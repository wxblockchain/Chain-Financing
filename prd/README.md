# PRD 目录

产品需求文档统一存放于此，并按功能或版本组织子目录。

## 命名约定

- 单文档：`[版本号]-[功能名]-PRD.md`，例如 `v1.0-登录注册-PRD.md`。
- 模块化文档：每个功能建立独立子目录，包含 PRD 主文档及流程图、数据字典等附件。

## 文档索引

本表只做定位——**路径、对应需求、入口文件**。每份 PRD 具体讲什么，由其主文档开头的导航索引负责，本表不重复描述功能内容。

| 路径 | 形态 | 对应需求 | 入口文件 |
| --- | --- | --- | --- |
| `v1.0-协议管理-PRD.md` | 单文档 | WS-301 | 文件本身 |
| `v1.0-账户与登录/` | 目录（主文档 + 6 个分册） | WS-302 | `v1.0-账户与登录-PRD.md` |
| `v1.0-实名认证与审核/` | 目录（主文档 + 7 个分册） | WS-303 | `v1.0-实名认证与审核-PRD.md` |
| `v1.0-消息通知/` | 目录（主文档 + 4 个分册） | WS-304 | `v1.0-消息通知-PRD.md` |

## 维护规则

- **新增一份 PRD、或把已有 PRD 拆成目录时，必须在同一次提交里补上表。** 索引与文件同源，不允许只改一处——否则这张表很快就会变成一份只覆盖部分模块的旧账。
- 表里只写路径、形态、对应需求与入口文件。功能内容、章节清单、编号索引一律放在各自主文档里，不往这里搬。
- 目录型 PRD 的入口文件统一命名为 `[版本号]-[功能名]-PRD.md`，与目录同名，便于一眼定位。

## 模板要点

- 背景与目标
- 用户故事与需求清单
- 功能详述（交互流程、规则、边界）
- 数据要求
- 验收标准
