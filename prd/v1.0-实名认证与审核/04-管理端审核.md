### 7.6 M6 · 管理端个人认证审核

#### 7.6.1 审核列表（P-M30，F-K20）

| 项 | 规则 |
| --- | --- |
| 入口 | 管理端左侧菜单「个人认证审核」，带待审数量角标 |
| 默认排序 | 提交时间**升序**（先提交先处理） |
| 默认筛选 | 状态 = 审核中 |
| 列 | 申请编号、账号标识（邮箱，无邮箱时为钱包地址缩略）、姓名、英文姓名、证件类型、国籍、提交时间、版本、状态、结论人、操作（查看） |
| **不设证件号码列** | 列表页不展示证件号码。审核比对在详情页完成（详情页明文完整展示已满足需要），列表页不展示可减少不必要的暴露面。此为设计口径，非脱敏——详情页仍完整明文（DK-39，见 13.1） |
| 筛选 | 状态、证件类型、国籍、提交时间范围、是否重提件 |
| 搜索 | 关键词搜索姓名 / 英文姓名（模糊）；**证件号码支持精确搜索**（输入完整号码，按 [`01-个人认证.md`](./01-个人认证.md) 8.2 归一化后比对，命中即返回，不做模糊匹配） |
| 分页 | 服务端分页，默认每页 20 条 |
| 空状态 | `No applications to review. / 暂无待审核的申请。` |

#### 7.6.2 审核详情（P-M31）

**页面结构：左右两栏**

| 栏 | 内容 |
| --- | --- |
| 左栏 · 申请信息 | 按填写顺序展示六字段：证件类型、姓名、英文姓名、国籍、**证件号码（明文完整）**、证件影像缩略；下方为账号信息（账号标识、建号时间、账户状态）与本次提交信息（版本、提交时间） |
| 右栏 · 影像查看器（C-M02） | 身份证：人像面与国徽面**并排展示**，可单独放大；护照：人像页。支持放大 / 缩小 / 旋转 90° / 全屏 |
| 下方 · 审核要点 | 按证件类型渲染的检查清单（8.6.2），展示为提示清单，不强制逐条勾选 |
| 下方 · 关联信息 | 同一账号的**企业认证**当前状态与结论，提供跳转链接（F-K27） |
| 下方 · 审核记录（C-M03） | 全部版本的提交与结论时间线（7.8） |
| 底部 · 操作区 | 「通过 / Approve」「驳回 / Reject」两个按钮 |

**证件号码的展示（F-K22，强制条款）**：见 13.1，此处不重复。

**重提件的差异展示（F-K28）**

- 版本 > 1 的申请，详情页顶部展示提示条：`Resubmission (v{n}). Previous decision: Rejected on {time}. / 第 {n} 次提交。上一版结论：{time} 驳回。`
- 展示上一版的驳回问题项列表。
- 本次相较上一版发生变化的字段与材料**标记为「本次已修改 / Updated」**；无变化的标记为「与上一版一致 / Unchanged」。

#### 7.6.3 通过与驳回（F-K25）

| 操作 | 规则 |
| --- | --- |
| 通过 | 二次确认弹窗；确认后个人认证状态置 `approved`，记录结论人与时间 |
| 驳回 | 打开 C-M01 驳回弹窗：**至少选择一个问题项**（多选，来自 [`06-双语文案与线框.md`](./06-双语文案与线框.md) 8.7.4 预置清单，每项可定位到具体字段或材料），可填补充说明（0–500 字，**对用户可见**）；确认后状态置 `rejected` |
| 撤销 | 结论一经提交**不可撤销**（DK-27）。若结论有误，由用户走重新提交流程重新审核——包括「误判通过」的情形：用户在已通过状态下同样可以发起重新提交（[`03-流程与状态机.md`](./03-流程与状态机.md) 7.5.3.3）。管理端不提供任何改判入口 |
| 并发保护（F-K29） | 提交结论时校验申请版本与当前状态；若已被他人出结论，拒绝本次提交并提示 `This application has already been reviewed by {name}. Refresh to see the latest status. / 该申请已由 {name} 完成审核，请刷新查看最新状态。` |
| 结论后的跳转 | 出结论后返回列表并自动定位到下一条待审申请，Toast 提示结论已保存 |

#### 7.7.3 级联规则：个人未通过则企业默认不通过（F-K26，强制条款）

**规则**：同一账号同一提交批次内，**个人认证的结论为 `rejected` 时，企业认证的最终状态一律为 `rejected`**，不存在「个人不通过但企业通过」的组合。

**执行时机与处理**

| 个人结论发生时，企业认证处于 | 系统行为 |
| --- | --- |
| 未开始 / 审核中 | 立即将企业认证置为 `rejected`，标记 `rejected_by_cascade = true`，从企业待审队列移除；驳回原因自动写入「个人认证未通过 / Personal verification was not approved」，并附带个人认证的问题项摘要 |
| 已通过（企业审核员先出了通过结论） | 企业认证的**对外状态被覆盖为 `rejected`（级联）**；企业审核员原先的「通过」结论**保留在审核记录中不被抹除**，时间线上明确呈现「企业审核员 X 于 T1 通过 → T2 因个人认证未通过级联驳回」 |
| 已驳回 | 不变，保持企业审核员自己给出的驳回原因；不额外追加级联原因 |

**界面表达**

- 企业审核详情页：个人认证已驳回时，页面顶部展示不可忽略的提示条 `Personal verification was rejected. This business application will be rejected automatically. / 该账号的个人认证已驳回，本企业认证将自动驳回。`，同时**禁用「通过」按钮**（防止审核员做出一个立刻会被覆盖的结论）。
- 企业列表：级联驳回的记录带「级联 / Cascaded」标签，可按此筛选。
- 资产端：企业认证卡展示驳回原因为「个人认证未通过」，并引导用户先修正个人认证材料。

**为什么保留而不是抹除企业审核员的原结论**：审核记录是审计对象，抹除会让「谁在什么时间基于什么材料做了什么判断」失真。对外状态以级联结果为准，对内记录保留全过程，两者不冲突。

**与「已通过后重新提交」的关系**：已通过的账号发起更新后（[`03-流程与状态机.md`](./03-流程与状态机.md) 7.5.3.3），两条认证重新进入审核，级联规则照常适用——若本轮个人认证被驳回，企业认证一并驳回，**原先有效的通过结论随之失效、业务功能被收回**。这一后果已在提交前的确认弹窗中告知用户。

#### 7.7.4 通过与驳回

- 规则与 7.6.3 一致（结构化问题项、并发保护、不可撤销）。
- 企业侧的预置问题项见 [`06-双语文案与线框.md`](./06-双语文案与线框.md) 8.7.4，按模板差异提供对应材料的问题项。
- **额外校验**：企业审核员点击「通过」时，服务端**再次执行企业唯一键查重**（[`02-企业认证与模板.md`](./02-企业认证与模板.md) 9.4.2）。若此刻已存在另一家已通过的同一唯一键企业（并发场景），拒绝本次通过并提示审核员，需按重复注册处理。

### 7.8 M8 · 审核记录与操作留痕（F-K30、F-K31）

#### 7.8.1 审核记录时间线（C-M03）

每份申请的详情页底部展示完整时间线，条目类型：

| 事件 | 记录内容 |
| --- | --- |
| 提交 / 重新提交 | 版本号、提交时间、提交人（账号标识） |
| 查看 / 下载 | 审核员查看详情（含证件号明文与影像）、下载材料原件的时间与操作人（见 7.8.2） |
| 通过 | 操作人、时间 |
| 驳回 | 操作人、时间、问题项列表、补充说明 |
| 级联驳回 | 触发来源（个人认证申请编号）、时间；操作人记为「系统 / System」 |
| 唯一性拦截 | 拦截时间、冲突的企业唯一键（不展示对方账号信息） |

- 时间线按时间倒序，最新在上。
- 每条记录的时间按 WS-302 13.4 展示（本地时间 + 时区标注），存储为 UTC。
- 审核记录**只增不改不删**。

#### 7.8.2 敏感数据访问留痕（F-K31）

以下操作必须写入访问日志，日志本身不在管理端界面展示（供合规与安全事后调阅）：

| 操作 | 记录字段 |
| --- | --- |
| 打开个人 / 企业认证审核详情页 | 操作人 `admin_id`、目标申请编号、目标 `account_id`、时间、来源 IP、User-Agent |
| 打开影像查看器 / 放大查看某份材料 | 同上 + 材料标识 |
| **下载材料原件**（单份或打包中的每一份） | 同上 + 材料标识；打包下载时每份各记一条 |
| 复制证件号码 | 同上 |
| 列表页执行证件号码精确搜索 | 操作人、搜索发生时间、是否命中（**不记录被搜索的号码原文**，只记录哈希，避免日志本身成为号码泄露源） |

- 保留期见 16 章。
- 这是「证件号码明文完整展示」这一决策的配套控制项，不可省略。

### 8.6 审核要点清单

> 审核要点在管理端详情页展示为检查清单（F-K24），起提示作用，**不强制逐条勾选**（强制勾选会诱发机械式点选，不提升实际质量）。

#### 8.6.1 通用要点（个人与企业均适用）

1. 影像清晰可辨，四角完整，无遮挡、无反光、无明显涂改痕迹。
2. 影像非明显的屏幕翻拍或明显编辑痕迹（尽力核验，不做技术鉴定）。
3. 文件在有效期内（对有有效期的证照）。
4. 文件语言非中英文时，材料是否可读（如不可读，驳回并要求提供中英文译本）。

#### 8.6.2 个人认证审核要点（P-M31）

| # | 要点 | 对应驳回原因项 |
| --- | --- | --- |
| 1 | **证件号码与证件影像上的号码完全一致**（强制核对项） | R-P01 |
| 2 | 姓名与影像上的姓名一致 | R-P02 |
| 3 | 英文姓名与护照机读区 / 证件英文栏一致（持身份证者与拼音一致即可） | R-P03 |
| 4 | 国籍与证件签发国 / 证件类型相符（如选择身份证但国籍非中国大陆，需判断合理性） | R-P04 |
| 5 | 身份证：人像面与国徽面为**同一张证件**，两面信息可相互印证 | R-P05 |
| 6 | 护照：人像页信息完整，含机读区 | R-P06 |
| 7 | 证件在有效期内 | R-P07 |
| 8 | 影像清晰、完整、无涂改 | R-P08 |

## 13. 敏感数据的展示与安全

### 13.1 运营端证件号码明文完整展示（强制条款）

> 这是需求方明确给出的展示规则，本节按原样落地，**不得在实现或后续修订中改为脱敏方案**。

| 项 | 规则 |
| --- | --- |
| 适用范围 | 管理端**个人认证审核详情页 P-M31** 的证件号码字段；企业认证详情页中引用的被授权人证件号码同样适用 |
| 展示形态 | **完整明文，展示用户输入的原始字符串**（含用户输入的空格 / 连字符，见 [`01-个人认证.md`](./01-个人认证.md) 8.2.3） |
| **不得**做的事 | ❌ 不做任何形式的掩码（不出现 `3101**********1234` 这类展示）<br>❌ 不设「查看完整 / Show full number」二次点击<br>❌ 不设悬停才显示<br>❌ 不做点击后才解密的延迟加载<br>❌ 不限制展示时长、不自动重新遮盖 |
| 交互 | 号码旁提供「复制」按钮，一键复制完整号码，复制成功以 Toast 提示 |
| 字体 | 等宽字体展示，便于与影像逐位比对 |
| 位置 | 与证件影像**同屏可见**（左右分栏，见 [`06-双语文案与线框.md`](./06-双语文案与线框.md) 8.8 线框），审核员不需要切换页面即可比对 |
| 理由（写给实现者） | 审核员的核心动作就是「把表单里的号码和影像上的号码逐位比对」。任何遮盖或二次动作都会让这个高频动作变成每单一次的额外点击，且遮盖后的号码根本无法完成比对——脱敏在这个具体场景下会直接破坏功能 |

### 13.2 与之配套的访问控制（不可省略）

> 本期**管理端不做角色区分**（DK-38），**材料原件也允许下载**（13.3）。这两条决定了本节的控制手段：应用内已经没有"按角色收窄可见范围"这条路可走，也没有"看得到但拿不走"这道屏障，**逐次留痕因此成为唯一的可审计抓手，不可省略、不可降级**。

| 控制项 | 要求 |
| --- | --- |
| 访问主体 | **管理端登录用户即可见**：任何已登录且状态为 `active` 的管理端账号，都可查看全部认证详情、证件号码明文与材料原件，并可下载原件。本期不存在只读审计、只看个人不看企业之类的细分范围 |
| 不可访问的情形 | 未完成首登改密（`pending_reset`）、被锁定（`locked`）、被停用（`disabled`）的管理端账号一律不得访问（WS-302 7.7.3、10.2） |
| 实际的收敛点 | 由于应用内无法进一步收窄，**"谁能拿到管理端账号"就是本口径的实际防线**。管理端账号由技术在数据层直接发放（WS-302 7.7.1），因此账号发放的审批、离职转岗的及时停用与定期复核必须写入运维手册——这是本节要求的一部分，不是运维的自选动作 |
| 服务端鉴权 | 认证详情接口必须在服务端校验管理员身份与状态，前端路由守卫不得作为唯一防线 |
| **访问与下载留痕** | 每一次打开详情页、查看影像、复制号码、**下载原件**均写入访问日志（7.8.2、[`05-通知.md`](./05-通知.md) 14.6）；留痕本身不可关闭、不可跳过 |
| 传输 | 全链路 HTTPS；认证详情接口禁止被缓存（响应头显式禁用缓存） |
| 前端 | 证件号码不写入浏览器本地存储、不出现在 URL 参数、不出现在前端日志与埋点上报中 |
| 服务端日志 | 应用日志、访问日志、错误日志中**一律不得打印证件号码原文**；确需关联时使用不可逆哈希 |
| 埋点 | 任何行为分析埋点不得携带证件号码、姓名、影像地址 |

### 13.3 下载、导出与打印口径

| 能力 | 本期口径 |
| --- | --- |
| **下载证件影像 / 企业材料原件** | **允许，不做限制**：审核员在详情页与查看器内可直接下载原件；**不需审批、不加水印、不限次数、不限时间窗、不区分材料类型** |
| **下载留痕** | 每一次下载写入敏感访问日志（[`03-流程与状态机.md`](./03-流程与状态机.md) 15.6，`action = download_document`），记录操作人、目标申请、材料标识、时间、IP 与 User-Agent。**这是下载解禁后唯一的可审计抓手，不可省略** |
| 打包下载 | 可提供「下载本申请全部材料」的打包下载；打包内**每份材料各计一条下载留痕**，不因打包而只记一条 |
| 在线预览 | 保留（C-M02）。下载不替代预览：日常比对以预览为主，下载用于存档、线下复核与外部尽调等场景 |
| 认证数据的字段级批量导出（Excel / CSV） | **不提供**。需求方的答复指向「证件影像与企业材料原件」的下载；把姓名、证件号码等字段批量导出成表格是另一件事，本期不开放，确需时单独提需求 |
| 打印 | 不提供打印优化视图（下载后自行处理） |
| 材料访问地址 | 仍通过**短时效签发的访问凭据**获取（N-K04），目的是防止访问链接被转发后遭第三方直接取用；**该机制不构成对审核员的限制**——凭据过期后重新进入详情页即自动重新签发，下载随时可再次进行 |
| 下载后的文件 | 一经下载即离开系统边界，系统无法再控制其复制与流转。这是本口径的固有代价，对应风险与配套要求见 [`v1.0-实名认证与审核-PRD.md`](./v1.0-实名认证与审核-PRD.md) 18.2 R-13 与 [`v1.0-实名认证与审核-PRD.md`](./v1.0-实名认证与审核-PRD.md) 16.4 |
