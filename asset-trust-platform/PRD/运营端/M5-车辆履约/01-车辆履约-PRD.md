本模块共三册：本册写功能、业务规则与字段规则；[流程图与状态机](./02-车辆履约-流程图与状态机.md)画出主要流程与状态；[验收](./04-车辆履约-验收.md)供测试使用。本模块自身不发送任何消息，所以没有 03 消息通知册，并非缺失。

本册只定义信息需求与业务行为；页面布局与交互承载由 Hallmark 设计决定。以下设计约束由用户确定，保持不变：详情统一为“概要 → 进度与核对 → 明细”三层，物流进度以竖排时间线展示在详情右侧、最新一条在最上方；明细放在价格链下方，按采购、内销、运输与保险、外销、出入库五组信息以页签切换，各组直接展示全部字段，不收起、不展开；列表只放描述车辆当前状况的信息，单据编号移到详情；页面中的单据编号都可点击，进入该单据所在模块的详情；一个事实只在一个模块完整展示，其他模块展示摘要并跳转。

## 1. 模块是什么

车辆履约以一辆车（VIN）为单位，回答“这辆车从外采、内销、装船运输到外销卖出，走到了哪一步，每一段对应哪些单据、本车的价格和收款是多少，有没有需要留意的风险”。平台按 VIN 把已审核的外采合同、外采发票、内销合同、内销发票、提单、保单、清关单、外销合同、出入库和外销收款关联到这辆车，在一个详情中串起来，并展示外采合同车辆明细中这辆车本身的属性。本模块是资产数据各模块之间的枢纽：任何模块车辆清单中的 VIN 都进入这里；这里列出的每个单据编号又可以跳到它所在模块的详情。本模块只供运营端使用，只读。

基本原则：

- 车辆页只展示本车涉及的单据编号和本车自己的值（单价、日期、本车收款）。合同金额、付款条件、提单船名航次、保险金额等单据级信息只在该单据所在模块完整展示，车辆页点编号跳过去看。
- 一辆车对应多张同类单据时（如转运有两张提单、退车后再售有两份外销合同）全部列出，每个编号都可跳转。
- 只采信已审核的单据；未审核、已反审核、已作废或已删除的单据不出现在本模块。
- 美元金额按汇率管理（M11）中查看时的当前汇率折算，同时保留原币金额。
- 本模块不判断任何风控规则。风控规则由风控预警（M8）按其[风控规则目录](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#rule-catalog)判断和处理，本模块只承接 M8 提供的本车关联预警。
- 企业端（债权人、债务人）本期都看不到车辆履约。

**一个完整的例子**（企业、客户名称、单据编号和汇率为演示值；汇率按 1 USD = 1,500.00 NGN）。VIN-A 列在外采合同 PC-0301（外采合同日期 2026-07-15，外采供应商“主机厂甲”，外采买方 Carloha Holding，本车外采合同单价 18,000.00 USD）和外采发票 PPI-0301（2026-07-20，本车外采发票单价 18,000.00 USD）中，2026-08-25 外采交货；列在内销合同 CT-0012（2026-08-01，内销卖方 Carloha Holding、内销买方 Carloha Nigeria）和内销发票 INV-0012（2026-08-20，本车内采单价 22,000.00 USD）中；2026-09-10 装上提单 BL-5501，2026-10-12 到港，BL-5501 关联保单 PL-889；2026-10-20 按清关单 CD-0901 清关；2026-10-25 内销收货入库；外销合同 SO-2045（2026-11-01，外销卖方 Carloha Nigeria，外销客户 Lagos Motors Ltd，本车外销单价 39,600,000.00 NGN）；2026-11-03 收到外销收款 RC-7781 共 30,000,000.00 NGN；2026-11-05 外销出库。

运营人员打开“车辆履约”菜单，VIN-A 一行为：当前物流节点“已外销出库”、在库情况“不在库”、所属应收账款 INV-0012、外销收款情况“部分收款”、预警条数（以 M8 提供为准）。在应收账款 INV-0012 的车辆清单中点 VIN-A，同样进入车辆履约详情：概要中看到 PC-0301 车辆明细中本车的车辆属性、所属应收账款 INV-0012、当前物流节点“已外销出库”、在库情况“不在库（外销出库 2026-11-05）”和关联预警数量；物流进度从新到旧依次为外销出库 2026-11-05（SO-2045）、入库 2026-10-25（内销收货）、清关 2026-10-20（CD-0901）、到港 2026-10-12（BL-5501）、装船 2026-09-10（BL-5501）、外采交货 2026-08-25（PC-0301），最上方一条为当前物流节点；价格链为外采单价 18,000.00 USD → 内采单价 22,000.00 USD → 外销单价 26,400.00 USD（原币 39,600,000.00 NGN），外销收款 20,000.00 USD（原币 30,000,000.00 NGN）。价格链下方是五组明细，运营切到“外销”，点收款 RC-7781 进入资金收付的收款详情，看完返回 VIN-A，仍停在“外销”；切到“出入库”看到内销收货 2026-10-25 和外销出库 2026-11-05 两条记录；再点提单号 BL-5501 进入提单信息详情查看船名航次和清关，最后返回应收账款 INV-0012。

### 1.2 本期不做

- 在平台录入、编辑、删除任何车辆、单据或出入库资料；运营端和企业端都没有这类操作。
- 提单（含船名航次、航程、清关明细）、保单（含保险金额、覆盖率）、合同（含合同金额、开票和收付进度）、应收账款、收付记录的完整信息：分别在 M12、M13、M4、M3、M14 展示，本模块只展示本车的值并跳转。
- 任何风控规则的判断，包括与车辆有关的价格、物流、外销与收款核对：由风控预警（M8）判断、生成和处理，本模块只承接 M8 提供的预警信息。
- 原车辆物流与履约追溯中的费用登记、组装质检、出库交付记录（仓库、交付对象、交付结果）和车辆异常事件：不保留。出库交付由[出入库与在库情况（F-M5-11）](#F-M5-11)承接，退车回库、调拨等以出入库记录体现。
- 仓库、库龄、来源订单：出入库只展示方向、类型和日期，并判断车辆是否在库。
- 车辆与集装箱号的关联：本期不实现，本模块任何位置都不展示车辆的集装箱号。
- 企业端查看车辆履约，包括债权人和债务人。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| VIN | 车辆识别代号；本模块一辆车一个 VIN |
| 已审核单据 | 来源系统中已审核的单据；本模块只采信这类单据 |
| 外采合同 | Carloha Holding 向主机厂采购车辆的合同，以合同编号作为外采合同号 |
| 外采发票 | 主机厂就外采合同开给 Holding 的发票 |
| 内销合同 | Holding 卖给 Carloha Nigeria 的合同 |
| 内销发票 | Holding 就内销合同开给 Nigeria 的发票；一张内销发票就是一笔应收账款 |
| 外销合同 | Nigeria 卖给终端客户的合同，即外销订单，含零售和批售 |
| 外销收款 | 终端客户就外销合同付给 Nigeria 的收款，按外销合同归集 |
| 内销收货 | Nigeria 收到车辆并入库；不是 Holding 从主机厂收货 |
| 外采交货日期 | 主机厂向 Holding 交付车辆的日期，取外采合同（采购订单）车辆明细中本车的厂家出库日期 |
| 外采单价 | 本车的采购单价：取外采发票单价；尚无外采发票时取外采合同单价，并标“合同价” |
| 内采单价 | 本车的内销单价：已开内销发票时取内销发票单价；尚未开票时取内销合同单价，并标“合同价”；币种为内采币种 |
| 入库、出库（出入库方向） | 按出入库记录的类型划分，见[判定规则](#stock-rule) |
| 车辆属性 | 外采合同（采购订单）车辆明细中描述车辆本身的信息，见[车辆属性（F-M5-19）](#F-M5-19) |
| 物流节点 | 外采交货、装船、到港、清关、入库、外销出库六种节点，见[物流节点进度（F-M5-02）](#F-M5-02) |
| 入库（物流节点） | 车辆进入 Carloha Nigeria 仓库、可以外销的里程碑；只由内销收货和销售退库两类出入库记录生成。调拨入库、其他入库、入库调整等不生成物流节点，只影响在库情况 |
| 物流记录 | 车辆每发生一次物流节点变动生成的一条记录，含节点、日期和来源单据 |
| 当前物流节点 | 最新一条物流记录对应的节点 |
| 在库情况 | 按出入库记录判断车辆当前是否在仓库，见[出入库与在库情况（F-M5-11）](#F-M5-11) |
| 价格链 | 本车外采单价 → 内采单价 → 外销单价，以及外销收款金额，统一以美元对照 |
| 关联预警 | 风控预警（M8）判定为与本车有关的预警；哪些算与本车有关以 M8 为准 |
| 运营人员 | 运营端账号的使用者，即 M2 定义的运营管理员；本期运营端只有这一种角色，权限相同 |

## 3. 共用展示与异常规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。

<a id="display-values"></a>
### 3.1 来源值、金额与日期

- 单据编号、主体名称、车辆属性、日期、金额等按来源单据原值展示，不翻译、不改写。
- 单据上某项值为空时，原因为“未提供”，页面上按[缺失值的展示](#placeholder)呈现。
- 金额与币种代码同时展示，数值在前、币种代码在后，带千分位，例如“22,000.00 USD”。原币金额按单据原值展示，不四舍五入、不截断。
- 单据日期按原样展示，不做时区换算；单据日期带时区时，时区写在日期后面。

<a id="placeholder"></a>
#### 缺失值的展示

- 取不到或算不出的值，按应收账款（M3）[缺失值的展示](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#placeholder)统一以“-”展示。本册写作“未提供”“无法折算”“无可用汇率”的，都是缺失原因，页面上均显示为“-”。
- “无法折算”“无可用汇率”写在“-”下方，让运营人员知道美元值为什么没有。
- 以下是业务状态，照常以文字展示，不改为“-”：暂无记录、未关联应收账款、暂无物流记录、无出入库记录、未交货、暂无外采发票、未开票、暂无保单、未出库、暂无收款、外销收款情况的各个值、无关联预警、无，以及“合同价”“合同合计”“批售合同整体收款”“合同与发票单价不一致”标记。
- 空清单与无结果（如“暂无车辆履约资料”“没有符合条件的车辆”）照常以文字展示。

<a id="usd"></a>
### 3.2 美元折算

字段名带“（美元）”的值按下表得出，并与原币金额同时展示；折算值标明“折算”。

| 原币 | 美元值 |
| --- | --- |
| USD | 等于原币金额，不标“折算” |
| NGN | 原币金额 ÷ 查看时 M11 的当前汇率（1 USD = R NGN） |
| 其他币种 | 无法折算（M11 只维护美元与奈拉） |
| NGN，但 M11 无可用汇率 | 无可用汇率 |

- 折算结果保留两位小数，四舍五入；合计用未取舍的值计算，展示时再取舍。口径与应收账款（M3）的[美元折算与比率](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#usd-rule)一致。
- 汇率按[对外提供的汇率口径（FX-05）](../M11-汇率管理/01-汇率管理-PRD.md#FX-05)取得；折算值旁可查看所用汇率值及其生效时间。
- 美元值为“无法折算”或“无可用汇率”时，美元值显示“-”并在下方注明原因，原币金额照常展示，不用 0 或其他值代替。

### 3.3 单据编号跳转

本模块中的单据编号都可点击，进入该单据所在模块的详情；看完可返回本车详情，返回时回到进入前所在的明细页签。目标详情及其中的定位由所属模块定义，本模块只决定从哪个编号进入哪个详情。

| 编号 | 进入 |
| --- | --- |
| 内销发票号（所属应收账款） | 应收账款（M3）中该笔应收账款的详情 |
| 外采合同号 | 合同信息（M4）的[外采合同详情（F-M4-05）](../M4-合同信息/01-合同信息-PRD.md#F-M4-05) |
| 外采发票号 | 合同信息（M4）中该发票所属外采合同的[外采合同详情（F-M4-05）](../M4-合同信息/01-合同信息-PRD.md#F-M4-05)，按 M4 定位到外采发票清单中的这张发票 |
| 内销合同号 | 合同信息（M4）的[内销合同详情（F-M4-12）](../M4-合同信息/01-合同信息-PRD.md#F-M4-12) |
| 外销合同号 | 合同信息（M4）的[外销合同详情（F-M4-14）](../M4-合同信息/01-合同信息-PRD.md#F-M4-14) |
| 提单号 | 提单信息（M12）的[提单详情（F-M12-03）](../M12-提单信息/01-提单信息-PRD.md#F-M12-03) |
| 清关单号 | 提单信息（M12）中本车所在提单的[提单详情（F-M12-03）](../M12-提单信息/01-提单信息-PRD.md#F-M12-03)，按 M12 定位到[车辆清单（F-M12-07）](../M12-提单信息/01-提单信息-PRD.md#F-M12-07)中的本车；本车在多张提单上时，进入装船日期最晚的一张 |
| 保单号 | 保单信息（M13）的[保单详情（F-M13-03）](../M13-保单信息/01-保单信息-PRD.md#F-M13-03) |
| 外销收款的交易流水号 | 资金收付（M14）中该笔收款的[收付记录详情（F-M14-03）](../M14-资金收付/01-资金收付-PRD.md#F-M14-03) |

- 目标模块中没有可承载的详情时，编号按原值展示、不可点击，与 M3 [单据编号跳转](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#doc-links)一致。例如本车不在任何已采信提单上时，清关单号不可点击（M12 不展示没有提单承载的清关单）。
- 进入时目标单据已不再被采信（如已反审核、已作废）时，提示“该内容不存在或已更新”，可返回本车详情。

<a id="no-access"></a>
### 3.4 不可访问

- 企业端没有车辆履约入口。以企业账号的登录状态访问本模块任何内容时，按 M2 [运营端菜单与无权访问（F-OP-11）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-11)处理，不返回任何内容。
- 运营账号待首登改密或锁定中时不能使用本模块，账号状态见 M2 [运营账号状态](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#op-account-status)；本期运营账号不设停用。

<a id="load-fail"></a>
### 3.5 加载失败

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的金额、节点或提示，避免把加载失败误显示为“暂无记录”。
- 详情中某一部分（如价格链、明细中的某一组）加载失败时，仅该部分提示失败并可重试，其他部分正常展示。

<a id="link-rules"></a>
### 4.1 哪些资料属于这辆车

<a id="adopt-rules"></a>
### 4.2 只采信已审核单据

- 只有已审核的单据和记录进入本模块；未审核的不展示，也不参与物流节点、在库情况和价格链。
- 已采信的单据之后被反审核、作废或删除时，从本模块移除，相关节点、在库情况和价格按剩余资料重新判定。
- 同一张单据再次取得且内容一致时不重复展示；内容不同（含车辆增减、单价、日期变化）时，新内容直接成为当前展示内容。
- 运营人员只看到当前资料，本模块不展示单据变化前的内容和变化历史。
- 资料更新只影响本模块的展示和判定，不改变其他模块的单据本身。

## 5. 车辆履约列表（F-M5-03）

适用角色与前提：可正常使用的运营人员，从运营端“车辆履约”菜单进入。可查看本模块的全部车辆。

验收参见：[车辆履约列表](./04-车辆履约-验收.md#acc-f-m5-03)。

列表每个 VIN 一行，只放描述车辆当前状况的信息；外采合同号、提单号、外销合同号、外销客户等单据信息在详情的明细中查看：

| 业务信息 | 含义 | 没有时 |
| --- | --- | --- |
| VIN | 车辆识别代号，点击进入[车辆履约详情（F-M5-05）](#F-M5-05) | — |
| 当前物流节点 | 见[物流节点进度（F-M5-02）](#F-M5-02) | — |
| 在库情况 | 在库、不在库或无出入库记录，见[出入库与在库情况（F-M5-11）](#F-M5-11) | — |
| 所属应收账款 | 本车所在内销发票的发票号，可点击进入 M3；本车在多张内销发票中时，展示发票日期最近的一张并标出共几张，日期相同时按发票号排列取第一张 | 展示“未关联应收账款” |
| 外销收款情况 | 见下表 | — |
| 预警 | 本车未处理的关联预警条数，由 M8 提供，见[关联预警（F-M5-13）](#F-M5-13) | 展示“无” |

- 外销收款情况按本车最近一份外销合同判定；批售合同的收款属于整份合同，按该合同的收款合计与合同外销金额（各车外销单价之和）比较：

| 外销收款情况 | 判定条件 |
| --- | --- |
| 无外销合同 | 没有外销合同 |
| 未收款 | 有外销合同，没有外销收款 |
| 部分收款 | 有外销收款，外销收款金额低于外销单价（批售为合同外销金额） |
| 已收款 | 有外销收款，外销收款金额不低于外销单价（批售为合同外销金额） |
| 已有收款 | 有外销收款，但收款与单价币种不同且无法折算，不能比较 |

外销收款金额与外销单价币种相同时按原币比较，不同时按[美元折算](#usd)后比较。合同信息（M4）的内销合同车辆清单原样引用本表的判定结果。

查找与筛选：

- 按 VIN 查找，支持部分匹配。
- 按内销发票号、外采合同号、外采发票号、内销合同号、提单号、清关单号、保单号、外销合同号查找，支持部分匹配；结果为该单据涉及的全部车辆。
- 筛选：当前物流节点、在库情况、外销收款情况、是否有未处理关联预警。多个条件同时生效。
- 默认按最新一条物流记录的日期从新到旧排列；日期相同时按 VIN 排列；没有物流记录的车辆排在最后。

边界与异常：

- 平台尚未采信任何车辆时，展示“暂无车辆履约资料”；查找或筛选无结果时，展示“没有符合条件的车辆”并可清除条件。
- 列表不提供新增、编辑、删除操作。
- 加载失败按[加载失败](#load-fail)处理。

## 6. 车辆履约详情（F-M5-05）

适用角色与前提：可正常使用的运营人员，从车辆履约列表或任何模块中的 VIN 进入。详情只读。

验收参见：[车辆履约详情](./04-车辆履约-验收.md#acc-f-m5-05)。

<a id="detail-layers"></a>
### 6.1 三层结构

| 层 | 展示内容 |
| --- | --- |
| 概要 | VIN；[车辆属性（F-M5-19）](#F-M5-19)；所属应收账款（全部内销发票号，可点击进入 M3）；当前物流节点；[在库情况](#F-M5-11)；[关联预警](#risk-entry) |
| 进度与核对 | [物流节点进度（F-M5-02）](#F-M5-02)；[价格链（F-M5-15）](#F-M5-15) |
| 明细 | 价格链下方，按业务顺序的五组信息：[采购段（F-M5-16）](#F-M5-16)、[内销段（F-M5-17）](#F-M5-17)、[运输与保险段（F-M5-06）](#F-M5-06)、[外销段（F-M5-18）](#F-M5-18)、[出入库记录](#stock-records) |

- 概要中已展示的内容，下方不再重复展示。
- 五组信息以页签切换（用户确定），每组直接展示全部字段，不收起、不展开；默认打开哪一组由设计决定。

- 各组中多张同类单据全部列出，按单据日期从新到旧排列。
- 从本车详情进入其他模块再返回时，回到进入前所在的页签。
- 所属应收账款没有时展示“未关联应收账款”。

<a id="F-M5-19"></a>
### 6.2 车辆属性（F-M5-19）

适用角色与前提：可正常使用的运营人员，在详情概要中查看。只读。

验收参见：[车辆属性](./04-车辆履约-验收.md#acc-f-m5-19)。

- 车辆属性取自本车所在外采合同（采购订单）的车辆明细，只在详情展示，列表不展示：

| 业务信息 | 含义 |
| --- | --- |
| 品牌 | 车辆明细中本车的品牌名称 |
| 车型 | 车辆明细中本车的车型名称 |
| 外饰颜色 | 车辆明细中本车的外饰颜色名称 |

- 三项都按 ERP 原值展示，不翻译、不改写；品牌、车型、外饰颜色的编码不展示。
- 本车在多份外采合同中时，取外采合同日期最近的一份；日期相同时按外采合同号排列取第一份。
- 某项属性为空时原因为“未提供”，按[缺失值的展示](#placeholder)显示为“-”。
- 本车没有外采合同时，车辆属性展示“暂无记录”。
- 外采合同更新或被移除时，车辆属性按当前资料重新取值；不同外采合同中的属性不一致时只展示所取的一份，本模块不比较、不提示。

### 6.3 边界与异常

- 按 VIN 进入、但该 VIN 不在本模块任何资料中时，展示“未找到该 VIN 的车辆履约资料”，可返回来源位置。
- 进入后该车的全部资料已被移除时，同样按上一条处理。
- 加载失败按[加载失败](#load-fail)处理。

<a id="F-M5-02"></a>
## 7. 物流节点进度（F-M5-02）

适用范围：平台为每辆车记录每次物流节点变动，在列表、概要中展示当前物流节点，在详情中以竖排时间线展示。没有用户操作。

流程参见：[物流节点进度（图 M5-3）](./02-车辆履约-流程图与状态机.md#fig-m5-3)。
验收参见：[物流节点进度](./04-车辆履约-验收.md#acc-f-m5-02)。

<a id="node-rule"></a>
### 7.1 物流记录与当前物流节点

车辆每发生一次物流节点变动，生成一条物流记录：

| 物流节点 | 何时生成记录 | 记录日期 | 来源单据 |
| --- | --- | --- | --- |
| 外采交货 | 本车有外采交货日期 | 外采交货日期 | 外采合同号 |
| 装船 | 本车列在一张提单上；每张提单一条，转运时每次装船各一条 | 该提单的装船日期 | 提单号 |
| 到港 | 本车所在提单有到港日期；每张提单一条 | 到港日期，取自 M12 [航程与到港（F-M12-05）](../M12-提单信息/01-提单信息-PRD.md#F-M12-05) | 提单号 |
| 清关 | 清关单列有本车；每张清关单一条 | 清关日期 | 清关单号 |
| 入库 | 本车每条内销收货、销售退库记录各一条 | 出入库日期 | 出入库单号，并标出出入库类型（内销收货或销售退库） |
| 外销出库 | 本车每次外销出库一条 | 外销出库日期 | 外销合同号 |

- 物流记录按日期先后排序；同一天有多条时，按上表节点顺序排序，排在后面的为较新。入库与外销出库在同一天时，按出入库记录的审核时间先后排序，例如当天外销出库后又销售退库，入库为较新。
- 当前物流节点取最新一条物流记录：

| 最新一条物流记录 | 当前物流节点 |
| --- | --- |
| 没有任何物流记录 | 暂无物流记录 |
| 外采交货 | 已外采交货 |
| 装船 | 在途 |
| 到港 | 已到港 |
| 清关 | 已清关 |
| 入库 | 已入库 |
| 外销出库 | 已外销出库 |

- 只为已经发生的节点生成记录，不补记、不推断未发生的节点。
- 来源单据被移除，或其中的日期被更正时，对应记录随之删除或更新，当前物流节点按最新记录重新判定，可以后退。
- 内销收货、销售退库、外销出库以外的出入库记录（调拨入库、其他入库、入库调整、其他出库、调拨出库、调拨退库、采购退货、调拨退货、出库调整）不生成物流记录，只影响[在库情况](#F-M5-11)，并在[出入库记录](#stock-records)中查看。
- 退车再售在时间线上依次为外销出库、入库（销售退库）、外销出库，当前物流节点按最新一条如实变化。
- 当前物流节点只描述已有记录，不是审核结论，不影响确权、审核或出库。

<a id="node-view"></a>
### 7.2 物流时间线

- 详情中以竖排时间线展示本车全部物流记录，最新一条在最上方，越早的越靠下；每条展示物流节点、日期和来源单据（入库记录展示出入库单号和出入库类型）。
- 来源单据编号可点击，按[单据编号跳转](#doc-links)进入对应详情；入库记录的出入库单号按原值展示、不可点击（没有模块承载出入库单详情）。
- 最新一条突出为当前物流节点；最新一条为装船时标“在途”。
- 没有任何物流记录时展示“暂无物流记录”。

<a id="F-M5-11"></a>
## 8. 出入库与在库情况（F-M5-11）

适用范围：平台按本车的入库、出库记录判断在库情况，在列表、列表筛选和概要中展示；运营人员在明细的出入库记录中逐条查看。只读。

流程参见：[在库情况（图 M5-5）](./02-车辆履约-流程图与状态机.md#fig-m5-5)。
验收参见：[出入库与在库情况](./04-车辆履约-验收.md#acc-f-m5-11)。

<a id="stock-rule"></a>
### 8.1 判定规则

入库、出库按出入库记录的类型划分：

| 方向 | 出入库类型 |
| --- | --- |
| 入库 | 内销收货（采购入库）、调拨入库、其他入库、入库调整、销售退库 |
| 出库 | 外销出库（销售出库）、其他出库、调拨出库、调拨退库、采购退货、调拨退货、出库调整 |

| 在库情况 | 判定条件 |
| --- | --- |
| 在库 | 最近一次入库晚于最近一次出库；或只有入库、没有出库 |
| 不在库 | 最近一次出库晚于最近一次入库；或只有出库、没有入库 |
| 无出入库记录 | 本车没有任何出入库记录 |

- 先比较出入库日期（出入库单据的业务日期）；同一天的记录按审核时间先后比较。
- 在库情况旁展示最近一次出入库的类型名称和日期，如“销售退库 2026-10-28”。
- 只判断是否在库，不展示仓库、库龄和来源订单。

<a id="stock-combo"></a>
### 8.2 当前物流节点与在库情况的组合

当前物流节点、在库情况是两个独立维度，各自展示，互不覆盖：

| 当前物流节点 | 在库情况 | 运营看到 |
| --- | --- | --- |
| 已入库 | 在库（最近为内销收货或销售退库） | 两者照常展示，属于正常情况；销售退库后当前物流节点回到“已入库” |
| 已外销出库 | 不在库（最近为外销出库） | 两者照常展示，属于正常情况 |
| 已外销出库 | 在库（最近为调拨入库、其他入库或入库调整） | 当前物流节点仍为“已外销出库”，在库情况为“在库”并展示最近一次入库的类型名称及日期；平台不推断原因 |
| 已外采交货、在途、已到港、已清关或已入库 | 不在库（最近为外销出库以外的出库，如其他出库、调拨出库） | 当前物流节点不变，在库情况为“不在库”并展示该出库的类型名称及日期 |
| 已清关及之前的节点 | 在库（只有调拨入库、其他入库或入库调整，没有内销收货） | 两者如实展示，不补记入库记录 |
| 任一 | 无出入库记录 | 在库情况展示“无出入库记录” |

<a id="stock-records"></a>
### 8.3 出入库记录

详情明细的“出入库”一组逐条列出本车全部出入库记录：

| 业务信息 | 含义 |
| --- | --- |
| 出入库单号 | 出入库单据的单据编号，按原值展示，不可点击 |
| 方向 | 入库或出库，按[判定规则](#stock-rule)的类型划分 |
| 出入库类型 | 记录的类型名称，如内销收货、调拨出库、销售退库 |
| 出入库日期 | 出入库单据的业务日期，按原样展示 |

- 按出入库日期从新到旧排列；同一天的按审核时间，较晚的在上。
- 本车没有任何出入库记录时，该组展示“暂无记录”。
- 记录被反审核、作废或删除时从清单移除，在库情况和入库物流记录随之重新判定。
- 仓库、库龄和来源订单不展示。

- 外销收款原币有多个币种时，原币按币种分别列出，美元值为各笔美元值之和；任一笔无法折算时美元合计为“无法折算”。
- 美元值按[美元折算](#usd)得出。
- 价格链只展示数值，不判断价格高低或收款是否足额；相关风险由 M8 判断，见[关联预警（F-M5-13）](#F-M5-13)。

<a id="risk-entry"></a>
### 14.1 承接规则

- 本模块不判断任何风控规则，也不在字段旁给出风控提示。哪些预警算本车的关联预警、条数含哪些预警，按 M8 [向其他模块提供的预警信息](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#external)。
- 本模块只展示 M8 提供的本车关联预警：
  - 列表“预警”：本车未处理的关联预警条数；没有时展示“无”。
  - 详情概要：未处理和已处理的关联预警条数；都没有时展示“无关联预警”。
- 点击预警数量进入 M8，落点与返回按 M8 [进入与返回](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#entries)；看完可返回本车详情。
- 本模块展示的数量与处理结果始终与 M8 一致，M8 生成、处理或解除预警后随之更新。
- 预警不改变本模块的任何金额、物流节点、在库情况或外销收款情况；本模块没有处理预警的操作。
- 关联预警加载失败时，仅该部分提示失败并可重试，不显示为“无”或“无关联预警”。

## 16. 待确认事项与依赖

当前没有待确认事项。

<a id="dependencies"></a>
依赖：

- 客户 ERP：提供本模块所列的已审核单据、出入库记录（出入库单号、类型、业务日期、审核时间）、收款记录，以及外采合同车辆明细中本车的品牌、车型、外饰颜色和厂家出库日期；数据对接由研发负责。
- 汇率管理（M11）：提供查看时的当前汇率；M11 只维护美元与奈拉，其他币种的美元值为“无法折算”。
- 应收账款（M3）、合同信息（M4）、提单信息（M12）、保单信息（M13）、资金收付（M14）：提供各单据详情及其中的定位供跳转；M3、M4、M12、M13 在各自车辆清单中提供进入本模块的 VIN；M12 提供提单的到港日期和清关单与车辆的对应结果。
- 风控预警（M8）：判断全部风控规则，定义哪些预警与本车有关，向车辆履约列表提供本车未处理条数、向详情提供未处理与已处理条数及入口；M8、M9 在预警详情、审核详情中提供进入本模块的 VIN。
- 运营登录与企业管理（M2）：提供运营账号及状态、运营端菜单登记，以及无权访问的统一处理。
