# 汇率管理 · 功能与业务规则

2026-11-12｜运营端：运营管理员｜需求评审稿

本模块共三册：本册写功能、业务规则、字段规则与交互逻辑；[流程图与状态机](./02-汇率管理-流程图与状态机.md)画出主要流程与状态；[验收](./04-汇率管理-验收.md)供测试使用。本模块自己不发送任何消息，所以没有 03 消息通知册，并非缺失。

本册只定义汇率维护本身的信息需求与业务行为，页面布局、组件形态与交互承载由 Hallmark 决定。

## 1. 模块是什么

汇率管理是资产可信平台运营端的一项平台配置：运营管理员在这里人工维护美元与尼日利亚奈拉之间的汇率，统一表达为“1 USD = R NGN”（每 1 美元对应多少奈拉）。每次更新都新增一条汇率记录并立即生效，旧记录保留为历史，任何时候都能查到“当前用的是哪条汇率”以及“某一时刻适用的是哪条汇率”。本模块只负责把汇率维护准确、可追溯，并对外提供统一的汇率口径；平台中哪些功能使用汇率、怎样换算和展示，由使用汇率的模块在各自 PRD 中规划。

基本原则：

- **方向固定。** 汇率始终是“1 USD = R NGN”，R 大于 0；奈拉金额折合美元时用“奈拉金额 ÷ R”，美元金额折合奈拉时用“美元金额 × R”。
- **只增不改。** 已保存的汇率记录不能修改、不能删除；要改汇率只能再保存一条新的汇率，新汇率从保存成功那一刻起生效。
- **没有就是没有。** 平台还没有设置过汇率，或要查的时刻早于第一条汇率生效时，结果为“无可用汇率”，不用 0、1 或其他值代替。
- **人工维护。** 汇率由运营管理员手工录入并写明来源，平台不自动抓取、不定时更新。

**一个完整的例子。** 平台上线后，运营管理员甲第一次打开汇率管理，看到“尚未设置汇率”→ 甲点击更新汇率，录入 1,535.84 和来源说明“CBN 2026-11-12 官方汇率”，确认页显示“首次设置，1 USD = 1,535.84 NGN，保存后立即生效” → 甲确认保存，当前汇率变为 1 USD = 1,535.84 NGN，生效时间为保存成功的时刻，维护人是甲 → 一周后同事乙更新为 1,540.20，确认页显示当前值 1,535.84、新值 1,540.20、变动幅度 +0.28% → 乙保存后，乙的这条成为当前汇率；甲的那条在汇率历史中显示为已被替代，失效时间等于乙这条的生效时间 → 使用汇率的模块此后取“当前汇率”得到 1,540.20；取“甲保存后、乙保存前某一时刻适用的汇率”仍得到 1,535.84 及甲那条的编号、生效时间和来源说明。

### 1.1 需求清单

| 功能 | 谁 | 想做什么 | 为了什么 |
| --- | --- | --- | --- |
| [谁能使用汇率管理（FX-01）](#FX-01) | 运营管理员 | 在运营端使用本模块 | 只有运营人员能看和改汇率 |
| [查看当前汇率（FX-02）](#FX-02) | 运营管理员 | 看到现在生效的汇率及其依据 | 确认平台当前按什么汇率换算 |
| [更新汇率（FX-03）](#FX-03) | 运营管理员 | 录入新的汇率并立即生效 | 让汇率跟上实际变化 |
| [汇率历史（FX-04）](#FX-04) | 运营管理员 | 查看每一次汇率的值、生效区间、来源和维护人 | 解释某一时刻用的是哪条汇率 |
| [对外提供的汇率口径（FX-05）](#FX-05) | 使用汇率的模块 | 按统一口径取到当前汇率或某一时刻适用的汇率 | 各处使用的汇率一致、可追溯 |

### 1.2 本期不做

- 只有美元与奈拉这一组币种，不提供新增币种、任意币种对或多组汇率。
- 不接入外部行情，不自动或定时更新汇率。
- 不提供预约未来生效、追溯过去生效、停用汇率，也不提供修改或删除已保存的汇率。
- 不设审批或复核流程，保存即生效。
- 不提供汇率历史的导出。
- 不发送站内信、邮件或其他消息。
- 企业端没有汇率管理，也不展示本模块的任何信息。
- 不规划哪些功能使用汇率、换算结果怎样计算精度与展示、取哪个时刻的汇率；这些由使用汇率的模块在各自 PRD 中规划，见[与使用汇率模块的分工](#division)。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 汇率 | 1 美元对应的奈拉数量，记作 R，表达为“1 USD = R NGN” |
| 汇率记录 | 一次成功的更新汇率所保存的一条记录，包括汇率值、生效时间、来源说明、备注、维护人和汇率编号；保存后不可修改、不可删除 |
| 汇率编号 | 每条汇率记录的唯一编号，由平台在保存成功时生成，不复用；用于在汇率历史和使用汇率的模块中指认是哪一条 |
| 生效时间 | 汇率记录保存成功的时刻，从这一刻起该记录适用 |
| 失效时间 | 下一条汇率记录的生效时间；当前汇率没有失效时间 |
| 当前汇率 | 生效时间最晚的那条汇率记录 |
| 某一时刻适用的汇率 | 生效时间不晚于该时刻、且生效时间最晚的那条汇率记录 |
| 无可用汇率 | 平台没有任何汇率记录，或所查时刻早于第一条汇率记录的生效时间；此时没有汇率值 |
| 运营管理员 | 运营端的账号，由开发分配；本期运营端只有这一种角色，所有运营管理员权限相同 |

## 3. 谁能使用汇率管理（FX-01）

| 访问者 | 能否使用汇率管理 |
| --- | --- |
| 运营管理员，可正常使用 | 可以查看当前汇率和汇率历史，也可以更新汇率；所有运营管理员权限相同 |
| 运营管理员，待首次改密、已停用或锁定中 | 不能使用；完成首次改密或恢复后重新登录才能使用，判定以运营登录、企业邀请与企业管理（M2）为准 |
| 企业用户 | 企业端没有汇率管理入口；企业账号不能进入运营端 |
| 未登录 | 不能使用；直接打开本模块链接时按运营端的登录规则处理 |

- 登录已失效时提交更新的，本次不保存，当前汇率不变；重新登录后需重新填写并确认。
- 汇率信息只在运营端展示，不进入企业端，也不作为本模块对外的资产数据。

验收参见：[谁能使用汇率管理](./04-汇率管理-验收.md#ac-1)。

<a id="FX-02"></a>
## 4. 查看当前汇率（FX-02）

适用角色与前提：可正常使用的运营管理员。

- 已有汇率记录时，展示当前汇率的下列信息：

| 业务信息 | 含义 | 展示规则 |
| --- | --- | --- |
| 币种与方向 | 固定为“1 USD = R NGN” | 始终完整写出方向，不只写一个数字 |
| 汇率值 | 当前汇率的 R | 按[汇率值的展示](#rate-display)展示 |
| 生效时间 | 当前汇率保存成功的时刻 | 按[时间的展示](#time-display)展示 |
| 来源说明 | 维护人录入的汇率来源 | 按录入原文展示，不翻译 |
| 备注 | 维护人录入的补充说明 | 按录入原文展示；未填写时不显示该项 |
| 维护人 | 保存这条汇率的运营管理员 | 显示该运营账号的名称；账号之后停用或改名，仍显示保存时的名称 |
| 汇率编号 | 当前汇率记录的编号 | 原样展示 |

- 还没有任何汇率记录时，明确显示“尚未设置汇率”，不显示 0、1 或空白数值；提供更新汇率入口，首次设置即从这里开始。
- 从这里可以进入[汇率历史（FX-04）](#FX-04)；进入[更新汇率（FX-03）](#FX-03)的入口与是否已有汇率无关，始终可用。
- 其他运营管理员更新汇率后，重新打开或刷新即看到新的当前汇率。

<a id="rate-display"></a>
**汇率值的展示。**

- 固定展示 2 位小数，不足 2 位时补零，整数部分用千分位分隔。例如保存 1535.84 展示为 1,535.84，保存 1535.8 展示为 1,535.80，保存 1536 展示为 1,536.00。

<a id="time-display"></a>
**时间的展示。**

- 生效时间、失效时间精确到秒，按本人账号设置中的时区展示并标明时区；切换时区只改变展示，不改变时间本身和记录顺序。运营端的时区设置由 M2 提供。

验收参见：[查看当前汇率](./04-汇率管理-验收.md#ac-2)。

<a id="FX-03"></a>
## 5. 更新汇率（FX-03）

适用角色与前提：可正常使用的运营管理员；无论是否已有汇率都可以更新，首次设置也走本功能。

流程参见：[更新汇率（图 1）](./02-汇率管理-流程图与状态机.md#fig-1)。

### 5.1 填写

| 业务信息 | 含义/类型 | 必填与默认值 | 可编辑 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 币种与方向 | 固定为“1 USD = R NGN” | 固定值，无需填写 | 不可编辑 | 不适用 |
| 汇率值 | 1 美元对应的奈拉数量 R；数字 | 必填；不预填，当前汇率作为参照一并展示 | 可编辑 | 必须大于 0，最多 2 位小数，最小为 0.01；为空、为 0、为负数、不是数字或超过 2 位小数时不能提交，并说明原因；不自动舍入多出的小数位 |
| 来源说明 | 这次汇率从哪里来，例如“CBN 2026-11-12 官方汇率”；纯文本 | 必填；不预填 | 可编辑 | 去掉前后空格后 1～100 个字符；为空或只有空格、超过 100 个字符时不能提交，并说明原因 |
| 备注 | 内部补充说明；纯文本 | 选填；默认空 | 可编辑 | 去掉前后空格后最多 200 个字符；超过时不能提交，并说明原因 |

- 汇率值与当前汇率相同时不能提交，并说明“与当前汇率相同，无需更新”；不保存重复记录。是否相同按数值判断，例如 1535.8 与 1535.80 相同。
- 生效时间不由人填写，等于保存成功的时刻。
- 中途放弃时不保存任何内容，当前汇率不变。

<a id="confirm"></a>
### 5.2 确认并保存

- 提交前必须确认，确认时展示：币种与方向、当前汇率值（还没有汇率时写“首次设置”）、新汇率值、变动幅度、来源说明、备注（填写了才展示），以及“保存后立即生效；已保存的汇率不能修改或删除”。
- 变动幅度 =（新汇率值 − 当前汇率值）÷ 当前汇率值 × 100%，保留 2 位小数，四舍五入，带正负号；首次设置时不展示变动幅度。变动幅度只供核对，不设阈值，不阻止保存。
- 确认保存成功后：
  - 新增一条汇率记录，生成汇率编号，生效时间为保存成功的时刻，维护人为本人；
  - 这条记录立即成为当前汇率；原当前汇率变为已被替代，其失效时间等于新记录的生效时间；
  - 本人看到保存成功和新的当前汇率。
- 已被替代的汇率记录不改变任何内容，在[汇率历史（FX-04）](#FX-04)中保留。

### 5.3 异常与边界

| 情况 | 结果 |
| --- | --- |
| 填写或确认期间，其他运营管理员已保存了新汇率 | 本次不保存；说明汇率已被他人更新，并展示最新的当前汇率；本人需基于最新汇率重新确认后再提交，变动幅度按最新汇率重新计算 |
| 新汇率值与提交时的当前汇率相同（包括他人刚更新为同一值） | 本次不保存；说明与当前汇率相同，无需更新 |
| 网络或服务异常导致保存失败 | 说明本次未保存；当前汇率不变；已填写的内容保留，可以再次提交 |
| 结果未知时重复点击或再次提交 | 一次填写最多只生成一条汇率记录，不因重复提交产生两条 |
| 保存时登录已失效，或账号已被停用 | 本次不保存，当前汇率不变；按[谁能使用汇率管理（FX-01）](#FX-01)处理 |
| 录入了错误的汇率并已保存 | 已保存的记录不能修改或删除；需再更新一次正确的汇率，正确值从这次保存成功起生效，错误那条在其生效区间内仍是该区间适用的汇率，并留在汇率历史中 |

验收参见：[更新汇率](./04-汇率管理-验收.md#ac-3)。

## 6. 汇率历史（FX-04）

适用角色与前提：可正常使用的运营管理员。

- 列出全部汇率记录，按生效时间从晚到早排列，当前汇率排在最前并标明“当前汇率”。
- 每条记录展示：

| 业务信息 | 展示规则 |
| --- | --- |
| 汇率编号 | 原样展示 |
| 币种与方向、汇率值 | 写作“1 USD = R NGN”，R 按[汇率值的展示](#rate-display)展示 |
| 状态 | 当前汇率或已被替代，见[汇率记录的状态（状态机 1）](./02-汇率管理-流程图与状态机.md#state-1) |
| 生效时间 | 按[时间的展示](#time-display)展示 |
| 失效时间 | 已被替代的记录展示下一条记录的生效时间；当前汇率不展示失效时间，以“当前汇率”表示 |
| 变动幅度 | 相对上一条（更早一条）记录的变动幅度，算法与[确认并保存](#confirm)中的变动幅度相同；第一条记录展示“首次设置” |
| 来源说明 | 按录入原文展示，不翻译 |
| 备注 | 按录入原文展示；未填写时该项为空，不显示占位值 |
| 维护人 | 保存时的运营账号名称 |

- 历史中的每条记录都只能查看，不能修改、删除或恢复为当前汇率；要回到以前的某个值，只能再更新一次汇率。
- 记录永久保留。
- 还没有任何汇率记录时，显示“尚未设置汇率”。
- 只有保存成功的汇率会进入历史；未通过校验、未确认、保存失败的填写不留记录。

验收参见：[汇率历史](./04-汇率管理-验收.md#ac-4)。

<a id="FX-05"></a>
## 7. 对外提供的汇率口径（FX-05）

本节定义本模块向平台内使用汇率的模块提供什么、按什么规则提供；不列举使用方，也不规定使用方如何换算和展示。

判定规则参见：[某一时刻适用的汇率（图 2）](./02-汇率管理-流程图与状态机.md#fig-2)。

- 本模块提供两种取法，使用方按自己的业务规则选择：
  - **当前汇率**：取用时生效时间最晚的那条汇率记录。
  - **某一时刻适用的汇率**：使用方给出一个时刻 T，取生效时间不晚于 T、且生效时间最晚的那条汇率记录。T 正好等于某条记录的生效时间时，适用这条记录。
- 取得汇率时一并提供该记录的：汇率值、币种与方向（1 USD = R NGN）、生效时间、来源说明、汇率编号，便于使用方说明换算依据；备注只在本模块内查看，不对外提供。
- 没有符合条件的记录时，结果为“无可用汇率”，不提供汇率值，也不用 0、1、最近一条之后的记录或其他值代替。
- 汇率记录只增不改，因此同一时刻 T 适用的汇率不会因之后的更新而改变；之后更新只影响取当前汇率的结果。
- 汇率的方向以本模块为准：奈拉金额折合美元 = 奈拉金额 ÷ R；美元金额折合奈拉 = 美元金额 × R。使用方不得把 R 当作“1 NGN 对应的美元数”使用。

<a id="division"></a>
### 7.1 与使用汇率模块的分工

| 事项 | 归属 |
| --- | --- |
| 汇率的维护、生效、历史，以及当前汇率、某一时刻适用的汇率、无可用汇率的判定 | 本模块 |
| 哪些功能使用汇率，取当前汇率还是某一时刻适用的汇率 | 使用汇率的模块 |
| 换算结果的精度、舍入、展示位置与文案，以及无可用汇率时该功能如何表达 | 使用汇率的模块 |
| 换算结果与原币金额、实际收付款的关系，以及换算结果的可见范围（用户已确认换算价值只在运营端作为信息核对参考） | 使用汇率的模块，在各自 PRD 中遵守 |

验收参见：[对外提供的汇率口径](./04-汇率管理-验收.md#ac-5)。

## 8. 依赖

本模块没有待确认事项。

- 运营登录、企业邀请与企业管理（M2）提供运营管理员账号、登录与账号状态规则、账号名称，以及运营端账号设置中的界面语言与时区。本模块自身的文字提供中文、英文两套，按本人界面语言展示；来源说明和备注按录入原文展示。
- 使用汇率的模块按[对外提供的汇率口径（FX-05）](#FX-05)取用汇率，并在各自 PRD 中规划使用方式；本模块不因使用方增减而修改。
- 保存成功后，使用方取当前汇率即得到新记录；实现与验证归研发、测试。
