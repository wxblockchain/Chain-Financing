## 1. 模块是什么

本模块回答“应收账款里的这辆车，装上了哪条船、哪个集装箱，有没有保险，在目的港清关了没有，是否组装、质检、入库，最后有没有交给客户，中间有没有借出或退回，发生了哪些费用”。平台以应收账款的发票为入口：按发票销售清单中的 VIN 取得登记了该车的提单，再按提单取得保单，按提单中该车的集装箱号和船名航次取得清关登记，按提单或合同取得费用登记，并按 VIN 取得组装质检、入库、出库交付和异常事件记录。运营人员可以从应收账款（M3）、上游采购（M4）或下游销售（M6）中的某个 VIN 直接进入，看到这辆车的完整履约经历；也可以在车辆履约列表中按 VIN、提单号、集装箱号、保单号查找。本模块只供运营端使用，并为风控预警（M8）、运营审核与资产出库（M9）提供车辆履约事实和原件的查看入口。

基本原则：

- 车辆是本模块的主线。每辆车的履约资料按装船运输、保险、清关、组装质检、入库、出库交付的顺序集中查看，异常事件和费用随这辆车一起展示，不按单据拆成互不相连的列表。
- 提单是装船运输的批次。一张提单常装多辆车，每辆车装入的集装箱号以提单为准；保单、费用按提单覆盖其中全部车辆，清关登记按集装箱号与船名航次对应到车辆。车辆与单据、批次的对应关系在详情中逐项写明。
- 保单的保险金额、费用金额常覆盖多辆车，按原值展示并标明覆盖的车辆数，不分摊到单辆车，不计入应收账款的金额、回款或任何状态。
- 履约资料以 ERP 传值为准，字段名称和顺序沿用客户 ERP 的叫法。ERP 给出的是关键字段；本 PRD 定义的其他字段和记录默认 ERP 具备，未提供时按缺失规则展示。各金额的币种由 ERP 提供，本模块不做汇率折算。任何角色都不能在平台新增、修改或删除履约资料，也不能在平台办理调度、入库审批或退车。
- 车辆实物的出库与交付在本模块查看；资产数据的出库由运营审核与资产出库（M9）定义，两者分别记录、互不代替。
- 企业端（债权人、债务人）本期都看不到车辆履约资料。

**一个完整的例子**（企业、船公司、客户名称和单据编号为演示值）。应收账款 AR-0012（发票号码 INV-0012，卖方 Carloha Holding、买方 Carloha Nigeria，发票信息中的装船日期 2026-09-10）的销售清单含 VIN-A、VIN-B 两辆车，两车都列在合同 CT-0012 中。平台按这两个 VIN 取得提单 BL-5501：提单号 BL-5501，装船日期 2026-09-10，船公司“航运甲”，船名航次 OCEAN STAR 025W，发货人 Carloha Holding，收货人 Carloha Nigeria，装运港 Shanghai，卸货港 Lagos；提单共 4 辆车，VIN-A 装入集装箱 CSNU1234567，VIN-B 装入 CSNU7654321。勾选了 BL-5501 的保单 PL-889：关联合同 CT-0012，VIN-A、VIN-B 的售价各为 30,000.00 USD；保险日期 2026-09-09，保险公司“保险甲”，投保人和被保险人均为 Carloha Holding，保险金额 132,000.00 USD，覆盖 4 辆车。关联 BL-5501 的费用登记有两笔：海运费 3,600.00 USD、保险费 240.00 USD；只关联合同 CT-0012 的费用登记有一笔进口关税 9,800,000.00 NGN。清关登记一条：清关日期 2026-10-20，进口方 Carloha Nigeria，出口方 Carloha Holding，船名航次 OCEAN STAR 025W，集装箱号 CSNU1234567、CSNU7654321，平台据此把两辆车都对应到这条清关登记。之后 VIN-A 于 2026-10-25 入库“Lagos 一号仓”，2026-11-05 出库并交付给客户 Lagos Motors Ltd（客户号 C-0388），依据销售合同 SC-2045；VIN-B 于 2026-10-26 入库，2026-11-01 借出给展厅，2026-11-08 归还。运营人员在 AR-0012 的详情中点 VIN-B 进入本模块：先看到 AR-0012 两辆车的履约总览，VIN-A 履约进展为“已出库交付”，VIN-B 为“已入库”；点 VIN-B 的“查看”打开车辆履约详情，顶部看到 VIN-B、异常事件 2 条、核对提示“无”，下方的履约进度条显示装船、清关、入库三个环节已有记录，再依次查看提单与集装箱、保单、清关、费用、入库和借出归还记录及附件，然后返回 AR-0012。

### 1.2 本期不做

- 二手车业务。
- 在平台录入、编辑、删除或补传任何履约资料；运营端和企业端都没有这类操作。
- 车辆调度、订舱、入库或出库审批、借车或退车办理等实物业务操作。
- 船公司、保险公司、仓库、客户等交易对象入驻、账号或确认。
- 企业端查看车辆履约资料，包括债权人和债务人。
- 把保险金额、费用金额分摊到单辆车，或计算单车履约成本。
- 汇率折算：本模块不折算任何金额，不同币种的金额不相加。
- 对价格条款、保险权益、清关申报和税费作专业或合规结论。
- 人工认定车辆与单据的对应关系、记录核验结论：对应结果和核对提示只按资料自动展示，随资料更新重新判定。
- 资料进度统计（齐全程度、已取得项数）：各环节有无记录在履约进度条和对应位置如实展示。
- 退车、退订涉及的退款、冲销等款项：本期 ERP 不提供这类数据。
- 主体不一致、VIN 不一致的风控比对与处理：由 M8 定义，本模块只提供资料和预警入口。
- 资产数据出库、存证与供数：由 M9 定义。
- 外采订单、外采发票、VIN 登记等上游资料：由上游采购追溯（M4）定义。
- 下游销售合同、发票、收款：由下游销售与收款追溯（M6）定义。
- 中文、英文以外的语言。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 车辆履约 | 一辆车从装船到交付客户之间的实物经历，包括装船运输、保险、清关、组装质检、入库、出库交付，以及过程中的费用和异常事件 |
| 提单 | ERP 提单登记中的一张提单，含提单号、装船日期、船公司、船名航次、发货人、收货人、装运港、卸货港，以及所装车辆的 VIN 和每辆车的集装箱号。一张提单是一个运输批次 |
| 集装箱号 | 提单中登记的、某辆车装入的集装箱编号，用来把清关登记对应到车辆 |
| 保单 | ERP 保单登记中的一张保单，登记时勾选一张或多张提单，覆盖所勾选提单中的全部车辆 |
| 售价 | 保单登记时由 ERP 调取的车辆在合同中的单价 |
| 清关登记 | ERP 清关登记中的一条记录，含清关日期、进口方、出口方、船名航次、集装箱号；不直接列明 VIN |
| 费用登记 | ERP 费用登记中的一条记录，含费用类型、付款日期、收款方、付款方、费用金额，并关联合同、提单之一或两者 |
| 组装质检记录 | SKD 车辆在目的地组装完成与质检的记录，只对需要组装的车辆适用 |
| 入库记录 | 车辆进入仓库的记录 |
| 出库交付记录 | 车辆从仓库出库并交给客户的记录，即车辆实物出库；与 M9 的资产数据出库不同 |
| 车辆异常事件 | 正常交付之外实际发生的车辆流转，如提前交车、借出、归还、退车、退订，事件类型按 ERP 原值展示 |
| 履约进展 | 平台按已有记录判定的、一辆车已到达的最远履约环节，见[履约进展（F-M5-02）](#F-M5-02) |
| 履约进度条 | 按顺序展示五个履约环节，标明哪些环节已有记录及其日期，并突出履约进展所在环节 |
| 对应 | 平台按本册规则把某份单据或记录关联到某辆车的结果 |
| 核对提示 | 平台按资料自动给出、只供运营参考的差异说明；不是风控预警，不需要人工处理 |
| 客户 | 车辆交付的对象，即下游销售中的客户，按 ERP 原值展示客户名称和客户号，口径与 M6 一致 |
| 运营人员 | 运营端账号的使用者，即 M2 定义的运营管理员；本期运营端只有这一种角色，权限相同 |
| VIN | 车辆识别代号，用来从应收账款、上游采购或下游销售的车辆进入本模块 |

<a id="shared-rules"></a>
## 3. 共用展示与异常规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。展示口径与 M3 的[来源值、金额与时间](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#display-values)一致。

<a id="display-values"></a>
### 3.1 来源值、金额与时间

- 提单、保单、清关、费用及各类车辆履约记录的值按 ERP 原值展示，不翻译、不改写；切换中英文只改变平台自身的字段名称、状态名称和提示。
- ERP 没有提供某项值时，该项展示“未提供”；某份附件没有取得时，展示“附件未取得”；某个环节一条记录都没有时，展示“暂无记录”。
- 金额与币种代码同时展示，数值在前、币种代码在后，带千分位，例如“132,000.00 USD”。ERP 提供的金额按原值展示，不四舍五入、不截断。任何位置都不展示没有币种的金额。
- 各金额的币种由 ERP 提供。本模块不对任何金额做汇率折算，不同币种的金额不相加。
- ERP 提供的日期（装船日期、保险日期、清关日期、付款日期、组装完成日期、质检日期、入库日期、出库日期、交付日期、事件发生日期）按 ERP 日期原样展示，不做时区换算；ERP 随日期提供时区时，时区写在日期后面，不单独列为字段。
- 平台自己记录的时间（资料取得时间）展示到分钟并标注时区：按运营人员在 M2 账号设置中选择的时区展示；M2 不提供时区设置时统一按 UTC 展示。

<a id="file-view"></a>
### 3.2 附件查看

- 各类资料的文件统一以“附件”字段展示，可有多份；每份展示附件名称和取得时间，可在线查看和下载。
- 同一份文件支持多个环节或多辆车时只保存一份，在各处引用。
- 附件打开或下载失败时，提示“文件暂时无法打开，请稍后重试”，不影响查看其他信息。

<a id="no-access"></a>
### 3.3 不可访问

- 企业端没有任何车辆履约入口。企业用户通过链接打开本模块任何内容时，统一提示“该内容不存在或无权查看”，不透露其是否存在及任何内容。
- 运营人员处于待首次改密、已停用或锁定中时不能使用本模块，判定以 M2 为准。

<a id="load-fail"></a>
### 3.4 加载失败

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的金额或进展，避免把加载失败误显示为“暂无记录”或“暂无履约记录”。
- 详情中某一部分（例如清关、费用、关联应收账款）加载失败时，仅该部分提示失败并可重试，其他部分正常展示。

## 4. 履约资料的取得与关联（F-M5-01）

| 保单登记 | 关联信息：勾选的提单，以及由提单调取的车辆 VIN、关联合同号、售价 | [保单](#field-policy)中的关联提单、覆盖车辆、关联合同号码与售价 |
| 保单登记 | 保单信息：保单号、保险日期、保险公司、投保人、被保险人、保险金额 | [保单](#field-policy) |
| 费用登记 | 费用类型、付款日期、收款方、付款方、费用金额、关联合同、关联提单 | [履约费用](#field-fee) |
| 清关登记（ERP 入库管理下） | 清关日期、进口方、出口方、船名航次、集装箱号 | [清关登记](#field-customs) |

以下记录客户 ERP 未单独列出，按本 PRD 定义的字段默认 ERP 具备，ERP 未提供时对应环节展示“暂无记录”：[组装质检记录](#field-assembly)、[入库记录](#field-inbound)、[出库交付记录](#field-delivery)、[车辆异常事件](#field-event)，以及各类资料的附件。

- 保费、税费不另设字段，以费用登记中的费用类型（如保险费、关税）体现，按 ERP 原值展示。
- ERP 保单登记中的关联合同号按“合同号码”展示。

<a id="link-rules"></a>
### 4.2 取得资料与对应到车辆

平台以应收账款发票销售清单中的 VIN 为入口，按下表取得资料并对应到车辆：

| 资料 | 取得方式 | 对应到哪些车辆 |
| --- | --- | --- |
| 提单 | 取得登记了该 VIN 的全部提单 | 提单货物信息中勾选的全部车辆；每辆车的集装箱号以该提单的集装箱信息为准 |
| 保单 | 取得勾选了上述提单的全部保单 | 保单所勾选提单中的全部车辆 |
| 清关登记 | 取得含上述提单中车辆集装箱号的清关登记 | 按[清关登记与车辆的对应](#customs-match)判定 |
| 费用登记 | 取得关联了上述提单，或关联了该车所在合同的费用登记 | 关联了提单的，对应该提单中的全部车辆；只关联合同的，对应该合同列明的全部车辆 |
| 组装质检、入库、出库交付记录、车辆异常事件 | 按 VIN 取得 | 记录所列的那辆车 |

- “该车所在合同”指 M3 中车辆 VIN 列明了该车的合同。
- 同一 VIN 出现在多张提单中时，每张提单都对应到该车，由[核对提示](#check-hints)如实标出。
- 费用登记既关联提单又关联合同时，按提单对应车辆，同时展示关联合同号码；两者都未提供时无法对应车辆，不在本模块展示。
- 提单、保单中不在任何应收账款销售清单中的车辆，照常展示在对应提单和保单的车辆中，标“未关联应收账款”。
- 平台以“提单号”识别同一张提单，以“保险公司 + 保单号”识别同一张保单；清关登记、费用登记和各类车辆履约记录没有单据号码，以 ERP 中的同一条登记记录识别。

<a id="customs-match"></a>
### 4.3 清关登记与车辆的对应

清关登记不列明 VIN，平台按提单中该车的集装箱号与船名航次对应：

| 对应结果 | 判定条件 | 运营看到 |
| --- | --- | --- |
| 已对应 | 清关登记的集装箱号中有该车所在提单登记的集装箱号，且清关登记的船名航次与该提单的船名航次一致 | 该清关登记计入这辆车的清关环节 |
| 船名航次不一致 | 集装箱号一致，但清关登记的船名航次与提单不一致或未提供 | 列为“其他含该集装箱号的清关登记”并说明原因，不计入这辆车的清关环节 |
| 无法对应 | 提单未登记该车的集装箱号 | 清关环节展示“提单未登记该车的集装箱号，无法对应清关登记” |

- 集装箱号和船名航次按 ERP 原值比对，不区分大小写，忽略空格。
- 同一集装箱号可能在不同航次重复使用，因此只凭集装箱号一致不计入清关环节。
- 一辆车对应多条清关登记时全部列出，按清关日期从新到旧排列，并给出[核对提示](#check-hints)。

<a id="data-update"></a>
### 4.4 资料更新

- 履约资料随 ERP 持续补充。ERP 再次提供同一份资料且内容一致时，不重复展示，也不产生变化记录。
- 内容不同（含提单车辆增减、集装箱号变化、金额变化、附件更换）时，新内容成为当前展示内容，之前的版本保留在[资料补充记录](#supplement-log)中，不覆盖删除。
- ERP 不再提供某份资料时，该资料从当前展示中移除，移除记录保留在资料补充记录中。
- 资料更新后，车辆对应、[清关登记与车辆的对应](#customs-match)、[履约进展](#progress-rule)和[核对提示](#check-hints)都按最新资料重新判定。
- 履约资料的更新不改变应收账款（M3）的销售清单、装船日期、金额、回款和任何状态。

<a id="F-M5-02"></a>
## 5. 履约进展（F-M5-02）

适用范围：平台对每辆车判定履约进展，在列表、追溯总览中展示履约进展，在车辆履约详情中以履约进度条展示。结果对运营人员可见，没有用户操作。

流程参见：[履约进展（图 M5-3）](./02-车辆物流与履约追溯-流程图与状态机.md#fig-m5-3)。
验收参见：[履约进展](./04-车辆物流与履约追溯-验收.md#acc-f-m5-02)。

<a id="progress-rule"></a>
### 5.1 判定规则

履约环节按以下顺序排列，每个环节有至少一条对应到该车的记录即视为“已有记录”：

| 顺序 | 履约环节 | 视为已有记录的条件 | 环节日期 |
| --- | --- | --- | --- |
| 1 | 装船运输 | 有提单对应到该车 | 提单装船日期，多张提单时取最晚的一个 |
| 2 | 清关 | 有清关登记按[清关登记与车辆的对应](#customs-match)为“已对应” | 清关日期，多条时取最晚的一个 |
| 3 | 组装质检 | 有该车的组装质检记录 | 组装完成日期与质检日期中较晚的一个 |
| 4 | 入库 | 有该车的入库记录 | 入库日期，多条时取最晚的一个 |
| 5 | 出库交付 | 有该车的出库交付记录 | 交付日期；未提供时取出库日期 |

履约进展取已有记录的最远环节：

| 履约进展 | 判定条件 |
| --- | --- |
| 暂无履约记录 | 五个环节都没有记录 |
| 已装船 | 最远的已有记录环节为装船运输 |
| 已清关 | 最远的已有记录环节为清关 |
| 已组装质检 | 最远的已有记录环节为组装质检 |
| 已入库 | 最远的已有记录环节为入库 |
| 已出库交付 | 有出库交付记录 |

- 保单和费用不是履约环节，不影响履约进展；它们随提单、合同查看。
- 组装质检只对 SKD 车辆适用。没有组装质检记录不表示缺失，前后环节有记录时照常判定。
- 环节日期未提供时，该环节仍视为已有记录，日期展示“未提供”。
- 前序环节没有记录、后续环节已有记录时，按最远环节判定，前序环节如实展示“暂无记录”，不推断前序环节已发生。
- 履约进展只描述已有记录，不表示车辆当前所在位置，也不是审核结论；不影响确权申请、运营审核或出库。
- 资料被更正或移除后，按最新资料重新判定，履约进展可以后退。

<a id="progress-bar"></a>
### 5.2 履约进度条

- 车辆履约详情中，紧接在[车辆与关联应收账款](#field-vehicle)下面，以进度条依次展示装船运输、清关、组装质检、入库、出库交付五个环节。
- 已有记录的环节标为已完成并展示环节日期；履约进展所在环节标为当前环节；没有记录的环节展示“暂无记录”。
- 前序环节没有记录、后续环节已有记录时，进度条如实展示中间的“暂无记录”，不补全。
- 组装质检没有记录时标注“适用于 SKD 车辆”。

<a id="progress-combo"></a>
### 5.3 履约进展与异常事件、核对提示的组合

一辆车的履约进展、[车辆异常事件](#F-M5-12)、[核对提示](#check-hints)是三个独立维度，互不覆盖：

| 履约进展 | 车辆异常事件 | 核对提示 | 运营看到 |
| --- | --- | --- | --- |
| 任一 | 无 | 无 | 详情顶部异常事件为“无”、核对提示为“无”；进度条照常展示 |
| 任一 | 有 | 无 | 详情顶部展示异常事件条数和最近一条事件的类型与日期；进度条照常展示 |
| 任一 | 任一 | 有 | 在上述基础上，详情顶部核对提示为“有”，并在对应信息类别中说明差异 |
| 已出库交付 | 最近一条为退车或退订 | 任一 | 履约进展仍为“已出库交付”；详情顶部最近一条事件展示为该退车或退订事件，平台不推断车辆已回到仓库 |

<a id="F-M5-03"></a>
## 6. 运营查看车辆履约列表（F-M5-03）

适用角色与前提：可正常使用的运营人员。可查看平台已取得履约资料或出现在应收账款销售清单中的全部车辆。

验收参见：[运营查看车辆履约列表](./04-车辆物流与履约追溯-验收.md#acc-f-m5-03)。

列表以车辆为单位，每个 VIN 一行，只展示定位和判断所需的关键字段；集装箱号、各环节日期、异常事件和核对提示等在详情中查看：

| 业务信息 | 含义 | 来源与缺失时 |
| --- | --- | --- |
| VIN | 车辆识别代号 | 不会缺失 |
| 车型 | 取自 M3 销售清单中该车的车型 | M3 原值；车辆未关联应收账款或 M3 未提供时展示“未提供” |
| 关联应收账款 | 该车出现在哪些应收账款的销售清单中，展示应收账款编号；超过一笔时展示笔数 | 平台判定；没有时展示“未关联应收账款” |
| 提单号 | 对应到该车的提单号；超过一张时展示张数 | ERP 原值；没有时展示“暂无记录” |
| 装船日期 | 装船运输环节日期 | 见[判定规则](#progress-rule)；没有提单时展示“暂无记录” |
| 履约进展 | 见[判定规则](#progress-rule) | 平台判定 |
| 操作 | “查看”，进入该车的[车辆履约详情（F-M5-05）](#F-M5-05) | 每行都有 |

查找与筛选：

- 按 VIN 查找，支持部分匹配。
- 按提单号、集装箱号、保单号查找，支持部分匹配；结果为该提单、该集装箱或该保单覆盖的全部车辆。
- 按应收账款编号或应收账款的发票号码查找，结果为该应收账款销售清单中的全部车辆。
- 筛选：履约进展、船公司、卸货港、是否有异常事件、是否有核对提示、是否关联应收账款、装船日期区间。多个条件同时生效。
- 默认按装船日期从新到旧排列；没有提单或装船日期未提供的排在最后。

边界与异常：

- 平台尚未取得任何车辆时，展示“暂无车辆履约资料”；有车辆但查找或筛选无结果时，展示“没有符合条件的车辆”并可清除条件。
- 列表不提供新增、编辑、删除操作。
- 加载失败按[加载失败](#load-fail)处理。

<a id="F-M5-04"></a>
## 7. 按应收账款车辆追溯（F-M5-04）

适用角色与前提：可正常使用的运营人员。从应收账款（M3）详情的车辆信息明细中点某个 VIN 进入（见 M3 [关联追溯与风控入口](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#trace-entry)），或从上游采购（M4）、下游销售（M6）的按应收账款车辆追溯中点某辆车进入，带入该应收账款作为追溯对象和返回目标。

流程参见：[各入口与返回路径（图 M5-4）](./02-车辆物流与履约追溯-流程图与状态机.md#fig-m5-4)。
验收参见：[按应收账款车辆追溯](./04-车辆物流与履约追溯-验收.md#acc-f-m5-04)。

<a id="trace-receivable"></a>
### 7.1 从应收账款进入

展示本笔应收账款的车辆履约总览，并定位到所点的 VIN。总览上方展示追溯对象：

| 业务信息 | 含义 | 来源与缺失时 |
| --- | --- | --- |
| 应收账款编号、发票号码 | 追溯对象，取自 M3 | M3 原值 |
| 卖方、买方 | 取自 M3 | M3 原值 |
| 装船日期 | M3 发票信息中的装船日期 | M3 原值；未提供时展示“未提供” |
| 车辆数量 | 本笔应收账款销售清单的车辆数 | M3 原值 |
| 履约进展汇总 | 各履约进展各几辆，如“已出库交付 1 辆、已入库 1 辆” | 平台判定 |

下方每辆车一行：

| 业务信息 | 含义 | 来源与缺失时 |
| --- | --- | --- |
| VIN、车型 | 取自 M3 销售清单 | M3 原值 |
| 提单号 | 对应到该车的提单号；超过一张时展示张数 | ERP 原值；没有时展示“暂无记录” |
| 履约进展 | 见[判定规则](#progress-rule) | 平台判定 |
| 操作 | “查看”，进入该车的车辆履约详情，并带上本笔应收账款作为对照对象和返回目标 | 每行都有 |

- 每辆车都可进入上游采购（M4）、下游销售（M6）查看同一 VIN，并带上本笔应收账款作为返回目标。
- 可返回进入前的位置（M3 应收账款详情，或 M4、M6 中的追溯总览）。

<a id="trace-vin"></a>
### 7.2 按 VIN 查找进入

- 从列表或其他模块按 VIN 进入、没有带入应收账款时，直接进入该车的[车辆履约详情（F-M5-05）](#F-M5-05)，详情中列出该车出现在哪些应收账款中。
- 该 VIN 既不在任何应收账款中、也没有任何履约资料时，展示“未找到该 VIN 的车辆履约资料”。

边界与异常：

- 从其他模块带入的 VIN 已不在该应收账款当前展示的销售清单中时，按该应收账款当前销售清单展示总览，不定位到该 VIN，并说明“该车已不在本笔应收账款的销售清单中”。
- 加载失败按[加载失败](#load-fail)处理。

## 8. 车辆履约详情（F-M5-05）

适用角色与前提：可正常使用的运营人员，从车辆履约列表、按应收账款车辆追溯、M4、M6、M8 或 M9 进入。详情只读，任何角色都没有编辑、补传入口。

验收参见：[车辆履约详情](./04-车辆物流与履约追溯-验收.md#acc-f-m5-05)。

<a id="detail-groups"></a>
### 8.1 详情的信息分类与顺序

详情顶部展示 VIN、车型，以及异常事件（“无”，或条数及最近一条的事件类型与日期）、核对提示（有／无）。这些内容已在顶部展示，下方各类信息中不再重复。

顶部之下按履约顺序分类：

1. [车辆与关联应收账款](#field-vehicle)。
2. [履约进度条](#progress-bar)：紧接在车辆与关联应收账款下面。
3. [装船运输与提单（F-M5-06）](#F-M5-06)。
4. [保险（F-M5-07）](#F-M5-07)。
5. [清关（F-M5-08）](#F-M5-08)。
6. [履约费用（F-M5-09）](#F-M5-09)。
7. [组装与质检（F-M5-10）](#F-M5-10)。
8. [入库与出库交付（F-M5-11）](#F-M5-11)。
9. [车辆异常事件（F-M5-12）](#F-M5-12)。

[资料补充记录](#supplement-log)、[核对提示](#check-hints)的差异说明和[关联风控预警](#risk-entry)另行提供，展示位置由设计确定。

从按应收账款车辆追溯进入时，详情带上该应收账款作为对照对象，并展示与该应收账款有关的核对提示。

<a id="field-vehicle"></a>
### 8.2 车辆与关联应收账款

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 关联应收账款 | 该车出现在其销售清单中的全部应收账款，以列表直接展示：应收账款编号、发票号码、卖方、买方、M3 发票信息中的装船日期；每笔都可进入 M3 应收账款详情 | 展示“未关联应收账款” |
| 所在合同 | M3 中列明该车的合同号码 | 展示“未提供” |

- VIN、车型已在详情顶部展示，本类不重复。
- 详情中可进入上游采购（M4）、下游销售（M6）查看同一 VIN。

<a id="F-M5-06"></a>
## 9. 装船运输与提单（F-M5-06）

- 从其他模块带入的应收账款或 VIN 已不存在时，展示“该内容不存在或已更新”，并可返回来源位置。

## 18. 待确认事项与依赖

本模块当前没有待确认事项。

依赖：

- ERP：提供内部销售下的提单登记、保单登记、费用登记，以及入库管理下的清关登记，字段见[ERP 资料与本模块的对应](#erp-mapping)；组装质检、入库、出库交付、车辆异常事件记录，各金额币种及各类附件等本 PRD 定义的其他字段默认 ERP 具备，未提供时按缺失规则展示。取得方式由研发决定。
- 应收账款与发票（M3）：提供应收账款编号、发票号码、卖方、买方、发票信息中的装船日期、销售清单（VIN、车型）、合同及其列明的 VIN，以及从 VIN 进入本模块的入口和返回目标。
- 上游采购追溯（M4）、下游销售与收款追溯（M6）：按 VIN 进入本模块并可返回；本模块按 VIN 进入两者。
- M1、M2：提供运营人员账号及状态、运营端账号设置中的界面语言与时区。
- 风控预警（M8）：使用本模块的提单、清关等车辆资料进行 VIN 比对，向本模块提供关联预警数量与入口。
- 运营审核与资产出库（M9）：从审核中进入本模块查看车辆履约事实和附件，是否以本模块资料作为审核依据由 M9 定义；资产数据出库在 M9 记录。
