# 上游采购追溯 · 功能与业务规则

2026-11-12｜运营端：运营人员｜需求评审稿

本模块共三册：本册写功能、业务规则与字段规则；[流程图与状态机](./02-上游采购追溯-流程图与状态机.md)画出主要流程与状态；[验收](./04-上游采购追溯-验收.md)供测试使用。本模块自身不发送任何消息，所以没有 03 消息通知册，并非缺失。

编号说明：功能编号（F-M4-*）标在章节标题上，供验收追溯。文中“M1”—“M11”均指资产可信平台的同级模块；“应收账款”及其字段、状态以[应收账款与发票（M3）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md)为准。

本册只定义信息需求与业务行为；页面布局与交互承载由 Hallmark 设计决定。以下设计约束由用户指定，保持不变：分类清晰、页面层级少，可有多个二级菜单。

## 1. 模块是什么

本模块回答“应收账款里的这辆车，是卖方向哪家供应商、按哪张外采订单买来的，供应商开了什么形式发票，采购款付了多少”。平台以应收账款的发票为入口：按发票销售清单中的 VIN 找到 ERP 的 VIN 登记，再取得该 VIN 所属的外采订单，以及订单下的外采发票、外采付款和全部 VIN 登记。这些资料以外采订单为单位组成一笔采购交易。运营人员可以从应收账款（M3）中的某个 VIN 直接进入，看到这辆车对应的采购交易，以及这笔采购是否确实由本笔应收账款的卖方购入；也可以在上游采购列表中按 VIN、订单号码、形式发票号码查找全部采购交易。本模块只供运营端使用，并为风控预警（M8）、运营审核与资产出库（M9）提供已有采购事实和原件的查看入口。

基本原则：

- 上游采购是本笔应收账款的卖方（M3 中的债权人一方）向供应商采购车辆的交易，与形成应收账款的发票是两笔不同的交易。外采发票单独展示，不并入应收账款的发票，不改变应收账款的任何金额和状态。
- 外采订单、外采发票、外采付款、VIN 登记随同一采购交易一起展示，不按单据拆成互不相连的列表。
- VIN 相同不等于这笔采购就属于本笔应收账款：平台同时比对外采订单的买方是否就是本笔应收账款的卖方，结果如实标出，不自动认定、不自动排除。
- 外采订单和外采发票常覆盖多辆车。订单金额、发票金额按原值展示并标明覆盖的车辆数，不当作本笔应收账款车辆的采购金额；本笔应收账款车辆只看各自的采购单价。
- 上游采购资料以 ERP 传值为准。ERP 给出的是关键字段；本 PRD 定义的其他字段默认 ERP 具备，未提供时按缺失规则展示。各金额的币种由 ERP 提供，本模块不做汇率折算。任何角色都不能在平台新增、修改或删除上游资料。
- 企业端（债权人、债务人）本期都看不到上游采购资料；供应商只是交易对象，没有平台账号或确权职责。

**一个完整的例子**（企业与供应商名称为演示值）。应收账款 AR-0012（发票号码 INV-0012，卖方 Carloha Holding、买方 Carloha Nigeria）的销售清单含 VIN-A、VIN-B 两辆车。平台按这两个 VIN 找到 ERP 的 VIN 登记，取得它们所属的外采订单 PO-031：日期 2026-07-15，买方 Carloha Holding，卖方（供应商）主机厂甲，采购明细为型号甲、单价 20,000.00 USD、数量 10，金额 200,000.00 USD，未开票金额 0.00 USD。订单下有外采发票 PI-778：形式发票号码 PI-778，日期 2026-07-16，金额 200,000.00 USD；有两笔外采付款：2026-07-20 付款 60,000.00 USD、2026-08-15 付款 140,000.00 USD，ERP 给出该形式发票未付金额 0.00 USD；VIN 登记共 10 个 VIN，含 VIN-A、VIN-B。平台把这些资料组成采购交易 PO-031，外采发票付款状态和订单付款情况都是“已付清”。另有一张外采订单 PO-090 的 VIN 登记中也有 VIN-B，但买方是企业丙。运营人员在 AR-0012 的详情中点 VIN-B 进入本模块：看到 AR-0012 的 2 辆车里，VIN-A、VIN-B 的归属结果都是“已对应”，对应采购交易 PO-031；VIN-B 下另列“其他登记了该 VIN 的采购交易”PO-090，标“买方与应收账款卖方不一致”。运营人员打开 PO-031，看到订单金额 200,000.00 USD 标明“覆盖 10 辆车，其中本笔应收账款 2 辆”，本笔应收账款车辆采购单价合计 40,000.00 USD；查看形式发票和付款凭证原件后，返回 AR-0012。

### 1.2 本期不做

- 二手车业务。
- 在平台录入、编辑、删除或补传任何上游采购资料；运营端和企业端都没有这类操作。
- 供应商（主机厂）入驻、账号、确认或确权。
- 企业端查看上游采购资料，包括债权人和债务人。
- 把外采发票合并为应收账款的发票，或用上游采购金额改变应收账款金额、回款或到期状态。
- 把付款拆分到单辆车或单笔应收账款，以及计算单车成本、毛利。
- 汇率折算：本模块不折算任何金额，不同币种的金额不相加。
- 人工认定车辆归属或记录核验结论：归属结果和核对提示只按资料自动展示，随资料更新重新判定。
- 主体不一致、VIN 不一致的风控比对与处理：由 M8 定义，本模块只提供资料和预警入口。
- 提单、保单、费用、清关等车辆履约资料：由车辆物流与履约追溯（M5）定义。
- 下游销售与收款资料：由下游销售与收款追溯（M6）定义。
- 中文、英文以外的语言。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 上游采购 | 应收账款的卖方向供应商采购车辆的交易。归入“上游采购”信息大类，与应收账款（M3）、下游销售（M6）中的合同和发票以所属大类区分 |
| 外采订单 | ERP 中卖方向供应商下的采购订单，含订单号码、日期、买方、卖方（供应商）、采购明细（型号、单价、数量）、金额、未开票金额 |
| 供应商 | 外采订单的卖方，通常是主机厂，按 ERP 原值展示；在平台中只是交易对象 |
| 未开票金额 | ERP 外采订单中的“合同未开票金额”，即订单中供应商尚未开具形式发票的金额 |
| 外采发票 | ERP 中供应商就外采订单开出的形式发票（PI）。每张外采发票对应一张外采订单，一张订单可以有多张外采发票 |
| 未付金额 | ERP 外采发票中的“发票未付金额”，即该形式发票尚未支付的金额 |
| 外采付款 | ERP 中针对某一张形式发票登记的付款记录，付款金额为收款方实际收到的金额。定金、尾款等分次付款各为一条 |
| VIN 登记 | ERP 中登记的采购车辆 VIN，每个 VIN 属于一张外采订单。外采订单和外采发票只按型号列明数量，车辆具体是哪些 VIN 以 VIN 登记为准 |
| 采购交易 | 一张外采订单，以及该订单下的外采发票、外采付款和 VIN 登记。上游采购列表以采购交易为单位 |
| 采购单价 | 某辆车按其型号在外采订单采购明细中的单价 |
| 归属结果 | 对“本笔应收账款的某辆车”判定的上游采购对应情况：已对应、多笔采购、买方不一致、未找到上游采购 |
| 核对提示 | 平台按资料自动给出、只供运营参考的差异说明；不是风控预警，不需要人工处理 |
| 运营人员 | 运营端账号的使用者，即 M2 定义的运营管理员；本期运营端只有这一种角色，权限相同 |
| VIN | 车辆识别代号，用来从应收账款的车辆进入本模块 |

## 3. 共用展示与异常规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。展示口径与 M3 的[来源值、金额与时间](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#display-values)一致。

<a id="display-values"></a>
### 3.1 来源值、金额与时间

- 外采订单、外采发票、外采付款、VIN 登记的各项值按 ERP 原值展示，不翻译、不改写；切换中英文只改变平台自身的字段名称、状态名称和提示。
- ERP 没有提供某项值时，该项展示“未提供”；某份附件没有取得时，展示“附件未取得”。
- 金额与币种代码同时展示，数值在前、币种代码在后，带千分位，例如“200,000.00 USD”。ERP 提供的金额按原值展示，不四舍五入、不截断。任何位置都不展示没有币种的金额。
- 各金额的币种由 ERP 提供。本模块不对任何金额做汇率折算，不同币种的金额不相加。
- ERP 提供的日期（订单日期、形式发票日期、付款日期）按 ERP 日期原样展示，不做时区换算。
- 平台自己记录的时间（资料取得时间）展示到分钟并标注时区：按运营人员在 M2 账号设置中选择的时区展示；M2 不提供时区设置时统一按 UTC 展示。

<a id="file-view"></a>
### 3.2 附件查看

- 每份附件展示附件名称和取得时间，可在线查看和下载。
- 同一份文件支持多个环节时只保存一份，在各环节引用。
- 附件打开或下载失败时，提示“文件暂时无法打开，请稍后重试”，不影响查看其他信息。

<a id="no-access"></a>
### 3.3 不可访问

- 企业端没有任何上游采购入口。企业用户通过链接打开本模块任何内容时，统一提示“该内容不存在或无权查看”，不透露其是否存在及任何内容。
- 运营人员处于待首次改密、已停用或锁定中时不能使用本模块，判定以 M2 为准。

<a id="load-fail"></a>
### 3.4 加载失败

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的金额或状态，避免把加载失败误显示为“未付款”“未取得”或“未找到上游采购”。
- 详情中某一部分（例如外采付款、关联应收账款）加载失败时，仅该部分提示失败并可重试，其他部分正常展示。

### 4.1 ERP 资料与本模块的对应

| ERP 功能 | ERP 字段 | 在本模块中的位置 |
| --- | --- | --- |
| 外采订单 | 订单号码、日期、买方、卖方（供应商）、型号、单价、数量、金额、合同未开票金额 | [外采订单](#field-order)；未开票金额即合同未开票金额 |

| 外采付款 | 发票信息（发票号码与日期、买方、卖方、发票金额，由所选形式发票带出） | 外采付款归入该形式发票，发票信息在[外采发票](#field-invoice)中展示，[付款记录](#field-payment)中只展示对应形式发票号码 |
| 外采付款 | 付款交易编号、付款日期、收款方、付款方、付款银行、付款账号、付款金额（收款方收到）、发票未付金额 | [付款记录](#field-payment) |
| VIN 登记 | VIN 码 | [VIN 登记与车辆明细](#field-vehicles) |

<a id="trade-identity"></a>
### 4.2 取得资料与组成采购交易

- 平台以应收账款的发票为入口：对发票销售清单中的每个 VIN，取得登记了该 VIN 的 VIN 登记，再取得其所属的外采订单，以及该订单下的全部外采发票、外采付款和 VIN 登记。
- 平台以“卖方（供应商）+ 订单号码”识别同一张外采订单；首次取得时形成一笔采购交易。
- 外采发票归入其对应外采订单所在的采购交易；外采付款归入其对应的外采发票；VIN 登记归入其所属外采订单所在的采购交易。
- 同一 VIN 被登记在多张外采订单下时，每张订单都形成采购交易，由[车辆归属判定（F-M4-02）](#F-M4-02)如实标出。
- ERP 有该 VIN 的 VIN 登记、但没有给出所属外采订单时，该 VIN 不形成采购交易，归属结果为“未找到上游采购”，并说明“该 VIN 已在 ERP 登记，但未对应外采订单”。
- 同一张外采发票（以“卖方 + 形式发票号码”识别）、同一笔外采付款（以付款交易编号及对应形式发票识别）、同一条 VIN 登记再次取得且内容一致时，不重复展示，也不产生变化记录。

<a id="trade-update"></a>
### 4.3 资料更新

- 上游采购资料随 ERP 持续补充。ERP 再次提供同一份资料但内容不同（含 VIN 增减、金额变化、未开票金额或未付金额变化、附件更换）时，新内容成为当前展示内容，之前的版本保留在[资料补充记录](#supplement-log)中，不覆盖删除。
- ERP 不再提供某份资料时，该资料从当前展示中移除，移除记录保留在资料补充记录中。
- 资料更新后，[车辆归属判定（F-M4-02）](#F-M4-02)、[付款状态与付款情况](#pay-status)和[核对提示](#check-hints)都按最新资料重新判定。
- 上游资料的更新不改变应收账款（M3）的销售清单、金额、回款和任何状态。

适用范围：平台对“应收账款中的每一辆车”判定其上游采购对应情况。结果对运营人员可见，没有用户操作。

流程参见：[车辆归属判定（图 M4-2）](./02-上游采购追溯-流程图与状态机.md#fig-m4-2)。
验收参见：[车辆归属判定](./04-上游采购追溯-验收.md#acc-f-m4-02)。

<a id="attribution"></a>
### 5.1 判定规则

对应收账款 R 销售清单中的某个 VIN：

1. 找出 VIN 登记中有该 VIN 的全部采购交易。
2. 逐笔比对外采订单的买方与 R 的卖方主体。比对方式与 M3 中[买卖双方与平台企业的对应](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#party-match)相同：卖方已对应平台企业时，与该平台企业登记的企业主体信息比对；未对应时，与 R 发票上的卖方主体信息比对。订单买方未提供时视为比对不一致。本期按主体本身比对，不把关联公司视为同一主体。
3. 按下表得出归属结果：

| 归属结果 | 判定条件 | 运营看到 |
| --- | --- | --- |
| 已对应 | 恰有 1 笔登记了该 VIN 的采购交易，其订单买方与 R 的卖方比对一致 | 对应的采购交易；买方不一致的其他采购交易另列为“其他登记了该 VIN 的采购交易”，逐笔说明原因 |
| 多笔采购 | 有 2 笔及以上登记了该 VIN 的采购交易，其订单买方与 R 的卖方比对一致 | 全部列出，按订单日期从新到旧；平台不判断哪一笔是本车的实际采购 |
| 买方不一致 | 有登记了该 VIN 的采购交易，但订单买方都与 R 的卖方比对不一致 | 全部列出，逐笔标“买方与应收账款卖方不一致”或“买方未提供”；这些采购交易不视为本笔应收账款车辆的上游采购 |
| 未找到上游采购 | 没有任何采购交易登记了该 VIN | 展示“未找到该车的上游采购资料”；属于[已登记但未对应外采订单](#trade-identity)时另加该说明 |

- 归属结果是事实标注，不是审核结论，也不是风控预警；运营人员不需要也不能在本模块认定或更改归属结果。
- 同一 VIN 出现在多笔应收账款中时，对每笔应收账款分别判定，互不影响。
- 资料更新后自动重新判定，例如补充了 VIN 登记后“未找到上游采购”可变为“已对应”。
- 是否构成主体不一致、VIN 不一致的风控预警，由 M8 判定。

## 6. 运营查看上游采购列表（F-M4-03）

适用角色与前提：可正常使用的运营人员。可查看平台已取得的全部采购交易。

验收参见：[运营查看上游采购列表](./04-上游采购追溯-验收.md#acc-f-m4-03)。

列表以采购交易为单位，每行一笔：

| 业务信息 | 含义 | 来源与缺失时 |
| --- | --- | --- |
| 订单号码 | 外采订单号码 | ERP 原值 |
| 日期 | 外采订单日期 | ERP 原值；未提供时展示“未提供” |
| 买方 | 外采订单的买方 | ERP 原值；未提供时展示“未提供” |
| 卖方（供应商） | 外采订单的卖方 | ERP 原值；未提供时展示“未提供” |
| 数量 | 外采订单采购明细的数量合计 | ERP 原值合计；未提供时展示“未提供” |
| 已登记 VIN 数 | 本订单 VIN 登记的车辆数 | 平台计数 |
| 金额及币种 | 外采订单金额 | ERP 原值，按[来源值、金额与时间](#display-values)展示；未提供时展示“未提供” |
| 未开票金额 | 见[外采订单](#field-order) | ERP 原值；未提供时展示“未提供” |
| 累计已付 | 本订单下全部外采付款的付款金额合计，币种不同时按币种分别列出 | 没有付款时展示 0 |
| 付款情况 | 未付款／部分付款／已付清 | 平台判定，见[付款状态与付款情况](#pay-status) |
| 资料进度 | 七项资料全部取得时为“齐全”，否则为已取得项数与总数，如“5/7” | 平台判定，见[资料进度](#material-progress) |
| 关联应收账款 | VIN 登记中的车辆出现在哪些应收账款中，展示应收账款编号；超过一笔时展示笔数 | 平台判定 |
| 核对提示 | 有／无 | 平台判定，见[核对提示](#check-hints) |

查找与筛选：

- 按 VIN 查找，结果为 VIN 登记中有该 VIN 的全部采购交易。
- 按订单号码、形式发票号码查找，支持部分匹配。
- 按应收账款编号或应收账款的发票号码查找，结果为 VIN 登记中有该应收账款任一 VIN 的全部采购交易。
- 筛选：卖方（供应商）、买方、币种、付款情况、资料进度是否齐全、是否有核对提示、订单日期区间。多个条件同时生效。
- 默认按订单日期从新到旧排列；日期未提供的排在最后。

边界与异常：

- 平台尚未取得任何上游采购资料时，展示“暂无上游采购资料”；有资料但查找或筛选无结果时，展示“没有符合条件的采购交易”并可清除条件。
- 列表不提供新增、编辑、删除操作。
- 加载失败按[加载失败](#load-fail)处理。

## 7. 按应收账款车辆追溯（F-M4-04）

适用角色与前提：可正常使用的运营人员。从应收账款（M3）详情的车辆信息明细中点某个 VIN 进入（见 M3 [关联追溯与风控入口](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#trace-entry)），带入该应收账款作为追溯对象和返回目标；也可在本模块按 VIN 查找后进入。

流程参见：[各入口与返回路径（图 M4-4）](./02-上游采购追溯-流程图与状态机.md#fig-m4-4)。
验收参见：[按应收账款车辆追溯](./04-上游采购追溯-验收.md#acc-f-m4-04)。

<a id="trace-receivable"></a>
### 7.1 从应收账款进入

展示本笔应收账款的上游采购总览，并定位到所点的 VIN：

| 业务信息 | 含义 | 来源与缺失时 |
| --- | --- | --- |
| 应收账款编号、发票号码、卖方 | 追溯对象，取自 M3 | M3 原值 |
| 车辆数量 | 本笔应收账款销售清单的车辆数 | M3 原值 |
| 归属结果汇总 | 已对应、多笔采购、买方不一致、未找到上游采购各几辆 | 平台判定 |
| 每辆车：VIN、车型 | 取自 M3 销售清单 | M3 原值 |
| 每辆车：归属结果 | 见[车辆归属判定（F-M4-02）](#attribution) | 平台判定 |
| 每辆车：对应的采购交易 | 订单买方与本笔应收账款卖方比对一致的采购交易（已对应时 1 笔，多笔采购时全部列出）：订单号码、日期、买方、卖方（供应商）、该车型号、采购单价及币种、付款情况 | ERP 原值与平台判定；缺失项展示“未提供”；没有时按归属结果展示 |
| 每辆车：其他登记了该 VIN 的采购交易 | 订单买方与本笔应收账款卖方不一致的采购交易及原因 | 没有时不展示 |

- 每笔采购交易都可进入[采购交易详情（F-M4-05）](#F-M4-05)，并带上本笔应收账款作为对照对象和返回目标。
- 每辆车都可进入车辆物流与履约追溯（M5）查看同一 VIN，并带上本笔应收账款作为返回目标。
- 可返回进入前的应收账款详情。

<a id="trace-vin"></a>
### 7.2 按 VIN 查找进入

- 没有带入应收账款时，展示该 VIN 出现在哪些应收账款中（应收账款编号、发票号码、卖方），以及对每笔应收账款的归属结果；选择某笔应收账款后按[从应收账款进入](#trace-receivable)展示。
- 该 VIN 不在任何应收账款的销售清单中、但在某笔采购交易的 VIN 登记中时，列出这些采购交易，标“未关联应收账款”，不判定归属结果。
- 该 VIN 既不在任何应收账款中、也不在任何采购交易中时，展示“未找到该 VIN 的上游采购资料”。

边界与异常：

- 从 M3 带入的 VIN 已不在该应收账款当前展示的销售清单中时，按该应收账款当前销售清单展示总览，不定位到该 VIN，并说明“该车已不在本笔应收账款的销售清单中”。
- 加载失败按[加载失败](#load-fail)处理。

## 8. 采购交易详情（F-M4-05）

适用角色与前提：可正常使用的运营人员，从上游采购列表、按应收账款车辆追溯、M8 或 M9 进入。详情只读，任何角色都没有编辑、补传入口。

<a id="detail-groups"></a>
### 8.1 详情包含的信息

详情包含以下信息类别，展示顺序与承载方式由 Hallmark 决定：

1. [外采订单](#field-order)。
2. [外采发票](#field-invoice)。

<a id="field-order"></a>
### 8.2 外采订单

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 订单号码 | 外采订单号码 | 不会缺失（以此识别同一张订单） |
| 日期 | 外采订单日期 | 展示“未提供” |
| 买方 | 采购方 | 展示“未提供” |
| 卖方（供应商） | 供货方 | 展示“未提供” |
| 采购明细 | 每个型号一行：型号、单价及币种、数量 | 某项展示“未提供”；没有采购明细时展示“未提供” |
| 金额及币种 | 订单金额，覆盖订单中全部车辆 | 展示“未提供” |
| 未开票金额及币种 | ERP 合同未开票金额 | 展示“未提供” |
| 外采订单附件 | 订单、采购合同等文件，可多份 | 展示“附件未取得” |

- 订单金额按原值展示，并标明覆盖的数量；不当作本笔应收账款车辆的采购金额。
- 平台不对订单的法律或财务有效性下结论。

<a id="field-invoice"></a>
### 8.3 外采发票

一笔采购交易可以有多张外采发票，逐张展示，按日期从新到旧排列；一张都未取得时展示“外采发票未取得”。

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 形式发票号码 | 外采发票号码 | 不会缺失（以此识别同一张外采发票） |
| 日期 | 形式发票日期 | 展示“未提供” |
| 对应订单号码 | 开票时所选的外采订单 | 不会缺失（外采发票按此归入采购交易） |
| 采购明细 | 开票时由订单带出的采购明细，按 ERP 原值展示 | 展示“未提供” |
| 金额及币种 | 形式发票金额 | 展示“未提供” |
| 未付金额及币种 | ERP 发票未付金额 | 展示“未提供” |
| 累计已付 | 该形式发票下外采付款的付款金额合计，币种不同时按币种分别列出 | 没有付款时展示 0 |
| 付款状态 | 未付款／部分付款／已付清，见[付款状态与付款情况](#pay-status) | 不会缺失 |
| 外采发票附件 | 形式发票原件 | 展示“附件未取得” |

- 外采发票的买方、卖方由所选订单带出，与[外采订单](#field-order)相同，不重复展示。
- 外采发票只说明采购事实，不是应收账款的发票，不进入应收账款的发票信息和回款统计。

<a id="field-vehicles"></a>
### 8.4 VIN 登记与车辆明细

本订单 VIN 登记中的每个 VIN 一行，按 ERP 登记顺序展示；一个都未登记时展示“VIN 未登记”。

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| VIN | 登记的 VIN 码 | 不会缺失 |
| 型号 | 该车对应的采购明细型号 | 展示“未提供” |
| 采购单价及币种 | 该车型号在外采订单采购明细中的单价 | 型号未提供或采购明细中没有该型号时展示“未提供” |
| 所属应收账款 | 该 VIN 出现在哪些应收账款的销售清单中（应收账款编号）及对每笔的归属结果 | 没有时展示“未关联应收账款” |
| VIN 登记附件 | 交货单、装箱单、VIN 清单等列明 VIN 的文件，可多份 | 展示“附件未取得” |

<a id="cost-rule"></a>
对照应收账款时的车辆金额：

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 本笔应收账款车辆数 | 该应收账款的车辆中，在本订单 VIN 登记里的车辆数，同时展示本订单已登记 VIN 数，如“10 辆中的 2 辆” | 平台计数 |
| 本笔应收账款车辆采购单价合计 | 上述车辆的采购单价之和，币种全部相同时才计算 | 有单价未提供或币种不同时展示“无法合计” |

- 订单金额、形式发票金额都按原值展示，并标明覆盖的车辆数；不按比例分摊，不当作本笔应收账款车辆的采购金额。
- 车辆的提单、保单、清关等在 M5 展示；本模块的 VIN 登记只说明这辆车属于哪张外采订单。

<a id="field-receivables"></a>
### 8.5 关联应收账款

列出 VIN 登记中的车辆出现在其销售清单里的全部应收账款：应收账款编号、发票号码、卖方、涉及本采购交易的 VIN 及车辆数、各 VIN 的归属结果。每笔应收账款都可进入 M3 应收账款详情。

## 9. 外采付款（F-M4-06）

适用角色与前提：可正常使用的运营人员，在采购交易详情中查看；付款资料只读，由 ERP 持续补充。

流程参见：[外采发票付款状态（图 M4-3）](./02-上游采购追溯-流程图与状态机.md#fig-m4-3)。
验收参见：[外采付款](./04-上游采购追溯-验收.md#acc-f-m4-06)。

<a id="pay-status"></a>
### 9.1 付款状态与付款情况

每张外采发票的付款状态按 ERP 提供的未付金额和该形式发票下的外采付款判定，口径与 M3 回款状态一致：

| 付款状态 | 判定条件 |
| --- | --- |
| 未付款 | 未付金额不为 0（或未提供），且该形式发票下没有外采付款 |
| 部分付款 | 未付金额大于 0（或未提供），且该形式发票下已有外采付款 |
| 已付清 | 未付金额为 0 |

每笔采购交易的付款情况按订单下的全部外采发票和未开票金额判定，自上而下取第一条满足的结果：

| 付款情况 | 判定条件 |
| --- | --- |
| 已付清 | 订单下至少有一张外采发票，全部外采发票的付款状态为“已付清”，且未开票金额为 0 |
| 未付款 | 订单下没有任何外采付款 |
| 部分付款 | 其他情况，例如已有付款但仍有外采发票未付清，或未开票金额不为 0 或未提供 |

- 付款状态和付款情况只描述上游采购款，与应收账款的回款状态无关，也不影响应收账款能否申请确权。
- 累计已付、未付金额与形式发票金额之间的关系异常（例如两者之和不等于发票金额）时，按原值展示，不由本模块更正；是否预警由 M8 判断。

<a id="field-payment"></a>
### 9.2 付款记录

每张外采发票下逐笔展示外采付款，按付款日期从新到旧排列；没有付款时展示“暂无付款记录”。

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 对应形式发票号码 | 登记付款时所选的形式发票 | 不会缺失（外采付款按此归入外采发票） |
| 付款交易编号 | 付款交易编号 | 展示“未提供” |
| 付款日期 | 付款日期 | 展示“未提供” |
| 付款方 | 付款主体 | 展示“未提供” |
| 收款方 | 收款主体 | 展示“未提供” |
| 付款银行 | 付款方的付款银行 | 展示“未提供” |
| 付款账号 | 付款方的付款账号 | 展示“未提供” |
| 付款金额及币种 | 收款方实际收到的金额 | 展示“未提供” |
| 登记时的未付金额 | ERP 在这笔付款登记中给出的发票未付金额，按原值展示；当前未付金额以[外采发票](#field-invoice)为准 | 展示“未提供” |
| 同一交易编号登记的其他外采发票 | 同一付款交易编号还登记在哪些形式发票下（以形式发票号码标识）及各自付款金额 | 没有时不展示 |
| 付款凭证 | 汇款凭证等附件 | 展示“附件未取得” |

- 每条外采付款只属于一张形式发票；同一笔交易登记在多张形式发票下时，每张只计本发票下登记的付款金额。
- 定金、尾款等分次付款各为一条付款记录。
- 付款按外采发票展示，不拆分到单辆车，不计入任何应收账款的回款。
- 付款币种与形式发票币种不同时按 ERP 原币种展示，不折算。

<a id="F-M4-07"></a>
## 10. 资料进度与持续补充（F-M4-07）

适用角色与前提：可正常使用的运营人员。

验收参见：[资料进度与持续补充](./04-上游采购追溯-验收.md#acc-f-m4-07)。

<a id="material-progress"></a>
### 10.1 资料进度

每笔采购交易按以下资料项逐项展示“已取得”或“未取得”，已取得的同时展示最近取得时间：

| 资料项 | 判定为已取得的条件 |
| --- | --- |
| 外采订单 | 采购交易已形成即为已取得 |
| 外采订单附件 | 已取得至少一份外采订单文件 |
| 外采发票 | 已取得至少一张外采发票 |
| 外采发票附件 | 已取得至少一份形式发票原件 |
| VIN 登记 | 已有至少一条 VIN 登记 |
| 外采付款 | 已有至少一笔外采付款 |
| 付款凭证 | 已取得至少一份付款凭证 |

- “未取得”只表示平台还没有这项资料，不表示业务有错误；外采付款未取得与“未付款”不冲突。
- 七项全部已取得时，资料进度为“齐全”。
- 资料进度不作为确权申请、运营审核或出库的条件；是否在审核中使用由 M9 定义。

<a id="supplement-log"></a>
### 10.2 资料补充记录

- 每次取得新资料、资料更新或资料被移除，记录资料项、变化内容（变化前后的值或文件）和取得时间，按时间从新到旧展示。
- 补充记录不可编辑、不可删除。

<a id="F-M4-08"></a>
## 11. 核对提示与风控入口（F-M4-08）

适用角色与前提：可正常使用的运营人员。

验收参见：[核对提示与风控入口](./04-上游采购追溯-验收.md#acc-f-m4-08)。

<a id="check-hints"></a>
### 11.1 核对提示

平台按当前资料自动给出以下核对提示，满足任一项时列表中“核对提示”为“有”：

| 核对提示 | 出现条件 | 展示位置 |
| --- | --- | --- |
| 采购明细合计与订单金额不一致 | 采购明细各行单价、数量都已提供且币种与订单金额相同，各行“单价 × 数量”之和不等于订单金额 | 外采订单，两者都按原值展示 |
| 登记车辆数超过订单数量 | 某型号已登记的 VIN 数超过该型号在采购明细中的数量 | VIN 登记与车辆明细，标出超出的型号 |
| 登记车辆的型号不在采购明细中 | 某个已登记 VIN 的型号在采购明细中没有对应行 | VIN 登记与车辆明细，逐车标出 |
| 车辆归属需留意 | 本采购交易涉及的应收账款车辆中，有车辆的归属结果为“多笔采购”，或本订单买方与该应收账款卖方比对不一致 | 关联应收账款，逐车说明归属结果及原因 |

- 已登记的 VIN 少于订单数量属于资料尚在补充，不给核对提示。
- 核对提示只供运营参考：不改变任何金额和状态，不需要也不能在本模块记录处理结论，资料更新后条件不再满足时自动消失。
- 核对提示不是风控预警，不影响确权申请、运营审核或出库。

<a id="risk-entry"></a>
### 11.2 关联风控预警

- 采购交易有关联风控预警（例如 M8 的主体不一致、VIN 不一致）时，展示未处理和已处理预警的数量，可进入 M8 查看；没有时展示“无关联预警”。
- 预警的比对口径、生成与处理由 M8 定义，本模块不重复比对。

## 12. 可见范围与跨模块入口（F-M4-09）

适用角色与前提：见下表。

流程参见：[各入口与返回路径（图 M4-4）](./02-上游采购追溯-流程图与状态机.md#fig-m4-4)。
验收参见：[可见范围与跨模块入口](./04-上游采购追溯-验收.md#acc-f-m4-09)。

<a id="visibility"></a>
### 12.1 谁能看

| 角色 | 能否查看上游采购 | 说明 |
| --- | --- | --- |
| 运营人员 | 可以查看全部内容 | 只读，没有编辑、补传或认定操作 |
| 债权人企业用户 | 不可以 | 企业端没有上游采购入口；应收账款详情中也没有上游采购入口，与 M3 [企业可见内容](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#enterprise-scope)一致 |
| 债务人企业用户 | 不可以 | 企业端没有上游采购入口；采购单价、供应商和付款属于卖方的采购商业信息，不向买方展示 |
| 供应商 | 不适用 | 只是交易对象，没有平台账号 |

企业用户通过链接打开本模块内容时按[不可访问](#no-access)处理。

<a id="entries"></a>
### 12.2 进入与返回

| 从哪里进入 | 进入什么 | 返回到哪里 |
| --- | --- | --- |
| 应收账款（M3）详情中某个 VIN | [从应收账款进入](#trace-receivable)，定位到该 VIN | 该应收账款详情 |
| 上游采购列表 | [采购交易详情（F-M4-05）](#F-M4-05) | 上游采购列表，保留原查找与筛选条件 |
| 风控预警（M8）详情中的上游采购资料 | 对应采购交易详情 | 该预警详情 |
| 运营审核与资产出库（M9）中的上游采购资料 | 对应应收账款的[从应收账款进入](#trace-receivable)或某笔采购交易详情 | M9 中进入前的位置 |
| 本模块中某个 VIN | 车辆物流与履约追溯（M5）中同一 VIN | 本模块进入前的位置 |

- 本模块始终展示当前资料；M9 审核当次使用的依据以 M9 为准。
- 从其他模块带入的应收账款、采购交易或 VIN 已不存在时，展示“该内容不存在或已更新”，并可返回来源位置。

<a id="pending"></a>
## 13. 待确认事项与依赖

本模块当前没有待确认事项。

依赖：

- ERP：提供外部采购下的外采订单、外采发票、外采付款、VIN 登记，字段见[ERP 资料与本模块的对应](#erp-mapping)；VIN 登记所属外采订单、VIN 型号、各金额币种及各类附件等本 PRD 定义的其他字段默认 ERP 具备，未提供时按缺失规则展示。取得方式由研发决定。
- 应收账款与发票（M3）：提供应收账款编号、发票号码、卖方及其平台企业对应结果、销售清单（VIN、车型），以及从 VIN 进入本模块的入口和返回目标。
- M1、M2：提供企业主体信息（用于买方比对）、运营人员账号及状态、运营端账号设置中的界面语言与时区。
- 车辆物流与履约追溯（M5）：按 VIN 提供车辆履约查看入口并可返回本模块；提单、保单、费用、清关登记在 M5 展示。
- 风控预警（M8）：使用本模块的上游资料进行主体、VIN 比对，向本模块提供关联预警数量与入口，并判断付款金额关系异常是否预警。
- 运营审核与资产出库（M9）：从审核中进入本模块查看上游采购事实和原件，是否以本模块资料作为审核依据由 M9 定义。
