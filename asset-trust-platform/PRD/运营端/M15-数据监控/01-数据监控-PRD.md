# 数据监控 · 功能与业务规则

本模块共四册：本册写功能、业务规则与字段规则；[流程图与状态机](./02-数据监控-流程图与状态机.md)画出主要流程与状态；[消息通知](./03-数据监控-消息通知.md)写明本模块发出的站内消息；[验收](./04-数据监控-验收.md)供测试使用。

编号说明：功能编号（F-M15-*）标在章节标题上，供验收追溯；编号沿用原值，已删除的条目不再占号，缺号不代表遗漏。本模块目前没有待确认事项。文中“M1”—“M14”均指资产可信平台的同级模块，各模块的规则以其现行正文为准，本册只链接引用。

本册只定义信息需求与业务行为；页面布局与交互承载由 Hallmark 设计决定。以下设计约束由用户指定，保持不变：

- 分类清晰、页面层级少，可有多个二级菜单；列表只放定位和判断所需的关键字段，明细放在详情，每行右侧有操作；左侧菜单有待办时以小角标提示待办数量。
- 详情中的信息上下布局，不左右布局；适用于资产推送详情与接口调用记录。分区宽度、是否用页签等具体呈现由设计决定。
- 外部跟踪数据以后要纳入数据接入：数据接入的页面，尤其是统计数据的呈现（含监控概览与大屏），要能在增加数据来源后沿用，不写死为只有 ERP。
- 本模块按“不做重”的原则设计：明细只有列表和详情两层；统计图表与大屏只汇总这两层已有的数据，不新增判断口径。

## 1. 模块是什么

本模块让运营人员在一个地方看清平台与外部系统之间的数据交换是否正常。运营端菜单分组“数据监控”下有三个二级菜单：

- “监控概览”用统计图表汇总接入与推送的整体情况，并可切换为大屏展示。
- “数据接入”看平台从外部取数据的情况，按接口逐个展示接口是否正常、最近什么时候取到数据、有没有单据没被接收；本期的数据来源只有客户 ERP。
- “数据推送”看资产数据有没有和其他平台交互、交互结果是成功还是失败：一笔资产与其他平台发生过交互才会出现在这里；每笔资产的每一次交互在详情中查看。交互方式（由对方调取还是由本平台推送）不在本模块区分。

<a id="scope"></a>记录范围：

- 数据接入记录平台接入了哪些接口，以及每个接口的每一次调用。
- 数据推送记录本平台的应收账款数据与哪些平台有过交互，以及每一次交互。
- 未审核通过资产的交互不在本模块记录和展示；从未与其他平台交互过的资产不在本模块展示。

本模块只负责展示和告警：取数方式由研发决定；资产与其他平台怎样交互、什么情况下成功，不在本模块定义；运营审核与上链以[运营审核（M9）](../M9-运营审核/01-运营审核-PRD.md)为准。

基本原则：

- **数据接入按接口，数据推送按资产。** 取数出问题通常是整条接口出问题，按接口看最直接；推送的资产数量少，每一笔都要看到“给出去没有”。
- **只看不改。** 本模块没有任何办理操作，不修改业务数据，不调整接口配置。
- **数据推送只看推送结果。** 只展示发生过推送的资产及成功、失败；推送条件、失败原因、“待推送”、上链状态与上链失败不在本模块展示，上链失败在运营审核环节由 M9 处理。
- **失败不显示成功。** 调用或推送结果未知时按事实展示，不推断为成功。
- **告警只报状态变化。** 接口由正常变为异常时提醒一次，单次失败只记在记录里，不逐次发消息。
- **业务问题回到业务模块。** 单据资料前后不一致由 M3 的核心资料差异核实处理，资料之间互相矛盾由 M8 风控预警处理；本模块不重复判断、不重复展示。

**一个完整的例子**（编号与时间为演示值）。运营人员甲打开“数据监控 · 数据接入”，看到 9 个接口，数据来源都是客户 ERP，其中“提单”状态为“异常”，菜单角标为 1。甲点进“提单”，看到最近一次调用在 10:05 失败，失败原因“connection timeout”，最近成功时间为 09:05；今日成功 9 次、失败 1 次。10:05 失败时全体运营收到站内消息“数据接入异常：提单”。10:35 的下一次调用成功，未接收 1 条（原因“缺少提单号”），“提单”恢复为“正常”，角标归零，不再发消息。甲转到“数据推送”，看到资产数字化平台最近一次推送时间为 10:20；AP-0001 推送结果“成功”，首次推送时间 2026-11-20 09:30；AP-0003 推送结果“失败”；AP-0005 还没有与其他平台交互过，不在列表中。甲点进 AP-0001 的详情，看到推送 2 次，都成功；点进 AP-0003，看到推送 1 次、结果为“失败”。

### 1.1 需求清单

| 功能 | 谁 | 想做什么 | 为了什么 |
| --- | --- | --- | --- |
| [接口列表与状态（F-M15-01）](#F-M15-01) | 运营人员 | 看到每个接口现在是否正常、数据新不新 | 及时发现取数中断 |
| [接口调用记录（F-M15-02）](#F-M15-02) | 运营人员 | 查看一个接口每次调用的时间、结果、未接收情况和失败原因 | 定位从什么时候、哪一次出了问题 |
| [资产推送列表（F-M15-03）](#F-M15-03) | 运营人员 | 看到发生过推送的每笔资产推送成功还是失败 | 知道哪些资产已经给出去、哪些没给成 |
| [资产推送详情（F-M15-04）](#F-M15-04) | 运营人员 | 查看一笔资产每一次推送的结果 | 追溯推送过程 |
| [告警与待办数量（F-M15-05）](#F-M15-05) | 平台（结果对运营人员可见） | 接口异常时提醒运营，菜单上显示异常接口个数 | 不必一直盯着页面 |
| [监控概览与大屏（F-M15-06）](#F-M15-06) | 运营人员 | 用统计图表一眼看清接入与推送的整体情况和趋势，并在大屏上持续展示 | 快速判断整体是否正常，发现趋势变化 |

### 1.2 本期不做

- 逐条单据的异常处理流程：未接收的单据只在调用记录中写明条数与原因摘要。
- “长时间无数据”的自动判断与告警：阈值需要研发与客户按 ERP 同步频率约定；本期展示“最近成功时间”，由运营人员判断。
- 手动重新取数、调整接口配置或调用频率、查看技术报文。
- 外部跟踪数据（提单信息（M12）的航程动态与到港日期来源）的接入监控：后续纳入数据接入，作为新的数据来源增加接口。
- 三方数据源的接入监控：三方数据源本期未接入（按 M8）；以后接入时同样作为数据接入中的接口增加。
- 推送条件与推送失败原因的展示。
- 上链状态、上链失败与重新提交：属于运营审核环节，按 M9。
- 运营人员手动执行推送。
- 交互方式（由对方调取还是由本平台推送）的定义与区分、什么情况下交互成功：不在本模块定义，本模块只记录有没有交互及结果。
- 企业端查看任何监控内容。
- 中文、英文以外的语言。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 运营人员 | 运营端账号的使用者，即 M2 定义的运营管理员；本期运营端只有这一种角色，所有运营人员权限相同 |
| 数据来源 | 接口从哪类外部系统取数。本期只有“客户 ERP”；外部跟踪数据、三方数据源以后纳入时作为新的数据来源 |
| 接口 | 平台从某一数据来源取得某一类业务数据的通道，以业务名称表示（如内销发票、提单）。接口清单由研发按实际对接登记，每个接口登记业务名称、数据来源及承接模块 |
| 调用 | 平台与外部系统之间针对一个接口的一次取数，无论由平台拉取还是由对方推送，取数方式由研发决定 |
| 调用结果 | 成功：本次取数完成；失败：本次取数没有完成（如连接失败、对方返回错误、内容无法读取） |
| 未接收 | 调用成功、但单据按承接模块的规则不能处理（如按 M3 内销发票缺少发票号或金额时不形成应收账款，按 M4、M12 缺少合同号、提单号或清关单号的单据无法识别）；哪些单据不能处理以承接模块现行正文为准。ERP 中未审核的单据按 M3 [采信范围](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#adopt-scope)不采信，不计入未接收 |
| 接口状态 | 正常／异常／暂无调用，见[接口状态](#interface-status) |
| 资产 | 一笔运营审核通过的确权申请及其对应的应收账款，以申请编号识别；申请状态见 M7a，运营审核见 M9 |
| 推送 | 本模块中指资产数据与其他平台的一次交互，不区分交互方式；每一次推送的结果为成功或失败，由负责对外提供的功能记录 |
| 推送结果 | 一笔资产的推送情况：成功／失败，见[推送结果](#push-result) |
| 资产数字化平台 | 接收本平台可信资产的外部平台，本期唯一的目标平台 |

<a id="shared-rules"></a>
## 3. 共用规则

<a id="access"></a>
### 3.1 谁能使用

- 只有账号状态为“正常”的运营人员能使用本模块；待首登改密、锁定中的账号按 M2 [运营账号状态](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#op-account-status)不能进入业务菜单。所有运营人员看到的内容相同。
- 企业端没有本模块的任何入口。企业账号的登录状态访问本模块、打开不存在的接口或资产、从未交互过或未审核通过的资产（含改写链接中的编号）时，按 M2 [运营端菜单与无权访问（F-OP-11）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-11)处理，不返回任何内容。

<a id="display-values"></a>
### 3.2 时间、原因、缺失值与语言

- 平台记录的时间（调用时间、最近成功时间、推送时间、首次推送时间、数据更新时间）展示到分钟，按本人时区展示并标明时区，见 M2 [界面语言与时区（F-OP-10）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-10)。
- “今日”按 UTC+1 的当天计算，与 M3 [来源值、金额与时间](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#display-values)中“今天”的口径一致；时区只影响展示，不改变“今日”的划分。
- 失败原因、未接收原因按系统返回的原文展示，不翻译。失败原因中含账号、密钥时，页面和消息中都只展示遮盖后的内容，不展示原值；接口地址在页面上按原文展示，在消息中不出现（见[数据接入异常（M15-NT01）](./03-数据监控-消息通知.md#M15-NT01)）。遮盖的实现方式由研发确定。
- 金额与币种按 M3 [来源值、金额与时间](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#display-values)展示。
- 取不到或算不出的值按 M3 [缺失值的展示](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#placeholder)以“-”展示，原因需要让运营人员知道时写在“-”下方。本册“缺失时”一栏写作“未返回失败原因”“无法计算”的，都是缺失原因，页面上显示为“-”。
- 以下是业务状态，照常以文字展示，不改为“-”：暂无接口、暂无调用、从未成功、暂无调用记录、暂无推送记录、暂无推送。
- 单据编号、申请编号可点击，按 M3 [单据编号跳转](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#doc-links)进入所在模块的详情，并可返回。
- 平台自身的字段名称、状态名称有中文、英文两套，随 M2 界面语言切换。

<a id="load-fail"></a>
### 3.3 加载失败与登录失效

- 列表、记录或详情加载失败时，提示加载失败并可重试；不展示不完整的状态或次数，不把加载失败显示为“正常”或 0 次。
- 待办数量取数失败时不展示数量，不展示为 0，菜单照常可用。
- 使用过程中登录失效或账号被锁定时，按 M2 [登录有效期、无操作登出与退出（F-OP-07）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-07)回到登录入口。

## 4. 接口列表与状态（F-M15-01）

适用角色与前提：满足[谁能使用](#access)的运营人员。菜单为“数据监控 · 数据接入”。每行一个接口。

流程参见：[数据接入的状态与告警（图 M15-1）](./02-数据监控-流程图与状态机.md#fig-m15-1)。
验收参见：[接口列表与状态](./04-数据监控-验收.md#acc-f-m15-01)。

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 接口名称 | 业务名称，如内销发票、内销合同、外采合同、外销合同、提单、清关单、保单、收付款、ERP 企业；以研发登记的接口清单为准 | 不会缺失 |
| 数据来源 | 见[术语](#terms)中的数据来源；本期都为“客户 ERP” | 不会缺失 |
| 承接模块 | 取得的数据进入哪个模块，如应收账款（M3）、合同信息（M4）、车辆履约（M5）、提单信息（M12）、保单信息（M13）、资金收付（M14）、运营登录与企业管理（M2，ERP 企业）；以研发登记的接口清单为准 | 不会缺失 |
| 接口状态 | 见[接口状态](#interface-status) | 不会缺失 |
| 最近成功时间 | 最近一次调用成功的时间，运营人员据此判断数据是否新 | 从未成功时展示“从未成功” |
| 最近一次调用 | 时间与结果；失败时附失败原因 | 从未调用时展示“暂无调用” |
| 今日调用 | 成功次数、失败次数 | 当日没有调用时都为 0 |

<a id="interface-status"></a>
接口状态：

| 接口状态 | 条件 |
| --- | --- |
| 暂无调用 | 接口已登记，还没有任何调用 |
| 正常 | 最近一次调用成功 |
| 异常 | 最近一次调用失败 |

- 状态只看最近一次调用：异常的接口下一次调用成功即恢复为“正常”，正常的接口一次调用失败即变为“异常”。
- 调用成功但有未接收单据时，接口状态仍为“正常”，未接收情况在[接口调用记录（F-M15-02）](#F-M15-02)中查看。
- 调用结果尚未返回的不计入状态和次数。
- 接口状态、调用记录与告警规则对所有数据来源相同；以后新增数据来源时照此执行。

操作与查找：

- 每行可“查看”，进入该接口的[接口调用记录（F-M15-02）](#F-M15-02)，返回后保留原有筛选。
- 筛选：接口状态、数据来源、承接模块。
- 默认排序：异常在前，其次正常、暂无调用；同一状态内按接口清单顺序。

边界与异常：

- 研发尚未登记任何接口时，展示“暂无接口”。
- 列表不提供新增、编辑、删除接口或调整配置的操作。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

<a id="F-M15-02"></a>
## 5. 接口调用记录（F-M15-02）

适用角色与前提：满足[谁能使用](#access)的运营人员，从接口列表或消息“数据接入异常（M15-NT01）”进入。只读。

验收参见：[接口调用记录](./04-数据监控-验收.md#acc-f-m15-02)。

页面顶部展示该接口的接口名称、数据来源、承接模块、接口状态、最近成功时间；下方按时间从新到旧列出调用记录：

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 调用时间 | 本次调用开始的时间 | 不会缺失 |
| 调用结果 | 成功／失败 | 不会缺失 |
| 未接收条数 | 本次取得但不能处理的单据条数 | 失败时不展示；没有时为 0 |
| 未接收原因摘要 | 按原因归类的条数，如“缺少提单号 1 条”；可展开查看对应单据号 | 没有未接收时不展示 |
| 失败原因 | 调用失败的原因原文 | 成功时不展示；未返回时为“未返回失败原因”，展示“-” |

- 筛选：调用时间区间、调用结果（成功／失败）、是否有未接收。
- 未接收的单据号按原值展示；单据已在平台中存在时可按[单据编号跳转](#display-values)进入。
- 调用记录长期保留，不可编辑、不可删除。
- 不展示本次取得的单据条数；未接收条数与原因由平台按承接模块规则判定。
- 调用结果尚未返回的调用不出现在调用记录中，返回后按结果记入。
- 接口没有调用记录时展示“暂无调用记录”；筛选无结果时展示“没有符合条件的记录”并可清除条件。

<a id="platform-line"></a>
列表上方展示一行平台情况：

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 目标平台 | 资产数字化平台 | 不会缺失 |
| 最近一次推送时间 | 最近一次与该平台发生、计入资产推送记录的交互的时间，无论结果；未审核通过资产的交互不计入。很久没有交互时，运营人员可据此判断数据交换可能中断 | 从未发生时展示“暂无推送” |

资产列表：

| 业务信息 | 含义 | 来源与缺失时 |
| --- | --- | --- |
| 申请编号 | 资产对应的确权申请，可进入 M9 申请详情 | M7a，不会缺失 |

| 首次推送时间 | 第一次推送成功的时间 | 推送结果为失败时不展示 |

<a id="push-result"></a>
推送结果：

| 推送结果 | 条件 |
| --- | --- |
| 成功 | 至少有一次推送成功 |
| 失败 | 有推送记录，但每一次都失败 |

- 推送结果只有成功、失败两种，不展示“待推送”或上链状态。
- 成功后不再变为失败；之后的推送失败只记入[资产推送详情（F-M15-04）](#F-M15-04)。
- 失败的资产之后推送成功时变为成功。

操作：

- 每行可“查看”，进入该资产的[资产推送详情（F-M15-04）](#F-M15-04)，返回后保留原有查找、筛选和页码。
- 列表不提供推送、撤回、删除或批量操作。

查找与筛选：

- 按申请编号、内销发票号或应收账款编号查找，支持部分匹配。
- 筛选：推送结果（成功／失败）、债权人、首次推送时间区间。多个条件同时生效。按首次推送时间区间筛选时，推送结果为失败的资产（没有首次推送时间）不在结果中。
- 默认排序：失败在前，按最近一次推送时间从新到旧；成功按首次推送时间从新到旧。

边界与异常：

- 还没有任何资产有推送记录时，展示“暂无推送记录”；查找或筛选无结果时，展示“没有符合条件的资产”并可清除条件。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

## 9. 监控概览与大屏（F-M15-06）

适用角色与前提：满足[谁能使用](#access)的运营人员。菜单为“数据监控 · 监控概览”，在“数据接入”“数据推送”之前。概览中的全部数字都由数据接入、数据推送的记录汇总得出，口径与两处列表一致；图表形式、布局与配色由设计决定。

流程参见：[监控概览与大屏（图 M15-4）](./02-数据监控-流程图与状态机.md#fig-m15-4)。
验收参见：[监控概览与大屏](./04-数据监控-验收.md#acc-f-m15-06)。

<a id="overview-range"></a>
### 9.1 统计范围与通用规则

- 概览中的指标分两类：“当前”指标展示打开或刷新时的情况，不受时间范围影响；“区间”指标按所选时间范围统计。
- 时间范围可选今日、近 7 天、近 30 天，或自定义起止日期；默认近 7 天。日期按 UTC+1 划分，与“今日”的口径一致。“近 7 天”“近 30 天”含今日。
- 趋势图按日展示，横轴为日期（UTC+1）；当天没有数据的日期展示为 0，不跳过。
- 比率以百分数展示，保留两位小数、向下截取；分母为 0 时为“无法计算”，展示“-”，规则同 M3 [美元折算与比率](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#usd-rule)。
- 美元金额按 M3 [美元折算与比率](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#usd-rule)以查看时的当前汇率折算；无法折算的资产不计入合计，并在合计下方注明“另有 N 笔无法折算”。
- 页面展示“数据更新时间”（本次取数的时间，按本人时区展示并标明时区），可手动刷新。
- 点击分布图中的某一类或排行中的某一项，进入对应列表并带上筛选条件（如点“异常”进入接口列表并筛选异常接口；点“失败”进入资产推送列表并筛选失败）；返回后回到概览。
- 从接口失败排行进入某接口的调用记录时，带上概览所选的时间范围和调用结果“失败”的筛选，记录条数与排行中的失败次数一致。

<a id="overview-intake"></a>
### 9.2 数据接入统计

数据接入统计包含全部数据来源的接口；本期只有客户 ERP。以后新增数据来源时，新来源的接口按同一口径计入各指标，不另设口径。

| 指标 | 类型 | 口径 |
| --- | --- | --- |
| 接口状态分布 | 当前 | 正常、异常、暂无调用的接口个数，按[接口状态](#interface-status) |
| 调用次数与成功率 | 区间 | 调用总次数、成功次数、失败次数；成功率 = 成功次数 ÷ 调用总次数 |
| 每日调用趋势 | 区间 | 每天的成功次数、失败次数 |
| 每日未接收趋势 | 区间 | 每天的未接收条数 |
| 接口失败排行 | 区间 | 各接口的失败次数，从多到少排列；没有失败的接口不列入 |
| 数据新鲜度 | 当前 | 各接口的最近成功时间，从早到晚排列（最久没有取到数据的在前），从未成功的排在最前；多个从未成功的接口之间按接口清单顺序 |

<a id="overview-push"></a>
### 9.3 数据推送统计

| 指标 | 类型 | 口径 |
| --- | --- | --- |
| 推送结果分布 | 当前 | 推送结果为成功、失败的资产笔数，以及各自的应收账款金额（美元）合计，按[推送结果](#push-result) |
| 每日新增成功资产 | 区间 | 每天首次推送成功的资产笔数 |
| 推送次数与成功率 | 区间 | 推送总次数、成功次数、失败次数；成功率 = 成功次数 ÷ 推送总次数 |
| 每日推送趋势 | 区间 | 每天推送的成功次数、失败次数 |
| 平台最近一次推送时间 | 当前 | 同[资产推送列表](#platform-line)上方的平台情况 |

推送次数按资产推送详情中的推送记录统计，不区分交互方式；未审核通过资产的交互不计入。

<a id="big-screen"></a>
### 9.4 大屏

- 在监控概览中可切换为大屏：铺满整个屏幕，展示[数据接入统计](#overview-intake)、[数据推送统计](#overview-push)的全部指标，供运营在固定屏幕上持续观看。
- 大屏只展示，不提供筛选、查找或点击进入列表；可选择时间范围，默认近 7 天；可退出回到监控概览。
- 大屏每 1 分钟自动刷新一次，并展示数据更新时间。
- 自动刷新失败时，保留上一次成功取得的数据，并醒目提示“数据更新失败，当前显示 {数据更新时间} 的数据”，不把旧数据当作最新数据，也不展示为 0；下一次刷新成功后提示消失。
- 有接口处于异常时，大屏上醒目展示异常接口个数，与“数据接入”菜单待办数量一致。
- 大屏按本人界面语言展示中文或英文。
- 大屏与运营端其他页面使用同一登录：按 M2 [登录有效期、无操作登出与退出（F-OP-07）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-07)，登录满 4 小时或连续 2 小时没有真实操作即需重新登录，自动刷新不算真实操作；大屏不另设登录时长，需要时重新登录后再次进入大屏。

边界与异常：

- 平台还没有任何调用或资产时，各指标照常展示（个数、次数为 0，比率展示“-”），不展示错误。
- 某一指标取数失败时，仅该指标提示失败并可重试，其他指标正常展示。

<a id="status-combo"></a>
## 10. 状态组合

数据接入中，接口状态与“最近一次成功调用是否有未接收”是两个独立维度：

| 接口状态 | 最近一次成功调用有未接收 | 运营看到 | 计入数据接入待办 | 发送告警 |
| --- | --- | --- | --- | --- |
| 暂无调用 | 不适用 | 暂无调用 | 不计入 | 不发送 |
| 正常 | 否 | 正常，最近成功时间 | 不计入 | 不发送 |
| 正常 | 是 | 正常，记录中可见未接收条数与原因 | 不计入 | 不发送 |
| 异常 | 不适用 | 异常，最近一次失败原因 | 计入 | 进入异常时发送一次 |

数据推送只展示推送结果（成功／失败）一个维度，没有组合状态；推送条件不在本模块展示。

<a id="pending"></a>
## 11. 依赖


- 研发：登记接口清单（业务名称、数据来源、承接模块），记录每次调用的时间、结果、未接收单据与原因、失败原因；取数方式与频率由研发与客户确定。原型展示不代表取数能力已实现。
- 运营审核（M9）：资产的范围（运营审核通过的申请）、申请详情入口；审核、上链与上链失败由 M9 定义和处理。
- 对外提供：每笔资产与其他平台的每一次交互（目标平台、时间、成功或失败）由负责对外提供的功能记录；对外提供后续单独定义，交互方式与成功条件由其定义（见 M9 [对外提供](../M9-运营审核/01-运营审核-PRD.md#external-provision)）。这只影响本模块的数据来源与联调，不影响本模块的规则与验收。
- 应收账款（M3）及合同信息（M4）、车辆履约（M5）、提单信息（M12）、保单信息（M13）、资金收付（M14）、运营登录与企业管理（M2）：作为承接模块，提供未接收单据的判定规则与单据详情入口；单据编号跳转按 M3 [单据编号跳转](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#doc-links)，缺失值展示按 M3 [缺失值的展示](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#placeholder)。
- 运营登录、企业邀请与企业管理（M2）：运营人员账号及状态、界面语言与时区、登录有效期、无权访问的统一处理；“监控概览”“数据接入”“数据推送”三个菜单在 M2 [运营端菜单表](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-11)的“数据监控”分组登记，菜单内容与待办数量由本模块定义。
- 消息中心（M10）：承接本模块的站内消息，按[来源接入要求（MSG-06）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-06)。
- 调用结果的记录须完整、不遗漏失败，实现与验证归研发、测试。
