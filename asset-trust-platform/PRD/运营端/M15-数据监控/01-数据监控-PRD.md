# 数据监控 · 功能与业务规则

2026-11-24｜运营端：运营人员｜需求评审稿

本模块共四册：本册写功能、业务规则与字段规则；[流程图与状态机](./02-数据监控-流程图与状态机.md)画出主要流程与状态；[消息通知](./03-数据监控-消息通知.md)写明本模块发出的站内消息；[验收](./04-数据监控-验收.md)供测试使用。

编号说明：功能编号（F-M15-*）标在章节标题上，供验收追溯。文中“M1”—“M14”均指资产可信平台的同级模块。

本册只定义信息需求与业务行为；页面布局与交互承载由 Hallmark 设计决定。以下设计约束由用户指定，保持不变：分类清晰、页面层级少，可有多个二级菜单；列表只放定位和判断所需的关键字段，明细放在详情，每行右侧有操作；左侧菜单有待办时以小角标提示待办数量。本模块按“不做重”的原则设计：明细只有状态列表和记录两层；统计图表与大屏只汇总这两层已有的数据，不新增判断口径。

## 1. 模块是什么

本模块让运营人员在一个地方看清平台与外部系统之间的数据交换是否正常。运营端菜单分组“数据监控”下有三个二级菜单：“监控概览”用统计图表汇总接入与推送的整体情况，并可切换为大屏展示；“数据接入”看平台从客户 ERP 取数据的情况，按接口逐个展示接口是否正常、最近什么时候取到数据、有没有单据没被接收；“数据推送”看审核通过的资产被资产数字化平台调取的情况，按资产逐笔展示存证与推送状态、每一次调取的结果。本模块只负责展示和告警：取数方式由研发决定，资产能否被调取、调取时返回什么、存证规则都以[运营审核与资产推送（M9）](../M9-运营审核与资产推送/01-运营审核与资产推送-PRD.md)为准。

基本原则：

- **数据接入按接口，数据推送按资产。** ERP 取数出问题通常是整条接口出问题，按接口看最直接；推送出去的只有审核通过的资产，数量少，每一笔都要追到“给出去没有”。
- **只看不改。** 本模块不修改任何业务数据，不调整接口配置；唯一的操作是对存证失败的资产“重新存证”，规则按 M9。
- **失败不显示成功。** 调用或调取结果未知时按事实展示，不推断为成功。
- **告警只报状态变化。** 接口由正常变为异常时提醒一次，单次失败只记在记录里，不逐次发消息。
- **业务问题回到业务模块。** 单据资料前后不一致由 M3 的核心资料差异核实处理，资料之间互相矛盾由 M8 风控预警处理；本模块不重复判断、不重复展示。

**一个完整的例子**（编号与时间为演示值）。运营人员甲打开“数据监控 · 数据接入”，看到 8 个接口，其中“提单”状态为“异常”，菜单角标为 1。甲点进“提单”，看到最近一次调用在 10:05 失败，失败原因“connection timeout”，最近成功时间为 09:05；今日成功 9 次、失败 1 次。10:05 失败时全体运营收到站内消息“数据接入异常：提单”。10:35 的下一次调用成功，取得 12 条、未接收 1 条（原因“缺少提单号”），“提单”恢复为“正常”，角标归零，不再发消息。甲转到“数据推送”，看到资产数字化平台最近一次调取时间为 10:20；AP-0001 推送状态“已推送”，首次推送时间 2026-11-20 09:30，调取 2 次均成功；AP-0007 推送状态“存证失败”，菜单角标为 1。甲点进 AP-0007 查看失败原因后选择“重新存证”，推送状态变为“存证中”，之后变为“待推送”，角标归零。

### 1.1 需求清单

| 功能 | 谁 | 想做什么 | 为了什么 |
| --- | --- | --- | --- |
| [接口列表与状态（F-M15-01）](#F-M15-01) | 运营人员 | 看到每个 ERP 接口现在是否正常、数据新不新 | 及时发现取数中断 |
| [接口调用记录（F-M15-02）](#F-M15-02) | 运营人员 | 查看一个接口每次调用的时间、结果、条数和原因 | 定位从什么时候、哪一次出了问题 |
| [资产推送列表（F-M15-03）](#F-M15-03) | 运营人员 | 看到每笔审核通过的资产存证、推送到哪一步 | 知道哪些资产已经给出去、哪些卡住了 |
| [资产推送记录（F-M15-04）](#F-M15-04) | 运营人员 | 查看一笔资产每一次被调取的结果 | 追溯推送过程，核对拒绝原因 |
| [告警与待办数量（F-M15-05）](#F-M15-05) | 平台（结果对运营人员可见） | 接口异常时提醒运营，菜单上显示需要处理的数量 | 不必一直盯着页面 |
| [监控概览与大屏（F-M15-06）](#F-M15-06) | 运营人员 | 用统计图表一眼看清接入与推送的整体情况和趋势，并在大屏上持续展示 | 快速判断整体是否正常，发现趋势变化 |

### 1.2 本期不做

- 逐条单据的异常处理流程：未接收的单据只在调用记录中写明条数与原因摘要。
- “长时间无数据”的自动判断与告警：阈值需要研发与客户按 ERP 同步频率约定；本期展示“最近成功时间”，由运营人员判断。
- 手动重新取数、调整接口配置或调用频率、查看技术报文。
- 主动向外发送资产，或手动执行推送：推送只通过资产数字化平台调取完成（按 M9）。
- 三方数据源的接入监控：三方数据源本期未接入（按 M8）；以后接入时作为数据接入中的接口增加。
- 企业端查看任何监控内容。
- 中文、英文以外的语言。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 运营人员 | 运营端账号的使用者，即 M2 定义的运营管理员；本期运营端只有这一种角色，所有运营人员权限相同 |
| 接口 | 平台从 ERP 取得某一类业务单据的通道，以业务名称表示（如内销发票、提单）。接口清单由研发按实际对接登记，每个接口登记业务名称及承接模块 |
| 调用 | 平台与 ERP 之间针对一个接口的一次取数，无论由平台拉取还是由 ERP 推送，取数方式由研发决定 |
| 调用结果 | 成功：本次取数完成；失败：本次取数没有完成（如连接失败、对方返回错误、内容无法读取） |
| 未接收 | 调用成功、但单据按承接模块的规则不能处理（如内销发票缺少发票号或金额，不形成应收账款）。ERP 中未审核的单据按承接模块的采信规则不采信，不计入未接收 |
| 接口状态 | 正常／异常／暂无调用，见[接口状态](#interface-status) |
| 资产、推送、调取、存证、推送状态、推送条件 | 沿用 M9 的定义，见 M9 [术语](../M9-运营审核与资产推送/01-运营审核与资产推送-PRD.md#terms)、[推送状态](../M9-运营审核与资产推送/01-运营审核与资产推送-PRD.md#push-status)、[推送条件（F-M9-05）](../M9-运营审核与资产推送/01-运营审核与资产推送-PRD.md#F-M9-05) |
| 资产数字化平台 | 调取本平台可信资产的外部平台，本期唯一获准调取资产的平台 |

<a id="shared-rules"></a>
## 3. 共用规则

<a id="access"></a>
### 3.1 谁能使用

- 只有可正常使用的运营人员能使用本模块；运营人员处于待首次改密、已停用或锁定中时不能使用，判定以 M2 为准。
- 企业端没有本模块的任何入口。
- 打开不存在的接口或资产（含改写链接中的编号）时，提示“该内容不存在或已更新”，并可返回来源位置。

<a id="display-values"></a>
### 3.2 时间、原因与语言

- 平台记录的时间（调用时间、最近成功时间、存证时间、调取时间、审核时间）展示到分钟，按运营人员在 M2 账号设置中选择的时区展示并标明时区；M2 不提供时区设置时统一按 UTC 展示。
- “今日”按 UTC+1 的当天计算，与 M3 对“今天”的口径一致。
- 失败原因、未接收原因、存证失败原因按系统返回的原文展示，不翻译；未返回原因时展示“未返回失败原因”。
- 金额与币种按 M3 [来源值、金额与时间](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#display-values)展示。
- 单据编号、申请编号可点击，按 M3 [单据编号跳转](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#doc-links)进入所在模块的详情，并可返回。
- 平台自身的字段名称、状态名称有中文、英文两套，随界面语言切换。

<a id="load-fail"></a>
### 3.3 加载失败与登录失效

- 列表或记录加载失败时，提示加载失败并可重试；不展示不完整的状态或次数，不把加载失败显示为“正常”或 0 次。
- 待办数量取数失败时不展示数量，不展示为 0，菜单照常可用。
- 操作过程中登录失效、账号被停用或锁定时，按 M2 规则回到登录入口，本次未提交的操作不生效。

## 4. 接口列表与状态（F-M15-01）

适用角色与前提：满足[谁能使用](#access)的运营人员。菜单为“数据监控 · 数据接入”。每行一个接口。

流程参见：[数据接入的状态与告警（图 M15-1）](./02-数据监控-流程图与状态机.md#fig-m15-1)。
验收参见：[接口列表与状态](./04-数据监控-验收.md#acc-f-m15-01)。

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 接口名称 | 业务名称，如内销发票、内销合同、内销收款、外采合同、外采发票、外采付款、提单、保单、车辆物流节点、外销合同、外销出库、外销收款、ERP 企业；以研发登记的接口清单为准 | 不会缺失 |
| 承接模块 | 取得的单据进入哪个模块，如应收账款（M3）、提单信息（M12） | 不会缺失 |
| 接口状态 | 见[接口状态](#interface-status) | 不会缺失 |
| 最近成功时间 | 最近一次调用成功的时间，运营人员据此判断数据是否新 | 从未成功时展示“从未成功” |
| 最近一次调用 | 时间与结果；失败时附失败原因 | 从未调用时展示“暂无调用” |
| 今日调用 | 成功次数、失败次数 | 当日没有调用时都为 0 |

<a id="interface-status"></a>
接口状态：

| 接口状态 | 条件 |
| --- | --- |
| 暂无调用 | 接口已登记，还没有任何调用 |
| 正常 | 最近一次调用成功 |
| 异常 | 最近一次调用失败 |

- 状态只看最近一次调用：异常的接口下一次调用成功即恢复为“正常”，正常的接口一次调用失败即变为“异常”。
- 调用成功但有未接收单据时，接口状态仍为“正常”，未接收情况在[接口调用记录（F-M15-02）](#F-M15-02)中查看。
- 调用结果尚未返回的不计入状态和次数。

操作与查找：

- 每行可“查看”，进入该接口的[接口调用记录（F-M15-02）](#F-M15-02)，返回后保留原有筛选。
- 筛选：接口状态、承接模块。
- 默认排序：异常在前，其次正常、暂无调用；同一状态内按接口清单顺序。

边界与异常：

- 研发尚未登记任何接口时，展示“暂无接口”。
- 列表不提供新增、编辑、删除接口或调整配置的操作。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

## 5. 接口调用记录（F-M15-02）

适用角色与前提：满足[谁能使用](#access)的运营人员，从接口列表或消息“数据接入异常（M15-NT01）”进入。只读。

验收参见：[接口调用记录](./04-数据监控-验收.md#acc-f-m15-02)。

页面顶部展示该接口的接口名称、承接模块、接口状态、最近成功时间；下方按时间从新到旧列出调用记录：

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 调用时间 | 本次调用开始的时间 | 不会缺失 |
| 调用结果 | 成功／失败 | 不会缺失 |
| 取得条数 | 本次取得的单据条数，含新增与更新 | 失败时不展示；未返回条数时展示“未提供” |
| 未接收条数 | 本次取得但不能处理的单据条数 | 没有时为 0；未返回时展示“未提供” |
| 未接收原因摘要 | 按原因归类的条数，如“缺少提单号 1 条”；可展开查看对应单据号 | 没有未接收时不展示 |
| 失败原因 | 调用失败的原因原文 | 成功时不展示；未返回时为“未返回失败原因” |

- 筛选：调用时间区间、调用结果（成功／失败）、是否有未接收。
- 未接收的单据号按原值展示；单据已在平台中存在时可按[单据编号跳转](#display-values)进入。
- 调用记录长期保留，不可编辑、不可删除。
- 每次调用能否返回取得条数、未接收条数与原因，待研发核验，见[逐条结果能否取得（Q-M15-01）](#Q-M15-01)；不能返回时只展示调用时间、结果与失败原因。
- 接口没有调用记录时展示“暂无调用记录”；筛选无结果时展示“没有符合条件的记录”并可清除条件。

验收参见：[资产推送列表](./04-数据监控-验收.md#acc-f-m15-03)。

资产列表：

| 内销发票号 | 申请对应的内销发票号 | 当次依据，不会缺失 |
| 债权人 | 债权人企业名称 | 当次依据，不会缺失 |

| 目标平台 | 本期固定为资产数字化平台 | 不会缺失 |
| 推送状态 | 存证中／存证失败／待推送／已推送，按 M9 [推送状态](../M9-运营审核与资产推送/01-运营审核与资产推送-PRD.md#push-status) | M9，不会缺失 |
| 推送条件 | 满足，或不满足及全部原因，按 M9 [推送条件（F-M9-05）](../M9-运营审核与资产推送/01-运营审核与资产推送-PRD.md#F-M9-05)中到期、回款、核心资料三项；推送状态为“待推送”“已推送”时展示 | 按打开或刷新时判断 |
| 首次推送时间 | 第一次被成功调取的时间 | 未推送时不展示 |
| 最近调取时间 | 最近一次计入推送记录的调取时间 | 没有调取时不展示 |
| 调取次数 | 成功次数、被拒绝次数 | 没有调取时都为 0 |

操作：

- 每行可“查看”，进入该资产的[资产推送记录（F-M15-04）](#F-M15-04)，返回后保留原有查找、筛选和页码。
- 推送状态为“存证失败”的行可“重新存证”；确认内容、结果与异常全部按 M9 [重新存证](../M9-运营审核与资产推送/01-运营审核与资产推送-PRD.md#re-notarize)，本模块不新增规则。

查找与筛选：

- 按申请编号、内销发票号或应收账款编号查找，支持部分匹配。
- 筛选：推送状态、推送条件（满足／不满足）、债权人、审核通过时间区间、首次推送时间区间。多个条件同时生效。
- 默认排序：存证失败在前，其余按审核通过时间从新到旧。

边界与异常：

- 还没有取得推送资格的资产时，展示“暂无可推送的资产”；查找或筛选无结果时，展示“没有符合条件的资产”并可清除条件。
- 列表不提供推送、撤回、删除或批量操作。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

## 7. 资产推送记录（F-M15-04）

适用角色与前提：满足[谁能使用](#access)的运营人员，从资产推送列表或 M9 申请详情进入。只读，存证失败时可重新存证。

验收参见：[资产推送记录](./04-数据监控-验收.md#acc-f-m15-04)。

顶部展示该资产的申请编号（可进入 M9 申请详情）、内销发票号、债权人、推送状态、推送条件、首次推送时间；下方分两部分：

存证记录（按时间从新到旧）：

| 业务信息 | 含义 |
| --- | --- |
| 存证次序 | 第 1 次、第 2 次…… |
| 提交方式 | 审核通过后自动；重新存证（附提交人） |
| 提交时间 | 本次存证开始的时间 |
| 结果 | 成功（存证时间、存证凭证）／失败（失败时间、失败原因）／存证中 |

调取记录（按时间从新到旧）：

| 业务信息 | 含义 |
| --- | --- |
| 调取平台 | 本期为资产数字化平台 |
| 调取时间 | 收到本次调取的时间 |
| 结果 | 成功／被拒绝 |
| 拒绝原因 | 被拒绝时按 M9 推送条件列出全部原因，如“已到期”“核心资料待核实”“存在阻断类风控预警”“存证未完成” |

- 记录长期保留，不可编辑、不可删除。
- 只记录 M9 规定计入推送记录的调取；未获准平台的调取、对未审核通过资产的调取不出现在任何资产的记录中（按 M9 [推送条件（F-M9-05）](../M9-运营审核与资产推送/01-运营审核与资产推送-PRD.md#F-M9-05)）。
- 没有调取时，调取记录展示“暂无调取”。

<a id="F-M15-05"></a>
## 8. 告警与待办数量（F-M15-05）

适用范围：数据接入的接口状态变化；两个菜单的待办数量。没有用户操作。

通知：接口状态变为“异常”时向全体运营发送[数据接入异常（M15-NT01）](./03-数据监控-消息通知.md#M15-NT01)。资产存证失败的告警由 M9 发送“资产存证失败（M9-NT03）”，本模块不发同义消息。
验收参见：[告警与待办数量](./04-数据监控-验收.md#acc-f-m15-05)。

- 接口状态由“正常”或“暂无调用”变为“异常”时，发送一条 M15-NT01；保持异常期间的后续失败不再发送；恢复正常时不发送。
- “数据接入”菜单的待办数量为当前接口状态为“异常”的接口个数。
- “数据推送”菜单的待办数量为当前推送状态为“存证失败”的资产笔数。
- 两个数量所有运营人员看到相同的值，按本人打开或刷新页面时的结果展示；数量为 0 时不展示；取数失败按[加载失败与登录失效](#load-fail)处理。

## 9. 监控概览与大屏（F-M15-06）

适用角色与前提：满足[谁能使用](#access)的运营人员。菜单为“数据监控 · 监控概览”，在“数据接入”“数据推送”之前。概览中的全部数字都由数据接入、数据推送的记录汇总得出，口径与两处列表一致；图表形式、布局与配色由设计决定。

流程参见：[监控概览与大屏（图 M15-4）](./02-数据监控-流程图与状态机.md#fig-m15-4)。
验收参见：[监控概览与大屏](./04-数据监控-验收.md#acc-f-m15-06)。

<a id="overview-range"></a>
### 9.1 统计范围与通用规则

- 概览中的指标分两类：“当前”指标展示打开或刷新时的情况，不受时间范围影响；“区间”指标按所选时间范围统计。
- 时间范围可选今日、近 7 天、近 30 天，或自定义起止日期；默认近 7 天。日期按 UTC+1 划分，与“今日”的口径一致。“近 7 天”“近 30 天”含今日。
- 趋势图按日展示，横轴为日期（UTC+1）；当天没有数据的日期展示为 0，不跳过。
- 比率以百分数展示，保留两位小数、向下截取；分母为 0 时展示“无法计算”，规则同 M3 [美元折算与比率](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#usd-rule)。
- 美元金额按 M3 [美元折算与比率](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#usd-rule)以查看时的当前汇率折算；无法折算的资产不计入合计，并在合计旁注明“另有 N 笔无法折算”。
- 页面展示“数据更新时间”（本次取数的时间，按本人时区展示并标明时区），可手动刷新。
- 点击分布图中的某一类或排行中的某一项，进入对应列表并带上筛选条件（如点“异常”进入接口列表并筛选异常接口；点“存证失败”进入资产推送列表并筛选存证失败）；返回后回到概览。

<a id="overview-intake"></a>
### 9.2 数据接入统计

| 指标 | 类型 | 口径 |
| --- | --- | --- |
| 接口状态分布 | 当前 | 正常、异常、暂无调用的接口个数，按[接口状态](#interface-status) |
| 调用次数与成功率 | 区间 | 调用总次数、成功次数、失败次数；成功率 = 成功次数 ÷ 调用总次数 |
| 每日调用趋势 | 区间 | 每天的成功次数、失败次数 |
| 每日取得与未接收趋势 | 区间 | 每天的取得条数、未接收条数；未接收率 = 未接收条数 ÷ 取得条数。只统计返回了条数的调用，见[逐条结果能否取得（Q-M15-01）](#Q-M15-01) |
| 接口失败排行 | 区间 | 各接口的失败次数，从多到少排列；没有失败的接口不列入 |
| 数据新鲜度 | 当前 | 各接口的最近成功时间，从早到晚排列（最久没有取到数据的在前），从未成功的排在最前 |

<a id="overview-push"></a>
### 9.3 数据推送统计

| 指标 | 类型 | 口径 |
| --- | --- | --- |
| 推送状态分布 | 当前 | 存证中、存证失败、待推送、已推送的资产笔数，以及各状态的应收账款金额（美元）合计 |
| 每日推送趋势 | 区间 | 每天审核通过的笔数、首次推送（第一次被成功调取）的笔数 |
| 调取次数与成功率 | 区间 | 计入推送记录的调取总次数、成功次数、被拒绝次数；成功率 = 成功次数 ÷ 调取总次数 |
| 每日调取趋势 | 区间 | 每天的调取成功次数、被拒绝次数 |
| 拒绝原因分布 | 区间 | 被拒绝的调取按原因（已到期、已收清、核心资料待核实、存在阻断类风控预警、存证未完成）计次；一次调取有多个原因时每个原因各计一次 |
| 平台最近一次调取时间 | 当前 | 资产数字化平台最近一次调取的时间，同[资产推送列表](#platform-line) |

<a id="big-screen"></a>
### 9.4 大屏

- 在监控概览中可切换为大屏：铺满整个屏幕，展示 9.2、9.3 的全部指标，供运营在固定屏幕上持续观看。
- 大屏只展示，不提供重新存证、筛选、查找或点击进入列表；可选择时间范围，默认近 7 天；可退出回到监控概览。
- 大屏按设定的间隔自动刷新，并展示数据更新时间；刷新间隔待确认，见[大屏刷新间隔（Q-M15-02）](#Q-M15-02)。
- 自动刷新失败时，保留上一次成功取得的数据，并醒目提示“数据更新失败，当前显示 {数据更新时间} 的数据”，不把旧数据当作最新数据，也不展示为 0；下一次刷新成功后提示消失。
- 有接口处于异常、或有资产存证失败时，大屏上醒目展示对应数量，与菜单待办数量一致。
- 大屏按本人界面语言展示中文或英文。
- 大屏与运营端其他页面使用同一登录：按 M2 [登录有效期、无操作登出与退出（F-OP-07）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-07)，登录满 4 小时或连续 2 小时没有真实操作即需重新登录，自动刷新不算真实操作；是否为大屏另设规则待确认，见[大屏登录时长（Q-M15-03）](#Q-M15-03)。

边界与异常：

- 平台还没有任何调用或资产时，各指标照常展示（个数、次数为 0，比率为“无法计算”），不展示错误。
- 某一指标取数失败时，仅该指标提示失败并可重试，其他指标正常展示。

<a id="status-combo"></a>
## 10. 状态组合

数据接入中，接口状态与“最近一次成功调用是否有未接收”是两个独立维度：

| 接口状态 | 最近一次成功调用有未接收 | 运营看到 | 计入数据接入待办 | 发送告警 |
| --- | --- | --- | --- | --- |
| 暂无调用 | 不适用 | 暂无调用 | 不计入 | 不发送 |
| 正常 | 否 | 正常，最近成功时间 | 不计入 | 不发送 |
| 正常 | 是 | 正常，记录中可见未接收条数与原因 | 不计入 | 不发送 |
| 异常 | 不适用 | 异常，最近一次失败原因 | 计入 | 进入异常时发送一次 |

数据推送中，推送状态与推送条件的组合按 M9 [状态组合](../M9-运营审核与资产推送/01-运营审核与资产推送-PRD.md#status-combo)；只有“存证失败”计入数据推送待办。

## 11. 待确认事项与依赖

| 编号 | 事项（具体冲突点） | 当前处理与影响 |
| --- | --- | --- |
| <a id="Q-M15-01"></a>逐条结果能否取得（Q-M15-01，待验证） | 调用记录要展示取得条数、未接收条数与原因，这取决于各接口能否返回逐条处理结果；目前没有对接说明，需要研发核验 | 正文按能取得编写；不能取得的接口只展示调用时间、结果与失败原因，取得条数与未接收条数展示“未提供”。影响[接口调用记录（F-M15-02）](#F-M15-02)；对应验收标“待验，不判通过” |
| <a id="Q-M15-02"></a>大屏刷新间隔（Q-M15-02） | 大屏需要自动刷新，输入没有给出间隔。推荐每 1 分钟刷新一次：与消息送达时效（M10 规定 60 秒内可见）同一量级，接口进入异常后一分钟左右能在大屏上看到；风险是刷新越频繁，取数压力越大，研发评估后可调整 | 正文按“定时自动刷新”编写，间隔确认前不写死；影响[大屏](#big-screen)；对应验收标“待验，不判通过” |
| <a id="Q-M15-03"></a>大屏登录时长（Q-M15-03） | M2 规定运营端登录 4 小时到期、连续 2 小时无真实操作即登出，自动刷新不算操作；大屏挂在固定屏幕上持续展示时，最长约 2 小时就会退回登录页。推荐本期沿用 M2 规则、不为大屏放宽：理由是运营账号可以查看全平台数据，长时间免登录有安全风险；代价是大屏需要定期重新登录。如需全天展示，可另设只能查看大屏的专用账号或延长时长，属于安全规则变化，需要您决定并同步修改 M2 | 正文按沿用 M2 规则编写；影响[大屏](#big-screen)与 M2 |

依赖：

- 研发：登记接口清单（业务名称、承接模块），记录每次调用的时间、结果、条数、未接收单据与原因、失败原因；取数方式与频率由研发与客户确定。
- 运营审核与资产推送（M9）：推送资格、推送状态、推送条件、存证与重新存证规则、调取记录，以及资产数字化平台的调取方式（M9 Q-M9-03 待验证）。
- 应收账款（M3）及合同信息（M4）、车辆履约（M5）、提单信息（M12）、保单信息（M13）、资金收付（M14）、运营登录与企业管理（M2）：作为承接模块，提供未接收单据的判定规则与单据详情入口。
- 运营登录、企业邀请与企业管理（M2）：运营人员账号及状态、界面语言与时区；运营端菜单登记“数据监控：监控概览”“数据监控：数据接入”“数据监控：数据推送”。
- 消息中心（M10）：承接本模块的站内消息，按[来源接入要求（MSG-06）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-06)。
- 调用结果的记录须完整、不遗漏失败，实现与验证归研发、测试。
