# 数据监控 · 消息通知

2026-11-24｜需求评审稿｜配套[功能与业务规则](./01-数据监控-PRD.md)

本模块发送 1 类站内消息，经消息中心（M10）展示，按 [来源接入要求（MSG-06）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-06)登记；必发，收件人不能关闭。本模块不发送邮件。

| 消息 | 端 | 所在功能 | 触发环节 | 谁收到 | 打开后去哪 |
| --- | --- | --- | --- | --- | --- |
| [数据接入异常（M15-NT01）](#M15-NT01) | 运营端 | [告警与待办数量（F-M15-05）](./01-数据监控-PRD.md#F-M15-05) | 接口状态由“正常”或“暂无调用”变为“异常” | 全体运营 | 该接口的调用记录 |

以下情况本模块不发消息：接口保持异常期间的再次失败；接口恢复正常；调用成功但有未接收单据；查看列表、记录；待办数量变化；资产存证失败（由 M9 发送“资产存证失败（M9-NT03）”）；资产被调取或调取被拒绝。

<a id="M15-NT01"></a>
## 数据接入异常（M15-NT01）

| 项目 | 规则 |
| --- | --- |
| 发送来源 | 数据监控（M15）；其他模块不发同义消息 |
| 端 | 运营端 |
| 分类 | 运营告警 / Operations alerts |
| 收件范围 | 全体运营。不发给企业 |
| 触发 | 一次调用失败，使接口状态由“正常”或“暂无调用”变为“异常”时发送 |
| 不触发 | 接口已是“异常”时的再次失败；调用成功（含有未接收单据）；恢复正常 |
| 同一事实的区分依据 | 全体运营 + 接口 + 本次进入异常的时间 + “数据接入异常”。同一次进入异常只发一条；恢复正常后再次进入异常是新的事实，另发一条 |
| 发生时间 | 使接口进入异常的那次调用的时间 |
| 原业务识别信息 | 接口名称 |
| 打开后去哪 | 原业务：本模块中该接口的调用记录 |
| 查看与办理条件 | 查看：可正常使用的运营人员。没有办理动作；前往时接口已恢复正常的，照常查看当前状态与记录 |
| 必须出现的业务值 | 接口名称、承接模块、失败时间、失败原因、最近成功时间（从未成功时为“从未成功”） |
| 业务值取值 | 取进入异常时的值；失败原因按返回原文展示，未返回原因时为“未返回失败原因”；之后不改写 |
| 不得出现 | 技术报文、接口地址、账号或密钥 |

文案（按收件人的界面语言展示；花括号为业务值，失败原因按原值展示不翻译；接口名称、承接模块随界面语言展示）：

| 语言 | 标题 | 正文 |
| --- | --- | --- |
| 中文 | 数据接入异常：{接口名称} | ERP 接口“{接口名称}”（承接模块：{承接模块}）于 {失败时间} 调用失败，原因：{失败原因}。最近成功时间：{最近成功时间}。接口恢复前，这类单据的新数据不会进入平台，请查看调用记录。 |
| English | Data intake failure: {interface name} | The ERP interface "{interface name}" (used by: {module}) failed at {failure time}. Reason: {failure reason}. Last successful call: {last success time}. New data of this type will not reach the platform until the interface recovers. Please review the call records. |
