## 1. 模块是什么

本模块是运营端的“最后一道关”，并规定审核通过的资产怎样提供给外部平台。债务人确认后的确权申请进入运营审核，运营人员核对申请当次提交的资料、处理记录、应收账款当前状况和关联风控预警，决定是否审核通过。审核通过后，这笔资产取得推送资格：平台自动把审核通过的那一版资料中的核心数据上链到万纳连（联盟链）存证，存证成功后，资产数字化平台就可以来调取这笔资产。资产数字化平台成功调取一次，这笔资产即为“已推送”。推送情况的查看、存证失败后的重新存证入口，以及推送相关的监控都在[数据监控（M15）](../M15-数据监控/01-数据监控-PRD.md)的“数据推送”中；本模块定义规则，M15 负责展示。运营人员还可以在本模块查看全部确权申请的完整处理记录。

基本原则：

- **运营审核只有“通过”。** 没有驳回或不通过；运营人员不予通过的申请一直处于“待运营审核”，直到通过或应收账款到期由 M7a 自动关闭。
- **审核看当次依据。** 审核对象是申请提交时记录的当次依据；申请提交后资料变化不要求债务人重新确认或运营重新审核，只作为当前情况提示。
- **推送由对方调取，不由本平台发送。** 审核通过后平台不主动发送资产；资产数字化平台按约定来调取。本平台负责决定哪些资产可以被调取、调取时返回什么、记录每一次调取。
- **审核通过不等于已推送。** 审核通过只表示取得推送资格；存证成功且被资产数字化平台成功调取后才是“已推送”。
- **推送的是审核通过的那一版资料。** 推送内容在审核通过时确定，每次调取都返回同一份内容，不随之后的 ERP 更新改变。
- **没有审核通过，就不能被调取。** 未提交、待债务人确认、债务人已驳回、待运营审核、已关闭的申请对应的资产，都不在可调取范围内，任何平台调取都会被拒绝；本平台不向其他平台提供除此以外的资产查询。
- **只有阻断类风控预警会拦住业务。** 关联应收账款有差异仍存在的阻断类预警时，不能审核通过，资产数字化平台调取也被拒绝；预警类、提示类不阻止审核和推送，由审核人判断；存在未处理或“确认有风险”的阻断、预警类预警时，审核通过必须写明审核说明。等级以 M8 风控规则配置中的当前等级为准。

**一个完整的例子**（企业名称、编号、金额为演示值）。Carloha Holding 对应收账款 AR-0012（内销发票 PI-0012，90,000.00 USD，到期日 2026-12-19）发起确权申请 AP-0001，Carloha Nigeria 确认后申请变为“待运营审核”，全体运营收到“有新的确权申请待运营审核（M7b-NT03）”，左侧“运营审核”菜单角标加 1。运营人员甲从消息进入 AP-0001 的审核详情，看到申请信息、处理记录（Holding 用户张三单笔发起、Nigeria 用户李四确认）、当次依据，以及当前情况：到期状态“未到期”、回款状态“部分收款”、核心资料状态“一致”、资产健康度四项指标、关联风控预警“未处理 1、已处理 0”（主体不一致）。甲点 VIN-B 进入车辆履约（M5）、点内销合同号进入合同信息（M4）核对后返回，再进入 M8 查看该预警后返回，选择“审核通过”。确认时平台提示存在 1 条未处理预警，甲填写审核说明“付款方为债务人委托代付，代付函已线下核实”后提交。AP-0001 变为“运营审核通过”，待审核角标减 1；Holding 收到“运营审核已通过”。平台随即为 AP-0001 的推送内容做存证，推送状态“存证中”；存证成功后变为“待推送”。当天资产数字化平台来调取 AP-0001，平台核对推送条件全部满足，返回推送内容；推送状态变为“已推送”，Holding 收到“资产已推送”，在 M7a 申请详情中看到推送进度“已推送”。运营人员在 M15“数据推送”中看到 AP-0001 的首次推送时间和这次调取记录。一周后资产数字化平台再次调取 AP-0001，此时 ERP 更新了 PI-0012 的合同，平台仍返回审核通过时的那一份内容，并记录第二次调取。

<a id="out-of-scope"></a>
### 1.2 本期不做

- 运营审核驳回或不通过，以及填写不通过原因、不通过后重新提交（用户已裁定运营审核只有通过）。
- 撤回或撤销审核通过；撤回、撤销、注销已推送的资产。
- 运营批量审核。
- 由本平台主动向外发送资产，或由运营人员手动执行推送：推送只通过资产数字化平台调取完成。
- 推送内容的更新、修订或重新确定；资料变化后自动更新推送内容。
- 资产数字化平台调取之后的处理（生成数字凭证、发放、结清注销等）在本平台的展示与回写；是否回传待验证，见[资产数字化平台的调取能力（Q-M9-03）](#Q-M9-03)。
- 向资产数字化平台以外的平台提供资产，或与借贷服务平台交互。
- 企业钱包目录与资产数字化平台的同步：不属于本模块；本模块的审核门槛只约束资产数据。
- 推送列表、推送记录、接口监控的展示：由数据监控（M15）定义。
- 审核时要求企业补充或修改资料，或运营人员在平台上修改任何单据资料。
- 企业端查看审核人、审核说明、存证凭证、调取记录；债务人查看推送进度（按 M7b）。
- 风控预警的生成与处理：由 M8 定义，本模块只展示并留存审核时的预警情况。
- 中文、英文以外的语言。

| 术语 | 含义 |

| 运营人员 | 运营端账号的使用者，即 M2 定义的运营管理员；本期运营端只有这一种角色，所有运营人员权限相同 |

| 申请状态 | 沿用 M7a [申请状态](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#apply-status)：待债务人确认／债务人已驳回／待运营审核／运营审核通过／已关闭 |
| 当次依据 | 债权人提交申请成功那一刻本笔应收账款的资料记录，由 M7a 保存，见 M7a [当次依据](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#snapshot) |
| 待审核 | 申请状态为“待运营审核”的申请。“待审核”是列表范围，不是另一种状态 |
| 到期时点 | M3 判定本笔应收账款由“未到期”变为“已到期”的时点，即到期日当天结束（UTC+1 的 24:00），见 M3 [到期状态](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#due-status) |
| 推送资格 | 申请状态为“运营审核通过”。取得后不会失去；某一次调取能否成功，还要满足[推送条件（F-M9-05）](#F-M9-05) |
| 资产 | 本模块中指一笔取得推送资格的申请及其对应的应收账款；一笔应收账款最多只有一笔“运营审核通过”的申请（按 M7a 申请资格） |
| 推送 | 资产数字化平台成功调取一笔资产的推送内容。由对方调取完成，本平台不主动发送；与车辆履约（M5）中车辆实物的外销出库无关 |
| 推送内容 | 一笔资产对外提供的资料，见[推送内容](#push-content) |
| 存证 | 把推送内容中的[上链数据](#chain-data)写入万纳连（联盟链），使用平台配置的私钥签名，并取得链上凭证；存证成功是可被调取的前提 |
| 万纳连 | 本平台存证使用的联盟链 |
| 调取 | 资产数字化平台向本平台请求一笔资产的推送内容。每一次调取都有结果：成功（返回推送内容）或被拒绝（不返回内容，记录原因） |
| 资产数字化平台 | 接收本平台可信资产的外部平台，本期唯一获准调取资产的平台 |
| 接收钱包 | 债权人企业在 M1 绑定的唯一钱包地址，包含在推送内容中；债权人发起申请前必须已完成入驻，因此一定存在，且不可更换 |
| 推送状态 | 一笔资产的存证与推送结果，只有一个维度，见[推送状态](#push-status) |

<a id="shared-rules"></a>
## 3. 共用规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。

<a id="access"></a>
### 3.1 谁能使用、看到什么

- 只有可正常使用的运营人员能使用本模块；运营人员处于待首次改密、已停用或锁定中时不能使用，判定以 M2 为准。
- 运营人员可查看全部确权申请，可对待审核申请审核通过，可对存证失败的资产重新存证（入口在 M15 和本模块申请详情）。所有运营人员权限相同。
- 企业端没有本模块的任何入口。企业能看到的审核与推送结果，只通过 M7a、M7b、M3 按各自可见范围展示，见[推送进度对外提供（F-M9-08）](#F-M9-08)。
- 打开不存在的申请编号（含改写链接中的编号）时，提示“该内容不存在或已更新”，并可返回来源位置。

<a id="display-values"></a>
### 3.2 金额、日期与时间

- 金额、ERP 日期、附件的展示沿用 M3 [来源值、金额与时间](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#display-values)与[附件查看](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#file-view)：金额与币种同时展示、按原值不取整；不同币种不直接相加。
- 应收账款到期日按 M3 展示，只有日期、不带时区；涉及“今天”的判断按 UTC+1 的当前日期。
- 平台自己记录的时间（发起时间、处理时间、审核时间、关闭时间、存证时间、调取时间、状态更新时间）展示到分钟，按运营人员在 M2 账号设置中选择的时区展示并标明时区；M2 不提供时区设置时统一按 UTC 展示。
- 驳回原因、审核说明按填写的原文展示；存证返回的失败原因按返回原文展示；均不随界面语言翻译。
- 接收钱包地址按 M1 的写法缩写展示，保留大小写；可复制完整地址。
- 运营端页面中出现的单据编号（应收账款编号、内销发票号、合同号、VIN、提单号、保单号、交易流水号）按 M3 [单据编号跳转](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#doc-links)进入所在模块的详情，并可返回本模块进入前的位置。
- 平台自身的字段名称、状态名称、拒绝原因有中文、英文两套，随界面语言切换。

<a id="load-fail"></a>
### 3.3 加载失败与登录失效

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的金额、状态或待办数量，也不提供审核通过、重新存证操作。
- 详情中某一部分（如当次依据、处理记录、当前情况、关联风控预警、推送信息）加载失败时，仅该部分提示失败并可重试，其他部分正常展示。当次依据或关联风控预警未完整加载时不能审核通过。
- 待办数量取数失败时不展示数量，不展示为 0，菜单照常可用。
- 操作过程中登录失效、账号被停用或锁定时，按 M2 规则回到登录入口，本次未提交的操作不生效。

| 预警信息 | 本笔应收账款当前的有／无，按 M3 [预警信息](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#warning-flag) | M3、M8 当前结果 | 展示 | 不展示 |
| 申请状态 | 见 M7a [申请状态](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#apply-status) | M7a，不会缺失 | 展示（均为“待运营审核”） | 展示 |
| 状态更新时间 | 最近一次申请状态变化的时间 | M7a 记录，不会缺失 | 不展示 | 展示 |

- 只有到期状态为“未到期”的应收账款才能发起申请，因此当次依据中的到期日不会缺失。
- 列表不展示应收账款编号，可按其查找；申请详情中展示。

操作：

- 每行可“查看”，进入[申请详情与审核依据（F-M9-02）](#F-M9-02)，返回后保留原有范围、查找、筛选和页码。
- 待审核的行可“审核通过”，规则见[审核通过（F-M9-03）](#F-M9-03)；其他行没有审核操作。

查找与筛选：

- 按申请编号、内销发票号或应收账款编号查找，支持部分匹配；查找在当前范围内进行。
- 筛选：债权人、债务人、币种、应收账款到期日区间、发起时间区间；待审核另可按预警信息筛选，全部申请另可按申请状态筛选。多个条件同时生效。
- 待审核默认按应收账款到期日从早到晚排列，到期日相同时按债务人确认时间从早到晚；先到期的排在前面，避免因到期关闭而错过审核。
- 全部申请默认按状态更新时间从新到旧排列。

边界与异常：

- 平台还没有任何申请时，两个范围都展示“暂无确权申请”；待审核为空、全部申请有记录时，待审核展示“暂无待审核的申请”；查找或筛选无结果时，展示“没有符合条件的申请”并可清除条件。
- 列表中的状态和可审核操作是打开或刷新时的结果；申请状态因审核通过、到期关闭发生变化后，刷新时移出待审核。
- 列表不提供新增、编辑、删除申请的操作，也不提供批量选择。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

<a id="review-count"></a>
### 4.2 待审核数量

- 待审核数量为全平台申请状态为“待运营审核”的申请笔数，随“运营审核”菜单展示；数量为 0 时不展示数量。所有运营人员看到同一个数量。
- 待审核数量按本人打开或刷新页面时的结果展示；本人审核通过一笔申请成功后立即减少；有新申请进入待审核、其他运营人员审核通过或申请到期关闭后，在下一次打开或刷新时更新。
- 取数失败按[加载失败与登录失效](#load-fail)处理。

<a id="F-M9-03"></a>
## 6. 审核通过（F-M9-03）

适用角色与前提：运营人员；申请满足[可以审核通过的条件](#review-conditions)。入口为待审核列表中的行和申请详情。

通知：审核通过生效后向债权人企业发送[运营审核已通过（M9-NT01）](./03-运营审核与资产推送-消息通知.md#M9-NT01)。
流程参见：[审核通过的提交（图 M9-2）](./02-运营审核与资产推送-流程图与状态机.md#fig-m9-2)。
验收参见：[审核通过](./04-运营审核与资产推送-验收.md#acc-f-m9-03)。

<a id="review-conditions"></a>
### 6.1 可以审核通过的条件

一笔申请同时满足以下全部条件时，运营人员才可以审核通过。列表与详情按打开或刷新时的结果提供操作；提交时平台重新判断，以提交时为准。

| 条件 | 不满足时用户看到的结果 |
| --- | --- |
| 满足[谁能使用、看到什么](#access)的使用前提 | 按 M2 规则处理，本次不生效 |
| 申请状态为“待运营审核” | 不能审核，展示该申请的当前状态，见下表 |
| 当前时间未到本笔应收账款的到期时点 | 不能审核，说明“应收账款已到期，该申请已关闭”，展示“已关闭” |
| 当次依据与关联风控预警已完整加载 | 不能审核，按[加载失败与登录失效](#load-fail)提示重试 |
| 关联风控预警中没有差异仍存在的阻断类预警（按 M8 [阻断的作用](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#blocking)） | 不能审核，展示“存在阻断类风控预警：{规则名称}（{预警编号}）”，可进入该预警；阻断在差异消除、或该规则在 M8 中被降级或停用后解除 |

提交时申请已不是“待运营审核”，本次提交不生效，按当前状态说明：

| 提交时的申请状态 | 用户看到的说明 |
| --- | --- |
| 运营审核通过 | 该申请已由其他运营人员审核通过，不能重复审核 |
| 已关闭 | 应收账款已到期，该申请已关闭 |

- 到期以到期时点为界：到期时点之前提交成功的审核通过有效；到期时点之后提交的一律不生效，即使 M7a 尚未完成关闭，也按“已关闭”处理。
- 当前到期状态以外的当前情况（回款状态、核心资料状态、资产健康度）和预警类、提示类风控预警都不是审核条件。

<a id="review-confirm"></a>
### 6.2 确认与审核说明

审核通过时展示：

- 申请编号、债权人、债务人、内销发票号、应收账款编号、应收账款金额及币种、应收账款到期日（均取自当次依据）。
- 阻断类、预警类关联风控预警中未处理的数量，以及处理结果为“确认有风险”的数量；两者都为 0 时展示“无未处理或确认有风险的风控预警”。提示类不计入。
- 说明“审核通过后这笔资产取得推送资格，资产数字化平台可以调取，不能撤回；审核通过不会处理任何风控预警，也不代表已推送”。

审核时填写：

| 业务信息 | 含义/类型 | 必填条件/默认值 | 可编辑范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 审核说明 | 审核人对审核依据和判断的说明，例如为何在存在风控预警时仍予通过；多行文本 | 关联风控预警中存在未处理或“确认有风险”的阻断类、预警类预警时必填（提示类不计），否则选填；无默认值 | 提交前可编辑；提交后不能修改 | 去除首尾空格后不超过 500 个字符；必填时为空或只有空白不能提交并指出该项；超过 500 个字符不能提交并指出该项 |

- 是否必填以提交时的关联风控预警为准：填写过程中预警被处理、不再需要必填时，已填写内容照常保存；新出现未处理预警而说明为空时，提交不生效，提示“出现新的未处理风控预警，请填写审核说明”。
- 审核说明只对运营人员可见。

<a id="review-result"></a>
### 6.3 结果

- 用户确认提交后，平台按[可以审核通过的条件](#review-conditions)和审核说明的规则重新判断。满足时申请状态变为“运营审核通过”，记录审核结论“通过”、审核人、审核时间、审核说明，以及审核时的关联预警情况：未处理、已处理数量，每条预警的预警编号、等级、规则、差异摘要、预警状态、处理结果。审核时的预警情况之后不随 M8 的处理而改变。
- 成功后展示申请编号与新状态“运营审核通过”；该申请移出待审核，待审核数量减 1。
- 这笔资产取得推送资格，推送内容随即确定，平台自动开始存证，推送状态为“存证中”，见[存证与推送内容（F-M9-06）](#F-M9-06)。
- 审核通过只改变申请状态，不改变当次依据、应收账款资料和风控预警。
- 用户取消时申请不变，已填写的审核说明不保存。

边界与异常：

- 提交时已不满足条件（已被其他运营人员审核通过、已到期关闭）：本次不生效，按[可以审核通过的条件](#review-conditions)说明结果，列表与详情刷新为最新状态。
- 两名运营人员同时审核同一申请，或重复点击提交：只有先提交成功的一次生效；后到的提交不生效，说明“该申请已由其他运营人员审核通过，不能重复审核”或展示本人刚生效的结果，不会生成第二条审核记录。
- 提交失败：申请不变，保留已填写的审核说明，提示提交失败可重试。
- 提交后未收到明确结果（如网络中断）：提示“审核结果未确认，请刷新后查看”，不自动重新提交；再次提交时如已生效，按“不能重复审核”说明。
- 提交时登录失效或账号被停用：申请不变，按[加载失败与登录失效](#load-fail)处理。

<a id="not-approved"></a>
### 6.4 不予通过的申请

- 运营人员认为申请不应通过时，不作任何操作；申请保持“待运营审核”，直到之后审核通过，或到期时点到达由 M7a 关闭为“已关闭”。
- 期间这笔应收账款仍有处理中的申请，债权人不能重新发起（按 M7a 申请资格）；资产不能被调取。
- 本期没有向企业说明不予通过原因的平台功能；运营人员需要时在平台外与企业沟通。

<a id="F-M9-05"></a>
## 7. 推送条件（F-M9-05）

适用范围：资产数字化平台每一次调取时的判断，以及 M15 中“推送条件”的展示。判断以调取时的数据为准。

验收参见：[推送条件](./04-运营审核与资产推送-验收.md#acc-f-m9-05)。

一次调取同时满足以下全部条件时才成功：

| 条件 | 依据 | 不满足时的拒绝原因 |
| --- | --- | --- |
| 调取方是获准调取的平台（本期只有资产数字化平台） | 研发登记的对接平台 | 调取方未获准 |
| 申请状态为“运营审核通过” | M7a [申请状态](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#apply-status) | 未通过运营审核 |
| 存证已成功 | [推送状态](#push-status) | 存证未完成 |
| 本笔应收账款当前到期状态为“未到期” | M3 [到期状态](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#due-status)；到期日当天仍为未到期 | 已到期 |
| 本笔应收账款当前回款状态为“未收款”或“部分收款” | M3 [回款状态](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#repayment-status) | 已收清 |
| 本笔应收账款当前核心资料状态为“一致” | M3 [核心资料差异核实（F-M3-07）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-07) | 核心资料待核实 |
| 关联风控预警中没有差异仍存在的阻断类预警 | M8 [阻断的作用](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#blocking) | 存在阻断类风控预警 |

- 同时有多项不满足时，全部原因都记录。
- 前两项不满足时，不返回这笔资产的任何内容，也不透露它是否存在；这类调取不计入任何资产的推送记录。其余各项不满足时，本次调取被拒绝，记入该资产的推送记录。
- 预警类、提示类风控预警（含未处理和“确认有风险”）、M4、M5、M12—M14 的资料、合同或附件是否取得、债权人或债务人企业的角色与账号状态都不是推送条件。
- 不满足推送条件不改变申请状态、推送资格和推送状态；条件恢复（例如核心资料核实后回到“一致”、阻断类预警的差异消除）时之后的调取可以成功。到期和已收清不会恢复。
- 可调取范围：资产数字化平台能发现的资产只包括推送状态为“待推送”“已推送”、且当前满足后四项条件的资产；发现方式由研发对接确定。

<a id="F-M9-06"></a>
## 8. 存证与推送内容（F-M9-06）

适用范围：申请审核通过之后。存证由平台自动完成；运营人员只在存证失败时重新存证，入口在 M15 [数据推送](../M15-数据监控/01-数据监控-PRD.md#F-M15-03)和本模块申请详情的[推送信息](#push-detail)。

通知：存证失败时向全体运营发送[资产存证失败（M9-NT03）](./03-运营审核与资产推送-消息通知.md#M9-NT03)。
流程参见：[存证与被调取（图 M9-3）](./02-运营审核与资产推送-流程图与状态机.md#fig-m9-3)。
验收参见：[存证与推送内容](./04-运营审核与资产推送-验收.md#acc-f-m9-06)。

<a id="push-content"></a>
### 8.1 推送内容

一笔资产对外提供的内容固定为以下各项：

- 该申请的当次依据全部内容，含当时取得的附件。
- 申请编号、应收账款编号。
- 债务人确认结论与确认时间；运营审核结论“通过”与审核时间。不含处理人、审核人姓名和审核说明。
- 接收钱包：债权人企业在 M1 绑定的钱包地址。

规则：

- 推送内容在审核通过时确定，之后每一次调取都返回同一份内容，不随 ERP 更新、核心资料差异或核实改变。
- 不含风控预警、M3 核实记录与资产健康度，以及 M4、M5、M12—M14 的资料。
- 当次依据中“未提供”“附件未取得”“未取得”的项按原样提供，不事后补入。

<a id="chain-data"></a>
### 8.2 上链数据

审核通过时，平台把以下数据写入万纳连，每笔资产上链一次。数据取自审核通过时确定的[推送内容](#push-content)，之后资料更新不再上链：

| 类别 | 数据项 | 上链方式 |
| --- | --- | --- |
| 资产标识 | 应收账款编号、确权申请编号、内销发票号 | 原文 |
| 交易双方 | 债权人企业名称、债务人企业名称（平台企业）；债权人接收钱包地址 | 原文 |
| 金额与期限 | 应收账款金额及币种、内销发票日期、账期、应收账款起算日、应收账款到期日 | 原文 |
| 车辆明细 | 车辆数量；每辆车的 VIN 与内采单价（原币及币种） | 原文 |
| 基础合同 | 内销合同号、内销合同日期、内销合同金额及币种 | 原文 |
| 确权与审核结果 | 债务人确认结论与确认时间、运营审核结论（通过）与审核时间 | 原文 |
| 文件指纹 | 内销发票附件、内销合同附件，以及整份推送内容的哈希值 | 只上哈希，不上文件 |
| 上链记录 | 上链时间、签名地址 | 平台生成 |

- 不上链：回款情况（已收款、待收款金额与回款记录）、银行名称与账号、交易流水号、收款凭证、发起人、处理人与审核人姓名、审核说明、风控预警及处理结果、资产健康度、美元折算值，以及 M4、M5、M12—M14 的资料。
- 推送内容中未提供或未取得的项，上链时按“未提供”记录；附件未取得时不生成该附件的哈希，记为“附件未取得”。
- 签名使用平台配置的私钥直接完成，不需要运营人员或企业签名。私钥由研发与运维在部署配置中维护，运营端任何页面都不展示、也不能修改私钥。
- 上链的原文对联盟链成员可见；上链范围为本表，调整须修订本节。

<a id="notarize"></a>
### 8.3 存证

- 审核通过后，平台自动把[上链数据](#chain-data)写入万纳连，推送状态为“存证中”。
- 存证成功：记录存证时间与存证凭证（链上交易标识及万纳连返回的上链结果），推送状态变为“待推送”，这笔资产进入可调取范围。
- 存证失败：记录失败时间与失败原因（返回原文；未返回时为“未返回失败原因”），推送状态变为“存证失败”，资产不可被调取，向全体运营发送 M9-NT03。
- 一笔资产最多只有一份成功的存证；存证成功后不再重新存证。
- 存证凭证只在运营端展示；凭证中的技术细节（例如链上交易标识）由设计决定展示方式，运营人员可复制。
- 存证中结果未返回时保持“存证中”，不按失败或成功推断。

<a id="re-notarize"></a>
### 8.4 重新存证

- 推送状态为“存证失败”时，运营人员可以“重新存证”；没有自动重试，次数不限。
- 确认时展示申请编号、内销发票号、债权人、最近一次失败时间与失败原因，以及说明“将为审核通过时的资料重新存证，存证成功后资产数字化平台即可调取”。
- 提交后推送状态变为“存证中”，记录提交人与提交时间；结果按[存证](#notarize)处理，再次失败时另发一条 M9-NT03。
- 重新存证使用审核通过时确定的推送内容与上链数据。
- 推送条件（到期、已收清、核心资料）不影响能否重新存证。
- 两名运营人员同时重新存证，或重复点击：只形成一次；后到的说明“该资产已在存证中”或“该资产已完成存证”，并展示当前推送状态。
- 提交失败时推送状态不变，提示提交失败可重试；提交后未收到明确结果时，提示“提交结果未确认，请刷新后查看”，不自动重新提交。

<a id="F-M9-07"></a>
## 9. 被调取与推送状态（F-M9-07）

适用范围：资产数字化平台的每一次调取。没有运营人员操作；调取情况在 M15 [数据推送](../M15-数据监控/01-数据监控-PRD.md#F-M15-03)和本模块申请详情中查看。

通知：资产第一次被成功调取时向债权人企业发送[资产已推送（M9-NT02）](./03-运营审核与资产推送-消息通知.md#M9-NT02)。
流程参见：[存证与被调取（图 M9-3）](./02-运营审核与资产推送-流程图与状态机.md#fig-m9-3)、[推送状态（图 M9-4）](./02-运营审核与资产推送-流程图与状态机.md#fig-m9-4)。
验收参见：[被调取与推送状态](./04-运营审核与资产推送-验收.md#acc-f-m9-07)。

<a id="retrieval"></a>
### 9.1 调取的处理

- 每次调取按[推送条件（F-M9-05）](#F-M9-05)判断：全部满足时返回[推送内容](#push-content)，本次调取成功；不满足时不返回内容，本次调取被拒绝。
- 同一笔资产可以被调取多次，每次成功都返回同一份推送内容。
- 每一次计入推送记录的调取都记录：调取平台、调取时间、结果（成功／被拒绝）、拒绝原因。
- 资产数字化平台是否按资产逐笔调取、调取之后的处理是否回传，待验证，见[资产数字化平台的调取能力（Q-M9-03）](#Q-M9-03)；按批调取时，推送记录按资产逐笔记录。

<a id="push-status"></a>
### 9.2 推送状态

| 推送状态 | 含义 | 由什么带来 | 后续 |
| --- | --- | --- | --- |
| 存证中 | 已审核通过，存证结果尚未返回 | 审核通过；运营人员重新存证 | 存证成功变为“待推送”；存证失败变为“存证失败” |
| 存证失败 | 最近一次存证失败，资产不可被调取 | 存证结果为失败 | 运营人员重新存证后变为“存证中” |
| 待推送 | 存证成功，还没有被成功调取过 | 存证成功 | 第一次调取成功后变为“已推送” |
| 已推送 | 已被资产数字化平台成功调取至少一次 | 第一次调取成功 | 结束，不再变化；之后的调取照常记录 |

- 状态只由上表所列的结果改变，没有其他转换；资料变化、风控预警、被拒绝的调取、企业角色或账号变化都不改变推送状态。
- “已推送”只表示本平台已把推送内容交给资产数字化平台；对方之后的处理本期不在平台中展示。

<a id="push-detail"></a>
### 9.3 推送信息（申请详情中）

申请状态为“运营审核通过”时，申请详情中展示：

- 推送状态；推送状态为“待推送”“已推送”时，展示当前推送条件结果（满足，或不满足及全部原因）。
- 存证时间与存证凭证；存证失败时展示失败时间与失败原因，并提供“重新存证”。
- 首次推送时间、最近一次调取时间与结果、调取次数（成功／被拒绝）。
- 推送内容：按[推送内容](#push-content)列出。
- 进入 M15 查看该资产完整推送记录的入口。

## 10. 推送进度对外提供（F-M9-08）

适用范围：M7a 申请详情中的[推送进度](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#outbound)，M3 应收账款详情中的[确权与审核进度](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#apply-progress)，本模块的[进度条](#progress-bar)，以及 M15 的数据推送。没有用户操作。

验收参见：[推送进度对外提供](./04-运营审核与资产推送-验收.md#acc-f-m9-08)。

- 推送进度只在申请状态为“运营审核通过”后提供；申请为其他状态时，推送环节为“未开始”。
- 不同角色看到的推送进度口径不同，对应关系如下：

| 推送状态 | 运营端（本模块、M3 运营视角、M15） | 债权人（M7a 申请详情、M3 债权人视角） | 债务人（M7b、M3 债务人视角） |
| --- | --- | --- | --- |
| 存证中 | 存证中 | 未推送 | 不展示推送环节 |
| 存证失败 | 存证失败（附失败原因） | 未推送 | 不展示推送环节 |
| 待推送 | 待推送 | 未推送 | 不展示推送环节 |
| 已推送 | 已推送（附首次推送时间） | 已推送（附首次推送时间） | 不展示推送环节 |

- 债权人看到的“未推送”表示资产尚未提供给资产数字化平台；存证状态、失败原因、存证凭证、调取记录只对运营人员展示。
- 推送进度与申请状态分开展示，不改变 M7a 的申请状态；“运营审核通过”不等于已推送。
- 债务人看到的进度到“运营审核通过”为止，与 M7b 一致。

<a id="data-change"></a>
## 11. 资料变化与对审核、推送的影响

本节集中说明资料变化在各阶段的结果，各功能直接引用，不再分别展开。

| 资料变化发生时 | 对申请与审核 | 对推送 |
| --- | --- | --- |
| 待运营审核期间：核心资料变为“差异待核实”、合同或回款更新、出现新的风控预警 | 出现差异仍存在的阻断类预警时不能审核通过；其他变化不影响，申请照常可审核通过，按当次依据审核；不要求债务人重新确认；变化只在[当前情况](#current-state)中提示 | 审核通过后，核心资料仍为“差异待核实”时调取被拒绝，见[推送条件（F-M9-05）](#F-M9-05) |
| 运营审核通过后 | 审核结论不变，不要求重新审核 | 推送内容仍为审核通过时确定的内容；每次调取按推送条件判断 |
| 已推送后 | 不变 | 推送状态保持“已推送”；之后的调取仍返回同一份内容，不满足条件时被拒绝；没有自动更新或撤回 |

- 平台不因资料变化撤销、终止或改写任何申请、审核结论、推送内容或推送记录。
- 已推送资产之后出现核心资料差异或风控预警时，申请详情的[当前情况](#current-state)照常展示，运营人员据此在平台外与资产数字化平台、企业沟通；本期没有已推送内容的修订功能。

<a id="status-combo"></a>
## 12. 状态组合

一笔取得推送资格的资产，推送状态与推送条件是两个独立维度。下表写清每种组合下调取的结果、运营人员能做什么，以及债权人看到什么。

| 推送状态 | 推送条件（到期、回款、核心资料、阻断类预警） | 资产数字化平台调取时 | 运营能做什么 | 债权人看到 |
| --- | --- | --- | --- | --- |
| 存证中 | 不判断 | 被拒绝（存证未完成） | 不能操作 | 未推送 |
| 存证失败 | 不判断 | 被拒绝（存证未完成） | 重新存证 | 未推送 |
| 待推送 | 满足 | 成功，推送状态变为“已推送” | 不需要操作 | 未推送 |
| 待推送 | 不满足 | 被拒绝，记录原因 | 不需要操作；核心资料待核实时可在 M3 核实 | 未推送 |
| 已推送 | 满足 | 成功，返回同一份内容 | 不需要操作 | 已推送 |
| 已推送 | 不满足 | 被拒绝，记录原因 | 不需要操作 | 已推送 |

<a id="records"></a>
## 13. 操作留痕

- 每次生效的审核通过留存：申请编号、应收账款编号、审核人、审核时间、审核结论、审核说明、审核时的关联预警情况。
- 每次存证留存：申请编号、提交方式（审核通过后自动／重新存证及提交人）、提交时间、结果、存证凭证或失败原因。
- 每次计入推送记录的调取留存：申请编号、调取平台、调取时间、结果、拒绝原因。
- 留痕不可编辑、不可删除；审核与存证在[申请详情与审核依据（F-M9-02）](#F-M9-02)中查看，调取在 M15 中查看。
- 因不满足条件、提交失败或重复提交而未生效的审核或重新存证，不形成记录，状态不变。

<a id="pending"></a>
## 14. 待确认事项与依赖

| <a id="Q-M9-03"></a>资产数字化平台的调取能力（Q-M9-03，待验证） | 推送依赖资产数字化平台的调取方式，目前未取得其对接说明：如何发现可调取的资产、是否按资产逐笔调取、调取后生成数字凭证与发放的结果是否回传、调取方如何认证。这些不是产品取舍，需要研发与资产数字化平台核验 | 正文按“只有获准平台能调取、按资产逐笔记录、调取成功即已推送、对方后续处理本期不展示”编写。核验结果影响[推送条件（F-M9-05）](#F-M9-05)、[调取的处理](#retrieval)；对应验收标“待验，不判通过” |
| <a id="Q-M9-04"></a>万纳连的上链能力（Q-M9-04，待验证） | 存证依赖万纳连的上链接口，目前未取得对接说明：单笔数据大小限制、上链结果返回哪些凭证（交易哈希、区块高度等）、写入失败与超时如何返回。这些不是产品取舍，需要研发与万纳连核验 | 正文按“上链成功即存证成功、返回失败即存证失败、未返回时保持存证中”编写；存证凭证展示的项目以核验结果为准。影响[存证](#notarize)；对应验收标“待验，不判通过” |

依赖：

- 应收查看与确权申请（M7a）：申请、申请编号、申请状态定义、当次依据、发起记录、到期自动关闭（含关闭时间与关闭前环节）；接收本模块的审核通过，使申请状态变为“运营审核通过”；在申请详情中原样展示本模块提供的推送进度。
- 确权待办与确认处理（M7b）：债务人确认结论、处理人、处理时间，带来“待运营审核”；发送“有新的确权申请待运营审核（M7b-NT03）”，打开后前往本模块该申请的详情，本模块不发同义消息；债务人不展示推送进度。
- 应收账款（M3）：应收账款当前资料与到期、回款、核心资料状态，资产健康度，预警信息，单据编号跳转规则；进度条中接入本模块的推送环节（运营与债权人视角），申请编号进入本模块申请详情的入口。
- 合同信息（M4）、车辆履约（M5）、提单信息（M12）、保单信息（M13）、资金收付（M14）：从本模块按单据编号与 VIN 进入查看当前资料并返回。
- 风控预警与三方数据源（M8）：被审核应收账款的关联预警（数量、等级、规则、差异摘要、差异现状、预警状态、处理结果、入口）及是否存在差异仍存在的阻断类预警；规则的当前等级与启用状态由 M8 风控规则配置决定；按 M8 [与运营审核的关系](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#m9-relation)。
- 数据监控（M15）：展示资产的推送状态、推送条件、推送记录与平台调取情况，提供重新存证入口；规则以本模块为准。
- 企业登录与首次入驻（M1）：企业用户姓名、债权人企业绑定的钱包地址及其缩写规则。
- 运营登录、企业邀请与企业管理（M2）：运营人员账号及状态、运营端界面语言与时区；运营端菜单登记。
- 消息中心（M10）：承接本模块的站内消息，按[来源接入要求（MSG-06）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-06)。
- 万纳连与资产数字化平台：上链能力与对方的调取方式由研发对接，见[万纳连的上链能力（Q-M9-04）](#Q-M9-04)、[资产数字化平台的调取能力（Q-M9-03）](#Q-M9-03)；原型展示不代表能力已实现。
- 审核与推送条件须以提交或调取时的数据为准、同一申请只有一次审核生效、同一资产只有一份成功的存证、到期时点之后的审核通过不生效，实现与验证归研发、测试。
