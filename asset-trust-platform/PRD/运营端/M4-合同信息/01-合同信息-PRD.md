# 合同信息 · 功能与业务规则

2026-11-24｜运营端：运营人员｜需求评审稿（待多模块联调）

本模块共三册：本册写功能、业务规则与字段规则；[流程图](./02-合同信息-流程图与状态机.md)画出资料归集与跨模块跳转；[验收](./04-合同信息-验收.md)供测试使用。本模块自身不发送任何消息，所以没有 03 消息通知册，并非缺失。

编号说明：功能编号（F-M4-*）标在章节标题上，供验收追溯；含义不变的编号沿用原值，已删除的条目不再占号，缺号不代表遗漏。文中“M1”“M2”“M8”“M9”“M11”指资产可信平台的同级模块；应收账款（M3）、合同信息（M4，本模块）、车辆履约（M5）、提单信息（M12）、保单信息（M13）、资金收付（M14）是同批重组的运营端资产数据模块，本册只引用其业务名称。

本册只定义信息需求与业务行为，不涉及来源系统的接口字段和取数方式；页面布局与交互承载由 Hallmark 设计决定。以下设计约束由用户确定，保持不变：

- 运营端左侧菜单名称为“合同信息”，下分“内销合同”“外采合同”“外销合同”三个页签，默认打开“内销合同”。
- 三个页签的详情使用同一结构：概要 → 执行进度 → 单据清单 → 车辆清单 → 附件。
- 列表只放用于筛选和比较的字段；页面中的单据编号都可点击，进入该单据所在模块的详情；一个事实只在一个模块完整展示，其他模块展示摘要并跳转。
- 字段名称按资产数据模块统一命名：合同分外采合同、内销合同、外销合同，发票分外采发票、内销发票，字段名带对应前缀；单价链为外采单价 → 内采单价 → 外销单价。

## 1. 模块是什么

合同信息以“一份合同”为单位，回答“这份合同执行到哪一步：开了多少票、付了或收了多少款、合同里的车走到哪里”。平台把 ERP 中已审核的三类交易依据分别作为合同展示：Carloha Holding 向主机厂采购车辆的外采合同、Holding 卖给 Carloha Nigeria 的内销合同、Nigeria 卖给终端客户的外销合同。每份合同的详情先给出合同身份与金额，再给出 2～4 个执行进度指标，最后列出关联的发票或收款、合同车辆和附件。本模块是资产数据的“交易依据”：应收账款（M3）、车辆履约（M5）中的合同号都进入这里；这里的发票号、VIN、交易流水号又进入应收账款、车辆履约、资金收付。本模块只供运营端使用，只读。

基本原则：

- 三类合同各自独立，不互相合并：内销合同只看内销发票和内销收款，外采合同只看外采发票和外采付款，外销合同只看外销收款。外销没有销售发票，外销合同不含发票层。
- 合同详情展示合同自己的金额和进度；单张发票、单辆车、单笔收付的完整信息在其所在模块查看，本模块只展示摘要并跳转。
- 内销合同的内销已收款、内销未收款与应收账款（M3）的已收款、待收款同口径：一张内销发票就是一笔应收账款，合同的收款是其全部内销发票收款的合计。
- 本模块不判断任何风控规则，也不在字段旁给出风控提示。功能清单中合同维度的风控逻辑（如内销发票金额合计大于内销合同金额、外采总成本高于内销合同金额、外采付款高于外采发票金额、外销单价低于内采单价、车辆销售款未全部收回、车辆出库时未收款）由风控预警（M8）判断和完善，本模块只承接 M8 提供的关联预警。
- 平台不生成、不签署、不修改任何单据；任何角色都不能在本模块新增、修改或删除合同、发票、车辆和款项资料。
- 企业端（债权人、债务人）本期都看不到合同信息菜单；企业端在应收账款详情中看到的内销合同摘要按应收账款（M3）的规定，可见范围不因本次调整扩大。

**一个完整的例子**（企业、客户名称、单据编号和金额为演示值；汇率按 1 USD = 1,500.00 NGN）。

- 内销合同 SC-0008（内销订单编号 DO-0008）：内销合同日期 2026-08-01，内销卖方 Carloha Holding、内销买方 Carloha Nigeria，内销合同金额 150,000.00 USD，价格条款 CIF，交货地点 Lagos，付款条件“T/T 90 天”，合同车辆 VIN-A 至 VIN-E 共 5 辆，合同中车辆单价各 30,000.00 USD。合同下有两张已审核的内销发票：PI-0012（VIN-A、VIN-B、VIN-C，90,000.00 USD，账期 90 天，应收账款到期日 2026-12-19，已收款 45,000.00 USD）和 PI-0015（VIN-D，30,000.00 USD，账期 90 天，尚无收款）；VIN-E 尚未开票。
- 外采合同 PC-0301（外采订单编号 PO-0301）：外采合同日期 2026-07-15，采购公司 Carloha Holding，外采供应商“主机厂甲”，外采合同金额 260,000.00 USD，共 10 辆车（含 VIN-A 至 VIN-E），合同车辆单价各 26,000.00 USD。合同下有外采发票 PPI-0301（VIN-A 至 VIN-E，车辆单价各 26,000.00 USD，合计 130,000.00 USD），已付款两笔：PAY-0101 60,000.00 USD、PAY-0102 70,000.00 USD；其余 5 辆尚未开外采发票。
- 外销合同 SO-2045（零售）：外销卖方 Carloha Nigeria，外销客户 Lagos Motors Ltd，外销合同日期 2026-11-01，VIN-A 外销单价 48,000,000.00 NGN（32,000.00 USD），收款 RC-7781 48,000,000.00 NGN，2026-11-05 外销出库。VIN-B 在另一份外销合同 SO-2046 中，外销单价 31,000.00 USD，已收款 15,000.00 USD，已出库。

运营人员打开“合同信息”，默认看到“内销合同”页签，SC-0008 一行显示内销合同金额 150,000.00 USD、内销已开票 120,000.00 USD／内销未开票 30,000.00 USD、内销已收款 45,000.00 USD／内销未收款 75,000.00 USD、终端销售进度 40.00%、终端回款进度 31.33%、预警“无”。进入详情，执行进度并列展示内销合同金额 150,000.00 USD 与外采总成本 130,000.00 USD（只对照，不作判断）；内销发票清单中点 PI-0012 进入应收账款（M3）详情，返回后在车辆清单中看到 VIN-E 的归属内销发票为“未开票”，内采单价取内销合同车辆单价 30,000.00 USD 并标“合同价”，点 VIN-A 进入车辆履约（M5）。运营切到“外采合同”页签打开 PC-0301：外采已开票 130,000.00 USD、外采未开票 130,000.00 USD、外采已付款 130,000.00 USD、外采未付款 0.00 USD、外采已付款比率 100.00%；车辆清单中 VIN-A 至 VIN-E 的外采单价取自外采发票，其余 5 辆取外采合同单价并标“合同价”；在外采发票 PPI-0301 下点付款 PAY-0101 进入资金收付（M14）核对凭证，返回 PC-0301。再切到“外销合同”页签打开 SO-2045：外销合同金额 48,000,000.00 NGN（32,000.00 USD），外销已收款比率 100.00%，已出库 1 辆／共 1 辆，收款记录中点 RC-7781 进入资金收付。

### 1.2 本期不做

- 二手车业务。
- 在平台录入、编辑、删除或补传任何合同、发票、车辆和款项资料；运营端和企业端都没有这类操作。
- 任何风控规则的判断和提示，包括功能清单列在合同维度下的全部风控逻辑：由风控预警（M8）判断、生成和处理，本模块只承接 M8 提供的关联预警。
- 原上游采购追溯、下游销售与收款追溯中的“车辆归属判定”（外采合同买方、外销合同卖方与应收账款主体的比对）：本期推荐不保留，见[待确认事项](#pending)中的 M4-Q01。
- 原上游采购追溯中的“按应收账款车辆追溯”和核对提示：本模块以合同为单位展示，车辆按合同自己的车辆明细列出，不再从应收账款反查。
- 外销销售发票：外销没有销售发票，外销合同不含发票层。
- 车辆的历次物流节点：合同车辆清单只展示每辆车当前的物流节点，节点记录在车辆履约（M5）中查看。
- 把付款或收款拆分到单辆车，以及计算单车成本、毛利。
- 单张发票、单笔收付、单辆车、提单、保单的完整信息：分别在应收账款（M3）、资金收付（M14）、车辆履约（M5）、提单信息（M12）、保单信息（M13）展示，本模块只展示摘要并跳转。
- 汇率维护：由 M11 汇率管理定义。
- 企业端查看合同信息，包括债权人和债务人。
- 中文以外的语言。

## 3. 共用规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。采信范围、金额与美元折算、比率、单据编号跳转与详情三层结构与应收账款（M3）共用规则同口径。

<a id="adopt-scope"></a>
### 3.1 采信范围

- 平台只采信 ERP 中已审核的单据。未审核的合同、发票、付款、收款和出库记录不出现在本模块，也不参与任何金额、比率和进度计算。
- 已采信的单据之后在 ERP 中被反审核、作废或删除时，从本模块移除，相关金额、比率和进度按剩余资料重新计算。
- 同一张单据再次取得且内容一致时不重复展示；内容不同（含车辆增减、金额、日期变化）时，新内容直接成为当前展示内容，本模块的计算值随之更新。
- 运营人员只看到当前资料，本模块不展示单据变化前的内容和变化历史。

<a id="display-values"></a>
### 3.2 来源值、金额与时间

- 单据编号、主体名称、日期、金额等按 ERP 原值展示，不翻译、不改写。
- 某张单据的某项为空时，该项展示“未提供”；附件没有取得时展示“附件未取得”。各章节只写出带业务含义的空状态（如“未开票”“暂无外采”“暂无外销”“未出库”）。
- 金额与币种代码同时展示，数值在前、币种代码在后，带千分位，例如“150,000.00 USD”。原币金额按原值展示，不四舍五入、不截断。
- 不同币种的原币金额不直接相加；需要合计时按美元折算值合计。
- 单据日期（合同日期、发票日期、交货日期、付款日期、收款日期、出库日期等）按原样展示，不做时区换算。
- 平台记录的时间（附件取得时间）展示到分钟并标注时区：按用户在 M2 选择的时区展示；M2 不提供时区设置时按 UTC 展示。

<a id="usd-rule"></a>
### 3.3 美元折算与比率

- 字段名带“（美元）”的值，按汇率管理（M11）中查看时的当前汇率（1 USD = R NGN）折算：原币为 USD 时等于原值；原币为 NGN 时等于原币金额 ÷ R；M11 没有汇率的其他币种展示“无法折算”；NGN 但 M11 没有可用汇率时，展示“无可用汇率”。M11 汇率更新后，再次查看时按新汇率折算。
- 美元折算值保留两位小数，四舍五入；合计与比率用未取舍的值计算，展示时再取舍。
- 合计中任一笔无法折算或无可用汇率时，合计展示“无法计算”，不用 0 或部分合计代替。
- 比率以百分数展示，保留两位小数、向下截取（例如 99.996% 展示为 99.99%），未达到 100% 时不会显示为 100.00%；超过 100% 时按实际值展示，不封顶。
- 比率的分子或分母无法取得或分母为 0 时，比率展示“无法计算”。
- 比率中分子与分母币种相同时按原币计算；币种不同时按美元折算值计算。

### 3.4 单据编号跳转

本模块中的单据编号都可点击，进入该单据所在模块的详情；看完可返回进入前的位置。

| 编号 | 进入 |
| --- | --- |
| 内销发票号 | 应收账款（M3）中该笔应收账款的详情 |
| 内销合同号、外采合同号、外销合同号 | 本模块对应页签中该合同的详情 |
| VIN | 车辆履约（M5）中该车的详情 |
| 外采付款、内销收款、外销收款的交易流水号 | 资金收付（M14）中该笔收付记录的详情 |

- 同一位置对应多张单据时（例如一辆车属于两张外采发票），全部列出，每个编号各自可进入。
- 编号对应的单据在平台中不存在（未审核或已移除）时，编号按原值展示，不可点击。
- 进入后目标单据已被移除时，提示“该内容不存在或已更新”，可返回来源位置。
- 内销订单编号、外采订单编号只作辅助展示，不可点击。
- 各模块详情的具体落点在多模块联调时核对，见 M4-Q10。

<a id="file-view"></a>
### 3.5 附件查看

- 每份附件展示附件名称和取得时间，可在线查看和下载。
- 同一份附件出现在多个位置时只保存一份，各处引用。
- 附件打开或下载失败时，提示“文件暂时无法打开，请稍后重试”，不影响查看其他信息。

<a id="no-access"></a>
### 3.6 不可访问

- 企业端没有合同信息入口。企业用户通过链接打开本模块任何内容时，统一提示“该内容不存在或无权查看”，不透露其是否存在及任何内容。
- 运营人员处于待首次改密、已停用或锁定中时不能使用本模块，判定以 M2 为准。

<a id="load-fail"></a>
### 3.7 加载失败

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的金额、比率或进度，避免把加载失败误显示为“0.00 USD”“0.00%”或空清单。
- 详情中某一部分（例如执行进度、某个清单）或某一项来自其他模块的值（例如物流节点、应收账款到期日）加载失败时，仅该处提示失败并可重试，其他部分正常展示；依赖该值的合计与比率展示“无法计算”。

<a id="link-rules"></a>
### 4.2 哪些资料属于这份合同

| 资料 | 属于本合同的条件 | 在本模块中的位置 |
| --- | --- | --- |
| 内销发票 | 已审核、关联本内销合同的发票 | [内销发票清单](#field-domestic-invoices) |

| 外采付款 | 登记在本合同任一外采发票下的已审核付款 | [外采发票与付款（F-M4-06）](#F-M4-06) |

<a id="domestic-progress"></a>
### 7.2 执行进度

执行进度分四组并列展示：

| 组 | 业务信息 | 计算 | 无法计算时 |
| --- | --- | --- | --- |
| 开票 | 内销已开票金额（美元） | 本合同全部内销发票金额（美元）合计；没有内销发票时为 0.00 USD | 展示“无法计算” |
| 开票 | 内销未开票金额（美元） | 内销合同金额（美元）− 内销已开票金额（美元）；结果小于 0 时展示 0.00 USD | 展示“无法计算” |
| 收款 | 内销已收款金额（美元） | 本合同全部内销发票下收款金额（美元）合计；没有收款时为 0.00 USD | 展示“无法计算” |
| 收款 | 内销未收款金额（美元） | 本合同各内销发票的待收款金额（美元）合计，即已开票但尚未收回的金额（推荐口径，见 M4-Q02）；没有内销发票时为 0.00 USD | 展示“无法计算” |
| 终端 | 终端销售进度 | 本合同已外销出库的车辆数 ÷ 本合同车辆总数，同时注明“已售 X 辆／共 Y 辆” | 展示“无法计算” |
| 终端 | 终端回款进度 | 本合同全部车辆的外销收款金额（美元）合计 ÷ 内销合同金额（美元） | 展示“无法计算” |
| 成本 | 内销合同金额（美元） | 取[内销合同概要](#field-domestic-summary)中的内销合同金额（美元），在此与外采总成本并列对照 | 展示“无法折算” |
| 成本 | 外采总成本（美元） | 本合同全部车辆的外采单价（美元）合计；外采单价按[术语](#terms)中的口径，取自外采发票或外采合同 | 任一车辆没有外采合同时展示“无法计算”，并注明“N 辆车没有外采合同” |

- 每张内销发票的金额、待收款金额与应收账款（M3）中该笔应收账款的应收账款金额、待收款金额相同。
- 车辆是否已外销出库、每辆车的外销收款金额取自车辆履约（M5）。
- 内销合同金额与外采总成本只并列对照，本模块不判断高低；内销已开票金额超过内销合同金额时按实际值展示，内销未开票金额展示 0.00 USD，不另给提示。是否构成风险由 M8 判断。

### 7.4 车辆清单

- 外采未付款金额是已开票但尚未支付的金额；外采未开票部分由外采未开票金额单独展示。

### 14.1 承接规则

- 本模块不判断任何风控规则，也不在字段旁给出风控提示。哪些预警算与本合同有关，以风控预警（M8）为准。
- 本模块只展示 M8 提供的本合同关联预警：
  - 列表“预警”：本合同未处理的关联预警条数；没有时展示“无”。
  - 详情概要：未处理和已处理的关联预警数量；都没有时展示“无关联预警”。
- 点击预警数量进入 M8，落点按 M8 规定（按本合同筛选的风控预警列表，只有一条时直接进入该预警详情）；看完可返回本合同详情。
- 本模块展示的数量与处理结果始终与 M8 一致，M8 生成或处理预警后随之更新。
- 预警不改变本模块的任何金额、比率和进度；本模块没有处理预警的操作。
- 关联预警加载失败时，仅该部分提示失败并可重试，不显示为“无”或“无关联预警”。

| 编号 | 事项（具体冲突点） | 推荐与当前处理 | 影响 |
| --- | --- | --- | --- |
| M4-Q01 | 原上游采购追溯、下游销售与收款追溯中的“车辆归属判定”（外采合同买方、外销合同卖方与应收账款主体比对，标出“买方不一致”“卖方不一致”）是否保留 | **推荐**：不保留。理由：本模块以合同为单位，车辆取自合同自身的车辆明细，不存在“同一 VIN 归到哪笔采购或销售”的歧义；主体是否一致由 M8 的主体不一致预警判断。风险：应收账款（M3）、车辆履约（M5）按 VIN 列出外采合同、外销合同时，同一 VIN 出现在不同主体的合同中会全部列出，不再标注归属，需由运营结合关联预警判断。下游影响：M8 修订时把原“采购交易”“销售交易”改为外采合同、外销合同。确认前按不保留处理 | [合同资料的采信与归集（F-M4-01）](#F-M4-01)、M3 车辆清单、M8 |
| M4-Q02 | 合同维度的“内销未收款金额”“外采已付款比率”分母：内销未收款可理解为“内销合同金额 − 内销已收款”或“内销已开票 − 内销已收款”；外采已付款比率可理解为“÷ 外采合同金额”或“÷ 外采已开票金额” | **推荐**：内销未收款金额 = 各内销发票待收款合计（内销已开票 − 内销已收款），外采已付款比率 = 外采已付款 ÷ 外采已开票。理由：与应收账款（M3）待收款、外采未付款金额（外采已开票 − 外采已付款）以及外采发票已付款比率的定义一致，合同数是发票数之和；未开票部分已由未开票金额单独展示。风险：合同尚未全部开票时，“未收款 0.00 USD”“已付款比率 100.00%”不代表整份合同已收清或付清，需结合未开票金额阅读 | [内销合同执行进度](#domestic-progress)、[外采合同执行进度](#purchase-progress) |
| M4-Q10 | 各模块详情的跳转落点（外采发票定位、资金收付收付记录、M8 按合同筛选）需与 M3、M5、M8、M14 一致 | 本册按信息架构方案写明目标模块与对象；多模块联调时核对 | [单据编号跳转](#doc-links)、[进入与返回](#entries) |
| M4-Q12 | 外销合同详情的“收款记录”功能清单未单列，是信息架构方案建议新增 | **推荐**：保留。理由：外销已收款金额需要能逐笔核对，并进入资金收付查看凭证。风险：无。确认前按展示处理 | [外销收款记录（F-M4-15）](#F-M4-15) |
| M4-Q13 | 现行风控预警（M8）只向原上游采购追溯的“采购交易”、原下游销售与收款追溯的“销售交易”提供关联预警，没有内销合同；功能清单中合同维度的风控提示尚未纳入 M8 | 本模块按 M8 提供的结果展示，列表“预警”列和详情数量随 M8 完善生效。M8 完善时需写明哪些预警算与内销、外采、外销合同有关，并向三个页签的列表和详情提供未处理、已处理数量及入口 | [关联预警（F-M4-08）](#F-M4-08) |

<a id="dependencies"></a>
依赖：

- ERP：提供已审核的内销合同、外采合同、外销合同（零售、批售）及其车辆明细，内销发票与外采发票（含车辆明细与车辆单价、账期），外采付款、内销收款、外销收款，外采交货日期与外销出库记录，以及各单据附件。取得与同步方式由研发决定。
- 应收账款（M3）：提供每张内销发票形成的应收账款的详情入口、应收账款到期日、已收款金额、待收款金额，以及收款口径。
- 车辆履约（M5）：提供每辆车的当前物流节点、是否外销出库及出库日期、外采单价（含是否为合同价）、外销单价与外销收款金额，以及车辆履约详情入口。
- 资金收付（M14）：提供外采付款、内销收款、外销收款的交易流水号与收付记录详情入口。
- 汇率管理（M11）：提供 USD/NGN 当前汇率。
- 风控预警（M8）：判断全部风控规则（含功能清单合同维度的风控逻辑），定义哪些预警与内销、外采、外销合同有关，向本模块列表和详情提供未处理、已处理的关联预警数量及入口。
- M1、M2：提供运营人员账号及状态、时区设置。
