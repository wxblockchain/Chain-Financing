## 1. 模块是什么

本模块是运营端的风控工作台。平台把已经从 ERP 取得的应收账款、上游采购、车辆履约、下游销售资料互相比对，发现三类问题时生成风控预警：同一笔交易里同一个角色的主体在不同单据上写的不一致（主体不一致）；同一件车辆事情在两份互相引用的资料里 VIN 对不上（VIN 不一致）；一笔应收账款按汇率折算后，已收和未收加起来与应收账款金额差得太多（回款金额偏差）。运营人员在这里查看每条预警的比较对象、实际差异和关联的应收账款，核实后记录处理结果；预警及处理结果同时提供给应收账款、上下游追溯和运营审核查看。本模块另有“三方数据源”入口，只说明后续可接入三方数据源的能力，本期不接入。

基本原则：

- **预警只是提示，不是结论，也不阻断业务。** 预警不改变任何资料、金额和状态，不自动阻止确权申请、债务人确认、运营审核或出库；平台不对主体是否为同一法定主体、资料是否真实下结论，由运营人员核实后记录处理结果。
- **只比已有资料。** 只比较平台已经取得、且有值的资料；资料缺失、尚未取得或无法对应时不比较，也不因此生成预警。
- **比对口径固定，人工不能增删预警。** 预警只由平台按本册规则生成，运营人员不能手动新建、修改或删除预警，也不能调整比对口径。
- **同一件事只预警一次。** 同一个比较对象同一时间最多一条未处理预警；新差异追加到这条预警中，已经处理过的同一差异再次出现不再预警。
- **折算价值只在运营端用于核对。** 回款金额偏差中的汇率折算值只在本模块展示，作为信息核对参考；应收账款的金额、回款数据始终以 ERP 传值为准，汇率取自汇率管理（M11）。
- **只在运营端使用。** 企业端（债权人、债务人）看不到任何风控预警和三方数据源内容。

**一个完整的例子**（企业名称、单据编号为演示值）。应收账款 AR-0012（发票号码 INV-0012，发票卖方 Carloha Holding、买方 Carloha Nigeria，金额 60,000.00 USD）已有两条收款登记。ERP 在 INV-0012 下新登记一笔收款 RC-1003，付款方为“Lagos Auto Trading Ltd”。平台比对应收账款交易 AR-0012 的“买方”角色：基准是发票买方“Carloha Nigeria”，收款登记 RC-1003 的付款方与之不一致，于是生成预警 W-0007：预警类型“主体不一致”，比较对象“应收账款 AR-0012 · 买方”，状态“未处理”，差异现状“差异仍存在”，关联应收账款 AR-0012。全体运营收到站内消息“新的风控预警：主体不一致”；风控预警菜单角标加 1；AR-0012 在应收账款列表中的预警信息变为“有”。运营人员甲从消息进入 W-0007 详情，看到比对口径“同一应收账款交易中，买方在发票、合同、收款登记中应为同一主体”，以及差异明细“发票 INV-0012 买方 Carloha Nigeria；收款登记 RC-1003 付款方 Lagos Auto Trading Ltd”；甲进入 M3 查看 RC-1003 的收款凭证，并向业务方取得代付说明，于是记录处理：处理结果“核实无风险”，处理说明“债务人委托 Lagos Auto Trading Ltd 代付，已取得代付函”，上传代付函。W-0007 变为“已处理”，角标减 1，AR-0012 的预警信息恢复为“无”，M3 中关联风控预警显示“未处理 0、已处理 1”。一周后 ERP 又登记一笔同一付款方的收款 RC-1006，平台不再新建预警，只把 RC-1006 追加到 W-0007 的差异明细并标“处理后新增”。之后 AR-0012 的确权申请进入运营审核（M9），审核人可看到 W-0007 及其处理结果，预警不会自动阻止审核。

### 1.2 本期不做

- 主体不一致、VIN 不一致、回款金额偏差以外的其他风控条件；包括同一 VIN 出现在多笔应收账款、上游付款金额关系、下游收款金额关系、提单装船日期与发票不一致等。其中各模块已有的“核对提示”继续由 M3、M4、M5 自行展示，不转为风控预警。
- 风控预警自动阻止确权申请、债务人确认、运营审核或出库，或者自动改变任何申请、审核、出库资格。
- 平台判断两个不同名称是否为同一法定主体，或维护主体别名、关联公司对照表。
- 运营人员手动新建、修改、删除、合并预警，或者调整比对口径与阈值。
- 处理结果的修改、撤回或二次处理。
- 风控预警的导出、批量处理和指派给某个运营人员。
- 接入任何三方数据源：不提供数据源配置、连接、测试、联网核验，也不展示模拟的接入状态或核验结果。
- 企业端查看风控预警或三方数据源。
- 以三方数据或用户自填资料作为比对依据：本期只比较平台从 ERP 取得的资料和 M11 的汇率。
- 邮件、短信等站外通知。
- 中文、英文以外的语言。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 风控预警（预警） | 平台按本册比对规则发现差异后生成的一条记录，有平台生成的预警编号，全平台唯一、生成后不变 |
| 预警类型 | 主体不一致（Party mismatch）、VIN 不一致（VIN mismatch）、回款金额偏差（Collection amount deviation） |
| 交易 | 本模块比较主体时使用的业务单位：应收账款交易（M3 的一笔应收账款）、采购交易（M4 的一张外采订单）、销售交易（M6 的一份销售合同） |
| 角色 | 主体在交易中的身份，例如应收账款交易的卖方、买方，采购交易的买方、卖方（供应商），销售交易的卖方、客户 |
| 比较对象 | 一条预警所比较的那件事：主体不一致为“某交易 · 某角色”；VIN 不一致为“某份资料与其引用的合同”；回款金额偏差为“某笔应收账款的回款” |
| 基准值 | 比较时作为标准的那一项值，例如应收账款交易中发票上的买方 |
| 差异项 | 比较对象中一处具体的不一致：主体不一致为一个与基准值不同的主体值；VIN 不一致为一个在被引用合同中找不到的 VIN；回款金额偏差为一次超过阈值的比对结果 |
| 预警状态 | 未处理（Open）、已处理（Processed），只表示运营人员是否已记录处理结果 |
| 差异现状 | 差异仍存在（Persists）、差异已消除（Cleared），表示按最新资料比对时差异是否还在；与预警状态相互独立 |
| 处理结果 | 运营人员核实后选择的结论：核实无风险（Verified – no risk）、确认有风险（Risk confirmed） |
| 关联应收账款 | 一条预警涉及的应收账款，用于从预警追到应收账款、从应收账款看到预警 |
| 核对提示 | M3、M4、M5 按资料自动给出、只供运营参考的差异说明；不是风控预警，本模块不接收、不处理 |
| 三方数据源 | 平台以外的第三方数据服务；本期只做能力说明占位，不接入 |
| 运营人员 | 运营端账号的使用者，即 M2 定义的运营管理员；本期运营端只有这一种角色，权限相同 |

## 3. 共用展示与异常规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。展示口径与 M3 的[来源值、金额与时间](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#display-values)一致。

<a id="display-values"></a>
### 3.1 来源值、金额与时间

- 主体名称、VIN、单据编号、金额等来自 ERP 的值，按 ERP 原值展示，不翻译、不改写；切换中英文只改变平台自身的字段名称、类型名称、状态名称和提示。
- 金额与币种代码同时展示，数值在前、币种代码在后，带千分位，例如“60,000.00 USD”。ERP 提供的金额按原值展示，不四舍五入、不截断。任何位置都不展示没有币种的金额。
- 平台按汇率折算得到的金额只出现在[回款金额偏差比对（F-M8-04）](#F-M8-04)中，并标明“折算”；展示保留两位小数，四舍五入；比较时使用未取舍的计算值。
- ERP 提供的日期（收款日期、合同日期等）按 ERP 日期原样展示，不做时区换算。
- 平台自己记录的时间（预警生成时间、最近比对时间、处理时间、预警记录中的各时间）展示到分钟并标注时区：按运营人员在 M2 账号设置中选择的时区展示；M2 不提供时区设置时统一按 UTC 展示。

<a id="no-access"></a>
### 3.2 不可访问

- 企业端没有任何风控预警、三方数据源入口。企业用户通过链接打开本模块任何内容时，统一提示“该内容不存在或无权查看”，不透露其是否存在及任何内容。
- 运营人员处于待首次改密、已停用或锁定中时不能使用本模块，判定以 M2 为准。

<a id="load-fail"></a>
### 3.3 加载失败

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的差异或状态，避免把加载失败误显示为“暂无风控预警”或“差异已消除”。
- 详情中某一部分（例如关联应收账款、预警记录）加载失败时，仅该部分提示失败并可重试，其他部分正常展示；差异明细加载失败时不能提交处理。
- 待办数量取数失败时不展示角标（不展示为 0），菜单照常可用。

<a id="F-M8-01"></a>
## 4. 比对与预警生成（F-M8-01）

适用范围：平台取得或更新资料后的自动比对与预警生成规则。结果对运营人员可见，没有用户操作。

流程参见：[比对与预警生成（图 M8-1）](./02-风控预警与三方数据源-流程图与状态机.md#fig-m8-1)。
验收参见：[比对与预警生成](./04-风控预警与三方数据源-验收.md#acc-f-m8-01)。

<a id="compare-when"></a>
### 4.1 什么时候比对

- 平台从 ERP 取得新资料、资料内容更新或资料被移除后，对受影响的比较对象重新比对。受影响的比较对象分别见[主体不一致比对（F-M8-02）](#F-M8-02)、[VIN 不一致比对（F-M8-03）](#F-M8-03)、[回款金额偏差比对（F-M8-04）](#F-M8-04)。
- 应收账款核心资料以 M3 当前展示的原资料为准；M3 中处于“差异待核实”时新取得但未被采用的值不参与比对。
- 只比较与应收账款有关的资料：应收账款交易本身，以及 M4、M6 中有关联应收账款的采购交易、销售交易，M5 中出现在应收账款销售清单里的车辆。
- 平台上线时，对已经取得的全部资料做一次比对。
- 运营人员不能手动发起比对。

<a id="item-rules"></a>
### 4.2 生成、追加与去重

比对发现差异项时，按下表处理（同一比较对象内判断）：

| 情况 | 结果 | 是否发消息 |
| --- | --- | --- |
| 该比较对象此前没有出现过这个差异项，且当前没有未处理预警 | 新建一条预警，状态“未处理”，差异现状“差异仍存在” | 发送[新的风控预警（M8-NT01）](./03-风控预警与三方数据源-消息通知.md#M8-NT01) |
| 该比较对象此前没有出现过这个差异项，但当前已有一条未处理预警 | 把新差异项追加到这条未处理预警中，不新建预警 | 不发送 |
| 这个差异项已在该比较对象的某条预警中出现过，只是出现在一份新的记录中 | 把新记录追加到包含该差异项的那条预警的差异明细中；那条预警已处理时标“处理后新增”，预警状态不变 | 不发送 |
| 这个差异项与已有预警完全相同（同一记录、同一值） | 不做任何变化 | 不发送 |

- 差异项的判断口径：主体不一致按“比较对象 + 不一致的主体值”判断是否同一差异项；VIN 不一致按“比较对象 + 找不到的 VIN”判断；回款金额偏差没有已处理后的去重，见[回款金额偏差的生成](#repay-item)。
- 预警一经生成不会被删除；比较对象所涉及的资料之后被 ERP 移除时，预警保留，差异现状按最新资料更新。

<a id="diff-state"></a>
### 4.3 差异现状

- 每次重新比对后，更新该比较对象全部预警的差异现状和最近比对时间：仍有任一差异项时为“差异仍存在”，全部差异项都不再出现时为“差异已消除”。
- 差异已消除不会自动结束预警：未处理的预警仍为“未处理”，需要运营人员核实后记录处理结果。
- 差异已消除后同一差异项再次出现时，差异现状恢复为“差异仍存在”，不新建预警，不发消息。
- 差异现状只描述资料比对结果，不改变预警状态和处理结果。

<a id="related-receivables"></a>
### 4.4 关联应收账款

| 预警类型 | 比较对象 | 关联应收账款 |
| --- | --- | --- |
| 主体不一致 | 应收账款交易 · 角色 | 该应收账款 |
| 主体不一致 | 采购交易 · 角色 | M4 中该采购交易的[关联应收账款](../M4-上游采购追溯/01-上游采购追溯-PRD.md#field-receivables) |
| 主体不一致 | 销售交易 · 角色 | M6 中该销售交易的关联应收账款 |
| VIN 不一致 | 应收账款发票与其合同 | 该发票形成的应收账款 |
| VIN 不一致 | 保单、出库交付记录或车辆异常事件与其引用的合同 | 销售清单中含该 VIN 的全部应收账款 |
| 回款金额偏差 | 应收账款的回款 | 该应收账款 |

- 关联应收账款随资料更新而变化，预警中展示当前结果。
- 关联应收账款的债权人、债务人企业看不到这条预警，见[不可访问](#no-access)。

<a id="not-blocking"></a>
### 4.5 预警与后续业务的关系

- 预警的生成、未处理或处理结果都不改变应收账款的任何资料、金额和状态，不改变 M4、M5、M6 的归属结果和核对提示。
- 预警不是确权申请、债务人确认、运营审核或出库的条件，不自动阻止这些业务；M7a、M7b 已按此规定，M9 按[关联预警对外提供与跨模块入口（F-M8-08）](#F-M8-08)展示关联预警供审核人判断。
- 处理结果“确认有风险”同样不自动阻止后续业务，只作为运营审核时的参考。

<a id="F-M8-02"></a>
## 5. 主体不一致比对（F-M8-02）

适用范围：平台对同一交易、同一角色的主体在已有合同、发票或款项记录中是否一致的比对。没有用户操作。

流程参见：[比对与预警生成（图 M8-1）](./02-风控预警与三方数据源-流程图与状态机.md#fig-m8-1)。
验收参见：[主体不一致比对](./04-风控预警与三方数据源-验收.md#acc-f-m8-02)。

<a id="party-points"></a>
### 5.1 比较哪些主体

每个交易的每个角色以一项基准值为准，与同一交易中其他记录里同一角色的主体逐一比较：

**应收账款交易（M3）**

| 角色 | 基准值 | 与之比较的值 |
| --- | --- | --- |
| 卖方 | 发票卖方 | 每份合同的卖方；每条收款登记的收款方 |
| 买方 | 发票买方 | 每份合同的买方；每条收款登记的付款方 |

**采购交易（M4）**

| 角色 | 基准值 | 与之比较的值 |
| --- | --- | --- |
| 买方 | 外采订单买方 | 每条外采付款的付款方 |
| 卖方（供应商） | 外采订单卖方 | 每条外采付款的收款方 |

**销售交易（M6）**

| 角色 | 基准值 | 与之比较的值 |
| --- | --- | --- |
| 卖方 | 销售合同卖方 | 每条收款的收款方 |
| 客户 | 销售合同客户 | 每条收款的付款方 |

- 由 ERP 从所选单据带出的主体（外采发票、外采付款中带出的订单买卖方，收款登记中带出的发票买卖方，下游发票带出的合同信息）与原单据相同，不重复比较。
- 不比较不同交易之间的主体。M4 的“买方不一致”、M6 的“卖方不一致”是跨交易的车辆归属标注，不生成主体不一致预警。
- 提单的发货人与收货人、保单的投保人与被保险人、清关登记的进口方与出口方、费用登记的收付款方不属于合同、发票或款项记录中的交易主体，本期不比较。

<a id="party-equal"></a>
### 5.2 怎样算一致

- 按 ERP 原值比较主体名称；比较时忽略首尾空格、把连续空格视为一个空格、不区分英文大小写。除此之外的任何不同（包括标点、缩写、“Ltd”与“Limited”、中英文名称）都算不一致。
- 平台不判断两个不同名称是否为同一法定主体，也不把关联公司视为同一主体；是否为同一主体由运营人员核实后在处理结果中说明。
- 基准值未提供时，该交易的该角色本次不比较；某条记录中的主体未提供时，该条记录不参与比较。两者都不生成预警。

<a id="party-detail"></a>
### 5.3 预警内容

- 比较对象写作“交易类型 + 交易标识 · 角色”，例如“应收账款 AR-0012 · 买方”“采购交易 PO-031 · 卖方（供应商）”“销售交易 SC-2045 · 客户”。
- 比对口径写作“同一{交易类型}中，{角色}在{参与比较的单据}中应为同一主体”。
- 差异明细先列基准：单据类型、单据编号、主体值；再逐条列出不一致的记录：单据类型、单据编号（收款或付款记录写交易编号，未提供时写“未提供”）、主体值、该记录的取得时间、是否“处理后新增”。
- 差异摘要取第一处差异，写作“{角色}：{基准单据} 为 {基准值}，{不一致单据} 为 {不一致值}”；还有其他差异时加“等 N 处”。

<a id="F-M8-03"></a>
## 6. VIN 不一致比对（F-M8-03）

适用范围：平台对互相引用的两份资料中同一车辆事项的 VIN 是否一致的比对。没有用户操作。

流程参见：[比对与预警生成（图 M8-1）](./02-风控预警与三方数据源-流程图与状态机.md#fig-m8-1)。
验收参见：[VIN 不一致比对](./04-风控预警与三方数据源-验收.md#acc-f-m8-03)。

<a id="vin-points"></a>
### 6.1 比较哪些资料

“同一车辆事项”指一份列有 VIN 的资料，与它所引用的、同样列有 VIN 的合同：前者中的车辆应当出现在后者的车辆中。本期比较以下四组：

| 比较对象 | 列有 VIN 的资料 | 被引用的合同 | 判为不一致的条件 |
| --- | --- | --- | --- |
| 应收账款发票与其合同 | M3 发票销售清单中的每辆车 | 该发票对应的全部合同（M3 合同信息），看合同列明的车辆 VIN | 销售清单中的某个 VIN 不在任何一份对应合同中 |
| 保单与其关联合同 | M5 保单覆盖车辆中的每辆车 | 保单的关联合同号码对应的 M3 合同，看合同列明的车辆 VIN | 覆盖车辆中的某个 VIN 不在任何一份关联合同中 |
| 出库交付记录与其销售合同 | M5 该车出库交付记录中的 VIN | 记录中的销售合同编号对应的 M6 销售合同，看合同车辆 | 该 VIN 不在这份销售合同的车辆中 |
| 车辆异常事件与其关联合同 | M5 该车异常事件中的 VIN | 事件中的关联合同编号对应的 M3 合同或 M6 销售合同，看合同列明的车辆 | 该 VIN 不在这份合同的车辆中 |

- VIN 按 ERP 原值比较，不区分大小写，忽略空格。
- 以下情况不比较，也不生成预警：被引用的合同号码未提供；平台没有取得该号码对应的合同；被引用合同的车辆 VIN 未提供；列有 VIN 的资料中的车辆不在任何应收账款的销售清单中。
- 上游采购只有 VIN 登记列明 VIN，外采订单和外采发票只列型号和数量，因此上游没有 VIN 比较点；登记车辆数、型号与订单的差异由 M4 核对提示展示。
- 同一 VIN 出现在多张提单、多笔应收账款或多笔上下游交易中，不属于 VIN 不一致，分别由 M3、M4、M5、M6 如实展示。

<a id="vin-detail"></a>
### 6.2 预警内容

- 比较对象写作“{资料} 与 {被引用合同}”，例如“发票 INV-0012 与合同 CT-0012”“保单 PL-889 与合同 CT-0012”“VIN-B 出库交付记录与销售合同 SC-2045”。
- 比对口径写作“{资料}中的车辆应列在其{引用的合同}中”。
- 差异明细逐个列出找不到的 VIN：VIN、所在资料（类型与编号）、被引用合同（类型与编号）及该合同列明的车辆数、取得时间、是否“处理后新增”。
- 差异摘要取第一个 VIN，写作“{资料}中的 {VIN} 不在{合同}的车辆中”；还有其他 VIN 时加“等 N 个”。

<a id="F-M8-04"></a>
## 7. 回款金额偏差比对（F-M8-04）

适用范围：平台对每笔应收账款的应收账款金额，与按汇率折算后的累计已收、未收金额之和的比对。没有用户操作。本节即 M3 中的“回款预警”。

流程参见：[比对与预警生成（图 M8-1）](./02-风控预警与三方数据源-流程图与状态机.md#fig-m8-1)。
验收参见：[回款金额偏差比对](./04-风控预警与三方数据源-验收.md#acc-f-m8-04)。

<a id="repay-rule"></a>
### 7.1 比对规则

- 比较时机：该应收账款的收款登记、未收金额或发票金额有新增、更新或移除时；以及 M11 首次设置汇率后，对此前因“无可用汇率”而无法比对的应收账款补做一次比对。之后单纯更新汇率不触发重新比对。
- 计算口径（全部换成应收账款币种）：
  - 已收折算合计 = 本发票下每条收款登记的收款金额折算为应收账款币种后之和；
  - 未收折算 = ERP 未收金额折算为应收账款币种；
  - 差额 = 应收账款金额 −（已收折算合计 + 未收折算）；
  - 偏差比例 = 差额的绝对值 ÷ 应收账款金额。
- 折算：币种与应收账款相同的金额不折算；美元与奈拉之间按 M11 汇率折算，“1 USD = R NGN”，奈拉折合美元 = 奈拉金额 ÷ R，美元折合奈拉 = 美元金额 × R。使用比对时 M11 的当前汇率，并在预警中记录所用汇率的编号、汇率值和生效时间。
- 超过[回款金额偏差阈值](#repay-threshold)时，视为出现差异项。
- 以下情况无法比对，不生成预警，也不视为没有偏差：未收金额未提供；某条收款登记的收款金额或币种未提供；需要折算但无可用汇率；涉及美元、奈拉以外的不同币种。

<a id="repay-threshold"></a>
### 7.2 回款金额偏差阈值

| 本次比对情形 | 视为出现差异项的条件 |
| --- | --- |
| 同币种：收款金额、未收金额与应收账款币种都相同，没有任何金额需要折算 | 差额不为 0 |
| 需要折算：至少一项金额经汇率折算 | 偏差比例超过 5%；正好 5% 不算超过 |

- 判断使用未取舍的计算值；展示的偏差比例保留两位小数，四舍五入。
- 阈值为平台统一规则，运营人员不能调整。

<a id="repay-item"></a>
### 7.3 回款金额偏差的生成

- 每笔应收账款同一时间最多一条未处理的回款金额偏差预警。
- 比对超过阈值、且没有未处理预警时，新建一条预警并发送[新的风控预警（M8-NT01）](./03-风控预警与三方数据源-消息通知.md#M8-NT01)。
- 比对超过阈值、且已有未处理预警时，把本次比对结果追加到这条预警中，预警以最新一次比对结果展示，不新建、不发消息。
- 比对未超过阈值时，该应收账款的回款金额偏差预警差异现状变为“差异已消除”。
- 已处理之后，资料再次变化且比对仍超过阈值时，视为新的事实，新建一条预警。

<a id="repay-detail"></a>
### 7.4 预警内容

| 业务信息 | 含义 |
| --- | --- |
| 比较对象 | “应收账款 {应收账款编号} · 回款” |
| 应收账款金额及币种 | 取自 M3，按原值展示 |
| 收款登记明细 | 每条收款登记的收款交易编号、收款日期、收款金额及币种（原值），以及折算为应收账款币种后的金额（标明折算；同币种时与原值相同） |
| 已收折算合计 | 应收账款币种，标明折算 |
| 未收金额 | ERP 原值及币种，以及折算为应收账款币种后的金额（同币种时与原值相同） |
| 差额 | 应收账款币种，正数表示已收与未收之和少于应收账款金额，负数表示多于应收账款金额 |
| 偏差比例 | 百分比，保留两位小数，四舍五入 |
| 阈值 | 本次比对适用的条件：同币种时为“差额不为 0”，需要折算时为“偏差比例超过 5%” |
| 所用汇率 | 汇率编号、“1 USD = R NGN”、生效时间；本次没有折算时展示“未折算” |
| 比对时间 | 本次比对的时间 |

- 预警追加过多次比对结果时，以最新一次为当前内容，之前各次比对结果在[预警记录](#history)中可查看。
- 差异摘要写作“按汇率折算后，已收与未收之和比应收账款金额{少／多} {偏差比例}”。
- 折算值只用于核对参考，不改变 M3 中的任何金额、回款状态，也不向企业端展示。

## 8. 风控预警列表与待办数量（F-M8-05）

适用角色与前提：可正常使用的运营人员。可查看全部风控预警。运营端左侧菜单名称为“风控预警”。

验收参见：[风控预警列表与待办数量](./04-风控预警与三方数据源-验收.md#acc-f-m8-05)。

列表以预警为单位，每行一条，只展示定位和判断所需的关键字段；差异明细、处理记录等在详情中查看：

| 业务信息 | 含义 | 来源与缺失时 |
| --- | --- | --- |
| 预警编号 | 本条预警的编号 | 平台生成 |
| 预警类型 | 主体不一致／VIN 不一致／回款金额偏差 | 平台判定 |
| 比较对象 | 见各类型的预警内容 | 平台生成 |
| 关联应收账款 | 应收账款编号；有多笔时展示第一笔并注明“等 N 笔” | 平台判定；没有时展示“无” |
| 状态 | 未处理／已处理 | 平台记录 |
| 生成时间 | 预警生成的时间 | 平台记录 |
| 操作 | “查看”，进入该预警详情 | 每行都有 |

查找与筛选：

- 按预警编号查找，支持部分匹配。
- 按应收账款编号或应收账款的发票号码查找，结果为关联应收账款中含该应收账款的预警。
- 按 VIN 查找，结果为差异明细中含该 VIN 的 VIN 不一致预警，以及关联应收账款销售清单中含该 VIN 的其他预警。
- 按单据编号查找（外采订单号码、销售合同编号、合同号码、保单号、收款或付款交易编号），支持部分匹配。
- 筛选：预警类型、状态、差异现状、处理结果、生成时间区间。多个条件同时生效。
- 默认排序：未处理在前，已处理在后；同一状态内按生成时间从新到旧。

<a id="badge"></a>
待办数量：

- 左侧菜单“风控预警”上以小角标展示当前未处理预警的条数；没有未处理预警时不展示角标。
- 预警新建后加 1，处理生效后减 1；差异已消除不改变数量。全体运营人员看到同一个数量。

边界与异常：

- 平台还没有任何预警时，展示“暂无风控预警”；有预警但查找或筛选无结果时，展示“没有符合条件的风控预警”并可清除条件。
- 列表不提供新增、编辑、删除和批量处理操作。
- 加载失败按[加载失败](#load-fail)处理。

## 9. 预警详情（F-M8-06）

适用角色与前提：可正常使用的运营人员，从风控预警列表、站内消息、M3—M6 的关联风控预警入口或 M9 进入。

流程参见：[各入口与返回路径（图 M8-4）](./02-风控预警与三方数据源-流程图与状态机.md#fig-m8-4)。
验收参见：[预警详情](./04-风控预警与三方数据源-验收.md#acc-f-m8-06)。

<a id="detail-groups"></a>
### 9.1 详情包含的信息

详情顶部展示预警编号、预警类型、状态、差异现状和生成时间；已处理时同时展示处理结果。这些内容已在顶部展示，下方各类信息中不再重复。

顶部之下包含以下信息类别，展示顺序与承载方式由 Hallmark 决定：

1. 比较对象与比对口径：比较对象、比对口径说明、最近比对时间。
2. 差异明细：按预警类型展示，见[主体不一致的预警内容](#party-detail)、[VIN 不一致的预警内容](#vin-detail)、[回款金额偏差的预警内容](#repay-detail)。
3. 关联应收账款：每笔展示应收账款编号、发票号码、债权人、债务人，可进入 M3 应收账款详情。
4. 处理：未处理时提供[记录处理](#process)入口；已处理时展示处理结果、处理说明、依据附件、处理人和处理时间。
5. [预警记录](#history)。

<a id="source-entry"></a>
### 9.2 资料入口

差异明细中的每份单据都可进入其所属模块查看当前资料和原件，并带上本预警作为返回目标：

| 单据 | 进入哪里 |
| --- | --- |
| 应收账款发票、合同、收款登记 | M3 该应收账款详情 |
| 外采订单、外采付款 | M4 该采购交易详情 |
| 销售合同、收款 | M6 该销售交易详情 |
| 保单、出库交付记录、车辆异常事件 | M5 该车的车辆履约详情 |

- 原件在所属模块中查看，本模块不另存、不另展示附件原件（处理时上传的依据附件除外）。
- 所属模块中的资料已被 ERP 移除时，进入后按该模块规则展示“该内容不存在或已更新”，可返回本预警；本预警中的差异明细保留生成和追加时的值。

边界与异常：

- 打开的预警编号不存在时，展示“该预警不存在”，可返回列表。
- 加载失败按[加载失败](#load-fail)处理。

<a id="F-M8-07"></a>
## 10. 核实处理与预警记录（F-M8-07）

适用角色与前提：可正常使用的运营人员；预警状态为“未处理”。已处理的预警没有处理入口。

流程参见：[预警状态（图 M8-2）](./02-风控预警与三方数据源-流程图与状态机.md#fig-m8-2)、[记录处理的提交（图 M8-3）](./02-风控预警与三方数据源-流程图与状态机.md#fig-m8-3)。
验收参见：[核实处理与预警记录](./04-风控预警与三方数据源-验收.md#acc-f-m8-07)。

<a id="process"></a>
### 10.1 记录处理

运营人员针对本条预警当前全部差异项记录一次处理：

| 业务信息 | 类型与取值 | 必填与默认 | 校验与失败结果 |
| --- | --- | --- | --- |
| 处理结果 | 单选：核实无风险／确认有风险 | 必填，无默认 | 未选择时不能提交并提示 |
| 处理说明 | 文本，说明核实过程、依据及结论，例如是否为同一法定主体、差异原因 | 必填，无默认 | 去除首尾空格后为 1—500 字；为空或超长时不能提交并提示 |
| 依据附件 | 附件 | 选填 | PDF、JPG、PNG；最多 5 个；单个不超过 20 MB；不符合时该文件不能加入并提示原因 |

- 提交前须让运营人员确认：处理结果提交后不能修改或撤回。
- 差异现状为“差异已消除”时同样需要记录处理，处理结果和说明由运营人员按核实情况填写。

结果：

- 提交成功后预警状态变为“已处理”，记录处理结果、处理说明、依据附件、处理人和处理时间；风控预警待办数量减 1。
- 处理不改变任何资料、金额和业务状态；关联应收账款在 M3 的预警信息按[关联预警对外提供](#external)重新计算。
- 处理结果不可编辑、不可删除、不可撤回。

边界与异常：

- 两名运营人员同时处理同一条预警时，先提交者生效；后提交者提示“该预警已被他人处理，请刷新后查看”，本次内容不保存。
- 打开处理后、提交前，本条预警追加了新的差异项时，本次提交不生效，提示“该预警有新的差异，请刷新后核对再处理”，保留已填写内容。
- 提交失败时保留已填写内容，提示失败并可重新提交。
- 运营人员在填写过程中账号被停用或登录失效时，提交不生效，按 M2 规则处理。

<a id="history"></a>
### 10.2 预警记录

每条预警保留从生成到处理的全部经过，按时间从新到旧展示，不可编辑、不可删除：

| 记录事件 | 记录内容 |
| --- | --- |
| 生成预警 | 生成时间、当时的差异项 |
| 追加差异 | 追加时间、新增的差异项或记录；处理后追加的标“处理后新增” |
| 差异已消除 | 比对时间、说明全部差异项已不再出现 |
| 差异再次出现 | 比对时间、再次出现的差异项 |
| 回款比对结果 | 回款金额偏差每次追加的比对结果（各项金额、偏差比例、所用汇率、比对时间） |
| 记录处理 | 处理时间、处理人、处理结果、处理说明、依据附件 |

## 11. 关联预警对外提供与跨模块入口（F-M8-08）

适用角色与前提：可正常使用的运营人员。

流程参见：[各入口与返回路径（图 M8-4）](./02-风控预警与三方数据源-流程图与状态机.md#fig-m8-4)。
验收参见：[关联预警对外提供与跨模块入口](./04-风控预警与三方数据源-验收.md#acc-f-m8-08)。

<a id="external"></a>
### 11.1 向其他模块提供的预警信息

| 使用模块与位置 | 哪些预警算“关联” | 提供什么 |
| --- | --- | --- |
| M3 应收账款列表与详情概要中的“预警信息” | 关联应收账款中含该应收账款的预警 | 是否有未处理预警；M3 再结合自身的核心资料状态得出有／无 |
| M3 回款统计中的“回款预警” | 该应收账款的回款金额偏差预警 | 有未处理的回款金额偏差预警时为“有”，并提供该预警的差异摘要和入口；否则为“无” |
| M3 详情中的关联风控预警 | 关联应收账款中含该应收账款的预警 | 未处理、已处理数量和入口 |
| M4 采购交易详情中的关联风控预警 | 比较对象为该采购交易的预警 | 未处理、已处理数量和入口 |
| M5 车辆履约详情中的关联风控预警 | 差异明细中含该 VIN 的 VIN 不一致预警 | 未处理、已处理数量和入口 |

| M9 运营审核 | 关联应收账款中含被审核应收账款的预警 | 未处理、已处理数量，每条预警的类型、差异摘要、差异现状、处理结果和入口 |

- 回款金额偏差无法比对时不生成预警，M3“回款预警”按其规则展示“无”。
- 企业端看不到以上任何预警信息，与 M3 [企业可见内容](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#enterprise-scope)一致。

### 11.2 与运营审核的关系

- 运营审核时，审核人可以看到被审核应收账款的关联预警及处理结果，并进入本模块查看详情。
- 有未处理预警或处理结果为“确认有风险”时，不自动阻止审核通过或出库；审核人如何考虑预警由 M9 定义，M9 编写时按本节对齐。
- 审核当次所看到的预警情况是否作为审核依据留存，由 M9 定义。

## 12. 三方数据源占位（F-M8-09）

适用角色与前提：可正常使用的运营人员。运营端左侧菜单名称为“三方数据源”。企业端没有该入口。

验收参见：[三方数据源占位](./04-风控预警与三方数据源-验收.md#acc-f-m8-09)。

- 入口内只展示能力说明，须表达三点：
  - 用途：后续可接入第三方数据源，交叉核验平台已取得的企业主体、车辆等资料，并作为风控预警的补充依据。
  - 本期状态：“本期未接入任何三方数据源”。
  - 当前风控预警的依据：只比较平台从 ERP 取得的资料和汇率管理中的汇率，不使用三方数据。
- 不展示任何数据源名称或供应商、连接状态、配置项、接入进度、上线时间、核验结果或示例数据。
- 没有任何操作：不提供配置、连接、测试、申请接入或联网核验。
- 其他模块不以三方数据源为前提，不出现“三方核验通过”等结果表述。

<a id="status-combo"></a>
## 13. 状态组合

一条预警的预警状态与差异现状是两个独立维度，下表写清每种组合下运营人员看到什么、能做什么，以及对外提供的结果。

| 预警状态 | 差异现状 | 运营看到 | 能否记录处理 | 计入待办数量 | M3 预警信息 |
| --- | --- | --- | --- | --- | --- |
| 未处理 | 差异仍存在 | 差异明细与处理入口 | 可以 | 计入 | 有 |
| 未处理 | 差异已消除 | 差异明细（标明已消除）与处理入口 | 可以 | 计入 | 有 |
| 已处理 | 差异仍存在 | 差异明细与处理记录 | 不可以 | 不计入 | 不因本预警为有 |
| 已处理 | 差异已消除 | 差异明细（标明已消除）与处理记录 | 不可以 | 不计入 | 不因本预警为有 |

- 已处理的预警在差异再次出现或追加“处理后新增”记录时，预警状态和处理结果不变。
- M3 预警信息还受 M3 自身核心资料状态影响，以 M3 [预警信息](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#warning-flag)为准。

<a id="pending"></a>
## 14. 待确认事项与依赖

本模块当前没有待确认事项。

依赖：

- 应收账款与发票（M3）：提供应收账款交易的发票、合同、收款登记中的主体，销售清单与合同列明的 VIN，应收账款金额、收款登记金额及币种、未收金额，以及原资料口径；展示本模块提供的预警信息、回款预警和关联风控预警入口。
- 上游采购追溯（M4）：提供采购交易的外采订单买卖方、外采付款付收款方及关联应收账款；展示关联风控预警入口。
- 车辆物流与履约追溯（M5）：提供保单覆盖车辆与关联合同号码、出库交付记录的 VIN 与销售合同编号、车辆异常事件的 VIN 与关联合同编号；展示关联风控预警入口。
- 下游销售与收款追溯（M6）：提供销售交易的合同卖方、客户、合同车辆，收款的收款方、付款方及关联应收账款；展示关联风控预警入口。
- 汇率管理（M11）：提供比对时的当前汇率（汇率值、生效时间、汇率编号）及“无可用汇率”结果。
- 运营审核与资产出库（M9）：展示被审核应收账款的关联预警，预警不自动阻止审核通过和出库；M9 编写时按[与运营审核的关系](#m9-relation)对齐。
- 消息中心（M10）：承接本模块的[新的风控预警（M8-NT01）](./03-风控预警与三方数据源-消息通知.md#M8-NT01)。
- M2：提供运营人员账号及状态、运营端账号设置中的界面语言与时区。
- ERP：各项资料通过 M3—M6 取得，取得方式由研发决定；比对的执行时效由研发确定，消息送达时效按 M10。
