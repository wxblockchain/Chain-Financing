# 资金收付 · 功能与业务规则

2026-11-19｜运营端：运营人员｜需求评审稿（待多模块联调）

本模块共三册：本册写功能、业务规则与字段规则；[流程图与状态机](./02-资金收付-流程图与状态机.md)画出主要流程与状态；[验收](./04-资金收付-验收.md)供测试使用。本模块自身不发送任何消息，所以没有 03 消息通知册，并非缺失。

编号说明：功能编号（F-M14-*）标在章节标题上，供验收追溯。文中“M2”“M8”“M11”指资产可信平台的同级模块；应收账款（M3）、合同信息（M4，分外采合同、内销合同、外销合同三个页签）、车辆履约（M5）、提单信息（M12）、保单信息（M13）、资金收付（M14，本模块）是运营端六个资产数据模块。

本册只定义信息需求与业务行为；页面布局与交互承载由 Hallmark 设计决定。以下设计约束由用户确定，保持不变：运营端菜单名称为“资金收付”；按收付记录展示，每笔收款或付款一行；可按外采付款、内销收款、外销收款三类分别查看（以页签还是筛选承载由设计决定）；详情统一为“概要 → 进度与核对 → 明细”三层；页面中的单据编号都可点击，进入该单据所在模块的详情；一个事实只在一个模块完整展示，其他模块展示摘要并跳转。

## 1. 模块是什么

资金收付以一笔收付记录为单位，回答“这笔钱是谁通过哪个银行账户付给谁的、什么时候、多少钱、对应哪笔业务、凭证是什么”。平台把 ERP 中已审核的收付款整理为三类收付记录：外采付款（采购方付给供应商的车款）、内销收款（债务人付给债权人的车款，即应收账款的回款）、外销收款（终端客户付给债务人的车款）。本模块是资金流水的唯一完整展示位置：应收账款（M3）的回款记录、合同信息（M4）外采合同的付款记录和外销合同的收款记录、车辆履约（M5）的外销收款，都只展示摘要，点交易流水号进入本模块查看收付机构、账号和凭证。本模块只供运营端使用，只读。

基本原则：

- 一笔收付记录就是一笔资金往来，以交易流水号识别，有一个收付日期、一个币种和一个金额。
- 本模块只展示收付记录本身的事实。已收、已付金额的汇总和比率由关联业务所在模块计算（应收账款在 M3，外采合同、外销合同在 M4），本模块不计算。
- 本模块不判断任何风控规则，也不在字段旁给出风控提示；风控由风控预警（M8）判断和处理，本模块只承接 M8 提供的关联预警。
- 企业端（债权人、债务人）本期都看不到资金收付；企业端可见范围不因本次调整扩大。

**一个完整的例子**（企业、客户名称、单据编号、银行和汇率为演示值；汇率按 1 USD = 1,500.00 NGN）。2026-10-15，债务人 Carloha Nigeria 从 Bank N 账号 0123456789 向债权人 Carloha Holding 在 Bank H 的账号 9876543210 支付 25,000.00 USD，支付的是内销发票 PI-0012，ERP 登记并审核后，平台形成内销收款记录 PAY-0451，附付款凭证一份。2026-11-03，终端客户 Lagos Motors Ltd 从 Bank L 向 Carloha Nigeria 在 Bank N 的账号支付 30,000,000.00 NGN，支付的是外销合同 SO-2045，平台形成外销收款记录 RC-7781。运营人员打开“资金收付”，只看内销收款，看到 PAY-0451 一行：收付类型“内销收款”、收付日期 2026-10-15、Carloha Nigeria → Carloha Holding、25,000.00 USD、25,000.00 USD、关联业务 PI-0012。进入详情：概要展示上述信息和关联预警“无关联预警”；进度与核对展示付款方 Carloha Nigeria（Bank N，0123456789）与收款方 Carloha Holding（Bank H，9876543210）；明细中打开付款凭证。运营点关联业务 PI-0012 进入应收账款（M3）该笔应收账款详情，看完返回 PAY-0451 详情，再返回列表，原筛选条件仍在。随后运营在车辆履约（M5）VIN-A 的外销段点交易流水号 RC-7781，进入本模块：收付类型“外销收款”、Lagos Motors Ltd → Carloha Nigeria、30,000,000.00 NGN、20,000.00 USD（折算）、关联业务 SO-2045；点 SO-2045 进入合同信息（M4）外销合同详情，看完返回 RC-7781，再返回 VIN-A。

### 1.2 本期不做

- 在平台录入、编辑、删除任何收付记录或凭证；运营端和企业端都没有这类操作。
- 已收、已付金额的汇总、比率和收付状态：应收账款的已收款、待收款与回款状态在 M3；外采发票已付款、外销合同已收款在 M4。本模块不合计、不判定。
- 把一笔收付拆分到单辆车：外销收款落到单车由车辆履约（M5）定义。
- 任何风控规则的判断，包括付款方、收款方与合同主体是否一致、付款是否超过发票金额：由风控预警（M8）判断、生成和处理，本模块只承接 M8 提供的预警信息。
- 退款、冲销等特殊款项。
- 银行流水的外部核验：三方数据源本期未接入。
- 企业端查看资金收付，包括债权人和债务人。债权人在应收账款中看到的回款银行、账号和凭证以 M3 为准，不因本模块变化。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 收付记录 | 本模块的一行：ERP 中一笔已审核的付款或收款 |
| 收付类型 | 按这笔资金支付的是哪类业务分为外采付款、内销收款、外销收款，见[收付类型的判定](#pay-type) |
| 外采付款 | 采购方向供应商支付外采车款，支付对象是外采发票 |
| 内销收款 | 债务人向债权人支付内销车款，即应收账款的回款（功能清单中称“合同收款”），支付对象是内销发票 |
| 外销收款 | 终端客户向债务人支付外销车款，支付对象是外销合同 |
| 交易流水号 | 识别一笔收付记录的编号，全模块唯一 |
| 外采发票 | 关联到外采订单的形式发票，在合同信息（M4）外采合同中展示 |
| 内销发票 | 关联到内销合同的形式发票；一张内销发票就是一笔应收账款（M3） |
| 外销合同 | 债务人与终端客户的合同（零售或批售），在合同信息（M4）外销合同中展示 |
| 关联业务 | 收付记录支付的业务单据：外采付款对应外采发票，内销收款对应内销发票，外销收款对应外销合同；一笔收付可对应一张或多张 |
| 分配金额 | 一笔收付对应多张关联单据时，分到每张单据的金额 |
| 关联预警 | 风控预警（M8）判定为与本收付记录有关的预警；哪些算有关以 M8 为准 |
| 运营人员 | 运营端账号的使用者，即 M2 定义的运营管理员；本期运营端只有这一种角色，权限相同 |

## 3. 共用展示与异常规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。来源值、美元折算、单据编号跳转与附件查看的口径与[应收账款共用规则（M3）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#shared-rules)一致。

<a id="display-values"></a>
### 3.1 来源值、金额与日期

- 交易流水号、主体名称、银行、账号、日期、金额等按 ERP 原值展示，不翻译、不改写；账号完整展示。
- 金额与币种代码同时展示，数值在前、币种代码在后，带千分位，例如“25,000.00 USD”。原币金额按原值展示，不四舍五入、不截断。
- 收付日期按原样展示，不做时区换算。

<a id="usd"></a>
### 3.2 美元折算

“金额（美元）”按下表得出，并与原币金额同时展示；折算值标明“折算”。

| 原币 | 金额（美元） |
| --- | --- |
| USD | 等于原币金额，不标“折算” |
| NGN | 原币金额 ÷ M11 汇率（1 USD = R NGN），取哪个时刻的汇率见 M14-Q01 |
| 其他币种 | 展示“无法折算”，M11 只维护美元与奈拉 |
| NGN，但 M11 无可用汇率 | 展示“无可用汇率” |

- 折算结果保留两位小数，四舍五入。
- 汇率按[对外提供的汇率口径（FX-05）](../M11-汇率管理/01-汇率管理-PRD.md#FX-05)取得；折算值旁可查看所用汇率值及其生效时间。
- 美元值无法得出时，只展示原币金额和对应说明，不用 0 或其他值代替。

<a id="doc-links"></a>
### 3.3 单据编号跳转

本模块中的单据编号都可点击，进入该单据所在模块的详情；看完可返回进入前的位置。

| 编号 | 进入 |
| --- | --- |
| 交易流水号（列表中） | 本模块该笔[收付记录详情（F-M14-03）](#F-M14-03) |
| 外采发票号 | 合同信息（M4）外采合同页签中该发票所属外采订单的详情，并定位到外采发票清单中的这张发票 |
| 内销发票号 | 应收账款（M3）中该笔应收账款的详情 |
| 外销合同号 | 合同信息（M4）外销合同页签中该合同的详情 |

- 编号对应的单据在平台中不存在（例如尚未审核）时，编号按原值展示，不可点击；该单据之后被采信时变为可点击。
- 进入后目标单据已不再被采信时，提示“该内容不存在或已更新”，可返回本模块。
- 各模块详情的具体落点在多模块联调时核对，见 M14-Q03。

<a id="file-view"></a>
### 3.4 凭证附件查看

- 每份附件展示附件名称和取得时间，可在线查看和下载。
- 平台自己记录的取得时间展示到分钟并标注时区：按运营人员在 M2 选择的时区展示；M2 不提供时区设置时统一按 UTC 展示。
- 附件打开或下载失败时，提示“文件暂时无法打开，请稍后重试”，不影响查看其他信息。

<a id="no-access"></a>
### 3.5 不可访问

- 企业端没有资金收付入口。企业用户通过链接打开本模块任何内容时，统一提示“该内容不存在或无权查看”，不透露其是否存在及任何内容。
- 运营人员处于待首次改密、已停用或锁定中时不能使用本模块，判定以 M2 为准。

<a id="load-fail"></a>
### 3.6 加载失败

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的金额或关联业务，避免把加载失败误显示为“暂无收付记录”。
- 详情中某一部分（如收付双方与账户、凭证附件、关联预警）加载失败时，仅该部分提示失败并可重试，其他部分正常展示。

## 4. 收付记录的采信与分类（F-M14-01）

适用范围：平台从 ERP 取得收付款后，判断哪些进入本模块、属于哪种收付类型。结果对运营人员可见，没有用户操作。

流程参见：[收付记录的采信与分类（图 M14-1）](./02-资金收付-流程图与状态机.md#fig-m14-1)、[收付记录在本模块的展示状态（图 M14-3）](./02-资金收付-流程图与状态机.md#fig-m14-3)。
验收参见：[收付记录的采信与分类](./04-资金收付-验收.md#acc-f-m14-01)。

<a id="pay-type"></a>
### 4.1 收付类型的判定

| 收付类型 | 是什么钱 | 付款方 → 收款方 | 关联业务 |
| --- | --- | --- | --- |
| 外采付款 | 采购方支付外采车款 | 采购方 → 供应商 | 所支付的外采发票 |
| 内销收款 | 债务人支付内销车款（应收账款回款） | 债务人 → 债权人 | 所支付的内销发票 |
| 外销收款 | 终端客户支付外销车款 | 终端客户 → 债务人 | 所支付的外销合同 |

- 收付类型由平台按这笔资金支付的业务判定，运营人员不能修改。
- 一笔收付只属于一种收付类型；它对应的关联单据都属于同一类业务。
- 内销收款就是应收账款（M3）的回款记录；同一笔记录在 M3 中作为回款摘要展示、在本模块中完整展示，两处的交易流水号、日期、付款方、收款方、金额一致。

<a id="adopt-rules"></a>
### 4.2 只采信已审核的收付款

- 只有 ERP 中已审核的收付款进入本模块；未审核的不展示。
- 已采信的收付款之后在 ERP 中被反审核、作废或删除时，从本模块移除；从其他模块带入它的交易流水号时，按[收付记录详情的边界与异常](#detail-edge)处理。
- 同一笔收付款再次取得且内容一致时不重复展示；内容不同（含金额、日期、关联业务、凭证变化）时，新内容直接成为当前展示内容。
- 运营人员只看到当前资料，本模块不展示变化前的内容和变化历史。

<a id="F-M14-02"></a>
## 5. 资金收付列表（F-M14-02）

适用角色与前提：可正常使用的运营人员，从运营端“资金收付”菜单进入。可查看本模块的全部收付记录。

验收参见：[资金收付列表](./04-资金收付-验收.md#acc-f-m14-02)。

列表每条收付记录一行：

| 业务信息 | 含义 |
| --- | --- |
| 收付类型 | 外采付款、内销收款或外销收款，见[收付类型的判定](#pay-type) |
| 交易流水号 | 点击进入[收付记录详情（F-M14-03）](#F-M14-03) |
| 收付日期 | 资金付出或收到的日期 |
| 付款方 → 收款方 | 付款主体与收款主体 |
| 金额（币种） | 这笔收付的原币金额 |
| 金额（美元） | 按[美元折算](#usd) |
| 关联业务 | 外采发票号、内销发票号或外销合同号，可点击进入其所在模块；对应多张时全部列出，见[关联业务（F-M14-04）](#F-M14-04) |

查看范围、查找与筛选：

- 可按收付类型分别查看外采付款、内销收款、外销收款，也可不限收付类型查看全部记录；默认不限收付类型。
- 按交易流水号查找，支持部分匹配。
- 按关联业务编号（外采发票号、内销发票号、外销合同号）查找，支持部分匹配；结果为关联到该单据的全部收付记录。
- 按付款方或收款方名称查找，支持部分匹配。
- 筛选：收付日期区间（含起止日）、币种。多个条件与收付类型同时生效。
- 默认按收付日期从新到旧排列；收付日期相同时按交易流水号排列。

边界与异常：

- 平台尚未采信任何收付记录时，展示“暂无收付记录”；某一收付类型下没有记录时，展示“暂无该类收付记录”；查找或筛选无结果时，展示“没有符合条件的收付记录”并可清除条件。
- 列表不提供新增、编辑、删除操作，也不展示金额合计。
- 加载失败按[加载失败](#load-fail)处理。

## 6. 收付记录详情（F-M14-03）

适用角色与前提：可正常使用的运营人员，从资金收付列表或任何模块中的交易流水号进入。详情只读。

<a id="detail-layers"></a>
### 6.1 三层结构

| 层 | 展示内容 |
| --- | --- |

<a id="parties"></a>
### 6.2 收付双方与账户

| 业务信息 | 含义 |
| --- | --- |
| 付款方 | 付出这笔资金的主体 |
| 付款银行 | 付款方付款所用的银行 |
| 付款账号 | 付款方付款所用的银行账号 |
| 收款方 | 收到这笔资金的主体 |
| 收款银行 | 收款方收款所用的银行 |
| 收款账号 | 收款方收款所用的银行账号 |

- 付款方、收款方与关联业务的买卖双方是否一致，本模块不判断，如实展示；是否预警由 M8 判断。
- 外销收款的付款方为个人客户时，只展示其名称、付款银行和付款账号，本模块不展示客户的其他个人信息。

- 加载失败按[加载失败](#load-fail)处理。

## 7. 关联业务（F-M14-04）

适用角色与前提：可正常使用的运营人员，在列表和详情概要中查看。

流程参见：[各入口与跳转（图 M14-2）](./02-资金收付-流程图与状态机.md#fig-m14-2)。
验收参见：[关联业务](./04-资金收付-验收.md#acc-f-m14-04)。

| 收付类型 | 关联业务 | 进入 |
| --- | --- | --- |
| 外采付款 | 外采发票号 | 合同信息（M4）外采合同详情，定位到该发票 |
| 内销收款 | 内销发票号 | 应收账款（M3）该笔应收账款详情 |
| 外销收款 | 外销合同号 | 合同信息（M4）外销合同详情 |

- 一笔收付对应一张关联单据时，关联业务展示该单据编号。
- 一笔收付对应多张关联单据时，全部列出；详情概要中每张单据旁同时展示分配金额（原币，币种与本笔收付相同），各张分配金额之和等于本笔收付金额。列表中展示全部编号，不展示分配金额。
- 关联业务所在模块按分配金额计入该单据的已收或已付；只对应一张单据时按全额计入。
- 关联业务只展示单据编号和分配金额，不展示该单据的金额、已收或已付合计；这些在关联业务所在模块查看。
- 关联单据在平台中不存在时按[单据编号跳转](#doc-links)处理。

<a id="F-M14-05"></a>
## 8. 关联预警（F-M14-05）

适用角色与前提：可正常使用的运营人员，在详情概要中查看。

验收参见：[关联预警](./04-资金收付-验收.md#acc-f-m14-05)。

- 本模块不判断任何风控规则，也不在字段旁给出风控提示。哪些预警算与本收付记录有关，以风控预警（M8）为准。
- 详情概要展示 M8 提供的关联预警数量：未处理 N 条、已处理 M 条；都没有时展示“无关联预警”。
- 点击数量进入 M8，落点按 M8 规定；看完可返回本记录详情。
- 本模块展示的数量与处理结果始终与 M8 一致，M8 生成或处理预警后随之更新。
- 预警不改变本模块的任何金额、收付类型或关联业务；本模块没有处理预警的操作。
- 关联预警加载失败时，仅该部分提示失败并可重试，不显示为“无关联预警”。
- M8 向本模块提供关联预警的口径见 M14-Q02。

<a id="dependencies"></a>
依赖：

- ERP：提供已审核的外采付款、内销收款、外销收款，包括交易流水号、收付日期、付款方与收款方及其银行和账号、币种、金额、关联业务及分配金额、凭证，以及反审核、作废、删除的结果。
- 汇率管理（M11）：提供当前汇率和某一时刻适用的汇率。
- 应收账款（M3）：提供内销发票所在应收账款的详情入口，并在回款记录中提供进入本模块的交易流水号。
- 合同信息（M4）：提供外采合同（可定位到外采发票）、外销合同的详情入口，并在付款记录、收款记录中提供进入本模块的交易流水号。
- 车辆履约（M5）：在外销段提供进入本模块的交易流水号。
- 风控预警（M8）：判断全部风控规则，定义哪些预警与一笔收付记录有关，提供未处理、已处理数量及入口。
- M2：提供运营人员账号、状态及时区设置。
