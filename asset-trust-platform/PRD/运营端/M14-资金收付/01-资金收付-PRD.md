本册只定义信息需求与业务行为；页面布局与交互承载由 Hallmark 设计决定。以下设计约束由用户确定，保持不变：

- 运营端菜单名称为“资金收付”，按收付记录展示，每笔收款或付款一行。
- 可按外采付款、内销收款、外销收款三类分别查看，以页签还是筛选承载由设计决定。
- 详情分为概要、基本信息、凭证附件三部分：概要与其他资产数据模块一样展示身份与关键金额，基本信息只放关联业务和收付双方的银行、账号；不设“进度与核对”“明细”。
- 列表不展示关联业务。
- 金额（美元）不标注“折算”字样。
- 页面中的单据编号都可点击，进入该单据所在模块的详情。
- 一个事实只在一个模块完整展示，其他模块展示摘要并跳转。收付记录的收付双方、银行、账号和凭证只在本模块展示；账号与个人客户姓名按[客户敏感信息的遮盖](#sensitive-mask)展示。

## 1. 模块是什么

资金收付以一笔收付记录为单位，回答“这笔钱是谁通过哪个银行账户付给谁的、什么时候、多少钱、对应哪笔业务、凭证是什么”。平台把 ERP 中已审核的收付登记整理为三类收付记录：外采付款（采购方付给外采供应商的车款）、内销收款（债务人付给债权人的车款，即应收账款的回款）、外销收款（终端客户付给债务人的车款）。应收账款（M3）的回款记录、合同信息（M4）外采发票的付款记录和外销合同的收款记录、车辆履约（M5）外销段的收款都只展示摘要，点交易流水号进入本模块查看收付双方、账号和凭证。本模块只供运营端使用，只读。

基本原则：

- 一笔收付记录就是 ERP 中的一条已审核收付登记，有一个收付日期、一个币种和一个金额。记录按 ERP 收付登记区分，不按交易流水号合并；同一交易流水号出现在多条登记中时，各自是一条收付记录，是否属于重复登记由 M8 [交易流水号重复（RK-33）](../M8-风控预警/01-风控预警-PRD.md#RK-33)判断。
- 金额（美元）按收付日期当日的汇率确定，确定后不随 M11 之后的汇率变化而变化。
- 本模块只展示收付记录本身的事实，并向关联业务所在模块提供每张关联单据的分配金额。已收、已付金额的汇总、比率和收付状态由关联业务所在模块定义，本模块不计算。
- 本模块不判断任何风控规则，也不在字段旁给出风控提示；风控由 M8 判断和处理，本模块只承接 M8 提供的本记录关联预警条数。
- 企业端（债权人、债务人）都看不到资金收付。

**一个完整的例子**（企业、客户名称、单据编号、银行和汇率为演示值）。2026-10-15，债务人 Carloha Nigeria 从 Bank N 账号 0123456789 向债权人 Carloha Holding 在 Bank H 的账号 9876543210 支付 25,000.00 USD，支付的是内销发票 PI-0012（应收账款 AR-0012），ERP 登记并审核后，平台形成内销收款记录 PAY-0451，附付款凭证一份。2026-11-03，终端客户 Lagos Motors Ltd 从 Bank L 向 Carloha Nigeria 在 Bank N 的账号支付 30,000,000.00 NGN，支付的是外销合同 SO-2045；当日 M11 适用的汇率为 1 USD = 1,500.00 NGN，平台形成外销收款记录 RC-7781，金额（美元）确定为 20,000.00 USD。运营人员打开“资金收付”，只看内销收款，看到 PAY-0451 一行：收付类型“内销收款”、收付日期 2026-10-15、Carloha Nigeria → Carloha Holding、25,000.00 USD、25,000.00 USD。进入详情：概要展示 Carloha Nigeria → Carloha Holding、内销收款、PAY-0451、金额、金额（美元）、收付日期和关联预警“无关联预警”；基本信息展示关联业务“应收账款 AR-0012（内销发票 PI-0012）”、付款银行 Bank N 与账号 ******6789、收款银行 Bank H 与账号 ******3210；凭证附件中打开付款凭证。运营点 AR-0012 进入应收账款（M3）该笔应收账款详情，看完返回 PAY-0451 详情，再返回列表，原筛选条件仍在。2026-11-20，运营在 M11 把汇率更新为 1 USD = 1,600.00 NGN。之后运营在车辆履约（M5）VIN-A 的外销段点交易流水号 RC-7781，进入本模块：收付类型“外销收款”、Lagos Motors Ltd → Carloha Nigeria、30,000,000.00 NGN、20,000.00 USD（所用汇率 1,500.00，不随新汇率变化）、关联业务“外销合同 SO-2045”；点 SO-2045 进入合同信息（M4）外销合同详情，看完返回 RC-7781，再返回 VIN-A。

### 1.2 本期不做

- 在平台录入、编辑、删除任何收付记录或凭证；运营端和企业端都没有这类操作。
- 已收、已付金额的汇总、比率和收付状态：分别在 M3 [回款信息（F-M3-05）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-05)、M4 [外采发票与付款（F-M4-06）](../M4-合同信息/01-合同信息-PRD.md#F-M4-06)与[外销收款记录（F-M4-15）](../M4-合同信息/01-合同信息-PRD.md#F-M4-15)中定义。
- 把一笔收付拆分到单辆车：外销收款在车辆页如何展示由 M5 定义。
- 任何风控规则的判断，包括付款方、收款方与合同主体是否一致、付款是否超过发票金额、交易流水号是否重复：由 M8 判断、生成和处理。
- 退款、冲销等特殊款项。
- 银行流水的外部核验：三方数据源本期未接入。
- 企业端查看资金收付，包括债权人和债务人。债权人在应收账款中能看到哪些回款信息以 M3 为准。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 收付记录 | 本模块的一行：ERP 中一条已审核的付款或收款登记 |
| 收付类型 | 按这笔资金支付的是哪类业务分为外采付款、内销收款、外销收款，见[收付类型的判定](#pay-type) |
| 外采付款 | 采购方向外采供应商支付外采车款，支付对象是外采发票 |
| 内销收款 | 债务人向债权人支付内销车款，即应收账款的回款，支付对象是内销发票；一张内销发票就是一笔应收账款 |
| 外销收款 | 终端客户向债务人支付外销车款，支付对象是外销合同（零售或批售的外销订单） |
| 交易流水号 | ERP 登记的银行交易流水号，用于展示和查找；可能出现在多条收付记录中，不作为记录的唯一标识 |
| 外采发票 | 外采供应商就外采合同开给采购方的发票，在 M4 外采合同中展示 |
| 应收账款 | 一张已审核的内销发票在 M3 形成的一笔应收账款，有应收账款编号，并对应一个内销发票号 |
| 外销合同 | 债务人与终端客户的合同，即外销订单（零售订单或批售订单），在 M4 外销合同中展示 |
| 关联业务 | 收付记录支付的业务对象：外采付款对应外采发票，内销收款对应应收账款（内销发票），外销收款对应外销合同；一笔收付可对应一个或多个 |
| 分配金额 | 一笔收付对应多张关联单据时，ERP 登记分到每张单据的金额 |
| 所用汇率 | 确定一笔非美元收付的金额（美元）时所用的 M11 汇率，见[美元金额](#usd) |
| 关联预警 | M8 中关联对象含本收付记录的预警；口径见 M8 [向其他模块提供的预警信息](../M8-风控预警/01-风控预警-PRD.md#external) |
| 运营人员 | 运营端账号的使用者，即 M2 定义的运营管理员；本期运营端只有这一种角色，权限相同。账号状态见 M2 [运营账号状态](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#op-account-status) |

## 3. 共用展示与异常规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。来源值、单据编号跳转、附件查看与缺失值展示的口径与应收账款（M3）的[共用规则](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#shared-rules)一致；美元金额的取用汇率与 M3 [回款的计入](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#receipt-booking)使用同一时点。本节只写本模块的取值与结果。

<a id="display-values"></a>
### 3.1 来源值、金额与时间

- 交易流水号、主体名称、银行、账号、日期、金额等按 ERP 原值展示，不翻译、不改写；付款账号、收款账号与个人客户姓名另按[客户敏感信息的遮盖](#sensitive-mask)展示。
- 金额与币种代码同时展示，数值在前、币种代码在后，带千分位，例如“25,000.00 USD”。原币金额按原值展示，不四舍五入、不截断。
- 收付日期按原样展示，不做时区换算。
- 平台自己记录的时间（凭证取得时间）和所用汇率的生效时间展示到分钟，按 M2 [界面语言与时区（F-OP-10）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-10)中本人的时区展示并标明时区。
- 平台文字（收付类型、空状态、说明）随 M2 界面语言切换；来源值不随界面语言翻译。

<a id="sensitive-mask"></a>
#### 客户敏感信息的遮盖

客户提供的敏感资料遮盖后展示。本模块需要遮盖的是银行账号和个人客户姓名，其他资料照常展示；平台自己产生的资料不遮盖。

- **银行账号**：付款账号、收款账号只显示最后 4 个字符，其余每个字符用“*”代替，例如 0123456789 展示为“******6789”；账号不足 4 个字符时全部用“*”代替。账号未提供时展示“-”。
- **个人客户姓名**：外销收款的付款方为个人客户时，姓名按 M4 [合同信息](../M4-合同信息/01-合同信息-PRD.md)统一定义的个人姓名遮盖规则展示：每个词保留首字母，其余用“***”代替，例如“J*** A***”。企业名称照常完整展示。是否为个人，以 ERP 提供的客户类型判断；ERP 已提供遮盖后姓名的，按原值展示。
- 本模块所有出现账号与个人客户姓名的位置（列表的付款方 → 收款方、详情的概要与基本信息）都按上述规则展示。
- 本模块不提供查看、复制或导出完整账号与完整个人姓名的方式。
- 查找不使用遮盖前的内容：账号不参与查找；按付款方或收款方名称查找时，个人客户只按展示出的遮盖后姓名匹配，用完整姓名查不到。

<a id="placeholder"></a>
#### 缺失值的展示

- 取不到或算不出的值统一以“-”展示，与 M3 [缺失值的展示](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#placeholder)一致；读屏读出对应的原因文字。
- 需要让运营人员知道原因时，原因写在“-”下方：金额（美元）的原因为“无法折算”“无可用汇率”或“收付日期未提供”，见[美元金额](#usd)。ERP 没有提供的来源值（如交易流水号、付款银行）只展示“-”，不另写原因。
- 以下是业务状态，照常以文字展示，不改为“-”：暂无收付记录、暂无该类收付记录、没有符合条件的收付记录、暂无凭证、无关联预警、暂计。

<a id="usd"></a>
### 3.2 美元金额

“金额（美元）”与原币金额同时展示，不标注“折算”字样。

| 原币 | 金额（美元） |
| --- | --- |
| USD | 等于原币金额 |
| NGN | 原币金额 ÷ 收付日期（UTC+1）当日最后时刻（23:59:59.999）M11 适用的汇率（1 USD = R NGN）；次日 00:00 起生效的汇率不适用 |
| 其他币种 | “-”，下方注明“无法折算”，M11 只维护美元与奈拉 |
| NGN，收付日期早于 M11 第一条汇率的生效时间，或当时 M11 为无可用汇率 | “-”，下方注明“无可用汇率” |
| NGN，收付日期未提供 | “-”，下方注明“收付日期未提供” |
| NGN，收付日期为今天或晚于今天（UTC+1） | 暂计，见下文 |

- 金额（美元）一经确定，不随 M11 之后新增的汇率变化而变化；只有本笔收付的金额、币种或收付日期在 ERP 中变化时，才按新内容重新确定。
- 收付日期为今天或晚于今天（UTC+1）的 NGN 收付，收付日期当日的汇率尚未确定：在收付日期当日结束前，按查看时 M11 适用的汇率暂计，列表和详情中金额旁都注明“暂计”；其间 M11 生效新汇率后，之后的查看按新汇率暂计。收付日期当日结束后按当日最后时刻适用的汇率确定，不再注明“暂计”，此后不再变化。
- “今天”统一按 UTC+1 的当前日期判断，不随查看人的时区变化。
- 暂计时 M11 为无可用汇率的，金额（美元）展示“-”，下方注明“无可用汇率”。
- 汇率按 M11 [对外提供的汇率口径（FX-05）](../M11-汇率管理/01-汇率管理-PRD.md#FX-05)中某一时刻适用的汇率取得。
- 结果保留两位小数，四舍五入。
- 详情概要中，NGN 收付同时展示所用汇率（汇率值及其生效时间）；暂计时展示暂计所用的汇率。列表只展示金额（美元）。
- 美元值无法得出时，不用 0 或其他值代替。

| --- | --- |
| 交易流水号（列表中） | 本模块该笔[收付记录详情（F-M14-03）](#F-M14-03) |
| 外采发票号 | M4 [外采合同详情（F-M4-05）](../M4-合同信息/01-合同信息-PRD.md#F-M4-05)中该发票所属的外采合同，并定位到外采发票清单中的这张发票 |
| 应收账款编号、内销发票号 | M3 中该笔应收账款的详情，按 M3 [单据编号跳转](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#doc-links) |
| 外销合同号 | M4 [外销合同详情（F-M4-14）](../M4-合同信息/01-合同信息-PRD.md#F-M4-14) |

- 编号对应的单据在平台中不存在（例如尚未审核）时，编号按原值展示，不可点击；该单据之后被采信时变为可点击。
- 进入后目标单据已不再被采信时，提示“该内容不存在或已更新”，可返回本模块。

<a id="file-view"></a>
### 3.4 凭证附件查看

- 每份附件展示附件名称和取得时间，可在线查看和下载；取得时间按[来源值、金额与时间](#display-values)展示。
- 附件打开或下载失败时，提示“文件暂时无法打开，请稍后重试”，不影响查看其他信息。

<a id="no-access"></a>
### 3.5 不可访问

- 企业端没有资金收付入口。以企业账号的登录状态访问本模块任何内容时，按 M2 [运营端菜单与无权访问（F-OP-11）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-11)处理，不返回任何内容，不透露收付记录是否存在。
- 运营账号待首登改密或锁定中时不能使用本模块，账号状态见 M2 [运营账号状态](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#op-account-status)；本期运营账号不设停用。

<a id="load-fail"></a>
### 3.6 加载失败

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的金额，避免把加载失败误显示为“暂无收付记录”。
- 详情中某一部分（如收付双方与账户、凭证附件、关联预警）或某一项来自其他模块的值（如汇率）加载失败时，仅该处提示失败并可重试，其他部分正常展示；汇率加载失败时金额（美元）提示失败并可重试，不显示为“-”或 0。

## 4. 收付记录的采信与分类（F-M14-01）

适用范围：平台从 ERP 取得收付登记后，判断哪些进入本模块、属于哪种收付类型。结果对运营人员可见，没有用户操作。

流程参见：[收付记录的采信与分类（图 M14-1）](./02-资金收付-流程图与状态机.md#fig-m14-1)、[收付记录在本模块的展示状态（图 M14-3）](./02-资金收付-流程图与状态机.md#fig-m14-3)。
验收参见：[收付记录的采信与分类](./04-资金收付-验收.md#acc-f-m14-01)。

<a id="pay-type"></a>
### 4.1 收付类型的判定

| 收付类型 | 是什么钱 | 付款方 → 收款方 | 关联业务 |
| --- | --- | --- | --- |
| 外采付款 | 采购方支付外采车款 | 采购方 → 外采供应商 | 所支付的外采发票 |
| 内销收款 | 债务人支付内销车款（应收账款回款） | 债务人 → 债权人 | 所支付内销发票对应的应收账款 |
| 外销收款 | 终端客户支付外销车款 | 终端客户 → 债务人 | 所支付的外销合同（零售或批售的外销订单） |

- 收付类型由平台按 ERP 登记的关联业务属于哪类单据判定，运营人员不能修改。
- 一笔收付只属于一种收付类型；它对应的关联单据都属于同一类业务。
- 内销收款就是 M3 [回款记录](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#field-receipt)中的一条；同一笔记录在 M3 中作为回款摘要展示、在本模块中完整展示，两处的交易流水号、日期、付款方、收款方一致，M3 的金额为本模块中分配到该内销发票的金额。

<a id="adopt-rules"></a>
### 4.2 采信与更新

- 只有 ERP 中已审核的收付登记进入本模块；未审核的不展示。
- 已采信的收付登记之后在 ERP 中被反审核、作废或删除时，从本模块移除；从其他模块带入它的交易流水号时，按[收付记录详情的边界与异常](#detail-edge)处理。
- 同一条收付登记再次取得且内容一致时不重复展示；内容不同（含金额、日期、关联业务、凭证变化）时，新内容直接成为当前展示内容；金额（美元）按[美元金额](#usd)重新确定。
- 运营人员只看到当前资料，本模块不展示变化前的内容和变化历史。

<a id="not-received"></a>
### 4.3 不能处理的收付登记

已审核的收付登记出现以下情况之一时不进入本模块，在 M15 [接口调用记录（F-M15-02）](../M15-数据监控/01-数据监控-PRD.md#F-M15-02)中按未接收计入，原因如下：

| 情况 | 未接收原因 |
| --- | --- |
| 没有登记关联业务，或登记的关联单据不属于同一类业务，无法判定收付类型 | 无法判定收付类型 |
| 缺少金额或币种 | 缺少金额或币种 |
| 对应多张关联单据，但有单据缺少分配金额，或各张分配金额之和不等于本笔收付金额 | 分配金额不完整 |

- 内容更新后不再属于上述情况时，按[采信与更新](#adopt-rules)进入本模块；已展示的记录更新后属于上述情况时，从本模块移除。
- 交易流水号、收付日期、付款方、收款方、银行、账号或凭证缺失不影响进入本模块，缺失项按[缺失值的展示](#placeholder)展示。

<a id="F-M14-02"></a>
## 5. 资金收付列表（F-M14-02）

适用角色与前提：可正常使用的运营人员，从运营端“资金收付”菜单进入。可查看本模块的全部收付记录。

验收参见：[资金收付列表](./04-资金收付-验收.md#acc-f-m14-02)。

列表每条收付记录一行：

| 业务信息 | 含义 |
| --- | --- |
| 收付类型 | 外采付款、内销收款或外销收款，见[收付类型的判定](#pay-type) |
| 交易流水号 | 点击进入[收付记录详情（F-M14-03）](#F-M14-03)；未提供时展示“-”，该行仍可进入详情 |
| 收付日期 | 资金付出或收到的日期 |
| 付款方 → 收款方 | 付款主体与收款主体 |
| 金额（币种） | 这笔收付的原币金额 |
| 金额（美元） | 按[美元金额](#usd) |

查看范围、查找与筛选：

- 可按收付类型分别查看外采付款、内销收款、外销收款，也可不限收付类型查看全部记录；默认不限收付类型。
- 按交易流水号查找，支持部分匹配。
- 按关联业务编号（外采发票号、应收账款编号、内销发票号、外销合同号）查找，支持部分匹配；结果为关联到该业务的全部收付记录。列表不展示关联业务，命中的业务在详情基本信息中查看。
- 按付款方或收款方名称查找，支持部分匹配；个人客户按遮盖后的姓名匹配，账号不参与查找，见[客户敏感信息的遮盖](#sensitive-mask)。
- 筛选：收付日期区间（含起止日）、币种。设了收付日期区间时，收付日期未提供的记录不列出。多个条件与收付类型同时生效。
- 默认按收付日期从新到旧排列，收付日期未提供的排在最后；收付日期相同时按交易流水号升序排列，逐个字符比较、不区分大小写（例如 TRX-10 排在 TRX-9 之前），交易流水号未提供的排在同日最后；交易流水号也相同或都未提供时按 ERP 登记顺序排列。
- 同一交易流水号有多条收付记录时，列表中各占一行，均可分别进入详情；同号记录不合并、不另加标记，每条记录的关联预警按[关联预警（F-M14-05）](#F-M14-05)各自展示。

边界与异常：

- 平台尚未采信任何收付记录时，展示“暂无收付记录”；某一收付类型下没有记录时，展示“暂无该类收付记录”；查找或筛选无结果时，展示“没有符合条件的收付记录”并可清除条件。
- 列表不提供新增、编辑、删除操作，也不展示金额合计。
- 加载失败按[加载失败](#load-fail)处理。

## 6. 收付记录详情（F-M14-03）

适用角色与前提：可正常使用的运营人员，从资金收付列表或任何模块中的交易流水号进入。详情只读。

验收参见：[收付记录详情](./04-资金收付-验收.md#acc-f-m14-03)。

<a id="detail-layers"></a>
<a id="M14-Q06"></a>
### 6.1 详情的组成

详情分三部分：

| 部分 | 展示内容 |
| --- | --- |
| 概要 | 付款方 → 收款方；收付类型；交易流水号；金额（币种）；金额（美元）及 NGN 收付的所用汇率；收付日期；[关联预警（F-M14-05）](#F-M14-05) |
| 基本信息 | [关联业务（F-M14-04）](#F-M14-04)及分配金额；付款银行、付款账号；收款银行、收款账号 |
| 凭证附件 | [凭证附件](#vouchers) |

- 各项的含义与[资金收付列表（F-M14-02）](#F-M14-02)和[收付双方与账户](#parties)相同；同一项只展示一次。
- 付款方 → 收款方、收付类型、交易流水号可作为详情的标题与说明展示，具体承载由设计决定。
- 不设“进度与核对”“明细”。

<a id="parties"></a>
### 6.2 收付双方与账户

| 业务信息 | 含义 |
| --- | --- |
| 付款方 | 付出这笔资金的主体 |
| 付款银行 | 付款方付款所用的银行 |
| 付款账号 | 付款方付款所用的银行账号，遮盖后展示 |
| 收款方 | 收到这笔资金的主体 |
| 收款银行 | 收款方收款所用的银行 |
| 收款账号 | 收款方收款所用的银行账号，遮盖后展示 |

- 付款方、收款方名称在概要中展示；银行与账号在基本信息中展示。
- 付款方、收款方与关联业务的买卖双方是否一致，本模块不判断，如实展示原值，不展示比对结果；由 M8 [内销收款主体不一致（RK-14）](../M8-风控预警/01-风控预警-PRD.md#RK-14)、[外采付款主体不一致（RK-20）](../M8-风控预警/01-风控预警-PRD.md#RK-20)判断。
- 外销收款的付款方为个人客户时，姓名按[客户敏感信息的遮盖](#sensitive-mask)展示，同时展示付款银行和遮盖后的付款账号；本模块不展示客户的其他个人信息。

<a id="vouchers"></a>
### 6.3 凭证附件

| 收付类型 | 凭证 |
| --- | --- |
| 外采付款 | 外采付款凭证 |
| 内销收款 | 内销收款凭证 |
| 外销收款 | 外销收款凭证 |

- 一笔收付有多份凭证时全部列出；查看与下载按[凭证附件查看](#file-view)。
- 没有凭证时展示“暂无凭证”。

<a id="detail-edge"></a>
### 6.4 边界与异常

- 从其他模块的交易流水号或链接进入、但该收付记录不在本模块（未采信、不能处理或已移除）时，展示“未找到该收付记录”，可返回来源位置。
- 加载失败按[加载失败](#load-fail)处理。

## 7. 关联业务（F-M14-04）

适用角色与前提：可正常使用的运营人员，在详情基本信息中查看；列表不展示关联业务。

流程参见：[各入口与跳转（图 M14-2）](./02-资金收付-流程图与状态机.md#fig-m14-2)。
验收参见：[关联业务](./04-资金收付-验收.md#acc-f-m14-04)。

关联业务逐个写明业务类型和编号：

| 收付类型 | 关联业务的展示 | 示例 | 进入 |
| --- | --- | --- | --- |
| 外采付款 | 外采发票 + 外采发票号 | 外采发票 PPI-0301 | M4 外采合同详情，定位到该发票 |
| 内销收款 | 应收账款 + 应收账款编号，并带出对应的内销发票号 | 应收账款 AR-0012（内销发票 PI-0012） | M3 该笔应收账款详情 |
| 外销收款 | 外销合同 + 外销合同号 | 外销合同 SO-2045 | M4 外销合同详情 |

- 内销发票尚未在平台形成应收账款（如尚未审核）时，展示“内销发票”+ 内销发票号，按原值展示、不可点击；形成应收账款后改为上表的展示并可点击。外采发票、外销合同不在平台中时，按[单据编号跳转](#doc-links)处理。
- 一笔收付对应一个关联业务时，展示该业务。
- 一笔收付对应多个关联业务时，全部列出；详情基本信息中每个业务旁同时展示分配金额（原币，币种与本笔收付相同），各分配金额之和等于本笔收付金额。
- <a id="M14-Q03"></a>本模块向关联业务所在模块提供每张单据的分配金额；只对应一张单据时分配金额为本笔收付全额。一笔收付对应多张单据时，各单据只计入分配到本单据的金额，同一笔资金不重复计入；已收、已付如何计算由该模块定义。
- <a id="M14-Q05"></a>本模块向其他模块提供本笔收付已确定的金额（美元）、所用汇率及是否暂计。M4 付款记录与外销收款记录、M5 外销段逐笔展示的美元值取本模块已确定的值，M11 更新汇率后与本模块仍一致。M3 回款记录的金额（美元）属于 M3 已收款口径，按 M3 [回款记录](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#field-receipt)，不取本模块的值；应收账款原币为 NGN 时，汇率更新后两处的美元值可以不同。
- 关联业务只展示业务类型、编号和分配金额，不展示该业务的金额、已收或已付合计；这些在关联业务所在模块查看。
- 外销收款对应到它所支付的外销订单，零售订单、批售订单都按外销合同展示与跳转。

## 8. 关联预警（F-M14-05）

适用角色与前提：可正常使用的运营人员，在详情概要中查看。

验收参见：[关联预警](./04-资金收付-验收.md#acc-f-m14-05)。

- 本模块不判断任何风控规则，也不在字段旁给出风控提示。哪些预警算本收付记录的关联预警、条数含哪些预警，按 M8 [向其他模块提供的预警信息](../M8-风控预警/01-风控预警-PRD.md#external)。
- 详情概要展示本记录未处理和已处理的关联预警条数；都没有时展示“无关联预警”。
- 点击条数进入 M8，落点按 M8 [进入与返回](../M8-风控预警/01-风控预警-PRD.md#entries)；看完可返回本记录详情。
- 展示的条数始终与 M8 一致，M8 生成、处理或解除预警后随之更新。
- 预警不改变本模块的任何金额、收付类型或关联业务；本模块没有处理预警的操作。
- 关联预警加载失败时，仅该部分提示失败并可重试，不显示为“无关联预警”。

<a id="pending"></a>
## 10. 依赖

本模块没有待用户确认的事项。ERP 能否提供外销客户的客户类型待研发核验，见下方 ERP 依赖。

<a id="dependencies"></a>

- ERP：提供已审核的外采付款、内销收款、外销收款登记，包括交易流水号、收付日期、付款方与收款方及其银行和账号、币种、金额、关联业务及分配金额、凭证，以及反审核、作废、删除的结果；外销收款付款方的客户类型（个人或企业），用于判断是否遮盖姓名。ERP 能否提供客户类型待研发核验；未核验前，个人姓名遮盖的判断依据按 M4 的规则执行。
- 汇率管理（M11）：按[对外提供的汇率口径（FX-05）](../M11-汇率管理/01-汇率管理-PRD.md#FX-05)提供某一时刻适用的汇率（汇率值与生效时间）或“无可用汇率”。
- 应收账款（M3）：提供应收账款编号与内销发票号的对应、应收账款详情入口，并在回款记录中提供进入本模块的交易流水号。
- 合同信息（M4）：统一定义个人姓名遮盖规则（本模块按其展示个人客户姓名）；提供外采合同（可定位到外采发票）、外销合同的详情入口，并在付款记录、收款记录中提供进入本模块的交易流水号；逐笔金额（美元）取本模块已确定的值，见 M4 [收付记录的美元值与合计](../M4-合同信息/01-合同信息-PRD.md#payment-booking)。
- 车辆履约（M5）：在外销段提供进入本模块的交易流水号；逐笔收款金额（美元）取本模块已确定的值，见 M5 [外销段（F-M5-18）](../M5-车辆履约/01-车辆履约-PRD.md#F-M5-18)。
- 风控预警（M8）：判断全部风控规则，按[向其他模块提供的预警信息](../M8-风控预警/01-风控预警-PRD.md#external)提供本记录未处理、已处理的关联预警条数及入口；预警详情中的交易流水号进入本模块。
- 运营审核（M9）：当次依据中的交易流水号进入本模块。
- 数据监控（M15）：按[不能处理的收付登记](#not-received)展示未接收条数与原因。
- 运营登录与企业管理（M2）：提供运营账号及状态、界面语言与时区、运营端菜单登记，以及无权访问的统一处理。
