## 1. 模块是什么

提单信息以一张提单为单位，回答“这批车装了哪条船、什么时候装船、走到哪里、到港没有、清关了多少辆、值多少钱、有没有保单”。平台把已审核的提单及其车辆、已审核的清关单按车辆 VIN 关联起来，再结合外部跟踪数据给出的航程动态和到港日期，在一个详情中串起来。提单货值由提单上各车辆的内采单价（取自内销发票）折成美元后合计。本模块只供运营端使用，只读。

基本原则：

- 提单车辆、清关车辆都按 VIN 关联；提单不关联内销合同。提单的装船日期即其所装车辆的装船日期。
- 只采信已审核的单据；未审核、已反审核、已作废或已删除的提单和清关单不出现在本模块。
- 美元金额按汇率管理（M11）中查看时的当前汇率折算，同时保留原币金额。
- 航程跟踪、到港日期来自外部跟踪数据，按提单展示。
- 本模块不判断任何风控规则。与提单、清关有关的核对由风控预警（M8）按其[风控规则目录](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#rule-catalog)判断和处理，本模块只承接 M8 提供的本提单关联预警。
- 企业端（债权人、债务人）本期都看不到提单信息。

**一个完整的例子**（企业、船公司名称、单据编号和汇率为演示值；汇率按 1 USD = 1,500.00 NGN）。已审核的提单 BL-5501：船公司“航运甲”，船名 OCEAN STAR、航次 025W，发货人 Carloha Holding，收货人 Carloha Nigeria，装运港 Shanghai，卸货港 Lagos，装船日期 2026-09-10；登记集装箱 CSNU1234567、CSNU7654321；车辆 VIN-A、VIN-C、VIN-D。三辆车都已开内销发票：VIN-A、VIN-C 在 INV-0012 中单车金额各 22,000.00 USD，VIN-D 在 INV-0015 中单车金额 33,000,000.00 NGN（折算 22,000.00 USD）。平台算出提单货值 66,000.00 USD。外部跟踪数据显示该船 2026-09-11 自 Shanghai 离港、2026-09-28 经 Singapore 中转、2026-10-15 抵达 Lagos，航程状态为“已到港”，到港日期 2026-10-15。已审核清关单 CC-0101（清关日期 2026-10-20，进口方 Carloha Nigeria，出口方 Carloha Holding，船名 OCEAN STAR、航次 025W，集装箱 CSNU1234567）列有 VIN-A、VIN-C，VIN-D 还没有清关单，所以清关进度为“部分清关（已清关 2／共 3 辆）”。保单 PL-889 关联了 BL-5501。M8 中与 BL-5501 有关的预警为 1 条未处理、2 条已处理。运营人员打开“提单信息”菜单，在列表中看到 BL-5501 一行：航运甲、OCEAN STAR 025W、Shanghai → Lagos、2026-09-10、2026-10-15、3 辆、66,000.00 USD、部分清关 2／3、预警 1。进入详情：概要中看到提单身份、装船日期、集装箱数及集装箱号、提单货值和关联预警（未处理 1、已处理 2）；进度与核对中看到航程状态“已到港”及三条航程动态，清关进度 2／3 和清关单 CC-0101；明细中车辆清单逐车列出 VIN、内采单价、清关单号、清关日期、清关进口方、出口方和清关船名航次，VIN-D 的清关各项展示“未清关”；关联保单列出 PL-889；附件分提单附件和清关单附件（按清关单号分组）。运营点 VIN-D 进入车辆履约（M5）查看该车，返回后点 PL-889 进入保单信息（M13），再返回 BL-5501。

### 1.2 本期不做

- 在平台录入、编辑、删除任何提单、清关单、航程数据或附件；运营端和企业端都没有这类操作。
- 任何风控规则的判断，包括提单与外部跟踪数据的比对、清关进口方和出口方与内销合同买卖方的比对、清关船名航次与提单的比对：由风控预警（M8）判断、生成和处理，本模块只承接 M8 提供的预警信息。
- 车辆的外采、内销、外销完整信息，合同的金额与进度，保单的保险金额与覆盖率，应收账款的金额与期限：分别在车辆履约（M5）、合同信息（M4）、保单信息（M13）、应收账款（M3）展示，本模块只展示本提单需要的值并跳转。
- 按集装箱号或船名航次把清关单对应到车辆：清关单只按其中的 VIN 对应车辆。
- 费用登记（海运费、保险费、关税等金额明细）：功能清单没有对应数据项；相关凭证随提单、清关单附件查看，见[附件（F-M12-09）](#F-M12-09)。
- 预计到港日期、船舶实时位置地图：功能清单没有对应数据项。
- 对清关申报、税费作专业或合规结论。
- 企业端查看提单信息，包括债权人和债务人。

| 术语 | 含义 |

## 3. 共用展示与异常规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。来源值、美元折算、单据编号跳转与附件查看的口径与应收账款（M3）的[共用规则](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#shared-rules)一致，本节只写本模块的取值与结果；运营端缺失值的展示方式见[运营端缺失值展示是否统一（M12-Q04）](#M12-Q04)。

<a id="display-values"></a>
### 3.1 来源值、金额与日期

- 提单号、清关单号、船公司、船名、航次、发货人、收货人、港口、进口方、出口方、集装箱号、日期、金额，以及外部跟踪数据中的地点与动态，都按来源原值展示，不翻译、不改写。
- 船名航次由船名和航次组合展示，例如“OCEAN STAR 025W”。
- 金额与币种代码同时展示，数值在前、币种代码在后，带千分位，例如“22,000.00 USD”。来源中的原币金额按原值展示，不四舍五入、不截断。
- 来源中的日期与时间（装船日期、清关日期、到港日期、航程动态时间、保单日期）按原样展示，不做时区换算；来源随日期或时间提供时区时，时区写在后面。
- 平台自己记录的时间（附件取得时间）展示到分钟，按 M2 [界面语言与时区（F-OP-10）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-10)中本人的时区展示并标明时区。
- 平台文字（状态、空状态、说明）随 M2 界面语言切换；来源值不随界面语言翻译。
- 来源没有提供某项值时，该项展示“未提供”。
- 业务上尚未发生的事项按业务状态展示：车辆尚无清关单展示“未清关”，车辆既未开内销发票、也不在任何内销合同中时展示“未关联内销合同”，尚未到港展示“未到港”，某部分一条记录都没有时展示该部分的空状态（如“暂无关联保单”）。

<a id="usd"></a>
### 3.2 美元折算

字段名带“（美元）”的值按下表得出：

| 原币 | 美元值 |
| --- | --- |
| USD | 等于原币金额，不标“折算” |
| NGN | 原币金额 ÷ 查看时 M11 的当前汇率（1 USD = R NGN），标“折算” |
| M11 未维护汇率的其他币种 | 展示“无法折算” |
| NGN，但 M11 尚未设置任何汇率 | 展示“无可用汇率” |

- 折算结果保留两位小数，四舍五入；合计用未取舍的值计算，展示时再取舍。
- 汇率按[对外提供的汇率口径（FX-05）](../M11-汇率管理/01-汇率管理-PRD.md#FX-05)取“当前汇率”；折算值旁可查看所用汇率值及其生效时间。口径与 M3 [美元折算与比率](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#usd-rule)一致。
- 美元值为“无法折算”或“无可用汇率”时，只展示原币金额和对应说明，不用 0 或其他值代替。

<a id="doc-links"></a>
### 3.3 单据编号跳转

本模块中的单据编号都可点击，进入该单据所在模块的详情；看完可返回本提单详情。目标详情及其中的定位由所属模块定义，本模块只决定从哪个编号进入哪个详情。

| 编号 | 进入 |
| --- | --- |
| VIN | 车辆履约（M5）的[车辆履约详情（F-M5-05）](../M5-车辆履约/01-车辆履约-PRD.md#F-M5-05) |
| 保单号 | 保单信息（M13）的[保单详情（F-M13-03）](../M13-保单信息/01-保单信息-PRD.md#F-M13-03) |

- 清关单的完整信息在本模块展示：清关单号用于在本提单详情中定位到[清关单](#customs-bills)中的这张清关单，不跳转到其他模块。
- 进入时目标单据已不再被采信（如已反审核、已作废）时，提示“该内容不存在或已更新”，可返回本提单详情。

<a id="file-view"></a>
### 3.4 附件查看

- 附件按 M3 [附件查看](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#file-view)查看和下载：每份附件展示附件名称和取得时间，可在线查看和下载；同一份附件出现在多个位置时只保存一份，各处引用。
- 附件打开或下载失败时，提示“文件暂时无法打开，请稍后重试”，不影响查看其他信息。

<a id="no-access"></a>
### 3.5 不可访问

- 企业端没有提单信息入口。以企业账号的登录状态访问本模块任何内容时，按 M2 [运营端菜单与无权访问（F-OP-11）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-11)处理，不返回任何内容，不透露提单是否存在。
- 运营账号待首登改密或锁定中时不能使用本模块，账号状态见 M2 [运营账号状态](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#op-account-status)；本期运营账号不设停用。

<a id="load-fail"></a>
### 3.6 加载失败

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的货值、车辆数、航程状态或清关进度，避免把加载失败误显示为“未清关”“未到港”或“暂无提单资料”。
- 详情中某一部分（如航程、车辆清单、关联保单、关联预警）或某一项来自其他模块的值（如内采单价）加载失败时，仅该处提示失败并可重试，其他部分正常展示；依赖该值的提单货值展示“无法计算”。

## 4. 提单与清关资料的采信与关联（F-M12-01）

适用范围：平台取得提单、清关单后，判断哪些资料属于哪张提单、哪辆车。结果对运营人员可见，没有用户操作。

流程参见：[提单与清关资料的采信与关联（图 M12-1）](./02-提单信息-流程图与状态机.md#fig-m12-1)。
验收参见：[提单与清关资料的采信与关联](./04-提单信息-验收.md#acc-f-m12-01)。

<a id="link-rules"></a>
### 4.1 哪些资料属于这张提单

| 资料 | 属于本提单的条件 | 在本模块中的位置 |
| --- | --- | --- |
| 提单车辆 | 本提单列出的 VIN | [车辆清单（F-M12-07）](#F-M12-07) |
| 集装箱号 | 本提单登记的集装箱号 | [提单详情（F-M12-03）](#F-M12-03)概要 |
| 航程动态、到港日期 | 外部跟踪数据中本提单的记录 | [航程与到港（F-M12-05）](#F-M12-05) |
| 清关单 | 清关单车辆中有本提单的任一 VIN；按 VIN 对应到本提单中的这辆车 | [清关进度与清关单（F-M12-06）](#F-M12-06)、[车辆清单（F-M12-07）](#F-M12-07) |
| 内采单价 | 该 VIN 所在的已审核内销发票中的单车金额；尚未开票时，该 VIN 所在的已审核内销合同中的本车单价（合同价） | [车辆清单（F-M12-07）](#F-M12-07)、[提单货值（F-M12-04）](#F-M12-04) |
| 关联保单 | 已审核保单的关联提单中有本提单 | [关联保单（F-M12-08）](#F-M12-08) |
| 附件 | 本提单的附件；与本提单车辆对应的清关单的附件 | [附件（F-M12-09）](#F-M12-09) |

- 提单不关联内销合同；内销合同、内销发票都按 VIN 对应到车辆，车辆和货值只按 VIN 确定。
- 车辆与集装箱不逐一对应：集装箱号只按提单、清关单单据展示，不展示到单车。
- 清关单按 VIN 对应车辆，不比对集装箱号或船名航次；两者是否一致由 M8 判断。
- 一张清关单的车辆可以分属多张提单，在各提单中分别对应到其中的车辆。
- 同一 VIN 出现在多张提单上（如转运）时，该车在每张提单中都列出；该车的清关单在每张提单中都对应到该车。
- 清关单中的 VIN 都不在任何已采信提单上时，本模块不展示该清关单（没有提单可以承载）；该清关单在其他模块中如何展示由所在模块定义。
- 一辆车在多张已审核内销发票中都有单车金额时，内采单价取发票日期最近的一张；发票日期相同时按发票号排列取第一张。
- 车辆尚未开内销发票时，内采单价取该车所在已审核内销合同中的本车单价，并标“合同价”；在多份内销合同中时取合同日期最近的一份，合同日期相同时按内销合同号排列取第一份。
- 车辆开出内销发票后，内采单价改按内销发票取值，“合同价”标识随之去掉。
- 提单列表中的提单为全部已采信的提单。

<a id="adopt-rules"></a>
### 4.2 只采信已审核单据

- 只有已审核的提单、清关单、内销发票、内销合同和保单参与本模块；未审核的不展示，也不参与车辆数、清关进度和提单货值。
- 平台以提单号识别提单、以清关单号识别清关单。缺少提单号或清关单号的单据无法识别，不进入本模块；在数据监控（M15）中按未接收计入。
- 已采信的单据之后被反审核、作废或删除时，从本模块移除，车辆数、清关进度、提单货值和关联保单按剩余资料重新得出。
- 同一张单据再次取得且内容一致时不重复展示；内容不同（含车辆增减、集装箱号、日期、港口、附件变化）时，新内容直接成为当前展示内容。
- 外部跟踪数据更新时，航程动态、到港日期和航程状态随之更新。
- 运营人员只看到当前资料，本模块不展示单据变化前的内容和变化历史。

边界与异常：

- 平台尚未采信任何提单时，展示“暂无提单资料”；查找或筛选无结果时，展示“没有符合条件的提单”并可清除条件。
- 列表不提供新增、编辑、删除操作。
- 加载失败按[加载失败](#load-fail)处理。

## 7. 提单货值（F-M12-04）

适用范围：平台为每张提单计算提单货值（美元），在列表和详情概要中展示。没有用户操作。

验收参见：[提单货值](./04-提单信息-验收.md#acc-f-m12-04)。

<a id="bl-value"></a>
### 7.1 计算规则

- 提单货值（美元）= 本提单全部车辆的内采单价（美元）合计。
- 每辆车的内采单价按[哪些资料属于这张提单](#link-rules)取得（已开票取内销发票，未开票取内销合同的合同价），按[美元折算](#usd)折成美元；先逐车折算，再合计。
- 含合同价的车辆照常计入合计。
- 合计用未取舍的美元值计算，展示时保留两位小数，四舍五入。
- 同一 VIN 在本提单中只计一次。

<a id="bl-value-missing"></a>
### 7.2 不能合计时

| 情形 | 提单货值展示 |
| --- | --- |
| 全部车辆的内采单价都取自内销发票 | 合计值，例如“66,000.00 USD” |
| 全部车辆都有内采单价，其中 N 辆为合同价 | 合计值，并注明“含 N 辆合同价” |
| 有车辆既无内销发票单价、也无内销合同单价，或其内采单价无法折算、无可用汇率 | “无法计算”，并注明“N 辆车无内采单价或无法折算”；不展示部分车辆的合计 |

- 任一车辆缺内采单价或无法折算时，不按部分车辆先算。
- 提单货值是展示值，不影响航程、清关进度、关联保单或任何状态。

## 8. 航程与到港（F-M12-05）

适用角色与前提：可正常使用的运营人员，在详情“进度与核对”中查看；到港日期同时在列表中展示，航程状态可在列表中筛选。

流程参见：[航程状态（图 M12-4）](./02-提单信息-流程图与状态机.md#fig-m12-4)。
验收参见：[航程与到港](./04-提单信息-验收.md#acc-f-m12-05)。

<a id="voyage"></a>
### 8.1 航程内容

| 业务信息 | 含义 | 尚无记录时 |
| --- | --- | --- |
| 航程状态 | 在途或已到港，判定见下表 | — |
| 到港日期 | 船舶抵达本提单卸货港的日期 | 展示“未到港” |
| 航程跟踪 | 本提单的航程动态，逐条展示时间、地点和动态（如离港、中转、到港），按时间从新到旧排列 | 展示“暂无航程动态” |

| 航程状态 | 判定条件 |
| --- | --- |
| 在途 | 外部跟踪数据中本提单尚无到港日期 |
| 已到港 | 外部跟踪数据给出了本提单的到港日期 |

- 航程状态和到港日期只取外部跟踪数据，平台不按装船日期、航程动态或清关日期推算。
- 外部跟踪数据更新到港日期后，航程状态随之变化；到港日期被撤销时回到“在途”。
- 外部跟踪数据中的船公司、船名航次、港口、装船日期与提单是否一致，由 M8 [BL 信息与外部数据不一致（RK-26）](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#RK-26)判断；本模块按提单原值展示提单信息，不展示比对结果。
- 外部跟踪数据加载失败时，仅航程部分提示失败并可重试，不显示为“在途”“未到港”或“暂无航程动态”。
- 航程状态与清关进度相互独立：未到港时已有清关单的车辆照常计为已清关，本模块不作判断。

## 9. 清关进度与清关单（F-M12-06）

适用角色与前提：可正常使用的运营人员，在列表和详情“进度与核对”中查看。

流程参见：[清关进度（图 M12-2）](./02-提单信息-流程图与状态机.md#fig-m12-2)。
验收参见：[清关进度与清关单](./04-提单信息-验收.md#acc-f-m12-06)。

<a id="customs-progress"></a>
### 9.1 清关进度

- 已清关车辆数 k：本提单车辆中，至少有一张已采信清关单列有其 VIN 的车辆数。
- 车辆总数 N：本提单不重复的 VIN 个数。
- 清关进度展示为清关状态加“已清关 k／共 N 辆”：

| 清关状态 | 判定条件 |
| --- | --- |
| 未清关 | k = 0 |
| 部分清关 | 0 < k < N |
| 全部清关 | k = N |

- 清关单被移除、提单车辆增减后按最新资料重新判定，清关状态可以后退（如“全部清关”变为“部分清关”）。
- 清关状态只描述已有记录，不是审核结论，不影响确权、审核或出库。

<a id="customs-bills"></a>
### 9.2 清关单

清关进度下列出与本提单车辆对应的全部清关单，按清关日期从新到旧排列，清关日期相同时按清关单号排列；没有时展示“暂无清关单”。

| 业务信息 | 含义 |
| --- | --- |
| 清关单号 | 清关单编号，用于在车辆清单中定位对应车辆 |
| 清关日期 | 完成清关的日期 |
| 进口方 | 清关单进口方（收货人） |
| 出口方 | 清关单出口方（发货人） |
| 船名航次 | 清关单中的船名与航次 |
| 集装箱号 | 清关单中登记的集装箱号 |
| 本提单中对应车辆数 | 该清关单列有的 VIN 中属于本提单的车辆数 |

- 清关单中还列有不属于本提单的 VIN 时，只计入本提单的车辆，不在本提单中展示其他车辆。
- 清关进口方、出口方与内销合同买卖方是否一致，由 M8 [清关主体与内销合同不一致（RK-24）](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#RK-24)判断；清关船名航次与提单是否一致，由 M8 [清关船名航次与提单不一致（RK-25）](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#RK-25)判断。本模块如实展示原值，不展示比对结果。

## 10. 车辆清单（F-M12-07）

适用角色与前提：可正常使用的运营人员，在详情明细中查看。只读。

验收参见：[车辆清单](./04-提单信息-验收.md#acc-f-m12-07)。

每个 VIN 一行，按提单中车辆的顺序排列。车辆清单不展示集装箱号，集装箱号见概要和[清关单](#customs-bills)。

| 业务信息 | 含义 | 业务上尚未发生时 |
| --- | --- | --- |
| VIN | 车辆识别代号，点击进入车辆履约（M5）详情 | — |

| 内采单价（美元） | 按[美元折算](#usd)；取合同价时同样标“合同价” | 既未开票也不在任何内销合同中，展示“未关联内销合同” |
| 清关单号 | 本车对应的清关单编号 | 展示“未清关” |
| 清关日期 | 该清关单的清关日期 | 展示“未清关” |
| 清关进口方 | 该清关单的进口方 | 展示“未清关” |
| 清关出口方 | 该清关单的出口方 | 展示“未清关” |
| 清关船名航次 | 该清关单的船名航次 | 展示“未清关” |

- 车辆清单可按清关情况筛选：全部、已清关、未清关。
- 从车辆履约（M5）的清关单号进入本提单时，定位到车辆清单中的该 VIN，见[进入与返回](#entries)。

## 12. 附件（F-M12-09）

适用角色与前提：可正常使用的运营人员，在详情明细中查看。按[附件查看](#file-view)查看和下载。

验收参见：[附件](./04-提单信息-验收.md#acc-f-m12-09)。

附件按单据展示，不再细分类别：

| 分组 | 内容 |
| --- | --- |
| 提单附件 | 本提单的全部附件 |
| 清关单附件 | 与本提单车辆对应的每张清关单的全部附件，按清关单号分组 |

- 本提单还没有附件时，提单附件展示“暂无附件”；某张清关单还没有附件时，该清关单分组展示“暂无附件”。
- 本提单没有清关单时，清关单附件展示“暂无清关单”。

## 13. 关联预警（F-M12-10）

适用角色与前提：可正常使用的运营人员，在列表和详情概要中查看。

流程参见：[各入口与跳转（图 M12-3）](./02-提单信息-流程图与状态机.md#fig-m12-3)。
验收参见：[关联预警](./04-提单信息-验收.md#acc-f-m12-10)。

<a id="risk-entry"></a>
### 13.1 承接规则

- 本模块不判断任何风控规则，也不在字段旁给出风控提示。哪些预警算本提单（含其清关单）的关联预警、条数含哪些预警，按 M8 [向其他模块提供的预警信息](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#external)。
- 本模块只展示 M8 提供的本提单关联预警：
  - 列表“预警”：本提单未处理的关联预警条数；没有时展示“无”。
  - 详情概要：未处理和已处理的关联预警条数；都没有时展示“无关联预警”。
- 点击预警条数进入 M8，落点与返回按 M8 [进入与返回](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#entries)；看完可返回本提单详情。
- 本模块展示的条数始终与 M8 一致，M8 生成、处理或解除预警后随之更新。
- 预警不改变本模块的任何字段、货值、航程状态或清关进度；本模块没有处理预警的操作。
- 关联预警加载失败时，仅该部分提示失败并可重试，不显示为“无”或“无关联预警”。

<a id="dependencies"></a>
依赖：

- 客户 ERP：提供已审核的提单（含车辆 VIN 和集装箱号）、清关单（含车辆 VIN）、内销发票、内销合同（含车辆单价与币种）、保单（含关联提单），以及各单据附件和单据的反审核、作废、删除；数据对接由研发负责。
- 外部跟踪数据：按提单提供航程动态和到港日期；数据的覆盖与准确性由研发核验。
- 汇率管理（M11）：按[对外提供的汇率口径（FX-05）](../M11-汇率管理/01-汇率管理-PRD.md#FX-05)提供查看时的当前汇率及其生效时间。
- 车辆履约（M5）、保单信息（M13）：提供车辆详情、保单详情供跳转；M5、M13 及应收账款（M3）、风控预警（M8）、运营审核与资产推送（M9）在各自页面提供进入本模块的提单号（M5、M8 还提供清关单号）。
- 风控预警（M8）：判断全部风控规则，按[向其他模块提供的预警信息](../M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md#external)提供本提单未处理、已处理的关联预警条数及入口。
- 数据监控（M15）：展示提单等接口的取得与未接收情况。
- 运营登录与企业管理（M2）：提供运营账号及状态、界面语言与时区、运营端菜单登记，以及无权访问的统一处理。

本模块向其他模块提供：提单的车辆、装船日期、到港日期与详情入口，以及清关单与车辆的对应结果。各模块如何使用这些值（如应收账款起算日、车辆物流节点）以所在模块为准。
