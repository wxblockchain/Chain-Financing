# 提单信息 · 功能与业务规则

2026-11-19｜运营端：运营人员｜需求评审稿（待多模块联调）

本模块共三册：本册写功能、业务规则与字段规则；[流程图与状态机](./02-提单信息-流程图与状态机.md)画出主要流程与状态；[验收](./04-提单信息-验收.md)供测试使用。本模块自身不发送任何消息，所以没有 03 消息通知册，并非缺失。

编号说明：功能编号（F-M12-*）标在章节标题上，供验收追溯。文中“M3”“M4”“M5”“M8”“M11”“M12”“M13”“M14”均指资产可信平台运营端的同级模块：应收账款（M3）、合同信息（M4，分外采合同、内销合同、外销合同三个页签）、车辆履约（M5）、风控预警（M8）、汇率管理（M11）、提单信息（M12，本模块，含清关）、保单信息（M13）、资金收付（M14）。待确认事项编号沿用原值，缺号不代表遗漏。

本册按《平台功能清单》的数据项设计，所需数据默认均可取得。

本册只定义信息需求与业务行为；页面布局与交互承载由 Hallmark 设计决定。以下设计约束由用户确定，保持不变：

- 运营端菜单名称为“提单信息”，列表以一张提单为一行。
- 详情统一为“概要 → 进度与核对 → 明细”三层。
- 页面中的单据编号都可点击，进入该单据所在模块的详情；VIN 进入车辆履约（M5）。
- 一个事实只在一个模块完整展示，其他模块展示摘要并跳转。提单、航程与清关的完整信息只在本模块展示。

## 1. 模块是什么

提单信息以一张提单为单位，回答“这批车装了哪条船、什么时候装船、走到哪里、到港没有、清关了多少辆、值多少钱、有没有保单”。平台把已审核的提单及其车辆、已审核的清关单按车辆 VIN 关联起来，再结合外部跟踪数据给出的航程动态和到港日期，在一个详情中串起来。提单货值由提单上各车辆的内采单价（取自内销发票）折成美元后合计。本模块只供运营端使用，只读。

基本原则：

- 提单车辆、清关车辆都按 VIN 关联；提单不关联内销合同。提单的装船日期即其所装车辆的装船日期。
- 只采信已审核的单据；未审核、已反审核、已作废或已删除的提单和清关单不出现在本模块。
- 美元金额按汇率管理（M11）中查看时的当前汇率折算，同时保留原币金额。
- 航程跟踪、到港日期来自外部跟踪数据，按提单展示。
- 本模块不判断任何风控规则。功能清单中列在提单下的风控提示（“BL 信息与外部数据不一致”“清关信息与基础交易不一致”）由风控预警（M8）判断和完善，本模块只承接 M8 提供的本提单关联预警。
- 企业端（债权人、债务人）本期都看不到提单信息。

**一个完整的例子**（企业、船公司名称、单据编号和汇率为演示值；汇率按 1 USD = 1,500.00 NGN）。已审核的提单 BL-5501：船公司“航运甲”，船名 OCEAN STAR、航次 025W，发货人 Carloha Holding，收货人 Carloha Nigeria，装运港 Shanghai，卸货港 Lagos，装船日期 2026-09-10；登记集装箱 CSNU1234567、CSNU7654321；车辆 VIN-A、VIN-C、VIN-D。三辆车都已开内销发票：VIN-A、VIN-C 在 INV-0012 中单车金额各 22,000.00 USD，VIN-D 在 INV-0015 中单车金额 33,000,000.00 NGN（折算 22,000.00 USD）。平台算出提单货值 66,000.00 USD。外部跟踪数据显示该船 2026-09-11 自 Shanghai 离港、2026-09-28 经 Singapore 中转、2026-10-15 抵达 Lagos，航程状态为“已到港”，到港日期 2026-10-15。已审核清关单 CC-0101（清关日期 2026-10-20，进口方 Carloha Nigeria，出口方 Carloha Holding，船名 OCEAN STAR、航次 025W，集装箱 CSNU1234567）列有 VIN-A、VIN-C，VIN-D 还没有清关单，所以清关进度为“部分清关（已清关 2／共 3 辆）”。保单 PL-889 关联了 BL-5501。运营人员打开“提单信息”菜单，在列表中看到 BL-5501 一行：航运甲、OCEAN STAR 025W、Shanghai → Lagos、2026-09-10、2026-10-15、3 辆、66,000.00 USD、部分清关 2／3、预警（以 M8 提供为准）。进入详情：概要中看到提单身份、装船日期、集装箱数及集装箱号、提单货值和关联预警数量；进度与核对中看到航程状态“已到港”及三条航程动态，清关进度 2／3 和清关单 CC-0101；明细中车辆清单逐车列出 VIN、内采单价、清关单号、清关日期、清关进口方、出口方和清关船名航次，VIN-D 的清关各项展示“未清关”；关联保单列出 PL-889；附件分提单附件和清关附件。运营点 VIN-D 进入车辆履约（M5）查看该车，返回后点 PL-889 进入保单信息（M13），再返回 BL-5501。

### 1.2 本期不做

- 在平台录入、编辑、删除任何提单、清关单、航程数据或附件；运营端和企业端都没有这类操作。
- 任何风控规则的判断，包括功能清单中列在提单下的“BL 信息与外部数据不一致”（船公司、船名航次、装运港、卸货港、装船日期与外部跟踪数据比对）和“清关信息与基础交易不一致”（清关进口方、出口方与合同买卖方比对，清关船名航次与提单比对）：由风控预警（M8）判断、生成和处理，本模块只承接 M8 提供的预警信息。
- 车辆的外采、内销、外销完整信息，保单的保险金额与覆盖率，应收账款的金额与期限：分别在车辆履约（M5）、合同信息（M4）、保单信息（M13）、应收账款（M3）展示，本模块只展示本提单需要的值并跳转。
- 原车辆物流与履约追溯中按“集装箱号 + 船名航次”把清关登记对应到车辆的做法：改为直接按清关单中的 VIN 对应。
- 原车辆物流与履约追溯中的费用登记（海运费、保险费、关税等金额明细）：功能清单没有对应数据项；运费、关税以支付凭证附件体现，见[附件（F-M12-09）](#F-M12-09)。
- 预计到港日期、船舶实时位置地图：功能清单没有对应数据项。
- 对清关申报、税费作专业或合规结论。
- 企业端查看提单信息，包括债权人和债务人。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 提单 | 提单（BL），一张提单是一个运输批次。含提单号、船公司、船名、航次、发货人、收货人、装运港、卸货港、装船日期、集装箱号，以及所装车辆的 VIN |
| 提单车辆 | 提单中列出的 VIN；本模块的车辆数按不重复的 VIN 计 |
| 清关单 | 一次进口清关的记录，含清关单号、清关日期、进口方、出口方、船名、航次、集装箱号和所清关车辆的 VIN |
| 已清关车辆 | 至少有一张已采信的清关单列有该 VIN 的提单车辆 |
| 清关进度 | 本提单中已清关车辆数与车辆总数的对比，见[清关进度与清关单（F-M12-06）](#F-M12-06) |
| 外部跟踪数据 | 平台以外的航运跟踪数据，按提单提供航程动态和到港日期 |
| 航程动态 | 外部跟踪数据中的一条航行记录，如离港、中转、到港 |
| 航程状态 | 按到港日期判定的在途或已到港，见[航程与到港（F-M12-05）](#F-M12-05) |
| 内采单价、内采币种 | 车辆在内销发票车辆明细中的单车金额及该发票的币种；内销合同本身不提供单车价 |
| 集装箱号 | 提单、清关单按单据登记的集装箱号；车辆与集装箱不逐一对应，集装箱号不展示到单车 |
| 提单货值（美元） | 本提单全部车辆的内采单价（美元）合计，见[提单货值（F-M12-04）](#F-M12-04) |
| 关联保单 | 关联提单中包含本提单的已审核保单 |
| 关联预警 | 风控预警（M8）判定为与本提单有关的预警；哪些算与本提单有关以 M8 为准 |
| 运营人员 | 运营端账号的使用者，即 M2 定义的运营管理员；本期运营端只有这一种角色，权限相同 |

## 3. 共用展示与异常规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。展示与折算口径与应收账款（M3）定义的六个资产数据模块共用规则一致；多模块联调时如有差异，以联调统一结果为准。

<a id="display-values"></a>
### 3.1 来源值、金额与日期

- 提单号、清关单号、船公司、船名、航次、发货人、收货人、港口、进口方、出口方、集装箱号、日期、金额，以及外部跟踪数据中的地点与动态，都按来源原值展示，不翻译、不改写。
- 船名航次由船名和航次组合展示，例如“OCEAN STAR 025W”。
- 金额与币种代码同时展示，数值在前、币种代码在后，带千分位，例如“22,000.00 USD”。来源中的原币金额按原值展示，不四舍五入、不截断。
- 来源中的日期与时间（装船日期、清关日期、到港日期、航程动态时间、保单日期）按原样展示，不做时区换算；来源随日期或时间提供时区时，时区写在后面。
- 平台自己记录的时间（附件取得时间）展示到分钟并标注时区：按运营人员在 M2 选择的时区展示；M2 不提供时区设置时统一按 UTC 展示。
- 业务上尚未发生的事项按业务状态展示：车辆尚无清关单展示“未清关”，车辆尚未开内销发票展示“未开票”，尚未到港展示“未到港”，某部分一条记录都没有时展示该部分的空状态（如“暂无关联保单”）。

<a id="usd"></a>
### 3.2 美元折算

字段名带“（美元）”的值按下表得出：

| 原币 | 美元值 |
| --- | --- |
| USD | 等于原币金额，不标“折算” |
| NGN | 原币金额 ÷ 查看时 M11 的当前汇率（1 USD = R NGN），标“折算” |
| M11 未维护汇率的其他币种 | 展示“无法折算” |
| NGN，但 M11 尚未设置任何汇率 | 展示“无可用汇率” |

- 折算结果保留两位小数，四舍五入；合计用未取舍的值计算，展示时再取舍。
- 汇率按[对外提供的汇率口径（FX-05）](../M11-汇率管理/01-汇率管理-PRD.md#FX-05)取得；折算值旁可查看所用汇率值及其生效时间。
- 美元值为“无法折算”或“无可用汇率”时，只展示原币金额和对应说明，不用 0 或其他值代替。

<a id="doc-links"></a>
### 3.3 单据编号跳转

本模块中的单据编号都可点击，进入该单据所在模块的详情；看完可返回本提单详情。

| 编号 | 进入 |
| --- | --- |
| VIN | 车辆履约（M5）中该车的详情 |
| 保单号 | 保单信息（M13）中该保单的详情 |

- 清关单的完整信息在本模块展示，清关单号用于在本提单详情中定位，不跳转到其他模块。
- 进入时目标单据已不再被采信（如已反审核、已作废）时，提示“该内容不存在或已更新”，可返回本提单详情。
- 各模块详情的具体落点在多模块联调时核对。

<a id="file-view"></a>
### 3.4 附件查看

- 每份附件展示附件名称和取得时间，可在线查看和下载。
- 同一份附件出现在多个位置时只保存一份，各处引用。
- 附件打开或下载失败时，提示“文件暂时无法打开，请稍后重试”，不影响查看其他信息。

<a id="no-access"></a>
### 3.5 不可访问

- 企业端没有提单信息入口。企业用户通过链接打开本模块任何内容时，统一提示“该内容不存在或无权查看”，不透露其是否存在及任何内容。
- 运营人员处于待首次改密、已停用或锁定中时不能使用本模块，判定以 M2 为准。

<a id="load-fail"></a>
### 3.6 加载失败

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的货值、车辆数、航程状态或清关进度，避免把加载失败误显示为“未清关”“未到港”或“暂无提单资料”。
- 详情中某一部分（如航程、车辆清单、关联保单、关联预警）或某一项来自其他模块的值（如内采单价）加载失败时，仅该处提示失败并可重试，其他部分正常展示；依赖该值的提单货值展示“无法计算”。

## 4. 提单与清关资料的采信与关联（F-M12-01）

适用范围：平台取得提单、清关单后，判断哪些资料属于哪张提单、哪辆车。结果对运营人员可见，没有用户操作。

流程参见：[提单与清关资料的采信与关联（图 M12-1）](./02-提单信息-流程图与状态机.md#fig-m12-1)。
验收参见：[提单与清关资料的采信与关联](./04-提单信息-验收.md#acc-f-m12-01)。

<a id="link-rules"></a>
### 4.1 哪些资料属于这张提单

| 资料 | 属于本提单的条件 | 在本模块中的位置 |
| --- | --- | --- |
| 提单车辆 | 本提单列出的 VIN | [车辆清单（F-M12-07）](#F-M12-07) |
| 集装箱号 | 本提单登记的集装箱号 | [提单详情（F-M12-03）](#F-M12-03)概要 |
| 航程动态、到港日期 | 外部跟踪数据中本提单的记录 | [航程与到港（F-M12-05）](#F-M12-05) |
| 清关单 | 清关单车辆中有本提单的任一 VIN；按 VIN 对应到本提单中的这辆车 | [清关进度与清关单（F-M12-06）](#F-M12-06)、[车辆清单（F-M12-07）](#F-M12-07) |
| 内采单价 | 本提单车辆所在的已审核内销发票中，该 VIN 的单车金额 | [车辆清单（F-M12-07）](#F-M12-07)、[提单货值（F-M12-04）](#F-M12-04) |
| 关联保单 | 已审核保单的关联提单中有本提单 | [关联保单（F-M12-08）](#F-M12-08) |
| 附件 | 本提单的附件；与本提单车辆对应的清关单的附件 | [附件（F-M12-09）](#F-M12-09) |

- 提单不关联内销合同；车辆和货值只按 VIN 确定。
- 车辆与集装箱不逐一对应：集装箱号只按提单、清关单单据展示，不展示到单车。
- 清关单按 VIN 对应车辆，不比对集装箱号或船名航次。清关单与提单船名航次是否一致属于风控判断，由 M8 负责。
- 一张清关单的车辆可以分属多张提单，在各提单中分别对应到其中的车辆。
- 同一 VIN 出现在多张提单上（如转运）时，该车在每张提单中都列出；该车的清关单在每张提单中都对应到该车。
- 清关单中的 VIN 不在任何已采信提单上时，本模块不展示该清关单（没有提单可以承载）；车辆履约（M5）仍按 VIN 使用该清关单判定清关节点。
- 一辆车在多张已审核内销发票中都有单车金额时，内采单价取发票日期最近的一张；发票日期相同时按发票号排列取第一张。与车辆履约（M5）价格链的取值一致。
- 提单列表中的提单为全部已采信的提单。

<a id="adopt-rules"></a>
### 4.2 只采信已审核单据

- 只有已审核的提单、清关单、内销发票和保单参与本模块；未审核的不展示，也不参与车辆数、清关进度和提单货值。
- 已采信的单据之后被反审核、作废或删除时，从本模块移除，车辆数、清关进度、提单货值和关联保单按剩余资料重新得出。
- 同一张单据再次取得且内容一致时不重复展示；内容不同（含车辆增减、集装箱号、日期、港口、附件变化）时，新内容直接成为当前展示内容。
- 外部跟踪数据更新时，航程动态、到港日期和航程状态随之更新。
- 运营人员只看到当前资料，本模块不展示单据变化前的内容和变化历史。

- 平台尚未采信任何提单时，展示“暂无提单资料”；查找或筛选无结果时，展示“没有符合条件的提单”并可清除条件。
- 列表不提供新增、编辑、删除操作。

## 7. 提单货值（F-M12-04）

适用范围：平台为每张提单计算提单货值（美元），在列表和详情概要中展示。没有用户操作。

验收参见：[提单货值](./04-提单信息-验收.md#acc-f-m12-04)。

<a id="bl-value"></a>
### 7.1 计算规则

- 提单货值（美元）= 本提单全部车辆的内采单价（美元）合计。
- 每辆车的内采单价按[哪些资料属于这张提单](#link-rules)取自内销发票，按[美元折算](#usd)折成美元；先逐车折算，再合计。
- 合计用未取舍的美元值计算，展示时保留两位小数，四舍五入。
- 同一 VIN 在本提单中只计一次。

<a id="bl-value-missing"></a>
### 7.2 不能合计时

| 情形 | 提单货值展示 |
| --- | --- |
| 全部车辆都有内采单价（美元） | 合计值，例如“66,000.00 USD” |
| 有车辆尚未开内销发票，或其内采单价无法折算、无可用汇率 | “无法计算”，并注明“N 辆车未开票或无法折算”；不展示部分车辆的合计 |

- 与保单信息（M13）的保险货值口径一致：任一车辆缺内采单价时不按部分车辆先算。
- 提单货值是展示值，不影响航程、清关进度、关联保单或任何状态。

## 8. 航程与到港（F-M12-05）

适用角色与前提：可正常使用的运营人员，在详情“进度与核对”中查看；到港日期同时在列表中展示，航程状态可在列表中筛选。

流程参见：[航程状态（图 M12-4）](./02-提单信息-流程图与状态机.md#fig-m12-4)。
验收参见：[航程与到港](./04-提单信息-验收.md#acc-f-m12-05)。

<a id="voyage"></a>
### 8.1 航程内容

| 业务信息 | 含义 | 尚无记录时 |
| --- | --- | --- |
| 航程状态 | 在途或已到港，判定见下表 | — |
| 到港日期 | 船舶抵达本提单卸货港的日期 | 展示“未到港” |
| 航程跟踪 | 本提单的航程动态，逐条展示时间、地点和动态（如离港、中转、到港），按时间从新到旧排列 | 展示“暂无航程动态” |

| 航程状态 | 判定条件 |
| --- | --- |
| 在途 | 外部跟踪数据中本提单尚无到港日期 |
| 已到港 | 外部跟踪数据给出了本提单的到港日期 |

- 航程状态和到港日期只取外部跟踪数据，平台不按装船日期、航程动态或清关日期推算。
- 外部跟踪数据更新到港日期后，航程状态随之变化；到港日期被撤销时回到“在途”。
- 航程中的船公司、船名航次、港口、装船日期与提单是否一致由 M8 判断（“BL 信息与外部数据不一致”），本模块按提单原值展示提单信息，不展示比对结果。
- 外部跟踪数据加载失败时，仅航程部分提示失败并可重试，不显示为“在途”“未到港”或“暂无航程动态”。
- 航程状态与清关进度相互独立：未到港时已有清关单的车辆照常计为已清关，本模块不作判断。

## 9. 清关进度与清关单（F-M12-06）

适用角色与前提：可正常使用的运营人员，在列表和详情“进度与核对”中查看。

流程参见：[清关进度（图 M12-2）](./02-提单信息-流程图与状态机.md#fig-m12-2)。
验收参见：[清关进度与清关单](./04-提单信息-验收.md#acc-f-m12-06)。

<a id="customs-progress"></a>
### 9.1 清关进度

- 已清关车辆数 k：本提单车辆中，至少有一张已采信清关单列有其 VIN 的车辆数。
- 车辆总数 N：本提单不重复的 VIN 个数。
- 清关进度展示为清关状态加“已清关 k／共 N 辆”：

| 清关状态 | 判定条件 |
| --- | --- |
| 未清关 | k = 0 |
| 部分清关 | 0 < k < N |
| 全部清关 | k = N |

- 清关单被移除、提单车辆增减后按最新资料重新判定，清关状态可以后退（如“全部清关”变为“部分清关”）。
- 清关状态只描述已有记录，不是审核结论，不影响确权、审核或出库。

<a id="customs-bills"></a>
### 9.2 清关单

清关进度下列出与本提单车辆对应的全部清关单，按清关日期从新到旧排列，清关日期相同时按清关单号排列；没有时展示“暂无清关单”。

| 业务信息 | 含义 |
| --- | --- |
| 清关单号 | 清关单编号，用于在车辆清单中定位对应车辆 |
| 清关日期 | 完成清关的日期 |
| 进口方 | 清关单进口方（收货人） |
| 出口方 | 清关单出口方（发货人） |
| 船名航次 | 清关单中的船名与航次 |
| 集装箱号 | 清关单中登记的集装箱号 |
| 本提单中对应车辆数 | 该清关单列有的 VIN 中属于本提单的车辆数 |

- 清关单中还列有不属于本提单的 VIN 时，只计入本提单的车辆，不在本提单中展示其他车辆。
- 清关进口方、出口方与合同买卖方是否一致，清关船名航次与提单是否一致，本模块不判断，由 M8 负责；本模块如实展示原值。

## 13. 关联预警（F-M12-10）

适用角色与前提：可正常使用的运营人员，在列表和详情概要中查看。

<a id="risk-entry"></a>
### 13.1 承接规则

- 本模块不判断任何风控规则，也不在字段旁给出风控提示。功能清单中列在提单下的风控提示由风控预警（M8）判断和完善；哪些预警算与本提单有关，以 M8 为准。
- 本模块只展示 M8 提供的本提单关联预警：
  - 列表“预警”：本提单未处理的关联预警条数；没有时展示“无”。
  - 详情概要：未处理和已处理的关联预警数量；都没有时展示“无关联预警”。
- 点击预警数量进入 M8，落点按 M8 规定（按本提单筛选的风控预警列表，只有一条时直接进入该预警详情）；看完可返回本提单详情。
- 本模块展示的数量与处理结果始终与 M8 一致，M8 生成或处理预警后随之更新。
- 预警不改变本模块的任何字段、货值、航程状态或清关进度；本模块没有处理预警的操作。
- 关联预警加载失败时，仅该部分提示失败并可重试，不显示为“无”或“无关联预警”。

<a id="dependencies"></a>
依赖：

- 客户业务系统：提供已审核的提单（含车辆 VIN 和集装箱号）、清关单（含车辆 VIN）、内销发票（含车辆单价与币种）、保单（含关联提单），以及各单据附件和附件类别。
- 外部跟踪数据：按提单提供航程动态和到港日期。
- 汇率管理（M11）：提供查看时的当前汇率及其生效时间。
- 车辆履约（M5）：提供车辆详情供 VIN 跳转；使用本模块定义的清关单与车辆对应结果判定清关节点，可使用本模块的航程状态与到港日期展示在途／到港节点，并从清关节点进入本模块。
- 保单信息（M13）：提供保单详情供跳转，并在保单详情中提供进入本模块的提单号。
- 应收账款（M3）：在车辆清单中提供进入本模块的提单号；应收账款起算日使用提单装船日期，计算规则以 M3 为准。
- 风控预警（M8）：判断全部风控规则，定义哪些预警与本提单有关，向提单列表和详情提供未处理、已处理的关联预警数量及入口。
- M1、M2：提供运营人员账号及状态、运营端账号设置中的时区。
