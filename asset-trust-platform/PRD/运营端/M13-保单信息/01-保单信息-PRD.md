# 保单信息 · 功能与业务规则

2026-11-19｜运营端：运营人员｜需求评审稿（待多模块联调）

本模块共三册：本册写功能、业务规则与字段规则；[流程图](./02-保单信息-流程图与状态机.md)画出主要流程；[验收](./04-保单信息-验收.md)供测试使用。本模块自身不发送任何消息，所以没有 03 消息通知册，并非缺失。

编号说明：功能编号（F-M13-*）标在章节标题上，供验收追溯；编号沿用原值，已删除的条目不再占号，缺号不代表遗漏。文中“M3”“M4”“M5”“M8”“M11”“M12”“M13”“M14”均指资产可信平台运营端的同级模块：应收账款（M3）、合同信息（M4）、车辆履约（M5）、风控预警（M8）、汇率管理（M11）、提单信息（M12，含清关）、保单信息（M13，本模块）、资金收付（M14）。M3、M4、M5、M12、M14 是与本模块同批重组的资产数据模块，本册只引用其业务名称，多模块联调时补齐链接。

本册只定义信息需求与业务行为；页面布局与交互承载由 Hallmark 设计决定。以下设计约束由用户确定，保持不变：

- 运营端菜单名称为“保单信息”；列表一行是一张保单，只放用于筛选和比较的字段。
- 详情统一为“概要 → 进度与核对 → 明细”三层；本模块的“进度与核对”即保障核对。
- 页面中的单据编号都可点击，进入该单据所在模块的详情；VIN 进入车辆履约（M5）。
- 一个事实只在一个模块完整展示，其他模块展示摘要并跳转。

## 1. 模块是什么

保单信息以一张保单为单位，回答“这批货保了多少、保险金额够不够覆盖货值、每辆车摊到多少保险金额”。平台采信 ERP 中已审核的保单，按保单关联的提单找到提单上的车辆，再按每辆车的内采单价算出保险货值、保险覆盖率和车辆保险金额。本模块是保险金额与覆盖率的唯一完整展示处：应收账款（M3）的保险覆盖率、车辆清单中的车辆保险金额都按本模块的定义取值；车辆履约（M5）、提单信息（M12）只展示保单号并跳转到这里。本模块只供运营端使用，只读。

基本原则：

- 保单不直接关联车辆，也不关联内销合同：保单关联提单，提单上的全部车辆都是本保单覆盖的车辆。
- 一辆车只应被一张保单覆盖。同一辆车出现在多张保单中（含同一张提单被多张保单关联）属于需要核实的数据异常：本模块如实展示、照常计算，不判断是否构成风险；应收账款（M3）不汇总这类车辆的车辆保险金额，异常由风控预警（M8）判断并生成预警。
- 车辆的内采单价取自内销发票车辆明细中本车的单车金额；本车尚未开内销发票时，内采单价为“未开票”，依赖它的保险货值、保险覆盖率和车辆保险金额展示“无法计算”，不按部分车辆先算。
- 只采信 ERP 中已审核的保单；未审核、已反审核、已作废或已删除的保单不出现在本模块。
- 美元金额按汇率管理（M11）的汇率折算，同时保留原币金额。
- 本模块不判断任何风控规则。功能清单中列在保单下的风控提示（保险未足额覆盖、保单信息与基础交易不一致）由风控预警（M8）判断和完善，本模块只承接 M8 提供的本保单关联预警。
- 企业端（债权人、债务人）本期都看不到保单信息。

**一个完整的例子**（企业、保险公司名称、单据编号和金额为演示值）。ERP 中有一张已审核的保单 PL-889：保单日期 2026-09-09，保险公司“保险甲”，投保人和被保险人均为 Carloha Holding，币种 USD，保险金额 132,000.00 USD，关联提单 BL-5501 和 BL-5502。按提单信息（M12），BL-5501（装船日期 2026-09-10）装有 VIN-A、VIN-B，BL-5502（装船日期 2026-09-12）装有 VIN-C、VIN-D；四辆车在内销发票车辆明细中的单车金额都是 30,000.00 USD。平台算出：保险货值 120,000.00 USD，保险覆盖率 110.00%，每辆车的车辆保险金额 33,000.00 USD。运营人员打开“保单信息”，在列表中看到 PL-889 一行：保险金额 132,000.00 USD、保险货值 120,000.00 USD、保险覆盖率 110.00%、关联提单 2 张／车辆 4 辆、预警“无”。进入详情：概要展示保单号、保单日期、保险公司、投保人、被保险人、币种和保险金额；保障核对展示保险金额（美元）、保险货值（美元）、保险覆盖率和覆盖车辆数；明细中列出两张关联提单、四辆车（VIN、提单号、内采单价、车辆保险金额）和保单附件。运营人员点 VIN-C 进入车辆履约（M5）查看该车的外销情况，返回后点 BL-5502 进入提单信息（M12）查看船名航次，再返回 PL-889。在应收账款（M3）中，含 VIN-A 的那笔应收账款按本模块给出的车辆保险金额 33,000.00 USD 计入其保险覆盖率。

### 1.2 本期不做

- 在平台录入、编辑、删除保单或附件；运营端和企业端都没有这类操作。
- 任何风控规则的判断，包括保险覆盖率低于 100% 时的“保险未足额覆盖”、被保险人与合同卖方不一致时的“保单信息与基础交易不一致”：由风控预警（M8）判断、生成和处理，本模块只承接 M8 提供的预警信息，覆盖率低于 100% 时也不在本模块突出显示。
- 提单的船名航次、港口、清关明细：在提单信息（M12）完整展示，本模块只展示提单号、装船日期并跳转。
- 车辆的采购、内销、外销经历：在车辆履约（M5）完整展示，本模块只展示 VIN 并跳转。
- 保费金额、保费支付记录的展示与核对：本期只展示保费支付凭证附件。
- 对保险条款、险种、承保范围作专业或合规结论。
- 企业端查看保单信息，包括债权人和债务人。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 保单 | ERP 中一张已审核的保单单据，关联一张或多张提单 |
| 保单号 | 保单的编号 |
| 保单日期 | 保单上的保险日期；只展示，不参与任何计算 |
| 投保人 | 购买保险的一方，按 ERP 原值展示 |
| 被保险人 | 享有保险赔偿权利的一方，按 ERP 原值展示 |
| 保险金额 | 保单承保的金额，即整张保单的赔偿上限，按 ERP 原值展示 |
| 关联提单 | 保单在 ERP 中关联的提单；保单通过关联提单覆盖车辆 |
| 覆盖车辆 | 关联提单上的全部车辆（按 VIN 去重），见[保单的采信与车辆对应（F-M13-01）](#F-M13-01) |
| 内采单价 | 本车在内销发票车辆明细中的单车金额；保单本身不提供单车价 |
| 保险货值 | 本保单全部覆盖车辆的内采单价（美元）合计，见[保障核对（F-M13-04）](#F-M13-04) |
| 保险覆盖率 | 保险金额（美元）÷ 保险货值（美元），见[保障核对（F-M13-04）](#F-M13-04) |
| 车辆保险金额 | 本车按本保单分得的保险金额：内采单价（美元）× 保险覆盖率，见[车辆清单与车辆保险金额（F-M13-05）](#F-M13-05) |
| 关联预警 | 风控预警（M8）判定为与本保单有关的预警；哪些算与本保单有关以 M8 为准 |
| 运营人员 | 运营端账号的使用者，即 M2 定义的运营管理员；本期运营端只有这一种角色，权限相同 |

## 3. 共用展示与异常规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。展示、折算和比率口径与应收账款（M3）定义的资产数据模块共用规则一致。

<a id="display-values"></a>
### 3.1 来源值、金额与日期

- 保单号、保险公司、投保人、被保险人、日期、金额等按 ERP 原值展示，不翻译、不改写。
- 某类附件没有时展示“暂无附件”；某类内容一条都没有时展示“暂无记录”。
- 金额与币种代码同时展示，数值在前、币种代码在后，带千分位，例如“132,000.00 USD”。ERP 提供的原币金额按原值展示，不四舍五入、不截断。任何位置都不展示没有币种的金额。
- 不同币种的原币金额不直接相加；需要合计时按美元折算值合计。
- ERP 提供的日期（保单日期、装船日期）按原样展示，不做时区换算；ERP 随日期提供时区时，时区写在日期后面。
- 平台自己记录的时间（附件取得时间）展示到分钟并标注时区：按运营人员在 M2 选择的时区展示；M2 不提供时区设置时统一按 UTC 展示。

<a id="usd"></a>
### 3.2 美元折算与比率

字段名带“（美元）”的值按下表得出，并与原币金额同时展示；折算值标明“折算”。

| 原币 | 美元值 |
| --- | --- |
| USD | 等于原币金额，不标“折算” |
| NGN | 原币金额 ÷ M11 汇率（1 USD = R NGN），汇率取查看时 M11 的当前汇率 |
| 其他币种 | 展示“无法折算”（M11 只维护美元与奈拉） |
| NGN，但 M11 无可用汇率 | 展示“无可用汇率” |

- 全部美元值都按查看时 M11 的当前汇率折算，与其他资产数据模块一致；汇率按[对外提供的汇率口径](../M11-汇率管理/01-汇率管理-PRD.md#FX-05)取得；折算值旁可查看所用汇率值及其生效时间。
- 美元值保留两位小数，四舍五入；合计、比率和车辆保险金额用未取舍的值计算，展示时再取舍。
- 比率以百分数展示，保留两位小数、向下截取（例如 99.996% 展示为 99.99%），保证未达到 100% 时不会显示为 100.00%；超过 100% 时按实际值展示，不封顶。
- 美元值为“无法折算”“无可用汇率”时，该项只展示原币金额和对应说明，不用 0 或其他值代替；依赖它的合计、比率和车辆保险金额展示“无法计算”。
- 比率的分子或分母无法取得，或分母为 0 时，比率展示“无法计算”。

<a id="doc-links"></a>
### 3.3 单据编号跳转

本模块中的编号都可点击，进入该编号所在模块的详情；看完可返回本保单详情。

| 编号 | 进入 |
| --- | --- |
| 保单号 | 本模块该保单的详情 |
| 提单号 | 提单信息（M12）中该提单的详情 |
| VIN | 车辆履约（M5）中该车的详情 |

- 编号对应的单据尚未审核、不在平台中时，编号按原值展示，不可点击。
- 进入后目标已不再被采信（如已反审核、作废）时，提示“该内容不存在或已更新”，可返回本保单详情。

<a id="file-view"></a>
### 3.4 附件查看

- 每份附件展示附件名称和取得时间，可在线查看和下载。
- 附件打开或下载失败时，提示“文件暂时无法打开，请稍后重试”，不影响查看其他信息。

<a id="no-access"></a>
### 3.5 不可访问

- 企业端没有保单信息入口。企业用户通过链接打开本模块任何内容时，统一提示“该内容不存在或无权查看”，不透露其是否存在及任何内容。
- 运营人员处于待首次改密、已停用或锁定中时不能使用本模块，判定以 M2 为准。

<a id="load-fail"></a>
### 3.6 加载失败

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的金额或比率，避免把加载失败误显示为“暂无记录”或“0.00%”。
- 详情中某一部分（如车辆清单、关联提单、附件、关联预警）或某一项来自其他模块的值加载失败时，仅该处提示失败并可重试，其他部分正常展示；依赖该值的保险货值、保险覆盖率和车辆保险金额展示“无法计算”。

## 4. 保单的采信与车辆对应（F-M13-01）

适用范围：平台从 ERP 取得保单后，判断哪些保单进入本模块、每张保单覆盖哪些车辆。结果对运营人员可见，没有用户操作。取得方式由研发决定，本 PRD 不限定。

流程参见：[保单的采信与车辆对应（图 M13-1）](./02-保单信息-流程图与状态机.md#fig-m13-1)。
验收参见：[保单的采信与车辆对应](./04-保单信息-验收.md#acc-f-m13-01)。

<a id="adopt-rules"></a>
### 4.1 只采信已审核保单

- 只有 ERP 中已审核的保单进入本模块；未审核的保单不展示，也不参与任何计算。
- 平台以 ERP 中的同一张保单单据识别同一张保单。同一张保单再次取得且内容一致时不重复展示；内容不同（含保险金额、币种、关联提单的增减）时，新内容直接成为当前展示内容，本模块的计算值随之更新。
- 已采信的保单之后被反审核、作废或删除时，从本模块移除，并不再向 M3、M5、M12 提供该保单。
- 运营人员只看到当前资料，本模块不展示保单变化前的内容和变化历史。

<a id="vehicle-rules"></a>
### 4.2 保单覆盖哪些车辆

| 对象 | 取得方式 | 缺失或异常时 |
| --- | --- | --- |
| 关联提单 | 保单在 ERP 中关联的提单，可多张 | 保单没有关联任何提单时，关联提单展示“未关联提单”，覆盖车辆为 0 辆 |
| 提单号、装船日期、提单上的车辆 | 按提单信息（M12）中该提单的当前资料 | 关联提单在 ERP 中尚未审核时，该提单展示“提单未审核”，它的车辆不计入 |
| 覆盖车辆 | 全部关联提单上的车辆，按 VIN 去重 | 同一 VIN 出现在本保单的两张关联提单上时只计一辆，提单号两张都列出 |
| 内采单价 | 本车所在内销发票车辆明细中的单车金额；本车有多张内销发票时取内销发票日期最近的一张 | 本车尚未开内销发票时展示“未开票” |

- 保单不需要 VIN，也不关联内销合同；车辆一律经关联提单得到。
- 关联提单的车辆增减（如 M12 中提单车辆变化）后，本保单的覆盖车辆和计算值随之更新。
- 一辆车只应被一张保单覆盖。同一辆车出现在多张保单中（含同一张提单被多张保单关联）时，本模块如实展示：每张保单的车辆清单都列出该车，每张保单的保险货值、保险覆盖率和车辆保险金额照常计算。
- 这种情况是否构成风险由风控预警（M8）判断，本模块不作提示；应收账款（M3）对这类车辆的处理见[车辆清单与车辆保险金额（F-M13-05）](#F-M13-05)。

## 5. 保单信息列表（F-M13-02）

适用角色与前提：可正常使用的运营人员，从运营端“保单信息”菜单进入。可查看本模块的全部保单。

验收参见：[保单信息列表](./04-保单信息-验收.md#acc-f-m13-02)。

列表每张保单一行，只放定位和比较所需的字段：

| 业务信息 | 含义 | 来源 |
| --- | --- | --- |
| 保单号 | 点击进入[保单详情（F-M13-03）](#F-M13-03) | 保单 |
| 保单日期 | 保险日期 | 保单 |
| 保险公司 | 承保保险公司 | 保单 |
| 被保险人 | 被保险人 | 保单 |
| 保险金额（美元） | 按[美元折算与比率](#usd)，同时展示原币金额 | 保单保险金额折算 |
| 保险货值（美元） | 见[保障核对（F-M13-04）](#F-M13-04) | 平台计算；不能计算时展示“无法计算” |
| 保险覆盖率 | 见[保障核对（F-M13-04）](#F-M13-04) | 平台计算；不能计算时展示“无法计算” |
| 关联提单数／车辆数 | 关联提单张数、覆盖车辆辆数，如“2 张／4 辆” | 平台计数；有未审核的提单时注明“含 N 张提单未审核” |
| 预警 | 本保单未处理的关联预警条数；没有时展示“无” | M8 提供，见[关联预警（F-M13-07）](#F-M13-07) |

查找与筛选：

- 按保单号查找，支持部分匹配。
- 按提单号查找，支持部分匹配；结果为关联了该提单的全部保单。
- 按 VIN 查找，支持部分匹配；结果为覆盖该车的全部保单。
- 筛选：保险公司、保单日期范围、是否有未处理关联预警。多个条件同时生效。
- 默认按保单日期从新到旧排列；日期相同时按保单号排列。

边界与异常：

- 平台尚未采信任何保单时，展示“暂无保单资料”；查找或筛选无结果时，展示“没有符合条件的保单”并可清除条件。
- 列表不提供新增、编辑、删除操作，也不按保险覆盖率高低突出显示。
- 加载失败按[加载失败](#load-fail)处理。

## 7. 保障核对（F-M13-04）

适用范围：平台对每张保单计算保险货值和保险覆盖率，在列表和详情“保障核对”中展示。没有用户操作。

流程参见：[保险货值、覆盖率与车辆保险金额（图 M13-2）](./02-保单信息-流程图与状态机.md#fig-m13-2)。
验收参见：[保障核对](./04-保单信息-验收.md#acc-f-m13-04)。

<a id="coverage-rule"></a>
### 7.1 计算口径

| 指标 | 计算 | 展示 |
| --- | --- | --- |
| 保险金额（美元） | 保单保险金额按[美元折算与比率](#usd)折算 | 美元金额，同时展示原币金额 |
| 保险货值（美元） | 本保单全部覆盖车辆的内采单价（美元）合计 | 美元金额，并注明“共 N 辆车” |
| 保险覆盖率 | 保险金额（美元）÷ 保险货值（美元） | 百分数，按[美元折算与比率](#usd)取舍，超过 100% 按实际值展示 |

<a id="coverage-cases"></a>
### 7.2 不能计算的情形

| 情形 | 保险货值（美元） | 保险覆盖率 |
| --- | --- | --- |
| 任一覆盖车辆尚未开内销发票 | 展示“无法计算”，并注明“N 辆车未开票” | 展示“无法计算” |
| 任一覆盖车辆的内采单价无法折算或无可用汇率 | 展示“无法计算”，并注明对应车辆数及原因 | 展示“无法计算” |
| 关联提单中有提单尚未审核 | 展示“无法计算”，并注明“N 张关联提单未审核” | 展示“无法计算” |
| 保单没有覆盖车辆（未关联提单，或关联提单上没有车辆） | 展示“无法计算”，并注明“无覆盖车辆” | 展示“无法计算” |
| 保险金额无法折算或无可用汇率 | 照常计算 | 展示“无法计算” |
| 保险货值合计为 0 | 展示“0.00 USD” | 展示“无法计算” |

- 不按部分车辆先算保险货值；全部覆盖车辆都有内采单价（美元）后才得出结果。
- 内采单价、汇率、关联提单或车辆变化后，保险货值和保险覆盖率随之重新计算。
- 保险覆盖率只是计算结果，本模块不判断是否足额、不作提示，也不影响其他模块的任何状态；覆盖率是否构成风险由风控预警（M8）判断。
- 保单日期不参与计算；汇率按[美元折算与比率](#usd)取当前口径。

## 8. 车辆清单与车辆保险金额（F-M13-05）

适用角色与前提：可正常使用的运营人员，在详情明细中查看。只读。

验收参见：[车辆清单与车辆保险金额](./04-保单信息-验收.md#acc-f-m13-05)。

每辆覆盖车辆一行，按提单号、再按 VIN 排列：

| 业务信息 | 含义 |
| --- | --- |
| VIN | 可点击，进入车辆履约（M5）详情 |
| 提单号 | 本车所在的本保单关联提单，可点击进入提单信息（M12）详情；本车在本保单两张关联提单上时两张都列出 |
| 内采单价（美元） | 本车内采单价按[美元折算与比率](#usd)折算，同时展示原币金额；本车尚未开内销发票时展示“未开票” |
| 车辆保险金额（美元） | 内采单价（美元）× 本保单保险覆盖率；不能计算时展示“无法计算” |

- 车辆保险金额用未取舍的内采单价（美元）和保险覆盖率计算，结果保留两位小数、四舍五入。全部车辆保险金额之和与保险金额（美元）因取舍可能相差几分，不另作调整。
- 本保单保险覆盖率为“无法计算”时，全部车辆的车辆保险金额都展示“无法计算”。
- 车辆保险金额是本车在本保单中的值，向应收账款（M3）的车辆清单和保险覆盖率提供。
- 本车同时在多张保单中时，本模块在每张保单中照常给出它的车辆保险金额，并向 M3 标明本车在几张保单中。M3 不汇总这类车辆：该车车辆保险金额不取最大值、也不相加，所在应收账款的保险覆盖率展示“无法计算”，并注明“N 辆车在多张保单中”。
- 没有覆盖车辆时，车辆清单展示“暂无车辆”；有提单尚未审核时，只列已审核提单上的车辆，并注明“N 张关联提单未审核”。

## 10. 关联预警（F-M13-07）

适用角色与前提：可正常使用的运营人员，在列表和详情中查看。

流程参见：[各入口与跳转（图 M13-3）](./02-保单信息-流程图与状态机.md#fig-m13-3)。
验收参见：[关联预警](./04-保单信息-验收.md#acc-f-m13-07)。

- 本模块不判断任何风控规则，也不在字段旁给出风控提示。功能清单中列在保单下的风控提示由风控预警（M8）判断和完善；哪些预警算与本保单有关，以 M8 为准。
- 本模块只展示 M8 提供的本保单关联预警：
  - 列表“预警”：本保单未处理的关联预警条数；没有时展示“无”。
  - 详情概要：未处理和已处理的关联预警数量；都没有时展示“无关联预警”。
- 点击预警数量进入 M8，落点按 M8 规定；看完可返回本保单详情。
- 本模块展示的数量始终与 M8 一致，M8 生成或处理预警后随之更新。
- 预警不改变本模块的任何金额、比率或车辆清单；本模块没有处理预警的操作。
- 关联预警加载失败时，仅该部分提示失败并可重试，不显示为“无”或“无关联预警”。

## 12. 待确认事项与依赖

按用户要求，本期先按功能清单字段设计页面，计算与关联口径后续细化。下表事项在确认前按“当前处理”执行。

| 编号 | 事项（具体冲突点） | 当前处理与影响 |
| --- | --- | --- |
| M13-Q08 | 现行风控预警（M8）的“VIN 不一致”以“保单关联合同”为比较对象；保单只关联提单、不关联内销合同，该比较失去依据。M8 也尚未向本模块提供关联预警数量，功能清单中的“保险未足额覆盖”“保单信息与基础交易不一致”，以及“同一车辆被多张保单覆盖”，尚未纳入 M8 | 本模块按 M8 提供的结果展示，列表“预警”和详情数量随 M8 完善生效。M8 完善时需：改写或取消保单与合同的 VIN 比对；新增“同一车辆被多张保单覆盖”规则（含同一张提单被多张保单关联），并向本模块和 M3 提供关联预警；写明哪些预警算与本保单有关并向本模块列表和详情提供数量；“保单信息与基础交易不一致”须明确比对的是哪份合同的卖方。影响[关联预警](#F-M13-07) |

<a id="dependencies"></a>
依赖：

- ERP：提供已审核的保单（保单号、保险日期、保险公司、投保人、被保险人、币种、保险金额、关联提单）、保单与保费支付凭证附件，以及保单的反审核、作废、删除。
- 提单信息（M12）：按提单提供提单号、装船日期、车辆 VIN 及详情入口；在提单详情中展示本模块给出的关联保单。
- 应收账款（M3）：按本模块的车辆保险金额计算应收账款保险覆盖率，并在车辆清单中展示保单号和车辆保险金额；在多张保单中的车辆不参与汇总，所在应收账款的保险覆盖率展示“无法计算”。
- 车辆履约（M5）：提供车辆履约详情入口；在运输与保险段展示本车所在保单号。
- 应收账款（M3）采信的内销发票：提供每辆车的内采单价。
- 汇率管理（M11）：提供当前汇率及其生效时间。
- 风控预警（M8）：判断全部风控规则，定义哪些预警与本保单有关，向本模块列表和详情提供未处理、已处理的关联预警数量及入口。
- M1、M2：提供运营人员账号、状态与时区设置。
