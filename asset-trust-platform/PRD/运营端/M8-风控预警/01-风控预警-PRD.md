## 1. 模块是什么

本模块是运营端唯一判断和处理风控规则的地方。平台把已经采信的内销发票、三类合同、车辆、提单与清关单、保单、收付记录互相比对，按本册的风控规则目录发现问题时生成风控预警。每条预警有一个风控类别（资产成立、回款与期限、价格与成本、采购与付款、物流与清关、外销与终端回款、保险、资金流水）和一个等级：**阻断**会阻止关联应收账款发起确权申请和运营审核通过，差异在来源资料中更正后自动解除，运营人员不处理；**预警**需要运营人员核实并记录处理结果；**提示**只提醒运营人员留意、条件消除后自动解除。应收账款、合同信息、车辆履约、提单信息、保单信息、资金收付和运营审核都只展示本模块提供的关联预警，不自行判断。运营人员可在“风控规则”中调整每条规则的等级、停用或启用规则。资料缺失、到期等不能进入后续业务的条件属于平台限制，由 M3、确权申请（M7a）与运营审核（M9）定义，不在本模块。本模块另有“三方数据源”入口，只说明后续接入三方数据的能力。

基本原则：

- **规则只在这里判断。** 资产数据各模块不在字段旁给出风控提示；规则、比较口径、等级和处理都以本册为准。
- **按等级决定后果。** 只有阻断类预警影响业务办理：存在时关联应收账款不能发起确权申请、不能运营审核通过，直到差异消除；预警和提示都不阻止任何业务。
- **阻断只由数据解除。** 阻断类预警没有人工处理，差异消除后平台自动结束；运营人员只能核对资料，或在风控规则中调整该规则。
- **风控与平台限制分开。** 本模块只判断已有资料之间的矛盾与风险信号；资料是否齐全、是否已到期、是否已收清等平台限制由所属模块定义，本模块不重复判断。
- **只比已有资料。** 只比较平台已采信、且有值的资料；资料缺失、尚未取得或币种无法折算时不比较，也不因此生成预警。
- **同一件事只预警一次。** 同一个比较对象、同一条规则同一时间最多一条未处理预警；新差异追加进去，运营人员已处理过的同一差异再次出现不再预警。
- **比率按发票币种计算。** 涉及应收账款的比率与金额比较按应收账款币种（内销发票币种）计算，其他币种按 M11 当前汇率折算到发票币种；美元只用于展示和汇总。
- **人工不能增删预警。** 预警只由平台按规则生成，运营人员不能手动新建、修改或删除预警，也不能修改规则的判断条件。
- **等级与启用可配置、全程留痕。** 每条规则的等级和启用状态由运营人员在[风控规则配置（F-M8-19）](#F-M8-19)中调整，必须写明原因，每次修改都留痕并通知全体运营。
- **只在运营端使用。** 企业端（债权人、债务人）看不到任何风控预警内容和三方数据源内容；因阻断不能发起申请时，企业端只看到 M7a 的统一不可申请原因。

**一个完整的例子**（企业名称、编号、金额与日期为演示值）。应收账款 AR-0012（内销发票 PI-0012，Carloha Holding → Carloha Nigeria，90,000.00 USD，车辆 VIN-A、VIN-B、VIN-C，应收账款到期日 2026-12-19）有一笔“待运营审核”的确权申请 AP-0001。2026-12-12（剩余 7 天）已收款 45,000.00 USD、回款状态“部分收款”，平台生成预警 W-0101：回款风险（RK-10），类别“回款与期限”，等级“预警”，全体运营收到站内消息，“风控预警”菜单角标加 1。同一天 ERP 中另一张已审核内销发票 PI-0020（形成 AR-0020）也列有 VIN-C，平台生成预警 W-0102：VIN 重复（RK-01），等级“阻断”，关联应收账款 AR-0012、AR-0020。运营人员甲在 M9 打开 AP-0001，看到“存在阻断类风控预警：VIN 重复（W-0102）”，不能审核通过。VIN-B 已于 2026-11-20 外销出库，至今只收到外销收款 15,000.00 USD（外销单价 31,000.00 USD），平台生成一条提示：车辆销售款未全部收回（RK-28）；提示不发消息、不计入角标。甲从 W-0102 进入 M3 核对，确认 PI-0020 为误开发票，联系 ERP 更正；阻断类预警没有处理入口。ERP 将 PI-0020 反审核后，W-0102 的差异现状变为“差异已消除”，阻断随之解除，平台自动结束该预警（处理结果“已自动解除”）。甲回到 M9，因 W-0101 仍未处理，按 M9 填写审核说明后审核通过。之后 VIN-B 的外销收款收齐，RK-28 的提示自动解除。

### 1.2 本期不做

- 本册规则目录以外的风控条件。
- 平台限制：资料缺失、到期日未确定、已到期、已收清等不能进入后续业务的条件，由 M3、M7a、M9 定义。核心资料与原资料不同属于风控，由[核心资料变更（RK-36）](#RK-36)判断。
- 阻断类预警阻止债务人确认（M7b），或撤销、关闭已提交的确权申请；本期只阻止发起新的确权申请和运营审核通过。
- 平台判断两个不同名称是否为同一法定主体，或维护主体别名、关联公司对照表。
- 运营人员手动新建、修改、删除、合并预警，新增规则或修改规则的判断条件，或者处理阻断类预警。
- 处理结果的修改、撤回或二次处理。
- 风控预警的导出、批量处理和指派给某个运营人员。
- 向企业端展示任何预警内容（规则、编号、差异、处理），或向企业发送风控消息。
- 接入监管账户银行流水等三方数据独立核对收付款：列为后续规划，本期收付数据只来自 ERP。
- 用三方数据或用户自填资料作为比较依据：本期只比较平台从 ERP 采信的资料、M11 的汇率、提单信息（M12）已使用的外部航程跟踪数据，以及 M2 中运营维护的平台企业名称与关联的 ERP 企业。
- 邮件、短信等站外通知。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 风控规则 | 本册[风控规则目录](#rule-catalog)中的一条判断，有规则编号（RK-*）、名称、类别、等级和触发条件 |
| 风控预警（预警） | 平台按某条风控规则发现差异后生成的一条记录，有平台生成的预警编号，全平台唯一、生成后不变；“预警”也是等级名称，按上下文区分 |
| 风控类别 | 资产成立、回款与期限、价格与成本、采购与付款、物流与清关、外销与终端回款、保险、资金流水八类，按规则所查的业务环节划分 |
| 等级 | 阻断（Blocking）、预警（Warning）、提示（Notice），决定预警的后果，见[三个等级](#levels) |
| 默认等级、当前等级 | 默认等级是本册规则目录中为每条规则确定的等级；当前等级是运营人员在[风控规则配置（F-M8-19）](#F-M8-19)中设置后生效的等级，上线时与默认等级相同 |
| 启用状态 | 启用、停用。停用的规则不再比对，其未处理的预警由平台关闭，见[停用与启用](#rule-toggle) |
| 比较对象 | 一条预警所比较的那件事，例如“VIN-C”“应收账款 AR-0012 · 回款”“外采发票 PPI-0301” |
| 差异项 | 比较对象中一处具体的不一致，例如一个不一致的主体值、一个找不到的 VIN、一次条件成立 |
| 值差异型规则 | 比较两项值是否一致的规则，差异项按不一致的值区分 |
| 条件型规则 | 判断某个条件是否成立的规则（如金额高低、日期先后、期限），条件持续成立期间是同一个差异项 |
| 预警状态 | 未处理、已处理，只表示是否已记录处理结果 |
| 差异现状 | 差异仍存在、差异已消除，表示按最新资料比对时差异是否还在；与预警状态相互独立 |
| 处理结果 | 核实无风险、确认有风险：运营人员对预警类、提示类记录；已自动解除：阻断类、提示类差异消除后由平台记录；规则停用关闭：规则停用时由平台记录 |
| 关联对象 | 一条预警涉及的应收账款、合同、车辆、提单、保单、收付记录，用于在这些对象所在模块展示关联预警 |
| 在融资资产 | 确权申请状态为“运营审核通过”，或申请有“上链中”的审核提交（按 M9 [提交与上链](../M9-运营审核/01-运营审核-PRD.md#review-result)）的应收账款，按其申请当次依据中的车辆计 |
| 外采交货日期 | 主机厂（外采供应商）实际交付本车的日期，按车辆履约（M5）[采购段（F-M5-16）](../M5-车辆履约/01-车辆履约-PRD.md#F-M5-16)；M3、M4 使用同一名称和取值 |
| 平台企业、ERP 企业、ERP 名称 | 平台企业是 M2 中由运营邀请和维护的企业；ERP 企业是 ERP 单据中的交易主体，以 ERP 企业标识识别，ERP 名称是它在 ERP 中的名称；两者的关联按 M2 [关联 ERP 企业（F-EN-10）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-EN-10) |
| 终端回款金额、终端回款进度 | 按 M3 [资产健康度（F-M3-11）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-11)：终端回款金额是本笔应收账款计入的外销收款金额，终端回款进度是它对应收账款金额的覆盖程度；外销收款以外销合同为单位整份计入、不拆到车辆，见 M3 [终端回款金额的计入](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#terminal-receipt)，本模块不另行计算 |
| 风控参数 | 规则中使用的天数等数值，见[风控参数](#params) |
| 运营人员 | 运营端账号的使用者，即 M2 定义的运营管理员；本期运营端只有这一种角色，权限相同 |

## 3. 共用规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。

<a id="adopt-scope"></a>
### 3.1 比较哪些资料

- 只比较平台已采信的资料，口径按 M3 [采信范围](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#adopt-scope)：ERP 中已审核的单据；未审核、已反审核、作废或删除的单据不参与比较。
- 资产数据各模块的字段、单价、比率按其所在模块的定义取值，本模块不另行计算口径；例如外采单价、内采单价、外销单价按 M5 [价格链](../M5-车辆履约/01-车辆履约-PRD.md#price-chain)，已收款比率、终端回款进度、保险覆盖率按 M3、M13。
- 应收账款的核心资料按 M3 的原资料比较；再次取得的、与原资料不同的值只用于[核心资料变更（RK-36）](#RK-36)，其他规则不比较这些值。
- 平台企业的企业名称、企业英文名称和关联的 ERP 企业按 M2 当前资料，只用于[平台企业名称与 ERP 名称不一致（RK-34）](#RK-34)。
- 资料缺失不属于风控：缺少的资料不比较，也不生成预警；资料缺失时能否进入确权申请与运营审核，由 M3 的资料校验及 M7a、M9 的条件决定。

<a id="display-values"></a>
### 3.2 来源值、金额与时间

- 主体名称、VIN、单据编号、金额等来自 ERP 的值按原值展示，不翻译、不改写。
- 金额与币种代码同时展示，数值在前、币种代码在后，带千分位，例如“60,000.00 USD”；ERP 金额按原值展示，不四舍五入、不截断。
- 平台折算得到的金额标明“折算”，保留两位小数，四舍五入；比较和比率使用未取舍的计算值。
- 比率以百分数展示，保留两位小数、向下截取，与 M3 [美元折算与比率](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#usd-rule)一致。
- ERP 提供的日期按原样展示，不做时区换算；涉及“今天”的判断（剩余天数、已到期天数、等待天数）统一按 UTC+1 的当前日期，与 M3 [剩余天数与临近到期](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#days-left)一致。
- 平台自己记录的时间（预警生成时间、最近比对时间、处理时间、预警记录中的各时间）展示到分钟，按运营人员本人的时区展示并标明时区，见 M2 [界面语言与时区（F-OP-10）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-10)。
- 界面语言按 M2 [界面语言与时区（F-OP-10）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-10)切换；规则名称、等级等平台文字随界面语言展示，英文名称见消息通知册[规则与等级的英文名称](./03-风控预警-消息通知.md#en-names)；来自 ERP 的值按原值展示。

<a id="compare-rules"></a>
### 3.3 比较口径

| 比较内容 | 口径 |
| --- | --- |
| 金额高低与相等 | 币种相同时按原币比较；币种不同时把一方按 M11 当前汇率折算为各规则写明的基准币种后比较。只有美元与奈拉之间能折算；涉及其他币种，或需要折算但 M11 无可用汇率时，不比较 |
| 涉及应收账款的比率 | 按应收账款币种计算：分子中其他币种的金额按 M11 当前汇率折算为应收账款币种。同一汇率下与 M3 按美元计算的结果相同；美元值只用于展示和汇总 |
| 日期先后 | 按 ERP 日期原值比较；同一天不算“早于”或“晚于” |
| 主体是否一致 | 两方都有 ERP 企业主数据 ID 时按 ID 比较；否则按名称比较：忽略首尾空格、把连续空格视为一个、不区分英文大小写，其他任何不同（含标点、缩写、“Ltd”与“Limited”）都算不一致。平台不判断不同名称是否为同一法定主体 |
| VIN、船名航次、交易流水号 | 不区分大小写，忽略空格 |
| 缺失 | 参与比较的任一项未提供、单据未取得或无法计算时，该次不比较，不生成预警，也不视为没有差异 |

- 汇率更新本身不触发重新比对；比对时使用当时 M11 的当前汇率，并在预警中记录所用汇率编号、汇率值与生效时间。

<a id="no-access"></a>
### 3.4 不可访问

- 企业端没有任何风控预警、风控规则、三方数据源入口，也看不到任何预警内容；M7a 以统一原因告知因阻断不能发起申请，不展示预警的规则、编号和差异。企业账号访问本模块页面时，按 M2 [运营端菜单与无权访问（F-OP-11）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-11)处理，不透露任何内容。
- 运营账号待首登改密或锁定时不能使用本模块，按 M2 [运营账号状态](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#op-account-status)。

<a id="load-fail"></a>
### 3.5 加载失败

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的差异或状态，避免把加载失败误显示为“暂无风控预警”或“差异已消除”。
- 详情中某一部分（例如关联对象、预警记录）加载失败时，仅该部分提示失败并可重试，其他部分正常展示；差异明细加载失败时不能提交处理。
- 待办数量取数失败时不展示角标（不展示为 0），菜单照常可用。
- 其他模块读取本模块结果失败时，不能当作“没有关联预警”；各处的展示按所在模块的加载失败规则。阻断结果无法取得时的处理见[阻断的作用](#blocking)。

<a id="F-M8-01"></a>
## 4. 比对与预警生成（F-M8-01）

适用范围：平台采信或更新资料后的自动比对与预警生成规则。结果对运营人员可见，没有用户操作。

流程参见：[比对与预警生成（图 M8-1）](./02-风控预警-流程图与状态机.md#fig-m8-1)。
验收参见：[比对与预警生成](./04-风控预警-验收.md#acc-f-m8-01)。

<a id="compare-when"></a>
### 4.1 什么时候比对

- 平台采信新资料、资料内容变化或资料被移除后，对受影响的比较对象按相关规则重新比对。只比对启用中的规则。
- 涉及“今天”的规则（回款风险、逾期、严重逾期、终端已回款而内销未收齐），每天在 UTC+1 日期变化时重新判断一次，须在日期变化的时点（UTC+1 当日 00:00）后 5 分钟内完成判定；资料变化时随之判断。
- 外部航程跟踪数据更新时，重新判断 BL 信息与外部数据不一致（RK-26）。
- M2 中平台企业的企业名称、企业英文名称变化，或关联、取消关联 ERP 企业时，重新判断平台企业名称与 ERP 名称不一致（RK-34）。
- 再次取得同一张内销发票时，重新判断核心资料变更（RK-36）。
- M9 形成审核提交、上链成功或上链失败时，对该申请当次依据中的 VIN 重新判断 VIN 重复（RK-01）。
- 平台上线时，对已经采信的全部资料做一次比对。这次比对生成的预警照常计入待办数量和各模块的关联预警条数，但不逐条发送[新的风控预警（M8-NT01）](./03-风控预警-消息通知.md#M8-NT01)。
- 运营人员不能手动发起比对。

<a id="item-rules"></a>
### 4.2 生成、追加与去重

同一条规则、同一个比较对象内，按下表处理比对结果：

| 情况 | 结果 | 是否发消息 |
| --- | --- | --- |
| 出现一个此前没有出现过的差异项，且当前没有未处理预警 | 新建一条预警，状态“未处理”，差异现状“差异仍存在” | 规则当前等级为阻断、预警时发送[新的风控预警（M8-NT01）](./03-风控预警-消息通知.md#M8-NT01)；提示时不发 |
| 出现一个此前没有出现过的差异项，但当前已有一条未处理预警 | 把新差异项追加到这条未处理预警中，不新建 | 不发送 |
| 已出现过的差异项出现在一份新的记录中 | 把新记录追加到包含该差异项的预警；那条预警已由运营人员处理时标“处理后新增”，状态不变 | 不发送 |
| 与已有预警完全相同（同一记录、同一值） | 不做任何变化 | 不发送 |

差异项的区分口径：

| 规则类型 | 什么算同一个差异项 |
| --- | --- |
| 值差异型 | 比较对象 + 不一致的值（如不一致的主体、找不到的 VIN、另一张保单号、另一笔应收账款） |
| 条件型 | 比较对象 + 条件成立的这一段时间：条件持续成立期间，数值变化只更新差异明细，不算新差异项；条件消除后再次成立，算新差异项 |

- 预警一经生成不会被删除；资料之后被移除时，预警保留：
  - 比较对象本身不再存在（例如作为比较对象的内销发票、外采发票被反审核、作废或删除，平台企业取消了关联），差异现状变为“差异已消除”，并按[差异现状](#diff-state)处理；
  - 只是另一份参与比较的资料被移除（例如 RK-04 的内销合同），按[缺失](#compare-rules)不比较，差异现状保持原状。

<a id="diff-state"></a>
### 4.3 差异现状

- 每次重新比对后，更新该比较对象全部预警的差异现状和最近比对时间：仍有任一差异项时为“差异仍存在”，全部差异项都不再出现时为“差异已消除”。
- 阻断类、提示类：差异已消除且仍为未处理时，平台自动将其改为“已处理”，处理结果“已自动解除”；阻断同时解除，见[阻断的作用](#blocking)。
- 预警类：差异已消除不会自动结束预警，仍需运营人员记录处理。
- 差异已消除后同一差异项再次出现：
  - 未处理的预警恢复为“差异仍存在”；
  - 运营人员处理过的预警，值差异型恢复为“差异仍存在”、不新建，条件型按新差异项新建预警；
  - 由平台结束的预警（已自动解除、规则停用关闭）不恢复，按新差异项新建预警。

<a id="related-objects"></a>
### 4.4 关联对象

- 每条预警按规则目录中写明的关联对象，记录涉及的应收账款、合同、车辆、提单、保单、收付记录。
- 关联应收账款：规则涉及车辆时，为这些车辆所在的应收账款（车辆在已采信内销发票车辆明细中）；规则以应收账款或内销合同为比较对象时，为该应收账款或该合同下的全部应收账款。没有时为“无”。
- 规则以车辆为比较对象、涉及保单时（RK-35），关联对象另含涉及的各张保单及其关联提单。
- 规则以平台企业为比较对象时（RK-34），关联应收账款为该平台企业作为债权人或债务人的全部应收账款，对应口径按 M3 [买卖双方与平台企业的对应](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#party-match)。
- 关联对象随资料更新而变化，预警中展示当前结果。

<a id="F-M8-10"></a>
## 5. 风控等级与阻断（F-M8-10）

适用范围：每条风控规则有一个当前等级，决定其预警的后果。默认等级见[风控规则目录](#rule-catalog)，运营人员可在[风控规则配置（F-M8-19）](#F-M8-19)中调整。

流程参见：[预警状态（图 M8-2）](./02-风控预警-流程图与状态机.md#fig-m8-2)、[阻断对确权申请与运营审核的作用（图 M8-5）](./02-风控预警-流程图与状态机.md#fig-m8-5)。
验收参见：[风控等级与阻断](./04-风控预警-验收.md#acc-f-m8-10)。

<a id="levels"></a>
### 5.1 三个等级

| 等级 | 用在什么问题上 | 对业务的作用 | 处理 | 站内消息 | 计入菜单待办 |
| --- | --- | --- | --- | --- | --- |
| 阻断 | 应收账款本身不能成立或会被重复融资 | 差异仍存在时，关联应收账款不能发起确权申请，也不能运营审核通过 | 运营人员不能记录处理；差异消除后平台自动结束，阻断同时解除 | 发送 | 未处理时计入 |
| 预警 | 需要核实的风险信号 | 不阻止任何业务；作为审核参考提供给 M9 | 运营人员记录处理 | 发送 | 未处理时计入 |
| 提示 | 需要留意的执行情况 | 不阻止任何业务 | 可由运营人员记录处理；差异消除后自动解除 | 不发送 | 不计入 |

- 同一条规则的全部预警（含调整前已生成的）都按规则的当前等级执行；等级调整的效果见[调整等级](#rule-level)。
- 审核说明是否必填由 M9 按本模块提供的等级、预警状态和处理结果判断，见 M9 [确认与审核说明](../M9-运营审核/01-运营审核-PRD.md#review-confirm)。
- 停用规则的预警不按任何等级产生作用，见[停用与启用](#rule-toggle)。

<a id="blocking"></a>
### 5.2 阻断的作用

- 阻断类预警的差异现状为“差异仍存在”时：
  - 关联应收账款不能发起新的确权申请，判断以 M7a 提交申请时为准，不可申请原因按 M7a [可申请的条件](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#eligibility)；
  - 关联应收账款中处于“待运营审核”的确权申请不能审核通过。
- 已提交的确权申请照常推进：阻断不撤销、不关闭申请，也不阻止债务人确认。
- 是否阻断只看差异现状，不看预警状态：调为阻断前已由运营人员处理、差异仍存在的预警同样阻断；未处理的阻断类预警计入待办。
- 阻断的判断以 M9 提交审核通过时的结果为准；已形成的审核提交在上链期间及上链后不受本模块变化影响，按 M9 [提交与上链](../M9-运营审核/01-运营审核-PRD.md#review-result)。本模块提供造成阻断的规则名称与预警编号，M9 据此展示阻断原因并可进入该预警。
- 关联预警结果无法取得（读取失败）时，不能确认没有阻断，按存在阻断处理：不能审核通过；发起申请时由 M7a 按“暂无法判断”处理，不当作通过。
- 阻断类预警没有记录处理入口；差异已消除时阻断立即解除，平台自动结束该预警。
- 运营人员要解除阻断，只能在来源资料中更正差异，或在[风控规则配置（F-M8-19）](#F-M8-19)中调低该规则的等级或停用该规则；调整须写明原因、留痕并通知全体运营。
- 阻断不改变申请状态、应收账款资料或任何其他状态。

<a id="params"></a>
### 5.3 风控参数

| 参数 | 用于 | 本期取值 |
| --- | --- | --- |
| 临近到期天数 | [回款风险（RK-10）](#RK-10) | 7 天，与 M3 临近到期（剩余 0—7 天）一致 |
| 严重逾期天数 | [严重逾期（RK-12）](#RK-12) | 30 天 |
| 截留等待天数 | [终端已回款或已售完、内销未收齐（RK-13）](#RK-13) | 7 天 |

- 上表为默认取值；运营人员可在[风控规则配置（F-M8-19）](#F-M8-19)中调整，见[风控参数](#rule-params)。

<a id="rule-catalog"></a>
## 6. 风控规则目录

规则按类别分节，共 30 条，默认等级为阻断 5 条、预警 13 条、提示 12 条。下表与各规则标题中的等级均为默认等级，实际执行按[风控规则配置（F-M8-19）](#F-M8-19)中的当前等级。规则按类别分节，每节一张表。表中“比较对象”是一条预警比较的那件事，“关联对象”决定哪些模块展示这条预警。各规则的差异明细列出触发条件中比较的每一项值及其来源单据编号、取得时间；差异摘要为“规则名称：首个差异的关键值”，有多处时加“等 N 处”。

| 类别 | 阻断 | 预警 | 提示 |
| --- | --- | --- | --- |
| [资产成立（F-M8-11）](#F-M8-11) | VIN 重复（RK-01）、发票金额与车辆明细不一致（RK-03）、内销发票与内销合同主体不一致（RK-04）、平台企业名称与 ERP 名称不一致（RK-34）、核心资料变更（RK-36） | 基础交易合同日期存疑（RK-07） | 内销发票单价与合同单价不一致（RK-06）、账款起算日不一致（RK-08）、账款到期日不一致（RK-09） |
| [回款与期限（F-M8-12）](#F-M8-12) | — | 回款风险（RK-10）、逾期（RK-11）、严重逾期（RK-12）、内销收款主体不一致（RK-14） | 终端已回款或已售完、内销未收齐（RK-13） |
| [价格与成本（F-M8-13）](#F-M8-13) | — | 外采单价高于内采单价（RK-15）、外销单价低于内采单价（RK-16） | 形式发票金额合计大于合同金额（RK-18） |
| [采购与付款（F-M8-14）](#F-M8-14) | — | 外采付款主体不一致（RK-20） | 外采付款金额高于外采形式发票金额（RK-21）、外采款项登记存疑（RK-22） |
| [物流与清关（F-M8-15）](#F-M8-15) | — | 基础交易货物流存疑（RK-23）、BL 信息与外部数据不一致（RK-26） | 清关主体与内销合同不一致（RK-24）、清关船名航次与提单不一致（RK-25） |
| [外销与终端回款（F-M8-16）](#F-M8-16) | — | 外销收款方不一致（RK-29） | 车辆销售款未全部收回（RK-28） |
| [保险（F-M8-17）](#F-M8-17) | — | 同一车辆被多张保单覆盖（RK-35） | 保险未足额覆盖（RK-31）、保单信息与基础交易不一致（RK-32） |
| [资金流水（F-M8-18）](#F-M8-18) | — | 交易流水号重复（RK-33） | — |

<a id="F-M8-11"></a>
## 7. 资产成立规则（F-M8-11）

适用范围：核对一笔应收账款本身能否成立。没有用户操作。到期日是否确定属于平台限制，按 M3 [到期状态](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#due-status)，不在本节。

验收参见：[资产成立规则](./04-风控预警-验收.md#acc-f-m8-11)。

<a id="RK-01"></a>
**VIN 重复（RK-01）**｜阻断｜值差异型

- 比较对象：一个 VIN。
- 触发条件：该 VIN 同时占用两笔及以上不同的应收账款。占用指：VIN 列在该应收账款当前已采信内销发票的车辆明细中；或该应收账款是在融资资产，VIN 列在其申请当次依据的车辆中。
- 差异项：占用该 VIN 的每一笔应收账款。
- 关联对象：占用该 VIN 的全部应收账款、该车辆。
- 不比较：无。在融资资产的内销发票之后被反审核或作废，其当次依据中的车辆仍计为占用。
- 阻断作用于关联应收账款中处于“待运营审核”的申请，见[阻断的作用](#blocking)。

<a id="RK-03"></a>
**发票金额与车辆明细不一致（RK-03）**｜阻断｜条件型

- 比较对象：一笔应收账款（内销发票）。
- 触发条件：内销发票车辆明细中各车的单价合计不等于内销发票金额。
- 关联对象：该应收账款及其车辆、关联的内销合同。
- 不比较：任一车辆单价未提供，或车辆单价币种与发票币种不同。

<a id="RK-04"></a>
**内销发票与内销合同主体不一致（RK-04）**｜阻断｜值差异型

- 比较对象：一笔应收账款 · 卖方或买方。
- 触发条件：内销发票的内销卖方与其关联内销合同的卖方不一致，或内销买方与合同买方不一致，按[主体是否一致](#compare-rules)。
- 关联对象：该应收账款、该内销合同。
- 不比较：内销合同未取得，或任一方主体未提供。

<a id="RK-06"></a>
**内销发票单价与合同单价不一致（RK-06）**｜提示｜值差异型

- 比较对象：内销发票与其关联内销合同。
- 触发条件：同一 VIN 在内销发票中的单价与在内销合同中的单价币种不同，或币种相同而金额不同。
- 差异项：每个单价不一致的 VIN。
- 关联对象：该应收账款、该内销合同、相关车辆。
- 不比较：内销合同未取得，或任一单价未提供。

<a id="RK-07"></a>
**基础交易合同日期存疑（RK-07）**｜预警｜条件型

- 比较对象：一笔应收账款。
- 触发条件：关联内销合同的合同日期晚于内销发票日期。
- 关联对象：该应收账款、该内销合同。
- 不比较：任一日期未提供，或内销合同未取得。

<a id="RK-08"></a>
**账款起算日不一致（RK-08）**｜提示｜条件型

- 比较对象：一笔应收账款。
- 触发条件：内销发票上的 ERP 账款起算日与 M3 平台计算的应收账款起算日不同。
- 关联对象：该应收账款。
- 不比较：ERP 账款起算日未提供，或应收账款起算日未确定。

<a id="RK-09"></a>
**账款到期日不一致（RK-09）**｜提示｜条件型

- 比较对象：一笔应收账款。
- 触发条件：内销发票上的 ERP 账款到期日与 M3 平台计算的应收账款到期日不同。
- 关联对象：该应收账款。
- 不比较：ERP 账款到期日未提供，或应收账款到期日未确定。
- RK-08、RK-09 只提示 ERP 值与平台计算值不同，应收账款的起算日、到期日始终以 M3 平台计算值为准。

<a id="RK-34"></a>
**平台企业名称与 ERP 名称不一致（RK-34）**｜阻断｜条件型

M2 在关联 ERP 企业时已使平台企业名称与 ERP 名称一致，正常情况下不会触发；本规则是兜底，防止应收账款对应到名称不符的企业。

- 比较对象：一个已关联 ERP 企业的平台企业（企业编号）及其关联的 ERP 企业。
- 触发条件：平台企业的企业名称、企业英文名称都与所关联 ERP 企业的 ERP 名称不一致。比较口径与 M2 [名称一致](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#erp-name)相同：
  - 不区分英文字母大小写；
  - 各类空白字符（半角空格、全角空格、不间断空格、制表符等）都按空格处理，忽略首尾空格，连续多个空格视为一个；
  - 除此之外的任何写法差异都算不一致，包括“Ltd”与“Limited”、标点的全角与半角（如“（）”与“()”）。
- 企业英文名称为空时按与 ERP 名称不一致计，只要企业名称也不一致即触发。
- 差异明细：企业编号、企业名称、企业英文名称、ERP 名称、ERP 企业标识。
- 关联对象：该平台企业作为债权人或债务人的全部应收账款，见[关联对象](#related-objects)。
- 不比较：平台企业没有关联 ERP 企业。
- 条件消除：企业名称或企业英文名称与 ERP 名称恢复一致，或平台企业取消了与该 ERP 企业的关联；差异现状变为“差异已消除”，阻断随之解除。
- 更正方式按 M2：线下联系开发人员处理。本规则为阻断类时没有人工处理，名称恢复一致后平台自动结束预警。

<a id="RK-36"></a>
**核心资料变更（RK-36）**｜阻断｜值差异型

M3 保留首次取得的原资料，再次取得的不同值不覆盖原资料，交给本规则判断，见 M3 [核心资料保护（F-M3-07）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-07)。

- 比较对象：一笔应收账款（内销发票）的核心资料。
- 触发条件：再次取得同一张内销发票时，以下任一项的取得值与 M3 原资料不同：内销发票日期、内销买方、币种、金额、账期、车辆明细中的 VIN 与内采单价（含车辆增减），共 6 项。
- 内销卖方不比较：按 M3，内销卖方是识别同一张内销发票的依据，卖方不同即视为另一张内销发票、形成新的应收账款；同一批车辆因此出现在两笔应收账款中时，由 [VIN 重复（RK-01）](#RK-01)判断。
- 差异项：每一项不同的资料项及其取得值；车辆差异按 VIN 逐辆区分为增加、减少、内采单价变化。
- 差异明细：逐项列出资料项、原值、取得值和取得时间；车辆差异逐车列出增加、减少或内采单价变化的 VIN。
- 关联对象：该应收账款、涉及的车辆。
- 不比较：原来缺失、后来补齐的项（按 M3 属于资料更新，直接成为原资料）；原资料中被 M3 [资料齐全且有效（F-M3-15）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-15)判为无效或无法折算的项（如账期为 0、金额或内采单价不大于 0、币种不是 USD 或 NGN），ERP 更正为有效值后按 M3 直接成为原资料；ERP 账款起算日、ERP 账款到期日（不是核心资料，由账款起算日不一致（RK-08）、账款到期日不一致（RK-09）判断）。
- 条件消除：最新一次取得的各项值都恢复为与原资料一致；或该内销发票被反审核、作废或删除，比较对象不再存在，见[生成、追加与去重](#item-rules)。
- 其他规则仍只比较原资料，不使用本规则中的取得值。
- 风险：原资料本身有误时，本规则的预警不会自动解除，只能在 ERP 中作废原发票、重开新发票（新发票按 M3 形成新的应收账款）；业务上需要临时放行时，只能在[风控规则配置（F-M8-19）](#F-M8-19)中调低本规则等级或停用本规则，调整须写明原因、留痕并通知全体运营。

<a id="F-M8-12"></a>
## 8. 回款与期限规则（F-M8-12）

适用范围：按应收账款到期日、回款与终端回款判断回款风险。没有用户操作。到期日、剩余天数、回款状态、已收款比率、终端销售进度、终端回款金额与终端回款进度均按 M3，取比对时 M3 的当前值。

验收参见：[回款与期限规则](./04-风控预警-验收.md#acc-f-m8-12)。

<a id="RK-10"></a>
**回款风险（RK-10）**｜预警｜条件型

- 比较对象：应收账款 · 回款。
- 触发条件，同时满足：
  - 剩余天数不超过临近到期天数（默认 7 天，含已到期）；
  - M3 [回款状态](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#repayment-status)不是“已收清”；
  - 终端回款进度未达到 100%，即终端回款金额低于应收账款金额。债务人还没有从终端客户收回足够的钱，到期付款有风险。
- 关联对象：该应收账款。
- 不比较：到期日未确定（属于平台限制，按 M3）。
- 终端回款进度达到或超过 100% 时不属于本规则，由[终端已回款或已售完、内销未收齐（RK-13）](#RK-13)提示；M3 终端回款进度为“无法计算”时，不判断这一项，只按前两项判断，避免因汇率缺失漏报。
- 已收清，或终端回款进度达到 100% 后，条件消除。

<a id="RK-11"></a>
**逾期（RK-11）**｜预警｜条件型

- 比较对象：应收账款 · 回款。
- 触发条件：到期状态为“已到期”，且回款状态不是“已收清”。
- 关联对象：该应收账款。

<a id="RK-12"></a>
**严重逾期（RK-12）**｜预警｜条件型

- 比较对象：应收账款 · 回款。
- 触发条件：已到期天数达到严重逾期天数（默认 30 天，即到期日后第 30 天起），且回款状态不是“已收清”。
- 关联对象：该应收账款。
- 回款风险、逾期、严重逾期是三条规则：进入下一阶段时生成下一条规则的预警，前一阶段的预警保留、照常更新，不合并。

<a id="RK-13"></a>
**终端已回款或已售完、内销未收齐（RK-13）**｜提示｜条件型

这是资金截留信号：债务人已从终端客户收回不少于本笔应收账款金额的外销款，或本笔应收账款的车辆已经全部卖出，但还没有付清本笔应收账款。

- 比较对象：应收账款 · 回款。
- 触发条件，同时满足：
  - 以下两项至少一项成立：
    - 终端已回款：终端回款进度达到 100%，即终端回款金额不低于应收账款金额；
    - 车辆已售完：本发票全部车辆都已外销出库，即 M3 终端销售进度达到 100%；
  - 回款状态不是“已收清”；
  - 当前日期减去达到日超过截留等待天数（默认 7 天）。达到日为上述两项中最早成立的那一项的日期：终端已回款为把计入终端回款金额的外销收款按收款日期累计、首次达到应收账款金额的那笔收款的收款日期；车辆已售完为最后一辆车的外销出库日期。
- 差异明细同时列出两项的当前情况（终端回款金额与终端回款进度、已外销出库车辆数与终端销售进度）及各自的达到日；两项都成立时也只有一条预警。
- 关联对象：该应收账款及其车辆。
- 不比较：两项都无法判断时（M3 终端回款进度为“无法计算”，且有车辆的外销出库日期未提供）；只有一项无法判断时，按另一项判断。
- 车辆已售完以外销出库为准，与 M3 终端销售进度的口径一致。
- 本规则为提示：不发消息、不计入待办，也不通知企业；条件消除（已收清）后自动解除。

<a id="RK-14"></a>
**内销收款主体不一致（RK-14）**｜预警｜值差异型

- 比较对象：应收账款 · 回款。
- 触发条件：某条回款记录的付款方与内销买方不一致，或收款方与内销卖方不一致。
- 关联对象：该应收账款、该回款记录。
- 不比较：付款方或收款方未提供。

<a id="F-M8-13"></a>
## 9. 价格与成本规则（F-M8-13）

适用范围：核对外采、内采、外销三级价格，以及合同成本与开票。没有用户操作。单价按 M5 [价格链](../M5-车辆履约/01-车辆履约-PRD.md#price-chain)取值，内采单价取合同价（标“合同价”）时照常比较。

验收参见：[价格与成本规则](./04-风控预警-验收.md#acc-f-m8-13)。

<a id="RK-15"></a>
**外采单价高于内采单价（RK-15）**｜预警｜条件型

- 比较对象：一个 VIN。
- 触发条件：内采单价不高于外采单价（按内采币种比较）。
- 关联对象：该车辆、其外采合同、内销合同、所在应收账款。
- 不比较：外采单价或内采单价未取得。

<a id="RK-16"></a>
**外销单价低于内采单价（RK-16）**｜预警｜条件型

即功能清单中的“外销单价低于合同单价”。

- 比较对象：一个 VIN · 一份外销合同。
- 触发条件：该外销合同中本车外销单价不高于本车内采单价（按内采币种比较）。
- 关联对象：该车辆、该外销合同、内销合同、所在应收账款。
- 不比较：没有外销合同，或内采单价未取得。
- 一辆车有多份外销合同时，每份分别比较。

<a id="RK-18"></a>
**形式发票金额合计大于合同金额（RK-18）**｜提示｜条件型

- 比较对象：一份内销合同，或一份外采合同。
- 触发条件：内销已开票金额高于内销合同金额；或外采已开票金额高于外采合同金额（按 M4 执行进度，按合同币种比较）。开票金额等于合同金额不提示。
- 关联对象：该合同；内销合同时另有其下全部应收账款。
- 不比较：任一发票金额无法折算。

<a id="F-M8-14"></a>
## 10. 采购与付款规则（F-M8-14）

适用范围：核对外采付款与外采发票。没有用户操作。外采发票、付款与已付款金额按 M4 [外采发票与付款（F-M4-06）](../M4-合同信息/01-合同信息-PRD.md#F-M4-06)。

验收参见：[采购与付款规则](./04-风控预警-验收.md#acc-f-m8-14)。

<a id="RK-20"></a>
**外采付款主体不一致（RK-20）**｜预警｜值差异型

- 比较对象：一份外采合同 · 采购公司或外采供应商。
- 触发条件：登记在该合同外采发票下的某笔外采付款，付款方与采购公司不一致，或收款方与外采供应商不一致。
- 关联对象：该外采合同、该付款记录、合同车辆所在应收账款。
- 不比较：付款方或收款方未提供。

<a id="RK-21"></a>
**外采付款金额高于外采形式发票金额（RK-21）**｜提示｜条件型

- 比较对象：一张外采发票。
- 触发条件：登记在本发票下的外采已付款金额高于外采发票金额（按发票币种比较）。付清（等于发票金额）不提示。
- 关联对象：该外采合同、本发票下的付款记录。

<a id="RK-22"></a>
**外采款项登记存疑（RK-22）**｜提示｜条件型

- 比较对象：一张外采发票。
- 触发条件：本发票车辆中已有外采交货日期的车辆，其本发票单价合计高于本发票下外采已付款金额，即已交货车辆的价款没有被付款覆盖（按发票币种比较）。
- 关联对象：该外采合同、已交货的车辆及其所在应收账款。
- 不比较：本发票车辆都没有外采交货日期。

<a id="F-M8-15"></a>
## 11. 物流与清关规则（F-M8-15）

适用范围：核对装船、清关与基础交易。没有用户操作。提单、清关单与车辆按 M12 [哪些资料属于这张提单](../M12-提单信息/01-提单信息-PRD.md#link-rules)按 VIN 对应；车辆与集装箱本期不关联，清关核对不使用集装箱号。

验收参见：[物流与清关规则](./04-风控预警-验收.md#acc-f-m8-15)。

<a id="RK-23"></a>
**基础交易货物流存疑（RK-23）**｜预警｜条件型

- 比较对象：一个 VIN。
- 触发条件：本车初始提单（装船日期最早的一张）的装船日期早于外采交货日期。
- 关联对象：该车辆、该提单、其外采合同、所在应收账款。
- 不比较：任一日期未提供。

<a id="RK-24"></a>
**清关主体与内销合同不一致（RK-24）**｜提示｜值差异型

- 比较对象：一张清关单 · 进口方或出口方。
- 触发条件：清关单所列某辆车，清关进口方与该车内销合同的买方不一致，或清关出口方与内销合同的卖方不一致。该车内销合同为该车所在内销发票关联的内销合同；尚未开票时为车辆明细含该车的内销合同（多份时取合同日期最近的一份）。
- 差异项：每个不一致的内销合同主体。
- 关联对象：该清关单所在提单、相关车辆及其所在应收账款。
- 不比较：进口方或出口方未提供，或该车没有内销合同。

<a id="RK-25"></a>
**清关船名航次与提单不一致（RK-25）**｜提示｜值差异型

- 比较对象：一张清关单。
- 触发条件：清关单所列某辆车，清关单的船名航次与该车所在任何一张提单的船名航次都不一致。转运车辆与其中任一张提单一致即视为一致。
- 差异项：每张不一致的提单。
- 关联对象：相关提单、相关车辆及其所在应收账款。
- 不比较：船名航次未提供，或该车没有已采信提单。

<a id="RK-26"></a>
**BL 信息与外部数据不一致（RK-26）**｜预警｜值差异型

- 比较对象：一张提单。
- 触发条件：提单的船公司、船名航次、装运港、卸货港、装船日期中，任一项与外部航程跟踪数据中本提单的对应值不一致。
- 差异项：每一项不一致的提单字段。
- 关联对象：该提单、提单车辆及其所在应收账款。
- 不比较：外部航程跟踪数据中没有本提单，或没有该项值。外部航程跟踪数据本期按 M12 口径取得，本规则本期生效；数据的覆盖与准确性由研发核验。

<a id="F-M8-16"></a>
## 12. 外销与终端回款规则（F-M8-16）

适用范围：核对外销出库与外销收款。没有用户操作。外销合同、出库与收款按 M4 [外销合同详情（F-M4-14）](../M4-合同信息/01-合同信息-PRD.md#F-M4-14)、M5 [外销段（F-M5-18）](../M5-车辆履约/01-车辆履约-PRD.md#F-M5-18)；零售合同的收款即本车收款，批售合同的收款属于整份合同。

验收参见：[外销与终端回款规则](./04-风控预警-验收.md#acc-f-m8-16)。

<a id="RK-28"></a>
**车辆销售款未全部收回（RK-28）**｜提示｜条件型

- 比较对象：一份外销合同。
- 触发条件（只看已外销出库的车辆，按外销合同币种比较）：
  - 零售：本车已外销出库，当前外销收款合计低于外销单价；
  - 批售：当前合同外销收款合计低于已外销出库车辆的外销单价合计。
- 关联对象：该外销合同、相关车辆及其所在应收账款。
- 不比较：没有已出库车辆（尚未出库的车辆收款不足属于正常的销售过程），或任一笔收款无法折算。
- 收齐后条件消除，提示自动解除。

<a id="RK-29"></a>
**外销收款方不一致（RK-29）**｜预警｜值差异型

- 比较对象：一份外销合同 · 外销卖方。
- 触发条件：某笔外销收款的收款方与外销卖方不一致，即外销款没有付到卖方。
- 关联对象：该外销合同、该收款记录、合同车辆及其所在应收账款。
- 不比较：收款方未提供。
- 付款方与外销客户不比较：终端客户由他人代付较常见，比较会大量误报。

<a id="F-M8-17"></a>
## 13. 保险规则（F-M8-17）

适用范围：核对保险金额、被保险人与车辆是否被多张保单覆盖。没有用户操作。保单覆盖车辆、保险覆盖率按 M13 [保单的采信与车辆对应（F-M13-01）](../M13-保单信息/01-保单信息-PRD.md#F-M13-01)、[保障核对（F-M13-04）](../M13-保单信息/01-保单信息-PRD.md#F-M13-04)；保单只关联提单，不关联内销合同。

验收参见：[保险规则](./04-风控预警-验收.md#acc-f-m8-17)。

<a id="RK-31"></a>
**保险未足额覆盖（RK-31）**｜提示｜条件型

- 比较对象：一张保单；或一笔应收账款。
- 触发条件：
  - 保单：M13 保险覆盖率低于 100%；
  - 应收账款：M3 [保险覆盖率](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-11)低于 100%，且应收账款起算日已确定（全部车辆已装船）。
- 关联对象：保单为该保单、其关联提单与覆盖车辆及其所在应收账款；应收账款为该应收账款及相关保单。
- 不比较：保险覆盖率无法计算（含车辆在多张保单中）；应收账款尚有车辆未装船。

<a id="RK-32"></a>
**保单信息与基础交易不一致（RK-32）**｜提示｜值差异型

- 比较对象：一张保单。
- 触发条件：保单的被保险人与覆盖车辆的内销合同卖方不一致。内销合同按车辆取，规则同[清关主体与内销合同不一致（RK-24）](#RK-24)；一张保单的车辆分属多份内销合同时逐份比较。
- 差异项：每个不一致的内销合同。
- 关联对象：该保单、相关提单与车辆及其所在应收账款。
- 不比较：被保险人未提供；该内销合同的价格条款不是 CIF 或 CIP（这两种条款由卖方投保，其他条款下被保险人不一定是卖方）。

<a id="RK-35"></a>
**同一车辆被多张保单覆盖（RK-35）**｜预警｜值差异型

一辆车只应被一张保单覆盖。出现多张时，M3 保险覆盖率为“无法计算”，保险未足额覆盖（RK-31）也不比较，资产的保障情况无法判断，需要运营人员核实。

- 比较对象：一个 VIN。
- 触发条件：本车经关联提单出现在两张及以上已采信保单中，包括同一张提单被多张保单关联；覆盖车辆按 M13 [保单的采信与车辆对应（F-M13-01）](../M13-保单信息/01-保单信息-PRD.md#F-M13-01)。
- 差异项：覆盖本车的每一张保单。
- 关联对象：本车、覆盖本车的各张保单及其关联提单、本车所在应收账款。
- 条件消除：只剩一张保单覆盖本车。
- 转运车辆两程分别投保也会触发，由运营人员核实后记录处理结果。

<a id="F-M8-18"></a>
## 14. 资金流水规则（F-M8-18）

适用范围：核对收付记录的交易流水号。没有用户操作。收付记录按 M14 [收付记录的采信与分类（F-M14-01）](../M14-资金收付/01-资金收付-PRD.md#F-M14-01)。

验收参见：[资金流水规则](./04-风控预警-验收.md#acc-f-m8-18)。

<a id="RK-33"></a>
**交易流水号重复（RK-33）**｜预警｜值差异型

- 比较对象：一个交易流水号。
- 触发条件：同一交易流水号出现在两条及以上不同的 ERP 已审核收付登记中，包括登记为不同收付类型；交易流水号按[比较口径](#compare-rules)不区分大小写、忽略空格。
- 差异项：每一条重复的收付登记。
- 关联对象：相关收付记录及其关联业务（应收账款、外采合同、外销合同）。
- 不属于重复：同一条收付登记对应多张关联单据并分配金额，按 M14 [关联业务（F-M14-04）](../M14-资金收付/01-资金收付-PRD.md#F-M14-04)属于正常拆分。
- 收付记录按 M14 的口径以 ERP 收付登记区分，同一交易流水号的多条登记是多条收付记录。

## 15. 风控预警列表与待办数量（F-M8-05）

适用角色与前提：可正常使用的运营人员。可查看全部风控预警。菜单“风控预警”按 M2 [运营端菜单与无权访问（F-OP-11）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-11)登记。

验收参见：[风控预警列表与待办数量](./04-风控预警-验收.md#acc-f-m8-05)。

列表以预警为单位，每行一条：

| 业务信息 | 含义 | 来源与缺失时 |
| --- | --- | --- |
| 预警编号 | 本条预警的编号 | 平台生成 |
| 等级 | 阻断／预警／提示，按规则的当前等级 | 按风控规则配置 |
| 规则 | 规则名称及编号，如“VIN 重复（RK-01）” | 按规则 |
| 比较对象 | 见各规则 | 平台生成 |
| 状态 | 未处理／已处理 | 平台记录 |
| 生成时间 | 预警生成的时间 | 平台记录 |
| 操作 | “查看”，进入该预警详情 | 每行都有 |

查找与筛选：

- 列表不展示关联应收账款，在详情中查看；按应收账款编号查找仍可找到其关联预警。
- 查找为单一输入框：输入内容与预警编号、应收账款编号、内销发票号、VIN、合同号、提单号、清关单号、保单号、交易流水号、企业编号任一项部分匹配，即列出关联对象或比较对象中含该编号的预警；匹配前去除输入内容的首尾空格，不区分英文大小写。
- 筛选：风控类别、等级、规则、规则启用状态、状态、差异现状、处理结果、生成时间区间。多个条件同时生效。
- 默认排序：未处理在前；未处理中阻断、预警、提示依次排列；同一组内按生成时间从新到旧，生成时间相同时按预警编号升序。

<a id="badge"></a>
待办数量：

- 左侧菜单“风控预警”上以小角标展示未处理的阻断类、预警类预警条数；提示类不计入。没有时不展示角标。
- 预警新建后加 1；预警类处理生效、阻断类自动结束、规则停用关闭后减 1；预警类差异已消除不改变数量。全体运营人员看到同一个数量。

边界与异常：

- 平台还没有任何预警时，展示“暂无风控预警”；查找或筛选无结果时，展示“没有符合条件的风控预警”并可清除条件。
- 列表不提供新增、编辑、删除和批量处理操作。
- 加载失败按[加载失败](#load-fail)处理。

## 16. 预警详情（F-M8-06）

适用角色与前提：可正常使用的运营人员，从风控预警列表、站内消息、资产数据各模块的关联预警入口或 M9 进入。

流程参见：[各入口与返回路径（图 M8-4）](./02-风控预警-流程图与状态机.md#fig-m8-4)。
验收参见：[预警详情](./04-风控预警-验收.md#acc-f-m8-06)。

<a id="detail-groups"></a>
### 16.1 详情包含的信息

详情顶部展示预警编号、等级、规则名称及编号、风控类别、状态、差异现状和生成时间；已处理时同时展示处理结果；阻断类差异仍存在时展示“正在阻止：{应收账款编号}的运营审核通过”；规则已停用时展示“规则已停用”。顶部内容在下方不再重复。

顶部之下包含以下信息类别，展示顺序与承载方式由 Hallmark 决定：

1. 比较对象与规则说明：比较对象、规则触发条件的业务说明、最近比对时间；用到折算时展示所用汇率编号、“1 USD = R NGN”与生效时间；用到风控参数时展示参数取值。
2. 差异明细：每个差异项展示比较的各项值、来源单据编号、取得时间，以及是否“处理后新增”；条件型规则展示最新一次比对的数值，之前各次在预警记录中查看。
3. 关联对象：关联应收账款（应收账款编号、内销发票号、债权人 → 债务人），以及关联的合同、车辆、提单、保单、收付记录编号。
4. 处理：预警类、提示类未处理时提供[记录处理](#process)入口；阻断类未处理时不提供，说明“阻断类预警不需人工处理，差异更正后自动解除”。已处理时展示处理结果、处理说明、依据附件、处理人和处理时间；由平台结束时展示处理结果（已自动解除或规则停用关闭）、处理人“平台”和时间，规则停用关闭另展示停用人和停用原因。
5. [预警记录](#history)。

<a id="source-entry"></a>
### 16.2 资料入口

差异明细和关联对象中的编号都可点击，按 M3 [单据编号跳转](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#doc-links)进入对应模块的详情，并可返回本预警：应收账款编号、内销发票号进入 M3；合同号、外采发票号进入 M4；VIN 进入 M5；提单号、清关单号进入 M12；保单号进入 M13；交易流水号进入 M14；企业编号进入 M2 [企业详情与入驻进度（F-EN-03）](../M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-EN-03)。

- 原件在所属模块中查看，本模块不另存、不另展示（处理时上传的依据附件除外）。
- 所属资料已被移除时，按所属模块规则展示“该内容不存在或已更新”，可返回本预警；本预警的差异明细保留生成和追加时的值。

边界与异常：

- 打开的预警编号不存在时，展示“该预警不存在”，可返回列表。
- 加载失败按[加载失败](#load-fail)处理。

## 17. 核实处理与预警记录（F-M8-07）

适用角色与前提：可正常使用的运营人员；预警状态为“未处理”，且规则的当前等级为预警或提示。阻断类预警和已处理的预警没有处理入口。

流程参见：[预警状态（图 M8-2）](./02-风控预警-流程图与状态机.md#fig-m8-2)、[记录处理的提交（图 M8-3）](./02-风控预警-流程图与状态机.md#fig-m8-3)。
验收参见：[核实处理与预警记录](./04-风控预警-验收.md#acc-f-m8-07)。

<a id="process"></a>
### 17.1 记录处理

运营人员针对本条预警当前全部差异项记录一次处理：

| 业务信息 | 类型与取值 | 必填与默认 | 校验与失败结果 |
| --- | --- | --- | --- |
| 处理结果 | 单选：核实无风险／确认有风险 | 必填，无默认 | 未选择时不能提交并提示 |
| 处理说明 | 文本，说明核实过程、依据及结论，例如是否为同一法定主体、差异原因 | 必填，无默认 | 去除首尾空格后为 1—500 字；为空或超长时不能提交并提示 |
| 依据附件 | 附件 | 选填 | PDF、JPG、PNG；最多 5 个；单个不超过 20 MB；不符合时该文件不能加入并提示原因 |

- 提交前须让运营人员确认：处理结果提交后不能修改或撤回。
- 差异现状为“差异已消除”时同样可以记录处理。

结果：

- 提交成功后预警状态变为“已处理”，记录处理结果、处理说明、依据附件、处理人和处理时间；预警类的待办数量减 1。
- 处理不改变任何资料、金额和业务状态。
- 处理结果不可编辑、不可删除、不可撤回。

边界与异常：

- 两名运营人员同时处理同一条预警时，先提交者生效；后提交者提示“该预警已被他人处理，请刷新后查看”，本次内容不保存。
- 打开处理后、提交前，本条预警追加了新的差异项、已自动解除，或其规则被调为阻断、被停用时，本次提交不生效，提示“该预警已有变化，请刷新后查看”，保留已填写内容。
- 提交失败时保留已填写内容，提示失败并可重新提交。
- 运营人员在填写过程中账号被锁定或登录失效时，提交不生效，按 M2 规则处理。

<a id="history"></a>
### 17.2 预警记录

每条预警保留从生成到处理的全部经过，按时间从新到旧展示，不可编辑、不可删除：

| 记录事件 | 记录内容 |
| --- | --- |
| 生成预警 | 生成时间、当时的差异项与数值 |

<a id="rule-level"></a>
### 20.2 调整等级

调整时填写：

| 业务信息 | 类型与取值 | 必填与默认 | 校验与失败结果 |
| --- | --- | --- | --- |
| 新等级 | 单选：阻断／预警／提示 | 必填，默认为当前等级 | 与当前等级相同时不能提交，提示“等级没有变化” |
| 调整原因 | 文本 | 必填，无默认 | 去除首尾空格后为 1—500 字；为空或超长时不能提交并提示 |

确认时展示：规则名称及编号、当前等级 → 新等级、本规则当前未处理与差异仍存在的预警条数；新旧等级之一为阻断时，另展示调整后将开始或停止被阻断的“待运营审核”申请笔数；以及说明“调整立即生效，作用于本规则已有和以后的全部预警”。

结果：

- 提交后立即生效：本规则全部预警（含已处理的）按新等级执行，包括列表与详情中的等级、是否计入待办、是否阻断，以及提供给其他模块和 M9 的等级。
- 调整为提示时，本规则中差异已消除、仍未处理的预警随即自动解除（处理结果“已自动解除”）。
- 调整为阻断或预警时，已自动解除的预警保持已处理，不恢复；未处理的预警开始计入待办。
- 调整为阻断时，本规则未处理的预警不再提供记录处理入口；其中差异已消除的随即自动解除。运营人员已处理的预警保持原处理结果，差异仍存在时照常阻断。
- 由阻断调为预警或提示时，本规则未处理的预警提供记录处理入口。
- 调整不补发也不撤回任何“新的风控预警（M8-NT01）”；之后新建的预警按新等级决定是否发送。
- 每条受影响预警的[预警记录](#history)增加一条“等级调整”：时间、调整人、原等级、新等级、调整原因。
- 已经完成的审核通过不受影响；审核时的预警情况（含当时的等级）由 M9 留存。

<a id="rule-toggle"></a>
### 20.3 停用与启用

停用、启用都需填写调整原因（规则同[调整等级](#rule-level)）。停用确认时展示“将关闭本规则 N 条未处理预警”，以及差异仍存在的预警条数；启用确认时展示本规则当前差异仍存在的预警条数。

停用后：

- 本规则不再比对，不再新建预警、追加差异或更新差异现状。
- 本规则全部未处理的预警由平台关闭：预警状态“已处理”，处理结果“规则停用关闭”，预警记录增加一条平台处理记录（时间、处理人“平台”、停用人、停用原因）；已处理的预警不变。
- 本规则的全部预警保留，可以查看，详情标“规则已停用”；它们不计入任何待办数量和其他模块的关联预警条数，不阻止审核通过，也不参与 M9 的判断。

启用后：

- 平台立即按本规则对全部已采信资料重新比对一次，之后按[什么时候比对](#compare-when)照常比对。
- 这次比对中，只存在于“规则停用关闭”预警里的差异项（停用前已有、启用时仍然存在），按新差异项新建预警，并按当前等级决定是否发送[新的风控预警（M8-NT01）](./03-风控预警-消息通知.md#M8-NT01)；同一比较对象另有运营人员处理过的预警且包含该差异项时，按[生成、追加与去重](#item-rules)追加到那条预警。
- 停用时关闭的预警不恢复为未处理，按普通已处理预警计入各模块的已处理条数并提供给 M9，详情不再标“规则已停用”，保留规则停用关闭的记录；运营人员处理过的预警恢复按当前等级产生作用（差异仍存在的阻断类照常阻断）。比对中仍存在或新出现的差异按[生成、追加与去重](#item-rules)与[差异现状](#diff-state)处理，新建预警时按当前等级决定是否发消息。

### 20.5 配置记录与异常

- 每次生效的调整都记录：时间、调整人、调整项（等级／启用状态／风控参数）、调整前、调整后、调整原因；在规则详情中按时间从新到旧展示，不可编辑、不可删除。
- 两名运营人员同时调整同一条规则时，先提交者生效；后提交者提示“该规则已被他人调整，请刷新后查看”，本次内容不保存。

- 列表或详情加载失败按[加载失败](#load-fail)处理。
- 本期任何可正常使用的运营人员都可以调整，不设审批；调整原因必填、每次调整留痕并通知全体运营，作为事后控制。

## 21. 状态组合

一条预警的预警状态、差异现状与等级是三个独立维度。下表写清各组合下运营人员能做什么，以及对运营审核的作用；M9 审核说明是否必填按 M9 [确认与审核说明](../M9-运营审核/01-运营审核-PRD.md#review-confirm)。

| 等级 | 预警状态 | 差异现状 | 能否记录处理 | 计入菜单待办 | 是否阻止发起申请与运营审核通过 |
| --- | --- | --- | --- | --- | --- |
| 阻断 | 未处理 | 差异仍存在 | 不可以 | 计入 | 阻止 |
| 阻断 | 已处理（已自动解除） | 差异已消除 | 不可以 | 不计入 | 不阻止 |
| 阻断 | 已处理（调为阻断前由运营人员处理） | 差异仍存在 | 不可以 | 不计入 | 阻止 |
| 阻断 | 已处理（调为阻断前由运营人员处理） | 差异已消除 | 不可以 | 不计入 | 不阻止 |
| 预警 | 未处理 | 差异仍存在 | 可以 | 计入 | 不阻止 |
| 预警 | 未处理 | 差异已消除 | 可以 | 计入 | 不阻止 |
| 预警 | 已处理 | 差异仍存在 | 不可以 | 不计入 | 不阻止 |
| 预警 | 已处理 | 差异已消除 | 不可以 | 不计入 | 不阻止 |
| 提示 | 未处理 | 差异仍存在 | 可以 | 不计入 | 不阻止 |
| 提示 | 已处理 | 差异仍存在 | 不可以 | 不计入 | 不阻止 |
| 提示 | 已处理 | 差异已消除 | 不可以 | 不计入 | 不阻止 |

- 表中等级为规则的当前等级。规则已停用时，其预警都已处理（未处理的在停用时关闭），不计入待办、不阻止任何业务、不参与 M9 的判断。
- 阻断类、提示类差异已消除时自动变为已处理，不会出现“未处理、差异已消除”。
- 运营人员处理过的预警在差异再次出现或追加“处理后新增”记录时，状态和处理结果不变；由平台结束的预警遇到同一差异再次出现时，新建预警。

## 22. 待确认事项与依赖

本模块当前没有待确认事项。

依赖：

- 应收账款（M3）：应收账款金额与币种、到期日与到期状态、剩余天数、回款状态、已收款比率、终端销售进度、终端回款金额与终端回款进度、保险覆盖率、ERP 账款起算日与到期日、回款记录、核心资料原资料，以及再次取得同一张内销发票时各核心资料项的取得值与取得时间（含恢复为与原资料一致的情况，用于判断核心资料变更（RK-36）的差异是否消除）；展示本模块提供的关联预警。
- 合同信息（M4）：三类合同的主体、金额、车辆明细、价格条款，内销与外采的已开票金额，外采发票及付款、外销收款与出库；展示关联预警。
- 车辆履约（M5）：外采单价、内采单价、外销单价（价格链），外采交货日期，外销出库；展示关联预警。
- 提单信息（M12）：提单车辆、装船日期、船公司、船名航次、港口，清关单的进口方、出口方、船名航次与车辆，外部航程跟踪数据；展示关联预警。
- 保单信息（M13）：保单覆盖车辆（含一辆车所在的保单数）、被保险人、保险覆盖率；展示关联预警。
- 资金收付（M14）：收付记录的付款方、收款方、金额、关联业务与交易流水号；展示关联预警。
- 汇率管理（M11）：比对时的当前汇率（汇率值、生效时间、汇率编号）及“无可用汇率”结果，按[对外提供的汇率口径](../M11-汇率管理/01-汇率管理-PRD.md#FX-05)。
- 应收查看与确权申请（M7a）：申请状态、当次依据（用于在融资资产的车辆占用）；按[阻断的作用](#blocking)使用阻断结果判断能否发起申请。
- 运营审核（M9）：按[与运营审核的关系](#m9-relation)使用关联预警和阻断结果；提供审核提交的上链中、上链成功、上链失败结果（用于在融资资产的车辆占用）。
- 消息中心（M10）：承接本模块的[新的风控预警（M8-NT01）](./03-风控预警-消息通知.md#M8-NT01)与[风控规则已调整（M8-NT02）](./03-风控预警-消息通知.md#M8-NT02)，按[来源接入要求（MSG-06）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-06)。
- M2：运营账号状态、界面语言与时区、无权访问的处理；运营端菜单表登记“风控预警”“风控规则”“三方数据源”；平台企业的企业编号、企业名称、企业英文名称，关联的 ERP 企业（ERP 名称、ERP 企业标识）及企业详情入口，用于平台企业名称与 ERP 名称不一致（RK-34）。
- ERP：各项资料通过资产数据各模块采信，取得方式由研发决定；日期型规则的判定须在日期变化后 5 分钟内完成（见[什么时候比对](#compare-when)），其他比对的执行时效由研发确定，消息送达时效按 M10。
