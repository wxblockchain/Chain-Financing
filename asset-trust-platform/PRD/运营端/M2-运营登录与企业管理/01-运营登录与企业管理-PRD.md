## 1. 模块是什么

运营管理人员用开发人员分配的邮箱账号登录运营端，首次登录先改掉初始密码，之后在企业管理中邀请企业：填写企业身份与联系人资料、勾选债权人／债务人业务角色、为该企业唯一的企业用户分配登录邮箱，平台随机生成初始密码并发送邀请邮件。企业用户在企业端完成首次改密、绑定钱包、完善并提交资料（由[企业登录与首次入驻（M1）](#neighbors)定义）后，运营在企业详情中看到入驻结果；此后运营维护企业资料、增加业务角色；企业用户完成首次改密之前，运营可以重发邀请。企业用户忘记密码时在企业端用登录邮箱验证码自助找回，也可以在企业端修改自己的登录邮箱；企业端的临时锁定、自助找回和改邮箱都由企业登录与首次入驻（M1）处理，运营端不展示、不接收通知。企业完成资料提交后即为已认证，供本平台及代币发行平台等使用本平台企业身份的平台判断认证资格。运营在新增或编辑企业时，为企业关联 ERP 企业；应收账款按内销发票上的内销卖方、内销买方所属的 ERP 企业，对应到关联了它的平台企业。

基本原则：

- 运营账号由开发人员分配，产品内没有运营账号管理【确认】。所有运营账号同为“运营管理员”角色、权限相同【沿用】。
- 一个企业只邀请一次、只有一个企业用户【确认】。重复判断按企业身份（注册国家／地区＋企业登记号码），换一个登录邮箱不能把同一企业当成新企业【确认】。
- 债权人、债务人角色可以多选，由同一个企业用户使用；多选不产生第二个用户【确认】。角色只决定企业端开放哪些业务菜单，不改变企业在具体交易中的身份【确认】。
- 重发邀请作用于原账号：不新建用户，不清空、不解绑、不更换已绑定的钱包【确认】。企业管理不提供源资产修改或钱包改址【确认】。
- 企业编号是本平台为企业生成的唯一标识，生成后不随企业名称、企业身份、联系人、登录邮箱等任何资料的变化而变化【确认】。
- 本期企业账号不设停用、启用；业务角色只能增加、不能取消【确认】。
- 平台企业与应收账款的对应只看运营设置的 ERP 企业关联：一个平台企业可以关联多个 ERP 企业，一个 ERP 企业只能关联一个平台企业；没有关联 ERP 企业的平台企业，不与任何应收账款对应【确认】。
- 初始密码由平台随机生成，只通过邀请邮件发给企业登录邮箱，运营在任何页面都看不到【沿用】。
- 企业用户一旦完成首次改密，运营端不再能重置其密码；企业用户忘记密码时在企业端通过登录邮箱验证码自助设置新密码，运营端不接收通知、不展示自助找回的状态【确认】。
- 运营看得到全部企业，但企业角色和运营操作权分开：运营的全量查看不等于可以替企业办理确权、修改源资产或越过审核【确认】。

**一个完整的例子。** 运营在企业管理中邀请“Carloha Nigeria Ltd”：注册国家／地区选尼日利亚，企业登记号码填 RC 123456，填写联系人、联系电话和联系邮箱，勾选“债务人”，登录邮箱填 finance@carloha-ng.example。提交成功后，平台生成企业编号和随机初始密码，建立企业档案和唯一企业用户（账号待首登改密、入驻进度待首次改密），并向登录邮箱发送企业邀请邮件。企业用户登录企业端、改密、绑定钱包、提交资料后，运营在企业详情中看到入驻进度为“已完成入驻”、钱包地址与绑定时间。之后企业用户忘记密码，在企业端用登录邮箱验证码自助设置了新密码；运营端不收到通知，企业详情也不出现这次找回，钱包和资料不变。邀请时 ERP 已同步过这家企业作为内销买方的内销发票，运营在邀请表单中选择了 ERP 企业“CARLOHA NIGERIA LIMITED”，保存后这些内销发票形成的应收账款都以本企业为债务人。另一名运营试图再次邀请“RC 123456”，平台拦下并指向已有的这家企业。

### 1.2 本期不做

- 运营账号的界面化管理：新增运营账号、为运营重新分配初始密码，都由开发人员在产品外完成【确认】。
- 运营账号、企业账号的停用与启用【确认】。
- 取消企业的业务角色【确认】。
- 运营角色细分：运营只有“运营管理员”一个角色【沿用】。
- 运营本人修改登录邮箱：本期需求未要求，运营登录邮箱需更换时由开发人员在产品外处理。
- 运营端验证码登录、钱包登录、第三方登录、“记住我”，以及动态口令等附加登录校验：运营端只用邮箱＋密码，配合临时锁定、发码前人机校验、登录有效期与无操作登出【确认】。
- 企业自主注册；同一企业第二次邀请；为企业新增第二个用户【确认】。
- 删除企业或企业用户。
- 企业用户完成首次改密后由运营重置密码；运营接收或查看企业用户自助找回密码的通知与状态【确认】。
- 运营端展示企业账号的临时锁定、提前解除企业账号锁定；运营端感知企业用户修改登录邮箱【确认】。
- 运营修改企业登录邮箱、查看或代设密码；登录邮箱填错时的处理见[登录邮箱填错的更正](#login-email-fix)。
- 解绑、更换钱包地址，或从多个钱包中另选接收钱包；旧钱包变更申请与运营改址审核不恢复【确认】。
- 运营代企业填写入驻资料、代企业提交入驻，或增设入驻资料审批环节【确认】。
- 企业用户登录运营端，或运营账号登录企业端：两类账号互不相通。
- 账号锁定与解除的通知；登录成功或失败的通知。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 运营端 | 运营管理人员使用的端，与企业用户使用的企业端是两套入口和两套账号 |
| 运营账号 | 登录运营端的账号，以登录邮箱识别，由开发人员分配，可以有多个 |
| 企业 | 由运营邀请进入本平台的法人主体，以企业编号识别，企业编号生成后不变；同一注册国家／地区下同一企业登记号码只对应一家企业 |
| 企业用户 | 企业唯一的平台使用者账号，以登录邮箱登录企业端；邀请时与企业一起建立，此后不新增、不替换 |
| 企业账号 | 企业用户的登录账号。本册的重发邀请作用于它；其登录、锁定、找回密码和修改登录邮箱由 M1 定义 |
| 认证状态 | 企业是否已认证：企业完成资料提交（入驻进度为已完成入驻）即为已认证，其余为未认证；由入驻进度得出，不是单独审核的结果 |
| 业务角色 | 企业在本平台可使用的业务范围：债权人、债务人，可多选。只决定企业端开放哪些业务菜单 |
| 入驻进度 | 企业用户完成首次改密、绑定钱包、提交资料三步的进展，事实由企业端产生，运营只查看 |
| 初始密码 | 不是由账号使用者本人设置的密码：开发人员为运营账号分配的密码，以及平台为企业账号随机生成的密码（邀请、重发邀请时）。只能用来完成首次登录强制改密 |
| 临时锁定 | 账号连续 5 次输错密码后被自动暂停登录一段时间（第一次 15 分钟，第二次 30 分钟，之后每次 60 分钟），用于防止密码被猜中；到期自动解除，没有提前解除的办法。锁定不是停用，不改变密码、钱包、资料和认证状态。运营账号的锁定见[连续失败与临时锁定（F-OP-06）](#F-OP-06)；企业账号的锁定由 M1 定义，运营端不展示【确认】 |
| 原目标 | 未登录时想打开的运营端页面，例如从邮件或消息链接打开的一条记录 |
| ERP 企业 | 在 ERP 同步到本平台的单据中作为交易主体出现过的企业，以 ERP 企业标识识别、以 ERP 名称展示；不是本平台的企业，也没有本平台账号 |
| 关联 ERP 企业 | 运营为平台企业指定它在 ERP 中对应的一个或多个 ERP 企业，用于把应收账款对应到平台企业 |

## 3. 运营账号与角色（F-OP-01）

适用角色与前提：运营管理人员。

- 运营账号由开发人员分配登录邮箱、姓名和初始密码，可以有多个【确认】。
- 运营只有“运营管理员”一个角色，每个运营账号权限相同【沿用】；角色在账号建立时确定，产品内不能更改。
- 运营账号只能登录运营端，企业账号只能登录企业端；同一邮箱不能同时作为运营账号和企业账号的登录邮箱，见[登录邮箱的唯一性](#email-unique)。

<a id="op-account-info"></a>
### 3.1 运营账号信息

以下信息对本人只读；密码、界面语言和时区按对应功能维护。

| 业务信息 | 含义 | 来源与可编辑性 |
| --- | --- | --- |
| 登录邮箱 | 登录账号；不区分大小写 | 开发人员分配；产品内不能修改 |
| 姓名 | 识别是谁在操作；出现在[企业操作记录（F-EN-09）](#F-EN-09)等操作人位置 | 开发人员配置；产品内不能修改 |
| 角色 | 运营管理员 | 建立时确定，不能修改 |
| 账号状态 | 见[运营账号状态](#op-account-status) | 由首次改密、本人找回、锁定及开发人员操作改变；产品内不能手工修改 |
| 界面语言 | 简体中文或 English | 本人可修改，见[界面语言与时区（F-OP-10）](#F-OP-10) |
| 时区 | 决定运营端时间的展示 | 本人可修改，见[界面语言与时区（F-OP-10）](#F-OP-10) |
| 最近登录时间 | 最近一次登录成功的时间 | 系统记录，按本人时区展示并标明时区 |
| 创建时间 | 账号建立的时间 | 系统记录，按本人时区展示并标明时区 |

<a id="op-account-status"></a>
### 3.2 运营账号状态

| 状态 | 含义 |
| --- | --- |
| 待首登改密 | 新分配的账号，或开发人员重新分配初始密码后的账号；完成首次登录强制改密或本人自助找回成功后变为正常 |
| 正常 | 可以使用运营端 |
| 锁定 | 连续输错密码达到次数后的临时状态，到期自动回到锁定前的状态，见[连续失败与临时锁定（F-OP-06）](#F-OP-06) |

各状态下能做什么：

| 能力 | 待首登改密 | 正常 | 锁定 |
| --- | --- | --- | --- |
| 登录 | 登录后只能进入首次登录强制改密 | 登录后进入运营端 | 不能登录；输入正确邮箱和密码后才看到锁定提示与剩余时间 |
| 账户设置与业务菜单 | 不能，只能切换界面语言或退出 | 可以 | 不能 |
| 自助找回密码 | 可以；成功后完成首次密码设置并变为正常 | 可以，成功后保持正常 | 可发码；正确验证后告知锁定，不能完成重置 |

- 锁定时，该账号在所有设备和标签页上的登录立即结束。
- 开发人员重新分配初始密码时，平台不发送邮件或消息，新初始密码由线下告知；平台按[安全记录](#security-records)留存一条记录。
- 运营账号状态的变化见[运营账号状态机](./02-运营登录与企业管理-流程图与状态机.md#state-1)。

<a id="password-rules"></a>
### 3.3 设置密码的共同规则

适用于[首次登录强制改密（F-OP-04）](#F-OP-04)、[修改密码（F-OP-09）](#F-OP-09)、[自助找回密码（F-OP-03）](#F-OP-03)。平台为企业账号随机生成的初始密码，以及开发人员分配的运营初始密码，同样须满足长度、组成和空格规则【沿用】。

**密码条件**：输入新密码时只列出以下两条，分两行展示，输入过程中实时标明是否满足【确认】。

| 条件 | 要求 |
| --- | --- |
| 长度 | 8～20 个字符 |
| 组成 | 至少包含 1 个英文字母和 1 个数字 |

**输入校验**：以下情况不列为条件，出现时直接在对应输入框下方说明，改正后说明消失【确认】。

| 情况 | 在哪个输入框下说明 |
| --- | --- |
| 新密码中间有空格（前后的空格自动去除，不提示） | 新密码 |
| 新密码与该账号当前密码相同 | 新密码 |
| 新密码与本账号最近一次被设置的初始密码相同 | 新密码 |
| 两次输入不一致 | 确认新密码 |

- 两条条件都满足且没有输入校验问题时才能提交；不展示密码强弱分档。
- 用户已确认的呈现约束：两条条件的文字可小于正文字号；具体样式由设计确定。
- 所有密码输入都可以由本人通过眼睛图标切换显示或隐藏【沿用】。
- 提交时由平台再次校验，不满足时不改变原密码，并说明哪一项不满足。
- 除本人在输入时主动切换显示外，界面、通知邮件和日志中都不出现明文密码；[企业邀请邮件（NT-EN-01）](./03-运营登录与企业管理-消息通知.md#NT-EN-01)中的初始密码是例外。

<a id="email-unique"></a>
### 3.4 登录邮箱的唯一性

- 登录邮箱去首尾空格、不区分大小写、符合邮箱格式、最长 254 个字符。
- 同一时刻，本平台全部运营账号和企业账号的登录邮箱互不重复，包括企业用户在企业端修改后的登录邮箱【确认】。
- 只按当前是否被其他账号使用判断，不保留、不检验历史：某个账号的登录邮箱改为新邮箱后，旧邮箱立即释放，可用于邀请新企业，也可被其他账号改用；原账号在旧邮箱未被他人使用前，也可以改回【确认】。
- 旧邮箱释放后不再能登录原账号，也不再接收原账号的验证码或通知。
- 联系邮箱与登录邮箱用途分开：联系邮箱只用于业务联系，不能登录、不接收验证码或初始密码；两者可以填写同一个地址【确认】。

<a id="security-records"></a>
### 3.5 安全记录

- 以下事件留存安全记录，可追溯到账号、时间与结果：运营账号登录成功与失败（含失败原因）、锁定与解除、密码变更（首次改密、自助找回、本人修改）、开发人员重新分配初始密码、越权访问被拒绝；运营对企业账号的重发邀请【沿用】。
- 安全记录长期保留，不设保留期限，不自动删除【沿用】。
- 本期不向运营提供安全记录的查询或导出入口，由内部支持人员排查使用【沿用】。运营对企业的操作另在[企业操作记录（F-EN-09）](#F-EN-09)中可见。
- 安全记录中不出现密码或验证码明文。

## 4. 运营登录与退出

<a id="F-OP-02"></a>
### 4.1 邮箱与密码登录（F-OP-02）

适用角色与前提：未登录的访问者。

- 运营端只有一个登录入口，输入登录邮箱和密码登录；邮箱前后的空格自动去除、不区分大小写【确认】。
- 登录不设动态口令或其他附加校验；账号安全由[连续失败与临时锁定（F-OP-06）](#F-OP-06)、[发码前人机校验](#captcha)和[登录有效期、无操作登出与退出（F-OP-07）](#F-OP-07)保障【确认】。
- 登录入口提供[忘记密码（F-OP-03）](#F-OP-03)，没有注册、验证码登录、钱包登录或“记住我”。
- 未登录时访问运营端受保护页面，先到登录入口并记住原目标，见[登录后进入与返回原目标（F-OP-05）](#F-OP-05)。

| 情况 | 用户看到的结果 |
| --- | --- |
| 邮箱或密码为空 | 不能提交，指出未填写的一项 |
| 邮箱不是运营账号（含企业账号的登录邮箱），或密码错误 | 统一说明“邮箱或密码错误”；几种情况的提示、表现和响应快慢都不能区分。账号未锁定时，密码错误计入连续失败次数 |
| 邮箱和密码正确，账号待首登改密 | 进入[首次登录强制改密（F-OP-04）](#F-OP-04)，不进入任何业务页面 |
| 邮箱和密码正确，账号正常 | 登录成功，按[登录后进入与返回原目标（F-OP-05）](#F-OP-05)进入 |
| 邮箱和密码正确，账号锁定中 | 不能登录；说明账号已临时锁定和剩余时间，到期后可直接重新登录 |
| 网络或服务异常 | 说明暂时无法登录、请重试；已输入的邮箱保留，不计入失败次数 |

- 登录提交期间不能重复提交。
- 首次登录成功时，按浏览器推断写入时区偏好，见[界面语言与时区（F-OP-10）](#F-OP-10)。
- 登录结果按[安全记录](#security-records)留存。

流程参见：[运营登录与首次改密（图 1）](./02-运营登录与企业管理-流程图与状态机.md#fig-1)。

<a id="F-OP-03"></a>
### 4.2 自助找回密码（F-OP-03）

适用角色与前提：已分配运营账号的本人，从登录入口选择忘记密码【沿用】。

- 输入当前登录邮箱（去首尾空格、不区分大小写、最长 254 个字符），获取验证码前须先通过[发码前人机校验](#captcha)，再满足[验证码参数](#code-params)中的重发间隔与发送限额；只向运营账号当前登录邮箱发送[运营找回密码验证码（NT-OP-01）](./03-运营登录与企业管理-消息通知.md#NT-OP-01)。
- 邮箱不是运营账号（含企业账号的登录邮箱）时，反馈与有效邮箱相同，不透露邮箱是否存在；真实发送失败时说明暂不能发送、可重试，不虚报发送成功。
- 输入收到的验证码，通过后输入两次新密码，遵守[设置密码的共同规则](#password-rules)。
- 验证码通过后取得的找回资格 10 分钟内有效；超时未提交成功的须重新获取并验证验证码，原密码不变【沿用】。
- 正确验证后才检查账号锁定：锁定中告知剩余时间，不能完成重置，不提前解锁。
- 提交时重新检查账号状态和本次验证资格；资格失效须重新开始，原密码不被覆盖。
- 成功后新密码生效、原密码与初始密码失效；平台发送[运营密码变更通知（NT-OP-02）](./03-运营登录与企业管理-消息通知.md#NT-OP-02)，随后该账号全部登录及未使用验证码结束，回到登录入口用新密码重新登录，不自动登录。原来待首登改密的账号视为已完成首次密码设置，变为正常。
- 取消、离开、校验失败或保存失败时密码不变，不结束已有登录，不发送通知。

<a id="verification-rules"></a>
#### 验证码的共同规则

- 验证码只能用于本账号本次找回；同一账号仅最新成功发送的验证码有效，重新发送成功使旧码作废。
- 使用成功、过期或累计输错达到上限后不可再次使用；错误、过期、已使用、已作废均说明验证码无效，可重试或重新获取。
- 密码变更成功使该账号未用验证码全部作废。
- 码值只在本人邮箱中提供，不出现在公开提示或日志中；验证码有效不等于已登录。

<a id="code-params"></a>
**验证码参数**【沿用】

| 项目 | 要求 |
| --- | --- |
| 位数与输入 | 6 位数字；粘贴时自动去除空格和连字符 |
| 有效期 | 自发送成功起 10 分钟 |
| 单个验证码错误上限 | 同一个验证码累计输错 5 次即作废 |
| 重发间隔 | 同一邮箱两次发送至少间隔 60 秒；间隔未满时显示剩余秒数，刷新页面不会重置 |
| 同一邮箱发送限额 | 24 小时内最多 10 次；用完时说明大约还需等待多久 |
| 同一网络地址（IP）发送限额 | 每小时最多 20 次；用完时说明稍后再试 |

- 邮件真实发送失败时可立即重试 1 次，这次重试不计入额度、不受重发间隔限制，但仍须重新通过人机校验。
- 等待与超限提示对任何邮箱都相同，不因该邮箱是否为运营账号而不同。
- 验证码输错只计入该验证码自己的错误次数，不计入[连续失败与临时锁定（F-OP-06）](#F-OP-06)。

<a id="captcha"></a>
#### 发码前人机校验【沿用】

人机校验指滑块拼图这一类校验，具体呈现由设计确定。

- 每次获取、重发验证码（含发送失败后的立即重试）都先完成人机校验，再检查重发间隔与发送限额，全部通过才发码；绕过界面直接请求发码同样须满足。

| 情况 | 用户看到的结果 |
| --- | --- |
| 人机校验通过 | 说明验证通过，随后检查重发间隔与发送限额；通过不等于验证码已发出 |
| 单次未通过 | 说明验证失败并自动更换题目，可以立即再试，不发码 |
| 连续未通过 3 次 | 还可以主动更换题目；不发码 |
| 连续未通过 5 次 | 进入 60 秒冷却，显示剩余时间；刷新或重新发起都不能绕过；不发码 |
| 关闭或取消 | 不发码，回到原流程，已填写的邮箱保留 |
| 题目加载失败 | 说明加载失败、可以重试；不发码 |

- 一次通过只用于随后一次发送，须是同一目标邮箱、同一请求来源，2 分钟内有效。
- 人机校验的失败与冷却不计入密码连续失败次数，也不计入验证码错误次数；其结果和提示对任何邮箱都相同。

流程参见：[运营自助找回密码（图 2）](./02-运营登录与企业管理-流程图与状态机.md#fig-2)。

<a id="F-OP-04"></a>
### 4.3 首次登录强制改密（F-OP-04）

适用角色与前提：邮箱和密码正确、账号待首登改密的运营管理人员。

- 用初始密码登录时必须先设置新密码，不能跳过或稍后再改【确认】。
- 改密前只能做三件事：设置新密码、切换界面语言、退出登录；其他页面和操作都不可用，绕过界面直接访问同样被拒绝。
- 只需输入两次新密码，不需要再输入初始密码；新密码须符合[设置密码的共同规则](#password-rules)。
- 设置成功后账号变为正常、初始密码失效；平台发送[运营密码变更通知（NT-OP-02）](./03-运营登录与企业管理-消息通知.md#NT-OP-02)，随后该账号全部登录（包括当前这次）立即结束，回到登录入口并说明“密码已修改，请用新密码重新登录”；原目标在同一标签页内保留。
- 设置失败时账号仍为待首登改密，初始密码仍可使用，可以重试；不发送通知。
- 改密期间登录到期或无操作登出时，回到登录入口，账号仍为待首登改密。

流程参见：[运营登录与首次改密（图 1）](./02-运营登录与企业管理-流程图与状态机.md#fig-1)。

<a id="F-OP-05"></a>
### 4.4 登录后进入与返回原目标（F-OP-05）

适用角色与前提：登录成功、账号正常的运营管理人员。

- 有原目标时回到原目标；回到之前按当前账号重新判断权限，无权访问时按[运营端菜单与无权访问（F-OP-11）](#F-OP-11)处理。
- 没有原目标或原目标不在运营端范围内时，进入默认页面（具体页面由设计确定）。
- 原目标只在发起登录的同一浏览器标签页内保留，包括中途完成首次改密后重新登录的情况；刷新页面或新标签页登录后进入默认页面。
- 原目标只用于本次登录；换成另一个账号登录时按该账号重新判断。

<a id="F-OP-06"></a>
### 4.5 连续失败与临时锁定（F-OP-06）

适用角色与前提：所有运营账号【沿用】。

- 登录时输错密码、修改密码时输错当前密码，共用同一个连续失败次数。
- 连续失败达到 3 次起，每次提示还剩几次机会。
- 连续失败达到 5 次，账号临时锁定：第一次 15 分钟，第二次 30 分钟，之后每次 60 分钟；第一次锁定时提示“如再次触发，锁定时间会更长”。
- 登录成功后，连续失败次数清零，锁定时长回到第一级；锁定到期自动解除时，连续失败次数归零，锁定级别保留。
- 锁定时，该账号在所有设备和标签页上的登录立即结束；锁定期间的密码错误不计入次数，也不延长锁定。
- 运营账号的锁定没有提前解除的办法：本人找回、开发人员重新分配初始密码都不会提前解除。锁定到期回到锁定前的状态；锁定期间被重新分配初始密码的，到期后为待首登改密。
- 锁定提示只在输入正确邮箱和密码，或找回时正确验证验证码后出现。
- 锁定与解除不发通知。

<a id="F-OP-07"></a>
### 4.6 登录有效期、无操作登出与退出（F-OP-07）

适用角色与前提：已登录的运营管理人员，包括待首登改密时的受限登录【沿用】。

| 规则 | 要求 |
| --- | --- |
| 登录有效期 | 自登录成功起 4 小时，到期即结束，不因操作延长 |
| 无操作登出 | 连续 2 小时没有真实操作，登录失效；不提前提醒，用户下一次真实操作时不执行该次操作，转到登录入口并说明需要重新登录 |
| 什么算真实操作 | 点击、键盘输入、提交、页面跳转；页面自动刷新数据、消息自动更新不算 |
| 主动退出 | 账号入口中有唯一的退出入口；退出后该账号全部登录立即结束 |
| 全部登录结束 | 主动退出、完成首次改密、本人修改密码、自助找回成功、账号锁定、开发人员重新分配初始密码时，该账号在所有设备和标签页的登录都立即结束 |

- 可立即感知的结束场景回到登录入口并说明原因，立即清除受保护内容；失效后不再显示新的受保护数据或迟到的操作结果。
- 尚未保存的内容不保留；结束前未提交成功的操作不当作已完成。
- 界面语言保留，不随退出恢复默认。

## 5. 运营账户设置

<a id="F-OP-08"></a>
### 5.1 账号入口与账号信息（F-OP-08）

适用角色与前提：账号正常、已登录的运营管理人员。

- 登录后在任何页面都能看到账号入口，显示姓名、登录邮箱和角色；账号入口中有账户设置和退出登录。
- 账户设置展示[运营账号信息](#op-account-info)中的全部项目，并提供修改密码、界面语言和时区的修改；不提供改角色、新增账号、修改登录邮箱或修改他人信息的入口。
- 读取失败时说明暂时无法读取、可以重试，不显示为空。

<a id="F-OP-09"></a>
### 5.2 修改密码（F-OP-09）

适用角色与前提：账号正常、已登录的本人【沿用】。

- 先输入当前密码完成验证，验证通过后 10 分钟内有效；超时未提交成功须重新验证，原密码不变。
- 当前密码输错时不能继续，说明当前密码不正确；输错计入[连续失败与临时锁定（F-OP-06）](#F-OP-06)。
- 新密码须符合[设置密码的共同规则](#password-rules)。
- 修改成功后新密码立即生效；平台发送[运营密码变更通知（NT-OP-02）](./03-运营登录与企业管理-消息通知.md#NT-OP-02)，随后该账号全部登录（包括当前这次）结束，回到登录入口并说明“密码已修改，请用新密码重新登录”。
- 修改失败、取消、离开，或修改期间登录已结束时，原密码不变，不发送通知；提交期间不能重复提交。

<a id="F-OP-10"></a>
### 5.3 界面语言与时区（F-OP-10）

适用角色与前提：界面语言对所有运营端访问者；时区对账号正常、已登录的本人。

- 界面语言有简体中文、English 两种，登录入口和登录后任何页面都可以切换，切换后立即生效，已填写未提交的内容不丢失【确认】。
- 登录后切换即保存为本人偏好；未登录时切换的语言保存在当前浏览器。账号保存过偏好时按账号偏好展示，没有时沿用当前页面语言，都没有时默认 English【沿用】。
- 界面文字随语言切换；企业名称、联系人、邮箱、编号、钱包地址、金额、时间等业务值按原值展示，不翻译。
- 首次登录成功时按浏览器推断写入时区，推断不出时为 UTC；本人可在账户设置中改为任一有效的 IANA 时区（如 Asia/Shanghai、Africa/Lagos、UTC），保存成功后立即生效，失败时保留原时区【沿用】。
- 运营端所有时间按本人时区展示并标明时区；时区只影响展示，不改变到期等业务判断。
- 语言与时区变更不发送通知。

## 7. 企业档案与唯一企业用户

<a id="fields"></a>
### 7.1 企业档案字段

运营在邀请时填写、之后可按[编辑企业资料（F-EN-04）](#F-EN-04)维护的字段：

| 业务信息 | 含义／类型或枚举 | 必填条件／默认值 | 可编辑范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 企业编号 | 本平台为企业生成的唯一标识 | 邀请成功时由平台生成 | 不能修改或重新分配；不随企业名称、注册国家／地区、企业登记号码、联系人、登录邮箱等任何资料的变化而变化【确认】 | 全平台唯一；本平台其他模块及使用本平台企业身份的平台引用企业时均以企业编号为准 |

| 联系人姓名 | 企业业务联系人 | 必填 | 运营可编辑 | 去首尾空格后 2–100 字 |
| 联系电话 | 联系人电话，由国家／地区区号和电话号码组成 | 必填，两部分都必填；区号初始不预选，选择注册国家／地区后自动带出对应区号，可修改 | 运营可编辑 | 区号从下拉选项中选择，选项按“+区号 国家／地区名”展示（如“+234 尼日利亚”）；选中后区号处只显示“+区号”（如“+234”），不再附带国家／地区名【确认】；号码允许数字、空格、短横线和括号，至少包含 1 个数字，6–30 字（不含区号）【沿用】；不合规时不能保存并指出联系电话的问题 |
| 联系邮箱 | 业务联系邮箱 | 必填 | 运营可编辑 | 合法邮箱，最长 254 个字符；可与登录邮箱相同；不用于登录或接收密码 |

| 关联 ERP 企业 | 本企业在 ERP 中对应的 ERP 企业，展示为“ERP 名称（ERP 企业标识）” | 选填，可多选，可以一个都不选；无默认值 | 邀请时和编辑时运营可增加或取消，见[关联 ERP 企业（F-EN-10）](#F-EN-10) | 候选项与校验见[关联 ERP 企业（F-EN-10）](#F-EN-10) |

- 联系电话区号选项中，多个国家／地区共用同一区号时各自为一个选项（如“+1 美国”“+1 加拿大”）；区号是自动带出且运营未手动改过时，修改注册国家／地区会随之改变，运营手动选过区号后不再随之变化；编辑时保留已保存的区号和号码【沿用】。
- 联系电话在列表、详情和操作记录中展示为区号在前、号码在后，如“+234 803 000 0000”，不附带国家／地区名【确认】。

<a id="two-dimensions"></a>
**运营维护的资料与企业端维护的资料**【确认】

- 企业身份、联系人和业务角色由运营在邀请时填写，之后只由运营维护。
- 企业用户入驻时提交的个人资料和企业补充资料，字段、校验和后续更新由企业登录与首次入驻（M1）定义，只由企业用户维护；运营在[企业详情与入驻进度（F-EN-03）](#F-EN-03)中只读查看，不能代填或修改。
- 两者是两个维度、互不绑定：运营修改联系人不改变企业用户的个人资料，企业用户更新个人资料也不改变运营维护的联系人；同名字段（如邮箱、电话）不互相同步、不互相校验。

<a id="enterprise-account-status"></a>
### 7.2 入驻进度与认证状态

运营端只展示企业的入驻进度和认证状态，不展示企业账号的登录状态：企业用户是否被临时锁定、是否自助找回过密码、是否修改过登录邮箱，运营端都不展示、不接收通知，相关规则由 M1 定义【确认】。

**入驻进度**

| 入驻进度 | 含义 |
| --- | --- |
| 待首次改密 | 企业用户还没有完成过首次改密 |
| 待绑定钱包 | 已完成首次改密，尚未成功绑定钱包 |
| 待完善资料 | 已绑定钱包，尚未提交个人与企业资料 |
| 已完成入驻 | 钱包已绑定、资料已提交成功；企业端按业务角色开放业务功能【确认】 |

- 入驻进度只前进、不后退：重发邀请，以及企业用户的临时锁定、自助找回密码和修改登录邮箱都不改变入驻进度，已绑定的钱包和已提交的资料保留【确认】。
- 入驻进度的事实由企业端产生，运营不能手动改变。

<a id="certification"></a>
**认证状态**

| 认证状态 | 条件 |
| --- | --- |
| 已认证 | 入驻进度为已完成入驻：钱包已绑定，个人与企业资料已提交成功 |
| 未认证 | 入驻进度为待首次改密、待绑定钱包或待完善资料 |

- 企业信息完善完成（入驻进度为已完成入驻）才算已认证，其余均为未认证【确认】。
- 认证状态由入驻进度得出，不另设认证审核；运营不能手动设置。入驻进度只前进，已认证的企业不会回到未认证。
- 本平台对外提供企业身份时（如代币发行平台按钱包地址读取企业身份），以企业编号识别企业，按上表给出已认证或未认证。
- 本期不设企业账号停用，对外不存在“账户禁用”。企业端的密码临时锁定只限制在本平台用密码登录，不改变认证状态，也不对外表示为账户锁定。
- 状态变化见[入驻进度状态机](./02-运营登录与企业管理-流程图与状态机.md#state-3)。

<a id="combo"></a>
**各入驻进度下的运营操作与企业用户结果**

| 入驻进度 | 企业用户能做什么 | 运营可用的账号操作 |
| --- | --- | --- |
| 待首次改密 | 用初始密码登录并改密，或在企业端自助找回密码 | 重发邀请 |
| 待绑定钱包或待完善资料 | 登录后只能继续完成入驻准备，不能使用业务功能 | 无 |
| 已完成入驻 | 按业务角色使用企业端 | 无 |

- 编辑企业资料在任何入驻进度下都可用；增加业务角色在企业只有一个角色时可用。
- 企业用户在企业端的具体登录、改密、自助找回、绑定钱包和资料提交行为由 M1 定义，本表只列运营视角的结果。
- 企业用户在任何入驻进度下都可能因输错密码被临时锁定，锁定按 M1 规则到期自动解除，不影响上表的运营操作，运营端也不展示锁定。
- 企业用户完成首次改密后，没有运营重置密码的操作；企业用户自助找回密码不通知运营，运营端也不展示找回的过程或结果【确认】。

## 8. 企业管理

<a id="F-EN-01"></a>
### 8.1 企业列表与查找（F-EN-01）

适用角色与前提：账号正常、已登录的运营管理人员。

- 列表展示全部企业：企业编号、企业名称、注册国家／地区、业务角色、登录邮箱、入驻进度、认证状态、钱包是否已绑定、关联 ERP 企业（展示 ERP 名称，多个时全部列出；未关联时展示“未关联”）、邀请时间、最近登录时间。
- 支持按企业编号、企业名称（含英文名称）、企业登记号码或登录邮箱查找，按业务角色、入驻进度、认证状态、是否已关联 ERP 企业组合筛选；也可按 ERP 名称或 ERP 企业标识查找其关联的平台企业；登录邮箱按企业当前的登录邮箱查找；查找不区分英文字母大小写。
- 默认按邀请时间从新到旧排列；展示总数并分页，查找或筛选条件变化后回到第一页；从详情返回时回到原所在页并保留条件。
- 业务角色同时有两个时两个都展示，不合并为“双角色”以外的说法。
- 没有任何企业、筛选无结果、读取失败三种情况可区分；读取失败可重试，不显示为空列表。
- 从列表可以发起[邀请企业并开通唯一企业用户（F-EN-02）](#F-EN-02)，或进入[企业详情与入驻进度（F-EN-03）](#F-EN-03)。

<a id="F-EN-02"></a>
### 8.2 邀请企业并开通唯一企业用户（F-EN-02）

适用角色与前提：账号正常、已登录的运营管理人员。企业不开放自主注册【确认】。

- 运营按[企业档案字段](#fields)填写企业资料、勾选业务角色、设置登录邮箱，可同时选择[关联 ERP 企业（F-EN-10）](#F-EN-10)，然后提交；初始密码由平台随机生成，运营不填写【沿用】。
- 提交时平台校验全部字段、[企业身份与重复邀请](#identity)、登录邮箱唯一性和所选 ERP 企业是否仍可关联；任何一项不通过都不建立企业或账号，不发邮件，指出原因并保留仍有效的输入。
- 校验通过后，平台生成企业编号和初始密码，同时建立企业档案和唯一企业用户：企业账号为待首登改密、入驻进度为待首次改密。两者一起成功或一起不建立，不留下只有企业没有用户、或只有用户没有企业的记录【沿用】。
- 成功后向登录邮箱发送[企业邀请邮件（NT-EN-01）](./03-运营登录与企业管理-消息通知.md#NT-EN-01)，并说明邀请已发出及发往的登录邮箱；初始密码只出现在邮件中，任何页面都不展示【沿用】。
- 邀请邮件发送失败时，企业和账号照常建立、不回滚，明确说明邀请邮件未发出；运营可在企业详情中[重发邀请（F-EN-07）](#F-EN-07)。
- 重复点击、刷新或网络重发只建立一家企业、一个账号，只发一封邀请邮件。
- 两名运营同时邀请同一企业身份或使用同一登录邮箱时，只有一次成功；另一次按重复邀请或登录邮箱不可用处理。
- 邀请成功记入[企业操作记录（F-EN-09）](#F-EN-09)。

<a id="identity"></a>
#### 企业身份与重复邀请

- 企业身份由“注册国家／地区＋企业登记号码”确定；登记号码比较时忽略英文字母大小写、空格和连字符【确认】。
- 提交的企业身份已存在时，不论该企业处于什么入驻进度，都不能再次邀请、不新建账号；说明该企业已被邀请，并展示已有企业的企业编号、企业名称和入驻进度，可以进入其详情【确认】。
- 需要恢复已有企业的使用时，在其详情中对原账号操作：首次改密前未收到邀请用[重发邀请（F-EN-07）](#F-EN-07)；忘记密码由企业用户在企业端自助找回，被临时锁定时等待到期【确认】。
- 更换登录邮箱、联系人或企业名称写法都不能绕过身份判断【确认】。

<a id="same-name"></a>
#### 同名提醒

- 企业名称或英文名称与已有企业相同（去首尾空格、不区分英文字母大小写）而企业身份不同时，提交前提示可能重复，并列出同名企业的企业编号、注册国家／地区和企业登记号码；运营确认是不同企业后可以继续提交，取消则回到填写内容。

<a id="login-email-fix"></a>
#### 登录邮箱填错的更正

- 邀请成功后，产品内不提供修改企业登录邮箱的入口【沿用】。入驻进度为待首次改密（企业用户从未完成首次改密）时，运营发现填错可线下联系开发人员处理：开发人员把登录邮箱改为正确邮箱，平台为该账号重新生成初始密码，视为一次凭据重置【沿用】。
- 正确邮箱须满足[登录邮箱的唯一性](#email-unique)；填错的邮箱立即失去登录与找回资格，并被释放，可以分配给其他账号【确认】。
- 更正生效后，原初始密码作废，该账号全部登录结束，企业账号仍为待首登改密；业务角色不变，仍是该企业唯一的企业用户。
- 平台向正确邮箱发送[企业邀请邮件（NT-EN-01）](./03-运营登录与企业管理-消息通知.md#NT-EN-01)；填错的邮箱不再收到任何邮件。
- 企业用户已完成首次改密后，登录邮箱由企业用户在企业端自行修改（M1）；运营端和开发人员都不再更正。企业用户既忘记密码又收不到登录邮箱验证码时的恢复见[企业用户无法使用登录邮箱时的恢复（Q-M2-07）](#Q-M2-07)。
- 平台按[安全记录](#security-records)留存一条记录，含修改前后的登录邮箱，并记入[企业操作记录（F-EN-09）](#F-EN-09)，操作人为开发人员。

流程参见：[邀请企业（图 3）](./02-运营登录与企业管理-流程图与状态机.md#fig-3)。

### 8.3 企业详情与入驻进度（F-EN-03）

适用角色与前提：账号正常、已登录的运营管理人员。

详情展示以下几组信息，具体分组与承载由设计确定：

| 信息组 | 展示内容 |
| --- | --- |
| 企业档案 | [企业档案字段](#fields)中除初始密码外的全部项目；邀请时间、最近更新时间与最近更新人 |
| 唯一企业用户 | 当前登录邮箱（企业用户在企业端修改后展示新邮箱）、首次改密完成时间、最近登录时间；不展示临时锁定、找回密码或修改登录邮箱的状态与记录 |
| 入驻进度与认证状态 | 当前入驻进度和[认证状态](#certification)；钱包绑定时间、资料提交时间（尚未发生的不展示） |
| 钱包 | 已绑定的钱包地址、控制权验证结果、绑定时间；未绑定时说明尚未绑定 |
| 入驻资料 | 企业用户在企业端维护的个人资料与企业补充资料，按 M1 定义的字段原值只读展示，与运营维护的联系人分开展示、不合并；尚未提交时说明尚未提交 |
| 业务角色 | 当前业务角色 |
| 关联 ERP 企业 | 每个已关联的 ERP 企业：ERP 名称、ERP 企业标识、关联时间、关联人；未关联时说明“未关联 ERP 企业，本企业不与任何应收账款对应” |
| 操作记录 | 见[企业操作记录（F-EN-09）](#F-EN-09) |

- 钱包地址对运营可核对完整地址并复制，复制得到完整地址；展示缩写方式由设计确定。钱包地址对应本企业，没有修改、解绑或另选钱包的入口【确认】。
- 详情只提供当前入驻进度下可用的账号操作，见[各入驻进度下的运营操作与企业用户结果](#combo)；不展示初始密码，没有修改登录邮箱、代填资料、代绑钱包或删除企业的入口。
- 详情所列信息读取中、读取失败、确实没有数据三种情况可区分；部分信息读取失败时只说明该部分失败并可重试，不影响其他部分。
- 访问不存在的企业时，按[运营端菜单与无权访问（F-OP-11）](#F-OP-11)说明内容不存在。

<a id="F-EN-04"></a>
### 8.4 编辑企业资料（F-EN-04）

适用角色与前提：账号正常、已登录的运营管理人员；企业处于任一入驻进度。

- 可编辑企业名称、企业英文名称、联系人姓名、联系电话、联系邮箱；校验同[企业档案字段](#fields)。
- 可增加或取消关联 ERP 企业，规则见[关联 ERP 企业（F-EN-10）](#F-EN-10)。
- 注册国家／地区和企业登记号码只在入驻进度为“已完成入驻”之前可编辑，用于更正录入错误；修改后的企业身份仍须唯一，与已有企业相同时按[企业身份与重复邀请](#identity)拦截。已完成入驻后两项不可编辑，企业身份不能改成另一主体【确认】。
- 不能编辑企业编号、登录邮箱、初始密码、入驻进度、认证状态、钱包和企业用户在企业端维护的资料；编辑任何资料都不改变企业编号【确认】。
- 保存时按最新版本校验：其他运营在此期间已改动同一企业资料时，不覆盖，说明资料已变化并展示最新值，运营确认后重新编辑。
- 保存成功后使用新值，记入[企业操作记录（F-EN-09）](#F-EN-09)并记录修改前后的值；保存失败保持最近一次成功结果，可重试。
- 修改联系人不改变企业用户的个人资料，见[运营维护的资料与企业端维护的资料](#two-dimensions)。
- 编辑不结束企业用户的登录，不发送通知。企业名称变更后，历史业务记录中名称如何展示由所属业务模块定义，本模块不改写历史。

<a id="F-EN-05"></a>
### 8.5 增加业务角色（F-EN-05）

适用角色与前提：账号正常、已登录的运营管理人员；企业当前只有债权人或只有债务人一个角色。

- 运营可以为企业增加另一个角色，增加后企业同时有债权人、债务人两个角色；角色作用于该企业唯一的企业用户，不新建用户【确认】。
- 本期不能取消角色：已有的角色在任何情况下都不能移除；企业已有两个角色时不提供增加入口【确认】。
- 增加角色后，企业端在下一次请求时按新角色开放对应业务菜单；企业在交易中是债权方还是债务方仍按具体交易判断，增加角色不使企业可以处理不属于自己的申请【确认】。
- 确认时展示增加前后的角色；增加记入[企业操作记录（F-EN-09）](#F-EN-09)。
- 两名运营同时增加同一角色时只执行一次，另一次说明该角色已存在。增加不结束企业用户的登录、不发送通知。

<a id="F-EN-10"></a>
### 8.6 关联 ERP 企业（F-EN-10）

适用角色与前提：账号正常、已登录的运营管理人员，在[邀请企业并开通唯一企业用户（F-EN-02）](#F-EN-02)或[编辑企业资料（F-EN-04）](#F-EN-04)时操作；企业处于任一入驻进度【确认】。

**候选项**
- 候选项是 ERP 已同步到本平台的单据中出现过的全部 ERP 企业，每项展示 ERP 名称和 ERP 企业标识；可以按 ERP 名称或 ERP 企业标识查找【确认】。
- ERP 名称按 ERP 最新同步的原值展示；ERP 中改名后展示新名称，关联关系不变。识别 ERP 企业只看 ERP 企业标识，不按名称或企业登记号码比对。
- 已关联其他平台企业的 ERP 企业仍出现在候选项中，但不能选择，并说明已关联的平台企业名称和企业编号。
- 还没有任何单据同步过来的企业不在候选项中：此时可以不选，先完成邀请或保存其他资料；等该企业的单据同步后，再在编辑企业资料中补关联【确认】。候选项为空时说明“暂无可关联的 ERP 企业，单据同步后可在编辑企业资料中补充关联”。

**关联规则**
- 一个平台企业可以关联多个 ERP 企业；一个 ERP 企业同一时刻只能关联一个平台企业【确认】。
- 保存时逐个检查所选 ERP 企业：已在此期间被其他平台企业关联的，本次保存不成功，指出是哪个 ERP 企业、已关联哪个平台企业，其他已填内容保留；邀请时同样整体不成功，不建立企业或账号。两名运营同时把同一 ERP 企业关联到不同平台企业时，只有先保存的一次成功。
- 关联不检查业务角色：关联后本企业以内销卖方出现的应收账款对应为债权人、以内销买方出现的对应为债务人；企业端能否看到和办理，按其业务角色和应收账款（M3）、应收查看与确权申请（M7a）、确权待办与确认处理（M7b）的规则判断。
- 关联与取消关联只对运营可见，企业端不展示关联了哪些 ERP 企业。

**对应收账款的影响**
- 关联保存成功后立即生效：已形成的应收账款和之后新同步形成的应收账款，凡内销发票的内销卖方或内销买方是该 ERP 企业的，都自动对应到本平台企业【确认】。
- 没有关联 ERP 企业的平台企业，不与任何应收账款对应，企业端看不到任何应收账款，即使已完成入驻；应收账款中对应不上的一方，按 M3 的规则展示“未对应平台企业”【确认】。
- 保存前确认本次变化：列出新增关联和取消关联的 ERP 企业，以及每个 ERP 企业当前涉及的应收账款笔数（分别列出作为内销卖方、内销买方的笔数）。

**取消关联**
- 取消关联保存成功后，以该 ERP 企业为内销卖方或内销买方的应收账款立即不再对应本平台企业，企业端不再看到这些应收账款；运营端按 M3 规则展示为“未对应平台企业”，之后可以把该 ERP 企业关联到其他平台企业【确认】。
- 这些应收账款中有处理中的确权申请（待债务人确认或待运营审核）时，不能取消关联，说明处理中的申请笔数；申请结束（被驳回、运营审核通过或到期关闭）后才能取消。
- 已经结束的确权申请、运营审核结论和推送记录作为历史保留，不因取消关联而撤回或改写。

**记录**
- 每次关联、取消关联记入[企业操作记录（F-EN-09）](#F-EN-09)，记录 ERP 名称、ERP 企业标识、操作人和时间。
- 关联与取消关联不结束企业用户的登录，不发送通知。

流程参见：[关联与取消关联 ERP 企业（图 6）](./02-运营登录与企业管理-流程图与状态机.md#fig-6)。

<a id="F-EN-07"></a>
### 8.7 重发邀请（F-EN-07）

适用角色与前提：账号正常、已登录的运营管理人员；企业入驻进度为待首次改密，即企业用户从未设置过自己的密码（首次登录强制改密成功或自助找回成功，都算已完成首次改密）。企业用户完成首次改密后不提供本操作，也没有运营重置密码【确认】。

- 确认时说明：将生成新的初始密码并重新发送邀请邮件到该登录邮箱，此前的初始密码立即作废；业务角色不变。
- 成功后：平台生成新的初始密码，此前的初始密码作废；该账号全部登录结束、未使用的验证码作废；企业用户仍须用初始密码登录并改密。企业用户在企业端处于临时锁定时，重发邀请不解除锁定，锁定按 M1 规则到期。
- 向该账号当前登录邮箱发送[企业邀请邮件（NT-EN-01）](./03-运营登录与企业管理-消息通知.md#NT-EN-01)，不发联系邮箱；运营看不到新的初始密码。
- 邮件发送失败时，新初始密码照常生效、不回滚，明确说明邮件未发出，可再次执行；再次执行会再生成一个新初始密码，使上一个作废。
- 重复点击或网络重发只生成一个新初始密码、只发一封邮件。
- 提交时按最新状态校验：企业用户在此期间已完成首次改密的，不执行，说明企业用户已完成首次改密、无需重发邀请。
- 不新建用户，不改变业务角色【确认】。
- 重发邀请记入[企业操作记录（F-EN-09）](#F-EN-09)和[安全记录](#security-records)。

<a id="F-EN-09"></a>
### 8.8 企业操作记录（F-EN-09）

适用角色与前提：账号正常、已登录的运营管理人员，在企业详情中查看。

- 记录以下事件：邀请、编辑企业资料（含修改前后的值）、增加业务角色（含增加前后）、关联与取消关联 ERP 企业（含 ERP 名称与 ERP 企业标识）、重发邀请、开发人员更正登录邮箱（含修改前后的邮箱）；以及企业端产生的入驻节点：完成首次改密、绑定钱包、提交资料。企业用户的临时锁定、自助找回密码和修改登录邮箱不进入操作记录【确认】。
- 每条记录展示时间（按本人时区并标明时区）、操作人（运营姓名、“企业用户”或“开发人员”）、事件和结果；邮件类操作同时记录邮件是否发出。
- 不记录、不展示任何密码或验证码。
- 按时间从新到旧排列；记录只读，不能修改或删除。

### 待确认事项

| 编号 | 事项 | 当前处理与影响 |
| --- | --- | --- |
| <a id="Q-M2-07"></a>Q-M2-07 | **企业用户无法使用登录邮箱时的恢复。** 企业用户完成首次改密后，只能用登录邮箱验证码自助找回密码；还能登录时，可以先在企业端把登录邮箱改为可用的新邮箱。剩下两种情况在产品内无法恢复：一是既忘记密码、又收不到登录邮箱的验证码（邮箱停用、经办人离职）；二是登录邮箱被他人控制，对方可借自助找回和改邮箱占用账号。运营不能重置、不能更正邮箱，本期也没有停用；每个企业只能邀请一次、只有一个用户，该企业相当于无法再使用本平台。推荐：保留开发人员在产品外的凭据更正——运营线下核实企业身份后联系开发人员，开发人员把登录邮箱改为企业指定的新邮箱，平台重新生成初始密码并发送企业邀请邮件，企业用户须用新初始密码登录并改密；钱包、资料、入驻进度、认证状态和业务角色不变，留存安全记录和操作记录。理由：运营端不开放任何重置入口，符合“首次改密后运营端不得重置”，仅作线下异常处理。风险：依赖人工核实，需要明确核实材料。 | 裁定前，本册不提供以上两种情况的恢复途径；企业用户能收到登录邮箱验证码，或仍能登录并修改登录邮箱时，可以自行闭环。裁定后同步更新[登录邮箱填错的更正](#login-email-fix)、02 册与 04 册 |

### 依赖

- 开发人员：在产品外分配运营账号的登录邮箱、姓名和初始密码，重新分配运营初始密码，并线下告知新初始密码；按[登录邮箱填错的更正](#login-email-fix)更正企业登录邮箱。
- 企业登录与首次入驻（M1）：提供企业用户的首次改密、钱包绑定与验证、资料提交结果和当前登录邮箱；提供用登录邮箱验证码自助找回密码，这是企业用户完成首次改密后唯一的密码恢复途径；提供本人修改登录邮箱，新邮箱须符合本册[登录邮箱的唯一性](#email-unique)；定义个人资料与企业补充资料的字段。企业端的密码条件与输入校验、锁定规则须与本册[设置密码的共同规则](#password-rules)和[连续失败与临时锁定（F-OP-06）](#F-OP-06)一致；企业端不再有运营停用、启用、运营重置密码和运营解锁的结果。
- 应收账款（M3）：按本模块的 ERP 企业关联确定每笔应收账款的债权人、债务人，并在关联或取消关联后立即更新对应结果；定义“未对应平台企业”的展示。
- ERP 单据同步：提供单据中交易主体的 ERP 名称和 ERP 企业标识，作为关联候选项；企业的单据尚未同步时无法选择，需同步后补关联。
- 邮件服务：投递验证码、密码变更通知和企业邀请邮件。验证码发送失败不得提示已发出；邀请邮件失败不回滚已生效的账号结果。
- 需求方：上线后提供通知中“非本人操作时的求助方式”使用的官方客服邮箱；提供前通知省略求助方式一句，见[客服邮箱](./03-运营登录与企业管理-消息通知.md#support-channel)。
- 浏览器时区：用于首次登录时写入时区偏好；推断失败时为 UTC。
- 会话与锁定计时、真实操作的判定、人机校验、验证码计时与计数、初始密码的随机生成、安全记录的保留由研发实现，测试负责验证。
