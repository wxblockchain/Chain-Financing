## 1. 模块是什么

本模块是运营端的“最后一道关”。债务人确认后的确权申请进入运营审核，运营人员核对申请当次提交的资料、处理记录、应收账款的当前状态和关联风控预警，决定是否审核通过。审核通过后，这笔应收账款取得出库资格；运营人员再对它执行资产出库：平台把审核通过的那一版资料做存证，并提供给资产数字化平台。资产数字化平台确认接收后，这笔资产才算“已出库”。出库失败时运营人员能看到失败环节和原因，并在条件仍满足时重新出库。运营人员还可以在这里查看全部确权申请的完整处理记录。

基本原则：

- **运营审核只有“通过”。** 没有驳回或不通过；运营人员不予通过的申请一直处于“待运营审核”，直到通过或应收账款到期由 M7a 自动关闭。
- **审核看当次依据。** 审核对象是申请提交时记录的当次依据；申请提交后资料变化不要求债务人重新确认或运营重新审核，只作为当前情况提示。
- **审核通过不等于已出库。** 审核通过只表示取得出库资格；出库由运营人员另行执行，资产数字化平台确认接收后才是“已出库”。审核通过、可出库、出库处理中、已出库、出库失败分别表达。
- **出库的是审核通过的那一版资料。** 对外提供的内容固定为该申请的当次依据和审核结论，不随之后的 ERP 更新改变。
- **没有审核通过，就没有对外提供。** 未提交、待债务人确认、债务人已驳回、待运营审核、已关闭的申请对应的资产，都不能出库、存证或提供给任何其他平台；本平台也不向其他平台提供除出库以外的资产查询。
- **风控预警只提示、不阻断。** 未处理预警或“确认有风险”的预警都不自动阻止审核通过和出库，由审核人判断；存在这类预警时审核通过必须写明审核说明。
- **失败不显示成功。** 出库失败只能由运营人员重新出库，没有自动重试；重新出库仍须满足出库条件。

**一个完整的例子**（企业名称、编号、金额为演示值）。Carloha Holding 对应收账款 AR-0012（发票 INV-0012，60,000.00 USD，到期日 2026-12-09（Africa/Lagos））发起确权申请 AP-0001，Carloha Nigeria 确认后申请变为“待运营审核”，全体运营收到“有新的确权申请待运营审核（M7b-NT03）”，左侧“运营审核”菜单角标加 1。运营人员甲从消息进入 AP-0001 的审核详情，看到申请信息、处理记录（Holding 用户张三单笔发起、Nigeria 用户李四确认）、当次依据（应收账款信息、发票及附件、2 辆车、1 份合同、回款统计），以及当前情况：到期状态“未到期”、回款状态“部分收款”、核心资料状态“一致”、关联风控预警“未处理 1、已处理 0”（主体不一致：买方在收款登记中为 Lagos Auto Trading Ltd）。甲进入 M8 查看该预警后返回，选择“审核通过”，确认时平台提示存在 1 条未处理预警，甲填写审核说明“付款方为债务人委托代付，代付函已线下核实”后提交。AP-0001 变为“运营审核通过”，待审核角标减 1；Holding 收到“运营审核已通过”。AP-0001 进入出库列表，出库状态“未出库”，满足出库条件，“出库与供数”菜单角标加 1。甲执行出库，确认时看到将提供给资产数字化平台的内容和接收钱包（Holding 绑定的钱包，缩写展示）。提交后出库状态为“出库处理中”：存证成功，资产数字化平台返回“未接收”，原因“receiver wallet not registered”，出库状态变为“出库失败”（失败环节：供数），全体运营收到“资产出库失败”。对接问题解决后，甲对 AP-0001 重新出库，平台沿用已有存证、只重新供数；资产数字化平台返回“已接收”，出库状态变为“已出库”，Holding 收到“资产已出库”，在 M7a 申请详情中看到出库进度“已出库”。之后 ERP 更新了 INV-0012 的合同，已出库内容不变。

<a id="out-of-scope"></a>
### 1.2 本期不做

- 运营审核驳回或不通过，以及填写不通过原因、不通过后重新提交（用户已裁定运营审核只有通过）。
- 撤回或撤销审核通过；撤回、撤销、注销已出库的资产。
- 运营批量审核、批量出库：本期逐笔审核、逐笔出库。
- 审核通过后自动出库：出库由运营人员逐笔执行。
- 已出库内容的更新、修订或重新提供；资料变化后自动重新出库或增量供数。
- 资产数字化平台接收之后的处理（生成数字凭证、发放、结清注销等）在本平台的展示与回写；是否回传待验证，见[资产数字化平台的接收能力（Q-M9-03）](#Q-M9-03)。
- 自动重试出库、出库失败的补偿处理。
- 向资产数字化平台以外的平台提供资产，或与借贷服务平台交互。
- 企业钱包目录与资产数字化平台的同步：不属于本模块；本模块的审核门槛只约束资产数据。
- 审核时要求企业补充或修改资料，或运营人员在平台上修改发票、车辆、合同、款项资料。
- 企业端查看审核人、审核说明、存证凭证、出库失败原因；债务人查看出库进度（按 M7b）。
- 风控预警的生成与处理：由 M8 定义，本模块只展示并留存审核时的预警情况。
- 中文、英文以外的语言。

| 申请状态 | 沿用 M7a [申请状态](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#apply-status)：待债务人确认／债务人已驳回／待运营审核／运营审核通过／已关闭 |
| 当次依据 | 债权人提交申请成功那一刻本笔应收账款的资料记录，由 M7a 保存，见 M7a [当次依据](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#snapshot) |
| 待审核 | 申请状态为“待运营审核”的申请。“待审核”是列表范围，不是另一种状态 |
| 到期时点 | M3 判定本笔应收账款由“未到期”变为“已到期”的时点，即 ERP 时区下到期日当天结束（24:00），见 M3 [到期状态](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#due-status) |
| 出库资格 | 申请状态为“运营审核通过”。取得后不会失去；能否在某一时刻真正出库，还要满足[出库条件（F-M9-05）](#F-M9-05) |
| 资产 | 本模块中指一笔取得出库资格的申请及其对应的应收账款；一笔应收账款最多只有一笔“运营审核通过”的申请（按 M7a 申请资格），因此最多出库一次 |
| 资产出库（出库） | 平台把一笔资产的出库内容做存证，并提供给资产数字化平台；资产数字化平台确认接收后为“已出库”。与 M5 中车辆实物的出库交付不同，两者分别记录、互不代替 |
| 出库内容 | 一笔资产对外提供的资料，见[出库内容](#outbound-content) |
| 存证 | 出库的第一步：为出库内容生成不可篡改的存证记录，并取得存证凭证 |
| 供数 | 出库的第二步：把出库内容和存证凭证提供给资产数字化平台，并取得其接收结果 |
| 资产数字化平台 | 接收本平台可信资产的外部平台，是本平台唯一的资产出库对象 |
| 接收钱包 | 债权人企业在 M1 绑定的唯一钱包地址，随出库内容提供给资产数字化平台；债权人发起申请前必须已完成入驻，因此一定存在，且不可更换 |
| 出库状态 | 一笔资产的出库结果，只有一个维度，见[出库状态](#outbound-status) |
| 出库处理 | 运营人员每提交一次出库或重新出库，形成一次出库处理，按次序编号为第 1 次、第 2 次…… |

<a id="shared-rules"></a>
## 3. 共用规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。

<a id="access"></a>
### 3.1 谁能使用、看到什么

- 只有可正常使用的运营人员能使用本模块；运营人员处于待首次改密、已停用或锁定中时不能使用，判定以 M2 为准。
- 运营人员可查看全部确权申请和全部取得出库资格的资产；可对待审核申请审核通过，对资产执行出库和重新出库。所有运营人员权限相同，本期不区分审核人与出库人，也不限制同一人既审核又出库。
- 企业端没有本模块的任何入口。企业能看到的审核与出库结果，只通过 M7a、M7b、M3 按各自可见范围展示，见[出库进度对外提供（F-M9-08）](#F-M9-08)。
- 打开不存在的申请编号（含改写链接中的编号）时，提示“该内容不存在或已更新”，并可返回来源位置。

<a id="display-values"></a>
### 3.2 金额、日期与时间

- 金额、ERP 日期、附件的展示沿用 M3 [来源值、金额与时间](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#display-values)与[附件查看](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#file-view)：金额与币种同时展示、按 ERP 原值不取整；不同币种不相加。
- 应收账款到期日把时区写在日期后面，例如“2026-12-09（Africa/Lagos）”。
- 平台自己记录的时间（发起时间、处理时间、审核时间、关闭时间、出库提交时间、存证时间、接收时间、状态更新时间）展示到分钟，按运营人员在 M2 账号设置中选择的时区展示并标明时区；M2 不提供时区设置时统一按 UTC 展示。
- 驳回原因、审核说明按填写的原文展示；存证或资产数字化平台返回的失败原因按返回的原文展示；均不随界面语言翻译。
- 接收钱包地址按 M1 的写法缩写展示，保留大小写；可复制完整地址。
- 平台自身的字段名称、状态名称、不可出库原因有中文、英文两套，随界面语言切换。

<a id="load-fail"></a>
### 3.3 加载失败与登录失效

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的金额、状态或待办数量，也不提供审核通过、出库、重新出库操作。
- 详情中某一部分（如当次依据、处理记录、关联风控预警、出库记录）加载失败时，仅该部分提示失败并可重试，其他部分正常展示。当次依据或关联风控预警未完整加载时不能审核通过；出库内容未完整加载时不能出库或重新出库。
- 待办数量取数失败时不展示数量，不展示为 0，菜单照常可用。
- 操作过程中登录失效、账号被停用或锁定时，按 M2 规则回到登录入口，本次未提交的操作不生效。

| 状态更新时间 | 最近一次申请状态变化的时间 | M7a 记录，不会缺失 | 不展示 | 展示 |

- 只有到期状态为“未到期”的应收账款才能发起申请，因此当次依据中的到期日及时区不会缺失。
- 列表不展示应收账款编号，可按其查找；申请详情中展示。

操作：

- 每行可“查看”，进入[申请详情与审核依据（F-M9-02）](#F-M9-02)，返回后保留原有范围、查找、筛选和页码。
- 待审核的行可“审核通过”，规则见[审核通过（F-M9-03）](#F-M9-03)；其他行没有审核操作。

查找与筛选：

- 按申请编号、发票号或应收账款编号查找，支持部分匹配；查找在当前范围内进行。
- 筛选：债权人、债务人、币种、应收账款到期日区间、发起时间区间；待审核另可按预警信息筛选，全部申请另可按申请状态筛选。多个条件同时生效。
- 待审核默认按应收账款到期日从早到晚排列，到期日相同时按债务人确认时间从早到晚；先到期的排在前面，避免因到期关闭而错过审核。
- 全部申请默认按状态更新时间从新到旧排列。

边界与异常：

- 平台还没有任何申请时，两个范围都展示“暂无确权申请”；待审核为空、全部申请有记录时，待审核展示“暂无待审核的申请”；查找或筛选无结果时，展示“没有符合条件的申请”并可清除条件。
- 列表中的状态和可审核操作是打开或刷新时的结果；申请状态因审核通过、到期关闭发生变化后，刷新时移出待审核。
- 列表不提供新增、编辑、删除申请的操作，也不提供批量选择。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

<a id="review-count"></a>
### 4.2 待审核数量

- 待审核数量为全平台申请状态为“待运营审核”的申请笔数，随“运营审核”菜单展示；数量为 0 时不展示数量。所有运营人员看到同一个数量。
- 待审核数量按本人打开或刷新页面时的结果展示；本人审核通过一笔申请成功后立即减少；有新申请进入待审核、其他运营人员审核通过或申请到期关闭后，在下一次打开或刷新时更新。
- 取数失败按[加载失败与登录失效](#load-fail)处理。

<a id="F-M9-03"></a>
## 6. 审核通过（F-M9-03）

适用角色与前提：运营人员；申请满足[可以审核通过的条件](#review-conditions)。入口为待审核列表中的行和申请详情。

通知：审核通过生效后向债权人企业发送[运营审核已通过（M9-NT01）](./03-运营审核与资产出库-消息通知.md#M9-NT01)。
流程参见：[审核通过的提交（图 M9-2）](./02-运营审核与资产出库-流程图与状态机.md#fig-m9-2)。
验收参见：[审核通过](./04-运营审核与资产出库-验收.md#acc-f-m9-03)。

<a id="review-conditions"></a>
### 6.1 可以审核通过的条件

一笔申请同时满足以下全部条件时，运营人员才可以审核通过。列表与详情按打开或刷新时的结果提供操作；提交时平台重新判断，以提交时为准。

| 条件 | 不满足时用户看到的结果 |
| --- | --- |
| 满足[谁能使用、看到什么](#access)的使用前提 | 按 M2 规则处理，本次不生效 |
| 申请状态为“待运营审核” | 不能审核，展示该申请的当前状态，见下表 |
| 当前时间未到本笔应收账款的到期时点 | 不能审核，说明“应收账款已到期，该申请已关闭”，展示“已关闭” |
| 当次依据与关联风控预警已完整加载 | 不能审核，按[加载失败与登录失效](#load-fail)提示重试 |

提交时申请已不是“待运营审核”，本次提交不生效，按当前状态说明：

| 提交时的申请状态 | 用户看到的说明 |
| --- | --- |
| 运营审核通过 | 该申请已由其他运营人员审核通过，不能重复审核 |
| 已关闭 | 应收账款已到期，该申请已关闭 |

- 到期以到期时点为界：到期时点之前提交成功的审核通过有效；到期时点之后提交的一律不生效，即使 M7a 尚未完成关闭，也按“已关闭”处理。
- 当前到期状态以外的当前情况（回款状态、核心资料状态）和风控预警都不是审核条件。

<a id="review-confirm"></a>
### 6.2 确认与审核说明

审核通过时展示：

- 申请编号、债权人、债务人、发票号、应收账款编号、应收账款金额及币种、应收账款到期日及时区（均取自当次依据）。
- 关联风控预警的未处理数量，以及处理结果为“确认有风险”的数量；两者都为 0 时展示“无未处理或确认有风险的风控预警”。
- 说明“审核通过后这笔应收账款取得出库资格，不能撤回；审核通过不会处理任何风控预警，也不代表已出库”。

审核时填写：

| 业务信息 | 含义/类型 | 必填条件/默认值 | 可编辑范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 审核说明 | 审核人对审核依据和判断的说明，例如为何在存在风控预警时仍予通过；多行文本 | 关联风控预警中存在未处理或“确认有风险”的预警时必填，否则选填；无默认值 | 提交前可编辑；提交后不能修改 | 去除首尾空格后不超过 500 个字符；必填时为空或只有空白不能提交并指出该项；超过 500 个字符不能提交并指出该项 |

- 是否必填以提交时的关联风控预警为准：填写过程中预警被处理、不再需要必填时，已填写内容照常保存；新出现未处理预警而说明为空时，提交不生效，提示“出现新的未处理风控预警，请填写审核说明”。
- 审核说明只对运营人员可见。

<a id="review-result"></a>
### 6.3 结果

- 用户确认提交后，平台按[可以审核通过的条件](#review-conditions)和审核说明的规则重新判断。满足时申请状态变为“运营审核通过”，记录审核结论“通过”、审核人、审核时间、审核说明，以及审核时的关联预警情况：未处理、已处理数量，每条预警的预警编号、类型、差异摘要、预警状态、处理结果。审核时的预警情况之后不随 M8 的处理而改变。
- 成功后展示申请编号与新状态“运营审核通过”；该申请移出待审核，待审核数量减 1。
- 本笔应收账款取得出库资格，出库状态为“未出库”，进入[出库列表与待办数量（F-M9-04）](#F-M9-04)。审核通过不自动出库。
- 审核通过只改变申请状态，不改变当次依据、应收账款资料和风控预警。
- 用户取消时申请不变，已填写的审核说明不保存。

边界与异常：

- 提交时已不满足条件（已被其他运营人员审核通过、已到期关闭）：本次不生效，按[可以审核通过的条件](#review-conditions)说明结果，列表与详情刷新为最新状态。
- 两名运营人员同时审核同一申请，或重复点击提交：只有先提交成功的一次生效；后到的提交不生效，说明“该申请已由其他运营人员审核通过，不能重复审核”或展示本人刚生效的结果，不会生成第二条审核记录。
- 提交失败：申请不变，保留已填写的审核说明，提示提交失败可重试。
- 提交后未收到明确结果（如网络中断）：提示“审核结果未确认，请刷新后查看”，不自动重新提交；再次提交时如已生效，按“不能重复审核”说明。
- 提交时登录失效或账号被停用：申请不变，按[加载失败与登录失效](#load-fail)处理。

<a id="not-approved"></a>
### 6.4 不予通过的申请

- 运营人员认为申请不应通过时，不作任何操作；申请保持“待运营审核”，直到之后审核通过，或到期时点到达由 M7a 关闭为“已关闭”。
- 期间这笔应收账款仍有处理中的申请，债权人不能重新发起（按 M7a 申请资格）；资产不能出库。
- 本期没有向企业说明不予通过原因的平台功能；运营人员需要时在平台外与企业沟通。

<a id="F-M9-04"></a>
## 7. 出库列表与待办数量（F-M9-04）

流程参见：[执行出库与重新出库（图 M9-3）](./02-运营审核与资产出库-流程图与状态机.md#fig-m9-3)。
验收参见：[出库列表与待办数量](./04-运营审核与资产出库-验收.md#acc-f-m9-04)。

<a id="outbound-list-fields"></a>
### 7.1 列表信息

| 业务信息 | 含义 | 来源与缺失时 |
| --- | --- | --- |
| 申请编号 | 取得出库资格的申请 | M7a，不会缺失 |
| 发票号 | 申请对应的发票号 | 当次依据，不会缺失 |
| 债权人 | 债权人企业名称 | 当次依据，不会缺失 |
| 应收账款金额及币种 | 发起时的应收账款金额 | 当次依据，不会缺失 |

| 状态更新时间 | 最近一次出库状态变化的时间；未出库时为审核时间 | 本模块记录，不会缺失 |

操作：

- 每行可“查看”，进入该申请的[申请详情与审核依据（F-M9-02）](#F-M9-02)并定位到[出库信息](#outbound-detail)，返回后保留原有查找、筛选和页码。
- 出库状态为“未出库”且可出库的行可“出库”；出库状态为“出库失败”且可出库的行可“重新出库”。规则见[执行出库（F-M9-06）](#F-M9-06)、[出库结果、失败与重新出库（F-M9-07）](#F-M9-07)。
- 不满足出库条件的行不提供“出库”“重新出库”，展示不可出库原因。

查找与筛选：

- 按申请编号、发票号或应收账款编号查找，支持部分匹配。
- 筛选：出库状态、出库条件（可出库／不可出库）、债权人、币种、审核时间区间、应收账款到期日区间。多个条件同时生效。
- 默认按应收账款到期日从早到晚排列，到期日相同时按审核时间从早到晚。

边界与异常：

- 还没有取得出库资格的资产时，展示“暂无可出库的资产”；查找或筛选无结果时，展示“没有符合条件的资产”并可清除条件。
- 列表中的出库条件和操作是打开或刷新时的结果；执行时重新判断，以执行时为准。
- 列表不提供批量选择、批量出库或删除操作。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

<a id="outbound-count"></a>
### 7.2 出库待办数量

- 出库待办数量为出库状态为“未出库”或“出库失败”、且当前满足[出库条件（F-M9-05）](#F-M9-05)的资产笔数，随“出库与供数”菜单展示；数量为 0 时不展示数量。所有运营人员看到同一个数量。
- 按本人打开或刷新页面时的结果展示；本人提交出库或重新出库成功后立即减少；出库失败、新的审核通过、资产因到期等不再满足出库条件后，在下一次打开或刷新时更新。
- 取数失败按[加载失败与登录失效](#load-fail)处理。

<a id="outbound-status"></a>
### 7.3 出库状态

出库状态表达一笔资产的出库结果，只有一个维度。

| 出库状态 | 含义 | 由什么带来 | 后续 |
| --- | --- | --- | --- |
| 未出库 | 已取得出库资格，从未提交过出库 | 审核通过 | 运营人员执行出库后变为“出库处理中” |
| 出库处理中 | 已提交出库或重新出库，存证或供数的结果尚未全部返回 | 运营人员提交出库或重新出库 | 存证成功且资产数字化平台返回“已接收”时变为“已出库”；存证失败或资产数字化平台返回“未接收”时变为“出库失败” |
| 已出库 | 存证成功，且资产数字化平台已确认接收 | 本次出库处理的供数结果为“已接收” | 结束，不再变化 |
| 出库失败 | 最近一次出库处理的存证失败，或资产数字化平台未接收 | 本次出库处理的存证结果为“失败”，或供数结果为“未接收” | 满足出库条件时可重新出库，重新出库后变为“出库处理中” |

- 状态只由上表所列的结果改变，没有其他转换；资料变化、风控预警、债权人企业的角色或账号变化都不改变出库状态。
- “出库处理中”期间结果未返回时保持“出库处理中”，不按失败或成功推断；结果未返回的时限与处理待验证，见[资产数字化平台的接收能力（Q-M9-03）](#Q-M9-03)。
- “出库失败”与“未出库”是不同状态：出库失败表示至少提交过一次出库，失败环节和原因可查。

<a id="F-M9-05"></a>
## 8. 出库条件（F-M9-05）

适用范围：出库列表中“出库条件”的展示，以及每一次出库、重新出库提交时的判断。判断以提交时的数据为准。

验收参见：[出库条件](./04-运营审核与资产出库-验收.md#acc-f-m9-05)。

一笔资产同时满足以下全部条件时为“可出库”：

| 条件 | 依据 | 不满足时的不可出库原因 |
| --- | --- | --- |
| 申请状态为“运营审核通过” | M7a [申请状态](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#apply-status) | 不进入出库列表；从其他入口提交时说明“未通过运营审核，不能出库” |
| 出库状态为“未出库”或“出库失败” | [出库状态](#outbound-status) | 出库处理中；或已出库 |
| 本笔应收账款当前到期状态为“未到期” | M3 [到期状态](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#due-status)；到期日当天仍为未到期 | 已到期 |
| 本笔应收账款当前回款状态为“未收款”或“部分收款” | M3 [回款状态](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#repayment-status) | 已收清 |
| 本笔应收账款当前核心资料状态为“一致” | M3 [核心资料差异核实（F-M3-07）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-07) | 核心资料待核实 |

- 同时有多项不满足时，全部原因都展示。
- 风控预警（含未处理和“确认有风险”）、M4—M6 资料、合同或附件是否取得、债权人或债务人企业的角色与账号状态都不是出库条件。
- 不满足出库条件不改变申请状态和出库资格：本笔资产保持“未出库”或“出库失败”；条件恢复（例如核心资料核实后回到“一致”）时重新可出库。到期和已收清不会恢复。

<a id="F-M9-06"></a>
## 9. 执行出库（F-M9-06）

适用角色与前提：运营人员；资产出库状态为“未出库”且满足[出库条件（F-M9-05）](#F-M9-05)。入口为出库列表中的行和申请详情中的[出库信息](#outbound-detail)。

通知：出库结果为“已出库”时向债权人企业发送[资产已出库（M9-NT02）](./03-运营审核与资产出库-消息通知.md#M9-NT02)；为“出库失败”时向全体运营发送[资产出库失败（M9-NT03）](./03-运营审核与资产出库-消息通知.md#M9-NT03)。
流程参见：[执行出库与重新出库（图 M9-3）](./02-运营审核与资产出库-流程图与状态机.md#fig-m9-3)。
验收参见：[执行出库](./04-运营审核与资产出库-验收.md#acc-f-m9-06)。

<a id="outbound-content"></a>
### 9.1 出库内容

一笔资产对外提供的内容固定为以下各项：

- 该申请的当次依据全部内容，含当时取得的发票附件、车辆明细附件、合同附件。
- 申请编号、应收账款编号。
- 债务人确认结论与确认时间；运营审核结论“通过”与审核时间。不含处理人、审核人姓名和审核说明。
- 接收钱包：债权人企业在 M1 绑定的钱包地址。

规则：

- 出库内容在第 1 次出库处理提交时确定，之后的重新出库使用同一份内容，不随 ERP 更新、核心资料差异或核实改变。
- 不含风控预警、M3 核实记录、M4—M6 的上游采购、车辆履约、下游销售资料。
- 当次依据中“未提供”“附件未取得”“合同未取得”的项按原样提供，不事后补入。

<a id="outbound-confirm"></a>
### 9.2 确认

执行出库时展示：

- 申请编号、发票号、应收账款编号、债权人、债务人、应收账款金额及币种、应收账款到期日及时区。
- 出库对象“资产数字化平台”，以及接收钱包地址（缩写展示，可核对完整地址）。
- 出库内容所含的附件数量；当次依据中有“附件未取得”“合同未取得”的项时，列出这些项。
- 说明“出库将为审核通过时的资料做存证，并提供给资产数字化平台；提交后不能撤回”。

用户取消时不提交，资产不变。

<a id="outbound-submit"></a>
### 9.3 提交与处理

- 用户确认提交后，平台按[出库条件（F-M9-05）](#F-M9-05)重新判断。满足时形成第 1 次出库处理，出库状态变为“出库处理中”，记录提交人、提交时间。
- 出库处理依次为两步：先存证，存证成功后再供数。

| 环节 | 结果 | 记录内容 | 对出库状态的影响 |
| --- | --- | --- | --- |
| 存证 | 成功 | 存证时间、存证凭证 | 继续供数 |
| 存证 | 失败 | 失败时间、失败原因（返回原文；未返回时为“未返回失败原因”） | 出库失败，失败环节为“存证”，不进行供数 |
| 供数 | 已接收 | 接收时间；资产数字化平台返回的资产标识（返回时记录） | 已出库 |
| 供数 | 未接收 | 返回时间、未接收原因（返回原文；未返回时为“未返回失败原因”） | 出库失败，失败环节为“供数” |

- 存证凭证和资产标识只在运营端展示；存证凭证中的技术细节（例如链上交易标识）由设计决定展示方式，运营人员可复制。
- 提交成功后展示申请编号与出库状态，出库待办数量减 1；结果返回后出库状态随之更新，刷新时可见。

边界与异常：

- 提交时已不满足出库条件：不形成出库处理，展示具体原因，列表刷新为最新结果。
- 两名运营人员同时出库同一资产，或重复点击提交：只形成一次出库处理；后到的提交不生效，说明“该资产已在出库处理中”或“该资产已出库”，并展示当前出库状态。
- 提交失败（出库处理未形成）：资产不变，提示提交失败可重试。
- 提交后未收到明确结果（如网络中断）：提示“提交结果未确认，请刷新后查看”，不自动重新提交；再次提交时如已形成出库处理，按“该资产已在出库处理中”处理，不会形成第二次。
- 出库处理中到期时点到达、回款变为已收清或核心资料变为差异待核实：已提交的出库处理继续完成，结果照常记录；只影响之后能否重新出库。
- 提交时登录失效或账号被停用：资产不变，按[加载失败与登录失效](#load-fail)处理。

<a id="F-M9-07"></a>
## 10. 出库结果、失败与重新出库（F-M9-07）

适用角色与前提：运营人员。查看适用于全部取得出库资格的资产；重新出库适用于出库状态为“出库失败”且满足[出库条件（F-M9-05）](#F-M9-05)的资产。

通知：重新出库的结果按[执行出库（F-M9-06）](#F-M9-06)发送消息；每一次出库失败各发一条。
流程参见：[执行出库与重新出库（图 M9-3）](./02-运营审核与资产出库-流程图与状态机.md#fig-m9-3)、[出库状态（图 M9-4）](./02-运营审核与资产出库-流程图与状态机.md#fig-m9-4)。
验收参见：[出库结果、失败与重新出库](./04-运营审核与资产出库-验收.md#acc-f-m9-07)。

<a id="outbound-detail"></a>
### 10.1 出库信息

申请状态为“运营审核通过”时，申请详情中展示：

- 出库状态；出库状态为“未出库”“出库失败”时，展示出库条件结果（可出库，或不可出库及全部原因）。
- 已出库时：已出库时间（即资产数字化平台的接收时间）、存证时间与存证凭证、资产数字化平台返回的资产标识。
- 出库失败时：失败环节（存证／供数）、失败时间、失败原因。
- 出库内容：按[出库内容](#outbound-content)列出；第 1 次出库处理提交前为“将提供的内容”，提交后为“已确定的出库内容”。
- 出库记录，见下。

<a id="outbound-record"></a>
### 10.2 出库记录

按次序展示每一次出库处理，新的在前：

| 业务信息 | 含义 |
| --- | --- |
| 处理次序 | 第 1 次、第 2 次…… |
| 提交人、提交时间 | 提交出库或重新出库的运营人员及时间 |
| 存证结果 | 成功（存证时间、存证凭证）；失败（失败时间、失败原因）；本次沿用已有存证时注明“沿用第 N 次的存证”；尚无结果时为“处理中” |
| 供数结果 | 已接收（接收时间、资产标识）；未接收（返回时间、未接收原因）；存证失败时为“未进行”；尚无结果时为“处理中” |
| 本次结果 | 已出库／出库失败／出库处理中 |

- 出库记录不可编辑、不可删除。

<a id="retry"></a>
### 10.3 重新出库

- 出库状态为“出库失败”且满足出库条件时，可“重新出库”；没有自动重试，重新出库的次数不限。
- 重新出库的确认内容同[确认](#outbound-confirm)，并展示最近一次的失败环节和失败原因。
- 提交后按[出库条件（F-M9-05）](#F-M9-05)重新判断；满足时形成新一次出库处理，出库状态变为“出库处理中”。
- 上一次失败环节为“存证”时，从存证开始。上一次存证已成功、失败环节为“供数”时，沿用已有存证凭证，只重新供数，不再次存证。一笔资产最多只有一份成功的存证。
- 重新出库使用第 1 次出库处理时确定的出库内容。
- 不满足出库条件时不能重新出库，出库状态保持“出库失败”，展示不可出库原因；例如供数失败后应收账款已到期，这笔资产将一直为“出库失败”。
- 提交的边界与异常同[提交与处理](#outbound-submit)。
- 同一资产不会在资产数字化平台形成两笔资产：重新出库与第 1 次出库对应同一笔资产，实现与验证归研发、测试。

<a id="F-M9-08"></a>
## 11. 出库进度对外提供（F-M9-08）

适用范围：M7a 申请详情中的[出库进度](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#outbound)，M3 应收账款详情中的[确权与审核进度](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#apply-progress)，以及本模块的[进度条](#progress-bar)。没有用户操作。

验收参见：[出库进度对外提供](./04-运营审核与资产出库-验收.md#acc-f-m9-08)。

- 出库进度只在申请状态为“运营审核通过”后提供；申请为其他状态时，出库环节为“未开始”。
- 不同角色看到的出库进度口径不同，对应关系如下：

| 出库状态 | 运营端（本模块、M3 运营视角） | 债权人（M7a 申请详情、M3 债权人视角） | 债务人（M7b、M3 债务人视角） |
| --- | --- | --- | --- |
| 未出库 | 未出库 | 未出库 | 不展示出库环节 |
| 出库处理中 | 出库处理中 | 出库处理中 | 不展示出库环节 |
| 出库失败 | 出库失败（附失败环节与原因） | 未出库 | 不展示出库环节 |
| 已出库 | 已出库（附已出库时间） | 已出库（附已出库时间） | 不展示出库环节 |

- 债权人看到的“未出库”包含从未出库和出库失败两种情况：两者都表示资产尚未提供给资产数字化平台；失败原因、存证凭证、资产标识、出库提交人只对运营人员展示。
- 出库进度与申请状态分开展示，不改变 M7a 的申请状态；“运营审核通过”不等于已出库。
- 债务人看到的进度到“运营审核通过”为止，与 M7b 一致。

<a id="data-change"></a>
## 12. 资料变化与对审核、出库的影响

本节集中说明资料变化在各阶段的结果，各功能直接引用，不再分别展开。

| 资料变化发生时 | 对申请与审核 | 对出库 |
| --- | --- | --- |
| 待运营审核期间：核心资料变为“差异待核实”、合同或回款更新、出现新的风控预警 | 申请照常可审核通过，按当次依据审核；不要求债务人重新确认；变化只在[当前情况](#current-state)中提示 | 审核通过后，核心资料仍为“差异待核实”时暂不能出库，见[出库条件（F-M9-05）](#F-M9-05) |
| 运营审核通过后、出库前 | 审核结论不变，不要求重新审核 | 出库内容仍为当次依据；按出库条件判断能否出库 |
| 出库处理中 | 不变 | 已提交的出库处理继续完成，内容不变 |
| 已出库后 | 不变 | 已出库内容不变，不自动更新、重新出库或撤回；之后的变化在 M3 当前资料和 M8 预警中查看 |

- 平台不因资料变化撤销、终止或改写任何申请、审核结论、出库内容或出库结果。
- 已出库资产之后出现核心资料差异或风控预警时，申请详情的[当前情况](#current-state)照常展示，运营人员据此在平台外与资产数字化平台、企业沟通；本期没有已出库内容的修订功能。

<a id="status-combo"></a>
## 13. 状态组合

一笔取得出库资格的资产，出库状态与出库条件是两个独立维度。下表写清每种组合下运营人员能做什么、看到什么，以及是否计入出库待办数量。

| 出库状态 | 出库条件 | 运营能做什么 | 运营看到 | 计入出库待办 | 债权人看到 |
| --- | --- | --- | --- | --- | --- |
| 未出库 | 可出库 | 出库 | 可出库 | 计入 | 未出库 |
| 未出库 | 不可出库 | 不能出库 | 不可出库原因 | 不计入 | 未出库 |
| 出库处理中 | 不判断 | 不能操作 | 已提交的出库处理与已返回的环节结果 | 不计入 | 出库处理中 |
| 出库失败 | 可出库 | 重新出库 | 失败环节、失败原因，可出库 | 计入 | 未出库 |
| 出库失败 | 不可出库 | 不能重新出库 | 失败环节、失败原因、不可出库原因 | 不计入 | 未出库 |
| 已出库 | 不判断 | 不能操作 | 已出库时间、存证凭证、资产标识 | 不计入 | 已出库 |

<a id="records"></a>
## 14. 操作留痕

- 每次生效的审核通过留存：申请编号、应收账款编号、审核人、审核时间、审核结论、审核说明、审核时的关联预警情况。
- 每次出库处理留存：申请编号、应收账款编号、处理次序、提交人、提交时间、出库内容、存证结果、供数结果及各自的时间、凭证、标识与原因。
- 留痕不可编辑、不可删除，在[申请详情与审核依据（F-M9-02）](#F-M9-02)中查看。
- 因不满足条件、提交失败或重复提交而未生效的审核或出库，不形成审核记录或出库处理，申请与出库状态不变。
