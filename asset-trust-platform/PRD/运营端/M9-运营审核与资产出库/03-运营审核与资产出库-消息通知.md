# 运营审核与资产出库 · 消息通知

2026-11-12｜需求评审稿｜配套[功能与业务规则](./01-运营审核与资产出库-PRD.md)

本模块发送 3 类站内消息，经消息中心（M10）展示，按 [来源接入要求（MSG-06）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-06)登记；必发，收件人不能关闭。本模块不发送邮件。

| 消息 | 端 | 所在功能 | 触发环节 | 谁收到 | 打开后去哪 |
| --- | --- | --- | --- | --- | --- |
| [运营审核已通过（M9-NT01）](#M9-NT01) | 企业端 | [审核通过（F-M9-03）](./01-运营审核与资产出库-PRD.md#F-M9-03) | 审核通过生效、申请变为“运营审核通过” | 该申请的债权人企业 | 应收查看与确权申请（M7a）中这笔申请的详情 |
| [资产已出库（M9-NT02）](#M9-NT02) | 企业端 | [执行出库（F-M9-06）](./01-运营审核与资产出库-PRD.md#F-M9-06)、[出库结果、失败与重新出库（F-M9-07）](./01-运营审核与资产出库-PRD.md#F-M9-07) | 资产数字化平台返回“已接收”、出库状态变为“已出库” | 该申请的债权人企业 | M7a 中这笔申请的详情 |
| [资产出库失败（M9-NT03）](#M9-NT03) | 运营端 | [执行出库（F-M9-06）](./01-运营审核与资产出库-PRD.md#F-M9-06)、[出库结果、失败与重新出库（F-M9-07）](./01-运营审核与资产出库-PRD.md#F-M9-07) | 一次出库处理的存证失败或资产数字化平台返回“未接收”、出库状态变为“出库失败” | 全体运营 | 本模块中这笔申请的详情（出库信息） |

以下情况本模块不发消息：审核通过、出库或重新出库因不满足条件、提交失败、重复提交而未生效；用户取消；提交出库或重新出库成功（出库处理中）；存证成功但供数结果尚未返回；资产因到期、已收清、核心资料待核实而不满足出库条件；查看列表、详情；待审核数量、出库待办数量变化。

不发给债务人企业：债务人看到的进度到“运营审核通过”为止（按 M7b）。新申请待运营审核的消息由确权待办与确认处理（M7b）发送“有新的确权申请待运营审核（M7b-NT03）”，本模块不发同义消息；申请到期关闭的消息由 M7a 发送。

<a id="M9-NT01"></a>
## 运营审核已通过（M9-NT01）

| 项目 | 规则 |
| --- | --- |
| 发送来源 | 运营审核与资产出库（M9）；其他模块不发同义消息 |
| 端 | 企业端 |
| 分类 | 业务办理进度 / Business progress |
| 收件范围 | 本企业：该申请的债权人企业（发起企业）。不发给债务人企业，不发运营 |
| 触发 | 审核通过生效、申请状态由“待运营审核”变为“运营审核通过”时发送 |
| 不触发 | 审核通过未生效的任何情况（不满足审核条件、到期时点后提交、提交失败、重复提交、取消） |
| 同一事实的区分依据 | 债权人企业 + 申请编号 + “运营审核已通过”。一笔申请只会审核通过一次，只发一条；重复送达、重试、刷新不新增 |
| 发生时间 | 审核通过生效的时间（即审核时间） |
| 债权人企业尚无可查看消息的条件（账号停用、锁定等） | 消息照常生成并保留，按 M10 规则在可查看后展示 |
| 原业务识别信息 | 申请编号、发票号 |
| 打开后去哪 | 原业务：M7a 中该申请的详情（只能查看，含出库进度） |
| 查看与办理条件 | 查看：本企业是该申请的发起企业且当前拥有债权人角色，按 M7a 规则。没有办理动作 |
| 必须出现的业务值 | 债务人企业名称、发票号、应收账款编号、申请编号；写明本企业在这笔业务中是债权人；写明审核通过表示取得出库资格、尚未出库 |
| 业务值取值 | 取审核通过生效时的值（企业名称、发票号、编号取当次依据），之后资料或状态变化不改写 |
| 不得出现 | 审核人姓名、审核说明、风控预警；发票、合同等原件或下载地址 |

文案（按收件人的界面语言展示中文或 English；花括号为业务值，企业名称、发票号按原值展示不翻译）：

| 语言 | 标题 | 正文 |
| --- | --- | --- |
| 中文 | 运营审核已通过 | 贵企业就发票 {发票号}（应收账款编号 {应收账款编号}）向 {债务人企业名称} 发起的确权申请 {申请编号} 已通过运营审核。贵企业在这笔业务中是债权人。审核通过表示这笔应收账款已取得出库资格，尚未出库；出库进度可在申请详情中查看。 |
| English | Operations review approved | Confirmation request {request number} submitted by your company to {debtor name} for invoice {invoice number} (receivable {receivable number}) has been approved by operations. Your company is the creditor in this transaction. Approval means the receivable is now eligible for release; it has not been released yet. You can track the release progress in the request details. |

<a id="M9-NT02"></a>
## 资产已出库（M9-NT02）

| 项目 | 规则 |
| --- | --- |
| 发送来源 | 运营审核与资产出库（M9）；其他模块不发同义消息 |
| 端 | 企业端 |
| 分类 | 业务办理进度 / Business progress |
| 收件范围 | 本企业：该申请的债权人企业（发起企业）。不发给债务人企业，不发运营 |
| 触发 | 一次出库处理的供数结果为“已接收”、出库状态变为“已出库”时发送；第 1 次出库或重新出库成功都按此发送 |
| 不触发 | 出库处理中；存证成功但供数结果尚未返回；出库失败；出库未生效的任何情况 |
| 同一事实的区分依据 | 债权人企业 + 申请编号 + “资产已出库”。一笔资产只会出库成功一次，只发一条；重复送达、重试、刷新不新增 |
| 发生时间 | 资产数字化平台的接收时间（即已出库时间） |
| 债权人企业尚无可查看消息的条件（账号停用、锁定等） | 消息照常生成并保留，按 M10 规则在可查看后展示 |
| 原业务识别信息 | 申请编号、发票号 |
| 打开后去哪 | 原业务：M7a 中该申请的详情（只能查看，出库进度为“已出库”） |
| 查看与办理条件 | 查看：本企业是该申请的发起企业且当前拥有债权人角色，按 M7a 规则。没有办理动作 |
| 必须出现的业务值 | 发票号、应收账款编号、申请编号、出库对象“资产数字化平台”；写明本企业在这笔业务中是债权人 |
| 业务值取值 | 取已出库时的值（发票号、编号取当次依据），之后不改写 |
| 不得出现 | 完整钱包地址；存证凭证、资产标识；出库提交人姓名；发票、合同等原件或下载地址 |

文案（按收件人的界面语言展示；花括号为业务值，发票号按原值展示不翻译）：

| 语言 | 标题 | 正文 |
| --- | --- | --- |
| 中文 | 资产已出库 | 贵企业发票 {发票号}（应收账款编号 {应收账款编号}，确权申请 {申请编号}）对应的资产已完成出库：平台已将审核通过时的资料存证，并由资产数字化平台确认接收。贵企业在这笔业务中是债权人。 |
| English | Asset released | The asset for your company's invoice {invoice number} (receivable {receivable number}, confirmation request {request number}) has been released: the approved records have been notarised and accepted by the asset digitisation platform. Your company is the creditor in this transaction. |

<a id="M9-NT03"></a>
## 资产出库失败（M9-NT03）

| 项目 | 规则 |
| --- | --- |
| 发送来源 | 运营审核与资产出库（M9）；其他模块不发同义消息 |
| 端 | 运营端 |
| 分类 | 运营告警 / Operations alerts |
| 收件范围 | 全体运营。不发给企业 |
| 触发 | 一次出库处理的存证结果为“失败”，或供数结果为“未接收”，出库状态变为“出库失败”时发送 |
| 不触发 | 出库处理中、结果尚未返回；出库成功；出库或重新出库未生效的任何情况；资产不满足出库条件 |
| 同一事实的区分依据 | 全体运营 + 申请编号 + 出库处理次序 + “资产出库失败”。同一次出库处理只发一条；重新出库后再次失败是新的出库处理，另发一条 |
| 发生时间 | 失败结果返回的时间（存证失败时间或资产数字化平台返回时间） |
| 原业务识别信息 | 申请编号、发票号 |
| 打开后去哪 | 原业务：本模块中该申请的详情，定位到出库信息 |
| 查看与办理条件 | 查看：可正常使用的运营人员。办理：重新出库另需出库状态为“出库失败”且满足出库条件；已由其他运营人员重新出库、已出库或不再满足出库条件时，前往后只能查看当前结果，按 M10 [前往原业务（MSG-05）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-05)处理 |
| 必须出现的业务值 | 申请编号、发票号、应收账款编号、债权人企业名称、出库处理次序、失败环节（存证／供数）、失败原因 |
| 业务值取值 | 取失败结果返回时的值；失败原因按返回原文展示，未返回原因时为“未返回失败原因”；之后不改写 |
| 不得出现 | 完整钱包地址；发票、合同等原件或下载地址 |

文案（按收件人的界面语言展示；花括号为业务值，企业名称、发票号、失败原因按原值展示不翻译；失败环节随界面语言展示为“存证／供数”或“Notarisation／Data supply”）：

| 语言 | 标题 | 正文 |
| --- | --- | --- |
| 中文 | 资产出库失败 | 债权人 {债权人企业名称} 的发票 {发票号}（应收账款编号 {应收账款编号}，确权申请 {申请编号}）第 {出库处理次序} 次出库失败，失败环节：{失败环节}，原因：{失败原因}。资产尚未出库，请查看后在条件满足时重新出库。 |
| English | Asset release failed | Release attempt {attempt number} for creditor {creditor name}'s invoice {invoice number} (receivable {receivable number}, confirmation request {request number}) failed at {failed step}. Reason: {failure reason}. The asset has not been released. Please review it and retry when the release conditions are met. |
