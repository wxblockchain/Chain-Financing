## 1. 模块是什么

本模块是运营端资产数据的主入口，也为企业端（M7a、M7b）提供应收账款的数据口径。平台把 ERP 中每一张已审核的内销发票作为一笔应收账款，在一处回答四个问题：这笔资产值多少、何时到期、债务人已经还了多少、背后的车辆卖得怎样和是否足额投保。运营人员先在这里判断一笔资产的状况，再通过单据编号进入合同信息、车辆履约、提单信息、保单信息、资金收付核实细节。本模块不重复展示这些模块的完整内容，只展示它们对本笔资产的结论（进度、比率），并承接风控预警（M8）提供的预警信息。债权人企业用户在 M7a、债务人企业用户经确权申请只读查看与本企业有关的应收账款，取值与本模块相同，可见范围不因资产全景扩大。本模块也是确权申请（M7a）、债务人确认（M7b）、运营审核（M9）共同引用的应收账款资料来源。

基本原则：

- 一张已审核的内销发票就是一笔应收账款。内销发票的内销卖方对应的平台企业是债权人，内销买方对应的平台企业是债务人；应收账款金额及原币取自内销发票。
- 应收账款金额、已收款、待收款在两端统一以 USD 展示，按查看时 M11 的当前汇率折算。USD 是展示与汇总口径，不改变内销发票的原币债权，也不改写来源单据。
- 能否进入申请与运营审核，系统分三类校验：必备资料齐全且有效由本模块定义（见[资料齐全且有效（F-M3-15）](#F-M3-15)）；资料之间是否矛盾由风控预警（M8）的阻断类规则判断；到期、回款、核心资料等业务状态由本模块定义。三类中任一项不满足，都不能审核通过；运营审核只确认系统核对不了的部分。
- 核心资料（发票日期、买卖双方、币种、金额、账期、车辆与内采单价）在正常业务中视为不变；提单装船日期取得后也不变更；已采信的值不被新取得的值静默覆盖，来源出现冲突时按异常处理，见[核心资料差异核实（F-M3-07）](#F-M3-07)。回款、物流、附件和由它们计算的比率随来源更新。
- 平台企业与 ERP 企业的对应由运营人员在 M2 关联；应收账款按内销发票上的 ERP 企业与关联结果对应到平台企业，不按名称比对。
- 应收账款起算日、到期日由平台按提单装船日期和内销发票账期计算；内销发票上 ERP 给出的账款起算日、到期日同时展示供对照，不用 ERP 值替代平台计算值。
- 回款是债务人为本内销发票向债权人支付的内销收款；外销收款（终端客户向债务人付款）只用于终端回款进度，不计入本笔应收账款的回款。
- 回款状态按应收账款原币判定：币种不同的回款按收付日期当日汇率换算，已收款比率达到 99.00% 即为已收清（上下浮动 1% 的收清容差）；之后的汇率变化不改变回款状态。
- 一个事实只在一个模块完整展示。本模块对其他模块的单据只展示摘要和结论，点击单据编号进入其所在模块的详情。
- 风控规则的判定、提示与处理全部由风控预警（M8）负责；本模块不自行判定任何风控条件，只承接 M8 提供的预警信息。
- 平台不生成、不签署、不修改任何单据。任何角色都不能新增、修改或删除应收账款、发票、车辆、合同和款项资料；运营人员只能对核心资料差异记录核实。

**一个完整的例子**（企业名称、编号、金额与日期为演示值）。运营人员已在 M2 为平台企业 Carloha Holding、Carloha Nigeria 分别关联了 ERP 中的同名企业。ERP 中有一张已审核的内销发票 PI-0012：内销卖方 Carloha Holding、内销买方 Carloha Nigeria，关联内销合同 SC-0008，内销发票日期 2026-09-05，金额 90,000.00 USD，账期 90 天，ERP 账款起算日 2026-09-10、账款到期日 2026-12-09，车辆 VIN-A、VIN-B、VIN-C 的内采单价各 30,000.00 USD。平台形成应收账款 AR-0012，按关联结果对应到债权人 Carloha Holding、债务人 Carloha Nigeria。VIN-A、VIN-B 在提单 BL-01 上于 2026-09-10 装船；在 VIN-C 装船前，起算日展示“未确定（尚有 1 辆车未装船）”，这笔应收账款不能申请确权。VIN-C 在提单 BL-02 上于 2026-09-20 装船，之后在中转港换装到提单 BL-03（装船日期 2026-10-05）；VIN-C 按初始提单 BL-02 计，车辆清单中 VIN-C 只列 BL-02，转运航段在提单信息（M12）中查看；平台确定应收账款起算日为三辆车中最晚的 2026-09-20，到期日为 2026-12-19。内销发票部分同时展示 ERP 账款起算日 2026-09-10、账款到期日 2026-12-09，供运营人员对照。债务人先后两次付款，ERP 在本发票下登记内销收款 25,000.00 USD 和 20,000.00 USD：已收款金额 45,000.00 USD，待收款金额 45,000.00 USD，已收款比率 50.00%（45,000.00 USD／90,000.00 USD），回款状态“部分收款”。VIN-A、VIN-B 已外销出库，终端销售进度 66.66%（已售 2 辆／共 3 辆）；两车外销收款合计 47,000.00 USD（VIN-A 32,000.00 USD、VIN-B 15,000.00 USD），终端回款进度 52.22%。保单按内采单价的 110% 投保，保险覆盖率 110.00%。2026-12-14（剩余 5 天）运营人员打开“应收账款”，看到 AR-0012 的到期日 2026-12-19（剩余 5 天）被突出显示；M8 对 AR-0012 有 1 条未处理预警，列表预警列显示“1 条”。进入详情后，概要中关联预警为“未处理 1 条、已处理 0 条”，运营人员点“未处理 1 条”进入 M8 查看该预警；返回后点 VIN-B 进入车辆履约（M5）查看该车的外销合同与收款，返回后点回款记录中的交易流水号进入资金收付（M14）核对付款凭证，再点内销合同号 SC-0008 进入合同信息（M4）。债权人企业用户在 M7a 查看同一笔应收账款时，应收账款金额、起算日、到期日、账期、已收款和待收款与本模块取值相同，可见内容按 M7a。

### 1.2 本期不做

- 车辆归属判定（外采合同买方、外销合同卖方与本应收账款主体的比对）：本模块不做。车辆按 VIN 关联外采合同、外销合同；主体是否一致由风控预警（M8）的主体比对规则判断。
- 二手车业务；外采发票（关联外采合同的发票）不形成应收账款，在合同信息（M4）的外采合同中展示。
- 在平台录入、编辑、删除或补传任何单据、车辆、合同和款项资料；企业端和运营端都没有这类操作。
- 合同、提单、保单、外采、外销、资金收付的完整信息与其计算规则：分别由合同信息（M4）、车辆履约（M5）、提单信息（M12）、保单信息（M13）、资金收付（M14）定义，本模块只展示摘要、结论和跳转。
- 平台企业与 ERP 企业的关联与取消关联操作：由 M2 定义，本模块只使用关联结果。
- 风控规则的判定、提示与处理：功能清单列在应收账款下的风控逻辑（账款日期不一致、合同日期存疑、价格倒挂、保险未足额覆盖、回款风险、车辆出库与收款等）由风控预警（M8）完善，本模块只承接 M8 提供的预警信息。
- 航程与到港等外部航程跟踪数据：由提单信息（M12）展示，本模块不展示。
- 汇率维护：由 M11 汇率管理定义。
- 确权申请、债务人确认、运营审核的操作和状态定义：分别由 M7a、M7b、M9 定义；本模块展示其结果。
- 企业端的应收账款详情：债权人视角（含不可申请原因、历次申请与发起申请入口）由 M7a [应收账款详情（F-M7a-09）](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#F-M7a-09) 定义，债务人视角由 M7b [应收账款详情（F-M7b-05）](../../企业端/M7b-确权待办与确认处理/01-确权待办与确认处理-PRD.md#F-M7b-05) 定义，取值按本模块当前资料。
- 业务总览：由[运营端首页（M17）](../../运营端/M17-运营端首页/01-运营端首页-PRD.md)承载，本模块提供明细与统计口径；本期不做企业端总览。
- 车辆的转运航段与历史外销合同在本模块的展示：本模块只展示计算起算日所用的初始提单和当前有效的外销合同，其他在提单信息（M12）、车辆履约（M5）中查看。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 应收账款 | 由一张已审核的内销发票形成的债权。一张内销发票对应一笔应收账款 |
| 应收账款编号 | 平台为每笔应收账款生成的编号（功能清单中称“应收账款资产编号”），与内销发票一一对应，全平台唯一，生成后不变 |
| 内销发票 | 内销卖方开给内销买方、关联内销合同的发票（Proforma Invoice）。关联外采合同的发票是外采发票，不属于本模块 |
| 内销合同 | 内销卖方与内销买方之间的新车内销合同。一张内销发票关联一份内销合同 |
| 内销卖方、内销买方 | 内销发票上的卖方、买方，即 ERP 中的企业 |
| 债权人、债务人 | 内销卖方、内销买方分别对应的平台企业，见[买卖双方与平台企业的对应](#party-match) |
| 平台企业 | 运营人员在 M2 邀请入驻的企业，企业用户、业务角色（债权人、债务人）与 ERP 企业关联都按 M2 定义，见 M2 [关联 ERP 企业（F-EN-10）](../../运营端/M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-EN-10) |
| 账期 | 内销发票上的账款天数（整数天，如 90 天），功能清单中也称“合同账期（tenor）” |
| 应收账款起算日、应收账款到期日 | 平台计算的起算日与到期日，见[账期与到期状态（F-M3-04）](#F-M3-04)。内销发票上 ERP 给出的称“ERP 账款起算日”“ERP 账款到期日”，只供对照 |
| 初始提单 | 一辆车首次装船时的提单。车辆转运时会出现在多张提单上，本模块取其中装船日期最早的一张为初始提单，用于计算应收账款起算日，也是车辆清单中唯一展示的提单 |
| 回款、回款记录 | 债务人为本内销发票向债权人支付的内销收款。每条回款记录是一笔内销收款中登记到本内销发票的部分，金额为该笔收款分配到本内销发票的金额 |
| 外采 | 债权人向外采供应商采购车辆，单据为外采合同、外采发票 |
| 外销、终端 | 债务人把车辆卖给终端客户，单据为外销合同、外销出库、外销收款。“终端销售”“终端回款”分别指外销出库和外销收款 |
| 价格对比 | 一辆车的外采单价、内采单价、外销单价，统一以美元对照 |
| 外采单价 | 本车的外采价格，取值按车辆履约（M5）[价格链内容](../../运营端/M5-车辆履约/01-车辆履约-PRD.md#price-chain) |
| 内采单价 | 本车在内销发票车辆明细中的单价，即债务人从债权人处采购本车的价格 |
| 当前有效外销合同 | 一辆车当前有效的那一份外销合同；同一时期一辆车只有一份，历史外销合同保留在来源模块。判定按合同信息（M4）、车辆履约（M5），见[当前有效外销合同的判定（Q-M3-14）](#Q-M3-14) |
| 外销单价 | 本车在当前有效外销合同中的车辆单价，按车辆履约（M5）[价格链内容](../../运营端/M5-车辆履约/01-车辆履约-PRD.md#price-chain) |
| 物流节点 | 一辆车当前所处的物流节点，由车辆履约（M5）判定，本模块原样展示 |
| 美元折算值 | 标注“（美元）”或“USD”的金额，由平台按[美元折算与比率](#usd-rule)得出；两端统一以它展示应收账款金额、已收款和待收款 |
| 预警信息 | 运营端对本笔应收账款是否存在需关注事项的有／无标识，由 M8 关联预警和本模块核心资料状态得出，见[预警信息（F-M3-14）](#F-M3-14) |
| 关联风控预警 | M8 生成、关联到本笔应收账款的风控预警。预警的规则、内容和处理都以 M8 为准 |
| 核心资料 | 内销发票中决定应收账款身份、金额与期限的资料，见[差异的产生与展示](#core-diff)。正常业务中视为不变；已有值出现冲突时进入核实 |
| 确权申请结果 | 本笔应收账款最近一笔确权申请当前的申请状态，见[确权申请结果（F-M3-10）](#F-M3-10) |
| 原资料 | 本笔应收账款首次形成（或该项首次取得）时的核心资料，始终是展示与后续业务的依据 |
| VIN | 车辆识别代号，用来从本应收账款的车辆进入车辆履约（M5） |

## 3. 共用规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。其中[采信范围](#adopt-scope)、[来源值、金额与时间](#display-values)、[美元折算与比率](#usd-rule)、[单据编号跳转](#doc-links)是六个运营端资产数据模块（应收账款、合同信息、车辆履约、提单信息、保单信息、资金收付）共用的规则，[详情三层结构](#detail-groups)是其中五个模块（资金收付除外，其详情结构按 M14 [详情结构（M14-Q06）](../../运营端/M14-资金收付/01-资金收付-PRD.md#M14-Q06)）共用的规则；其他模块可直接引用本节。

<a id="adopt-scope"></a>
### 3.1 采信范围

- 平台只采信 ERP 中已审核的单据。未审核的内销发票不形成应收账款；未审核的提单、付款、合同、外采、外销单据不参与本模块的任何展示和计算。

<a id="display-values"></a>
### 3.2 来源值、金额与时间

- ERP 提供的值按原值展示，不翻译、不改写。
- ERP 没有提供某项值时，该项展示“未提供”；附件没有取得时展示“附件未取得”；关联单据在平台中不存在时，在对应位置展示“未取得”（如“内销合同未取得”）。
- 金额与币种代码同时展示，数值在前、币种代码在后，带千分位，例如“60,000.00 USD”。ERP 提供的金额按原值展示，不四舍五入、不截断。
- 应收账款金额、已收款金额、待收款金额，以及车辆清单中的单价与收款，两端统一以美元折算值展示；原币金额只在内销发票、内销合同和回款记录中作为核对依据展示。
- 不同币种的原币金额不直接相加；需要合计时按美元折算值合计。
- ERP 提供的日期（发票日期、合同日期、装船日期、出库日期、收付日期等）按原样展示，不做时区换算。
- 平台计算的日期（应收账款起算日、应收账款到期日）只有日期，不带时区；涉及“今天”的判断（到期状态、剩余天数、临近到期）统一按 UTC+1 的当前日期。
- 平台自己记录的时间（首次取得时间、附件取得时间、核实时间）展示到分钟，按查看者本人的时区展示并标明时区；时区设置按 M1 [界面语言与时区（M1-F12）](../../企业端/M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#M1-F12)（企业端）、M2 [界面语言与时区（F-OP-10）](../../运营端/M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-10)（运营端）。时区只影响展示，不改变到期等判断。
- 界面语言（English、简体中文）按 M1 [界面语言与时区（M1-F12）](../../企业端/M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#M1-F12)、M2 [界面语言与时区（F-OP-10）](../../运营端/M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-10)切换；企业名称、编号、文件名、金额、日期等业务值按原值展示，不翻译。语言不改变金额、币种、日期和任何判断。
- 本册的业务文字以中文写定含义；英文界面文字以 Hallmark 原型的文案为准，须与中文含义一致。本册直接写出的固定文字（如不可访问说明、附件打开失败提示、核实冲突提示、企业可见差异说明，以及“合同价”“合同合计”“N 辆车在多张保单中”“含 N 份跨发票的批售合同”等标注）在英文界面同样展示，英文措辞按原型文案。

<a id="placeholder"></a>
#### 缺失值的展示（运营端）

- 运营端取不到或算不出的值，统一以占位符“-”展示，不展示文字。本册各表“缺失时”一栏及正文中写作“未提供”“无法计算”“无法折算”“附件未取得”“未取得”的，都是缺失原因，页面上均显示为“-”；读屏读出对应的原因文字。
- 原因需要让运营人员知道时，写在“-”下方，例如保险覆盖率下方注明“N 辆车在多张保单中”。
- 以下是业务状态，照常以文字展示，不改为“-”：未确定（含“尚有 N 辆车未装船”）、到期日未确定、暂无物流记录、未装船、未投保、暂无外采、未交货、未出库、未收款、暂无外销、暂无回款记录、未申请、待核实、无。
- 企业端的缺失值展示按 M7a、M7b。

<a id="usd-rule"></a>
### 3.3 美元折算与比率

- 美元折算值按查看时 M11 [对外提供的汇率口径（FX-05）](../../运营端/M11-汇率管理/01-汇率管理-PRD.md#FX-05)中的当前汇率（1 USD = R NGN）折算：原币为 USD 时等于原值；原币为 NGN 时等于原币金额 ÷ R；M11 为“无可用汇率”时 NGN 金额展示“无法折算”；其他币种 M11 没有汇率，展示“无法折算”（ERP 是否存在 USD、NGN 以外的币种待验证，见[USD、NGN 以外的币种（Q-M3-16）](#Q-M3-16)）。
- 汇率按页面取用：每次打开或刷新一个页面（列表页、详情页）时取一次当前汇率，该页面内所有美元折算值、合计与比率都用这一个汇率。从列表进入详情、或刷新页面时重新取当前汇率；两次之间 M11 生效了新汇率时，列表与详情的美元值可以不同，但同一页面内不会混用两个汇率。
- 无法折算时不以 0 或原币数值代替美元金额，也不据此判定“已收清”。
- 美元金额（含已收款金额、待收款金额与各项合计）无法得出时展示“无法折算”；比率无法得出时展示“无法计算”。两者都是缺失原因，运营端按[缺失值的展示](#placeholder)显示为“-”，企业端显示文字。
- 美元折算值保留两位小数，四舍五入；合计与比率用未取舍的值计算，展示时再取舍。
- 比率以百分数展示，保留两位小数、向下截取（例如 99.996% 展示为 99.99%），保证未达到 100% 时不会显示为 100.00%；超过 100% 时按实际值展示，不封顶。
- 比率的分子或分母无法取得（未提供、无法折算）时，比率展示“无法计算”。
- 分母为 0 时，比率展示“无法计算”。

### 3.7 加载失败

- 详情中某一部分（例如车辆清单、回款记录、确权申请结果）或某一项来自其他模块的值加载失败时，仅该处提示失败并可重试，其他部分正常展示；依赖该值的比率展示“无法计算”。

<a id="F-M3-01"></a>
## 4. 应收账款的形成与识别（F-M3-01）

适用范围：平台从 ERP 取得内销发票时的处理规则。结果对全部角色可见，没有用户操作。取得方式由研发决定，本 PRD 不限定。

流程参见：[应收账款形成与差异识别（图 M3-1）](./02-应收账款与发票-流程图与状态机.md#fig-m3-1)。
验收参见：[应收账款的形成与识别](./04-应收账款与发票-验收.md#acc-f-m3-01)。

<a id="receivable-identity"></a>
### 4.1 一张内销发票一笔应收账款

- 平台只对已审核的内销发票形成应收账款；外采发票不形成应收账款。
- 平台以“内销卖方 + 内销发票号”识别同一张内销发票；首次取得时形成一笔应收账款并生成应收账款编号。
- 内销发票缺少发票号或金额时不形成应收账款，在数据监控（M15）[接口调用记录（F-M15-02）](../../运营端/M15-数据监控/01-数据监控-PRD.md#F-M15-02)中按未接收计入。
- 再次取得同一张内销发票、且核心资料与原资料一致时，不形成新的应收账款，也不产生差异记录。
- 再次取得同一张内销发票、但核心资料任一项已有值与原资料不一致时，不形成新的应收账款，按[核心资料差异核实（F-M3-07）](#F-M3-07)进入“差异待核实”。
- 应收账款的原币取内销发票币种；两端展示的应收账款金额统一为其美元折算值。

<a id="party-match"></a>
### 4.2 买卖双方与平台企业的对应

- 运营人员在 M2 新增或编辑平台企业时，为其关联 ERP 企业，规则见 M2 [关联 ERP 企业（F-EN-10）](../../运营端/M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-EN-10)：一个平台企业只能关联一个 ERP 企业，一个 ERP 企业同一时刻只能关联一个平台企业。
- 平台按内销发票上内销卖方、内销买方的 ERP 企业与关联结果对应：内销卖方所关联的平台企业为债权人，内销买方所关联的平台企业为债务人。不按企业名称、登记号比对。
- 债权人、债务人展示平台企业名称。
- 双方都已对应时，本笔应收账款出现在对应企业的入口中（入口与可见内容按 M7a、M7b，见[企业端查看（F-M3-09）](#F-M3-09)）。
- 任一方的 ERP 企业没有关联任何平台企业时，本笔应收账款照常形成并对运营人员可见；该方展示 ERP 上的企业名称，详情中标“未对应平台企业”及具体是哪一方（列表不展示该标识）；对应不上的一方企业看不到本笔应收账款。之后运营人员在 M2 为某平台企业补充关联该 ERP 企业时，本笔应收账款立即自动对应并出现在其入口中。
- 运营人员在 M2 取消某平台企业与 ERP 企业的关联后，以该 ERP 企业为内销卖方或内销买方的应收账款立即不再对应该平台企业，该方改为展示 ERP 企业名称并标“未对应平台企业”；什么情况下不能取消关联按 M2。
- M2 保存关联前展示的“每个 ERP 企业当前涉及的应收账款笔数”，按本节口径分别统计该 ERP 企业作为内销卖方、内销买方的应收账款笔数。
- 同一平台企业同时拥有债权人、债务人角色，不改变它在某张内销发票中的身份：它只能以卖方身份查看本企业开出的发票形成的应收账款，以买方身份查看本企业收到的发票形成的应收账款。

<a id="data-update"></a>
### 4.3 资料更新

- 内销合同、提单、保单、回款记录、外采与外销单据、附件，以及内销发票中原来缺失、后来补齐的项，随 ERP 更新后直接成为当前展示内容，本模块的计算值随之更新。
- 各角色只看到当前资料，平台不提供资料更新的历史记录，也不展示变化前的内容。
- 核心资料已有值的变化不按资料更新处理，按[核心资料差异核实（F-M3-07）](#F-M3-07)处理。

## 7. 账期与到期状态（F-M3-04）

适用角色与前提：运营人员；企业端可见范围按 M7a、M7b。全部只读。

流程参见：[应收账款起算日与到期日的确定（图 M3-7）](./02-应收账款与发票-流程图与状态机.md#fig-m3-7)、[到期状态（图 M3-4）](./02-应收账款与发票-流程图与状态机.md#fig-m3-4)。
验收参见：[账期与到期状态](./04-应收账款与发票-验收.md#acc-f-m3-04)。

<a id="start-date"></a>
### 7.1 应收账款起算日与到期日

- 应收账款起算日 = 本内销发票全部车辆装船日期中最晚的一个。车辆按 VIN 对应到提单（提单的完整信息见提单信息（M12））。
- 一辆车出现在多张提单上（如转运）时，取该车初始提单的装船日期。
- 车辆分多张提单陆续装船时，全部车辆都有装船日期后才确定起算日；之前起算日展示“未确定（尚有 N 辆车未装船）”，到期日、到期状态同为未确定；这期间本笔应收账款不满足 M7a [可申请的条件](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#eligibility)中的“未到期”，不能申请确权。车辆没有已审核的提单、或其初始提单没有装船日期，都按未装船计。
- 应收账款到期日 = 应收账款起算日 + 账期（整数天，按日历日计算）。起算日未确定、或内销发票没有账期时，到期日为“未确定”。
- 提单装船日期取得后不变更。全部车辆都有装船日期、起算日确定之后，起算日和到期日不再改变。
- 转运后新提单的装船日期不参与起算日计算，也不推迟到期日。

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 账期 | 内销发票上的账款天数，如“90 天” | 展示“未提供” |
| 应收账款起算日 | 平台计算值 | “未确定（尚有 N 辆车未装船）” |
| 应收账款到期日 | 平台计算值 | “未确定” |
| ERP 账款起算日 | 内销发票上 ERP 给出的账款起算日，在[基础交易（F-M3-12）](#F-M3-12)中展示，只供对照，不改变应收账款起算日 | 展示“未提供” |
| ERP 账款到期日 | 内销发票上 ERP 给出的账款到期日，在[基础交易（F-M3-12）](#F-M3-12)中展示，只供对照，不改变应收账款到期日和到期状态 | 展示“未提供” |

<a id="due-status"></a>
### 7.2 到期状态

| 到期状态 | 条件 |
| --- | --- |
| 到期日未确定 | 应收账款到期日未确定（含尚有车辆未装船） |
| 未到期 | 当前日期（UTC+1）早于或等于到期日 |
| 已到期 | 当前日期（UTC+1）晚于到期日 |

- 到期时点为到期日当天结束（UTC+1 的 24:00）：到期日当天仍为“未到期”。
- 到期状态由“未到期”变为“已到期”时，处理中的确权申请按 M7a [到期自动关闭（F-M7a-08）](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#F-M7a-08)关闭；本模块不直接撤销申请。

<a id="days-left"></a>
### 7.3 剩余天数与临近到期

- 未到期时展示“剩余 N 天”，N = 到期日 − 当前日期（UTC+1）；到期日当天为“剩余 0 天”。
- 已到期时展示“已到期 N 天”，N = 当前日期（UTC+1）− 到期日。
- 到期日未确定时不展示剩余天数。
- 剩余 0—7 天为“临近到期”，在列表和概要中突出显示。

## 8. 回款信息（F-M3-05）

适用角色与前提：运营人员可见全部回款信息；企业端可见范围按 M7a、M7b。回款信息只读，随 ERP 更新。

流程参见：[回款状态（图 M3-5）](./02-应收账款与发票-流程图与状态机.md#fig-m3-5)。
验收参见：[回款信息](./04-应收账款与发票-验收.md#acc-f-m3-05)。

- 回款只计债务人为本内销发票支付、已审核的内销收款；为其他内销发票支付的款项不计入本笔。
- 一笔内销收款对应多张内销发票时，本笔只计 ERP 登记到本内销发票的分配金额，见资金收付（M14）[关联业务（F-M14-04）](../../运营端/M14-资金收付/01-资金收付-PRD.md#F-M14-04)；只对应本内销发票时即为该笔收款全额。

<a id="repay-summary"></a>
### 8.1 已收、待收与比率

<a id="receipt-booking"></a>
每条回款按以下方式计入本笔应收账款（计入金额），已收款比率与回款状态都按应收账款原币判定，不随之后的汇率变化：

- 回款币种与应收账款币种相同：计入金额为该条回款金额（分配到本发票的金额）。
- 回款币种与应收账款币种不同：按该条回款收付日期（UTC+1）当日最后时刻（23:59:59.999）M11 适用的汇率，换算为应收账款原币作为计入金额；次日 00:00 起生效的汇率不适用。收付日期早于 M11 第一条汇率记录时，该条回款无法计入；汇率取 M11 [对外提供的汇率口径（FX-05）](../../运营端/M11-汇率管理/01-汇率管理-PRD.md#FX-05)中某一时刻适用的汇率。换算结果保留两位小数、四舍五入，合计与比率用未取舍的值计算。
- 收付日期未提供、当时 M11 为“无可用汇率”，或回款币种 M11 没有汇率时，该条回款无法计入，已收款比率为“无法计算”。
- 收付日期为今天或晚于今天（UTC+1）的回款，收付日期当日的汇率尚未确定：在收付日期当日结束前，按查看时适用的汇率暂计，计入金额旁注明“暂计”，已收款比率与回款状态按暂计值判定；其间 M11 生效新汇率后，之后的查看按新汇率暂计。收付日期当日结束后，按当日最后时刻适用的汇率确定，不再注明“暂计”，此后不再随汇率变化。口径与资金收付（M14）一致。
- 各条计入金额、各条金额（美元）与合计在未取舍的值上相等；页面上每个值各自四舍五入到两位，逐条展示值相加与合计展示值之间可以有 0.01 级的取舍差，不作为错误。

| 业务信息 | 含义 | 缺失或无法计算时 |
| --- | --- | --- |
| 已收款金额（美元） | 本发票下全部回款计入金额合计（应收账款原币）的美元折算值，按[美元折算与比率](#usd-rule)以查看时的当前汇率折算 | 没有回款记录时为 0.00 USD；任一条无法计入，或合计无法折算时展示“无法折算” |
| 待收款金额（美元） | 应收账款金额（美元）− 已收款金额（美元）；结果小于 0 时展示 0.00 USD | 应收账款金额或已收款金额无法折算时展示“无法折算” |
| 已收款比率 | 回款计入金额合计 ÷ 应收账款原币金额 | 展示“无法计算” |

- 已收款比率与“已收款金额（美元）÷ 应收账款金额（美元）”始终一致，因为两者都由原币按同一个当前汇率折算。
- 已收款金额超过应收账款金额时，已收款比率按实际值展示（如 102.00%），待收款金额为 0.00 USD。
- M11 当前为“无可用汇率”时，已收款比率与回款状态仍按原币判定；需要当前汇率的已收款金额、待收款金额展示“无法折算”。
- 在 1% 容差内判为“已收清”（见[回款状态](#repayment-status)）但仍有差额时，待收款金额按实际差额展示，并注明“在 1% 容差内视为已收清”。

<a id="repayment-status"></a>
### 8.2 回款状态

回款状态在概要中展示，两端看到同一个回款状态：

| 回款状态 | 判定条件 |
| --- | --- |
| 未收款 | 本发票下没有回款记录 |
| 部分收款 | 本发票下有回款记录，且已收款比率低于 99.00%，或已收款比率无法计算 |
| 已收清 | 已收款比率达到或超过 99.00% |

- 收清容差为上下浮动 1%：已收款比率在 99.00%—101.00% 之间视为正好收清，低于 99.00% 为部分收款；超过 101.00% 同样为“已收清”，按实际比率展示，不另设多收状态。比较用未取舍的比率，正好等于 99.00% 时为“已收清”。
- 容差对所有币种的应收账款都适用；汇率变化不改变回款状态，只有回款记录或分配金额的变化会改变它。
- 回款状态与到期状态相互独立，两者同时展示；已到期且未收清时不另设“逾期”状态。
- 回款状态是 M7a [可申请的条件](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#eligibility)、M9 [可以审核通过的条件](../../运营端/M9-运营审核/01-运营审核-PRD.md#review-conditions)引用的状态。

<a id="field-receipt"></a>
### 8.3 回款记录

每条回款记录一行，按收付日期从新到旧排列。只在运营端展示摘要，凭证、银行和账号在资金收付（M14）中查看。

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 交易流水号 | 这笔回款的交易流水号（定义按资金收付（M14）），可进入资金收付详情 | 展示“未提供” |
| 收付日期 | 回款日期 | 展示“未提供” |
| 付款方 → 收款方 | 付款主体与收款主体 | 展示“未提供” |
| 金额及币种 | 本条回款分配到本内销发票的原币金额，币种与该笔收款相同 | 不会缺失（缺金额或分配金额的收款不进入资金收付（M14），也不出现在回款记录） |
| 计入金额 | 回款币种与应收账款币种不同时展示：按收付日期汇率换算成的应收账款原币金额，并注明所用汇率及其生效时间；币种相同时不单独展示 | 无法计入时展示“无法计算”，并注明原因（收付日期未提供或当时无可用汇率） |
| 金额（美元） | 本条回款计入金额的美元折算值（当前汇率）；各条未取舍的值相加等于已收款金额（美元），展示值之间可有 0.01 级的取舍差 | 展示“无法折算” |

- 没有回款记录时展示“暂无回款记录”。

<a id="F-M3-11"></a>
## 9. 资产健康度（F-M3-11）

适用角色与前提：运营人员。四项指标在详情“进度与核对”层并列展示，列表不展示；企业端不可见。

验收参见：[资产健康度](./04-应收账款与发票-验收.md#acc-f-m3-11)。

| 指标 | 计算 | 同时展示的数值依据 |
| --- | --- | --- |
| 已收款比率 | 见[已收、待收与比率](#repay-summary) | 已收款金额（美元）／应收账款金额（美元） |
| 终端销售进度 | 本发票已完成销售的车辆数 ÷ 本发票车辆总数 | 已售 X 辆／共 Y 辆 |
| 终端回款进度 | 终端回款金额（美元）÷ 应收账款金额（美元），终端回款金额见[终端回款金额的计入](#terminal-receipt) | 终端回款金额（美元）／应收账款金额（美元），并注明这是相对应收账款金额的覆盖程度 |
| 保险覆盖率 | 应收账款保险金额（美元）÷ 应收账款金额（美元） | 应收账款保险金额（美元）／应收账款金额（美元） |

- 每项指标都同时展示百分数及其分子、分母；比率按未取舍的分子、分母计算，不用展示后的取舍值重算。
- 分子或分母取不到时，该数值按[缺失值的展示](#placeholder)展示，比率为“无法计算”，不按 0 计。
- 终端回款进度不是终端客户已付款的比例；超过 100% 时按实际值展示。

- 完成销售按车辆当前物流节点判定：车辆在车辆履约（M5）[物流记录与当前物流节点](../../运营端/M5-车辆履约/01-车辆履约-PRD.md#node-rule)中的当前物流节点为“已外销出库”，即为已完成销售；口径与合同信息（M4）的已售判定一致。
- 签订外销合同不算完成销售。车辆外销出库后又销售退库、当前物流节点回到“已入库”时，不再算已售；再次外销出库后重新计入。一辆车有多条外销出库记录时只计 1 辆。

<a id="terminal-receipt"></a>
终端回款金额的计入：

- 终端回款按金额计算，以外销合同为单位，口径与合同信息（M4）[终端回款金额的计入](../../运营端/M4-合同信息/01-合同信息-PRD.md#terminal-receipt)一致，范围为本发票的车辆。
- 先找出本发票每辆车的当前有效外销合同（见[车辆清单（F-M3-13）](#F-M3-13)），较早的外销合同不计入。
- 零售合同：计入该合同的外销已收款金额（美元）。
- 批售合同：计入该合同的外销已收款金额（美元）× 本发票车辆在该批售合同中的外销单价合计 ÷ 该批售合同的外销合同金额，即按本发票车辆所占的外销单价比例分摊，不按辆数均分。分子只计当前有效外销合同就是该批售合同的本发票车辆。批售合同只含本发票车辆时比例为 100%，整份收款计入；同时含其他内销发票的车辆时，各发票按各自车辆的比例分摊，合计不超过该合同的实际收款。
- 同一份外销合同只计入一次，不按车辆重复计入。
- 有分摊比例低于 100% 的批售合同时，终端回款进度下方注明“含 N 份批售合同按外销单价比例分摊”；N 只数比例低于 100% 的批售合同。
- 分摊值只用于计算终端回款，不作为单车外销收款展示；车辆清单中批售车辆仍展示整份合同的合计。
- 计入的任一份外销合同已收款金额无法折算，或批售合同的外销合同金额为 0、无法取得时，终端回款金额为“无法折算”或“无法计算”，终端回款进度为“无法计算”。
- 本发票车辆都没有外销合同时，终端回款金额为 0.00 USD。
- 未开票的车辆不在本模块中，因此合同信息（M4）内销合同的终端回款金额不等于该合同各发票在本模块中的终端回款金额之和，两者不对账。

保险覆盖率的计入：

- 应收账款保险金额 = 本发票全部车辆的车辆保险金额（美元）合计。每辆车在每张保单中的车辆保险金额及所在保单数取自保单信息（M13）[车辆清单与车辆保险金额（F-M13-05）](../../运营端/M13-保单信息/01-保单信息-PRD.md#F-M13-05)。
- 车辆没有保单时，该车保险金额按 0 计入合计。
- 任一车辆有保单但车辆保险金额无法计算时，保险覆盖率展示“无法计算”。
- 任一车辆同时在多张保单中时，不汇总该车的车辆保险金额（不取最大值、也不相加），保险覆盖率展示“无法计算”，并注明“N 辆车在多张保单中”。
- 比率的精度与无法计算的处理按[美元折算与比率](#usd-rule)。

## 12. 预警信息（F-M3-14）

适用角色与前提：运营人员；企业端不可见。风控规则的判定、提示与处理全部由风控预警（M8）定义，本模块只承接 M8 提供的预警信息，不自行判定任何风控条件。

<a id="warning-flag"></a>
### 12.1 预警信息（有／无）

- 本笔应收账款在 M8 中有未处理的关联风控预警，或本模块核心资料状态为“差异待核实”时，预警信息为“有”；两者都没有时为“无”。
- 预警信息用于列表“预警（有／无）”筛选，并供 M9 引用；页面上按[预警的展示](#warning-display)呈现。

<a id="warning-display"></a>
<a id="related-warning"></a>
### 12.2 预警的展示

列表“预警”列：

| 情形 | 展示 |
| --- | --- |
| 有未处理的关联风控预警 | 未处理条数（如“1 条”），可进入 M8 查看本笔应收账款的关联预警，落点按[单据编号跳转](#doc-links) |
| 没有未处理的关联风控预警，核心资料状态为“差异待核实” | “待核实” |
| 没有未处理的关联风控预警，核心资料状态为“一致” | “无” |

详情概要“关联预警”：

- 第一行为“未处理 N 条”，N 大于 0 时可进入 M8 查看；第二行为“已处理 M 条”。
- 核心资料状态为“差异待核实”时，第一行为“待核实”，未处理、已处理条数照常列在下方。
- 没有任何关联风控预警、且核心资料状态为“一致”时，展示“无”。

共同规则：

- 条数只统计 M8 的关联风控预警，计数口径按 M8 [向其他模块提供的预警信息](../../运营端/M8-风控预警/01-风控预警-PRD.md#external)；核心资料差异不计入条数。
- 预警的类型、名称、比较口径、差异明细和处理结果以 M8 为准，本模块不复述、不改写，也没有处理预警的操作。
- 关联风控预警不改变本模块的任何金额、比率和状态，也不影响能否发起确权申请。
- M8 结果读取失败时，按[加载失败](#load-fail)仅该处提示失败并可重试，不展示为“无”。

## 14. 核心资料差异核实（F-M3-07）

适用角色与前提：运营人员。本笔应收账款的核心资料状态为“差异待核实”时可记录核实；状态为“一致”时没有核实入口，没有核实记录时详情不展示本部分。

核心资料在正常业务中视为不变，本节只处理来源出现冲突的异常：冲突时保留原资料、展示差异事实，并维持对申请与审核的保护，直到运营记录核实。本期只支持记录核实并继续采用原资料，不支持用新值替换原资料；原资料本身有误时的作废或重开路径未定义。

流程参见：[核心资料状态（图 M3-3）](./02-应收账款与发票-流程图与状态机.md#fig-m3-3)。
验收参见：[核心资料差异核实](./04-应收账款与发票-验收.md#acc-f-m3-07)。

<a id="core-diff"></a>
### 14.1 差异的产生与展示

- 核心资料包括：内销发票的内销发票日期、内销卖方、内销买方、币种、金额、账期，内销发票车辆明细中的 VIN 与内采单价（含车辆增减）。应收账款起算日由提单装船日期计算，不属于核心资料。
- 平台再次取得同一张内销发票，使上述任一项已有值与原资料不一致时，核心资料状态变为“差异待核实”。原来缺失、后来补齐的项属于资料更新，不算差异。
- ERP 账款起算日、ERP 账款到期日不是核心资料，变化时直接更新。
- 详情和列表继续以原资料展示和计算，不用新取得的值覆盖。
- 运营端展示每一项差异：资料项、原资料值、新取得值、取得时间；车辆差异逐车展示增加、减少或内采单价变化的 VIN。
- 已处于“差异待核实”时又取得新的差异，新差异追加展示。

<a id="verify-record"></a>
### 14.2 记录核实

运营人员针对本笔应收账款当前全部未核实的差异记录一次核实：

| 业务信息 | 类型与取值 | 必填与默认 | 校验与失败结果 |
| --- | --- | --- | --- |
| 核实说明 | 文本，说明核实过程、依据及与 ERP 来源方的沟通结果 | 必填，无默认 | 去除首尾空格后为 1—500 字；为空或超长时不能提交并提示 |
| 核实依据文件 | 附件 | 选填 | PDF、JPG、PNG；最多 5 个；单个不超过 20 MB（20 × 1024 × 1024 = 20,971,520 字节，正好等于时可以加入）；不符合时该文件不能加入并提示原因 |

结果：

- 提交后核心资料状态变为“一致”，原资料继续有效，不自动更正、不另建应收账款；差异和本次核实保留在核实记录中。
- 每次核实记录核实人、核实时间、说明、依据文件和所针对的差异，记录不可编辑、不可删除，按时间从新到旧展示。
- 之后又取得新的差异时，状态再次变为“差异待核实”。

边界与异常：

- 两名运营人员同时核实同一笔应收账款时，先提交者生效；后提交者提示“该差异已被他人处理，请刷新后查看”，本次内容不保存。
- 提交时又取得了新的差异，提交仍按提交时可见的差异生效，新差异使状态回到“差异待核实”。
- 提交失败时保留已填写内容，提示失败并可重新提交。

<a id="enterprise-diff"></a>
### 14.3 企业可见差异

- 企业端看到的差异说明按 M7a [应收账款详情（F-M7a-09）](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#F-M7a-09)、M7b [应收账款详情（F-M7b-05）](../../企业端/M7b-确权待办与确认处理/01-确权待办与确认处理-PRD.md#F-M7b-05)；本模块向它们提供核心资料状态，不向企业端提供差异明细、核实说明和依据文件。

<a id="core-impact"></a>
### 14.4 对后续业务的影响

- 核心资料状态是本模块向 M7a、M7b、M9 提供的信息，由 M7a [可申请的条件](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#eligibility)、M9 [可以审核通过的条件](../../运营端/M9-运营审核/01-运营审核-PRD.md#review-conditions)引用；状态为“差异待核实”时对申请与审核的影响按这两个模块。
- 申请提交后资料变化对申请的影响按 M7a [申请状态](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#apply-status)；本模块不撤销、驳回或终止任何申请。
- “差异待核实”是本模块的资料采信状态，不是风控预警，不计入 M8 关联预警条数；它只在列表预警列和预警信息（有／无）中提示运营人员。是否改由风控预警（M8）统一处理待定，见[核心资料异常是否改由 M8 处理（Q-M3-15）](#Q-M3-15)；确定前，M7a、M7b、M9 对它的现行处理不变。

## 15. 资料齐全且有效（F-M3-15）

适用角色与前提：平台判定，没有用户操作；结果在运营端详情概要中展示，并供确权申请（M7a）、运营审核（M9）引用。

验收参见：[资料齐全且有效](./04-应收账款与发票-验收.md#acc-f-m3-15)。

本节只管必备资料“有没有、值是否有效”。资料之间对不上（如发票金额与车辆明细不一致、发票与合同主体不一致）由风控预警（M8）的阻断类规则判断，见 M8 [阻断的作用](../../运营端/M8-风控预警/01-风控预警-PRD.md#blocking)；到期、回款、核心资料是否一致等业务状态见本模块[到期状态](#due-status)、[回款状态](#repayment-status)、[核心资料差异核实（F-M3-07）](#F-M3-07)。

<a id="info-items"></a>
### 15.1 校验项

以下各项按本模块当前展示的资料判断；核心资料状态为“差异待核实”时按原资料判断。

| 校验项 | 不通过的情形 | 问题项名称 |
| --- | --- | --- |
| 内销发票日期 | ERP 未提供 | 内销发票日期（缺失） |
| 账期 | ERP 未提供；或不是正整数 | 账期（缺失）；账期（无效） |
| 内销发票金额 | 不大于 0（缺少金额时不形成应收账款） | 内销发票金额（无效） |
| 内销发票币种 | ERP 未提供；或不是 M11 提供汇率的币种（USD、NGN） | 内销发票币种（无法折算） |
| 内销发票附件 | 附件未取得 | 内销发票附件（缺失） |
| 内销合同 | 关联的内销合同在平台中不存在 | 内销合同（缺失） |
| 内销合同日期 | 内销合同已取得但 ERP 未提供 | 内销合同日期（缺失） |
| 内销合同金额 | 内销合同已取得但 ERP 未提供；或不大于 0 | 内销合同金额（缺失）；内销合同金额（无效） |
| 内销合同币种 | 内销合同已取得但 ERP 未提供；或不是 M11 提供汇率的币种（USD、NGN） | 内销合同币种（无法折算） |
| 内销合同附件 | 附件未取得 | 内销合同附件（缺失） |
| 车辆明细 | 内销发票没有车辆，或任一辆车没有 VIN、没有内采单价，为缺失；任一辆车内采单价不大于 0，为无效 | 车辆明细（缺失）；车辆明细（无效） |

- 内销合同不存在时，只列“内销合同（缺失）”，不再列内销合同日期、金额、币种和附件。
- 同一校验项同时有缺失和无效时（如一辆车没有 VIN、另一辆车内采单价为 0），两个问题项都列，“缺失”在前、“无效”在后；同一种问题出现在多辆车上时只列一次。
- 内销合同付款条件、ERP 账款起算日与到期日、回款记录、外采与外销资料不是校验项，缺失不影响结果。
- M11 当前为“无可用汇率”不算不通过：币种为 USD、NGN 时，即使暂时没有可用汇率也视为可折算。USD、NGN 以外的币种是否出现，待验证，见[USD、NGN 以外的币种（Q-M3-16）](#Q-M3-16)。

<a id="info-result"></a>
### 15.2 校验结果

- 结果为“通过”或“不通过”。不通过时列出全部问题项，按上表自上而下的顺序排列；企业端与审核处的写法和分隔方式由引用模块定义。
- 资料按[资料更新](#data-update)变化后，结果随之重新判断；ERP 补齐或更正后自动变为“通过”。平台不提供补传，运营人员也不能手动改为“通过”。
- 判断所需的资料读取失败时，结果为“暂无法判断”，按[加载失败](#load-fail)处理；引用模块不能把它当作“通过”。
- 运营端详情概要展示校验结果；不通过时展示问题项。列表不新增列和筛选。
- 校验结果不改变本模块的到期状态、回款状态和核心资料状态，也不计入 M8 关联预警条数。

<a id="info-use"></a>
### 15.3 引用方式

- 确权申请：M7a 的申请条件引用本节结果，不通过时不能发起申请，不可申请原因的写法按 M7a。
- 运营审核：M9 在提交审核通过时按本节对当前资料再核对一次，不通过时不能审核通过，见 M9 [可以审核通过的条件](../../运营端/M9-运营审核/01-运营审核-PRD.md#review-conditions)，具体写法按 M9。
- 校验项的增减只在本节修改，引用模块不另列清单。

## 16. 企业端查看（F-M3-09）

企业端看到的应收账款详情由 M7a [应收账款详情（F-M7a-09）](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#F-M7a-09)（债权人）和 M7b [应收账款详情（F-M7b-05）](../../企业端/M7b-确权待办与确认处理/01-确权待办与确认处理-PRD.md#F-M7b-05)（债务人）定义，取值按本模块当前资料。本模块不再定义企业端的入口、可见内容和展示方式，只提供数据口径：应收账款金额、已收与待收、日期与状态的取值，[核心资料差异核实（F-M3-07）](#F-M3-07)的状态，以及[资料齐全且有效（F-M3-15）](#F-M3-15)的结果。M7a 当次依据中的各项（含车辆清单的 VIN 与内采单价、内销合同日期与金额等），取值与缺失时的写法按本模块对应字段的定义。

<a id="status-combo"></a>
## 17. 状态组合与对后续业务的影响

一笔应收账款同时有核心资料状态、到期状态、回款状态三个独立维度，以及由 M7a、M7b、M9 提供的确权申请结果。下表写清各组合下运营看到什么（企业端看到的按 M7a、M7b）；能否发起申请按 M7a [可申请的条件](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#eligibility)，最后一列只列出本模块状态对应的 M7a 不可申请原因。

| 核心资料状态 | 到期状态 | 回款状态 | 运营看到 | 对应的 M7a 不可申请原因 |
| --- | --- | --- | --- | --- |
| 一致 | 未到期 | 未收款 | 三个状态原样展示 | 无（能否申请还取决于 M7a 的其他条件） |
| 一致 | 未到期 | 部分收款 | 三个状态原样展示 | 无（能否申请还取决于 M7a 的其他条件） |
| 一致 | 未到期 | 已收清 | 三个状态原样展示 | 已收清 |
| 一致 | 已到期 | 任一 | 三个状态原样展示，到期日旁为“已到期 N 天” | 已到期 |
| 一致 | 到期日未确定（含尚有车辆未装船） | 任一 | 三个状态原样展示，起算日注明未确定原因 | 到期日未确定 |
| 差异待核实 | 任一 | 任一 | 预警信息为“有”（没有未处理关联预警时，列表预警列为“待核实”），原资料、差异明细及核实入口 | 核心资料待核实 |

- 资产健康度、预警信息和关联预警只对运营展示，不改变本模块的任何状态。
- [资料齐全且有效（F-M3-15）](#F-M3-15)的结果与上表三个状态相互独立；不通过时，按 M7a 不能发起申请，按 M9 不能审核通过。
- 任一方未对应平台企业时，对应不上的一方企业看不到本笔应收账款；内销卖方没有对应到拥有债权人角色的平台企业时，没有企业能对本笔发起申请（按 M7a）。

下表各项在确认前按“当前处理”执行；推荐口径确认后直接转为规则。

<a id="dependencies"></a>
依赖：

- ERP：提供已审核的内销发票（含车辆明细与内采单价、账期、ERP 账款起算日与到期日、附件）、内销合同。取得方式由研发决定。
- M1、M2：企业首次入驻完成状态、本人时区、运营分配的企业角色、运营账号状态与无权访问；ERP 企业关联结果见 M2 [关联 ERP 企业（F-EN-10）](../../运营端/M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-EN-10)。本模块向 M2 提供关联确认时展示的各 ERP 企业涉及的应收账款笔数。
- 合同信息（M4）：本车所在外采合同（外采合同号、外采供应商）、外销合同（外销合同号、外销客户）及内销合同的本车值与详情入口；终端回款按整份外销合同计入的口径与 M4 [终端回款金额的计入](../../运营端/M4-合同信息/01-合同信息-PRD.md#terminal-receipt)一致。
- 车辆履约（M5）：每辆车的当前物流节点（用于判定是否已售）与最近一次外销出库日期、外采交货日期、价格链中的外采单价、外销单价与外销收款金额（批售合同为合同合计）、当前有效外销合同的判定（待验证），以及车辆履约详情入口。
- 提单信息（M12）：每辆车所在的全部提单及其装船日期、提单附件与[提单详情（F-M12-03）](../../运营端/M12-提单信息/01-提单信息-PRD.md#F-M12-03)入口；初始提单由本模块按装船日期判定。
- 保单信息（M13）：每辆车在每张保单中的车辆保险金额与所在保单数、保单附件及详情入口，见 [车辆清单与车辆保险金额（F-M13-05）](../../运营端/M13-保单信息/01-保单信息-PRD.md#F-M13-05)。
- 资金收付（M14）：已审核内销收款登记到每张内销发票的分配金额、交易流水号、收付双方、银行、账号、凭证，以及收付记录详情入口。
- M11 汇率管理：USD/NGN 当前汇率或“无可用汇率”，见 [对外提供的汇率口径（FX-05）](../../运营端/M11-汇率管理/01-汇率管理-PRD.md#FX-05)。
- 风控预警（M8）：与本笔应收账款关联的风控预警的未处理、已处理条数及入口，见 [向其他模块提供的预警信息](../../运营端/M8-风控预警/01-风控预警-PRD.md#external)。
- M7a、M7b、M9：申请状态、申请资格、审核条件与申请详情入口；M7a、M9 的办理条件引用本模块的[资料齐全且有效（F-M3-15）](#F-M3-15)；企业端的应收账款详情由 M7a [应收账款详情（F-M7a-09）](../../企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#F-M7a-09)、M7b [应收账款详情（F-M7b-05）](../../企业端/M7b-确权待办与确认处理/01-确权待办与确认处理-PRD.md#F-M7b-05) 定义。本模块向它们提供到期状态、回款状态、核心资料状态、[资料齐全且有效](#F-M3-15)的结果、当前资料与预警信息。
- 运营端首页（M17）：业务总览引用本模块的应收账款金额、已收与待收、到期与回款状态，见[运营端首页（M17）](../../运营端/M17-运营端首页/01-运营端首页-PRD.md)。
- 数据监控（M15）：本模块按[一张内销发票一笔应收账款](#receivable-identity)判定不形成应收账款的内销发票，在 M15 按未接收计入。
