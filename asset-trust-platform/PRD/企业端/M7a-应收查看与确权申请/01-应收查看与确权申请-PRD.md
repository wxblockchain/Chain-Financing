## 1. 模块是什么

债权人企业用户在“应收账款”业务入口中查看本企业作为债权人的全部应收账款，挑出可以确权的记录，单笔或批量发起确权申请，并跟踪每一笔申请在债务人确认、运营审核中的进度和结果。被债务人驳回时，债权人能看到原因，并在条件满足时重新发起；应收账款到期时仍未走完的申请自动关闭。应收账款本身的内容（发票、车辆、合同、款项）由应收账款与发票（M3）提供，本模块只读引用，不修改。

基本原则：

- 查看全部不等于全部可申请。债权人能看到本企业为债权人的全部应收账款（含已到期、已收清），只有满足[申请资格（F-M7a-02）](#F-M7a-02)的记录才能发起。
- 一笔申请只对应一笔应收账款。批量发起只是一次选择多笔，每笔应收账款各自生成申请编号、各自判定成败、各自走后续确认与审核，不存在“一批一个申请”。
- 同一笔应收账款同一时间最多只有一笔处理中的申请；已通过运营审核的应收账款不再发起。
- 发起申请时记录本笔应收账款当时的资料作为“当次依据”，后续资料更新不改写当次依据。
- 企业端只读：发起申请不需要也不允许上传、补充或修改任何资料；资料有误或缺失时由 ERP 更新，债权人在资料更新后重新发起。
- 发起申请只是请债务人确认，不代表债务人已认可，更不代表可以出库。
- 运营审核只有“通过”，没有驳回或不通过：未通过前申请一直处于“待运营审核”，直到通过或应收账款到期关闭。
- 申请提交后资料变化不要求重新确认或重新审核，债务人与运营都以当次依据处理。

**一个完整的例子**（企业名称、编号与金额为演示值）。企业 H 的唯一企业用户已完成入驻，运营给 H 分配了债权人角色。该用户打开“应收账款”，看到三笔本企业为债权人的应收账款：INV-0012（债务人 Carloha Nigeria，60,000.00 USD，到期日 2026-12-09（Africa/Lagos），未到期，部分收款，可申请）、INV-0013（已到期，不可申请；打开详情可看到原因“已到期”）、INV-0015（40,000.00 USD，未到期，未收款，可申请）。用户点开 INV-0012 查看应收账款详情（M3），返回后勾选 INV-0012 和 INV-0015 发起批量申请。确认时看到：共 2 笔，应收账款金额合计 100,000.00 USD，债务人 Carloha Nigeria。提交后两笔分别生成申请编号 AP-0001、AP-0002，状态均为“待债务人确认”；Carloha Nigeria 收到两条“收到新的确权申请”站内消息。之后债务人确认了 AP-0001，状态变为“待运营审核”，运营审核通过后变为“运营审核通过”；AP-0002 被债务人驳回，原因“合同金额与发票不一致”。H 在申请记录中看到驳回原因。ERP 更新合同后，H 对 INV-0015 重新发起，生成新的申请编号 AP-0003，AP-0002 作为历史记录保留。

### 1.1 需求清单

| 功能 | 谁 | 想做什么 | 为了什么 |
| --- | --- | --- | --- |
| [债权人应收账款列表（F-M7a-01）](#F-M7a-01) | 债权人企业用户 | 查找本企业为债权人的全部应收账款，看清每笔能否申请、申请到了哪一步 | 快速挑出要发起确权的记录 |
| [申请资格（F-M7a-02）](#F-M7a-02) | 平台（结果对债权人可见） | 统一判断一笔应收账款现在能否发起确权，并说明不能的原因 | 只让符合条件的记录进入确权，不重复占用 |

| [申请记录与进度（F-M7a-05）](#F-M7a-05) | 债权人企业用户 | 查找本企业发起的全部申请，看到每笔的状态 | 跟踪确认与审核进展 |
| [申请详情与当次依据（F-M7a-06）](#F-M7a-06) | 债权人企业用户 | 查看一笔申请的进度、处理结果、原因及发起时的资料 | 了解结果并追溯依据 |
| [债务人驳回后的处理（F-M7a-07）](#F-M7a-07) | 债权人企业用户 | 看到驳回原因后，在条件满足时重新发起 | 让被驳回的应收账款有明确的后续路径 |
| [到期自动关闭（F-M7a-08）](#F-M7a-08) | 平台（结果对债权人、债务人可见） | 应收账款到期时关闭仍在处理中的申请 | 到期后不再确认或审核，申请有明确的结束 |

### 1.2 本期不做

- 撤回或取消已提交的申请。
- 发起申请时上传、补充或修改资料，或填写申请说明；应收账款资料只由 ERP 更新。
- 债务人批量确认、运营批量审核：分别由确权待办与确认处理（M7b）、运营审核与资产出库（M9）定义，本期均为逐笔处理。
- 债务人确认或驳回、运营审核、出库的操作本身：分别由 M7b、M9 定义，本模块只展示其结果。
- 应收账款详情的内容与可见范围：由应收账款与发票（M3）的[企业查看应收账款详情（F-M3-09）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-09)定义。
- 上游采购、车辆履约、下游销售资料：企业端不可见。
- 运营审核驳回或不通过。
- 因资料变化、角色变化或账号停用自动撤销、终止在途申请；只有到期会关闭申请，见[到期自动关闭（F-M7a-08）](#F-M7a-08)。
- 中文、英文以外的语言。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 应收账款 | 由一张发票形成的债权，内容由 M3 提供；本模块中的应收账款编号、到期状态、回款状态、核心资料状态均沿用 M3 的定义 |
| 债权人企业用户 | 拥有债权人角色的平台企业的唯一用户；本册所称“债权人”即指该用户代表本企业操作 |

<a id="shared-rules"></a>
## 3. 共用规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。

<a id="access"></a>
### 3.1 谁能使用、看到什么

- 使用前提：账号启用、已完成首次入驻（M1），且本企业当前拥有债权人角色。入口与无权访问按 M1 [角色业务入口与无权访问（M1-F08）](../M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#M1-F08)。
- 债权人只能看到本企业的应收账款，以及本企业发起的确权申请。
- 打开不属于本企业的应收账款或申请（含改写链接中的编号）时，统一提示“该内容不存在或无权查看”，不透露其是否存在及任何内容；应收账款详情内的不可访问按 M3 [不可访问](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#no-access)。
- 运营移除本企业的债权人角色后，下一次请求即失去本模块全部入口与查看范围，正在进行的发起被拒绝，不生成申请；已提交的申请不因此撤销，继续由债务人和运营处理，到期时按[到期自动关闭（F-M7a-08）](#F-M7a-08)关闭。角色恢复后重新可见全部历史申请。
- 同时拥有债权人、债务人角色的企业，在本模块只以债权人身份出现：只看本企业作为卖方的应收账款及本企业发起的申请。一张发票的卖方和买方不会是同一平台企业，因此本企业发起的申请不会出现在本企业的债务人待办中；债务人一侧的隔离由 M7b 定义。

<a id="display-values"></a>
### 3.2 金额、日期与时间

- 金额、ERP 日期、附件的展示沿用 M3 [来源值、金额与时间](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#display-values) 与 [附件查看](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#file-view)：金额与币种同时展示、按 ERP 原值不取整；不同币种不相加。
- 应收账款到期日按 M3 [账期与到期状态（F-M3-04）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-04)的写法展示：时区写在日期后面，例如“2026-12-09（Africa/Lagos）”；到期日未提供时展示“未提供”，只缺时区时展示日期并注明“时区未提供”。
- 平台自己记录的时间（发起时间、处理时间、审核时间、关闭时间、状态更新时间）展示到分钟，按本人在 M1 [界面语言与时区（M1-F12）](../M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#M1-F12)中设置的时区展示并标明时区；未设置时按 UTC。
- 驳回原因按债务人填写的原文展示，不随界面语言翻译。
- 平台自身的字段名称、状态名称、不可申请原因有中文、英文两套，随界面语言切换。

<a id="load-fail"></a>
### 3.3 加载失败与登录失效

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的金额、状态或申请资格，避免把加载失败误显示为“可申请”或“未申请”。
- 详情中某一部分（如当次依据、处理记录）加载失败时，仅该部分提示失败并可重试，其他部分正常展示。
- 操作过程中登录失效、账号被停用或锁定时，按 M1 规则回到登录入口，本次未提交的操作不生效。

<a id="F-M7a-01"></a>
## 4. 债权人应收账款列表（F-M7a-01）

适用角色与前提：满足[谁能使用、看到什么](#access)的债权人企业用户。

流程参见：[单笔发起确权申请（图 M7a-1）](./02-应收查看与确权申请-流程图与状态机.md#fig-m7a-1)。
验收参见：[债权人应收账款列表](./04-应收查看与确权申请-验收.md#acc-f-m7a-01)。

列表范围为本企业为债权人的全部应收账款，含已到期、已收清、核心资料待核实、债务人未对应平台企业的记录；每行一笔应收账款。

| 业务信息 | 含义 | 来源与缺失时 |
| --- | --- | --- |
| 应收账款编号 | 本笔应收账款的编号 | M3 生成 |
| 发票号 | 形成本笔应收账款的发票号 | ERP 原值 |
| 债务人 | 债务人企业名称；未对应平台企业时展示发票买方名称 | M3 对应结果 |
| 应收账款金额及币种 | 取自发票金额 | ERP 原值 |
| 应收账款到期日 | 到期日及其后的时区 | ERP 原值；未提供时展示“未提供” |
| 到期状态 | 未到期／已到期／到期日未确定 | M3 判定 |
| 回款状态 | 未收款／部分收款／已收清 | M3 判定 |
| 申请状态 | 本笔应收账款最近一笔申请的[申请状态](#apply-status)；从未申请时展示“未申请” | 本模块 |
| 申请资格 | 可申请／不可申请，列表中不展示不可申请原因；原因在应收账款详情中展示，见[申请资格（F-M7a-02）](#F-M7a-02) | 本模块，按打开或刷新列表时判断 |

操作：

- 每行可“查看”，进入 M3 应收账款详情（债权人可见范围），并可返回列表，返回后保留原有查找、筛选和页码。
- 可申请的行可“发起申请”，进入[单笔发起确权申请（F-M7a-03）](#F-M7a-03)；单笔发起的全部入口见该节。
- 可申请的行可被选中用于[批量发起确权申请（F-M7a-04）](#F-M7a-04)；不可申请的行不能被选中，债权人可通过“查看”进入应收账款详情了解原因。
- 申请状态不是“未申请”时，可从该行进入最近一笔申请的[申请详情](#F-M7a-06)。

查找与筛选：

- 按应收账款编号或发票号查找，支持部分匹配。
- 按 VIN 查找，结果为车辆清单中包含该 VIN 的本企业应收账款。
- 按申请编号查找，结果为该申请对应的应收账款；申请编号不属于本企业时按无结果处理。
- 筛选：申请资格（可申请／不可申请）、申请状态（含未申请）、到期状态、回款状态、债务人、币种、到期日区间。多个条件同时生效。
- 默认按账款起算日从新到旧排列；账款起算日未提供的排在最后。

边界与异常：

- 本企业还没有任何应收账款时，展示“暂无应收账款”；有应收账款但查找或筛选无结果时，展示“没有符合条件的应收账款”并可清除条件。
- 列表展示的申请资格是打开或刷新时的结果；发起时重新判断，以发起时为准。
- 列表不提供新增、编辑、删除应收账款的操作。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

<a id="F-M7a-02"></a>
## 5. 申请资格（F-M7a-02）

适用范围：列表与 M3 债权人视角应收账款详情中“申请资格”的展示，以及每一次单笔、批量提交时的判断。判断以提交时的数据为准。

验收参见：[申请资格](./04-应收查看与确权申请-验收.md#acc-f-m7a-02)。

<a id="eligibility"></a>
### 5.1 可申请的条件

本企业满足[谁能使用、看到什么](#access)的前提下，一笔应收账款同时满足以下全部条件时为“可申请”：

| 条件 | 依据 | 不满足时的不可申请原因 |
| --- | --- | --- |
| 核心资料状态为“一致” | M3 [核心资料差异核实（F-M3-07）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-07) | 核心资料待核实 |
| 到期状态为“未到期” | M3 [账期与到期状态（F-M3-04）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-04)；到期日当天仍为未到期 | 已到期；或到期日未确定 |
| 回款状态为“未收款”或“部分收款” | M3 [回款状态](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#repayment-status) | 已收清 |
| 发票买方已对应到平台企业，且该企业当前拥有债务人角色 | M3 [买卖双方与平台企业的对应](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#party-match)；M2 分配的角色 | 债务人暂不能处理确权申请，请联系平台运营 |
| 本笔应收账款没有处理中的申请 | [申请状态](#apply-status) | 已有申请处理中（附该申请编号） |
| 本笔应收账款没有“运营审核通过”的申请 | [申请状态](#apply-status) | 已通过运营审核（附该申请编号） |

- 不可申请原因的展示位置：
  - 应收账款列表只展示“可申请／不可申请”，不展示原因。
  - M3 债权人视角的应收账款详情在本笔不可申请时展示全部不可申请原因，见 M3 [债权人发起申请入口](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#apply-entry)。
  - 提交时不满足、债务人驳回后重新发起时不满足，在当时的结果或申请详情中展示具体原因，见[单笔发起确权申请（F-M7a-03）](#F-M7a-03)、[批量发起确权申请（F-M7a-04）](#F-M7a-04)、[债务人驳回后的处理（F-M7a-07）](#F-M7a-07)。
- 同时有多项不满足时，展示原因处全部原因都展示。
- 回款预警、资料进度、合同或附件是否取得、车辆明细合计是否一致，都不是申请条件。
- 债务人企业账号停用、尚未完成入驻不是申请条件：申请照常提交，等待债务人处理；消息按 M10 保留。
- 本笔应收账款以前有过“债务人已驳回”的申请，不影响再次申请，见[债务人驳回后的处理（F-M7a-07）](#F-M7a-07)。“已关闭”的申请只因到期产生，此时本笔应收账款已到期，不能再申请。

<a id="apply-status"></a>
### 5.2 申请状态

申请状态表达一笔申请当前的结果，只有一个维度。名称供 M3 的确权与审核进度、M7b、M9 原样使用。

| 申请状态 | 含义 | 由谁带来 | 是否处理中 | 后续 |
| --- | --- | --- | --- | --- |
| 待债务人确认 | 申请已提交，等待债务人确认或驳回 | 本模块：提交成功 | 是 | M7b 确认后变为“待运营审核”；驳回后变为“债务人已驳回”；到期时变为“已关闭” |
| 债务人已驳回 | 债务人驳回了申请，附驳回原因 | M7b：债务人驳回 | 否 | 结束；本笔应收账款满足资格时可重新发起 |
| 待运营审核 | 债务人已确认，等待运营审核 | M7b：债务人确认 | 是 | 运营审核只有通过：M9 审核通过后变为“运营审核通过”；未通过前一直保持本状态，到期时变为“已关闭” |
| 运营审核通过 | 运营审核结论为通过，本笔应收账款取得出库资格 | M9：审核通过 | 否 | 结束；出库进度另由 M9 提供，见[出库进度](#outbound) |
| 已关闭 | 应收账款到期时申请仍在处理中，平台自动关闭，关闭原因为“应收账款已到期” | 本模块：到期时点到达 | 否 | 结束；不能再确认、审核或重新发起 |

- 状态只由上表所列的业务结果改变，没有其他转换；“债务人已驳回”“运营审核通过”“已关闭”之后不再变化。
- 核心资料变化、回款变化、本企业或债务人角色变化、账号停用都不改变申请状态，也不要求债务人重新确认或运营重新审核；到期是唯一会自动关闭申请的情况，见[到期自动关闭（F-M7a-08）](#F-M7a-08)。
- “运营审核通过”表示取得出库资格，不代表已经出库或对外提供成功。

<a id="progress-stage"></a>
M3 详情以进度条展示本笔应收账款最近一笔申请的[确权与审核进度](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#apply-progress)，按以下三个环节对应申请状态；出库环节由 M9 定义后接在其后：

| 申请状态 | 发起申请 | 债务人确认 | 运营审核 |
| --- | --- | --- | --- |
| 待债务人确认 | 已完成 | 进行中 | 未开始 |
| 债务人已驳回 | 已完成 | 已驳回 | 未开始 |
| 待运营审核 | 已完成 | 已确认 | 进行中 |
| 运营审核通过 | 已完成 | 已确认 | 通过 |
| 已关闭（关闭前为待债务人确认） | 已完成 | 已关闭（应收账款已到期） | 未开始 |
| 已关闭（关闭前为待运营审核） | 已完成 | 已确认 | 已关闭（应收账款已到期） |

<a id="F-M7a-03"></a>
## 6. 单笔发起确权申请（F-M7a-03）

适用角色与前提：债权人企业用户；所选应收账款为“可申请”。

发起入口：应收账款列表中可申请的行；M3 债权人视角的应收账款详情（本笔可申请时提供，不可申请时展示全部不可申请原因，资格与结果全部按本节）；状态为“债务人已驳回”的申请详情（见[债务人驳回后的处理（F-M7a-07）](#F-M7a-07)）。

通知：提交成功后向债务人企业发送[收到新的确权申请（M7a-NT01）](./03-应收查看与确权申请-消息通知.md#M7a-NT01)。
流程参见：[单笔发起确权申请（图 M7a-1）](./02-应收查看与确权申请-流程图与状态机.md#fig-m7a-1)。
验收参见：[单笔发起确权申请](./04-应收查看与确权申请-验收.md#acc-f-m7a-03)。

<a id="confirm-single"></a>
确认时展示：

- 应收账款编号、发票号、债务人、应收账款金额及币种、应收账款到期日及时区、回款状态、未收金额。
- 说明“提交后将发给债务人确认，提交后不能撤回”。

结果：

- 用户确认提交后，平台按[申请资格（F-M7a-02）](#F-M7a-02)重新判断。满足时生成一笔申请：分配申请编号，状态为“待债务人确认”，记录发起人、发起企业、发起时间、发起方式“单笔”，并保存[当次依据](#snapshot)。
- 成功后展示申请编号和状态，可进入该申请详情或返回列表；列表中本笔应收账款的申请状态变为“待债务人确认”，申请资格变为不可申请（已有申请处理中）。
- 用户取消确认时不生成申请，回到发起入口所在处。

边界与异常：

- 提交时已不满足申请资格（例如刚刚到期、核心资料刚变为待核实、已在另一窗口提交）：不生成申请，展示具体原因，列表刷新为最新资格。
- 重复点击提交或同一应收账款在两个窗口同时提交：只生成一笔申请，其余提交按“已有申请处理中”处理并展示已生成的申请编号。
- 提交失败：不生成申请，提示提交失败可重试。
- 提交后未收到明确结果（如网络中断）：提示“提交结果未确认，请在申请记录中查看”，不自动重新提交；再次提交时如已生成申请，按“已有申请处理中”处理，不会生成第二笔。
- 提交时登录失效、角色被移除或账号被停用：不生成申请，按[谁能使用、看到什么](#access)与[加载失败与登录失效](#load-fail)处理。

## 7. 批量发起确权申请（F-M7a-04）

适用角色与前提：债权人企业用户；在列表中选中至少 1 笔“可申请”的应收账款。

通知：每笔提交成功的申请各自向其债务人企业发送一条[收到新的确权申请（M7a-NT01）](./03-应收查看与确权申请-消息通知.md#M7a-NT01)。
流程参见：[批量发起确权申请（图 M7a-2）](./02-应收查看与确权申请-流程图与状态机.md#fig-m7a-2)。
验收参见：[批量发起确权申请](./04-应收查看与确权申请-验收.md#acc-f-m7a-04)。

<a id="batch-select"></a>
### 7.1 选择

- 只有“可申请”的行能被选中。
- “全选”只选中当前页中可申请的行；翻页后已选记录保留，已选数量为各页累计。
- 修改查找或筛选条件时清空已选记录。
- 随时展示已选数量，可逐笔取消选择或全部清空。
- 单次最多选择 10 笔。已选满 10 笔时不能再选中，并说明“单次最多 10 笔”。
- “全选”时，当前页可申请的行按列表顺序选中，选满 10 笔为止；未能选中的行保持未选，并说明“单次最多 10 笔”。

<a id="batch-confirm"></a>
### 7.2 确认

确认时展示：

- 已选笔数。
- 逐笔清单：应收账款编号、发票号、债务人、应收账款金额及币种、应收账款到期日及时区。
- 应收账款金额按币种分别合计，不同币种不相加。
- 涉及的债务人及各自笔数。
- 说明“每笔将分别生成申请编号、分别发给债务人确认，提交后不能撤回”。

用户取消确认时不生成任何申请，已选记录保留。

<a id="batch-result"></a>
### 7.3 提交与逐笔结果

- 提交后平台对每一笔分别按[申请资格（F-M7a-02）](#F-M7a-02)重新判断，各自独立处理：满足的生成一笔申请（规则与[单笔发起确权申请（F-M7a-03）](#F-M7a-03)相同，发起方式记为“批量”，各笔使用同一个发起时间）；不满足的不生成申请。
- 一笔失败不影响其他笔，已成功的不回退。
- 提交完成后展示逐笔结果：成功的展示申请编号与状态“待债务人确认”；未提交的展示具体原因。同时展示成功笔数和未提交笔数。
- 全部未提交时，说明“本次没有提交任何申请”，并逐笔展示原因。
- 结果中的申请编号可进入申请详情；离开结果后，可在[申请记录与进度（F-M7a-05）](#F-M7a-05)中按发起时间查到本次提交的各笔申请。
- 提交完成后清空已选记录，列表刷新为最新的申请状态与申请资格。

边界与异常：

- 提交过程中个别笔出现系统失败：该笔展示“提交失败，可重新发起”，不生成申请；其他笔按各自结果处理。
- 提交后未收到明确结果（如网络中断）：提示“提交结果未确认，请在申请记录中查看”，不自动重新提交；再次提交已生成申请的应收账款时按“已有申请处理中”处理，不会重复生成。
- 重复点击提交：同一次提交只处理一次。
- 提交时登录失效、角色被移除或账号被停用：全部不生成申请。

## 8. 申请记录与进度（F-M7a-05）

适用角色与前提：满足[谁能使用、看到什么](#access)的债权人企业用户。范围为本企业发起的全部确权申请，含已结束的申请；每行一笔申请。

流程参见：[申请状态（图 M7a-3）](./02-应收查看与确权申请-流程图与状态机.md#fig-m7a-3)。
验收参见：[申请记录与进度](./04-应收查看与确权申请-验收.md#acc-f-m7a-05)。

| 业务信息 | 含义 | 来源与缺失时 |
| --- | --- | --- |
| 申请编号 | 本笔申请的编号 | 本模块生成 |
| 应收账款编号 | 申请对应的应收账款 | M3 |
| 发票号 | 申请对应的发票号 | 当次依据 |
| 债务人 | 债务人企业名称 | 当次依据 |
| 应收账款金额及币种 | 发起时的应收账款金额 | 当次依据 |
| 发起时间 | 申请提交成功的时间 | 本模块记录 |
| 申请状态 | 见[申请状态](#apply-status) | 本模块 |
| 状态更新时间 | 最近一次申请状态变化的时间 | 本模块记录 |

操作：每行可进入[申请详情与当次依据（F-M7a-06）](#F-M7a-06)。

查找与筛选：

- 按申请编号、应收账款编号或发票号查找，支持部分匹配。
- 筛选：申请状态、债务人、发起时间区间。多个条件同时生效。
- 默认按发起时间从新到旧排列；同一次批量提交的申请发起时间相同，按申请编号排列。

边界与异常：

- 本企业还没有发起过申请时，展示“暂无确权申请”；有申请但查找或筛选无结果时，展示“没有符合条件的申请”并可清除条件。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

## 9. 申请详情与当次依据（F-M7a-06）

适用角色与前提：债权人企业用户，申请由本企业发起。详情只读。

验收参见：[申请详情与当次依据](./04-应收查看与确权申请-验收.md#acc-f-m7a-06)。

<a id="apply-basic"></a>
### 9.1 申请信息

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 申请编号 | 本笔申请的编号 | 不会缺失 |
| 申请状态 | 见[申请状态](#apply-status)，并按[确权与审核进度](#progress-stage)展示环节 | 不会缺失 |
| 应收账款编号 | 可进入 M3 应收账款详情（当前资料，债权人可见范围） | 不会缺失 |
| 债权人 | 本企业名称 | 不会缺失 |
| 债务人 | 债务人企业名称 | 不会缺失 |
| 发起人 | 发起时本企业用户的姓名（M1 个人信息） | 不会缺失 |
| 发起时间 | 申请提交成功的时间 | 不会缺失 |
| 发起方式 | 单笔／批量 | 不会缺失 |

<a id="process-record"></a>
### 9.2 处理记录

按发生时间顺序展示已经发生的处理，未发生的环节不展示结果：

| 环节 | 展示内容 | 来源 |
| --- | --- | --- |
| 发起申请 | 发起人、发起时间 | 本模块 |
| 债务人确认 | 处理结论（确认／驳回）、处理企业、处理时间；驳回时展示驳回原因 | M7b |
| 运营审核 | 审核结论（通过）、审核时间 | M9 |
| 关闭 | 关闭时间（到期时点）、关闭原因“应收账款已到期”、关闭前所处的环节 | 本模块 |

- 债权人看不到运营审核人姓名；债务人一侧处理人以债务人企业名称展示。
- 驳回原因按原文展示，不翻译。

<a id="outbound"></a>
### 9.3 出库进度

- 申请状态为“运营审核通过”后，展示 M9 提供的出库进度；名称与含义由 M9 定义，本模块原样接入，不改变本模块的申请状态。M9 定义前不展示该项。
- 出库进度与申请状态分开展示：运营审核通过不等于已出库。

<a id="snapshot"></a>
### 9.4 当次依据

当次依据是申请提交成功那一刻本笔应收账款的资料，按 M3 [详情的信息分类与顺序](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#detail-groups)展示，范围为 M3 中债权人可见的以下内容：

- 状态：到期状态、回款状态、核心资料状态。
- 应收账款信息：应收账款编号、债权人、债务人、应收账款金额及币种、账款起算日、天数、应收账款到期日及时区。
- 发票信息与附件：发票号码、发票开立日期、发票金额及币种、装船日期、发票附件。
- 车辆信息明细：每辆车的 VIN、车型、单价及币种，车辆数量，车辆明细合计，车辆明细附件。
- 合同信息：当时已取得的全部合同及附件。
- 回款统计：应收账款金额及币种、累计已收、未收金额。

规则：

- 当次依据在提交成功时一次性记录，之后不随 ERP 更新、核心资料差异或核实而改变；附件为当时取得的版本。
- 提交时某项资料未提供或附件未取得的，当次依据中同样展示“未提供”“附件未取得”“合同未取得”，不事后补入。
- 详情同时提供进入 M3 当前资料的入口；当次依据与当前资料不同时，各自按原值展示，本模块不比较、不提示差异。
- 当次依据同时是债务人确认（M7b）和运营审核（M9）的依据；M7b、M9 中的可见范围由其各自定义。
- 申请提交后资料发生变化（包括 M3 核心资料变为“差异待核实”、合同或回款更新），不要求债务人重新确认或运营重新审核，申请照常推进。

<a id="F-M7a-07"></a>
## 10. 债务人驳回后的处理（F-M7a-07）

适用角色与前提：债权人企业用户；申请状态为“债务人已驳回”。

流程参见：[债务人驳回后重新发起（图 M7a-4）](./02-应收查看与确权申请-流程图与状态机.md#fig-m7a-4)。
验收参见：[债务人驳回后的处理](./04-应收查看与确权申请-验收.md#acc-f-m7a-07)。

- 债权人在申请记录、申请详情及应收账款列表的申请状态中看到结果；申请详情展示驳回原因。驳回结果消息由确权待办与确认处理（M7b）发送。
- 被驳回的申请保持原状态，不能修改、补充或再次提交；它作为历史记录保留。
- 本笔应收账款满足[申请资格（F-M7a-02）](#F-M7a-02)时，债权人可以像首次一样单笔或批量重新发起，生成新的申请编号和新的当次依据，重新经过债务人确认与运营审核。重新发起的次数不限。
- 驳回原因涉及资料错误或缺失时，资料由 ERP 更新，企业端不提供补正或上传；平台不检查资料是否已更新，也不阻止在资料未变化时重新发起。
- 状态为“债务人已驳回”的申请详情提供前往本笔应收账款的入口；本笔应收账款当前可申请时，可直接发起新的申请（规则同[单笔发起确权申请（F-M7a-03）](#F-M7a-03)），不可申请时展示原因。
- 本笔应收账款已有新的申请后，旧申请详情中注明“已重新发起”及新申请编号，可进入新申请。

<a id="F-M7a-08"></a>
## 11. 到期自动关闭（F-M7a-08）

适用范围：状态为“待债务人确认”或“待运营审核”的申请。没有用户操作。

通知：关闭后向债权人企业发送[确权申请已到期关闭（M7a-NT02）](./03-应收查看与确权申请-消息通知.md#M7a-NT02)；关闭前为“待债务人确认”的，另向债务人企业发送[待确认的确权申请已到期关闭（M7a-NT03）](./03-应收查看与确权申请-消息通知.md#M7a-NT03)。
流程参见：[申请状态（图 M7a-3）](./02-应收查看与确权申请-流程图与状态机.md#fig-m7a-3)。
验收参见：[到期自动关闭](./04-应收查看与确权申请-验收.md#acc-f-m7a-08)。

- 本笔应收账款到达到期时点（ERP 时区下到期日当天 24:00，见 M3 [到期状态](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#due-status)）、M3 到期状态由“未到期”变为“已到期”时，处理中的申请变为“已关闭”，关闭原因为“应收账款已到期”。
- 关闭时间记为到期时点，按本人时区展示并标明时区；平台须在到期时点后 5 分钟内完成关闭（M10 对到点触发事件的要求），实现与验证归研发、测试。
- 以到期时点为界：到期时点之前已生效的债务人确认、驳回或运营审核通过照常有效；到期时点之后提交的确认、驳回或审核通过一律不生效，按“已关闭”处理。M7b、M9 中的拒绝结果由其各自定义。
- 关闭后申请不能再确认、驳回、审核或重新提交；本笔应收账款已到期，不能再发起新申请。
- “运营审核通过”“债务人已驳回”的申请到期时不变。
- 到期判断沿用 M3：到期日当天仍为未到期；已有到期日在 ERP 中被改动时按原资料判断；只要 M3 的到期状态没有变为“已到期”，申请就不关闭。

<a id="records"></a>
## 12. 操作留痕

- 每笔申请留存：申请编号、应收账款编号、发起企业、发起人、发起时间、发起方式、当次依据，以及每次状态变化的时间、来源模块和原因（驳回原因、关闭原因）。
- 留痕不可编辑、不可删除；运营查看方式由 M9 定义。
- 发起时因资格不满足或系统失败而未生成申请的，不生成申请记录。

<a id="pending"></a>
## 13. 待确认事项与依赖

本模块当前没有待确认事项。

依赖：

- 企业登录与首次入驻（M1）：入驻完成状态、企业用户姓名、界面语言与时区、债权人角色入口与无权访问处理。
- 运营登录、企业邀请与企业管理（M2）：平台企业、企业唯一用户、债权人与债务人角色分配、账号启停。
- 应收账款与发票（M3）：本企业为债权人的应收账款及其详情（债权人可见范围）、应收账款编号、到期状态（到期日当天仍为未到期）、回款状态、核心资料状态、买卖双方对应结果；按本模块的申请状态和环节名称展示确权与审核进度（含“已关闭”），在债权人视角的详情中按本模块规则承载“发起申请”入口，并支持按申请编号查找。
- 确权待办与确认处理（M7b）：债务人确认或驳回结论、驳回原因、处理时间，带来“待运营审核”“债务人已驳回”；发送驳回结果消息。到期时点之后的确认、驳回不生效。
- 运营审核与资产出库（M9）：运营审核只有通过，带来“运营审核通过”及审核时间；出库进度；发送审核结果消息。到期时点之后的审核通过不生效。
- 消息中心（M10）：承接本模块发出的站内消息，按 [来源接入要求（MSG-06）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-06)。
- 资格判断须以提交时的数据为准、同一应收账款同一时间只生成一笔处理中的申请，实现与验证归研发、测试。
