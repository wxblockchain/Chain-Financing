# 应收查看与确权申请 · 消息通知

2026-11-12｜需求评审稿｜配套[功能与业务规则](./01-应收查看与确权申请-PRD.md)

本模块发送 3 类站内消息，经消息中心（M10）展示，按 [来源接入要求（MSG-06）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-06)登记；必发，企业不能关闭。本模块不发送邮件。

| 消息 | 端 | 所在功能 | 触发环节 | 谁收到 | 打开后去哪 |
| --- | --- | --- | --- | --- | --- |
| [收到新的确权申请（M7a-NT01）](#M7a-NT01) | 企业端 | [单笔发起确权申请（F-M7a-03）](./01-应收查看与确权申请-PRD.md#F-M7a-03)、[批量发起确权申请（F-M7a-04）](./01-应收查看与确权申请-PRD.md#F-M7a-04) | 一笔申请提交成功、状态为“待债务人确认” | 该申请的债务人企业 | 确权待办与确认处理（M7b）中这笔申请的详情 |
| [确权申请已到期关闭（M7a-NT02）](#M7a-NT02) | 企业端 | [到期自动关闭（F-M7a-08）](./01-应收查看与确权申请-PRD.md#F-M7a-08) | 处理中的申请因到期变为“已关闭” | 该申请的债权人企业 | 本模块中这笔申请的详情 |
| [待确认的确权申请已到期关闭（M7a-NT03）](#M7a-NT03) | 企业端 | [到期自动关闭（F-M7a-08）](./01-应收查看与确权申请-PRD.md#F-M7a-08) | 状态为“待债务人确认”的申请因到期变为“已关闭” | 该申请的债务人企业 | M7b 中这笔申请的详情（只能查看） |

以下情况本模块不发消息：提交时资格不满足、提交失败或结果未确认而未生成申请；用户取消确认；批量提交中未生成申请的各笔；列表浏览、查找筛选、查看详情；“债务人已驳回”“运营审核通过”的申请到期（申请不关闭）；“待运营审核”的申请到期关闭时不另通知债务人（债务人已完成确认）；申请到期关闭不通知运营（运营端待审核范围的变化由 M9 展示）。

债权人不会因本企业自己提交申请而收到消息。债务人确认、驳回的结果由确权待办与确认处理（M7b）发送，运营审核通过与出库结果由运营审核与资产出库（M9）发送，本模块不发同义消息。

<a id="M7a-NT01"></a>
## 收到新的确权申请（M7a-NT01）

| 项目 | 规则 |
| --- | --- |
| 发送来源 | 应收查看与确权申请（M7a）；其他模块不发同义消息 |
| 端 | 企业端 |
| 分类 | 待处理事项 / Pending tasks |
| 收件范围 | 本企业：该申请当次依据中的债务人企业。不发给债权人企业，不发运营 |
| 触发 | 单笔或批量发起中，一笔申请提交成功、生成申请编号并进入“待债务人确认”时发送 |
| 不触发 | 未生成申请的任何情况（资格不满足、提交失败、结果未确认后实际未生成、取消确认） |
| 同一事实的区分依据 | 债务人企业 + 申请编号 + “收到新的确权申请”。一笔申请只发一条；重复点击、重试、刷新不新增。同一应收账款重新发起时有新的申请编号，是新的事实，另发一条 |
| 批量发起 | 每笔成功的申请各发一条，不合并；同一批次涉及多个债务人时各自收到属于本企业的各条 |
| 发生时间 | 申请提交成功的时间（即申请的发起时间） |
| 原业务识别信息 | 申请编号、发票号 |
| 打开后去哪 | 原业务：M7b 中该申请的详情 |
| 查看与办理条件 | 查看：本企业是该申请的债务人且当前拥有债务人角色。办理：另需申请状态为“待债务人确认”，具体由 M7b 定义；状态已变化时前往后只能查看当前结果，按 M10 [前往原业务（MSG-05）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-05)处理 |
| 债务人尚未完成入驻、账号停用或锁定 | 消息照常生成并保留，按 M10 规则在可查看后展示 |
| 必须出现的业务值 | 债权人企业名称、发票号、应收账款编号、应收账款金额及币种、申请编号；写明本企业在这笔业务中是债务人 |
| 业务值取值 | 取提交成功时当次依据中的值，之后资料或申请状态变化不改写消息 |
| 不得出现 | 发票、合同等原件或下载地址；债权人的收款账户等债务人不可见的信息 |

文案（按收件人的界面语言展示中文或 English；花括号为业务值，企业名称、发票号按原值展示不翻译）：

| 语言 | 标题 | 正文 |
| --- | --- | --- |
| 中文 | 收到新的确权申请 | {债权人企业名称} 就发票 {发票号}（应收账款编号 {应收账款编号}，金额 {应收账款金额} {币种}）向贵企业发起确权申请，申请编号 {申请编号}。贵企业在这笔业务中是债务人，请核对后确认或驳回。 |
| English | New confirmation request received | {creditor name} has submitted a confirmation request to your company for invoice {invoice number} (receivable {receivable number}, amount {amount} {currency}). Request number: {request number}. Your company is the debtor in this transaction. Please review it and confirm or reject. |

<a id="M7a-NT02"></a>
## 确权申请已到期关闭（M7a-NT02）

| 项目 | 规则 |
| --- | --- |
| 发送来源 | 应收查看与确权申请（M7a）；其他模块不发同义消息 |
| 端 | 企业端 |
| 分类 | 业务办理进度 / Business progress |
| 收件范围 | 本企业：该申请的债权人企业（发起企业）。不发运营 |
| 触发 | 状态为“待债务人确认”或“待运营审核”的申请，因到达到期时点变为“已关闭”时发送 |
| 不触发 | 申请在到期时点前已是“债务人已驳回”或“运营审核通过”；申请未关闭的任何情况 |
| 同一事实的区分依据 | 债权人企业 + 申请编号 + “确权申请已到期关闭”。一笔申请只会关闭一次，只发一条 |
| 发生时间 | 到期时点（应到时点），不用实际判定或送达时间代替；须在到期时点后 5 分钟内由本模块判定，消息展示时效按 M10 [送达时效](../../两端共用/M10-消息中心/01-消息中心-PRD.md#delivery-time) |
| 原业务识别信息 | 申请编号、发票号 |
| 打开后去哪 | 原业务：本模块中该申请的详情（只能查看） |
| 查看与办理条件 | 查看：本企业是该申请的发起企业且当前拥有债权人角色。没有办理动作 |
| 必须出现的业务值 | 发票号、应收账款编号、申请编号、关闭前所处环节（待债务人确认／待运营审核）、关闭原因“应收账款已到期”；写明本企业在这笔业务中是债权人 |
| 业务值取值 | 取关闭时的值，之后不改写 |
| 不得出现 | 发票、合同等原件或下载地址 |

文案（按收件人的界面语言展示；花括号为业务值，发票号按原值展示不翻译；{关闭前环节} 中文为“待债务人确认”或“待运营审核”，English 为 “awaiting debtor confirmation” 或 “awaiting operations review”）：

| 语言 | 标题 | 正文 |
| --- | --- | --- |
| 中文 | 确权申请已到期关闭 | 贵企业就发票 {发票号}（应收账款编号 {应收账款编号}）发起的确权申请 {申请编号} 在{关闭前环节}期间，因应收账款已到期，已自动关闭。贵企业在这笔业务中是债权人。该应收账款已到期，不能再发起确权申请。 |
| English | Confirmation request closed on expiry | Confirmation request {request number} submitted by your company for invoice {invoice number} (receivable {receivable number}) was closed automatically while {stage before closing}, because the receivable has passed its due date. Your company is the creditor in this transaction. A new confirmation request cannot be submitted for this receivable. |
