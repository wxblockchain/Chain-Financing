## 1. 模块是什么

债务人企业用户在“确权申请”业务入口中，查看债权人发给本企业的确权申请，核对申请当次提交的应收账款资料，逐笔确认或驳回。确认后申请进入运营审核；驳回时必须写明原因，结果回到债权人，债权人可在条件满足时重新发起。处理过的申请和因到期关闭的申请仍可查看。申请的发起、申请状态和到期关闭由应收查看与确权申请（M7a）定义，应收账款本身的内容由应收账款与发票（M3）提供，本模块只读引用；运营审核由运营审核与资产出库（M9）负责。

基本原则：

- 只处理发给本企业的申请。一笔申请的债务人是发票买方对应的平台企业；同时拥有债权人、债务人角色的企业，在本模块只以债务人身份出现，不能处理本企业自己发起的申请。
- 一次只处理一笔。确认和驳回都逐笔进行，本期没有批量确认。
- 只按当次依据处理。债务人核对的是债权人发起申请时记录的资料；申请提交后资料变化不要求重新确认，也不阻止确认或驳回。
- 确认不等于审核通过，更不等于出库。确认后申请变为“待运营审核”，由运营审核决定能否出库。
- 确认、驳回都是终局结论，提交后不能撤回或改为另一结论。
- 企业端只读：确认和驳回都不需要也不允许上传、补充或修改应收账款资料；驳回只填写原因。
- 应收账款到期时仍待确认的申请由 M7a 自动关闭；到期时点之后提交的确认或驳回不生效。

**一个完整的例子**（企业名称、编号与金额为演示值）。平台企业 Carloha Holding 拥有债权人角色，平台企业 Carloha Nigeria 拥有债务人角色并已完成入驻。Holding 对两笔应收账款批量发起确权，生成申请 AP-0001（发票 INV-0012，60,000.00 USD，到期日 2026-12-09（Africa/Lagos））和 AP-0002（发票 INV-0015，40,000.00 USD）。Nigeria 的企业用户收到两条“收到新的确权申请”站内消息，左侧“确权申请”菜单显示待办数量 2。用户打开待处理列表，进入 AP-0001 的申请详情，核对当次依据中的应收账款信息、发票及附件、车辆明细、合同和回款统计，确认无误后点“确认”，确认时看到申请编号、债权人、发票号、金额和到期日，以及“确认后进入运营审核，不能撤回”。提交后 AP-0001 变为“待运营审核”，移入已处理列表，待办数量变为 1；Holding 收到“确权申请已被债务人确认”，全体运营收到“有新的确权申请待运营审核”。用户再打开 AP-0002，发现合同金额与发票不一致，选择“驳回”，填写原因“合同金额与发票不一致”后提交；AP-0002 变为“债务人已驳回”，待办数量变为 0，Holding 收到带驳回原因的消息。ERP 更新合同后，Holding 对同一笔应收账款重新发起，生成新申请 AP-0003，Nigeria 的待处理列表中出现 AP-0003；AP-0002 的详情注明“债权人已重新发起”及新申请编号。之后运营审核通过 AP-0001，Nigeria 在已处理列表中看到 AP-0001 的状态变为“运营审核通过”。

### 1.2 本期不做

- 批量确认或批量驳回。
- 撤回已提交的确认或驳回，或把确认改为驳回、把驳回改为确认。
- 确认或驳回时上传文件、补充或修改应收账款资料；驳回原因不设分类。
- 确认时填写说明。
- 钱包签名确认：确认按本人登录身份生效，不另要求钱包签名。
- 申请的发起、重新发起、申请状态定义与到期关闭：由应收查看与确权申请（M7a）定义。
- 运营审核与出库：由运营审核与资产出库（M9）定义。
- 向债务人展示出库进度。
- 债务人查看本企业全部应付：没有“全部应付”列表，债务人只能经由发给本企业的申请查看对应应收账款，见 M3 [谁能看、从哪里进](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#enterprise-entry)。
- 上游采购、车辆履约、下游销售资料：企业端不可见。
- 到期前的催办或提醒消息。
- 中文、英文以外的语言。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 确权申请 | 债权人请债务人确认某一笔应收账款的申请，一笔申请只对应一笔应收账款，由 M7a 生成；申请编号全平台唯一 |
| 债务人企业用户 | 拥有债务人角色的平台企业的唯一用户；本册所称“债务人”即指该用户代表本企业操作 |
| 发给本企业的申请 | 当次依据中的债务人是本企业的确权申请 |
| 申请状态 | 一笔申请当前的结果，沿用 M7a [申请状态](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#apply-status)：待债务人确认／债务人已驳回／待运营审核／运营审核通过／已关闭 |
| 待处理 | 申请状态为“待债务人确认”的发给本企业的申请。“待处理”是列表分组，不是另一种状态 |
| 已处理 | 申请状态不是“待债务人确认”的发给本企业的申请，包括本企业已确认或已驳回的，以及因到期关闭、本企业未处理的申请 |
| 待办数量 | 本企业待处理申请的笔数 |
| 当次依据 | 债权人提交申请成功那一刻本笔应收账款的资料记录，由 M7a 保存，见 M7a [当次依据](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#snapshot) |
| 到期时点 | M3 判定本笔应收账款由“未到期”变为“已到期”的时点，即 ERP 时区下到期日当天结束（24:00），见 M3 [到期状态](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#due-status) |

## 3. 共用规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。

<a id="access"></a>
### 3.1 谁能使用、看到什么

- 使用前提：账号启用、已完成首次入驻（M1），且本企业当前拥有债务人角色。入口与无权访问按 M1 [角色业务入口与无权访问（M1-F08）](../M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#M1-F08)；入驻未完成时菜单可见但锁定。
- 债务人只能看到发给本企业的申请，以及这些申请对应的应收账款详情（M3 债务人可见范围）。
- 打开不是发给本企业的申请（含改写链接中的申请编号）时，统一提示“该内容不存在或无权查看”，不透露其是否存在及任何内容；应收账款详情内的不可访问按 M3 [不可访问](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#no-access)。越权访问被拒绝时按 M1 [安全记录](../M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#security-records)留存。
- 运营移除本企业的债务人角色后，下一次请求即失去本模块全部入口与查看范围，正在进行的确认或驳回被拒绝，申请状态不变。待处理的申请不因此撤销，仍为“待债务人确认”，直到角色恢复后处理或到期关闭；角色恢复后重新可见全部申请，未到期的待处理申请可继续处理。
- 同时拥有债权人、债务人角色的企业：在本模块只看到本企业作为发票买方的申请。一张发票的卖方和买方不会是同一平台企业，因此本企业发起的申请不会出现在本企业的待处理中；平台在确认、驳回时仍检查申请的发起企业不是本企业，是本企业时拒绝处理，说明“不能处理本企业发起的申请”。
- 本企业账号停用、锁定或尚未完成入驻期间，发给本企业的申请照常生成，等待处理；恢复可用后出现在待处理中，到期前仍可处理。

<a id="display-values"></a>
### 3.2 金额、日期与时间

- 金额、ERP 日期、附件的展示沿用 M3 [来源值、金额与时间](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#display-values) 与 [附件查看](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#file-view)：金额与币种同时展示、按 ERP 原值不取整；不同币种不相加。
- 应收账款到期日按 M3 [账期与到期状态（F-M3-04）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-04)的写法展示：时区写在日期后面，例如“2026-12-09（Africa/Lagos）”。
- 平台自己记录的时间（发起时间、处理时间、审核时间、关闭时间、状态更新时间）展示到分钟，按本人在 M1 [界面语言与时区（M1-F12）](../M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#M1-F12)中设置的时区展示并标明时区；未设置时按 UTC。
- 驳回原因按填写的原文展示，不随界面语言翻译；企业名称、发票号等业务值按原值展示。
- 平台自身的字段名称、状态名称、提示说明有中文、英文两套，随界面语言切换。

<a id="load-fail"></a>
### 3.3 加载失败与登录失效

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的金额、状态或待办数量，也不提供确认、驳回操作，避免在资料不全时作出结论。
- 详情中某一部分（如当次依据、处理记录）加载失败时，仅该部分提示失败并可重试，其他部分正常展示；当次依据未完整加载时不能确认或驳回。
- 待办数量取数失败时不展示数量，不展示为 0，菜单照常可用。
- 操作过程中登录失效、账号被停用或锁定时，按 M1 规则回到登录入口，本次未提交的操作不生效。

<a id="process-conditions"></a>
### 3.4 可以确认或驳回的条件

一笔申请同时满足以下全部条件时，债务人才可以确认或驳回。列表与详情按打开或刷新时的结果提供操作；提交时平台重新判断，以提交时为准。

| 条件 | 不满足时用户看到的结果 |
| --- | --- |
| 满足[谁能使用、看到什么](#access)的使用前提，且申请是发给本企业的 | 按无权访问处理，不返回任何内容 |
| 申请的发起企业不是本企业 | 不能处理，说明“不能处理本企业发起的申请” |
| 申请状态为“待债务人确认” | 不能处理，展示该申请的当前状态与结果，见下表 |
| 当前时间未到本笔应收账款的到期时点 | 不能处理，说明“应收账款已到期，该申请已关闭”，展示“已关闭” |

提交时申请已不是“待债务人确认”，本次提交不生效，按当前状态说明：

| 提交时的申请状态 | 用户看到的说明 |
| --- | --- |
| 待运营审核、运营审核通过 | 该申请已确认，不能重复处理 |
| 债务人已驳回 | 该申请已驳回，不能重复处理 |
| 已关闭 | 应收账款已到期，该申请已关闭 |

- 到期以到期时点为界：到期时点之前提交成功的确认或驳回有效；到期时点之后提交的一律不生效，即使 M7a 尚未完成关闭，也按“已关闭”处理。
- 核心资料状态、回款状态、回款预警、资料是否齐全都不是处理条件；债务人在这些情况下都可以确认或驳回。

## 4. 确权申请列表与待办数量（F-M7b-01）

适用角色与前提：满足[谁能使用、看到什么](#access)的债务人企业用户。范围为发给本企业的全部确权申请，每行一笔申请，分为待处理和已处理两组。

流程参见：[查看与处理确权申请（图 M7b-1）](./02-确权待办与确认处理-流程图与状态机.md#fig-m7b-1)。
验收参见：[确权申请列表与待办数量](./04-确权待办与确认处理-验收.md#acc-f-m7b-01)。

<a id="list-fields"></a>
### 4.1 列表信息

| 业务信息 | 含义 | 来源与缺失时 | 待处理 | 已处理 |
| --- | --- | --- | --- | --- |
| 申请编号 | 本笔申请的编号 | M7a 生成，不会缺失 | 展示 | 展示 |
| 发票号 | 申请对应的发票号 | 当次依据，不会缺失 | 展示 | 展示 |
| 债权人 | 发起申请的债权人企业名称 | 当次依据，不会缺失 | 展示 | 展示 |
| 应收账款金额及币种 | 发起时的应收账款金额 | 当次依据，不会缺失 | 展示 | 展示 |
| 应收账款到期日 | 到期日及其后的时区 | 当次依据，不会缺失 | 展示 | 展示 |
| 发起时间 | 申请提交成功的时间 | M7a 记录，不会缺失 | 展示 | 不展示 |
| 申请状态 | 见 M7a [申请状态](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#apply-status) | M7a，不会缺失 | 展示（均为“待债务人确认”） | 展示 |
| 状态更新时间 | 最近一次申请状态变化的时间 | M7a 记录，不会缺失 | 不展示 | 展示 |

- 只有到期状态为“未到期”的应收账款才能发起申请，因此当次依据中的到期日及时区不会缺失。
- 列表不展示应收账款编号，可按其查找；申请详情中展示。

操作：

- 每行可“查看”，进入[申请详情与当次依据（F-M7b-02）](#F-M7b-02)，返回后保留原有分组、查找、筛选和页码。
- 待处理的行可“确认”“驳回”，规则见[确认申请（F-M7b-03）](#F-M7b-03)、[驳回申请（F-M7b-04）](#F-M7b-04)；已处理的行没有处理操作。

查找与筛选：

- 按申请编号、发票号或应收账款编号查找，支持部分匹配；查找在当前分组内进行。
- 筛选：债权人、币种、应收账款到期日区间、发起时间区间；已处理组另可按申请状态筛选。多个条件同时生效。
- 待处理默认按应收账款到期日从早到晚排列，到期日相同时按发起时间从早到晚；先到期的排在前面，避免因到期关闭而错过处理。
- 已处理默认按状态更新时间从新到旧排列。

边界与异常：

- 本企业还没有收到过申请时，两组都展示“暂无确权申请”；待处理为空、已处理有记录时，待处理展示“暂无待处理的确权申请”；查找或筛选无结果时，展示“没有符合条件的申请”并可清除条件。
- 列表中的状态和可处理操作是打开或刷新时的结果；申请状态因处理、到期关闭或运营审核发生变化后，刷新时移入对应分组。
- 列表不提供新增、编辑、删除申请的操作，也不提供批量选择。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

<a id="pending-count"></a>
### 4.2 待办数量

- 待办数量为本企业申请状态为“待债务人确认”的申请笔数，随“确权申请”菜单展示；数量为 0 时不展示数量。
- 待办数量按本人打开或刷新页面时的结果展示；本企业确认或驳回一笔申请成功后，立即减少；收到新申请或待处理申请到期关闭后，在下一次打开或刷新时更新。
- 只有拥有债务人角色、已完成入驻的企业展示待办数量；入驻未完成时菜单锁定，不展示数量。
- 同时拥有两种角色的企业，待办数量只统计发给本企业的待处理申请，不含本企业发起的申请。
- 取数失败按[加载失败与登录失效](#load-fail)处理。

<a id="F-M7b-02"></a>
## 5. 申请详情与当次依据（F-M7b-02）

适用角色与前提：债务人企业用户，申请是发给本企业的。详情只读；申请为“待债务人确认”且满足[可以确认或驳回的条件](#process-conditions)时，详情中提供“确认”“驳回”。

流程参见：[查看与处理确权申请（图 M7b-1）](./02-确权待办与确认处理-流程图与状态机.md#fig-m7b-1)。
验收参见：[申请详情与当次依据](./04-确权待办与确认处理-验收.md#acc-f-m7b-02)。

<a id="apply-basic"></a>
### 5.1 申请信息

| 业务信息 | 含义 | 缺失时 |
| --- | --- | --- |
| 申请编号 | 本笔申请的编号 | 不会缺失 |
| 申请状态 | 见 M7a [申请状态](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#apply-status)，并按 M7a [确权与审核进度](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#progress-stage)展示环节 | 不会缺失 |
| 应收账款编号 | 可进入 M3 应收账款详情（当前资料，债务人可见范围） | 不会缺失 |
| 债权人 | 发起申请的债权人企业名称 | 不会缺失 |
| 债务人 | 本企业名称 | 不会缺失 |
| 发起时间 | 申请提交成功的时间 | 不会缺失 |
| 当前核心资料状态 | 本笔应收账款在 M3 中当前的核心资料状态；为“差异待核实”时展示 M3 [企业可见差异](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#enterprise-diff)中的说明 | 不会缺失 |

- 债务人看不到债权人企业用户的姓名，也看不到发起方式（单笔或批量）。
- 当前核心资料状态只作提示：申请照常可以确认或驳回，处理以当次依据为准。

<a id="process-record"></a>
### 5.2 处理记录

按发生时间顺序展示已经发生的处理，未发生的环节不展示结果：

| 环节 | 展示内容 | 来源 |
| --- | --- | --- |
| 发起申请 | 发起企业（债权人企业名称）、发起时间 | M7a |
| 债务人确认 | 处理结论（确认／驳回）、处理人（本企业用户在 M1 个人信息中的姓名）、处理时间；驳回时展示驳回原因 | 本模块 |
| 运营审核 | 审核结论（通过）、审核时间 | M9 |
| 关闭 | 关闭时间（到期时点）、关闭原因“应收账款已到期”、关闭前所处的环节 | M7a |

- 债务人看不到运营审核人姓名。
- 处理人姓名取处理当时的姓名，之后本人修改姓名不改写记录。
- 驳回原因按原文展示，不翻译。

<a id="snapshot-view"></a>
### 5.3 当次依据

- 按 M7a [当次依据](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#snapshot)展示，内容与分类顺序同 M7a：状态（到期状态、回款状态、核心资料状态）、应收账款信息、发票信息与附件、车辆信息明细、合同信息、回款统计。
- 当次依据中的全部内容债务人都可见；当次依据不含回款明细，因此不涉及债务人不可见的收款交易编号、收款银行、收款账号和收款凭证。
- 提交申请时未提供的项按“未提供”“附件未取得”“合同未取得”展示，不事后补入；附件为当时取得的版本，可在线查看和下载。
- 当次依据不随 ERP 更新、核心资料差异或核实而改变；详情同时提供进入 M3 当前资料的入口，两者不同时各自按原值展示，本模块不比较、不提示具体差异。

<a id="after-result"></a>
### 5.4 处理之后能看到什么

- 申请处理后、到期关闭后或运营审核通过后，详情仍可查看，全部内容只读，不再提供“确认”“驳回”。
- 申请为“债务人已驳回”、且债权人已对同一笔应收账款重新发起时，详情注明“债权人已重新发起”及新申请编号，可进入新申请；新申请出现在待处理中，与旧申请各自处理。
- 申请为“运营审核通过”时，申请状态展示“运营审核通过”。债务人看到的进度到“运营审核通过”为止，不展示出库进度；出库是债权人资产的对外提供，出库进度只在债权人一侧（M7a）和运营端展示。

边界与异常：

- 从消息前往的申请已不是“待债务人确认”时，只能查看当前结果，按 M10 [前往原业务（MSG-05）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-05)处理。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

<a id="F-M7b-03"></a>
## 6. 确认申请（F-M7b-03）

适用角色与前提：债务人企业用户；申请满足[可以确认或驳回的条件](#process-conditions)。入口为待处理列表中的行和申请详情。

通知：确认成功后向债权人企业发送[确权申请已被债务人确认（M7b-NT01）](./03-确权待办与确认处理-消息通知.md#M7b-NT01)，向全体运营发送[有新的确权申请待运营审核（M7b-NT03）](./03-确权待办与确认处理-消息通知.md#M7b-NT03)。
流程参见：[确认或驳回的提交（图 M7b-2）](./02-确权待办与确认处理-流程图与状态机.md#fig-m7b-2)。
验收参见：[确认申请](./04-确权待办与确认处理-验收.md#acc-f-m7b-03)。

<a id="confirm-view"></a>
确认时展示：

- 申请编号、债权人、发票号、应收账款编号、应收账款金额及币种、应收账款到期日及时区（均取自当次依据）。
- 说明“确认表示本企业认可这笔应收账款；确认后申请进入运营审核，不能撤回或改为驳回”。

结果：

- 用户确认提交后，平台按[可以确认或驳回的条件](#process-conditions)重新判断。满足时申请状态变为“待运营审核”，记录处理结论“确认”、处理企业、处理人、处理时间。
- 成功后展示申请编号与新状态“待运营审核”；该申请移入已处理，待办数量减 1，可进入其详情或返回列表。
- 确认只改变申请状态，不改变当次依据和应收账款资料；确认后由运营审核与资产出库（M9）审核。
- 用户取消确认时申请不变，回到确认入口所在处。

边界与异常：

- 提交时已不满足处理条件（已处理、已到期关闭、角色被移除、不是发给本企业的申请）：本次不生效，按[可以确认或驳回的条件](#process-conditions)说明结果，列表与详情刷新为最新状态。
- 重复点击提交，或同一申请在两个窗口分别提交确认、驳回：只有先提交成功的一次生效；后到的提交不生效，说明“该申请已确认，不能重复处理”或“该申请已驳回，不能重复处理”，并展示当前状态。
- 提交失败：申请不变，提示提交失败可重试。
- 提交后未收到明确结果（如网络中断）：提示“处理结果未确认，请刷新后查看”，不自动重新提交；再次提交时如已生效，按“不能重复处理”说明，不会生成第二次处理。
- 提交时登录失效或账号被停用：申请不变，按[加载失败与登录失效](#load-fail)处理。

<a id="F-M7b-04"></a>
## 7. 驳回申请（F-M7b-04）

适用角色与前提：债务人企业用户；申请满足[可以确认或驳回的条件](#process-conditions)。入口为待处理列表中的行和申请详情。

通知：驳回成功后向债权人企业发送[确权申请被债务人驳回（M7b-NT02）](./03-确权待办与确认处理-消息通知.md#M7b-NT02)。
流程参见：[确认或驳回的提交（图 M7b-2）](./02-确权待办与确认处理-流程图与状态机.md#fig-m7b-2)。
验收参见：[驳回申请](./04-确权待办与确认处理-验收.md#acc-f-m7b-04)。

<a id="reject-fields"></a>
驳回时填写：

| 业务信息 | 含义/类型 | 必填条件/默认值 | 可编辑范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 驳回原因 | 说明本企业不认可这笔应收账款的原因，如资料与事实不符的具体内容；多行文本 | 必填；无默认值 | 驳回提交前可编辑；提交后不能修改 | 去除首尾空格后 1～500 个字符；为空、只有空白或超过 500 个字符时不能提交并指出该项 |

驳回时同时展示申请编号、债权人、发票号、应收账款金额及币种，以及说明“驳回后本申请结束，不能撤回；驳回原因将展示给债权人”。

结果：

- 用户提交后，平台按[可以确认或驳回的条件](#process-conditions)重新判断。满足时申请状态变为“债务人已驳回”，记录处理结论“驳回”、驳回原因原文、处理企业、处理人、处理时间。
- 成功后展示申请编号与新状态“债务人已驳回”；该申请移入已处理，待办数量减 1。
- 驳回结果回到债权人：债权人在 M7a 申请记录与申请详情中看到驳回原因，满足申请资格时可重新发起，规则见 M7a [债务人驳回后的处理（F-M7a-07）](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#F-M7a-07)。重新发起是新的申请，债务人需重新处理。
- 驳回不改变当次依据和应收账款资料；资料有误时由 ERP 更新，本模块不提供补正。
- 用户取消驳回时申请不变，已填写的原因不保存。

边界与异常：

- 提交时已不满足处理条件、重复点击或两个窗口同时处理、提交后未收到明确结果、登录失效：与[确认申请（F-M7b-03）](#F-M7b-03)的边界与异常相同。
- 提交失败：申请不变，保留已填写的驳回原因，提示提交失败可重试。

<a id="records"></a>
## 8. 操作留痕

- 每次生效的确认或驳回留存：申请编号、应收账款编号、处理企业、处理人、处理时间、处理结论、驳回原因原文。
- 留痕不可编辑、不可删除；运营查看方式由 M9 定义。
- 因不满足处理条件、提交失败或重复提交而未生效的操作，不形成处理记录，申请状态不变；其中越权访问被拒绝的按 M1 [安全记录](../M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#security-records)留存。

<a id="pending"></a>
## 9. 待确认事项与依赖

本模块当前没有待确认事项。

依赖：

- 企业登录与首次入驻（M1）：入驻完成状态、企业用户姓名、界面语言与时区、债务人角色入口与无权访问、安全记录。
- 运营登录、企业邀请与企业管理（M2）：平台企业、企业唯一用户、债务人角色分配、账号启停。
- 应收账款与发票（M3）：发给本企业的申请所对应的应收账款详情（债务人可见范围）、到期状态与到期时点、核心资料状态及企业可见差异说明；按 M7a 的申请状态与环节名称展示确权与审核进度，债务人看到发给本企业的最近一笔申请；债务人视角的进度条不接出库环节。
- 应收查看与确权申请（M7a）：生成申请与申请编号、当次依据、申请状态定义、到期自动关闭（含关闭时间、关闭前环节）、债权人重新发起；接收本模块的确认、驳回结论，使申请状态变为“待运营审核”“债务人已驳回”。M7a 在到期时点关闭待确认申请时，向本企业发送“待确认的确权申请已到期关闭（M7a-NT03）”，打开后前往本模块该申请的详情。
- 运营审核与资产出库（M9）：审核“待运营审核”的申请，运营审核只有通过，带来“运营审核通过”及审核时间；本模块发出的“有新的确权申请待运营审核（M7b-NT03）”打开后前往 M9 中该申请的审核详情，M9 不再发同义消息；到期时点之后的审核通过不生效；出库进度对债务人不可见。
- 消息中心（M10）：承接本模块发出的站内消息，按 [来源接入要求（MSG-06）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-06)。
- 处理条件须以提交时的数据为准、同一申请只有一次处理生效、到期时点之后的提交不生效，实现与验证归研发、测试。
