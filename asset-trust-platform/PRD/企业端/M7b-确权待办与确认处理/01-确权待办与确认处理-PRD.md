## 1. 模块是什么

债务人企业用户在“确权申请”业务入口中，查看债权人发给本企业的确权申请，核对申请当次提交的应收账款资料和这笔应收账款的当前资料，逐笔确认或驳回。确认后申请进入运营审核；驳回时必须写明原因，结果回到债权人，债权人可在条件满足时重新发起。处理过的申请和因到期关闭的申请仍可查看。债务人看到的应收账款详情也在本模块，债务人不需要进入其他模块。申请的发起、申请状态和到期关闭由应收查看与确权申请（M7a）定义；应收账款的数据口径（起算日与到期日、到期状态、回款状态、美元折算、核心资料状态）由应收账款（M3）定义，本模块按其取值展示，不修改；运营审核由运营审核与资产推送（M9）负责。

基本原则：

- 只处理发给本企业的申请。一笔申请的债务人是内销买方对应的平台企业；同时拥有债权人、债务人角色的企业，在本模块只以债务人身份出现，看不到、也不能处理本企业自己发起的申请。
- 一次只处理一笔。确认和驳回都逐笔进行，本期没有批量确认。
- 只按当次依据处理。债务人核对的是债权人发起申请时记录的资料；申请提交后资料变化不要求重新确认，也不阻止确认或驳回。
- 确认不等于审核通过，更不等于推送。确认后申请变为“待运营审核”，由运营审核决定能否推送。
- 确认、驳回都是终局结论，提交后不能撤回或改为另一结论。
- 企业端只读：确认和驳回都不需要也不允许上传、补充或修改应收账款资料；驳回只填写原因。
- 应收账款到期时仍待确认的申请由 M7a 自动关闭；到期时点之后提交的确认或驳回不生效。

**一个完整的例子**（企业名称、编号与金额为演示值）。平台企业 Carloha Holding 拥有债权人角色，平台企业 Carloha Nigeria 拥有债务人角色并已完成入驻。Holding 对两笔应收账款批量发起确权，生成申请 AP-0001（应收账款 AR-0012，内销发票 PI-0012，应收账款金额 60,000.00 USD，到期日 2026-12-09）和 AP-0002（应收账款 AR-0015，内销发票 PI-0015，40,000.00 USD）。Nigeria 的企业用户收到两条“收到新的确权申请”站内消息，左侧“确权申请”菜单显示待办数量 2。用户打开待处理列表，进入 AP-0001 的申请详情，核对当次依据中的应收账款信息、内销发票与附件、内销合同摘要、车辆清单和回款，再点应收账款编号进入 AR-0012 的应收账款详情，看到当前已收款、待收款金额和回款状态，返回后点“确认”，确认时看到申请编号、债权人、内销发票号、应收账款编号、金额和到期日，以及“确认后进入运营审核，不能撤回”。提交后 AP-0001 变为“待运营审核”，移入已处理列表，待办数量变为 1；Holding 收到“确权申请已被债务人确认”，全体运营收到“有新的确权申请待运营审核”。用户再打开 AP-0002，发现合同金额与发票不一致，选择“驳回”，填写原因“合同金额与发票不一致”后提交；AP-0002 变为“债务人已驳回”，待办数量变为 0，Holding 收到带驳回原因的消息。ERP 更新合同后，Holding 对同一笔应收账款重新发起，生成新申请 AP-0003，Nigeria 的待处理列表中出现 AP-0003；AP-0002 的详情注明“债权人已重新发起”及新申请编号。之后运营审核通过 AP-0001，Nigeria 在已处理列表中看到 AP-0001 的状态变为“运营审核通过”。

### 1.1 需求清单

| [确权申请列表与待办数量（F-M7b-01）](#F-M7b-01) | 债务人企业用户 | 看到还有哪些申请等本企业处理，以及处理过的申请的后续结果 | 不漏处理，便于回看 |

| [应收账款详情（F-M7b-05）](#F-M7b-05) | 债务人企业用户 | 查看申请所对应的应收账款当前的金额、期限、回款和最近一笔申请结果 | 确认或驳回前核对同一张内销发票的现状 |
| [确认申请（F-M7b-03）](#F-M7b-03) | 债务人企业用户 | 认可一笔应收账款，让申请进入运营审核 | 完成债务人确认 |
| [驳回申请（F-M7b-04）](#F-M7b-04) | 债务人企业用户 | 不认可时驳回并说明原因 | 让债权人知道问题所在，能在条件满足时重新发起 |

### 1.2 本期不做

- 批量确认或批量驳回。
- 撤回已提交的确认或驳回，或把确认改为驳回、把驳回改为确认。
- 确认或驳回时上传文件、补充或修改应收账款资料；驳回原因不设分类。
- 确认时填写说明。
- 钱包签名确认：确认按本人登录身份生效，不另要求钱包签名。
- 申请的发起、重新发起、申请状态定义与到期关闭：由应收查看与确权申请（M7a）定义。
- 运营审核与推送：由运营审核与资产推送（M9）定义。
- 向债务人展示推送进度。
- 债务人查看本企业全部应付：没有“全部应付”列表，债务人只能经由发给本企业的申请进入对应的[应收账款详情（F-M7b-05）](#F-M7b-05)。
- 应收账款数据的计算口径（起算日与到期日、到期状态、回款计入与回款状态、美元折算、核心资料差异与核实）：由 M3 定义，本模块只引用。
- 企业端的资产健康度、车辆清单（当次依据中的除外）、回款记录明细、风控预警：企业端不展示，这些资料用户可在本企业 ERP 中查看。
- 到期前的催办或提醒消息。
- 中文、英文以外的语言。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 确权申请 | 债权人请债务人确认某一笔应收账款的申请，一笔申请只对应一笔应收账款，由 M7a 生成；申请编号全平台唯一 |
| 债务人企业用户 | 拥有债务人角色的平台企业的唯一用户；本册所称“债务人”即指该用户代表本企业操作 |
| 发给本企业的申请 | 当次依据中的债务人是本企业的确权申请 |
| 申请状态 | 一笔申请当前的结果，沿用 M7a [申请状态](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#apply-status)：待债务人确认／债务人已驳回／待运营审核／运营审核通过／已关闭 |
| 待处理 | 申请状态为“待债务人确认”的发给本企业的申请。“待处理”是列表分组，不是另一种状态 |
| 已处理 | 申请状态不是“待债务人确认”的发给本企业的申请，包括本企业已确认或已驳回的，以及因到期关闭、本企业未处理的申请 |
| 待办数量 | 本企业待处理申请的笔数 |
| 当次依据 | 债权人提交申请成功那一刻本笔应收账款的资料记录，由 M7a 保存，见 M7a [当次依据](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#snapshot) |
| 到期时点 | 本笔应收账款到期日当天结束的时刻，即到期状态由“未到期”变为“已到期”的时点，判定按 M3 [到期状态](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#due-status) |

## 3. 共用规则

本节规则适用于本模块全部功能，其他章节直接引用，不重复展开。

<a id="access"></a>
### 3.1 谁能使用、看到什么

- 使用前提：已完成首次入驻（M1），且本企业拥有债务人角色。业务入口、入驻期间的菜单锁定与角色不可用时的处理按 M1 [角色业务入口与无权访问（M1-F08）](../M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#M1-F08)。
- 债务人只能看到发给本企业的申请，以及这些申请对应的[应收账款详情（F-M7b-05）](#F-M7b-05)。
- 打开不是发给本企业的申请，或没有发给本企业申请的应收账款（含改写链接中的编号）时，统一提示“该内容不存在或无权查看”，不透露其是否存在及任何内容。越权访问被拒绝时按 M1 [安全记录](../M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#security-records)留存。
- 同时拥有债权人、债务人角色的企业，在本模块只以债务人身份出现：只看本企业作为内销买方收到的申请及其应收账款；本企业作为债权人的应收账款与发起的申请在 M7a 查看，在本模块打开时按上一条的不可访问处理。M2 规定一个平台企业只关联一个 ERP 企业，同一张内销发票的内销卖方、内销买方不会对应到同一平台企业。
- 本企业尚未完成入驻或账号临时锁定期间，发给本企业的申请照常等待处理；可以使用后出现在待处理中，到期前仍可处理。

<a id="display-values"></a>
### 3.2 金额、日期、时间与语言

- 应收账款金额、已收款金额、待收款金额以美元展示：
  - 申请列表、确认与驳回时展示的应收账款金额（美元）取自当次依据，即提交时按当时汇率折算的值，之后不随汇率变化；当次依据中为“无法折算”时，展示“无法折算”并注明原币金额及币种。
  - [应收账款详情（F-M7b-05）](#F-M7b-05)展示当前资料，美元金额按 M3 [已收、待收与比率](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#repay-summary)和[美元折算与比率](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#usd-rule)以打开或刷新页面时的当前汇率折算，同一页面内只用一个汇率；无法折算时展示“无法折算”，并在应收账款金额旁注明原币金额及币种。不以 0 或原币数值代替美元金额。
- 原币金额（内销发票金额及币种）只作为核对依据展示，按 ERP 原值，不取整。ERP 提供的日期按原样展示。
- ERP 没有提供某项值时展示“未提供”，附件没有取得时展示“附件未取得”，关联单据不存在时展示“未取得”（如“内销合同未取得”）；企业端按文字展示，不使用占位符“-”。附件可在线查看和下载，打开失败按 M3 [附件查看](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#file-view)。
- 应收账款起算日、到期日是 M3 计算的日期，只有日期，不带时区；未确定时展示“未确定”，起算日另注明原因（如“尚有 N 辆车未装船”），按 M3 [账期与到期状态（F-M3-04）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-04)。
- 平台自己记录的时间（发起时间、处理时间、审核时间、关闭时间、状态更新时间）展示到分钟，按本人在 M1 [界面语言与时区（M1-F12）](../M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#M1-F12)中的时区展示并标明时区。
- 驳回原因按填写的原文展示，不随界面语言翻译；企业名称、内销发票号等业务值按原值展示。
- 平台自身的字段名称、状态名称、提示说明有中文、英文两套，随界面语言切换；英文措辞以原型文案为准，与中文含义一致；原型尚未给出英文的文字，在原型定稿前只要求英文界面展示含义一致的英文，措辞以原型定稿为准。
- 企业端的单据编号（内销发票号、内销合同号）只展示、不可点击；申请编号可进入本模块的[申请详情与当次依据（F-M7b-02）](#F-M7b-02)，应收账款编号可进入[应收账款详情（F-M7b-05）](#F-M7b-05)。

<a id="load-fail"></a>
### 3.3 加载失败与登录失效

- 列表或详情加载失败时，提示加载失败并可重试；不展示不完整的金额、状态或待办数量，也不提供确认、驳回操作，避免在资料不全时作出结论。
- 详情中某一部分（如当次依据、处理记录、确权申请）加载失败时，仅该部分提示失败并可重试，其他部分正常展示；当次依据未完整加载时不能确认或驳回。
- 待办数量取数失败时不展示数量，不展示为 0，菜单照常可用。
- 操作过程中登录结束（到期、无操作、临时锁定等）时，按 M1 [登录结束后的处理](../M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#session-end)回到登录入口，本次未提交的操作不生效。

<a id="process-conditions"></a>
### 3.4 可以确认或驳回的条件

一笔申请同时满足以下全部条件时，债务人才可以确认或驳回。列表与详情按打开或刷新时的结果提供操作；提交时平台重新判断，以提交时为准。

| 条件 | 不满足时用户看到的结果 |
| --- | --- |
| 满足[谁能使用、看到什么](#access)的使用前提，且申请是发给本企业的 | 按无权访问处理，不返回任何内容 |
| 申请状态为“待债务人确认” | 不能处理，展示该申请的当前状态与结果，见下表 |
| 当前时间未到本笔应收账款的到期时点 | 不能处理，说明“应收账款已到期，该申请已关闭”，展示“已关闭” |

提交时申请已不是“待债务人确认”，本次提交不生效，按当前状态说明：

| 提交时的申请状态 | 用户看到的说明 |
| --- | --- |
| 待运营审核、运营审核通过 | 该申请已确认，不能重复处理 |
| 债务人已驳回 | 该申请已驳回，不能重复处理 |
| 已关闭 | 应收账款已到期，该申请已关闭 |

- 到期以到期时点为界，按平台收到提交的时刻判断（以平台时间为准，与用户设备时间和本人时区无关）：
  - 收到时刻早于到期时点的，按本表其他条件判断，满足即生效；生效记录在到期时点之后才完成的，仍按收到时刻有效。
  - 收到时刻等于或晚于到期时点的（到期日当天 UTC+1 的 24:00:00.000 起），一律不生效，即使 M7a 尚未完成关闭，也按“已关闭”处理。
  - 生效的确认、驳回，处理时间记为平台收到提交的时刻。
  - 与到期关闭的先后：收到时刻早于到期时点、且满足其他条件的确认或驳回，即使 M7a 的[到期自动关闭（F-M7a-08）](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#F-M7a-08)在其生效记录完成前执行，也以这次处理为准，视为发生在关闭之前：
    - 驳回：申请为“债务人已驳回”，不被关闭；发送[确权申请被债务人驳回（M7b-NT02）](./03-确权待办与确认处理-消息通知.md#M7b-NT02)，不发送 M7a 的到期关闭消息。
    - 确认：申请先变为“待运营审核”，发送[确权申请已被债务人确认（M7b-NT01）](./03-确权待办与确认处理-消息通知.md#M7b-NT01)和[有新的确权申请待运营审核（M7b-NT03）](./03-确权待办与确认处理-消息通知.md#M7b-NT03)；随后按 M7a 到期关闭变为“已关闭（关闭前为待运营审核）”，关闭消息按 M7a，不发送“待确认的确权申请已到期关闭（M7a-NT03）”。
    - 先后顺序由平台保证，用户看不到中间的不一致结果；实现与验证归研发、测试。M7a 一侧的同步见[到期关闭与临界处理的先后（Q-M7b-04）](#Q-M7b-04)。
- 核心资料状态、回款状态、风控预警，以及 M3 [资料齐全且有效（F-M3-15）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-15)的当前结果，都不是处理条件；债务人在这些情况下都可以确认或驳回，处理以当次依据为准。

## 4. 确权申请列表与待办数量（F-M7b-01）

适用角色与前提：满足[谁能使用、看到什么](#access)的债务人企业用户。范围为发给本企业的全部确权申请，每行一笔申请，分为待处理和已处理两组。

流程参见：[查看与处理确权申请（图 M7b-1）](./02-确权待办与确认处理-流程图与状态机.md#fig-m7b-1)。
验收参见：[确权申请列表与待办数量](./04-确权待办与确认处理-验收.md#acc-f-m7b-01)。

<a id="list-fields"></a>
### 4.1 列表信息

| 业务信息 | 含义 | 来源与缺失时 | 待处理 | 已处理 |
| --- | --- | --- | --- | --- |
| 申请编号 | 本笔申请的编号 | M7a 生成，不会缺失 | 展示 | 展示 |
| 内销发票号 | 申请对应的内销发票号 | 当次依据，不会缺失 | 展示 | 展示 |
| 债权人 | 发起申请的债权人企业名称 | 当次依据，不会缺失 | 展示 | 展示 |
| 应收账款金额（美元） | 当次依据中提交时的美元金额，按[金额、日期、时间与语言](#display-values) | 当次依据；提交时无法折算的展示“无法折算”并注明原币金额及币种 | 展示 | 展示 |
| 应收账款到期日 | 发起时的应收账款到期日 | 当次依据，不会缺失 | 展示 | 展示 |
| 发起时间 | 申请提交成功的时间 | M7a 记录，不会缺失 | 展示 | 不展示 |
| 申请状态 | 见 M7a [申请状态](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#apply-status) | M7a，不会缺失 | 展示（均为“待债务人确认”） | 展示 |
| 状态更新时间 | 最近一次申请状态变化的时间 | M7a 记录，不会缺失 | 不展示 | 展示 |

- 到期日未确定或已到期的应收账款不能发起申请（见 M7a [可申请的条件](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#eligibility)），因此当次依据中的到期日不会缺失。
- 列表不展示应收账款编号，可按其查找；申请详情中展示，并可进入[应收账款详情（F-M7b-05）](#F-M7b-05)。

操作：

- 每行可“查看”，进入[申请详情与当次依据（F-M7b-02）](#F-M7b-02)，返回后保留原有分组、查找、筛选和页码。
- 待处理的行可“确认”“驳回”，规则见[确认申请（F-M7b-03）](#F-M7b-03)、[驳回申请（F-M7b-04）](#F-M7b-04)；已处理的行没有处理操作。

查找与筛选：

- 按申请编号、内销发票号或应收账款编号查找，支持部分匹配；查找在当前分组内进行。查找内容先去掉首尾空格（含全角空格），再匹配；不区分英文字母大小写；全角与半角字符视为不同字符，不做转换。去掉首尾空格后为空的，按未输入查找条件处理。
- 筛选：债权人、应收账款到期日区间、发起时间区间；已处理组另可按申请状态筛选。多个条件同时生效。
- 待处理默认按应收账款到期日从早到晚排列，到期日相同时按发起时间从早到晚，两者都相同（如同一批发起）时按申请编号升序；先到期的排在前面，避免因到期关闭而错过处理。
- 已处理默认按状态更新时间从新到旧排列，相同时按申请编号升序。
- 时间比较用平台记录的完整时间，不只看展示到分钟的值；申请编号升序为逐个字符比较、不区分大小写（例如 AP-10 排在 AP-9 之前）。

边界与异常：

- 本企业还没有收到过申请时，两组都展示“暂无确权申请”；待处理为空、已处理有记录时，待处理展示“暂无待处理的确权申请”；查找或筛选无结果时，展示“没有符合条件的申请”并可清除条件。
- 列表中的状态和可处理操作是打开或刷新时的结果；申请状态因处理、到期关闭或运营审核发生变化后，刷新时移入对应分组。
- 列表不提供新增、编辑、删除申请的操作，也不提供批量选择。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

<a id="pending-count"></a>
### 4.2 待办数量

- 待办数量为本企业申请状态为“待债务人确认”的申请笔数，随“确权申请”菜单展示；数量为 0 时不展示数量。
- 待办数量按本人打开或刷新页面时的结果展示；本企业确认或驳回一笔申请成功后，立即减少；收到新申请或待处理申请到期关闭后，在下一次打开或刷新时更新。
- 只有拥有债务人角色、已完成入驻的企业展示待办数量；入驻未完成时菜单锁定，不展示数量。
- 同时拥有两种角色的企业，待办数量只统计发给本企业的待处理申请，不含本企业发起的申请。
- 取数失败按[加载失败与登录失效](#load-fail)处理。

### 5.3 当次依据

### 5.4 处理之后能看到什么

- 申请处理后、到期关闭后或运营审核通过后，详情仍可查看，全部内容只读，不再提供“确认”“驳回”。
- 申请为“债务人已驳回”、且债权人已对同一笔应收账款重新发起时，详情注明“债权人已重新发起”及新申请编号，可进入新申请；新申请出现在待处理中，与旧申请各自处理。
- 申请为“运营审核通过”时，申请状态展示“运营审核通过”。债务人看到的进度到“运营审核通过”为止，本模块不展示推送进度。

边界与异常：

- 从消息前往的申请已不是“待债务人确认”时，只能查看当前结果，按 M10 [前往原业务（MSG-05）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-05)处理。
- 加载失败按[加载失败与登录失效](#load-fail)处理。

## 6. 应收账款详情（F-M7b-05）

适用角色与前提：满足[谁能使用、看到什么](#access)的债务人企业用户；本笔应收账款至少有一笔发给本企业的申请（任一申请状态）。从[申请详情与当次依据（F-M7b-02）](#F-M7b-02)中的应收账款编号或当前资料入口进入，可返回进入前的申请详情。详情只读，展示本笔应收账款的当前资料；没有任何编辑、补传、核实或发起申请的操作。

流程参见：[查看与处理确权申请（图 M7b-1）](./02-确权待办与确认处理-流程图与状态机.md#fig-m7b-1)。
验收参见：[应收账款详情](./04-确权待办与确认处理-验收.md#acc-f-m7b-05)。

<a id="receivable-content"></a>
### 6.1 展示内容

详情只展示核对金额、期限和办理确认所需的关键信息，取值与运营端相同，均按 M3 当前资料：

| 部分 | 业务信息 | 缺失时 |
| --- | --- | --- |
| 概要 | 债权人 → 债务人（平台企业名称） | 不会缺失（发给本企业的申请，双方都已对应平台企业） |
| 概要 | 应收账款编号 | 不会缺失 |
| 概要 | 应收账款金额（美元） | “无法折算”，并注明原币金额及币种 |
| 概要 | 已收款金额（美元）、待收款金额（美元） | “无法折算”；在 1% 容差内视为已收清但仍有差额时，按 M3 [已收、待收与比率](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#repay-summary)注明“在 1% 容差内视为已收清” |
| 概要 | 应收账款起算日 | “未确定”及原因 |
| 概要 | 应收账款到期日（不展示剩余天数） | “未确定” |
| 概要 | 账期 | “未提供” |
| 概要 | 到期状态、回款状态 | 不会缺失 |
| 内销发票 | 内销发票号、内销发票日期、内销发票金额及币种（原币）、内销发票附件 | 日期为“未提供”，附件为“附件未取得” |
| 内销合同 | 内销合同号、内销合同附件 | 关联的内销合同不存在时为“内销合同未取得”，附件为“附件未取得” |
| 确权申请 | 见[确权申请结果](#receivable-apply) | 不会缺失（至少有一笔发给本企业的申请） |

<a id="receivable-diff"></a>
- 企业可见差异说明：核心资料状态为“差异待核实”时，详情展示 M3 的原资料，并说明“本笔应收账款的核心资料存在差异，平台正在核实，当前展示原资料”；不展示差异明细、核实说明和依据文件。状态为“一致”时不展示该说明。该说明只作提示，申请照常可以确认或驳回。
- 企业端不展示：资产健康度、已收款比率、车辆清单、回款记录明细（含收付日期、收款银行、账号与凭证）、内销合同日期、金额与付款条件、预警信息与关联预警、ERP 账款起算日与到期日、首次取得时间、核心资料差异明细与核实记录、M3 [资料齐全且有效（F-M3-15）](../../两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md#F-M3-15)的校验结果与问题项，以及任何单据跳转。
- 申请发起时记录的车辆清单、内销合同日期与金额等，在申请详情的[当次依据](#snapshot-view)中查看。
- 企业端不注明“暂计”：M3 对当天外币回款的“暂计”标注在回款记录上，企业端不展示回款记录；已收款、待收款金额本身按查看时的当前汇率折算，随汇率和回款更新而变化，回款状态按 M3 判定后原样展示。

<a id="receivable-apply"></a>
### 6.2 确权申请结果

展示发给本企业的最近一笔申请的申请编号和申请状态，并提供进入其[申请详情与当次依据（F-M7b-02）](#F-M7b-02)的入口：入口与申请结果在同一区域，以文字呈现，不需要展开其他内容即可看到；视觉上是否足够明显由原型评审确认。按状态附带以下信息：

| 申请状态 | 附带展示 |
| --- | --- |
| 待债务人确认、待运营审核 | 无 |
| 债务人已驳回 | 驳回原因 |
| 已关闭 | 关闭原因“应收账款已到期” |
| 运营审核通过 | 无，不展示推送进度 |

- 发给本企业的最近一笔申请指本笔应收账款发给本企业的申请中发起时间最晚的一笔；从较早的申请进入时，这里同样展示最近一笔。
- 发给本企业的全部申请在[确权申请列表与待办数量（F-M7b-01）](#F-M7b-01)中查看；“发起申请—债务人确认—运营审核”的进度与处理记录在申请详情中查看。
- 申请为“待债务人确认”时，确认、驳回在申请详情或待处理列表中办理，本详情不提供处理操作。

<a id="receivable-errors"></a>
### 6.3 边界与异常

- 本笔应收账款没有发给本企业的申请，或本企业不是其债务人时，按[谁能使用、看到什么](#access)的不可访问处理。
- 运营在 M2 取消本企业与 ERP 企业的关联后（有处理中申请时不能取消，按 M2 [关联 ERP 企业（F-EN-10）](../../运营端/M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-EN-10)），本笔应收账款详情不可访问（含从申请详情中的应收账款编号进入），按上一条处理；发给本企业的申请及其当次依据仍在列表和申请详情中可查看，列表中按应收账款编号仍能查到这些申请。
- 详情或其中一部分加载失败按[加载失败与登录失效](#load-fail)处理；确权申请部分加载失败时，不展示申请状态。

<a id="F-M7b-03"></a>
## 7. 确认申请（F-M7b-03）

适用角色与前提：债务人企业用户；申请满足[可以确认或驳回的条件](#process-conditions)。入口为待处理列表中的行和申请详情。

通知：确认成功后向债权人企业发送[确权申请已被债务人确认（M7b-NT01）](./03-确权待办与确认处理-消息通知.md#M7b-NT01)，向全体运营发送[有新的确权申请待运营审核（M7b-NT03）](./03-确权待办与确认处理-消息通知.md#M7b-NT03)。
流程参见：[确认或驳回的提交（图 M7b-2）](./02-确权待办与确认处理-流程图与状态机.md#fig-m7b-2)。
验收参见：[确认申请](./04-确权待办与确认处理-验收.md#acc-f-m7b-03)。

<a id="confirm-view"></a>
确认时展示：

- 申请编号、债权人、内销发票号、应收账款编号、应收账款金额（美元）、应收账款到期日（均取自当次依据；美元金额为“无法折算”时注明原币金额及币种）。
- 说明“确认表示本企业认可这笔应收账款；确认后申请进入运营审核，不能撤回或改为驳回”。

结果：

- 用户确认提交后，平台按[可以确认或驳回的条件](#process-conditions)重新判断。满足时申请状态变为“待运营审核”，记录处理结论“确认”、处理企业、处理人、处理时间。
- 成功后展示申请编号与新状态“待运营审核”；该申请移入已处理，待办数量减 1，可进入其详情或返回列表。
- 确认只改变申请状态，不改变当次依据和应收账款资料；确认后由运营审核与资产推送（M9）审核。
- 用户取消确认时申请不变，回到确认入口所在处。

边界与异常：

- 提交时已不满足处理条件（已处理、已到期关闭、不是发给本企业的申请）：本次不生效，按[可以确认或驳回的条件](#process-conditions)说明结果，列表与详情刷新为最新状态。
- 重复点击提交，或同一申请在两个窗口分别提交确认、驳回：只有先提交成功的一次生效；后到的提交不生效，说明“该申请已确认，不能重复处理”或“该申请已驳回，不能重复处理”，并展示当前状态。
- 提交失败：申请不变，提示提交失败可重试。
- 提交后未收到明确结果（如网络中断）：提示“处理结果未确认，请刷新后查看”，不自动重新提交；再次提交时如已生效，按“不能重复处理”说明，不会生成第二次处理。
- 提交时登录已结束：申请不变，按[加载失败与登录失效](#load-fail)处理。

<a id="F-M7b-04"></a>
## 8. 驳回申请（F-M7b-04）

适用角色与前提：债务人企业用户；申请满足[可以确认或驳回的条件](#process-conditions)。入口为待处理列表中的行和申请详情。

通知：驳回成功后向债权人企业发送[确权申请被债务人驳回（M7b-NT02）](./03-确权待办与确认处理-消息通知.md#M7b-NT02)。
流程参见：[确认或驳回的提交（图 M7b-2）](./02-确权待办与确认处理-流程图与状态机.md#fig-m7b-2)。
验收参见：[驳回申请](./04-确权待办与确认处理-验收.md#acc-f-m7b-04)。

<a id="reject-fields"></a>
驳回时填写：

| 业务信息 | 含义/类型 | 必填条件/默认值 | 可编辑范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 驳回原因 | 说明本企业不认可这笔应收账款的原因，如资料与事实不符的具体内容；多行文本 | 必填；无默认值 | 驳回提交前可编辑；提交后不能修改 | 去除首尾空白（普通空格、全角空格、换行、制表符）后 1～500 个字符；为空、只有空白或超过 500 个字符时不能提交并指出该项 |

驳回原因的计数与保存：

- 按用户看到的字符计数：一个汉字、字母、数字、标点、空格或 emoji（含组合 emoji、带组合符号的字符）都算 1 个；中间的一个换行算 1 个。
- 中间的空格（含连续空格）和换行原样保留，并计入字数；保存与展示的是去除首尾空白后的内容。

驳回时同时展示申请编号、债权人、内销发票号、应收账款金额（美元）（取自当次依据，规则同确认），以及说明“驳回后本申请结束，不能撤回；驳回原因将展示给债权人”。

结果：

- 用户提交后，平台按[可以确认或驳回的条件](#process-conditions)重新判断。满足时申请状态变为“债务人已驳回”，记录处理结论“驳回”、驳回原因原文、处理企业、处理人、处理时间。
- 成功后展示申请编号与新状态“债务人已驳回”；该申请移入已处理，待办数量减 1。
- 驳回结果回到债权人：债权人在 M7a 应收账款详情与申请详情中看到驳回原因，满足申请资格时可重新发起，规则见 M7a [债务人驳回后的处理（F-M7a-07）](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#F-M7a-07)。重新发起是新的申请，债务人需重新处理。
- 驳回不改变当次依据和应收账款资料；资料有误时由 ERP 更新，本模块不提供补正。
- 用户取消驳回时申请不变，已填写的原因不保存。

边界与异常：

- 提交时已不满足处理条件、重复点击或两个窗口同时处理、提交后未收到明确结果、登录已结束：与[确认申请（F-M7b-03）](#F-M7b-03)的边界与异常相同。
- 提交失败：申请不变，保留已填写的驳回原因，提示提交失败可重试。

<a id="records"></a>
## 9. 操作留痕

- 每次生效的确认或驳回留存：申请编号、应收账款编号、处理企业、处理人、处理时间、处理结论、驳回原因原文。
- 留痕不可编辑、不可删除；运营在 M9 [处理记录](../../运营端/M9-运营审核/01-运营审核-PRD.md#process-record)中查看。
- 因不满足处理条件、提交失败或重复提交而未生效的操作，不形成处理记录，申请状态不变；其中越权访问被拒绝的按 M1 [安全记录](../M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md#security-records)留存。

## 10. 待确认事项与依赖

下表各项在确认前按“当前处理”执行；已关闭的待确认事项不再占号。

| 编号 | 事项（具体冲突点） | 当前处理 | 影响 |
| --- | --- | --- | --- |
| <a id="Q-M7b-04"></a>到期关闭与临界处理的先后（Q-M7b-04） | 本模块按平台收到提交的时刻判断到期，收到早于到期时点的确认或驳回以这次处理为准；M7a [到期自动关闭（F-M7a-08）](../M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md#F-M7a-08)只写“到期时点之前已生效的”照常有效，且允许在到期时点后 5 分钟内完成关闭，没有写明关闭执行时遇到已收到、尚未完成记录的处理如何处理 | 按本模块[可以确认或驳回的条件](#process-conditions)中“与到期关闭的先后”执行；M7a 在 F-M7a-08 中写明“到期时点之前已收到的确认、驳回视为已生效，关闭以处理后的状态为准”后，本项关闭 | M7a、本模块 AC-M7b-06 场景 5 |

依赖：

- 企业登录与首次入驻（M1）：入驻完成状态、企业用户姓名、界面语言与时区、业务入口与无权访问、登录结束后的处理、安全记录。
- 运营登录、企业邀请与企业管理（M2）：平台企业、企业唯一用户、债务人角色分配（只增不减）；平台企业与 ERP 企业一对一关联，有处理中申请时不能取消关联。
- 应收账款（M3）：发给本企业的申请所对应的应收账款及其当前资料、平台计算的起算日与到期日、到期状态与到期时点、回款计入与回款状态、美元金额（按 M11 当前汇率折算）、核心资料状态（是否改由 M8 处理待 M3 定，确定前按现行规则）。M3 不再定义企业端的入口与可见内容，债务人视角以本模块为准；M3 的资料齐全且有效（F-M3-15）只约束 M7a 发起和 M9 审核与推送，不约束本模块的确认与驳回。
- 应收查看与确权申请（M7a）：生成申请与申请编号、当次依据（含提交时的美元金额与折算汇率）、申请状态定义、到期自动关闭（含关闭时间、关闭前环节）、债权人重新发起；接收本模块的确认、驳回结论，使申请状态变为“待运营审核”“债务人已驳回”；发送“收到新的确权申请（M7a-NT01）”“待确认的确权申请已到期关闭（M7a-NT03）”，打开后前往本模块该申请的详情。
- 运营审核与资产推送（M9）：审核“待运营审核”的申请，带来“运营审核通过”及审核时间；承接本模块发出的“有新的确权申请待运营审核（M7b-NT03）”，打开后前往 M9 中该申请的审核详情。
- 消息中心（M10）：承接本模块发出的站内消息，按[来源接入要求（MSG-06）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-06)。
- 处理条件须以提交时的数据为准、同一申请只有一次处理生效、到期时点之后的提交不生效，实现与验证归研发、测试。
