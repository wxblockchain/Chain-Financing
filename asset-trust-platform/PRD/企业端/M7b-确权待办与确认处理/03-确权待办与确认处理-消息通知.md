# 确权待办与确认处理 · 消息通知

2026-11-12｜需求评审稿｜配套[功能与业务规则](./01-确权待办与确认处理-PRD.md)

本模块发送 3 类站内消息，经消息中心（M10）展示，按 [来源接入要求（MSG-06）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-06)登记；必发，收件人不能关闭。本模块不发送邮件。

| 消息 | 端 | 所在功能 | 触发环节 | 谁收到 | 打开后去哪 |
| --- | --- | --- | --- | --- | --- |
| [确权申请已被债务人确认（M7b-NT01）](#M7b-NT01) | 企业端 | [确认申请（F-M7b-03）](./01-确权待办与确认处理-PRD.md#F-M7b-03) | 确认生效、申请变为“待运营审核” | 该申请的债权人企业 | 应收查看与确权申请（M7a）中这笔申请的详情 |
| [确权申请被债务人驳回（M7b-NT02）](#M7b-NT02) | 企业端 | [驳回申请（F-M7b-04）](./01-确权待办与确认处理-PRD.md#F-M7b-04) | 驳回生效、申请变为“债务人已驳回” | 该申请的债权人企业 | M7a 中这笔申请的详情 |
| [有新的确权申请待运营审核（M7b-NT03）](#M7b-NT03) | 运营端 | [确认申请（F-M7b-03）](./01-确权待办与确认处理-PRD.md#F-M7b-03) | 确认生效、申请变为“待运营审核” | 全体运营 | 运营审核与资产出库（M9）中这笔申请的审核详情 |

以下情况本模块不发消息：确认或驳回因不满足处理条件、提交失败、重复提交而未生效；用户取消确认或驳回；查看列表、详情；待办数量变化；申请到期关闭（由 M7a 发送“确权申请已到期关闭（M7a-NT02）”“待确认的确权申请已到期关闭（M7a-NT03）”）；运营审核结果与出库结果（由 M9 发送）。

债务人不会因本企业自己确认或驳回而收到消息。收到新申请的消息“收到新的确权申请（M7a-NT01）”由 M7a 发送，本模块不发同义消息；M9 不发送与“有新的确权申请待运营审核（M7b-NT03）”同义的消息。

<a id="M7b-NT01"></a>
## 确权申请已被债务人确认（M7b-NT01）

| 项目 | 规则 |
| --- | --- |
| 发送来源 | 确权待办与确认处理（M7b）；其他模块不发同义消息 |
| 端 | 企业端 |
| 分类 | 业务办理进度 / Business progress |
| 收件范围 | 本企业：该申请的债权人企业（发起企业）。不发给债务人企业 |
| 触发 | 债务人确认生效、申请状态由“待债务人确认”变为“待运营审核”时发送 |
| 不触发 | 确认未生效的任何情况（不满足处理条件、到期时点后提交、提交失败、重复提交、取消） |
| 同一事实的区分依据 | 债权人企业 + 申请编号 + “确权申请已被债务人确认”。一笔申请只会确认一次，只发一条；重复送达、重试、刷新不新增 |
| 发生时间 | 确认生效的时间（即处理时间） |
| 债权人企业尚无可查看消息的条件（账号停用、锁定等） | 消息照常生成并保留，按 M10 规则在可查看后展示 |
| 原业务识别信息 | 申请编号、发票号 |
| 打开后去哪 | 原业务：M7a 中该申请的详情（只能查看） |
| 查看与办理条件 | 查看：本企业是该申请的发起企业且当前拥有债权人角色，按 M7a 规则。没有办理动作 |
| 必须出现的业务值 | 债务人企业名称、发票号、应收账款编号、申请编号；写明本企业在这笔业务中是债权人、申请已进入运营审核 |
| 业务值取值 | 取确认生效时的值（企业名称、发票号、编号取当次依据），之后资料或申请状态变化不改写 |
| 不得出现 | 发票、合同等原件或下载地址；处理人姓名 |

文案（按收件人的界面语言展示中文或 English；花括号为业务值，企业名称、发票号按原值展示不翻译）：

| 语言 | 标题 | 正文 |
| --- | --- | --- |
| 中文 | 确权申请已被债务人确认 | {债务人企业名称} 已确认贵企业就发票 {发票号}（应收账款编号 {应收账款编号}）发起的确权申请 {申请编号}。贵企业在这笔业务中是债权人。申请已进入运营审核，审核通过前不能出库。 |
| English | Confirmation request confirmed by debtor | {debtor name} has confirmed confirmation request {request number} submitted by your company for invoice {invoice number} (receivable {receivable number}). Your company is the creditor in this transaction. The request is now awaiting operations review; the asset cannot be released before the review is approved. |

<a id="M7b-NT02"></a>
## 确权申请被债务人驳回（M7b-NT02）

| 项目 | 规则 |
| --- | --- |
| 发送来源 | 确权待办与确认处理（M7b）；其他模块不发同义消息 |
| 端 | 企业端 |
| 分类 | 业务办理进度 / Business progress |
| 收件范围 | 本企业：该申请的债权人企业（发起企业）。不发给债务人企业，不发运营 |
| 触发 | 债务人驳回生效、申请状态由“待债务人确认”变为“债务人已驳回”时发送 |
| 不触发 | 驳回未生效的任何情况（驳回原因不合格、不满足处理条件、到期时点后提交、提交失败、重复提交、取消） |
| 同一事实的区分依据 | 债权人企业 + 申请编号 + “确权申请被债务人驳回”。一笔申请只会驳回一次，只发一条。债权人重新发起后的新申请再被驳回，有新的申请编号，是新的事实，另发一条 |
| 发生时间 | 驳回生效的时间（即处理时间） |
| 债权人企业尚无可查看消息的条件（账号停用、锁定等） | 消息照常生成并保留，按 M10 规则在可查看后展示 |
| 原业务识别信息 | 申请编号、发票号 |
| 打开后去哪 | 原业务：M7a 中该申请的详情；本笔应收账款当前可申请时，债权人可在该详情中重新发起，规则按 M7a |
| 查看与办理条件 | 查看：本企业是该申请的发起企业且当前拥有债权人角色。重新发起的条件按 M7a 申请资格；不可申请时详情中展示原因 |
| 必须出现的业务值 | 债务人企业名称、发票号、应收账款编号、申请编号、驳回原因原文；写明本企业在这笔业务中是债权人 |
| 业务值取值 | 取驳回生效时的值，之后不改写；驳回原因按原文展示，不翻译 |
| 不得出现 | 发票、合同等原件或下载地址；处理人姓名 |

文案（按收件人的界面语言展示；花括号为业务值，企业名称、发票号、驳回原因按原值展示不翻译）：

| 语言 | 标题 | 正文 |
| --- | --- | --- |
| 中文 | 确权申请被债务人驳回 | {债务人企业名称} 驳回了贵企业就发票 {发票号}（应收账款编号 {应收账款编号}）发起的确权申请 {申请编号}。驳回原因：{驳回原因}。贵企业在这笔业务中是债权人。该应收账款满足申请条件时可以重新发起确权申请。 |
| English | Confirmation request rejected by debtor | {debtor name} has rejected confirmation request {request number} submitted by your company for invoice {invoice number} (receivable {receivable number}). Reason: {rejection reason}. Your company is the creditor in this transaction. You can submit a new confirmation request when the receivable meets the request conditions. |

<a id="M7b-NT03"></a>
## 有新的确权申请待运营审核（M7b-NT03）

| 项目 | 规则 |
| --- | --- |
| 发送来源 | 确权待办与确认处理（M7b）；M9 不发同义消息 |
| 端 | 运营端 |
| 分类 | 待处理事项 / Pending tasks |
| 收件范围 | 全体运营。不发给企业 |
| 触发 | 债务人确认生效、申请状态由“待债务人确认”变为“待运营审核”时发送 |
| 不触发 | 确认未生效的任何情况；驳回；申请到期关闭 |
| 同一事实的区分依据 | 全体运营 + 申请编号 + “有新的确权申请待运营审核”。一笔申请只发一条；同一应收账款重新发起后再次确认，有新的申请编号，另发一条 |
| 发生时间 | 确认生效的时间（即处理时间） |
| 原业务识别信息 | 申请编号、发票号 |
| 打开后去哪 | 原业务：M9 中该申请的审核详情 |
| 查看与办理条件 | 查看：可正常使用的运营管理员。办理：另需申请状态为“待运营审核”，具体由 M9 定义；已由其他运营管理员审核或已到期关闭时，前往后只能查看当前结果，按 M10 [前往原业务（MSG-05）](../../两端共用/M10-消息中心/01-消息中心-PRD.md#MSG-05)处理 |
| 必须出现的业务值 | 申请编号、发票号、应收账款编号、债权人企业名称、债务人企业名称、应收账款金额及币种、应收账款到期日及时区 |
| 业务值取值 | 取确认生效时的值（应收账款相关值取当次依据），之后不改写 |
| 不得出现 | 发票、合同等原件或下载地址 |

文案（按收件人的界面语言展示；花括号为业务值，企业名称、发票号按原值展示不翻译；到期日按 ERP 原值展示并带时区）：

| 语言 | 标题 | 正文 |
| --- | --- | --- |
| 中文 | 有新的确权申请待运营审核 | 债务人 {债务人企业名称} 已确认债权人 {债权人企业名称} 就发票 {发票号}（应收账款编号 {应收账款编号}，金额 {应收账款金额} {币种}，到期日 {应收账款到期日}）发起的确权申请 {申请编号}，请进行运营审核。应收账款到期时仍未审核通过的申请将自动关闭。 |
| English | New confirmation request awaiting review | Debtor {debtor name} has confirmed confirmation request {request number} submitted by creditor {creditor name} for invoice {invoice number} (receivable {receivable number}, amount {amount} {currency}, due date {due date}). Please review it. Requests not approved by the receivable's due date will be closed automatically. |
