# 确权待办与确认处理 · 验收

2026-11-12｜需求评审稿｜供测试使用

本册只写验收标准，测试用例与执行步骤由测试小队编写。规则见[功能册](./01-确权待办与确认处理-PRD.md)，消息见[消息通知册](./03-确权待办与确认处理-消息通知.md)，各节顺序与功能册一致；原型画面用于核对布局，不作为验收依据。

怎么读：

- 共 25 条验收，编号连续。
- 一条验收写了多个场景时，全部场景都满足才算通过。
- 申请的生成、到期关闭由 M7a 提供，运营审核通过由 M9 提供；相关模块未交付前可用模拟结果验证本模块的展示与处理。
- 写明“待验，不判通过”的场景依赖尚未闭合的事项，闭合前不判定通过。

## 0. 验收前准备

账号：

- 平台企业 N：只有债务人角色，已完成首次入驻，是 H、H2 若干发票的买方（演示值可用 Carloha Nigeria）。N 用户在 M1 中设置时区为 Africa/Lagos，另准备一个未设置时区的情况。
- 平台企业 H：只有债权人角色，已完成首次入驻，是 N 若干发票的卖方（演示值可用 Carloha Holding）。
- 平台企业 H2：拥有债权人角色，是 N 另一些发票的卖方。
- 平台企业 D：同时拥有债权人、债务人角色，已完成首次入驻；既以卖方身份向 N 发起过申请，也以买方身份收到 H 发起的申请。
- 平台企业 X：只有债务人角色，与 N 的申请无关。
- 平台企业 N4：拥有债务人角色、尚未完成首次入驻，是 H 某张发票的买方，已收到申请。
- 运营管理员甲、乙：均可正常使用。

数据（均为发给 N 的申请，另注明者除外）：

- 状态变体：“待债务人确认”多笔；“待运营审核”“运营审核通过”“债务人已驳回”“已关闭（关闭前为待债务人确认）”“已关闭（关闭前为待运营审核）”各至少一笔。
- 驳回后重新发起：一笔“债务人已驳回”的申请，债权人已对同一应收账款重新发起新申请。
- 到期边界：一笔“待债务人确认”的申请，其应收账款到期日为今天（ERP 时区）；可调整系统时间或使用临近到期的样本跨过到期时点。
- 资料变化：一笔“待债务人确认”的申请，提交后 M3 核心资料变为“差异待核实”；一笔提交后合同在 ERP 中更新；一笔提交后回款变为“已收清”。
- 资料缺失：一笔申请的当次依据中合同未取得、发票附件未取得、某车型未提供。
- 数量：N 的待处理申请多于一页；至少两种币种；来自 H、H2 两个债权人。
- 一个提交时会模拟系统失败的样本，以及一个网络中断、结果未确认的样本。
