# 企业登录与首次入驻 · 功能与业务规则

2026-11-12｜企业端：企业用户（债权人、债务人或两者兼有）｜需求评审稿

本模块共四册：本册写功能、业务规则、字段规则与交互逻辑；[流程图与状态机](./02-企业登录与首次入驻-流程图与状态机.md)画出主要流程与状态；[消息通知](./03-企业登录与首次入驻-消息通知.md)写明本模块发出的两类邮件；[验收](./04-企业登录与首次入驻-验收.md)供测试使用。

本册只定义信息需求与业务行为，页面布局、组件形态与交互承载由 Hallmark 设计决定。

## 1. 模块是什么

每个企业只有一个企业用户，账号由平台运营在企业邀请时分配（见“运营登录、企业邀请与企业管理（M2）”）。企业用户用登录邮箱和初始密码首次登录，设置新密码后直接进入平台，在平台内依次完成两步入驻准备：绑定钱包、完善资料（个人信息、企业信息与组织资料）。两步都完成后，平台按运营分配的业务角色开放债权人或债务人业务；之后企业用户可以查看本人账户信息、维护允许修改的资料、修改密码和自助找回密码。

基本原则：

- 账号不自助开通：本平台没有注册入口，登录邮箱、初始密码、企业身份和业务角色都来自运营邀请；一个企业只有一个企业用户，角色可同时有债权人和债务人，由同一个用户使用。
- 入驻准备是开放业务的前提，但不能把用户挡在准备步骤之外：入驻未完成时，用户随时可以登录进入平台并继续当前步骤；菜单可见但锁定，只有入驻步骤可以办理。
- 钱包一经绑定不可更换、不可解绑；它是本企业在平台使用的唯一钱包地址。密码找回、运营重置密码、账号停用与启用都不会新建用户、解除或更换钱包。
- 资料提交后直接生效，不设资料审批；企业身份、业务角色、登录邮箱和钱包地址不能由企业用户自行修改。
- 隐藏入口不是唯一防线：未开放的功能直接访问同样被拒绝，不返回业务数据。

**一个完整的例子。** 运营邀请 Nigeria 公司，为其唯一企业用户分配登录邮箱 ops@ng.example 和初始密码，并分配债务人角色。该用户用这组邮箱和密码登录，先设置新密码；设置成功后直接进入平台，导航中的“确权申请”和“账户信息”带锁、不能点击，页面上是入驻准备的第一步“绑定钱包”。用户填写自己的 Ethereum 钱包地址，同一页面提示“绑定后不可更换或解绑”；随后连接钱包，钱包当前地址与填写的地址一致，签名一次，地址绑定成功。第二步填写本人姓名和与企业的关系，核对运营登记的企业名称与登记标识，补充注册地址，上传公司注册证书和授权书两份组织资料并提交。提交成功即完成入驻，菜单解锁，可以办理债务人的“确权申请”业务；用户之后可在账户信息中查看已绑定的钱包，并修改注册地址。退出后回到登录入口。

### 1.1 需求清单

| 功能 | 谁 | 想做什么 | 为了什么 |
| --- | --- | --- | --- |
| [邮箱与密码登录（M1-F01）](#M1-F01) | 已获邀请的企业用户 | 用登录邮箱和密码登录，并被带到当前该做的事 | 进入平台继续入驻或办理业务 |
| [首次登录强制改密（M1-F02）](#M1-F02) | 持初始密码的企业用户 | 首次登录或运营重置后先换掉初始密码，设置成功即进入平台 | 初始密码经过他人之手，降低泄露风险 |
| [自助找回密码（M1-F03）](#M1-F03) | 忘记密码或没收到初始密码的企业用户 | 用登录邮箱接收验证码、设置新密码，成功即进入平台 | 本人恢复登录，不必等运营重置 |
| [连续失败与临时锁定（M1-F04）](#M1-F04) | 企业用户 | 密码多次输错后账号被临时锁定 | 防止密码被猜中 |
| [入驻准备与进度（M1-F05）](#M1-F05) | 尚未完成入驻的企业用户 | 进入平台后知道还差哪一步，并随时回到当前步骤 | 完成入驻后办理业务 |
| [绑定钱包并验证控制权（M1-F06）](#M1-F06) | 已设置密码、尚未绑定钱包的企业用户 | 绑定本企业使用的钱包地址 | 平台确认该地址由本人控制，并作为本企业的唯一钱包 |
| [完善并提交个人与企业信息（M1-F07）](#M1-F07) | 已绑定钱包、尚未提交资料的企业用户 | 填写本人资料、核对并补充企业资料、上传组织资料后提交 | 完成入驻，开放角色业务 |
| [角色业务入口与无权访问（M1-F08）](#M1-F08) | 已完成入驻的企业用户 | 按本企业的业务角色看到可用的业务 | 债权人、债务人各办各的业务 |
| [账户信息查看与维护（M1-F09）](#M1-F09) | 已完成入驻的企业用户 | 查看账号、钱包、个人与企业信息和组织资料，修改允许维护的资料 | 资料随业务保持准确 |
| [修改密码（M1-F10）](#M1-F10) | 已完成入驻的企业用户 | 修改本人密码 | 定期更换或怀疑泄露时更换 |
| [登录有效期、无操作登出与退出（M1-F11）](#M1-F11) | 已登录的企业用户 | 离开后登录自动结束，也能主动退出 | 防止他人在无人看管的电脑上操作 |
| [界面语言与时区（M1-F12）](#M1-F12) | 所有企业端访问者（时区只限已登录的本人） | 在简体中文和 English 之间切换，按本人时区看时间 | 用熟悉的语言和时间办理业务 |

### 1.2 本期不做

- 企业或用户自助注册、一个企业多个用户、新增企业用户。
- 资料审批或实名认证审核：平台不审核个人信息、企业信息和组织资料的内容。
- 上传个人证件影像：组织资料只用于企业层面的证明文件。
- 本人修改登录邮箱：登录邮箱由运营分配和维护。
- 更换、解绑或新增钱包地址，以及运营代为改址，包括误绑或失去钱包控制权的情况；旧的钱包变更申请与改址审核流程不恢复。
- 展示、带入或使用运营在企业邀请时登记的联系信息（联系人、联系电话、联系邮箱）：这些信息只供运营线下联系企业，与企业端无关。
- 修改企业名称、注册国家／地区、企业登记标识或业务角色：这些由运营在企业管理中维护。
- 验证码登录、动态口令、钱包登录、第三方登录和“记住我”；验证码只用于自助找回密码。
- 站内消息：本模块只发邮件，见[消息通知](./03-企业登录与首次入驻-消息通知.md)。
- 采集下游采购商或其他交易对象的个人信息；本模块的“个人信息”只指企业用户本人。
- 企业邀请、角色分配、账号启停、运营重置密码与解锁的操作本身：由运营登录、企业邀请与企业管理（M2）定义，本册只定义这些操作对企业用户登录与入驻的结果，见[运营操作对账号的影响](#operator-actions)。
- 债权人、债务人业务菜单内的列表、详情和操作：由应收查看与确权申请（M7a）、确权待办与确认处理（M7b）定义。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 企业用户 | 企业在本平台唯一的用户，由运营邀请时建立；本册所称“用户”“本人”均指他 |
| 业务角色 | 运营为企业分配的债权人、债务人角色，可只有一个，也可两个都有；由同一个企业用户使用 |
| 登录邮箱 | 企业用户登录本平台使用的邮箱，由运营分配 |
| 运营登记的联系信息 | 运营在企业邀请时登记的联系人、联系电话、联系邮箱，只供运营线下联系企业；企业端任何位置都不展示、不带入、不使用，联系邮箱不能用于登录或找回密码 |
| 初始密码 | 不是企业用户本人设置的密码：运营邀请时分配的密码，以及运营重置密码后的新密码。只能用来完成首次登录强制改密 |
| 入驻准备 | 设置新密码进入平台后，在平台内依次完成的两步：绑定钱包、完善资料。首次登录强制改密在进入平台前完成，不属于入驻准备的步骤 |
| 组织资料 | 企业用户在完善资料时上传的企业层面证明文件，如注册证书或营业执照、公司章程、授权本人代表企业办理业务的授权书；平台不区分文件类别、不审核内容 |
| 完成入驻 | 钱包已绑定且个人与企业信息已提交。完成后不会因找回密码、运营重置密码或账号停用而回退 |
| 钱包控制权验证 | 用户用要绑定的钱包地址签署一条说明用途的消息，证明本人控制该地址。不是交易，不消耗 gas，不转移或授权任何资产 |
| 原目标 | 未登录时想打开的企业端页面，例如从邮件或收藏打开的某个业务页面 |

<a id="address-display"></a>
**钱包地址与网络名称的展示**（本模块各处共用）：

- 已绑定或已连接的钱包地址在页面上缩写展示，保留大小写；本人可以核对完整地址，复制得到的是完整地址。缩写的具体位数由设计确定。
- 绑定钱包时，用户填写的地址完整显示，便于本人逐位核对。
- 网络名称在中英文界面都写作 Ethereum，不译为“以太坊”，也不写作 ETH。

<a id="account-states"></a>
## 3. 账号与入驻状态

企业用户的账号有五个互相独立的维度，一个维度只表达一件事：

| 维度 | 取值 | 谁改变它 |
| --- | --- | --- |
| 账号启停 | 启用、停用；邀请时为启用 | 运营在企业管理（M2）中停用或启用 |
| 密码状态 | 待首登改密、已设置；邀请时为待首登改密 | 首次登录强制改密或自助找回成功后为已设置；运营重置密码后回到待首登改密 |
| 临时锁定 | 未锁定、锁定中（到某一时刻） | 连续输错密码进入锁定；到期自动解除，或运营在 M2 中解锁 |
| 钱包绑定 | 未绑定、已绑定；邀请时为未绑定 | 本人[绑定钱包并验证控制权（M1-F06）](#M1-F06)后为已绑定，之后不再改变 |
| 资料提交 | 未提交、已提交；邀请时为未提交 | 本人首次[提交个人与企业信息（M1-F07）](#M1-F07)后为已提交，之后不再改变 |

入驻进度由钱包绑定和资料提交两项得出，供本人和运营查看：

| 入驻进度 | 条件 |
| --- | --- |
| 待绑定钱包 | 钱包未绑定 |
| 待完善资料 | 钱包已绑定，资料未提交 |
| 已完成入驻 | 钱包已绑定，资料已提交 |

- 首次登录强制改密不属于入驻准备，不计入入驻进度，它在运营重置密码后会再次出现；密码状态为待首登改密时，不能进入平台。
- 入驻进度只能前进，不会回退。

<a id="login-combination"></a>
邮箱和密码都正确时，各维度组合下用户看到的结果（自上而下，命中第一行即止）：

| 账号启停 | 临时锁定 | 密码状态 | 入驻进度 | 登录结果 |
| --- | --- | --- | --- | --- |
| 停用 | 任意 | 任意 | 任意 | 不能登录；说明账号已停用，请联系平台运营 |
| 启用 | 锁定中 | 任意 | 任意 | 不能登录；说明账号已临时锁定和剩余时间，见[连续失败与临时锁定（M1-F04）](#M1-F04) |
| 启用 | 未锁定 | 待首登改密 | 任意 | 进入[首次登录强制改密（M1-F02）](#M1-F02)，设置成功前不进入平台 |
| 启用 | 未锁定 | 已设置 | 待绑定钱包 | 登录成功，进入平台，当前入驻步骤为[绑定钱包并验证控制权（M1-F06）](#M1-F06)，菜单锁定 |
| 启用 | 未锁定 | 已设置 | 待完善资料 | 登录成功，进入平台，当前入驻步骤为[完善并提交个人与企业信息（M1-F07）](#M1-F07)，菜单锁定 |
| 启用 | 未锁定 | 已设置 | 已完成入驻 | 登录成功，按[登录后去向](#login-destination)进入原目标或默认页面 |

状态变化见[企业用户账号状态机](./02-企业登录与首次入驻-流程图与状态机.md#state-1)与[入驻进度状态机](./02-企业登录与首次入驻-流程图与状态机.md#state-2)。

<a id="operator-actions"></a>
### 3.1 运营操作对账号的影响

运营在企业管理（M2）中对企业用户只有以下四类操作；操作入口、确认和操作记录由 M2 定义，对企业用户的结果以本节为准：

| 运营操作 | 对企业用户的结果 |
| --- | --- |
| 停用 | 该账号在所有设备和标签页上的登录立即结束；之后输入正确邮箱和密码时说明账号已停用，请联系平台运营；自助找回在验证码验证通过后说明账号已停用，不能重置。密码、锁定计时、钱包、资料和入驻进度不变 |
| 启用 | 账号恢复为停用前的密码状态和入驻进度；停用期间锁定已到期的不再锁定。不新建用户，不需要重新绑定钱包或重新提交资料 |
| 重置密码 | 运营重置后的新密码是初始密码，由 M2 交付给企业用户；平台不发送[密码变更通知（M1-NT02）](./03-企业登录与首次入驻-消息通知.md#M1-NT02)。旧密码与此前的初始密码立即作废，未用验证码作废，所有登录立即结束，账号回到待首登改密；钱包、资料、入驻进度、业务角色不变，不新建用户。锁定中的账号不因重置而解除锁定 |
| 解锁 | 立即解除临时锁定，连续失败次数清零；锁定级别保留，之后再次连续输错 5 次按下一级时长锁定 |

- 运营修改企业身份信息或业务角色时，企业用户在下一次请求时看到新内容；角色变化的影响见[角色业务入口与无权访问（M1-F08）](#M1-F08)。
- 运营不能为企业用户设置密码以外的登录凭据，不能修改或解除已绑定的钱包，也不能新建第二个企业用户。

验收参见：[账号状态与运营操作](./04-企业登录与首次入驻-验收.md#ac-operator)。

<a id="password-rules"></a>
### 3.2 设置密码的共同规则

适用于[首次登录强制改密（M1-F02）](#M1-F02)、[自助找回密码（M1-F03）](#M1-F03)、[修改密码（M1-F10）](#M1-F10)。运营分配或重置的初始密码同样须满足长度、组成和空格规则。

| 规则 | 要求 |
| --- | --- |
| 长度 | 8～20 个字符 |
| 组成 | 至少包含 1 个英文字母和 1 个数字 |
| 空格 | 前后的空格自动去除；中间不能有空格 |
| 与当前密码 | 本人设置新密码时，不能与当前密码相同 |
| 与初始密码 | 本人设置新密码时，不能与最近一次分配或重置的初始密码相同 |
| 两次输入 | 须输入两次且一致；不一致时在第二次输入处说明并不能提交，改为一致后提示消失 |

- 输入过程中实时说明各项规则是否满足，全部满足才能提交；不展示密码强弱分档。
- 所有密码输入都可以由本人切换显示或隐藏。
- 提交时由平台再次校验，不满足时不改变原密码，并说明哪一项不满足。
- 除本人在输入时主动切换显示外，界面、邮件和日志中都不出现明文密码。

<a id="security-records"></a>
### 3.3 安全记录

- 以下事件须留存记录，可追溯到账号、时间与结果：登录成功与失败（含失败原因）、账号锁定与解除（含运营解锁）、密码变更（首次登录强制改密、自助找回重置、本人修改密码、运营重置密码）、账号停用与启用、钱包绑定（含绑定地址与失败原因）、个人与企业信息的提交与每次修改（含修改前后的值）、组织资料的每次上传与移除（含文件名）、越权访问被拒绝。
- 安全记录长期保留，不自动删除。
- 记录中不出现密码、验证码明文或签名原文。
- 企业用户在本模块中不能查询安全记录；运营端的操作追溯入口由对应运营端模块定义。

## 4. 登录与密码

<a id="M1-F01"></a>
### 4.1 邮箱与密码登录（M1-F01）

适用角色与前提：已获运营邀请的企业用户；未登录。

- 企业端只有一个登录入口；登录需要输入登录邮箱和密码。邮箱前后的空格自动去除，不区分大小写。
- 登录入口提供[忘记密码（M1-F03）](#M1-F03)和界面语言切换；没有注册入口、验证码登录、钱包登录或“记住我”。
- 未登录时访问企业端受保护页面，都先到登录入口，并记住原目标，见[登录后去向](#login-destination)。

登录结果：

| 情况 | 用户看到的结果 |
| --- | --- |
| 邮箱或密码为空 | 不能提交，指出未填写的一项 |
| 邮箱不是企业用户的登录邮箱，或密码错误 | 统一说明“邮箱或密码错误”；两种情况的提示、表现和响应快慢都不能区分。账号未锁定时，密码错误计入连续失败次数，见[连续失败与临时锁定（M1-F04）](#M1-F04) |
| 邮箱和密码正确 | 按[各维度组合下的登录结果](#login-combination)处理；停用、锁定的提示只在邮箱和密码都正确时出现 |
| 网络或服务异常 | 说明暂时无法登录、请重试；已输入的邮箱保留，不计入失败次数 |

- 登录提交期间不能重复提交。
- 首次登录成功时，按浏览器推断写入时区偏好，见[界面语言与时区（M1-F12）](#M1-F12)。
- 同一账号可以在多个设备上同时登录。

<a id="login-destination"></a>
登录后去向：

- 入驻未完成时，进入平台内的当前入驻步骤；原目标不保留。
- 已完成入驻且有原目标时，回到原目标前按当前业务角色和数据范围重新判断，无权访问时按[无权访问的处理](#no-access)；不能把登录成功当作有权。
- 没有原目标或原目标不在企业端范围内时，进入默认页面（具体页面由设计确定，须是本人可用的页面）。
- 原目标只在发起登录的同一个浏览器标签页内保留，包括中途完成首次登录强制改密或自助找回密码后直接登录的情况；刷新页面或在新标签页登录后进入默认页面。

流程参见：[登录与入驻去向（图 1）](./02-企业登录与首次入驻-流程图与状态机.md#fig-1)。
验收参见：[邮箱与密码登录](./04-企业登录与首次入驻-验收.md#ac-login)。

<a id="M1-F02"></a>
### 4.2 首次登录强制改密（M1-F02）

适用角色与前提：邮箱和密码正确、账号启用且未锁定、密码状态为待首登改密的企业用户。包括新邀请的账号和运营重置密码后的账号。

- 用初始密码登录时必须先设置新密码，不能跳过或稍后再改。已通过[自助找回密码（M1-F03）](#M1-F03)设置过密码的账号不再进入本流程。
- 改密在进入平台前完成。改密前只能做三件事：设置新密码、切换界面语言、退出登录。平台内的入驻步骤、账户信息和业务都不可用，绕过界面直接访问同样被拒绝。
- 只需输入两次新密码，不需要再输入初始密码；新密码须符合[设置密码的共同规则](#password-rules)。
- 设置成功即登录成功，不需要再输入邮箱和密码：密码状态变为已设置，初始密码失效；平台向登录邮箱发送[密码变更通知（M1-NT02）](./03-企业登录与首次入驻-消息通知.md#M1-NT02)；该账号在其他设备和标签页上的登录立即结束；当前页面直接进入平台，按[各维度组合下的登录结果](#login-combination)进入：入驻未完成时进入当前入驻步骤，运营重置后的账号如果早已完成入驻，按[登录后去向](#login-destination)进入。登录有效期自设置成功起计算。
- 设置失败时（规则不满足、网络或服务异常）仍为待首登改密，初始密码仍可使用，可以重试；不发送密码变更通知。
- 改密期间登录到期、无操作登出、被停用或被运营再次重置时，回到登录入口，修改不生效。

流程参见：[登录与入驻去向（图 1）](./02-企业登录与首次入驻-流程图与状态机.md#fig-1)。
验收参见：[首次登录强制改密](./04-企业登录与首次入驻-验收.md#ac-first-password)。

<a id="M1-F03"></a>
### 4.3 自助找回密码（M1-F03）

适用角色与前提：已获邀请的企业用户本人，从登录入口选择忘记密码；无论密码状态为待首登改密还是已设置，也无论入驻是否完成，均可发起。

- 输入登录邮箱（去首尾空格、不区分大小写、邮箱格式、最长 254 个字符）后获取验证码。每次获取、重发都须先通过[发码前人机校验](#captcha)，再满足[验证码参数](#code-params)中的重发间隔与发送限额。
- 只向该企业用户的登录邮箱发送[找回密码验证码（M1-NT01）](./03-企业登录与首次入驻-消息通知.md#M1-NT01)，不向运营登记的联系邮箱发码。
- 输入的邮箱不是任何企业用户的登录邮箱时，使用与有效邮箱相同的中性反馈，不透露邮箱是否存在；真实发送失败时说明暂不能发送、可重试，不虚报已发送。
- 输入收到的验证码，通过后输入两次新密码，遵守[设置密码的共同规则](#password-rules)；不显示或回填原密码。
- 验证码通过后取得的本次找回资格自通过起 10 分钟内有效；超过 10 分钟仍未提交成功的不能提交，原密码不变，须重新获取并验证验证码。
- 验证码错误、过期、已使用、已作废时不能继续，说明验证码无效，可重试或重新获取，见[验证码的共同规则](#verification-rules)。
- 验证码正确后才检查账号：停用时说明账号已停用、不能重置，请联系平台运营；锁定中时告知剩余时间、本次不能重置，不提前解锁。两种情况都不修改密码。
- 提交时重新检查账号状态与本次找回资格；期间账号被停用、被运营重置密码或密码已被其他流程修改的，本次找回资格失效，须重新开始，不覆盖已发生的变更。
- 成功即登录成功，不需要再输入邮箱和密码：新密码生效，旧密码与初始密码失效，密码状态为已设置（原为待首登改密的账号视为已通过邮箱验证完成首次密码设置，之后不再进入首次登录强制改密）；平台发送[密码变更通知（M1-NT02）](./03-企业登录与首次入驻-消息通知.md#M1-NT02)；该账号已有的其他登录与未用验证码立即结束；当前页面直接进入平台，按[各维度组合下的登录结果](#login-combination)进入。登录有效期自找回成功起计算。
- 找回只改变密码：钱包、资料、入驻进度和业务角色不变，不新建用户，也不能借此跳过入驻准备。
- 取消、离开、校验失败或保存失败时密码不变，不结束已有登录，不发送密码变更通知。

<a id="verification-rules"></a>
#### 验证码的共同规则

- 验证码只能用于本账号本次找回；同一账号仅最新成功发送的验证码有效，重新发送成功使旧码作废。
- 使用成功、过期或累计输错达到上限后不能再次使用。密码变更成功（含运营重置）使该账号未用验证码全部作废。
- 提交期间不能重复提交，同一次找回资格最多成功提交一次。
- 码值只出现在本人登录邮箱中，不出现在页面提示或日志中；验证码有效不等于已登录。

<a id="code-params"></a>
**验证码参数**

| 项目 | 要求 |
| --- | --- |
| 位数与输入 | 6 位数字；只接受数字，粘贴时自动去除空格和连字符 |
| 有效期 | 自发送成功起 10 分钟 |
| 单个验证码错误上限 | 同一个验证码累计输错 5 次即作废，之后即使输入正确也不能使用 |
| 重发间隔 | 同一邮箱两次发送至少间隔 60 秒 |
| 同一邮箱发送限额 | 24 小时内最多 10 次 |
| 同一网络地址（IP）发送限额 | 每小时最多 20 次 |

- 间隔未满时不能获取或重发，并显示剩余秒数；刷新页面不会重置等待时间，剩余时间以平台为准。
- 同一邮箱 24 小时额度用完时说明大约还需等待多久；同一网络地址额度用完时说明稍后再试。
- 邮件真实发送失败时，可立即重试 1 次，这次重试不计入发送额度，也不受重发间隔限制，但仍须重新通过人机校验。
- 以上等待与超限提示对任何邮箱都相同，不因邮箱是否属于企业用户而不同。
- 验证码输错只计入该验证码自己的错误次数，不计入密码连续失败次数。

<a id="captcha"></a>
#### 发码前人机校验

人机校验指滑块拼图一类的校验机制，具体呈现由设计确定。

- 邮箱格式校验通过后发起获取或重发，才进入人机校验；之前通过过、属于发送失败重试，都不能跳过。

| 情况 | 用户看到的结果 |
| --- | --- |
| 人机校验通过 | 说明验证通过；随后检查重发间隔与发送限额，通过后才发码。通过不等于验证码已发出 |
| 单次未通过 | 说明验证失败并自动更换题目，可以立即再试；不发码 |
| 连续未通过 3 次 | 除自动更换外，还可以主动更换题目；不发码 |
| 连续未通过 5 次 | 进入 60 秒冷却，期间不能发起校验并显示剩余时间；刷新或重新发起都不能绕过；不发码 |
| 关闭或取消 | 不发码，回到原流程，已填写的邮箱保留 |
| 题目加载失败 | 说明加载失败、可以重试；不发码，已填写内容保留 |

- 一次通过只用于随后一次发送，且须是同一目标邮箱、同一请求来源，2 分钟内有效；绕过界面直接请求发码同样须满足。
- 人机校验的失败与冷却不计入密码连续失败次数或验证码错误次数；其结果与提示对任何邮箱都相同。

流程参见：[自助找回密码（图 2）](./02-企业登录与首次入驻-流程图与状态机.md#fig-2)。
验收参见：[自助找回密码](./04-企业登录与首次入驻-验收.md#ac-recover)。

<a id="M1-F04"></a>
### 4.4 连续失败与临时锁定（M1-F04）

适用角色与前提：所有企业用户账号。

- 登录时输错密码、修改密码时输错当前密码，共用同一个连续失败次数。
- 连续失败达到 3 次起，每次提示还剩几次机会。
- 连续失败达到 5 次，账号临时锁定。锁定时长逐级加长：第一次 15 分钟，第二次 30 分钟，之后每次 60 分钟；第一次锁定时提示“如再次触发，锁定时间会更长”。
- 登录成功后（包括设置新密码或找回成功后直接登录），连续失败次数清零，锁定时长回到第一级。锁定到期自动解除时，连续失败次数清零，锁定级别保留。运营解锁的结果见[运营操作对账号的影响](#operator-actions)。
- 锁定时，该账号在所有设备和标签页上的登录立即结束，包括由他人在其他设备输错密码触发的锁定。
- 锁定期间不能登录；这期间的密码错误不计入连续失败次数，也不延长锁定。本人找回密码、运营重置密码都不提前解除锁定。
- 锁定提示只在输入正确邮箱和密码后，或在找回中正确验证验证码后出现。
- 钱包签名失败、验证码输错、人机校验失败都不计入连续失败次数。
- 锁定与解除不发通知。

验收参见：[连续失败与临时锁定](./04-企业登录与首次入驻-验收.md#ac-lock)。

## 5. 首次入驻

<a id="M1-F05"></a>
### 5.1 入驻准备与进度（M1-F05）

适用角色与前提：账号启用、未锁定、密码状态为已设置、入驻进度为待绑定钱包或待完善资料、已进入平台的企业用户。

- 入驻准备在平台内进行，共两步，按固定顺序：绑定钱包 → 完善资料。前一步未完成时不能进入后一步；已完成的步骤可以查看结果，不能重做。
- 入驻期间始终展示两步的完成情况和当前所在步骤；不把修改初始密码列为入驻步骤。
- 入驻期间平台导航中的菜单全部可见但锁定：菜单范围与完成入驻后本人可用的菜单相同，即按本企业业务角色可用的业务入口，以及账户信息（见[角色业务入口与无权访问（M1-F08）](#M1-F08)）。每个菜单带锁形标记（与代币发行平台相同），点击不进入、不返回任何内容，并说明完成入驻后可用。
- 入驻期间可以使用：当前入驻步骤、已完成步骤的结果、界面语言切换、退出登录。消息入口是否展示由消息中心（M10）定义。
- 入驻期间访问业务页面或账户信息（包括改写链接直接访问），回到当前入驻步骤，不返回任何业务数据。
- 入驻进度保存在平台：中途退出、登录到期或换设备登录后，从当前步骤继续；已绑定的钱包和已提交的资料不丢失。
- 资料提交成功即完成入驻，菜单立即解锁，平台开放角色业务；不设资料审批。

流程参见：[登录与入驻去向（图 1）](./02-企业登录与首次入驻-流程图与状态机.md#fig-1)、[入驻进度状态机](./02-企业登录与首次入驻-流程图与状态机.md#state-2)。
验收参见：[入驻准备与进度](./04-企业登录与首次入驻-验收.md#ac-onboarding)。

<a id="M1-F06"></a>
### 5.2 绑定钱包并验证控制权（M1-F06）

适用角色与前提：账号启用、未锁定、密码状态为已设置、钱包未绑定、已进入平台的企业用户本人。

- 钱包地址对应本企业：企业只有一个用户，该用户绑定的地址就是本企业在平台使用的钱包地址，不另设企业接收钱包或从多个地址中选择。
- 只支持 Ethereum 网络的地址；支持哪些钱包由研发对接钱包服务商时确定。
- 绑定依次经过以下步骤：

| 步骤 | 用户可见结果 |
| --- | --- |
| 1. 填写钱包地址 | 用户填写要绑定的 Ethereum 地址，填写内容完整显示。本步骤明确提示：绑定后不可更换或解绑，该地址将作为本企业在平台使用的唯一钱包地址；下一步需要连接该地址的钱包并签名一次，不涉及转账或资金授权。地址通过格式与可用性检查后才能进入下一步 |
| 2. 连接钱包 | 用户连接钱包；钱包须处于 Ethereum 网络，且钱包当前地址须与填写的地址一致。只连接成功不算绑定 |
| 3. 签名确认 | 用户在钱包中签名，平台按[钱包签名规则](#signature-rules)校验 |
| 4. 绑定成功 | 填写的地址绑定到本企业用户，记录绑定时间；入驻进度变为待完善资料，进入[完善并提交个人与企业信息（M1-F07）](#M1-F07) |

| 业务信息 | 含义/类型 | 必填条件/默认值 | 可编辑范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 钱包地址 | 要绑定的 Ethereum 地址；文本 | 必填；无默认值 | 签名确认前可以修改；修改后须重新连接钱包和签名；绑定成功后不可修改 | 去除首尾空格；须为 0x 开头加 40 位十六进制字符的 Ethereum 地址，大小写混写时须符合 Ethereum 地址的校验规则；不合规时不能继续并指出格式错误。地址已被其他企业用户绑定时不能继续，说明“该地址不能绑定，请更换钱包地址”，不透露它属于哪个企业 |

- 签名确认前可以修改地址或放弃本次绑定；签名验证通过后立即生效，此后不能更换或解绑。
- 同一地址在全平台只能绑定给一个企业用户（含已停用的账号）；同一地址的不同大小写写法视为同一地址。填写时检查一次，签名通过后、生效前再检查一次，防止同时绑定。
- 同一用户在两个设备上同时绑定时只有一次成功；另一设备提交时说明钱包已绑定，并展示已绑定的地址。
- 签名失败不累计锁定次数，也不锁定账户；同一网络地址 1 小时内签名验证失败超过 20 次后降速，不封禁。

<a id="signature-rules"></a>
钱包签名规则：

- 钱包内的签名消息须声明用途：只用于证明本人控制该钱包、用于绑定本平台企业账号，不发起交易、不消耗 gas，也不转移或授权任何资产；签名消息中包含要绑定的完整地址。
- 每个签名请求只能成功使用一次，自签发起 5 分钟内有效（按平台时间，到达 5 分钟整即失效）；已使用或已过期的签名被拒绝，平台准备新的签名请求，由用户重新签名。页面不得早于 5 分钟自行判定超时。
- 签名地址必须与用户填写的地址一致，签名使用的网络必须是 Ethereum；由平台校验，不能只靠界面限制。

绑定过程中的异常：

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 填写的地址格式不正确，或已被其他企业用户绑定 | 按上表说明，不能继续；可修改地址 |
| 没有可用钱包，或钱包无法唤起 | 说明原因，提示安装或启用钱包后重试；仍为未绑定，填写的地址保留 |
| 用户取消连接，或钱包处于锁定状态 | 说明原因（钱包已锁定时提示先解锁），可重新连接；填写的地址保留 |
| 钱包当前不在 Ethereum 网络 | 提示在钱包中切换到 Ethereum 网络后重试；不绑定 |
| 钱包当前地址与填写的地址不一致 | 说明两者不一致并同时展示两个地址，提示在钱包中切换到填写的地址，或返回修改填写的地址；不静默改用钱包地址 |
| 连接后、签名前或签名中，钱包切换了地址 | 中止本次签名并说明钱包地址已变化，按上一行重新核对；新地址不能沿用原地址的签名 |
| 用户拒绝签名、验签失败，或签名地址与填写的地址不一致 | 不绑定，说明未完成验证，可重试 |
| 签名请求已过期或已被使用 | 不绑定，平台准备新的签名请求，提示重新签名 |
| 网络或服务异常 | 说明暂时无法完成绑定、请重试；不能显示为已绑定 |
| 绑定期间登录结束（到期、无操作、退出、锁定、停用、运营重置密码） | 本次绑定不生效，重新登录后从填写钱包地址重新开始 |

### 5.3 完善并提交个人与企业信息（M1-F07）

适用角色与前提：账号启用、未锁定、密码状态为已设置、钱包已绑定、资料未提交的企业用户本人。

- 一次填写个人信息、企业信息并上传组织资料后一起提交；全部通过校验才能提交。
- 企业信息分两类：运营邀请时登记的企业身份信息只读展示，供本人核对；企业补充信息由本人填写，初始为空。
- 运营登记的联系信息不在本流程展示或带入，企业用户也不填写联系人、联系电话或联系邮箱。
- 只读的企业身份信息有误时，本人不能自行修改，说明“如有错误请联系平台运营更正”；运营更正后，本人在下一次读取时看到新值。错误不阻止本人提交其他信息。
- 提交前离开或登录结束时，未提交的内容（包括已上传但未提交的组织资料）不保留，离开前提示有未提交内容；重新进入时个人信息、企业补充信息和组织资料为空。
- 提交时由平台再次校验全部字段；失败时不提交，指出问题字段，已填写内容保留。
- 提交成功后：资料提交状态变为已提交，记录提交时间，入驻进度变为已完成入驻，立即进入默认页面并开放角色业务；不设审批，不发送消息。
- 提交期间不能重复提交；重复点击或网络重发只提交一次。组织资料仍在上传时不能提交。
- 个人信息、企业补充信息和组织资料只由企业用户本人填写和维护；运营在企业管理中可以查看，不能修改。

## 6. 业务入口与账户

### 6.1 角色业务入口与无权访问（M1-F08）

适用角色与前提：账号启用、未锁定、密码状态为已设置、已完成入驻的企业用户。

业务入口按企业当前的业务角色开放：

| 业务入口 | 仅债权人 | 仅债务人 | 债权人与债务人 | 所属模块 |
| --- | --- | --- | --- | --- |
| 应收账款（债权人） | 可用 | 不可用 | 可用 | 应收查看与确权申请（M7a） |
| 确权申请（债务人） | 不可用 | 可用 | 可用 | 确权待办与确认处理（M7b） |
| 账户信息、修改密码、界面语言与时区、退出 | 可用 | 可用 | 可用 | 本模块 |

- 不可用的入口不出现；直接访问按[无权访问的处理](#no-access)拒绝。业务入口的名称、顺序和导航形式由设计确定。
- 入驻未完成时，上表中本企业可用的菜单同样展示，但全部锁定，见[入驻准备与进度（M1-F05）](#M1-F05)。
- 同时有两种角色时，同一个用户看到两类业务入口的合并范围；仍按本企业在每笔交易中的身份查看和处理，不能替交易对方确认，也不能确认本人提交的申请。具体规则由 M7a、M7b 定义。
- 运营增加或移除业务角色后，在本人下一次请求时生效，不需要重新登录：新增的业务入口出现；移除的业务入口消失，正在进行的该角色操作被拒绝，数据不变。移除角色后该角色下未完成业务的处理由 M7a、M7b 定义。
- 企业当前没有任何业务角色时，完成入驻后不展示业务入口，说明“暂无可办理的业务，请联系平台运营”；账户信息照常可用。
- 菜单内有哪些数据和操作由所属模块定义；本模块只提供登录状态、入驻完成、业务角色、企业与用户标识及已绑定钱包地址。

<a id="no-access"></a>
无权访问的处理：

| 情况 | 结果 |
| --- | --- |
| 未登录访问企业端受保护页面 | 先到登录入口，登录后按[登录后去向](#login-destination)处理 |
| 待首登改密时访问其他页面 | 回到首次登录强制改密 |
| 入驻未完成时访问账户信息或业务页面 | 回到当前入驻步骤，不返回任何内容 |
| 访问本企业角色不可用的业务入口 | 不返回任何内容，说明无权访问，可以回到默认页面 |
| 访问不属于本企业的数据，或访问不存在的数据 | 两种情况结果完全相同：不返回任何内容，统一说明“无权查看或内容不存在”，不透露该数据是否存在 |
| 发起本企业角色没有的操作 | 被拒绝，数据不变，说明无权操作 |

- 判断由平台完成，不能只靠界面隐藏；改写链接中的编号或企业标识，也拿不到其他企业的数据。
- 越权访问被拒绝时按[安全记录](#security-records)留存。

### 6.2 账户信息查看与维护（M1-F09）

适用角色与前提：账号启用、未锁定、密码状态为已设置、已完成入驻的企业用户本人。

- 登录后在任何页面都能看到账号入口，显示本人姓名和登录邮箱；账号入口提供账户信息和退出登录。
- 账户信息展示以下内容，全部只对本人可见：

| 分组 | 内容 | 可否由本人修改 |
| --- | --- | --- |
| 账号 | 登录邮箱、业务角色、账号创建时间、最近登录时间、资料提交时间 | 不能 |
| 钱包 | [钱包信息](#wallet-fields)全部内容 | 不能；不提供更换、解绑或新增入口 |
| 个人信息 | [个人信息](#fields-personal)全部内容 | 姓名、英文姓名、与企业的关系、关系说明可以修改；登录邮箱不能 |
| 企业信息 | [企业身份信息](#fields-enterprise)与[企业补充信息](#fields-supplement) | 企业英文名称、州／省、注册地址可以修改；企业身份信息不能 |
| 组织资料 | [组织资料](#fields-files)全部文件 | 可以添加和移除，始终至少保留 1 份；不能替换已上传文件的内容 |
| 偏好设置 | 界面语言、时区 | 可以，见[界面语言与时区（M1-F12）](#M1-F12) |

- 修改个人或企业信息、添加或移除组织资料时，按[个人信息](#fields-personal)、[企业补充信息](#fields-supplement)和[组织资料](#fields-files)的规则校验；必填项不能清空，只剩 1 份组织资料时不能移除。保存成功即生效并说明已保存，不需要审批，不改变入驻进度，不发送消息。
- 保存失败时说明失败、保留本次填写内容，原值不变，可以重试。
- 个人信息、企业补充信息与组织资料只由本人维护，运营只读查看；运营登记的联系信息不在账户信息中展示。

- 读取中、读取失败、确实没有数据三种情况须可区分；读取失败时说明失败并可重试，不显示为空。选填项没有值时不展示该项。
- 退出或登录结束后不残留本人资料。
- 时间按本人时区展示并标明时区。

### 6.3 修改密码（M1-F10）

适用角色与前提：账号启用、未锁定、密码状态为已设置、已完成入驻、已登录的本人。

- 先输入当前密码完成验证，通过后在 10 分钟内输入两次新密码并提交；新密码须符合[设置密码的共同规则](#password-rules)。超过 10 分钟仍未提交成功的，须重新验证当前密码，原密码不变。
- 当前密码输错时不能继续，说明当前密码不正确；输错计入[连续失败与临时锁定（M1-F04）](#M1-F04)的连续失败次数，达到 5 次时账号锁定、全部登录结束。
- 修改成功后：新密码立即生效；平台发送[密码变更通知（M1-NT02）](./03-企业登录与首次入驻-消息通知.md#M1-NT02)，随后该账号的全部登录（包括当前这次）立即结束，回到登录入口并说明“密码已修改，请用新密码重新登录”。
- 修改失败、取消或离开时，原密码不变，不发送密码变更通知。
- 提交期间不能重复提交；修改期间登录已结束时，修改不生效。

<a id="M1-F11"></a>
### 6.4 登录有效期、无操作登出与退出（M1-F11）

适用角色与前提：已登录的企业用户，包括待首登改密时的受限登录和平台内入驻期间的登录。

| 规则 | 要求 |
| --- | --- |
| 登录有效期 | 自登录成功起 4 小时，到期即结束，不因操作延长 |
| 无操作登出 | 连续 2 小时没有真实操作，登录失效；不提前提醒，用户下一次真实操作时平台不执行该次操作，转到登录入口并说明需要重新登录 |
| 什么算真实操作 | 点击、键盘输入、提交、页面跳转；页面自动刷新数据不算 |
| 主动退出 | 账号入口中有唯一的退出入口；入驻期间和待首登改密时同样可以退出。退出后该账号的全部登录立即结束 |
| 全部登录结束 | 主动退出、本人修改密码、账号锁定、运营停用、运营重置密码时，该账号在所有设备和标签页上的登录都立即结束 |
| 设置新密码后直接登录 | 完成首次登录强制改密或本人找回成功时，该账号在其他设备和标签页上的登录立即结束；设置新密码的当前页面直接登录并进入平台，登录有效期自设置成功起计算 |

<a id="session-end"></a>
登录结束后的处理：

- 回到登录入口并说明原因：到期或无操作时说明需要重新登录；被停用时说明账号已停用；运营重置密码时说明登录信息已重置，请使用平台运营提供的新密码登录；因本人在其他页面设置新密码而结束时说明密码已修改，请用新密码登录。
- 受保护内容立即清除；无操作失效时，当前画面可以保留到下一次真实操作，届时清除并进入登录入口。失效后不再显示新的受保护数据或迟到的操作结果。
- 尚未保存的内容不保留，结束前未提交成功的操作不会被当作已完成。
- 界面语言保留，不随退出恢复默认。

流程参见：[登录结束（图 6）](./02-企业登录与首次入驻-流程图与状态机.md#fig-6)、[登录状态机](./02-企业登录与首次入驻-流程图与状态机.md#state-3)。
验收参见：[登录有效期、无操作登出与退出](./04-企业登录与首次入驻-验收.md#ac-session)。

<a id="M1-F12"></a>
### 6.5 界面语言与时区（M1-F12）

适用角色与前提：界面语言适用于所有企业端访问者（含未登录、待首登改密和入驻期间）；时区适用于已完成入驻的本人。

界面语言：

- 两种：简体中文、English。登录入口和登录后的任何页面都可以切换；切换后立即生效，不需要刷新，已填写但未提交的内容不丢失。
- 界面文字按所选语言展示；邮箱、金额、时间、编号、地址等业务值和用户填写的内容按原值展示，不翻译；网络名称始终写作 Ethereum。
- 登录后切换即保存为本人偏好，换浏览器或设备登录后仍按上次所选；保存失败时说明并恢复为切换前的语言，可以重试。
- 未登录时切换的语言保存在当前浏览器，不保存到账号。登录后，本人保存过偏好时按偏好展示；没有保存过时沿用当前页面正在使用的语言；都没有时为 English。
- 退出后保留当前语言。没有对应译文时显示英文，不显示内部标识。

时区：

- 首次登录成功时，按浏览器推断写入本人时区偏好；推断不出时为 UTC。
- 本人可以在账户信息中修改，可选范围为有效的 IANA 时区（例如 Asia/Shanghai、Africa/Lagos、UTC）；改选即保存，保存成功后立即生效，保存失败时保留原时区，可以重试。
- 企业端的时间按本人时区展示并标明时区；时区只影响展示，不改变有效期、到期或任何业务判断的计算。

语言与时区变更不发送任何通知。

验收参见：[界面语言与时区](./04-企业登录与首次入驻-验收.md#ac-locale)。

## 8. 依赖

本模块没有待确认事项。

- 运营登录、企业邀请与企业管理（M2）：邀请时为企业登记企业名称、注册国家／地区、企业登记标识和至少一个业务角色，建立唯一企业用户并分配登录邮箱和初始密码，初始密码的交付方式由 M2 定义；对企业用户填写的个人信息、企业补充信息与组织资料只读查看；执行停用、启用、重置密码和解锁，结果按[运营操作对账号的影响](#operator-actions)。
- 对外身份口径：代币发行平台、借贷平台现行 PRD 按钱包地址向本平台调取账户、资料和认证结论，并引导“前往资产可信平台注册／认证”，与本平台只接受运营邀请、不设认证审核的口径不一致；由独立任务处理，本模块不展开方案，只记录启停、入驻进度和钱包地址等事实。
- 邮件服务：投递[找回密码验证码（M1-NT01）](./03-企业登录与首次入驻-消息通知.md#M1-NT01)和[密码变更通知（M1-NT02）](./03-企业登录与首次入驻-消息通知.md#M1-NT02)。验证码发送失败不得提示已发出；通知投递失败不回滚已生效的密码。
- 钱包服务商：提供钱包连接、地址识别与签名；具体支持的钱包、签名与地址格式校验的实现由研发确定，验证由测试负责。
- 平台运营联系邮箱：由开发直接配置，用于密码变更通知中“非本人操作时”的求助方式，见[共同内容](./03-企业登录与首次入驻-消息通知.md#common)。
- 浏览器时区：用于首次登录写入时区偏好；推断失败时为 UTC。
- 会话与锁定计时、真实操作的判定、人机校验的判定与冷却、验证码的计时与计数、签名有效期以及安全记录的保留由研发实现，测试负责验证。
