# M7b 确权待办与确认处理 · 企业端（债务人）原型

依据 [`PRD/企业端/M7b-确权待办与确认处理/`](../../../PRD/企业端/M7b-确权待办与确认处理/01-确权待办与确认处理-PRD.md)，需求提交 `35faf784`（2026-11-26：删去核心资料状态与差异说明，核心资料一律按原资料展示；此前已新增应收账款详情 F-M7b-05、金额改用美元、去掉币种筛选、删除推送表述；无待确认事项）。申请状态、确权与审核进度环节、当次依据内容按 M7a，当次依据的版式与 M7a 原型一致。沿用当前共享组件规范；本轮模块限定视觉变体见 [UI设计说明](UI设计说明.md)。

原型只用于评审页面、字段和主流程；规则、校验及异常分支以 PRD 为准。企业、编号、金额、汇率、VIN、日期、姓名、驳回原因和文件均为演示值，菜单待办数量为演示值。

## 打开与路径

双击 [`确权待办与确认处理.html`](确权待办与确认处理.html)，或使用离线单文件附件。默认进入“确权申请 · 待处理”；侧栏底部「画面目录 · 演示数据」默认关闭，可到达全部 29 屏。

- 主流程：L1 待处理 → D1 申请详情 → C1 确认 → D2 已确认（待运营审核，待办数量 5 → 4）。
- 驳回：D1 → R1 驳回（未填写）→ R2 原因为空 → R3 已填写 → D3 已驳回。
- 应收账款详情：申请详情概要中的应收账款编号，或当次依据右上的“查看应收账款当前资料”，进入本模块的 A 组画面（D1、D5、D9 → A1；D3 → A2；D4 → A3；D7 → A4）；A 组“确权申请”中的“查看申请详情”及申请编号回到最近一笔申请的详情，面包屑可回到申请详情。其他申请提示“演示仅提供部分应收账款的详情画面。”。
- 列表行的“确认”“驳回”打开同一弹窗，取消或 Esc 回到列表；演示只为 AP-DEMO-0031 提供处理画面，其他行提示演示范围。

## 本期不做与未出屏

- 按 PRD 本期不做：批量确认或驳回、撤回或改结论、确认说明、上传或补正资料、钱包签名、全部应付列表、到期前提醒；企业端不展示核心资料状态、差异说明与风控预警，核心资料按原资料展示。应收账款详情不展示资产健康度、已收款比率、车辆清单、回款记录、内销合同日期 / 金额 / 付款条件、预警、资料齐全且有效（F-M3-15）的校验结果与问题项。
- 未单独出屏（以 PRD 为准）：确认提交失败、结果未确认、提交时已确认 / 已驳回（不能重复处理）、提交时已非发给本企业（按 D10）、登录结束、待办数量单独取数失败，沿用 R4、D8、D10、L6 的提示位置与结构；债权人重新发起的新申请发给了其他企业时，旧申请详情不注明、不提供入口，画面同 D3；当次依据或确认、驳回弹窗中金额“无法折算”的写法同 L1 的 AP-DEMO-0044；应收账款详情中金额“无法折算”、1% 容差注明、起算日“未确定”，写法与 M7a A4、A6、A7 相同；申请详情处理记录读取失败同 A5 的局部失败。
- 消息（M7b-NT01～03）由 M10 消息中心承载；顶栏铃铛与最近消息预览由共享层 `inbox.js` 提供。

## 共享层变动

- `frame.js`：画面可用 `data-pending-count` 指定本屏所在菜单的演示待办数量（空值不展示）；未使用该属性的模块不受影响。
- `tokens.css` / `components.css`：文末新增 M7b token 与 A34–A36。
