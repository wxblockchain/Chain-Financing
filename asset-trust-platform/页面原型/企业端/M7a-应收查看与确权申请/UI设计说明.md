# M7a UI 设计说明

2026-11-25 · WS-670 · 现有系统适配（existing-system adaptation）· 企业端桌面控制台。

基线为 `6104a930` 的 34 屏原型、PRD `36f756a6`、共享组件规范及《列表与详情规范》。衔接 `cly-v6.0.0` 当次最新共享层；M7b 的当次依据继续作为同类只读详情的视觉参照。

## 实际变化

- 列表采用明确列宽，发票号、日期、金额和状态保留完整值；表头按词换行。金额右对齐、数字等宽，币种作为次要文字；为 `28,647,720.00 NGN` 原币长值留足空间。中性状态改为圆点加文字，保留待处理、驳回、可申请等语义色，减少重复浅底标签。
- 中文表宽下限仍为 1088 / 1136 px（默认 / 批量），1440 px 完整显示；英文调整到 1520 / 1568 px，低于所需空间时在表内滚动，选择框、编号和操作固定。英文 1920 px 可完整显示。没有隐藏列或缩写金额。
- 批量选择条提高已选数量的文字层级；有选择时用浅主色和左侧强调线标记。退出、清空和提交保持原顺序，提交与辅助操作留出间距，窄桌面可换行。
- 应收账款概要将状态对齐到金额区域上方，关键字段成组排列。确权申请卡增加“当前申请 / Current request”标签，同区右侧用文字入口进入申请详情；历次申请用浅底表格与当前结果区分，驳回原因、推送时间等完整保留。1024 px 时入口自然换到结果区下方。
- 申请详情移除误用的四列 `.review-steps`，复用与 M7b 一致的三环节 `.receivable-steps`；改善进度与处理记录间距。当次依据继续使用共享事实字段、分区导航、附件与明细表，只调整本模块字段间距。推送进度仍是审核通过后独立出现的卡片。
- 修复预设画面跳转复选框的原生勾选残留：仅对 `.claim-check[data-go]` 取消原生切换，由原有 `data-go` 打开既有预设画面。没有增加选择计算、校验或提交模拟。

原业务字段、文本、精度、权限、禁用状态、时间、数据与跳转目标均保留；新增文字只有“当前申请”分组标签。默认无选择框、到期日期与状态分列、列表无申请编号等裁定保持不变。

## 核验与限制

- Chromium 149 / Playwright，离线单文件：34 屏 × 中英文 × 1024 / 1280 / 1440 / 1920 px，共 272 组；没有整页横向溢出、单元格长金额越界、操作文字裁切、脚本错误或外部请求。英文界面中 ERP 业务原文保留。
- 内部截图观察列表、批量、确权申请卡、待确认 / 已推送进度、非美元当次依据与批量确认 / 部分失败结果。表格两端滚动核对固定列可见，中文 1440 px 起无表内横滚；英文 1440 px 需表内横滚。
- 中英文 × 1024 / 1440 px 实际点击：单笔提交、批量提交、清空、退出批量、驳回后重新发起、当前 / 历史申请、申请与应收账款双向入口；推送卡的显隐按既有画面核对。
- 键盘实测：文字入口 Enter、焦点可见、表内左右滚动、批量弹窗 Tab 圈定、Esc 关闭及返回触发按钮、分区导航定位和焦点；1024 / 1440 px 双语均核对。另在 960 × 540 CSS px、设备比例 2 下检查四个代表画面（L3、A3、D1b、B1），相当于 1920 px 桌面放大后的阅读空间，不等同于全量浏览器缩放验收。
- 源页与导出件 5 个代表画面 × 双语截图一致；M7b 29 屏 × 双语的共享层变更前后截图对比，结果无差异。所有 `.claim-*` 消费者均在 M7a，通用字体、颜色、壳层与 M7b 源码未修改。
- 未验证：1024 px 以下全部画面、移动端、其他浏览器、屏幕阅读器和真实接口。静态原型的选择与提交仍为预设画面跳转，不代表真实业务能力。模块没有图表。

```sh
  --output /tmp/M7a-应收查看与确权申请.html
```
