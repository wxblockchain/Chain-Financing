# M7a 应收查看与确权申请 · 企业端（债权人）原型

依据 [`PRD/企业端/M7a-应收查看与确权申请/`](../../../PRD/企业端/M7a-应收查看与确权申请/01-应收查看与确权申请-PRD.md)，需求提交 `18f75b93`（2026-11-24 复核稿：到期日按 M3 平台计算值只有日期，字段名对齐“内销发票号”“待收款金额（美元）”，推送进度按 M9 F-M9-08 债权人口径）。组件规范 v1.20（先用本平台已有组件，缺少的按代币发行平台基线补齐，见规范 A46–A50）。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。企业、编号、金额、日期、VIN、姓名、驳回原因和文件均为演示数据。

## 打开与入口

双击 [`应收查看与确权申请.html`](应收查看与确权申请.html)，或用 `_shared/export.py` 导出的离线单文件。左侧菜单“业务”下为债权人的两个入口：

- **应收账款**：本企业为债权人的全部应收账款，单笔、批量发起确权申请。
- **申请记录**：本企业发起的全部确权申请，进入申请详情（进度、处理记录、当次依据）。

“申请记录”为本次新增的共享菜单项（`_shared/menu.client.js`），债权人、双角色和入驻锁定菜单同步出现；双角色企业仍另有债务人的“确权申请”（M7b）。应收账款详情属于 M3：“查看”与应收账款编号经[仓库联看](../../README.md#仓库联看)进入企业端 M3（AR-DEMO-0012、0019 有详情画面，其他提示“演示仅提供部分应收账款的详情画面。”）；顶栏预览的消息进入 M10。单模块附件中这些入口提示到 index.html 打开。

主流程：

1. 单笔：L1 行内“发起申请” → S1 确认 → S2 提交成功（列表已刷新）→ D1 申请详情。
2. 批量：L1 勾选 → L2 已选 3 笔 → B1 确认 → B2 逐笔结果（列表已刷新）→ R1 申请记录。
3. 驳回后重新发起：R1 → D4 债务人已驳回 → D5 确认 → D6 已重新发起。

申请详情顺序：页头申请编号（主操作在右）→ 概要（金额、应收账款编号、内销发票号、债务人、到期日；申请状态、发起方式）→ 确权与审核进度（发起申请 / 债务人确认 / 运营审核三环节进度条 + 处理记录时间线，只列已发生的环节，运营审核只有结论与时间、不显示审核人和审核说明；运营审核通过后才接第四环节“推送”，按 M9 F-M9-08 的债权人口径为“未推送”或“已推送”附首次推送时间，其他状态不展示推送）→ 当次依据（应收账款信息：编号、债权人、债务人、金额及币种、账期、起算日、到期日与三项状态；内销发票与附件；内销合同摘要；车辆清单：车辆数、VIN、内采单价；回款：已收款、待收款金额（美元））。

## 待确认与未覆盖

- Q-M7a-01（债务人为本企业）：按推荐画为不可申请，见 L1 的 AR-DEMO-0022。列表不展示原因；原因“债务人为本企业，不能发起确权申请”按 PRD 在 M3 债权人视角的应收账款详情及提交时的结果中展示，M3 企业端原型尚未同步。确认前对应验收 AC-M7a-34 待验。
- Q-M7a-02（English）：本模块自身的字段、状态与原因有中英文两套；进入的 M3 应收账款详情按 M3 原型。
- 演示编号沿用全平台的 AR-DEMO- / INV- / AP-DEMO- 写法（与 M3、M7b、M9、M10 的同一笔记录一致，跨模块入口按编号登记），未单独改为 PRD 举例中的 AR-0012 / PI-0012。

## 未单独出屏（以 PRD 为准）

- 单笔 / 批量“提交失败可重试”“提交结果未确认”、批量“本次没有提交任何申请”、提交时登录已结束。
- ERP 企业关联取消后：对应应收账款不再出现在列表中，申请记录与详情照常（版式同 R1、D1–D8）。
- 列表按 VIN、申请编号查找的结果，以及申请记录筛选无结果：沿用 L5 版式。
- 申请详情中某一部分（当次依据、处理记录）读取失败。
- 双角色企业：本模块页面与债权人相同，只是菜单多一项“确权申请”，未单独出屏。
- 本期不做：撤回申请、申请时上传或补充资料、债务人批量确认、运营批量审核、运营审核不通过。

## 实际核验
