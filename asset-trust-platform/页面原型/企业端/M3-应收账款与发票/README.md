# M3 应收账款与发票 · 企业端只读详情原型

依据 [`PRD/两端共用/M3-应收账款与发票/`](../../../PRD/两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md)，最新需求提交 `5defb17`；“发起申请”的资格、不可申请原因、确认内容与申请状态按 M7a 应收查看与确权申请（WS-607，F-M7a-02 / 03）。组件规范 v1.12。

原型只用于评审页面、字段和主流程；规则、校验及异常分支以 PRD 为准。企业、编号、金额、VIN、日期、银行账号和文件均为演示值。

## 打开与路径

双击 [`应收账款与发票.html`](应收账款与发票.html)，或使用离线单文件附件。债权人从 M7a“应收账款”、债务人从 M7b“确权申请”进入本详情；申请编号、“返回申请”经[仓库联看](../../README.md#仓库联看)回到 M7a / M7b 申请详情。在画面目录中切换债权人 / 债务人画面时，菜单随角色切换。

主流程：C1 可发起申请 → C2 确认 → C3 已提交 → D1 债务人详情。

## 画面清单

| 身份 | 编号 | 画面 |
| --- | --- | --- |
| 债权人 | C1 | 详情 · 可发起申请：进度条“未申请”，概要底部“可发起确权申请”，页头“发起申请”可用 |
| 债权人 | C2 | 发起确认弹窗（M7a 单笔确认内容）：编号、发票号码、债务人、金额、到期日及时区、回款状态、未收金额；“提交后将发给债务人确认，提交后不能撤回” |
| 债权人 | C3 | 已提交：进度条“待债务人确认”（AP-DEMO-0031）；“发起申请”不可用，原因“已有申请处理中（AP-DEMO-0031）” |
| 债权人 | C4 | 债务人已驳回：进度条停在“债务人确认”，展示驳回原因与时间；本笔仍可申请，“发起申请”可用 |
| 债权人 | C5 | 核心资料存在差异：差异说明；进度条“待运营审核”；不可申请时列出全部原因（核心资料待核实、已有申请处理中），M7a 列表只标“不可申请”，原因在此查看 |
| 债权人 | C6 | 该应收账款不存在或无权查看 |
| 债务人 | D1 | 只读详情：无“发起申请”，回款表仅日期 / 收款方 / 付款方 / 金额 |
| 债务人 | D2 | 详情读取失败 |

企业端概要只有到期状态、回款状态两项，不显示预警信息；不可见首次取得时间、资料追溯、回款预警、明细核对及上下游入口。

## 待确认与未覆盖

- C2 确认与提交属于 M7a 单笔发起流程；M7a 原型交付后以其为准，本模块的弹窗应保持一致或改为跳转。提交失败、结果未确认、提交时已不满足资格等分支按 M7a，未出屏。
- “运营审核通过”“已关闭”在企业端的进度条版式与运营端 O11 相同，未单独出屏。

## 实际核验（v1.12）

Chromium / Playwright，中英文 × 1280 / 1440 / 1920 px：8 屏无脚本错误、无整页横向溢出，英文模式除演示账号姓名外无未翻译文案。离线附件断网无外部请求；C1 → C2 → C3 → D1 主流程、弹窗 Esc 返回、C3 按钮不可用、债务人无发起入口实测通过。未验证 1280 px 以下、屏幕阅读器与真实服务。
