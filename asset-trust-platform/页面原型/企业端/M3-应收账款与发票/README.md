# M3 应收账款与发票 · 企业端只读详情原型

依据 [`PRD/两端共用/M3-应收账款与发票/`](../../../PRD/两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md)，提交 `887265ed`（2026-11-25 WS-682：企业详情只保留核对金额、期限和办理确权所需的关键信息，金额统一 USD）。“发起申请”的资格与不可申请原因按 M7a 可申请的条件，确认内容按 M7a 单笔发起确权申请（F-M7a-03）；申请状态名称按 M7a，推送情况按 M9 F-M9-08 的债权人口径。

原型只用于评审页面、字段和主流程；规则、校验及异常分支以 PRD 为准。界面以英文为主、可切换中文（M1-F12），业务值不翻译。企业、编号、金额、日期和文件均为演示值，与运营端 M3 同一笔应收账款取值一致。

## 打开与路径

双击 [`应收账款与发票.html`](应收账款与发票.html)，或使用离线单文件附件。债权人从 M7a“应收账款”、债务人从 M7b“确权申请”进入本详情；概要“确权申请结果”中的申请编号、债务人页头“返回申请”经[仓库联看](../../README.md#仓库联看)回到 M7a / M7b 申请详情。在画面目录中切换债权人 / 债务人画面时，菜单随角色切换。

主流程：C1 可发起申请 → C2 确认 → C3 已提交 → D1 债务人详情。

## 详情结构

页头：应收账款编号，下一行内销发票号与时区；债权人页头右侧“发起申请”，债务人为“返回申请”。

1. **概要**：应收账款金额（美元）；债权人、债务人、应收账款起算日、应收账款到期日（不展示剩余天数）、账期、已收款金额（美元）、待收款金额（美元）；右侧到期状态、回款状态、确权申请结果（申请状态、驳回原因或推送情况、申请编号）。债权人在概要底部看到可申请或全部不可申请原因。核心资料差异待核实时，概要下方为说明“本笔应收账款的核心资料存在差异，平台正在核实，当前展示原资料”。
2. **基础交易**：内销发票（号、原币金额、日期、附件）；内销合同（号，不可点击；附件）。

企业端不展示：资产健康度、车辆清单、回款记录明细（含收款银行、账号与凭证）、内销合同日期、金额与付款条件、关联预警、ERP 账款起算日与到期日、首次取得时间、核心资料差异明细与核实记录、确权申请的环节进度，以及任何单据跳转。详情只剩一张明细卡，因此不再显示分区导航和“明细”分组标题。企业端缺失值按原文字展示，不使用“-”占位；金额无法折算时写“无法折算”并注明原币（本轮演示样本均为 USD，未单独出屏）。

## 待确认与未覆盖

- 未完成首次入驻的企业用户（画面目录“入驻准备中”）侧栏菜单带锁、不能进入应收账款，按 M1 回到当前入驻步骤（M1 画面），本模块不单独出屏。
- Q-M3-17：M7a、M7b 的列表、确认内容和当次依据仍以原币为主、仍有币种筛选，M7a“环节对应”仍写 M3 以进度条展示；C2 确认内容按 M7a 现行写法，待 M7a 同步。M3 与 M7a / M7b 同号演示样本的金额与到期日不一致，待一起对齐。
- 提交失败、结果未确认、提交时已不满足资格等分支按 M7a，未出屏；申请“已关闭”在企业端的版式与 C4 相同（状态 + 原因），未单独出屏。
