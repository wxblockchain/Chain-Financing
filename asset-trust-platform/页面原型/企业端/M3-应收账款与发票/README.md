## 详情结构

页头：应收账款编号，下一行内销发票号与时区；债权人页头右侧“发起申请”，债务人为“返回申请”。

1. **概要**：应收账款金额；债权人、债务人、应收账款起算日、应收账款到期日（不展示剩余天数）、已收款金额（美元）、待收款金额（美元）；右侧到期状态、回款状态。债权人在概要底部看到可申请或全部不可申请原因。核心资料差异待核实时，概要下方为说明“本笔应收账款的核心资料存在差异，平台正在核实，当前展示原资料”。
2. **明细**（按 PRD 详情顺序，企业不可见的资产健康度不出现）：基础交易（内销发票：号、金额、日期、账期、附件；内销合同摘要：号（不可点击）、金额、日期、付款条件、账期、附件）→ 车辆清单（VIN、内采单价原币，不可点击）→ 回款记录 → 确权与审核进度。
   - 回款记录：债权人为交易流水号（不可点击）、收付日期、付款方 → 收款方、金额、收款银行 / 收款账号、凭证附件；债务人为收付日期、付款方 → 收款方、金额。
   - 确权与审核进度：债权人四个环节（发起申请 / 债务人确认 / 运营审核 / 推送），推送环节为未开始 / 未推送 / 已推送（附首次推送时间）；债务人三个环节。

企业端不可见：美元折算值（已收款、待收款金额除外）、已收款比率、资产健康度、关联预警、ERP 账款起算日与到期日、首次取得时间、核心资料差异明细与核实记录，以及车辆清单中 VIN、内采单价以外的字段和单据跳转。企业端缺失值按原文字展示，不使用“-”占位。

## 待确认与未覆盖
