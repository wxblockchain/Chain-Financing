# M1 · 企业登录与首次入驻（企业端）

邮箱密码登录、首登强制改密、自助找回密码、入驻准备（绑定钱包并验证控制权 → 完善并提交个人与企业信息）、按业务角色开放的菜单、账户信息查看与维护、修改密码。

- PRD 基线：`cly-v6.0.0` 提交 `699c51f` 的四册：[功能](../../../PRD/企业端/M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md)、[流程](../../../PRD/企业端/M1-企业登录与首次入驻/02-企业登录与首次入驻-流程图与状态机.md)、[通知](../../../PRD/企业端/M1-企业登录与首次入驻/03-企业登录与首次入驻-消息通知.md)、[验收](../../../PRD/企业端/M1-企业登录与首次入驻/04-企业登录与首次入驻-验收.md)。
- 视觉口径：本平台 [`_shared/` 组件规范 v1.1](../../_shared/design-system/组件规范.md)，基线为代币发行平台组件规范 v1.96；展示约定参考《资产可信平台列表与详情展示参考规范 v1.0》。
- **规则、校验与异常分支以 PRD 为准。** 原型只画规则生效后的画面，不实现校验、计时、锁定或状态机。画面中的企业、邮箱、地址、时间均为演示数据。

## 打开方式

- 源码：双击 [`企业登录与首次入驻.html`](企业登录与首次入驻.html)（引用 `../../_shared/`），默认进入登录页。
- 单文件：在 `页面原型/` 下执行 `python3 _shared/export.py --source 企业端/M1-企业登录与首次入驻/企业登录与首次入驻.html --output <仓库外路径>.html`。生成件不入库。
- 左下角（窄屏右下角）「画面目录 · 演示数据」默认关闭，按“页面 → 状态”列出全部画面，并提供「主流程下一屏」。界面语言在顶栏切换，默认 English。

## 主流程

L1 登录 → P1 设置新密码 → L5 用新密码重新登录 → W1 连接钱包 → W2 确认地址 → W3 等待签名（等待画面用目录「主流程下一屏」推进）→ F1 填写资料并提交 → A1 账户信息（默认页面）→ C1 / C2 修改密码 → L5。

- 账号入口（右上角）：入驻期间只显示登录邮箱与退出；完成入驻后显示姓名，展开为登录邮箱、业务角色、账户信息、退出登录。
- 入驻期间点击已完成的“绑定钱包”步骤可查看绑定结果（W4）。
- 业务菜单“应收账款”“确权申请”属于 M7a / M7b，未交付，点击显示“该入口尚未纳入原型。”。

## 设计决定

- **默认页面为“账户信息”**（本轮视觉核验沿用）：它是任何角色组合（含暂无业务角色）都可用、且本模块交付的页面；业务入口在侧栏一步可达。后续若经确认调整为首个业务入口（债权人→应收账款、债务人→确权申请），应在 M7a / M7b 交付后统一核对角色映射、`TP.routes`、L5 / F1 与各返回入口；本轮不改去向。
- 入驻准备与首登改密使用 focus 骨架（无侧栏、无业务菜单），三步进度始终可见；运营重置后、早已完成入驻的账号改密不显示入驻步骤（P3）。
- 登录邮箱只在“账号”分区展示一次，不在“个人信息”分区重复。
- 资料表单的企业身份信息只读核对，与企业补充信息分开；运营登记的联系信息（联系人、联系电话、联系邮箱）不出现在任何画面。
- 修改密码沿用代币发行平台的两步弹窗（验证当前密码 → 设置新密码）。

注册入口、验证码登录 / 钱包登录 / 记住我、本人修改登录邮箱、更换或解绑钱包、修改企业身份信息或业务角色、证件或营业执照上传、站内消息与消息入口（M10）、业务菜单内页面（M7a / M7b）、运营端操作（M2）、邮件正文（见 03 册）、安全记录查询。原型不实现真实钱包连接与验签、接口、计时与计数。

## 视觉深化（2026-11-12）

既有系统适配，surface 为企业端桌面 Web；基于原型提交 `6ce49f2`。修改 `_shared/tokens.css`、`components.css`、`frame.js` 与组件规范，模块 HTML 与文案保持原样。

- 账户信息分区标题列加宽，英文 Personal / Company information 不再因列宽被迫拆行；字段采用留白分组，保留分区分隔线。阅读区域最大 1360 px，1280 px 下保持合适的两列字段，宽屏短值组三列；编辑区增加左侧主色标记与操作分隔线。
- 入驻三步使用等列布局与当前步下划线；标题和进度随长资料表单滚动保持可见，控件定位按实际标题区高度避让。
- 企业身份信息集中为浅底只读区，与白底填写区区分；绑定前完整地址核对区增加内边距，复制按钮保持独立位置，不可更换或解绑的后果使用警告语义。
- 密码规则清单增加上下分隔和条目间距，保留原有满足 / 不满足状态。

逐组的“修改 / 继承”覆盖见组件规范 §7；未增加画面、校验、模拟钱包行为或业务数据。

## 核验（2026-11-12，视觉深化后）

Chromium / Playwright，`file://`，以默认 English 与简体中文检查。源码与 `_shared/export.py` 生成的单文件各 38 屏 × 2 种语言 × 1280 / 1440 / 1920 px，共 456 次画面渲染；没有脚本错误、HTTP(S) 请求或可见元素横向越界，全部 `data-go` / `data-next` / `data-base` 目标存在。重点实屏审阅登录、改密、地址确认、填写资料及错误、账户查看与编辑、账号菜单和密码弹窗。

点击实测主流程 L1 → P1 → L5 → W1 → W2 → W3 → 目录推进 F1 → W4 → F1 → A1；四种角色的菜单分别核对。完整地址可由键盘展开及 Esc 关闭；修改密码弹窗 Tab 焦点保持在弹窗内，Esc 关闭后回到原按钮。1280 × 900 下滚动至资料页中部与底部，三步进度仍在视口内；控件滚动定位未被吸顶区遮挡。720 × 500 CSS px（1440 × 1000 的 200% 缩放等效可用空间）补查 P1、W2、F1、A1、A7、C2 无横向越界；该检查不等同于完整浏览器缩放测试或移动端适配。减少动态效果偏好下等待签名的旋转动画停用。

另外检查中英文的键盘反向遍历与字段标签滚动避让、主按钮 hover / 焦点、禁用与错误状态。地址风险后果、核对区标签、当前步骤文字的实际对比度分别为 5.20:1、7.19:1、6.70:1；这是针对所改关键文字的抽查，不是全页面无障碍认证。

同步分支时合并 M2 并行提交 `aa73779`，保留其 A7–A11、运营菜单和账号入口配置。共享密码清单与账户分区同时影响 M2，因此补查其首登、找回、账户设置与密码弹窗，加上企业列表、邀请、详情代表画面，共 17 屏 × 中英文 × 3 个桌面宽度（102 次渲染）；无脚本错误、网络请求或整页横向越界。M2 宽表保持原来的表内滚动；没有改动 M2 模块源码或宣称完成其全量核验。

未验证 Safari / Firefox、原生浏览器 200% 缩放、完整移动端覆盖与真实接口、钱包验签、服务端权限、校验或计时；这些能力仍以 PRD 和后续实现为准。
