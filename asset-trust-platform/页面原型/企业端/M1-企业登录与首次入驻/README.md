# M1 · 企业登录与首次入驻（企业端）

邮箱密码登录、首登强制改密、自助找回密码、入驻准备（绑定钱包并验证控制权 → 完善并提交个人与企业信息）、按业务角色开放的菜单、账户信息查看与维护、修改密码。

- PRD 基线：`cly-v6.0.0` 提交 `699c51f` 的四册：[功能](../../../PRD/企业端/M1-企业登录与首次入驻/01-企业登录与首次入驻-PRD.md)、[流程](../../../PRD/企业端/M1-企业登录与首次入驻/02-企业登录与首次入驻-流程图与状态机.md)、[通知](../../../PRD/企业端/M1-企业登录与首次入驻/03-企业登录与首次入驻-消息通知.md)、[验收](../../../PRD/企业端/M1-企业登录与首次入驻/04-企业登录与首次入驻-验收.md)。
- 视觉口径：本平台 [`_shared/`](../../_shared/design-system/组件规范.md)，基线为代币发行平台组件规范 v1.96；展示约定参考《资产可信平台列表与详情展示参考规范 v1.0》。
- **规则、校验与异常分支以 PRD 为准。** 原型只画规则生效后的画面，不实现校验、计时、锁定或状态机。画面中的企业、邮箱、地址、时间均为演示数据。

## 打开方式

- 源码：双击 [`企业登录与首次入驻.html`](企业登录与首次入驻.html)（引用 `../../_shared/`），默认进入登录页。
- 单文件：在 `页面原型/` 下执行 `python3 _shared/export.py --source 企业端/M1-企业登录与首次入驻/企业登录与首次入驻.html --output <仓库外路径>.html`。生成件不入库。
- 左下角（窄屏右下角）「画面目录 · 演示数据」默认关闭，按“页面 → 状态”列出全部画面，并提供「主流程下一屏」。界面语言在顶栏切换，默认 English。

## 主流程

L1 登录 → P1 设置新密码 → L5 用新密码重新登录 → W1 连接钱包 → W2 确认地址 → W3 等待签名（等待画面用目录「主流程下一屏」推进）→ F1 填写资料并提交 → A1 账户信息（默认页面）→ C1 / C2 修改密码 → L5。

- 账号入口（右上角）：入驻期间只显示登录邮箱与退出；完成入驻后显示姓名，展开为登录邮箱、业务角色、账户信息、退出登录。
- 入驻期间点击已完成的“绑定钱包”步骤可查看绑定结果（W4）。
- 业务菜单“应收账款”“确权申请”属于 M7a / M7b，未交付，点击显示“该入口尚未纳入原型。”。

## 设计决定

- **默认页面暂定为“账户信息”**：它是任何角色组合（含暂无业务角色）都可用、且本模块交付的页面；业务入口在侧栏一步可达。若希望完成入驻后直接进入首个业务入口（债权人→应收账款、债务人→确权申请），待 M7a / M7b 原型交付后只改 `TP.routes` 与 L5 / F1 的去向。
- 入驻准备与首登改密使用 focus 骨架（无侧栏、无业务菜单），三步进度始终可见；运营重置后、早已完成入驻的账号改密不显示入驻步骤（P3）。
- 登录邮箱只在“账号”分区展示一次，不在“个人信息”分区重复。
- 资料表单的企业身份信息只读核对，与企业补充信息分开；运营登记的联系信息（联系人、联系电话、联系邮箱）不出现在任何画面。
- 修改密码沿用代币发行平台的两步弹窗（验证当前密码 → 设置新密码）。

Chromium（Playwright，`file://`）：源码与单文件各 38 屏 × 中英文 × 1280 / 1440 / 1920 px，无脚本错误、无整页横向溢出、无网络请求；全部 `data-go` / `data-next` / `data-base` 目标存在；英文界面除业务值（姓名、企业名称、地址等原值）外无未翻译文案。点击实测主流程 L1 → P1 → L5 → W1 → W2 → W3 → F1（含已完成步骤进入 W4 并返回）→ A1，账号入口展开与“账户信息”、完整地址浮层开合、修改密码弹窗与 Esc 关闭、业务菜单范围提示、退出登录。
