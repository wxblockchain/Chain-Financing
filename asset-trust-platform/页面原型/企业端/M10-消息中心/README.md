# M10 消息中心 · 企业端原型

依据 [`PRD/两端共用/M10-消息中心/`](../../../PRD/两端共用/M10-消息中心/01-消息中心-PRD.md)（提交 `e5dbee4b`），页面结构参照代币发行平台 M7 消息通知原型。消息标题与正文取自来源模块现行 03 消息通知册：M7a（NT01～03）、M7b（NT01～02）、M9（NT01～02）。组件规范与本轮 UI 变体见下文。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。企业、编号、金额、时间与驳回原因均为演示数据。

## 打开与路径

双击 [`消息中心.html`](消息中心.html)，或使用离线单文件附件。默认进入消息列表；侧栏底部「画面目录 · 演示数据」默认关闭，可到达全部 34 屏，并提供「主流程下一屏」。

- 演示企业同时有债权人、债务人角色：两类消息进入同一个信箱、同一个未读数，正文写明本企业在这笔业务中的身份。
- 主流程：顶栏铃铛 → P01 最近消息 → 查看全部消息 → L01 消息列表 → D02「收到新的确权申请 · AP-DEMO-0041」（打开即已读，未读 4 → 3）→ 面包屑回 L09（该条原地变为已读）→ A02 全部已读确认 → A04 处理中 → A06 成功。
- 详情中的申请编号是前往原业务的入口（M7a / M7b 申请详情）。经[仓库联看](../../README.md#仓库联看)进入；来源模块未画出该申请时提示“该入口尚未纳入原型。”。
- 企业端只有“本企业”一种收件范围；顶栏铃铛同时接入 M1、M3、M7a、M7b 等企业端模块；临时锁定、待首登改密、入驻未完成与未登录画面不显示消息入口。

## 本期不做与未出屏

- 按 PRD 本期不做：发送、编辑、撤回消息与模板；邮件、短信、浏览器推送；删除、归档；逐条标为已读 / 未读；通知开关；账户安全类消息；两端未读合计。
- 业务提醒目前没有来源模块登记企业端消息，列表分类下拉只列出本企业实际有消息的分类（业务办理进度、待处理事项）。
- 未单独出屏（以 PRD 为准）：未登录打开消息链接、登录失效、新消息自动插入、多标签页同步、加载更多（企业端演示不足一批 20 条，画法见运营端 L01 / L07 / L08）。

## 上一轮原型核验（历史记录）

Chromium / Playwright：

- 34 屏 × 中英文 × 1280 / 1440 / 1920 px：无脚本错误、无整页横向溢出、无失效跳转；英文模式除演示账号姓名与驳回原因原文外无中文。各屏铃铛未读数与画面一致（读后 4 → 3、全部已读后不显示数字）。
- 点击实测：铃铛开合与 Esc、预览进入详情、编号入口（仓库联看跳转、附件范围提示）、面包屑返回、已读状态分段、分类下拉（无“账户安全”）、全部已读确认与 Esc、无未读时全部已读不可用及原因；S05 无前往入口并提示“相关内容暂不可访问。”。
- 离线单文件由 `_shared/export.py` 生成，打开时无外部请求。
- 未验证：1280 px 以下、屏幕阅读器、真实消息服务（送达时效、已读保存、权限判断）。


## 本轮 UI 深化（2026-11-25，WS-683）

产物类型：existing-system adaptation；现有系统桌面控制台。原型代码基线 `096030bc`，结合最新 PRD `647b90c0`（包含 `025bf9d3` 的行为口径）。上游已说明这两次 PRD 修订不需新增画面；本轮只调整呈现，不补写排序、已读保存、登录回跳或消息服务逻辑。

### 设计变化

- 列表按“标题 → 分类及业务识别 → 单行摘要”扫描；未读同时用字重、圆点、文字状态及浅底区分。时间列固定阅读空间，日期与时分分两行；列表保留整行进入详情，不增加统计与查询步骤。
- 恢复详情原有的两级面包屑返回入口：此前被壳层的两级目录隐藏规则遮住；仅对 M10 有返回目标的详情显示，不改目标或导航层级。
- 详情使用“分类 → 完整标题 → 时间与时区 → 正文 → 相关业务”的阅读顺序；宽屏正文与相关业务分栏，窄屏顺序堆叠。完整正文保留换行；业务编号 / 名称沿用原链接，增加下划线和方向图标辨识。
- 顶栏预览沿用最近 10 条，标题两行、摘要一行；时间与已读状态共用弹性行。筛选、数据、原入口和已读 / 未读行为继承原型。
- 全部已读流程统一 600 px 弹窗，范围条件独立浅底分组；原条数、说明、处理中与失败分支继承。列表空、筛选无结果及失败区保留各自反馈和操作。
- 实现与尺寸集中在共享源码，由 `data-module="messages"` 限定 M10 页面；共享预览使用 `.dd.inbox`，不复制共享层。规范见[组件规范的本轮说明](../../_shared/design-system/组件规范.md#m10-消息中心-ui-深化ws-6832026-11-25)。

Chromium / Playwright：两端共 85 屏 × 2 语言 × 5 宽度（850 次画面布局检查），检查整页横向溢出、消息字段 / 正文 / 链接溢出、预览时间与状态相交、脚本错误及原画面目录 / 局部目标完整性。英文用于检查长标题及业务名称；系统字体栈继承，不下载字体。

共享消费者：除 M10 外 16 个模块源码（含 M17），按已有可显示消息的身份分别打开预览，在中英文 × 768 / 1440 px 共 76 次检查；只检查共享预览及页面溢出，不代表重跑消费者业务、表格或图表流程。M10 无业务图表或数据表格，本次为消息列表及正文阅读。

关键交互另行实测（中英文）：列表键盘焦点与 Enter 打开详情、原面包屑返回、分段与分类下拉、确认框初始焦点 / Tab 限制 / Esc 返回、预览 10 条与底部入口 / Esc 回到铃铛、S05 正文可读且没有前往入口。仓库联看已点通 D04 → M7b AP-DEMO-0036 已关闭详情；D02 的 AP-DEMO-0041 在来源原型未出屏，仍继承原范围提示，没有换成另一笔申请。两份最终离线 HTML 均点验原业务入口给出附件范围提示，打开无 HTTP(S) 请求。

打开方式沿用本页“打开与路径”。离线附件继续由 `_shared/export.py` 从源码生成，可双击；附件不包含跨模块业务画面，原入口给出单模块范围提示，完整仓库内沿用真实原型路由。

未验证：768 px 以下、其他浏览器、屏幕阅读器、真实消息送达 / 保存 / 权限服务。动态新消息、按产生时间排序、打开确认时的截止集合和多标签同步均继承 PRD 合同，静态原型不代表这些服务能力已经实现。上一轮核验不计作本轮新增实测。
