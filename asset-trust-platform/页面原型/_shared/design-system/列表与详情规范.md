# 列表与详情 · 通用规范

2026-11-13 · v1.1 · 资产可信平台企业端、运营端桌面控制台。主规范：[组件规范](组件规范.md)。

本规范由 WS-600 的几轮用户反馈提炼而来（11-13：列表去面包屑、筛选区精简、状态圆点、详情突出重点；原因放详情；不展示资料变化历史；列表范围并入状态筛选）。新增或修订模块时，按本规范组织列表与详情。规则、校验与异常分支以各模块 PRD 为准；本规范只约定画面怎样呈现。

## 1. 页面层级与面包屑

| 页面 | 面包屑 | 说明 |
| --- | --- | --- |
| 菜单直达的页面（列表、账户信息 / 账户设置、说明页） | 不显示 | 侧栏菜单已标明当前位置 |
| 详情及其下级页面 | 显示，可点击返回上级 | `data-crumb` 写到三段及以上 |

由 `frame.js` 按 `data-crumb` 段数判断，模块不另写显示逻辑。

## 2. 列表

### 2.1 页面结构

页标题（可带一句说明）→ 列表卡片：筛选条 →（批量操作条，如有）→ 表格 → 分页条。

- 列表卡片不放“标题 + N 笔”卡头，条数只在分页条“共 N 条”出现。
- 列表范围（如“待审核 / 全部申请”“待处理 / 已处理”）不单独放一行分段，作为筛选条第一个下拉“申请状态”的选项：默认选中待办范围（待审核、待处理），其余为全部或各状态。选中有对应画面的范围时切换到该画面（选项写 `data-go`，由 `list-filters.js` 处理）。
- 同一页有两组结果时（如按 VIN 查找：所在应收账款 + 采购交易），每组用卡头标题区分，不带条数。

### 2.2 筛选条

- 常用条件（下拉）→ 更多筛选 → 搜索（可带检索字段下拉）→ 重置、查询，排在一行；宽度不够时再换行。
- 下拉按内容取宽（`--filter-chip-min`），已选条件用强调色底。
- 筛选区不放统计、说明或提示语；低频条件收进“更多筛选”。

### 2.3 单元格内容

- 每列只放该列的业务值。原因、限制说明、补充信息放到详情或操作当时的反馈里（例：申请资格列只标“可申请 / 不可申请”，不可申请原因在应收账款详情中展示）。
- 编号或名称本身就是入口，点击进入详情；操作列的通用“查看”可以保留，不另加“查看申请”这类重复文字链接。
- 一格多值时主值在上、次要信息在下（如日期 + 时区、金额 + 覆盖车辆数），不超过三行。
- 状态用带圆点的标签，单行显示，不折行。
- 首列可吸附，但不画竖向分隔线；操作列固定在右侧，保留左侧分隔。
- 以后可能变多的数据一开始就用列表承载，即使当前只有一条。

### 2.4 状态画面

列表至少有默认、空（尚无数据）、筛选无结果、读取失败四种画面；空与失败画面同样不放统计卡头。

## 3. 详情

### 3.1 阅读顺序

页头（对象标识，必要时一行副信息）→ 摘要卡 → 分区导航 → 各分区 → 记录类分区。

- 摘要卡左侧放关键字段，右侧放状态：
  - 关键字段按 **对象身份 → 当事方 → 金额 → 日期** 排列，“字段名在上、值在下”成组排布。
  - 有主金额的对象（应收账款、确权申请）用大号金额开头；没有主金额的（销售交易、车辆）直接从关键字段开始。
  - 状态（到期、回款、申请、收款、履约进展、核对提示等）放在右侧状态区。
- 分区内字段按同一顺序：身份 → 当事方 → 金额 → 日期 → 条款 / 说明类 → 状态类 → 附件。
- 页头副信息与摘要不重复同一字段。

### 3.2 只展示当前资料

- 资料随 ERP 更新、补齐或撤回时，直接按最新资料展示，不提供变化历史，不展示变化前的内容。
- 业务动作的记录照常展示，因为它们是业务结果，不是资料变化：确权处理记录、运营审核与出库记录、核心资料核实记录、风控预警记录、账号操作记录、汇率历史。
- 需要保留提交时资料的，用业务快照呈现（如确权申请的“当次依据”），不用变化日志。

### 3.3 原因与提示

- 不可操作时，在操作入口附近一次列出全部原因（如应收账款详情的“暂不能发起申请”）。
- 风险与差异提示放在摘要下方或对应分区内，提示只写此刻需要知道什么、下一步可以做什么。

## 4. 实现位置

| 规则 | 实现 |
| --- | --- |
| 面包屑按层级显示 | `frame.js` `renderCrumb` |
| 筛选一行、状态圆点、首列无分隔线 | `components.css` 文末 v1.23 一节 |
| 摘要关键字段排布 | `components.css` 中的 `.asset-sum .meta` 规则（v1.23、v1.30） |
| 列表与详情的字段顺序、原因位置 | 各模块 HTML |

## 5. 自检清单

1. 菜单直达的页面没有面包屑，详情有。
2. 列表卡片没有“标题 + 条数”卡头，也没有单独一行的范围分段；范围在筛选条的状态下拉里。
3. 1440 px 下筛选条为一行。
4. 列表单元格里没有原因列表、说明段落或提示条。
5. 状态标签带圆点且不折行。
6. 详情摘要左侧为身份 / 当事方 / 金额 / 日期，右侧为状态。
7. 分区内状态类字段排在身份、当事方、金额与日期之后。
8. 没有资料变化历史类卡片；业务记录类卡片按 PRD 保留。
9. 不可操作时原因在操作入口附近一次列全。
