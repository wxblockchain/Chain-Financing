# 列表与详情 · 通用规范

2026-11-26 · v1.3 · 资产可信平台企业端、运营端桌面控制台。主规范：[组件规范](组件规范.md)。

本规范由 WS-600 的几轮用户反馈提炼而来（11-13：列表去面包屑、筛选区精简、状态圆点、详情突出重点；原因放详情；不展示资料变化历史；列表范围并入状态筛选）。新增或修订模块时，按本规范组织列表与详情。规则、校验与异常分支以各模块 PRD 为准；本规范只约定画面怎样呈现。

## 1. 页面层级与面包屑

| 页面 | 面包屑 | 说明 |
| --- | --- | --- |
| 菜单直达的页面（列表、账户信息 / 账户设置、说明页） | 不显示 | 侧栏菜单已标明当前位置 |
| 详情及其下级页面 | 显示，可点击返回上级 | `data-crumb` 写到三段及以上 |

由 `frame.js` 按 `data-crumb` 段数判断，模块不另写显示逻辑。M10 企业端从顶栏进入，详情原路径仅“消息中心 / 消息详情”两级；壳层对 M10 已有返回目标的两级详情显示面包屑，保留原层级与目标，不增加虚构菜单层级（WS-683）。

## 2. 列表

### 2.1 页面结构

页标题（可带一句说明）→ 列表卡片：筛选条 →（批量操作条，如有）→ 表格 → 分页条。

- 列表卡片不放“标题 + N 笔”卡头，条数只在分页条“共 N 条”出现。
- 列表范围（如“待审核 / 全部申请”“待处理 / 已处理”）不单独放一行分段，作为筛选条第一个下拉“申请状态”的选项：默认选中待办范围（待审核、待处理），其余为全部或各状态。选中有对应画面的范围时切换到该画面（选项写 `data-go`，由 `list-filters.js` 处理）。
- 同一页有两组结果时（如按 VIN 查找：所在应收账款 + 采购交易），每组用卡头标题区分，不带条数。

### 2.2 筛选条

- 常用条件（下拉）→ 更多筛选 → 搜索（可带检索字段下拉）→ 重置、查询，排在一行；宽度不够时再换行。
- 下拉按内容取宽（`--filter-chip-min`），已选条件用强调色底。
- 筛选区不放统计、说明或提示语；低频条件收进“更多筛选”。

### 2.3 单元格内容

- 每列只放该列的业务值。原因、限制说明、补充信息放到详情或操作当时的反馈里（例：申请资格列只标“可申请 / 不可申请”，不可申请原因在应收账款详情中展示）。
- 编号或名称本身就是入口，点击进入详情；操作列的通用“查看”可以保留，不另加“查看申请”这类重复文字链接。
- 一格多值时主值在上、次要信息在下（如日期 + 时区、金额 + 覆盖车辆数），不超过三行。
- 状态用带圆点的标签，单行显示，不折行。
- 首列可吸附，但不画竖向分隔线；操作列固定在右侧，保留左侧分隔。
- 以后可能变多的数据一开始就用列表承载，即使当前只有一条。

### 2.4 状态画面

列表至少有默认、空（尚无数据）、筛选无结果、读取失败四种画面；空与失败画面同样不放统计卡头。

## 3. 详情

### 3.1 阅读顺序

页头（对象标识，必要时一行副信息）→ 摘要卡 → 分区导航 → 各分区 → 记录类分区。

- **详情主体的独立信息分区纵向排列，一行一个并占满内容区宽度**，宽屏不改为左右并排；适用于交易资料、当次依据、附件、处理记录等信息详情。卡片标题与内容左缘对齐，表格使用完整分区宽度；关键内容保持展开，沿用分区导航上下滚动定位，不用固定高度裁切内容。
- **卡片内部的短字段可以分列**：编号、日期、金额等按可用宽度排两至三列，标签在上、值在下；长文本与附件可以跨整行，窄容器自然收为单列。分区之间保持紧凑、稳定的间距，避免通过空白占位对齐不同分区。
- 上述约定限定详情主体的信息分区，不改变概要卡内部金额与状态的排布，也不扩大到统计图表、仪表盘和既有流程弹窗。以下概要卡约定继续适用。
- 摘要卡左侧放关键字段，右侧放状态：
  - 关键字段按 **对象身份 → 当事方 → 金额 → 日期** 排列，“字段名在上、值在下”成组排布。
  - 有主金额的对象（应收账款、确权申请）用大号金额开头；没有主金额的（销售交易、车辆）直接从关键字段开始。
  - 状态（到期、回款、申请、收款、履约进展、核对提示等）放在右侧状态区。
- 分区内字段按同一顺序：身份 → 当事方 → 金额 → 日期 → 条款 / 说明类 → 状态类 → 附件。
- 页头副信息与摘要不重复同一字段。

### 3.2 只展示当前资料

- 资料随 ERP 更新、补齐或撤回时，直接按最新资料展示，不提供变化历史，不展示变化前的内容。
- 业务动作的记录照常展示，因为它们是业务结果，不是资料变化：确权处理记录、运营审核与出库记录、核心资料核实记录、风控预警记录、账号操作记录、汇率历史。
- 需要保留提交时资料的，用业务快照呈现（如确权申请的“当次依据”），不用变化日志。

### 3.3 原因与提示

- 不可操作时，在操作入口附近一次列出全部原因（如应收账款详情的“暂不能发起申请”）。
- 风险与差异提示放在摘要下方或对应分区内，提示只写此刻需要知道什么、下一步可以做什么。

## 4. 资产数据模块统一呈现（v1.2，WS-655）

用户 2026-11-23 在 WS-655 要求资产数据各模块“类似的展示统一，需要个性化的单独说明”。以 M3 应收账款、M4 合同信息按用户 11-23 反馈调整后的写法为准，运营端 M3、M4、M5、M12、M13、M14 统一如下；各模块保留的差异写在模块 README 的“与资产数据其他模块统一”一节。

| 项 | 统一写法 |
| --- | --- |
| 列表页头 | 只有页标题，不带说明句 |
| 查找 | 单一查找框，不选查找方式；占位文字列出可匹配的编号或名称 |
| 列表列 | 只放识别、当事方、金额、日期、状态与预警；比率、进度（开票 / 付款 / 收款进度、已清关数量、保险货值与覆盖率、终端进度、资产审核状态）只在详情展示 |
| 当事方 | 一列“A → B”，单元格两行“角色 + 名称”（`.party-line`）；方向与详情页头一致 |
| 预警列 | 有未处理预警直接展示条数（`.alert-count`，警示色，可进入关联预警）；没有为“无” |
| 取不到 / 算不出 | 统一“-”占位（`.na-dash`，读屏保留原文字），原因放详情；“未开票”“未到港”“未清关”“暂无外销”等业务状态照常用文字 |
| 详情页头 | 有当事双方的对象为“角色 名称 → 角色 名称”（`.receivable-parties`），说明行“编号 · 时区”；页头不放返回按钮，面包屑返回列表，跨模块进入用浏览器返回 |
| 概要 | 左侧大号主金额（带币种旗标）+ 关键字段；右侧状态区；页头已有的当事方不重复 |
| 关联预警 | 概要右侧状态区一项：“未处理 N 条”（警示色链接，进入关联预警）/“已处理 M 条”；没有为“无”；不另放预警横条 |
| 分层 | “概要 → 进度与核对 → 明细”，用 `.detail-group` 二级标题分组 |
| 折算 | 美元值旁“折算 ⓘ”（`.fx-mark` 信息浮层），浮层为当前汇率与生效时间；原币写在美元值下方或单独一列 |
| 附件分区 | 表格“附件类别 | 附件 | 取得时间”，附件格为文件名 + 下载图标；只有一类时省略类别列；不设“查看 / 下载”操作列 |

模块个性化（摘要，详见各模块 README）：M3 预警“待核实”、单据附件跟随单据；M4 三个页签、辅助订单编号不可点击、外销列表保留销售方式；M5 页标题为 VIN、概要无主金额、明细五个分区依次展示，以导航上下滚动定位（含出入库）；M12 港口单行“装运港 → 卸货港”、清关附件按清关单分组；M13 列表只展示美元值与折算标识，原币在详情；附件只有一类，不设类别列，无附件时写“暂无附件”；M14 列表无预警列、无关联业务列（关联业务只在详情展示）；按 WS-680 用户裁定，M14 详情为概要卡加“基本信息、凭证附件”两个分区（基本信息只含关联业务与收付双方银行、账号），不用三层结构，金额（美元）按 M14 PRD 固定／暂计口径展示、不带折算标记，关联业务明确类型，详见 [M14 README](../../运营端/M14-资金收付/README.md)。

## 6. 自检清单

1. 菜单直达的页面没有面包屑，详情有。
2. 列表卡片没有“标题 + 条数”卡头，也没有单独一行的范围分段；范围在筛选条的状态下拉里。
3. 1440 px 下筛选条为一行。
4. 列表单元格里没有原因列表、说明段落或提示条。
5. 状态标签带圆点且不折行。
6. 详情摘要左侧为身份 / 当事方 / 金额 / 日期，右侧为状态。
7. 分区内状态类字段排在身份、当事方、金额与日期之后。
8. 没有资料变化历史类卡片；业务记录类卡片按 PRD 保留。
9. 不可操作时原因在操作入口附近一次列全。
10. 资产数据模块：列表无比率 / 进度列、无查找方式下拉；预警为条数；缺值为“-”；详情页头为当事双方、关联预警在概要状态区。
11. 详情主体独立信息分区上下通栏，宽屏不恢复并排；分列只发生在卡片内部的短字段，表格与长附件仍完整可达。
