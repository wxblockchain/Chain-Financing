# 进度与操作记录 · 通用组件规范

2026-11-12 · v1.0 · 资产可信平台桌面控制台。主规范：[组件规范 v1.10](组件规范.md)。适用于既有系统适配；不定义业务步骤、状态、权限或日志采集规则。

## 1. 选择组件

| 使用任务 | 组件 | 信息范围 |
| --- | --- | --- |
| 快速定位固定流程的当前位置 | 横向 `.steps`；详情入驻采用 `.onboarding-steps` | 已确认步骤、完成 / 当前 / 未开始状态。M2 为“首次改密 → 钱包绑定 → 资料完善 → 入驻完成” |
| 追溯一个对象已经发生的操作 | `.operation-history` 内的有序列表 `.operation-log` | 每次动作、结果、操作人、时间与必要说明；重复操作各占一条 |
| 比较大量对象或大量记录的同类字段 | 项目既有表格组件 | 按行列比较；不因通用时间线规范强制改造所有明细表 |

横向进度用于固定阶段，纵向记录承载可重复事件。阶段名变化不自动改变业务状态值：M2 节点“资料完善”对应既有资料提交环节；状态“待提交资料”、事件“提交入驻资料”、资料提交时间保持业务原义。入驻完成后重置密码或解除锁定，不回退入驻进度。

## 2. 时间线结构与尺寸

源码唯一来源为同目录上一级 `components.css` 中既有的 `.operation-log` 组件，继承代币发行平台管理端；不在模块内复制样式，不新增一套 token。

| 区域 | 类名与约定 |
| --- | --- |
| 外层 | `.card.operation-history`，使用既有卡头、标题与记录数量；不增加固定高度或嵌套纵向滚动 |
| 记录列表 | `ol.operation-log[role="list"]`，上下 20 px、左右 24 px；原生列表语义配合显式 role 保证去序号后仍可识别 |
| 节点与竖线 | 8 px 主色圆点、1 px 边框色竖线；最后一项不再向下连线。由 CSS 伪元素装饰，不作为唯一状态标识 |
| 每条记录 | 左侧留白 32 px，记录间距 24 px；记录自然增高，长内容完整可读 |
| 动作与主结果 | `.operation-heading`，`h3` 为 14 px / 600；结果使用既有 `.tag` 语义色，允许换行 |
| 元信息 | `.operation-meta`，13 px / muted；宽屏操作人在左、时间在右，视口 ≤1100 px 上下排列。只显示来源已有的操作人或账号，不编造角色 |
| 时间 | `.operation-time` 内 `time[data-minute][data-instant]` 保留源时间戳并由既有显示层格式化，附 `span[data-zone]`；时区与模块合同一致。ERP 等外部时间按所属模块规则处理，不擅自转换 |
| 详细说明 | `.operation-detail` 位于元信息下方，顶部 12 px 留白、左侧轻分隔线；说明正文 14 px，支持多行与长值换行 |

以上数字均来自已有 `sp`、`fs`、`accent`、`border` 等 token。基线 `.operation-detail` 支持 `h4` + `p`，仅当数据已有对应标题时使用，不为整齐补造业务字段。

## 3. 结果、顺序与信息保真

- 顺序由模块决定，说明与实现必须一致。M2 按时间从新到旧；不能照搬参考截图的从早到晚。
- 每条保留原动作、原结果、原操作人、原时间戳及全部修改前后值；保留事件数量与顺序。重发、重置、重试等重复发生时逐条显示，不合并成固定阶段。
- 成功使用 `.tag.ok`；只有整个动作确实失败 / 驳回时才用危险结果及 `li.failed` 的危险色节点，并保留原因文字。其他模块如有独立当前状态，沿用其已确认状态文案，不增加“进行中”记录。
- 主操作与通知结果分别表达。M2 新初始密码已生效而邮件未发出时，保留“成功”主结果，详细说明单独用 `.tag.warn` 展示原邮件未发出文案，不标记 `li.failed`，不暗示回滚。
- 变更前后的值以原顺序展示，保留号码、地址、币种及精度；示例数据不是新增真实采集字段。只有来源具备角色和账号时才并列显示，只有“企业用户”等原操作人时按原值显示。
- 没有发生的动作不补造记录，不把历史失败删除或改成成功。不新增日志、分页、折叠、筛选或查询能力；空与失败状态复用模块既有画面。

## 4. 复用示例

下面取自 M2 现有“修改企业资料”记录，按模块上下文放入 `.card.operation-history`；业务字段原值不翻译，标签和动作由模块文案映射翻译。

```html
<ol class="operation-log" role="list" aria-label="操作记录">
  <li>
    <div class="operation-heading">
      <h3>修改企业资料</h3>
      <span class="tag ok">成功</span>
    </div>
    <div class="operation-meta">
      <span>运营示例账号</span>
      <span class="operation-time">
        <time data-minute data-instant="2026-11-12T07:05:00Z"
              datetime="2026-11-12T07:05:00Z"></time>
        (<span data-zone></span>)
      </span>
    </div>
    <div class="operation-detail">
      <p>联系电话：+234 803 000 0001 → +234 803 111 2222</p>
    </div>
  </li>
</ol>
```

## 5. 验收与当前覆盖

新增消费者需检查动作及结果先于元信息的阅读顺序，中英文换行，1280 / 1440 / 1920 px 布局，时区与原时间戳、记录数量和顺序；文字说明不能只靠颜色区分。只读记录不做成可点击的步骤或按钮。若记录内已有链接 / 复制入口，沿用原语义并检查键盘操作。

当前实装为 M2 的 16 个详情画面、56 条既有演示记录；另有 6 个确认 / 冲突弹窗继承其详情背景。其他模块未改造。参考截图为 WS-602 用户附件 `01a1cec4-d7c0-7e42-984f-c644314f5ebf`；用户于 2026-11-12 确认执行并指定入驻节点名称。核验条件和实测结果见 [M2 README](../../运营端/M2-运营登录与企业管理/README.md)。
