# 资产可信平台 · 组件规范（v1.0）

2026-11-12｜适用：资产可信平台企业端、运营端页面原型｜已落地模块：企业端 M1 企业登录与首次入驻、运营端 M2 运营登录与企业管理

本规范只约定画面怎样呈现；规则、校验与异常分支以各模块 PRD 为准。

## 1. 取值基线

| 来源 | 用法 |
| --- | --- |
| 代币发行平台组件规范 v1.96（`cly-v6.0.0` 的 `token-issuance-platform/页面原型/_shared/`，提交 `e2f8eb3`） | `tokens.css`、`components.css`、`asset-icons.js`、`export.py` 原样复制；`frame.js`、`display.js` 复制后按第 3 节改动。组件写法、文字角色、尺寸、响应式与原型轻量化约定沿用该规范的 §2–§6，本文不重复 |
| 《资产可信平台列表与详情展示参考规范 v1.0》（WS-599 交付，WS-601 引用） | 列表、详情、抽屉、金额与时间、双语和验收清单的展示约定；M3 等含列表与详情的模块按其选用。与上一行冲突时，以本平台 token 与组件为唯一取值来源 |

三平台独立后不跨平台引用公共层：本目录是资产可信平台的唯一 token 与组件来源，代币发行平台规范只作为复制基线和阅读参考。

## 3. 与代币发行平台的差异

| 项 | 代币发行平台 | 本平台 | 原因 |
| --- | --- | --- | --- |
| 品牌 | TI · 代币发行平台 | AT · 资产可信平台，侧栏副标题“企业端” | 平台不同 |
| 登录方式 | 钱包签名登录 | 邮箱与密码登录；钱包只在入驻时绑定并验证控制权 | M1 PRD |
| 账号入口 | 企业端显示缩写地址 | 显示姓名；展开为姓名、登录邮箱、业务角色标签，再是“账户信息”“退出登录” | M1 PRD §6.2 |
| 受限登录 | 首登改密 focus 画面放一个“退出登录”按钮 | 首登改密与入驻准备的账号入口只显示登录邮箱，菜单只有“退出登录” | M1 PRD：退出只在账号入口 |
| 菜单 | 业务 / 用户中心；未认证时锁形标记 | 业务（应收账款 / 确权申请，按角色出现）/ 账户（账户信息）；没有认证锁定 | M1 PRD §6.1：不可用的入口不出现 |
| 消息入口 | 顶栏铃铛 | 本期不显示；消息中心（M10）原型交付后接入 | M10 未出原型 |
| 未交付入口提示 | 附件 / 仓库联看两种文案 | 统一“该入口尚未纳入原型。” | 本平台暂无 `index.html` 联看入口 |
| 界面语言记忆 | `tp-visitor-language` | `atp-visitor-language` | 避免与代币平台原型互相覆盖 |
| 运营端账号入口 | 管理端：名称、邮箱、角色，“账户设置” | 运营端沿用管理端结构：姓名、登录邮箱、“运营管理员”标签，再是“账户设置”“退出登录”；`frame.js` 由账号的 `settingsLabel` 决定菜单项文字（企业端默认“账户信息”） | M2 PRD F-OP-08 |
| 运营端菜单图标 | — | `frame.js` 新增 cart / truck / database / send，用于上游采购、车辆履约、三方数据源、出库与供数 | M2 菜单表 |

## 4. 本平台新增组件（§A）

| 编号 | 类名 | 用途与规格 |
| --- | --- | --- |
| A1 | `.auth-screen.onboard-screen`、`.onboard-head` | 入驻准备：沿用 focus 骨架，卡片加宽到 `--onboard-w`（720 px）。卡片顶部为标题、一句说明与三步 `.steps`（修改初始密码 / 绑定钱包 / 完善资料），下方 1 px 分隔线。已完成且有结果可看的步骤（绑定钱包）用 `.btn-link` 进入结果画面 |
| A2 | `.rule-list` | 设置密码时逐项说明规则是否满足：满足为绿色对勾，未满足为红色圆点（仅在出错的那一屏），未开始为灰色圆点；两列，≤ 600 px 一列。不展示强弱分档 |
| A3 | `.addr-check`、`.addr-full` | 绑定前核对：浅底框内完整展示 42 位地址（16 px 等宽、一行，窄屏任意位置换行）与网络，旁边复制图标；地址不缩写 |
| A4 | `.step-section`、`.subhead` | 入驻各步及资料表单内的分组：16 px / 600 标题，组间 24 px 与分隔线；组内只读核对字段（`.facts.cols-2.inset`）与可填写字段（`.form-grid`）分开，小节标题 14 px / 600。命名避开基线 M3a 的 `.form-section` |
| A5 | `.profile-section>.section-head`、`.section-body`、`.is-editing` | 账户信息的可维护分区：左列标题下放“编辑”，编辑时本分区原位变为表单，底部“取消 / 保存”；只读分区不出现编辑入口 |
| A6 | `.addr>.value-pop` | 缩写地址旁“查看完整钱包地址”：复用基线 `.value-pop` 浮层，按钮为无框图标，点击与键盘可开合、Esc 关闭；复制得到完整地址 |

| A7 | `.enterprise-table-card`、`.tbl.enterprise-list`、`.enterprise-table-hint` | 运营端企业列表：十二列固定比例，表头不在词中断开，状态标签按词换行；容器窄于 `--enterprise-table-min`（1280 px）时显示横向滚动提示并在表内滚动，操作列固定在右 |
| A8 | `fieldset.field.role-field`、`.role-choices` | 业务角色多选：两张 `.choice-card` 复选卡并排（每张最宽 240 px，≤ 600 px 一列）；未选时 `.role-choices.is-error` 加红框并在下方 `.err-msg` |
| A9 | `.ref-block` | 表单内引用已有记录（重复邀请时的已有企业）：浅底细框内 `.facts.cols-2`，编号用 `.btn-link.mono` 进入其详情 |
| A10 | `.steps.onboarding-steps`、`.enterprise-summary` | 企业详情“入驻与认证”卡：入驻四节点沿用 `.steps` 的完成 / 当前 / 未开始三态，节点按内容取宽，下接认证状态、入驻进度、业务角色与已发生的时间 |
| A11 | `.detail-table > .tbl.operation-records` | 操作记录明细：时间（表头标时区）/ 操作人 / 事件（变更前后为副文本）/ 结果（邮件是否发出为副文本），按时间从新到旧 |

设置密码规则清单复用 A2 `.rule-list`（运营端首登改密、找回、本人改密同样逐项说明）。

新增 token：`--onboard-w: 720px`；`--enterprise-table-min: 1280px`（A7）。

## 5. 展示约定（本平台）

- 钱包地址：除绑定前核对外一律缩写（前 6 位 + … + 后 4 位），保留大小写，可查看完整地址（A6）并复制；网络名称中英文都写 Ethereum。
- 时间：`data-instant` 按本人时区展示为“日期 时:分”，下方副文本标注 IANA 时区。
- 由平台运营登记、企业不能修改的信息：在分区内用一句提示说明“如有错误请联系平台运营更正”，不提供修改入口（包括不可用的修改按钮）。
- 选填项没有值时不展示该字段。
- 业务值（邮箱、姓名、企业名称、地址、登记号码）用 `data-upstream` 标记，切换语言时不翻译；国家／地区名、字段名与状态随语言切换。

## 6. 新增或修订模块

1. 先复用基线组件和第 4 节组件；确实缺少时追加到 `components.css` 文末一节并在第 4 节登记。
2. 模块目录：`页面原型/<企业端|运营端>/<PRD 模块号>-<模块名>/`，内含 `<模块名>.html`、模块文案 `m<N>-copy.js`、`README.md`；不复制壳层、菜单、token 或 CSS，不写行内样式。
3. 交付单文件：`python3 _shared/export.py --source <模块 HTML> --output <仓库外路径>.html`。
