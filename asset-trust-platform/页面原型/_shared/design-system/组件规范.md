# 资产可信平台 · 组件规范（v1.19）

2026-11-12｜适用：资产可信平台企业端、运营端页面原型｜已落地模块：企业端 M1 企业登录与首次入驻、运营端 M2 运营登录与企业管理、M3 应收账款与发票（运营端 / 企业端）、运营端 M4 上游采购追溯、M5 车辆物流与履约追溯、运营端 M6 下游销售与收款追溯、企业端 M7b 确权待办与确认处理、M10 消息中心（两端）、运营端 M9 运营审核与资产出库、运营端 M11 汇率管理

本规范只约定画面怎样呈现；规则、校验与异常分支以各模块 PRD 为准。

## 3. 与代币发行平台的差异

| 项 | 代币发行平台 | 本平台 | 原因 |
| --- | --- | --- | --- |
| 品牌 | TI · 代币发行平台 | AT · 资产可信平台，侧栏副标题“企业端” | 平台不同 |
| 登录方式 | 钱包签名登录 | 邮箱与密码登录；钱包只在入驻时绑定并验证控制权 | M1 PRD |
| 账号入口 | 企业端显示缩写地址 | 显示姓名；展开为姓名、登录邮箱、业务角色标签，再是“账户信息”“退出登录” | M1 PRD §6.2 |
| 受限登录 | 首登改密 focus 画面放一个“退出登录”按钮 | 首登改密（focus）与入驻准备（平台内）的账号入口只显示登录邮箱，菜单只有“退出登录” | M1 PRD：退出只在账号入口 |
| 菜单 | 业务 / 用户中心；未认证时锁形标记，菜单仍可点击进入认证引导 | 业务（应收账款 / 确权申请，按角色出现）/ 账户（账户信息）。入驻未完成时按本企业角色列出全部菜单，使用同一锁形标记，不可点击（`aria-disabled`，悬停提示“完成入驻后可用”）；身份由账号的 `locked:true` 决定 | 用户 2026-11-12 确认（WS-601） |
| 消息入口 | 顶栏铃铛 | 沿用顶栏铃铛、未读数（超过 99 为 99+）与最近 10 条预览，列表 / 详情 / 全部已读组件沿用基线 §12；分类改为 M10 的五类；无“认证引导”“固定页面”去向；运营端另有菜单“消息中心”（M2 菜单表） | M10 PRD |
| 未交付入口提示 | 附件 / 仓库联看两种文案 | 统一“该入口尚未纳入原型。” | 本平台暂无 `index.html` 联看入口 |
| 界面语言记忆 | `tp-visitor-language` | `atp-visitor-language` | 避免与代币平台原型互相覆盖 |
| 运营端账号入口 | 管理端：名称、邮箱、角色，“账户设置” | 运营端沿用管理端结构：姓名、登录邮箱、“运营管理员”标签，再是“账户设置”“退出登录”；`frame.js` 由账号的 `settingsLabel` 决定菜单项文字（企业端默认“账户信息”） | M2 PRD F-OP-08 |
| 运营端菜单图标 | — | `frame.js` 新增 cart / truck / database / send，用于上游采购、车辆履约、三方数据源、出库与供数；v1.15 新增 fx（双向箭头）用于汇率管理 | M2 菜单表；M11 |

## 5. 展示约定（本平台）

- 钱包地址：除绑定前核对外一律缩写（前 6 位 + … + 后 4 位），保留大小写，可查看完整地址（A6）并复制；网络名称中英文都写 Ethereum。
- 时间：`data-instant` 按本人时区展示为“日期 时:分”，下方副文本标注 IANA 时区。
- 由平台运营登记、企业不能修改的信息：在分区内用一句提示说明“如有错误请联系平台运营更正”，不提供修改入口（包括不可用的修改按钮）。
- 选填项没有值时不展示该字段。
- 业务值（邮箱、姓名、企业名称、地址、登记号码）用 `data-upstream` 标记，切换语言时不翻译；国家／地区名、字段名与状态随语言切换。
