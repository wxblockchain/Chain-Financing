# 资产可信平台 · 组件规范（v1.72）

2026-11-12｜适用：资产可信平台企业端、运营端页面原型｜已落地模块：企业端 M1 企业登录与首次入驻、运营端 M2 运营登录与企业管理、M3 应收账款与发票（运营端 / 企业端）、运营端 M4 上游采购追溯（v1.34 起菜单由 M4 合同信息替代）、M4 合同信息、M5 车辆物流与履约追溯、运营端 M6 下游销售与收款追溯、企业端 M7b 确权待办与确认处理、M10 消息中心（两端）、运营端 M9 运营审核、运营端 M11 汇率管理、企业端 M7a 应收查看与确权申请、运营端 M8 风控预警、运营端 M12 提单信息、运营端 M13 保单信息、运营端 M15 数据监控

本规范只约定画面怎样呈现；规则、校验与异常分支以各模块 PRD 为准。

**详情主体分区（2026-11-26，WS-671）**：交易资料、当次依据、附件、处理记录等独立信息分区纵向排列，一行一个、占满内容区宽度；卡头与内容左缘对齐，表格通栏，关键内容展开并沿用分区导航滚动定位。卡片内部编号、日期、金额等短字段可以两至三列，标签在上、值在下，长文本／附件可跨整行，窄容器收为单列。适用范围是信息详情主体，概要卡内部金额／状态排布继续按 A24 等原约定；统计图表、仪表盘与流程弹窗不在本条范围。详见[列表与详情规范 §3.1](列表与详情规范.md#31-阅读顺序)。

## 3. 与代币发行平台的差异

| 项 | 代币发行平台 | 本平台 | 原因 |
| --- | --- | --- | --- |
| 品牌 | TI · 代币发行平台 | AT · 资产可信平台，侧栏副标题“企业端” | 平台不同 |
| 登录方式 | 钱包签名登录 | 邮箱与密码登录；钱包只在入驻时绑定并验证控制权 | M1 PRD |
| 账号入口 | 企业端显示缩写地址 | 显示姓名；展开为姓名、登录邮箱、业务角色标签，再是“账户信息”“退出登录” | M1 PRD §6.2 |
| 受限登录 | 首登改密 focus 画面放一个“退出登录”按钮 | 首登改密（focus）与入驻准备（平台内）的账号入口只显示登录邮箱，菜单只有“退出登录” | M1 PRD：退出只在账号入口 |
| 菜单 | 业务 / 用户中心；未认证时锁形标记，菜单仍可点击进入认证引导 | 业务（债权人：应收账款 / 申请记录；债务人：确权申请；按角色出现）/ 账户（账户信息）。入驻未完成时按本企业角色列出全部菜单，使用同一锁形标记，不可点击（`aria-disabled`，悬停提示“完成入驻后可用”）；身份由账号的 `locked:true` 决定 | 用户 2026-11-12 确认（WS-601） |
| 消息入口 | 顶栏铃铛 | 沿用顶栏铃铛、未读数（超过 99 为 99+）与最近 10 条预览，列表 / 详情 / 全部已读组件沿用基线 §12；分类改为 M10 的五类；无“认证引导”“固定页面”去向；运营端另在账号入口“账户设置”下放“消息中心”，侧栏不设消息菜单 | M10 PRD；用户 2026-11-13 确认（WS-611） |
| 未交付入口提示 | 附件 / 仓库联看两种文案 | 沿用两种文案（v1.22 起）；另有未画出记录的“演示仅提供部分…画面。” | 已有 `index.html` 联看入口 |
| 界面语言记忆 | `tp-visitor-language` | `atp-visitor-language` | 避免与代币平台原型互相覆盖 |
| 运营端账号入口 | 管理端：名称、邮箱、角色，“账户设置” | 运营端沿用管理端结构：姓名、登录邮箱、“运营管理员”标签，再是“账户设置”“退出登录”；`frame.js` 由账号的 `settingsLabel` 决定菜单项文字（企业端默认“账户信息”） | M2 PRD F-OP-08 |
| 运营端菜单图标 | — | `frame.js` 新增 cart / truck / database / send，用于上游采购、车辆履约、三方数据源、出库与供数；v1.15 新增 fx（双向箭头）用于汇率管理；v1.32 新增 ship（船）用于提单信息；v1.35 新增 umbrella（伞）用于保单信息 | M2 菜单表；M11；M12 |

## 5. 展示约定（本平台）

- 钱包地址：除绑定前核对外一律缩写（前 6 位 + … + 后 4 位），保留大小写，可查看完整地址（A6）并复制；网络名称中英文都写 Ethereum。
- 时间：`data-instant` 按本人时区展示为“日期 时:分”，下方副文本标注 IANA 时区。
- 由平台运营登记、企业不能修改的信息：在分区内用一句提示说明“如有错误请联系平台运营更正”，不提供修改入口（包括不可用的修改按钮）。
- 选填项没有值时不展示该字段。
- 业务值（邮箱、姓名、企业名称、地址、登记号码）用 `data-upstream` 标记，切换语言时不翻译；国家／地区名、字段名与状态随语言切换。
- 列表与详情的通用规则统一见[列表与详情规范](列表与详情规范.md)，以下三条为其摘要。
- 面包屑（v1.23 起）：菜单直达的页面（列表、账户等，路径只有“分组 / 菜单”）不显示，详情及其下级页面显示。由 `frame.js` 按 `data-crumb` 段数判断，模块不另写。
- 列表（v1.23 起）：列表卡片不再放“标题 + N 笔”卡头，条数只在分页条“共 N 条”出现；筛选条件、更多筛选、搜索与查询排在一行，放不下时再换行；状态标签前带圆点；首列只吸附不画分隔线。列表范围（待审核 / 全部申请、待处理 / 已处理）不单放一行，作为筛选条“申请状态”下拉的选项（v1.31 起）。
- 详情（v1.23 起）：摘要中的关键字段以“字段名在上、值在下”成组排布，先放对象身份与当事方，再放金额、日期，状态在摘要右侧；分区内的字段按同一顺序，状态类字段放在身份、当事方、金额与日期之后。

## 6. 新增或修订模块

1. 先复用基线组件和第 4 节组件；确实缺少时追加到 `components.css` 文末一节并在第 4 节登记。
2. 模块目录：`页面原型/<企业端|运营端>/<PRD 模块号>-<模块名>/`，内含 `<模块名>.html`、模块文案 `m<N>-copy.js`、`route.js`、`README.md`；不复制壳层、菜单、token 或 CSS，不写行内样式。模块 HTML 在 `inbox.js`（及 `inbox-pages.js`）之后加载 `navigation.js`（`data-local-only`），并在 `_shared/modules.js` 追加一行。跨模块入口写 `data-module-key` 加附件提示 `data-toast`，只给有对应记录画面的编号登记路由。
3. 交付单文件：`python3 _shared/export.py --source <模块 HTML> --output <仓库外路径>.html`。

## M10 消息中心 UI 深化（WS-683，2026-11-25）

适用：现有系统桌面控制台，两端 M10 原型；沿用企业端 34 屏、运营端 51 屏的画面目录。规则以 M10 最新 PRD（含 `025bf9d3`、`647b90c0`）为准，本节只约定呈现。

- **列表**：标题 14 px，未读 600 字重、已读 500；保留圆点、浅底及“未读 / 已读”文字，避免只靠颜色。分类与来源识别信息排在标题下，摘要一行省略，整行进入原有详情读取全文。时间列使用 `--message-time-w:128px`，日期 / 时分两行、等宽数字，时区仍在页头。保留原筛选分段、分类下拉和不可用原因，不增加查询步骤、统计卡头或排序操作。
- **共享预览**：标题最多两行；分类、业务识别信息、摘要、发生时间与阅读状态全部保留。时间与状态放在 `.msg-footer` 的同一弹性行；摘要一行，完整标题与正文由详情承载。标题 14 px，元信息与状态 12 px，未读 / 已读字重与列表同语义。预览列表独立滚动，底部“查看全部消息”始终位于预览容器内；不增加全部已读。
- **详情**：分类作标题上方的辅助信息，完整标题 24 px；时间 / 时区 13 px。正文 16 px、1.9 行高，保留纯文本换行、完整内容和原有时间格式化。按用户 2026-11-26 裁定，所有宽度均为正文在上、相关业务及原业务入口在下，一行一个分区；分区标题与内容左缘对齐。正文内边距 24 px，相关业务上下 20 px、左右 24 px；短字段两列，规则名称等文本通栏，≤900 px 单列且两区内边距均为 20 px。移除旧宽屏分栏及 280 px 侧栏 token。编号 / 名称继续使用原业务路由，以下划线与方向图标强化入口，图标为装饰，不替代可访问名称。不可访问时保留说明，不制造入口。
- **全部已读**：同一流程弹窗统一使用现有 600 px 大弹窗 token；浅底范围区承载原有筛选条件，条数、影响范围、说明、取消、处理中和失败分支全部继承。没有新增已读存储或批处理逻辑。
- **空与失败**：继承不同状态图标、提示及原按钮，M10 列表状态区居中且最小 264 px，防止筛选与反馈挤在一起；读取失败不伪装为空。

实现：`inbox.js`、`inbox-pages.js`、`components.css` 文末 M10 UI 一节，以及 `tokens.css` 的 `[data-module="messages"]` 尺寸。列表、详情、确认与状态样式限定在 M10；共享预览规则限定 `.dd.inbox`。不复制壳层，不改变全局字体、颜色、token 默认值、消息数据、收件范围、顺序、状态条件、画面 ID 和路由。

企业端详情原有两级面包屑会被壳层的通用两级隐藏规则遮住；`frame.js` 对 M10 且已有返回目标的两级详情显示原面包屑，保留现有目标，不虚构账户或首页层级。其他模块仍按原段数规则显示。
