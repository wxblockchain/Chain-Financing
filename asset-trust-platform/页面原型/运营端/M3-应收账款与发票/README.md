## 详情结构

页头：债权人 → 债务人（首要信息），下一行应收账款编号与时区。

1. **概要**：应收账款金额；应收账款金额（美元）、已收款金额（美元）、待收款金额（美元）、应收账款起算日、应收账款到期日（剩余天数）；右侧到期状态、回款状态、关联预警（“未处理 N 条”可进入 M8 关联预警，下方“已处理 M 条”；未处理为 0 时不是链接；没有任何关联预警时为“无”）。
2. **进度与核对**：资产健康度四项并列——已收款比率、终端销售进度（已售 X 辆／共 Y 辆）、终端回款进度、保险覆盖率（应收账款保险金额）。比率条只表示读数，不按阈值变色。
3. **明细**：基础交易（内销发票、内销合同摘要）→ 车辆清单 → 回款记录 → 确权与审核进度（发起申请 / 债务人确认 / 运营审核 / 推送）→ 核心资料差异与核实。

车辆清单默认列为 VIN、物流节点、外采 / 内采 / 外销单价（美元）、外销收款金额（美元）；外采单价取外采合同单价时下方标“合同价”。行首按钮展开本车的内销（内销合同号、内销买方）、采购、运输与保险、外销、附件五组，卡头“全部展开”同时展开全部车辆。一辆车有多张同类单据时逐条列出，日期或金额跟在各自编号旁。

本模块不展示任何自行判定的风控提示，预警只承接 M8 的结果（PRD F-M3-14）。比率、金额或日期取不到 / 算不出（无法计算、无法折算、未提供、附件未取得等）时一律以占位符“-”展示，读屏仍读出原文字；原因（如“1 辆车在多张保单中”）写在值下方。

M3 是六模块（M3 / M4 / M5 / M12 / M13 / M14）统一口径的基准，列表原已符合，本轮只调整详情：

- **关联预警（O5、O6、O8–O12，O7 弹窗底层同 O6）**：概要右侧状态区的“预警信息 N 条”改为“关联预警”：第一行“未处理 N 条”（有未处理时为 warn 色链接，进入 M8 关联预警），第二行“已处理 M 条”；未处理为 0 时第一行不是链接；没有任何关联预警时为“无”。删除概要下方的“关联风控预警 未处理…、已处理… + 查看关联预警”横条，不再重复展示。
- **取不到 / 算不出统一为“-”**：EUR 样本的美元折算金额（概要、内销发票、内销合同、车辆清单内采单价、回款记录）、ERP 账款起算日 / 到期日“未提供”、外采收货日期“未提供”、内销合同号“未取得”、各处“附件未取得”、车辆清单物流节点“暂无履约记录”，均改为“-”占位，读屏读出原文字。
- **列表（O1–O4）**：核对 L1–L6，无需改动——页头只有标题；单一查找框；列为编号、债权人 → 债务人、金额、到期日、应收账款状态、预警、操作；预警直接展示未处理条数，没有为“无”。
- **折算标记**：本模块没有成功折算的非美元金额（EUR 样本为“无法折算”），不涉及 `fx-mark`。
- 车辆清单外采单价单元格去掉与 M4“合同价 / 发票价”标签同名的 `price-basis` 类，避免被套上 M4 的胶囊边框；单价与“合同价”标签由 `.num .value-lines` 右对齐。

### 个性化说明

- **预警“待核实”**：只有核心资料差异待核实时，列表预警列显示“待核实”；详情 O6 在“关联预警”第一行保留“待核实”，下面照常列未处理 / 已处理条数。这是 M3 独有的核心资料核实流程，其他模块没有。
- **内销发票、内销合同附件跟在各自单据旁**（基础交易分区内），车辆清单展开行的“附件”组按单车列出提单、保单附件，不另设统一附件分区。
- **车辆清单展开行**：行首按钮展开内销、采购、运输与保险、外销、附件五组，“全部展开”同时展开全部车辆，结构不变。
- **保留的业务状态文字**：到期日“未确定”（对应应收账款状态“到期日未确定”，概要起算日写明“尚有 1 辆车未装船”）、未装船、未投保、未出库、未收款、暂无外销，属于业务状态，不改为“-”。
- **“-”的原因**：保险覆盖率“-”下方注明“1 辆车在多张保单中”；其他“-”的原因在对应分区（如车辆清单读取失败）中说明。
