# M3 应收账款与发票 · 运营端原型

依据 PRD：[`PRD/两端共用/M3-应收账款与发票/`](../../../PRD/两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md)（提交 `e2f8eb3`，2026-11-12 需求评审稿）。原型只说明页面布局和展示的信息；**规则、校验与异常分支以 PRD 为准**。企业端的债权人、债务人只读详情见 [`企业端/M3-应收账款与发票/`](../../企业端/M3-应收账款与发票/README.md)。

画面中的企业（Carloha Holding、Carloha Nigeria、Demo Buyer X Ltd.）、编号、VIN、金额、日期、银行账号与文件均为演示数据。

## 打开

双击 [`应收账款与发票.html`](应收账款与发票.html)，进入「资产数据 / 发票与应收」列表，无需启动服务。侧栏底部「画面目录 · 演示数据」默认关闭，列出全部画面与「主流程下一屏」。列表中点击应收账款编号进入详情（演示提供 AR-DEMO-0012 / 0019 / 0021 三笔）；其他模块入口（上游采购、车辆履约、下游销售、风控预警、申请详情等）提示“该入口尚未纳入原型。”。

## 主流程

O1 列表 → O5 详情 → O6 差异待核实 → O7 记录核实 → O8 核实已记录。

未单独出屏（以 PRD 为准）：两名运营同时核实的冲突提示、核实提交失败、附件打开失败。本期不做见 PRD §1.2，原型未出现录入、编辑、补传、汇率折算与核验结论入口。

## 待确认

- **菜单名称**：运营端菜单沿用 M2 PRD 菜单表的「发票与应收」，与 M3 模块名「应收账款与发票」不一致；如需统一，请在 M2 PRD 与 `_shared/menu.ops.js` 一并修改。
- **确权与审核进度的环节名称**：由 M7a、M7b、M9 定义，尚未成稿；原型暂用演示名称（未申请、待债务人确认、待运营审核、债务人已驳回、审核通过）。
- **运营端时间的时区（已按现有 PRD 修正）**：M2 无运营时区设置，平台记录时间统一按 UTC 展示并在页头标注；ERP 日期及到期日时区按原值展示，不换算。

## 本轮视觉优化（v1.4）

既有系统适配，基于 `9d51dac`；继承原有品牌、组件、业务语义与演示数据。

- 详情页用应收账款编号作为标题，发票号置于副标题；阅读宽度最大 1360 px，分组 / 卡头 / 小节维持 20 / 16 / 14 px 层级，导航当前项加底线，多份合同间增加分隔。
- 摘要里的交易方与到期日逐行展示。平台记录时间在明细表中分为日期、时分两行；ERP 日期原样保留。
- 修复回款交易编号下“同一编号另登记”长说明不换行而覆盖相邻交易方的问题；明细顶部对齐、金额使用 14 px 等宽数字，保留原值与币种。
- 列表加宽金额、主体与英文状态列，固定左侧编号列，方向键可在表格内横向滚动；仍以应收账款为单位，无编辑入口。
- 运营平台记录时间依照已确认 PRD §3 固定 UTC，修正只在本模块生效。菜单和跨模块进度名称保持原样，见待确认。

## 实际核验

2026-11-12，Chromium（Playwright），中英文 × 1280 / 1440 / 1920 px，视口高度 1000 px。

- O1、O5、O6、O8、O9、O10 修改且实测；O7 弹窗本体继承、背景页随详情变化并实测；O2–O4 继承未改并回归。10 屏均无脚本错误、整页横向溢出、控件溢出或表格文字覆盖。
- 列表在 1280 宽中文 / 英文分别表内滚动 128 / 368 px；1440 宽英文 208 px、中文无需滚动；1920 宽两种语言均完整显示。编号列在左、中、右三个滚动位置保持可见，方向键可滚动。
- 1280 宽回款 / 付款明细最多表内滚动 26 px，1440 起完整展示。全部详情锚点均避让吸顶页头，当前项正确。
- 编号进入详情、记录核实到完成、弹窗 Tab 焦点循环、Esc 关闭及焦点返回实测。Asia/Shanghai 浏览器下平台记录显示 UTC，ERP 到期日仍为原值。
