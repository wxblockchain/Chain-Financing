# M3 应收账款与发票 · 运营端原型

依据 PRD：[`PRD/两端共用/M3-应收账款与发票/`](../../../PRD/两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md)（提交 `e2f8eb3`，2026-11-12 需求评审稿）。原型只说明页面布局和展示的信息；**规则、校验与异常分支以 PRD 为准**。企业端的债权人、债务人只读详情见 [`企业端/M3-应收账款与发票/`](../../企业端/M3-应收账款与发票/README.md)。

画面中的企业（Carloha Holding、Carloha Nigeria、Demo Buyer X Ltd.）、编号、VIN、金额、日期、银行账号与文件均为演示数据。

## 打开

双击 [`应收账款与发票.html`](应收账款与发票.html)，进入「资产数据 / 发票与应收」列表，无需启动服务。侧栏底部「画面目录 · 演示数据」默认关闭，列出全部画面与「主流程下一屏」。列表中点击应收账款编号进入详情（演示提供 AR-DEMO-0012 / 0019 / 0021 三笔）；其他模块入口（上游采购、车辆履约、下游销售、风控预警、申请详情等）提示“该入口尚未纳入原型。”。

## 主流程

O1 列表 → O5 详情 → O6 差异待核实 → O7 记录核实 → O8 核实已记录。

## 画面清单

| 页面 | 编号 | 画面 |
| --- | --- | --- |
| 应收账款列表 | O1 | 默认：每行一笔应收账款；覆盖到期 / 回款 / 核心资料三类状态的主要取值、多币种已收、未对应平台企业、各确权进度 |
|  | O2 | 暂无应收账款（空，不显示筛选条） |
|  | O3 | 筛选无结果（保留已填条件，可清除） |
|  | O4 | 列表读取失败（代表性异常，保留筛选条件，可重试） |
| 应收账款详情 | O5 | 默认：一致 · 未到期 · 部分收款 · 两份合同 · 确权申请进行中 |
|  | O6 | 差异待核实：核心资料差异明细、明细合计不一致、回款预警“有”，页头主操作「记录核实」 |
|  | O7 | 记录核实弹窗：必填说明与字数、依据文件格式提示、一个文件错误示例、提交后果 |
|  | O8 | 核实已记录：状态恢复一致，核实记录与资料补充记录各新增一条 |
|  | O9 | 资料未齐 · 未对应平台企业：到期日未确定，单价、附件、合同、未收金额缺失 |
|  | O10 | 款项与回款读取失败（局部失败，其余信息正常） |

详情按 PRD 指定顺序分两组：「应收账款资料」（应收账款信息含账期与到期 → 发票信息与附件 → 车辆信息明细 → 合同信息 → 款项与回款：回款统计 → 回款明细 → 债务人付款记录）、「处理进度」（资料进度、确权与审核进度、资料补充记录、核实记录、关联风控预警）。车辆明细中每个 VIN 带上游采购 / 车辆履约 / 下游销售入口。

未单独出屏（以 PRD 为准）：两名运营同时核实的冲突提示、核实提交失败、附件打开失败。本期不做见 PRD §1.2，原型未出现录入、编辑、补传、汇率折算与核验结论入口。

## 待确认

- **菜单名称**：运营端菜单沿用 M2 PRD 菜单表的「发票与应收」，与 M3 模块名「应收账款与发票」不一致；如需统一，请在 M2 PRD 与 `_shared/menu.ops.js` 一并修改。
- **确权与审核进度的环节名称**：由 M7a、M7b、M9 定义，尚未成稿；原型暂用演示名称（未申请、待债务人确认、待运营审核、债务人已驳回、审核通过）。
- **运营端时间的时区**：PRD 规定按 M1、M2 选择的时区、未提供时按 UTC；M2 未提供运营时区设置，原型按浏览器时区预览并在页头标注。

## 实际核验

2026-11-12 Chromium（Playwright）：10 个画面 × 中英文 × 1280 / 1440 / 1920，无脚本错误、无整页横向溢出；英文模式除演示账号名与演示输入内容外无未翻译文案。1280 宽时详情的「回款明细」「债务人付款记录」在表内横向滚动（≤ 80 px），1440 起完整展示。断网打开单文件附件，无外部请求，主流程、列表编号进入详情、页头主操作、Esc 关闭弹窗、面包屑返回列表均实测可用。未核验 1280 以下宽度与屏幕阅读器。
