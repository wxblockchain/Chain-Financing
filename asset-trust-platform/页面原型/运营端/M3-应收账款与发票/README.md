# M3 应收账款与发票 · 运营端原型

依据 [`PRD/两端共用/M3-应收账款与发票/`](../../../PRD/两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md)，最新需求提交 `5defb17`；申请状态名称与进度条环节按 M7a 应收查看与确权申请（WS-607，2026-11-12 PRD）。组件规范 v1.12。

原型只用于评审页面、字段和主流程；规则、校验及异常分支以 PRD 为准。企业、编号、金额、VIN、日期、银行账号和文件均为演示值；Carloha Holding / Carloha Nigeria 不代表实际业务主体。

## 打开与路径

双击 [`应收账款与发票.html`](应收账款与发票.html)，或使用离线单文件附件；无需服务。左侧菜单“资产数据 / 应收账款”进入列表。侧栏底部“画面目录 · 演示数据”默认收起，列出全部画面和“主流程下一屏”。

列表编号或右侧“查看”进入演示详情：AR-DEMO-0012 / 0019 / 0021 / 0008，其他演示行提示“演示仅提供部分应收账款的详情画面。”。申请编号、上游采购、车辆履约、下游销售和风控入口经[仓库联看](../../README.md#仓库联看)进入 M9 / M4 / M5 / M6 / M8 已有画面，未画出的记录给“演示仅提供部分…画面。”提示。

主流程：O1 列表 → O5 详情 → O6 差异待核实 → O7 记录核实 → O8 核实已记录。

## 详情结构

1. **应收账款概要**（页面最上方）：应收账款金额；债权人、债务人、账款起算日、天数、应收账款到期日（ERP 时区跟随日期）；右侧到期状态、回款状态、预警信息。核心资料状态不单独展示，差异明细在底部“资料追溯”。
2. **确权与审核进度**：紧接概要。发起申请 / 债务人确认 / 运营审核三环节，状态与环节对应按 M7a；申请编号旁显示申请状态。
3. 发票信息与附件 → 4. 车辆信息明细 → 5. 合同信息 → 6. 回款信息（先统计、后 ERP 收款明细）。
7. **资料追溯**（仅运营）：核心资料差异、资料补充记录、核实记录、关联风控预警。

预警信息为“有”的口径（未处理的 M8 预警含回款预警，或核心资料差异待核实）以 PRD 为准，原型只展示结果。

## 待确认与未覆盖

- “运营审核通过”只改变进度条文字（运营审核：通过），版式与其他进行中状态相同，未单独出屏。出库环节待 M9 定义后接入进度条。
- 跨模块真实入口、并发核实、提交失败等以 PRD 为准；未将静态页面当作真实服务。
- ERP 回款八列表格在 1440 px 以下宽度于表内横向滚动（沿用既有下限 1240 px）。

Chromium / Playwright，中英文 × 1280 / 1440 / 1920 px：11 屏无脚本错误、无整页横向溢出，英文模式无未翻译文案。离线附件断网无外部请求；主流程、列表进入 O11、菜单名称、弹窗 Esc 实测通过。M1（44 屏）、M2（87 屏）在两种语言、三档宽度回归加载、脚本错误与整页溢出；未重跑其业务流程。未验证 1280 px 以下、屏幕阅读器与真实服务。
