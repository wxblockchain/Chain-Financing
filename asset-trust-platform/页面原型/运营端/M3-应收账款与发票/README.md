# M3 应收账款（资产全景）· 运营端原型

依据 [`PRD/两端共用/M3-应收账款与发票/`](../../../PRD/两端共用/M3-应收账款与发票/01-应收账款与发票-PRD.md)，提交 `f3011833`（2026-11-25 WS-682：M9 收窄为运营审核后，M3 删除推送与调取相关规则——“运营审核通过”只展示申请状态；资料校验只在提交审核通过时再核对；收付日期晚于今天的回款同样暂计；资料校验（F-M3-15）、企业端移出等沿用 `80019d01`），运营端详情概要展示资料校验结果；企业端查看全部移出 M3，改由 M7a、M7b 定义；终端回款、物流节点等沿用 `7723476f`）。申请状态名称按 M7a，运营审核通过只展示申请状态；物流节点按 M5 原样展示当前节点。

## 详情结构

页头：债权人 → 债务人（首要信息），下一行应收账款编号与时区。

1. **概要**：应收账款金额（美元）；已收款金额（美元）、待收款金额（美元）、应收账款起算日、应收账款到期日（剩余天数）、账期；右侧四格：到期状态、回款状态、关联预警、确权申请结果（只展示申请状态，驳回 / 关闭时下方写原因，“运营审核通过”不附推送、存证或调取信息；申请编号进入 M9 申请详情；没有申请时为“未申请”）。概要底部为“资料校验”：通过（O5、O6、O8、O11）；不通过并按 PRD 校验项顺序列出问题项（O9、O12）；暂无法判断（O10，判断所需资料读取失败，不当作通过）。列表不新增列和筛选。
2. **进度与核对**：资产健康度四项并列，每项在百分数与读数条下列出数值依据——已收款 / 应收账款（美元）、已售 / 共（辆）、终端回款金额 / 应收账款（美元，注明“相对应收账款金额”；终端回款以外销合同为单位、每份只计一次，零售全额、批售按本发票车辆外销单价比例分摊，有比例低于 100% 的批售合同时注明）、应收账款保险金额 / 应收账款（美元）。比率条只表示读数，不按阈值变色。
3. **明细**：基础交易（内销发票：号、原币金额、日期、ERP 账款起算日 / 到期日、首次取得时间、附件；内销合同摘要）→ 车辆清单 → 回款记录 → 核心资料差异与核实（只在差异待核实或已有核实记录时出现）。

确权与审核的环节进度条已删除，完整进度在 M9 申请详情中查看。

车辆清单默认列为 VIN、物流节点、外采 / 内采 / 外销单价（美元）、外销收款金额（美元）；外采单价取外采合同单价时下方标“合同价”，批售外销合同的外销收款金额为整份合同的收款合计、下方标“合同合计”（同一批售合同的几辆车显示同一个合计）。展开后五组：内销；采购（外采合同号 · 外采供应商、外采交货日期）；运输与保险（初始提单号 · 装船日期，只列一张；保单号 · 车辆保险金额，多张保单全部列出）；外销（当前有效外销合同号 · 外销客户、外销出库日期、外销收款日期）；附件（提单、保单，只有附件名称，不展示取得时间）。

回款记录的金额是该笔内销收款分配到本发票的金额（原币 + 美元）。本笔有币种与应收账款不同的回款时（O9、O11），表格多出“计入金额”列：按收付日期当日最后时刻适用的 M11 汇率换算成应收账款原币，下方两行注明所用汇率与生效时间（生效时间按本人时区）；收付日期为今天或晚于今天（UTC+1）时金额旁标“暂计”，收付日期当日结束后按当日最后时刻的汇率确定；无法计入时为“-”并注明原因。币种相同的行该列留空。演示汇率取 M11 原型的汇率历史（1,538.60 生效于 2026-11-12、当前 1,540.20 生效于 2026-11-19）。交易流水号进入 M14 中这条回款对应的那一条收付记录：同号的 TRX-DEMO-1102 在 O5 / O10（INV-0012）进入 D5、在 O6 / O8（INV-0019）进入 D9；交易流水号未提供时显示“-”，仍可进入。

本模块不展示任何自行判定的风控提示，预警只承接 M8 的结果（PRD F-M3-14）；“待核实”是本模块的资料采信状态，不计入关联预警条数。比率、金额或日期取不到 / 算不出时以占位符“-”展示，读屏仍读出原文字；原因写在值下方。

## 与资产数据其他模块统一（WS-655，2026-11-23）

M3 是六模块（M3 / M4 / M5 / M12 / M13 / M14）统一口径的基准，列表原已符合，本轮只调整详情：

- **关联预警（O5、O6、O8–O12，O7 弹窗底层同 O6）**：概要右侧状态区的“预警信息 N 条”改为“关联预警”：第一行“未处理 N 条”（有未处理时为 warn 色链接，进入 M8 关联预警），第二行“已处理 M 条”；未处理为 0 时第一行不是链接；没有任何关联预警时为“无”。删除概要下方的“关联风控预警 未处理…、已处理… + 查看关联预警”横条，不再重复展示。
- **取不到 / 算不出统一为“-”**：EUR 样本的美元折算金额（概要、内销发票、内销合同、车辆清单内采单价、回款记录）、ERP 账款起算日 / 到期日“未提供”、外采收货日期“未提供”、内销合同号“未取得”、各处“附件未取得”、车辆清单物流节点“暂无履约记录”，均改为“-”占位，读屏读出原文字（2026-11-24 起外采交货日期、物流节点、外采单价的缺失改为业务状态文字，见下文 72ad4966 同步）。
- **列表（O1–O4）**：核对 L1–L6，无需改动——页头只有标题；单一查找框；列为编号、债权人 → 债务人、金额、到期日、应收账款状态、预警、操作；预警直接展示未处理条数，没有为“无”。
- **折算标记**：本模块没有成功折算的非美元金额（EUR 样本为“无法折算”），不涉及 `fx-mark`。
- 车辆清单外采单价单元格去掉与 M4“合同价 / 发票价”标签同名的 `price-basis` 类，避免被套上 M4 的胶囊边框；单价与“合同价”标签由 `.num .value-lines` 右对齐。

### 个性化说明

- **预警“待核实”**：只有核心资料差异待核实时，列表预警列显示“待核实”；详情 O6 在“关联预警”第一行保留“待核实”，下面照常列未处理 / 已处理条数。这是 M3 独有的核心资料核实流程，其他模块没有。
- **内销发票、内销合同附件跟在各自单据旁**（基础交易分区内），车辆清单展开行的“附件”组按单车列出提单、保单附件，不另设统一附件分区。
- **车辆清单展开行**：行首按钮展开内销、采购、运输与保险、外销、附件五组，“全部展开”同时展开全部车辆，结构不变。
- **保留的业务状态文字**：到期日“未确定”（对应应收账款状态“到期日未确定”，概要起算日写明“尚有 1 辆车未装船”）、暂无物流记录、未装船、未投保、暂无外采、未交货、未出库、未收款、暂无外销、暂无回款记录、未申请、待核实、无，属于业务状态，不改为“-”（PRD 缺失值的展示）。
- **“-”的原因**：保险覆盖率“-”下方注明“1 辆车在多张保单中”；其他“-”的原因在对应分区（如车辆清单读取失败）中说明。
