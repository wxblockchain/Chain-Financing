# M3 运营端 · UI 设计说明

2026-11-25 · WS-682 · existing-system adaptation · 桌面控制台。

执行基线为 `cly-v6.0.0` 的 `7ab0ff83`，已含 PRD `f3011833` 及原型同步 `fe850ef0`。本轮沿用现有三层结构、英文优先方向、画面目录和共享壳层，直接深化源码，不新增业务画面。

## 实际变化

- **列表**：金额使用正文栈和等宽数字，币种保持次要层级；表头允许按词换行，状态单行。企业名称使用共享 `name-clip` 首尾保留与 `value-pop` 全名浮层，点击或键盘 Enter 打开、Esc 关闭并回到触发按钮，完整名称保留在无障碍名称和 title 中。编号与查看沿用共享固定列。
- **概要**：金额／已收／待收与起算日／到期日／账期分层。≥1280 px 时左侧金融字段、右侧状态区；右侧到期与回款并排，预警和申请各占一行。窄于 1280 px 时状态区移到金额下方，保留全部信息。资料校验继续独立成带，保留通过、不通过及问题项、暂无法判断三类写法。
- **资产健康度**：四项比率仍完整保留，数值依据改为标签在上、金额或数量在下，使用 14 px 值；分组标题 20 px、记录标题 16 px。小于 1280 px 时四项按两列显示。比率条仍只表达读数，超过 100% 满格，不引入阈值或风险判定。
- **基础交易**：≥1440 px 时内销发票与内销合同摘要并排，组内默认两列；窄屏顺序堆叠，字段容器 ≥420 px 时两列、≥900 px 时三列。附件仍在各自单据旁，取得时间保持可见。
- **车辆**：保留默认列、逐车展开及全部展开，默认展开状态不变。展开内容为内销、采购、运输与保险、外销四组，附件单独横跨下一行；小于 1280 px 时业务组改为两列，附件仍可达。保留全部保单、原有缺失值原因和文件操作。
- **回款与核实**：回款当事方与汇率说明可换行，流水号和金额保留完整精度；暂计、1% 容差、批售分摊说明保留。O7 核对字段用浅底分组，说明输入区更易阅读，保留上传超限、提交后果与原有焦点行为。

实现仅在 `m3-ui.css`、`m3-presentation.js` 及源 HTML 的三个接入点。所有选择器限定 `data-module="ops-receivables"`，复用 `_shared/tokens.css`、`components.css`、`frame.js` 的数值、弹层、键盘和导航实现。状态区下限 300 px，其余排版沿用共享字号、间距与色彩；没有新增 token、复制共享层或改变共享运行逻辑。

## 实际核验

Chromium／Python Playwright，英文及中文，视口 1024×768、1280×900、1440×1000、1920×1080。14 个既有画面共 112 个默认组合，另检查运营车辆表全展开 48 个组合，共 160 个布局检查点：无脚本错误、整页横向溢出或非预期内容裁切；英文界面固定文案无中文残留（来源业务值、输入的核实说明不翻译）。1280 px 起表格完整显示；1024 px 的列表和部分车辆表只在表内横向滚动，表格区域可键盘聚焦。

另外实测列表 → O5、O6 → O7 → O8、更多筛选／Esc、车辆键盘展开、分区导航及焦点、核实弹窗焦点环绕与关闭返回；仓库联看中的车辆 M5、合同 M4、提单 M12、保单 M13、回款 M14、申请 M9、预警 M8 跳转；81／243 字符英文企业名在四种宽度下保留首尾省略，表宽不被名称撑大，完整名称可在浮层中查看。企业端 M7a／M7b 已分别在模块内承接详情，旧企业端 M3 `receivable:` 路由保持不存在，`debtorReceivable:` 过渡路由仍保留。

离线件由 `_shared/export.py` 从本次源页生成，双击可开；断网检查全部 12 屏 × 中英文（24 个组合）和完整名称、车辆展开、核实流程；1024 px 下横滚前后固定编号和查看操作均可达。跨模块跳转在单文件附件中沿用原有范围提示，请使用仓库联看验证。

未验证：真实 ERP／附件／服务、屏幕阅读器、其他浏览器及手机布局。原型筛选、上传、提交等仍是既有评审演示，不代表新增真实能力。Q-M3-03／11／12／14／15／16 沿用现行 PRD 的当前处理，本轮没有裁定业务事项。
