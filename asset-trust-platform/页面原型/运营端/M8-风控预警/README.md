# M8 风控预警 · 运营端原型

依据 [`PRD/运营端/M8-风控预警/`](../../../PRD/运营端/M8-风控预警/01-风控预警-PRD.md)，需求提交 `53371ee0`（2026-11-25：阻断类不人工处理、停用即关闭、风控规则目录 29 条）。组件规范 v1.63。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。预警编号、应收账款编号、单据号码、VIN、企业、金额、汇率、日期、处理说明、调整原因与文件均为演示值；Carloha Holding / Carloha Nigeria、Demo Auto Trading Ltd 等不代表实际业务主体。演示“今天”为 2026-12-14，与 M3 一致。界面语言随顶栏中英切换（M2 F-OP-10）；规则、等级、启用状态与风控参数的英文名称按 PRD 03 册[规则与等级的英文名称](../../../PRD/运营端/M8-风控预警/03-风控预警-消息通知.md#en-names)，其余英文未经审校。平台记录的时间按本人时区展示并标明时区：单文件打开时取浏览器时区，仓库联看中沿用跨模块带入的展示时区（可在 M2 账户设置中切换）；ERP 日期按原样展示，不换算。

## 打开与路径

双击 [`风控预警.html`](风控预警.html)，或使用离线单文件附件；无需服务。左侧菜单“风控”下依次为“风控预警”“风控规则”“三方数据源”（三方数据源入口按用户决定暂留，内容未改）。侧栏底部“画面目录 · 演示数据”默认收起，列出全部 35 屏和“主流程下一屏”。

- 主流程一（阻断自动解除，PRD 第 1 节示例）：L1 → D1 W-DEMO-0009 VIN 重复（阻断，正在阻止 AR-DEMO-0012、AR-DEMO-0020；没有“记录处理”）→ D2 差异已消除后平台自动结束（已自动解除，处理人“平台”），“风控预警”角标 7 → 6。
- 主流程二（记录处理，预警类）：L1 → D3 W-DEMO-0007 内销收款主体不一致 → “记录处理” P1 → P3（提交后不能修改或撤回）→ D4 已处理（核实无风险），角标 7 → 6。
- 主流程三（风控规则）：R1 → RK-16“调整等级” A1 → A3 确认（预警 → 阻断，列出受影响的申请与资产）→ R6 规则详情与配置记录；R1 → RK-26“停用” S1 → S2（将关闭本规则 1 条未处理预警）→ R7；被关闭的预警见 D8；R3 风控参数 → 截留等待天数“调整” Q1 → Q2 → R4。
- 列表：预警编号或“查看”进入详情（演示提供 W-DEMO-0009 / 0015 / 0011 / 0013 / 0007 / 0012 / 0010；共 11 条、每页 10 条，W-DEMO-0006 按排序在第 2 页，其详情 D7 从画面目录进入）；规则名或“查看”进入规则详情（演示提供 RK-01，另有 RK-16、RK-26 调整后的详情）；其余行提示仅提供部分画面。
- 应收账款、合同、VIN、提单、保单、交易流水号、企业编号等编号按[仓库联看](../../README.md#仓库联看)进入所属模块（已登记的编号）；未登记的编号提示“该入口尚未纳入原型。”。route.js 登记 `alert:` / `m8-` 预警详情、`alertsOf:AR-DEMO-0012`、`alertsOfRule:RK-01` 和 `rule:` 规则详情（M8-NT02 打开处）。

## 本期不做（按 PRD §1.2）

企业端没有任何风控预警、风控规则或三方数据源入口，本模块不出企业端画面；企业账号访问本模块页面按 M2 运营端菜单与无权访问（F-OP-11）处理，运营账号待首登改密或锁定时按 M2 运营账号状态处理，均由 M2 原型展示。资料缺失、到期日未确定、已到期、已收清、核心资料待核实属于平台限制，由 M3、M7a、M9 展示，本模块不出屏。不提供手动新建、修改、删除、合并预警，新增规则、修改判断条件、阻断类预警的人工处理、发起比对、导出、批量处理、指派，也不提供处理结果的修改、撤回或二次处理。阻断对运营审核与资产数字化平台调取的作用、审核说明是否必填由 M9 原型展示；站内消息 M8-NT01、M8-NT02 由 M10 承接；资产数据各模块的关联预警由各模块原型承接。
