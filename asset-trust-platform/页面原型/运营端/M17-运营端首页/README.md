## 设计与覆盖

一个页面，六个板块。默认画面 H1（`#home-default`）：

| 板块 | 本轮呈现 |
| --- | --- |
| 外采与外销总览 | 两张图表卡（2026-11-25 用户要求统一为图表）：数量卡（辆）与金额卡（USD）分开刻度；每卡按累计、当年度、本月分组，外采（主色）与外销（--chart-2）两条横条同一比例尺，数值与同比以文字常显；无法折算、合同价及同比未计入的注明紧跟对应横条；数量卡下方为供应商与终端客户（家，累计）横条 |
| 月度趋势 | 四个指标各一图，月度值为柱、环比为折线且右轴独立；固定近 12 月，本月标截至今日；缺值断线、无法折算不当作 0；每图可展开完整数值表 |
| 业务周期 | 平均、最长、最短；七档横向柱状分布，明确缺少交货日期的排除数量 |
| 总体盈利 | 总体、最高、最低；七档售车分布，亏损文字与图形同时表达，保留仅比较车价和合同价披露 |
| 应收账款 | 发生额、余额、约定及实际账期；发生额柱状、月末余额折线，同一美元刻度；附完整月度表 |
| 账款逾期 | 两项历史汇总，九列逐笔列表，逾期中排前；应收编号固定左侧，其他字段横向可达 |

首页画布只保留标题、数据更新时间与刷新，进入即为图表（2026-11-25 用户要求）：去掉了业务范围副标题、统计日与汇率说明、演示数据标签及各板块的口径说明（同比口径、环比读法、账期加权、逾期金额含义、“只比较车价”等），这些口径以 PRD 为准。PRD 要求随数值注明的内容保留：无法折算、合同价、缺少外采交货日期未计入、同比“上年同期为 0”、截至今日。演示数据标识在画面目录入口与本说明中。

使用现有 token，不新建配色或字体体系。`.home-*` 规则位于共享 `components.css` 的 M17 专节；仅首页消费。1250 px 以下趋势与分布改单列；小屏密集表格、12 月图表区域内滚动，不压缩金额与日期。数值表用原生 details/summary，支持键盘展开；金额保留两位小数、天数精度及同比精度按样本原值；图中 k 标签为准确简写，完整金额在数值表中可达。

继承未改：其他模块页面内容、账号、消息预览与语言/时区组件。首页入口对共享层与 M2 的改动见下文“首页入口”。

## 画面清单

侧栏底部「画面目录 · 演示数据」默认关闭，展开后可到达下列全部画面并给出“主流程下一屏”。

| 编号 | 画面 id | 画面 | 到达方式 | 主流程下一屏 |
| --- | --- | --- | --- | --- |
| H1 | `home-default` | 默认（标准样本） | 菜单“首页”；登录后无原目标 | 刷新 → L4 |
| H2 | `home-empty` | 暂无资料（全部为 0） | 画面目录 | — |
| L1 | `home-loading` | 首次加载中 | 画面目录；L2 重试 | H1 |
| L2 | `home-fail` | 首页加载失败 | 画面目录 | 重试 → L1 |
| L3 | `home-cycle-fail` | 单个板块加载失败（业务周期，AC-M17-04 场景 1） | 画面目录 | 板块内重试 → H1 |
| L4 | `home-refreshing` | 刷新中（保留当前数据） | H1、L5、L6 点“刷新” | L5 |
| L5 | `home-refreshed` | 刷新完成（数据更新时间更新） | L4 下一屏 | — |
| L6 | `home-refresh-fail` | 刷新失败（保留上次数据） | 画面目录 | 刷新 → L4 |

画面要点（规则生效后的结果，口径见 PRD 3.4、3.5、6.1、7–11）：

- 加载中：刷新不可用；六个板块保留标题、内容位为加载中，不出现 0、0.00 USD 或 0.00%。
- 整页失败：只保留页头与失败提示和“重试”，不显示数据更新时间与任何数字。
- 单板块失败：仅该板块提示失败并可重试，其他五个板块正常；其余板块失败为同一呈现，未逐一出屏。
- 刷新中：按钮显示“刷新中”且不可用，页面数字与数据更新时间保持不变。刷新完成后只更新数据更新时间（演示为 10:25 → 10:40 UTC）。
- 刷新失败：保留上次数字，页头下方提示“数据更新失败，当前显示 {数据更新时间}（时区）的数据”，可再次刷新。
- 暂无资料：总览横条为空轨道，数量为 0、金额为 0.00 USD；同比为“-”并注明“上年同期为 0”；环比全部为“-”，曲线不画；平均周期、盈利水平、约定／实际账期为“-”，分档均为 0；月末余额为 0 照常连线；逾期 0 次、0.00 USD，列表显示“暂无逾期记录”。
- 缺失值统一按 PRD 显示“-”；负数仍用减号“−”（如 −10.00%）。

源文件维护方式：只维护 H1。其余画面用 `data-from="home-default"` 加 `<template data-replace|data-body="板块">` 声明与 H1 的差异，页尾脚本在启动前复制 H1 并替换对应板块（`data-part`：actions、meta、context、overview、trend、analysis、cycle、profit、ar、overdue）。脚本只拼装静态画面，不计算、不请求、不计时；H1 后续视觉调整会自动带到各状态画面。

## 首页入口（Q-M17-01，待确认）

按 M17 PRD Q-M17-01 推荐口径接入仓库联看：

- `_shared/menu.ops.js`：“首页”位于全部菜单之前，不属于任何分组；`frame.js` 新增 home 图标，分组名为空时不显示分组标题。运营端所有模块的侧栏随之出现“首页”。
- `route.js` 登记 `home → home-default`，`_shared/modules.js` 追加本模块；`navigation.js` 中“运营管理员”的进入点改为首页。
- M2 中没有原目标的 7 个登录画面（login、login-service、login-changed、login-recovered、login-expired、login-idle、login-out），点“登录”在仓库联看中进入首页；有原目标的 `login-target → d-active` 不变。M2 单模块附件不含首页，仍落在企业管理。

M2 PRD F-OP-11 菜单表仍写“运营端首页尚未规划，本表不登记首页菜单”，AC-OP-21 仍为“没有首页菜单”。M2 正文与验收同步前，以上入口按“待确认”处理；如用户否决推荐，回退菜单项、`route.js` 与模块清单、`navigation.js` 进入点和 M2 登录按钮即可，H1–L6 画面不受影响。

访问约束沿用 M2：锁定中、待首登改密的账号与企业账号到不了首页（M2 已有对应画面），本模块不另出屏；`data-who="ops"` 只是展示身份，不代表鉴权已实现。
