# M6 下游销售与收款追溯 · 运营端原型

依据 [`PRD/运营端/M6-下游销售与收款追溯/`](../../../PRD/运营端/M6-下游销售与收款追溯/01-下游销售与收款追溯-PRD.md)，PRD 提交 `320388d`（2026-11-12 需求评审稿）。既有系统适配（桌面 Web），先读取本平台[组件规范](../../_shared/design-system/组件规范.md)并沿用 M3 列表、M4 追溯与详情、M5 筛选条组件；本平台已有组件覆盖全部需要，未另行引入代币发行平台组件。组件规范更新至 v1.16。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。企业、客户、客户号、单据编号、金额、VIN、日期、银行账号和文件均为演示值；Carloha Holding / Carloha Nigeria、Demo Lagos Motors Ltd. 等不代表实际业务主体。应收账款编号、VIN 与车型沿用 M3 原型的演示数据。

## 打开与路径

双击 [`下游销售与收款追溯.html`](下游销售与收款追溯.html)，或使用离线单文件附件；无需服务。左侧菜单“资产数据 / 下游销售”进入列表。侧栏底部“画面目录 · 演示数据”默认收起，列出全部画面和“主流程下一屏”。

- 主流程（PRD 示例）：S1 列表 → S5 按 VIN 查找 → “查看追溯”进入 T1 → 点 SC-DEMO-2045 进入 D2（对照应收账款）→ “返回车辆追溯”。
- 列表销售合同编号或右侧“查看”进入详情（演示提供 SC-DEMO-2045 / 2048 / 2060，其余行提示仅提供部分销售交易）；面包屑“下游销售”返回列表。
- M3 应收账款详情、M5 车辆履约、M8 风控预警等跨模块入口经[仓库联看](../../README.md#仓库联看)跳转，未画出的记录给“演示仅提供部分…画面。”提示。

归属结果、收款状态与收款情况为只读标签，不设认定或处理入口；全模块无新增、编辑、删除、补传入口。

## 未单独出屏（以 PRD 为准）

- 企业端：PRD 规定债权人、债务人都没有下游销售入口，本模块只做运营端；企业用户通过链接访问时的“该内容不存在或无权查看”沿用平台无权限画面。
- 按 VIN 查找时该 VIN 出现在多笔应收账款、VIN 既不在应收账款也不在销售交易中（“未找到该 VIN 的下游销售资料”）、附件打开失败、整页详情加载失败、关联应收账款部分加载失败：PRD 已定义文案，原型未逐一出屏。
- 从 M8 / M9 进入后的返回位置：仓库联看用浏览器返回；不另画来源相关的返回按钮。
- 本期不做（PRD §1.2）：交付 / 签收 / 退车等交付事件、退款与冲销、录入或补传资料、客户入驻与确权、客户个人信息、汇率折算、金额拆分到单车、人工认定归属。

## 待 PRD 确认

- 没有发票、也无法从车辆价格得到币种时（D4），PRD 要求“已开票金额 / 累计已收展示 0”，与“任何位置都不展示没有币种的金额”冲突。原型暂按前者展示不带币种的“0”，请 PRD 明确此时的币种来源或展示方式。

## 实际核验

Chromium / Playwright，中英文 × 1280 / 1440 / 1920 px，视口高 1000 px，源文件与离线单文件：

- 全部 16 屏加载无脚本错误、无整页横向溢出、侧栏不遮挡内容、按钮与标签无截断、表格操作列可见；英文模式下除 ERP 原值与共享演示账号名外无残留中文。
- 主流程与交互逐项点击通过：列表编号进入详情、面包屑返回、“查看”进入 D3、画面目录主流程下一屏、S5“查看追溯”→ T1、T1“查看”→ D2、D2“返回车辆追溯”、详情分区导航定位、更多筛选展开与 Esc 收起、未出屏行的提示。
- 1280 px 列表在表内滚动，编号与“查看”固定可见；收款明细九列不足阅读宽度时在表内滚动。
- 离线单文件断网打开无 HTTP 请求。
- 共享层：M3 两端、M4、M5 在中英文 × 1280 / 1920 px 与改动前逐像素比较，剩余差异在未改动版本自身重复截图时同样出现（亚像素抖动），视觉无变化；未重跑其完整业务流程。

未验证 1280 px 以下、屏幕阅读器、完整无障碍符合性，以及真实 ERP 取数、附件下载和跨模块跳转。
