# M5 车辆物流与履约追溯 · 运营端原型

依据 [`PRD/运营端/M5-车辆物流与履约追溯/`](../../../PRD/运营端/M5-车辆物流与履约追溯/01-车辆物流与履约追溯-PRD.md)，需求提交 `56af212`（2026-11-12 需求评审稿）。组件规范 v1.14。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。企业、VIN、单据号码、集装箱号、金额、日期、客户、仓库和文件均为演示值；Carloha Holding / Carloha Nigeria 不代表实际业务主体。ERP 原值（事件类型、质检结果、费用类型等）在英文界面不翻译。

## 打开与路径

双击 [`车辆物流与履约追溯.html`](车辆物流与履约追溯.html)，或使用离线单文件附件；无需服务。左侧菜单“资产数据 / 车辆履约”进入列表。侧栏底部“画面目录 · 演示数据”默认收起，列出全部画面和“主流程下一屏”。

- 列表：VIN 或右侧“查看”进入详情（演示提供 …001 / …011 / …015 / …021，其余行提示仅提供部分车辆）。
- 从应收账款（M3）、上游采购（M4）、下游销售（M6）进入的追溯总览 T1 / T2，只能从画面目录打开；返回 M3 / M4 / M6、进入 M4 / M6 / M8 以及应收账款编号经[仓库联看](../../README.md#仓库联看)跳转，未画出的记录给“演示仅提供部分…画面。”提示。
- 主流程（PRD 示例）：T1 应收账款车辆总览（定位 …002）→ D1 车辆履约详情 → “返回履约总览”。列表流程：V1 → D2 → D3。

## 详情结构

页头 VIN（返回、上游采购、下游销售）→ 概要（车型 / 异常事件 / 核对提示；有提示时底部逐条可定位）→ 分区导航 → 车辆与关联应收账款 → 履约进度（五环节）→ 装船运输与提单（每张提单可展开“本批次车辆与集装箱”：本批车辆、每个集装箱的车辆、本批保单 / 费用 / 清关）→ 保险（先关联信息、后保单信息；保险金额标覆盖车辆数）→ 清关（本车集装箱号标“本车”；另列船名航次不一致的记录）→ 履约费用（覆盖范围按提单或合同）→ 组装与质检 → 入库与出库交付 → 车辆异常事件 → 关联风控预警（资料按 ERP 最新内容展示，不提供补充记录，PRD 94ccac6）。

## 本期不做（按 PRD §1.2）

企业端（债权人、债务人）不提供任何车辆履约入口，本模块不出企业端画面；企业用户通过链接访问的统一提示以 PRD §3.3 为准。不提供录入、编辑、补传、调度、审批、借还或退车办理入口；不分摊保险或费用，不做汇率折算；资产数据出库归 M9。

## 待确认与未覆盖

- 按 VIN 查找未找到（PRD §7.2）、带入对象已不存在（§17.2）、附件打开失败、列表分页切换等以 PRD 为准，未单独出屏。
- 追溯总览的“空”不成立（应收账款必有销售清单车辆），未出屏；其加载失败沿用列表 V4 的表现。
