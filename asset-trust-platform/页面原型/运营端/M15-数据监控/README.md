# M15 数据监控 · 运营端原型

依据 [`PRD/运营端/M15-数据监控/`](../../../PRD/运营端/M15-数据监控/01-数据监控-PRD.md)（2026-11-25 需求评审稿，提交 `512d31c4`，WS-681，含用户 2026-11-25 两轮裁定；首版 `b693d078`，WS-610）。内容不存在或无权查看按 [M2 F-OP-11](../../../PRD/运营端/M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-11)，缺失值按 M3 以“-”展示。组件规范 v1.65。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。接口清单、调用次数、未接收条数、金额、时间均为演示值；图表是静态画面，不做统计、刷新或筛选。时间按本人时区展示并标明时区。

## 本版要点

- 数据推送只展示发生过推送的资产：从未被调取的资产不在列表中；推送结果只有成功 / 失败（成功后再失败仍为成功，那次失败只记在详情）。列表默认失败在前；平台情况为“最近一次推送时间”（从未发生为“暂无推送”）。
- 推送详情：资产概要 → 推送情况（最近一次推送时间、成功 / 失败次数）→ 推送记录（目标平台、推送方式、推送时间、结果，不含失败原因）。推送方式本期均为“被调取”（主动推送是否本期提供待确认，Q-M15-07）。
- 操作上下布局：列表行操作纵向排列、右对齐（本期只有“查看”）；详情各部分自上而下，不用页签。用户尚未补充具体含义，暂按此理解。
- 数据接入不展示取得条数：调用记录去掉取得条数列，概览去掉未接收率，“每日取得与未接收”改为“每日未接收趋势”。
- 数据接入有“数据来源”（本期均为客户 ERP）：列表一列 + 筛选、调用记录概要一项；失败排行注明来源，数据新鲜度表有来源列，新增来源后沿用。
- 缺失值统一为“-”（读屏读出原因），如比率无法计算；暂无调用、从未成功、暂无推送等业务状态仍为文字。

## 打开与路径

双击 [`数据监控.html`](数据监控.html)，或从仓库 [`index.html`](../../index.html) 以运营端进入“数据监控”。侧栏底部「画面目录 · 演示数据」默认关闭，可到达全部 23 屏。

- 概览 → 接入：V1 点“异常 1 个接口”→ I2 接口列表（筛选异常）→ C1 提单调用记录。
- 概览 → 推送：V1 点“失败”→ P2 资产列表（筛选失败）→ PR2 推送详情（AP-DEMO-0024，推送失败）。
- 大屏：V1 页头“大屏”→ S1；“退出大屏”回到概览。
- 申请编号经仓库联看进入 M9 申请详情；未接收单据中已在平台的提单号进入 M12。

## 待确认与本期不做

- 待确认（按当前正文画，不写成已确认）：大屏刷新间隔（Q-M15-02，按推荐每 1 分钟标注）；大屏登录时长（Q-M15-03，沿用 M2，不在画面中体现）；M9 中与本模块的分工待同步（Q-M15-06）；本平台主动推送是否本期提供（Q-M15-07，推送方式本期只出现“被调取”）；“上下布局”的具体含义（用户尚未补充）。
- 按 PRD 本期不做：取得条数、推送条件与失败原因、“待推送”、存证状态与重新存证（属 M9）、运营人员手动推送、逐条单据异常处理、“长时间无数据”自动判断、手动重新取数与接口配置、主动推送、外部跟踪数据与三方数据源的接入监控（后续作为新数据来源加入）、企业端查看。
- 未单独出屏：自定义时间范围的日期选择、大屏登录失效、推送详情读取失败；以 PRD 为准。
- 告警 M15-NT01 未加入 M10 演示消息：加入会改变 M10 已评审画面中的未读数与条数，需 M10 负责人一并调整。
- M9 联动：M9 画面仍有未发生推送资产的“查看完整推送记录”（如存证失败的 AP-DEMO-0022，本模块不登记，点击为兜底提示）和 `push:1` 演示角标，随 M9 同步时处理。
