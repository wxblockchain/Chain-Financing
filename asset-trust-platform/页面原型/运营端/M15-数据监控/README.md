# M15 数据监控 · 运营端原型

依据 [`PRD/运营端/M15-数据监控/`](../../../PRD/运营端/M15-数据监控/01-数据监控-PRD.md)（2026-11-27 需求评审稿，提交 `29eddd9f`，WS-681，含用户 2026-11-25、11-26 裁定与 U-M15-01、02（按 PRD 推荐）与 Eval 口径 Q-EV-M15-01～10；首版 `b693d078`，WS-610），本轮按用户 11-26 追加裁定调整列表原因展示与概览分区定位。内容不存在或无权查看按 [M2 F-OP-11](../../../PRD/运营端/M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-11)，缺失值按 M3 以“-”展示。共享 A43、A83–A87 为基线，M15 模块视觉变体见 [UI设计说明](UI设计说明.md)。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。接口清单、调用次数、取得条数、金额、时间均为演示值；图表是静态画面，不做统计、刷新或筛选。时间按本人时区展示并标明时区。

## 本版要点

- 数据推送只展示与其他平台发生过交互的资产（不区分对方调取还是本平台推送）：从未交互的资产不在列表中；推送结果只有成功 / 失败（成功后再失败仍为成功，那次失败只记在详情）。列表默认失败在前；平台情况为“最近一次推送时间”（从未发生为“暂无推送”）。
- 推送详情：资产概要 → 推送情况（最近一次推送时间、成功 / 失败次数）→ 推送记录（目标平台、推送时间、结果，不含失败原因）。
- 详情各分区上下排列，当前呈现为全部展开；列表行操作方式由设计决定，本期只有“查看”。“上下、不左右”的约束已写入 PRD `362988db`，不再列为待确认。
- 监控概览 V1–V3 在更新时间下方提供“数据接入／数据推送”定位标签，点击或 Enter 在当前概览内滚动定位，标签吸顶并随滚动高亮；全部指标仍连续展示，不切换画面、不新增跨模块跳转。大屏不增加这组导航。
- 数据接入（U-M15-01、02）：调用记录展示“取得条数”（成功时显示条数，返回不了条数时为“-”并注明“未返回条数”，失败时不显示），不再展示未接收条数、原因摘要与单据号，也没有“是否有未接收”筛选；接口列表去掉“今日调用”；概览“每日未接收趋势”改为“每日取得条数”。数据推送的推送结果分布只显示成功、失败笔数，不再有美元金额合计。
- 数据接入有“数据来源”（本期均为客户 ERP）：列表一列 + 筛选、调用记录概要一项；失败排行注明来源，数据新鲜度表有来源列，新增来源后沿用。
- 缺失值统一为“-”（比率无法计算时读屏读出原因；未返回失败原因写在“-”下方），暂无调用、从未成功、暂无推送等业务状态仍为文字。
- 接口列表 I1／I2 不展示失败原因，只展示最近调用时间与结果；从“查看”进入调用记录详情后查看原原因。详情原因中的账号、密钥继续遮盖，接口地址照常展示（提单 11-24 失败样本）；同一次进入异常的告警消息（共享 `inbox.js` 的 o08）去掉接口地址，账号、密钥同样遮盖。
- 从接口失败排行点“提单”进入 C2：带上概览的时间范围（近 7 天）与“调用结果 · 失败”，共 9 条，与排行一致；其他排行项为演示提示。
- 数据新鲜度：外销合同、清关单都“从未成功”，按接口清单顺序排在最前。
- 按首次推送时间筛选（P3）时失败的资产不在结果中；从未交互（AP-DEMO-0027）或未审核通过（AP-DEMO-0022）的资产经链接打开推送详情时进入 PR4 兜底屏。

## 打开与路径

双击 [`数据监控.html`](数据监控.html)，或从仓库 [`index.html`](../../index.html) 以运营端进入“数据监控”。侧栏底部「画面目录 · 演示数据」默认关闭，可到达全部 25 屏。

- 概览 → 接入：V1 点“异常 1 个接口”→ I2 接口列表（筛选异常）→ C1 提单调用记录；V1 接口失败排行点“提单”→ C2（近 7 天 · 失败，9 条）。
- 概览 → 推送：V1 点“失败”→ P2 资产列表（筛选失败）→ PR2 推送详情（AP-DEMO-0024，推送失败）。
- 大屏：V1 页头“大屏”→ S1；“退出大屏”回到概览。
- 申请编号经仓库联看进入 M9 申请详情。

## 待确认与本期不做

- 已定：大屏每 1 分钟自动刷新；大屏不另设登录时长，沿用 M2（不在画面中体现）；详情上下布局已按 PRD `362988db` 明确。
- 用户已按 PRD 推荐裁定 U-M15-01（恢复取得条数）、U-M15-02（删 B 今日调用、D 未接收、E 中的每日未接收趋势与美元金额合计；A、C、F、G 保留），本轮已同步。
- 按 PRD 本期不做：单据级接收结果（未接收单据与原因）、推送条件与失败原因、“待推送”、上链状态与重新提交（属 M9 运营审核）、交互方式的区分（不在本模块定义）、运营人员手动推送、逐条单据异常处理、“长时间无数据”自动判断、手动重新取数与接口配置、外部跟踪数据与三方数据源的接入监控（后续作为新数据来源加入）、企业端查看。主动推送或调取的方式与成功条件由对外提供功能定义，M15 不裁定。
- 未单独出屏：自定义时间范围的日期选择、大屏登录失效、推送详情读取失败；以 PRD 为准。
- 告警 M15-NT01 演示消息在共享 `inbox.js`（M10 消息中心展示）：本轮只改正文与接口名称（客户 ERP 接口、与本模块演示清单一致、失败原因遮盖），条数与未读数不变。
- M9 联动：当前远程 M9 原型已同步运营审核，旧“查看完整推送记录”入口与 `push:1` 演示角标已移除。本模块 `pushRecord:` 路由用于直接链接：已交互资产进入详情，AP-DEMO-0027 / 0022 进入兜底屏。

## 实际核验

PRD `29eddd9f` 同步后（基于 hallmark-GPT `82f78ad7` 的 UI 版本），源码与离线附件以 Chromium / Playwright 检查：各 25 屏 × 中英文 × 1024 / 1280 / 1440 / 1920 px，无脚本错误、整页横向溢出、操作列越界；英文无界面中文残留。调用记录四列在 1280 px 完整展示；V1 定位标签、失败排行“提单”→ C2、“失败”→ P2 → PR2 点击实测。UI 视觉变体与此前核验范围见 [UI设计说明](UI设计说明.md#coverage-与核验)（其中调用记录五列的描述已由本轮四列替代）。离线单文件由 `_shared/export.py` 从源码生成。未验证：1024 px 以下、屏幕阅读器、其他浏览器、真实接口与对外交互服务。
