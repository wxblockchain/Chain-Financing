# M15 数据监控 · 运营端原型

依据 [`PRD/运营端/M15-数据监控/`](../../../PRD/运营端/M15-数据监控/01-数据监控-PRD.md)（2026-11-26 需求评审稿，提交 `dcb9f2cd`，WS-681，含用户 2026-11-25 裁定与 Eval 口径 Q-EV-M15-01～07；首版 `b693d078`，WS-610）。内容不存在或无权查看按 [M2 F-OP-11](../../../PRD/运营端/M2-运营登录与企业管理/01-运营登录与企业管理-PRD.md#F-OP-11)，缺失值按 M3 以“-”展示。共享 A43、A83–A87 为基线，本轮 M15 模块视觉变体见 [UI设计说明](UI设计说明.md)。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。接口清单、调用次数、未接收条数、金额、时间均为演示值；图表是静态画面，不做统计、刷新或筛选。时间按本人时区展示并标明时区。

## 本版要点

- 数据推送只展示与其他平台发生过交互的资产（不区分对方调取还是本平台推送）：从未交互的资产不在列表中；推送结果只有成功 / 失败（成功后再失败仍为成功，那次失败只记在详情）。列表默认失败在前；平台情况为“最近一次推送时间”（从未发生为“暂无推送”）。
- 推送详情：资产概要 → 推送情况（最近一次推送时间、成功 / 失败次数）→ 推送记录（目标平台、推送时间、结果，不含失败原因）。
- 操作上下布局：列表行操作纵向排列、右对齐（本期只有“查看”）；详情各部分自上而下，不用页签。用户尚未补充具体含义，暂按此理解，补充后再调整。
- 数据接入不展示取得条数：调用记录去掉取得条数列，概览去掉未接收率，“每日取得与未接收”改为“每日未接收趋势”。
- 数据接入有“数据来源”（本期均为客户 ERP）：列表一列 + 筛选、调用记录概要一项；失败排行注明来源，数据新鲜度表有来源列，新增来源后沿用。
- 缺失值统一为“-”（比率无法计算时读屏读出原因；未返回失败原因写在“-”下方），暂无调用、从未成功、暂无推送等业务状态仍为文字。
- 失败原因中的账号、密钥只展示遮盖后的内容，接口地址在页面上照常展示（提单 11-24 失败样本）；同一次进入异常的告警消息（共享 `inbox.js` 的 o08）去掉接口地址，账号、密钥同样遮盖。
- 从接口失败排行点“提单”进入 C2：带上概览的时间范围（近 7 天）与“调用结果 · 失败”，共 9 条，与排行一致；其他排行项为演示提示。
- 数据新鲜度：外销合同、清关单都“从未成功”，按接口清单顺序排在最前。
- 按首次推送时间筛选（P3）时失败的资产不在结果中；从未交互（AP-DEMO-0027）或未审核通过（AP-DEMO-0022）的资产经链接打开推送详情时进入 PR4 兜底屏。

## 打开与路径

双击 [`数据监控.html`](数据监控.html)，或从仓库 [`index.html`](../../index.html) 以运营端进入“数据监控”。侧栏底部「画面目录 · 演示数据」默认关闭，可到达全部 25 屏。

- 概览 → 接入：V1 点“异常 1 个接口”→ I2 接口列表（筛选异常）→ C1 提单调用记录；V1 接口失败排行点“提单”→ C2（近 7 天 · 失败，9 条）。
- 概览 → 推送：V1 点“失败”→ P2 资产列表（筛选失败）→ PR2 推送详情（AP-DEMO-0024，推送失败）。
- 大屏：V1 页头“大屏”→ S1；“退出大屏”回到概览。
- 申请编号经仓库联看进入 M9 申请详情；未接收单据中已在平台的提单号进入 M12。

## 待确认与本期不做

- 已定：大屏每 1 分钟自动刷新；大屏不另设登录时长，沿用 M2（不在画面中体现）。“上下布局”的具体含义用户尚未补充，暂按上文理解。
- PRD 输出提交用户决定、本轮未画：是否恢复“取得条数”（决定 1）；A–G 各项去留（决定 2，如今日调用、未接收、美元金额合计）。用户确认、PRD 修订后再同步。
- 按 PRD 本期不做：取得条数、推送条件与失败原因、“待推送”、上链状态与重新提交（属 M9 运营审核）、交互方式的区分（不在本模块定义）、运营人员手动推送、逐条单据异常处理、“长时间无数据”自动判断、手动重新取数与接口配置、外部跟踪数据与三方数据源的接入监控（后续作为新数据来源加入）、企业端查看。主动推送或调取的方式与成功条件由对外提供功能定义，M15 不裁定。
- 未单独出屏：自定义时间范围的日期选择、大屏登录失效、推送详情读取失败；以 PRD 为准。
- 告警 M15-NT01 演示消息在共享 `inbox.js`（M10 消息中心展示）：本轮只改正文与接口名称（客户 ERP 接口、与本模块演示清单一致、失败原因遮盖），条数与未读数不变。
- M9 联动：当前远程 M9 原型已同步运营审核，旧“查看完整推送记录”入口与 `push:1` 演示角标已移除。本模块 `pushRecord:` 路由用于直接链接：已交互资产进入详情，AP-DEMO-0027 / 0022 进入兜底屏。

## 实际核验

PRD `dcb9f2cd` 同步后，源码与离线附件以 Chromium / Playwright 检查：各 25 屏 × 中英文 × 1024 / 1280 / 1440 / 1920 px，无脚本错误、整页横向溢出、操作列越界；英文无界面中文残留。失败原因长原值（含接口地址）在列内换行。V1 失败排行“提单”→ C2（9 条）、V1“失败”→ P2 → PR2 点击实测；M10 消息中心中 o08 正文不含接口地址、账号与密钥为遮盖值。UI 视觉变体与此前核验范围见 [UI设计说明](UI设计说明.md#coverage-与核验)。离线单文件由 `_shared/export.py` 从源码生成。未验证：1024 px 以下、屏幕阅读器、其他浏览器、真实接口与对外交互服务。
