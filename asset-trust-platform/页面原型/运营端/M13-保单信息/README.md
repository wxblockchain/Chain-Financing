# M13 保单信息 · 运营端原型

依据 [`PRD/运营端/M13-保单信息/`](../../../PRD/运营端/M13-保单信息/01-保单信息-PRD.md)，PRD 提交 `9350dde2`（2026-11-20 按 WS-655 确认口径修订）。属于既有系统适配（桌面 Web）：先读取本平台[组件规范](../../_shared/design-system/组件规范.md)与[列表与详情规范](../../_shared/design-system/列表与详情规范.md)，列表沿用 A14 固定列骨架，详情沿用 A18 / A24 版式，筛选条、分区导航、提示、区块状态、文件引用、分页均为既有组件；只为保障核对四项指标和本模块列宽新增 A70–A71（组件规范 v1.35）。2026-11-23 按 WS-655 与资产数据其他模块统一呈现（见下文“与资产数据其他模块统一”）。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。保险公司、企业、保单号、提单号、VIN、金额、汇率与文件均为演示值；PL-DEMO-889 关联的 BL-DEMO-5501 及其 3 辆车与单车金额与 M12 提单信息原型一致（其中一辆为 NGN 单价折算）；汇率沿用 M11 原型当前汇率（1 USD = 1,540.20 NGN，生效时间 2026-11-19 02:15 UTC）。保险金额等保单数据为本模块演示值，不再沿用旧版 M5 中的数值。

## 打开与路径

双击 [`保单信息.html`](保单信息.html)，或使用离线单文件附件；无需服务。左侧菜单“资产数据 / 保单信息”进入列表。侧栏底部“画面目录 · 演示数据”默认收起，列出全部画面和“主流程下一屏”。

- 主流程：L1 列表 → 点 PL-DEMO-889 进入 D1 详情 → 面包屑“保单信息”返回列表。
- 列表保单号或右侧“查看”进入详情（演示提供 PL-DEMO-921 / 903 / 889 / 862，其余行提示仅提供部分保单）。
- 详情中的 VIN 进入车辆履约（`vehicle:`）、提单号进入提单信息（`bl:`，M12 已画出 BL-DEMO-5501）、列表预警条数与详情“未处理 N 条”进入风控预警，经[仓库联看](../../README.md#仓库联看)跳转；未画出的记录提示“该入口尚未纳入原型。”。其他模块可用 `policy:<保单号>` 进入本模块已画出的详情，M12 关联保单中的 PL-DEMO-889 已可进入 D1。

## 与资产数据其他模块统一（WS-655，2026-11-23）

按 WS-655 统一口径（基准 M3 应收账款、M4 合同信息），同类信息与 M3、M4、M5、M12、M14 同样呈现：

- 列表页头只有页标题，删去说明句。
- 列表查找：去掉“查找方式”下拉，改为单一查找框，占位“保单号、提单号或 VIN”；L3 查找无结果、L5 按 VIN 查找保留已填内容。
- 列表当事方：原“保险公司”“被保险人”两列合为“保险公司 → 被保险人”，每行“角色短名 + 名称”（同 M3 应收账款列表），方向与详情页头一致。
- 列表只放识别、当事方、金额、日期和预警：删去“保险货值（美元）”“保险覆盖率”两列，“关联提单／车辆”只留张数 / 辆数，删去“含 1 张提单未审核”等原因；这些值与原因在详情“保障核对”、关联提单中照常展示。列表由十列减为七列，表宽下限随之收窄。
- 预警列直接展示未处理条数（warn 色，可进入风控预警），没有时为“无”。
- 详情页头：“保险公司 X → 被保险人 Y”，说明行“保单号 PL-… · 时区 UTC”；概要不再重复保险公司、被保险人，保留投保人、保单日期；主金额带币种旗标。
- 关联预警：概要右侧单项“关联预警”，有未处理时“未处理 N 条”为链接、下方“已处理 M 条”；没有任何关联预警时为“无”（原“无关联预警”）。
- 详情分层：概要 →“进度与核对”（保障核对）→“明细”（车辆清单、关联提单、附件），写法同 M3 应收账款详情。
- 取不到或算不出的值（保险货值、保险覆盖率、车辆保险金额、覆盖车辆，未审核提单的装船日期与车辆数）用“-”占位，读屏保留原文字；原因（“1 辆车未开票 · 1 张关联提单未审核”“无覆盖车辆”）照旧写在值下方。
- 折算：原“折算 ⌄”下拉改为 `fx-mark`“折算ⓘ”信息浮层，内容为“当前汇率 1 USD = 1,540.20 NGN”与生效时间（同 M5、M14）；用于列表与保障核对的保险金额（美元）、概要“保险金额（美元）”和车辆清单 NGN 内采单价。浮层不再显示汇率编号。
- 附件：由分组字段改为表格“附件类别 | 附件 | 取得时间”，附件格为文件名 + 下载（同 M4），取得时间不再逐条标时区（页头已有时区）。

个性化说明（与通用口径不同或本模块特有之处）：

- 列表没有原币列：NGN 保单在“保险金额（美元）”美元值下方以小字写“原币 … NGN 折算ⓘ”（M14 资金收付另有原币“金额”列，美元列下只写“折算ⓘ”）。车辆清单中 NGN 内采单价同样写法。
- 附件某一类没有文件时，附件格按 PRD §9.2 写“暂无附件”（业务文字，不用“-”），取得时间为“-”；同一类多份时逐份一行，类别只在第一行写。
- 车辆清单中“未开票”是 PRD 定义的内采单价状态，按原文保留，不改为“-”。整块无内容的分区（“暂无车辆”“未关联提单”）保留空状态文字。
- 列表“关联提单／车辆”是数量，0 张／0 辆照常显示数字，不是缺值。
- 保单只有原币与美元两种金额，概要只在原币非美元时另列“保险金额（美元）”；美元保单不重复美元值（保障核对第一项已是美元值）。
- 详情页头与列表角色同为“保险公司 / 被保险人”（无全称 / 短名之分）。投保人不进入页头，留在概要。
- 公共层：只在 `components.css` 文末追加“WS-655 统一 · M13”一小块（列表合并列宽与表宽下限、原币折算行、概要关联预警单项与折算标记、保障核对“-”字号、附件表垂直居中）；未改 `tokens.css`。A70 / A71 中原 `.policy-usd`、`.policy-fx`、`.attach-line` 与四个旧列宽类已不再使用。

## 未单独出屏（以 PRD 为准）

- 企业端：PRD 规定债权人、债务人都没有保单信息入口，本模块只做运营端；企业用户通过链接访问时的“该内容不存在或无权查看”沿用平台无权限画面。
- PRD 已定义、未逐一出屏的情形：整页详情加载失败、关联提单 / 附件 / 关联预警分别加载失败、附件打开失败、内采单价无法折算或无可用汇率、保险金额无法折算、保险货值为 0、跳转目标已不再被采信。
- 从 M3、M5、M12 进入后的返回：仓库联看用浏览器返回，不另画来源相关的返回按钮。
- 本期不做（PRD §1.2）：录入、编辑、删除保单或附件；风控规则判断（保险未足额覆盖、保单信息与基础交易不一致）；提单船名航次、港口与清关明细；车辆的采购、内销、外销经历；保费金额与支付记录；保险条款结论；企业端查看。

## 待确认（不影响本原型布局）

- M13-Q08 风控预警同步：列表“预警”与详情关联预警数量为演示值，随 M8 完善生效。
- 运营端菜单：本模块在“资产数据”分组追加“保单信息”。按信息架构方案 v1，资产数据菜单会整体重组（应收账款、车辆履约、合同信息、提单信息、保单信息、资金收付），需在 M2 PRD 菜单表统一登记；本原型未改动其他菜单项。
