# M8 风控预警与三方数据源 · 运营端原型

依据 [`PRD/运营端/M8-风控预警与三方数据源/`](../../../PRD/运营端/M8-风控预警与三方数据源/01-风控预警与三方数据源-PRD.md)，需求提交 `7c2033fd`（2026-11-24 M8 复核稿，风控规则目录 28 条）。组件规范 v1.45。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。预警编号、应收账款编号、单据号码、VIN、企业、金额、汇率、日期、处理说明、调整原因与文件均为演示值；Carloha Holding / Carloha Nigeria、Demo Auto Trading Ltd 等不代表实际业务主体。演示“今天”为 2026-12-14，与 M3 一致。界面语言随顶栏中英切换（M2 F-OP-10）；规则、等级、启用状态与风控参数的英文名称按 PRD 03 册[规则与等级的英文名称](../../../PRD/运营端/M8-风控预警与三方数据源/03-风控预警与三方数据源-消息通知.md#en-names)，其余英文未经审校。平台记录的时间按本人时区展示并标明时区：单文件打开时取浏览器时区，仓库联看中沿用跨模块带入的展示时区（可在 M2 账户设置中切换）；ERP 日期按原样展示，不换算。

## 打开与路径

双击 [`风控预警与三方数据源.html`](风控预警与三方数据源.html)，或使用离线单文件附件；无需服务。左侧菜单“风控”下依次为“风控预警”“风控规则”“三方数据源”。侧栏底部“画面目录 · 演示数据”默认收起，列出全部 33 屏和“主流程下一屏”。

- 主流程一（PRD 第 1 节示例）：L1 → D1 W-DEMO-0009 VIN 重复（阻断，正在阻止 AR-DEMO-0012、AR-DEMO-0020）→ D2 差异已消除、阻断已解除 → “记录处理” P1 → P3（提交后不能撤回；记录处理不解除阻断）→ D3 已处理，“风控预警”角标 5 → 4。
- 主流程二（风控规则）：R1 → RK-16“调整等级” A1 → A3 确认（预警 → 阻断，列出受影响的申请与资产）→ R6 规则详情与配置记录；R1 → RK-26“停用” S1 → S2 → R7；R3 风控参数 → 截留等待天数“调整” Q1 → Q2 → R4。
- 列表：预警编号或“查看”进入详情（演示提供 W-DEMO-0009 / 0014 / 0011 / 0007 / 0005 / 0012 / 0006）；规则名或“查看”进入规则详情（演示提供 RK-01，另有 RK-16、RK-26 调整后的详情）；其余行提示仅提供部分画面。
- 应收账款、合同、VIN、提单、保单、交易流水号等编号按[仓库联看](../../README.md#仓库联看)进入所属模块（已登记的编号）；未登记的编号提示“该入口尚未纳入原型。”。route.js 登记 `alert:` / `m8-` 预警详情、`alertsOf:AR-DEMO-0012`、`alertsOfRule:RK-01` 和 `rule:` 规则详情（M8-NT02 打开处）。

## 本期不做（按 PRD §1.2）

企业端没有任何风控预警、风控规则或三方数据源入口，本模块不出企业端画面；企业账号访问本模块页面按 M2 运营端菜单与无权访问（F-OP-11）处理，运营账号待首登改密或锁定时按 M2 运营账号状态处理，均由 M2 原型展示。不提供手动新建、修改、删除、合并预警，新增规则、修改判断条件、用处理结果解除阻断、发起比对、导出、批量处理、指派，也不提供处理结果的修改、撤回或二次处理。阻断对运营审核与资产数字化平台调取的作用、审核说明是否必填由 M9 原型展示；站内消息 M8-NT01、M8-NT02 由 M10 承接；资产数据各模块的关联预警由各模块原型承接。

- 风控规则列表 28 条一次列出，不分页，便于整体对照。
- 角标为演示值：未处理的阻断类、预警类且规则启用中的预警 5 条；提示类、规则已停用的预警不计入。D3 为处理后 4。
- 预警编号为本模块演示值，与 M10 演示消息中的 M8-NT01 编号不联动；M10 尚无 M8-NT02 演示消息。
