# M4 合同信息 · 运营端原型

依据 [`PRD/运营端/M4-合同信息/`](../../../PRD/运营端/M4-合同信息/01-合同信息-PRD.md)，PRD 提交 `fda173d`（按 WS-655 确认口径修订：统一命名、辅助订单编号、外采未付款、外采单价取发票价或合同价、外销一单一合同）。既有系统适配（桌面 Web），沿用本平台公共层与列表、详情组件，组件规范更新至 v1.39。替代原 M4 上游采购追溯与 M6 下游销售与收款追溯的菜单入口（旧原型已于 WS-663 删除）。

原型仅用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。企业、客户、编号、金额、VIN、日期与文件均为演示数据，汇率按 1 USD = 1,500.00 NGN 演示；Carloha Holding、Carloha Nigeria、Demo OEM A / B、Demo Trading C 等不代表实际业务主体。内销发票号与应收账款编号（INV-0012 / AR-DEMO-0012、INV-0019 / AR-DEMO-0019）、VIN 沿用 M3、M5 原型的演示数据；合同号沿用上一版，M3、M14 中的合同入口仍可到达。

## 打开与路径

双击 [`合同信息.html`](合同信息.html)，或使用离线单文件附件；无需服务。侧栏底部“画面目录 · 演示数据”默认收起，可访问本模块全部画面和主流程下一屏。

- 菜单：资产数据 / 合同信息（`menu.ops.js` 的 `contracts`；M2 PRD 菜单表待同步登记）。页内“内销合同 / 外采合同 / 外销合同”三个页签（A54），菜单进入默认为内销合同。
- 主流程：C1 内销列表 → C5 内销详情 → P1 外采列表 → P5 外采详情 → P6 从外采发票号进入 → S1 外销列表 → S5 外销详情（零售）→ S6 外销详情（批售）。
- 列表中的合同号或右侧“查看”进入详情；面包屑“合同信息”回到进入前的页签。外采详情车辆清单中的“归属外采发票号”定位到本页外采发票清单中的该发票。内销订单编号、外采订单编号只作辅助展示，不可点击。
- 跨模块入口经[仓库联看](../../README.md#仓库联看)跳转：内销发票号 → M3（`receivable:`），VIN → M5（`vehicle:`），预警数量 → M8（`alertsOf:<合同号>`，M8 尚未登记），交易流水号 → M14（`funds:`；M14 未画出的流水号提示“演示仅提供部分收付记录的详情画面。”）。未登记的入口给范围提示。
- 本模块登记的路由：`contracts`、`domesticContract:`、`purchaseContract:`、`exportContract:`、`purchaseInvoice:`（打开所属外采合同并定位到该发票），见 [`route.js`](route.js)。

## 待确认与未单独出屏（以 PRD 为准）

- **M4-Q14（待确认）**：外采合同车辆清单中的“外采收货日期”“上游交货单据”按 PRD 设计照常展示，但口径仍待确认，对应验收为“待验，不判通过”；确认后如有变化再改画面。
- 其余待确认事项按 PRD 推荐口径出屏：M4-Q01 不保留车辆归属判定；M4-Q02 内销未收款 = 内销已开票 − 内销已收款、外采已付款比率 ÷ 外采已开票金额；M4-Q12 保留外销收款记录；M4-Q13 关联预警数量以 M8 提供为准。
- 企业端：PRD 规定债权人、债务人都没有合同信息入口；企业用户通过链接访问时的“该内容不存在或无权查看”沿用平台无权限画面。
- 附件打开失败、整页详情加载失败、某车物流节点等跨模块单值加载失败、按发票号 / 订单编号 / VIN 查找的结果（与默认列表同结构）、一辆车有多张外采发票时取最近一张的单价。
