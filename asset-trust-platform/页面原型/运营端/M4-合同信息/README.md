# M4 合同信息 · 运营端原型

依据 [`PRD/运营端/M4-合同信息/`](../../../PRD/运营端/M4-合同信息/01-合同信息-PRD.md)，最近同步 PRD 提交 `a8e28f8a`；初版依据 `fda173d`（按 WS-655 确认口径修订：统一命名、辅助订单编号、外采未付款、外采单价取发票价或合同价、外销一单一合同）。既有系统适配（桌面 Web），沿用本平台公共层与列表、详情组件，组件规范更新至 v1.41。2026-11-23 按用户反馈调整：内销合同列表只保留身份、当事方、金额与预警；三类详情页头展示合同买卖双方（同 M3 应收账款详情）；取不到或算不出的值以“-”占位。同日按 WS-655 与资产数据其他模块统一呈现（见下文“与资产数据其他模块统一”）。替代原 M4 上游采购追溯与 M6 下游销售与收款追溯的菜单入口（旧原型已于 WS-663 删除）。

2026-11-24 按 PRD `9670e87`（`cly-v6.0.0` @ `b693d078`）同步：内销合同车辆清单的内采单价（美元）在车辆尚未开内销发票时取内销合同中的车辆单价并标“合同价”，不再显示“未开票”（C5、C6、C7）；“归属内销发票号”仍按 PRD 显示“未开票”。外采合同车辆清单的“外采收货日期 / 未收货”暂按原样保留（PRD 已改为“外采交货日期 / 未交货”，因 M3 仍用“外采收货日期”，名称统一待用户裁定）。M9 改名“运营审核与资产推送”不涉及本模块画面。

2026-11-24 按 PRD `a8e28f8a`（WS-673 复核）同步：内销合同车辆清单的外销收款金额改为只取与外销单价同一份（最近一份）外销合同的收款，批售合同按本车外销单价占合同金额的比例分摊并标“按比例分摊”（C5、C7 的 LDEMOVIN000000002 属批售合同 SC-DEMO-2048：31,000.00 ÷ 124,000.00 × 46,000.00 = 11,500.00 USD），C5 终端回款进度随之为 29.00%（(32,000.00 + 11,500.00) ÷ 150,000.00）；三个页签的关联预警按 M8 已提供的结果展示；新增从 M8 预警详情、M9 当次依据中的合同号与外采发票号进入的入口（落到对应详情，外采发票号定位到该发票，即 P6）；不可访问改按 M2 处理，本模块没有自己的无权提示页；展示时区不再固定为 UTC，随 M2 中本人设置（仓库联看中沿用跨模块带入的时区）。

原型仅用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。企业、客户、编号、金额、VIN、日期与文件均为演示数据，汇率按 1 USD = 1,500.00 NGN 演示；Carloha Holding、Carloha Nigeria、Demo OEM A / B、Demo Trading C 等不代表实际业务主体。内销发票号与应收账款编号（INV-0012 / AR-DEMO-0012、INV-0019 / AR-DEMO-0019）、VIN 沿用 M3、M5 原型的演示数据；合同号沿用上一版，M3、M14 中的合同入口仍可到达。

## 打开与路径

双击 [`合同信息.html`](合同信息.html)，或使用离线单文件附件；无需服务。侧栏底部“画面目录 · 演示数据”默认收起，可访问本模块全部画面和主流程下一屏。

- 菜单：资产数据 / 合同信息（`menu.ops.js` 的 `contracts`；M2 PRD 菜单表待同步登记）。页内“内销合同 / 外采合同 / 外销合同”三个页签（A54），菜单进入默认为内销合同。
- 主流程：C1 内销列表 → C5 内销详情 → P1 外采列表 → P5 外采详情 → P6 从外采发票号进入 → S1 外销列表 → S5 外销详情（零售）→ S6 外销详情（批售）。
- 列表中的合同号或右侧“查看”进入详情；面包屑“合同信息”回到进入前的页签。外采详情车辆清单中的“归属外采发票号”定位到本页外采发票清单中的该发票。内销订单编号、外采订单编号只作辅助展示，不可点击。
- 跨模块入口经[仓库联看](../../README.md#仓库联看)跳转：内销发票号 → M3（`receivable:`），VIN → M5（`vehicle:`），预警数量 → M8（`alertsOf:<合同号>`，落点按 M8 PRD“进入与返回”：按本合同筛选的预警列表，只有一条时直接进入该预警详情；M8 原型尚未登记合同筛选画面，仓库联看中给范围提示），交易流水号 → M14（`funds:`；M14 未画出的流水号提示“演示仅提供部分收付记录的详情画面。”）。未登记的入口给范围提示。
- M8 预警详情、M9 当次依据中的合同号与外采发票号按本模块已登记的路由进入（`domesticContract:` / `purchaseContract:` / `exportContract:` / `purchaseInvoice:`）；M8、M9 原型尚未在这两处加入入口，加入时直接使用这些路由。
- 本模块登记的路由：`contracts`、`domesticContract:`、`purchaseContract:`、`exportContract:`、`purchaseInvoice:`（打开所属外采合同并定位到该发票），见 [`route.js`](route.js)。

## 与资产数据其他模块统一（WS-655，2026-11-23）

按 WS-655 统一口径（基准 M3 应收账款、M4 本模块），同类信息与 M3、M5、M12、M13、M14 同样呈现：

- 列表查找：三个页签都去掉“查找方式”下拉，改为单一查找框，占位文字列出可匹配项（内销：内销合同号、内销订单编号、内销发票号或 VIN；外采：外采合同号、外采订单编号、外采发票号或 VIN；外销：外销合同号或 VIN）。查找无结果画面保留已填内容。
- 列表当事方：两方合为一列“A → B”，每行“角色短名 + 名称”（同 M3 应收账款列表）：内销“卖方 / 买方”；外采原“采购公司”“外采供应商”两列合为“外采供应商 → 采购公司”（供应商 / 采购公司，方向同详情页头）；外销原“外销卖方”“外销客户”两列合为“外销卖方 → 外销客户”（卖方 / 客户，个人客户仍脱敏）。
- 列表只放识别、当事方、金额、日期和预警：外采列表删去“外采已开票 / 未开票（美元）”“外采已付款比率”，外销列表删去“外销已收款比率”；这些值在详情“执行进度”中照常展示。预警列直接展示未处理条数（warn 色），没有时为“无”。
- 详情分层：概要 → “进度与核对”（执行进度）→ “明细”（内销发票清单 / 外采发票清单 / 收款记录、车辆清单、附件），写法同 M3 应收账款详情；分区导航仍按卡片标题生成，两组之间留间隔。
- 关联预警：未处理为 0 时“未处理 0 条”不再是链接，下方照常列已处理条数；没有任何关联预警时为“无”；加载失败画面保留“加载失败 + 重试”。
- 附件：表头为“附件 | 取得时间”，取得时间表头下不再另写时区（页头说明行已有时区）；本模块每个合同只有合同文件一类附件，省略“附件类别”列。内销发票清单、外采发票中的发票附件保持原位。
- 折算：NGN 金额的美元折算值统一带 `fx-mark`“折算”标记，点开显示“当前汇率 1 USD = 1,500.00 NGN”与生效时间（同 M5、M14），替代原“折合”写法；用于概要金额下方、外销车辆单价下方和外销收款记录的“金额（美元）”。
- 取不到或算不出的值仍为“-”（读屏保留原因），原因以 `metric-note` 跟在值下方。

个性化说明（与通用口径不同或本模块特有之处）：

- 页内保留“内销合同 / 外采合同 / 外销合同”三个页签（A54），三类合同共用列表与详情骨架，菜单进入默认为内销合同；面包屑“合同信息”回到进入前的页签。
- 内销订单编号、外采订单编号只是辅助编号，在概要中展示，不可点击；合同号是唯一入口。
- 外采详情的车辆清单可按“归属外采发票号”在本页定位到外采发票清单中的该发票（P6），不跨模块。
- 外销列表保留“销售方式”（零售 / 批售）列，是外销合同的识别信息；外销客户为个人时脱敏。
- 详情页头角色用全称（内销卖方 / 内销买方、外采供应商 / 采购公司、外销卖方 / 外销客户），列表单元格用短名，与 M3 一致。
- 车辆清单中“未开票”（归属内销发票号）、“暂无外采”“暂无外销”“未收货”“未出库”等带业务含义的状态文字按 PRD 保留，不改为“-”。
- 公共层：只在 `components.css` 文末追加“WS-655 统一 · M4”一小块，把外采列表表宽下限收窄到与内销相同、外销另加销售方式列宽；未改 `tokens.css`。
