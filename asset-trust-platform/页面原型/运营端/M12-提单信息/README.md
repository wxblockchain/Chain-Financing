# M12 提单信息（含清关）· 运营端原型

依据 [`PRD/运营端/M12-提单信息/`](../../../PRD/运营端/M12-提单信息/01-提单信息-PRD.md)（WS-661，01 功能与业务规则、02 流程图与状态机、04 验收，2026-11-19 需求评审稿）。组件规范 v1.32。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。企业、船公司、单据号码、VIN、集装箱号、金额、日期、航程动态与文件均为演示数据；Carloha Holding / Carloha Nigeria 不代表实际业务主体。船公司、船名航次、港口、当事方与航程动态是来源原值，英文界面不翻译。

## 打开与路径

双击 [`提单信息.html`](提单信息.html)，或使用离线单文件附件；无需服务。左侧菜单“资产数据 / 提单信息”进入列表。侧栏底部“画面目录 · 演示数据”默认收起，列出全部画面和“主流程下一屏”。

- 列表：提单号或右侧“查看”进入详情（演示提供 BL-DEMO-5501、BL-DEMO-5530，其余行提示仅提供部分提单）。
- 详情：VIN 进入车辆履约（M5），保单号进入保单信息（M13），预警数量进入风控预警（M8）按本提单筛选；清关单号定位到车辆清单。跨模块入口经[仓库联看](../../README.md#仓库联看)跳转，未登记的提示“该入口尚未纳入原型。”。
- 主流程：L1 列表 → D1 提单详情 → 返回列表。从 M5 清关节点进入为 D3（路由 `blVehicle:<提单号>:<VIN>` 定位到车辆清单）。

## 本期不做（按 PRD §1.2）

企业端（债权人、债务人）没有提单信息入口，本模块不出企业端画面。不提供录入、编辑、删除、补传或预警处理；不做风控判断，字段旁没有比对提示；不展示费用金额明细、预计到港日期与船舶位置地图。

## 待确认与未覆盖

- 集装箱号按车辆展示（M12-Q01）按 PRD 推荐口径出屏，待用户确认。
- 预警列与概要预警数量依赖 M8 提供（M12-Q03）；M8 尚无“按提单筛选”的画面，入口提示尚未纳入原型。
- 保单信息（M13）尚无原型，保单号入口提示尚未纳入原型。M3、M5、M8、M13 中进入本模块的提单号入口待各模块改版时接入（路由 `bl:<提单号>` 已登记）。
- 菜单“提单信息”已加入 `menu.ops.js` 的“资产数据”分组，待 M2 PRD 菜单表登记；资产数据其他菜单（合同信息、保单信息、资金收付）的重组不在本模块范围。
- 汇率时点（M12-Q02）按 PRD 当前口径，折算旁可查看所用汇率与生效时间；演示汇率与 M11 当前汇率一致。
- 合同单价单元格加载失败、附件打开失败、一辆车多张清关单（标出共几张）、企业用户链接访问等以 PRD 为准，未单独出屏。

## 实际核验（v1.32）

Chromium / Playwright：9 屏 × 中英文 × 1280 / 1440 / 1920 px 无脚本错误、无整页横向溢出；英文模式除演示账号名外无未翻译平台文案。提单列表中文 1440 px 起完整展示，1280 px 与英文 1280 / 1440 px 表内滚动，提单号与“查看”固定可达；车辆清单 1440 px 起完整展示。离线单文件断网打开无外部请求；画面目录 9 屏、列表 → 详情 → 返回列表、清关单号定位车辆清单、汇率浮层开合实测；仓库联看中从 M5 菜单进入提单信息、VIN 进入 M5 详情实测。运营端 M2–M11 与 `index.html` 在 1280×720 / 1440×900 回归加载、脚本错误、整页溢出与侧栏末项可达，未重跑其业务流程。未验证 1280 px 以下与屏幕阅读器。
