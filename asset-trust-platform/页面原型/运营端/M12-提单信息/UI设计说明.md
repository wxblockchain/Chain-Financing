## 11月27日增量 · 长单号与定位反馈

现有运营桌面控制台适配；本轮基线为执行时远端 `c3f4053e`，模块原型 `f492413c`，最新 PRD `0c2fe29a`。当事方完整展示及 `eae0b7fc` 的双向定位已在现有原型中符合要求，不新增业务画面或遮盖行为。以下为本轮增量，下方保留 11月25日的设计与历史核验记录。

实页发现：较长清关单按钮沿用不换行样式时覆盖邻列，鼠标可能点击到相邻日期；“已标出”标注将长单号与操作强制排在一行，1024 px 英文下“取消标出”超出视口；键盘取消后按钮被移除，焦点落回 body。

本轮仅修改模块 `m12-ui.css`、`m12-locate.js` 及 README／本说明：

- 详情表格的编号链接、附件分组单号及页头单号完整换行，保留全文及原事件目标；不会裁切或省略单号。
- 车辆卡头的定位标注按可用宽度换行，单号与“取消标出”采用两列约束；数量不拆成两行，筛选仍可访问。长标注不压住操作，不缩小字号。
- 取消标出后将焦点移到原有、可聚焦的车辆表滚动区域，留在当前工作位置；原单据关联、标出／清除规则和 D3／D7 进入时的定位行不变。
- 沿用全部 12 屏；详情独立信息分区始终纵向占满内容宽度，概要与卡内短字段的现有分列保持。没有修改共享 token、组件样式或壳层，无其他模块消费者变化。

本轮覆盖：D1／D3／D4／D7 修改且实测定位反馈、编号及焦点；D2／D6 继承详情结构并实测缺值原因、空清关单和合同价；L1–L5、D5 内容继承未改、完成布局回归。关联保单与附件分区继承原结构，只允许编号在自身列内完整换行。

实际核验（Chromium，视口高 900 px）：全部 12 屏 × 中英文 × 1024／1280／1440／1920 px，共 96 组合无脚本错误、整页横向溢出或单元格超宽；D1／D3／D4／D7 × 中英文 × 四宽度 × 原编号／长编号，共 64 组合通过双向定位、对应两辆车标出、取消后的焦点与原定位行保留、长按钮鼠标点击和标注边界检查。临时长单号为 60 字符清关单号与 53 字符提单号，不写入演示数据。

另复测既有长港口处理 12 组合，无越界、全值浮层可键盘查看；VIN → M5、保单 → M13 和返回、M5／M8 原有三个进入路由均通过。离线附件从最新源文件用既有 `_shared/export.py` 导出，断网打开无外部请求，不修改生成件。此前所有其他模块的业务核验不计入本轮；本轮未改共享层。

未验证范围沿用下方限制：真实鉴权、数据服务、计算、附件真实查看／下载、屏幕阅读器及其他浏览器；不将静态原型核验作为业务 Eval 或上线结论。

## 呈现变化

- 列表保持十一列、一张提单一行，提单号与“查看”固定两侧。按中英文分别分配阅读宽度；船公司、船名航次及港口复用共享 `name-clip` 和 `value-pop`，保留首尾，点击或键盘 Enter 可查看来源全值，Esc 收起并返回触发点。港口仍在同一行连接。
- 详情概要首层为货值、装运港 → 卸货港及关联预警，其下三列展示船公司、船名航次、装船日期、车辆数与集装箱资料。字段标签在上、值在下；1279 px 以下预警移到概要底部，900 px 以下航线与金额顺序排列、字段两列。港口字段从原概要网格移入航线，未删字段或重复造值。
- 航程动态仍为时间／地点／动态的原表格，从新到旧；添加装饰节点与连接线，最新一行用浅底区分，原值、来源时区和到港日期全部保留。清关逐车分段条保持原读数、状态及 meter 名称，只压缩宽度并调整间距。
- 车辆清单与清关单采用明确列宽。车辆 VIN 固定在左；金额用正文栈和等宽数字，VIN 与单据号保留等宽字体。折算图标与美元金额同行，合同价和缺值原因完整换行，不挤占相邻列。
- 清关附件按既有清关单分组，每组独立 `tbody`，单号为带 `scope="rowgroup"` 的跨行表头；附件仍一份一行，保留查看、下载。长文件名直接换行，取得时间为日期与时分两行，仍按本人时区换算。没有重新划分附件类别。
- 901–1100 px 的画面目录沿用更宽桌面的侧栏位置，避免遮住文件操作和取得时间。没有改变共享壳层行为。

## 源码与继承

| 文件 | 本轮职责 |
| --- | --- |
| `提单信息.html` | 概要展示结构、附件行组及时间排版，引用模块样式和展示脚本 |
| `m12-ui.css` | 仅 `.m12-ui` 启用的 A60/A61 变体；复用共享颜色、字号、间距、表格、焦点与状态组件 |

| `_shared/tokens.css` | 维护已有 `--bl-*` 尺寸及新增 M12 尺寸；英文覆盖限定 `data-module="ops-bills"`。字号、字体、色彩和其他模块 token 不变 |
| `README.md`、本说明、组件规范 A60/A61 | 与实际呈现及覆盖同步 |

`--bl-*` 代码消费者检索只命中共享 A60/A61 和 M12 模块样式。没有复制公共层、修改共享 JS、路由、菜单或翻译。数据精度、预警数、合同价说明、缺值“-”和原因保持原值；未到港／未清关等业务状态及原有空态继续显示文字。

关键尺寸在唯一 token 文件维护：列表最小宽度中文 1104／英文 1408 px，车辆表中文 1100／英文 1408 px，清关表中文 1000／英文 1200 px，附件时间列 176 px、单号列 200 px。空间不足时只在表内滚动，不缩小字号或隐藏字段。字体沿用系统栈，不新增字体下载依赖。

附加实测：

- 列表横向滚动后，固定提单号与查看仍可访问；车辆 VIN 固定列及卡内横滚保留。
- 独立审阅发现中文长港口尾部可能覆盖箭头，已改为航线名称保留末 2 字符、两端等分空间；补测“上海外高桥港／尼日利亚拉各斯港”和英文长港口 × 中英文界面 × 1024／1440／1920 px，共 12 组合，名称尾部不越界，键盘浮层仍展示全值。
- 长来源名称用键盘打开全值浮层、视口内定位，Esc 关闭且焦点返回；集装箱（概要与清关表）和汇率图标同样核验。40 个临时集装箱值以三列、320 px 上限内部滚动，全量可达，未写入演示数据。
- 五个详情导航锚点逐个点击，目标获得焦点，未被吸顶导航遮挡。长当事方、港口及文件名在 1024 px 换行并保留全值。窄桌面目录未遮住文件操作。
- 附件取得时间分别以 Africa/Lagos 与 Asia/Tokyo 打开，相差 8 小时，页头显示对应时区；来源航程时间保持原值。
- 仓库联看：VIN → M5、保单号 → M13 及浏览器返回；五个原提单／车辆／清关入口路由均到达原画面。D3、D7 的定位行与 L5 的预填值保留。
- 离线附件由既有 `_shared/export.py` 生成，断网打开无外部请求；样式、来源全名与集装箱浮层可用。离线文件不提供跨模块详情和真实文件，沿用原提示。
- M3／M5／M13 的英文 1440 px 壳层冒烟无脚本错误、无整页溢出；未将其视为其他模块业务流程验收。

## 运行与离线导出

保留完整仓库目录时双击 `提单信息.html`，使用原画面目录选择 L1–L5／D1–D7。独立审阅使用本 issue 附带的自包含 HTML，双击即可打开。

从仓库根目录生成附件（生成件放仓库外，不入库）：

```bash
python3 asset-trust-platform/页面原型/_shared/export.py --source asset-trust-platform/页面原型/运营端/M12-提单信息/提单信息.html --output /tmp/M12-提单信息-UI优化.html
```
