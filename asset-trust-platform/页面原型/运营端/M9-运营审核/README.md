# M9 运营审核 · 运营端原型

**2026-11-25 UI 优化**：在原型 `6107c883`、PRD `95c37ea7` 基础上，优化列表表头、数字及名称查看，详情概要、分组导航、连续分区、上链长反馈，以及 A1–A5 的统一排版。菜单与全部业务字段、状态、审核入口条件不变。模块样式及呈现脚本为 `m9.css`、`m9-presentation.js`，均复用共享层，不改全局组件；实际修改／继承覆盖和本轮核验见 [UI设计说明](UI设计说明.md)。下文“实际核验”保留上游业务同步时的历史记录，以 UI设计说明 的本轮记录为准。

依据 [`PRD/运营端/M9-运营审核/`](../../../PRD/运营端/M9-运营审核/01-运营审核-PRD.md)（2026-11-25 需求评审稿，提交 `c3eec479`，WS-676；到期以审核提交的时刻为界，M7a 待同步见 Q-M9-09）；当次依据按 M7a，资产健康度与资料校验（F-M3-15）按 M3，预警等级与规则名称按 M8。组件规范 v1.69。原目录“M9-运营审核与资产推送”已随 PRD 改名为“M9-运营审核”，推送相关画面已删除。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。企业、姓名、编号、金额、VIN、钱包地址、上链凭证、签名地址、哈希值与文件均为演示值，菜单待办数量为演示值。万纳连的写入方式、上链凭证包含哪些项、失败与超时的返回由研发确认；原型能展示上链凭证与上链数据，不代表上链能力已实现。

## 打开与路径

双击 [`运营审核.html`](运营审核.html)，或从仓库 [`index.html`](../../index.html) 以运营端进入“审核 / 运营审核”（菜单在“资产数据”之前）。侧栏底部「画面目录 · 演示数据」默认关闭，可到达全部 24 屏。

- 审核主流程：L1 待审核 → D1 申请详情 → A1 审核通过 → A2 审核说明为空 → A3 已填写 → D4 已提交 · 上链中（运营审核角标 4 → 3）→ D5 运营审核通过（上链成功，展示上链信息）。
- 上链失败：L1 中 AP-DEMO-0022 → D6 上链失败（仍为待运营审核，页头“审核通过”）→ A5 再次审核通过（带入上次审核说明）→ D7 第 2 次提交 · 上链中（角标 4 → 3）。
- 应收账款编号、“查看应收账款当前资料”“查看差异”、内销合同号、VIN、关联单据（提单 / 保单 / 内销收款）、预警编号是跨模块入口，经仓库联看进入 M3、M4、M5、M12、M13、M14、M8 已有画面；单模块附件中提示到 index.html 打开。

## 本期不做与未出屏

- 按 PRD 本期不做：审核驳回或不通过、撤回审核通过、撤回或更正已上链数据、批量审核、自动重新上链、企业端查看审核人 / 审核说明 / 上链结果；哪些数据能被调取不在本模块定义（Q-M9-08）。原推送信息、存证与重新存证画面（原 D3–D8、D14、R1）已删除。
- 未单独出屏（以 PRD 为准）：审核提交失败、提交结果未确认、提交时“出现新的未处理风控预警”拦截、提交时已审核通过或已关闭（“应收账款已到期，该申请已关闭”）、提交时已到期但 M7a 尚未关闭（申请仍显示“待运营审核”，不计入角标，提示“应收账款已到期，不能审核通过”，沿用 D10 的提示位置）、已收清、资料校验“暂无法判断”、当次依据 / 上链信息读取失败、登录失效或账号被锁定；沿用 A2、D3、D10、D11、L7 的提示位置与结构。万纳连返回失败原文的情形沿用 D9 的记录写法；超时后才返回的结果只记入处理记录，未出屏。到期前提交、到期后才上链成功的结果与 D5 相同（运营审核通过、展示上链信息），未单独出屏；到期后列表与详情不提供“审核通过”，见 D9。
- 无权访问：企业账号的登录状态访问、待首登改密或锁定的运营账号按 M2“运营端菜单与无权访问（F-OP-11）”处理，本模块不单独出屏；打开不存在的申请编号为 D12。
- 消息 M9-NT01、M9-NT03 由 M10 承载，演示消息见 `_shared/inbox.js`。
