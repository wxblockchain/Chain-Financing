# M4 上游采购追溯 · 运营端原型

依据 [`PRD/运营端/M4-上游采购追溯/`](../../../PRD/运营端/M4-上游采购追溯/01-上游采购追溯-PRD.md)，PRD 提交 `4c50413`。既有系统适配（桌面 Web），沿用本平台公共层与 M3 列表、详情组件，组件规范更新至 v1.13。

原型仅用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。企业、供应商、编号、金额、VIN、日期、银行账号和文件均为演示数据；Carloha Holding、Demo OEM A / B、Demo Trading C 不代表实际业务主体。应收账款编号、VIN 与车型沿用 M3 原型的演示数据。

## 打开与路径

双击 [`上游采购追溯.html`](上游采购追溯.html)，或使用离线单文件附件；无需服务。侧栏底部“画面目录 · 演示数据”默认收起，可访问本模块全部画面和主流程下一屏。

- 菜单：资产数据 / 上游采购（M2 菜单表已有项）。
- 主流程：P1 列表 → P5 按 VIN 查找 → T1 从应收账款追溯 → D2 采购交易详情（对照应收账款）→“返回车辆追溯”。
- 列表订单号码或右侧“查看”进入详情；面包屑“上游采购”返回列表。
- M3 应收账款详情、M5 车辆履约、M8 风控预警等其他模块入口沿用统一范围提示“该入口尚未纳入原型。”；未画出详情的演示采购交易提示“演示仅提供部分采购交易的详情画面。”

| 采购交易详情 | D1 | 默认：顶部订单号码、供应商与买方，付款情况与核对提示；外采订单（含采购明细、多份附件）→ VIN 登记与车辆明细 → 外采发票与付款（逐张发票，付款状态随发票，付款记录九列）→ 关联应收账款 → 资料追溯（资料补充记录含更换前版本、关联风控预警） |

| | D5 | 关联应收账款部分加载失败，其他信息正常 |
| | D6 | 从其他模块带入的采购交易不存在或已更新 |

核对提示只在对应信息处以提示条或标签标出，不设处理或认定入口；归属结果和付款状态为只读标签。全模块无新增、编辑、删除、补传入口。

## 未单独出屏（以 PRD 为准）

- 企业端：PRD 规定债权人、债务人本期都没有上游采购入口，本模块只做运营端；企业用户通过链接访问时的“该内容不存在或无权查看”沿用平台无权限画面，不另画。
- 按 VIN 查找时 VIN 既不在应收账款也不在采购交易中（“未找到该 VIN 的上游采购资料”）、附件打开失败、整页详情加载失败、单价币种不同时“无法合计”：PRD 已定义文案，原型未逐一出屏。
- 从 M8 / M9 进入时的返回位置、按 VIN 查找结果中进入后的返回：跨模块入口尚未纳入原型。

## 实际核验

Chromium / Playwright，中英文 × 1280 / 1440 / 1920 px，视口高 1000 px，源文件与离线单文件：

- 全部 17 屏加载无脚本错误、无整页横向溢出、按钮与标签无截断；英文模式下除 ERP 原值外无残留中文。
- 主流程逐屏点击通过：列表订单号码进入详情、面包屑返回、画面目录主流程下一屏、P5“查看追溯”→ T1、T1“查看”→ D2、D2“返回车辆追溯”、T1 其他采购交易进入 D3、详情分区导航定位、更多筛选展开、跨模块入口提示。
- 1280 px 列表在表内滚动，订单号码与“查看”固定可见；1440 / 1920 px 中文完整显示。付款记录九列在不足阅读宽度时于表内滚动。
- 离线单文件断网打开无 HTTP 请求。
- 公共层只在文末追加 M4 段落与 token；M1（44 屏）、M2（87 屏）、M3 两端（11 + 8 屏）在两种语言 × 三档宽度回归加载、脚本错误与整页溢出通过，未重跑其完整业务流程。

未验证 1280 px 以下、屏幕阅读器、完整无障碍符合性，以及真实 ERP 取数、附件下载和跨模块跳转。
