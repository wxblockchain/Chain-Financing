# M14 资金收付 · 运营端原型

依据 [`PRD/运营端/M14-资金收付/`](../../../PRD/运营端/M14-资金收付/01-资金收付-PRD.md)（当前基线为 WS-680 复核提交 `838b75e2`：账号状态、时区、界面语言、菜单与企业账号访问按 M2，关联预警按 M8，新增从 M8 预警详情与 M9 当次依据进入，补齐来源值缺失与同号记录的落点）。组件规范 v1.37，WS-655 统一写法见 v1.43。

原型只用于评审页面、字段和主流程；规则、校验与异常分支以 PRD 为准。界面语言随顶栏中英切换；凭证取得时间与汇率生效时间按本人时区展示，时区标在详情说明行（M2 F-OP-10）；收付日期按原样展示，不换算。企业与客户名称、交易流水号、单据编号、金额、银行、账号、汇率与文件均为演示数据，交易流水号与 M3 回款记录、M4 合同信息付款 / 收款记录、M5 外销段一致（TRX-DEMO-1015、TRX-DEMO-1102、RC-DEMO-7781 等），PAY-DEMO-0130、PAY-DEMO-0140、第二条 TRX-DEMO-1102（关联 INV-0019）以及交易流水号未提供的一条外销收款（关联 SC-DEMO-2038）为本模块补充的演示样本。

## 打开与路径

双击 [`资金收付.html`](资金收付.html)，或使用离线单文件附件；无需服务。左侧菜单“资产数据 / 资金收付”进入。侧栏底部“画面目录 · 演示数据”默认收起，列出全部画面和“主流程下一屏”。

- 主流程：L1 → 点交易流水号 TRX-DEMO-1015 → D1 →（主流程下一屏）D2 → D3。
- 收付类型下拉选“内销收款”进入 L2、选“外采付款”进入 L3（演示该类为空），选“全部”回到 L1。
- 列表中有画面的交易流水号：TRX-DEMO-1015（D1）、PAY-DEMO-0130（D2）、RC-DEMO-7781（D3）、PAY-DEMO-0140（D4）、TRX-DEMO-1102（两条：关联 INV-0012 的进入 D5，关联 INV-0019 的进入 D9）、“未提供”（2026-10-12 外销收款，进入 D10）；其余提示演示范围。
- 跨模块入口（`data-module-key`）：内销发票 INV-0012 → `receivable:AR-DEMO-0012`（M3）；外采发票 PPI-DEMO-0302 → `purchaseInvoice:`、PPI-DEMO-0301 → `purchaseContract:PO-DEMO-031`（M4）；外销合同 → `exportContract:`（M4）；“返回应收账款” → `invoices`。关联预警条数为 `alertsOfFunds:<交易流水号>`（同号记录为 `alertsOfFunds:<交易流水号>:<关联单据编号>`），落点按 M8；M8 原型尚未登记，仓库联看中提示“该入口尚未纳入原型。”。演示未画出的单据提示“演示仅提供部分单据的详情画面。”
- 其他模块进入本模块（PRD §9.2），都用浏览器返回进入前的位置：
  - M3 回款记录、M4 付款 / 收款记录、M5 外销段、M8 预警详情、M9 当次依据中的交易流水号：路由 `funds:<交易流水号>`，进入该笔收付记录详情。M3、M4、M5、M9 中已画出的 TRX-DEMO-1015、TRX-DEMO-1102、RC-DEMO-7781 进入详情，其余交易流水号提示“演示仅提供部分收付记录的详情画面。”
  - 同一交易流水号有多条记录时，每个入口落到来源位置对应的那一条，不改为按交易流水号查找：路由 `funds:<交易流水号>:<关联单据编号>`，演示 `funds:TRX-DEMO-1102:INV-0012` → D5、`funds:TRX-DEMO-1102:INV-0019` → D9。M3 AR-DEMO-0012 回款记录现有的 `funds:TRX-DEMO-1102` 对应的就是关联 INV-0012 的那一条，仍登记到 D5。

## 呈现说明

- 只有运营管理员一种角色，没有身份差异画面；企业端没有入口，本模块不出企业端画面。
- 收付日期按原样展示；凭证取得时间与汇率生效时间按本人时区展示（M2 F-OP-10），时区只在详情页头说明行标出一次。
- 不能处理的收付登记（无法判定收付类型、缺少金额或币种、分配金额不完整，PRD §4.3）不进入本模块，从其他模块带入时与未采信、已移除一样展示 D8“未找到该收付记录”，不单独出屏。
- 列表与平台其他业务列表一样每页 10 条（只画第 1 页），不展示金额合计，没有新增、编辑、删除操作。

## 与资产数据其他模块统一（WS-655，2026-11-23）

按 M3 应收账款、M4 合同信息的统一口径调整，规则与字段不变：

- 列表（L1–L6）：页头去掉说明句；去掉“交易流水号 / 关联业务编号 / 付款方或收款方”查找方式下拉，改为单一查找框，placeholder 列出可匹配项；“付款方 → 收款方”单元格改为 M3 的两行写法（角色 + 名称）；无法折算的“金额（美元）”改为“-”占位（读屏仍读“无法折算”）。
- 详情页头（D1–D7）：说明行补“时区 UTC”，为“收付类型 · 交易流水号 … · 时区 …”；不放返回按钮，从面包屑回到列表。
- 概要：主金额前加币种旗标（USD / NGN；其他币种不加旗标）；关联预警统一为“未处理 N 条”预警色链接（进入 M8，`alertsOfFunds:<交易流水号>`）+ “已处理 M 条”辅助文字，没有关联预警时为“无关联预警”（WS-680 按 PRD §8 由“无”改回）；D7 保留加载失败与重试。
- 凭证附件：去掉“查看 / 下载”操作列，附件格改为 M4 的文件引用（文件图标 + 文件名按钮 + 下载图标）；“取得时间”表头不再另标时区。D5“暂无凭证”保留。

### 个性化说明

- 列表没有“预警”列：PRD §5 列表字段不含预警，关联预警只在详情概要展示。
- 详情按 PRD §6.1 的三层加分组标题：收付双方与账户在“进度与核对”下，凭证附件在“明细”下（与 M3、M4、M5、M12、M13 同一写法）。收付记录没有比率类指标，“进度与核对”只有收付双方与账户一张卡。
- 凭证附件只有一类，省略“附件类别”列，表头为“附件 | 取得时间”（同 M4）。
- 详情“收付双方与账户”分区仍列出付款方、收款方：该分区按方展示银行与账号，名称作为账户归属保留，概要中不重复。
- 列表保留“金额（美元）”和“关联业务”列：PRD §5 列表字段要求，不是比率或进度。
