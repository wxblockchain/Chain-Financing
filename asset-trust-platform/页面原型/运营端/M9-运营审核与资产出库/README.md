# M9 运营审核与资产出库 · 运营端原型

依据 [`PRD/运营端/M9-运营审核与资产出库/`](../../../PRD/运营端/M9-运营审核与资产出库/01-运营审核与资产出库-PRD.md)，需求提交 `0caed08`（含 Q-M9-01、Q-M9-02 按推荐裁定）；申请状态、当次依据按 M7a，债务人确认结论按 M7b，关联预警字段按 M8。组件规范 v1.19。

原型只用于评审页面、字段和主流程；规则、校验及异常分支以 PRD 为准。企业、姓名、编号、金额、VIN、钱包地址、存证凭证、资产标识和文件均为演示值，两个菜单的待办数量为演示值。存证与资产数字化平台的对接能力尚未核验（PRD Q-M9-03），原型展示不代表能力已实现。

## 打开与路径

双击 [`运营审核与资产出库.html`](运营审核与资产出库.html)，或使用离线单文件附件。默认进入“运营审核 · 待审核”；侧栏底部「画面目录 · 演示数据」默认关闭，可到达全部 31 屏。

- 审核主流程：L1 待审核 → D1 申请详情 → A1 审核通过（有未处理预警）→ A2 审核说明为空 → A3 已填写 → D2 审核通过 · 未出库（运营审核 4 → 3，出库与供数 1 → 2）。
- 出库主流程（PRD 示例）：D2 → E1 出库确认 → B1 出库处理中 → B2 供数未接收 · 出库失败 → E2 重新出库（沿用存证）→ B3 出库处理中 → B4 已出库。
- 列表行的“审核通过”“出库”“重新出库”打开与详情相同的弹窗，取消或 Esc 回到列表；演示只为部分行提供详情或处理画面，其他行提示演示范围。
- 应收账款编号、“查看应收账款当前资料”、VIN 追溯（M4 / M5 / M6）与预警编号（M8）是跨模块入口；经[仓库联看](../../README.md#仓库联看)进入对应模块已有的记录画面；未画出的记录提示“演示仅提供部分…画面。”，单模块附件中提示到 index.html 打开。

## 本期不做与未出屏

- 按 PRD 本期不做：审核驳回或不通过、撤回审核或出库、批量审核与批量出库、自动出库与自动重试、已出库内容修订或重新提供、资产数字化平台接收后的处理结果、向其他平台提供资产、企业端查看审核人 / 审核说明 / 失败原因。
- 未单独出屏（以 PRD 为准）：审核提交失败、结果未确认、“出现新的未处理风控预警”提交拦截、两人同时出库、出库提交失败、当次依据读取失败、出库记录读取失败、登录失效、待办数量单独取数失败；沿用 A2、D5、D6、B7、L6 / O4 的提示位置与结构。
- 消息（M9-NT01～03）由 M10 消息中心承载，本原型不含消息入口。M3 进度条接入出库环节、M7a 申请详情的出库进度属于对应模块的后续同步，本次未改动。

## 共享层变动

- `frame.js`：画面可用 `data-pending-counts="review:3,outbound:2"` 同时指定多个菜单的演示待办数量（数量为空不展示）；原 `data-pending-count` 不变。
- `menu.ops.js`：“出库与供数”增加演示待办数量 2，M2–M5 侧栏随之显示该角标。
- `tokens.css` / `components.css`：文末新增 M9 token 与 A42–A45。

## 实际核验

Chromium / Playwright：

- 31 屏 × 中英文 × 1280 / 1440 / 1920 px：无脚本错误、无整页横向溢出，操作列在视口内；中文 1440 px 起两张列表完整展示不需表内滚动，1280 px 与英文模式在表内横向滚动，申请编号与操作列固定。英文模式除演示账号姓名与业务原值外无中文。
- 主流程点击实测：列表行审核通过弹窗与 Esc 返回、详情审核通过后两个菜单角标 4 / 1 → 3 / 2、出库与重新出库各步角标、列表行重新出库、面包屑返回、分段切换、画面目录 31 项。
- 离线单文件由 `_shared/export.py` 生成，打开时无外部请求。
- 共享层回归：M1、M2、M3 两端、M4、M5、M6、M7b、M10 两端、M11 全部画面 × 中英文 × 三档宽度加载无脚本错误、无整页溢出；未重跑其业务流程。
