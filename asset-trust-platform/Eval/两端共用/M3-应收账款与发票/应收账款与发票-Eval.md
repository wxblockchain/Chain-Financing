**关键阻断项**（单列，不计入平均分，任一失败即不能发布）：

- B1 企业端越权或可见范围扩大：
  - 企业用户从接口或页面取得 F-M3-09 不允许的字段，或取得不属于本企业的应收账款；
  - “不存在”和“无权查看”能区分。
  - 依据：AC-M3-35、36、75；01 册 §3.6、§15.2。
- B2 一张内销发票形成了两笔应收账款，或按企业名称、登记号对应到平台企业（AC-M3-02、03；01 册 §4.1、§4.2）。
- B3 核心资料保护失效：
  - 冲突的新值覆盖了原资料；
  - 或“差异待核实”期间，M7a 读取到的状态允许发起申请。
  - 依据：AC-M3-28、46 场景 2；01 册 §14.1、§14.4。
- B4 无法折算时，以 0.00 USD 或原币数值代替美元金额（AC-M3-79；01 册 §3.3）。
  - 注意：按 `b7f930f6`，M11 当前“无可用汇率”时，比率和回款状态仍按原币判定，可以是“已收清”；这不算 B4 失败。
- B5 回款错计（按 `b7f930f6` 的口径核对）：
  - 外销收款、登记在其他发票下的收款、未审核的收款计入已收款；
  - 跨发票的收款按整笔计入，而不是按分配到本发票的金额；
  - 币种不同的回款按查看时的当前汇率计入，而不是按收付日期当日结束时适用的汇率；
  - 回款状态或已收款比率随 M11 当前汇率变化。唯一的例外是收付日期为今天的暂计回款：当天内按查看时适用的汇率暂计，当天 M11 生效新汇率后按新汇率暂计；当日结束后按当天最后时刻的汇率确定，之后不再变化；
  - 当日结束后，暂计回款没有按当天最后时刻的汇率确定，或者仍注明“暂计”；
  - 无法计入的回款（收付日期未提供、当时无可用汇率、币种没有汇率）被按 0 计入，或者因此判为“已收清”；
  - 1% 容差边界判错：未取舍的比率达到 99.00% 却判为“部分收款”，或低于 99.00% 却判为“已收清”。
  - 依据：AC-M3-20、21、53、60、61、77、80、81；01 册 §8.1、§8.2。
- B6 加载失败被展示成业务结论：列表、详情、回款记录或 M8 结果读取失败时，展示为“未收款”“暂无回款记录”“0.00%”“无”或“未取得”（AC-M3-08 场景 3、25、47 场景 5；01 册 §3.7）。

## 3. 通过线

以下数值都是**建议、待业务确认**。依据如下：

- M3 是规则明确的确定性功能，金额和状态的任何偏离都是缺陷；
- 错误成本高：M3 的金额、到期状态、回款状态和核心资料状态，被 M7a 的申请资格、M9 的推送条件和 M17 的业务总览直接引用，错误会传到外部机构；
- 兜底有限：本模块只读，运营不能在平台更正数据，只能回到 ERP 更正。

**统计与随机性**

- 确定性 Case 每次执行一次。失败后在干净环境重跑 1 次，用来排除环境问题；重跑通过时仍记为“不稳定”，要排查原因，不能直接算作通过。
- 涉及“今天”的 Case 一律注入平台时间，不按真实日期执行；汇率一律用 M11 桩控制。
- 并发类 Case（C-D1-02、C-D3-05）：每条重复 n 次，建议 n ≥ 50。零失败只说明失败率较低，**不能证明没有竞态**。零失败时，95% 单侧上界约为 3／n（n = 50 时约 6%）。比例指标用 Wilson 区间报告。
- 随机生成的计算组合：要求 100% 一致，不用比例描述。一旦出现不一致，把该组合固化为 P0 回归 Case。
  - 组合中要包括：多条 M11 汇率记录与不同的收付日期；比率落在 98.99%～99.01% 附近的回款合计；之后再改当前汇率，检查比率和回款状态不变。
- 版本比较按同一 Case ID 配对，看 Case 在新旧版本之间从通过变失败、从失败变通过的情况，不只比较总通过率。
- 本文没有执行数据，所以不填写任何区间、通过率或显著性结论。

**失败兜底**（发布判断之外的处置，建议）

- 阻断项失败：不能发布。修复后重跑该维度全部 Case，以及 M7a、M9 中引用 M3 状态的联调 Case。
- D2 计算失败：除修复外，要列出受影响的应收账款范围（币种、是否跨发票收款、是否转运），供运营判断已发起的申请是否受影响。
