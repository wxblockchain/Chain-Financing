## 1. 评估维度（5 个）

**评估范围**

- 被评对象：M7a 在测试或预发环境中的实现，包括：
  - 债权人的应收账款列表和应收账款详情；
  - 申请资格判断；
  - 单笔、批量发起申请；
  - 申请详情与当次依据；
  - 驳回后重新发起，以及到期自动关闭；
  - 本模块发出的 3 类站内消息。
- 不在范围内：下列内容的结果都可以用模拟结果注入，M7a 只判定是否按其取值正确展示和流转。
  - M3 的数据口径：起算日、到期日、回款、美元折算，以及 F-M3-15 各校验项本身的判定。F-M3-15 各项判得对不对，由 M3 Eval 的 D4 判定。
  - M7b 的确认和驳回，M9 的审核和推送，M10 的消息展示时效。
- 判定方式：M7a 是规则确定的系统，没有被测模型。判定以 code-based 为主；入口是否醒目、英文措辞是否得当由人工判定。LLM-as-judge 只用于英文文案的初筛，而且是可选的。
- P0 口径：沿用业务方已确认的“影响业务进程，或危及平台安全”（见 Eval 目录 README，2026-11-25，WS-672）。
- 假设：列表每页条数以原型为准，且多于 10 条。AC-M7a-21 需要一页里可申请的行超过 10 笔。

## 3. 通过线

以下数值都是**建议值，待业务确认**。

依据：M7a 的错误直接影响确权和融资，例如错发申请、重复申请、越权泄露，都属于 P0 口径中“影响业务进程，或危及平台安全”的情形。企业端只读，提交后不能撤回，出错后用户无法自行纠正。因此关键维度采用零容忍。

### 3.1 单例判定

- 一个判定点的全部断言都满足，才算通过。一条验收含多个场景的，全部场景都满足才算通过（沿用 04 册规则）。
- 不计入分母、单独列出的有两类：待验用例；依赖模块未交付、且没有注入模拟结果的用例。
- 并发、竞态类用例按重复次数统计，只要失败一次，该用例即判为不通过。

### 3.2 维度门槛

| 维度 | 指标（分子 / 分母） | 建议门槛 | 状态 |
| --- | --- | --- | --- |
| D1 | 资格结论与原因序列都正确的判定点数 / D1 全部判定点数（含全量组合） | 100% | 建议，待业务确认 |
| D2 | 通过的判定点数 / D2 全部判定点数；并发重放中出现第 2 笔处理中申请的次数 | 100%；0 次 | 建议，待业务确认 |
| D2 关闭时效 | 到期时点后 5 分钟内关闭的申请数 / 跨过到期时点的处理中申请数（每轮至少 50 笔） | 100% | 5 分钟来自 PRD §11 和 M10；要求每笔都达到是建议，待确认 |
| D3（code） | 通过的字段、取值与快照断言数 / D3 code 判定点数 | 100% | 建议，待业务确认 |
| D3（human） | rubric 判为通过的项数 / D3 人工判定项数 | P0、P1 为 0；P2（措辞、视觉强弱）不超过 3 个，且每个都有修复计划 | 建议，待业务确认 |
| D4 | 正确拒绝且响应无法区分的格子数 / 越权矩阵全部格子数 | 100% | 建议，待业务确认 |
| D5（code） | 触发、收件人、去重、业务值都正确的判定点数 / D5 code 判定点数 | 100% | 建议，待业务确认 |
| D5（文案） | 双语审校判定中英一致的条数 / 本模块文案条数 | 100%；原型未定稿的措辞先只判含义 | 建议，待业务确认 |

### 3.3 阻断项（出现任意一次即不能发布，不参与平均）

1. 不可申请或“暂无法判断”的应收账款生成了申请；或“暂无法判断”被当作“通过”。
2. 同一应收账款同时有两笔处理中的申请，或申请编号重复。
3. 状态发生表外转换，或终态再次变化；到期时点之后的确认、驳回、审核通过生效。
4. 任意一次跨企业的数据可见，或能从响应推断记录是否存在。
5. 加载失败被显示为“可申请”“未申请”“未收款”或金额 0。
6. 企业端出现不可见信息：回款账号与凭证、预警、核心资料差异明细、运营审核人或审核说明。
7. 当次依据在提交后被改写。
8. 消息发给了错误的企业，或消息中带原件、下载地址、收款账户。

### 3.4 整体发布门槛

D1～D5 全部达到维度门槛，阻断项为 0；待验用例已列明，且业务方接受带着这些待验项发布。

兜底：本期没有撤回功能，PRD 也没有定义线上兜底。上线后如发现阻断类问题，例如需要暂停发起入口，用什么方式止损由业务方决定；Eval 只登记这一需求。

### 3.5 不确定性说明

- 规则类判定点都是确定性的，100% 指全部通过，不作概率解释。
- 并发和竞态只能做有限次重放，零失败不等于风险为零。按 Wilson 方法，0/200 的 95% 置信上界约为 1.9%，0/20 约为 16%。因此建议每项并发重放不少于 200 次，上线后再持续监控重复申请数。以上是计算方法和样本量建议，不是评测结果。

- **分歧仲裁**：两人结论不一致时，由 PRD 负责人仲裁。属于规则不清的，记为待确认项，确认前该项不判为通过。

**L3 线上验证**（建议；是否需要做，待业务确认）

- **一致性指标**：重复处理中申请数应为 0；到期关闭延迟的最大值不超过 5 分钟；越权访问告警数；申请资格为“暂无法判断”的应收账款占比及持续时长。最后一项用来观察 M3 读取失败的频率。
- **体验代理指标**：驳回原因属于资料问题的占比；同一笔应收账款被驳回后重新发起的次数；从详情进入申请详情的路径使用情况。这些只是代理指标，不等于“确权效率提升”。后者的口径需要业务方另定，例如从发起申请到运营审核通过的时长。
- **统计集与风险集分开管理**：线上指标按真实流量统计，不和第 2 节那套人为调高了边界与对抗占比的风险集混在一起算。

- 已删除能力的回归用例至少保留两个大版本，例如“应收账款信息缺失”的旧写法、“申请记录”菜单。
