## 1. 评估维度（3–5 个）

**评估范围与依据**

- 需求来源：[01 功能与业务规则][p01]、[02 流程图与状态机][p02]、[03 消息通知][p03]、[04 验收][p04]。下文用 `§x` 指 01 册章节，用 `AC-xx` 指 04 册的 `AC-M15-xx`。
- 被评对象：M15 的研发实现，包括接口状态与调用记录的计算和展示、资产推送结果的计算和展示、告警消息与待办数量、监控概览与大屏的统计，以及权限、时区、缺失值和失败时的表现。
- 判定方式：M15 只展示和告警，结果由确定的规则得出，不含模型生成内容，因此**不使用 LLM-as-judge**。测试按 PRD 口径独立实现一份事件回放程序（下称 oracle）：输入接口调用事件序列和资产推送事件序列，输出每个接口的状态、各项次数、应发的告警、待办数量、每笔资产的推送结果和概览各指标，与页面和消息逐项比对。版面、文案与设计约束由人工按二元 rubric 判定。
- 判定口径：时间按展示精度（分钟）比对，比率按两位小数、向下截取比对，不设容差；“-”、0 与业务状态文字（暂无调用、从未成功、暂无推送等）不能互相替代。
- 不在范围内：§1.2“本期不做”的内容；取数方式与频率；资产与其他平台怎样交互、什么情况下算成功（对外提供后续单独定义，见 §11 与 M9 [对外提供](../../../PRD/运营端/M9-运营审核/01-运营审核-PRD.md#external-provision)）；M2、M3、M9、M10 自身规则（只核对 M15 的引用结果）；原型本身；响应时间与告警送达时延（PRD 未设目标，L3 只观察记录）。
- 记录范围（01 册开头）：数据接入记录接入了哪些接口及每个接口的每一次调用；数据推送记录本平台应收账款数据与哪些平台有过交互及每一次交互；未审核通过资产的交互不记录、不展示，也不计入平台情况、概览的最近一次推送时间和推送次数；从未交互过的资产不展示，链接直接打开时按 M2 F-OP-11 不返回任何内容。
- 待用户决定（PRD 输出在 WS-681 提出，确认前按现行正文评估）：决定 1 是否恢复“取得条数”；决定 2 是否删除 A～G 中超出“只记录”范围的内容（如今日调用次数、未接收、概览的部分统计、大屏）。确认后，受影响的 D1、D3、D4 维度、用例与阻断项随 PRD 新提交同步。两项均列入第 3 节待用户确认（U-M15-01、02）。
- 跨模块文档不一致（不影响 M15 判定）：合同信息（M4）§“依赖”与提单信息（M12）§“依赖”写数据监控“展示……接口的取得与未接收情况”，M15 现行正文不展示取得条数。随决定 1 的结果，由 M4、M12 维护人同步，本 Eval 只登记。

**阻断项**（不与任何维度平均，任意一条出现即不能发布；按已确认的 P0 口径，B1～B7 都属于 P0）

- B1 结果未知或加载失败显示为成功、正常或 0：调用结果未返回却计为成功；列表、详情、待办或大屏取数失败时显示“正常”、0 次或 0（§1“失败不显示成功”、§3.3、§9.4）。
- B2 接口进入异常时没有发出 M15-NT01，或同一次进入异常发出多条（§8、03 册）。
- B3 企业账号、锁定或待首登改密账号能取到本模块任何内容；页面或消息展示失败原因中账号、密钥的原值；消息中出现接口地址（§3.1、§3.2、03 册“不得出现”）。
- B4 推送结果误判：每次都失败的资产显示“成功”；成功过的资产显示“失败”；从未交互的资产出现在列表；未获准平台或未审核通过资产的交互计入任何资产的记录、平台最近一次推送时间或推送次数（§6、§7、§9.3）。
- B5 大屏自动刷新失败后把旧数据当作最新数据（数据更新时间改为当前时间、没有提示），或展示为 0（§9.4）。
- B6 本模块出现任何办理或修改操作：新增、编辑、删除接口，调整配置，手动取数或推送，撤回、删除记录（§1“只看不改”）。
- B7 调用记录遗漏失败：注入的失败调用在调用记录、今日次数或概览中缺失（§11“调用结果的记录须完整、不遗漏失败”）。

## 4. 标注方法

M15 的预期结果由 PRD 规则唯一确定。这里的“标注”指编写并复核每条用例的期望值，以及对画面做人工判定。不使用模型判定，因此不需要校准模型 judge。

**阶段与角色**

| 阶段 | 做什么 | 角色 | 产物 |
| --- | --- | --- | --- |
| 启动 | 测试按 PRD 独立实现 oracle（不复用研发代码），用它重算 S0 期望值并与 04 册比对 | 测试编写，PRD 复核口径 | oracle、S0 比对记录 |
| 启动 | 复核 S1 期望值：两名测试分别手算，再与 oracle 结果比对，三者一致才入库 | 测试 A、B 独立标注，PRD 仲裁 | S1 v1（标“合成”） |
| 扩展 | 编写 S2 生成规则与不变量，例如：今日成功 + 今日失败 = 今日已返回调用数；角标 = 状态为异常的接口数；进入异常的次数 = NT01 条数；成功资产数 + 失败资产数 = 有推送记录的资产数；推送结果为成功 ⇔ 至少一条成功记录 | 测试 | S2 生成规则 |
| 持续 | 联调与上线后对账：调用日志、推送记录、告警逐条比对 | 测试比对，研发提供日志，运营协助核实 | S3 对账记录 |

**分歧仲裁**：oracle、手算与实现不一致时，先按 PRD 原文判定哪一方错。PRD 没写到的情况记为新的 Q-EV-M15 交 PRD 补充，测试和研发不自行定口径；仲裁结果同时更新用例与 oracle。标注分歧的原因按“读错 PRD／PRD 有歧义／测试数据错”记录。

**人工 rubric**（每项二元判定：通过或不通过）

| 检查项 | 通过（正例） | 不通过（反例） |
| --- | --- | --- |
| R1 只读 | 三个菜单都没有新增、编辑、删除、配置、取数、推送、撤回入口；行操作只有“查看” | 出现“重新推送”“编辑接口”或批量勾选 |
| R2 已删除内容 | 推送列表与详情没有推送条件、拒绝或失败原因、待推送、推送方式、上链状态；调用记录没有取得条数 | 旧版原型中的“推送方式”列出现在实现中 |
| R3 缺失值与业务状态 | 取不到、算不出的值为“-”；暂无接口、暂无调用、从未成功、暂无调用记录、暂无推送记录、暂无推送照常显示文字 | “从未成功”显示为“-”；成功率无法计算显示 0.00% |
| R4 大屏失败提示 | 刷新失败提示在大屏上醒目可见（远处可读），包含数据时间；异常接口个数醒目 | 提示只在角落以小字出现，或被图表遮挡 |
| R5 数据来源可扩展 | 接入统计（概览与大屏）的标题、图例和说明没有写死“ERP”；排行、新鲜度能标明来源 | 指标标题为“ERP 调用次数”；增加来源后需要改版式才能展示 |
| R6 详情上下布局 | 推送详情、调用记录的各信息分区（概要、推送情况或调用概要、记录表）上下排列 | 分区左右并排，如概要在左、推送记录在右 |

- R6 按 01 册设计约束（`362988db`，Q-EV-M15-08）判定：只看详情的各分区是上下排列还是左右并排；分区宽度、是否用页签由设计决定，不作为判定条件；分区内部的字段排布（如概要内对象字段在左、状态在右）不算左右布局。原型 `82f78ad7` 的推送详情与调用记录符合正例。
- 概览定位标签（Q-EV-M15-10）在 PRD 写入前不判定；写入后增加 R7：正例为标签只定位到概览内对应统计分区、大屏没有标签；反例为点击后跳转到其他页面或模块。
- 人工判定由测试执行，覆盖中英文 × 1280、1440、1920 px；每次 release 由设计或 PRD 随机抽 20% 画面复审，结论不一致时按分歧仲裁处理并修订 rubric 正反例。可统计复审一致率（结论相同的画面数 / 复审画面数），目前没有执行数据，不填写数值。
