**排除规则**：fixture 本身有误（经第 4 节仲裁确认）的 case 不计入分母，修正 fixture 后重跑；“待确认”“待验”用例同样不计入分母。两类都要在报告中列出，不能静默剔除。

**统计与不确定性**：离线集合是规则覆盖测试，不是抽样统计，结论只说“覆盖到的规则组合都正确”，不外推为错误率。L3 对账是抽样，用 Wilson 区间报告不一致率的 95% 置信区间。计算方法举例：如果 300 辆车中有 0 处不一致，Wilson 95% 上界约为 1.3%。这只说明真实不一致率很可能低于这个值，**不证明没有错误**。版本对比时用同一批 fixture 和同一批抽样车辆做配对比较。目前没有执行数据，不填区间。

**失败兜底**（用户已确认按建议执行，2026-11-25，WS-674）：PRD 没有定义功能开关或降级方式，按以下方式处理：L3 对账发现阻断项时，回滚到上一个通过的版本；发现非阻断的字段不一致时，由产品判断是否需要先在运营侧发说明，并在下一个版本修复。

## 4. 标注方法

M5 没有主观质量需要打分，“标注”指两件事：为 fixture **编写预期结果**（预言机），以及按二元 rubric **人工评审页面承载**。

**角色**

| 角色 | 职责 |
| --- | --- |
| 测试（标注人 A） | 依据 PRD 为每个 case 编写前置数据和预期结果，实现状态预言机 |
| 测试或研发（标注人 B，不是被测功能的开发者） | 独立推导同一批 case 的预期结果，与 A 对比 |
| 产品（PRD 负责人） | 仲裁分歧。PRD 没有覆盖的情况，进入 PRD 待确认，由业务方裁定后修订 PRD，再更新预期；Eval 不自行定规则 |
| 研发（ERP 对接） | 确认 fixture 字段与 ERP 字段的映射（出入库单号、业务日期、审核时间、厂家出库日期等） |
| 运营人员 | L3 阶段对照 ERP 原单逐字段核对抽样车辆 |
| M15 负责人 | 确认核对“未接收”记录时使用的调用记录口径 |
| M8 负责人 | 确认关联预警对数时使用的 M8 接口口径 |

**阶段**

- 启动：A、B 独立标注全部补充集和 P0 冒烟集的预期结果。不一致的由产品仲裁，记录不一致原因（读错 PRD / PRD 有歧义 / fixture 错）。PRD 有歧义的转成待确认项。
- 扩展：新增用例由 A 标注、B 抽 20% 复核；连续两轮复核没有分歧后，降到抽 10%。
- 持续：PRD 每次修订，按变更章节找出受影响的用例，重新标注；每条预期结果都注明所依据的 PRD commit 和章节。
- 隔离：预期结果必须从 PRD 推导，**禁止拿系统的实际输出作为预期**（即不允许“快照通过”）。预言机由测试实现，不复用被测代码。

**人工二元 rubric**（只用于 D5 的页面承载，以及 D2、D4 的抽查；每项只判通过或不通过）

| 项 | 通过（正例） | 不通过（反例） | 严重程度 |
| --- | --- | --- | --- |
| 列表字段 | 只有 VIN、当前物流节点、在库情况、所属应收账款、外销收款情况、预警六项业务信息 | 出现外采合同号、提单号、外销合同号、外销客户或车辆属性 | P1 |
| 详情结构 | 概要 → 进度与核对 → 明细；明细在价格链下方，五组依次展示，可通过导航定位；物流时间线竖排，最新的在最上方，与价格链、明细上下排列 | 明细可以收起或展开，或改为页签切换；时间线最早的在上方；时间线与价格链、明细左右并排 | P1 |
| 缺失值与业务状态 | 缺失显示“-”，“无法折算”“无可用汇率”写在“-”下方；“未开票”“暂无保单”等照常显示文字 | 缺失显示空白、0、N/A；业务状态被显示成“-” | P0（涉及金额时）/ P1 |
| 编号可点击 | 规则中可跳转的编号可以点击；出入库单号和不可承载的清关单号是纯文本 | 出入库单号可以点击；可跳转的编号不能点 | P1 |
| 定位可见 | 跳转后目标单据或本车在可视区域内被定位 | 落在目标详情顶部，看不到对应的单据或车辆 | P2 |
| 无风控判断 | 价格倒挂、收款不足时没有任何提示或颜色区分 | 出现提示或颜色区分 | P0（B7） |
| 只读 | 没有新增、编辑、补录、处理预警的入口 | 有任一入口 | P0（B7） |
| VIN 展示 | 列表、详情、查找结果中的 VIN 都是规范写法（没有空白、字母大写） | 出现小写或带空格的 VIN | P1 |
| 外销客户 | 名称按 ERP 原值完整展示，个人客户也不脱敏；不展示名称以外的个人信息 | 名称被打码；展示电话、证件号等 | P0（B6） |

严重程度：P0 沿用 [Eval 目录](../../README.md)中已确认的口径“影响业务进程，或危及平台安全”，在本模块中包括触发阻断项、金额、归属或权限错误；P1 = 违反 PRD 中已确定的展示规则；P2 = 不影响信息正确性的视觉问题。

**评审范围**：按原型已有的核验口径，覆盖 1280、1440、1920 px 三种宽度，中英文各一遍。人工评审员需要先在 5 个已知正例、5 个已知反例上与产品对齐，判定全部一致后再开始正式评审。

**LLM-as-judge**：本期不用。如果以后有人提出用模型辅助核对截图，需要先用人工标注的校准集（与评测集分开）做一致性验证；在没有校准数据前，不能声称模型判定可靠。
