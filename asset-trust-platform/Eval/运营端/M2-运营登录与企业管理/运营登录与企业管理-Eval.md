## 2. Case 数量与覆盖

**数量是计划，没有已执行 case。** 启动集 136 条原子 case：D1 42、D2 30、D3 20、D4 30、D5 14。下限是 48 条 AC 全部子条件拆分后的数量；拆分不足 136 条时按下列切片补足，超过时以拆分结果为准，不为凑数删减场景。稳态每维度 40～80 条，合计 220～350 条，主要扩充并发、时钟边界、跨模块联调与回流 case。数量按 U2 已确认。

## 3. 通过线

**单例判定。** 预期行为全部满足、禁止行为都没出现才算通过；模板行拆分后逐个判定，多数子场景通过不代表整行通过。无法执行的记“未验证”；环境原因造成无法判定的记“无效”，需研发说明并经测试确认后重跑。产品超时、把未发出的邮件说成已发出等属于有效失败，不能排除。

**级别。** P0 口径由业务方确认沿用代币发行平台的“影响业务进程，或危及平台安全”（2026-11-25，WS-672）；P1、P2 由本 Eval 定义，不作为 PRD 待确认项。同一 case 涉及多个风险时取最高级别；新出现问题的业务影响有歧义时由产品仲裁。

**指标口径。** 维度通过率 ＝ 有效通过的原子 case 数 ÷ 有效执行的原子 case 数；按 P0／P1／P2、账号状态、入驻进度、关联状态、入口（页面／接口）、界面语言、模拟／真实依赖分别列出，不合并掩盖。未验证、无效、跳过单列数量和原因。无效占计划执行数超过 5% 时暂停本轮结论、修复环境后重跑（U1）。

**重复与统计。** 并发、时钟、会话和邮件 case 各重复 3 次（U2），任一次产品失败即该 case 失败；固定账号快照、ERP 数据快照、时间基点与请求顺序。登录失败枚举（EV-M2-01、41）需对有效、无效、格式不正确的邮箱随机交错做配对时延观察，每类邮箱至少 200 次（U2），记录样本量和分布；测量窗口与可区分容差属于测量技术，由安全负责人按环境精度确定，不声称绝无侧信道。规则断言逐条判定，不用置信区间替代；人工复核比例和 L3 比例按分子／分母报告 Wilson 95% 区间（置信水平按 U5），小样本零失败不证明低风险。版本比较固定同一 case 集与环境逐例配对，新增 case 单列；没有稳定基线前不报告“提升”。

**失败兜底（按 PRD 核对是否生效）。** 邀请邮件失败：企业与账号不回滚，可重发邀请；重发邮件失败：新初始密码已生效，可再次执行；保存或校验失败：保留最近一次成功结果，有效输入不丢；企业用户无法使用登录邮箱：开发人员线下更正并交付新邮箱、新密码；关联错误：运营取消关联（有处理中申请时须等申请结束）；名称不一致：M8 RK-34 兜底识别，开发人员线下处理。“无法使用登录邮箱”的新密码经过开发人员之手且不强制改密，这是 PRD 已确认的规则，Eval 不判为失败，只在 L3 观察企业是否自行改密。线上出现 B 类问题时按 U6 停用相关入口或回退版本并保留证据，本文不执行处置。
