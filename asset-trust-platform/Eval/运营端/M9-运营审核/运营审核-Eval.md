## 1. 评估维度（3–5 个）

**评估范围与基线**

- 需求范围：[M9 PRD](../../../PRD/运营端/M9-运营审核/01-运营审核-PRD.md) 四册，即 01 功能与业务规则、02 流程图与状态机、03 消息通知（M9-NT01、M9-NT03）、04 验收（26 条 AC）。需求追溯：F-M9-01 列表与待办数量、F-M9-02 申请详情与审核依据、F-M9-03 审核通过（含 §6.1 审核条件、§6.2 审核说明、§6.3 提交与上链、§6.4 上链数据），以及 §7 资料变化、§8 状态组合、§9 操作留痕。
- 本版纳入的 PRD 演变（`5d2ec4f3` → `b1697243` → `95c37ea7` → `65662de1` → `81465438`）：
  - 只保留运营审核，上链成功才算审核通过；上链失败（含超时）不算通过，申请仍为“待运营审核”，可再次提交，不自动重新上链。
  - 新增上链等待时限：超过时限按上链失败处理，原因“上链超时未返回结果”；超时后才返回的结果只记录。
  - 用户在 WS-668 裁定（Q-M9-07）：到期以审核提交的时刻为界。到期时点前提交、之后才上链成功的，审核照常生效；到期时点及之后不提供、不受理审核通过；到期时正在上链的不关闭，等待结果，失败（含超时）时按 M7a 在失败结果返回时关闭，只记录、不发 M9-NT03。
  - 列表与详情统一按“满足审核条件”提供“审核通过”，详情常驻展示全部不能审核的原因。
  - Q-M9-08、Q-M9-09 已关闭；PRD 01 册第 10 节现无待确认事项。
- 不在范围内：
  - Q-M9-08 资产对外提供（怎样提供给其他平台、提供哪些内容、什么情况算成功）：用户确定“后续单独定义”，本 Eval 只登记为范围外，不设维度和 Case。
  - 推送、调取、存证、推送资格与推送进度：已从 M9 删除，不评估；如实现中仍出现这些入口或状态，按 D4 判为多余功能。
  - M7a 的申请生成与到期关闭本身、M7b 的债务人确认、M3 的资料校验计算、M8 的预警生成与阻断判定、M10 消息中心本身：由各自 Eval 判定。本文只检查 M9 对这些结果的引用、展示与处理；上游未交付前可用模拟结果驱动（同 04 册说明）。
  - 万纳连的写入方式、上链凭证包含哪些项、失败与超时如何返回、等待时限的取值：由研发确认（01 §6.4、§10 依赖）。本文用参数 T 表示等待时限，Case 按 T 前后取值，不预设具体时长。
- 产品性质：确定性的业务规则模块，没有模型输出。各维度以 code-based 判定为主，人工只判文案、双语和视觉呈现。不使用 LLM-as-judge 作阻断判定。
- 到期时点口径：按 M3 §7.2，到期时点为到期日当天 UTC+1 的 24:00。审核提交以平台收到提交的时刻为界：早于 24:00:00.000 收到且满足条件的形成审核提交；等于或晚于的一律不受理（01 §6.1）。上链失败结果返回时“已到达到期时点”含恰好等于到期时点。
- P0 口径：沿用业务方已确认的“影响业务进程，或危及平台安全”（见 Eval 目录 README，2026-11-25，WS-672）。

## 3. 通过线

**判定层级**

- 单例：每条用例二元判定，预期结果的全部断言都满足才算通过（同 04 册“一条验收写了多个场景时，全部场景都满足才算通过”）。
- 维度通过率：分子是该维度判定为通过的用例数；分母是该维度应执行的用例数，排除标“待验”的用例或断言。被排除的单独列清单，不计入分母，也不能算作通过。
- 切片：按维度、AC 编号、上链模拟结果（成功／失败带原因／失败不带原因／时限内未返回／超时／超时后返回）、到期相对位置（到期前／到期时上链中／到期后）、语言分别统计。任一切片低于门槛即未达标，不能用整体通过率抵消。

**不确定性与重复试验**

- 确定性用例每个版本执行一次。并发、幂等与回调重放类用例（S08、S09、S12、AC-M9-16 场景 1 与 5）每个 release 各重复 100 次，要求零失败（建议，待用户确认 U-M9-02）。
- 零失败不等于没有风险：n 次全部通过时，单次失败概率的 95% 置信上界约为 3/n（三法则），100 次约 3%。所以“同一时间最多一个上链中、最多一次通过”还需要研发对唯一约束或加锁的代码评审作为补充证据。
- 比例指标（如 L3 上链失败率、超时率）给区间时用 Wilson 区间；版本比较用同一套 fixture、同一时钟与桩脚本配对比较。目前没有执行数据，本文不填写任何通过率、区间或提升。

## 4. 标注方法

本模块的“标注”就是为每条用例写出可机读的预期结果（状态、计数、消息、载荷），以及人工判定文案时用的 rubric。

**角色与流程**

| 阶段 | 做什么 | 角色 |
| --- | --- | --- |
| 启动 | 按 PRD `81465438` 为验收场景集和补充风险集写预期结果，每条注明 PRD 条款；上链载荷期望值按当次依据 fixture 独立计算（含哈希） | 测试负责人写，另一名测试人员逐条交叉复核；载荷期望由第三人独立计算后比对 |
| 口径分歧 | 两人结论不一致或 PRD 没写明时，编号记入第 3 节“需要 PRD 确认的口径”，交 PRD 负责方裁定；裁定前标“待验” | PRD 负责方（PRD 输出 agent）；需要业务取舍的由产品负责人 cuiluyao 决定 |
| 依赖确认 | 等待时限 T、上链凭证包含的项、失败与超时的返回格式确认后，写入用例参数与凭证展示断言 | 研发 |
| 文案与双语 | 按下面的 rubric 判定中英文 | 双语评审员 1 名，产品抽查 |
| 扩展 | 上游修订、万纳连联调发现、线上缺陷回流时新增用例，同样双人复核 | 测试小队 |
| 持续 | 每个 release 抽 10% 已有用例复核预期是否仍符合当前 PRD（建议，U-M9-07） | 测试负责人 |

**文案与双语 rubric（二元判定）**

| 检查项 | 通过 | 不通过 |
| --- | --- | --- |
| 不能审核的原因用 PRD 原词 | “应收账款已到期，该申请已关闭”“该申请正在上链，请稍后查看结果”逐字一致 | 改写成“已过期”“处理中” |
| 英文与中文含义一致（01 §3.2） | NT03 英文保留“has not been approved and is still pending operations review” | 英文漏掉“尚未审核通过”或“上链成功才算审核通过”的限制语义 |
| 业务原文不翻译 | 万纳连返回的失败原因、审核说明、企业名称在 English 界面按原文显示 | 被机器翻译或音译 |
| 确认弹窗的提示完整 | 写明“上链成功才算审核通过；审核通过后不能撤回，不会处理任何风控预警” | 缺少“上链成功才算通过”或“不能撤回” |
| 不出现已删除概念 | 页面与消息中没有“推送”“调取”“存证状态”“审核未生效” | 出现任一已删除概念 |
| 缺失值 | 运营端按 M3 以“-”展示 | 空白、“N/A”、“0” |

- 证据要求：每个不通过的判定附截图、DOM 片段或拦截到的载荷片段，并写明 PRD 条款。
- LLM-as-judge：本模块不使用。如之后要用于中英文含义预筛，须先由双语评审员人工标注至少 30 对文案作为校准集（校准集不得用于调提示词），一致率达标后才可预筛，结论仍由人工复核；D1～D5 的阻断判定一律不用 LLM。目前没有校准数据，不能认为 judge 可靠。

## 5. 跑评频率

以下都是建议节奏（待用户确认 U-M9-05、U-M9-06），只描述触发条件、责任角色和产物，不接入任何自动化。

| 层级 | 触发 | 范围 | 责任角色 | 产物 |
| --- | --- | --- | --- | --- |
| L1 确定性检查 | 每次 commit 或合并请求 | 接口层 D1 条件与到期边界、D2 状态机（桩驱动的全部上链结果 × 到期相对位置）、D3 载荷黑名单与逐项比对、D5 越权与消息触发去重；不依赖 UI | 研发 | 用例通过或失败清单；有阻断失败时不合并 |
| L2 完整验收 | 每次提测和发版 | 全部验收场景集、补充风险集与历史失败集，含 UI、中英文、可控时钟跨过到期时点与 T、并发与回调重放各 100 次、故障注入、文案 rubric | 测试小队；双语评审员 | 按维度与切片的通过率、“待验”与“依赖未就绪”清单、失败证据 |
| 万纳连联调 | 研发确认 T 与返回方式后一次；之后对接代码或万纳连环境变化时 | 真实上链样本（U-M9-04）、凭证展示项、失败与超时的真实返回 | 研发；测试小队 | 载荷与凭证核对记录 |
| 每周回归 | 每周一次；M2、M3、M7a、M7b、M8、M10 的 PRD 或实现入库，或万纳连对接变更时加跑 | L1 全量，加上与上游相关的 L2 子集：审核条件读取、到期关闭、M8 阻断、消息前往 | 测试小队 | 回归报告；与上游的口径冲突转给对应模块 |
| 上游口径复审 | 每月一次；M3、M7a、M8 的到期、资料校验、阻断规则修订时 | 复审预期是否仍符合当前 PRD，更新受影响用例 | 测试负责人；PRD 负责方 | 用例集新版本和变更记录 |

- 本模块没有模型，通用 Eval 节奏中的“每月 frontier eval”不适用，改为上表的“上游口径复审”。
- L3 线上验证（上线后，只设计、不接入）：
  - 正确性守护指标，期望恒为 0：同一申请同时有两个“上链中”或两次审核通过的数量；申请为“运营审核通过”但没有上链成功记录的数量；到期时点及之后受理的审核提交数量；载荷黑名单命中次数；企业会话访问 M9 接口成功的次数。出现 1 例按 U-M9-06 处置并回流为回归用例。
  - 观察指标，不作为 Eval 通过线：上链失败率与超时率（分子为失败或超时的审核提交数，分母为审核提交总数，按日、周统计，Wilson 区间）、上链耗时分布（P50、P95，对照 T）、到期时正在上链的笔数、到期关闭前未审核的申请占比。失败率或超时率升高先归因万纳连与对接，不直接归因审核规则；统计用真实流量，不能用第 2 节加权过的风险覆盖集解释整体表现。
- 失败回流：线上缺陷、联调问题和测试中的失败都写成用例，类别记“历史失败”，来源写真实缺陷号或工单号，经双人复核后入库；合成用例与真实失败分开标记。
- 版本管理：用例集版本与 PRD 提交绑定，当前为 `81465438`。Q-EV-M9-01～06 裁定入库后升版，标记受影响用例并重写预期，保留旧版本用于追溯。风险覆盖集（第 2 节）与 L3 真实流量统计集分开管理。
