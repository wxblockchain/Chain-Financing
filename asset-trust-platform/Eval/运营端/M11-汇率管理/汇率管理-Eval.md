## 2. Case 数量与覆盖

**数量是计划，没有已执行 case。** 22 条 AC 的场景与样本拆分后约 90 条原子 case（FX-AC-11 十六个汇率值与输入格式样本、FX-AC-12 十二个文字样本、FX-AC-21 十个取值点、FX-AC-10 七个变动幅度样本占比最大），再补 PRD 派生 case，启动集约 125 条：D1 40、D2 33、D3 24、D4 18、D5 10。拆分结果超过计划时以拆分结果为准，不为凑数删减场景。稳态每维度 30～50 条，合计 160～220 条，主要扩充并发与重复提交的时序变体、取舍边界、时区与语言组合、使用方联调和回流 case。启动集与稳态规模已确认（用户，2026-11-26，WS-668），见 U-M11-04。

**启动集覆盖配比（风险覆盖集，计划）：** 正常约 38、边界约 48、异常与对抗约 31、OOD 约 8；历史失败 0。没有收到真实线上或测试失败材料，因此不设历史失败 case，也不据此推断产品没有失败。本模块规则简单、但口径被全平台使用，主要风险在“输入被静默改值”“并发与重复提交破坏只增不改”“T 判定错位”，所以边界与对抗占比较高；这个人为配比不代表真实流量，L3 另用真实使用情况统计。

**必需切片（按需组合，不要求全笛卡尔积）：**

- 环境：从未设置过汇率；只有 1 条；3 条以上；超过一页（原型每页 10 条，PRD 要求列出全部）。
- 汇率值：AC 样本（1535.84、1535.8、1535.80、1536、1540.20、1520.00、1535.123、0.01、0.001、0、-1、非数字、空）；与当前值相等的不同写法；输入格式样本（首尾空格、千分位、全角、正号、科学计数法、前导零、“1540.”、“1540.200”、“.5”）；超过最大值（研发确定后）。
- 文字：来源说明 0／1／100／101 个字符、只有空格、前后带空格、汉字字母与表情符号混合 100 个字符；备注 0／200／201 个字符、只有空格和换行、含中间换行共 200 个字符。
- 变动幅度：正、负、正负方向的进位临界值（±0.005%）、取舍后为 ±0.00、极大（+900.00%、+15,358,300.00%）、接近 −100%。

## 3. 通过线

**单例判定。** 预期行为全部满足、禁止行为都没出现才算通过；模板行拆分后逐个判定，多数子场景通过不代表整行通过。挂起的子条件（目前只有“超过最大值”，见 EV-M11-04 与 FX-AC-11 场景二）记“待验”，不计入分子分母，单列数量。无法执行的记“未验证”；环境原因造成无法判定的记“无效”，需研发说明并经测试确认后重跑。

| D2 并发与重复提交 | 除 P0 全过外，每个时序 case（EV-M11-12～17、31、35）重复执行不少于 20 次，任一次失败即该 case 失败 | 竞态问题偶发，单次通过不代表没有问题 |
| D4 使用方联调 | 除 P0 全过外，至少与一个“取当前汇率”的使用方（如 M5）和一个“取某一时刻”的使用方（如 M14）完成真实联调，取到的编号与本模块记录一致；联调未执行时 D4 不能判整体通过 | 模拟接口一致不证明使用方拿到的一致 |
| 各维度 P1 | 通过率 ≥ 95%；未通过的逐条建缺陷，由产品说明影响与兜底，评审放行 | 有恢复路径的偏差可以评审放行 |
| P2 | 不设发布阈值，保留缺陷与修复计划 | 错误成本低 |
| 完整性 | 22 条 AC 全部场景映射率 100%；必需 case 无未验证；P0 相对上一版无回归；“待验”项在研发确定最大值后补跑 | 少跑不能换来更高通过率 |

**指标口径。** 维度通过率 ＝ 有效通过的原子 case 数 ÷ 有效执行的原子 case 数（不含待验、未验证、无效）；按 P0／P1／P2、环境（未设置／已有）、入口（页面／直接 URL／接口）、界面语言、本人时区、模拟取值／使用方联调分别列出，不合并掩盖。待验、未验证、无效单列数量和原因。无效占计划执行数超过 5% 时暂停本轮结论、修复环境后重跑（已确认（用户，2026-11-26，WS-668），见 U-M11-06）。

**重复与统计。** 规则断言为确定性结果，逐条判定，不用置信区间替代；固定账号快照（姓名、时区、状态）与汇率记录快照。并发、重复提交与保存中取值（EV-M11-12～17、31、35）按上表重复执行；重复 n 次零失败只说明该时序下未复现，不证明低风险，例如 0/20 的 Wilson 95% 区间上限约为 16%，报告时写明 n 与区间。人工复核比例和 L3 比例按分子／分母报告 Wilson 95% 区间（已确认（用户，2026-11-26，WS-668），见 U-M11-06）。版本比较固定同一 case 集与环境逐例配对，新增 case 单列；没有稳定基线前不报告“提升”。

**失败兜底（按 PRD 核对是否生效）。** 误录：不能修改，只能再更新一次纠正，误录区间内的取值保持可追溯；保存失败：不保存、填写保留、可再次提交；并发：不保存、展示最新值、重新确认；登录结束：不保存，按 M2 重新登录。线上出现 B 类问题时，先暂停更新入口或回退版本并保留证据（含汇率记录快照与使用方取值日志）；已被错误汇率影响的换算由各使用方评估；修复后按 L2 全量重跑（已确认（用户，2026-11-26，WS-668），见 U-M11-09）。本文不执行处置。

## 4. 标注方法

| 角色 | 职责 |
| --- | --- |
| PRD 输出／产品负责人 | 解释规则；已定稿 Q-EV-M11-01～08，新的口径问题按 PRD 流程定稿；仲裁业务预期与级别歧义 |
| 测试负责人 | 拆分 22 条 AC、补齐启动集与追溯矩阵；准备账号与汇率记录快照；维护十进制变动幅度参考实现；设计并发与重复提交的时序脚本；按 U-M11-03～05 执行数量、重复次数与抽样 |
| 研发 | 提供事实证据（记录的编号、生效时间与维护人、并发判定与幂等的依据、对外取值的原始返回、失败与登录结束的注入方式）；说明环境无效原因；不单方判定缺陷可放行 |
| 使用方模块测试（如 M3、M5、M13、M14） | 联调 FX-05 的当前汇率与某一时刻取值，核对编号与生效时间 |
| 安全负责人 | 复核 B1 的直接 URL、接口、会话结束后的重放，以及 B2 的修改与删除接口 |
| 中英文审校 | 与产品独立判定英文平台文字与中文含义一致（英文措辞以 Hallmark 原型文案为准，Q-EV-M11-08） |
| Hallmark 设计师 | 只对布局问题提供设计说明，不参与通过判定 |

**流程。** 启动阶段产品与测试逐条共同标注预期；变动幅度类预期由参考实现生成，产品抽查 20% 的算式；R2、R4、R5 由产品与审校各自独立判定。扩展阶段产品抽查新增普通 case 的 20%，B 类、D1 变动幅度与 D2 时序 case 全部复核。持续发布时第二人复判 human 项的 10%（不足 10 条至少 1 条）。以上比例已确认（用户，2026-11-26，WS-668），见 U-M11-05。分歧先记为“未决”并写明各方依据，由产品仲裁；规则本身不明的，提交 PRD 确认，本 Eval 不代改规则。

**二元 rubric（适用项全部为“是”才通过；不适用须写明理由）**

| 项 | 级别 | 判定问题 | 正例锚点 | 反例锚点 |
| --- | --- | --- | --- | --- |
| R1 方向与数值写法 | P1，影响数值升 P0 | 每处汇率是否完整写作“1 USD = R NGN”，R 是否两位小数、补零、千分位，同一条记录在各处写法一致？ | 当前汇率与历史都写“1 USD = 1,535.80 NGN” | 只写“1,535.8”；写成“1 NGN = 0.00065 USD”（P0） |
| R2 空状态与失败可区分 | P0 | 从未设置时是否明确写“尚未设置汇率”，且读取失败、无可用汇率都不会被呈现为某个数值或“尚未设置汇率”？ | 空环境两处都写“尚未设置汇率”，更新入口可用；读取失败时写暂时无法读取并可重试，更新入口仍在 | 空环境显示“1 USD = 0.00 NGN”；读取失败显示“尚未设置汇率” |
| R3 原文与双语 | P1，影响事实升 P0 | 本模块文字是否随界面语言切换且含义一致，来源说明、备注、维护人姓名、编号是否保持原值、不翻译？ | English 下来源说明仍为“CBN 2026-11-12 官方汇率” | 来源说明被机器翻译（P1）；切换语言后汇率值变化（P0） |
| R4 不能提交时说明原因 | P1 | 每个不能提交、未保存或读取失败的情形，是否说明具体原因和下一步（修改哪一项、重试、重新确认或再次提交），且提示含义与实际结果一致（实际已保存成功时不说“汇率已更新”或“与当前汇率相同”）？ | 1535.123 下方说明最多 2 位小数；并发时说明“汇率已更新”并展示最新值 | 只显示“提交失败”；并发时只刷新页面不说明，或写“他人已更新”；实际已保存成功却提示“汇率已更新” |
| R5 确认页信息完整 | P0 | 确认页是否展示方向、当前值或“首次设置”、新值、变动幅度（首次设置除外）、来源说明、备注（填写了才有），以及立即生效、不能修改或删除的提示？ | F2 写“首次设置”且无变动幅度；U4 写当前值、新值、+0.28% | 缺少“不能修改或删除”提示；首次设置显示变动幅度 |

每次判定保留页面或响应、汇率记录快照、时间、账号与时区，不保存与本模块无关的账号信息。启动阶段不使用模型 judge；若以后用模型初筛英文文案，须先建立人工双标校准集并与回归集隔离，并在启用前另定一致率与关键错误漏检门槛，结果仍由人工裁决；本期不启用。目前没有校准数据，不声称任何 judge 可靠。

## 5. 跑评频率

节奏与范围已确认（用户，2026-11-26，WS-668），见 U-M11-07、08；以下只是方案，不创建自动化，不执行评测或线上实验。

| 层级／节奏 | 触发与范围 | 责任与产物 |
| --- | --- | --- |
| L1 每次相关 commit | 汇率值与文字校验、相同值判断、变动幅度计算、保存与替代、并发判定、幂等、对外取值接口、权限中间件有改动时：确定性断言、十进制参考实现比对、FX-AC-21 取值点表、记录不可改写的接口断言 | 研发与测试；逐例结果、AC 映射、B 类清单；B 类失败阻断合入 |
| L2 每次 release | 全量启动／稳态集；中英文；两个以上时区；并发与重复提交按次数重复；至少一个取当前汇率（如 M5）和一个取某一时刻（如 M14）的使用方真实联调，含 EV-M11-36；human 项复核 | 测试组织，产品与审校复核；分维度切片结果、未验证与待验清单、与上一版的配对回归、发布签字 |
| 每周回归 | 每周一次：B1～B6 全部 case；并发与重复提交时序集；M2 账号、会话、菜单或时区规则有变更，或使用方改变取值方式时加跑相应联调；研发确定汇率值最大值后补跑 EV-M11-04 与 FX-AC-11 场景二的上限子条件 | 测试；跨模块回归记录与回流 case |
| 每月一次或外部变化时探索 | 本模块没有被测模型，以外部变化代替 frontier eval：新增币种或币种对的需求、使用方新增“某一时刻”用法、时区或夏令时规则变化、存储精度变化 | 研发与测试；兼容与 OOD 清单、新增风险说明 |
| L3 上线后业务观察 | 经正常上线流程后，用真实使用情况观察；本次不接入、不开展实验 | 产品与测试；脱敏统计，不能用离线通过率推断业务收益 |

**L3 口径（已确认（用户，2026-11-26，WS-668），见 U-M11-08）。** 上线后前 4 周每周看一次，之后每月看一次。只对“重复记录数”和“使用方取值抽样对账不一致数”告警，出现即告警；其余只观察、不告警。

- 上线到首次设置汇率的时长，以及这段时间内使用方取到“无可用汇率”的次数：只观察、不告警，反映上线准备是否到位，不判定 M11 好坏。
- 短时间内被再次更新的记录数 ÷ 记录数（1 小时内由同一人反向更新）：作为误录的代理信号，只观察、不告警，转产品核对是否需要更强的确认提示；PRD 不设阈值，本项不作为通过线。
- 变动幅度绝对值的分布与极值：只观察、不告警，作业务参考。
- 并发冲突与重复提交被拦截的次数：确认机制在真实使用中是否生效；重复记录数出现即告警（期望为 0），转 EV-M11-12～17、35 回流。
- 当前汇率距上次更新的天数：只观察、不告警，作业务参考；本模块本期不提醒。
- 使用方取值与本模块记录的抽样对账：每周至少 20 次取值、按使用方分层，编号、汇率值与生效时间不一致数出现即告警（期望为 0），转 EV-M11-29、31、36 回流。

**回流与版本。** 工单、使用方对账异常、线上指标异常和探索发现的问题，3 个工作日内脱敏复现并落为历史失败 case（已确认（用户，2026-11-26，WS-668），见 U-M11-09），注明真实来源编号、规则提交、失败条件和复核人。未经证实的投诉记为待核查，不当作真实失败。数据集版本为 `Eval-M11-OP-v1.2`，对应 PRD 完整提交 `b75577cedd922c2446cf9ff596aea8d0569e9a55`；PRD 任一册更新或研发确定最大值时，对比规则与 AC 变化，更新受影响的映射与挂起状态，作废的 case 归档并写明原因。风险覆盖集与真实使用统计集分开管理；更新频率或使用方取值方式变化时，重新评估覆盖配比。

**研发与测试待定事项（只记录，不作为 PRD 待确认）：**

- 研发：汇率值可保存的最大值（PRD 已交研发确定，确定后通知测试补跑上限子条件）；生效时间的存储精度，以及 FX-05 比较 T 时的精度（用返回的生效时间原值作 T 时必须命中该条）；汇率编号格式与生成方式；并发判定与幂等的实现依据和取证字段；读取失败（含进入确认前读取当前汇率失败）、保存失败、结果未知（含实际已成功）与登录结束的注入方式；“同一次填写”的识别依据与取证字段；直接 URL 与接口对企业账号、未登录、受限账号的统一处理。
