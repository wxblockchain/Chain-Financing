**本版纳入的评审变更（WS-680，用户 2026-11-25 的四条意见，PRD `d2e32402`）**：金额（美元）按收付日期（UTC+1）当日最后时刻 M11 适用的汇率确定，之后不随汇率变化，当天的 NGN 收付先“暂计”；不标“折算”，NGN 收付在详情中展示所用汇率；详情只分基本信息、凭证附件两部分；关联业务写明应收账款、外采发票或外销合同，内销发票未形成应收账款时写“内销发票”且不可点击，查找支持应收账款编号。M14-Q04 已关闭，缺失值统一为“-”、原因写在下方。相关 Case 打“评审变更回归”标签，它们来自真实的评审决定，不是生产事故。

**Eval 对 PRD 的理解（已从 PRD 推出，不另提问）**

- 已确定的金额（美元）只取决于原币金额、币种、收付日期和 M11 的汇率历史。M11 只能新增汇率，不能追溯生效，也不能修改或删除（[M11 本期不做][m11-scope]、[FX-05][m11-fx05]），所以对收付日期早于今天的记录，任何时候按 PRD 口径重算都应得到同一个值。D2 的随机计算集以此为不变量。
- ERP 修改了已展示记录的金额、币种或收付日期后，重新确定时仍取新收付日期当日最后时刻适用的汇率，而不是查看时的当前汇率。
- 判断“今天”一律按 UTC+1，与查看人的时区无关；查看人的时区只影响所用汇率生效时间和凭证取得时间的展示。

- Q-EV-M14-01～03 确认前，C-D2-12、C-D4-10 和 C-D2-03 的列表部分标“待验”，不计入分子和分母；确认后按确认的口径修订预期值，再计入。
- M14-Q03、Q05、Q06 涉及的 M3、M4、M5 差异按第 1 节处理，不计为 D3 或 D4 失败。
- 原型与 PRD 不一致时以 PRD 为准，不计为 M14 失败，单独登记给设计。

**整体发布门槛（建议，待业务确认）**

- D1～D5 全部达到上表门槛，没有阻断项；Q-EV-M14-01～03 已有结论，且对应 Case 已计入。
- 日界专项（C-D2-03～06 及随机集中的日界样本）在可控测试时钟下全部通过。
- 真实数据对账集 300 条已完成，每一处差异都查明原因：是 M14 的缺陷、ERP 来源数据问题，还是口径问题。属于 M14 缺陷的必须为 0 条，同时按对应阻断项处理，修复后重新核对受影响的记录；其余两类单独登记，不计为 M14 的不一致，但发布前要有结论。

**统计与不确定性**

- 规则集是确定性判定，100% 只表示“这些 Case 都对”，不代表没有其他缺陷，所以 D2 另用随机计算集补充覆盖面。
- 真实数据对账集按比例统计，用 Wilson 区间报告不一致率的上界。建议样本量 300 条：0 条不一致时，95% Wilson 上界约为 1.26%（这是计算方法，不是结果）；如果要求上界低于 1%，样本至少约 381 条。出现不一致时按实际条数重新计算上界并如实报告。
- 分层抽样时，NGN 收付和一笔对应多张单据的记录按风险加权多抽；报告整体不一致率时按真实分布加权还原，加权前后的结果分开报告，不用加重样本的比例代表整体。
- 版本对比用同一批收付记录、同一份 M11 汇率历史和同一个测试时钟配对比较，避免把汇率或日期变化误判为版本差异。
- 本文没有执行任何评测，不包含通过率、分数或通过结论。

## 4. 标注方法

**预期值怎样产生**：D1～D3 和 D5 不需要人工给出主观标签，预期值的来源分三种：

- 验收册写好的预期值，直接使用（例如 C-D2-02、C-D3-02）。
- 测试小队按 PRD 口径独立实现的金额（美元）计算，用于随机计算集和“Eval 补充”Case。必须由不参与 M14 开发的人编写，避免开发和测试犯同一个口径错误；只读取 M11 汇率历史，不读取 M14 保存的结果。
- 真实数据对账集：由财务或运营人员对照 ERP 原登记、银行回单和 M11 汇率历史手工核对。

| 阶段 | 做什么 | 角色 | 产物 |
| --- | --- | --- | --- |
| 启动 | 编写约 110 条 Case 的前置数据、测试时钟设置和预期值；PRD 负责人复核每条 Case 是否符合 PRD 口径，“Eval 补充”Case 逐条复核 | 测试小队编写；PRD 负责人复核口径 | 启动集 v1，每条 Case 标注来源 AC 或 PRD 章节、类别和复核状态 |
| 扩展 | 独立实现预期值计算；先用 D2 中有验收册预期值的 Case（C-D2-01～03、07）校准，结果全部一致后才用于随机计算集；校准用例与随机集分开存放 | 测试小队（非 M14 开发） | 计算口径说明及校准记录 |
| 真实对账 | 分层抽样，双人独立核对，结果不一致时由第三人仲裁；口径争议交 PRD 负责人 | 财务或运营 2 人核对；PRD 负责人仲裁口径 | 对账表：每条记录的 M14 值、核对值、差异和结论 |
| 持续 | 每个线上问题和每次需求变更都转成 Case；每季度重新复核 10% 的旧 Case 是否仍符合当前 PRD | 测试小队；PRD 负责人 | 新版本的 Case 集及变更说明 |

**D4 人工评审 rubric**：每项只判“是”或“否”，由 2 人独立评审，不一致时由产品仲裁。

| 检查项 | 通过（是） | 不通过（否） |
| --- | --- | --- |
| 两部分结构 | 详情只有“基本信息”“凭证附件”两部分，收付双方、关联业务、关联预警都在基本信息中 | 出现第三个部分或折叠层，或同一项在两处出现 |
| 不出现折算 | 金额（美元）旁没有“折算”字样或同义标注；NGN 收付在详情能看到所用汇率和生效时间 | 有“折算”标签、图标说明或悬停提示 |
| 暂计可见 | 暂计值旁的“暂计”与数值同时可见，不需要悬停 | 只能悬停或展开才看到“暂计” |
| 失败与空状态可以区分 | 加载失败有明确的失败提示和重试入口，与“暂无收付记录”“无关联预警”“-”在视觉上不同 | 失败与空状态长得一样 |
| 关联业务可读 | 业务类型和编号在同一处，一眼能分出应收账款、外采发票、外销合同；不可点击的编号在样式上与可点击的不同 | 只显示编号；不可点击的编号看起来能点 |
| 缺失原因的位置 | 需要原因的“-”下方紧跟原因文字；来源值缺失只显示“-” | 原因写在别处；来源值缺失也写了原因 |

- 评审人先用 3 张正例截图和 3 张反例截图对齐标准，再正式评审。正反例截图取自按 `d2e32402` 更新后的原型，作为锚点，不作为验收依据。
- 本模块不建议用 LLM-as-judge 作为主要判定。如果以后用模型预筛截图，要先用人工结果校准；校准用的截图和正式评审用的截图分开，校准前不能把模型结果当作通过依据。

## 5. 跑评频率

以下节奏为建议，待业务确认。具体责任人和触发方式由研发和测试落实，本文不接入任何自动化。

| 层级 | 触发 | 范围 | 责任 | 产物 |
| --- | --- | --- | --- | --- |
| L1 每次提交 | M14 代码提交 | D2 规则集与金额（美元）不变量的确定性检查；“折算”文本扫描；D5 的接口字段与写接口检查 | 研发 | 通过或失败清单；任一失败不能合并 |
| L2 每次发布 | M14 提测或发布前 | 启动集或稳态规则集全量；随机计算集一次；日界专项（可控测试时钟）；D4 人工 rubric；联调环境中的 D3 跨模块比较 | 测试小队；产品参加 D4 评审 | 评测记录：各维度通过数／总数、阻断项、单独列出的待验项 |
| 依赖模块回归 | M2、M3、M4、M5、M8、M9、M11、M15 发布，或它们的 PRD 口径变更；ERP 收付接口变更 | 引用该模块的 Case。例如 M11 改动跑 D2 全部和随机集；M3、M4、M5 改动跑 D3 落点与摘要比较；M8 改动跑关联预警；M15 改动跑不能处理的登记；M14-Q03、Q05 在 M4、M5 同步后，把 C-D3-07 扩展到 M4 外销收款记录和 M5 外销段，并恢复金额比较 | 测试小队 | 回归记录；不一致时同时通知两边模块的负责人 |
| 每周回归 | 联调期间每周一次 | 稳态规则集全量 | 测试小队 | 周报：新增失败及其处理状态 |
| 每月真实数据对账 | 上线后每月一次（代替模型类产品的“每月 frontier eval”，本模块不适用） | 真实数据对账集；按当月收付的真实分布重新分层抽样，含当月 M11 汇率更新前后的 NGN 收付 | 财务或运营；测试小队 | 对账表及 Wilson 上界 |

**L3 上线后核对（方案）**

- 运营在日常使用中发现 M14 的金额、收付双方或关联业务与 ERP、银行回单或其他模块不一致时，按“记录、字段、M14 值、预期值”登记，作为线上问题回流。
- 离线 Eval 只证明“按 PRD 口径做对了”，不能证明运营据此完成了核对。上线后另看三件事：运营是否还要回 ERP 手工查收付双方和凭证；M15 中三种未接收原因的条数趋势（这反映 ERP 数据质量，不计为 M14 缺陷）；汇率更新后是否有人报告 M14 与 M4、M5 美元值不同（M14-Q05 同步前预期会出现）。具体指标和门槛由业务方在上线前确定，**待确认**。

**失败回流与版本管理**

- 每个线上问题和每次口径变更都转成至少一条 Case，并标注来源（线上问题编号或 PRD 提交号）。
- 规则集、随机计算集的生成规则、真实对账样本分别管理版本，并记录对应的 PRD 提交号（当前为 `d2e32402`）。真实对账集用于统计整体不一致率，规则集和随机集用于发现缺陷，两者的结果不混在一起报告。
- PRD 口径变更时（例如 Q-EV-M14-01～03 定稿，或 M4、M5 同步 M14-Q03、Q05），先改相关 Case 的预期值，再重新运行受影响的层级。
