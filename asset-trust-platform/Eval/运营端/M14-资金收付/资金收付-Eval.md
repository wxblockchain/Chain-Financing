**Eval 对 PRD 的理解（已从 PRD 推出，不另提问）**

- 已确定的金额（美元）只取决于原币金额、币种、收付日期和 M11 的汇率历史。M11 只能新增汇率，不能追溯生效，也不能修改或删除（[M11 本期不做][m11-scope]、[FX-05][m11-fx05]）。所以收付日期早于今天的记录，任何时候按 PRD 口径重算都应得到同一个值。D2 的随机计算集以此为不变量。
- ERP 修改了已展示记录的金额、币种或收付日期后，重新确定时取新收付日期当日最后时刻适用的汇率，不取查看时的当前汇率。
- M4 和 M5 怎样取一笔多单据收付的分配部分的美元值，写法不同：M4 是“分配金额 ÷ M14 所用汇率”，M5 是“M14 该笔金额（美元）× 分配金额 ÷ 该笔收款金额”。两者在未取舍时相等，只差 M14 金额（美元）两位小数的取舍。D3 按“分配金额 ÷ M14 所用汇率”比较，允许 ±0.01 USD 的取舍差；只对应一张单据时，要求与 M14 完全相同。

**L3 上线后核对（方案；指标待确认，U5）**

- 运营在日常使用中发现 M14 的金额、收付双方或关联业务与 ERP、银行回单或其他模块不一致时，按“记录、字段、M14 值、预期值”登记，作为线上问题回流。
- 离线 Eval 只证明“按 PRD 口径做对了”，不能证明运营据此完成了核对。上线后另看三件事，具体指标和目标见 U5：
  - 运营是否还要回 ERP 手工查收付双方和凭证；
  - 同一笔收付在 M4、M5 与 M14 的值是否一致；
  - M15 中三种未接收原因的条数趋势。这反映 ERP 的数据质量，不计为 M14 缺陷。

**失败回流与版本管理**

- 每个线上问题和每次口径变更，都转成至少一条 Case，并标注来源（线上问题编号或 PRD 提交号）。
- 规则集、随机计算集的生成规则、真实对账样本分别管理版本，并记录对应的 PRD 提交号（当前为 `d13c6514`）。
- 真实对账集用于统计整体不一致率，规则集和随机集用于发现缺陷，两者的结果不混在一起报告。
- PRD 口径变更时（例如 Q-EV-M14-04～06 定稿，或 M4、M5 调整分配部分美元值的算法），先改相关 Case 的预期值，再重新运行受影响的层级。
