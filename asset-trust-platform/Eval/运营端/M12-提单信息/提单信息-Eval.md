## 2. Case 数量与覆盖

**数量是计划，没有已执行 case。** 31 条 AC 的场景拆分后约 112 条原子 case，再补 PRD 派生 case，建议启动集约 170 条：D1 33、D2 32、D3 36、D4 39、D5 30。拆分结果超过计划时以拆分结果为准，不为凑数删减场景。稳态建议每维度 40～70 条，合计 220～300 条，主要扩充资料变更序列、多汇率与多币种、跨模块联调和回流 case。具体条数由测试负责人在拆分时落实，属测试范围，不列为待确认项。

**启动集覆盖配比（风险覆盖集，计划）：** 正常约 55、边界约 55、异常与对抗约 35、OOD 约 15；历史失败 0。没有收到真实线上或测试失败材料，因此不设历史失败 case，也不据此推断产品没有失败。本模块只读、无凭据操作，主要风险在“算错”和“把失败当成业务状态”，所以边界与异常占比高于对抗；这个人为配比不代表真实流量，L3 另用真实流量统计。

## 3. 通过线

**单例判定。** 预期行为全部满足、禁止行为都没出现才算通过；模板行拆分后逐个判定，多数子场景通过不代表整行通过。无法执行的记“未验证”；环境原因造成无法判定的记“无效”，需研发说明并经测试确认后重跑。本版没有“待验”case；之后 PRD 出现未定口径时，相关 case 标“待验”，照常执行、记录结果，但不计入通过线分子分母，在报告中单列为“未判定”，PRD 定稿后按新提交改写并计入。

**级别。** P0 沿用已确认口径“影响业务进程，或危及平台安全”；P1、P2 由本 Eval 定义，不作为 PRD 待确认项。同一 case 涉及多个风险时取最高级别；新问题的业务影响有歧义时由产品仲裁。

**指标口径。** 维度通过率 ＝ 有效通过的原子 case 数 ÷ 有效执行的原子 case 数；按 P0／P1／P2、币种、内采单价来源、航程状态、清关状态、入口（页面／直接 URL／接口）、界面语言、模拟／真实依赖分别列出，不合并掩盖。未验证、无效单列数量和原因。无效占计划执行数超过 5% 时暂停本轮结论、修复环境后重跑（U-M12-03，已确认）。

**重复与统计。** 规则断言为确定性结果，逐条判定，不用置信区间替代；固定 ERP 数据快照、外部跟踪数据快照、M11 汇率快照与 M8 条数快照。资料变更序列（EV-M12-06、17、19）与汇率切换（EV-M12-13）各重复 3 次（U-M12-03，已确认），任一次失败即该 case 失败。人工复核比例和 L3 比例按分子／分母报告 Wilson 95% 区间（置信水平为建议），小样本零失败不证明低风险。版本比较固定同一 case 集与环境逐例配对，新增 case 单列；没有稳定基线前不报告“提升”。

**失败兜底（按 PRD 核对是否生效）。** 加载失败：提示失败并可重试，不展示不完整的数；局部失败：只影响该处；跳转目标已不再采信：提示“该内容不存在或已更新”并可返回；附件打开失败：提示稍后重试；本模块只读，数据错误的修正在 ERP 或 M8，本模块随新资料重新得出。Eval 不通过不上线；线上出现 B 类问题时，先停用相关展示或回退版本并保留证据，修复后按 L2 全量重跑（U-M12-06，已确认），具体执行由研发／运维负责，本文不执行处置。

**L3 口径（窗口、样本与告警线按 U-M12-05，已确认：按月统计；M8 条数每月抽 100 张提单对账，任何不一致即告警；货值为“-”的比例环比上升超过 5 个百分点告警；“未找到该提单”占跨模块进入次数超过 1% 告警；局部加载失败率超过 1% 告警；外部数据无航程动态比例、合同价车辆比例只观察）。**

- 提单货值为“-”的提单数 ÷ 提单数，按原因（无内采单价、无法折算、无可用汇率、加载失败）分层：检验 ERP 与 M11 数据是否足以算出货值。
- 已采信提单中外部跟踪数据没有任何航程动态的比例：检验外部数据覆盖，结论交研发核验，不作为 M12 失败。
- 列表与详情的 M8 条数抽样对账：不一致数（期望为 0），大于 0 转 EV-M12-38、39 回流。
- 从其他模块进入时展示“未找到该提单”的次数 ÷ 进入次数，按来源模块分层：偏高说明上下游对“哪些提单可进入”的口径不一致。
- 局部加载失败次数 ÷ 详情打开次数，按部分分层：观察依赖稳定性。
- 合同价车辆数 ÷ 提单车辆数：作为“未开票即装船”的业务参考，不判定 M12 好坏。

**回流与版本。** 工单、M8 对账异常、线上指标异常和探索发现的问题，3 个工作日内脱敏复现并落为历史失败 case（U-M12-05，已确认），注明真实来源编号、规则提交、失败条件和复核人。未经证实的投诉记为待核查，不当作真实失败。数据集版本为 `Eval-M12-OP-v1.4`，对应 PRD 完整提交 `0c2fe29a17760637166c820566d01cfbd53d322a`；PRD 任一册更新时，对比规则与 AC 变化，更新受影响的映射与“评审变更回归”标签，作废的 case 归档并写明原因。风险覆盖集与真实流量统计集分开管理；提单规模、币种或失败原因分布变化时，重新评估覆盖配比。

**研发与测试待定事项（只记录，不作为 PRD 待确认）：**

- 研发：局部加载失败的注入方式；采信与移除的事件来源，便于测试构造变更序列；汇率取值与生效时间的取证字段；直接 URL 与接口对企业账号的统一处理。
- 测试：ERP、外部跟踪数据、M11、M8 四类快照的准备与固定方式；金额参考实现的维护；集装箱号多值样本。
- 测试／发布：签字机制；M8／M5／M13／M15 联调环境的准备（通过线、节奏与告警按已确认的 U-M12-01～05）。
