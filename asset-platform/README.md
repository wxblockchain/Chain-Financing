# 资产平台（Asset Platform）

资产平台包含 **资产端**（面向资产参与方的 Web）与 **资产管理端**（平台运营使用的 Web）两个端。
本目录收纳资产平台的全部 PRD 与原型；设计系统 `docs/design-system/` 为两个平台共用，仍留在仓库顶层。

## 目录结构

```text
asset-platform/
├── prd/          # 资产平台的产品需求文档，按模块建子目录
└── prototypes/   # 资产平台的原型（HTML、Figma、交互稿等）
    ├── _shared/  # 原型公共底座：tokens.css / base.css / registry.js / shell.js
    └── [功能名]/ # 每个模块一个子目录，以 ../_shared/ 引用底座
```

> `_shared/` 必须与模块目录保持同级：模块 HTML 以 `../_shared/` 引用底座，跨模块跳转按 `../[模块目录]/` 拼接，挪动它会同时打断这两条相对路径。

## 端的归属只做标注，不做目录拆分

本目录**不再按端拆二级目录**（不建 `资产端/`、`资产管理端/`）。现有模块基本都跨端写在同一份文档里——例如实名认证同一目录内既有 `01-个人认证.md`（资产端）又有 `04-管理端审核.md`（资产管理端）——按端物理拆分会变成改写文档内容而非移动文件。端的归属统一由上表标注。

## 维护规则

- 新增模块时，同一次提交里补上表的一行，并在 [`prd/README.md`](prd/README.md) 的文档索引里登记路径与入口文件。
- 端归属以 PRD 主文档的「覆盖端」字段为准（无该字段时以用户角色表的「所在端」列为准）；PRD 改了覆盖端，本表同步改。
- 新写 PRD 时建议在「文档信息」表里补上「覆盖端」行，省得后来人再去正文里翻角色表。
- 金融服务平台（金融服务端 / 运营端）的产物不放本目录，见 [`financial-service-platform/`](../financial-service-platform/README.md)。
