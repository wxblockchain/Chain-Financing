## 2. 背景与目标

### 2.1 为什么现在要写这一册

金融服务端有一条跨平台链路：资产方在金融服务端点登录 → 被带到**资产平台**登录或完成实名认证 → 回到金融服务端原来那个页面。

对端已经把自己那一半写死了，并且加了一条否定式前置条件（`D-F171`）：**对端未确认执行同等强度校验的，不得开启到该对端的跨域回跳。** 理由很直接——我方校验再严，只要资产平台这一侧能被塞进一个任意目标，用户照样会被从一个可信页面弹到钓鱼站，钓鱼一样成立。**两边校验的安全性等于其中较弱的那一边，不是两边的平均。**

在这条确认落地之前，对端按保守口径处理：跨域回跳**直接不跳转**，落默认落地页 + Toast（对端 `E-95` / `AC-F618`）。代价只在体验——资产方去资产平台做完实名认证回来，会落在首页而不是他原本在看的那条资产。

### 2.2 但这不只是"给对端一个答复"

写这一册的过程中发现：**资产平台自己的站内回跳，今天的口径比对端弱。** 现状是「跳转登录页，并携带原页面路径，登录成功后回跳」（[`04-安全与风控.md`](./04-安全与风控.md) 12.1.3 第 4 条），WS-304 的消息深链回跳也是同一条路径——**原始目标路径直接出现在可见 URL 里，且没有写明白名单、规范化与会话绑定的判定规则**。

所以本文不是一份"我们早就做到了"的确认书，而是：**三问的口径全部按对端同等强度确认，其中句柄形态与会话绑定一项，资产平台需要补做**（7.4 列出改动面与影响范围）。把这一点写在明处，比给一个漂亮的"是"更有用。

### 2.3 本期做什么

| # | 做 |
| --- | --- |
| 1 | 定义资产端 / 资产管理端的**允许回跳路径前缀清单**，及按完整路径段的判定方式 |
| 2 | 定义**规范化与一轮解码**口径 |
| 3 | 定义**被拒绝的目标形态**与禁止出现的查询参数 |

| 6 | 明确 `Referer` / `Origin` **只留痕、不作信任依据** |
| 7 | 给出可独立执行的验收标准 `AC-278`～`AC-302` |

## 4. 结论一（`Q1`）· 允许回跳的路径前缀清单

> **正面回答**：是。资产平台的回跳目标采用**允许清单**，**没列进来的一律不允许**；命中判定**按完整路径段比较**，不做字符串前缀包含判定。清单如下。

### 4.1 判定方式（`D-47`、`D-48`）

| 编号 | 口径 |
| --- | --- |
| **`D-47`** | 回跳目标必须命中允许清单中的某一项前缀，**否则判定失败**。清单是允许清单（白名单），不是禁止清单——新增一个业务域没有登记进清单，它就是不可回跳的，这是有意的默认拒绝 |
| **`D-48`** | **命中判定按完整路径段比较**：把规范化后的目标路径按 `/` 切成段序列，把清单前缀也按 `/` 切成段序列，**逐段做完全相等比较**，且清单的段序列必须是目标段序列的**前缀序列**。不做任何形式的字符串包含 / `startsWith` 判定 |

### 4.2 资产端允许清单（`D-49`）

清单**按能力域分组维护，不按具体页面维护**：一个新业务页面如果落在已有前缀下，不需要改清单；新增一个业务**域**才走 4.6 的变更流程。

| --- | --- | --- | --- | --- |
| 1 | `/`（**精确匹配**） | 登录后的默认落地 | ✅ | 也是判定失败时的兜底目标（第 10 章） |

## 5. 结论二（`Q2`）· 规范化与解码

> **正面回答**：是。**先规范化再判定，且规范化只做一轮**；规范化前后不一致、或一轮解码后仍含 `%` 编码序列，**一律判定失败**。

| 编号 | 口径 |
| --- | --- |
| **`D-54`** | **规范化 = 一次百分号解码 + 路径归一**（消解 `.` 与 `..`、折叠连续 `/`）。**规范化后与规范化前不一致的，直接判定失败**，不进入后续任何一条判定 |
| **`D-55`** | **一轮解码后目标中仍含 `%` 编码序列的，判定失败，不做第二轮解码。** 多轮解码是绕过白名单的标准手法，本平台不给第二轮机会 |
| **`D-56`** | **判定前不做任何"修正后再试"的兜底**：不补斜杠、不去空白、不折叠大小写、不猜测用户意图。**目标要么原样通过，要么失败落兜底**（第 10 章）。判定失败不是错误，是正常分支 |

**两条相对对端的补强**（对端未写、资产平台加严，不构成分歧）：

| 编号 | 补强 |
| --- | --- |
| **`D-55a`** | **大小写不折叠**：清单中的前缀段一律小写；目标路径段按**区分大小写**比较。`/Receivables` 不命中 `/receivables`。理由：大小写混淆是绕过判定的常见手法，而资产平台不存在需要大写路径段的页面 |
| **`D-55b`** | **控制字符与空白零容忍**：目标中出现 `\t`、`\r`、`\n`、`\0` 或任何 C0 / C1 控制字符（含其编码形式）时，**直接判定失败并按安全留痕处理**（`X-R03`）。理由：这类字符只在构造攻击时出现，正常链接里不会有 |

## 6. 结论三（`Q3`）· 被拒绝的目标形态与凭据段

> **正面回答**：是，全部拒绝，逐条如下。

### 6.1 目标形态（`D-57`）

| 编号 | 口径 |
| --- | --- |
| **`D-57`** | **只接受站内相对路径：目标必须以单个正斜杠 `/` 开头。** 以下形态一律拒绝，无例外、无兜底修正：<br>① 带协议头的绝对地址：`http://`、`https://`，以及**任何 `xxx:` 形式**（含 `javascript:`、`data:`、`file:`、自定义 scheme）；<br>② **协议相对地址 `//`**（含 `///`、`/\/` 等变体）；<br>③ 以反斜杠开头或路径中含反斜杠的写法：`\`、`/\`、`\/`；<br>④ 以 `.` 或 `..` 开头的相对写法；<br>⑤ 空串、纯空白、单独的 `?` 或 `#` 开头的目标 |

| 编号 | 口径 |
| --- | --- |

### 6.3 禁止出现在目标中的查询参数

任何一类命中即判定失败。**前四类与对端 `N-F31` 逐字一致**；第五类是资产平台专有凭据，对端没有，须由本平台补上。

| 类 | 参数 | 来源 |
| --- | --- | --- |
| 会话与令牌 | `token`、`access_token`、`id_token`、`session`、`sid`、`auth` | 与对端一致 |
| 授权码 | `code`、`code_verifier`、`state` | 与对端一致 |

| **资产平台专有** | `ticket`（滑块票据，[`04-安全与风控.md`](./04-安全与风控.md) 12.3.3）、`slider_ticket`、`sign_nonce`（钱包签名 nonce，同文件 12.1.2）、`reset_token`（设置 / 重置密码链接令牌） | **本文新增** |

## 7. 对齐项一 · 句柄形态与会话绑定

> **正面回答**：确认对齐。句柄必须由生成它的那个会话消费，跨会话、跨设备一律失败。**此项资产平台需要补做**，改动面见 7.4。

### 7.1 句柄形态（`D-59`、`D-60`）

| 编号 | 口径 |
| --- | --- |
| **`D-59`** | **回跳目标不以原始地址的形式在客户端流转。** 生成回跳时，服务端把已通过第 4～6 章判定的目标**登记下来**，只把一个**不透明句柄**交给客户端；句柄本身不含目标信息，拿到句柄也推不出目标 |
| **`D-60`** | **句柄的承载位置只有两种，二选一，不得出现第三种**：① **服务端会话暂存**（站内回跳默认用这种）；② **塞进 SSO 授权请求的 `state`**（仅跨平台链路用）。**任何情况下不得放进可见 URL 查询参数、不得放进浏览器本地存储（`localStorage` / `sessionStorage`）、不得放进未加 `HttpOnly` 的 Cookie** |

### 7.2 会话绑定与一次性消费（`D-61`、`D-62`）

| 编号 | 口径 |
| --- | --- |
| **`D-61`** | **句柄必须由生成它的那个会话消费。** 生成时记录所在浏览器会话；消费时比对，**不一致即判定失败并安全留痕**（`X-R04`）。跨会话、跨设备消费一律失败——这一条挡住的是"把链接发给别人点"这一整类场景 |
| **`D-62`** | **一次性消费**：句柄被成功消费一次后**立即作废**，重放同一句柄按失效处理并安全留痕（`X-R05`）。此外，**登录 / 认证流程完成、用户中途放弃、会话销毁（含退出登录、会话过期、[`04-安全与风控.md`](./04-安全与风控.md) 12.1 的任一强制失效）时一并作废** |

### 7.3 有效期（`N-24`、`N-25`）

| 编号 | 参数 | 取值 | 理由 |
| --- | --- | --- | --- |
| **`N-24`** | 回跳句柄有效期 | **30 分钟**（可配置） | 与对端 `N-F33` **取同值**。它要覆盖「被拦下 → 登录 / 收邮箱验证码 / 连钱包签名 → 回来」这一整段，其中收验证码是最慢的一环；同时不宜长到让一个被遗忘的标签页在半天后仍能跳转。**这是可调参数，不是安全边界**——安全边界是第 4～6 章的判定规则 |
| **`N-25`** | 同一会话未消费句柄并存上限 | **20 个**（可配置） | 防止构造大量句柄占用会话暂存。超限时**淘汰最旧的一个**，不报错 |

### 7.4 与现状的差异，以及这项为什么标"需补做"

**现状**：[`04-安全与风控.md`](./04-安全与风控.md) 12.1.3 第 4 条写的是「跳转登录页，并携带原页面路径，登录成功后回跳」；WS-304 8.1 的深链回跳（`/messages/{id}`）、WS-303 的「未通过认证访问业务路由重定向到用户中心」走的是同一条路径。**这几处都把原始目标路径放在可见 URL 里，且没有白名单、规范化与会话绑定的判定文本。**

**结论**：资产平台在**判定规则**上可以直接确认同等强度（第 4～6 章即为规则），但在**句柄形态**上今天弱于对端，需要补做。补做内容与影响面：

| # | 补做项 | 影响的既有条目 | 是否改变用户可见行为 |
| --- | --- | --- | --- |
| 1 | 站内回跳由 "URL 携带原路径" 改为 "服务端登记 + 不透明句柄" | [`04-安全与风控.md`](./04-安全与风控.md) 12.1.3 第 4 条 | **否**——用户看到的仍是"登录完回到原页"，只是地址栏里不再出现原路径 |

| 3 | 认证前置校验的重定向接入同一实现 | WS-303 未通过认证访问业务路由重定向到用户中心 | 否 |
| 4 | 会话失效跳登录页时生成句柄 | [`04-安全与风控.md`](./04-安全与风控.md) 12.1.3 整条 | 否 |

| 编号 | 口径 |
| --- | --- |
| **`D-63`** | **回跳的判定、句柄生成与消费在资产平台只有一处实现**，WS-302 / WS-303 / WS-304 / WS-305 一律调用，**不得自建**。理由与对端 `D-F99` 完全一致：同一条否定式规则写多遍，只要有一遍漏了一种绕过写法，攻击者就从那一处进来；**多处实现的安全性等于其中最弱的那一处，不是它们的平均** |

> **句柄值本身不是一个字段口径**：它是不透明的、由服务端生成、对客户端无语义，**不得由目标路径编码得到**（可解码的"句柄"等于把目标又放回了 URL）。

## 12. 异常分支

| 编号 | 场景 | 处理 | 留痕级别 |
| --- | --- | --- | --- |
| **`X-R01`** | 目标未通过第 4～6 章任一判定 | 按 10.1 兜底 | 普通 |
| **`X-R02`** | 句柄已过期（超 `N-24`） | 按 10.1 兜底；Toast「链接已失效，已为你回到首页 / This link has expired. You're back at the home page.」 | 普通 |
| **`X-R03`** | 目标含 `@`、禁止的查询参数、或控制字符（`D-58`、`D-55b`） | 按 10.1 兜底 | **安全** |
| **`X-R04`** | 句柄被非生成会话消费（`D-61`） | 按 10.1 兜底 | **安全** |
| **`X-R05`** | 同一句柄重复消费（`D-62`） | 按 10.1 兜底 | **安全** |
| **`X-R06`** | 跨平台目标的对端来源不在登记表内，或该项未确认同等校验（`D-65`） | 按 10.1 兜底，**不跳转** | **安全** |
| **`X-R07`** | 单会话未消费句柄超 `N-25` | 淘汰最旧一个，**不报错、不影响本次流程** | 普通 |

> **安全留痕与普通留痕的区别不在格式，在于它是不是"被探测"的信号**。`X-R03`～`X-R06` 出现即说明有人在构造目标，应当可被单独统计与告警；`X-R01`、`X-R02` 大多是用户放了太久或链接过期，属正常损耗。

## 13. 非功能要求

| 项 | 要求 |
| --- | --- |
| **安全** | 判定在**服务端**执行，前端不得作为判定的唯一环节；**默认拒绝**——判定逻辑出现任何未覆盖分支时按失败处理，不按通过处理；判定不得因目标是否存在而返回可区分的响应或耗时（与 WS-302 `D-17` 账户枚举防护同一取向） |
| **性能** | 判定为纯字符串运算 + 一次会话查询，不引入外部调用；**不得因判定失败而重试** |
| **兼容性** | 回跳须在**浏览器后退、页面被恢复、第三方 Cookie 受限**三种情况下均不白屏——三种情况都按句柄失效走 10.1 兜底 |
| **可用性** | **无错误死胡同**：每一个判定失败都有出口（默认落地页 + Toast），不出现报错页、不出现技术错误信息 |
| **可访问性** | Toast 沿用 WS-302 `C-12` 的既有规范（顶部居中、停留 5 秒、可手动关闭、对屏幕阅读器可播报） |
| **国际化** | 本文涉及的全部对外文案按 WS-302 第 13 章的双语基线出中英两版 |
