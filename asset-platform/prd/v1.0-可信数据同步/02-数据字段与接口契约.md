> **字段清单以简报第五节的建议列表为基线，并按 WS-305 已定稿字段逐条对齐**。资产管理端如给出正式字段定义，以其为准 `[假设-待确认 Q-DS-10]`。
> **「参与存证」列**（2026-09-10 新增）标注该字段是否进入哈希存证的计算范围。口径是：**能唯一确定这笔债权是什么、值多少、谁欠谁的字段都参与**；纯展示字段（企业名称）、过程字段（批次号、推送时间与推送人）与 **D-DS-05 资产方钱包地址**不参与。
> **D-DS-05 资产方钱包地址不参与存证**（需求方 2026-09-10 裁定）：该字段虽已改为必填，但它描述的是「下游把币打给谁」，不是这笔债权本身的内容，因此不纳入存证计算范围。**存证范围的定性以「这笔债权是什么」为界，不以「字段是否必填」为界**——两者不要混为一谈。
> 参与范围一旦上线不得随意调整——改了范围，历史存证就无法用同一套规则复算 `[假设-待确认 Q-DS-13]`。
> **D-DS-05 由选填改必填**（需求方 2026-09-10）：该字段原定「本期只存不用、缺失不阻断」，前提是它只是给后续 issue 的透传字段。后续 issue（WS-318）要用它作铸币的收币地址，没有地址物理上无法铸造，选填的前提不再成立。缺失或格式非法的处置链路见分册一 7.3 / 7.4 / 8.1 与分册三 AC-DS-11，**全部落在既有机制上，不新增接口、字段或原因码**。

> **D-DS-20～D-DS-24 五项凭证缺一不可**：推送前置校验（V-DS-06）与运营端收单校验（8.1 第 4b 步）都要求五项齐全，缺任一项按凭证不完整拒绝。

## 11. 接口契约要点

本节只定义**语义**，不指定协议实现、传输格式与技术选型。

| 编号 | 接口 | 方向 | 语义 |
| --- | --- | --- | --- |
| I-DS-01 | 资产推送 | 资产平台 → 运营端 | 输入：推送批次号 + 资产数组（D-DS-01～**D-DS-24**，含五项链上凭证），单批 ≤ 500 条；输出：与输入等长的逐条结果数组，每条含来源资产 ID、结果类型（新入库 / 幂等命中 / 失败）、原因码。**部分成功不整体回滚** |
| **I-DS-04** | **资产上链存证** | 资产平台 → 链 / 存证服务 | 输入：上链批次号 + 各资产的存证哈希（按 10.1「参与存证」列计算），单批 ≤ 500 条；输出：与输入等长的逐条结果，每条含来源资产 ID、结果类型（上链成功 / 已有有效存证 / 失败）、五项凭证或原因码。**部分成功不整体回滚**；调用前先查该资产是否已有有效存证（7.8.3 幂等） |
| ~~I-DS-02~~ | ~~重推请求（运营端 → 资产平台）~~ | — | **已随「运营端不提供重推入口」删除，编号保留为空位不再复用**。本期不存在任何由运营端发起的反向调用 |
| ~~I-DS-03~~ | ~~对账查询~~ | — | **已随对账视图删除，编号保留为空位不再复用** |

**契约级约束**

1. **本期只有一个跨平台接口，且只有一个方向**：资产平台 → 运营端（I-DS-01）。运营端不主动调用资产平台的任何接口，**也不调用链或区块浏览器 API**——I-DS-04 是资产平台与链侧之间的调用，运营端不参与。
2. **幂等语义写在接口层**：同一「来源系统标识 + 来源资产 ID」重复调用 I-DS-01，第二次及以后一律返回「幂等命中」且为成功语义，不得返回错误，不得改动已有数据。
3. **回执必须逐条可归因**：任何一条失败都要能定位到具体资产与具体字段，不允许只返回批次级的成功 / 失败。这是本期失败排查的唯一信息来源——运营端不留失败痕迹，回执写得含糊就等于失败不可查。
4. **金额传输遵循脱敏基线**：传数值 + 币种代码，不传拼好的字符串（WS-308 `01-国际化基线.md` 8.2）。
5. **钱包地址不得进入日志与通知参数**：完整钱包地址仅存储于清单数据，日志与任何展示层取缩略形态。
6. **接口调用失败与业务失败必须可区分**：推送侧前者落 E-DS-05 / E-DS-06、后者落 E-DS-02～E-DS-04；上链侧前者落 E-DS-07 / E-DS-08、后者落 E-DS-09 / E-DS-10。
7. **凭证只透传、不重算**：运营端存的凭证必须与资产管理端上链拿到的回执逐字一致。中间任何一方不得重新计算、补齐或格式化存证哈希与交易哈希——凭证一旦被中途加工，它就不再是链上那一份，核查也就失去意义。

## 12. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 单批 500 条的推送提交，从点击确认到返回逐条结果的**目标**耗时 ≤ 30 秒；**上链批次受链上确认速度制约，目标另行按链侧实际出块与确认时间校准**，页面须在提交后给出明确的进行中反馈，不得让用户面对无响应界面；清单列表首屏与筛选响应目标 ≤ 2 秒。标「目标」的数值在联调阶段校准，不影响功能验收 |
| 一致性 | 幂等唯一约束在数据层强制，不得仅靠应用层判重；并发推送同一资产不得产生两条记录 |
| 安全 | 两端账号完全不互通，跨平台调用走**服务间鉴权**（凭据由技术侧配置下发，不在页面上配置、不由运营自助管理）；**链侧凭据（私钥 / 签名服务访问凭据）由技术侧托管，任何页面、日志、回执与报文中都不得出现，资产管理人员全程不接触私钥**；越权访问与上链、推送、重试动作须记入安全审计日志 |
| 脱敏 | 运营端一切展示、日志遵循 WS-308 `01-国际化基线.md` 第 8 节；钱包地址缩略前 6 后 4，完整值仅在用户主动复制时进入剪贴板；企业名称、金额按该表口径处理 |
| 可追溯 | 上链、重新上链、推送、重推、收单各留一条记录，**记录只增不改不删**；收单失败虽不进运营端产品页面，但**必须记入运营端服务日志**用于排障，日志保留期遵循各端既有审计口径 |
| 兼容性 | 两端均为 Web 桌面端，浏览器支持范围沿用 WS-302 / WS-308 既有口径；本期不做移动端适配 |
| 国际化 | 资产管理端文案沿用 WS-302 双语口径；运营端沿用 WS-308 `01-国际化基线.md` 第 1～7 节；**币种代码、来源资产 ID、批次号、钱包地址不翻译** |
| 可用性 | 失败必须在资产管理端可见、可自助解决：任何一条 S-DS-2 或 S-DS-4 都要在页面上给出原因文案与下一步动作，不得只给错误码 |
