## 13. 依赖与风险

### 13.1 依赖

| 编号 | 依赖 | 说明 | 阻塞性 |
| --- | --- | --- | --- |
| DEP-DS-01 | WS-305《应收账款录入与确权》 | 提供「已确权」资产与 D-01～D-19 字段，是本模块的数据来源 | 强依赖，已定稿 |
| DEP-DS-02 | WS-302 / WS-308 账户与登录 | 两端登录态、角色模型、路由前缀、国际化与脱敏基线 | 强依赖，已定稿 |
| DEP-DS-03 | WS-305 第 12 章的只读表述 | 需补一句「`data_sync.push` 为例外」，由 WS-305 维护方执行（见 3.1） | 弱依赖，不阻塞开发 |
| DEP-DS-04 | `docs/notification-contract/接入指南.md` 4.2 登记表 | 入库时同批补登 `DS` 模块字母与本模块段位，并补登 WS-305 已在用的 `P-M40` / `P-M41`（见 3.2） | 弱依赖，随入库执行 |
| DEP-DS-05 | 资产管理端的正式字段定义 | 决定 D-DS-01～D-DS-19 的最终取值范围（Q-DS-10） | 不阻塞开工，按本文档默认值实现 |

### 13.2 风险

| 编号 | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| R-DS-01 | 幂等键选错（来源资产 ID 实际不唯一或会变更） | 清单重复入库或两端追溯主键失效，属本期红线事故 | Q-DS-01 优先确认；唯一约束建在数据层，一旦冲突即按幂等命中处理而非失败 |
| R-DS-02 | 「回执未知」被误判为失败，重推造成重复入库 | 清单统计被污染 | 幂等在接口层强制（11.2），重推天然安全；结果面板明确提示「重推受幂等保护」 |
| R-DS-03 | 无自动重试，运营端短时不可用时大批量条目落 S-DS-2 | 人工重推工作量集中爆发 | P-M-DS-03 支持**按批次一键全量重推**失败条目（7.6） |
| R-DS-04 | 钱包地址口径是账号维度还是企业维度未定 | 下游 issue 拿到的地址可能不是收币主体的地址 | Q-DS-02；本期只存不用，答复变化只改取数来源，不改结构 |
| R-DS-05 | 资产管理端首次出现写操作，与既有「管理端只读」安全口径冲突 | 安全评审时口径不一致 | 3.1 的独立入口 + 独立权限点 + DEP-DS-03 的文档补充 |
| R-DS-06 | 确权信息快照与源数据后续不一致（源数据被修正） | 运营端看到的是旧值 | 本期明确「快照取推送时刻的值、只存不改」；增量同步在后续迭代（Q-DS-08） |
| R-DS-07 | **漏推在运营侧不可发现**：运营端既不展示失败资产，本期也没有对账视图，运营人员无法判断「我看到的是不是全部」 | 某批资产因失败或漏推没进清单时，只能靠资产管理端主动发现，运营侧的业务判断可能基于不完整的数据 | 这是需求方为控制本期范围主动接受的取舍。**本期缓解**：P-M-DS-01 的「未推送 / 推送失败」筛选是唯一的发现入口，建议在上线运营规范中约定由资产管理人员例行检查。**后续定案（需求方 2026-09-09）**：不做完整的两端对账视图，改为在 P-M-DS-01 增加默认视图「已确权且未推送 / 推送失败」+ 条数角标，**排在代币铸造 issue 之后**作为同步链路的收口迭代（见主文档 2.4）。该方案不需要跨平台拉数与新接口，成本远低于对账视图 |

## 14. 验收标准

### 14.1 资产管理端列表与推送

| 编号 | 验收项 |
| --- | --- |
| AC-DS-01 | P-M-DS-01 默认只展示「已确权且未推送」的资产，非「已确权」资产不出现 |
| AC-DS-02 | 支持按同步状态、币种、资产方、确权时间区间、关键词筛选，筛选结果与条件一致 |
| AC-DS-03 | 列表时间均带时区标注，无裸时间 |
| AC-DS-04 | 「已推送」条目的勾选框禁用，并给出 hover 说明 |
| AC-DS-05 | 汇总区按币种分组给出「笔数 + 该币种合计」，页面任何位置不出现跨币种总额 |
| AC-DS-06 | 未选定单一币种时金额排序控件禁用并提示 |
| AC-DS-07 | 单条推送与批量勾选推送均可用 |
| AC-DS-08 | 勾选超过 500 条时提交按钮禁用并提示分批处理 |
| AC-DS-09 | 跨页勾选后已选项不丢失，顶部常驻「已选 N 条」与清空入口 |
| AC-DS-10 | V-DS-01～V-DS-04 任一未通过的条目不可提交，并给出具体到字段的原因 |
| AC-DS-11 | 钱包地址缺失或格式异常时，仅提示不阻断，提交后仍成功入库 |
| AC-DS-12 | 资产状态在勾选后变化的，提交时被剔除并提示 |
| AC-DS-13 | 服务端对推送请求二次执行 V-DS-01～V-DS-04，绕过前端也无法提交非法条目 |
| AC-DS-14 | C-M-DS-01 展示待推条数、分币种金额、钱包地址提示条数 |
| AC-DS-15 | 提交期间为 loading 态，页面不出现「推送中」这一状态标签，数据库无中间状态 |
| AC-DS-16 | 提交超时或中断时，该批次条目落「推送失败 · E-DS-06」，并提示可直接重推 |
| AC-DS-17 | 批量推送中部分条目失败时，成功条目正常入库，不整体回滚 |
| AC-DS-18 | 结果面板区分「新入库 / 幂等命中 / 失败」，失败条目展示原因码与文案 |
| AC-DS-19 | 结果面板可展开逐条明细并跳转 P-M-DS-03 |

### 14.2 重推与推送记录

| 编号 | 验收项 |
| --- | --- |
| AC-DS-20 | 仅「推送失败」条目提供重推入口，「已推送」条目无该入口 |
| AC-DS-21 | 重推生成新批次号，重新走全套校验与幂等 |
| AC-DS-22 | 重推成功后同步状态转「已推送」，重推次数 +1，D-DS-43 失败原因清空 |
| AC-DS-23 | 系统不存在任何自动重试、定时补偿逻辑：运营端不可用期间不产生自动重发 |
| AC-DS-24 | P-M-DS-02 按批次倒序展示，字段完整（批次号、操作人、时间、条数、成功 / 失败数、来源） |
| AC-DS-25 | P-M-DS-03 支持深链，展示该批次逐条结果，并支持对全部失败条目一键重推 |
| AC-DS-26 | 推送记录不可编辑、不可删除 |

### 14.3 幂等（红线）

| 编号 | 验收项 |
| --- | --- |
| AC-DS-27 | **同一资产连续推送 5 次，运营端清单中始终只有 1 条记录**，条数与金额汇总不变 |
| AC-DS-28 | 第 2 次及以后的推送返回「幂等命中」且为成功语义，不返回错误 |
| AC-DS-29 | 幂等命中不更新已有记录的任何字段，仅在时间线追加一条「重复推送已忽略」 |
| AC-DS-30 | 并发推送同一资产（同时发起 10 次）不产生第二条记录，全部返回成功语义 |
| AC-DS-31 | 直接绕过应用层向数据层写入重复的「来源系统标识 + 来源资产 ID」被唯一约束拒绝 |
