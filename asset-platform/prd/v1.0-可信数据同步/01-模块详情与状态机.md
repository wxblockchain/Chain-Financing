## 7. 模块详情 · 资产管理端上链与推送侧

> **本章的阅读顺序说明**：业务上的先后是「上链（7.8）→ 推送（7.3～7.7）」，但 7.1～7.7 的编号在 V1.1 已入库并被其他章节引用，**本次不重排**，上链相关内容以 7.8、7.9 追加在本章末尾。实现与测试请以 5.2 的时序图为准。
> **落点说明（需求方 2026-09-10 合页裁定）**：**上链发生在 WS-305 资产管理端「应收账款」列表 / 详情页（P-M40 / P-M41）**，7.8 描述的动作、勾选、二次确认、结果、凭证与重新上链全部落在那两个页面上；本模块的「数据同步」菜单只有「数据推送」（P-M-DS-01）与「同步记录」（P-M-DS-02 / P-M-DS-03），**不设「底层数据上链」入口**。7.1～7.7 描述的都是推送侧。

### 7.1 F-DS-01 数据推送列表（P-M-DS-01）

| 项 | 规则 |
| --- | --- |
| 数据范围 | 全部企业中**状态为「已确权」**（WS-305 S3）的应收账款。非「已确权」状态的资产不出现在本页 |
| 本页的动作 | **只有「推送 / 重推」**。上链动作不在本页——上链状态列在此**只读**，仅用于推送前置判断与跳转（口径 12） |
| 默认筛选 | **「已上链且未推送」**——本页的作业对象就是这一批 |
| 列 | 应收账款编号、资产方（债权方企业名称）、资产类型、金额 + 币种、到期日、确权时间、**上链状态**、同步状态、最近推送时间、操作 |
| 筛选 | **上链状态（未上链 / 已上链 / 上链失败）**、同步状态（未推送 / 已推送 / 推送失败）、币种、资产方、确权时间区间、关键词（应收账款编号 / 任一合同号 / 资产方名称 / 交易哈希） |
| 排序 | 默认按确权时间倒序；**金额排序仅在已选定单一币种时开放**（继承 WS-305 CU-03） |
| 已推送条目 | 保留在列表中且**勾选框禁用**，hover 提示「该资产已推送，重复推送不会在运营端新增记录」 |
| **未上链 / 上链失败条目** | **勾选框禁用**，hover 提示「该资产尚未上链，需先完成上链才能推送」；行内提供「**去上链**」入口，跳到 WS-305 应收账款页（P-M40）对应记录（F-DS-21） |
| **已上链条目** | 展示交易哈希缩略（前 10 位 + `…` + 后 8 位，WS-302 13.5 口径），可复制完整值 |
| 失败条目 | 上链失败以「上链失败」、推送失败以「推送失败」标签呈现，行内直接给出失败原因与对应的重试入口——**本期两类失败的可见性都只在这一端**（口径 5） |
| 时间展示 | 以 UTC 存储，按账户时区渲染并带时区标注（WS-302 13.4） |

### 7.2 F-DS-02 金额展示与不做汇率折算的连锁约束

本模块**继承 WS-305 6.3 的 CU-01～CU-06，不做任何放宽**，两端同时适用：

| 约束 | 内容 |
| --- | --- |
| CU-01 | 任何列表、详情、汇总区**不得跨币种求和**，不得给出单一「总金额」 |
| CU-02 | 金额汇总一律按币种分组，每组给「笔数 + 该币种合计」，例 `1,200,000.00 CNY · 3 笔` |
| CU-03 | 金额排序仅在筛选条件已选定单一币种时开放，否则控件禁用并提示 |
| CU-04 | 金额与币种代码必须同屏相邻，数值在前、代码在后、千分位、法币 2 位小数；任何位置不得出现无币种的裸金额 |
| CU-05 | 两端的任何汇总区、导出内容同样受 CU-01～CU-04 约束，不得出具跨币种的单一口径报表 |
| CU-06 | 金额比对按该币种最小单位精度进行，`1000` 与 `1000.00` 视为相同 |

> 运营端的金额格式化按其自持基线（WS-308 `01-国际化基线.md` 第 5 节）执行，与上表不冲突：CU 约束管「能不能加总、能不能排序」，基线管「怎么显示一个数」。

### 7.3 F-DS-03 / F-DS-04 勾选、批量上限与推送前校验

**批量上限**：单批最多 500 条 `[假设-待确认 Q-DS-03]`。勾选超过上限时提交按钮禁用，并提示「单次最多推送 500 条，请分批处理」。跨页勾选保留已选项，页面顶部常驻「已选 N 条」与清空入口。

**推送前校验**（提交前在资产管理端本地执行，逐条判定）。**V-DS-01～V-DS-06 全部为硬拦项，前端剔除、服务端二次校验**，前端置灰不得作为唯一防线；其中 V-DS-05（钱包地址必填）与 V-DS-06（上链前置）是 2026-09-10 两次口径变更新增或收紧的：

| 编号 | 校验项 | 判定 | 未通过的处置 |
| --- | --- | --- | --- |
| V-DS-01 | 资产状态 | 必须为「已确权」 | 剔除该条并提示「资产状态已变化，不可推送」 |
| V-DS-02 | 必填字段完整 | D-DS-01～D-DS-19 中标必填的字段均非空 | 列出缺失字段，该条不可提交 |
| V-DS-03 | 资产方主体存在 | 债权方企业在平台存在且认证通过 | 该条不可提交，提示「资产方主体不可用」 |
| V-DS-04 | 未重复推送 | 同步状态不为「已推送」 | 勾选框禁用（7.1） |
| V-DS-05 | 钱包地址 | **必填 + 格式校验**：非空且符合 `0x` + 40 位十六进制（大小写不敏感） | **该条不可提交**，提示「资产方钱包地址缺失或格式异常，请先在资产平台补齐后再推送」，与 V-DS-02 同级处理 |
| V-DS-06 | **上链前置** | **该资产上链状态必须为「已上链」且持有完整链上凭证**（D-DS-20～D-DS-24） | 勾选框禁用；即便绕过前端，服务端也拒绝并返回「该资产尚未上链，不可推送」 |

> **V-DS-05 由「提示不阻断」改为「阻断」**（需求方 2026-09-10 裁定）：该地址是代币铸造的收币地址，缺失则下游无法铸造，因此本期不再存在「校验但不阻断」的项。**但它仍不产生任何独立状态**——拦截发生在收单之前，两端状态机不新增「待补充地址」一类状态（AC-DS-58）。

### 7.4 F-DS-05 二次确认与提交（C-M-DS-01）

- 确认弹层展示：待推条数、按币种分组的金额合计、**因钱包地址校验未通过而被剔除的条目数**、批量上限校验结果。语义是「有 N 条已被剔除、不会推」，不是「有 N 条带风险但仍会推」。
- 提交为**一次性阻塞操作**：前端进入 loading 态直至拿到逐条回执。「推送中」**不是持久状态**，不落库、不在列表展示（第 9 章）。
- 提交请求超时或网络中断：该批次全部条目按「推送失败 · 原因码 E-DS-06 回执未知」落状态，提示「结果未知，请稍后刷新或直接重推——重推受幂等保护，不会重复入库」。

### 7.5 F-DS-06 逐条结果反馈（C-M-DS-02）

| 回执类型 | 资产管理端落的同步状态 | 展示 |
| --- | --- | --- |
| 新入库 | 已推送 | 绿色成功标记 |
| 幂等命中（运营端已存在同一资产） | 已推送 | 绿色成功标记 + 「运营端已存在，未重复入库」说明 |
| 收单失败 | 推送失败 | 红色标记 + 原因码与原因文案（10.4） |
| 回执未知（超时 / 中断） | 推送失败 | 红色标记 + E-DS-06 |

批量**逐条独立处理、部分成功不整体回滚**；结果面板按「成功 N 条 / 失败 M 条」聚合，并可展开逐条明细、跳转 P-M-DS-03。

### 7.6 F-DS-07 主动再次推送（本期唯一重推入口）

| 项 | 规则 |
| --- | --- |
| 入口 | **只在资产管理端**：P-M-DS-01 列表行操作列、P-M-DS-03 批次详情行操作列，均支持单条与批量重推。运营端不提供任何重推入口（口径 5） |
| 可重推范围 | **仅「推送失败」的资产**。「已推送」的条目不提供重推入口 |
| 重推行为 | 生成**新的推送批次号**，重新走 7.3 校验与幂等；成功后同步状态转「已推送」 |
| 批量重推 | 支持在 P-M-DS-03 对某批次的全部失败条目一键重推，应对运营端短时不可用导致的批量失败（R-DS-03） |
| 重推次数 | 不限次，每次留痕；列表展示「重推次数」列 |
| 自动化 | **无自动重试、无补偿队列、无定时扫描**（需求方口径 4） |

### 7.7 F-DS-08 推送记录（P-M-DS-02 / P-M-DS-03）

- P-M-DS-02（「数据同步 · 同步记录」）按批次倒序展示**上链与推送两类批次**——上链动作虽然发生在 WS-305 页面上，**批次记录仍统一归本模块**，两类批次一处可查：批次类型（上链 / 推送）、批次号、操作人、时间、总条数、成功 / 失败条数、来源（人工上链 / 人工重新上链 / 人工推送 / 人工重推）；支持按批次类型筛选。
- P-M-DS-03 展示该批次逐条结果：应收账款编号、资产方、金额 + 币种、结果类型、原因码与原因、重试入口；**上链批次额外展示每条的交易哈希、区块高度、存证时间**。
- 同步记录**只增不改**，任何条目不可编辑与删除。**两类失败的完整原因只在这里可查**——运营端既不留失败痕迹、也看不到上链过程，因此本页是本期排查同步问题的唯一现场。

### 7.8 F-DS-17～F-DS-20 资产上链存证（2026-09-10 新增）

> **业务目的**：让金融服务平台拿到的每一条资产都带一份独立于资产平台的可信凭证。上链在业务上是推送的前置动作。
> **落点（需求方 2026-09-10 合页裁定）**：上链的全部交互落在 **WS-305 资产管理端「应收账款」列表 / 详情页（P-M40 / P-M41）**——资产管理人员在哪儿看资产，就在哪儿给它上链，不必先跳到另一个菜单。**不单独开「底层数据上链」菜单，也不新建页面编号。**

#### 7.8.1 触发与批量

| 项 | 规则 |
| --- | --- |
| 触发方式 | **人工触发**：在 **P-M40 应收账款列表**勾选「已确权且未上链」的资产点「上链」，或在 **P-M41 详情**对单条资产上链。确权完成**不自动上链** `[假设-待确认 Q-DS-11]` |
| 入口位置 | **WS-305 的 P-M40 / P-M41**：列表的常驻选择条与行操作、详情页右侧操作区。**本模块不新开菜单、不新建页面编号**，只在这两个已定稿页面上新增控件（5.1） |
| 与 305 的边界 | 只加勾选列、上链状态列与筛选、上链相关按钮与凭证展示；**不改 WS-305 既有的列、筛选、流程与文案**，**不在该页引入推送入口或运营端能力** |
| 权限 | 上链按钮受 `data_sync.chain` 控制，无该权限的账号看不到按钮、直接调接口也被服务端拒绝；该权限可单独回收，回收后 305 页面回到纯只读（主文档 3.1） |
| 批量 | 支持单条与批量，单批上限 500 条 `[假设-待确认 Q-DS-03]`，与推送同一套勾选、跨页保留、「已选 N 条」交互习惯 |
| 二次确认 | C-M-DS-04 展示待上链条数、按币种分组的金额、校验未通过条目摘要 |
| 操作人身份 | 资产管理人员**不装钱包、不接触私钥**，上链由平台侧服务代为发起；页面上不出现任何钱包连接、签名、gas 相关交互 |

#### 7.8.2 上链前校验（F-DS-18）

| 编号 | 校验项 | 判定 | 未通过的处置 |
| --- | --- | --- | --- |
| V-DS-07 | 资产状态 | 必须为 WS-305 的「已确权」 | 剔除该条并提示「资产状态已变化，不可上链」 |
| V-DS-08 | 存证字段完整 | 参与哈希存证的关键字段（10.1 中标注「参与存证」的字段）均非空 | 列出缺失字段，该条不可提交 |
| V-DS-09 | 未重复上链 | 上链状态不为「已上链」 | 勾选框禁用，hover 提示「该资产已上链」 |

#### 7.8.3 上链内容与凭证（F-DS-17）

| 项 | 规则 |
| --- | --- |
| 上链内容 | **关键字段的哈希存证**，不把业务明文写上链 `[假设-待确认 Q-DS-13]`。参与存证的字段见 10.1 的「参与存证」列，哈希算法与存证结构由链侧同学给定 |
| 为什么不上明文 | 应收账款金额、合同号、企业主体属于商业敏感信息，写上链即公开且不可撤回。存证哈希同样能证明「这条数据从上链那一刻起没被改过」，这正是运营端核查需要的性质 |
| 回执凭证 | 存证哈希、交易哈希、区块高度、链 ID、存证时间（D-DS-20～D-DS-24），**五项齐全才算上链成功** |
| 成功判定 | 以链上回执为准。回执未拿到（超时 / 中断）一律按失败处理并落 E-DS-08，由人工重新上链 |
| 幂等 | 以「来源系统标识 + 来源资产 ID」为存证幂等键：重新上链前先查该资产是否已有有效回执，已有则直接落「已上链」而不重复发交易，避免同一资产在链上留下多条存证（R-DS-08） |

#### 7.8.4 上链结果与人工重新上链（F-DS-19）

| 回执类型 | 上链状态 | 展示 |
| --- | --- | --- |
| 上链成功 | 已上链 | 绿色标记 + 交易哈希缩略 |
| 已存在有效存证（幂等命中） | 已上链 | 绿色标记 + 「该资产已有存证，未重复上链」说明 |
| 上链失败 | 上链失败 | 红色标记 + 原因码与原因文案（10.4 E-DS-07～E-DS-10） |
| 回执未知（超时 / 中断） | 上链失败 | 红色标记 + E-DS-08，提示「可直接重新上链，重试前会先查已有存证」 |

- 批量**逐条独立处理、部分成功不整体回滚**，与推送同口径。
- 重新上链入口在 **P-M40 行操作列、P-M41 详情页**与 **P-M-DS-03 批次详情**，支持单条与批量，生成新的上链批次号，**不限次、每次留痕**。
- **无自动重试、无补偿队列、无定时扫描**。
- 「上链中」与「推送中」同理，**不是持久状态**，只是提交请求期间的前端 loading 态（第 9 章）。

### 7.9 F-DS-21 推送前置拦截

| 项 | 规则 |
| --- | --- |
| 前端 | 在 P-M-DS-01 数据推送页：上链状态非「已上链」的资产勾选框禁用、推送按钮不可用，hover 给出「该资产尚未上链，需先完成上链才能推送」，并在行内给「去上链」跳转到 P-M40 对应记录 |
| 服务端 | **必须独立校验**（V-DS-06）。前端置灰不得作为唯一防线，绕过前端直接调接口一律拒绝 |
| 凭证完整性 | 上链状态为「已上链」但凭证字段缺失的，同样拒绝推送并提示「链上凭证不完整，请重新上链」——避免把一条没有凭证的资产推给运营端，那等于本次变更白做 |
| 失败资产 | 上链失败的资产不允许推送；先回到 WS-305 应收账款页重新上链成功，才能进入推送动作 |

## 8. 模块详情 · 运营端收单与资产清单

> **本章的总口径**：运营端只承接成功的结果。收单失败的条目不写入运营端任何数据、不在运营端任何页面出现、运营管理员不承担同步失败的处置职责（需求方 2026-09-09 第三轮拍板）。
> **2026-09-10 变更对本章的影响只有一处**：运营端收到的报文多了链上凭证，资产详情要展示凭证并提供区块浏览器跳转（8.3）。**上链过程本身对运营端不可见**——不展示「上链中 / 上链失败」，不新增状态标签与筛选项（8.4）。

### 8.1 F-DS-10 收单校验与入库

收单按**逐条**处理，顺序如下，任一步失败即终止该条并返回对应原因码：

| 顺序 | 校验 | 失败原因码 |
| --- | --- | --- |
| 1 | 来源可信性：调用方身份与来源系统标识合法（第 12 章） | E-DS-01 |
| 2 | 报文结构完整：必填字段齐全（**含 D-DS-05 资产方钱包地址**）、类型与长度合规 | E-DS-02 |
| 3 | 枚举合法：币种在 WS-305 6.2 枚举内，资产类型在 D-DS-06 枚举内 | E-DS-03 |
| 4 | 数值合规：金额 > 0 且精度符合该币种最小单位；日期格式与先后关系合规 | E-DS-04 |
| 4b | **链上凭证完整性**：存证哈希、交易哈希、区块高度、链 ID、存证时间五项齐全且格式合规。**只校验「有没有、格式对不对」，不调链验证真伪** | E-DS-02 |
| 5 | 幂等判定：按「来源系统标识 + 来源资产 ID」查重（8.2） | 不算失败，返回「幂等命中」 |
| 6 | 写入资产清单，同步状态置 **S-DS-1 已推送**，记录收单时间与来源批次 | E-DS-05（服务内部异常） |

**收单失败的处置（本版重点变化）**：

| 项 | 规则 |
| --- | --- |
| 数据 | **不写入资产清单、不写入任何失败记录表**。运营端不因一次失败的收单产生任何可查询数据 |
| 展示 | 运营端**任何页面、任何筛选项都不出现该条资产**，包括清单、详情与空态提示 |
| 回执 | 逐条返回原因码与原因文案给资产管理端（F-DS-11），失败的可见性与处置全部落在资产管理端 P-M-DS-01 / P-M-DS-03 |
| 服务端日志 | 收单失败仍须记入运营端服务日志用于排障（第 12 章可追溯），但**日志不是产品功能**，不提供运营端页面入口、不对运营管理员开放查询 |

> **运营端不做链上真伪校验**：本期运营端只存储与展示凭证，不连链、不调区块浏览器 API、不比对存证哈希。理由是运营端本期无链上能力（WS-308 定稿：运营管理员不装钱包、无链上操作能力），引入链验证意味着运营端要接链节点与链 ID 映射，属于另一个量级的工作。**核查动作由人完成**：运营管理员点凭证区的链接跳区块浏览器自行核对。这条取舍记在 R-DS-10。

> **为什么失败不落运营端**：运营端本期没有任何处置手段（不能改数据、不能重推、不能驳回）。让运营管理员看到一条自己动不了的失败记录，只会制造「这条我要不要管」的判断负担，并让清单的条数统计出现两种口径。失败的现场统一收在资产管理端，那里既有原因也有动作。

### 8.2 F-DS-09 幂等控制（本期红线）

| 项 | 规则 |
| --- | --- |
| 幂等键 | **来源系统标识 + 来源资产 ID**（D-DS-01 + D-DS-02）。来源资产 ID 沿用资产管理端的资产主键，即 WS-305 D-01 应收账款编号 `[假设-待确认 Q-DS-01]` |
| 约束位置 | 运营端资产清单对该组合建**唯一约束**，不依赖应用层判重作为唯一防线 |
| 命中行为 | **不新增记录、不更新已有记录、不重复计数**，直接返回「幂等命中」回执，并在该资产的同步链路时间线追加一条「重复推送已忽略」事件 |
| 并发 | 同一资产被并发推送时，唯一约束冲突同样按「幂等命中」返回成功，不得返回失败 |
| 与重推的关系 | 重推同一资产：若运营端已存在 → 幂等命中 → 资产管理端转「已推送」；若不存在 → 正常入库 |
| 红线 | 清单中同一资产出现两条记录，即为本期验收不通过（AC-DS-27） |

### 8.3 F-DS-12 资产清单与详情

**P-O-DS-01 资产清单**

## 9. 状态机

### 9.1 同步状态定义（本期只有两态）

| 编号 | 状态 | 含义 | 呈现端 | 是否终态 |
| --- | --- | --- | --- | --- |
| S-DS-1 | 已推送 | 运营端收单成功并已入清单（含幂等命中） | 两端（资产管理端的同步状态 + 运营端清单内的恒定值） | **是** |
| S-DS-2 | 推送失败 | 收单校验不通过，或回执未知（超时 / 中断） | **仅资产管理端** | 否，可人工重推转 S-DS-1 |

> 状态模型本身是两态，但**两态的呈现端不同**：S-DS-1 两端都有，S-DS-2 只在资产管理端呈现。运营端不存在处于 S-DS-2 的数据——不是「有但不显示」，是**根本没有写入**（8.1）。
> **同步状态与上链状态是两个独立的状态位**（9.3）：2026-09-10 变更新增的是上链状态，**同步状态仍然只有两态，运营端仍然只有一种可见状态**，这条口径没有被上链改动。
> 资产管理端另有一个**非状态**的初始形态：「未推送」＝同步状态字段为空，它不是状态机中的一态，仅作为列表筛选项。
> **「推送中」不作为持久状态存在**，只是提交请求期间的前端 loading 态；请求结束必落 S-DS-1 或 S-DS-2。这是「只有两态」口径的直接结果，实现时不得为了展示方便新增中间态。

### 9.2 同步状态流转（资产管理端视角）

```mermaid
stateDiagram-v2
    [*] --> 未推送: 资产已确权并完成上链（S-DS-3）
    未推送 --> 已推送: 收单成功 / 幂等命中
    未推送 --> 推送失败: 收单校验不通过 / 回执未知
    推送失败 --> 已推送: 人工主动再次推送成功
    推送失败 --> 推送失败: 人工主动再次推送仍失败（不限次）
    已推送 --> 已推送: 重复推送被幂等拦截，状态不变、不新增记录
```

**流转约束**

- 「已推送」为终态：本期没有任何动作可以让它离开该状态（无作废、无驳回、无撤回、无删除）。
- 「推送失败」→「已推送」的唯一路径是**资产管理人员主动再次推送**，无自动重试、无定时补偿、无运营端触发。
- **推送的前置条件是上链状态为「已上链」**（F-DS-21）：未上链或上链失败的资产进不了这张状态机。
- 状态变更一律由回执驱动，不允许人工直接改状态。
- 运营端不参与状态流转：它只产生回执，不持有 S-DS-2，也不能改变任何资产的同步状态。
- 服务端须对状态流转做强制校验：对「已推送」资产的推送请求，回执一律为「幂等命中」，不得产生新记录，也不得改变任何已有数据。

### 9.3 上链状态（2026-09-10 新增，资产管理端独有）

| 编号 | 状态 | 含义 | 呈现端 | 是否终态 |
| --- | --- | --- | --- | --- |
| S-DS-3 | 已上链 | 拿到完整链上回执（五项凭证齐全），含幂等命中 | **仅资产管理端** | **是** |
| S-DS-4 | 上链失败 | 链侧返回失败，或回执未知（超时 / 中断） | **仅资产管理端** | 否，可人工重新上链转 S-DS-3 |

> 「未上链」＝上链状态字段为空，与「未推送」一样**不是状态机中的一态**，仅作为列表筛选项。
> 「上链中」**不作为持久状态存在**，只是提交请求期间的前端 loading 态。
> **运营端不持有、不展示 S-DS-3 / S-DS-4**：运营端能看到的资产必然已上链，上链状态在那里没有区分价值。运营端展示的是**凭证本身**，不是上链状态。

```mermaid
stateDiagram-v2
    [*] --> 未上链: 资产在 WS-305 达到「已确权」
    未上链 --> 已上链: 上链成功 / 已有有效存证（幂等命中）
    未上链 --> 上链失败: 链侧失败 / 回执未知
    上链失败 --> 已上链: 人工主动重新上链成功
    上链失败 --> 上链失败: 人工主动重新上链仍失败（不限次）
    已上链 --> 已上链: 重复上链先查已有存证，不重复发交易
```

**流转约束**

- 「已上链」为终态：本期没有任何动作可以让它离开该状态（无撤销存证、无作废）。
- 「上链失败」→「已上链」的唯一路径是**资产管理人员主动重新上链**，无自动重试。
- 上链状态与同步状态**互不覆盖、各自独立存储**（D-DS-44 与 D-DS-40），实现时不得合并成一个字段——合并会让「已上链未推送」这个正常中间形态无处安放。
- 两个状态位的合法组合：未上链 + 未推送 / 上链失败 + 未推送 / 已上链 + 未推送 / 已上链 + 已推送 / 已上链 + 推送失败。**其余组合（如未上链 + 已推送）为非法，服务端须拒绝产生。**
