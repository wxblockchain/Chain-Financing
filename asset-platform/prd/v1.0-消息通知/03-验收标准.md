# 平台消息推送能力 PRD · 03 验收标准

> 本文件是《平台消息推送能力 PRD》的分册。章节号与编号沿用拆分前，未做重排。
> 入口与全文导航见主文档 [`v1.0-消息通知-PRD.md`](./v1.0-消息通知-PRD.md)。

**本文件讲什么**：第 16 章全部验收条目 AC-N01～AC-N88，按入口与角标、列表、详情与已读、跳转与失效、权限、业务办理进度、数据契约、与首批接入方的接入、平台通用性、边界十组组织。

**本文件不讲什么**：每条验收对应的规则本身。规则在 [`v1.0-消息通知-PRD.md`](./v1.0-消息通知-PRD.md)、[`01-页面与展示.md`](./01-页面与展示.md) 与 [`02-数据契约与字段.md`](./02-数据契约与字段.md) 中，本文件只列判定口径。

## 16. 验收标准

### 16.1 入口与角标

| # | 验收项 |
| --- | --- |
| AC-N01 | 已登录任意页面，顶部导航栏均展示通知铃铛，位置固定在语言切换器左侧；未登录页面不展示 |
| AC-N02 | 无未读时铃铛不展示角标，也不展示 `0` |
| AC-N03 | 有未读时角标数与服务端未读数一致；未读数超过 99 时展示 `99+` |
| AC-N04 | 已过期的未读消息不计入角标，但仍能在列表中看到并带「已过期」标签 |
| AC-N05 | 账号下拉内存在「消息中心」条目，点击直达消息中心（不经快捷面板） |
| AC-N06 | 点击铃铛展开快捷面板，展示最近 10 条（含已读），点击面板外区域或 Esc 收起 |
| AC-N07 | 快捷面板内仅展开不产生任何已读；点击某条进入详情后该条变已读 |
| AC-N08 | 页面切到后台时轮询暂停，切回前台立即拉取一次未读数 |
| AC-N09 | 未读数接口失败时角标保留上一次数值，不清零、不弹错误提示 |
| AC-N10 | 同一浏览器两个标签页：A 读一条消息，B 的角标立即减 1，B 列表中该行立即变为已读样式 |

### 16.2 列表

| # | 验收项 |
| --- | --- |
| AC-N11 | 分类筛选项由服务端返回的分类元数据渲染，前端代码中不存在写死的分类清单 |
| AC-N12 | 只渲染当前接收者实际拥有消息的分类，不展示会必然为空的分类 |
| AC-N13 | 分类筛选与已读/未读筛选可叠加，结果为两者的与关系 |
| AC-N14 | 筛选条件写入 URL，刷新后筛选态保持 |
| AC-N15 | 列表按创建时间倒序；标记某条已读后该行位置不变、不被移除 |
| AC-N16 | 资产端为「加载更多」，管理端为分页器；分页期间有新消息插入顶部时，翻页不出现重复项或漏项 |
| AC-N17 | 首次空态与筛选空态文案不同，且筛选空态提供「清除筛选」并可一键回到无筛选状态 |
| AC-N18 | 首屏失败展示错误态与重试；加载更多失败时已加载内容不清空 |

### 16.3 详情与已读

| # | 验收项 |
| --- | --- |
| AC-N19 | 详情为独立路由整页，支持直接打开深链与刷新 |
| AC-N20 | 详情内容渲染成功后才标记已读；详情加载失败时不标记已读 |
| AC-N21 | 标记已读请求失败不影响详情展示，不弹错误提示 |
| AC-N22 | 从详情返回列表，筛选条件、已加载页数与滚动位置全部保持 |
| AC-N23 | 在「只看未读」筛选下读完一条返回，该条仍留在列表中并显示为已读样式，不立即消失 |
| AC-N24 | 列表行悬浮出现「标为已读」，点击后就地标记，不进入详情 |
| AC-N25 | 「全部标为已读」在有筛选条件时只作用于筛选命中的消息，不影响其他分类的未读 |
| AC-N26 | 「全部标为已读」作用于筛选命中的**全部**消息，不限于当前已加载的页 |
| AC-N27 | 「全部标为已读」执行前有确认弹窗，弹窗内展示条数与当前筛选条件，并说明不可撤销 |
| AC-N28 | 当前筛选下无未读时，「全部标为已读」按钮禁用并有 tooltip 说明 |
| AC-N29 | 「全部标为已读」失败时角标与列表不发生任何变化 |
| AC-N30 | 重复标记同一条消息为已读不报错，`read_at` 保持首次已读时间 |

### 16.4 跳转与失效

| # | 验收项 |
| --- | --- |
| AC-N31 | 消息实体中不存在 URL 或路径字段；跳转由 `biz_type` + `biz_ref` 经映射表解析得出 |
| AC-N32 | 映射表中不存在该 `biz_type` 时，详情页**不渲染**跳转按钮，**且不展示任何说明文案**（操作区只剩「返回列表」），消息内容正常可读，不跳 404、不跳首页 |
| AC-N33 | 映射缺失时前端上报一次「未知业务类型」事件（含 `biz_type`） |
| AC-N34 | 预检返回 `resource_deleted` / `state_changed` / `no_permission` 时，跳转按钮**禁用**（不是隐藏）并展示对应的 C-23 说明条，三种文案各不相同 |
| AC-N35 | 四类失效下消息的标题、正文、时间均完整展示，不被隐藏或截断 |
| AC-N36 | 预检接口本身失败或超时时，跳转按钮保持可用并放行跳转 |
| AC-N37 | 预检在进入详情时执行一次，失效状态在按钮上提前体现；列表页不触发预检 |
| AC-N38 | 已过期消息的详情展示「该消息已过期」说明条且不渲染跳转按钮 |

### 16.5 权限

| # | 验收项 |
| --- | --- |
| AC-N39 | 列表接口忽略请求参数中的接收者标识，只按会话身份返回消息 |
| AC-N40 | 用他人消息 ID 访问详情接口返回 404 语义，与「消息 ID 不存在」的返回**完全一致**，无法区分 |
| AC-N41 | 用他人消息 ID 调用标记已读接口被拒绝，且不产生任何已读记录 |
| AC-N42 | 全部已读接口不接受前端传入的消息 ID 列表，范围由服务端按会话身份与筛选条件圈定 |
| AC-N43 | 跳转预检接口同时校验消息归属与目标资源的业务权限 |
| AC-N44 | 各端接口只返回本端 `end` 的消息（管理端只返回 `end = admin`、资产端只返回 `end = asset`，`fs` / `fs_ops` 同理），**任意两端之间不串池** |
| AC-N45 | 管理员 A 读一条管理端消息后，管理员 B 的未读数不变，该消息对 B 仍是未读且仍在列表中 |
| AC-N46 | 管理端界面不存在任何「查看某个资产端用户的消息」的入口 |
| AC-N47 | 新建的管理员账号首次登录时，其创建时间之前的历史消息不计入未读，但仍可在列表中查到 |
| AC-N48 | 未登录访问消息详情深链跳登录页并携带原路径，登录后回跳该详情；若该消息不属于登录账户则落到「消息不存在」页 |
| AC-N49 | 未读数轮询遇到 401 时触发统一的会话失效处理，不被静默忽略 |

### 16.6 业务办理进度

| # | 验收项 |
| --- | --- |
| AC-N50 | 进度类消息在列表中展示业务名称、当前节点、节点状态标签与更新时间 |
| AC-N51 | 节点状态标签为四态封闭枚举，每种状态有各自的视觉且始终带文本 |
| AC-N52 | 同一笔业务的多次进度更新在列表中是多条独立消息，各自独立已读，不合并为一条 |
| AC-N53 | 进度类消息详情展示进度区块（业务名称、当前节点、状态标签、更新时间），跳转按钮文案默认为「查看业务详情」 |
| AC-N54 | `node_index` 与 `node_total` 同时存在时展示「第 i/n 步」，缺任一则不展示 |
| AC-N55 | 管理端不出现「业务办理进度」分类 |

### 16.7 数据契约

| # | 验收项 |
| --- | --- |
| AC-N56 | 同一 `event_id` 重复提交只产生一条消息 |
| AC-N57 | 缺少文案（既无模板 key 也无快照）的消息被服务端拒收，并向触发方返回明确错误 |
| AC-N58 | 使用模板 key 的消息，用户切换语言后历史消息的标题与正文立即变为目标语言 |
| AC-N59 | 使用快照双语文案的消息（WS-302 现有负载形态）可直接接入并正确展示、正确切换语言，WS-302 无需改造 |
| AC-N60 | 当前语言翻译缺失时**回落到该端的默认语言**（`02-数据契约与字段.md` 9.5.4 逐端表）；该语言也缺失时展示最小形态，**任何情况下界面上不出现文案键名** |
| AC-N61 | `params` 缺少某变量时该占位符渲染为空，不展示 `{xxx}` 原文 |
| AC-N62 | 未登记的 `category` 的消息仍正常展示，分类标签回落为「其他」 |
| AC-N63 | 管理端不存在任何业务类型 / 消息分类的配置界面 |
| AC-N64 | 消息标题、正文与参数按纯文本渲染并转义，注入 HTML 标签的内容不会被作为标签解析 |
| AC-N65 | `dedupe_key` 命中时消息合并为一条、时间更新为最新，且若此前已读则恢复为未读并重新计入角标 |

### 16.8 与首批接入方的接入（以 WS-302 为例）

| # | 验收项 |
| --- | --- |
| AC-N66 | WS-302 现存的 3 类站内信事件（`account.wallet.linked` / `account.password.changed` / `account.email.changed`）全部能被本模块接收、展示、已读，无一落空 |
| AC-N67 | 上述事件由 WS-302 直接提供三段式 `biz_type`、`end`、`recipient_scope`、`page_target`，**本模块不做任何字段转换**（原 9.3.4 过渡表已移除） |
| AC-N68 | WS-302 事件的 `page_target`（页面编号 `P-A11`）经页面路由表解析，详情页跳转按钮可用并落到账户设置页；**不走映射缺失的降级路径** |
| AC-N69 | `recipient_scope = admin_account` 的消息只投递给 `recipient_admin_id` 指定的那一个管理员，其他管理员的列表与未读数中不出现该条（本期无接入方，用构造数据验证） |
| AC-N70 | 其他管理员用该条 `admin_account` 消息的 ID 访问详情接口返回 404 语义 |
| AC-N71 | WS-302 只走邮件的事件（E-09 通知旧邮箱、E-11 账户被锁定）不产生任何站内信 |
| AC-N72 | WS-302 的 `title_i18n` / `body_i18n` 落到快照字段后可正确展示，且用户切换语言后按新语言展示 |
| AC-N73 | 快照消息在用户变更时区偏好后，正文中的时间按新时区重新渲染（`variables` 有值时），文本其余部分不变 |
| AC-N74 | 资产端消息的 `page_target` 指向 `P-M*` 时被服务端拒收；管理端消息指向 `P-A*` 同样被拒收 |
| AC-N75 | 同一条消息同时携带 `biz_ref` 与 `page_target` 时被服务端拒收 |
| AC-N76 | 无跳转目标的消息详情页不渲染按钮，**且不展示「当前版本暂不支持跳转」之类的说明文案** |
| AC-N77 | 进度类消息的 `dedupe_key` 不含节点标识时，本模块不做「按事件类型 + 时间窗」的兜底去重推导（不会静默合并不同节点） |
| AC-N78 | 本模块**不存在任何命名转换层**；所有接入方（含 WS-302）直接提供三段式 `biz_type` |
| AC-N79 | 移除转换层后全部站内信功能不受影响（WS-302 已于 `5601e00` 完成 A-01，转换层已随之移除） |
| AC-N80 | `page_target` 取值在页面路由表中唯一命中；同一页面编号对应多个页面时，该编号不得进入路由表，相关消息按映射缺失降级而非落到错误页面 |

### 16.9 平台通用性（本轮新增）

> 这一组验收的对象不是某个功能，而是**规则的通用程度**。判定方法：拿一个**未在本 PRD 中出现过的虚构模块**（如「放款」）走一遍接入，看是否需要改动本模块。

| # | 验收项 |
| --- | --- |
| AC-N81 | 用 `docs/notification-contract/接入指南.md` 第 9 章的最小示例（虚构的放款模块）走通接入：产出消息 → 列表展示 → 已读 → 跳转 → 失效降级，**全程不修改本模块的任何页面逻辑、数据模型与 PRD 条款** |
| AC-N82 | 一级域取自 `docs/notification-contract/接入指南.md` 3.2 规划表的 `biz_type` 可直接使用；**未登记**的 `biz_type` 消息仍被接收、投递、展示与已读，仅跳转按钮不渲染并记录告警——**不丢消息** |
| AC-N83 | `biz_type` 使用保留段 `test` / `demo` / `tmp` 时被服务端拒收 |
| AC-N84 | 分类枚举中本期无接入方的取值（`finance` / `announcement` / `system` / `ops_alert`）已在代码层定义；这些分类**不出现在任何接收者的筛选器中**（因为无消息），不产生空筛选项 |
| AC-N85 | 未读计数按「可见集 − 已读集」计算，对 `account` / `admin_account` / `admin_all` 三种已实现的 `recipient_scope` 结果正确；新增一种 scope 时**未读计数算法不需要改动** |
| AC-N86 | 已读状态为独立实体，**不预生成未读记录**；一条 `admin_all` 消息在 N 个管理员未读时，已读表中该消息的记录数为 0 |

### 16.10 边界（本轮新增）

| # | 验收项 |
| --- | --- |
| AC-N87 | 消息契约中**不存在** `channels` / `channel_targets` 字段；接入方在负载中携带这两个字段时被**忽略**（不校验、不存储、不透传），不影响该条站内消息的正常投递与展示 |
| AC-N88 | 本模块的任何接口、任务与告警**不产生任何邮件 / 短信投递行为**，也不记录站外渠道的送达结果 |
