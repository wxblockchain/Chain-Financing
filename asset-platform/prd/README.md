# 资产平台 · PRD 目录

资产平台（资产端 + 资产管理端）的产品需求文档统一存放于此，按功能模块组织子目录。
模块的端归属清单见上一级 [`asset-platform/README.md`](../README.md)；金融服务平台的 PRD 不放这里，见 [`financial-service-platform/prd/`](../../financial-service-platform/prd/README.md)。

> 本目录原为仓库顶层的 `prd/`，已随平台级目录调整迁到 `asset-platform/prd/`。仓库外部对旧路径 `prd/…` 的引用需相应加上 `asset-platform/` 前缀。

## 命名约定

- 每个功能模块建立独立子目录，包含 PRD 主文档及流程图、数据字典等分册；入口文件与目录同名，为 `[版本号]-[功能名]-PRD.md`。
- 不再新增散落在本目录下的单文件 PRD——`v1.0-协议管理-PRD.md` 已收进 `v1.0-协议管理/`，四个模块形态统一。

## 维护规则

- **新增一份 PRD、或把已有 PRD 拆成目录时，必须在同一次提交里补上表。** 索引与文件同源，不允许只改一处——否则这张表很快就会变成一份只覆盖部分模块的旧账。
- 同一次提交里还要补 [`asset-platform/README.md`](../README.md) 的模块清单（含端归属），两张表都不允许漏。
- 表里只写路径、形态、对应需求与入口文件。功能内容、章节清单、编号索引一律放在各自主文档里，不往这里搬。
- 目录型 PRD 的入口文件统一命名为 `[版本号]-[功能名]-PRD.md`，与目录同名，便于一眼定位。

## 模板要点

- 背景与目标
- 用户故事与需求清单
- 功能详述（交互流程、规则、边界）
- 数据要求
- 验收标准
