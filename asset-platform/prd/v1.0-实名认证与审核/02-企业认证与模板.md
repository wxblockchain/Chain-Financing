### 7.3 M3 · 企业认证信息填写（P-K01 步骤 2）

#### 7.3.1 模板机制（F-K09）

步骤 2 的表单分两段：

| 段 | 内容 | 是否随模板变化 |
| --- | --- | --- |
| A · 公共段 | 企业注册地、企业名称、企业英文名称、注册地址、与本人的关系（授权关系） | 否 —— 所有模板都有，字段名与口径一致 |
| B · 模板段 | 注册号类字段、注册证明文件、董事 / 法定代表人 / 授权人材料、授权委托书 | 是 —— 由「企业注册地」决定 |

- **企业注册地是模板的唯一驱动字段**，位于步骤 2 的第一项。未选择注册地时，模板段整体不渲染，仅展示占位说明 `Select the place of registration to load the required documents. / 选择企业注册地后加载所需材料清单。`
- 选中注册地后立即渲染对应模板；渲染前后页面不跳转、不刷新，已填的公共段内容不受影响。
- 模板与注册地的映射：

| 企业注册地 | 加载模板 | 模板编号 |
| --- | --- | --- |
| 中国（大陆） | 国内模板 | T1 |
| 中国香港特别行政区 | 香港模板 | T2 |
| 美国 | 美国模板 | T3 |
| 开曼群岛 | 开曼模板 | T4 |
| 尼日利亚 | 尼日利亚模板 | T5 |
| **中国澳门特别行政区** | **通用模板** | **T6** |
| **中国台湾地区** | **通用模板** | **T6** |
| 其他任何注册地 | 通用模板 | T6 |

> **中国澳门特别行政区与中国台湾地区显式走 T6**（需求方已确认，DK-35）。之所以在表里单独列出来，是因为它们在国家 / 地区清单里与「中国（大陆）」相邻，实现时极易被并入 T1；模板路由必须按 `registration_region` 的**具体代码**匹配（`MO`、`TW` → T6），不得按「是否属于中国」这类归类判断。二者的企业唯一键按 T6 通用规则处理，作用域取各自的地区代码：`MO:{归一化注册号}`、`TW:{归一化注册号}`（见 9.2）。

各模板的完整字段与材料定义见 8.5。

#### 7.3.2 授权关系段（F-K13）

企业认证不重复采集个人信息。步骤 2 的公共段包含一项只读引用：

| 项 | 内容 |
| --- | --- |
| 被授权人 / 提交人 | **自动引用步骤 1 的姓名、英文姓名、证件类型与证件号码**，只读展示，不可在步骤 2 修改（要改回步骤 1 改） |
| 与企业的关系 | 单选：`Legal representative / 法定代表人`、`Director / 董事`、`Authorized signatory / 授权代表`、`Authorized person / 被授权人`（必填） |

- 该项的业务意义：授权委托书上的被授权人必须是提交认证的这个自然人，这是个人认证与企业认证之间唯一的业务关联，也是审核要点之一（[`04-管理端审核.md`](./04-管理端审核.md) 8.6.3）。
- 当「与企业的关系」选择为法定代表人 / 董事本人时，界面提示：授权委托书仍需提交（各模板的必填口径以 8.5 为准），本期不做「本人即法定代表人则免交委托书」的豁免（DK-41）——口径统一，可以省掉审核员判断「这个人是不是法定代表人本人」这一额外环节。

#### 7.3.3 切换企业注册地的已填内容处理（F-K11，强制）

切换注册地是本模块最容易丢数据的操作，处理规则必须明确到字段级：

| 内容类别 | 切换后处理 | 说明 |
| --- | --- | --- |
| 公共段字段（企业名称、英文名称、注册地址、与企业的关系） | **保留** | 语义与模板无关 |
| 模板专有的号码类字段（统一社会信用代码、CR 编号、EIN、RC 编号等） | **清空** | 语义与位数规则均不同，保留即错误 |
| 注册证明类文件（营业执照 / CI / Articles of Incorporation / …） | **清空引用** | 各法域文件名称与性质不同 |
| 董事 / 法定代表人 / 授权人证件 | **保留** | 各模板语义相同：一份自然人身份证件影像 |
| 授权委托书 | **保留** | 各模板语义相同 |
| 已计算出的企业唯一键 | **作废重算** | 见 9.2 |

**二次确认（C-K03）**

- 切换前弹出确认弹窗，**逐条列出**将被清空的字段名与文件名（不是笼统的一句「部分内容将被清空」）。
- 文案：`Changing the place of registration will clear the following fields and documents: … / 切换企业注册地将清空以下字段与材料：…`
- 用户确认后执行清空并加载新模板；取消则注册地回到原值，不做任何改动。
- 若切换时模板段尚未填写任何内容，则**不弹确认**，直接切换。
- 被清空的上传文件在**草稿保留期内不做物理删除**，用户若切回原注册地，系统提示可从「最近上传」重新选用，避免重复上传（实现要求，不额外出界面：在上传控件内以「最近上传」列表呈现）。

### 8.4 企业认证：公共字段与模板机制

#### 8.4.1 公共段字段（所有模板共用）

| 序 | 字段 | 标识 | 类型 | 必填 | 校验规则 | 业务意义 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | **企业注册地** | `registration_region` | enum | 是 | 标准国家 / 地区清单；**驱动模板加载**；注册地为美国时，additionally 必填「注册州」（见 T3） | 决定适用的登记制度与材料清单 |
| 2 | 企业名称 | `company_name` | string | 是 | 1–200 字符；与注册证明文件上的名称一致（人工核验） | 主体名称原文 |
| 3 | 企业英文名称 | `company_name_en` | string | 视模板 | 1–200 字符；仅拉丁字母、数字、空格与常见标点；注册地为中国（大陆）时**选填**，其余模板**必填** | 国际业务与英文界面展示 |
| 4 | 注册地址 | `registered_address` | string | 是 | 1–300 字符；与注册证明文件一致（人工核验） | 主体注册地址 |
| 5 | 与企业的关系 | `applicant_role` | enum | 是 | `legal_representative` / `director` / `authorized_signatory` / `authorized_person` | 授权链条的起点，对应授权委托书 |
| 6 | 被授权人（只读） | — | — | — | 自动引用个人认证的姓名、英文姓名、证件类型、证件号码 | 个人与企业两份申请之间的业务关联 |

#### 8.4.2 模板配置的下发方式

- 六套模板的字段清单、材料清单、校验规则与中英文案由**配置下发**（随部署配置文件维护），不硬编码在前端代码中。
- 新增一个法域的专属模板 = 增加一份模板配置，不改前端代码结构。
- 国家 / 地区清单与美国州清单同样由配置下发。
- 配置加载失败时：注册地选择器仍可用，模板段展示错误态并提示联系客服，**不允许降级为"什么都不填也能提交"**。

#### 8.4.3 模板段字段的通用约定

| 约定 | 说明 |
| --- | --- |
| 注册号类字段 | 每套模板有且只有一个**主注册号**（参与企业唯一键，见 9.2），可另有辅助号码字段 |
| 号码校验强度 | 中国大陆的统一社会信用代码做**强校验**（格式明确且唯一）；**境外注册号一律只做宽松校验**（字符集 + 长度区间），格式不符时**提示但不阻断**，最终以人工审核为准 |
| 为什么境外号码不做强校验 | 各法域的编号规则会随登记机构调整而变化，把规则写死在前端会导致合法企业填不进来。宽松校验 + 人工核对文件，是更稳的组合。该口径需在 20 章 Q-01 与需求方确认后固化 |
| 材料必填标记 | 每份材料明确标注「必填 / 选填」，界面上不使用模糊表述 |
| 材料名称 | 使用该法域的**官方文件名称**（中英并列），不做本地化意译 |

### 8.5 六套企业认证模板

> **[待确认 Q-01]** 以下四个境外法域（香港 / 美国 / 开曼 / 尼日利亚）的材料清单，是依据各地公开的公司登记制度惯例拟定的**建议清单**，尚未获得需求方指定的权威来源。若贵司或合规顾问已有指定的材料清单来源（如银行开户 KYB 清单、律所出具的尽调清单），请提供，本节按其覆盖修订。各注册号的位数规则同理，本期一律按宽松校验实现（8.4.3）。

#### 8.5.1 T1 · 中国（大陆）国内模板

| 序 | 字段 / 材料 | 标识 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- | --- | --- |
| 1 | **统一社会信用代码** | `uscc` | string | **是** | 18 位；仅大写字母与数字；**强校验**：`^[0-9A-HJ-NPQRTUWXY]{2}[0-9]{6}[0-9A-HJ-NPQRTUWXY]{10}$`（不含字母 I、O、S、V、Z）；归一化：去空格、转大写；**存储与展示保留原样输入** |
| 2 | **营业执照** | `business_license` | file | **是** | 副本影像；应为现行有效版本 |
| 3 | **法定代表人证件** | `legal_rep_id` | file | **是** | 法定代表人的身份证件影像；身份证需人像面 + 国徽面（2 份），护照需人像页（1 份） |
| 4 | **授权委托书** | `authorization_letter` | file | **是** | 由法定代表人签署、授权本次提交人代表企业办理；应含企业公章 / 签章 |
| 5 | 法定代表人姓名 | `legal_rep_name` | string | 是 | 1–64 字符；与营业执照一致（人工核验） |

- **主注册号**：`uscc`（参与企业唯一键）。
- 上述 1–4 项为需求方明确指定的必填集合，不得降级为选填。

#### 8.5.2 T2 · 中国香港特别行政区模板

| 序 | 字段 / 材料 | 标识 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- | --- | --- |
| 1 | **公司注册编号（CR No.）** | `hk_cr_number` | string | **是** | 公司注册处签发、印于法团成立为法团证明书上的编号；宽松校验：归一化后 1–12 位数字；**主注册号** |
| 2 | 商业登记号码（BR No.） | `hk_br_number` | string | 是 | 商业登记证上的登记号码；宽松校验：归一化后 8 位数字（如含 3 位分支号则为 11 位）；不参与唯一键，作为辅助识别 |
| 3 | **法团成立为法团证明书**<br>Certificate of Incorporation (CI) | `hk_ci` | file | **是** | 注册证明文件 |
| 4 | **商业登记证**<br>Business Registration Certificate (BR) | `hk_br_cert` | file | **是** | 有有效期，须在有效期内（人工核验） |
| 5 | **周年申报表 NAR1 / 法团成立表格 NNC1** | `hk_nar1` | file | **是** | 载有董事及股东资料；新成立未满一年的公司可提交 NNC1 |
| 6 | **董事 / 授权人证件** | `hk_director_id` | file | **是** | 签署授权文件的董事或授权代表的身份证件影像（香港身份证正反面 / 护照人像页） |
| 7 | **授权委托书 / 董事会决议**<br>Authorization Letter / Board Resolution | `hk_authorization` | file | **是** | 由董事签署，授权提交人代表公司办理 |
| 8 | 董事姓名 | `hk_director_name` | string | 是 | 与 NAR1 / NNC1 上的记载一致（人工核验） |

- **主注册号**：`hk_cr_number`。
- 与国内模板的差异要点：香港有 **CR 与 BR 两套编号**，前者标识法团、后者标识商业登记；董事资料来自 NAR1 / NNC1 而非营业执照。

#### 8.5.3 T3 · 美国模板

| 序 | 字段 / 材料 | 标识 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- | --- | --- |
| 1 | **注册州 / State of registration** | `us_state` | enum | **是** | 美国州与属地标准清单（含 DC）；由配置下发；**参与企业唯一键** |
| 2 | **州注册号 / State Entity (File) Number** | `us_entity_number` | string | **是** | 由注册州州务卿签发；**各州格式不统一**，宽松校验：归一化后 2–20 位字母、数字或连字符；**主注册号** |
| 3 | 联邦雇主识别号（EIN） | `us_ein` | string | 是 | 9 位数字，通常书写为 `XX-XXXXXXX`；宽松校验：归一化（去连字符空格）后 9 位数字；**作为第二唯一键**（见 9.2） |
| 4 | 实体类型 / Entity type | `us_entity_type` | enum | 是 | `Corporation` / `LLC` / `LP` / `LLP` / `Other`；决定注册证明文件的名称 |
| 5 | **注册证明文件** | `us_formation_doc` | file | **是** | 按实体类型：公司为 **Articles of Incorporation / Certificate of Incorporation**；LLC 为 **Articles of Organization / Certificate of Formation**；界面按所选实体类型展示对应名称 |
| 6 | 良好存续证明<br>Certificate of Good Standing | `us_good_standing` | file | 是 | 由注册州签发；建议签发日期在 6 个月内（可调参数 N-K03），超期由人工判断是否驳回 |
| 7 | **董事 / 授权签署人证件** | `us_signatory_id` | file | **是** | 签署授权文件者的身份证件影像 |
| 8 | **授权文件**<br>Corporate Resolution / Power of Attorney | `us_authorization` | file | **是** | 授权提交人代表公司办理；美国实践中常以董事会决议或授权书形式出具 |
| 9 | 授权签署人姓名与职务 | `us_signatory_name` / `us_signatory_title` | string | 是 | 与授权文件一致（人工核验） |

- **主注册号**：`us_entity_number`（**必须与 `us_state` 组合使用**——同一号码在不同州可能重复，单独使用不构成唯一）。
- 与国内模板的差异要点：注册在**州**一级而非国家一级，因此唯一键必须含州；EIN 是联邦税务编号，不是注册号，但在全国范围内唯一，故作为第二唯一键。

| 4 | **董事及高级职员名册**<br>Register of Directors and Officers | `ky_register_directors` | file | **是** | 开曼公司的董事信息不公开可查，故须由公司提供名册 |

- **主注册号**：`ky_registration_number`。
- 与其他模板的差异要点：董事与股东信息**不通过公开登记册获取**，必须以公司出具的名册（Register of Directors and Officers / Register of Members）替代；现况证明由注册代理人而非登记机关签发。

#### 8.5.5 T5 · 尼日利亚模板

| 序 | 字段 / 材料 | 标识 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- | --- | --- |

| 8 | **授权委托书 / 董事会决议** | `ng_authorization` | file | **是** | 授权提交人代表公司办理 |

- 与其他模板的差异要点：CAC 的编号带业务类型前缀；董事与股东资料来自 Status Report（现行）或 CO7（旧制），两者择一提交。

#### 8.5.6 T6 · 通用模板（其余注册地）

| 序 | 字段 / 材料 | 标识 | 类型 | 必填 | 规则 |

| 2 | **注册号** | `generic_registration_number` | string | **是** | 宽松校验：归一化后 2–40 位字母、数字或连字符；**主注册号** |
| 3 | 注册机关 | `generic_registry_authority` | string | 是 | 签发该编号的登记机构名称；1–200 字符 |
| 4 | 成立日期 | `generic_incorporation_date` | date | 是 | 不得晚于当天 |

| 6 | **董事 / 法定代表人 / 授权人证件** | `generic_signatory_id` | file | **是** | 签署授权文件者的身份证件影像 |

- **主注册号**：`generic_registration_number`（与 `registration_region` 组合构成唯一键，见 9.2）。

- **不新增独立的"补件"状态与流程**：审核员在材料不足以判断时，**以驳回处理**（原因项 R-E10「材料缺失或不足，请提供：{note}」并写明需补充什么），用户按驳回流程补齐后重新提交。理由是新增补件状态会让状态机从 4 态变成 6 态、并引出「补件期间是否占用唯一键」等一连串新口径，而驳回 + 明确原因项已能达成同样效果。

## 9. 企业唯一标识（F-K12）

> 本章回答一个问题：**平台如何判定"这是同一家企业"**。它同时是重复注册拦截的依据，也是后续「一账号多企业」扩展的地基。

### 9.1 目标与判定原则

| 原则 | 说明 |
| --- | --- |
| 唯一性来自**登记机关签发的编号**，不来自企业名称 | 名称可重名、可变更、可有中英两版；编号是登记机关对法人主体的唯一指派 |
| 编号必须**带作用域** | 注册号只在其签发法域内唯一。`123456` 在开曼和香港可能是两家不同公司，因此唯一键必须是「作用域 + 编号」，不能是裸编号 |
| 作用域的粒度**跟随登记机关的层级** | 中国大陆、香港、开曼、尼日利亚在国家 / 地区一级登记 → 作用域 = 国家 / 地区代码；**美国在州一级登记 → 作用域 = 国家代码 + 州代码** |
| 比对用归一化值，展示用原样值 | 与证件号码口径一致（[`01-个人认证.md`](./01-个人认证.md) 8.2.3） |
| 唯一键**一经生成即不可变** | 企业实体的唯一键在企业认证通过时固化；后续企业改名不影响唯一键 |

### 9.2 各模板的唯一键构成

**唯一键格式**：`{作用域}:{归一化主注册号}`

| 模板 | 作用域 | 主注册号字段 | 唯一键示例 | 备注 |
| --- | --- | --- | --- | --- |
| T1 中国（大陆） | `CN` | `uscc` 统一社会信用代码 | `CN:91310000MA1K3XYZ8H` | 统一社会信用代码本身即全国唯一 |
| T2 香港 | `HK` | `hk_cr_number` 公司注册编号（CR） | `HK:3012345` | BR 号码不参与唯一键（同一法团换发 BR 不影响其法团身份） |
| T3 美国 | `US-{州代码}` | `us_entity_number` 州注册号 | `US-DE:7654321` | **必须带州**，同一号码在不同州可能指向不同实体 |
| T3 美国（第二唯一键） | `US-EIN` | `us_ein` 联邦雇主识别号 | `US-EIN:123456789` | EIN 为联邦级、全国唯一，作为**并行的第二唯一键**参与查重 |
| T4 开曼群岛 | `KY` | `ky_registration_number` 公司注册编号 | `KY:345678` | |
| T5 尼日利亚 | `NG` | `ng_rc_number` CAC 注册号 | `NG:1234567` | 归一化时剥离 `RC` / `BN` / `IT` 前缀 |
| T6 通用 | 该注册地的 ISO 3166-1 alpha-2 代码 | `generic_registration_number` | `SG:202312345K` | 用户填写的「注册号名称」不参与唯一键，仅作展示与审核参考 |
| T6 · 中国澳门 | `MO` | 同上 | `MO:12345` | 走 T6 通用规则（DK-35），不并入 `CN` 作用域 |
| T6 · 中国台湾 | `TW` | 同上 | `TW:12345678` | 走 T6 通用规则（DK-35），不并入 `CN` 作用域 |

**第二唯一键的判定规则（仅美国）**

- 美国企业同时生成两个唯一键：`US-{州}:{州注册号}` 与 `US-EIN:{EIN}`。
- 查重时**任一命中即视为重复**。
- 这样处理的原因：同一家美国公司可能在多个州注册（本州注册 + 外州 foreign qualification），只用州注册号会漏判；EIN 是联邦层面的唯一标识，能兜住这种情况。

### 9.3 归一化规则（强制）

对主注册号执行以下步骤，得到用于比对的归一化值：

| 步骤 | 处理 | 例 |
| --- | --- | --- |
| ① | Unicode 规范化（NFKC），全角转半角 | `１２３` → `123` |
| ② | 去除首尾空白 | ` 3012345 ` → `3012345` |
| ③ | 剔除所有非字母数字字符（空格、连字符 `-`、下划线 `_`、点 `.`、斜杠 `/`、逗号、括号等） | `RC-1,234.567` → `RC1234567` |
| ④ | 字母统一转**大写** | `ma1k3xyz8h` → `MA1K3XYZ8H` |
| ⑤ | **按模板剥离业务前缀**（仅尼日利亚：`RC` / `BN` / `IT`） | `RC1234567` → `1234567` |
| ⑥ | 拼接作用域，得到唯一键 | → `NG:1234567` |

- **归一化只用于唯一键计算与查重比对。** 企业注册号的**存储与展示一律保留用户原样输入**（与 [`01-个人认证.md`](./01-个人认证.md) 8.2.3 同一口径）。
- 归一化后为空字符串时视为无效注册号，提交被拦截（与必填校验合并提示）。
- 归一化规则随模板配置下发；规则变更属于**破坏性变更**，需同步重算并核对存量唯一键，不得静默上线。

### 9.4 查重时点与重复注册的拦截

#### 9.4.1 提交时查重（主拦截点）

- 时点：用户在 P-K01 步骤 3 点击「提交」，服务端完成字段校验后、创建申请前。
- 比对范围：所有**占用中**的企业唯一键（定义见 9.4.3）。
- 命中时：**拦截提交**，不创建申请，草稿保留。页面停留在步骤 3，注册号字段标红并展示：

| 场景 | 提示文案 |
| --- | --- |
| 该唯一键被**其他账号**占用 | `This company is already registered on the platform. If you believe this is an error, contact support. / 该企业已在平台注册，如有疑问请联系客服。`（**不透露占用方的账号、姓名或联系方式**） |
| 该唯一键被**本账号**占用（用户重复提交同一家企业） | `You have already submitted this company. / 你已提交过该企业的认证申请。` 并引导至用户中心查看当前状态 |

- 拦截事件写入审核记录（[`04-管理端审核.md`](./04-管理端审核.md) 7.8.1）与风控日志，便于识别恶意批量试探。

#### 9.4.2 审核通过时二次查重（并发保护）

- 时点：企业审核员点击「通过」，服务端写入 `approved` 之前。
- 目的：拦住"两个账号在极短时间内各自提交同一家企业、都通过了提交时查重"的并发场景。
- 命中时：拒绝本次通过操作，提示审核员 `Another company with the same unique key has already been approved. / 已存在相同唯一标识且已通过的企业。`，由审核员按重复注册驳回（原因项 R-E10 + 说明）。

#### 9.4.3 唯一键的占用与释放

| 企业认证状态 | 是否占用唯一键 | 说明 |
| --- | --- | --- |
| 草稿（未提交） | **否** | 草稿不锁定唯一键，避免有人填一半就把企业占住 |
| 审核中 `under_review` | **是** | 防止同一企业被多个账号并行提交、耗费重复审核成本 |
| 已通过 `approved` | **是** | 正式绑定 |
| 已通过后重新提交、新一轮审核中 | **是（不释放）** | 见 [`03-流程与状态机.md`](./03-流程与状态机.md) 7.5.3.3：原绑定持续有效，不允许他人在此空档提交同一家企业 |
| 已驳回 `rejected`（含级联驳回） | **否** | 释放，允许该企业被重新提交（可能是原账号重提，也可能是另一账号来提） |

> 为什么"审核中"就占用：如果只在通过后才占用，两个账号可以并行提交同一家企业，审核员会重复审两次同样的材料，最后还得驳回一个——把成本前置到提交这一刻更划算，代价是极小概率下第二个提交人需要等第一个被驳回后才能提交，这一点在提示文案里引导他联系客服。

### 9.5 与账号的绑定关系及后续扩展

#### 9.5.1 本期的关系模型

```
Account (account_id)  ──1:1──  PersonalVerification（个人认证申请，多版本）
       │
       └──1:1──  EnterpriseVerification（企业认证申请，多版本）  ──N:1──  Enterprise（企业实体）
                                                                          └─ unique_key（唯一）
```

| 关系 | 本期口径 |
| --- | --- |
| 账号 : 企业 | **1 : 1**。一个账号本期只能认证并绑定一家企业 |
| 企业 : 账号 | **1 : 1**。一家企业（同一唯一键）只能被一个账号绑定为已通过状态 |
| 企业实体的产生 | 企业认证**通过时**创建或关联 `Enterprise` 记录，并固化 `unique_key`；审核中的申请只占用唯一键，不创建企业实体 |
| 企业改名 | 企业实体的名称字段可随后续版本更新，`unique_key` 不变 |

#### 9.5.2 为后续「一账号多企业」预留的扩展位

后续扩展时，**唯一键与企业实体不需要改动**，只需把账号与企业之间的直连关系替换为独立的关系对象：

```
Account ──N:N── Enterprise
        通过 AccountEnterpriseRelation：
        { account_id, enterprise_id, role, authorization_doc, status, valid_from, valid_to }
```

| 扩展点 | 本期如何预留 |
| --- | --- |
| 企业实体独立成对象 | **本期即独立**：企业信息不挂在账户档案上，而是 `Enterprise` 对象（[`03-流程与状态机.md`](./03-流程与状态机.md) 15.3），账户只持有一个指向它的关系 |
| 关系上的角色与授权 | 本期把 `applicant_role`（与企业的关系）与授权委托书记录在**企业认证申请**上，扩展时平移到关系对象即可，字段语义不变 |
| 唯一键 | 本期的 `{作用域}:{归一化注册号}` 与账号无关，天然支持一家企业被多个账号以不同角色关联 |
| 唯一性口径的变化 | 扩展后，「唯一」的含义从「一家企业只能被一个账号绑定」变为「一家企业在平台只有一条企业实体记录，可被多个账号按角色关联」——**唯一键定义不变，变的是关系表的约束**，这正是本设计要保证的 |
| 界面 | 本期不出任何企业切换、企业列表、成员管理界面 |
