## 7. 模块详情

### 7.1 M1 · 认证入口与准入

#### 7.1.1 用户中心的认证状态区（P-A17，F-K01）

用户中心是 WS-302 定义的登录落地页。本文档定义其顶部区域：**认证状态区**，展示两条相互独立的认证轨道。

| 区块 | 内容 |
| --- | --- |
| 标题区 | `Identity & business verification / 实名认证`，副行说明「完成个人认证与企业认证后即可开始业务」 |
| 个人认证卡 | 状态标签、提交时间、结论时间、驳回原因摘要（仅驳回态）、版本号（重提后展示「第 N 次提交」） |
| 企业认证卡 | 同上，另展示企业名称与注册地 |
| 主操作按钮 | 按当前状态变化：`Start verification / 开始认证`、`View submission / 查看提交内容`、`Resubmit / 重新提交` |

**主操作按钮的状态映射**

| 个人状态 | 企业状态 | 主按钮 | 点击后 |
| --- | --- | --- | --- |
| 未提交 | 未提交 | 开始认证 | 先走 7.1.2 凭据校验，通过后进 P-K01 步骤 1 |
| 未提交（有草稿） | 未提交（有草稿） | 继续填写 | 进 P-K01，定位到草稿最后停留的步骤 |
| 审核中 | 审核中 / 已通过 | 查看提交内容 | 进 P-K03（只读） |
| 已通过 | 审核中 | 查看提交内容 | 进 P-K03（只读） |
| 任一为已驳回 | — | 重新提交 | 进 P-K01，预填上一版数据并高亮被驳回项 |
| 已通过 | 已通过 | **更新认证资料** | 展示「已认证」标记；点击进入 P-K01 并预填现有内容，提交后重新进入审核；**原通过结论在新结论出来前继续有效**（[`03-流程与状态机.md`](./03-流程与状态机.md) 7.5.3.3） |

- 状态卡采用**双轨并列**呈现，不合并成一条总状态。用户必须能看出「个人已通过、企业还在审」这类中间态。
- 驳回态的卡片使用错误色，并直接展示第一条驳回原因摘要 + 「查看全部原因」。

#### 7.1.2 发起认证前的凭据完备性校验（F-K03，引用 WS-302）

- 点击「开始认证 / 继续填写 / 重新提交」时，**先**执行 WS-302 7.5.2 的凭据完备性校验：账户的 `email` 与 `wallet_address` 是否同时非空。
- 未通过时不跳走，在当前页弹出 WS-302 的 C-09 就地补齐弹层；补齐后原地继续进入认证流程。
- 密码不参与判定。
- **服务端在创建 / 更新认证草稿与提交时同样校验**，前端弹层不是唯一防线。

#### 7.1.3 认证准入与未完成时的功能可达范围（F-K02）

**准入规则**：业务功能的放行条件是 **个人认证 `approved` 且 企业认证 `approved`**（即「双认证通过」）。任一未通过，业务功能不放行。

| 能力 | 未提交 | 审核中 | 存在驳回 | 双通过 |
| --- | --- | --- | --- | --- |
| 登录、退出登录 | ✅ | ✅ | ✅ | ✅ |
| 切换语言 / 时区 | ✅ | ✅ | ✅ | ✅ |
| 查看协议与隐私政策 | ✅ | ✅ | ✅ | ✅ |
| 联系客服 | ✅ | ✅ | ✅ | ✅ |
| 账户设置（P-A11：改邮箱、设密码、看钱包地址） | ✅ | ✅ | ✅ | ✅ |
| 用户中心与认证状态查看 | ✅ | ✅ | ✅ | ✅ |
| 填写 / 保存认证草稿 | ✅ | ❌（已提交，草稿冻结） | ✅（重提） | ❌ |
| 查看已提交内容（P-K03 只读） | — | ✅ | ✅ | ✅ |
| 重新提交 | — | ❌ | ✅ | ✅（更新认证资料） |
| 总览页（P-A16） | ✅ 可进入（本期为壳子） | ✅ | ✅ | ✅ |
| **业务功能**（资产、额度、合同、结算等） | ❌ | ❌ | ❌ | ✅ |

**口径说明**

1. **不做全局封锁**。未完成认证的用户仍可正常登录、浏览与维护账户；被拦住的只有业务功能本身。理由与 WS-302 7.5.3 一致：业务功能本来就以认证通过为前置，提前到进门处封锁并不会多挡住任何真实业务操作，代价却是新用户刚进门就撞墙、且无法自助补救。
2. **登录后的落地页**由 WS-302 D-04 决定：认证未完成 → 用户中心；企业认证已通过 → 总览页。本模块只提供状态位。
3. **业务模块的拦截口径唯一**：以本模块输出的「双认证通过」信号为准，业务模块不得自行读取认证子状态或凭据状态做拦截。
4. 未通过认证的用户访问业务路由时，重定向到用户中心并以 Toast 提示 `Complete verification to access this feature. / 完成实名认证后即可使用该功能。`

### 7.2 M2 · 个人认证信息填写（P-K01 步骤 1）

#### 7.2.1 表单结构与字段顺序（F-K04，强制）

步骤 1 只有一个区块「个人认证信息 / Personal verification」，字段自上而下**顺序固定**，不允许调整、不允许分栏打乱视觉顺序：

| 序 | 字段 | 控件 |
| --- | --- | --- |
| 1 | 证件类型 | 单选（身份证 / 护照） |
| 2 | 姓名 | 文本输入 |
| 3 | 英文姓名 | 文本输入 |
| 4 | 国籍 | 下拉选择（标准国家 / 地区清单，可搜索） |
| 5 | **证件号码** | 文本输入 |
| 6 | 证件影像 | 上传控件（数量随证件类型变化） |

> **证件号码的位置是硬性要求**：必须在「国籍」之后、「证件影像」之前。这一顺序在填写页（P-K01）、只读详情页（P-K03）、管理端审核详情页（P-M31）三处保持一致，用户填写的顺序、复核的顺序与审核员比对的顺序是同一条。

字段的类型、必填、校验、默认值见 8.1；证件号码的校验与归一化见 8.2；影像规则见 8.3。

#### 7.2.2 证件类型的联动

选择证件类型后，联动影响三处：

| 联动项 | 身份证 | 护照 |
| --- | --- | --- |
| 证件号码校验规则 | 18 位规则（8.2.1） | 5–20 位规则（8.2.2） |
| 证件号码输入框 placeholder / 帮助文案 | 见 [`06-双语文案与线框.md`](./06-双语文案与线框.md) 8.7 文案表 | 见 [`06-双语文案与线框.md`](./06-双语文案与线框.md) 8.7 文案表 |
| 影像上传槽位 | 两个槽位：人像面、国徽面（均必传） | 一个槽位：护照人像页（必传） |

**切换证件类型的处理**（C-K03 二次确认）

- 切换会使已填的**证件号码**与已上传的**证件影像**失去意义（校验规则与槽位都变了）。
- 弹出确认弹窗，明确列出将被清空的内容：`Changing the document type will clear the document number and uploaded images. / 切换证件类型将清空已填的证件号码与已上传的证件影像。`
- 用户确认后清空这两项，姓名、英文姓名、国籍**保留**。
- 用户取消则不做任何改变，证件类型回到原值。

#### 7.2.3 国籍字段（F-K08）

| 项 | 规则 |
| --- | --- |
| 数据来源 | 标准国家 / 地区清单（ISO 3166-1），随部署配置下发，不硬编码在前端代码里 |
| 存储值 | ISO 3166-1 alpha-2 代码（如 `CN`、`HK`、`US`、`KY`、`NG`） |
| 展示值 | 按界面语言展示中文名或英文名；下拉项同时展示代码，便于搜索 |
| 搜索 | 支持中文名、英文名、代码三种输入方式的模糊匹配 |
| 自由输入 | **不允许**，也不提供「其他」选项。遇到无国籍、旅行证件、争议地区等清单外情形，引导用户联系客服由运营侧处理（DK-40） |
| 默认值 | 空（不做地理位置推断预填，避免用户不看就过） |
| 与证件类型的关系 | **不做强制联动校验**。选择身份证但国籍非中国大陆时不阻断提交，转为审核要点由人工判断（[`04-管理端审核.md`](./04-管理端审核.md) 8.6.2） |

#### 7.2.4 姓名与英文姓名

| 字段 | 规则 |
| --- | --- |
| 姓名 | 证件上的姓名原文（中文或其他本国文字）。1–64 字符；允许中文、字母、空格、连字符 `-`、撇号 `'`、点 `.`；不允许数字与其他符号；前后空格自动去除 |
| 英文姓名 | 拉丁字母表达的姓名，应与护照机读区或证件英文栏一致。1–64 字符；只允许 `A–Z a–z`、空格、连字符 `-`、撇号 `'`、点 `.`；前后空格自动去除；不做大小写强制转换 |

- 两项**均必填**。持护照的用户若证件上只有拉丁字母姓名，两栏可填相同内容，系统不阻断。
- 英文姓名的输入提示文案说明「请与证件上的英文姓名保持一致」，姓名与影像不一致属于人工审核要点（[`04-管理端审核.md`](./04-管理端审核.md) 8.6.2），不做前端强校验。

## 8. 页面与字段定义

### 8.1 个人认证字段总表

> 顺序即表单顺序，不可调整（7.2.1）。

| 序 | 字段 | 标识 | 所在页面 | 类型 | 必填 | 校验规则 | 默认值 | 业务意义 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 证件类型 | `id_type` | P-K01 步骤1 | enum | 是 | 枚举：`id_card`（身份证）/ `passport`（护照）；二选一 | 空（不预选） | 决定号码校验规则与影像必传槽位 |
| 2 | 姓名 | `name` | P-K01 步骤1 | string | 是 | 1–64 字符；中文、字母、空格、`-`、`'`、`.`；去除首尾空格 | 空 | 证件上的姓名原文 |
| 3 | 英文姓名 | `name_en` | P-K01 步骤1 | string | 是 | 1–64 字符；仅 `A–Z a–z`、空格、`-`、`'`、`.`；去除首尾空格；不强制大小写 | 空 | 国际业务与英文界面展示、与护照机读区比对 |
| 4 | 国籍 | `nationality` | P-K01 步骤1 | enum | 是 | 取值来自标准国家 / 地区清单（ISO 3166-1 alpha-2）；不可自由输入 | 空 | 主体所属法域 |
| 5 | **证件号码** | `id_number` | P-K01 步骤1 | string | 是 | 见 8.2（按 `id_type` 分流）；**存储与展示保留原样输入** | 空 | 自然人唯一识别信息；须与影像一致 |
| 6 | 证件影像 | `id_documents` | P-K01 步骤1 | file[] | 是 | 见 8.3；槽位随 `id_type` 变化 | 空 | 人工核验依据 |

**补充口径**

- 六项字段**全部必填**，缺任一项不可进入步骤 2。
- 字段值在提交后不可编辑，只能通过「重新提交」产生新版本（[`03-流程与状态机.md`](./03-流程与状态机.md) 7.5.3）。
- 本期**不采集**出生日期、性别、证件有效期、住址等字段（DK-37）——需求方给出的字段清单即为本期全集，不自行扩展。证件是否过期由审核员看影像判断（审核要点 [`04-管理端审核.md`](./04-管理端审核.md) 8.6.2 第 7 条）。

### 8.2 证件号码的校验与归一化（强制条款）

> 本节是本模块最容易被"顺手优化"的地方，规则以本节为准：**归一化只用于校验判定与唯一性比对；写库与展示一律是用户输入的原始字符串。**

#### 8.2.1 身份证（`id_type = id_card`）

| 项 | 规则 |
| --- | --- |
| 归一化（仅用于判定） | ① 去除首尾空白；② 去除字符串内部的空格（含全角空格）；③ 英文字母转大写 |
| 判定正则 | `^[0-9]{17}[0-9X]$`（对归一化后的字符串） |
| 通俗表述 | 共 18 位：前 17 位必须是数字，第 18 位是数字或字母 `X`；**`x` 与 `X` 等价** |
| 校验时机 | 输入框失焦时校验一次；提交时前端再校验一次；**服务端提交时必校验** |
| 不做的事 | **不校验 GB 11643 末位校验码**、**不校验出生日期段的合法性**、**不校验行政区划码**、不联网核验 |
| 失败提示 | `Enter a valid 18-digit ID card number (the last character may be a digit or X). / 请输入 18 位身份证号码（末位可为数字或 X）。` |

#### 8.2.2 护照（`id_type = passport`）

| 项 | 规则 |
| --- | --- |
| 归一化（仅用于判定） | ① 去除首尾空白；② **剔除分隔符**：空格（含全角空格）、连字符 `-`、下划线 `_`、点 `.`、斜杠 `/`；③ 英文字母转大写 |
| 判定正则 | `^[A-Z0-9]{5,20}$`（对归一化后的字符串） |
| 通俗表述 | 剔除分隔符后为 5–20 位的字母或数字组合，大小写不敏感 |
| **不按签发国做进一步校验** | **明确不做**：不按国籍 / 签发国套用该国护照号的位数或前缀规则，不维护各国护照号规则库 |
| 校验时机 | 同 8.2.1 |
| 失败提示 | `Enter a valid passport number (5–20 letters or digits). / 请输入有效的护照号码（5–20 位字母或数字）。` |

#### 8.2.3 归一化的适用边界（强制）

| 用途 | 用哪个值 |
| --- | --- |
| 前端格式校验 | 归一化值 |
| 服务端格式校验 | 归一化值 |
| 唯一性 / 查重比对（**本期不启用**，DK-42：不对证件号码做跨账号唯一性拦截） | 归一化值（若后续启用，一律用归一化值比对） |
| 管理端精确搜索的匹配 | 归一化值（用户输入的搜索词也做同样归一化后比对） |
| **写入存储** | **原始输入值**（用户键入什么就存什么，含其输入的空格与连字符） |
| **资产端展示（P-K03）** | **原始输入值** |
| **管理端审核详情展示（P-M31）** | **原始输入值，明文完整，见 [`04-管理端审核.md`](./04-管理端审核.md) 13.1** |
| 下载 / 导出 / 日志 | 见 [`04-管理端审核.md`](./04-管理端审核.md) 13.3：材料原件可下载（下载留痕）；证件号码的字段级批量导出本期不提供 |

- 系统**不得**对用户输入做自动改写（不去空格、不转大写、不补零、不加分隔符）后再回填输入框。
- 建议实现同时保存 `id_number`（原样）与 `id_number_normalized`（归一化，仅内部使用），但界面与审核端**只呈现前者**。

#### 8.2.4 与证件影像的一致性（强制条款）

- 证件号码**必须与证件影像上的号码一致**。
- 系统**不做**自动 OCR 比对（本期无 OCR，DK-36），该一致性由**人工审核**保证：它是个人认证审核要点的第一条（[`04-管理端审核.md`](./04-管理端审核.md) 8.6.2），也是驳回原因预置项之一（[`06-双语文案与线框.md`](./06-双语文案与线框.md) 8.7.4）。
- 资产端在证件号码输入框下展示提示：`The number must match the one on your uploaded document. / 号码须与所上传证件影像上的号码一致。`

### 8.3 证件影像与材料上传

#### 8.3.1 证件影像必传规则（F-K05，强制条款）

| 证件类型 | 必传槽位 | 槽位标识 | 说明文案（中 / 英） |
| --- | --- | --- | --- |
| 身份证 `id_card` | **2 个，均必传** | `id_card_front` | 身份证人像面 / ID card – photo side |
| | | `id_card_back` | 身份证国徽面 / ID card – emblem side |
| 护照 `passport` | **1 个，必传** | `passport_bio_page` | 护照人像页 / Passport – biodata page |

- 槽位随证件类型即时切换（7.2.2）；切换类型时已上传影像清空（二次确认）。
- 每个槽位**一张**影像；不支持在同一槽位放多张。
- 缺任一必传槽位时，「下一步」与「提交」均不可用，并在槽位上标红提示。

#### 8.3.2 上传控件通用规则（C-K01，F-K16）

| 项 | 规则 |
| --- | --- |
| 支持格式 | `JPG` / `JPEG` / `PNG` / `PDF`（企业材料常见为 PDF；证件影像建议图片，但不禁止 PDF） |
| 单文件大小 | ≤ 10 MB（可调参数 N-K01） |
| 单份材料文件数 | 证件影像每槽位 1 份；企业材料每项默认 1 份，标注「可多份」的项最多 5 份（N-K02） |
| 上传方式 | 点击选择或拖拽；移动端支持调用相机 / 相册 |
| 进度与失败 | 展示上传进度；失败时展示原因（格式 / 大小 / 网络）并提供「重试」，**已填字段与其他已上传文件不受影响** |
| 预览 | 上传成功后展示缩略图；点击可放大查看（图片）或分页浏览（PDF） |
| 替换 / 删除 | 提交前可替换或删除；提交后不可改（走重新提交） |
| 命名与展示 | 展示原始文件名（截断展示，hover 显示全名）与上传时间 |
| 清晰度提示 | 上传前展示要求：`Make sure all four corners are visible, the text is legible, and there is no glare or obstruction. / 请确保证件四角完整、文字清晰、无反光遮挡。`（提示性，不做机器判定） |
| 存储 | 见 16 章：加密存储、私有访问、按需签发短时效访问凭据；**不可通过可猜测的公开 URL 访问**。管理端审核员可下载原件（[`04-管理端审核.md`](./04-管理端审核.md) 13.3），该访问凭据机制不构成对其下载的限制 |
