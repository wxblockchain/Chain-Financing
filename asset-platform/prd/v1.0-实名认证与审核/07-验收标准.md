## 19. 验收标准

### 19.1 认证入口与准入

| # | 验收项 |
| --- | --- |
| AC-K01 | 登录后认证未完成的账户落到用户中心，认证状态区展示个人与企业两张独立状态卡 |
| AC-K02 | 两条认证的状态、提交时间、结论、版本分别展示，不合并成一条总状态 |
| AC-K03 | 缺邮箱或缺钱包时点击「开始认证」，弹出 WS-302 C-09 补齐弹层，不跳转页面；补齐后原地继续 |
| AC-K04 | 服务端在创建草稿与提交时同样校验凭据完备性，绕过前端仍被拒绝 |
| AC-K05 | 未双通过时访问业务路由被重定向到用户中心并给出 Toast 提示 |
| AC-K06 | 未双通过时，登录、退出、语言切换、账户设置、查看协议、联系客服全部可用 |
| AC-K07 | 双通过后综合状态输出 `verified`，业务功能放行，下次登录落到总览页 |

### 19.2 个人认证字段与校验

| # | 验收项 |
| --- | --- |
| AC-K08 | 步骤 1 的字段顺序为：证件类型 → 姓名 → 英文姓名 → 国籍 → **证件号码** → 证件影像 |
| AC-K09 | **证件号码位于国籍之后、证件影像之前**；填写页、只读详情页、管理端审核详情页三处顺序一致 |
| AC-K10 | 证件号码为用户手工输入，系统不做 OCR 自动带出、不做只读回填 |
| AC-K11 | 身份证：输入 18 位、前 17 位数字、末位数字或 `X` 时校验通过；末位小写 `x` 同样通过 |
| AC-K12 | 身份证：17 位、19 位、末位为 `X` 以外的字母、含字母的前 17 位，均校验不通过并给出提示 |
| AC-K13 | 身份证：**不校验末位校验码**——末位随意填数字（不满足 GB 11643 校验位）仍可提交 |
| AC-K14 | 护照：输入含连字符、空格的号码，剔除分隔符后为 5–20 位字母或数字时校验通过 |
| AC-K15 | 护照：剔除分隔符后不足 5 位或超过 20 位、或含 `#`、`@` 等字符时校验不通过 |
| AC-K16 | 护照：**不按签发国做进一步校验**——任一国籍下，只要满足 5–20 位字母数字即通过 |
| AC-K17 | **归一化只用于判定**：输入 `A1234 5678-9`，提交后数据库存储值与资产端展示值均为 `A1234 5678-9`（原样） |
| AC-K18 | **管理端审核详情展示的证件号码与用户输入完全一致**，含用户输入的空格与连字符 |
| AC-K19 | 输入框不会在失焦后自动去空格、自动转大写并回填 |
| AC-K20 | 国籍来自标准清单，可按中文名、英文名、代码搜索，不能自由输入 |
| AC-K21 | 姓名与英文姓名均为必填；英文姓名只接受拉丁字母与 `空格 - ' .` |
| AC-K22 | 选择身份证但国籍非中国大陆时**不被阻断**，可正常提交 |

### 19.3 证件影像

| # | 验收项 |
| --- | --- |
| AC-K23 | 证件类型为身份证时，展示两个必传槽位：人像面、国徽面 |
| AC-K24 | 证件类型为护照时，只展示一个必传槽位：护照人像页 |
| AC-K25 | 身份证只传一面时不可进入下一步，缺失槽位标红 |
| AC-K26 | 切换证件类型弹出二次确认，明确告知将清空证件号码与影像；确认后两项被清空，姓名 / 英文姓名 / 国籍保留 |
| AC-K27 | 切换证件类型时点「取消」，证件类型回到原值，已填内容不变 |
| AC-K28 | 超过 10 MB 或非支持格式的文件在上传前被拦截并给出具体原因 |
| AC-K29 | 上传失败后可重试，已填字段与其他已上传文件不丢失 |

| # | 验收项 |
| --- | --- |
| AC-K30 | 未选择企业注册地时，模板段不渲染并展示引导文案 |

| AC-K38 | 境外注册号格式不符合建议规则时**提示但不阻断**提交 |

| AC-K41 | 模板段未填写任何内容时切换注册地不弹确认 |
| AC-K42 | 步骤 2 的「被授权人」为只读，自动引用步骤 1 的姓名与证件号码，不可在步骤 2 修改 |
| AC-K43 | 模板配置加载失败时禁止提交，并给出可重试的错误态 |

### 19.5 企业唯一标识

| # | 验收项 |
| --- | --- |
| AC-K44 | 中国大陆企业的唯一键为 `CN:{归一化统一社会信用代码}` |
| AC-K45 | 香港企业的唯一键为 `HK:{归一化 CR 编号}`，BR 号码不参与 |
| AC-K46 | 美国企业生成两个唯一键：`US-{州代码}:{归一化州注册号}` 与 `US-EIN:{归一化 EIN}`，任一命中即判重 |
| AC-K47 | 尼日利亚企业的唯一键剥离 `RC` 前缀：输入 `RC-1234567` 与 `rc1234567` 生成同一个唯一键 |
| AC-K48 | 通用模板的唯一键为 `{注册地代码}:{归一化注册号}` |
| AC-K49 | 归一化包含：全角转半角、去首尾空白、剔除所有非字母数字字符、转大写；`91310000MA1K3XYZ8H` 与 `9131 0000-ma1k3xyz8h` 生成同一唯一键 |
| AC-K50 | 企业注册号的**存储与展示保留原样输入**，不因归一化被改写 |
| AC-K51 | 提交时唯一键与他人已占用的键冲突，提交被拦截，不创建申请，草稿保留，提示文案不透露对方任何信息 |
| AC-K52 | 提交时唯一键与本账号已有申请冲突，提示「你已提交过该企业」并引导查看状态 |
| AC-K53 | 唯一键占用规则：`under_review` 与 `approved` 占用；`draft` 与 `rejected` 不占用 |
| AC-K54 | 企业审核员点击「通过」时执行二次查重，命中已通过的相同唯一键时拒绝通过并提示审核员 |
| AC-K55 | 企业实体在企业认证通过时创建 / 关联，唯一键固化后不随企业改名而变化 |

| --- | --- |

| AC-K57 | 保存草稿不做必填与格式校验，半成品可保存 |

| AC-K59 | 会话失效后重新登录，草稿内容不丢失 |
| AC-K60 | 提交前弹确认弹窗，明确告知提交后不可修改 |
| AC-K61 | 一次提交同时创建个人与企业两份申请，共享批次号与版本号，二者状态均为审核中 |
| AC-K62 | 提交后草稿冻结，认证内容不可编辑 |
| AC-K63 | 重复点击提交不产生第二份申请（幂等） |

| AC-K64a | 限频计数为**个人与企业合并按提交动作计一次**，不是分别计数 |
| AC-K64b | 被校验或唯一键冲突拦下的失败尝试**不计入**限频次数 |

### 19.9 级联规则

| # | 验收项 |
| --- | --- |
| AC-K91 | 个人认证被驳回时，同批次企业认证自动置为已驳回，标记为级联，并从企业待审队列移除 |
| AC-K92 | 级联驳回的原因自动写入「个人认证未通过」（R-E11），审核员不能手动选择该原因项 |
| AC-K93 | 个人认证被驳回时，若企业认证此前已通过，企业对外状态被覆盖为已驳回（级联）；企业审核员原「通过」结论仍保留在审核记录中 |
| AC-K94 | 个人认证已驳回时，企业审核详情页展示醒目提示条，且「通过」按钮禁用；绕过前端调用接口同样被服务端拒绝 |
| AC-K95 | 企业列表可按「级联」筛选，级联记录带标签 |
| AC-K96 | 资产端展示的级联驳回原因为「因个人认证未通过，企业认证一并驳回」，并引导先修正个人材料 |
| AC-K97 | 不存在「个人已驳回且企业为已通过」的最终状态组合 |
