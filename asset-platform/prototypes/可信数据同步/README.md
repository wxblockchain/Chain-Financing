## 1. 本轮口径：存量对齐，不是从零重做

本轮的输入是外部团队先行交付的一版单文件原型。它自建了一套 shell、样式与运行时，与仓库既有五份原型不同源，因此**本轮不保留它的实现，只保留它已经对齐 PRD 的业务口径与页面快捷键**，把页面按仓库既有原型基线重做一遍：

| 对齐项 | 既有基线 | 本原型的落法 |
| --- | --- | --- |
| 导航与路由 | `_shared/registry.js` 登记页面 ID、`CF.NAV` 出侧栏、`CF.MODULES` + `CF.ENTRY` 出跨文件跳转 | 五个页面全部先登记后实现；管理端新增「数据同步」一级分组，与「应收账款」「用户管理」并列 |
| 页面骨架 | `docs/design-system/harbour-credit-page-prototype-reference.md` 4.1 管理端 app shell + 第 5 节列表 / 双栏详情 archetype | 三张列表页走列表母版，两张详情页走双栏详情母版；未新增整页骨架 |
| 组件 | `base.css` 的 `.filters` / `.tbl` / `.pill` / `.note` / `.modal` / `.drawer` / `.tl` / `.skel` / `.pager` / `.statebar` | 全部直接套用，未复制也未重写任何公共组件 |
| 色板字号间距 | `tokens.css` 的 71 个 token | 模块 `<style>` 内无 `:root`、无字面色值、无平行 token；只写本模块的列宽、栅格与局部组合 |
| 组件命名与交互习惯 | `data-act` 事件委托、`CF.define()` / `CF.boot()`、`pageHead()` + `原型 · 状态` 条、`demobar` 演示数据条 | 同一套；模块只提供 `content` / `modals` / `drawers` / `onAct` / `hash` |
| 交付形态 | 仓库源是多文件（模块 HTML + `../_shared/`），评审附件由 `financial-service-platform/prototypes/_shared/export.py` 机械内联生成 | 同上；不手改内联快照 |

**原型里不带 PRD**：`CF.define({ topbarPrd:false })` 且不提供 `prd` 表，顶栏没有 PRD 按钮、没有 PRD 抽屉、页面内没有 PRD 摘录或说明性长文。页面就是产品界面本身。

**没有评审脚手架**：没有左侧演示导航、没有右下角演示控制台、没有把页面摆进中间画布的页面选择器。五个页面都由真实导航或行内下钻到达，另保留 `Alt+1～5` 页面快捷键。

## 2. Stage 2 设计方向与继承关系

**端/角色: 资产管理人员（`data_sync.view` / `data_sync.push`）+ 运营管理员（`asset_inventory.view`） · 模块: 可信数据同步 · 功能点: 14 个（F-DS-01～12、15、16） · 页面: P-M-DS-01～03、P-O-DS-01～02，组件 C-M-DS-01～03 · 状态: S-DS-1 / S-DS-2 + 未推送 + 9 类必达界面状态 · 视觉口径取自: `asset-platform/prototypes/_shared/tokens.css`、`base.css`、`shell.js` 与 `asset-platform/prototypes/应收账款录入与确权/v1.0-应收账款录入与确权-原型.html`。**

| 页面 | 继承端别 / shell | archetype | 本页增量 |
| --- | --- | --- | --- |
| P-M-DS-01 已确权资产推送 | admin / app | 管理端列表母版 | 分币种汇总、批量勾选条（已选 N / 清空 / 全选筛选结果 / 推送）、已推送行禁选、失败行内原因与重推 |
| P-M-DS-02 推送记录 | admin / app | 管理端列表母版 | 批次维度的成功 / 失败计数与来源列 |
| P-M-DS-03 推送批次详情 | admin / app | 管理端记录母版 | 批次摘要四卡 + 逐条回执表 + 本批失败一键重推 |
| P-O-DS-01 资产清单 | ops / app | 管理端列表母版 | 只读；无同步状态筛选项；恒定「已推送」标签与其说明 |
| P-O-DS-02 资产详情 | ops / app | 管理端双栏详情 + timeline | 左列资产 / 贸易 / 确权快照，右列资产方 + 钱包脱敏 + 同步链路时间线；无任何写操作 |

复用方案：

- shell / navigation：`_shared/shell.js` + `registry.js`。管理端侧栏在「应收账款」与「用户管理」之间插入「数据同步」分组（二级：已确权资产推送 / 推送记录）；运营端画布的侧栏只有「资产清单」。
- token / typography：只引用 `_shared/tokens.css`。
- components：复用 `base.css` 的筛选区、表格与 sticky 操作列、Pill、Note、Stat、Modal、Drawer、Toast、Timeline、骨架屏、分页、状态切换条。
- runtime：复用语言切换、路由与 URL 同步、面包屑、顶栏工具区、账号菜单、Toast 与弹层宿主；模块脚本只处理本业务状态。
- 既有页面：协议管理、应收账款、实名认证、消息通知、账户与登录全部保留，通过同一 registry 双向跨文件跳转。
- 公共层增量（本次改动）：
  - `_shared/registry.js` 新增 `P-M-DS-01`～`03`、`P-O-DS-01`～`02` 五个页面登记、`CF.NAV.admin` 的「数据同步」分组、`CF.NAV.ops`、`CF.MODULES.datasync` 与对应 `CF.OWNER` / `CF.ENTRY`；
  - `_shared/shell.js` 让侧栏分组标签与品牌副标题识别第三种画布端别 `ops`，并补三条导航文案；`admin` / `asset` 的既有行为逐字未变；
  - `tokens.css`、`base.css` **未改动**。

## 3. 运行方式

### 仓库原生版

保留整个 `asset-platform/prototypes/` 目录结构，双击本目录 HTML。它以普通 `<link>` / `<script src>` 引用 `../_shared/`，不使用 CDN、远程字体、远程图片、ES module、`fetch` 或任何网络请求。

### Issue 附件版

由仓库原生版机械内联 `_shared/tokens.css`、`base.css`、`registry.js`、`shell.js` 生成单文件快照：

```bash
python3 financial-service-platform/prototypes/_shared/export.py \
  --source asset-platform/prototypes/可信数据同步/v1.0-可信数据同步-原型.html \
  --output ../deliverables/chain-financing-trusted-data-sync-prototype.html
```

生成件不放回仓库；公共源更新后重新执行导出即可。附件里指向其他模块 HTML 的跨文件链接会提示「仅包含当前模块」，完整跨模块操作请打开仓库版。

### 导航

默认落在 P-M-DS-01。左侧「数据同步」下切换两页，批次详情从推送记录行下钻、资产详情从资产清单行下钻；演示数据条上的端切换按钮在资产管理端与运营端之间往返。「原型 · 状态」条用于直接查看每页的必达状态。

| 快捷键 | 端 | 页面 |
| --- | --- | --- |
| Alt+1 | 资产管理端 | 已确权资产推送 P-M-DS-01 |
| Alt+2 | 资产管理端 | 推送记录 P-M-DS-02 |
| Alt+3 | 资产管理端 | 推送批次详情 P-M-DS-03（取最近批次） |
| Alt+4 | 运营端 | 资产清单 P-O-DS-01 |
| Alt+5 | 运营端 | 资产详情 P-O-DS-02（取清单首条） |

输入控件内不截获快捷键；弹层与抽屉按 Esc 关闭，提交进行中的确认弹层锁定不可 Esc。

## 5. 关键交互怎么验

1. **一次完整推送**：默认视图（同步状态 = 未推送）→ 勾选若干条 → 「推送」→ 确认弹层给出待推条数、分币种金额、钱包提示条数与被剔除条目 → 确认后按钮进入 loading → 结果抽屉逐条给出「新入库 / 幂等命中 / 失败」→ 「查看批次」进 P-M-DS-03。
2. **幂等红线**：把演示数据条的「下次回执」设为「回执未知（E-DS-06）」，推一条未推送资产 → 管理端落「推送失败 · E-DS-06」，但运营端其实已入库 → 在失败行「重推」→ 结果为「幂等命中」，运营端清单条数不变，该资产详情的时间线追加一条「重复推送已忽略」。
3. **推送前校验**：全选后确认弹层会剔除三类条目并各自给出原因——资产状态已变化（V-DS-01）、合同号缺失（V-DS-02）、资产方主体不可用（V-DS-03）；钱包地址缺失或格式异常只给黄色提示、不阻断（V-DS-05）。
4. **500 上限与跨页勾选**：「载入 495 条批量演示资产」→「全选筛选结果」→ 已选 504 条，推送按钮禁用并提示分批处理；翻页后已选数不丢失，顶部常驻「已选 N 条」与清空。
5. **金额口径**：页面任何位置没有跨币种总额；汇总按币种给「合计 + 笔数」；未选定单一币种时「按金额排序」禁用并给出 hover 说明。
6. **权限**：演示数据条把权限切到「仅 data_sync.view」→ 页面出现说明条，推送与重推入口置灰，点击给出「data_sync.push is not granted」的拒绝反馈；`原型 · 状态` 的「无权限」态演示连 `data_sync.view` 都没有的样子。
7. **运营端只读**：切到运营端后，侧栏只有「资产清单」，页面头是「只读」标记，没有任何重推、失败筛选、失败计数与同步状态筛选器；失败与未推送的资产不出现在清单里。
8. **深链**：批次详情与资产详情的地址分别是 `#/admin/data-sync/batches/{批次号}` 与 `#/ops/asset-inventory/{来源资产 ID}`，刷新后仍落在同一页。

## 7. 视觉口径

量取自 `asset-platform/prototypes/_shared/tokens.css` 与 `base.css`，并对照 `../应收账款录入与确权/v1.0-应收账款录入与确权-原型.html` 的管理端组合：

主色 `--accent` · 应用底色 `--bg` · 侧栏 238px 白底、导航项 9px 圆角 · 内容区 22/26px 内边距 · 卡片 `--radius` 12px、`--shadow` · 控件高 `--ctrl-h` 36px / `--ctrl-h-sm` 28px · 表头 10.5px 大写字距 `.06em`、行高约 48px · 结构化短值用 `--mono` · Pill 走 `.pill.green` / `.red` / `.gray` 并始终带文本，不以颜色为唯一提示。

模块自有样式只包含：四张表的列宽与换行、分币种汇总栅格、勾选条、结果行、双栏详情栅格与钱包芯片。没有 `:root`、没有字面色值、没有对 `base.css` 已有类的全局覆盖（对 `.c-time` / `.cell-note` 的换行处理限定在本模块四张表内，与母版对 `.ar-table` 的处理同一手法）。

## 10. 假设、差异与限制

1. **运营端画布挂在资产平台 registry**：本模块跨两个平台，而仓库约定「两平台不同时加载对方的登记表」。为了让「推送 → 幂等 → 清单」这条唯一值得评审的跨端链路在同一份原型里连得上，五个页面统一登记在 `asset-platform/prototypes/_shared/registry.js`，运营端页面取第三种画布端别 `ops`。**已知差异**：金融服务平台自己那几份原型（总览 / 协议管理 / 代币合约 / 消息通知）的侧栏因此看不到「资产清单」，本模块的运营端侧栏也只有「资产清单」一项。真正接入运营端控制台时，应把 `P-O-DS-01` / `P-O-DS-02` 补登进 `financial-service-platform/prototypes/_shared/registry.js` 并决定由哪个平台的文件实现——这个决定需要产品侧拍板，不适合由原型单方面定。
2. 运营端画布没有消息中心与账户设置入口：这两页归金融服务平台的登记表，本文件不重复实现，账号菜单里的「退出登录」给出归属说明而不是死链。
3. 演示数据在内存中，刷新即回到初始样例；演示数据条的「重置演示数据」也可手动恢复。
4. 前端演示不证明服务端鉴权、数据层唯一约束、并发安全、审计留痕与性能指标——这些是 AC-DS-13 / 27～31 / 50～53 的真正验收现场，需要联调。
5. 时间统一按账户时区渲染并带时区标注；到期日按 PRD 与 WS-305 口径标注 UTC+8。
6. 移动端不在范围内（PRD 12 章：本期不做移动端适配）。
