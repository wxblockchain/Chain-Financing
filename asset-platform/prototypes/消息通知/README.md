## 1. 沿用了什么、动了什么

**沿用（一行没抄，全部通过 `../_shared/` 引用）**

| 层 | 取用方式 |
| --- | --- |
| token | `_shared/tokens.css`，本模块 `<style>` 里没有任何 `:root`、字面色值或新 token |
| 公共组件 | `_shared/base.css` 的壳层、卡片、按钮、Pill、Tag、Note、筛选栏、分页器、骨架屏、Modal、Toast、PRD 面板 |

| 跨模块跳转 | 详情页的跳转按钮直接落到另外两份原型的对应页面（见第 5 节），与侧栏跨文件跳转同一套规则 |

**对 `_shared/` 的改动（4 处，都是因为 PRD 5.1 把它们定义为「全局组件 · 双端复用」，写在模块里就等于复制公共组件）**

| 文件 | 改了什么 | 为什么非改不可 |
| --- | --- | --- |
| `registry.js` | 登记 4 个页面、`CF.MODULES.notify`、`CF.OWNER` / `CF.ENTRY`，新增 `CF.NOTIFY_PAGE`（各端消息中心落地页） | 页面 ID 必须先登记后实现；`NOTIFY_PAGE` 让铃铛「查看全部」与账号下拉条目在两个端各自找到落点 |
| `shell.js` | 新增铃铛 **C-20**、快捷面板 **C-21**、消息列表项 **C-22** 渲染器 `CF.msgItem`、相对时间 `CF.fmtRel`，账号下拉新增「消息中心」条目 | C-20 / C-21 挂在**顶栏**上、双端所有页面共用，属于壳层能力；C-22 同时被面板与列表用，放模块里就会出现两套列表项 |
| `base.css` | 新增 `.bell` / `.bdg` / `.dd-list.panel` / `.msgs` / `.msg*` / `.sr-only`，全部是新类名，未覆盖任何既有类，未出现字面色值 | 同上；样式必须和组件实现待在同一层 |

**没有动的**：token 一个值没改；既有组件一条规则没覆盖；侧栏菜单没加项（PRD 5.1「不新增左侧菜单项」，入口收敛在铃铛与账号下拉）；另外两个模块的页面一处没动——它们只是因为公共层升级而多了账号下拉里的「消息中心」入口，点过去就是本模块。

**「无权限」在本模块的落地方式**：PRD 5.4 明确消息模块**不设认证状态门槛**，因此列表页没有「无权限」形态；越权只发生在单条消息上，且一律按 **404 语义**呈现（AC-N40 / AC-N70）——在两个详情页的状态切换器里可直接切到。这不是漏做，是 PRD 的口径。

**本期不做（PRD 已明确，原型据此不画）**：手动标为未读（D-N08）、消息删除与归档（D-N09）、通知偏好中心与按分类退订（2.5.1）、广播消息（2.5.2）、完整进度条 / 步骤条（7.8.5）、同一业务的消息聚合视图（7.8.5）、进度类单独角标或单独入口（7.8.5）、管理端的业务类型 / 分类配置界面（AC-N63）、任何邮件与站外渠道形态（D-N36）。

**演示数据的事件来源**：严格按仓库 `cly-V1.0.0` 现状取——WS-302 精简后只剩 E-03 钱包已绑定 /
E-05 密码变更 / E-10 邮箱已更新三条站内信（`8e18350`、`46e1d59`），WS-303 提供认证与合规、
业务办理进度两类。被明确判定「不产出站内信」的事件（自动建号、凭据补齐、登录成功与失败、
语言时区偏好变更、其他设备被退出、管理端各类账号事件）在演示数据里一条都没有。
因此资产端的分类筛选里**没有**「账户」——该分类已定义但当前无接入方，正好也是 AC-N84 的表现。
管理端那条个人消息（`admin_account`）没有对应的在跑事件，只用来验证「只投递给一个管理员」
这条仍然成立的契约（PRD D-N34），消息正文里写明了这一点。

**交付标签：full prototype（本模块范围内）**。PRD 5.1 登记的 4 个页面与 4 个组件全是真页面真组件，没有占位；模块外的页面按既有系统保留，不在本文件内重复实现。

## 3. 功能点怎么验

19 个功能点里，M1～M7 的 15 个属于展示层，逐条对应到界面上点得动的东西；M8 / M9 的 4 个是服务端契约与权限，原型只能呈现其**前端可见的后果**，如实标注。

| 编号 | 功能点 | 在原型里怎么验 |
| --- | --- | --- |
| F-N01 | 顶部通知铃铛 | 任意页面顶栏右侧，固定在语言切换器**左侧**、账号下拉之前；两个端一致 |
| F-N02 | 未读角标计数 | 无未读时不出角标也不显示 `0`；点「模拟 132 条未读」看 `99+`（1 位数圆形、2 位以上胶囊，数字不裁切）；`aria-label` 同步播报 |
| F-N03 | 铃铛快捷面板 | 点铃铛展开，**每次展开都重新拉一次**（先 3 行骨架屏）；最近 10 条、含已读；点面板外区域或 Esc 收起，焦点回到铃铛；面板内**没有**「全部已读」 |
| F-N04 | 账号下拉「消息中心」 | 右上角账号下拉里「账户设置」**之上**的那一条，直达消息中心、不经面板 |
| F-N05 | 角标刷新与多标签页一致 | 原型内可验：读一条 / 行内标记 / 全部已读后角标立即变。轮询、切回前台重拉、跨标签页广播是运行时行为，**静态原型不演示**，见第 7 节 |
| F-N06 | 分类筛选 | 下拉里只有「该接收者名下已有消息的分类」——资产端 4 个（安全 / 认证与合规 / 业务办理进度 / 其他）、管理端 3 个；`finance` / `announcement` / `system` / `ops_alert` 已在契约里定义但本期无消息，**不会出现在筛选器里**（AC-N84）；未登记分类回落「其他」，消息照常展示 |
| F-N07 | 已读 / 未读筛选 | 三档单选，与分类**叠加**，条件写进 URL，刷新保持 |
| F-N08 | 分页与排序 | 资产端「加载更多」，管理端分页器（20 / 50 / 100）；一律按创建时间倒序，**已读不参与排序** |
| F-N09 | 空态 / 加载态 / 失败重试 | 状态切换器直接切；首次空态与筛选空态文案和操作**不同**，后者有「清除筛选」；打开「接口故障」再点加载更多，底部出错误条且**已加载内容不清空** |
| F-N10 | 单条已读 | 两条路径并存：打开详情自动已读（**渲染成功之后**才标记，加载失败不标记）；列表行悬浮出现「标为已读」，就地标记不进详情 |
| F-N11 | 全部已读 | 作用于**当前筛选命中的全部消息**；确认弹窗写明条数与当前筛选，并注明不可撤销；开「接口故障」再执行，Toast 报错且角标与列表**一点没变** |
| F-N12 | 消息详情 | 整页独立路由，`#/messages/{id}` / `#/admin/messages/{id}` 可直接深链、可刷新 |
| F-N13 | 返回列表的状态同步 | 在「只看未读」下读完一条返回：该行**仍在原位**并变成已读样式；筛选、已加载页数与滚动位置全部保留 |
| F-N14 | 跳转契约与降级 | 见第 4、5 节，各种落地表现各有一条演示消息；**没有跳转按钮的三种情形（无跳转 / 映射缺失 / 已过期）界面表现完全一致：只有「返回列表」** |
| F-N21 | 静态页面目标 | 带 `page_target` 的消息**不预检**，按钮直接可用，落到对应页面 |
| F-N15 | 业务办理进度形态 | 列表里的进度型列表项：业务名称作标题、当前节点、四态标签、更新时间；详情里额外有进度区块（业务编号可复制、第 i/n 步） |
| F-N16 | 同一业务多次更新 | 实名认证 `IDV-20260905-014` 在列表里是**两条独立消息**，各自独立已读，不合并 |
| F-N17 | 管理端共享池 + 个人已读 | 切到管理端：共享池消息与个人消息**混排不分区**；「你的管理端账号安全提醒」是个人消息（`admin_account`） |
| F-N22 | 管理端个人消息 | 用另一端的消息 ID 打开详情（例如在资产端打开 `#/messages/m-m01`），落到 404 语义页，与「不存在」不可区分 |
| F-N18 / F-N19 / F-N20 | 归属校验 / 数据契约 / 业务类型登记表 | 服务端与契约层能力，原型只呈现前端后果：越权 404、未登记分类回落、未登记 `biz_type` 不渲染按钮。**原型不能证明服务端实现**，验收以 `03-验收标准.md` 16.5 / 16.7 为准 |

## 4. 四类失效 + 两种「没有按钮」，分别长什么样

PRD 7.7 与 7.6.3 / 7.6.4 一共有六种落地表现，最容易被做成同一句「该消息已失效」。原型里每种都有一条对应的演示消息：

| 表现 | 演示消息 | 详情页表现 |
| --- | --- | --- |
| 已过期 `expired` | 资产端「请复核你的经营范围」 | 列表整体降权 + 「已过期」标签、**不计入角标**；详情有说明条，**不渲染**跳转按钮 |
| 目标资源已删除 `resource_deleted` | 资产端「实名认证 · 未通过」 | 说明条「相关记录已不存在。」，按钮**禁用**并带 tooltip |
| 状态已流转 `state_changed` | 资产端「实名认证 · 待你处理」 | 说明条带业务方补充的当前状态，按钮**禁用** |
| 无权限 `no_permission` | 资产端「实名认证 · 已关闭」 | 说明条「你当前无权访问该记录。」，按钮**禁用** |
| 映射缺失（客户端版本旧） | 资产端「认证复核已启动」、管理端「批量导入完成」 | **不渲染**按钮，**也不给任何说明文案**，只留「返回列表」；消息内容照常可读，不跳 404、不跳首页；仍按 AC-N33 上报一次「未知业务类型」 |
| 无跳转（合法形态） | 资产端「你已加入早期体验组」 | 不渲染按钮，**也不出现任何说明文案**（AC-N76） |
| 预检接口自己失败 | 管理端「认证审核单重开」 | 按钮**保持可用**、放行跳转（超时口径 N-N05 = 3 秒）；界面上**不作解释**，要验证就打开这条看按钮是不是还能点 |

四种失效下，标题、正文、时间都完整展示——失效只影响「能不能跳过去」。

> **用户 2026-09-08 裁定**：**没有跳转按钮的消息，详情页一律只留「返回列表」，不给任何说明文案。**
> 这覆盖了 PRD 7.6.3「映射缺失展示一句次要说明」的要求（AC-N32 的说明文案部分作废，
> 上报日志 AC-N33 不受影响），PRD 需要同步这一条。
> 同一条口径也用在另外两处原本挂着解释文案的地方：文案模板缺失的降级消息（正文留空、不解释原因）、
> 预检超时放行（按钮照常可用、不解释）。理由一致——那几句都是给前端看的规格说明，
> 不该出现在用户界面上；它们的口径留在 PRD 面板与本文件里。

## 5. 跳转按钮真的会跳

跳转目标由**页面编号 / 业务类型登记表**解析，消息实体里不存 URL（AC-N31）。原型里三种形态各自落地：

| 形态 | 演示消息 | 点下去会发生什么 |
| --- | --- | --- |
| 静态页面目标 `page_target` | 「登录密码已修改」（WS-302 E-05）→ `P-A11` | 真的打开 `../账户与登录/v1.0-账户与登录-原型.html#/p-a11` |
| 静态页面目标（管理端） | 「你的管理端账号安全提醒」→ `P-M05` | 真的打开账户与登录原型的管理端账户设置 |
| 业务资源目标 `biz_ref` | 「实名认证 · 材料复核」→ `idv.verification.progress` → `P-A17` | 先预检（按钮进入等待态），可达则跳到用户中心 |
| 业务资源目标（管理端） | 审核待办 → `review.idv_case.assigned` | 目标页由 WS-303 交付、**本仓库尚未落库**，因此点击后如实说明，不造一个假页面 |

## 6. 演示控制条

紫色那条是**原型评审脚手架**，不属于产品界面，与另外两个模块的 `demobar` 同一套：

| 控件 | 作用 |
| --- | --- |
| 端别：资产端 / 管理端 | 切换同一份原型的两个端别视图。菜单、分类集合、分页形态、进度类消息的有无都会跟着变 |
| 模拟收到新消息 | 往列表顶部插一条未读，角标 +1 |
| 模拟重复推送（去重合并） | 命中 `dedupe_key` 时的系统行为：已读消息**恢复为未读**、时间更新、回到列表顶部（AC-N65） |
| 模拟 132 条未读 | 角标上限展示 `99+`（N-N03） |
| 接口故障 | 打开后，面板拉取 / 加载更多 / 全部已读 / 详情加载都会失败，用来看四处失败态 |
| 重置演示数据 | 恢复初始数据与筛选 |

页面标题下方的「原型 · 状态」切换条切的是**该页面的强制状态**（首屏加载 / 空 / 筛选无结果 / 加载失败 / 404）。
