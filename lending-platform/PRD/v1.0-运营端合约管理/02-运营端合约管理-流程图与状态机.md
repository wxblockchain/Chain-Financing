# 运营端合约管理 · 流程图与状态机

2026-09-24｜需求评审稿｜配套本模块当前[主 PRD](01-运营端合约管理-PRD.md#entry)与[消息通知](03-运营端合约管理-消息通知.md)。

<a id="entry"></a>
开发、测试、设计共同参考。业务规则与同序验收见主 PRD，通知事件见消息通知册。本册只表达角色、用户路径和业务状态，不表示页面或组件，承载形式由设计决定（见[统一条款](01-运营端合约管理-PRD.md#design-boundary)）；与正文不一致时以正文为准。

本模块的核心是一条链路：**资产方提交审核 → 运营核对创建信息 → 通过即由平台统一钱包发起质押合约部署 → 部署成功就是审核通过**。审核结论只有通过与退回两种；签名或部署失败不是结论，项目回到待审核由管理人员再次发起。全链路**无任何时限**，不因等待自动通过或自动失败。连线为已确认业务分支：部署异常只保留真实事实与保护，不画工单、升级、改判或强制回滚流程。日期判定与统计统一 UTC，时点按偏好时区显示并标注。项目状态的权威定义归[融资项目状态 `ST-LS-01`](../v1.0-借贷广场-融资需求与代币质押/02-融资需求与代币质押-流程图与状态机.md#st-ls-01)，本册只读消费并标出对应关系，不另造一套。

## FL-CM-01 项目审核与合约部署

规则回查：[项目审核队列](01-运营端合约管理-PRD.md#m1)、[审核详情与创建信息核对](01-运营端合约管理-PRD.md#m2)、[通过并部署合约](01-运营端合约管理-PRD.md#m3)、[退回与唯一结论](01-运营端合约管理-PRD.md#m4)。

```mermaid
flowchart TD
  A0["资产方在面客端创建融资项目并提交审核<br/>项目待审核 · 私有 · 零费用 · 无链上动作"] --> A1["运营端项目审核队列出现一条记录<br/>一个项目一条，默认待审核、提交时间升序"]
  A1 --> A2["运营打开审核详情<br/>创建信息、资产方与参数上下文、审核历史同处可得"]
  A2 --> A3{"锁定的质押率与期限<br/>同当前参数配置是否一致？"}
  A3 -- "不一致" --> A4["并列展示锁定值与当前配置值并标出差异<br/>核对基准仍是创建时锁定的快照<br/>不自动拦截、不改写锁定值、不自动退回、不产生整改待办"]
  A3 -- "一致或当前配置不可读，标待核实" --> A5
  A4 --> A5{"有查询与处置权限<br/>且项目仍待审核、无部署处理中？"}
  A5 -- "否" --> A6["不显示或拒绝处置入口<br/>展示当前事实或无权说明"]
  A5 -- "是" --> A7{"线下判定后的结论"}
  A7 -- "退回" --> B1["填写面客可读原因 10～500 字<br/>全文预览并二次确认"]
  B1 --> B2["项目已退回 · 面客 S-FP-8<br/>不部署、不产生合约地址、不消耗 gas"]
  B2 --> B3["发送项目审核退回站内信<br/>原因全文原样"]
  B2 --> B4["资产方修改创建信息后重新提交<br/>项目编号不变 · 项目期限不重新起算"]
  B4 --> A1
  B2 -- "资产方主动关闭项目" --> B5["项目已关闭 · 离开待审队列<br/>运营端无关闭与恢复入口，历史仍可只读"]
  A7 -- "通过" --> C1["确认知悉：提交后由平台统一钱包发起部署<br/>部署成功即审核通过 · 项目与合约一一对应 · 不可撤销"]
  C1 -- "在本次办理内一次提交" --> C2{"提交生效时权限与状态仍满足？"}
  C2 -- "否" --> A6
  C2 -- "是" --> C3["审核轴与部署执行状态转为部署处理中<br/>尚未形成结论 · 面客仍为待审核<br/>处置入口不可用 · 并发提交只有一笔成立"]
  C3 --> C4["平台统一钱包发起本项目质押合约部署<br/>gas 由管理端承担 · 运营人员不签名不付费"]
  C4 --> C5{"真实链上结果"}
  C5 -- "明确失败或长期无结果" --> C6["见 FL-CM-02，不形成结论、不通知资产方"]
  C5 -- "部署成功 = 审核通过" --> D1["回写质押合约地址与部署链上事实<br/>记录审核人与结论时间 · 结论终态不可撤销"]
  D1 --> D2["面客项目转为可用 S-FP-1 · 空池<br/>资产方可发起代币质押，需本人签名、gas 自担"]
  D1 --> D3["发送项目审核通过站内信<br/>含合约地址，说明现在可以发起质押"]
  D1 --> D4["进入质押合约台账<br/>项目与合约一一对应、只读"]
  A1 -- "无人裁定" --> W["无限期停留在待审核<br/>无截止、无倒计时、无自动通过或自动失败"]
  W --> A2
```

三条判断相互独立：**权限与状态**决定能不能裁定，**线下判定**决定通过还是退回，**真实链上结果**决定通过是否成立。审核核对的对象始终是资产方提交创建时锁定的快照，审核期间运营调整融资参数配置不改变在审项目的核对结论，也不改变退回后重提的核对基准（沿[运营端融资参数配置 `D-O-FC-03`](../v1.0-运营端融资参数配置/01-运营端融资参数配置-PRD.md#d-o-fc-03)）。通过办理在本次办理内一次提交，没有第二步确认、没有第二位审核人。退回是运营端唯一能让项目回到资产方手上的结论；运营端没有修改创建信息、代提交与关闭项目的入口。项目审核不产生任何质押额——项目通过只是允许发起质押。

## FL-CM-02 部署失败、结果待核实与再次发起

规则回查：[部署失败、结果待核实与再次发起](01-运营端合约管理-PRD.md#m5)、[合约部署执行状态](01-运营端合约管理-PRD.md#d-cm-07)。

```mermaid
flowchart TD
  A["部署处理中 · 已由平台统一钱包发起"] --> B{"真实链上结果"}
  B -- "明确失败：签名失败、部署失败" --> C["部署失败 · 视为审核未完成<br/>审核轴回到待审核 · 面客仍为待审核"]
  B -- "长期无确定结果或事实冲突" --> D["结果待核实<br/>保留已知链上凭证与已发生事实"]
  B -- "明确成功" --> E["部署成功 = 审核通过<br/>见 FL-CM-01"]
  C --> C1["展示失败原因原文、失败时点、已消耗 gas<br/>gas 未知标待核实，不填 0"]
  C1 --> C2{"有处置权限的管理人员再次发起？"}
  C2 -- "是" --> C3["复用同一项目编号与同一条审核记录<br/>形成新的部署尝试 · 回到部署处理中"]
  C3 --> A
  C2 -- "暂不发起" --> C4["项目停留在待审核并计入部署失败待再次发起统计<br/>不自动重试、不自动退回、不自动通过"]
  C4 --> C2
  D --> D1["不推定成功或失败<br/>不重复发起部署 · 不自动改判 · 不自动回滚<br/>处置入口不可用并给出可理解说明"]
  D1 --> D2["真实链上结果回写后按结果继续<br/>成功转 FL-CM-01，失败转部署失败"]
  D2 --> B
  C --> X["不向资产方发送任何消息<br/>面客侧只见项目待审核"]
  D --> X
  C3 --> X
```

失败与待核实都**不是审核结论**：不改变项目期限起算点、不要求资产方重新提交、不产生第二个项目、不产生第二份合约。再次发起次数本期不设上限。本期没有工单、异常待办、自动升级、人工改判或补记、强制回滚、补偿与手工录入合约地址的能力；无法自行处理时联系建设方核实链上与配置，产品内不编造处理时限或工单流程。

    不再部署第二份合约，创建信息全部只读

  end note

审核轴只有这四个业务态加一个离队事实，**没有第三种结论**，也没有驳回终结、作废、冻结、暂缓。部署处理中是过渡态不是结论，此时界面不得展示"已通过"，也不得引导资产方发起质押。项目状态的权威定义与其余转换归[融资项目状态 `ST-LS-01`](../v1.0-借贷广场-融资需求与代币质押/02-融资需求与代币质押-流程图与状态机.md#st-ls-01)；已通过之后的募集中、已锁定、融资中、已结清等转换不由本模块驱动。

## ST-CM-02 合约部署执行状态 `CF-07`

规则回查：[合约部署执行状态](01-运营端合约管理-PRD.md#d-cm-07)、[部署失败与再次发起](01-运营端合约管理-PRD.md#m5)。

```mermaid
stateDiagram-v2
  NONE: 未发起 · 无合约地址 · 不显示占位值
  RUNNING: 部署处理中 · 已发起、尚无确定结果
  SUCCESS: 部署成功 · 回写合约地址与链上凭证
  FAILED: 部署失败 · 视为审核未完成
  UNKNOWN: 结果待核实 · 保留已知凭证与事实
  [*] --> NONE: 项目提交审核
  NONE --> RUNNING: 运营提交通过 · 平台统一钱包发起部署
  RUNNING --> SUCCESS: 链上明确成功
  RUNNING --> FAILED: 签名或部署明确失败
  RUNNING --> UNKNOWN: 长期无确定结果或事实冲突
  FAILED --> RUNNING: 管理人员再次发起 · 复用同一项目与审核记录
  UNKNOWN --> SUCCESS: 真实结果回写为成功
  UNKNOWN --> FAILED: 真实结果回写为失败
  SUCCESS --> [*]
  note right of SUCCESS
    项目与合约一一对应、地址终身稳定只读
    同一项目此后不再发起部署
    无人工录入、修改、解绑或重新部署入口
  end note
  note right of UNKNOWN
    不推定成功或失败、不重复发起
    不自动改判、不自动回滚
    处置入口不可用，无工单、升级或补偿
  end note
```

部署执行状态是**链上执行事实**，与审核轴是两条独立的轴：部署成功同时推动审核轴到已通过，部署失败把审核轴退回待审核，结果待核实则两条轴都不变更结论。部署 gas 由管理端承担，运营人员全程不签名、不付费；平台统一钱包的取值在代码层面维护、随版本发布，本模块与全平台都不提供其维护、配置、切换、余额或充值入口。历次部署尝试与结果全部保留在审核历史与操作记录中，不被覆盖。
