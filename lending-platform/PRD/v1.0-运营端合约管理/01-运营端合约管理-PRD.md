# 运营端合约管理 · PRD

2026-09-24｜运营管理平台 · 运营端｜需求评审稿，真实未决项见第 5 章。本模块为 2026-09-24 批新建。

<a id="entry"></a>
## 1. 目标与阅读入口

资产方在面客端创建融资项目并提交审核后，运营人员在运营管理平台核对创建信息，**核对通过即由平台统一钱包发起本项目质押合约部署；部署成功就是审核通过**，同时产生本项目唯一的质押合约地址。审核结论只有**通过**与**退回**两种：退回须给出面客可读原因，资产方可修改创建信息后重新提交，项目期限不重新起算；签名或部署失败视为审核未完成，项目仍为待审核，由管理人员再次发起，不需要资产方重提、不产生第二个项目。项目审核**不设时效管控**，运营人员**不签名、不代付 gas**，只做业务操作。

本期包含：项目审核队列与统计筛选、创建信息核对与资产方/参数上下文、通过并部署合约、退回与唯一结论、部署失败与结果待核实的再次发起、质押合约台账与项目审核历史、留痕与通知触发、本模块所需的运营端权限项。相邻模块负责：面客创建项目与项目审核的业务判定（融资需求与代币质押）、逐笔代币质押审核（代币质押审核）、代币类型与最高质押率/项目期限的参数配置（运营端融资参数配置，本批新建）、面客站内消息的阅读入口与未读语义（面客消息中心）、运营账号与功能权限矩阵（运营端账户与登录）。本期不包含第 [1.2 节](#1-2-本期不包含) 各项。

有效依据（用户已确认，2026-09-24 批）：项目与合约 1:1，创建项目需审核；审核对象为项目名称、代币类型、自填质押率、自填项目期限、参考结算币种、还款方式，其中还款方式为只读定值、参考结算币种不限制资金方实际选择，审核时属核对带出值；先建池 → 待审核 → 审核通过后才能发起质押；**审核与部署合为一步，部署成功即视为审核通过**；签名或部署失败视为审核未完成，由管理人员再次发起；审核结论只有通过与退回；退回后允许修改重提，项目期限不重新起算，合约部署完成后创建信息不可再改；部署由平台统一钱包发起，**钱包取值在代码层面维护、随版本发布**，平台不提供维护/配置/切换入口；gas 由管理端承担，充值不在本系统范围；**运营人员不签名，只做业务操作**。沿用本批未变更的既有口径：全链路无任何审核时限；异常保留真实事实与保护，不实现异常处置系统；业务日期统一 UTC、具体时点按用户偏好时区展示；详情以按发生时间倒序的操作记录承载本项目全部审核事实。

<a id="d-cm-02"></a>`D-CM-02`【承接边界】：本册承接的是**运营端这一侧的操作与信息**——运营人员看到什么、能做什么、做完之后运营端与面客端各自变成什么。项目审核的业务判定、创建信息字段口径、项目状态与面客结果由[融资需求与代币质押](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)定义，本册只读消费、不重写、不自行裁定，也不在本册复制其字段校验规则。两册口径不一致时以该册为准，并按跨册标注（[跨册标注](#cross-book)）回传，不在本册单方修改。

阅读顺序：第 2 章角色、对象与共同口径 → 第 3 章完整功能 → 第 4 章同序验收 → 第 5 章依赖、限制与待决。

## 2. 角色、对象与共同口径

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

<a id="d-cm-03"></a>
### 2.1 审核对象与角色

`D-CM-03`【审核对象的统一来源】：

| 对象 | 含义与范围 |
| --- | --- |
| 待审核项目 | 资产方已提交审核、尚未得出有效结论的一个融资项目，对应面客[融资项目状态](../v1.0-借贷广场-融资需求与代币质押/02-融资需求与代币质押-流程图与状态机.md#st-ls-01) `S-FP-7`。**审核对象是项目本身，不是代币、不是批次**；一个项目在队列里始终只有一条记录 |
| 本次审核提交 | 资产方的一次提交审核动作。首次提交与每一次退回后的重新提交各算一次，按发生时间形成提交序次；重新提交仍走同一条审核与部署链路，不产生新的项目编号 |
| 审核结论 | 每次审核提交至多一个有效结论：**通过**或**退回**。通过的成立条件是合约部署成功；退回须有面客可读原因。签名或部署失败不是结论，见[部署执行](#d-cm-07) |
| 质押合约 | 部署成功产生的本项目质押合约，与项目**一一对应**、终身稳定。一个项目只部署一份合约，部署成功后不再部署第二份 |
| 项目审核历史 | 本项目全部提交、结论、部署尝试与结果的累积记录，按发生时间倒序；重新提交不覆盖既往退回原因（沿面客[`FP-37`](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-37)） |

| 参与方 | 本模块责任 |
| --- | --- |
| 运营人员 | 按功能权限查看待审核项目、创建信息、参数上下文、审核历史与合约台账；线下判断后在线提交通过或退回。**不签名、不代付 gas、不发起或撤销任何链上动作**，也不修改创建信息；不按运营机构隔离 |
| 资产方 | 在面客端创建项目、提交审核、按退回原因修改并重新提交、主动关闭项目；审核期间不付费、不签名、无链上动作 |
| 借贷平台 | 受理通过结论后由**平台统一钱包**发起本项目质押合约部署并承担 gas；按真实链上结果回写部署状态与合约地址，并派生项目状态 |
| 平台统一钱包 | 部署的唯一发起方。取值在代码层面维护、随版本发布，平台内无维护、配置、切换或审批入口，面客端与运营端都没有；范式同[SPV机构名称](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-31) |

本期两个信息域：项目审核队列（`P-O-CM-01`）、项目审核详情（`P-O-CM-02`，可查看创建信息、参数上下文、审核历史与合约事实）。合约台账是审核详情之外的只读查询视图，归 `P-O-CM-01` 同一入口体系下的独立列表（`P-O-CM-03`）；承载形式由设计决定。

### 2.2 权限与账号准入

<a id="permissions-runtime"></a>`D-CM-10`：按[运营端账户与登录](../v1.0-运营端账户与登录/01-运营端账户与登录-PRD.md)交付的功能权限执行，本模块不新增授权管理；管理员与被配置业务权限的专员均可按权限办理。本模块需要两项权限项，名称、粒度与登记归属见 [5.3 节](#permissions)，本册以业务能力表达，不代 WS-380 分配编号。

| 能力 | 仅有[融资项目审核查询](#pm-cm-01) | 同时有[融资项目审核与合约部署处置](#pm-cm-02) |
| --- | --- | --- |
| 队列、审核详情、创建信息、参数上下文、审核历史、合约台账 | 可查全部授权业务范围，不按机构或本人分配过滤 | 同左 |
| 提交通过并部署、提交退回、部署失败后再次发起 | 不显示处置入口，绕过界面仍拒绝 | 仅当前项目仍待审核且无部署处理中时可执行 |
| 改已生效结论、改创建信息、签名、发起或撤销链上动作、手工录入合约地址 | 不可 | 不可 |
| 运营站内消息 | 另需运营端消息查看（`PM-AL-12`），不由本模块赠予 | 同左；读消息不表示有处置权限 |

只有处置而无查询权限不能进入本流程，联系建设方核对配置。账号待首登改密、锁定、登录失效或当前无权限时，此前已进入的入口提交同样拒绝。已授权但业务已终结的项目保留可读原因；无权入口不展示且不泄露记录存在性。待审核与已退回项目属资产方私有（面客[`F-LS-12`](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-12)），运营端的可见性来自功能权限，不改变其对游客与其他企业的不可见。

### 2.3 时间、日期与金额口径

`D-CM-11`【统一业务日期与展示】：

- **业务日期边界**：近七个自然日统计、按日期筛选等统一 UTC；日期筛选需让操作者识别其 UTC 口径。
- **展示**：具体时点按用户偏好时区显示并标注。切换显示时区、跨周末或夏令时不改变已发生事实、统计归属或事件先后。
- **无审核时效**：项目审核不设截止、不设倒计时、不因时间流逝改变任何审核状态或项目状态；已等待时长只作事实陈述，不构成期限，也不触发催办或超时通知。
- **项目期限起算点不由本模块决定**：自项目创建时间起算，退回重提不重新起算，审核耗时不延长也不缩短项目有效期（面客[`FP-35`](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-35)、[`FP-09`](../00-字段命名与术语对照表.md)）。
- **金额与费用**：项目审核阶段资产方零费用。部署 gas 由管理端承担，实际发生额按真实币种如实展示；未知标"待核实"，不填 0，不编造数币精度。

<a id="states"></a>
### 2.4 状态、项目口径与外部只读事实

<a id="d-cm-04"></a>`D-CM-04`【运营端项目审核轴 `CF-03`】枚举，必有，默认待审核：**待审核 / 部署处理中 / 已通过 / 已退回**。已通过与已退回是结论态，部署处理中是提交通过后等待真实链上结果的过渡态，不是结论。审核轴不因时间流逝自动改变，也没有第三种结论。

审核轴与面客[融资项目状态](../v1.0-借贷广场-融资需求与代币质押/02-融资需求与代币质押-流程图与状态机.md#st-ls-01)的对应关系如下；**项目状态的权威定义归融资需求与代币质押，本册只读消费、不另造一套**：

| 运营端审核轴（`CF-03`） | 面客项目状态 | 触发及允许行为 |
| --- | --- | --- |
| 待审核 | `S-FP-7` 待审核 | 资产方已提交、尚无有效结论；有处置权限可随时裁定，无截止；资产方可主动关闭项目 |
| 部署处理中 | 仍为 `S-FP-7` | 已提交通过并发起部署、尚无确认的链上结果；**不得重复发起、不得改判为退回**，不推定成功或失败 |
| 已通过 | `S-FP-1` 可用（空池） | 合约部署成功，产生[质押合约地址](#cf-08)，项目转入可用并可发起代币质押；结论终态，不可撤销、不可二次裁定 |
| 已退回 | `S-FP-8` 已退回 | 结论为退回且原因齐备；资产方可修改创建信息后重新提交，重新提交回到待审核，本次退回原因保留在历史 |
| 已离开队列 | `S-FP-5` 已关闭 | 资产方在待审核或已退回期间主动关闭项目；本模块无关闭入口，记录仍可按权限只读回看 |

<a id="d-cm-07"></a><a id="cf-07"></a>`D-CM-07`【合约部署执行状态 `CF-07`】枚举，必有，默认未发起：**未发起 / 部署处理中 / 部署成功 / 部署失败 / 结果待核实**。这是链上执行事实，与审核轴是两条独立的轴：

| 部署执行状态 | 业务含义与后续 |
| --- | --- |
| 未发起 | 尚未提交通过；项目待审核或已退回。无合约地址，不显示占位值 |
| 部署处理中 | 已由平台统一钱包发起、尚无确定结果；审核轴同步为部署处理中，处置入口暂不可用 |
| 部署成功 | **即审核通过**：产生本项目质押合约地址，回写部署时点与链上凭证；项目转为可用。同一项目此后不再发起部署 |
| 部署失败 | 签名或部署明确失败，**视为审核未完成**：审核轴退回待审核，展示失败原因原文，由有处置权限的管理人员再次发起；不需要资产方重新提交、不改变项目期限起算点、不产生第二个项目，也不向资产方发送任何消息 |
| 结果待核实 | 长期无确定结果或事实冲突：保留已知链上凭证与已发生事实，标"待核实"；**不推定成功或失败、不重复发起、不自动改判**，按 [`D-CM-16`](#d-cm-16) 处理 |

<a id="d-cm-05"></a>`D-CM-05`【项目与合约 1:1】：一个融资项目对应一份质押合约。部署成功产生的[质押合约地址](#cf-08)全局唯一、与项目一一对应、终身稳定、只读；本模块不提供人工录入、修改、解绑或重新部署入口。部署成功后创建信息全部只读（面客[`F-LS-22`](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-22)），运营端同样不可改。

<a id="d-cm-06"></a>`D-CM-06`【运营端不代资产方动作】：修改创建信息、重新提交审核、关闭项目均为资产方动作，运营端没有对应入口，也不能以退回之外的方式推动项目。退回是运营端唯一能让项目回到资产方手上的结论。

<a id="chain"></a>`D-CM-15`【两处链概念分开表述】：本模块涉及的是**质押链**——质押合约所在链，本期仍为 ETH；合约部署、合约地址与部署凭证均属质押链事实。**结算收款链**（数币收款地址所在链，本期支持 ETH 与 TRON）与本模块无关，项目审核不读取、不校验、不展示任何收款地址。

状态图见[运营端项目审核轴](02-运营端合约管理-流程图与状态机.md#st-cm-01)与[合约部署执行状态](02-运营端合约管理-流程图与状态机.md#st-cm-02)。

## 3. 完整功能

<a id="m1"></a>
### 3.1 项目审核队列（`F-CM-01`～`05`）

前置为正常运营账号且有[融资项目审核查询](#pm-cm-01)权限。队列中**一条记录对应一个项目**，不是一次提交；项目退回后重新提交仍是同一条记录，提交序次与历史在详情内可查。

| 内容 | 产品规则 |
| --- | --- |
| 默认（`F-CM-01`） | 审核轴＝待审核，本次提交时间升序；同时间按稳定项目顺序，重新取数不改变相对次序。不做风险优先排序 |
| <a id="d-cm-13"></a>筛选（`F-CM-03` / `D-CM-13`） | 审核轴（全部 / 待审核 / 部署处理中 / 已通过 / 已退回）、资产方企业、代币类型、提交时间范围、关键词（项目编号 / 项目名称 / 企业名称 / 质押合约地址）。默认除待审核外均为空或全部；组合生效，起止含边界，起点不得晚于终点；关键词忽略首尾空白 |
| 部署情况筛选 | 全部 / 未发起 / 部署处理中 / 部署成功 / 部署失败 / 结果待核实，命中相应项目；这是链上执行事实的筛选，**不是新增人工结论** |
| 须可得的信息（`F-CM-02`） | 项目编号、项目名称、资产方企业、代币类型、项目质押率、项目期限、本次提交时间、已等待时长、审核轴、部署执行状态、查看。已通过的项目另可得质押合约地址 |
| 三项统计（`F-CM-04`） | 待审核**项目数**、部署失败待再次发起**项目数**、近 7 个自然日人工审结**项目数**。应用企业 / 代币类型 / 提交时间 / 关键词条件，不应用审核轴和部署情况筛选；各项按自身状态定义计数并标明范围。人工审结只计通过与退回，部署失败不计入 |
| 排序与分页（`F-CM-05`） | 本次提交时间、已等待时长可升降序；带总数常规分页。筛选改变回首页、重置回默认。每页条数沿用平台现行取值，不另造值。返回与后退保留筛选、排序、页码；原页为空回最后有效页并说明 |
| 空与失败 | 待审为空、筛选无结果、读取失败分别反馈；失败可重试，不假报 0。无查询权限不显示入口，直接访问亦拒绝 |

资产方在待审核或已退回期间主动关闭项目后，该项目离开待审队列，不再可裁定；按权限仍可检索并只读回看其历史。队列不提供逐条裁定动作与批量选择，进入详情才能办理。流程见[项目审核与合约部署](02-运营端合约管理-流程图与状态机.md#fl-cm-01)。

### 3.2 审核详情与创建信息核对（`F-CM-06`～`08`）

<a id="d-cm-12"></a>`D-CM-12`：线下完成判定，线上维护结论。须中性说明"本处信息供线下判定参考，结论由审核人线下作出后在此维护"；不提供评分、风险灯、建议通过 / 退回、自动筛出不合格项目。格式必填、权限与状态校验照常生效。

`F-CM-06`：审核详情须使**创建信息、资产方上下文、参数上下文、合约事实与操作记录同处可得**，并始终可定位当前项目编号与本次提交序次。

| 区块 / 字段 | 业务含义、类型、必填与校验 |
| --- | --- |
| <a id="cf-01"></a>项目定位（`CF-01`） | 项目编号（创建时生成、全局唯一、终身稳定）、项目名称；只读，必有。退回重提不产生新编号，不以名称替代编号定位 |
| <a id="cf-02"></a>本次提交（`CF-02`） | 本次提交审核的真实时点与提交序次（第 N 次提交），必有、只读；已等待时长为事实陈述，非期限 |
| 创建信息（核对对象） | 项目名称（`FP-02`）、代币类型（`FP-29`）、项目质押率（`FP-34`）、项目期限（`FP-35`）、参考结算币种（`FP-30`）、还款方式（`FP-36`）、SPV机构名称（`FP-31`）；全部只读呈现，运营端不可编辑。各字段的业务含义与面客校验归[融资需求与代币质押](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#create)，本模块不重复定义、不二次校验改写 |
| 只读定值的核对口径 | 还款方式为平台定值（按季付息、到期还本付息），创建时带出、本期不可选择或修改；参考结算币种只供参考，**不限制资金方实际报价币种**。两者属**核对带出值**：审核人确认其确为平台带出的现行取值即可，不因资产方偏好改写，也不以此作为退回依据之外的判断标准 |
| 资产方上下文 | 企业名称、稳定主体标识；只读，不以名称替代归属判定。缺失标"待核实"，不得猜测，见[`Q-CM-05`](#q-cm-05) |
| <a id="cf-11"></a>参数上下文（`CF-11`） | 该代币类型在[运营端融资参数配置](../v1.0-运营端融资参数配置/01-运营端融资参数配置-PRD.md)中的当前[最高质押率](../v1.0-运营端融资参数配置/01-运营端融资参数配置-PRD.md#fc-02)与[最长项目期限](../v1.0-运营端融资参数配置/01-运营端融资参数配置-PRD.md#fc-03)，只读引用、标明取数时点，**仅作背景参考**。与本项目创建时锁定的值并列展示并标出是否一致，按 [`D-CM-17`](#d-cm-17) 处理 |
| <a id="cf-08"></a>质押合约地址（`CF-08`） | 文本 / 部署成功后必有。只读消费面客[`FP-33`](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-33)：全局唯一、与项目一一对应、终身稳定；可复制完整值并自行打开区块链浏览器查验，平台不做链上核验。部署完成前为空，不显示占位值 |
| <a id="cf-09"></a>部署链上事实（`CF-09`） | 质押链（本期 ETH）、部署发起时点、部署交易凭证、部署实际 gas 与币种、部署发起地址（即平台统一钱包地址）；均为只读链上事实，随真实结果回写。**运营端只读，无维护、配置或切换入口**；未提供的项标"待核实"，不填 0、不造值 |
| 审核信息 | 本项目审核轴（`CF-03`）、结论时间（`CF-04`）、审核人（`CF-05`）、退回原因（`CF-06`，存在时）；每次提交的结论各自展示，不互相覆盖 |

<a id="d-cm-17"></a>`D-CM-17`【核对对象是创建时的快照】：项目质押率与项目期限**创建时锁定终身**。审核核对的是资产方提交创建时锁定的那份快照，沿[运营端融资参数配置 `D-O-FC-03`](../v1.0-运营端融资参数配置/01-运营端融资参数配置-PRD.md#d-o-fc-03) 的"审核核对用快照"：**运营在审核期间调高或调低参数配置，不改变在审项目的核对结论，也不改变退回后重提的核对基准**，本身不构成退回理由。

当锁定值与[参数上下文](#cf-11)的当前配置不一致时，如实并列展示并标出差异，**不自动拦截提交、不自动改写锁定值、不自动退回、不产生存量整改待办**；上限被调低到存量锁定值以下同样不使该项目变为违规。当前配置不可读时标"待核实"，不以此阻断审核。

`F-CM-07`【项目审核历史】：本项目历次提交、结论、退回原因全文、审核人与时间，以及历次部署尝试与结果，按发生时间倒序可查；摘要可收起，退回原因必须完整可读。重新提交不覆盖既往退回原因，也不把上一次结论改写为本次结论。

<a id="d-cm-18"></a>`D-CM-18`【操作记录是本项目进度的唯一来源，覆盖 `F-CM-06`～`08`、`F-CM-15`、`F-CM-17`～`19`】：不另设第二套进度来源或重复的明细。

| 记录内容 | 含义与信息要求 |
| --- | --- |
| 事件 / 进度 | 必有文本，区分提交审核、审核通过（含部署发起）、部署成功 / 失败 / 结果待核实、再次发起部署、审核退回、资产方修改重提、资产方关闭项目；只展示本项目事实，不混入其他项目 |
| 发生时间 | 已发生事件展示真实时间与时区；按发生时间倒序，同时间保持稳定顺序。时间暂缺标"待核实"，不得用访问时刻代替；未发生的步骤不生成完成记录 |
| 操作主体 | 人工事件显示当时审核人；来自资产方的动作标"资产方"；来自链上结果回写的标"系统"；未提供主体时标"待核实"，不推定为审核人 |
| 结果与说明 | 该事件的结果、前后状态及原因；原因可展开全文。进行中明确"部署处理中"及已知事实，未来步骤不预写成功 |
| 关联凭据 | 有则提供本次部署的链上凭证与合约地址，遵守权限规则；没有则说明暂无，不伪造凭据、不复用其他项目的凭证 |
| 记录反馈 | 加载中、暂无记录、读取失败须分别说明；失败可重试且不伪装为空。记录只读，不提供编辑、删除或手工完成进度动作 |

`F-CM-08`：同一事件重复到达只保留一条，不因重新取数重复生成；新增进度不覆盖既往审核事实。从队列进入详情只进入该项目，返回时保留队列原有的筛选、排序、分页与所在位置。流程见[审核历史与操作记录的查看](02-运营端合约管理-流程图与状态机.md#fl-cm-03)。

<a id="m3"></a>
### 3.3 通过并部署合约（`F-CM-09`～`11`）

<a id="d-cm-08"></a><a id="d-cm-09"></a>`D-CM-08` / `D-CM-09`【审核与部署合为一步】：前置为同时具备查询与处置权限，**当前项目仍为待审核且没有部署处理中**（无截止条件）。通过办理（`C-O-CM-01`）依次为：回显创建信息、资产方与参数上下文 → 确认知悉"提交后将由平台统一钱包发起本项目质押合约部署，部署成功即审核通过、项目与合约一一对应且不可撤销" → 提交。

**提交即发起部署，运营人员不签名、不付费**：部署由平台统一钱包发起，gas 由管理端承担；钱包取值在代码层面维护、随版本发布，本模块及全平台都不提供其维护、配置、切换入口，也不展示余额或提供充值（[`X-CM-01`](#1-2-本期不包含)）。通过在本次办理内完成、不再叠加下一层办理，也没有"核对结论 / 确认审核结论"的后续步骤，不新增第二位审核人。

| 编号 | 规则 |
| --- | --- |
| `F-CM-09` | 提交前取消不产生结论、不发起部署；提交中明确反馈且不可重复点击。权限或状态在提交生效时已变化（项目已被关闭、已被他人裁定、已在部署处理中）时就地说明并拒绝，不产生结论、不重复发起部署 |
| <a id="d-cm-19"></a>`F-CM-10` / `D-CM-19` | 提交成功后审核轴转为**部署处理中**、部署执行状态转为部署处理中，本项目处置入口暂不可用；此时**尚未形成结论**，界面不得展示"已通过"，也不得引导资产方发起质押。同一项目在部署处理中不接受第二次提交，并发提交只有一笔成立 |
| `F-CM-11` | **部署成功即审核通过**：回写[质押合约地址](#cf-08)与[部署链上事实](#cf-09)，审核轴转为已通过并记录审核人与结论时间，项目转为可用（面客 `S-FP-1`，空池），资产方可发起代币质押。结论终态：不可撤销、不可改判为退回、不再部署第二份合约 |
| <a id="d-cm-20"></a>`D-CM-20` | 审核通过不修改创建信息、不改写代币事实、不触发任何额度变化。**项目通过审核只是允许发起质押，本身不产生任何质押额**；三项额度的定义与派生归[融资需求与代币质押](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#pledge-fields)，本模块不消费、不展示、不计算 |

成功后结束本次办理并回到本项目详情，操作记录出现审核通过与部署成功两个事件，当前项目只读，队列中该项目从待审核统计移出，人工审结数加一。面客侧由本模块发送一条[项目审核通过](03-运营端合约管理-消息通知.md#notice-rules)站内信。

<a id="m4"></a>
### 3.4 退回与唯一结论（`F-CM-12`～`13`）

`F-CM-12`：前置同 [3.3 节](#m3)。退回办理（`C-O-CM-02`）为：填写本次退回原因 → 全文预览与二次确认 → 提交。退回**不发起部署、不产生合约地址、不消耗 gas**。

| 编号 | 规则 |
| --- | --- |
| <a id="cf-06"></a>`F-CM-13` / `CF-06` | 退回原因必填，**面客可读原文**，沿用本平台审核驳回原因的现行校验口径：10～500 字，完整展示不截断改写。原因将原样呈现给资产方并进入站内信，**不得写入内部代号、内部备注或超出本项目的信息**；提交前可修改，提交后不可编辑或删除 |
| 唯一结论 | 一次提交至多一个有效结论。并发裁定只有一笔成立，败方明确告知当前已有结论并展示现状，不产生第二条结论、不覆盖原因 |
| 退回后 | 审核轴转为已退回（面客 `S-FP-8`），项目不出现在广场、不可质押、不可发布；资产方可修改创建信息后重新提交，**项目期限不重新起算、不产生新的项目编号**。重新提交后本项目回到待审核并回到队列，本次退回原因保留在[审核历史](#m2)中不被覆盖 |
| 多次退回 | 退回次数本期不设上限，平台不自动终结、不自动通过、不限制重提次数 |

提交前取消不产生结论，跨项目不携带原因；提交中不可重复点击，保存失败保留当前输入可重试。结果不确定时先查当前事实，不展示成功或引导重复裁定。成功后结束本次办理并回到本项目详情，面客侧由本模块发送一条[项目审核退回](03-运营端合约管理-消息通知.md#notice-rules)站内信。

### 3.5 部署失败、结果待核实与再次发起（`F-CM-14`～`15`）

<a id="d-cm-16"></a>`D-CM-16`【签名或部署失败视为审核未完成】：

| 情形 | 业务变化与运营端动作 |
| --- | --- |
| 部署明确失败（`F-CM-14`） | **不是审核结论**：审核轴退回待审核，部署执行状态为部署失败，项目仍为面客 `S-FP-7`。展示<a id="cf-10"></a>部署失败原因（`CF-10`，仅运营端可读的失败事实原文，**不进入面客与站内信**，也不写入退回原因）、失败时点、已消耗 gas（未知标"待核实"）。由有处置权限的管理人员**再次发起**，不需要资产方重新提交、不改变项目期限起算点、不产生第二个项目、不产生第二份合约 |
| 再次发起（`F-CM-15`） | 复用同一条审核记录与同一项目编号，形成新的部署尝试并进入部署处理中；历次尝试与结果全部保留在审核历史与操作记录中，不覆盖。再次发起次数本期不设上限，平台不自动重试、不自动退回、不自动通过 |
| 结果待核实 | 长期无确定结果或事实冲突时标"待核实"，保留已知链上凭证与已发生事实；**不推定成功或失败、不重复发起部署、不自动改判、不自动回滚**。此时处置入口不可用，展示可理解说明并保留项目当前真实状态。链上结果的核实与回写属实现侧能力，见[`Q-CM-02`](#q-cm-02) |
| 面客与消息 | 签名或部署失败、再次发起、结果待核实**都不向资产方发送任何消息**，面客侧仍显示项目待审核；只有部署成功（通过）与退回各发一条（见[消息通知](03-运营端合约管理-消息通知.md#notice-rules)） |

本期不提供工单、异常待办、自动升级、人工改判或补记、强制回滚、补偿、手工录入合约地址等处置能力（[`X-CM-04`](#1-2-本期不包含)、[`X-CM-12`](#1-2-本期不包含)）；无法自行处理时联系建设方核实链上与配置，不在产品内编造处理时限或工单流程。流程见[部署失败与再次发起](02-运营端合约管理-流程图与状态机.md#fl-cm-02)。

### 3.6 质押合约台账（`F-CM-16`～`17`）

`F-CM-16`：台账（`P-O-CM-03`）按项目逐条列出**已部署成功**的质押合约，一条一个项目，与项目一一对应；尚未部署成功的项目不出现在台账。前置为[融资项目审核查询](#pm-cm-01)权限。

| 内容 | 产品规则 |
| --- | --- |
| 须可得的信息 | 项目编号、项目名称、资产方企业、代币类型、质押合约地址、质押链、部署时点、部署审核人、项目当前状态（只读消费面客[融资项目状态](../v1.0-借贷广场-融资需求与代币质押/02-融资需求与代币质押-流程图与状态机.md#st-ls-01)） |
| 筛选与排序 | 按企业、代币类型、部署时间范围、关键词（项目编号 / 项目名称 / 合约地址）筛选；按部署时点升降序。默认部署时点倒序，带总数常规分页，规则同[队列](#m1) |
| 地址可用性 | 合约地址须可复制完整值；可自行打开区块链浏览器查验，**平台不做链上核验、不声称地址在链上的当前状态** |
| `F-CM-17` | 从台账一条记录可进入该项目的[审核详情](#m2)查看创建信息与完整审核历史；返回保留原筛选、排序、分页与所在位置。台账只读，不提供编辑、解绑、重新部署或批量导出之外的业务动作 |
| 空与失败 | 暂无已部署合约、筛选无结果、读取失败分别反馈；失败可重试，不假报 0 条 |

台账不承载逐笔代币质押、额度与覆盖事实，这些归[融资需求与代币质押](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)与[代币质押审核](../v1.0-代币质押审核/01-代币质押审核-PRD.md)；本模块不重复呈现，也不提供跳转以外的第二套数据。

### 3.7 留痕与通知触发（`F-CM-18`～`19`）

`F-CM-18`：留痕关联**项目＋本次提交**，包含提交审核、审核通过、部署发起、部署成功 / 失败 / 待核实、再次发起、审核退回、资产方修改重提与关闭项目；记录事件、时间、主体、前后状态、原因与凭据。人工事件取当时身份，链上与系统事件不伪造审核人；不可编辑删除，重新提交不覆盖旧结论。留痕内容与进度统一按 [`D-CM-18`](#d-cm-18)，同一事件不得同时生成重复的操作记录与进度记录。

<a id="d-cm-14"></a>`D-CM-14` / `F-CM-19`：本模块**只发送两类面客事件**，沿用面客侧既有事件编号与模板，**本模块是这两类事件的唯一发送来源**；事件归属为项目本次结论，不合并、不双发。

| 事件 | 收件方与内容 / 落点 |
| --- | --- |
| 项目审核通过（`financing.project.review_approved`） | 创建该项目的资产方本平台账号；项目、通过时间、质押合约地址；说明项目已可用、现在可以发起代币质押，质押需本人签名且 gas 自担 |
| 项目审核退回（`financing.project.review_returned`） | 同上；退回原因全文原样，说明可修改创建信息后重新提交、项目期限不重新起算、不产生新的项目编号 |
| 签名或部署失败、再次发起、结果待核实 | **不发送任何消息**，属平台内部重试；面客侧仍显示项目待审核 |
| 运营端广播与副本 | 本模块**不产生运营端站内消息**：新项目待审不全员广播，裁定后不向刚裁定的运营再发结果副本，也不新增运营端异常告警 |

通知必须定位本项目及本次结论；页内结果始终保底，投递失败不回滚已生效结论、不重审、不撤销已部署合约。审核详情权限不等于消息收件资格；面客结果只对创建该项目的资产方账号开放，资金方与游客不收、不可读。通知事件、模板、收件、时效与验收统一见[消息通知第 2～5 节](03-运营端合约管理-消息通知.md#notice-rules)及[第 6 节验收](03-运营端合约管理-消息通知.md#notice-acceptance)；本模块不另造事件副本。

## 4. 同序验收

前置：资产方提交项目 P1、P2、P3 审核；运营有查询＋处置、仅查询和无权三组身份；平台统一钱包的部署可分别产生成功、失败与长期无结果三种真实链上结果。审核结论、面客项目状态、合约地址与通知可分别观察。以下为业务验收要求，未决分支按[第 5 章](#open-items)限制，不以模拟结果冒充已上线能力。

### 4.1 项目审核队列（对应 [3.1](#m1)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-CM-01` 队列按项目生成且退回重提不产生第二条记录 | P1 提交后队列出现一条记录，默认按本次提交时间升序、审核轴为待审核；P1 退回后重新提交仍是同一条记录、同一项目编号，提交序次变为第 2 次 |
| `AC-CM-02` 三项统计随真实状态变化且不被状态筛选影响 | 待审核项目数随裁定减少；P2 部署失败后计入"部署失败待再次发起"且**不计入**近 7 日人工审结；P1 通过、P3 退回后人工审结加 2。切换审核轴或部署情况筛选不改变统计范围 |
| `AC-CM-03` 筛选与排序生效且取值范围正确 | 审核轴只有待审核 / 部署处理中 / 已通过 / 已退回四个可选值，无第三种结论、无超时项；部署情况可按未发起 / 处理中 / 成功 / 失败 / 待核实筛选；企业、代币类型、提交时间区间与关键词组合生效，起止错误就地提示，重置回默认 |
| `AC-CM-04` 翻页往返保留上下文且失败不假报为空 | 翻页与详情往返保留原筛选、排序、分页与所在位置；队列无逐条裁定入口、无批量选择；加载失败不显示为零条，可重试 |
| `AC-CM-05` 资产方关闭后离开待审队列但历史仍可读 | P3 在已退回期间被资产方关闭后不再出现在待审核、不可裁定；按权限仍可检索并只读回看其创建信息与审核历史，运营端无关闭与恢复入口 |

### 4.2 审核详情与创建信息核对（对应 [3.2](#m2)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-CM-06` 创建信息完整只读且无运营端编辑能力 | 项目名称、代币类型、项目质押率、项目期限、参考结算币种、还款方式、SPV机构名称全部可见且只读；还款方式显示为平台定值、参考结算币种标明只供参考不限制资金方报价币种；运营端无任何编辑、代改或代提交入口 |
| `AC-CM-07` 核对以创建快照为准，参数变动不改变在审结论 | P1 在审期间运营把该代币类型的最高质押率调低到 P1 锁定值以下，详情同时展示创建时锁定值与当前配置值并标出差异；核对基准仍是创建快照，提交通过不被自动拦截、锁定值不被改写、不自动退回、不产生整改待办，P1 不被标记为违规；退回后重提的核对基准同样不变；当前配置不可读时标"待核实"且不阻断审核 |
| `AC-CM-08` 审核历史累积不覆盖 | P1 经两次退回后再通过，历史按发生时间倒序可见三次提交、两条退回原因全文与一次通过；重新提交不覆盖既往原因，不把上次结论改写成本次结论 |
| `AC-CM-09` 操作记录是唯一进度来源且不伪造主体 | 提交审核、审核通过、部署发起、部署成功 / 失败、再次发起、退回、资产方重提与关闭均出现在本项目操作记录，与创建信息、合约事实同处可得；链上与系统事件标"系统"、资产方动作标"资产方"，不伪造审核人；同一事件重复到达只保留一条；加载中、无数据与读取失败可分辨 |
| `AC-CM-10` 资产方主体与链上事实缺失时不猜测 | 稳定主体标识缺失标"待核实"不放行、不以企业名称替代归属；部署 gas 或凭证未提供时标"待核实"，不填 0、不造值 |

### 4.3 通过并部署合约（对应 [3.3](#m3)）

### 4.4 退回与唯一结论（对应 [3.4](#m4)）

| 验收 | 场景与预期 |

<a id="limits"></a>
### 5.2 按用户决定保留的业务限制（供研发与测试知悉）

以下为用户明确裁定后的既定结果，如实记录其业务后果，不作为异议保留。

**本模块直接承担的限制：**

1. **审核与部署合为一步，通过不可撤销。** 一旦部署成功即审核通过并产生合约地址，平台侧没有任何动作能撤销该结论或销毁该合约。若事后发现创建信息有误，只能由资产方另建新项目，原项目按其当前状态自行关闭或到期。测试应按此预期设计用例，不将其判为缺陷。
2. **项目审核无时效。** 待审项目可无限期停留在待审核，平台不催办、不自动终结、不自动通过。若运营长期不处理，资产方的出路只有等待或主动关闭项目重建；项目期限自创建时间起算，审核耗时会实际占用项目有效期。
3. **签名或部署失败没有对资产方的可见出口。** 失败仅在运营端可见并由管理人员再次发起，面客侧始终显示待审核、收不到任何消息。若部署持续失败或长期无结果，资产方只能看到项目一直待审核，无法自行判断原因。
4. **平台统一钱包与 gas 充值不在本系统范围。** 平台不提供钱包余额展示、充值入口或余额不足告警。若钱包余额不足导致部署失败，本模块只能如实展示失败原因，由建设方在系统外处理。

**本批同时确认、写入以供全局知悉的限制（归属他册，本模块不承担）：**

5. **平台不再采集与校验收款人名称。** 法币与数币账户均取消收款人名称，受益人名称需由业务双方在平台外补充。
6. **报价一经提交，资金方无法撤回。** 退出路径仅为资产方拒绝。
7. **待放款阶段无终止出口。** 待放款的唯一出口是资金方提交放款；若线下协商结果是不放款，业务将持续停留在待放款，对应质押代币持续被占用。

### 5.3 本模块需要的运营端权限项（归 WS-380 第 5 批登记）

| 需要的权限项（业务名称） | 类别 | 覆盖的业务能力 | 与既有项的关系 |
| --- | --- | --- | --- |
| <a id="pm-cm-01"></a>融资项目审核查询 | 查询类 | 查看项目审核队列与统计、审核详情、创建信息与参数上下文、项目审核历史与操作记录、质押合约台账 | 与"代币质押申请查询"（`PM-AL-07`）并列且互不包含：项目审核与逐笔质押审核是两个对象、两条队列 |
