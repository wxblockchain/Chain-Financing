# 运营端合约管理 · 消息通知

2026-09-24｜配套本模块当前[主 PRD](01-运营端合约管理-PRD.md#entry)与[图册](02-运营端合约管理-流程图与状态机.md)。

<a id="notify-entry"></a>
## 1. 范围与阅读入口

本模块只有**两类**项目审核结果事件——项目审核通过与项目审核退回，全部发给**创建该项目的资产方本平台账号**，只走"借贷平台 · 面客端"站内信。本册定义发什么、何时发、发给谁、打开到哪里；通知的承载形式与视觉由设计决定（见[统一条款](01-运营端合约管理-PRD.md#design-boundary)）。站内消息的阅读入口、未读语义与可见范围归[面客消息中心](../v1.0-面客消息中心/01-面客消息中心-PRD.md)，本册不重复定义，也不规定消息接口或投递实现。

两类事件沿用面客侧既有事件编号 `N-LS-09`～`N-LS-10` 与模板 `T-LS-09`～`T-LS-10`，**本模块是这两类事件的唯一发送来源**；[融资需求与代币质押](../v1.0-借贷广场-融资需求与代币质押/03-融资需求与代币质押-消息通知.md)承接面客侧的结果查看与模板权威版本，不发同义副本。分类语义为"业务办理进度"。不新增邮件、短信、浏览器推送、催办、部署进度通知或客服进度通知。

**本模块不产生运营端站内消息**：新项目待审不向运营全员广播，裁定后不向刚裁定的运营再发结果副本，部署失败与结果待核实也不产生运营端告警。[运营端消息通知](../v1.0-运营端消息通知/01-运营端消息通知-PRD.md)只承接来源事件，本模块没有可供其承接的运营端事件。

业务完整规则回查[通过并部署合约](01-运营端合约管理-PRD.md#m3)、[退回与唯一结论](01-运营端合约管理-PRD.md#m4)、[部署失败与再次发起](01-运营端合约管理-PRD.md#m5)、[留痕与通知触发](01-运营端合约管理-PRD.md#m7)，流程回查[项目审核与合约部署](02-运营端合约管理-流程图与状态机.md#fl-cm-01)。

## 2. 两项事件与发送边界

| 通知 / 业务类型 / 模板 | 触发条件与必须告知的结果 | 收件与目标 |
| --- | --- | --- |
| `N-LS-09` / `financing.project.review_approved` / [`T-LS-09`](#templates) | **合约部署成功、项目转为可用时发送一次**（部署成功即审核通过）。带本项目通过时间与[质押合约地址](01-运营端合约管理-PRD.md#cf-08)，说明项目已可用、现在可以在项目详情发起代币质押，质押需本人签名且 gas 自担 | 创建该项目的资产方本平台账号；进入对应项目，可从中发起质押。不自动勾选或执行任何动作 |
| `N-LS-10` / `financing.project.review_returned` / [`T-LS-10`](#templates) | **退回结论生效即发送，每次退回各发一次**。完整面客原因与正文[退回原因 `CF-06`](01-运营端合约管理-PRD.md#cf-06) 原文一致，说明可修改创建信息后重新提交、项目期限不重新起算、不产生新的项目编号 | 同上；进入对应项目的创建信息，可直接修改后重新提交。已重新提交的显示当前状态，不回到旧版本 |

**签名或部署失败、再次发起部署、结果待核实都不发送任何消息**——这些属平台内部重试，面客侧始终显示项目待审核。未提交的原因、仅打开办理、并发未生效的裁定同样不触发消息。提交通过后进入部署处理中时**尚未形成结论，不得提前发送通过通知**；真实事实已存在冲突时不能用普通措辞掩盖异常，按正文保护呈现，不另造异常结果通知。

通过与退回结论生效后不能再次修改同一次结论。审核历史不随后续重新提交被重写，也不因后续事件再次发送同一次结论的结果。**任何时间流逝都不触发通知**：项目审核无时效，没有临期提醒、没有超时告知、没有待审催办。

| 本期不新增的通知 | 保留的业务能力 |
| --- | --- |
| 待审临期提醒、审核催办、审核超时告知 | 面客可随时查看项目当前状态；运营端可查看已等待时长（事实陈述、非期限） |
| 新项目待审全员广播、给刚裁定运营再发结果副本、部署成功运营端回执 | 运营端项目审核队列、三项统计与审核历史仍可查 |
| 部署发起、部署处理中、部署失败、再次发起、结果待核实的第二套消息 | 运营端在审核详情与操作记录中可见全部部署尝试与结果 |
| 平台钱包余额不足、gas 消耗、充值提醒类消息 | 部署失败原因原文与已消耗 gas 在运营端如实展示；钱包与充值不在本系统范围 |
| 部署结果待核实的升级、工单、异常处置或客服进度消息 | 页内真实事实与保护；无法自行处理时联系建设方核实链上与配置 |

## 3. 收件、去重、时间与可读性

**收件。** 每条固定发给**创建该项目的资产方本平台账号**，不按企业全员、不任选管理员或当前查看人；资金方、游客和运营不收这两类结果副本。运营有融资项目审核查询 / 处置权限可看、可办审核，不因此成为面客消息收件人；运营端消息查看权限也不赋予读取他人面客信件的资格。本期一个企业只有一个员工，原多成员资产方的收件归属问题自然消解，不再作为待决项；账号停用、交接或归属缺失仍按来源及消息框架依赖处理，不猜新收件人、不转移历史。

**同一事实。** 按面客端、收件账号、通知类型和**本次结论**区分。同一次结论重复送达不新增消息 / 未读、不把已读恢复未读、不改变发生时间或原有次序。一个项目经多次退回后通过，每次退回各保留一条消息、通过再保留一条，**不按"项目＋结论类型"合并掉第二条**；重新提交是新的一次提交，新结论可有新通知，旧记录不覆盖。是否分组呈现由设计决定，但每次原因及定位不能丢失。

**时间。** 通知使用业务给定的真实发生时间——通过取部署成功回写的真实通过时点，退回取结论生效时点；不自行重新计算、不以发送 / 阅读时间重置，也不取部署发起时刻冒充通过时刻。**本模块不再有任何截止或期限类时间**：不发送截止、不计算剩余时长、不因到期删除或改写原消息。时点按收件人偏好时区展示并标注，切换时区或夏令时不改通知事实和业务资格。

**打开目标。** 通过消息进入对应项目后可按当前资格发起质押，**质押动作必须由用户主动发起**，消息不直接打开办理、不代为签名、不替用户确认。退回消息进入创建信息后由用户自行修改并重新提交。进入时核对当前身份、权限与项目当前状态，不能绕过业务准入；项目此后被资产方关闭或已重新提交时，仍按当前权限展示当前状态与本次历史原因，不回到旧版本。正常登录失效须登录后再按当前资格进入；无权不泄露对象或私有账户信息。目标尚未登记时按消息框架采用可读无跳转的降级，不把默认首页当成准确定位。

消息已读只改变消息状态，不完成审核、不发起质押、不撤销已部署的合约、不改变项目状态。内部信息、部署交易的原始技术报错、可越权链接不进入通知；业务原因保留全文。SPV机构名称与平台统一钱包地址不进入消息模板，也不作为收件判据。公共客服联系方式仅使用已有真实公开值，不编造地址。

## 4. 消息内容与模板

以下业务信息随结果提供，必填表示该事件成立时必须有真实值，不得用演示数据补齐。本册不定义编号编码、传输结构或表结构。

| 业务信息 | 类型、必填与校验 |
| --- | --- |
| 项目定位 | 业务标识文本，两事件必有且能定位；取本项目[项目编号与名称 `CF-01`](01-运营端合约管理-PRD.md#cf-01)。**项目名称不能替代项目编号**，同名项目以编号区分；不使用其他项目替代缺项 |
| 收件与业务发生时间 | 创建该项目的账号及真实时点，必有；不能取审核员、部署发起或阅读时刻 |
| `project_name` / `project_id` | 两模板必有；沿业务原值，名称按项目 1～60 字符规则，编号稳定不变。退回重提不产生新编号，消息前后指向同一项目 |
| `approved_at` | `T-LS-09` 必有，为**部署成功回写的真实通过时点**；未部署成功不造值，不取部署发起时刻或结论提交时刻 |
| `contract_address` | `T-LS-09` 必有，取部署成功回写的真实质押合约地址，与项目一一对应；不造值、不用占位串、不在部署完成前发送 |
| `reason` | `T-LS-10` 必有，为本次退回原因原文，沿正文 10～500 字校验，完整可读；不用内部信息或原始技术报错替代，不因摘要省略而丢失全文；英文界面不假称人工中文原因已翻译 |

<a id="templates"></a>本册复用面客侧 `T-LS-09`～`T-LS-10` 的完整双语模板，不新建另一组名称；标题和正文为成对文本，变量同名同数量。模板名称沿既有 `msg.<业务类型>.title` / `msg.<业务类型>.body` 约定。下表为[融资需求与代币质押消息通知](../v1.0-借贷广场-融资需求与代币质押/03-融资需求与代币质押-消息通知.md#t-ls-09)现行模板的原样复述，**模板权威版本以该册为准，本册不改写文案**。

| 模板 | 中文标题 / 正文 | English title / body |
| --- | --- | --- |
| `T-LS-09` | 融资项目审核通过 / 项目 {project_name}（{project_id}）已于 {approved_at} 审核通过，质押合约地址 {contract_address}。现在可以在项目详情发起代币质押；质押需要你本人签名，gas 自担。 | Financing project approved / Project {project_name} ({project_id}) was approved at {approved_at}. Pledge contract address: {contract_address}. You can now pledge tokens from the project details. Pledging requires your signature and the gas is payable by you. |
| `T-LS-10` | 融资项目审核退回 / 项目 {project_name}（{project_id}）的审核结论为退回。原因：{reason}。请修改创建信息后重新提交；项目期限不会重新起算，重新提交不产生新的项目编号。 | Financing project returned / Project {project_name} ({project_id}) was returned for revision. Reason: {reason}. Update the project details and resubmit. The project term is not restarted and resubmission does not create a new project. |

标题、正文、账号或项目业务事实不足时不得伪造可用消息；非关键跳转配置缺失按框架降级，不把所有缺项一律等同丢弃整条消息。原文原因作为业务文本完整展示，不扩展成其他通知或动作。

## 5. 时效、偏好与依赖

关键结果在真实业务发生后的 **60 秒**内可见，未读计数同步更新；通过以部署成功回写为业务发生时点，不能把接收完成才作为起点，也不以用户重新取数作为前提。消息失败不回滚已生效结论、不重审、不撤销已部署的合约，业务结果始终可查。本册不设计重试方案。

本期两个审核结果未列入可关闭事件，不自行新增关闭或补送策略；沿消息框架既有偏好规则。分类筛选不是退订，业务进度分类不等于允许屏蔽。没有明确可选事件时不制造新通知来填充开关。

剩余依赖：共享消息分类值与正式登记、端到端时效（部分来源为"60 秒与最坏 5 分钟"）的冲突与真实联验仍在面客消息框架侧，本模块保持 60 秒要求，不声称全平台冲突已解决；创建账号真实对应见[`Q-CM-05`](01-运营端合约管理-PRD.md#q-cm-05)，部署结果真实回写见[`Q-CM-02`](01-运营端合约管理-PRD.md#q-cm-02)——回写缺失时本模块不得提前发送通过通知。异常升级 / 关闭责任不是本期功能待决；本册不重新建设来源或运营端队列。原多成员收件归属依赖随"一个企业一个员工"闭合。

## 6. 验收要求

沿正文[留痕与通知触发](01-运营端合约管理-PRD.md#m7)及 `AC-CM-30`。前置：项目 P1 经一次退回后重新提交并部署成功，P2 部署失败后再次发起，P3 停留在已退回。以下是可观察结果，不是详细测试步骤。

| 编号 | 验收结果 |
| --- | --- |
| `AC-CM-N01` 两类结果分别触达创建账号 | P1 的退回与其后的通过各产生一条消息、互不吞并；P3 的退回产生一条；仅创建该项目的资产方账号收到，资金方、游客与运营不收。通过文案含真实合约地址并说明现在可以发起质押，退回文案原因全文准确并说明期限不重算、编号不变 |
| `AC-CM-N02` 部署未成功不提前发送也不误发 | 提交通过后处于部署处理中时不发送任何消息；P2 的部署失败、再次发起与结果待核实全程不向资产方发送消息，面客侧只见项目待审核；只有部署成功后才发送通过通知 |
| `AC-CM-N03` 同一事实去重且多次结论各自保留 | P1 同一次通过重复到达只有一条消息，不新增未读计数、不改变原有次序或发生时间；同一项目的历次退回与最终通过分别保留，不按"项目＋结论类型"合并掉第二条 |
| `AC-CM-N04` 时点与时区展示一致且无期限类时间 | 两端及消息中的通过时点指向部署成功回写的同一时刻并带时区标注，不取部署发起或结论提交时刻；消息中不出现任何截止、剩余时长或倒计时；切换展示时区、夏令时不改变已发生事实，不以阅读时间重算 |
| `AC-CM-N05` 历史消息可读但不误触发办理 | 项目被关闭或已重新提交后，原消息仍可按权限读本次历史原因，不可用的动作停止，不回到旧版本；质押必须由用户主动发起，读消息不完成审核、不发起质押、不撤销已部署合约、不改变项目状态；无权者不能读私有项目信息 |
| `AC-CM-N06` 事件范围限于两类结果且无运营端消息 | 本模块只有项目审核通过与项目审核退回两类事件；部署发起、部署处理中、部署失败、再次发起与结果待核实均不发送。运营端无新项目待审广播、无裁定回执、无部署失败告警、无钱包余额类消息 |
| `AC-CM-N07` 模板变量完整且不泄露内部信息 | 两组中英标题正文变量一致，完整原因保留；不泄露内部信息、原始技术报错、SPV机构名称或平台统一钱包地址；合约地址、通过时点缺失时不以演示值或占位串补齐、不发送该条消息；消息投递失败不回滚已生效结论 |
| `AC-CM-N08` 可见时效以真实投递为准 | 从真实业务发生时点观察 60 秒可见目标；未登记、真实收件依赖或时效冲突如实标未完成，不能以文档模板核对替代实际投递验收；两个结果不因未定义的可选开关被屏蔽 |
