## 2. 背景、目标与平台边界

L6 已完成报价接受、线下签约及盖章件上传，将业务交到 `S-FD-3 待放款`。L7 让资金方核验合同、登记其已在平台外完成的付款，再由资产方核实到账并确认，最后交 L8 生成还款计划。平台不执行转账，也不判断付款或合同真伪。

本期覆盖：盖章件核验及三个处置动作、盖章件重传、法币 / 数币放款记录、还款收款账户登记、资产方到账确认、168 小时确认时限与超期出口、通知、控制台及还款模块交接。

借贷平台拥有融资项目、授信、报价、放款与还款计划的业务事实；代币事实归代币发行平台，本模块只使用借贷平台提供的质押覆盖结论，不执行链上质押、释放或转账。资产方通过资产可信平台授权登录，资金方使用借贷平台账户体系；父 issue 指定的 OIDC 接入作为登录模块既定约束引用，不在 L7 展开。

本期不提供部分或分次放款、放款记录修改 / 撤回、还款收款账户提交后修改、确认撤销、异议 / 申诉 / 驳回、运营裁决、催办、自动确认、确认展期、合同审核、链上真实性核验、提前还款。对应 X-LS-28～39 沿用；还款方式与计息规则归 L8。P04已确定SPV视同运营；本期维持两方资金链路，运营和SPV均不参与L7资金操作，不另建SPV认证、账户或审批轨道。

## 3. 角色、可见性与状态

### 3.1 角色权限

| 角色 | 可看 | 可做 |
| --- | --- | --- |
| 本笔资金方 | 公开信息及本笔双方业务资料、盖章件版本、账户、凭证、处置原因 | S-FD-3：核验、暂不放款、要求重传、终止、提交放款；S-FD-4 起无本模块写动作 |
| 本项目资产方 | 公开信息及本笔双方业务资料 | S-FD-3 且 FD-31 为真：重传；S-FD-4：确认到账，超期仍可确认 |
| 登录的非当事方 | 公开信息 | 无 L7 写动作，无双方私有资料 |
| 未登录访客 | 公开信息 | 操作区只出“立即登录”，不逐个展示禁用动作 |
| 运营人员 | 本模块不增加其资料可见权 | 无面客写动作、无裁决或代确认能力 |
| SPV机构 | 与运营人员相同，本模块不新增资料可见权 | 无代付、归集、放款登记、还款收取、终止、审批或代确认动作，不继承资金方权限 |

同一企业主体的任一已登录员工可代表该企业执行其已获角色的动作，沿用基线，不增加企业内分级授权。登录成功不等于成为某笔业务的当事方；无权者即使从通知或旧入口直达也不能读取私有内容或执行动作。

公开字段沿用 D-LN-06 及字段表明确标记：放款币种、金额、提交时间、确认时间、终止时间与原因；FD-37 到期时刻在基线字段表明确公开，沿用该单字段可见性，**不因此公开当事方轮次轨、剩余时限或新增列表筛选**。商务条款本已公开的内容按上游范围展示。

私有范围：账户 / 地址、发放时间、凭证、交易哈希与链、盖章件及历史版本、暂缓与重传原因、实收金额、放款备注、补充材料及还款收款账户，仅本笔双方可访问。下载与复制同受权限约束；通知不得携带完整私有账户或凭证。终止原因按已确认口径公开且中性呈现。

**L7-REV-01 本人档案与交易资料（P01）。** 个人、企业账户档案仅本人可查；对手方不能通过“核验资料”读取完整账户档案、证件、认证材料或私人联系方式。本笔交易必需的主体名称、合同、约定条款及付款资料按上表和字段定义提供，业务资料可见不等于整个档案可见。已有且有权用于本笔的信息自动取得，不要求用户复制或手填对方已知资料；缺失、读取中、读取失败分别展示，失败可重试，关键主体归属或必要付款资料不能确认时不放行相关提交，不用假值补齐。

普通列表及摘要保留掩码；已确认的本笔付款当事方在办理付款时能受控核对并复制所需完整账户。本笔双方的只读对账按既有权限查阅，非当事方、运营和SPV不因身份或直达入口获得完整资料。私有下载和完整值读取同样受本笔权限限制。掩码位数等未有明确依据的细项保留Q-L7-05，不能因此阻止已定的付款用途读取，也不能默认公开完整账户。

### 4.1 F-LS-56 · 融资放款清单、详情与办理入口

**入口与对象。** 项目主页面左侧纵向排列的「融资放款信息」清单负责查记录；右侧固定办理区「融资」页签、控制台待办和通知负责进入当前对象的办理。所有入口落到同一笔业务、相同权限与最新状态。多笔待办先明确选择融资申请 / 业务，再从操作区进入对应办理弹窗，不能默认对第一笔提交。主页面其余清单、右侧操作页签及导航规则见L5 V1.4 §9.2、§11.7；四区定位标签按用户后续确认滚动定位原清单，不替换纵向清单、不新增办理动作；不继续把申请、报价、放款、还款的全部资料堆入同一详情。

**入列时机与行粒度。** L6 报价被接受、进入 S-FD-3 时即进入融资放款清单，一行一笔已接受融资业务 FD-01，不能等成功提交放款后才出现。已暂缓、待重传仍在原行显示 S-FD-3 与标记；S-FD-4 显示待放款确认，超期是标记；确认后保留原记录，还款信息清单以同笔编号承接；已终止保留只读历史，不表示成功放款。资产方确认到账后，本清单的放款展示状态固定为“已放款”；后续S-FD-6还款中、S-FD-8已结清及还款逾期只在还款信息清单与对应详情表达，不回写成本放款行的状态。不新增放款业务状态、不改变到账确认或还款入列时点。

| --- | --- |
| 融资申请编号 FP-28 | 原需求编号，展示名称统一为融资申请编号；可关联该轮申请，只读，不生成新号 |
| 融资业务编号 FD-01 | 本笔已接受业务的定位依据；同一申请重新报价可出现新的业务编号，不能覆盖旧终止记录 |
| 放款编号 LN-01 | 仅成功提交放款记录后生成；待放款或放款前终止显示「尚无放款记录」，不预生成或以 FD 充作 LN |

**详情顺序。** 只用一个右侧只读抽屉承载融资放款详情。自上而下为：①放款信息（金额、业务状态、当前动作方、编号、提交 / 确认时间及既有标记；凭证或哈希按权限查看）；②资金方还款收款账户（LN-15/16，明确将来还款收款用途）；③资产方放款收款账户（LN-10，承接 L6）；④协议文件表（文件名、版本、上传时间、上传人和下载操作）。账户展示只使用 F-LS-49 的已定义字段，待放款时 LN-15/16 尚未提交则显示「待资金方提交」，不补造出账账户、不把 LN-15/16 称作实际放款出账账户。放款办理须核对的合同与商务条款在 F-LS-45 核验视图完整提供。

### 4.11 F-LS-53 · 放款确认时限

FD-37 到期时刻 = LN-06 成功提交时间 + 168 小时，精确到秒，为连续168小时，不是工作日、七个UTC日期末或用户当地第七天日终；不可延长、无宽限期，不从发放时间、送达或查看时间起算。FD-38 是剩余时长，下限为 0；平时精确到小时，不足 24 小时精确到分钟并加强提示。
