## 2. 背景、目标与平台边界

L6 已完成报价接受、线下签约及盖章件上传，将业务交到 `S-FD-3 待放款`。L7 让资金方核验合同、登记其已在平台外完成的付款，再由资产方核实到账并确认，最后交 L8 生成还款计划。平台不执行转账，也不判断付款或合同真伪。

本期覆盖：盖章件核验及三个处置动作、盖章件重传、法币 / 数币放款记录、还款收款账户登记、资产方到账确认、168 小时确认时限与超期出口、通知、控制台及还款模块交接。

借贷平台拥有融资项目、授信、报价、放款与还款计划的业务事实；代币事实归代币发行平台，本模块只使用借贷平台提供的质押覆盖结论，不执行链上质押、释放或转账。资产方通过资产可信平台授权登录，资金方使用借贷平台账户体系；父 issue 指定的 OIDC 接入作为登录模块既定约束引用，不在 L7 展开。

本期不提供部分或分次放款、放款记录修改 / 撤回、还款收款账户提交后修改、确认撤销、异议 / 申诉 / 驳回、运营裁决、催办、自动确认、确认展期、合同审核、链上真实性核验、提前还款。对应 X-LS-28～39 沿用；还款方式与计息规则归 L8。本模块存在运营管理平台的外部角色，不等于已授权这些角色执行 L7 操作。

## 3. 角色、可见性与状态

### 3.1 角色权限

| 角色 | 可看 | 可做 |
| --- | --- | --- |
| 本笔资金方 | 公开信息及本笔双方业务资料、盖章件版本、账户、凭证、处置原因 | S-FD-3：核验、暂不放款、要求重传、终止、提交放款；S-FD-4 起无本模块写动作 |
| 本项目资产方 | 公开信息及本笔双方业务资料 | S-FD-3 且 FD-31 为真：重传；S-FD-4：确认到账，超期仍可确认 |
| 登录的非当事方 | 公开信息 | 无 L7 写动作，无双方私有资料 |
| 未登录访客 | 公开信息 | 操作区只出“立即登录”，不逐个展示禁用动作 |
| 运营人员 | 本模块不增加其资料可见权 | 无面客写动作、无裁决或代确认能力 |
| SPV 机构 | 待 Q-L7-01 裁定，不沿用资金方权限 | 不在已确认链路中新增入口、代理操作或中间状态 |

同一企业主体的任一已登录员工可代表该企业执行其已获角色的动作，沿用基线，不增加企业内分级授权。登录成功不等于成为某笔业务的当事方；无权者即使从通知或旧入口直达也不能读取私有内容或执行动作。

公开字段沿用 D-LN-06 及字段表明确标记：放款币种、金额、提交时间、确认时间、终止时间与原因；FD-37 到期时刻在基线字段表明确公开，沿用该单字段可见性，**不因此公开当事方轮次轨、剩余时限或新增列表筛选**。商务条款本已公开的内容按上游范围展示。

私有范围：账户 / 地址、发放时间、凭证、交易哈希与链、盖章件及历史版本、暂缓与重传原因、实收金额、放款备注、补充材料及还款收款账户，仅本笔双方可访问。下载与复制同受权限约束；通知不得携带完整私有账户或凭证。终止原因按已确认口径公开且中性呈现。

### 4.1 F-LS-56 · 融资放款清单、详情与办理入口

**入口与对象。** 项目主页面左侧纵向排列的「融资放款信息」清单负责查记录；右侧固定办理区「融资」页签、控制台待办和通知负责进入当前对象的办理。所有入口落到同一笔业务、相同权限与最新状态。多笔待办先明确选择融资申请 / 业务，再进入对应抽屉，不能默认对第一笔提交。主页面其余清单、右侧操作页签及导航规则见 L5 §9.2、§11.7；不继续把申请、报价、放款、还款的全部资料堆入同一详情。

**入列时机与行粒度。** L6 报价被接受、进入 S-FD-3 时即进入融资放款清单，一行一笔已接受融资业务 FD-01，不能等成功提交放款后才出现。已暂缓、待重传仍在原行显示 S-FD-3 与标记；S-FD-4 显示待放款确认，超期是标记；确认后保留原记录并可关联还款信息；已终止保留只读历史，不表示成功放款。进入 L8 后本清单按 L8 的当前业务结果显示，不继续暴露已失效的 L7 办理动作，也不创建放款记录独立状态。

| 清单字段 | 业务含义、展示与空值口径 |
| --- | --- |
| 融资申请编号 FP-28 | 原需求编号，展示名称统一为融资申请编号；可关联该轮申请，只读，不生成新号 |
| 融资业务编号 FD-01 | 本笔已接受业务的定位依据；同一申请重新报价可出现新的业务编号，不能覆盖旧终止记录 |
| 放款编号 LN-01 | 仅成功提交放款记录后生成；待放款或放款前终止显示「尚无放款记录」，不预生成或以 FD 充作 LN |
| 资金方、融资金额、放款币种 / 金额 | 已接受商务条款的摘要；未提交时金额明确为「约定放款金额」，不伪装已实际放款 |
| 业务状态与标记 | 当前融资业务状态；暂缓、待重传、确认超期分别呈现标记，不新增状态筛选值 |
| 放款提交时间、确认时间 | 分别取 LN-06、FD-35；事件未发生显示「未提交」或「未确认」，不得填预计时间 |
| 当前操作 | 查看详情常驻；办理只对当前有权角色出现，资金方放款、资产方重传 / 确认按本章各功能控制 |

无记录时保留融资放款信息清单及空态，说明接受报价后在此查看放款业务；不得用演示记录替代。FP-28 / FD-01 / LN-01 可用于定位同一记录；只有已经生成的 LN 才可按放款编号检索。列表及详情的私有信息仍按第 3 章隔离，不因增加清单扩大可见范围。

**详情顺序。** 只用一个右侧业务抽屉承载融资放款详情。自上而下为：①放款信息（金额、业务状态、当前动作方、编号、提交 / 确认时间及既有标记；凭证或哈希按权限查看）；②资金方还款收款账户（LN-15/16，明确将来还款收款用途）；③资产方放款收款账户（LN-10，承接 L6）；④协议文件表（文件名、版本、上传时间、上传人和下载操作）。账户展示只使用 F-LS-49 的已定义字段，待放款时 LN-15/16 尚未提交则显示「待资金方提交」，不补造出账账户、不把 LN-15/16 称作实际放款出账账户。放款办理须核对的合同与商务条款在 F-LS-45 核验视图完整提供。

关联融资申请入口仅用于查看该笔业务对应的申请与已接受条款，在同一抽屉切换视图并可返回原放款详情；不复制全套申请、多轮报价及还款计划。协议文件点击下载不打开第二层弹窗；预览在同一容器内切换，返回后恢复原位置，历史版本可查且不覆盖当前版本。

**办理与确认。** P-LS-07 放款、P-LS-08 确认到账、盖章件重传均由详情切到同一抽屉的办理视图。L7 依次提示「资金方放款 → 资产方确认到账」，展示「轮到您 / 等待对方」；游客、非当事方不展示当事方轮次轨。提交放款、确认到账、终止业务的最终二次确认均在该抽屉内切换到确认步骤，明确对象、金额和各功能规定的不可逆后果，不另开居中确认层或重叠抽屉。原因输入就地展开。宽度由设计根据内容判断；窄屏同一抽屉全屏呈现，核验可读性遵循 F-LS-45。

**返回、关闭与结果。** 返回仅退当前步骤并保留已填内容、已成功上传材料及浏览位置；最终确认取消回原办理步骤。关闭回原清单，保留筛选、分页、滚动及行焦点；有未提交编辑时，在原抽屉内确认是否放弃，取消放弃则保留内容。成功更新原记录和状态，抽屉展示办理结果及适用的下一步入口，不自动打开下一业务。资产方确认成功后可主动查看还款信息，不能自动跳到某一期还款办理。

**异常。** 旧通知或旧入口遇到已放款、已确认、已终止，仍落同一对象的当前详情并说明结果，不白屏、不静默回首页、不继续打开失效操作。游客看公开信息及立即登录；非当事方提示无操作权限且不泄露私有信息。覆盖不足仅禁用放款提交，不阻止打开核验视图。提交放款仅表明资金方已登记付款，不代表资产方确认到账。

### 4.2 F-LS-45 · 盖章件核验区

**角色与前置。** 本笔资金方在 S-FD-3 从放款详情进入同抽屉核验视图。桌面左侧盖章件在线预览、下载、历史版本切换，右侧商务条款九项只读对照；窄屏承载见下文。并呈现资产方已作出的条款一致性声明与时间 FD-16。

核验由资金方自行判断，无“核验通过”按钮、无勾选进度、无平台合同审核状态。必须提示“平台不审核合同真伪与法律效力，请自行核验”。桌面可视区应支持盖章件金额与摘要金额同屏对照，不因进入确认步骤而丢失核验对象；抽屉宽度由设计决定，不再规定固定像素宽度。窄屏在同一全屏抽屉内切换文件与摘要并保留文件位置、版本和条款上下文，可随时返回对照，不依赖重叠弹窗完成核验；不能因压缩页面省略九项摘要或合同阅读入口。

历史版含上传时间与动作人，切换不覆盖文件。预览 / 下载失败不得显示“已核验”；现有资料是否可读不改变业务状态。依据 D-LN-20/23/58、AC-LN-03；图 [P-L7-01](v1.0-借贷广场-放款与放款确认-流程图与状态机.md#p-l7-01)。

### 4.4 F-LS-47 · 要求重传与盖章件重传

### 4.5 F-LS-48 · 终止业务

仅本笔资金方在 S-FD-3 可执行。必填原因 1～200 字、初始空、自由文本；同一抽屉的最终二次确认明确终止不可恢复、释放本笔在途报价金额，以及普通未到期项目的需求重新可被报价（包含本机构重新报价）。取消回已填原因且不改变任何业务事实；特殊组合依 Q-L7-02，不提前承诺重开报价。

**普通未到期项目的成功结果同时成立：**业务转 S-FD-10；本笔在途报价金额全额释放且不转入授信占用额；项目在途金额保持；项目由 S-FP-4 回 S-FP-2；质押不释放；需求对外回待报价。释放是本笔金额，不是清空该机构的全部在途报价金额。确认或终止均不得改变授信额度、融资上限、有效质押价值本身。

### 4.7 F-LS-50 · 放款覆盖校验及外部事件边界

提交放款时必须依据当前质押覆盖结论满足上游 INV-FIN-01；打开抽屉时的旧结果不能代替提交时校验。覆盖不足时不产生记录、不改业务状态，放款按钮不可提交并显示覆盖缺口与追加指引，核验资料仍可读，三个处置动作仍可用。资产方追加使覆盖恢复后，放款入口自动恢复，不要求资金方重新进入详情。

已接受报价的 S-FD-3/4 业务不得因覆盖变化自动失效。S-FD-4 的到账确认不增加占用，覆盖不足仍允许确认，保持覆盖不足提示与追加指引。项目到期也不终结存量 S-FD-3/4 业务：保留放款 / 确认，中性显示“已到期 · 存量处理中”，不因到期允许新报价。报价有效期在接受后不继续控制本模块。

跨平台质押 / 代币情况尚未形成可信覆盖结果时的产品阻断与恢复口径待 L5 对齐，见 Q-L7-07；不可将“未知”显示为“覆盖有余”。L7 不增设链上失败、签名或 gas 操作。

### 4.8 F-LS-51 · 交易哈希格式与自行查验

数币分支仅校验 LN-08 为 `0x` 后接 64 位十六进制字符，不判断交易是否存在、是否成功或是否到账。格式错误在字段处说明格式，不写“交易不存在”。格式正确但无真实交易不能被平台标成已核验。

ETH 是唯一链，只读展示，USDT/USDC 标为 ERC-20；区块浏览器打开相应 ETH 交易并常驻“平台未核验该交易，链接仅供自行查验”。链接不可用时不提供死链接，保留有权限者复制哈希的能力；平台外查验结果不自动确认到账。收款侧链锚定 FD-06 的原则保留，本期恒为 ETH，不制造选错链分支。

### 4.9 F-LS-52 · 放款确认与金额同步变化

**角色与前置。** 本项目资产方、S-FD-4；超期、项目到期、覆盖不足均不取消确认资格。查看放款币种、金额、资产方收款账户、发放时间与提交时间、法币凭证或数币哈希与查验链接、商务条款摘要、还款收款账户、剩余时限。发放时间标为资金方填写，提交时间标为平台记录，两者并列可辨。

先展示 F-LS-58 差额告知及选填实收金额，再提供唯一主动作“确认到账”。同一抽屉内最终二次确认告知：本人已核实款项实际到账；平台不核验；确认不可撤销，确认后进入还款并触发还款计划。未到账或尚有疑问可以取消并返回办理视图、保持待确认，转客服线下沟通，不设异议 / 驳回入口。

**成功结果同时成立。** S-FD-4 → S-FD-6，产生只读 FD-35 确认时间；以 `X = QT-03 融资金额（USD）` 同时完成下表，项目保持 S-FP-4；同时形成 L8 生成还款计划的业务依据，通知资金方。确认后不保留确认按钮。

| --- | --- | --- | --- | --- |
| 放款提交 | 不变 | 不变 | 不变 | 不变 |
| 资产方确认 | 减本笔 X | 加本笔 X | 减本笔 X | 加本笔 X |
| S-FD-3 普通终止 | 不变 | 不变 | 减本笔 X | 不变 |

转移一律按融资本金、不按实收、不按当日汇率；不改变授信额度、融资上限或质押价值。一个事件不能导致同笔金额遗漏或重复计量。示例：本金 150 万 USD、融资上限 200 万、其余融资余额为 0；放款提交后可融金额仍为 50 万，确认后也为 50 万，仅金额从项目在途转到项目融资余额。

### 4.10 F-LS-58 · 到账差额告知与实收金额

在确认动作之前常态展示、不可折叠或弱化为小字：“到账金额会少于融资金额（跨境手续费由您承担）；您需要偿还的本金仍按融资金额 {X} USD 计算。”沿用已确认手续费口径，不增加预估手续费数字、平台代收或垫付能力。

FD-39 是到账实收金额，金额业务类型、币种与 LN-03 相同，由资产方选填、默认空，仅双方可见。填与不填都能确认；不与融资金额比较、不对账、不参与本金或额度计量、不因差额显示警示色或阻断。确认后保留该笔记录。基线明确“不校验”，本版不补强成金额一致、非零或必填校验；金额类型与任意输入的表现边界待 Q-L7-04 明确。

例如融资金额 1,500,000 USD，实收 1,499,750 USD，确认正常完成，全部本金与转移仍按 1,500,000 USD。实际未到账不能因该差额规则被引导确认。

### 4.11 F-LS-53 · 放款确认时限

FD-37 到期时刻 = LN-06 成功提交时间 + 168 小时，精确到秒，是 7 个自然日，不是工作日或第七天日终；不可延长、无宽限期，不从发放时间、送达或查看时间起算。FD-38 是剩余时长，下限为 0；平时精确到小时，不足 24 小时精确到分钟并加强提示。

仍待确认时，到期前 24 小时只提醒资产方一档；到期时双方各收到一条超期通知，之后无周期推送。归零后换为中性“已超过确认时限 N 天”，FD-36 记录以 FD-37 为准的超期事实，不用通知实际到达时间。未满一天的 N 展示规则待 Q-L7-05，不影响已超期判定。

到期只改变提示与标记，不自动确认、不失效、不终止、不转移 / 释放金额、不生成还款计划、不改操作权限。确认成功后不再显示待处理倒计时；历史到期与确认时间保留。两种时限必须分别称“报价有效期”和“放款确认时限”，不得用泛称诱导用户认为到期会自动作废。详情、控制台和通知对同笔业务使用相同时间事实。

### 4.13 F-LS-55 · 还款计划与控制台交接
