# 放款与放款确认 · 消息通知

版本：V1.2｜配套 L7 V1.4｜2026-09-22。

**本模块发送六类关键站内信：放款记录已提交、确认到期前24小时提醒、确认超期、资产方已确认到账、要求重传盖章件、放款前业务已终止。** “报价已接受／进入待放款”由L6发送，L7不重发。暂不放款、重传完成和周期催办不发；本模块不新增运营广播。

事件、收件账号、时间和双语文案以本册为准；完整业务见[PRD](01-放款与放款确认-PRD.md)，同序验收见[主册验收](01-放款与放款确认-PRD.md#acceptance)，流程见[图册](02-放款与放款确认-流程图与状态机.md)。

## 1. 哪个环节发送站内信

N-LN-01～06为本文件通知编号。每条都识别原融资申请FP-28和融资业务FD-01；成功登记放款才有放款编号LN-01。一个申请可先后出现不同FD-01，消息不能改投该申请的“最新一笔”。

| 编号 | 发送节点与条件 | 收件人及次数 | 告知内容与下一步 | 业务依据 |
| --- | --- | --- | --- | --- |
| <a id="n-ln-01"></a>N-LN-01 | 资金方放款记录正式提交成功，生成LN-01并从S-FD-3进入S-FD-4 | 本笔资产方收件账号，一次 | 哪家资金方登记了哪笔放款、币种金额、提交时间及准确确认截止；自行核实到账后确认，未到账不要确认 | F-LS-49/52、D-LN-07/09/30/42 |
| <a id="n-ln-02"></a>N-LN-02 | 距本笔确认时限截止还剩24小时，仍待放款确认 | 同上，每笔一档一次 | 准确截止与未确认事实；已到账可确认，未到账先线下核实，到期不会自动确认或作废 | F-LS-53、D-LN-31～33 |
| <a id="n-ln-03"></a>N-LN-03 | 确认时限届满且尚未确认，形成FD-36确认超期事实 | 本笔资产方、放款登记资金方账号，各一条 | 已超期但业务仍待确认；两类在途金额继续占用、未生成还款计划、质押不释放；真实客服邮箱与线下核实指引 | F-LS-53/54、D-LN-34～37/42 |
| <a id="n-ln-04"></a>N-LN-04 | 资产方确认到账正式成功，FD-35与两维度金额转移成立，进入S-FD-6并触发计划生成 | 本笔放款登记资金方账号，一次 | 已确认到账、确认时间及真实计划进度；前往同笔还款信息查看，不能将生成触发说成生成完成 | F-LS-52/55、E-LN-13、L8当前计划规则 |
| <a id="n-ln-05"></a>N-LN-05 | 资金方在S-FD-3正式提出一次要求重传，原因成立，FD-31为待重传 | 本笔资产方收件账号，每次独立要求一条；成功重传后关闭本轮入口，再次要求才重新开放 | 哪笔、谁提出、何时及完整原因；查看本次要求并重传融资合同盖章件 | F-LS-47、D-LN-22/23/41 |
| <a id="n-ln-06"></a>N-LN-06 | 资金方在S-FD-3正式终止业务，业务进入S-FD-10，本笔机构在途报价金额释放等结果一致 | 本笔资产方收件账号，一次 | 终止时间、完整原因、本笔在途报价释放且尚无放款登记；旧业务不恢复，后续是否能新报价取当前项目/需求资格 | F-LS-48、D-LN-04/24～27/42 |

所有消息均以正式业务事实为依据；点击、文件上传完成、提交中或结果未知不构成成功通知。N-LN-01不另给资金方发送提交回执；N-LN-04不另给资产方发送本次确认回执；N-LN-05/06不另向发起资金方发送动作回执。

## 2. 收件账号与跨模块发送归属

### 2.1 企业业务权限不等于全员收信

<a id="n-ln-r01"></a>N-LN-R01：消息属于借贷平台面客端的自然人账号。业务允许同企业其他员工办理，不代表每个员工都应收到一封。本人消息、企业私有资料权限、当前业务办理权限分别判断，不用企业名、邮箱、钱包地址或另一平台账号代替收件归属。

| 角色 | 本模块收件范围 |
| --- | --- |
| 资产方 | N-LN-01/02/03/05/06只发送给本业务已明确关联的资产方收件账号。多成员场景继续沿Q-LS-N01统一待确认，不另猜为接受报价人、最近上传人、企业管理员或全体成员。建议与L5/L6需求类通知采用同一责任归属；该建议未获确认前不作已定实现 |
| 资金方 | N-LN-03/04发送给本笔成功提交放款记录的本平台账号，依LN-14确定，属于本笔报价机构。与L6通知原报价提交人的时点区别明确：若两次操作是不同员工，L7不同时给原报价人追加副本 |
| 运营管理人员 | 当前六类事件均不接收。业务可见权及既有线下职责不因此扩大；无运营全员、角色组或指定运营账号的新模板 |
| 游客、其他机构/资产方、其他端或同钱包的另一身份 | 不接收、不共享该条消息。同一人若有两种平台身份，按本次业务对应的账号及端隔离 |

收件归属缺失不能以当前登录者或任意同事补位。账号停用、角色改变、失去目标访问资格不自动改投他人；历史消息也不随另一人后来办理转移所有权。未定账号场景阻塞该分支收件验收，不阻塞已明确账号的其余通知需求，也不改变融资业务本身的状态和计时。

### 2.2 每个事实只有一个发送模块

| 事实 | 唯一归属与边界 |
| --- | --- |
| 报价被接受、进入待放款 | L6 N-CR-04。L7不另建“已进入放款流程”事件，不将其说成已放款 |
| 登记放款、临期、超期、到账确认、要求重传、放款前终止 | L7 N-LN-01～06；清单、控制台及消息中心只承接，不另发同义信 |
| 覆盖不足造成需求与待接受报价失效 | L5 N-LS-05合并通知；已接受的S-FD-3/4不适用这条失效，不冒用N-LN-06通知终止 |
| 到账确认与还款计划 | L7向放款登记资金方发N-LN-04；L8向资产方发计划定稿通知。计划尚未完成时，L7不等计划成功才承认到账，也不告知已生成；之后不向资金方再发同义“确认完成／计划已生成” |
| 还款登记、还款确认、逾期、结清 | L8定义其通知。融资放款清单确认到账后固定显示“已放款”，不随还款状态变化再次发L7消息 |
| 本模块超期与客服处理 | 超期由L7发面客信；展示客服邮箱是线下联系入口，不是本期新增邮件推送、运营站内待办或平台介入事件 |

## 3. 时限、防重复及真实结果

<a id="n-ln-r02"></a>N-LN-R02：确认截止FD-37为平台成功提交放款的LN-06加连续168小时，精确到秒。不从资金方自填发放时间LN-05、报价接受、送达或阅读起算；不是工作日或第七天日终。临期节点是该截止前24小时，每笔只有一档。临期判定迟到但尚未届满且仍待确认，可补一次，文案使用准确截止，不承诺“还剩24小时”；已确认或已届满不补发临期提醒。

<a id="n-ln-r03"></a>N-LN-R03：确认时限届满只产生超期事实和提醒，业务仍S-FD-4；不自动确认、失效、终止、释放/转移金额或生成还款计划，不关闭资产方确认资格。到期与确认先后以正式业务时刻为准：到期前已确认不发超期；到期时仍未确认才成立超期。晚确认的结果与期内确认一致，不能把超期说成还款逾期、违约或业务作废。

<a id="n-ln-r04"></a>N-LN-R04：补发N-LN-03前若已完成确认，不再追补“尚未确认”的超期催办；已送达的超期消息保留为历史，不撤销真实超期事实。同次重传成功后关闭本轮入口，不允许资金方再次要求前主动上传；再次正式要求才产生新通知。独立重传要求等待发送时，若该要求已完成、已被后一次要求替代，或业务已经放款/终止，不补发过时重传待办；已经送达的旧要求仍可查，不以最新原因覆盖。各次正式新要求按N-LN-05区分，单纯刷新、重复提交或补送不是新要求。通知是否补发不改变原处置历史和业务效力。

<a id="n-ln-r05"></a>N-LN-R05：同一面客账号、同一FD-01、同一通知事件只收一次；要求重传另区分每一次正式要求，临期区分固定24小时节点。同一事实重复到达不产生第二条、不重新置顶、不恢复未读、不改发生时间；不同真实节点不合并覆盖。FP-28相同但新FD-01的新业务独立通知。N-LN-03的两方是各自一条，不是共享一条企业消息。

<a id="n-ln-r06"></a>N-LN-R06：消息保留事件发生时的金额、机构、原因与时间；标题“已提交”仅表示平台登记，不代表资金已到账、已由平台核验或已上链确认。N-LN-04仅在确认及本笔金额转移成功后发送；计划是否定稿采用实际进度选择完整模板，不能靠修改状态词拼接。读信、全部已读、打开旧目标不代替确认、重传、终止或还款。

<a id="n-ln-r07"></a>N-LN-R07：放款前终止只告知已确认的本笔结果；本笔机构在途报价释放不等于项目在途金额、全部授信、质押代币或资金退款。不得在所有终止信中承诺“需求已重新开放”：按P07及主册F-LS-48，已到期项目不恢复发布或新报价；未到期项目按全部债务、在途与有效质押覆盖重判，不强制回募集中。S-FD-4后不存在终止入口，超期不能生成N-LN-06。

<a id="n-ln-r08"></a>N-LN-R08：通知失败不回滚已提交/已确认/已终止事实，不暂停168小时，不重置额度；业务页面仍可查询准确状态和时间。条件、账号、模板齐备后沿面客消息中心 IF-NC-01要求，业务事件后60秒内在消息列表及未读数一致可见。L7原超期判定“目标≤1分钟、最坏≤5分钟”保留为既有业务要求；其最坏值不能被用作60秒可见的达标证明，冲突在第7章交消息中心与L7联验时统一，不擅自把任一项删掉或相加延长。
