## P-L7-00 · 放款清单、只读详情与办理

规则回链：[F-LS-56](01-放款与放款确认-PRD.md#f-ls-56)。跨模块入口遵循 [项目查看与办理](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#interaction)；本图表达查看、办理及结果返回的业务路径，不创造融资业务状态。

```mermaid
flowchart TD
  A[接受报价，S-FD-3] --> B[放款清单每笔FD各一条记录，尚无LN]
  B -->|查看| C[只读详情：资料、账户及文件，无办理跳转]
  C -->|关闭| B
  B --> D[选择本笔及角色允许的动作]
  D --> E[进入办理，已有资料自动带入]
  E --> F[适用的最终确认在本次办理内完成]
  F -->|取消| E
  F -->|失败| E
  F -->|成功| G[更新本笔记录与办理入口，不自动打开详情]
  G --> H{业务事实}
  H -->|登记放款| I[S-FD-4及唯一LN，清单显示待放款确认]
  H -->|资产方确认到账| J[S-FD-6，放款清单显示已放款；还款信息清单入列]
  J --> K[后续还款或结清在还款信息展示；本放款行仍已放款]
  E -->|确认放弃未提交修改并关闭| B
```

清单在接受后已存在，成功登记才产生LN-01；终止历史不冒充成功放款。详情只读，办理与必要确认在本次办理内完成，不再叠加下一层办理。放款清单以资产方确认到账作为“已放款”的展示终点，后续还款事实不反向改变此展示；各业务状态机与放款记录编号不变。

## P-L7-01 · 资金方核验、处置与放款

规则回链：[入口 F-LS-56](01-放款与放款确认-PRD.md#f-ls-56)、[核验 F-LS-45](01-放款与放款确认-PRD.md#f-ls-45)、[暂缓 F-LS-46](01-放款与放款确认-PRD.md#f-ls-46)、[终止 F-LS-48](01-放款与放款确认-PRD.md#f-ls-48)、[放款 F-LS-49](01-放款与放款确认-PRD.md#f-ls-49)、[覆盖 F-LS-50](01-放款与放款确认-PRD.md#f-ls-50)、[哈希 F-LS-51](01-放款与放款确认-PRD.md#f-ls-51)。

```mermaid
flowchart TD
  A[已接受报价：S-FD-3 待放款；清单已有 FD，无 LN] --> B[本笔资金方从项目办理入口进入放款办理]
  B --> C[盖章件与商务条款核验；金额须同时可得对照，切换时保留上下文]
  C --> D{资金方决定}
  D -->|暂不放款| H[填写原因；保留 S-FD-3 和四个金额]
  H --> C
  D -->|要求重传| R[填写原因；保留 S-FD-3；进入 P-L7-02]
  R --> C
  D -->|终止业务| T[填写原因；本次办理内最终二次确认]
  T -->|取消| C
  T -->|确认成功| U[业务 S-FD-10；释放本笔在途报价金额；项目在途不变；质押不释放]
  U --> Z[交L5按当前期限、存量、债务与覆盖判定项目和需求资格；见S-L7-02]
  D -->|已在平台外付款，登记记录| F[核对只读币种金额及资产方账户；填发放时间与还款收款账户]
  F --> G{报价结算币种}
  G -->|USD| I[上传 1 至 5 个转账凭证；还款法币账户五项必填]
  G -->|USDT 或 USDC| J[填写交易哈希；ETH 只读；还款地址取绑定钱包]
  I --> K[本次办理内二次确认：记录和还款账户不可改、时限不自动确认、平台未核验]
  J --> K
  K -->|取消| F
  K -->|确认提交| V{当前业务、字段与覆盖条件满足}
  V -->|覆盖未知| WU[不登记、不伪判覆盖；保留资料，恢复真实结论或联系客服]
  WU --> C
  V -->|覆盖不足| W[无记录无状态变化；提示缺口和追加；三个处置仍可用]
  W --> C
  V -->|字段不合格| X[具体提示；保留已成功材料]
  X --> F
  V -->|已有记录或业务已变| Y[返回当前详情并说明结果]
  V -->|满足且成功| N[生成唯一 LN 并更新原 FD 行；S-FD-4；清暂缓与待重传；开始 168 小时；四个金额不变]
  N --> O[显示提交结果并通知资产方；资产方另行按 P-L7-03 核实到账]
```

核验不是审核状态；资金转账发生在平台外。覆盖校验只挡放款提交，不挡处置；重传等待不额外挡放款。覆盖未知不登记放款；执行异常联系客服，不建设异常处置流程。缺绑定钱包回既有企业账户入口，不手输替代；地区格式、精度及真实供给依赖见正文第7章。付款资料按本笔当事方受控完整读取，个人/企业档案不随之开放；金额复用L6固定1:1:1本笔快照，不重新取价。

## P-L7-02 · 要求重传与重传闭环

规则回链：[F-LS-47](01-放款与放款确认-PRD.md#f-ls-47)。

```mermaid
flowchart TD
  A[本笔资金方：S-FD-3 内要求重传并填原因] --> B[待重传标记为真；通知资产方；业务与四个金额不变]
  B --> C[资产方从项目办理入口进入重传办理]
  C --> D[查看要求和历史版本；上传新盖章件]
  D --> E{上传结果及当前业务}
  E -->|格式、大小、数量或上传失败| F[就地说明；保留已有材料；未完成重传]
  F --> D
  E -->|业务已终止| G[返回详情：已终止，不再成功重传]
  E -->|业务仍待放款、本轮要求有效且成功| H[形成新版本并保留旧版；清待重传标记、关闭本轮入口]
  H --> I[资金方核验时可看新版本；无需核验通过；不发完成通知]
  I --> J[按 P-L7-01 继续处置或放款]
  I --> Q[同次完成后不可再主动上传，旧入口不产生新版本]
  Q -->|资金方再次正式要求| A
```

重传等待期间，资金方可以改为放款或终止；重传先完成不阻止之后终止。再次独立要求可再次触发此图；历史版本始终保留。

## P-L7-03 · 到账确认、超期出口与还款交接

规则回链：[确认 F-LS-52](01-放款与放款确认-PRD.md#f-ls-52)、[实收 F-LS-58](01-放款与放款确认-PRD.md#f-ls-58)、[时限 F-LS-53](01-放款与放款确认-PRD.md#f-ls-53)、[线下出口 F-LS-54](01-放款与放款确认-PRD.md#f-ls-54)、[交接 F-LS-55](01-放款与放款确认-PRD.md#f-ls-55)、[通知 F-LS-57](01-放款与放款确认-PRD.md#f-ls-57)。

```mermaid
flowchart TD
  A[S-FD-4 待放款确认；提交成功时间起算 168 小时] --> B[资产方进入确认办理；查看金额、付款时间、凭证、账户要点与进度]
  B --> C[看差额告知；可选填实收金额]
  C --> D{资产方是否已核实到账并决定确认}
  D -->|未确认| E[保留 S-FD-4 和全部金额；可联系对方或客服]
  E --> F{当前放款确认时限}
  F -->|到期前 24 小时且仍待确认| G[仅给资产方一档提醒]
  F -->|到期仍待确认| H[中性超期标记；双方各一条通知；无状态、金额或权限改变]
  F -->|其他等待时段| B
  G --> B
  H --> I[业务详情与通知提供客服邮箱及持续占用后果；不代确认、不自动作废]
  I -->|线下核实后返回| B
  I -->|仍未确认| E
  D -->|确认| J[本次办理内二次确认：实际到账、不可撤销、进入还款]
  J -->|取消| B
  J -->|提交失败| K[保持 S-FD-4 和原金额；可再次确认]
  K --> B
  J -->|确认成功| L[S-FD-6；确认时间；两维度四个金额同时按融资本金转移；还款清单按 FD 入列并触发 L8]
  L --> M[通知资金方已确认及当前计划进度]
  L --> N{还款计划是否就绪}
  N -->|已就绪| O[由 L8 展示唯一一套定稿还款计划；主动查看还款入口]
  N -->|尚未就绪| P[展示还款计划生成中；保留已确认事实和金额]
  P -->|计划恢复就绪| O
```

覆盖不足、项目到期、确认超期均不阻断资产方确认。实收空值或差额不阻断、不改变本金；填写值仍须符合有限金额类型与已批准精度。时限为连续168小时，业务日期UTC，展示时区不改截止。长期未确认持续等待，不自动流向还款或终止。图中回到等待不表示周期推送；计划就绪不自动打开还款办理，预计计划不能充作定稿计划。

## S-L7-02 · 融资项目状态片段及融资需求展示映射

规则回链：[终止F-LS-48](01-放款与放款确认-PRD.md#f-ls-48)、[覆盖F-LS-50](01-放款与放款确认-PRD.md#f-ls-50)。项目终态仍由L5判定，本图说明本笔终止后如何消费项目结果，不新增项目状态。

```mermaid
flowchart TD
  A[本笔S-FD-3正式终止为S-FD-10] --> B[仅释放本笔机构在途报价；项目在途不因L7动作直接释放]
  B --> C[L5保留其他债务及在途，核对期限、存量、有效质押与覆盖]
  C --> D{项目是否已到期}
  D -->|已到期| E[不恢复发布或新报价，不重置期限]
  E --> F{是否还有存量}
  F -->|有| G[沿当前项目状态处理存量，标记已到期存量处理中]
  F -->|无| H[L5按既有条件判定S-FP-5或S-FP-6]
  H --> I[项目实际终态才按L5完成整体业务释放，非L7终止直接释放]
  D -->|未到期且未终态| J{当前资格事实是否可靠且满足条件}
  J -->|缺失或不满足| K[不承诺新融资，保留具体原因及原业务历史]
  J -->|满足| L[原需求有效才可按规则回待报价；原需求已终结则按L5新发布条件办理]
  L --> M[项目状态由全部剩余业务判定，不强制回募集中；新报价用新FD]
```

S-FP-2募集中只在L5当前事实满足该状态条件时出现；同项目仍有其他业务时不因本笔终止改掉其状态。原需求失效、项目在途释放或项目终态是各自独立事实，不能借图中终止节点清零整池。S-FD-4以后无终止路径。

| 业务事件 | 融资业务 | 融资需求对外显示 |
| --- | --- | --- |
| 接受报价后/暂缓/要求重传/重传完成 | S-FD-3 | 放款中 |
| 放款提交后/确认超期 | S-FD-4 | 放款中 |
| 资产方确认到账 | S-FD-6 | 已放款 |
| 放款前终止 | 原业务S-FD-10 | 由L5判定原需求是否仍有效；满足可报价条件才回待报价，不无条件重开 |

项目、需求、业务分别表达，不增第六个需求状态。放款清单确认到账后仍显示已放款，后续还款状态只在还款信息承接。项目整体业务释放与链上提取不是同一结果，L7不执行两者。
