# 放款与放款确认 · PRD

版本：L7 V1.4｜2026-09-22｜当前有效需求整理稿，待专业评审及真实联验。

让本笔资金方核对合同并登记平台外付款，由资产方核实到账后确认，衔接还款计划。适用依据为已确认的 P01～P12、付款资料与重传闭环决策及查看/办理分离、四区定位等后续反馈；布局和组件由 Hallmark 在已确认约束内决定。

## 2. 背景、目标与平台边界

L6 已完成报价接受、线下签约及盖章件上传，将业务交到 `S-FD-3 待放款`。L7 让资金方核验合同、登记其已在平台外完成的付款，再由资产方核实到账并确认，最后交 L8 生成还款计划。平台不执行转账，也不判断付款或合同真伪。

本期覆盖：盖章件核验及三个处置动作、盖章件重传、法币 / 数币放款记录、还款收款账户登记、资产方到账确认、168 小时确认时限与超期出口、通知、控制台及还款模块交接。

借贷平台拥有融资项目、授信、报价、放款与还款计划的业务事实；代币事实归代币发行平台，本模块只使用借贷平台提供的质押覆盖结论，不执行链上质押、释放或转账。资产方通过资产可信平台授权登录，资金方使用借贷平台账户体系；OIDC 接入作为登录模块既定约束引用，不在 L7 展开。

本期不提供部分或分次放款、放款记录修改 / 撤回、还款收款账户提交后修改、确认撤销、异议 / 申诉 / 驳回、运营裁决、催办、自动确认、确认展期、合同审核、链上真实性核验、提前还款。对应 X-LS-28～39 沿用；还款方式与计息规则归 L8。P04已确定SPV视同运营；本期维持两方资金链路，运营和SPV均不参与L7资金操作，不另建SPV认证、账户或审批轨道。

## 3. 角色、可见性与状态

### 3.1 角色权限

| 角色 | 可看 | 可做 |
| --- | --- | --- |
| 本笔资金方 | 公开信息及本笔双方业务资料、盖章件版本、账户、凭证、处置原因 | S-FD-3：核验、暂不放款、要求重传、终止、提交放款；S-FD-4 起无本模块写动作 |
| 本项目资产方 | 公开信息及本笔双方业务资料 | S-FD-3 且 FD-31 为真：重传；S-FD-4：确认到账，超期仍可确认 |
| 登录的非当事方 | 公开信息 | 无 L7 写动作，无双方私有资料 |
| 未登录访客 | 公开信息 | 操作区只出“立即登录”，不逐个展示禁用动作 |
| 运营人员 | 本模块不增加其资料可见权 | 无面客写动作、无裁决或代确认能力 |
| SPV机构 | 与运营人员相同，本模块不新增资料可见权 | 无代付、归集、放款登记、还款收取、终止、审批或代确认动作，不继承资金方权限 |

同一企业主体的任一已登录员工可代表该企业执行其已获角色的动作，沿用基线，不增加企业内分级授权。登录成功不等于成为某笔业务的当事方；无权者即使从通知或旧入口直达也不能读取私有内容或执行动作。

公开字段沿用 D-LN-06 及字段表明确标记：放款币种、金额、提交时间、确认时间、终止时间与原因；FD-37 到期时刻在基线字段表明确公开，沿用该单字段可见性，**不因此公开当事方轮次轨、剩余时限或新增列表筛选**。商务条款本已公开的内容按上游范围展示。

私有范围：账户 / 地址、发放时间、凭证、交易哈希与链、盖章件及历史版本、暂缓与重传原因、实收金额、放款备注、补充材料及还款收款账户，仅本笔双方可访问。下载与复制同受权限约束；通知不得携带完整私有账户或凭证。终止原因按已确认口径公开且中性呈现。

**本人档案与交易资料（L7-REV-01）<a id="l7-rev-01"></a>。** 个人、企业账户档案仅本人可查；对手方不能通过“核验资料”读取完整账户档案、证件、认证材料或私人联系方式。本笔交易必需的主体名称、合同、约定条款及付款资料按上表和字段定义提供，业务资料可见不等于整个档案可见。已有且有权用于本笔的信息自动取得，不要求用户复制或手填对方已知资料；缺失、读取中、读取失败分别展示，失败可重试，关键主体归属或必要付款资料不能确认时不放行相关提交，不用假值补齐。

普通列表及摘要保留掩码；已确认的本笔付款当事方在办理付款时能受控核对并复制所需完整账户。本笔双方的只读对账按既有权限查阅，非当事方、运营和SPV不因身份或直达入口获得完整资料。私有下载和完整值读取同样受本笔权限限制。掩码位数等未有明确依据的细项保留Q-L7-05，不能因此阻止已定的付款用途读取，也不能默认公开完整账户。

### 4.1 融资放款清单、详情与办理入口（F-LS-56）

**入口与对象。** 项目主页面左侧纵向排列的「融资放款信息」清单负责查记录；右侧固定办理区「融资」页签、控制台待办和通知负责进入当前对象的办理。所有入口落到同一笔业务、相同权限与最新状态。多笔待办先明确选择融资申请 / 业务，再从操作区进入对应办理弹窗，不能默认对第一笔提交。主页面清单、操作页签及导航遵循[项目查看与办理](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#interaction)；四区定位标签按用户后续确认滚动定位原清单，不替换纵向清单、不新增办理动作；不继续把申请、报价、放款、还款的全部资料堆入同一详情。

**入列时机与行粒度。** L6 报价被接受、进入 S-FD-3 时即进入融资放款清单，一行一笔已接受融资业务 FD-01，不能等成功提交放款后才出现。已暂缓、待重传仍在原行显示 S-FD-3 与标记；S-FD-4 显示待放款确认，超期是标记；确认后保留原记录，还款信息清单以同笔编号承接；已终止保留只读历史，不表示成功放款。资产方确认到账后，本清单的放款展示状态固定为“已放款”；后续S-FD-6还款中、S-FD-8已结清及还款逾期只在还款信息清单与对应详情表达，不回写成本放款行的状态。不新增放款业务状态、不改变到账确认或还款入列时点。

| 清单字段 | 业务含义、展示与空值口径 |
| --- | --- |
| 融资申请编号 FP-28 | 原需求编号，展示名称统一为融资申请编号；可关联该轮申请，只读，不生成新号 |
| 融资业务编号 FD-01 | 本笔已接受业务的定位依据；同一申请重新报价可出现新的业务编号，不能覆盖旧终止记录 |
| 放款编号 LN-01 | 仅成功提交放款记录后生成；待放款或放款前终止显示「尚无放款记录」，不预生成或以 FD 充作 LN |
| 资金方、融资金额、放款币种 / 金额 | 已接受商务条款的摘要；未提交时金额明确为「约定放款金额」，不伪装已实际放款 |
| 放款展示状态与标记 | S-FD-3显示待放款；S-FD-4显示待放款确认；资产方确认到账后显示已放款（后续还款中/结清不改变此展示）；S-FD-10显示已终止并保留原因。暂缓、待重传、确认超期按原阶段呈现，不新增业务状态 |
| 放款提交时间、确认时间 | 分别取 LN-06、FD-35；事件未发生显示「未提交」或「未确认」，不得填预计时间 |
| 查看与办理分工 | 清单行打开只读详情，无办理或跨业务跳转按钮；资金方放款、资产方重传/确认由右侧项目操作区按当前角色和状态提供 |

无记录时保留融资放款信息清单及空态，说明接受报价后在此查看放款业务；不得用演示记录替代。FP-28 / FD-01 / LN-01 可用于定位同一记录；只有已经生成的 LN 才可按放款编号检索。列表及详情的私有信息仍按第 3 章隔离，不因增加清单扩大可见范围。

**详情顺序。** 只用一个右侧只读抽屉承载融资放款详情。自上而下为：①放款信息（金额、业务状态、当前动作方、编号、提交 / 确认时间及既有标记；凭证或哈希按权限查看）；②资金方还款收款账户（LN-15/16，明确将来还款收款用途）；③资产方放款收款账户（LN-10，承接 L6）；④协议文件表（文件名、版本、上传时间、上传人和下载操作）。账户展示只使用 F-LS-49 的已定义字段，待放款时 LN-15/16 尚未提交则显示「待资金方提交」，不补造出账账户、不把 LN-15/16 称作实际放款出账账户。放款办理须核对的合同与商务条款在 F-LS-45 核验视图完整提供。

关联融资申请、融资业务及放款编号在详情中只读展示，不设置查看申请/还款的跳转按钮。协议点击下载，文件预览在当前读取容器内可返回；历史版本不覆盖当前版本。放款详情不复制全套申请、多轮报价和还款计划。

**办理与确认。** P-LS-07放款、P-LS-08确认到账及盖章件重传均从右侧操作区或有效待办/通知进入居中办理弹窗，不从只读详情转办。以同一业务展示“资金方放款 → 资产方确认到账”的完成情况、当前处理方及轮到您/等待对方；游客和非当事方不展示私有办理进度。放款、到账确认、终止原有最终确认保留，在本操作弹窗完成，不叠第二层；角色、信息与动作按本章，不规定字段排版。

**返回、关闭与结果。** 操作返回保留已填内容与成功材料；必要最终确认取消退回本操作，未提交改动关闭时就地确认放弃。成功刷新本笔与清单、操作区，展示真实结果，不自动打开详情或下一阶段，也不增加跨业务快捷按钮；关闭回原位置。查看只读详情时关闭直接返回，保留原筛选、分页与滚动。确认到账后放款清单显示已放款，还款区承接业务，不自动进入某一期还款。

**异常。** 旧通知或旧入口遇到已放款、已确认、已终止，仍落同一对象的当前详情并说明结果，不白屏、不静默回首页、不继续打开失效操作。游客看公开信息及立即登录；非当事方提示无操作权限且不泄露私有信息。覆盖不足仅禁用放款提交，不阻止打开核验视图。提交放款仅表明资金方已登记付款，不代表资产方确认到账。

流程参见：[P-L7-00](02-放款与放款确认-流程图与状态机.md#p-l7-00)、[P-L7-01](02-放款与放款确认-流程图与状态机.md#p-l7-01)。

### 4.2 盖章件核验区（F-LS-45）

**角色与前置。** 本笔资金方在S-FD-3从右侧操作区进入放款办理，核对本笔盖章件与已接受商务条款。提供文件读取、下载及历史版本；核对资料与本笔对应，布局由设计决定。资产方已作出的条款一致性声明及时间FD-16可读，不新增核验通过动作或平台审核状态。

九项为：融资业务编号、双方企业主体全称、融资项目编号、融资金额 USD、结算币种及结算金额、报价汇率快照及生效时间与来源、年化利率、抵押物概况、报价提交时间。均沿用 L6 已接受的商务条款，不能编辑或改取当日汇率。

核验由资金方自行判断，无“核验通过”按钮、无勾选进度、无平台合同审核状态。必须提示“平台不审核合同真伪与法律效力，请自行核验”。桌面可视区应支持盖章件金额与摘要金额同屏对照，不因进入确认步骤而丢失核验对象；容器宽度由设计决定，不再规定固定像素宽度。窄屏在同一全屏容器内切换文件与摘要并保留文件位置、版本和条款上下文，可随时返回对照，不依赖重叠弹窗完成核验；不能因压缩页面省略九项摘要或合同阅读入口。

历史版含上传时间与动作人，切换不覆盖文件。预览 / 下载失败不得显示“已核验”；现有资料是否可读不改变业务状态。依据 D-LN-20/23/58、AC-LN-03；图 [P-L7-01](02-放款与放款确认-流程图与状态机.md#p-l7-01)。

### 4.3 暂不放款（F-LS-46）

本笔资金方在 S-FD-3 可执行，覆盖不足时仍可用。原因是自由文本，必填 1～200 字，初始空，不分类。在当前办理场景填写并提交，无二次确认；具体位置与组件由设计决定。

成功后业务仍为 S-FD-3，四个金额均不变；FD-32 标为已暂缓放款，双方可见最新原因、动作人与时间，历史处置保留。资产方同时可找到客服邮箱。重复登记以最新一条呈现，不另发暂缓通知。资金方仍可直接放款、要求重传或终止；放款成功自动清除暂缓标记，无“恢复放款”前置动作。提交失败不新增成功处置；状态已变按 F-LS-56 返回。

流程参见：[P-L7-01](02-放款与放款确认-流程图与状态机.md#p-l7-01)。

### 4.4 要求重传与盖章件重传（F-LS-47）

本笔资金方在 S-FD-3 填 1～200 字原因（必填、初始空、自由文本）要求重传，无二次确认。成功后 FD-31 为待资产方重传，双方可见原因，业务、金额不变；向资产方发送一条要求重传通知。

资产方在 S-FD-3 且 FD-31 为真时从右侧操作区进入居中重传弹窗，查看要求与现有版本，上传新的盖章件。文件为 PDF / JPG / PNG、单文件不超过 10 MB、每版 1～5 个；每次成功上传形成新版本，历史不覆盖，记录上传时间与动作人。上传失败或不符格式 / 大小 / 数量时就地说明，保留其余成功上传材料，不形成完成标记。

重传成功即清除 FD-31，资金方立即能查看新版本，无需再点“通过”，不发重传完成通知。重传等待期间资金方仍可放款（须通过覆盖校验）或终止。基线不设重传次数上限、冷却；再次被要求重传后继续保留版本。**同一次要求重传成功后关闭本轮重传入口**，不得在资金方再次要求前主动继续上传；再次正式要求才重新开放。旧窗口、旧通知或重复提交不得生成第二个完成版本。E-LN-08仅适用于再次独立要求的闭环，不赋予无限期上传权。

终止先成功则后续重传不再成功，提示已终止；重传先成功不阻止资金方终止。任何并行操作不得丢失已成功版本、重复释放金额。依据 D-LN-22/23、FD-09/30/31、E-LN-06/08/09；图 [P-L7-02](02-放款与放款确认-流程图与状态机.md#p-l7-02)。

### 4.5 终止业务（F-LS-48）

### 4.8 交易哈希格式与自行查验（F-LS-51）

### 4.10 到账差额告知与实收金额（F-LS-58）

在确认动作之前常态展示、不可折叠或弱化为小字：“到账金额会少于融资金额（跨境手续费由您承担）；您需要偿还的本金仍按融资金额 {X} USD 计算。”沿用已确认手续费口径，不增加预估手续费数字、平台代收或垫付能力。

### 4.11 放款确认时限（F-LS-53）

FD-37 到期时刻 = LN-06 成功提交时间 + 168 小时，精确到秒，为连续168小时，不是工作日、七个UTC日期末或用户当地第七天日终；不可延长、无宽限期，不从发放时间、送达或查看时间起算。FD-38 是剩余时长，下限为 0；平时精确到小时，不足 24 小时精确到分钟并加强提示。

仍待确认时，到期前 24 小时只提醒资产方一档；到期时双方各收到一条超期通知，之后无周期推送。归零后换为中性“已超过确认时限 N 天”，FD-36 记录以 FD-37 为准的超期事实，不用通知实际到达时间。不足完整24小时显示“已超过放款确认时限，不足1天”，满24小时起显示已完整经过的天数，并始终可核对准确截止。此为常规展示口径，不改变超期起点；不把0天显示为尚未超期。

到期只改变提示与标记，不自动确认、不失效、不终止、不转移 / 释放金额、不生成还款计划、不改操作权限。确认成功后不再显示待处理倒计时；历史到期与确认时间保留。两种时限必须分别称“报价有效期”和“放款确认时限”，不得用泛称诱导用户认为到期会自动作废。详情、控制台和通知对同笔业务使用相同时间事实。

## 5. 展示与质量要求

已确认目标：打开放款容器到核验区可读 ≤2 秒；放款提交处理、确认处理各 ≤2 秒；确认时限届满提示 / 通知判定延迟目标 ≤1 分钟、最坏 ≤5 分钟，超期效力仍取真实到期时刻。业务金额、权限、状态以最终成功结果一致为准，不允许可观察的半成功。

所有私有材料只对本笔双方开放，换入口或猜测文件位置不能绕过权限。处置原因、合同版本、放款、确认及金额变化均可追溯到相关业务、主体、动作人和时间，不另定保存年限。

界面默认英文，可切换中文，沿用已读原型术语：Disbursement record / 放款记录、Transfer receipt / 放款凭证、Transaction hash / 交易哈希、Confirmation window / 放款确认时限、Confirm receipt / 确认到账、Amount received / 实收金额。术语应在同一场景一致，不把报价确认与放款确认混用。

**UTC日期与展示（L7-REV-05）<a id="l7-rev-05"></a>。** 业务日期、放款编号中的日期、项目期限与L8起息日使用UTC。LN-05、LN-06、FD-35、FD-37等具体时刻按用户偏好时区展示并标注，无偏好沿平台既有展示规则；游客按浏览器时区并标注。日期字段明确为UTC业务日期，不能因查看者跨日、夏令时或切换语言重算。确认时限仍连续168小时，时区切换不延长。

金额显示币种与千分位，USD两位；代币数量的展示规则与资金结算精度分别处理，完整交易金额依本笔批准精度和锁定值，不能用缩略或六位展示截断实际付款数。账号/地址/哈希摘要脱敏，有权者按付款、对账用途读取和复制完整值；私人身份档案不随之开放。掩码细则、数币正式精度和实收允许范围等剩余项见第7章。

暂缓原因、终止原因、确认超期、“已到期 · 存量处理中”使用中性展示；不足 24 小时的确认时限强化提示不等于把超期显示为违约。字段错误说明具体缺失或格式；不出现暗示平台已审核 / 已核验 / 自动确认 / 承诺介入的文案。

业务规则通过状态与交互体现；融资申请、业务与放款编号按 F-LS-56 展示，不要求面客页面展示内部条款号、字段来源论证、规则推导，不添加审阅模式。只在必要处清楚区分“资金方填写的发放时间”和“平台记录的提交时间”。
