## 2. 背景、目标与平台边界

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

L6 完成报价接受后把业务交到 `S-FD-3 待放款`；接受环节不再上传合同盖章件，授信协议改为非必填。L7 让资金方登记其已在平台外完成的付款，再由资产方核实到账并确认，最后交 L8 生成还款计划。平台不执行转账，也不判断付款或合同真伪。

本期覆盖：法币 / 数币放款记录登记、还款收款账户选用、资产方到账确认、两类核心通知、控制台及还款模块交接。

借贷平台拥有融资项目、授信、报价、放款与还款计划的业务事实；代币事实归代币发行平台，本模块只使用借贷平台提供的有效质押额结论，不执行链上质押、释放或转账。资产方通过资产可信平台授权登录，资金方使用借贷平台账户体系；OIDC 接入作为登录模块既定约束引用，不在 L7 展开。

## 3. 角色、可见性与状态

### 3.1 角色权限

| 角色 | 可看 | 可做 |
| --- | --- | --- |
| 本笔资金方 | 公开信息及本笔双方业务资料、已接受商务条款、账户、凭证 | `S-FD-3`：提交放款，为本模块唯一写动作；`S-FD-4` 起无本模块写动作 |
| 本项目资产方 | 公开信息及本笔双方业务资料 | `S-FD-4`：确认到账，不设时限 |
| 登录的非当事方 | 公开信息 | 无 L7 写动作，无双方私有资料 |
| 未登录访客 | 公开信息 | 唯一可办理的动作是立即登录，不逐个展示禁用动作 |
| 运营人员 | 本模块不增加其资料可见权 | 无面客写动作、无裁决或代确认能力 |
| SPV机构 | 与运营人员相同，本模块不新增资料可见权 | 无代付、归集、放款登记、还款收取、审批或代确认动作，不继承资金方权限 |

本期一个企业只有一个员工账号，由该账号代表企业执行其已获角色的动作，不开放企业内员工管理或分级授权。登录成功不等于成为某笔业务的当事方；无权者即使从通知或旧入口直达也不能读取私有内容或执行动作。

公开字段沿用 D-LN-06 及字段表明确标记：放款币种、金额、提交时间、确认时间。商务条款本已公开的内容按上游范围展示；**不公开当事方轮次轨，也不新增列表筛选**。

私有范围：账户 / 地址、发放时间、凭证、交易标识与结算收款链、实收金额、放款备注、补充材料及还款收款账户，仅本笔双方可访问。下载与复制同受权限约束；通知不得携带完整私有账户或凭证。

**本人档案与交易资料（L7-REV-01）<a id="l7-rev-01"></a>。** 个人、企业账户档案仅本人可查；对手方不能借核对本笔资料读取完整账户档案、证件、认证材料或私人联系方式。本笔交易必需的主体名称、约定条款及付款资料按上表和字段定义提供，业务资料可见不等于整个档案可见。已有且有权用于本笔的信息自动取得，不要求用户复制或手填对方已知资料；缺失、读取中、读取失败分别展示，失败可重试，关键主体归属或必要付款资料不能确认时不放行相关提交，不用假值补齐。

普通列表及摘要保留掩码；已确认的本笔付款当事方在办理付款时能受控核对并复制所需完整账户。本笔双方的只读对账按既有权限查阅，非当事方、运营和 SPV 不因身份或直达入口获得完整资料。私有下载和完整值读取同样受本笔权限限制。掩码位数等未有明确依据的细项保留 Q-L7-05，不能因此阻止已定的付款用途读取，也不能默认公开完整账户。

## 4. 功能需求

<a id="f-ls-56"></a>
### 4.1 融资放款清单、详情与办理入口（F-LS-56）

**入口与对象。** 「融资放款信息」清单负责查记录；项目办理入口、控制台待办和通知负责进入当前对象的办理。所有入口落到同一笔业务、相同权限与最新状态。多笔待办先明确选择融资申请 / 业务，再进入对应办理，不能默认对第一笔提交。清单与办理入口遵循[项目查看与办理](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#interaction)；项目内的定位方式只用于找回原清单，不新增办理动作；不把申请、报价、放款、还款的全部资料堆入同一详情。

**入列时机与记录粒度。** L6 报价被接受、进入 `S-FD-3` 时即进入融资放款清单，每笔已接受融资业务 `FD-01` 各为一条独立记录，不能等成功提交放款后才出现。`S-FD-4` 显示待放款确认；确认后保留原记录，还款信息清单以同笔编号承接。资产方确认到账后，本清单的放款展示状态固定为“已放款”；后续 `S-FD-6` 还款中、`S-FD-8` 已结清及还款逾期只在还款信息清单与对应详情表达，不回写成本放款记录的状态。不新增放款业务状态、不改变到账确认或还款入列时点。

| 清单字段 | 业务含义、展示与空值口径 |
| --- | --- |
| 融资申请编号 FP-28 | 原需求编号，展示名称统一为融资申请编号；可关联该轮申请，只读，不生成新号 |
| 融资业务编号 FD-01 | 本笔已接受业务的定位依据；同一申请重新报价可出现新的业务编号，不覆盖既有记录 |
| 放款编号 LN-01 | 仅成功提交放款记录后生成；待放款时显示「尚未提交放款记录」，不预生成或以 FD 充作 LN |
| 资金方、融资金额、放款币种 / 金额 | 已接受商务条款的摘要；未提交时金额明确为「约定放款金额」，不伪装已实际放款 |
| 放款展示状态 | `S-FD-3` 显示待放款；`S-FD-4` 显示待放款确认；资产方确认到账后显示已放款（后续还款中 / 结清不改变此展示）。本模块不再有终止、暂缓、待重传、确认超期等标记 |
| 放款提交时间、确认时间 | 分别取 `LN-06`、`FD-35`；事件未发生显示「未提交」或「未确认」，不得填预计时间 |
| 查看与办理分工 | 清单记录打开只读详情，不承载办理或跨业务跳转；资金方放款、资产方确认由项目办理入口按当前角色和状态提供 |

无记录时保留融资放款信息清单及空态，说明接受报价后在此查看放款业务；不得用演示记录替代。`FP-28 / FD-01 / LN-01` 可用于定位同一记录；只有已经生成的 LN 才可按放款编号检索。列表及详情的私有信息仍按第 3 章隔离，不因增加清单扩大可见范围。

**详情顺序。** 融资放款详情一次完整给出下列信息，顺序为：①放款信息（金额、业务状态、当前动作方、编号、提交 / 确认时间；凭证或交易标识按权限查看）；②资金方还款收款账户（`LN-15/16`，明确将来还款收款用途）；③资产方放款收款账户（`LN-10`，承接 L6）；④本笔已接受商务条款摘要；⑤协议文件（授信协议为非必填，缺失时说明本笔未提供，不显示待上传或待审核）。账户展示只使用 [F-LS-49](#f-ls-49) 的已定义字段，待放款时 `LN-15/16` 尚未提交则显示「待资金方提交」，不补造出账账户、不把 `LN-15/16` 称作实际放款出账账户。

关联融资申请、融资业务及放款编号在详情中只读展示，不提供查看申请 / 还款的跳转动作。协议可直接下载；提供文件预览时不改变当前查看对象、可返回原对象。放款详情不复制全套申请、多轮报价和还款计划。

**办理与确认。** `P-LS-07` 放款与 `P-LS-08` 确认到账从项目办理入口或有效待办 / 通知进入办理，不从只读详情转办。以同一业务展示“资金方放款 → 资产方确认到账”的完成情况、当前处理方及轮到您 / 等待对方；游客和非当事方不展示私有办理进度。放款与到账确认各自的最终确认在本次办理内完成，不再叠加下一层办理。

**返回、关闭与结果。** 操作返回保留已填内容与成功材料；最终确认取消退回本操作，未提交改动关闭时就地确认放弃。成功刷新本笔记录、清单与办理入口，展示真实结果，不自动打开详情或下一阶段，也不增加跨业务快捷入口；关闭后回到来源并保留原筛选、分页与所在位置。查看只读详情时关闭直接返回来源。确认到账后放款清单显示已放款，还款信息清单承接业务，不自动进入某一期还款。

**异常。** 旧通知或旧入口遇到已放款、已确认，仍落同一对象的当前详情并说明结果，不白屏、不静默回首页、不继续打开失效操作。游客看公开信息及立即登录；非当事方提示无操作权限且不泄露私有信息。有效质押额不足仅阻断放款提交，不阻断查看本笔资料。提交放款仅表明资金方已登记付款，不代表资产方确认到账。

流程参见：[P-L7-00](02-放款与放款确认-流程图与状态机.md#p-l7-00)、[P-L7-01](02-放款与放款确认-流程图与状态机.md#p-l7-01)。

确认成功时，L7 提供确定的确认事实、融资本金 `QT-03`（USD）、报价汇率 `QT-04`、结算币种 / 金额、`LN-06` 提交时间、`FD-35` 确认时间及 `LN-15/16` 还款收款账户。L8 承接计划生成、还款方式、期数、计息、还款确认与余额递减。按 L8 已定规则，起息日取 `LN-06` 的 UTC 日期，计划生成触发 / 定稿事实取 `FD-35`；`LN-05` 不用于计息。还款开窗与逾期标记按 L8 当前规则执行；还款确认时限已随本批取消，期次结清由资金方在还款确认入口执行，本模块不扩展提前还款能力。

## 5. 展示与质量要求

已确认目标：打开放款办理到本笔条款与账户可读 ≤2 秒；放款提交处理、确认处理各 ≤2 秒。业务金额、权限、状态以最终成功结果一致为准，不允许可观察的半成功。本模块不再有任何到期判定，原“超期判定延迟目标”一并取消。

所有私有材料只对本笔双方开放，换入口或猜测文件位置不能绕过权限。放款、确认及金额变化均可追溯到相关业务、主体、动作人和时间，不另定保存年限。

界面默认英文，可切换中文，沿用已读原型术语：Disbursement record / 放款记录、Transfer receipt / 放款凭证、Transaction ID / 交易标识、Confirm receipt / 确认到账、Amount received / 实收金额。术语应在同一场景一致，不把报价环节与放款确认混用；“Confirmation window / 放款确认时限”随时限取消而废止。

**UTC日期与展示（L7-REV-05）<a id="l7-rev-05"></a>。** 业务日期、放款编号中的日期、项目期限与 L8 起息日使用 UTC。`LN-05`、`LN-06`、`FD-35` 等具体时刻按用户偏好时区展示并标注，无偏好沿平台既有展示规则；游客按浏览器时区并标注。日期字段明确为 UTC 业务日期，不能因查看者跨日、夏令时或切换语言重算。本模块不再有任何截止时刻或剩余时长。

金额显示币种与千分位，USD 两位；代币数量的展示规则与资金结算精度分别处理，完整交易金额依本笔批准精度和锁定值，不能用缩略或六位展示截断实际付款数。账号 / 地址 / 交易标识摘要脱敏，有权者按付款、对账用途读取和复制完整值；私人身份档案不随之开放。掩码细则、数币正式精度和实收允许范围等剩余项见第 7 章。

“已到期 · 存量处理中”使用中性展示；字段错误说明具体缺失或格式；不出现暗示平台已审核 / 已核验 / 自动确认 / 承诺介入的文案。长期未确认按 [F-LS-54](#f-ls-54) 中性表达，不使用逾期、违约或失效措辞。

业务规则通过状态与交互体现；融资申请、业务与放款编号按 [F-LS-56](#f-ls-56) 展示，不要求面客页面展示内部条款号、字段来源论证、规则推导，不添加审阅模式。只在必要处清楚区分“资金方填写的发放时间”和“平台记录的提交时间”。

沿用的业务观察口径：M-LS-32 放款转化、M-LS-33 接受到放款时长、M-LS-38 放款币种分布、M-LS-39 确认后金额不一致、M-LS-40 待确认期间因错误释放造成可融金额异常。后两项应为 0；不因此新增运营看板、催办或 SPV 权限。原 M-LS-34～37 随确认时限、处置动作与终止取消而废止，见[第 8 章](#retired)。

### 7.2 按用户决定保留的业务限制

以下三项是用户 2026-09-24 裁定后的既定结果（简报第 7 节），此处如实记录其业务后果，供研发与测试知悉，不作为异议保留。

| 限制 | 业务后果 |
| --- | --- |
| 平台不再采集与校验收款人名称 | 法币与数币账户均取消收款人名称，原“收款账户须属本企业”的硬校验一并删除。受益人名称由业务双方在平台外补充；平台不再具备该项自动校验能力，本册也不得以其他字段变相恢复 |

同理，`S-FD-4` 在资产方确认前也没有其他出口：无时限、无自动确认、无终止，业务停留期间两类在途金额持续占用，见 [F-LS-54](#f-ls-54)。
