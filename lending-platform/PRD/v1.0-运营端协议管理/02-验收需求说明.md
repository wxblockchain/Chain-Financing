V1.2 · 2026-09-21。测试主阅读文件；与[功能需求](./01-功能需求说明.md#functions)共用稳定需求编号，范围和未完成依赖见[主册](./v1.2-运营端协议管理-PRD.md#questions)。以下要求用于产品行为验收，不表示真实系统已通过。

<a id="acceptance"></a>
## 4. 验收需求说明（测试主阅读入口）

按 M1～M6 顺序验收，均以本端有效运营账号为管理侧角色；涉及维护、发布分别具备对应权限；历史仅管理员，记录对正常账号固定可读。公开当前读取场景包含借贷业务端和游客，并验证其无法读取历史。另两平台使用同规格进行独立实例验收；不能只验证本端操作成功，就认定三平台独立成立。Q-O-AG-* 未关闭的分支分别标记待裁定，不判作通过，也不阻止验证其余已确定能力。以下是业务验收要求，不是详细执行用例。

| AC-O-AG-102 | F-O-AG-05：同一协议不同状态下主入口均为更新协议；有待生效时打开即为该版本，不先撤销、不新建 |

### 4.3 M3 发布与生效

前提：有查询和发布权限，草稿已满足字段规则；包含无旧版本、有旧生效版本及有待生效版本三类背景。规则正文：[3.3](./01-功能需求说明.md#m3)，关联 F-O-AG-06。

| 编号 | 场景与预期结果 |
| --- | --- |
| AC-O-AG-37 | 立即发布后新版本生效，原生效版本自动归档 |
| AC-O-AG-38 | 任意可观察时刻至多一个生效版本，替换不出现临时无版本 |
| AC-O-AG-39 | 定时发布后为待生效；到时无需运营打开页面即可生效，原版归档 |
| AC-O-AG-40 | 任意时刻至多一个待生效版本，不建立待生效队列 |
| AC-O-AG-41 | 有待生效点击更新协议直接载入其内容和计划；确认弹窗显示同一版本及修改前后内容，无撤销并发布提示 |
| AC-O-AG-42 | 确认调整仍定时时，同一版本采用最新文件和计划，原计划不再触发；历史列表不增行；取消或失败全部保持原样 |
| AC-O-AG-43 | 草稿定时发布及待生效确认调整为定时时，距提交少于 5 分钟被拒、恰为 5 分钟有效；不因只改文件而绕过时间要求 |
| AC-O-AG-44 | 不同时区表示同一计划时刻，均有时区标注，切换时区不更改计划 |
| AC-O-AG-45 | 撤销只在更新页二次确认后退回同一编号草稿，保留已确认文件、取消计划；有其他草稿时阻断，不覆盖资料 |
| AC-O-AG-46 | 定时失败保留旧生效版，首版明确无生效内容；更新仍调整该失败待生效版本，无需先撤销，可改计划或立即生效 |
| AC-O-AG-47 | 已生效与归档文件及凭据固定；待生效各次确认保留真实前后记录，普通账号只读业务摘要，旧文件仅管理员可读；生效冻结最终内容。 |
| AC-O-AG-48 | 有对应权限的同一人可维护并发布，无强制第二角色复核 |
| AC-O-AG-92 | 发布或确认更新均校验文件、非空说明、500 字符及计划时间；确认内容与将正式采用的版本和变更一致 |
| AC-O-AG-93 | 首版待生效时管理侧显示待生效，公开读取仍暂无生效版本；调整原版本不变成另一首版，到点成功才公开 |
| AC-O-AG-104 | F-O-AG-06：待生效编辑期间若原计划先使其生效，旧表单确认更新或撤销被拒；已生效文件不被覆盖 |
| AC-O-AG-105 | F-O-AG-06：待生效确认改为立即后本版本立即生效、旧生效版归档、原定时计划结束，编号不变 |
| AC-O-AG-106 | F-O-AG-06：确认更新同时改变文件与时间时要么全部成功，要么保持原版本；重复提交不新增版本或重复生效 |
| AC-O-AG-107 | F-O-AG-05/06：撤销与取消编辑分别说明后果；前者经确认取消计划，后者只丢弃未提交内容；异常双草稿冲突不静默覆盖 |
| AC-O-AG-115 | F-O-AG-06/10：有无当前生效版本、正常及失败待生效计划下线均直接取消未完成计划，到原时点不再执行；无需运营手动撤销。 |
| AC-O-AG-116 | F-O-AG-06/10：下线后原生效版归档，草稿/待生效标已取消，未生效者无实际生效时间；原文件、计划及下线取消原因可留存追溯。 |
| AC-O-AG-117 | F-O-AG-06：下线后旧编辑/发布/调整/撤销提交不可成功；若到点已先生效则保留事实再下线归档，不出现下线后恢复为当前。 |
| AC-O-AG-118 | F-O-AG-06/10：下线结果失败或未知不伪报成功；恢复读取后按真实状态展示，不产生虚假取消/生效记录。 |
| AC-O-AG-119 | F-O-AG-05/06：重新上线是独立新协议、初始未发布；旧协议编号、文件、计划和记录均不继承，创建发布按新对象校验。 |

| 编号 | 场景与预期结果 |
| --- | --- |
| AC-O-AG-49 | 历史为四列简表：版本号、状态、生效时间、操作；详细字段只在版本详情展示，按版本号倒序 |
| AC-O-AG-50 | 查看进入独立 P-O-AG-04 只读详情；下载取选定版本文件；无文件不可下载；预览失败可重试或下载 |

| AC-O-AG-53 | 不提供手动归档动作；另一版本成功生效或协议下线时自动归档原生效版本，实际生效记录不被篡改。 |
| AC-O-AG-108 | F-O-AG-07：简表不展开说明、人员、文件大小、归档时间等；查看在独立详情展示全信息，返回保留历史页签和位置 |
| AC-O-AG-109 | F-O-AG-07/10：有全部写权限的账号在历史及版本详情仍只能查看、下载，不出现更多菜单藏写操作；无文件下载说明明确 |
| AC-O-AG-120 | F-O-AG-07：专员即使具查询、维护、发布或误配历史权限，完整历史入口、旧链接、预览与下载均不可读；当前及办理所需工作版本仍按查询权可达。 |
| AC-O-AG-121 | F-O-AG-07/10：下线或移除定义后管理员仍可定位旧对象读取留存；同名新对象和同号 v1 不覆盖旧对象，旧链接不重定向新对象。 |

| 编号 | 场景与预期结果 |
| --- | --- |
| AC-O-AG-54 | 版本写动作、待生效确认调整、系统生效/归档/失败都留下对应记录；每次调整可核对前后业务摘要，不因同版本号覆盖历史事实；旧文件读取另限管理员 |
| AC-O-AG-55 | 操作进度表含操作、版本、操作人、时间、结果、摘要；人员邮箱脱敏、IP仅地区；改邮箱不改写历史操作归属 |
| AC-O-AG-56 | 系统自动生效和归档明确显示“系统”，不冒记为发布人手动执行 |
| AC-O-AG-57 | 操作记录在基本信息协议定义下方以列表展示，无独立记录页签；正常运营全员可读，不可改删；记录入口不依赖 PM-AL-09 或 PM-AL-12。 |
| AC-O-AG-58 | 文件替换含旧新文件名，计划调整含旧新时间或方式；撤销与取消编辑区别清楚，未提交不记成功变更 |
| AC-O-AG-110 | F-O-AG-09：操作进度覆盖原协议全部版本，默认20条、倒序；无数据、加载失败、登录失效分别表达；无查询权的正常账号仍能读取记录。 |
| AC-O-AG-111 | F-O-AG-06/09：同版本的多次待生效调整分别留痕，正常账号能核对旧新文件名和时间，旧文件内容仅管理员可读；不把调整留痕伪装成多个待生效版本 |
| AC-O-AG-122 | F-O-AG-09：无查询/消息权专员仍可读所有协议记录，不按经办人或机构过滤；游客、面客、其他端及异常账号不得读取。 |
| AC-O-AG-123 | F-O-AG-09/10：记录含原对象、实际动作与执行方、时间、结果、摘要及关联版本；无版本的下线不造版本；自动取消/归档标系统。 |
| AC-O-AG-124 | F-O-AG-09：普通记录读者看不到旧正文、内容凭据、文件地址或附件；从记录跳转旧文件按管理员历史权复核，无权可返回原记录。 |

| 编号 | 场景与预期结果 |
