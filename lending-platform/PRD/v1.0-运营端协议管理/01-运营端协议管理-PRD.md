# 运营端协议管理 · PRD

版本：V1.3｜日期：2026-09-22｜运营管理平台 · 运营端｜状态：当前需求稿，真实未决项见[依赖与待决](#questions)。本版仅把原有四份文件重组为三册并统一引用方式，功能与验收编号沿用 V1.2，业务规则未变。

## 1. 目标与阅读入口

运营人员按权限查看本平台预置协议的用途，从统一的“更新协议”入口维护草稿或调整唯一的待生效版本，立即或定时生效，并查询版本历史与操作进度；本平台业务端与游客始终能明确取得当前生效版本。

本期包含：协议定义的只读展示与检索、协议文件内容维护、发布与定时生效、待生效版本调整与撤销、协议下线后的留存与重新上线、版本历史与版本详情、操作进度留痕、当前生效版本的公开读取、协议事件告知。相邻模块负责：运营账号、会话与功能权限配置（运营端账户与登录）；站内消息的页面、未读语义与可见范围（运营端消息通知）；面客侧的协议勾选、同意记录与重新同意流程（各消费模块）；语言、时区、脱敏等口径（三平台共享国际化基线）。

本期不包含：在线富文本编辑、协议正文多语种版本、运营自助创建协议或协议类型、历史版本回溯创建、手动归档生效版本、审批复核、同意记录页面、强制重新同意流程、协议邮件、面客交互设计、跨平台总控台。协议清单与面客使用位置由对应业务先行明确，运营端只维护内容与版本；“服务协议、隐私政策”等仅是类别示例，不是已批准的上线清单。

有效依据：需求方 2026-09-21 四点反馈（先 PRD 后原型；基本信息单列、删右侧版本区；精简历史、详情另看；操作进度置于基本信息；统一“更新协议”入口、历史仅查看下载、在唯一待生效版本上调整）；需求方 P12 裁定（协议下线由建设方直接取消、重新上线作为全新协议、历史版本仅管理员可读、操作记录本端全员可看）；P04（SPV 与运营同一主体）与 P10（统一业务日期）裁定。最新用户确认优先于旧 PRD 与原型；原型中的演示数据、评审控件和临时处理不作为已确认需求。

阅读顺序：共同业务规则 → 完整功能 → 同序验收 → 依赖与待决。

配套（须共同阅读）：[流程图与状态机](02-运营端协议管理-流程图与状态机.md)、[消息通知](03-运营端协议管理-消息通知.md)。

## 2. 共同业务规则

<a id="d-o-ag-01"></a>
### 2.1 平台独立与单一规格（`D-O-AG-01`）

| 规则 | 产品含义 |
| --- | --- |
| 规格只有一份 | 本册有效功能及配套规则被运营管理平台、代币发行平台、资产可信平台三个实例共同引用；不各写一套草稿、发布、历史与验收规则。其他实例若有已确认差异，须集中登记并确认，不能据旧文档自行分叉 |
| 内容各自维护 | 三个实例各有自己的协议定义、文件、版本历史、当前生效版本、操作记录和消息；同名协议或相同标识不表示共用内容 |
| 标识本平台内唯一 | 协议标识上线后不可变；另一平台有相同标识不构成冲突，不要求运营人员添加平台前缀 |
| 生效各自独立 | 本端发布、撤销、定时生效、失败或下线，均不改变另两平台的版本、文件、消息或业务端读到的内容；其他平台的变化也不影响本端 |
| 单端使用 | 本端列表、管理入口与读取能力只服务本端协议域，不提供平台列、筛选器、切换器或跨平台批量读取 |
| 身份不继承 | 本端登录或授权不能直接取得另两平台的管理权限；SPV 同主体不代表跨平台授权，也不代表已获本模块所有权限 |
| 面客归属 | 本体为运营管理平台维护、借贷面客端消费；另两平台只消费各自实例。运营管理平台的最终部署与目录归属不由本册新增裁定 |

本册页面编号沿用本端 `P-O-AG-01`～`P-O-AG-04`；其他平台的实际页面编号由各自登记，跨文档引用须同时带平台与需求出处，不能把本端页面当作跨平台目标。

<a id="d-o-ag-02"></a>
### 2.2 角色与准入（`D-O-AG-02`）

“运营人员”指本端正常、已完成首登改密且登录有效的运营管理员与运营专员。SPV 沿同一角色体系，不新增独立账号、机构过滤、资金操作或跨平台权限。账号与授权由运营端账户与登录承接，本模块不新增人员或授权管理功能。

| 阅读或动作 | 权限及结果 | 不包含的能力 |
| --- | --- | --- |
| 当前协议基本信息、当前生效内容、草稿与待生效工作版本 | `PM-AL-09`；维护或发布任一开通须配套本项 | 不包含历史内容、下线前旧版本和已被调整替换的文件 |
| 更新内容、保存/丢弃草稿、填写待生效调整 | `PM-AL-10`，并具 `PM-AL-09` | 不能单独确认待生效调整或发布 |
| 发布、确认待生效调整、主动撤销待生效 | `PM-AL-11`，并具 `PM-AL-09`；修改并确认内容或计划还须 `PM-AL-10` | 仅发布者可发布已保存草稿或撤销计划，不可修改内容 |
| 历史版本、下线留存版本及旧文件的预览与下载 | 仅运营管理员具 `PM-AL-15` | 专员即使具查询、维护和发布权，或被误配历史权，仍不可读取 |
| 协议操作记录及业务记录字段 | `PM-AL-16` 对正常管理员与专员固定开放；不依赖 `PM-AL-09` 或 `PM-AL-12` | 不包含协议正文、旧文件或修改能力；不按本人经办或机构过滤 |
| 协议事件站内信 | `PM-AL-12`；按运营端消息通知的合法消息范围读取 | 不替代目标版本、历史文件或记录的准入 |

管理员固定具有本期业务权限；专员的可配置项沿运营端账户与登录。只有记录权也必须有可达的协议记录入口，不能因缺查询权隐藏整个模块；此时仅提供识别原协议所需的名称、标识、下线情况及操作记录，不返回无权查看的完整定义或正文。共享账户菜单展示本人当前邮箱与真实角色，不能由展示文字取得权限。

未登录、登录失效、待首登改密或账号锁定时不开放受保护记录及内容，按账户模块引导；有效账号无目标权限时说明限制并保留原入口返回。内容查询、历史读取、记录读取分别判定，进入页面、下载文件及从记录或消息跳转都不得绕过。游客、面客及其他平台账号不属于“全员”。公开当前协议按[当前生效版本与公开读取（F-O-AG-11）](#f-o-ag-11)，不开放公开历史。

## 3. 功能需求

<a id="f-o-ag-01"></a>
### 3.1 协议定义、列表与检索（`F-O-AG-01`～`F-O-AG-03`）

运营人员从一级菜单“协议管理 / Agreements”进入协议列表（`P-O-AG-01`）；仅记录可读者同样可到达记录入口，页面只展示其授权信息；列表行或“查看”进入协议详情（`P-O-AG-02`）。详情保留“基本信息、版本历史”两个业务入口，版本历史仅管理员开放；首次从列表进入默认基本信息；刷新及前进后退保留当前页签。标题区使用统一主入口“更新协议 / Update agreement”，不再随草稿状态改名。基本信息按整页单列从上到下展示“协议定义”“操作进度”，不再设置右侧当前版本或待生效计划卡，也不保留独立操作记录页签。此处协议基本信息指当前所选协议的定义，不是另一个版本摘要。当前及工作版本须有可达的只读查询入口，按 `PM-AL-09` 进入版本详情（`P-O-AG-04`）；历史入口仅管理员可达。具体当前查询承载由设计决定，不恢复右侧版本区，不以历史入口限制阻断专员合法办理。返回列表保持已应用筛选、排序、页码、滚动位置及触发行焦点。流程见[按对象读取与统一更新入口（FL-O-AG-01）](02-运营端协议管理-流程图与状态机.md#fl-o-ag-01)。

**协议定义字段**全部只读，运营端不提供新增、编辑、下线、删除协议及类型的入口。下表“必填”指协议定义的完整性，不是运营可编辑表单；没有提供的默认值不能补成真实业务值。

| 业务信息 | 含义与业务类型 | 必填与校验 | 默认值 |
| --- | --- | --- | --- |
| 协议标识 | 文本；引用协议的固定标识 | 必填；本平台内唯一；上线后不可变；字符和长度限制未定，见[协议定义供给（Q-O-AG-05）](#q-o-ag-05) | 无 |
| 类型编码、类型中英文名称 | 文本；分类与筛选依据 | 均必填；取本平台定义，不能套用他平台类型清单 | 无 |
| 协议中英文名称 | 文本；按界面语言显示协议名 | 均必填；只表示界面名称双语，不表示文件分语种 | 无 |
| 协议说明 | 文本；供运营理解用途 | 可选；不对外公开；长度限制未定，见[协议定义供给（Q-O-AG-05）](#q-o-ag-05) | 空 |
| 使用环节 | 触点列表；每项含编码及中英文名 | 必填；明确本平台业务端用在哪些环节；实际清单及字段限制见[协议定义供给（Q-O-AG-05）](#q-o-ag-05) | 无 |
| 允许文件格式 | 格式列表；本协议可上传的格式 | 必填；按协议逐项明确；需要在线阅读的使用环节应选择可在线呈现的格式 | 无全局兜底 |
| 文件大小上限 | 文件容量；上传可接受的最大大小 | 必填；按协议明确值及单位，上传区展示；未明确不得上线 | 无全局兜底 |
| 上线状态 | 二值；已上线 / 已下线 | 必填；运营只读；已下线仍保留历史 | 无 |
| 排序值 | 数值；定义默认列表顺序 | 可选；缺值时顺序及数值范围未定，见[协议定义供给（Q-O-AG-05）](#q-o-ag-05) | 未定 |

协议定义及业务端适配由研发随既定配置发布提供（基线 §7.1 的既定约束，本册不展开实现）。新定义可用后以“未发布”出现在列表。缺格式或大小上限的定义不得上线、不显示为可用条目。已下线协议标记“已下线”，取消既有未完成计划并停止当前内容使用，全部维护与发布动作不可执行，详见[协议下线、留存与重新上线](#offline)。移除定义不删除历史版本及操作记录：当前业务查询可不再展示该定义，公开读取为“协议不存在”，但管理侧仍有按原协议定位的留存入口。管理员可查看原定义必要留存信息和历史文件；其他正常运营账号可定位并查看操作记录，不能借留存入口读取旧正文。重新上线作为全新协议显示“未发布”，不恢复旧对象。

**列表与交互**：表格列为协议名称/标识、类型、使用环节、当前生效版本、生效时间、版本数、状态、最近更新、查看。无当前生效版本或从未操作的值显示“—”；版本数不含草稿。使用环节超过 3 项折叠为“+N”，可展开完整清单；详情完整展示。存在待生效版本时显示其版本号与计划时间，不能把它作为当前生效版本。

| 列表展示状态 | 判定优先级与含义 |
| --- | --- |
| 已下线 / Offline | 定义为已下线，优先于版本状态 |
| 已生效 / Active | 已上线且有已生效版本；同时有草稿或待生效版本不改变主状态 |
| 待生效 / Scheduled | 已上线、无已生效版本、存在待生效版本；当前版本仍为“—”，不得标成已生效 |
| 草稿 / Draft | 已上线、无已生效和待生效版本、有草稿 |
| 未发布 / Unpublished | 已上线、无任何版本 |

关键词同时模糊匹配中英名称与标识，忽略大小写、前后空格。类型、使用环节、状态为多选；更新时间按最近操作时间及运营人员时区筛选。不同条件取交集，同条件多选取并集。“查询”应用条件，“重置”清空并回第 1 页；日期区间的端点及单侧输入规则见[协议定义供给（Q-O-AG-05）](#q-o-ag-05)。

默认按定义排序值，再按最近更新时间倒序；生效时间、版本数可排序。默认每页 20 条，可切 50、100；刷新、浏览器前进后退保留筛选与分页。加载显示占位、失败可重试且保留条件；尚无定义显示“暂无协议，协议由系统预置”，筛选无结果显示“没有符合条件的协议”及重置入口。均无新建协议入口。

<a id="f-o-ag-04"></a>
### 3.2 更新协议与内容维护（`F-O-AG-04`～`F-O-AG-05`）

适用角色与前提：协议为当前已上线对象、运营人员完成准入且具 `PM-AL-09`。下线留存对象不可继续编辑或发布；重新上线的新对象从空白首版开始。协议详情（`P-O-AG-02`）标题区的“更新协议”统一进入更新协议页（`P-O-AG-03`）；有维护或发布权限者进入其获授权的办理模式，仅查询者不出现更新入口。更新指协议内容和计划，协议定义仍不可编辑。历史列表及版本详情没有更新入口。

| 进入时的协议情况 | 更新对象与默认内容 | 结果约束 |
| --- | --- | --- |
| 有待生效版本 | 直接载入这一个待生效版本的文件、说明、生效方式、计划时间和标记；页面明确显示版本号与待生效状态 | 不创建另一版本，不先撤销为草稿，不出现“撤销并发布”或覆盖另一草稿的流程 |
| 无待生效，有未完成草稿 | 继续该草稿，入口仍叫“更新协议” | 不创建第二个草稿 |
| 无待生效、无草稿，有当前生效版本 | 生成下一编号草稿，复制当前生效文件，变更说明为空；默认立即生效、重新同意标记为否 | 当前生效文件保持原样，更新只发生在新草稿 |
| 从未有版本 | 创建空白首份草稿 | 保存可暂缺文件，发布必须完整 |

有维护权限才能编辑内容。仅有发布权限者进入现有草稿的只读发布模式，或待生效版本的只读计划处置模式；无可处置版本时不创建空草稿，说明“暂无可发布内容”。“更新协议”不是自动授权入口；调整待生效文件、说明、时间或生效方式并正式确认，必须同时具有维护与发布权限。

同一当前已上线协议最多一个草稿、一个待生效、一个已生效版本；正常更新流程的草稿与待生效是同一待完成版本的先后阶段，有待生效时不再生成并行草稿。若既有数据同时存在草稿和待生效，优先调整待生效，保留另一草稿且不自动发布或覆盖；需要撤销而将出现两个草稿时阻断撤销，提示先处理冲突，不静默丢弃资料。

**文件规则**：单文件，支持点击、键盘选择与拖拽；一个版本只对应一个当前文件，无语种选择或正文编辑。格式、大小按本协议定义；改扩展名伪装、空文件和一次选多个文件均拒绝。大小等于上限可接受，超过才拒绝。错误具体说明该协议实际限制；已上传区显示原始文件名、大小、上传时间、替换和下载。上传有进度，失败保留原文件及输入，可重试。

草稿反复替换不生成新版本，替换成功后旧草稿文件不保留。调整待生效时，新选文件与其他改动在“确认更新”成功前只是本次未提交内容，不能改变已确认文件或既有生效计划。原文件和原计划继续有效；离开页面不会暂停定时任务。已生效、已归档内容始终不可就地修改。

| 业务信息 | 含义与业务类型 | 必填、可编辑与校验 | 默认值 |
| --- | --- | --- | --- |
| 版本号 | 文本，形如 v1、v2；标识该内容版本 | 系统生成、只读；新建采用从未使用的下一编号；待生效调整或撤销再发保持该版本号；丢弃编号不复用 | 现有草稿/待生效取原值；新建自动递增 |
| 协议文件 | 文件；协议正文或模板 | 草稿保存可缺；发布或确认待生效更新必须成功上传并符合本协议限制；只有维护权限可替换 | 按上表载入 |
| 生效方式 | 枚举：立即生效 / 定时生效 | 发布或确认更新必填；修改需维护权限，正式提交另需发布权限 | 新草稿为立即；待生效沿用定时 |
| 计划生效时间 | 时间点；分钟粒度 | 定时发布或调整后仍定时时必填；提交时须至少晚于当前时间 5 分钟，恰为 5 分钟有效；按账号时区输入并标注 | 新草稿为空；待生效载入原计划 |
| 变更说明 | 文本；说明这次内容或计划变化 | 草稿保存可缺；发布或确认更新去空白后非空，最多 500 字符；待生效调整沿用后可改，确认弹窗另列实际变化 | 新草稿为空；待生效载入原说明 |
| 需重新同意 | 是/否标记 | 可选；仅保留并随公开版本提供，不触发任何面客动作 | 新草稿否；待生效沿用原值 |

**草稿模式**：提供“保存草稿”“发布”“丢弃草稿”，按权限开放。保存允许缺文件、说明、计划时间，但已填内容仍受格式和 500 字符上限约束；成功停留编辑页并提示保存成功。发布按[发布、待生效调整与生效](#f-o-ag-06)。丢弃需在丢弃确认（`C-O-AG-02`）中确认，取消无变化；移除草稿与草稿文件但不影响已生效或归档内容。曾由待生效退回的版本，其已确认过的调整与撤销记录继续保留。

**待生效模式**：主操作为“确认更新 / Confirm update”，无“保存草稿”“新建另一版本”“丢弃待生效”。需维护、发布两项权限，未改动时不可重复提交。已有“撤销待生效”能力移至本页次级操作，由发布权限控制，单独二次确认。取消编辑/离开与撤销计划明确区分：前者只放弃未提交输入，后者才取消已确认计划。有维护但无发布权限者可准备表单与校对文件，但不能正式保存待生效调整；页面明确告知此权限限制，不伪装成成功保存。

**异常与边界**：编辑页离开有未提交内容时确认，取消则留在原页，确认才放弃本次输入。草稿或待生效版本被他人修改后，后提交的旧表单被拒并提示刷新；失败保留可重试输入。刷新将丢弃输入时先确认。正在提交时不重复执行。待生效已到点变为已生效时，禁止用旧表单覆盖，提示“该版本已生效，请返回协议详情后更新协议”；本次输入可供复制核对，但不自动变成已生效内容或另一已发布版本。

流程见[按对象读取与统一更新入口（FL-O-AG-01）](02-运营端协议管理-流程图与状态机.md#fl-o-ag-01)，状态见[单个版本状态机（ST-O-AG-01）](02-运营端协议管理-流程图与状态机.md#st-o-ag-01)。

<a id="f-o-ag-06"></a>
### 3.3 发布、待生效调整与生效（`F-O-AG-06`）

发布已保存草稿需查询和发布权限；提交表单中的内容变化还需维护权限。文件、说明、时间均做完整校验；缺文件定位上传区，其他错误定位对应字段。不要求第二人复核，但不得用发布权限绕过内容维护权限。

发布确认（`C-O-AG-01`）对草稿使用“发布确认”，对待生效使用“确认更新”；均展示协议名称、版本号、文件名与大小、生效方式和带时区的时间，以及需重新同意标记的无面客行为说明。待生效调整额外展示变化前后的文件名、计划时间、生效方式和说明；未变化项无需重复对照。确认后按完整成功结果执行，取消则不改变已确认内容和计划。成功返回协议详情（`P-O-AG-02`）的“基本信息”并更新操作进度；当前及工作版本按查询权进入只读的版本详情（`P-O-AG-04`），管理员还可从版本历史进入，不恢复右侧版本卡。

| 场景 | 成功结果与边界 |
| --- | --- |
| 草稿立即发布 | 本版本成为已生效；原已生效版本同时自动归档；实际生效时间为本次成功发布时刻 |
| 草稿定时发布 | 本版本成为唯一待生效；原生效版本不变；首版定时等待期间公开读取仍为暂无生效版本 |
| 待生效调整后仍定时 | 在同一待生效版本上确认新文件、说明或时间；版本标识与版本号不变；新确认的计划整体替代原计划，原时间不再触发生效；不新增历史版本行、不把原版退回草稿 |
| 待生效改为立即生效 | 确认提示将立即替换当前生效版本；成功后该待生效版本直接变已生效，旧生效版本归档，原定时计划结束；版本号不变 |
| 到时自动生效 | 按最近一次确认成功的内容和时间生效，原已生效版本同时归档；不以运营人员打开页面为条件 |
| 主动撤销待生效 | 仅在更新协议页执行；撤销确认（`C-O-AG-02`）明确版本号、计划时间及后果。确认后退回同一编号草稿、保留文件并取消计划，当前已生效版本不变；不能将未提交的编辑内容顺带保存。已有其他草稿的异常数据不得覆盖，按[更新协议与内容维护](#f-o-ag-04)阻断处理 |
| 调整提交失败或校验失败 | 既有待生效版本文件和计划全部保持原样；当前生效不变，页面说明失败并保留输入；不能一部分采用新文件、一部分仍用旧计划 |
| 编辑期间到点生效 | 如果到时生效已先完成，确认更新或撤销必须拒绝，转为只读处理并提示返回；如果调整先确认成功，则只按新计划生效。两种结果必须明确，不出现生效后被旧表单改写 |
| 定时生效失败 | 保留待生效记录，显示失败提示，旧生效版本不变；首版仍无当前生效版本；记录失败并发站内信。点击更新协议仍调整该待生效版本，可重新设定未来时间或选择立即生效，无需先撤销 |

同一协议任意时刻最多一个待生效、一个已生效版本。正常替换已有生效内容不得出现同时两份生效或暂时无生效版本的中间结果。有待生效时所有更新入口都复用该版本；旧的“另建草稿→撤销并发布→原待生效退回”替换链路不再使用。

版本号只在所属协议内计数；重新上线新协议的首个草稿从 v1 开始，与旧协议同号不代表同一版本。版本号在新建草稿时分配，后续编辑、保存、定时、调整、撤销再发均不改变该对象编号；新建版本使用更大且从未用过的编号，丢弃后允许编号空档，不能人工指定或复用。已生效、已归档及下线已取消对象的留存内容和凭据固定；仍已上线的待生效版本允许经授权确认调整，每次确认的文件、内容凭据、时间和操作者保留可追溯的调整记录，供按权限查阅，不能覆盖掉前一次确认事实。生效时冻结最终实际生效的文件与凭据，后续管理员历史读取不会变成曾被替换的待生效文件。旧调整文件属于历史内容，读取须管理员具 `PM-AL-15`，记录查看权本身不足。

计划按同一真实时刻判断，切换时区只改变显示，不改变时间。基线“切换偏差不超过 60 秒”保留为目标值。下线与计划或编辑相遇按[协议下线、留存与重新上线](#offline)处理，不采用暂停后恢复原计划的演示假设。

通知触发见[协议事件告知](#d-o-ag-03)；流程见[草稿发布与原待生效版本调整（FL-O-AG-02）](02-运营端协议管理-流程图与状态机.md#fl-o-ag-02)，状态见[单个版本状态机（ST-O-AG-01）](02-运营端协议管理-流程图与状态机.md#st-o-ag-01)。

<a id="offline"></a>
### 3.4 协议下线、留存与重新上线（`F-O-AG-06`、`F-O-AG-07`、`F-O-AG-09`～`F-O-AG-11` 的下线口径）

依据需求方 P12 裁定，下线由建设/研发侧执行，运营端不新增上下线按钮、审批或人工撤销步骤。用户所述“开发层面直接取消”作为既定约束保留，本节只定义用户可观察的结果。

| 场景 | 产品结果 |
| --- | --- |
| 下线成功 | 原协议停止对外提供当前内容；全部待生效计划直接取消，到原计划时间也不会生效；原草稿和待生效版本结束办理并只读留存，不退回可编辑草稿、不等待恢复 |
| 原来已有生效版本 | 下线后不再是当前可用版本，转为已归档，保留原实际生效时间、文件和归档时间；不是运营手动归档 |
| 原草稿或待生效版本 | 标记“已取消”，原状态、原计划和取消原因在详情与记录可查；从未生效的版本实际生效时间为空，不伪造已生效或已归档经历 |
| 定时失败后再下线 | 原失败事实保留，未完成计划按下线取消；不可再次尝试原计划，不将取消报告成定时失败或成功 |
| 编辑、发布、撤销或到点与下线相遇 | 下线结果成立后不能再成功保存、发布、确认更新或执行旧计划；旧表单显示协议已下线并提供返回，未提交输入不自动转为新协议。若生效已先成功，则保留该次真实生效记录，再按下线归档；下线后不出现旧内容重新成为当前可用版本 |
| 下线处理未成功或结果未明 | 不展示已下线/已取消成功；说明结果尚未确认，重新读取可信状态；不把未确认结果写成成功记录或通知 |
| 移除定义 | 保留原协议身份与必要历史上下文；管理员历史和全员记录仍可按原对象定位。公开业务不再取用原内容，不因定义消失把历史删除或误指新协议 |
| 重新上线 | 建设方提供完整的新协议定义，成为独立新协议，初始未发布、无当前版本、无待生效计划及旧草稿；首次更新创建空白 v1，文件与说明重新准备，发布仍按既定校验 |
| 新旧对象区分 | 新协议具有独立协议与版本标识；名称或用途相同也不继承旧协议文件、版本序列、待生效计划、操作记录或消息归属，不以“恢复旧版”或旧版本复制创建代替全新上线 |
| 旧链接与留存 | 旧版本、旧记录和旧消息仍指向原协议；管理员按历史权读取，正常专员按记录权读取，内容无权时说明并返回；绝不自动转到同名新协议或其 v1。用户已下载的文件不在本模块追删范围 |

“已取消 / Cancelled”仅表示本对象因下线终止的草稿或未生效版本，是只读终态；与运营主动撤销待生效不同，后者在已上线协议内退回同号草稿。下线留存仍按原版本号倒序；重新上线新对象单独计数，旧记录不能混入新对象记录列表。

下线的留痕包括原协议、关联版本（如有）、原计划（如有）、发生时间、实际执行方、结果及原因“协议下线”；无版本的定义下线可不填版本并显示“—”，不得造 v0 或版本。自动取消/归档显示“系统”，不得冒记为某运营人员。旧记录和文件永久保留、不可篡改，但可读范围分别按 `PM-AL-16` 与 `PM-AL-15`；不把留存等同公开。

流程见[下线、旧对象留存与全新上线（FL-O-AG-06）](02-运营端协议管理-流程图与状态机.md#fl-o-ag-06)，协议对象状态见[协议对象的上线与下线（ST-O-AG-02）](02-运营端协议管理-流程图与状态机.md#st-o-ag-02)，单版本状态见[单个版本状态机（ST-O-AG-01）](02-运营端协议管理-流程图与状态机.md#st-o-ag-01)。

<a id="f-o-ag-07"></a>
### 3.5 版本历史与版本详情（`F-O-AG-07`；`F-O-AG-08` 已取消）

协议详情（`P-O-AG-02`）的“版本历史”仅管理员具 `PM-AL-15` 可进入，使用精简列表，按版本号倒序，保留草稿、待生效、已生效、已归档及下线已取消记录；当前已生效行突出显示。列表只用于辨认版本并打开内容，不在每行铺开全部元数据，也不采用一版一张大卡。历史入口中的各状态行只允许查看、下载。专员不进入完整历史列表；有 `PM-AL-09` 时可从当前内容查询入口读取当前生效及办理所需的草稿/待生效版本，进入相同的版本详情（`P-O-AG-04`）只读页，不能浏览归档、下线留存或已被替换的调整文件。

| 列 | 展示与空值 |
| --- | --- |
| 版本号 | v{n}，本协议内唯一；待生效多次调整仍只占一行 |
| 状态 | 草稿、待生效、已生效、已归档、已取消；失败的待生效在同格追加“生效失败”，不另造版本状态 |
| 生效时间 | 待生效显示最近确认的计划时间并标“计划”；已生效/归档显示实际生效时间；草稿与已取消且从未生效的版本为“—”，原计划到详情和记录查看；均带时区 |
| 操作 | 仅“查看”“下载协议”；尚无文件时下载不可用并说明原因，查看仍可用 |

不在简表展示文件大小、变更说明、归档时间、来源版本、操作人或内容凭据；这些内容进入版本详情统一查看。版本历史内没有更新、编辑、发布、撤销、丢弃、删除、手动归档、回溯及“以此新建版本”，空态也不出现这些写入口；需维护内容时回到协议详情标题区“更新协议”。已有功能权限不改变这个操作范围。

版本详情（`P-O-AG-04`）是独立只读页，关联指定协议与版本，不能用当前生效内容冒替被查看版本。页面展示版本号、状态、版本标识、所属协议、文件名、格式、大小、上传时间、生效方式、计划/实际生效时间、归档时间、最近草稿保存时间及保存人、首次发布时间及发布人、最近确认调整时间及操作人、变更说明、需重新同意标记、内容凭据；适用字段尚无值用“—”，不适用字段可省略，不虚构人或时间。来源版本仅对管理员在已有历史关联时只读呈现；不再提供从来源复制创建。

| 业务信息 | 含义、类型与校验 |
| --- | --- |
| 协议标识、版本标识及版本号 | 系统提供的文本；必有、只读；必须对应打开的对象 |
| 版本状态 | 草稿、待生效、已生效、已归档、已取消；由[发布、待生效调整与生效](#f-o-ag-06)决定，不能手动修改 |
| 文件信息 | 文件实际名称、格式、容量、上传时间；系统提供、只读；草稿或已取消对象原无文件时为空 |
| 最近草稿保存、首次发布、最近确认调整 | 时间点及对应人员；只读；尚未保存、发布或调整时不填造对应时间，历史曾经发生的动作仍保留；邮箱脱敏 |
| 生效、归档、取消时间 | 带时区的时间点；待生效计划与实际生效明确区分；未发生的时点为空；已取消需有真实取消时点、原状态和下线原因，原计划仅曾定时者有值 |
| 内容凭据 | 对应所展示文件的凭据；只读、可复制；待生效标明“尚未生效，仍可经确认调整”，已生效及归档固定 |
| 来源版本 | 可选历史关联；仅管理员在已有数据有值时显示并支持只读查看，不是新建入口 |

文件可在线呈现则提供预览和下载，不支持则说明并下载；预览失败可重试或下载，无文件对象明确“尚未上传文件”。返回时保留原协议和来源：管理员历史入口恢复页签、列表位置与触发行焦点；当前查询、操作记录或消息入口则返回原来源，不能把专员带入历史列表；页面刷新及浏览器前进后退保留指定版本。加载失败可重试，对象不存在或无权限须给出明确提示与有效返回路径，不能默认为第一条样本。详情页除内容查看、复制凭据、下载及返回外，无写操作。

历史版本回溯创建（`F-O-AG-08`）已取消，编号保留、不迁作其他功能；已经存在的历史来源关联、文件及操作记录不得因入口移除而删除。管理员可正常下载历史文件，但系统不提供一键恢复旧版本的动作。已生效版本在另一版本成功生效或本协议下线时自动归档，无手动归档入口。已下线及移除定义后的历史由管理员从原协议留存入口读取，规则见[协议下线、留存与重新上线](#offline)，不恢复旧协议办理能力。流程见[当前查询、管理员历史与原来源返回（FL-O-AG-03）](02-运营端协议管理-流程图与状态机.md#fl-o-ag-03)。

### 3.6 操作进度与留痕（`F-O-AG-09`～`F-O-AG-10`）

协议详情（`P-O-AG-02`）的“基本信息”按单列顺序展示：上方协议定义、下方“操作进度 / Activity”。不单设“操作记录”页签，不使用时间线侧栏；这里表达该协议已发生的操作与结果，不新建审批流或虚构完成百分比。列表覆盖全部版本，不只取当前生效版本。

| 列 | 业务含义与展示 |
| --- | --- |
| 操作 | 实际业务动作；包括创建/保存草稿、上传或替换、丢弃、发布、确认待生效调整、撤销、系统生效、系统归档、定时生效失败、协议下线及关联取消 |
| 版本 | 本次动作关联的版本号；版本动作必有；无版本的定义下线为“—”；始终关联原协议，不能只靠 v1 等同号辨认新旧协议 |
| 操作人 | 实际姓名及掩码工作邮箱；自动动作显示“系统 / System”，不冒记为发布人 |
| 操作时间 | 动作发生的时间点，带时区；按时间倒序，最新一条在上 |
| 结果 | 成功 / 失败；取消确认、仅打开页面和未提交输入不记成功变更；定时失败明确失败 |
| 变更摘要 | 一句话说明实际变化，长内容可展开；替换含旧、新文件名；调整含变化前后计划/生效方式；撤销说明计划取消并退回草稿 |

记录为只读、系统生成；时间、动作、原协议、执行方、结果、摘要均必有，版本按上表条件必填。人工动作采用发生时的姓名与掩码邮箱作可读归属，后续改邮箱不改写已经发生的记录；系统动作不填造邮箱。来源审计约束沿基线，用户仅查看地区摘要，不展示完整 IP。待生效确认调整的记录可核对当次确认前后的文件名、计划和说明；普通运营人员仅核对业务变更摘要；旧文件正文、预览、下载和内容凭据仅管理员具 `PM-AL-15` 可见。不得将正文、附件或可取文件的地址复制到记录字段中绕过历史权限；当前工作文件另按 `PM-AL-09`。记录仅显示脱敏业务身份，不链接他人账户档案。正常未发布草稿的反复替换仍按[更新协议与内容维护](#f-o-ag-04)，不要求保留每一次草稿文件。

默认每页 20 条，可选 50/100；无记录显示“暂无操作记录”；加载失败只影响本区块并可重试，不将失败当作无记录。日期排序不因人员语言或时区改变实际先后。`PM-AL-16` 对本端正常管理员与专员固定开放，不依赖协议查询或消息权限。无 `PM-AL-09` 者仍可从记录入口查看本协议全部业务记录，仅呈现识别原对象所需的名称、标识、状态和记录，不带出完整协议定义、正文或历史文件；其具体承载由设计决定。账号不正常或登录失效按账户准入处理，不伪装成空记录。

记录只增不改、永久保留，所有已生效与归档文件永久保留不可改删，历史仅管理员可读；下线已取消对象及已确认调整留存同样受历史权限控制。已有回溯或旧替换动作的历史记录仍原样保留，但不再据此提供相应操作入口。实际执行同样必须拒绝越权、更改定义、覆盖已生效内容或篡改操作记录；不能只靠页面隐藏入口。记录读取与内容权限边界见[按对象读取与统一更新入口（FL-O-AG-01）](02-运营端协议管理-流程图与状态机.md#fl-o-ag-01)，发布及调整结果见[草稿发布与原待生效版本调整（FL-O-AG-02）](02-运营端协议管理-流程图与状态机.md#fl-o-ag-02)。

### 3.7 当前生效版本与公开读取（`F-O-AG-11`）

本平台业务端及游客可按协议标识读取当前生效版本，可一次取得多份或按类型取得已上线协议的当前生效版本，不提供公开指定历史版本回看；归档、下线留存和旧调整内容仅管理员在管理端读取。本模块只定义取到什么与异常结果；面客页面、勾选、同意记录及重新同意流程由对应需求负责。

| 情形 | 可观察结果 |
| --- | --- |
| 已上线、有当前生效版本 | 取得本平台该版本的协议名、标识、类型、使用环节、版本标识及版本号、文件信息与文件、固定内容凭据、生效与发布时间、需重新同意标记 |
| 草稿或待生效 | 不作为当前版本返回；外部直接指定版本或尝试访问文件也不能得到未生效内容 |
| 已归档、下线留存、已取消或旧调整文件 | 不公开提供；直接指定历史版本或旧文件地址同样不可读，不能借当前协议读取能力绕过管理员历史权 |
| 标识未定义、已下线、暂无生效版本、指定版本不存在或不属于可公开的当前版本 | 分别可识别为“协议不存在”“协议已下线”“暂无生效版本”“版本不存在”；不表现为成功的空白文件 |
| 读取失败 | 需要用户同意的环节不得以“没有协议”静默放行；当前显示版本过期时不能按旧版完成应以当前版本为准的确认，应刷新后重试，具体面客交互由消费模块定义 |
| 其他平台同名或同标识 | 始终取本平台版本；本平台无可用版本也不借用另两平台版本兜底 |

公开内容不含内部说明、运营人员身份、操作记录或未生效草稿；不附加正文语种、在线富文本或平台切换能力。“需重新同意”仅是保留的业务标记，本期不能据此弹窗、通知或强制阻断老用户。

既有读取字段映射和内容凭据约束引用基线 §9，消息契约引用既有接入指南并由运营端消息通知承接跨平台调整；本册不复制报文、参数、算法或访问路径。基线规定当前版本切换后消费方最迟 5 分钟更新显示；提交同意等关键确认须针对当前生效版本，不能以该展示更新窗口绕过版本一致性要求。下线后不提供当前内容；重新上线尚未发布时仍为暂无生效版本，不从旧协议补取。公开历史拒绝，不以版本存在性提示泄露非公开内容；管理员历史读取走管理侧授权。流程见[公开当前版本读取（FL-O-AG-04）](02-运营端协议管理-流程图与状态机.md#fl-o-ag-04)。

### 3.8 协议事件告知（`D-O-AG-03`）

本模块负责事件何时发生及通知内容，运营端消息通知负责消息页、可见范围、未读和跳转。仅向本端运营人员的共享消息范围发送；实际查看仍需 `PM-AL-12`，每人独立已读，不投递给资产方、资金方或另两平台账号，不因 SPV 职责新增消息池。

### 3.9 展示、安全与质量（`N-O-AG-01`）

界面默认英文、支持中英即时切换；完整规则引用三平台共享国际化基线，切换不清空表单、不改变文件内容。关键术语采用 Agreements/协议管理、Draft/草稿、Scheduled/待生效、Active/已生效、Archived/已归档、Cancelled/已取消、Unpublished/未发布、Offline/已下线、Save draft/保存草稿、Publish/发布、Update agreement/更新协议、Confirm update/确认更新、Version details/版本详情、Activity/操作进度。

所有时间带时区；长名称、标识和文件名可查看完整值，内容凭据可复制；共享脱敏规则适用于记录和通知。桌面 1280、1440、1920 像素下操作列可达、无页面横向溢出；更窄时保留关键操作。支持 Chrome、Edge、Firefox、Safari 最近两个大版本；中英文均无错位和信息丢失。键盘可完成操作、焦点可见、状态含文字，浮层焦点不移到背景，关闭后恢复；错误与进度对辅助阅读可感知，减少动效偏好有效。

文件呈现不能执行其中的恶意内容或泄露非公开文件；不合法格式不得仅凭改名通过。既定文件安全与访问约束引用基线 §12.2，保持其安全目标，本册不扩展实现。基线性能目标沿用：20 条列表首屏及详情 P95 小于 1.5 秒、业务端当前版本读取 P95 小于 300 毫秒、下载首字节 P95 小于 800 毫秒、定时切换偏差不超过 60 秒。均为观察及校准目标，不冒充已测结果，也不提升为未确认的发布门槛。

## 4. 验收需求

与第 3 节同序。每条验收映射到对应功能，与功能正文冲突时以功能正文为准；本节给出业务行为与可观察结果，不含测试执行步骤与用例数据。

**全章适用的业务前提**：均以本端有效运营账号为管理侧角色，涉及维护、发布分别具备对应权限；历史仅管理员，记录对正常账号固定可读。公开当前读取场景包含借贷业务端和游客，并验证其无法读取历史。另两平台使用同规格进行独立实例验收；不能只验证本端操作成功，就认定三平台独立成立。[依赖与待决](#questions)中未关闭的分支分别标记待裁定，不判作通过，也不阻止验证其余已确定能力。
