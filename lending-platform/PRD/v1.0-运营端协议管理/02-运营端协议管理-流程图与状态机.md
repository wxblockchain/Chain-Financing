<a id="fl-o-ag-01"></a>
## FL-O-AG-01 按对象读取与统一更新入口

回指[协议定义、列表与检索](01-运营端协议管理-PRD.md#f-o-ag-01)、[更新协议与内容维护](01-运营端协议管理-PRD.md#f-o-ag-04)、[操作进度与留痕](01-运营端协议管理-PRD.md#f-o-ag-09)。记录、当前内容和历史权限分开判定；正常专员无内容查询权也能读取记录。

```mermaid
flowchart TD
    A[本端运营账号进入协议模块] --> B{账号正常 已改初始密码且登录有效}
    B -->|否| C[按账户状态引导 不开放受保护内容]
    B -->|是| D[可达原协议操作记录 PM-AL-16]
    D --> E[读取原对象识别及业务记录摘要]
    B -->|是| F{要读取的内容}
    F -->|当前内容及工作版本| G{具 PM-AL-09}
    F -->|历史或下线留存| H{管理员且具 PM-AL-15}
    G -->|否| I[说明无权 保留合法记录阅读]
    H -->|否| I
    H -->|是| J[历史只读查看下载 见 FL-O-AG-03]
    G -->|是| K[查看当前协议及工作版本]
    K --> L{当前已上线且具维护或发布权}
    L -->|否| M[只读 不开放更新]
    L -->|是| N[统一更新协议]
    N --> O{已有待生效版本}
    O -->|是| P[载入原待生效版本 不暂停计划]
    O -->|否| Q{已有草稿}
    Q -->|是| R[载入原草稿]
    Q -->|否且有维护权| S[当前对象创建下一编号草稿]
    Q -->|否且仅发布权| T[无可发布内容 不创建草稿]
    S --> R
    P --> U[按权限办理 见 FL-O-AG-02]
    R --> U
```

协议定义与操作进度同属基本信息、须同时可得且先定义后进度。仅记录可读时不带出完整定义、正文和文件。新上线对象无旧内容可复制，从空白 v1 起；同一已上线对象的常规下一版仍沿原更新规则。

<a id="fl-o-ag-02"></a>
## FL-O-AG-02 草稿发布与原待生效版本调整

回指[发布、待生效调整与生效](01-运营端协议管理-PRD.md#f-o-ag-06)。确认待生效调整需查询、维护和发布权；发布已保存草稿或撤销计划可仅具查询及发布权。

```mermaid
flowchart TD
    A[更新协议] --> B{当前对象}
    B -->|草稿| C[准备内容或只读发布已有内容]
    B -->|待生效| D[调整原版本文件 说明及计划]
    C --> E[发布确认]
    D --> F[确认更新 展示前后变化]
    D --> G[取消编辑或离开]
    G --> H[确认放弃未提交输入 原计划继续]
    E --> I{最终提交仍符合权限 字段 时间及状态}
    F --> I
    I -->|否| J[拒绝 说明原因 保留可核对输入]
    I -->|是| K{提交结果}
    K -->|失败| L[已确认文件与计划保持 不伪报成功]
    K -->|成功且立即| M[本版本生效 旧生效版归档 原计划结束]
    K -->|成功且定时| N[同一版本唯一待生效 使用最新确认内容]
    N --> O{计划到点且协议仍已上线}
    O -->|实际生效成功| P[本版本生效 旧版归档 留痕并告警]
    O -->|实际生效失败| Q[保留待生效及原生效版 失败留痕并告警]
    O -->|已下线| R[原计划已取消 不执行 不发定时结果]
    Q --> A
    B -->|主动撤销待生效| S[单独二次确认]
    S -->|取消| H
    S -->|仍已上线可撤销且无草稿冲突| T[同号退回草稿 保留已确认文件 取消计划 留痕并告警]
    S -->|已生效 已下线或草稿冲突| J
```

取消确认、失败或未提交修改不改变已确认文件和计划。办理期间如到点生效先成功，旧内容不可覆盖已生效内容；下线已成立则旧的办理提交不可继续。调整成功后只按新计划运行，版本历史不增加另一个待生效版本。图中三处告警分别对应[定时生效成功告警](03-运营端协议管理-消息通知.md#nt-o-ag-01)、[定时生效失败告警](03-运营端协议管理-消息通知.md#nt-o-ag-02)、[待生效计划撤销告警](03-运营端协议管理-消息通知.md#nt-o-ag-03)。

## FL-O-AG-03 当前查询、管理员历史与原来源返回

回指[版本历史与版本详情](01-运营端协议管理-PRD.md#f-o-ag-07)。历史版本回溯创建（`F-O-AG-08`）已取消，本图只表达现行只读流程；“版本详情”是信息域，不指定其承载形式。

```mermaid
flowchart TD
    A[从当前查询 历史 记录或消息进入原版本] --> B{目标此时属于哪类内容}
    B -->|当前或工作版本| C{具 PM-AL-09}
    B -->|归档 下线留存或旧调整内容| D{管理员且具 PM-AL-15}
    C -->|否| E[说明无权 不展示正文预览或文件]
    D -->|否| E
    C -->|是| F[版本详情 读取指定原版本]
    D -->|是| F
    F --> G{取数结果}
    G -->|失败| H[说明取数失败 可重试]
    G -->|对象确实不可得| I[说明目标不可用 不跳同名新对象]
    G -->|成功| J[只读展示完整版本信息]
    J --> K{文件情况}
    K -->|可预览| L[只读预览 下载原文件]
    K -->|不支持或预览失败| M[说明情况 可重试或下载]
    K -->|无文件| N[说明尚未上传 不提供空下载]
    E --> O[回到原来源 保留原筛选分页与所在位置]
    I --> O
    J --> O
```

版本历史仅管理员可进入，只承载版本号、状态、生效时间与查看/下载动作，完整信息在独立只读的版本详情；全部写权限也不能在版本历史中恢复、发布或删除。专员合法当前查询不经过版本历史。原来源为消息或记录时回到该来源并保留所在位置，不能把无历史权者带入版本历史；旧地址始终指向旧对象。

## FL-O-AG-04 公开当前版本读取

回指[当前生效版本与公开读取](01-运营端协议管理-PRD.md#f-o-ag-11)。公开读取只服务本平台当前生效内容，历史由管理侧单独授权。

```mermaid
flowchart TD
    A[本平台业务端或游客请求协议] --> B{请求是否为公开当前内容}
    B -->|否 归档旧版本或旧文件| C[不公开提供 不泄露非公开内容]
    B -->|是| D{当前定义可用情况}
    D -->|不存在或已移除| E[协议不存在]
    D -->|已下线| F[协议已下线]
    D -->|已上线| G{当前对象有生效版本}
    G -->|否| H[暂无生效版本 不取旧对象或其他平台兜底]
    G -->|是| I[展示当前文件与对应信息]
    I --> J{业务要求按当前版本确认}
    J -->|否| K[只读阅读]
    J -->|是| L{确认时仍为当前有效内容}
    L -->|是| M[按消费业务规则继续]
    L -->|否| N[重新读取当前内容后重试]
    E --> O[需同意环节不得静默放行]
    F --> O
    H --> O
```

重新上线的新协议未发布时不继承旧内容。显示更新窗口不允许关键确认使用失效版本。需重新同意标记仅是保留的业务标记，本期不由此新增面客流程或通知。

<a id="fl-o-ag-05"></a>
## FL-O-AG-05 事件告知、阅读及目标权限

回指[协议事件告知](01-运营端协议管理-PRD.md#d-o-ag-03)与[消息通知册](03-运营端协议管理-消息通知.md)。本模块确认事实并发送，运营端消息通知承接共享消息阅读；记录开放不增加收信范围。

```mermaid
flowchart TD
    A[协议业务事实] --> B{事实种类}
    B -->|发布 立即生效 调整确认| C[办理结果与操作记录告知 不发新信]
    B -->|下线自动取消 重新上线 阅读或下载| C
    B -->|定时真实成功 真实失败 主动撤销| D[来源向本端既有运营消息范围发送]
    D --> E{是否同一事实补送}
    E -->|是| F[保留原消息时间及阅读状态]
    E -->|否| G[独立事实保留 不按同版本覆盖旧事实]
    F --> H[有消息权者读取详情]
    G --> H
    H --> I{详情是否成功呈现}
    I -->|否| J[不标已读 可重试或返回]
    I -->|是| K[仅本人自动已读 保留原事实]
    K --> L[请求进入关联原版本]
    L --> M{目标性质及当前权限 见 FL-O-AG-03}
    M -->|有权且目标可得| N[查看原版本 说明已发生的状态变化]
    M -->|无权或目标不可用| O[说明原因 不展示受限文件 不跳新对象]
    N --> P[回到原消息 保留原筛选分页与所在位置]
    O --> P
```

旧消息不迁到重新上线的新协议；下线不是主动撤销，取消不冒报定时失败。目标的承载形式由设计决定，本图只约束能否进入与回到哪里。一次计划失败的反复发现不恢复未读，后续新确认计划真实失败才是独立事实。唯一共享登记、真实时效和目标能力继续保留依赖。

<a id="fl-o-ag-06"></a>
## FL-O-AG-06 下线、旧对象留存与全新上线

回指[协议下线、留存与重新上线](01-运营端协议管理-PRD.md#offline)。由建设/研发侧执行上下线，运营端没有新增的上下线办理动作。

```mermaid
flowchart TD
    A[建设方执行原协议下线] --> B{下线结果已成立}
    B -->|否或未知| C[不伪报下线成功 读取可信状态]
    B -->|是| D[原对象停止公开当前内容与全部办理]
    D --> E[未完成计划直接取消 草稿及待生效只读已取消]
    D --> F[原生效版本归档 保留真实生效经历]
    E --> G[按原协议保留文件 计划事实及操作记录]
    F --> G
    G --> H[管理员读旧历史 正常运营全员读记录]
    H --> I[旧地址与旧消息仍定位原对象]
    J[建设方另行提供完整新协议定义] --> K[独立新协议 未发布且无旧文件或计划]
    K --> L[运营按原权限准备空白首版 v1 并发布]
```

两条流程之间没有“恢复原计划”的箭头。原协议下线后的终态不返回已上线；新对象单独开始。到点先生效则先记录真实生效，再下线归档；下线先成立则旧计划不再执行。移除定义仍保留历史与记录可达性，权限不因同名新协议而改变。

<a id="st-o-ag-01"></a>
## ST-O-AG-01 单个版本状态机

回指[更新协议与内容维护](01-运营端协议管理-PRD.md#f-o-ag-04)、[发布、待生效调整与生效](01-运营端协议管理-PRD.md#f-o-ag-06)。图中是同一协议内的同一版本，不把调整记录画作另一版本。

```mermaid
stateDiagram-v2
    state "草稿" as Draft
    state "待生效" as Scheduled
    state "已生效" as Active
    state "已归档" as Archived
    state "已取消" as Cancelled
    [*] --> Draft: 已上线且无草稿和待生效时创建
    Draft --> Draft: 保存或替换
    Draft --> [*]: 确认丢弃 编号不复用 留痕保留
    Draft --> Active: 立即发布成功
    Draft --> Scheduled: 定时发布成功
    Scheduled --> Scheduled: 确认调整成功且仍定时 编号不变
    Scheduled --> Scheduled: 实际生效失败 留痕并提示
    Scheduled --> Draft: 已上线时主动撤销 保留编号和文件
    Scheduled --> Active: 最新计划到点成功或确认立即生效
    Active --> Archived: 新版成功生效或原协议下线
    Draft --> Cancelled: 原协议下线 结束办理
    Scheduled --> Cancelled: 原协议下线 直接取消计划
    note right of Archived
        文件固定 历史仅管理员可读
        不提供恢复与手动写入
    end note
    note right of Cancelled
        保留原状态及原计划等事实
        不恢复草稿 不再执行原计划
    end note
```

| 状态 | 允许的业务动作（另需权限且协议已上线） | 内容读取 |
| --- | --- | --- |
| 草稿 | 编辑、保存、发布、确认丢弃 | 工作查询按 `PM-AL-09`；不公开 |
| 待生效 | 原版本调整并确认，或主动撤销 | 工作查询按 `PM-AL-09`；旧调整文件仅管理员；不公开 |
| 已生效 | 原对象不可改；统一更新入口准备后续版本 | 当前查询按 `PM-AL-09`，当前公开内容可读 |
| 已归档 | 无写动作 | 仅管理员历史权，不公开 |
| 已取消 | 无写动作、不可恢复；仅用于下线终止未生效版本 | 仅管理员历史权，不公开 |

正常账号读取操作记录不随版本状态丧失，也不据此取得上述内容。每条状态的呈现方式由设计决定。每个当前协议最多一个草稿、一个待生效、一个已生效；有待生效时不新建并行草稿。取消编辑、并发拒绝和失败提示不是新版本状态。

## ST-O-AG-02 协议对象的上线与下线

回指[协议下线、留存与重新上线](01-运营端协议管理-PRD.md#offline)。与单版本状态分开：协议列表中的草稿/待生效等是按当前版本派生的协议状态。

```mermaid
stateDiagram-v2
    state "已上线" as Online
    state "已下线 只读留存" as Offline
```
