## 2. 目标、范围与统一口径

运营人员能够按权限查看预置协议的用途，从“更新协议”统一维护草稿或调整待生效版本，立即或定时生效，并查询历史及操作进度；业务端始终能明确取得本平台当前生效版本。历史版本仅管理员查看与下载，操作记录对本端正常运营账号开放；不提供历史回溯创建或其他写操作。

本期包括协议及模板文件内容维护，不预设真实协议清单。“服务协议、隐私政策”等仅是类别示例，不能作为已批准上线清单。协议定义与面客使用位置由对应业务先明确，运营端只能维护内容与版本。

不包括在线富文本编辑、协议正文多语种版本、运营自助创建协议或类型、历史版本回溯创建、手动归档生效版本、审批复核、同意记录页面、强制重新同意流程、邮件、面客交互设计及跨平台总控台。

### 2.1 单一规格与独立实例（D-O-AG-01）

| 规则 | 产品含义 |
| --- | --- |
| 规格只有一份 | 本文有效功能及配套规则被三个实例共同引用（F-O-AG-08 为已取消功能编号）；不各写一套草稿、发布、历史与验收规则。其他实例若有已确认差异，须集中登记并确认，不能据旧文档自行分叉 |
| 内容各自维护 | 本端、代币发行平台、资产可信平台各有自己的协议定义、文件、版本历史、当前生效版本、操作记录和消息；同名协议或相同标识不表示共用内容 |
| 标识本平台内唯一 | 协议标识上线后不可变；另一平台有相同标识不构成冲突，不要求运营人员添加平台前缀 |
| 生效各自独立 | 本端发布、撤销、定时生效、失败或下线，均不改变另两平台的版本、文件、消息或业务端读到的内容；其他平台的变化也不影响本端 |
| 单端使用 | 本端列表、管理入口、读取能力只服务本端协议域，不提供平台列、筛选器、切换器或跨平台批量读取 |
| 身份不继承 | 本端登录或授权不能直接取得另两平台的管理权限；SPV 同主体不代表跨平台授权，也不代表已获本模块所有权限 |
| 面客归属 | 本体为运营管理平台维护、借贷面客端消费；另两平台只消费各自实例。运营管理平台的最终部署与目录归属不由本文新增裁定 |

三平台实例化只替换协议清单、使用环节、消费端名称和本平台角色映射，不共享运行中的协议版本，也不由本模块决定共用哪套实现。本文页面编号沿用本端 P-O-AG-01～04；其他平台的实际页面编号由各自登记，跨文档引用同时带平台及需求出处，不能把本端页面当作跨平台目标。

### 2.2 角色与准入（D-O-AG-02）

“运营人员”指本端正常、已完成首登改密且登录有效的运营管理员和运营专员。SPV 沿同一角色体系，不新增独立账号、机构过滤、资金操作或跨平台权。账号和授权由 WS-357 承接，本模块不新增人员或授权管理功能。

| 阅读或动作 | 权限及结果 | 不包含的能力 |
| --- | --- | --- |
| 当前协议基本信息、当前生效内容、草稿与待生效工作版本 | PM-AL-09；维护或发布任一开通须配套本项 | 不包含历史内容、下线前旧版本和已被调整替换的文件 |
| 更新内容、保存/丢弃草稿、填写待生效调整 | PM-AL-10，并具 PM-AL-09 | 不能单独确认待生效调整或发布 |
| 发布、确认待生效调整、主动撤销待生效 | PM-AL-11，并具 PM-AL-09；修改并确认内容或计划还须 PM-AL-10 | 仅发布者可发布已保存草稿或撤销计划，不可修改内容 |
| 历史版本、下线留存版本及旧文件的预览和下载 | 仅运营管理员具 PM-AL-15 | 专员即使具查询、维护和发布权，或被误配历史权，仍不可读取 |
| 协议操作记录及业务记录字段 | PM-AL-16 对正常管理员与专员固定开放；不依赖 PM-AL-09 或 PM-AL-12 | 不包含协议正文、旧文件或修改能力；不按本人经办、机构过滤 |
| 协议事件站内信 | PM-AL-12；按 WS-360 合法消息范围读取 | 不替代目标版本、历史文件或记录的准入 |

管理员固定具有本期业务权限；专员的可配置项沿 WS-357。只有记录权也必须有可达的协议记录入口，不能因缺查询权隐藏整个模块；仅提供识别原协议所需名称、标识、下线情况及操作记录，不返回无权查看的完整定义或正文。共享账户菜单展示本人当前邮箱与真实角色，沿 WS-357/360，不能由展示文字取得权限。

未登录、登录失效、待首登改密或账号锁定时，不开放受保护记录及内容，按账户模块引导；有效账号无目标权限时说明限制并保留原入口返回。内容查询、历史读取、记录读取分别判定，进入页面、下载文件及从记录/消息跳转都不得绕过。游客、面客及其他平台账号不属于“全员”。公开当前协议沿 M6，不开放公开历史。
