## 2. 目标、范围与统一口径

运营人员能够查看预置协议的用途，自助上传内容、维护草稿、立即或定时发布、查看历史、回溯内容及查询操作记录；业务端始终能明确取得本平台当前生效版本。

本期包括协议及模板文件内容维护，不预设真实协议清单。“服务协议、隐私政策”等仅是类别示例，不能作为已批准上线清单。协议定义与面客使用位置由对应业务先明确，运营端只能维护内容与版本。

不包括在线富文本编辑、协议正文多语种版本、运营自助创建协议或类型、手动归档生效版本、审批复核、同意记录页面、强制重新同意流程、邮件、面客交互设计及跨平台总控台。

### 2.1 单一规格与独立实例（D-O-AG-01）

| 规则 | 产品含义 |
| --- | --- |
| 规格只有一份 | 本文 F-O-AG-01～11 及配套规则被三个实例共同引用；不各写一套草稿、发布、历史与验收规则。其他实例若有已确认差异，须集中登记并确认，不能据旧文档自行分叉 |
| 内容各自维护 | 本端、代币发行平台、资产可信平台各有自己的协议定义、文件、版本历史、当前生效版本、操作记录和消息；同名协议或相同标识不表示共用内容 |
| 标识本平台内唯一 | 协议标识上线后不可变；另一平台有相同标识不构成冲突，不要求运营人员添加平台前缀 |
| 生效各自独立 | 本端发布、撤销、定时生效、失败或下线，均不改变另两平台的版本、文件、消息或业务端读到的内容；其他平台的变化也不影响本端 |
| 单端使用 | 本端列表、管理入口、读取能力只服务本端协议域，不提供平台列、筛选器、切换器或跨平台批量读取 |
| 身份不继承 | 本端登录或授权不能直接取得另两平台的管理权限；SPV 同主体不代表跨平台授权，也不代表已获本模块所有权限 |
| 面客归属 | 本体为运营管理平台维护、借贷面客端消费；另两平台只消费各自实例。运营管理平台的最终部署与目录归属不由本文新增裁定 |

三平台实例化只替换协议清单、使用环节、消费端名称和本平台角色映射，不共享运行中的协议版本，也不由本模块决定共用哪套实现。本文页面编号沿用本端 P-O-AG-01～04；其他平台的实际页面编号由各自登记，跨文档引用同时带平台及需求出处，不能把本端页面当作跨平台目标。

### 2.2 角色与准入（D-O-AG-02）

“运营人员”是本模块统一业务称谓。WS-357 的运营管理员、运营专员按已配置权限进入本模块；角色默认集合引用 WS-357，不重建角色体系。账号开通、改密和改邮箱均由 WS-357 承接。本模块不新增授权管理页面。

| 动作 | 所需业务权限 | 边界 |
| --- | --- | --- |
| 查看列表、基本信息、版本、文件 | PM-AL-09 协议内容与版本查询 | 登录有效且已完成首登改密；无查询权限不开放管理内容 |
| 新建、编辑、上传替换、保存、丢弃、回溯创建草稿 | PM-AL-10 协议内容与版本维护 | 执行动作需有维护权限；页面查询仍遵守 PM-AL-09，不因取得维护权限暗中扩大查询授权 |
| 立即/定时发布、撤销待生效 | PM-AL-11 协议版本发布 | 单独判定发布权限；仅维护授权不能发布；有相应权限者可自行编辑并发布，不强制另一人复核 |
| 查看操作记录 | 沿用旧基线独立的操作记录查看能力 | WS-357 未单列或明确合入哪一项，见 Q-O-AG-01；不得擅自赋予所有运营人员 |
| 查看协议事件站内信 | PM-AL-12 运营端消息查看（WS-360） | 可读消息不等于可进协议详情，跳转时仍验证业务权限 |

未登录或登录失效按 WS-357 返回运营端登录；首登未改密时不得进入协议管理办理业务；已登录但无权限时不显示对应入口，直接访问或执行动作也须拒绝。承担 SPV 职责的运营人员适用同一规则，不新增 SPV 独立账号、机构过滤或专用动作。借贷资产方、资金方及游客仅按 3.6 读取公开内容，不具备管理权限。

### 3.1 M1 协议定义、列表与检索（F-O-AG-01～03）

运营人员从一级菜单“协议管理 / Agreements”进入 P-O-AG-01；列表行或“查看”进入 P-O-AG-02。详情有“基本信息、版本历史、操作记录”三个区块，按权限开放；返回列表保留检索上下文。页面流程见 [FL-O-AG-01](./v1.0-运营端协议管理-流程图与状态机.md#fl-o-ag-01)。

**协议定义字段：**全部只读，运营端不提供新增、编辑、下线、删除协议及类型的入口。下表“必填”指协议定义完整性，不是运营可编辑表单；没有提供的默认值不能补成真实业务值。

| 字段 | 含义与业务类型 | 必填与校验 | 默认值 |
| --- | --- | --- | --- |
| 协议标识 | 文本；引用协议的固定标识 | 必填；本平台内唯一；上线后不可变；字符和长度限制未定，见 Q-O-AG-05 | 无 |
| 类型编码、类型中英文名称 | 文本；分类与筛选依据 | 均必填；取本平台定义，不能套用他平台类型清单 | 无 |
| 协议中英文名称 | 文本；按界面语言显示协议名 | 均必填；只表示界面名称双语，不表示文件分语种 | 无 |
| 协议说明 | 文本；供运营理解用途 | 可选；不对外公开；长度限制未定，见 Q-O-AG-05 | 空 |
| 使用环节 | 触点列表；每项含编码及中英文名 | 必填；明确本平台业务端用在哪些环节；实际清单及字段限制见 Q-O-AG-05 | 无 |
| 允许文件格式 | 格式列表；本协议可上传的格式 | 必填；按协议逐项明确；需要在线阅读的使用环节应选择可在线呈现的格式 | 无全局兜底 |
| 文件大小上限 | 文件容量；上传可接受的最大大小 | 必填；按协议明确值及单位，上传区展示；未明确不得上线 | 无全局兜底 |
| 上线状态 | 二值；已上线 / 已下线 | 必填；运营只读；已下线仍保留历史 | 无 |
| 排序值 | 数值；定义默认列表顺序 | 可选；缺值时顺序及数值范围未定，见 Q-O-AG-05 | 未定 |

协议定义及业务端适配由研发随既定配置发布提供（基线 §7.1 的既定约束，本文不展开实现）。新定义可用后以“未发布”出现在列表。缺格式或大小上限的定义不得上线、不显示为可用条目。移除定义不删除历史版本；列表不再展示该协议，当前读取表现为“协议不存在”。已下线协议在列表标记“已下线”，详情、历史与操作记录仍可按权限查看，全部内容维护动作不可执行。

**列表与交互：**表格列为协议名称/标识、类型、使用环节、当前生效版本、生效时间、版本数、状态、最近更新、查看。无当前生效版本或从未操作的值显示“—”；版本数不含草稿。使用环节超过 3 项折叠为“+N”，可展开完整清单；详情完整展示。存在待生效版本时显示其版本号与计划时间，不能把它作为当前生效版本。

| 列表展示状态 | 判定优先级与含义 |
| --- | --- |
| 已下线 / Offline | 定义为已下线，优先于版本状态 |
| 已生效 / Active | 已上线且有已生效版本；同时有草稿或待生效版本不改变主状态 |
| 草稿 / Draft | 已上线、无已生效版本、有草稿 |
| 未发布 / Unpublished | 已上线、无任何版本 |
| 仅有待生效版本，无生效版本和草稿 | 基线未定义主状态；原型暂用“未发布”，不能视为确认。Q-O-AG-02 待裁定；当前版本必须为空，待生效计划必须可见 |

关键词同时模糊匹配中英名称与标识，忽略大小写、前后空格。类型、使用环节、状态为多选；更新时间按最近操作时间及运营人员时区筛选。不同条件取交集，同条件多选取并集。“查询”应用条件，“重置”清空并回第 1 页。日期区间的端点及单侧输入规则见 Q-O-AG-05。

默认按定义排序值，再按最近更新时间倒序；生效时间、版本数可排序。默认每页 20 条，可切 50、100；刷新、浏览器前进后退保留筛选与分页。加载显示占位、失败可重试且保留条件；尚无定义显示“暂无协议，协议由系统预置”，筛选无结果显示“没有符合条件的协议”及重置入口。均无新建协议入口。

### 3.2 M2 文件上传、草稿与覆盖（F-O-AG-04～05）

前置条件：协议已上线、运营人员完成准入且有维护权限。P-O-AG-02 的“新建版本”进入 P-O-AG-03；已有草稿时改为“继续编辑草稿”，不能再建第二个。有当前生效版本时默认以其文件创建草稿；没有任何版本时空白新建；历史回溯按 3.4。只有待生效版本而无可复制生效版本时，新建草稿的默认内容见 Q-O-AG-02。

**文件规则：**单文件，支持点击、键盘选择与拖拽；一个版本只对应一个文件，无语种选择或正文编辑。按当前协议定义校验格式与大小；仅改扩展名伪装、空文件及一次选择多个文件均拒绝。校验失败须说明具体原因与该协议真实限制；不能只隐藏按钮而允许不合法文件保存成功。允许格式内且未超过上限才可接受。

已上传区展示原始文件名、大小、上传时间及替换、下载。草稿可反复替换；替换成功后旧草稿文件不保留，也不新增版本。上传有进度提示；失败保留原草稿文件和其他已填内容，可重试。已发布内容不能就地替换，更新要使用草稿。

| 编辑字段 | 含义与业务类型 | 必填、可编辑与校验 | 默认值 |
| --- | --- | --- | --- |
| 版本号 | 文本，形如 v1、v2 | 系统生成、只读、协议内唯一，运营不可自选或跳号；撤销后再次发布的递增歧义见 Q-O-AG-03 | 新建时自动递增 |
| 协议文件 | 文件，本版本正文/模板 | 草稿可编辑；保存可缺，发布必须已成功上传并通过本协议限制 | 空白创建为空；复制创建取来源文件 |
| 生效方式 | 枚举：立即生效 / 定时生效 | 可编辑；发布必填 | 立即生效 |
| 计划生效时间 | 时间点；选择定时生效后的计划 | 定时发布必填，分钟粒度，确认发布时距离当前时间至少 5 分钟；按账号时区输入并标注时区 | 空 |
| 变更说明 | 文本，本次修改的业务说明 | 草稿可缺；发布去除空白后非空，最多 500 字符；不可因保存草稿而放过超长内容 | 空；回溯时预填“回溯至 v{n} 的内容”并可编辑 |
| 需重新同意 | 是/否标记 | 可编辑、可选；仅保留及随公开版本提供，不触发任何面客动作或通知 | 否 |

“保存草稿”允许缺文件、说明及计划时间，成功后停留编辑页并提示“草稿已保存”；“发布”按 3.3 完整校验。基线早期页面流将保存画为返回详情，与功能正文及原型不一致，本轮以明确的保存规则为准。

未保存改动离开时确认；取消离开留在编辑页，确认后放弃未保存改动。并发编辑中后提交的旧内容不得覆盖他人已保存内容，提示“草稿已被其他运营人员更新，请刷新后重试”。保存或发布失败保留可重试的表单，不显示成功。丢弃草稿需 C-O-AG-02 二次确认，取消无变化，确认后移除草稿及其文件，已发布版本不受影响；丢弃编号是否复用见 Q-O-AG-03。

流程与异常出口见 [FL-O-AG-01](./v1.0-运营端协议管理-流程图与状态机.md#fl-o-ag-01)，状态见 [ST-O-AG-01](./v1.0-运营端协议管理-流程图与状态机.md#st-o-ag-01)。

<a id="m3"></a>
### 3.3 M3 发布、撤销与生效（F-O-AG-06）

具有查询及发布权限的运营人员可对已有草稿发布；无维护权限不能借发布修改草稿。发布前文件、说明、时间完整校验；缺文件聚焦上传区，缺说明或时间错误定位相应字段并说明原因。没有任何需另一角色审核的环节。

C-O-AG-01 显示协议名、版本号、文件名与大小、生效方式、带时区的计划时间、需重新同意标记及本期无面客行为说明。取消关闭弹窗且不发布；确认成功后回 P-O-AG-02 版本历史并显示结果。确认时规则已不满足，保持原业务状态，说明原因并允许重新检查。

| 场景 | 成功结果与边界 |
| --- | --- |
| 立即生效 | 草稿成为已生效；原已生效版本同时自动归档；实际生效时间为此次发布时刻 |
| 定时发布 | 草稿成为待生效；内容冻结；当前生效版本保持不变；首版定时发布期间仍无当前生效版本 |
| 到时生效 | 待生效变已生效，原已生效自动归档；任意可观察时刻至多一个已生效、至多一个待生效、至多一个草稿 |
| 新发布替换已有待生效 | 弹窗指出已有待生效版本及时间，按钮“撤销并发布”；按基线增加确认，明确“当前草稿将发布，原待生效版本退回为唯一草稿并保留文件”。完成后是两个不同版本：当前草稿已发布，旧待生效成为草稿；分别记录两项动作。不能覆盖正在发布的文件，取消任一确认均不改变状态 |
| 主动撤销待生效 | 生效前可撤销，C-O-AG-02 确认后退回草稿并保留原文件；当前已生效版本不变；若已有另一草稿，须明确显示将被覆盖的草稿并再次确认，不得静默丢弃 |
| 定时生效失败 | 原生效版本保持不变；首版则仍无生效版本；待生效记录保留并展示失败提示，记录失败且发送站内信。失败是处理结果，不新增“失败版本”状态 |
| 失败后的人工处置 | 可按已存在的撤销能力退回草稿，再按普通发布条件处理；不新增自动重试次数、间隔或新的审批流程 |

已经存在当前生效版本时，正常替换或失败都不得出现两份同时生效或暂时无生效版本的结果。计划时间按同一真实时刻判断，切换时区只改变显示，不改变计划。到时自动切换，不以运营人员打开页面为条件。基线的“切换偏差不超过 60 秒”保留为目标值，不提升为新增强制门槛。

版本一旦待生效，其文件及内容凭据冻结，撤销回草稿才可再次编辑；已生效与已归档永不可改删。内容凭据用于辨认当时发布的确切文件，随发布版本固定，具体生成方法沿用既定约束、不在本文展开。撤销版本的旧凭据保留及再发布编号歧义集中 Q-O-AG-03；协议下线与待生效计划相遇集中 Q-O-AG-04，不以原型模拟行为替代裁定。

发布冲突流程见 [FL-O-AG-02](./v1.0-运营端协议管理-流程图与状态机.md#fl-o-ag-02)，状态见 [ST-O-AG-01](./v1.0-运营端协议管理-流程图与状态机.md#st-o-ag-01)。

### 3.4 M4 历史、预览与回溯（F-O-AG-07～08）

有查询权限者进入 P-O-AG-02：基本信息展示只读定义及当前生效摘要；版本历史按版本号倒序，含草稿、待生效、已生效、已归档，当前生效行突出显示。每行显示版本号、状态、文件名及大小、生效时间、归档时间、变更说明、来源版本、发布人与发布时间；草稿显示最近保存人，尚未发生的时间显示“—”。

P-O-AG-04 为只读抽屉，展示上述内容以及版本标识、文件格式、上传时间、内容凭据和需重新同意标记。支持内嵌预览的格式展示文件；其他格式解释仅支持下载；预览失败可重试或下载。无文件草稿显示“尚未上传文件”，不提供不可用的下载。关闭抽屉回原页、原位置；Escape、遮罩、关闭按钮均可关闭。

| 展示字段组 | 含义、可编辑性与空值 |
| --- | --- |
| 版本标识、所属协议、版本号 | 标识具体内容版本及归属；系统生成、只读，不由运营填写 |
| 文件名、格式、大小、上传时间 | 来自该版本实际文件；只读；无文件时为空，不伪造默认文件 |
| 内容凭据 | 辨认发布文件的固定凭据；只读，发布后可完整查看和复制；未发布时不显示为已冻结凭据 |
| 版本状态 | 草稿 / 待生效 / 已生效 / 已归档；由业务动作决定，不可手动修改 |
| 生效、归档、发布时间 | 计划或实际业务时间及发生时间；只读、带时区；草稿的生效时间显示“—”，尚未归档则无归档时间 |
| 发布人、最近保存人 | 实际动作人身份；只读；草稿无发布人，以最近保存人展示；邮箱按共享基线脱敏 |
| 来源版本 | 复制来源的版本关联；有回溯来源时“基于 v{n}”可定位原版本，无来源为空 |

任一版本可查看；有文件且有权限才可下载。草稿可编辑、发布、丢弃；待生效可撤销；已生效或已归档可“以此版本为基础新建版本”，各动作仍需相应权限。

回溯创建新的草稿、复制文件、预填说明并记录来源；原历史版本保持不变，不能把已归档版本直接改回生效。新草稿按普通发布规则完成，成为更大编号的新版本。已有草稿时基线只明确“不能产生第二个”，未明确回溯覆盖方式，见 Q-O-AG-03，不静默覆盖。流程见 [FL-O-AG-03](./v1.0-运营端协议管理-流程图与状态机.md#fl-o-ag-03)。

新版本生效是旧生效版本自动归档的唯一原因；没有手动归档生效版本入口。协议下线不删除历史、文件或记录；移除定义后的历史恢复入口基线未定义，见 Q-O-AG-04。

### 3.5 M5 留痕与变更约束（F-O-AG-09～10）

P-O-AG-02“操作记录”按协议集中呈现时间线；覆盖创建、保存、上传/替换、丢弃、发布、撤销、被替换退回、系统生效、系统归档、回溯创建，以及定时生效失败。权限映射待 Q-O-AG-01 收口；记录生成不得因查看权限未定而取消。

| 记录信息 | 业务含义与展示 |
| --- | --- |
| 操作对象、动作 | 协议及版本号、实际发生的动作；必记、只读 |
| 操作时间 | 动作发生时刻；必记、带时区 |
| 操作人 | 人工动作保留实际人员身份，展示姓名及掩码邮箱；系统生效、归档明确显示“系统 / System” |
| 变更摘要 | 可读的业务说明；必记；替换文件包含旧、新文件名；发布说明生效方式与时间；撤销区分主动撤销和被新发布替换 |
| 操作来源 | 保留审计需要的来源 IP；界面仅显示地区摘要，不展示完整 IP，遵守共享脱敏基线 |

记录只增不改、永久保留，不提供编辑或删除；已发布历史永久可查。基线协议 PRD 的完整邮箱/IP 展示与其引用的共享脱敏基线冲突，本轮按共享基线展示，保留必要审计事实，不向公开协议读取暴露运营身份。账号邮箱变更不改写已经发生的动作归属；历史邮箱是否跟随变更，见 Q-O-AG-01。

所有限制必须在实际执行时成立：不能绕过页面修改定义、删除已发布版本、覆盖冻结内容或篡改记录；有管理权限也不例外。草稿替换与丢弃只影响草稿，不删除已经发布的历史文件。

### 3.6 M6 当前生效版本与公开读取（F-O-AG-11）

本平台业务端及游客可按协议标识读取当前生效版本，可一次取得多份或按类型取得已上线协议的当前生效版本，也可按指定版本回看已归档内容。本模块只定义取到什么与异常结果；面客页面、勾选、同意记录及重新同意流程由对应需求负责。

| 情形 | 可观察结果 |
| --- | --- |
| 已上线、有当前生效版本 | 取得本平台该版本的协议名、标识、类型、使用环节、版本标识及版本号、文件信息与文件、固定内容凭据、生效与发布时间、需重新同意标记 |
| 草稿或待生效 | 不作为当前版本返回；外部直接指定版本或尝试访问文件也不能得到未生效内容 |
| 已归档 | 只支持指定历史版本回看，不混入当前版本列表；其内容不因新版本发布而变化 |
| 标识未定义、已下线、暂无生效版本、指定版本不存在或尚未生效 | 分别可识别为“协议不存在”“协议已下线”“暂无生效版本”“版本不存在”；不表现为成功的空白文件 |
| 读取失败 | 需要用户同意的环节不得以“没有协议”静默放行；当前显示版本过期时不能按旧版完成应以当前版本为准的确认，应刷新后重试，具体面客交互由消费模块定义 |
| 其他平台同名或同标识 | 始终取本平台版本；本平台无可用版本也不借用另两平台版本兜底 |

公开内容不含内部说明、运营人员身份、操作记录或未生效草稿；不附加正文语种、在线富文本或平台切换能力。“需重新同意”仅是保留的业务标记，本期不能据此弹窗、通知或强制阻断老用户。

既有读取字段映射和内容凭据约束引用源 PRD §9，消息契约引用既有 `docs/notification-contract/接入指南.md` 并由 WS-360 承接跨平台调整；本文不复制报文、参数、算法或访问路径。基线规定当前版本切换后消费方最迟 5 分钟更新显示；提交同意等关键确认须针对当前生效版本，不能以该展示更新窗口绕过版本一致性要求。下线后历史直取的优先关系见 Q-O-AG-04。业务流程见 [FL-O-AG-04](./v1.0-运营端协议管理-流程图与状态机.md#fl-o-ag-04)。

### 3.7 运营端通知（D-O-AG-03，关联 F-O-AG-06）

本模块负责事件何时发生及通知内容，WS-360 负责消息页、可见范围、未读和跳转。仅向本端运营人员的共享消息范围发送；实际查看仍需消息权限，每人独立已读，不投递给资产方、资金方或另两平台账号，不因 SPV 职责新增消息池。

| 事件 | 是否通知 | 必要信息与文案含义 |
| --- | --- | --- |
| 发布成功、立即生效 | 不发 | 当前操作结果由页面告知；定时发布提交成功时也不发 |
| 定时到点成功 | 发运营告警 | 协议名、版本号、生效时间；“{协议} {版本} 已按计划生效 / {agreement} {version} took effect as scheduled.” |
| 定时到点失败 | 必发运营告警 | 协议名、待生效版本、计划时间、当前仍生效版本；“{协议} {版本} 未能按计划生效 / {agreement} {version} could not take effect as scheduled.”；首版无当前版本时明确“暂无生效版本” |
| 主动撤销或新发布替换待生效 | 发运营告警 | 协议名、版本号、原因、操作人；“{协议} {版本} 的定时生效已撤销 / Scheduled activation of {agreement} {version} was cancelled.”；原因区别主动撤销/被新发布替换 |

同版本同事件不反复堆叠相同消息；定时失败再次发生时更新同一消息并恢复未读。运营告警不可退订，无按时间自动失效规则。消息不包含文件地址、完整邮箱、完整 IP 或内容凭据等不必要信息；按接收者当前语言及时区展示。

点击指向 P-O-AG-02 的版本历史；目标状态已变化须说明并引导查看最新状态，不误导为仍待处理。无业务查询权限须解释无权限，不因消息可见开放详情。旧基线“永不出现无权限或资源不存在”的单角色假设不再适用：撤回草稿后可能被丢弃、定义可能被移除，目标不可用时给出明确提示及返回消息列表入口，不出现空白页。见 [FL-O-AG-05](./v1.0-运营端协议管理-流程图与状态机.md#fl-o-ag-05)。不发送邮件或面客“重新同意”通知。

### 3.8 展示、安全与质量（N-O-AG-01）

界面默认英文、支持中英即时切换；完整规则引用第 1 章国际化基线，切换不清空表单、不改变文件内容。关键术语采用 Agreements/协议管理、Draft/草稿、Scheduled/待生效、Active/已生效、Archived/已归档、Unpublished/未发布、Offline/已下线、Save draft/保存草稿、Publish/发布、Cancel and publish/撤销并发布。

所有时间带时区；长名称、标识和文件名可查看完整值，内容凭据可复制；共享脱敏规则适用于记录和通知。桌面 1280、1440、1920 像素下操作列可达、无页面横向溢出；更窄时保留关键操作。支持 Chrome、Edge、Firefox、Safari 最近两个大版本；中英文均无错位和信息丢失。键盘可完成操作、焦点可见、状态含文字，浮层焦点不移到背景，关闭后恢复；错误与进度对辅助阅读可感知，减少动效偏好有效。

文件呈现不能执行其中的恶意内容或泄露非公开文件；不合法格式不得仅凭改名通过。既定文件安全与访问约束引用源 PRD §12.2，保持其安全目标，不在本文件扩展实现。基线性能目标沿用：20 条列表首屏及详情 P95 小于 1.5 秒、业务端当前版本读取 P95 小于 300 毫秒、下载首字节 P95 小于 800 毫秒；定时切换偏差不超过 60 秒。均为观察及校准目标，不冒充已测结果，也不提升为未确认的发布门槛。

## 4. 验收需求说明（测试主阅读入口）

按 M1～M6 顺序验收，均以本端有效运营账号为管理侧角色；涉及维护、发布、记录分别具备对应权限。公开读取场景包含借贷业务端和游客。另两平台使用同规格进行独立实例验收；不能只验证本端操作成功，就认定三平台独立成立。Q-O-AG-* 未关闭的分支分别标记待裁定，不判作通过，也不阻止验证其余已确定能力。以下是业务验收要求，不是详细执行用例。
