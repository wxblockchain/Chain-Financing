# 运营端协议管理 · 消息通知

2026-09-23｜需求评审稿｜配套本模块当前[主 PRD](01-运营端协议管理-PRD.md)与[流程图与状态机](02-运营端协议管理-流程图与状态机.md)。

本册定义本模块发什么、何时发、发给谁、读者能做什么；站内消息的可见范围、未读计数、自动已读与跳转归[运营端消息通知](../v1.0-运营端消息通知/01-运营端消息通知-PRD.md)，本册不重复定义。通知的承载形式与视觉由设计决定（见[统一条款](01-运营端协议管理-PRD.md#design-boundary)）。事件编号 `NT-O-AG-01`～`NT-O-AG-03` 为本模块首次登记，供共享消息登记引用；协议事件的共同口径仍记在[协议事件告知（D-O-AG-03）](01-运营端协议管理-PRD.md#d-o-ag-03)，验收见[4.8 协议事件告知](01-运营端协议管理-PRD.md#ac-8)，流程见[事件告知、阅读及目标权限（FL-O-AG-05）](02-运营端协议管理-流程图与状态机.md#fl-o-ag-05)。

## 1. 本模块通知范围

本模块只有三类运营告警，均由协议来源确认事实后向本端运营人员的共享消息范围发送。

| 事件编号 | 业务名称 | 渠道 | 收件范围 |
| --- | --- | --- | --- |
| [`NT-O-AG-01`](#nt-o-ag-01) | 定时生效成功告警 | 本端站内运营告警 | 本端运营人员的共享消息范围 |
| [`NT-O-AG-02`](#nt-o-ag-02) | 定时生效失败告警 | 本端站内运营告警 | 本端运营人员的共享消息范围 |
| [`NT-O-AG-03`](#nt-o-ag-03) | 待生效计划撤销告警 | 本端站内运营告警 | 本端运营人员的共享消息范围 |

**明确不产生通知的事件**：发布成功、立即生效、待生效调整确认成功、定时发布提交成功，当次操作结果由办理结果及[操作进度](01-运营端协议管理-PRD.md#f-o-ag-09)告知；协议下线及其自动取消、重新上线、记录被查看、历史被下载同样不新增通知。下线不等于运营主动撤销，不得借用[待生效计划撤销告警](#nt-o-ag-03)；下线前已真实发生的定时结果仍按原事实处理，不冒报下线后执行成功。不为通知开关编造事件，不新增邮件、短信、浏览器推送，也不产生面向资产方、资金方的协议更新或重新同意通知。

**收件边界**：实际查看仍需 `PM-AL-12`，每人独立已读。不投递给资产方、资金方或另两平台账号，不影响另两平台未读数，不因 SPV 与运营同主体新增消息池。操作记录“全员可看”不等于全员收信，收到消息也不绕过目标版本的内容权限（[角色与准入](01-运营端协议管理-PRD.md#d-o-ag-02)）。运营告警不可退订，无按时间自动失效规则。

**内容边界**：消息中不含文件地址、完整邮箱、完整 IP、协议正文或内容凭据；按读者当前语言与时区呈现，不展示内部定位参数。

<a id="nt-o-ag-01"></a>
## 2. 定时生效成功告警（`NT-O-AG-01`）

关联[发布、待生效调整与生效](01-运营端协议管理-PRD.md#f-o-ag-06)的“到时自动生效”。

| 项目 | 产品规则 |
| --- | --- |
| 触发 / 不触发 | 待生效版本按最近一次确认成功的计划真实生效后触发。定时发布提交成功、待生效调整确认成功、立即发布与立即生效均不触发；调整成功也不得冒报为定时生效成功 |
| 收件人 | 本端运营人员的共享消息范围；不改投单个经办人，不抄送另两平台或面客账号 |
| 发送时点 / 渠道 | 实际生效之后；仅本端站内运营告警，不发邮件 |
| 必要信息 | 协议名称、版本号、实际生效时间（带时区） |
| 同次事实与再次发生 | 一次真实生效是一条事实，重复投递或补送不产生副本、不改原发生时间、不恢复未读。下一次真实的定时生效才是新事件 |
| 阅读与操作 | 详情成功呈现才对本人自动已读；阅读不改变协议计划或他人状态。进入关联版本按其当前性质重新判权，见[第 5 节](#target-access) |
| 失败 / 离线 | 告警投递失败不回滚已生效的版本，也不改变生效事实 |

<a id="nt-o-ag-02"></a>
## 3. 定时生效失败告警（`NT-O-AG-02`）

关联[发布、待生效调整与生效](01-运营端协议管理-PRD.md#f-o-ag-06)的“定时生效失败”。

| 项目 | 产品规则 |
| --- | --- |
| 触发 / 不触发 | 计划到点但实际生效未成功时必发。协议已下线导致计划取消不属于失败，不发本事件；结果未明时先确认可信状态，不把未确认结果写成失败通知 |
| 收件人 | 本端运营人员的共享消息范围 |
| 发送时点 / 渠道 | 失败事实成立后；仅本端站内运营告警 |
| 必要信息 | 协议名称、待生效版本号、原计划时间、当前仍生效的版本；首版无当前版本时明确“暂无生效版本” |
| 同次事实与再次发生 | 一次失败的重复发现仍是同一事实，补送不新增消息、不改时间、不恢复未读。该版本经再次确认的新计划真实失败是另一业务事实，各自保留计划、发生时点与阅读状态，不按同版本号覆盖旧事实 |
| 阅读与操作 | 失败后该版本仍是待生效，可从更新协议重新设定时间或改立即生效，无需先撤销。旧失败消息在计划已变化后须说明计划已变，不误导为仍待原计划执行 |
| 失败 / 离线 | 告警投递失败不改变待生效与当前生效版本的真实状态 |

<a id="nt-o-ag-03"></a>
## 4. 待生效计划撤销告警（`NT-O-AG-03`）

关联[发布、待生效调整与生效](01-运营端协议管理-PRD.md#f-o-ag-06)的“主动撤销待生效”。

| 项目 | 产品规则 |
| --- | --- |
| 触发 / 不触发 | 运营人员在更新协议办理内二次确认撤销、计划真实取消后触发。取消编辑、离开办理、撤销被阻断（草稿冲突）、协议下线导致的自动取消均不触发；待生效调整确认成功不误发本事件 |
| 收件人 | 本端运营人员的共享消息范围 |
| 发送时点 / 渠道 | 计划取消、版本退回同号草稿之后；仅本端站内运营告警 |
| 必要信息 | 协议名称、版本号、原计划时间、主动撤销原因、操作人（脱敏后的可读归属） |
| 同次事实与再次发生 | 一次撤销一条事实，不重复发送；该版本再次发布并再次撤销才是新事件 |
| 阅读与操作 | 撤销后该版本为草稿，当前已生效版本不变；读者进入目标按其当前性质判权 |
| 失败 / 离线 | 告警投递失败不恢复已取消的计划 |

<a id="target-access"></a>
## 5. 目标访问与返回

从消息进入业务目标时，按目标此刻的性质重新判权：仍为当前或工作版本时，具 `PM-AL-09` 可进入[版本详情](01-运营端协议管理-PRD.md#f-o-ag-07)；已成历史、已归档或下线留存时，仅管理员具 `PM-AL-15` 可查看。保留原版本定位，禁止以最新版本或重新上线的新协议冒替；旧通知始终关联原协议与原事实。

无内容权限时说明限制并可返回原消息；若提供原操作记录入口，仅凭 `PM-AL-16` 读取记录摘要，不据此展示受限文件。目标状态或计划已变化时保留消息原事实并说明目标当前状况；无权限、已丢弃、定义已移除或目标确实不可得分别提示，不跳空白页或默认首页。返回时回到原消息并保留原筛选、分页与所在位置；目标有未提交内容时沿原离开保护。共享的未读计数与本人身份呈现沿运营端消息通知，本模块不另造一份阅读状态。

## 6. 文案要素

按读者当前界面语言呈现，动态变量取真实业务值；时间均带时区。

| 事件 | 中文 / 英文 |
| --- | --- |
| [定时生效成功告警](#nt-o-ag-01) | {协议} {版本} 已按计划生效 / {agreement} {version} took effect as scheduled. |
| [定时生效失败告警](#nt-o-ag-02) | {协议} {版本} 未能按计划生效 / {agreement} {version} could not take effect as scheduled. |
| [待生效计划撤销告警](#nt-o-ag-03) | {协议} {版本} 的定时生效已撤销 / Scheduled activation of {agreement} {version} was cancelled. |

## 7. 待衔接依赖

唯一共享登记、正式分类及原目标能力须与运营端消息通知接续，真实投递、历史/记录权限与消息返回尚须联验；本册明确现有三类事件及发送责任，不代替实际登记完成。消息框架保留“业务发生/应到时点起 60 秒可见”与其他来源最迟 5 分钟发现的时效冲突：不改计时起点、不相加放宽，也不以本模块的目标切换或消费显示窗口替代，详见[共享基线与唯一消息登记（Q-O-AG-06）](01-运营端协议管理-PRD.md#q-o-ag-06)。
