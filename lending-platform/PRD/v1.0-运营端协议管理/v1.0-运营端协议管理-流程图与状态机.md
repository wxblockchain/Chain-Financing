## FL-O-AG-01 列表、编辑与保存

回指 [正文 M1](./v1.0-运营端协议管理-PRD.md#m1)、[M2](./v1.0-运营端协议管理-PRD.md#m2)；验收 AC-O-AG-01～36、76、89～91。无权限、未登录及首登未改密均不能绕过准入。

```mermaid
flowchart TD
    A[运营人员进入协议管理] --> B{满足准入和查询权限}
    B -->|否| C[按账号状态引导登录或改密 无权限则拒绝]
    B -->|是| D[P-O-AG-01 协议列表]
    D --> E[筛选 查看使用环节与当前版本]
    E --> F[P-O-AG-02 协议详情]
    F --> G{已上线且有维护权限}
    G -->|否| H[仅保留有权查看的内容]
    G -->|是| I{是否已有草稿}
    I -->|是| J[继续编辑唯一草稿]
    I -->|否| K[按已明确来源创建草稿]
    J --> L[P-O-AG-03 上传文件 填写版本信息]
    K --> L
    L --> M{上传或替换结果}
    M -->|失败| N[说明原因 保留原文件与其余输入 可重试]
    N --> L
    M -->|成功| O[展示新文件信息]
    O --> P{运营人员动作}
    P -->|保存草稿| Q{保存成功}
    Q -->|是| R[停留编辑页 提示草稿已保存]
    Q -->|否或他人已更新| S[保留输入 提示失败或刷新]
    R --> L
    S --> L
    P -->|发布| T[进入 FL-O-AG-02]
    P -->|离开且有未保存改动| U{确认离开}
    U -->|取消| L
    U -->|确认| V[放弃未保存改动 返回所选页面]
```

只有待生效版本时新草稿的默认来源待 Q-O-AG-02；图中“按已明确来源”仅指空白首建、复制当前生效版本和正文已确定的回溯场景。保存草稿不返回详情，发布成功才返回版本历史。

<a id="fl-o-ag-02"></a>
## FL-O-AG-02 发布、撤销与定时结果

回指 [正文 M3](./v1.0-运营端协议管理-PRD.md#m3)；验收 AC-O-AG-37～48、92～93。图中的发布者须具查询与发布权限；内容修改另需维护权限。

```mermaid
flowchart TD
    A[运营人员发布草稿] --> B{文件 说明 计划时间符合规则}
    B -->|否| C[定位问题 保持草稿 可修正]
    B -->|是| D[C-O-AG-01 发布确认]
    D --> E{已有待生效版本}
    E -->|是| F[显示旧计划 提示撤销并发布]
    F --> G[再次确认 当前草稿发布 旧待生效退回唯一草稿]
    E -->|否| H[确认发布]
    G --> H
    D -->|取消| I[保留原状态]
    G -->|取消| I
    H --> J{发布成功}
    J -->|否| K[原版本保持 提示失败 可重试]
    J -->|是| L{生效方式}
    L -->|立即| M[新版本已生效 旧生效版本同时归档]
    L -->|定时| N[新版本待生效 当前版本保持]
    M --> O[返回详情版本历史 留痕]
    N --> O
    N --> P{计划后续结果}
    P -->|到时成功| Q[新版本生效 旧生效版本归档 留痕并通知]
    P -->|到时失败| R[保留待生效及旧生效状态 标注失败 留痕并通知]
    P -->|运营人员主动撤销| S{二次确认撤销}
    S -->|取消| N
    S -->|确认| T{已有其他草稿}
    T -->|否| U[退回草稿 保留文件 当前生效版本不变]
    T -->|是| V{明确覆盖对象后再次确认}
    V -->|取消| N
    V -->|确认| U
    U --> W[记录撤销 发送本端通知]
```

新发布替换旧待生效的成功结果包含“旧待生效退回唯一草稿”，并分别留痕及产生撤销通知，详见正文。任一确认取消或发布失败不得先丢失旧状态。首版无旧生效版本时，定时等待或失败均仍无当前生效版本。下线与定时计划相遇、退回版本再次发布编号待 Q-O-AG-03～04，不在图中画成已确定分支。

回指 [正文 M4](./v1.0-运营端协议管理-PRD.md#m4)；验收 AC-O-AG-49～53。回溯创建的是另一个版本，历史状态不倒退。

## FL-O-AG-04 当前生效版本读取

回指 [正文 M6](./v1.0-运营端协议管理-PRD.md#m6)及 [D-O-AG-01](./v1.0-运营端协议管理-PRD.md#scope)；验收 AC-O-AG-59～68、94～97。这里只画“读取当前版本”；指定历史版本是独立能力，不借此图裁定下线历史回看。

```mermaid
flowchart TD
    A[本平台业务端或游客需要协议] --> B[按本平台协议标识读取当前版本]
    B --> C{本平台定义是否存在}
    C -->|否| D[说明协议不存在 不借用其他平台版本]
    C -->|是| E{是否已上线}
    E -->|否| F[说明协议已下线]
    E -->|是| G{是否有已生效版本}
    G -->|否| H[说明暂无生效版本 不返回草稿或待生效内容]
    G -->|是| I[展示对应已生效文件及版本信息]
    I --> J{需针对当前版本完成关键确认}
    J -->|是| K{展示版本仍为当前版本}
    J -->|否| O[仅阅读协议内容]
    K -->|是| L[可按消费业务的同意规则继续]
    K -->|否| M[刷新当前协议后重试]
    D --> N[需用户同意的业务不得静默放行]
    F --> N
    H --> N
```

“需重新同意”标记不触发新流程。公开版本信息不包含运营身份或内部记录。其他平台执行同样规则，取得的是各自实例的当前版本。

<a id="st-o-ag-01"></a>
## ST-O-AG-01 单个协议版本的状态机

回指 [正文 M2](./v1.0-运营端协议管理-PRD.md#m2)、[M3](./v1.0-运营端协议管理-PRD.md#m3)、[M4](./v1.0-运营端协议管理-PRD.md#m4)；验收 AC-O-AG-31～48、51～53。一个图只描述一个版本对象，回溯创建的新草稿在 FL-O-AG-03 表达。

```mermaid
stateDiagram-v2
    state "草稿" as Draft
    state "待生效" as Scheduled
    state "已生效" as Active
    state "已归档" as Archived
    [*] --> Draft: 新建或复制来源创建本版本
    Draft --> Draft: 保存或替换草稿文件
    Draft --> [*]: 确认丢弃草稿
    Draft --> Active: 确认立即发布成功
    Draft --> Scheduled: 确认定时发布成功
    Scheduled --> Scheduled: 到时失败 保留状态并标注失败
    Scheduled --> Draft: 确认撤销或被新发布替换退回
    Scheduled --> Active: 到达计划时间且生效成功
    Active --> Archived: 另一版本成功生效
    note right of Archived
        保持历史内容及状态
        回溯创建另一个草稿对象
        不把本版本变回草稿
    end note
```

| 状态 | 运营端允许动作（另需权限） | 对外读取 | 结束或后续 |
| --- | --- | --- | --- |
| 草稿 | 查看、有文件则下载、维护、发布、丢弃 | 不可见 | 可发布或丢弃；丢弃后对象结束 |
| 待生效 | 查看、下载、撤销 | 不可见 | 到时生效或退回草稿；失败仍待生效 |
| 已生效 | 查看、下载、作为新草稿来源 | 当前版本可读 | 仅另一版本生效时自动归档 |
| 已归档 | 查看、下载、作为新草稿来源 | 仅按指定历史版本回看 | 永久保留，不画删除终态 |

同一协议同时至多一个草稿、一个待生效、一个已生效版本；归档版本可有多个。协议列表“已下线/未发布”等是定义与版本共同派生的展示值，不与上述版本状态混为同一个状态机。Q-O-AG-02～04 所列主标签、重新编号、下线交叉分支仍待裁定；本图未替这些问题给出新结论。
