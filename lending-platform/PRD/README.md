# 借贷平台 · PRD 阅读入口

本目录汇集借贷平台当前仓库中的 PRD，共 17 个业务模块，**按端分组存放**：面客端 10 册、运营端 7 册，端内目录名以两位序号体现阅读顺序（面客端：登录 → 账户基础 → 资产广场 → 借贷广场四步业务 → 控制台 → 消息中心；运营端：登录 → 平台配置 → 日常审核 → 消息通知）。共用基础件（本入口、[全流程阅读入口](00-阅读入口与全流程范围.md)、[字段命名与术语对照表](00-字段命名与术语对照表.md)）留在本目录根下。原型底座不属于 PRD 正文。

序号只表示端内阅读次序，**不是业务标识**：新增模块按其业务位置插入、其后序号顺延，功能与验收编号锚点不随路径变化。实际内容以各模块主阅读入口为准。

全库共用的业务名称与释义见[字段命名与术语对照表](00-字段命名与术语对照表.md)；各册更名以该表为基线，编号锚点不随更名变化。

### WS-386 · 企业账户

面客端资产方与资金方双侧。本模块共三册：01 功能与业务规则、02 流程图与状态机、04 验收（供测试）；本模块不发送任何消息，所以没有 03 消息通知册。三册只定义信息需求与业务行为，页面布局与组件由设计决定。

企业在一处登记并维护本企业自己的法币账户和数币账户，业务办理时只能下拉选用、不能新建。关键口径：不设默认账户；不采集收款人名称，平台不核对账户归属；法币账户的账户币种可多选、只作标注，不设中转行信息；数币账户当前仅支持以太坊网络，结算收款链固定为以太坊（ETH），填写地址后用该地址签名证明所有权，地址登记后不可修改；总览按两个 Tab 呈现，数币账户在前；账户变更不审核、不发消息、保存即生效；已提交业务保留账户快照。关键状态见[数币账户登记状态机](./面客端/03-企业账户/02-企业账户-流程图与状态机.md#state-1)与[企业账户生命周期状态机](./面客端/03-企业账户/02-企业账户-流程图与状态机.md#state-2)。

### WS-373 · 资产广场

关键口径：一笔代币只有一个发行方，可以有多个持有方，持有方以链上地址表示、不展示身份；代币信息展示铸造链与铸造时间；质押状态只在详情的持有方清单中逐个持有方展示，列表与概览不展示，一笔代币的持有方可分属不同融资项目；业务释放后即显示未质押；信息如何取得由研发决定，PRD 只定义需要哪些信息。本模块当前没有待确认事项，依赖见[待确认事项与依赖](./面客端/04-资产广场-已上架代币只读域/01-资产广场-PRD.md#dependencies)。

### WS-374 · 融资需求与代币质押

面客端资产方、资金方、游客与登录未绑定角色。本模块共四册：01 功能与业务规则、02 流程图与状态机、03 消息通知、04 验收（供测试）。四册只定义信息需求与业务行为，页面布局与组件由设计决定。

资产方创建项目并经审核（审核与合约部署合为一步），再签名把代币质押上链；合约执行上链成功即质押成功、计入有效质押额，不经运营审核，据此发布融资需求。关键口径：质押单位是质押份额（本企业一个持有地址上持有的某笔代币的全部数量，只能整份质押）；质押、解押、提取都由资产方一步签名、gas 自担；创建入口只对资产方开放；项目详情按身份决定可见范围（本企业资产方与资金方看完整详情，游客、登录未绑定角色和其他企业资产方只看基本信息）；质押水位不安全（有效质押额低于项目融资余额＋在途金额，与需求失效同一判据）时合约内的代币一律不能转出；全流程没有审核或报价时限。本模块已无待确认事项（Q-LS-01～03 已于 2026-10-21 裁定），依赖见 01 册末节。

### WS-375 · 授信报价与接受拒绝

面客端资金方、资产方、游客与登录未绑定角色。本模块共四册：01 功能与业务规则、02 流程图与状态机、03 消息通知、04 验收（供测试）。四册只定义信息需求与业务行为，页面布局与组件由设计决定。

资金方点击立即报价时，平台先核验本机构对项目发布企业的授信；尚无、不足或已到期时就地办理企业授信（首次、追加或重新授信，协议选填），保存后须再次发起报价；报价成功即锁定本轮需求。关键口径：报价没有有效期，资金方不能撤回，退出只有资产方拒绝，或需求因项目到期、质押水位不足终结带来的连带失效（连带失效由融资需求模块合并通知）；接受只需选用企业账户中已登记的账户并核对商务摘要，不收合同盖章件，不采集收款人名称；待放款没有时限和终止出口。三项既定业务限制见[01 册第 9 节](./面客端/06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#limits)；只有已认证资金方可以报价；非本笔当事的资金方只知道哪家机构报价，看不到条款；报价信息的查看权限只在本模块定义，其他模块展示时沿用。待确认事项（数币精度、授信协议下载的权限矩阵取值）见 01 册末节。须与 WS-376 同批评审。

### WS-376 · 放款与放款确认

面客端资金方与资产方，另含非当事资金方、游客与登录未绑定角色的查看边界。本模块共四册：01 功能与业务规则、02 流程图与状态机、03 消息通知、04 验收（供测试）。四册只定义信息需求与业务行为，页面布局与组件由设计决定。

只有两步：资金方在平台外付款后登记放款并从企业账户中选定资金方收款账户，资产方核实到账后确认（两步都是点击即提交，不设二次确认）；确认成功时金额从在途转为本金并交还款模块生成计划。关键口径：待放款与待放款确认都没有时限和终止出口，也没有盖章件核验、暂缓、重传或异议；提交放款时复核质押水位；交易标识按结算收款链（ETH / TRON）校验，资金方的数币还款收款账户必须与本笔结算收款链相同；放款金额与币种只对本笔双方可见，沿授信报价模块的报价信息查看权限。既定业务限制（含质押水位不安全时待放款只能等资产方追加质押）见[01 册第 9 节](./面客端/07-借贷广场-放款与放款确认/01-放款与放款确认-PRD.md#limits)；放款相关规则以本模块为准，融资需求模块中的放款内容只是概述；确认到账不采集实际到账金额，客服邮箱取值在代码中固定；本模块没有待确认事项。须与 WS-375 同批评审。
