### 2.2 游客态默认与登录入口（`F-L01`）

| 编号 | 口径 |
| --- | --- |
| **`D-L01`** | **平台的默认态是游客态。** 任何未登录用户访问游客态可达路由，**一律直接渲染内容——不得跳转到登录页、不得弹出遮挡性的登录弹层、不得用登录墙盖住内容** |
| **`D-L02`** | **登录只在两种时机出现**：① 用户主动点右上角「登录」；② 用户触发了受限操作（主干 4.2 引导）。**除此之外不得出现任何形式的登录提示** |
| — | **右上角常驻「登录」按钮**：全站壳层内固定位置，游客态可见；登录后替换为账号下拉。点击 → `P-L01` |
| — | **游客态可达范围由权限矩阵决定**。资产广场列表等游客可达内容直接呈现；账户、消息、控制台等登录后页面不能因列入回跳允许范围就对游客开放。不可见能力按矩阵 ❌ 处理，不强制跳登录 |
| — | **游客顶部身份入口只保留「登录」**，保留语言切换；不展示「申请入驻」。登录后替换为钱包地址缩写入口，资产方菜单内显示角色「资产方」，其只读地址、缺失兜底与「企业信息」入口见 SSO 9.2。账户入口及回跳不得展示其他账户的个人或企业基本资料，业务可见信息按 SSO 9.4 已确认范围处理。资金方完成签名验证并建号后进入既有机构注册流程；「用户信息」等登录后入口的去向由 WS-349 承接，不创建第二个身份选择页 |

**`D-L19` 默认入口与浏览上下文**：打开平台、点击品牌入口、访问旧首页入口或无可用落点时，进入既有资产广场；不展示独立首页。`P-L02` 保留为游客壳层编号，不另建资产列表。取消登录时，有合法原浏览页则回原页并保留浏览上下文；没有则回资产广场。该变化只定义入口，不改变资产范围、认证权限或有效原操作回跳。

### 2.3 用户类型选择与路径分流（`F-L02`）

> **本节是相对基线的实质变更**：基线是「共用表单 + 登录后分流」，本期是**路径分流**——两张卡片点下去进入的是**两条完全不同的流程**，不是同一个表单的两种填法。基线登录页形态需**重画**。

| 编号 | 口径 |
| --- | --- |
| **`D-L03`** | **必须显式选择用户类型，不可跳过、不可由系统推断。** 角色由**用户点击的入口**确定 |
| **`D-L04`** | **类型选择是路径分流，不是表单切换**：选「资产方」→ 进入离站告知后前往**资产可信平台授权中心**；选「资金方」→ 进入**连接钱包并签名**。**两条路径不共用任何输入控件，也不存在「先填再判断身份」的中间态** |
| **`D-L05`** | `P-L01` 与 `C-L01` 是**同一组件的两种呈现**：两张卡片的标题、说明、按钮文案**必须逐字一致**。弹层形态额外带一行上下文说明（主干 4.2） |
| **`D-L06`** | **两张卡片并列、视觉权重相同**。不得把任一方做成默认选中、高亮或更大——本平台两侧是对等的交易参与方，权重差异会被读成平台立场 |
| **`D-L07`**（**否决项，必须显式保留**） | **「输入邮箱后自动判定身份并路由」维持否决，不得实现。** 三条理由：① 系统回答「这是资产方账户」等于确认该邮箱在资产可信平台存在，属账户枚举；② 本期资产方**根本不采集邮箱**，该方案在资产方一侧无输入可依据；③ 该方案在评审中极易被重新提出（看起来省一次点击），因此否决理由必须留在 PRD 里 |
| **`D-L13`** | **本平台不为资产方提供任何自有账号、密码、验证码登录或兜底入口。** 授权中心不可用时资产方无法登录，这是有意的取舍（风险见 SSO 第 11 章），**不得以「加一套本地凭据」缓解** |
| **`D-L14`** | **本平台不向资产方采集邮箱或任何其他联系方式。** 资产方的身份与联系方式均来自上游，本平台侧无录入入口、无修改入口（SSO 第 9 章） |
| **`D-L15`** | **主按钮按「用什么方式登录」命名，角色作副标**：`第三方授权（资产方）` / `连接钱包（资金方）`。这两个按钮**点下去用户立刻离开本平台的界面**——去到资产可信平台，或看到浏览器里的钱包弹窗。**按钮上写的动作必须就是他下一眼看到的那件事**；写成中性的「继续」，用户不知道下一屏为什么是一个钱包弹窗、或者为什么换了一个网站 |
| **`D-L16`** | **点击入口即开始对应登录路径，两侧都没有重复连接的中间页**：资产方 → 先看到离站告知 `C-L04`，确认后到资产可信平台；资金方 → **直接唤起浏览器里的钱包**。**任一侧都不得插入一个「再点一次同样动作」的本平台页面**——入口按钮写「连接钱包」、下一页主按钮还写「连接钱包」，那一页只让用户多点了一次 |
| **`D-L17`** | **`D-L16` 只合并「连接」这一步，不合并后面的确认。** 资金方侧**连接与签名仍然是两次，签名不自动接着弹**：连接只是让本平台知道用户用的是哪个钱包地址，**不建号、不建会话**，直接弹没有风险；但**签名意味着建号**，在此之前本平台必须先把用途说明、凭据保管须知与协议勾选露给用户看。**签名确认这一层及其失败态归 WS-349**（`P-L20`），本 PRD 到「连接成功」为止，不展开 |

> **卡片 1「将前往资产可信平台登录」这句是必须的**：资产方点下去会离站，用户应当在点之前就知道。正式的离站告知在 `C-L04`，但文案上先打招呼能显著降低跳出。
> **卡片 2 不提邮箱**：资金方的邮箱在机构注册流程中填写，不是登录凭据；在登录入口提邮箱会让用户以为可以用邮箱登录。
> **两张卡片的主按钮文案不对称是有意的**（`D-L15`）：它们分别说的是两件不同的事，而不是同一个「下一步」。卡片的标题、说明仍然对等，**视觉权重也仍然相同**（`D-L06`）——`D-L15` 改的是按钮上写什么，不是谁更突出。
> **选错类型的代价不对称**：选错「资金方」只是多签一次名；选错「资产方」会**在资产可信平台建出一个空账号**，本平台无法撤销。因此卡片说明是唯一的预防手段，不得简化为一个词。

资产方卡片采用较宽泛的「资产」表达，仅调整入口文案；不据此扩大融资业务接受的资产种类。整页采用居中身份选择区域，两卡等权；受限触发使用 `C-L01`，不再额外打开整页。

### 2.4 每次明确选择身份（`F-L03`）

| 编号 | 口径 |
| --- | --- |
| **`D-L08`** | 身份选择页与身份选择弹层均只提供对等的资产方、资金方两条路径；不展示「上次选择」或「直接继续」快捷入口，不记忆身份以供下次快捷登录 |
| **`D-L09`** | 浏览器中即使存在旧版身份选择记录，也不得据此增加快捷入口、默认选中、自动跳转或决定当前身份；退出、重登、换浏览器都遵循同一选择规则 |
| **`D-L10`** | 每次进入身份选择时，必须由用户明确点击本次要使用的身份。当前流程内保留已选路径用于完成本次授权，不等于记忆上次身份 |

`F-L03` 保留原编号，表示本节与 2.5 的身份选择、切换边界；原身份记忆有效期 `N-L02` 停用、不复用。取消离站依旧按 2.6 返回原层，不引入新的快捷入口。

### 2.5 「切换身份」的返回路径

| 场景 | 「切换身份」出现在哪 | 点击后 |
| --- | --- | --- |
| 已选资产方、进到离站告知（`C-L04`）但还没跳走 | 弹层内的次要操作 | 选择「切换身份」时回 `P-L01`（经 `P-L03`）；只取消离站时按 `D-L18` 回到原呈现 |
| 已点「连接钱包」，**钱包弹窗还开着** | 不提供——此刻界面在钱包那边，本平台没有可见的控件 | 用户在钱包弹窗里取消即可，按 `E-L11` **回到仍然可见的 `P-L01`** |
| **已连接成功、尚未签名** | 签名确认层顶部返回区（该层归 **WS-349**） | 回 `P-L01`，**断开本次钱包连接、不保留任何未完成的中间态**；本 PRD 只定这一条返回口径，该层的其余规格不展开 |
| 从授权中心返回、尚未建立会话 | 落地时 | 回 `P-L01` |
| **已登录成功之后** | **不提供** | 已登录用户要换身份，路径是**退出登录**（`ST-2` 回落游客态）后重新选择 |

| 编号 | 口径 |
| --- | --- |
| **`D-L11`** | **切换身份保留原目标意图，不清空机构注册草稿。** 若实际改选角色，按 `D-L36` 重新判断返回目标；草稿由资金方域管理。当前身份仅用于本次流程，不产生下次快捷登录记录 |
| **`D-L12`** | **已登录用户不得出现「切换身份」入口。** 一个已建立会话的用户点「切换身份」，会同时面临「旧会话怎么办」「已产生的业务数据归谁」两个没有答案的问题 |

### 2.6 离站告知与逐层返回（`F-L02` / `F-L08`）

**`D-L18`**：`C-L04` 明确展示目标平台与继续前往、返回操作。确认前不发起离站。点击「返回」、关闭或按 Escape 均只取消本次离站，不建会话、不改变认证、不清空原浏览上下文，也不等同于「切换身份」。

| 来自哪里 | 取消离站后的落点 | 焦点归还 |
| --- | --- | --- |
| `P-L01` 资产方入口 | 原类型选择页 | 原资产方按钮 |
| `C-L01` 身份选择弹层 | 原身份选择弹层，保留触发能力说明 | 原资产方按钮 |
| `C-L02` 认证引导 | 原认证引导弹层 | 原前往认证按钮 |
| `C-L03` 或账户页的认证 / 修改跳链 | 原页面与提示位置 | 原跳链按钮 |

同一时刻只允许操作最上层弹层，键盘焦点在该层内循环；关闭后逐层返回。原触发控件已因状态更新消失时，焦点回到原区域可操作元素或区域标题，不落入已关闭内容。账户页跳链亦遵循本节。见《流程图与状态机》图 1。

## 3. 回跳 `RT-1`～`RT-5`（**安全关键章**）

> **统一规则 `D-L39`**：两类登录及业务引导共用本章的返回规则、安全边界与失败落点；不得各自解释一套。

### 3.1 五条原则（`RT-1`～`RT-5`）

| 编号 | 原则 |
| --- | --- |
| `RT-1` | 回跳目标**不以原始地址的形式在客户端流转** |
| `RT-2` | 回跳目标必须通过**白名单判定**才允许跳转 |
| `RT-3` | 回跳记录与登录流程**同生命周期** |
| `RT-4` | 跨平台回跳须**对端配合并执行同等强度校验** |
| `RT-5` | 目标失效时**静默兜底**，不报错、不白屏 |

### 3.2 原操作的返回信息（`F-L04`）

| 编号 | 产品规则 |
| --- | --- |
| **`D-L20`** | 登录前保留用户原本要去的页面与被拦下的操作；不得让用户通过可复制的登录链接改变目标或冒用他人的返回信息。原始回跳目标不得作为登录过程中的可见参数流转 |
| **`D-L21`** | 返回信息不向用户或其他会话暴露，不在地址栏或可复制的页面内容中泄露凭据。沿用既有主干的回跳保护约束；句柄保管、传递与浏览器存储不在本册展开 |
| **`D-L22`** | 返回信息仅用于本次登录流程；流程完成、放弃或会话结束后失效 |

需保留的业务上下文为原页面、触发能力与所属平台。主动点击登录时没有受限触发能力；登录后仍需先完成必要前置条件，再按 3.6 落地。页面及能力不得超出当前用户可访问范围。

### 3.3 返回目标的安全边界（`RT-2` · `F-L05`）

下列条件均须满足；任一不满足按 3.7 兜底。现有回跳安全约束继续有效，本节只定义可接受目标与拒绝结果，不规定解析算法。

| 编号 | 产品规则 |
| --- | --- |
| **`D-L23`** | 站内返回只能到本平台允许的页面；不得被外部网址、伪装为站内的地址或含歧义的地址带离平台 |
| **`D-L24`** | 不接受依赖特殊编码、路径改写或多次解释才看似合法的目标；不得通过修正可疑目标获得额外访问能力 |
| **`D-L25`** | 目标须属于允许的业务范围（3.3.1）；名称相似但不属于该范围的页面、管理端与内部页面不能放行 |
| **`D-L26`** | 目标不得携带身份凭据、一次性授权、验证码、签名或另一个跳转目标；拒绝时不泄露敏感信息 |
| **`D-L27`** | 仅本次登录、同一用户会话可使用原返回信息；跨会话、跨设备转用无效 |
| **`D-L28`** | 不能仅凭页面宣称的来源或来访平台认定目标可信 |



#### 3.3.1 允许的站内路径前缀清单（`N-L03`）

#### 3.3.2 目标中不得携带的参数类别（`N-L04`）

**回跳目标里不得夹带下列任何一类参数，命中即判定失败。**

| 类 | 这一类是什么 | 为什么不允许 |
| --- | --- | --- |
| **身份与登录凭据类** | 任何用于表示「这个人已经登录了」的参数 | 一条链接就能把别人的登录状态带走 |
| **一次性授权凭据类** | 任何用于换取一次登录的凭据 | 同上，且这类凭据往往可被立刻使用 |
| **验证码与签名类** | 任何一次性验证码或签名 | 泄露即被冒用 |
| **回跳自身类** | 任何用于指定「下一步去哪」的参数 | **防二次跳转**：允许目标里再带一个回跳，等于把校验过的目标变成一个新的跳板 |

> **具体参数名清单**由实现方按上述四类维护，属 `N-L04` 安全配置；**新增或删除任何一项都必须走主干 5.4 同级的变更流程并留痕**。本 PRD 定义的是「哪几类不允许」，不逐一枚举参数名——枚举会随技术方案变动，类别不会。

### 3.4 跨平台回跳与三平台域名精确白名单（`RT-4` · `F-L06` · `N-L05`）

> **本节是相对基线的实质变更**：基线的对端只有一个、且判定落在「平台内同域 + 一张对端登记表」。三平台独立部署后，**同域假设不再成立**，对端登记表升级为**三平台域名精确白名单**。

| 编号 | 口径 |
| --- | --- |
| **`D-L30`** | **三平台域名精确白名单是一份平台级登记表，不是可由调用方传入的参数**。表中每一项登记：平台标识、站点域名、允许回跳到该平台的路径前缀、以及该平台是否已确认执行同等强度校验。**登记表的唯一来源是 3.4.1**，任何链路不得在运行时临时添加对端 |
| **`D-L31`** | **域名判定按完整域名精确比对**：与登记值逐字符相等才算命中，**不做子域匹配、不做后缀匹配、不接受通配符、不接受端口或大小写变体**。这是「精确白名单」四个字的全部含义 |
| **`D-L32`** | **对端必须做同等强度的校验**（`RT-4`）。对端未确认执行 3.3 同等规则的，**不得开启到该平台的跨平台回跳**——我方判定得再严，对端把用户跳走，钓鱼一样成立 |
| **`D-L33`** | 跨平台回跳**必须显式告知即将离开本平台并展示目标平台名称**，载体为离站告知弹层 `C-L04`，**不用 Toast**——Toast 出现即消失，用户来不及读就已经跳走 |
| **`D-L34`** | 跨平台场景同样保护本次返回信息；**用户回到本平台落地时，必须先确认这次返回确实对应本平台发起的那一次授权、且仍是同一个浏览器会话，再消费句柄**，顺序不得颠倒 |

#### 3.4.1 三平台域名精确白名单登记表

| 平台 | 标识 | 站点域名 | 允许的对端路径前缀 | 本期是否开启 | 对端已确认同等校验 |
| --- | --- | --- | --- | --- | --- |
| **借贷平台（本平台）** | `self` | 本平台面客端域名 | 见 3.3.1 | ✅ | — |
| **资产可信平台** | `asset_trust_platform` | 待登记 | 授权中心登录与授权路径；用户中心（实名认证引导的去向） | ✅ **本期唯一的跨平台回跳对端** | **❌ 未确认** —— 见 `E-L06` 与 `[待确认 Q-L01]` |
| **代币发行平台** | `token_issuance_platform` | 待登记 | — | **❌ 本期不开启** | — |

> **`asset_trust_platform` 一行**：授权中心是新增模块，其对外提供信息的形式与回跳校验强度**均未确认**（`Q-L01`）。按 `D-L32`，在对端书面确认执行 3.3 同等规则之前，**跨平台回跳按 3.7 兜底处理、不放行**（`E-L06`）。这**只影响资产方跨平台引导的体验**——用户去授权中心完成认证后回来落在资产广场而不是原来那条资产——**不产生安全问题，也不阻塞开发**。
> **`token_issuance_platform` 一行**：面客端在本期没有前往代币发行平台的用户流程，故登记为占位、**不开启**。开启须走主干 5.4 同级的变更流程并留痕，**不得因为「表里已经有这一行」就当作已放行**。
> **两处「待登记」的域名字面串**：随三平台部署域名确定后填入，**判定规则不受影响**。

### 3.5 有效期与作废时机

| 时机 | 处理 | 编号 |
| --- | --- | --- |
| **超过有效期**（`N-L01`，默认 **30 分钟**，可配置） | 句柄失效，按 3.7 兜底（`E-L02`） | **`D-L35`** |
| **被成功消费一次之后** | **立即作废，一次性使用**。重放同一句柄按失效处理（`E-L05`） | **`D-L35`** |
| 登录 / 注册流程完成、用户中途放弃、会话销毁（含退出登录、会话过期、跨平台失效） | 作废 | `D-L22` |
| **用户在流程中改变了身份类型** | **作废并重新生成**——原句柄记录的触发能力可能不再适用于新身份 | **`D-L36`** |

> `N-L01` 取 30 分钟的理由：它要覆盖「被拦下 → 选身份 → 去授权中心登录 / 连钱包签名 → 回来」这一整段。同时不宜长到让一个被遗忘的标签页在半天后仍能跳转。**这是可调参数，不是安全边界**——安全边界是 3.3 的判定规则。

### 3.6 登录完成后的落地

**两类角色共用下列优先级，必要前置条件完成后才可恢复原操作：**

| 优先级 | 条件 | 落地目标 | 用户看到的表达 |
| --- | --- | --- | --- |
| 1 | 资产方尚未完成本平台必需协议同意 | `P-L11`；完成后继续判定返回目标 | 受限会话，仅可阅读协议、同意或退出 |
| 2 | 资金方首次签名验证成功并建号 | 既有机构注册引导页，归 WS-349 | 账号已创建，开始申请入驻；仍为未认证，不直接执行出资 |
| 3 | 必要前置条件已满足，且存在有效原目标 | 回到原触发点，重新判断权限后恢复原操作 | 合法原浏览上下文保留，无重复点击要求 |
| 4 | 无原目标，或目标失效、不合法、跨平台对端未确认 | 资产广场 | 正常默认进入；无效回跳按 3.7 提示 |

| 编号 | 口径 |
| --- | --- |
| **`D-L37`** | 有效回跳恢复的是被拦下的操作，不仅是页面；前置同意未完成或首次建号仍在入驻引导时，不得借回跳跳过这些步骤 |
| **`D-L38`** | 恢复操作前重新判断当前身份与权限。仍不具备资格则展示相应引导，不报业务成功，不重复创建业务。原触发能力保留供引导说明使用 |

取消登录属于主动放弃，优先恢复合法原浏览页（`D-L19`），不因取消而强制跳默认页。资金方后续业务正文由 WS-349 定义，本册只提供衔接边界。

### 3.7 失效兜底（`RT-5` · `F-L07`）

**目标失效、判定不通过、或跨平台对端未确认时，一律落到该身份的默认落地页 + 一条 Toast，不报错、不白屏、不显示技术错误信息。**

| 身份 | 默认落地页 |
| --- | --- |
| 游客 | 资产广场 |
| 资产方 | 资产广场 |
| 资金方 | 资产广场 |

> **Toast 文案口径**：只说「已为你回到资产广场」这一层，**不暴露判定失败的原因**（如「目标不在白名单内」）——把判定细节讲给用户，等于讲给探测者。失败原因进留痕（3.8），不进界面。

### 3.8 安全与追溯

回跳拒绝应可追溯；跨会话转用、重复使用与夹带凭据的情况须能识别为安全异常。用户只看到中性返回提示，不展示判定细节；追溯资料不得暴露登录凭据、钱包签名原文或可冒用的返回信息。
