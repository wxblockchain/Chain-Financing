# 登录主干与资产方 SSO 接入 · PRD

<a id="scope"></a>
## 1. 目标与阅读入口

用户先以游客浏览资产广场与借贷广场。**唯一的登录方式是连接钱包**：连接钱包、选择地址、完成消息签名，验证通过即登录成功。**登录成功不等于有角色**：本平台在每次登录成功后，用该登录地址与资产可信平台同步过来的账户数据匹配——命中即自动绑定资产方；未命中则为**登录未绑定角色**。用户不选择角色，平台也不提供选择入口。

未绑定角色的用户触发业务动作时按动作归属分流：资产方动作引导前往资产可信平台完成注册与认证；资金方动作直接进入本平台的资金方入驻流程，**提交申请时**绑定资金方角色。一个钱包地址只绑定一个角色，换钱包视为全新用户。能否办理融资由当前有效认证决定；账户和企业资料来自上游，借贷平台只读展示本人资料。

**登录、角色、资料与业务资格是四件独立的事**：签名通过只代表登录成功；绑定角色不代表已认证；资料同步成功也不代表取得业务资格。

本期为桌面 Web，**登录钱包仅支持以太坊（ETH）链**；钱包连接所用的第三方 SDK／服务由研发环节确认，本文不指定选型。**登录所在链与质押链、结算收款链是不同用途的概念，互不决定**：质押链见融资需求与代币质押模块，结算收款链（本期 ETH 与 TRON）见[企业账户 PRD](../v1.0-企业账户/01-企业账户-PRD.md)。本文负责共用钱包登录、角色匹配与绑定、返回、状态及权限规则，以及资产方完整账户链路；资金方入驻表单、审核衔接和账户功能由资金方账户模块负责，收款／出资账户的字段与维护由企业账户模块负责，本文只挂载入口并给出权限取值。本期不增加移动端、资产方本地账号登录或本地实名认证。**本平台本期不签署任何协议**，详见[协议](#agreement)。

**主阅读顺序：第 2～7 章功能 → 第 8 章已裁定口径与依赖 → 第 9 章同序验收。** 流程文字已在对应功能中说明，无需跨册拼接。配套只有[流程图与状态机](./02-登录主干与资产方SSO接入-流程图与状态机.md)和[本模块消息通知](./03-登录主干与资产方SSO接入-消息通知.md)。本册的信息需求与设计职责边界见[职责边界](#design-boundary)；“我的控制台”为用户明确指定的名称，其承载形式由设计决定。

版本：2026-09-24。

## 2. 浏览、钱包登录与角色绑定

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

### 2.1 游客浏览与唯一登录入口

<a id="F-L01"></a><a id="f-l01"></a>
游客访问默认入口、品牌入口或旧首页入口，都进入既有资产广场；没有独立首页。资产广场与借贷广场的游客可达内容直接可读，**不得因未登录而打断阅读**：不主动要求登录、不遮蔽可达内容、不设登录墙。登录入口和语言切换在已登录与未登录时都持续可用，不提供“申请入驻”入口。不可见页面按权限拒绝访问，不强制跳登录页。（F-L01）

<a id="F-L02"></a><a id="f-l02"></a>
只有两种操作发起登录：使用登录入口；触发可见但受限的业务动作，此时就地发起登录、说明被拦下的原操作并保留其意图，用户取消后仍留在原处。两者使用同一条钱包登录路径，**登录前后都不要求用户选择身份**。（F-L02）

| 步骤 | 用户可见结果 |
| --- | --- |
| 发起登录 | 唤起钱包前须先让用户知道本次将连接钱包并请求一次登录签名、签名不涉及转账或资金授权；不插入账号密码、邮箱、验证码等其他登录方式 |
| 连接钱包并选择地址 | 用户在钱包内选择本次登录使用的地址；仅取得地址**不等于登录成功**，不建号、不绑定角色 |
| 消息签名 | 用户在钱包内确认签名；本平台验证签名通过才建立登录，以此确认登录者控制该地址 |
| 登录成功 | 立即按[登录后的角色匹配](#F-L34)判定角色，再到相应落点；匹配未命中时为登录未绑定角色 |

登录不采集邮箱、手机号或其他联系方式，也**不得输入邮箱后自动识别角色**：这会泄露账户是否存在。**一个钱包地址只能绑定一个角色**，同一钱包不能同时是资金方和资产方，见[账户识别与匹配](#F-L22)。本期只支持以太坊（ETH）链钱包，其他链的钱包不在本期范围。

<a id="F-L03"></a><a id="f-l03"></a>
### 2.2 取消、不可用与更换钱包

钱包登录过程中的取消与异常按下表处理。（F-L03）

| 分支 | 用户可见结果与可继续操作 |
| --- | --- |
| 无可用钱包或钱包无法唤起 | 就地说明原因并给实际可执行的下一步；可继续游客浏览，不把用户带到只有报错的结果 |
| 钱包连接取消 | 回到发起登录的原处，登录入口仍可用，不停留在无内容或无出口的中间状态 |
| 拒绝签名或签名验证失败 | 不建立登录、不建号、不绑定角色、不提前披露该地址在本平台是否已有账户；就地可重试或继续游客浏览 |
| 登录成功后希望更换钱包 | 先退出再用另一钱包登录；登录状态下不提供“切换钱包”入口，账户内也没有“更换钱包”功能 |
| <a id="new-wallet-new-user"></a>改用另一个钱包 | **换钱包视为全新用户**：新地址重新执行匹配，不从旧地址继承角色、资料、业务记录或权限。新地址匹配到同一上游稳定账户时按[稳定标识认人](#F-L22)接续原账户与历史；匹配不到则为登录未绑定角色 |
| <a id="wrong-upstream-account"></a>在上游建立了不该建的账号 | 本平台不能撤销该上游账号，也不提供清理上游账号入口；以引导说明帮助用户在上游正确处理 |

<a id="ownership-signature"></a>
**例外：为登记收款地址发起的一次性签名不是登录。** 在[企业账户](../v1.0-企业账户/01-企业账户-PRD.md)登记数币收款地址时，用户会用**被登记的那个地址**签名一次以证明其所有权。该签名**不建立登录会话、不切换登录钱包、不参与登录地址匹配、不改变已绑定角色，也不改绑登录凭据**；被登记地址可以与当前登录地址不同，也可以在另一条结算收款链上。本节“登录状态下不提供切换钱包入口”“换钱包视为全新用户”只针对建立登录身份的签名，不适用于该一次性签名。

<a id="console-role"></a>
### 2.3 登录后的角色匹配与未绑定角色

<a id="F-L34"></a><a id="f-l34"></a>
**角色由系统自动绑定，平台不提供选择角色的入口。** 每次登录成功后（不只首次）都以本次登录地址在上游同步数据中匹配：命中即绑定并进入资产方角色，用户在上游新注册后的下一次登录即自动成为资产方；未命中即为**登录未绑定角色**。匹配结果与绑定关系随本平台账户保存，不依赖浏览器本地记忆，隐私模式或禁用本地存储不影响。（F-L34）

| 当前角色 | 可用范围 |
| --- | --- |
| 登录未绑定角色 | 可浏览资产广场与借贷广场的可达内容，可退出。**我的控制台、个人信息、企业信息、机构信息一律不展示**，也不产生站内信；触发业务动作时按下表分流 |
| 已绑定资产方 | 按认证结论使用资产方业务，资料只读，见[本人账户、企业信息与偏好](#profiles) |
| 已绑定资金方 | 由资金方账户模块承接入驻与账户功能，本文只定义共用登录、返回与权限口径 |

<a id="action-routing"></a>
未绑定角色的用户触发业务动作时，按**动作归属**分流，不要求用户先选角色：

| 触发的动作 | 结果 |
| --- | --- |
| 资产方动作（如发起融资申请、关联应收账款） | 引导前往资产可信平台完成注册与认证；离站前按[离站确认](#leave-confirm)告知目标平台。完成后下次登录匹配命中即绑定资产方 |
| 资金方动作（如发起出资、授信报价） | 直接进入本平台的资金方入驻流程；**提交申请时**绑定资金方角色，具体表单与提交规则见[资金方账户 PRD](./01-资金方登录与账户体系-PRD.md) |
| 两类角色都不适用的受限内容 | 按[受限后的下一步](#guidance)给对应说明，不引导绑定任何角色 |

绑定不向用户额外说明后果，也不要求用户确认“提交即绑定”。

<a id="role-memory"></a>
绑定一经建立即随账户保持，后续登录自动恢复该角色，不重复询问，并接续已有的入驻进度与审核状态（资金方入驻表单在提交前不保存，见[资金方账户 PRD](./01-资金方登录与账户体系-PRD.md)）。换浏览器、退出重登、中断后回访都不改变已有绑定。

<a id="role-change"></a>
**用户不能更改已绑定的角色**，平台不提供改选、解绑或双角色开通入口；需要另一角色时以另一个钱包重新入驻，按[换钱包视为全新用户](#new-wallet-new-user)处理，两个账户彼此独立、资料与历史互不可见。

<a id="leave"></a>
### 2.4 离站确认与返回原位置

<a id="leave-confirm"></a>
前往资产可信平台注册、认证、查看或修改资料，均先告知目标平台名称。确认后才离站；用户取消离站时回到发起处（原浏览页、引导或账户/企业信息），不改变角色绑定、不改变资格、不清空原浏览上下文。**取消离站不改变已建立的钱包登录。**

同一时刻只要求用户处理一件需要确认的事，取消后可从原发起处继续；原触发入口已不存在时，回到该业务仍可继续的位置。当前状态与受限原因须对辅助技术可得。流程见[钱包登录、匹配与返回流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-1)。

## 3. 上游同步、地址匹配与账户建立

### 3.1 同一套匹配判定

<a id="F-L25"></a><a id="f-l25"></a>
资产方身份**不再由用户离站授权建立**，而由上游推送的同步数据与本次登录地址匹配得出。无论用户从本平台登录进入、还是从资产可信平台跳转回来，匹配与绑定都走同一条判定，结果一致；判定期间立即给处理中反馈，不白屏等待，也不阻塞游客浏览。见[登录、匹配与账户流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-2)。（F-L25）

<a id="F-L20"></a><a id="f-l20"></a>
上游同步与推送数据必须**来源可信且面向本平台**：本平台服务端确认数据确由资产可信平台发出、未被篡改、属于本平台的同步范围，才能用于匹配、绑定与资料展示；仅声称“来自资产可信平台”不能作为信任依据。无法确认来源的数据不参与匹配、不改动既有绑定、不结束任何登录，并产生安全告警，见[来源异常处理](#change-alert)。同步数据的范围、粒度与时效属待核实依赖。（F-L20）

<a id="F-L21"></a><a id="f-l21"></a>
引导用户前往资产可信平台注册或认证时，上游已有登录的优先免二次输入；若仍需用户操作，最多回退一次完整登录，不反复弹回。真实能力属于待核实依赖。用户在上游取消或浏览器后退时，**保留本平台已建立的钱包登录**，回到发起处继续，不视为业务操作成功。（F-L21）

### 3.2 账户识别、匹配结果与绑定

<a id="F-L22"></a><a id="f-l22"></a>
**上游稳定、不可变的账户标识是本平台资产方账户的主体**；**钱包地址是匹配入口与登录凭据，不是账户主体**。首次匹配命中即建立本平台账户，后续复用；同一上游账户更换登记地址不产生新账户、不拆分历史。邮箱、企业标识都不用于认人或合并账户。稳定标识缺失的数据不能用于建立账户。一个钱包地址只绑定一个角色，同一钱包不能同时存在资产方与资金方账户。（F-L22）

| 结果 | 匹配结果与用户可见处理 |
| --- | --- |
| <a id="account-success"></a>命中且上游账户可用 | 建立或复用本平台资产方账户与地址绑定，同步获准资料与当前认证结论，进入资产方角色 |
| <a id="account-unavailable"></a>命中但上游账户锁定或禁用 | 不绑定，结束该主体已有的本平台登录；就地回游客视图，显示实际可取得的解除信息，不捏造 |
| 未命中 | 不绑定，用户停留在登录未绑定角色态，可继续浏览或按[动作分流](#action-routing)办理；不提示该地址是否曾经存在于上游 |
| 曾绑定过、现因上游换地址而匹配不到 | 说明“该地址在资产可信平台的登记已变更，请使用新地址登录”，不静默当作全新用户 |
| 命中但本平台账户建立失败 | 唯一需要用户单独处理的失败结果“建号失败”：同时给出错误码、重试和继续浏览两条出路；不得静默返回或留下无出口的结果 |

<a id="F-L35"></a><a id="f-l35"></a>
<a id="binding-check"></a>
**地址匹配只有两种业务结果：命中与未命中。**（F-L35）

| 匹配情况 | 业务处理 |
| --- | --- |
| 登录地址在上游同步数据中命中唯一账户 | 绑定该上游稳定账户，完成资料同步 |
| 未命中 | 保持登录未绑定角色，不猜测、不按邮箱或企业名称近似匹配、不自动接管任何历史账户 |
| 命中多个上游账户 | 业务上不存在该情况；一旦出现按数据异常处理：不绑定、不取其中任一条，产生告警并就地给中性说明 |

<a id="address-normalize"></a>
**比较口径**：登录地址本期只比较以太坊（ETH）链地址（企业账户登记的收款地址按结算收款链另行校验，不参与登录匹配）。同一地址的不同书写形式（checksum 大小写差异、带与不带 `0x` 前缀等）必须视为同一地址；上游登记的地址不属于本期支持的链或格式时无法比较，按未命中处理并产生告警。规范化的具体实现由开发按 EVM 规范完成，产品只要求上述业务结果。

<a id="binding-cardinality"></a>
**绑定基数**：一个上游资产方账户同时只有一个有效登录地址；一个钱包地址只绑定一个角色。上游把登记地址改为新地址后，用户以新地址登录即接续原账户与历史，旧地址绑定同时失效，见[上游变更的同步](#F-L36)。

<a id="binding-login"></a>
**身份可信性**：上游在登记钱包地址时已验证登记人控制该地址，本平台在登录时以消息签名验证控制权；两端验证的是同一地址的控制权，因此匹配即绑定成立，不再要求用户另做一次授权确认。上游的这项验证能力属接入前必须核实的事项，见[真实接入核实项](#dependency-wallet)。

<a id="F-L24"></a><a id="f-l24"></a>
所有失败不暴露内部判定原因。数据来源不可信、缺少稳定标识、一个地址命中多个账户等配置或数据异常须产生运维告警；这不是向运营人员发站内信。**建号失败是唯一需要用户单独处理的失败结果**，其余失败就地说明并保留可继续的出口。恢复原页不代表可以继续读取其受保护内容。（F-L24）

### 3.4 上游变更的同步与通知

<a id="F-L36"></a><a id="f-l36"></a>

| 机制 | 内容 | 本期定位 |
| --- | --- | --- |

| 变更类型 | 业务影响与处理 |
| --- | --- |

| 上游账户禁用／锁定 | 结束该主体的本平台资产方登录，沿[退出与失效](#F-L27)的既定时限 |

| 有效企业归属变更 | 确认即更新；资料始终对应当前有效企业，待审企业不提前替代 |
| 个人／企业基本资料变更 | 仅影响展示，下次登录或下次读取时更新即可，不要求秒级 |
| 上游删除或撤回字段可见权限 | **本期不考虑上游撤权**，系统实现不做；相关旧值处理待该场景纳入范围后再定义 |

<a id="change-alert"></a>
无法确认来源的同步或变更数据不影响合法登录与既有绑定，须产生安全告警，不能凭一条无法验证的通知改动绑定关系或结束登录。推送丢失、延迟或上游推送不可用时由登录与关键动作前核对兜底并记录接入缺口，不能以“等下一次用户访问”充当及时性承诺。见[上游变更处理流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-7)。

## 4. 登录后回到原页面与原操作

### 4.1 返回顺序与失败结果

<a id="F-L04"></a><a id="f-l04"></a>
登录前保留原页面、被拦下的操作及目标平台；主动登录没有原业务动作。**钱包签名成功后立即执行地址匹配**：命中即以资产方角色回原目标；未命中则保持登录未绑定角色，原操作意图仍保留，触发时按[动作分流](#action-routing)办理——资产方动作引导去上游注册认证，资金方动作进入入驻流程。有有效目标则返回，无目标则进入资产广场。（F-L04）

<a id="return-permission"></a>
回到原触发点时重新判断当前权限：允许才恢复操作，仍受限则展示对应引导（未绑定角色按动作归属分流，已绑定但未认证给认证引导）；不能把登录成功当作已取得角色或融资/出资已成功，也不能重复创建业务。返回规则由本章统一定义，两类角色及各业务共用，不再各写一套。

<a id="return-lifetime"></a>
返回信息只用于本次登录，有效期默认 **30 分钟（可配置）**且只能成功使用一次；完成、放弃或登录结束后失效。不能被其他会话、设备冒用；实际切换角色须重新判定。用户可见或可复制的登录信息不暴露可冒用的返回内容或凭据。

<a id="F-L07"></a><a id="f-l07"></a>
无效、过期或不允许的目标，统一回资产广场并给中性提示，不白屏、不展示内部拒绝原因；过期可提示“链接已失效，已为你回到资产广场”，其他拒绝只说明“已为你回到资产广场”。正常默认进入和取消登录恢复浏览不伪报失败。重复使用、跨会话冒用等安全异常须可追溯。（F-L07）

## 5. 当前资格、业务权限与受限引导

<a id="state-contract"></a>
<a id="F-L11"></a><a id="f-l11"></a>
### 5.1 登录、角色与认证分别判断

**角色与认证是两条独立的轴。** 角色共四种取值：游客、登录未绑定角色、登录已绑定资产方、登录已绑定资金方；认证结论另行判断，同一角色下可以已认证或未认证。签名通过只代表登录有效，不代表已绑定角色；已绑定角色不代表认证有效；认证仍有效但登录已失效时仍是游客。本期没有协议受限登录态。（F-L11）

| 状态信息 | 业务含义与默认 |
| --- | --- |
| 是否登录 | 必须明确；由钱包签名验证结果决定，默认游客 |
| 当前角色 | 资产方或资金方。游客必须为空；**已登录时可以为空，表示登录未绑定角色**，此时按[登录后的角色匹配与未绑定角色](#F-L34)的范围使用平台。角色只能来自地址匹配命中（资产方）或提交入驻申请（资金方），**不由用户选择，也不从邮箱或企业名称推断** |
| 当前业务资格 | 必须明确；默认未取得有效认证，由服务端权威判定。未绑定角色时恒为未取得资格 |
| 当前账户 | 本平台本人账户标识；游客为空，登录未绑定角色时也为空（资产方账户在匹配命中时建立，资金方账户在提交入驻申请时建立），不用钱包或企业标识替代 |
| 钱包地址绑定 | 两种取值：未绑定 / 已绑定。见[地址匹配](#F-L35)；原“钱包待重新确认”取值已停用，地址变更改为终止登录，见[上游登记钱包地址变更](#wallet-change) |

<a id="whole-state"></a>
以上状态整体取用，所有业务使用同一套状态，不各自读取原始审核状态猜资格；客户端伪造角色或资格不能放行。判定存在冲突时采用较低有效资格，不能据单个较高结果越权。

| 资格阶段 | 资产方 | 资金方的共用语义 |
| --- | --- | --- |
| 未绑定角色 | 登录未绑定角色，两类角色的业务均不开放；只能浏览可达内容、按动作分流办理或退出 | 同左 |
| 未完成认证 | 未取得当前有效已认证结论，按已登录未激活处理 | 已签名建号、机构资料未提交（含未填写及草稿），按已登录未激活处理 |
| 审核中 | 不适用；异常出现时按未完成认证并记录异常 | 待审核，机构资料锁定，不允许编辑、撤回或回到未提交状态；仍为已登录未激活 |
| 已驳回 | 不适用；异常出现时按未完成认证并记录异常 | 可按所属模块规则修改重提；仍为已登录未激活 |
| 已认证 | 上游确认当前有效已认证，按已登录已激活处理 | 已认证，按已登录已激活处理 |

<a id="funder-visibility"></a>
资金方未提交、审核中、已驳回的信息可见范围一致，差异在提示与可执行动作；账户联系方式与机构资料是不同功能，不把审核中机构资料锁定扩大成所有账户操作锁定。详细行为见[资金方账户 PRD](./01-资金方登录与账户体系-PRD.md)。需要核对已有状态代码和字段名时，查[文末对照](#state-code-reference)。

### 5.2 认证更新与发起融资

<a id="F-L29"></a><a id="f-l29"></a>
资产可信平台是认证权威，本平台只读，不自建审核、修改或拼装认证结论。**只认当前有效综合认证结论**；个人或企业单项通过、资料齐全、申请审核进度都不能代替它。更新审核中仍保留有效认证时不自行降级；失效或驳回后的有效资格同样以上游结论为准。未知取值按未认证处理并告警，不猜测新状态。（F-L29）

<a id="qualification-refresh"></a>
匹配命中时取得当前结论；会话内认证刷新参考时限为 **5 分钟**，在受限判定点对过旧状态刷新。上游推送到达后即时刷新，但不以推送为唯一更新手段。读取失败可沿旧快照继续浏览，但不能当作已经确认新资格，也不能误报“认证被收回”。上游完成认证后刷新即可生效，无需退出重登；下次登录的匹配立即读取当前结果。

<a id="F-L31"></a><a id="f-l31"></a>
资产方唯一硬卡点是**发起融资申请**，动作前必须实时确认资格，旧的已认证快照不能放行；同一判定点一并核对绑定仍然有效（上游登记地址已变更时登录已被终止，不会走到这一步）。等待时显示“正在确认资格”，不重复发起；无法确认则说明申请尚未发起并可重试。未认证时显示认证引导，即使绕过界面发起请求也不创建融资申请。（F-L31）

<a id="qualification-late"></a>
等待中发生认证降级、退出、过期、换角色或离开页面，迟到的通过结果不能恢复旧权限、显示操作成功或把用户拉回旧流程。仍在原页且已降级时给认证引导；重新进入后重新判断。此等待不是新账户状态，也不定义融资提交自身的结果。

<a id="confirmed-downgrade"></a>
确认由有效已认证降为非已认证时，及时降低权限，下次进入明确解释当前限制，并向受影响的资产方本人发送一条强制站内信；发送时点、去重与文案统一见[通知册](./03-登录主干与资产方SSO接入-消息通知.md#event)。不因消息投递失败保留已失效权限。见[认证资格与融资流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-4)。

<a id="permission-ownership"></a>
每行按能力或动作定义，不以整页为单位授权；取值由所属模块提供，主干合并，不能两处各定一版，也不能为审核中与未提交另加列。受限默认保留可解释的 ⊘，受限原因须对辅助技术可得；仅隐私要求或展示本身泄露信息时取 ❌ 并说明理由。“修改邮箱／联系方式”对资产方不可见，是因为联系方式完全由上游维护、本平台不提供此动作。

<a id="permission-data-scope"></a>
**“维护收款 / 出资账户”一行覆盖企业账户的查看总览与新增、修改、删除、默认标记**，取值由[企业账户 PRD](../v1.0-企业账户/01-企业账户-PRD.md#p-ea-01)与[资金方账户 PRD](./01-资金方登录与账户体系-PRD.md#permissions)同名能力共同确认，三处不各定一版；不为“查看账户总览”另开一行，也不构成第二个资产方硬卡点。未认证的两类角色取 ⊘：入口仍可见可触达，触达时按[受限后的下一步](#guidance)给补齐引导，不隐藏入口、不整页封锁。

原“钱包待重新确认时资金类动作临时冻结”的取值调整**已停用**：上游登记地址变更改为直接终止登录，不再有冻结态。资金方取值继续查[资金方账户 PRD](./01-资金方登录与账户体系-PRD.md)的同名能力，本轮不重写或覆盖。“账户设置”“查看本人有效归属企业信息”仅允许本人资料；“资产明细字段”“合同／发票／附件影像”“交易对手联系方式”等只授权相应业务已确认必要信息，不能据此开放整份基本资料、个人证件或认证材料。具体字段脱敏由业务模块定义；不得先把敏感原文交给无权用户再遮盖。游客排序筛选只能使用区间，不能据精确排序反推敏感值。

<a id="guidance"></a>
### 5.4 受限后的下一步

<a id="F-L08"></a><a id="f-l08"></a>
共用引导的行为由本主干统一定义，具体业务文案由所属模块提供。游客触发受限能力打开钱包登录；登录未绑定角色时按[动作归属分流](#action-routing)——资产方动作引导去上游注册认证，资金方动作进入入驻流程；已绑定角色但未满足资格时打开认证/补全引导。引导说明“缺什么、补完能做什么、去哪里补”，适用时补充审核状态或驳回说明，不只写“无权限”“请先登录”。关闭不改变任何账户状态；前往补齐须保留原操作，跨平台先离站确认，返回仍按第 4 章。（F-L08）

<a id="F-L30"></a><a id="f-l30"></a>
登录未绑定角色的用户仍可浏览资产广场与借贷广场的可达内容，不全局封锁；引导按动作归属给出，不要求也不提供选择角色的入口。未认证资产方仍可浏览可达业务、本人账户、企业信息和消息，不全局封锁。资金方未提交机构资料时指向机构注册；审核中只读展示审核状态及真实可用辅助信息，不暗示修改/撤回、不捏造时长或客服渠道；已驳回时指向查看原因并修改重提。审核说明引用资金方账户／机构审核模块当前已确认内容，不另规定字段级驳回模型。（F-L30）

<a id="F-L09"></a><a id="f-l09"></a>
已登录存在待补齐事项时，平台须持续提醒该事项，且**不因用户阅读正文而丢失、也不遮蔽正文**；用户可在本次会话内暂时收起，但不能永久关闭，事项完成即消失。原“钱包待重新确认”常驻提醒项与“未选择角色”项**均已停用**。同一时刻只呈现优先级最高的一项，其余以“还有 N 项待完成”可展开查看；优先级为已驳回→未提交/未认证→审核中→降级说明，最高项完成后下一项接替。用户处理某一事项期间，仍能看到自己原来在做什么，取消离站可回到原处。游客不适用此提醒。本册只定义触发、展示条件与解除条件，呈现形式由设计决定。（F-L09）

<a id="profiles"></a>
## 6. 本人账户、企业信息与偏好

### 6.1 进入与只读边界

<a id="F-L32"></a><a id="f-l32"></a>
登录后须持续可见一个账户入口，展示**本次登录钱包地址**的可辨识标识：缩略展示时须保留大小写且完整地址可核对，地址本身足够短时完整展示。该地址来自本次已验证的登录凭据而非上游快照，异常读取不到时显示“我的账户”，不使用假地址、不阻断登录。账户入口下可用的事项：已绑定资产方时显示当前角色“资产方”，提供“账户设置”“企业信息”“企业账户”和**全平台唯一的主动退出入口**；**登录未绑定角色时只有登录地址标识与退出**，不出现我的控制台、账户设置、个人信息、企业信息、机构信息或企业账户。（F-L32）

<a id="enterprise-account-entry"></a>
**企业账户入口**：面客端提供“企业账户”独立入口，**资产方与资金方一致**，用于维护法币与数币收款／出资账户；资金方侧在其账户与机构信息入口清单中同步登记，由[资金方账户 PRD](./01-资金方登录与账户体系-PRD.md#account)承接。未认证的已绑定角色仍可见、可触达该入口并得到补齐引导，取值见[统一权限矩阵](#permissions)的“维护收款 / 出资账户”一行。账户设置继续只管登录钱包只读信息、联系邮箱与偏好，**不把收款账户字段混入账户设置**；字段定义、校验与维护规则全部归[企业账户 PRD](../v1.0-企业账户/01-企业账户-PRD.md)。

账户设置可独立访问并可返回原处，包含账户信息、个人信息及偏好三组内容且彼此可区分；长地址和邮箱全文可核对。

<a id="F-L33"></a><a id="f-l33"></a>
企业信息独立于账户设置，可直接访问并可回到原业务浏览入口；名称不使用“机构信息”，账户设置内不重复整套企业资料。（F-L33）

<a id="read-only-profile"></a>
只读资料统一说明“这些信息由资产可信平台维护”，提供经离站确认的上游查看/修改入口。不提供任何编辑入口（包括不可用状态的编辑入口）、本地资料录入、提交审核、材料上传/预览/下载或本地企业切换、成员管理。绕过界面的资料修改同样拒绝。上游表单必填不等于借贷端要求补填。未认证者仍有前往完成认证入口，资料已存在不代表已认证。

账户设置中不展示登录状态、不提供第二个退出入口、不要求手动保存偏好，也不展示内部编号或规则论证。语言偏好可写，须与上游只读资料可区分。流程见[资料与偏好流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-5)。

<a id="profile-visibility"></a>
### 6.2 谁可看、何时更新

<a id="F-L23"></a><a id="f-l23"></a>
个人和企业基本资料**仅当前合法登录的本平台资产方本人及其有效企业归属可见**。同一人以另一钱包登录的资金方账户、同企业其他账户、其他资产方和运营人员均不因此获得访问权，已认证者也不能看他人基本资料。账户页误入的资金方进入自身账户页；企业页误入的资金方回可达资产广场并提示不适用。游客不能读取；登录未绑定角色的用户既无本平台账户也无可展示资料，相关入口一律不展示。（F-L23）

<a id="business-fields"></a>
业务办理需要的信息自动获取，只按该业务已有的对象、必要字段和角色权限展示，不开放整组本人资料，不要求借贷端手填上游资料。可选缺失不阻断业务；必要信息不足、主体不明或读取失败，只限制依赖该信息的动作，说明原因并提供返回及适用重试/上游查看，不把旧资料伪装成已确认当前信息。

<a id="profile-refresh"></a>
匹配命中时取得当前获准资料及同步时间；此后按[上游变更的同步与通知](#F-L36)在每次登录成功后及关键动作前核对，从上游返回后读取当前资料。**本期不考虑上游撤回资料可见权限**，该分支不实现；未返回字段、读取失败不等于删除。资料永远对应当前有效企业，待审核企业变更不提前替代有效企业。退出、换账户或有效归属变化后不残留旧资料，迟到结果不得重新展示他人或旧主体信息。

| 证件类型 | 身份证、护照等只作模板参考，以真实供给为准 |
| 证件号码 | 供给及脱敏尚未明确的部分不显示真实明文，不臆造展示/脱敏规则 |

**读取中、读取失败与确实无数据三种情况必须可区分**：读取中给明确的处理中反馈；读取失败说明失败并可重试，不伪装成空数据；单项可选值确实缺失时不展示该项。个人信息整组缺失保留其空态，企业 id 或整组企业信息缺失仍保留企业信息入口与空态，并提供适用的上游查看出口。身份证影像、企业证明、授权材料、审核记录不属于本模块基本资料展示。

<a id="preferences"></a>
### 6.4 语言偏好与通知说明

<a id="language-save"></a>
语言可选 English / 简体中文，无已保存值时沿当前平台语言。改选即保存，不要求用户另做保存确认；保存进行中须给处理中反馈且该项在完成前不能再次触发，不影响其他已生效偏好，同值不重复保存。成功后生效并提示“偏好设置已保存”，刷新、重进及重登回显最后成功值；失败时提示“保存失败，请重新选择”，选项及实际生效值都恢复保存前值，可再选重试。

## 7. 退出、失效与既定时效

<a id="F-L27"></a><a id="f-l27"></a>
主动退出只有全平台唯一一个入口（位于账户入口下），结束本平台登录，不级联退出资产可信平台。到期、上游账户锁定/禁用也结束相应本平台登录。**上游资产可信平台的普通退出不再结束本平台的钱包登录**：本平台登录凭据是本次钱包签名，与上游会话是两回事；用户在上游正常登出后，本平台仍可继续按当前角色与资格使用，直到本平台登录自身到期或用户主动退出。此口径已由用户裁定，见[本期已裁定的关键口径](#pending-decisions)。（F-L27）

| 结束或限制的原因 | 用户可见结果 |
| --- | --- |
| 主动退出 | 就地回游客视图并说明，不退出上游，不跳登录页 |
| 本平台登录到期 | 原页面就地回游客视图并说明，受保护内容不可继续读取，不自动跳转或弹登录页 |
| 上游账户锁定或禁用 | 结束该主体的本平台登录，就地游客视图并说明；显示实际可取得的解除信息，不编造 |
| 上游登记钱包地址变更 | **结束该地址对应的本平台登录**，就地说明“资产可信平台登记的钱包地址已变更，请重新登录”，见[上游登记钱包地址变更](#wallet-change) |
| 有效认证失效 | 不结束登录，按[认证降级](#confirmed-downgrade)限制融资资格并发本人强制站内信 |
| 上游资料授权撤销 | **本期不考虑**，系统实现不做 |

前四类结束登录的原因均在原页面就地回游客视图并给说明，受保护内容不可继续读取，不自动跳转或弹出登录页；认证失效只限制相应动作，不结束登录。原“钱包待重新确认不结束登录、只冻结资金类动作”一行**已停用**。

<a id="F-L28"></a><a id="f-l28"></a>
不能确认来源的退出、禁用或变更告知不影响合法登录与既有绑定，须产生安全告警；重复告知不反复打扰。上游禁用告知延迟或丢失仍须满足禁用生效时限，不能仅等待下一次用户访问。登录失效时尚未保存的内容提示未保存，不暂存草稿；迟到操作结果不能恢复登录。见[登录与绑定状态图](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-3)。（F-L28）

| --- | --- |

以下代码沿用原定义，日常阅读使用[登录、角色与认证的业务说明](#state-contract)。

游客、已登录未激活、已登录已激活分别为 T1、T2、T3。**登录未绑定角色**不另造 T 代码，取值为 `session_state=authenticated`、`identity_type` 为空、`completeness_level=L0`、`account_id` 为空，可见范围与游客一致。登录有效不代表已绑定角色，已绑定角色不代表认证有效；认证仍有效但登录已失效时仍是游客。本期没有协议受限登录态。

| 共用状态字段 | 业务含义、取值与默认 |
| --- | --- |
| `session_state` | 必须有值：`guest` / `authenticated`；默认 `guest` |
| `identity_type` | 当前角色：`asset_party` / `funder`；游客必须为空；**已登录时可以为空，表示登录未绑定角色**；只能来自地址匹配命中或提交入驻申请，不由用户选择，也不从邮箱、企业名称推断 |
| `completeness_level` | 必须有值：`L0` / `L1` / `L2` / `L3`；默认 `L0`；业务资格由服务端权威判定 |
| `account_id` | 本平台当前账户标识；游客及登录未绑定角色时必须为空，不以钱包或企业标识替代。资产方账户在匹配命中时建立，资金方账户在提交入驻申请时建立 |
| 钱包地址绑定 | 无历史代码，业务取值见[地址匹配](#F-L35)：未绑定 / 已绑定 |

以上状态整体取用，所有业务使用同一套状态，不各自读取原始审核状态猜资格；客户端伪造资格不能放行。判定存在冲突时采用较低有效资格，不能据单个较高结果越权。

| 完备度 | 资产方 | 资金方的共用语义（正文归 资金方账户模块） |
| --- | --- | --- |
| L0 | 未取得当前有效已认证结论 | 签名已建号、机构资料未提交，含未填写及草稿 |
| L1 | 不适用；异常出现时按 L0 并记录异常 | 待审核，机构资料锁定，不允许编辑、撤回或回到 L0 |
| L2 | 不适用；异常出现时按 L0 并记录异常 | 已驳回，可按所属模块规则修改重提 |
| L3 | 上游确认当前有效已认证 | 已认证 |
