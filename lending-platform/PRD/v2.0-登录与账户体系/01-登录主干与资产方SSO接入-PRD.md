# 登录主干与资产方 SSO 接入 · PRD

<a id="scope"></a>
## 1. 目标与阅读入口

用户先以游客浏览资产广场与借贷广场，主动登录或遇到受限操作时进入**唯一的钱包登录入口**：连接钱包并完成消息签名即登录成功。登录成功时可以尚未选择角色，用户在“我的控制台”选择资金方或资产方，角色一经确认即记住，后续登录不再重复选择。资金方接续机构认证；资产方在完成本平台必需协议后授权关联资产可信平台，校验钱包地址一致性后建立绑定并同步个人、企业与认证信息。能否办理融资由当前有效认证决定。账户和企业资料来自上游，借贷平台只读展示本人资料。

**登录成功、角色确定、资料同步、业务资格四件事分别判断**：签名通过只代表登录成功；选定角色不代表已关联或已认证；资料同步成功不代表认证通过。

本期为桌面 Web。本文负责共用钱包登录入口、角色选择、返回、状态及权限规则，以及资产方完整账户链路；资金方从建号后的机构注册、审核衔接和账户功能由资金方账户模块负责。资金方机构多附件等仍归资金方账户模块。本期不增加移动端、资产方本地账号登录或本地实名认证。

**主阅读顺序：第 2～7 章功能 → 第 8 章依赖与待确认决策 → 第 9 章同序验收。** 流程文字已在对应功能中说明，无需跨册拼接。配套只有[流程图与状态机](./02-登录主干与资产方SSO接入-流程图与状态机.md)和[本模块消息通知](./03-登录主干与资产方SSO接入-消息通知.md)。页面布局沿已批准设计，本文不增加布局要求；“我的控制台”为用户明确指定的页面名称，其分区与布局留设计判断。

版本：2026-09-22。

有效依据为本模块已确认业务规则、用户 2026-09-22 两轮明确口径（统一钱包登录与消息签名、控制台内选择角色、未选角色可浏览、已授权用户免选身份、钱包地址一致性校验、上游变更及时同步）、用户最新资料可见范围与通知政策。本轮按需求诊断简报推荐落稿的决策集中在[按推荐落稿、待确认的决策](#pending-decisions)，尚未取得用户裁定；资产可信平台实际供给仍按第 8 章核实。本模块仅保留主 PRD、流程图与状态机、消息通知三册；历史分册见 [cly2.0.0 分支](https://github.com/wxblockchain/Chain-Financing/tree/cly2.0.0/lending-platform/PRD/v2.0-登录与账户体系)。正文按业务名称阅读，现用功能编号在对应功能保留一次，验收编号在对应验收行保留一次；历史条款、状态代码及权限行号在文末按需查询。时间、数量、业务字段和验收结果不因呈现调整而删减。

## 2. 浏览、钱包登录与选择角色

### 2.1 游客浏览与唯一登录入口

<a id="F-L01"></a><a id="f-l01"></a>
游客访问默认入口、品牌入口或旧首页入口，都进入既有资产广场；没有独立首页。资产广场与借贷广场的游客可达内容直接展示，不主动弹登录、遮挡正文或设置登录墙。顶部保留“登录”和语言切换，不显示“申请入驻”。不可见页面按权限拒绝访问，不强制跳登录页。（F-L01）

<a id="F-L02"></a><a id="f-l02"></a>
只有两种操作发起登录：点击顶部“登录”；点击可见但受限的业务动作，此时在原页面打开登录，补充一行原操作的上下文说明并保留操作意图。**两处使用同一条钱包登录路径，不再出现身份选择卡片，也不再有两条按角色区分的登录入口。**（F-L02）

| 步骤 | 用户可见结果 |
| --- | --- |
| 点击“登录” | 先说明本次将连接钱包并请求一次登录签名、签名不涉及转账或资金授权，再唤起钱包；不插入账号密码、邮箱、验证码等其他登录方式 |
| 连接钱包 | 仅取得钱包地址，**不等于登录成功**，不建号、不建立任何角色 |
| 消息签名 | 用户在钱包内确认签名；本平台验证通过才建立登录 |
| 登录成功 | 进入“我的控制台”或回到合法原目标；**此时可以尚无角色**，按[已登录未选角色](#F-L34)的范围使用平台 |

登录不采集邮箱、手机号或其他联系方式，也**不得输入邮箱后自动识别角色**：这会泄露账户是否存在。角色只能由用户在控制台明确选择或由既有绑定恢复，不能从钱包地址、邮箱或企业名称推断。同一钱包在本平台的资金方账户与资产方账户互不冲突的既有边界不变，见[账户识别与绑定](#F-L22)。

<a id="F-L03"></a><a id="f-l03"></a>
### 2.2 取消、不可用与更换钱包

钱包登录过程中的取消与异常按下表处理。（F-L03）

| 分支 | 用户可见结果与可继续操作 |
| --- | --- |
| 无可用钱包或钱包无法唤起 | 留在原页面就地说明，并给实际可执行的下一步；可继续游客浏览，不进入错误页 |
| 钱包连接取消 | 回到发起登录的原页面或控制台入口，登录入口仍可操作，不留下空白或中间态 |
| 拒绝签名或签名验证失败 | 不建立登录、不建号、不提前披露该钱包是否已有账户；就地可重试或继续游客浏览 |
| 登录成功后希望更换钱包 | 先退出再用另一钱包登录；登录状态下不提供“切换钱包”入口。不同钱包不继承角色、资料、机构草稿或权限 |
| 已绑定资产方账户后更换钱包 | 属于绑定变更，按[登录钱包与上游账户的绑定](#F-L35)处理，不通过重新登录自动换绑 |
| <a id="wrong-upstream-account"></a>选错角色并在上游建立了空账号 | 本平台不能撤销该上游账号，也不提供清理上游账号入口；以控制台说明帮助用户正确选择 |

<a id="console-role"></a>
### 2.3 我的控制台与选择角色

<a id="F-L34"></a><a id="f-l34"></a>
登录成功后进入“我的控制台”。**已登录未选角色**是一个正式状态：用户可以不选角色，继续浏览资产广场与借贷广场的可达内容，也可以随时回控制台选择。未选角色时，控制台只提供角色选择与必要说明，不展示任一角色的业务区、账户资料或企业信息，不产生站内信；具体可用范围见[统一权限矩阵](#permissions)。（F-L34）

| 用户选择 | 接下来发生什么 |
| --- | --- |
| 资金方 | 完成本平台必需协议后进入机构认证流程（填写、待审、驳回重提），由资金方账户／机构审核模块承接；审核通过才取得出资相关业务权限 |
| 资产方 | 完成本平台必需协议后，先说明即将前往资产可信平台、将授权哪些资料、以及要求上游登记的钱包地址与本次登录钱包一致；确认后离站授权，返回时按[授权、绑定与同步](#authorization)处理 |
| 暂不选择 | 停留在已登录未选角色态，可继续浏览可达内容或退出；点击需要角色的能力时给“先选择角色”的引导，不自动代选 |

<a id="role-memory"></a>
角色一经确认即记住，**后续登录自动恢复该角色，不再重复选择**；换浏览器、退出重登、入驻中断都不重新询问，并接续机构认证草稿、审核状态或资产方关联进度。角色归属随本平台账户与绑定关系恢复，不依赖浏览器本地记忆，隐私模式或禁用本地存储不影响。

<a id="role-change"></a>
选错角色且**尚未建立资产方绑定、未提交机构认证、未产生任何业务记录**时，允许回控制台重新选择；已有绑定或业务记录时不通过再次选择覆盖，须按对应模块的变更规则处理。本期一个钱包在正常使用中只进入一个默认角色，不新增双角色自助开通；历史同钱包双角色账户的归属处理见[未决依赖](#pending-dependency)，不自动合并也不丢弃任一账户。

### 2.4 离站确认与返回原位置

<a id="leave-confirm"></a>
前往资产可信平台授权、认证、查看或修改资料，均先告知目标平台名称。确认后才离站；点击返回、关闭或 Escape，恢复原控制台、认证引导、提示条或账户/企业页，不发起授权、不改变资格、不清空原浏览上下文。**取消离站不改变已建立的钱包登录，也不取消已选择的角色。**

弹层打开时焦点进入弹层，只允许最上层操作；关闭后回到原触发控件，控件已不存在时回该区域的可用位置。控制台角色卡键盘顺序为资产方→资金方，提示条折叠控件有可读标签。流程见[钱包登录、选择角色与返回流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-1)。

## 3. 资产方关联可信平台、绑定与协议同意

### 3.1 两个发起入口，一条完成流程

<a id="F-L25"></a><a id="f-l25"></a>
从资产可信平台发起，或在本平台控制台选择资产方发起，返回后都立即展示“处理中”，依次完成授权有效性确认、上游账户可用性确认、**钱包地址一致性校验**、本平台账户建立或更新与绑定、资料同步，再按第 4 章落地。不会白屏等待，也不因入口不同产生不同角色、绑定或协议规则。从上游入口进入而本平台尚无有效登录时，**先完成钱包登录**再继续本流程，上游登录不能替代本平台钱包登录。见[授权、绑定与协议流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-2)。（F-L25）

### 3.2 授权结果、账户识别与钱包绑定

<a id="F-L20"></a><a id="f-l20"></a>
本平台服务端须确认授权来自可信授权中心、面向本平台、仍有效且属于本次发起的授权，只能返回预先登记的唯一授权落地位置，不能仅靠界面验证。一次授权只能完成一次关联，不能在其他浏览器或上下文冒用；重复使用失败不影响已建立的有效登录与绑定。仅声称“来自资产可信平台”不能作为信任依据。处理中状态须可读屏播报，登录状态检查不阻塞游客浏览。（F-L20）

<a id="F-L21"></a><a id="f-l21"></a>
上游已有登录时优先免二次输入；若仍需用户操作，最多回退一次完整登录，不反复弹回。真实能力属于待核实依赖；待完成授权保留 15 分钟，完成或放弃即失效。上游取消或浏览器后退时，**保留本平台已建立的钱包登录与已选角色**，停在“尚未关联”，可重试、改选（未产生记录时）或继续按当前权限浏览，不视为业务操作成功。（F-L21）

<a id="F-L22"></a><a id="f-l22"></a>
本平台资产方账户只以**上游稳定、不可变的账户标识**识别。首次成功建立本平台账户，后续复用；邮箱、钱包地址、企业标识都不用于认人或合并账户。**钱包是已验证的登录凭据，不是识别依据**：同一人更换钱包不产生新账户、不拆分历史，持有他人钱包也不能冒领上游账户。联系方式或有效企业变化不产生新账户；同钱包的资金方账户与资产方账户互不冲突。稳定标识缺失不能完成关联，其他可选资料缺失不阻断关联，展示规则见第 6 章。（F-L22）

| 结果 | 关联及页面处理 |
| --- | --- |
| <a id="account-success"></a>授权有效、上游账户可用、钱包地址校验通过、账户建立或更新成功 | 建立或复用本平台资产方账户与钱包绑定，同步获准资料；若当前登录钱包已绑定另一资产方账户，拒绝本次绑定并进入冲突核实，资料始终隔离 |
| <a id="account-unavailable"></a>上游账户锁定或禁用 | 不建立绑定，结束该主体已有本平台资产方登录；就地游客视图，显示实际可取得的解除时间或客服入口，不捏造信息 |
| 授权失败、超时、无效身份或缺少稳定标识 | 不建立绑定、不同步资料；**保留已建立的钱包登录**，在合法原目标给中性提示和可复述错误码，可重试或继续按当前权限浏览。不影响与本次失败无关的有效登录与绑定 |
| 钱包地址不一致 | 不完成关联、不覆盖任何一方、**不结束已有钱包登录**，按[一致性校验](#F-L35)给两条出路 |
| 上游授权成功，但本平台账户建立失败 | 唯一独立失败页“建号失败”：同时有错误码、重试、继续浏览；不得静默返回或留下死胡同 |

<a id="F-L35"></a><a id="f-l35"></a>
<a id="binding-check"></a>
**登录钱包与上游账户的绑定及一致性校验。** 一致性校验是架在稳定标识认人之上的附加约束，用于确认“正在操作的钱包”与“上游登记的钱包”属于同一人，**不替代[稳定标识认人](#F-L22)**。（F-L35）

| 上游钱包地址状态 | 业务处理 |
| --- | --- |
| 有，且规范化后与本次登录钱包一致 | 通过，建立“上游稳定标识 ↔ 已验证登录钱包”的绑定，正常完成资料同步 |
| 有，但不一致 | 不完成本次关联、不覆盖任何一方、不结束已有钱包登录，也不据此判定欺诈。就地说明并给两条可执行出路：换用与资产可信平台登记一致的钱包登录；或先到资产可信平台更新钱包地址后重试 |
| 缺失（上游未提供该可选字段） | 无法校验。以本次已签名验证的钱包完成绑定，并在账户资料中标注“钱包地址未经资产可信平台确认”；上游支持登记时引导用户回上游补登记。此项按推荐落稿，见[待确认决策](#pending-decisions) |

<a id="address-normalize"></a>
**比较口径**：同一地址的不同书写形式（EVM checksum 大小写差异、带与不带 `0x` 前缀等）必须视为同一地址，不得判为不一致；不同链的地址格式不同，不能直接按字符串比对。上游登记地址所属的链与格式范围属于待核实依赖，规范化的具体实现由开发按各链规范完成，产品只要求上述业务结果。

<a id="binding-cardinality"></a>
**绑定基数**：一个上游资产方账户同时只有一个有效登录钱包；同一钱包不得同时绑定两个不同的上游资产方账户。同钱包的资金方账户仍与资产方账户互不冲突。命中冲突时拒绝本次绑定，不合并、不覆盖、不自动抢占，进入冲突核实。此项按推荐落稿，见[待确认决策](#pending-decisions)。

<a id="binding-login"></a>
**授权后的登录**：再次以已绑定钱包登录时，签名通过即恢复资产方角色、免选身份，并按[上游变更的同步](#F-L36)核对上游账户可用性、钱包地址一致性、有效企业与认证结论；一致且账户可用才正常进入，出现不一致或账户禁用按本节及第 7 章处理，不静默放行。未命中绑定的钱包视为新钱包，回到已登录未选角色态，**不因地址相近、邮箱相同或企业同名自动接管任何历史账户**。

<a id="F-L24"></a><a id="f-l24"></a>
所有失败不暴露内部判定原因。身份来源错误、缺少稳定标识、登记落地位置不一致、绑定冲突等配置或数据异常须产生运维告警；这不是向运营人员发站内信。除建号失败页外，不新增授权失败页。恢复原页不代表可以继续读取其受保护内容。（F-L24）

<a id="agreement"></a>
<a id="F-L26"></a><a id="f-l26"></a>
### 3.3 必需协议同意

**必需协议的触发点是“确认角色”这一步**：用户在控制台确认资产方或资金方后、离站授权或进入机构认证之前，完成当前必需协议清单。清单由协议管理模块提供，不在本模块写死。钱包登录签名不等于协议同意；**资产可信平台签署的是上游侧协议，不能代替本平台必需协议**。（F-L26）

未完成必需协议时只有受限登录，**只可访问协议同意页、协议正文、资产广场与借贷广场的游客可达内容以及退出**，不能进入账户页、关联授权或其他业务。已登录未选角色且未触发角色确认时不强制弹出协议页。

协议正文可匿名查看、下载；阅读不代表同意。页面只有一个同意复选框，不自动勾选；未勾选不能提交。加载失败可重试；保存期间不能重复提交，失败继续受限并允许重试，成功后才继续落地。保留当时用户、同意时间、语言、协议版本及原文，后续修改不能覆盖原同意记录。

拒绝或关闭同意流程按放弃本次角色确认处理：回到已登录未选角色态或退出后的游客浏览，不循环拉回协议页。两个资产方授权入口及资金方入口均执行以上规则。

<a id="change-sync"></a>
### 3.4 上游变更的同步与通知

<a id="F-L36"></a><a id="f-l36"></a>
资产方完成关联后，上游资料、企业归属、认证结论和钱包地址的变化必须及时反映到本平台。本期按以下分层落地，**上游是否具备主动推送尚未确认**，承诺分层见[待确认决策](#pending-decisions)。（F-L36）

| 层 | 机制 | 本期定位 |
| --- | --- | --- |
| 主动推送 | 上游在变更发生时向本平台推送变更事件 | 接入目标；取决于上游能力，确认前不写入时限承诺 |
| 登录与关键动作前核对 | 每次钱包登录成功后，以及发起融资等关键动作前，读取上游当前资料与结论并核对 | **本期必达保底；即使主动推送落地也保留**，推送可能丢失或延迟 |
| 定期刷新 | 对活跃账户按周期刷新 | 可选，不作为本期承诺 |

| 变更类型 | 业务影响与处理 |
| --- | --- |
| 上游账户禁用／锁定 | 结束该主体的本平台资产方登录，沿[退出与失效](#F-L27)的既定时限 |
| 有效认证结论失效 | 停止融资资格并按[认证降级](#confirmed-downgrade)发本人强制站内信，规则不变 |
| <a id="wallet-change"></a>钱包地址变更 | 属于凭据级事件，按下文单独处理 |
| 有效企业归属变更 | 确认即更新；资料始终对应当前有效企业，待审企业不提前替代 |
| 个人／企业基本资料变更 | 仅影响展示，下次登录或下次读取时更新即可，不要求秒级 |
| 上游删除或撤回字段可见权限 | 移除旧值，见[资料刷新](#profile-refresh)；这不等于地址变更，不触发换绑处理 |

**钱包地址变更的处理**：不自动把本平台登录凭据换成新地址——上游数据可能滞后或录错，静默换绑等于把账户交给未经本平台签名验证的地址；也不立即结束当前登录——误报会把用户锁在门外且没有自助出路。处理方式为：账户标记“钱包待重新确认”，**立即冻结资金类动作**（发起融资、签署协议、维护收款账户等），保留浏览与本人资料查看，并向本人发送一条强制站内信，见[通知册](./03-登录主干与资产方SSO接入-消息通知.md#event-wallet)。解除路径二选一：用新地址连接并完成一次登录签名，且本次授权确认其对应同一上游稳定账户后换绑到原账户；或用户到上游改回原地址，下次核对一致即自动解除标记。换绑全程**不建新账户、不拆分历史**。

无法确认来源的变更推送不影响合法登录与既有绑定，须产生安全告警，不能凭一条无法验证的通知改动绑定关系或结束登录。推送丢失或延迟时由登录与关键动作前核对兜底，不能以“等下一次用户访问”充当及时性承诺。见[钱包绑定与上游变更流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-7)。

<a id="return"></a>
## 4. 登录后回到原页面与原操作

### 4.1 返回顺序与失败结果

<a id="F-L04"></a><a id="f-l04"></a>
登录前保留原页面、被拦下的操作及目标平台；主动登录没有原业务动作。**钱包签名成功后先判断角色**：已有绑定或已记住角色的用户直接恢复角色；尚无角色的用户先回“我的控制台”选择角色，原操作意图仍保留。确认角色后先完成必需协议，资产方继续关联授权，资金方首次进入机构注册引导，再考虑原目标。其他正常登录有有效目标则返回，无目标则进入资产广场。（F-L04）

<a id="return-permission"></a>
回到原触发点时重新判断当前权限：允许才恢复操作，仍受限则展示对应引导（未选角色给选择角色引导，未认证给认证引导）；不能把登录成功当作已取得角色、已完成关联或融资/出资已成功，也不能重复创建业务。返回规则由本章统一定义，两类角色及各业务共用，不再各写一套。

<a id="return-lifetime"></a>
返回信息只用于本次登录，有效期默认 **30 分钟（可配置）**且只能成功使用一次；完成、放弃或登录结束后失效。不能被其他会话、设备冒用；实际切换角色须重新判定。用户可见或可复制的登录信息不暴露可冒用的返回内容或凭据。

<a id="F-L07"></a><a id="f-l07"></a>
无效、过期或不允许的目标，统一回资产广场并给中性提示，不白屏、不展示内部拒绝原因；过期可提示“链接已失效，已为你回到资产广场”，其他拒绝只说明“已为你回到资产广场”。正常默认进入和取消登录恢复浏览不伪报失败。重复使用、跨会话冒用等安全异常须可追溯。（F-L07）

<a id="F-L05"></a><a id="f-l05"></a>
### 4.2 允许范围与跨平台边界

返回目标须满足以下范围。（F-L05）

| 范围 | 判定要求 |
| --- | --- |
| <a id="allowed-pages"></a>站内业务页 | 仅面客端已登记业务范围；允许前缀暂按 `/`（资产广场）、`/assets`、`/financing`、`/funding`、`/console`、`/onboarding`、`/account`、`/messages`、`/about`、`/faq`、`/agreement`，字面路径仍待页面登记对齐。`/` 只指默认页，不代表全部路径 |
| <a id="excluded-pages"></a>不可返回的位置 | 登录选择、中转、授权处理、首登协议、签名流程本身，以及管理端、内部资源、静态资源和未允许外站。正常账户/企业页不因编号相邻被误排除 |
| <a id="unsafe-target"></a>歧义与敏感目标 | 伪装外站、歧义分隔、多次解释/编码、近似业务名、改写后越界的目标均拒绝，不通过自动修正放行；目标不能夹带用户信息片段、登录凭据、验证码、签名或另一跳转目标 |
| <a id="F-L06"></a><a id="f-l06"></a>平台登记（F-L06） | 三平台完整域名精确匹配；子域、近似后缀、端口、大小写变体、通配均不能代替已登记值。由统一平台登记维护，调用方不能临时加白名单 |
| <a id="cross-platform-closed"></a>本期跨平台实际状态 | 借贷平台站内可用；资产可信平台的正式域名及对端同等返回校验尚未确认，**跨平台返回暂不开放，完成授权后按资产广场兜底**；代币发行平台即使有登记，本期也不开启 |

<a id="return-change-control"></a>
允许路径、禁止携带的内容和平台白名单属于安全边界，变更须按共用规则统一审定、登记及留痕，不作为普通时长配置调整。

<a id="return-authority"></a>
返回目标由服务端按本章判定，不能仅凭来访平台声明或前端检查放行。回跳允许不等于访问允许，落地仍检查身份和业务权限。跨平台返回待确认不阻止资产方授权登录本身。浏览器后退、页面恢复、第三方 Cookie 受限时均须有可继续操作的页面。既定 OIDC、back-channel logout 跨平台登出通知和精确白名单约束保留，具体接入方式由开发设计。

<a id="qualification"></a>
## 5. 当前资格、业务权限与受限引导

<a id="state-contract"></a>
<a id="F-L11"></a><a id="f-l11"></a>
### 5.1 登录、角色与认证分别判断

游客、已登录未选角色、已登录未激活、已登录已激活是四种共用访问状态。**签名通过只代表登录有效**，不代表已有角色；有角色不代表认证有效；认证仍有效但登录已失效时仍是游客。必需协议未同意的受限登录先执行[协议同意规则](#agreement)，不能借资格表进入业务。（F-L11）

| 状态信息 | 业务含义与默认 |
| --- | --- |
| 是否登录 | 必须明确；由钱包签名验证结果决定，默认游客 |
| 当前角色 | 资产方或资金方。游客必须为空；**已登录时可以为空，表示已登录未选角色**，此时按[我的控制台与选择角色](#F-L34)的范围使用平台。角色只能来自用户明确选择或既有绑定恢复，**不能从钱包地址、邮箱或企业名称推断** |
| 当前业务资格 | 必须明确；默认未取得有效认证，由服务端权威判定。未选角色时恒为未取得资格 |
| 当前账户 | 本平台本人账户标识；游客为空，已登录未选角色时也为空（资产方账户在完成绑定时建立，资金方账户按其模块规则建立），不用钱包或企业标识替代 |
| 钱包绑定状态 | 资产方适用：未绑定 / 已绑定 / 已绑定但未经可信平台确认 / 钱包待重新确认。取值影响资金类动作，见[登录钱包与上游账户的绑定](#F-L35)与[钱包地址变更](#wallet-change) |

<a id="whole-state"></a>
以上状态整体取用，所有业务使用同一套状态，不各自读取原始审核状态猜资格；客户端伪造角色或资格不能放行。判定存在冲突时采用较低有效资格，不能据单个较高结果越权。

| 资格阶段 | 资产方 | 资金方的共用语义 |
| --- | --- | --- |
| 未选角色 | 已登录未选角色，两类角色的业务均不开放；只能浏览可达内容、选择角色或退出 | 同左 |
| 未完成认证 | 未取得当前有效已认证结论，按已登录未激活处理 | 已签名建号、机构资料未提交（含未填写及草稿），按已登录未激活处理 |
| 审核中 | 不适用；异常出现时按未完成认证并记录异常 | 待审核，机构资料锁定，不允许编辑、撤回或回到未提交状态；仍为已登录未激活 |
| 已驳回 | 不适用；异常出现时按未完成认证并记录异常 | 可按所属模块规则修改重提；仍为已登录未激活 |
| 已认证 | 上游确认当前有效已认证，按已登录已激活处理 | 已认证，按已登录已激活处理 |

<a id="funder-visibility"></a>
资金方未提交、审核中、已驳回的信息可见范围一致，差异在提示与可执行动作；账户联系方式与机构资料是不同功能，不把审核中机构资料锁定扩大成所有账户操作锁定。详细行为见[资金方账户 PRD](./01-资金方登录与账户体系-PRD.md)。需要核对已有状态代码和字段名时，查[文末对照](#state-code-reference)。

### 5.2 认证更新与发起融资

<a id="F-L29"></a><a id="f-l29"></a>
资产可信平台是认证权威，本平台只读，不自建审核、修改或拼装认证结论。**只认当前有效综合认证结论**；个人或企业单项通过、资料齐全、申请审核进度都不能代替它。更新审核中仍保留有效认证时不自行降级；失效或驳回后的有效资格同样以上游结论为准。未知取值按未认证处理并告警，不猜测新状态。（F-L29）

<a id="qualification-refresh"></a>
授权成功时取得当前结论；会话内认证刷新参考时限为 **5 分钟**，在受限判定点对过旧状态刷新。若上游可提供变化告知，获知后即时刷新，但不以此作为唯一更新手段。读取失败可沿旧快照继续浏览，但不能当作已经确认新资格，也不能误报“认证被收回”。上游完成认证后刷新即可生效，无需退出重登；再次授权立即读取当前结果。

<a id="F-L31"></a><a id="f-l31"></a>
资产方唯一硬卡点是**发起融资申请**，动作前必须实时确认资格，旧的已认证快照不能放行；同一判定点一并核对当前钱包绑定状态，处于[钱包待重新确认](#wallet-change)时资金类动作被冻结，给重新确认引导而不是认证引导。等待时显示“正在确认资格”，不重复发起；无法确认则说明申请尚未发起并可重试。未认证时显示认证引导，即使绕过界面发起请求也不创建融资申请。**冻结与未认证是两回事**，不得互相替代或叠加为同一提示。（F-L31）

<a id="qualification-late"></a>
等待中发生认证降级、退出、过期、换角色或离开页面，迟到的通过结果不能恢复旧权限、显示操作成功或把用户拉回旧流程。仍在原页且已降级时给认证引导；重新进入后重新判断。此等待不是新账户状态，也不定义融资提交自身的结果。

<a id="confirmed-downgrade"></a>
确认由有效已认证降为非已认证时，及时降低权限，下次进入明确解释当前限制，并向受影响的资产方本人发送一条强制站内信；发送时点、去重与文案统一见[通知册](./03-登录主干与资产方SSO接入-消息通知.md#event)。不因消息投递失败保留已失效权限。见[认证资格与融资流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-4)。

<a id="permissions"></a>

### 5.3 统一权限矩阵

## 6. 本人账户、企业信息与偏好

### 6.1 进入与只读边界

<a id="F-L32"></a><a id="f-l32"></a>
登录后顶部账户入口显示**本次登录钱包地址**前 6 字符（含前缀）＋省略号＋后 4 字符；不超过 10 字符时完整展示，保留大小写。悬浮或键盘聚焦可读全文；该地址来自本次已验证的登录凭据而非上游快照，异常读取不到时显示“我的账户”，不使用假地址、不阻断登录。悬浮、点击和键盘均可展开菜单：正常资产方登录时菜单内显示“资产方”，提供“账户设置”“企业信息”和唯一主动退出入口；**已登录未选角色时菜单只显示“未选择角色”、进入“我的控制台”选择角色和退出**，不出现账户设置与企业信息内容。（F-L32）

账户设置为独立页面，带面包屑，包含账户信息、个人信息及偏好；长地址和邮箱全文可核对。

<a id="F-L33"></a><a id="f-l33"></a>
企业信息为另一个独立详情页，面包屑可回原业务浏览入口，名称不使用“机构信息”，账户页不重复整套企业资料。（F-L33）

<a id="read-only-profile"></a>
只读资料组统一说明“这些信息由资产可信平台维护”，提供经离站确认的上游查看/修改入口。没有编辑按钮（包括灰色按钮）、本地资料录入、提交审核、材料上传/预览/下载或本地企业切换、成员管理。绕过界面的资料修改同样拒绝。上游表单必填不等于借贷端要求补填。未认证者仍有前往完成认证入口，资料已存在不代表已认证。

账户页不设登录状态分区、退出按钮或“保存偏好”按钮，不展示内部编号或规则论证。语言偏好可写，需与上游只读资料区分。流程见[资料与偏好流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-5)。

<a id="profile-visibility"></a>
### 6.2 谁可看、何时更新

<a id="F-L23"></a><a id="f-l23"></a>
个人和企业基本资料**仅当前合法登录的本平台资产方本人及其有效企业归属可见**。同钱包资金方、同企业其他账户、其他资产方和运营人员均不因此获得访问权，已认证者也不能看他人基本资料。账户页误入的资金方进入自身账户页；企业页误入的资金方回可达资产广场并提示不适用。游客不能读取，未同意协议者仍只能按第 3.3 节访问。（F-L23）

<a id="business-fields"></a>
业务办理需要的信息自动获取，只按该业务已有的对象、必要字段和角色权限展示，不开放整组本人资料，不要求借贷端手填上游资料。可选缺失不阻断业务；必要信息不足、主体不明或读取失败，只限制依赖该信息的动作，说明原因并提供返回及适用重试/上游查看，不把旧资料伪装成已确认当前信息。

<a id="profile-refresh"></a>
授权成功更新当前获准资料及同步时间；此后按[上游变更的同步与通知](#F-L36)在每次登录成功后及关键动作前核对，从上游返回后读取当前资料。上游明确删除或撤回可见权限时移除旧值；未返回字段、读取失败不等于删除。资料永远对应当前有效企业，待审核企业变更不提前替代有效企业。退出、换账户或有效归属变化后不残留旧资料，迟到结果不得重新展示他人或旧主体信息。

<a id="session"></a>
## 7. 退出、失效与既定时效

<a id="F-L27"></a><a id="f-l27"></a>
主动退出只在账户菜单提供，结束本平台登录，不级联退出资产可信平台。到期、上游账户锁定/禁用也结束相应本平台登录。**上游资产可信平台的普通退出不再结束本平台的钱包登录**：本平台登录凭据是本次钱包签名，与上游会话是两回事；用户在上游正常登出后，本平台仍可继续按当前角色与资格使用，直到本平台登录自身到期或用户主动退出。此项为本轮按推荐落稿的修改，见[待确认决策](#pending-decisions)。（F-L27）

| 结束或限制的原因 | 用户可见结果 |
| --- | --- |
| 主动退出 | 就地回游客视图并说明，不退出上游，不跳登录页 |
| 本平台登录到期 | 原页面就地回游客视图并说明，受保护内容不可继续读取，不自动跳转或弹登录页 |
| 上游账户锁定或禁用 | 结束该主体的本平台登录，就地游客视图并说明；显示实际可取得的解除信息，不编造 |
| 上游资料授权撤销 | 不结束登录，移除受影响的旧值并限制依赖该信息的动作，见[资料刷新](#profile-refresh) |
| 有效认证失效 | 不结束登录，按[认证降级](#confirmed-downgrade)限制融资资格并发本人强制站内信 |
| 钱包待重新确认 | 不结束登录，冻结资金类动作并给重新确认出路，见[钱包地址变更](#wallet-change) |

以上三类结束登录的原因均在原页面就地回游客视图并给说明，受保护内容不可继续读取，不自动跳转或弹出登录页；其余三类只限制相应动作，不结束登录。

<a id="F-L28"></a><a id="f-l28"></a>
不能确认来源的退出、禁用或变更告知不影响合法登录与既有绑定，须产生安全告警；重复告知不反复打扰。上游禁用告知延迟或丢失仍须满足禁用生效时限，不能仅等待下一次用户访问。登录失效时尚未保存的内容提示未保存，不暂存草稿；迟到操作结果不能恢复登录。见[登录与绑定状态图](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-3)。（F-L28）

| 项目 | 既定口径 |
| --- | --- |
| <a id="session-period"></a>资产方钱包登录有效期 | 1 周（暂定），无“记住我”；资金方时效由资金方账户模块独立定义，共用退出后游客态结果。统一入口不自动统一两类角色的时长，最终取值待确认 |
| <a id="logout-deadline"></a>上游账户禁用／锁定后本平台失效 | ≤60 秒，须验证真实能力，不能用 5 分钟认证刷新替代 |
| <a id="upstream-logout"></a>上游普通退出 | 不联动结束本平台钱包登录（按推荐落稿，待确认）；原“上游退出后 ≤60 秒结束本平台登录”的联动口径仅保留给账户禁用／锁定 |
| <a id="change-sync-timing"></a>上游变更同步 | 每次登录成功后及资金类动作前必须核对，属本期必达保底；主动推送为接入目标，上游能力确认前不承诺秒级同步，见[上游变更的同步与通知](#F-L36) |
| <a id="silent-performance"></a>免二次输入体验 | 资产方关联授权中，本平台发起的免输入全程 P95 ≤2 秒；无法免输入最多回退一次完整登录 |
| 认证刷新、待完成授权、返回信息 | 分别为 5 分钟参考、15 分钟、30 分钟，见所属功能；不能互相替代 |
| <a id="baseline-constraints"></a>身份有效期兼容与审计保留 | 沿用既有身份有效期兼容、审计保留约束及[基准定义](https://github.com/wxblockchain/Chain-Financing/blob/1ac445bd344c5511efc02df616539ff0c87fdf94/lending-platform/PRD/v2.0-登录与账户体系/01-资产方SSO接入.md)，本次不更改、不展开技术校验 |

<a id="audit-results"></a>
钱包登录签名验证结果、角色确认、授权结果、绑定建立与变更、资料同步、协议同意、登录建立/失效及原因、禁用与变更告知均须可追溯；联系方式脱敏、地址缩略，登录凭据、签名原文、返回句柄不进入日志。产品验收核对行为及上述已确认约束，算法、报文、存储与传输方式由开发设计。

以下代码沿用原定义，日常阅读使用[登录、角色与认证的业务说明](#state-contract)。

游客、已登录未激活、已登录已激活分别为 T1、T2、T3。本次新增的**已登录未选角色**不另造 T 代码，取值为 `session_state=authenticated`、`identity_type` 为空、`completeness_level=L0`、`account_id` 为空，可见范围与游客一致。登录有效不代表已有角色，有角色不代表认证有效；认证仍有效但登录已失效时仍是游客。必需协议未同意的受限登录优先执行[必需协议同意](#agreement)，不能借下表进入业务。

| 共用状态字段 | 业务含义、取值与默认 |
| --- | --- |
| `session_state` | 必须有值：`guest` / `authenticated`；默认 `guest` |
| `identity_type` | 当前角色：`asset_party` / `funder`；游客必须为空；**已登录时可以为空，表示已登录未选角色**；只能来自用户明确选择或既有绑定恢复，不能从邮箱、钱包推断 |
| `completeness_level` | 必须有值：`L0` / `L1` / `L2` / `L3`；默认 `L0`；业务资格由服务端权威判定 |
| `account_id` | 本平台当前账户标识；游客及已登录未选角色时必须为空，不以钱包或企业标识替代。资产方账户在完成绑定时建立 |
| 钱包绑定状态 | 无历史代码，业务取值见[登录钱包与上游账户的绑定](#F-L35)；资产方适用，影响资金类动作 |

以上状态整体取用，所有业务使用同一套状态，不各自读取原始审核状态猜资格；客户端伪造资格不能放行。判定存在冲突时采用较低有效资格，不能据单个较高结果越权。

| 完备度 | 资产方 | 资金方的共用语义（正文归 资金方账户模块） |
| --- | --- | --- |
| L0 | 未取得当前有效已认证结论 | 签名已建号、机构资料未提交，含未填写及草稿 |
| L1 | 不适用；异常出现时按 L0 并记录异常 | 待审核，机构资料锁定，不允许编辑、撤回或回到 L0 |
