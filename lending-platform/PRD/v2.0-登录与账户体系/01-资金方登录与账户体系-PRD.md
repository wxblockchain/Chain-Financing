# 资金方登录与账户体系 PRD

版本：2026-09-24。任务：资金方登录与账户（WS-372）。适用：借贷平台桌面 Web 面客端。业务基线为当前资金方账户规则、登录主干三册和机构认证审核 V2.5；具体来源见文末追溯说明。

## 1. 目标与阅读方式

让用户用自己的钱包登录借贷平台，填写机构资料并提交入驻申请；审核通过后获得认证业务权限。登录身份、角色绑定、机构认证和账户是否可用是四件不同的事：钱包签名证明地址控制权，提交申请绑定资金方角色，机构审核决定业务资格，停用限制账户访问。**填写过程中的信息不入库，只有提交才保存。**

主流程：**连接钱包 → 选择地址 → 消息签名（登录由[登录主干](./01-登录主干与资产方SSO接入-PRD.md#F-L02)统一承担）→ 登录未绑定角色时触发资金方动作即进入入驻流程 → 验证联系邮箱、填写机构资料 → 提交申请（此时建立资金方账户并绑定该地址）→ 查看通过或驳回结果。** 已认证账户变更机构资料时重新提交审核；账户联系邮箱的修改不触发机构重审。用户不选择角色，平台也没有选择角色的入口。

产品、开发和设计连续阅读钱包登录、机构注册、审核权限、账户设置与会话安全（第 2～6 章）；外部依赖集中在“共用规则与仍需落实的依赖”（第 7 章）；测试阅读“验收要求”（第 8 章）。配套：[流程图与状态机](./02-资金方登录与账户体系-流程图与状态机.md)、[独立消息通知](./03-资金方登录与账户体系-消息通知.md)。图册表达业务关系，完整功能规则以本册为准。正文及交叉引用均以业务名称为主：每条功能规则以“业务名称（功能标识）”开头，每条验收以“验收场景名称（验收标识）”标注，两类标识各只出现一次；验收场景名称说明这一条验收的是哪种情形，不重复功能名称。既有细条款锚点继续定位具体规则或验收行，不需要阅读旧版 PRD。

SPV 与正常运营是同一职责范围，不增加资金方分类、独立注册／认证轨道或角色切换；运营登录不会建立资金方会话，也不新增代付、代确认或钱包操作权限。全册业务时间以实际发生时点为准，采用平台既定 UTC 同源时间及用户时区展示并标注时区，显示偏好不改变先后和限频时长。

## 2. 钱包登录与首次建号

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

### 2.1 登录并入主干，入驻由动作触发

<a id="F-L50"></a><a id="f-l50"></a>**钱包登录并入主干（F-L50）**：**本册不再定义独立的资金方登录入口**。用户通过[共用钱包登录](./01-登录主干与资产方SSO接入-PRD.md#F-L02)连接钱包、选择地址并完成消息签名；登录时不选择角色。登录未绑定角色的用户触发资金方业务动作（发起出资、授信报价等）时，直接进入本册的资金方入驻流程，见[动作分流](./01-登录主干与资产方SSO接入-PRD.md#action-routing)。存在多个钱包时由用户选择，不默认取第一个；Web 中使用移动钱包时保留既有二维码／深链连接能力，不扩展为独立移动端产品。钱包需支持连接、断开、地址和网络变更提示及身份签名；本期仅支持以太坊（ETH）链，具体钱包与第三方 SDK／服务由研发环节确认。

连接取消、钱包锁定或连接未成功时回到发起登录的原处，不进入签名确认，也不建立登录。没有可用钱包、连接能力加载失败时就地说明原因，保留安装／适用钱包指引与重试，不把用户带到只有报错、无法继续的结果，也不提供邮箱登录替代。已进入签名确认后发起的重新连接被取消，回到未连接状态。

### 2.2 连接后确认签名

<a id="P-L20"></a><a id="p-l20"></a><a id="C-L20"></a><a id="c-l20"></a><a id="F-L51"></a><a id="f-l51"></a>**确认签名与异常反馈（F-L51）**：连接成功后进入签名确认。连接本身不建立账户或登录态，也不自动唤起签名。用户在确认前必须同时可得只读钱包地址、签名用途与凭据保管提示，由用户主动发起后才请求签名。**本期本平台不签署任何协议**，签名确认处没有协议同意环节，见[登录主干的协议口径](./01-登录主干与资产方SSO接入-PRD.md#agreement)。

| 展示信息／操作 | 业务含义与规则 |
| --- | --- |
| 钱包地址 | 来自本次实际连接的钱包，必有值、只读、可复制；格式为 `0x` 加 40 位十六进制字符，不提供手填。大小写不同视为同一地址，统一小写标准值参与身份比对；缩略展示时仍可核对全文，区块浏览器查看沿共用钱包规则 |
| 签名用途 | 本端请求前与钱包内的用途声明均说明：不发起交易、不消耗 gas、不转移或授权任何资产；本端须先行说明，不能只由钱包自身的提示承担 |
| ~~同意协议~~ | **已停用**：本期不签任何协议，签名确认处不出现协议勾选或同意记录 |
| 重新连接 | 重新唤起钱包；新地址整体替换旧回显，清除未完成的签名过程，不继承另一地址的确认结果 |
| 返回原处 | 各状态均有出口；断开本次连接、清除未完成签名，原业务意图按共用主干保留；本次入驻填写内容不保存 |

| 钱包签名确认页状态 | 出现条件 | 用户可做什么及结果 |
| --- | --- | --- |
| 签名确认 | 已连接且网络支持 | 确认信息后签名、重新连接、返回原处；拒签留在此处提示并可重试 |
| 未连接 | 从签名确认发起重新连接后取消、锁定或连接失败 | 解锁或重新连接、返回原处；不建立登录态 |
| 网络不支持 | 连接返回不受支持的网络 | 提示切换受支持 EVM 网络后重试，或重连、返回；不建立登录态 |
| 地址冲突 | 提交入驻申请时发现地址已被另一账户或另一角色占用 | 说明地址占用，可换钱包重新登录或联系现有客服；不建立第二个角色、不合并账户 |
| 账户已停用 | 签名身份验证通过后确认账户停用 | 明确停用原因范围及客服入口，可返回或游客浏览；不新建会话，相关既有会话失效 |

<a id="F-L52"></a><a id="f-l52"></a>**签名有效期与单次使用（F-L52）**：签名请求一次有效，有效期 **5 分钟**。已用或过期时拒绝并准备新的签名请求，由用户重新确认签名；硬件钱包较慢不能导致页面早于该时限自行超时。

<a id="F-L53"></a><a id="f-l53"></a>**身份验证与失败处理（F-L53）**：签名身份必须与本次连接地址一致，实际使用的网络也必须受支持，不能只靠界面限制。身份不一致、验签失败或签名中换地址时中止本次登录，说明原因并允许重试；换地址提供“用该地址重新登录”，不静默切号或改绑。

签名失败不累计账户锁定次数、不锁账户。既定防滥用阈值为同一 IP **1 小时内验签失败超过 20 次后降速**，不封禁 IP，不连带锁定账户。既定签名安全约束沿用[既定钱包签名安全约束](https://github.com/wxblockchain/Chain-Financing/blob/327a9554522a3829fdadac7967ed4e0b905709a9/lending-platform/PRD/v2.0-登录与账户体系/05-资金方登录与账户体系-功能需求说明.md)：签名请求由服务端提供并校验。此处不展开实现。

### 2.3 登录身份与落点

<a id="F-L55"></a><a id="f-l55"></a>**资金方账户建立与已有账户识别（F-L55）**：**签名登录本身不建立资金方账户**；用户在入驻流程中**成功提交申请时**才建立本平台资金方账户并把该地址绑定为资金方角色。账户具有稳定内部身份，账户正常、机构注册为审核中；记录实际建号／绑定时间及来源。内部账户标识不作为用户可见或可编辑字段。已有正常账户再次登录复用原账户及注册状态，不重复建号；提交前退出或放弃不产生账户，也不占用地址。

<a id="F-L56"></a><a id="f-l56"></a>**角色不由用户选择（F-L56）**：平台没有选择角色的入口；资金方角色只在成功提交入驻申请时绑定，绑定后不可改选，见[登录主干的角色匹配](./01-登录主干与资产方SSO接入-PRD.md#F-L34)。

<a id="F-L77"></a><a id="f-l77"></a>**钱包与邮箱唯一性（F-L77）**：钱包与资金方账户一对一，已验证联系邮箱与钱包在资金方范围内严格一对一。其他账户已占用的地址不能再次绑定；**一个地址只绑定一个角色**，已绑定资产方的地址不能再提交资金方入驻。

<a id="F-L78"></a><a id="f-l78"></a>**资产方与资金方隔离（F-L78）**：不同地址上的资产方账户与资金方账户彼此独立，即使属于同一自然人也不合并、不互相读取档案或继承认证；同一地址不能同时具备两种角色。

按[共用返回规则](./01-登录主干与资产方SSO接入-PRD.md#return)决定落点：未绑定角色时按动作分流先进入入驻流程，再处理仍有效且当前有权访问的原业务目标，最后回资产广场。原业务意图采用主干既定默认 30 分钟（可配置）有效期及安全返回规则；重新登录不得刷新原期限。

<a id="F-L57"></a><a id="f-l57"></a>**入驻引导与返回（F-L57）**：登录未绑定角色的用户触发资金方动作即进入入驻流程，其间不插入单独的建号步骤；须让用户知道本次登录地址与凭据提示。用户可随时取消并继续允许的浏览，**取消即放弃本次填写内容，不保存、不入库，也不再另行提示**。登录前不提供“申请入驻”入口；已绑定资金方且尚未完成认证的账户可从补全提示再次进入，账户信息入口统一为“用户信息”。**提交申请只到审核中，不代表审核通过，也不能因此执行原来受限的出资动作。** 在资格、目标及时效全部满足时，才按主干规则恢复原触发动作；目标已失效则说明并提供适用返回，不自动越权。

## 3. 机构注册与提交

### 3.1 谁能填写、怎样保存

账户正常且会话有效时，未提交、已驳回、已认证可以填写或编辑；审核中只能查看当前提交，直接访问机构注册流程编辑入口也转到申请状态与审核记录只读进度，不能修改。**注册状态只有未提交、审核中、已驳回、已认证四种，没有“草稿”这一状态。**

<a id="F-L65"></a><a id="f-l65"></a>**认证后变更重审（F-L65）**：已认证用户开始编辑时说明成功提交将重新审核并暂停认证业务权限，但**编辑、放弃或提交失败不改变当前已认证或已提交资料**。

<a id="P-L21"></a><a id="p-l21"></a><a id="F-L58"></a><a id="f-l58"></a>**填写内容不入库、提交才保存（F-L58）**：入驻流程**不拆成步骤页**，用户在一个流程内完成联系邮箱验证、机构信息与材料填写、核对与提交。邮箱尚未验证可以先填机构资料，但不能提交。完成度按当前必填项及真实上传状态计算，不能以“曾经填过”代替当前合格。

**填写过程中的信息不入库**：本平台不保存未提交的表单内容与材料，也不提供草稿保存动作。**同一会话内已填内容不丢失**，用户在流程内往返查看不清空已填写的值。**取消即放弃**：用户取消、退出或主动离开即丢弃本次填写内容，不保存、不恢复，也不再额外提示。关闭浏览器、刷新或会话失效同样不保留，本册不承诺挽留。

**“不入库”只针对未提交内容**：成功提交的版本正常入库并作为当前已提交资料，驳回后重新编辑时该版本仍在库；**联系邮箱的验证结果（已验证邮箱与验证时间）属账户级数据，照常保存**，否则验证码有效期、冷却与限额、邮箱唯一性无法实现。只有成功提交才替换当前已提交资料：驳回编辑保持已驳回、认证后编辑保持已认证。

<a id="email-verification"></a>
### 3.2 联系邮箱首次验证

<a id="F-L59"></a><a id="f-l59"></a>**联系邮箱验证（F-L59）**：联系邮箱是账户的有效联系通道，**不是登录凭据，也不是本期业务通知渠道**。首次在注册第一步填写并验证；修改已有效邮箱使用[账户邮箱修改](#email-change)的同一流程。注册资料中的“业务联系人邮箱”是另一个独立字段，不能互相覆盖。

字段标签为“联系邮箱 / Contact email”。说明沿既定文案：“请使用长期有效的企业邮箱并完成验证码验证。审核结果与账号通知请在平台消息中心查看。 / Use a long-lived company mailbox and verify it with an email code. Review results and account notices are available in the platform message center.”

| 字段 | 类型、必填及默认 | 校验与生效 |
| --- | --- | --- |
| 联系邮箱 | 文本；提交注册前必填；新账户为空，已有有效邮箱回显 | 去首尾空格、转小写后校验；仅一个 `@`、域名至少一个点，最多 254 字符；资金方范围内未被另一账户占用，不能披露占用者身份 |
| 邮箱验证码 | 6 位数字组成的字符串；验证时必填；初始为空 | 仅验证本次待验证邮箱；有效期 10 分钟；同一码连续输错 5 次即作废，要求重新获取，不锁账户、不改变注册状态 |
| 验证时间 | 实际成功时间；只读，无人工默认值 | 成功验证并完成本次绑定／变更后记录；失败不写入新的验证时间 |

每次获取或重发验证码，先满足邮箱格式、可用性、发送冷却及限额，再**通过本次滑块验证**才向待验证邮箱发送。未完成、失败或取消滑块均不发码；上一次滑块成功不能代替本次重发。验证码不进入站内消息池，不发给旧邮箱。

三条发码限制同时适用：距上次发送至少 **60 秒**；同一次填写／修改流程最多 **重发 5 次**；同一目标邮箱 **24 小时最多发送 10 次**。分别提示剩余等待时间、本次流程上限（可退出重新发起）、邮箱发送上限。重新开启流程不取消邮箱 24 小时限制或仍在生效的发送冷却。

邮箱冲突在发码前拒绝，用户可直接改填，无需退出流程且不消耗本次流程。已有效邮箱修改为与当前相同的标准化邮箱，提示“这已经是你当前的联系邮箱”，不发码、不增加发送或重发次数。输入正确验证码后，生效前仍检查唯一性；若已被另一资金方占用，拒绝并保留原邮箱及验证时间。未完成绑定时，新账户仍为空；原来有有效邮箱时仍使用原值。首次绑定不产生站内信，邮箱验证邮件仅承担功能验证。

<a id="institution-fields"></a>
### 3.3 机构信息与材料

<a id="F-L60"></a><a id="f-l60"></a>**机构字段与材料（F-L60）**：正式字段与校验同源于 [机构认证审核 PRD](../v2.0-资金方机构认证审核/01-资金方机构认证审核-PRD.md#F-L80)的机构资料同源模版与字段表及[机构标识查重](../v2.0-资金方机构认证审核/01-资金方机构认证审核-PRD.md#F-L81)。面客采集与运营查看使用同一份定义；下表保留填写本流程所需的业务口径，不另建第二套审核标准。

| 信息 | 含义、类型与必填 | 当前填写规则／默认 |
| --- | --- | --- |
| 机构名称 | 法定机构名称，文本，必填 | 非空；初始空，不代猜主体；名称本身不作为唯一机构标识 |
| 注册国家或地区 | 机构登记地，文本，必填 | 非空；按当前同源规则为文本填写，不强加国家枚举或默认国家 |
| 标识类型 | 必填枚举 `USCC`／`LEI`／`REG_NO` | 无默认，初始“请选择”；分别表示统一社会信用代码、LEI、注册登记编号 |
| 机构唯一标识 | 所选类型对应编号，文本，必填 | 非空，保留原样显示；境内按生效模版强校验；境外存在格式差异时提示并由人工核实，不因一般格式提示自动拒绝 |
| 机构类型 | 描述机构类别，文本，必填 | 非空；不擅自限定为银行／基金枚举，初始空 |
| 注册地址 | 完整登记地址，文本，必填 | 非空，初始空 |
| 监管机构 | 适用的监管机构名称，文本，选填 | 初始空；不是工商登记机关字段，不新增无依据的长度上限 |
| 金融牌照编号 | 机构提供的金融牌照号码，文本，选填 | 初始空；有值不自动说明牌照有效或满足准入，不新增牌照影像或有效期字段 |
| 业务联系人邮箱 | 本次机构资料中的联系信息，文本，选填 | 有值时满足邮箱格式、最多 254 字符；无需账户验证码和唯一性校验，不自动复制账户邮箱 |
| 机构证明材料 | 用于本次审核的文件集合，必填 | 至少 1 个成功上传且可读取的文件，支持多附件；类型、大小、数量上限按已确认模版执行，尚未确认的限制列为依赖，不假定无限制 |

同源字段在填写、核对、当前资料及运营详情中同名展示，选填空值为“—”；文本必填项不得仅空白。境内采用统一社会信用代码；境外有 LEI 时优先使用 LEI（全球范围判重），否则采用国家／地区加注册登记编号。提交和审核通过生效前都核验机构唯一性；其他资金方待审核或已认证申请占用同一标识时，提示“该机构已在平台注册，如有疑问请联系客服”，不合并账户、不泄露对方信息。

成功提交时占用机构标识，通过后继续占用；首次或普通重提被驳回释放本轮占用。未提交内容不入库，也不占用标识。已认证后变更机构标识按机构认证审核的机构标识变更规则：审核期间新旧标识均保留占用，通过后释放旧标识；驳回释放新标识、保留原绑定和原标识占用，但当前为已驳回，**原绑定不保留认证权限，也不恢复旧表单／附件**。同一账户已有绑定不误判为另一资金方冲突。

附件展示真实文件名、大小和上传状态／进度，支持按当前权限预览、下载原文件。新增文件不覆盖其余已选文件；取消选择或替换保留原文件，主动删除后的迟到上传结果不能使文件复活。上传中、失败、不可读取的文件必须处理或移除，不能提交时静默遗漏；支持重试且不凭刷新伪造上传成功。暂不支持预览与文件不可读分开说明；仍可下载的原件保留下载入口。关闭预览返回原填写状态，不生成模拟附件、不丢表单内容。

当前提交沿提交时的模版规则审核，不因模版更新临时变成缺资料；再次填写与提交采用当前有效模版。无法取得有效模版时不猜字段或放行，就地说明并提供重试／现有客服，本次已填内容在同一会话内保留。原“草稿遇模版更新时保留兼容内容”一段随不入库口径**已停用**。

### 3.4 核对与成功提交

<a id="F-L61"></a><a id="f-l61"></a>**核对与成功提交（F-L61）**：核对展示有效联系邮箱、机构信息及全部材料。**本期无协议同意环节**（见[登录主干的协议口径](./01-登录主干与资产方SSO接入-PRD.md#agreement)）。**提交前必须有一次明确的二次确认**，每次提交都要求确认，不提供“不再提示”；该确认是操作确认，不具备协议同意效力。二次确认时取消回到当前填写内容继续编辑；离开流程则按[不入库](#F-L58)放弃本次内容。

成功提交必须同时满足：有效登录、账户正常（已有账户时）、当前可提交状态、联系邮箱已验证、机构必填项和所有材料合格、有效模版与机构唯一性校验通过、用户完成二次确认、提交频次未超限。首次提交同时建立资金方账户并绑定角色，见[资金方账户建立](#F-L55)。经界面提交与直接提交均受相同限制；失败须指明具体不合格字段／材料且对辅助技术可得，保留已填内容，不生成申请结果或改变当前资料。

同一账户在 **24 小时滑动窗口内最多 5 次成功提交**，包括首次、驳回重提和认证后变更。失败、重复返回同一成功结果不计；累计重提次数无上限。限频时本次已填内容在同一会话内保留、显示具体可再次提交时间及其时区，提交不可用并说明原因；窗口按真实连续时长计算，不因显示日期或时区切换重置。

成功后进入申请状态与审核记录页，注册状态统一为审核中，用本次机构资料及材料整体替换唯一当前已提交版本；新增一个真实提交节点及提交时间，等待运营审核。向正常运营范围发送一条机构资料待审核站内信；资金方在提交结果中已即时获知，不再收到普通提交回执。已认证变更提交另向本人发送一条认证权限暂停通知，并按[资格说明](#guidance)即时限制业务。

重复点击或网络重返同一结果不重复生成申请、提交节点、成功次数或通知。结果暂未知时不得提前显示成功、覆盖当前资料或通知；保持结果待确认且防止重复提交，再次打开或登录后继续核实。已接收则呈现同一次成功，明确未接收才回到可再次提交的填写状态（本次内容仅在同一会话内保留）；查询失败不视为材料丢失。旧提交的迟到审核结果不能应用到新提交。

## 4. 审核结果、状态与业务权限

<a id="review"></a>
### 4.1 查看申请与处理结果

<a id="P-L22"></a><a id="p-l22"></a><a id="F-L63"></a><a id="f-l63"></a>**审核结果与记录（F-L63）**：本人在申请状态与审核记录页查看申请编号、当前注册状态、本次提交时间、已生效审核时间与结果（通过时即认证时间）、唯一当前机构资料和材料，以及实际发生的提交／审核记录。

<a id="F-L62"></a><a id="f-l62"></a>**审核中只读（F-L62）**：审核中机构资料只读，不提供编辑、删除、重新提交、撤回或回退为未提交的操作，产品文案不出现“撤回”或暗示可在审核中修改材料的表述；账户联系邮箱仍可独立修改。

机构自行决定实质审核标准，平台按机构认证审核承载已确认的形式校验、正常运营人工审核及结果。资料齐全、金融牌照有值、等待较久或机构标准变化不自动通过、驳回、触发重审；不承诺审核天数、队列位置或超时自动结论，不要求新增平台评分或准入名单。

审核通过：本次有效结论使审核中 → 已认证，展示通过记录并开放当前认证业务。审核驳回：审核中 → 已驳回，显示驳回原因**原文**，保留段落，不翻译、不按字段拆分、不虚构驳回分类。

<a id="F-L64"></a><a id="f-l64"></a>**驳回后修改重提（F-L64）**：用户可查看原因后进入原资料预填的注册流程，修改并重新提交；字段本身的填写校验仍正常执行。机构审核通过／驳回通知由机构认证审核唯一发送，本模块不重复告知。

时间线每次成功提交与每次生效审核各为一个独立节点，按实际发生顺序显示；时间相同仍保持真实先后。待审核只是最新提交的状态提示，不预造审核动作、审核人或时间。旧原因保留在旧审核节点，不能复制为新提交的当前原因；面客审核人员统一显示“运营审核 / Operations review”，不展示真实审核员身份。

只保留一份当前认证资料，历史保留的是提交／审核动作及原因，不提供历史材料回看、下载、版本切换、比较或回退。旧通知只能对应其原提交及记录，不能把当前材料冒充旧材料，也不能据旧通过记录授予当前资格。审核行为与结论只读保护按机构认证审核执行。

<a id="state-contract"></a>
### 4.2 两组状态及允许动作

<a id="F-L66"></a><a id="f-l66"></a>**账户与注册状态（F-L66）**：账户可用性（正常／已停用）与机构注册四态（未提交／审核中／已驳回／已认证）分别维护，没有“草稿”“锁定”“凭据不完整”等额外状态。机构注册不存在终态：已认证仍可成功提交变更进入新一轮审核。

| 机构注册状态与用户标签 | 正常登录时资格 | 允许的资料动作 | 可以如何改变状态 |
| --- | --- | --- | --- |
| 未提交／Registration not submitted | 未认证 | 可填写并提交；填写内容提交前不入库，可浏览但不能办理认证业务 | 首次成功提交 → 审核中（同时建立账户并绑定资金方角色） |
| 审核中／Under review | 未认证 | 当前申请与材料只读；账户联系邮箱仍可改 | 本次有效人工审核 → 已认证或已驳回 |
| 已驳回／Rejected | 未认证 | 查看原文原因，编辑并重提；累计重提无上限 | 成功重提 → 审核中 |
| 已认证／Verified | 已认证 | 查看、编辑变更内容；成功提交前保留认证资格与当前已提交资料 | 确认并成功提交变更 → 审核中 |

正常登录时呈现资金方本人身份和对应注册资格；账户标识不作为用户可编辑字段。共用含义及状态展示引用[主干状态与资格规则](./01-登录主干与资产方SSO接入-PRD.md#state-contract)。

任一注册状态叠加停用或无有效登录时，对外回游客，角色和账户标识为空，不开放本人保护数据；底层原注册状态保留。停用使该账户全部会话立即失效；恢复只恢复可登录能力，需重新正常登录后按原注册状态获得相应认证资格，不自动恢复旧会话或变为已认证。每次真实停用或恢复均向本人发送一条对应通知，不依赖收件或阅读才限制访问。

<a id="F-L67"></a><a id="f-l67"></a>**当前资格同步（F-L67）**：登录、退出、提交成功、有效审核结果到达和会话失效后同步当前状态与权限；进入需要判权限的功能时重新确认当前权威结果，不自行用旧资料推算资格。共用状态的既定约束见[登录主干](./01-登录主干与资产方SSO接入-PRD.md#state-contract)，各入口读到的资格必须一致。审核中不能直接回未提交；已认证或已驳回账户必须先成功提交本轮机构资料，进入审核中后才能得到新的审核结论。不得仅修改认证资格而保留矛盾的注册状态。

<a id="permissions"></a>
### 4.3 资金方业务权限

下表承接[主干权限矩阵](./01-登录主干与资产方SSO接入-PRD.md#permissions)的资金方两列。✅允许；⊘需引导完成资格；❌禁止。未提交、审核中或已驳回的信息可见权限相同，但引导动作不同；游客按主干游客规则。认证也不突破数据本人归属及具体业务对象的授权。

| 功能 | 未认证资金方（未提交、审核中、已驳回） | 已认证资金方 |
| --- | --- | --- |
| 业务字段详情 | 按对应业务已确认范围 | 按对应业务已确认范围 |
| 精确搜索／排序 | 按对应业务已确认范围 | 按对应业务已确认范围 |
| 合同／发票等业务附件 | 按业务对象权限，不包含他人认证材料 | 同左 |
| 本人账户以外的个人联系方式 | ❌；业务明确允许的联系信息按原业务范围展示，不从账户档案补取 | 同左 |
| 出资／授信报价（资金方资格硬拦截点） | ⊘ | ✅ |
| 签约／合同下载 | ⊘ | ✅ |
| 维护收款 / 出资账户 | ⊘ | ✅ |
| 编辑机构资料 | 未提交✅；审核中❌；已驳回✅ | ✅，成功提交后重审 |
| 查看审核进度／记录 | ✅，无提交时按实际空状态 | ✅ |
| 控制台 | ✅，按实际数据呈现空状态引导 | ✅ |
| 消息中心 | ✅，仅本人 | ✅，仅本人 |
| 账户设置 | ✅，本人钱包只读 | ✅，本人钱包只读 |
| 修改账户联系邮箱 | ✅，包括审核中 | ✅ |
| 退出登录 | ✅ | ✅ |

“维护收款 / 出资账户”按[主干权限矩阵](./01-登录主干与资产方SSO接入-PRD.md#permission-11)取值，账户的新增与维护在[企业账户入口与收款账户归属（5.5）](#enterprise-account)所指模块办理；本期只维护收款账户，出账（付款）账户不采集。

公共列表与平台介绍继续允许浏览。其余业务及资产方行不在本册另定义。禁止动作必须在直接访问或提交时同样拒绝，不能只在界面上隐去了事。

## 5. 账户设置、本人资料与偏好

### 5.1 账户与机构信息入口

<a id="P-L23"></a><a id="p-l23"></a><a id="C-L23"></a><a id="c-l23"></a><a id="F-L73"></a><a id="f-l73"></a>**本人账户与偏好（F-L73）**：正常登录的资金方在所有注册状态下均可进入本人账户设置。登录后可进入“账户设置”和“用户信息”两处：账户设置用于管理钱包只读信息、联系邮箱与偏好；用户信息在未提交状态进入机构注册流程，其他注册状态进入申请状态与审核记录。审核中的机构只读不扩大为账户邮箱禁止修改。

| 账户信息／操作 | 展示与权限 |
| --- | --- |
| 钱包地址 | 只读；缩略展示时仍可完整复制并核对全文，可用既有区块浏览器查看；无修改、解绑、更换入口；不显示内部账户标识 |
| 联系邮箱 | 当前有效邮箱完整显示；尚未填写显示“未填写 / Not set”；本人可按下节修改，附保管提示 |
| 账户状态 | 正常 / Active、已停用 / Disabled 的实际业务含义；停用后不得继续访问本人数据，正常登录是读取前提 |
| 注册状态 | 四态只读业务标签；提供“查看进度”到申请状态与审核记录页；未提交时按实际无记录状态显示，不虚构申请 |
| 语言、时区 | 语言可选 English / 简体中文，未保存时沿当前平台语言、无偏好默认英文。时区为有效 IANA 时区，优先已保存值；按既有面客基线在建号时取浏览器时区，推断失败用 UTC，之后不自动覆盖用户选择；选择即保存，成功反馈并在刷新后保留，失败提示并回退至上次成功值，允许重试。同一业务时间和发生顺序不改变 |
| 企业账户 | 指向[企业账户](../v1.0-企业账户/01-企业账户-PRD.md)的独立入口，资产方与资金方一致；账户设置本身不展示、不采集任何收款账户字段 |
| 通知偏好 | 当前模块无可选事件，不展示无实际作用的可操作开关或虚假保存；无历史值的可选偏好沿既定默认开启，但不能因此虚构事件 |

偏好业务值引用[国际化基线第 1～4 节](https://github.com/wxblockchain/Chain-Financing/blob/ea56882/financial-service-platform/prd/v1.0-账户与登录/01-国际化基线.md)，仅沿用资金方面客适用的语言、时区与显示规则，不引入其中运营账户初始化或旧登录体系。偏好属于可编辑选项，不是注册必填材料；不允许保存无效选项。保存进行中须让用户知道处理未完成，同值不重复保存；退出、过期、换账户或离开后不以迟到结果恢复旧身份或已离开的内容，已成功值保留、未成功值不另存。

账户设置不展示机构名称、牌照、业务联系人邮箱等机构资料，也不展示法币或数币收款账户字段，不混入密码相关项；机构资料在机构注册流程与申请状态页按注册状态查看或编辑。

<a id="C-L22"></a><a id="c-l22"></a><a id="F-L75"></a><a id="f-l75"></a>**钱包不可改绑（F-L75）**：钱包是唯一登录凭据，本期无任何面客、运营或工单改绑通道；直接改绑请求也拒绝并留痕，不使用“如需更换请联系客服”等暗示可改绑的文案。

联系邮箱修改、账户停用／恢复、认证权限暂停均为强制关键通知，当前或历史关闭值都不影响；运营的机构资料待审核通知不受面客偏好控制。账户设置中明确告知“安全、认证等关键通知始终接收 / Security and verification notices are always delivered”。通知行为和模板统一见[通知册](./03-资金方登录与账户体系-消息通知.md)。

### 5.2 修改账户联系邮箱

<a id="F-L71"></a><a id="f-l71"></a>**修改邮箱前确认本人（F-L71）**：本人在账户设置选择修改，先用绑定钱包签名再认证，通过后填写新邮箱及验证码。签名前说明此次用途为确认本人修改联系邮箱，不能显示为首次登录。同一有效会话内已完成的再认证在 **10 分钟**内可复用；只有钱包签名一个再认证因子，不用密码或邮箱码代替身份证明。再认证失败可重试、不锁账户；签名规则与时效见[钱包登录与首次建号（第 2 章）](#wallet-login)。

<a id="C-L24"></a><a id="c-l24"></a><a id="F-L74"></a><a id="f-l74"></a>**联系邮箱修改（F-L74）**：新邮箱与验证码初始为空；按照[统一邮箱规则](#email-verification)完成发码前置、每次滑块、新邮箱验证及生效前唯一性复核，再确认修改。钱包已切换成另一地址不能用其签名证明当前账户身份。尚未成功生效、校验失败、取消或离开时，原有效邮箱和验证时间不变；已发验证码按原有效期处理。

### 5.3 本人资料及业务必要信息

机构注册、申请状态与审核记录、账户设置的个人、企业档案、联系信息、证件及认证材料只归本人。认证通过、同企业、同钱包的另一身份不扩大可见范围；普通运营只能在机构认证审核指定审核场景查看对应已提交材料及记录，不据此查看未提交内容、账户档案或代改资料。

业务确需既有企业名称／登记信息等已确认字段时，平台自动取得并只向该业务原有权限内的角色展示必要字段，不要求重复手填来源资料，不整组公开个人／企业档案，不从账户资料补出未授权联系方式。第三方来源字段只读，更新在来源方处理；本地机构资料按本册编辑和重审规则办理，资产方身份资料不自动转成资金方认证。

自动获取失败、必要字段缺失或主体对应冲突时明确资料暂不可用／需要处理，提供适用重试、返回，只限制依赖该信息的操作，保留合法登录和其他浏览。可选项确实为空按原规则显示，不阻断；获取失败不冒充空值或删除，旧值未核实不能冒充当前有效资料。明确删除或归属失效后不继续展示旧资料，也不因一次获取失败自动改变机构注册状态。字段供给、归属及脱敏见[共用规则与仍需落实的依赖（第 7 章）](#dependencies)。

## 6. 会话、退出与账户安全

<a id="F-L69"></a><a id="f-l69"></a>**会话有效期（F-L69）**：资金方会话沿既定 **4 小时**有效期；空闲达到 4 小时失效，不提供“记住我”或更长会话选项。失效回游客并就地说明，可继续浏览可达内容，不打断要求立即登录，也不把用户带到只有报错、无法继续的结果。填写中失效不得继续填写或提交；未提交内容不保留，重新登录后需重新填写。

<a id="F-L70"></a><a id="f-l70"></a>**主动退出（F-L70）**：退出入口唯一，不在其他位置另设退出；退出使该账户各设备会话全部失效，回游客，保护功能和本人资料不可继续访问，按[共用退出规则](./01-登录主干与资产方SSO接入-PRD.md#session)落到可浏览位置。退出不强制断开钱包连接，但必须明确显示为未登录。停用同样结束全部会话；邮箱修改不结束会话。

<a id="F-L72"></a><a id="f-l72"></a>**钱包断连与地址切换（F-L72）**：钱包插件单独断开连接不等于平台退出：有效平台会话仍保留，提示钱包未连接，下一次签名操作才要求重连。钱包从 A 切到 B 时提示登录账户与钱包地址不同并提供“用该地址重新登录”，不静默切换当前账户、覆盖 A 的绑定或沿用 A 的再认证结果证明 B。

未提交状态的账户连续 **180 天**无活跃可标记休眠；只做标记，不删除账户数据、不变更账户可用性或注册状态（未提交内容本就不入库，无数据可留）。再次正常登录自动清除休眠标记，用户无须办理恢复，不触发停用／恢复通知。

保留登录成功／失败、建号、邮箱绑定／变更、提交及审核状态变化、拒绝改绑、拒绝审核中修改机构资料、停用／恢复和休眠处理的必要业务留痕；敏感内容不泄露到日志或通知。访问与业务动作均校验当前身份、归属和状态。不得索取私钥，不编造性能指标、留存天数或新的锁定策略。
