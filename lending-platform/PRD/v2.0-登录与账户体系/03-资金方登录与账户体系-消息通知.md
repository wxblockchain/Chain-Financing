# 资金方登录与账户体系 · 消息通知

版本：2026-09-22。需求：WS-372。配套[主 PRD](./01-资金方登录与账户体系-PRD.md)及[图 6](./02-资金方登录与账户体系-流程图与状态机.md#notification-flow)。本文件只定义本模块的站内信，机构审核结果由 WS-358 的独立通知文件负责。面客／运营消息中心沿 WS-356/360 现有框架最终统一比对登记与映射，当前文案齐备不代表真实投递已实现。

## 1. 哪些节点发给谁

仅在他人需要处理、账户安全或认证业务资格发生实质变化时发送。三方分别核对接收范围，不同发三方。本期采用四类事件、五套模板，全部为关键通知，不可退订。

| 事件与触发时点 | 资金方本人 | 正常运营人员（含 SPV） | 资产方 |
| --- | --- | --- | --- |
| EV-L42：首次注册、驳回重提或认证后变更资料，真实成功提交进入 L1 | 页面即时展示结果，无普通提交站内回执 | 一条对应本次提交的待审核消息 | 不发 |
| EV-L43：原有效联系邮箱修改成功生效 | 一条安全消息 | 不发 | 不发 |
| EV-L45：账户正常→停用、停用→正常的每次真实变化 | 每次变化一条对应安全消息 | 不发操作回执或广播 | 不发 |
| EV-L46：已认证 L3 变更资料成功提交，进入 L1 | 一条资格变化消息 | 使用本次 EV-L42，不另收资格副本 | 不发 |

资金方面客消息只归受影响的本平台账户，不按联系邮箱、业务联系人邮箱或钱包地址分发。同钱包资产方、其他资金方均不可见。运营待审核进入既有运营共享消息池，不增加指派、认领、查询／处置分权；SPV 按同一运营身份，不作为第三接收群体再发一份。

审核通过／驳回 EV-L60/61 由 WS-358 唯一发送；本模块更新状态与记录，不重复发结果，也不将审核驳回当作 EV-L46。机构自行定标准不取消人工审核与通知，不让资料齐全、牌照有值、标准变化或等待较久自动变为通过。

首次建号、首次邮箱绑定不产生 EV-L40/41 欢迎／绑定消息，不启用 EV-L44 旧邮箱变更邮件。常规登录、退出、签名失败、草稿／偏好保存、获取资料或重试、提交失败／限频、未读停留均不发送。EV-L47 邮箱验证码属于功能验证：注册／修改／每次重发先满足全部发送条件并通过本次滑块，才发往待验证邮箱；不进入站内消息池，不恢复邮件登录或业务邮件。

## 2. 每个事件的结果与例外

| 事件 | 成功事实及访问边界 |
| --- | --- |
| EV-L42 | 成功提交才覆盖唯一当前认证资料并新增真实提交节点；失败、草稿及重复结果不产生任务。消息关联申请和这次提交，不因后来有新提交改指新任务。打开时若原提交已处理／流转，说明状态并进入对应记录，不可用旧消息审核新提交，不再占当前待审核任务 |
| EV-L43 | 完成绑定钱包再认证、新邮箱验证及变更生效才发。未完成前原有效邮箱及验证时间不变；首次、相同邮箱、冲突、取消均不发。本人到账户设置查看当前邮箱，通知不含邮箱全文；不按新旧邮箱各发一份 |
| EV-L45 | 仅真实 active/disabled 切换；重复状态、重新登录、休眠及休眠恢复不发。停用立即限制登录和本人资料访问，不等通知；停用时不能读新旧消息，恢复并正常登录后可读历史，恢复不自动认证、不删除停用消息 |
| EV-L46 | 仅 L3 实际成功变更提交→L1；编辑、放弃、失败或 L2 重提不发。资格立即变化，下次进入的显式说明与站内信基于同一事实，不能用读信或旧通过记录恢复资格；之后审核结果归 WS-358，无 verified→rejected 直接审核 |

账户与注册完整规则见[主 PRD 第 3～6 章](./01-资金方登录与账户体系-PRD.md#registration)。资料保护覆盖消息预览、正文、目标页面：运营只能在指定已提交申请审核范围看材料，不获账户档案、草稿或代改权限；面客只进本人记录。

## 3. 不重复打扰，按当前权限查看

1. 同端、同接收范围、同一事件的同一次业务事实只形成一条消息。重复告知、失败补送、刷新、重登不新增、不改回未读、不置顶、不改变原发生时间或增加未读计数；运营每个人的已读状态也不重置。下一次真实提交、邮箱修改、停用／恢复或再次认证后降级，各为新事实，独立保留。
2. 不追加未读催促、定时催审、草稿提醒、认证倒计时或重复安全提醒；沿现有消息列表和未读计数，不增加强制弹窗、声音、浏览器推送或站外触达。
3. 通知延迟／失败不回滚已成功业务或权限、不要求用户重做；业务结果未知不提前发成功消息。失败补送仍遵守同一事实只一条，权限不依赖送达或已读才更新。
4. 每次跳转按当前登录、收件归属、申请及提交状态检查，不自动登录、启用账户、审核、改邮箱、恢复认证或执行被拦业务。目标不存在／映射未完成时保留可读正文，说明暂不可查看详情并禁用操作，不猜测链接。
5. 历史提交／审核动作和原因可读，当前材料只代表最新提交，不提供旧材料回看、版本比较或回退，也不把当前材料冒充旧消息当次材料。面客审核人仅显示“运营审核”，原因在受保护记录内查看。
6. 任务是否结束与是否已读不同。已处理任务不再提供处置动作，但保留历史告知；读信不完成审核。无业务到期日的消息沿框架保留，不自行设删除天数或伪造已读。

EV-L43/45 属安全强制告知，EV-L46 属认证合规强制告知；不受当前或历史关闭偏好影响。EV-L42 属运营待办，不受面客偏好控制。本模块可选事件为零，无历史值沿既定默认开启也不生成可操作空开关或虚假保存；账户页说明“安全、认证等关键通知始终接收 / Security and verification notices are always delivered”。后续实际可选事件由所属模块定义；关闭偏好不删除历史或重置已读。

## 4. 模板登记与双语文案

### 4.1 沿用现有框架的登记项

沿用 `msg.<业务类型>.title` / `msg.<业务类型>.body` 成对模板。下表的业务类型及带平台标识的页面映射为本轮拟登记项，需消息中心最后核对唯一性；业务含义、接收范围与文案已在本文件定义，不等待框架补齐才确定需求。

| 事件 / 模板业务类型 | 端与分类 | 接收范围 | 触发方 | 目标形态与落点 | 可退订 / 有效性 |
| --- | --- | --- | --- | --- | --- |
| EV-L42 / `verification.funder.submitted` | 运营管理端；`review_todo` | 本模块既有正常运营范围 | 资金方注册成功提交 | 业务对象：该申请及对应提交，进入运营 P-L41；拟映射 `operations:P-L41` | 否；只在这次提交仍待审核时可处置，结束后只读 |
| EV-L43 / `account.funder.email_changed` | 借贷面客端；`security` | 受影响资金方账户 | 资金方邮箱变更生效 | 静态页面：P-L23；拟映射 `lending:P-L23` | 否；历史告知，无业务到期日 |
| EV-L45 停用 / `account.funder.disabled` | 借贷面客端；`security` | 受影响资金方账户 | 账户模块确认停用生效 | 静态页面：P-L23；拟映射 `lending:P-L23`，当前不可用时不得进入 | 否；恢复后保留历史告知 |
| EV-L45 恢复 / `account.funder.restored` | 借贷面客端；`security` | 受影响资金方账户 | 账户模块确认恢复生效 | 静态页面：P-L23；拟映射 `lending:P-L23` | 否；不授予机构认证资格 |
| EV-L46 / `verification.funder.review_started` | 借贷面客端；`compliance` | 因变更提交失去认证业务资格的资金方账户 | 资金方变更成功提交 | 业务对象：该申请及对应提交，进入 P-L22；拟映射 `lending:P-L22` | 否；历史告知，不附审核进度步骤 |

每条登记的去重范围为“端＋接收范围＋事件类型＋同一次业务事实”；运营共享消息的个人已读状态沿用管理端框架，重复事实不能重置任何人的已读状态。发生时间取业务事实成功生效的时间，补送不改写；不把消息创建时间冒充提交/审核时间。运营审核列表既有的提交时间排序不受通知排序改变。

### 4.3 字段口径与内容限制

| 字段 / 业务信息 | 业务类型、必填与来源 | 校验、默认与展示 |
| --- | --- | --- |
| `application_number` | 文本；EV-L42/46 必填，来自所属机构认证申请；其余模板无此变量 | 必须对应本账户的真实申请，不为空、不臆造，用户不可编辑；无默认值；不用于暴露其他申请信息 |
| `submitted_time` | 时间；EV-L42/46 必填，取该次成功提交的实际时间 | 按阅读者语言和时区格式化并标注时区；不得取最近查看时间或其他提交时间；无默认值，用户不可编辑 |
| 对应提交 | 必须关联到产生事件的那次真实提交；用于业务对象跳转 | 不是历史材料版本；不能仅凭“当前申请”将旧消息替换指向新提交。具体关联实现由开发设计 |
| 收件账户 / 运营可见范围 | 必填业务归属；面客取本平台资金方账户，运营取已有运营范围 | 不按联系邮箱、业务联系人邮箱或钱包地址直接分发，不允许审核员任意填写接收人 |
| 发生时间与已读状态 | 沿用消息框架展示字段；已读仅表示用户读过 | 时间由事件产生时确定，用户不可编辑；新消息按框架为未读，读后不因同一事实重发而恢复未读 |

中英标题变量均为空；EV-L42/46 的中英正文变量集合均为 `application_number`、`submitted_time`，其余正文无动态变量。标题、正文与变量均为纯文本；不包含钱包全文、邮箱全文、身份证件、材料附件、驳回全文或审核员身份。审核原因在受保护的对应记录查看，不塞进通知预览。必要内容缺失时不显示原始模板键、占位符或虚构值，保留业务结果可查并按现有消息异常规则处理；语言缺失采用消息框架既有回落。


## 5. 跨模块衔接与验收

| 对接位置 | 需保持或最终核对的内容 |
| --- | --- |
| WS-358 机构审核 V2.5 | 已采用仅站内信和当前提交关联；EV-L60/61 仍唯一由其发送，EV-L42 不再生成相同待办；机构标准由机构决定，运营权限与本人资料边界保持 |
| WS-356 面客消息中心 | 最后比对四套面客模板、security/compliance、账户隔离、强制告知、P-L22/P-L23 映射、历史与当前资格；本期无可选空开关，无业务邮件 |
| WS-360 运营消息中心 | 最后比对 EV-L42、review_todo、P-L41 及本次提交关联；正常运营/SPV 同范围，个人已读与审核任务结束分开，旧消息不处理新提交 |
| 两个消息中心共同处理 | 登记名称和页面映射尚需比对；旧框架合并同类消息后恢复未读的规则须区分新事实与重复送达，本模块重复事实不得再次提醒。保留已有消息异常／语言回落，不以未适配改变业务定义 |

验收集中在[主 PRD 8.7](./01-资金方登录与账户体系-PRD.md#notification-acceptance)，邮箱验证码另见[8.3](./01-资金方登录与账户体系-PRD.md#accept-email)。重点核对触发事实、三方隔离、同一事实去重、五模板、旧消息与当前状态、停用不可读，以及失败不回滚业务。本文件不规定页面布局；消息编号和规则来源不作为产品界面文案。
