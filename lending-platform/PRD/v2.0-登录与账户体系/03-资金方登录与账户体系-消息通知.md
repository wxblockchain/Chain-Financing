# 资金方登录与账户体系 · 消息通知

版本：2026-09-24。需求：资金方登录与账户（WS-372）。配套[主 PRD](./01-资金方登录与账户体系-PRD.md)及[关键消息及发送归属（图 6）](./02-资金方登录与账户体系-流程图与状态机.md#notification-flow)。本文件只定义本模块的站内信，机构审核结果由机构认证审核的独立通知文件负责。面客与运营消息中心负责核对真实投递和目标页面，当前文案齐备不代表真实投递已实现。

本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。通知的承载形式与视觉由设计决定。

<a id="notification-scope"></a>
## 1. 哪些节点发给谁

仅在他人需要处理、账户安全或认证业务资格发生实质变化时发送。按下表区分三方接收范围，不向所有角色广播。本期采用四类事件、五套模板，全部为关键通知，不可退订。

| 事件与触发时点 | 资金方本人 | 正常运营人员（含 SPV） | 资产方 |
| --- | --- | --- | --- |
| 机构资料待审核通知：首次注册、驳回重提或认证后变更资料，真实成功提交进入审核中 | 页面即时展示结果，无普通提交站内回执 | 一条对应本次提交的待审核消息 | 不发 |
| 联系邮箱修改通知：原有效联系邮箱修改成功生效 | 一条安全消息 | 不发 | 不发 |
| 账户停用／恢复通知：账户正常→停用、停用→正常的每次真实变化 | 每次变化一条对应安全消息 | 不发操作回执或广播 | 不发 |
| 认证权限暂停通知：已认证变更资料成功提交，进入审核中 | 一条资格变化消息 | 使用本次机构资料待审核通知，不另收资格副本 | 不发 |

资金方面客消息只归受影响的本平台账户，不按联系邮箱、业务联系人邮箱或钱包地址分发。同钱包资产方、其他资金方均不可见。运营待审核进入既有运营共享消息池，不增加指派、认领、查询／处置分权；SPV 按同一运营身份，不作为第三接收群体再发一份。

机构审核通过／驳回通知由机构认证审核唯一发送；本模块更新状态与记录，不重复发结果，也不将审核驳回当作认证权限暂停通知。机构自行定标准不取消人工审核与通知，不让资料齐全、牌照有值、标准变化或等待较久自动变为通过。

企业账户模块本期无独立发送事件：资金方收款账户的新增、修改、删除与默认变更，以及为登记数币地址所做的地址所有权签名，均不产生本册通知，也不改变本册的四类事件与五套模板。

首次建号、首次邮箱绑定不产生欢迎或绑定消息，不启用旧邮箱变更邮件。常规登录、退出、签名失败、偏好保存、获取资料或重试、提交失败／限频、未读停留均不发送。邮箱验证码属于功能验证：注册／修改／每次重发先满足全部发送条件并通过本次滑块，才发往待验证邮箱；不进入站内消息池，不恢复邮件登录或业务邮件。

## 2. 每个事件的结果与例外

| 事件 | 成功事实及访问边界 |
| --- | --- |
| 机构资料待审核通知 | 成功提交才覆盖唯一当前认证资料并新增真实提交节点；失败与重复结果不产生任务。消息关联申请和这次提交，不因后来有新提交改指新任务。打开时若原提交已处理／流转，说明状态并进入对应记录，不可用旧消息审核新提交，不再占当前待审核任务 |
| 联系邮箱修改通知 | 完成绑定钱包再认证、新邮箱验证及变更生效才发。未完成前原有效邮箱及验证时间不变；首次、相同邮箱、冲突、取消均不发。本人到账户设置查看当前邮箱，通知不含邮箱全文；不按新旧邮箱各发一份 |
| 账户停用／恢复通知 | 仅真实 正常／已停用 切换；重复状态、重新登录、休眠及休眠恢复不发。停用立即限制登录和本人资料访问，不等通知；停用时不能读新旧消息，恢复并正常登录后可读历史，恢复不自动认证、不删除停用消息 |
| 认证权限暂停通知 | 仅在已认证账户成功提交机构资料变更、实际进入审核中后发送；编辑、放弃、失败或已驳回重提不发。资格立即变化，下次进入的显式说明与站内信基于同一事实，不能用读信或旧通过记录恢复资格；之后审核结果归机构认证审核，无 已认证直接转为已驳回 直接审核 |

完整规则见[机构注册与提交（主 PRD 第 3 章）](./01-资金方登录与账户体系-PRD.md#registration)、[审核结果与业务权限（第 4 章）](./01-资金方登录与账户体系-PRD.md#review)、[账户设置、本人资料与偏好（第 5 章）](./01-资金方登录与账户体系-PRD.md#account)及[会话、退出与账户安全（第 6 章）](./01-资金方登录与账户体系-PRD.md#session)。资料保护覆盖消息预览、正文、目标页面：运营只能在指定已提交申请审核范围看材料，不获账户档案、草稿或代改权限；面客只进本人记录。

## 3. 不重复打扰，按当前权限查看

1. 同端、同接收范围、同一事件的同一次业务事实只形成一条消息。重复告知、失败补送、刷新、重登不新增、不改回未读、不再次提醒、不改变原发生时间或增加未读计数；运营每个人的已读状态也不重置。下一次真实提交、邮箱修改、停用／恢复或再次认证后降级，各为新事实，独立保留。
2. 不追加未读催促、定时催审、填写提醒、认证倒计时或重复安全提醒；沿现有消息与未读计数口径，不增加打断式提醒、站外触达或其他额外提醒渠道。
3. 通知延迟／失败不回滚已成功业务或权限、不要求用户重做；业务结果未知不提前发成功消息。失败补送仍遵守同一事实只一条，权限不依赖送达或已读才更新。
4. 每次跳转按当前登录、收件归属、申请及提交状态检查，不自动登录、启用账户、审核、改邮箱、恢复认证或执行被拦业务。目标不存在／映射未完成时保留可读正文，说明暂不可查看详情并禁用操作，不猜测链接。
5. 历史提交／审核动作和原因可读，当前材料只代表最新提交，不提供旧材料回看、版本比较或回退，也不把当前材料冒充旧消息当次材料。面客审核人仅显示“运营审核”，原因在受保护记录内查看。
6. 任务是否结束与是否已读不同。已处理任务不再提供处置动作，但保留历史告知；读信不完成审核。无业务到期日的消息沿框架保留，不自行设删除天数或伪造已读。

联系邮箱修改及账户停用／恢复通知属安全强制告知，认证权限暂停通知属认证合规强制告知；不受当前或历史关闭偏好影响。机构资料待审核通知属运营待办，不受面客偏好控制。本模块可选事件为零，无历史值沿既定默认开启也不生成可操作空开关或虚假保存；账户页说明“安全、认证等关键通知始终接收 / Security and verification notices are always delivered”。后续实际可选事件由所属模块定义；关闭偏好不删除历史或重置已读。

## 4. 通知落点与双语文案

<a id="notification-view"></a>
### 4.1 各通知可以查看什么

| 通知 | 展示端与业务分类 | 查看落点与可操作条件 |
| --- | --- | --- |
| 机构资料待审核 | 运营管理端；审核待办 | 打开该申请的运营机构审核详情，并定位本次提交；只有这次提交仍待审核时可处置，已处理后只读 |
| 联系邮箱修改 | 借贷面客端；账户安全 | 本人账户设置，查看当前有效邮箱；历史通知不恢复旧邮箱 |
| 账户停用 | 借贷面客端；账户安全 | 账户设置；停用期间不可进入或读信，恢复并正常登录后可查历史告知 |
| 账户恢复 | 借贷面客端；账户安全 | 正常登录后进入本人账户设置；不自动登录或授予机构认证资格 |
| 认证权限暂停 | 借贷面客端；认证资格 | 本人申请状态与审核记录，定位造成权限暂停的那次提交；当前资格以最新有效状态为准 |

全部不可退订。历史告知没有额外业务到期日，待办是否可处置取决于该次提交是否仍待审核。发生时间取业务事实成功生效的时间，补送不改写；不把通知生成时间冒充提交或审核时间。运营审核列表按既定提交时间排序，不受通知排序影响。

### 4.3 字段口径与内容限制

| 字段 / 业务信息 | 业务类型、必填与来源 | 校验、默认与展示 |
| --- | --- | --- |
| 申请编号（文案中的 application_number） | 文本；机构资料待审核通知和认证权限暂停通知必填，来自所属机构认证申请；其余模板无此变量 | 必须对应本账户的真实申请，不为空、不臆造，用户不可编辑；无默认值；不用于暴露其他申请信息 |
| 提交时间（文案中的 submitted_time） | 时间；机构资料待审核通知和认证权限暂停通知必填，取该次成功提交的实际时间 | 按阅读者语言和时区格式化并标注时区；不得取最近查看时间或其他提交时间；无默认值，用户不可编辑 |
| 对应提交 | 必须关联到产生事件的那次真实提交；用于业务对象跳转 | 不是历史材料版本；不能仅凭“当前申请”将旧消息替换指向新提交。打开后须定位到该次提交记录 |
| 收件账户 / 运营可见范围 | 必填业务归属；面客取本平台资金方账户，运营取已有运营范围 | 不按联系邮箱、业务联系人邮箱或钱包地址直接分发，不允许审核员任意填写接收人 |
| 发生时间与已读状态 | 沿用消息框架展示字段；已读仅表示用户读过 | 时间由事件产生时确定，用户不可编辑；新消息按框架为未读，读后不因同一事实重发而恢复未读 |

标题不包含动态信息；机构资料待审核与认证权限暂停正文均展示真实申请编号和该次提交时间，中英信息一致；其余正文无动态信息。标题、正文与变量均为纯文本；不包含钱包全文、邮箱全文、身份证件、材料附件、驳回全文或审核员身份。审核原因在受保护的对应记录查看，不写入通知摘要。必要内容缺失时不显示原始模板键、占位符或虚构值，保留业务结果可查并按现有消息异常规则处理；语言缺失采用消息框架既有回落。


## 5. 跨模块衔接与验收

| 对接位置 | 需保持或最终核对的内容 |
| --- | --- |
| 机构认证审核 V2.5 | 已采用仅站内信和当前提交关联；机构审核通过／驳回通知仍唯一由其发送，审核模块不再重复生成本模块已发送的待审核通知；机构标准由机构决定，运营权限与本人资料边界保持 |
| 面客消息中心 | 最终核对四套面客模板、账户安全／认证资格分类、账户隔离、强制告知、申请状态与审核记录页/账户设置映射、历史与当前资格；本期无可选空开关，无业务邮件 |
| 运营消息中心 | 最终核对机构资料待审核通知、审核待办分类、运营机构审核详情及本次提交关联；正常运营/SPV 同范围，个人已读与审核任务结束分开，旧消息不处理新提交 |
| 两个消息中心共同处理 | 消息归类和目标页面尚需核对；旧框架合并同类消息后恢复未读的规则须区分新事实与重复送达，本模块重复事实不得再次提醒。保留已有消息异常／语言回落，不以未适配改变业务定义 |

验收集中在[关键站内信验收（主 PRD 8.7）](./01-资金方登录与账户体系-PRD.md#notification-acceptance)，邮箱验证码另见[联系邮箱验证与修改验收（主 PRD 8.3）](./01-资金方登录与账户体系-PRD.md#accept-email)。重点核对触发事实、三方隔离、同一事实去重、五模板、旧消息与当前状态、停用不可读，以及失败不回滚业务。本文件不规定页面布局；消息编号和规则来源不作为产品界面文案。
