## 功能需求说明 · **资产方 SSO 接入**

> **本册读者**：资产方登录链路的实现方。
> **本册写的是「接入方」一侧的全部规格**——本平台作为 OIDC 依赖方（RP）接入资产可信平台授权中心时，本平台要做什么、要怎么表现、什么结果算对。

## 3. 第三方授权登录的接入规则（`F-L20` / `F-L21`）

### 3.1 本平台必须保证的结果（真实能力依赖 `Q-L01`）

> **`Q-L01`：授权中心（资产可信平台 A2）为新增模块，其对外提供信息的具体形式未定。** 下表写的是**本平台自己必须保证的结果**——它们不依赖对端怎么实现，因此现在就可以定稿并开发。**表中任何一条都不构成对授权方的规格要求**，实际能力由开发对接核实；分工、差异处理与验收边界统一见[主册 8.4](./00-登录主干与资产方SSO接入-PRD.md#interface-boundary)。
> **既定技术约束**：OIDC 沿用 WS-348 issue 明确要求；本节不展开协议参数与算法，具体联调约定仍受 `Q-L01` 约束。

| # | 本平台必须保证的结果 | 不做到会发生什么 |
| --- | --- | --- |
| 1 | 用户在授权中心完成登录后，**只能回到本平台预先登记的那一个落地位置** | 用户可能被带到任意第三方页面，构成钓鱼 |
| 2 | **一次授权只能换来一次登录**；同一次授权被重复使用或被他人搬到别处使用时，一律判定登录失败 | 他人截获一次授权就能反复登进同一个账号 |
| 3 | 本平台必须**能够确认这次身份信息确实来自资产可信平台授权中心、确实是发给本平台的、且尚未过期**；三者任一不成立即判定登录失败 | 伪造的身份信息可以直接登进来 |
| 4 | 用户**在授权中心已经登录时，不应被要求再输入一次凭据** | 入口 B 每次都要重新登录一遍，体验明显劣化 |
| 5 | 上游登出后，本平台的登录**必须在约定时限内同步结束**（6.3） | 用户以为已经全部登出，实际还留着一个活着的登录 |
| 6 | 上游给出的任何信息**只读消费、绝不回写**（第 7 章） | 两边状态互相打架，身份权威被架空 |
| 7 | 登录过程中产生的凭据与回跳句柄**不出现在用户可见的地址栏，也不进日志** | 复制一条链接或翻一次日志就能拿到别人的登录 |
| 8 | 授权中心不可用、超时或返回异常时，用户**落回游客态并能继续浏览**，不出现没有出口的页面 | 用户被卡在一个只有报错的页面上 |

| 项 | 现状 |
| --- | --- |
| **上游会给出哪些身份信息** | **暂定：用户 id、钱包地址、邮箱、企业 id，以及个人认证基本信息、企业认证基本信息**（2026-09-21）。两类基本信息实际供给仍需核实；9.4 已按 P01 明确字段分类、本人可见及业务用途边界，不等于上游接口已经提供 |
| 授权中心对外提供信息的具体形式与地址 | 未定 |
| 用户在上游已登录时能否免去二次输入 | 未定。不支持时入口 B 每次都要用户手动登录一遍 |
| 上游认证状态的取值语义与变更告知方式（`X-07`） | 开发核实实际接口如何表达当前有效综合认证结论及其变化；第 7 章的只读、放行与复核规则保持 |
| 上游登出的告知方式（`X-08`） | 未定 |
| 授权中心是否执行与主干 3.3 同等强度的回跳校验（`RT-4`） | **未确认** → 跨平台回跳按主干 3.7 兜底，不放行（`E-L06`） |

### 3.2 登录失败的判定规则（`SSO-1`～`SSO-3`，`F-L20`）

> **本节写的是「什么情况下这次登录被判定为失败、用户看到什么、还能做什么」。** 用什么方式达成由开发设计。
> **三条规则全部由服务端判定，前端不构成防线。**

| 编号 | 规则（业务口径） | 判定不通过时 |
| --- | --- | --- |
| **`SSO-1`** | **落地位置唯一**：授权完成后，用户只能回到本平台**预先登记的那一个落地位置**；任何其他落地位置——包括看起来很像、只差一级路径或多一个参数的——一律不接受 | 判定**登录失败**（`R3`），按 `E-L30` 处理。成因若是两边登记不一致，**另触发运维告警** |
| **`SSO-2`** | **一次授权只用一次**：同一次授权只能换来一次登录。被第二次使用、或被搬到另一个浏览器会话里使用，一律视为重放 | 判定**登录失败**（`R3`），按 `E-L31` / `E-L32` 处理。**用户侧表现与其他失败完全一致**，不提示「检测到重放」——那等于告诉探测者他触到了哪一条 |
| **`SSO-3`** | **身份信息可信且在有效期内**：本平台必须能确认这次身份信息**确实来自资产可信平台授权中心**、**确实是发给本平台的**、**且尚未过期**。三者任一不成立即判定失败。既有有效期兼容约束引用 `N-L24`，本册不展开校验实现 | 判定**登录失败**（`R3`），按 `E-L33` / `E-L36` 处理。「不是来自授权中心」属配置类成因，**另触发运维告警** |

> **`SSO-4` 已移除。** 原条目规定的是授权码交换的具体实现形式，**不含任何产品可观察的行为**，属技术方案，交由开发设计。编号 `SSO-4` **作废、不再复用**；原先由它承载的业务结果（「这次授权确实是本平台发起的、没有被中途掉包」）已并入 **`SSO-3`**。变更已登记在主册第 6 章。

**三条规则任一不通过时，用户看到什么**（与 `R3` 完全一致，见 5.2）：

| 项 | 表现 |
| --- | --- |
| 落点 | **回落游客态**，停在原本要去的那个页面的游客视图，**不被送到资产广场、不弹登录页** |
| 提示 | 一条 Toast：中性说明 + **一个可复述给客服的错误码** |
| **不告诉用户什么** | **不说明具体是哪一条不通过**（`D-L90`）——判定细节讲给用户，等于讲给探测者 |
| 还能做什么 | 继续浏览；也可以**重新发起一次登录** |
| 不会发生什么 | 不进错误页、不白屏、不产生没有出口的页面 |

### 3.3 已登录用户免二次输入与回退（`SSO-5`，`F-L21`）

| 编号 | 规则（业务口径） | 用户看到 |
| --- | --- | --- |
| **`SSO-5`** | 用户**在授权中心已经处于登录状态时，不应被要求再输入一次凭据**——本平台优先按这条路走。若上游判定本次仍需用户亲自操作，则**回退为一次完整登录，且回退最多一次**（`N-L21`） | 顺利时：点「继续前往」后一段短暂的过渡即回到本平台，**不出现登录表单**；需要回退时：在授权中心看到一次登录页。**任何情况下都不得出现「反复被弹回登录页」** |
| — | 该能力是否可用取决于上游 `[待确认 Q-L01]`。**不可用时链路仍必须成立**，只是每次都要用户在上游登录一次 | 体验劣化，但**功能不缺失** |

### 6.5 两类角色的登录时效各自独立（原 `Q-L02`，**已确认关闭**）

> **用户 2026-09-18 明确：无需统一口径。** 本节由待确认项转为**已定结论**，不再带待确认标记。

| 项 | 结论 |
| --- | --- |
| **结论** | **资产方的 SSO 登录与资金方的钱包登录，在有效期与过期表达上各自独立，本平台不强求一致。** 两者的登录方式本来就不同——一个由上游平台决定什么时候结束，一个由钱包连接的实际情况决定；硬拉齐反而要为其中一侧凭空造一个不自然的失效条件 |
| **本册定什么** | **只定资产方 SSO 这一侧**：`S-1`～`S-6`，登录有效期 `N-L20` = **1 周（暂定）** |
| **本册不定什么** | **资金方钱包登录的时效与过期表达归 WS-349 自己定**，本册不替它定死，也不要求它跟本册取同一个值 |
| **两侧仍然共用的部分** | `ST-2`（退出一律回落游客态）与 `D-L108`（失效后就地降级、不弹登录页）是**主干口径，两类角色共用**——「各自独立」只作用于**多久过期**与**怎么表达过期**，不作用于**过期之后落在哪** |

保存期间退出、过期、身份变化或离开账户页，不显示迟到成功、不将用户拉回旧页面；下一次进入读取最后已成功保存值。已完成的保存不因离开页面被撤回，尚未成功的选择不作为偏好草稿保留；会话失效时未保存提示沿用 `S-5`。该规则不承诺离开页面会取消已完成的保存。

### 9.2 钱包地址缩写与账户下拉菜单（`F-L32`）

**`D-L117`**：正常登录后，顶部账户入口以钱包地址缩写展示，不能只写角色名「资产方」。缩写采用前 6 个字符（含地址前缀）＋省略号＋后 4 个字符，短于或等于 10 个字符的值完整展示；保留原地址大小写。悬浮或键盘聚焦可读完整地址，账户页同样可核对全文。这里是只读身份展示，不增加钱包登录、连接、切换、签名或交易能力。上游暂未给钱包地址时使用「我的账户」作为入口，不用示例地址冒充真实信息，也不因此阻断登录。

悬浮展开的账户下拉菜单同时支持点击和键盘打开。菜单内显示角色「资产方」，提供「企业信息」「账户设置」及既有适用入口；不出现「机构信息」。仅在该菜单提供「退出登录」；退出沿用 `S-2`，提示退出本平台不会退出资产可信平台。关闭菜单返回入口焦点；只读地址更新后，顶部缩写与账户详情须属于同一当前账户，不残留上一人的信息。

资金方菜单与账户功能由 WS-349 承接；本章定义资产方菜单，主干只共享登录后入口采用钱包地址缩写的呈现规则。

### 9.3 企业信息只读（`P-L14` / `F-L33`）

**`D-L118`**：菜单名称及页面标题均为「企业信息」。进入独立详情页，面包屑可返回原业务浏览入口；已登录资产方 `L0`、`L3` 均仅可查看当前本人账户有效归属下已取得资料（主干矩阵第 19 行）。页面显示企业 id 对应的企业认证基本信息，不在账户设置重复整套企业详情，不提供机构注册、编辑、提交审核或材料上传。

页面统一说明资料由资产可信平台维护，展示 9.4 的企业基本信息；适用的上游模板字段按实际已确认供给展示，不制造其他注册地的空必填项。资料来自当前企业，不从企业名称或钱包地址推断归属；当前有效企业关联与待审核企业变更须区分，按 4.2 处理；不新增本地成员管理或企业切换。

### 9.4 上游只读字段与展示边界（`F-L23` / `F-L32` / `F-L33`）

**`D-L119` 资料与业务信息的可见范围**：依据用户 P01，个人、企业基本资料在借贷平台仅本人可见。“本人”指当前合法登录的本平台资产方账户及其有效企业归属，不等同于任何资产方角色、同钱包资金方、同企业的其他账户或运营人员。`P-L12`、`P-L14` 不向其他账户开放，直接访问也不得取得他人资料；认证为 `L3` 不增加查看他人基本资料的权利。

业务所需信息自动获取，沿用相应业务已确认的对象、字段、可见角色和状态规则。业务场景所需的单项企业名称、注册信息等可以作为业务信息展示，但不能以“业务信息可展示”为由开放整份企业档案、个人资料、联系方式或证件信息。本册不增加资金方、游客或运营角色权限；无既有业务用途与可见角色依据的字段仍限本人。来源相同不代表可见范围相同，不能把账户资料整组搬到广场、融资详情或消息正文。

| **`E-L38`** | 对端账户被停用 | `R2`；Toast 含客服入口 | 回落游客态，已有会话立即失效 | 否 |
| **`E-L39`** | 上游返回的认证状态不在约定枚举内 | **按 `L0` 保守处理**，不猜、不修正（7.2） | 正常落地但停在 `T2` | **是（配置类）** |
| **`E-L40`** | 上游给出用户 id，但缺少可选主体信息或某类基本信息 | 正常登录；缺失字段隐藏，整个个人 / 企业资料组缺失时保留分区或页面并显示空态（9.1、9.3）；不要求补填 | 正常落地，仍可从菜单查看企业信息空态 | 否 |
| **`E-L41`** | **影子账号建立失败** | **`P-L13` 失败页**：可复述错误码 + 「重试」+「以游客身份继续浏览」两个出口；**不得白屏、不得静默跳回**（`D-L89`） | `P-L13` | **是** |
| **`E-L42`** | 回跳时本平台已有**另一账号**的会话 | **先销毁旧会话再建新会话**（防串台），并在落地后 Toast 告知已切换账号 | 正常落地 | 否 |
| **`E-L43`** | 上游触发全局会话失效 | 本平台会话在 `N-L22` 内失效（`S-4`） | **回落游客态**，页面就地降级为游客视图，不弹登录页 | 通道异常时**是** |
| **`E-L44`** | 会话到期时正在填表 | Toast 提示内容未保存，**不暂存草稿**（`S-5`） | 回落游客态 | 否 |
| **`E-L45`** | 回跳目标判定不通过 / 已失效 | 落默认落地页 + Toast，**不报错**（主干 3.7） | 默认落地页 | 否 |
| **`E-L46`** | 入口 B：用户在授权中心登录页放弃返回 | 按「待完成授权」记录恢复类型选择页或原触发点（`D-L93`），**不得白屏或报错** | 类型选择页 / 原触发点 | 否 |
| **`E-L47`** | 入口 B：用户选错类型，在授权中心建出空账号 | **本平台无法撤销**；以主干 2.3 的卡片文案预防为主；本平台不提供任何「清理对端账号」入口 | — | 否 |
| **`E-L48`** | 收到一条**无法确认来源**的登出告知 | **丢弃，不结束任何用户的登录** | 无变化 | **是（安全）** |
| **`E-L49`** | 上游的登出告知**没有送达** | 仍须确认并结束已失效登录，不能长期保留（`D-L106`、`S-4`） | 回落游客态 | 长期收不到任何告知时**是** |

> **`E-L30`～`E-L38` 的用户可见文案统一为中性表述 + 错误码**，不区分内部成因；成因进服务端日志（`S-6`）。

## 11. 非功能约束、依赖与风险

### 11.1 非功能约束

| 类别 | 要求 |
| --- | --- |
| **性能** | `P-L10` 中转页须在用户回到本平台后立即可见并展示处理中状态，**不得白屏**；免二次输入路径的全程耗时 P95 ≤ `N-L27`；登录状态校验不得阻塞游客态浏览 |
| **安全（强制条款）** | ① `SSO-1`～`SSO-3`、`SSO-5` 全部由服务端判定，前端不构成防线；② 用户身份只能按上游给出的用户 id 来认，**不得改用邮箱、钱包地址或企业 id**；③ 上游给的主体信息只读，本平台不提供修改入口、也一律拒绝修改请求；④ 认证状态**只读、不得回写**；⑤ 硬卡点放行前必须实时向上游复核，不凭快照；⑥ 上游登出必须能同步结束本平台登录，且**无法确认来源的登出告知一律丢弃**；⑦ **回跳判定必须在主干统一实现，本册不得自建**；⑧ 登录过程中产生的凭据、回跳句柄与签名原文不入日志；⑨ **不得以「请求是从哪里来的」作为信任依据**——信任只来自 `SSO-1`～`SSO-3` 的判定结果 |
| **可用性** | **无错误死胡同**：每一个失败态都必须有出口（回落游客态或 `P-L13` 的两个按钮）；跨平台跳转前必有离站告知 |
| **可访问性** | 置灰控件可聚焦、可读屏并读出受限原因；离站告知不依赖颜色单独表意；中转页处理中状态对读屏可播报 |
| **兼容性** | 桌面优先；用户从授权中心返回时，**浏览器后退、页面被恢复、浏览器限制第三方站点存储**三种情况下均不得白屏（`D-L93`） |
| **国际化** | 面向用户的文案提供中英双语，遵循本平台的国际化与展示基线 |

### 11.3 风险

| 编号 | 风险 | 后果 | 缓解 |
| --- | --- | --- | --- |
| **`RISK-L01`** | **授权中心不可用时，资产方在本平台完全无法登录**——本平台刻意不为资产方保留任何本地凭据 | 资产方侧登录整体不可用 | 游客态不受影响，用户仍可浏览；`E-L34` 文案明确指向上游并提示稍后重试。**不以「加一套本地凭据」缓解**，那会瓦解第三方授权登录的价值（`D-L13`） |
