# 借贷平台 · 面客端 · 登录主干与资产方 SSO 接入 PRD
## 功能需求说明 · **资产方 SSO 接入**

> **本册读者**：资产方登录链路的实现方。
> **本册写的是「接入方」一侧的全部规格**——本平台作为 OIDC 依赖方（RP）接入资产可信平台授权中心时，本平台要做什么、要怎么表现、什么结果算对。
> **本册不写授权中心（资产可信平台 A2）自身怎么做**——它是新增模块，对外提供信息的形式尚未确定（`Q-L01`）；本册只写**本平台这一侧必须保证的结果与用户可见的表现**。
> 回跳、类型选择、引导组件、权限矩阵、三态契约在**登录主干两分册**（主干 A / 主干 B），本册**只调用、不实现、不改定义**；验收见《验收需求说明》。
> **流程图与状态机不在本册**——本册涉及的三张图（授权登录结果分流与统一落地、会话状态机、资产方三态判定）统一在 [`03-登录主干与资产方SSO接入-流程图与状态机.md`](./03-登录主干与资产方SSO接入-流程图与状态机.md)，本册正文只引用图号。
> **本册写「什么情况下用户被判定为登录失败、他看到什么、还能做什么」，不写用什么协议参数和校验算法达成**——达成手段属技术方案，由开发设计。

## 3. 第三方授权登录的接入规则（`F-L20` / `F-L21`）

### 3.1 本平台必须保证的结果 `[待确认 Q-L01]`

> **`Q-L01`：授权中心（资产可信平台 A2）为新增模块，其对外提供信息的具体形式未定。** 下表写的是**本平台自己必须保证的结果**——它们不依赖对端怎么实现，因此现在就可以定稿并开发。**表中任何一条都不构成对授权方的规格要求**，授权方义务以后续的跨平台契约册为准。
> **本节不写达成手段**：用什么协议、什么算法、什么参数去满足下面这些结果，由开发在技术方案里决定。

| # | 本平台必须保证的结果 | 不做到会发生什么 |
| --- | --- | --- |
| 1 | 用户在授权中心完成登录后，**只能回到本平台预先登记的那一个落地位置** | 用户可能被带到任意第三方页面，构成钓鱼 |
| 2 | **一次授权只能换来一次登录**；同一次授权被重复使用或被他人搬到别处使用时，一律判定登录失败 | 他人截获一次授权就能反复登进同一个账号 |
| 3 | 本平台必须**能够确认这次身份信息确实来自资产可信平台授权中心、确实是发给本平台的、且尚未过期**；三者任一不成立即判定登录失败 | 伪造的身份信息可以直接登进来 |
| 4 | 用户**在授权中心已经登录时，不应被要求再输入一次凭据** | 入口 B 每次都要重新登录一遍，体验明显劣化 |
| 5 | 上游登出后，本平台的登录**必须在约定时限内同步结束**（6.3） | 用户以为已经全部登出，实际还留着一个活着的登录 |
| 6 | 上游给出的任何信息**只读消费、绝不回写**（第 7 章） | 两边状态互相打架，身份权威被架空 |
| 7 | 登录过程中产生的凭据与回跳句柄**不出现在用户可见的地址栏，也不进日志** | 复制一条链接或翻一次日志就能拿到别人的登录 |
| 8 | 授权中心不可用、超时或返回异常时，用户**落回游客态并能继续浏览**，不出现没有出口的页面 | 用户被卡在一个只有报错的页面上 |

**`[待确认 Q-L01]` 清单**——以下各项在契约册落定前**不得写死，不得据以验收**：

| 项 | 现状 |
| --- | --- |
| **上游会给出哪些身份信息** | **暂定四项：用户 id、钱包地址、邮箱、企业 id**（2026-09-18）。本册 4.1～4.3、10.1 已按这四项写实，**但仍为暂定，以第三方平台最终确认为准** |
| 授权中心对外提供信息的具体形式与地址 | 未定 |
| 用户在上游已登录时能否免去二次输入 | 未定。不支持时入口 B 每次都要用户手动登录一遍 |
| 上游认证状态的取值语义与变更告知方式（`X-07`） | 未定。本册按第 7 章的**消费机制**写规格，取值语义以契约册为准 |
| 上游登出的告知方式（`X-08`） | 未定 |
| 授权中心是否执行与主干 3.3 同等强度的回跳校验（`RT-4`） | **未确认** → 跨平台回跳按主干 3.7 兜底，不放行（`E-L06`） |

**暂定的四项信息，本平台各自怎么用** `[待确认 Q-L01]`

| 上游给的 | 本平台怎么用 | 备注 |
| --- | --- | --- |
| **用户 id** | **身份映射主键**——落为本平台的 `asset_account_id`，用来认「这是同一个人」（4.1） | 四项里**唯一**参与身份判定的一项 |
| **企业 id** | **机构归属标识**——表示这个人属于哪家企业，用于展示与业务归属（4.2） | **不参与身份映射**，不做识别依据 |
| **钱包地址** | **只读快照**，仅按需展示 | **是否参与身份映射标为待确认**；在确认之前**一律不参与**（4.2） |
| **邮箱** | **只读快照**，仅展示、标注来源 | 本平台**仍然不采集、不提供录入与修改入口**（`D-L88`） |

### 3.2 登录失败的判定规则（`SSO-1`～`SSO-3`，`F-L20`）

> **本节写的是「什么情况下这次登录被判定为失败、用户看到什么、还能做什么」。** 用什么方式达成由开发设计。
> **三条规则全部由服务端判定，前端不构成防线。**

| 编号 | 规则（业务口径） | 判定不通过时 |
| --- | --- | --- |
| **`SSO-1`** | **落地位置唯一**：授权完成后，用户只能回到本平台**预先登记的那一个落地位置**；任何其他落地位置——包括看起来很像、只差一级路径或多一个参数的——一律不接受 | 判定**登录失败**（`R3`），按 `E-L30` 处理。成因若是两边登记不一致，**另触发运维告警** |
| **`SSO-2`** | **一次授权只用一次**：同一次授权只能换来一次登录。被第二次使用、或被搬到另一个浏览器会话里使用，一律视为重放 | 判定**登录失败**（`R3`），按 `E-L31` / `E-L32` 处理。**用户侧表现与其他失败完全一致**，不提示「检测到重放」——那等于告诉探测者他触到了哪一条 |
| **`SSO-3`** | **身份信息可信且在有效期内**：本平台必须能确认这次身份信息**确实来自资产可信平台授权中心**、**确实是发给本平台的**、**且尚未过期**。三者任一不成立即判定失败。「尚未过期」允许一个很小的时间容忍窗口（`N-L24`），用于吸收两边服务器的正常时间差 | 判定**登录失败**（`R3`），按 `E-L33` / `E-L36` 处理。「不是来自授权中心」属配置类成因，**另触发运维告警** |

> **`SSO-4` 已移除。** 原条目规定的是授权码交换的具体实现形式，**不含任何产品可观察的行为**，属技术方案，交由开发设计。编号 `SSO-4` **作废、不再复用**；原先由它承载的业务结果（「这次授权确实是本平台发起的、没有被中途掉包」）已并入 **`SSO-3`**。变更已登记在主册第 6 章。

**三条规则任一不通过时，用户看到什么**（与 `R3` 完全一致，见 5.2）：

| 项 | 表现 |
| --- | --- |
| 落点 | **回落游客态**，停在原本要去的那个页面的游客视图，**不被送到首页、不弹登录页** |
| 提示 | 一条 Toast：中性说明 + **一个可复述给客服的错误码** |
| **不告诉用户什么** | **不说明具体是哪一条不通过**（`D-L90`）——判定细节讲给用户，等于讲给探测者 |
| 还能做什么 | 继续浏览；也可以**重新发起一次登录** |
| 不会发生什么 | 不进错误页、不白屏、不产生没有出口的页面 |

### 3.3 已登录用户免二次输入与回退（`SSO-5`，`F-L21`）

| 编号 | 规则（业务口径） | 用户看到 |

| **`SSO-5`** | 用户**在授权中心已经处于登录状态时，不应被要求再输入一次凭据**——本平台优先按这条路走。若上游判定本次仍需用户亲自操作，则**回退为一次完整登录，且回退最多一次**（`N-L21`） | 顺利时：点「继续前往」后一段短暂的过渡即回到本平台，**不出现登录表单**；需要回退时：在授权中心看到一次登录页。**任何情况下都不得出现「反复被弹回登录页」** |

## 4. 影子账号（`F-L22` / `F-L23`）

### 4.1 映射键

| 项 | 口径 |
| --- | --- |
| 映射键 | **上游给出的用户 id** `[待确认 Q-L01]`，落为本平台 `asset_account_id`，**不可变、唯一** |
| 建号时点 | 首次 SSO 成功回跳（`L-5`）时创建；失败按 `E-L41` 处理 |
| **禁止** | **禁止以邮箱、钱包地址或企业 id 作为映射键**；服务端必须拒绝任何以这三项做主键或唯一标识的实现 |
| **企业 id 的分工** | **只表示机构归属**（这个人属于哪家企业），**不参与身份映射**。一家企业下可以有多个用户 id，用企业 id 认人会把同事认成同一个账号 |
| **钱包地址的分工** | **只读快照**；**是否参与身份映射 `[待确认 Q-L01]`，在确认前一律不参与** |

| 编号 | 口径 |
| --- | --- |
| **`D-L84`** | **映射键只能是上游给出的、代表这一个人的不可变标识（当前暂定为用户 id）。** **为什么不能用邮箱**：邮箱是可以换的，用户在上游改一次邮箱，本平台就会把同一个人识别成两个账户——历史融资记录、协议同意记录、消息全部分裂，且无法自动合并。**为什么不能用钱包地址**：钱包可能为空、也可能被换掉，用它认人会让一批人塌缩成同一个账号或凭空多出一个账号。**为什么不能用企业 id**：企业 id 认的是机构不是人，同一家企业的两个经办人会被认成同一个账号 |
| **`D-L112`** | **多出来的上游信息不等于多出来的本平台能力。** 上游给了钱包地址，**不代表资产方在本平台获得任何与钱包相关的功能**——不展示钱包相关操作入口、不因此放开任何权限矩阵行、不作为登录方式。资产方的登录方式仍然只有第三方授权登录一种（`D-L13`）；钱包登录是资金方的形态，两者不因字段重名而互通 |

| 字段类别 | 字段 | 权威方 | 本平台 |
| --- | --- | --- | --- |
| 映射键 | `asset_account_id`（来自上游的**用户 id**） | 资产可信平台 | 只读、不可变 |
| **主体信息快照** `[待确认 Q-L01]` | **企业 id**（机构归属）、**钱包地址**、**邮箱** | **资产可信平台** | **只读**，本平台**不提供任何录入或修改入口，一律拒绝任何修改请求** |

### 6.3 跨平台登录联动失效（`S-4`，`F-L28`）—— **本册相对基线的实质变更**

> **为什么必须改**：基线的跨端登出建立在「金融服务端与资产平台浏览器同域」这一前提上。三平台独立部署后**同域不再成立**，浏览器侧的登出信号既不可靠也不可验证，因此 `S-4` 必须改为**由上游直接通知本平台后台（不经用户浏览器）**，并辅以本平台定期复核。

| --- | --- |
| **`S-4`**（**强制条款**） | 资产可信平台触发全局会话失效后，本平台会话须在 `N-L22` 内失效；失效后**回落游客态并给出说明，不弹登录页**（`E-L43`） |

| 场景 | 用户看到 |
| --- | --- |
| 主动退出 | 就地回到当前页面的游客视图 + Toast「已退出登录」 |
| 会话到期 | 就地降级为游客视图 + Toast「登录已过期，可重新登录继续」 |

### 6.5 两类角色的登录时效各自独立（原 `Q-L02`，**已确认关闭**）

> **用户 2026-09-18 明确：无需统一口径。** 本节由待确认项转为**已定结论**，不再带待确认标记。

| 项 | 结论 |
| --- | --- |
| **结论** | **资产方的 SSO 登录与资金方的钱包登录，在有效期与过期表达上各自独立，本平台不强求一致。** 两者的登录方式本来就不同——一个由上游平台决定什么时候结束，一个由钱包连接的实际情况决定；硬拉齐反而要为其中一侧凭空造一个不自然的失效条件 |
| **本册定什么** | **只定资产方 SSO 这一侧**：`S-1`～`S-6`，登录有效期 `N-L20` = **1 周（暂定）** |
| **本册不定什么** | **资金方钱包登录的时效与过期表达归 WS-349 自己定**，本册不替它定死，也不要求它跟本册取同一个值 |
| **两侧仍然共用的部分** | `ST-2`（退出一律回落游客态）与 `D-L108`（失效后就地降级、不弹登录页）是**主干口径，两类角色共用**——「各自独立」只作用于**多久过期**与**怎么表达过期**，不作用于**过期之后落在哪** |
| **对用户的影响** | 同一台设备上同时用过两种身份的用户，可能遇到一侧还在登录、另一侧已经过期。这是可接受的——两侧本来就是两条独立的登录，界面上也各自给出各自的过期说明，不会出现「一处过期、全站莫名其妙退出」 |

| 场景 | 本平台的行为 |
| --- | --- |

## 8. 资产方三态映射与降级表达（`F-L30` / `F-L31`）

### 8.1 三态二维判定与契约取值

三态由**两个独立维度**共同判定，**不是一维状态机**：

| 维度 | 取值 | 变化来源 |
| --- | --- | --- |

| **完备度** | 资产方只有 `L0` / `L3` | **上游**：资产可信平台的认证结论，可升可降 |

**契约四字段的资产方取值规则**

| `identity_type` | `null` | `asset_party` | `asset_party` |
| `completeness_level` | `L0` | `L0` | `L3` |
| `account_id` | `null` | `asset_account_id` | `asset_account_id` |

| 编号 | 口径 |
| --- | --- |
| **`D-L111`** | **三态必须二维判定，不得压成一维状态机。** 两个维度的变化源不同且互不通知——会话可能因跨平台登出在任意时刻消失，完备度可能因上游认证被驳回而在会话存续期间从 `L3` 掉回 `L0`。压成一维后：① 「会话有效但认证被收回」和「认证有效但会话已失效」这两个真实组合会被迫塞进同一个状态或被漏掉；② 每加一个角色或一档完备度，状态迁移按乘积增长；③ 每个功能模块都会各自补一套分支来还原被丢掉的那一维，口径必然漂移 |
| — | 资产方**不使用 `L1` / `L2`**——这两档是资金方申请单的「待审核」「已驳回」，资产方链路上不存在（`D-L62`） |

| **`E-L39`** | 上游返回的认证状态不在约定枚举内 | **按 `L0` 保守处理**，不猜、不修正（7.2） | 正常落地但停在 `T2` | **是（配置类）** |
| **`E-L40`** | 上游给出了账户标识，但某些主体信息没给（如未给企业名称） | **正常建号、正常登录**，缺失的区块整块不展示（`D-L88`） | 正常落地 | 否 |
| **`E-L41`** | **影子账号建立失败** | **`P-L13` 失败页**：可复述错误码 + 「重试」+「以游客身份继续浏览」两个出口；**不得白屏、不得静默跳回**（`D-L89`） | `P-L13` | **是** |
| **`E-L42`** | 回跳时本平台已有**另一账号**的会话 | **先销毁旧会话再建新会话**（防串台），并在落地后 Toast 告知已切换账号 | 正常落地 | 否 |
| **`E-L43`** | 上游触发全局会话失效 | 本平台会话在 `N-L22` 内失效（`S-4`） | **回落游客态**，页面就地降级为游客视图，不弹登录页 | 通道异常时**是** |
| **`E-L44`** | 会话到期时正在填表 | Toast 提示内容未保存，**不暂存草稿**（`S-5`） | 回落游客态 | 否 |
| **`E-L45`** | 回跳目标判定不通过 / 已失效 | 落默认落地页 + Toast，**不报错**（主干 3.7） | 默认落地页 | 否 |
| **`E-L46`** | 入口 B：用户在授权中心登录页放弃返回 | 按「待完成授权」记录恢复类型选择页或原触发点（`D-L93`），**不得白屏或报错** | 类型选择页 / 原触发点 | 否 |
| **`E-L47`** | 入口 B：用户选错类型，在授权中心建出空账号 | **本平台无法撤销**；以主干 2.3 的卡片文案预防为主；本平台不提供任何「清理对端账号」入口 | — | 否 |
| **`E-L48`** | 收到一条**无法确认来源**的登出告知 | **丢弃，不结束任何用户的登录** | 无变化 | **是（安全）** |
| **`E-L49`** | 上游的登出告知**没有送达** | 由定期复核在下一个复核点补上（`D-L106`） | 回落游客态 | 长期收不到任何告知时**是** |

> **`E-L30`～`E-L38` 的用户可见文案统一为中性表述 + 错误码**，不区分内部成因；成因进服务端日志（`S-6`）。

## 11. 非功能约束、依赖与风险

### 11.1 非功能约束

| 类别 | 要求 |
| --- | --- |
| **性能** | `P-L10` 中转页须在用户回到本平台后立即可见并展示处理中状态，**不得白屏**；免二次输入路径的全程耗时 P95 ≤ `N-L27`；登录状态校验不得阻塞游客态浏览 |
| **安全（强制条款）** | ① `SSO-1`～`SSO-3`、`SSO-5` 全部由服务端判定，前端不构成防线；② 用户身份只能按上游给出的用户 id 来认，**不得改用邮箱、钱包地址或企业 id**；③ 上游给的主体信息只读，本平台不提供修改入口、也一律拒绝修改请求；④ 认证状态**只读、不得回写**；⑤ 硬卡点放行前必须实时向上游复核，不凭快照；⑥ 上游登出必须能同步结束本平台登录，且**无法确认来源的登出告知一律丢弃**；⑦ **回跳判定必须在主干统一实现，本册不得自建**；⑧ 登录过程中产生的凭据、回跳句柄与签名原文不入日志；⑨ **不得以「请求是从哪里来的」作为信任依据**——信任只来自 `SSO-1`～`SSO-3` 的判定结果 |
| **可用性** | **无错误死胡同**：每一个失败态都必须有出口（回落游客态或 `P-L13` 的两个按钮）；跨平台跳转前必有离站告知 |
| **可访问性** | 置灰控件可聚焦、可读屏并读出受限原因；离站告知不依赖颜色单独表意；中转页处理中状态对读屏可播报 |
| **兼容性** | 桌面优先；用户从授权中心返回时，**浏览器后退、页面被恢复、浏览器限制第三方站点存储**三种情况下均不得白屏（`D-L93`） |
| **国际化** | 面向用户的文案提供中英双语，遵循本平台的国际化与展示基线 |
