# 资金方登录与账户体系 · 流程图与状态机

版本：2026-09-22。需求：WS-372。与[主 PRD](./01-资金方登录与账户体系-PRD.md)及[通知册](./03-资金方登录与账户体系-消息通知.md)共同使用。图中只表达角色、业务条件、结果和状态；字段、允许动作、时效与异常的完整定义在主 PRD，不在图册另建一套口径。

实线表示业务推进或状态变化，虚线表示关联通知。机构注册与账户可用性是两个独立业务对象；本册保留图 1～7，并单列两张状态机。功能编号定位到主 PRD 具体规则或对应验收。

<a id="login-flow"></a>
## 图 1 · 钱包连接、签名与建号

对应[主 PRD 第 2 章](./01-资金方登录与账户体系-PRD.md#wallet-login)，沿用 F-L50～57、77～78。

```mermaid
flowchart TD
    A[游客选择资金方] --> B[直接唤起钱包连接或选择]
    B -->|环境不可用 / 首次取消 / 锁定| C[类型选择页说明原因并可重试]
    B -->|连接成功但网络不支持| D[P-L20 C：切换网络或返回]
    B -->|连接成功且网络支持| E[P-L20 A：确认地址、用途、凭据提示和协议]
    E -->|重新连接失败或取消| F[P-L20 B：重试或返回]
    F --> R[从 P-L20 重新连接]
    R -->|成功且网络支持| E
    R -->|取消 / 锁定 / 失败| F
    R -->|网络不支持| D
    E -->|主动同意并点击签名| G[用户签名证明本次钱包身份]
    G -->|拒签 / 无效 / 过期或已用| H[说明原因；需要时准备新请求]
    H --> E
    G -->|地址切换| I[中止；提示用新地址重新登录]
    G -->|身份确认后地址冲突| J[P-L20 D：换钱包重连或客服]
    G -->|身份确认后账户停用| K[P-L20 E：不可登录；客服或游客浏览]
    G -->|通过且账户正常| L{首次建号？}
    L -->|是| M[建立资金方账户：正常、草稿 L0]
    M --> N[P-L21 注册引导；可稍后填写]
    L -->|否| O[复用原账户与注册资格]
    O --> P{原目标仍有效且当前有权？}
    P -->|是| Q[按主干恢复原目标及允许的动作]
    P -->|否| Z[按主干返回可浏览位置]
```

P-L20 各态均可返回类型选择，清除本次未完成签名并断开本次连接；首次连接取消不落 B。连接成功未签名不能建号或登录，返回不得越过首次注册引导。登录后的退出与插件断连含义不同，见主 PRD 第 6 章。

<a id="registration-flow"></a>
## 图 2 · 机构资料填写与提交

对应[主 PRD 第 3 章](./01-资金方登录与账户体系-PRD.md#registration)，沿用 F-L58～62、64～65。

```mermaid
flowchart TD
    A[正常登录资金方进入机构资料] --> B{当前注册状态}
    B -->|审核中 L1| C[P-L22 只读当前提交]
    B -->|草稿 L0 / 驳回 L2 / 已认证 L3| D[进入或恢复编辑草稿]
    D --> E[第一步：有效联系邮箱]
    E --> F[第二步：机构信息及多附件]
    F --> G{邮箱、字段、全部材料和模版有效？}
    G -->|否| H[定位待处理项；保留草稿]
    H --> E
    G -->|是| I[第三步：核对、同意协议、确认本次提交]
    I -->|取消| D
    I --> J{当前资格、机构唯一性及提交频次允许？}
    J -->|否| H
    J -->|是| K[提交]
    K -->|结果未知| U[保留待确认；防重复并继续核实]
    U -->|明确未接收| H
    U -->|确认已成功| L
    K -->|明确失败| H
    K -->|成功| L[覆盖唯一当前资料；新增本次提交节点；进入 L1]
    L --> C
    L -.-> O[EV-L42：运营待审核]
    L -.原为 L3.-> P[EV-L46：本人资格变化]
```

邮箱未验证可先填第二步，但不能最终提交。编辑、退出或失败分别保持原 L0/L2/L3 和已提交资料；只有成功提交才替换。每次提交都需确认；已保存草稿和同一次成功结果不因刷新重复生成。

<a id="review-flow"></a>
## 图 3 · 查看审核结果与重提

对应[主 PRD 4.1](./01-资金方登录与账户体系-PRD.md#review)，沿用 F-L63～67。审核行为以 WS-358 为准。

```mermaid
flowchart TD
    A[当前提交 L1；资金方只读进度] --> B[正常运营在 WS-358 人工审核本次提交]
    B -->|有效通过结论| C[L3；新增独立通过节点]
    B -->|有效驳回结论| D[L2；新增独立驳回节点及原因原文]
    C -.-> N[审核模块唯一发送 EV-L60]
    D -.-> O[审核模块唯一发送 EV-L61]
    D --> E[本人查看原因、修改草稿]
    C --> F[本人编辑变更草稿；说明重审影响]
    E -->|成功重提| A
    F -->|确认并成功提交变更| A
    E -->|取消或失败| D
    F -->|取消或失败| C
```

新提交和新审核分别增加真实节点；只读旧记录不能把旧资格赋予当前资料，也不能查看旧材料副本。机构标准变化或资料自动获取不触发图中任何自动审核迁移。

<a id="email-flow"></a>
## 图 4 · 首次验证与修改联系邮箱

对应[主 PRD 3.2](./01-资金方登录与账户体系-PRD.md#email-verification)、[5.2](./01-资金方登录与账户体系-PRD.md#email-change)，沿用 F-L59、71、74。

```mermaid
flowchart TD
    A[注册首次填写联系邮箱] --> C[填写待验证邮箱]
    B[账户设置修改有效邮箱] --> R[绑定钱包再认证；同会话有效 10 分钟可复用]
    R -->|未通过| B
    R -->|通过| C
    C --> D{格式、可用性、冷却和限额允许？}
    D -->|否 / 与当前相同| E[提示原因；不发码]
    E --> C
    D -->|是| F[本次滑块验证]
    F -->|未完成 / 失败 / 取消| E
    F -->|通过| G[仅向待验证邮箱发送验证码]
    G -->|申请重发| D
    G --> H[输入验证码]
    H -->|过期 / 输错达上限| E
    H -->|输错但未达上限| H
    H -->|验证码正确| I{邮箱仍未被占用？}
    I -->|否| E
    I -->|是且完成本次确认| J[有效邮箱与验证时间生效]
    J --> K{首次绑定还是修改？}
    K -->|首次| L[继续注册；无绑定站内信]
    K -->|修改| M[EV-L43 本人安全站内信；注册资格和会话不变]
```

流程未完成或离开时不改原邮箱／验证时间；每次重发都重新经过全部条件和本次滑块。审核中仅机构材料只读，不禁止该账户邮箱流程。

<a id="guidance-flow"></a>
## 图 5 · 受限业务与引导回流

对应[主 PRD 4.3～4.4](./01-资金方登录与账户体系-PRD.md#guidance)，沿用 F-L66～68。

```mermaid
flowchart TD
    A[用户触发需要机构认证的业务] --> B{正常登录且当前具备业务资格？}
    B -->|游客 / 停用 / 会话失效| C[按主干完成登录；停用不可登录]
    C -->|已正常登录| A
    C -->|停用 / 取消 / 失败| X[保持游客或当前失败提示；不执行业务]
    B -->|正常 L0| D[去完成机构注册]
    B -->|正常 L1| E[只读审核进度]
    B -->|正常 L2| F[查看驳回原文并修改]
    B -->|正常 L3| G[按该业务对象权限继续动作]
    D -->|成功提交仅到 L1| E
    F -->|成功重提仅到 L1| E
    E -->|当前有效审核通过| H[按主干核验原目标及原意图有效期]
    H -->|有效且有权| G
    H -->|无效 / 无权| I[说明并提供当前可用返回]
```

首次建号必须先进入注册引导；提交不是获得资格。可浏览场景不因未认证而全局封锁；原业务意图期限不因重登或提交刷新。

<a id="notification-flow"></a>
## 图 6 · 关键消息及发送归属

对应[通知册](./03-资金方登录与账户体系-消息通知.md)，沿用 EV-L42/43/45/46；审核结果归 WS-358。

```mermaid
flowchart LR
    A[真实成功提交] --> O[EV-L42：运营待审核消息池]
    A -->|原状态为 L3| F[EV-L46：本人资格变化]
    B[有效联系邮箱修改生效] --> G[EV-L43：本人安全告知]
    C[账户真实停用或恢复] --> H[EV-L45：本人可用性告知]
    D[WS-358 生效审核结论] --> I[WS-358 唯一发送 EV-L60/61]
    O --> J[打开时核对对应提交及当前状态]
    F --> K[本人正常登录后按当前权限查看]
    G --> K
    H --> K
```

资产方无收件。重复事实不产生新消息或重置已读，通知失败不回滚业务；停用用户不能因消息进入账户。普通操作、首次建号／首绑、失败和未读停留不另发消息。

## 图 7 · 本人资料与业务必要信息

对应[主 PRD 5.3](./01-资金方登录与账户体系-PRD.md#profile-visibility)，沿用 F-L73/78、D-L162/163。

```mermaid
flowchart TD
    A[请求查看资料] --> B{访问场景和当前归属允许？}
    B -->|否| C[拒绝；不展示旧资料或扩大权限]
    B -->|本人账户 / 指定运营审核 / 已有业务必要字段| D[按该场景最小范围取得资料]
    D -->|真实可选空值| E[按原规则展示；不阻断]
    D -->|有效且主体正确| F[展示该场景允许的信息]
    D -->|获取失败 / 必要缺失 / 主体冲突| G[明确不可用；适用重试和返回]
    G --> H[仅限制依赖操作；不改注册状态或伪造内容]
```

指定运营审核只包含已提交申请资料，不包括账户档案或未提交草稿。共用身份、证件供给和脱敏依赖未完成时，不把已取得的其他数据当作权限证明。

<a id="registration-state"></a>
## 状态机 · 机构注册

对应[主 PRD 4.2](./01-资金方登录与账户体系-PRD.md#state-contract)，沿用 D-L130～133、157。各状态允许动作以主 PRD 的四态表为准。

```mermaid
stateDiagram-v2
    [*] --> draft: 首次成功建号
    draft --> submitted: 首次成功提交
    submitted --> verified: 本次审核通过生效
    submitted --> rejected: 本次审核驳回生效
    rejected --> submitted: 成功重提
    verified --> submitted: 确认并成功提交变更
    draft: 草稿 L0
    submitted: 审核中 L1
    rejected: 已驳回 L2
    verified: 已认证 L3
```

编辑、取消、失败、未确认结果、通知阅读均不触发迁移；verified 非终态。L 档仅在正常登录时用于权限；账户停用不修改此状态机。

<a id="account-state"></a>
## 状态机 · 账户可用性

对应[主 PRD 4.2](./01-资金方登录与账户体系-PRD.md#state-contract)、[第 6 章](./01-资金方登录与账户体系-PRD.md#session)，沿用 D-L158。

```mermaid
stateDiagram-v2
    [*] --> active: 首次成功建号
    active --> disabled: 既有停用事实生效
    disabled --> active: 既有恢复事实生效
    active: 正常；有效登录后按原注册资格访问
    disabled: 已停用；全部会话失效，不可访问本人资料
```

恢复须重新登录，不自动认证或复活旧会话。登出、会话过期、插件断连、休眠标记不把账户状态改成 disabled；只影响各自定义的登录／连接／休眠结果。通知消费既有可用性事实，不因此新增运营停用功能。
