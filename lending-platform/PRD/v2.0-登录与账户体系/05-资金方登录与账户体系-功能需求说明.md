## M1 · 资金方登录与钱包签名

### 1.1 模块目标与适用角色

| 项 | 内容 |
| --- | --- |
| 目标 | 资金方用钱包地址完成身份证明并建立会话；这是本平台资金方**唯一**的登录方式 |
| 适用业务角色 | 资金方（机构经办人） |
| 前置条件 | 用户在 WS-348 的类型选择页 `P-L01` 点了**资金方入口**；该点击已直接唤起钱包 provider（1.2） |
| 责任边界 | **入口按钮的标签、位置与"点击即唤起 provider"这条交互归 WS-348**；本册负责 **provider 弹窗之后**的全部链路。本册不定义入口文案 |

### 1.2 `F-L50` 入口即连接：从类型选择页直达 provider

| 编号 | 规则 |
| --- | --- |
| **`D-L159`** | **用户在类型选择页点资金方入口，即直接唤起钱包连接弹窗。中间不存在"先进一个登录页、再点一次连接钱包"的二次点击。** 入口按钮上写的动作和用户实际得到的动作必须是同一个 |
| **`D-L134`** | 资金方登录**只有一种方式**：连接钱包 + 签名。全链路**不提供**账号密码、邮箱验证码、找回密码、注册链接或任何第二入口 |
| `F-L50-1` | 点击入口后由前端直接调起 provider：装有多个钱包插件时**先出钱包选择器，不默认取第一个**（`E-L71`）；移动端无插件环境**直接走 WalletConnect 类方案**（二维码 / deeplink，`E-L72`）。**这两种形态都由入口点击直接触发，不再需要一个中间页承载"选钱包"这一步** |
| `F-L50-2` | **连接成功不建号、不建立会话**，只把地址带回本平台，随后落到 `P-L20` 签名确认层（1.3）。**连接未成功（含用户取消）则一律不生成 `P-L20`**，按 `F-L51-4` 回到唤起弹窗的界面 |
| **`D-L160`** | **连接与签名是两个弹窗，签名不自动接着弹。** 连接本身是只读动作（不建号、不建会话），直接弹没有风险；但签名之前，平台这一侧必须先露出**用途说明**（`D-L140`）、**凭据保管须知**与**协议勾选**。签名弹窗只能由用户在 `P-L20` 上显式点击「签名并继续」触发 |
| `F-L50-3` | **环境不可用**（未检测到任何钱包 `E-L70`、SDK 加载失败 `E-L74`）在点击那一刻就能判定，此时**按 WS-348 的既定处理停在类型选择页就地说明**，保留另一条路径可选，**不进入 `P-L20`、不跳失败页、不白屏** |
| `F-L50-4` | 全链路**不提供"记住我"**（`D-L149`），也**不提供**"先输邮箱由系统判断身份"的任何形式——后者属 WS-348 已否决项，本册不得以任何形式复活 |

> **为什么合成一步**：旧写法里入口按钮写「连接钱包」，落地页主按钮还是「连接钱包」，用户点两次才见到钱包。而且这样两侧不对称——资产方那一侧点下去直接离站去授权中心，资金方却多一页。合成之后两个入口都是"点了就直接进外部环境"（授权中心 / 钱包）。

### 1.3 `F-L51` `P-L20` 签名确认层

**`P-L20` 不是登录页，是连接回来之后的落点**：它承载签名前必须露出的内容，同时兜住连接环节的失败与中断。

| 编号 | 规则 |
| --- | --- |
| **`D-L161`** | `P-L20` 是资金方登录链路**唯一的界面落点**：连接成功后的签名确认、连接失败与中断、链不支持、地址冲突**全部落在这一页的不同状态上**。**任一状态都必须提供「返回选择用户类型」的出路，不得出现空页、白屏或无出路的死角** |
| `F-L51-1` | **签名确认态**（默认，连接成功后）自上而下依次为：钱包地址只读回显（`C-L22` 缩略 + 复制）→ **用途说明**（1.6）→ **凭据保管提示第 2 条**（7.5）→ **协议勾选行**（挂载点，正文归 WS-361）→ 主按钮「签名并继续」 |
| **`D-L139`** | **地址一律取自钱包 provider，不提供手工填写入口。** 回显的地址**只读**；用户若要换地址，在钱包里切换后重新连接 |
| **`D-L142`** | 钱包清单与连接 SDK **不在 PRD 锁定**，只写能力要求：连接 / 断开 / 感知账户切换 / 感知与切换网络 / 链上消息签名 |
| `F-L51-2` | 协议未勾选时「签名并继续」**不可点**，且不得下发签名挑战 |
| `F-L51-3` | 用户在 `P-L20` 点「重新连接钱包」时，重新唤起 provider；**已连接的地址被新地址整体替换**，不保留上一次的任何中间态 |

**`P-L20` 的五个状态与各自的出路**

| 态 | 何时进入 | 页面主体 | 出路（**每一态都必须有**） |
| --- | --- | --- | --- |
| **A 签名确认** | 连接成功、链受支持 | 见 `F-L51-1` | 「签名并继续」／「重新连接钱包」／**「返回选择用户类型」** |
| **B 未连接** | **仅限从 `P-L20` 发起的「重新连接钱包」未成功**（用户在该次弹窗里拒绝连接 `E-L73`、钱包已锁定 `E-L87` 等） | 说明发生了什么 + 下一步怎么做（解锁钱包 / 重试） | 「重新连接钱包」／**「返回选择用户类型」** |
| **C 网络不支持** | 连接成功但链 ID 不在支持范围（`E-L77`） | 说明仅支持 EVM 系列并指引切换网络 | 「已切换，重试」／「重新连接钱包」／**「返回选择用户类型」** |
| **D 地址冲突** | 签名验证通过后，服务端判定该地址已被**另一资金方账号**绑定（`E-L81`） | 明确说明该地址已被占用 + 客服入口 | 「换一个钱包地址重新连接」／**「返回选择用户类型」** |
| **E 账号停用** | 签名验证通过后，服务端判定 `account_status = disabled`（`E-L86`） | 明确告知停用 + 客服入口 | **「返回选择用户类型」**／「以游客身份继续浏览」 |

| 编号 | 规则 |
| --- | --- |
| `F-L51-4` | **连接弹窗内的取消 / 失败，一律回到唤起该弹窗的那个界面**（主干 `E-L11`，入口这一段的持表方是主干）：**入口点击唤起的 → 回类型选择页**；**`P-L20`「重新连接钱包」唤起的 → 回 `P-L20`**（以态 B 呈现）。两种情况都**不得留下空白页** |
| `F-L51-7` | **`P-L20` 态 B 只在 `F-L51-4` 的第二种情况下出现。** 用户从类型选择页第一次点入口就取消的，他还没进入资金方链路，落点是类型选择页而不是态 B——**不得为这种情形先造一个 `P-L20` 再显示"未连接"** |
| `F-L51-5` | 态 B / C / D / E **都不建立会话**；态 D / E 发生在验签之后，此时**已建立的会话（若有）立即失效** |
| `F-L51-6` | 「返回选择用户类型」跳回 WS-348 的类型选择页，并**断开本次钱包连接、不保留任何签名中间态**（与 WS-348 的「切换身份」口径一致） |

### 1.4 `F-L52` 下发签名挑战

| 编号 | 规则 |
| --- | --- |
| `F-L52-1` | 地址带回后，**由服务端生成签名挑战**并下发。挑战内容必含：域名、账户地址、链 ID、nonce、签发时间、有效期、用途声明，并明确说明不发起交易 / 不转移资产 / 不涉及授权 |
| `F-L52-2` | **nonce 一次性**，有效期 `N-L40` = **5 分钟**。已消费或过期的挑战一律拒绝（`E-L75`） |
| `F-L52-3` | 挑战由服务端生成、服务端校验。**前端不得自行拼装待签消息** |

### 1.5 `F-L53` 服务端验签与会话建立

| 编号 | 规则 |
| --- | --- |
| `F-L53-1` | 服务端从签名中**恢复签名者地址**，与本次挑战登记的地址做**大小写不敏感的严格比对**，不一致一律拒绝（`E-L76`） |
| `F-L53-2` | 地址统一按**小写归一化**存储与比对 |
| `F-L53-3` | 验签通过后的处理顺序**一步都不能调换**：`验签通过 → 建号（若首次）→ 账号停用判定 → 建立会话 → 协议同意判定 → 落地` |
| **`D-L141`** | **仅支持 EVM 系列。** 链 ID 在**连接返回时**即判定，不受支持则落 `P-L20` 态 C 并阻断（`E-L77`）；服务端在验签时**再兜一次**，前端判定不构成防线 |
| `F-L53-4` | **不做账户锁定**：验签失败不计数、不锁账号（主文件 Δ-6）。只保留 IP 层限频 `N-L42` |
| `F-L53-6` | 验签之后的两种拒绝各有界面落点：**地址已被另一资金方账号绑定** → `P-L20` 态 D（`E-L81`）；**账号已停用** → `P-L20` 态 E（`E-L86`）。两者都**不建立会话**，且都保留返回类型选择页的出路（`D-L161`） |

**落地规则（`F-L53-5`，优先级自上而下，命中即停）**

| 优先级 | 条件 | 落地目标 | 用户看到的表达 |
| --- | --- | --- | --- |
| 1 | 存在有效回跳目标（用户是被某个受限操作引导来登录的） | **回到原触发点并重新执行那个被拦下的操作** | 无中间页、无额外提示 |
| 2 | 本次是首次签名建号 | **机构注册流程 `P-L21`**（`D-L137`） | 顶部为建号确认区块 + 凭据保管须知 |
| 3 | 其余 | 资金方默认落地页（当前按平台首页写，主文件 11.3 第 3 条） | 正常进入 |
| — | 回跳目标校验不通过或已失效 | 按优先级 3 落地 + Toast | **不报错、不白屏** |

> **优先级 1 的硬要求**：回到原触发点后是**重新执行被拦下的操作**，不是"回到那个页面让用户自己再点一次"（`US-L43`）。回跳句柄的生成、校验与消费一律调用 WS-348 的统一实现，**本册不自行解析跳转**。

## M2 · 首次签名即建号

### 2.1 模块目标与适用角色

| 项 | 内容 |
| --- | --- |
| 目标 | 让"拥有账号"这件事零成本发生，同时保证"拥有账号"不等于"能做业务" |
| 适用业务角色 | 资金方（首次到访） |
| 前置条件 | `M1` 的签名验证已通过（用户在 `P-L20` 态 A 显式点了「签名并继续」），且该地址在 `identity_type = funder` 范围内不存在账号 |

### 2.2 `F-L55` 建号时机与写入内容

| 编号 | 规则 |
| --- | --- |
| **`D-L135`** | **建号发生在签名验证通过之后**，不是钱包连接成功之时。理由：连接是一个几乎无成本的误操作，签名不是。建在连接上会产生大量空账号 |
| `F-L55-1` | 建号时写入：`funder_account_id`（不可变主键）、`identity_type = funder`、`wallet_address`（小写归一化）、`wallet_bound_at`、`created_via = wallet_signature`、`account_status = active`、**`registration_status = draft`**、`created_at`、`last_active_at` |
| `F-L55-2` | 建号**不发邮件**（此时还没有邮箱），**发站内信**（`EV-L40`） |
| `F-L55-3` | 建号动作须留痕：地址、时间、来源 |

### 2.3 `F-L56` 默认角色

| 编号 | 规则 |
| --- | --- |
| **`D-L136`** | 建号时 `identity_type` 恒为 `funder`。**不在钱包连接之后再让用户选角色**——角色由用户在 WS-348 类型选择页点的哪个入口就已经决定了（资产方那个入口根本不连钱包，走授权中心） |

### 2.4 `F-L57` 建号后直接进入注册流程

| 编号 | 规则 |
| --- | --- |
| **`D-L137`** | 建号成功后**直接进入机构注册流程 `P-L21`**，不经过独立的"建号成功"中间页。建号确认信息作为 `P-L21` 顶部的一个区块呈现 |

| `F-L70-1` | 触发**该账户全部会话失效**（含当前设备）的事件：① 主动退出；② 账号被运营停用 |

## M9 · 唯一键与双身份并存

### 9.1 模块目标

把"同一个钱包地址在两个身份下各有一份记录"这件合法的事，与"同一个钱包被两个资金方账号抢注"这件非法的事分开。

### 9.2 `F-L77` 唯一键

| 编号 | 规则 |
| --- | --- |
| `F-L77-1` | 唯一键取 **`(identity_type, wallet_address)`** 与 **`(identity_type, email)`** 两组，**均为定稿**（严格 1:1，主文件 11.1 ②） |
| **`D-L156`** | **唯一性的作用域是"资金方角色域内"**：两组唯一键都以 `identity_type = funder` 为前缀，**不是全平台跨角色唯一**。跨角色的身份并存口径归 **WS-348**，本册不越界定义 |
| `F-L77-2` | 资金方建号、邮箱填写与邮箱修改时的重复校验，**一律只在 `identity_type = funder` 的范围内做**；修改邮箱时还要在验证码校验通过的瞬间再校验一次（`F-L74-8`） |
| `F-L77-3` | 「该地址已被另一**资金方**账号绑定」是冲突，明确拒绝 + 客服入口（`E-L81`） |

> **关于 `E-L81` 的枚举面**：明确告知"该地址已被占用"会泄漏"这个地址在本平台注册过资金方账号"。**此处接受该泄漏**——钱包地址本就是链上公开信息，且不告知会让用户完全无法理解为什么登不进去。这与邮箱侧的处理（`F-L59-2` 不暴露归属）不冲突：邮箱是私密标识，地址不是。

### 9.3 `F-L78` 与资产方身份并存

| 编号 | 规则 |
| --- | --- |
| **`D-L153`** | 同一钱包地址**允许同时是资产方与资金方**。资产方的地址是**资产可信平台的只读快照**，资金方的是**本平台权威绑定**，语义不同，**不得放进同一张唯一索引** |
| `F-L78-1` | 命中资产方影子账号**不构成冲突，正常放行**（`E-L82`） |
| `F-L78-2` | 同理，联系邮箱与某资产方影子账号的邮箱相同时**各自独立、正常放行**（`E-L83`） |

## M10 · 异常分支

**本册只承担资金方登录与账户侧异常。** 资产方 SSO 异常归 WS-348；审核侧异常归 WS-358。

### 10.1 钱包环境与连接

| 编号 | 场景 | 处理 |
| --- | --- | --- |
| `E-L70` | 未检测到任何钱包 | **点击入口那一刻即判定**：按 WS-348 的既定处理**停在类型选择页就地说明**（如何安装 / 改用移动端钱包），保留另一条路径可选；**不进入 `P-L20`、不跳失败页、不白屏**。本版没有"改用邮箱登录"这条出路 |
| `E-L71` | 装有多个钱包插件、provider 互相覆盖 | **入口点击后直接出钱包选择器**（由 SDK 承担），**不默认取第一个**；不需要中间页承载这一步 |
| `E-L72` | 移动端无插件环境 | **入口点击后直接走 WalletConnect 类方案**（二维码 / deeplink） |
| `E-L73` | 用户在连接弹窗里主动拒绝连接 | **回到唤起该弹窗的那个界面**（主干 `E-L11`）：入口点击唤起的 → **回类型选择页**；`P-L20`「重新连接钱包」唤起的 → **回 `P-L20` 态 B**。两种情况均可重试，且都保留返回类型选择页的出路 |
| `E-L74` | 钱包 SDK 加载失败 | 同 `E-L70`：**停在类型选择页就地说明** + 重试入口；**不进错误页** |
| `E-L87` | 钱包已锁定（用户未解锁钱包） | 同 `E-L73` 的落点规则；落在 `P-L20` 时以**态 B** 呈现，提示先解锁钱包后重新连接 |

### 10.2 签名与验签

| 编号 | 场景 | 处理 |
| --- | --- | --- |
| `E-L75` | 签名消息过期（超过 `N-L40`）或 nonce 已被消费 | 提示重新获取并再次签名，**自动重新下发挑战** |
| `E-L76` | 验签失败 / 签名恢复地址与挑战登记地址不一致 | 明确拒绝，提示重试；**不计数、不锁账号** |
| `E-L77` | 链 ID 不在支持范围（非 EVM 或不受支持的网络） | 落 **`P-L20` 态 C**：提示切换网络并阻断；切换后可点「已切换，重试」继续。服务端在验签时再兜一次 |
| `E-L78` | 硬件钱包签名慢 | **不设短超时**；以 `N-L40` = 5 分钟为准，**UI 不得提前自行超时** |
| `E-L79` | 用户主动拒绝签名 | Toast 告知已取消，**停在 `P-L20` 态 A**；**不建号、不建立会话**，可重试 |
| `E-L80` | 签名过程中在钱包里切换了账户 | 明确提示地址已变化并中止本次签名；提供「用该地址重新登录」入口。**不得静默改绑或切号**（`D-L151`） |
| `E-L89` | 同 IP 验签失败超过 `N-L42` | 后续请求降速；**不封禁 IP、不锁账号** |

### 10.3 账号与唯一性

| 编号 | 场景 | 处理 |
| --- | --- | --- |
| `E-L81` | 该地址已被另一**资金方**账号绑定 | 验签通过后由服务端判定；落 **`P-L20` 态 D**：明确拒绝 + 客服入口 + 「换一个钱包地址重新连接」（9.2） |
| `E-L82` | 该地址同时是某**资产方**在资产可信平台绑定的地址 | 按 `D-L153` 允许并存，**正常放行** |
| `E-L83` | 联系邮箱与某资产方影子账号邮箱相同 | 各自独立，**正常放行** |
| `E-L84` | 联系邮箱已被另一**资金方**账号占用（注册填写或修改时） | 明确提示该邮箱不可用，**不暴露它属于谁**；**不消耗本次流程**，可直接换一个继续（`F-L74-11`） |
| `E-L85` | 邮箱验证码连续输错达 `N-L45` | 该码作废、需重新获取；**账号可用性、登录能力与注册状态一律不受影响** |
| `E-L93` | 修改邮箱时填入的新邮箱**与当前邮箱相同** | 直接提示"这已经是你当前的联系邮箱"；**不发码、不消耗任何限额** |
| `E-L94` | 验证码校验通过的瞬间，新邮箱**已被他人占用**（并发） | 服务端二次校验拒绝，提示重试；`email` 字段**保持原值不变** |
| `E-L95` | 邮箱修改流程**未完成即关闭弹层 / 离开页面** | **不改变任何状态**，`email` 保持原值；已发出的验证码按自然过期处理；**不发任何通知** |
| `E-L96` | 验证码重发未到冷却 `N-L48`、或本次流程重发达 `N-L49`、或该邮箱 24 小时达 `N-L46` | 分别提示剩余等待秒数 / 已达上限需退出重发起 / 稍后再试；**三条互相独立，任一命中即阻断** |
| `E-L86` | 账号被停用（`disabled`） | **验签通过之后**判定；落 **`P-L20` 态 E**：明确告知 + 客服入口；现有会话立即失效；出路为返回类型选择页或以游客身份继续浏览 |
| `E-L90` | 草稿态账号被标记休眠（`N-L43`） | 再次登录**自动恢复**，用户无感知；**不删除数据** |

### 10.4 注册流程

| 编号 | 场景 | 处理 |
| --- | --- | --- |
| `E-L88` | `submitted` 期间通过接口尝试编辑**机构资料 / 申请单** | **服务端拒绝**并留痕；前端不提供入口（`D-L131`）。**注意：联系邮箱不在此范围内**，`submitted` 态改邮箱是允许的（`D-L154`） |
| `E-L91` | 提交时门槛校验不通过（邮箱未验证或机构资料不全） | 停留在提交步骤，**逐项指出缺什么**并可点击跳到对应步骤；不产生申请单 |
| `E-L92` | 会话在填写注册流程时过期 | Toast 提示需重新登录；**已保存的草稿不丢失**（`F-L58-2`），重新登录后从上次位置继续 |

## M11 · 数据对象与字段口径

> 本章只写**产品要定的业务口径**（取值、枚举、必填、校验、默认、业务意义）。存储结构与索引由开发按本 PRD 自行设计。

### 11.1 `FunderAccount`（资金方账户，**本册权威**）

| 字段 | 类型 | 必填 | 口径 | 业务意义 |
| --- | --- | --- | --- | --- |
| `funder_account_id` | 标识 | 是 | **不可变主键** | 账户的唯一身份。**任何映射与外键都用它**，不用邮箱（可改）、不用钱包（虽不可改但属业务标识） |
| `identity_type` | 枚举 | 是 | 恒为 `funder` | 与资产方影子账号区分；参与唯一键 |
| `wallet_address` | 字符串 | **是** | 唯一键 `(identity_type, wallet_address)`，**作用域为资金方角色域内**（`D-L156`）；`0x` + 40 位十六进制；**小写归一化存储**；**绑定后不可自助更换 `[待确认]`** | 身份凭据 + 链上业务主体。**本版唯一的登录凭据** |
| `wallet_bound_at` | 时间 | 是 | 建号时写入 | — |
| `email` | 字符串 | 否（建号时为空，**提交注册前必填**） | 唯一键 `(identity_type, email)`，**作用域为资金方角色域内**（`D-L156`）；校验见 `F-L59-1`；**登录后可改**（7.3），改动只在新邮箱验证通过那一刻整体写入（`D-L155`） | **联系邮箱**，审核结论与账号通知的唯一通道（`D-L144`） |
| `email_verified_at` | 时间 | 否 | 验证码校验通过时写入；**每次改邮箱成功后覆盖为新的校验时间** | 空表示未验证；未验证不得提交注册 |
| `created_via` | 枚举 | 是 | **恒为 `wallet_signature`** | 建号路径。本版只有一条 |
| `account_status` | 枚举 | 是 | `active` / `disabled` | **只表示能否登录**（5.2 维度一） |
| `registration_status` | 枚举 | 是 | `draft` / `submitted` / `verified` / `rejected`；默认 `draft` | **注册进度**（5.2 维度二）。`verified` / `rejected` 由 WS-358 回写 |
| `submitted_at` | 时间 | 否 | 每次提交时覆盖写入 | 进度展示与审核时长统计 |
| `reviewed_at` | 时间 | 否 | WS-358 回写 | 审核结论时间 |
| `agreement_version_accepted` | 字符串 | 否 | 已同意的本平台协议版本 | 挂载点，语义归 WS-361 |
| `last_active_at` | 时间 | 是 | 每次有效会话活动时更新 | 休眠判定依据（`N-L43`） |
| `dormant_at` | 时间 | 否 | 休眠标记时间；**再次登录自动清空** | **标记而非删除**，保留审计 |
| `disabled_at` / `disabled_by` / `disabled_reason` | — | 否 | 停用留痕 | `E-L86` 的告知依据 |

### 11.2 本册**不**定义的字段（防止被顺手加进来）

| 字段 | 归属 | 为什么不能放在 `FunderAccount` |
| --- | --- | --- |
| 机构名称、证照、受益人等机构资料字段 | **WS-358** | 字段模版有版本，且随审核分档演进。放进账户对象会让模版升级变成账户表结构变更 |
| 业务联系人邮箱（若机构资料中存在） | **WS-358** | 与联系邮箱解耦是硬要求（`D-L147`）。放进本对象，两者迟早会被同一个更新接口一起改掉 |
| 审核分档、驳回原因、审核人 | **WS-358** | 审核过程属运营端 |
| `verification_status` | **WS-348**（资产方影子账号） | 资金方的认证结论来自本平台审核，与上游只读字段不是一回事 |
| `password_hash` / `failed_attempts` / `lock_tier` / `locked_until` | **无归属，本版不存在** | 密码体系与账户锁定均已作废（主文件 Δ-1、Δ-6） |

### 11.3 页面表单字段（新增）

| 字段 | 页面 | 类型 | 必填 | 校验 | 默认值 | 业务意义 |
| --- | --- | --- | --- | --- | --- | --- |
| `connected_address` | `P-L20`、`C-L20` | 字符串 | 是 | 由 provider 返回，**只读展示，不可编辑**（`D-L139`） | 空 | 当前连接的钱包地址 |
| `registration_step` | `P-L21` | 枚举 `email` / `institution` / `confirm` | 是 | 三选一 | `email`（首次）／上次离开的步骤 | 注册流程当前步 |
