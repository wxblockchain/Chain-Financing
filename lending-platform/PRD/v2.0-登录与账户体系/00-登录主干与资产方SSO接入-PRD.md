# 登录主干与资产方 SSO 接入 · PRD

<a id="scope"></a>
## 1. 目标与阅读入口

用户先以游客浏览，主动登录或遇到受限操作时明确选择身份。资产方经资产可信平台授权，在本平台完成必要协议同意后继续原操作；能否办理融资由当前有效认证决定。账户和企业资料来自上游，借贷平台只读展示本人资料。

本期为桌面 Web。本文负责共用登录入口、返回、状态及权限规则，以及资产方完整账户链路；资金方从钱包连接后的签名、机构注册、审核衔接和账户功能由资金方账户模块负责。资金方邮箱验证码发送前的滑块验证、机构多附件等仍归资金方账户模块。本期不增加移动端、资产方本地登录或本地实名认证。

**主阅读顺序：第 2～7 章功能 → 第 8 章依赖 → 第 9 章同序验收。** 流程文字已在对应功能中说明，无需跨册拼接。配套只有[流程图与状态机](./03-登录主干与资产方SSO接入-流程图与状态机.md)和[本模块消息通知](./08-登录主干与资产方SSO接入-消息通知.md)。页面布局沿已批准设计，本文不增加布局要求。

版本：2026-09-22。

有效依据为本模块已确认业务规则、用户最新资料可见范围与通知政策，以及《PRD 精简修订执行要求》。资产可信平台用户架构仅作参考，实际供给仍按第 8 章核实。旧分册的定位入口保留为转向索引，不再维护第二份正文。正文按业务名称阅读，现用功能编号在对应功能保留一次，验收编号在对应验收行保留一次；历史条款、状态代码及权限行号在文末按需查询。时间、数量、业务字段和验收结果不因呈现调整而删减。

## 2. 浏览、选择身份与前往登录

### 2.1 正常操作

<a id="F-L01"></a><a id="f-l01"></a>
游客访问默认入口、品牌入口或旧首页入口，都进入既有资产广场；没有独立首页。游客可达内容直接展示，不主动弹登录、遮挡正文或设置登录墙。顶部保留“登录”和语言切换，不显示“申请入驻”。不可见页面按权限拒绝访问，不强制跳登录页。（F-L01）

<a id="F-L02"></a><a id="f-l02"></a>
只有两种操作发起登录：点击顶部“登录”，打开整页身份选择；点击可见但受限的业务动作，在原页面打开身份选择弹层，补充一行原操作的上下文说明并保留操作意图。两处使用相同的两张身份卡片，视觉权重相同，每次都必须明确选择；无默认选中、上次身份快捷入口或自动跳转。旧身份记录、隐私模式及禁用本地存储均不改变这一行为。（F-L02）

| 用户选择 | 接下来发生什么 |
| --- | --- |
| 资产方：第三方授权 | 先确认即将前往资产可信平台，再离站授权；不插入重复确认登录方式的本平台页面 |
| 资金方：连接钱包 | 直接唤起钱包，无第二个连接按钮或中间登录页。连接仅取得地址，不建号、不建立登录；连接后由资金方账户模块展示用途、凭据保管须知与协议，用户明确操作才唤起签名 |
| 以游客身份继续浏览 | 恢复合法原浏览页；无原页则到资产广场，不执行被拦下的业务动作 |

资产方只有第三方授权一种登录方式，不提供本地账号、密码、验证码、钱包登录或联系方式补录。**不得输入邮箱后自动识别角色**：这会泄露账户是否存在，且资产方不采集邮箱；角色始终由本次入口选择决定，登录后不再二次选角色。

### 2.2 取消、不可用和切换身份

身份选择后的取消与切换按下表处理。（F-L03）

| 分支 | 用户可见结果与可继续操作 |
| --- | --- |
| 尚未离站时授权中心不可达，或无可用钱包、钱包无法唤起 | 留在身份选择处就地说明，并给实际可执行的下一步；另一身份入口仍可用，不进入错误页或下游页面 |
| 钱包连接取消 | 回到唤起钱包的身份选择界面，两张卡片仍可操作，不留下空白或中间态 |

| 已建立登录后希望换身份 | 先退出，再重新选择；登录状态下不提供“切换身份”入口 |
| <a id="wrong-upstream-account"></a>选错身份并在上游建立了空账号 | 本平台不能撤销该上游账号，也不提供清理上游账号入口；以入口说明帮助用户正确选择 |

### 2.3 离站确认与返回原位置

<a id="leave-confirm"></a>

## 3. 资产方授权、建立账户与协议同意

### 3.1 两个发起入口，一条完成流程

<a id="F-L25"></a><a id="f-l25"></a>
从资产可信平台发起，或从借贷平台选择资产方发起，返回后都立即展示“处理中”，依次完成身份确认、账户可用性确认、本平台账户建立或更新、必需协议检查，再按第 4 章落地。不会白屏等待，也不因入口不同产生不同身份或协议规则。见[授权与协议流程](./03-登录主干与资产方SSO接入-流程图与状态机.md#flow-2)。（F-L25）

<a id="F-L20"></a><a id="f-l20"></a>
本平台服务端须确认授权来自可信授权中心、面向本平台、仍有效且属于本次发起的授权，只能返回预先登记的唯一授权落地位置，不能仅靠界面验证。一次授权只能建立一次登录，不能在其他浏览器或上下文冒用；重复使用失败不影响第一次建立的有效登录。仅声称“来自资产可信平台”不能作为信任依据。处理中状态须可读屏播报，登录状态检查不阻塞游客浏览。（F-L20）

<a id="F-L21"></a><a id="f-l21"></a>
上游已有登录时优先免二次输入；若仍需用户操作，最多回退一次完整登录，不反复弹回。真实能力属于待核实依赖；待完成授权保留 15 分钟，完成或放弃即失效。上游取消或浏览器后退恢复合法原浏览页/身份选择，无原页时到资产广场，不视为业务操作成功。（F-L21）

### 3.2 账户识别与授权结果

<a id="F-L22"></a><a id="f-l22"></a>
本平台资产方账户只以**上游稳定、不可变的账户标识**识别。首次成功建立本平台账户，后续复用；邮箱、钱包地址、企业标识都不用于认人或合并账户。联系方式或有效企业变化不产生新账户、不拆分历史；同钱包/邮箱的资金方账户互不冲突。稳定标识缺失不能建立登录，其他可选资料缺失不阻断登录，展示规则见第 6 章。（F-L22）

| 结果 | 登录及页面处理 |
| --- | --- |
| <a id="account-success"></a>身份有效、上游账户可用、账户建立或更新成功 | 建立本次资产方登录，检查协议；若当前已有另一账号，先结束旧登录再建立新登录，提示账号已切换，资料始终隔离 |
| <a id="account-unavailable"></a>上游账户锁定或禁用 | 不建立新登录，结束该主体已有本平台登录；就地游客视图，显示实际可取得的解除时间或客服入口，不捏造信息 |
| 授权失败、超时、无效身份或缺少稳定标识 | 不建立新登录；在合法原目标的游客视图给中性提示和可复述错误码，可重试或继续浏览。无原目标到资产广场；不影响与本次失败无关的有效登录 |
| 上游授权成功，但本平台账户建立失败 | 唯一独立失败页“建号失败”：同时有错误码、重试、以游客身份继续浏览；不得静默返回或留下死胡同 |

<a id="F-L24"></a><a id="f-l24"></a>
所有失败不暴露内部判定原因。身份来源错误、缺少稳定标识、登记落地位置不一致等配置异常须产生运维告警；这不是向运营人员发站内信。除建号失败页外，不新增授权失败页。恢复原页不代表游客可以继续读取其受保护内容。（F-L24）

### 3.3 必需协议未完成时

首次登录或尚未覆盖当前必需协议清单时，进入协议同意页。清单由协议管理模块提供，不在本模块写死。即使账户已建立，此时也只有受限登录，**只可访问协议同意页、协议正文和退出**，不能进入账户页或其他业务。（F-L26）

协议正文可匿名查看、下载；阅读不代表同意。页面只有一个同意复选框，不自动勾选；未勾选不能提交。加载失败可重试；保存期间不能重复提交，失败继续受限并允许重试，成功后才继续落地。保留当时用户、同意时间、语言、协议版本及原文，后续修改不能覆盖原同意记录。

拒绝或关闭同意流程按退出处理，回游客浏览，不循环拉回协议页。两种授权入口均执行以上规则。

## 4. 登录后回到原页面与原操作

### 4.1 返回顺序与失败结果

<a id="F-L04"></a><a id="f-l04"></a>
登录前保留原页面、被拦下的操作及目标平台；主动登录没有原业务动作。资产方先完成必需协议，资金方首次建号先进入机构注册引导，再考虑原目标。其他正常登录有有效目标则返回，无目标则进入资产广场。（F-L04）

<a id="return-permission"></a>
回到原触发点时重新判断当前权限：允许才恢复操作，仍受限则展示对应引导；不能把登录成功当作融资/出资已成功，也不能重复创建业务。返回规则由本章统一定义，两类登录及各业务共用，不再各写一套。

<a id="return-lifetime"></a>
返回信息只用于本次登录，有效期默认 **30 分钟（可配置）**且只能成功使用一次；完成、放弃或登录结束后失效。不能被其他会话、设备冒用；实际切换角色须重新判定。用户可见或可复制的登录信息不暴露可冒用的返回内容或凭据。

<a id="F-L07"></a><a id="f-l07"></a>
无效、过期或不允许的目标，统一回资产广场并给中性提示，不白屏、不展示内部拒绝原因；过期可提示“链接已失效，已为你回到资产广场”，其他拒绝只说明“已为你回到资产广场”。正常默认进入和取消登录恢复浏览不伪报失败。重复使用、跨会话冒用等安全异常须可追溯。（F-L07）

<a id="F-L05"></a><a id="f-l05"></a>
### 4.2 允许范围与跨平台边界

返回目标须满足以下范围。（F-L05）

| 范围 | 判定要求 |
| --- | --- |
| <a id="allowed-pages"></a>站内业务页 | 仅面客端已登记业务范围；允许前缀暂按 `/`（资产广场）、`/assets`、`/financing`、`/funding`、`/console`、`/onboarding`、`/account`、`/messages`、`/about`、`/faq`、`/agreement`，字面路径仍待页面登记对齐。`/` 只指默认页，不代表全部路径 |

| <a id="cross-platform-closed"></a>本期跨平台实际状态 | 借贷平台站内可用；资产可信平台的正式域名及对端同等返回校验尚未确认，**跨平台返回暂不开放，完成授权后按资产广场兜底**；代币发行平台即使有登记，本期也不开启 |

<a id="return-change-control"></a>
允许路径、禁止携带的内容和平台白名单属于安全边界，变更须按共用规则统一审定、登记及留痕，不作为普通时长配置调整。

<a id="return-authority"></a>
返回目标由服务端按本章判定，不能仅凭来访平台声明或前端检查放行。回跳允许不等于访问允许，落地仍检查身份和业务权限。跨平台返回待确认不阻止资产方授权登录本身。浏览器后退、页面恢复、第三方 Cookie 受限时均须有可继续操作的页面。既定 OIDC、back-channel logout 跨平台登出通知和精确白名单约束保留，具体接入方式由开发设计。

## 5. 当前资格、业务权限与受限引导

<a id="state-contract"></a>
<a id="F-L11"></a><a id="f-l11"></a>
### 5.1 登录与认证分别判断

游客、已登录未激活、已登录已激活是三种共用访问状态。登录有效不代表认证有效；认证仍有效但登录已失效时仍是游客。必需协议未同意的受限登录先执行[协议同意规则](#agreement)，不能借资格表进入业务。（F-L11）

| 状态信息 | 业务含义与默认 |
| --- | --- |
| 是否登录 | 必须明确；默认游客 |
| 当前身份 | 由本次入口选择资产方或资金方；游客为空，登录后必须有值，不能从邮箱或钱包推断 |
| 当前业务资格 | 必须明确；默认未取得有效认证，由服务端权威判定 |
| 当前账户 | 本平台本人账户标识；游客为空，不用钱包或企业标识替代 |

<a id="whole-state"></a>
四项整体取用，所有业务使用同一套状态，不各自读取原始审核状态猜资格；客户端伪造资格不能放行。判定存在冲突时采用较低有效资格，不能据单个较高结果越权。

| 资格阶段 | 资产方 | 资金方的共用语义 |
| --- | --- | --- |
| 未完成认证 | 未取得当前有效已认证结论，按已登录未激活处理 | 已签名建号、机构资料未提交（含未填写及草稿），按已登录未激活处理 |
| 审核中 | 不适用；异常出现时按未完成认证并记录异常 | 待审核，机构资料锁定，不允许编辑、撤回或回到未提交状态；仍为已登录未激活 |
| 已驳回 | 不适用；异常出现时按未完成认证并记录异常 | 可按所属模块规则修改重提；仍为已登录未激活 |
| 已认证 | 上游确认当前有效已认证，按已登录已激活处理 | 已认证，按已登录已激活处理 |

<a id="funder-visibility"></a>
资金方未提交、审核中、已驳回的信息可见范围一致，差异在提示与可执行动作；账户联系方式与机构资料是不同功能，不把审核中机构资料锁定扩大成所有账户操作锁定。详细行为见[资金方账户 PRD](./04-资金方登录与账户体系-PRD.md)。需要核对已有状态代码和字段名时，查[文末对照](#state-code-reference)。

### 5.2 认证更新与发起融资

<a id="F-L29"></a><a id="f-l29"></a>
资产可信平台是认证权威，本平台只读，不自建审核、修改或拼装认证结论。**只认当前有效综合认证结论**；个人或企业单项通过、资料齐全、申请审核进度都不能代替它。更新审核中仍保留有效认证时不自行降级；失效或驳回后的有效资格同样以上游结论为准。未知取值按未认证处理并告警，不猜测新状态。（F-L29）

<a id="qualification-refresh"></a>
授权成功时取得当前结论；会话内认证刷新参考时限为 **5 分钟**，在受限判定点对过旧状态刷新。若上游可提供变化告知，获知后即时刷新，但不以此作为唯一更新手段。读取失败可沿旧快照继续浏览，但不能当作已经确认新资格，也不能误报“认证被收回”。上游完成认证后刷新即可生效，无需退出重登；再次授权立即读取当前结果。

<a id="F-L31"></a><a id="f-l31"></a>
资产方唯一硬卡点是**发起融资申请**，动作前必须实时确认资格，旧的已认证快照不能放行。等待时显示“正在确认资格”，不重复发起；无法确认则说明申请尚未发起并可重试。未认证时显示认证引导，即使绕过界面发起请求也不创建融资申请。（F-L31）

<a id="qualification-late"></a>
等待中发生认证降级、退出、过期、换身份或离开页面，迟到的通过结果不能恢复旧权限、显示操作成功或把用户拉回旧流程。仍在原页且已降级时给认证引导；重新进入后重新判断。此等待不是新账户状态，也不定义融资提交自身的结果。

<a id="confirmed-downgrade"></a>
确认由有效已认证降为非已认证时，及时降低权限，下次进入明确解释当前限制，并向受影响的资产方本人发送一条强制站内信；发送时点、去重与文案统一见[通知册](./08-登录主干与资产方SSO接入-消息通知.md#event)。不因消息投递失败保留已失效权限。见[认证资格与融资流程](./03-登录主干与资产方SSO接入-流程图与状态机.md#flow-4)。

## 6. 本人账户、企业信息与偏好

### 6.1 进入与只读边界

<a id="F-L32"></a><a id="f-l32"></a>
正常资产方登录后，顶部账户入口显示钱包地址前 6 字符（含前缀）＋省略号＋后 4 字符；不超过 10 字符时完整展示，保留大小写。悬浮或键盘聚焦可读全文；缺失则显示“我的账户”，不使用假地址、不阻断登录。悬浮、点击和键盘均可展开菜单，菜单内显示“资产方”，提供“账户设置”“企业信息”和唯一主动退出入口。（F-L32）

账户设置为独立页面，带面包屑，包含账户信息、个人信息及偏好；长地址和邮箱全文可核对。

<a id="F-L33"></a><a id="f-l33"></a>
企业信息为另一个独立详情页，面包屑可回原业务浏览入口，名称不使用“机构信息”，账户页不重复整套企业资料。（F-L33）

<a id="read-only-profile"></a>
只读资料组统一说明“这些信息由资产可信平台维护”，提供经离站确认的上游查看/修改入口。没有编辑按钮（包括灰色按钮）、本地资料录入、提交审核、材料上传/预览/下载或本地企业切换、成员管理。绕过界面的资料修改同样拒绝。上游表单必填不等于借贷端要求补填。未认证者仍有前往完成认证入口，资料已存在不代表已认证。

账户页不设登录状态分区、退出按钮或“保存偏好”按钮，不展示内部编号或规则论证。语言偏好可写，需与上游只读资料区分。流程见[资料与偏好流程](./03-登录主干与资产方SSO接入-流程图与状态机.md#flow-5)。

<a id="profile-visibility"></a>
### 6.2 谁可看、何时更新

<a id="F-L23"></a><a id="f-l23"></a>
个人和企业基本资料**仅当前合法登录的本平台资产方本人及其有效企业归属可见**。同钱包资金方、同企业其他账户、其他资产方和运营人员均不因此获得访问权，已认证者也不能看他人基本资料。账户页误入的资金方进入自身账户页；企业页误入的资金方回可达资产广场并提示不适用。游客不能读取，未同意协议者仍只能按第 3.3 节访问。（F-L23）

<a id="business-fields"></a>

## 7. 退出、失效与既定时效

<a id="F-L27"></a><a id="f-l27"></a>
资产方主动退出只在账户菜单提供，结束本平台登录，不级联退出资产可信平台。到期、上游全局退出、上游账户锁定/禁用也结束相应本平台登录。四种原因均在原页面就地回游客视图并给说明，受保护内容不可继续读取，不自动跳转或弹出登录页。上游退出须明确提示“你已在资产可信平台登出，本平台登录同时结束”；解除时间等未知信息不得编造。（F-L27）

<a id="F-L28"></a><a id="f-l28"></a>
不能确认来源的退出告知不影响合法登录，须产生安全告警；重复告知不反复打扰。上游告知延迟或丢失仍须满足退出时限，不能仅等待下一次用户访问。登录失效时尚未保存的内容提示未保存，不暂存草稿；迟到操作结果不能恢复登录。见[退出与失效状态图](./03-登录主干与资产方SSO接入-流程图与状态机.md#flow-3)。（F-L28）

| 项目 | 既定口径 |
| --- | --- |
| <a id="session-period"></a>资产方登录有效期 | 1 周（暂定），无“记住我”；资金方时效由资金方账户模块独立定义，共用退出后游客态结果 |
| <a id="logout-deadline"></a>上游退出后本平台失效 | ≤60 秒，须验证真实能力，不能用 5 分钟认证刷新替代 |
| <a id="silent-performance"></a>免二次输入体验 | 本平台发起的免输入全程 P95 ≤2 秒；无法免输入最多回退一次完整登录 |
| 认证刷新、待完成授权、返回信息 | 分别为 5 分钟参考、15 分钟、30 分钟，见所属功能；不能互相替代 |
| <a id="baseline-constraints"></a>身份有效期兼容与审计保留 | 沿用既有身份有效期兼容、审计保留约束及[基准定义](https://github.com/wxblockchain/Chain-Financing/blob/1ac445bd344c5511efc02df616539ff0c87fdf94/lending-platform/PRD/v2.0-登录与账户体系/01-资产方SSO接入.md)，本次不更改、不展开技术校验 |

## 8. 未决依赖与开发核实边界

<a id="integration-provisional"></a>
**资产可信平台真实接入仍为暂定，文档交付不代表接入通过。** 本人资料可见、必要业务信息自动获取、强制通知规则已确认，不再交给接口设计重新决定；开发需依据资产可信平台实际接口确认下表对应关系。

| 待核实项 | 必须得到的业务结果 | 未满足时的边界 |
| --- | --- | --- |
| <a id="dependency-identity"></a>稳定身份及账户可用性 | 同一上游人始终对应同一本平台账户，可识别禁用/锁定 | 缺稳定标识不登录；不能改用钱包/邮箱认人 |

两类角色登录时效各自独立，以及通知默认开启、仅可关闭明确可选事件，均已确认。本模块没有可选事件；以上不重新列为决策待定。待确认项的原编号可在[文末定位表](#reference-map)查询。

<a id="integration-boundary"></a>
开发自主设计接口对应与实现；若真实能力导致业务资格、资料权限或时效无法满足，应明确差异供产品处理，不能静默改变本 PRD。资金方的已确认注册/审核行为继续由资金方账户／机构审核模块承接。消息中心最后比对通知登记与框架差异，见通知册末节。

游客、已登录未激活、已登录已激活分别为 T1、T2、T3。登录有效不代表认证有效；认证仍有效但登录已失效时仍是游客。必需协议未同意的受限登录优先执行第 3.3 节，不能借下表进入业务。
