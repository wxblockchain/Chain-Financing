# 登录主干与资产方 SSO 接入 · 流程图与状态机

图仅表达业务流程和状态，**不表达页面布局、组件形态与视觉层级**；承载形式由 Hallmark 设计决定。具体分支、字段与验收统一见[主 PRD](./01-登录主干与资产方SSO接入-PRD.md)。资金方节点仅表示 资金方账户模块的接续边界。

<a id="flow-1"></a>
## 图 1 · 从游客浏览到钱包登录、选择角色与恢复原操作

对应[统一钱包登录入口](./01-登录主干与资产方SSO接入-PRD.md#F-L02)、[我的控制台与选择角色](./01-登录主干与资产方SSO接入-PRD.md#F-L34)与[返回](./01-登录主干与资产方SSO接入-PRD.md#F-L04)。

```mermaid
flowchart TD
    G["游客浏览：资产广场与借贷广场"] -->|使用登录入口| W["连接钱包"]
    G -->|受限操作| W
    W -->|取消或无可用钱包| O["回原页面，保留浏览上下文"]
    W --> S{"消息签名通过"}
    S -->|否| O
    S -->|是| IN["登录成功"]
    IN --> HAS{"已有角色或有效绑定"}
    HAS -->|有| ROLE["恢复既有角色与入驻进度，免选身份"]
    HAS -->|无| CONSOLE["我的控制台：已登录未选角色"]
    CONSOLE -->|暂不选择| BROWSE["继续浏览可达内容，可随时回控制台"]
    CONSOLE -->|选择资金方| AGR["完成本平台必需协议"]
    CONSOLE -->|选择资产方| AGR
    AGR -->|资金方| FUND["机构认证：填写、待审或驳回重提"]
    AGR -->|资产方| LEAVE["离站确认：资产可信平台授权"]
    LEAVE -->|取消| CONSOLE
    LEAVE -->|确认| AUTH["授权、绑定校验与资料同步，见图 2"]
    ROLE --> NEXT{"前置条件满足后的有效原目标"}
    FUND --> NEXT
    AUTH --> NEXT
    NEXT -->|无或不允许| M["资产广场；无效返回给中性提示"]
    NEXT -->|有效| Q{"当前角色、绑定与资格允许原动作吗"}
    Q -->|是| BACK["回原触发点并恢复操作"]
    Q -->|否| GUIDE["按缺项给选择角色、认证或重新确认引导，不执行业务"]
    GUIDE -->|前往补齐| CONSOLE
```

取消登录不执行原业务；未选角色不阻断浏览；跨平台返回未满足对端确认时按资产广场兜底，不阻止本身符合条件的关联授权。

## 图 2 · 授权、钱包绑定校验与必需协议

对应[关联流程](./01-登录主干与资产方SSO接入-PRD.md#F-L25)、[一致性校验](./01-登录主干与资产方SSO接入-PRD.md#F-L35)与[必需协议](./01-登录主干与资产方SSO接入-PRD.md#F-L26)。控制台发起与上游发起共用此流程。

```mermaid
flowchart TD
    START["授权返回，立即显示处理中"] --> LOGIN{"本平台已有有效钱包登录"}
    LOGIN -->|否| SIGNIN["先完成钱包登录，上游登录不替代本平台登录"]
    SIGNIN --> AUTH
    LOGIN -->|是| AUTH{"授权可信、面向本平台、属于本次发起且稳定标识可用"}
    AUTH -->|否| FAIL["不完成关联；保留钱包登录，中性错误及重试出口"]
    AUTH -->|是| ACTIVE{"上游账户可用"}
    ACTIVE -->|否| BLOCK["不建立绑定，结束该主体资产方登录；就地游客视图"]
    ACTIVE -->|是| MATCH{"上游登记钱包地址"}
    MATCH -->|与登录钱包完全一致| BIND
    MATCH -->|不一致| CONFLICT["不建立绑定、不覆盖、不结束登录；给换钱包登录或回上游更新地址两条出路"]
    MATCH -->|上游未登记或非 ETH 地址| MISSING["不完成关联；说明先到上游登记相同地址后重试，并产生告警"]
    BIND{"本平台账户建立或更新并写入绑定"} -->|失败| ERROR["建号失败结果：错误码、重试、继续浏览"]
    BIND -->|钱包已绑定其他账户或角色| REJECT["拒绝本次绑定，不合并不覆盖，进入冲突核实"]
    BIND -->|成功| SYNC["同步获准个人资料、有效企业与当前认证结论"]
    SYNC --> LAND["按图 1 返回与资格规则继续"]
    ERROR -->|重试| START
```

必需协议在控制台**确认角色**时完成，早于本图；上游侧协议不替代本平台必需协议，钱包签名也不视为协议同意。**上游必须登记与登录钱包完全一致的地址才能完成关联**，缺失、非支持链或不一致都不放行。普通授权失败不结束已建立的钱包登录，也不影响无关的有效绑定。

## 图 3 · 资产方登录、角色与绑定状态

对应[登录、角色与认证分别判断](./01-登录主干与资产方SSO接入-PRD.md#state-contract)与[退出与失效](./01-登录主干与资产方SSO接入-PRD.md#F-L27)。

```mermaid
stateDiagram-v2
    [*] --> 游客
    游客 --> 已登录未选角色: 钱包签名通过且无既有绑定
    游客 --> 正常登录: 钱包签名通过且命中有效绑定
    已登录未选角色 --> 协议受限: 确认角色，必需协议未完成
    已登录未选角色 --> 游客: 主动退出或登录到期
    协议受限 --> 已登录未选角色: 拒绝或关闭协议，放弃本次角色确认
    协议受限 --> 待关联: 资产方协议已完成，尚未完成授权关联
    待关联 --> 正常登录: 授权有效且钱包地址校验通过
    待关联 --> 待关联: 授权失败、取消或地址不一致，可重试
    正常登录 --> 钱包待重新确认: 上游登记钱包地址变更
    钱包待重新确认 --> 正常登录: 用户在上游把登记地址改回，核对一致
    钱包待重新确认 --> 游客: 改用新钱包时先退出，按全新用户重新入驻
    正常登录 --> 游客: 主动退出
    正常登录 --> 游客: 登录到期
    正常登录 --> 游客: 上游账户锁定或禁用
    钱包待重新确认 --> 游客: 主动退出、登录到期或上游账户禁用
```

退出均就地降为游客且解释原因，不自动弹登录；主动退出不退出上游，主动退出只有全平台唯一一个入口。**上游普通退出不结束本平台钱包登录**；上游账户禁用须在 60 秒内结束对应登录，含告知失败兜底。钱包待重新确认不结束登录，只冻结资金类动作并触发常驻提醒。一个钱包只绑定一个角色，改用其他钱包按全新用户重新入驻。

## 图 4 · 认证资格与发起融资

对应[认证更新与发起融资](./01-登录主干与资产方SSO接入-PRD.md#F-L29)。必需协议与关联绑定先完成；申请审核进度不代替当前有效综合认证。

```mermaid
flowchart TD
    S{"登录有效、角色为资产方且已完成必需协议与关联"} -->|否| OUT["按游客、已登录未选角色或协议受限的访问范围处理"]
    S -->|是| B{"钱包绑定状态正常"}
    B -->|待重新确认| FREEZE["冻结资金类动作，给重新确认引导；浏览与本人资料不受影响"]
    B -->|正常| V{"当前有效综合结论为已认证"}
    V -->|否或未知| UNVERIFIED["未认证资产方：可浏览、本人账户及消息；受限动作给认证引导"]
    V -->|是| VERIFIED["已认证资产方"]
    UNVERIFIED -.->|确认已认证并刷新| VERIFIED
    VERIFIED -.->|确认认证失效，页面说明及图 6 通知| UNVERIFIED
    VERIFIED -->|发起融资申请| WAIT["正在确认资格，不重复发起"]
    WAIT --> CHECK{"当前登录、绑定、认证及原操作仍有效"}
    CHECK -->|是| GO["允许继续融资申请"]
    CHECK -->|已未认证| UNVERIFIED
    CHECK -->|绑定待重新确认| FREEZE
    CHECK -->|无法确认| RETRY["申请尚未发起，可重试"]
    RETRY --> WAIT
    CHECK -->|退出、过期、换角色或离页| STOP["丢弃旧操作结果，不恢复权限或旧页面"]
```

## 图 5 · 本人资料与偏好

对应[本人账户与企业信息](./01-登录主干与资产方SSO接入-PRD.md#F-L32)。

```mermaid
flowchart TD
    MENU["账户入口"] --> ROLE{"当前是否已有角色"}
    ROLE -->|未选角色| ONLY["仅提供未选择角色说明、进入我的控制台与退出"]
    ROLE -->|资产方| P["账户设置 / 企业信息"]
    P --> OWNER{"本人账户及当前有效企业归属可确认"}
    OWNER -->|否| DENY["不展示他人或待审主体资料；保留可达出口"]
    OWNER -->|是| LOAD{"读取结果"}

    P -->|上游查看/修改| LEAVE["离站确认；取消返回原页和焦点"]
    P -->|语言改选| SAVE["选择即保存，锁定该项"]
    SAVE -->|成功| OK["生效并反馈，后续回显最后成功值"]
    SAVE -->|失败| ROLLBACK["选项与生效值恢复旧值，可重试"]
    P --> NOTICE["关键通知始终接收；无可选事件，无可操作开关"]
    B["已有业务需要上游信息"] --> AUTO["自动取得该业务必要字段，按已有角色可见"]
    AUTO --> NEED{"必要信息及主体有效"}
    NEED -->|是| USE["继续相应业务，不开放整份档案"]
    NEED -->|否| LIMIT["仅限制依赖动作，说明并保留返回及适用重试"]
```

退出、换账户或离页后，旧资料/操作结果不得恢复旧角色或页面；未成功保存无草稿，已成功值不因离页撤回。资料多少不决定认证资格。

## 图 6 · 认证资格失效站内信

对应[认证资格失效通知](./03-登录主干与资产方SSO接入-消息通知.md#event)。

```mermaid
flowchart TD
    V["取得上游当前有效综合认证结论"] --> CHANGE{"确认由有效已认证变为非已认证"}
    CHANGE -->|否或无法确认| NONE["不发认证失效消息；资格/异常按原规则处理"]
    CHANGE -->|是| APPLY["立即应用降级及页面说明"]
    APPLY --> SAME{"同次变化已通知"}
    SAME -->|是| KEEP["不新增、不置顶、不恢复未读"]
    SAME -->|否| SEND["一条强制站内信，仅受影响资产方本人"]
    SEND --> READ["合法访问后阅读历史告知"]
    READ --> TARGET["按当前权限查看本平台账户；不重放旧资格"]
```

降级不等待通知成功；持续未认证不催促，恢复后再次真实失效是新事件。资金方和运营人员不接收本模块事件。

## 图 7 · 上游变更同步与钱包地址变更处理

对应[上游变更的同步与通知](./01-登录主干与资产方SSO接入-PRD.md#F-L36)与[钱包绑定待重新确认通知](./03-登录主干与资产方SSO接入-消息通知.md#event-wallet)。

```mermaid
flowchart TD
    SRC{"变更获知方式"} -->|上游主动推送，上游必须提供| VERIFY{"来源可验证"}
    SRC -->|每次登录成功后及关键动作前核对，兜底必达| READ["读取上游当前资料、企业与认证结论"]
    VERIFY -->|否| ALERT["不改动绑定、不结束登录；产生安全告警"]
    VERIFY -->|是| READ
    READ --> KIND{"变更类型"}
    KIND -->|账户禁用或锁定| END["结束该主体登录，沿既定时限"]
    KIND -->|认证结论失效| DOWN["停止融资资格并按图 6 通知"]
    KIND -->|有效企业归属变更| ORG["确认即更新，待审企业不提前替代"]
    KIND -->|普通资料变更| MINOR["下次登录或读取时更新展示"]
    KIND -->|字段被删除或撤回可见权限| REMOVE["移除旧值，不视为地址变更"]
    KIND -->|钱包地址变更| PEND["标记钱包待重新确认：冻结资金类动作，保留浏览与本人资料，发本人强制站内信并触发常驻提醒"]
    PEND --> FIX{"解除路径"}
    FIX -->|用户在上游改回原地址| RECHECK["下次核对一致即自动解除标记与冻结"]
    FIX -->|用户确实改用新钱包| NEWUSER["按全新用户重新登录、选角色并授权；上游同一账户时接续原账户，旧绑定失效"]
    RECHECK --> OKS["恢复原权限"]
    NEWUSER --> OKS
```

上游必须承诺并提供主动推送；推送丢失、延迟或不可用时由登录与关键动作前核对兜底并按接入缺口上报，不能以“等下一次用户访问”充当及时性承诺。推送的具体时限随接入确认后补入，确认前不写入秒级时限。
