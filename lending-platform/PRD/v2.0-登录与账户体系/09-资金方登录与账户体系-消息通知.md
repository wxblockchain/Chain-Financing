## 3. 触发时点与业务结果

### 3.1 EV-L42 提交形成新的待审核任务

关联 F-L61、F-L64、F-L65。首次提交、驳回后重提、已认证资料变更提交均以**成功提交并进入 submitted/L1**为触发点；创建待编辑草稿、校验失败、超过既有限频、重复返回同一次成功结果均不产生新消息。同一机构的下一次真实成功提交是新事件。

每次成功提交新增一个真实提交节点，等待审核时仅附待审核提示，不预造审核节点；提交成功后才覆盖当前认证资料与材料。运营消息指向所属申请及这次提交。资金方在 P-L22 看提交结果，不再收一条普通“提交成功”站内信；如果此前已认证，另按 EV-L46 收取资格变化告知。两条分属不同接收端及业务目的，不合并成群发。

通知表示“这次提交形成了审核任务”，不承诺送达或查看时仍待审核。如果通知到达前已被处理，或随后又有新提交，原通知仍只关联原提交；打开时告知原提交已处理/已流转，保留对应记录入口，不能直接以旧消息执行当前新提交的审核。查看当前申请及审核操作仍服从 WS-358 当前状态限制。

### 3.2 EV-L43 联系邮箱修改生效

关联 F-L74、D-L155。本人已通过钱包再认证，新邮箱完成必要校验且变更成功生效后，给该资金方账户一条安全消息。仅发送验证码、验证未通过、邮箱相同或冲突、取消修改均不触发。

消息不发送到旧邮箱或新邮箱，收件人也不因邮箱变化而变动。未生效前保留旧的有效联系邮箱；成功后才替换，审核与账户业务站内信始终按账户归属。首次填写不触发此“修改”消息。不显示邮箱全文或将原/新邮箱作为模板变量；用户通过账户设置查看当前联系邮箱。文案给出已有客服路径供非本人操作时反馈，不暗示客服能改绑或找回钱包。

### 3.3 EV-L45 账户停用与恢复

关联 F-L66、E-L86。既有账户可用性从 active→disabled 或 disabled→active 确认生效时，各产生一条对应告知。重复取得 disabled/active、重新登录、休眠标记或休眠恢复均不是新的状态切换，不触发。

停用立即限制访问并沿用现有登录停用提示，不等待站内信成功。站内信可为已有账户保留，停用期间不能登录读取；恢复并正常登录后才可查看，不承诺停用用户能实时读到消息，也不因此新增站外渠道。恢复只代表恢复登录能力，注册状态保持原值，不等于机构审核通过。每次独立停用、恢复记录分别保留；恢复不删除旧停用消息。

### 3.4 EV-L46 已认证后重新进入审核

关联 F-L65、F-L67、D-L133。已认证资金方确认并**成功提交**变更资料，verified/L3→submitted/L1 时，产生一条资格变化站内信。编辑草稿、放弃、提交失败时仍保持原认证状态，不发送此通知；驳回/L2 后重提到 L1 不是由已认证降级，也不发送。

本次业务链不存在 verified→rejected 的直接审核动作。变更提交先触发 EV-L46，之后审核驳回 L1→L2 的结果由 WS-358 的 EV-L61 发送。消息说明“该次提交使认证业务权限暂不可用”，不提前断言被驳回，不提供未经确认的审核完成时间。资格变化立即生效；D-L133 的下次进入显式说明和站内信共用同一事实，读信、关闭提示、点开旧通过记录均不能恢复资格。

## 4. 防干扰、消息访问与历史语义

1. **同一事实只形成一条消息。** 同端、同接收范围、同一事件的重复告知/失败补送，不新增记录，不改回未读、不再次置顶、不改变原发生时间。新的成功提交、下一次邮箱变更、下一次真实停用/恢复或恢复认证后的再次降级，各自形成新消息，不被旧事件合并吞掉。
2. **不追加催促。** 本模块无定时催审、未读催促、草稿提醒、认证完成倒计时或重复安全提醒；不因运营未处理、资金方未打开而重发。沿用现有消息列表和未读计数，不新增强制弹窗、声音或浏览器推送。
3. **消息与业务结果解耦。** 发送失败不回滚提交、邮箱修改、停用或资格变化；已成功的业务不显示成失败以要求用户重做。失败补送仍遵守单次规则；结果未知不能提前通知成功。状态变化和权限更新不依赖用户读到通知。
4. **所有跳转检查当前访问资格。** 面客仅本人可读；运营需正常登录。消息不得自动登录、启用账号、执行审核、改邮箱、恢复认证或直接恢复被拦业务；目标不存在、映射未完成时保留可读内容，说明暂不可查看详情并禁用对应操作，不猜测地址。
5. **申请消息准确关联对应提交。** 申请编号加对应提交的业务关联用于定位；页面以提交时间区分记录，不展示“版本号”。历史提交与审核节点保留动作和时间，旧驳回原因保持原文；当前材料只显示为最新资料，不作为旧消息所指材料，不提供历史材料下载、对比或回退。面客审核节点人员显示“运营审核”，不展示真实审核员身份。
6. **旧消息不能重演旧状态。** 后续通过、驳回、重提或恢复不篡改旧消息的事实；查看时另用当前状态决定可操作项。已处理运营消息不再提供该次审核动作，也不占用当前待审核任务；是否已读与任务是否完成是不同概念，不能用读信完成审核。
7. **分类与偏好。** EV-L43/45 属安全强制告知，EV-L46 属认证合规强制告知；EV-L42 为运营必须处理的审核待办，不列入面客账户通知开关。上述事件均不可退订；不由此扩大未确定的普通可选通知范围。无业务到期日的历史告知沿用消息中心保留规则，不自设删除天数；任务结束只影响动作有效性，不伪造删除或已读。

### 4.1 资料边界、审核政策与通知偏好

通知正文、预览及跳转均适用功能册 D-L162：面客仅本人可读，不把企业基本档案、个人联系方式、证件或认证材料移入消息扩大可见范围。EV-L42 的申请编号和提交时间是指定审核业务所需信息，运营只能在既有审核场景查看对应已提交材料及记录，不藉通知取得账户档案、未提交草稿或代改权限；SPV 按同一运营身份规则处理。

P11 将审核标准归机构自行决定，不取消人工审核、状态回写与结果告知。成功提交仍发 EV-L42，WS-358 生效通过/驳回仍唯一发送 EV-L60/61；标准变化、自动获取、资料查看或重试本身不产生新消息、自动重审或资格变化。资料齐全、牌照有值或长时间未处理均不得被通知文案描述成“已通过”。

| 通知范围 | 偏好政策 |
| --- | --- |
| EV-L43 邮箱安全、EV-L45 账户可用性、EV-L46 认证资格变化 | 强制关键通知，不可退订，当前或历史关闭值均不影响 |
| EV-L42 运营待审核 | 既有运营待办范围，不受面客通知偏好控制；SPV 不另收副本 |
| 本模块可选事件 | 无。无历史值时默认开启；没有实际可控事件，不展示可操作开关或虚假保存反馈 |

账户页显示“安全、认证等关键通知始终接收 / Security and verification notices are always delivered”。不新增常规登录、资料变更抓取或催促消息来制造开关用途。后续其他模块可选事件由其先定义并实际接入；关闭偏好不能删除旧消息或重置已读。验收见 06 册 AC-L510～512。

### 5.3 字段口径与内容限制

| 字段 / 业务信息 | 业务类型、必填与来源 | 校验、默认与展示 |
| --- | --- | --- |
| `application_number` | 文本；EV-L42/46 必填，来自所属机构认证申请；其余模板无此变量 | 必须对应本账户的真实申请，不为空、不臆造，用户不可编辑；无默认值；不用于暴露其他申请信息 |
| `submitted_time` | 时间；EV-L42/46 必填，取该次成功提交的实际时间 | 按阅读者语言和时区格式化并标注时区；不得取最近查看时间或其他提交时间；无默认值，用户不可编辑 |
| 对应提交 | 必须关联到产生事件的那次真实提交；用于业务对象跳转 | 不是历史材料版本；不能仅凭“当前申请”将旧消息替换指向新提交。具体关联实现由开发设计 |
| 收件账户 / 运营可见范围 | 必填业务归属；面客取本平台资金方账户，运营取已有运营范围 | 不按联系邮箱、业务联系人邮箱或钱包地址直接分发，不允许审核员任意填写接收人 |
| 发生时间与已读状态 | 沿用消息框架展示字段；已读仅表示用户读过 | 时间由事件产生时确定，用户不可编辑；新消息按框架为未读，读后不因同一事实重发而恢复未读 |

中英标题变量均为空；EV-L42/46 的中英正文变量集合均为 `application_number`、`submitted_time`，其余正文无动态变量。标题、正文与变量均为纯文本；不包含钱包全文、邮箱全文、身份证件、材料附件、驳回全文或审核员身份。审核原因在受保护的对应记录查看，不塞进通知预览。必要内容缺失时不显示原始模板键、占位符或虚构值，保留业务结果可查并按现有消息异常规则处理；语言缺失采用消息框架既有回落。
