## 4. 受限操作引导组件（`F-L08`～`F-L09`）

### 4.1 两个组件的分工

| 组件 | 触发 | 性质 | 能否关闭 |
| --- | --- | --- | --- |
| **`C-L02` 受限操作引导弹层** | 用户**主动触发**了一个受限能力 | **打断式**——用户此刻正想做这件事，说明缺什么最有效 | 可关闭（回到原页面，**不改变任何状态**） |
| **`C-L03` 常驻补全提示条** | 用户已登录且存在待补齐事项，**与当前操作无关**；游客不展示此条 | **非打断式**——持续提醒，但不挡路 | **可折叠，不可永久关闭**，直到补齐 |

### 4.2 `C-L02` 引导弹层的本体规格

**视觉结构（线框级，自上而下四段，顺序固定）**

```
┌────────────────────────────────────────┐
│ ① <标题：说清缺什么>                [×] │
│ ② <一句话：补完之后能做什么>            │
│                                        │
│ ③ [ 主按钮：去补齐 ]  ← 必须带回跳      │
│    次按钮 / 稍后再说                    │
│                                        │
│ ④ 补充信息区（仅 L1 / L2 两种情形有）   │
└────────────────────────────────────────┘
```

| 段 | 内容 | 强制口径 |
| --- | --- | --- |
| ① 标题 | **缺什么** | **`D-L40`**：**不得**写「无权限」「请先登录」这类不含信息的文案 |
| ② 说明 | **补完之后能做什么** | **`D-L41`**：**成本与收益放在同一句**（「完成实名认证后可发起融资」） |
| ③ 主按钮 | **可点的去处**，**必须带回跳** | **`D-L42`**；跨平台去处须先过 `C-L04` 离站告知（`D-L33`） |
| ④ 补充区 | 驳回摘要 / 进度节点 / 客服入口 | 仅 `L1`、`L2` 两种情形有 |

**触发情形与载体**（本 PRD 只定义**载体与结构**；每种情形的具体文字由拥有该情形的册提供）

| 触发者 | 缺什么 | 载体 | 主按钮去向 | 补充区 | 文案归口 |
| --- | --- | --- | --- | --- | --- |
| **游客** | 没有身份 | **`C-L01` 类型选择弹层**（不是 `C-L02`——此时问题不是「缺什么」而是「你是谁」） | 资产方 → 授权中心；资金方 → 连接钱包 | — | 主干 A · 2.3 |
| **资产方 `L0`** | 上游实名认证 | `C-L02` + `C-L03` | **跨平台**跳资产可信平台用户中心（带 `RT-4`，先过 `C-L04`） | — | SSO 8.2 |
| **资金方 `L0`** | 机构资料未提交 | `C-L02` + `C-L03` | 机构注册引导页 | — | **WS-349** |
| **资金方 `L1`** | 等结论 | `C-L02`（**纯只读说明**） | 查看进度 | 当前审核状态及可用辅助信息；有正式时长或客服渠道时才展示，不以原型示例补定 | **WS-349 / 审核需求** |
| **资金方 `L2`** | 修改资料 | `C-L02` + 驳回摘要 | 编辑重提 | **字段级驳回原因摘要** | **WS-349 / 审核需求** |

| 编号 | 口径 |
| --- | --- |
| **`D-L43`** | **弹层不改变任何账户状态**。它只展示与跳转；**关闭弹层等同于「什么都没发生」** |
| **`D-L44`** | **组件归主干、文案归各链路。** 本册定义四段结构、按钮行为与回跳接入；每种情形的具体文字由拥有该情形的册提供（上表末列）。**本册不代写文案，各册也不另建组件** |
| **`D-L45`** | 前往补齐前须保留原页面与受限操作，按主干 3.2～3.7 返回；不能只完成补齐而丢失用户原本要做的事 |
| **`D-L48`**（**红线**） | **`L1` 审核中的引导文案不得暗示可以修改或撤回。** 应写「审核中无法修改，如资料有误请联系客服」 |

离站确认取消及 Escape 的逐层返回、键盘焦点恢复统一遵循主干 A · 2.6 `D-L18`；取消后恢复原引导，不跳回无关整页。

### 4.3 `C-L03` 常驻提示条的本体规格

| 项 | 规格 |
| --- | --- |
| **位置** | 仅已登录用户的全站壳层内、主内容区上方，**占位而不悬浮**——悬浮条会盖住页面底部内容，而它要长期存在 |
| **展开态** | 一行文案 + 一个主按钮 + 一个折叠控件 |
| **折叠态** | 收起为**一条细条 + 一个图标 + 计数**（多条并存时显示条数），点击重新展开。**折叠态必须仍然可见**——`D-L46` 要求「可折叠但不可永久关闭」，折叠成完全不可见等于关闭 |
| **折叠状态的记忆** | 仅当前会话有效，会话结束后再次登录回到展开态 |
| **消失条件** | **只有一种：对应的缺失被补齐。** 不提供「不再提示」 |
| **主按钮** | 与 `C-L02` 一样保留原操作并遵循统一返回规则（`D-L45`） |

| 编号 | 口径 |
| --- | --- |
| **`D-L46`** | 提示条**可折叠、不可永久关闭**，直到对应的缺失被补齐 |

### 4.4 多条提示并存时的优先级与堆叠规则

| 编号 | 规则 |
| --- | --- |
| **`D-L47`** | **全站同一时刻最多展示一条常驻提示条**，其余以计数与清单表达，**不堆叠、不并列** |
| 优先级 | 自上而下取第一条命中的：① **`L2` 已驳回**（有明确待办且有时限压力）→ ② **`L0` 未提交 / 未认证** → ③ **`L1` 审核中**（只读说明性质）→ ④ **`T3 → T2` 降级说明** |
| 多条并存的表达 | 当前条右侧显示「**还有 N 项待完成**」，点击展开一个**清单**（而不是再弹出几条提示条）。清单里每项各自带自己的主按钮 |
| 补齐后的行为 | 当前条消失，**队列中下一条立即接替、位置不变**——避免页面因为提示条消失又出现而跳动 |
| 与弹层的关系 | 提示条与引导弹层**可以同时存在**（一个常驻、一个打断式），但**同一时刻只有一个弹层**；弹层展开期间提示条不重绘 |

### 4.5 引导组件的异常分支

| 编号 | 场景 | 处理 |
| --- | --- | --- |
| **`E-L09`** | 调用引导组件时传入的档位与契约四字段不一致 | **以服务端计算的四字段为准**渲染，忽略调用方传入值；按 `D-L64` 处理 |

> 入口与回跳的异常分支（`E-L01`～`E-L08`、`E-L10`）在**主干 A · 第 8 章**。

### 4.6 降级说明

资产方具体事件与文案见[本模块《消息通知》](./08-登录主干与资产方SSO接入-消息通知.md)；资金方事件由 WS-349 自身消息通知文件定义，主干不重复投递。

**`T3 → T2` 降级不得静默**（`ST-1`）：资产方上游认证失效、资金方机构认证被撤销时，须**发站内信 + 下次进入时显式说明**。显式说明的载体即 `C-L03`（优先级 ④），**文案由发生降级的那一册提供**，符合 `D-L44`。

## 5. 权限矩阵总表（`F-L10`）

### 5.1 取值语义（四档，**不得新增第五档**）

| 取值 | 语义 | 服务端行为 |
| --- | --- | --- |
| **✅** | 完整可见 / 可用 | 正常返回 |
| **◐** | 脱敏可见 | **服务端直接不返回敏感字段**，不是前端遮挡 |
| **⊘** | **置灰**：可见不可点，附引导 | **收到请求照样拒绝执行** |
| **❌** | 不可见 / 直接拒绝 | 拒绝执行，数据也不返回 |

| 编号 | 口径 |
| --- | --- |
| **`D-L50`** | **⊘ 与 ❌ 全部由服务端强制。** ⊘ 只表示「前端仍画着这个按钮」，服务端收到请求照样拒绝执行。**前端隐藏不构成防线**——绕过界面直接发起请求的人，必须同样被拦住 |
| **`D-L58`** | **⊘ 的「不可点」指的是不执行原业务操作，不是不响应点击**。置灰控件仍必须可聚焦、可点击并唤起引导弹层，且对读屏可读出受限原因。一个点了毫无反应的灰按钮把用户留在原地，直接违反 `D-L42` |
| **`D-L57`** | **降级默认取 ⊘**；仅当 `X-L1` 要求或「展示本身即泄露」时才取 ❌。**取 ❌ 的行必须写明理由**——❌ 会让用户完全不知道平台有这个能力，是有代价的选择 |
| **`D-L59`** | **不得新增第五档取值。** 需要第五种表达时，说明该行的粒度不对，回 5.4 重新切行 |
| **`X-L1`** | **脱敏必须在服务端完成**——接口对游客直接不返回敏感字段。前端隐藏在开发者工具面前等于没有 |
| **`X-L2`** | **游客态的排序与筛选只能按区间维度提供**。逐条脱敏会被聚合接口整体绕过：按金额精确排序可用二分法还原精确值 |

### 5.2 两种「空」必须区分（**硬性**）

| 记号 | 含义 |
| --- | --- |
| **⬜** | **「待对应需求填」**——这一格该有取值，只是还没人填 |
| **—** | **「不适用」**——该能力在这一列的身份下不存在这个语义（例如资产方没有「填写机构资料」） |

> **不区分的后果**：评审会把待填格当成遗漏，或者反过来把遗漏当成不适用。**本图例必须随表出现，不得省略。**

| --- | --- |
| **`D-L52`** | 每一行由**该功能所属的需求**填；主干只做合并与冲突裁决；**同一行不得在两份文档里各写一版** |
| **`D-L53`** | 每一行先满足本人归属、业务对象可见范围等前提，再按**三态 + 完备度档位**判定。若某一行需要区分「审核中」与「未提交」，用 `L1` / `L0` 表达，**不得为此加列** |
| **`D-L54`** | 行的粒度是**能力 / 动作**，不是页面。同一页面内不同动作可以落在不同取值上 |
| **`D-L55`** | **◐ 的具体字段口径不在矩阵里定义**，由各展示类功能按第 6 章契约各自定义；矩阵只定到「该能力在该档下是脱敏的」 |
| **`D-L56`** | **新增行由主干登记行号与归属之后，相应需求才填取值。任何需求不得自行往总表加行**，也不得自行新增硬卡点 |

**资金方两列的切分界线**：凡与**账号 / 钱包 / 会话**有关的行归 **WS-349**；凡与**机构资料 / 申请单 / 审核**有关的行归**机构认证审核需求**。按此判定不会有第三种情况。

**冲突裁决流程**

| 步 | 谁 | 做什么 |
| --- | --- | --- |
| 1 | 发现方 | 在 WS-348 上登记冲突：**行标识 + 两个候选归属 + 各自的理由** |
| 2 | 主干（持表方） | 先用上面的切分界线判一次。**能判出来的当场判，不上升** |
| 3 | 主干 | 判不出来（既不属账号 / 钱包 / 会话，也不属机构资料 / 申请单 / 审核）——这说明**该行不是登录域的行**，退回给业务需求并从总表移除 |
| 4 | 主干 | 仍无法判定的上交 WS-346 裁决；**在裁决落定前该行保持 ⬜，不得由任一方先填** |

> **为什么禁止「先填了再说」**：一行被两边各填一版之后，评审看到的是两个都言之成理的取值，成本比空着高得多。

### 5.5 矩阵的消费方式

矩阵**不是一份给人看的表，而是服务端判定的依据**。展示类功能按第 6 章的四字段定位到列、按能力定位到行，取交叉格的取值。**任何模块不得自行读取账户原始状态字段来推断这张表的取值**（`D-L60`）。

## 6. 三态与对外契约四字段（`F-L11`）

> **本章是两类角色共用的状态语义的唯一定义处。** WS-349、机构认证审核需求与所有展示类功能一律引用本章，**不得自行改变既定状态语义与枚举**。6.2 仅保留既有跨模块状态名称映射，接口报文及字段扩展不在本 PRD 定义。

### 6.1 三态

| 态 | 判定 |
| --- | --- |
| **T1 游客** | 无会话 |
| **T2 已登录未激活** | 有会话，完备度未达标 |
| **T3 已登录已激活** | 有会话，完备度达标 |

| 编号 | 口径 |
| --- | --- |
| **`ST-1`** | **`T3 → T2` 降级不得静默**：须发站内信 + 下次进入时显式说明（载体见 4.6） |
| **`ST-2`** | **退出登录一律回落 T1 游客态**，不落到登录页（与 `D-L01` 同一条线） |
| **`D-L68`** | **状态语义两类角色共用，不得为任一角色另造一套状态名。** 资产方与资金方的差异只体现在**档位怎么算出来**（6.4），不体现在**档位叫什么**——这是本模块能只做一套矩阵和一套引导组件的前提 |

### 6.2 共用状态信息（沿用既有四项名称映射）

| 字段 | 业务类型 | 取值枚举 | 必填 | 默认值 | 业务意义 |
| --- | --- | --- | --- | --- | --- |
| `session_state` | 枚举 | `guest` / `authenticated` | 是 | `guest` | 当前是否有有效会话。**只有两个取值**——「会话即将过期」「受限会话」等不在此字段表达 |
| `identity_type` | 枚举 | `null` / `asset_party` / `funder` | 是 | `null` | 业务角色。`session_state = guest` 时**必为 `null`**；`authenticated` 时**必不为 `null`** |
| `completeness_level` | 枚举 | `L0` / `L1` / `L2` / `L3` | 是 | `L0` | 完备度档位，**取值范围随角色不同**，见 6.3 |
| `account_id` | 标识 | 影子账号或资金方账号主键；游客为 `null` | 是 | `null` | 账户标识。`session_state = guest` 时**必为 `null`** |

| 编号 | 口径 |
| --- | --- |
| **`D-L60`** | 展示类功能**不得自行读取账户原始状态字段**（如 `verification_status`、审核申请单状态）做判定，**一律消费上述四项**——否则每个模块各自解释一遍状态，口径必然漂移 |
| **`D-L61`** | **四字段是一个整体，必须同时取用。** 只读 `completeness_level` 而不看 `identity_type` 会得到错误结论——`L0` 对资产方与资金方是两件不同的事（6.3） |
| **`D-L69`** | **`identity_type` 由用户在 `P-L01` 点击的入口决定**，在登录流程开始时就已确定；**不得在钱包连接成功或授权回跳之后再让用户选一次角色**，也不得由系统从凭据形态反推 |

### 6.3 `completeness_level` 的分支边界（**最容易写错的一条**）

| 档 | 语义（**共用**） | **资产方分支** | **资金方分支** |
| --- | --- | --- | --- |
| `L0` | **未达标，可补齐** | 上游未完成实名认证 | **草稿态**：签名已建号、机构资料未提交（含从未填写、有草稿未提交） |
| `L1` | **待审核（锁定，不可编辑）** | **— 不适用** | **待审核**：邮箱 + 机构资料已提交，等运营端审核 |
| `L2` | **已驳回（可改重提）** | **— 不适用** | **已驳回** |
| `L3` | **已激活** | 上游 `verified` | **已认证**：审核通过 |

> **这张表是 WS-349「账号状态机」与本 PRD 的映射锚点**：草稿态 = `L0`、待审核 = `L1`、已驳回 = `L2`、已认证 = `L3`。WS-349 可以在自己的正文里继续用中文状态名描述业务，但**对外契约与矩阵一律用 `L0`～`L3`**，不另发编号。

| 编号 | 口径 |
| --- | --- |
| **`D-L65`** | **`L0` / `L1` / `L2` 三档的信息可见性完全一致**；差异只在**提示文案与可执行动作**——`L0` 可填写与提交、**`L1` 只能查看进度**、`L2` 可编辑重提 |
| **`D-L62`** | **资产方分支只有 `L0` / `L3` 两个取值。** 消费方遇到 `identity_type = asset_party` 且 `completeness_level ∈ {L1, L2}`，应视为**数据异常并按 `L0` 保守处理，不得放行** |
| **`D-L63`** | **`L1 → L0` 的回边不存在**：`L1` 是**单向锁定态**，只有审核结论能让它离开（去 `L2` 或 `L3`）。任何文档出现 `L1 → L0` 的跃迁一律为错误 |

### 6.4 完备度由谁计算

| 编号 / 分支 | 口径 |
| --- | --- |
| **`D-L64`** | **完备度只由服务端计算并输出，前端不自行拼装三态** |
| 资产方分支的取值 | 由 **SSO 第 7 章**从上游 `verification_status` 只读映射得出。**本平台不得回写 `verification_status`** |
| 资金方分支的取值 | 由 **WS-349 / 机构认证审核需求**从本平台的审核结论得出 |
| 两侧同时判为未达标时 | 取**更低**的那一档。`L0` 是二者的公共下界，因此不会出现取值打架 |

### 6.5 展示类功能该读哪份文档

| 你要做的事 | 读这里 |
| --- | --- |
| 判断当前用户是谁、处于哪一档 | **本册 6.2**（四字段定义与枚举） |
| 判断某个能力现在可不可用 | **本册 5.3**（矩阵总表）+ `D-L50` |
| 知道某个字段在脱敏档下显示成什么样 | **不在本 PRD**——由你自己这个功能按 `X-L1` 定义（`D-L55`） |
| 登录后要把用户送回原处 | **主干 A · 第 3 章**，调用主干的句柄生成 / 消费，**不要自己解析跳转** |
| 用户被拦下时要提示什么 | **本册 4.2** 的组件 + 你所属那一册提供的文案 |
| 资产方的 `verification_status` 怎么来的 | **SSO 第 7 章**（**你不需要知道，也不应该读它**） |
| 资金方的审核状态机 | WS-349（**同上**） |

## 9. 非功能约束

| 维度 | 要求 |
| --- | --- |
| **安全** | ① 主干 3.3 的安全边界必须有效，即使绕过界面也不得越权；② 矩阵 ⊘ / ❌ 服务端强制（`D-L50`）；③ 脱敏服务端完成（`X-L1`）；④ 回跳句柄、登录过程中产生的任何一次性凭据、钱包签名原文**不入日志**；⑤ **不得以「请求是从哪里来的」作为信任依据**，来源信息只能用于留痕；⑥ 判定失败原因**不回显给用户**，只进留痕 |
| **可用性** | 回跳失败一律**静默兜底 + Toast**，不报错、不白屏（`RT-5`）；本地存储不可用时身份选择仍正常（`E-L07`）；**任何失败态都必须有可点的出口**，不存在只有报错没有出路的页面 |
| **一致性** | `P-L01` 与 `C-L01` 文案必须**逐字一致**（`D-L05`）；四字段枚举在本 PRD 与 WS-349 之间保持一致，**以本册 6.2 为准** |
| **可访问性** | 两张身份卡片可键盘操作，tab 顺序为「资产方 → 资金方」；提示条折叠控件有可读标签；弹层打开时焦点进入弹层、关闭后归还原触发元素；置灰控件可聚焦并读出受限原因（`D-L58`） |
| **国际化** | 全部面向用户的文案提供中英双语；语言、时区、日期与金额展示遵循本平台的国际化与展示基线，**不跨平台引用其他平台的同类章节** |
| **兼容性** | 隐私模式 / 禁用本地存储下**全部主流程可用**，身份选择不依赖旧身份记录；跨平台回跳须在浏览器后退、第三方 Cookie 受限、页面被恢复三种情况下均不白屏 |
