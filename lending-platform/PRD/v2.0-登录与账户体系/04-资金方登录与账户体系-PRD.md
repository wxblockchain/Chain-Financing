## 2. 背景与目标

### 2.1 背景

三平台拆分后，资金方是借贷平台的**自有身份**，不接入资产可信平台授权中心——这是三平台身份边界最干净的一条。资产方走 OIDC 授权登录（WS-348），资金方走本平台自建账号体系（本册）。

基线（`cly-V1.0.0`）的资金方账户体系是"邮箱验证码 / 邮箱密码 / 钱包签名三方式并列 + 凭据完备性门槛 + 独立注册流程取消"的形态。本轮用户把登录方式收敛到**只剩钱包签名**一条，并把邮箱从"登录凭据"改成"机构注册流程中填写的联系方式"。**这不是改文案，是换掉了账户体系的骨架**：账户锁定计数、密码、找回密码、防枚举中性提示、凭据补齐弹层等一整套机制随登录凭据一起失去存在前提。

### 2.2 本期目标

| # | 目标 | 可验收的结果 |
| --- | --- | --- |
| 1 | 资金方能用钱包唯一入口登录本平台 | 连接钱包 + 签名一次即可进入，无第二种登录方式、无密码 |
| 2 | 首次签名即拥有账号，但"有账号"不等于"能做业务" | 签名成功即建号并落在草稿态；草稿态只能只读浏览，业务动作被拦截并引导去完成注册 |
| 3 | 机构注册流程能把邮箱与机构资料一次收齐并提交审核 | 提交成功后账号进入待审核，且不可再编辑 |
| 4 | 审核结论能回写并改变用户可做的事 | 已认证解锁既有资金方业务权限（仍受业务对象和资料范围限制）；已驳回可修改后重新提交 |
| 5 | 账户状态与主干三态同源 | 本册四个注册状态一一映射主干 `completeness_level` 的 `L0`～`L3`，不新造状态名 |

### 2.3 本期明确不做

| # | 不做 | 说明 |
| --- | --- | --- |
| 1 | 账号密码、邮箱验证码登录、找回 / 重置 / 修改密码 | 登录方式仅保留钱包签名（用户 2026-09-18 确认） |
| 2 | 账户锁定与阶梯锁定计数 | 计数的三种来源（密码失败、再认证失败、验签失败）中前两者随密码体系消失；验签失败无爆破价值（[8.1](#81-安全) 第 4 条）。改为 IP 层限频 |
| 3 | 机构资料同源模版、审核办理与结论产生；实质审核标准由机构自行决定 | 归 WS-358（运营端）。本册只负责提交入口、编排与结论消费（[3.3](#33-与-ws-358运营端资金方机构认证审核的接缝)） |
| 4 | 多钱包 / 多经办人账号模型 | **严格 1:1 已定稿**（2026-09-18 用户确认）。钱包与邮箱在资金方角色域内各自唯一，本期不放开 |
| 5 | **钱包地址更改**（自助换绑，以及运营侧的改绑流程） | 2026-09-18 用户确认"本次不实现钱包地址更改"。本期不提供改绑页面或流程；个案可经已有客服入口反馈，但不承诺可以改绑或恢复账户（[8.1](#81-安全) 第 8 条） |
| 6 | 账号恢复通道（钱包私钥或邮箱同时失联） | 本期无自助恢复，只做告知性缓解（《功能需求说明》 `M7`）；风险登记见 [9.2](#92-已知风险) `RISK-L01` |
| 7 | 协议正文、版本策略与强制重新同意弹窗 | 归 WS-361；本册只做勾选与留痕的挂载点 |

## 4. 与基线的差异

### 4.1 差异点逐条说明

`cly-V1.0.0` 的资金方 PRD 中，与登录凭据无关的规则（钱包签名链路本身、国际化、脱敏）**沿用不改**。通知按 [《消息通知》](./09-资金方登录与账户体系-消息通知.md) 定义，本期仅站内信；邮箱验证码作为功能验证仍保留。以下为登录体系与旧基线的差异。

| # | 项 | 基线（`cly-V1.0.0`） | 本版（V2.1） | 为什么必须不同 |
| --- | --- | --- | --- | --- |
| **Δ-1** | 登录方式 | 邮箱验证码 / 邮箱密码 / 钱包签名**三者并列**，任一可登录同一账号 | **仅钱包签名一条** | 用户 2026-09-18 确认。一条凭据意味着不存在"方式之间打架"的问题，也意味着丢失即失联——缓解见 `RISK-L01` |
| **Δ-2** | 邮箱的角色 | **登录凭据**（可用于验证码登录、密码登录、找回密码） | **联系方式**，在机构注册流程中填写，不参与登录 | 用户确认。邮箱不再是凭据后，防枚举中性提示、验证码登录限频、改邮箱触发全局会话失效等一整组规则失去前提 |
| **Δ-3** | 邮箱的采集时机 | 建号时（验证码路径）或登录后补齐弹层 `C-F22` | **机构注册流程第 1 步**，不做登录后补填弹窗 | 用户确认。注册流程本来就要收资料，把邮箱并进去比单独弹一次少一个打断点 |
| **Δ-4** | 建号时机与角色 | 首登即建号；角色由入口决定 | **钱包签名成功即建号**（不是钱包连接成功），**默认角色资金方**，随即进入机构注册流程 | 用户确认。建在签名而非连接，避免误连产生一堆空账号；角色由登录页入口确定，不在连钱包之后再让用户选一次 |
| **Δ-5** | 账号状态的层数与语义 | 双层：`FunderAccount.status`（`incomplete`/`active`/`locked`/`disabled`，能否登录）+ `FunderApplication.status`（归 WS-316） | 双层保留但语义重划：`account_status`（`active`/`disabled`，能否登录）+ **`registration_status`（`draft`/`submitted`/`verified`/`rejected`，本册权威到"提交"为止）** | `incomplete` 表达的"凭据未齐"随 Δ-2 消失；`locked` 随 Δ-6 消失。新的四态直接映射主干 `L0`～`L3`（[7.3](#73-账号状态与主干三态的映射)） |
| **Δ-6** | 账户锁定与计数 | 密码失败 + 验签失败 + 再认证失败共用计数器，满 5 次阶梯锁定 | **取消账户锁定**，只保留 IP 层限频 | 三种来源里两种已不存在；验签失败无爆破价值（攻击者没有私钥，重试一万次与一次等价）。保留锁定只会把"钱包插件抽风"变成"账号被锁 30 分钟" |
| **Δ-7** | 「申请入驻」与「登录」双入口 | 两个入口标签共用同一条链路，差别只在文案与建号后引导 | **合并为单一入口**：登录页只有"连接钱包登录"一个动作 | 三方式并列时双标签是为了让新用户不怕"登录"二字；只剩钱包签名后，两个标签指向完全一样的一个按钮，保留它只是增加一处要同步的文案 |
| **Δ-8** | 凭据完备性硬门槛 `D-F14` 与补齐弹层 `C-F22` | 邮箱 + 钱包同时具备才可提交机构资料；缺项时唤起就地补齐弹层 | **整套机制取消** | 钱包必然具备（它是登录凭据），邮箱在注册流程内收——门槛与被门槛的动作变成同一步，不再需要跨模块的门槛协议 |
| **Δ-9** | 登录后落地 | 回跳目标优先 → 首登去入驻引导页 → 默认落地页 | **规则不变**，仅把"入驻引导页"替换为本册的机构注册流程 `P-L21` | 落地优先级属主干口径，本册不改规则只改取值 |
| **Δ-10** | 钱包地址的输入方式 | 保留**手工填写**，语义为账户选择器，服务端与签名恢复地址比对 | **不再提供手工填写**，地址一律取自钱包 provider | 手填存在的理由是"密码 / 验证码路径的用户也要绑地址"；只剩钱包登录后，地址必然来自 provider，手填只是多一个会填错、且必须再写一套一致性校验与异常文案的入口。**已由用户确认**（2026-09-18），基线 `D-F36`～`D-F40` 那一组保持作废 |
| **Δ-12** | 资金方登录的入口形态 | 类型选择 → **资金方登录页** → 页内再点「连接钱包」→ 钱包弹窗（两次点击、一个中间页） | **类型选择页的资金方入口点击即唤起 provider**；`P-L20` 降为**连接回来之后的签名确认层**，同时承载全部失败与中断态 | 入口按钮写的是「连接钱包」，落地页主按钮还是「连接钱包」，中间那一页只承担了一次重复点击。改完之后两侧对称：资产方点下去直接离站去授权中心，资金方点下去直接进钱包。**但连接与签名仍是两个弹窗**——签名前平台侧必须先露出用途说明、凭据保管与协议勾选（`D-L160`）。**连接弹窗内取消 / 失败的落点由主干 `E-L11` 收口**：回到唤起该弹窗的那个界面，本册不另立口径 |
| **Δ-11** | 改邮箱是否触发全局会话失效 | 是（邮箱是登录凭据） | **否** | 邮箱不再是登录凭据，改它不改变"谁能登进来"。把所有设备踢下线是没有对应风险的惩罚 |

## 7. 统一术语与状态口径

### 7.1 术语

| 术语 | 含义 | 不要说成 |
| --- | --- | --- |
| **资金方** | 借贷平台面客端的自有身份，出资一侧。契约字段 `identity_type = funder` | 投资人、出资方、LP |
| **建号** | 钱包签名验证通过后，系统创建资金方账号这一动作 | 注册（注册在本册特指机构注册流程） |
| **机构注册流程** | 填邮箱 + 填机构资料 + 提交审核的完整流程 | 入驻、认证申请（基线用词，本版统一为"机构注册"） |
| **草稿态 / 待审核 / 已认证 / 已驳回** | 本册的 `registration_status` 四取值 | 未入驻、审核中、已入驻（基线用词） |
| **三态（T1/T2/T3）** | **WS-348 主干定义**的会话与权限状态 | 本册不另造名字 |
| **完备度 `L0`～`L3`** | **WS-348 主干定义**的契约字段取值 | 本册只负责把自己的四个注册状态映射过去 |

### 7.2 三态与契约字段（**引用 WS-348，本册不重定义**）

| 项 | 取值 | 定义处 |
| --- | --- | --- |
| 三态 | `T1 游客` / `T2 已登录` / `T3 已激活` | [共用登录与资格状态](./01-登录主干与资产方SSO接入-PRD.md#state-contract) |
| 对外契约字段 | `session_state`、`identity_type`、`completeness_level`、`account_id` | [共用状态字段对照](./01-登录主干与资产方SSO接入-PRD.md#state-code-reference) |
| 本册在契约中的角色 | `identity_type = funder` 分支的**生产方**：会话由本册建立，`completeness_level` 由本册的 `registration_status` 映射 | 本册 |

> **口径的唯一权威定义在 [《流程图与状态机》第 3 章](./07-资金方登录与账户体系-流程图与状态机.md)。** 本节只给名称对照与指针，**不重复定义规则**——迁移触发条件、各态允许 / 禁止的动作、终态判定、`account_status` 与 `L` 档的叠加矩阵，一律去 《流程图与状态机》取。

**名称对照（仅用于统一说法）**

| --- | --- | --- | --- |

## 8. 非功能约束

### 8.1 安全

| # | 要求 |
| --- | --- |
| 1 | **验签必须在服务端完成**。前端可先行比对以便快速反馈，但前端比对不构成防线 |

| 3 | 签名内容、nonce、会话令牌**一律不入日志** |
| 4 | **不做账户锁定**（Δ-6），但保留 **IP 层限频**：同 IP 1 小时内签名验证失败超过 `N-L42` 次后，后续请求强制降速。不做 IP 封禁 |
| 5 | 权限拦截（⊘ / ❌）由服务端强制。前端置灰只表示"按钮还画着"，服务端收到请求照样拒绝 |
| 6 | 日志脱敏：钱包地址按缩略格式，邮箱按 `a***@example.com` |
| 7 | 服务端必须拒绝任何修改已绑定钱包地址的请求，**且被拒绝的请求也要留痕**（《功能需求说明》 6.6） |
| 8 | **本期不存在申请换绑或运营代改通道**，SPV 同运营也不增加该权限。客服反馈不等于改绑申请，不承诺恢复结果或处理时效 |
