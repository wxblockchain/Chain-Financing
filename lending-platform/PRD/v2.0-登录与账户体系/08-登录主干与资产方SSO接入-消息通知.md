# 登录主干与资产方 SSO 接入 · 消息通知

本文件只定义 WS-348 功能模块产生的站内信，是本模块通知业务规则与文案的统一来源。每个功能模块各有一份消息通知文件；资金方账户、机构审核及其他业务模块在各自 issue 单独产出，不能将本文件扩成全平台通知总册。

## 1. 范围、来源与阅读入口

本期仅实现站内信，不新增邮件、短信、浏览器推送或其他站外通知。三方均须核对是否受本模块事件影响，但不要求每个事件向三方各发一条。只在影响权益或需要后续处理的关键节点通知；用户当场可见的操作结果不重复推送。

## 2. 三方接收范围与关键节点筛选

| 角色 | 本模块是否发送站内信 | 依据与边界 |
| --- | --- | --- |
| 资产方 | 是，仅向受认证降级影响的本平台资产方账户发送 `EV-L20` | 已有效认证变为非已认证，失去发起融资申请资格，属于需明确告知的权益变化；仅本人可见 |
| 资金方 | 本模块无独立投递事件 | 共用入口、回跳及引导不产生资金方账户消息。机构审核或资格变化归 WS-349 / WS-358 自身通知文件，沿用 `ST-1`，本册不重复发 |
| 运营管理人员 | 本模块无投递事件 | 本平台不审核或修改资产方上游认证；现有功能未给借贷运营人员新增处理任务。资产方认证降级不群发运营人员，SSO 技术异常也不转成运营站内信 |

| 场景 | 是否发站内信 | 现有处理方式 |
| --- | --- | --- |
| 已有效认证后，上游确认有效综合认证结论不再为已认证 | 发 `EV-L20` | 降低对应权限，同时保留 `ST-1` 下次进入时的显式说明 |
| 初次登录就是未认证；一直未认证；更新审核中但有效认证仍保留 | 不发 | 正常未认证引导或沿用当前有效资格；不把申请进度当成认证失效 |
| 登录成功、首次影子账户建立、协议同意、主动退出、登录过期、上游退出 | 不发 | 现有成功反馈、会话提示与游客态回落；不为日常登录活动增加未读消息 |

| 资产方资格变化对融资项目、资金方业务或运营工作产生影响 | 本模块不推导、不扩散 | 有关业务模块依据其已有规则决定是否有独立关键事件，并在自己的通知文件中定义接收者 |

## 3. `EV-L20` 资产方认证资格失效通知

关联功能：`F-L29` / `F-L30`；关联规则：`ST-1`、`D-L98`、`R-5`。`EV-L20` 使用主册为资产方 SSO 保留的通知事件号段。

| 项 | 业务规则 |
| --- | --- |
| 触发条件 | 本平台已建立该资产方账户，且此前有有效已认证结论；本次取得上游明确、有效的综合结论，确认其从已认证转为非已认证。以此资格变化为一次事件，不按子审核状态各发一条 |
| 发送时点 | 本平台确认并应用该次有效认证降级时产生站内信；不等用户再次登录、点击受限操作或进入消息中心才产生。若在下一次授权或复核时才获知变化，届时发送，不虚构此前已经送达 |
| 不成立的条件 | 初次未认证、持续未认证、通信失败、缺失或无法解释的返回值均不构成已确认降级。异常时原有保守权限规则继续生效，但不向用户声称“上游已收回认证” |
| 收件人 | 被降级的本平台资产方账户。不得按钱包、邮箱、企业或上游原始账号直接确定消息归属；同钱包的资金方身份、其他企业账户、运营人员均不接收 |
| 账户不在线 | 可为已有账户产生站内信；未登录时不可读取，重新取得合法访问资格后才可查看本人消息。投递或查看消息不能恢复会话、绕过协议或解除账户不可用限制 |
| 消息与业务的先后关系 | 降级及操作限制不能等待通知发送成功。通知失败不能回滚降级；补送同一事件仍只形成一条消息。消息中心沿用其可见时效要求，不新增本模块专属重试周期 |
| 与页面说明的关系 | 站内信记录已发生的变化，`ST-1` 页面说明解释当前限制；二者共用同一业务事实。已读不代表已完成认证，关闭页面说明也不删除消息 |
| 偏好开关 | `EV-L20` 属认证与合规强制通知，任何当前或历史关闭值均不影响发送。默认开启、仅控制明确可选事件的政策已确认；本模块无可选事件，本期无可操作开关，见 3.1 |

## 4. 防干扰、历史消息与跳转

1. **同一次变化只通知一次。** 多标签、状态刷新、重新登录、重复上游告知和失败补送不得增加第二条，也不得把已读消息反复改回未读或置顶。事件发生时间与排序不因这些重复而改变。
2. **持续非已认证不催促。** 不按天、按登录次数或按受限点击次数重发，不追加“尚未处理”提醒；本事件不生成新的待办或倒计时。
3. **恢复后再次真实降级是新事件。** 同一账户先恢复有效认证，随后再次被确认降级，需生成新记录；不能以“该账户终身只通知一次”吞掉后续变化。新旧记录分别已读，互不覆盖。
4. **旧消息保留历史含义。** 本事件无业务到期日，按消息中心现有保留规则保留。恢复认证不删除旧记录、不改写发生过的降级事实；查看旧消息时以当前真实状态决定操作权限，不重新降级。
5. **一个明确的站内落点。** 消息的“查看账户”进入本平台 `P-L12` 账户设置；用户可经既有离站确认前往资产可信平台查看或管理认证。消息不自动跳出平台、不直接执行认证或融资，不新增本地审核页。
6. **访问与异常沿用消息框架。** 进入消息及账户页均检查当前身份权限；目标映射未完成时保留内容、暂不显示跳转操作，不猜地址。会话失效按登录主干处理，不通过消息绕过访问限制。
7. **减少额外打扰。** 本事件进入现有消息列表及未读计数；不新增强制弹窗、声音或站外触达。现有 `ST-1` 显式说明保留，展示位置与组件由设计师沿既有规范处理。
