## 图 1 · 登录入口、离站返回与登录后落地

游客默认进入既有资产广场，顶部只有登录入口；每次进入身份选择都须明确点击，不提供上次身份快捷入口或自动跳转；受限操作使用弹层身份选择，不另开一张选择页。下图的资金方节点只引用 WS-349 的边界，未定义其页面正文。

```mermaid
flowchart TD
    G["游客浏览<br/>默认资产广场"] -->|顶部登录| P["P-L01 整页身份选择"]
    G -->|触发受限操作| C["C-L01 身份选择弹层<br/>保留原页面与操作"]
    P --> ROLE{"用户选择身份"}
    C --> ROLE
    ROLE -->|资产方| LEAVE["C-L04 离站确认<br/>显示资产可信平台"]
    ROLE -->|资金方| WALLET["直接连接钱包<br/>无重复连接中间页"]
    LEAVE -->|确认| UP["前往资产可信平台授权"]
    LEAVE -->|取消或 Escape| ORIGIN["回原身份页或原弹层<br/>恢复原按钮焦点"]
    UP -->|授权返回| SSO["资产方授权结果与必需协议<br/>见图 2"]
    UP -->|放弃返回| CANCEL["恢复合法原浏览上下文<br/>无原页则到资产广场"]
    WALLET -->|取消或不可用| ORIGIN
    WALLET -->|连接成功| F["WS-349 签名确认 P-L20<br/>连接不建号，签名不自动弹出"]
    F -->|切换身份| P
    F -->|首次验证成功建号| ONB["WS-349 既有机构注册引导<br/>未认证，不直接执行出资"]
    F -->|老用户完成登录| LAND
    SSO -->|已满足登录与协议条件| LAND{"有有效原目标吗"}
    LAND -->|有| PERM{"当前资格允许原动作吗"}
    PERM -->|允许| BACK["回原触发点并恢复操作"]
    PERM -->|仍受限| GUIDE["显示对应受限引导"]
    LAND -->|无或无效| MARKET["资产广场<br/>无效回跳给中性提示"]
    GUIDE -->|去资产可信平台认证| VERIFY["C-L04 离站确认"]
    VERIFY -->|取消或 Escape| GUIDE
    VERIFY -->|确认| UP
```

资金方首次建号先入驻、资产方未同意协议先到 `P-L11`，都不能被回跳绕过。有效返回还须满足主干安全边界；跨平台对端确认未完成时按 3.7 兜底。`C-L03` 和账户页的离站取消同样返回原区域并恢复焦点；取消不同于切换身份，不清除原浏览上下文。

## 图 2 · 资产方授权结果与协议同意

入口 A（资产可信平台发起）与入口 B（借贷平台发起）共用以下业务结果；不在图中展开协议处理或校验算法。

```mermaid
flowchart TD
    START["资产方授权返回<br/>P-L10 展示处理中"] --> TRUST{"本次身份确认通过且账户标识可用吗"}
    TRUST -->|否| FAIL["R3 登录失败<br/>不建立新登录"]
    TRUST -->|是| AVAILABLE{"上游账户可用吗"}
    AVAILABLE -->|否| BLOCK["R2 主体不可用<br/>不建新会话，已有会话失效"]
    AVAILABLE -->|是| ACCOUNT{"本平台账户建立或更新成功吗"}
    ACCOUNT -->|否| P13["P-L13 建号失败<br/>错误码与双出口"]
    ACCOUNT -->|是| SIGNIN["R1 登录成功<br/>不同旧账号退出，资料保持隔离"]
    SIGNIN --> CONSENT{"必需协议已同意吗"}
    CONSENT -->|否| P11["P-L11 协议同意<br/>受限会话"]
    P11 -->|阅读协议| READ["查看或下载正文<br/>不代替同意"]
    READ --> P11
    P11 -->|同意成功| LAND["按当前认证状态与主干规则落地"]
    P11 -->|加载或保存失败| RETRY["就地说明并可重试<br/>仍不得进入业务"]
    RETRY --> P11
    P11 -->|退出并继续浏览| GUEST["游客态<br/>恢复合法原浏览页，无原页到资产广场"]
    CONSENT -->|是| LAND
    FAIL --> FEEDBACK["原目标游客视图与中性提示<br/>可继续浏览或重新登录"]
    BLOCK --> FEEDBACK
    P13 -->|重试| START
    P13 -->|以游客身份继续| GUEST
```

`R3` 不新增登录，不影响与本次失败无关的既有有效登录；`R2` 必须结束对应不可用主体的会话。无合法原浏览页时按主干兜底；不能用原页恢复绕过游客不可见权限。失败信息不得暴露内部判定细节；只有建号失败使用 `P-L13`，其他失败不另增错误死胡同。

## 图 3 · 资产方登录状态

```mermaid
stateDiagram-v2
    [*] --> 游客态
    游客态 --> 受限会话: 授权成功但必需协议未同意
    游客态 --> 正常登录: 授权成功且协议已同意
    受限会话 --> 正常登录: 同意成功
    受限会话 --> 受限会话: 阅读协议或同意失败后重试
    受限会话 --> 游客态: 退出或登录失效
    正常登录 --> 游客态: 主动退出 S-2
    正常登录 --> 游客态: 到期 S-1
    正常登录 --> 游客态: 上游全局登出 S-4
    正常登录 --> 游客态: 上游主体不可用 R2
```

| 失效原因 | 用户可见结果 |
| --- | --- |
| 主动退出 | 就地回游客视图，提示已退出；资产可信平台登录不受影响 |
| 到期 | 就地降级并提示登录已过期，可主动重新登录 |
| 上游登出 | 提示「你已在资产可信平台登出，本平台登录同时结束」 |
| 主体不可用 | 就地降级，显示可取得的解除时间或客服入口；不捏造时间 |

所有失效均不自动弹登录页；原页面受保护内容不可继续读取。尚未成功保存的偏好无草稿，按 `S-5` 提示未保存；已完成保存不撤回，重新进入读取最后成功值。迟到结果不能恢复旧登录或显示旧操作成功。资产方主动退出仅在账户下拉菜单提供，账户页不展示登录状态分区或退出按钮，见 SSO 9。

## 图 4 · 资产方认证状态与操作资格

```mermaid
flowchart TD
    ENTER["用户浏览或发起操作"] --> SESSION{"登录是否有效"}
    SESSION -->|否| T1["T1 游客<br/>只可浏览游客允许的内容"]
    SESSION -->|是且已同意协议| VERIFY{"上游当前有效综合结论是否为已认证"}
    VERIFY -->|否或异常| T2["T2 资产方 L0<br/>允许浏览、账户设置与消息<br/>融资入口受限并提供认证引导"]
    VERIFY -->|是| T3["T3 资产方 L3"]
    T2 -.->|上游认证通过并刷新| T3
    T3 -.->|认证收回并说明，发送站内信| T2
    T3 -->|发起融资申请| WAIT["正在确认当前资格"]
    WAIT --> RESULT{"当前登录、认证与操作仍有效吗"}
    RESULT -->|有效且确认通过| CONTINUE["可继续融资申请"]
    RESULT -->|未认证| T2
    RESULT -->|无法确认| RETRY["尚未发起申请<br/>说明并可重试"]
    RESULT -->|退出、过期、身份变化或已离页| STOP["不展示旧成功结果<br/>不恢复旧流程或旧权限"]
    RETRY -->|重试| WAIT
```

图中认证判断使用上游当前有效综合结论，不能以资料更新申请的审核进度替代；更新审核中仍有效或驳回后失效均以上游结论为准。当前企业资料对应有效归属，待审核企业变更不提前生效。实际接口对应由开发核实，见[主册 8.4](./00-登录主干与资产方SSO接入-PRD.md#interface-boundary)。

会话与认证是两个独立维度。资产方只有 `L0` / `L3`；资金方 `L1` / `L2` 不套用到资产方。图中的资格等待不是新的账号状态，也不是融资申请已创建；旧结果不得反向覆盖当前降级状态（`D-L116`）。

规则正文：[主干 A](./00-登录主干-01-入口与回跳.md)、[主干 B](./00-登录主干-02-引导与权限契约.md)、[资产方 SSO](./01-资产方SSO接入.md)。测试主读[验收需求说明](./02-登录主干与资产方SSO接入-验收需求说明.md)。

```mermaid
flowchart TD
    TOP["正常资产方登录<br/>顶部显示钱包地址缩写<br/>缺失时为我的账户"] --> MENU["悬浮、点击或键盘展开菜单<br/>菜单内显示资产方"]
    MENU -->|账户设置| ACCOUNT["P-L12<br/>仅本人账户及个人资料只读<br/>语言选择即保存"]
    MENU -->|企业信息| COMPANY["P-L14<br/>仅本人有效归属企业资料只读"]
    MENU -->|唯一主动退出入口| OUT["退出本平台<br/>回落游客态，不退出上游"]
    ACCOUNT --> ACCESS{"是否为本人资料且企业资料归属有效"}
    COMPANY --> ACCESS
    ACCESS -->|是| DATA{"资料读取结果"}
    ACCESS -->|否或归属无法确认| DENY["不展示其他账户或待审主体资料<br/>保留返回及适用重试入口"]
    DATA -->|有资料| DETAIL["只读详情<br/>隐藏缺失可选字段"]
    DATA -->|无资料| EMPTY["暂无企业认证信息<br/>保留返回及上游查看入口"]
    DATA -->|失败| RETRY["就地说明并可重试"]
    RETRY --> COMPANY
    ACCOUNT --> POLICY["关键通知始终接收<br/>无可选事件，不提供可操作开关"]
    ACCOUNT -->|改选语言| SAVE["正在保存该项<br/>该控件暂时锁定"]
    SAVE -->|成功| SUCCESS["新值生效并反馈<br/>后续回显最后成功值"]
    SAVE -->|失败| FAIL["恢复原选项与生效值<br/>失败提示，可再次选择"]
    FAIL --> ACCOUNT
    ACCOUNT -->|前往上游管理资料| LEAVE["C-L04 离站告知"]
    COMPANY -->|前往上游查看或修改| LEAVE
    LEAVE -->|取消| BACK["回原页面及触发位置"]
    LEAVE -->|确认| UP["前往资产可信平台<br/>返回后读取当前资料"]
    BUSINESS["进入已有业务场景"] --> GET["自动获取必要业务信息<br/>不要求借贷端手填上游资料"]
    GET --> READY{"必要信息可用且有效主体可确认吗"}
    READY -->|是| SHOW["只展示该业务必要信息<br/>按该业务既有可见角色"]
    READY -->|否| LIMITED["相关动作暂不可继续<br/>说明原因并保留返回及适用重试"]
```

读取中显示占位，空态与失败态分开；个人信息区同样遵循这一区分。资料展示不参与认证资格推断。`Q-L01` 的两类基本信息仅为暂定供给，模拟资料不代表联调通过。退出、过期或身份变化后不再展示旧资料；离开页面后不显示迟到保存成功，已成功保存值不会因离开被撤回。`Q-L03` 已关闭：通知默认开启且仅可控制明确可选事件；本模块可选清单为空，账户页无可操作开关，`EV-L20` 始终接收。本人基本资料与业务信息的边界见 SSO 9.4 `D-L119`，不得以业务展示开放整份资料；业务信息不足只限制依赖该信息的动作。

## 图 6 · 本模块认证降级通知

关联[本模块《消息通知》](./08-登录主干与资产方SSO接入-消息通知.md)与验收 `AC-L315`～`AC-L324`。本图只表示业务判定，不规定通知传输或去重实现；偏好与权限验收补充见 `AC-L325`～`AC-L329`。

```mermaid
flowchart TD
    CHECK["确认上游当前有效综合认证结论"] --> CHANGE{"是否从有效已认证变为非已认证"}
    CHANGE -->|否，或未取得可确认结论| NO["不产生认证降级站内信<br/>权限与异常按原规则处理"]
    CHANGE -->|是| APPLY["应用认证降级<br/>保留 ST-1 页面说明"]
    APPLY --> SAME{"是否为已经通知过的同一次变化"}
    SAME -->|是| KEEP["不新增、不置顶<br/>不恢复未读"]
    SAME -->|否| NOTICE["EV-L20 一条强制站内信<br/>仅受影响资产方本人<br/>不受关闭偏好影响"]
    NOTICE --> READ["合法登录后阅读历史告知"]
    READ --> ACCOUNT["按当前权限查看本平台账户<br/>旧消息不改变当前认证状态"]
```

持续未认证不重复催促；恢复有效认证后再次降级属于新事件。资金方与运营人员不接收本模块这条通知，其各自业务事件由所属功能模块单独定义。通知不可用不延迟权限降级；消息投递或阅读不恢复登录、不替代业务处理。
