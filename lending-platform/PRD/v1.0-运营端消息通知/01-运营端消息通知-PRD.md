# 运营端消息通知 · PRD

版本：V1.2｜日期：2026-09-22｜使用端：借贷平台运营管理端（运营管理员 `RO-AL-1`、运营专员 `RO-AL-2`）｜状态：当前需求稿，真实依赖见[第 5 节](#deps)。

## 1. 目标与阅读入口

运营人员在账户、机构审核、质押审核、协议管理和消息页面之间工作，需要一致的通知入口、未读提示与历史消息，并能判断原通知描述的事情现在是否还能办。本模块承接已定义来源发往本运营端的站内消息：从任一模块看到未读提示，打开最近预览或整页列表，筛选、翻页、进入详情读完整事实，必要时前往原业务对象，再沿原路返回。

消息不是业务本身，也不是办结凭证：阅读与审核、发布、改密、资金动作互不替代。**本模块没有独立发送事件、没有新增业务模板、不发送邮件或站外消息**；发什么、何时发、发给谁由各来源模块定义。接入一个已符合本框架的新业务，只更新来源通知册与共享登记，不在本模块正文追加业务事件章节。

本期包含：共享铃铛与未读计数、最近预览、整页列表与详情、分类与阅读筛选、分页、单条自动已读与当前筛选跨页全部已读、来源返回、业务目标与失效、账户与端隔离。相邻模块负责：各来源的触发条件、收件范围与文案；账户与登录负责身份、会话、语言与时区偏好；面客消息中心负责面客端的同类能力。本期不包含：消息发布、公告编辑、人群圈选、订阅偏好入口、邮件/短信、站外送达统计、删除或归档、待办认领转派、异常升级/关闭/释放。

阅读顺序：[第 2 节共同规则](#common) → [第 3 节完整功能](#functions) → [第 5 节依赖与待决](#deps) → [第 4 节同序验收](#acceptance)。配套两册须共同使用：[流程图与状态机](02-运营端消息通知-流程图与状态机.md)、[消息通知与来源衔接](03-运营端消息通知-消息通知.md)。

## 2. 角色、页面与共同业务规则

### 2.1 角色与使用场景

运营管理员与运营专员使用同一运营账号体系，均按各自的实际功能权限使用本模块。管理员的业务权限按运营端账户与登录的预置配置固定，不能查看他人的个人安全消息；专员的运营端消息查看（`PM-AL-12`）默认开启但可按交付配置调整。界面显示的角色与当前权限一致，“管理员”称谓不是授予权限的动作。SPV 是同一运营主体的职责，不是第三种账号或第三个消息池。

典型场景：运营从任一模块打开最近通知再进入详情；读到机构资料待审核后去看原提交，若已处理则只看原记录而不能再次审核；读到协议定时生效失败后进入对应版本处理，无内容权限时只能返回消息；读到本人密码变更通知后进入本人账户设置并返回原消息；有消息权限但无协议历史权限时可读合法消息，却打不开历史文件。

## 3. 功能需求说明

<a id="f-o01"></a>
### 3.1 共享入口、未读计数与最近预览（`F-O01`～`F-O05`）

<a id="f-o02"></a><a id="f-o03"></a><a id="f-o04"></a><a id="f-o05"></a>

**适用角色与前提。** 正常登录、已完成首登强制改密且持有运营端消息查看（`PM-AL-12`）的运营人员，可从本端任一模块获得一致的通知入口。账户、机构审核、质押审核、协议管理、消息页面使用同一账号的消息与同一份已读结果，各页不另造独立未读。无消息权限时入口隐藏、深链拒绝；业务目标的权限另行判断。

**入口与账户信息（`F-O01`、`F-O04`）。** 共享铃铛 `C-O20` 打开最近预览 `C-O21`；账户菜单中的“消息中心”直接打开无筛选的 `P-O20`，不先经过预览，也不新增侧栏一级菜单。顶栏显示本人当前工作邮箱，悬浮菜单显示真实角色（管理员显示“管理员”，专员显示其实际角色），中英对应且支持键盘访问。本人邮箱是身份展示，不因正文的私人信息限制被错误隐藏；其他人的完整邮箱不展示。账户菜单不新增用户邀请、权限配置或人员管理。

**未读计数（`F-O02`）。** 只统计本端、本账号可见、仍有效且未读的消息，不受当前分类或阅读筛选影响。没有有效未读时不显示数字 0；1～99 显示真实数量，超过按 `N-O03` 显示 `99+`。已过期、来源主动失效、账号创建前的全体历史不计入。目标被删除、当前无权限或原任务已被处理，本身都不等于消息失效，仍按消息的真实有效性与阅读状态计数。

| 编号 | 当前规则 |
| --- | --- |
| <a id="d-o15"></a>`D-O15` | 计数范围是本端、本人、有效、未读；上限按 `N-O03` |
| <a id="d-o16"></a>`D-O16` | 前台按 `N-O01` 每 60 秒刷新，页面不可见时停止，回到前台立即刷新 |
| <a id="d-o08"></a>`D-O08` | 后台自动刷新不计作用户操作，不延长会话 |

**一致性与失败（`F-O05`）。** 当前页成功已读后即时更新；其他模块与同账号的其他标签页同步，最长不超过 `N-O01`。刷新失败保留最后可信数值，不清零、不反复弹错；遇会话失效不静默忽略，按[异常与边界出口](#exits)退出。修改邮箱后顶栏显示新邮箱，个人消息历史、首次已读与接收归属不变。切换或退出账号后不沿用前一人的计数与正文，旧操作的迟到反馈不得写入新账号。

**最近预览（`F-O03`）。** 展示本人本端最近 `N-O02` 条（含已读），与列表采用同一批消息事实与阅读状态，提供可获得的完整标题、必要摘要、发生时间、分类与阅读状态。展开、滚动、悬浮都不产生已读；选择一条进入独立详情，内容成功呈现才已读。“查看全部”进入 `P-O20`；预览不承载全部已读。再次点击铃铛、点击外部、Esc 或关闭操作可收起，焦点返回铃铛；打开后焦点进入预览，键盘可达且读屏名称明确。首次无消息给空态；加载失败给重试且不显示为“无消息”，已有可信内容时失败保留内容。打开预览不改变原业务表单；存在未保存业务内容时服从来源页面自身的离开保护，不用消息入口绕过。

流程参见[共享入口、阅读与返回（FL-O01）](02-运营端消息通知-流程图与状态机.md#fl-o01)、[消息准入与目标权限分别判断（FL-O05）](02-运营端消息通知-流程图与状态机.md#fl-o05)。

### 3.2 消息中心列表、筛选与分页（`F-O06`～`F-O09`）

<a id="f-o07"></a><a id="f-o08"></a><a id="f-o09"></a>

**展示。** `P-O20` 为独立整页，沿用已采纳的白底分隔行阅读方式，提供标题、摘要、分类、发生时间与已读/未读状态。整行可进入详情，列表没有行内“标为已读”。分类是业务归类，不作为附加的阅读状态；过期与目标不可用的说明放在详情，不在列表增加状态标签。字段定义见[业务信息与校验](#fields)。

**分类与阅读筛选（`F-O06`、`F-O07`）。** 默认全部分类、全部阅读状态；阅读状态可选全部/未读/已读，分类与阅读状态取交集。只列出当前账号实际拥有消息的分类，取自来源的真实业务归类，不预设固定空分类；未知映射不得使合法消息整条消失。分类筛选不改变收信政策，不等于退订。切换筛选回到第 1 页与列表起始位置。无效筛选回落默认值并正常可读，不报错、不伪造空集。

**排序与分页（`F-O08`）。** 按原发生时间倒序，同一时点保持稳定次序；已读不置底、未读不置顶。同一事实补送不改原时间、位置或数量。使用页码式分页，默认与可选值按 `N-O04`，改变每页条数回到第 1 页，并显示当前筛选的总条数。该总数包括匹配的已读条目，不要求与全部已读确认的未读条数相等。翻页或新消息到达都不得造成浏览结果重复或漏项；保留已加载的阅读上下文，新结果在主动刷新后纳入当前浏览。

| 编号 | 当前规则 |
| --- | --- |
| <a id="d-o14"></a>`D-O14` | 页码式分页，条数按 `N-O04` |
| <a id="d-o17"></a>`D-O17` | 按原发生时间倒序，阅读状态不参与排序 |

筛选、页码与每页条数可随当前页面地址保持，刷新可恢复；默认值不产生多个不同的默认地址。详情返回还须恢复滚动与来源消息焦点，见[消息详情、阅读已读与来源返回](#f-o10)。若可见结果变化导致原页不存在，展示最近的有效页并说明结果已变化，不停在无效页。

**空态与失败（`F-O09`）。** 首次无消息说明“暂无消息”；筛选无结果说明“没有符合条件的消息”并提供清除筛选，两者含义不同。首屏读取失败展示重试，不能伪装成空态。翻页时保留当前内容并防止重复翻页操作，翻页失败仍停留原页可重试。单条文案异常按 `D-O22` 降级，不影响同页其他条目、不泄漏文案键。加载与空态都不产生已读，也不产生新通知。

流程参见[共享入口、阅读与返回（FL-O01）](02-运营端消息通知-流程图与状态机.md#fl-o01)。

### 3.3 消息详情、阅读已读与全部已读（`F-O10`～`F-O13`）

<a id="f-o11"></a><a id="f-o12"></a><a id="f-o13"></a>

**详情阅读（`F-O12`）。** `P-O21` 为独立整页、可深链打开。先满足消息准入与归属，成功后显示标题、完整正文、分类、原发生时间及必要的原业务关联。正文为纯文本，标签与脚本作为文字显示、不执行。时间为绝对时间并标注时区；正文中的日期、金额、期限不得被当前业务状态重写。

| 编号 | 当前规则 |
| --- | --- |
| <a id="d-o18"></a>`D-O18` | 只有详情内容成功呈现才对本人自动已读；无行内已读，无手动改回未读 |
| <a id="d-o19"></a>`D-O19` | 全部已读的范围是本账号、本端、当前筛选命中的全部未读，跨所有页；须二次确认，只影响本人 |

**单条阅读已读（`F-O10`）。** 仅在详情成功呈现后自动已读，或在全部已读中被明确选定。预览展开、消息经过视窗、标题悬浮、详情加载失败与跳转预判都不产生已读。已读只属于“当前账号与这条消息”，不改变其他账号、其他端或业务进度。详情加载失败保留未读，明确说明并提供重试与返回列表；已读保存失败不阻断正文阅读、不弹错误干扰，也不能伪称成功或清除真实未读，下一次同步以真实结果为准。重复阅读不更新首次已读时间。同一业务事实重复投递或补送继续沿用原消息的阅读事实（`D-O29`）；新一次真实提交或审核结果是独立事实，形成自己的消息，不按“同机构、同代币”把不同笔合并吞掉。来源明确的条件模板或合并结果沿来源的唯一规则，不由本框架拼接或拆成多封。

**当前筛选跨页全部已读（`F-O11`）。** 用户在 `P-O20` 发起。执行前二次确认，展示真实待处理的未读条数、当前分类与阅读筛选，并说明“跨页、仅影响本人、不可撤销”，默认焦点在取消。当前匹配未读为 0 时禁用并解释；全局未读包含其他分类也不能扩大范围。确认圈定本次范围后到达的新消息保持未读，操作不转为持续自动已读。确认显示数与实际可处理数不一致时如实反馈实际结果，不按旧数伪报成功；已被本人在另一页读过的消息不重复计算、不改首次时间。成功后更新列表、总未读及其他模块，仅改变本人的阅读状态。失败不宣称成功、不乐观清零，保留可确认的原状态并允许重试；会话失效须重新登录后核实结果。执行期间防止重复确认，确认、取消与外部关闭暂不可用，完成后恢复可用并把焦点还给可用入口。阅读操作不发送回执消息、不通知其他运营人员、不生成业务完成记录。

**来源返回（`F-O13`）。** 面包屑、返回列表与浏览器返回都恢复原分类、阅读筛选、页码、每页条数、滚动位置及可用的来源消息焦点；详情刷新后仍可恢复同一会话内的来源。刚读过的条目原位显示为已读、不重排；在“未读”结果中暂留该行，直到用户主动刷新或切换筛选，返回本身不主动移除该行。来自预览或无列表来源的深链，返回默认列表；不接受外部不可信的返回地址。从消息前往本人账户设置时提供返回原消息的途径，不丢失原列表上下文。业务目标若有未保存操作，遵循目标自身的离开保护；返回不是批准或取消业务。来源账号已变化、权限已撤销或消息不再可见时重新判断权限，不恢复旧内容。

流程参见[共享入口、阅读与返回（FL-O01）](02-运营端消息通知-流程图与状态机.md#fl-o01)、[当前筛选跨页全部已读（FL-O04）](02-运营端消息通知-流程图与状态机.md#fl-o04)、[一个账号对一条消息的阅读状态（ST-O02）](02-运营端消息通知-流程图与状态机.md#st-o02)。

### 3.4 业务目标、动作失效与原对象可读（`F-O14`、`F-O15`）

<a id="f-o15"></a>

**三类目标（`F-O14`、`F-O15`）。** 无跳转、原业务对象、静态页面三者互斥。原业务目标须明确属于本端且已登记，必要时定位到原申请、原提交、原期次、原执行笔或原协议版本；静态页面须是本平台本端的唯一页面。消息不携带任意页面地址，既有映射约束引用[文档同源规则](#26-文档同源规则)所述基线，本册不定义路由协议。混合目标或错端目标不得成为可访问的本端消息，不使用猜测地址或默认首页。

| 编号 | 当前规则 |
| --- | --- |
| <a id="d-o20"></a>`D-O20` | 无目标、原业务目标、静态页面互斥；旧动作是否可办与原对象能否查看分开判断 |
| <a id="d-o32"></a>`D-O32` | 机构认证的不分权业务口径、质押的既有权限与协议的历史/记录边界分别适用，互不扩散 |

来源不需要跳转时可以合法无目标，正常展示且不出现无效按钮或多余说明。映射未登记时正文仍可阅读、计数与已读，不显示无效按钮、不跳首页，也不掩盖登记依赖；来源已明确要求保留“暂不可查看详情”提示时按来源保留该提示，不能用通用的无目标静默规则掩盖其已知故障。

**进入目标。** 原业务对象在进入详情时按 `N-O05` 做辅助可达性判断，列表不提前判断也不因此阻塞。静态页面可直接进入，目标仍校验当前资格。辅助判断失败或超时后允许用户尝试进入目标，但目标自身的权限与状态限制必须生效，不能凭超时取得资料或执行操作。

**动作失效与原对象可读。**

| 情况 | 消息与可用入口 |
| --- | --- |
| 原动作已过期或任务已被处理，但当前有权查看原对象 | 说明原动作不再可用，保留原对象/原记录的只读入口；禁止重开、再次提交原审核、冒用新提交或回退状态 |
| 原对象已删除或确实不可得 | 保留完整消息，说明目标不存在或暂不可用，禁用对应目标，不跳最新对象或错误首页 |
| 原对象存在但当前无查看权限 | 消息仍在本人合法范围内时可读，目标禁用并说明当前无权限，不泄漏受限内容或文件 |
| 消息自身过期或来源主动失效 | 不计未读，详情给出有效性说明，原办理动作不可用；若来源明确保留原对象历史且当前有权，仍可只读查看，否则无原动作入口 |
| 正常且当前有权 | 可进入来源已明确的目标；办理必须在原模块由用户按当前状态明确操作 |

业务状态流转不是消息状态，阅读也不改变来源事实。机构认证的旧提交通知只指该次提交与其操作历史，当前资料不能冒充旧材料，不提供历史材料下载、对比或回退。协议消息的目标按其当前性质重新判权：仍为当前或工作版本时凭协议当前内容与工作版本查询（`PM-AL-09`）进入，已成历史或下线留存时仅管理员凭协议历史版本读取（`PM-AL-15`）可读，操作记录凭协议操作记录查看（`PM-AL-16`）读取，三者不能互替。所有说明须能被键盘和读屏获取；不用一句“消息失效”掩盖不同原因，也不因跳转失败隐藏完整通知。

流程参见[原业务目标、历史查看与动作失效（FL-O03）](02-运营端消息通知-流程图与状态机.md#fl-o03)、[单条消息的有效性（ST-O01）](02-运营端消息通知-流程图与状态机.md#st-o01)。

### 3.5 接收范围、准入与端隔离（`F-O16`、`F-O17`）

<a id="f-o17"></a>

**消息功能准入（`F-O17`）。** 须正常运营登录、完成首登强制改密并持有 `PM-AL-12`。准入同时约束铃铛、预览、列表、详情、单条与全部已读、目标入口；无权限时入口隐藏，直接访问按运营端账户与登录的功能拒绝处理。登录失效统一回本端登录页并保留安全的本端原路径；未登录不泄漏消息是否存在。权限变化后再次访问立即按当前资格判断，不延续旧页面的授权。收回 `PM-AL-12` 后再次访问立即拒绝，重新授权后恢复符合资格的历史且阅读状态不重置——这是权限生效的结果，不是产品内新增的授权配置页面。

**两类接收范围（`F-O16`）。** 来源确认的全体运营消息，对当前具有消息权限的正常运营管理员与专员可见，个人阅读互不影响；个人安全消息仅接收账号本人可见。所有查看、计数与阅读都依据实际登录账号与本端，不能靠改写身份、消息编号或端标识取得他人内容。无查看他人阅读明细的入口，不暴露可枚举的消息查询能力。同一条全体消息，A 阅读不改变 B；同一人在另一端的阅读也不联动。

**目标权限的判断顺序。** 先合法读取消息，再由目标模块检查原对象的可见性，最后由目标模块判断当前业务能否操作。

| 目标 | 采用的边界 |
| --- | --- |
| 本人账户设置 | 本人账户设置（`PM-AL-14`）的本人范围；不得跳入其他人员档案或账号管理 |
| 资金方机构认证查询/审核 | 业务口径沿资金方机构认证审核“正常运营登录即可、不做查询/处置分权”；消息准入仍为 `PM-AL-12`，不从消息侧另加门槛。该口径与运营端账户与登录矩阵登记的 `PM-AL-05`／`PM-AL-06` 存在文档接缝，按 [`Q-O07`](#q-o07) 保留，不从消息侧恢复已取消的分权 |
| 代币质押查询/处置 | 沿代币质押审核的 `PM-AL-07`／`PM-AL-08` 与逐笔状态限制，不套用机构认证的局部例外 |
| 协议当前内容、维护与发布 | 沿 `PM-AL-09`／`PM-AL-10`／`PM-AL-11`；维护与发布需要当前内容查询资格 |
| 协议历史内容、预览及文件 | `PM-AL-15` 仅运营管理员可读；专员不因读到通知而取得历史内容 |
| 协议操作记录 | `PM-AL-16` 对正常管理员与专员均可读，不要求先有 `PM-AL-09`，也不公开无权内容或历史文件；无 `PM-AL-12` 的账号仍可从协议模块读取记录，但不恢复消息入口 |

**会话与账号变化（`F-O05`、`F-O17`）。** 后台未读刷新不算用户操作（`D-O08`）。会话到期、无操作超时、改密导致的失效按运营端账户与登录处理，停止受保护访问并回本端登录页。执行全部已读遇会话失效不能声称成功，重新登录后以真实阅读状态为准。邮箱修改不创建新的接收身份、不清空已读，也不把历史移交给新邮箱所属的其他账号。切换账号后不得显示前一人的旧数值、正文或迟到的成功反馈。

流程参见[消息准入与目标权限分别判断（FL-O05）](02-运营端消息通知-流程图与状态机.md#fl-o05)。

<a id="f-o18"></a>
### 3.6 来源承接与既有编号（`F-O18`）

接收范围采用[相邻模块与来源](#sources-index)及[消息通知与来源衔接](03-运营端消息通知-消息通知.md)登记的已定义来源；发送时点、收件对象、模板与原业务目标由各来源负责。新增合法业务种类可沿同一列表、详情、阅读与目标规则使用，不为每个业务重建本模块。没有正式登记的映射不声称可跳转，也不因映射缺失丢掉合法通知。

本端目前承接四类来源事实：机构资料待审核（`EV-L42`）与定时生效成功告警（`NT-O-AG-01`）、定时生效失败告警（`NT-O-AG-02`）、待生效计划撤销告警（`NT-O-AG-03`）属“全体运营”范围；密码变更通知（`NT-AL-01`）属“本人”范围。机构认证审核不重复发送待审核，代币质押审核与融资需求模块不重复发送同一审核结论；面客审核结果与借贷广场各阶段事件不自动抄送运营或 SPV，我的控制台无独立事件。不从阅读、状态查询、失败重试或旧任务结束制造新事件。**本模块新增的独立业务事件数与模板数均为零。**

`P-O20`／`P-O21`、`C-O20`～`C-O23` 沿用既有编号，不占用其他平台段位，目标须能唯一定位本平台本端。共享登记的正式分类、端标识、来源原目标及其当前完成状态沿 [`Q-O05`](#q-o05)，旧只读参考不作为已接通的证据。来源须提供真实业务能力与消息证据；真实时效、权限、目标跳转与投递仍待联验，原型断言与文档核对不能替代。

### 3.7 业务信息与校验

用户只能筛选、阅读与跳转，不能编辑消息内容。下表是业务信息需求，不是接口字段表。

| 业务信息 | 含义/必填与默认 | 展示、校验及权限 |
| --- | --- | --- |
| 标题 | 必须能说明原事件；来源提供成对语言文案 | 列表、预览、详情均可获得完整标题；缺失按 `D-O22` 降级，不展示内部键 |
| 摘要 | 来源可提供简述，非必填；无则留空 | 不用当前状态重写原事件；详情保留完整正文 |
| 正文 | 来源必须提供完整业务告知及条件模板对应内容 | 纯文本；保留原因、金额币种、原日期/截止与完整条目，不拼出未发生的结果；缺失明确降级 |
| 分类 | 来源明确的业务分类，正式取值依唯一共享登记 | 只展示本人有消息的分类；缺登记不隐去合法消息，不在本册新造分类值 |
| 发生时点 | 原业务实际发生或应到的时点，必填 | 不用消息到达或读取时间替换；带时区显示，同一时点排序稳定 |
| 阅读状态 | 对当前账号为未读/已读，新事实默认未读 | 只允许 `D-O18` 的正向转换；首读时间不被覆盖；账号创建前的全体历史可查但不计角标 |
| 消息有效性 | 来源明确的生效/过期/主动失效事实；无期限不自设 | 详情展示说明，列表阅读标签仍仅已读/未读；任务完成不自动过期 |
| 接收范围 | 来源明确“全体运营”或“本人”，必填 | “本人”须确定原接收账号；不得按邮箱变更、机构或业务办理人猜测与重分配 |
| 原业务关联 | 有业务目标时必填；可含申请、提交、期次、单笔执行、协议版本等定位信息 | 指向原事实，不用技术版本号代替提交时间；无目标不强造关联 |
| 目标说明/入口 | 条件必填，随来源已登记目标与当前权限 | 无目标不必展示；失败、无权、已处理按[业务目标、动作失效与原对象可读](#f-o14)分别说明 |
| 本人邮箱与角色 | 本人实际当前邮箱与预置角色，必填 | 只用于共享账户菜单；不公开他人档案，不凭文字升权 |
| 公共客服 | 来源提供真实对外联系方式才展示，未配置不编造 | 完整可阅读与复制；缺失时反馈暂不可用，不新增发送渠道 |

账号密码、验证码、私人完整档案、钱包凭据、材料原件不得进入正文、摘要或预览。必要业务数据按来源权限可读，查看业务信息不能变成查看他人账户档案。机构审核员的私人身份沿来源的匿名规则，不在通知中披露。真实公共客服联系方式可完整阅读与复制，不套用私人邮箱的屏蔽规则；未提供时不写虚构地址、不新增邮件渠道。

### 3.8 异常与边界出口

| 情况 | 产品结果 |
| --- | --- |
| 未登录或会话失效 | 隐藏受保护内容，停止消息访问，回本端登录页；首登改密未完成先完成账户流程，之后按当前资格返回本端原路径 |
| 无 `PM-AL-12` | 入口消失，深链与阅读操作拒绝，不以旧页面继续访问；其他合法业务功能按各自权限保留 |
| 其他端消息或他人个人消息 | 与“不存在”同一结果，不泄漏是否存在，已读不发生 |
| 首屏或详情读取失败 | 明确失败并可重试；失败的详情不标已读 |
| 刷新或翻页失败 | 保留可信计数或当前页内容；会话失效不按普通刷新失败忽略 |
| 全部已读中失效或结果未知 | 不显示成功，不污染其他账号；重新登录核实真实状态，不借此完成业务 |
| 目标失败 | 按[业务目标、动作失效与原对象可读](#f-o14)保留通知并分别反馈原因，不跳猜测页面 |
| 原业务异常 | 保持来源的真实事实与限制，按真实渠道联系客服；不在消息中心增加异常办理 |

### 3.9 非功能目标与保留策略

沿用既有目标：未读计数 P95＜300ms、20 条首屏＜1s、预览与详情各＜800ms、1000 条以内全部已读＜2s、目标可达性辅助判断＜500ms。这些是观察与校准目标，不等于已实测；上线时须能观察列表与未读时延，不等性能退化后才建立观察能力。<a id="d-o35"></a>`D-O35`：真实业务发生/应到时点到消息可见的 60 秒要求、来源最迟 5 分钟发现的约束以及本端 `N-O01` 的 60 秒前台刷新周期是三个不同口径，分别验收，不以进入框架的时刻重置第一项，也不把三者相加放宽；冲突按 [`Q-O08`](#q-o08) 联验，裁定前不擅自放宽、不宣称达标。

长期保留本人可见历史，不清理、不归档、不提供删除（`D-O12`）。已过期或主动失效的消息仍可查；未读筛选按真实阅读事实筛选，因此筛选结果可以包含“不计角标的过期未读”，全部已读可标记这些匹配条目但不恢复其有效性。`N-O07` 仅保留为未启用引用，不得因性能退化自动启用归档；调整保留政策需另有业务确认。

界面默认英文、中英即时切换，账户语言偏好沿运营端账户与登录。列表与预览在 24 小时内可用相对时间，超过用绝对时间；详情必须绝对时间并标注时区。首次登录的时区推断与写入归账户模块，推断失败或无可用偏好时兜底 UTC，消息中心不覆盖本人偏好。响应布局沿既有 1280/1440/1920 适配目标；操作可键盘完成、焦点可追踪、状态不只靠颜色、读屏不被未读更新抢焦点，尊重减少动效设置。布局、字重、间距与组件组合由 Hallmark 按现有公共规范落实，本册不附线框或新增布局规格。
