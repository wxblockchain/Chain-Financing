# 借贷平台 · 运营端 · 消息通知 PRD **V1.0**

> **本模块不是一套新的消息系统，而是平台消息能力在借贷平台运营端的一个消费端。** 消息数据契约、业务类型命名空间、分类定义表与接入规范全部沿用三平台共用契约，本 PRD **不重写、不分叉、不复制**。
>
> **本 PRD 只定义三件事**：运营端的**通用可见范围与权限口径**、运营端的**页面与展示**、运营端的**验收要求**。
>
> **本 PRD 不定义任何通知触发口径**——不列事件清单、不写「某某操作后发某某消息」、不写任何一条具体消息文案。借贷平台运营端各业务模块（资金方机构认证审核、代币质押审核、协议管理、对账、放款、运营公告……）的触发时点、事件集与文案，由**它们各自的 issue** 在自己的 PRD 里定义，按共用契约的接入指南自助接入。

## 3. 背景、目标与本期范围

### 3.1 背景

运营管理平台承担资金方机构认证审核、代币质押审核、协议管理、对账、放款与运营公告等工作。这些工作的共同特征是**事情先发生在别处、人要被告知**——一笔质押申请提交了、一笔对账出现差异、一个账号发生了安全事件。没有统一的站内消息入口，运营人员只能逐个打开业务列表页轮巡。

平台消息能力已经存在并已有多个消费端，**运营端需要的不是一套新东西，而是把这套能力接过来**。基线已完成这项接入并定稿入库。

**本轮真正要改的是一件事**：三平台重划分后，原来由一个运营端消息池承载的内容，现在分属**借贷运营端**与**代币发行运营端**两个相互独立部署的运营端。一个池同时装两端的消息，会让未读提示失去可操作性——运营人员看到的未读里混着自己这一端根本处理不了的事。

### 3.2 本期目标

| # | 目标 | 达成判据 |
| --- | --- | --- |
| 1 | 运营人员在运营端**任意已登录页面**都能看到「有几件事需要我知道」 | 顶栏铃铛常驻 + 未读提示（第 7 章、分册 `01` 12.1） |
| 2 | 点进去能知道**发生了什么**，需要处理的能**一键跳到该处理的地方** | 快捷面板 + 消息中心 + 详情 + 跳转三形态与四类失效降级（分册 `01` 12.2～12.6） |
| 3 | **借贷运营端的消息池与代币发行运营端、与其他端严格隔离**，不互相污染未读数 | 第 6 章可见范围与越权条款（`AC-O44`～`AC-O57`、`AC-O97`～`AC-O100`） |
| 4 | 借贷平台运营端各业务模块能**照着已有的一份契约接入**，不需要改本模块 | 接入方只读共用契约的接入指南，本模块零改动（`AC-O71`～`AC-O83`） |
| 5 | 消息功能的可用性随运营端的**功能权限**收敛，且与账号是否承担 SPV 职责无关 | 6.2 准入口径（`AC-O101`～`AC-O103`） |

### 3.3 本期做什么

- 借贷运营端的**通用可见范围与权限口径**（含按端隔离、SPV 受限可见、越权处置）。
- 借贷运营端的**站内消息展示层**：铃铛与未读提示、快捷面板、消息中心列表、消息详情、已读语义、跳转与失效降级。
- 借贷运营端的**验收要求全集**与**流程图 / 状态机**。

### 3.4 本期不做什么（各有归属，不是遗漏）

| 不做 | 归属 |
| --- | --- |
| **任何通知触发口径**（事件清单、发送时点、具体文案） | 借贷平台运营端各业务 issue。本模块只提供能力 |
| **数据契约与接入指南** | 三平台共用契约（0.2），本 PRD 显式引用、不重写 |
| **代币发行平台运营端的消息通知** | 代币发行平台侧另行实例化。本 PRD 只定义借贷运营端一个池 |
| **运营端账号主体、角色模型、登录与会话、路由前缀、国际化基线** | **WS-357「运营管理平台 · L13 运营端账户与登录」**。本模块不自造，只列依赖（第 9 章） |
| 面客端（借贷平台用户侧）的消息中心 | 借贷平台面客消息中心模块，另有 issue |
| 邮件、短信及其他站外触达 | 各业务模块自持。本模块只做站内消息，不定义、不消费、不承担 |
| **运营人员「发出」公告给用户**（内容编辑、人群圈选、发布撤回、定时） | 独立业务能力「运营公告管理」，属运营端某个业务 issue（3.5.2） |
| 待办的认领、转派、审核流程、对账流程本身 | 各业务 issue |

### 3.5 本期取舍

#### 3.5.1 通知偏好 / 订阅开关：本期不实现（`D-O11`）

沿用基线。运营端的消息几乎全部是工作性质——审核待办、运营告警、系统状态、资金对账，这些按共用契约的分类口径属**不可退订**。运营人员能关掉审核待办通知，等于允许他关掉自己的工作提醒。**本期不提供任何偏好或订阅界面**；退订能力的最小粒度为消息分类，承载已在共用契约中留位。对展示层的影响为零。

#### 3.5.2 运营公告的「发」与「收」：本模块只做「收」（`D-O10`）

| 项 | 内容 |
| --- | --- |
| 本期结论 | **不实现面向全平台用户的广播发布能力**，等「运营公告管理」业务 issue 立项 |
| 边界三条 | ① 本模块只做「运营人员**收到**消息」这一层；② 「运营人员**发出**公告给用户」是独立业务能力，不属于本模块；③ 两者是标准接入关系——运营公告模块作为接入方提交消息，本模块负责投递与展示 |
| 承载 | 共用契约已确认现有承载不挡住广播（一条消息多个接收者、已读只记读过的人、受众起算点、无跳转合法），**本模块不需要重做这份确认** |

#### 3.5.3 消息保留与清理：不设保留期，但提前列入监控（`D-O12`）

本期不设保留期、不清理、不归档，消息长期保留，已过期消息仍可查。**运营端是本平台业务的汇聚点**，消息增速高于面客单业务线，因此额外要求两条：① 列表与未读提示的响应时延**上线即纳入监控**；② 归档策略提前写成可调参数 `N-O07`（保留 365 天后归档、安全与合规类不参与、归档指不在默认列表展示但可筛选查到，**不是物理删除**），本期不启用。

| **WS-357 运营端账户与登录**（已入库） | **强依赖，本模块引用它** | 账号主体与账号状态、**角色与功能权限矩阵**（含消息查看权限项 `PM-AL-12`）、会话有效期与全局失效口径、顶栏与账号下拉的挂载位、国际化与脱敏基线的引用方。**本模块不自造运营端角色模型，也不自造权限项** |
| **WS-357（作为触发方）** | **本模块是它的展示层** | 它定义密码变更类站内消息「发什么、何时发」（其 `D-AL-26`），怎么展示归本模块；它同时明确了哪些事件**不产生**通知（其 `D-AL-27`），本模块不替它补 |

| **L10 已裁定的对外页面编号形态** | **本模块沿用，不另造** | 本平台对外使用的页面编号带平台标识（其 `D-NC-03`～`D-NC-05`，作为跨平台契约册的输入）。本端消息的静态页面目标按同一形态表达，**本模块不在本平台内起第二种形态**（6.3） |
| **代币发行平台运营端消息通知** | **平行实例，互不承接** | 另一套消息池、另一套编号段位。两端之间**不共享消息、不合并未读、不提供跨端查看入口** |
| 借贷平台运营端各业务 issue | **它们是接入方** | 按共用契约的接入指南自助接入，登记业务类型、跳转目标与预检。**接入不需要修改本 PRD** |

## 5. 业务角色与场景

### 5.1 业务角色（`D-O26`）

**运营端只有一套运营账号体系**（WS-357 `D-AL-03`～`D-AL-06`，需求方 2026-09-18 确认）：SPV 机构与运营机构是同一家主体，账号由平台创建或邀请开通，**不做机构级数据隔离**，SPV 相关职责按职能落在运营人员的**功能权限项**上。因此**本模块不按机构主体切分消息可见范围，也不设 SPV 专属消息池**。

## 6. 通用可见范围与权限（**强制条款**）

> **本章是本 PRD 必须自己写的部分**——可见范围是这一端特有的业务口径，不能靠引用解决。**校验机制本身沿用共用契约，本章写的是它在借贷运营端的落地口径与可验收结果。**

### 6.1 总纲

| 项 | 规则 |
| --- | --- |
| 准入 | 由 WS-357 的功能权限项 **`PM-AL-12`「运营端消息查看」**决定；**本模块不新增模块级权限项**。未持有该权限项时，铃铛与「消息中心」入口不出现，直接访问也不可用（按 WS-357 的权限拒绝口径处置） |
| 可见集 | 一个持有 `PM-AL-12` 的账号，其可见集 = 「本端面向全体运营人员的消息」∪「发给本账号的个人消息」，**不含任何其他端的消息**；**不按机构主体、不按岗位再切分** |
| 已读 | **按账号独立**：一个人已读不改变他人的未读 |
| 未读数 | 按账号各自计算，**只统计本端可见集内的未读** |
| 消息本身 | 不因任何人的已读而消失、归档或从列表移除 |
| 新账号 | 账号创建时间之前的消息**可见但不计未读** |
| 「谁读过这条」 | **不在任何界面展示**。没有认领机制时，A 读过不代表 A 在处理 |

### 6.2 两类可见范围（`D-O03`、`D-O26`）

| 类别 | 典型内容 | 谁可见 | 未读计入 |
| --- | --- | --- | --- |
| **面向全体运营人员** | 审核待办、运营告警、系统状态、资金对账 | 全部**持有 `PM-AL-12` 的运营账号**，不区分预置角色，也不区分是否承担 SPV 职责 | 各自计入 |
| **面向某一个人** | 本人的密码变更通知等只与本人有关的事件（触发方与触发时点归 WS-357 `D-AL-26`） | **仅该账号本人** | 仅本人 |

> **本期没有第三类**：需求方已确认 SPV 机构与运营机构是同一家主体，运营端**不做机构级数据隔离**（WS-357 `D-AL-05`），因此**不存在「面向某机构主体」的可见范围**，界面上也不出现按机构筛选消息的能力。若将来确有机构维度的诉求，按下面的扩展路径处理，**不在本模块单开一套**。

**怎么判断该用哪一类**（与具体是哪个模块的哪个事件无关）：这件事**任何一个运营人员都可以去处理**吗 → 面向全体；只跟某个人有关 → 面向个人。**判断错的代价不对称**——错发成「面向全体」会泄漏个人信息并污染所有人的未读数，错发成「面向个人」只是少几个人看到；**拿不准时选范围更小的那个**。

**为什么个人消息必须分开**：把「某运营人员刚改了密码」推给全体，既泄漏了同事的账号安全动作，又会让每个人的未读数被与自己无关的事件污染。

**为什么本期不按角色或岗位把全员池切开**（`D-O04`）：共享可见的失败模式是「多人重复看到同一条」——**效率问题**；按角色定向的失败模式是「分给了一个当时没人在岗的角色，没人处理」——**业务事故**。运营端承担审核、对账这类不能漏的工作，且本期不存在认领 / 转派机制（那属于各业务模块的待办能力）。**在没有认领机制的前提下收窄可见范围，等于把「漏处理」的风险提前引入。**

**将来要收窄时的扩展路径**（`D-O06`）：一律**新增一类接收方范围**（例如按角色或按机构主体定向），**绝不改写「面向全体」的既有语义**——该语义已被其他端引用，改语义会污染已定稿的口径。改动落在可见集计算、查询条件与越权判定三处，**展示层零改动**；若届时引入机构维度，账号侧的主体归属仍以 WS-357 为准，**本模块不自造**。

### 6.3 按端隔离（`D-O07`、`D-O27`，**本轮主改造点，强制条款**）

| 项 | 规则 |
| --- | --- |
| **一端一池** | 借贷运营端有**自己独立的消息池**。原来由单一运营端池承载的内容，按端拆分为**借贷运营端**与**代币发行运营端**两个池，互不混用 |
| **只呈现本端消息** | 本端的列表、快捷面板、详情、筛选结果**只包含属于本端的消息**。任何入口、任何参数、任何构造方式下**都不得读到另一端的消息**——包括**代币发行平台运营端**、**本平台面客端消息中心（L10）**以及其他平台的任何消息池 |
| **异常数据不兼容展示** | 若因故障或数据错误，池中出现不属于本端的记录：**不渲染、不计入未读、不可经详情深链打开**，并记录一次数据异常。**不做兼容展示、不做降级展示**（与 L10 `D-NC-13` 同口径） |
| **未读只统计本端** | 未读数只统计本端可见集内的未读，**不合并、不汇总其他端的未读** |
| **不提供跨端入口** | 运营端界面**不提供**任何查看其他端消息的入口；排障诉求走后台审计流程，不走界面 |
| **跨端事件由触发方各发一条** | 需要两端都知晓的事件，由触发方**分别产出两条消息**，各进各自的池。**不存在一条消息同时投递两端，也不存在消息在两端之间转发** |
| **端标识是契约层的事** | 原来一个运营端标识现在要能区分出借贷运营端与代币发行运营端，**属跨平台契约层的变更**。**本 PRD 只提业务要求，不写取值、格式与报文**；契约册尚未成立期间，本端的业务要求即为上面各条（`Q-O05`） |
| **对外页面编号带平台标识** | 本端消息的静态页面目标须能被唯一解析到「**本平台 + 本端**的某一个页面」。表达形态**沿用本平台 L10 已裁定的「平台标识 + 页面编号」**（其 `D-NC-03`），本模块**不另造第二种形态**；不带平台标识的裸编号在三平台独立后不具唯一性 |
| **账号是否打通不改变结论** | 即使将来两端账号打通，**端隔离优先于账号互通**：一个人在借贷运营端只看到借贷运营端的池，在代币发行运营端只看到那一端的池，**两个入口、两套未读数** |

> **为什么必须隔离到这个程度**：把两端的消息汇进一个铃铛，会让未读数失去可操作性——运营人员看到 12 条未读，其中 7 条要切到另一个平台才能处理。三平台已相互独立部署，一个混合的未读数没有任何一个岗位能对它负责。

### 6.4 越权处置（**强制条款，不可降级**）

**界面不是安全边界。** 以下每一处功能入口都必须**独立判定归属**，不得依赖前端只传自己的标识，也不得依赖上一步已经过滤过：

| # | 功能入口 | 判定内容 | 越权时的结果 |
| --- | --- | --- | --- |
| 1 | **列表取数** | 以**登录身份 × 本端**圈定可见集；**忽略请求中任何形式的接收者标识与端标识** | 不适用（结果集天然受限） |
| 2 | **消息详情** | ① 该消息属于本端；② 该消息在当前账号的可见范围内 | **按「不存在」处置**（见下） |
| 3 | **标记单条已读** | 先判定归属与端，再记已读；**不得只按消息标识写入**。重复标记不报错、不改变首次已读时间 | 按「不存在」处置 |
| 4 | **全部已读** | 范围由服务端按登录身份 + 本端 + 当前筛选自行圈定；**不接受界面传入的消息清单** | 拒绝执行并提示参数不合法 |
| 5 | **未读计数** | 以登录身份 + 本端统计；对该入口做频次限制，防止被当作探活手段滥用 | 不适用 |
| 6 | **跳转可达性判定** | ① 判定消息归属与端；② 判定该账号对**目标业务资源**的访问权限（后者由业务方的预检负责） | 消息不属于本人 → 按「不存在」处置；消息属于本人但目标无权 → 归入「无权限」失效（分册 `01` 12.6.4） |

**越权一律按「不存在」处置（`D-O28`）**：

> 访问不属于自己的消息时，**界面表现必须与「该消息本来就不存在」完全一致，使用者不可区分**。**不得给出「无权限」这类提示**——它会泄漏「这条消息确实存在」这一事实，可被用来探测系统内的消息规模与分布。

| 场景 | 界面表现 |
| --- | --- |
| 消息标识不存在 | 「消息不存在」页 + 「返回消息中心」 |
| 消息存在但**属于另一端** | **与上一行完全一致，不可区分** |
| 消息存在但属于他人（面向个人的消息） | **与上一行完全一致，不可区分** |
| 未登录访问详情深链 | 跳登录页并携带原路径，登录后回跳（6.5） |

> **功能权限缺失与消息归属越权是两件事，处置口径不同**：未持有 `PM-AL-12` 属**账号授权层**，按 WS-357 的权限拒绝与入口收敛口径处置（其 `D-AL-11`、`F-AL-17`），**本模块不另造一套**；上表的「按不存在处置」只针对**持有权限但去取不属于自己、或不属于本端的消息**，该条不可降级。

**其他强制要求**：

| 项 | 要求 |
| --- | --- |
| 消息标识 | **不可枚举**（不使用连续序号），避免被遍历探测 |
| 批量取数 | **不提供**「按标识清单批量取消息」的能力；若后续需要，必须逐条判定归属，且**部分越权时整体拒绝**，不做部分返回 |
| 越权记录 | 越权访问须记入安全审计，**不在任何前台界面展示**，按合规流程调阅；字段脱敏遵循三平台共享基线的脱敏口径 |
| 跳转目标的端一致性 | **拒收**「跳转目标页面所属端与消息所属端不一致」的消息（6.3、分册 `01` 12.6.1） |

### 6.5 未登录与会话失效下的表现

> 会话规则本身（有效期、无操作超时、全局失效的触发场景、跳转与提示、多标签页同步）由 **WS-357** 定义（其 `D-AL-19`、`D-AL-20`），本节**不重复定义**，只说明消息模块在这些状态下的表现。

| 场景 | 表现 |
| --- | --- |
| 未登录访问消息中心或消息详情深链 | 跳运营端登录页并携带原路径，登录成功后**回跳原页面**；登录前**不泄漏任何消息内容，也不泄漏该消息是否存在** |
| 深链登录后消息不属于该账号 | 落到「消息不存在」页，**不提示「你登错账号了」**（同样会泄漏消息归属） |
| 停留在消息模块内会话失效 | 按 WS-357 的统一失效处理：清除登录态 → **中止进行中的请求（含未读提示的后台刷新）** → 提示 → 跳登录页并携带原路径 |
| 「全部已读」执行中会话失效 | **不展示「操作成功」**；重新登录后未读数**以服务端结果为准**，界面不做假设 |
| 未读提示的后台刷新遇到登录态失效 | 与其他请求一视同仁，触发统一的失效处理。**不得静默忽略**——否则会出现「页面还在、未读还在刷、但登录态其实已经没了」的假活状态 |
| **后台刷新是否算「用户操作」** | **不算**（`D-O08`）。未读提示的后台刷新**不得**被计入无操作超时判定，否则无操作自动登出将永远不会触发。**该口径已被 WS-357 采纳为其自身条款**（其 `F-AL-12`），两处一致 |
| 账号被停用 / 本人改密 / 被重置密码 | 该账号全部会话立即失效（WS-357 `D-AL-20`），本模块随之不可达；提示文案走 WS-357 |

### 6.6 数据可见范围汇总

| 数据 | 谁可见 |
| --- | --- |
| 本端面向全体运营人员的消息 | 全部持有 `PM-AL-12` 的运营账号（**不区分预置角色，也不区分是否承担 SPV 职责**） |
| 按机构主体划分的消息 | **本期不存在**：运营端不做机构级数据隔离（WS-357 `D-AL-05`） |
| 面向个人的消息 | **仅该账号本人** |
| 某账号的已读状态与未读数 | **仅本人**（界面不展示「谁读过这条」） |
| **代币发行运营端及其他端的任何消息** | **本端不可见**，界面不提供任何跨端查看入口 |
| 消息中引用的业务资源详情 | 由目标业务模块的权限规则决定，**本模块不放宽** |
| 越权访问记录 | 不在前台展示，按合规流程调阅 |

## 7. 信息架构

### 7.1 页面与组件清单

**页面**

| 编号 | 页面 | 形态 | 说明 |
| --- | --- | --- | --- |
| **P-O20** | 运营端消息中心 | 整页 | 完整列表、分类与已读筛选、**分页器**、全部已读 |
| **P-O21** | 运营端消息详情 | 整页 | 单条消息的完整内容与跳转操作，**支持深链** |

> **页面地址**：两个页面各有**独立地址**，详情页**支持深链**；未登录访问时跳运营端登录页并携带原路径，登录后回跳（6.5）。**具体路径与路由前缀遵循运营端的统一路由规范，本文不自造**——WS-357 未定义路径取值，本模块只要求「地址独立 + 深链可回跳」这一业务结果。

**组件**

| 编号 | 组件 | 说明 |
| --- | --- | --- |
| **C-O20** | 通知铃铛 | 挂在 WS-357 已预留的顶栏挂载位：**语言切换器 `C-O-AL-02` 左侧、账号下拉 `C-O-AL-04` 之前**；铃铛本体承载未读提示 |
| **C-O21** | 铃铛快捷面板 | 点击铃铛展开的下拉面板，展示最近 `N-O02`（默认 10）条消息摘要，底部「查看全部」进入消息中心 |
| **C-O22** | 消息列表项 | 列表行组件。本端**只用通用型变体**，不用进度型变体（分册 `01` 12.7） |
| **C-O23** | 失效说明条 | 详情页内的失效原因说明条，四种失效原因对应四套文案 |

> 顶栏的语言切换器 `C-O-AL-02`、账号下拉 `C-O-AL-04` 与面包屑 `C-O-AL-03` 由 **WS-357** 定义并提供（其 `01` 9.1 已把铃铛与「消息中心」条目留为本模块的挂载位），本模块只**挂载**，**不定义宿主组件本身**。

### 7.2 两个入口与落点（`D-O13`）

| 入口 | 位置 | 点击落点 | 理由 |
| --- | --- | --- | --- |
| **通知铃铛 C-O20** | 顶部导航栏右侧，语言切换器 `C-O-AL-02` 左侧、账号下拉 `C-O-AL-04` 之前 | **展开快捷面板 C-O21**，不直接跳页 | 铃铛是高频轻量的查看入口，多数情况只想确认「是什么事」，直接跳整页会打断当前任务 |
| **账号下拉 →「消息中心」** | 右上角账号下拉 `C-O-AL-04` 内，「账户设置」之上（位置由 WS-357 预留，条目由本模块挂载） | **直达 P-O20**，不带筛选条件 | 从账户菜单进入代表要「集中处理消息」，直达整页符合预期 |
| 快捷面板底部「查看全部」 | 面板底部 | 进入 P-O20，不带筛选条件 | — |
| 快捷面板内单条消息 | 面板内 | 进入 P-O21 详情 | 与列表点击行为一致，两个入口交互心智统一 |

> **两个入口共用同一份数据与同一份已读状态**：任一处的已读在另一处立即生效。**不得为快捷面板另建一套本地已读**。
>
> **两个入口都随权限收敛**：未持有 `PM-AL-12` 的账号，顶栏不出现铃铛、账号下拉不出现「消息中心」条目；权限被收回后入口在下一次进入时消失（WS-357 `D-AL-11`、`F-AL-17`）。
>
> **不新增左侧菜单一级入口**（`D-O05`）：消息中心属账户维度功能，入口收敛在铃铛与账号下拉。运营端待办的主入口应当是各业务模块自己的列表页（它们有筛选、批量操作、认领这些消息中心给不了的能力）；把消息中心提到一级菜单会造成「两个待办入口」，用户不知道该以哪个为准。**消息中心是通知汇总，不是工作队列。**

### 7.3 页面流与状态

页面流、消息从产生到被消费的主流程、全部已读流程、跳转与四类失效的分支，以及消息可用性状态机与单人已读状态机，**集中在图册** [`v1.0-运营端消息通知-流程图与状态机.md`](v1.0-运营端消息通知-流程图与状态机.md)：`FL-O01`～`FL-O04`、`ST-O01`～`ST-O02`。本册与分册 `01` 在对应位置直接引用图号，不重复嵌图。

## 9. 非功能要求与依赖

### 9.1 时效目标（沿用基线取值，均为**目标值**）

| 场景 | 目标值 |
| --- | --- |
| 未读计数返回 | P95 < 300ms |
| 列表首屏（20 条） | P95 < 1s |
| 铃铛面板展开到内容可见（10 条） | P95 < 800ms |
| 详情加载 | P95 < 800ms |
| 全部已读（1000 条内） | P95 < 2s；超过时可先返回结果，界面以下一次刷新对账 |
| 跳转可达性判定 | P95 < 500ms；超时（`N-O05`，默认 3 秒）按判定失败处理并**放行跳转** |
| 页面不在前台时的未读刷新开销 | **为 0** |

> 以上为目标值，需在联调与灰度阶段校准，**不影响功能逻辑与验收通过与否**；但**上线即纳入监控**（3.5.3、`AC-O65`）。

### 9.2 安全与内容

| 项 | 要求 |
| --- | --- |
| 归属校验 | 六处功能入口全部独立判定，**按「账号 × 端」**，越权按「不存在」处置（6.4） |
| 消息标识 | 不可枚举 |
| **内容渲染** | 标题、正文与参数一律按**纯文本**渲染并转义，**不支持富文本与外链自动识别**。运营端消息的内容部分来自业务侧提交的原文（如申请说明、审核意见），富文本渲染会直接构成注入入口 |
| 参数脱敏 | 完整邮箱、完整钱包地址、完整 IP、证件号码**不得进入消息参数**，由**触发方**脱敏后传入；脱敏清单以**三平台共享国际化与展示基线**为准（WS-357 `D-AL-18` 的同一引用源，落盘位置见 `Q-O06`）。账号主体标识可传（不可枚举、本身不含个人信息），但**不得在界面上展示原值** |
| 深链 | 登录前不得泄漏任何消息内容或消息是否存在 |
| 审计 | 越权访问与全部已读操作记入安全审计；保留期遵循 WS-357 的审计口径 |
| **跨端与跨平台数据** | 本端消息**不含**其他平台或面客用户的敏感个人信息明文；需要查看时跳转到对应业务详情页，由该页的权限与审计规则约束 |

### 9.6 风险

| # | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| 1 | 跨平台契约册未成立期间，两个运营端的消息归属无处登记 | 消息可能被投到错误的端，或本端收到不属于自己的消息 | 6.3 已把业务要求写死并配可验收条款（`AC-O97`～`AC-O100`）；异常数据按「不呈现、不计未读、不可深链打开并记录一次异常」处置；**本 PRD 不自造取值** |
| 2 | 有人按 WS-357 原描述的「运营人员 + SPV 机构两类角色」来实现消息可见范围 | 凭空多出一套机构级隔离，与已定案口径冲突 | 6.2 已写死：**本期只有两类可见范围、不做机构级隔离**（WS-357 `D-AL-05`、`D-AL-13`）；`AC-O103` 直接验收「不存在按机构主体切分的可见范围」 |
| 3 | **两端撞号** | 跳转目标无法唯一反查出端归属，消息跳到另一个平台 | 2.2 已写死段位纪律：本平台沿用原段位，代币发行运营端另行申请 |
| 4 | 消息量增速高于面客单业务线 | 列表与未读查询变慢 | **上线即监控**（`AC-O65`）；出现退化趋势时启用 `N-O07` 归档策略（**不是物理删除**） |
| 5 | 跳转目标登记依赖各业务 issue | 用户看到消息但跳不过去 | 降级表现已明确定义（分册 `01` 12.6.3），**不会出错页**；统计「未知业务类型」作为推动补齐的依据 |
| 6 | 触发方各自定义文案，风格参差 | 同一个列表里消息质量不一 | 契约要求文案模板 + 参数，便于集中审校 |
| 7 | 未读提示存在最长 `N-O01` 的滞后 | 待办可能晚看到 | 本期不调小（理由见分册 `01` 12.1.3）；它是**可调参数**，改一个数即可 |
| 8 | 共享可见 + 个人已读，已读记录随人数线性增长 | 数据量上升 | 本期运营账号数量有限，风险可接受；未读起算点已避免为历史消息全量生成记录 |
| 9 | 「全部已读」不可撤销 | 在运营端等于丢失待办提示 | 二次确认 + 明确说明作用范围与条数，**不得省略**（分册 `01` 12.5.2） |
| 10 | 运营端将来会成为「运营公告」的发起端 | 有人误以为公告发布属于本模块 | 3.5.2 已把边界写死：本模块只做「收」 |

## 10. 已确认口径与可调参数

### 10.1 已确认口径

| 编号 | 口径 | 结论 |
| --- | --- | --- |
| D-O01 | 本 PRD 的范围 | **只做借贷平台运营端**：通用可见范围 + 展示层 + 验收。不含面客端；不定义任何触发口径与具体文案；不重写数据契约与接入指南 |
| D-O02 | 与共用契约的关系 | **本模块是消费端，不是平台通用规则的定义方**；不自定义契约里不存在的字段或取值 |
| D-O03 | 可见范围 | **两类**：面向全体运营人员 / 面向个人；已读个人独立；**本期不存在按机构主体划分的第三类**（6.2） |
| D-O04 | 按角色定向 | **本期不做**运营人员内部的角色或岗位切池；理由见 6.2（无认领机制时定向的失败模式是业务事故） |
| D-O05 | 左侧菜单 | **不新增消息中心一级入口**，入口收敛在铃铛与账号下拉（7.2） |
| D-O06 | 将来引入更细角色时的承接方式 | **一律新增一类接收方范围，绝不改写「面向全体」的既有语义**；展示层零改动 |
| D-O07 | 消息池隔离 | **按端严格隔离**，借贷运营端与代币发行运营端**两池不混**；归属判定按「账号 × 端」；**端隔离优先于账号互通**（6.3） |
| D-O08 | 后台刷新与无操作登出 | 未读提示的后台刷新**不得被计为「用户操作」**（6.5）；该口径已被 WS-357 `F-AL-12` 采纳，两处一致 |
| D-O09 | 广播 | **本期不实现**；等「运营公告管理」业务 issue 立项。承载已就绪（3.5.2） |
| D-O10 | 公告的「发」与「收」 | **本模块只做「收」**，发布能力属独立业务 issue，两者是标准接入关系 |
| D-O11 | 通知偏好 / 订阅 | **本期不实现**；退订最小粒度为分类，安全 / 账户 / 合规类永不可退订（3.5.1） |
| D-O12 | 保留与清理 | **本期不设保留期、不清理、不归档**；但**上线即监控**，归档策略提前写为 `N-O07`（3.5.3） |
| D-O13 | 两个入口的落点 | 铃铛**展开面板**（不直接跳页）；账号下拉**直达整页**；两者共用同一数据与同一已读（7.2） |
| D-O14 | 分页形态 | **分页器**（页码 + 每页条数 20/50/100），不用「加载更多」。运营端属管理端形态，存在「跳到某一页复查」的诉求 |
| D-O15 | 未读计数口径 | 服务端计算；全分类合计、不分类；**已过期与已主动失效的不计入**；上限展示 `99+` |
| D-O16 | 未读提示的刷新 | 沿用基线既定方案：**定时刷新（默认 60 秒）+ 切回前台立即刷新 + 页面不可见时停止**，本期不引入长连接。**实现机制不在本文展开** |
| D-O17 | 列表排序 | 时间倒序；**已读状态不参与排序**，标记已读后行位置不变 |
| D-O18 | 单条已读的触发 | **打开详情即已读**（内容渲染成功后）**并**在列表行内提供显式「标为已读」；仅展开面板或滚动不产生已读 |
| D-O19 | 全部已读的作用范围 | **当前筛选命中的全部消息**（不限当前页，也不是全库无差别）；执行前二次确认并说明条数与筛选 |
| D-O20 | 跳转与失效 | 三形态互斥，**消息不存地址**；**映射缺失与无跳转都不渲染按钮、且都不给说明文案**；四类失效**禁用而非隐藏**（已过期不渲染按钮），且均完整展示消息内容 |
| D-O21 | 默认语言与时区 | 以**三平台共享国际化与展示基线**为准（WS-357 `D-AL-18` 同源）：界面默认英文、不读浏览器语言、中英可切换、切换即时生效；时间存 UTC、展示带时区标注，时区按账号偏好。本文**只引用不复制**（`Q-O06`） |
| D-O22 | 文案回落 | 回落到**该端的默认语言**，不硬编码某一种语言；**任何情况下不展示文案键名** |
| D-O23 | 国际化与脱敏基线的归属 | **引用三平台共享基线**（与 WS-357 同一引用源），不在本模块复制正文、不跨平台另引一份 |
| D-O24 | 本端编号段位 | 页面 `P-O20` 起、组件 `C-O20` 起，**沿用不迁号**；登记在共用契约的段位表，本 PRD 不另维护（2.2） |
| **D-O25** | **拆端后的段位纪律** | **本平台沿用原段位；代币发行运营端另行申请新段位，不得复用 `P-O2x` / `C-O2x`**（2.2） |
| **D-O26** | **SPV 职责与消息可见范围** | 需求方 2026-09-18 确认 **SPV 机构与运营机构是同一家主体**（WS-357 `D-AL-03`～`D-AL-06`、`D-AL-13`）：只有一套运营账号体系、**不做机构级数据隔离**，SPV 职责落在功能权限项上。因此本模块**不设 SPV 专属消息池、不按机构主体切分可见范围**；消息功能的准入由 `PM-AL-12` 决定（6.1、6.2）。**本模块不自造运营端角色模型** |
| **D-O27** | **按端隔离拆池** | 原单一运营端池按端拆为**借贷运营端**与**代币发行运营端**两池；本端只呈现本端消息、未读只统计本端、**任何情况下不得读到另一端的池**；跨端事件由触发方各发一条（6.3） |
| **D-O28** | **越权处置** | 越权与不存在**表现完全一致、不可区分**；**不得给出「无权限」提示**（6.4） |
