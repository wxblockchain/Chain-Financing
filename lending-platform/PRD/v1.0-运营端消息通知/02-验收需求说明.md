> 入口与全文导航见主册 [`v1.0-运营端消息通知-PRD.md`](v1.0-运营端消息通知-PRD.md)；功能规则见 [`01-功能需求说明.md`](01-功能需求说明.md)；流程图与状态机见 [`v1.0-运营端消息通知-流程图与状态机.md`](v1.0-运营端消息通知-流程图与状态机.md)。

**本册讲什么**：本模块的全部验收要求 `AC-O01`～`AC-O104`，按与功能需求**相同的模块顺序与相同的需求编号**组织。

**三条使用说明**：

1. **规则的唯一来源是主册与分册 `01`**，本册只列**判定口径与预期结果**，不重复论证规则，也不代写测试执行用例。
2. **本册不验收任何触发口径**——不会出现「某某操作后应发某某消息」这类条目。本端有哪些消息、什么时点发、文案怎么写，由各业务 issue 在自己的 PRD 里验收。
3. **本册不重复验收数据契约本身**（字段必填性、去重键构造、业务类型命名规范由共用契约侧验收）。这里只验收**契约在本端的落地结果**。

## 13. 验收要求

### 13.1 入口与未读提示（`F-O01`～`F-O05`）

| # | 验收项 |
| --- | --- |
| AC-O01 | 已登录且持有 `PM-AL-12` 的账号，在运营端**任意页面**顶部导航栏均展示通知铃铛 `C-O20`，位置固定；未登录页面不展示铃铛 |
| AC-O02 | 铃铛位于**语言切换器 `C-O-AL-02` 左侧、账号下拉 `C-O-AL-04` 之前**，位置在所有页面一致且可预期 |
| AC-O03 | 无未读时铃铛不展示计数，**也不展示 `0`** |
| AC-O04 | 有未读时计数与服务端口径一致；超过 99 时展示 `99+`，且该状态下不展示精确数字 |
| AC-O05 | **已过期的未读消息不计入未读数**，但仍能在列表中看到并带「已过期」标签 |
| AC-O06 | 「目标资源已删除 / 状态已流转 / 无权限」三类跳转失效的未读消息**仍然计入未读数** |
| AC-O07 | 账号下拉 `C-O-AL-04` 内存在「消息中心」条目且排在「账户设置」之上，点击**直达 `P-O20`**（不经快捷面板、不带筛选条件） |
| AC-O08 | 点击铃铛展开快捷面板 `C-O21`，展示最近 **10 条（含已读）**；再次点击铃铛、点击面板外、按 Esc、点击面板内关闭按钮均可收起，收起后焦点回到铃铛 |
| AC-O09 | 快捷面板**仅展开不产生任何已读**；滚动经过也不产生已读；点击面板内某条进入详情后该条才变已读 |
| AC-O10 | 页面切到后台时未读提示**停止刷新**；切回前台**立即刷新一次**；刷新失败时**保留上一次数值**，不清零、不弹错误提示 |

### 13.2 列表、筛选与分页（`F-O06`～`F-O09`）

| # | 验收项 |
| --- | --- |
| AC-O11 | 分类筛选项由服务端返回的分类元数据渲染，**界面中不存在写死的分类清单** |
| AC-O12 | **只渲染当前账号实际拥有消息的分类**，不展示必然为空的筛选项 |
| AC-O13 | 分类筛选与已读 / 未读筛选**可叠加**，结果为两者的「与」关系；状态筛选三档为 全部 / 未读 / 已读，默认「全部」 |
| AC-O14 | 筛选与分页状态在**页面地址中保持**，刷新后不丢失；切换筛选时回到第 1 页且滚动位置回到顶部 |
| AC-O15 | 列表按时间**倒序**；标记某条已读后该行**位置不变、不被移除**（未读不置顶、已读不沉底） |
| AC-O16 | 同一时间的多条消息有稳定的次级顺序，翻页时**不重复、不漏项** |
| AC-O17 | 分页形态为**分页器**（页码 + 每页条数），**不是「加载更多」**；每页默认 20，可切换 **20 / 50 / 100**，切换后回到第 1 页 |
| AC-O18 | 翻页期间有新消息产生时，**不出现重复项或漏项** |
| AC-O19 | **首次空态与筛选空态文案不同**，且筛选空态提供「清除筛选」并可一键回到无筛选状态 |
| AC-O20 | 首屏失败展示错误态与重试；**翻页失败时当前页已加载内容不清空**，可重试 |
| AC-O21 | 单条内容异常（如文案缺失）时该行降级为最小形态，**不影响同页其他行**，且仍可点击进入详情 |

### 13.3 详情与已读（`F-O10`～`F-O13`）

| # | 验收项 |
| --- | --- |
| AC-O22 | 消息详情为**整页 + 独立地址**，支持深链直接打开；不使用抽屉或弹窗 |
| AC-O23 | 详情页时间**一律绝对时间 + 时区标注**；列表时间为 24 小时内相对时间、超过则绝对时间 |
| AC-O24 | 详情正文按**纯文本渲染并转义**：提交含标签的正文或参数时，页面上原样显示为文本，**不被解析执行** |
| AC-O25 | 已读标记在**详情内容取数成功并渲染之后**才发生；详情加载失败时**不产生任何已读记录** |
| AC-O26 | 已读标记失败时**不阻断详情阅读**、不弹错误；重复标记同一条消息不报错，**首次已读时间不被覆盖** |
| AC-O27 | 列表行悬浮出现「标为已读」，点击后**不进入详情**即就地标记；已读项不再展示该按钮 |
| AC-O28 | 界面上**不存在**「标为未读」的手动操作入口 |
| AC-O29 | 从详情返回列表（面包屑上级 / 「返回列表」/ 浏览器后退，三者行为一致）后，**保留筛选、页码、每页条数与滚动位置**，不跳回第 1 页 |
| AC-O30 | 返回列表后刚读过的那条**就地变为已读样式**，不重排、不移除；在「只看未读」筛选下该条**仍留在列表中**，直到主动刷新或切换筛选才消失 |
| AC-O31 | 「全部标为已读」作用于**当前筛选命中的全部消息**：当前页显示 20 条、实际命中 300 条时，执行后 300 条全部变已读，**不是只标记当前页** |
| AC-O32 | 「全部标为已读」**必须二次确认**，弹窗内**明确展示条数**，并展示当前筛选（无筛选时显示为「全部分类 · 全部」）；默认焦点在「取消」 |
| AC-O33 | 「全部标为已读」失败时**列表与未读数不做任何变更**，可重试；当前筛选下无未读时按钮禁用并说明原因 |

### 13.4 跳转与失效（`F-O14`、`F-O15`）

| # | 验收项 |
| --- | --- |
| AC-O34 | 消息中**不存放任何页面地址**；跳转路径在展示时按业务类型或页面编号解析得到 |
| AC-O35 | 三种跳转形态**互斥**：同时携带业务资源目标与静态页面目标的消息被**拒收** |
| AC-O36 | **「无跳转」是合法状态**：无任何跳转目标的消息正常展示，详情页不渲染跳转按钮，**且不展示任何说明文案**；与 `AC-O37` 的界面表现**完全一致**，差别只在后台是否记录 |
| AC-O37 | **登记缺失**（携带业务类型但前端无对应登记）时：详情页**不渲染跳转按钮**、**不展示任何说明文案**（操作区只剩「返回列表」），并记录一次「未知业务类型」；消息在列表与面板中**正常展示、可进详情、不被分类筛选过滤掉** |
| AC-O38 | 登记缺失时**不出现**以下任何一种：跳错误页、跳首页、展示点了没反应的按钮、隐藏整条消息 |
| AC-O39 | 静态页面目标**不做可达性判定**，直接跳转；业务资源目标是否判定由业务类型登记声明，默认「需要判定」 |
| AC-O40 | 可达性判定在**进入详情页时执行一次**（不是点击时才执行）；**列表页不做任何判定** |
| AC-O41 | 判定失败或超时（3 秒）时**放行跳转**，按钮保持可用，由目标页自行处理 |
| AC-O42 | 四类失效各有**独立文案**（不使用一句笼统的「该消息已失效」）；已过期的跳转按钮**不渲染**，其余三类**按钮禁用而非隐藏**，且禁用原因**对键盘与读屏用户可达** |
| AC-O43 | 四类失效下消息的**标题、正文、时间均完整展示**，消息不被删除、不被隐藏；`C-O23` 为浅底信息条、不可关闭、**不使用错误红色** |

### 13.5 可见范围与越权处置（`F-O16`、`F-O17`，**强制条款，不可降级**）

| # | 验收项 |
| --- | --- |
| AC-O44 | 列表取数**忽略请求中任何形式的接收者标识与端标识**，只按登录身份 + 本端圈定可见集 |
| AC-O45 | 本端**只呈现属于本端的消息**；构造任何形式的请求尝试取回其他端（含**代币发行运营端**）的消息均不成功 |
| AC-O46 | 用他人个人消息的标识访问详情，界面表现与「消息不存在」**完全一致，无法区分** |
| AC-O47 | 用不属于本端的消息标识访问详情，同样按「不存在」处置，且与上一条**不可区分** |
| AC-O48 | 用他人消息标识标记已读被拒绝，且**不产生任何已读记录** |
| AC-O49 | 「全部已读」**不接受界面传入的消息清单**，范围由服务端按登录身份 + 本端 + 当前筛选圈定；传入清单时按参数不合法处理 |
| AC-O50 | 跳转可达性判定**同时判定**消息归属与目标资源的业务权限；消息不属于本人 → 按「不存在」处置，消息属于本人但目标无权 → 归入「无权限」失效 |
| AC-O51 | **运营人员 A 读一条面向全体的消息后，B 的未读数不变**，该消息对 B 仍是未读且仍在列表中；A 执行「全部已读」同样不影响 B |
| AC-O52 | 面向个人的消息**只对该账号本人可见**：其他账号的列表中不出现该条，未读数不包含该条，直接访问其标识按「不存在」处置。（本期唯一已定义的个人消息来源是 WS-357 的密码变更通知，其 `D-AL-26`） |
| AC-O53 | 新建账号首次登录时，其**创建时间之前**的历史消息**不计入未读**，但仍可在列表中查到 |
| AC-O54 | 界面上**不存在**「谁读过这条消息」的任何展示 |
| AC-O55 | 运营端界面**不存在**任何查看其他端消息的入口 |
| AC-O56 | 消息标识**不可枚举**（非连续序号）；系统**不提供**「按标识清单批量取消息」的能力 |
| AC-O57 | **拒收**跳转目标所属平台或端与消息不一致的消息；本端消息的静态页面目标只能是本端已登记的页面编号，且按本平台已裁定的「平台标识 + 页面编号」形态表达，能被唯一解析到本平台本端的某一个页面 |

### 13.6 会话与登录态（规则归 WS-357 `D-AL-19` / `D-AL-20`，本组只验收本模块的落地表现）

| # | 验收项 |
| --- | --- |
| AC-O58 | 未登录访问消息中心或消息详情深链时，跳**运营端登录页**并携带原路径，登录成功后回跳原页面；**不落到其他平台的登录页** |
| AC-O59 | 未登录访问详情深链时，登录前页面**不泄漏任何消息内容，也不泄漏该消息是否存在** |
| AC-O60 | 深链登录成功后若该消息不属于该账号，落到「消息不存在」页，**不提示「你登录了错误的账号」** |
| AC-O61 | 会话到期、无操作超时，或因改密 / 重置密码 / 账号被停用而全局失效后，停留在消息模块内的页面按 WS-357 的统一失效处理：清除登录态、**中止进行中的请求（含未读提示的后台刷新）**、跳登录页并携带原路径 |
| AC-O62 | 「全部已读」执行中会话失效时**不展示「操作成功」**；重新登录后未读数**以服务端为准** |
| AC-O63 | 未读提示的后台刷新遇到登录态失效时**触发统一失效处理，不被静默忽略**（不出现「页面还在、未读还在刷、但登录态已没了」的假活状态） |
| AC-O64 | 未读提示的后台刷新**不被计入无操作超时判定**：一个只开着消息中心、不做任何操作的标签页，超时后仍会被自动登出 |

### 13.7 非功能、可访问性与监控

| # | 验收项 |
| --- | --- |
| AC-O65 | 列表与未读计数的响应时延**在上线时即已纳入监控**并可查询时间序列，不是等出现退化趋势后才补建 |
| AC-O66 | 时效目标达成：未读计数 P95 < 300ms、列表首屏 P95 < 1s（20 条）、面板展开 P95 < 800ms、详情 P95 < 800ms、全部已读 P95 < 2s（1000 条内）；**页面不在前台时未读刷新开销为 0** |
| AC-O67 | 1280 / 1440 / 1920px 三个断点下无水平溢出，铃铛面板不被导航栏裁切；低于 1280px 时摘要可折行或省略，但**标题、分类标签与时间不得隐藏** |
| AC-O68 | 铃铛、面板内每条消息、列表项、行内「标为已读」、筛选器、分页器、跳转按钮**全部可用键盘到达**并有可见聚焦态；所有图标按钮具备可读名称 |
| AC-O69 | 铃铛面板展开后焦点进入面板、键盘导航限制在面板内，Esc 关闭并把焦点还给铃铛；未读数变化可被读屏播报且**不抢焦点** |
| AC-O70 | 未读状态**不以颜色为唯一提示**（同时使用圆点与字重），且对读屏可感知；尊重系统的减少动效设置 |

### 13.8 通用性与边界

> 本组验收的对象不是某个功能，而是**本模块的通用程度与边界是否守住**。判定方法：拿一个**未在本 PRD 中出现过的虚构运营端业务模块**（如「对账差异处理」）走一遍接入，看是否需要改动本模块。

| # | 验收项 |
| --- | --- |
| AC-O71 | 用一个**虚构的运营端业务模块**走通接入：登记业务类型 → 产出消息 → 列表展示 → 已读 → 跳转 → 失效降级，**全程不修改本模块的任何页面逻辑与 PRD 条款** |
| AC-O72 | 新增一个分类只需登记 + 补齐中英文案，**不需要改动本模块任何页面逻辑**；本期无消息的分类**不出现在筛选器中** |
| AC-O73 | 未登记业务类型的消息仍被**接收、投递、展示与已读**，仅跳转按钮不渲染并记录告警——**不丢消息** |
| AC-O74 | 未读计数按「可见集 − 已读集」计算，对本期两类可见范围结果均正确；**新增一类接收方范围时计数算法不需要改动** |
| AC-O75 | 已读状态为**独立记录，不预生成未读记录**：一条面向全体的消息在所有人均未读时，已读记录数为 **0** |
| AC-O76 | 本 PRD 及其实现中**不存在**任何共用契约里没有的消息字段或取值；其他端既有取值的语义与登记条目**未被本模块改动** |
| AC-O77 | 「面向全体」的既有语义**未被本模块改动**（其他端对该范围的行为与本模块上线前完全一致） |
| AC-O78 | 本 PRD 目录下**不存在**数据契约文件与接入指南文件；两者以显式引用的形式指向共用契约，**仓库内不存在第二份**内容重复的接入指南或登记表 |
| AC-O79 | `P-O20`～`P-O21` 与 `C-O20`～`C-O23` 在共用契约的段位表中已登记；本 PRD 内**不另维护**一张段位表；这六个编号在全平台不与任何其他编号重复 |
| AC-O80 | 本模块**不产生任何邮件 / 短信投递行为**，也不记录站外渠道的送达结果；消息中携带渠道类信息时被**忽略**，不影响该条站内消息的正常投递与展示 |
| AC-O81 | 本端**不产生**业务办理进度类消息，界面上不出现进度类展示；但该分类、进度承载与进度型组件变体**在契约与代码中仍然存在**，未被删除 |
| AC-O82 | 本模块**不提供**任何消息发布 / 人群圈选 / 公告编辑的界面；广播能力本期不实现，但契约中对应的承载**保留未删** |
| AC-O83 | 运营端左侧菜单中**不存在**「消息中心」一级入口 |

### 13.10 按端隔离与准入收敛（**本轮新增，强制条款**）

| # | 验收项 |
| --- | --- |
| AC-O97 | **本端只呈现属于本端的消息**：列表、快捷面板、详情与任何筛选结果中，均不出现代币发行运营端、本平台面客端消息中心或其他端的消息；通过改写请求参数、直接访问标识等任何方式**都取不到另一端的消息**。若因故障导致池中出现不属于本端的记录，**不渲染、不计未读、不可经深链打开**，并记录一次数据异常 |
| AC-O98 | **未读数只统计本端**：代币发行运营端产生任意数量消息时，本端未读数**不发生任何变化**；本端界面不展示任何合并的、跨端的未读汇总 |
| AC-O99 | 用代币发行运营端的消息标识访问本端详情，界面表现与「消息不存在」**完全一致、不可区分**，且**不出现任何「无权限」字样** |
| AC-O100 | 需要两端都知晓的事件由触发方**各产出一条消息**，本端只看到属于本端的那一条；在本端标记已读**不改变另一端那条的已读状态**；两端之间**不存在任何消息转发** |
| AC-O101 | **消息功能的准入随 `PM-AL-12` 收敛**：未持有该权限项的账号，顶栏不出现铃铛、账号下拉不出现「消息中心」条目，直接访问消息中心或消息详情同样不可用（按 WS-357 的权限拒绝口径） |
| AC-O102 | **授权变更当场生效**：收回某账号的 `PM-AL-12` 后，其消息入口在下一次进入时消失且绕过界面直接访问同样被拒；重新授权后入口恢复，未读数以服务端为准，**历史已读状态不丢失** |
| AC-O103 | 运营端**不存在按机构主体切分的消息可见范围**：界面上没有任何「只看本机构」的筛选或视图，两个预置角色（运营管理员 / 运营专员）在**同一份**面向全体的消息上可见范围一致，**承担 SPV 职责与否不改变可见范围**（WS-357 `D-AL-05`、`D-AL-13`） |
| AC-O104 | 本平台运营端页面与组件编号**沿用 `P-O20`～`P-O21` / `C-O20`～`C-O23`，未迁号**；本模块**不占用、不引用**代币发行运营端的任何编号，也不与本平台 L13 的 `P-O-AL-*` / `C-O-AL-*` 相交；携带另一平台或另一端页面编号的消息被**拒收**（与 `AC-O57` 同源） |
