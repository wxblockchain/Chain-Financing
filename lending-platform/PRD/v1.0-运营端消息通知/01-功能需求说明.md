## 12. 模块详情

<a id="entry"></a>
### 12.1 M1 入口与未读提示（F-O01～F-O05）

**目标与前提**：正常登录且已完成首次改密、持有 PM-AL-12 的运营人员，可从本端任一模块获取一致通知。账户、机构审核、质押审核、协议管理、消息页面使用同一当前账户消息和已读结果；各页不各造一份独立未读。无消息权限时入口隐藏，深链拒绝；目标业务权限另判。

**入口与账户信息**：铃铛打开最近预览；账户菜单“消息中心”直接打开无筛选的 P-O20，不先经过预览，不新增侧栏一级菜单。顶栏显示本人当前工作邮箱；悬浮菜单显示真实角色，管理员为“管理员”，专员为其实际角色，中英对应。菜单支持键盘访问。本人邮箱是身份展示，不因消息正文的私人信息限制被错误隐藏；其他人的完整邮箱不展示。

**计数**：只统计本端、本账户可见、仍有效、未读的消息；不受当前分类或列表筛选影响。没有未读不显示数字 0；1～99 显示真实数，超过显示 99+。已过期、来源主动失效、账户创建前的全体历史不计入；目标删除、无权限或任务已经处理本身不等于消息失效，仍按消息真实有效性与阅读状态计数。

**一致性**：前台按 N-O01（60 秒）刷新，页面不可见时停止，回到前台立即刷新。当前页成功已读后即时更新；其他模块和同账户标签页同步，最长不超过 60 秒。刷新失败保留最后可信数值，不清零、不反复弹错；登录失效不静默忽略，按 12.11 退出。自动刷新不计用户操作。

**身份变化**：修改邮箱后显示新邮箱，个人消息历史、首次已读和接收归属不变；邮箱只是展示，不能当作新账户。切换或退出账户后不沿用前一人的计数和正文，旧操作的迟到反馈不能更新新账户。账户菜单不新增用户邀请、权限配置或其他人员管理；这些不是本期产品功能。

图示：[FL-O01](v1.0-运营端消息通知-流程图与状态机.md#fl-o01)、[FL-O05](v1.0-运营端消息通知-流程图与状态机.md#fl-o05)。验收 AC-O01～10、58～64、101～103、105～107。

### 12.2 M1 最近消息预览（F-O03）

展示本人本端最近 10 条，包括已读；与列表采用同一消息事实和阅读状态。信息含完整可获得的标题、必要摘要、发生时间、分类与阅读状态。展开、滚动、悬浮不标已读；选择一条进入独立详情，内容成功呈现才已读。“查看全部”进入 P-O20；预览不承载全部已读。

再次点击铃铛、点击外部、Esc 或关闭操作可收起，焦点返回铃铛；打开后焦点进入预览，键盘访问和读屏名称明确。首次无消息给空态；加载失败给重试，不显示为无消息；已有可信内容时失败保留内容。预览打开不改变原业务表单；存在未保存业务内容时服从来源页面离开保护，不用消息入口绕过。

### 12.3 M2 消息中心列表（F-O06～F-O09）

**展示**：P-O20 独立整页，沿已采纳白底分隔行阅读方式，提供标题、摘要、分类、时间和已读/未读状态。整行可进入详情，无行内“标为已读”。分类是业务归类，不作为附加阅读状态；过期和目标不可用说明在详情，不增列表状态标签。字段定义见 12.9。

**筛选**：默认全部分类、全部阅读状态；阅读状态可选全部/未读/已读，分类与状态取交集。仅列出当前账户实际拥有消息的分类，来自真实业务归类，不预设固定空分类；未知映射不使合法消息整条消失。分类筛选不改变收信政策，不等于退订。切换筛选回第 1 页、回到列表起始位置。无效筛选回默认并正常可读，不报错伪造空集。

**排序与分页**：按原发生时间倒序，同一时点保持稳定次序。已读不置底，未读不置顶。同一事实补送不改原时间、位置或数量。使用页码，默认 20 条，支持 20/50/100，改变每页量回第一页；显示当前筛选总条数。该总数包括匹配的已读条目，不要求与全部已读确认的未读条数相等。翻页或新消息到达不得造成浏览结果重复、漏项；保留已加载阅读上下文，新结果在主动刷新后纳入当前浏览。

筛选、页码、每页量可随当前页面地址保持，刷新可恢复；默认值不产生多种不同默认地址。详情返回还须恢复滚动及来源消息焦点，见 12.4。若可见结果变化导致原页不存在，展示最近的有效页并说明结果变化，不停在无效页。

**状态与失败**：首次无消息说明“暂无消息”；筛选无结果说明“没有符合条件的消息”，提供清除筛选。首屏读取失败展示重试，不能伪装空态。翻页时保留当前内容并防重复翻页操作；翻页失败仍停留原页可重试。单条文案异常按 12.10 降级，不影响同页其他条目、不泄漏文案键。加载与空态均不产生已读或新通知。

图示：[FL-O01](v1.0-运营端消息通知-流程图与状态机.md#fl-o01)。验收 AC-O11～21、27、85～90、96、108。

### 12.4 M4 详情与来源返回（F-O12、F-O13）

**阅读**：P-O21 为独立整页、可深链打开。先满足消息准入和归属，成功显示标题、完整正文、分类、原发生时间及必要原业务关联；正文纯文本，标签及脚本作为文字显示，不执行。时间为绝对时间并标时区；包含日期/金额/期限的来源正文不得被当前业务状态重写。

详情展示成功才对本人标已读；加载失败保留未读，明确说明、提供重试及返回列表。已读保存失败不阻断正文阅读、不弹错误干扰；不能伪称成功或清除真实未读，下一次同步仍以真实结果为准。重复阅读不更新首次已读时间。

**返回**：面包屑、返回列表、浏览器返回均恢复原分类、阅读筛选、页码、每页量、滚动及可用的来源消息焦点；详情刷新后仍可恢复同一会话内来源。刚读的条目原位显示已读，不重排。在“未读”结果中暂留该行，直到用户主动刷新或切换筛选；返回本身不主动删除该行。来自预览或无列表来源的深链，返回默认列表；不得接受外部不可信返回地址。

从消息去本人账户设置时提供返回原消息的途径，不丢原列表上下文。业务目标若有未保存操作，遵循目标自己的离开保护；返回不是批准或取消业务。来源账户已变化、权限已撤销或消息不再可见时重新判断权限，不恢复旧内容。

**目标**：按 12.6 处理“可查看原对象”“原动作失效”“资源不存在”“无权”等情况；消息内容可读不意味着仍可执行通知中描述的操作。

### 12.5 M3 已读语义（F-O10、F-O11）

#### 12.5.1 单条阅读

仅详情成功呈现后自动已读，或在全部已读中被明确选定；无行内已读，无手动改回未读。预览展开、消息经过视窗、标题悬浮、详情加载失败及跳转预判均不产生已读。已读只属于“当前账户与这条消息”，不改变其他账户、其他端或业务进度。

同一业务事实重复投递或补送继续使用原消息的阅读事实，不新增未读、不重置已读、不改发生时间、不重复置顶。新一次真实提交/审核结果是独立事实，形成自己的消息；不按“同机构、同代币”把不同笔合并吞掉。来源明确的条件模板或合并结果沿来源唯一规则，不由本框架随意拼接或拆多封。

#### 12.5.2 当前筛选全部已读

用户在 P-O20 发起，范围为**本账户、本端、当前筛选命中的全部尚未读消息，跨所有页**。执行前二次确认，展示真实待处理未读条数、当前分类及阅读筛选，说明“跨页、仅影响本人、不可撤销”；默认焦点取消。当前匹配未读为 0 时禁用并解释；全局未读包含其他分类也不能扩大范围。

确认圈定本次范围后到达的新消息保持未读，不把操作变为持续自动已读。确认显示数与实际可处理数变化时如实反馈实际结果，不按旧数伪报成功。已被本人另一页读过的消息不重复计算、不改首次时间。成功后更新列表、总未读及其他模块；仅改变本人的阅读。失败不宣称成功、不乐观清零，保留可确认的原状态并允许重试；会话失效重新登录后核实结果。

执行期间防止重复确认，确认、取消及外部关闭暂不可用；完成后可继续操作，焦点恢复可用入口。阅读操作不发送回执消息、不通知其他运营人员，不生成业务完成记录。

### 12.6 M5 目标与失效（F-O14、F-O15）

#### 12.6.1 三类目标与业务关联

无跳转、原业务对象、静态页面三者互斥。原业务目标须明确属于本端且已登记，必要时定位原提交、原期次、原执行笔；静态页面须为本平台本端唯一页面。消息不携带任意页面地址，既有映射约束仅引用主册契约基线；不在本文定义路由协议。混合/错端目标不得成为可访问的本端消息，不使用猜测地址或默认首页。

来源不需要跳转时可合法无目标，正常展示且不出现无效按钮或多余说明。映射未登记时正文仍可阅读、计数和已读，不显示无效按钮、不跳首页，也不掩盖登记依赖。EV-L42 原提交已有明确“暂不可查看详情”提示要求时按来源保留该提示；不能拿通用无目标静默规则隐藏其已知故障。

#### 12.6.2 进入目标

业务对象在进入详情时辅助判断当前可读性和操作有效性，列表不提前判断。静态页面可直接进入，但目标仍校验当前资格。辅助判断失败或超过 N-O05（3 秒）时沿基线允许用户尝试进入目标；目标自身权限及状态限制必须生效，不能凭超时取得资料或执行操作。

#### 12.6.3 动作失效与原对象可读

| 情况 | 消息与可用入口 |
| --- | --- |
| 原动作已过期/任务已处理，但当前有权查看原对象 | 说明原动作不再可用，保留原对象/原记录的只读入口；禁止重开、再次提交原审核、冒用新提交或回退状态 |
| 原对象已经删除或确实不可得 | 保留完整消息，说明目标不存在/暂不可用；禁用对应目标，不跳最新对象或错误首页 |
| 原对象存在但当前无查看权限 | 消息仍在本人合法范围内时可读，目标禁用并说明当前无权限；不能泄漏受限内容/文件 |
| 消息自身过期或来源主动失效 | 不计未读，详情给出有效性说明；原办理动作不可用。若来源明确保留原对象历史且当前有权，仍可只读查看；否则无原动作入口 |
| 正常且当前有权 | 可进入来源已明确目标；办理必须在原模块由用户按当前状态明确操作 |

状态流转不是消息状态，阅读也不改变来源事实。WS-349/358 的旧提交通知仅指该次提交和操作历史，当前资料不能冒充旧材料，不提供历史材料下载/对比/回退。协议历史能否看遵守 PM-AL-15，操作记录按 PM-AL-16；两者不能互替。

说明须能被键盘及读屏获取；不使用一句“消息失效”掩盖不同原因，不因跳转失败隐藏完整通知。

图示：[FL-O03](v1.0-运营端消息通知-流程图与状态机.md#fl-o03)、[ST-O01](v1.0-运营端消息通知-流程图与状态机.md#st-o01)。验收 AC-O34～43、50、57、91、110～111。

### 12.7 本期边界

不创建业务办理进度组件、异常工作台或新的广播；来源要求的原业务编号、日期及完整对照内容仍须保留，不能因“不展示进度”而丢失定位信息。已有其他端能力不因本端不用而被删除。

P03 的未知、跨期、部分、冲突执行结果仅沿来源指引联系平台客服；本期无异常认领、升级、关闭、手工改判或异常释放，也不新增这类运营通知。审核连续 48 小时与单笔通过后七天是业务来源期限，不扩展为链上执行失败时限。真实结果未确定时不能通知已成功或已释放；读信不关闭问题。

运营端无通知偏好入口；面客账户已确认的可选开关归原端，不覆盖运营 EV-L42 必要待审核及本人安全告知。没有可选事件不制造新事件支撑空开关。本模块不发送邮件，但不取消 WS-357 已定义的安全邮件和功能验证码。

### 12.8 保留与清理

长期保留本人可见历史，不清理、不归档、不提供删除。已过期/主动失效仍可查；未读筛选按实际阅读事实筛选，因此筛选结果可以包含“不计角标的过期未读”。全部已读可标记这些匹配条目，不恢复其有效性。

旧 N-O07 仅保留未启用引用，不能以性能退化自动启用归档。上线观察列表与未读性能，调整保留政策需另有业务确认。

<a id="fields"></a>
### 12.9 业务信息与校验

用户只能筛选、阅读和跳转，不能编辑消息内容。以下为业务信息需求，不是接口字段表。

| 信息 | 含义与必填/默认 | 展示、校验及权限 |
| --- | --- | --- |
| 标题 | 必须能说明原事件；来源提供成对语言文案 | 列表、预览、详情可获得完整标题；缺失按 12.10 降级，不展示内部键 |
| 摘要 | 来源可提供简述，非必填；无则留空 | 不拿当前状态重写原事件；详情保留完整正文 |
| 正文 | 来源必须提供完整业务告知及条件模板对应内容 | 纯文本；保留原因、金额币种、原日期/截止和完整条目，不拼出未发生结果；缺失明确降级 |
| 分类 | 来源明确的业务分类，正式取值依唯一共享登记 | 只展示本人有消息的分类；缺登记不隐去合法消息，不在本册新造分类值 |
| 发生时点 | 原业务实际发生/应到时点，必填 | 不用消息到达或读取时间替换；带时区显示，同一时点稳定排序 |
| 阅读状态 | 对当前账户为未读/已读，默认新事实未读 | 只允许 12.5 的正向转换；首读时间不被覆盖；创建前全体历史虽可查但不计角标 |
| 消息有效性 | 来源明确的生效/过期/主动失效事实；无期限不自设 | 详情展示说明，列表阅读状态仍仅已读/未读；任务完成不自动过期 |
| 接收范围 | 来源明确全体运营或本人，必需 | 本人须确定原接收账户；不可根据邮箱变更、机构、业务办理人猜测或重分配 |
| 原业务关联 | 有业务目标时必需；可含申请、提交、期次、单笔执行等定位信息 | 指向原事实，不显示技术版本号代替提交时间；无目标不强造关联 |
| 目标说明/入口 | 条件必需，随来源已登记目标及当前权限 | 无目标不必展示；失败、无权、已处理按 12.6 分别说明 |
| 本人邮箱、角色 | 本人实际当前邮箱和 WS-357 预置角色，必需 | 只用于共享账户菜单；不公开他人档案，不凭文字升权 |
| 公共客服 | 来源有真实对外联系方式才展示，未配置不编造 | 完整可阅读与复制；缺失反馈暂不可用，不新增发送渠道 |

账户密码、验证码、私人完整档案、钱包凭据、材料原件不得进入正文/摘要/预览。必要业务数据按来源权限可读；查看业务信息不能变成查看他人账户档案。机构审核员私人身份沿来源匿名规则，不在通知披露。

### 12.10 时间、语言及来源内容

默认英文，不按浏览器语言静默切换；中英切换即时生效，账户偏好沿 WS-357。来源当前语言缺失先回默认语言；均缺失时标题与详情用通用 `Notification / 消息`，摘要为空，分类和时间仍可读，任何位置不泄漏文案键名。

列表/预览 24 小时内可用相对时间，超过用绝对时间；详情必须绝对时间及明确时区。同一真实时点按本人偏好显示；首次登录的时区推断与写入归 WS-357，推断失败或无可用偏好时兜底 UTC，不由消息中心覆盖本人偏好。业务日期统一 UTC，源业务已经确定的连续 48 小时和独立七天截止不因时区、补送、读取或页面刷新改变。来源金额按原金额及币种展示，USD/USDT/USDC 固定 1:1:1 不能被拿来重算原消息；未知精度、尾差规则不造值。

来源条件模板按来源唯一条件选完整中英一对，不新增事件；可变期数等完整条目可用纯文本阅读，不分拆为多封、不裁掉单侧条目。WS-360 不改写来源模板和邮件职责。真实业务发生/应到至可见的时效按主册 Q-O08 联验，不能用 N-O01 替代或自动放宽。

### 12.11 异常与边界出口

| 情况 | 产品结果 |
| --- | --- |
| 未登录或会话失效 | 隐藏受保护内容，停止消息访问，回运营端登录；首次改密未完成先完成账户流程，之后按当前资格返回本端原路径 |
| 无 PM-AL-12 | 入口消失、深链和阅读操作拒绝，不以旧页面继续访问；其他合法业务功能按其权限保留 |
| 其他端/他人个人消息 | 与不存在同一结果，不泄漏是否存在，已读不发生 |
| 首屏/详情失败 | 明确失败、可重试；失败详情不已读 |
| 刷新/翻页失败 | 保留可信计数或当前页内容；会话失效不按普通刷新失败忽略 |
| 全部已读中失效或结果未知 | 不显示成功，不污染其他账户；重登核实真实状态，不借此完成业务 |
| 目标失败 | 按 12.6 保留通知，分别反馈目标原因，不跳猜测页 |
| 原业务异常 | 保持来源真实事实及限制，真实渠道联系客服；不在消息中心增加异常办理 |

### 12.12 M6 可见范围与权限（F-O16、F-O17）

来源确认的全体运营消息，对当前具有消息权限的正常运营管理员和专员可见；个人安全消息仅接收本人可见。所有查看、计数和阅读操作均依据实际登录账户与本端，不能靠改写身份、消息编号或端标识取他人内容。无查看他人阅读明细的入口；不暴露可枚举的消息查询能力。全体消息 A 阅读不改变 B，同一人另一端的阅读也不联动。

收回 PM-AL-12 后再次访问立即拒绝；重新授权恢复符合资格的历史，阅读状态不重置。这是权限生效结果，不新增产品内配置权限的页面。当前账号资料只限本人；建设方/运维提供账户，不增加管理员建号、邀请、停用产品流程。

目标权限顺序为：先合法读取消息，再按目标模块检查原对象可见性，最后由目标模块判断当前业务能否操作。机构认证采用 WS-358 的正常登录不分权局部例外；消息入口仍有 PM-AL-12。质押仍用 PM-AL-07/08，不能扩散例外。

协议历史内容/文件为管理员 PM-AL-15；操作记录为正常管理员和专员 PM-AL-16，不能要求 PM-AL-09 才能看记录。没有 PM-AL-09 者只读操作记录，不显示当前协议正文；专员即使有维护/发布权限也不因此获得 PM-AL-15。缺 PM-AL-12 的正常账号可从协议模块读取操作记录，不可通过此规则访问消息池。“所有人”指本运营体系正常账号，不指匿名访客或其他平台。

### 12.13 M7 来源承接与编号（F-O18）

接收范围采用[主册第 4 章](v1.0-运营端消息通知-PRD.md#4-既有消息来源与发送责任)的已定义来源；发送时点、收件对象、模板及原业务目标由各来源负责。新增合法业务种类可以沿同一列表、详情、阅读和目标规则使用，不为每个业务重建本模块。没有正式登记的映射不声称可跳转；不因映射缺失丢掉合法通知。

本端目前承接 EV-L42 运营待审核及 WS-357 本人密码安全站内信；前者仅真实成功提交，后者仅真实密码生效。WS-358 不重复发待审核，WS-359/L5 不重复发同一审核结论。面客审核与 L5～L8 事件不自动抄送运营/SPV，WS-355 控制台无事件；不从阅读、状态查询、失败重试或旧任务结束制造新事件。本模块新增独立业务事件和模板数均为零。

P-O20/21、C-O20～23 沿用，不占其他平台编号；目标能唯一定位本平台本端。共享登记的正式分类、端标识、来源原目标及当前完成状态沿 Q-O05，旧只读参考不作为已接通证据。来源须提供真实业务能力及消息证据；真实时效、权限、目标跳转和投递仍待联验，原型断言与文档核对不能替代。
