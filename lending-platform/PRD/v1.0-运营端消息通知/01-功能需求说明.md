## 12. 模块详情

### 12.1 M1 · 入口与未读提示（F-O01～F-O05）

> 两个入口的页面流见图册 `FL-O01`；消息从产生到被消费的全链路见 `FL-O02`。

#### 12.1.1 铃铛与未读的呈现

| 项 | 规则 |
| --- | --- |
| 位置 | 运营端顶部导航栏右侧，**语言切换器左侧、账号下拉之前**；位置在所有已登录页面**固定且可预期** |
| 无未读 | 铃铛正常展示，**不展示任何计数、也不展示 `0`** |
| 有未读 | 铃铛上展示未读计数；超过 `N-O03`（99）时展示 `99+`，且此状态下**不再展示精确数字** |
| 未登录 | **不展示铃铛**（未登录态无顶部账号区） |
| 无消息查看权限 | **不展示铃铛**：未持有 WS-357 功能权限项 `PM-AL-12` 的账号，顶栏不出现铃铛；权限被收回后入口在下一次进入时消失（主册 6.1） |
| 可读名称 | 铃铛具备可读名称，计数变化对读屏用户可播报且**不抢焦点** |

> 铃铛挂在 WS-357 已预留的挂载位——语言切换器 `C-O-AL-02` 左侧、账号下拉 `C-O-AL-04` 之前（其 `01` 9.1）。宿主组件由 WS-357 定义并提供，本模块只挂载，**不定义宿主组件本身**。

#### 12.1.2 未读计数口径（`D-O15`，强制条款）

| 项 | 规则 |
| --- | --- |
| 计算方 | **服务端计算**，界面不自行统计 |
| 计数范围 | 当前账号在**本端**可见集内的未读条数（可见集三类见主册 6.2）。**只统计本端，不合并任何其他端的未读**（主册 6.3） |
| 不计入 | **已过期**与**已主动失效**的消息不计入 |
| 仍计入 | 「目标资源已删除 / 状态已流转 / 无权限」三类**跳转失效**的未读消息**仍然计入**——它们是打开详情时才判定的实时结果，不做全量预判 |
| 分类 | **全分类合计**，不按分类拆成多个计数 |
| 新账号 | 账号创建时间之前的消息**可见但不计未读** |

> 新增一类接收方范围时，未读计数的算法**零改动**——它始终是「可见集 − 已读集」。

#### 12.1.3 未读提示的刷新时机（`D-O16`）

| 场景 | 行为 |
| --- | --- |
| 首次加载 / 页面切换 | 立即刷新一次 |
| 常态 | 每 `N-O01`（默认 60 秒）刷新一次 |
| 页面切回前台 | **立即刷新并重置计时** |
| 页面不在前台 | **停止刷新**，开销为 0 |
| 标记已读后 | 计数立即下调，以下一次刷新对账 |
| 刷新失败 | **静默保留上一次数值**，不清零、不弹提示 |

**两条本端专门确认过、都不改的口径**：

| 问题 | 结论 | 理由 |
| --- | --- | --- |
| 运营端承担审核待办，**刷新间隔要不要调小？** | **不调**，`N-O01` 保持 60 秒 | ① 待办的主入口是**各业务模块自己的列表页**（它们有自己的刷新与筛选），未读提示是**辅助提示**而不是工作队列的实时看板；② 需要更强时效的事件，触发方本就应同时走自己的站外渠道，不依赖站内消息兜底；③ 它是**可调参数**，若上线后确有实时性诉求，改一个数即可，不需要改设计 |
| 要不要引入长连接？ | **本期不引入** | 站内消息无秒级时效要求，收益与复杂度不匹配。**既定约束，实现机制不在本文展开** |

#### 12.1.4 多标签页一致性

任一标签页的已读变更须同步给同一账号的其他标签页；同步通道**复用 WS-357 的跨标签页同步机制**，不另做一套。同步不可用时降级为按 `N-O01` 的定时刷新对齐（最长滞后 60 秒），**不报错、不阻断功能**。

#### 12.1.5 账号下拉「消息中心」入口（F-O04）

| 项 | 规则 |
| --- | --- |
| 位置 | 右上角账号下拉 `C-O-AL-04` 内，「账户设置」**之上**；下拉内共三项：消息中心 / 账户设置 / 退出登录（位置由 WS-357 预留，**条目由本模块挂载**） |
| 落点 | **直接进入 `P-O20`**，不经快捷面板，不带任何筛选条件 |
| 为什么在「账户设置」之上 | 消息中心是**高频查看**入口，账户设置是**低频维护**入口 |
| 权限收敛 | 未持有 `PM-AL-12` 时**不展示该条目**；权限被收回后条目在下一次进入时消失（WS-357 `D-AL-11`、`F-AL-17`） |
| 不做的 | **不在左侧菜单新增一级入口**（`D-O05`，理由见主册 7.2） |

### 12.2 M1 · 铃铛快捷面板（C-O21，F-O03）

| 项 | 规则 |
| --- | --- |
| 展开 / 收起 | 点击铃铛展开；**再次点击铃铛、点击面板外区域、按 Esc、点击面板标题栏右侧的关闭按钮**四种方式等价，收起后焦点归还铃铛 |
| 内容 | 最近 `N-O02`（10）条消息摘要，**不区分已读未读** |
| 单条构成 | 分类标签 + 标题（单行截断）+ 摘要（单行截断）+ 相对时间 + 未读标记 |
| 点击单条 | 进入 `P-O21` 详情，与列表点击行为一致 |
| 底部 | 「查看全部」进入 `P-O20`，不带筛选条件 |
| 数据新鲜度 | **每次展开重新取数**，不使用上一次的缓存 |
| 空态 / 加载态 / 失败态 | 空态给出「暂无消息」；加载态展示与列表项等高的占位，避免加载完成后跳动；失败态给出原因与重试 |
| 可访问性 | 展开后焦点进入面板，键盘导航限制在面板内，Esc 关闭并归还焦点 |

**两条在本端是强制条款，单独点名**：

| 条目 | 规则 | 本端为什么更要守 |
| --- | --- | --- |
| **面板内不提供「全部已读」** | 全部已读影响面广且**本期不可撤销**，必须在能看清作用范围（当前筛选）的消息中心内执行 | 运营端的未读 = 待办提示。在一个只展示 10 条的浮层里误清全部未读，代价比面客端高 |
| **仅展开不算已读** | 展开面板、滚动经过都不产生已读；点击某条进入详情后才按 12.5 标记 | 同上：面板一展开就批量清未读，等于让运营人员丢掉待办 |

> 进度型消息在本端不产生（12.7），面板内不会出现进度状态标签；**组件变体保留，不做删除**。

### 12.3 M2 · 消息中心列表（P-O20，F-O06～F-O09）

#### 12.3.1 页面结构（线框级）

```
┌──────────────────────────────────────────────────────────────┐
│ 面包屑：消息中心                                （运营端面包屑组件）│
├──────────────────────────────────────────────────────────────┤
│  消息中心                                    [全部标为已读]    │
├──────────────────────────────────────────────────────────────┤
│  [分类：全部 ▾]  [状态：全部 / 未读 / 已读]                    │
├──────────────────────────────────────────────────────────────┤
│  ● [审核待办] 有 1 笔质押申请待审核           2 小时前  [标为已读]│
│      申请编号 ……，提交于 ……                                    │
├──────────────────────────────────────────────────────────────┤
│    [运营告警] 对账任务出现差异                2026-09-17        │
│      差异笔数 ……，需人工核对。                                 │
├──────────────────────────────────────────────────────────────┤
│  ● [安全] 你的登录密码已变更                  2026-09-16        │
│      （个人消息，仅本人可见）                                   │
├──────────────────────────────────────────────────────────────┤
│         [ ‹ 1 2 3 … › ]        每页 [20 ▾] 条                 │
└──────────────────────────────────────────────────────────────┘
```

> 线框里的标题与摘要**只是形态示意，不是本 PRD 定义的文案**。本端有哪些消息、标题怎么写，归各业务 issue（主册 3.4）。

#### 12.3.2 筛选（F-O06、F-O07）

| 项 | 规则 |
| --- | --- |
| 分类筛选 | 筛选项由服务端返回的分类元数据**动态渲染**，界面**不写死分类清单** |
| 只渲染有消息的分类 | **只渲染当前账号实际拥有消息的分类**，不产生必然为空的筛选项 |
| 状态筛选 | 三档：全部 / 未读 / 已读，默认「全部」 |
| 叠加 | 两者**可叠加，是「与」关系** |
| 保持 | 筛选与分页状态在**页面地址中保持**，刷新后不丢失；**取缺省值时不写入地址**，使「无筛选的消息中心」始终是同一个干净地址 |
| 非法取值 | 地址中出现非法取值时**回落到缺省值**，页面正常渲染，**不报错、不出现空列表** |
| 切换筛选 | 重置到第 1 页并回到顶部 |
| 分类文案 | 取分类的多语言展示名，按当前语言渲染；缺失翻译时回落到该端默认语言（12.10），**不展示文案键名** |

**本端的分类集合**：由本端消息池实际拥有的分类构成。分类定义表是**共用契约的一份**，本端在其中**声明启用哪些**，**不另写一张表**；本端预计启用哪些分类由各业务 issue 接入时决定，**本 PRD 不预先定死**。本模块只保证一件事——**新增一个分类不需要改本模块的任何页面逻辑**。

#### 12.3.3 排序（`D-O17`，强制条款）

| 项 | 规则 |
| --- | --- |
| 主排序 | 按消息产生时间**倒序** |
| 已读状态 | **不参与排序**：未读不置顶、已读不沉底，标记已读后**行位置不变** |
| 稳定性 | 同一时间的多条消息有稳定的次级顺序，**翻页时不重复、不漏项** |
| 不做 | 不做分类分组、不做优先级排序 |

> **「待办应该置顶」这条不做**：若未读参与排序，运营人员读完一条待办后该行会立刻跳位，正在处理的上下文被打乱。需要「只看未读」时用状态筛选，那是显式且可预期的。**优先级排序更不做**——消息的轻重缓急是业务语义，本模块不持有这个判断。

#### 12.3.4 分页（`D-O14`、F-O08）

| 项 | 规则 |
| --- | --- |
| 形态 | **分页器**（页码 + 每页条数），**不是「加载更多」** |
| 每页条数 | 默认 `N-O04`（20），可切换 **20 / 50 / 100**；切换后回到第 1 页 |
| 总数 | 分页条左侧展示「共 N 条消息」，N 为**当前筛选命中的总条数**，与「全部已读」确认弹窗中的条数**同源** |
| 页码 | 首页、末页与当前页 ±1 常显，其余折叠；当前页高亮且对读屏可识别 |
| 上一页 / 下一页 | 在首页 / 末页时禁用，两者具备可读名称 |
| 只有一页时 | 分页条仍然展示（总数是有用信息），翻页按钮禁用 |
| **翻页一致性（强制）** | 翻页过程中即使有新消息产生，**也不得出现重复项或漏项** |

> 分页器是**管理端形态**的结果：运营端存在「跳到某一页复查」的诉求，与面客端的「加载更多」不同。

#### 12.3.5 空态、加载态与失败态（F-O09）

| 状态 | 表现 |
| --- | --- |
| **首次空态** | 无筛选且结果为 0：插画位 + `No notifications yet / 暂无消息` + 副文案，**无额外操作** |
| **筛选空态** | 有筛选且结果为 0：`No messages match these filters / 没有符合筛选条件的消息` + **「清除筛选 / Clear filters」**，一键回到无筛选 |
| 首屏加载态 | 与列表项等高的占位若干行，避免加载完成后跳动 |
| **翻页进行中** | **页码按钮与「每页条数」同时禁用**，总数行追加「加载中…」；**当前页内容保持不动**，不清空、不被占位替换 |
| 首屏失败 | 内容区错误态 + 原因 + 「重试 / Retry」 |
| **翻页失败** | 错误提示，**当前页内容不清空**，可重试 |
| 单条内容异常 | 该行降级为最小形态（标题位展示通用词 `Notification / 消息`、**摘要整行留空**、分类标签与时间照常展示），**不影响同页其他行**，仍可进详情 |

> **两种空态必须区分**：首次空态是「一切正常，只是还没有消息」，筛选空态是「你把结果筛没了，可以退回去」。用同一套文案会让运营人员以为消息全丢了。
>
> **上线初期首次空态是常态**——本期无接入方，各业务模块陆续接入前列表就是空的。这不是缺陷，首次空态的文案要经得起「空很久」。

### 12.4 M4 · 消息详情（P-O21，F-O12、F-O13）

#### 12.4.1 形态与地址

| 项 | 规则 |
| --- | --- |
| 形态 | **整页 + 独立地址 + 支持深链**，不用抽屉或弹窗 |
| 地址 | 两个页面各有**独立地址**，详情地址可唯一定位到一条消息；**具体路径遵循运营端统一路由规范，本文不自造取值**（主册 7.1） |

#### 12.4.2 内容结构

| 区块 | 规则 |
| --- | --- |
| 面包屑 | `消息中心 / {标题}`，上级可点击返回 |
| 头部 | 分类标签 + 标题（过长换行，**不截断**）；已过期消息在分类标签旁另带「已过期 / Expired」标记 |
| 元信息 | **绝对时间 + 时区标注**（详情是回查场景，需要精确时间） |
| 正文 | **纯文本渲染并转义**，不支持富文本；含标签的内容原样显示为文本，**不被解析执行** |
| 失效说明条 `C-O23` | 条件展示，四类失效各一套文案（12.6.4） |
| 主操作 | 跳转按钮，文案由业务类型登记提供，缺省「查看详情 / View details」 |
| 次操作 | 「返回列表 / Back to list」 |
| 加载失败 | 错误态须**明确告知该条未被标记为已读**（`It has not been marked as read. / 本条消息未被标记为已读。`），并同时提供「重试」与「返回列表」 |

> 进度区块在本端不出现（12.7）；**字段与组件保留，本端只是不产生这类消息**。

#### 12.4.3 进入详情即已读（`D-O18`）

| 项 | 规则 |
| --- | --- |
| 标记时机 | 详情内容**取数成功并渲染之后**才标记已读，**不在进入页面时就标记** |
| 为什么 | 若详情加载失败，用户实际没看到内容，此时标记已读会让这条消息从未读里消失且用户毫不知情 |
| 标记失败 | **不阻断详情阅读**、不弹错；下次进入或下次同步时重试 |
| 重复标记 | 不报错、**不改变首次已读时间** |

#### 12.4.4 返回列表的状态同步（F-O13）

三种返回方式（面包屑上级 / 「返回列表」/ 浏览器后退）**行为一致**，且：

- **保留筛选条件、页码与每页条数**（不跳回第 1 页）、**恢复滚动位置**；
- 刚读过的那条**就地变为已读样式**，**不重排、不从列表移除**；
- 在「只看未读」筛选下，刚读过的那条**仍留在列表中**并显示为已读样式，直到主动刷新或切换筛选才消失；
- 未读计数已在详情页更新，返回后不再跳变。

> **为什么已读项不立即移除**：用户在「只看未读」下读完一条返回，若该行立刻消失，下面的行会整体上移，**接下来点的那一行很可能不是他想点的那条**。在运营端这意味着点错待办。

#### 12.4.5 未登录深链

跳**运营端登录页**并携带原路径（含消息标识），登录成功后回跳该条详情。登录前**不泄漏任何消息内容，也不泄漏该消息是否存在**；若该消息不属于登录成功的账号，落到「消息不存在」页，**不提示「你登错账号了」**（主册 6.4、6.5）。

### 12.5 M3 · 已读语义（F-O10、F-O11）

#### 12.5.1 单条已读的触发方式

| 触发方式 | 是否标记已读 |
| --- | --- |
| 列表点击整行 → 进入详情 | ✅ |
| 快捷面板点击某条 → 进入详情 | ✅ |
| 快捷面板 / 列表中**仅展开、仅滚动经过** | ❌ |
| 列表行悬浮出现的「标为已读」按钮 | ✅（不进详情，就地标记） |
| 详情页点击跳转按钮 | ✅（详情打开时已标记） |
| **手动标记为未读** | ❌ **本期不提供**。系统侧的重复事件合并可使其恢复未读，属系统行为（12.5.4） |

> **为什么两者并存**：只做「显式点击才算已读」，未读数会长期虚高，提示变成永远的红点；只做「进详情才算已读」，则「看标题就知道是什么事、不想点开」的消息会永久堆在未读里。**在运营端这两种失效都直接损害待办提示的可信度。**

#### 12.5.2 全部已读（`D-O19`，含一条本端强制条款）

**作用范围**：**当前筛选条件命中的全部消息**，不限当前页，也不是全库无差别。

流程见图册 `FL-O04`。

| 场景 | 实际作用范围 |
| --- | --- |
| 无任何筛选 | 该账号可见集内的**全部**未读消息 |
| 分类筛选 = 某分类 | **仅**该分类下的未读消息 |
| 分类 + 状态叠加 | 两个条件同时命中的未读消息 |
| 当前页显示 20 条、实际命中 300 条 | **300 条全部标记**，不是只标记当前页的 20 条 |

**交互规则**：按钮位于消息中心页头右侧（**快捷面板内不提供**）；当前筛选下无未读时禁用并说明原因；执行成功后提示条数、未读计数与列表立即更新；**执行失败时列表与计数不做任何变更**（不做乐观更新），可重试；并发一致性以服务端执行时刻的筛选结果为准，执行期间新到达的消息保持未读。

**确认弹窗的构成**：

| 元素 | 内容 |
| --- | --- |
| 标题 | `Mark {n} notifications as read? / 将 {n} 条消息标为已读？` |
| 筛选说明 | `Filter: {分类} · {状态} / 当前筛选：{分类} · {状态}`；**无筛选时也展示**（显示为「全部分类 · 全部」），不做隐藏——否则用户无法确认自己处在哪个范围 |
| 影响范围 | **三件事都要说全**：跨页、仅影响本人、不可撤销 |
| 按钮 | 「取消」+「确认」，**默认焦点在「取消」** |
| 执行中 | 「确认」进入等待态并禁用；**「取消」同时禁用**，遮罩点击与 Esc 也不关闭——批量已读不可撤销，中途关窗会让用户不知道操作到底有没有发生 |

> **本端强制条款：二次确认不得省略，且必须明确说明作用范围与条数。**
> 面客端误清未读丢的是通知，运营端误清未读丢的是**待办提示**——而本期既没有「标为未读」，也没有认领机制可以兜底，一次误点不可撤销、不可追回。

#### 12.5.3 已读后的即时反馈

- 未读计数立即下调，以服务端下次返回对账；
- 列表项未读标记消失、标题字重回落、**行位置不变、不移除**；
- 快捷面板若同时开着一并更新；其他标签页同步（12.1.4）；
- 服务端失败时**回滚界面上的乐观更新**并提示；
- 行内「标为已读」提交中：该行进入等待态（降低不透明度、**行内所有按钮禁用**、对读屏可感知为忙碌），完成后**焦点回到该行的消息入口**；**同一时刻只允许一行处于提交中**。

#### 12.5.4 已读状态的唯一性（强制条款）

> 单个接收者对单条消息的已读状态流转见图册 `ST-O02`。

已读状态按「**账号 + 消息**」唯一，存储在服务端。两个入口（快捷面板、消息中心）与两个页面（列表、详情）读取**同一份**已读状态；**不得为快捷面板另建一套本地已读**——这是本模块把两个入口合并的根本原因。**一个人的已读不改变他人的未读**（主册 6.1）。

> **例外：系统可将已读消息恢复为未读。** 同一事件重复触发时按共用契约的合并规则归并为一条并更新时间；若该条此前已被读过，**恢复为未读**（它承载的是一次新发生的事件），重新回到列表顶部并计入未读。合并规则本体见共用契约，本文不复制。

#### 12.5.5 会话失效对已读操作的影响

| 场景 | 表现 |
| --- | --- |
| 「全部已读」执行中会话失效 | 走 WS-357 的统一失效处理（其 `D-AL-19`、`D-AL-20`）；**不展示「操作成功」**；重新登录后未读数**以服务端为准** |
| 未读提示的后台刷新遇到登录态失效 | 与其他请求一视同仁，触发统一失效处理，**不得静默忽略** |
| **后台刷新是否算「用户操作」** | **不算**（`D-O08`）。本模块有一个常驻的后台刷新，若被计为用户活跃，无操作自动登出将**永远不会触发**；WS-357 已把同一口径写入其 `F-AL-12`，两处一致 |

### 12.6 M5 · 跳转与失效（F-O14、F-O15）

> 本节是**跳转规则在本端的落地**，不是「每类消息跳哪」。每类消息的具体目标由**各业务 issue** 在业务类型登记中补齐。

#### 12.6.1 三种跳转形态（`D-O20`）

| # | 形态 | 含义 | 落地方式 |
| --- | --- | --- | --- |
| 1 | **业务资源目标** | 消息指向一笔具体的业务记录 | 按业务类型查前端登记得到目标页面，用资源标识填充 |
| 2 | **静态页面目标** | 消息指向一个固定页面 | 按页面编号查本端页面目录直达，**不需要资源参数、不需要预判** |
| 3 | **无跳转** | 消息只是告知，没有可去之处 | 不渲染跳转按钮，**这是正常形态而非缺失** |

**共同的强制约定**：

- 三形态**互斥**，一条消息只能是其中之一；两者同时携带属接入错误，**拒收**。
- **消息本身不存放页面地址**——地址会随前端重构失效，而历史消息不可能回头批量改写。
- **本端消息的静态页面目标只能是本端已登记的页面编号**，且须能被唯一解析到「**本平台 + 本端**的某一个页面」——表达形态沿用本平台 L10 面客消息中心已裁定的「平台标识 + 页面编号」（其 `D-NC-03`），**本模块不另造第二种形态**；**目标所属平台或端与消息不一致时拒收**（主册 6.3、6.4）。

> **这条在拆端后比拆端前更容易踩**：一条借贷运营端的消息带着代币发行运营端、或本平台面客端的页面编号，会把人带到一个本端人员根本打不开的落点。**页面编号能否被唯一解析是这条判定的依据**，因此两端编号不得撞号（主册 2.2），对外编号也必须带平台标识。

#### 12.6.2 跳转的执行

| 项 | 规则 |
| --- | --- |
| 静态页面目标 | **一律不做可达性判定**，直接跳转 |
| 业务资源目标 | 是否判定由业务类型登记声明，**默认「需要判定」**，业务方可显式声明不需要 |
| 判定时机 | **进入详情页时判定一次**（而不是点击时才判定），使失效状态能在按钮上提前体现 |
| 列表页 | **不做任何可达性判定**（会对每行触发一次业务查询，成本不可接受） |
| 判定失败或超时 | 超时 `N-O05`（3 秒）按判定失败处理，**放行跳转**，由目标页按自己的规则处理不存在或无权限——**这是目标页本来就必须具备的能力** |

流程见图册 [`v1.0-运营端消息通知-流程图与状态机.md`](v1.0-运营端消息通知-流程图与状态机.md) `FL-O03`。

#### 12.6.3 映射缺失时的降级（强制条款）

| 位置 | 表现 |
| --- | --- |
| **详情页** | **不渲染跳转按钮**（既不展示可点的、也不展示置灰的）；正文正常展示；**不展示任何说明文案**，操作区只保留「返回列表」 |
| **列表 / 快捷面板** | **正常展示该条消息**，点击正常进入详情；不因映射缺失而隐藏或置灰 |
| 分类筛选 | 该消息仍归入其分类，**不被过滤掉** |
| 后台记录 | 记录一次「未知业务类型」事件，用于发现登记遗漏 |
| **禁止的做法** | ❌ 跳错误页；❌ 跳首页；❌ 展示一个点了没反应的按钮；❌ 隐藏整条消息 |

> **消息内容本身永远优先于跳转能力。** 即使跳不过去，运营人员也应能读到「发生了什么」——跳转是增强，不是消息的存在前提。
>
> **本端触发概率更高**：业务模块是陆续接入的，灰度期与版本不一致时映射缺失必然发生。

#### 12.6.4 四类失效（`D-O20`）

| # | 失效类型 | 判定方式 | 列表表现 | 详情表现 | 跳转按钮 |
| --- | --- | --- | --- | --- | --- |
| 1 | **已过期** | 消息自带有效期，服务端标记 | 整体降低视觉权重，标题右侧带 `Expired / 已过期` 标签；**不计入未读** | `C-O23`：`This notification has expired. / 该消息已过期。` | **不渲染** |
| 2 | **目标资源已删除** | 进入详情时判定 | **无特殊表现**（列表不判定） | `C-O23`：`The related record is no longer available. / 相关记录已不存在。` | **禁用**，悬浮说明原因 |
| 3 | **状态已流转、不可再操作** | 进入详情时判定 | 无特殊表现 | `C-O23`：`This has already been handled — no action is needed. / 该业务状态已变更，无需再处理。` 可附带业务方提供的**当前状态描述** | **禁用**，悬浮说明原因 |
| 4 | **当前账号无权限** | 进入详情时判定 | 无特殊表现 | `C-O23`：`You no longer have access to this record. / 你当前无权访问该记录。` | **禁用** |

> 消息自身的可用性状态（生效中 / 已过期 / 已主动失效）见图册 `ST-O01`。

**三条共同规则（强制条款）**：

1. **失效不删除消息、不隐藏内容**：四种情况下标题、正文、时间都必须**完整展示**——用户仍有权知道当时发生过什么。失效只影响「能不能跳过去」。
2. **禁用而不是隐藏**（第 2～4 类），并说明原因；若直接隐藏按钮，用户无法区分「本来就没有跳转」与「有但现在不能用」。禁用状态的原因**必须对键盘与读屏用户可达**，不能只靠鼠标悬浮。
3. **`C-O23` 形态统一**：详情页正文上方的浅底说明条，左侧信息图标，纯文本，不可关闭，**不使用错误红色**（失效是正常业务状态，不是错误）。

> **第 3 类在运营端会高频得多**：本端全员可见，「一条待办被同事先处理掉了」正是它的典型场景。这不是缺陷——它恰恰是共享可见范围要承受的那个「多人重复看到」的效率成本（主册 6.2）。**建议各业务 issue 的判定实现都提供当前状态描述**，它在这里价值最高。
>
> **第 4 类的边界**：这里的「无权限」指**跳转目标资源的业务权限**，**不是消息本身的归属权限**。消息归属的越权在服务端就已被拦截（主册 6.4），用户根本拿不到别人的消息，不会走到这一步。

#### 12.6.5 「无跳转」是合法状态，不是缺失

一条既无业务资源目标也无静态页面目标的消息**完全合法**，按正常消息渲染，只是详情页不出现跳转按钮，**也不展示任何说明文案**——给一条本就没有跳转的消息加一句解释，会让人以为系统出了问题。

| 情形 | 是否合法 | 详情页表现 |
| --- | --- | --- |
| 无跳转目标（形态 3） | ✅ 合法 | 不渲染按钮，**无任何额外说明** |
| 有业务类型但登记缺失（12.6.3） | ❌ 接入 / 版本异常 | 不渲染按钮，**同样无任何说明**；**仅在后台记录** |
| 有目标但已失效（12.6.4 第 2～4 类） | ✅ 业务正常状态 | **按钮禁用 + `C-O23` 失效说明条** |

### 12.7 本期不适用的展示能力（**不等于从契约或组件里删掉**）

| # | 能力 | 本端本期 | 依据 | 处置 |
| --- | --- | --- | --- | --- |
| 1 | **业务办理进度消息**（进度分类、进度型列表项、详情进度区块） | **不产生** | 进度类消息面向业务办理方。运营端是管理端，进度的接收方是**面客用户**，不是运营人员 | **契约字段与组件变体全部保留不动**，本端只是不产生这类消息 |
| 2 | 面客形态的「加载更多」分页 | 不适用 | 本端取管理端形态的分页器（12.3.4） | 形态归类问题，不是能力裁剪 |
| 3 | 面客端「按用户账号严格隔离」的具体表述 | 不适用 | 本端走运营端的可见范围模型（主册 6.2） | **但归属独立判定与越权按「不存在」处置两条通用规则仍然完全适用**（主册 6.4） |

### 12.8 消息的保留与清理（`D-O12`）

**结论：本期不设保留期、不做自动清理、不做归档，消息长期保留。**

| 项 | 本期口径 |
| --- | --- |
| 保留期 | 无上限，消息不因时间流逝被删除或隐藏 |
| 自动清理 / 归档 | 不做 |
| 用户手动删除 | **不提供** |
| 已过期消息 | **仍然保留并可在列表中查到**，只是不计入未读、带「已过期」标签 |
| 已读消息 | 与未读同等保留 |

**理由**：安全与合规类消息是事后回查「我的账号什么时候发生过什么」的唯一站内通道，设保留期等于给这条记录设了个静默的失效日期；在没有偏好中心、没有按分类退订能力的前提下，清理与删除都会变成逃避通知的出口，掩盖「消息过载」这个真正该解决的问题。

**本端额外要求两条**（主册 3.5.3）：① 列表与未读的响应时延**上线即纳入监控**，不等出现退化趋势才补建；② 归档策略提前写成可调参数 `N-O07`，本期**不启用**，启用时只是把开关打开。

### 12.9 展示字段

#### 12.9.1 列表项（`C-O22`）

| 字段 | 是否展示 | 取值与规则 |
| --- | --- | --- |
| 未读标记 | 条件 | 未读时展示；**不以颜色为唯一提示**（圆点 + 字重） |
| 分类标签 | ✅ | 分类的展示名；分类未登记时展示「其他 / Other」，消息正常展示 |
| 标题 | ✅ | 单行截断，悬浮展示完整 |
| 摘要 | ✅ | 单行截断 |
| 时间 | ✅ | 24 小时内相对时间（悬浮展示绝对时间），超过则绝对时间 |
| 「已过期」标签 | 条件 | 已过期或已主动失效时展示 |
| 行内「标为已读」 | 条件 | 悬浮出现；已读项不展示 |

> 每一行的消息入口须有可读名称，格式为「**已读：/ 未读：**」+ **完整标题**（英文 `Read: ` / `Unread: `）：未读标记是纯视觉的，读屏用户只能从这里知道读没读；标题在列表里被截断为一行，可读名称与悬浮提示都给完整标题。
>
> 进度型变体本期不使用（12.7）。

#### 12.9.2 详情页（`P-O21`）

| 字段 | 是否必现 | 取值 |
| --- | --- | --- |
| 面包屑 | ✅ | `消息中心 / {标题}` |
| 分类标签 | ✅ | 分类展示名 |
| 「已过期」标记 | 条件 | 与 `C-O23` 说明条**并存**（标记回答「这条是什么状态」，说明条回答「所以会怎样」） |
| 标题 | ✅ | 完整展示，不截断 |
| 时间 | ✅ | **绝对时间 + 时区标注** |
| 失效说明条 `C-O23` | 条件 | 四类失效之一时展示 |
| 正文 | ✅ | **纯文本 + 转义** |
| 跳转按钮 | 条件 | 有跳转目标且登记存在时；失效时禁用（第 1 类不渲染） |
| 返回列表 | ✅ | — |

> 相对基线，本端详情页**不渲染**「业务编号」与「进度区块」两项——两者是进度类消息专属（12.7）。**字段定义本身不删。**

### 12.10 时间、国际化与文案

| 项 | 口径 | 来源 |
| --- | --- | --- |
| 存储 | 全部 UTC | **三平台共享国际化与展示基线**（与 WS-357 `D-AL-18` 同源，落盘位置见主册 `Q-O06`） |

### 12.11 异常与边界出口汇总

本节不新增规则，只把散在各节的异常出口集中一览，便于开发与测试对照；每一行的完整规则回查「所在小节」。

| # | 异常场景 | 用户看到什么 | 用户可做什么 | 所在小节 |
| --- | --- | --- | --- | --- |
| 1 | 列表首屏取数失败 | 内容区错误态 + 原因 | 重试 | 12.3.5 |
| 2 | 翻页失败 | 错误提示，**当前页内容不清空** | 重试 | 12.3.5 |
| 3 | 未读提示刷新失败 | **静默保留上一次数值**，无提示 | 无需操作 | 12.1.3 |
| 4 | 详情取数失败 | 错误态 + **明确告知未被标记为已读** | 重试 / 返回列表 | 12.4.2 |
| 5 | 消息不存在、越权或不属于本端 | 「消息不存在」页，**三种情形不可区分** | 返回消息中心 | 主册 6.4 |
| 6 | 标记已读失败 | 不打断阅读、不弹错 | 无需操作 | 12.4.3 |
| 7 | 全部已读失败 | 提示失败，未读数与列表不变 | 重试 | 12.5.2 |
| 8 | 跳转登记缺失 | 不渲染按钮、**不给说明文案**，仅后台记录 | 阅读消息内容 | 12.6.3 |
| 9 | 跳转目标已失效（三类） | `C-O23` 说明条 + 按钮禁用 | 阅读消息内容 | 12.6.4 |
| 10 | 可达性判定失败或超时 | 按钮保持可用，**放行跳转** | 正常跳转 | 12.6.2 |
| 11 | 文案缺失 | 降级为最小形态，**不展示文案键名** | 仍可打开详情 | 12.3.5、12.10 |
| 12 | 分类未登记 | 分类标签展示「其他 / Other」，消息正常展示 | 正常阅读 | 12.9.1 |
| 13 | 会话在消息模块内失效 | 走 WS-357 的统一失效处理（`D-AL-19`、`D-AL-20`） | 重新登录后回跳 | 12.5.5、主册 6.5 |
| 14 | 多标签页同步不可用 | 降级为定时刷新对齐，最长滞后 `N-O01` | 无感知 | 12.1.4 |
| 15 | 触发方提交的消息缺必要内容 | 服务端拒收并告知触发方，**不产生半成品消息** | 用户无感知 | 主册 6.4 |
| 16 | 同一事件重复提交 | 按共用契约的合并规则处理，不产生重复条目 | 用户无感知 | 12.5.4 |
| 18 | **账号没有 `PM-AL-12` 消息查看权限** | 顶栏无铃铛、账号下拉无「消息中心」条目；直接访问按 WS-357 的权限拒绝口径处置 | 找运营管理员授权 | 12.1.1、主册 6.1 |
| 17 | **跳转目标页面所属端与消息所属端不一致** | **服务端拒收**，用户不会看到这条消息 | 用户无感知 | 12.6.1、主册 6.3 |

> 第 17 行是**拆端后最需要盯住的一条**：借贷运营端的消息带上代币发行运营端的页面编号，会把人跳到一个本端根本无权访问的平台。判定依据是共用契约的编号段位表，因此两端编号不得撞号（主册 2.2、`AC-O104`）。
