1. **图只表达业务角色、触发入口、主流程、关键分支与业务状态**，不画内部程序执行链。
2. **图不是规则的来源**。每张图都标注了它对应的正文位置与需求编号，规则细节回查正文；**图与正文冲突时以正文为准**。
3. **本册不另造业务口径，也不复制大段规则**；正文在对应模块处直接引用本册图号。

## FL-O02 消息从产生到被运营人员消费

**关联需求**：`F-O02`（未读提示）、`F-O10`（已读）、`F-O12`（详情）、`F-O16` / `F-O17`（可见范围与归属判定）
**对应正文**：主册 6.2 可见范围、6.3 按端隔离、6.4 越权处置；分册 `01` 12.1、12.4、12.5

```mermaid
sequenceDiagram
    autonumber
    participant B as 借贷运营端某业务模块 · 触发方
    participant M as 消息模块 · 借贷运营端消息池
    participant U as 运营人员 · 持有消息查看权限

    B->>M: 按共用契约提交一条本端消息 · 含可见范围与跳转目标
    M->>M: 按可见范围确定收件人 · 全体运营人员 或 某个人
    M->>M: 校验跳转目标所属端与本端一致 · 不一致则拒收
    M->>M: 重复事件按共用契约的合并规则归并
    Note over M: 消息只进本端池 · 不进代币发行运营端池
    U->>M: 查看未读提示 · 登录身份 × 本端
    M-->>U: 本端可见集内的未读条数
    U->>M: 点击铃铛 · 查看最近 10 条
    M-->>U: 本端可见集内的消息摘要
    U->>M: 打开某条消息详情
    M->>M: 判定归属与端 · 越权按「不存在」处置
    M-->>U: 消息内容
    U->>M: 内容渲染成功后标记已读 · 仅影响本人
    M-->>U: 未读数下调 · 同步其他标签页
    U->>M: 点击跳转 · 进入 FL-O03
```

> **跨端事件由触发方各发一条**（主册 6.3）：同一个事件若两端都要知晓，触发方分别提交两条消息，各进各自的池；**两端之间不转发、不合并未读**。

## FL-O03 跳转与四类失效的分支

**关联需求**：`F-O14`（跳转形态与失效降级）、`F-O15`（静态页面目标）
**对应正文**：分册 `01` 12.6

```mermaid
flowchart TD
    A([运营人员在 P-O21 详情页]) --> B{消息携带哪种跳转目标}

    B -->|无跳转目标| N1[不渲染跳转按钮 · 不给任何说明文案]
    B -->|静态页面目标| S1{目标页面是否属于本端且已登记}
    B -->|业务资源目标| R1{前端是否有该业务类型的登记}

    S1 -->|是| S2[直接跳转 · 不做可达性判定]
    S1 -.->|否 · 端不一致| S3[消息在接收时即被拒收 · 用户不会看到这条]

    R1 -.->|登记缺失| N2[不渲染跳转按钮 · 不给说明文案 · 后台记录未知业务类型]
    R1 -->|已登记| P1{登记是否声明需要可达性判定}

    P1 -->|不需要| S2
    P1 -->|需要 · 进入详情时判定一次| P2{判定结果}

    P2 -->|可达| S2
    P2 -->|目标资源已删除| D2[C-O23 说明条 · 按钮禁用]
    P2 -->|状态已流转| D3[C-O23 说明条 · 按钮禁用 · 可附当前状态描述]
    P2 -->|当前账号无权限| D4[C-O23 说明条 · 按钮禁用]
    P2 -.->|判定失败或超时 3 秒| P3[放行跳转 · 由目标页自行处理]

    E([消息已过期]) --> E1[不渲染跳转按钮 · C-O23 说明条 · 内容仍完整可读]
```

> **消息内容永远优先于跳转能力**：四类失效与登记缺失下，标题、正文、时间都**完整展示**（分册 `01` 12.6.4）。
> **「不渲染按钮」与「按钮禁用」不可混用**：本来就没有跳转、或登记缺失 → **不渲染且不解释**；有目标但当前不可用 → **禁用并说明原因**。

## FL-O04 全部已读

**关联需求**：`F-O11`
**对应正文**：分册 `01` 12.5.2

```mermaid
flowchart TD
    A([运营人员在 P-O20 点击「全部标为已读」]) --> B{当前筛选下是否有未读}
    B -->|否| B1[按钮禁用 · 说明原因]
    B -->|是| C[二次确认 · 展示条数与当前筛选 · 说明跨页 / 仅影响本人 / 不可撤销 · 默认焦点在取消]
    C -->|取消| A
    C -->|确认| D[服务端按 登录身份 + 本端 + 当前筛选 圈定范围并标记已读]
    D -->|成功| E[提示条数 · 未读数与列表就地更新 · 同步其他标签页 · 不影响他人]
    D -.->|失败| F[提示失败 · 未读数与列表不变 · 可重试]
    D -.->|会话失效| G[按 WS-357 统一失效处理 · 不提示成功 · 未读数以服务端为准]
```

> 执行期间「确认」与「取消」**同时禁用**，遮罩点击与 Esc 不关闭（分册 `01` 12.5.2）；执行期间新到达的消息**保持未读**。

## ST-O01 消息的可用性状态

**状态对象**：一条消息本身
**关联需求**：`F-O02`（未读计数）、`F-O14`（跳转）
**对应正文**：分册 `01` 12.1.2、12.6.4、12.8

```mermaid
stateDiagram-v2
    [*] --> 生效中: 消息进入本端消息池
    生效中 --> 已过期: 到达消息自带的有效期
    生效中 --> 已主动失效: 触发方主动置为失效
    已过期 --> [*]
    已主动失效 --> [*]

    note right of 生效中
        未读时计入未读数
        跳转按钮按可达性判定结果渲染
    end note
    note right of 已过期
        不计入未读数
        列表带「已过期」标签
        不渲染跳转按钮
        内容仍完整可读
    end note
```

> **「目标资源已删除 / 状态已流转 / 无权限」不是消息的状态**，而是**跳转可达性判定的实时结果，不落到消息上**。理由：这三者是业务侧的动态状态，会随时间变化——一条今天不可操作的记录，明天可能因业务重开而再次可操作，固化到消息上会产生永久性的错误标记。
>
> **消息不因过期或失效而被删除或隐藏**（分册 `01` 12.8）。

## ST-O02 单个接收者对单条消息的已读状态

**状态对象**：「一个账号 × 一条消息」
**关联需求**：`F-O10`（单条已读）、`F-O11`（全部已读）
**对应正文**：主册 6.1；分册 `01` 12.5

```mermaid
stateDiagram-v2
    [*] --> 未读: 消息进入该账号的可见集
    未读 --> 已读: 打开详情 / 行内标为已读 / 全部已读
    已读 --> 未读: 同一事件重复触发被合并 · 系统行为

    note right of 已读
        用户不可手动改回未读
        首次已读时间不因重复标记而更新
    end note
```

> **可见范围在这张图里的读法**：一条面向全体运营人员的消息，对应 N 个「账号 × 消息」的**独立**状态机，彼此互不影响——A 走到「已读」，B 仍停在「未读」。这就是「已读个人独立」的表达（主册 6.1、`AC-O51`）。
>
> **承担 SPV 职责的账号没有第二套状态机**：运营端只有一套账号体系、不做机构级数据隔离，其可见集与同角色的其他运营人员一致（主册 5.1、6.2、`AC-O103`）。**没有消息查看权限的账号不进入本图**——它不具备消息功能的准入（主册 6.1、`AC-O101`）。
