# 运营端消息通知 · 消息通知与来源衔接

2026-09-24｜需求评审稿｜配套本模块当前主 PRD 与图册。

**运营端消息通知没有独立发送事件、没有新增业务模板、不发送邮件或站外消息。** 本册承接已经定义的来源通知，登记本端实际接收哪些事件、归谁发送、发给哪类接收范围、目标指向什么，并核对框架能否正确接收、阅读与跳转；通知的承载形式与视觉由设计决定（见[统一条款](01-运营端消息通知-PRD.md#design-boundary)）。具体的触发条件、收件归属与中英全文仍在各来源最新通知册，不复制成另一套权威事件表。

## 2. 关键归属与承接结论

### 2.1 唯一发送与不双发

| 对照对象 | 来源当前结论 | 本模块承接与验收重点 |
| --- | --- | --- |
| 机构资料待审核的唯一来源 | `EV-L42` 由资金方登录与账户体系唯一发送，覆盖首次注册、驳回后重提、已认证后变更资料三种真实成功提交；机构认证审核不再发“收到申请” | 每次真实成功提交形成一条待审核消息；重复结果、失败提交、草稿不产生消息。消息关联该申请与这次提交，不因后来有新提交改指新任务 |
| 已认证变更的降级与待审核 | `EV-L46` 告知面客本人资格暂不可用，运营使用同次 `EV-L42` | 运营端不收降级副本，也不把降级与待审核并成两条运营消息 |
| 机构审核结果 | `EV-L60`／`EV-L61` 仅发申请所属的面客资金方账号，运营无结果回执 | 运营读到的仍是原待审核消息；结论生效后原动作失效，按原提交只读查看，不重演旧审核 |
| 质押审核结果 | `N-LS-01`／`N-LS-02` 由代币质押审核唯一发送给发起该笔质押的资产方账号；本批审核时效整体取消，`N-LS-03` 废止 | 本端不收副本；运营的审核队列与统计仍在原模块，不从消息侧重建。**审核无时效即无时点事件**：本端不因等待时长产生临期提醒、超时告知或待审催办，也不新增运营催办或链上结果消息 |
| 项目审核结果 | `N-LS-09`／`N-LS-10` 由运营端合约管理唯一发送给创建该项目的资产方账号；部署成功即审核通过，签名或部署失败、再次发起、结果待核实均不发送 | 本端不收副本，也不收待审广播与裁定回执。运营端的项目审核队列、统计与操作记录仍在原模块；部署尝试与失败原因在其审核详情中可见，不搬进消息池。项目审核同样无时效，本端不产生任何时点事件 |
| 融资参数维护 | 运营端融资参数配置零发送事件；保存成功、被校验拒绝、保存失败或结果未知都不发送 | 本端不为这些事实制造消息。上限调低后存量项目按其既定隔离规则不受影响，本端不产生整改提醒、存量清单或待办 |
| 协议发布类操作 | 发布成功、立即生效、待生效调整确认成功、定时发布提交成功均不发通知；结果由页面与操作进度告知（[`D-O-AG-03`](../v1.0-运营端协议管理/01-运营端协议管理-PRD.md#d-o-ag-03)） | 本端不得为这些动作生成消息，调整未取消为草稿时不误显示撤销消息 |
| 协议定时结果与撤销 | `NT-O-AG-01`～`NT-O-AG-03` 三类运营告警；下线及其自动取消不等于主动撤销、不得借用 `NT-O-AG-03`，重新上线、记录被查看、历史被下载都不新增通知；结果未明时先确认可信状态，不把未确认结果写成失败告警 | 三类消息进入本端全体运营范围，每人独立已读；不投递给资产方、资金方或另两个平台账号 |
| 协议同一失败事实的重复发现 | 同一原协议、版本、已确认计划的重复投递或补送不产生副本 | 沿 [`D-O29`](01-运营端消息通知-PRD.md#d-o29)：不新增、不改变其原有次序、不恢复未读、不改原发生时间；后续经确认的新计划再次真实失败是另一业务事实，各自保留计划、时点与阅读状态，不按“同版本号”覆盖旧事实 |
| 密码变更的三种情形 | `NT-AL-01` 在新密码真实生效后触发一次，覆盖首登强制改密、忘记密码重置、本人修改；邮件与站内消息各一条，先安排生效通知再使全部会话失效 | 本端只呈现该账号本人的站内消息，不改投管理员、不扩为全员、不因 SPV 再发一份。阅读不改变账号状态、不撤销已生效的密码 |
| 邮箱变更 | `NT-AL-02` 仅向本人新旧邮箱各发一封安全邮件，来源未定义站内信 | 本端不补发站内信。账户菜单与账户设置更新为本人当前邮箱，历史消息仍属同一账号：邮箱变更不创建新接收身份、不清空已读、不把历史移交新邮箱所属的其他账号 |
| 登录、锁定与偏好 | 账号锁定、锁定自动解除、登录成功、登录失败、语言与时区偏好变更均不发通知；账号交付与角色配置由建设方线下完成 | 本端不为这些事实制造消息，也不因账号配置变化推测新事件 |

### 2.2 本模块自身动作一律不产生通知

浏览、筛选、翻页、切换每页条数、阅读自动已读、当前筛选全部已读、进入或返回业务目标、取数失败重试、语言或时区切换，均不发送回执消息、不通知其他运营人员、不生成业务完成记录。本模块新增的独立业务事件数与模板数均为零（[`D-O01`](01-运营端消息通知-PRD.md#d-o01)、[`D-O10`](01-运营端消息通知-PRD.md#d-o10)）。

### 2.3 资料、金额与日期

私人账户档案仅本人可见；通知可展示来源已授权的必要业务名称、编号、金额与时间，不复制他方完整档案、证件、凭证或私人联系方式（[`D-O31`](01-运营端消息通知-PRD.md#d-o31)）。账号密码、验证码、钱包凭据、材料原件、完整 IP 与文件地址不得进入正文、摘要或预览；机构审核员的私人身份沿来源匿名规则，面客侧审核节点统一显示“运营审核”。

业务日期统一 UTC，具体时刻按本人偏好时区显示并标注；USD/USDT/USDC 固定 1:1:1 不能用来重算历史消息，来源未定的数币精度与尾差保持未定（[`D-O21`](01-运营端消息通知-PRD.md#d-o21)）。真实公共客服联系方式在来源配置后可完整阅读与复制，未配置时明确暂不可用，不编造地址、不新增发送渠道。

## 4. 收件、目标与文案责任

本模块不定义文案，也不规定接口报文或投递实现。来源须为其事件提供：明确的接收范围（“全体运营”或“本人”）、成对的中英标题与正文、真实的发生时点、以及可唯一定位本平台本端的目标。缺任一项时，本端按主 PRD 的降级与无目标规则处理，正文仍可阅读、计数与已读，但不伪装可跳转（[`AC-O73`](01-运营端消息通知-PRD.md#ac-o73)）。

| 接收范围 | 当前承接 |
| --- | --- |
| 全体运营 | 对当前具有 `PM-AL-12` 的正常运营管理员与专员可见，个人已读各自独立；SPV 同一身份，不另切池。不增加指派、认领或查询/处置分权 |
| 本人 | 仅该账号本人可见，其他管理员、专员与 SPV 均看不到、不计数 |
| 收件人未明确或错端 | 保留供给依赖，不猜定某个经办人、某个管理员或全员，不改投、不转移历史 |
| 账号停用、交接或归属不明 | 由来源业务明确后再验收；不暂停业务计时，不回滚业务事实 |

目标沿来源给出的原申请、原提交、原协议版本与本人账户设置。业务状态变化时旧动作不可用、原对象按当前权限只读；目标未登记时仍可阅读但无跳转，不把通用默认页当成准确定位。协议消息的目标按其当前性质重新判权（见 [FL-O05](02-运营端消息通知-流程图与状态机.md#fl-o05)）；消息中不含文件下载地址或协议正文。

## 6. 剩余依赖

框架已经承接重复到达、旧对象可读、公共客服边界、通知偏好边界、事件归属与最新交互。本批新闭合三项：本批两个新增运营端模块（合约管理、融资参数配置）与企业账户均无可供本端承接的运营端事件；审核时效取消后来源侧不再有时点事件，`N-LS-03` 废止保号；运营端权限项扩容至 `PM-AL-20` 不改本端准入。此前已闭合的两项——密码变更站内信登记（`NT-AL-01`）与协议三类运营告警（`NT-O-AG-01`～`NT-O-AG-03`）——继续有效。仍需完成：
