## 3. 背景与目标

### 3.1 背景

三平台独立部署后，一笔代币的事实链路是：资产方在**资产可信平台**完成应收账款录入与确权并上链存证 → 推送到**代币发行平台** → 代币发行平台铸造代币 → 同步到**借贷平台**。代币随后可以在借贷广场被质押进融资项目、撑起额度、完成融资全生命周期。

借贷平台对外能被看见的资产，此前只有**已经进入融资项目的那一部分**——借贷广场只收录已发布的融资项目，草稿项目不进广场，**未质押的代币在对外任何页面上都不可见**。而未质押代币恰恰是平台资产总量里占比最大的部分。

资产广场补的就是这一面：**按「代币」这个视角，公开展示本平台已同步到的全部代币资产。**

### 3.2 产品定位

| 项 | 口径 |
| --- | --- |
| 一句话 | 按「代币」视角公开展示**借贷平台已同步到的全部代币资产**的只读门户 |
| 主对象 | **按代币业务编号识别的一笔代币记录**，每笔有独立代币数量（枚）；一笔不等于一枚 |
| **数据性质** | **上游数据的只读副本**。代币事实的权威在代币发行平台，本平台只持有同步过来的副本（`D-AM-47`） |
| **展示范围** | **上游同步过来的全集**。本平台**没有上架闸门**、没有运营挑选（`D-AM-48`） |
| 与借贷广场的分工 | **借贷广场看融资项目，资产广场看代币记录。** 借贷广场回答"谁在融资、融多少、池子够不够"；资产广场回答"平台上到底有哪些真实资产、每一笔是什么、现在被用在哪里" |
| 与我的控制台的分工 | **控制台是「我的」，广场是「全平台」。** 字段口径复用同一套定义，不另立第二套（`D-AM-44`） |
| 与代币发行平台代币清单的分工 | 同一批数据的**运营视角**与**公开视角**。运营侧保留签发收币快照与诊断字段；公开侧本轮增加本代币持有地址表，不公开签发诊断字段；两侧分属两个平台 |
| 产品形态 | Web 公开层，桌面 + 移动自适应（借贷平台面客公开层母版） |
| 页面数 | **2**：`P-F-AM-01` 资产广场列表页（含头部汇总）、`P-F-AM-02` 代币详情页 |
| 性质 | **纯只读。零写操作、零业务动作。** 唯一的出站动作是深链借贷广场、以及外链区块浏览器 |

### 5.4 `D-AM-11` 代币状态取上游同步数据，质押状态取本平台自有数据

> `V1.0` 的原条款是「读借贷广场 `PL-*`、不读代币侧 `D-TI-24`」的**二选一**；三平台拆分后这条升级为**数据主权边界声明**。

| 轴 | 取自 | 说明 |
| --- | --- | --- |
| **代币状态**（`有效`/`失效`） | **上游同步数据**（代币发行平台） | 失效判定（对应应收账款已过到期日）在上游算，本平台**只读取判定结果**，`D-AM-51` |
| **质押状态**（`未质押`/`已质押`） | **本平台自有质押记录** | 质押业务发生在本平台借贷广场，属本平台数据主权，本模块以代币编号关联本平台质押记录读取 |
| 明确禁止 | **不取上游数据里的质押状态** | 代币记录上的质押状态是本平台业务产生、再同步给上游的结果，回头去读它等于绕一圈读自己的旧值（`D-AM-57`） |
| 错了会怎样 | 回读上游的质押状态会把**所有已质押代币显示成未质押**（上游该字段的历史默认值），且与借贷广场上同一笔代币的展示直接矛盾 | |

`AC-AM-03`【红线】：构造一张在本平台质押记录中为「已质押」且链上转移「成功」的代币，资产广场列表与详情**必须显示「已质押」**；同一场景显示「未质押」即不通过。

### 5.5 `D-AM-12` 质押状态的业务口径以本平台定义为准

> 需求方 2026-09-18 裁定「独立的平台，以本模块为主」——质押是本平台的业务，**质押状态的语义由本平台定义，全平台统一采用**。参考基线里代币侧另有一套语义相反的质押状态取值，**不再沿用**；`V1.0` 的「只读中文标签、不碰编号」绕法随之作废。

**统一的业务状态值（质押状态轴，权威方＝借贷平台）：**

| 状态值 | 业务语义 | 对外展示 |
| --- | --- | --- |
| `PS-1` | **可质押**：该代币当前没有生效的质押 | 未质押 |
| `PS-2` | **已质押**：该代币已进入某个融资项目的资产池 | 已质押 |
| `PS-3` | 作废占位，不再使用（原「报价冻结中」，冻结在额度层不在资产层） | 不会出现 |
| `PS-4` | **已释放**：质押业务解除；实际转回和再次质押资格由所属业务判断，本模块不承诺已到账 | 未质押 |

| 编号 | 配套裁定 |
| --- | --- |
| `D-AM-50` | **以上表为质押状态的唯一业务定义**，本平台内部与跨平台沟通一律照此表述；代币侧原有的另一套取值（含把"未质押"记为 `PS-0`）**不再使用** |
| `D-AM-51` | **质押状态与代币状态是两套不同的业务状态，各有唯一权威方**：质押状态属借贷平台，代币状态属代币发行平台。**任何一方不持有对方那套状态的第二份定义**（状态机见图 `ST-AM-01`、`ST-AM-02`） |
| `D-AM-56` | **状态值编号不出现在用户可见的任何位置**：界面文案、URL 参数与双语文案只出现中文 / 英文语义标签 |

`AC-AM-04`【反向】：界面文案、URL 参数与双语文案**不出现任何状态值编号**（`PS-` / `TS-` 形态）；质押状态对用户只呈现「未质押 / 已质押」两个取值。

> 本裁定同时是提给跨平台口径维护方的请求（分册 02 `CR-AM-01`）：本模块先按此执行、**不等**统一登记；登记结果若与本表不一致，按 `CR-AM-01` 复核，**本模块不单方面改口径**。

### 5.6 `D-AM-13` 质押对外收敛为二元 + 深链

本平台质押记录有三根轴（质押状态、链上转移状态、底层失效标记）。**三根轴直接搬上公开页面读不懂**，本模块按下表收敛：

| 本平台质押记录状态 | 资产广场对外展示 | 依据 |
| --- | --- | --- |
| 无质押记录（`PS-1` 可质押） | **未质押** | 无记录即未质押 |
| `PS-2` 已质押 且 链上转移**成功** | **已质押** + 「所属融资项目」深链 | 转入成功才计入质押 |
| `PS-2` 已质押 但 链上转移**处理中** | **未质押**（保守） | 入池处理中不预先计入 |
| `PS-2` 已质押 但 链上转移**失败** | **未质押** | 链上没成，业务上不成立 |
| `PS-4` 已释放 | **未质押** | 待提取标记不对外 |

| 编号 | 裁定 | 理由 |
| --- | --- | --- |
| `D-AM-14` | **链上转移状态不对外展示** | 它是链上过程态。公众看到「处理中」既不能做什么、也无从判断要等多久 |
| `D-AM-15` | **待提取、对账差异、失败原因、实际 gas、撤回预扣一律不对外** | 都是资产方自己的处置事务与运营诊断字段 |
| `D-AM-16` | **质押状态与代币状态是两根独立的轴，不合并成一列、不合并成组合枚举** | **一笔代币记录可以同时是「失效 + 已质押」** |
| `D-AM-17` | **本模块不会遇到「冻结」** | `PS-3` 已作废，冻结在额度层不在资产层。**不为它留任何字段、标签、筛选项或文案** |

`AC-AM-05`【反向】：全文检索页面、字段表与双语文案，**不出现**「冻结」「报价冻结」「锁定中」「处理中」「待提取」「对账差异」「gas」「失败原因」等取值或列。

### 5.8 `D-AM-06` 融资需求对外状态五值不适用本模块

### 6.3 典型场景

- **S1 体量判断**：游客打开列表页 → 头部读到「代币数量 1,284.00 枚 / 代币价值 1,284.00 USD（按各笔签发时汇率折算）/ 其中失效 62.00 枚」→ 明确知道总价值里含失效部分、且这个价值不是实时市值。
- **S2 逐笔核实**：游客筛「代币状态 = 有效」+「质押状态 = 未质押」，按代币价值倒序 → 点开第一行 → 详情页读到代币编号、代币价值、底层买卖双方与账期 → 复制铸造交易哈希 → 点区块浏览器外链（新窗口）→ 在链上看到这笔铸造。
- **S3 顺着代币找到融资**：游客在详情页看到「已质押」→ 点「所属融资项目」→ 跳借贷广场融资需求详情。
- **S4 失效且已质押**：代币的底层应收账款已过到期日 → 上游把代币状态推成「失效」；同时它仍在某个已发布项目的池里 → 质押状态「已质押」。**两个标签同时出现，是正确的**（`D-AM-16`）。
- **S5 已质押但项目是草稿**：资产方建池时质押了首笔代币但还没发布 → 质押状态显示「已质押」，但**不给深链**、给一句「所属融资项目尚未公开」（`E-AM-03`）。
- **S6 上游失效翻转**：某笔代币的应收账款今日到期 → 代币发行平台当日判定为失效并同步过来 → 列表该行、详情页标签与头部「其中失效」**当日一致翻转**（`D-AM-57`、`AC-AM-59`）。
- **S7 新代币同步**：代币发行平台铸造并同步一张新代币 → **本平台无需任何操作**，该代币直接出现在列表与汇总中（`AC-AM-65`）。

### 7.1 代币是怎么出现在资产广场上的（图 `FL-AM-01`）

资产方在资产可信平台完成应收账款确权并上链存证；代币发行平台据此铸造代币，并把代币及其展示所需的业务信息同步给借贷平台；**同步到即可见**——本平台没有上架闸门、无需任何运营动作（`D-AM-48`）。代币失效由代币发行平台判定，**失效当日**同步到本平台并反映在列表、详情与头部汇总上（`D-AM-57`、`D-AM-58`）。本平台**每日至少核对一次**代币数量合计（枚）与代币价值合计，不一致时一律以代币发行平台为准修正后展示（`D-AM-59`）。

质押状态不走这条路：它是本平台自己的融资业务产生的事实，直接取本平台质押记录（`D-AM-11`）。

### 7.2 访客怎么用这两个页面（图 `FL-AM-02`）

顶栏「资产广场」、外部分享链接、搜索引擎结果都可直达列表页；点击列表行中编号以外的区域（含 logo）进详情页；点击编号仅复制完整值并反馈结果；详情页的出站动作只有两个——已质押时跳借贷广场的所属融资项目、以及新窗口打开区块浏览器自行查验。顶部登录与页尾引导 CTA 均由用户主动点击才进入登录 / 注册（`D-AM-52`）。借贷广场**不提供**反向入口（`X-AM-10`）。

### 7.3 两根状态轴（图 `ST-AM-01`、`ST-AM-02`）

代币状态（`有效` / `失效`）与质押状态（`未质押` / `已质押`）是**两根正交的轴，不合并成一列**：一笔代币记录可以同时是「失效 + 已质押」（`D-AM-16`）。质押侧上游有三种过程情形（链上转移处理中、失败、已释放），对外**一律收敛显示为「未质押」**（`D-AM-13`）。

### 7.4 列表页视图状态（图 `ST-AM-03`）

列表在内嵌区域向下滚动并连续追加，**每批 20 条**；筛选、排序或搜索条件变化后展示新条件的首批并回到列表顶部。筛选、排序与关键词支持 URL 分享；刷新、分享后打开、浏览器前进后退及从详情页返回均恢复**对应条件、已加载范围与内嵌列表滚动位置**，不依赖页码（`D-AM-22`）。首批、追加中、追加失败可重试与加载结束的完整规则统一见[分册 01 9.1.3](01-功能需求说明.md#913-筛选排序搜索与内嵌滚动加载)。结果为 0 时仍区分**全局空态**与**筛选空态**，后者提供「重置筛选」（`E-AM-01`、`E-AM-02`）。

### 7.5 当前唯一链上持有地址与项目关系（图 `FL-AM-03`）

进入本代币详情，只展示该笔当前唯一链上持有地址及其整笔数量、签发价值。一个地址持有其他代币，或本笔先后关联过多个项目，都不增加本详情的当前行数与数量价值；零余额历史地址不列入。质押状态与当前项目取本平台有效业务关系，已释放则未质押、项目“—”，地址只有在实际转回事实到位后才变化。当前地址为合约不自动代表已质押。事实缺失、同一笔同时多地址或多有效项目按 `E-AM-12`，不取第一条充数。Q-AM-55 已关闭，Q-AM-56 仅保留事实供给与核对依赖。
