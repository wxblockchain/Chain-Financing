#### 9.1.1 头部汇总（`F-AM-02` / `C-F-AM-01`）

| 统计项 | 取值 | 口径 |
| --- | --- | --- |
| **代币数量** | 当前展示集合的代币笔数 | **单位「张」**。一张代币整张质押，以张为单位。**含失效代币**；范围＝经 `X-03` 同步进来的全集（`D-AM-48`） |
| **代币价值** | 展示集合的代币价值合计 | **USD**。各笔签发时快照金额加总，**永不重算**、本平台不折算第二次 |
| **其中失效** | 代币状态 = 失效 的笔数 | 单位「张」。既然汇总含失效，就必须让人看得出含了多少 |

**三条强制标注（`D-AM-23`）：**

| # | 标注 | 理由 |
| --- | --- | --- |
| 1 | 代币价值旁必须标注「**按各笔签发时汇率折算**」 | 防止被读成实时市值 |
| 2 | **出现第二类合约时，本汇总改为分组展示或停止求和** | 代币数量在不同合约之间不可相加。本期只有一个合约，求和成立；这条是**写进 PRD 的前置条件**，不是将来再议 |
| 3 | 空态下头部**显示 0，不隐藏整块** | 空态是一等状态 |

> **不得相加的三个量**：代币数量、代币价值（USD）、应收账款原币金额。三者在任何汇总、排序中不得相加。
>
> **汇总数的准确性依赖第 10 章**：`X-03` 若只推首次上架，「其中失效」会长期偏低、「代币数量」会漏掉上游后续变更，**且页面上无从察觉**。这正是 `IF-AM-01`～`IF-AM-04` 被定为硬性要求的原因。

#### 9.2.1 分区顺序

按访客的判断路径排：**这是什么 → 它值多少 → 底层是什么生意 → 现在被用在哪 → 怎么自行验证**。

| 区 | 内容 | 关键约束 |
| --- | --- | --- |
| **概览** | logo 48×48 + 代币名称 + 代币编号（完整 + 可复制）+ 代币状态标签 + 质押状态标签 | 两个状态标签旁以小字给**判定依据**（如「对应应收账款已于 {到期日} 到期」） |
| **代币信息** | 代币数量、代币价值（USD）、代币类型、所属合约（名称 + **完整地址可复制**）、所属链（`ETH`，只读无选择控件）、**铸造交易哈希**（缩略 + 复制 + 区块浏览器）、铸造时间（带时区标注） | 哈希字面必须是「**铸造交易哈希**」，**页面任何位置不出现无限定词的「交易哈希」** |

| **链上存证** | 存证哈希、**链上存证交易哈希**、区块高度、链 ID、存证时间 | 与铸造交易哈希是**两笔不同的交易**，两者**都必须带限定词**。这是详情页最容易看错的一处 |
| **当前质押信息** | 质押状态（二元）；已质押时给「所属融资项目」深链 | 链上转移状态、待提取、对账差异、gas、失败原因、撤回预扣**一律不展示**（`D-AM-15`） |
| **页尾引导 CTA** | 单个，见 9.3 | 不得遮挡、模糊、截断任何信息 |

#### 9.2.2 链上凭证的展示形态（`F-AM-08` / `C-F-AM-04`）

| 字段 | 展示形态 | 依据 |
| --- | --- | --- |
| **所属合约** | 合约名称 + **合约地址完整展示 + 可复制**（不缩略） | 合约地址是平台自身的公开部署信息，不是用户数据；这是链上地址缩略规则的唯一例外 |
| **所属链** | 只读展示 `ETH`，**不给选择控件** | 本期恒为单值 |
| **铸造交易哈希** | **缩略前 10 后 8** + 可复制 + 区块浏览器外链（新窗口） | 国际化基线哈希缩略规则 |
| **链上存证交易哈希** | 同上，**且必须带限定词区分** | 两笔交易不可混 |
| **区块浏览器链接** | 旁边**常驻**「平台未核验该交易，链接仅供自行查验」 | `D-AM-19`；链接 URL 取 ETH 固定前缀 |
| **收币地址 / 持有人地址** | **不展示** | `D-AM-08` |

`D-AM-24`【反向】：资产广场是平台对外可信度最高的页面，一旦措辞暗示平台背书了链上交易，风险比在登录后的抽屉里大得多。全文检索页面与文案，**不得出现**「已核验」「已上链确认」「交易有效」「平台已审核」等字样（验收 `AC-AM-38`）。

### 9.5 数据实时性与时区

| 项 | 口径 |
| --- | --- |
| 实时性 | **非实时读链、非实时回查上游。** 数据取本平台快照库，准实时；与上游的一致性由 `X-03` 的状态变更事件 + 定期对账保证（第 10 章） |

## 10. 对 `X-03` 的硬性接口要求（`IF-AM-01`～`IF-AM-09`）

> `X-03`（代币上架/发布：代币发行平台 → 借贷平台）在跨平台接口清单中仍标 `[缺口]`。本章是**本模块作为消费方提出的产品级硬性要求**：规定必须传什么、什么时候传、不传会怎样，**不规定协议、报文格式、存储与实现方式**。
>
> **这不是建议项。** `IF-AM-01`～`IF-AM-05` 任一未满足，头部汇总的「代币数量」「其中失效」与列表的「代币状态」列会**长期偏差且在页面上无从察觉**——这正是需求方要求把本条写成硬性要求的原因。

| 编号 | 要求 | 不满足的后果 |
| --- | --- | --- |
| `IF-AM-01` | **事件覆盖面：`X-03` 不得只推首次上架。** 必须覆盖三类事件：① **首次上架**（新铸造的代币）；② **代币状态变更**（`有效 → 失效`，以及将来的 `→ 已销毁`）；③ **快照字段修正**（上游对已同步代币的任何字段更正） | 只有 ① 时，代币一旦失效，本平台永远显示「有效」，「其中失效」恒为 0 |
| `IF-AM-02` | **失效判定的单一来源与时效**：失效判定在代币发行平台完成，**本平台不自行计算**；上游必须在判定翻转**当日**推送状态变更事件 | 本平台自行判定会形成第二套判定，两平台对同一张代币给出不同状态 |

| `IF-AM-04` | **对账口径三项**：① 代币**张数**；② 代币价值**合计**；③ **逐张代币状态**。三项都要对，缺一项即视为对账不成立 | 只对张数会漏掉状态漂移；只对状态会漏掉漏推的代币 |
| `IF-AM-05` | **幂等与顺序**：幂等键 = 代币编号；重复事件返回成功语义、不产生第二条记录；**事件乱序到达时以上游事件时间为准，旧事件不得覆盖新状态** | 乱序覆盖会把已失效的代币改回「有效」，且下一次对账前无从察觉 |

| `IF-AM-07` | **不得携带的内容**：`X-03` 报文**不得携带任何质押状态字段**（质押状态权威在本平台，`D-AM-11`）。若报文出于其他模块需要携带持有人地址等字段，**本模块不消费、不展示、不落入任何对外返回**（`D-AM-08`）。合同号、发票号、提单号、附件影像、贸易背景描述与备注**本模块不要求携带** | 携带质押状态会诱使实现方回读上游，`AC-AM-03` 红线当场失守 |
| `IF-AM-08` | **本模块不向 `X-03` 提出上架闸门相关的任何能力要求**：不要求上架审核回执、不要求下架指令、不要求可见性开关——本平台没有闸门（`D-AM-48`） | 增加闸门即改变「全部代币」的含义，与需求方 2026-09-18 的裁定相悖 |
| `IF-AM-09` | **接口未就绪时不接受降级上线**：`IF-AM-01`～`IF-AM-05` 未满足时，`AC-AM-21`、`AC-AM-23`、`AC-AM-59`～`AC-AM-61` 不可能通过，**属未达验收**；不得以"上游接口未就绪"为由放行本模块上线 | 一个数字长期错误的对外证明面，比没有这个页面更伤可信度 |

**本模块反提给 `X-03` 的字段范围**（第 5 条改造点的收口）：详情页与列表页所需字段的**逐字段清单在第 11.7 节**，该清单即本模块对 `X-03` 快照范围的正式请求，**不留"随快照带过来还是本平台回查"的开放项**——一律随快照带过来（`D-AM-49`）。

## 12. 公开集合、枚举与跨平台消费约定

### 12.1 公开集合的定义

`D-AM-32`【本模块的公开集合】：

> **全量公开的范围** = 资产广场列表页与代币详情页上展示的代币身份信息、其底层应收账款的商务要素、链上凭证与当前质押状态；
> **不含**：收币地址 / 持有人地址、合同号与发票号、提单号、附件影像件、贸易背景描述与备注、应收账款编号、来源资产 ID、上游事件时间与同步/对账状态、签发过程与运营端诊断字段、质押过程的链上过程态与处置事务字段、他人控制台数据、授信额度与联系人联系方式。

| 编号 | 条款 |
| --- | --- |
| `D-AM-33` | 公开集合**之内**的字段：游客与任意登录态**字段集合、字段取值、脱敏形态、可用筛选与排序项完全一致**；**不脱敏、不区间化、不截断、不限制行数** |
| `D-AM-34` | 公开集合**之外**的字段：对**所有人**（含登录态）在本模块内都不展示。**它们不是被藏起来了，是不属于这两个页面**——因此不构成对"完全一致"的违反 |
| `D-AM-35` | **一致性在服务端成立**，不是在前端拼出来的。前端隐藏 / 置灰 / 截断均不构成一致性证明 |
| `D-AM-54` | **同步与对账状态不进公开集合**：最后同步时间、对账差异、快照版本号等一律**不在对外页面展示**（运营诊断字段）；同步异常时的页面表现按 `E-AM-11` |

### 12.2 枚举与常量

| 项 | 取值 | 权威方 | 本模块的处理 |
| --- | --- | --- | --- |
| **代币状态** | `有效`(`TS-1`) / `失效`(`TS-2`)（`已销毁 TS-3` 本期无来源） | 代币发行平台 | 二值展示；**对外只出中文/英文语义标签，不出编号** |
| **质押状态** | `PS-1` 可质押 / `PS-2` 已质押 / `PS-4` 已释放（`PS-3` 作废占位） | **本平台** | 对外收敛为二元 `未质押` / `已质押`，映射见主册 `D-AM-13` |
| **代币类型** | `应收账款类` | 代币发行平台 | 本期唯一取值，保留筛选位 |
| **所属链** | `ETH` | 代币发行平台 | 常量，只展示不给控件、不做筛选 |
| **记账本位币** | `USD` | 本平台记账口径与上游快照一致 | 代币价值恒以 USD 计，**本平台不二次折算** |
| **底层应收账款币种** | 3 位 ISO 4217 | 资产可信平台 | 原样展示，**不与 USD 金额相加** |
| **每页条数** | 常量 **20** | 本模块裁定 | 不提供切换 |
| **哈希缩略** | 前 10 后 8 | 国际化基线 | 两个哈希均适用 |
| **链上地址缩略** | 前 6 后 4 | 同上 | **合约地址是唯一例外**：详情页完整展示 + 可复制 |

### 12.3 `PS-*` 统一定义的消费约定（本版取代 `V1.0` 的降级方案）

> `V1.0` 走的是「只消费中文语义标签、不消费编号、不建映射表」的**降级绕法**，理由是当时两套 `PS-*` 定义同在一个系统内、谁也不能改谁。三平台拆分后靠接口传值，需求方 2026-09-18 裁定「以本模块为主」，本模块因此在契约层**直接统一定义**（主册 `D-AM-12`），**降级方案作废**。

| 编号 | 约定 |
| --- | --- |
| `D-AM-36` | **接口契约层消费统一后的 `PS-*` 编号**（`PS-1`/`PS-2`/`PS-4`），值域与语义以主册 `D-AM-12` 表为唯一定义。**不再维护"只读中文标签"的降级消费方式** |
| `D-AM-37` | **`PS-0` 不是合法取值。** 任何跨平台报文或内部消费中出现 `PS-0`，按契约违例处理，不做兼容映射、不做静默转换 |
| `D-AM-38` | **本模块不新造 `PS-` 取值、不维护第二张编号映射表**；`TS-*` 同理（权威在代币发行平台，本模块只读） |
| `D-AM-39` | **编号不透出对外面**：`PS-*` / `TS-*` 只作用于接口契约与实现内部，**界面文案、URL query、对外返回内容与双语文案一律只出语义标签**（`AC-AM-04`） |

### 12.4 深链消费契约（平台内，不跨平台）

| 编号 | 条款 |
| --- | --- |
| `D-AM-40` | 本模块**消费**本平台借贷广场既有深链契约 `H-01`～`H-05`，**不新造一套**：融资项目 ID 全局唯一、终身稳定、进入终态后仍可寻址；提供 `project/{id}` 锚点；状态已变时落详情页 + Toast，不报 404、不白屏、不静默跳首页；草稿项目返回"内容不存在或无权访问" |
| `D-AM-41` | 本模块**不消费**动作取值（零动作）、**不消费**「返回我的控制台」锚点（本模块不从控制台深链进入） |
| `D-AM-42` | 本模块**不向借贷广场提出任何新增锚点、新增动作或新增参数的要求**。若将来需要"从广场跳到某个池内的某一张代币"，那属于借贷广场的页内定位能力，**届时另提** |
| `D-AM-43` | 本模块**自身的深链**只有两个 URL：`/marketplace/assets`（含 query）与 `/marketplace/assets/{代币编号}`。两者对游客直达可用，**不触发登录回跳、不触发跨平台授权**（`D-AM-52`） |
| `D-AM-55` | **深链目标全部在本平台内**。本模块对外的跨平台跳出只有区块浏览器外链一处；**不深链到代币发行平台或资产可信平台的任何页面** |

| --- | --- |

### 13.3 与借贷广场的边界

| 项 | 口径 |
| --- | --- |
| 对象 | **「张」对「池」**：资产广场的主对象是单枚代币，借贷广场的主对象是融资项目（资产池） |
| 覆盖面 | 借贷广场只收录已发布的融资项目；**未质押代币在借贷广场完全不可见**，那恰是平台资产总量里占比最大的部分 |
| 状态 | 资产广场**不展示**融资需求对外状态（`D-AM-06`），只在已质押时给深链 |
| 数据 | 质押记录是两边**共用的同一份本平台数据**，资产广场只读不写 |
| 方向 | **单向**：借贷广场不提供"查看这枚代币在资产广场的页面"的反向入口（`X-AM-10`） |
