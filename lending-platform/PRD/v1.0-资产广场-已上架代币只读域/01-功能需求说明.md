#### 9.1.1 头部汇总（`F-AM-02` / `C-F-AM-01`）

| 统计项 | 取值 | 口径 |
| --- | --- | --- |
| **代币数量** | 当前筛选、搜索匹配全集中，各代币记录的 `D-TI-11` 合计 | **单位「枚」，2 位小数，含失效代币**；无筛选时为上游同步且满足展示条件的全集（`D-AM-48`、`E-AM-10`）。不按记录条数、已加载行数、地址数或项目数计数 |
| **代币价值** | 展示集合的代币价值合计 | **USD**。各笔签发时的金额加总，**永不重算**、本平台不折算第二次 |
| **其中失效** | 同一筛选、搜索全集中，代币状态为失效的各记录 `D-TI-11` 合计 | 单位「枚」，2 位小数；是上项代币数量的子集，不是失效记录条数 |

`D-AM-64`【本轮修订 · 数量与价值分别汇总】：每笔代币记录在匹配全集内只参与一次数量求和、一次价值求和；按所属地址或质押项目展开不得复制其贡献。排序、连续追加、失败重试和恢复视图不改变匹配全集的汇总；修改筛选或搜索后，三项一起切换到新全集。持有地址表不作为头部汇总的第二个统计来源。空集合为 0，缺值不得冒充 0。

**三条强制标注（`D-AM-23`）：**

| # | 标注 | 理由 |
| --- | --- | --- |
| 1 | 代币价值旁必须标注「**按各笔签发时汇率折算**」 | 防止被读成实时市值 |
| 2 | **出现第二类合约时，本汇总改为分组展示或停止求和** | 代币数量在不同合约之间不可相加。本期只有一个合约，求和成立；这条是**写进 PRD 的前置条件**，不是将来再议 |
| 3 | 空态下头部**显示 0，不隐藏整块** | 空态是一等状态 |

> **不得相加的三个量**：代币数量、代币价值（USD）、应收账款原币金额。三者在任何汇总、排序中不得相加。
>
> **汇总数的准确性依赖第 10 章**：上游只同步"新代币"而不同步后续状态变化时，「其中失效」会长期偏低、「代币数量」会漏掉变更，**且页面上无从察觉**。这正是 `D-AM-57`～`D-AM-59` 被定为硬性业务要求的原因。

| **内嵌滚动加载**（`F-AM-05`） | 列表在页面内的独立区域滚动，向下滚动至已加载内容末端时，**自动按当前筛选、搜索与排序连续追加下一批，每批固定 20 条，无需点击加载按钮**；首次展示首批，最后一批不足 20 条时按实际余量展示。保留前面已加载的记录，不重复、不漏项；没有更多记录时显示结束提示并停止追加。**不提供分页器、页码跳转或批量大小切换**。每批上限沿用 `F-AM-12` 的防批量抓取约束，不改变全部公开记录均可浏览的范围 |

| **加载反馈**（`F-AM-05`、`E-AM-08`） | 首批加载时显示加载中；追加时在列表末尾显示加载中，已有记录与位置保留。追加失败在末尾给出可重试提示，重试成功继续追加本批，不清空已有记录、不回到首批、不重复追加；全部加载完毕与加载失败、无结果空态分别呈现 |
| **视图状态**（`D-AM-22`） | 筛选、排序、搜索关键词保留在 URL 中以支持直达与分享；视图恢复内容为**这些条件、已加载范围及内嵌列表滚动位置**。刷新、分享后打开、浏览器前进后退到列表、从详情页返回时均恢复对应视图，先恢复已加载范围再回到原浏览位置，并可继续加载后续批次。**不以页码表示或恢复加载进度**；无历史视图的首次进入按当前条件展示首批并位于顶部（见图 `ST-AM-03`） |

| **空态** | 全局空态与筛选空态**必须可区分**，后者提供「重置筛选」（`E-AM-01`/`E-AM-02`） |

#### 9.2.1 分区顺序

按访客的判断路径排：**这是什么 → 它值多少 → 底层是什么生意 → 现在被用在哪 → 怎么自行验证**。

| 区 | 内容 | 关键约束 |
| --- | --- | --- |
| **概览** | logo 48×48 + 代币名称 + 代币编号（完整 + 可复制）+ 代币状态标签 + 质押状态标签 | 两个状态标签旁以小字给**判定依据**（如「对应应收账款已于 {到期日} 到期」） |
| **代币信息** | 代币数量、代币价值（USD）、代币类型、所属合约（名称 + **完整地址可复制**）、所属链（`ETH`，只读无选择控件）、**铸造交易哈希**（缩略 + 复制 + 区块浏览器）、铸造时间（带时区标注） | 哈希字面必须是「**铸造交易哈希**」，**页面任何位置不出现无限定词的「交易哈希」** |
| **原始资料信息** | 资产方企业名、买方企业名、应收账款金额 + 币种、账期起始日 ～ 到期日、贸易类型、结算方式 | 逐字段的展示 / 不展示与依据见第 11.3 节；**这些字段必须随代币一并同步到本平台**（`D-AM-61`） |
| **链上存证** | 存证哈希、**链上存证交易哈希**、区块高度、链 ID、存证时间 | 与铸造交易哈希是**两笔不同的交易**，两者**都必须带限定词**。这是详情页最容易看错的一处 |
| **代币持有地址【持有地址要求】** | 详情内五列表：地址、持有数量、对应价值、质押状态、所属融资项目，见 9.2.4 与 11.7 | 替换原质押信息模块，不保留重复模块；本代币范围、同地址归组及不重复统计见 `D-AM-65`～`D-AM-68` |
| **页尾引导 CTA** | 单个，见 9.3 | 不得遮挡、模糊、截断任何信息 |

**设计边界**：沿用用户要求，内容使用可用宽度，不为不存在的操作保留右侧空栏；具体分栏与交互承载由设计师按现行规范决定。持有地址表五项按指定顺序呈现，窄屏也须可读完整的状态与项目对应关系，不把某列永久隐藏。

#### 9.2.2 链上凭证的展示形态（`F-AM-08` / `C-F-AM-04`）

| 字段 | 展示形态 | 依据 |
| --- | --- | --- |
| **所属合约** | 合约名称 + **合约地址完整展示 + 可复制**（不缩略） | 合约地址是平台自身的公开部署信息，不是用户数据；这是链上地址缩略规则的唯一例外 |
| **所属链** | 只读展示 `ETH`，**不给选择控件** | 本期恒为单值 |
| **铸造交易哈希** | **缩略前 10 后 8** + 可复制 + 区块浏览器外链（新窗口） | 国际化基线哈希缩略规则 |
| **链上存证交易哈希** | 同上，**且必须带限定词区分** | 两笔交易不可混 |
| **区块浏览器链接** | 旁边**常驻**「平台未核验该交易，链接仅供自行查验」 | `D-AM-19`；链接 URL 取 ETH 固定前缀 |
| **代币持有地址** | 详情持有地址表展示，前 6 后 4 缩略并可复制完整值；不在链上凭证区重复 | `D-AM-08`、`H-AM-01`；签发实际收币快照不能代替当前持有事实 |

`D-AM-24`【反向】：资产广场是平台对外可信度最高的页面，一旦措辞暗示平台背书了链上交易，风险比在登录后的抽屉里大得多。全文检索页面与文案，**不得出现**「已核验」「已上链确认」「交易有效」「平台已审核」等字样（验收 `AC-AM-38`）。

#### 9.2.4 代币持有地址表（`F-AM-14`，持有地址要求）

**目标与角色**：游客、资产方、资金方在同一代币详情查看同一份当前唯一链上持有事实与当前项目关系，全部只读。仅替换详情原质押信息模块，不改变九列主列表。五列顺序为用户明确要求，具体布局仍由设计师决定。

| 编号 | 完整业务规则 |
| --- | --- |

## 12. 公开集合、枚举与状态口径

### 12.1 公开集合的定义

`D-AM-32`【本模块的公开集合】：

> **全量公开的范围** = 资产广场列表页与代币详情页上展示的代币身份信息、其底层应收账款的商务要素、链上凭证、当前质押状态与本代币持有地址五列信息；
> **不含**：个人/企业账户资料与认证材料（`D-AM-69`），合同号与发票号、提单号、附件影像件、贸易背景描述与备注、应收账款编号、同步与核对一类的内部运维信息、签发过程与运营诊断字段、质押过程的链上过程态与处置事务字段、他人控制台数据、授信额度与联系人联系方式。

| `D-AM-34` | 公开集合**之外**的字段：对**所有人**（含登录态）在本模块内都不展示。**它们不是被藏起来了，是不属于这两个页面**——因此不构成对"完全一致"的违反 |

### 12.1a `D-AM-69` 本人资料与公开业务信息边界（P01）

P01 原话优先：个人、企业信息在借贷平台只能自己查看；其他业务所需信息直接获取，不让用户手动填写，业务信息可以展示。**本模块不增加本人资料页**；游客、资产方、资金方在本模块均只看下表公开业务信息，即使本人打开自己的代币详情，也不追加账户私有字段。本人账户资料按所属账户模块权限查看，公开代币或地址关联不授予他人资料访问权。

| 信息类别 | 本模块展示与获取规则 | 缺失或访问边界 |
| --- | --- | --- |

| **代币状态** | `有效`(`TS-1`) / `失效`(`TS-2`)（`已销毁 TS-3` 本期无来源） | 代币发行平台 | 二值展示；**对外只出中文/英文语义标签，不出编号** |
| **质押状态** | `PS-1` 可质押 / `PS-2` 已质押 / `PS-4` 已释放（`PS-3` 作废占位） | **本平台** | 对外收敛为二元 `未质押` / `已质押`，映射见主册 `D-AM-13` |
| **代币类型** | `应收账款类` | 代币发行平台 | 本期唯一取值，保留筛选位 |
| **所属链** | `ETH` | 代币发行平台 | 常量，只展示不给控件、不做筛选 |
| **记账本位币** | `USD` | 与上游一致 | 代币价值恒以 USD 计，**本平台不二次折算** |
| **底层应收账款币种** | 3 位 ISO 4217 | 资产可信平台 | 原样展示，**不与 USD 金额相加** |
| **每批加载条数** | 常量 **20** | WS-347 用户已确认 | 内嵌列表连续追加；末批按实际余量展示，不提供切换 |
| **哈希缩略** | 前 10 后 8 | 国际化基线 | 两个哈希均适用 |
| **链上地址缩略** | 前 6 后 4 | 同上 | **合约地址是唯一例外**：详情页完整展示 + 可复制 |

### 12.3 质押状态口径的统一（本版取代 `V1.0` 的绕法）

> 参考基线里代币侧与借贷侧各有一套质押状态取值、语义相反。`V1.0` 当时两边都不能改，只好绕开编号、只认中文标签。三平台拆分后需求方 2026-09-18 裁定「以本模块为主」，质押状态的业务定义因此**以本平台为准并统一采用**（主册 `D-AM-12`），绕法作废。

| 编号 | 约定 |
| --- | --- |
| `D-AM-36` | 质押状态的取值与语义**以主册 `D-AM-12` 表为唯一定义**（可质押 / 已质押 / 已释放），本平台内部与跨平台沟通一律照此表述 |
| `D-AM-37` | 代币侧原有的另一套取值（含把"未质押"记为 `PS-0`）**不再使用**，本模块不做兼容映射 |
| `D-AM-38` | 本模块**不新造质押状态取值、不维护第二套状态定义**；代币状态同理，权威在代币发行平台，本模块只呈现 |
| `D-AM-39` | **状态值编号不出现在用户可见的任何位置**：界面文案、URL 参数与双语文案只出现语义标签（`AC-AM-04`） |

### 12.4 跳转规则（均在本平台内）

| 编号 | 条款 |
| --- | --- |
| `D-AM-40` | 「所属融资项目」跳转**沿用借贷广场既有的跳转规则，不新造一套**：项目标识长期稳定、项目进入终态后仍可打开；目标项目状态已变时落到项目详情页并给出提示，**不报 404、不白屏、不静默跳首页**；草稿项目对外一律"内容不存在或无权访问"，因此本模块**不给深链**（`E-AM-03`） |
