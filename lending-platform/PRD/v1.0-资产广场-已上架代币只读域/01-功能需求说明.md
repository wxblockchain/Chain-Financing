#### 9.1.1 头部汇总（`F-AM-02` / `C-F-AM-01`）

| 统计项 | 取值 | 口径 |
| --- | --- | --- |
| **代币数量** | 当前展示集合的代币笔数 | **单位「张」**。一张代币整张质押，以张为单位。**含失效代币**；范围＝代币发行平台同步过来的全集（`D-AM-48`） |
| **代币价值** | 展示集合的代币价值合计 | **USD**。各笔签发时的金额加总，**永不重算**、本平台不折算第二次 |
| **其中失效** | 代币状态 = 失效 的笔数 | 单位「张」。既然汇总含失效，就必须让人看得出含了多少 |

**三条强制标注（`D-AM-23`）：**

| # | 标注 | 理由 |
| --- | --- | --- |
| 1 | 代币价值旁必须标注「**按各笔签发时汇率折算**」 | 防止被读成实时市值 |
| 2 | **出现第二类合约时，本汇总改为分组展示或停止求和** | 代币数量在不同合约之间不可相加。本期只有一个合约，求和成立；这条是**写进 PRD 的前置条件**，不是将来再议 |
| 3 | 空态下头部**显示 0，不隐藏整块** | 空态是一等状态 |

> **不得相加的三个量**：代币数量、代币价值（USD）、应收账款原币金额。三者在任何汇总、排序中不得相加。
>
> **汇总数的准确性依赖第 10 章**：上游只同步"新代币"而不同步后续状态变化时，「其中失效」会长期偏低、「代币数量」会漏掉变更，**且页面上无从察觉**。这正是 `D-AM-57`～`D-AM-59` 被定为硬性业务要求的原因。

#### 9.2.1 分区顺序

按访客的判断路径排：**这是什么 → 它值多少 → 底层是什么生意 → 现在被用在哪 → 怎么自行验证**。

| 区 | 内容 | 关键约束 |
| --- | --- | --- |
| **概览** | logo 48×48 + 代币名称 + 代币编号（完整 + 可复制）+ 代币状态标签 + 质押状态标签 | 两个状态标签旁以小字给**判定依据**（如「对应应收账款已于 {到期日} 到期」） |
| **代币信息** | 代币数量、代币价值（USD）、代币类型、所属合约（名称 + **完整地址可复制**）、所属链（`ETH`，只读无选择控件）、**铸造交易哈希**（缩略 + 复制 + 区块浏览器）、铸造时间（带时区标注） | 哈希字面必须是「**铸造交易哈希**」，**页面任何位置不出现无限定词的「交易哈希」** |
| **原始资料信息** | 资产方企业名、买方企业名、应收账款金额 + 币种、账期起始日 ～ 到期日、贸易类型、结算方式 | 逐字段的展示 / 不展示与依据见第 11.3 节；**这些字段必须随代币一并同步到本平台**（`D-AM-61`） |
| **链上存证** | 存证哈希、**链上存证交易哈希**、区块高度、链 ID、存证时间 | 与铸造交易哈希是**两笔不同的交易**，两者**都必须带限定词**。这是详情页最容易看错的一处 |
| **当前质押信息** | 质押状态（二元）；已质押时给「所属融资项目」深链 | 链上转移状态、待提取、对账差异、gas、失败原因、撤回预扣**一律不展示**（`D-AM-15`） |
| **页尾引导 CTA** | 单个，见 9.3 | 不得遮挡、模糊、截断任何信息 |

#### 9.2.2 链上凭证的展示形态（`F-AM-08` / `C-F-AM-04`）

| 字段 | 展示形态 | 依据 |
| --- | --- | --- |
| **所属合约** | 合约名称 + **合约地址完整展示 + 可复制**（不缩略） | 合约地址是平台自身的公开部署信息，不是用户数据；这是链上地址缩略规则的唯一例外 |
| **所属链** | 只读展示 `ETH`，**不给选择控件** | 本期恒为单值 |
| **铸造交易哈希** | **缩略前 10 后 8** + 可复制 + 区块浏览器外链（新窗口） | 国际化基线哈希缩略规则 |
| **链上存证交易哈希** | 同上，**且必须带限定词区分** | 两笔交易不可混 |
| **区块浏览器链接** | 旁边**常驻**「平台未核验该交易，链接仅供自行查验」 | `D-AM-19`；链接 URL 取 ETH 固定前缀 |
| **收币地址 / 持有人地址** | **不展示** | `D-AM-08` |

`D-AM-24`【反向】：资产广场是平台对外可信度最高的页面，一旦措辞暗示平台背书了链上交易，风险比在登录后的抽屉里大得多。全文检索页面与文案，**不得出现**「已核验」「已上链确认」「交易有效」「平台已审核」等字样（验收 `AC-AM-38`）。

### 9.5 数据实时性与时区

| 项 | 口径 |
| --- | --- |
| 实时性 | **不读链、不临时向上游取数。** 页面取本平台已同步的数据，准实时；与上游的一致性由「失效当日可见 + 每日至少核对一次」保证（第 10 章 `D-AM-57`～`D-AM-59`） |
| 代币状态的按日翻转 | 「失效 = 对应应收账款已过到期日」的判定在**代币发行平台**发生。本模块**只读取判定结果，不自行计算、不按日扫描、不缓存出第二套判定**（`AC-AM-60`） |
| 时区 | UTC 存储，按时区渲染 **+ 显式时区标注**，**无裸时间**。**游客无账户时区，取浏览器时区** |

## 10. 代币数据来源与同步时效要求

> 本章说明**本模块需要代币发行平台提供什么业务能力、什么时候提供、拿不到时用户看到什么**。接口形式、报文与实现方式不在本 PRD 内定义，由实现方按跨平台能力清单（`X-03`）落地。业务流程见图 `FL-AM-01`。

| 编号 | 业务要求 | 不满足时用户看到什么 |
| --- | --- | --- |
| `D-AM-57` | **新代币同步到即可见，失效当日即可见。** 代币发行平台新铸造的代币同步过来后即进入展示范围；代币**失效当日**必须在本模块的列表、详情与头部汇总上同时反映出来 | 代币失效了页面还写「有效」，头部「其中失效」长期为 0，对外资产体量被高估且无从察觉 |
| `D-AM-58` | **失效判定不在本平台。** 失效（对应应收账款已过到期日）由代币发行平台判定，本平台**只呈现上游给出的代币状态**，不自行计算、不按日扫描、不缓存出第二套判定 | 两个平台对同一张代币给出不同状态，谁也说不清哪个对 |

| `D-AM-60` | **状态不回退。** 上游的代币状态更新**不得被更早的状态覆盖**；用户最终看到的是上游最新状态 | 已失效的代币被改回「有效」，下一次核对前无从察觉 |
| `D-AM-61` | **展示所需字段随代币一并到位。** 两个页面展示的全部业务字段（第 11.2～11.4 节，含底层应收账款商务要素与链上存证信息）必须随代币同步到本平台；**关键业务字段**（代币编号、代币数量、代币价值、代币状态、铸造交易哈希、铸造时间）缺失的代币**不展示、不计入头部汇总**，非关键字段缺失的代币**照常展示**、缺项显示"—"（`E-AM-07`、`E-AM-10`） | 详情页开天窗，或出现只有半条信息的代币行 |
| `D-AM-62` | **上游不可用时不清空、不报错。** 数据同步中断或核对未完成时，页面继续展示**最近一次可用的数据**；同步与核对状态属内部运维信息，**不对外展示**（`D-AM-54`、`E-AM-11`） | 公开页面因上游抖动而空白或报错 |
| `D-AM-63` | **不接受"上游没做"的降级上线。** 上述要求未满足时，`AC-AM-59`～`AC-AM-62`、`AC-AM-64` 无法通过，**属未达验收**；不以"上游能力未就绪"为由放行本模块上线 | 一个数字长期错误的对外证明面，比没有这个页面更伤可信度 |

## 12. 公开集合、枚举与状态口径

### 12.1 公开集合的定义

`D-AM-32`【本模块的公开集合】：

> **全量公开的范围** = 资产广场列表页与代币详情页上展示的代币身份信息、其底层应收账款的商务要素、链上凭证与当前质押状态；
> **不含**：收币地址 / 持有人地址、合同号与发票号、提单号、附件影像件、贸易背景描述与备注、应收账款编号、同步与核对一类的内部运维信息、签发过程与运营诊断字段、质押过程的链上过程态与处置事务字段、他人控制台数据、授信额度与联系人联系方式。

| 编号 | 条款 |

| **质押状态** | `PS-1` 可质押 / `PS-2` 已质押 / `PS-4` 已释放（`PS-3` 作废占位） | **本平台** | 对外收敛为二元 `未质押` / `已质押`，映射见主册 `D-AM-13` |
| **代币类型** | `应收账款类` | 代币发行平台 | 本期唯一取值，保留筛选位 |
| **所属链** | `ETH` | 代币发行平台 | 常量，只展示不给控件、不做筛选 |
| **记账本位币** | `USD` | 与上游一致 | 代币价值恒以 USD 计，**本平台不二次折算** |
| **底层应收账款币种** | 3 位 ISO 4217 | 资产可信平台 | 原样展示，**不与 USD 金额相加** |
| **每页条数** | 常量 **20** | 本模块裁定 | 不提供切换 |
| **哈希缩略** | 前 10 后 8 | 国际化基线 | 两个哈希均适用 |
| **链上地址缩略** | 前 6 后 4 | 同上 | **合约地址是唯一例外**：详情页完整展示 + 可复制 |

### 12.3 质押状态口径的统一（本版取代 `V1.0` 的绕法）

> 参考基线里代币侧与借贷侧各有一套质押状态取值、语义相反。`V1.0` 当时两边都不能改，只好绕开编号、只认中文标签。三平台拆分后需求方 2026-09-18 裁定「以本模块为主」，质押状态的业务定义因此**以本平台为准并统一采用**（主册 `D-AM-12`），绕法作废。

| 编号 | 约定 |
| --- | --- |
| `D-AM-36` | 质押状态的取值与语义**以主册 `D-AM-12` 表为唯一定义**（可质押 / 已质押 / 已释放），本平台内部与跨平台沟通一律照此表述 |
| `D-AM-37` | 代币侧原有的另一套取值（含把"未质押"记为 `PS-0`）**不再使用**，本模块不做兼容映射 |
| `D-AM-38` | 本模块**不新造质押状态取值、不维护第二套状态定义**；代币状态同理，权威在代币发行平台，本模块只呈现 |
| `D-AM-39` | **状态值编号不出现在用户可见的任何位置**：界面文案、URL 参数与双语文案只出现语义标签（`AC-AM-04`） |

### 12.4 跳转规则（均在本平台内）

| 编号 | 条款 |
| --- | --- |
| `D-AM-40` | 「所属融资项目」跳转**沿用借贷广场既有的跳转规则，不新造一套**：项目标识长期稳定、项目进入终态后仍可打开；目标项目状态已变时落到项目详情页并给出提示，**不报 404、不白屏、不静默跳首页**；草稿项目对外一律"内容不存在或无权访问"，因此本模块**不给深链**（`E-AM-03`） |

| `D-AM-43` | 本模块**自身可被直达的地址**只有两个：资产广场列表页（含视图参数）与代币详情页。两者对游客直达可用，**不触发登录回跳、不触发授权跳转**（`D-AM-52`） |
| `D-AM-55` | **跳转目标全部在本平台内**。对外的跨站跳出只有区块浏览器外链一处；**不跳到代币发行平台或资产可信平台的任何页面** |

### 13.3 与借贷广场的边界

| 项 | 口径 |
| --- | --- |
| 对象 | **「张」对「池」**：资产广场的主对象是单枚代币，借贷广场的主对象是融资项目（资产池） |

| 方向 | **单向**：借贷广场不提供"查看这枚代币在资产广场的页面"的反向入口（`X-AM-10`） |
