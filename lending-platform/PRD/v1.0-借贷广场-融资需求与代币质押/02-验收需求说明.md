## 14. 非功能需求

> **全部继承本平台既有基线，不新设一套。**

| 维度 | 要求 |
| --- | --- |
| **性能** | `P-LS-01` 首屏 ≤ 2 秒（首批 20 条）；派生量页面预览 ≤ 200 毫秒；平台权威重算 ≤ 1 秒返回；**跨平台执行为异步，页面须在 1 秒内给出"已发起 · 处理中"的反馈**，不得表现为卡住 |
| **数据时效与跨平台一致性** | 代币事实取只读代币域，准实时；代币状态变更须及时同步并触发受影响项目的重算（`IF-LS-08`）。**页面渲染不回查上游、不读链**；质押事实以本平台为准，**不回读上游的质押状态**（`IF-LS-10`） |
| **时区与时间** | UTC 存储，按时区渲染 **+ 显式时区标注**，**无裸时间**；游客无账户时区时取浏览器时区。项目有效期、入池有效期按平台统一时区判定并标注 |
| **金额** | 数值 + 币种代码，**不传拼好的字符串**；统一 `USD`、展示 2 位小数、计算过程不提前四舍五入；**代币数量、代币价值、应收账款原币金额三者不得相加**；本平台**不二次折算** |
| **安全 · 鉴权** | ① 全部写动作服务端鉴权，可见不可点与隐藏均不构成校验；② 跨主体隔离按企业主体过滤；③ **转出目的地址恒为质押前的原持有地址，不接受人工指定，界面无该入口**；④ **同一次操作不得产生第二次链上转移、不得二次收费**；⑤ 发起链上执行前必须已展示操作内容与费用预估并经确认 |
| **安全 · 不暴露存在性** | 草稿项目深链直达返回"内容不存在或无权访问"，**不暴露该项目是否存在**；他方主体的质押申请与执行过程一律不可见（`D-LS-36`） |
| **一致性** | 任一时刻 `INV-FIN-01` 必须成立；额度的产生、保持、释放原子无空档；并发下的额度校验基于同一份权威数据串行结算；**跨平台执行结果按张结算，成功张与失败张互不牵连** |
| **可用性** | 执行失败、结果未回写、部分结果三类必须有用户可读反馈，且都回答"费用产生没有""要不要重来""重来要不要再花钱"；额度类拒绝必须给出差额与出路；两段式可中断可续做 |
| **留痕** | 建池、提交与撤回申请、审核结论回写、复核结论、发起执行、**逐张执行结果与实际费用**、业务释放、额度占用与释放、覆盖不足提醒触发与解除、对账差异消费，每一次变化均留痕（动作人、企业主体、时间、前后状态、关联对象、链上凭证、实际费用） |
| **国际化** | 中英双语、**默认英文**，切换不刷新即完成全部替换（含表头、状态标签、空态、提示与费用文案）；语言、时区、日期、数字、金额、链上凭证的展示口径整段引用本平台国际化基线，**本模块不重新定义** |
| **可访问性** | 状态标签**不以颜色为唯一区分**，必须含文本；键盘可达；窄屏列表转摘要卡，**代币编号、代币价值、代币状态、质押覆盖状态不得被折叠隐藏** |
| **组件与响应式** | 全部取本平台自持的面客端组件规范，**本模块不新设计组件**；两个广场的列表统一为**定高内置滚动区 + 每批 20 条**，窄屏（≤900px）交还整页滚动 |
| **防批量抓取** | 公开页面与其数据接口具备按访问来源的速率限制与异常抓取识别：正常浏览不受影响，超阈值降速并要求人机校验；不提供批量导出 |
| **通知** | 按分册 01 12.2 的事件清单投递，**页面标记始终保底**，推送失败不得导致用户完全不知情；本模块**不自定义通知契约** |

## 15. 指标

| 编号 | 层级 | 指标 | 口径 |
| --- | --- | --- | --- |
| `M-LS-01` | 北极星 | **建池转化率 / 发布转化率** | 创建草稿 → 成功发布的比例，两段各统计一次，用于判断是否在第二段流失 |
| `M-LS-14`（**新**） | 北极星 | **质押链路完成率** | 提交申请 → 成功入池的比例，按「审核驳回 / 结论失效 / 复核作废 / 执行失败 / 未回写」拆因分布——这是本版跨平台改造是否成立的主指标 |
| `M-LS-15`（**新**） | 驱动 | **按张执行成功率与失败张的再质押率** | 失败张在 7 日内被重新选入任一池的比例；**该值低说明失败张事实上被卡住了**，与 `D-LS-30` 的设计意图相悖 |
| `M-LS-16`（**新**） | 健康度 | **结果未回写的发生率与滞留时长** | 进入中间态后超过约定观察期仍无结论的笔数与时长分布——它是 `Q-LS-01` 定兜底口径的取数依据 |
| `M-LS-17`（**新**） | 健康度 | **审核周期分布** | 提交 → 结论的时长分布；用于验证 `IF-LS-09` 建议的对外承诺时限是否可承诺 |
| `M-LS-04` | 驱动 | 链上执行成功率 | 入池 / 撤回 / 提取分开统计 |
| `M-LS-05` | 驱动 | 单位融资额的链上成本 | 实际费用合计 ÷ 融资发生额，衡量资产方真实成本负担 |
| `M-LS-02` | 驱动 | 平均池内资产价值 / 平均质押张数 | 按已发布项目统计 |
| `M-LS-03` | 驱动 | 额度利用率 | 项目融资余额合计 ÷ 融资上限合计 |
| `M-LS-06`/`M-LS-07` | 健康度 | 覆盖不足发生率与平均持续时长 / 诱因分布 | 诱因分代币失效、对账差异、其他 |
| `M-LS-08` | 健康度 | 撤回被拒率 | 判断"可撤回上限"是否展示得够清楚 |
| `M-LS-09` | 健康度 | 待提取代币滞留量与时长 | 费用自担下会真实反映"嫌贵不提" |
| `M-LS-10` | 驱动 | 游客 → 注册转化 | 从列表 / 详情的登录引导进入注册的转化 |
| `M-LS-11` | 健康度 | **二次扣费投诉数 / 重复转移发生数** | **应恒为 0** |
| `M-LS-12`/`M-LS-13` | 健康度 | 空池草稿占比 / 需求自动失效率与失效后复发布率 | 前者反映质押链路失败对建池体验的冲击；后者是"判定即失效"实际代价的主要依据 |

## 16. 依赖与风险

### 16.1 依赖

| 编号 | 依赖方 | 依赖内容 | 状态 | 不满足的影响 |
| --- | --- | --- | --- | --- |
| `DEP-LS-01` | **代币发行平台** | `X-04`/`X-05`：审核通过后的链上执行与**按张回写**（`IF-LS-01`～`IF-LS-05`） | ⚠️ **契约未定义** | **本模块的质押链路无法闭环**：能提交、能审核，但代币进不了池，池值恒为 0 |
| `DEP-LS-02` | **本平台只读代币域（资产广场）** | 可质押代币的候选来源与代币字段、代币状态跟随（`IF-LS-06`～`IF-LS-08`） | ✅ 已入库 | 无来源即建不了池；归属标识缺失则可质押清单的归属过滤不可靠 |
| `DEP-LS-03` | 代币发行平台 | **代币失效状态的及时同步** | ⚠️ 关键依赖 | 失效同步延迟或缺失，平台会长期按**高估的抵押物**放贷 |
| `DEP-LS-04` | **运营端质押审核（WS-359）** | 审核结论、驳回原因、留痕（`IF-LS-09`） | ⏳ 已立项、未交付 | **"审核通过才是质押成功"跑不通**，申请永远停在待审核 |
| `DEP-LS-05` | 本平台登录与企业主体体系 | 企业主体标识与其在只读代币域快照中的对应口径（`Q-LS-03`） | ⏳ | 归属判定不可靠，最坏情况是把他人的代币列进可质押清单 |
| `DEP-LS-06` | **本平台面客消息中心** | 触发登记与投递（分册 01 12.2、`CR-LS-06`） | ⏳ 已入库、登记待合入 | 审核通过 / 驳回 / 执行失败三类触达不到；**页面标记保底，但资产方可能 7 天后才发现结论失效** |
| `DEP-LS-07` | 本平台我的控制台 | 深链 `H-01`～`H-05` 的消费方 | ⏳ | 不阻塞本模块；本模块是契约的提供方 |
| `DEP-LS-08` | 后台链上持仓对账 | 差异标记（`PL-16`） | ⏳ 后台自动进行 | 本模块只消费标记，不实现对账 |
| `DEP-LS-09` | 本平台国际化基线与面客端组件规范 | 时间 / 金额 / 凭证展示口径、组件与列表形态 | ✅ 已入库 | — |

### 16.2 风险

| 编号 | 风险 | 处理 |
| --- | --- | --- |
| `R-LS-14`（**新**） | **跨系统事务没有契约，是本版最大的不确定项**：执行、回写、费用归属三件事分属两个平台，任何一处不按 `IF-LS-*` 落地，都会退化成"平台说成了、链上没成"或"钱花了、池子没变"的错配 | `IF-LS-01`～`IF-LS-05` 写死业务结果要求；`GAP-LS-01` 登记为**上线前必须闭合**的缺口；`Q-LS-01` 的兜底口径由需求方与代币发行平台共同裁定 |
| `R-LS-15`（**新**） | **中间态可能长期滞留**：结果不回写时该张代币既不在池里也不能另作他用，资产方的资产事实上被占住，而本期**没有超时收口口径** | 保守呈现 + 明示"请勿重复提交" + 生成运营待办；`M-LS-16` 跟踪滞留时长与发生率，作为 `Q-LS-01` 的取数依据 |
| `R-LS-09` | **二次扣费是最直接的客诉来源**：重复点击、网络重试、未回写后盲目重提都可能造成重复转移，而费用由资产方真金白银承担 | `D-FIN-68` 写死结果要求 + `E-5` 不给重试按钮 + `E-6` 处理中拒绝新动作，三道一起 |
| `R-LS-13` | **审核让"追加质押救覆盖不足"这条自救路径变慢**：判定即失效已无自救窗口，追加还要先过人工审核，等结论期间那批代币不计入覆盖 | `IF-LS-09` 要求给出可承诺的审核时限并在页面显示预期等待；提醒文案直接说明"追加需先经审核"（`D-LS-39`） |
| `R-LS-12` | **判定即失效 ⇒ 资产方没有自救窗口**：诱因（代币失效）与资产方操作无关，一笔已公开的要约可能在他毫不知情时被作废，在途报价一并作废 | 本期缓解两条：失效**必推**通知；失效后**可立即重新发布**，不设冷却。用 `M-LS-13` 跟踪实际代价 |
| `R-LS-10` | **平台记录与链上失配**：有效质押价值是对外公开的数，一旦与链上事实不符，广场展示的覆盖充足性就是错的 | 收到差异标记后按保守原则处理（不计入、冻结动作、重算并告警）；发现失配靠后台对账，不在本模块 |
| `R-LS-16`（**新**） | **两个广场对同一张代币说法不一致**：资产广场的二元展示与本模块的业务判定若各自维护一份数据，会当场自相矛盾 | `D-LS-27`/`D-LS-43` 写死"同一事实只取一处"；`AC-LS-120` 构造同一张代币在两个广场对照的用例 |
| `R-LS-02` | **费用由资产方承担**：批量入池 / 撤回 / 提取有真实成本，费用高企时资产方可能放弃使用或长期不提取 | 批量提交 + 费用前置告知；`M-LS-05`/`M-LS-09` 跟踪 |
| `R-LS-07` | **覆盖不足的主要诱因是代币失效，而平台对失效既无提前量也无处置手段** | 提醒 + 催追加 + `M-LS-07`；处置能力需另行立项（`GAP-LS-03`） |
| `R-LS-08` | **覆盖不足状态公开会对资产方产生真实市场影响** | 限定为中性事实披露；且数据本就公开，隐藏属选择性披露 |
| `R-MC-27`/`R-MC-22` | 质押率硬编码需发版调整；同企业任一员工可动用公司资产并触发费用支出 | 需求方已裁定接受 |

## 17. 缺口处置与修订请求

### 17.1 缺口处置

| 编号 | 缺口 | 谁来补 | **本期怎么做** | **不补的后果** |
| --- | --- | --- | --- | --- |
| `GAP-LS-01` | **`X-04`/`X-05` 跨系统事务契约未定义** | 代币发行平台 + 跨平台契约总册 | 本模块以 `IF-LS-01`～`IF-LS-05` 提出业务结果要求；**不接受"上游未就绪"的降级放行**，也不自行编造超时与重试口径 | **质押链路无法闭环，本模块无法上线** |
| `GAP-LS-02` | **运营端质押审核（WS-359）未交付** | 本平台运营端 | 本模块以 `IF-LS-09` 提出结论三要素与留痕要求；面客端按"提交 + 呈现结论"完成 | 申请永远停在待审核，**"审核通过才是质押成功"在产品上是断的** |
| `GAP-LS-03` | **失效代币的处置能力无任何承接** | 需另行立项 | 本期只能"通知 + 催追加"，处置 / 变现 / 清算完全没有模块 | 覆盖不足只能告知、不能挽回；**这是本期明确接受的口子** |
| `GAP-LS-04` | **企业主体标识的跨平台对应口径未定** | 登录体系 + 只读代币域 | 以 `IF-LS-06` 要求快照携带可稳定比对的主体标识；本期不以企业名称作归属判据 | 归属过滤不可靠，最坏情况是把他人的代币列进可质押清单——**这是资金安全问题，不是体验问题** |
