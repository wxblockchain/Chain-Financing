## 9. 模块详情

### 9.1 `P-LS-03` 创建融资项目（建池）

**入口**：借贷广场列表页与我的控制台（深链 `project/new`）；仅登录资产方可见可点。

| 区域 | 内容 |
| --- | --- |
| 基本信息 | **项目名称**（必填，1～60 字符，同一企业内不要求唯一）、**代币类型**（必选，本期唯一取值「应收账款」，其余取值置灰并标注为本期能力边界） |
| 可质押代币清单 | 按 9.4.1 六项条件筛选后的代币，**按所选代币类型过滤**；支持批量勾选；列与分页同 11.7.1（**不展示合同号 / 发票号**） |
| 提交与费用 | 本次提交的是**质押申请**：**不发生链上操作、不产生任何费用**；同屏给出**两步告知**（9.4.2）与通过后要承担的费用口径 |
| 提交结果 | 成功 → **直接进入该项目详情页 `P-LS-02`**，项目落 `S-FP-1 草稿`（广场不可见），每张形成单笔「待审核」，提交批次仅供追溯 |

| 编号 | 条款 |
| --- | --- |
| `D-FIN-60`（**本版改写**） | **创建时必须至少选中一张代币**，校验对象是**质押申请已提交**，不要求等待审核结论、更不要求等待链上结果。理由：审核与链上执行都跨出本模块，让建池等它们等于把建池的成功率押在两个外部环节上 |
| `D-FIN-77` | **同一项目只能质押同一种代币类型**：创建时显式选定，后续追加只能追加同类型代币 |
| `D-FIN-64` | **草稿项目不进广场**：不进列表、不可搜索，他人与游客深链直达返回"内容不存在或无权访问"，**不暴露该项目是否存在** |
| `D-FIN-62` | **空池草稿**：首笔申请被驳回、撤回或链上执行全部失败时，项目保留为空池草稿，顶部常驻提示"本项目暂无有效质押，请重新提交质押申请后再发布"，发布入口不可点；资产方可重新提交或直接关闭项目（`E-12`） |
| `AC-LS-54`（沿用） | **两段式可中断可续做**：创建成功后不立即发布的，项目留在草稿态，详情页操作区常驻「发布融资需求」入口；**任何一步都不得要求重新质押或重新付一次费用** |

### 9.2 `P-LS-02` 融资项目详情页

关联 `F-LS-11`、`F-LS-18`、`F-LS-20`。项目是广场一行记录及详情页的主体；项目内可先后发布多轮融资申请，并存在不同融资业务及还款期次。面向用户的“融资申请”沿用原融资需求业务，不新增申请审批。统一查看与办理流程见图册 [FL-LS-07](v1.0-借贷广场-融资需求与代币质押-流程图与状态机.md#fl-ls-07)。

| 区域 | 内容与行为 | 可见范围 |
| --- | --- | --- |
| 广场壳与项目摘要 | 导航、返回来源、项目名称及编号、资产方企业、项目有效期和项目状态；当前需求金额与状态单独辨认 | 已公开项目的公开字段，草稿仅本方 |
| 统计区 | 保留9.2.1五项业务统计及质押覆盖事实 | 公开 |
| 项目记录 | 左侧依次纵向展示「质押代币清单 → 融资申请信息 → 融资放款信息 → 还款信息」，随页面自然滚动；提供“质押代币 / 融资申请 / 融资放款 / 还款”定位标签，点击滚动到对应区，不隐藏或切换其他清单；字段见11.7，不加全项目操作日志区 | 公开字段按既有范围；授信、账户、协议和凭证等私有字段按各业务双方权限 |
| 项目操作 | 右侧内嵌「质押 / 融资 / 还款」，三页签恒定保留；只承载当前可办理事项，内容超高时在操作区内滚动，主要入口可达 | 登录后按角色；游客保留页签、统一登录入口 |
| 质押审核与确认 | 位于右侧「质押」的入口；一行一张代币，可跨提交选择；逐笔协议可直接下载，详情/历史在同一业务容器中查看 | 仅本企业资产方 |

**D-LS-52 项目记录与办理分工。** 左侧四类清单纵向展示业务事实，右侧操作页签办理事项。首次进入按上述顺序展示全部清单；来源指定申请、放款或期次时定位相应清单及记录。浏览、分页和详情返回保留各清单独立的筛选与页码，不因操作一张清单重置其他清单；无记录显示对应空态，读取失败提供重试，不混成空态。右侧同一页签有多笔待办时先显示可识别的申请/业务/期次供选择，不凭最近一笔替用户选错对象。从记录或操作区打开同一对象，内容、权限、当前阶段一致。

| 编号 | 条款 |
| --- | --- |
| `D-LS-10` | 公开融资需求与履约事实不包含授信额度、私有账户、协议与凭证文件、他人控制台数据、运营诊断、联系人、底层合同号与发票号；私有资料的查看和下载均需对应权限 |
| `D-LS-36` | 质押申请、审核与执行过程仅本方资产方可见；公开面仅消费代币是否计入覆盖等已公开结果 |
| `AC-LS-01` | 游客、非本企业或非业务当事方不能通过直接访问或提交绕过权限；隐藏/禁用按钮不能替代该结果 |
| `AC-LS-06` | 全量公开不取消企业归属过滤，私有清单和动作按本方企业及业务角色限制 |

#### 9.2.2 项目操作：质押 / 融资 / 还款

| 页签 | 内容 | 业务归属 |
| --- | --- | --- |
| 质押 | 追加质押、质押审核与确认、解除质押、关闭项目；按各自前置条件可用 | 本模块9.4、9.5及既有项目关闭规则 |
| 融资 | 发布/改额/撤下或再次发布融资需求；当前申请的报价、接受/拒绝及放款办理；每项显示申请编号，报价成功后并列业务编号 | 本模块9.2.5、L6、L7；保留发布→报价→报价确认→放款四环节的业务顺序 |
| 还款 | 选择已确认到账业务，显示本期应还或待确认摘要，进入计划、提交还款或确认收到还款 | L8；无业务保留页签和空态，不借用融资环节高亮 |

| 编号 | 条款 |
| --- | --- |
| `D-FIN-78` | 解除质押是撤回与提取的合并入口；容器区分已失效、有效抵押物、已释放待提取，判定按9.5。关闭项目仍按既有终态条件，不因导航调整扩大权限 |
| `D-FIN-48` | 追加质押在项目S-FP-1～S-FP-4按原条件允许；终态追加不可用，解除质押仍按条件可用 |
| `D-FIN-79` / `AC-LS-85` | 针对所选业务，只在当前阶段提供对应角色可办动作；历史可查看但不可办理。不同存量业务可以分别处于不同阶段，不用项目最近一笔状态屏蔽其他业务还款。所有办理按9.2.4的查看与办理规则完成 |
| `D-LS-37` | 中间态不锁整池：某张代币处理中只限制该张，其他动作仍按其资格判定 |

#### 9.2.3 非登录态

`D-LS-14`、`AC-LS-86`：游客可读已公开项目及公开记录，右侧三个页签保留并仅提供一个统一「立即登录」操作，不展示私有待办。直接打开私有详情或文件不能获得权限；草稿不暴露存在性。登录后按来源定位，再核实当前身份及业务阶段。

#### 9.2.4 只读详情、业务办理与资料复用

**D-LS-53 查看与办理分离。** 左侧记录进入右侧只读详情抽屉，仅展示当前记录、历史、计划、账户和文件等有权读取的信息；不保留办理按钮、跨业务跳转按钮或重复快捷查看入口。计划、历史与记录在当前详情展开，文件仍按权限下载/预览。办理集中于项目右侧操作区，使用居中弹窗；控制台待办、通知中的有效办理入口可定位同一对象的操作弹窗。详情与办理不互相套层，同时只显示当前所需容器。用户已明确的纵向清单、右侧操作页签及查看/办理承载保留；具体组件、尺寸、分栏、字段排版和窄屏适配由Hallmark决定。

**D-LS-54 确认、退出与成功结果。** 办理中的步骤、适用的最终确认、放弃未提交修改都在本次操作弹窗内完成，不叠加第二层。返回只退当前步骤并保留已填资料及成功附件；有未提交编辑时关闭先确认放弃，取消放弃继续编辑。关闭回项目原位置，保留清单筛选、分页、滚动及行焦点。详情关闭直接回原清单，不产生业务变更。

成功更新本笔记录与操作区，不能自动打开详情、下一笔或下一阶段。发布成功、质押成功发起、报价成功均关闭本次操作弹窗；授信保存成功关闭并toast提示“已授信，请继续报价”，由资金方再次点击“立即报价”进入报价弹窗并重新校验。报价不设提交二次确认，提交前在表单可见必要后果提示，用户点击提交即执行校验；其他业务原有必要确认不因报价调整而取消。失败保留可复用输入和已成功文件；结果未知不当成功、不引导重复提交。状态变化显示当前事实及原因，不能静默改办其他对象。

**D-LS-55 历史与文件。** 报价历史按条展开本条内容，不替换当前有效报价，不提供接受或恢复历史报价动作。协议表按已有文件展示名称、用途、业务/版本及已有上传时间，点击文件下载；无文件、无权、读取失败分别处理。文件读取不改变业务状态，不附加跨业务快捷入口，不新增在线签署或协议审核。

**D-LS-61 已有信息自动带入。** 平台已知且当前用户有权使用的本笔资料自动填充，不要求重新抄写：企业主体、项目/申请编号、需求金额、已接受条款、已确认账户、钱包地址及本次操作已成功上传的资料。优先使用本笔已确认事实，其次使用相同企业、用途及币种的有效已登记资料；无可靠可复用资料才填写业务必填缺项。只读事实不能改写，可编辑资料保留校验，自动填充不等于代替用户确认。不同机构、不同企业、不同账户用途及不同业务的协议/凭证不得串用；新授信协议和新转账凭证不能默认复用旧业务文件。缺失或读取失败显示真实情况，不用示例、零值或推测补齐。各模块账户明细仍按其定义，自动填充不新增账户管理功能。

操作信息只保留识别当前对象、核对本次金额/币种/必要账户、完成输入、了解费用及不可撤销后果所需内容；不重复堆入完整企业档案、历史业务和弱关联条款。完整业务只读资料可从对应清单按业务权限查阅，个人与企业账户档案仍仅本人可见，不在操作弹窗增加快捷查看入口。各模块定义本步骤具体信息与验收：L6 [功能说明](https://8.216.50.84.nip.io/api/attachments/01a0c35e-cc3d-7ca0-9ed3-f272cdd9d706/download)、L7 [放款PRD](https://8.216.50.84.nip.io/api/attachments/01a0c35e-cc3d-7ca0-9ed3-f272cdd9d706/download)、L8 [还款PRD](https://8.216.50.84.nip.io/api/attachments/01a0c35e-cc3d-7ca0-9ed3-f272cdd9d706/download)。

#### 9.2.5 发布、修改、撤下与再次发布

关联 `F-LS-02`、`F-LS-03`、`D-FIN-61`，图见 [FL-LS-02](v1.0-借贷广场-融资需求与代币质押-流程图与状态机.md#fl-ls-02-发布融资需求)。本企业资产方从「融资」进入，草稿建池完成但未发布时入口持续可见。

| 场景 | 输入、判断与结果 |
| --- | --- |
| 发布 | 融资需求金额必填USD、正数、最多2位小数，无默认建议金额；参考结算币种按D-LS-60必选至少一项；当前可融金额及不足差额只在办理时展示。项目未到期且未终态、有效质押价值>0、无另一笔在途需求、金额不超过当场可融金额才可提交；审核中/执行中代币不计覆盖 |
| 成功 | 首次发布确定项目一年有效期；本轮生成稳定FP-28，项目在途金额按本轮金额增加，申请状态待报价。关闭容器，定位融资申请清单该行，不自动打开报价；失败保留金额、参考结算币种及可读原因，已完成质押不回滚、不重复收费 |
| 改额 | 仅尚未被报价且仍可修改的当前需求；带出原金额和参考结算币种，金额修改仍按最新额度复核；成功更新本轮金额与占用，保留本轮编号，不把修改当新发布。已锁定或进入放款/还款的条款不能在此改写 |
| 撤下 | 仅尚未被报价且仍有效的本轮可执行；同容器最终确认后终结该轮、释放其在途占用，保留原编号及终结原因；不释放其他业务债务或全部项目质押。后续项目可办动作依当前全部事实判断 |
| 再次发布 | 需求失效后无冷却，可在原项目未到期/未终态且满足发布资格时创建新轮次；生成新的FP-28，不覆盖历史申请/报价/成交业务，不重置项目首次发布时间或有效期。已成交且未结清的存量业务继续可在还款清单办理 |

**D-LS-60 参考结算币种（FP-30）。** 资产方发布融资申请时必填多选，至少一项；沿用本期已支持币种USD（法币）、USDT/USDC（数币），可以同时选择法币与数币。首次默认无选中，未选或含不支持项不能提交；同轮编辑自动带出已选项，再次发布可带出本企业上一轮选择供确认/修改，新一轮单独留存。申请详情展示“参考结算币种”并说明仅供资金方参考，不作为实际报价币种的限制或默认确认；资金方仍可独立选择任一已支持报价币种，不能因不在偏好集合中拒绝报价。偏好不影响USD需求金额、额度、汇率锁定、合同与实际结算结果；历史申请无该资料时显示“未提供”，不回填假偏好。实际币种以成功报价及资产方接受的条款为准。

需求失效只结束原轮次：保留原申请编号、报价与终结原因，释放规则沿D-FIN-76；恢复覆盖并满足发布条件后可立即发布新申请，不要求重建项目。项目已到期或终态、覆盖仍不足、有其他在途需求时仍按原条件拦截；失效后的重新发布不能恢复旧报价、重置项目期限或清除存量债务。

申请发布、报价接受、放款登记、到账确认和还款确认分别是不同成功事实，页面切换不能越过任一步。已到期项目继续承接原有存量履约，不借新导航开放新融资。

#### 9.2.6 单笔放款终止后的项目资格与共用日期

**D-LS-64 单笔终止与项目资格（P07）。** 接收L7已经正式成立的本笔终止结果，只移出该笔应释放的占用，不清零整个项目或机构的其他业务。其他在途申请、已成立债务和履约计划继续保留。项目已到期时，不恢复发布、新报价或项目期限；仍有存量业务继续处理，全部存量结束后按既有关闭/结清规则判断。未到期且未终态时，按剩余全部债务、项目在途、有效质押及当前覆盖重新判断，满足既有发布条件才可发新一轮；不得仅因“终止一笔”就改为募集中。整池业务释放仍只能在项目实际进入S-FP-5/6时成立，不按FD-01终止自动触发；正常额度允许的撤回仍按9.5执行。本条不新增终止审批或操作入口。

**D-LS-65 UTC业务日期与金额口径（P10）。** 本平台业务日期判断使用UTC，项目有效期、通过后的七个自然日以及项目届满前七天提醒统一按UTC生成业务截止，再按用户偏好时区展示并明确标注；游客沿浏览器时区展示并标注。切换时区、跨周末或夏令时不改变截止事实。入池截止仍为本笔通过时点按UTC增加七个自然日，不改为用户所在日期日末；本笔尚未发起而到达截止即不得发起。审核仍为提交成功后连续48小时，报价168小时由L6承接，不因自然日规则延长。项目首次发布日期按UTC确定，之后发布新需求不重置一年有效期。代币是否失效仍消费发行平台权威结果，不在L5按本地日期重算。

本模块需求金额与额度沿既定USD两位展示、计算不提前舍入。代币价值沿签发事实，当前唯一地址对应整笔价值，不按汇率或地址数量重新分配。P05本期USD/USDT/USDC固定1:1:1由L6～L8各自承接，不因此改变L5参考币种仅参考的含义；数币最终结算精度和尾差没有已批准具体数值，保留后续模块实际依赖，不自行写成全部两位。费用按真实费用资产精度，未知不填零。

| 5 · 结果 | 实际已执行后按张呈现成功 / 失败 / 未有结果，互不回滚，保留原单笔归属；重复确认不产生第二次转移或收费；成功发起即关闭容器并定位项目记录的质押代币清单，后续逐张查看处理中、成功或失败；不等待全部完成才关闭，不自动打开下一事项 |

**D-LS-51 三类释放不混用**：审核 48 小时失败释放的是未上链的申请占用（PS-1、零费用、无提取）；正常质押后额度允许撤回、项目终态释放与自助提取仍按 9.5；审核记录和真实已转入事实冲突后的**异常释放本期不考虑**，不设计其入口、待办、处理进度、费用或恢复流程。已有差异标记及保护限制不代表提供异常释放功能。

本节与运营端WS-359《代币质押审核PRD》D-PR-32/33（既有依赖资料，未在本轮重修）同源。批量确认不重新生成审核结论、不统一或刷新各张七天截止。内容 / 费用由本平台同一操作弹窗确认步骤承载已明确；Q-LS-02 只保留真实签名所在侧的能力衔接，不把已确认的界面退回两步。


#### 9.4.5 执行结果的按张呈现

| 编号 | 条款 |
| --- | --- |
| `D-LS-30`（主册 5.3） | **按张独立结算**：正常明确成功且当前项目及本笔资格成立的张 → `PS-2 已质押` 并计入有效质押价值；失败张 → 退回 `PS-1 可质押`，**可再次选入本池或其他池**；提交批次不设统管全部代币的成功 / 失败结论；各单笔保留自己的实际结果 |
| `AC-LS-109`（**新**） | 结果呈现必须**逐张**给出四件事：① 这张成了还是没成；② 没成的原因（业务可读，不透出运营诊断字段）；③ **这张是否已经产生费用、金额多少**；④ 下一步能做什么（失败张：重新选入任一池；成功张：已计入覆盖，可在解除质押入口处置）。**不存在只说"部分成功"或"操作失败"的笼统结论** |
| `AC-LS-110`（**新**） | 同一次执行确认内**成功张不因失败张而回滚**；明确失败且无占用的张不继续挂起；无结果或冲突张不在该前提内；构造"2 成 1 败"场景，失败那张**立即出现在另一个项目的可质押清单里** |
| `D-FIN-68`（沿用 · 结果要求） | **同一次操作无论重复提交多少次，都不得产生第二次链上转移、不得二次收费。** 本条只要求结果，**具体机制由实现方决定**，本 PRD 不规定 |
| `D-FIN-40`（**本版改写**） | **质押成立 = 该张代币转入质押合约执行成功并回写**；释放 = 从质押合约转回**质押前的原持有地址**，**不允许人工指定目的地址**。执行由代币发行平台承担，**本平台不接受任何"指定其他地址"的入参与界面入口** |
| `AC-LS-30`（沿用） | **平台侧质押记录永远不领先于链上事实**——撤回不得先置已释放再等回写。**唯一例外是项目终态时的业务释放**（`D-FIN-57` 第一段），它是业务关系的解除而非资产位置的变更，且对外明确标注为"待提取" |

#### 9.4.6 异常仅联系客服，不建设处置流程

**D-LS-63（P03，衔接主册 `D-LS-47`）。** 适用于转入、正常撤回、已释放代币提取的长期无结果、跨入池期限/项目终态、事实冲突，以及部分结果中仍待核实的笔。本期页面告知“执行结果待核实，请联系平台客服人员”，保留当前真实状态、业务编号、代币、本次动作、已知费用和凭证供当事人核对；不编造客服电话、核实完成时限或处理承诺。沿现有客服联系方式能力提供指引，不建设工单、自动升级、人工改判/补记、强制释放、补偿、代付、换地址或恢复资格流程。

客服介入不自动改变审核、链上结果、质押状态或可质押资格。未知仍保持处理中/待核实，不计入新增有效覆盖，不自动失败、重复执行或放开重押；费用未知标待核实。项目终态后返回的转入事实不因此恢复项目或增加有效覆盖，保留真实资产位置并联系客服，不设计自动异常退回。

正常明确结果的逐张呈现与E-1～4仍保留：成功且满足资格的张独立成立，明确失败且确认无占用的张才按资格恢复；正常撤回明确失败撤销本次预扣，正常提取明确失败保持PS-4，不撤销业务释放。混合结果不整批回滚、不将已知成功改成失败，也不把“部分成功”做成一键补偿流程。普通晚到且无跨期/冲突的结果按原笔事实更新；跨期、冲突及仍未知的笔只提供本节保护和客服指引，不宣称本期已完成异常处置。

### 9.5 解除质押（撤回 / 失效清出 / 释放与自助提取）

| 编号 | 规则 |
| --- | --- |
| `AC-FIN-13` | **未失效代币的撤回**：撤回后须满足 `(有效质押价值 − 拟撤回价值) × 80% ≥ 项目融资余额 + 项目在途金额`；用户可读形式是 `拟撤回价值 ≤ 可撤回上限` |
| `D-FIN-59` | **已失效代币**：撤回**不做任何额度判定，直接放行**。两件事互为因果：正因为它本来就不顶覆盖，移出它才不会削弱覆盖 |
| `AC-LS-36` | 解除质押容器**必须分区展示**：「已失效 · 可随时撤回（不计入覆盖）」「有效抵押物 · 受额度限制」「已释放 · 待提取」；第二区顶部常驻"当前最多可撤回 X USD"，勾选时实时累计对照 |
| `AC-LS-37` | 撤回被拒绝时必须给出**三个数**（拟撤回价值、当前可撤回上限、差额）与两条出路（减少勾选 / 等待还款释放余额）。只说"不允许撤回"不合格 |
| `D-FIN-54` ② | 撤回一旦发起执行即**预扣**该部分价值，执行失败回滚才恢复（`E-3`） |
| `D-FIN-57` | **释放两段式**：① **业务释放**（项目进入 `S-FP-5`/`S-FP-6` 的同一时刻，平台解除全部质押占用关系，代币置 `PS-4 已释放 · 待提取`，即时、无链上动作、零费用）；② **链上提取**（资产方自助发起，链上执行由代币发行平台承担、**费用由资产方承担**，支持批量一次提取，**无时间限制、不过期**）。未提取的代币**不属于任何池、不计入任何质押价值、也不能被再次质押** |
| `AC-LS-38` | 存在可提取代币时，在「解除质押」入口上以角标 + 副文案提示张数与金额，并说明需自付费用、可批量一次提完，**不得让资产方以为代币会自动回到钱包** |
| `D-FIN-53` | 撤回 / 提取频次**不设硬性阻断**，改用三道软约束：支持批量一次提交；每次提交前展示张数与费用预估；24 小时内提交超过 5 次时提示"频繁链上操作会产生较多费用"，**不阻断** |
| `D-FIN-49` | **质押释放时点与项目终态绑定**，不提供"某笔业务结清即释放对应代币"的部分释放——额度语义下不存在"对应代币"；某笔结清的效果是余额下降，从而提高可撤回上限 |

| --- | --- | --- |

| **`E-15`（新）** | **同一张代币被重复选入** | 被在途申请或处理中执行占用的代币，在两处可质押清单里**可见但不可选**，并给出占用来源（申请编号 / 处理中）。并发提交时**只有一笔成立** |
| **`E-16`** | **审核 48 小时未完成** | 自本笔提交成功起连续 48 小时仍待审，自动质押失败（审核超时），释放该笔申请占用、保持 / 恢复 PS-1，记录保留、零费用，可按资格新笔重提；不触发 X-05 或 PS-4 提取。同批已处理笔不改变；全部未入池时仍为空池草稿 |

#### 12.2.1 推与不推（业务判断）

| 事件 | 推送 | 收件人 | 理由 |
| --- | --- | --- | --- |
| **质押审核通过 · 待入池** | ✅ 必推 | 提交申请的资产方 | 通过后**还要他回来确认并承担费用才算质押成功**；不推他不会知道要回来，7 天后结论就失效了 |
| **质押审核驳回**（含原因） | ✅ 必推 | 同上 | 否定结论且需要重新提交；**原因原样带上**，否则只能盲目重提 |
| **链上执行失败**（逐张） | ✅ 必推 | 发起该操作的资产方 | 可能发生在用户离开页面之后，且直接关系"费用产生没有、要不要重来" |
| 执行长期无结果 | 暂不新增终态推送 | — | 执行期限与最终收口待 Q-LS-07；页内逐币显示已知事实，不沿旧 execution_timeout 发失败消息 |
| **质押失败（审核超时）**（连续 48 小时未审） | ✅ 必推 | 提交申请的资产方 | 他在等一个不会来的结论；文案须写明**是运营端未在时限内审核**、**本笔未执行、零费用**、申请占用已释放，按资格可再次质押 |
| **融资需求因覆盖不足自动失效** | ✅ 必推 | 资产方 + 该需求上有在途报价的机构 | 诱因与资产方操作无关，且结果是一笔已公开的要约被作废 |
| **覆盖不足提醒触发** | ✅ 必推 | 资产方 + 该项目下有未结清业务的债权机构 | 资产方要尽快补、债权机构有知情权 |
| 覆盖不足**解除** | ✅ 推 | 同上 | 让双方知道窗口已关闭，不必反复追加 |
| 项目有效期届满**前 7 天** | ✅ 推一次 | 资产方 | 这是"还能不能成交"的最后窗口 |
| 链上执行**成功** | ❌ 不推 | — | 按既有通知范围不新增成功推送；发起后关闭容器，结果在质押代币清单可查 |
| 通过后**超时未入池而失效** | ❌ 不单独推 | — | 仅指到期仍未发起的笔，零费用、可按资格重新提交；截止时间已写在通过通知里 |
| 可提取代币提醒 | ❌ 不单独推（页面常驻提示） | — | 资产安全、没有时限；单独推等于催用户去花钱 |
| 项目有效期届满前 30 天 | ❌ 不推（仅页面标记） | — | 太早、无行动价值——本期有效期不可延期 |

通知的完整事件、发送归属、模板及验收以本模块[03通知册](03-融资需求与代币质押-消息通知.md)为准。P03客服指引不是新通知事件；不为长期等待、跨期、部分结果或联系客服重复催办，不新增运营异常广播。覆盖不足导致需求及报价同步失效统一由L5 N-LS-05发送，L6不另发同义通知。

#### 12.2.2 通知定位与有效性

既有通知类型与分类引用面客消息中心RG-NC-01～12及本模块CR-LS-06；本节只定义收件人应看到的业务对象、有效操作和结果。具体登记及投递形式沿用消息中心规范，不在PRD展开。

| 事件 | 用户落点 | 失效或状态已变化时 |
| --- | --- | --- |
| 审核通过待入池 | 本项目质押审核与确认，定位该代币本次申请，显示独立七天截止，不自动勾选 | 许可过期、已处理或已作废时显示原结论及当前原因，不执行 |
| 审核驳回、审核48小时超时 | 对应代币单笔历史及完整原因 | 原记录保留，不覆盖重新提交的新申请 |
| 链上执行失败 | 对应代币本次动作及费用结果 | 查看真实已知结果，不重复发起；结果未知不作为已确定失败通知 |
| 融资需求自动失效 | 融资申请记录中该轮编号及终结原因 | 已有新轮次仍定位原申请，不静默切到新轮次 |
| 覆盖不足触发/解除 | 项目摘要的当前覆盖事实及发生时间 | 解除后原告警不再作为当前待办；历史事实保留 |
| 项目届满前7天 | 对应项目及有效期 | 已到期显示当前状态和存量办理入口，不再引导新融资 |

执行长期未知仍不启用终态失败消息（原execution_timeout登记暂不启用），不因导航调整扩大发送范围。


| 编号 | 条款 |
| --- | --- |
| `D-LS-44` | 审核消息按单笔区分：同项目、同提交的两张先后通过均触达，重复同一笔同一事件不重复；重新提交新笔不覆盖旧通知。覆盖提醒按轮次、执行结果按本次动作及代币区分 |
| `D-LS-45` | 通知标题和正文按D-LS-65统一UTC业务截止、展示标注时区及金额币种；审核通过明确代币及本次入池截止，驳回带完整原因，执行失败逐张说明已知结果和费用。通知不展示私有文件内容或可越权读取的账户 |

## 13. 模块边界与术语

### 13.1 与资产广场（已上架代币只读域）的边界

| 项 | 资产广场 | 本模块 |
| --- | --- | --- |
| 主对象 | 单枚代币 | 融资项目（资产池） |
| 数据性质 | 上游代币快照的公开只读投影 | **融资事实的权威与唯一写入方** |
| 质押状态 | **只读消费**本模块的 `PS-*`，对外收敛为二元 | **权威方与唯一写入方** |
| 方向 | 详情页「所属融资项目」深链到本模块 `P-LS-02` | **不提供反向入口**（资产广场 `X-AM-10` 已裁定单向） |
| 代币字段 | 持快照并对外展示 | **消费同一份快照，不复制第二份**（`D-LS-27`） |

`D-LS-43`：**两个广场对同一张代币的说法必须一致且不矛盾**：资产广场说"这张现在在不在池里"（二元），本模块说"这张能不能选进池、算不算进覆盖"（业务判定）。两者口径不同但同源——都以本平台质押记录为准，**不得各自维护一份**。

### 13.2 与运营端质押审核（WS-359）的边界

本模块是**提交方与结论消费方**，WS-359 是**审核动作的承接方**。边界详见 9.4.3 与第 10.3 节：本模块不展开审核页面、审核规则、审核人权限与工作量分配；WS-359 不代资产方发起链上执行、不改代币清单；同批各张独立审核，可不同结论，面客逐币消费。

### 13.3 与后续融资环节的边界

本模块提供额度口径与 `INV-FIN-01`，并要求后续环节遵守：**报价不新增占用**（占用只有发布一个来源）、**放款确认完成时原子转余额**、**拒绝报价或报价届满退回 `待报价`**、**需求因覆盖不足失效时其在途报价一并失效**。L6～L8各自保留完整业务规则，本模块统一项目记录、查看与办理入口（9.2、11.7）；三类清单和右侧操作读取同一对象，不各自维护第二套状态。接受后承接放款、到账确认后承接还款，交接字段由相应模块定义。
