## 9. 模块详情

### 9.1 `P-LS-03` 创建融资项目（建池）

**入口**：借贷广场列表页与我的控制台（深链 `project/new`）；仅登录资产方可见可点。

| 区域 | 内容 |
| --- | --- |
| 基本信息 | **项目名称**（必填，1～60 字符，同一企业内不要求唯一）、**代币类型**（必选，本期唯一取值「应收账款」，其余取值置灰并标注为本期能力边界） |
| 可质押代币清单 | 按 9.4.1 六项条件筛选后的代币，**按所选代币类型过滤**；支持批量勾选；列与分页同 11.7.1（**不展示合同号 / 发票号**） |
| 提交与费用 | 本次提交的是**质押申请**：**不发生链上操作、不产生任何费用**；同屏给出**两步告知**（9.4.2）与通过后要承担的费用口径 |
| 提交结果 | 成功 → **直接进入该项目详情页 `P-LS-02`**，项目落 `S-FP-1 草稿`（广场不可见），申请落「待审核」 |

| 编号 | 条款 |
| --- | --- |
| `D-FIN-60`（**本版改写**） | **创建时必须至少选中一张代币**，校验对象是**质押申请已提交**，不要求等待审核结论、更不要求等待链上结果。理由：审核与链上执行都跨出本模块，让建池等它们等于把建池的成功率押在两个外部环节上 |
| `D-FIN-77` | **同一项目只能质押同一种代币类型**：创建时显式选定，后续追加只能追加同类型代币 |
| `D-FIN-64` | **草稿项目不进广场**：不进列表、不可搜索，他人与游客深链直达返回"内容不存在或无权访问"，**不暴露该项目是否存在** |
| `D-FIN-62` | **空池草稿**：首笔申请被驳回、撤回或链上执行全部失败时，项目保留为空池草稿，顶部常驻提示"本项目暂无有效质押，请重新提交质押申请后再发布"，发布入口不可点；资产方可重新提交或直接关闭项目（`E-12`） |
| `AC-LS-54`（沿用） | **两段式可中断可续做**：创建成功后不立即发布的，项目留在草稿态，详情页操作区常驻「发布融资需求」入口；**任何一步都不得要求重新质押或重新付一次费用** |

#### 9.2.1 统计区（一排 5 个）

| # | 统计项 | 取值 | 说明 |
| --- | --- | --- | --- |
| 1 | 质押代币数量 | 池内**计入质押覆盖**的代币张数 | 与第 2 项同口径，只数有效的 |
| 2 | 质押代币价值 | `FP-11 有效质押价值` | 已排除失效、审核未过、执行未成功、对账差异、撤回预扣 |
| 3 | 融资需求 | `FP-06 融资需求金额` | 本轮对外要融的金额 |
| 4 | 已融资余额 | `FP-13 项目融资余额` | 文档术语不得省限定词（`D-FIN-06`） |
| 5 | 质押率 | 常量 `80%` | 纯文本，不可编辑、不得暗示可调 |

| 编号 | 条款 |
| --- | --- |
| `AC-LS-53`（沿用） | `融资上限`、`可融金额`、`项目在途金额` 三个中间量**不在详情页常驻展示**，但 `INV-FIN-01` 与 `AC-FIN-12` 一条不减。**不展示 ≠ 不校验**；用户需要知道"还能融多少"的时刻只有发布 / 改额弹窗，此时给出当场重算的可融金额与差额 |
| `AC-LS-84` | 详情页**不得**出现额度尺、进度条式额度可视化或"额度明细与判定口径"折叠说明区 |
| `AC-LS-106`（**新**） | **统计区不受审核期与执行中间态影响**：构造"提交质押申请后立刻查看统计区"与"发起链上执行后结果未回写时查看统计区"两个场景，五个数与提交前**完全一致** |

#### 9.2.2 操作区（三段，自上而下）

| 段 | 内容 | 条款 |
| --- | --- | --- |
| **① 全局操作** | **追加质押**、**解除质押**（撤回与提取的合并入口）、**关闭项目**；项目处于草稿态时此处同时提供**发布融资需求** | `D-FIN-78` |
| **② 融资流程四环节** | 融资需求（发布）→ 融资报价 → 报价确认 → 融资放款。**只有当前环节下方出操作按钮**，其余环节只读展示；按钮按角色限定可点；操作一律走弹窗 | `D-FIN-79`、`AC-LS-85` |
| **③ 还款流程** | 展示最近一笔还款的核心信息，可按**需求编号**切换；「立即还款」走弹窗 | 规则属后续模块，本模块只承载展示 |

| 编号 | 条款 |
| --- | --- |
| `D-FIN-78` | **「解除质押」是撤回与提取的合并入口**：用户不需要先分清自己的代币在池里还是已释放待提取。弹窗内分三区（已失效 · 可随时撤回 / 有效抵押物 · 受额度限制 / 已释放 · 待提取），判定各自照旧（9.5） |
| `D-FIN-48` | **追加质押在项目 `S-FP-1`～`S-FP-4` 任何状态下都允许**；项目终态时该入口不可点并说明原因，而**「解除质押」在终态仍可用**（未提取的代币还在合约里，这是资产方取回自己代币的唯一入口） |
| `AC-LS-85` | 非当前环节**不得**出现任何可点操作按钮；角色不符时按钮不可点并给出原因；所有环节操作在弹窗内完成，不跳离详情页 |
| `D-LS-37`（**新**） | **中间态不锁整池**：池内存在处理中的代币时，追加质押、发布、关闭等动作**照常按各自判据判定**，不因为有一张在处理中而整块禁用；被禁用的只有**那一张代币自身**的动作（`D-LS-32`） |

### 9.4 代币质押（面客端全链路）

> 链路：**勾代币 → 提交质押申请（零费用）→ 运营端审核 → 通过后平台复核 → 发起链上执行（代币发行平台承担）→ 按张回写 → 成功张入池 / 失败张回可质押**。流程图见 [`FL-LS-01`](v1.0-借贷广场-融资需求与代币质押-流程图与状态机.md#fl-ls-01-建池与首笔质押跨平台)。

#### 9.4.1 可质押代币的筛选条件（`D-FIN-38`，**本版改写来源**）

| # | 条件 | 来源与判定方 |
| --- | --- | --- |
| 1 | **该代币在本平台只读代币域内**（上游同步全集，**无上架闸门**） | 只读代币域（`D-LS-26`） |
| 2 | **归属于当前登录的企业主体** | 本平台按企业主体过滤（`IF-LS-06` 要求快照携带可稳定比对的主体标识） |
| 3 | **当前未被任何有效质押占用、不在质押合约内、且未被在途质押申请或处理中的执行占用** | 本平台质押记录与申请（防同一张代币同时进两份申请或两个池） |
| 4 | **代币状态为「有效」**（底层应收账款未过到期日） | **只读代币域的判定结果**，本平台不自行判定（`D-LS-28`） |
| 5 | **代币类型 = 应收账款类** | 本期能力边界 |
| 6 | **与本项目已选定的代币类型一致** | 长期规则（`D-FIN-77`） |

> 条件 5 是本期能力边界，条件 6 是长期规则，**必须分开写**。
> `D-FIN-39`：**一张代币整张质押**，以"张"为单位勾选，无数量输入框。
> `D-LS-38`（**新**）：**"可质押"是本模块的业务判定，不是代币的属性**。只读代币域不展示、不判定、不回写可质押性；同一张代币在资产广场只有「未质押 / 已质押」二元展示（`D-AM-13`），**两边不矛盾**——一个说"现在有没有在池里"，一个说"现在能不能选进池"。

#### 9.4.2 提交质押申请与两步告知

| 编号 | 条款 |
| --- | --- |
| `D-FIN-80`（**本版改写**） | **先审核、后链上执行。** 勾代币 → 提交**质押申请** → 运营端审核 → **通过后**才发起链上执行。**审核期内代币留在资产方自己的地址，一分费用都不花；驳回 = 零费用。** 本版改写点：执行方由本平台变为**代币发行平台**（`D-LS-29`），时序与费用归属不变 |
| `AC-LS-97` | **提交时必须明确告知要操作两次**：① 现在提交审核，不付费；② 通过后回来确认并承担链上费用。两步告知在**三处**出现：创建页、追加质押入口、提交确认弹窗 |
| `D-FIN-83` | **追加质押同样走审核**（同样是往池里加担保物）；**撤回与失效代币清出不走审核**——撤回是资产退出、不增加任何人的风险敞口，且它本就有一道更严且即时的额度闸门（`AC-FIN-13`） |
| `D-FIN-84` | **审核状态挂在质押申请上，不挂在代币上**：代币的 `PS-*` 与链上执行轴 `CT-*` 一律不变；代币上只加一个派生标记「已被在途申请或在途执行占用」 |
| `AC-LS-108`（**新**） | 提交确认弹窗的正文**第一句**即说明"本次提交的是质押申请，此刻不发生链上操作、不产生任何费用"；该弹窗内**不得**出现任何"确认并支付""立即签名"类按钮 |

#### 9.4.3 审核结论的呈现与撤回（质押审核卡）

| 项 | 规则 |
| --- | --- |
| 呈现位置 | 详情页 L7 质押审核卡：在途申请逐条铺开，已结论的收进「审核历史」折叠；**仅本方资产方可见**（`D-LS-36`） |
| 逐条内容 | 申请编号、申请类型（建池首笔 / 追加）、代币清单（编号、数量、代币价值、底层账期、买方企业）、提交时间、当前状态、结论时间 |
| **驳回** | **驳回原因原样透传、不截断、不改写**（`AC-LS-99`）；给「重新提交」，重新提交生成**新的申请**，原申请留档 |
| **撤回** | 资产方**只在结论作出之前**可撤回自己的申请；撤回后代币立即回到可质押清单，全程零费用 |
| **通过待入池** | 明确写出两件事：① **通过还不等于质押成功**；② **入池有效期**（结论时间起 7 个自然日）与剩余时间 |
| 结论失效 | 有效期内未完成入池 → 结论失效，落审核历史并注明"全程未产生任何费用"，给「重新提交」 |
| **审核超时失败** | 提交满 **2 个自然日**仍无审核结论 → 申请置**「超时失败」**（`D-LS-33`、`E-16`）：失败原因写明**「运营端未在时限内完成审核」**，不得笼统写"质押失败"；注明**全程未发生链上操作、未产生任何费用**；代币立即回到可质押清单；记录落审核历史**可查**，并给「重新提交」（生成新的申请） |
| 等待期的呈现 | 待审核状态下同屏给出**已等待时长**与**判失败的时点**（提交时点 + 2 个自然日）；运营端给出对外承诺时限时另行展示预期等待（`Q-LS-05`） |

| 编号 | 条款 |
| --- | --- |
| `D-FIN-81`（**沿用 + 本版补充**） | **审核通过 ≠ 入池成功。** 通过后、发起链上执行前，平台**重新校验 9.4.1 的六项条件**；不通过则该结论作废、说明原因、**不发起链上执行、不产生费用**，资产方可重新提交（`E-13`）。**通过后 7 个自然日内未完成入池，结论自动失效**——不设期限会留下无限期挂起的通过单，而池值口径要靠"要么入池要么了结"来收敛 |
| `D-LS-48`（**新**） | **审核时限是平台自动判定，不依赖任何人点一下**：到期即判失败并回写申请状态，**不需要运营端补审、不需要资产方催办、也不因运营端稍后补上结论而翻转**——补上的结论落到一个已终结的申请上，只会让"已经拿回代币又重新质押到别处"的资产方出现两份互相矛盾的事实 |
| `D-FIN-82`（**沿用 + 本版扩展**） | **审核期内、通过待入池期间、链上执行中间态，该代币一律不计入 `有效质押价值`**，因而不撑融资上限、不撑任何报价与放款准入。这不是第二套规则，是 `D-FIN-54` 保守原则——**计入的充要条件是"审核通过 + 链上转入执行成功回写"两个条件同时满足** |

#### 9.4.4 通过后的确认与发起执行

| 步骤 | 产品行为 |
| --- | --- |
| 1 · 复核 | 平台按 9.4.1 六项条件复核；不通过按 `E-13` 收口 |
| 2 · 费用与承担方告知 | 发起前必须展示：本次涉及的代币张数与逐张清单、**费用预估**、**承担方 = 本企业**、"链上费用由区块链收取、平台不收费、不代付、不返还"、**"执行失败的那一张，已经产生的费用同样不退回"**，并**二次确认**（`AC-LS-32`、`D-LS-31`） |
| 3 · 发起 | 由资产方确认后发起；**链上执行由代币发行平台承担**（`D-LS-29`）。该动作在业务上是"把这一批代币交付执行"，本平台据此把相关代币置为**质押处理中**（`CT-1`） |
| 4 · 中间态 | 按 `D-LS-32` 呈现：逐张显示处理中并说明结果回写后本页会更新；该张不可再选、不可撤回、不可提取、不可重复发起；**项目其余功能照常** |
| 5 · 回写 | 按张消费执行结果（9.4.5） |

`Q-LS-02`【待确认】**费用确认与签名由哪一侧界面承载**（本平台页面内完成、还是跳转代币发行平台完成）取决于 `X-04` 的交互形态，**契约未定前不预设**。不论落在哪一侧，以下业务要求必须成立且可验收：**发起前资产方已看到本次操作内容与费用预估并明确确认承担；未确认不得发起；确认后资产方能回到本页看到逐张结果**（`IF-LS-03`）。

#### 9.4.5 执行结果的按张呈现

| 编号 | 条款 |
| --- | --- |
| `D-LS-30`（主册 5.3） | **按张独立结算**：成功张 → `PS-2 已质押` 并计入有效质押价值；失败张 → 退回 `PS-1 可质押`，**可再次选入本池或其他池**；申请层不给"整体成功 / 整体失败"这一个结论 |
| `AC-LS-109`（**新**） | 结果呈现必须**逐张**给出四件事：① 这张成了还是没成；② 没成的原因（业务可读，不透出运营诊断字段）；③ **这张是否已经产生费用、金额多少**；④ 下一步能做什么（失败张：重新选入任一池；成功张：已计入覆盖，可在解除质押入口处置）。**不存在只说"部分成功"或"操作失败"的笼统结论** |
| `AC-LS-110`（**新**） | 同一申请内**成功张不因失败张而回滚**；失败张不停留在任何"待处理"的第三态；构造"2 成 1 败"场景，失败那张**立即出现在另一个项目的可质押清单里** |
| `D-FIN-68`（沿用 · 结果要求） | **同一次操作无论重复提交多少次，都不得产生第二次链上转移、不得二次收费。** 本条只要求结果，**具体机制由实现方决定**，本 PRD 不规定 |
| `D-FIN-40`（**本版改写**） | **质押成立 = 该张代币转入质押合约执行成功并回写**；释放 = 从质押合约转回**质押前的原持有地址**，**不允许人工指定目的地址**。执行由代币发行平台承担，**本平台不接受任何"指定其他地址"的入参与界面入口** |
| `AC-LS-30`（沿用） | **平台侧质押记录永远不领先于链上事实**——撤回不得先置已释放再等回写。**唯一例外是项目终态时的业务释放**（`D-FIN-57` 第一段），它是业务关系的解除而非资产位置的变更，且对外明确标注为"待提取" |

### 9.5 解除质押（撤回 / 失效清出 / 释放与自助提取）

| 编号 | 规则 |
| --- | --- |
| `AC-FIN-13` | **未失效代币的撤回**：撤回后须满足 `(有效质押价值 − 拟撤回价值) × 80% ≥ 项目融资余额 + 项目在途金额`；用户可读形式是 `拟撤回价值 ≤ 可撤回上限` |
| `D-FIN-59` | **已失效代币**：撤回**不做任何额度判定，直接放行**。两件事互为因果：正因为它本来就不顶覆盖，移出它才不会削弱覆盖 |
| `AC-LS-36` | 解除质押弹窗**必须分区展示**：「已失效 · 可随时撤回（不计入覆盖）」「有效抵押物 · 受额度限制」「已释放 · 待提取」；第二区顶部常驻"当前最多可撤回 X USD"，勾选时实时累计对照 |
| `AC-LS-37` | 撤回被拒绝时必须给出**三个数**（拟撤回价值、当前可撤回上限、差额）与两条出路（减少勾选 / 等待还款释放余额）。只说"不允许撤回"不合格 |
| `D-FIN-54` ② | 撤回一旦发起执行即**预扣**该部分价值，执行失败回滚才恢复（`E-3`） |
| `D-FIN-57` | **释放两段式**：① **业务释放**（项目进入 `S-FP-5`/`S-FP-6` 的同一时刻，平台解除全部质押占用关系，代币置 `PS-4 已释放 · 待提取`，即时、无链上动作、零费用）；② **链上提取**（资产方自助发起，链上执行由代币发行平台承担、**费用由资产方承担**，支持批量一次提取，**无时间限制、不过期**）。未提取的代币**不属于任何池、不计入任何质押价值、也不能被再次质押** |
| `AC-LS-38` | 存在可提取代币时，在「解除质押」入口上以角标 + 副文案提示张数与金额，并说明需自付费用、可批量一次提完，**不得让资产方以为代币会自动回到钱包** |
| `D-FIN-53` | 撤回 / 提取频次**不设硬性阻断**，改用三道软约束：支持批量一次提交；每次提交前展示张数与费用预估；24 小时内提交超过 5 次时提示"频繁链上操作会产生较多费用"，**不阻断** |
| `D-FIN-49` | **质押释放时点与项目终态绑定**，不提供"某笔业务结清即释放对应代币"的部分释放——额度语义下不存在"对应代币"；某笔结清的效果是余额下降，从而提高可撤回上限 |

### 9.7 异常与边界

> `E-1`/`E-2`/`E-5` 按跨系统事务**重写**（不是平移）；`E-13`～`E-16` 为本版新增。**`E-5`（执行超时）与 `E-16`（审核超时）是同一形态的两个节点**，共同口径见 `D-LS-33`。

| # | 异常 | 处理 |
| --- | --- | --- |
| **`E-1`** | **某张代币的链上转入执行失败回写** | **按张收口**：该张退回 `PS-1 可质押`、**不计入覆盖**、可立即再次选入本池或其他池；申请上记录该张的失败结论与业务可读原因；页面就地告知该张**是否已产生费用**（**已产生的费用不退回**，`D-LS-31`）与下一步。**不整单回滚、不自动重试**；重新发起是资产方的一次新动作，并按新的一次费用告知 |
| **`E-2`** | **同一申请内结果不齐**（部分成功） | **这是常态路径，不是异常**：成功张即时入池并计入覆盖，失败张按 `E-1` 收口；**发布校验以实际成功入池后的权威重算结果为准**；页面**逐张**给出结果，不给"部分成功"的笼统结论（`AC-LS-109`） |
| `E-3` | **撤回的链上执行失败** | 代币**回到 `PS-2` 在池**、预扣撤销、派生量重算，撤回请求置「撤回失败」可重试。**禁止**先置 `PS-4` 再回滚 |
| `E-4` | **提取的链上执行失败** | 代币保持 `PS-4 已释放 · 待提取`，不影响任何项目的额度与状态（业务已在第一段释放完毕），可随时重试 |
| **`E-5`（本版重写）** | **执行结果到期未回写** | 发起执行满 **2 个自然日**仍无回写 → **该张判失败**（`D-LS-33`）：退回 `PS-1 可质押`、不计入覆盖、可立即重新选入任一池；质押记录保留，失败结论写明**「链上执行结果未在时限内回写」**并按张给出**是否已经产生费用**（已产生的不退回）；生成运营待办。**判失败之前**：保持处理中、不计入覆盖、不自动重发、页面不提供重试入口，只明示已等待时长与判失败时点。**判失败之后**若结果迟到回写为成功，按 `D-LS-47` 走对账收口，**平台不自动改回已质押** |
| `E-6` | **重复提交 / 并发操作** | 处理中的代币的任何新动作一律拒绝并提示"该代币正在链上处理中"；**同一次操作不得产生第二次链上转移、不得二次收费**（`D-FIN-68`） |
| `E-7` | **撤回提交瞬间额度变化** | 按提交时刻的权威数据重算并拒绝，返回最新可撤回上限与差额；页面须刷新，不允许残留过期数字 |
| `E-8` | **撤回处理中与报价并发** | 撤回一进处理中即**预扣**其价值，因此并发的报价看到的是已扣减后的池值，**不会出现"报价基于虚高池值通过、随后撤回成功导致覆盖穿底"**；撤回失败则预扣撤销，已通过的报价不受影响 |
| `E-9` | **代币在质押期间底层资产失效** | 只读代币域把代币状态推成失效 → 本平台读到结果后**立即从有效质押价值中扣除** → 派生量重算 → 可能触发覆盖不足提醒。不自动解除质押，但资产方可随时无限制撤回；生成运营待办 |
| `E-10` | **费用不足 / 资产方在确认环节放弃** | 按"未发起"收口：**不产生质押处理中**、不产生任何记录变更；提示费用不足或已取消，可重新发起。**不得表现为失败并留下悬空记录** |
| `E-11` | **平台记录与链上持仓不一致** | 差异由后台对账判定并置标记（对账不在本模块）。本模块收到标记后：该代币**不计入有效质押价值**、**冻结其一切新动作**、触发受影响项目的重算与运营待办 |
| `E-12` | **建池那唯一一笔质押最终未成立**（驳回 / 撤回 / 全部执行失败） | 项目保留为**空池草稿**（`D-FIN-62`），顶部常驻提示与发布入口不可点；资产方可重新提交申请或直接关闭项目 |
| **`E-13`（新）** | **通过后、发起执行前的复核不通过** | 结论作废（`PA-08` 记录原因，如"该代币已质押至其他项目""底层应收账款已失效"），**不发起链上执行、不产生任何费用**，原因告知资产方并给「重新提交」 |
| **`E-14`（新）** | **链上执行入口不可用**（代币发行平台侧不可用或未就绪） | **不得表现为卡住或静默失败**：明确告知"当前无法发起，本次未产生任何费用，可稍后重试"，**不产生中间态记录、不占用代币**；连续不可用生成运营待办 |
| **`E-15`（新）** | **同一张代币被重复选入** | 被在途申请或处理中执行占用的代币，在两处可质押清单里**可见但不可选**，并给出占用来源（申请编号 / 处理中）。并发提交时**只有一笔成立** |
| **`E-16`（新）** | **运营端未在时限内审核** | 提交满 **2 个自然日**无审核结论 → 申请自动置**「超时失败」**：**从未走到链上执行、不产生任何费用**；代币退回 `PS-1 可质押`，可重新选入同一或其他项目；`PA-*` 记录**保留可查**（不是删除、不是撤回）；失败原因写明**「运营端未在时限内完成审核」**；生成运营待办。建池首笔遇此情形按 `E-12` 落空池草稿 |

## 10. 对跨平台的业务要求（`IF-LS-01`～`IF-LS-10`）

> **本章是业务要求，不是接口设计。** 每条写"本模块需要对方保证什么业务结果"与"不保证会怎样"；**报文格式、字段名、回调方式、去重与重试机制不在本 PRD 范围**。`X-04`/`X-05` 契约尚未定义（`GAP-LS-01`），本章即本模块提出的消费口径。

### 10.1 对 `X-04`/`X-05`（链上执行与回写）的要求

| 编号 | 要求 | 不满足会怎样 |
| --- | --- | --- |

| `IF-LS-02`【按张回写 · 有时限】 | 执行结果**必须按张回写**，且每张可区分：成功 / 失败、失败的业务可读原因、**该张是否已产生费用与金额**、执行完成时间、可供资产方自行查验的链上凭证（成功时）。**回写须在发起后 2 个自然日内到达**——这是本平台判超时失败的业务时限（`D-LS-33`），超出即按失败收口，迟到的成功结果只能走对账更正（`D-LS-47`） | 只回一个整单结论，本平台无法做按张结算（`D-LS-30`），只能整单回滚或整单放行，两者都错 |

| `IF-LS-10`【质押事实的回写方向】 | **质押状态的权威在本平台**：本平台经 `X-04`/`X-05` 把质押事实回写代币发行平台；**本平台不反向读取上游的质押状态**，只读代币域的供给中**不得携带质押状态**；即便携带，本模块也不消费（与资产广场 `D-AM-11`/`D-AM-57` 同源） | 回读上游的质押状态会把所有已质押代币显示成未质押，并与资产广场自相矛盾 |

## 12. 深链契约与通知事件

### 12.1 深链契约 `H-01`～`H-05`

> 本模块**对我的控制台、资产广场与后续融资环节的对外义务**。资产广场三册已在消费 `H-01`～`H-05`（`D-AM-40`），**本版不改写其含义**。

| 编号 | 契约 | 落地要求 |
| --- | --- | --- |
| `H-01` 稳定的业务对象 ID | 融资项目、质押记录、融资业务等对象拥有**全局唯一、终身稳定**的标识，不随状态变化、不随再次发布而变更，进入终态后仍可寻址 | 项目编号即广场上这条融资需求的编号，不另发号 |
| `H-02` 可寻址锚点 | 本模块交付：`project/new`（建池）、`project/{id}`（详情）、`project/{id}?action=pledge`（追加质押）、`project/{id}?action=withdraw`（解除质押）、`project/{id}?action=publish`（填金额并发布）、`project/{id}?action=redeem`（提取已释放代币）、**`project/{id}?action=enter_pool`（审核通过后回来确认并发起入池）**。三条边界：① **重新判权**；② **状态已变**时落详情页 + 提示（"该项目已关闭""可撤回额度已变化"），**不报 404、不白屏、不静默跳首页**；③ 游客深链照常全量可见，但**草稿项目一律返回"内容不存在或无权访问"** |
| `H-03` 可执行动作由平台判定 | 每次读取由**平台**给出当前可执行动作，页面按其渲染、**不自行依据状态推断**；须区分"不可见"与"可见不可点"，后者**必须附原因**。**额度不足时"解除质押"必须以可见不可点 + 原因（含可撤回上限）呈现，而不是直接隐藏**——隐藏会让资产方以为功能没了 |
| `H-04` 数据回流 | 广场侧写操作成功后，控制台与资产广场可见的字段与派生量必须来自**同一来源、同一算法**；状态枚举一处定义多处引用。**六个派生量、覆盖状态档位、质押状态与链上执行状态，均由本模块权威输出**，其他模块只读引用 |
| `H-05`「返回我的控制台」 | 从控制台深链进入的页面须提供返回入口，动作完成后引导回控制台对应位置；来源上下文由平台暂存，**不拼进 URL**；非深链来源时不展示 |

`AC-LS-111`（**新**）：`action=enter_pool` 对**非本方主体**只落页面、不打开任何操作层；申请已失效或已结论时落详情页并说明原因，**不报错、不白屏**。

### 12.2 通知事件与触发登记（走本平台面客消息中心）

> **本模块是面客消息中心的接入方**：按其分册 01 第 10 章的登记框架，在**本模块 PRD 内**登记完整的触发行，落到本平台共享登记表后同步一行（`CR-LS-06`）。**本模块不自定义通知契约、不复制其登记表、不定义投递机制。**
>
> **页面标记对每一类事件都始终存在**，推送只是叠加的主动触达；**推送失败不得导致用户完全不知情**。

#### 12.2.1 推与不推（业务判断）

| 事件 | 推送 | 收件人 | 理由 |
| --- | --- | --- | --- |
| **质押审核通过 · 待入池** | ✅ 必推 | 提交申请的资产方 | 通过后**还要他回来确认并承担费用才算质押成功**；不推他不会知道要回来，7 天后结论就失效了 |
| **质押审核驳回**（含原因） | ✅ 必推 | 同上 | 否定结论且需要重新提交；**原因原样带上**，否则只能盲目重提 |
| **链上执行失败**（逐张） | ✅ 必推 | 发起该操作的资产方 | 可能发生在用户离开页面之后，且直接关系"费用产生没有、要不要重来" |
| **执行结果到期未回写 · 判超时失败**（逐张） | ✅ 必推 | 同上 | 结论是失败且代币已回到可质押，不触达他就不知道要重来；文案须说明**是否已经产生费用** |
| **审核超时失败**（两天无结论） | ✅ 必推 | 提交申请的资产方 | 他在等一个不会来的结论；文案须写明**是运营端未在时限内审核**、**全程零费用**、代币已可重新质押 |
| **融资需求因覆盖不足自动失效** | ✅ 必推 | 资产方 + 该需求上有在途报价的机构 | 诱因与资产方操作无关，且结果是一笔已公开的要约被作废 |
| **覆盖不足提醒触发** | ✅ 必推 | 资产方 + 该项目下有未结清业务的债权机构 | 资产方要尽快补、债权机构有知情权 |
| 覆盖不足**解除** | ✅ 推 | 同上 | 让双方知道窗口已关闭，不必反复追加 |
| 项目有效期届满**前 7 天** | ✅ 推一次 | 资产方 | 这是"还能不能成交"的最后窗口 |
| 链上执行**成功** | ❌ 不推 | — | 成功那一路用户就在页面上等着，结果即时可见 |
| 通过后**超时未入池而失效** | ❌ 不单独推 | — | 失效零成本、可立即重新提交；截止时间已写在通过通知里 |
| 可提取代币提醒 | ❌ 不单独推（页面常驻提示） | — | 资产安全、没有时限；单独推等于催用户去花钱 |
| 项目有效期届满前 30 天 | ❌ 不推（仅页面标记） | — | 太早、无行动价值——本期有效期不可延期 |

## 13. 模块边界与术语

### 13.1 与资产广场（已上架代币只读域）的边界

| 项 | 资产广场 | 本模块 |
| --- | --- | --- |
| 主对象 | 单枚代币 | 融资项目（资产池） |
| 数据性质 | 上游代币快照的公开只读投影 | **融资事实的权威与唯一写入方** |
| 质押状态 | **只读消费**本模块的 `PS-*`，对外收敛为二元 | **权威方与唯一写入方** |
| 方向 | 详情页「所属融资项目」深链到本模块 `P-LS-02` | **不提供反向入口**（资产广场 `X-AM-10` 已裁定单向） |
| 代币字段 | 持快照并对外展示 | **消费同一份快照，不复制第二份**（`D-LS-27`） |

`D-LS-43`：**两个广场对同一张代币的说法必须一致且不矛盾**：资产广场说"这张现在在不在池里"（二元），本模块说"这张能不能选进池、算不算进覆盖"（业务判定）。两者口径不同但同源——都以本平台质押记录为准，**不得各自维护一份**。

### 13.2 与运营端质押审核（WS-359）的边界

本模块是**提交方与结论消费方**，WS-359 是**审核动作的承接方**。边界详见 9.4.3 与第 10.3 节：本模块不展开审核页面、审核规则、审核人权限与工作量分配；WS-359 不代资产方发起链上执行、不改代币清单、不部分通过。

### 13.3 与后续融资环节的边界

本模块提供额度口径与 `INV-FIN-01`，并要求后续环节遵守：**报价不新增占用**（占用只有发布一个来源）、**放款确认完成时原子转余额**、**拒绝报价或报价届满退回 `待报价`**、**需求因覆盖不足失效时其在途报价一并失效**。四环节的业务规则本模块**不重写**，只承载展示与入口（9.2.2）。
