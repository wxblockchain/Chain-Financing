## 1. 流程图

### `FL-LS-01` 建池与首笔质押（跨平台）

> 关联：`F-LS-01`、`F-LS-12`、`F-LS-21`、`D-FIN-60`、`D-FIN-80`～`D-FIN-82`、`D-LS-29`～`D-LS-33`、`E-1`/`E-2`/`E-5`/`E-13`。正文见分册 01 [9.1](01-功能需求说明.md#91-p-ls-03-创建融资项目建池) 与 [9.4](01-功能需求说明.md#94-代币质押面客端全链路)。追加质押走同一条链路，区别只在入口与 `PA-04` 申请类型。

```mermaid
flowchart TD
  A["资产方 · 填项目名 + 选代币类型"] --> B["资产方 · 从可质押清单勾选代币<br/>来源＝只读代币域，无上架闸门"]
  B --> C["本平台 · 校验六项可质押条件"]
  C --> D["资产方 · 提交质押申请<br/>零费用，不发生链上操作"]
  D --> E["本平台 · 项目落 S-FP-1 草稿，广场不可见<br/>直达详情页；统计区五个数不变"]
  E --> F{"运营端 · 审核结论"}
  F -- "驳回 · 零费用" --> G["本平台 · 原因原样呈现<br/>代币回 PS-1，可重新提交"]
  F -- "结论前资产方撤回" --> G
  F -- "通过" --> H["本平台 · 审核通过 · 待入池<br/>入池有效期 7 个自然日"]
  H -- "有效期内未入池" --> I["本平台 · 结论失效<br/>全程未产生费用，可重新提交"]
  H --> J["本平台 · 发起前复核六项条件"]
  J -- "不通过 E-13" --> K["本平台 · 结论作废<br/>不发起执行、不产生费用"]
  J -- "通过" --> L["本平台 · 展示操作内容与费用预估<br/>承担方＝资产方，二次确认"]
  L -- "资产方放弃 E-10" --> M["本平台 · 未发起，无记录变更、无费用"]
  L --> N["代币发行平台 · 承担链上执行"]
  N -.-> O["本平台 · 该批代币置质押处理中<br/>不计入覆盖、不可再选、不可撤回"]
  O --> P{"代币发行平台 · 按张回写结果"}
  P -. "该张成功" .-> Q["本平台 · PS-2 已质押<br/>计入有效质押价值"]
  P -. "该张失败 E-1" .-> R["本平台 · 退回 PS-1 可质押<br/>可再次选入本池或其他池"]
  P -. "长时间未回写 E-5" .-> S["本平台 · 保持中间态<br/>不判失败、不自动重发、不给重试<br/>兜底口径待确认 Q-LS-01"]
  Q --> T["资产方 · 可在详情页操作区发布融资需求"]
  R --> U["本平台 · 逐张告知结果、原因与是否已产生费用<br/>已产生的费用不退回"]
  Q --> U
```

**这张图要读出来的三件事**：① **审核在前、链上执行在后**，驳回与撤回都是零费用；② **执行结果按张分叉**（`Q` 与 `R` 是同一次申请内可以同时发生的两条出口）；③ **中间态 `O`/`S` 只锁那一张代币，不锁项目**。

```mermaid
flowchart TD
```

## 2. 状态机

> 三张状态机分属**三个不同的业务对象**，互不覆盖、不合并：项目（`S-FP-*`）、代币在本平台的质押（`PS-*` + `CT-*`）、质押申请（`PA-05`）。

### `ST-LS-01` 融资项目状态机 `S-FP-*`

> 关联：`F-LS-01`～`F-LS-03`、`D-FIN-33`、`D-FIN-43`、`D-FIN-47`、`D-FIN-63`、`FP-04`。正文见主册 6.3 与分册 01 11.2。**一套跨模块共用的项目状态机，本模块是唯一写入方。**

```mermaid
stateDiagram-v2
  [*] --> S_FP_1: 创建项目并提交首笔质押申请
  S_FP_1: S-FP-1 草稿 · 已建池未发布 · 广场不可见
  S_FP_2: S-FP-2 募集中
  S_FP_3: S-FP-3 已锁定
  S_FP_4: S-FP-4 融资中
  S_FP_5: S-FP-5 已关闭
  S_FP_6: S-FP-6 已结清
  S_FP_1 --> S_FP_2: 填写金额并发布 · 需求金额计入在途
  S_FP_2 --> S_FP_1: 撤下需求或需求自动失效且无其他在途业务
  S_FP_2 --> S_FP_3: 机构提交报价 · 占用不变
  S_FP_3 --> S_FP_2: 拒绝报价或报价有效期届满
  S_FP_3 --> S_FP_4: 资产方接受报价
  S_FP_4 --> S_FP_2: 可融金额大于 0 且资产方再次发布
  S_FP_4 --> S_FP_6: 全部融资业务结清 · 释放全部质押
  S_FP_1 --> S_FP_5: 资产方主动关闭
  S_FP_2 --> S_FP_5: 主动关闭 或 到期且无在途与未结清业务
  S_FP_5 --> [*]
  S_FP_6 --> [*]
```

| 说明 | 口径 |
| --- | --- |
| **并行标记不是状态** | 「已到期 · 存量处理中」是 `FP-05` 并行标记，不新增状态；该标记必须**按正常状态呈现**（中性样式），不得做成告警（`D-FIN-47`） |
| **终态仍有动作** | `S-FP-5`/`S-FP-6` 下「追加质押」「关闭项目」不可点，但**「解除质押」仍可用**——未提取的代币还在合约里（`D-FIN-57`） |
| **需求不是独立对象** | 融资需求没有自己的状态机；对外 5 值是同一批事实的展示视角，映射由本平台派生下发（分册 01 11.6） |

### `ST-LS-02` 代币在本平台的质押状态机 `PS-*` 与链上执行轴 `CT-*`

> 关联：`PS-1`/`PS-2`/`PS-4`、`CT-0`～`CT-3`、`D-LS-22`～`D-LS-25`、`D-LS-30`～`D-LS-33`、`D-FIN-54`、`E-1`～`E-5`。正文见主册 5.1、5.3 与分册 01 9.4.5。
>
> **两根正交轴**：`PS-*` 回答"这张在不在池里"（权威在本平台）；`CT-*` 回答"链上这一步走到哪"（由代币发行平台按张回写）。**审核态不在这张图上**——它挂在质押申请上（`ST-LS-03`）。**代币自身是否失效是第三根独立的轴，取只读代币域的代币状态，不在本图。**

```mermaid
stateDiagram-v2
  PS_1: PS-1 可质押 · 在资产方地址
  PS_2: PS-2 已质押 · 在质押合约 · 池内
  PS_4: PS-4 已释放 · 不再计入覆盖
  PROC: 质押处理中 · CT-1 · 不计入覆盖
  [*] --> PS_1
  PS_1 --> PROC: 审核通过并确认后发起转入 · CT-1
  PROC --> PS_2: 该张执行成功回写 · CT-2
  PROC --> PS_1: 该张执行失败回写 · CT-3 · E-1
  PROC --> PROC: 结果长时间未回写 · E-5 · 保持中间态
  PS_2 --> PS_4: 撤回通过额度判定且转出成功
  PS_2 --> PS_4: 失效代币撤回 · 不做额度判定
  PS_2 --> PS_4: 项目关闭或结清 · 业务即时释放 · 链上待提取
  PS_2 --> PS_2: 撤回执行失败 · 预扣撤销 · 保持在池 · E-3
  PS_4 --> PS_1: 自助提取成功 · 回到资产方地址
  PS_4 --> PS_4: 提取执行失败 · 保持待提取 · E-4
```

| 说明 | 口径 |
| --- | --- |
| **计入覆盖的充要条件** | **审核通过 且 转入执行成功回写**（`D-FIN-82`）。处理中、审核期、失败、对账差异、撤回预扣一律不计入 |
| **按张独立结算** | 同一次申请的多张代币各自沿本图走，**互不牵连**：一张走到 `PS-2`、另一张回到 `PS-1` 是正常结果（`D-LS-30`） |
| **`PS-0` 非法** | 值域只有 `PS-1`/`PS-2`/`PS-4`，`PS-3` 作废占位（`D-LS-23`）；编号不透出对外面（`D-LS-25`） |
| **图中没有"冻结"** | 冻结发生在项目的额度维度，不发生在代币上 |

### `ST-LS-03` 质押申请状态机 `PA-05`

> 关联：`PA-01`～`PA-10`、`D-FIN-80`～`D-FIN-84`、`E-13`、`AC-LS-99`。正文见分册 01 9.4.3 与 11.3。**申请是审核的对象，代币不是。**

```mermaid
stateDiagram-v2

  APPROVED: 审核通过 · 待入池
```

| 说明 | 口径 |
| --- | --- |
| **`已入池` 是申请的终结，不是"全部成功"** | 按张独立结算下，一条申请可以"2 张成功、1 张失败"后即告终结；逐张结论记在 `PA-10`，**申请层不设整体成功 / 失败**（`D-LS-30`） |
| **重新提交是新申请** | 驳回、撤回、结论失效、结论作废后重新提交，生成**新的申请编号**，原申请留档可回溯 |
| **与代币两轴互不覆盖** | 申请上的审核态与代币上的 `PS-*`/`CT-*` 分属两个对象，界面上天生分得开（`D-FIN-84`） |
