# 融资需求与代币质押 · PRD

资产方先创建融资项目——填项目名称、代币类型、质押率、项目期限与参考结算币种，核对平台带出的还款方式与SPV机构名称后提交审核；管理端核对后由平台钱包部署本项目质押合约，**部署成功即视为审核通过**，项目与合约一一对应。项目可用后，资产方在项目详情用代币持有地址向质押合约签名发起质押、gas 自担；代币上链后先计入待审质押额，经运营逐笔审核通过才计入有效质押额，驳回后由资产方自助解押取回。只有通过审核的有效质押才支持发布融资需求；资金方随后报价，成交后继续放款与还款。项目是一只资产池，可承接多轮申请及多笔存量业务。

**主阅读入口就是本文。** 产品与研发按“浏览项目 → 创建项目 → 发起质押 → 发布需求 → 查看融资记录 → 撤回与提取 → 覆盖变化”顺序阅读；测试集中阅读文末同序验收。按需打开[流程图与状态机](02-融资需求与代币质押-流程图与状态机.md)和[消息通知](03-融资需求与代币质押-消息通知.md)。功能规则见第2～8章，验收见第9章。三册共同作为设计输入。

## 1. 范围与角色
<a id="scope"></a>

本模块负责项目、质押申请、质押事实、额度及覆盖判断，以及四类项目记录的查看与办理入口。运营审核在质押审核模块；链上执行由代币发行平台承担；授信报价、放款、还款由各自模块定义，本文保留必要衔接。不新增代币上架审批、部分数量质押、平台代签代付、抵押物处置或异常处置系统。

| 角色 | 可以做什么 | 边界 |
| --- | --- | --- |
| 游客 | 浏览已公开项目及公开融资、抵押物与覆盖事实 | 无写权限、私有资料或私有待办；未通过审核或未发布的项目不暴露存在性 |
| 本企业资产方 | 创建项目并提交审核、签名发起质押与解押、发布及管理需求、按条件撤回或提取；承接本方履约办理 | 按当前有效身份、企业归属及业务资格判断；发起融资前实时核实有效认证，无法确认不放行 |
| 资金方 | 浏览公开项目；按自身资格办理本机构报价、放款及还款确认 | 私有资料只向相应业务当事方开放，注册或待审核不等于可出资 |
| 平台运营 | 在运营端逐笔审核、查看既有覆盖待办及监控 | 不在本面客模块裁定审核或代资产方执行 |

个人与企业账户档案仅本人查看。业务必要的项目、企业名称、代币等信息可自动获取并按本业务权限展示；不能据此开放对方整份账户档案。授信、账户、协议、凭证、联系方式、底层合同号/发票号及运营诊断不是公开融资信息。查看、下载和直接提交均检查权限，隐藏入口不能代替权限控制。

共同登录资格与本人资料沿[登录主干](../v2.0-登录与账户体系/01-登录主干与资产方SSO接入-PRD.md)及[资金方账户](../v2.0-登录与账户体系/01-资金方登录与账户体系-PRD.md)；本模块公开业务字段范围按本文。上游代币事实沿[资产广场](../v1.0-资产广场-已上架代币只读域/01-资产广场-PRD.md)。不因精简改变既有权限。

## 2. 浏览项目与进入办理
<a id="browse"></a>

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

### 找到项目

<a id="F-LS-10"></a><a id="f-ls-10"></a>**F-LS-10** 借贷广场按项目逐条列出，一条一个项目，未发布的项目不出现；没有当前需求时显示“暂无融资需求”。展示项目名称、企业、有效质押额、当前需求金额/币种及状态、覆盖情况。只显示中性的覆盖事实与缺口，不新增健康评分、风险等级、黑名单或评价性标签。

支持既有币种、期限、关键词筛选，默认发布时间倒序，可按需求金额、总质押额排序。每批20条，已显示数量须可得；继续浏览时自动追加后续批次，已加载内容不丢失，不能按页码定位，也不能改变每批条数。换排序或重置筛选从新条件的首批重新开始。从条目可进入项目详情，列表不提供逐条办理动作；返回时保留原筛选、排序与已加载范围，并回到原来所在的条目。暂无项目、筛选无结果和读取失败分别呈现，后两者提供清空筛选或重试。

### 查看与办理分开
<a id="interaction"></a>

<a id="F-LS-11"></a><a id="f-ls-11"></a>**F-LS-11** 项目摘要包含名称、项目编号、资产方企业、SPV机构名称、质押合约地址、项目期限与到期日、项目状态；当前需求金额与状态可单独辨认，不与项目状态混为一项。<a id="F-LS-18"></a><a id="f-ls-18"></a>**F-LS-18** 项目统计为六项：[总质押额](#fp-10)、[待审质押额](#fp-32)、[有效质押额](#fp-12)、本轮融资需求、已融资余额（业务含义为项目融资余额）、[项目质押率](#fp-34)。上链处理中的代币不计入任何一项；已上链未通过审核的计入待审质押额，通过后才转入有效质押额。项目在途金额与可融金额不作常态展示，只在办理需要时当场给出，也不另行提供其换算说明。

<a id="F-LS-20"></a><a id="f-ls-20"></a>**F-LS-20** 查看与办理分开，已确认的业务安排继续保留：项目详情同时提供质押代币清单、融资申请信息、融资放款信息、还款信息四类记录，并按此顺序讲述；定位到其中一类时其余三类仍然可得，不被隐藏或替换。办理按质押、融资、还款三类业务归集，三类入口在项目详情始终可达。游客同样能看到这三类业务的存在，但只有统一“立即登录”动作，不展示私有待办。各清单独立保留筛选和页码，空态与读取失败分别呈现，不提供全项目操作日志。

| 用户动作 | 结果 |
| --- | --- |
| 从记录查看详情 | 只读呈现当前记录、历史、计划、账户和文件；不提供办理、跨业务跳转或重复的查看入口。历史与预览在本次查看内直接展开，文件按权限下载 |
| 从办理入口办理 | 先明确申请、业务或期次，再进入本次办理；多笔待办不能默认代选“最新一笔”。步骤、必要确认与放弃修改都在本次办理内完成，不再叠加下一层办理 |
| 返回或关闭 | 返回上一步保留已填内容和成功附件；关闭有未提交编辑时就地确认放弃，取消放弃继续编辑。关闭后回到来源并保留原筛选、分页与所在位置；只读详情关闭不改业务 |
| 成功、失败或结果未知 | 成功只更新本笔及相关办理入口，不自动打开详情、下一笔或下一阶段。失败保留可复用输入；未知显示待核实，不假报成功或引导重复提交 |

发布、质押成功发起、报价成功均结束本次办理；授信保存成功同样结束本次办理并提示“已授信，请继续报价”，须由用户再次发起报价才进入报价。报价说明必要后果后直接提交，无二次确认；其他动作原有必要确认保留。见[查询与办理图](02-融资需求与代币质押-流程图与状态机.md#fl-ls-07)。

<a id="D-LS-61"></a><a id="d-ls-61"></a>平台已知且有权使用的本笔信息自动带入，优先本笔已确认事实，其次同企业、用途及币种的有效登记资料；仅补业务必需缺项。只读事实不能改写，可编辑项仍校验，逐笔确认不能省略。不得串用不同机构、企业、用途的账户，或把旧合同、旧转账凭证默认用于新业务；缺失/失败不填示例或零值。

## 3. 创建项目、项目审核与代币质押
<a id="pledge"></a>

### 创建融资项目并提交审核
<a id="create"></a>

<a id="F-LS-01"></a><a id="f-ls-01"></a>**F-LS-01** 本企业资产方从广场或控制台进入创建，填写项目名称、选择代币类型、自填质押率与项目期限、选择参考结算币种，并核对平台带出的还款方式与SPV机构名称后提交。提交即进入项目审核：创建本身不勾选代币、不发生链上操作、不需要签名、不产生任何费用。一个融资项目对应一份质押合约，项目与合约一一对应。

| 创建信息 | 必填与校验 |
| --- | --- |
| <a id="FP-02"></a><a id="fp-02"></a>项目名称（FP-02） | 文本，必填1～60字符，同企业不要求唯一；同名项目以项目编号区分。合约部署完成前可修改，部署完成后只读 |
| <a id="FP-29"></a><a id="fp-29"></a>代币类型（FP-29） | 必选单值，取运营已配置的代币类型，形如 `ERC-20-应收账款`，代币标准与底层资产类型合并为一个字段；候选按当前企业在只读代币域已有代币的类型过滤，本期配置表只有一行。不可自定义输入，无可选类型时不能提交并提示先完成代币发行与同步。字段形态须能容纳将来的其他标准（如 `TRC-20-应收账款`），不写死 `ERC-20`。合约部署完成后只读，本项目只接受同类型代币 |
| <a id="FP-34"></a><a id="fp-34"></a>项目质押率（FP-34） | 百分比，必填，由资产方自填，不得超过运营对该代币类型配置的最高质押率，超出不可提交并给出当前上限。**创建时锁定终身**：运营此后调整配置不影响存量项目，本项目全部额度计算始终用创建时锁定的值。合约部署完成后只读 |
| <a id="FP-35"></a><a id="fp-35"></a>项目期限（FP-35） | 必填，3 个月～1 年，不得超过运营对该代币类型配置的上限；**自项目创建时间起算**，审核退回后修改重提不重新起算。合约部署完成后只读 |
| <a id="FP-30"></a><a id="fp-30"></a><a id="D-LS-60"></a><a id="d-ls-60"></a>参考结算币种（FP-30） | 必填多选，USD（法币）、USDT/USDC（数币）至少一项，可跨类选择，首次默认空；不支持项不能提交。审核时属核对带出值，不因审核改写。它只供参考，不限制机构选择任何已支持报价币种，不决定实际币种、额度或合同；实际结算以成功报价及接受条款为准 |
| <a id="FP-36"></a><a id="fp-36"></a>还款方式（FP-36） | 平台定值，按季付息、到期还本付息；创建时带出、只读，本期不提供选择或修改，也不按企业或项目区分 |
| <a id="FP-31"></a><a id="fp-31"></a>SPV机构名称（FP-31） | 平台默认的单一机构名称，**取值在代码层面维护、随版本发布**；创建时只读带出并随项目留存。平台内不提供该名称的维护、配置、切换或审批入口，面客端与运营端都没有；本期不按企业或项目区分，不可选择、修改或留空，也不会出现空值或占位名。版本更新默认值只影响此后新建项目，不改写已创建项目，也不产生变更通知 |
| 企业与项目编号 | 当前企业自动取得；项目编号创建时生成、全局唯一、终身稳定，只读 |

<a id="F-LS-12"></a><a id="f-ls-12"></a>**F-LS-12** 提交后项目进入待审核，属本企业私有：不出现在广场、不暴露存在性，不能发起质押，也不能发布融资需求；待审核期间创建信息不可改，等结论后按结论办理。审核通过即合约部署成功，项目转入可用状态，资产方在项目详情[自主发起代币质押](#pledge-apply)；审核退回则给出面客可读原因，资产方可修改后重新提交，项目期限不重新起算。

项目通过审核后至首张代币质押通过审核前为空池：发布入口保持可见但不可提交，并说明“本项目暂无有效质押，请先完成代币质押后再发布”。项目可长期停留在空池，随时发起质押或按既有条件关闭，不因未质押被自动关闭、自动清除或自动催办；同一企业可同时存在的空池项目数量本期不设上限，创建不因已有空池项目被拦截或提示。质押全部被驳回、撤回或上链失败后回到同一空池状态，可按资格重新发起。创建、质押与发布各自可中断再继续，不要求重复质押或重复付费。

### 项目审核与合约部署
<a id="project-review"></a>

<a id="F-LS-22"></a><a id="f-ls-22"></a>**F-LS-22** 审核与部署是同一步：管理端核对创建信息后，由平台统一钱包发起本项目质押合约部署；**部署成功即视为审核通过**，同时产生本项目的合约地址。签名或部署失败视为审核未完成，由管理人员再次发起，不需要资产方重新提交、不改变项目期限起算点、不产生第二个项目。

审核结论只有**通过**与**退回**两种，没有第三种结论，也没有时限管控——平台不设审核截止，不会因等待自动通过或自动失败。退回必须给出面客可读原因；资产方可修改创建信息后重新提交，重新提交仍走同一条审核与部署链路。

部署 gas 由管理端承担，资产方不付费也不签名；运营人员只做业务操作，不签名。平台统一钱包的取值在代码层面维护、随版本发布，平台不提供维护、配置或切换入口，范式同[SPV机构名称](#fp-31)。合约模板与代码、部署脚本、链与网络配置、部署确认数、钱包密钥保管与 gas 充值属实现侧依赖，不在本册定义，见[真实依赖](#dependencies)。

| 信息 | 类型 / 必有条件 | 含义及校验 |
| --- | --- | --- |
| <a id="FP-33"></a><a id="fp-33"></a>质押合约地址（FP-33） | 文本 / 审核通过后必有 | 部署成功时产生的本项目质押合约地址，全局唯一、与项目一一对应、终身稳定、只读；属公开业务事实，可复制完整值并自行打开区块链浏览器查验，平台不做链上核验。部署完成前为空，不显示占位值 |
| <a id="FP-37"></a><a id="fp-37"></a>审核退回原因（FP-37） | 文本 / 退回时必有 | 面客可读原文，不截断改写、不带内部备注；通过或待审核为空。重新提交后保留在本项目审核历史中，不覆盖 |

### 在项目详情发起代币质押
<a id="pledge-apply"></a>

<a id="F-LS-05"></a><a id="f-ls-05"></a>**F-LS-05** 项目审核通过后才能发起质押：本企业资产方从控制台的融资项目进入本项目，办理动作在项目详情内完成，首笔与追加共用同一条链路和同一套规则。项目在可用、募集中、已锁定、融资中均按资格允许发起，待审核、已退回与终态不允许。资产方从可质押清单批量勾选代币：至少一张、不重复、整张勾选，无数量输入；清单默认按本项目代币类型过滤，显示数量/币种、签发价值、账期、买方及有效性，不显示合同号/发票号。

<a id="eligibility"></a>

<a id="F-LS-04"></a><a id="f-ls-04"></a>**F-LS-04** 可选代币必须同时满足六项：已同步至本平台只读代币域；归属当前企业；不在任何质押合约内、无其他在途质押或解押占用；发行平台判为有效；属本期已配置的代币类型；与本项目代币类型一致。无需本平台上架动作。其他企业代币不可见；被在途质押或解押占用、以及已驳回尚未解押的代币可只读提示占用来源但不可选；并发选择同张只有一笔成立。

<a id="D-LS-62"></a><a id="d-ls-62"></a>每张代币只有**一个当前真实链上持有地址**，对应整笔数量和签发价值；企业归属、当前地址、质押前原持有地址分别表达。业务释放未提取不能把地址提前改回企业地址，不能将原地址和合约地址重复计量。当前所在质押合约至多一个，历史项目不算当前占用。地址、归属或数量价值不可靠时不猜测放行。代币价值不二次折算，失效只取发行平台结果；本平台质押事实不反向读取上游同名状态。

### 由资产方签名发起上链
<a id="execution"></a>

<a id="F-LS-08"></a><a id="f-ls-08"></a>**F-LS-08** <a id="D-LS-50"></a><a id="d-ls-50"></a>质押上链由资产方用代币当前持有地址向本项目质押合约签名发起，平台不代签、不代付、不垫付。<a id="F-LS-14"></a><a id="f-ls-14"></a>**F-LS-14** 链上 gas 由资产方自担，平台不收服务费、不返还，**上链失败已经产生的 gas 同样不退**；发起前须把“本次将发生链上操作、需要本人签名、gas 自担且失败不退”一次讲清，不在发起后才告知。

<a id="D-LS-51"></a><a id="d-ls-51"></a>发起前逐张复核资格。任一资格或状态变化，指明变化并更新集合，此时任何张都未发起；保留有效选择，由用户确认更新后再签名，不静默剔除或补选。未签名、取消签名或钱包不可用时明确本次未发生链上操作、无 gas 产生，代币保持可质押。

| 上链结果 | 业务变化和反馈 |
| --- | --- |
| 明确成功 | 本张代币进入本项目质押合约，质押状态为已质押，**计入[待审质押额](#fp-32)，暂不计入[有效质押额](#fp-12)**，等待逐笔审核；可核对完成时间、实际 gas 和链上凭证 |
| 明确失败 | 本张未进入合约、不计任何额度，按当前资格可重新发起；显示原因、是否已产生 gas 及金额、下一步。失败通知定位本次动作 |
| 结果未确认 | 本张处理中，不计任何额度，不可重押、撤回或重复发起；显示等待时长、已知 gas，未知标待核实。其他张和项目办理仍按各自资格，不锁整池 |

同次多张的结果分别呈现，不回滚成功张、不给一次操作一个笼统结果；重复点击、刷新或重复提交同次操作不得二次转移或二次扣费。上链成功不另发通知。见[创建项目、审核与质押图](02-融资需求与代币质押-流程图与状态机.md#fl-ls-01)与[质押与执行状态图](02-融资需求与代币质押-流程图与状态机.md#st-ls-02)。

### 逐笔审核结果与后续动作
<a id="review"></a>

<a id="F-LS-21"></a><a id="f-ls-21"></a>**F-LS-21** <a id="D-LS-49"></a><a id="d-ls-49"></a>已上链的每张代币独立审核，提交批次仅用于追溯。同批可有不同审核人、结果和协议；一笔通过即计入有效质押额，不等全批。审核状态在申请上，代币在合约内不等于已通过审核。运营端负责结论，资产方在本项目“质押审核”查看：一张当前代币一条记录，当前有效申请优先，否则显示最近结果；重新发起生成新单笔，旧结果留在逐币历史。

| 本笔结果或动作 | 用户所见与后续 |
| --- | --- |
| 待审核 | 显示已等待时长。**审核无时效管控**：不设截止，不因等待自动通过或自动失败，也不因查看、上传或编辑改变状态。本张在合约内，计入待审质押额，不计入有效质押额；资产方可自助撤回 |
| 通过 | 展示本笔审核人、时间及协议；本张自通过起计入有效质押额并参与覆盖判断，从待审质押额移出 |
| 驳回 | 原样完整展示面客原因，不能截断改写或暴露内部备注。**本张仍在质押合约内并继续计入待审质押额**，既不自动退回，也不能用于其他项目；须由资产方[自助解押](#withdraw)取回后才恢复可质押 |
| 待审撤回 | 资产方在裁定前自助解押取回；与审核同时发生仅一个结果成立，已通过不能借撤回取消结论。撤回保留本笔记录 |

审核清单提供代币标识、数量、金额、审核状态、上链时间及勾选，不提供逐条办理动作，默认上链时间倒序。默认包含全部当前代币，可按审核状态、后续情况及代币编号筛选，并可重置。对应协议文件名可直接下载；账期、买方、审核人及上链明细在本次查看内可得，提交编号在历史可查。分页后已勾选张数须保持并可见；换项目、改筛选或结束本次查看清空选择并提示，再次进入默认未勾选。

本笔协议通过后必有1～5个有效关联文件，只向本企业相应资产方提供；文件关联失效仅存档，不连带作废其他笔共用文件。审核通过与驳回各由运营审核模块发送一条站内信，本模块不双发；审核超时通知随时效管控取消一并作废。见[申请状态机](02-融资需求与代币质押-流程图与状态机.md#st-ls-03)。

<a id="exceptions"></a>

<a id="D-LS-63"></a><a id="d-ls-63"></a>**异常仅联系客服。** 长期未知、已发起但跨项目终态、事实冲突及混合结果中的待核实笔，提示“链上结果待核实，请联系平台客服人员”，保留业务编号、代币、动作、已知 gas 和凭证及保护限制。差异代币不计有效覆盖、冻结其新动作并重算。无工单、自动升级、人工改判/补记、强制释放、补偿、换地址或恢复资格流程；不编造联系方式、处理时限。客服介入不等于自动完成、退款或恢复。普通晚到且无跨期/冲突的结果按原笔更新；终态项目晚到转入保留真实持有位置，不恢复项目或覆盖，也不设计自动异常退回。

当前质押状态由借贷平台定义：PS-1 可质押、PS-2 已质押（在质押合约内）、PS-4 已释放；PS-3为作废编号，PS-0不是合法值。PS-2 只说明代币在合约内，不代表已通过审核：审核通过前计入待审质押额，通过后才计入有效质押额。业务释放后尚在合约内为已释放待提取，实际转回原地址且无占用后才按当前资格可质押。链上执行状态独立为未发起（CT-0）、处理中（CT-1）、成功（CT-2）、失败（CT-3），成功不替代审核结论、代币有效性及项目资格判断。内部状态号不出现在面客文案。

## 4. 发布与管理融资需求
<a id="publish"></a>

<a id="F-LS-02"></a><a id="f-ls-02"></a>**F-LS-02** 本企业资产方从“融资”办理。项目通过审核后发布入口持续可见，但必须已有通过审核的质押；空池不可发布。提交时重新核实当前身份和最新额度；项目未到期、未终态，有效质押价值大于0，金额不超过可融金额才可成功。**本环节未结束不允许发布新需求**：上一轮需求须已终结，且其成交业务已完成放款确认，才能发起新一轮。

| 办理 | 输入与结果 |
| --- | --- |
| 发布 | 必填USD需求金额，正数、最多2位小数，无默认建议金额。参考结算币种取创建时的选择，发布时只读带出。办理时展示当场可融金额，不足给出差额。成功生成本轮申请编号，占用在途金额，状态待报价；项目期限自创建起算，不因发布重置 |
| <a id="F-LS-03"></a><a id="f-ls-03"></a>修改（F-LS-03） | 仅尚未被报价且仍可修改的当前轮；带出金额，按最新额度复核本轮更新后的占用，不把原占用重复计算。成功保留轮次编号，已锁定或进入履约的条款不可在此改写 |
| 撤下 | 仅尚未被报价且仍有效的本轮；已收到报价的须先拒绝该报价、本轮回到待报价后才能撤下。确认后终结本轮、释放其占用并保留原编号及原因，不清除其他债务或整池质押 |
| <a id="D-FIN-76"></a><a id="d-fin-76"></a>再次发布 | 原需求终结且本环节已结束后无冷却；在项目未到期、未终态并重新满足发布条件时创建新轮次、新编号。旧报价/成交记录保留，不重建项目、不重置项目期限、不清除存量债务 |

发布成功即结束本次办理并回到融资申请信息清单的该轮记录，不自动打开报价；失败保留输入和原因，不回滚已完成质押、不再次收费。首次成功发布之前项目保持可用状态，对外不可见。见[发布图](02-融资需求与代币质押-流程图与状态机.md#fl-ls-02)。

参考结算币种（FP-30）在[创建融资项目](#create)时确定并随项目锁定，各轮需求沿用同一取值，发布与修改时只读带出、不在本环节重选；历史无值显示“未提供”。本期固定1:1:1及具体结算规则由L6～L8承接。

| 业务量 | 定义 |
| --- | --- |
| <a id="FP-10"></a><a id="fp-10"></a>总质押额（FP-10） | 本项目质押合约内全部代币的签发价值合计，含失效代币与尚未通过审核的代币；只展示、不参与准入。原名“池内资产总额”，口径不变 |
| <a id="FP-11"></a><a id="fp-11"></a>有效质押价值（FP-11） | 同时审核通过、实际转入成功、发行平台判有效、无差异且未撤回预扣的在池价值；上链处理中、待审核、已驳回未解押均不计入 |
| <a id="FP-32"></a><a id="fp-32"></a>待审质押额（FP-32） | 已在本项目质押合约内、但尚未计入有效质押价值的签发价值合计，包含**审核尚未裁定**与**审核已驳回、资产方尚未解押**两部分。两部分合计成一个数值，明细必须能区分这两种状态——待审的可以等待或自助撤回，已驳回的须自助解押。上链处理中尚未成功的不计入 |
| <a id="FP-12"></a><a id="fp-12"></a>有效质押额（FP-12） | 有效质押价值 × [项目质押率](#fp-34)。原名“融资上限”，口径不变；质押率取创建时锁定值，运营后续调整不影响存量项目 |
| <a id="FP-13"></a><a id="fp-13"></a>项目融资余额（FP-13） | 本项目未偿本金合计；不得在规则中简写为“融资余额” |
| <a id="FP-14"></a><a id="fp-14"></a>项目在途金额（FP-14） | 已发布且未终结需求金额合计，唯一来源是发布占用，报价不再新增项目占用 |
| <a id="FP-15"></a><a id="fp-15"></a>可融金额（FP-15） | max(0，有效质押额 − 项目融资余额 − 项目在途金额) |
| <a id="FP-16"></a><a id="fp-16"></a>可撤回上限（FP-16） | 可融金额 ÷ 项目质押率，只约束已通过审核的抵押物撤回；待审与已驳回未解押的代币不受此上限约束 |

<a id="F-LS-09"></a><a id="f-ls-09"></a>**F-LS-09** <a id="INV-FIN-01"></a><a id="inv-fin-01"></a>新增占用后须满足“有效质押额 ≥ 项目融资余额＋项目在途金额”；外部失效导致不足则按第7章收口，不能继续新增占用。已发布需求的报价只校验已有覆盖和L6授信条件，不因可融金额为0单独禁止报价。放款确认时，本笔金额同时从在途移出、计入项目融资余额，不能有两边都不计的空档。占用不从有效质押价值里扣减。

可先预览，提交以当场权威重算为准，不用旧的预览数字放行。项目审核通过、质押上链结果与审核结论、发布/修改/撤下、质押变化、报价与接受/失效、放款及确认、还款结清、项目终态/到期、审核/执行结果、代币状态及差异变化均触发相应重算。金额展示与日期共用口径见第8章。

处理中的质押变更（FP-24）仅用于提示相关代币执行进度与防重复提交，不锁定整池；不存在执行中代币时不显示处理中。

### 项目、轮次及后续业务
<a id="project-state"></a>

项目状态为待审核（S-FP-7）、已退回（S-FP-8）、可用（S-FP-1）、募集中（S-FP-2）、已锁定（S-FP-3）、融资中（S-FP-4）、已关闭（S-FP-5）、已结清（S-FP-6）。创建提交后进入待审核；审核通过即合约部署成功，转入可用（原“草稿”，语义为已建池未发布）；审核退回进入已退回，修改重提回到待审核，项目期限不重新起算。待审核与已退回不出现在广场、不可质押、不可发布，可由资产方主动关闭。报价锁定本轮，拒绝或届满后仅在需求仍有效、项目未到期时恢复相应可办状态。接受报价进入融资中。撤下/失效后无其他在途与未结清业务时回可用；项目实际关闭或全部融资业务结清时才整池业务释放。可用状态可主动关闭；募集中按既有无阻断业务条件关闭，到期且无在途/未结清业务可关闭。到期仍有存量业务保留“已到期·存量处理中”并行标记，按正常中性状态展示，禁止新融资但继续存量履约。详见[项目状态机](02-融资需求与代币质押-流程图与状态机.md#st-ls-01)。

<a id="D-LS-64"></a><a id="d-ls-64"></a>**单笔融资业务没有中途终止出口**：进入待放款后，本笔在途占用只会在放款确认时转为项目融资余额，平台侧没有任何动作能提前释放它，也不新增终止或审批入口（业务后果见[按用户决定保留的业务限制](#accepted-limits)）。各笔债务、在途与履约互不牵连：某笔停在待放款不影响其他笔继续履约，也不因此回到募集中或释放整池质押。已到期不恢复新发布、新报价或期限；未到期未终态按剩余全部事实重新判资格。终态仍可解押或提取未取回代币，不能追加质押或再次关闭。

### 融资申请详情
<a id="application-detail"></a>

融资申请详情包含金额与申请状态、需求信息、当前报价及授信摘要、报价历史、协议文件五部分信息，并按此顺序讲述。需求信息含申请/项目标识、企业、本轮金额、参考币种、时间和项目有效期。申请状态保留待报价、已报价待确认、放款中、已放款、已失效/已关闭五类事实展示，终结同时说明原因；不拼入还款逾期或结清状态，不新增一套申请审批。

只呈现当前有效或已接受的一笔报价；历史报价按需查看，每条可查看自身条款，不替换当前报价、不提供恢复或接受旧报价动作。授信摘要仅当前报价机构对企业的总授信和已用授信，不等于本项目额度，不提供历次授信/追加明细，也不另设授信详情入口。预计还款计划在查看报价时按需可得，明确“预计·未生效”，接受前可读。报价和授信的完整条款见[授信报价PRD](../v1.0-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md)。

协议按文件逐条给出名称、用途、业务/版本及已有上传时间，并可下载。当前适用版本与历史版本可辨，同文件在放款详情复用，不生成另一份事实。无文件、无权、读取失败分别反馈，不新增签署或审核。

### 放款与还款详情
<a id="fulfilment"></a>

放款详情须说明金额、阶段和当前处理方，并给出放款信息、凭证/Hash、已有定义账户、适用协议，按此顺序讲述；申请编号仅作展示，不提供跨业务跳转或嵌套的申请详情。放款展示状态只有待放款、待放款确认、已放款三种，沿[放款PRD](../v1.0-借贷广场-放款与放款确认/01-放款与放款确认-PRD.md)；该模块的合同盖章件核验、要求重传、暂不放款、放款前终止与确认时限已全部取消，本册不保留这些说法，也不以其他名义恢复。**资产方确认到账后，该笔在融资放款信息中保持“已放款”；后续还款、逾期或结清归还款信息。** 登记不等于到账，待放款确认不冒充已放款。

还款详情给出本期应还/待确认摘要、定稿计划（一期一条）、账户及还款/确认记录；选期仅办理本期。正式计划生成中、不存在待还期次或已全部结清分别说明，不填虚假金额，不拿预计计划充正式计划，不回滚到账事实。期次、金额、期限及办理资格见[还款PRD](../v1.0-借贷广场-还款计划与还款确认/01-还款计划与还款确认-PRD.md)。只在进入还款的成交笔中申请/业务/放款编号为1:1:1，报价阶段可先后多笔；期次编号与一次成功还款提交编号分别识别。

放款收款账户属资产方，由接受报价时确认、放款沿用；还款收款账户属资金方，由放款登记确定、还款沿用。账户统一在企业账户模块维护后于办理时下拉选用，**业务办理过程中不支持临时新增账户**。本期不新增双方出账账户必填，不把付款账户默认等同其收款账户；原有付款凭证保留。文件与账户不因新增清单而公开。

## 6. 撤回、业务释放与自助提取
<a id="withdraw"></a>

<a id="F-LS-06"></a><a id="f-ls-06"></a>**F-LS-06** 本企业资产方从“质押—解除质押”统一进入，待审代币、已驳回代币、已失效代币、有效抵押物、已释放待提取五类分别呈现且互不混淆。解押与提取都不走运营审核，由资产方自行向本项目质押合约签名发起、**gas 自担且失败不退**，合约按记录转回**质押前原持有地址**，平台不代签、不代付，也不能人工指定其他地址。见[解除质押图](02-融资需求与代币质押-流程图与状态机.md#fl-ls-03)。

| 对象 | 准入与结果 |
| --- | --- |
| 待审代币 | 审核尚未裁定即可自助撤回，无需额度判定、无需等待审核；撤回成立后本笔审核终结为已撤回，该张从待审质押额移出 |
| 已驳回代币 | 驳回后仍在合约内并继续计入待审质押额，须自助解押取回；无需额度判定，取回且无占用后才恢复可质押、才能用于其他项目 |
| 有效抵押物 | 已通过审核的代币，撤回后仍须“剩余有效质押价值× 项目质押率 ≥ 项目融资余额＋项目在途金额”。办理时可撤回上限须可得，并随勾选实时累计对照；提交以最新值校验。有在途报价本身不阻止符合额度的撤回 |
| 已失效代币 | 已不计覆盖，撤回无需额度判定；仍受真实占用、处理中和差异保护，不因失效绕过安全条件 |
| <a id="F-LS-17"></a><a id="f-ls-17"></a>已释放待提取（F-LS-17） | 项目实际关闭/结清时即时解除池内业务关系，零 gas、无链上动作；之后资产方自助提取，可批量、gas 自担、无时间限制。未提取仍在合约内，不属于任何池、不计任何额度且不能再质押 |

撤回超限必须给出拟撤回价值、当前上限、差额，并给出减少勾选/等待还款释放余额两条路径。额度不足的对应动作保持可见但不可提交并说明原因，不能因此使有资格的失效代币撤回或待提取操作无法进行；游客/非本方无私有动作。

已通过审核代币的撤回，实际发起即预扣该张有效价值，并发报价按扣后池值判断。明确失败保持在池、撤销预扣并重算；成功按真实转出移出池，不先假报已释放。待审与已驳回代币的解押不涉及有效质押价值，成功后直接从待审质押额移出。提取失败仍已释放待提取，不恢复池占用；成功确认转回原地址。记录保留实际凭证、时间、gas 和原因；未知/冲突按第3章联系客服与保护，不自动重试。

有待提取或待解押代币时，解除质押入口须提示张数和金额，并明确 gas 自担、可批量、不自动回钱包。每次签名前告知张数与预估 gas；24小时提交超过5次提示频繁操作 gas 较多，不硬性阻断。单笔业务结清只降低项目融资余额、提高可撤回上限，不自动释放“对应代币”。

## 7. 覆盖变化、需求失效与通知
<a id="coverage"></a>

发行平台判代币失效或后台标记持仓差异后，先从有效质押价值排除并权威重算，再判现有需求和债务覆盖。代币失效不自动转出，产生既有运营待办，可由资产方按上章自助解押清出；差异保护不新增异常处置队列。

| 当前情况 | 判据及用户结果 |
| --- | --- |
| 覆盖有余 | 有效质押额足以覆盖项目融资余额及在途，且可融金额大于0；按资格正常办理 |
| 覆盖持平 | 已有占用仍满足覆盖，可融金额为0；不新增发布，有效抵押物可撤回上限为0；原有效申请报价按已有覆盖及授信条件，不一概禁止 |
| 覆盖不足 | 有效质押额小于项目融资余额，即已存在债务本身不足；禁止新增占用并触发覆盖提醒 |

**需求失效与债务提醒是两种事实。** 新增准入比较“项目融资余额＋项目在途金额”，债务提醒只比较“项目融资余额”。需求失效后可能债务仍被覆盖；无在途需求时债务仍可能不足。

<a id="invalidation"></a>

<a id="F-LS-19"></a><a id="f-ls-19"></a>**F-LS-19** 需求重算后不能满足占用覆盖时，立即按发布时间倒序使最小必要的需求失效，每失效一笔释放其在途并重算；满足即停止。等价校验为：按发布时间正序保留较早需求，对每笔比较“有效质押额－项目融资余额－更早已保留金额”是否足够。本期单一在途需求仍遵守此口径，不借多笔兜底规则开放并行发布。无需求可失效而仍不足就停止，保留债务提醒，不空转。

<a id="D-FIN-75"></a><a id="d-fin-75"></a>该轮需求与在途报价在同一事实变更内失效，用户不能看到需求失效而报价仍可接受。记录原编号及“自动失效·覆盖不足”终结原因，不新增项目状态、缓冲期或补质押倒计时；原轮不可恢复，满足资格可立即新轮发布。通知只由L5发送，L6不为同一覆盖原因再发一封报价失效信。见[需求失效图](02-融资需求与代币质押-流程图与状态机.md#fl-ls-04)。

<a id="F-LS-16"></a><a id="f-ls-16"></a>**F-LS-16** 覆盖不足时显示缺口＝项目融资余额－有效质押额，以及需追加资产价值＝缺口 ÷ 项目质押率。资产方在项目与控制台都能得到提示、待办和追加入口，明确“追加质押须先上链再经审核通过才计入有效质押额，上链成功不即时生效”；债权机构可见缺口及触发时间，平台运营有既有待办与监控。广场向游客和全部资金方公开中性覆盖事实。条件反转自动解除，无需人工确认；触发与解除保留时间、当时有效质押价值/有效质押额/项目融资余额、诱因及解除时间。见[覆盖提醒图](02-融资需求与代币质押-流程图与状态机.md#fl-ls-06)。

主动通知为八类：项目审核通过、项目审核退回、逐笔质押审核通过、逐笔质押驳回（前四类由相应审核模块唯一发送）；明确上链失败、需求自动失效、覆盖不足及解除、项目届满前7天（本模块唯一发送）。上链结果未知、上链成功、可提取及持续不足不新增消息；业务事实始终可查。原“48小时审核超时”通知随时效取消一并作废。收件范围、去重、原对象落点和双语模板统一见[通知册](03-融资需求与代币质押-消息通知.md)；收件账号为该企业的唯一员工账号。
