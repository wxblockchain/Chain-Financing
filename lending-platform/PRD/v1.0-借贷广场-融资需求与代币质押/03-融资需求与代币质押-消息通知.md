# 融资需求与代币质押 · 消息通知

版本：V1.1｜所属模块：WS-351 / L5｜配套功能基线：L5 V1.4｜产品经理：许楚清。

**本模块涉及 8 类关键站内信：其中 3 类审核结果由 WS-359 统一发送，5 类执行与项目事件由 WS-351 负责。** 同一审核结果不由两个模块各发一条。资产方接收与本人办理或本项目有关的通知；资金方只接收与其在途报价、未结清债权相关的项目事件；运营管理人员保留已有待办与监控，本轮不增加运营广播。仅站内信，不增加邮件、短信、浏览器推送。

核对“哪个环节要发给谁”直接读第 1 章；开发主读第 1～5 章，测试主读第 6 章；跨模块归属与未定项见第 2、7 章。本文件补齐 L5 功能册 §12.2 的通知细节，保留 D-LS-44～46、AC-LS-82/125/126/135/136；不代改 L6～L8，也不改变审核、质押与项目状态机。业务图继续使用 L5 既有 FL-LS-01、04、06 及 ST-LS-03，本文件无新增业务流程或状态机。

## 1. 哪个环节发送站内信

以下 N-LS-01～08 是本文件通知编号，不替代业务状态或原需求编号。“一笔”指一张代币的本次申请；批次只是提交追溯，不是审核或消息的最小对象。

| 编号 | 发送节点与成立条件 | 收件人 | 需要知道或办理什么 | 唯一发送归属 |
| --- | --- | --- | --- | --- |
| N-LS-01 | 单笔审核通过结论生效；本笔可待资产方确认入池 | 提交该笔申请的资产方本平台账号 | 哪笔已通过、通过时间、本笔七天入池截止；仍须本人确认并承担实际执行费用，审核通过不等于质押成功 | WS-359 审核结果；L5 提供面客承接 |
| N-LS-02 | 单笔审核驳回结论生效 | 同上 | 仅本笔被驳回、完整面客原因；保留记录，按当前资格可重新申请 | WS-359 审核结果 |
| N-LS-03 | 自本笔提交成功起连续 48 小时届满，仍未完成审核，正式判定本笔质押失败（审核超时） | 同上 | 未在审核时限内处理、本笔未执行且零费用、申请占用已释放；保留记录，按资格可再次申请 | WS-359 审核超时结果 |
| N-LS-04 | 某笔实际链上操作收到明确失败结果；包括转入、正常撤回、已释放代币提取 | 发起这次操作的资产方本平台账号 | 哪张代币、哪次操作失败、业务可读原因、已知费用及当前可做的下一步 | WS-351 执行结果；发行平台提供事实，不另向本平台收件人重复推送 |
| N-LS-05 | 权威重算后，某轮融资需求正式因覆盖不足自动失效，该轮在途报价同时失效 | 本轮需求的资产方；该轮有在途报价的资金方业务关联账号 | 明确原融资申请编号、失效原因和报价影响；重新发布必须满足当前资格并产生新轮次 | WS-351 项目与需求事件 |
| N-LS-06 | 项目从非覆盖不足进入覆盖不足，形成新一轮覆盖提醒 | 项目资产方；该项目有未结清业务的债权机构所关联的本平台资金方账号 | 发生时间、覆盖缺口、需追加资产价值；追加先审核、成功入池后才生效 | WS-351 覆盖事件 |
| N-LS-07 | 原覆盖不足条件反转，本轮提醒自动解除 | 项目资产方；解除时该项目仍有未结清业务的债权机构所关联的本平台资金方账号 | 本轮覆盖不足已解除；不等于债务已还清，也不承诺以后不会再出现缺口 | WS-351 覆盖事件 |
| N-LS-08 | 项目到达现行有效期届满前 7 天的提醒节点，项目尚未提前关闭或结清 | 项目资产方 | 项目有效期、已进入最后窗口；到期不再支持新增融资，存量业务按其当前状态办理 | WS-351 项目期限事件 |

N-LS-06 与 N-LS-05 不互相替代：前者针对已放款债务的覆盖，后者针对某一轮需求的自动失效。一次资产变化可能使两种事实都成立，应分别告知对应受影响人，不将它们合成“项目失效”。参考币种仅供报价参考，不作为筛选收件机构或判定通知金额的依据。

### 1.1 明确不发送的场景

| 场景 | 处理 |
| --- | --- |
| 建池、保存草稿、发布、改额、主动撤下、关闭等当场操作反馈 | 保留页面结果；本轮不加自操作回执或向所有资金方推送新项目 |
| 批量提交成功、进入待审、查看、上传协议、编辑原因、打开通知 | 不发送过程消息；审核时钟不因这些操作重新计时 |
| 审核通过后的七天内催办、未发起而许可过期、发起前复核不通过 | 截止及当前原因在对应记录展示，不新增临期、每日催办或过期推送；不把许可失效改成历史审核驳回 |
| 执行已发起、处理中、执行成功、批量确认整体进度 | 在代币清单展示；不为每个中间阶段或成功结果发消息，不等待批次全部结束才通知已确定失败的笔 |
| 执行长时间无结果、跨期、结果冲突及部分结果待核实 | 未知不能当失败；P03已确定仅提示联系平台客服，本期不实现异常处置；保留真实逐张结果与保护限制，不新增差异处置待办、升级或客服进度通知，不启用旧execution_timeout失败通知 |
| 正常释放后可提取、提取成功、项目届满前 30 天 | 页面提示；不催用户支付提取费用，不新增早期提醒或到期当天第二次提醒 |
| 覆盖不足持续存在、缺口数字变化但未解除 | 更新项目事实与既有待办，不按重算次数、登录次数、时间周期重复发信 |
| 列表浏览、筛选、四区定位标签、复制、下载或页面读取失败 | 页面反馈，不产生业务通知；L5 V1.3 后新增的定位标签不改变通知范围 |
| 资产广场同步、代币失效或持有分布展示变化 | WS-350 无发送事件；若由此引起 L5 的实际覆盖/失效事件，仅按 N-LS-05～07 通知 |
| 报价、授信、接受/拒绝、放款/到账确认、还款/确认 | 分别由 WS-352、WS-353、WS-354 定义通知；虽在同一项目展示，不转为 L5 的额外消息 |

## 2. 三方范围与跨模块发送责任

### 2.1 接收范围

| 角色 | 账户归属与禁止扩散 |
| --- | --- |
| 资产方 | 审核事件按该笔原提交账号，执行事件按本次原发起账号；项目/需求事件按已有业务明确关联的资产方收件账号。项目归属企业不能直接推出“所有成员都是收件人”；多成员项目事件的具体代表账号见 Q-LS-N01，不临时猜人 |
| 资金方 | N-LS-05 仅该轮仍在途报价的机构，N-LS-06/07 仅该项目仍有未结清债权的机构；映射到相关业务登记的本平台账号，每个账号独立消息。同一账号有多笔相关报价或债权时，同一项目事件仅收一次；不通知曾浏览、已拒绝/已失效报价、已全部结清或不相关机构 |
| 运营管理人员 | 逐笔审核队列、覆盖监控继续存在；结果异常仅客服指引，不新增异常处置队列；读取或处理事实不等于需要一条额外站内信。新申请不全员广播，审核成功不通知刚完成操作的审核人；本轮无新增运营模板。WS-359后续按P03同步客服边界，本期不追加异常处置站内提醒 |
| 游客与跨平台身份 | 不作为收件人。归属以借贷平台自然人账号及端别隔离，不用钱包、邮箱、企业名称或其他平台原账号替代；同一钱包的资产方/资金方身份不串信 |

业务节点成立时确定受影响主体，延迟展示不把历史消息改投新操作人。收件账号尚无可靠关联时，不广播补位、不任意选择管理员；由来源业务补齐归属，业务事实和页面结果不回滚。账号停用或当前无访问资格时，也不自动改投其同事。

### 2.2 发送与承接边界

| 事实 | 谁负责产生唯一通知 | 其他模块的责任 |
| --- | --- | --- |
| 单笔通过、驳回、审核 48 小时超时 | WS-359，继续使用现有 financing.pledge.review_approved / review_rejected / review_timeout | 本文给出面客所需内容、目标和模板补充；L5 更新清单并承接跳转，不再登记一套同义事件。WS-359 独立通知文件轮次核对同一份口径 |
| 明确链上失败 | WS-351 | 发行平台提供本次真实逐笔结果与费用，WS-359 只读展示；只有本平台的一份结果消息。正常撤回/提取失败沿 L5 既有闭环，不扩为异常释放 |
| 需求因覆盖不足自动失效 | WS-351 | WS-352 同步失效该需求的在途报价；同一“需求覆盖不足导致报价失效”不再发一封同义报价失效消息。其他独立的报价超时、拒绝等由 WS-352 定义 |
| 覆盖不足与解除、项目届满前 7 天 | WS-351 | 控制台/广场展示相同事实，不能各自补发；运营监控职责保留 |

| 消息列表、未读、语言、权限和跳转框架 | WS-356；运营接入最终由 WS-360 比对 | 消息中心不根据页面状态自行创造业务触发点；本轮不修改消息中心或原型 |

## 3. 节点、去重与历史消息

### 3.1 对象、时点和下一步

| 事件 | 时点与防误报 | 落点及当前状态变化后的行为 |
| --- | --- | --- |
| N-LS-01 | 正式审核通过即逐笔通知，不等同批审完；带本笔通过时间与业务给出的入池截止，不由通知另算七天 | 项目质押审核与确认清单，定位原单笔及代币。可由用户主动办理；不自动勾选或执行。已入池/已作废/已过期则显示本笔当前结果，不重新发起 |
| N-LS-02 | 只有生效的驳回才发送；并发败方、保存原因草稿不发送。面客原因全文与审核结果一致 | 原单笔历史，显示原因，不覆盖再次提交的新笔；是否可重提按当前资格判断 |
| N-LS-03 | 仅从本笔提交成功起连续 48 小时仍待审者；同批已通过/驳回/撤回不被整体超时覆盖；不套到执行阶段 | 原单笔历史；只释放本次申请占用、不发生链上退款、不产生待提取。不宣称同批所有代币都零费用 |
| N-LS-04 | 以本次操作的确定失败为准，不因等待、关闭弹窗、页面超时判断失败。费用未知与结果未知是两回事 | 精确到原代币本次转入/撤回/提取记录。转入失败退回可质押但须重新判资格；撤回失败仍在池、预扣撤销；提取失败仍已释放待提取。消息只展示和定位，不直接重试或代签 |
| N-LS-05 | 在该轮需求及其在途报价的失效事实一致生效后通知，不发送暂态预判 | 原融资申请编号及终结原因；已有新轮次也不跳到新轮次。恢复资格后可新轮发布，无冷却，不保证当前必可发布 |
| N-LS-06 | 权威结果首次进入本轮覆盖不足；内容保存本次发生时间、覆盖缺口、需追加资产价值 | 项目当前覆盖事实；资产方可按现行操作办理追加，资金方只读。提醒明确先审核、成功入池才生效，不把提交视为已补足 |
| N-LS-07 | 本轮条件实际反转、自动解除才通知，无需任何人点击；解除不是偿债完成 | 查看项目当前覆盖及历史触发/解除时间；旧不足通知保留历史，但不继续展示成当前待办 |
| N-LS-08 | 使用项目既有有效期与UTC业务日期，届满前 7 天仅一次；不因刷新、重新发布新需求重置项目有效期或补发第二封 | 对应项目。已到期时显示现状，不再引导新增融资；存量办理不因旧提醒而获得额外权限 |

### 3.2 同一事实只触达一次

N-LS-R01：每个事件按“借贷面客端＋本平台收件账号＋通知类型＋业务事实”区分。审核使用本次单笔申请；执行使用本次动作及代币；需求使用该轮融资申请；覆盖使用项目与本轮触发/解除节点；七天提醒使用项目本次有效期。这里定义业务区分范围，不规定内部字段、算法或存储。

- 同笔同一事件重复送达，只保留一条；不新增未读、不重新置顶、不把已读恢复未读，也不因原因或已知费用补齐另发催促。
- 同批 A/B 两笔分别通过，分别收到通知；不按“提交批次＋通过”吞掉第二笔。不增加“本批全部审完”汇总消息。视觉是否分组由设计师决定，但不得丢失每笔截止、原因或定位。
- 重新申请是新笔，重新实际发起操作是新动作；新的明确结果可形成新消息，原记录不覆盖。持续处理中不构成新动作。
- 同一项目持续不足只通知本轮首次触发；解除通知是新节点，再次进入不足是新轮次。不能终身只发一次，也不按每次余额重算发信。
- 不同事件确实同时成立时分别保留，例如需求自动失效和债务覆盖不足；同一事件的同一收件人即使有多笔债权也不多收。

N-LS-R02：消息保留发生时的事实，当前状态与可办理资格按点击时判断。乱序到达不得把当前已解除/已处理的业务恢复为待办；消息已读不等于业务已办、差异已关闭或费用已支付。审核通过的办理有效性截止于本笔入池期限，历史消息不因此删除；其余结果告知不另设业务删除期限，沿消息中心保留规则。

以上 8 类不因同事件不同收件人或费用文案分支增加为多次发送。分类使用现有分类定义表；“业务提醒”若尚无正式取值，本文件先给出语义与内容，WS-356 最后统一登记，不擅自宣布编码已上线。

所有事件的平台与端固定“借贷平台 · 面客端”；收件人、发送时点见第 1～3 章。跳转形态均为业务对象，沿 L5 的 P-LS-02 / H-02 / H-05，项目、原申请/单笔及操作须能准确定位；三项审核事件沿现有 enter_pool 或本笔历史能力。均需进入时预判当前权限与对象状态。失效判断按第 3 章，不把公开项目可浏览等同私有审核、协议与费用可读取。

模板成对命名沿 `msg.<业务类型>.title` / `msg.<业务类型>.body`；T-LS-* 是本文模板对编号，双语每对变量同名同数量。N-LS-04/05 的完整文案变体须在同一事件下择一呈现，变体标识由消息中心按既有命名统一登记，不制造新的业务事件。本文件不定义投递接口或内部字段。

## 5. 打开消息后的权限与反馈

N-LS-R03：消息只进入本人本平台消息范围；业务目标再次判权。未授权的审核记录、协议、费用、账户不因消息可读而开放，不在消息中附私有文件内容、钱包地址或可越权直达的下载链接。无当前权限或目标不可用时保留可读的本人消息，按消息中心现有无跳转降级，不猜外部地址、不白屏、不跳新申请。

N-LS-R04：历史事件与当前可办理状态分离。按 L5 最新要求，查看目标只读；办理必须由用户主动进入对应操作，单次确认与批量逐笔结果规则不变。消息不自动打开多重容器、不自动勾选、不代确认、不重发链上操作。关闭或返回恢复消息来源位置；项目内定位到对应质押代币/融资申请区域，新增四区定位标签仅帮助找到信息，不承担新业务动作。

N-LS-R05：沿用面客消息中心 N-NC-01 的 60 秒可见要求，未读和列表同步体现；通知投递失败不回滚已生效业务，页面结果始终可查。不得通过重新制造审核结论、执行动作或项目事件来“补通知”。本文件不规定后台重试方案。

N-LS-R06：不增加强制弹窗、声音、定时催办或“未处理继续提醒”。消息摘要可以简短，但详情必须能读到完整驳回原因、本笔截止、明确费用语义与必要对象识别。按平台中英文与时间金额规则呈现；保留准确业务信息，不在面客消息中写内部条款号、流程算法或诊断错误。
