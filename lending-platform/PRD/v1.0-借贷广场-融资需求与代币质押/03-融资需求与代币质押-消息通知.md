# 融资需求与代币质押 · 消息通知

配套[主 PRD](01-融资需求与代币质押-PRD.md)。本册只定义通知的事件、收件范围与内容；通知的承载形式与视觉由设计决定。本模块只有站内信，共八类关键事件；三类审核结果由运营质押审核模块唯一发送，五类执行/项目事件由L5发送。资产广场、控制台和消息中心展示同一事实，不各自补发。无新增邮件、短信、浏览器推送或运营广播。

| <a id="N-LS-01"></a><a id="n-ls-01"></a>N-LS-01 | 单笔审核通过结论生效；本笔可待资产方确认入池 | 提交该笔申请的资产方本平台账号 | 哪笔已通过、通过时间、本笔七天入池截止；仍须本人确认并承担实际执行费用，审核通过不等于质押成功 | WS-359 审核结果；L5 提供面客承接 |

| <a id="N-LS-06"></a><a id="n-ls-06"></a>N-LS-06 | 项目从非覆盖不足进入覆盖不足，形成新一轮覆盖提醒 | 项目资产方；该项目有未结清业务的债权机构所关联的本平台资金方账号 | 发生时间、覆盖缺口、需追加资产价值；追加先审核、成功入池后才生效 | WS-374 覆盖事件 |
| <a id="N-LS-07"></a><a id="n-ls-07"></a>N-LS-07 | 原覆盖不足条件反转，本轮提醒自动解除 | 项目资产方；解除时该项目仍有未结清业务的债权机构所关联的本平台资金方账号 | 本轮覆盖不足已解除；不等于债务已还清，也不承诺以后不会再出现缺口 | WS-374 覆盖事件 |
| <a id="N-LS-08"></a><a id="n-ls-08"></a>N-LS-08 | 项目到达现行有效期届满前 7 天的提醒节点，项目尚未提前关闭或结清 | 项目资产方 | 项目有效期、已进入最后窗口；到期不再支持新增融资，存量业务按其当前状态办理 | WS-374 项目期限事件 |

需求失效与债务覆盖不足是独立事实，可同时分别成立；不能合成“项目失效”。参考结算币种不用于筛选收件机构或折算消息金额。L6同步需求的在途报价失效，但不为同一覆盖原因双发；其他报价/授信、放款、还款通知分别由其业务模块负责。

**不发送**：创建项目、发起质押申请、发布/改额/主动撤下/关闭等当场回执；新申请/待审/协议上传等过程；通过后催办、未发起过期及复核不通过；执行已发起/处理中/成功、批次整体进度；长期未知/跨期/冲突/联系客服进度；可提取/提取成功；到期前30天或到期当天；持续不足或仅数字变化；项目长期停留空池草稿及空池数量变化；平台默认SPV机构名称随版本更新；浏览、复制、下载、页面读取失败及代币同步。页面仍显示真实事实，普通已确定执行失败无需等待全批结束。

## 2. 收件归属、落点与去重
<a id="delivery"></a>
<a id="2-三方范围与跨模块发送责任"></a><a id="21-接收范围"></a><a id="22-发送与承接边界"></a><a id="3-节点去重与历史消息"></a><a id="31-对象时点和下一步"></a><a id="32-同一事实只触达一次"></a><a id="5-打开消息后的权限与反馈"></a>

审核发原单笔申请账号，执行发本次发起账号。需求/项目资产方账号须有明确业务归属；多成员问题见文末，不能默认全企业、任意管理员或最后查看人。资金方仅限事件发生时在途报价方或未结清债权方的本平台业务关联账号，同账号多笔相关业务仅收一次；不通知浏览者、已拒绝/已失效报价方或已全部结清机构。游客无通知，账号及端别隔离，同钱包/同企业/跨平台身份不串信。账号停用、无权或无可靠归属时不自动改投同事，页面事实不回滚。

| 事件 | 时点与防误报 | 落点及当前状态变化后的行为 |
| --- | --- | --- |
| N-LS-01 | 正式审核通过即逐笔通知，不等同批审完；带本笔通过时间与业务给出的入池截止，不由通知另算七天 | 项目质押审核与确认清单，定位原单笔及代币。可由用户主动办理；不自动勾选或执行。已入池/已作废/已过期则显示本笔当前结果，不重新发起 |
| N-LS-02 | 只有生效的驳回才发送；并发败方、保存原因草稿不发送。面客原因全文与审核结果一致 | 原单笔历史，显示原因，不覆盖再次提交的新笔；是否可重提按当前资格判断 |
| N-LS-03 | 仅从本笔提交成功起连续 48 小时仍待审者；同批已通过/驳回/撤回不被整体超时覆盖；不套到执行阶段 | 原单笔历史；只释放本次申请占用、不发生链上退款、不产生待提取。不宣称同批所有代币都零费用 |
| N-LS-04 | 以本次操作的确定失败为准，不因等待、用户中止查看或超时判断失败。费用未知与结果未知是两回事 | 精确到原代币本次转入/撤回/提取记录。转入失败退回可质押但须重新判资格；撤回失败仍在池、预扣撤销；提取失败仍已释放待提取。消息只展示和定位，不直接重试或代签 |
| N-LS-05 | 在该轮需求及其在途报价的失效事实一致生效后通知，不发送暂态预判 | 原融资申请编号及终结原因；已有新轮次也不跳到新轮次。恢复资格后可新轮发布，无冷却，不保证当前必可发布 |
| N-LS-06 | 权威结果首次进入本轮覆盖不足；内容保存本次发生时间、覆盖缺口、需追加资产价值 | 项目当前覆盖事实；资产方可按现行操作办理追加，资金方只读。提醒明确先审核、成功入池才生效，不把提交视为已补足 |
| N-LS-07 | 本轮条件实际反转、自动解除才通知，无需任何人点击；解除不是偿债完成 | 查看项目当前覆盖及历史触发/解除时间；旧不足通知保留历史，但不继续展示成当前待办 |
| N-LS-08 | 使用项目既有有效期与UTC业务日期，届满前 7 天仅一次；不因刷新、重新发布新需求重置项目有效期或补发第二封 | 对应项目。已到期时显示现状，不再引导新增融资；存量办理不因旧提醒而获得额外权限 |

同一账号、端别、事件和业务事实只收一次：审核按本次单笔、失败按本次动作及代币、需求按原轮次、覆盖按本轮触发或解除、七天提醒按项目有效期区分。重复送达不新增未读、不恢复未读、不置顶、不改发生时间；补齐原因或费用不重发。新单笔、新实际动作、新覆盖轮次各自保留。同批多笔通过不能合并丢失独立截止与落点，不增加“全批已审”消息。

消息保存发生时事实，点击按当前权限/阶段判断；旧事件或乱序到达不恢复待办，已读不等于业务已办或已支付。旧消息仍指原笔，不开新轮、不自动执行或代签。无权/目标不可用保留本人可读消息，按消息中心既有无跳转降级，不把用户带到无法继续的结果，也不猜地址或泄露私有文件、钱包、下载链接。查看只读，办理由用户主动进入，返回保留来源位置。历史不因办理期限结束删除，沿消息中心保留规则。

沿现有60秒可见要求，未读及列表同步；投递失败不回滚业务，用户仍可从业务本身查到结果。不制造新业务事实补信，不增加强制打断、声音或定时催办。

### 业务变量与缺失处理

| 变量 | 含义、必填与校验 |
| --- | --- |
| project_name / project_id | 发生事件的项目名称及稳定项目编号；模板中使用者必有，名称按项目 1～60 字符规则，编号用于区分同名项目；不使用其他项目替代缺项。SPV机构名称不进入消息模板，也不作为收件判据；该名称在代码层面维护，其变更不产生任何消息 |
| token_id | 本笔代币完整业务编号；涉及代币必有，沿 D-TI-21 的 16 位 TK 编号，不是钱包地址或链上 tokenId |
| application_id / batch_id | 本次单笔申请标识 PA-11＝RV-19、提交批次 PA-01；审核及转入结果必能关联，批次只追溯，不能代替单笔。消息详情可显示业务关联信息，不强行加入短标题 |
| action_id | 本次实际执行动作的业务识别号；执行失败必有，不能只靠 token_id 区分历次重试；编码形式不在本文件规定 |
| demand_id | 失效的本轮融资申请编号 FP-28；N-LS-05 必有，重新发布不沿用原编号 |
| approved_at / entry_deadline | 本笔真实通过时间与入池截止；N-LS-01 必有，未通过不造值、不取同批其他笔日期 |
| occurred_at / expires_at | 该事件真实发生时点、项目有效期；使用模板对应者必有，业务日期统一UTC判定、按收件人展示时区显示并带标注，不从阅读时刻重算期限 |
| reason | 面客业务原因全文；驳回沿 RV-14 的原文和已确认长度规则，执行失败沿 PL-12。必有且可读，不用内部备注、异常堆栈或原始链上报错替代；不因摘要截断而丢失详情全文 |
| shortfall / additional_value | 事件发生时的覆盖缺口与需追加资产价值，USD、非负且两位小数展示；取 L5 权威结果，不在通知另算或用参考结算币种折算；触发通知时缺口须大于 0 |
| fee_amount / fee_currency | 已确认实际产生的费用及币种；有费用分支必有、金额大于 0，精度沿费用资产规则，不套 USD 金额精度；未知不得填 0，无费用分支必须有真实零费用结论。同笔如有多币种，分别展示而不混加 |

事件归属、收件账号、可渲染标题正文须齐全；缺失不能以空白消息、假编号、演示数值或猜测结论补齐。跳转映射等非关键展示项缺失沿消息中心既有降级，不自行扩大为整条丢弃。原因作为用户业务文本原样呈现；固定文案提供中英两套，不伪称人工中文原因已经翻译。
