# 融资需求与代币质押 · 消息通知

配套[主 PRD](01-融资需求与代币质押-PRD.md)。本册只定义通知的事件、收件范围与内容；通知的承载形式与视觉由设计决定。本模块只有站内信，当前在用八类关键事件（另有一类已废止、编号保留）：两类项目审核结果与两类逐笔质押审核结果由相应审核模块唯一发送，四类链上/项目事件由本模块发送。资产广场、控制台和消息中心展示同一事实，不各自补发。无新增邮件、短信、浏览器推送或运营广播。

需求失效与债务覆盖不足是独立事实，可同时分别成立；不能合成“项目失效”。参考结算币种不用于筛选收件机构或折算消息金额。签名或部署失败属平台内部重试，不向资产方发送消息；项目审核通过与退回各只发一条。L6同步需求的在途报价失效，但不为同一原因双发；其他报价/授信、放款、还款通知分别由其业务模块负责。

**不发送**：创建项目提交、发起质押签名、发布/改额/主动撤下/关闭等当场回执；待审提醒、协议上传等过程；审核催办；上链已发起/处理中/成功、批次整体进度；长期未知/跨期/冲突/联系客服进度；可提取/提取成功；到期前30天或到期当天；持续不足或仅数字变化；项目长期停留空池及空池数量变化；待审质押额变化；平台默认SPV机构名称或平台钱包随版本更新；浏览、复制、下载、页面读取失败及代币同步。页面仍显示真实事实，普通已确定执行失败无需等待全批结束。

## 2. 收件归属、落点与去重
<a id="delivery"></a>
<a id="2-三方范围与跨模块发送责任"></a><a id="21-接收范围"></a><a id="22-发送与承接边界"></a><a id="3-节点去重与历史消息"></a><a id="31-对象时点和下一步"></a><a id="32-同一事实只触达一次"></a><a id="5-打开消息后的权限与反馈"></a>

项目审核发创建该项目的账号，逐笔审核发发起该笔质押的账号，链上失败发本次签名发起的账号。本期一个企业只有一个员工，项目与需求事件即发给该账号；不因此开放跨企业或跨端投递。资金方仅限事件发生时在途报价方或未结清债权方的本平台业务关联账号，同账号多笔相关业务仅收一次；不通知浏览者、已拒绝/已失效报价方或已全部结清机构。游客无通知，账号及端别隔离，同钱包/同企业/跨平台身份不串信。账号停用、无权或无可靠归属时不自动改投同事，页面事实不回滚。

| 事件 | 时点与防误报 | 落点及当前状态变化后的行为 |
| --- | --- | --- |
| N-LS-01 | 正式审核通过即逐笔通知，不等同批审完；带本笔通过时间，不带任何截止或待办 | 项目质押审核清单，定位原单笔及代币。通知只作知会，无需用户再做动作；代币若已被撤回或解押则显示本笔当前结果 |
| N-LS-02 | 只有生效的驳回才发送；并发败方、保存原因草稿不发送。面客原因全文与审核结果一致 | 原单笔历史，显示原因及“须自助解押取回”，不覆盖再次发起的新笔；是否可重新发起按解押完成后的当前资格判断 |
| N-LS-03 | 本条废止，不再触发 | — |
| N-LS-04 | 以本次操作的确定失败为准，不因等待、用户中止查看或超时判断失败。gas 未知与结果未知是两回事 | 精确到原代币本次质押/解押/撤回/提取记录。质押上链失败保持可质押但须重新判资格；解押或撤回失败仍在合约内、预扣撤销；提取失败仍已释放待提取。消息只展示和定位，不直接重试或代签 |
| N-LS-05 | 在该轮需求及其在途报价的失效事实一致生效后通知，不发送暂态预判 | 原融资申请编号及终结原因；已有新轮次也不跳到新轮次。恢复资格后可新轮发布，无冷却，不保证当前必可发布 |
| N-LS-06 | 权威结果首次进入本轮覆盖不足；内容保存本次发生时间、覆盖缺口、需追加资产价值 | 项目当前覆盖事实；资产方可按现行操作办理追加，资金方只读。提醒明确先审核、成功入池才生效，不把提交视为已补足 |
| N-LS-07 | 本轮条件实际反转、自动解除才通知，无需任何人点击；解除不是偿债完成 | 查看项目当前覆盖及历史触发/解除时间；旧不足通知保留历史，但不继续展示成当前待办 |
| N-LS-08 | 使用项目既有有效期与UTC业务日期，届满前 7 天仅一次；有效期自创建起算，不因刷新、重新发布新需求重置或补发第二封 | 对应项目。已到期时显示现状，不再引导新增融资；存量办理不因旧提醒而获得额外权限 |
| N-LS-09 | 部署成功、项目转为可用时发送一次；期间的签名或部署失败与重试不发送 | 对应项目，可从中进入发起质押；项目此后被关闭则显示当前状态，不恢复可用 |
| N-LS-10 | 退回结论生效即发送，原因全文与审核结果一致；每次退回各发一次 | 对应项目的创建信息，可直接修改后重新提交；已重新提交的显示当前状态，不回到旧版本 |

同一账号、端别、事件和业务事实只收一次：项目审核按本次结论、逐笔审核按本次单笔、失败按本次动作及代币、需求按原轮次、覆盖按本轮触发或解除、七天提醒按项目有效期区分。重复送达不新增未读、不恢复未读、不置顶、不改发生时间；补齐原因或费用不重发。新单笔、新实际动作、新覆盖轮次各自保留。同批多笔通过不能合并丢失独立截止与落点，不增加“全批已审”消息。

消息保存发生时事实，点击按当前权限/阶段判断；旧事件或乱序到达不恢复待办，已读不等于业务已办或已支付。旧消息仍指原笔，不开新轮、不自动执行或代签。无权/目标不可用保留本人可读消息，按消息中心既有无跳转降级，不把用户带到无法继续的结果，也不猜地址或泄露私有文件、钱包、下载链接。查看只读，办理由用户主动进入，返回保留来源位置。历史不因办理期限结束删除，沿消息中心保留规则。

沿现有60秒可见要求，未读及列表同步；投递失败不回滚业务，用户仍可从业务本身查到结果。不制造新业务事实补信，不增加强制打断、声音或定时催办。
