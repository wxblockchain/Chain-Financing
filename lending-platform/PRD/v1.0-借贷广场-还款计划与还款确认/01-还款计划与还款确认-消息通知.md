# 还款计划与还款确认 · 消息通知

版本：V1.1｜所属模块：WS-354 / L8｜业务基线：L8 V2.3｜日期：2026-09-21｜产品经理：许楚清。

**本模块保留八类关键站内信：计划定稿、应还临近、还款逾期、还款已提交、还款确认临近到期、还款确认超期、还款已确认、融资业务已结清。** 计划定稿只发资产方；资金方沿 L7 到账确认通知查看计划。最后一次还款确认使整笔业务结清时，向资产方合并告知本期确认与整笔结清，不连续发送两封结果信。本期只做站内信，不做邮件、短信或运营广播。

“哪个环节发给谁”见第 1 章。开发主读第 1～5 章，测试主读第 6 章；第 7 章为来源、必要缺口及下游交接。本文件细化 F-LS-76、D-RP-61～63，不改变还款业务。没有新增业务流程或状态机，继续参考 L8 V2.3 同批《流程图与状态机》L8-F01～03、L8-S01～03；本轮与[L8 PRD V2.3](l8-repayment-prd.md#entry)、[图册 V2.3](l8-repayment-flows-and-states.md#entry)三份完整附件同交；按P08/P09/P10等已确认决策同步差异，不启动新通知队列。

## 2. 收件账号与发送归属

### 2.1 收件范围

N-RP-R01：消息属于借贷平台面客端的本人账号。企业其他员工可以依原业务权限办理，不因此共享同一条消息或自动收副本。消息收件资格不授予还款、确认、凭证下载或跨企业访问权限。

| 角色 | 本模块收件口径 |
| --- | --- |
| 资产方 | 使用本笔已经明确关联的资产方收件账号，贯穿计划、还款及结清。多成员企业尚无已确认责任归属的，沿 Q-LS-N01 待定；不擅自取最后登录者、接受报价人、某期还款提交人或企业全员 |
| 资金方 | 本轮沿 L7 同笔放款登记账号 LN-14，接收 N-RP-03/04/05/06/08；其他员工办理本期确认不触发自动改投、多人副本或历史消息转移。此为通知承接规则，不限制同机构员工的既有办理权限 |
| 运营管理人员、SPV | 八类均不接收；客服承接未定义不能以全体运营广播兜底 |
| 无关企业、其他平台身份、访客 | 不接收。不用邮箱、钱包或其他平台账号判断收件人，同一自然人不同身份不串信 |

账号缺失、停用或无法确定归属时不得转给任意同事，待责任归属明确后再验收该分支。人员交接规则不能由“最近一次操作人”暗中替代；若未来明确新的责任人机制，应由本业务同步调整 L7/L8 收件规则，不由消息中心猜测。收件问题不阻断还款事实生效，不暂停业务计时。

### 2.2 跨模块边界与同次结果合并

N-RP-R02：L7 N-LN-04 向资金方通知资产方已确认放款到账。若计划生成中，该信如实说明进度；恢复定稿后不重发 L7，也不给资金方另发 L8 N-RP-01。N-RP-01 向资产方只发送一次，且必须等完整定稿实际可读。定稿时间继续取原 FD-35/FD-41，不能以恢复时间替换。

N-RP-R03：同一次资金方确认若同时使本期与整笔结清，资产方只收到 N-RP-08 的资产方模板，其中完整保留该期期次、RP-01、确认时间与整笔结清时间；本次不再单独发 N-RP-07。资金方收到 N-RP-08 一条。普通期次确认只发 N-RP-07，不提前发整笔结清。两项业务事实均保留，合并的是用户通知，不是业务状态。

判断以“本次确认是否使全部期次结清”为准，不能仅凭期次序号等于总期数。若末期已结清、较早一期仍未结清，则末期确认仅 N-RP-07；最后完成的较早一期才随 N-RP-08 告知。之前已发的独立期次结果不撤销、不改成整笔结清。合并的共享登记适配见第 7 章。

| 事实或入口 | 唯一发送归属 |
| --- | --- |
| 到账确认与计划定稿 | L7 发资金方到账确认；L8 发资产方计划定稿，按 R02 分工 |
| 还款、确认、逾期和单笔业务结清 | L8 N-RP-01～08，控制台/还款清单/消息中心不得另发同义信 |
| 单笔结清后项目状态判断、项目整体业务释放 | L5。L8 只说明本笔结果与后续查看路径，不承诺项目一定已终态 |
| 代币自助提取结果 | L5/T7 原归属。L8 不把请求受理、重复“已释放”或未知执行当成链上提取成功 |
| WS-355 我的控制台 | 只消费同一业务和期次，待办数与未读数独立；阅读通知不完成待办，待办出现不再发一次通知 |
| WS-356 / WS-360 | 最后核对框架承接，分别承接面客通知与核对本模块零新增运营通知 |

## 3. 时点、过时提醒与异常

### 3.1 还款临近与逾期

N-RP-R04（P08/P10）：N-RP-02保留应还临近的准备提醒用途，于应还日前3个UTC自然日00:00提醒一次，不再取RP-15作为发送时点。RP-15已改为应还日00:00 UTC，普通期和含本金末期一致；消息明确录入开启时点，到期前仅查看计划和有权查看的付款资料，无可编辑表单、上传或提交。提醒不是平台付款动作，不能说“窗口已开启”或“现在可提交”。迟到但尚未逾期、仍待还款可补一次，使用准确应还日及开启时点，不写“还剩三天”；到期当日补送不另造一条开启消息。计划迟生成时不按预计期次提醒；定稿后若已到准备提醒时点、未逾期才补临近，已经逾期只告知逾期，不倒补临近。定稿通知仍提供完整新旧对照。

N-RP-R05：应还日次日 00:00 UTC 仍未成功提交才成立逾期；首次自然日为 1 天。N-RP-03 每期双方各一次，不每日重发或随天数增长恢复未读。成功提交冻结该期期次逾期天数，不因资金方长期不确认继续增加；另一未提交期次独立计算。逾期提醒尚未送达时该期已提交/结清，不追补过时催还，历史逾期事实仍保留；已送达的信保留当时事实，打开原期次看当前状态。

P08/P09已关闭Q-L8-03：所有期次不提前开放录入；FD-44只要存在逾期未结清期次就为真，包含天数冻结的S-RP-2。相关逾期期次全部确认后清当前业务标记，未来正常期未结清不阻止清除，历史天数保留；另一未提交期独立增长。消息中的“已提交”不能暗示逾期问题已结清，但FD-44变化本身不发新信。

### 3.2 还款确认时限

N-RP-R06：RM-15 = 平台成功提交时间 RM-06 + 连续 168 小时，精确到秒；不是工作日、第七天日终，也不从自填还款时间 RM-05、阅读或送达起算。N-RP-05 只在截止前 24 小时一档，迟到但仍未届满且待确认可补一次；已确认或已届满不追补临期。N-RP-04 等待发送时若该期已确认，不再补发“请确认”的旧待办。

N-RP-R07：确认截止届满仍 S-RP-2 才成立 N-RP-06。届满不自动确认、不结清、不释放本金占用、不解冻逾期、不关闭确认入口，不把资金方确认超期算成资产方新增还款逾期。截止前已确认不发超期；截止后确认但超期提醒尚未发送，不追补过时催办，已成立的超期历史仍保留。

超期后仍可以真实到账为依据确认，不能引导未到账先确认。客服邮箱必须在完整超期正文可读可复制，同时带 FP-28、FD-01、RP-01；不得造邮箱、以不可联系的脱敏值充数或承诺客服处理时限。暂无真实邮箱及通用规则例外时，该模板场景尚不能完成真实投递验收。

### 3.3 防重复、真实结果及失败

N-RP-R08：同一账号、同一业务/期次、同一事件只收一次。计划定稿、整笔结清按 FD-01；期次类按 RP-01；确认临期另标固定 24 小时节点。不同期次是不同事件，不因同机构、同一天或同 FP-28 被合并。重复提交、补判、刷新、恢复生成、重复已释放或同事实补送均不新增、不置顶、不恢复未读、不改原发生时间。同次期次确认与结清另按 R03 合并，不能误用普通去重覆盖不同事实。

N-RP-R09：提交/确认失败、结果未知不发成功消息。N-RP-04 以还款记录和 S-RP-2 正式成立为准，提交不减少额度；N-RP-07/08 以期次、累计金额、对应本金占用变化等本地业务结果一致成立为准。普通利息期本金为 0，不声称归还本金或释放额度；末期减的是本金，不能把本息合计当释放额。全部本金已还但仍有利息期未确认时，不发业务结清。

通知失败不回滚业务、不重置确认截止、不重复扣减占用。页面仍能查看真实计划、进度和截止。等待发送时重新判断待办是否仍适用；抑制过时催办不抹除业务历史，不将成功结果改写成“仍待办理”。历史正文的金额、时间、期次和对照保留事件时点事实，目标显示当前事实。

N-RP-R10：满足事实、账号和模板条件的消息沿 WS-356 IF-NC-01，事件后 60 秒内列表与未读数同时可见。L8 §3.8 的既有逾期判定目标 ≤5 分钟、确认超期判定目标 ≤1 分钟/最坏 ≤5 分钟与该要求存在需统一验收的差异，详见第 7 章。不从延迟处理完成时重新计时，也不把两段时长相加作为放宽后的新承诺；未联验不宣称达标。

### 4.2 模板业务信息与校验

所有变量是只读业务信息，用户不在消息里填写或修改。缺失必需值不得填0、假编号或裸占位符。应还日、起息日为UTC业务日期并标注；具体时刻按用户偏好时区展示并标注，游客沿浏览器时区；更改语言/时区不改变业务日期或连续168小时。USD逐期利息两位四舍五入、不跨期结转；本期固定1:1:1按本期本息复用原快照，不重取行情、不重写历史、不中途用显示精度改金额。
