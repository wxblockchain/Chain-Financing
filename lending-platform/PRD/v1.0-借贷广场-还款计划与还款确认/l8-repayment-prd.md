**L8-REV-01 资料与角色边界（P01/P04）。** 个人、企业账户档案仅本人可查，不因交易关系开放对方完整档案、认证材料或私人联系方式。本笔必要主体、机构、金额、条款和付款资料自动取得并按业务权限展示；加载中、缺失和读取失败区分，失败可重试，不要求手填对方档案或用假值补齐。运营与 SPV 同等处理，无新增私有资料读取、资金操作或代确认权限。

沿用同一企业主体下任一登录员工均可代表企业执行该企业动作的规则，本模块不增设企业内复核层级。资产方授权登录、资金方账号和准入由 L1/L2/L3 提供，本册不展开登录协议。

融资申请编号 `FP-28`（原需求编号）、融资业务编号 `FD-01`、放款记录编号 `LN-01` 在已成交并进入还款的单笔业务上为 1:1:1；报价阶段同一申请可能先后关联多笔 FD，不能把这一对应关系扩大到整个报价历史。一个项目可以先后有多笔业务、多个资金方。还款信息清单一行对应一笔已确认到账的融资业务，以融资申请编号作主标识，业务编号和放款编号作关联检索；`RP-01` 一期一个，`RM-01` 一次成功提交一个，均不得用作整笔清单的唯一标识，不能把整笔业务和单期期次混称“还款计划编号”。

**L8-REV-02 日期口径（P10）。** 默认英文、可切中文。应还日、最终还款日、起息日、编号中的日期均为 UTC 业务日期；还款录入开放为应还日 00:00 UTC，逾期从次日 00:00 UTC 起算。具体时刻按用户偏好时区展示并标注，无偏好沿平台既有展示规则，游客按浏览器时区并标注；日期字段明确标注 UTC 业务日期，不能按当地跨日另生应还日。语言、时区和夏令时切换不改变事实。确认时限连续 168 小时，不按第七个自然日末延长。术语区分“报价有效期”“放款确认时限”“还款确认时限”，不得把确认超期称为还款逾期。金额注明币种；记账本位币为 USD；使用完整名称“项目融资余额”“授信占用额”“质押覆盖状态”。

### 3.1 业务选择与还款入口

需求：F-LS-75、77、79。依据：D-RP-59/60/66/67/71～74/76～81。流程：[L8-F01](l8-repayment-flows-and-states.md#l8-f01)。

项目主页面左侧依次纵向展示“质押代币清单 → 融资申请信息 → 融资放款信息 → 还款信息”，随页面自然滚动；顶部“质押代币 / 融资申请 / 融资放款 / 还款”定位标签只滚动到对应区，不隐藏或替换清单；右侧办理区固定“质押 / 融资 / 还款”三个页签。共同布局与返回行为以 [L5 功能需求说明 §9.2、§11.7](https://8.216.50.84.nip.io/api/attachments/01a0c3d3-0e29-7f3d-be39-b6aec382c00c/download) 为统一来源。还款信息负责查记录，右侧还款页签负责办理；不再在一个融资需求详情中堆叠全部还款流程。

**还款信息清单。** 资产方确认到账、业务进入 S-FD-6 后即产生一行；计划生成中也可进入查看，不能等到计划成功才隐藏或补造该笔已成交事实。结清后保留原行和只读计划。尚无还款业务时，清单显示“暂无还款信息”，右侧还款页签仍保留并说明“确认到账后可查看还款计划和办理还款”，不提供无对象的提交动作。角色可见范围仍遵循第 2 章。

| 清单信息 | 展示与业务口径 |
| --- | --- |
| 融资申请编号、融资业务编号、放款编号、出资机构 | FP-28 为主标识；FD-01、LN-01 和机构辅助识别，同一行始终指向同一笔业务；三个既有编号均可检索，不创建新编号 |
| 业务状态与计划情况 | 显示还款中或已结清；定稿未完成显示“还款计划生成中”；逾期和确认超期使用既有并行标记，不造新的主状态 |
| 本期应还信息 | 按 §3.3 的顺序选取该笔第一条 S-RP-1，显示期次/总期数、应还日、USD 应还合计、结算币种金额、期次状态、逾期天数及未开窗时的开启日期；无候选显示“暂无待还期次”，不是 0 元应还 |
| 待确认情况 | 有 S-RP-2 时显示待确认提示并提供对应记录入口；可与下一待还期并存，不能用下一期应还卡遮盖已提交记录；无 S-RP-1 但有 S-RP-2 时仍可进入确认 |
| 查看与办理 | 清单可打开只读详情；右侧资产方只保留立即还款，资金方保留确认收到还款，不放查看还款详情快捷按钮；办理按下表与业务权限提供，结清业务只读；未到期、生成中不因无法提交而从清单消失 |

### 3.2 初始计划、定稿与计划查看

需求：F-LS-60～64。依据：D-RP-04～20/40/72/80/81。流程：[L8-F01](l8-repayment-flows-and-states.md#l8-f01)。

**初始计划。** 资金方提交报价后，按报价提交时刻的 UTC 日期作为预计放款日试算；在只读报价详情和报价接受操作弹窗展示，不形成有效期次、不占用 RP 编号。整表标“预计 · 未生效”，日期列为“预计还款日”，常驻说明实际安排会在放款确认后按实际放款日重算。接受报价时展示此说明并记录展示时间，不增加勾选要求。报价拒绝、失效或终止后，初始计划不留下有效期次。

**定稿。** 资产方完成放款确认时生成，触发时点为 FD-35；起息日为放款记录提交时间 LN-06 的 UTC 日期，不能用资金方自填发放时间 LN-05，也不能改用放款确认日。本金取 QT-03，年化利率取 QT-06，最终还款日取 QT-16（等于项目截止日 FP-09，当前不可编辑）。定稿后期次、应还日、金额和计息规则不可更改，只追加还款记录、逾期历史和结清事实。

生成未完成时显示“还款计划生成中”，不能展示一份旧计划作为定稿，也不能回退已完成的放款确认、债务或额度事实。恢复后只生成同一套期次；定稿时间仍对应原放款确认时点。

日期变化属于已告知规则的执行，不新增一次报价确认：金额、币种、汇率快照、年化利率和期次规则沿用原条款。定稿告知须包含预计/实际起息日、期数变化、各期应还日与金额对照；资金方通过放款确认通知进入同笔详情查看计划进度；通知送达时若仍生成中，不声称已有完整计划。定稿后在同笔详情查看正式安排，不重复发送定稿提醒。

**期次与利息。** 还款类型唯一值为“按季付息；到期还本付息”，按起息日起每 3 个自然月同日划分，不按自然季度末；目标月份无同日时取该月末日。到期日在三个月内时只有一期。一般期仅付息，末期还全部本金及末期利息；不足完整一季的尾段与前一段合并为末期，不单独形成小额尾期，末期区间可长于三个月但不超过六个月。以起息 2026-09-15、到期 2027-03-20 为例，为 2026-12-15 付息、2027-03-20 还本付息两期。

年化单利、ACT/360、算头不算尾。每期计息天数为本期止日减起日；每期利息 = 本金 × 年化利率（百分比换成比例）× 天数 ÷ 360，独立保留两位小数、四舍五入，利息尾差不跨期结转。应还 USD 合计 = 本金 + 利息；结算金额 = USD 合计 ÷ 报价锁定汇率 QT-04，还款不重取汇率。数币结算精度、最终舍入和尾差沿 Q-L8-04 / Q-CR-09 使用同一待批准表，不把原型两位或代币展示六位升级为资金结算规则。

**L8-REV-03 固定折算与金额同源（P05/P10）。** 本期平台固定 1 USD = 1 USDT = 1 USDC，QT-04 为 1；每期结算数值等于该期 USD 本息合计，单位为原 QT-02，不能把报价本金当成每期应还。例如一期应还 100.25 USD，结算为 100.25 个所选币种。报价锁定的汇率值、真实规则生效时间、来源说明、版本标识继续随本笔复用，规则生效与报价锁定时刻区分。还款不取外部行情、不设置汇率维护或人工改价、不让用户补填快照，不以本期固定规则追溯重写历史业务。固定比例不是外部兑换保证；完整本笔快照不因行情不可用失效。必要条款/金额依据缺失时说明暂不能核对，恢复真实资料后继续，不以固定“1”、旧笔快照或零金额猜补，不回退已成立债务。USD金额及逐期利息保留既定两位四舍五入、利息尾差不跨期结转；缩略展示不改变完整应付金额。

**定稿计划查看。** 只显示选定业务的定稿版，无初始版切换或双版对照。标题带融资申请编号、出资机构、业务/放款编号、结算币种、定稿时间。计划必须包含期次、应还日、应还合计（USD）、结算币种金额、期次状态、逾期天数，并能识别当前应还期次；本息拆分、计息区间及天数可查看，末期注明含本金及合并区间。年化利率和计息规则可核对；组件、字段视觉顺序及窄屏适配由设计决定。只合计选定业务的 USD 本金/利息/合计，不对结算金额或跨笔数据求和。

### 3.3 选期与还款提交

需求：F-LS-65～69、78。依据：D-RP-21～31/41～45/68～70/75/79。流程与状态：[L8-F02](l8-repayment-flows-and-states.md#l8-f02)、[L8-S01](l8-repayment-flows-and-states.md#l8-s01)。

候选为资产方企业名下 S-RP-1 期次：全局待办可跨业务/项目；项目操作区及办理弹窗仅在所选业务内取候选。依次按应还日、LN-06 放款提交时间、FD-01、期次序号升序，第一条为默认项。逾期组在前，未到期组在后；禁止按“距离今天的绝对天数”排序。可以改选已开窗期次；未开窗期次可见但不可提交，注明开启日期。不要求先结清另一个已开窗期次才可选择当前期；所谓禁止跳期是不得越过开窗规则提交未来期次。

**L8-REV-04 还款录入开放（P08，修订 D-RP-26）。** 普通利息期和含本金末期均自应还日 00:00 UTC 开放，不提前三日开放；到期当日可以提交，次日未提交才逾期，逾期期次仍可录入。此前可只读查计划、金额及有权读取的收款资料，不开放还款信息编辑、凭证上传或提交；直达与旧通知同样受此限制。一次仅录入一期，不多选、不全选、不合并，金额币种只读，不出现“提前还本”“全部结清”动作。Q-L8-03①据此关闭，没有末期例外。

这里的“还款”仅登记用户已完成的付款信息，由资金方另行核实到账；不执行银行划款、钱包支付、扣款或签名，不因点击、上传或提交而表示真实付款成功。RM-05仍允许过去但不得未来的真实付款时刻，仅作对账，不能倒填来减免逾期或提前开放录入；本稿不据此新增提前结清、重算计息或平台控制线下支付的能力。应还临近通知仍可提前三日提醒准备，只读查看不授予录入权限，详见通知册 N-RP-R04。

法币账户五项来自放款登记，数币地址来自资金方绑定钱包。只读账户必须能供双方核对打款对象，不得借“精简”隐藏；普通清单及摘要掩码；已确认的本笔付款当事方可按付款用途受控核对、复制完整收款账户，本笔双方按既有对账权限查阅原快照。完整值及下载不得向非当事方、运营或 SPV 开放，也不能借此读对方账户档案。账户掩码细则及上游地区账号规则仍待 Q-L8-04；受控完整读取原则已定。凭证、哈希、链、账户、备注、补充材料、自填还款时间均非公开，直接访问和下载同样受权限限制。

提交前在同一容器内切换至最终二次确认步骤，明示：提交后不可修改撤回；成功提交即停止本期逾期累加，资金方有 168 小时还款确认时限，到期不自动确认；平台不核验转账真实性。资产方显式确认后，提交成功同时形成记录、期次转 S-RP-2、冻结该期逾期天数并启动时限；项目融资余额与授信占用额均不动。完成后在本操作弹窗显示本期已提交待确认并更新原清单/操作区；关闭回原位置，不自动打开详情。

跨境手续费由付款方承担，可能造成到账差额；沿用基线的手续费告知，不预估手续费数字。本期应还仍为计划金额，资金方确认不以实收等于应还为前提；本模块不采集还款实收金额，不用放款时资产方实收 FD-39 参与任何还款计算。

异常：格式/大小/数量错误就地说明，保留其他已上传文件；未来还款时间拒绝；未开窗、非本人业务、期次已变更均不能提交。多人重复提交最多一条成功，后到者看到“该期已提交还款记录”及当前详情，不重复冻结或重新启动时限。链为 ETH 常量，原 E-RP-05“选错链”本期不可达，不为其设置选择或错误分支。

### 3.4 逾期与提交保护

需求：F-LS-68、70。依据：D-FIN-11、D-RP-29～31/34/35/46～50/58。状态：[L8-S01](l8-repayment-flows-and-states.md#l8-s01)。

应还日次日 00:00 UTC 仍未成功提交，即标逾期；不设宽限期，首个逾期自然日为 1 天，之后逐日增加。迟于应到时点才完成判定时仍按应到时点计算，不能减免延迟期间天数，也不能重复提醒。逾期是期次和业务的并行标记，不替换“待还款”“还款中”状态。

成功提交时冻结本期期次逾期天数，此后不因资金方不确认继续增加，也不继续产生该期新增逾期通知。本期利息已在定稿时确定，应还金额不随提交或确认早晚变化。结清后保留历史逾期天数；另一未提交期次仍独立计逾期，不能因本期提交冻结整笔业务的所有期次。

还款性质在提交时依是否逾期，取“正常还款/逾期还款”；不得与“还款类型”混名。

**L8-REV-05 业务逾期标记（P09）。** FD-44 为真，当且仅当本业务存在“已发生逾期且尚未结清”的期次，包括逾期中的 S-RP-1 和逾期提交后天数被冻结的 S-RP-2。提交不清除业务标记；待确认显示该期已提交、冻结天数及仍未结清，不再冒充待资产方补交。相关逾期期次全部转 S-RP-3 时才清除当前业务整体标记；无需等尚未逾期的未来期次全部结清，历史逾期天数始终保留。若另一未提交期次随后逾期，按该期事实再次形成当前业务标记，不重发旧期通知。FD-44 的最早逾期期次、最长天数仅在当前未结清逾期期次中取值，包含冻结值；已结清历史另查，不混入当前集合。无当前集合时标记否、当前摘要为空，不能将历史天数归零。Q-L8-03②据此关闭。

不计算或展示罚息，不增加应还金额，不自动处置质押，不影响其他资金方授信。即使资金方线下主张凭证无效，本期也没有裁决和解冻回补路径。覆盖不足不阻断还款、确认或结清；项目“已到期 · 存量处理中”按中性正常履约路径呈现。

### 3.5 还款确认与超期处理

需求：F-LS-71～73。依据：D-RP-32/33/36/37/51～57、AC-FIN-36。流程：[L8-F02](l8-repayment-flows-and-states.md#l8-f02)。

资金方打开目标期次，核对金额、币种、只读收款账户、还款时间与平台提交时间、凭证或哈希及未核验提示、本期计划和冻结逾期天数。两个时间名称必须清楚，自填还款时间仅用于对账，时限从成功提交开始，不能从通知送达或首次查看开始。

**当前进度（F-LS-71、AC-L8-PROG-01）。** 对本业务双方明确展示“资产方提交还款 → 资金方确认到账”的本期期次进度、当前状态与处理方，不只展示金额或空白：

| 本期期次事实 | 进度及下一步信息 |
| --- | --- |
| 待还款 S-RP-1 | 资产方尚未成功提交；当前由资产方办理，资金方等待。尚无确认截止时点，不虚构已提交/确认时间 |
| 待还款确认 S-RP-2 | 资产方提交已完成，显示RM-06平台提交时间；资金方确认待完成，资金方见“轮到您确认”，资产方见“等待资金方确认”；显示确认截止RM-15及剩余时限 |
| 确认超期、仍S-RP-2 | 保留已提交完成、待资金方确认及超期时长，不显示已完成或自动结清；确认仍可办理 |
| 本期已结清 S-RP-3 | 两步均完成，显示真实确认时间RP-17/RM-18；该期无重复确认动作，其他期次未结清时整笔业务仍还款中 |

进度仅表达本期已发生事实，不用一笔的进度代替其他业务或全部期次。确认信息聚焦应还/结算金额与币种、期次/应还日、收款账户要点、付款时间及平台提交时间、凭证/哈希、冻结逾期天数和不可撤销告知；记录人员、重复商务条款等辅助内容留在只读详情。业务选择处的放款编号保留，不能因信息精简又失去同机构多笔识别。双方之外不展示私有处理进度和材料。组件和具体排列由Hallmark决定。

剩余还款确认时限平常精确到小时，不足 24 小时精确到分钟并加强提示；到期以 RM-15 为准，倒计时下限 0。到期前 24 小时提醒资金方；届满双方各一次超期通知，改为“已超过还款确认时限 N 天”的中性标记；不足完整 24 小时明确“已超过还款确认时限，不足1天”，此后显示完整经过天数，准确截止始终可查，不显示“0天”掩盖已超期。到期不改状态、不释放额度、不自动确认、不解冻资产方逾期天数、不关闭确认入口。

唯一业务动作“确认收到还款”。同一容器内最终二次确认说明：资金方已自行核实到账、平台未核验；确认不可撤销。含本金期次说明本次本金对应授信占用额会减少；只有该次操作会使全部期次结清时，才能同时提示“本笔融资业务将结清”，不能只凭“是最后日期的期次”作此承诺。

确认成功时，期次 S-RP-2 → S-RP-3、形成 RP-17/RM-18，同步累计已还本金/利息；按本期已偿本金同时减少项目融资余额和该资金方对该资产方的授信占用额。利息期本金为 0，两项均不变；末期减少本金而非本息合计；手续费不参与计量。同时按 §3.4 更新 FD-44；相关逾期期次未全部结清则保留，历史不删除。全部期次完成时按 §3.6 结清业务。

上述本地还款结果整体生效或整体不发生；确认失败保持待还款确认并允许再次办理，不出现“已结清但额度未减”。重复确认或操作时页面已过期，展示当前事实，不重复减少额度，不新增第二次结清结果。成功在本操作弹窗显示该期已确认结果并更新原清单/操作区；关闭回原位置，不自动打开详情或其他期次。

资金方始终不确认时，目标期次停在 S-RP-2，业务不能最终结清；该期本金若尚未确认，两项本金占用不减少，项目不能据此释放质押。页面和超期通知同时说明逾期天数已冻结、平台不自动或代为确认。双方线下沟通后，资金方仍回原入口确认，结果与未超期时一致。

客服邮箱在还款确认办理步骤、还款详情、超期通知三处可见并可复制，附融资申请编号、融资业务编号、计划编号；共用平台既有邮箱，真实值待提供，不造地址。平台不承诺处理时限或结果。无申诉、驳回、部分确认、平台介入中、后台强制确认入口；不得引导未收到款项的资金方“先确认再说”。

### 3.6 业务结清及项目释放衔接

需求：F-LS-74、L8-REL-01。依据：D-RP-38/39/64、D-FIN-43/49/57、B5 §4.1 X-05。图：[L8-F03](l8-repayment-flows-and-states.md#l8-f03)、[L8-S02](l8-repayment-flows-and-states.md#l8-s02)、[L8-S03](l8-repayment-flows-and-states.md#l8-s03)。

**单笔业务结清。** 全部期次 S-RP-3 才使该业务 S-FD-6 → S-FD-8，记 FD-45；未偿本金为 0、该笔对应两项本金占用均归零、清除业务逾期标记，业务编号保留且不回收。不是资产方提交即结清，不是确认超期即结清，也不是末期期次单独结清就无视其他未结清期次。该需求的对外状态一直为“已放款”，不新增“已结清”需求状态或“已放款·逾期”拼接状态。

**项目层判断。** L8 将“该笔业务已结清”交给借贷平台 L5，由 L5 综合项目在途、其他未结清业务及项目到期/关闭条件判定。单笔业务结清只减少对应本金占用，不按“对应代币”部分释放。

| 项目情形（引用 L5） | 释放关系 |
| --- | --- |
| 项目未满足关闭/结清条件，即使一笔业务已结清 | 不以该笔结清触发整个池或所谓对应代币自动释放 |
| 项目到期且无在途、无未结清业务 | L5 判为 S-FP-5 已关闭，触发项目全部质押释放 |
| 项目到期仍有存量在途或未结清业务 | 不关闭，显示“已到期 · 存量处理中”；存量全部走完后 L5 判 S-FP-6 已结清，触发全部释放 |
| L5 已允许的主动关闭 | S-FP-1/S-FP-2 且无在途、无未结清业务，由 L5 关闭后触发全部释放；本模块不增设关闭按钮 |

**L8-REL-01 跨平台业务边界。** 释放的业务决策归借贷平台，代币相关执行由代币发行平台 T7 提供；借贷平台还款计划和结清事实不改由 T7 裁决。X-05 已定方向为借贷平台 → 代币发行平台；既定“同步发起 + 异步回调”仅作 B5/B8 的依赖约束记录，本稿不扩写交互协议。

**业务释放与链上提取分开。** 以最新 [L5 功能 §9.5 D-FIN-49/57](https://8.216.50.84.nip.io/api/attachments/01a0c3d3-0e29-7f3d-be39-b6aec382c00c/download) 为准：项目进入 S-FP-5/S-FP-6 的同一时刻，借贷平台解除全部质押占用关系，代币置 PS-4“已释放 · 待提取”，即时、无链上动作、零费用。此业务时点已经确定，不因跨平台执行细节未完备而重新列为待裁定。链上提取另由资产方自助发起、代币发行平台执行，资产方自付 gas，可批量、无提取时限。

业务终态不依赖链上转回成功；未提取代币仍在合约内，不属于任何池，不计入覆盖，不能再次质押。提取失败不回退业务结清或恢复授信占用，仍可按 L5 提取规则办理。跨平台执行未知时，已确定的“业务已释放”与“尚未确认提取成功”可以同时呈现；请求受理、重复请求或项目终态均不等于链上转回成功。只依据真实执行结果显示已提取，不将未知自动当成失败或成功。

**L8-REV-06 执行异常仅联系客服（P03，承接 L5 D-LS-63）。** 长期无结果、跨期/项目终态、事实冲突、部分结果中未核实的笔，显示“执行结果待核实，请联系平台客服人员”，保留真实业务/代币标识、动作、已知结果和费用供核对。正常明确结果逐笔呈现，已知成功与待核实不得整批合并为成功或失败；客服联系不改变任何结果或恢复资格。未知不重试执行、不放开重押、不补有效覆盖，费用未知不填零；项目终态后结果迟到不恢复项目。正常明确失败的提取保留 PS-4 及既有办理条件；与结果未知分开。本期不建设工单、自动补偿、强制释放、人工改判/补记、异常退回或恢复资格流程。Q-L8-01只留真实执行结果、联系方式及跨平台核验依赖，不再等负责人重选异常处置方案。

**重复释放反馈（已确认）。** 对同一项目、同一批已完成业务释放的代币再次发起释放，返回“已释放”，按成功事实反馈，不报操作失败，不再解除一次占用、不再次变更本金/额度，也不因此重复发起链上提取。仍在合约内时不能把“已释放”改写成“已提取”。若对象尚无已释放事实，不能用“重复请求”推断已释放；链上执行未知按本节联系客服，实际联验依赖见 Q-L8-01，不能用它覆盖本平台已经确定的业务释放事实。

**用户可见结果。** 业务结清展示业务本身的结清事实；项目与质押信息使用各自已确认结果。实际可提取时引导到 L5“解除质押”入口中“提取已释放”部分，显示可提取数量/金额与自付 gas 提示，不承诺自动回钱包。正常提取入口按 L5 已定条件开放；执行异常按本节客服边界处理；Q-L8-01为真实衔接核验依赖，不在还款确认步骤要求再次签名提取。

**融资业务字段。** 以下均只读，不作为用户录入项。

| 字段 | 类型、出现时点与规则 |
| --- | --- |
| FD-40 日期重算告知留痕 | 时间；接受报价展示告知时记录，不需用户勾选 |
| FD-41 计划定稿时间 | 时间；放款确认时形成，恢复生成不改成重试时刻；公开 |

所有通知带融资申请编号、融资业务编号和放款编号；期次类另带计划编号。通知不包含敏感凭证、哈希、完整账户或双方备注。同一事件重复办理、刷新或补判不重复提醒；不增加每天催收、单独开窗、标记清除等消息。资金方收到的消息不能提供资产方写权限。

控制台只读使用同一计划/期次事实：待我还款、已逾期待我还款、待我确认、已超期待我确认四类待办；未到期仍只读，已提交即不再列待资产方还款，但逾期未结清业务标记持续；详情、待办、通知对状态、确认时限和逾期天数一致。不在广场列表卡片增设还款进度或第六个需求状态；公开还款进展在项目“还款信息”清单、对应详情及控制台呈现；各入口指向同一笔业务/期次。

### 3.8 质量与业务约束

沿用 B2 第 8 章既有目标，不另定指标：打开还款容器至期次可选 ≤2 秒；还款提交和确认各 ≤2 秒；不超过 8 期的定稿计划生成 ≤2 秒。逾期判定延迟目标 ≤5 分钟；确认时限届满判定目标 ≤1 分钟、最坏 ≤5 分钟；两者都以应到时点生效，不能重复产生结果。

以上是原基线的借贷平台体验目标，不据此承诺跨平台 X-05 或链上提取完成时长。重要动作可追溯至业务、期次、动作人和时间，能够解释为何形成还款和额度结果；不在本稿展开内部记录格式或保留期限。
