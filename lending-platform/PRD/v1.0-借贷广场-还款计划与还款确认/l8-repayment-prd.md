## 2. 角色、对象与共同口径

| 角色 | 可执行动作 | 可见范围 |
| --- | --- | --- |
| 资产方 | 本企业所属业务选择期次、录入并提交还款；查看计划和记录 | 本业务双方资料可见；不能替资金方确认 |
| 资金方 | 仅对本机构出资业务确认收到还款；查看计划和记录 | 本业务双方资料可见；不能替资产方提交或修改计划 |
| 访客、非当事方 | 只读公开履约信息 | 不得访问凭证、哈希、收款账户、还款时间自填值、备注、补充材料 |
| 运营人员、SPV 机构 | 本模块没有新增面客业务动作 | 不因运营或 SPV 身份取得还款、确认或代为裁决权限 |

沿用同一企业主体下任一登录员工均可代表企业执行该企业动作的规则，本模块不增设企业内复核层级。资产方授权登录、资金方账号和准入由 L1/L2/L3 提供，本册不展开登录协议。

融资申请编号 `FP-28`（原需求编号）、融资业务编号 `FD-01`、放款记录编号 `LN-01` 在已成交并进入还款的单笔业务上为 1:1:1；报价阶段同一申请可能先后关联多笔 FD，不能把这一对应关系扩大到整个报价历史。一个项目可以先后有多笔业务、多个资金方。还款信息清单一行对应一笔已确认到账的融资业务，以融资申请编号作主标识，业务编号和放款编号作关联检索；`RP-01` 一期一个，`RM-01` 一次成功提交一个，均不得用作整笔清单的唯一标识，不能把整笔业务和单期期次混称“还款计划编号”。

| 对象 | 本模块使用的状态/标记 | 边界 |
| --- | --- | --- |
| 还款期次 | S-RP-1 待还款 → S-RP-2 待还款确认 → S-RP-3 已结清 | 只有资金方成功确认才结清；S-RP-4 本期不产生 |
| 融资业务 | S-FD-6 还款中 → S-FD-8 已结清 | 全部期次结清才进入终态；S-FD-9 逾期为并行标记 |
| 融资项目 | S-FP-5 已关闭 / S-FP-6 已结清 | 由 L5 判定；不能从单笔 S-FD-8 直接推导 |
| 质押关系 | 沿用 L5：PS-1 可质押、PS-2 已质押、PS-4 已释放 | 本平台口径引用 L5 主册 §5.1 D-LS-22～25；PS-0 非法，不重新裁定；不据此声称跨平台已联验 |
| 链上资产位置 | 仍在合约待提取 / 已转回资产方地址 | “已释放”不等于“已到账钱包” |

默认英文、可切中文；所有时点有时区标注，开窗与逾期判定使用统一业务时区，具体值待 Q-L8-04 确认。术语区分“报价有效期”“放款确认时限”“还款确认时限”，不得把确认超期称为还款逾期。金额注明币种；记账本位币为 USD；使用完整名称“项目融资余额”“授信占用额”“质押覆盖状态”。

用户界面展示实际业务编号供识别，但不展示 `RP-11` 一类字段定义号、条款号、字段来源论证或规则说明图。

### 3.1 业务选择与还款入口

需求：F-LS-75、77、79。依据：D-RP-59/60/66/67/71～74/76～81。流程：[L8-F01](l8-repayment-flows-and-states.md#l8-f01)。

项目主页面左侧依次纵向展示“质押代币清单 → 融资申请信息 → 融资放款信息 → 还款信息”，随页面自然滚动，不做清单Tab切换；右侧办理区固定“质押 / 融资 / 还款”三个页签。共同布局与返回行为以 [L5 功能需求说明 §9.2、§11.7](../v1.0-借贷广场-融资需求与代币质押/01-功能需求说明.md) 为统一来源。还款信息负责查记录，右侧还款页签负责办理；不再在一个融资需求详情中堆叠全部还款流程。

**还款信息清单。** 资产方确认到账、业务进入 S-FD-6 后即产生一行；计划生成中也可进入查看，不能等到计划成功才隐藏或补造该笔已成交事实。结清后保留原行和只读计划。尚无还款业务时，清单显示“暂无还款信息”，右侧还款页签仍保留并说明“确认到账后可查看还款计划和办理还款”，不提供无对象的提交动作。角色可见范围仍遵循第 2 章。

| 清单信息 | 展示与业务口径 |
| --- | --- |
| 融资申请编号、融资业务编号、放款编号、出资机构 | FP-28 为主标识；FD-01、LN-01 和机构辅助识别，同一行始终指向同一笔业务；三个既有编号均可检索，不创建新编号 |
| 业务状态与计划情况 | 显示还款中或已结清；定稿未完成显示“还款计划生成中”；逾期和确认超期使用既有并行标记，不造新的主状态 |
| 本期应还信息 | 按 §3.3 的顺序选取该笔第一条 S-RP-1，显示期次/总期数、应还日、USD 应还合计、结算币种金额、期次状态、逾期天数及未开窗时的开启日期；无候选显示“暂无待还期次”，不是 0 元应还 |
| 待确认情况 | 有 S-RP-2 时显示待确认提示并提供对应记录入口；可与下一待还期并存，不能用下一期应还卡遮盖已提交记录；无 S-RP-1 但有 S-RP-2 时仍可进入确认 |
| 查看与办理 | 查看详情始终可达；立即还款和确认收到还款按下表与业务权限提供，结清业务只读；未到期、生成中不因无法提交而从清单消失 |

右侧还款办理区用一个业务选择器选择本项目的某笔业务，选择项的编号与清单相同；只有一笔时显示编号，不出现多余选择控件。多个待办先选业务，再选期次；从清单行进入时直接带入该行业务，不要求再次选择业务。切换业务后，应还卡片、默认期次、计划和账户同步，不混入其他业务。选中业务没有待办时显示对应原因，不能悄悄转到另一笔业务。

**还款详情顺序。** 顶部展示融资申请编号、业务/放款编号、出资机构及业务状态；其后依次为本期应还信息、还款计划列表、资金方还款收款账户、还款记录及凭证。计划按 §3.2 展示该笔定稿单版，已提交期次可查看记录并由有权资金方办理确认。账户引用 RP-14，历史记录使用 RM-10 快照，仅双方可见；本轮不新增资产方独立出账账户，也不将资产方放款收款账户默认为还款出账账户。计划生成中只呈现已知业务事实、生成提示与有权查看的账户，不伪造期次、应还金额或办理入口。全部结清展示结清结果及只读计划，历史逾期仍保留。

| 入口 | 条件与反馈 |
| --- | --- |
| 立即还款 P-LS-09 | 本企业资产方、业务还款中且存在待还期次，可查看期次与开窗信息；只有已开窗且仍待还的期次可提交。未开窗展示原因及开启日期 |
| 确认收到还款 P-LS-10 | 本业务资金方、目标期次待还款确认；确认超期后仍可用 |
| 查看还款计划 | 定稿后按选定业务只读查看；结清后保留；非当事方只见公开信息 |
| 未登录 | 操作区只出“立即登录”；公开履约信息仍可读，直接访问公开计划不授予操作或敏感资料权限 |

查看详情、选择期次、办理和必要的最终二次确认均在同一个右侧业务抽屉中逐步切换。最终确认保留取消和继续两个动作及全部不可逆告知；取消退回原办理步骤，保留原业务、期次和已填写内容，不另开居中弹窗或第二个抽屉。查看完整计划、关联申请/放款详情、凭证预览也在同一容器内切换，可返回原业务和期次；下载直接执行，不增加遮罩层。宽度由设计按信息可读性确定，窄屏同一抽屉全屏展示。

返回只退当前步骤；关闭回原清单并保留筛选、分页、滚动位置和行焦点。有未提交内容时在原抽屉内确认是否放弃，取消放弃保留内容。提交或确认成功后更新原记录和同一抽屉内详情，展示可用下一步入口，不自动打开其他业务。重新进入时按业务最新状态呈现。

通知、控制台或直达链接定位项目详情的还款信息清单及指定业务/期次，并进入同一业务抽屉；状态已变化则展示当前事实与可执行动作。未开窗、已提交待确认、已结清、非当事方分别说明原因，不只显示“暂不可操作”；无效目标不给空白页，按既有详情导航返回可访问入口。公开信息访问不暴露双方私有资料。

### 3.2 初始计划、定稿与计划查看

需求：F-LS-60～64。依据：D-RP-04～20/40/72/80/81。流程：[L8-F01](l8-repayment-flows-and-states.md#l8-f01)。

**初始计划。** 资金方提交报价后，按报价提交日作为预计放款日试算；只在报价详情和报价确认接受抽屉展示，不形成有效期次、不占用 RP 编号。整表标“预计 · 未生效”，日期列为“预计还款日”，常驻说明实际安排会在放款确认后按实际放款日重算。接受报价时展示此说明并记录展示时间，不增加勾选要求。报价拒绝、失效或终止后，初始计划不留下有效期次。

**定稿。** 资产方完成放款确认时生成，触发时点为 FD-35；起息日为放款记录提交时间 LN-06 的日期，不能用资金方自填发放时间 LN-05，也不能改用放款确认日。本金取 QT-03，年化利率取 QT-06，最终还款日取 QT-16（等于项目截止日 FP-09，当前不可编辑）。定稿后期次、应还日、金额和计息规则不可更改，只追加还款记录、逾期历史和结清事实。

生成未完成时显示“还款计划生成中”，不能展示一份旧计划作为定稿，也不能回退已完成的放款确认、债务或额度事实。恢复后只生成同一套期次；定稿时间仍对应原放款确认时点。

日期变化属于已告知规则的执行，不新增一次报价确认：金额、币种、汇率快照、年化利率和期次规则沿用原条款。定稿告知须包含预计/实际起息日、期数变化、各期应还日与金额对照；资金方通过放款确认通知进入同笔详情查看计划进度；通知送达时若仍生成中，不声称已有完整计划。定稿后在同笔详情查看正式安排，不重复发送定稿提醒。

**期次与利息。** 还款类型唯一值为“按季付息；到期还本付息”，按起息日起每 3 个自然月同日划分，不按自然季度末；目标月份无同日时取该月末日。到期日在三个月内时只有一期。一般期仅付息，末期还全部本金及末期利息；不足完整一季的尾段与前一段合并为末期，不单独形成小额尾期，末期区间可长于三个月但不超过六个月。以起息 2026-09-15、到期 2027-03-20 为例，为 2026-12-15 付息、2027-03-20 还本付息两期。

年化单利、ACT/360、算头不算尾。每期计息天数为本期止日减起日；每期利息 = 本金 × 年化利率（百分比换成比例）× 天数 ÷ 360，独立保留两位小数、四舍五入，利息尾差不跨期结转。应还 USD 合计 = 本金 + 利息；结算金额 = USD 合计 ÷ 报价锁定汇率 QT-04，还款不重取汇率。结算金额精度与统一时区的缺口见 Q-L8-04，不把原型两位小数演示自动升级为数币结算规则。

**定稿计划查看。** 只显示选定业务的定稿版，无初始版切换或双版对照。标题带融资申请编号、出资机构、业务/放款编号、结算币种、定稿时间。主表六列：期次、应还日、应还合计（USD）、结算币种金额、期次状态、逾期天数。当前应还期次高亮并进入可视区；本息拆分、计息区间及天数在行内展开，末期注明含本金及合并区间。标题、年化利率和计息规则常驻；表头与期次列固定，窄屏允许表格横向滚动。表尾只合计选定业务的 USD 本金/利息/合计，不对结算金额或跨笔数据求和。

**计划字段（F-LS-62/64）。** 下表系统生成字段均只读；所述条件未满足时为空，不用 0 冒充未知。除 RP-14 外为公开业务信息，RP-13 提交后才形成正式还款性质。

### 3.3 选期与还款提交

需求：F-LS-65～69、78。依据：D-RP-21～31/41～45/68～70/75/79。流程与状态：[L8-F02](l8-repayment-flows-and-states.md#l8-f02)、[L8-S01](l8-repayment-flows-and-states.md#l8-s01)。

候选为资产方企业名下 S-RP-1 期次：全局待办可跨业务/项目；项目详情及其抽屉仅在所选业务内取候选。依次按应还日、LN-06 放款提交时间、FD-01、期次序号升序，第一条为默认项。逾期组在前，未到期组在后；禁止按“距离今天的绝对天数”排序。可以改选已开窗期次；未开窗期次可见但不可提交，注明开启日期。不要求先结清另一个已开窗期次才可选择当前期；所谓禁止跳期是不得越过开窗规则提交未来期次。

开窗为应还日前 3 个自然日零时；逾期期次保持可还。一次仅提交一期，不多选、不全选、不合并；金额和币种只读，不出现“提前还本”“全部结清”动作。末期也按此开窗规则呈现；上游“到期之后才还本金”的措辞与该规则存在边界冲突，见 Q-L8-03，不能默改末期窗口。

还款办理步骤仅集中本期应还信息、期次选择、收款账户和填写项。四项不可省略：期次/应还日、USD 应还及结算金额、只读收款账户、逾期天数及提交即冻结提示。完整计划与验算数据通过“查看完整还款计划”可达；其他业务的期次可返回清单换选业务或从控制台查看，不在本次选期中混列。注明平台仅登记还款，不代为转账；提交记录本身不收取 gas。

**还款记录字段。** 用户填写项无已确认自动填值，默认空；可选材料和备注可留空。系统项只读。提交成功后全部记录不可修改或撤回。

异常：格式/大小/数量错误就地说明，保留其他已上传文件；未来还款时间拒绝；未开窗、非本人业务、期次已变更均不能提交。多人重复提交最多一条成功，后到者看到“该期已提交还款记录”及当前详情，不重复冻结或重新启动时限。链为 ETH 常量，原 E-RP-05“选错链”本期不可达，不为其设置选择或错误分支。

<a id="f-overdue"></a>
### 3.4 逾期与提交保护

需求：F-LS-68、70。依据：D-FIN-11、D-RP-29～31/34/35/46～50/58。状态：[L8-S01](l8-repayment-flows-and-states.md#l8-s01)。

应还日次日 00:00 仍未成功提交，即标逾期；不设宽限期，首个逾期自然日为 1 天，之后逐日增加。迟于应到时点才完成判定时仍按应到时点计算，不能减免延迟期间天数，也不能重复提醒。逾期是期次和业务的并行标记，不替换“待还款”“还款中”状态。

成功提交时冻结本期期次逾期天数，此后不因资金方不确认继续增加，也不继续产生该期新增逾期通知。本期利息已在定稿时确定，应还金额不随提交或确认早晚变化。结清后保留历史逾期天数；另一未提交期次仍独立计逾期，不能因本期提交冻结整笔业务的所有期次。

还款性质在提交时依是否逾期，取“正常还款/逾期还款”；不得与“还款类型”混名。业务整体逾期标记 FD-44 在全部逾期期次转待确认时是否立即清除，原字段定义与说明冲突，见 Q-L8-03；不影响本期期次天数冻结、成功结清时清除业务标记。

不计算或展示罚息，不增加应还金额，不自动处置质押，不影响其他资金方授信。即使资金方线下主张凭证无效，本期也没有裁决和解冻回补路径。覆盖不足不阻断还款、确认或结清；项目“已到期 · 存量处理中”按中性正常履约路径呈现。

### 3.5 还款确认与超期处理

需求：F-LS-71～73。依据：D-RP-32/33/36/37/51～57、AC-FIN-36。流程：[L8-F02](l8-repayment-flows-and-states.md#l8-f02)。

资金方打开目标期次，核对金额、币种、只读收款账户、还款时间与平台提交时间、凭证或哈希及未核验提示、本期计划和冻结逾期天数。两个时间名称必须清楚，自填还款时间仅用于对账，时限从成功提交开始，不能从通知送达或首次查看开始。

剩余还款确认时限平常精确到小时，不足 24 小时精确到分钟并加强提示；到期以 RM-15 为准，倒计时下限 0。到期前 24 小时提醒资金方；届满双方各一次超期通知，改为“已超过还款确认时限 N 天”的中性标记。到期不改状态、不释放额度、不自动确认、不解冻资产方逾期天数、不关闭确认入口。

唯一业务动作“确认收到还款”。同一抽屉内最终二次确认说明：资金方已自行核实到账、平台未核验；确认不可撤销。含本金期次说明本次本金对应授信占用额会减少；只有该次操作会使全部期次结清时，才能同时提示“本笔融资业务将结清”，不能只凭“是最后日期的期次”作此承诺。

确认成功时，期次 S-RP-2 → S-RP-3、形成 RP-17/RM-18，同步累计已还本金/利息；按本期已偿本金同时减少项目融资余额和该资金方对该资产方的授信占用额。利息期本金为 0，两项均不变；末期减少本金而非本息合计；手续费不参与计量。全部期次完成时按 §3.6 结清业务。

上述本地还款结果整体生效或整体不发生；确认失败保持待还款确认并允许再次办理，不出现“已结清但额度未减”。重复确认或操作时页面已过期，展示当前事实，不重复减少额度，不新增第二次结清结果。成功后在同一抽屉回到详情显示该期结果并更新原清单行；不自动跳到其他期次。

资金方始终不确认时，目标期次停在 S-RP-2，业务不能最终结清；该期本金若尚未确认，两项本金占用不减少，项目不能据此释放质押。页面和超期通知同时说明逾期天数已冻结、平台不自动或代为确认。双方线下沟通后，资金方仍回原入口确认，结果与未超期时一致。

客服邮箱在还款确认办理步骤、还款详情、超期通知三处可见并可复制，附融资申请编号、融资业务编号、计划编号；共用平台既有邮箱，真实值待提供，不造地址。平台不承诺处理时限或结果。无申诉、驳回、部分确认、平台介入中、后台强制确认入口；不得引导未收到款项的资金方“先确认再说”。

### 3.6 业务结清及项目释放衔接

需求：F-LS-74、L8-REL-01。依据：D-RP-38/39/64、D-FIN-43/49/57、B5 §4.1 X-05。图：[L8-F03](l8-repayment-flows-and-states.md#l8-f03)、[L8-S02](l8-repayment-flows-and-states.md#l8-s02)、[L8-S03](l8-repayment-flows-and-states.md#l8-s03)。

**单笔业务结清。** 全部期次 S-RP-3 才使该业务 S-FD-6 → S-FD-8，记 FD-45；未偿本金为 0、该笔对应两项本金占用均归零、清除业务逾期标记，业务编号保留且不回收。不是资产方提交即结清，不是确认超期即结清，也不是末期期次单独结清就无视其他未结清期次。该需求的对外状态一直为“已放款”，不新增“已结清”需求状态或“已放款·逾期”拼接状态。

**项目层判断。** L8 将“该笔业务已结清”交给借贷平台 L5，由 L5 综合项目在途、其他未结清业务及项目到期/关闭条件判定。单笔业务结清只减少对应本金占用，不按“对应代币”部分释放。

| 项目情形（引用 L5） | 释放关系 |
| --- | --- |
| 项目未满足关闭/结清条件，即使一笔业务已结清 | 不以该笔结清触发整个池或所谓对应代币自动释放 |
| 项目到期且无在途、无未结清业务 | L5 判为 S-FP-5 已关闭，触发项目全部质押释放 |
| 项目到期仍有存量在途或未结清业务 | 不关闭，显示“已到期 · 存量处理中”；存量全部走完后 L5 判 S-FP-6 已结清，触发全部释放 |
| L5 已允许的主动关闭 | S-FP-1/S-FP-2 且无在途、无未结清业务，由 L5 关闭后触发全部释放；本模块不增设关闭按钮 |

**L8-REL-01 跨平台业务边界。** 释放的业务决策归借贷平台，代币相关执行由代币发行平台 T7 提供；借贷平台还款计划和结清事实不改由 T7 裁决。X-05 已定方向为借贷平台 → 代币发行平台；既定“同步发起 + 异步回调”仅作 B5/B8 的依赖约束记录，本稿不扩写交互协议。

**业务释放与链上提取分开。** 以同批 [L5 功能 §9.5 D-FIN-49/57](../v1.0-借贷广场-融资需求与代币质押/01-功能需求说明.md) 为准：项目进入 S-FP-5/S-FP-6 的同一时刻，借贷平台解除全部质押占用关系，代币置 PS-4“已释放 · 待提取”，即时、无链上动作、零费用。此业务时点已经确定，不因跨平台执行细节未完备而重新列为待裁定。链上提取另由资产方自助发起、代币发行平台执行，资产方自付 gas，可批量、无提取时限。

业务终态不依赖链上转回成功；未提取代币仍在合约内，不属于任何池，不计入覆盖，不能再次质押。提取失败不回退业务结清或恢复授信占用，仍可按 L5 提取规则办理。跨平台执行未知时，已确定的“业务已释放”与“尚未确认提取成功”可以同时呈现；请求受理、重复请求或项目终态均不等于链上转回成功。只依据真实执行结果显示已提取，不将未知自动当成失败或成功。

Q-L8-01 仅保留跨平台执行未完成的具体业务反馈、未知/失败/部分结果的后续办理口径及其联验边界。既定业务释放、正常自助提取入口和业务终态均不等待这项补齐；本册不另外设计自动补办、失败回滚或新的状态枚举。

**重复释放反馈（已确认）。** 对同一项目、同一批已完成业务释放的代币再次发起释放，返回“已释放”，按成功事实反馈，不报操作失败，不再解除一次占用、不再次变更本金/额度，也不因此重复发起链上提取。仍在合约内时不能把“已释放”改写成“已提取”。若对象尚无已释放事实，不能用“重复请求”推断已释放；链上执行未知的后续反馈见 Q-L8-01，不能用它覆盖本平台已经确定的业务释放事实。

**用户可见结果。** 业务结清展示业务本身的结清事实；项目与质押信息使用各自已确认结果。实际可提取时引导到 L5“解除质押”入口中“提取已释放”部分，显示可提取数量/金额与自付 gas 提示，不承诺自动回钱包。正常提取入口按 L5 已定条件开放；具体跨平台执行异常反馈见 Q-L8-01，不在还款确认步骤要求再次签名提取。

控制台只读使用同一计划/期次事实：待我还款、已逾期待我还款、待我确认、已超期待我确认四类待办；详情、待办、通知对状态、确认时限和逾期天数一致。不在广场列表卡片增设还款进度或第六个需求状态；公开还款进展在项目“还款信息”清单、对应详情及控制台呈现；各入口指向同一笔业务/期次。

### 3.8 质量与业务约束

沿用 B2 第 8 章既有目标，不另定指标：打开还款抽屉至期次可选 ≤2 秒；还款提交和确认各 ≤2 秒；不超过 8 期的定稿计划生成 ≤2 秒。逾期判定延迟目标 ≤5 分钟；确认时限届满判定目标 ≤1 分钟、最坏 ≤5 分钟；两者都以应到时点生效，不能重复产生结果。

以上是原基线的借贷平台体验目标，不据此承诺跨平台 X-05 或链上提取完成时长。重要动作可追溯至业务、期次、动作人和时间，能够解释为何形成还款和额度结果；不在本稿展开内部记录格式或保留期限。
