# 还款计划与还款确认 · PRD

版本：L8 V2.4｜需求评审稿｜2026-09-22。

<a id="entry"></a>
## 1. 目标、范围与阅读入口

资产方查看每期何时、向谁、还多少并录入付款信息；资金方核实到账后确认。还款提交、期次结清、整笔业务结清、项目终态和质押释放分别依据各自事实成立。

本期包含预计与定稿计划、按笔选期、还款信息录入、逾期与确认时限、资金方确认、额度递减、业务结清、项目释放衔接及相关通知。平台不代转账；不提供提前结清、跨期合并支付、部分或超额还款、改期改额、展期重组、罚息、自动确认、裁决、记录修改撤回、确认撤销、自动处置质押或跨机构风险传导。项目关闭、撤回和提取由融资需求与代币质押模块管理。

有效依据：现行还款业务及用户已确认的 P01～P12 中适用规则、单选择器、四区滚动定位、只读详情与居中办理分离。应还日开放录入、提交冻结逾期天数与确认后清当前标记、固定折算和 UTC 规则适用于全部期次。

阅读顺序：共同口径 → 完整功能 → 同序验收；必要外部依赖见第5章。产品、研发和测试共读本册。配套：[流程图与状态机](02-还款计划与还款确认-流程图与状态机.md#entry)、[消息通知](03-还款计划与还款确认-消息通知.md#notify-entry)。上游采用[融资需求与代币质押](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)、[授信报价](../v1.0-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md)、[放款与放款确认](../v1.0-借贷广场-放款与放款确认/01-放款与放款确认-PRD.md)现行正式文件。

## 2. 角色、对象与共同口径

| 角色 | 可执行动作 | 可见范围 |
| --- | --- | --- |
| 资产方 | 本企业所属业务选择期次、录入并提交还款；查看计划和记录 | 本笔必要业务资料依下述权限可见；不能替资金方确认 |
| 资金方 | 仅对本机构出资业务确认收到还款；查看计划和记录 | 本笔必要业务资料依下述权限可见；不能替资产方提交或修改计划 |
| 访客、非当事方 | 只读公开履约信息 | 不得访问凭证、哈希、收款账户、还款时间自填值、备注、补充材料 |
| 运营人员、SPV 机构 | 本模块没有新增面客业务动作 | 不因运营或 SPV 身份取得还款、确认或代为裁决权限 |

<a id="L8-REV-01"></a>

**L8-REV-01 资料与角色边界（P01/P04）。** 个人、企业账户档案仅本人可查，不因交易关系开放对方完整档案、认证材料或私人联系方式。本笔必要主体、机构、金额、条款和付款资料自动取得并按业务权限展示；加载中、缺失和读取失败区分，失败可重试，不要求手填对方档案或用假值补齐。运营与 SPV 同等处理，无新增私有资料读取、资金操作或代确认权限。

沿用同一企业主体下任一登录员工均可代表企业执行该企业动作的规则，本模块不增设企业内复核层级。资产方授权登录、资金方账号和准入由 L1/L2/L3 提供，本册不展开登录协议。

融资申请编号 `FP-28`（原需求编号）、融资业务编号 `FD-01`、放款记录编号 `LN-01` 在已成交并进入还款的单笔业务上为 1:1:1；报价阶段同一申请可能先后关联多笔 FD，不能把这一对应关系扩大到整个报价历史。一个项目可以先后有多笔业务、多个资金方。还款信息清单一行对应一笔已确认到账的融资业务，以融资申请编号作主标识，业务编号和放款编号作关联检索；`RP-01` 一期一个，`RM-01` 一次成功提交一个，均不得用作整笔清单的唯一标识，不能把整笔业务和单期期次混称“还款计划编号”。

| 对象 | 本模块使用的状态/标记 | 边界 |
| --- | --- | --- |
| 还款期次 | S-RP-1 待还款 → S-RP-2 待还款确认 → S-RP-3 已结清 | 只有资金方成功确认才结清；S-RP-4 本期不产生 |
| 融资业务 | S-FD-6 还款中 → S-FD-8 已结清 | 全部期次结清才进入终态；S-FD-9 逾期为并行标记 |
| 融资项目 | S-FP-5 已关闭 / S-FP-6 已结清 | 由 L5 判定；不能从单笔 S-FD-8 直接推导 |
| 质押关系 | 沿用 L5：PS-1 可质押、PS-2 已质押、PS-4 已释放 | 本平台口径引用融资需求与代币质押的质押业务规则；PS-0 非法，不重新裁定；不据此声称跨平台已联验 |
| 链上资产位置 | 仍在合约待提取 / 已转回资产方地址 | “已释放”不等于“已到账钱包” |

<a id="L8-REV-02"></a>

**L8-REV-02 日期口径（P10）。** 默认英文、可切中文。应还日、最终还款日、起息日、编号中的日期均为 UTC 业务日期；还款录入开放为应还日 00:00 UTC，逾期从次日 00:00 UTC 起算。具体时刻按用户偏好时区展示并标注，无偏好沿平台既有展示规则，游客按浏览器时区并标注；日期字段明确标注 UTC 业务日期，不能按当地跨日另生应还日。语言、时区和夏令时切换不改变事实。确认时限连续 168 小时，不按第七个自然日末延长。术语区分“报价有效期”“放款确认时限”“还款确认时限”，不得把确认超期称为还款逾期。金额注明币种；记账本位币为 USD；使用完整名称“项目融资余额”“授信占用额”“质押覆盖状态”。

用户界面展示实际业务编号供识别，但不展示 `RP-11` 一类字段定义号、条款号、字段来源论证或规则说明图。

## 3. 功能需求

<a id="f-entry"></a>
### 3.1 业务选择与还款入口

流程：[L8-F01](02-还款计划与还款确认-流程图与状态机.md#l8-f01)。

<a id="F-LS-77"></a>
#### 按业务查看与选择还款（F-LS-77）

项目主页面左侧依次纵向展示“质押代币清单 → 融资申请信息 → 融资放款信息 → 还款信息”，随页面自然滚动；顶部“质押代币 / 融资申请 / 融资放款 / 还款”定位标签只滚动到对应区，不隐藏或替换清单；右侧办理区固定“质押 / 融资 / 还款”三个页签。共同布局与返回行为以 [项目查看与办理规则](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-20) 为统一来源。还款信息负责查记录，右侧还款页签负责办理；不再在一个融资需求详情中堆叠全部还款流程。

**还款信息清单。** 资产方确认到账、业务进入 S-FD-6 后即产生一行；计划生成中也可进入查看，不能等到计划成功才隐藏或补造该笔已成交事实。清单按到账确认时间倒序，每页5条，不提供条数切换并保留页码；办理选择器另按最近待办排序。结清后保留原行和只读计划。尚无还款业务时，清单显示“暂无还款信息”，右侧还款页签仍保留并说明“确认到账后可查看还款计划和办理还款”，不提供无对象的提交动作。角色可见范围仍遵循第 2 章。

| 清单信息 | 展示与业务口径 |
| --- | --- |
| 融资申请编号、融资业务编号、放款编号、出资机构 | FP-28 为主标识；FD-01、LN-01 和机构辅助识别，同一行始终指向同一笔业务；三个既有编号均可检索，不创建新编号 |
| 业务状态与计划情况 | 显示还款中或已结清；定稿未完成显示“还款计划生成中”；逾期和确认超期使用既有并行标记，不造新的主状态 |
| 本期应还信息 | 按 §3.3 的顺序选取该笔第一条 S-RP-1，显示期次/总期数、应还日、USD 应还合计、结算币种金额、期次状态、逾期天数及未开窗时的开启日期；无候选显示“暂无待还期次”，不是 0 元应还 |
| 待确认情况 | 有 S-RP-2 时显示待确认提示并提供对应记录入口；可与下一待还期并存，不能用下一期应还卡遮盖已提交记录；无 S-RP-1 但有 S-RP-2 时仍可进入确认 |
| 查看与办理 | 清单可打开只读详情；右侧资产方只保留立即还款，资金方保留确认收到还款，不放查看还款详情快捷按钮；办理按下表与业务权限提供，结清业务只读；未到期、生成中不因无法提交而从清单消失 |

<a id="F-LS-79"></a>
#### 选择同笔业务并查看最近应还（F-LS-79）

右侧还款办理区按本项目融资业务下拉选择，不把多笔编号平铺成按钮。每项及当前选中结果同时显示最近待还/待确认应还日期、机构和放款编号LN-01；不得只凭机构名区分，同一机构多笔必须可准确选择。仅一笔时无需额外选择动作，但仍显示日期、机构及编号。清单与详情继续支持FP-28/FD-01/LN-01定位；编号为信息，不是详情跳转按钮。业务按最近待办应还日期升序，逾期在前、未到期在后；同日按LN-06、FD-01稳定排序，不按距今天绝对天数排序。选中业务内再按§3.3选期；有待确认与下一待还并存时两者都保留，不因默认值漏掉确认待办。生成中/无待办/已结清在清单可查，不冒充可立即还款候选。切换业务同步金额、账户、期次和计划，不静默改办另一笔。

**还款详情内容。** 包含融资申请编号、业务/放款编号、出资机构及业务状态、本期应还信息、还款计划、资金方还款收款账户、还款记录及凭证；具体信息排列由设计决定。计划按 §3.2 展示该笔定稿单版，已提交期次可只读查看记录，有权资金方从右侧操作区办理确认。账户引用 RP-14，历史记录使用 RM-10 快照，仅双方可见；本期不新增资产方独立出账账户，也不将资产方放款收款账户默认为还款出账账户。计划生成中只呈现已知业务事实、生成提示与有权查看的账户，不伪造期次、应还金额或办理入口。全部结清展示结清结果及只读计划，历史逾期仍保留。

<a id="F-LS-75"></a>
#### 按当前权限进入还款或确认（F-LS-75）

| 入口 | 条件与反馈 |
| --- | --- |
| 立即还款 P-LS-09 | 本企业资产方、业务还款中且存在待还期次；到应还日 00:00 UTC 才开放该期录入与提交。此前只读显示计划、未开放原因及开启时点，不提供可编辑表单、凭证上传或提交 |
| 确认收到还款 P-LS-10 | 本业务资金方、目标期次待还款确认；确认超期后仍可用 |
| 查看还款计划 | 定稿后按选定业务只读查看；结清后保留；非当事方只见公开信息 |
| 未登录 | 操作区只出“立即登录”；公开履约信息仍可读，直接访问公开计划不授予操作或敏感资料权限 |

查看详情使用右侧只读抽屉，无办理或跨业务跳转按钮。立即还款与确认收到还款由右侧操作区或有效待办/通知进入居中弹窗。业务、期次、金额和已有账户自动带入，用户仅补本次必要资料；返回保留输入，未提交关闭在本操作弹窗确认放弃。还款提交和到账确认原有最终确认继续在本操作弹窗完成，不叠第二层；报价免二次确认的规则不适用于还款。

“立即还款”弹窗直接包含本笔定稿还款计划，默认折叠，可原位展开/收起，不另开计划弹窗或查看详情按钮；展开不清空输入、不切换业务，不代替当前期次金额和必要告知。确认弹窗按§3.5显示当前期次的进度及核对信息。成功更新该期与原清单/操作区，不自动打开详情、其他期次或下一业务；只读计划及历史记录仍可从清单详情查看。

通知/控制台的有效办理目标定位同一业务与期次的操作弹窗；查看目标进入只读详情。旧目标已变化时说明本笔当前结果、停用已失效动作，不静默跳到另一笔。未开窗、已提交、已结清、非当事方各有原因；无效目标给可访问返回路径，私有账户/凭证不因直达公开。容器尺寸、布局和窄屏适配由设计决定。

### 3.2 初始计划、定稿与计划查看

流程：[L8-F01](02-还款计划与还款确认-流程图与状态机.md#l8-f01)。

<a id="F-LS-60"></a>
#### 报价阶段查看预计计划（F-LS-60）

**初始计划。** 资金方提交报价后，按报价提交时刻的 UTC 日期作为预计放款日试算；在只读报价详情和报价接受操作弹窗展示，不形成有效期次、不占用 RP 编号。整表标“预计 · 未生效”，日期列为“预计还款日”，常驻说明实际安排会在放款确认后按实际放款日重算。报价拒绝、失效或终止后，初始计划不留下有效期次。

<a id="F-LS-61"></a>
#### 接受报价时告知日期重算（F-LS-61）

接受报价时展示实际安排将按实际放款日重算的说明，并记录展示时间 FD-40；不增加勾选要求。

<a id="F-LS-62"></a>
#### 放款确认后生成定稿计划（F-LS-62）

**定稿。** 资产方完成放款确认时生成，触发时点为 FD-35；起息日为放款记录提交时间 LN-06 的 UTC 日期，不能用资金方自填发放时间 LN-05，也不能改用放款确认日。本金取 QT-03，年化利率取 QT-06，最终还款日取 QT-16（等于项目截止日 FP-09，当前不可编辑）。定稿后期次、应还日、金额和计息规则不可更改，只追加还款记录、逾期历史和结清事实。

生成未完成时显示“还款计划生成中”，不能展示一份旧计划作为定稿，也不能回退已完成的放款确认、债务或额度事实。恢复后只生成同一套期次；定稿时间仍对应原放款确认时点。

**期次与利息。** 还款类型唯一值为“按季付息；到期还本付息”，按起息日起每 3 个自然月同日划分，不按自然季度末；目标月份无同日时取该月末日。到期日在三个月内时只有一期。一般期仅付息，末期还全部本金及末期利息；不足完整一季的尾段与前一段合并为末期，不单独形成小额尾期，末期区间可长于三个月但不超过六个月。以起息 2026-09-15、到期 2027-03-20 为例，为 2026-12-15 付息、2027-03-20 还本付息两期。

年化单利、ACT/360、算头不算尾。每期计息天数为本期止日减起日；每期利息 = 本金 × 年化利率（百分比换成比例）× 天数 ÷ 360，独立保留两位小数、四舍五入，利息尾差不跨期结转。应还 USD 合计 = 本金 + 利息；结算金额 = USD 合计 ÷ 报价锁定汇率 QT-04，还款不重取汇率。数币结算精度、最终舍入和尾差沿 Q-L8-04 / Q-CR-09 使用同一待批准表，不把原型两位或代币展示六位升级为资金结算规则。

<a id="L8-REV-03"></a>

**L8-REV-03 固定折算与金额同源（P05/P10）。** 本期平台固定 1 USD = 1 USDT = 1 USDC，QT-04 为 1；每期结算数值等于该期 USD 本息合计，单位为原 QT-02，不能把报价本金当成每期应还。例如一期应还 100.25 USD，结算为 100.25 个所选币种。报价锁定的汇率值、真实规则生效时间、来源说明、版本标识继续随本笔复用，规则生效与报价锁定时刻区分。还款不取外部行情、不设置汇率维护或人工改价、不让用户补填快照，不以本期固定规则追溯重写历史业务。固定比例不是外部兑换保证；完整本笔快照不因行情不可用失效。必要条款/金额依据缺失时说明暂不能核对，恢复真实资料后继续，不以固定“1”、旧笔快照或零金额猜补，不回退已成立债务。USD金额及逐期利息保留既定两位四舍五入、利息尾差不跨期结转；缩略展示不改变完整应付金额。

<a id="F-LS-63"></a>
#### 定稿后告知新旧安排（F-LS-63）

### 3.3 选期与还款提交

流程与状态：[L8-F02](02-还款计划与还款确认-流程图与状态机.md#l8-f02)、[L8-S01](02-还款计划与还款确认-流程图与状态机.md#l8-s01)。

<a id="F-LS-65"></a>
#### 定位最近应还期次（F-LS-65）

候选为资产方企业名下 S-RP-1 期次：全局待办可跨业务/项目；项目操作区及办理弹窗仅在所选业务内取候选。依次按应还日、LN-06 放款提交时间、FD-01、期次序号升序，第一条为默认项。逾期组在前，未到期组在后；禁止按“距离今天的绝对天数”排序。可以改选已开窗期次；未开窗期次可见但不可提交，注明开启日期。不要求先结清另一个已开窗期次才可选择当前期；所谓禁止跳期是不得越过开窗规则提交未来期次。

<a id="F-LS-66"></a>
#### 应还日开放录入（F-LS-66）

<a id="L8-REV-04"></a>

**L8-REV-04 还款录入开放（P08，修订 D-RP-26）。** 普通利息期和含本金末期均自应还日 00:00 UTC 开放，不提前三日开放；到期当日可以提交，次日未提交才逾期，逾期期次仍可录入。此前可只读查计划、金额及有权读取的收款资料，不开放还款信息编辑、凭证上传或提交；直达与旧通知同样受此限制。一次仅录入一期，不多选、不全选、不合并，金额币种只读，不出现“提前还本”“全部结清”动作。普通期及末期没有例外。

这里的“还款”仅登记用户已完成的付款信息，由资金方另行核实到账；不执行银行划款、钱包支付、扣款或签名，不因点击、上传或提交而表示真实付款成功。RM-05仍允许过去但不得未来的真实付款时刻，仅作对账，不能倒填来减免逾期或提前开放录入；本稿不据此新增提前结清、重算计息或平台控制线下支付的能力。应还临近通知仍可提前三日提醒准备，只读查看不授予录入权限，详见通知册 N-RP-R04。

<a id="F-LS-67"></a>
#### 填写并提交本期付款信息（F-LS-67）

还款办理步骤仅集中本期应还信息、期次选择、收款账户和填写项。四项不可省略：期次/应还日、USD 应还及结算金额、只读收款账户、逾期天数及提交即冻结提示。完整定稿计划及本息明细直接在立即还款弹窗默认折叠，原位展开可读，不提供跳转型“查看完整还款计划”按钮；其他业务的期次可返回清单换选业务或从控制台查看，不在本次选期中混列。注明平台仅登记还款，不代为转账；提交记录本身不收取 gas。

**还款记录字段。** 本笔已有且可复用的有效资料按L5 D-LS-61自动带入；平台尚不知道的本次实际还款时间、交易哈希及凭证由用户补充，不能拿旧交易值预填，可选材料和备注可留空。系统项只读。提交成功后全部记录不可修改或撤回。

异常：格式/大小/数量错误就地说明，保留其他已上传文件；未来还款时间拒绝；未开窗、非本人业务、期次已变更均不能提交。多人重复提交最多一条成功，后到者看到“该期已提交还款记录”及当前详情，不重复冻结或重新启动时限。链为 ETH 常量，原 E-RP-05“选错链”本期不可达，不为其设置选择或错误分支。

#### 交易哈希格式与自行查验（F-LS-69）

<a id="F-LS-78"></a>
#### 手续费告知与到账差额（F-LS-78）

跨境手续费由付款方承担，可能造成到账差额；还款和确认场景均保留手续费及差额告知，不预估手续费数字。本期应还仍为计划金额，资金方确认不以实收等于应还为前提；本模块不采集还款实收金额，不用放款时资产方实收 FD-39 参与任何还款计算。

<a id="f-overdue"></a>
### 3.4 逾期与提交保护

状态：[L8-S01](02-还款计划与还款确认-流程图与状态机.md#l8-s01)。

<a id="F-LS-70"></a>
#### 形成逾期标记（F-LS-70）

应还日次日 00:00 UTC 仍未成功提交，即标逾期；不设宽限期，首个逾期自然日为 1 天，之后逐日增加。迟于应到时点才完成判定时仍按应到时点计算，不能减免延迟期间天数，也不能重复提醒。逾期是期次和业务的并行标记，不替换“待还款”“还款中”状态。

<a id="F-LS-68"></a>
#### 提交后冻结本期逾期天数（F-LS-68）

成功提交时冻结本期期次逾期天数，此后不因资金方不确认继续增加，也不继续产生该期新增逾期通知。本期利息已在定稿时确定，应还金额不随提交或确认早晚变化。结清后保留历史逾期天数；另一未提交期次仍独立计逾期，不能因本期提交冻结整笔业务的所有期次。

还款性质在提交时依是否逾期，取“正常还款/逾期还款”；不得与“还款类型”混名。

<a id="L8-REV-05"></a>

**L8-REV-05 业务逾期标记（P09）。** FD-44 为真，当且仅当本业务存在“已发生逾期且尚未结清”的期次，包括逾期中的 S-RP-1 和逾期提交后天数被冻结的 S-RP-2。提交不清除业务标记；待确认显示该期已提交、冻结天数及仍未结清，不再冒充待资产方补交。相关逾期期次全部转 S-RP-3 时才清除当前业务整体标记；无需等尚未逾期的未来期次全部结清，历史逾期天数始终保留。若另一未提交期次随后逾期，按该期事实再次形成当前业务标记，不重发旧期通知。FD-44 的最早逾期期次、最长天数仅在当前未结清逾期期次中取值，包含冻结值；已结清历史另查，不混入当前集合。无当前集合时标记否、当前摘要为空，不能将历史天数归零。

不计算或展示罚息，不增加应还金额，不自动处置质押，不影响其他资金方授信。即使资金方线下主张凭证无效，本期也没有裁决和解冻回补路径。覆盖不足不阻断还款、确认或结清；项目“已到期 · 存量处理中”、逾期及确认超期按已批准约束中性呈现，不用告警色或警示图标。覆盖信息使用质押覆盖状态、覆盖有余/覆盖持平/覆盖不足、覆盖缺口及覆盖不足提醒。

<a id="f-confirm"></a>
### 3.5 还款确认与超期处理

流程：[L8-F02](02-还款计划与还款确认-流程图与状态机.md#l8-f02)。

<a id="F-LS-71"></a>
#### 核实到账并确认还款（F-LS-71）

资金方打开目标期次，核对金额、币种、只读收款账户、还款时间与平台提交时间、凭证或哈希及未核验提示、本期计划和冻结逾期天数。两个时间名称必须清楚，自填还款时间仅用于对账，时限从成功提交开始，不能从通知送达或首次查看开始。

**当前进度。** 对本业务双方明确展示“资产方提交还款 → 资金方确认到账”的本期期次进度、当前状态与处理方，不只展示金额或空白：

| 本期期次事实 | 进度及下一步信息 |
| --- | --- |
| 待还款 S-RP-1 | 资产方尚未成功提交；当前由资产方办理，资金方等待。尚无确认截止时点，不虚构已提交/确认时间 |
| 待还款确认 S-RP-2 | 资产方提交已完成，显示RM-06平台提交时间；资金方确认待完成，资金方见“轮到您确认”，资产方见“等待资金方确认”；显示确认截止RM-15及剩余时限 |
| 确认超期、仍S-RP-2 | 保留已提交完成、待资金方确认及超期时长，不显示已完成或自动结清；确认仍可办理 |
| 本期已结清 S-RP-3 | 两步均完成，显示真实确认时间RP-17/RM-18；该期无重复确认动作，其他期次未结清时整笔业务仍还款中 |

进度仅表达本期已发生事实，不用一笔的进度代替其他业务或全部期次。确认信息聚焦应还/结算金额与币种、期次/应还日、收款账户要点、付款时间及平台提交时间、凭证/哈希、冻结逾期天数和不可撤销告知；记录人员、重复商务条款等辅助内容留在只读详情。业务选择处的放款编号保留，不能因信息精简又失去同机构多笔识别。双方之外不展示私有处理进度和材料。组件和具体排列由Hallmark决定。

唯一业务动作“确认收到还款”。同一容器内最终二次确认说明：资金方已自行核实到账、平台未核验；确认不可撤销。含本金期次说明本次本金对应授信占用额会减少；只有该次操作会使全部期次结清时，才能同时提示“本笔融资业务将结清”，不能只凭“是最后日期的期次”作此承诺。

确认成功时，期次 S-RP-2 → S-RP-3、形成 RP-17/RM-18，同步累计已还本金/利息；按本期已偿本金同时减少项目融资余额和该资金方对该资产方的授信占用额。利息期本金为 0，两项均不变；末期减少本金而非本息合计；手续费不参与计量。同时按 §3.4 更新 FD-44；相关逾期期次未全部结清则保留，历史不删除。全部期次完成时按 §3.6 结清业务。

上述本地还款结果整体生效或整体不发生；确认失败保持待还款确认并允许再次办理，不出现“已结清但额度未减”。重复确认或操作时页面已过期，展示当前事实，不重复减少额度，不新增第二次结清结果。成功在本操作弹窗显示该期已确认结果并更新原清单/操作区；关闭回原位置，不自动打开详情或其他期次。

<a id="F-LS-72"></a>
#### 查看确认时限与超期后果（F-LS-72）

剩余还款确认时限平常精确到小时，不足 24 小时精确到分钟并加强提示；到期以 RM-15 为准，倒计时下限 0。到期前 24 小时提醒资金方；届满双方各一次超期通知，改为“已超过还款确认时限 N 天”的中性标记；不足完整 24 小时明确“已超过还款确认时限，不足1天”，此后显示完整经过天数，准确截止始终可查，不显示“0天”掩盖已超期。到期不改状态、不释放额度、不自动确认、不解冻资产方逾期天数、不关闭确认入口。

资金方始终不确认时，目标期次停在 S-RP-2，业务不能最终结清；该期本金若尚未确认，两项本金占用不减少，项目不能据此释放质押。页面和超期通知同时说明逾期天数已冻结、平台不自动或代为确认。双方线下沟通后，资金方仍回原入口确认，结果与未超期时一致。

<a id="F-LS-73"></a>
#### 确认超期后的线下联系（F-LS-73）

客服邮箱在还款确认办理步骤、还款详情、超期通知三处可见并可复制，附融资申请编号、融资业务编号、计划编号；共用平台既有邮箱，真实值待提供，不造地址。平台不承诺处理时限或结果。无申诉、驳回、部分确认、平台介入中、后台强制确认入口；不得引导未收到款项的资金方“先确认再说”。

### 3.6 业务结清及项目释放衔接

图：[L8-F03](02-还款计划与还款确认-流程图与状态机.md#l8-f03)、[L8-S02](02-还款计划与还款确认-流程图与状态机.md#l8-s02)、[L8-S03](02-还款计划与还款确认-流程图与状态机.md#l8-s03)。

<a id="F-LS-74"></a>
#### 全部期次结清后结束业务（F-LS-74）

**单笔业务结清。** 全部期次 S-RP-3 才使该业务 S-FD-6 → S-FD-8，记 FD-45；未偿本金为 0、该笔对应两项本金占用均归零、清除业务逾期标记，业务编号保留且不回收。不是资产方提交即结清，不是确认超期即结清，也不是末期期次单独结清就无视其他未结清期次。该需求的对外状态一直为“已放款”，不新增“已结清”需求状态或“已放款·逾期”拼接状态。

**项目层判断。** L8 将“该笔业务已结清”交给借贷平台 L5，由 L5 综合项目在途、其他未结清业务及项目到期/关闭条件判定。单笔业务结清只减少对应本金占用，不按“对应代币”部分释放。

| 项目情形（引用 L5） | 释放关系 |
| --- | --- |
| 项目未满足关闭/结清条件，即使一笔业务已结清 | 不以该笔结清触发整个池或所谓对应代币自动释放 |
| 项目到期且无在途、无未结清业务 | L5 判为 S-FP-5 已关闭，触发项目全部质押释放 |
| 项目到期仍有存量在途或未结清业务 | 不关闭，显示“已到期 · 存量处理中”；存量全部走完后 L5 判 S-FP-6 已结清，触发全部释放 |
| L5 已允许的主动关闭 | S-FP-1/S-FP-2 且无在途、无未结清业务，由 L5 关闭后触发全部释放；本模块不增设关闭按钮 |

<a id="L8-REL-01"></a>

**L8-REL-01 跨平台业务边界。** 释放的业务决策归借贷平台，代币相关执行由代币发行平台 T7 提供；借贷平台还款计划和结清事实不改由 T7 裁决。X-05 已定方向为借贷平台 → 代币发行平台；既定“同步发起 + 异步回调”作为三平台职责划分的依赖约束，本稿不扩写交互协议。

**业务释放与链上提取分开。** 以最新 [项目终态](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#project-state)及[自助提取规则](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#withdraw) 为准：项目进入 S-FP-5/S-FP-6 的同一时刻，借贷平台解除全部质押占用关系，代币置 PS-4“已释放 · 待提取”，即时、无链上动作、零费用。此业务时点已经确定，不因跨平台执行细节未完备而重新列为待裁定。链上提取另由资产方自助发起、代币发行平台执行，资产方自付 gas，可批量、无提取时限。

业务终态不依赖链上转回成功；未提取代币仍在合约内，不属于任何池，不计入覆盖，不能再次质押。提取失败不回退业务结清或恢复授信占用，仍可按 L5 提取规则办理。跨平台执行未知时，已确定的“业务已释放”与“尚未确认提取成功”可以同时呈现；请求受理、重复请求或项目终态均不等于链上转回成功。只依据真实执行结果显示已提取，不将未知自动当成失败或成功。

<a id="L8-REV-06"></a>

**L8-REV-06 执行异常仅联系客服（P03，承接 L5 D-LS-63）。** 长期无结果、跨期/项目终态、事实冲突、部分结果中未核实的笔，显示“执行结果待核实，请联系平台客服人员”，保留真实业务/代币标识、动作、已知结果和费用供核对。正常明确结果逐笔呈现，已知成功与待核实不得整批合并为成功或失败；客服联系不改变任何结果或恢复资格。未知不重试执行、不放开重押、不补有效覆盖，费用未知不填零；项目终态后结果迟到不恢复项目。正常明确失败的提取保留 PS-4 及既有办理条件；与结果未知分开。本期不建设工单、自动补偿、强制释放、人工改判/补记、异常退回或恢复资格流程。Q-L8-01只留真实执行结果、联系方式及跨平台核验依赖，

**重复释放反馈（已确认）。** 对同一项目、同一批已完成业务释放的代币再次发起释放，返回“已释放”，按成功事实反馈，不报操作失败，不再解除一次占用、不再次变更本金/额度，也不因此重复发起链上提取。仍在合约内时不能把“已释放”改写成“已提取”。若对象尚无已释放事实，不能用“重复请求”推断已释放；链上执行未知按本节联系客服，实际联验依赖见 Q-L8-01，不能用它覆盖本平台已经确定的业务释放事实。

**用户可见结果。** 业务结清展示业务本身的结清事实；项目与质押信息使用各自已确认结果。实际可提取时引导到 L5“解除质押”入口中“提取已释放”部分，显示可提取数量/金额与自付 gas 提示，不承诺自动回钱包。正常提取入口按 L5 已定条件开放；执行异常按本节客服边界处理；Q-L8-01为真实衔接核验依赖，不在还款确认步骤要求再次签名提取。

### 3.8 质量与业务约束

既有体验目标：打开还款容器至期次可选 ≤2 秒；还款提交和确认各 ≤2 秒；不超过 8 期的定稿计划生成 ≤2 秒。逾期判定延迟目标 ≤5 分钟；确认时限届满判定目标 ≤1 分钟、最坏 ≤5 分钟；两者都以应到时点生效，不能重复产生结果。

以上是原基线的借贷平台体验目标，不据此承诺跨平台 X-05 或链上提取完成时长。重要动作可追溯至业务、期次、动作人和时间，能够解释为何形成还款和额度结果；不在本稿展开内部记录格式或保留期限。
