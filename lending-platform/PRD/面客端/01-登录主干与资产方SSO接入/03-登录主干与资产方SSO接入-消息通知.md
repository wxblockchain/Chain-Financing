# 登录主干与资产方 SSO 接入 · 消息通知

2026-10-23｜需求评审稿


## 1. 本模块通知哪些关键节点

**本期只有一项：有效认证失效。** 资产方原已有效认证，本平台确认其有效认证失效时，向该资产方本人发一条强制站内信，规则见[有效认证失效](#event)。


第 3 节为配套文案，接入登记在文末按需展开，第 4 节为框架待比对项。

本册只定义通知的业务事实与信息需求；消息的呈现形式、入口位置与视觉由 Hallmark 设计决定。本文件独立属于登录主干与资产方 SSO 模块，不是全平台总册。本期仅站内信，不发邮件、短信、浏览器推送，不增加强制弹窗、声音或站外触达。触发依据见[主 PRD 的认证资格](./01-登录主干与资产方SSO接入-PRD.md#confirmed-downgrade)，验收见[关键站内信验收](04-登录主干与资产方SSO接入-验收.md#notification-acceptance)，流程见[认证失效通知流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-6)；上游登记地址变更的处理见[上游变更处理流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-7)。

站内信的列表、阅读与未读呈现依赖[面客消息中心](../10-面客消息中心/01-面客消息中心-PRD.md)；本期本平台记录认证失效的事件事实，消息中心接入后按本册规则呈现。

| 角色 / 场景 | 本模块是否通知及原因 |
| --- | --- |
| 受影响资产方本人 | 通知认证资格失效：影响发起融资申请资格，需要明确告知 |
| 资金方 | 无本模块独立事件；资金方账户及机构审核通知归资金方账户／机构审核模块，不能复制资产方事件或重复发送审核结果 |
| 运营管理人员 | 无本模块独立事件；借贷运营不审核上游资产方认证，未产生处理任务，不广播认证降级或 SSO 技术异常 |
| 初次或持续未认证、更新审核中但有效认证仍保留 | 不发，按当前资格展示引导；不能将申请进度当资格失效 |
| 钱包登录、角色自动判定、建号、退出/过期、资料刷新、偏好保存、受限点击 | 不发，原场景已有结果或引导，不新增未读干扰 |
| 调取不到该地址、调取失败、上游登记地址变更 | 均不发站内信：调取不到或失败就地说明，地址变更在调取发现时直接终止登录并提示重新登录 |
| 企业账户的新增、修改与删除 | 不属本模块事件；企业账户模块不发送任何消息通知（用户 2026-10-12 裁定账户变更不发通知），见[企业账户 PRD](../03-企业账户/01-企业账户-PRD.md#instant-change) |
| 调取失败或返回异常，资格缺失、未知或读取失败 | 不发认证失效通知，异常不等于确认被收回认证 |
| 认证通过或恢复；变化影响其他业务 | 不重复转发上游审核结果；对融资项目或其他角色的影响由相应业务模块判断并独立定义 |

## 2. 站内信的触发、接收与防干扰

<a id="event"></a>
### 2.1 有效认证失效

| 项目 | 业务规则 |
| --- | --- |
| 事件 | 资产方由有效已认证变为非已认证。须已有本平台账户、此前有效已认证，且本次取得上游明确有效综合结论；不按个人/企业子审核各发一条 |
| 发送时点 | 本平台确认并应用该次降级时产生，不等再次登录、点击受限操作或进入消息中心。若在下一个调取时点（登录成功后、资产方登录期间的 60 秒复核或关键动作前）才获知变化，届时发送，不虚构此前送达 |
| 收件人 | 被降级的本平台资产方账户。不能直接按钱包、邮箱、企业或上游原始账号归消息；同一人的资金方账户、同企业其他账户、运营均不接收 |
| 离线与失败 | 已有账户离线可产生消息，合法登录并满足当前访问条件后才能读。降级和业务限制不等待投递，失败不能回滚资格；补送仍是同一事件，不新增专属重试周期，消息可见时效沿消息中心 |
| 同次变化重复出现 | 重复告知、多标签、刷新、重登和补送均只一条；不改事件时间或排序、不置顶、不增加未读数、不将已读恢复未读 |
| 持续未认证 / 再次失效 | 不按天、登录或点击次数催促，不增加待办/倒计时。恢复有效认证后再次确认失效属于新事件，单独保留消息与已读状态 |
| 当前限制说明 | 既有降级说明解释当前限制，站内信记录历史事实；已读不代表认证完成，关闭该说明不删除消息 |
| 历史 | 无业务到期日，按消息中心保留规则保存；认证恢复不删除、不改写历史，读旧消息不再次降级，权限始终按当前状态 |
| 操作及异常 | “查看账户”到本平台“用户信息”，不自动出站或执行业务；前往上游仍经离站确认。映射缺失保留正文但隐藏跳转，不猜地址；登录失效或账户不可用不能被消息绕过 |

<a id="notification-preference"></a>
**通知偏好：** 本期唯一事件为认证与合规强制通知，任何当前/历史关闭值都不能屏蔽。默认开启政策只控制明确登记的可选事件；本模块可选事件为零，账户页显示“认证等关键通知始终接收”，没有可操作开关或假保存。不添加普通钱包登录、角色判定、资料刷新等事件制造开关用途。未来可选事件先在所属模块明确范围并完成登记；偏好变化不删除历史或改变已读状态。通知偏好规则已确认，真实接入仍须验证。

<a id="3-双语文案及接入登记"></a>
## 3. 双语文案

有效认证失效（已确认文案）：

| 内容 | 简体中文 | English |
| --- | --- | --- |
| 标题 | 实名认证状态已变更 | Verification status changed |
| 正文 | 你的实名认证状态已变更，本次变更使发起融资申请权限暂不可用。你仍可浏览平台。请前往资产可信平台查看当前认证状态。 | Your verification status changed. At the time of this change, access to submitting financing applications became unavailable. You can still browse the platform. Visit the Asset Trust Platform to check your current verification status. |
| 操作用语 | 查看账户 | View account |

中英正文动态变量均为空；时间和已读状态沿消息中心，不拼入未经确认的上游变更时间。标题/正文为纯文本，不带证件号、联系方式、钱包、材料或内部失败原因，不猜哪一项被驳回。历史消息按当前语言展示，翻译缺失按消息框架回落，不显示模板键。


## 4. 与消息框架的衔接

本册沿面客消息中心的单账户消息池、登记列与跳转降级，以及已有双语纯文本模板规范补齐本事件；管理端仍有独立消息池，不沿用旧端标识或页面号。来源编号及共享登记集中在文末。

| 承接范围 | 待比对内容 |
| --- | --- |
| 面客消息中心 | 最后核对本期唯一事件（EV-L20）的类型唯一性、分类、账户隔离、强制消息、模板与页面映射；登记成功不能代替真实投递、阅读权限和跳转联调 |
| 面客／管理端重复消息规则 | 已与[面客消息中心](../10-面客消息中心/01-面客消息中心-PRD.md)“同一件事只收一条”的规则一致：同一事实重试不新增、不再次提醒、不重新变为未读；新业务事实另记，不能覆盖历史 |
| 管理端消息中心 | 登记本模块无运营事件，不能因支持广播就复制资产方失效通知 |
| 资金方账户／机构审核模块 | 各自保留独立通知文件，按最新审核及账户规则确定发送归属，避免同一审核结果双发 |

上游真实有效结论、登记地址的控制权验证与按地址调取账户信息的接口、本人归属仍依赖主 PRD 中暂定的资产可信平台真实接入，见[真实接入核实项](./01-登录主干与资产方SSO接入-PRD.md#dependency-wallet)。模拟通知不能证明真实联调完成；失效通知的出现不能反过来作为业务资格依据。
