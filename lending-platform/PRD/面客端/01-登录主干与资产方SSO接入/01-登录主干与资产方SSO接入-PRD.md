# 登录主干与资产方 SSO 接入 · PRD

<a id="scope"></a>
## 1. 目标与阅读入口

用户先以游客浏览资产广场与借贷广场。**唯一的登录方式是连接钱包**：连接钱包、选择地址、完成消息签名，验证通过即登录成功。**登录成功不等于有角色**：本平台在每次登录成功后按固定顺序判定——**先查本平台是否已有该地址的资金方账户**；不是资金方时，**由本平台主动向资产可信平台调取该地址对应的账户信息**，调取到即为资产方并继续取其个人与企业信息，调取不到则为**登录未绑定角色**（业务上即“登录后的游客”）。角色判定与资料获取都由本平台发起调取，**不依赖上游主动推送**。
**一个完整的例子。** 游客在借贷广场触发需要资产方资格的动作，连接 MetaMask 并签名。平台先查询该地址是否已有资金方账户，未命中时向资产可信平台调取资料，确认其为已认证资产方后返回仍有效且本人有权访问的原目标；业务仍由本人继续办理。用户主动退出后回到游客浏览状态。


**用户注册与实名／企业认证在资产可信平台进行**，个人信息与企业信息也由该平台提供，本平台只读展示；本册所称“上游”均指资产可信平台。用户不选择角色，平台也不提供选择入口。

未绑定角色的用户触发业务动作时按动作归属分流：资产方动作引导前往资产可信平台完成注册与认证；资金方动作直接进入本平台的资金方入驻流程，**提交申请时**建立资金方账户。一个钱包地址只对应一个角色，换钱包视为全新用户。能否办理融资由当前有效认证决定；账户和企业资料来自上游，借贷平台只读展示本人资料。

**登录、角色、资料与业务资格是四件独立的事**：签名通过只代表登录成功；判定出角色不代表已认证；资料同步成功也不代表取得业务资格。

本期为桌面 Web，**登录钱包仅支持 Ethereum 链，钱包仅支持桌面浏览器中的 MetaMask 插件**。**登录所在链与质押链、结算收款链是不同用途的概念，互不决定**：质押链见融资需求与代币质押模块，结算收款链（当前仅 Ethereum）见[企业账户 PRD](../03-企业账户/01-企业账户-PRD.md#chains)。本文负责共用钱包登录、角色定义与判定、返回、共用资格状态与受限后的统一引导，以及资产方完整账户链路；**各功能按角色的可见与可用由所属业务模块在本模块 PRD 内定义，本文不维护统一权限矩阵**。资金方入驻表单、审核衔接和账户功能由资金方账户模块负责，收款／出资账户的字段、维护与权限由企业账户模块负责，本文只挂载入口。本期不增加移动端、资产方本地账号登录或本地实名认证。**本平台本期不签署任何协议**，详见[协议](#agreement)。

本模块共四册：本册定义功能与业务规则；[流程图与状态机](./02-登录主干与资产方SSO接入-流程图与状态机.md)、[消息通知](./03-登录主干与资产方SSO接入-消息通知.md)及[验收](./04-登录主干与资产方SSO接入-验收.md)配套阅读。编号沿用原值，缺号不代表遗漏。

## 2. 浏览、钱包登录与角色判定

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

### 2.1 游客浏览与唯一登录入口

<a id="F-L01"></a><a id="f-l01"></a>
游客访问默认入口或旧首页入口，进入既有资产广场。面客端各页面顶栏左侧的品牌图标进入首页，主导航不设“首页”菜单项；首页是面客端公开的平台介绍页，只做介绍和引导，不办理业务。首页、资产广场与借贷广场的游客可达内容直接可读，**不得因未登录而打断阅读**：不主动要求登录、不遮蔽可达内容、不设登录墙。未登录时登录入口持续可用，面客端各页面的登录入口按钮统一为“连接钱包”（Connect wallet），不使用“登录 / Sign in”；语言切换始终可用；不提供“申请入驻”入口。不可见页面按权限拒绝访问，不强制跳登录页。（F-L01）

<a id="F-L02"></a><a id="f-l02"></a>
只有两种操作发起登录：使用登录入口；触发可见但受限的业务动作，此时就地发起登录、说明被拦下的原操作并保留其意图，用户取消后仍留在原处。两者使用同一条钱包登录路径，**登录前后都不要求用户选择身份**。（F-L02）

| 步骤 | 用户可见结果 |
| --- | --- |
| 发起登录 | 唤起钱包前须先让用户知道本次将连接钱包并请求一次登录签名、签名不涉及转账或资金授权；不插入账号密码、邮箱、验证码等其他登录方式 |
| 连接钱包并选择地址 | 用户在钱包内选择本次登录使用的地址；地址只来自钱包，不提供手填；仅取得地址**不等于登录成功**，不建号、不判定角色。钱包须处于 Ethereum 网络，否则按[网络不是 Ethereum](#unsupported-network)处理 |
| 消息签名 | 选定地址后即请求登录签名，不另设签名前的确认步骤；签名时可核对本次登录地址全文；用户在钱包内确认签名，本平台验证签名通过才建立登录，以此确认登录者控制该地址。签名须满足[登录签名规则](#signature-rules) |
| 登录成功 | 签名验证通过后立即按[登录后的角色判定](#F-L34)判定角色，再到相应落点；调取不到时为登录未绑定角色；判定所需的上游调取失败时本次登录不成立，按该判定的第 ④ 行处理 |

登录不采集邮箱、手机号或其他联系方式，也**不得输入邮箱后自动识别角色**：这会泄露账户是否存在。**一个钱包地址只对应一个角色**，同一钱包不能同时是资金方和资产方，见[账户识别与匹配](#F-L22)。本期只支持 Ethereum 链钱包，其他链的钱包不在本期范围。

<a id="signature-rules"></a>
**登录签名规则**：

- 签名用途：唤起钱包前，本平台先在页面说明本次将请求一次登录签名、不涉及转账或资金授权，不能只由钱包自身的提示承担，用语见[登录与分流文案](#draft-copy)。钱包内签名消息的用途声明为：
  > 签署这条消息只用于证明你拥有该钱包。它不会发起交易、不消耗 gas，也不会转移或授权任何资产。
  >
  > Signing this message proves you own this wallet. It does not send a transaction, does not cost gas, and does not move or approve any assets.
- 有效期与单次使用：每个签名请求只能成功使用一次，有效期 **5 分钟**；已使用或已过期的签名被拒绝、不建立登录，平台准备新的签名请求，由用户重新签名，不替用户签署。硬件钱包确认较慢时，页面不得早于 5 分钟自行判定超时。
- 身份与网络一致：签名地址必须与本次连接的地址一致，签名使用的网络必须是 Ethereum；由平台校验，不能只靠界面限制。签名请求由平台提供并校验（既定签名安全约束，库外依赖，待补充；实现与验证归研发、测试）。
- 失败不锁账户与防滥用：签名失败不累计锁定次数、不锁定任何账户；同一 IP **1 小时内验签失败超过 20 次后降速**，不封禁 IP，不连带锁定账户。
- 签名前不展示凭据保管提示：登录签名发生在角色判定之前，“该钱包是你唯一的登录方式，绑定后不可更换”这一凭据保管提示只在资金方入驻流程与资金方用户信息中展示，见资金方账户 PRD 的[凭据保管提示（F-L76）](../02-资金方登录与账户体系/01-资金方登录与账户体系-PRD.md#F-L76)。
- 签名失败、地址不一致、请求过期与网络不支持的用户可见结果见[取消、不可用与更换钱包](#F-L03)。

<a id="F-L03"></a><a id="f-l03"></a>
### 2.2 取消、不可用与更换钱包

钱包登录过程中的取消与异常按下表处理。（F-L03）

| 分支 | 用户可见结果与可继续操作 |
| --- | --- |
| 无可用钱包或钱包无法唤起 | 就地说明原因并给实际可执行的下一步（安装或启用 MetaMask 后重试）；可继续游客浏览，不把用户带到只有报错的结果，也不提供邮箱等替代登录方式 |
| 钱包连接取消、钱包已锁定或连接未成功 | 回到发起登录的原处，说明原因（钱包已锁定时提示先解锁），登录入口仍可用，可重新连接；不停留在无内容或无出口的中间状态 |
| <a id="unsupported-network"></a>钱包网络不是 Ethereum | 提示在钱包中切换到 Ethereum 网络后重试，可重新连接或继续游客浏览；不建立登录、不判定角色。绕过界面以其他网络签名同样不能登录 |
| 拒绝签名、签名验证失败或签名地址与连接地址不一致 | 不建立登录、不建号、不判定角色、不提前披露该地址在本平台是否已有账户；就地可重试或继续游客浏览 |
| 签名请求已过期或已使用 | 拒绝该签名、不建立登录；平台准备新的签名请求，提示用户重新签名，见[登录签名规则](#signature-rules) |
| <a id="signature-switched"></a>签名过程中钱包切换了地址 | 中止本次登录并说明钱包地址已变化，提供“用该地址重新登录”：以新地址重新签名并按判定顺序判定；不静默改用新地址，也不让新地址沿用原地址的签名 |
| 登录成功后希望更换钱包 | 登录状态下不提供“切换钱包”入口，账户内也没有“更换钱包”功能；需要换钱包时先退出再用另一钱包登录 |
| <a id="wallet-account-switched"></a>登录期间钱包插件切换了账户 | 平台提示当前钱包账户与本次登录地址不一致，并提供“用该地址重新登录”：选择后先结束当前登录，再以该地址发起新的登录（重新签名并按判定顺序重新判定）。不自动改用新地址，也不让新地址沿用当前登录的角色或资料；用户未选择前，本次登录仍对应原登录地址 |
| <a id="new-wallet-new-user"></a>改用另一个钱包 | **换钱包视为全新用户**：新地址按判定顺序重新判定，不从旧地址继承角色、资料、业务记录或权限。新地址调取到同一上游稳定账户时按[稳定标识认人](#F-L22)接续原账户与历史；调取不到则为登录未绑定角色 |
| <a id="wrong-upstream-account"></a>在上游建立了不该建的账号 | 本平台不能撤销该上游账号，也不提供清理上游账号入口；以引导说明帮助用户在上游正确处理 |

<a id="ownership-signature"></a>
**例外：为登记数币地址发起的一次性签名不是登录。** 在[企业账户](../03-企业账户/01-企业账户-PRD.md#ownership-signature)登记数币地址时，用户会用**被登记的那个地址**签名一次以证明其所有权。该签名**不建立登录会话、不切换登录钱包、不参与登录地址匹配、不改变本次判定的角色，也不改变登录地址**；被登记地址可以与当前登录地址不同，也可以在另一条结算收款链上。本节“登录状态下不提供切换钱包入口”“换钱包视为全新用户”只针对建立登录身份的签名，不适用于该一次性签名。

<a id="console-role"></a>
### 2.3 登录后的角色判定与未绑定角色

<a id="F-L34"></a><a id="f-l34"></a>
**角色由系统自动判定，平台不提供选择角色的入口；本平台不保存“地址 ↔ 角色”的绑定关系，每次登录都重新判定**（2026-10-08 裁定）。判定顺序如下，顺序不可调换：（F-L34）

| 次序 | 判定 | 结果 |
| --- | --- | --- |
| ① | 本平台是否已有该登录地址的**资金方账户**（在提交入驻申请时建立） | 有即本次会话为资金方角色，**不再向上游调取**，按资金方账户模块承接；该资金方账户已停用时本次登录不成立，见资金方账户 PRD 的[签名后发现账户已停用](../02-资金方登录与账户体系/01-资金方登录与账户体系-PRD.md#disabled-at-login)。**一个地址只对应一个角色**，不因上游也登记了该地址而改判，见[禁止并存](#role-exclusive) |
| ② | 不是资金方时，**本平台主动向资产可信平台调取该地址对应的账户信息** | 调取到即本次会话为资产方：按上游稳定标识复用或建立本平台资产方账户，并继续调取其个人信息、企业信息与当前认证结论 |
| ③ | 调取不到该地址对应的上游账户（**含上游未登记该地址**，按没有账户处理） | 本次会话为**登录未绑定角色**（业务上即“登录后的游客”）；用户在上游完成注册并登记该地址后，下一次登录即判定为资产方 |
| ④ | 调取失败（上游不可用、超时、返回不可用） | **不等于调取不到**：登录时调取失败则**本次登录不成立**，仍为游客，不判定角色、不开放任何角色功能，就地说明“暂时无法确认身份，请重试”；用户可重试登录或继续浏览游客可达内容，重试成功后按 ①～③ 判定。登录期间（60 秒复核或关键动作前）调取失败，不改变本次已判定的角色与已取得资料，但关键动作不放行 |

角色是**本次会话的判定结果**，不作为账户上的长期属性保存，也没有“绑定状态”这类需要维护的字段。本平台账户仍然存在并承载资料、历史与消息归属：资产方账户以上游稳定账户标识为主体，不记录登录地址；资金方账户在提交入驻申请时建立，提交时的登录地址作为该账户唯一且不可修改的登录地址保存（判定顺序 ① 据此查找），这是账户属性而非绑定状态，没有解绑或换绑。判定不依赖浏览器本地记忆，隐私模式或禁用本地存储不影响。

<a id="role-exclusive"></a>
**禁止并存**：一个钱包地址只会对应一个角色。该地址已有本平台资金方账户时按判定顺序 ① 进入资金方、不向上游调取，因此**不改判为资产方、不同时开放两种角色**，登录时也不核对或提示上游是否登记了同一地址。冲突在提交资金方入驻时拦截：已在资产可信平台登记的地址不能提交资金方入驻，见资金方账户 PRD 的[钱包与邮箱唯一性（F-L77）](../02-资金方登录与账户体系/01-资金方登录与账户体系-PRD.md#F-L77)。已是资金方的地址此后才在上游登记的，本期无法发现，该地址仍按资金方登录，见[已知并接受的取舍](#accepted-tradeoff)。不自动转换、不合并、不新建第二个账户。用户需要另一角色时以另一个地址重新入驻，两个账户彼此独立、资料与历史互不可见。

| 当前角色 | 可用范围 |
| --- | --- |
| 登录未绑定角色 | 可浏览资产广场与借贷广场的可达内容，可退出。**我的控制台、个人信息、企业信息、机构信息一律不展示**，也不产生站内信；触发业务动作时按下表分流 |
| 判定为资产方 | 按认证结论使用资产方业务，资料只读，见[本人账户、企业信息与偏好](#profiles) |
| 判定为资金方 | 由资金方账户模块承接入驻与账户功能，本文只定义共用登录、返回与资格口径 |

<a id="action-routing"></a>
未绑定角色的用户触发业务动作时，按**动作归属**分流，不要求用户先选角色：

| 触发的动作 | 结果 |
| --- | --- |
| 资产方动作（如发起融资申请、关联应收账款） | 引导前往资产可信平台完成注册与认证；离站前按[离站确认](#leave-confirm)告知目标平台。在上游完成注册并登记该地址后须重新登录，调取到即判定为资产方 |
| 资金方动作（如发起出资、授信报价） | 直接进入本平台的资金方入驻流程；**提交申请时**建立资金方账户：提交成功后本次登录直接以资金方继续，登录有效期自提交成功时起重新计算 4 小时（见[登录有效期](#session-period)）；此后该地址的登录按判定顺序 ① 判为资金方，具体表单与提交规则见[资金方账户 PRD](../02-资金方登录与账户体系/01-资金方登录与账户体系-PRD.md) |
| 两类角色都不适用的受限内容 | 按[受限后的下一步](#guidance)给对应说明，不引导取得任何角色 |

判定与账户建立都不向用户额外说明后果，也不要求用户确认“提交即成为资金方”。

<a id="role-memory"></a>

<a id="role-change"></a>

## 3. 上游同步、地址匹配与账户建立

### 3.1 同一套匹配判定

<a id="F-L25"></a><a id="f-l25"></a>

<a id="F-L20"></a><a id="f-l20"></a>

<a id="F-L21"></a><a id="f-l21"></a>

### 3.2 账户识别与调取结果

<a id="F-L22"></a><a id="f-l22"></a>
**上游稳定、不可变的账户标识是本平台资产方账户的主体**；**钱包地址是调取入口与登录凭据，不是账户主体，也不被本平台保存为绑定关系**。首次调取到即建立本平台账户，后续按稳定标识复用；同一上游账户更换登记地址不产生新账户、不拆分历史。邮箱、企业标识都不用于认人或合并账户。稳定标识缺失的数据不能用于建立账户。**一个钱包地址只对应一个角色，禁止并存**，见[禁止并存](#role-exclusive)。（F-L22）

| 结果 | 调取结果与用户可见处理 |
| --- | --- |
| <a id="account-success"></a>调取到且上游账户可用 | 按上游稳定标识建立或复用本平台资产方账户，取得获准资料与当前认证结论，本次会话进入资产方角色 |
| <a id="account-unavailable"></a>调取到但上游账户锁定或禁用 | 不判定为资产方，结束该主体已有的本平台登录；就地回游客视图，显示实际可取得的解除信息，不捏造 |
| 调取不到该地址对应的账户（含上游未登记该地址） | 本次会话为登录未绑定角色（“登录后的游客”），可继续浏览或按[动作分流](#action-routing)办理；不提示该地址是否曾经存在于上游，也不在本平台补录地址 |
| 调取失败、超时或上游不可用 | 不等于“调取不到”：登录时失败则本次登录不成立，就地说明“暂时无法确认身份，请重试”，可重试或继续游客浏览；登录期间已判定成功后失败，保持本次判定结果与已取得资料，关键动作不放行 |
| 以旧地址登录（上游已把登记地址改为其他地址） | 与调取不到相同：本次为登录未绑定角色，不提示“请使用新地址”，也不提示该地址曾属于某上游账户 |
| 调取到但本平台账户建立失败 | 唯一需要用户单独处理的失败结果“建号失败”：同时给出错误码、重试和继续浏览两条出路；不得静默返回或留下无出口的结果 |

<a id="F-L35"></a><a id="f-l35"></a>
<a id="binding-check"></a>
**本平台先查资金方、再按地址向上游调取**（顺序见[角色判定](#F-L34)）；**调取的业务结果只有两种：调取到与调取不到**；调取失败按[角色判定](#F-L34)第 ④ 行处理，一个地址调取到多个账户按数据异常处理，二者都不并入这两种结果。本平台不保存地址与资产方账户的绑定关系，因此没有“绑定状态”“解绑”“换绑”这类概念。（F-L35）

| 调取情况 | 业务处理 |
| --- | --- |
| 调取到：以登录地址向上游调取到唯一账户 | 本次会话判定为该上游稳定账户的资产方，并继续调取个人信息、企业信息与当前认证结论 |
| 调取不到（含上游未登记该地址，或上游已把登记地址改为其他地址） | 本次会话为登录未绑定角色，不猜测、不按邮箱或企业名称近似匹配、不自动接管任何历史账户，也不提示该地址曾属于某账户 |
| 数据异常：一个地址调取到多个上游账户 | 业务上不存在该情况；一旦出现按数据异常处理：不判定角色、不取其中任一条，产生告警并就地给中性说明 |

<a id="address-normalize"></a>
**比较口径**：登录地址本期只比较 Ethereum 链地址（企业账户登记的数币地址按结算收款链另行校验，不参与登录判定与调取）。同一地址的不同书写形式（checksum 大小写差异、带与不带 `0x` 前缀等）必须视为同一地址；上游登记的地址不属于本期支持的链或格式时无法比较，按未命中处理并产生告警。规范化的具体实现由开发完成，产品只要求上述业务结果。

<a id="binding-cardinality"></a>
**账户归属与地址的关系**：资产方账户归属只由上游稳定标识决定，本平台不维护地址与资产方账户的绑定，因此没有绑定基数或旧绑定失效的概念；资金方账户的登录地址是唯一且不可修改的账户属性，见[角色判定](#F-L34)。上游把登记地址改为新地址后：用旧地址进行中的登录在下一个调取时点被发现并立即结束；用户以新地址登录即调取到同一稳定标识、接续原账户与历史；此后以旧地址登录按调取不到处理，为登录未绑定角色，不提示“请使用新地址”，见[上游登记钱包地址变更](#wallet-change)。一个地址在任一时刻只对应一个角色，见[禁止并存](#role-exclusive)。

<a id="binding-login"></a>
**身份可信性**：上游在登记钱包地址时已验证登记人控制该地址，本平台在登录时以消息签名验证控制权；两端验证的是同一地址的控制权，因此调取到即可判定身份，不再要求用户另做一次授权确认；**授权环节在资产可信平台完成，不在借贷平台进行**。上游的这项验证能力属接入前必须核实的事项，见[真实接入核实项](#dependency-wallet)。

<a id="F-L24"></a><a id="f-l24"></a>
所有失败不暴露内部判定原因。数据来源不可信、缺少稳定标识、一个地址命中多个账户等配置或数据异常须产生运维告警；这不是向运营人员发站内信。**建号失败是唯一需要用户单独处理的失败结果**，其余失败就地说明并保留可继续的出口。恢复原页不代表可以继续读取其受保护内容。（F-L24）

## 4. 登录后回到原页面与原操作

### 4.1 返回顺序与失败结果

<a id="F-L04"></a><a id="f-l04"></a>
登录前保留原页面、被拦下的操作及目标平台；主动登录没有原业务动作。**钱包签名成功后立即按[角色判定顺序](#F-L34)执行**（先查本平台资金方、再向上游调取）：判定为资产方或资金方即以该角色回原目标；调取不到则保持登录未绑定角色，原操作意图仍保留，触发时按[动作分流](#action-routing)办理——资产方动作引导去上游注册认证，资金方动作进入入驻流程；调取失败则本次登录不成立，回发起处并可重试。有有效目标则返回，无目标则进入资产广场。（F-L04）

<a id="return-permission"></a>
回到原触发点时重新判断当前权限：允许才恢复操作，仍受限则展示对应引导（未绑定角色按动作归属分流，已判定角色但未认证给认证引导）；不能把登录成功当作已取得角色或融资/出资已成功，也不能重复创建业务。返回规则由本章统一定义，两类角色及各业务共用，不再各写一套。

<a id="return-lifetime"></a>
返回信息只用于本次登录，有效期默认 **30 分钟（可配置）**且只能成功使用一次；完成、放弃或登录结束后失效。不能被其他会话、设备冒用；实际切换角色须重新判定。用户可见或可复制的登录信息不暴露可冒用的返回内容或凭据。

<a id="F-L07"></a><a id="f-l07"></a>
无效、过期或不允许的目标，统一回资产广场并给中性提示，不白屏、不展示内部拒绝原因；过期可提示“链接已失效，已为你回到资产广场”，其他拒绝只说明“已为你回到资产广场”。正常默认进入和取消登录恢复浏览不伪报失败。重复使用、跨会话冒用等安全异常须可追溯。（F-L07）

| --- | --- |
| <a id="allowed-pages"></a>站内业务页 | 仅面客端已登记业务范围；允许前缀暂按 `/`（资产广场）、`/assets`、`/financing`、`/funding`、`/console`、`/onboarding`、`/account`、`/messages`、`/about`、`/faq`、`/agreement`，字面路径仍待页面登记对齐。`/` 只指默认页，不代表全部路径 |

## 5. 当前资格、业务权限归属与受限引导

<a id="state-contract"></a>
<a id="F-L11"></a><a id="f-l11"></a>
### 5.1 登录、角色与认证分别判断

**角色与认证是两条独立的轴。** 角色共四种取值：游客、登录未绑定角色、登录判定为资产方、登录判定为资金方；认证结论另行判断，同一角色下可以已认证或未认证。签名通过并完成角色判定才建立登录；登录有效不代表已判定角色，已判定角色不代表认证有效；认证仍有效但登录已失效时仍是游客。登录时上游调取失败则本次登录不成立、仍为游客，不另设状态。本期没有协议受限登录态。（F-L11）

| 状态信息 | 业务含义与默认 |
| --- | --- |
| 是否登录 | 必须明确；由钱包签名验证结果决定，默认游客 |
| 当前角色 | 资产方或资金方。游客必须为空；**已登录时可以为空，表示登录未绑定角色**，此时按[登录后的角色判定与未绑定角色](#F-L34)的范围使用平台。角色只能来自地址匹配命中（资产方）或提交入驻申请（资金方），**不由用户选择，也不从邮箱或企业名称推断** |
| 当前业务资格 | 必须明确；默认未取得有效认证，由服务端权威判定。未绑定角色时恒为未取得资格 |
| 当前账户 | 本平台本人账户标识；游客为空，登录未绑定角色时也为空（资产方账户在匹配命中时建立，资金方账户在提交入驻申请时建立），不用钱包或企业标识替代 |
| 角色判定结果 | 每次登录成功后由[判定顺序](#F-L34)得出，只在本次会话内有效，不作为账户属性保存；没有“绑定状态”字段；资金方账户的唯一登录地址是账户属性，不是绑定状态。原“钱包地址绑定”“钱包待重新确认”取值均已停用 |

<a id="whole-state"></a>
以上状态整体取用，所有业务使用同一套状态，不各自读取原始审核状态猜资格；客户端伪造角色或资格不能放行。判定存在冲突时采用较低有效资格，不能据单个较高结果越权。

| 资格阶段 | 资产方 | 资金方的共用语义 |
| --- | --- | --- |
| 未绑定角色 | 登录未绑定角色，两类角色的业务均不开放；只能浏览可达内容、按动作分流办理或退出 | 同左 |
| 未完成认证 | 未取得当前有效已认证结论，按已登录未激活处理 | 不适用：未提交入驻申请时尚无资金方账户，按登录未绑定角色处理 |
| 审核中 | 不适用；异常出现时按未完成认证并记录异常 | 待审核，机构资料锁定，不允许编辑或撤回；仍为已登录未激活 |
| 已驳回 | 不适用；异常出现时按未完成认证并记录异常 | 可按所属模块规则修改重提；仍为已登录未激活 |
| 已认证 | 上游确认当前有效已认证，按已登录已激活处理 | 已认证，按已登录已激活处理 |

<a id="funder-visibility"></a>
资金方审核中、已驳回的信息可见范围一致，差异在提示与可执行动作；尚未提交入驻申请的用户没有资金方账户，按登录未绑定角色处理；账户联系方式与机构资料是不同功能，不把审核中机构资料锁定扩大成所有账户操作锁定。详细行为见[资金方账户 PRD](../02-资金方登录与账户体系/01-资金方登录与账户体系-PRD.md)。需要核对已有状态代码和字段名时，查[文末对照](#state-contract)。

### 5.2 认证更新与发起融资

<a id="F-L29"></a><a id="f-l29"></a>
资产可信平台是认证权威，本平台只读，不自建审核、修改或拼装认证结论。**只认当前有效综合认证结论**；个人或企业单项通过、资料齐全、申请审核进度都不能代替它。更新审核中仍保留有效认证时不自行降级；失效或驳回后的有效资格同样以上游结论为准。未知取值按未认证处理并告警，不猜测新状态。（F-L29）

<a id="qualification-refresh"></a>
调取到账户时取得当前结论；此后按[上游变更的同步](#F-L36)的调取时点更新：资产方登录期间距上次调取超过 60 秒后的下一次请求前复核，关键动作前实时确认。本期没有上游推送，结论的更新完全依赖本平台调取。读取失败可沿旧快照继续浏览，但不能当作已经确认新资格，也不能误报“认证被收回”。已是资产方的用户在上游完成或变更认证后无需退出重登，在下一个调取时点生效；登录未绑定角色的用户在上游完成注册后，须重新登录才判定为资产方。

<a id="F-L31"></a><a id="f-l31"></a>
资产方**发起融资申请**前必须实时确认资格，旧的已认证快照不能放行；同一判定点一并重新调取并核对账户可用性与登记地址，发现登记地址已变更即结束登录，见[上游登记钱包地址变更](#wallet-change)。等待时显示“正在确认资格”，不重复发起；无法确认则说明申请尚未发起并可重试。未认证时显示认证引导，即使绕过界面发起请求也不创建融资申请。其他业务动作是否要求资产方已认证、是否需要在动作前实时确认，由所属业务模块定义；需要实时确认时沿用本条的确认、等待与失败结果。（F-L31）

<a id="qualification-late"></a>
等待中发生认证降级、退出、过期、换角色或离开页面，迟到的通过结果不能恢复旧权限、显示操作成功或把用户拉回旧流程。仍在原页且已降级时给认证引导；重新进入后重新判断。此等待不是新账户状态，也不定义融资提交自身的结果。

<a id="confirmed-downgrade"></a>
确认由有效已认证降为非已认证时，及时降低权限，下次进入明确解释当前限制，并向受影响的资产方本人发送一条强制站内信；发送时点、去重与文案统一见[通知册](./03-登录主干与资产方SSO接入-消息通知.md#event)。不因消息投递失败保留已失效权限。见[认证资格与融资流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-4)。

### 5.3 业务权限的归属与共同底线

各功能按角色的可见与可用，由该功能所属的业务模块在本模块 PRD 内定义；本主干不维护统一权限矩阵，也不为其他模块的功能填写或审定取值。主干只提供各模块共用的角色及其判定（见[登录后的角色判定与未绑定角色](#F-L34)）、共用资格状态（见[登录、角色与认证分别判断](#F-L11)）和[受限后的下一步](#guidance)。各模块定义权限时遵守以下底线：（F-L10）

- 受限（能看到、能触达但不能办理）与不可见都由服务端拒绝：绕过界面读取或操作时同样不返回数据、不执行业务，不能只靠界面隐藏。
- 入口可见但能力受限时，触达须给出[受限后的下一步](#guidance)的引导，受限原因对辅助技术可得，不出现毫无反馈的不可用入口。
- 本人账户资料（个人信息、企业信息、机构资料）只对本人开放；业务模块只展示办理所需的必要字段，不借业务权限开放整份资料、个人证件或认证材料，也不先把敏感原文交给无权用户再遮盖。

<a id="guidance"></a>
### 5.4 受限后的下一步

<a id="F-L08"></a><a id="f-l08"></a>
共用引导的行为由本主干统一定义，具体业务文案由所属模块提供。游客触发受限能力打开钱包登录；登录未绑定角色时按[动作归属分流](#action-routing)——资产方动作引导去上游注册认证，资金方动作进入入驻流程；已判定角色但未满足资格时打开认证/补全引导。引导说明“缺什么、补完能做什么、去哪里补”，适用时补充审核状态或驳回说明，不只写“无权限”“请先登录”。关闭不改变任何账户状态；前往补齐须保留原操作，跨平台先离站确认，返回仍按第 4 章。（F-L08）

<a id="F-L30"></a><a id="f-l30"></a>
登录未绑定角色的用户仍可浏览资产广场与借贷广场的可达内容，不全局封锁；引导按动作归属给出，不要求也不提供选择角色的入口。未认证资产方仍可浏览可达业务、本人账户、企业信息和消息，不全局封锁。尚未提交资金方入驻申请的用户按登录未绑定角色处理，资金方动作进入入驻流程；资金方审核中只读展示审核状态及真实可用辅助信息，不暗示修改/撤回、不捏造时长或客服渠道；已驳回时指向查看原因并修改重提。审核说明引用资金方账户／机构审核模块当前已确认内容，不另规定字段级驳回模型。（F-L30）

<a id="F-L09"></a><a id="f-l09"></a>
已登录存在待补齐事项时，平台须持续提醒该事项，且**不因用户阅读正文而丢失、也不遮蔽正文**；用户可在本次会话内暂时收起，但不能永久关闭，事项完成即消失。原“钱包待重新确认”常驻提醒项与“未选择角色”项**均已停用**。同一时刻只呈现优先级最高的一项，其余以“还有 N 项待完成”可展开查看；优先级为已驳回→未认证→审核中→降级说明，最高项完成后下一项接替。用户处理某一事项期间，仍能看到自己原来在做什么，取消离站可回到原处。游客不适用此提醒。本册只定义触发、展示条件与解除条件，呈现形式由设计决定。（F-L09）

## 6. 本人账户、企业信息与偏好

### 6.1 进入与只读边界

<a id="F-L32"></a><a id="f-l32"></a>
登录后须持续可见一个账户入口，展示**本次登录钱包地址**的可辨识标识：缩略展示时须保留大小写且完整地址可核对，地址本身足够短时完整展示。该地址来自本次已验证的登录凭据而非上游快照，异常读取不到时显示“我的账户”，不使用假地址、不阻断登录。账户入口下可用的事项：判定为资产方时显示当前角色“资产方”，菜单固定为**四项并列**——“用户信息”“企业信息”“企业账户”“消息中心”（第三项在资金方侧显示为“机构账户”，见[账户菜单](#account-menu)），外加**全平台唯一的主动退出入口**；**登录未绑定角色时只有登录地址标识与退出**，四项一律不展示。（F-L32）

<a id="account-menu"></a>
**账户菜单的四项与两侧命名（2026-10-09 裁定）**：

| 菜单项 | 资产方 | 资金方 | 内容归属 |
| --- | --- | --- | --- |
| 第一项 | 用户信息 | 用户信息 | 本人账户信息、个人信息与偏好 |
| 第二项 | 企业信息 | 机构信息 | **按各自字段体系命名**：资产方展示资产可信平台同步的企业资料（企业名称、企业 id 等）；资金方展示机构认证资料与申请进度（机构名称、机构唯一标识等，主定义在机构认证审核册）。两侧位置相同、内容各按本册与资金方册定义 |
| 第三项 | **企业账户** | **机构账户** | 同一入口、同一套字段与规则；**字段与模块口径统一为“企业账户”，面客展示名按侧区分**（2026-10-09 裁定）。字段与维护归[企业账户 PRD](../03-企业账户/01-企业账户-PRD.md) |
| 第四项 | 消息中心 | 消息中心 | 入口挂在账户菜单，功能、事件与归属仍由面客消息中心模块承接，本册不重复定义 |

第二项与第三项都不强行统一为一个词，但口径不同：第二项是两侧各自的信息域，内容本就不同；**第三项是同一个模块、同一套字段，只有展示名按侧区分**——字段名、模块名、跨册引用与验收一律写“企业账户”，面客端资产方侧显示“企业账户”、资金方侧显示“机构账户”。研发与测试按“企业账户”理解数据与接口，按本表核对界面文字。

<a id="enterprise-account-entry"></a>
**企业账户入口**：账户菜单第三项，**资产方侧显示“企业账户”、资金方侧显示“机构账户”**，两侧是同一入口、同一套账户类型、字段与维护动作，用于维护法币与数币收款／出资账户；资金方侧的入口同样挂在账号菜单，其“用户信息”不登记该入口，衔接口径由[资金方账户 PRD](../02-资金方登录与账户体系/01-资金方登录与账户体系-PRD.md#enterprise-account)承接。未认证的资产方与资金方仍可见、可触达该入口并得到补齐引导，各身份的权限见企业账户的[谁能使用（P-EA-01）](../03-企业账户/01-企业账户-PRD.md#p-ea-01)。“用户信息”继续只管登录钱包只读信息、联系邮箱与偏好，**不把法币账户与数币账户字段混入“用户信息”**；字段定义、校验与维护规则全部归[企业账户 PRD](../03-企业账户/01-企业账户-PRD.md)。

“用户信息”可独立访问并可返回原处，包含账户信息、个人信息及偏好三组内容且彼此可区分；本次登录钱包地址按[详情中的钱包地址（F-WA-01）](../../00-钱包地址展示.md#F-WA-01)完整展示并可复制，邮箱全文可核对。

<a id="F-L33"></a><a id="f-l33"></a>
企业信息是账户菜单的第二项、独立于“用户信息”，可直接访问并可回到原业务浏览入口；资产方侧名称用“企业信息”（资金方侧同位置为“机构信息”，见[账户菜单](#account-menu)），“用户信息”内不重复整套企业资料。（F-L33）

<a id="read-only-profile"></a>
只读资料统一说明“这些信息由资产可信平台维护”。**本平台不提供前往上游查看或修改资料的跳转入口**（2026-10-08 裁定）：不提供任何编辑入口（包括不可用状态的编辑入口）、不提供资料类的离站跳转、不做本地资料录入、提交审核、材料上传/预览/下载或本地企业切换、成员管理。实名认证引导（“前往完成认证”）不属于资料修改入口，继续保留。绕过界面的资料修改同样拒绝。上游表单必填不等于借贷端要求补填。未认证者仍有前往完成认证入口，资料已存在不代表已认证。

“用户信息”中不展示登录状态、不提供第二个退出入口、不要求手动保存偏好，也不展示内部编号或规则论证。语言偏好可写，须与上游只读资料可区分。流程见[资料与偏好流程](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-5)。

<a id="profile-visibility"></a>
### 6.2 谁可看、何时更新

<a id="F-L23"></a><a id="f-l23"></a>
个人和企业基本资料**仅当前合法登录的本平台资产方本人及其有效企业归属可见**。同一人以另一钱包登录的资金方账户、同企业其他账户、其他资产方和运营人员均不因此获得访问权，已认证者也不能看他人基本资料。账户页误入的资金方进入自身账户页；企业页误入的资金方回可达资产广场并提示不适用。游客不能读取；登录未绑定角色的用户既无本平台账户也无可展示资料，相关入口一律不展示。（F-L23）

<a id="business-fields"></a>
业务办理需要的信息自动获取，只按该业务已有的对象、必要字段和角色权限展示，不开放整组本人资料，不要求借贷端手填上游资料。可选缺失不阻断业务；必要信息不足、主体不明或读取失败，只限制依赖该信息的动作，说明原因并提供返回及适用的重试，不把旧资料伪装成已确认当前信息。

<a id="profile-refresh"></a>
匹配命中时取得当前获准资料及同步时间；此后按[上游变更的同步与通知](#F-L36)的调取时点（登录成功后、资产方登录期间的 60 秒复核、关键动作前）核对更新。**本期不考虑上游撤回资料可见权限**，该分支不实现；未返回字段、读取失败不等于删除。资料永远对应当前有效企业，待审核企业变更不提前替代有效企业。退出、换账户或有效归属变化后不残留旧资料，迟到结果不得重新展示他人或旧主体信息。

## 7. 退出、失效与既定时效

<a id="F-L27"></a><a id="f-l27"></a>
主动退出只有全平台唯一一个入口（位于账户入口下），结束本平台登录，不级联退出资产可信平台。到期、上游账户锁定/禁用也结束相应本平台登录。**上游资产可信平台的普通退出不再结束本平台的钱包登录**：本平台登录凭据是本次钱包签名，与上游会话是两回事；用户在上游正常登出后，本平台仍可继续按当前角色与资格使用，直到本平台登录自身到期或用户主动退出。此口径已由用户裁定，见[本期已裁定的关键口径](#scope)。（F-L27）

| 结束或限制的原因 | 用户可见结果 |
| --- | --- |
| 主动退出 | 就地回游客视图并说明，不退出上游，不跳登录页 |
| 本平台登录到期 | 原页面就地回游客视图并说明，受保护内容不可继续读取，不自动跳转或弹登录页 |
| 上游账户锁定或禁用 | 禁用／锁定满 60 秒后，任何需要登录的操作或页面刷新被拒绝，结束该主体的本平台登录，就地游客视图并说明原因；显示实际可取得的解除信息，不编造 |
| 上游登记钱包地址变更 | **结束该地址对应的本平台登录**，就地说明“资产可信平台登记的钱包地址已变更，请重新登录”，见[上游登记钱包地址变更](#wallet-change) |
| 有效认证失效 | 不结束登录，按[认证降级](#confirmed-downgrade)限制融资资格并发本人强制站内信 |
| 上游资料授权撤销 | **本期不考虑**，系统实现不做 |

前四类结束登录的原因均在原页面就地回游客视图并给说明，受保护内容不可继续读取，不自动跳转或弹出登录页；认证失效只限制相应动作，不结束登录。

<a id="F-L28"></a><a id="f-l28"></a>
无法确认来源的调取结果（含禁用、锁定或变更信息）不影响合法登录与本次会话的判定结果，须产生安全告警；同一异常不反复打扰用户。上游不向本平台推送禁用或退出，禁用／锁定后的登录结束以[上游账户禁用后失效](#logout-deadline)为准。登录失效时尚未保存的内容提示未保存，不暂存草稿；迟到操作结果不能恢复登录。见[角色与登录状态图](./02-登录主干与资产方SSO接入-流程图与状态机.md#flow-3)。（F-L28）

| 项目 | 既定口径 |
| --- | --- |
| <a id="session-period"></a>登录有效期 | 资产方 7 天；登录未绑定角色 4 小时；资金方 4 小时，见资金方账户 PRD 的[会话有效期（F-L69）](../02-资金方登录与账户体系/01-资金方登录与账户体系-PRD.md#F-L69)。均为自登录成功起计算的绝对有效期，到期即结束、不因操作延长，无“记住我”，到期后共用游客态结果。登录未绑定角色在本次登录内成功提交资金方入驻申请后，本次登录以资金方继续，4 小时自提交成功时起重新计算 |

<a id="audit-results"></a>

<a id="interface-boundary"></a>
## 8. 未决依赖与开发核实边界

<a id="pending-dependency"></a>
### 8.1 剩余缺口与已知取舍

尚未取得事实、需在接入阶段补齐的：

| 事项 | 缺什么 | 本版边界 |
| --- | --- | --- |
| 调取接口的响应与范围 | 按地址查询账户的接口是否可用、响应时延、可返回哪些字段与粒度、失败与限流的返回约定 | 调取能力为接入前置条件；确认前不写入秒级承诺，业务判断以[上游变更的同步](#F-L36)的调取时点为准，调取失败按[角色判定](#F-L34)第 ④ 行处理 |
| 上游登记地址的控制权验证 | 验证方式，以及存量已登记地址是否都经过验证 | 调取到即判定为资产方的成立前提；接入前必须确认，存量未覆盖部分须由上游说明处理方式 |
| 上游不可用期间的禁用发现 | 60 秒复核调取失败时，无法确认账户是否已被禁用／锁定 | 按[角色判定](#F-L34)第 ④ 行处理：保持本次判定结果、关键动作不放行；60 秒失效以复核调取成功为前提，上游可用性在接入阶段确认 |

<a id="accepted-tradeoff"></a>
以下取舍由业务知悉并接受，写在此处供研发、测试与后续评审共读，不再作为待决项：

| 取舍 | 影响 |
| --- | --- |
| 本期不签任何协议 | 本平台侧没有服务条款／隐私政策的明示同意记录（同意时间、版本、原文），争议时无凭据可追溯；本平台自身的个人信息处理缺少独立告知与同意基础；后续若需补签涉及存量用户补签 |
| 不告知判定后果 | 用户可能在不知情下被固定角色，改角色只能换钱包重新入驻 |
| 本期不考虑上游撤权 | 用户在上游撤回资料可见权限后，本平台仍保有旧值 |
| 已是资金方的地址此后在上游登记 | 本期无法发现该冲突：判定顺序先查资金方、登录时不向上游调取，该地址继续按资金方登录；禁止并存只在提交资金方入驻时拦截 |
| 入驻信息提交前不入库 | 机构认证表单较长且含多附件，中断即全部重填，可能拉低入驻完成率 |

<a id="integration-provisional"></a>
### 8.2 资产可信平台真实接入的核实项

**资产可信平台真实接入仍为暂定，文档交付不代表接入通过。** 本人资料可见、必要业务信息自动获取、强制通知规则已确认，不再交给接口设计重新决定；开发需依据资产可信平台实际接口确认下表对应关系。

| 待核实项 | 必须得到的业务结果 | 未满足时的边界 |
| --- | --- | --- |
| <a id="dependency-identity"></a>稳定身份及账户可用性 | 同一上游人始终对应同一本平台账户，可识别禁用/锁定 | 缺稳定标识不建立账户；不能改用邮箱或企业名称认人 |
| <a id="dependency-wallet"></a>登记地址的控制权验证与调取接口 | 上游登记钱包地址时验证控制权的**具体方式**与存量地址覆盖情况；按地址调取账户、个人、企业与认证结论的接口可用、结果来源可验证，并说明响应时延、失败与限流约定 | 两项均为接入前置条件，不能以放宽判定或回补确认绕过；上游确认前不写入秒级同步承诺，缺口按接入问题上报而不是降低业务口径 |
| <a id="dependency-sync"></a>同步数据的范围与粒度 | 匹配所需的“地址 → 稳定标识 → 认证状态”索引可独立获取；个人证件、企业明细等明文在匹配成功后按需取得 | 未与本平台建立关系的自然人明文不预先落到本平台；范围未确认前不按整份档案预取 |
| <a id="dependency-register"></a>上游注册与认证链路 | 引导用户前往上游注册／认证的入口、免二次输入能力与返回后的处理可确认 | 无法免输入时最多回退一次完整登录；返回处理不改变本平台已建立的登录 |
| <a id="dependency-profile"></a>用户 id、地址、邮箱、企业 id 及两类基本资料的真实供给 | 字段含义、适用模板、缺失、获准展示范围可确认 | 可选缺失空态；必要信息不足仅限制相关业务，不增加本地补填 |
| <a id="dependency-qualification"></a>当前有效企业与综合认证 | 区分有效归属/资格与待审核申请、单项结论 | 不以待审企业替代，不自行拼认证；无法确认不放行依赖动作 |
| <a id="dependency-privacy"></a>证件字段与剩余脱敏口径 | 明确可提供、可展示的内容 | 未确认不显示真实明文；涉及新增可见范围由产品确认，开发不自行扩大 |
| <a id="dependency-session"></a>禁用联动与变化获知 | 验证 60 秒复核下的真实资格更新，以及禁用／锁定满 60 秒后需登录的操作或页面刷新被拒并结束登录的结果 | 可模拟页面行为，不能据此声称性能或真实联动通过；不擅自放宽时限 |
| <a id="dependency-return"></a>域名、页面登记及对端返回安全 | 唯一落地位置、允许业务页及对端同等校验可确认 | 跨平台返回仍关闭，站内默认落资产广场；不影响已满足条件的角色判定 |
| <a id="dependency-notification"></a>通知接入 | 确认真实降级、本人归属、强制消息及正确跳转 | 业务限制不等消息；登记、页面映射和真实投递仍需消息中心验证 |
