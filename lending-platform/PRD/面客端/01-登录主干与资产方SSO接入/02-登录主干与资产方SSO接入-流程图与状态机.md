# 登录主干与资产方 SSO 接入 · 流程图与状态机

图仅表达业务流程和状态，**不表达页面布局、组件形态与视觉层级**；承载形式由 Hallmark 设计决定。图中“上游”统一指资产可信平台（用户注册认证与个人、企业信息的来源）。具体分支、字段与验收统一见[主 PRD](./01-登录主干与资产方SSO接入-PRD.md)。资金方节点仅表示 资金方账户模块的接续边界。

<a id="flow-1"></a>
## 图 1 · 从游客浏览到钱包登录、角色判定与恢复原操作

对应[统一钱包登录入口](./01-登录主干与资产方SSO接入-PRD.md#F-L02)、[登录签名规则](./01-登录主干与资产方SSO接入-PRD.md#signature-rules)、[取消、不可用与更换钱包](./01-登录主干与资产方SSO接入-PRD.md#F-L03)、[登录后的角色匹配](./01-登录主干与资产方SSO接入-PRD.md#F-L34)与[返回](./01-登录主干与资产方SSO接入-PRD.md#F-L04)。

```mermaid
flowchart TD
    G["游客浏览：资产广场与借贷广场"] -->|使用登录入口| W["连接钱包并选择地址"]
    G -->|触发受限动作| W
    W -->|取消、无可用钱包、钱包锁定或网络不是 Ethereum| O["就地说明原因并可重试；回原处，保留浏览上下文"]
    W -->|选定地址即请求签名| S{"消息签名通过"}
    S -->|否：拒签、验签失败、地址不一致、请求过期或已用| O
    S -->|签名中钱包切换地址| RE["中止本次登录，提供用该地址重新登录"]
    S -->|是| IN["签名验证通过，开始角色判定"]
    IN --> F{"本平台已有该地址的资金方账户"}
    F -->|有且账户正常| FUNDER["进入资金方角色，不再向上游调取"]
    F -->|有但账户已停用| DIS["本次登录不成立，按资金方账户模块处理"]
    F -->|无| PULL{"向资产可信平台调取该地址对应账户"}
    PULL -->|调取到| ASSET["本次会话判定为资产方，继续取个人与企业信息，见图 2"]
    PULL -->|调取不到| NONE["登录未绑定角色（登录后的游客）：可浏览可达内容、可退出"]
    PULL -->|调取失败| KEEP["本次登录不成立：提示暂时无法确认身份请重试，可重试或继续游客浏览"]
    NONE --> ACT{"触发业务动作"}
    ACT -->|资产方动作| UP["离站确认后前往资产可信平台完成注册与认证；登记该地址后须重新登录，调取到即判定为资产方"]
    ACT -->|资金方动作| FUND["进入资金方入驻流程；提交成功即建立资金方账户，本次登录以资金方继续"]
    ACT -->|其他受限内容| GUIDE["按受限引导说明，不改变角色"]
    ASSET --> NEXT{"有效原目标"}
    FUNDER --> NEXT
    FUND --> NEXT
    NEXT -->|无或不允许| PLAZA["资产广场；无效返回给中性提示"]
    NEXT -->|有效| Q{"当前角色与资格允许原动作吗"}
    Q -->|是| BACK["回原触发点并恢复操作"]
    Q -->|否| GUIDE
```

取消登录不执行原业务；未绑定角色不阻断浏览，也不要求用户选择角色；跨平台返回未满足对端确认时按资产广场兜底。判定顺序固定为先查本平台资金方、再向资产可信平台调取，**本期不接收上游主动推送**；**本平台不保存地址与资产方角色的绑定关系，每次登录都重新判定**，一个地址只对应一个角色；资金方账户保存唯一且不可修改的登录地址作为账户属性。

## 图 2 · 上游信息调取、角色判定与账户建立

对应[同一套判定](./01-登录主干与资产方SSO接入-PRD.md#F-L25)、[调取与来源校验](./01-登录主干与资产方SSO接入-PRD.md#F-L20)与[调取结果](./01-登录主干与资产方SSO接入-PRD.md#F-L35)。每次登录与登录期间的调取时点共用此判定；从上游注册或认证后返回本身不触发改判。

```mermaid
flowchart TD
    START["签名验证通过、60 秒复核或关键动作判定点，立即显示处理中"] --> FUND{"本平台已有该地址的资金方账户"}
    FUND -->|有| ROLEF["资金方角色，不调取上游"]
    FUND -->|无| CALL["本平台服务端按地址向资产可信平台调取"]
    CALL --> OK{"调取是否成功"}
    OK -->|失败或超时| KEEP["登录时：本次登录不成立，提示暂时无法确认身份请重试；登录期间：保持本次判定结果，关键动作不放行"]
    OK -->|成功| SRC{"响应来源可信且面向本平台"}
    SRC -->|否| ALERT["不参与判定、不改判角色、不结束登录；安全告警"]
    SRC -->|是| MATCH{"调取结果"}
    MATCH -->|调取不到（含上游已改登记为其他地址的旧地址）| NONE["登录未绑定角色；不猜测、不近似匹配、不提示新地址"]
    MATCH -->|调取到多个账户（数据异常）| CONFLICT["不判定角色、不取其中任一条；告警并给中性说明"]
    MATCH -->|调取到唯一账户| ACTIVE{"上游账户可用"}
    ACTIVE -->|否| BLOCK["不判定为资产方，结束该主体登录；就地游客视图"]
    ACTIVE -->|是| BIND{"建立或复用本平台资产方账户"}
    BIND -->|失败| ERROR["建号失败结果：错误码、重试、继续浏览"]
    BIND -->|成功| SYNC["继续调取个人资料、有效企业与当前认证结论"]
    SYNC --> LAND["按图 1 返回与资格规则继续"]
    ERROR -->|重试| START
```

本期本平台不签任何协议，流程中没有协议同意环节；上游注册时签署的同步授权属上游侧行为。登录时调取失败则本次登录不成立；登录期间调取失败不结束已建立的钱包登录。

## 图 3 · 角色与登录状态

对应[登录、角色与认证分别判断](./01-登录主干与资产方SSO接入-PRD.md#state-contract)与[退出与失效](./01-登录主干与资产方SSO接入-PRD.md#F-L27)。角色与认证是两条独立的轴，本图只表达角色与登录。

```mermaid
stateDiagram-v2
    [*] --> 游客
    游客 --> 登录未绑定角色: 签名通过、非资金方且调取不到
    游客 --> 判定为资产方: 签名通过、非资金方且调取到上游账户
    游客 --> 游客: 签名通过但上游调取失败，本次登录不成立
    登录未绑定角色 --> 判定为资金方: 提交资金方入驻申请成功，4 小时自提交时重新计算
    登录未绑定角色 --> 游客: 主动退出或登录到期（4 小时）
    判定为资产方 --> 游客: 主动退出
    判定为资产方 --> 游客: 登录到期（7 天）
    判定为资产方 --> 游客: 上游账户锁定或禁用满 60 秒后的下一次需登录请求
    判定为资产方 --> 游客: 调取发现上游登记地址变更，终止登录并提示重新登录
    判定为资金方 --> 游客: 主动退出或登录到期（4 小时）
```

退出均就地降为游客且解释原因，不自动弹登录；主动退出不退出上游，退出入口全平台唯一。**上游普通退出不结束本平台登录**；上游账户禁用或锁定满 60 秒后，任何需要登录的操作或页面刷新即被拒绝并结束登录，页面停留无请求时不主动提示。登录未绑定角色的用户在上游完成注册后，须退出并重新登录才判定为资产方；登录有效期均为自登录成功起的绝对时长。一个地址只对应一个角色且**禁止并存**；本次判定出的角色不可由用户改选，改用其他地址按全新用户重新判定。图中状态是本次会话的判定结果，不是账户上保存的绑定。原“钱包待重新确认”状态已停用。

## 图 4 · 认证资格与发起融资

对应[认证更新与发起融资](./01-登录主干与资产方SSO接入-PRD.md#F-L29)。角色判定先完成；申请审核进度不代替当前有效综合认证。

```mermaid
flowchart TD
    S{"登录有效且判定为资产方"} -->|否| OUT["按游客或登录未绑定角色的访问范围处理"]
    S -->|是| V{"当前有效综合结论为已认证"}
    V -->|否或未知| UNVERIFIED["未认证资产方：可浏览、本人账户及消息；受限动作给认证引导"]
    V -->|是| VERIFIED["已认证资产方"]
    UNVERIFIED -.->|下一个调取时点确认已认证| VERIFIED
    VERIFIED -.->|确认认证失效，页面说明及图 6 通知| UNVERIFIED
    VERIFIED -->|发起融资申请| WAIT["正在确认资格，不重复发起"]
    WAIT --> CHECK{"重新调取后账户可用、登记地址未变、认证有效且原操作仍有效"}
    CHECK -->|是| GO["允许继续融资申请"]
    CHECK -->|已未认证| UNVERIFIED
    CHECK -->|无法确认| RETRY["申请尚未发起，可重试"]
    RETRY --> WAIT
    CHECK -->|退出、过期、换角色或离页| STOP["丢弃旧操作结果，不恢复权限或旧页面"]
```

## 图 7 · 上游信息调取与登记地址变更处理

对应[上游变更的同步与通知](./01-登录主干与资产方SSO接入-PRD.md#F-L36)。

```mermaid
flowchart TD
    SRC{"调取时点"} -->|每次登录成功后| READ["本平台按地址调取上游账户、资料、企业与认证结论"]
    SRC -->|资产方登录期间距上次调取超过 60 秒后的下一次请求前| READ
    SRC -->|发起融资等关键动作前| READ
    READ --> OK{"调取是否成功"}
    OK -->|失败或超时| KEEP["登录期间：保持本次判定结果与已取得资料，关键动作不放行，可重试"]
    OK -->|成功| VERIFY{"响应来源可验证"}
    VERIFY -->|否| ALERT["不采信：不改判角色、不结束登录；产生安全告警"]
    VERIFY -->|是| KIND{"变更类型"}
    KIND -->|账户禁用或锁定| END["结束该主体登录并说明原因；禁用满 60 秒后的需登录请求必被拒绝"]
    KIND -->|认证结论失效| DOWN["停止融资资格并按图 6 通知"]
    KIND -->|有效企业归属变更| ORG["确认即更新，待审企业不提前替代"]
    KIND -->|普通资料变更| MINOR["随本次调取更新展示"]
    KIND -->|登记钱包地址变更| STOP["一经发现即终止该地址对应的登录，提示登记地址已变更请重新登录"]
    STOP --> RELOGIN{"用户以新地址登录"}
    RELOGIN -->|是| SAME["调取到同一上游稳定账户，接续原账户与历史；旧地址此后调取不到"]
    RELOGIN -->|仍用旧地址| TELL["按调取不到处理：登录未绑定角色，不提示新地址"]
```

**本期由本平台主动调取，不接收上游主动推送**：变更（含登记地址变更）都在下一个调取时点（登录成功后、资产方登录期间的 60 秒复核、关键动作前）被发现并应用，不承诺秒级同步，页面停留无请求时不主动发现；登录期间调取失败不改判本次会话的角色、不放行关键动作，重复失败按接入缺口上报。**本期不考虑上游撤回资料可见权限**，该分支不实现。登记地址变更不设待重新确认状态、不冻结资金类动作。
