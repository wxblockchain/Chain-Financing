# 首页 · 功能与业务规则

2026-10-27｜面客端：游客、登录未绑定角色、资产方、资金方｜草案

本模块共三册：本册写功能、业务规则、字段规则与交互逻辑；[流程图与状态机](./02-首页-流程图与状态机.md)画出主要流程与状态；[验收](./04-首页-验收.md)供测试使用。本模块不发送任何消息，所以没有 03 消息通知册，并非缺失。

## 1. 模块是什么

<a id="scope"></a>
首页是面客端公开的平台介绍页。任何人（包括未登录的游客）都可以在这里了解：平台做什么、平台当前的业务规模、一笔贸易资产怎样经过验真、代币化、质押走到机构放款，以及平台在业务中不做什么，并从这里进入资产广场查看代币数据。首页只做介绍和引导，不办理任何业务，也不因登录与否或角色不同而改变内容。

基本原则：

- 只介绍、不办理：首页不提供融资、报价、质押、授信、账户维护等业务动作；需要办理时由入口带到所属模块。
- 所有访问状态看到的首页内容相同；顶栏中的导航、消息入口与账户入口按各自所属模块的规则显示。
- 首页的说明只转述现行模块已明确的规则，与所属模块冲突时以所属模块为准；现行规则中没有的信息（如资产等级、按面值折算份额、本期范围以外的区块链网络）不在首页出现。
- 业务概览展示真实数据，口径以[业务概览（F-HM-04）](#F-HM-04)为准；首屏示意卡片是固定示例，须让访客能辨认是示意。
- 首页只公开本册明确列出的信息；各模块定义为不公开的其他内容（如可融金额、报价利率与条款、未准入的代币）在首页同样不出现。

**一个完整的例子。** 游客在资产广场点击顶栏左侧的品牌图标，进入首页。首屏说明平台是“可信贸易资产在链上完成融资”的基础设施，并用一组示意卡片展示一笔资产从验真到放款的过程；继续向下浏览，看到平台当前的代币化资产总值、累计融资额、活跃项目数等统计，以及最近的融资需求与放款金额播报；再往下是四步运作机制、平台特点和使用须知。游客打开存证校验，输入一个代币编号，得到与登记记录一致的结果和对应的链上存证信息；关闭后回到原浏览位置。随后点击进入资产广场，继续查看代币列表。全程不要求登录；游客在首页使用“连接钱包”登录成功后，仍留在首页。

### 1.1 本期不做

- 在首页办理任何融资、报价、质押、授信或账户业务。
- 展示个人或本企业数据、待办与消息内容。
- 登录、注册、成为资产方或成为资金方的单独引导；登录入口只有顶栏的“连接钱包”。
- 主导航中的“首页”菜单项。
- 按访问状态或角色区分首页内容。
- 首页内容的运营端配置与维护功能。
- 合作伙伴名单：原型预留位置，本期不定义规则。
- 页脚各入口（服务协议、隐私声明、风险揭示、联系我们）所指向的内容。

## 3. 进入首页与离开（F-HM-01）

适用角色与前提：所有访问状态，无需登录。页面标识 P-HOME-01，地址为 `/home`。

- 首页地址可直接打开、刷新和分享；任一访问状态打开时都不要求登录、不设登录墙、不遮蔽内容。
- 面客端各页面顶栏左侧的品牌图标进入首页；主导航中不设“首页”菜单项，与[游客浏览与唯一登录入口（F-L01）](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#F-L01)、[进入资产广场（F-AM-01）](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-01)一致。
- 面客端默认入口（`/`）、登录后没有返回目标时的落点、无效返回目标的兜底，仍是资产广场，按[游客浏览与唯一登录入口（F-L01）](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#F-L01)、[登录返回（F-L04）](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#F-L04)与[无效目标兜底（F-L07）](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#F-L07)执行。
- 首页沿用面客端公共顶栏，首页不增减其中任何内容：
  - 资产广场、借贷广场两个一级入口对所有访问状态可用，按[进入资产广场（F-AM-01）](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-01)。
  - 我的控制台只对资产方、资金方显示，按[我的控制台的可见范围](../09-我的控制台/01-我的控制台-PRD.md#visibility)。
  - 消息入口与未读数只对已登录的资产方、资金方显示，按[消息入口、最近预览与未读数](../10-面客消息中心/01-面客消息中心-PRD.md#f-nc-11)。
  - 语言切换始终可用；未登录时显示“连接钱包”；登录后显示账户入口与账户菜单，按[游客浏览与唯一登录入口（F-L01）](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#F-L01)与[账户菜单](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#account-menu)。
- 在首页使用“连接钱包”属于主动登录，没有被拦下的业务动作；登录、取消与失败按登录主干处理。
- 在哪个页面登录，登录成功后就回到哪个页面：在首页登录成功后留在首页；在其他页面登录不会被带到首页。首页须属于登录主干允许返回的页面，见[首页作为登录返回目标（Q-HM-03）](#Q-HM-03)。
- 登录、退出或角色变化后，首页内容不变，只有顶栏按上述规则变化。
- 默认英文，可切换中文；切换语言不刷新页面，首页全部文字随之切换，只使用术语表中的译法，与[共同要求与访问保护（F-AM-12）](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-12)一致。
- 在首页打开顶栏菜单、消息预览或切换语言，访客当前的浏览位置不变，已经播放过的内容不重新播放。
- 离开首页再回到首页时，从首页开头开始浏览。

流程参见：[进入与离开首页（FL-HM-01）](./02-首页-流程图与状态机.md#FL-HM-01)。

## 5. 平台介绍（F-HM-03）

适用角色与前提：所有访问状态。

- 给出平台定位：经资产可信平台提供资产事实与链上存证的贸易资产以代币形式登记，机构基于质押直接放款，业务记录在 Ethereum 上。
- 给出三项要点：链上存证可查、机构直接放款而平台不经手资金、任何人可以自行查验。“任何人可以自行查验”依赖[存证校验（F-HM-10）](#F-HM-10)与资产广场[链上凭证与自行查验（F-AM-08）](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-08)。
- 用一组示意卡片展示一笔资产依次经过的四个环节：

| 示意卡片 | 应体现的业务信息 | 口径来源 |
| --- | --- | --- |
| 可信资产 | 一笔已准入资产的代币编号与准入结果 | [哪些代币出现在资产广场（F-AM-15）](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-15) |
| 代币 | 该资产对应代币的代币数量（枚）与区块链网络 | [代币信息字段](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#token-fields) |
| 项目质押 | 质押到融资项目后的有效质押价值、项目质押率与有效质押额 | [有效质押价值（FP-11）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#FP-11)、[有效质押额（FP-12）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#FP-12)、[项目质押率（FP-34）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#FP-34) |
| 放款 | 一笔链上放款的放款金额与放款币种 | [放款金额（LN-04）](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#ln-04)、[放款币种（LN-03）](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#ln-03) |

- 示意卡片使用固定示例，不读取实时业务数据；须让访客能辨认这是示意。
- 示例中的业务值须符合现行规则：区块链网络为 Ethereum；代币数量以“枚”计、签发时 1 USD 对应 1 枚；项目质押率是资产方自填、不超过最高质押率的值，不表述为平台固定比例；放款币种为 USDT 或 USDC。
- 示意卡片中不出现真实机构名称、真实成交利率或资产等级。

## 6. 业务概览（F-HM-04）

适用角色与前提：所有访问状态，看到的数据相同。数据为真实业务数据。

### 6.1 平台统计

| 统计项 | 口径 | 单位与精度 |
| --- | --- | --- |
| <a id="hm-total-value"></a>代币化资产总值 | 全部已准入代币的签发价值合计，含失效代币与已到期的代币；待审核、已退回的代币不计入。与资产广场[头部汇总（F-AM-02）](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-02)的代币价值（只计有效代币、随筛选变化）是两个独立口径，互不影响 | USD，2 位小数；同时说明按各笔签发时汇率折算 |
| <a id="hm-total-quantity"></a>代币总量 | 与代币化资产总值同一范围的代币数量合计 | 枚，2 位小数 |
| <a id="hm-cumulative-financing"></a>累计融资额 | 全部链上放款成功的[放款金额（LN-04）](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#ln-04)合计；历史累计，不因还款或结清减少；放款处理中与失败的不计入；USDT 与 USDC 先分别合计，再各按 1 USDT = 1 USD、1 USDC = 1 USD 折算为 USD 后相加，展示为一个 USD 金额 | USD，2 位小数 |
| <a id="hm-active-projects"></a>活跃项目数 | 有效的融资项目数：[项目状态（FP-04）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#FP-04)为可用、募集中、已锁定、融资中的项目；待审核、已退回、已关闭、已结清的不计入 | 个，整数 |
| <a id="hm-institutions"></a>合作机构数 | 入驻并认证通过的资金方机构数，即注册状态当前为已认证的资金方；审核中、已驳回的不计入 | 家，整数 |
| <a id="hm-attestations"></a>链上存证笔数 | 按代币笔数计：同一发行方、同一代币类型、同一代币编号、同一资产槽位算一笔；范围与代币化资产总值相同 | 笔，整数 |

- 统计须同时给出数据来源与更新时间；时间以 UTC 为基准并标明时区。
- 金额与数量可以缩写展示，但访客须能查看完整值；完整值金额带币种、2 位小数，代币总量 2 位小数。
- 某项取不到时该项显示“—”，不以 0 或旧值代替，其他统计照常展示。
- 活跃项目数、代币总量与链上存证笔数的范围，以及累计融资额是否另外展示各币种小计，见[统计口径的理解（Q-HM-11）](#Q-HM-11)。

### 6.2 融资动态播报

- 以滚动播报的方式展示最近发生的融资事件，按发生时间从近到远。
- 只播报两类事件：

| 事件 | 何时产生 | 每条展示 |
| --- | --- | --- |
| 融资需求 | 资产方发布融资需求成功（冻结上链成功） | 事件类型、[融资需求金额（FP-06）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#FP-06)，USDT |
| 放款 | 链上放款成功 | 事件类型、[放款金额（LN-04）](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#ln-04)与[放款币种（LN-03）](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#ln-03) |

- 每条只展示事件类型与金额（带币种），区块链网络统一为 Ethereum；不展示项目、资产方企业、资金方机构、利率、期限、地址或交易标识。
- 发布处理中或失败的需求、放款处理中或失败的放款不播报。
- 放款金额对公众播报与授信报价模块的查看权限尚未统一，见[放款金额公开播报的跨模块统一（Q-HM-04）](#Q-HM-04)。
- 持续滚动的内容可以暂停和继续，见[动态效果与可读性（F-HM-11）](#F-HM-11)。

## 7. 运作机制（F-HM-05）

适用角色与前提：所有访问状态。

用四步说明一笔资产如何得到融资。每步只转述所属模块的规则，示例数值须能按该规则算通：

| 步骤 | 应传达的业务事实 | 以哪个模块为准 |
| --- | --- | --- |

<a id="F-HM-06"></a>
## 8. 平台特点（F-HM-06）

适用角色与前提：所有访问状态。

展示四项平台特点，每项附一条佐证。佐证只使用现行规则中成立的事实，或本册[业务概览（F-HM-04）](#F-HM-04)中的统计：

| 特点 | 应传达的业务事实 |
| --- | --- |
| 源头验真 | 资产事实与链上存证来自资产可信平台 |
| 合规内建 | 代币经运营准入审核后才公开展示；只有已认证资金方可以授信与报价；资产方须在资产可信平台完成注册与认证 |
| 双边直贷 | 平台不归集资金、不垫付；年化利率由资金方填写；授信由资金方自行决定 |
| 自行查验 | 任何人可以凭代币编号或存证哈希比对存证记录，也可以到区块浏览器自行查验 |

## 9. 使用须知与进入资产广场（F-HM-08）

适用角色与前提：所有访问状态。

- 说明“谁能看、谁能办”，内容须与各模块的公开与资格规则一致：
  - 资产广场的代币信息对所有访问状态公开，按[角色、权限与公开范围（F-AM-10）](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-10)。
  - 借贷广场的项目列表对所有访问状态公开；项目详情按身份决定可见范围，游客只看到基本信息，按[项目详情按身份的可见范围（F-LS-82）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#F-LS-82)。
  - 授信、报价与放款只对已认证资金方开放。
  - 资产方在资产可信平台完成注册与认证；登录方式只有连接钱包。
- 提供进入资产广场的入口，入口名称使用“资产广场”；点击后在当前窗口进入资产广场列表。
- 本部分之后是页脚，见[页脚（F-HM-09）](#F-HM-09)。

<a id="F-HM-09"></a>
## 10. 页脚（F-HM-09）

适用角色与前提：所有访问状态，内容相同。

- 首页页脚的内容与资产广场页脚相同（2026-10-26 用户确认），两处使用同一份内容，任一处调整时两处同步变化。
- 当前内容包括：平台名称、平台简介、服务协议、隐私声明、风险揭示、联系我们四个入口，以及当前时区。
- 各入口所指向的协议、说明与联系方式不在本册定义。
- 首页页脚不另外展示合约地址、参考资料或其他披露文本。

<a id="F-HM-10"></a>
## 11. 存证校验（F-HM-10）

适用角色与前提：所有访问状态，无需登录；首页提供存证校验入口，入口位置由设计决定。

### 11.1 输入与校验

| 业务信息 | 含义/类型 | 必填条件/默认值 | 可编辑范围 | 校验与结果 |
| --- | --- | --- | --- | --- |
| 待校验内容 | 代币编号或存证哈希，文本 | 必填，无默认值 | 校验进行中不可编辑，其余时间可编辑 | 去掉首尾空格后为空时提示需要输入内容，不发起校验；不区分大小写，与登记记录完全一致才算匹配 |

- 只接受代币编号与存证哈希两种输入；代币编号格式按[代币信息字段](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#token-fields)，存证哈希即资产广场[链上凭证与自行查验（F-AM-08）](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-08)中的存证哈希。
- 输入框附近给出两种输入的示例格式。
- 提交后进入校验中：明确告知正在读取记录，不能重复提交。

### 11.2 校验结果

| 结果 | 访客看到什么 |
| --- | --- |
| 输入为空 | 提示需要输入内容，不展示结果 |
| 一致 | 说明与登记的存证记录一致，并展示对应信息：代币编号、存证哈希、链上存证交易哈希、区块高度、存证链、存证时间（标明时区）；字段名称与资产广场[链上凭证与自行查验（F-AM-08）](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-08)相同 |
| 未找到 | 说明没有匹配的登记记录，请核对后重试；不说明原因 |

- 只匹配资产广场展示范围内的代币（含失效代币）；待审核、已退回的代币和不存在的值一样返回“未找到”，不暴露其是否存在。
- 一个代币编号对应多笔代币（代币发行合约或资产槽位不同）时，逐笔展示各自的存证信息。
- 一致结果中某项存证信息缺失时，该项显示“—”，其余照常展示。
- 结果只表达“与登记的存证记录一致”或“未找到”，不表述为资产真实、平台已确认或平台担保。

### 11.3 关闭与再次打开

- 关闭存证校验后回到首页原浏览位置。
- 校验进行中关闭，本次校验结束，不再显示其结果。
- 再次打开时不显示上一次的结果。

流程与状态参见：[存证校验（FL-HM-02）](./02-首页-流程图与状态机.md#FL-HM-02)、[存证校验状态（ST-HM-01）](./02-首页-流程图与状态机.md#ST-HM-01)。

## 12. 动态效果与可读性（F-HM-11）

适用角色与前提：所有访问状态。动效的形式与节奏沿用第一版设计。

- 持续运动的内容（融资动态的滚动播报、放款示意的数值轮换等）可以暂停，暂停后可以继续。
- 访客的设备开启“减少动态效果”时，不播放持续运动与入场动画，统计数字直接显示最终值，此时不需要提供暂停操作。
- 动画播放过程中和结束后，统计数字的完整值都可以查看。
- 首页全部内容和操作可以只用键盘到达。
