## 1. 模块是什么

资金方对一轮融资需求出资前，先确认自己对该资产方企业的授信是否够用：没有、不够或已到期时，当场核定或追加授信；授信够用后提交全额报价。报价一经提交即锁定这一轮需求，资产方选用本企业的收款账户、核对商务摘要后接受，或填写原因拒绝。接受后业务转入放款，接受本身不代表资金到账。本模块负责授信核定与追加、报价锁定、接受与拒绝、需求终结时报价的连带失效，以及相关的记录展示与站内信。

基本原则：

- 授信是“一家资金方机构 × 一家资产方企业”的关系，跨该资产方的所有项目共用，不按项目拆开。
- 授信只在报价时就地办理，没有独立的授信菜单；授信保存后须由用户再次发起报价。
- 报价没有有效期：提交后一直待接受，资金方不能撤回或修改，退出只有资产方拒绝，或所属需求终结带来的连带失效。
- 平台不生成、不收取、不核验融资合同；双方线下签署合同，接受时只核对商务摘要。
- 收款账户只能从企业账户中选用，办理中不新增、不编辑账户；平台不采集收款人名称，也不校验账户归属。
- 全流程没有倒计时，平台不因等待自动改变任何结论，也不因时间流逝释放任何占用。
- 本模块的操作都不触发链上动作、不产生 gas；真实放款与还款由后续模块办理。

**一个完整的例子。** 资产方甲的一个项目发布了一轮 150 万 USD 的融资需求。资金方乙在项目详情点击“立即报价”，平台判定乙对甲尚无授信，先请乙确认是否现在核定；乙确认后填写授信额度 500 万 USD、有效期至一年后，本次授信协议选择不上传，保存成功，看到“已授信，请继续报价”。乙再次点击“立即报价”，进入报价：融资金额 150 万 USD 已带出且不可改，乙选择结算币种 USDT、填写年化利率，看到“提交后不可修改、不可撤回，本轮需求将被锁定”等后果后提交。平台生成融资业务编号，本轮需求变为已报价待确认，甲收到“收到融资报价”站内信。甲进入项目详情选择这笔报价，选用本企业已登记的一个 ETH 数币账户并确认，查看商务摘要（摘要明确“不是合同”）后提交接受；本笔转为待放款，乙收到“融资报价已接受”站内信，同一业务编号出现在融资放款信息中，等待乙登记放款。如果甲改为拒绝并填写原因，乙收到“融资报价已拒绝”站内信，乙的在途报价金额释放，本轮需求回到待报价，任何机构（包括乙）都可以重新报价。

<a id="out-of-scope"></a>
### 1.1 本期不做

- 授信审批、额度主动调低、冻结与解冻。
- 多家机构同时报价、比价与部分融资。
- 报价的修改、撤回、展期，以及报价有效期、临期提醒与自动到期。
- 平台生成合同、提供合同模板、收取或核验合同盖章件。
- 收款账户的新增、修改、删除与默认管理（归[企业账户](../03-企业账户/01-企业账户-PRD.md)）。
- 资金方还款收款账户的登记（归[放款与放款确认](../07-借贷广场-放款与放款确认/01-放款与放款确认-PRD.md)）。
- 待放款阶段的暂缓、要求重传与终止；单笔融资业务的中途终止。
- 人工改价、汇率维护与外部行情取数。
- 运营代报价、代接受，以及本模块向运营发送的消息。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 授信 | 一家资金方机构对一家资产方企业核定的融资额度关系，有稳定的授信编号，跨该资产方全部项目共用 |
| 授信额度 | 该机构对该资产方的授信总额，USD |
| 授信占用额 | 该机构对该资产方已放款确认、尚未偿还的本金 |
| 在途报价金额 | 该机构已提交、尚未转为本金的报价金额合计，含待接受、待放款、待放款确认三个阶段 |
| 授信已用额 | 授信占用额与在途报价金额之和；不是第三种独立的占用 |
| 可用授信 | 授信额度减授信已用额，最小为 0 |
| 授信有效期至 | 授信的最后有效日（UTC 业务日期，含当天）；只决定能否提交新报价，与报价、最终还款日无关 |
| 报价（融资业务） | 资金方对一轮融资需求提交的一次全额出资条款；成功即生成融资业务编号（FD-01） |
| 待接受 | 报价成功后、资产方接受或拒绝之前的状态；没有截止时刻 |
| 连带失效 | 所属融资需求终结时，仍待接受的报价随之失效；失效原因只有“所属融资需求终结” |
| 固定折算 | 本期平台业务规则：1 USD = 1 USDT = 1 USDC；不是外部市场价格或兑换承诺 |
| 折算快照 | 报价成功时锁定的折算依据，包括比值、规则生效时间、来源与版本，之后不重算 |
| 商务摘要 | 平台根据本笔事实生成的条款汇总，可复制、打印，明确不是合同、不产生法律效力 |
| 收款账户 | 资产方为本笔放款选用的本企业账户：USD 结算选法币账户，USDT/USDC 结算选数币账户 |
| 结算收款链 / 质押链 | 结算收款链是数币账户地址所在的链（ETH 或 TRON），本模块只用这一个；质押链是代币与质押合约所在的链，与本模块无关。两者互不决定 |
| 质押水位 | 融资需求与代币质押模块的判据：有效质押额不低于“项目融资余额＋项目在途金额”为水位安全，低于为水位不安全；水位不安全时需求自动失效 |
| 质押情况 | 融资需求与代币质押模块的项目级结果：质押充足、质押持平、质押不足；质押不足只用于提醒，不作需求终结原因 |
| 项目在途金额 | 已发布、尚未终结的融资需求金额合计；报价不增加它 |
| 项目融资余额 | 本项目已放款确认、尚未偿还的本金合计 |
| 登录未绑定角色 | 已用钱包登录，但既不是本平台资金方、也调取不到上游资产方账户的用户 |

- 无权或不存在的对象不暴露是否存在，不报错页、不空白、不静默跳回首页。

<a id="view-and-act"></a>
### 3.2 查看与办理

- 查看与办理分开，沿[查看与办理分开（融资需求与代币质押 F-LS-20）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-20)：项目详情的记录与详情只读，不提供办理或跨业务快捷入口；办理从“融资”业务入口进入。
- 有多个待办时，先明确办理对象，不默认“最新一笔”。
- 融资办理保留“发布需求—机构报价—确认签署—融资放款”四阶段进度，分别识别已完成、当前和后续；已结束的需求不标为进行中。接受办理的各步骤只是报价内的填写进度，不替代这四个阶段。
- 一次办理中的步骤、必要确认和放弃未保存修改都在本次办理内完成，不再叠加下一层办理。
- 返回上一步时保留已填内容和已成功上传的文件；有未保存修改时关闭须先确认放弃，没有修改时直接关闭。
- 关闭后回到来源，保留原筛选、分页与所在位置。
- 成功只更新本笔及相关办理入口，不自动打开详情、下一笔或下一阶段；失败保留可复用的输入；结果未知时显示待核实，不假报成功，也不引导重复提交。
- 不能办理时分别说明原因：本机构自己的需求、已被其他机构报价、项目已到期、需求已终结、授信不足、质押水位不安全。
- 不向用户展示条款号、字段来源、内部判据或论证；金额、差额算式、期限与失败出路照常给出。

<a id="profile"></a>
### 3.3 业务资料的自动取得与本人档案

- 个人与企业的账户档案只对本人开放；本模块不提供查看对方完整档案的入口。
- 业务需要的企业名称、编号、条款与账户自动取得：优先取本笔已确认的事实，其次取同一企业、同一用途的有效登记资料。
- 读取失败时说明暂时不可用并可重试，不说成“尚未登记”，不要求用户手填对方资料。
- 不串用其他企业、其他用途或其他业务的资料与文件；新的授信协议不自动套用历史文件。

<a id="time-and-money"></a>
### 3.4 时间、金额与时效

- 业务日期用 UTC；时刻按用户偏好时区展示（游客按浏览器时区），并标注时区；日期字段明确为 UTC。
- 本模块没有任何倒计时类时限；跨日、周末、夏令时与切换语言都不改变业务结论。授信有效期是准入条件，不是倒计时。
- 金额一律带币种。界面默认英文，支持中文。
- 已确认的时效目标：授信判定 1 秒内给出结果；提交终检与结果 2 秒内；提交时的质押水位判断 1 秒内；需求终结后报价连带失效的处理反馈 1 分钟内、最长 5 分钟，处理延迟不构成可以继续接受的宽限。实现与验证归研发、测试。
- 授信、报价、账户确认、摘要查看、接受、拒绝、连带失效及占用变化，都可追溯操作主体、原因与时间。

### 4.1 立即报价后的四种授信结果（F-LS-20）

适用角色与前提：资金方；需求处于待报价，项目未到期、未进入终态，且不是本机构所属企业自己的需求。

资金方点击“立即报价”后，平台先判断本机构对该资产方的当前授信：

| 当前授信 | 先告诉资金方什么 | 资金方确认后 |
| --- | --- | --- |
| 没有授信 | 尚未核定授信，是否现在核定 | 填写授信额度、有效期至与本次授信协议，见[核定与追加](#credit-save) |
| 生效但可用授信不足 | 本次报价金额、可用授信与差额，算式为“本次报价 − 可用授信 = 差额” | 填写正数的增加额，核对调整后的授信额度与有效期至，可上传本次协议 |
| 已到期 | 原有效期至，是否重新核定 | 沿同一授信关系带出上一版额度供修改，重新填写有效期至，可上传本次协议 |
| 生效且可用授信充足 | 无需授信确认 | 直接进入报价，不要求补交历史授信协议 |

- 前三种情形都先确认意图，确认后才进入授信填写。
- 取消意图即结束本次办理并回到原项目：不生成授信记录、融资业务编号、占用或需求锁定，也不留下“曾取消”的记录；再次点击时重新判断。
- 没有独立的授信菜单或“去授信”入口，授信只能由“立即报价”的判断进入。

<a id="credit-save"></a><a id="f-ls-21"></a><a id="p-ls-04"></a>
### 4.2 核定与追加授信（F-LS-21）

适用角色与前提：资金方；由[立即报价后的四种授信结果](#credit-entry)进入且已确认意图。

- 机构自行决定授信：金额、日期合格即生效，没有审批。
- 首次核定成功生成稳定的授信编号；追加与重新核定沿用同一授信关系，保留历次记录。
- 保存成功即结束本次办理，提示“已授信，请继续报价”，授信摘要同步更新；须由用户再次发起报价才进入报价。
- 授信本身不生成报价、不锁定需求；之后取消报价或报价失败，都不回滚已生效的授信与协议。
- 提交失败时定位到具体字段，保留金额、日期、备注与已成功上传的文件；提交过程中防止重复提交，重复点击不重复增加额度。

<a id="credit-fields"></a>
授信字段：

| 字段 | 业务含义与类型 | 必填与默认值 | 可编辑性 | 校验与结果 |
| --- | --- | --- | --- | --- |
| <a id="cr-01"></a>授信编号（CR-01） | 一条授信关系的唯一标识，文本 | 首次核定成功时生成 | 只读 | 追加与重新核定不改变编号 |
| <a id="cr-03"></a>授信对象（CR-03） | 当前项目所属的资产方企业 | 自动带出 | 只读，不可另选 | 不能用代币买方、债务方或项目名代替；主体归属无法确认或无权时阻止提交 |
| <a id="cr-04"></a>授信状态（CR-04） | 生效中 / 已到期 | 系统判定 | 只读 | 没有冻结、停用等其他取值 |
| <a id="cr-05"></a>授信额度（CR-05） | USD 金额 | 必填，无默认金额 | 首次填总额；追加填正数增加额；重新核定带出上一版额度供修改 | 大于 0，最多两位小数；不得调低，不得低于当前授信已用额 |
| <a id="cr-06"></a>首次核定时间（CR-06） | 授信关系首次核定成功的时刻 | 系统记录 | 只读 | 追加不覆盖 |
| <a id="cr-07"></a>授信有效期至（CR-07） | UTC 业务日期 | 首次与重新核定默认核定日 + 1 年 | 可选范围见[授信有效期](#credit-term) | 越界拒绝并给出可选范围 |
| <a id="cr-08"></a>授信占用额（CR-08） | USD 金额，见[术语](#glossary) | 系统计算 | 只读 | — |
| <a id="cr-09"></a>在途报价金额（CR-09） | USD 金额，见[术语](#glossary) | 系统计算 | 只读 | — |
| <a id="cr-10"></a>授信已用额（CR-10） | 授信占用额 + 在途报价金额 | 系统计算 | 只读 | 不作为第三种独立占用 |
| <a id="cr-11"></a>可用授信（CR-11） | 授信额度 − 授信已用额，最小为 0 | 系统计算 | 只读 | — |
| <a id="cr-12"></a>备注（CR-12） | 机构内部说明，文本 | 选填，无默认值 | 可编辑 | 最多 200 字；只对本机构可见 |
| <a id="cr-14"></a>本次授信协议（CR-14） | 本次授信操作对应的协议文件 | 选填，可为 0 份 | 可上传、移除 | 本次最多 10 份；每份不超过 10MB（含 10MB）；PDF、JPG、JPEG、PNG；空文件无效 |

<a id="credit-company"></a>
**授信对象的识别资料。**

- 自动只读带入资产方的法定名称、适用于本笔的已登记英文名、项目编号与融资申请编号；不自行翻译法定名称。
- 对方的注册地区、登记号码、完整注册地址、个人证件与认证材料不在本步骤展示，也不提供完整档案入口。
- 资料完整、暂未提供、加载中、读取失败分别说明；读取失败可重试。选填资料缺失不增加准入条件；名称缺失时说明“未提供”。

<a id="credit-files"></a>
**本次授信协议的上传。**

- 10 份是本次操作的累计上限，不是单次选择的上限，也不限制历次累计。
- 选择前说明格式、大小与上限；已上传份数与上限须可得，每份文件给出名称、大小与当前状态。
- 一次选择超出剩余名额时，整批不加入，保留原列表并告知剩余名额；格式或大小不合格的文件不计数，其他已成功的文件保留。
- 上传中可以取消；尚未提交的文件可以移除、重选、预览或下载；失败的文件可以重试或移除。
- 有上传中或失败待处理的文件时不能提交；处理完成后可以一份都不保留。
- 只有文件名、没有实际内容的不算上传完成；重新进入时按真实状态显示，不承诺跨设备保留草稿。
- 文件操作不改变授信状态、额度或需求。

<a id="credit-records"></a>
**授信协议的留存与可见范围。**

- 本次协议随这次成功的授信操作，与金额、有效期至、时间和机构对应留存；授信双方可查看和下载，其他企业与游客不可见。
- 后续操作不覆盖历史，不提供删除已生效协议的动作。
- 本次未上传即这次授信操作没有协议，不影响授信生效与后续报价；历史记录缺少协议的显示“历史记录未提供协议”，不追溯补件、不作废额度。
- 授信协议没有盖章、一致性声明、线上签署或平台审核要求，不显示“协议已审核”；它与融资合同是两回事。

<a id="credit-term"></a><a id="f-ls-22"></a>
### 4.3 授信有效期（F-LS-22）

适用角色与前提：资金方，在[核定与追加授信](#credit-save)中填写授信有效期至。

- 首次核定与到期后的正式重新核定：默认本次核定日 + 1 年；可选范围为核定日 + 1 年至 + 5 年，两端可选，越界拒绝并给出范围。
- 普通追加：可以保持原日期或往后延，不能提前，不强制延至追加日之后一年。
- 五年上限的起点始终是首次核定日或最近一次正式重新核定日；追加不重置起点。不提供提前重新核定的入口。
- 已到五年上限时仍可只追加金额；起点无法可靠确定时不猜测、不放行延期。
- 核定日与可选范围按 UTC 业务日期；“授信有效期至”含当天，次日 00:00 UTC 起为已到期。
- 加年取同月同日；目标年没有该日时取该月最后一日（例如 2028-02-29 核定，默认有效期至 2029-02-28）。
- 授信到期只阻止新报价；已提交的报价、未偿本金以及接受、放款、还款都不受影响。项目到期不作废授信。

<a id="credit-check"></a><a id="f-ls-23"></a>
### 4.4 可用授信与再次校验（F-LS-23）

适用角色与前提：资金方，每次点击“立即报价”与每次正式提交报价时。

- 新报价必须满足：授信占用额 + 在途报价金额 + 本次报价金额（USD）≤ 授信额度。不扣减授信额度本身。
- 跨项目的报价各按自己锁定的依据计量。
- 再次点击“立即报价”和正式提交时，都重新校验授信、项目与需求状态、质押水位，不以“刚核定过”为放行理由。
- 其他项目的报价先占用导致不足时，重新给出金额、可用授信与差额并进入追加；不重复增加上一次已生效的增加额。
- 质押水位不安全时不能引导去提额；授信不足与质押水位不安全分别说明，不合并为笼统失败。
- 授信已用额已超过授信额度时，停止该机构对该资产方的全部新报价，不自动修改额度或抹去金额。
- 发现同一机构对同一资产方存在多条授信关系时，按最早生效的一条计量，不把额度相加。
- 上两种异常交由运营处理，但目前没有承接的运营端模块，见[待确认事项 Q-CR-12](#q-cr-12)。
- 每次授信变更都可追溯：谁代表哪家企业、何时、因哪个项目改变了多少额度与有效期至。

<a id="quote"></a>
## 5. 提交报价

前提：资金方不是该项目资产方所属企业；本轮需求待报价且没有在途融资业务；项目未到期、未进入终态；授信与当前质押水位同时满足。同一轮需求同一时刻只允许一家机构报价，先成功者锁定，不提供比价和部分融资。

<a id="quote-form"></a><a id="f-ls-24"></a><a id="p-ls-05"></a>
### 5.1 报价条款与提交（F-LS-24）

适用角色与前提：资金方，授信判断为“生效且可用授信充足”。

报价只采集识别本轮申请、核对金额与必要授信摘要、本次输入和不可撤销后果所需的信息；不提供完整授信或企业档案入口，不采集报价时的池况快照，当前池况取融资需求与代币质押模块的事实。

| 字段 | 业务含义与类型 | 必填与默认值 | 可编辑性 | 校验与结果 |
| --- | --- | --- | --- | --- |
| <a id="qt-03"></a>融资金额（QT-03） | 本轮需求的 USD 金额 | 自动带出 | 只读 | 等于本轮需求金额，不支持部分融资 |
| <a id="qt-02"></a>结算币种（QT-02） | USD / USDT / USDC | 必选，无预选 | 资金方独立选择 | 不受资产方参考结算币种限制；不改变以 USD 记账 |
| <a id="qt-04"></a>折算比值（QT-04） | 所选币种对 USD 的固定比值 | 选择币种后自动带出 | 只读 | 按[固定折算与折算快照](#quote-rate)，不能手填 |
| <a id="qt-05"></a>结算金额（QT-05） | 融资金额按固定比值折算的金额 | 选择币种后自动带出 | 只读 | 按[固定折算与折算快照](#quote-rate) |
| <a id="qt-06"></a>年化融资利率（QT-06） | 百分比 | 必填，无默认值 | 可编辑 | 大于 0 且不超过 100%，最多两位小数；同时说明“计息规则以双方签署的融资合同为准” |
| <a id="qt-15"></a>还款类型（QT-15） | 按季付息；到期还本付息 | 自动带出 | 只读，不提供其他选项 | — |
| <a id="qt-16"></a>最终还款日（QT-16） | 等于本项目的有效期至 | 自动带出 | 只读 | 不另设维护入口；不按查看者当地日期另生日期 |
| <a id="qt-09"></a>报价时间（QT-09） | 平台确认报价成功的时刻 | 成功时记录 | 只读 | — |

- 资金方的还款收款账户在放款时登记，报价与接受时都不采集、不展示、不校验，也不能成为隐藏的必填项。
- 提交前须能看到这些后果：提交后不可修改、不可撤回；锁定本轮需求，其他机构不能再报价；本机构在途报价金额增加；只有资产方拒绝或所属需求终结才会退出。
- 提交即终检，不设二次确认。
- 成功即结束本次办理，刷新原申请与相关办理入口，不自动打开详情。
- 失败时说明原因并保留可复用的输入；项目已到期、需求已撤下或已被报价等状态变化须明确说明，不用旧数值引导继续提交。
- 授信已成功但报价失败的，授信保留，不生成融资业务编号。

<a id="quote-rate"></a><a id="f-ls-26"></a>
### 5.2 固定折算与折算快照（F-LS-26）

适用角色与前提：资金方提交报价时；资产方、放款与还款沿用。流程见[固定折算与逐笔沿用（FL-CR-04）](./02-授信报价与接受拒绝-流程图与状态机.md#fl-cr-04)。

- 本期只支持 USD、USDT、USDC，固定 1 USD = 1 USDT = 1 USDC，并标明这是本期平台业务规则，不是外部市场价格或兑换承诺。
- 没有人工改价、审核发布、行情获取或汇率过期流程；外部行情及其是否可用都不影响报价。
- 报价成功即锁定结算金额与本笔折算快照，之后不重算。快照须能追溯四项：该币种对 USD 的比值 1、规则真实生效时间、来源为平台固定折算规则、稳定的版本标识。规则生效时间不同于本笔报价锁定时间，不填虚构的行情机构或刷新时间，也不让用户补填。
- 例：融资 100.25 USD，选三种币种中任一种，结算数值都是 100.25，单位分别正确，不收折算差额；预览与最终条款一致。
- 放款复用锁定的本金金额；还款按本期应还本息与原快照折算，不能把融资本金当作每期本息。同一原金额、同一快照重复折算结果相同。
- 每笔在途与未偿本金都用自己的成功快照；不改写旧业务，也不把旧业务的快照借给新报价。
- 固定依据缺失、不完整或实际不是 1:1 时，拒绝新报价并说明“暂时无法确认本笔折算依据，请稍后重试”：不改用外部行情或旧快照，不生成编号、占用或锁定，也不因此判定需求失效。已锁定且依据完整的业务照常沿原快照履约。已拒绝或已失效报价的快照只用于历史，不能恢复为可放款业务。

金额精度：

| 金额类别 | 精度与处理 |
| --- | --- |
| USD 授信额度、需求金额与融资金额 | 输入最多两位小数，USD 展示两位，计算过程不提前舍入；手续费不冲减约定本金 |
| USD 每期利息 | 按[还款计划规则](../08-借贷广场-还款计划与还款确认/01-还款计划与还款确认-PRD.md#f-plan)：逐期独立两位、四舍五入、不跨期结转；本模块不另定计息 |
| USDT / USDC 结算金额 | 按 1:1 确定数值，放款同源复用；展示截断不能改变付款金额。最大小数位、最终舍入与尾差处理待确认，见[待确认事项 Q-CR-09](#q-cr-09) |

<a id="quote-coverage"></a><a id="f-ls-36"></a>
### 5.3 提交时复核质押水位（F-LS-36）

适用角色与前提：资金方正式提交报价时。

- 按融资需求与代币质押模块的[质押水位（INV-FIN-01）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#water-level)与[需求因质押水位不足失效（F-LS-19）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-19)使用当前权威事实，包括有效质押额（有效质押价值 × 项目质押率）、逐笔累计、失效顺序与停止条件。
- 不能用总质押额、待审质押额或打开报价时的旧数值判断，也不能漏算更早保留的需求。
- 已发布需求的报价只校验已有的有效质押额与授信，不因可融金额为 0 单独禁止报价。报价不重复增加项目在途金额。
- 当场证实质押水位不安全：本轮需求按融资需求与代币质押模块的规则自动失效，本次报价不成立；说明“该融资需求已失效（质押水位不足）”，由资产方补足质押后重新发布，不归咎报价机构，没有缓冲期。
- 当前质押水位暂时无法取得：只拒绝本次提交，说明“暂时无法完成质押校验”，不把未知当作不足而使需求失效。

<a id="quote-lock"></a><a id="f-ls-25"></a><a id="fd-01"></a>
### 5.4 生成融资业务并锁定需求（F-LS-25）

适用角色与前提：资金方报价通过终检。

- 同一事件内完成：生成稳定的融资业务编号（FD-01）、锁定折算快照、记录报价时间、增加本机构在途报价金额、本笔进入待接受，并向融资需求与代币质押模块提供锁定结果；项目在途金额不变。
- 报价自此不可修改、不可撤回。
- 失败时不预占编号，不产生新的占用或锁定；当场证实质押水位不安全的，仍按[提交时复核质押水位](#quote-coverage)使原需求失效。
- 两家机构同时提交时只有一笔成功；另一方被告知“已被报价”，不生成编号，不新增占用。
- 报价成功后通知该需求的资产方，见[消息通知](./03-授信报价与接受拒绝-消息通知.md)。

<a id="quote-expiry"></a><a id="f-ls-31"></a>
### 5.5 锁定信息的展示（F-LS-31）

适用角色与前提：本笔资产方与报价机构；可见范围按[角色与可见范围](#roles)。

- 项目的融资申请信息清单保留本轮锁定摘要；融资申请详情与资产方的我的控制台显示报价机构全称、锁定起始与已锁定时长。
- 锁定没有截止时刻：不显示剩余时间、倒计时或临期强调。已锁定时长通常精确到小时，并标注时区；接受或拒绝后停止累计。
- 公开说明保持中性；资产方可以随时拒绝，不受时限催促。

<a id="f-ls-34"></a>
### 5.6 报价的持续有效与退出路径（F-LS-34）

适用角色与前提：已进入待接受的报价。

- 报价成功后一直待接受，没有有效期、截止时刻、倒计时或自动失效，也没有续期、展期与宽限；长时间无人处理、无人登录都不改变结论，不释放任何占用。
- 待接受只有三条退出路径：资产方接受、资产方拒绝、所属需求终结使本笔连带失效。
- 资金方提交后不能撤回、不能修改，也没有催办动作，这是[按用户决定保留的业务限制](#limits)。
- 拒绝或连带失效后释放本笔在途报价金额，需求按融资需求与代币质押模块的事实处理；项目在途金额与质押不因拒绝而释放。
- 已终结的融资业务编号保留；需求仍有效、项目未到期且满足资格时，任何机构（包括原机构）都可以重新报价，没有冷却期和次数上限；重新报价生成新编号与新快照，不是原报价续期。

<a id="quote-combo"></a>
待接受报价在不同情形下的结果：

| 情形 | 资产方能否接受 | 资产方能否拒绝 | 用户看到的结果 |
| --- | --- | --- | --- |
| 正常待接受 | 能，完成账户确认与摘要查看后提交 | 能 | 已锁定时长持续累计 |
| 报价后授信到期 | 能 | 能 | 授信到期只阻止新报价，不影响本笔 |
| 质押持平但质押水位安全 | 能；接受环节不另设质押闸门 | 能 | 照常办理 |
| 质押水位变为不安全 | 不能 | 不能 | 需求按融资需求与代币质押模块自动失效，本笔连带失效，终结原因“自动失效·质押水位不足” |
| 项目到期 | 不能 | 不能 | 需求随项目到期终结，本笔连带失效，终结原因“项目到期” |
| 没有可用的收款账户或读取失败 | 不能，先到企业账户登记或稍后重试 | 能 | 分别说明尚未登记或暂时不可用 |
| 已接受、已拒绝或已失效 | 不能 | 不能 | 只读查看结果，不能凭保留的进度继续提交 |

<a id="respond"></a><a id="p-ls-06"></a>
## 6. 资产方接受或拒绝报价

适用角色与前提：本企业资产方；本笔报价仍待接受。流程见[接受与拒绝（FL-CR-02）](./02-授信报价与接受拒绝-流程图与状态机.md#fl-cr-02)。

资产方从“融资”业务入口选定本笔报价办理，先核对：报价机构的业务名称与允许公开的认证状态、项目编号、融资申请编号、融资业务编号、金额、结算币种、年化利率、折算快照、还款类型、最终还款日、报价时间、已锁定时长，以及当前池况与质押情况。不提供机构档案或认证材料的完整查看，不展示资金方的还款收款账户，不提供报价时的池况快照。

<a id="respond-plan"></a>
**预计还款计划。**

- 报价详情与接受办理中可以按需查看预计还款计划：由[还款计划与还款确认](../08-借贷广场-还款计划与还款确认/01-还款计划与还款确认-PRD.md)以报价提交日为预计放款日生成，整张计划标注“预计·未生效”，日期称“预计还款日”，没有有效期次或还款期次编号。
- “放款确认后将按实际放款日重新计算”的告知在接受前须始终可得，并记录展示时间；不以是否查看计划为条件，不新增勾选。查看计划前后，办理步骤与已选内容不丢失。
- 历史报价的预计计划只随历史只读，不成为应还计划；正式计划在还款信息中查看。

<a id="respond-account"></a><a id="f-ls-28"></a>
### 6.1 选用并确认本笔收款账户（F-LS-28）

适用角色与前提：本企业资产方，办理接受时。

- 接受依次完成：选用并确认本笔收款账户 → 查看可复制、可打印的商务摘要 → 提交接受。中途可以中断再继续，已确认的账户与进度保留；这些只是待接受内的办理进度，停留多久都不改变结论。拒绝不需要先完成这些步骤。
- 这里选的是资产方接收本笔放款的账户，接受成功后交放款使用；不是资产方以后还款的出账账户。资金方的还款收款账户由放款模块登记。不新增独立的出账账户，不默认收付账户相同。
- 选用规则沿[企业账户的业务办理中选用账户（F-EA-07）](../03-企业账户/01-企业账户-PRD.md#f-ea-07)：
  - 只能从本企业已登记的账户中选用，办理中没有新增、编辑或删除账户的入口，也不能手输账户信息。
  - USD 结算只能选法币账户，可选范围不按账户币种或账户类型筛选；所选法币账户须具备[企业账户定义的法币账户必填项](../03-企业账户/01-企业账户-PRD.md#f-ea-02)。
  - USDT 或 USDC 结算只能选数币账户；选中后带出该账户的结算收款链（ETH 或 TRON）与数币地址，本笔只读，不能换链、改地址或换钱包。不能用质押代币当前的持有地址代替。
  - 信息不完整的账户列出并说明缺什么，但不能作为本笔账户提交。
  - 没有可用账户时直接说明尚未登记并引导到企业账户；读取失败时说明暂时不可用并可重试。
- 本模块的带出顺序：先带出本笔已确认过的选择，其次带出本企业最近一次成功接受中同一结算币种类别的账户；任何带出都不等于已选定，每笔须显式确认，默认未确认，改选后原确认失效。
- 提交接受时再校验一次：所选账户已被删除或修改的，本次接受不成立，说明账户已变更并要求重新选用。
- 平台不采集收款人名称，不校验账户是否属于本企业，不验证银行账户真实性或汇路可达性，不显示“账户已验证”；后果见[按用户决定保留的业务限制](#limits)。
- 普通摘要中的账户脱敏；资产方接受时可核对本企业完整的账户信息；接受后，本笔的付款当事方在放款中可受控核对完整账户。非当事方不能读取；脱敏不能妨碍有权付款方付款。

<a id="respond-fee"></a>
**跨境手续费告知。**

- 接受前须始终可得以下告知：“跨境手续费由您承担；到账金额会少于融资金额，但偿还本金仍按融资金额{X} USD计算。”
- 汇出、中转、入账费用都由资产方承担；平台不预估、不代收、不垫付，不提供预估手续费或实收金额的输入。
- 告知写入商务摘要并记录展示时间，不另设勾选。
- 债务本金与占用不按扣除手续费后的实收金额减少（例：融资 150 万 USD、扣费后实收 1,499,750 USD，偿还本金与两个维度的占用仍为 150 万 USD）。

<a id="respond-contract"></a><a id="f-ls-29"></a>
### 6.2 核对商务摘要并接受（F-LS-29）

适用角色与前提：本企业资产方；本笔收款账户已确认。

- 合同由双方线下拟定与签署。平台不生成合同、不提供模板下载、不以模板配置作为接受前提。
- 商务摘要可复制、可打印，明确“本摘要不是合同，不产生法律效力”；内容包括项目编号、融资申请编号、融资业务编号、双方企业全称、USD 本金、结算币种与结算金额、完整折算快照、年化利率、当前抵押物概况、报价时间、还款类型、最终还款日、手续费与本金告知，与本笔事实一致。
- 接受不收取任何合同文件，没有份数、格式或大小校验，也没有“条款与摘要一致”的勾选声明；平台不保管、不转交、不核验合同，合同争议由双方线下解决。
- 接受成功的条件：收款账户已确认、商务摘要已查看、本笔仍待接受。
- 接受成功的结果同时成立：
  - 本笔转为待放款，并向融资需求与代币质押模块提供接受结果，项目进入融资中，需求对外显示放款中；
  - 机构与项目两个维度的在途金额都保持，不提前转为本金；
  - 同一融资业务编号立即出现在融资放款信息中，不等待放款编号；尚未登记放款时显示“尚未提交放款记录”；
  - 原报价资金方收到一次“融资报价已接受”站内信；放款模块不为同一次接受补发消息。
- 待放款没有时限，也没有平台侧的终止出口，唯一出口是资金方提交放款，见[按用户决定保留的业务限制](#limits)。
- 接受成功后更新本笔与相关办理入口，不自动打开下一项业务。

<a id="respond-reject"></a><a id="f-ls-30"></a>
### 6.3 拒绝及并发结果（F-LS-30）

适用角色与前提：本企业资产方；本笔报价仍待接受。

- 拒绝原因必填，自由文本 1～200 字，无默认值、不分类、不审核；对报价机构可见，不向游客或其他企业公开。
- 拒绝不需要先确认账户或查看摘要，没有冷却期。
- 拒绝成功的结果同时成立：本笔为已拒绝；释放本笔在途报价金额；需求仍有效时回到待报价；项目在途金额与质押不变；通知原报价资金方。
- 拒绝是本笔报价唯一的人工退出途径：资金方不能自行撤回；本轮需求也须先拒绝报价、回到待报价后才能撤下或修改金额。
- 授信在报价成功后到期，不影响本笔接受或拒绝。
- 项目在报价后到期时，本轮需求随之终结，本笔连带失效、不能再接受，按[需求终结与报价连带失效](#demand-invalid)处理。项目有待确认报价时不能主动关闭，见[融资需求与代币质押的未处理完成的业务](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#unfinished-business)。
- 接受环节不另设质押闸门：质押水位一旦不安全，需求即自动失效、本笔连带失效；水位仍安全时（包括质押持平）照常可以接受。接受本身不增加金额。
- 接受与需求终结竞争：需求先终结则报价一并失效，不能接受；有效接受先完成则转为待放款，不回翻为报价失效，之后的质押情况由放款环节判断。
- 同一笔的接受、拒绝与连带失效只有一个最终结果，以平台确认时本笔仍待接受为准；已处理后的重复提交在本次办理内说明最新结果并停用旧动作，保留可见历史。

## 7. 占用的保留、转移与释放

状态见[融资业务本模块状态（ST-CR-02）](./02-授信报价与接受拒绝-流程图与状态机.md#st-cr-02)。

<a id="allocation"></a><a id="f-ls-27"></a>
### 7.1 机构与项目两个维度（F-LS-27）

- 机构维度的在途报价金额包括待接受、待放款、待放款确认三个阶段；放款确认之前不转为授信占用额。
- 项目维度的额度只引用融资需求与代币质押模块的定义。

| 事件 | 机构维度 | 项目维度 |
| --- | --- | --- |
| 报价成功 | 增加本笔全额在途报价金额 | 发布需求时已计入项目在途金额，不重复增加 |
| 接受、待放款、待放款确认 | 保留在途报价金额，不转为授信占用额 | 保留项目在途金额 |
| 资产方拒绝 | 释放本笔在途报价金额，不转为本金 | 需求仍有效时解锁回到待报价；项目在途金额与质押保持 |
| 需求终结（项目到期、自动失效·质押水位不足） | 待接受报价连带失效，释放本笔在途报价金额 | 融资需求与代币质押模块同一事件终结需求，并释放其项目在途金额 |
| 放款确认完成 | 本笔全额在途报价金额转为授信占用额 | 同笔全额项目在途金额转为项目融资余额；两个维度同时转移，没有空档也不重复计算，按约定本金而非实收金额 |
| 还款经资金方确认 | 按已偿本金逐期减少授信占用额，结清后本笔归零 | 项目融资余额等额减少；利息与手续费不算本金释放 |

- 本笔贡献的授信占用额与在途报价金额，只在三条终结路径之后归零：资产方拒绝、需求终结连带失效、结清；不误清其他存量。
- 授信到期、接受成功、逾期标记都不提前释放；时间流逝本身不释放任何占用。
- 项目到期只连带终结尚未成交的待接受报价，不释放已成交存量债务的占用。
- 单笔融资业务没有中途终止出口，见[融资需求与代币质押的单笔融资业务没有中途终止出口（D-LS-64）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-64)；某笔长期停在待放款或待放款确认，不会使项目自动回到募集中、恢复新融资资格或释放整池。
- 已到期项目不开放发布与报价；未到期项目按全部存量、有效质押额与质押水位判断资格；其他债务继续履约。

<a id="demand-invalid"></a><a id="f-ls-35"></a>
### 7.2 需求终结与报价连带失效（F-LS-35）

流程见[需求终结与连带失效（FL-CR-03）](./02-授信报价与接受拒绝-流程图与状态机.md#fl-cr-03)。

- 融资需求与代币质押模块判定本轮需求终结时，本模块把仍待接受的报价置为已失效。会使在途报价连带失效的终结原因只有两种：项目到期、自动失效·质押水位不足。
- 项目关闭不会使在途报价失效：有待确认报价的项目不能关闭，关闭时一并终结的只有尚未收到报价的需求。
- 需求终结、项目在途金额释放、本笔在途报价金额释放在同一事件内完成；不出现“需求已终结但报价仍可接受”或金额未释放的中间状态。
- 报价失效只有一种原因“所属融资需求终结”，同时记录需求的具体终结原因与实际终结时刻，不记成未来时刻。
- 系统失效不要求拒绝原因，不计入拒绝率，不给机构负面记录。
- 没有缓冲期或恢复倒计时；补足质押不恢复原报价，只能按融资需求与代币质押模块重新发布后重新报价。
- 需求终结及其对报价的影响，由融资需求与代币质押模块的[融资需求终结通知（N-LS-05）](../05-借贷广场-融资需求与代币质押/03-融资需求与代币质押-消息通知.md#n-ls-05)合并发给资产方与在途报价的资金方；本模块不发送任何报价失效消息，但仍负责本笔状态与占用释放。
- 并发或重复处理不产生第二次状态变化、释放或消息。

### 8.1 当前报价、历史与跨入口定位（F-LS-32）

适用角色与前提：本笔资产方与报价机构；其他身份按[角色与可见范围](#roles)。

**融资申请与报价记录。**

**需求对外状态。**

- 需求对外状态（待报价、已报价待确认、放款中、已放款、已失效或已关闭）由融资需求与代币质押模块派生，列表、详情与我的控制台一致，本模块不另建。

### 8.2 本模块发送的站内信（F-LS-33）

- 本模块发送三类站内信：收到融资报价（发资产方）、融资报价已接受（发原报价资金方）、融资报价已拒绝（发原报价资金方）。触发、收件、内容与落点见[消息通知](./03-授信报价与接受拒绝-消息通知.md)。

<a id="limits"></a>
## 9. 按用户决定保留的业务限制

以下是用户明确裁定后的既定结果，如实记录业务后果，供研发与测试知悉，不作为缺陷处理。

1. **报价一经提交，资金方无法撤回。** 退出只有资产方拒绝，或所属需求终结带来的连带失效。若资产方长期不处理，该笔持续占用本机构的在途报价金额，本轮需求也持续锁定；平台不提供撤回、修改、催办或自动到期释放。
2. **平台不采集收款人名称，也不校验账户归属。** 受益人名称由双方在平台外补充；平台不具备“收款账户必须属于本企业”的自动校验能力，账户选错的后果由双方线下承担。
3. **待放款与待放款确认都没有终止出口和时限。** 待放款的唯一出口是资金方提交放款，待放款确认的唯一出口是资产方确认到账。若线下协商结果是不放款，平台侧没有任何动作能终结该笔业务：本笔持续停留，机构与项目两个维度的在途金额持续保留，资产方不能发布新一轮需求，对应质押代币持续被占用。

<a id="questions"></a>
### 10.2 待确认事项

<a id="q-cr-08"></a>**Q-CR-08 账号 / IBAN 的地区校验（已关闭）。** 放款、还款与原型仍引用此编号，故保留一句结论：账号 / IBAN 的校验归[企业账户的文本长度与字符规则](../03-企业账户/01-企业账户-PRD.md#text-limits)，本期不按地区校验、只限长度；本模块不另设账户字段校验。

<a id="q-cr-09"></a>**Q-CR-09 数币结算精度。** USDT/USDC 结算金额的最大小数位、最终舍入与尾差处理尚待统一批准，放款与还款共用。影响：报价、放款、还款中数币金额的边界值。当前处理：按 1:1 确定数值，展示截断不改变付款金额；不以演示用的两位或代币六位展示宣称边界已定。

<a id="q-cr-11"></a>**Q-CR-11 非当事资金方能否看到他方报价的机构与利率。** 冲突点：融资需求与代币质押模块的融资申请信息清单列出“当前有效或已接受报价的机构与年化利率”，资金方可查看所有已发布项目的四类记录；但同一模块的[项目详情按身份的可见范围（F-LS-82）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-82)规定报价条款只对本笔资产方与报价机构开放。影响：非当事资金方在项目详情看到的锁定信息、本模块的[锁定信息的展示](#quote-expiry)与相关验收。当前处理：本册按私有边界写，即报价机构、年化利率与已锁定时长只对本笔资产方与报价机构开放，非当事资金方只看到需求状态“已报价待确认”；待用户裁定后两册同改。

<a id="q-cr-12"></a>**Q-CR-12 授信异常的运营承接。** 冲突点：授信已用额超过授信额度、同一机构对同一资产方出现多条授信关系时，本册规定交由运营处理，但运营端没有任何模块承接这类待办。影响：异常发生后无人处理，该机构对该资产方的新报价持续被停止。当前处理：停止新报价、按最早生效的关系计量这两条照常执行；运营待办是否需要、由哪个模块承接，待用户裁定；若不需要，本册删除“交由运营处理”。

<a id="q-cr-13"></a>**Q-CR-13 报价资格的权限矩阵取值。** 冲突点：[主干权限矩阵“发起出资 / 授信报价”](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#permission-9)对入驻审核中或已驳回的资金方、已认证资金方两列仍为“待所属模块填写”，“签署协议 / 下载合同”一行的资金方两列同样未填。影响：哪些资金方能看到并使用“立即报价”、能否下载授信协议。建议：已认证资金方完整可用；入驻审核中或已驳回的资金方能看到入口但不能提交，触达时给出引导（硬卡点）；授信协议的下载按本笔当事方开放。待用户确认后回填主干矩阵。

<a id="q-cr-14"></a>**Q-CR-14 跨模块同号不同义。** 冲突点：本模块的功能编号 F-LS-20～F-LS-22 与融资需求与代币质押模块的同号功能含义不同；本模块验收册的 AC-LS-97～AC-LS-120 中多条与该模块验收册同号不同义；AC-MC-11 与我的控制台模块自己的同号验收不同义。影响：测试与研发按编号追溯时可能定位错册。当前处理：编号锚点按约定不动，各册引用时带模块名；是否为本模块重新分配专属前缀，待用户裁定。
