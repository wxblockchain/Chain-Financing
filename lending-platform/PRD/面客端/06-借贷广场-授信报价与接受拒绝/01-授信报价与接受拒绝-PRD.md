<a id="scope"></a>
## 1. 模块是什么

资金方对一轮融资需求报价前，平台先做授信核验：核验本机构对该项目发布企业的授信是否存在、是否在有效期内、可用额度是否足够。核验不通过时，资金方当场办理企业授信（首次授信、追加授信或重新授信）。核验通过后进入报价：报价分两步：资金方先填写结算币种、放款地址、还款收款地址与利率（页面以弱提示显示放款地址的可用余额），并用放款地址签名确认这些报价信息（不上链），签名后直接进入第二步发起授权，用放款地址签名授权本项目的放款合约调取本笔结算金额，这一签名就是提交报价，授权上链成功即报价成功，并锁定这一轮需求。资产方核对商务摘要与发布时选定的融资收款地址后，用本轮融资收款地址签名，这一签名就是接受，平台执行钱包随即签名执行链上放款：放款合约按授权从放款地址调取本笔结算金额，转入融资收款地址；上链成功即接受成功、放款完成，本笔进入还款。资产方也可以填写原因直接拒绝，拒绝不需要签名；拒绝后资金方可以撤销本笔授权。本模块负责授信核验与企业授信、报价前的放款地址与授权、报价锁定、接受与链上放款、拒绝与撤销授权、需求终结时报价的连带失效，以及相关的记录展示与站内信。

基本原则：

- 本模块不涉及法币（用户 2026-10-21 要求）：结算币种只有 USDT、USDC；授信额度、融资金额、在途报价金额与授信占用额都以 USDT 计。融资需求金额同样以 USDT 计（用户 2026-10-22 裁定），与融资需求与代币质押一致。
- 授信是“一家资金方机构 × 一家企业”的关系：授信给的是企业，不是某个项目或某个角色账号；同一企业发布的所有项目共用这份授信，不按项目拆开。
- 首次授信只在报价时就地办理，没有独立的授信菜单；授信保存后须由用户再次发起报价。资金方另可从我的控制台授信详情[修改授信](../09-我的控制台/01-我的控制台-PRD.md#credit-modify)（追加额度、后延有效期至或到期后重新授信），规则同本模块。
- USD、USDT、USDC 之间固定按 1:1 折算，本期不设汇率管理（用户 2026-10-28 裁定）：结算金额与以 USDT 计的融资金额数值相同，见[结算金额与 1:1 折算（F-LS-26）](#quote-rate)。
- 报价分两步办理：先填写并签名确认报价信息，再发起授权（用户 2026-10-23 要求）。第一步填写后用放款地址对报价信息签名，这一签名不上链、不提交报价，由平台保存，在后续放款时核验，用于防止报价信息被篡改（用户 2026-10-26 裁定只核验、不上链，2026-10-27 要求放款时核验）；签名完成即进入第二步，不另设“下一步”（用户 2026-10-26 要求）。提交报价的动作只有一个，就是第二步的签名授权：签名授权就是提交报价，授权之后没有单独的“提交”（用户 2026-10-22 裁定）。签名前须选定放款地址并通过余额校验；资金方用放款地址签名授权本项目的放款合约调取本笔结算金额（用户 2026-10-21 要求），授权上链成功即报价成功。授权由资金方用放款地址签名并发送交易（放款地址可以不是登录地址，用户 2026-10-22 裁定），gas 由资金方承担。报价时同时填写还款收款地址，默认与放款地址相同（用户 2026-10-22 裁定）。
- 报价没有有效期：提交后一直待接受，资金方不能撤回或修改，退出只有资产方拒绝，或所属需求终结带来的连带失效。
- 接受即放款（用户 2026-10-21 要求），接受也只有一个动作（用户 2026-10-22 裁定）：资产方用本轮融资收款地址签名就是接受（用户 2026-10-23 要求），平台拿到签名后由平台执行钱包签名执行链上放款，上链成功才算接受成功、放款完成；资产方不承担 gas，签名之后不再有确认或提交动作。接受之后不再有独立的放款登记与放款确认环节，本笔直接进入还款。
- 资产方拒绝不需要签名、不发生链上操作；拒绝后资金方可以撤销本笔授权（用户 2026-10-21 要求），报价因需求终结失效的同样可以；撤销在我的控制台的“链上授权”清单中办理，规则见[链上授权（F-MC-14）](../09-我的控制台/01-我的控制台-PRD.md#f-mc-14)与[撤销授权（D-MC-214）](../09-我的控制台/01-我的控制台-PRD.md#d-mc-214)（用户 2026-10-23 确认新开“链上授权”清单，见[链上授权的归集方式（Q-MC-66）](../09-我的控制台/01-我的控制台-PRD.md#q-mc-66)）；“我的报价”只显示本笔授权状态。
- 平台内所有地址签名都只用于授权合约或执行链上交易，与登录无关：用放款地址签名不切换、不结束当前登录；资产方用融资收款地址签名接受，同样不是登录动作，签名前后登录状态不变（用户 2026-10-22 裁定）。
- 资产方收放款的地址就是本轮发布时选定的[融资收款地址（FP-40）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-40)，接受时只读核对，不再另选。
- 平台不生成、不收取、不核验融资合同；双方线下签署合同，接受时核对本笔的商务摘要。
- 全流程没有倒计时，平台不因等待自动改变任何结论，也不因时间流逝释放任何占用。

**一个完整的例子。** 资产方甲的一个项目发布了一轮 150 万 USDT 的融资需求，发布时选定了本企业的 Ethereum 数币账户“甲收款钱包”作为融资收款地址。已认证资金方乙在项目详情点击“立即报价”，授信核验发现乙对甲的企业尚无授信，直接进入企业授信，页面一句话说明“本机构尚未给该企业授信”；乙填写授信额度 500 万 USDT、有效期至一年后，本次授信协议选择不上传，保存成功，看到“已授信，请继续报价”。乙再次点击“立即报价”，进入报价：融资金额 150 万 USDT 已带出且不可改。乙选择结算币种 USDC，看到按 1:1 折算的结算金额 1,500,000 USDC；乙在放款地址下拉选项中看到网络 Ethereum、备注名“乙放款钱包”和缩写地址，选定该已登记数币账户，下方以弱提示显示“可用余额 2,000,000 USDC”；还款收款地址随之默认为同一地址，乙保持不变；乙填写年化利率后点击“签名确认报价信息”，用“乙放款钱包”在钱包中签名确认本次报价信息（不上链、不产生费用），签名完成后直接进入第二步。乙在第二步看到已签名的报价信息、本次授权的放款合约（Ethereum 与完整合约地址）、一句签名用途说明（授权该合约调取 1,500,000 USDC 并提交本笔报价，gas 由本机构承担），以及“提交后不可修改、不可撤回，本轮需求将被锁定”等后果，点击“授权并报价”，用“乙放款钱包”在钱包中签名授权本项目的放款合约调取 1,500,000 USDC；签名发出后本轮需求先为乙的报价预占，授权上链成功即报价成功。平台生成融资业务编号，本轮需求变为已报价待确认，甲收到“收到融资报价”站内信。甲从“融资”业务入口选定这笔报价，在接受操作页核对关键条款和融资收款地址“甲收款钱包”的摘要；操作页同时给出执行本笔放款的放款合约和签名用途说明（确认接受本笔报价，平台据此执行链上放款；签名本身不上链、不收费）；甲按需到融资申请详情查阅完整条款并返回本笔办理，点击“接受并收款”，平台核验乙在报价时签名的报价信息与本笔条款一致后，甲用融资收款地址“甲收款钱包”在钱包中签名；平台核验甲的签名并再次核验乙的报价签名后，由平台执行钱包签名执行链上放款，放款合约从“乙放款钱包”调取 1,500,000 USDC 转入“甲收款钱包”，上链成功即接受成功、放款完成。平台生成放款编号，本笔进入还款中；甲与乙在融资申请详情的操作记录中可看到“报价授权”和“链上放款”两条，交易哈希缩写展示，点击即复制完整值，也可跳转区块链浏览器核对；乙收到“融资报价已接受，已放款”站内信，甲收到“融资放款已到账”站内信，本笔交还款模块生成还款计划。如果甲改为拒绝并填写原因，不需要签名，本笔立即为已拒绝；乙收到“融资报价已拒绝”站内信，乙的在途报价金额释放，本轮需求回到待报价，任何机构（包括乙）都可以重新报价；乙可以在我的控制台的“链上授权”清单中用“乙放款钱包”签名撤销本笔授权。

<a id="out-of-scope"></a>
### 1.1 本期不做

- 法币结算、法币账户与跨境手续费（用户 2026-10-21 要求删除法币相关内容）。
- 授信审批、额度主动调低、冻结与解冻。
- 多家机构同时报价、比价与部分融资。
- 报价的修改、撤回、展期，以及报价有效期、临期提醒与自动到期。
- 平台生成合同、提供合同模板、收取或核验合同盖章件。
- 汇率管理与可变汇率：USD、USDT、USDC 固定按 1:1 折算，不设汇率配置与汇率快照，也不取外部行情。
- 平台代资金方签名授权或撤销授权，或代付、垫付授权与撤销授权的 gas。
- 接受时另选或更换收款地址（收款地址在发布融资需求时选定）。
- 独立的放款登记、放款确认与到账核对，以及平台外付款（用户 2026-10-21 要求：放款为链上操作）。
- 账户与地址的新增、修改、删除（归[企业账户](../03-企业账户/01-企业账户-PRD.md)）。
- 链上放款的部分放款、分次放款、撤销或退回；单笔融资业务的中途终止。
- 运营代报价、代接受，以及本模块向运营发送的消息。

<a id="glossary"></a>
## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 授信核验 | 资金方点击“立即报价”后，平台核验本机构对被授信企业的授信是否存在、是否在有效期内、可用额度是否足够；核验本身不改变任何授信 |
| 企业授信 | 核验不通过时，资金方为该企业办理的授信：首次授信（尚无授信）、追加授信（可用额度不足）、重新授信（已到期） |
| 被授信企业 | 授信的对象，即本项目的发布企业（项目发布方）；它是一家企业，不是“资产方”这一账号角色 |
| 授信 | 一家资金方机构对一家企业授予的融资额度关系，有稳定的授信编号，该企业发布的所有项目共用 |
| 授信额度 | 该机构对该企业的授信总额，USDT |
| 授信占用额 | 该机构对该企业已链上放款成功、尚未偿还的本金，USDT |
| 在途报价金额 | 该机构已提交、尚未转为本金的报价融资金额合计，USDT；即待接受（含链上放款处理中）的报价 |
| 授信已用额 | 授信占用额与在途报价金额之和；不是第三种独立的占用 |
| 可用授信 | 授信额度减授信已用额，最小为 0 |
| 授信有效期至 | 授信的最后有效日（UTC 业务日期，含当天）；只决定能否提交新报价，与报价、最终还款日无关 |
| 报价（融资业务） | 资金方对一轮融资需求提交的一次全额出资条款；成功即生成融资业务编号（FD-01） |
| 待接受 | 报价成功后、资产方接受或拒绝之前的状态；没有截止时刻 |
| 连带失效 | 所属融资需求终结时，仍待接受的报价随之失效；失效原因只有“所属融资需求终结” |
| 1:1 折算 | USD、USDT、USDC 之间固定按 1:1 折算，结算金额与融资金额数值相同；它是平台业务规则，不是外部市场价格或兑换承诺 |
| 放款地址 | 资金方为本笔报价选定的出款地址，从本机构已登记的 Ethereum 数币账户中选；余额校验、授权与撤销授权都针对这个地址，签名也由这个地址完成 |
| 还款收款地址 | 资金方为本笔报价填写的、将来接收资产方还款的地址；默认与放款地址相同，可以另选 |
| 放款合约 | 每个项目一份，只属于本项目；由平台在项目审核通过时为本项目部署，规则见运营端项目合约管理的[通过并部署合约（F-CM-09～F-CM-11）](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#m3)；本模块只读取本项目的部署结果 |
| 授权（放款） | 资金方用放款地址签名并上链的交易，允许本项目的放款合约从放款地址调取本笔结算金额；签名授权就是提交报价，授权本身不转移资金 |
| 报价信息签名 | 报价第一步中资金方用放款地址对本次报价信息所作的签名；不上链、不产生 gas、不提交报价，也不预占需求；由平台保存，放款时核验。签名后报价信息有任何变化，原签名作废，须重新签名 |
| 报价处理中 | 资金方签名授权已发出、授权交易尚未上链确认的阶段；本轮需求为这笔报价预占，其他机构不能报价 |
| 链上放款 | 资产方签名接受后，平台执行钱包在本项目放款合约上执行的交易：按本笔授权从放款地址调取本笔结算金额，转入融资收款地址；上链成功即接受成功、放款完成 |
| 放款编号 | 链上放款成功时生成的本笔放款记录标识（LN-01），供还款与我的控制台区分多笔业务 |
| 撤销授权 | 资金方用放款地址签名并上链的交易，收回本笔报价的授权 |
| 交易哈希 | 一笔已发出的链上交易的唯一编号，可在 Ethereum 区块链浏览器查到这笔交易。本模块有两类：授权交易哈希（资金方授权并报价时发出的授权交易）与放款交易哈希（平台执行钱包发出的链上放款交易）。资产方接受时的签名与报价条款确认不是链上交易，没有交易哈希 |
| 平台执行钱包 | 平台配置的钱包地址，在资产方签名确认后代为签名执行本笔链上放款；gas 由该钱包承担。定义沿[融资需求与代币质押的术语](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md) |
| 商务摘要 | 本笔条款的汇总：接受操作页展示办理必需的关键条款，融资申请详情提供完整条款；接受后由平台随本笔留存，双方可在融资申请详情查看 |
| 融资收款地址 | 资产方发布本轮融资需求时选定的 Ethereum 数币账户，用于接收本轮放款；定义见[融资收款地址（FP-40）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-40)，本模块只读沿用 |
| 网络 | 放款地址、融资收款地址与放款合约所在的区块链网络，本期仅 Ethereum；网络名称一律展示为“Ethereum”，中文界面同样如此，不译为“以太坊”，也不用“ETH”缩写（用户 2026-10-22 裁定，同融资需求与代币质押） |
| 质押水位 | 融资需求与代币质押模块的判据：有效质押额不低于“项目融资余额＋项目在途金额”为水位安全，低于为水位不安全；水位不安全时需求自动失效 |
| 质押情况 | 融资需求与代币质押模块的项目级结果：质押充足、质押持平、质押不足；质押不足只用于提醒，不作需求终结原因 |
| 项目在途金额 | 已发布、尚未终结的融资需求金额合计；报价不增加它 |
| 项目融资余额 | 本项目已链上放款成功、尚未偿还的本金合计 |
| 登录未绑定角色 | 已用钱包登录，但既不是本平台资金方、也调取不到上游资产方账户的用户 |

<a id="naming"></a>
**界面名称与英文对照。** 报价与链上授权合为一步、接受与链上放款合为一步后，界面名称参考 Web3 借贷的通行叫法（loan offer、approve、revoke），让用户从名称就能看出这一步会动用资金。业务规则仍以本册各节为准；下列名称带业务含义，改动会改变用户对后果的理解，界面按此使用，具体版式由设计决定。

| 业务对象或动作 | 界面中文 | English | 用户须从名称或紧邻说明中明白的事 |
| --- | --- | --- | --- |
| 报价（融资业务） | 报价 | Loan offer | 这是已在链上授权资金的出资条款，资产方接受即放款，不是单纯的意向价格 |
| 资金方确认报价信息的动作（第一步） | 签名确认报价信息 | Sign offer details | 用放款地址签名确认已填写的报价信息；不上链、不提交、不产生费用，签名后直接进入第二步 |
| 资金方提交报价的唯一动作（第二步） | 授权并报价 | Approve & offer | 第一步只签名确认信息、不提交；第二步的这一次签名同时完成链上授权与提交报价；之后无需再确认，资产方接受时资金即从放款地址转出 |
| 资产方接受报价的唯一动作 | 接受并收款 | Accept & receive funds | 用本轮融资收款地址签名一次即接受，平台随即执行链上放款，款项转入融资收款地址，本笔进入还款 |
| 撤销资金方对放款合约的授权 | 撤销授权 | Revoke approval | 只在报价被拒绝或失效后提供；撤销后放款合约不能再按本笔授权调取资金 |
| 授权（放款） | 链上授权 | Approval | 与“授信”是两回事：授信是机构给企业的额度（Credit line），链上授权是放款地址允许放款合约调取资金（Allowance），界面不混用这两个词 |
| 报价处理中 | 报价上链确认中 | Offer pending on-chain | 签名已发出、等待链上确认，本轮需求已为这笔报价预占 |
| 链上放款 | 链上放款 | On-chain disbursement | 款项由放款合约直接从资金方放款地址转入资产方收款地址，平台不经手资金 |
| 授权交易哈希 / 放款交易哈希 | 授权交易哈希 / 放款交易哈希 | Approval tx hash / Disbursement tx hash | 这是哪一笔链上交易的编号，可复制后自行到区块链浏览器核对 |
| 放款地址 / 还款收款地址 / 融资收款地址 | 放款地址 / 还款收款地址 / 融资收款地址 | Funding address / Repayment address / Receiving address | 各自是哪一方、用来出款还是收款 |

<a id="view-and-act"></a>
### 3.2 查看与办理

- 查看与办理分开，沿[查看与办理分开（融资需求与代币质押 F-LS-20）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-20)：项目详情的记录与详情只读，不提供办理或跨业务快捷入口；办理从“融资”业务入口进入。
- 有多个待办时，先明确办理对象，不默认“最新一笔”。
- 融资办理保留“发布需求—机构报价—接受并放款”三阶段进度，分别识别已完成、当前和后续；已结束的需求不标为进行中。接受与链上放款是同一阶段，不再单列“融资放款”阶段。报价内的授权步骤与接受办理的签名步骤只是本阶段内的进度，不替代这三个阶段。
- 一次办理中的步骤、必要确认和放弃未保存修改都在本次办理内完成，不再叠加下一层办理。
- 返回上一步时保留已填内容和已成功上传的文件；有未保存修改时关闭须先确认放弃，没有修改时直接关闭。
- 关闭后回到来源，保留原筛选、分页与所在位置。
- 成功只更新本笔及相关办理入口，不自动打开详情、下一笔或下一阶段；失败保留可复用的输入；结果未知时显示待核实，不假报成功，也不引导重复提交。
- 只提供当前可以办理的动作（用户 2026-10-19 要求）；当前不能办理的动作不以不可操作的按钮呈现。需要让用户知道为何不能办理时，用说明文字告知原因：本机构自己的需求、已被其他机构报价、项目已到期、需求已终结、质押水位不安全。授信不足不属于不能办理，按[报价前的授信核验](#credit-entry)直接进入企业授信。
- 需要钱包签名的动作（签名确认报价信息、授权并报价、撤销授权、接受并收款）都只有这一个动作，以钱包内的签名为最终确认：点击即唤起钱包，点击前后都不再出现确认弹窗或勾选确认。这些签名都与登录无关，签名前后登录状态不变（用户 2026-10-22 裁定）。
- 不向用户展示条款号、字段来源、内部判据或论证；本次办理必需的金额、期限、后果与失败出路保留，授信不足时给出差额算式；资金方填写报价时，放款地址余额只按[余额校验](#quote-authorize)弱提示，不另列余额差额；资产方确认报价时按[确认报价页的放款地址与余额](#respond-balance)直接提示余额不足。

**所交互的合约、签名用途与交易哈希。**

适用于报价第二步“授权并报价”与资产方“确认报价”的“接受并收款”（报价第一步“签名确认报价信息”只适用签名用途），以及本笔在融资申请详情操作记录中的交易（用户 2026-10-26 要求）；拒绝不签名、不涉及合约，不适用。

- 所交互的合约：办理弹窗与签名主动作同时给出本次涉及的合约，即本项目所配置的放款合约，包括合约名称“放款合约”、网络“Ethereum”与完整合约地址。地址可复制完整值，也可在区块链浏览器打开该合约地址核对。报价时它是本次授权的对象；接受时它是平台据本笔授权执行放款的合约，须与本笔报价授权的合约为同一份。
- 合约地址只取平台在项目审核通过时为本项目部署的放款合约（每个项目一份，见运营端项目合约管理的[通过并部署合约（F-CM-09～F-CM-11）](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#m3)），与本笔报价已确认的合约一致，不由用户填写或选择。读取失败或与本笔已确认的合约不一致时不唤起钱包、不能签名，说明暂时不可用并可重试；接受时仍可拒绝。
- 本次签名用途：签名主动作旁用一两句话说明这次签名做什么，与已有后果说明合并，不另设确认弹窗或勾选。具体文字由设计决定，须包含以下要点：
  - 签名确认报价信息（报价第一步）：用放款地址签名确认本次填写的报价信息，防止提交前被篡改；这一签名不上链、不提交报价、不产生费用、不转移资金，与登录无关；签名后进入发起授权；平台保存这一签名，在资产方接受、执行放款时核验，报价信息本身不上链。这一步不与合约交互，合约在第二步展示；签名内容中的放款合约可在钱包中核对。
  - 授权并报价：用放款地址授权上述放款合约调取本笔结算金额（带金额与币种），同时提交本笔报价；这是一笔链上交易，gas 由本机构承担；签名本身不转出资金，与登录无关。
  - 接受并收款：用本轮融资收款地址确认接受本笔报价，平台随即通过上述放款合约把本笔结算金额从资金方放款地址转入融资收款地址；这一签名本身不上链、不产生费用，与登录无关。
- 交易哈希：只有已发出的链上交易才有交易哈希。本模块展示[授权交易哈希（QT-19）](#qt-19)与[放款交易哈希（LN-08）](#ln-08)；报价第一步的报价信息签名与资产方的接受签名都不是链上交易，不显示为交易哈希，也不提供区块链浏览器跳转。撤销授权的交易记录在[我的控制台的链上授权](../09-我的控制台/01-我的控制台-PRD.md#revoke)查看。
- 详情中，这两类交易哈希只在[融资申请详情的操作记录](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#application-detail)展示：每笔报价的授权交易一条“报价授权”（含已拒绝、已失效的报价），每次链上放款交易一条“链上放款”（用户 2026-10-26 要求整合，避免同一信息多处展示）。当前报价、报价历史与链上放款记录只展示业务事实，不重复交易哈希。操作记录的格式、地址取值与逐条可见范围由融资需求与代币质押定义，本模块提供两类交易的事实与状态。
- 办理结果中即时给出本次已取得的交易哈希，这是当次反馈；离开办理后到操作记录查看。
- 交易哈希缩写展示（保留开头与结尾，位数由设计统一）；点击即复制完整值并提示已复制，复制失败时给出完整值供手动复制；另可跳转 Ethereum 区块链浏览器中该笔交易，在新窗口打开，原页面位置与办理进度保留（用户 2026-10-26 要求）。缩写只影响展示，复制与跳转都使用完整值。
- 交易哈希在平台取得后才展示，未取得时不显示占位值。处理中、明确失败（交易已发出）与结果待核实时，办理结果与操作记录中的这一条都标明当前状态并给出已取得的哈希；状态变化只更新这一条。未签名、取消或终检未通过时没有链上交易，不显示交易哈希，也不产生操作记录。
- 区块链浏览器只供自行核对，打开它不改变本笔状态；本笔结论以平台确认的结果为准，链上与平台事实不一致时按[结果待核实](#time-and-money)处理。
- 交易哈希只对本笔资产方与报价机构展示，非当事方按[报价信息的查看权限](#non-party)不可见。

<a id="profile"></a>
### 3.3 业务资料的自动取得与本人档案

- 个人与企业的账户档案只对本人开放；本模块不提供查看对方完整档案的入口。
- 业务需要的企业名称、编号、条款与地址自动取得：优先取本笔已确认的事实，其次取同一企业、同一用途的有效登记资料。
- 读取失败时说明暂时不可用并可重试，不说成“尚未登记”，不要求用户手填对方资料。
- 不串用其他企业、其他用途或其他业务的资料与文件；新的授信协议不自动套用历史文件。

<a id="time-and-money"></a>
### 3.4 时间、金额与时效

- 业务日期用 UTC；时刻按用户偏好时区展示（游客按浏览器时区），并标注时区；日期字段明确为 UTC。
- 本模块没有任何倒计时类时限；跨日、周末、夏令时与切换语言都不改变业务结论。授信有效期是准入条件，不是倒计时。
- 金额一律带币种（USDT 或 USDC）。界面默认英文，支持中文。
- 已确认的时效目标：授信判定 1 秒内给出结果；提交终检与结果 2 秒内；提交报价与发起接受时的质押水位判断 1 秒内；需求终结后报价连带失效的处理反馈 1 分钟内、最长 5 分钟，处理延迟不构成可以继续接受的宽限。链上授权、撤销授权与链上放款以链上结果为准，不另设时效目标。实现与验证归研发、测试。
- 链上结果长期未知或与平台事实冲突时，沿[异常只提示联系客服（D-LS-63）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-63)：提示“链上结果待核实，请联系平台客服人员”，保留业务编号、动作、已知 gas 与凭证，不允许重复发起。
- 授信、报价、放款地址、授权与撤销授权、摘要查看、签名接受、链上放款、拒绝、连带失效及占用变化，都可追溯操作主体、原因与时间；链上动作另可追溯签名地址与链上凭证。

## 4. 授信核验与企业授信

流程见[授信与报价（FL-CR-01）](./02-授信报价与接受拒绝-流程图与状态机.md#fl-cr-01)，状态见[授信生命周期（ST-CR-01）](./02-授信报价与接受拒绝-流程图与状态机.md#st-cr-01)。

<a id="credit-entry"></a><a id="f-ls-37"></a>
### 4.1 报价前的授信核验（F-LS-37）

适用角色与前提：已认证资金方；需求处于待报价，项目未到期、未进入终态，且不是本机构所属企业自己的需求。

资金方点击“立即报价”后，平台直接核验本机构对被授信企业的当前授信，不先询问；按核验结果直接进入对应页面：

| 核验结果 | 直接进入 | 页面用一句话说明的原因 |
| --- | --- | --- |
| 尚无授信 | 企业授信（首次授信）：填写授信额度、有效期至与本次授信协议，见[企业授信](#credit-save) | 本机构尚未给该企业授信 |
| 生效但可用授信不足 | 企业授信（追加授信）：填写正数的增加额，核对调整后的授信额度与有效期至，可上传本次协议 | 可用授信不足以覆盖本次报价，并给出本次融资金额、可用授信与差额（本次融资金额 − 可用授信 = 差额），均为 USDT |
| 已到期 | 企业授信（重新授信）：沿同一授信关系带出上一版额度供修改，重新填写有效期至，可上传本次协议 | 本机构对该企业的授信已于原有效期至到期 |
| 生效且可用授信充足 | 报价，不要求补交历史授信协议 | 不需要说明 |

- 核验不通过时直接进入企业授信，中间没有“是否授信”的确认步骤；原因用一句话说明。
- 在企业授信中不保存就关闭，即结束本次办理并回到原项目：不生成授信记录、融资业务编号、占用或需求锁定，也不留下“曾取消”的记录；再次点击时重新核验。
- 没有独立的授信菜单或“去授信”入口，首次授信只能由“立即报价”的授信核验进入；已有授信关系的追加与重新授信另可从我的控制台[修改授信](../09-我的控制台/01-我的控制台-PRD.md#credit-modify)进入，规则同下方企业授信与授信有效期。

<a id="credit-save"></a><a id="f-ls-38"></a><a id="p-ls-04"></a>
### 4.2 企业授信：首次、追加与重新授信（F-LS-38）

适用角色与前提：已认证资金方；[报价前的授信核验](#credit-entry)不通过，由核验直接进入。

- 机构自行决定授信：金额、日期合格即生效，没有审批。
- 首次授信成功生成稳定的授信编号；追加授信与重新授信沿用同一授信关系，保留历次记录。
- 保存成功即结束本次办理，提示“已授信，请继续报价”，授信摘要同步更新；须由用户再次发起报价才进入报价。
- 授信本身不生成报价、不锁定需求、不涉及链上操作；之后取消报价或报价失败，都不回滚已生效的授信与协议。
- 提交失败时定位到具体字段，保留金额、日期、备注与已成功上传的文件；提交过程中防止重复提交，重复点击不重复增加额度。

<a id="credit-fields"></a>
授信字段：

| 字段 | 业务含义与类型 | 必填与默认值 | 可编辑性 | 校验与结果 |
| --- | --- | --- | --- | --- |
| <a id="cr-01"></a>授信编号（CR-01） | 一条授信关系的唯一标识，文本 | 首次授信成功时生成 | 只读 | 追加授信与重新授信不改变编号 |
| <a id="cr-03"></a>被授信企业（CR-03） | 本项目的发布企业（项目发布方） | 自动带出 | 只读，不可另选 | 不能用代币买方、债务方、项目名或资产方个人账号代替；主体归属无法确认或无权时阻止提交 |
| <a id="cr-04"></a>授信状态（CR-04） | 生效中 / 已到期 | 系统判定 | 只读 | 没有冻结、停用等其他取值 |
| <a id="cr-05"></a>授信额度（CR-05） | USDT 金额（用户 2026-10-21 要求） | 必填，无默认金额 | 首次填总额；追加填正数增加额；重新授信带出上一版额度供修改 | 大于 0，最多两位小数；不得调低，不得低于当前授信已用额 |
| <a id="cr-06"></a>首次授信时间（CR-06） | 该企业首次获得本机构授信的时刻 | 系统记录 | 只读 | 追加不覆盖 |
| <a id="cr-07"></a>授信有效期至（CR-07） | UTC 业务日期 | 首次与重新授信默认授信日 + 1 年 | 可选范围见[授信有效期](#credit-term) | 越界拒绝并给出可选范围 |
| <a id="cr-08"></a>授信占用额（CR-08） | USDT 金额，见[术语](#glossary) | 系统计算 | 只读 | — |

| <a id="cr-10"></a>授信已用额（CR-10） | 授信占用额 + 在途报价金额，USDT | 系统计算 | 只读 | 不作为第三种独立占用 |
| <a id="cr-11"></a>可用授信（CR-11） | 授信额度 − 授信已用额，最小为 0，USDT | 系统计算 | 只读 | — |
| <a id="cr-12"></a>备注（CR-12） | 机构内部说明，文本 | 选填，无默认值 | 可编辑 | 最多 200 字；只对本机构可见 |
| <a id="cr-14"></a>本次授信协议（CR-14） | 本次授信操作对应的协议文件 | 选填，可为 0 份 | 可上传、移除 | 本次最多 10 份；每份不超过 10MB（含 10MB）；PDF、JPG、JPEG、PNG；空文件无效 |

<a id="credit-company"></a>
**被授信企业的识别资料。**

- 自动取得被授信企业的法定名称、适用于本笔的已登记英文名、项目编号与融资申请编号；操作页只读展示企业名称，登记英文名与业务编号在详情查阅，不自行翻译法定名称。
- 对方的注册地区、登记号码、完整注册地址、个人证件与认证材料不在本步骤展示，也不提供完整档案入口。
- 资料完整、暂未提供、加载中、读取失败分别说明；读取失败可重试。选填资料缺失不增加准入条件；名称缺失时说明“未提供”。

<a id="credit-files"></a>
**本次授信协议的上传。**

- 10 份是本次操作的累计上限，不是单次选择的上限，也不限制历次累计。
- 选择前说明格式、大小与上限；已上传份数与上限须可得，每份文件给出名称、大小与当前状态。
- 一次选择超出剩余名额时，整批不加入，保留原列表并告知剩余名额；格式或大小不合格的文件不计数，其他已成功的文件保留。
- 上传中可以取消；尚未提交的文件可以移除、重选、预览或下载；失败的文件可以重试或移除。
- 有上传中或失败待处理的文件时不能提交；处理完成后可以一份都不保留。
- 只有文件名、没有实际内容的不算上传完成；重新进入时按真实状态显示，不承诺跨设备保留草稿。
- 文件操作不改变授信状态、额度或需求。

<a id="credit-records"></a>
**授信协议的留存与可见范围。**

- 本次协议随这次成功的授信操作，与金额、有效期至、时间和机构对应留存；授信双方可查看和下载，其他企业与游客不可见。
- 后续操作不覆盖历史，不提供删除已生效协议的动作。
- 本次未上传即这次授信操作没有协议，不影响授信生效与后续报价；历史记录缺少协议的显示“历史记录未提供协议”，不追溯补件、不作废额度。
- 授信协议没有盖章、一致性声明、线上签署或平台审核要求，不显示“协议已审核”；它与融资合同是两回事。

<a id="credit-term"></a><a id="f-ls-39"></a>
### 4.3 授信有效期（F-LS-39）

适用角色与前提：资金方，在[企业授信](#credit-save)中填写授信有效期至。

- 首次授信与到期后的重新授信：默认本次授信日 + 1 年；可选范围为授信日 + 1 年至 + 5 年，两端可选，越界拒绝并给出范围。
- 追加授信：可以保持原日期或往后延，不能提前，不强制延至追加日之后一年。
- 五年上限的起点始终是首次授信日或最近一次重新授信日；追加不重置起点。不提供提前重新授信的入口。
- 已到五年上限时仍可只追加金额；起点无法可靠确定时不猜测、不放行延期。
- 授信日与可选范围按 UTC 业务日期；“授信有效期至”含当天，次日 00:00 UTC 起为已到期。
- 加年取同月同日；目标年没有该日时取该月最后一日（例如 2028-02-29 首次授信，默认有效期至 2029-02-28）。
- 授信到期只阻止新报价；已提交的报价、未偿本金以及接受（含链上放款）、还款都不受影响。项目到期不作废授信。

<a id="credit-check"></a><a id="f-ls-23"></a>
### 4.4 可用授信与再次校验（F-LS-23）

适用角色与前提：资金方，每次点击“立即报价”与每次点击“授权并报价”时。

- 新报价必须满足：授信占用额 + 在途报价金额 + 本次融资金额 ≤ 授信额度，均以 USDT 计；结算币种为 USDC 时同样按本次融资金额计量。不扣减授信额度本身。
- 跨项目的报价各按自己的融资金额计量。
- 再次点击“立即报价”和点击“授权并报价”时，都重新校验授信、项目与需求状态、质押水位，不以“刚办理过授信”为放行理由。
- 其他项目的报价先占用导致不足时，重新给出金额、可用授信与差额并进入追加；不重复增加上一次已生效的增加额。
- 质押水位不安全时不能引导去提额；授信不足与质押水位不安全分别说明，不合并为笼统失败。
- 授信已用额任何时候都不能超过授信额度；同一机构对同一企业只有一条授信关系。这两条由系统保证，产品中不设针对它们的提示、待办或补救流程；一旦出现即属系统级缺陷，由研发修正生产代码。
- 每次授信变更都可追溯：谁代表哪家企业、何时、因哪个项目改变了多少额度与有效期至。

## 5. 提交报价

前提：资金方所属机构不是该项目的发布企业；本轮需求待报价，没有在途融资业务，也没有其他机构处理中的报价；项目未到期、未进入终态；授信与当前质押水位同时满足。同一轮需求同一时刻只允许一家机构报价，先签名通过终检者预占，不提供比价和部分融资。

报价分两步办理（用户 2026-10-23 要求）：

1. **填写并签名确认报价信息**：选择结算币种、放款地址与还款收款地址，填写年化利率；选定放款地址与币种后，以弱提示显示可用余额。填写后点击“签名确认报价信息”，用放款地址在钱包中签名；签名完成即进入第二步，不另设“下一步”（用户 2026-10-26 要求）。这一签名不上链、不提交、不预占需求，规则见[签名确认报价信息](#quote-terms-sign)。
2. **发起授权**：核对已签名的报价信息与后果，点击“授权并报价”，用放款地址在钱包中签名授权本项目的放款合约。这一签名就是提交报价，授权上链成功即报价成功（用户 2026-10-22 裁定）；授权之后没有单独的“提交”按钮。

第一步的签名只确认报价信息，不形成报价记录；提交报价的动作仍只有第二步这一个。两次签名都由放款地址完成，共同满足[本次报价条款的签名确认与一致性](#quote-integrity)：只有转账额度的授权凭证不能当作完整报价条款的确认。

<a id="quote-terms-sign"></a>
**签名确认报价信息（第一步）。**

- 适用：已认证资金方在报价第一步填写完成后（用户 2026-10-26 要求）。目的是在提交前固定资金方确认过的报价信息，防止中途被篡改。
- 点击“签名确认报价信息”时，平台先校验填写完整、格式合格，并取得本次待签名的报价信息：结算金额、本轮需求金额、还款类型与最终还款日、三个地址与本项目放款合约。填写不完整、格式不合格、放款合约读取失败、本轮需求已不可报价时，不唤起钱包，就地说明原因并保留输入。放款地址余额只按[余额校验](#quote-authorize)弱提示，不作为本次签名的前提；余额不足时仍可签名并进入第二步，点击“授权并报价”时才拦下（用户 2026-10-26 确认）。
- 签名内容覆盖[本次报价条款的签名确认与一致性](#quote-integrity)所列的全部报价信息；钱包中的内容须可读，完整地址可核对。
- 签名须由所选放款地址完成。钱包当前地址不是放款地址时，提示切换到该地址再签名；其他地址的签名不被采用。签名与登录无关，签名前后登录状态不变。
- 签名本身不上链、不产生 gas，不提交报价、不预占需求、不占用授信，也不产生报价记录或站内信；签名期间其他机构仍可报价，以第二步终检为准。
- 签名成功即进入第二步，第二步只读展示已签名的报价信息。未签名、取消或钱包不可用时留在第一步，保留已填内容，说明报价信息尚未签名确认。
- 已签名的报价信息只对本次办理与签名时的内容有效：
  - 返回第一步且未修改任何内容的，原签名继续有效，可直接回到第二步。
  - 修改结算币种、放款地址、还款收款地址或年化利率，或本轮需求金额、最终还款日、放款合约等签名内容发生变化的，原签名作废，须在第一步重新签名；重新签名后再进入第二步。
  - 关闭或离开本次办理，未提交的签名作废，不保留草稿；重新办理须重新填写与签名。关闭前沿[查看与办理](#view-and-act)确认放弃。
- 这一签名由平台保存，作为本笔报价的确认凭证；报价信息与签名都不上链（用户 2026-10-26 裁定），正式核验在资产方接受、执行放款时进行，见[放款前核验报价签名](#quote-sign-check)（用户 2026-10-27 要求）。它不是链上交易，没有交易哈希。

<a id="quote-integrity"></a>
**本次报价条款的签名确认与一致性。**

- 报价条款由资金方在第一步用本笔放款地址[签名确认](#quote-terms-sign)，平台保存、不上链，放款时核验；仅取得合约可调取某币种、某额度的授权，不能替代报价条款确认。提交入口仍只有“授权并报价”，不另加勾选或页面提交。
- 本次确认须对应唯一的项目、本轮融资申请、本次报价、报价机构与资产企业，并覆盖融资金额及计价单位、结算币种与金额、年化利率、还款类型、最终还款日、放款地址、融资收款地址、还款收款地址，以及适用网络与本项目放款合约；不能挪用于其他申请、报价、机构、网络或合约。
- 签名前可核对关键条款及三个地址的网络、备注名与缩写；融资收款地址只读沿用本轮发布快照。钱包中的报价确认须有可读的业务内容，完整地址可核对，不以一串无法理解的凭证替代条款。
- 页面核对内容、第一步签名确认的报价信息、第二步提交的报价内容，以及之后链上放款使用的地址、合约、币种与金额须一致，由[放款前核验报价签名](#quote-sign-check)检查；第一步的签名只用于这一次报价提交，不得重复形成另一笔报价或新的授权交易。
- 第二步点击“授权并报价”时，只检查第一步签名仍对应当前填写的报价信息：若本轮金额、结算金额、地址或其他已签名条款已变化，本次不唤起钱包，说明变化并回到第一步按最新信息重新签名。这项检查只为避免提交过期的签名，不替代放款时的核验。已签名内容不能沿用到改动后的条款；授权签名发出后保留本次已确认版本，不在上链等待期间按最新账户资料改写。
- 授权上链成功即报价成功：生成融资业务编号、正式锁定需求并通知资产方，本笔以第一步签名的版本作为报价条款。报价阶段不再另做签名核验；签名与条款不一致的报价在资产方接受时被拦下，不会放款。
- 报价详情、我的控制台及资产方接受时引用同一笔已确认条款；链上放款与还款使用其中适用的币种、金额和地址。语言、时区、金额格式与地址缩写可改变展示形式，不能改变实际业务值；详情可核对完整值，后续账户编辑不改写旧报价。
- 可用余额、授信可用额、当前质押情况、等待时长与业务状态属于当时事实，按原规则更新，不冒充资金方签名时固定的报价条款；后续结果与原因另行保留，不覆盖原已确认内容。
- 签名前发现身份或内容不一致时阻止发送，说明原因并保留可复用输入；签名不通过时不能改用其他地址代签。授权交易已发出后结果长期未知或与平台事实冲突的，按结果待核实处理：不显示报价成功、不允许资产方接受、不发成功消息，不重复发送；保留已知凭证、费用与预占，沿[时间、金额与时效](#time-and-money)提示联系客服，不假称授权已回滚或 gas 已退还。
- 当事双方在本轮融资申请详情查阅确认条款、签名地址与确认凭证，已发起过接受的另可查阅放款前的核验结果；我的控制台不另设确认条款与凭证；报价条款不上链，不得标为“已上链”，链上可查的只有本笔授权交易。
- 报价成功即结束本次办理，刷新原申请与相关办理入口，不自动打开详情。
- 未通过终检或报价未成功时，说明原因并保留可复用的输入；项目已到期、需求已撤下、已被报价或正被其他机构报价等状态变化须明确说明，不用旧数值引导继续签名。
- 授信已成功但报价未成功的，授信保留，不生成融资业务编号。明确判为授权上链失败时，没有本笔已生效授权需要处理（用户 2026-10-22：报价失败不会有授权）；授权结果长期未知时，属于[结果待核实](#quote-integrity)，不能当作已失败并释放预占或声称授权不存在。

### 5.2 结算金额与 1:1 折算（F-LS-26）

适用角色与前提：资金方提交报价时；资产方接受、链上放款与还款沿用。

- 本期结算币种只有 USDT、USDC。USD、USDT、USDC 之间固定按 1:1 折算，本期不设汇率管理（用户 2026-10-28 裁定）；没有汇率配置、汇率快照或可变汇率。
- 结算金额按 1:1 由融资金额得出，数值等于融资金额，单位为所选结算币种；资金方不能改价，外部行情及其是否可用都不影响报价。1:1 是平台业务规则，不是外部市场价格或兑换承诺。
- 操作页核对结算币种与结算金额。
- 报价成功即随本笔条款固定结算币种与结算金额，之后不重算。
- 例：融资 100.25 USDT。选 USDT 时结算 100.25 USDT；选 USDC 时结算 100.25 USDC；不收折算差额；预览与最终条款一致。
- 链上放款复用本笔结算金额；还款每期的结算金额按 1:1 由本期应还合计得出，不能把融资本金当作每期本息。

<a id="amount-precision"></a>金额精度：

| 金额类别 | 精度与处理 |
| --- | --- |
| USDT 授信额度、需求金额与融资金额 | 输入最多两位小数，展示两位，计算过程不提前舍入 |
| 每期利息 | 按[还款计划规则](../08-借贷广场-链上还款/01-链上还款-PRD.md#f-plan)：逐期独立两位、四舍五入、不跨期结转；本模块不另定计息 |
| 结算金额（USDT / USDC） | 按 1:1 由融资金额得出，与融资金额数值相同、两位小数，不产生折算舍入或尾差；链上放款同源复用；授权金额、余额校验与放款金额使用同一数值；展示截断不能改变付款金额 |

### 5.3 放款地址、余额校验与授权并报价（F-LS-40）

适用角色与前提：已认证资金方，授信核验通过、已选择结算币种（用户 2026-10-21 要求）。流程见[授权与撤销授权（FL-CR-06）](./02-授信报价与接受拒绝-流程图与状态机.md#fl-cr-06)，状态见[本笔授权状态（ST-CR-04）](./02-授信报价与接受拒绝-流程图与状态机.md#st-cr-04)。

**放款地址（QT-17）。**

- 先选定放款地址才能报价。只能从本机构在企业账户（资金方侧称“机构账户”）中已登记的数币账户中选，网络仅限 Ethereum；不能手输地址，办理中没有新增、编辑或删除账户的入口（沿[企业账户的业务办理中选用账户（F-EA-07）](../03-企业账户/01-企业账户-PRD.md#f-ea-07)）。
- 不预先带出，即使只有一个可选账户也须资金方显式选定。放款地址采用下拉选择；选项与选中值均给出网络、备注名、缩写钱包地址，网络展示为“Ethereum”（中文界面同样）；选中后不再另外展示账户详情或完整地址（用户 2026-10-23 要求）。各选项对应独立账户，不能因地址缩写相同而合并或串用。
- 信息不完整的账户列出并标注待补项，但不能选定。没有可用账户时说明尚未登记并引导到机构账户，登记完成后回到本次报价、已填内容不丢失；读取失败时说明暂时不可用并可重试，不说成“尚未登记”。
- 授权与撤销授权都用放款地址在钱包中签名；放款地址可以与当前登录地址不同。这一签名只为授权合约，与登录无关：钱包切到放款地址签名时，不切换、不结束当前登录，也不要求重新登录（用户 2026-10-22 裁定）。
- 报价成功后放款地址以快照随本笔固定；之后在机构账户修改或删除该账户，不改变本笔记录。

<a id="repay-address"></a>**还款收款地址（QT-18）。**

- 报价时填写本笔的还款收款地址，资产方将来按还款计划把还款付到这个地址（用户 2026-10-22 裁定）。
- 选定放款地址后，默认带出同一地址；资金方可以改选其他地址，只能从本机构机构账户中已登记的 Ethereum 数币账户中选（用户 2026-10-22 裁定），不能手输，与放款地址相同。还款收款地址同样采用下拉选择，选项与选中值均展示网络“Ethereum”、备注名与缩写钱包地址，选中后不再另外展示账户详情或完整地址（用户 2026-10-23 要求）；账户识别与完整地址使用规则同放款地址。
- 信息不完整的账户不能选定；读取失败时说明暂时不可用并可重试。
- 还款收款地址只用于收款，不需要签名、不做余额校验，也不参与授权。
- 报价成功后以快照随本笔固定，不能修改；之后在机构账户修改或删除该账户，不改变本笔记录。本笔当事双方可见，非当事方不可见。
- 链上放款成功后，随链上放款记录交给[链上还款](../08-借贷广场-链上还款/01-链上还款-PRD.md)。

**余额校验。**

- 选定放款地址与结算币种后，平台查询该地址在 Ethereum 上本笔结算币种的余额，与本笔结算金额比较（用户 2026-10-21 要求）。
- 选定放款地址与结算币种后，只以弱提示显示“可用余额”及金额与币种；余额不足时同样只显示可用余额，不另列所需金额或差额（用户 2026-10-23 要求）。
- 余额不低于结算金额才可以签名提交（用户 2026-10-21 要求）。第二步点击“授权并报价”时平台再校验一次，不足时不唤起钱包，就地说明“放款地址余额不足”，资金方可以补足余额，或返回第一步更换放款地址并重新签名确认报价信息。
- 余额暂时无法查询时，弱提示处说明暂时无法查询；第二步点击时仍无法查询的，不唤起钱包、不当作不足，说明可稍后重试。
- 更换结算币种或放款地址时，重新查询并更新可用余额提示。
- 余额校验只是报价前提，不冻结、不划转资金，也不占用授信。

<a id="quote-sign"></a>**授权并报价。**

- 资金方报价时，用放款地址签名授权本项目所配置的放款合约，允许其从放款地址调取本笔结算金额（用户 2026-10-21 要求）；这一签名就是提交报价（用户 2026-10-22 裁定）。授权金额等于本笔结算金额，币种为本笔结算币种。
- 每笔报价都签名授权一次，不因该地址已有授权而跳过；放款合约每个项目一份，授权只针对本项目的放款合约，同一放款地址对其他项目的授权互不影响；同一放款地址对本项目放款合约另有未撤销的授权（如本机构此前已拒绝或已失效的报价）时，本次照常授权，任何一笔的授权或撤销授权都不得减少待接受报价仍需的授权额度。
- 授权是资金方本人用放款地址签名并发送的链上交易，平台不代签、不代付；gas 由资金方承担，失败已产生的 gas 不退。
- 第二步须与“授权并报价”主动作同时可见：结算币种与结算金额、年化利率、放款地址、还款收款地址与只读融资收款地址摘要（网络、备注名与缩写地址）、授权币种与金额、本次授权的放款合约与本次签名用途（见[所交互的合约、签名用途与交易哈希](#chain-display)），以及[报价条款与提交](#quote-form)所列的后果说明。

**签名链路：**

1. 资金方在第二步点击“授权并报价”。平台先终检：授信、项目与需求状态（仍待报价、没有其他机构处理中的报价）、[质押水位](#quote-coverage)、放款合约可读且与页面所示一致、放款地址余额不低于结算金额，以及第一步签名仍有效（签名地址为放款地址、签名内容与当前报价信息一致）。任一不满足时不唤起钱包，就地说明原因，保留输入；签名已失效的，回到第一步重新签名。
2. 终检通过后，资金方用放款地址在钱包核对并签名授权交易，提交的报价内容与第一步已签名版本一致；第一步签名不上链。
3. 签名发出后，本笔进入报价处理中：本轮需求为这笔报价预占，其他机构不能报价，看到“本轮正在处理其他机构的报价”；本机构在途报价金额先按本笔预占，其他报价核验授信时一并计入；资金方不能再次签名或修改条款。
4. 授权上链成功即确认报价成功，结果见[生成融资业务并锁定需求](#quote-lock)；第一步签名在放款时核验。
5. 报价成功后，本笔授权一直保留，直到被链上放款使用或资金方撤销；待接受期间不需要、也不提供重新授权（用户 2026-10-22 裁定）。

**签名与上链结果（每次签名授权）。**

| 结果 | 报价与额度 | 资金方看到什么 |
| --- | --- | --- |
| 未通过终检 | 不唤起钱包，没有链上操作、没有预占 | 具体原因与出路，保留输入；第一步签名已失效的，说明变化并回到第一步重新签名 |
| 未签名、取消或钱包不可用 | 未发生链上操作、未产生 gas；没有预占 | 说明本次未提交报价 |
| 处理中（授权交易已发出） | 报价处理中：本轮需求与本机构在途报价金额按本笔预占；没有融资业务编号 | 已等待时长、已知 gas 与授权交易哈希，未知标“待核实”；离开不影响处理，回来后按当时结果显示 |
| 授权上链成功 | 报价成功：生成融资业务编号，本笔进入待接受 | 本笔确认条款、确认凭证、报价时间、授权交易哈希与实际 gas |
| 上链明确失败 | 报价未成功：预占释放，本轮需求回到可报价，不生成编号，授权没有上链 | 可读原因、是否已产生 gas 及金额，交易已发出的给出该授权交易哈希；可以按当时资格重新签名提交 |
| 长期未知或与平台事实冲突 | 保持预占，不生成成功报价，不能重复发起或接受 | 保留已取得的授权交易哈希、凭证与已知费用，按[时间、金额与时效](#time-and-money)提示联系客服 |

- 重复点击、刷新或重复提交同一次签名，链上只产生一笔授权交易，gas 只记一次。
- 报价处理中所属需求终结（项目到期、质押水位不安全）的，等上链结果回写后再判断：上链成功的报价照常生成融资业务编号，并随需求终结记为已失效，资金方可以[撤销授权](#revoke)；上链未成功的不形成报价。
- 签名与上链结果都不发送站内信；报价成功后由[收到融资报价（N-CR-01）](./03-授信报价与接受拒绝-消息通知.md#n-cr-01)通知资产方。

<a id="quote-coverage"></a><a id="f-ls-36"></a>
### 5.4 提交时复核质押水位（F-LS-36）

适用角色与前提：资金方点击“授权并报价”时（签名前的终检）。

- 按融资需求与代币质押模块的[质押水位（INV-FIN-01）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#water-level)与[需求因质押水位不足失效（F-LS-19）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-19)使用当前权威事实，包括有效质押额（有效质押价值 × 项目质押率）、逐笔累计、失效顺序与停止条件。
- 不能用总质押额或打开报价时的旧数值判断，也不能漏算更早保留的需求。
- 已发布需求的报价只校验已有的有效质押额与授信，不因可融金额为 0 单独禁止报价。报价不重复增加项目在途金额。
- 当场证实质押水位不安全：本轮需求按融资需求与代币质押模块的规则自动失效，本次报价不成立；说明“该融资需求已失效（质押水位不足）”，由资产方补足质押后重新发布，不归咎报价机构，没有缓冲期。
- 当前质押水位暂时无法取得：只拒绝本次提交，不唤起钱包，说明“暂时无法完成质押校验”，不把未知当作不足而使需求失效。
- 签名发出后、上链确认前质押水位变为不安全的，按[授权并报价](#quote-sign)中报价处理中的规则处理。

<a id="quote-lock"></a><a id="f-ls-25"></a><a id="fd-01"></a>
### 5.5 生成融资业务并锁定需求（F-LS-25）

适用角色与前提：资金方签名授权已上链成功。

- 报价成功的同一事件内完成：生成稳定的融资业务编号（FD-01）、正式生效本次签名确认的条款、固定结算金额及地址并关联本笔确认凭证与[授权交易哈希（QT-19）](#qt-19)、记录报价时间、本机构在途报价金额由预占转为正式计入、本笔进入待接受，并向融资需求与代币质押模块提供锁定结果；项目在途金额不变。
- 报价自此不可修改、不可撤回。
- 成功前不预占融资业务编号；明确失败时释放处理中的预占，结果未知或内容冲突时继续保留预占；签名前当场证实质押水位不安全的，仍按[提交时复核质押水位](#quote-coverage)使原需求失效。
- 两家机构同时点击时，只有先通过终检、发出签名的一方进入报价处理中；另一方在终检时被告知“本轮正在处理其他机构的报价”或“已被报价”，不唤起钱包，不产生授权、编号或占用。
- 报价成功后通知该需求的资产方，见[消息通知](./03-授信报价与接受拒绝-消息通知.md)。

<a id="quote-expiry"></a><a id="f-ls-31"></a>
### 5.6 锁定信息的展示（F-LS-31）

适用角色与前提：本笔资产方与报价机构；其他身份按[角色与可见范围](#roles)。

- 项目的融资申请信息清单保留本轮锁定摘要；融资申请详情与资产方的我的控制台显示报价机构全称、锁定起始与已锁定时长。
- 非本笔当事的资金方只看到本轮已被哪家机构报价，看不到锁定起始与已锁定时长。
- 锁定没有截止时刻：不显示剩余时间、倒计时或临期强调。已锁定时长通常精确到小时，并标注时区；接受或拒绝后停止累计。
- 公开说明保持中性；资产方可以随时拒绝，不受时限催促。

<a id="f-ls-34"></a>
### 5.7 报价的持续有效与退出路径（F-LS-34）

适用角色与前提：已进入待接受的报价。

- 报价成功后一直待接受，没有有效期、截止时刻、倒计时或自动失效，也没有续期、展期与宽限；长时间无人处理、无人登录都不改变结论，不释放任何占用。
- 待接受只有三条退出路径：资产方接受、资产方拒绝、所属需求终结使本笔连带失效。
- 资金方提交后不能撤回、不能修改，也没有催办动作，这是[按用户决定保留的业务限制](#limits)。待接受期间平台不提供撤销授权。
- 拒绝或连带失效后释放本笔在途报价金额，需求按融资需求与代币质押模块的事实处理；项目在途金额与质押不因拒绝而释放。
- 已终结的融资业务编号保留；需求仍有效、项目未到期且满足资格时，任何机构（包括原机构）都可以重新报价，没有冷却期和次数上限；重新报价生成新编号与新的报价条款，并须重新完成余额校验与授权，不是原报价续期。

<a id="quote-combo"></a>
待接受报价在不同情形下的结果：

| 情形 | 资产方能否接受 | 资产方能否拒绝 | 用户看到的结果 |
| --- | --- | --- | --- |
| 正常待接受 | 能，在操作页核对关键条款与融资收款地址摘要后签名接受 | 能 | 已锁定时长持续累计 |
| 报价后授信到期 | 能 | 能 | 授信到期只阻止新报价，不影响本笔 |
| 质押持平但质押水位安全 | 能 | 能 | 照常办理；发起接受时复核质押水位 |
| 接受签名后链上放款处理中 | 不能重复接受 | 不能 | 显示放款处理中与已等待时长，等链上结果 |
| 放款地址的授权或余额已不足以支付本笔 | 不能，确认页查得余额不足时直接提示；发起时仍复核授权与余额，不唤起钱包，不能签名 | 能 | 本笔保持待接受；仅查看余额不足不发送消息，实际发起接受首次被拦下时提醒资金方一次 |
| 链上放款明确失败 | 能，重新签名接受 | 能 | 本笔保持待接受，双方收到放款未完成通知 |
| 质押水位变为不安全（含发起接受时当场证实） | 不能 | 不能 | 需求按融资需求与代币质押模块自动失效，本笔连带失效，终结原因“自动失效·质押水位不足” |
| 发起接受时质押水位暂时无法取得 | 本次不能，稍后重试 | 能 | 说明暂时无法完成质押校验，不使需求失效 |
| 项目到期 | 不能 | 不能 | 需求随项目到期终结，本笔连带失效，终结原因“项目到期” |
| 融资收款地址读取失败 | 不能，稍后重试 | 能 | 说明暂时不可用并可重试 |
| 放款前报价签名核验不一致 | 不能 | 能 | 本笔保持待接受，说明报价信息核验未通过并提示联系平台客服人员；不发送消息 |
| 已接受、已拒绝或已失效 | 不能 | 不能 | 只读查看结果，不能凭保留的进度继续提交 |

<a id="respond"></a><a id="p-ls-06"></a>
## 6. 资产方接受（链上放款）或拒绝报价

适用角色与前提：本企业资产方；本笔报价仍待接受。流程见[接受与拒绝（FL-CR-02）](./02-授信报价与接受拒绝-流程图与状态机.md#fl-cr-02)。

资产方看到的每笔待接受报价，都须标明“资金已授权，接受即放款”以及本笔结算金额与币种，让资产方知道接受后款项会立即到账、随即进入还款。

资产方从“融资”业务入口选定本笔报价办理，按[操作页与详情页的信息归属](#operation-information)核对机构、关键金额与条款、地址及签名后果；业务编号、报价与锁定时间、质押明细在融资申请详情查阅。不提供机构档案或认证材料的完整查看，也不提供报价时的池况快照。资金方还款收款地址只在融资申请的报价详情按原权限查阅，确认报价页不展示该地址；其快照、报价条款确认范围与后续还款用途不变，不在接受时重新采集。

<a id="respond-balance"></a>
**确认报价页的放款地址与余额。**

适用角色与前提：本企业资产方在“确认报价”页办理本笔接受或拒绝（用户 2026-10-23 要求）。

- 本页保留资产方本轮融资收款地址及其签名用途，展示资金方本笔放款地址的网络、备注名与缩写；放款地址只读取已成功报价的快照，不允许资产方更换，不因资金方后来编辑机构账户而改变。完整地址在详情按当事方权限可核对。
- 打开本笔确认页即查询并展示该放款地址在 Ethereum 上本笔结算币种的当前可用余额，数值带币种；报价为 USDT 就查询 USDT，报价为 USDC 就查询 USDC，不展示机构总余额、其他币种余额或报价时的旧余额，也不以融资金额或授信额度代替余额。
- 当前余额小于本笔结算金额时，直接提示资金方放款地址余额不足、暂不能完成接受；不等用户点击后才告知。余额等于结算金额即满足代币余额条件，其他资格与授权仍须复核；本页不新增余额差额明细。
- 查询中或查询失败分别展示对应状态，失败可重试，不把未知余额写成 0 或判为不足。余额不足或尚未查明时不能发起签名接受；本笔保持待接受，仍可按原规则拒绝，资金方补足后可重试查询。
- 页面显示余额充足后，发起接受与签名后核验时仍按[发起前的校验](#accept-precheck)复核授权与余额；之后余额被转走的仍须拦下，旧查询结果不保证放款成功，不增加冻结或扣款动作。

- 本页不展示资金方还款收款地址；在融资申请的报价详情按原权限查看该地址，返回本笔办理时对象与进度保留。此要求只适用于资产方确认报价页，资金方报价两步中的地址填写、核对与可用余额弱提示仍按原规则。

### 6.2 核对商务摘要、接受并收款（链上放款）（F-LS-29）

适用角色与前提：本企业资产方；本笔报价仍待接受。

- 资产方看到并签名接受的条款，是本笔报价保存的、资金方第一步签名确认的版本；放款前平台按[放款前核验报价签名](#quote-sign-check)核验，不通过的不能接受、不会放款。
- 合同由双方线下拟定与签署。平台不生成合同、不提供模板下载、不以模板配置作为接受前提；接受不收取任何合同文件，没有份数、格式或大小校验。
- 商务摘要在操作页只展示[本次接受必需的关键条款](#operation-information)，完整条款在融资申请详情查阅；不另设“本摘要不是合同”的说明，也不提供摘要复制或打印（用户要求）。完整条款包括项目编号、融资申请编号、融资业务编号、双方企业全称、融资金额（USDT）、结算币种与结算金额、年化利率、当前抵押物概况、报价时间、还款类型、最终还款日、融资收款地址、资金方的还款收款地址，与本笔事实一致。

接受只有一个动作（用户 2026-10-22 裁定）：资产方点击“接受并收款”并在钱包中签名，这一签名就是接受；之后的链上放款由平台执行，资产方不再有任何确认或提交动作。

**签名链路**（用户 2026-10-21 要求）：

1. 资产方核对后点击“接受并收款”，平台核实本笔仍待接受、需求未终结、放款合约可读且与本笔报价授权的合约一致，按[放款前核验报价签名](#quote-sign-check)核验资金方的报价签名，复核当前质押水位，并查询放款地址对本项目放款合约的授权额度与余额仍覆盖本笔结算金额；不满足时不唤起钱包，见[发起前的校验](#accept-precheck)。
2. 资产方用本轮的融资收款地址在钱包中签名确认本次接受（用户 2026-10-23 要求）。钱包当前地址不是融资收款地址时，提示切换到该地址再签名；切换与签名都不影响当前登录。这一签名本身不上链、不产生 gas。
3. 平台核验签名：签名地址为本轮融资收款地址，签名内容与本笔一致，本笔在此刻仍待接受、需求未终结，质押水位、授权与余额在此刻仍满足；并在执行放款前再次[核验资金方的报价签名](#quote-sign-check)与本次放款参数一致。
4. 核验通过后，由平台执行钱包签名执行链上放款：本项目所配置的放款合约按本笔授权，从放款地址调取本笔结算金额，转入融资收款地址；gas 由平台执行钱包承担，资产方与资金方都不为这笔交易付费。
5. 链上放款成功即接受成功、放款完成（用户 2026-10-21 要求：放款为链上操作，不再有放款与放款确认）。

- **签名用途**：这一签名只用于执行本笔链上放款，与登录无关（用户 2026-10-22 裁定）；签名地址须为本轮融资收款地址，也就是款项将要转入的地址（用户 2026-10-23 要求，2026-10-26 确认），可以与登录地址不同。该地址是资产方发布时从本企业已登记的数币账户中选定的，资产方用它在钱包中签名；无法用该地址签名时不能接受，平台不代签，也不能换用其他地址接受。
- **签名内容**：须包含融资申请编号、融资业务编号、报价机构、融资金额（USDT）、结算币种与结算金额、年化利率、最终还款日与融资收款地址，供资产方在钱包中核对；签名只对这一次接受有效，不能被重复使用。
- **唯一确认**：点击“接受并收款”即唤起钱包，钱包内的签名就是最终确认；不另设勾选或确认弹窗（用户要求）。
- 以下几项须与签名主动作同时可见：结算币种与结算金额、融资收款地址与资金方放款地址摘要（备注名、网络与缩写地址）、该放款地址本笔结算币种的当前可用余额及适用的不足或查询异常提示、执行本笔放款的放款合约与本次签名用途（见[所交互的合约、签名用途与交易哈希](#chain-display)），以及简短的后果说明：签名后平台立即执行链上放款，本笔结算金额从资金方放款地址转入上述收款地址，上链成功即接受成功、本笔进入还款；资产方不承担费用。
- **签名后核验不通过**（本笔已被处理、需求已终结、签名地址不是本轮融资收款地址、授权或余额已不足、资金方报价签名核验未通过）：不上链，就地说明原因，本笔状态不变；不发送消息。质押水位当场证实不安全的，按下方质押水位规则处理。

<a id="quote-sign-check"></a>**放款前核验报价签名。**

资金方在报价第一步的[报价信息签名](#quote-terms-sign)不上链，在资产方接受、平台执行链上放款时核验（用户 2026-10-27 要求）。

- 核验时机：资产方点击“接受并收款”时核验一次，不通过不唤起钱包；资产方签名后、平台执行链上放款前再核验一次，不通过不执行放款。
- 核验内容：
  - 签名地址为本笔报价的放款地址，签名对应本笔项目、融资申请与融资业务编号。
  - 签名内容与本笔保存的报价条款逐项一致：融资金额、结算币种与结算金额、年化利率、还款类型、最终还款日、放款地址、融资收款地址、还款收款地址、网络与放款合约。
  - 本次链上放款将使用的放款地址、收款地址、币种、金额与放款合约，与已签名信息一致。
- 核验不一致：不唤起钱包或不执行放款，不上链、不产生费用；本笔保持待接受，资产方看到本笔报价信息核验未通过、暂不能完成接受，提示联系平台客服人员；资产方仍可拒绝。不发送站内信，不改变需求状态与占用。
- 核验暂时无法完成（如签名记录读取失败）：只拒绝本次接受，说明暂时无法完成核验并可稍后重试，不当作不一致。
- 核验结果随本次接受记录，当事双方在融资申请详情查阅；查看确认报价页不触发核验。

<a id="accept-precheck"></a>**发起前的校验。**

- **质押水位**：点击“接受并收款”与签名核验时，都按融资需求与代币质押模块的[质押水位（INV-FIN-01）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#water-level)使用当场的权威事实复核。当场证实不安全的，本轮需求按[需求因质押水位不足失效（F-LS-19）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-19)自动失效，本笔连带失效，不执行链上放款；暂时无法取得的，只拒绝本次接受，说明“暂时无法完成质押校验”，不使需求失效。
- **授权与余额**：放款地址对本项目放款合约的授权额度或本笔结算币种的余额不足以支付本笔结算金额时，不唤起钱包、不上链，说明“资金方放款地址的授权或余额不足，暂不能完成接受”；本笔保持待接受，资产方可以稍后再试或直接拒绝（用户 2026-10-22 裁定：额度不足不能签名执行放款）。同一笔第一次被拦下时，向资金方发一条[接受被拦下提醒（N-CR-08）](./03-授信报价与接受拒绝-消息通知.md#n-cr-08)，之后同一笔再被拦下不再发（用户 2026-10-22 裁定）。授权在报价后一直保留，资金方补足放款地址上本笔结算币种的余额即可，不需要重新授权（用户 2026-10-22 裁定）；授权若被资金方在平台外自行撤销，同样按不足拦下。查询暂时失败时说明暂时无法完成校验并可重试，不算被拦下。

| <a id="ln-08"></a>放款交易哈希（LN-08） | 链上放款交易的哈希（即交易标识），可在区块链浏览器查验 | 链上放款成功时记录 | 只读，不由用户填写；随本笔记录保存，详情中只在操作记录的“链上放款”一条展示，链上放款记录不重复；当事双方可见，展示、复制与跳转按[所交互的合约、签名用途与交易哈希](#chain-display) |
| <a id="fd-40"></a>放款成功时间（FD-40） | 链上放款上链成功、平台确认的时刻 | 链上放款成功时记录 | 只读；是两个维度金额转移的时点，也是交还款计划的依据 |

- 放款金额一律按锁定的结算金额，资产方收到的数额与之相同；本金与占用按融资金额（USDT）计量。
- 链上放款不是平台代付：资金从资金方授权的放款地址直接转入资产方收款地址，平台不归集、不垫付。

<a id="respond-reject"></a><a id="f-ls-30"></a>
### 6.3 拒绝及并发结果（F-LS-30）

适用角色与前提：本企业资产方；本笔报价仍待接受，且没有处理中的链上放款。

- 拒绝不需要地址签名，不发生链上操作，不产生 gas（用户 2026-10-21 要求）；填写原因后点击拒绝即提交。
- 拒绝操作页保留资金方名称、融资金额、拒绝原因及其可见范围、终结报价与释放本笔在途报价金额的后果；业务编号、历史与完整条款在详情查阅。
- 拒绝原因必填，自由文本 1～200 字，无默认值、不分类、不审核；对报价机构可见，不向游客或其他企业公开。
- 拒绝不需要先查看摘要，没有冷却期。
- 拒绝成功的结果同时成立：本笔为已拒绝；释放本笔在途报价金额；需求仍有效时回到待报价；项目在途金额与质押不变；通知原报价资金方；资金方可以对本笔[撤销授权](#revoke)。
- 拒绝是本笔报价唯一的人工退出途径：资金方不能自行撤回；本轮需求也须先拒绝报价、回到待报价后才能撤下或修改金额。
- 授信在报价成功后到期，不影响本笔接受或拒绝。
- 项目在报价后到期时，本轮需求随之终结，本笔连带失效、不能再接受，按[需求终结与报价连带失效](#demand-invalid)处理。项目有待确认报价时不能主动关闭，见[融资需求与代币质押的未处理完成的业务](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#unfinished-business)。
- 质押水位一旦不安全，需求即自动失效、本笔连带失效；发起接受时另按[发起前的校验](#accept-precheck)复核。水位仍安全时（包括质押持平）照常可以接受。接受本身不增加金额。
- 接受与需求终结竞争：需求先终结则报价一并失效，不能接受；链上放款先成功则进入还款中，不回翻为报价失效，之后的质押情况按融资需求与代币质押、还款模块的规则处理。
- 同一笔的接受、拒绝与连带失效只有一个最终结果，以平台确认时本笔仍待接受为准；已处理后的重复提交在本次办理内说明最新结果并停用旧动作，保留可见历史。

<a id="revoke"></a><a id="f-ls-41"></a>
### 6.4 撤销授权（F-LS-41）

适用角色与前提：本笔报价的资金方，本笔已拒绝或因需求终结而失效。

- 本模块提供报价状态、放款地址、本笔授权币种与额度，以及同一放款地址对同一放款合约的其他待接受报价。
- 平台内的查看与撤销统一由[我的控制台的链上授权与撤销授权](../09-我的控制台/01-我的控制台-PRD.md#revoke)定义；我的报价详情只显示授权状态并定位对应授权记录，不重复办理。
- 待接受、报价上链确认中、链上放款处理中或已使用的授权不能撤销；报价未成立时按本模块的报价结果处理。
- 撤销授权不改变报价结论、需求状态或授信占用，不发送本模块站内信。

<a id="lifecycle"></a>
## 7. 占用的保留、转移与释放

状态见[融资业务本模块状态（ST-CR-02）](./02-授信报价与接受拒绝-流程图与状态机.md#st-cr-02)。

<a id="allocation"></a><a id="f-ls-27"></a>
### 7.1 机构与项目两个维度（F-LS-27）

- 机构维度的在途报价金额就是待接受（含链上放款处理中）的报价；链上放款成功之前不转为授信占用额。两个维度都按融资金额计量，单位 USDT。
- 项目维度的额度只引用融资需求与代币质押模块的定义。
- 授权本身不计入占用，在途报价金额随报价处理中与报价成功计入；撤销授权不释放任何占用。

| 事件 | 机构维度 | 项目维度 |
| --- | --- | --- |
| 签名授权发出（报价处理中） | 按本笔全额预占在途报价金额；上链失败时释放 | 不变 |
| 报价成功（授权上链成功） | 预占转为本笔全额在途报价金额 | 发布需求时已计入项目在途金额，不重复增加 |
| 签名接受、链上放款处理中、链上放款失败 | 保留在途报价金额，不转为授信占用额 | 保留项目在途金额 |
| 资产方拒绝 | 释放本笔在途报价金额，不转为本金 | 需求仍有效时解锁回到待报价；项目在途金额与质押保持 |
| 需求终结（项目到期、自动失效·质押水位不足） | 待接受报价连带失效，释放本笔在途报价金额 | 融资需求与代币质押模块同一事件终结需求，并释放其项目在途金额 |
| 链上放款成功（接受成功） | 本笔全额在途报价金额转为授信占用额 | 同笔全额项目在途金额转为项目融资余额；两个维度在放款成功时间（FD-40）同时转移，没有空档也不重复计算 |
| 本期还款上链成功（本期即结清，不需资金方确认） | 按已偿本金逐期减少授信占用额，结清后本笔归零 | 项目融资余额等额减少；利息不算本金释放 |

- 本笔贡献的授信占用额与在途报价金额，只在三条终结路径之后归零：资产方拒绝、需求终结连带失效、结清；不误清其他存量。
- 授信到期、逾期标记都不提前释放；接受成功只把在途转为本金，不释放；时间流逝本身不释放任何占用。
- 项目到期只连带终结尚未成交的待接受报价，不释放已成交存量债务的占用。
- 单笔融资业务没有中途终止出口，见[融资需求与代币质押的单笔融资业务没有中途终止出口（D-LS-64）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-64)。
- 已到期项目不开放发布与报价；未到期项目按全部存量、有效质押额与质押水位判断资格；其他债务继续履约。

<a id="demand-invalid"></a><a id="f-ls-35"></a>
### 7.2 需求终结与报价连带失效（F-LS-35）

流程见[需求终结与连带失效（FL-CR-03）](./02-授信报价与接受拒绝-流程图与状态机.md#fl-cr-03)。

- 融资需求与代币质押模块判定本轮需求终结时，本模块把仍待接受的报价置为已失效。会使在途报价连带失效的终结原因只有两种：项目到期、自动失效·质押水位不足。
- 项目关闭不会使在途报价失效：有待确认报价的项目不能关闭，关闭时一并终结的只有尚未收到报价的需求。
- 需求终结、项目在途金额释放、本笔在途报价金额释放在同一事件内完成；不出现“需求已终结但报价仍可接受”或金额未释放的中间状态。链上放款处理中的，等结果回写后再判断，见[核对商务摘要、接受并收款（链上放款）](#respond-contract)。
- 报价失效只有一种原因“所属融资需求终结”，同时记录需求的具体终结原因与实际终结时刻，不记成未来时刻。
- 系统失效不要求拒绝原因，不计入拒绝率，不给机构负面记录。
- 没有缓冲期或恢复倒计时；补足质押不恢复原报价，只能按融资需求与代币质押模块重新发布后重新报价。
- 已失效报价的授权保留在链上，资金方可以[撤销授权](#revoke)（用户 2026-10-22 裁定）。
- 需求终结及其对报价的影响，由融资需求与代币质押模块的[融资需求终结通知（N-LS-05）](../05-借贷广场-融资需求与代币质押/03-融资需求与代币质押-消息通知.md#n-ls-05)合并发给资产方与在途报价的资金方；本模块不发送任何报价失效消息，但仍负责本笔状态与占用释放。
- 并发或重复处理不产生第二次状态变化、释放或消息。

## 8. 查看记录与定位

<a id="records"></a><a id="f-ls-32"></a><a id="fp-28"></a>
### 8.1 当前报价、历史与跨入口定位（F-LS-32）

适用角色与前提：本笔资产方与报价机构；其他身份按[角色与可见范围](#roles)。

**融资申请与报价记录。**

- 一轮申请一条融资申请编号（FP-28），可先后关联多个融资业务编号（FD-01）。
- 项目详情的记录边界由融资需求与代币质押定义（[项目详情的记录](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#records)，其 Q-LS-29 已于 2026-10-22 裁定）：报价与放款合为一步后，不再单设“融资放款信息”清单；本模块的报价、接受与链上放款记录都属于同一轮融资申请，在融资申请信息及融资申请详情中查看；放款成功后的还款计划、期次、逾期与结清只在还款信息中查看。
- 融资申请详情包含金额与申请状态、需求信息、当前报价及授信摘要、[链上放款记录](#loan-record)（已放款时）、报价历史（按需查看）、协议文件与操作记录，不展示冻结信息；详情边界沿[融资需求与代币质押的融资申请详情](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#application-detail)，其中报价信息对谁可见，按[报价信息的查看权限](#non-party)。
- 链上放款记录的明细只在融资申请详情展示；还款信息与还款详情只显示融资申请编号、融资业务编号与放款编号，用于识别与检索，不重复放款明细；融资申请信息只显示“已放款”，不拼入还款、逾期或结清状态。
- 本笔确认条款、签名确认凭证与核验结果在融资申请详情按[本次报价条款的签名确认与一致性](#quote-integrity)查阅；不能用当前编辑资料或其他报价的凭证替代。
- 授权交易哈希与放款交易哈希在详情中只出现在[融资申请详情的操作记录](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#application-detail)，按“报价授权”“链上放款”区分，不混用，也不用其他报价的哈希替代；规则见[所交互的合约、签名用途与交易哈希](#chain-display)。
- 操作页之外的只读资料按[操作页与详情页的信息归属](#operation-information)保留：完整商务条款、报价及锁定信息、完整地址与预计计划在本轮融资申请详情按权限可查；不因操作页精简而删去或失去入口。
- 当前报价给出关键信息：报价机构、结算币种与结算金额、年化利率、状态及已锁定时长；已放款的另给出放款编号与放款成功时间。还款类型、最终还款日、放款地址、授权状态、链上放款记录与完整条款不必常驻，可以按需查看。当前报价、报价历史与链上放款记录都不展示交易哈希；链上放款处理中、未成功或待核实的一次，在操作记录的“链上放款”一条中标明状态并给出已取得的哈希。没有当前报价时明确空态，不拿最近一笔已拒绝或已失效的报价充当当前。
- 非本笔当事的资金方在融资申请信息清单与申请详情中只看到报价机构名称与需求状态（清单中列出的年化利率同样不对其展示）；其余报价信息都不展示，也不能通过直接访问取得。
- 报价历史只给每笔的关键信息与终结原因：报价机构、融资业务编号、报价时间、结算币种、年化利率、终结结果（已拒绝或已失效）与终结时间；已拒绝的给出拒绝原因，已失效的给出所属需求的终结原因；资金方另可看到本机构这笔的授权状态，已拒绝或已失效且授权未撤销的，在我的控制台的“链上授权”清单中办理撤销（[撤销授权（D-MC-214）](../09-我的控制台/01-我的控制台-PRD.md#d-mc-214)）。不再展开该笔的完整条款（同一轮的融资金额、还款类型与最终还款日都相同）。
- 报价历史的可见范围：资产方看到本轮全部报价；资金方只看到本机构自己的报价，看不到其他机构的历史报价；拒绝原因只对该笔双方展示。查看历史不替换当前报价、不改变办理对象，历史报价不能接受、修改或恢复。
- 授信摘要只对当事方给出当前机构对该企业的授信额度与授信已用额（USDT），说明它跨项目共用、不是本申请独享；不改写历史业务的金额，不开放对方完整档案；融资申请详情可按需展开授信详情、历史与协议，给出被授信企业识别资料、授信编号、状态、额度、占用明细、可用授信、首次授信时间、有效期至与历次记录，按原有权限只读查阅，内部备注仍只对本机构可见。
- 协议文件现只有授信协议（融资合同不进入平台），只对该次授信的双方展示；按文件给出文件名、所属业务与文件状态，文件名可直接下载；没有文件与读取失败分别说明，失败可重试；提供预览时不改变当前办理对象，可返回原对象。历史文件不覆盖当前文件，授信协议不混作融资合同。

**需求对外状态。**

- 需求对外状态（待报价、已报价待确认、放款中、已放款、已失效／已关闭）由融资需求与代币质押模块派生，列表、详情与我的控制台一致，本模块不另建。
- 本模块提供的事实：报价成功推动“待报价 → 已报价待确认”；签名核验通过、链上放款处理中对应“放款中”；链上放款成功推动“已放款”；链上放款失败回到“已报价待确认”；拒绝且需求仍有效时回到“待报价”；需求终结取融资需求与代币质押模块的事实。融资需求模块的派生口径须同步，见[依赖](#deps)。见[对外状态协作（ST-CR-03）](./02-授信报价与接受拒绝-流程图与状态机.md#st-cr-03)。

<a id="navigation"></a>
**从控制台或消息进入。**

- 从我的控制台或站内信进入时，定位到原项目、原融资申请与具体的融资业务编号，沿[融资需求与代币质押的定位规则](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#records)。
- 控制台经摘要详情唯一导航进入原项目的原 FP-28/FD 只读位置；需要报价或接受时，由用户从项目既有业务入口独立发起；撤销授权在我的控制台的“链上授权”清单中办理。原对象定位按[控制台原对象阅读定位建议（Q-MC-60）](../09-我的控制台/01-我的控制台-PRD.md#q-mc-60)建议执行、待确认，未具备时显式降级同项目并保留原编号和返回。站内信目标仍按本模块通知册，不统一改为控制台。
- 每次进入都重新判断权限与当前状态；资金方真正发起报价时重新做授信核验，资产方发起本笔接受时重新核对对象；已处理只读原结果，不重开旧操作、不改投同申请新报价。
- 我的控制台除[修改授信](../09-我的控制台/01-我的控制台-PRD.md#credit-modify)与“链上授权”清单中的撤销授权（[撤销授权（D-MC-214）](../09-我的控制台/01-我的控制台-PRD.md#d-mc-214)）外，只读展示本模块事实，不执行报价、授权、接受或拒绝；返回时保留来源位置。

<a id="notifications"></a><a id="f-ls-33"></a>
### 8.2 本模块发送的站内信（F-LS-33）

- 本模块发送六类站内信：收到融资报价（发资产方）、融资报价已接受，已放款（发原报价资金方）、融资放款已到账（发资产方）、融资放款未完成（发双方）、接受被拦下提醒（发原报价资金方）、融资报价已拒绝（发原报价资金方）。触发、收件、内容与落点见[消息通知](./03-授信报价与接受拒绝-消息通知.md)。
- 需求终结带来的报价连带失效由融资需求与代币质押模块合并发送，本模块不重复。
- 报价没有有效期，因此没有临期提醒或到期结果消息；首次授信、追加授信、重新授信与授信到期，第一步的报价信息签名，余额校验、授权与撤销授权，接受签名与链上放款处理中，同一笔第二次及以后被授权或余额拦下，文件上传与浏览，失败与草稿都不发信；没有周期提醒、多档提醒或运营广播。
- 同一账号、同一笔、同一事件只发一条；通知发送失败不回滚业务，用户仍可在页面查看本笔状态。

## 9. 按用户决定保留的业务限制

以下是用户明确裁定后的既定结果，如实记录业务后果，供研发与测试知悉，不作为缺陷处理。
