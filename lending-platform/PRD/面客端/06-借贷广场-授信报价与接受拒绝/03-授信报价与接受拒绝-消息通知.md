# 授信报价与接受拒绝 · 消息通知

2026-10-26｜需求评审稿

本册写本模块发送的站内信，规则以[功能与业务规则](./01-授信报价与接受拒绝-PRD.md)为准；验收见[验收](./04-授信报价与接受拒绝-验收.md#notice)。只有站内信，没有邮件、短信、浏览器推送或运营广播。

- 本模块自己发送 6 类：收到融资报价、融资报价已接受，已放款、融资放款已到账、融资放款未完成、接受被拦下提醒、融资报价已拒绝。放款改为接受时的链上放款，原放款模块的放款消息不再存在，链上放款的结果由本模块发送。
- 所属融资需求终结使在途报价连带失效时，由融资需求与代币质押模块的[融资需求终结通知（N-LS-05）](../05-借贷广场-融资需求与代币质押/03-融资需求与代币质押-消息通知.md#n-ls-05)合并发给双方；本模块不另发报价失效消息。
- 我的控制台和消息中心展示同一事实，不各自补发。
- 本期一个企业只有一个账号；发给“资产方”的消息即发给该企业的唯一账号。

编号说明：事件编号（N-CR-*）与模板编号（T-CR-*）被其他模块引用，沿用原值；已删除的事件与模板不再占号，缺号不代表遗漏。

<a id="events"></a>
## 1. 本模块发送的消息

<a id="n-cr-01"></a>
### 收到融资报价（N-CR-01）

- **所在功能与触发环节**：[生成融资业务并锁定需求（F-LS-25）](./01-授信报价与接受拒绝-PRD.md#quote-lock)；资金方签名授权（即提交报价）上链成功并进入待接受时。
- **不触发**：资金方点击签名、报价处理中（授权交易未确认）、终检未通过、上链失败或结果未知；报价处理中上链成功、但所属需求已终结的（由融资需求终结通知覆盖）；不给刚提交的资金方发“提交成功”回执。
- **收件人**：该融资申请所属企业的资产方账号。不发给资金方、运营、浏览者或其他企业。
- **推送内容要点**：融资申请编号、融资业务编号、报价机构名称、融资金额（USDT）；说明报价机构已在链上授权本笔资金，接受即放款到本轮融资收款地址；说明报价没有有效期、在接受或拒绝之前一直有效；说明所属需求因项目到期或质押水位不足而终结时，本笔将同时失效。不出现任何到期时刻、剩余时长或倒计时。
- **打开后去哪**：本项目，定位到原融资申请与本笔报价，进入本笔接受或拒绝的办理（P-LS-06），进入时重新判断权限与状态。
- **原业务已变化时**：本笔已接受、已拒绝或已失效的，只展示原报价结果与当前状态，不开启旧操作，不自动切换到同申请的新报价；无权时按消息中心的无权限说明处理，不泄露私有记录。
- **模板**：[T-CR-01](#t-cr-01)。

<a id="n-cr-04"></a>
### 融资报价已接受，已放款（N-CR-04）

- **所在功能与触发环节**：[核对商务摘要、接受并收款（链上放款）（F-LS-29）](./01-授信报价与接受拒绝-PRD.md#respond-contract)；链上放款成功、本笔进入还款中时。
- **不触发**：资产方点击接受并收款、签名、签名核验不通过、发起前被拦下、链上放款处理中、明确失败或结果未知。
- **收件人**：本笔报价的资金方账号（原报价机构）。不发给该机构以外的资金方、浏览者或运营。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、放款金额与币种、放款成功时间；本笔结算金额已按授权从放款地址转出，本笔已进入还款中，正式还款计划在还款信息中查看。不出现地址，不提及合同盖章件。
- **打开后去哪**：原融资申请中本笔已接受的报价及其链上放款记录，只读。
- **原业务已变化时**：已推进到还款或结清的，展示同一笔的最新事实；消息点击不等于任何办理指令。
- **模板**：[T-CR-04](#t-cr-04)。

<a id="n-cr-06"></a>
### 融资放款已到账（N-CR-06）

- **所在功能与触发环节**：[核对商务摘要、接受并收款（链上放款）（F-LS-29）](./01-授信报价与接受拒绝-PRD.md#respond-contract)；链上放款成功、本笔进入还款中时。链上放款在资产方签名后异步完成，资产方可能已离开页面，因此单独告知结果。
- **不触发**：签名、签名核验不通过、发起前被拦下、链上放款处理中、明确失败或结果未知。
- **收件人**：本笔所属企业的资产方账号。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、报价机构名称、放款金额与币种、放款成功时间；款项已转入本轮融资收款地址，本笔已进入还款中，正式还款计划在还款信息中查看。不出现地址。
- **打开后去哪**：原融资申请中本笔已接受的报价及其链上放款记录，只读。
- **原业务已变化时**：已推进到还款或结清的，展示同一笔的最新事实。
- **模板**：[T-CR-06](#t-cr-06)。

<a id="n-cr-07"></a>
### 融资放款未完成（N-CR-07）

- **所在功能与触发环节**：[核对商务摘要、接受并收款（链上放款）（F-LS-29）](./01-授信报价与接受拒绝-PRD.md#respond-contract)；签名核验通过、链上放款明确失败、本笔保持待接受时。
- **不触发**：未签名或取消、签名核验不通过、发起前因授权或余额不足被拦下（由[接受被拦下提醒（N-CR-08）](#n-cr-08)处理）、处理中或结果长期未知（按客服提示处理）。
- **收件人**：本笔所属企业的资产方账号，与本笔报价的资金方账号，各一条。
- **推送内容要点**：融资申请编号、融资业务编号、失败时间、可读的失败原因（例如资金方放款地址的授权或余额不足）；本笔仍待接受，在途金额不变。给资产方的说明可以重新签名接受或拒绝；给资金方的说明若原因在授权或余额，须恢复后资产方才能完成接受。不出现地址或授权金额。
- **打开后去哪**：资产方定位到本笔报价，进入接受或拒绝的办理（P-LS-06），进入时重新判断权限与状态；资金方定位到本笔报价，只读。
- **原业务已变化时**：本笔之后已放款、已拒绝或已失效的，只展示最新结果，不开启旧操作。
- **模板**：[T-CR-07](#t-cr-07)。

<a id="n-cr-08"></a>
### 接受被拦下提醒（N-CR-08）

- **所在功能与触发环节**：[核对商务摘要、接受并收款（链上放款）（F-LS-29）](./01-授信报价与接受拒绝-PRD.md#accept-precheck)；资产方点击“接受并收款”或签名核验时，发现放款地址对本项目放款合约的授权额度或本笔结算币种的余额不足以支付本笔结算金额，本次接受被拦下（用户 2026-10-22 裁定）。
- **只发一次**：同一笔报价第一次被拦下时发送；之后同一笔再被拦下，不论原因是否相同，都不再发送。
- **不触发**：授权与余额查询暂时失败；质押水位不安全或未知；签名后链上放款失败（由[融资放款未完成（N-CR-07）](#n-cr-07)通知）。
- **收件人**：本笔报价的资金方账号（原报价机构）。不发给资产方（资产方在页面上直接看到原因），也不发给其他机构或运营。
- **推送内容要点**：融资申请编号、融资业务编号、被拦下的时间、原因（授权不足、余额不足或两者都不足）；资产方已尝试接受本笔，须补足放款地址上本笔结算币种的余额，资产方才能完成接受；授权在报价后一直保留，不需要重新授权（授权被自行撤销的除外）；本笔仍待接受，在途金额不变。不出现地址、授权金额或余额数值。
- **打开后去哪**：原融资申请中本笔的报价，只读；可以看到本笔放款地址、所需金额与当前授权状态。平台不提供重新授权，余额由资金方在平台外补足。
- **原业务已变化时**：本笔之后已放款、已拒绝或已失效的，只展示最新结果。
- **模板**：[T-CR-08](#t-cr-08)。

<a id="n-cr-05"></a>
### 融资报价已拒绝（N-CR-05）

- **所在功能与触发环节**：[拒绝及并发结果（F-LS-30）](./01-授信报价与接受拒绝-PRD.md#respond-reject)；资产方拒绝正式成功、本笔进入已拒绝时。
- **不触发**：拒绝原因为空、提交失败或结果未知；不给刚操作的资产方发回执。
- **收件人**：本笔报价的资金方账号（原报价机构）。
- **推送内容要点**：融资申请编号、融资业务编号、拒绝时间、资产方填写的拒绝原因全文；本笔在途报价金额已释放，原报价不能恢复，之后报价以当前资格为准；可以按需撤销本笔对放款合约的授权（[撤销授权（F-LS-41）](./01-授信报价与接受拒绝-PRD.md#revoke)）。不出现放款地址或授权金额。
- **打开后去哪**：原融资申请中本笔的报价历史，只读；需要撤销授权时，在我的控制台“我的报价”中选中本笔办理，进入时重新判断权限与授权状态。
- **原业务已变化时**：即使原申请已有新报价，仍定位原笔；可显示当前业务事实，但不在历史中提供重新报价或其他业务的快捷入口。
- **模板**：[T-CR-05](#t-cr-05)。

<a id="not-sent"></a>
## 2. 不发送的情况

- 首次授信、追加授信、重新授信与授信到期。
- 上传授信协议、选定放款地址、余额校验、查看摘要、草稿与失败。
- 报价第一步签名确认报价信息的成功、取消与作废。
- 签名授权（即提交报价）的发起、处理中与失败；撤销授权的发起与结果。
- 资产方签名接受、签名核验不通过、放款前资金方报价签名核验不通过与链上放款处理中；同一笔第二次及以后因授权或余额不足被拦下。
- 选定或改选还款收款地址。
- 浏览、复制、下载报价或切换历史。
- 报价长时间待接受：没有临期、催办、到期或周期提醒。
- 运营端汇率管理的配置变化、外部行情、参考结算币种、授信摘要的变化；不因此重算消息中的金额。
- 需求终结带来的报价连带失效（由融资需求与代币质押模块合并发送）。
- 还款节点（由链上还款模块发送）。

<a id="ownership"></a>
## 3. 同一事实由一个模块发送

| 事实 | 谁发送 | 相邻模块怎么做 |
| --- | --- | --- |
| 报价成功、接受（链上放款成功）、链上放款失败、接受被授权或余额拦下、拒绝 | 本模块发送收到融资报价（N-CR-01）、融资报价已接受，已放款（N-CR-04）、融资放款已到账（N-CR-06）、融资放款未完成（N-CR-07）、接受被拦下提醒（N-CR-08）、融资报价已拒绝（N-CR-05） | 融资需求与代币质押、链上还款、我的控制台和消息中心只展示事实，不发同义消息 |
| 本轮需求因项目到期或质押水位不足终结，连带本笔待接受报价失效 | 融资需求与代币质押模块按融资需求终结通知（N-LS-05）向资产方与在途报价的资金方各发一条，正文同时告知报价失效 | 本模块不发任何报价失效消息，但仍负责本笔失效与在途报价金额释放；历史中可查融资业务编号、实际终结时刻、具体原因与释放结果 |
| 先拒绝报价，之后需求另因项目到期或质押水位不足终结 | 两个独立事实各由其模块发送：拒绝由本模块发 N-CR-05，需求终结由融资需求与代币质押模块发 N-LS-05 | 已被拒绝、没有在途报价的原资金方不因历史报价再收到需求终结通知 |
| 需求终结与接受或拒绝同时发生 | 按业务裁定的本笔唯一结果发送：需求终结成立由融资需求与代币质押模块发，接受或拒绝成立由本模块发 | 不同时宣告已接受、已拒绝和已失效；补处理不产生第二个结果 |
| 链上放款成功之后的还款计划与还款 | 链上还款模块 | 本模块只告知已放款、已进入还款中；计划生成进度与还款提醒由还款模块按自己的规则发送，不重复告知放款 |

<a id="rules"></a>
## 4. 共同规则

- **收件归属**：收件账号须能由本笔可靠确定，消息归该账号；没有可靠归属时不由管理员或当前登录者补位；账号停用、换角色或失权不自动转给他人；历史消息不随后来的办理者改投。同钱包、同邮箱或跨端身份不串信。
- **同一事件只一条**：同一账号 + 同一融资业务编号 + 同一事件只发一条；重复到达或补处理不新增、不置顶、不恢复未读、不改发生时间。同一融资申请下的新报价是新业务，有自己的消息，不覆盖旧报价的消息。
- **内容是发生时的事实**：保留事件发生时的机构、金额、时间与结果；乱序到达不恢复待接受。金额、名称与时间来自本笔业务事实，不用当前汇率重算；参考结算币种不影响收件。
- **阅读不等于办理**：读信或全部已读不是接受、拒绝、放款或撤销授权；点击消息不代替勾选或提交，办理仍需当前权限与条件。
- **每次点击重新判权**：重新判断身份、归属、对象、状态与文件权限；未登录先登录并保留合法目标；无权或不存在不泄露存在性；原业务定位未就绪时保留可读消息并说明暂不可查看，不猜测地址、不静默跳首页。
- **发送失败**：不回滚业务、不解锁、不重置；用户仍可在页面查看本笔结果与可做的动作。
- **时间展示**：业务日期按 UTC，时刻按收件人偏好时区展示并标注时区；没有偏好时按平台规则。
- **消息内不出现**：授信额度、机构内部备注、账号、地址、协议正文；必要的企业名称不开放对方账户档案。

## 5. 登记信息与中英模板

<a id="registration"></a>
### 5.1 登记信息

按[面客消息中心的来源接入登记要求](../10-面客消息中心/01-面客消息中心-PRD.md#rg-nc-01)登记。六类消息的平台与端都是借贷平台面客端，发送来源都是本模块，打开后去哪都是原业务；适配状态均为“待适配”，不等于已完成共享登记或真实送达。分类取值由消息中心最后统一核对。

| 消息 | 业务类型标识 | 分类 | 模板 | 同一事件的区分依据 | 消息有效期 |
| --- | --- | --- | --- | --- | --- |
| 收到融资报价（N-CR-01） | financing.quote.submitted | 业务办理进度 | T-CR-01 | 收件账号 + 本笔融资业务编号 + 报价成功 | 办理指引持续有效，直到本笔被接受、拒绝或连带失效；之后停止引导办理，历史保留 |
| 融资报价已接受，已放款（N-CR-04） | financing.quote.accepted | 业务办理进度 | T-CR-04 | 收件账号 + 本笔融资业务编号 + 链上放款成功 | 结果消息，不另设有效期 |
| 融资放款已到账（N-CR-06） | financing.loan.disbursed | 业务办理进度 | T-CR-06 | 收件账号 + 本笔融资业务编号 + 链上放款成功 | 结果消息，不另设有效期 |
| 融资放款未完成（N-CR-07） | financing.loan.failed | 业务办理进度 | T-CR-07 | 收件账号 + 本笔融资业务编号 + 本次链上放款交易 | 对资产方的办理指引持续有效，直到本笔已放款、已拒绝或已失效；之后停止引导办理，历史保留 |
| 接受被拦下提醒（N-CR-08） | financing.loan.blocked | 业务办理进度 | T-CR-08 | 收件账号 + 本笔融资业务编号 + 接受被拦下（同一笔只发一次） | 提醒持续有效，直到本笔已放款、已拒绝或已失效；之后停止提醒，历史保留 |
| 融资报价已拒绝（N-CR-05） | financing.quote.rejected | 业务办理进度 | T-CR-05 | 收件账号 + 本笔融资业务编号 + 拒绝 | 结果消息，不另设有效期 |

模板标题与正文成对登记；同一账号同一事件不收两封。

<a id="variables"></a>
### 5.2 模板变量

| 变量 | 业务含义 | 用在哪些模板 | 要求 |
| --- | --- | --- | --- |
| demand_id | 原融资申请编号（FP-28） | 全部 | 不能用同一项目的新申请代替 |
| business_id | 本笔融资业务编号（FD-01） | 全部 | 不能用放款编号代替 |
| institution_name | 本笔真实报价机构名称 | T-CR-01、T-CR-06 | 用企业可展示名称，不用个人姓名、邮箱或钱包地址 |
| amount_usdt | 本笔报价的融资金额，USDT，大于 0 | T-CR-01 | 明确是融资金额，不把 USDC 结算金额标成 USDT |
| loan_id | 本笔放款编号（LN-01） | T-CR-04、T-CR-06 | 链上放款成功后才有，不用虚构编号补位 |
| loan_amount | 本笔放款金额（LN-04）与币种，USDT 或 USDC | T-CR-04、T-CR-06 | 取锁定的结算金额，不用当前汇率重算 |
| disbursed_at | 放款成功时间（FD-40） | T-CR-04、T-CR-06 | 取上链成功并经平台确认的时刻，不取签名时间 |
| failed_at | 平台确认链上放款失败的时刻 | T-CR-07 | 不取签名时间 |
| fail_reason | 可读的失败原因 | T-CR-07 | 面向业务人员的说明，不透出合约报错或内部诊断 |
| blocked_at | 平台确认本次接受被拦下的时刻 | T-CR-08 | 同一笔第一次被拦下的时刻 |
| block_reason | 授权不足、余额不足或两者都不足 | T-CR-08 | 只写原因类别，不出现金额或地址 |
| rejected_at | 平台确认本笔拒绝成功的时刻 | T-CR-05 | 不取点击时间 |
| reason | 资产方填写的拒绝原因原文，1～200 字 | T-CR-05 | 完整呈现，不用内部备注代替，不声称已自动翻译 |

- 必要变量或收件归属缺失时，不用演示值、空白消息、假编号或裸占位符补齐，按来源补齐后再发；单条缺失不影响整个消息列表可用。
- 中英模板的变量名称与数量一致；时间与金额按平台统一格式展示；拒绝原因按纯文本保留，不拼接动态动词或状态片段。
- 任何模板都不出现报价到期时刻、剩余时长或催办措辞。

## 6. 依赖

- **面客消息中心**：六类事件的分类、模板与原业务定位须完成共享登记与真实送达验证；未完成前为“待适配”，不能称已上线。
- **融资需求与代币质押**：需求终结通知（N-LS-05）的触发、收件与内容以该模块为准。
- **链上还款**：链上放款成功后的计划生成与还款提醒由该模块发送；原放款模块的“放款记录已提交”“资产方已确认放款到账”已随放款模块删除，不再存在。
