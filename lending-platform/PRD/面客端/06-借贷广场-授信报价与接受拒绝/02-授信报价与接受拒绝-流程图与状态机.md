```mermaid
  P -->|"通过"| J["资产方用登录地址<br/>在钱包中签名<br/>不上链、不产生 gas"]

  J --> K{"平台核验：签名地址为登录地址，<br/>内容一致，本笔仍待接受，<br/>水位、授权与余额仍满足？"}

  L --> M{"链上结果"}

  M2 --> D
  M -->|"成功"| N["接受成功、放款完成<br/>生成放款编号与链上放款记录<br/>两个维度在途转为本金<br/>本笔进入还款中，交还款模块<br/>双方收到通知，停留在原处"]
```

接受在同一页完成，看摘要只是待接受内的办理进度，停留多久都不改变结论；钱包内的签名就是最终确认，不另设勾选。接受即链上放款，之后没有独立的放款登记与放款确认。发起时被授权或余额拦下的，同一笔只在第一次提醒资金方。

同一放款地址可以同时为多笔待接受报价授权；任何一笔的授权或解除都不减少其他待接受报价所需的额度。授权与解除授权都用放款地址签名，放款地址可以不是登录地址；签名只为授权合约，与登录无关，签名前后登录状态不变。授权与解除授权都不发送站内信。

## 授信生命周期（ST-CR-01）

```mermaid
stateDiagram-v2
  direction LR
  state "生效中" as ACTIVE
  state "已到期" as EXPIRED
  [*] --> ACTIVE: 首次授信成功
  ACTIVE --> EXPIRED: 有效期至次日<br/>00:00 UTC
  EXPIRED --> ACTIVE: 报价流程内<br/>重新授信成功
  note right of ACTIVE
    追加：正数增加额（USDT）
    有效期至保持
    或在五年上限内延后
    状态不变；协议均为选填
  end note
```

追加不重置五年上限的起点；授信到期只阻止新报价，不影响已有业务。

<a id="st-cr-02"></a>
## 融资业务本模块状态（ST-CR-02）

```mermaid
stateDiagram-v2
  state "待接受" as WAIT
  state "已拒绝" as REJECTED
  state "报价已失效" as EXPIRED
  state "还款中（S-FD-6）" as FUNDING
  [*] --> WAIT: 报价成功<br/>生成融资业务编号<br/>增加在途报价金额
  WAIT --> REJECTED: 资产方拒绝<br/>原因必填，不签名
  WAIT --> EXPIRED: 所属需求终结<br/>项目到期或<br/>质押水位不足
  WAIT --> FUNDING: 资产方签名接受<br/>链上放款成功
  REJECTED --> [*]
  EXPIRED --> [*]
  note left of WAIT
    看摘要只是办理进度
    链上放款处理中
    仍属待接受，不能拒绝
    没有时限
  end note
  note right of FUNDING
    由还款计划与还款确认承接
    此处不是终态
    不再经过待放款
    与待放款确认
  end note
```

待接受、已拒绝、报价已失效对应融资业务状态 S-FD-1、S-FD-2、S-FD-11；已拒绝与报价已失效不能恢复。链上放款成功后本笔直接进入还款中（S-FD-6），之后的状态由[还款计划与还款确认](../08-借贷广场-还款计划与还款确认/01-还款计划与还款确认-PRD.md)定义；待放款（S-FD-3）与待放款确认（S-FD-4）不再使用。本状态机没有按时间自动发生的转移。

## 对外状态协作（ST-CR-03）

```mermaid
%%{init: {"flowchart": {"htmlLabels": false}}}%%
flowchart LR
  A["待报价"] -->|"本模块：报价成功"| B["已报价待确认"]
  B -->|"本模块：签名核验通过<br/>链上放款处理中"| C["放款中"]
  C -->|"本模块：链上放款失败"| B
  B -->|"本模块：拒绝<br/>需求仍有效"| A
  A -. "融资需求模块终结需求<br/>撤下或项目关闭<br/>项目到期或<br/>质押水位不足" .-> E["已失效／已关闭"]
  B -. "项目到期或<br/>质押水位不足<br/>报价同时连带终结" .-> E
  C -->|"本模块：链上放款成功"| D["已放款"]
```

需求对外状态的唯一来源是[融资需求与代币质押](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#project-state)；本模块只提供报价、链上放款、拒绝与连带失效的事实，不据此图另建派生规则。融资需求模块现行派生仍以放款确认推动“已放款”，须由该模块同步。

## 本笔授权状态（ST-CR-04）

```mermaid
stateDiagram-v2
  state "未授权" as NONE
  state "授权处理中" as GRANTING
  state "已授权" as GRANTED
  state "解除处理中" as REVOKING
  state "已解除" as REVOKED
  state "已使用" as USED
  [*] --> NONE: 选定放款地址<br/>余额校验通过
  NONE --> GRANTING: 放款地址签名<br/>发送授权交易
  GRANTING --> NONE: 明确失败
  GRANTING --> GRANTED: 上链成功
  GRANTED --> REVOKING: 本笔已拒绝或已失效<br/>放款地址签名解除
  REVOKING --> GRANTED: 明确失败
  REVOKING --> REVOKED: 上链成功
  GRANTED --> USED: 资产方接受<br/>链上放款成功
  REVOKED --> [*]
  USED --> [*]
  note right of GRANTED
    报价成功后关联本笔
    待接受与链上放款
    处理中不提供解除
    放款失败时授权保留
  end note
```

已足额授权的地址在报价时跳过授权，直接处于已授权。资金方在平台外自行撤销的，按链上事实显示。解除入口在我的控制台“我的报价”。
