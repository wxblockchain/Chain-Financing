# 链上还款 · 消息通知

2026-10-26｜需求评审稿

<a id="notify-entry"></a>
本册写本模块发送的站内信，规则以[功能与业务规则](./01-链上还款-PRD.md)为准；验收见[验收](./04-链上还款-验收.md#notice)。只有站内信，没有邮件、短信、浏览器推送或运营广播。

- 本模块自己发送 7 类：还款计划已定稿、应还临近提醒、本期还款逾期、本期还款已完成、本笔融资业务已结清、本期还款已到账、本期还款未完成。
- 链上放款成功由授信报价与接受拒绝告知双方：资金方收[融资报价已接受，已放款（N-CR-04）](../06-借贷广场-授信报价与接受拒绝/03-授信报价与接受拒绝-消息通知.md#n-cr-04)，资产方收[融资放款已到账（N-CR-06）](../06-借贷广场-授信报价与接受拒绝/03-授信报价与接受拒绝-消息通知.md#n-cr-06)；本模块的计划定稿只发资产方。
- 资产方先授权签名、授权上链成功后再进行还款交易签名；仅授权不提交还款。已发出交易的链上结果异步确认，授权或还款交易明确失败时告知资产方，链上还款成功时告知双方；资金方不参与办理。
- 本册“签名提交”指还款交易签名完成且交易已发出；授权签名或授权成功不冻结逾期。授权进度、待交易签名、签名提交与还款处理中不发信；没有资金方确认环节，因此没有“请确认收到还款”一类消息。
- 我的控制台和消息中心展示同一事实，不各自补发。
- 本期一个企业只有一个账号；发给“资产方”或“资金方”的消息即发给该企业的唯一账号。

编号说明：事件编号（N-RP-*）与模板编号（T-RP-*）被其他模块引用，沿用原值；已删除的事件与模板不再占号，新增事件接续原编号，缺号不代表遗漏。

<a id="events"></a>
## 1. 本模块发送的消息

<a id="n-rp-01"></a><a id="N-RP-01"></a>
### 还款计划已定稿（N-RP-01）

- **所在功能与触发环节**：[定稿后告知新旧安排（F-LS-63）](./01-链上还款-PRD.md#f-ls-63)；链上放款成功后，本笔定稿计划实际生成完成、可以完整阅读时。
- **不触发**：计划仍在生成中；生成失败或结果未知；报价阶段的预计计划试算；生成恢复后再次进入或刷新。
- **收件人**：本笔资产方账号。不发给资金方、运营、SPV 机构或其他企业；资金方从授信报价与接受拒绝的融资报价已接受，已放款（N-CR-04）得知本笔已进入还款中，在同一笔的还款信息中查看计划进度。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、资金方名称、计划定稿时间；预计与实际起息日、预计与定稿期数；逐期完整对照（每个序号的预计与定稿应还日、应还合计（USDT）与结算金额，任一侧没有该期时明确说明）；无需再次接受报价。
- **打开后去哪**：本项目，定位到本笔的还款详情，查看定稿计划；进入时重新判断权限与状态。
- **原业务已变化时**：之后的还款、逾期与结清按该笔当前事实展示；结清后仍可查看原定稿计划，不跳到另一笔，不在详情中恢复预计计划与定稿计划的双版切换。
- **模板**：[T-RP-01](#t-rp-01)，正文后逐期附对照条目 [T-RP-C01](#t-rp-c01)／[T-RP-C02](#t-rp-c02)／[T-RP-C03](#t-rp-c03)。

<a id="n-rp-02"></a><a id="N-RP-02"></a>
### 应还临近提醒（N-RP-02）

- **所在功能与触发环节**：[应还日开放还款（F-LS-66）](./01-链上还款-PRD.md#f-ls-66)；目标期次应还日前 3 个 UTC 自然日的 00:00，期次仍为待还款时。每期一次。
- **不触发**：开放当时或应还日当天不另发；期次已在还款处理中、已结清或已逾期时不发（已逾期只发逾期）；计划尚未定稿时不按预计期次提醒。
- **迟到补发**：计划定稿较晚、定稿时已过提醒时点但尚未逾期且仍待还款的，补发一次，写明准确的应还日与开放时刻，不写“还剩三天”。
- **收件人**：本笔资产方账号。不发给资金方、运营或 SPV 机构。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、资金方名称、期次与还款期次编号、应还日、应还合计（USDT）与结算金额及币种；还款开放时刻（应还日 00:00 UTC）；开放前只能查看、不能还款；请在出账地址上准备足够的结算币种余额及两笔交易所需的 gas，开放后先授权签名，再进行还款交易签名。不能写“已开放”或“现在可以还款”。
- **打开后去哪**：同一笔、同一期。开放前进入只读的本期安排并给出开放时刻；开放后仍为待还款的，进入本期的授权并还款办理（P-LS-09）。
- **原业务已变化时**：已在处理中或已结清的，展示本期当前结果，不自动选下一期或另一笔；提醒本身到应还日次日 00:00 UTC 失效，失效不取消逾期后仍可还款的资格。
- **模板**：[T-RP-02](#t-rp-02)。

<a id="n-rp-03"></a><a id="N-RP-03"></a>
### 本期还款逾期（N-RP-03）

- **所在功能与触发环节**：[形成逾期标记（F-LS-70）](./01-链上还款-PRD.md#f-ls-70)；应还日次日 00:00 UTC 仍未签名提交还款交易（包括授权未完成或已授权待交易签名）、首次形成该期逾期时；或签名提交后链上未成功、本期回到待还款时已经逾期而此前未发过本条，见[签名提交后冻结逾期天数与业务逾期标记（F-LS-68）](./01-链上还款-PRD.md#f-ls-68)。每期一次。
- **不触发**：逾期天数逐日增加时不重发、不恢复未读；应还日次日 00:00 UTC 时本期仍在还款处理中的，此时不发；本期已结清的，不追补过时的催还；业务逾期标记清除时不发。
- **收件人**：本笔资产方账号与本笔资金方账号（原报价机构的账号），各一条。不发给运营或 SPV 机构。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、资金方名称、期次与还款期次编号、应还日、截至发信时点的逾期天数（迟到判定按实际已经过的天数，不固定写 1 天）、应还合计（USDT）与结算金额及币种；不产生罚息。资产方的消息提示通过“授权并还款”先授权签名、再交易签名，还款交易发出才冻结本期逾期天数；资金方的消息只供查看，资金方无需办理。
- **打开后去哪**：同一笔、同一期。资产方仍为待还款时进入本期授权并还款办理；资金方进入只读的本期详情，不获得还款动作。
- **原业务已变化时**：处理中的展示链上进度，已结清的展示结果；已送达的消息保留当时事实。
- **模板**：资产方用 [T-RP-03A](#t-rp-03a)，资金方用 [T-RP-03B](#t-rp-03b)。

<a id="n-rp-07"></a><a id="N-RP-07"></a>
### 本期还款已完成（N-RP-07）

- **所在功能与触发环节**：[出账地址、余额校验与授权并还款（F-LS-67）](./01-链上还款-PRD.md#repay-success)；本期链上还款上链成功、本期结清，但这次还款没有使本笔全部期次结清时。每期一次。
- **不触发**：签名提交、还款处理中、明确失败或结果未知；这次还款使全部期次结清的（改发本笔融资业务已结清，不另发本条）。
- **收件人**：本笔资产方账号。不发给资金方、运营或 SPV 机构。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、资金方名称、期次与还款期次编号、还款金额与币种、还款成功时间；本期已结清，款项已由还款合约转入资金方还款收款地址，无需资金方确认；本笔仍有其他未结清期次；利息期不说成归还了本金或释放了额度；不表示项目质押已释放。不出现地址或交易哈希。
- **打开后去哪**：同一笔、同一期的只读结果，给出还款记录与本笔当前进度。
- **原业务已变化时**：之后整笔结清的，展示当前结清事实；已送达的消息仍说明当时本期的结果。
- **模板**：[T-RP-07](#t-rp-07)。

<a id="n-rp-08"></a><a id="N-RP-08"></a>
### 本笔融资业务已结清（N-RP-08）

- **所在功能与触发环节**：[全部期次结清后结束业务（F-LS-74）](./01-链上还款-PRD.md#f-ls-74)；某期链上还款成功使本笔全部期次结清、本笔进入已结清、记录业务结清时间时。
- **不触发**：全部本金已还但仍有利息期未结清；末期已结清而较早的期次仍未结清（末期只发本期还款已完成与本期还款已到账）；链上还款未成功或结果未知。是否全部结清以真实期次状态判断，不凭期次序号。
- **收件人**：本笔资产方账号与本笔资金方账号（原报价机构的账号），各一条。这一条同时说明本次结清的期次，双方都不再另收本期还款已完成或本期还款已到账。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、资金方名称、本次结清的期次与还款期次编号、还款成功时间、业务结清时间；本笔未偿本金与对应的项目融资余额、授信占用额已归零（不代表其他业务的占用归零）；单笔结清不直接释放项目质押，项目满足关闭或结清条件后才整池业务释放；已释放的代币须由资产方从“解除质押—提取已释放”自行提取并自付 gas，不会自动回到钱包。
- **打开后去哪**：本笔的还款详情与结清结果；正文给出项目质押与提取入口的名称与条件，实际办理走项目既有入口，不为资金方开放资产方的提取动作。
- **原业务已变化时**：项目之后的状态与质押变化按融资需求与代币质押模块的当前事实展示。
- **模板**：资产方用 [T-RP-08A](#t-rp-08a)，资金方用 [T-RP-08B](#t-rp-08b)。

<a id="n-rp-09"></a><a id="N-RP-09"></a>
### 本期还款已到账（N-RP-09）

- **所在功能与触发环节**：[出账地址、余额校验与授权并还款（F-LS-67）](./01-链上还款-PRD.md#repay-success)；本期链上还款上链成功、款项转入资金方还款收款地址，但这次还款没有使本笔全部期次结清时。每期一次。
- **不触发**：资产方签名提交、还款处理中、明确失败或结果未知；这次还款使全部期次结清的（改发本笔融资业务已结清，不另发本条）。
- **收件人**：本笔资金方账号（原报价机构的账号）。不发给资产方、运营、SPV 机构或其他机构。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、期次与还款期次编号、应还日、还款金额与币种、还款成功时间；本期已结清，款项已由还款合约转入本机构的还款收款地址，资金方无需确认；本期曾逾期的，说明本期已结清、逾期天数作为历史保留。不出现地址或交易哈希。
- **打开后去哪**：同一笔、同一期的只读结果与还款记录。
- **原业务已变化时**：之后整笔结清的，展示当前结清事实；已送达的消息仍说明当时本期的结果。
- **模板**：[T-RP-09](#t-rp-09)。

<a id="n-rp-10"></a><a id="N-RP-10"></a>
### 本期还款未完成（N-RP-10）

- **所在功能与触发环节**：[出账地址、余额校验与授权并还款（F-LS-67）](./01-链上还款-PRD.md#f-ls-67)；本次已发出的授权交易或还款交易明确失败时。授权失败的本期一直为待还款、不曾冻结逾期；还款交易失败的本期从还款处理中回到待还款，连续补算逾期。每次失败的办理一条。
- **不触发**：对应交易未发出前的校验失败、未签名、取消、拒绝或钱包不可用；授权成功但待交易签名；授权或还款交易仍未决、长期未知或冲突。授权成功后取消交易签名不发送失败通知，已产生的授权 gas 与授权事实保留。
- **收件人**：本笔资产方账号。不发给资金方（本期没有到账，资金方无需办理）、运营或 SPV 机构。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、资金方名称、期次与还款期次编号、应还日、应还合计（USDT）与结算金额及币种；本期还款未完成、款项没有转出，本期仍待还款；可读的失败原因（例如出账地址余额已不足）；已逾期的给出逾期天数，未逾期的提示在应还日内重新授权并还款；授权已上链而链上还款失败的，说明授权仍在链上、可在钱包中自行撤销；重办须先授权签名、再交易签名，两笔 gas 自行承担。不出现地址或交易哈希。
- **打开后去哪**：同一期的授权并还款办理（P-LS-09），进入时重新判断权限与状态。
- **原业务已变化时**：之后已重新提交或已结清的，展示本期当前结果，不再打开已失效的办理。
- **模板**：[T-RP-10](#t-rp-10)。

<a id="no-events"></a><a id="excluded"></a>
## 2. 不发送的场景

| 场景 | 处理 |
| --- | --- |
| 报价阶段的预计计划试算、日期重算告知、放款成功后计划生成中 | 不发本模块消息；链上放款成功由授信报价与接受拒绝告知双方 |
| 开放当时、应还日当天、每日或每周催还、逾期天数逐日变化 | 不发；应还临近提醒只用于准备，逾期每期只发一次 |
| 选定出账地址、余额校验、签名前校验未通过、对应交易未发出的未签名或取消、授权确认中、授权成功待交易签名、签名提交、还款处理中 | 在办理中反馈，不发信；仅交易签名取消不抹除已产生的授权 gas |
| 授权或还款交易结果长期未知或冲突 | 不发；区分待核实的是哪笔交易，保持对应期次状态与办理占用并提示联系客服 |
| 业务逾期标记清除、额度统计刷新 | 不发 |
| 切换业务、查看计划、打开详情、失败重试、读信 | 在原场景反馈，不发信，不靠消息推动状态 |
| 项目回到可用、关闭或结清，质押释放、提取成功或失败，质押情况变化 | 归融资需求与代币质押模块；本模块不另发“释放成功”或“已回到钱包” |
| 客服邮件往来、运营或 SPV 日常查看 | 本模块没有审批、裁决或代办职责，不生成运营消息，不抄送运营或 SPV |

<a id="ownership"></a>
## 3. 同一事实由一个模块发送

| 事实 | 谁发送 | 相邻模块怎么做 |
| --- | --- | --- |
| 链上放款成功 | 授信报价与接受拒绝：融资报价已接受，已放款（N-CR-04）发资金方，融资放款已到账（N-CR-06）发资产方 | 本模块不为同一次放款补发；资金方在还款信息中查看计划进度 |
| 还款计划定稿 | 本模块：还款计划已定稿（N-RP-01），只发资产方 | 资金方不收第二份定稿提醒 |
| 应还临近、逾期、本期链上还款成功或失败、业务结清 | 本模块：N-RP-02、N-RP-03、N-RP-07、N-RP-09、N-RP-10、N-RP-08 | 我的控制台、还款信息清单与消息中心只承接展示，不另发同义消息 |
| 项目状态判断、整池业务释放、提取结果 | 融资需求与代币质押模块 | 本模块只说明本笔结果与后续查看路径，不承诺项目已进入终态或代币已回到钱包 |

<a id="rules"></a>
## 4. 共同规则

- **收件归属**：资产方为本笔所属企业的账号；资金方为本笔报价机构的账号（原报价机构）。收件账号须能由本笔可靠确定，没有可靠归属时不由当前登录者或其他人补位；账号停用、换角色或失权不自动转给他人；历史消息不随后来的办理者改投；同钱包、同邮箱或跨端身份不串信。收件资格不授予还款或跨企业访问权限。非当事资金方可查看[非隐私履约信息](./01-链上还款-PRD.md#non-private-performance)，但不接收本模块任何消息。
- <a id="merge"></a>**末期结果与整笔结清合并**：某期链上还款使全部期次结清时，双方各只收一封本笔融资业务已结清，其中完整保留该期期次、还款期次编号、还款成功时间与业务结清时间；不再另收本期还款已完成或本期还款已到账。合并的是消息，不是业务事实；之前已发的单期消息不撤销、不改写。
- **同一事件只一条**：同一账号＋同一融资业务编号或还款期次编号＋同一事件只发一条；本期还款未完成按每次失败的办理区分，授权交易或还款交易明确失败分别按当次事实处理，同一次失败不重复发送。不同期次是不同事件，不因同一机构、同一天或同一融资申请而合并。重复提交、补判、刷新或生成恢复都不新增、不置顶、不恢复未读、不改发生时间。
- **内容是发生时的事实**：保留事件发生时的机构、金额、时间与结果；打开后看当前事实。金额来自本笔锁定的条款，不按当前汇率重算。
- **只发真实成立的结果**：链上还款未成功或结果未知时不发成功类消息。利息期结清不说成归还了本金或释放了额度；末期减少的是本金，不把本息合计说成释放额。
- **阅读不等于办理**：读信或全部已读不是授权或还款；点击消息不代替授权签名或还款交易签名，办理仍需当前权限与条件。
- **每次点击重新判权**：重新判断身份、归属、对象与状态；未登录先登录并保留合法目标；无权或不存在不泄露存在性；落点始终是原笔、原期，不静默改用当前默认选中的业务、同一机构最新的放款或下一期；原业务定位未就绪时保留可读消息并说明暂不可查看，不猜测地址、不静默跳首页。
- **发送失败**：不回滚已成立的业务事实，不重复扣减占用；用户仍可在页面查看本笔真实计划与进度。等待发送时重新判断消息是否仍适用；抑制过时的催还不抹除业务历史。
- **送达时效**：沿[送达时效（IF-NC-01）](../10-面客消息中心/01-面客消息中心-PRD.md#if-nc-01)。应还临近与逾期属于到点触发的事件，从应到时点起算；本模块的逾期判定在 5 分钟内完成。
- **时间展示**：业务日期按 UTC 并标注，时刻按收件人偏好时区展示并标注时区；没有偏好时按平台规则。
- **消息内不出现**：出账地址、收款地址、合约地址、交易哈希、gas 明细、客服邮箱、当事人私人邮箱；到达原业务后按原权限查阅，交易哈希在还款详情查看。
