# 链上还款 · 流程图与状态机

2026-10-26｜需求评审稿

<a id="entry"></a>
本册把[功能与业务规则](./01-链上还款-PRD.md)中的主要流程与状态画成图，规则以功能册为准。图中方框是业务环节与业务状态，不代表页面或组件，承载形式由设计决定（见[设计边界](./01-链上还款-PRD.md#design-boundary)）。资产方先完成授权签名，授权上链成功后再完成还款交易签名；还款交易发出才提交本期还款，链上还款成功即结清。两次签名时都展示所交互的还款合约与本次签名用途；两笔 gas 均由资产方承担，资金方只查看进展和结果。

## 计划形成与查看（L8-F01）

```mermaid
flowchart TD
  A[资金方报价成功] --> B[按报价日生成预计计划，标注预计·未生效]
  B --> C[资产方接受并收款，重算告知须始终可得并记录展示时间]
  C --> D[链上放款成功]
  D --> E[本笔进入还款中并进入清单，清单只显示业务状态]
  D --> N[授信报价模块告知双方已放款]
  E --> F{定稿计划已生成？}
  F -->|否| G[只在还款详情显示计划生成中，清单仍保留还款中业务]
  G -->|恢复| F
  F -->|是| H[以放款成功日为起息日，按双方约定的计息口径生成唯一定稿计划]
  H --> I[资产方收到计划定稿通知，含逐期对照]
  H --> J[双方在还款详情只读查看本期、计划、还款收款地址与记录]
  J --> W[操作记录：每笔已发出的授权或还款交易一条，哈希缩写、点击复制、可跳转区块链浏览器]
  H --> V[非当事资金方只读查看非隐私履约信息]
  H --> K[按应还日、机构与放款编号逐笔选择业务]
  K --> L[资产方按期次条件进入授权并还款]
  P[项目尚无还款业务] --> Q[保留清单与办理入口的空态说明，不伪造待办]
```

- 预计计划不进入还款信息，不产生期次编号。
- 计划尚未生成时不删除清单记录，清单业务状态仍为还款中；项目内与我的控制台还款清单都不展示生成进度，只有详情显示。
- 计划未生成时不伪造期次、日期、金额或可还款动作，也不回退已成立的链上放款。
- 还款详情中的交易哈希只在最下方的[操作记录](./01-链上还款-PRD.md#operation-records)展示，本期应还与还款记录不重复；只对本笔双方展示，跳转在新窗口打开，不改变本期状态，规则见[交易哈希的展示](./01-链上还款-PRD.md#tx-hash)。
- 还款收款地址取资金方报价时选定的还款收款地址；链上放款记录的明细在融资申请详情查看，还款信息只带编号识别同一笔。
- 平台计划采用的计息口径就是双方约定的计息口径，双方按定稿计划还款；预计计划采用同一口径但尚未生效。
- 游客、登录未绑定角色与其他企业的资产方看不到还款信息；非当事资金方可查看编号、机构、业务及期次状态、应还日、还款成功与结清时间、逾期信息，具体范围见[非隐私履约信息](./01-链上还款-PRD.md#non-private-performance)。金额、条款、地址与交易哈希仍受限，不提供办理或本笔消息。

## 授权并还款与链上结果（L8-F02）

```mermaid
flowchart TD
  A[资产方从还款办理入口选择本笔与已开放期次] --> B[在精简操作面选择本次出账地址，核对本期信息]
  B --> C[精简弹窗：本期应还、资金方、双方地址、授权金额与最终交易信息]
  C --> V1[需要完整计划、本息明细或历史时查看还款详情]
  V1 --> V2[返回原业务、原期次，保留选址与授权进度，按当前环节继续]
  C --> D{授权签名前校验通过？}
  D -->|否| E[保留内容，说明原因；本期仍待还款]
  E --> B
  D -->|是| C1[授权签名旁核对被授权的还款合约与签名用途：仅授权调取本期金额，不算还款]
  C1 --> F[本次出账地址授权签名，自付授权 gas]
  F -->|未签名或取消，授权交易未发出| E
  F -->|授权交易发出| G[授权上链确认中，授权交易计入操作记录；本笔不能重复办理，逾期照常计算]
  G --> H{授权结果？}
  H -->|明确失败| I[仍待还款，保留已产生 gas，通知资产方还款未完成]
  I --> B
  H -->|长期未知或冲突| J[授权待核实；仍待还款，逾期照常计算，不能重复发起，联系客服]
  H -->|成功| K[待交易签名；仅授权不还款，不冻结逾期]
  K --> L{交易签名前重新校验通过？}
  L -->|否| M[说明原因，保留授权事实；本期仍待还款]
  M --> K
  L -->|是| C2[交易签名旁核对执行还款的同一份还款合约与签名用途：发出即提交，不能撤回]
  C2 --> N[同一本次出账地址进行还款交易签名，自付还款 gas]
  N -->|取消、拒绝或交易未发出| K
  N -->|还款交易已发出| O[还款处理中，还款交易计入操作记录，记录提交时间，冻结本期逾期天数]
  O --> P{链上还款结果？}
  P -->|明确失败| Q[回待还款，冻结不成立，连续补算逾期；通知资产方，可重新办理]
  Q --> B
  P -->|长期未知或冲突| R[保持还款处理中与逾期冻结，不能重复发起，联系客服]
  P -->|成功| S[本期结清：唯一还款记录，操作记录两条更新为成功，累计已还更新，按本期本金减少两项占用，重判业务逾期]
  S --> T{全部期次已结清？}
  T -->|否| U[资产方收到本期已完成，资金方收到本期已到账]
  T -->|是| V[业务结清，进入业务结清与项目衔接]
```

- 操作页与操作弹窗只保留本次必要信息；完整计划、本息明细、整笔条款与历史记录在还款详情查看，正常办理不重复这些资料；页面选址后不展开出账账户详情；具体信息边界见[还款办理的信息范围](./01-链上还款-PRD.md#repay-content)。
- 两次签名的主动作旁都给出本项目还款合约（名称、Ethereum、完整地址）与一两句签名用途，不另设确认弹窗；合约读取失败或与本次授权的合约不一致时不唤起钱包，见[所交互的合约与签名用途](./01-链上还款-PRD.md#repay-contract)。
- 已发出的授权交易与还款交易在处理中、明确失败、待核实及成功结果中都给出已取得的交易哈希；未发出交易时不显示；这是当次反馈，离开办理后在还款详情的操作记录查看，见[交易哈希的展示](./01-链上还款-PRD.md#tx-hash)。
- 授权与交易签名是两个必要环节，均由资产方用本次出账地址完成、分别自付 gas；授权成功不自动发送还款交易，离开后返回仍须完成交易签名。
- 仅还款交易发出才冻结逾期；授权处理中、授权已成功但未发出还款交易时都仍待还款，逾期照常计算；这些阶段的办理占用不等于还款处理中。
- 授权成功后取消交易签名不产生还款交易 gas，但已产生的授权 gas 保留；授权仍在链上，平台无撤销入口，可在钱包自行撤销。签名取消不发失败通知，已发出交易明确失败才发。
- 签名提交与还款处理中不减少本金占用；利息期成功也不减少本金占用。重复点击、刷新或恢复同一次办理，不重复授权或还款。
- 资金方没有办理或确认环节；应还临近提醒只用于准备，不开放还款。

## 业务结清与项目衔接（L8-F03）

```mermaid
flowchart TD
  A[本笔全部期次结清] --> B[本笔业务已结清，未偿本金与两项本金占用归零]
  B --> C[双方收到本笔融资业务已结清通知]
  B --> D[交融资需求与代币质押判断项目]
  D --> E{项目内还有未处理完成的业务？}
  E -->|有| F[项目不变，不释放，不按单笔释放代币]
  E -->|没有| G{项目已到期？}
  G -->|否| H[项目回到可用，可再次发布或主动关闭；不释放]
  G -->|是| I[项目自动终结为已结清，整池业务释放]
  I --> J[代币为已释放待提取，资产方自助提取并自付 gas]
```

- 业务结清不依赖提取成功；提取失败不回退结清，也不恢复额度占用。
- 链上结果未知或冲突时只提示联系客服，不新增处置流程。

## 还款期次状态机（L8-S01）

每一期独立适用。授权阶段与待交易签名是办理进度，不新增期次状态。

```mermaid
stateDiagram-v2
  state "待还款 S-RP-1" as RP1
  state "还款处理中 S-RP-4" as RP4
  state "已结清 S-RP-3" as RP3
  [*] --> RP1: 定稿计划生成期次
  RP1 --> RP1: 授权签名或授权确认中，期次仍待还款
  RP1 --> RP1: 授权成功待交易签名，或交易签名取消
  RP1 --> RP1: 授权明确失败，结束办理占用
  RP1 --> RP1: 授权结果待核实，保留办理占用
  RP1 --> RP1: 应还日次日00时UTC仍未发出还款交易，形成或增加逾期
  RP1 --> RP4: 先授权成功，再还款交易签名并发出，冻结本期逾期
  RP4 --> RP4: 还款交易确认中或结果长期未知
  RP4 --> RP1: 还款交易明确失败，冻结不成立并连续补算逾期
  RP4 --> RP3: 链上还款成功
  RP3 --> [*]
```

- 授权上链未决时不能重复办理，本笔其他期次也不能发起；授权成功待交易签名时可以继续本次办理，主动结束后可重新选期办理，原授权保留。
- 授权阶段及待交易签名不冻结逾期；还款交易发出才记录提交时间并冻结，结清后逾期天数作为历史保留。
- 没有资金方确认或异议的状态转换；已结清不能回到其他状态，平台不提供撤销授权入口。
- 本期是否已提交与业务整体是否仍有逾期分别判断，见[业务逾期标记（FD-44）](./01-链上还款-PRD.md#f-ls-68)。

## 融资业务状态机（L8-S02）

只画本模块负责的状态段。

```mermaid
stateDiagram-v2
  state "还款中 S-FD-6" as FD6
  state "已结清 S-FD-8" as FD8
  [*] --> FD6: 链上放款成功
  FD6 --> FD6: 计划生成中，或部分期次还款处理中或结清
  FD6 --> FD6: 逾期或链上结果待核实，主状态不变
  FD6 --> FD8: 全部期次结清
  FD8 --> [*]
```

- 业务逾期标记（S-FD-9，即 FD-44）是并行标记：只要仍有已逾期且未结清的期次（待还款或还款处理中）就保留；相关逾期期次全部结清后清除，未来尚未逾期的期次不影响清除；之后另一期又逾期可以再次形成。
- 融资申请的对外状态在整个过程中保持“已放款”；业务结清不等于项目结清。
