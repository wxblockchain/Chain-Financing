## 0. 验收前准备

账号：

- 资产方两个，分属两家企业（甲、丙），均已认证；甲是本项目的发布方，并在企业账户登记了 Ethereum 数币账户用作出账地址。
- 资金方四个：乙（已认证，是本笔出资机构）；丁（已认证，与本笔无关）；戊（入驻审核中，与本笔无关）；己（入驻已驳回，与本笔无关）。乙在机构账户登记了两个以上 Ethereum 数币账户（可分别用作放款地址与不同的还款收款地址）。
- 登录未绑定角色的账号一个；游客（未登录）状态。
- 运营账号一个（用于确认无本模块能力）。

数据：

- 甲的项目上已链上放款成功的融资业务若干：USDT 结算；USDC 结算、汇率快照为 1；还款收款地址与放款地址相同、不同各一笔；同一机构乙在本项目有两笔业务；不同机构各有一笔业务。另有链上放款处理中、放款明确失败后仍待接受的报价各一笔。
- 计划样本：一期计划（起息日起 3 个月内到期）；两期计划（起息 2026-09-15、最终还款日 2027-03-20）；起息日在月末（如 1 月 31 日）使后续月份没有同日的计划；尾段不足一季被合并进末期的计划；预计期数与定稿期数不同（多一期、少一期）的业务。
- 状态样本：计划生成中；生成失败后恢复；待还款且未到应还日；应还日当天；已逾期（1 天、5 天）；还款处理中（刚签名、已等待很久、结果长期未知）；授权明确失败、授权成功而链上还款明确失败；已结清；全部结清；末期先结清而较早一期仍未结清。
- 逾期样本：两期分别逾期，一期待还款、一期已签名提交仍在处理中，另有一期未来正常期；一期应还日当天签名、次日仍在处理中后失败。
- 项目样本：项目内另有未结清业务；项目未到期且本笔是最后一笔未结清业务；项目已到期且本笔是最后一项未处理完成的业务。
- 地址与余额样本：甲在企业账户登记的多个 Ethereum 数币账户（含一个与登录地址不同、一个信息不完整），其结算币种余额充足、不足各一；余额查询失败；本项目还款合约未配置或读取失败；同一出账地址在同组合两个项目同时有还款处理中。
- 金额样本：融资 150 万 USDT、年化融资利率 8%；某期应还合计 100.25 USDT、结算币种 USDC、汇率快照为 1；结算金额在界面上会被截断展示的样本；报价后运营修改了汇率的业务。
- 时间样本：UTC 23:50 签名提交、查看者处于 UTC+8；夏令时切换日；判定晚于应到时点完成的逾期。
- 资料异常样本：还款收款地址读取失败；本笔汇率快照或关键金额缺失。

对应功能：[本模块发送的站内信与跨入口一致性（F-LS-76）](./01-链上还款-PRD.md#f-ls-76)

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| <a id="ac-l8-rev-05"></a>AC-L8-REV-05 | 计划生成中后恢复；一次末期还款使全部期次结清；一期临近应还日；业务逾期标记被清除 | 查看双方收到的消息 | 链上放款成功时资金方只收授信报价与接受拒绝的“融资报价已接受，已放款”，本模块不另发；资产方在定稿实际完成后收一条计划定稿；末期使全部结清时双方各只收一封本笔融资业务已结清；应还临近提醒不开放还款；标记清除不发消息 |
| <a id="ac-ls-132"></a>AC-LS-132 | 同一期在详情、控制台与站内信中都可查看 | 对比三处信息；让同一事实重复到达 | 状态、金额、冻结的逾期天数与环节名称一致，都不出现确认类环节；同一事实不重复提醒；不泄露私有信息 |
| <a id="ac-ls-136"></a>AC-LS-136 | 甲有待还、已逾期待还、还款处理中，以及链上失败后回到待还款的期次 | 在我的控制台查看并阅读相关消息 | 控制台只读复用同一业务事实，不自行重算；待还、已逾期待还与还款处理中都能被发现；未到期只读；处理中的期次不再列为待资产方还款，业务逾期标记仍在；已开放未提交及失败后回到待还款的期次使该笔业务标为资产方待处理“还款”；资金方没有本模块的待处理事项；阅读消息不等于完成还款 |

## 8. 消息通知

对应规则：[消息通知](./03-链上还款-消息通知.md)

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| <a id="ac-rp-n01"></a>AC-RP-N01 | 链上放款成功；计划生成中，之后恢复 | 查看双方消息 | 生成中不发计划定稿；放款结果不回退；实际定稿后资产方收一条还款计划已定稿，资金方没有本模块的定稿消息；生成恢复不重复发定稿，计划定稿时间不改 |
| <a id="ac-rp-n02"></a>AC-RP-N02 | 预计期数与定稿期数相同、多一期、少一期的业务 | 阅读计划定稿消息 | 含预计与实际起息日、预计与定稿期数，以及每一个序号的逐期对照；相同、增加与减少的期次都说明清楚，不出现不存在的零值期次；对照在消息正文中可读，还款详情仍只有定稿计划 |
| <a id="ac-rp-n03"></a>AC-RP-N03 | 利息期与末期；一笔定稿较晚、已过提醒时点但未逾期；一期已在还款处理中；一期已逾期 | 在应还日前 3 个 UTC 自然日及之后查看 | 两类期次都在应还日前 3 个 UTC 自然日 00:00 提醒一次，只用于准备；中英文都给出真实开放时刻并提示准备出账地址余额，不说已开放；之前打开只读、不能还款；定稿较晚的补发一次；不另发开放当时的消息；处理中或已逾期的不补发临近提醒 |
| <a id="ac-rp-n04"></a>AC-RP-N04 | 一期到应还日次日仍未签名提交；一次判定延迟；一期在应还日当天签名提交、次日仍在处理中 | 查看双方消息 | 应还日次日 00:00 UTC 仍未签名提交才发逾期，双方各一条；判定延迟时按应到时点与实际已经过的天数；逾期天数增加不重发；当天已签名提交、仍在处理中的期次不发逾期 |
| <a id="ac-rp-n05"></a>AC-RP-N05 | 一期逾期 5 天后签名提交并链上还款成功；另一期未提交 | 查看消息与标记 | 不再为已提交的一期发新的逾期消息，冻结天数为 5；该期结清后业务逾期标记按相关逾期期次是否全部结清判断，清除不发消息；另一期独立计算；送达前已结清的期次不追补过时的催还 |
| <a id="ac-rp-n10"></a>AC-RP-N10 | 一期利息期链上还款成功，本笔仍有其他未结清期次；另一次链上还款失败 | 查看双方消息 | 成功后甲收一条本期还款已完成、乙收一条本期还款已到账，含期次、还款期次编号、还款金额与币种、还款成功时间，并说明无需资金方确认；利息期不说成归还了本金或释放了额度；失败不发成功类消息；仍有未结清期次时不发整笔结清 |
| <a id="ac-rp-n11"></a>AC-RP-N11 | 某期链上还款使全部期次结清 | 查看双方消息 | 双方各只收一封本笔融资业务已结清，其中含本次结清的期次、还款期次编号与还款成功时间；不再另收本期还款已完成或本期还款已到账；事实与编号不丢失 |
| <a id="ac-rp-n12"></a>AC-RP-N12 | 末期先结清而较早一期仍未结清，之后较早一期链上还款成功 | 查看消息 | 末期结清只发本期还款已完成与本期还款已到账，不发整笔结清；较早一期结清使全部结清时，以该期的还款期次编号发合并消息；未偿本金为 0 不代替全部期次结清的判断 |
| <a id="ac-rp-n22"></a>AC-RP-N22 | 授权明确失败；授权成功而链上还款明确失败；签名前校验未通过；未签名；结果长期未知；同一期两次失败；失败时已逾期与未逾期各一 | 查看双方消息 | 只有授权或链上还款明确失败时向甲发本期还款未完成，含期次、应还金额、可读原因与重新授权并还款的指引，已逾期的给出逾期天数，授权已上链的说明可在钱包中自行撤销；签名前校验未通过、未签名与长期未知不发；乙不收；同一期两次失败各一条；消息不出现地址或交易标识 |
| <a id="ac-rp-n13"></a>AC-RP-N13 | 本笔结清时项目内另有未结清业务；项目已终态但代币待提取；提取结果未知 | 阅读本笔融资业务已结清 | 有其他未结清业务时不说项目已释放；已释放待提取时不说已回到钱包；未知或失败的结果不虚构；提取相关消息不由本模块发送 |
| <a id="ac-rp-n14"></a>AC-RP-N14 | 同一机构在本项目两笔业务、同一笔多期；非当事资金方可查看非隐私履约信息 | 查看各账号的消息 | 消息不串笔、不串期；资产方消息发给本笔所属企业的账号，资金方消息发给本笔报价机构的账号；非当事资金方不因可查看履约信息而收到本模块消息；运营、SPV 与其他平台身份不收 |
| <a id="ac-rp-n15"></a>AC-RP-N15 | 重复提交、补判、刷新、生成恢复；两期同一天发生同类事件；一条旧消息与已变化的原期次；一次发送失败 | 查看消息列表与原业务 | 重复事实不新增、不置顶、不恢复未读；不同期次各自一条；只有末期结果与整笔结清合并为一条；已送达的旧消息保留当时事实，打开后看原期次的当前结果；发送失败不改变业务状态与金额 |
| <a id="ac-rp-n17"></a>AC-RP-N17 | 应还临近与逾期等到点触发的事件；链上还款成功或失败等即时事件 | 记录事件发生或应到时点与消息可见时点 | 即时事件发生后 60 秒内消息出现在列表、未读数同步；到点触发的事件从应到时点起 6 分钟内可见，其中逾期判定不超过 5 分钟 |
| <a id="ac-rp-n18"></a>AC-RP-N18 | 七类消息、九对主模板与三种对照条目 | 检查中英模板内容 | 中英变量一致；应还合计以 USDT 标示，结算与还款金额按本笔汇率快照，USDT 结算或汇率为 1 时与应还合计数值相同，展示不改变金额；UTC 日期与时区标注正确；不出现 USD、金额与币种错配、裸占位符、客服邮箱、私人邮箱、地址或交易标识；业务类型标识均为三段式且沿用既有名称 |
| <a id="ac-rp-n19"></a>AC-RP-N19 | 有效消息与状态已变化的消息；资金方的逾期消息 | 点击消息进入 | 有效消息进入原业务、原期次的合法场景；状态已变化时展示原期次结果，不静默跳到下一期；资金方从逾期消息进入没有还款写入能力；私有材料不越权可见；读信不代替办理 |
| <a id="ac-rp-n20"></a>AC-RP-N20 | 一笔业务从链上放款成功到结清的全过程 | 汇总双方收到的全部消息 | 资金方不收定稿消息；签名提交、还款处理中与签名前校验未通过不发信；没有“请确认收到还款”或催办类消息；控制台与消息中心不重复发送还款消息；没有每日催还、标记清除或运营广播；项目状态、释放与提取类消息不由本模块发送 |
