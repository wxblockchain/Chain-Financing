# 还款计划与还款确认 · 消息通知

2026-10-19｜需求评审稿

<a id="notify-entry"></a>
本册写本模块发送的站内信，规则以[功能与业务规则](./01-还款计划与还款确认-PRD.md)为准；验收见[验收](./04-还款计划与还款确认-验收.md#notice)。只有站内信，没有邮件、短信、浏览器推送或运营广播。

- 本模块自己发送 6 类：还款计划已定稿、应还临近提醒、本期还款逾期、还款记录已提交、本期还款已确认、本笔融资业务已结清。
- 资产方确认到账由放款模块的[资产方已确认放款到账（N-LN-04）](../07-借贷广场-放款与放款确认/03-放款与放款确认-消息通知.md#n-ln-04)告知资金方；本模块的计划定稿只发资产方。
- 还款确认没有时限，因此没有确认临期、确认超期或催办消息。
- 我的控制台和消息中心展示同一事实，不各自补发。
- 本期一个企业只有一个账号；发给“资产方”或“资金方”的消息即发给该企业的唯一账号。

编号说明：事件编号（N-RP-*）与模板编号（T-RP-*）被其他模块引用，沿用原值；随还款确认时限取消而删除的事件与模板（N-RP-05、N-RP-06 及其模板）不再占号，缺号不代表遗漏。

<a id="events"></a>
## 1. 本模块发送的消息

<a id="n-rp-01"></a><a id="N-RP-01"></a>
### 还款计划已定稿（N-RP-01）

- **所在功能与触发环节**：[定稿后告知新旧安排（F-LS-63）](./01-还款计划与还款确认-PRD.md#f-ls-63)；资产方确认到账后，本笔定稿计划实际生成完成、可以完整阅读时。
- **不触发**：计划仍在生成中；生成失败或结果未知；报价阶段的预计计划试算；生成恢复后再次进入或刷新。
- **收件人**：本笔资产方账号。不发给资金方、运营、SPV 机构或其他企业；资金方从放款模块的资产方已确认放款到账（N-LN-04）查看同一笔的计划进度。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、资金方名称、计划定稿时间；预计与实际起息日、预计与定稿期数；逐期完整对照（每个序号的预计与定稿应还日、USD 合计与结算金额，任一侧没有该期时明确说明）；无需再次接受报价。
- **打开后去哪**：本项目，定位到本笔的还款详情，查看定稿计划；进入时重新判断权限与状态。
- **原业务已变化时**：之后的还款、逾期与结清按该笔当前事实展示；结清后仍可查看原定稿计划，不跳到另一笔，不在详情中恢复预计计划与定稿计划的双版切换。
- **模板**：[T-RP-01](#t-rp-01)，正文后逐期附对照条目 [T-RP-C01](#t-rp-c01)／[T-RP-C02](#t-rp-c02)／[T-RP-C03](#t-rp-c03)。

<a id="n-rp-02"></a><a id="N-RP-02"></a>
### 应还临近提醒（N-RP-02）

- **所在功能与触发环节**：[应还日开放录入（F-LS-66）](./01-还款计划与还款确认-PRD.md#f-ls-66)；目标期次应还日前 3 个 UTC 自然日的 00:00，期次仍为待还款时。每期一次。
- **不触发**：录入开放当时或应还日当天不另发；期次已提交、已结清或已逾期时不发（已逾期只发逾期）；计划尚未定稿时不按预计期次提醒。
- **迟到补发**：计划定稿较晚、定稿时已过提醒时点但尚未逾期且仍待还款的，补发一次，写明准确的应还日与开放时刻，不写“还剩三天”。
- **收件人**：本笔资产方账号。不发给资金方、运营或 SPV 机构。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、资金方名称、期次与还款期次编号、应还日、USD 应还合计与结算金额；录入开放时刻（应还日 00:00 UTC）；开放前只能查看、不能录入或提交；平台只登记信息、不代为转账。不能写“已开放”或“现在可以提交”。
- **打开后去哪**：同一笔、同一期。开放前进入只读的本期安排并给出开放时刻；开放后仍为待还款的，进入本期的还款办理（P-LS-09）。
- **原业务已变化时**：已提交或已结清的，展示本期当前结果，不自动选下一期或另一笔；提醒本身到应还日次日 00:00 UTC 失效，失效不取消逾期后仍可还款的资格。
- **模板**：[T-RP-02](#t-rp-02)。

<a id="n-rp-03"></a><a id="N-RP-03"></a>
### 本期还款逾期（N-RP-03）

- **所在功能与触发环节**：[形成逾期标记（F-LS-70）](./01-还款计划与还款确认-PRD.md#f-ls-70)；应还日次日 00:00 UTC 仍未成功提交、首次形成该期逾期时。
- **不触发**：逾期天数逐日增加时不重发、不恢复未读；成功提交后不再为该期发新的逾期消息；消息尚未送达时该期已提交或已结清的，不追补过时的催还；业务逾期标记清除时不发。
- **收件人**：本笔资产方账号与本笔资金方账号（提交本笔放款记录的账号，LN-14），各一条。不发给运营或 SPV 机构。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、资金方名称、期次与还款期次编号、应还日、截至发信时点的逾期天数（迟到判定按实际已经过的天数，不固定写 1 天）、USD 应还合计与结算金额；不产生罚息。资产方的消息提示录入本期付款信息，成功提交只冻结本期逾期天数；资金方的消息只供查看，不代表平台核验了线下付款。
- **打开后去哪**：同一笔、同一期。资产方仍为待还款时进入本期还款办理；资金方进入只读的本期详情，不获得还款动作。
- **原业务已变化时**：已提交的展示提交进度，已结清的展示结果；已送达的消息保留当时事实。
- **模板**：资产方用 [T-RP-03A](#t-rp-03a)，资金方用 [T-RP-03B](#t-rp-03b)。

<a id="n-rp-04"></a><a id="N-RP-04"></a>
### 还款记录已提交（N-RP-04）

- **所在功能与触发环节**：[填写并提交本期付款信息（F-LS-67）](./01-还款计划与还款确认-PRD.md#f-ls-67)；资产方的还款记录正式提交成功、生成还款记录编号、本期进入待还款确认时。每期一次。
- **不触发**：资产方点击提交、提交进行中、提交失败或结果未知；不给提交的资产方发回执；消息等待发送时该期已确认的，不再补发“请确认”。
- **收件人**：本笔资金方账号（LN-14）。不发给资产方、运营、SPV 机构或其他机构。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、期次与还款期次编号、应还日、提交时间、USD 应还合计与结算金额；请自行核实到账后再确认收到还款；确认没有时限、时机由双方线下商定；平台不会自动确认，也不核验付款真实性；本期曾逾期的，提交后仍保留逾期未结清的提示。不出现任何确认截止、剩余时长或倒计时。
- **打开后去哪**：同一期的还款确认办理（P-LS-10），仅限本笔资金方且本期仍待还款确认；进入时重新判断权限与状态。
- **原业务已变化时**：已结清的展示本期结果，不再次打开确认；消息不因时间经过而失效，资金方任何时点都可以从现行办理入口确认。
- **模板**：[T-RP-04](#t-rp-04)。

<a id="n-rp-07"></a><a id="N-RP-07"></a>
### 本期还款已确认（N-RP-07）

- **所在功能与触发环节**：[核实到账并确认还款（F-LS-71）](./01-还款计划与还款确认-PRD.md#f-ls-71)；资金方确认收到还款成功、本期结清，但这次确认没有使本笔全部期次结清时。每期一次。
- **不触发**：确认进行中、未成功或结果未知；这次确认使全部期次结清的（改发本笔融资业务已结清，不另发本条）；不给确认的资金方发回执。
- **收件人**：本笔资产方账号。不发给资金方、运营或 SPV 机构。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、资金方名称、期次与还款期次编号、确认时间；本期已结清；本笔仍有其他未结清期次；利息期不说成归还了本金或释放了额度；不表示项目质押已释放。
- **打开后去哪**：同一笔、同一期的只读结果，给出确认时间与本笔当前进度。
- **原业务已变化时**：之后整笔结清的，展示当前结清事实；已送达的消息仍说明当时本期的结果。
- **模板**：[T-RP-07](#t-rp-07)。

<a id="n-rp-08"></a><a id="N-RP-08"></a>
### 本笔融资业务已结清（N-RP-08）

- **所在功能与触发环节**：[全部期次结清后结束业务（F-LS-74）](./01-还款计划与还款确认-PRD.md#f-ls-74)；资金方的某次确认使本笔全部期次结清、本笔进入已结清、记录业务结清时间时。
- **不触发**：全部本金已还但仍有利息期未结清；末期已结清而较早的期次仍未结清（末期确认只发本期还款已确认）；确认未成功或结果未知。是否全部结清以真实期次状态判断，不凭期次序号。
- **收件人**：本笔资产方账号与本笔资金方账号（LN-14），各一条。资产方这一条同时说明本次完成确认的期次，不再另收本期还款已确认。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、资金方名称、本次完成确认的期次与还款期次编号、确认时间、业务结清时间；本笔未偿本金与对应的项目融资余额、授信占用额已归零（不代表其他业务的占用归零）；单笔结清不直接释放项目质押，项目满足关闭或结清条件后才整池业务释放；已释放的代币须由资产方从“解除质押—提取已释放”自行提取并自付 gas，不会自动回到钱包。
- **打开后去哪**：本笔的还款详情与结清结果；正文给出项目质押与提取入口的名称与条件，实际办理走项目既有入口，不在还款确认中追加签名，也不为资金方开放资产方的提取动作。
- **原业务已变化时**：项目之后的状态与质押变化按融资需求与代币质押模块的当前事实展示。
- **模板**：资产方用 [T-RP-08A](#t-rp-08a)，资金方用 [T-RP-08B](#t-rp-08b)。

<a id="no-events"></a><a id="excluded"></a>
## 2. 不发送的场景

| 场景 | 处理 |
| --- | --- |
| 报价阶段的预计计划试算、日期重算告知、确认到账后计划生成中 | 不发本模块消息；资金方的到账确认由放款模块告知并如实说明计划进度 |
| 录入开放当时、应还日当天、每日或每周催还、逾期天数逐日变化 | 不发；应还临近提醒只用于准备，逾期每期只发一次 |
| 资金方长期未确认、按时长的周期提醒、任何确认截止或超期告知 | 不发；没有确认时限，长期未确认的后果在还款详情中性可读 |
| 提交成功给资产方、确认成功给资金方的一般回执 | 在办理中反馈结果，不发站内信；整笔结清仍按本笔融资业务已结清告知双方 |
| 业务逾期标记清除、额度统计刷新 | 不发 |
| 切换业务、查看计划、打开详情、上传文件、格式错误、失败重试、读信 | 在原场景反馈，不发信，不靠消息推动状态 |
| 项目回到可用、关闭或结清，质押释放、提取成功或失败，质押情况变化 | 归融资需求与代币质押模块；本模块不另发“释放成功”或“已回到钱包” |
| 客服邮件往来、运营或 SPV 日常查看 | 本模块没有审批、裁决或代确认职责，不生成运营消息，不抄送运营或 SPV |

## 3. 同一事实由一个模块发送

| 事实 | 谁发送 | 相邻模块怎么做 |
| --- | --- | --- |
| 资产方确认到账 | 放款模块：资产方已确认放款到账（N-LN-04），发资金方 | 本模块不为同一次确认补发；资金方从该消息查看计划进度 |
| 还款计划定稿 | 本模块：还款计划已定稿（N-RP-01），只发资产方 | 资金方不收第二份定稿提醒 |
| 应还临近、逾期、还款提交、本期确认、业务结清 | 本模块：N-RP-02、N-RP-03、N-RP-04、N-RP-07、N-RP-08 | 我的控制台、还款信息清单与消息中心只承接展示，不另发同义消息 |
| 项目状态判断、整池业务释放、提取结果 | 融资需求与代币质押模块 | 本模块只说明本笔结果与后续查看路径，不承诺项目已进入终态或代币已回到钱包 |

<a id="rules"></a>
## 4. 共同规则

- **收件归属**：资产方为本笔所属企业的账号；资金方为提交本笔放款记录的账号（LN-14）。收件账号须能由本笔可靠确定，没有可靠归属时不由当前登录者或其他人补位；账号停用、换角色或失权不自动转给他人；历史消息不随后来的办理者改投；同钱包、同邮箱或跨端身份不串信。收件资格不授予还款、确认、凭证下载或跨企业访问权限。非当事资金方可查看[非隐私履约信息](./01-还款计划与还款确认-PRD.md#non-private-performance)，但不接收本模块任何消息。
- <a id="merge"></a>**同次确认与整笔结清合并**：资金方的一次确认同时使本期结清与全部期次结清时，资产方只收一封本笔融资业务已结清，其中完整保留该期期次、还款期次编号、确认时间与业务结清时间；资金方收一封本笔融资业务已结清。合并的是消息，不是业务事实；之前已发的单期确认消息不撤销、不改写。
- **同一事件只一条**：同一账号＋同一融资业务编号或还款期次编号＋同一事件只发一条；不同期次是不同事件，不因同一机构、同一天或同一融资申请而合并。重复提交、补判、刷新或生成恢复都不新增、不置顶、不恢复未读、不改发生时间。
- **内容是发生时的事实**：保留事件发生时的机构、金额、时间与结果；打开后看当前事实。“已提交”只表示平台已登记，不代表资金已到账、已由平台核验或已在链上确认。金额来自本笔锁定的条款，不按当前汇率重算。
- **只发真实成立的结果**：提交或确认未成功、结果未知时不发成功类消息。利息期确认不说成归还了本金或释放了额度；末期减少的是本金，不把本息合计说成释放额。
- **阅读不等于办理**：读信或全部已读不是提交还款、核实到账或确认收到还款；点击消息不代替最终确认，办理仍需当前权限与条件。
- **每次点击重新判权**：重新判断身份、归属、对象、状态与文件权限；未登录先登录并保留合法目标；无权或不存在不泄露存在性；落点始终是原笔、原期，不静默改用当前默认选中的业务、同一机构最新的放款或下一期；原业务定位未就绪时保留可读消息并说明暂不可查看，不猜测地址、不静默跳首页。
- **发送失败**：不回滚已成立的业务事实，不重复扣减占用；用户仍可在页面查看本笔真实计划与进度。等待发送时重新判断消息是否仍适用；抑制过时的催还不抹除业务历史。
- **送达时效**：沿[送达时效（IF-NC-01）](../10-面客消息中心/01-面客消息中心-PRD.md#if-nc-01)。应还临近与逾期属于到点触发的事件，从应到时点起算；本模块的逾期判定在 5 分钟内完成。
- **时间展示**：业务日期按 UTC 并标注，时刻按收件人偏好时区展示并标注时区；没有偏好时按平台规则。
- **消息内不出现**：凭证、交易标识、收款地址、完整银行账户、客服邮箱、当事人私人邮箱、双方备注与补充材料；到达原业务后按原权限查阅。

## 5. 登记信息与中英模板

<a id="registration"></a>
### 5.1 登记信息

按[面客消息中心的来源接入登记要求](../10-面客消息中心/01-面客消息中心-PRD.md#rg-nc-01)登记。六类消息的平台与端都是借贷平台面客端，发送来源都是本模块，打开后去哪都是原业务；适配状态均为“待适配”，不等于已完成共享登记或真实送达。业务类型标识均为三段式“业务域.对象.动作”，动作中的下划线不算分段，沿用既有标识不改名。分类取值由消息中心最后统一核对。

| submitted_at | 还款记录提交时间（RM-06） | T-RP-04 | 不取资产方填写的还款时间或阅读时间 |
| confirmed_at | 还款确认时间（RM-18） | T-RP-07、T-RP-08A、T-RP-08B | 正式确认成功的时刻，不用消息时间代替 |
| settled_at | 业务结清时间（FD-45） | T-RP-08A、T-RP-08B | 先有本期确认，再有全部结清 |
| finalized_at | 计划定稿时间（FD-41） | T-RP-01 | 原确认到账时点，不取生成恢复的时间 |
| planned_start_date / actual_start_date | 报价时的预计起息日 / 实际起息日（FD-47） | T-RP-01 | 实际起息日为放款提交时间（LN-06）的 UTC 日期，不取发放时间（LN-05） |
| planned_count / actual_count | 预计计划期数 / 定稿计划期数 | T-RP-01 | 正整数 |
| comparison_no | 对照序号 | 全部对照条目 | 按期次序号对应预计与定稿；取值从 1 到两版中较大的期数 |
| planned_due_date / planned_usd_total / planned_settlement_amount | 预计计划中该序号期次的日期、USD 合计与结算金额 | T-RP-C01、T-RP-C02 | 取接受报价时对应的预计计划，不用定稿倒推冒充旧值 |
| actual_due_date / actual_usd_total / actual_settlement_amount | 定稿计划中该序号期次的日期、USD 合计与结算金额 | T-RP-C01、T-RP-C03 | 对应实际定稿；某一侧没有该期时用对应条目说明，不以零金额或空日期假装存在 |

- 必要变量或收件归属缺失时，不用演示值、空白消息、假编号或裸占位符补齐，按来源补齐后再发；单条缺失不影响整个消息列表可用。
- 中英模板的变量名称与数量一致；时间与金额按平台统一格式展示。
- 计划对照须完整到每一期，变化与未变化都看得清；不只写“查看详情”。按序号对照只为阅读比较，不表示两版的计息区间相同；期数增减时用对应的条目模板。对照属于同一封信的正文，不是另一封消息。
- 任何模板都不出现确认截止、剩余时长、催办措辞或客服邮箱。

## 6. 依赖

- **面客消息中心**：六类事件的分类、模板与原业务定位须完成共享登记与真实送达验证；未完成前为“待适配”，不能称已上线。送达时效沿[送达时效（IF-NC-01）](../10-面客消息中心/01-面客消息中心-PRD.md#if-nc-01)。
- **放款与放款确认**：资产方已确认放款到账（N-LN-04）的触发、收件与内容以该模块为准；本模块的资金方收件账号取放款记录的提交人（LN-14）。
- **融资需求与代币质押**：项目状态、整池释放与提取相关消息以该模块为准。
