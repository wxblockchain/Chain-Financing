## 1. 模块是什么

资产方确认放款到账后，本笔融资业务进入还款中，平台按本笔已接受的条款生成一份定稿还款计划，告诉双方每一期在哪天、向哪个账户、还多少。资产方在平台外付款后，到平台登记本期的付款信息；资金方自行核实到账后确认收到还款，本期即结清。全部期次结清后本笔业务结清，再交融资需求与代币质押模块判断项目是否进入终态、是否释放质押。平台不执行转账，不核验付款或交易的真实性。

基本原则：

- 一次只登记一期、只办理一笔业务；不提供提前结清、跨期合并、部分或超额还款。
- 登记还款不等于到账。只有资金方确认收到还款，本期才结清、本金占用才减少。
- 还款确认没有时限：不倒计时、不判超期、不自动确认；资金方何时确认由双方线下商定，结果与任何时点确认相同。
- 逾期只由资产方在应还日之后仍未提交形成；成功提交即冻结本期逾期天数，资金方迟未确认不算资产方逾期。
- 计划一经定稿不可更改；应还金额复用报价锁定的条款与折算，不重新取价。
- 单笔业务结清不等于项目结清，也不直接释放质押。

**一个完整的例子。** 资产方甲接受了资金方乙的报价（融资申请 P01-01，融资业务 FD-001，融资金额 150 万 USD，年化融资利率 8%，结算币种 USDT，项目有效期至 2027-03-20）。乙于 2026-09-15（UTC）提交放款记录，并选了本机构一个 ETH 上的数币账户作为还款收款账户；甲 2026-09-16 确认到账。同一笔随即出现在项目详情的还款信息中，显示“还款计划生成中”，随后定稿：起息日为放款提交日 2026-09-15，分两期——第 1 期 2026-12-15 只付利息，第 2 期 2027-03-20 还全部本金及该期利息。甲收到“还款计划已定稿”站内信，内含预计计划与定稿计划的逐期对照。2026-12-12 甲收到第 1 期的应还临近提醒；2026-12-15 00:00 UTC 起第 1 期开放录入。甲在平台外向乙的 ETH 地址转出该期应还的 USDT，再从项目的“还款”办理入口选中本笔、第 1 期，核对应还金额与乙的还款收款地址，填写实际付款时间与交易标识，看到“提交后不可修改撤回、不启动任何确认倒计时、平台不核验转账”的告知后确认提交。本期变为待还款确认，乙收到“还款记录已提交”站内信。乙核实到账后从站内信进入确认，确认收到还款；第 1 期结清，甲收到“本期还款已确认”站内信。2027-03-20 第 2 期同样提交并确认后，全部期次结清，本笔业务结清，项目融资余额与授信占用额各减少 150 万 USD；双方各收到一封“本笔融资业务已结清”站内信。双方关闭办理后都回到原来的项目位置。

<a id="out-of-scope"></a>
### 1.1 本期不做

- 平台代为转账、扣款、代付，或链上自动核验付款。
- 提前结清、跨期合并支付、部分或超额还款、改期改额、展期与重组。
- 罚息、逾期加息或任何因逾期增加的应还金额；自动处置质押、强制扣划或跨机构授信惩罚。
- 还款确认时限、临期提醒、超期标记、催办与自动确认。
- 还款记录的修改与撤回、确认的撤销；异议、驳回、申诉与平台裁决。
- 在本模块新增、修改或删除企业账户（归[企业账户](../03-企业账户/01-企业账户-PRD.md)）。
- 项目关闭、项目终态判定、质押释放、解押与提取（归[融资需求与代币质押](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#project-state)）。
- 运营或 SPV 机构参与还款登记、确认、裁决或代确认；本模块向运营发送的消息。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 融资业务 | 一笔已接受报价形成的业务，以融资业务编号（FD-01）识别；进入还款的每笔业务都有且只有一条放款记录（LN-01） |
| 还款中 / 已结清 | 融资业务的状态：确认到账后为还款中（S-FD-6），全部期次结清后为已结清（S-FD-8） |
| 预计计划 | 报价阶段以报价提交日作为预计放款日试算的计划，标注“预计·未生效”，不产生期次编号，不是应还安排 |
| 定稿计划 | 资产方确认到账后按实际起息日生成的唯一正式计划，定稿后不可更改 |
| 期次 | 定稿计划中的一期，以还款期次编号（RP-01）识别；状态为待还款（S-RP-1）、待还款确认（S-RP-2）、已结清（S-RP-3） |
| 应还日 | 一期应当还款的 UTC 业务日期（RP-04）；该日 00:00 UTC 起开放录入 |
| 起息日 | 放款记录提交时间（LN-06）的 UTC 日期（FD-47），计息自该日起算 |
| 还款记录 | 资产方为一期登记的付款信息，成功提交时生成还款记录编号（RM-01）；一期最多一条 |
| 逾期 | 应还日次日 00:00 UTC 仍未成功提交时形成的并行标记，不是一种状态；逾期天数（RP-11）在成功提交时冻结 |
| 业务逾期标记 | 融资业务层面的逾期并行标记（FD-44，即 S-FD-9）：只要本笔有已逾期且未结清的期次就为是 |
| 还款收款账户 | 资金方在登记放款时选定、将来接收本笔还款的本机构账户（RP-14）：USD 为法币账户（LN-15），USDT/USDC 为数币账户（LN-16） |
| 结算收款链 / 质押链 | 结算收款链是数币账户地址所在的链（ETH 或 TRON）；一笔数币业务只有一条结算收款链，放款与还款都在这条链上。质押链是代币与质押合约所在的链，与本模块无关。两者互不决定 |
| 交易标识 | 数币还款时资产方提交的链上交易编号（RM-08），平台只校验格式 |
| 固定折算 | 本期平台业务规则 1 USD = 1 USDT = 1 USDC，在报价时锁入本笔快照；不是外部市场价格 |
| 项目融资余额 / 授信占用额 | 项目维度 / 机构维度已放款确认、尚未偿还的本金；定义分别沿[融资需求与代币质押](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#inv-fin-01)与[授信报价与接受拒绝](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#glossary) |

### 3.1 角色与可见范围

| 角色 | 可以做什么 | 能看到什么 | 不能做什么 |

| 游客（未登录）、登录未绑定角色 | 无本模块动作；按[项目详情按身份的可见范围（F-LS-82）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-82)登录或申请成为资金方 | 只看到项目基本信息，看不到还款信息 | 看到本模块任何内容 |
| 运营、SPV 机构 | 无面客动作 | 本模块不增加其资料可见权 | 代付、登记还款、确认、裁决或代确认 |

- 还款计划的金额、利率与币种来自本笔报价条款，其可见范围沿[报价信息的查看权限](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#non-party)：只对本笔资产方与出资机构开放。本模块不另定一套。非当事资金方能否看到期次状态与逾期提示尚待确认，见[非当事资金方可见的履约信息（Q-L8-08）](#q-l8-08)；确认前不展示。
- 本期一个企业只有一个员工账号，由该账号代表企业执行其角色的动作。登录成功不等于成为某笔业务的当事方。
- 查看、下载与提交都在服务端判权；隐藏或禁用入口不能代替权限控制，直接访问或直接提交同样被拒绝。
- 无权或不存在的对象不暴露是否存在，不报错页、不空白、不静默跳回首页。

<a id="view-and-act"></a>
### 3.2 查看与办理

查看与办理分开，以及返回、关闭、成功与失败后的去向，沿[查看与办理分开（融资需求与代币质押 F-LS-20）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-20)。本模块补充：

- 资产方登记还款（P-LS-09）、资金方确认收到还款（P-LS-10），都从项目的“还款”业务入口或有效的站内信进入办理；不从只读详情转办。
- 登记还款与确认收到还款各有一次最终确认，在本次办理内完成，不再叠加下一层办理。报价免二次确认的规则不适用于还款。
- 只提供当前可以办理的动作；当前不能办理时用说明告知原因，例如本期尚未到应还日（并给出开放时刻）、本期已提交待资金方确认、本期已结清、本笔不属于本企业。
- 不向用户展示字段编号、条款号、字段来源或内部判据；展示实际业务编号供识别。

<a id="profile"></a>
### 3.3 业务资料与本人档案

- 个人与企业的账户档案只对本人开放；对方不能借核对本笔资料读取完整账户档案、证件、认证材料或私人联系方式。
- 本笔必需的企业名称、约定条款与付款资料自动取得：优先取本笔已确认的事实，其次取同一企业、同一用途的有效登记资料，沿[自动带入（D-LS-61）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-61)。
- 资料缺失、读取中、读取失败分别说明；读取失败可重试，不说成“尚未登记”，不要求用户手填对方资料，也不用示例值或零值补齐。
- 列表与摘要中的账号、地址和交易标识脱敏；脱敏不妨碍本笔付款当事方在办理付款时受控核对并复制所需完整值。

<a id="time-and-money"></a><a id="L8-REV-02"></a>
### 3.4 时间、金额与时效

- 应还日、最终还款日、起息日与各编号中的日期都是 UTC 业务日期，展示时标明是 UTC 业务日期；录入开放为应还日 00:00 UTC，逾期自应还日次日 00:00 UTC 起算。
- 提交时间、确认时间等时刻按用户偏好时区展示并标注时区，没有偏好按平台规则。切换时区、跨日、夏令时或切换语言都不改变任何业务日期或业务事实。
- 本模块没有任何确认截止时刻、剩余时长或超期判定；资金方迟未确认不称为逾期。
- 金额一律带币种，记账本位币为 USD。USD 金额与逐期利息保留两位小数。USDT/USDC 应还金额按固定折算 1:1 复用本笔报价锁定的折算比值，数值与该期 USD 应还合计相同；展示截断不改变应付金额。
- 界面默认英文，支持中文。同一场景术语一致：还款环节称“还款确认”，不与放款环节的“放款确认”混称；额度与质押相关名称按术语表书写，例如项目融资余额、授信占用额、有效质押额、质押情况。
- 已确认的时效目标：打开还款办理到可以选期 2 秒内；还款提交与还款确认的处理各 2 秒内；不超过 8 期的定稿计划生成 2 秒内；逾期判定在应到时点后 5 分钟内完成，并以应到时点生效。实现与验证归研发、测试。
- 还款提交、还款确认、业务结清及其额度变化都可追溯到业务、期次、操作账号与时间。

<a id="ids"></a>
### 3.5 编号对应关系

- 已成交并进入还款的单笔业务上，融资申请编号（FP-28）、融资业务编号（FD-01）与放款编号（LN-01）一一对应；报价阶段同一申请可能先后关联多笔融资业务，这一对应关系不扩大到报价历史。
- 一个项目可以先后有多笔业务、多个资金方。
- 还款期次编号（RP-01）一期一个，还款记录编号（RM-01）一次成功提交一个；两者都不能作为整笔业务的标识，也不把整笔业务称作“还款计划编号”。

## 4. 还款信息：清单、详情与办理入口

适用角色与前提：能看到本项目完整详情的身份（本企业资产方、资金方），可见内容按[角色与可见范围](#roles)。流程见[计划形成与查看（L8-F01）](./02-还款计划与还款确认-流程图与状态机.md#l8-f01)。

<a id="F-LS-77"></a><a id="f-ls-77"></a>
### 4.1 还款信息清单（F-LS-77）

- 资产方确认到账、本笔进入还款中时，即进入项目详情的还款信息清单；计划生成中也在清单中，不等计划生成成功才出现。
- 每笔融资业务（FD-01）是一条独立记录，按到账确认时间倒序；每页 5 条，不提供条数切换，保留页码，沿[查看四类记录](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#records)。
- 结清后保留原记录与只读计划。
- 没有还款业务时保留清单并说明“暂无还款信息”；读取失败与无记录分别说明。还款办理入口仍在，并说明“确认到账后可查看还款计划和办理还款”，不提供没有对象的提交动作。不得用演示记录代替。
- 融资申请编号、融资业务编号、放款编号三者任一都能定位到同一条记录；不创建新编号。
- 清单记录只能打开只读详情，不承载办理或跨业务跳转。

| --- | --- | --- |

<a id="F-LS-79"></a><a id="f-ls-79"></a>
### 4.2 选择业务与查看还款详情（F-LS-79）

**选择业务。**

- 还款办理按本项目的融资业务逐笔选择，一次只指向一笔。每个可选项及当前选中结果都同时给出最近一期待还或待确认的应还日、出资机构与放款编号；不能只凭机构名区分，同一机构的多笔必须能准确选中。只有一笔时不需要额外选择，但仍给出这三项。
- 可选业务按最近待办应还日升序：逾期的在前、未到期的在后；同一天按放款提交时间（LN-06）、融资业务编号排序，不按距离今天的天数排序。
- 选中业务后再按[定位最近应还期次（F-LS-65）](#f-ls-65)选期；待确认与下一期待还款同时存在时两者都保留，不因默认选择漏掉待确认。
- 计划生成中、没有待办、已结清的业务在清单中可查，但不作为可还款的候选。
- 切换业务时，金额、账户、期次与计划随之切换，不静默改办另一笔。

**还款详情。** 只读详情一次给全下列信息，按此顺序讲述：

1. 本笔标识与状态：融资申请编号、融资业务编号、放款编号、出资机构、业务状态与业务逾期标记。
2. 本期应还：期次、应还日、USD 应还合计与结算金额、期次状态、逾期天数；待还款确认的期次给出已提交与待资金方确认的进度。
3. 定稿还款计划：按[只读查看定稿计划（F-LS-64）](#f-ls-64)。
4. 资金方还款收款账户（RP-14），明确用途是接收本笔还款。
5. 还款记录：逐期已提交的记录与凭证、交易标识与查验链接、确认时间，按权限查看。

- 计划生成中只给出已知的业务事实、生成提示与有权查看的账户，不伪造期次、应还金额或办理入口。
- 全部结清后给出结清结果与只读计划，历史逾期仍保留。
- 本期不新增资产方的还款出账账户，也不把资产方的放款收款账户默认为还款出账账户。
- 关联编号只读展示，不提供查看申请或放款的跳转动作。
- 还款详情中可复制客服邮箱，见[线下商定与客服出口（F-LS-73）](#f-ls-73)。

### 4.3 按当前权限进入还款或确认（F-LS-75）

| 办理 | 谁能办理、何时能办理 | 不能办理时 |
| --- | --- | --- |
| 立即还款（P-LS-09） | 本项目资产方；本笔还款中、存在待还款期次，且该期已到应还日 00:00 UTC | 尚未到应还日：只读给出计划、金额、有权查看的收款资料与开放时刻，不开放录入、上传或提交 |

- 业务、期次、金额与已有账户自动带出，用户只补本次必需的资料；返回时保留已填内容，未提交就关闭时就地确认是否放弃。

## 5. 还款计划

流程见[计划形成与查看（L8-F01）](./02-还款计划与还款确认-流程图与状态机.md#l8-f01)。

<a id="F-LS-60"></a><a id="f-ls-60"></a>
### 5.1 报价阶段的预计计划（F-LS-60）

适用角色与前提：本笔报价的资产方与报价机构，查看报价详情或办理接受时。

- 资金方提交报价后，以报价提交时刻的 UTC 日期作为预计放款日试算一份预计计划，按[期次划分与计息](#schedule-rules)生成。
- 预计计划在报价详情与接受办理中按需查看，承载与可见范围沿[授信报价与接受拒绝的预计还款计划](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#respond-plan)。
- 整张计划标注“预计·未生效”，日期称“预计还款日”；不形成有效期次，不占用还款期次编号。
- 报价被拒绝、失效或所属需求终结后，预计计划只随报价历史只读，不留下有效期次。

<a id="F-LS-61"></a><a id="f-ls-61"></a>
### 5.2 接受报价时告知日期将重算（F-LS-61）

适用角色与前提：本企业资产方，办理接受时。

- “放款确认后将按实际放款日重新计算”的告知在接受前须始终可得，并记录展示时间（FD-40）；不以是否查看计划为条件，不增加勾选要求。

<a id="F-LS-62"></a><a id="f-ls-62"></a>
### 5.3 放款确认后生成定稿计划（F-LS-62）

适用角色与前提：资产方确认到账成功时，由[放款与放款确认的交接（F-LS-55）](../07-借贷广场-放款与放款确认/01-放款与放款确认-PRD.md#f-ls-55)触发。

**取值。**

- 定稿的触发取确认到账时间（FD-35）；计划定稿时间（FD-41）记为该时点。
- 起息日（FD-47）取放款记录提交时间（LN-06）的 UTC 日期；不用资金方填写的发放时间（LN-05），也不改用确认到账日。
- 本金取融资金额（QT-03），年化利率取年化融资利率（QT-06），结算币种取结算币种（QT-02），折算取报价锁定的折算比值（QT-04）。
- 最终还款日（FD-46）取报价的最终还款日（QT-16），即本项目的有效期至（FP-09），不可编辑。

**生成。**

- 定稿后期次、应还日、金额与计息规则都不可更改，之后只追加还款记录、逾期历史与结清事实。
- 生成尚未完成时显示“还款计划生成中”；不把旧计划或预计计划当作定稿，也不回退已完成的确认到账、本金或额度事实。
- 生成恢复后只产生同一套期次，计划定稿时间仍为原确认到账时点。

<a id="schedule-rules"></a>
**期次划分与计息。**

- 还款类型只有一个值：按季付息；到期还本付息（QT-15）。
- 自起息日起每 3 个自然月的同日为一个应还日，不按自然季度末；目标月份没有同日时取该月最后一日。
- 除末期外各期只付利息；末期还全部本金及末期利息。
- 最终还款日在起息日起 3 个月内时只有一期。
- 不足完整一季的尾段与前一段合并为末期，不单独形成小额尾期；末期区间可以长于 3 个月，但不超过 6 个月。
- 计息为年化单利，按实际天数 ÷ 360，起息日计息、应还日不计息。每期计息天数 = 本期止日 − 本期起日。
- 每期利息 = 本金 × 年化融资利率 × 本期计息天数 ÷ 360，单独四舍五入保留两位小数；尾差不跨期结转。
- 每期 USD 应还合计 = 本期应还本金 + 本期利息；不含罚息或手续费。
- 每期结算金额 = USD 应还合计 ÷ 折算比值。固定折算下比值为 1，例如一期应还 100.25 USD、结算币种为 USDT 时，结算金额为 100.25 USDT。不能把报价本金当作每期应还。
- 例：起息日 2026-09-15、最终还款日 2027-03-20，分两期：2026-12-15 只付利息，2027-03-20 还本付息；第 2 期合并了不足一季的尾段。
- 计划须写明计息规则摘要（RP-18），与计划一起固定。年化融资利率旁“计息规则以双方签署的融资合同为准”的提示与本节平台计息规则的关系尚待确认，见[计息口径（Q-L8-07）](#q-l8-07)。

<a id="L8-REV-03"></a>
**固定折算与金额同源。**

- 应还金额复用报价成功时锁定的折算快照，沿[固定折算与折算快照（F-LS-26）](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#quote-rate)；本模块不取行情、不维护汇率，不让用户编辑汇率、补填快照或修改金额，也不以当前规则追溯改写历史业务。
- 固定比值不是对外部兑换的保证。
- 本笔折算依据或关键金额缺失时，说明暂时无法核对本笔条款，恢复真实资料后再继续；不用固定比值、其他业务的快照或零值猜补，不回退已成立的本金。

<a id="F-LS-63"></a><a id="f-ls-63"></a>
### 5.4 定稿后告知新旧安排（F-LS-63）

适用角色与前提：本笔资产方，定稿计划实际生成完成时。

- 日期按实际放款日重算属于接受时已告知规则的执行，不需要再次确认报价；金额、币种、折算快照、年化融资利率与期次规则沿用原条款。
- 资产方收到一条“还款计划已定稿”站内信，内含预计与实际起息日、期数变化，以及逐期应还日与金额的对照，见[还款计划已定稿（N-RP-01）](./03-还款计划与还款确认-消息通知.md#n-rp-01)。
- 资金方不收定稿提醒，通过放款模块的[资产方已确认放款到账（N-LN-04）](../07-借贷广场-放款与放款确认/03-放款与放款确认-消息通知.md#n-ln-04)进入同一笔查看计划进度。
- 定稿后在同一笔的还款详情查看正式安排；不重复发送定稿提醒。

<a id="F-LS-64"></a><a id="f-ls-64"></a>
### 5.5 只读查看定稿计划（F-LS-64）

适用角色与前提：本笔双方，定稿后。

## 6. 资产方提交还款

流程见[还款提交与资金方确认（L8-F02）](./02-还款计划与还款确认-流程图与状态机.md#l8-f02)，期次状态见[还款期次状态机（L8-S01）](./02-还款计划与还款确认-流程图与状态机.md#l8-s01)。

<a id="F-LS-65"></a><a id="f-ls-65"></a>
### 6.1 定位最近应还期次（F-LS-65）

适用角色与前提：本项目资产方。

- 候选是本企业名下的待还款期次。我的控制台的全局视图可以跨业务、跨项目；项目内的还款办理只在所选业务内取候选。
- 候选依次按应还日、放款提交时间（LN-06）、融资业务编号、期次序号升序，第一条为默认期次；已逾期的在前、未到期的在后；不按距离今天的天数排序。
- 可以改选其他已开放录入的期次；尚未开放的期次可以看到，但不能提交，并说明开放日期。
- 不要求先结清另一期才能选当前期；不能越过开放规则提交未来的期次。
- 待还款确认与已结清的期次不作为待还候选。

<a id="F-LS-66"></a><a id="f-ls-66"></a><a id="L8-REV-04"></a>
### 6.2 应还日开放录入（F-LS-66）

适用角色与前提：本项目资产方，对一期待还款期次。

- 利息期与含本金的末期都自应还日 00:00 UTC 开放录入，没有例外，不提前开放。
- 应还日当天可以提交；应还日次日 00:00 UTC 仍未提交才形成逾期；逾期的期次仍可录入。
- 开放前只能查看计划、金额与有权查看的收款资料，不开放还款信息录入、凭证上传或提交；从站内信或旧入口直接进入同样如此。
- 一次只录入一期，不能多选、全选或合并；金额与币种只读，不提供“提前还本”或“全部结清”。
- 这里的“还款”只是登记资产方已经完成的付款信息，由资金方另行核实到账；平台不执行银行划款、钱包支付、扣款或签名，点击、上传或提交都不表示真实付款成功。
- 资产方填写的实际还款时间（RM-05）可以是过去，但不能晚于提交时刻；它只供对账，不能用倒填来减免逾期或提前开放录入。
- 应还日前 3 个 UTC 自然日资产方会收到一条应还临近提醒，用于准备付款；这条提醒不开放录入，见[应还临近提醒（N-RP-02）](./03-还款计划与还款确认-消息通知.md#n-rp-02)。

<a id="F-LS-67"></a><a id="f-ls-67"></a>
### 6.3 填写并提交本期付款信息（F-LS-67）

适用角色与前提：本项目资产方；目标期次为待还款且已开放录入。

- 办理中只集中本期需要的信息：期次与应还日、USD 应还合计与结算金额、资金方还款收款账户（只读）、逾期天数，以及“提交即冻结本期逾期天数”的告知；这四项不可省略。
- 完整定稿计划与本息明细在本次办理内可以取得；其他业务的期次不混在本次选期中。
- 说明平台只登记还款信息、不代为转账；提交还款记录本身不收取 gas。
- 本笔已有且可复用的资料自动带出；平台尚不知道的本次实际还款时间、交易标识与凭证由资产方填写，不能拿旧记录预填；选填的材料与备注可以留空。

| 业务信息 | 含义与类型 | 必填与默认 | 可见 / 可编辑 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| <a id="rm-01"></a>还款记录编号（RM-01） | 本条还款记录的稳定标识；文本，RM＋UTC 业务日期＋当日 6 位序号 | 提交成功时生成 | 只读 | 唯一、终身保留；提交失败不产生 |

- 凭证、交易标识、结算收款链、账户、备注、补充材料与还款时间都不公开；直接访问和下载同样受权限限制。

**提交与结果。**

- 最终确认在本次办理内完成，须告知：提交后不可修改、不可撤回；成功提交即停止本期逾期天数的累加；提交不启动任何确认倒计时，资金方何时确认由双方线下商定；平台不核验转账真实性。取消最终确认回到已填内容。
- 提交成功的结果同时成立：
  - 生成唯一还款记录编号，本期从待还款变为待还款确认（S-RP-2）；
  - 冻结本期逾期天数，确定还款性质；
  - 项目融资余额与授信占用额都不变；
  - 资金方收到一条“还款记录已提交”站内信，见[还款记录已提交（N-RP-04）](./03-还款计划与还款确认-消息通知.md#n-rp-04)。
- 成功后显示本期已提交、待资金方确认，并更新原清单与办理入口；关闭后回到来源并保留原筛选、分页与所在位置，不自动打开详情。
- 失败时分别说明原因：必填缺失、凭证不合格、还款时间晚于提交时刻、交易标识格式错误、本期尚未开放、本笔不属于本企业、本期已变化。失败不生成记录，不改变期次状态，保留已填内容与已成功上传的文件。
- 两人或两次同时提交同一期时只有一次成功；后到者看到“该期已提交还款记录”并落到当前详情，不重复冻结、不产生第二条记录。
- 结算收款链由账户带出、不可改选，因此不存在“选错链”的情况。

### 6.4 交易标识格式与自行查验（F-LS-69）

适用角色与前提：数币还款时，本项目资产方填写交易标识；本笔双方查看。

- 只按本笔结算收款链校验交易标识的格式，不判断交易是否存在、是否成功或是否到账：

| 结算收款链 | 交易标识格式 | 查验入口 |
| --- | --- | --- |
| ETH | `0x` 后接 64 位十六进制字符 | 该交易在 ETH 区块浏览器中的页面 |
| TRON | 64 位十六进制字符，不带 `0x` | 该交易在 TRON 区块浏览器中的页面 |

- 格式错误时说明本链的格式要求，不说成“交易不存在”。
- 凭证与交易标识都不表示平台已审核、交易存在或款项到账；格式正确但实际没有这笔交易时，平台也不能把它标成已核验。
- “平台未核验该交易，链接仅供自行查验”须与查验链接同时可得。
- 查验链接不可用时不提供死链接，保留有权限者复制交易标识的能力。平台外的查验结果不会自动确认收到还款。
- USDT/USDC 在各链上的代币标准按该链既有事实展示（ETH 为 ERC-20，TRON 为 TRC-20），不写死单一标准。

### 6.5 跨境手续费与到账差额（F-LS-78）

适用角色与前提：本笔双方，在还款提交与还款确认时。

- 跨境手续费由付款方承担，可能使到账金额少于应还；还款提交与还款确认时都告知这一点，不预估手续费金额。
- 本期应还仍为计划金额。资金方确认不以到账金额等于应还为前提；本模块不采集实际到账金额，也不与应还金额比较或对账。

## 7. 逾期

期次状态见[还款期次状态机（L8-S01）](./02-还款计划与还款确认-流程图与状态机.md#l8-s01)。

<a id="F-LS-70"></a><a id="f-ls-70"></a>
### 7.1 形成逾期标记（F-LS-70）

适用角色与前提：定稿计划中的每一期待还款期次。

- 应还日次日 00:00 UTC 仍未成功提交，即为该期标记逾期；不设宽限期。首个逾期自然日为 1 天，之后逐日增加。
- 判定晚于应到时点完成时，仍按应到时点计算，不减免延迟期间的天数，也不重复提醒。
- 逾期是期次与业务的并行标记，不替换待还款或还款中的状态。
- 资产方与资金方各收到一条该期的逾期站内信，见[本期还款逾期（N-RP-03）](./03-还款计划与还款确认-消息通知.md#n-rp-03)。
- 不计算或展示罚息，不增加应还金额，不自动处置质押，不影响资金方对其他企业的授信。
- 逾期与项目已到期的并行标记（FP-05）都按正常中性状态呈现，不作违约告警；质押不足不阻断还款、确认或结清。

<a id="F-LS-68"></a><a id="f-ls-68"></a><a id="L8-REV-05"></a>
### 7.2 提交后冻结逾期天数与业务逾期标记（F-LS-68）

适用角色与前提：已逾期的期次被成功提交之后；以及本笔业务层面的逾期标记。

**本期逾期天数。**

- 成功提交时冻结本期逾期天数；此后不因资金方未确认而继续增加，也不再为该期发新的逾期消息。
- 本期利息在定稿时已经确定，应还金额不随提交或确认的早晚变化。
- 结清后保留历史逾期天数。另一期尚未提交的仍独立计算逾期；提交一期不冻结整笔业务的其他期次。
- 即使资金方线下主张凭证无效，本期也没有裁决或解冻回补的路径；资金方迟未确认也不会解冻已冻结的天数。

**业务逾期标记（FD-44）。**

- 本笔存在“已逾期且尚未结清”的期次时为是，包括逾期中的待还款期次，以及逾期后已提交、天数已冻结的待还款确认期次。
- 提交不清除业务逾期标记：待确认时显示该期已提交、冻结的天数以及仍未结清，不再说成待资产方补交。
- 相关的逾期期次全部结清时，清除当前的业务逾期标记；不需要等尚未逾期的未来期次全部结清；历史逾期天数始终保留。
- 之后另一期又逾期的，按该期事实再次形成业务逾期标记，不重发旧期的消息。
- 业务逾期标记附带的最早逾期期次与最长逾期天数，只在当前未结清的逾期期次中取值（含冻结的天数）；已结清的历史另行查看，不混入当前集合。没有当前逾期期次时标记为否、摘要为空，但不把历史天数清零。

## 8. 资金方确认还款

流程见[还款提交与资金方确认（L8-F02）](./02-还款计划与还款确认-流程图与状态机.md#l8-f02)。

<a id="F-LS-71"></a><a id="f-ls-71"></a>
### 8.1 核实到账并确认还款（F-LS-71）

适用角色与前提：本笔资金方；目标期次为待还款确认（S-RP-2）。没有时限，办理时机由双方线下商定。

- 办理中给出本次判断所需的信息：应还金额与结算金额及币种、期次与应还日、收款账户要点、资产方填写的还款时间与平台记录的提交时间、凭证或交易标识与查验链接（附“平台未核验”提示）、本期计划与冻结的逾期天数、不可撤销的告知。
- 两个时间须同时可得且来源可分辨：还款时间（资产方填写，只供对账）与提交时间（平台记录，只表示记录成立与逾期天数冻结的时刻，不派生任何确认截止）。
- 记录人员、重复的商务条款等弱关联信息留在只读详情，办理中不重复提供。业务选择处保留放款编号，不能因信息精简而失去同一机构多笔的识别。
- 唯一业务动作是“确认收到还款”。最终确认在本次办理内说明：资金方已自行核实到账、平台未核验；确认后不可撤销。含本金的期次说明本次本金对应的授信占用额会减少；只有这次确认会使全部期次结清时，才同时提示“本笔融资业务将结清”，不能只凭“这是最后一期”作此承诺。
- 尚未到账时可以取消，本期保持待还款确认，资金方线下核实；不提供异议或驳回入口。

**本期进度。** 对本笔双方明确给出“资产方提交还款 → 资金方确认到账”两步在本期的完成情况、当前处理方，以及“轮到您”或“等待对方”；非当事方看不到私有进度。

| 本期事实 | 进度与下一步 |
| --- | --- |
| 待还款（S-RP-1） | 资产方尚未成功提交，当前由资产方办理，资金方等待；不虚构提交或确认时间，不出现任何确认截止 |
| 待还款确认（S-RP-2），刚提交 | 提交已完成，给出平台提交时间；资金方看到“轮到您确认”，资产方看到“等待资金方确认”；不出现确认截止、剩余时长或倒计时 |
| 待还款确认（S-RP-2），已提交很久 | 保留已提交与待资金方确认的事实，可以给出自提交起已经过的时长作为进度信息；不显示已完成、不自动结清、不判超期；确认始终可办理 |
| 已结清（S-RP-3） | 两步都已完成，给出真实确认时间（RM-18）；本期没有重复确认的动作；其他期次未结清时，整笔业务仍为还款中 |

- 进度只表达本期已经发生的事实，不用一期的进度代替其他期次或其他业务。

**确认成功的结果同时成立。**

- 本期从待还款确认变为已结清（S-RP-3），记录期次结清时间（RP-17）与还款确认时间（RM-18）；
- 累计已还本金与利息（FD-42）、未偿本金（FD-43）同步更新；
- 按本期已偿本金同时减少项目融资余额与该资金方对该资产方的授信占用额：利息期本金为 0，两者都不变；末期减少的是本金，不是本息合计；手续费不参与计量；
- 按[业务逾期标记（FD-44）](#f-ls-68)重新判断，相关逾期期次未全部结清时保留，历史不删除；
- 资产方收到站内信：普通期次为[本期还款已确认（N-RP-07）](./03-还款计划与还款确认-消息通知.md#n-rp-07)；这次确认使全部期次结清时改为[本笔融资业务已结清（N-RP-08）](./03-还款计划与还款确认-消息通知.md#n-rp-08)，不另发本期确认；
- 全部期次结清时按[全部期次结清后结束业务（F-LS-74）](#f-ls-74)结清本笔业务。

**失败与重复。**

- 上述结果整体成立或整体不成立；确认失败时本期保持待还款确认、金额不变，可以再次办理，不出现“已结清但额度未减”。
- 重复确认，或办理时对象状态已经变化的，给出当前事实，不重复减少额度，不产生第二次结清结果。
- 成功后显示本期已确认的结果，并更新原清单与办理入口；关闭后回到来源并保留原筛选、分页与所在位置，不自动打开详情或其他期次。

| --- | --- | --- | --- |

| 资金方确认利息期 | 不变 | 不变 | 不变 |

<a id="F-LS-72"></a><a id="f-ls-72"></a>
### 8.2 长期未确认的业务后果（F-LS-72）

适用角色与前提：本笔双方；期次处于待还款确认。

- 期次进入待还款确认后不产生任何截止时点、倒计时或超期标记；平台不自动确认、不自动结清，不因时间流逝释放额度、解冻资产方已冻结的逾期天数或关闭确认入口。
- 资金方一直不确认时：本期一直停在待还款确认，本笔业务不能进入已结清；本期本金尚未确认的，项目融资余额与授信占用额持续占用；项目不能据此进入终态或释放质押。
- 还款详情须让双方读到这一后果：本期已提交、待资金方确认、逾期天数已冻结、平台不会自动或代为确认。
- 无论经过多久，资金方回原入口确认的结果都与尽早确认相同。

### 8.3 线下商定与客服出口（F-LS-73）

适用角色与前提：本笔双方，期次待还款确认期间。

- 本期结清的时机由双方线下商定；平台不安排催办，不新增线上动作。资金方核实到账后在原还款确认入口执行，平台只记录结果。
- 还款确认的办理与还款详情两处提供可复制的客服邮箱，并提示邮件注明融资申请编号（FP-28）、融资业务编号（FD-01）与还款期次编号（RP-01）。客服邮箱的取值在代码中固定、随版本发布，平台不提供维护或配置入口；邮箱不进入任何站内信。
- 平台不承诺处理时效或结果；没有申诉、驳回、部分确认、平台介入中或强制确认的入口。不得引导尚未收到款项的资金方“先确认再说”。
- 客服沟通不新增状态、计时或运营待办。

## 9. 全部期次结清后结束业务（F-LS-74）

适用角色与前提：本笔全部期次都已结清时。流程见[业务结清与项目衔接（L8-F03）](./02-还款计划与还款确认-流程图与状态机.md#l8-f03)，状态见[融资业务状态机（L8-S02）](./02-还款计划与还款确认-流程图与状态机.md#l8-s02)。

**单笔业务结清。**

- 全部期次都为已结清（S-RP-3）时，本笔业务从还款中（S-FD-6）变为已结清（S-FD-8），记录业务结清时间（FD-45）。
- 结清时未偿本金为 0，本笔对应的项目融资余额与授信占用额都已归零，业务逾期标记清除；业务编号保留、不回收。
- 资产方提交不等于结清；末期单独结清而较早的期次仍未结清时，本笔也不结清；没有任何时间流逝或平台动作能代替资金方的确认。
- 本笔业务对应的融资申请对外状态一直为“已放款”，不新增“已结清”需求状态，也不拼成“已放款·逾期”。
- 双方各收到一封“本笔融资业务已结清”站内信，见[本笔融资业务已结清（N-RP-08）](./03-还款计划与还款确认-消息通知.md#n-rp-08)。

**交给项目判断。** 本模块把“本笔业务已结清”交给融资需求与代币质押模块，由它结合项目内其他业务与项目是否到期判断项目状态，规则见[项目状态与后续业务](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#project-state)。本模块不判断项目状态、不释放质押。对还款模块读者，项目侧的结果概括如下：

| 本笔结清时的项目情形 | 项目结果（由融资需求与代币质押判定） | 质押 |
| --- | --- | --- |
| 项目内仍有[未处理完成的业务](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#unfinished-business) | 项目不变 | 不释放；不按“该笔对应的代币”部分释放 |
| 项目未到期，且全部业务都已结清 | 项目回到可用，可以再次发布新一轮，也可以主动关闭 | 不释放；主动关闭后才整池释放 |
| 项目已到期，且这是最后一项未处理完成的业务 | 项目自动终结为已结清（S-FP-6） | 整池业务释放 |

- 整池业务释放后，池内已通过审核的代币变为已释放待提取；资产方从“解除质押—提取已释放”自助提取，自付 gas、可批量、没有时间限制，规则见[已释放待提取（F-LS-17）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-17)。代币不会自动回到钱包，“已释放”不等于“已提取”。
- 业务结清不依赖提取成功；提取失败不回退业务结清，也不恢复额度占用。
- 链上结果未知、事实冲突或部分结果待核实时，只提示联系平台客服，沿[异常只提示联系客服（D-LS-63）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-63)；本模块不建设异常处置、人工改判或恢复资格的流程，也不在还款确认中要求再次签名或提取。

**融资业务字段。** 以下均由系统生成、只读，本笔双方可见。

## 10. 本模块发送的站内信与跨入口一致性（F-LS-76）

- 本模块发送六类站内信：还款计划已定稿（N-RP-01，发资产方）、应还临近提醒（N-RP-02，发资产方）、本期还款逾期（N-RP-03，发双方）、还款记录已提交（N-RP-04，发资金方）、本期还款已确认（N-RP-07，发资产方）、本笔融资业务已结清（N-RP-08，发双方）。触发、收件、内容与落点见[消息通知](./03-还款计划与还款确认-消息通知.md)。

<a id="limits"></a>
## 11. 按用户决定保留的业务限制

以下是用户明确裁定后的既定结果，如实记录业务后果，供研发与测试知悉，不作为缺陷处理。

1. **平台不采集收款人名称，也不校验账户归属。** 法币与数币账户都没有收款人名称，受益人名称由双方在平台外补充；平台不能自动校验“收款账户属于资金方本机构”，账户有误的后果由双方线下承担。
2. **报价一经提交，资金方无法撤回；待放款与待放款确认都没有终止出口。** 进入本模块的都是已确认到账的业务；本模块不为上游停滞的业务提供补救或终结动作，见[放款与放款确认的业务限制](../07-借贷广场-放款与放款确认/01-放款与放款确认-PRD.md#limits)。
3. **还款确认没有时限，资金方不确认时业务会一直停留。** 资金方始终不确认时，本期一直停在待还款确认，本笔业务不能结清，项目融资余额与授信占用额两项本金占用持续，项目不能据此进入终态或释放质押；平台没有任何动作能代替这次确认。见[长期未确认的业务后果（F-LS-72）](#f-ls-72)。
