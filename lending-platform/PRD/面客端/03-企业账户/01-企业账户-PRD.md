版本：2026-10-12 第三次修订，状态待评审。任务：企业账户（WS-386）。适用：借贷平台桌面 Web 面客端，资产方与资金方双侧。

## 1. 目标与阅读入口

企业在一个地方维护本企业自己的法币账户与数币账户，业务办理时只从已登记账户中下拉选用。资产方在接受报价时选一个账户收放款，资金方在登记放款时选一个账户收还款；两侧是同一套字段、同一套维护规则。“收放款”“收还款”是具体业务对所选账户的用途，不是账户本身的类别。

本期包含：法币账户与数币账户的账户总览、新增、修改与删除；数币账户的选链、填址与地址所有权签名；账户被业务选用后的快照与后续影响；本模块需要的权限项与入口挂载要求。

相邻模块负责：入口挂载与主干权限矩阵取值（登录主干与资产方SSO接入）、资金方用户信息与认证资格（资金方登录与账户体系）、资产方收放款账户的逐笔选用与确认（授信报价与接受拒绝）、资金方还款收款账户的选用（放款与放款确认）、还款期次对账户快照的引用（还款计划与还款确认）、只读摘要（我的控制台）。

本期不包含：默认账户标记、员工与成员管理、账户变更审核、账户变更消息通知、出账（付款）账户的采集与必填、业务办理内临时新增或就地编辑账户、收款人名称及以其做归属校验、银行账户真实性与汇路可达性验证、跨企业的账户唯一性校验、运营端查看或代维护企业账户、代币与地址的链上转账能力。

阅读顺序：共同规则（第 2 章）→ 完整功能（第 3 章）→ 与相邻模块的接口口径（第 4 章）→ 依赖与待决（第 5 章）→ 既定业务限制（第 6 章）→ 同序验收（第 7 章）。配套：[流程图与状态机](./02-企业账户-流程图与状态机.md)、[消息通知](./03-企业账户-消息通知.md)。

<a id="common"></a>
## 2. 共同规则

<a id="D-EA-01"></a><a id="d-ea-01"></a>
**账户归属与单员工（D-EA-01）**：账户归属企业，不归属某个自然人。本期一个企业只有一个账号，该账号即唯一维护人与查看人；不提供成员邀请、角色分配、维护人与查看人分离或交接功能，也不显示“由谁维护”。后续若恢复多员工，须先由登录与账户体系定义企业内的责任账号，本册不自行挑选任一成员。

<a id="D-EA-02"></a><a id="d-ea-02"></a>
**本企业自己的账户，用途由业务决定（D-EA-02）**：本模块登记的是本企业自己的法币账户与数币账户，类别只有“法币账户”“数币账户”两种，不称“收款账户”，也不给账户预设任何用途标签。资产方与资金方使用同一套账户类型、字段、校验与维护动作。账户在具体业务中的用途由该业务决定——资产方在接受报价时选定一个账户收放款，资金方在登记放款时选定一个账户收还款；本模块不按用途限制可选范围，同一个账户可被多笔业务、两种用途重复选用。本期不采集、不必填任何出账（付款）账户，也不把所选账户默认当作出账账户。

<a id="D-EA-03"></a><a id="d-ea-03"></a>
**两个链概念不混用（D-EA-03）**：本模块只使用**结算收款链**——数币账户地址所在链，本期支持 ETH 与 TRON，地址格式与签名按链分别定义；该名称沿全库对照表，表示业务结算时资金到达的链，不改变数币账户“本企业自己的账户”这一性质。代币与质押合约所在的**质押链**（本期仅 ETH）属融资需求与代币质押模块，与结算收款链互不决定。两者不共用同一个“链”字段，数币地址也不取代币的当前链上持有地址或质押合约地址。

<a id="D-EA-04"></a><a id="d-ea-04"></a>
**不采集收款人名称，平台不校验账户归属（D-EA-04）**：法币与数币账户**均不设收款人名称字段**，账户以账户备注名（EA-01）、账号 / IBAN（EA-04）或数币地址（EA-22）等关键信息辨识。原“收款人名称须与本企业法定名或已登记英文名一致”的硬校验不在本模块恢复，也不得用账户备注名、企业信息或任何其他字段变相实现。平台不具备“所登记账户必须属于本企业”的自动校验能力，受益人名称由业务双方在平台外补充；后果见[既定业务限制](#limits)。唯一性只在本企业内校验，不做跨企业校验，也不据此推断归属。

<a id="D-EA-05"></a><a id="d-ea-05"></a>
**变更不需审核，保存即生效，不发通知（D-EA-05）**：新增、修改与删除都不进入任何审核队列，不产生待办，不需要运营确认，也**不发送任何消息通知**（用户 2026-10-12 裁定）；校验通过即生效，并在本企业的账户总览与业务选用列表中立即可用或消失。保存进行中须让用户知道处理尚未完成，同值不重复保存；保存失败时账户保持上一次成功状态并可重试，不留半条账户。

<a id="D-EA-06"></a><a id="d-ea-06"></a>
**已选用账户的快照（D-EA-06）**：账户被业务选定并成功提交后，业务记录保存的是当时的账户快照，随记录固定。之后在本模块修改或删除该账户，都不回改、不补正、不撤回任何已提交的业务记录；已提交记录仍按其快照只读展示。尚未提交的办理若已选中被修改或删除的账户，下次进入该办理时说明该账户已变更或已删除，并要求重新选用，不静默替换成另一个账户。

<a id="D-EA-07"></a><a id="d-ea-07"></a>
**本人可见与脱敏（D-EA-07）**：企业账户属本企业档案，只有本企业账号可查看与维护。交易对手方不能从本模块读取账户；对手方在具体业务中按该笔当事方权限读取业务记录里的账户快照，与本模块无关。运营人员与 SPV 在任何场景都不可读取本模块账户、不可代维护、不可代选用。本企业本人在本模块查看与核对自己的账户时须能看到完整信息并可复制，不得只给掩码而让本人无法核对；业务侧的普通摘要仍按各业务已定的脱敏规则展示。

<a id="D-EA-08"></a><a id="d-ea-08"></a>
**账户可用的前提（D-EA-08）**：正常登录、角色已绑定、且当前业务资格为已认证时才能维护账户。账户被停用、登录失效、上游登记地址变更导致登录终止等情况下无有效会话，不能维护；恢复正常登录后账户数据不变、不需重登记。资格由服务端权威判定，界面隐藏不能代替服务端拒绝。

<a id="D-EA-09"></a><a id="d-ea-09"></a>
**时间与语言（D-EA-09）**：登记时间、修改时间取平台既定同源 UTC 时点，按用户时区展示并标注时区；显示偏好不改变先后顺序。界面语言沿既有面客双语基线，不为本模块新增语言范围。

## 3. 完整功能

<a id="f-ea-01"></a><a id="F-EA-01"></a>
### 3.1 企业账户入口与账户总览（F-EA-01）

验收：[企业账户总览验收](#ac-overview)。

**适用角色与前提**：已认证资产方、已认证资金方，正常登录。未认证的两侧可进入并看到本模块用途说明与补齐引导，看不到也不返回任何账户数据（本企业尚无账户时同样不虚构空账户）。

**正常流程**：进入企业账户 → 按**法币账户**与**数币账户**两类分别看到本企业已登记账户 → 对某个账户查看完整信息、修改或删除 → 新增一个账户。

**关键规则**：两类账户分开呈现，不混列在同一份清单里；按用户 2026-10-12 的设计要求，法币账户与数币账户以两个 Tab 呈现，具体布局由设计决定。每个账户至少可辨识：账户备注名、类别（法币 / 数币）、法币的账号 / IBAN、开户行名称与账户币种，或数币的结算收款链与数币地址、登记时间。**不设默认账户**，不展示也不提供“设为默认”。本期不限制账户数量；每个 Tab 按登记时间倒序（最近登记的在前）一页列全，**不分页、不提供列表搜索**（用户 2026-10-12 确认按现行原型）；顺序稳定可预期，不因一次读取失败改变顺序。

<a id="incomplete"></a>**信息不完整的账户**：已登记账户若缺少现行必填项（例如必填规则调整前登记、尚未标注账户币种），在总览与详情中标注“信息不完整”并列出待补项；补齐（走[修改账户（F-EA-04）](#f-ea-04)）之前不能作为任何业务的本笔账户提交：业务的可选范围中仍列出该账户并标注信息不完整与待补项，选中后不能提交并引导到企业账户补齐，补齐后回到原办理继续。平台不自动补值、不自动删除。

**异常与边界**：本企业尚无账户时给出明确空态并直接提供新增出路，不给空白表格假装有数据。读取账户失败时说明暂时不可用并可重试，**不把读取失败表达成尚未登记**，也不因此让用户重新录入一遍。账户被停用或会话失效时按[账户可用的前提（D-EA-08）](#d-ea-08)处理。

**通知**：无。本模块不发送任何消息通知，见[消息通知](./03-企业账户-消息通知.md)。

流程参见：[账户总览与新增入口（图 1）](./02-企业账户-流程图与状态机.md#fig-1)。

<a id="f-ea-02"></a><a id="F-EA-02"></a>
### 3.2 新增法币账户（F-EA-02）

验收：[法币账户新增验收](#ac-fiat)。

**适用角色与前提**：已认证资产方或已认证资金方。

**正常流程**：新增法币账户 → 填写下表信息 → 提交 → 校验通过即登记成功，立即出现在账户总览与业务选用列表。

**关键规则**：**没有收款人名称字段**，见[不采集收款人名称（D-EA-04）](#d-ea-04)。提交不进审核，保存即生效，不发通知。本企业内不允许重复登记同一账户：账号 / IBAN 与 SWIFT / BIC 同时相同即视为同一账户并拒绝，提示已存在并可直接去查看那一条；比较时忽略空格与大小写。

### 3.3 新增数币账户（F-EA-03）

验收：[数币账户新增与地址所有权验收](#ac-crypto)。

**适用角色与前提**：已认证资产方或已认证资金方，且能用**被添加的那个地址**完成一次签名。

**正常流程**：新增数币账户 → 在同一环节选择结算收款链（ETH 或 TRON）并填写该链的数币地址与账户备注名 → 用该地址签名确认地址所有权 → 签名通过即登记成功。选链与填地址是同一环节，不拆成先后两步；**进入签名前须已选链且地址符合所选链格式，没有签名通过不算登记成功**。改选链时已填地址按新链重新校验，不清空用户输入。

**地址所有权签名的边界**：签名只证明本企业持有该地址的私钥。它**不建立登录会话、不切换登录钱包、不参与登录地址匹配、不改变已绑定角色，也不改绑登录凭据**；被添加地址可以与登录地址不同，也可以在另一条链上（例如登录地址为 ETH 而登记 TRON 地址）。签名请求前须说明本次用途是“证明这个地址归你所有”，不得表现为登录或身份切换。签名拒绝、失败、超时或中途更换了钱包地址时，本次不登记，可重试；重试不影响当前登录与已有账户。此处与主干“登录状态下不提供切换钱包入口”的关系见[本模块需要的权限项（P-EA-01）](#p-ea-01)与[依赖与待决](#dependencies)。

**只能登记本企业能签名的地址**：由签名要求直接产生的业务约束是——交易所充值地址、第三方托管地址、以及无法签名的合约地址都无法登记。这一点须在填写地址**之前**告知，不能等用户签名失败才解释。

### 3.4 修改账户（F-EA-04）

验收：[账户修改验收](#ac-edit)。

**适用角色与前提**：已认证资产方或已认证资金方，账户属本企业且未删除。

**正常流程**：在账户总览选择某账户 → 修改可编辑项 → 提交 → 校验通过即生效。

**关键规则**：法币账户全部字段可改（含账户币种标注，[EA-02](#ea-02)），校验与新增一致。数币账户**只有账户备注名可改**；结算收款链（[EA-21](#ea-21)）与数币地址（[EA-22](#ea-22)）登记后不可修改——地址所有权是对那一个地址签名的结果，改地址等于登记另一个账户，须走[新增数币账户（F-EA-03）](#f-ea-03)并重新签名，旧账户可另行删除。修改不需审核、不重新签名（备注名不涉及所有权）、保存即生效、不发通知。修改不回改任何已提交业务记录，见[已选用账户的快照（D-EA-06）](#d-ea-06)。

**异常与边界**：校验失败时保持账户原值并定位到该项；修改后与本企业另一账户构成重复（法币同账号 / IBAN 与 SWIFT）时拒绝并说明。取消或离开不改变原值。不提供“批量修改”“导入覆盖”这类本期未确认的能力。

**通知**：无，见[消息通知](./03-企业账户-消息通知.md)。

### 3.5 删除账户（F-EA-05）

验收：[账户删除与快照验收](#ac-delete)。

**适用角色与前提**：已认证资产方或已认证资金方，账户属本企业。

**正常流程**：选择账户 → 删除 → 显式确认（说明删除后不再出现在任何选用列表、已提交业务记录不受影响）→ 删除生效。

**关键规则**：删除是“不再可选用”，不是抹除历史。删除后该账户不出现在账户总览与任何业务的选用列表；已提交业务记录中的账户快照不变，双方仍可按各业务权限只读查看，见[已选用账户的快照（D-EA-06）](#d-ea-06)。删除不需审核、不发通知，也不因该账户正被进行中业务引用而被禁止——尚未提交的办理按 D-EA-06 要求重新选用。

**异常与边界**：删除最后一个可用账户是允许的，但须在确认时告知“删除后暂无可选的法币账户／该链暂无可选数币账户，相关业务办理将无法提交，需要时可重新登记”；“可用”指信息完整、可被业务选用的账户。删除失败保持原状可重试。删除不可撤销，不提供回收站；需要恢复时重新登记（数币须重新签名）。

**通知**：无，见[消息通知](./03-企业账户-消息通知.md)。

<a id="f-ea-07"></a><a id="F-EA-07"></a>
### 3.7 业务办理侧的选用与回流（F-EA-07）

验收：[选用与回流验收](#ac-select)。

**适用角色与前提**：在具体业务办理中需要指定账户的当事方；本模块只定义被选用侧须满足什么，选用动作本身归相应业务模块。

**关键规则**：

1. **办理内只选不建**。业务办理过程中不提供新增、就地编辑或删除账户的入口，也不允许手输账户信息替代已登记账户。需要新账户时前往企业账户维护，再回到本笔选用。
2. **按结算币种与链匹配可选范围**。[信息不完整的账户](#incomplete)在可选范围中标注待补项，不能作为本笔账户提交。USD 业务只能选法币账户；USDT / USDC 业务只能选数币账户，并带出该账户的结算收款链（[EA-21](#ea-21)）与数币地址（[EA-22](#ea-22)），在本笔只读，办理中不切链、不改址、不换钱包。
3. **不设默认账户，账户币种不参与匹配**。法币账户的账户币种（[EA-02](#ea-02)）只作标注，业务选用不按它过滤或拦截，只展示供本人核对。本模块不提供默认标记；是否预先带出某个账户、按什么顺序带出，完全由业务模块按其已定规则决定（例如接受报价时先带出本笔已确认的选择，其次本企业最近一次成功接受中同币种的账户）。任何带出都不等于已选定，仍须按业务规则逐笔显式确认。
4. **无可用账户时不给空白表单**。直接说明本企业尚未登记可用账户并指向企业账户，登记完成后回到原办理的原位置继续，已填内容不丢失。
5. **读取失败不等于未登记**。读取本企业账户失败时说明暂时不可用并可重试，不把它表达成尚未登记而要求用户重填，也不因此放行缺账户的提交。
6. **提交即快照**。成功提交后账户信息随业务记录固定，见[已选用账户的快照（D-EA-06）](#d-ea-06)。

**异常与边界**：所选账户在提交瞬间已被删除或修改时，本次提交不成立，说明账户已变更并要求重新选用，不拿旧值提交；同一账户被多笔业务同时选用是允许的，不互相锁定。

<a id="limits"></a>
## 6. 既定业务限制（供研发与测试知悉）

以下四项是用户明确裁定后的既定结果，此处如实记录其业务后果，不作为异议保留。

1. **平台不再采集与校验收款人名称。** 法币与数币账户均取消收款人名称，原“账户必须属于本企业”的硬校验一并删除。后果：受益人名称需由业务双方在平台外补充；平台不具备该项自动校验能力，本模块也不得以账户备注名或其他字段变相恢复。账户填错或选错的后果由双方线下承担。
2. **只能登记本企业能签名的地址。** 地址所有权签名带来的必然限制是：交易所充值地址、第三方托管地址、无法签名的合约地址都无法作为数币账户登记。后果：使用托管钱包的企业无法在本平台登记该地址，须改用自持地址；该限制须在填写地址前告知，不能等签名失败才解释。
3. **本期一个企业只有一个员工。** 不提供员工管理、权限分配与交接。后果：该账号一旦不可用，本企业没有第二个人能维护企业账户；这不是缺陷，测试按此预期设计用例。恢复多员工须先由登录与账户体系定义企业内的责任账号。
4. **账户变更不发送消息通知。** 账户的新增、修改与删除都没有站内信或其他提醒。后果：账户被改动或删除后，除操作者本人在操作当时看到的结果外，平台不另行告知；测试按零通知验收，不把“没有账户变更通知”判为缺陷。

| 任何位置查看数币账户与质押链的关系 | 不出现与质押链混用同一个链字段；数币地址不取代币当前持有地址或质押合约地址 | <a id="ac-ea-19"></a><a id="AC-EA-19"></a>[AC-EA-19 结算收款链与质押链不混用](#d-ea-03) |
