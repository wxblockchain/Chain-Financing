# 企业账户 · 功能与业务规则

2026-10-15｜面客端：资产方、资金方｜需求评审稿

本模块共三册：本册写功能、业务规则、字段规则与交互逻辑；[流程图与状态机](./02-企业账户-流程图与状态机.md)画出主要流程与状态；[验收](./04-企业账户-验收.md)供测试使用。本模块不发送任何消息，所以没有 03 消息通知册，并非缺失。

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态与交互承载由 Hallmark 设计决定。业务名称以[字段命名与术语对照表](../../00-字段命名与术语对照表.md)为基线。

## 1. 模块是什么

企业在一个地方登记并维护本企业自己的法币账户和数币账户；资产方在接受报价时、资金方在登记放款时，只从这里已登记的账户中下拉选用。资产方与资金方用同一套字段和同一套维护规则。

基本原则：

- 登记的是本企业自己的账户，类别只有“法币账户”和“数币账户”两种，不叫“收款账户”。账户拿来收放款还是收还款，由使用它的业务决定。
- 账户只在本模块新增、修改和删除；业务办理中只能选用，不能新建、编辑或手输。
- 平台不采集收款人名称，也不核对账户是否真的属于本企业。
- 数币账户必须用被登记的那个地址签名一次，签名通过才算登记成功。
- 账户变更不审核、不发消息，保存即生效；已提交的业务记录保留提交当时的账户信息，之后的修改和删除不影响它。

**一个完整的例子。** 资金方 A 已通过机构认证。A 从账号菜单进入“机构账户”（资金方侧的展示名），数币账户一栏为空，于是新增数币账户：在同一步里选择结算收款链 TRON，填入以 T 开头的地址，备注名填“TRON 还款钱包”；随后用这个地址在钱包里签名，签名通过，账户登记成功，排在数币账户列表最前。几天后 A 在一笔放款登记中选择还款收款地址，下拉列表里出现“TRON 还款钱包”，选中后本笔只读带出 TRON 和该地址；A 提交放款登记。之后 A 在企业账户中删除了这个账户：它不再出现在任何选用列表里，但那笔放款记录仍显示提交时的地址。

### 1.1 本期不做

- 默认账户：没有“设为默认”，也没有默认标记。
- 员工与成员管理：一个企业只有一个账号。
- 账户变更审核与账户变更消息通知。
- 出账（付款）账户的采集与必填。
- 业务办理中临时新增、就地编辑或手输账户。
- 收款人名称，以及据此核对账户归属。
- 法币账户的中转行信息、账户持有人信息（地址）和开户行国家 / 地区。
- 银行账户真实性、汇路可达性和币种支持情况的核验。
- 账号 / IBAN 按地区的格式校验。
- 跨企业的账户唯一性校验。
- 运营端查看、代维护或代选用企业账户。
- 代币或地址的链上转账。
- 账户列表分页与列表搜索。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 企业账户 | 本模块名称，也是资产方侧的入口展示名。资金方侧的入口展示名是“机构账户”，两者是同一个模块、同一套字段 |
| 法币账户 | 本企业自己的银行账户，用于 USD 结算的业务 |
| 数币账户 | 本企业自己控制的钱包地址，用于 USDT、USDC 结算的业务 |
| 结算收款链 | 数币账户地址所在的链，本期为 ETH 或 TRON。它与代币和质押合约所在的“质押链”（本期仅 ETH）是两回事，互不决定 |
| 地址所有权签名 | 登记数币账户时，用被登记的那个地址做一次签名，证明本企业持有该地址的私钥。它不是登录 |
| 账户币种 | 法币账户上本企业自己标注的“这个账户支持哪些币种”，只作参考标注，平台不核验，也不据此筛选账户 |
| 账户类型 | 法币账户上本企业选择的“一般账户”或“监管账户”，只作标注，平台不核验 |
| 账户名称 | 法币账户的账户名称，由平台按本企业当前名称自动带出，本人不能修改。它与账户备注名不同：备注名是本企业自己起的便于辨识的名字 |
| 账户快照 | 业务提交时保存下来的所选账户信息。之后账户被修改或删除，快照都不变 |
| 信息不完整的账户 | 已登记、但缺少当前某项必填信息的账户（例如必填规则调整前登记、尚未标注账户币种）。补齐前不能在业务中提交 |

<a id="common"></a>
## 3. 共同规则

<a id="single-staff"></a>
### 3.1 账户归属与单员工

- 账户归属企业，不归属某个自然人。
- 本期一个企业只有一个账号，这个账号就是唯一的维护人和查看人。
- 不提供成员邀请、角色分配、维护人与查看人分离或交接，也不显示“由谁维护”。
- 这个账号不可用时，本企业没有第二个人能维护账户。这是本期的既定结果，不是缺陷。

<a id="permissions"></a><a id="P-EA-01"></a><a id="p-ea-01"></a>
### 3.2 谁能使用（P-EA-01）

入口在面客端账号菜单的第三项：资产方侧显示“企业账户”，资金方侧显示“机构账户”。各身份能否看到入口、进入后能做什么由本模块按下表定义；查看账户总览与新增、修改、删除同属一项权限，不另设查看权限。

| 身份 | 能看到入口吗 | 进入后能做什么 |
| --- | --- | --- |
| 游客 | 看不到 | 直接访问被拒绝，不返回任何账户数据 |
| 已登录但未绑定角色 | 看不到 | 直接访问被拒绝，不返回任何账户数据 |
| 未认证资产方 | 看得到 | 看到本模块用途和补齐资格的引导；看不到账户数据，不能新增、修改或删除 |
| 已认证资产方 | 看得到 | 查看本企业账户，新增、修改、删除 |
| 审核中或已驳回的资金方 | 看得到 | 看到本模块用途和“需先完成机构认证”的引导；看不到账户数据，不能新增、修改或删除 |
| 已认证资金方 | 看得到 | 查看本企业账户，新增、修改、删除 |
| 正常运营人员（含按运营角色工作的 SPV） | 运营端没有该入口 | 任何场景都不能查看、维护或代选用企业账户 |

- 补齐资格的引导沿用[登录主干的受限后的下一步](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#guidance)，不整页封锁。
- 所有拒绝都由服务端判定；界面隐藏入口不能代替服务端拒绝。
- 账户被停用、登录失效或因上游登记地址变更被终止登录时，没有有效会话，不能维护；恢复正常登录后账户数据不变，不需要重新登记。

<a id="P-EA-02"></a><a id="p-ea-02"></a>
**运营端不新增权限项（P-EA-02）。** 本模块不向运营端新增任何功能权限项，运营端也不因本模块引入钱包、签名或链上动作。这与 SPV 不代付、不代收、不代登记、不代确认的职责边界一致。

<a id="instant-change"></a>
### 3.3 变更即时生效，不审核、不发消息

- 新增、修改、删除都不进入审核，不产生待办，不需要运营确认，也不发送任何消息。
- 校验通过即生效：账户立即出现在（或立即消失于）本企业的账户总览和各业务的选用列表。
- 保存进行中，用户能知道处理尚未完成；同一内容不重复保存。
- 保存失败时，账户保持上一次成功保存的状态，可以重试，不会留下半条账户。
- 取消或离开时不保留未提交的内容，本模块没有草稿。

<a id="snapshot"></a>
### 3.4 已提交业务的账户快照

- 业务选定账户并成功提交后，业务记录保存的是当时的账户快照。
- 之后在本模块修改或删除该账户，不回改、不补正、不撤回任何已提交的业务记录；已提交记录继续按快照只读展示。
- 尚未提交的办理中已选中的账户被修改或删除时，下次进入该办理会说明“该账户已变更”或“该账户已删除”，并要求重新选用；不会静默换成另一个账户。

<a id="no-payee-name"></a>
### 3.5 不采集收款人名称，不核对账户归属

- 法币账户和数币账户都没有“收款人名称”字段。账户靠账户备注名、账号 / IBAN 或数币地址辨识。
- 法币账户有账户名称，由平台按本企业当前名称自动带出、不能修改；它随账户快照进入业务记录，供交易双方核对。
- 平台不核对“这个账户是否属于本企业”：不核对开户行登记的户名是否与账户名称一致，也不得用账户名称、账户备注名、企业信息或其他字段变相做这种核对。
- 受益人名称由业务双方在平台外自行补充；账户填错或选错的后果由双方线下承担。
- 唯一性只在本企业内判断，不跨企业比较，也不据此推断归属。

<a id="privacy"></a>
### 3.6 谁能看到账户信息

- 只有本企业账号能在本模块查看和维护本企业的账户。
- 本企业本人在本模块查看自己的账户时，看到完整信息并可复制；不能只给掩码导致本人无法核对。
- 交易对手方不能从本模块读取账户；对手方只能在具体业务中、按该笔当事方权限，读取业务记录里的账户快照。
- 业务侧的普通摘要按各业务已定的脱敏规则展示。

<a id="text-limits"></a>
### 3.7 文本长度与字符

以下取值为暂定，调整时只改本条。

- 账户备注名、账号 / IBAN、开户行名称：最多 100 个字符。账号 / IBAN 按去掉空格后的字符数计算。超过时在该项说明上限，不能保存。
- 地址类字段（开户行地址）：不限长度，也不限字符种类。
- 数币地址按所选结算收款链的格式校验，不适用本条长度上限。

<a id="chains"></a>
### 3.8 两个“链”不混用

- 本模块只使用结算收款链：数币账户地址所在的链，本期支持 ETH 与 TRON，地址格式和签名都按链分别处理。
- 质押链是代币与质押合约所在的链（本期仅 ETH），属于融资需求与代币质押模块，与结算收款链互不决定。
- 两者不共用同一个“链”字段；数币地址不取代币当前的链上持有地址，也不取质押合约地址。

<a id="time"></a>
### 3.9 时间

- 登记时间、最近修改时间取平台统一的 UTC 时点，按用户时区展示并标注时区。
- 显示偏好不改变时间的先后顺序。

<a id="f-ea-01"></a><a id="F-EA-01"></a>
## 4. 账户总览（F-EA-01）

适用角色与前提：已认证资产方或已认证资金方，正常登录。其他身份按[谁能使用（P-EA-01）](#p-ea-01)处理。

- 法币账户和数币账户分开呈现，不混在同一份清单里；按用户指定，两类以两个 Tab 呈现，其余布局由设计决定。
- 每个 Tab 按登记时间倒序（最近登记的在前），一页列全，不分页，也不提供列表搜索；本期不限制账户数量。
- 顺序稳定，不因一次读取失败而改变。
- 本企业还没有任何账户时，给出明确的空状态并直接提供新增入口，不显示空表格或假数据。
- 读取账户失败时，说明暂时不可用并可重试；不能把读取失败说成“尚未登记”，也不要求用户重新录入。
- 从总览可以查看某个账户的完整信息，修改、删除它，或新增账户。

每个账户在总览中至少能辨识以下信息：

| 账户类别 | 总览中至少展示 |
| --- | --- |
| 法币账户 | 账户备注名、账户类型、账户名称、账户币种、开户行名称、账号 / IBAN、登记时间 |
| 数币账户 | 账户备注名、结算收款链、数币地址、登记时间 |

两类账户共有的记录信息：

| 业务信息 | 含义 | 何时有值 | 可见 / 可编辑 | 规则 |
| --- | --- | --- | --- | --- |
| 登记时间 | 该账户登记成功的时点 | 登记成功即有 | 本企业本人只读 | 按[时间](#time)规则展示 |
| <a id="ea-26"></a><a id="EA-26"></a>最近修改时间（EA-26） | 该账户最近一次修改成功的时点 | 修改成功过才有 | 本企业本人只读 | 从未修改过的账户不展示本项 |

<a id="incomplete"></a>
### 4.1 信息不完整的账户

- 已登记账户缺少当前某项必填信息时（例如在账户类型成为必填项之前登记的法币账户），在总览和详情中标注“信息不完整”，并列出缺哪几项。
- 平台不自动补值，也不自动删除这样的账户。
- 补齐方式是[修改账户（F-EA-04）](#f-ea-04)；补齐后立即恢复正常。

信息是否完整、所处位置不同时，用户看到的结果：

| 账户状态 | 在企业账户总览中 | 在业务的可选范围中 | 选中后能否提交本笔 |
| --- | --- | --- | --- |
| 信息完整 | 正常展示 | 正常列出 | 能提交 |
| 信息不完整 | 标注“信息不完整”并列出待补项 | 仍然列出，同样标注信息不完整和待补项 | 不能提交；引导到企业账户补齐，补齐后回到原办理继续 |
| 已删除 | 不再出现 | 不再出现 | 不适用；尚未提交的办理中若已选中它，按[已提交业务的账户快照](#snapshot)要求重新选用 |

流程参见：[账户总览与新增入口（图 1）](./02-企业账户-流程图与状态机.md#fig-1)。

<a id="f-ea-02"></a><a id="F-EA-02"></a>
## 5. 新增法币账户（F-EA-02）

适用角色与前提：已认证资产方或已认证资金方。

- 填写下表信息后提交，校验通过即登记成功，立即出现在账户总览和业务选用列表，按[变更即时生效](#instant-change)处理。
- 没有收款人名称字段，也没有中转行信息、账户持有人信息和开户行国家 / 地区。
- 新增时取不到本企业当前名称的，不能新增法币账户：说明暂时无法取得企业名称、可稍后重试，不提供手填账户名称的方式。数币账户不受影响。
- 本企业内不允许重复登记：账号 / IBAN 与 SWIFT / BIC 都相同即视为同一账户，拒绝保存，并提示已存在、可直接去查看那一条。比较时忽略空格和大小写。
- 账号 / IBAN 与 SWIFT / BIC 保存时去掉空格并统一为大写。本人查看时 IBAN 可每 4 位分组展示，复制得到不带空格的值。这种整理不改变账户含义，也不构成额外拦截。
- 必填缺失、未选账户类型、未选任何账户币种、SWIFT / BIC 格式错误、超出长度上限、本企业内重复，分别在对应项说明具体原因，不笼统报“保存失败”。
- 平台不验证银行账户真实性、汇路可达性、账户类型或银行是否支持所标注的币种；任何位置都不出现“账户已验证”一类结论。

| 业务信息 | 含义与类型 | 必填与默认 | 可见 / 可编辑 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| <a id="ea-10"></a><a id="EA-10"></a>账户类型（EA-10） | 该法币账户的类型；单选：一般账户、监管账户 | 必选；无默认值，不预选 | 本企业本人可见可编辑 | 不选不能保存。只作标注：平台不核验账户类型，业务选用时不按它筛选或拦截，只展示出来供本人核对。 |
| <a id="ea-11"></a><a id="EA-11"></a>账户名称（EA-11） | 该法币账户的账户名称；文本 | 必有；由平台按本企业当前名称自动带出：资产方取资产可信平台同步的当前企业名称，资金方取审核通过的当前机构名称 | 本企业本人只读，不能修改 | 新增时取不到企业名称则不能新增法币账户。企业名称变更后，本企业所有法币账户的账户名称随之更新为新名称；已提交业务记录中的账户快照保留提交时的名称。之后取不到企业名称时，保留最近一次取得的名称。不参与重复判断；平台不核对开户行登记的户名是否与之一致 |
| <a id="ea-01"></a><a id="EA-01"></a>账户备注名（EA-01） | 本企业自定的、便于辨识的名称；文本 | 必填，无默认值 | 本企业本人可见可编辑 | 不能为空；最多 100 个字符；本企业内可以重名，但重名时提示可能混淆，不阻止保存。它不是收款人名称，平台不据此核对归属 |
| <a id="ea-02"></a><a id="EA-02"></a>账户币种（EA-02） | 本企业标注的、该账户支持的法币币种；多选。可选项本期为 USD、EUR、GBP 三个 | 必选，至少选一个；无默认值，不预选 | 本企业本人可见可编辑 | 一个都不选时不能保存。只作标注：平台不核验，业务选用时不按它筛选、排序或拦截，只展示出来供本人核对。可选项调整时，已登记账户原有的标注保持不变 |
| <a id="ea-04"></a><a id="EA-04"></a>账号 / IBAN（EA-04） | 银行账号或 IBAN；文本 | 必填 | 本企业本人可见可编辑 | 去掉空格后最多 100 个字符；不按地区校验格式，任何地区格式只要非空且不超长都可保存 |

<a id="f-ea-03"></a><a id="F-EA-03"></a>
## 6. 新增数币账户（F-EA-03）

适用角色与前提：已认证资产方或已认证资金方，并且能用要登记的那个地址完成一次签名。

- 流程分两步：第一步在同一环节选择结算收款链、填写数币地址和账户备注名；第二步用该地址签名，签名通过即登记成功。
- 填写地址之前就要告知：只能登记本企业能签名的地址，交易所充值地址、第三方托管地址和无法签名的合约地址都无法登记。不能等签名失败才解释。
- 结算收款链没有选择、或地址不符合所选链的格式时，不能进入签名。
- 改选链时，已填的地址保留，并按新选的链重新校验。
- 签名前说明本次签名的用途：证明这个地址归本企业所有，不发起交易，不改变登录方式，也不更换登录钱包。
- 只有签名通过才产生账户；签名前的填写内容不算账户，不出现在总览，不参与查重，也不能被业务选用。
- 没有“稍后验证”“跳过验证”或由运营代确认的方式。
- 签名被拒、签名失败或超时、签名用的地址与要登记的地址不一致、钱包环境不可用或不支持该链，分别说明原因和下一步；签名地址不一致时明确说“签名的地址和要登记的地址不是同一个”。
- 以上任何失败都不登记账户，不改变当前登录，可以重试。
- 平台不判断地址在链上有无余额，也不给出“地址已验证可收款”这类超出所有权证明的结论。

<a id="ownership-signature"></a>
**地址所有权签名不是登录。** 这次签名只证明本企业持有该地址的私钥：不建立登录会话，不切换登录钱包，不参与登录地址匹配，不改变已绑定的角色，也不改绑登录凭据。被登记的地址可以与当前登录地址不同，也可以在另一条链上（例如用 ETH 地址登录，登记一个 TRON 地址）。

| 业务信息 | 含义与类型 | 必填与默认 | 可见 / 可编辑 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| <a id="ea-20"></a><a id="EA-20"></a>账户备注名（EA-20） | 本企业自定的、便于辨识的名称；文本 | 必填，无默认值 | 本企业本人可见可编辑 | 不能为空；最多 100 个字符；本企业内可以重名，但重名时提示可能混淆，不阻止保存。它不是收款人名称 |
| <a id="ea-21"></a><a id="EA-21"></a>结算收款链（EA-21） | 数币地址所在的链；可选 ETH 或 TRON | 必选，无默认值，不预选；与数币地址在同一环节填写 | 本企业本人可见；登记后不可修改 | 不选择时不能进入签名；本期只有这两个选项 |
| <a id="ea-22"></a><a id="EA-22"></a>数币地址（EA-22） | 本企业在所选链上的地址；文本 | 必填 | 本企业本人可见完整值并可复制；登记后不可修改 | ETH 地址为 0x 开头加 40 位十六进制字符；TRON 地址为 T 开头、共 34 位的 Base58 字符。格式错误时只说明所选链的格式要求。本企业内同一条链上的同一地址不能重复登记：ETH 地址比较时不区分大小写，TRON 地址按原样比较、大小写不同即为不同地址 |
| <a id="ea-23"></a><a id="EA-23"></a>地址所有权确认（EA-23） | 本次登记是否已由该地址签名通过；取值只有“已确认” | 登记成功的账户必有 | 本企业本人只读 | 签名未通过不产生账户 |
| 适用代币 | 该地址在业务中可用于的数币：USDT 和 USDC | 登记成功的账户必有；本期两者皆可 | 本企业本人只读 | 按链登记，不按代币分别登记地址；业务选用时按结算收款链匹配，不按代币区分 |

## 7. 修改账户（F-EA-04）

适用角色与前提：已认证资产方或已认证资金方；账户属于本企业且未被删除。

- 法币账户除账户名称外的字段都可以修改（包括账户类型和账户币种），校验与新增法币账户相同；账户名称由平台按本企业当前名称维护，修改账户时不可编辑。
- 数币账户只能修改账户备注名，不需要重新签名。结算收款链和数币地址登记后不能修改：要换地址，就新增一个数币账户并重新签名，旧账户可另行删除。界面需说明这一点。
- 修改后与本企业另一个法币账户的账号 / IBAN 和 SWIFT / BIC 都相同时，拒绝保存并说明。
- 校验失败时保留账户原值，并指出是哪一项。取消或离开不改变原值。
- 修改按[变更即时生效](#instant-change)处理，不回改任何已提交的业务记录，见[已提交业务的账户快照](#snapshot)。
- 不提供批量修改或导入覆盖。

## 8. 删除账户（F-EA-05）

适用角色与前提：已认证资产方或已认证资金方；账户属于本企业。

- 删除前必须显式确认。确认时说明：删除后该账户不再出现在任何选用列表中；已提交的业务记录不受影响。
- 删除的是最后一个可用账户时（信息不完整的账户不算可用），确认时额外说明：删除后暂无可选的法币账户，或该链暂无可选的数币账户，相关业务办理将无法提交，需要时可重新登记。
- 删除后，该账户从账户总览和所有业务的选用列表中消失；已提交业务记录中的账户快照不变，双方仍可按各业务的权限只读查看。
- 账户正被尚未提交的办理选中时，也允许删除；该办理按[已提交业务的账户快照](#snapshot)要求重新选用。
- 删除不可撤销，没有回收站。需要时重新登记；数币账户需重新签名。
- 删除失败时账户保持原状，可以重试。
- 删除按[变更即时生效](#instant-change)处理，不审核、不发消息。

流程参见：[删除账户与已提交记录的关系（图 4）](./02-企业账户-流程图与状态机.md#fig-4)、[企业账户生命周期状态机](./02-企业账户-流程图与状态机.md#state-2)。

<a id="f-ea-07"></a><a id="F-EA-07"></a>
## 9. 业务办理中选用账户（F-EA-07）

适用角色与前提：在具体业务办理中需要指定账户的当事方。本节只规定被选用的账户须满足什么；选用这个动作本身，以及何时带出哪个账户，归各业务模块。

- 办理中只能选用已登记的账户，没有新增、就地编辑或删除账户的入口，也不能手输账户信息代替。
- USD 结算的业务只能选法币账户；可选范围不按账户币种或账户类型筛选，选用时展示账户名称、账户类型和账户币种供本人核对。
- USDT 或 USDC 结算的业务只能选数币账户；选中后带出该账户的结算收款链和数币地址，本笔只读，办理中不能换链、改地址或换钱包。
- 信息不完整的账户在可选范围中列出并标注待补项，但不能作为本笔账户提交，见[信息不完整的账户](#incomplete)。
- 本模块不设默认账户。是否预先带出某个账户、按什么顺序带出，完全由业务模块按其已定规则决定；任何带出都不等于已选定，仍需逐笔显式确认。
- 本企业没有可用账户时，不给空白表单：直接说明尚未登记，并引导到企业账户；登记完成后回到原办理的原位置继续，已填内容不丢失。
- 读取本企业账户失败时，说明暂时不可用并可重试；不能说成“尚未登记”，不要求手输，也不放行缺少账户的提交。
- 提交时再校验一次：所选账户已被删除或修改时，本次提交不成立，说明账户已变更并要求重新选用，不拿旧值提交。
- 同一个账户可被多笔业务同时选用，互不锁定。
- 提交成功后，账户信息随业务记录固定为快照，见[已提交业务的账户快照](#snapshot)。

流程参见：[业务办理中选用与回流（图 5）](./02-企业账户-流程图与状态机.md#fig-5)。

## 11. 待确认事项与依赖

当前没有待确认事项。

依赖：本模块支持 ETH 与 TRON 两条链，并按链校验地址格式。两条链的钱包适配、签名、地址格式校验以及区块浏览器查验入口的实现由研发确定，验证由测试负责。产品侧要求是：签名用途明确，按链分别校验，失败原因可以分辨，不改变当前登录。
