# 企业账户 · 消息通知

版本：2026-10-12 修订。需求：企业账户（WS-386）。配套[主 PRD](./01-企业账户-PRD.md)与[流程图与状态机](./02-企业账户-流程图与状态机.md)。本册只定义本模块的通知范围与边界；面客与运营消息中心负责框架、投递与目标页面。

本册只定义信息需求与业务行为；通知的承载形式与视觉由 Hallmark 设计决定。

<a id="scope"></a>
## 1. 本模块通知范围

**本模块不发送任何消息通知，没有发送事件，也没有消息模板。** 用户 2026-10-12 裁定：账户变更不需要发送消息通知。账户的新增、修改与删除都是本企业本人对自己账户的即时维护，结果在本次操作内直接可见；变更不需审核，没有第二方需要处理。因此本册不定义事件、不定义模板、不登记收件范围，也不为“可选通知开关”编造事件。

| 动作 | 通知处理 |
| --- | --- |
| 新增法币账户、新增数币账户 | 不发送。结果在本次操作内即时可见；不产生运营待办，不发欢迎或登记回执 |
| 修改账户、删除账户 | 不发送（用户已裁定）。本人在本次操作内看到结果，平台不另行告知 |
| 地址所有权签名通过或失败 | 不发送。签名是本次登记流程内的即时结果，不是需要事后告知的业务事实 |
| 读取账户失败、保存失败、校验失败 | 不发送。属本次操作的即时反馈，不入消息池 |
| 账户被某笔业务选用、被选用后该账户被改动 | 不由本模块发送。业务进展的通知归发起该业务的模块；本模块不因自己的数据被引用而发消息 |

本模块也不向运营端产生任何消息或待办：运营既不查看也不维护企业账户，见[运营端不新增权限项（P-EA-02）](./01-企业账户-PRD.md#p-ea-02)。

<a id="ownership"></a>
## 2. 相关场景的通知归属

企业账户会出现在其他模块的业务流程里，那些提醒由来源模块发送，本模块既不重复发送、也不复述其规则：

| 场景 | 发送方 |
| --- | --- |
| 接受报价、登记放款等办理进展中涉及所选账户 | [授信报价与接受拒绝](../06-借贷广场-授信报价与接受拒绝/03-授信报价与接受拒绝-消息通知.md)、[放款与放款确认](../07-借贷广场-放款与放款确认/03-放款与放款确认-消息通知.md)按各自事件发送；通知正文不携带完整账户信息 |
| 账户维护入口因资格不足受限 | 属界面内的常驻提醒与引导，由登录主干与资金方账户模块定义，不是站内信 |
| 联系邮箱修改、账户停用／恢复、认证资格变化 | [资金方登录与账户体系](../02-资金方登录与账户体系/03-资金方登录与账户体系-消息通知.md)与[登录主干与资产方SSO接入](../01-登录主干与资产方SSO接入/03-登录主干与资产方SSO接入-消息通知.md)的既有安全与资格通知，与企业账户无关，不因本模块改动 |

由于本模块零事件，[面客消息中心](../10-面客消息中心/01-面客消息中心-PRD.md)的来源登记无需为本模块增行；其框架与未读口径不受影响。

<a id="privacy"></a>
## 3. 其他模块通知中涉及账户时的边界

企业账户属本企业档案。其他模块的通知若涉及所选账户，预览、正文与目标页面都不得携带完整账号 / IBAN、完整数币地址或整组账户信息；对手方不得通过消息读取本模块账户。

<a id="acceptance"></a>
## 4. 关联需求与验收

本模块零通知的规则见[变更不需审核，保存即生效，不发通知（D-EA-05）](./01-企业账户-PRD.md#d-ea-05)与[既定业务限制](./01-企业账户-PRD.md#limits)，验收见[账户变更零通知（AC-EA-34）](./01-企业账户-PRD.md#ac-notify)。原“账户变更安全告知”待决项已按用户裁定闭合，见[Q-EA-04](./01-企业账户-PRD.md#q-ea-04)。测试按零通知验收，不把“没有账户变更通知”判为缺陷。
