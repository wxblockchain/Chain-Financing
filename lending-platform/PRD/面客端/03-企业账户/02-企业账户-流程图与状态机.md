# 企业账户 · 流程图与状态机

版本：2026-09-24。需求：企业账户（WS-386）。与[主 PRD](./01-企业账户-PRD.md)及[消息通知](./03-企业账户-消息通知.md)共同使用。图中只表达角色、业务条件、结果和状态；字段、校验、权限与异常的完整定义在主 PRD，不在图册另建一套口径。

本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。图中节点是业务环节与信息域，不表示页面或组件。

实线表示业务推进或状态变化。本册共 5 张业务流程图与 2 张状态机；各图通过业务名称链接到主 PRD 的对应功能。**数币账户登记**与**收款账户生命周期**是两个独立业务对象，状态不混用。资产方与资金方走同一套流程，图中不分两条线；差别只在账户的资金用途，见[双侧同规则、用途按业务区分（D-EA-02）](./01-企业账户-PRD.md#d-ea-02)。

## 账户总览与新增入口（图 1）

对应[企业账户入口与账户总览（F-EA-01）](./01-企业账户-PRD.md#f-ea-01)。

```mermaid
flowchart TD
    A[双侧用户进入企业账户] --> B{正常登录且角色已绑定?}
    B -->|否| C[按主干规则处理：不返回任何账户数据]
    B -->|是| D{当前业务资格为已认证?}
    D -->|否| E[可见入口与用途说明；给补齐资格引导<br/>不返回账户数据，不提供维护动作]
    D -->|是| F[读取本企业账户]
    F -->|读取失败| G[说明暂时不可用并可重试<br/>不表达为尚未登记，不要求重新录入]
    G --> F
    F -->|本企业无账户| H[明确空态并直接给新增出路]
    F -->|已有账户| I[按法币、数币两类分别呈现<br/>默认在前，其余按登记时间]
    H --> J{新增哪类账户?}
    I --> J
    I --> K[对某账户：查看完整信息 / 修改 / 删除 / 设为默认]
    J -->|法币| L[进入法币账户新增]
    J -->|数币| M[进入数币账户新增]
```

运营人员与 SPV 不出现在本图任何分支：任何入口与直接请求都被拒绝，见[运营端不新增权限项（P-EA-02）](./01-企业账户-PRD.md#p-ea-02)。

<a id="fig-2"></a>
## 法币账户新增与修改（图 2）

对应[新增法币收款账户（F-EA-02）](./01-企业账户-PRD.md#f-ea-02)与[修改账户（F-EA-04）](./01-企业账户-PRD.md#f-ea-04)。

```mermaid
flowchart TD
    A[已认证一侧进入法币账户新增或修改] --> B[填写账户备注名、收款人地址、账号/IBAN<br/>收款行名称、收款行地址、SWIFT/BIC、收款行国家<br/>中转行信息整组选填；无收款人名称字段]
    B --> C{必填齐备?}
    C -->|否| D[逐项定位缺失项；不笼统报保存失败]
    D --> B
    C -->|是| E{SWIFT/BIC 为 8 或 11 位字母数字?}
    E -->|否| F[拒绝保存并定位到该项]
    F --> B
    E -->|是| G{收款行国家与 SWIFT 国家段一致?}
    G -->|否| H[提示但不阻断；用户确认后继续]
    G -->|是| I{中转行三项齐全或整组为空?}
    H --> I
    I -->|否| J[说明整组选填但填则须齐全]
    J --> B
    I -->|是| K{本企业内已有同账号/IBAN 且同 SWIFT?}
    K -->|是| L[拒绝并可直接查看已存在那一条]
    K -->|否| M[提交保存]
    M -->|失败| N[保持上一次成功状态，不产生半条账户，可重试]
    N --> B
    M -->|成功| O[保存即生效：不进审核、不产生待办<br/>立即出现在总览与业务选用列表]
    O --> P[已提交业务记录中的账户快照不变]
```

修改与新增走同一套校验；账户币种本期定值 USD 且只读，不提供选择。取消或离开不保留未提交内容，本模块不设草稿。

<a id="fig-3"></a>
## 数币账户新增与地址所有权签名（图 3）

对应[新增数币收款账户（F-EA-03）](./01-企业账户-PRD.md#f-ea-03)。

```mermaid
flowchart TD
    A[已认证一侧进入数币账户新增] --> B[先告知可登记范围：只能登记你能签名的地址<br/>交易所充值地址、第三方托管地址、无法签名的合约地址不支持]
    B --> C[选择结算收款链：ETH 或 TRON，不预选]
    C --> D[填写该链的收款地址与账户备注名]
    D --> E{地址符合所选链的格式?}
    E -->|否| F[按所选链说明格式要求<br/>ETH 为 0x 加 40 位十六进制；TRON 为 T 开头 Base58<br/>不提示另一条链的规则]
    F --> D
    E -->|是| G{本企业内同链同地址已登记?}
    G -->|是| H[拒绝并说明该地址已登记]
    G -->|否| I[请求用被添加的那个地址签名<br/>说明用途为证明地址归属，并说明不改变登录方式]
    I -->|钱包环境不可用或不支持该链| J[说明原因与可执行下一步；本次不登记]
    I -->|用户拒签、失败或超时| K[本次未完成签名，账户未登记，可重试]
    I -->|签名地址与要登记的地址不同| L[明确签名地址与要登记的地址不是同一个]
    J --> D
    K --> D
    L --> D
    I -->|签名通过| M[地址所有权确认为已确认]
    M --> N[登记成功：可被业务选用<br/>记录登记时间]
    N --> O[结算收款链与收款地址此后不可修改<br/>换地址须新增并重新签名]
```

签名不建立登录会话、不切换登录钱包、不参与登录地址匹配、不改变角色绑定，也不改绑登录凭据；被添加地址可与登录地址不同、可在另一条链上。与主干登录条款的关系见[Q-EA-05](./01-企业账户-PRD.md#q-ea-05)。任何失败分支都不改变当前登录、不产生半条账户，也没有“稍后验证”“跳过验证”或运营代确认的出路。

## 删除账户与已提交记录的关系（图 4）

对应[删除账户（F-EA-05）](./01-企业账户-PRD.md#f-ea-05)与[已选用账户的快照（D-EA-06）](./01-企业账户-PRD.md#d-ea-06)。

```mermaid
flowchart TD
    A[已认证一侧选择某账户并删除] --> B{是该类最后一个可用账户?}
    B -->|是| C[确认时额外告知：该币种/该链将无可选账户<br/>相关业务办理无法提交，可重新登记]
    B -->|否| D[显式确认：删除后不再出现在任何选用列表<br/>已提交业务记录不受影响]
    C --> D
    D -->|取消| E[保持原状]
    D -->|确认| F{删除是否成功?}
    F -->|否| G[保持原状并可重试]
    F -->|是| H[该账户从总览与全部业务选用列表移除]
    H --> I[已提交业务记录：账户快照不变，双方按各业务权限只读可见]
    H --> J[尚未提交的办理：下次进入要求重新选用<br/>不静默替换，不用默认账户顶替]
    H --> K{被删的是该类默认账户?}
    K -->|是| L[该类此后无默认；不自动提升其他账户]
    K -->|否| M[默认标记不变]
```

删除不可撤销，无回收站；需要恢复时重新登记，数币账户须重新完成地址所有权签名。

## 业务办理侧选用与回流（图 5）

对应[业务办理侧的选用与回流（F-EA-07）](./01-企业账户-PRD.md#f-ea-07)。本图只画本模块与办理侧的衔接，办理动作本身的完整规则在相应业务模块。

```mermaid
flowchart TD
    A[当事方在业务办理中需要指定收款账户] --> B{本笔结算币种}
    B -->|USD| C[可选范围：本企业法币账户]
    B -->|USDT / USDC| D[可选范围：本企业数币账户<br/>带出其结算收款链与收款地址，本笔只读]
    C --> E{读取本企业账户成功?}
    D --> E
    E -->|失败| F[说明暂时不可用可重试<br/>不表达为尚未登记，不要求手输，不放行缺账户的提交]
    F --> E
    E -->|成功但无可用账户| G[说明尚未登记并指向企业账户<br/>不给空白表单]
    G --> H[在企业账户完成登记]
    H --> I[回到原办理的原位置，已填内容不丢失]
    E -->|成功且有可用账户| J[按业务自身带出顺序预置<br/>都不适用时带出默认账户；默认不自动勾选]
    I --> J
    J --> K[本笔显式确认所选账户；办理内无新增/编辑/删除入口，不可手输替代]
    K --> L{提交瞬间该账户仍有效?}
    L -->|已被删除或修改| M[本次提交不成立：说明账户已变更并要求重新选用<br/>不拿旧值提交]
    M --> J
    L -->|是| N[提交成功：账户信息随业务记录固定为快照]
```

<a id="state-1"></a>
## 数币账户登记状态机

对象：一次数币账户的登记过程。初始状态为未开始，终态为已登记或本次未登记。

```mermaid
stateDiagram-v2
    [*] --> 未开始
    未开始 --> 待选链: 进入数币账户新增并已看到可登记范围告知
    待选链 --> 待填址: 选定结算收款链（ETH 或 TRON）
    待填址 --> 待签名: 地址格式通过所选链校验且本企业内不重复
    待填址 --> 待填址: 格式不符或地址已登记，就地说明并可改
    待签名 --> 已登记: 被添加的那个地址签名通过
    待签名 --> 本次未登记: 拒签、签名失败或超时、签名地址不匹配、钱包环境不可用
    本次未登记 --> 待填址: 用户重试
    已登记 --> 已删除: 在账户总览删除该账户
    已登记 --> [*]
    本次未登记 --> [*]
```

只有已登记才产生可被选用的账户；待选链、待填址、待签名都不是账户，不落入总览、不占用去重判断、不可被业务选用。结算收款链与收款地址在进入已登记后不可修改；换地址须重新从待选链开始。

<a id="state-2"></a>
## 收款账户生命周期状态机

对象：一个已登记的收款账户（法币与数币共用）。

```mermaid
stateDiagram-v2
    [*] --> 可选用: 法币校验通过保存 / 数币签名通过登记
    可选用 --> 可选用: 修改可编辑项（法币除账户币种外均可；数币仅备注名）
    可选用 --> 默认: 设为该类默认账户
    默认 --> 可选用: 取消默认，或同类另一账户被设为默认
    可选用 --> 已删除: 删除并显式确认
    默认 --> 已删除: 删除并显式确认（该类此后无默认）
    已删除 --> [*]
```

可选用与默认都属“可被业务选用”，默认只影响带出兜底顺序，不影响是否可选。已删除是终态：不出现在总览与任何选用列表，不可撤销、不可恢复；但已提交业务记录中的账户快照不随之变化，仍按各业务权限只读可见。本期不设“停用”这一中间状态——停止使用某账户的唯一方式是删除它。
