# 我的控制台 · 功能与业务规则

2026-10-23｜面客端：资产方、资金方｜需求评审稿，建议执行项、已确认口径与外部依赖见末节。

本模块共三册：本册定义功能与业务规则；[流程图与状态机](./02-我的控制台-流程图与状态机.md)表达主要流程；[验收](./04-我的控制台-验收.md)供测试使用。控制台不发送消息，因此没有 03 消息通知册；消息承接规则在本册，具体事件由来源模块维护。编号沿用原值，缺号不代表遗漏。

## 1. 目标与阅读入口

我的控制台帮助资产方和资金方了解本企业跨项目的资产、授信与融资全貌：业务清单直接标出本企业现在需要处理的记录，各类列表与详情回答“是哪笔业务、对方是谁、进行到哪一步”，完整资料和业务办理到借贷广场对应项目。控制台只保留借贷广场没有、或需要跨项目汇总的信息；借贷广场已展示的完整资料不在控制台重复。

基本原则：

- 企业统计、业务记录和本人消息各有范围；筛选不改变企业统计和分类标签上的待处理数量，读信不办结业务，也不消除待处理提示。
- 不设独立待办模块：本企业现在就能处理的事项标在对应清单记录上，由业务事实自动产生和消失；等待对方、等待链上结果、尚未开放的事项不标为待处理。通知与已读未读仍归消息中心。
- 详情头部先让用户认出对象：报价看项目名称，授信、还款看对方企业名称，链上授权看授权地址。详情只保留判断所需的核心信息，完整条款、地址、凭证、历史和计划在借贷广场阅读。
- 融资项目详情直接复用借贷广场项目详情，不在控制台另做一份。
- 控制台只有两类写入动作：资金方修改授信，规则沿授信报价模块；在“链上授权”清单中撤销本企业在本平台给出的链上授权——资金方的放款授权（报价成功后即可撤销，用户 2026-10-23 裁定）与资产方的质押授权。融资、质押、报价、接受、还款的办理都在借贷广场完成。
- 报价与放款合为一步后（资产方接受即链上放款），控制台不再单设融资放款信息分类；还款信息清单直接给出放款金额、放款机构与放款时间，见[取消融资放款信息分类（Q-MC-64）](#q-mc-64)。
- 同一融资业务在报价和还款分类中可以重复出现，但仍是同一笔业务，不叠加成新的融资额。

**一个完整的例子。** 资产方甲进入我的控制台，“融资项目”分类标签显示 1、“还款信息”分类标签显示 1。甲打开还款信息并勾选“只看待处理”，看到资金方丙的一笔业务标着“待我方处理·还款”，写着第 3 期、应还 12,500.00 USDT（结算 12,500.00 USDC）、已逾期 2 天。甲点击该记录上的“还款·第 3 期”，到达借贷广场该项目并定位到第 3 期，从项目的还款入口选定出账地址、点击“授权并还款”签名后返回控制台：第 3 期显示“还款上链确认中”和冻结的逾期 2 天，这笔业务等待链上结果、不再标待处理，因已不匹配“只看待处理”而提示记录已更新。链上还款成功后再次进入，甲的还款详情头部写着“丙”，第 3 期已结清，逾期 2 天作为历史保留；资金方丙的还款信息同步显示第 3 期已结清，丙不需要做任何确认，丙的控制台也没有待处理事项。丙在“链上授权”清单中看到另一笔被甲拒绝的报价对应的放款授权仍为“已授权”，丙用该笔放款地址签名撤销授权，成功后显示“已撤销”。甲读没读过相关站内信，都不影响上述提示。

本期不做：支付、审核、代确认和账户维护；独立待办模块、页面级待办总数，以及待处理事项的手动完成、忽略、归档、指派或催办；授信调低、冻结、停用或删除；报价、接受、还款的签名办理（均在借贷广场）；复制消息信箱；列表与空态的广场快捷入口；页内刷新或重试取数动作（沿用既有全局导航和浏览器刷新）；反向直达资产广场。

| 融资申请、融资业务、期次 | 一轮申请用 FP-28 标识，一笔报价及后续融资用 FD-01 标识，一期定稿还款用 RP-01 标识；放款记录 LN-01、还款记录 RM-01 不另算融资业务 |

## 2. 角色、信息域与共同业务规则

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

“行级提醒”指列表记录自身显示的业务事实，“待处理提示”指标在记录上的本企业待处理事项，两者都不指定具体界面形态；“列表分类”指按角色适用的业务数据分类，不指定其承载形式。

<a id="d-mc-105"></a>`D-MC-105`、<a id="d-mc-128"></a>`D-MC-128`、<a id="d-mc-137"></a>`D-MC-137`：本期一个企业一个员工账号，业务集合仍按企业归属确定，不新增成员管理、分工或转交；机构不得看到资产方在其他机构的授信与占用，资产方不得看到机构内部备注。共享链接也必须受当前访问者归属约束。

<a id="d-mc-199"></a>本人档案与业务资料（`D-MC-199`）：个人、企业账户档案仅本人可查；企业共享业务视图不等于共享每位员工个人档案，也不向对手方开放完整企业档案、证件、认证材料或私人联系方式。控制台按原字段与当事方权限自动取得必要企业/机构名称、业务条款与金额，不让用户抄写对方已知资料。读取中、未提供、读取失败分别表达，缺项不补假值、不将失败转成手填表单；关键企业归属未确定不得展示“我的”集合。放款、还款所涉地址与交易标识的完整值在借贷广场按本笔当事方权限读取和复制；控制台只在链上授权清单中展示授权地址，不新增档案或账户编辑入口。SPV视同运营，无新增面客视图、代付、代确认或私有资料读取权。消息权限另见[业务共享与个人消息](#mc-nr-02)。

非当事资金方在借贷广场可读[非隐私履约信息](../08-借贷广场-链上还款/01-链上还款-PRD.md#non-private-performance)，不使其他机构业务进入本机构控制台集合；金额、条款、地址和凭证仍私有，不赋予办理或收信权限。来源重新按当时身份判权。

<a id="d-mc-123"></a><a id="d-mc-157"></a><a id="d-mc-174"></a>待处理数量与其他数字（D-MC-123、D-MC-157、D-MC-174）：控制台不设独立待办模块或页面级待办总数，只在分类标签上显示[待处理记录数](#pending-count)。该数量不与统计张数、业务笔数、列表总数或消息未读数互相替代或相加；未读数仍由消息中心负责。待处理不是新的列表分类，也不改变各列表的记录粒度。

<a id="d-mc-119"></a>只读为主、两类写入（D-MC-119）：控制台可以读业务事实、改变浏览视图、复制可见信息和跳转。写入动作只有两类：资金方在授信详情[修改授信](#credit-modify)，以及在[链上授权](#f-mc-14)清单中[撤销授权](#revoke)；规则与结果分别沿授信报价模块与融资需求与代币质押模块。控制台不录入、审核、提交或确认任何融资、质押、报价、接受或还款业务，撤销授权由授权地址本人签名，平台不代任何一方签名。同一业务的金额、状态、利息、逾期天数、质押缺口、授信可用额必须与对应广场一致，本页不另定计算口径或修正结果。

<a id="d-mc-130"></a>`D-MC-130`：项目状态、融资业务状态、还款期次状态、融资需求对外状态分别带业务标签，不合成“进行中”等新状态。融资需求对外状态只有“待报价”“已报价待确认”“放款中”“已放款”“已失效／已关闭”五值，末项为合并值，须配终结原因；还款进展不形成第六个对外状态。发布或改额冻结处理中、撤下处理中、报价上链确认中、链上放款处理中都是当前轮的链上处理事实，按来源显示，不另成需求状态。

<a id="money-units"></a>金额明确币种：代币价值、份额价值与质押价值以 USD 计；融资需求金额、授信额度与占用、融资金额、本金、利息与应还合计以 USDT 计；结算金额与放款、还款金额以本笔结算币种（USDT 或 USDC）计。USD 与 USDT 比较时按 1 USDT = 1 USD，不引入汇率（[Q-LS-28](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#q-ls-28)）。张数、代币数量和金额不是同一量，不互相相加。日期按UTC业务日期；具体时刻按用户偏好时区展示并标注，无偏好沿平台既有展示规则，不能因设备时钟偏差改变。报价接受没有办理时限；链上授权、链上放款、链上还款与撤销授权以链上结果为准，不设时限；项目有效期、授信有效期、应还日和还款开放时点仍按来源展示。业务字段均只读、不提供默认假值；0仅表示确有零值，缺失不转成0。地址与交易标识按平台已定脱敏规则显示，完整值去对应广场查看。

## 3. 功能需求说明

<a id="f-mc-01"></a>
### 3.1 企业统计（F-MC-01）

资产方看到资产与融资全貌；资金方看到授信与出资全貌。所有指标限定当前主体全部业务，不因当前列表分类、分页或筛选缩成当前页合计。进入页面、从广场返回或浏览器刷新当前网址时更新；同一组数量、金额和从属子项保持同批事实一致。相关流程见[准入与聚合视图（FL-MC-01）](./02-我的控制台-流程图与状态机.md#fl-mc-01)。

| 业务字段／编号 | 类型与业务意义 | 范围、必有值与显示 |
| --- | --- | --- |
| 全部代币张数、代币价值合计 | 非负整数张数、USD金额；本平台快照中属于本企业且符合展示条件的代币总量 | 资产方必有；含失效；资金方不展示；正常空集合为0 |
| 其中已质押代币张数、代币价值合计 | 已进入某个项目质押合约且归属该项目的代币子集；账面金额含失效 | 以“其中”从属于全部代币，不能表达为与总量互斥的两个独立指标（<a id="d-mc-47"></a>`D-MC-47`）。企业口径的“已质押”只说明代币在合约内，与项目口径的[总质押额、有效质押额](#f-mc-03)不是同一个量，不互相替代 |
| 其中已失效张数、金额 | 上述已质押子集中代币已失效的部分 | 必有，并标注“不计入有效质押”；不能用全部代币失效量冒充此子集 |
| 总授信额度、授信笔数（`CR-05`） | USDT金额、非负整数；资产方各机构授信／资金方授予各资产方的授信 | 双方可见；沿用授信域统计结果 |
| 已融额度、业务笔数（`FP-13`／`CR-08`） | USDT金额、非负整数；资产方为各项目的项目融资余额合计／资金方为本机构授信占用额与未结清融资业务数 | 双方可见；已融额度等于项目融资余额，只在链上放款成功时增加，不把在途报价、报价上链确认中或链上放款处理中的金额当成已融额度 |
| 剩余可用授信（`CR-11`） | 当前可用授信汇总，USDT | 双方可见；不是“还能融资多少”的承诺 |

<a id="d-mc-43"></a>`D-MC-43`、<a id="d-mc-44"></a>`D-MC-44`、<a id="d-mc-126"></a>`D-MC-126`、<a id="d-mc-127"></a>`D-MC-127`：代币价值按各笔签发时既定的 USD 金额汇总，并说明“按各笔签发价值计”，不实时换汇；与 USDT 金额只按 1:1 比较，不互相改写。企业口径的已质押账面值不等于任一项目的有效质押价值，不能以简单减失效值强行对平；项目侧还受有效质押条件约束。剩余可用授信须同时说明“实际可融金额以发布需求时的核定结果为准”。

项目在途金额、可融金额与可撤回上限不作为控制台的常态指标，只在办理需要时由归属模块当场给出，本页也不展示额度换算规则或公式；有效质押额按[融资项目](#f-mc-03)作为项目指标之一正常展示，两者不冲突。动作受限时仍保留归属模块给出的必要差额、原因与出路（`H-03`），不能为隐藏中间量而删掉用户解决问题所需的信息。

指标失败时仅该组显示暂不可用，提示可用浏览器刷新当前网址重试，不伪装成0；无机构主体按[准入、空态与异常](#f-mc-10)走机构资料引导，不进入正常统计空态。

<a id="token-stat-scope"></a>
整笔代币数量、签发价值和张数按企业归属集合及唯一代币编号计算；多持有方时任一持有方已质押即显示已质押，列出有权关联项目，全部未质押才为未质押。该结果不代表本企业当前可质押份额、有效质押价值或可融额度；后续份额口径仍见[多持有方代币统计含义](#q-mc-61)。

<a id="f-mc-02"></a>
### 3.2 代币列表（F-MC-02）

仅资产方可见。范围为本平台只读代币域中“属于本企业”的集合，与资产广场是同一套事实的主体过滤视图。从代币记录进入本控制台代币详情 `P-MC-02`；列表不提供借贷广场入口，详情仅按[详情前往借贷广场与返回](#f-mc-09)前往关联项目。详情沿用本节字段边界，不因新增详情而开放额外资产资料，不扩展资产广场未约定的反向入口。

<a id="d-mc-215"></a>与借贷广场代币详情的分工（D-MC-215）：借贷广场的代币详情只回答“这份代币在本项目质押得怎样”，不提供前往我的控制台或其他位置的入口（用户 2026-10-21 裁定，[Q-LS-26](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#q-ls-26)）。资产方需要查看本企业代币的整体情况时，自行从导航进入我的控制台代币列表；控制台代币详情仍按本节字段范围展示，不复制借贷广场的逐份质押上链事实、去向与逐币历史。

<a id="d-mc-195"></a>自己的全部代币（`D-MC-195`）：自己的指当前已确认资产方企业主体，不是当前员工个人、个人钱包或当前选中的融资项目。企业全集不随当前账号的钱包连接变化。默认不限状态及项目，包含跨项目、未关联项目、未质押、已质押、有效及失效的所有可展示代币；不能只从融资项目、已质押记录或发生融资的资产中取子集。按唯一代币编号展示一次，跨页合起来覆盖该集合；“全部”不要求单页取消分页。筛选只改变浏览结果，清除后恢复企业全集，企业统计始终采用未筛选全集及对应子集。代币当前唯一链上持有地址不等于本企业归属，不通过钱包、合约地址或地址变动推断“自己的”范围；本列表仍不新增持有地址或份额信息。资金方仍无代币列表或代币统计；不扩大他企业、机构或员工权限。快照范围与完整性要求继续依D-MC-175/178，不能把未同步、关键缺失或归属未知的数据冒充可展示代币。状态范围见[代币生命周期结果（ST-MC-01）](./02-我的控制台-流程图与状态机.md#st-mc-01)。

<a id="d-mc-175"></a>数据边界（`D-MC-175`）：代币事实由代币发行平台提供，本平台使用已同步快照；不设置运营上架闸门，不在打开控制台时临时访问上游。代币状态、价值取代币事实，质押结果取本平台借贷业务，不能回读上游旧质押结果。资产可信平台的应收账款信息随展示数据到位。来源为WS-350 `D-AM-47`～`D-AM-51`。

| 字段／既有编号 | 业务类型与含义 | 必有值、展示与校验 |
| --- | --- | --- |
| 代币编号（`D-TI-21`） | 唯一业务标识；16位 `TK` + 铸造日 + 6位序号 | 必有，完整可复制；关键缺失不得展示该记录 |
| 代币类型（`FP-29`） | 代币标准与底层资产类型合并的单一字段，形如 `ERC-3525-应收账款` | 只读，取上游已配置取值；字段形态须能容纳多个标准，不写死某一标准；代币标准不再单独成项 |
| 代币数量（`D-TI-11`） | 数值，最小0.01、2位小数 | 必有；符号只取已确认配置，不编造ticker；张数与此数值分开 |
| 代币价值（`D-TI-18`） | 固定USD金额，2位小数 | 必有；不二次折算；用“代币价值”标签 |
| 底层应收账款账期（`D-06`／`D-07`） | 起始日～到期日，`yyyy-MM-dd` | 只读；缺项显示“—”，不补造日期；有效数据不得起始日晚于到期日 |
| 买方企业名 | 对应底层应收账款债务方全称 | 只读；缺失显示“—”，不以本企业名替代 |
| 代币状态（`D-TI-22`） | “有效／失效”二值 | 必有；失效结果由上游判定，不根据本机日期自行翻转 |
| 质押状态（本平台 `PL-06`） | “未质押／已质押”二值 | 与代币状态分别标注，不复用上游 `D-TI-24` 旧口径；不是代币是否有效的判断。**已质押只说明代币在项目所配置的质押合约内并归属该项目**；同一份质押合约由同组合的多个项目共用，是否计入有效质押及其额度归属在对应项目查看 |
| 所属融资项目（`FP-01`／`FP-02`） | 项目稳定标识和名称 | 已质押时显示相应项目标识与名称；同组合项目共用质押合约，项目以项目编号区分，不以合约地址识别；列表不提供借贷广场直达入口。详情目标按[详情前往借贷广场与返回](#f-mc-09)确定，待审核、已退回项目的可访问性由融资需求与代币质押模块判定，不暴露他方私有项目 |
| 签发时间（`D-TI-07`） | 与资产广场“铸造时间”同一时刻 | 必有；显示时区；默认倒序排序，不另造第二个时间事实 |
| 铸造交易哈希（`D-TI-06`） | 铸造业务凭证，格式按[网络](#chain-scope)定义（本期 Ethereum：`0x`+64位十六进制） | 属共有数据完整性条件，不因此在代币列表新增哈希展示或外链入口 |

<a id="d-mc-176"></a>对外收敛（`D-MC-176`）：代币已在项目质押合约内时显示“已质押”，与是否计入有效质押无关；未质押、上链处理中、上链失败、已释放均按资产广场同源结果显示“未质押”。控制台不显示这些内部过程分支，也不自行翻译内部编号。失效与已质押可以同时成立；失效记录标注“不计入有效质押”。详见[代币生命周期结果（ST-MC-01）](./02-我的控制台-流程图与状态机.md#st-mc-01)和[质押对外展示状态（ST-MC-02）](./02-我的控制台-流程图与状态机.md#st-mc-02)。

<a id="d-mc-131"></a>`D-MC-131`、<a id="d-mc-177"></a>`D-MC-177`：代币列表与代币详情均不展示合同号、发票号、提单号、持有人地址、附件影像、运营诊断、链上过程态、gas或“已释放·待提取”第三种质押状态。代币列表不提供可提取汇总提示；解押与提取在融资需求与代币质押模块办理，提醒由融资项目列表的[待处理提示](#todo-types)承接。逐张质押的当前去向不扩展为第三根代币轴，用户到项目业务查看。

<a id="d-mc-178"></a>数据可用性（`D-MC-178`）：代币编号、数量、价值、代币状态、铸造交易哈希、铸造时间任一缺失的记录不进入展示集合、不计入对应统计；本企业归属无法确认时不得展示或计入。非关键项缺失逐项“—”。这是与WS-350 `E-AM-10`同源的集合规则，不能两页一边显示一边统计排除。

已同步新增代币即可见；失效在上游判定当日反映于代币列表、统计及资产广场，代币总量与价值每日至少与上游核对一次。上游同步不可用但本平台仍有可用快照时展示最近可用数据，不清空、不向用户暴露同步诊断；本平台读取也失败则显示失败，提示使用浏览器刷新当前网址，不能用空列表掩盖。不得把“暂未同步”视为允许永久过时上线。

代币列表可筛选代币状态、质押状态、代币类型、所属项目；可按代币价值、账期到期日排序。筛选为交集，默认不限；不新增网络筛选（本期网络唯一）或全平台企业选择条件。分页见[分页、筛选、排序与刷新恢复](#f-mc-11)。真空态说明“本企业暂无可展示的代币”，不把暂无同步数据断言为从未铸造；原资产平台入口改称资产可信平台，采用登录域离站告知，不因进入代币列表自动跳站。

<a id="f-mc-03"></a>
### 3.3 融资项目（F-MC-03）

仅资产方可见。一条记录一个本企业项目（FP-01），包括待审核、已退回和从未发布需求的项目；列表让资产方不进详情就能看出每个项目的状态、当前需求、债务和风险。项目详情直接复用借贷广场的项目详情，控制台不另做一份项目摘要。关联[从列表经详情到对应广场项目并返回（FL-MC-02）](./02-我的控制台-流程图与状态机.md#fl-mc-02)。

<a id="d-mc-210"></a>项目详情复用借贷广场（D-MC-210）：

- 点击项目记录，打开借贷广场该项目的项目详情（P-MC-03 由借贷广场项目详情承载），内容、可见范围和办理入口全部沿[项目详情按身份的可见范围（F-LS-82）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-82)与[查看与办理分开（F-LS-20）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-20)：资产方看到本企业项目的全部信息，包括项目摘要、五项统计、质押合约、质押代币、融资申请、还款三类记录，以及质押、融资、还款三类办理入口。
- 项目详情提供返回我的控制台的入口，返回后恢复原列表分类、筛选、排序、分页和所在位置，并显示最新事实，规则沿[从控制台、资产广场与消息进入（F-LS-13）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-13)。
- 记录、待处理事项或消息明确了某一轮申请（FP-28）时，打开项目详情并定位该申请，按[原对象阅读定位建议](#q-mc-60)执行、待确认。
- 控制台不复制项目基本信息、质押合约、逐轮申请历史、链上放款记录、操作记录、三类记录或逐张质押明细。

| 列表字段／编号 | 业务含义与显示条件 |
| --- | --- |
| 项目名称、项目编号（FP-02、FP-01） | 项目存在即必有，只读；同名项目以项目编号区分，不虚构名称 |
| 代币类型（FP-29） | 代币标准与底层资产类型合并的单一字段，形如“ERC-3525-应收账款”；只作筛选与识别 |
| 项目状态、到期标记、关闭原因（FP-04、FP-05、FP-23） | 状态为待审核、已退回、可用、募集中、已锁定、融资中、已关闭、已结清，沿[项目状态与后续业务](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#project-state)；资产方签名接受后链上放款处理中或放款失败时仍为已锁定，放款成功后为融资中；关闭原因仅关闭时有值 |
| 当前融资申请（FP-28）、需求金额（FP-06）、需求对外状态及终结原因（FP-27） | 有当前申请时显示编号、USDT 金额与五值状态；无当前申请时说明“暂无当前需求”，不用 0 或历史申请补位。发布处理中尚无融资申请编号，以金额与“发布处理中”识别 |
| 当前轮链上处理中 | 当前轮发布或改额冻结处理中、撤下处理中、机构报价上链确认中、链上放款处理中时，给出该事实与已等待时长；结果长期未知时说明“链上结果待核实，请联系平台客服人员”。这些不是新的需求状态，期间不标待处理 |
| 报价的链上授权已撤销 | 当前申请的待接受报价的放款授权已被资金方撤销（含平台外撤销）时，说明“资金方已撤销链上授权，暂不能接受，可拒绝”；“处理报价”事项照常标记 |
| 报价机构、已锁定时长（FD-13） | 当前申请为已报价待确认或放款中时显示；已锁定时长自报价成功起累计，接受成功、拒绝或连带失效后停止。**报价没有有效期、截止时刻、剩余时间或倒计时** |
| 已融资余额（FP-13） | 项目融资余额，USDT；只在链上放款成功时增加 |
| 质押情况（FP-20）、质押缺口与需追加资产价值（FP-21） | 三档为“质押充足／质押持平／质押不足”；质押不足时成对给出质押缺口（USDT）与需追加资产价值（USD） |
| 质押风险与待处理资产 | 适用时分别给出：已释放待提取的张数与 USD 金额、失效代币张数与价值（FP-19） |

<a id="fp-10"></a><a id="fp-12"></a><a id="fp-34"></a>两项质押额与项目质押率（D-MC-206）：项目详情（复用借贷广场）中的总质押额（FP-10）、有效质押额（FP-12）与项目质押率（FP-34）按[字段命名与术语对照表](../../00-字段命名与术语对照表.md)和融资需求与代币质押模块的现行口径展示，控制台不另算。**总质押额**含失效的代币，只展示、不参与准入；**有效质押额**＝有效质押价值 × 项目质押率。**项目质押率**由资产方创建项目时自填，合约配置完成后锁定（已退回时可修改），本期不存在固定 80% 的平台质押率。代币授权后签名质押、上链成功即质押成功，不经审核；撤回与解押都在借贷广场办理。对应[项目指标与质押事实验收（AC-MC-117）](./04-我的控制台-验收.md#ac-mc-117)。

<a id="d-mc-134"></a><a id="d-mc-135"></a><a id="d-mc-136"></a>质押不足（D-MC-134～D-MC-136）：质押不足的项目在列表成对给出“质押缺口 X USDT／需追加资产价值 Y USD”，项目记录标为待处理“[追加质押](#todo-types)”；追加质押在借贷广场项目内办理，上链成功即计入有效质押额。提醒没有缓冲倒计时，不暗示追加可以救回已失效需求。需求失效与项目质押情况是不同判断，允许“项目质押充足、某轮需求已失效”同时出现。资金方在本机构相关业务的借贷广场项目详情中也能看到该项目质押情况和缺口。

<a id="d-mc-132"></a><a id="d-mc-159"></a>待提取（D-MC-132、D-MC-159）：项目有已释放待提取的资产时，列表给出张数与金额，项目记录标为待处理“[提取代币](#todo-types)”；须由资产方主动在借贷广场项目内签名办理，不设倒计时，不暗示自动回到钱包。质押上链、解押和提取的业务判断与操作都在融资需求与代币质押模块。

项目可按项目状态、质押情况和代币类型筛选；需求五值不作为项目筛选项。默认创建时间倒序。空态说明“尚未创建融资项目”，不在列表空态提供创建或广场快捷入口；用户可使用既有全局借贷广场导航。

<a id="d-mc-200"></a>项目资格与执行异常（D-MC-200）：项目状态、到期标记、质押情况及融资资格直接采用融资需求与代币质押模块当前结果，控制台不重判。链上放款成功后单笔业务只能按还款计划还款直至结清，没有中途终止出口（[D-LS-64](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-64)）。到期项目不恢复发布或新报价资格，存量继续履约。质押情况未知时不冒充充足或不足，保留已确认事实并说明暂不可用。执行长期无结果、冲突或部分结果待核实时，列表只说明“链上结果待核实，请联系平台客服人员”，不新增异常处置、工单或执行态；真实客服渠道和逐笔结果见末节。见[项目资格与执行结果阅读（FL-MC-06）](./02-我的控制台-流程图与状态机.md#fl-mc-06)。

<a id="d-mc-189"></a>项目与申请（D-MC-189）：融资项目一条记录仍是一个项目，不因多轮申请或多笔报价重复入列。改额保留原申请编号，再次发布生成新一轮。完整逐轮历史、当前报价条款、授信摘要、链上放款记录与操作记录在借贷广场项目详情的融资申请详情中阅读；预计计划不产生有效期次，不进入还款列表。衔接见[申请、报价、还款入列与期次定位（FL-MC-05）](./02-我的控制台-流程图与状态机.md#fl-mc-05)。

<a id="f-mc-04"></a>
### 3.4 授信明细／授信汇总（F-MC-04）

资产方名称为“授信明细”，资金方为“授信汇总”。一条记录对应“一家资金方机构 × 一家资产方企业”的授信关系，不按项目拆分。借贷广场没有独立的授信页面，授信的使用情况和修改入口集中在控制台授信详情。授信金额一律以 USDT 计。

列表直接识别：对方名称、授信编号、授信状态、授信有效期至、授信额度、授信已用额、可用授信。按授信状态筛选，默认可用授信升序。双方授信列表空态均不提供发起授信或前往借贷广场的入口。

<a id="credit-detail"></a>
#### 授信详情

| 内容 | 资金方看到 | 资产方看到 | 规则 |
| --- | --- | --- | --- |
| 头部识别 | 被授信企业名称（CR-03） | 授信机构名称 | 以对方名称作为详情标题，不以“授信详情”字样代替；同时可读授信状态、授信有效期至和可复制的授信编号（CR-01） |
| 授信使用情况 | 授信额度（CR-05）、授信占用额（CR-08）、在途报价金额（CR-09）、可用授信（CR-11），以及授信已用额（CR-10），均为 USDT | 与资金方相同 | 四个数取授信报价模块当前结果，满足“占用额＋在途报价金额＋可用授信＝授信额度”；已用额是占用额与在途报价金额之和，不是第三种占用。在途报价金额含报价上链确认中的预占。图表形式由设计决定 |

<a id="credit-usage"></a>
**当前使用记录。**

- 一笔一条，只列当前仍在使用这份授信的报价与融资业务：在途报价（报价上链确认中、待接受，含资产方已签名接受、链上放款处理中）和授信占用（还款中、尚未还清本金）。已拒绝、报价已失效、已结清的业务，以及授权上链失败未形成的报价不在此列。
- 每条显示：项目名称、融资业务编号（报价上链确认中尚无融资业务编号，显示融资申请编号并标“报价上链确认中”）、使用类型（在途报价／授信占用）、使用金额（USDT）、当前业务阶段。在途报价的使用金额为融资金额（QT-03），授信占用的使用金额为未偿本金（FD-43）。
- 在途报价各条金额合计等于在途报价金额，授信占用各条金额合计等于授信占用额；两者取同一批事实，不一致时以授信报价模块结果为准并说明明细暂不可用，不自行调平。报价上链确认中按用户 2026-10-23 裁定列入（[Q-MC-65](#q-mc-65)）。
- 默认按报价时间倒序（报价上链确认中按签名发出时间）；记录较多时可分页浏览，不截断。
- 点击一条记录，进入当前角色对应的去向：资金方报价上链确认中与待接受进入我的报价详情，还款中进入还款详情；资产方报价上链确认中与待接受进入复用的借贷广场项目详情并定位原申请，还款中进入还款详情。
- 无使用记录时说明“当前没有在途或占用中的业务”。明细读取失败只影响这一部分，授信使用情况的数值照常显示。

<a id="credit-modify"></a><a id="d-mc-211"></a>
#### 修改授信（D-MC-211）

适用角色与前提：本机构已认证资金方，在授信汇总的授信详情中办理；授信关系已存在。资产方没有此入口。修改是对同一授信关系的变更，授信编号不变，规则与留存沿[企业授信（F-LS-38）](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#f-ls-38)和[授信有效期（F-LS-39）](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#f-ls-39)，控制台不另定口径。

| 授信状态 | 可以修改的内容 | 校验与限制 |
| --- | --- | --- |
| 生效中 | 增加授信额度（正数增加额，USDT）、后延授信有效期至、备注、本次授信协议 | 额度只增不减；有效期至可保持或后延，不能提前，后延不超过首次授信日或最近一次重新授信日起五年；额度与有效期至至少改变一项（按[授信修改范围](#q-mc-63)建议执行、待确认） |
| 已到期 | 重新授信：带出上一版额度供修改，重新填写授信有效期至，可改备注与本次授信协议 | 额度大于 0 且不得低于当前授信已用额；有效期至默认重新授信日＋1 年，可选＋1 年至＋5 年 |

- 授信额度只能增加或在重新授信时不低于已用额，**不提供调低、冻结、停用或删除授信**。
- 本次授信协议为选填，0～10 份，格式与大小沿授信报价模块；历史协议不被覆盖、不可删除。
- 保存成功立即生效，没有审批；授信详情的使用情况、可用授信和列表、企业统计同步更新。修改不生成报价、不锁定需求、不改变已有的在途与占用，不涉及链上操作。
- 提交时按最新授信状态、已用额和有效期起点重新校验；校验失败定位到具体字段并保留已填内容；提交过程中防止重复提交，重复点击不重复增加额度。
- 授信状态在填写期间发生变化（例如跨过到期日）时，按新状态重新给出可修改内容，不按旧状态保存。
- 每次修改都可追溯：谁代表哪家机构、何时、改变了多少额度与有效期至，来源记为“控制台修改授信”，没有关联项目。
- 修改授信不发送消息，与授信报价模块“授信变更不发信”一致。
- 取消或不保存即结束本次修改，不留下任何变更。

<a id="d-mc-92"></a><a id="d-mc-138"></a><a id="d-mc-160"></a>授信入口边界（D-MC-92、D-MC-138、D-MC-160）：控制台除修改授信外没有“去授信”、首次授信或审批入口；首次授信仍只能在借贷广场报价前的授信核验中办理。授信详情不设“前往借贷广场”导航，也不再要求选择关联项目；查看具体业务从当前使用记录进入。历次授信记录和授信协议的完整阅读沿授信报价模块的权限，控制台不复制。

<a id="d-mc-201"></a>授信期限（D-MC-201）：采用授信报价模块正式结果。五年上限从首次授信日或最近一次重新授信日起算，追加不重置起点。授信有效期至包含所选 UTC 日期，次日 00:00 UTC 起为已到期；按年加遇目标年无同日取该月最后一日。到期只阻止新报价，不消除存量占用。起点资料暂不可用时不编造新起点、不放行延期。

<a id="f-mc-06"></a>
### 3.5 还款信息（F-MC-06）

<a id="d-mc-192"></a>还款列表（D-MC-192）：双方按“一笔链上放款成功的融资业务一条记录”查看，记录唯一依据为融资业务编号（FD-01）。融资申请编号、融资业务编号、放款编号都能检索到同一条记录；分页总数按业务笔数计算，不按期数重复。列表直接识别：对方名称、项目名称、融资申请编号、放款信息、业务状态（还款中／已结清）与当前逾期标记、本期应还（期次、应还日、应还合计 USDT 与结算金额及币种）或“暂无待还期次”、还款上链确认中的期次与已等待时长（有时）。

<a id="d-mc-216"></a>放款信息（D-MC-216）：取消融资放款信息分类后，放款结果在还款信息清单的每条记录上直接可读（用户 2026-10-23 裁定，[Q-MC-64](#q-mc-64)）：放款金额与币种（[LN-04、LN-03](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#loan-record)，即本笔结算金额）、放款机构（本笔报价的资金方机构名称）、放款时间（放款成功时间 FD-40），以及用于识别的放款编号（LN-01）。资产方看到的放款机构就是对方名称；资金方查看本机构业务时放款机构即本机构，可不重复显示。放款地址、资产方收款地址与放款交易标识仍在借贷广场融资申请详情阅读。

链上放款成功（[放款成功时间（FD-40）](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#fd-40)）即入列，还款计划生成中也保留该业务，不伪造期次编号、期数、应还日期或金额；读取失败给暂不可用及浏览器刷新当前网址的文字指引，不回退已成立的放款。全部结清仍保留业务，不展示 0 元“本期应还”。

<a id="repay-detail"></a>
**还款详情（P-MC-06）。**

| 内容 | 规则 |
| --- | --- |
| 头部识别 | 对方名称作为详情标题：资金方看到资产方企业名称，资产方看到资金方机构名称；同时可读业务状态、当前逾期标记和项目名称 |
| 本期应还 | 期次序号与总期数、应还日（RP-04）、应还合计（RP-08，USDT）与应还结算金额及币种（RP-09）、期次状态（RP-10）、适用逾期天数（RP-11）；末期说明含本金；尚未开放时说明开放时点（应还日 00:00 UTC）；无待还期次显示“暂无待还期次” |

| 指定期次 | 从待处理提示、消息或旧入口指定某一期（RP-01）时，显示该期当前结果，即使已结清也不切换到新一期；已结清时给出期次结清时间（RP-17）与还款记录编号（RM-01） |
| 还款进度 | 已结清期数／总期数、累计已还本金与利息（FD-42）、未偿本金（FD-43）、最终还款日（FD-46）；整笔结清时显示结清时间（FD-45） |
| 放款信息 | 放款机构、放款金额与币种、放款时间与可复制的放款编号，口径同[放款信息](#d-mc-216) |
| 编号 | 可复制的融资申请编号、融资业务编号、放款编号 |

- 完整定稿还款计划、其他未来期次、已结清历史、逐期本息与计息区间、出账地址、资金方还款收款地址、链上还款交易标识与查验入口在借贷广场原笔还款详情阅读；链上放款明细在借贷广场融资申请详情阅读；控制台都不复制。报价阶段的预计计划不混作正式期次。
- 还款详情保留唯一的“前往借贷广场”导航，到对应项目并定位原笔及所选期次，见[详情前往借贷广场与返回](#f-mc-09)。
- 本期应还与还款上链确认中、当前未结清逾期期次须同时可发现，不能因精简而遗漏。

业务状态关系见[还款期次业务状态（ST-MC-03）](./02-我的控制台-流程图与状态机.md#st-mc-03)，各阶段入列见[申请、报价、还款入列与期次定位（FL-MC-05）](./02-我的控制台-流程图与状态机.md#fl-mc-05)。

<a id="d-mc-141"></a><a id="d-mc-142"></a><a id="d-mc-143"></a><a id="d-mc-170"></a>还款开放与链上还款（D-MC-141～D-MC-143、D-MC-170）：普通利息期和含本金末期均到应还日 00:00 UTC 才开放还款；提前三日只是还款模块的准备提醒。还款在借贷广场办理，规则沿[出账地址、余额校验与授权并还款（F-LS-67）](../08-借贷广场-链上还款/01-链上还款-PRD.md#f-ls-67)：资产方选定出账地址、签名“授权并还款”即提交本期还款，平台执行钱包随即执行链上还款，上链成功本期即结清，不需要资金方确认。签名提交即冻结本期逾期天数；链上明确失败等于本期没有提交，本期回到待还款，冻结作废，逾期按应到时点连续计算。本笔有一期还款上链确认中时，结果回写前不能提交本笔其他期次。链上还款没有办理时限，控制台不显示截止时刻、剩余时长、超期标记或倒计时。

已确认计息口径为按季、单利 ACT/360、算头不算尾，起息日取放款成功时间的 UTC 日期（FD-47）；每期利息（USDT）独立两位四舍五入。控制台展示还款模块的金额结果，不新增计息算法。无宽限期、罚息、提前还款、部分还款或跨期合并提交；资金方没有确认、异议或驳回环节。

<a id="d-mc-203"></a>当前逾期与历史（D-MC-203）：应还日次日 00:00 UTC 仍未签名提交（含提交后链上未成功）才发生逾期，首个逾期自然日为 1 天；签名提交冻结该期天数，结清后历史天数仍保留。当前业务逾期标记（FD-44）覆盖所有“曾逾期且未结清”的期次，包含待还款及逾期后已签名、还款上链确认中的期次；相关逾期期次全部结清后才清除，不必等未来正常期次结清。当前最早逾期期次及最长天数只取未结清逾期集合，无当前集合时不伪造 0 天逾期。

还款上链确认中的逾期期次同时呈现“已签名提交、链上确认中、冻结逾期天数、仍未结清”，不提示资产方重复提交同一期。等待链上结果不恢复逾期天数增长、不增加罚息，控制台不代办、不减少本金或释放质押。列表的包含逾期筛选、行级提醒、待处理提示与详情同源。

| 期次条件 | 用户看到的事实 | 当前处理方 |
| --- | --- | --- |
| 尚未到应还日，待还款 | 应还日、金额币种与还款开放时点 | 未来待还，不标为待处理，不表述为当前已可办理 |
| 已开放，尚未逾期，待还款；本笔没有还款上链确认中的期次 | 本期待还、金额币种与应还日 | 资产方，该笔业务标为资产方待处理“还款” |
| 已逾期，待还款；本笔没有还款上链确认中的期次 | 待还款、持续累计的逾期天数、业务当前逾期标记 | 资产方，该笔业务标为资产方待处理“还款” |
| 已开放待还款，但本笔另有一期还款上链确认中 | 待还期次与链上确认中的期次同时可见 | 等待链上结果，不标为待处理 |
| 已签名提交，未曾逾期，还款上链确认中 | 期次、提交时间、已等待时长、链上确认中、仍未结清 | 等待链上结果，不标为待处理；资产方不能重复提交 |
| 逾期后签名提交，还款上链确认中 | 期次、提交时间、已等待时长、冻结逾期天数、仍未结清及业务当前逾期 | 等待链上结果，不标为待处理；不提示资产方补交 |
| 链上明确失败，回到待还款 | 待还款，逾期按应到时点连续计算 | 已开放时为资产方，该笔业务重新标为待处理“还款” |
| 已结清 | 已结清、结清时间及原有历史逾期天数 | 无当前办理；指定该期时仍读该期结果 |

资金方在还款信息中只读查看上述事实，没有任何待处理事项；链上还款成功即视为资金方已收到本期还款。

<a id="d-mc-193"></a>本期与链上确认中并存（D-MC-193）：同笔“本期应还”取还款模块既定顺序下第一条待还款期次：逾期在前、未到期在后，依应还日、放款成功时间、业务编号、期次序号升序；只在本笔内选取。本笔有还款上链确认中的期次时，列表须同时可发现该期，详情保留该期且不被下一待还期取代。同笔多个期次不重复增加列表记录。

业务列表默认放款成功时间倒序；支持还款中／已结清、计划生成中、包含待还款／还款上链确认中／已结清期次、是否存在逾期期次筛选。期次筛选表示该业务“包含符合条件的期次”，按业务去重，进入详情标明匹配期次。支持按本期应还日排序，无候选的业务置后。包含逾期筛选同时匹配逾期后已签名、还款上链确认中的期次。

原控制台期次入口继续定位原 FD-01 与 RP-01，在同笔详情展示该期当前结果；即使本期已变也不静默跳期。在借贷广场完成或取消后返回同笔详情并保留原选定期次，再返回列表仍是同一条业务记录。

### 3.6 我的报价（F-MC-07）

仅资金方查看本机构的报价。一条记录一笔本机构已签名“授权并报价”的报价：报价上链确认中的（尚无融资业务编号，以融资申请编号与签名发出时间识别），以及授权上链成功、已生成融资业务编号（FD-01）的报价；授权上链失败未形成报价的不列入（用户 2026-10-23 裁定，[Q-MC-65](#q-mc-65)）。报价第一步只填写信息、不形成任何记录，不在控制台出现。同一申请先后报价各自保留，不按融资申请编号合并。

列表直接识别：项目名称、资产方企业名称、融资申请编号、融资需求金额（USDT）、结算币种、年化融资利率、报价结果或当前业务阶段、适用的已锁定时长或已等待时长、本笔链上授权状态。按业务状态筛选，默认报价时间倒序（报价上链确认中按签名发出时间）。无报价时说明尚未提交报价，不在列表空态给借贷广场入口，不复制全平台可报价需求列表。

<a id="quote-detail"></a>
**报价详情（P-MC-07）。** 展示客户的融资需求、本机构的报价、报价结果与本笔链上授权状态四部分：

| 内容 | 规则 |
| --- | --- |
| 头部识别 | 项目名称（FP-02）作为详情标题，同时可读资产方企业名称和报价结果；同名项目靠下方编号区分 |
| 客户融资需求 | 融资需求金额（USDT，即报价的融资金额 QT-03）；可复制的融资申请编号（FP-28） |
| 本机构报价 | 结算币种（QT-02）、年化融资利率（QT-06）、报价时间（QT-09，报价上链确认中显示“尚未生成”）；可复制的融资业务编号（FD-01，报价上链确认中显示“尚未生成”） |
| 报价结果 | 报价上链确认中：签名发出时间与已等待时长，结果长期未知时说明“链上结果待核实，请联系平台客服人员”。待接受：锁定起点与已锁定时长（FD-13）。资产方已签名接受、链上放款处理中：已等待时长，说明“资产方已接受，链上放款处理中”。已接受（链上放款成功）：放款成功时间（FD-40）、可复制的放款编号（LN-01）、放款币种与金额（LN-03、LN-04）与当前业务阶段（还款中、已结清），可进入同笔还款详情。已拒绝：拒绝时间与原因（FD-11，有值时）。报价已失效：失效时间（FD-17）与原因（FD-15） |
| 本笔链上授权 | 链上授权状态（授权处理中／已授权／撤销处理中／已撤销／已使用，沿[本笔授权状态（ST-CR-04）](../06-借贷广场-授信报价与接受拒绝/02-授信报价与接受拒绝-流程图与状态机.md#st-cr-04)），可进入[链上授权](#f-mc-14)清单中本笔对应的记录；撤销在该清单办理，报价详情不另设撤销入口 |

- 汇率快照、还款类型、最终还款日、预计还款计划、项目风险、授信摘要、报价历史、还款收款地址，以及链上放款记录中的资产方收款地址与交易标识，不在控制台报价详情展示，在借贷广场原融资申请详情阅读；报价详情保留唯一的“前往借贷广场”导航，到对应项目并定位原申请与原报价。

<a id="d-mc-144"></a><a id="d-mc-96"></a>报价锁定（D-MC-144、D-MC-96）：待接受报价须说明何时起锁定、已锁定多久。**报价一经授权上链成功即锁定本轮需求，没有有效期、截止时刻、剩余时间、倒计时或临期强调**，也没有续期、展期与宽限；平台不因时间流逝改变结论或释放占用。已锁定时长自报价成功起累计，接受成功、拒绝或连带失效后停止并转为历史结果。“报价已失效”只来自所属融资需求因项目到期或质押水位不足终结的连带失效；原因无值时不编造说明，中性表达，不给机构负面标签。

**资金方提交报价后不能撤回**：等待资产方处理的记录没有撤回、修改、展期或催办动作；退出路径只有资产方拒绝或所属需求终结，见[既定业务限制](#limits)。报价成功后资金方可以在[链上授权](#f-mc-14)清单撤销本笔放款授权，但撤销不是撤回报价：本笔仍为待接受，资产方此后不能接受、只能拒绝。等待资产方处理、报价上链确认中都不标为资金方待处理。

#### 撤销授权（D-MC-214）

**可以撤销的情形。**

| 授权与业务情形 | 能否撤销 | 撤销前必须同时可见的后果说明 |
| --- | --- | --- |

| 放款授权，资产方已签名接受、链上放款处理中 | 不能，说明放款正在执行 | — |
| 放款授权，已使用（链上放款成功后的还款中、已结清） | 不能，说明授权已按本笔放款使用 | — |
| 质押授权，已授权，且该地址没有涉及该发行合约的质押上链处理中 | 能 | 撤销后这份质押合约不能再调取该地址在该发行合约下的代币；已在合约内的代币不受影响，解押与提取照常；以后从该地址质押该发行合约的代币时须重新授权，使用这份质押合约的其他项目同样如此 |
| 质押授权，该地址有涉及该发行合约的质押上链处理中 | 不能，说明等待质押结果 | — |
| 任一授权处于撤销处理中或已撤销 | 不能重复发起 | — |

**办理规则。**

- 撤销须由授权地址（放款地址或持有地址）在钱包中签名并发送交易；该地址可以与当前登录地址不同，钱包当前不是该地址时提示切换。签名与登录无关，签名前后登录状态不变。平台不代签、不代付，gas 由授权所属企业承担，失败已产生的不退。
- 点击即唤起钱包，钱包内的签名就是最终确认，不另设确认弹窗或勾选。授权地址、被授权合约、授权范围（放款授权为币种与金额，质押授权为代币发行合约）、本次预估 gas 与上表的后果说明须与撤销主动作同时可见。
- 放款授权只收回本笔的授权额度；同一放款地址对同一放款合约仍有其他待接受报价时，保留这些报价所需的授权额度。
- 提交前按最新事实重新核对仍可撤销；不满足时不唤起钱包，就地说明当前结果。
- 撤销不改变任何报价或项目的业务结论，不释放或增加任何占用；不发送站内信，不是待处理事项。
- 资产方看不到资金方的放款授权记录，资金方看不到资产方的质押授权，其他企业与机构都不能查看或办理；直接访问统一不可访问。

| 撤销结果 | 授权与后续 | 用户看到什么 |
| --- | --- | --- |
| 成功 | 链上授权状态为已撤销；不能再次撤销 | 完成时间、链上凭证与实际 gas |
| 明确失败 | 仍为已授权，可以重新撤销 | 可读原因、是否已产生 gas 及金额 |
| 未签名、取消或钱包不可用 | 未发生链上操作、未产生 gas | 说明本次未撤销 |
| 处理中或结果未确认 | 撤销处理中，不能重复发起 | 已等待时长与已知 gas，未知标“待核实”；长期未知提示“链上结果待核实，请联系平台客服人员” |

- 重复点击、刷新或重复提交同一次撤销，链上只产生一笔交易。
- 待接受报价的放款授权被撤销后（含平台外撤销），资产方融资项目记录显示“资金方已撤销链上授权，暂不能接受，可拒绝”，“处理报价”事项照常标记；资产方接受被拦下的结果与对资金方的提醒沿[发起前的校验](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#accept-precheck)。
- 待接受时撤销放款授权、在本平台撤销质押授权，依赖授信报价模块与融资需求与代币质押模块同步规则，见[外部依赖](#dep-revoke-sync)。

流程见[撤销授权（FL-MC-08）](./02-我的控制台-流程图与状态机.md#fl-mc-08)，状态见[链上授权记录状态（ST-MC-07）](./02-我的控制台-流程图与状态机.md#st-mc-07)。

<a id="f-mc-08"></a>
### 3.8 待处理提示与行级提醒（F-MC-08）

控制台不设独立的待办模块。本企业当前需要处理的事项直接标在对应业务清单的记录上：清单分类标签显示待处理记录数，清单可以“只看待处理”，记录上写明要处理什么、并可前往借贷广场办理。所有记录仍由行级提醒显示状态、当前处理方和风险。两者都由业务事实自动得出，不能手动标记完成。参见[待处理提示与行级提醒（FL-MC-03）](./02-我的控制台-流程图与状态机.md#fl-mc-03)。

<a id="todo"></a><a id="d-mc-212"></a>
#### 待处理事项（D-MC-212）

适用角色与前提：已确定企业主体的资产方。报价与放款合为一步、还款上链成功即结清后，资金方没有需要在借贷广场办理的事项，当前没有待处理事项类型，各分类不显示待处理数量与“只看待处理”。

- 待处理事项只收本企业是当前处理方、且现在就能在借贷广场办理的事项。等待对方处理、等待链上结果、尚未开放的未来期次、只读历史都不是待处理事项。
- 每个待处理事项只归入一个清单分类中的一条记录，不在其他分类重复标记；同一笔业务出现在其他分类时只按状态显示。
- 待处理事项按企业主体共享，进入、从借贷广场返回或浏览器刷新当前网址时重新取得；条件不满足即不再标记，新满足的自动标记。没有手动完成、忽略、归档、指派或催办动作。
- 只显示已发生的事实，例如已逾期天数、已锁定时长，**不显示截止时刻、剩余时长或倒计时**。
- 控制台不为待处理事项出现或消失发送消息。

<a id="todo-types"></a>
**事项类型与归属。** 编号沿用原行级提醒编号，缺号不代表遗漏。

资产方：

| 事项（编号） | 产生条件 | 标在哪条记录 | 消失条件 |
| --- | --- | --- | --- |
| 处理报价（<a id="t-mc-01"></a>T-MC-01） | 本企业融资申请有待接受的报价，且没有链上放款处理中；链上放款明确失败后本笔回到待接受时重新产生 | 融资项目分类中该申请所属的项目 | 资产方签名接受且链上放款处理中或成功、资产方拒绝，或所属需求终结 |
| 追加质押（<a id="t-mc-15"></a>T-MC-15） | 项目质押情况为质押不足 | 融资项目分类中该项目 | 质押不足解除 |
| 提取代币（<a id="t-mc-17"></a>T-MC-17） | 项目内有已释放、尚未提取的代币 | 融资项目分类中该项目 | 该项目没有待提取的代币 |
| 修改并重新提交项目（<a id="t-mc-18"></a>T-MC-18） | 项目审核被退回，状态为已退回 | 融资项目分类中该项目 | 项目重新提交或关闭 |
| 还款（<a id="t-mc-05"></a>T-MC-05、<a id="t-mc-06"></a>T-MC-06） | 本笔有已到应还日 00:00 UTC、尚未签名提交的待还款期次（含链上明确失败后回到待还款的期次），且本笔没有还款上链确认中的期次 | 还款信息分类中该笔业务；指向本笔第一条已开放的待还款期次（顺序沿[本期与链上确认中并存](#d-mc-193)） | 本笔已没有已开放且未提交的待还款期次，或本笔有期次进入还款上链确认中 |

- 处理报价期间资金方放款地址的授权被撤销或余额不足、暂不能接受时，资产方仍可拒绝，事项照常标记；授权已撤销时记录另说明“资金方已撤销链上授权”，余额不足的原因在借贷广场办理时给出。
- 代币列表、授信明细、授信汇总、我的报价、链上授权、资金方的还款信息都没有待处理事项。

不是待处理事项的：资金方报价等待资产方处理（<a id="t-mc-11"></a>T-MC-11，只在我的报价记录显示状态与已锁定时长）；报价上链确认中、链上放款处理中、还款上链确认中、发布或改额冻结处理中、撤下处理中（等待链上结果，只显示事实与已等待时长）；两角色在链上授权清单中撤销授权（可选、无时限，只显示链上授权状态）；可报价的公开需求（<a id="t-mc-10"></a>T-MC-10，由既有借贷广场导航承接）；尚未开放的未来期次；资产方认证未达标（<a id="t-mc-12"></a>T-MC-12，由登录域壳层提示）；资产可信平台应收账款被驳回（<a id="t-mc-13"></a>T-MC-13，归资产可信平台）；资金方机构资料未提交或被驳回（<a id="t-mc-14"></a>T-MC-14，由机构注册引导承接）。

<a id="pending-count"></a>
**分类标签上的数量。**

- 数量为该分类中有待处理事项的记录数，不是事项数：一个项目同时需要处理报价和追加质押算 1 条。
- 按该分类的全部记录计算，不随当前筛选、检索、排序或分页变化；为 0 时不显示数量。
- 只有可能产生待处理事项的分类显示数量：资产方的融资项目与还款信息；资金方没有。
- 控制台不设页面级的待处理总数。分类标签上的数量不是企业统计指标，不与统计张数、业务笔数、列表总数或消息未读数互相替代或相加。

<a id="pending-filter"></a>
**只看待处理。**

- 在可能产生待处理事项的分类中提供“只看待处理”，默认关闭；同时可读该分类的待处理记录数。
- 开启后只显示有待处理事项的记录，与该分类其他筛选和编号检索取交集；列表总数按筛选结果计算。开启、关闭都回到第 1 页，不改变用户所选排序。
- “只看待处理”属于可分享、可刷新恢复的浏览视图，过滤说明与“清除筛选”同样覆盖它；切换到其他分类时不带入。
- 开启后没有结果时说明“当前没有待处理记录”；同时有其他筛选时按“当前筛选未匹配”表达，可清除。
- 从借贷广场处理完返回时，已处理或已进入链上确认中的记录不再匹配，按[浏览闭环](#d-mc-161)说明记录已更新，不保留过期结果凑位置。

<a id="todo-target"></a>
**记录上的提示与前往办理。**

- 有待处理事项的记录标为“待我方处理”，并写出事项名称和适用的关键事实：处理报价写已锁定时长；还款写期次与应还日，已逾期时写逾期天数；追加质押写质押缺口；提取代币写张数与金额。
- 同一记录有多个事项时按以下顺序取第一项提示，并可读到事项数量；全部事项在该记录的详情中可见：已逾期的在前，按逾期天数从多到少；其余按事项发生时间从早到晚。
- 记录提供一个以事项名称命名的动作（例如“处理报价”“还款·第 3 期”），点击后到借贷广场对应项目并定位到该事项的原对象：报价类到原申请与原报价，还款类到原笔及所指期次，质押、提取和退回类到该项目。用户在项目内从既有办理入口发起办理；控制台不代为办理，也不自动提交或唤起钱包。按[待处理归类、计数与去向建议](#q-mc-62)执行、待确认。
- 到达时借贷广场重新核对权限与当前状态；事项已被处理或已变化时显示当前结果，不跳到另一笔业务或新一期。原对象定位暂不支持时显式降级到同一项目并保留原编号，规则同[原对象阅读定位建议](#q-mc-60)。
- 返回控制台时回到原清单视图与所在位置并取得最新事实。
- 待处理判断读取失败时，分类标签不显示数量，“只看待处理”暂不可用并说明可用浏览器刷新当前网址；清单其余信息照常显示，不把失败表达为没有待处理事项。

<a id="d-mc-117"></a><a id="d-mc-173"></a>
#### 行级提醒（D-MC-117、D-MC-173）

- 每类列表记录直接显示状态、当前处理方与适用风险，不进入详情即可发现；状态须有文字，不只靠颜色区分。
- 行级提醒与待处理提示同源：同一事实在记录状态和待处理提示中一致；事项消失时，记录同步显示新状态。
- 等待对方或等待链上结果的事实（例如资金方报价待资产方处理、报价上链确认中、链上放款处理中、还款上链确认中）只显示状态、当前处理方与已等待时长，不标为待我方处理，也没有催办动作。
- 还款列表中待还和还款上链确认中可同时存在，新一期不取代链上确认中的期次，两者都可发现。

<a id="pending-vs-messages"></a><a id="d-mc-162"></a>
#### 与消息中心的分工（D-MC-162）

| | 控制台待处理提示 | 消息中心 |
| --- | --- | --- |
| 回答的问题 | 本企业现在有哪些业务需要处理 | 发生过什么、哪些通知本人还没读 |
| 范围 | 按企业主体共享 | 按本人账号 |
| 怎样消失 | 业务处理完成或条件不再满足时自动消失，没有已读概念 | 本人阅读后变为已读，历史消息保留 |
| 数量 | 分类标签上的待处理记录数 | 未读数 |

- 读信、全部已读都不消除待处理提示；业务处理完成也不把相关消息标为已读。
- 企业有待处理记录而本人未读数为 0、或本人有未读而企业没有待处理记录，都是允许结果；不能为对齐数字而过滤企业业务或增加消息。资金方收到放款、还款到账等通知而控制台没有待处理事项，同样是允许结果。
- 消息中心继续负责业务通知、已读未读和历史查询，不新增待办清单；控制台不复制消息列表。
- 各分类可读到简短说明“业务记录按企业共享，消息未读数按个人统计”。

<a id="d-mc-163"></a><a id="d-mc-164"></a><a id="d-mc-165"></a>消息落点（D-MC-163～D-MC-165）：消息列表、未读提示、已读和未读计数由面客消息中心负责，本页不新增；消息落到本页时按原对象、列表分类与过滤条件接住，旧期次消息在同笔还款详情定位原期次。消息中心或来源模块所称“待办”指其消息语义，控制台待处理范围以本节为准。

<a id="d-mc-205"></a>消息承接（D-MC-205）：控制台不发送或转发消息，来源业务维护事件及收件人，消息中心维护本人信箱。待处理提示与行级提醒出现或消失、统计或逾期天数变化、进入、返回、刷新、筛选、读信、复制、修改授信和撤销授权均不产生消息。通用规则见[消息承接与业务事实](#message-reception)。

<a id="message-reception"></a>
#### 消息承接与业务事实

<a id="mc-nr-01"></a>**唯一发送与承接（MC-NR-01）。** 来源模块拥有其触发、排除、收件、内容与目标规则；控制台没有自己的发送事件或模板。查看当前事实不补发消息，消息中心也不因承接而再发一条。来源发送规则与模板直接查其现行通知册，控制台不维护事件副本。

<a id="mc-nr-02"></a>**业务共享与个人消息（MC-NR-02）。** 企业业务按主体归属、信箱按本人账号判断；本期一个企业一个员工，不新增多人收件或转交。收信不授予项目、地址、凭证或办理权限；归属缺失不广播、不改投，运营/SPV不获得副本。业务正常存在不代表投递已成功。

<a id="mc-nr-03"></a>**重复与历史（MC-NR-03）。** 同一事实重复读取不新增消息、不恢复未读、不改发生时间；新事实由来源区分。历史消息保存当时事实，打开原对象看当前结果；已办完仍可读，不重开旧动作、不切换新业务。已读与业务完成互不代替。

<a id="mc-nr-04"></a>**通知与偏好（MC-NR-04）。** 面客消息中心本期不提供通知偏好开关，控制台不新增开关；消息分类与送达时效沿[共享分类与送达规则](../10-面客消息中心/01-面客消息中心-PRD.md#if-nc-01)。一般事件发生后 60 秒内可见，到点事件自应到时点起最晚 6 分钟；实现与真实送达验证归研发、测试，不据页面演示宣布通过。

<a id="mc-nr-05"></a>**待处理提示、提醒与信箱互不代替（MC-NR-05）。** 控制台的待处理提示与行级提醒反映当前业务事实，没有手动完成或归档，分工见[与消息中心的分工](#pending-vs-messages)。阅读或全部已读不提交、不签名，也不消除待处理提示；业务完成后提示消失、摘要更新，消息可仍未读；等待对方或链上结果不等于本人可办理。还款签名提交后，链上确认中保留冻结逾期与未结清事实。

<a id="mc-nr-06"></a>**原对象与目标（MC-NR-06）。** 来源通知决定其查看或办理目标，不统一绕经控制台。既有目标为控制台时，类型与稳定编号定位原对象，旧期次按原 FD+RP 阅读；原入口指定的已结清期次也须能读到当前结果，不切本期。未登录先认证、每次重新判权、无权或不存在统一说明；刷新和返回保留原对象与来源视图。原对象从控制台再前往来源时遵守[唯一广场导航与原对象阅读](#f-mc-09)。消息目标登记不全时沿消息中心降级，不伪造链接。

来源接入控制台须提供可核验的企业归属、对象类型、稳定编号、当前业务事实与有权项目关联；提供消息时还须在消息中心登记业务类型、分类、接收账号和原目标。缺失不使用假编号、完整地址或私人资料补位；读取失败与对象不存在分开处理。客服邮箱只在适用业务摘要或来源客服出口可得，不进入消息正文。

<a id="f-mc-09"></a>
### 3.9 详情前往借贷广场与返回（F-MC-09）

<a id="d-mc-196"></a>列表不设广场快捷入口（D-MC-196）：控制台两角色所有列表只提供查看详情等浏览操作，列表记录、列表操作及空态中不提供创建项目、发布需求、报价、质押、接受、还款等快捷入口。融资项目记录进入的详情本身就是借贷广场项目详情（见[项目详情复用借贷广场](#d-mc-210)），这是该类记录的详情入口，不是快捷办理入口。前往借贷广场办理的入口只有[待处理记录上的动作](#todo-target)（每条记录一个，以事项命名，只定位原对象、不代为办理）和各详情的唯一导航。[链上授权](#f-mc-14)清单中的[撤销授权](#revoke)是控制台自身的写入动作，不前往借贷广场。既有壳层全局借贷广场导航依原职责保留。

<a id="d-mc-197"></a>详情唯一广场导航（D-MC-197）：代币、还款和报价详情各保留一个“前往借贷广场”（英文“Go to lending marketplace”）业务导航；融资项目详情本身在借贷广场，授信详情不设此导航、改由当前使用记录进入具体业务，链上授权详情不设此导航、改由关联业务进入。该导航进入该对象对应项目的原记录阅读位置，按下表携带已知对象；本项按[原对象阅读定位建议](#q-mc-60)执行、待确认。各内容主题不重复“查看链上放款记录／定稿计划／本轮申请／合同”等广场入口，也不提供去追加、解除、接受、还款等单独动作。返回列表、复制、详情内各内容主题的分别定位、控制台内关联详情和期次阅读等浏览能力保留；不把“仅保留”解释为删除必要阅读能力。

| 当前控制台详情 | 对应融资项目及可用条件 |
| --- | --- |
| 代币 P-MC-02 | 使用代币真实关联且当前主体可访问的项目；无关联的自有代币仍展示，不因无法跳转而排除 |
| 融资项目 P-MC-03 | 不适用：记录直接打开借贷广场项目详情；已明确 FP-28 时定位原申请，未明确时展示该项目当前事实，不猜测历史轮次 |
| 授信 P-MC-04 | 不设导航；授信是一机构×企业，不虚构唯一项目，具体业务从[当前使用记录](#credit-usage)进入对应详情 |
| 链上授权 P-MC-08 | 不设“前往借贷广场”导航；放款授权进入本笔报价详情，质押授权进入关联项目（借贷广场项目详情），一条质押授权关联多个项目时由用户明确选择 |
| 还款 P-MC-06 | 当前 FD 所属 FP-01 与原笔还款阅读位置；已明确 RP 时保留原期，只读定位不自动办理；多个目标由用户明确选择，不默认第一期 |
| 我的报价 P-MC-07 | 当前FD及其FP-28所属FP-01；定位原 FP-28 和 FD 报价阅读结果，不换最新报价；报价上链确认中尚无 FD 时定位原 FP-28 |

<a id="d-mc-194"></a>项目落点（D-MC-194）：唯一目标已确定且可访问时启用上述导航。以下关联项目的零个、多个情形只发生在代币详情：没有关联项目时该导航不可用并说明“暂无关联融资项目”；存在关联但暂无可访问目标时说明“暂无可访问关联项目”，不显示无权项目的名称或编号。关联多项目时，由用户从有权查看的真实关联项目中明确选择一个，未选前该导航不可用，不自动选第一项或最近项目、不增加第二个广场导航目标。关联读取失败与无关联分开表达，按[分页、筛选、排序与刷新恢复](#f-mc-11)用浏览器刷新当前网址重试。不得退化为普通广场列表或创建流程来冒充“对应融资项目详情”，不得借选择项目扩大归属范围。

<a id="d-mc-115"></a>`D-MC-115`、`D-MC-160`：该导航是只读项目导航，其可用性按项目关联、可访问性判定，不因用户没有当前可执行业务或记录已结清而隐藏可读项目。到达广场重新核对权限与最新事实；无权或项目不存在统一“内容不存在或无权访问”，不泄露存在性。原申请、业务或期次已有明确编号时保留只读定位；缺少明确目标时不猜轮次、报价或期次。只读详情不转办，用户需要办理时回到项目既有业务入口，明确选择对象并重新核对权限和当前状态。控制台除修改授信与撤销授权外不包含业务提交。来源业务通知的办理目标按其通知册执行，不改变控制台唯一项目导航及原对象只读定位。消息中心若将既有查看消息落到本控制台，仍只读定位原对象/原期次，再由用户经唯一导航前往项目；不暗中切为办理直达。

原对象不存在或无权时统一不可访问，不替换最新业务、最新轮次或本期。项目可读而来源暂不支持原对象定位时，显式说明只到同一项目，保留原 FP/FD/RP 编号与返回；这是定位能力尚未完成的降级，原对象定位分支按[原对象阅读定位建议](#q-mc-60)待验，不判通过。不得降级到普通广场列表或创建流程。

<a id="d-mc-161"></a>浏览闭环（D-MC-161）：闭环为列表→控制台详情→对应广场项目详情→原控制台详情→来源列表；融资项目为列表→借贷广场项目详情→来源列表；待处理记录为清单→对应广场项目原对象→原清单视图。返回取得当前业务事实，保留原控制台详情类型、稳定对象及原选定申请/期次，再回列表恢复列表分类、筛选、检索、排序、页码、每页数及所在位置。目标不再满足筛选时说明记录已更新并可清除过滤；不保留过期结果凑行号。直接打开详情且无来源时，返回本类型默认列表。详见[从列表经详情到对应广场项目并返回（FL-MC-02）](./02-我的控制台-流程图与状态机.md#fl-mc-02)、[六类详情的访问与返回（FL-MC-04）](./02-我的控制台-流程图与状态机.md#fl-mc-04)及[六类详情与浏览闭环](#f-mc-13)。

<a id="f-mc-10"></a>
### 3.10 准入、空态与异常（F-MC-10）

<a id="d-mc-179"></a>`D-MC-179`：控制台引用当前登录域。两类角色都走统一钱包登录，角色由登录主干自动判定——先查本平台资金方账户，不是则按登录地址向资产可信平台调取该地址对应信息，调取到即为资产方；本页不增加本地密码、邮箱登录或补填邮箱流程，也不再有资产方离站授权环节。未认证仍可只读进入；动作资格由对应业务与认证结果共同决定，不能把旧“T2可点”解释为可绕过认证执行出资。业务签名（授权、撤销授权、接受、还款）与登录无关，不改变当前会话。

资产方会话采用WS-348 `S-1`（一周暂定值，由登录域管理）；资金方采用WS-349 `N-L41`四小时。用户已确认两类不必统一，控制台不再把四小时写成双方共同要求，也不擅自将资产方暂定值宣布定稿。

<a id="d-mc-11"></a>`D-MC-11`：退出、会话过期或账号不可用后立即移除页面已显示的统计、列表和详情信息，菜单消失并回到游客可见视图；须真实移除，不是仅作遮挡。重新进入需按登录域认证。钱包连接变化或切换到其他地址签名不等同退出，控制台以当前有效会话为准。见[准入与聚合视图（FL-MC-01）](./02-我的控制台-流程图与状态机.md#fl-mc-01)、[控制台视图可用状态（ST-MC-04）](./02-我的控制台-流程图与状态机.md#st-mc-04)。

| 情形 | 可观察结果 | 出路 |
| --- | --- | --- |
| 正常加载 | 统计及当前列表分别表达读取中，不先闪现0或他人数据 | 完成后显示本主体结果 |
| 代币真空集合 | 暂无可展示代币；正常统计为0 | 代币发行平台入口使用离站告知；不在本页铸造 |
| 融资项目为空 | 尚未创建项目 | 保留说明；列表不提供借贷广场入口，既有全局导航仍可用 |
| 资产方授信为空 | 暂无机构授信 | 不提供发起授信入口 |
| 资金方授信／我的报价为空 | 尚未授信／尚未报价 | 列表不提供借贷广场入口 |
| 链上授权为空 | 暂无链上授权 | 不提供授权入口；授权随质押或报价在借贷广场办理 |
| 还款为空 | 尚无链上放款成功的业务 | 列表不提供借贷广场入口 |
| 筛选无结果 | 明确为当前筛选未匹配，不称企业无业务 | 清除筛选 |
| 资金方无主体 | 以机构资料引导替代业务数据与统计，不报错 | 按机构资料当前阶段去注册／进度／重提；不允许待审核修改或撤回 |
| 某列表分类或某指标读取失败（`E-MC-01`／`02`） | 仅对应数据显示暂不可用，不把错误当空态；其余可正常读取的数据仍可用 | 文字提示使用浏览器刷新当前网址，不另设刷新或重试动作 |
| 未知动作（`E-MC-04`） | 不猜测、不提供未知业务动作 | 保留正常详情导航 |
| 业务已由对方处理或链上结果已回写（`E-MC-09`） | 下次刷新时状态与当前处理方更新 | 无手动已办操作 |
| 无权、记录不存在（`E-MC-10`） | 不返回、展示相关业务内容，也不区分对象是否真实存在 | 回可访问列表 |

<a id="d-mc-180"></a>`D-MC-180`：必须有可靠的企业主体归属才能显示“我的”数据。认证成功不等于主体归属已就绪；资产方缺少已确认主体映射时，不得按钱包、邮箱或名字猜归属，更不能展示全平台数据。需明确“暂无法取得本企业业务数据”并提示可用浏览器刷新当前网址重试，相关上游能力未就绪不能通过主体隔离验收。

### 3.11 分页、筛选、排序与刷新恢复（F-MC-11）

<a id="d-mc-198"></a>刷新当前网址（`D-MC-198`）：控制台统计、各列表分类、详情及详情内的计划/记录内容一律不提供页内重新取数动作；错误态不以“重试／重新加载／刷新状态”等名称变相保留同类动作。需要更新或重试时，用户使用浏览器刷新当前网址；失败状态可用文字说明此方法。浏览器刷新保留当前列表分类、筛选、只看待处理、编号检索、排序、页码、每页数；详情保留类型、对象、原选定申请/期次及已有来源列表上下文。重新读取后按最新权限与真实结果展示，越界页按MC-04收敛；链接不转让权限，会话失效先处理登录。直接访问无来源的详情依[六类详情与浏览闭环](#f-mc-13)回该类型默认列表分类。正常进入、筛选翻页、从广场返回仍取得所需结果，不要求用户先额外刷新，不新增周期刷新或延长会话。取消该动作不改变数据同步时效及错误/空态区分。见[控制台视图可用状态（ST-MC-04）](./02-我的控制台-流程图与状态机.md#st-mc-04)、[单个详情的可用状态（ST-MC-05）](./02-我的控制台-流程图与状态机.md#st-mc-05)。

控制台列表沿用默认20条、可切20／50／100的分页，显示按当前列表业务粒度计算的总数；还款总数为业务笔数，项目总数为项目数。借贷广场项目内清单每页5条及公开项目列表连续加载，不自动改变本企业跨项目台账分页。当前页码、每页条数与总数须可得。

| 本页可编辑视图字段 | 类型、必填与默认 | 校验和效果 |
| --- | --- | --- |
| 当前列表分类（`MC-01`） | 单选枚举，必有；按角色默认[可见范围](#visibility)所述分类 | 只允许本角色适用分类；非法值或已取消的分类回角色默认，不泄露另一角色视图 |
| 筛选（`MC-02`） | 各功能定义的枚举或所属项目选择，均可不选，默认不限 | 仅支持现有选项；不适用项清除，不解释为业务新状态；筛选变化回第1页 |
| 排序（`MC-03`） | 允许字段＋升／降序；默认按各功能已明确的业务日期/额度规则，时间相同时按稳定对象编号升序 | 金额与日期按精确值；不做金额区间近似排序；换排序回第1页 |
| 只看待处理（MC-06） | 开关，默认关闭；仅在资产方可能产生待处理事项的分类中提供 | 与筛选、编号检索取交集；变化回第1页；切换分类时不带入；规则见[只看待处理](#pending-filter) |
| 编号检索（`MC-05`） | 可选单行文本，默认空；还款信息支持FP-28、FD-01、LN-01的完整编号，我的报价与资金方链上授权支持FP-28、FD-01的完整编号 | 去除首尾空白后按完整编号精确匹配，与当前筛选取交集；变化回第1页，清空恢复筛选结果；未匹配仅提示当前范围无结果，不泄露他方编号是否存在 |
| 页码、每页条数（`MC-04`） | 正整数；默认第1页、20条 | 每页只能20／50／100；非法页码回第1页；超出最新总页数回最后有效页；无结果视为第1页 |

列表默认顺序按用户查账对象统一：代币签发时间倒序、项目创建时间倒序、授信可用额升序、报价时间倒序（报价上链确认中按签名发出时间）、还款放款成功时间倒序、链上授权授权时间倒序；具体期次候选按[本期与链上确认中并存](#d-mc-193)的顺序。本期不再叠加一套隐含“逾期自动提前”改变用户所选排序；关键逾期保持可见，可用对应筛选查找。

<a id="d-mc-147"></a>`D-MC-147`、<a id="d-mc-148"></a>`D-MC-148`：可分享、刷新恢复的视图包含列表分类、筛选、只看待处理、编号检索、排序、页码和每页条数；有过滤时“已按X过滤”说明及清除入口须始终可得。业务动作后返回、浏览器前进后退保留视图并使原目标仍可找到；主动改筛选、排序或翻页从新结果的第一条开始。链接不能转让权限。<a id="d-mc-68"></a>`D-MC-68`：本页只展示当前企业主体数据，允许精确排序，不采用游客区间排序规则。

### 3.12 语言、展示质量及共同约束（F-MC-12）

<a id="d-mc-152"></a>`D-MC-152`、<a id="d-mc-153"></a>`D-MC-153`：默认英文，切换中文时同步字段名称、状态、动作名称、空态、金额日期与说明。采用本平台已确认术语表；质押缺口数值为 `Pledge gap`，对外“已报价待确认”为 `Awaiting quote confirmation`，不能使用内部态 `Awaiting response` 代替。报价、授权与还款的界面名称沿来源模块：

<a id="d-mc-181"></a>`D-MC-181`：面向公开页面的浏览通则不适用于本控制台，不能据此开放控制台数据。页面只呈现可帮助用户判断的金额、差额、时长、结果与出路，不贴字段来源、条款编号、内部公式或实现解释。网络名称一律显示为“Ethereum”，中文界面同样如此，不译为“以太坊”，也不用“ETH”缩写，见[网络](#chain-scope)。

沿用原控制台已规定的目标：企业统计与默认列表分类首批20条完成展示不超过2秒，已取得内容的列表分类切换不超过300毫秒；待处理提示没有另行确认的时效目标。测量条件未在原输入中明确，需与项目整体性能验收条件一致，不凭演示环境宣称达标。

键盘可到达筛选、分页、详情入口、复制、撤销授权与跳转；状态有文字而非只用颜色。

<a id="chain-scope"></a>网络（`D-MC-209`）：本期代币、质押合约、放款与还款合约，以及所有数币地址都只在 Ethereum 上；融资需求与代币质押模块所称“质押链”与“结算收款链”当前都是 Ethereum，两个概念互不决定，控制台不合并为一个“链”字段，也不提供网络筛选或选择。代币持有地址、铸造交易哈希、放款地址、链上授权与撤销授权的交易标识均按 Ethereum 格式；数币地址取企业账户登记的 Ethereum 数币账户，只读不可改选，不取代币的当前链上持有地址或质押合约地址。对应[网络与地址验收（AC-MC-78）](./04-我的控制台-验收.md#ac-mc-78)。

<a id="d-mc-204"></a>日期与金额同源（`D-MC-204`）：业务日期统一UTC，项目期限、授信有效期、应还日、最终还款日、起息日及业务编号内日期不随用户本地跨日或夏令时改变。项目有效期至由资产方创建项目时选定，合约配置完成后只读、不可延期。具体时刻按偏好时区显示并标注；无偏好沿平台既有展示规则。借贷业务编号由来源模块生成，本页不改写；代币状态及原始签发事实继续采用发行平台结果。**报价接受没有办理时限，链上操作以链上结果为准**：本页不展示截止时刻、剩余时长、超期标记、临期强调或倒计时，也不因等待时长改变任何状态、金额、资格与结论。已锁定时长、已等待时长属于对既有事实的如实计时，只向前累计、不设上限、在对应业务被处理或链上结果回写后停止，不得表达为剩余量或超期。授信有效期至仍按 `D-MC-201` 的授信报价模块结果呈现，是授信关系的到期日，不是办理时限。

质押价值（USD）与 USDT 金额按 1 USDT = 1 USD 比较，是平台业务约定，不是外部市场保证（用户 2026-10-22 裁定，Q-LS-28）。结算币种为 USDC 时，结算金额按本笔报价成功时锁定的汇率快照计算（汇率由运营端汇率管理配置，默认 1 USDT = 1 USDC）；控制台不读取当前汇率、不重算，历史已锁定快照不被后续配置追溯覆盖。还款按本期应还本息及该笔快照读取，不用报价本金充当每期应还。必要折算依据或金额缺失显示暂不可用，不用当前行情、其他业务或默认1替缺失值。代币签发价值是发行侧独立事实，不按本规则重估资产。

数字千分位，金额带币种；USDT 金额展示两位，每期利息独立两位四舍五入且不跨期结转，控制台只展示还款模块结果，不另算利息。USDT/USDC 结算金额的正式位数、最终舍入及尾差统一批准表仍待[数币结算精度（Q-CR-09）](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#q-cr-09)，不把原型两位或代币展示六位当作结算上限，不截断真实付款金额。代币数量两位是另一口径。地址前6后4、交易哈希前10后8并允许依权限复制；完整地址与交易标识从对应广场承接。

既定依赖仅作边界引用：代币发行平台提供只读代币事实及既定同步时效；融资需求与代币质押、授信报价与接受拒绝、链上还款提供融资、质押、报价、链上放款、还款事实与动作结果；WS-348/349负责登录与主体；WS-356负责消息。沿用控制台不自行发起周期业务刷新、不延长会话的约束；用户进入、返回、浏览器刷新当前网址及浏览操作按需取得结果，不以此禁止正常筛选翻页。

<a id="d-mc-188"></a>列表与详情的信息底线（`D-MC-188`）：列表必须保留识别对象、金额币种、状态和当前紧迫事项所需的信息，逾期、质押不足与链上处理中等关键事实不得只有进入详情才能发现。详情补足必要摘要；完整资料归来源阅读，所有还款上链确认中及当前未结清逾期对象仍须可发现。统计业务含义、业务状态、字段权限、授信维度及广场办理资格以对应功能为准；还款列表总数按[还款信息](#f-mc-06)的业务笔数计算。
