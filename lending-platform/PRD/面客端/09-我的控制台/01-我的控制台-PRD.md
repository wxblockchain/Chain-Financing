# 我的控制台 · 功能与业务规则

2026-10-19｜面客端：资产方、资金方｜需求评审稿，建议执行项与外部依赖见末节。

本模块共三册：本册定义功能与业务规则；[流程图与状态机](./02-我的控制台-流程图与状态机.md)表达主要流程；[验收](./04-我的控制台-验收.md)供测试使用。控制台不发送消息，因此没有 03 消息通知册；消息承接规则在本册，具体事件由来源模块维护。编号沿用原值，缺号不代表遗漏。

## 1. 目标与阅读入口

我的控制台帮助资产方和资金方了解本企业跨项目的资产、授信与融资全貌，识别当前进展、处理方和风险，再到对应来源查看完整资料或办理。控制台保留六类只读摘要详情，不保存另一套完整业务档案。

基本原则：

- 企业统计、业务记录和本人消息各有范围；筛选不改变企业统计，读信不办结业务。
- 列表直接提供识别、金额币种、状态、处理方和适用风险；详情补足摘要，完整条款、历史、定稿计划及材料在来源阅读。
- 控制台只能阅读、调整视图、复制允许展示的信息和导航；交易办理、审核与确认在来源模块完成。
- 同一融资业务在报价、放款和还款分类中可以重复出现，但仍是同一笔业务，不叠加成新的融资额。

**一个完整的例子。** 资产方看到一笔业务的上一期已提交待确认、冻结逾期 5 天，下一期待还；进入还款摘要后选择原待确认期次，经唯一广场导航阅读该业务的原期次。来源显示当前结果，资金方仍未确认时资产方不能重复提交；需要本人办理的下一期须从项目既有还款入口选择。完成或取消后可回原控制台详情，再回原筛选列表，最新事实更新且原浏览位置恢复。

本期不新增支付、审核、代确认、授信写入口、账户维护、独立待办对象或计数，也不复制信箱；列表与空态不增加广场快捷入口，页内不增加刷新或重试取数动作，沿用既有全局导航和浏览器刷新能力。控制台不新增反向直达资产广场的能力。

## 2. 角色、信息域与共同业务规则

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

沿用的功能名称“行级提醒”指提醒是业务记录自身的事实、不是独立的待办对象，与其在界面上的位置无关；“列表分类”指按角色适用的业务数据分类，不指定其承载形式。

## 3. 功能需求说明

<a id="f-mc-01"></a>
### 3.1 企业统计（F-MC-01）

资产方看到资产与融资全貌；资金方看到授信与出资全貌。所有指标限定当前主体全部业务，不因当前列表分类、分页或筛选缩成当前页合计。进入页面、从广场返回或浏览器刷新当前网址时更新；同一组数量、金额和从属子项保持同批事实一致。相关流程见[准入与聚合视图（FL-MC-01）](./02-我的控制台-流程图与状态机.md#fl-mc-01)。

| 业务字段／编号 | 类型与业务意义 | 范围、必有值与显示 |
| --- | --- | --- |
| 全部代币张数、代币价值合计 | 非负整数张数、USD金额；本平台快照中属于本企业且符合展示条件的代币总量 | 资产方必有；含失效；资金方不展示；正常空集合为0 |
| 其中已质押代币张数、代币价值合计 | 已进入某个项目质押合约的代币子集；账面金额含失效，且不区分是否已通过审核 | 以“其中”从属于全部代币，不能表达为与总量互斥的两个独立指标（<a id="d-mc-47"></a>`D-MC-47`）。企业口径的“已质押”只说明代币在合约内，与项目口径的[总质押额、待审质押额、有效质押额](#f-mc-03)不是同一个量，不互相替代 |
| 其中已失效张数、金额 | 上述已质押子集中代币已失效的部分 | 必有，并标注“不计入有效质押”；不能用全部代币失效量冒充此子集 |
| 总授信额度、授信笔数（`CR-05`） | USD金额、非负整数；资产方各机构授信／资金方授予各资产方的授信 | 双方可见；沿用授信域统计结果 |
| 已融额度、业务笔数（`FP-13`／`CR-08`） | 资产方为各项目的项目融资余额合计／资金方为本机构授信占用额与未结清融资业务数 | 双方可见；已融额度仍等于项目融资余额，不采用“可融额度＋在途额度”的旧公式，不把在途报价当成已融额度 |
| 剩余可用授信（`CR-11`） | 当前可用授信汇总，USD | 双方可见；不是“还能融资多少”的承诺 |

<a id="d-mc-43"></a>`D-MC-43`、<a id="d-mc-44"></a>`D-MC-44`、<a id="d-mc-126"></a>`D-MC-126`、<a id="d-mc-127"></a>`D-MC-127`：代币价值按各笔签发时既定金额汇总（发行侧代币价值与借贷三币种固定折算是两项事实，不互相改写），并说明“按各笔签发时汇率折算”，不实时换汇。企业口径的已质押账面值不等于任一项目的有效质押价值，不能以简单减失效值强行对平；项目侧还受审核通过与已确认有效质押条件约束。剩余可用授信须同时说明“实际可融金额以发布需求时的核定结果为准”。

项目在途金额、可融金额与可撤回上限不作为控制台的常态指标，只在办理需要时由归属模块当场给出，本页也不展示额度换算规则或公式；有效质押额按 3.3 作为项目指标之一正常展示，两者不冲突。动作受限时仍保留归属模块给出的必要差额、原因与出路（`H-03`），不能为隐藏中间量而删掉用户解决问题所需的信息。

指标失败时仅该组显示暂不可用，提示可用浏览器刷新当前网址重试，不伪装成0；无机构主体按3.10走机构资料引导，不进入正常统计空态。

<a id="token-stat-scope"></a>
整笔代币数量、签发价值和张数按企业归属集合及唯一代币编号计算；多持有方时任一持有方已质押即显示已质押，列出有权关联项目，全部未质押才为未质押。该结果不代表本企业当前可质押份额、已通过审核价值或可融额度；后续份额口径仍见[多持有方代币统计含义](#q-mc-61)。

<a id="f-mc-02"></a>
### 3.2 代币列表（F-MC-02）

仅资产方可见。范围为本平台只读代币域中“属于本企业”的集合，与资产广场是同一套事实的主体过滤视图。从代币记录进入本控制台代币详情 `P-MC-02`；列表不提供借贷广场入口，详情仅按3.9前往关联项目。详情沿用本节字段边界，不因新增详情而开放额外资产资料，不扩展资产广场未约定的反向入口。

<a id="d-mc-195"></a>自己的全部代币（`D-MC-195`）：自己的指当前已确认资产方企业主体，不是当前员工个人、个人钱包或当前选中的融资项目。企业全集不随当前账号的钱包连接变化。默认不限状态及项目，包含跨项目、未关联项目、未质押、已质押、有效及失效的所有可展示代币；不能只从融资项目、已质押记录或发生融资的资产中取子集。按唯一代币编号展示一次，跨页合起来覆盖该集合；“全部”不要求单页取消分页。筛选只改变浏览结果，清除后恢复企业全集，企业统计始终采用未筛选全集及对应子集。代币当前唯一链上持有地址不等于本企业归属，不通过钱包、合约地址或地址变动推断“自己的”范围；本列表仍不新增持有地址或份额信息。资金方仍无代币列表或代币统计；不扩大他企业、机构或员工权限。快照范围与完整性要求继续依D-MC-175/178，不能把未同步、关键缺失或归属未知的数据冒充可展示代币。状态范围见[代币生命周期结果（ST-MC-01）](./02-我的控制台-流程图与状态机.md#st-mc-01)。

<a id="d-mc-175"></a>数据边界（`D-MC-175`）：代币事实由代币发行平台提供，本平台使用已同步快照；不设置运营上架闸门，不在打开控制台时临时访问上游。代币状态、价值取代币事实，质押结果取本平台借贷业务，不能回读上游旧质押结果。资产可信平台的应收账款信息随展示数据到位。来源为WS-350 `D-AM-47`～`D-AM-51`。

<a id="d-mc-178"></a>数据可用性（`D-MC-178`）：代币编号、数量、价值、代币状态、铸造交易哈希、铸造时间任一缺失的记录不进入展示集合、不计入对应统计；本企业归属无法确认时不得展示或计入。非关键项缺失逐项“—”。这是与WS-350 `E-AM-10`同源的集合规则，不能两页一边显示一边统计排除。

已同步新增代币即可见；失效在上游判定当日反映于代币列表、统计及资产广场，代币总量与价值每日至少与上游核对一次。上游同步不可用但本平台仍有可用快照时展示最近可用数据，不清空、不向用户暴露同步诊断；本平台读取也失败则显示失败，提示使用浏览器刷新当前网址，不能用空列表掩盖。不得把“暂未同步”视为允许永久过时上线。

代币列表可筛选代币状态、质押状态、代币类型、所属项目；可按代币价值、账期到期日排序。筛选为交集，默认不限；本期代币类型只有一个取值仍保留该筛选，不新增质押链筛选（本期质押链唯一）或全平台企业选择条件。分页见3.11。真空态说明“本企业暂无可展示的代币”，不把暂无同步数据断言为从未铸造；原资产平台入口改称资产可信平台，采用登录域离站告知，不因进入代币列表自动跳站。

### 3.3 融资项目（F-MC-03）

资产方查看本企业项目、当前融资申请及必要质押和债务摘要；明确指定旧申请的入口保留原编号与当前结果。逐轮历史和办理归借贷广场。关联[从列表经详情到对应广场项目并返回（FL-MC-02）](./02-我的控制台-流程图与状态机.md#fl-mc-02)。

<a id="fp-10"></a><a id="fp-32"></a><a id="fp-12"></a><a id="fp-34"></a>三项质押额与项目质押率（`D-MC-206`）：本册按[字段命名与术语对照表](../../00-字段命名与术语对照表.md)使用融资需求与代币质押模块的现行口径，只读呈现、不另算。**总质押额**为本项目质押合约内全部代币的签发价值合计，含失效代币与尚未通过审核的代币，只展示、不参与准入；**待审质押额**为已在合约内、尚未计入有效质押价值的签发价值合计，包含审核尚未裁定与审核已驳回尚未解押两部分，上链处理中尚未成功的不计入；**有效质押额**＝有效质押价值 × 项目质押率，有效质押价值仍须同时满足审核通过、实际转入成功、发行平台判有效、无对账差异、未撤回预扣。**项目质押率**由资产方创建项目时自填、不超过运营配置的上限，合约部署后锁定终身（已退回时可修改），运营后续调整不影响已部署项目；本期不存在固定 80% 的平台质押率。待审质押额的明细须能区分“审核尚未裁定”与“已驳回未解押”两种状态——前者可等待或自助撤回，后者须自助解押——不能只给一个合计数。三项额度、审核结论与解押动作的业务判断均在融资需求与代币质押模块，控制台只读展示，不新增审核清单、撤回或解押动作。对应[项目指标与质押事实验收（AC-MC-117）](./04-我的控制台-验收.md#ac-mc-117)。

<a id="d-mc-134"></a>`D-MC-134`～<a id="d-mc-136"></a>`D-MC-136`：质押不足的项目须成对给出“质押缺口X USD／需追加资产价值Y USD”、触发日期及可查看的失效代币信息；追加质押由项目详情唯一广场入口到达项目后办理，表述为事实；资金方在本机构相关业务中也能看到该项目质押情况和缺口。提醒没有缓冲倒计时，不暗示追加可以救回已失效需求。需求失效与项目质押情况档位是不同判断：提醒属于项目事实，失效及终结原因属于该轮需求事实，允许“项目质押充足、某轮需求已失效”同时出现。失效后满足条件可重新发布，无冷却，本页不负责重算。

<a id="d-mc-132"></a>`D-MC-132`、<a id="d-mc-159"></a>`D-MC-159`：本人项目如有已释放可提取资产，在该项目记录给出张数、USD金额及查看本项目详情的入口，说明仍需主动完成提取，费用与批量选择在L5操作中明确；不设提取倒计时，不暗示自动回钱包。质押上链、逐笔审核、待审撤回、驳回后自助解押及提取的业务判断与操作均在L5，由资产方用代币持有地址签名发起、gas 自担。当前需求不新增控制台审核清单或审批功能。

项目可按项目状态、质押情况和代币类型筛选；融资申请五值仅用于对应申请的状态展示，不作为项目筛选项。默认创建时间倒序；来源项目内完整申请历史按各轮发布时间倒序，控制台不复制历史清单。空态“尚未创建融资项目”，不在列表空态提供创建／广场快捷入口；用户可使用既有全局借贷广场导航。

<a id="d-mc-200"></a>项目资格与执行异常（`D-MC-200`）：项目状态、到期标记、质押情况及融资资格直接采用L5当前结果。**待放款阶段已没有任何终止出口**，控制台不展示单笔终止结果，也不据此重判项目资格（`D-MC-207` 与[既定业务限制](#limits)）。到期项目不恢复发布/新报价资格，存量继续履约；未到期且未终态须由L5结合剩余债务、在途、有效质押额及质押情况判断，不能在控制台承诺可再融资。旧FD保留，后续新业务沿新编号；单笔结清也不直接等于项目终态。质押情况未知不冒充足额/不足或使原需求自行失效，保留已确认事实并说明暂不可用；相关办理资格由广场按L5/L7核对。

执行长期无结果、跨期、冲突或部分结果待核实，只在适用项目/业务事实处说明“执行结果待核实，请联系平台客服人员”，保留允许展示的原编号及已知结果；未知不当作失败、成功或到账，不恢复重押、不重算新增有效质押。已成立业务释放不因提取未明而回滚；已释放也不等于已回钱包。控制台不新增异常处置、工单、自动升级、补偿、人工改判或运营催办；代币列表仍保持有效/失效及质押二元，不新增执行态，也不把审核结论并进质押状态。真实客服渠道和逐笔结果见末节，不能以演示地址或处理时限承诺补齐。见[项目资格与执行结果阅读（FL-MC-06）](./02-我的控制台-流程图与状态机.md#fl-mc-06)。

<a id="d-mc-189"></a>项目与申请（`D-MC-189`）：融资项目一条记录仍是一个项目（FP-01），不因多轮申请或多笔报价重复入列。摘要保留当前申请（FP-28）、本轮发布时间、金额、五值状态与终结原因；改额保留原编号，再发布生成新轮。无当前申请时说明暂无当前需求，不用 0 或最近历史申请冒充当前。旧入口指定的原申请保留其编号与当前结果，完整逐轮历史在来源项目阅读。

当前报价摘要只在来源权限允许时显示机构全称、年化利率、金额币种、报价时间、锁定起点和已锁定时长；当前有效或已接受报价为空时不以最近拒绝、失效报价补位。授信摘要为本机构对企业的总额与已用额，跨项目共用，详细额度分项见[授信明细／授信汇总](#f-mc-04)。完整报价条款、预计计划、历史与授信协议在原项目对应业务阅读；融资合同不进入平台。预计计划不产生有效 RP，不进入还款列表。衔接见[申请、放款、还款入列与期次定位（FL-MC-05）](./02-我的控制台-流程图与状态机.md#fl-mc-05)。

### 3.4 授信明细／授信汇总（F-MC-04）

资产方名称为“授信明细”，资金方为“授信汇总”。一条记录对应“资金机构×资产方企业”，不按项目拆授信。列表保留授信识别和额度摘要，详情集中展示本节字段，不把一笔授信当成一个项目。

### 3.6 还款信息（F-MC-06）

<a id="d-mc-192"></a>还款列表与详情（`D-MC-192`）：双方按“一笔已确认到账的融资业务一条记录”查看，记录唯一依据为 `FD-01`，以融资申请编号 `FP-28`为主要识别信息，并提供放款编号 `LN-01`与出资机构。三个编号均能检索同一条业务记录；仅成交并进入还款后才是1:1:1，不能扩大到报价阶段。控制台跨项目汇总与广场单项目还款清单使用相同业务粒度，分页总数按业务笔数计算，不按期数重复业务。

到账确认成功即入列，定稿计划生成中也保留已确认业务；列表可见还款中/已结清、计划情况、本期应还或尚无待还期次、适用逾期与待确认情况。生成中不伪造RP编号、期数、应还日期、金额或操作入口；失败给暂不可用及浏览器刷新当前网址的文字指引，不回退确认到账的事实。全部结清仍保留业务结清摘要，完整历史计划在来源可读，不展示0元“本期应还”。

从业务记录进入还款摘要详情（P-MC-06），保留本期应还、所有待确认和当前未结清逾期期次、已还本金/利息、未偿本金与结清事实，账户仅给用途与脱敏摘要。每个相关期次可区分 RP、序号、应还日、应还金额及结算币种金额、状态、适用逾期天数；待确认还须有 RM 和提交时间，旧入口指定原期时同时给出该期当前结果，即使该期已结清也不切换新期。末期明确含本金。

待确认的逾期期次应同时呈现“已提交、待资金方确认、冻结逾期天数、仍未结清”，不能继续提示资产方补交同一期。等待确认的时间长短不恢复逾期天数增长，不增加罚息，也不由控制台代确认、减少本金或释放项目质押。列表的包含逾期筛选、行级提醒、统计引用与详情同源；金额和占用只按L8正式确认结果更新，利息期确认不当作本金已还。见[还款期次业务状态（ST-MC-03）](./02-我的控制台-流程图与状态机.md#st-mc-03)。

| --- | --- | --- |
| 尚未到应还日，待还款 | 应还日、金额币种与录入开放时点 | 未来待还，不能表述为当前已可办理 |
| 已开放，尚未逾期，待还款 | 本期待还、金额币种与应还日 | 资产方到来源按当前资格登记 |
| 已逾期，待还款 | 待还款、持续累计的来源逾期天数、业务当前逾期标记 | 资产方到来源登记，不在控制台提交 |
| 已提交，未曾逾期，待还款确认 | RP/RM、提交时间、待资金方确认、仍未结清 | 资金方处理；资产方不能重复提交，不产生确认超期 |
| 曾逾期后提交，待还款确认 | RP/RM、提交时间、冻结逾期天数、仍未结清及业务当前逾期 | 资金方处理；不恢复天数增长，不提示资产方补交 |
| 已确认结清 | 已结清、结清时间及原有历史逾期天数 | 无当前办理；原入口仍读该期结果，当前业务标记仅看其他未结清逾期期次 |

<a id="d-mc-193"></a>本期与待确认并存（`D-MC-193`）：同笔“本期应还”取L8既定顺序下第一条待还款期次：逾期在前、未到期在后，依应还日、放款提交时间、业务编号、期次序号升序；只在本笔内选取，不跨到另一业务。可查看其他期次，具体办理仍由广场核对开窗和资格。无待还款期次显示“暂无待还期次”，不伪装为0元或全部结清。

只要该笔还存在待确认期次，列表须同时可发现待确认情况，详情保留每条记录的RP、RM与提交时间，且不被下一待还期摘要取代。多个待确认对象须可区分并明确选择目标；不自动替用户确认第一条。控制台不提供待办计数，也不为同笔每个待确认期次重复增加主列表记录。

业务列表默认到账确认时间倒序；支持还款中/已结清、计划生成中、包含待还款/待确认/已结清期次、是否存在逾期期次筛选。期次筛选表示该业务“包含符合条件的期次”，按业务去重；进入摘要详情标明匹配期次并保留所有待确认及未结清逾期对象，完整计划在来源阅读。筛选不是新增业务状态，未形成期次的业务不能命中期次条件。支持按应还日排序，取本期应还日，无候选业务置后。当前逾期按D-MC-203消费L8事实，筛选包含逾期提交后尚待确认的期次，不能只匹配未提交期次。

原控制台期次直达入口继续定位原 `FD-01 + RP-01`，在同笔详情展示该期当前结果；即使默认本期已变也不静默跳期。在广场完成或取消业务后返回同笔控制台详情并保留来源原选定期次，再返回列表时仍是同一条业务记录；只更新应还与待确认摘要。计划尚未形成、未开窗、已提交待确认、已结清各有明确反馈。

### 3.7 我的报价（F-MC-07）

仅资金方查看本机构已提交报价及其后续业务；列表须可直接识别 `FD-01`、`FP-28`、资产方企业名、项目、融资金额币种和业务状态，详情保留融资金额、结算金额币种、年化利率、还款类型、最终还款日、报价时间（QT-09）、已锁定时长（FD-13）、结果/原因/时间及相关项目风险；完整商务条款与预计计划在来源阅读。字段类型、只读条件沿用3.3、3.5。

业务状态沿用待接受、已拒绝、报价已失效、待放款、待放款确认、还款中、已结清；逾期仍为并行标记，不做独立报价状态。**放款段不再产生“已终止”**，放款段无终止终态，报价仍可有已拒绝或已失效的结果。“报价已失效”只来自所属融资需求因项目关闭、项目到期或质押不足而终结的连带失效，**不再存在按有效期自动到期的失效**。拒绝／失效原因无值时不得编造说明，也不把未取到原因解释为记录有效。

<a id="d-mc-144"></a>`D-MC-144`、<a id="d-mc-96"></a>`D-MC-96`：待接受报价须解释被谁锁定、何时起、已锁定多久。**报价一经提交即锁定本轮需求，没有有效期、截止时刻、剩余时间、倒计时或临期强调**，也没有续期、展期与宽限；平台不因时间流逝改变本笔结论或释放任何占用。已锁定时长自提交成功起累计，接受、拒绝或连带失效后停止累计并转为历史结果。终结报价保留，拒绝显示 `FD-11`原因，连带失效显示 `FD-15`原因和 `FD-17`时间，中性表达，不给机构负面标签。

等待对方处理的记录没有撤回、修改、展期或催办动作——**资金方提交报价后不能撤回**，退出路径只有资产方拒绝或所属需求终结连带失效，见[既定业务限制](#limits)；查看业务详情属于只读导航，可以保留，不能把“无可执行业务动作”误解为禁止查看历史。后续待放款业务从详情按3.9前往对应项目，不继续称为报价待接受。

一条记录一笔本机构成功提交的 `FD-01` 报价业务；同申请先后报价各自保留，不能按FP-28合并掉历史。按业务状态筛选，默认报价时间倒序。无报价时说明尚未提交报价，不在列表空态给借贷广场入口，不在控制台复制全平台可报价需求列表。

<a id="message-reception"></a>
#### 消息承接与业务事实

<a id="mc-nr-01"></a>**唯一发送与承接（MC-NR-01）。** 来源模块拥有其触发、排除、收件、内容与目标规则；控制台没有自己的发送事件或模板。查看当前事实不补发消息，消息中心也不因承接而再发一条。来源发送规则与模板直接查其现行通知册，控制台不维护事件副本。

<a id="mc-nr-02"></a>**业务共享与个人消息（MC-NR-02）。** 企业业务按主体归属、信箱按本人账号判断；本期一个企业一个员工，不新增多人收件或转交。收信不授予项目、账户、凭证或办理权限；归属缺失不广播、不改投，运营/SPV不获得副本。业务正常存在不代表投递已成功。

<a id="mc-nr-03"></a>**重复与历史（MC-NR-03）。** 同一事实重复读取不新增消息、不恢复未读、不改发生时间；新事实由来源区分。历史消息保存当时事实，打开原对象看当前结果；已办完仍可读，不重开旧动作、不切换新业务。已读与业务完成互不代替。

<a id="mc-nr-04"></a>**通知与偏好（MC-NR-04）。** 面客消息中心本期不提供通知偏好开关，控制台不新增开关；消息分类与送达时效沿[共享分类与送达规则](../10-面客消息中心/01-面客消息中心-PRD.md#if-nc-01)。一般事件发生后 60 秒内可见，到点事件自应到时点起最晚 6 分钟；实现与真实送达验证归研发、测试，不据页面演示宣布通过。

<a id="mc-nr-05"></a>**提醒与信箱互不代替（MC-NR-05）。** 控制台只显示当前业务状态、处理方与风险，不提供待办对象、计数或归档。阅读或全部已读不提交、不确认；业务完成后更新摘要，消息可仍未读；等待对方不等于本人可办理。还款提交后保留冻结逾期与未结清事实。

<a id="mc-nr-06"></a>**原对象与目标（MC-NR-06）。** 来源通知决定其查看或办理目标，不统一绕经控制台。既有目标为控制台时，类型与稳定编号定位原对象，旧期次按原 FD+RP 阅读；原入口指定的已结清期次也须能读到当前结果，不切本期。未登录先认证、每次重新判权、无权或不存在统一说明；刷新和返回保留原对象与来源视图。原对象从控制台再前往来源时遵守[唯一广场导航与原对象阅读](#f-mc-09)。消息目标登记不全时沿消息中心降级，不伪造链接。

来源接入控制台须提供可核验的企业归属、对象类型、稳定编号、当前业务事实与有权项目关联；提供消息时还须在消息中心登记业务类型、分类、接收账号和原目标。缺失不使用假编号、完整账户或私人资料补位；读取失败与对象不存在分开处理。客服邮箱只在适用业务摘要或来源客服出口可得，不进入消息正文。

### 3.9 详情前往借贷广场与返回（F-MC-09）

本期 USD、USDT、USDC 固定 1:1:1为平台业务约定，不是外部市场保证。报价、放款按该笔已锁定金额/币种和真实快照，还款按本期应还本息及该笔快照读取，不用报价本金充当每期应还；历史已锁定快照不被本期规则追溯覆盖。必要折算依据或金额缺失显示暂不可用，不用当前行情、其他业务或默认1替缺失值；固定规则的外部行情不可用不改变本笔已有事实。代币签发价值是发行侧独立事实，不按本规则重估资产。

数字千分位，金额带币种；USD展示两位，USD每期利息独立两位四舍五入且不跨期结转，控制台只展示L8结果，不另算利息。USDT/USDC正式位数、最终舍入及尾差统一批准表仍待Q-CR-09，不把原型两位或代币展示六位当作结算上限，不截断真实付款金额。代币数量两位是另一口径。地址前6后4、交易哈希前10后8并允许依权限复制；银行摘要掩码与数币精度依赖见末节，完整账户付款/对账读取权限已经明确，仍从对应广场承接。

<a id="d-mc-184"></a>共同详情行为（`D-MC-184`）：详情须明确对象类型，完整稳定编号可复制；内容按业务主题组织，区分当前事实、历史记录和缺失项。报价、放款可能沿用同一 `FD-01`，但进入时保留“报价详情／融资放款详情”的阅读侧重点；不能因此显示其他机构报价或另一业务。只读含义、字段权限与数据边界沿对应功能；实际展示范围以上述矩阵为准；详情仍不得展示合同号、发票号、资产影像、内部执行态或机构不该看到的信息。代币铸造哈希的完整性条件不自动变成新增展示字段或外链。

<a id="d-mc-185"></a>详情导航（`D-MC-185`）：统一采用3.9 D-MC-194/197的“前往借贷广场”唯一导航与对应融资项目落点；各详情内容主题不再重复广场入口或业务动作。控制台内选择明确的原申请或期次后，同一项目导航保留该原对象阅读定位，不增加第二个去向。无关联、关联不可读、多项目未选择与读取失败各自说明，不用普通广场链接兜底；失败按D-MC-198使用浏览器刷新。

<a id="d-mc-186"></a>返回与恢复（`D-MC-186`）：从列表进入详情后，详情提供返回来源列表的入口；浏览器后退同样恢复原列表分类、筛选、排序、页码、每页条数和所在位置。进入广场后完成或取消，再返回控制台时先回发起动作的详情，取得最新业务事实；继续返回列表才恢复列表位置。列表不发起广场快捷动作。目标因更新不再匹配筛选时说明记录已更新，可清除过滤查看；不保留过期值凑旧位置。直接打开、刷新或分享详情仍定位同一类型和对象；没有来源列表上下文时，返回该类型对应列表分类的默认视图，不凭空恢复他人的筛选。最新业务已不可访问时按下条处理。

<a id="d-mc-187"></a>详情状态与权限（`D-MC-187`）：详情加载时明确加载中，切换对象不得把上一对象内容当作新对象展示；失败为暂不可用及浏览器刷新当前网址的文字指引，不能写成尚无业务。成功后按真实条件区分“尚无放款记录／尚无还款记录”等局部空内容。不存在、已不属本主体、当前角色不允许的对象统一“内容不存在或无权访问”，提供返回本人可访问列表的出路；不泄露对象存在性。未登录直达先按登录域认证，再回可访问的原详情；协议、主体不明或无主体沿用3.10。会话失效即时移除详情数据；重新认证后重新判定归属，不直接恢复旧敏感内容。正常业务终结不等于对象不可访问。

<a id="d-mc-188"></a>列表与详情的信息底线（`D-MC-188`）：列表必须保留识别对象、金额币种、状态和当前紧迫事项所需的信息，逾期与质押不足等关键事实不得只有进入详情才能发现。详情补足必要摘要；完整资料归来源阅读，所有待确认及当前未结清逾期对象仍须可发现。统计业务含义、业务状态、字段权限、授信维度及广场办理资格以对应功能为准；还款列表总数按3.6业务笔数计算。

业务闭环见[从列表经详情到对应广场项目并返回（FL-MC-02）](./02-我的控制台-流程图与状态机.md#fl-mc-02)和[六类详情的访问与返回（FL-MC-04）](./02-我的控制台-流程图与状态机.md#fl-mc-04)，详情状态见[单个详情的可用状态（ST-MC-05）](./02-我的控制台-流程图与状态机.md#st-mc-05)；对应[六类详情验收](./04-我的控制台-验收.md#ac-section-13)。

## 4. 既定业务限制

以下业务限制沿用[放款与放款确认](../07-借贷广场-放款与放款确认/01-放款与放款确认-PRD.md)、[融资需求与代币质押](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)已入库正文同一口径。此处如实记录其在控制台的可观察后果，供研发与测试知悉，不作为异议保留。

| 限制 | 控制台可观察的业务后果 |
| --- | --- |
| <a id="d-mc-208"></a>`D-MC-208` 平台不再采集与校验收款人名称 | 法币与数币账户均取消收款人名称，原“收款账户须属本企业”的硬校验一并删除。控制台按账户备注名、账号 / IBAN 或收款地址辨识账户，不得以其他字段变相恢复该校验；受益人名称由业务双方在平台外补充 |
| 报价一经提交，资金方无法撤回 | 报价有效期取消后，退出路径仅为资产方拒绝或所属需求因项目关闭、项目到期、质押不足而终结的连带失效。我的报价中的待接受记录没有撤回、修改、展期或催办动作，也不会因等待时间自行终结 |
| <a id="d-mc-207"></a>`D-MC-207` 待放款阶段无终止出口 | 待放款的唯一出口是资金方提交放款。若线下协商结果是不放款，平台侧没有任何动作能终结该笔业务：放款记录持续显示待放款，本项目因“本环节未结束不允许发布新需求”无法另起一轮，对应质押代币持续被占用。控制台如实呈现这些事实，不提供终止入口、不判为异常、不以超期或催办表达 |

同理，待放款确认在资产方确认前也没有其他出口：无时限、无自动确认、无终止，业务停留期间还款计划不生成、两类在途金额持续占用、质押不释放。
