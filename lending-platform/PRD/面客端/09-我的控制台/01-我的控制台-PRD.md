# 我的控制台 · 功能与业务规则

2026-10-21｜面客端：资产方、资金方｜需求评审稿，建议执行项与外部依赖见末节。

本模块共三册：本册定义功能与业务规则；[流程图与状态机](./02-我的控制台-流程图与状态机.md)表达主要流程；[验收](./04-我的控制台-验收.md)供测试使用。控制台不发送消息，因此没有 03 消息通知册；消息承接规则在本册，具体事件由来源模块维护。编号沿用原值，缺号不代表遗漏。

## 1. 目标与阅读入口

我的控制台帮助资产方和资金方了解本企业跨项目的资产、授信与融资全貌：业务清单直接标出本企业现在需要处理的记录，各类列表与详情回答“是哪笔业务、对方是谁、进行到哪一步”，完整资料和业务办理到借贷广场对应项目。控制台只保留借贷广场没有、或需要跨项目汇总的信息；借贷广场已展示的完整资料不在控制台重复。

基本原则：

- 企业统计、业务记录和本人消息各有范围；筛选不改变企业统计和分类标签上的待处理数量，读信不办结业务，也不消除待处理提示。
- 不设独立待办模块：本企业现在就能处理的事项标在对应清单记录上，由业务事实自动产生和消失；等待对方、尚未开放的事项不标为待处理。通知与已读未读仍归消息中心。
- 详情头部先让用户认出对象：报价看项目名称，授信、放款、还款看对方企业名称。详情只保留判断所需的核心信息，完整条款、账户、凭证、历史和计划在借贷广场阅读。
- 融资项目详情直接复用借贷广场项目详情，不在控制台另做一份。
- 控制台唯一的写入动作是资金方修改授信，规则沿用授信报价模块；融资、质押、报价、放款、还款的办理与确认都在借贷广场完成。
- 同一融资业务在报价、放款和还款分类中可以重复出现，但仍是同一笔业务，不叠加成新的融资额。

**一个完整的例子。** 资产方甲进入我的控制台，“融资项目”分类标签显示 1、“还款信息”分类标签显示 1。甲打开还款信息并勾选“只看待处理”，看到资金方丙的一笔业务标着“待我方处理·还款”，写着第 3 期、应还 12,500.00 USD、已逾期 2 天。甲点击该记录上的“还款”，到达借贷广场该项目并定位到第 3 期，从项目的还款入口提交还款后返回控制台：这笔业务不再标待处理，因已不匹配“只看待处理”而提示记录已更新；还款详情头部写着“丙”，第 3 期显示“已提交、待资金方确认”和冻结的逾期 2 天。同一时刻，资金方丙的“还款信息”分类标签出现 1，这笔业务标着“待我方处理·确认收到还款”；丙到借贷广场确认后，提示消失，甲的还款详情显示第 3 期已结清，逾期 2 天作为历史保留。甲读没读过相关站内信，都不影响上述提示。

本期不做：支付、审核、代确认和账户维护；独立待办模块、页面级待办总数，以及待处理事项的手动完成、忽略、归档、指派或催办；授信调低、冻结、停用或删除；复制消息信箱；列表与空态的广场快捷入口；页内刷新或重试取数动作（沿用既有全局导航和浏览器刷新）；反向直达资产广场。

## 2. 角色、信息域与共同业务规则

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

“行级提醒”指列表记录自身显示的业务事实，“待处理提示”指标在记录上的本企业待处理事项，两者都不指定具体界面形态；“列表分类”指按角色适用的业务数据分类，不指定其承载形式。

### 2.1 可见范围

| 角色／条件 | 本页表现 | 业务边界 |
| --- | --- | --- |
| 未登录游客 | 不显示控制台菜单；直达先完成登录再回原目标 | 不泄露控制台个人数据；不能因资产广场公开而开放本页 |
| 已登录未绑定角色 | 沿登录域完成角色判定或资料引导，不展示“我的”敏感集合 | 不以游客公开范围替代企业归属校验 |
| 未完成必要协议同意的受限会话 | 先完成登录域的协议步骤，不展示控制台数据 | 控制台不自建协议确认流程 |
| 已登录资产方 | 本企业主体数据；代币列表、融资项目、授信明细、融资放款信息、还款信息，默认代币列表；后三者中需本企业处理的记录带待处理提示 | 未认证不隐藏控制台菜单；补全提示由登录域提供，具体业务动作由归属模块判权 |
| 已登录资金方 | 本机构数据；我的报价、授信汇总、融资放款信息、还款信息，默认我的报价；放款与还款中需本机构处理的记录带待处理提示 | 不提供代币列表或空的融资项目分类；不新增“可报价融资需求”分类（沿用 `Q-MC-50` 的本期不做范围） |
| 资金方尚无机构主体 | 以机构资料引导替代业务数据，不展示统计数字，不以0充当无主体 | 前往WS-349机构注册；已驳回、待审核的不同引导继续使用登录域结论，不能把所有未认证账号都当成无主体 |
| 运营人员、SPV运营角色 | 无本模块管理视图 | 不因运营身份绕过面客主体归属 |

<a id="d-mc-105"></a>`D-MC-105`、<a id="d-mc-128"></a>`D-MC-128`、<a id="d-mc-137"></a>`D-MC-137`：本期一个企业一个员工账号，业务集合仍按企业归属确定，不新增成员管理、分工或转交；机构不得看到资产方在其他机构的授信与占用，资产方不得看到机构内部备注。共享链接也必须受当前访问者归属约束。

<a id="d-mc-199"></a>本人档案与业务资料（`D-MC-199`）：个人、企业账户档案仅本人可查；企业共享业务视图不等于共享每位员工个人档案，也不向对手方开放完整企业档案、证件、认证材料或私人联系方式。控制台按原字段与当事方权限自动取得必要企业/机构名称、业务条款、金额与账户摘要，不让用户抄写对方已知资料。读取中、未提供、读取失败分别表达，缺项不补假值、不将失败转成手填表单；关键企业归属未确定不得展示“我的”集合。付款、对账所需完整账户按广场本笔权限读取和复制，控制台保持摘要脱敏，不新增档案或账户编辑入口。SPV视同运营，无新增面客视图、代付、代确认或私有资料读取权。消息权限另见[业务共享与个人消息](#mc-nr-02)。

非当事资金方在借贷广场可读[非隐私履约信息](../08-借贷广场-还款计划与还款确认/01-还款计划与还款确认-PRD.md#non-private-performance)，不使其他机构业务进入本机构控制台集合；金额、条款、账户和凭证仍私有，不赋予办理或收信权限。来源重新按当时身份判权。

<a id="d-mc-123"></a><a id="d-mc-157"></a><a id="d-mc-174"></a>待处理数量与其他数字（D-MC-123、D-MC-157、D-MC-174）：控制台不设独立待办模块或页面级待办总数，只在分类标签上显示[待处理记录数](#pending-count)。该数量不与统计张数、业务笔数、列表总数或消息未读数互相替代或相加；未读数仍由消息中心负责。待处理不是新的列表分类，也不改变各列表的记录粒度。

<a id="d-mc-119"></a>只读为主、唯一写入（D-MC-119）：控制台可以读业务事实、改变浏览视图、复制可见信息和跳转；唯一的写入动作是资金方在授信详情[修改授信](#credit-modify)，其规则与结果沿授信报价模块。控制台不录入、审核、提交或确认任何融资、质押、报价、放款或还款业务。同一业务的金额、状态、利息、逾期天数、质押缺口、授信可用额必须与对应广场一致，本页不另定计算口径或修正结果。

<a id="d-mc-130"></a>`D-MC-130`：项目状态、融资业务状态、还款期次状态、融资需求对外状态分别带业务标签，不合成“进行中”等新状态。融资需求对外状态只有“待报价”“已报价待确认”“放款中”“已放款”“已失效／已关闭”五值，末项为合并值，须配终结原因；还款进展不形成第六个对外状态。

金额明确币种，代币价值固定USD；张数、代币数量和金额不是同一量，不互相相加。日期按UTC业务日期；具体时刻按用户偏好时区展示并标注，无偏好沿平台既有展示规则，不能因设备时钟偏差改变。报价接受、放款确认与还款确认均无办理时限；项目有效期、授信有效期、应还日和录入开放时点仍按来源展示。业务字段均只读、不提供默认假值；0仅表示确有零值，缺失不转成0。对方账户按平台已定脱敏规则显示，凭证正文去对应广场查看。

## 3. 功能需求说明

<a id="f-mc-01"></a>
### 3.1 企业统计（F-MC-01）

资产方看到资产与融资全貌；资金方看到授信与出资全貌。所有指标限定当前主体全部业务，不因当前列表分类、分页或筛选缩成当前页合计。进入页面、从广场返回或浏览器刷新当前网址时更新；同一组数量、金额和从属子项保持同批事实一致。相关流程见[准入与聚合视图（FL-MC-01）](./02-我的控制台-流程图与状态机.md#fl-mc-01)。

| 业务字段／编号 | 类型与业务意义 | 范围、必有值与显示 |
| --- | --- | --- |
| 全部代币张数、代币价值合计 | 非负整数张数、USD金额；本平台快照中属于本企业且符合展示条件的代币总量 | 资产方必有；含失效；资金方不展示；正常空集合为0 |
| 其中已质押代币张数、代币价值合计 | 已进入某个项目质押合约的代币子集；账面金额含失效 | 以“其中”从属于全部代币，不能表达为与总量互斥的两个独立指标（<a id="d-mc-47"></a>`D-MC-47`）。企业口径的“已质押”只说明代币在合约内，与项目口径的[总质押额、有效质押额](#f-mc-03)不是同一个量，不互相替代 |
| 其中已失效张数、金额 | 上述已质押子集中代币已失效的部分 | 必有，并标注“不计入有效质押”；不能用全部代币失效量冒充此子集 |
| 总授信额度、授信笔数（`CR-05`） | USD金额、非负整数；资产方各机构授信／资金方授予各资产方的授信 | 双方可见；沿用授信域统计结果 |
| 已融额度、业务笔数（`FP-13`／`CR-08`） | 资产方为各项目的项目融资余额合计／资金方为本机构授信占用额与未结清融资业务数 | 双方可见；已融额度仍等于项目融资余额，不采用“可融额度＋在途额度”的旧公式，不把在途报价当成已融额度 |
| 剩余可用授信（`CR-11`） | 当前可用授信汇总，USD | 双方可见；不是“还能融资多少”的承诺 |

<a id="d-mc-43"></a>`D-MC-43`、<a id="d-mc-44"></a>`D-MC-44`、<a id="d-mc-126"></a>`D-MC-126`、<a id="d-mc-127"></a>`D-MC-127`：代币价值按各笔签发时既定金额汇总（发行侧代币价值与借贷三币种固定折算是两项事实，不互相改写），并说明“按各笔签发时汇率折算”，不实时换汇。企业口径的已质押账面值不等于任一项目的有效质押价值，不能以简单减失效值强行对平；项目侧还受有效质押条件约束。剩余可用授信须同时说明“实际可融金额以发布需求时的核定结果为准”。

项目在途金额、可融金额与可撤回上限不作为控制台的常态指标，只在办理需要时由归属模块当场给出，本页也不展示额度换算规则或公式；有效质押额按 3.3 作为项目指标之一正常展示，两者不冲突。动作受限时仍保留归属模块给出的必要差额、原因与出路（`H-03`），不能为隐藏中间量而删掉用户解决问题所需的信息。

指标失败时仅该组显示暂不可用，提示可用浏览器刷新当前网址重试，不伪装成0；无机构主体按3.10走机构资料引导，不进入正常统计空态。

<a id="token-stat-scope"></a>
整笔代币数量、签发价值和张数按企业归属集合及唯一代币编号计算；多持有方时任一持有方已质押即显示已质押，列出有权关联项目，全部未质押才为未质押。该结果不代表本企业当前可质押份额、有效质押价值或可融额度；后续份额口径仍见[多持有方代币统计含义](#q-mc-61)。

<a id="d-mc-195"></a>自己的全部代币（`D-MC-195`）：自己的指当前已确认资产方企业主体，不是当前员工个人、个人钱包或当前选中的融资项目。企业全集不随当前账号的钱包连接变化。默认不限状态及项目，包含跨项目、未关联项目、未质押、已质押、有效及失效的所有可展示代币；不能只从融资项目、已质押记录或发生融资的资产中取子集。按唯一代币编号展示一次，跨页合起来覆盖该集合；“全部”不要求单页取消分页。筛选只改变浏览结果，清除后恢复企业全集，企业统计始终采用未筛选全集及对应子集。代币当前唯一链上持有地址不等于本企业归属，不通过钱包、合约地址或地址变动推断“自己的”范围；本列表仍不新增持有地址或份额信息。资金方仍无代币列表或代币统计；不扩大他企业、机构或员工权限。快照范围与完整性要求继续依D-MC-175/178，不能把未同步、关键缺失或归属未知的数据冒充可展示代币。状态范围见[代币生命周期结果（ST-MC-01）](./02-我的控制台-流程图与状态机.md#st-mc-01)。

<a id="d-mc-175"></a>数据边界（`D-MC-175`）：代币事实由代币发行平台提供，本平台使用已同步快照；不设置运营上架闸门，不在打开控制台时临时访问上游。代币状态、价值取代币事实，质押结果取本平台借贷业务，不能回读上游旧质押结果。资产可信平台的应收账款信息随展示数据到位。来源为WS-350 `D-AM-47`～`D-AM-51`。

<a id="d-mc-178"></a>数据可用性（`D-MC-178`）：代币编号、数量、价值、代币状态、铸造交易哈希、铸造时间任一缺失的记录不进入展示集合、不计入对应统计；本企业归属无法确认时不得展示或计入。非关键项缺失逐项“—”。这是与WS-350 `E-AM-10`同源的集合规则，不能两页一边显示一边统计排除。

代币列表可筛选代币状态、质押状态、代币类型、所属项目；可按代币价值、账期到期日排序。筛选为交集，默认不限；本期代币类型只有一个取值仍保留该筛选，不新增质押链筛选（本期质押链唯一）或全平台企业选择条件。分页见3.11。真空态说明“本企业暂无可展示的代币”，不把暂无同步数据断言为从未铸造；原资产平台入口改称资产可信平台，采用登录域离站告知，不因进入代币列表自动跳站。

<a id="d-mc-134"></a><a id="d-mc-135"></a><a id="d-mc-136"></a>质押不足（D-MC-134～D-MC-136）：质押不足的项目在列表成对给出“质押缺口 X USD／需追加资产价值 Y USD”，项目记录标为待处理“[追加质押](#todo-types)”；追加质押在借贷广场项目内办理，上链成功即计入有效质押额。提醒没有缓冲倒计时，不暗示追加可以救回已失效需求。需求失效与项目质押情况是不同判断，允许“项目质押充足、某轮需求已失效”同时出现。资金方在本机构相关业务的借贷广场项目详情中也能看到该项目质押情况和缺口。

<a id="d-mc-132"></a><a id="d-mc-159"></a>待提取（D-MC-132、D-MC-159）：项目有已释放待提取的资产时，列表给出张数与金额，项目记录标为待处理“[提取代币](#todo-types)”；须由资产方主动在借贷广场项目内签名办理，不设倒计时，不暗示自动回到钱包。质押上链、解押和提取的业务判断与操作都在融资需求与代币质押模块。

项目可按项目状态、质押情况和代币类型筛选；需求五值不作为项目筛选项。默认创建时间倒序。空态说明“尚未创建融资项目”，不在列表空态提供创建或广场快捷入口；用户可使用既有全局借贷广场导航。

<a id="d-mc-200"></a>项目资格与执行异常（D-MC-200）：项目状态、到期标记、质押情况及融资资格直接采用融资需求与代币质押模块当前结果，控制台不重判。**待放款阶段已没有任何终止出口**（D-MC-207 与[既定业务限制](#limits)）。到期项目不恢复发布或新报价资格，存量继续履约。质押情况未知时不冒充充足或不足，保留已确认事实并说明暂不可用。执行长期无结果、冲突或部分结果待核实时，列表只说明“执行结果待核实，请联系平台客服人员”，不新增异常处置、工单或执行态；真实客服渠道和逐笔结果见末节。见[项目资格与执行结果阅读（FL-MC-06）](./02-我的控制台-流程图与状态机.md#fl-mc-06)。

<a id="d-mc-189"></a>项目与申请（D-MC-189）：融资项目一条记录仍是一个项目，不因多轮申请或多笔报价重复入列。改额保留原申请编号，再次发布生成新一轮。完整逐轮历史、当前报价条款和授信摘要在借贷广场项目详情的融资申请信息中阅读；预计计划不产生有效期次，不进入还款列表。衔接见[申请、放款、还款入列与期次定位（FL-MC-05）](./02-我的控制台-流程图与状态机.md#fl-mc-05)。

<a id="f-mc-04"></a>
### 3.4 授信明细／授信汇总（F-MC-04）

资产方名称为“授信明细”，资金方为“授信汇总”。一条记录对应“一家资金方机构 × 一家资产方企业”的授信关系，不按项目拆分。借贷广场没有独立的授信页面，授信的使用情况和修改入口集中在控制台授信详情。

列表直接识别：对方名称、授信编号、授信状态、授信有效期至、授信额度、授信已用额、可用授信。按授信状态筛选，默认可用授信升序。双方授信列表空态均不提供发起授信或前往借贷广场的入口。

<a id="credit-detail"></a>
#### 授信详情

| 内容 | 资金方看到 | 资产方看到 | 规则 |
| --- | --- | --- | --- |
| 头部识别 | 被授信企业名称（CR-03） | 授信机构名称 | 以对方名称作为详情标题，不以“授信详情”字样代替；同时可读授信状态、授信有效期至和可复制的授信编号（CR-01） |
| 授信使用情况 | 授信额度（CR-05）、授信占用额（CR-08）、在途报价金额（CR-09）、可用授信（CR-11），以及授信已用额（CR-10） | 与资金方相同 | 四个数取授信报价模块当前结果，满足“占用额＋在途报价金额＋可用授信＝授信额度”；已用额是占用额与在途报价金额之和，不是第三种占用。图表形式由设计决定 |
| 当前使用记录 | 本机构对该企业的每笔在途或占用中的融资业务 | 该机构对本企业的每笔在途或占用中的融资业务 | 见下方[当前使用记录](#credit-usage) |
| 授信期限 | 首次授信时间（CR-06）、授信有效期至（CR-07） | 与资金方相同 | 已到期显示“已到期·存量业务照常履约，如需再次报价请先重新授信”，中性表达，不消掉存量占用 |
| 备注（CR-12） | 本机构内部备注 | 不展示 | 空时显示“—” |
| 修改授信 | 提供入口，见[修改授信](#credit-modify) | 不提供 | 资产方只读 |

<a id="credit-usage"></a>
**当前使用记录。**

- 一笔融资业务（FD-01）一条，只列当前仍在使用这份授信的业务：在途报价（待接受、待放款、待放款确认）和授信占用（已放款、尚未还清本金）。已拒绝、报价已失效和已结清的业务不在此列。
- 每条显示：项目名称、融资业务编号、使用类型（在途报价／授信占用）、使用金额（USD）、当前业务阶段。在途报价的使用金额为融资金额（QT-03），授信占用的使用金额为未偿本金（FD-43）。
- 在途报价各条金额合计等于在途报价金额，授信占用各条金额合计等于授信占用额；两者取同一批事实，不一致时以授信报价模块结果为准并说明明细暂不可用，不自行调平。
- 默认按报价时间倒序；记录较多时可分页浏览，不截断。
- 点击一条记录，进入当前角色对应的控制台详情：资金方待接受阶段进入我的报价详情，待放款与待放款确认进入融资放款详情，已放款进入还款详情；资产方待接受阶段进入复用的借贷广场项目详情并定位原申请，其余同资金方。
- 无使用记录时说明“当前没有在途或占用中的业务”。明细读取失败只影响这一部分，授信使用情况的数值照常显示。

<a id="credit-modify"></a><a id="d-mc-211"></a>
#### 修改授信（D-MC-211）

适用角色与前提：本机构已认证资金方，在授信汇总的授信详情中办理；授信关系已存在。资产方没有此入口。修改是对同一授信关系的变更，授信编号不变，规则与留存沿[企业授信（F-LS-38）](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#f-ls-38)和[授信有效期（F-LS-39）](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#f-ls-39)，控制台不另定口径。

| 授信状态 | 可以修改的内容 | 校验与限制 |
| --- | --- | --- |
| 生效中 | 增加授信额度（正数增加额）、后延授信有效期至、备注、本次授信协议 | 额度只增不减；有效期至可保持或后延，不能提前，后延不超过首次授信日或最近一次重新授信日起五年；额度与有效期至至少改变一项（按[授信修改范围](#q-mc-63)建议执行、待确认） |
| 已到期 | 重新授信：带出上一版额度供修改，重新填写授信有效期至，可改备注与本次授信协议 | 额度大于 0 且不得低于当前授信已用额；有效期至默认重新授信日＋1 年，可选＋1 年至＋5 年 |

- 授信额度只能增加或在重新授信时不低于已用额，**不提供调低、冻结、停用或删除授信**。
- 本次授信协议为选填，0～10 份，格式与大小沿授信报价模块；历史协议不被覆盖、不可删除。
- 保存成功立即生效，没有审批；授信详情的使用情况、可用授信和列表、企业统计同步更新。修改不生成报价、不锁定需求、不改变已有的在途与占用。
- 提交时按最新授信状态、已用额和有效期起点重新校验；校验失败定位到具体字段并保留已填内容；提交过程中防止重复提交，重复点击不重复增加额度。
- 授信状态在填写期间发生变化（例如跨过到期日）时，按新状态重新给出可修改内容，不按旧状态保存。
- 每次修改都可追溯：谁代表哪家机构、何时、改变了多少额度与有效期至，来源记为“控制台修改授信”，没有关联项目。
- 修改授信不发送消息，与授信报价模块“授信变更不发信”一致。
- 取消或不保存即结束本次修改，不留下任何变更。

<a id="d-mc-92"></a><a id="d-mc-138"></a><a id="d-mc-160"></a>授信入口边界（D-MC-92、D-MC-138、D-MC-160）：控制台除修改授信外没有“去授信”、首次授信或审批入口；首次授信仍只能在借贷广场报价前的授信核验中办理。授信详情不设“前往借贷广场”导航，也不再要求选择关联项目；查看具体业务从当前使用记录进入。历次授信记录和授信协议的完整阅读沿授信报价模块的权限，控制台不复制。

<a id="d-mc-201"></a>授信期限（D-MC-201）：采用授信报价模块正式结果。五年上限从首次授信日或最近一次重新授信日起算，追加不重置起点。授信有效期至包含所选 UTC 日期，次日 00:00 UTC 起为已到期；按年加遇目标年无同日取该月最后一日。到期只阻止新报价，不消除存量占用。起点资料暂不可用时不编造新起点、不放行延期。

<a id="f-mc-05"></a>
### 3.5 融资放款信息（F-MC-05）

双方只读查看本企业相关融资业务的放款进展。放款只有“资金方登记放款 → 资产方确认到账”两步，都在借贷广场办理。控制台回答“给谁放、放多少、到哪一步、等谁处理”；完整商务条款、两侧收款账户、凭证、交易标识与查验、授信协议都在借贷广场原笔放款详情阅读，控制台不重复。

<a id="d-mc-190"></a>放款入列（D-MC-190）：一条记录一笔已接受报价的融资业务（FD-01），接受成功进入待放款即入列，不等提交放款后才入列。列表直接识别：对方名称、项目名称、融资申请编号、融资业务编号、已生成的放款编号、放款金额与币种、放款状态与当前处理方、接受时间。默认接受时间倒序；可按三个放款状态筛选，支持融资申请编号、融资业务编号及已生成的放款编号检索，同一笔只有一条记录。空态说明接受报价后在此查看。

<a id="loan-detail"></a>
**放款详情。**

| 内容 | 规则 |
| --- | --- |
| 头部识别 | 对方名称作为详情标题：资金方看到资产方企业名称，资产方看到资金方机构名称；让用户一进入就知道这笔款放给谁或由谁放出。同时可读放款状态与当前处理方 |
| 放款金额与币种 | 尚未登记时标为“约定放款金额”，取报价锁定的金额与币种；登记后取原放款记录，不按当前汇率回算 |
| 放款状态与当前处理方（FD-03） | 待放款（资金方处理）、待放款确认（资产方处理）、已放款（无旧放款动作） |
| 两步进展与时间 | 资金方登记、资产方确认各自是否完成；提交时间（LN-06）、确认时间（FD-35）未发生时分别显示“未提交”“未确认” |
| 关联与编号 | 项目名称；可复制的融资申请编号（FP-28）、融资业务编号（FD-01）、放款编号（LN-01）；尚无放款记录时显示“尚无放款记录”，不拿业务编号代替 |
| 后续去向 | 已放款时说明还款进展在还款信息查看，可进入同笔还款详情 |

- 待放款和待放款确认**都没有时限**：不显示截止时刻、剩余时长、超期标记或倒计时，等待不改变状态、金额或确认资格，也不产生催办。
- 放款详情保留唯一的“前往借贷广场”导航，到对应项目并定位原笔放款，见[详情前往借贷广场与返回](#f-mc-09)。

<a id="d-mc-139"></a><a id="d-mc-140"></a><a id="d-mc-169"></a>等待确认的后果（D-MC-139、D-MC-140、D-MC-169）：始终不确认到账时，业务停留在待放款确认，还款计划不生成、两类在途金额继续占用、质押不释放；这些后果、客服出路和交易查验提示在借贷广场原笔放款详情给出，控制台不代为确认，也不承诺平台代为确认。

<a id="d-mc-202"></a>放款结果（D-MC-202）：确认到账后放款记录固定展示“已放款”，还款中、整笔结清及还款逾期在同笔还款信息中读取，不覆盖放款结果。确认到账不采集实收金额，控制台不展示该字段；差额告知沿[到账差额告知（F-LS-58）](../07-借贷广场-放款与放款确认/01-放款与放款确认-PRD.md#f-ls-58)。放款记录提交后不能修改、撤回或新增第二笔；已接受业务不因有效质押额变化或项目到期自动失效。已废止的盖章件核验、要求重传、暂不放款与放款前终止不得以其他名义在本页恢复。

<a id="d-mc-191"></a>账户与材料（D-MC-191）：资产方收款账户与资金方收款账户的名称、用途和完整值沿[融资放款信息及详情（F-LS-49）](../07-借贷广场-放款与放款确认/01-放款与放款确认-PRD.md#f-ls-49)，在借贷广场按本笔当事方权限阅读和复制。控制台不展示账户摘要，不提供任何账户的新增、编辑或删除入口。已提交业务使用本笔当时的账户快照；数币放款和还款使用同一条结算收款链。

<a id="f-mc-06"></a>
### 3.6 还款信息（F-MC-06）

<a id="d-mc-192"></a>还款列表（D-MC-192）：双方按“一笔已确认到账的融资业务一条记录”查看，记录唯一依据为融资业务编号（FD-01）。融资申请编号、融资业务编号、放款编号都能检索到同一条记录；分页总数按业务笔数计算，不按期数重复。列表直接识别：对方名称、项目名称、融资申请编号、业务状态（还款中／已结清）与当前逾期标记、本期应还（期次、应还日、应还金额与币种）或“暂无待还期次”、待确认情况。

到账确认成功即入列，还款计划生成中也保留该业务，不伪造期次编号、期数、应还日期或金额；读取失败给暂不可用及浏览器刷新当前网址的文字指引，不回退确认到账的事实。全部结清仍保留业务，不展示 0 元“本期应还”。

<a id="repay-detail"></a>
**还款详情（P-MC-06）。**

| 内容 | 规则 |
| --- | --- |
| 头部识别 | 对方名称作为详情标题：资金方看到资产方企业名称，资产方看到资金方机构名称；同时可读业务状态、当前逾期标记和项目名称 |
| 本期应还 | 期次序号与总期数、应还日（RP-04）、应还合计及结算金额与币种（RP-08、RP-09）、期次状态（RP-10）、适用逾期天数（RP-11）；末期说明含本金；尚未开放时说明开放时点（应还日 00:00 UTC）；无待还期次显示“暂无待还期次” |
| 待确认期次 | 所有待还款确认的期次逐条可区分：期次、还款记录编号（RM-01）、提交时间（RM-06）、冻结的逾期天数（适用时）、“已提交、待资金方确认、仍未结清” |
| 当前未结清逾期期次 | 本期以外所有曾逾期且未结清的期次逐条可区分，含期次、应还日、金额与逾期天数 |
| 指定期次 | 从待处理提示、消息或旧入口指定某一期（RP-01）时，显示该期当前结果，即使已结清也不切换到新一期 |
| 还款进度 | 已结清期数／总期数、累计已还本金与利息、未偿本金（FD-42、FD-43）、最终还款日（FD-46）；整笔结清时显示结清时间（FD-45） |
| 编号 | 可复制的融资申请编号、融资业务编号、放款编号 |

- 完整定稿还款计划、其他未来期次、已结清历史、逐期本息与计息区间、还款凭证、交易标识和资金方收款账户在借贷广场原笔还款详情阅读，控制台不复制。报价阶段的预计计划不混作正式期次。
- 还款详情保留唯一的“前往借贷广场”导航，到对应项目并定位原笔及所选期次，见[详情前往借贷广场与返回](#f-mc-09)。
- 本期应还与所有待确认、当前未结清逾期期次须同时可发现，不能因精简而遗漏。

业务状态关系见[还款期次业务状态（ST-MC-03）](./02-我的控制台-流程图与状态机.md#st-mc-03)，各阶段入列见[申请、放款、还款入列与期次定位（FL-MC-05）](./02-我的控制台-流程图与状态机.md#fl-mc-05)。

<a id="d-mc-141"></a><a id="d-mc-142"></a><a id="d-mc-143"></a><a id="d-mc-170"></a>还款开放与确认（D-MC-141～D-MC-143、D-MC-170）：普通利息期和含本金末期均到应还日 00:00 UTC 才开放还款信息录入；提前三日只是还款模块的准备提醒。平台只登记还款信息，不执行转账；提交不等于资金方已确认到账。提交只冻结本期逾期天数，其他未提交期次独立计数。**还款确认不设时限**：提交后该期一直停留在待还款确认，直到资金方在借贷广场确认；控制台不显示截止时刻、剩余时长、超期标记或倒计时。

已确认计息口径为按季、单利 ACT/360、算头不算尾，起息日取放款提交时刻的 UTC 日期；USD 每期利息独立两位四舍五入。控制台展示还款模块的金额结果，不新增计息算法。无宽限期、罚息、提前还款、部分还款、跨期合并提交或异议处理中状态。

<a id="d-mc-203"></a>当前逾期与历史（D-MC-203）：应还日次日 00:00 UTC 仍未成功提交才发生逾期，首个逾期自然日为 1 天；提交冻结该期天数，结清后历史天数仍保留。当前业务逾期标记（FD-44）覆盖所有“曾逾期且未结清”的期次，包含待还款及已提交待确认；相关逾期期次全部确认结清后才清除，不必等未来正常期次结清。当前最早逾期期次及最长天数只取未结清逾期集合，无当前集合时不伪造 0 天逾期。

待确认的逾期期次同时呈现“已提交、待资金方确认、冻结逾期天数、仍未结清”，不提示资产方补交同一期。等待确认不恢复逾期天数增长、不增加罚息，控制台不代确认、不减少本金或释放质押。列表的包含逾期筛选、行级提醒、待处理提示与详情同源。

| 期次条件 | 用户看到的事实 | 当前处理方 |
| --- | --- | --- |
| 尚未到应还日，待还款 | 应还日、金额币种与录入开放时点 | 未来待还，不标为待处理，不表述为当前已可办理 |
| 已开放，尚未逾期，待还款 | 本期待还、金额币种与应还日 | 资产方，该笔业务标为资产方待处理“还款” |
| 已逾期，待还款 | 待还款、持续累计的逾期天数、业务当前逾期标记 | 资产方，该笔业务标为资产方待处理“还款” |
| 已提交，未曾逾期，待还款确认 | 期次、还款记录编号、提交时间、待资金方确认、仍未结清 | 资金方，该笔业务标为资金方待处理“确认收到还款”；资产方不能重复提交 |
| 曾逾期后提交，待还款确认 | 期次、还款记录编号、提交时间、冻结逾期天数、仍未结清及业务当前逾期 | 资金方，该笔业务标为资金方待处理“确认收到还款”；不提示资产方补交 |
| 已确认结清 | 已结清、结清时间及原有历史逾期天数 | 无当前办理；指定该期时仍读该期结果 |

<a id="d-mc-193"></a>本期与待确认并存（D-MC-193）：同笔“本期应还”取还款模块既定顺序下第一条待还款期次：逾期在前、未到期在后，依应还日、放款提交时间、业务编号、期次序号升序；只在本笔内选取。只要该笔还有待确认期次，列表须同时可发现待确认情况，详情保留每条记录且不被下一待还期取代；多个待确认对象须可区分，不自动替用户选择第一条。同笔多个待确认期次不重复增加列表记录。

业务列表默认到账确认时间倒序；支持还款中／已结清、计划生成中、包含待还款／待确认／已结清期次、是否存在逾期期次筛选。期次筛选表示该业务“包含符合条件的期次”，按业务去重，进入详情标明匹配期次。支持按本期应还日排序，无候选的业务置后。包含逾期筛选同时匹配逾期后已提交待确认的期次。

原控制台期次入口继续定位原 FD-01 与 RP-01，在同笔详情展示该期当前结果；即使本期已变也不静默跳期。在借贷广场完成或取消后返回同笔详情并保留原选定期次，再返回列表仍是同一条业务记录。

<a id="f-mc-07"></a>
### 3.7 我的报价（F-MC-07）

仅资金方查看本机构已提交的报价。一条记录一笔本机构成功提交的报价业务（FD-01）；同一申请先后报价各自保留，不按融资申请编号合并。列表直接识别：项目名称、资产方企业名称、融资申请编号、融资需求金额（USD）、结算币种、年化融资利率、报价结果或当前业务阶段、适用的已锁定时长。按业务状态筛选，默认报价时间倒序。无报价时说明尚未提交报价，不在列表空态给借贷广场入口，不复制全平台可报价需求列表。

<a id="quote-detail"></a>
**报价详情（P-MC-07）。** 只展示客户的融资需求、本机构的报价和报价结果三部分：

| 内容 | 规则 |
| --- | --- |
| 头部识别 | 项目名称（FP-02）作为详情标题，同时可读资产方企业名称和报价结果；同名项目靠下方编号区分 |
| 客户融资需求 | 融资需求金额（USD，即报价的融资金额 QT-03）；可复制的融资申请编号（FP-28） |
| 本机构报价 | 结算币种（QT-02）、年化融资利率（QT-06）、报价时间（QT-09）；可复制的融资业务编号（FD-01） |
| 报价结果 | 待接受：锁定起点与已锁定时长（FD-13）。已接受：接受时间与当前业务阶段（待放款、待放款确认、还款中、已结清），可进入同笔放款或还款详情。已拒绝：拒绝时间与原因（FD-11，有值时）。报价已失效：失效时间（FD-17）与原因（FD-15） |

- 结算金额、折算比值、还款类型、最终还款日、预计还款计划、项目风险、授信摘要和报价历史不在控制台报价详情展示，在借贷广场原融资申请详情阅读；报价详情保留唯一的“前往借贷广场”导航，到对应项目并定位原申请与原报价。
- 业务状态沿用待接受、已拒绝、报价已失效、待放款、待放款确认、还款中、已结清；逾期是并行标记，不是报价状态。放款段没有“已终止”。

<a id="d-mc-144"></a><a id="d-mc-96"></a>报价锁定（D-MC-144、D-MC-96）：待接受报价须说明何时起锁定、已锁定多久。**报价一经提交即锁定本轮需求，没有有效期、截止时刻、剩余时间、倒计时或临期强调**，也没有续期、展期与宽限；平台不因时间流逝改变结论或释放占用。已锁定时长自提交成功起累计，接受、拒绝或连带失效后停止并转为历史结果。“报价已失效”只来自所属融资需求因项目关闭、项目到期或质押不足终结的连带失效；原因无值时不编造说明，中性表达，不给机构负面标签。

**资金方提交报价后不能撤回**：等待资产方处理的记录没有撤回、修改、展期或催办动作，退出路径只有资产方拒绝或所属需求终结，见[既定业务限制](#limits)。等待资产方处理不标为资金方待处理。

<a id="f-mc-08"></a>
### 3.8 待处理提示与行级提醒（F-MC-08）

控制台不设独立的待办模块。本企业当前需要处理的事项直接标在对应业务清单的记录上：清单分类标签显示待处理记录数，清单可以“只看待处理”，记录上写明要处理什么、并可前往借贷广场办理。所有记录仍由行级提醒显示状态、当前处理方和风险。两者都由业务事实自动得出，不能手动标记完成。参见[待处理提示与行级提醒（FL-MC-03）](./02-我的控制台-流程图与状态机.md#fl-mc-03)。

<a id="todo"></a><a id="d-mc-212"></a>
#### 待处理事项（D-MC-212）

适用角色与前提：已确定企业主体的资产方与资金方；资金方尚无机构主体时以机构资料引导代替，不显示待处理提示。

- 待处理事项只收本企业是当前处理方、且现在就能在借贷广场办理的事项。等待对方处理、尚未开放的未来期次、只读历史都不是待处理事项。
- 每个待处理事项只归入一个清单分类中的一条记录，不在其他分类重复标记；同一笔业务出现在其他分类时只按状态显示。
- 待处理事项按企业主体共享，进入、从借贷广场返回或浏览器刷新当前网址时重新取得；条件不满足即不再标记，新满足的自动标记。没有手动完成、忽略、归档、指派或催办动作。
- 只显示已发生的事实，例如已逾期天数、已锁定时长、已等待时长，**不显示截止时刻、剩余时长或倒计时**。
- 控制台不为待处理事项出现或消失发送消息。

<a id="todo-types"></a>
**事项类型与归属。** 编号沿用原行级提醒编号，缺号不代表遗漏。

资产方：

| 事项（编号） | 产生条件 | 标在哪条记录 | 消失条件 |
| --- | --- | --- | --- |
| 确认报价（<a id="t-mc-01"></a>T-MC-01） | 本企业融资申请收到报价，报价待接受 | 融资项目分类中该申请所属的项目 | 资产方接受或拒绝，或所属需求终结 |
| 追加质押（<a id="t-mc-15"></a>T-MC-15） | 项目质押情况为质押不足 | 融资项目分类中该项目 | 质押不足解除 |
| 提取代币（<a id="t-mc-17"></a>T-MC-17） | 项目内有已释放、尚未提取的代币 | 融资项目分类中该项目 | 该项目没有待提取的代币 |
| 修改并重新提交项目（<a id="t-mc-18"></a>T-MC-18） | 项目审核被退回，状态为已退回 | 融资项目分类中该项目 | 项目重新提交或关闭 |
| 确认到账（<a id="t-mc-03"></a>T-MC-03） | 放款待放款确认 | 融资放款信息分类中该笔业务 | 资产方确认到账 |
| 还款（<a id="t-mc-05"></a>T-MC-05、<a id="t-mc-06"></a>T-MC-06） | 本笔有已到应还日 00:00 UTC、尚未提交的待还款期次 | 还款信息分类中该笔业务；指向本笔第一条已开放的待还款期次（顺序沿[本期与待确认并存](#d-mc-193)） | 本笔已没有已开放且未提交的待还款期次 |

资金方：

| 事项（编号） | 产生条件 | 标在哪条记录 | 消失条件 |
| --- | --- | --- | --- |
| 登记放款（<a id="t-mc-07"></a>T-MC-07） | 报价已接受，业务待放款 | 融资放款信息分类中该笔业务 | 资金方提交放款记录 |
| 确认收到还款（<a id="t-mc-08"></a>T-MC-08） | 期次待还款确认 | 还款信息分类中该笔业务；同笔多期待确认时每期是一个事项，仍标在同一条记录上 | 资金方确认收到该期还款 |

代币列表、授信明细／授信汇总、我的报价三个分类没有待处理事项。不是待处理事项的：资金方报价等待资产方处理（<a id="t-mc-11"></a>T-MC-11，只在我的报价记录显示状态与已锁定时长）、可报价的公开需求（<a id="t-mc-10"></a>T-MC-10，由既有借贷广场导航承接）、尚未开放的未来期次、资产方等待资金方放款或确认、资产方认证未达标（<a id="t-mc-12"></a>T-MC-12，由登录域壳层提示）、资产可信平台应收账款被驳回（<a id="t-mc-13"></a>T-MC-13，归资产可信平台）、资金方机构资料未提交或被驳回（<a id="t-mc-14"></a>T-MC-14，由机构注册引导承接）。

<a id="pending-count"></a>
**分类标签上的数量。**

- 数量为该分类中有待处理事项的记录数，不是事项数：一个项目同时需要确认报价和追加质押算 1 条，一笔还款业务有两期待确认也算 1 条。
- 按该分类的全部记录计算，不随当前筛选、检索、排序或分页变化；为 0 时不显示数量。
- 只有可能产生待处理事项的分类显示数量：资产方为融资项目、融资放款信息、还款信息；资金方为融资放款信息、还款信息。
- 控制台不设页面级的待处理总数。分类标签上的数量不是企业统计指标，不与统计张数、业务笔数、列表总数或消息未读数互相替代或相加。

<a id="pending-filter"></a>
**只看待处理。**

- 在可能产生待处理事项的分类中提供“只看待处理”，默认关闭；同时可读该分类的待处理记录数。
- 开启后只显示有待处理事项的记录，与该分类其他筛选和编号检索取交集；列表总数按筛选结果计算。开启、关闭都回到第 1 页，不改变用户所选排序。
- “只看待处理”属于可分享、可刷新恢复的浏览视图，过滤说明与“清除筛选”同样覆盖它；切换到其他分类时不带入。
- 开启后没有结果时说明“当前没有待处理记录”；同时有其他筛选时按“当前筛选未匹配”表达，可清除。
- 从借贷广场处理完返回时，已处理的记录不再匹配，按[浏览闭环](#d-mc-161)说明记录已更新，不保留过期结果凑位置。

<a id="todo-target"></a>
**记录上的提示与前往办理。**

- 有待处理事项的记录标为“待我方处理”，并写出事项名称和适用的关键事实：确认报价写已锁定时长；确认到账、登记放款写已等待时长；还款写期次与应还日，已逾期时写逾期天数；确认收到还款写期次与提交时间，曾逾期时写冻结的逾期天数；追加质押写质押缺口；提取代币写张数与金额。
- 同一记录有多个事项时按以下顺序取第一项提示，并可读到事项数量；全部事项在该记录的详情中可见：已逾期（含冻结逾期）的在前，按逾期天数从多到少；其余按事项发生时间从早到晚。
- 记录提供一个以事项名称命名的动作（例如“确认到账”“确认收到还款·第 3 期”），点击后到借贷广场对应项目并定位到该事项的原对象：报价类到原申请与原报价，放款类到原笔放款，还款类到原笔及所指期次，质押、提取和退回类到该项目。用户在项目内从既有办理入口发起办理；控制台不代为办理，也不自动提交。按[待处理归类、计数与去向建议](#q-mc-62)执行、待确认。
- 到达时借贷广场重新核对权限与当前状态；事项已被处理或已变化时显示当前结果，不跳到另一笔业务或新一期。原对象定位暂不支持时显式降级到同一项目并保留原编号，规则同[原对象阅读定位建议](#q-mc-60)。
- 返回控制台时回到原清单视图与所在位置并取得最新事实。
- 待处理判断读取失败时，分类标签不显示数量，“只看待处理”暂不可用并说明可用浏览器刷新当前网址；清单其余信息照常显示，不把失败表达为没有待处理事项。

<a id="d-mc-117"></a><a id="d-mc-173"></a>
#### 行级提醒（D-MC-117、D-MC-173）

- 每类列表记录直接显示状态、当前处理方与适用风险，不进入详情即可发现；状态须有文字，不只靠颜色区分。
- 行级提醒与待处理提示同源：同一事实在记录状态和待处理提示中一致；事项消失时，记录同步显示新状态。
- 等待对方的事实（例如资金方报价待资产方处理、资产方等待放款）只显示状态与当前处理方，不标为待我方处理，也没有催办动作。
- 还款列表中待还和待确认可同时存在，新一期不取代前期待确认，两者都可发现。

<a id="pending-vs-messages"></a><a id="d-mc-162"></a>
#### 与消息中心的分工（D-MC-162）

| | 控制台待处理提示 | 消息中心 |
| --- | --- | --- |
| 回答的问题 | 本企业现在有哪些业务需要处理 | 发生过什么、哪些通知本人还没读 |
| 范围 | 按企业主体共享 | 按本人账号 |
| 怎样消失 | 业务处理完成或条件不再满足时自动消失，没有已读概念 | 本人阅读后变为已读，历史消息保留 |
| 数量 | 分类标签上的待处理记录数 | 未读数 |

- 读信、全部已读都不消除待处理提示；业务处理完成也不把相关消息标为已读。
- 企业有待处理记录而本人未读数为 0、或本人有未读而企业没有待处理记录，都是允许结果；不能为对齐数字而过滤企业业务或增加消息。
- 消息中心继续负责业务通知、已读未读和历史查询，不新增待办清单；控制台不复制消息列表。
- 各分类可读到简短说明“业务记录按企业共享，消息未读数按个人统计”。

<a id="d-mc-163"></a><a id="d-mc-164"></a><a id="d-mc-165"></a>消息落点（D-MC-163～D-MC-165）：消息列表、未读提示、已读和未读计数由面客消息中心负责，本页不新增；消息落到本页时按原对象、列表分类与过滤条件接住，旧期次消息在同笔还款详情定位原期次。消息中心或来源模块所称“待办”指其消息语义，控制台待处理范围以本节为准。

<a id="d-mc-205"></a>消息承接（D-MC-205）：控制台不发送或转发消息，来源业务维护事件及收件人，消息中心维护本人信箱。待处理提示与行级提醒出现或消失、统计或逾期天数变化、进入、返回、刷新、筛选、读信、复制和修改授信均不产生消息。通用规则见[消息承接与业务事实](#message-reception)。

<a id="message-reception"></a>
#### 消息承接与业务事实

<a id="mc-nr-01"></a>**唯一发送与承接（MC-NR-01）。** 来源模块拥有其触发、排除、收件、内容与目标规则；控制台没有自己的发送事件或模板。查看当前事实不补发消息，消息中心也不因承接而再发一条。来源发送规则与模板直接查其现行通知册，控制台不维护事件副本。

<a id="mc-nr-02"></a>**业务共享与个人消息（MC-NR-02）。** 企业业务按主体归属、信箱按本人账号判断；本期一个企业一个员工，不新增多人收件或转交。收信不授予项目、账户、凭证或办理权限；归属缺失不广播、不改投，运营/SPV不获得副本。业务正常存在不代表投递已成功。

<a id="mc-nr-03"></a>**重复与历史（MC-NR-03）。** 同一事实重复读取不新增消息、不恢复未读、不改发生时间；新事实由来源区分。历史消息保存当时事实，打开原对象看当前结果；已办完仍可读，不重开旧动作、不切换新业务。已读与业务完成互不代替。

<a id="mc-nr-04"></a>**通知与偏好（MC-NR-04）。** 面客消息中心本期不提供通知偏好开关，控制台不新增开关；消息分类与送达时效沿[共享分类与送达规则](../10-面客消息中心/01-面客消息中心-PRD.md#if-nc-01)。一般事件发生后 60 秒内可见，到点事件自应到时点起最晚 6 分钟；实现与真实送达验证归研发、测试，不据页面演示宣布通过。

<a id="mc-nr-05"></a>**待处理提示、提醒与信箱互不代替（MC-NR-05）。** 控制台的待处理提示与行级提醒反映当前业务事实，没有手动完成或归档，分工见[与消息中心的分工](#pending-vs-messages)。阅读或全部已读不提交、不确认，也不消除待处理提示；业务完成后提示消失、摘要更新，消息可仍未读；等待对方不等于本人可办理。还款提交后保留冻结逾期与未结清事实。

<a id="mc-nr-06"></a>**原对象与目标（MC-NR-06）。** 来源通知决定其查看或办理目标，不统一绕经控制台。既有目标为控制台时，类型与稳定编号定位原对象，旧期次按原 FD+RP 阅读；原入口指定的已结清期次也须能读到当前结果，不切本期。未登录先认证、每次重新判权、无权或不存在统一说明；刷新和返回保留原对象与来源视图。原对象从控制台再前往来源时遵守[唯一广场导航与原对象阅读](#f-mc-09)。消息目标登记不全时沿消息中心降级，不伪造链接。

来源接入控制台须提供可核验的企业归属、对象类型、稳定编号、当前业务事实与有权项目关联；提供消息时还须在消息中心登记业务类型、分类、接收账号和原目标。缺失不使用假编号、完整账户或私人资料补位；读取失败与对象不存在分开处理。客服邮箱只在适用业务摘要或来源客服出口可得，不进入消息正文。

### 3.9 详情前往借贷广场与返回（F-MC-09）

<a id="d-mc-196"></a>列表不设广场快捷入口（D-MC-196）：控制台两角色所有列表只提供查看详情等浏览操作，列表记录、列表操作及空态中不提供创建项目、发布需求、报价、质押、放款、还款或确认等快捷入口。融资项目记录进入的详情本身就是借贷广场项目详情（见[项目详情复用借贷广场](#d-mc-210)），这是该类记录的详情入口，不是快捷办理入口。前往借贷广场办理的入口只有[待处理记录上的动作](#todo-target)（每条记录一个，以事项命名，只定位原对象、不代为办理）和各详情的唯一导航。既有壳层全局借贷广场导航依原职责保留。

<a id="d-mc-197"></a>详情唯一广场导航（D-MC-197）：代币、放款、还款和报价详情各保留一个“前往借贷广场”（英文“Go to lending marketplace”）业务导航；融资项目详情本身在借贷广场，授信详情不设此导航、改由当前使用记录进入具体业务。该导航进入该对象对应项目的原记录阅读位置，按下表携带已知对象；本项按[原对象阅读定位建议](#q-mc-60)执行、待确认。各内容主题不重复“查看放款记录／放款业务／定稿计划／本轮申请／合同”等广场入口，也不提供去追加、解除、接受、还款或确认等单独动作。返回列表、复制、详情内各内容主题的分别定位、控制台内关联详情和期次阅读等浏览能力保留；不把“仅保留”解释为删除必要阅读能力。

| 当前控制台详情 | 对应融资项目及可用条件 |
| --- | --- |
| 代币 P-MC-02 | 使用代币真实关联且当前主体可访问的项目；无关联的自有代币仍展示，不因无法跳转而排除 |
| 融资项目 P-MC-03 | 不适用：记录直接打开借贷广场项目详情；已明确 FP-28 时定位原申请，未明确时展示该项目当前事实，不猜测历史轮次 |
| 授信 P-MC-04 | 不设导航；授信是一机构×企业，不虚构唯一项目，具体业务从[当前使用记录](#credit-usage)进入对应详情 |
| 融资放款 P-MC-05 | 当前 FD 所属 FP-01 并定位原 FD 放款记录，已有 LN 时保留 LN；放款前仍可读原笔，无记录不造 LN |
| 还款 P-MC-06 | 当前 FD 所属 FP-01 与原笔还款阅读位置；已明确 RP/RM 时保留原期，只读定位不自动办理；多个目标由用户明确选择，不默认第一期 |
| 我的报价 P-MC-07 | 当前FD及其FP-28所属FP-01；定位原 FP-28 和 FD 报价阅读结果，不换最新报价 |

<a id="d-mc-194"></a>项目落点（D-MC-194）：唯一目标已确定且可访问时启用上述导航。以下关联项目的零个、多个情形只发生在代币详情：没有关联项目时该导航不可用并说明“暂无关联融资项目”；存在关联但暂无可访问目标时说明“暂无可访问关联项目”，不显示无权项目的名称或编号。关联多项目时，由用户从有权查看的真实关联项目中明确选择一个，未选前该导航不可用，不自动选第一项或最近项目、不增加第二个广场导航目标。关联读取失败与无关联分开表达，按3.11用浏览器刷新当前网址重试。不得退化为普通广场列表或创建流程来冒充“对应融资项目详情”，不得借选择项目扩大归属范围。

<a id="d-mc-115"></a>`D-MC-115`、`D-MC-160`：该导航是只读项目导航，其可用性按项目关联、可访问性判定，不因用户没有当前可执行业务或记录已结清而隐藏可读项目。到达广场重新核对权限与最新事实；无权或项目不存在统一“内容不存在或无权访问”，不泄露存在性。原申请、业务或期次已有明确编号时保留只读定位；缺少明确目标时不猜轮次、报价或期次。只读详情不转办，用户需要办理时回到项目既有业务入口，明确选择对象并重新核对权限和当前状态。控制台不包含业务提交。来源业务通知的办理目标按其通知册执行，不改变控制台唯一项目导航及原对象只读定位。消息中心若将既有查看消息落到本控制台，仍只读定位原对象/原期次，再由用户经唯一导航前往项目；不暗中切为办理直达。

原对象不存在或无权时统一不可访问，不替换最新业务、最新轮次或本期。项目可读而来源暂不支持原对象定位时，显式说明只到同一项目，保留原 FP/FD/RP 编号与返回；这是定位能力尚未完成的降级，原对象定位分支按[原对象阅读定位建议](#q-mc-60)待验，不判通过。不得降级到普通广场列表或创建流程。

<a id="d-mc-161"></a>浏览闭环（D-MC-161）：闭环为列表→控制台详情→对应广场项目详情→原控制台详情→来源列表；融资项目为列表→借贷广场项目详情→来源列表；待处理记录为清单→对应广场项目原对象→原清单视图。返回取得当前业务事实，保留原控制台详情类型、稳定对象及原选定申请/期次，再回列表恢复列表分类、筛选、检索、排序、页码、每页数及所在位置。目标不再满足筛选时说明记录已更新并可清除过滤；不保留过期结果凑行号。直接打开详情且无来源时，返回本类型默认列表。详见[从列表经详情到对应广场项目并返回（FL-MC-02）](./02-我的控制台-流程图与状态机.md#fl-mc-02)、[六类详情的访问与返回（FL-MC-04）](./02-我的控制台-流程图与状态机.md#fl-mc-04)及3.13。

### 3.10 准入、空态与异常（F-MC-10）

<a id="d-mc-179"></a>`D-MC-179`：控制台引用当前登录域。两类角色都走统一钱包登录，角色由登录主干自动判定——先查本平台资金方账户，不是则按登录地址向资产可信平台调取该地址对应信息，调取到即为资产方；本页不增加本地密码、邮箱登录或补填邮箱流程，也不再有资产方离站授权环节。未认证仍可只读进入；动作资格由对应业务与认证结果共同决定，不能把旧“T2可点”解释为可绕过认证执行出资。

资产方会话采用WS-348 `S-1`（一周暂定值，由登录域管理）；资金方采用WS-349 `N-L41`四小时。用户已确认两类不必统一，控制台不再把四小时写成双方共同要求，也不擅自将资产方暂定值宣布定稿。

<a id="d-mc-11"></a>`D-MC-11`：退出、会话过期或账号不可用后立即移除页面已显示的统计、列表和详情信息，菜单消失并回到游客可见视图；须真实移除，不是仅作遮挡。重新进入需按登录域认证。钱包连接变化不等同退出，控制台以当前有效会话为准。见[准入与聚合视图（FL-MC-01）](./02-我的控制台-流程图与状态机.md#fl-mc-01)、[控制台视图可用状态（ST-MC-04）](./02-我的控制台-流程图与状态机.md#st-mc-04)。

### 3.11 分页、筛选、排序与刷新恢复（F-MC-11）

<a id="d-mc-198"></a>刷新当前网址（`D-MC-198`）：控制台统计、各列表分类、详情及详情内的计划/记录内容一律不提供页内重新取数动作；错误态不以“重试／重新加载／刷新状态”等名称变相保留同类动作。需要更新或重试时，用户使用浏览器刷新当前网址；失败状态可用文字说明此方法。浏览器刷新保留当前列表分类、筛选、只看待处理、编号检索、排序、页码、每页数；详情保留类型、对象、原选定申请/期次及已有来源列表上下文。重新读取后按最新权限与真实结果展示，越界页按MC-04收敛；链接不转让权限，会话失效先处理登录。直接访问无来源的详情依3.13回该类型默认列表分类。正常进入、筛选翻页、从广场返回仍取得所需结果，不要求用户先额外刷新，不新增周期刷新或延长会话。取消该动作不改变数据同步时效及错误/空态区分。见[控制台视图可用状态（ST-MC-04）](./02-我的控制台-流程图与状态机.md#st-mc-04)、[单个详情的可用状态（ST-MC-05）](./02-我的控制台-流程图与状态机.md#st-mc-05)。

### 3.12 语言、展示质量及共同约束（F-MC-12）

<a id="d-mc-152"></a>`D-MC-152`、<a id="d-mc-153"></a>`D-MC-153`：默认英文，切换中文时同步字段名称、状态、动作名称、时限、空态、金额日期与说明。采用本平台已确认术语表；质押缺口数值为 `Pledge gap`，对外“已报价待确认”为 `Awaiting quote confirmation`，不能使用内部态 `Awaiting response` 代替。报价接受、放款确认、还款确认分别命名，不混用；已取消的“报价有效期 / Offer validity”“放款确认时限 / Confirmation window”“还款确认时限”不得出现在任何界面文案。“还款类型”与“还款性质”可区分。

<a id="d-mc-181"></a>`D-MC-181`：面向公开页面的浏览通则不适用于本控制台，不能据此开放控制台数据。页面只呈现可帮助用户判断的金额、差额、时限、结果与出路，不贴字段来源、条款编号、内部公式或实现解释。两处链概念分开表述，见[质押链与结算收款链](#chain-scope)。数币USDT／USDC本期在两条结算收款链上均可收款，区块浏览器入口按该笔所属链选用。

沿用原控制台已规定的目标：企业统计与默认列表分类首批20条完成展示不超过2秒，已取得内容的列表分类切换不超过300毫秒；待处理提示没有另行确认的时效目标。测量条件未在原输入中明确，需与项目整体性能验收条件一致，不凭演示环境宣称达标。

键盘可到达筛选、分页、详情入口、复制与跳转；状态有文字而非只用颜色。

<a id="chain-scope"></a>质押链与结算收款链（`D-MC-209`）：本册涉及两个互不决定的链概念，不共用同一个“链”字段，也不合称为“链”。**质押链**是代币与项目质押合约所在链，本期仅 ETH；代币持有地址、铸造交易哈希、链上存证哈希及其区块浏览器入口的格式均按质押链定义，控制台不提供质押链筛选或选择。**结算收款链**是数币收款地址所在链，本期支持 ETH 与 TRON，由[企业账户](../03-企业账户/01-企业账户-PRD.md)模块定义；放款与还款记录的收款地址、数币交易标识及其区块浏览器入口按该笔所属结算收款链分别定义，取所选账户登记的链、只读不可改选。数币收款地址不取代币的当前链上持有地址或质押合约地址。对应[链与账户验收（AC-MC-78）](./04-我的控制台-验收.md#ac-mc-78)。

<a id="d-mc-204"></a>日期与金额同源（`D-MC-204`）：业务日期统一UTC，项目期限、授信有效期、应还日、最终还款日、起息日及业务编号内日期不随用户本地跨日或夏令时改变。项目期限自项目创建时间起算，项目有效期至＝项目创建时间＋项目期限，只读不可延期。具体时刻按偏好时区显示并标注；无偏好沿平台既有展示规则。借贷业务编号由来源模块生成，本页不改写；代币状态及原始签发事实继续采用发行平台结果。**报价接受、放款确认和还款确认没有办理时限**：报价接受、放款确认、还款确认均不设截止，本页不展示截止时刻、剩余时长、超期标记、临期强调或倒计时，也不因等待时长改变任何状态、金额、资格与结论。已锁定时长、已等待时长属于对既有事实的如实计时，只向前累计、不设上限、在对应业务被处理后停止，不得表达为剩余量或超期。授信有效期至仍按 `D-MC-201` 的 L6 结果呈现，是授信关系的到期日，不是办理时限。

本期 USD、USDT、USDC 固定 1:1:1为平台业务约定，不是外部市场保证。报价、放款按该笔已锁定金额/币种和真实快照，还款按本期应还本息及该笔快照读取，不用报价本金充当每期应还；历史已锁定快照不被本期规则追溯覆盖。必要折算依据或金额缺失显示暂不可用，不用当前行情、其他业务或默认1替缺失值；固定规则的外部行情不可用不改变本笔已有事实。代币签发价值是发行侧独立事实，不按本规则重估资产。

数字千分位，金额带币种；USD展示两位，USD每期利息独立两位四舍五入且不跨期结转，控制台只展示L8结果，不另算利息。USDT/USDC正式位数、最终舍入及尾差统一批准表仍待Q-CR-09，不把原型两位或代币展示六位当作结算上限，不截断真实付款金额。代币数量两位是另一口径。地址前6后4、交易哈希前10后8并允许依权限复制；银行摘要掩码与数币精度依赖见末节，完整账户付款/对账读取权限已经明确，仍从对应广场承接。

既定依赖仅作边界引用：代币发行平台提供只读代币事实及既定同步时效；L5～L8提供融资、质押、报价、放款、还款事实与动作结果；WS-348/349负责登录与主体；WS-356负责消息。沿用控制台不自行发起周期业务刷新、不延长会话的约束；用户进入、返回、浏览器刷新当前网址及浏览操作按需取得结果，不以此禁止正常筛选翻页。

### 3.13 六类详情与浏览闭环（F-MC-13）

<a id="d-mc-182"></a>入口与对象（D-MC-182）：两角色所有列表分类的记录都能进入详情：资产方五类（代币、融资项目、授信、放款、还款），资金方四类（我的报价、授信、放款、还款），共六类对象。其中融资项目详情由借贷广场项目详情承载，其余五类是控制台详情。从列表记录或明确的“查看详情”入口进入，键盘可完成同样导航。复制、筛选、就地展开辅助信息等浏览操作不同时触发详情跳转。已终结的真实记录仍可查看。

<a id="d-mc-213"></a>详情头部识别（D-MC-213）：详情标题直接写对象的业务识别，不用“授信详情”“放款详情”等字样代替；对象类型仍须可辨，承载方式由设计决定。

<a id="d-mc-184"></a>共同详情行为（D-MC-184）：完整稳定编号可复制；内容区分当前事实、历史结果和缺失项。报价、放款可能沿用同一融资业务编号，但进入时保留各自的阅读侧重点，不显示其他机构报价或另一业务。详情不展示合同号、发票号、资产影像、内部执行态或机构不该看到的信息。

<a id="d-mc-185"></a>详情导航（D-MC-185）：代币、放款、还款、报价详情采用[详情唯一广场导航](#d-mc-197)；授信详情从当前使用记录进入其他控制台详情。控制台内选择明确的原申请或期次后，导航保留该原对象阅读定位，不增加第二个去向。无关联、关联不可读、多项目未选择与读取失败各自说明，不用普通广场链接兜底。

<a id="d-mc-186"></a>返回与恢复（D-MC-186）：从列表进入详情后，详情提供返回来源列表的入口；浏览器后退同样恢复原列表分类、筛选、排序、页码、每页条数和所在位置。从详情或待处理记录进入借贷广场后完成或取消，再返回控制台时先回发起的位置（详情或原清单视图），取得最新业务事实；继续返回列表才恢复列表位置。目标因更新不再匹配筛选时说明记录已更新，可清除过滤查看；不保留过期值凑旧位置。直接打开、刷新或分享详情仍定位同一类型和对象；没有来源列表上下文时，返回该类型对应列表分类的默认视图。

<a id="d-mc-187"></a>详情状态与权限（`D-MC-187`）：详情加载时明确加载中，切换对象不得把上一对象内容当作新对象展示；失败为暂不可用及浏览器刷新当前网址的文字指引，不能写成尚无业务。成功后按真实条件区分“尚无放款记录／尚无还款记录”等局部空内容。不存在、已不属本主体、当前角色不允许的对象统一“内容不存在或无权访问”，提供返回本人可访问列表的出路；不泄露对象存在性。未登录直达先按登录域认证，再回可访问的原详情；协议、主体不明或无主体沿用3.10。会话失效即时移除详情数据；重新认证后重新判定归属，不直接恢复旧敏感内容。正常业务终结不等于对象不可访问。

<a id="d-mc-188"></a>列表与详情的信息底线（`D-MC-188`）：列表必须保留识别对象、金额币种、状态和当前紧迫事项所需的信息，逾期与质押不足等关键事实不得只有进入详情才能发现。详情补足必要摘要；完整资料归来源阅读，所有待确认及当前未结清逾期对象仍须可发现。统计业务含义、业务状态、字段权限、授信维度及广场办理资格以对应功能为准；还款列表总数按3.6业务笔数计算。

业务闭环见[从列表经详情到对应广场项目并返回（FL-MC-02）](./02-我的控制台-流程图与状态机.md#fl-mc-02)和[六类详情的访问与返回（FL-MC-04）](./02-我的控制台-流程图与状态机.md#fl-mc-04)，详情状态见[单个详情的可用状态（ST-MC-05）](./02-我的控制台-流程图与状态机.md#st-mc-05)；对应[六类详情验收](./04-我的控制台-验收.md#ac-section-13)。

## 4. 既定业务限制

以下业务限制沿用[放款与放款确认](../07-借贷广场-放款与放款确认/01-放款与放款确认-PRD.md)、[融资需求与代币质押](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)已入库正文同一口径。此处如实记录其在控制台的可观察后果，供研发与测试知悉，不作为异议保留。

| 限制 | 控制台可观察的业务后果 |
| --- | --- |
| <a id="d-mc-208"></a>`D-MC-208` 平台不再采集与校验收款人名称 | 法币与数币账户均取消收款人名称，原“收款账户须属本企业”的硬校验一并删除。控制台按账户备注名、账号 / IBAN 或收款地址辨识账户，不得以其他字段变相恢复该校验；受益人名称由业务双方在平台外补充 |
| 报价一经提交，资金方无法撤回 | 报价有效期取消后，退出路径仅为资产方拒绝或所属需求因项目关闭、项目到期、质押不足而终结的连带失效。我的报价中的待接受记录没有撤回、修改、展期或催办动作，也不会因等待时间自行终结 |
| <a id="d-mc-207"></a>`D-MC-207` 待放款阶段无终止出口 | 待放款的唯一出口是资金方提交放款。若线下协商结果是不放款，平台侧没有任何动作能终结该笔业务：放款记录持续显示待放款，本项目因“本环节未结束不允许发布新需求”无法另起一轮，对应质押代币持续被占用。控制台如实呈现这些事实，不提供终止入口、不判为异常、不以超期或催办表达 |

同理，待放款确认在资产方确认前也没有其他出口：无时限、无自动确认、无终止，业务停留期间还款计划不生成、两类在途金额持续占用、质押不释放。
