<a id="fig-nc-01"></a>
## FIG-NC-01 一条消息从来源发出到本人阅读

```mermaid
flowchart TD
    A["来源业务的事实正式成立"] --> B{"来源规定要告知本人？"}
    B -->|否| C["只在业务页面反馈，不发消息"]
    B -->|是| E{"收件账号和必要内容都明确？"}
    E -->|否| F["来源补齐后再发，不猜收件人、不发空白消息"]
    E -->|是| G{"这个账号已收到过同一事实？"}
    G -->|是| H["保留原消息：不新增、不改顺序、不变回未读、不改发生时间"]
    G -->|否| I["新增一条消息，状态为未读"]
    I --> J["业务事件后 60 秒内出现在列表，未读数同步；到点触发的事件从应到时点起最晚 6 分钟"]
    J --> K["本人阅读，或从消息前往原业务"]
    H --> K
    K --> L["读消息不等于办业务，业务结果以来源为准"]
```

同一笔业务上的新事实（新的一期、新的一轮、新的一次操作）各自是一条新消息。消息送达延迟不影响业务本身，也不顺延业务期限。

## FIG-NC-02 入口、列表、详情、已读与返回

```mermaid
flowchart TD
    A["已登录且已判定为资产方或资金方"] --> B["消息入口（显示未读数）"]
    B --> C["最近消息预览：最近 10 条，只打开不算已读"]
    A --> D["账号菜单：消息中心"]
    D --> E["消息列表"]
    C -->|查看全部| E
    C -->|选择某条| F["消息详情"]
    E -->|点击某条| F
    E -->|按分类、阅读状态筛选| E
    E -->|加载更多，每次 20 条| E
    E -->|全部已读| ALL["见 FIG-NC-03"]
    F --> G{"详情内容展示成功？"}
    G -->|否| H["仍为未读，可重新加载"]
    H --> F
    G -->|是| I{"已读保存成功？"}
    I -->|否| J["正文照常可读，仍为未读，可重试"]
    J --> I
    I -->|是| K["变为已读，未读数减少"]
    F -->|返回| R["回到原列表：筛选、已加载批次和位置不变；没有原列表时回到不带筛选的列表"]
    R --> E
    F -->|前往原业务| T["见 FIG-NC-04"]
    T -->|后退| F
    F -.->|登录失效| S["清除全部本人消息内容，见 SM-NC-03"]
    E -.->|登录失效| S
```

## FIG-NC-03 全部已读

```mermaid
flowchart TD
    A["消息列表与当前筛选条件"] --> B["选择全部已读"]
    B --> C["确认：写明筛选条件和将标为已读的未读条数，包括尚未加载的"]
    C -->|取消| A
    C -->|确认| D["只处理确认时范围内的未读消息"]
    D -->|成功| E["范围内全部变为已读，未读数同步更新"]
    D -->|失败| F["全部保持原状，提示失败，可重试"]
    F --> C
    E --> G["业务状态不变；确认之后新到的消息仍为未读"]
```

<a id="fig-nc-04"></a>
## FIG-NC-04 前往原业务

```mermaid
flowchart TD
    A["本人打开一条消息"] --> B{"打开后去哪？"}
    B -->|不跳转，或类型尚未登记| C["只看正文，没有前往入口，也不提示错误"]
    B -->|本平台固定页面| D["可以前往，由目标页面判断权限"]
    B -->|原业务| E{"按当前权限检查原业务"}
    E -->|不存在或无权| F["不能前往，显示“相关内容暂不可访问”"]
    E -->|超过 3 秒或检查失败| G["仍可前往，由原业务页面判断权限"]
    E -->|可以查看| H{"消息仍有效，且提示的动作仍可办理？"}
    H -->|是| I["前往原业务查看或办理"]
    H -->|否| J["前往查看这一笔的当前结果，不再提供旧动作"]
    D --> K["用户主动前往，目标页面重新判断权限"]
    G --> K
    I --> K
    J --> K
    K -->|有权| L["看到原业务的当前事实和当前可做的动作"]
    K -->|已登录但无权| M["平台统一的权限不足引导"]
    K -->|未登录| N["先登录，成功后回到原业务"]
```

始终定位到消息所说的那一笔，不换成最新一笔、下一期或当前默认选中的业务。消息正文说的是当时的事实，原业务页面展示的是当前的事实。

<a id="fig-nc-05"></a>
## FIG-NC-05 从链接直接打开本平台页面

```mermaid
flowchart TD
    A["从链接打开本平台某个页面"] --> B{"是本平台已登记的页面？"}
    B -->|否| C["进入默认的资产广场，不出现空白页"]
    B -->|是| D{"已登录？"}
    D -->|否| E["先登录，然后回到原页面"]
    D -->|是| F{"有权查看？"}
    E --> F
    F -->|有权| G["打开原页面和原业务"]
    F -->|无权| H["平台统一的权限不足引导"]
```

本期消息不跳转到其他平台；需要在其他平台办理的事项，按所属业务已确认的入口办理。

<a id="sm-nc-01"></a>
## SM-NC-01 消息有效期

一条消息是否仍在有效期内，与是否已读、原业务能否办理是三件互相独立的事。

```mermaid
stateDiagram-v2
    [*] --> 有效: 消息产生
    有效 --> 已过期: 到达来源设定的有效期
    note right of 有效
        未读时计入未读数
    end note
    note right of 已过期
        不计入未读数，仍可查看，标示“已过期”
        原业务还能否办理，以原业务当前状态为准
    end note
```

没有设定有效期的消息一直有效。重复送达不会让过期的消息恢复有效。

<a id="sm-nc-02"></a>
## SM-NC-02 本人阅读状态

对象是一个收件账号的一条消息。

```mermaid
stateDiagram-v2
    [*] --> 未读: 收到新消息
    未读 --> 已读: 详情展示成功且已读保存成功
    未读 --> 已读: 在一次成功的全部已读范围内
    未读 --> 未读: 只打开预览、详情加载失败或已读保存失败
    未读 --> 未读: 同一事实重复送达
    已读 --> 已读: 再次打开、同一事实补齐或重复送达
    note right of 已读
        不提供改回未读
        读消息不执行业务，不影响其他人的消息
    end note
```

同一笔业务上的新事实是另一条新消息，不会把旧消息改回未读。消息过期只影响是否计入未读数，不改变是否读过。

<a id="sm-nc-03"></a>
## SM-NC-03 登录状态与能否看到消息

```mermaid
stateDiagram-v2
    [*] --> 游客: 未登录
    游客 --> 正常登录: 登录成功
    正常登录 --> 游客: 退出、到期或被动失效
    note right of 游客
        没有消息入口；从链接打开时先登录再回到原处
    end note
    note right of 正常登录
        已判定为资产方或资金方时可读本人消息；登录未绑定角色时没有消息入口
        业务资质不足只限制办理
        自动更新消息不延长登录有效期
    end note
```

变为游客时，消息入口、未读数、预览、列表和详情同时清除，必须真正清除，之后迟到的数据也不再显示。
