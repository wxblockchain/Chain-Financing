# 面客消息中心 · 验收

2026-10-15｜需求评审稿｜供测试使用

本册列出面客消息中心的验收标准：在什么前提下、做什么、应该看到什么结果。规则的完整说明见[功能与业务规则](./01-面客消息中心-PRD.md)，各节顺序与功能册一致，每节开头链接到对应的功能章节。本册只写验收标准，具体测试用例与执行步骤由测试小队编写。

怎么读这本册：

- 共 81 条验收。编号沿用原值，已删除的条目不再占号，所以编号不连续、按功能顺序而非数字顺序排列；缺号不代表遗漏。
- 一条验收写了多个场景（用“另”“再”分隔）时，**全部场景都满足才算通过**。
- 本模块没有消息通知册（03），故验收册编为 04，与其他模块的册序一致。

## 0. 验收前准备

**账号。** 以下每类至少准备一个：

- 已登录资产方、已登录资金方（双方处于同一笔业务中）；
- 同一钱包下的资产方身份与资金方身份；
- 另一个无关企业的账号；
- 游客（未登录）；
- 受限会话（已登录但尚未同意必需协议）；
- 运营人员账号（用于确认运营端消息不进入面客端）。

**消息。** 使用[功能册第 4.1 节](./01-面客消息中心-PRD.md#sources)列出的真实来源消息；另需准备：

- 一条业务类型尚未登记的消息、一条分类无法识别的消息；
- 一条当前语言缺失、一条中英文都无法展示的消息；
- 一条已过有效期的“应还临近提醒”；
- 原业务已流转（提示的动作已不适用）、原业务不存在、本人无权查看三种情况的消息各一条；
- 超过 99 条的未读消息，用于验证“99+”；超过 20 条的消息，用于验证“加载更多”。

**时效与性能。** 业务事件后 60 秒内可见属于硬性验收项（AC-NC-15）；未读数读取与列表、详情的性能目标见功能册第 11 节，须以真实环境数据验证，不能以文档或原型自测代替。

## 2. 消息从哪里来

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| AC-NC-14 | 已登录 | 查找发送、编辑模板或通知设置的入口；执行阅读、筛选、全部已读、加载、复制、返回、重试等操作 | 不存在发送、编辑或设置入口；以上操作都不会产生新的消息 |
| AC-NC-15 | 来源业务事件真实发生 | 记录事件发生时刻，观察列表与未读数 | 60 秒内消息出现在列表、未读数同步更新；从业务事件发生时起算。还款逾期判定与 60 秒的差异（Q-NC-04）未统一前，该分支记为待验，不判通过 |
| AC-NC-05 | 来源未能确定收件人 | 事件发生 | 不发送；不发给企业全体、最近操作人或按邮箱、钱包猜测的账号 |
| AC-NC-16 | 来源消息缺收件人、业务类型或可读的标题正文 | 事件发生 | 不生成空白消息；缺少来源规定的必要信息时，不用 0 或虚假编号补齐 |
| AC-NC-17 | 来源消息缺少可选的编号或跳转目标 | 查看该消息 | 消息照常展示，缺少的部分不显示 |
| AC-NC-18 | 同一事实重复送达 | 分别在消息未读、已读时重复送达 | 始终只有一条；未读时只计一次；已读时仍为已读；排序位置和发生时间不变 |
| AC-NC-19 | 同一业务先收到较新的事实，后收到较旧的结果 | 查看消息 | 事实不倒退；同一事实的补充不改变已读状态，也不覆盖其他独立事实 |
| AC-NC-28 | 同一笔业务先后发生不同期次、不同轮次或不同次操作 | 查看列表 | 每个事实各有一条，后一条不覆盖前一条 |
| AC-NC-92 | 一次还款确认使整笔业务结清 | 资产方查看消息 | 资产方只收到一条“融资业务已结清”，不另收“本期还款已确认”，结清所需的事实都在这一条里 |
| AC-NC-22 | 来源同时指定两种去向，或指定站外地址 | 事件发生 | 不接收该消息；与“类型尚未登记”的消息分开处理（后者照常可读） |
| AC-NC-23 | 一条消息有中英两种文案 | 切换语言查看 | 两种语言的事实和数值一致，金额、币种、时间正确显示 |
| AC-NC-24 | 来源消息涉及账户、钱包或联系方式 | 查看标题和正文 | 不出现私人邮箱、完整钱包地址、证件号、IP、完整账户或凭证，也不出现客服邮箱 |
| AC-NC-26 | 本人消息分布在若干分类 | 打开分类筛选 | 只出现“全部”和本人实际有消息的分类；新登记的分类能自然出现 |
| AC-NC-27 | 一条消息的分类无法识别 | 查看列表与筛选 | 该消息显示在“其他 / Other”下，照常可读 |
| AC-NC-29 | 一条消息的业务类型尚未登记 | 查看列表并打开详情 | 正常展示、可读、计入未读数；没有前往原业务的入口，也不提示错误或跳到错误页 |
| AC-NC-31 | 一条消息当前语言缺失；另一条中英都无法展示 | 查看列表和详情 | 前者显示另一种语言；后者以分类、发生时间和“通知 / Notification”展示，不露出模板编码，不影响其他消息 |
| AC-NC-32 | 一条消息缺少某个变量 | 查看详情 | 不出现裸露的占位符；缺少必要信息时不显示成语义错误的成功提示 |
| AC-NC-33 | 已有若干历史消息 | 切换界面语言 | 历史消息的标题、正文随之切换；金额、时间、期次和业务编号不变 |
| AC-NC-89 | 用户在不同时区查看同一条消息 | 对比业务日期、时刻与金额 | 业务日期相同（按 UTC）；具体时刻按偏好时区显示并标明时区；金额与币种保持事件当时的值，不按当前汇率或当前计划改写 |
| AC-NC-90 | 同一事件按角色或结果有不同文案 | 各收件人查看 | 每人只收到一条，用的是符合条件的那一套；切换语言不丢信息 |
| AC-NC-91 | 一条需要逐期对照的消息（如还款计划定稿），含两侧都有、只有一侧有的期次 | 查看详情 | 全部条目在同一条消息中完整给出，两种语言一致；不截成摘要、不拆成多条、不只写“去详情查看” |

| AC-NC-51 | 列表中某一条内容异常 | 查看列表并打开该条 | 只有这一条以兜底方式展示，其他消息正常；不显示为整个列表出错 |

| AC-NC-56 | 与 AC-NC-55 相同的筛选与消息；另制造一次失败；再准备一个范围内没有未读的筛选 | 确认全部已读；制造失败后重试；在无未读的范围内执行 | 成功后未读数与列表一致；失败时全部保持原状，有失败提示，不会只成功一部分，不会重复提交；无未读时不提示清除了其他消息 |
| AC-NC-57 | 有已读消息 | 查找“标为未读”；让同一事实重复送达 | 没有“标为未读”；重复送达也不会让消息变回未读 |
| AC-NC-58 | 在列表中加载了 5 批并设置了筛选 | 打开某条详情后返回；另用链接直接打开一条详情后返回；从详情前往原业务后再后退 | 返回后仍是 5 批，筛选和位置不变；直接打开的返回到不带筛选的列表；从原业务后退回到这条消息，不会又被带回原业务 |

## 6. 前往原业务

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |

| AC-NC-65 | 未登录时打开指向原业务的链接 | 登录 | 登录成功后回到原业务，那一期或那一笔不丢失 |
| AC-NC-66 | 已登录但无权查看原业务 | 前往 | 看到平台统一的权限不足引导，不展示私有内容，也看不出该业务是否存在 |
| AC-NC-67 | 打开一个本平台不认识的页面链接 | 打开 | 进入资产广场，不出现空白页或无反应 |

| AC-NC-69 | 一条消息提示的动作已办完，本人仍有权查看；另一条原业务已不可访问 | 分别打开详情 | 前者可查看这一笔的当前结果，没有旧动作入口；后者入口不可用，并显示“相关内容暂不可访问” |
| AC-NC-70 | 一条“应还临近提醒”已过有效期，原业务仍可查看 | 打开详情并前往 | 消息标示已过期、不计入未读数；可查看原业务；原业务仍可逾期还款时，不因消息过期而被拦住 |
| AC-NC-71 | 一条消息的来源设为不跳转 | 打开详情 | 没有前往入口，也没有错误提示；正文可读，可以返回 |
| AC-NC-72 | 打开详情后、前往之前，本人对原业务的权限发生变化 | 前往 | 原业务页面按最新权限处理；已确认不可访问的不展示私有信息；仅“可能无权”时不提前拦住入口 |
| AC-NC-73 | 消息指向某个办理场景，但该动作已不适用 | 前往 | 有权查看时进入原记录查看，不打开旧的办理动作 |
| AC-NC-74 | 一条消息的原业务不存在；另一条无权查看 | 分别打开详情 | 两者显示同样的“相关内容暂不可访问”，无法据此判断业务是否存在 |
| AC-NC-93 | 同一笔业务处于可办理、仅可查看、消息已过期、无权查看等不同情况 | 分别打开对应消息并前往 | 每种情况按功能册第 8 节的表格处理；始终是原业务的那一期，不会打开下一期，也不会因状态变化一律禁止查看 |

## 7. 登录状态与安全

对应功能：[第 9 节](./01-面客消息中心-PRD.md#f-nc-27) 与 [第 3 节](./01-面客消息中心-PRD.md#f-nc-01)

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| AC-NC-75 | 正在查看消息列表或详情 | 退出登录，或让登录失效 | 正文、列表、未读数全部真正清除，不能通过关闭提示等方式再看到 |
| AC-NC-76 | 正在查看消息列表或详情，然后退出登录或让登录失效 | 观察页面 | 消息入口和账号菜单中的“消息中心”同时消失，不出现游客仍能看到入口或数字的中间状态 |
| AC-NC-77 | 登录失效后，仍有之前发出的数据请求返回 | 观察页面 | 迟到的数据不再显示 |
| AC-NC-78 | 正在看某条消息详情时登录失效 | 观察页面 | 整个详情退出，不能通过关闭提示框看到旧正文 |
| AC-NC-79 | 游客 | 用链接直接打开消息列表或某条消息，然后登录 | 先要求登录；成功后回到原列表或原消息，不是“不存在”页，也不是直接回资产广场 |
| AC-NC-80 | 已登录，只开着消息页面不做任何操作 | 等到登录有效期结束 | 登录照常按时失效，不因消息自动更新而延长 |
| AC-NC-81 | 受限会话；另一个认证不足但已正常登录的资产方 | 分别查看消息 | 受限会话看不到消息，须先完成必须事项；认证不足的资产方照常阅读本人消息 |

## 8. 与我的控制台的分工

对应功能：[第 10 节](./01-面客消息中心-PRD.md#console-boundary)

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| AC-NC-85 | 一条消息提示某笔业务待办理 | 读消息；再到原业务办完 | 消息仍保留；控制台的业务状态按真实办理结果更新；控制台没有待办清单或待办计数 |
| AC-NC-86 | 有未读消息，控制台有相关业务提醒 | 执行全部已读；再到原业务办理 | 全部已读后控制台的业务提醒不变；业务办完后消息不会自动变为已读；控制台不另发消息 |
