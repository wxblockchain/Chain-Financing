# 资金方登录与账户体系 PRD

2026-10-28｜面客端：资金方及登录未绑定角色｜需求评审稿

## 1. 目标与阅读方式

让用户用自己的钱包登录借贷平台，填写机构资料并提交入驻申请；审核通过后获得认证业务权限。登录身份、资金方账户、机构认证和账户是否可用是四件不同的事：钱包签名证明地址控制权，首次成功提交申请建立资金方账户，机构审核决定业务资格，停用限制账户访问。**提交前的表单内容不保存、已上传材料仅为本次入驻临时保留，只有成功提交才形成正式申请与资料。**
**一个完整的例子。** 登录未绑定角色的用户触发资金方动作，在入驻流程验证账户联系邮箱、填写机构及业务联系人资料并上传材料。核对后确认提交，平台同时建立资金方账户与申请，状态为审核中，资料只读；运营通过后，用户查看已认证结果及当前资料。离开后再次登录仍查看同一账户，退出则回到游客浏览。


主流程：**连接钱包 → 选择地址 → 消息签名（登录由[登录主干](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#F-L02)统一承担）→ 登录未绑定角色时触发资金方动作即进入入驻流程 → 验证联系邮箱、填写机构资料 → 提交申请（首次成功提交时建立资金方账户，以该地址作为资金方账户的登录地址）→ 查看通过或驳回结果。** 已认证账户变更机构资料时重新提交审核；账户联系邮箱的修改不触发机构重审。用户不选择角色，平台也没有选择角色的入口。

本模块共四册：本册定义功能与业务规则；[流程图与状态机](./02-资金方登录与账户体系-流程图与状态机.md)、[消息通知](./03-资金方登录与账户体系-消息通知.md)及[验收](./04-资金方登录与账户体系-验收.md)配套阅读。功能与验收编号沿用原值，缺号不代表遗漏。

## 2. 钱包登录与资金方账户建立

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

### 2.1 登录并入主干，入驻由动作触发

<a id="F-L50"></a><a id="f-l50"></a>**钱包登录并入主干（F-L50）**：**本册不定义独立的资金方登录入口或签名步骤**。用户通过[共用钱包登录](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#F-L02)连接钱包、选择地址并完成消息签名，登录时不选择角色；签名用途、有效期与单次使用、身份与网络一致、防滥用降速等规则见登录主干的[登录签名规则](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#signature-rules)，连接与签名的取消、失败、网络不支持等结果见[取消、不可用与更换钱包](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#F-L03)。钱包范围同登录主干：本期仅支持桌面浏览器中的 MetaMask 钱包插件与以太坊（ETH）链。登录未绑定角色的用户触发资金方业务动作（发起出资、授信报价等）时，直接进入本册的资金方入驻流程，见[动作分流](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#action-routing)。

<a id="disabled-at-login"></a>**签名后发现账户已停用**：签名验证通过、该地址已有资金方账户但账户已停用时，本次登录不成立，按下列规则处理：

- 说明该账户已停用，沿既定文案“该账号已被停用，请联系客服恢复。 / This account has been disabled. Contact support to restore it.”，并显示[客服邮箱](#support-email)。
- 用户可继续游客浏览；不新建会话，该账户既有会话一并失效。
- 账户恢复后，该地址按登录主干正常签名即可登录，按原注册状态获得相应资格，见[账户与注册状态](#F-L66)。

### 2.2 登录身份与落点

<a id="F-L55"></a><a id="f-l55"></a>**资金方账户建立与已有账户识别（F-L55）**：**签名登录本身不建立资金方账户**；用户在入驻流程中**首次成功提交申请时**才建立本平台资金方账户，并以该地址作为资金方账户的登录地址。登录地址是资金方账户唯一且不可修改的账户属性，不是可解除或改换的绑定状态。账户具有稳定内部身份，建立时账户正常、机构注册为审核中；记录实际建立时间及来源。内部账户标识不作为用户可见或可编辑字段。已有资金方账户的地址再次登录复用原账户及注册状态，不重复建立；提交前退出或放弃不产生账户，也不占用地址。

<a id="F-L56"></a><a id="f-l56"></a>**角色不由用户选择（F-L56）**：平台没有选择角色的入口；用户只在首次成功提交入驻申请、建立资金方账户时成为资金方，此后该地址登录即为资金方，不可改选，见[登录主干的角色匹配](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#F-L34)。

<a id="F-L77"></a><a id="f-l77"></a>**钱包与邮箱唯一性（F-L77）**：登录地址与资金方账户一对一，已验证账户联系邮箱在资金方账户之间唯一。已有资金方账户的地址登录即进入该账户，不会再进入入驻流程；**一个地址只对应一个角色、禁止并存**（见[登录主干的禁止并存](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#role-exclusive)）。地址冲突只在提交入驻申请时校验：该地址已登记为资产方，或同一地址的另一次入驻提交已先被接受，本次提交被拒绝，不建立第二个角色或账户、不合并账户；登录本身不因此被拒绝。提示文案见[核对与成功提交](#F-L61)。邮箱唯一性的校验时点见[联系邮箱验证](#F-L59)。

<a id="F-L78"></a><a id="f-l78"></a>**资产方与资金方隔离（F-L78）**：不同地址上的资产方账户与资金方账户彼此独立，即使属于同一自然人也不合并、不互相读取档案或继承认证；**同一地址禁止并存两种角色**（见[登录主干的禁止并存](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#role-exclusive)），不能同时具备两种角色。

按[共用返回规则](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#return)决定落点：未绑定角色时按动作分流先进入入驻流程，再处理仍有效且当前有权访问的原业务目标，最后回资产广场。原业务意图采用主干既定默认 30 分钟（可配置）有效期及安全返回规则；重新登录不得刷新原期限。

<a id="F-L57"></a><a id="f-l57"></a>**入驻引导与返回（F-L57）**：登录未绑定角色的用户触发资金方动作即进入入驻流程，其间不插入单独的建号步骤；须让用户知道本次登录地址与凭据提示。用户可随时取消并继续允许的浏览，**取消即放弃本次表单内容，不保存；已上传材料按[提交前内容临时保留](#F-L58)规则清除，也不再另行提示**。登录前不提供“申请入驻”入口；已有资金方账户但尚未认证的用户按当前注册状态从资格提示或“机构信息”进入，审核中只读。**提交申请只到审核中，不代表审核通过，也不能因此执行原来受限的出资动作。** 在资格、目标及时效全部满足时，才按主干规则恢复原触发动作；目标已失效则说明并提供适用返回，不自动越权。

## 3. 机构注册与提交

### 3.1 谁能填写、怎样保存

尚未提交（登录未绑定角色）的用户在本次登录内的入驻流程中填写；已有资金方账户且账户正常、登录有效时，已驳回、已认证可以编辑；审核中只能查看当前提交，直接访问机构注册流程编辑入口也转到申请状态与审核记录只读进度，不能修改。**“未提交”表示尚未建立资金方账户，资金方账户上的注册状态只有审核中、已驳回、已认证三种，没有“草稿”这一状态。**

<a id="F-L65"></a><a id="f-l65"></a>**认证后变更重审（F-L65）**：已认证用户开始编辑时说明成功提交将重新审核并暂停认证业务权限，但**编辑、放弃或提交失败不改变当前已认证或已提交资料**。

<a id="P-L21"></a><a id="p-l21"></a><a id="F-L58"></a><a id="f-l58"></a>**提交前内容临时保留、提交才保存（F-L58）**：入驻流程**不拆成步骤页**，用户在一个流程内完成联系邮箱验证、机构信息与材料填写、核对与提交。邮箱尚未验证可以先填机构资料，但不能提交。完成度按当前必填项及真实上传状态计算，不能以“曾经填过”代替当前合格。

**提交前的内容不形成正式资料**：表单内容只在本次登录的入驻流程内保留，不提供草稿保存动作；**同一次登录内已填内容不丢失**，用户在流程内往返查看不清空已填写的值。提交前已上传的材料仅供本次入驻使用，只有本人可读取；仅在本次登录内可用，放弃入驻或自上传起 **24 小时**内未提交即自动清除。**取消即放弃**：用户取消、退出或主动离开即丢弃本次表单内容，不恢复，也不再额外提示。关闭浏览器、刷新或登录失效同样不保留表单内容，本册不承诺挽留。

**正式保存只发生在成功提交时**：成功提交的版本作为当前已提交资料保存，提交前上传的材料随之转为正式材料；驳回后重新编辑时该版本仍保留。首次入驻时联系邮箱的验证结果只在本次登录的本次入驻内有效，见[联系邮箱验证](#F-L59)。只有成功提交才替换当前已提交资料：驳回编辑保持已驳回、认证后编辑保持已认证。

<a id="email-verification"></a>
### 3.2 联系邮箱首次验证

<a id="F-L59"></a><a id="f-l59"></a>**联系邮箱验证（F-L59）**：联系邮箱是账户的有效联系通道，**不是登录凭据，也不是本期业务通知渠道**。首次在入驻流程内填写并验证；修改已有效邮箱使用[账户邮箱修改](#email-change)的同一流程。注册资料中的“业务联系人邮箱”是另一个独立字段，不能互相覆盖。

字段标签为“账户联系邮箱 / Account contact email”。说明沿既定文案：“请使用长期有效的企业邮箱并完成验证码验证。审核结果与账号通知请在平台消息中心查看。 / Use a long-lived company mailbox and verify it with an email code. Review results and account notices are available in the platform message center.”

| 字段 | 类型、必填及默认 | 校验与生效 |
| --- | --- | --- |
| 账户联系邮箱 | 文本；提交注册前必填；首次入驻初始为空，已有资金方账户时回显当前有效邮箱 | 去首尾空格、转小写后校验；仅一个 `@`、域名至少一个点，最多 254 字符；未被另一资金方账户使用，不能披露占用者身份 |
| 邮箱验证码 | 6 位数字组成的字符串；验证时必填；初始为空 | 仅验证本次待验证邮箱；有效期 10 分钟；同一码连续输错 5 次即作废，要求重新获取，不锁账户、不改变注册状态 |
| 验证时间 | 实际成功时间；只读，无人工默认值 | 首次入驻时随成功提交记入资金方账户，修改时随新邮箱生效记录；失败不写入新的验证时间 |

每次获取或重发验证码，先满足邮箱格式、可用性、发送冷却及限额，再**通过本次滑块验证**才向待验证邮箱发送。未完成、失败或取消滑块均不发码；上一次滑块成功不能代替本次重发。验证码不进入站内消息池，不发给旧邮箱。

三条发码限制同时适用：距上次发送至少 **60 秒**；同一次填写／修改流程最多 **重发 5 次**；同一目标邮箱 **24 小时最多发送 10 次**。分别提示剩余等待时间、本次流程上限（可退出重新发起）、邮箱发送上限。重新开启流程不取消邮箱 24 小时限制或仍在生效的发送冷却。

邮箱冲突在发码前拒绝，用户可直接改填，无需退出流程且不消耗本次流程。已有效邮箱修改为与当前相同的标准化邮箱，提示“这已经是你当前的联系邮箱”，不发码、不增加发送或重发次数。修改时输入正确验证码后，生效前仍检查唯一性；若已被另一资金方账户使用，拒绝并保留原邮箱及验证时间。首次验证不产生站内信，邮箱验证邮件仅承担功能验证。

**首次入驻的验证结果**：入驻提交前验证通过的邮箱只在本次登录的本次入驻内有效，有效期 **30 分钟**，超时须重新验证才能提交。资金方账户之间的邮箱唯一性在发送验证码、验证和提交时各检查一次；放弃入驻不占用该邮箱。两位用户先后验证了同一邮箱时，先成功提交者生效，后提交者的提交被拒绝并提示“该邮箱不可用，请更换。 / This email address isn't available. Please use another one.”，可改填其他邮箱重新验证，本次其他已填内容保留。成功提交时该邮箱及验证时间成为资金方账户的账户联系邮箱。

<a id="institution-fields"></a>
### 3.3 机构信息与材料

<a id="F-L60"></a><a id="f-l60"></a>**机构字段与材料（F-L60）**：正式字段与校验同源于 [机构认证审核 PRD](../../运营端/05-资金方机构认证审核/01-资金方机构认证审核-PRD.md#F-L80)的机构资料同源模版与字段表及[机构标识查重](../../运营端/05-资金方机构认证审核/01-资金方机构认证审核-PRD.md#F-L81)。面客采集与运营查看使用同一份定义；下表保留填写本流程所需的业务口径，不另建第二套审核标准。业务联系人姓名、邮箱、电话使用同源定义，见[业务联系人信息](#business-contact)及[共用规则与仍需落实的依赖（第 7 章）](#dependencies)。

| 信息 | 含义、类型与必填 | 当前填写规则／默认 |
| --- | --- | --- |
| 机构名称 | 法定机构名称，文本，必填 | 非空；初始空，不代猜主体；名称本身不作为唯一机构标识 |
| 注册国家或地区 | 机构登记地，文本，必填 | 非空；按当前同源规则为文本填写，不强加国家枚举或默认国家 |
| 标识类型 | 必填枚举 `USCC`／`LEI`／`REG_NO` | 无默认，初始“请选择”；分别表示 USCC 统一社会信用代码、LEI 法人机构识别编码、REG_NO 商业登记号 |
| 机构唯一标识 | 所选类型对应编号，文本，必填 | 非空，保留原样显示；境内按生效模版强校验；境外存在格式差异时提示并由人工核实，不因一般格式提示自动拒绝 |
| 机构类型 | 描述机构类别，文本，必填 | 非空；不擅自限定为银行／基金枚举，初始空 |
| 注册地址 | 完整登记地址，文本，必填 | 非空，初始空 |
| 监管机构 | 适用的监管机构名称，文本，选填 | 初始空；不是工商登记机关字段，不新增无依据的长度上限 |
| 金融牌照编号 | 机构提供的金融牌照号码，文本，选填 | 初始空；有值不自动说明牌照有效或满足准入，不新增牌照影像或有效期字段 |
| 业务联系人姓名 | 机构指定的业务联系人姓名，文本，必填 | 去首尾空格后非空，最多 100 字符；按联系人常用写法原样保留，不拆分姓与名、不限定语言；初始空，不预填 |
| 业务联系人邮箱 | 业务联系人的邮箱，文本，必填 | 去首尾空格后满足邮箱格式（仅一个 `@`、域名至少一个点），最多 254 字符；无需验证码和唯一性校验；初始空，不自动复制账户联系邮箱，允许与账户联系邮箱相同 |
| 业务联系人电话 | 业务联系人的电话，由电话区号与电话号码两项组成，均必填 | 区号与号码规则见[业务联系人信息](#business-contact)；初始均为空，区号无默认值 |
| 机构证明材料 | 用于本次审核的文件集合，必填 | 至少 1 个成功上传且可读取的文件，支持多附件；仅接受 PDF、JPG、PNG，单个文件不超过 10MB，每次提交最多 10 个；超出限制的文件就地说明且不计入本次材料 |

同源字段在填写、核对、当前资料及运营详情中同名展示，选填空值为“—”；文本必填项不得仅空白。境内采用统一社会信用代码；境外有 LEI 时优先使用 LEI（全球范围判重），否则采用注册国家或地区加商业登记号。提交和审核通过生效前都核验机构唯一性；其他资金方待审核或已认证申请占用同一标识时，提示“该机构已在平台注册，如有疑问请联系客服”并显示[客服邮箱](#support-email)，不合并账户、不泄露对方信息。

成功提交时占用机构标识，通过后继续占用；首次或普通重提被驳回释放本轮占用。未提交内容不占用标识。已认证后变更机构标识按机构认证审核的机构标识变更规则：审核期间新旧标识均保留占用，通过后释放旧标识；驳回释放新标识、保留原绑定和原标识占用，但当前为已驳回，**原绑定不保留认证权限，也不恢复旧表单／附件**。同一账户已有绑定不误判为另一资金方冲突。

<a id="business-contact"></a>**业务联系人信息**：业务联系人是机构指定、负责本次认证及后续业务沟通的人员，可以不是钱包持有人。姓名、邮箱、电话三项属于机构资料，随机构资料提交、审核和回显，与账户联系邮箱相互独立、互不覆盖。

| 信息 | 含义、类型与必填 | 填写与校验规则 |
| --- | --- | --- |
| 电话区号 | 业务联系人电话所属国家或地区的国际电话区号，单选，必填 | 选项为已分配国际电话区号的国家和地区，每项同时显示国家或地区名称与区号（形如“中国 +86”），名称随当前语言显示；可按名称或区号查找；无默认值，初始为“请选择”，不按钱包地址、注册国家或地区、浏览器语言或所在位置预选；多个国家或地区共用同一区号时分别列出，保存并回显用户实际所选的国家或地区 |
| 电话号码 | 不含区号的本地电话号码，文本，必填；固定电话、手机号码均可 | 去除输入中的空格、连字符和括号后只能为数字，不含“+”或“00”等国际拨号前缀；须符合所选国家或地区的号码规则；无法按所选国家或地区判定号码规则时，只校验仅为数字且区号与号码合计不超过 15 位；未选区号时提示先选择区号 |

- 校验未通过时在对应项就地说明原因，并计入提交前的缺项清单；本次其他已填内容保留。
- 电话统一按“+区号 号码”的国际格式回显，区号与号码在填写、核对和查看时均可分辨。
- 业务联系人邮箱和电话不发送验证码，不作为登录凭据，也不是本期通知渠道；平台不向其发送短信、邮件或站内信，仅供运营审核与业务沟通时人工联系。
- 三项均不做跨账户唯一性校验，同一联系人可以同时是多个机构的业务联系人。
- 三项在核对、申请状态与审核记录的当前资料、运营审核详情中完整显示；不在“用户信息”展示，不向其他业务角色展示，也不写入任何通知内容。
- 修改任一项都属于机构资料变更：审核中只读；已驳回可修改后重提；已认证修改须按[认证后变更重审](#F-L65)成功提交，提交后进入审核中并暂停认证业务权限。只改账户联系邮箱不影响这三项。
- 新增本组字段之前已成功提交的资料按提交时规则查看与审核，缺少的业务联系人姓名或电话显示“—”，不因此变为缺资料；该账户下一次编辑提交时须补齐全部必填项。

提交前上传的材料按[提交前内容临时保留](#F-L58)规则只供本人在本次入驻使用，成功提交后转为正式材料。附件展示真实文件名、大小和上传状态／进度，支持按当前权限预览、下载原文件。新增文件不覆盖其余已选文件；取消选择或替换保留原文件，主动删除后的迟到上传结果不能使文件复活。上传中、失败、不可读取的文件必须处理或移除，不能提交时静默遗漏；支持重试且不凭刷新伪造上传成功。暂不支持预览与文件不可读分开说明；仍可下载的原件保留下载入口。关闭预览返回原填写状态，不生成模拟附件、不丢表单内容。

当前提交沿提交时的模版规则审核，不因模版更新临时变成缺资料；再次填写与提交采用当前有效模版。无法取得有效模版时不猜字段或放行，就地说明并提供重试和[客服邮箱](#support-email)，本次已填内容在同一次登录内保留。

### 3.4 核对与成功提交

<a id="F-L61"></a><a id="f-l61"></a>**核对与成功提交（F-L61）**：核对展示已验证的账户联系邮箱、机构信息（含业务联系人信息）及全部材料。**本期无协议同意环节**（见[登录主干的协议口径](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#agreement)）。**提交前必须有一次明确的二次确认**，每次提交都要求确认，不提供“不再提示”；该确认是操作确认，不具备协议同意效力。二次确认时取消回到当前填写内容继续编辑；离开流程则按[提交前内容临时保留](#F-L58)放弃本次内容。

成功提交必须同时满足：有效登录、账户正常（已有账户时）、当前可提交状态、账户联系邮箱已验证且仍可用（首次入驻时验证结果在 30 分钟有效期内）、机构必填项和所有材料合格、有效模版与机构唯一性校验通过、登录地址未用于其他角色（首次入驻时）、用户完成二次确认、提交频次未超限。首次提交同时建立资金方账户，见[资金方账户建立与已有账户识别](#F-L55)。

地址冲突只在提交时校验：该地址已登记为资产方，或同一地址的另一次入驻提交已先被接受时，本次提交被拒绝并提示“该地址已用于其他角色 / This address is already used for another role”，不建立账户或申请、不合并账户，已填内容在同一次登录内保留；当前登录不受影响，用户可换一个地址重新登录后入驻。经界面提交与直接提交均受相同限制；失败须指明具体不合格字段／材料且对辅助技术可得，保留已填内容，不生成申请结果或改变当前资料。

同一账户在 **24 小时滑动窗口内最多 5 次成功提交**，包括首次、驳回重提和认证后变更。失败、重复返回同一成功结果不计；累计重提次数无上限。限频时本次已填内容在同一次登录内保留、显示具体可再次提交时间及其时区，提交不可用并说明原因；窗口按真实连续时长计算，不因显示日期或时区切换重置。

成功后进入申请状态与审核记录页，注册状态统一为审核中，用本次机构资料及材料整体替换唯一当前已提交版本；新增一个真实提交节点及提交时间，等待运营审核。向正常运营范围发送一条机构资料待审核站内信；资金方在提交结果中已即时获知，不再收到普通提交回执。已认证变更提交另向本人发送一条认证权限暂停通知，并按[资格说明](#guidance)即时限制业务。

重复点击或网络重返同一结果不重复生成申请、提交节点、成功次数或通知。结果暂未知时不得提前显示成功、覆盖当前资料或通知；保持结果待确认，用户可查询本次提交结果，同一次提交不会被重复受理。已接收则呈现同一次成功；已接收但其间本次登录已结束时，用户须重新登录，登录后在申请状态与审核记录中看到同一份申请。明确未接收才回到可再次提交的填写状态，本次内容仅在同一次登录内保留，重新登录后不恢复；查询失败不视为材料丢失。旧提交的迟到审核结果不能应用到新提交。

## 4. 审核结果、状态与业务权限

<a id="review"></a>
### 4.1 查看申请与处理结果

<a id="P-L22"></a><a id="p-l22"></a><a id="F-L63"></a><a id="f-l63"></a>**审核结果与记录（F-L63）**：本人在申请状态与审核记录页查看申请编号、当前注册状态、本次提交时间、已生效审核时间与结果（通过时即认证时间）、唯一当前机构资料和材料，以及实际发生的提交／审核记录。

<a id="F-L62"></a><a id="f-l62"></a>**审核中只读（F-L62）**：审核中机构资料只读，不提供编辑、删除、重新提交、撤回或回退为未提交的操作，产品文案不出现“撤回”或暗示可在审核中修改材料的表述；账户联系邮箱仍可独立修改。

机构自行决定实质审核标准，平台按机构认证审核承载已确认的形式校验、正常运营人工审核及结果。资料齐全、金融牌照有值、等待较久或机构标准变化不自动通过、驳回、触发重审；不承诺审核天数、队列位置或超时自动结论，不要求新增平台评分或准入名单。

审核通过：本次有效结论使审核中 → 已认证，展示通过记录并开放当前认证业务。审核驳回：审核中 → 已驳回，显示驳回原因**原文**，保留段落，不翻译、不按字段拆分、不虚构驳回分类。

<a id="F-L64"></a><a id="f-l64"></a>**驳回后修改重提（F-L64）**：用户可查看原因后进入原资料预填的注册流程，修改并重新提交；字段本身的填写校验仍正常执行。机构审核通过／驳回通知由机构认证审核唯一发送，本模块不重复告知。

时间线每次成功提交与每次生效审核各为一个独立节点，按实际发生顺序显示；时间相同仍保持真实先后。待审核只是最新提交的状态提示，不预造审核动作、审核人或时间。旧原因保留在旧审核节点，不能复制为新提交的当前原因；面客审核人员统一显示“运营审核 / Operations review”，不展示真实审核员身份。

只保留一份当前认证资料，历史保留的是提交／审核动作及原因，不提供历史材料回看、下载、版本切换、比较或回退。旧通知只能对应其原提交及记录，不能把当前材料冒充旧材料，也不能据旧通过记录授予当前资格。审核行为与结论只读保护按机构认证审核执行。

<a id="state-contract"></a>
### 4.2 两组状态及允许动作

<a id="F-L66"></a><a id="f-l66"></a>**账户与注册状态（F-L66）**：账户可用性（正常／已停用）与机构注册状态分别维护。资金方账户在首次成功提交时建立，账户上的注册状态只有审核中、已驳回、已认证三种；“未提交”表示尚未建立资金方账户（登录未绑定角色，可在入驻流程中首次填写），不是账户上保存的状态。没有“草稿”“锁定”“凭据不完整”等额外状态。机构注册不存在终态：已认证仍可成功提交变更进入新一轮审核。

| 机构注册状态与用户标签 | 正常登录时资格 | 允许的资料动作 | 可以如何改变状态 |
| --- | --- | --- | --- |
| 未提交（尚无资金方账户）／Registration not submitted | 未认证（登录未绑定角色） | 在入驻流程中填写并提交；提交前表单内容不保存、材料仅临时保留；可浏览可达内容，但不能办理认证业务 | 首次成功提交 → 审核中（同时建立资金方账户） |
| 审核中／Under review | 未认证 | 当前申请与材料只读；账户联系邮箱仍可改 | 本次有效人工审核 → 已认证或已驳回 |
| 已驳回／Rejected | 未认证 | 查看原文原因，编辑并重提；累计重提无上限 | 成功重提 → 审核中 |
| 已认证／Verified | 已认证 | 查看、编辑变更内容；成功提交前保留认证资格与当前已提交资料 | 确认并成功提交变更 → 审核中 |

正常登录时呈现资金方本人身份和对应注册资格；账户标识不作为用户可编辑字段。共用含义及状态展示引用[主干状态与资格规则](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#state-contract)。

审核中、已驳回、已认证任一状态的资金方账户被停用或无有效登录时，对外回游客，角色和账户标识为空，不开放本人保护数据；底层原注册状态保留。停用使该账户全部会话立即失效；恢复只恢复可登录能力，需重新正常登录后按原注册状态获得相应认证资格，不自动恢复旧会话或变为已认证。限制访问不依赖收件或阅读。**本期产品内没有资金方账户停用／恢复的操作入口**，停用与恢复只在数据层处理，上述效果在账户状态实际变化时适用；本期不触发账户停用／恢复通知，见[通知册](./03-资金方登录与账户体系-消息通知.md#notification-policy)。

<a id="F-L67"></a><a id="f-l67"></a>**当前资格同步（F-L67）**：登录、退出、提交成功、有效审核结果到达和会话失效后同步当前状态与权限；进入需要判权限的功能时重新确认当前权威结果，不自行用旧资料推算资格。共用状态的既定约束见[登录主干](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#state-contract)，各入口读到的资格必须一致。审核中不能直接回未提交；已认证或已驳回账户必须先成功提交本轮机构资料，进入审核中后才能得到新的审核结论。不得仅修改认证资格而保留矛盾的注册状态。

<a id="permissions"></a>

### 5.3 本人资料及业务必要信息

机构注册、申请状态与审核记录、用户信息的个人、企业档案、联系信息、证件及认证材料只归本人。认证通过、同企业、同钱包的另一身份不扩大可见范围；普通运营只能在机构认证审核指定审核场景查看对应已提交材料及记录，不据此查看未提交内容、账户档案或代改资料。

### 5.5 企业账户入口与账户归属

<a id="F-L79"></a><a id="f-l79"></a>**企业账户入口与账户归属（F-L79）**：资金方用于收取还款的本企业法币账户与数币账户不在“用户信息”维护，统一在[企业账户](../03-企业账户/01-企业账户-PRD.md)模块按本企业登记，业务办理时从已登记账户中下拉选用。本册只负责入口挂载与权限取值，不定义账户字段与校验；企业账户不设默认账户。

| 事项 | 本册的业务要求 |
| --- | --- |
| 入口 | 账户菜单第三项，**资金方侧显示“机构账户”**（资产方侧显示“企业账户”，字段与模块口径统一为“企业账户”，见[账户菜单](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#account-menu)）；两侧同一入口、同一套字段与维护动作。**“用户信息”内不展示、不采集、不校验任何法币账户或数币账户字段**，也不在其中另设跳转 |
| 可见与可用 | 已建立资金方账户的用户才有该入口：审核中、已驳回可见并可进入，进入后按当前注册状态说明需先完成机构认证，不能新增、修改或删除；已认证可完整维护。**未提交即尚未建立资金方账户，不展示该入口**，触发资金方动作时按动作分流先进入入驻流程。取值同企业账户模块的[谁能使用（P-EA-01）](../03-企业账户/01-企业账户-PRD.md#p-ea-01)，本期只维护本企业的法币账户与数币账户，出账（付款）账户不采集 |
| 业务办理 | 业务办理过程中不提供新增、就地编辑或删除账户的入口，也不允许手输账户信息替代已登记账户；本企业尚无可用账户时说明并指向企业账户，登记完成后回到原办理的原位置继续，已填内容不丢失，见企业账户模块的[业务办理中选用账户（F-EA-07）](../03-企业账户/01-企业账户-PRD.md#f-ea-07) |
| 登录边界 | 为登记数币地址而发起的一次性地址所有权签名不是登录，不建立新会话、不切换钱包、不改变本账户的登录地址，也不属于[钱包不可改绑](#F-L75)所拒绝的改绑请求，不产生改绑拒绝留痕；登录主干的[登录签名规则](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#signature-rules)不因此改变 |

本模块本期不因企业账户产生站内信，账户的新增、修改与删除均不发本册通知（企业账户不设默认账户）。

## 6. 会话、退出与账户安全

<a id="F-L69"></a><a id="f-l69"></a>**会话有效期（F-L69）**：资金方会话自登录成功起 **4 小时**有效，为绝对有效期，期间操作不延长；到期即失效，不提供“记住我”或更长会话选项。失效回游客并就地说明，可继续浏览可达内容，不打断要求立即登录，也不把用户带到只有报错、无法继续的结果。填写中失效不得继续填写或提交；未提交内容不保留，重新登录后需重新填写。

<a id="F-L70"></a><a id="f-l70"></a>**主动退出（F-L70）**：退出入口唯一，不在其他位置另设退出；退出使该账户各设备会话全部失效，回游客，保护功能和本人资料不可继续访问，按[共用退出规则](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#session)落到可浏览位置。退出不强制断开钱包连接，但必须明确显示为未登录。停用同样结束全部会话；邮箱修改不结束会话。

<a id="F-L72"></a><a id="f-l72"></a>**钱包断连与地址切换（F-L72）**：钱包插件单独断开连接不等于平台退出：有效平台会话仍保留，提示钱包未连接，下一次签名操作才要求重连。钱包从 A 切到 B 时提示登录账户与钱包地址不同并提供“用该地址重新登录”：先结束当前登录，再用地址 B 发起登录（登录状态下不直接切换钱包，见[登录主干的取消、不可用与更换钱包](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#F-L03)）；不静默切换当前账户、改变 A 账户的登录地址或沿用 A 的再认证结果证明 B。

保留登录成功／失败、资金方账户建立、联系邮箱验证生效／变更、提交及审核状态变化、拒绝改绑、拒绝审核中修改机构资料、停用／恢复的必要业务留痕；敏感内容不泄露到日志或通知。访问与业务动作均校验当前身份、归属和状态。不得索取私钥，不编造性能指标、留存天数或新的锁定策略。
