# 融资需求与代币质押 · 消息通知

2026-10-15｜需求评审稿

本册写本模块发送的站内信，规则以[功能与业务规则](./01-融资需求与代币质押-PRD.md)为准。只有站内信，没有邮件、短信、浏览器推送或运营广播。

- 本模块自己发送 5 类：链上操作失败、融资需求终结、质押不足、质押不足解除、项目届满前 7 天。
- 另有 4 类与本模块业务相关、但由相邻模块发送：项目审核通过与退回由[运营端项目合约管理](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md)发送，逐张质押审核通过与驳回由[代币质押审核](../../运营端/06-代币质押审核/01-代币质押审核-PRD.md)发送。它们的模板沿现行约定在本册维护，触发与收件以发送模块为准。
- 资产广场、我的控制台和消息中心展示同一事实，不各自补发。
- 本期一个企业只有一个账号；发给“资产方”的消息即发给该企业的唯一账号。

编号说明：事件编号（N-LS-*）与模板编号（T-LS-*）被其他模块引用，沿用原值；缺号不代表遗漏。

## 3. 不发送的情况

- 创建项目提交、发起质押签名、发布、改额、撤下、关闭等操作的当场结果。
- 审核过程中的提醒与催办；协议上传等过程。
- 上链已发起、处理中、成功；批次整体进度；全批已审。
- 链上结果长期未知、跨期、冲突，以及联系客服的进度。
- 可提取、提取成功。
- 项目到期前 30 天、到期当天。
- 质押不足持续期间仅金额变化。
- 项目长期停留空池、空池数量变化、待审质押额变化。
- 合约签名或部署失败与再次发起（平台内部重试）。
- 平台默认 SPV 机构名称或平台钱包随版本更新。
- 浏览、复制、下载、页面读取失败与代币同步。

## 4. 重复与新事实

- 同一账号、同一事件、同一业务事实只收一条：项目审核按本次结论区分，逐张审核按本次单笔，链上失败按本次动作和代币，需求终结按原轮次，质押不足按本轮触发或解除，届满提醒按项目有效期。
- 重复送达不新增未读、不恢复未读、不置顶、不改发生时间；补齐原因或费用不重发。
- 新的单笔、新的实际动作、新一轮质押不足、重新提交后的新结论，各自是新事实，各发一条。
- 同批多笔各自发送，不合并成一条“全批已审”。
- 消息保存发生时的事实；点击时按当前权限与阶段判断。旧消息仍指向原对象，不开新轮、不自动执行；无权或目标不可用时按消息中心的既有降级处理，不泄露私有文件、钱包或下载链接。
- 资产方与资金方账号、面客端与运营端相互隔离；同钱包、同企业、同机构不自动串信。无法确定归属时不改投他人。
- 投递失败不回滚业务，用户仍可从业务本身查到结果。符合条件的消息在消息中心既有的 60 秒内可见。

## 5. 文案

固定文案提供中英两套，变量集合一致。时间按 UTC 判定、按收件人时区显示并标注；金额带币种；未知的 gas 写“待核实”，不写 0；人工原因原样展示，不截断。

| 变量 | 业务含义 |
| --- | --- |
| project_name / project_id | 发生事件的项目名称与项目编号 |
| token_id | 代币的完整业务编号，不是钱包地址或链上 tokenId |
| action_id | 本次实际链上动作的业务标识，用于区分同一代币的多次操作 |
| demand_id | 终结的那一轮融资申请编号 |
| approved_at | 真实通过时间 |
| occurred_at / expires_at | 事件发生时点；项目有效期至 |
| reason | 面客可读的原因全文：驳回取审核原文，链上失败取失败说明 |
| shortfall / additional_value | 事件发生时的质押缺口与需追加资产价值，USD，两位小数 |
| fee_amount / fee_currency | 已确认实际产生的 gas 金额与币种 |
| contract_address | 本项目质押合约地址 |
