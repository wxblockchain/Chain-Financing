## 1. 模块是什么

资产方在借贷广场创建融资项目，项目通过审核后平台为它部署一份专属的质押合约；资产方把本企业的代币签名转入这份合约，代币经运营逐张审核通过后才计入可用于融资的额度；资产方据此发布融资需求，资金方报价，成交后进入放款与还款。一个融资项目就是一只资产池，可以先后承接多轮融资需求和多笔存量业务。本模块负责项目、代币质押、额度与质押情况的判断，以及项目详情里四类记录的查看与办理入口。

基本原则：

- 项目、代币上链、逐张审核是三件独立的事：项目审核决定项目能不能用，上链结果决定代币在不在合约里，逐张审核决定这张代币算不算有效质押额。代币在合约内不等于已通过审核。
- 所有链上动作（质押、解押、提取）都由资产方本人用钱包签名发起，gas 由资产方承担、失败不退；平台不代签、不代付。项目合约部署的 gas 由平台承担。
- 只有通过审核的有效质押才能支撑融资；新增占用必须始终满足“有效质押额 ≥ 项目融资余额＋项目在途金额”。
- 全流程没有倒计时：项目审核、逐张审核、报价都不因等待而自动改变结论。
- 链上结果长期未知、冲突等异常只提示联系平台客服，本期不建设异常处置流程。

**一个完整的例子。** 资产方甲从借贷广场点击“创建融资项目”，填写项目名称、选择代币类型“ERC-20-应收账款”、填写质押率 80%、选择一年后的到期日、勾选参考结算币种 USDT，核对平台带出的还款方式与 SPV 机构名称后提交；项目进入待审核，此时不签名、不付费。运营核对通过后，平台钱包部署本项目的质押合约，部署成功即审核通过，项目变为可用，甲收到“项目审核通过”站内信，信中带合约地址。甲进入项目详情，勾选三张代币，点击“签名并发起质押”，在钱包签名；三张代币上链成功，先计入待审质押额。运营逐张审核：两张通过，计入有效质押额；一张驳回，甲看到原因后自助解押取回。甲在项目办理区看到当前可融金额，发布一轮 50 万 USD 的融资需求；资金方乙报价，甲接受，乙登记放款、甲确认到账后，这一轮结束，甲可以按当时的可融金额发布下一轮。还款全部结清后项目转为已结清，池内代币变为“已释放待提取”，甲签名提取回原地址。

### 1.1 本期不做

- 代币上架审批：代币同步到本平台即可选用。
- 部分数量质押：资产方在一个持有地址上持有的某笔代币，只能整份质押，不能拆出一部分数量质押。
- 平台代签、代付或垫付 gas。
- 抵押物处置或变现。
- 异常处置系统：工单、自动升级、人工改判、强制释放、补偿。
- 指定代币转出的目的地址：一律转回质押前的原持有地址。
- 单笔融资业务的中途终止。
- 全项目操作日志、公开批量导出。
- 健康评分、风险等级、黑名单等评价性标签。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 融资项目（资产池） | 资产方创建的一个融资单位，对应一份质押合约，可承接多轮融资需求 |
| 项目发布方 | 创建并发布这个融资项目的资产方企业。它不是 SPV 机构（全平台同一个名称），也不是代币的发行方或持有方：一个项目内的代币可以来自不同发行方 |
| 质押合约 | 项目审核通过时由平台统一钱包为本项目部署的合约，项目与合约一一对应 |
| 持有方 | 当前持有一笔代币某一部分数量的链上地址，口径同[资产广场](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-14)。一笔代币可以有多个持有方，各持一部分，可以分属不同融资项目 |
| 质押份额（张） | 本企业的一个持有地址上持有的某笔代币的全部数量，是质押、审核、解押与提取的最小单位，只能整份办理，不能拆分数量。本册所说的“一张代币”“逐张”“张数”都指质押份额，不是一笔代币的全部数量 |
| 份额价值 | 一份质押份额的价值 = 持有数量 × 该笔代币价值 ÷ 该笔代币数量，USD，按签发价值折算，口径同资产广场的“对应价值” |
| 项目审核 | 运营核对创建信息并部署合约；部署成功即审核通过，结论只有通过与退回 |
| 空池 | 项目已可用，但还没有任何一张通过审核的质押代币 |
| 质押上链 | 资产方用代币持有地址签名，把代币转入本项目质押合约 |
| 自助解押 | 资产方签名把合约内的代币转回原持有地址，不经运营审核 |
| 提取 | 项目关闭或结清后，资产方签名取回“已释放待提取”的代币 |
| 总质押额 | 合约内全部质押份额的份额价值合计，含失效和未通过审核的份额 |
| 待审质押额 | 已在合约内、但尚未计入有效质押价值的份额价值，包括待审核的和已驳回未解押的 |
| 有效质押价值 | 审核通过、实际在池、发行平台判有效且无差异的质押份额的份额价值合计 |
| 有效质押额 | 有效质押价值 × 项目质押率，即本项目能支撑的融资上限 |
| 项目融资余额 | 本项目已放款、尚未偿还的本金合计（项目统计中显示为“已融资余额”） |
| 项目在途金额 | 已发布、尚未终结的融资需求金额合计 |
| 可融金额 | 有效质押额减去项目融资余额和项目在途金额，最小为 0 |
| 可撤回上限 | 可融金额 ÷ 项目质押率，只约束已通过审核的有效抵押物撤回 |
| 质押情况 | 项目级判断：有效质押额是否足以覆盖融资余额与在途，取值质押充足、质押持平、质押不足。不同于单张代币的“质押状态” |
| 质押缺口 | 质押不足时，项目融资余额减有效质押额 |
| 质押水位 | 有效质押额与“项目融资余额＋项目在途金额”的比较。前者不低于后者为水位安全，低于为水位不安全；水位不安全时需求失效、已通过审核的代币不能转出 |
| 一轮融资需求（融资申请） | 资产方发布的一次融资需求，有自己的融资申请编号；一个项目同一时刻只有一轮在途 |
| 本环节 | 一轮融资需求从发布到其成交业务完成放款确认的过程；本环节结束前不能发布下一轮 |
| 质押链 / 结算收款链 | 质押链是代币与质押合约所在的链，即创建项目时选择的区块链网络，本期仅以太坊（ETH）；结算收款链是数币收款地址所在的链（ETH 或 TRON），由企业账户模块定义。两者互不决定 |
| 登录未绑定角色 | 已用钱包登录，但本平台既不是资金方、也调取不到上游资产方账户的用户 |

## 3. 共同规则

<a id="roles"></a>
### 3.1 角色与可见范围

| 角色 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| 游客（未登录） | 浏览借贷广场列表；在项目详情只看到项目基本信息，规则见[项目详情按身份的可见范围（F-LS-82）](#f-ls-82) | 任何写操作；看到项目基本信息以外的详情内容；看到待审核、已退回或尚未发布的项目 |
| 登录未绑定角色 | 浏览借贷广场列表；在项目详情只看到项目基本信息，规则见[项目详情按身份的可见范围（F-LS-82）](#f-ls-82) | 创建融资项目；看到项目基本信息以外的详情内容；任何写操作 |
| 资产方 | 创建项目并提交审核；签名发起质押、解押与提取；发布和管理融资需求；关闭项目；办理本方的履约事项；本企业项目的详情全部可见 | 其他企业的项目只看到基本信息；看到或办理其他企业的私有项目与资料 |
| 资金方 | 浏览借贷广场列表；查看所有已发布项目的详情；按本机构资格办理报价、放款和还款确认 | 资产方的私有资料与私有待办；其他机构的报价、授信、账户与协议；未认证或审核中不等于可以出资 |
| 平台运营 | 在运营端做项目审核与合约部署、逐张质押审核，查看既有待办与监控 | 在面客端裁定审核或代资产方执行 |

- 个人与企业账户档案只有本人能看。业务必要的项目、企业名称、代币信息按本业务权限展示，不能因此开放对方的整份账户档案。
- 授信、账户、协议、凭证、联系方式、底层合同号与发票号、运营诊断都不是公开融资信息。
- 查看、下载和直接提交都由服务端检查权限；隐藏入口不能代替权限控制。
- 登录资格与本人资料沿[登录主干](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md)和[资金方账户](../02-资金方登录与账户体系/01-资金方登录与账户体系-PRD.md)；上游代币事实沿[资产广场](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md)。

<a id="interaction"></a><a id="F-LS-20"></a><a id="f-ls-20"></a>
### 3.2 查看与办理分开（F-LS-20）

项目详情同时提供四类记录：质押代币清单、融资申请信息、融资放款信息、还款信息，按此顺序讲述；定位到其中一类时，其余三类仍可得。办理按质押、融资、还款三类业务归集，三类入口在项目详情始终可达。以上只适用于能看到项目完整详情的身份（本企业资产方、资金方），其他身份见[项目详情按身份的可见范围（F-LS-82）](#f-ls-82)。各清单独立保留筛选和页码，空态与读取失败分别呈现。

| 用户动作 | 结果 |
| --- | --- |
| 从记录查看详情 | 只读呈现当前记录、历史、计划、账户和文件；不提供办理、跨业务跳转或重复的查看入口。历史与预览在本次查看内展开，文件按权限下载 |
| 从办理入口办理 | 先明确是哪一轮申请、哪一笔业务或哪一期，再进入本次办理；多笔待办时不默认代选最新一笔。步骤、必要确认与放弃修改都在本次办理内完成，不再叠加下一层办理 |
| 返回或关闭 | 返回上一步时保留已填内容和已成功的附件；有未提交的编辑时就地确认是否放弃。关闭后回到来源，保留原筛选、分页与所在位置；关闭只读详情不改变业务 |
| 成功、失败或结果未知 | 成功只更新本笔及相关办理入口，不自动打开详情、下一笔或下一阶段。失败保留可复用的输入；结果未知显示待核实，不假报成功，也不引导重复提交 |

- 发布、发起质押、报价成功后都结束本次办理。授信保存成功同样结束本次办理并提示“已授信，请继续报价”，需要用户再次发起报价。
- 报价、发起质押、解除质押与提取都不设二次确认；其余动作保留原有的必要确认。
<a id="D-LS-61"></a><a id="d-ls-61"></a>
- **自动带入（D-LS-61）**：平台已知且有权使用的本笔信息自动带入，优先本笔已确认的事实，其次是同企业、同用途、同币种的有效登记资料；只补业务必需的缺项。只读事实不能改写，可编辑项仍要校验，规定的逐笔确认不能省略。不得串用不同机构、企业或用途的账户，也不得把旧合同、旧转账凭证默认用于新业务；资料缺失或读取失败时不填示例值或零值。

<a id="quality"></a>
### 3.3 日期、金额与展示

- 业务日期一律按 UTC 判定；展示按用户偏好时区，游客按浏览器时区，时间都标注时区。切换时区不改变任何业务日期。
- USD 需求金额与额度按两位小数展示，计算过程不提前舍入；代币数量、签发价值和原币应收金额不能混加。
- 实际 gas 按费用资产自身的精度展示，未知时标“待核实”，不填 0。
- 界面支持中英双语，默认英文，切换语言即时生效。状态都有文字表达，不只靠颜色区分；代币编号、价值、状态和质押情况在任何展示条件下都不被省略。
- 内部状态编号（如 PS-、CT-）不出现在面客文案或访问地址中。
- 正常浏览不受影响；异常高频访问受限并提示必要验证；不提供公开批量导出。

<a id="facts"></a>
### 3.4 事实来源与链上凭证

- 代币、持有地址与失效状态取本平台只读代币域，本平台不回查上游或读链。
- 质押事实以本平台为准，并回传发行平台；本平台不读取上游带来的质押状态。
- 链上凭证（Hash、合约地址）给出完整值，可以复制，可以自行打开区块链浏览器查验，并明确标注平台未做链上核验，沿资产广场的同名口径。
- 质押链本期仅 ETH，只展示、不提供选择；与结算收款链分别表达，不共用同一个“链”字段。

<a id="exceptions"></a><a id="D-LS-63"></a><a id="d-ls-63"></a>
### 3.5 异常只提示联系客服（D-LS-63）

- 链上结果长期未知、已发起但项目已进入终态、事实冲突，以及多张结果中待核实的那几张，提示“链上结果待核实，请联系平台客服人员”，并保留业务编号、代币、动作、已知 gas、凭证和保护限制。
- 带对账差异的代币不计入有效质押，冻结它的一切新动作，并触发重算。
- 不提供工单、自动升级、人工改判或补记、强制释放、补偿、换地址或恢复资格流程；不编造联系方式或处理时限。客服介入不等于自动完成、退款或恢复。
- 普通的晚到结果（不跨期、不冲突）按原笔更新。项目已进入终态后才到达的转入结果，只记录代币的真实持有位置，不恢复项目或有效质押。

### 3.6 已确认的性能目标

列表首批 20 条 2 秒内可得；额度预览 200 毫秒内、提交时的权威重算 1 秒内完成；链上操作已发起后 1 秒内反馈“已发起·处理中”，不误称已完成。实现与验证归研发、测试。

<a id="browse"></a><a id="F-LS-10"></a><a id="f-ls-10"></a>
## 4. 借贷广场项目列表（F-LS-10）

适用角色：所有人，包括游客和登录未绑定角色。

- 一条记录一个项目；只列出已发布过融资需求的项目，待审核、已退回、可用但从未发布的项目不出现，也不暴露是否存在。
- 每条展示项目名称、项目发布方、有效质押额、当前需求金额与币种及其状态、质押情况。没有当前需求时显示“暂无融资需求”。
- 只显示中性的质押情况与缺口，不显示评价性标签。
- 支持按币种、期限、关键词筛选；默认按发布时间倒序，可按需求金额、总质押额排序。
- 每批 20 条，已显示的数量可得；继续浏览时自动追加下一批，已加载内容不丢失。不能按页码定位，也不能改变每批条数。换排序或重置筛选时从新条件的第一批重新开始。
- 从条目可进入项目详情；列表不提供逐条办理动作。从详情返回时保留原筛选、排序与已加载范围，并回到原来所在的条目。
- 暂无项目、筛选无结果、读取失败分别呈现；后两种分别提供清空筛选与重试。

<a id="F-LS-11"></a><a id="f-ls-11"></a>
## 5. 项目详情（F-LS-11）

适用角色：本企业资产方看本企业项目的全部详情，包括待审核、已退回和可用项目；资金方看所有已发布项目的详情；游客、登录未绑定角色和其他企业的资产方只看到基本信息，见[项目详情按身份的可见范围（F-LS-82）](#f-ls-82)。

- 项目摘要包含：项目名称、项目编号、项目发布方、SPV 机构名称、本项目质押合约（见 5.2）、项目期限与到期日、项目状态。
- 当前需求金额与需求状态单独可辨，不与项目状态混为一项。
- 详情同时提供四类记录与三类办理入口，规则见[查看与办理分开（F-LS-20）](#f-ls-20)；资金方只看到本机构可办理的事项，不展示资产方的私有待办。

<a id="F-LS-18"></a><a id="f-ls-18"></a>
### 5.1 项目统计（F-LS-18）

- 项目统计固定六项：总质押额、待审质押额、有效质押额、本轮融资需求、已融资余额（即项目融资余额）、项目质押率。
- 上链处理中的代币不计入任何一项；已上链但未通过审核的代币计入待审质押额，通过后转入有效质押额。
- 项目在途金额不作常态展示。
- 可融金额不进入项目统计，只向本企业资产方在两处给出：一是项目办理区的发布融资需求环节，在没有进行中需求时常驻展示当前可融金额；二是发布或改额办理时，给出当场重算的可融金额与差额。游客、资金方和其他企业在任何位置都看不到可融金额。
- 两者都不另行提供换算说明。

<a id="F-LS-81"></a><a id="f-ls-81"></a>
### 5.2 项目详情展示质押合约（F-LS-81）

项目与质押合约一一对应。在整个项目详情中，读者始终能辨认本项目对应的那一份合约：定位到任一类记录、打开只读详情，或进入质押、解除质押、提取办理时，合约信息都仍然可得。

| 信息 | 谁能看到 | 规则 |
| --- | --- | --- |
| [质押合约地址（FP-33）](#fp-33) | 能看到本项目完整详情的身份（本企业资产方、资金方） | 给出完整值，可复制，可自行打开区块链浏览器查验，并标注平台未做链上核验；不能只给缩略值 |
| 质押链 | 能看到本项目完整详情的身份（本企业资产方、资金方） | 即创建时选择的[区块链网络（FP-39）](#fp-39)，本期仅以太坊（ETH） |
| [合约部署完成时间（FP-38）](#fp-38) | 能看到本项目完整详情的身份（本企业资产方、资金方） | 部署成功（即审核通过）的时刻，标注时区 |

- 待审核与已退回的项目只有本企业资产方能看到，此时还没有合约：只说明“审核通过后由平台部署本项目质押合约”，不显示地址占位值、部署时间或半成品地址。部署失败后再次发起期间同样如此。
- 项目已关闭或已结清后，合约信息照常展示，因为未提取的代币仍在合约内。
- 资产方发起质押、自助解押或提取时，签名前的告知都给出本次目标质押合约地址，与项目详情所示为同一值；一次办理中不出现其他项目的合约。

<a id="F-LS-82"></a><a id="f-ls-82"></a>
### 5.3 项目详情按身份的可见范围（F-LS-82）

项目详情的可见范围按当前身份与项目归属决定：

| 身份 | 看到什么 | 不可见处的说明与入口 |
| --- | --- | --- |
| 游客（未登录，含登录时身份调取失败、本次登录未成立） | 只看到项目基本信息 | 说明需登录后才能查看，并提供“立即登录”入口；登录后回到本项目，按新身份重新判断 |
| 登录未绑定角色 | 只看到项目基本信息 | 统一说明“以下信息仅供资金方查看”，并提供“申请成为资金方”入口 |
| 资产方查看本企业的项目 | 全部信息，包括本企业待审核、已退回和可用的私有项目 | 不适用 |
| 资产方查看其他企业的项目 | 只看到项目基本信息 | 统一说明“非自身项目，无法查看”；不提示申请成为资金方，也不提供其他入口 |
| 资金方 | 所有已发布项目的详情：项目摘要、项目统计、质押情况与缺口、质押合约、四类记录 | 不适用；私有内容仍按当事方开放，见下方 |

- **项目基本信息**：项目名称、项目编号、项目发布方、项目状态、代币类型、项目期限（生效日～到期日）。
- 只看到基本信息的身份，其余内容一律不展示，也不能通过直接访问取得，包括：项目统计、质押情况与质押缺口、质押合约信息、SPV 机构名称、参考结算币种、四类记录及其详情、办理入口与待办。
- 待审核、已退回和尚未发布的项目只有本企业资产方能看到；资金方在内的其他身份都看不到，也不暴露是否存在。
- 凡已绑定资金方角色的账号都按资金方的范围查看，包括入驻审核中或已驳回的；可看不等于可以出资。
- **资金方看到的私有边界**：资金方能看所有已发布项目的详情，但以下内容仍只对相应当事方开放：
  - 报价条款、授信、账户、协议与凭证，只对该笔业务的资产方与报价机构开放；
  - 可融金额只对本企业资产方给出；
  - 逐张质押的审核状态、驳回原因、上链结果与 gas 只对本企业资产方开放，资金方只看到代币是否计入有效质押。
- “申请成为资金方”进入资金方入驻流程，规则沿[资金方账户的入驻引导与返回](../02-资金方登录与账户体系/01-资金方登录与账户体系-PRD.md#F-L57)；取消入驻回到本项目详情，仍只看到基本信息。提交入驻申请后即为资金方，按资金方的范围查看；入驻审核尚未通过不等于可以出资。
- 借贷广场列表不按身份收窄：所有身份看到的列表字段相同，见[借贷广场项目列表（F-LS-10）](#f-ls-10)。

## 6. 创建融资项目并提交审核

<a id="create-entry"></a><a id="F-LS-80"></a><a id="f-ls-80"></a>
### 6.1 创建入口（F-LS-80）

- 借贷广场的“创建融资项目”入口只对判定为资产方的用户显示。
- 游客（含登录时身份调取失败、本次登录未成立的情况）、登录未绑定角色和资金方都看不到这个入口。
- 不具备资产方身份时，直接访问创建地址或直接提交创建一律被拒绝，且不暴露任何企业的项目。
- 资产方也可从控制台进入创建，控制台入口沿控制台现有的可见范围。

<a id="F-LS-01"></a><a id="f-ls-01"></a>
### 6.2 填写创建信息并提交（F-LS-01）

适用角色与前提：本企业资产方。

- 资产方先选择区块链网络，再填写项目名称、选择代币类型、填写项目质押率、选择项目到期日、选择参考结算币种，核对平台带出的还款方式与 SPV 机构名称后提交。
- 提交即进入项目审核。创建本身不勾选代币、不发生链上操作、不需要签名、不产生任何费用；提交前的说明首句就讲清这一点。
- 一个融资项目对应一份质押合约。
- 创建与质押是两次独立的办理，不串成一次连续流程；创建过程也不包含发布步骤。

| 创建信息 | 含义与类型 | 必填与默认 | 可编辑范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| <a id="FP-39"></a><a id="fp-39"></a>区块链网络（FP-39） | 单选，本项目的质押链：质押合约部署在这条网络上，只有铸造链为该网络的代币可以质押 | 本期只有以太坊（ETH）一个选项，默认选中 | 本期不可更改；创建时随项目锁定，之后只读 | 选项增加前不提供其他网络；不能为空 |
| <a id="FP-02"></a><a id="fp-02"></a>项目名称（FP-02） | 文本 | 必填，1～60 个字符 | 合约部署完成前可修改，之后只读 | 同企业不要求唯一，同名项目以项目编号区分；空值或超过 60 个字符不能提交 |
| <a id="FP-29"></a><a id="fp-29"></a>代币类型（FP-29） | 单选，取运营已配置的代币类型，形如“ERC-20-应收账款”（代币标准与底层资产类型合为一个字段） | 必选；候选只来自本企业在只读代币域已有代币的类型 | 合约部署完成后只读；本项目此后只接受同类型代币 | 不能自定义输入；没有可选类型时不能提交，并提示先完成代币发行与同步。字段须能容纳将来的其他代币标准，不写死 ERC-20 |
| <a id="FP-34"></a><a id="fp-34"></a>项目质押率（FP-34） | 百分比，资产方自填 | 必填 | 创建时锁定终身；合约部署完成后只读 | 大于 0、不超过运营对该代币类型配置的[最高质押率（FC-02）](../../运营端/02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#fc-02)，最多两位小数。超过上限不能提交并给出当前上限；0、负数或超过两位小数不能提交并给出允许范围，不自动四舍五入。锁定后运营调整配置不影响本项目，全部额度计算都用锁定值 |
| <a id="FP-35"></a><a id="fp-35"></a>项目期限（FP-35） | 生效日～到期日。生效日就是项目创建日，自动带出、只读；到期日用日期选择，不提供月数或天数输入 | 到期日必选 | 合约部署完成后只读；审核退回重提时可在同一规则内重选 | 见下方“到期日规则” |
| <a id="FP-30"></a><a id="fp-30"></a>参考结算币种（FP-30） | 多选：USD（法币）、USDT、USDC（数币），可跨类选择 | 必选至少一项，首次默认空 | 随项目锁定；各轮需求沿用，发布和改额时只读带出 | 不支持的币种不能提交。它只供参考，不限制资金方选择任何已支持的报价币种，也不决定实际币种、额度或合同 |
| <a id="FP-36"></a><a id="fp-36"></a>还款方式（FP-36） | 平台定值：按季付息、到期还本付息 | 创建时自动带出 | 只读，不提供选择 | 不按企业或项目区分 |
| <a id="FP-31"></a><a id="fp-31"></a>SPV机构名称（FP-31） | 平台默认的单一机构名称，取值在代码层面维护、随版本发布 | 创建时自动带出并随项目留存 | 只读；面客端与运营端都没有维护、配置、切换入口 | 不会出现空值或占位名。版本更新默认值只影响此后新建的项目，不改写已创建项目，也不产生通知 |
| 企业与项目编号 | 企业取当前登录企业；项目编号创建时生成 | 系统生成 | 只读 | 项目编号全局唯一、终身不变 |

<a id="D-LS-66"></a><a id="d-ls-66"></a>**到期日规则。** 可选的到期日同时满足以下三条：

1. 不早于创建日 + 3 个月。
2. 不晚于创建日 + 该代币类型的[最长项目期限（FC-03）](../../运营端/02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#fc-03)，且不超过创建日 + 1 年；两端都可选。
3. 晚于当前日期，当天和过去的日期都不可选。

- “加 N 个月”取目标月的同一天；目标月没有这一天时取该月最后一天。例如 11 月 30 日加 3 个月为次年 2 月的最后一天。
- 日期按 UTC 业务日期判定。
- 可选范围外的日期不能选；提交时按当刻条件复核，越界不能提交，并给出当前可选的起止日。
- 该代币类型未配置最长项目期限时不能提交，并说明原因。
- 审核退回后修改重提：生效日仍是原创建日，不重新起算；第 1、2 条仍按创建时锁定的最长项目期限，第 3 条按重提当日判断。三条不能同时满足时本项目不能重提，可另建项目。

<a id="F-LS-12"></a><a id="f-ls-12"></a>
### 6.3 待审核、退回重提与空池（F-LS-12）

- 提交后项目进入待审核，属本企业私有：不出现在广场，不暴露存在性；不能发起质押，也不能发布融资需求；创建信息不能修改。
- 审核通过（即合约部署成功）后项目转为可用，资产方可在项目详情[发起代币质押](#pledge-apply)。审核通过后不自动进入质押办理，也不自动勾选代币。
- 审核退回时给出面客可读的原因，资产方可以修改后重新提交；重提不产生新项目、不产生新项目编号，生效日不变。
- 项目通过审核后、第一张代币通过质押审核前是空池：发布入口可见但不能提交，并说明“本项目暂无有效质押，请先完成代币质押后再发布”。
- 项目可以长期停留在空池，随时可以发起质押或按条件关闭；不会因未质押被自动关闭、清除或催办。
- 同一企业可同时存在的空池项目不设数量上限，创建不因已有空池项目被拦截或提示。
- 质押全部被驳回、撤回或上链失败后，项目回到空池，可以重新发起质押。
- 创建、质押、发布各自可以中断后再继续，不要求重复质押或重复付费。

<a id="project-review"></a><a id="F-LS-22"></a><a id="f-ls-22"></a>
## 7. 项目审核与合约部署（F-LS-22）

适用角色：运营在运营端办理，规则见[运营端项目合约管理](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md)；本节只写面客端看到的结果。

- 审核与部署是同一步：运营核对通过后，由平台统一钱包部署本项目的质押合约；部署成功即视为审核通过，同时产生本项目的合约地址。
- 审核结论只有通过与退回两种，没有时限：不会因等待而自动通过或自动失败。
- 退回必须给出面客可读的原因；资产方修改后重新提交，仍走同一条审核与部署流程。
- 签名或部署失败视为审核未完成，项目仍为待审核，由运营再次发起；不需要资产方重新提交，不改变生效日，不产生第二个项目，也不向资产方发消息。
- 部署 gas 由平台承担，资产方不签名也不付费；运营人员只做业务操作，不签名。平台统一钱包在代码层面维护，平台不提供维护、配置或切换入口。
- 通知：审核通过与审核退回各由运营端项目合约管理发送一条站内信，模板见[消息通知册](./03-融资需求与代币质押-消息通知.md#t-ls-09)。

<a id="D-LS-71"></a><a id="d-ls-71"></a>**部署进行中暂不可关闭（D-LS-71）。**

- 运营已提交通过、平台正在部署合约而结果尚未回写期间（含结果待核实），资产方不能关闭项目。
- 此时项目对资产方仍显示待审核；关闭入口可见但不能提交，并说明暂不可关闭，不透露部署失败或重试等运营端细节。直接提交关闭同样被拒绝，项目与代币都不变化。
- 部署结果回写后按结果处理：部署成功即审核通过，项目转为可用，此后按可用状态的条件关闭；部署失败则项目仍为待审核，可以关闭。
- 资产方关闭与运营提交通过同时发生时，只有先生效的一笔成立。
- 运营端的对应规则见[运营端项目合约管理](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#states)。

| 项目审核信息 | 含义与类型 | 何时有值 | 可见范围 | 规则 |
| --- | --- | --- | --- | --- |
| <a id="FP-33"></a><a id="fp-33"></a>质押合约地址（FP-33） | 文本，本项目质押合约地址 | 审核通过后必有；部署完成前为空 | 本企业资产方、资金方 | 全局唯一、与项目一一对应、终身不变、只读；不显示占位值 |
| <a id="FP-38"></a><a id="fp-38"></a>合约部署完成时间（FP-38） | 时间，合约部署成功即审核通过的时刻 | 审核通过后必有 | 本企业资产方、资金方 | 取运营端回写的部署事实，只读、终身不变；部署失败和再次发起不产生该时间 |
| <a id="FP-37"></a><a id="fp-37"></a>审核退回原因（FP-37） | 文本，面客可读原文 | 退回时必有；通过或待审核时为空 | 本企业资产方 | 不截断、不改写，不带内部备注；重新提交后保留在本项目审核历史中，不被覆盖 |

<a id="pledge-apply"></a><a id="F-LS-05"></a><a id="f-ls-05"></a>
## 8. 发起代币质押（F-LS-05）

适用角色与前提：本企业资产方；项目已通过审核，处于可用、募集中、已锁定或融资中。待审核、已退回、已关闭、已结清的项目不能发起质押。

- 资产方从控制台的融资项目进入本项目，在项目详情内办理。首笔质押与追加质押共用同一个入口、同一条流程和同一套规则。
- 从可质押清单批量勾选质押份额：至少一份、不重复；每份按其全部持有数量整份勾选，没有数量输入，不能拆分。
<a id="same-address"></a>
- **同一地址批量**：一次签名发起只能包含同一个持有地址上的份额。勾选了某个地址的份额后，其他地址的份额不能同时勾选，并说明原因；要质押其他地址的份额，另行发起一次。
- 同一笔代币在本企业的多个地址上都有持有时，每个地址上的持有各是一份，各自整份质押，可以分别进入不同项目。
- 清单默认按本项目代币类型过滤，一份一行，展示代币编号、持有地址、持有数量与代币符号、份额价值、账期、买方和有效性，不展示合同号或发票号。同一笔代币在本企业多个地址上的持有，分别列为多份。

<a id="eligibility"></a><a id="F-LS-04"></a><a id="f-ls-04"></a>
### 8.1 哪些代币可以质押（F-LS-04）

一份质押份额同时满足以下七条才可选：

1. 已同步到本平台只读代币域。
2. 持有地址归属当前企业（按只读代币域给出的企业归属，不按地址形态猜测）。
3. 这份数量不在任何质押合约内，也没有其他进行中的质押或解押占用。
4. 发行平台判为有效。
5. 属于本期已配置的代币类型。
6. 与本项目代币类型一致。
7. 代币的铸造链与本项目的[区块链网络（FP-39）](#fp-39)一致。

- 无需本平台任何上架动作；上游新同步的本企业持有份额直接出现在可质押清单。同一笔代币中由其他持有方持有、或已在质押合约中的部分，不影响本企业其他份额的可选性。
- 其他企业持有的份额不可见，直接提交一律被拒绝。
- 被进行中的质押或解押占用、已驳回尚未解押、已释放尚未提取的代币不可选，可以只读提示占用来源。
- 并发选择同一份额时，只有一笔成立；同一份额同一时刻只能在一个项目中。同一笔代币的不同份额可以分属不同项目。
<a id="D-LS-62"></a><a id="d-ls-62"></a>
- **每份一个当前持有地址**：每份质押份额只有一个当前真实的链上持有地址，对应该份的持有数量与份额价值。企业归属、当前地址、质押前原持有地址分别表达；已释放未提取的份额不能提前改回企业地址，原地址和合约地址不重复计量。地址、归属或数量价值不可靠时不放行。份额价值按签发价值折算，不重估；失效只取发行平台的结果，一笔代币失效时它的所有份额同时失效。

<a id="execution"></a><a id="F-LS-08"></a><a id="f-ls-08"></a>
### 8.2 签名并发起质押（F-LS-08）

<a id="F-LS-14"></a><a id="f-ls-14"></a>
- 质押上链由资产方用代币当前持有地址向本项目质押合约签名发起；平台不代签、不代付、不垫付。
- 链上 gas 由资产方承担，平台不收服务费、不返还；上链失败时已经产生的 gas 同样不退（F-LS-14）。

<a id="D-LS-68"></a><a id="d-ls-68"></a>**一步签名（D-LS-68）。**

- 勾选代币与签名在同一次办理内完成，不设单独的核对或二次确认步骤。
- 主动作名称为“签名并发起质押”（Sign and pledge）；未勾选时不可用。点击即唤起钱包签名，钱包内的签名就是最终确认，点击本身即视为本企业确认承担本次 gas。
- 本次办理最上方给出一段告知，打开办理即可见、随勾选即时更新、签名前一直可见。告知包括：
  - 本次签名的持有地址；
  - 已选份数、持有数量与份额价值合计；
  - 本次目标[质押合约地址（FP-33）](#fp-33)；
  - 预估 gas：只给一个合计及费用币种，可质押清单与告知中都不逐份列出；
  - 本次将发生链上操作、需本人签名、gas 由本企业承担且上链失败已产生的不退；
  - 上链成功后先计入待审质押额，须逐张审核通过才计入有效质押额、才可用于发布融资需求。
- 项目详情的质押入口不再另设一处同样内容的告知；创建页不出现任何质押或 gas 告知。

<a id="D-LS-51"></a><a id="d-ls-51"></a>**点击时逐张复核。**

- 点击“签名并发起质押”时逐张复核资格与预估 gas。
- 有任何变化时不唤起签名，此时任何一张都未发起：指出变化的代币，更新选择、告知与预估 gas，保留仍有效的选择，由用户再次点击才发起。这是资格变化时的必要处理，不是常规的二次确认；不静默剔除或补选。
- 未签名、取消签名或钱包不可用时，说明本次未发生链上操作、未产生 gas，代币保持可质押。

**上链结果（逐张）。**

| 上链结果 | 代币与额度的变化 | 资产方看到什么 |
| --- | --- | --- |
| 明确成功 | 代币进入本项目质押合约，质押状态为已质押；计入待审质押额和总质押额，暂不计入有效质押额 | 完成时间、实际 gas、链上凭证；本张等待逐张审核。上链成功不发通知 |
| 明确失败 | 代币未进入合约，不计任何额度，按当前资格可以重新发起 | 可读原因、是否已产生 gas 及金额、下一步；发送[链上操作失败通知（N-LS-04）](./03-融资需求与代币质押-消息通知.md#n-ls-04) |
| 结果未确认 | 本张处理中，不计任何额度；不能重押、撤回或重复发起 | 已等待时长、已知 gas，未知标“待核实”；其他代币和项目的其他办理照常，不锁整池 |

- 同一次发起的多张代币各自呈现结果，成功的不因失败的回滚，不给一个笼统的“部分成功”或“操作失败”。
- 重复点击、刷新或重复提交同一次操作，链上只产生一笔转移，gas 只记一次。
- 资产方签名成功即结束本次办理，回到质押代币清单查看逐张结果。

<a id="review"></a><a id="F-LS-21"></a><a id="f-ls-21"></a>
## 9. 逐张审核结果与质押代币清单（F-LS-21）

适用角色：审核由运营在[代币质押审核](../../运营端/06-代币质押审核/01-代币质押审核-PRD.md)办理；本节写资产方与其他身份看到的结果。

- 已上链的每张代币独立审核；提交批次只用于追溯。同批代币可以有不同的审核人、结果和协议；一张通过即计入有效质押额，不等全批。
- 审核状态记在这一笔申请上；代币在合约内不等于已通过审核。
- 审核结论只由运营端作出。资产方侧没有“质押审核”操作：资产方不审核、不确认，也不为审核结果另行办理。审核之后的后续动作只有待审撤回与驳回后的自助解押，都从[解除质押](#withdraw)办理。
- 审核无时效：不设截止，不因等待自动通过或自动失败，也不因查看或编辑改变状态。

| 本笔结果 | 代币与额度 | 资产方看到什么与后续 |
| --- | --- | --- |
| 待审核 | 代币在合约内，计入待审质押额，不计入有效质押额 | 已等待时长；可以自助撤回 |
| 通过 | 自通过起计入有效质押额并参与质押情况判断，从待审质押额移出 | 审核人、通过时间、适用协议；之后不再有任何截止或二次确认 |
| 驳回 | 代币仍在合约内并继续计入待审质押额；不自动退回，也不能用于其他项目 | 完整的面客原因（不截断、不带内部备注）；须自助解押取回后才恢复可质押 |
| 项目终态时仍待审核 | 由质押审核模块默认审核不通过（系统结论），按驳回处理：代币仍在合约内并计入待审质押额，不参与项目终态时的整池释放 | 原因写明所属项目已关闭或已结清；审核人显示“系统”；须自助解押取回 |
| 已撤回 | 资产方在裁定前自助解押成功，本笔终结，代币从待审质押额移出 | 撤回时间；撤回的解押处理中，运营暂不能裁定；撤回与审核同时发生只有一个结果成立，已通过的不能借撤回取消 |

- 重新发起同一份额生成新的一笔，旧结果留在该份额的历史中。
- 本笔通过后必有 1～5 个有效关联协议文件，只向本企业资产方提供；文件关联失效只存档，不连带作废其他笔共用的文件。
- 通知：审核通过与驳回各由代币质押审核模块发送一条站内信，模板见[消息通知册](./03-融资需求与代币质押-消息通知.md#t-ls-01)；本模块不重复发送。项目终态默认不通过是否发送驳回通知，以质押审核模块的裁定为准，见[依赖](#dependencies)。

| 移出原因 | 待审撤回 / 驳回后解押 / 资产方撤回 / 失效代币清出 / 项目关闭释放 / 项目结清释放 | 移出时有值 |
| 质押时间、业务释放时间、提取时间 | 时间 | 链上相关时间以回写时间为准；业务释放时间单独记录 |
| 失败说明 | 文本与分类 | 执行失败时必有，面向业务人员可读：为什么没成、是否已产生费用、下一步能做什么；不透出运营端诊断信息 |
| 底层资产失效 | 是 / 否，取只读代币域的代币状态 | 为“是”时不计入有效质押价值，解押规则见[解除质押](#withdraw) |
| 实际 gas | 金额与币种 | 本次质押或解押实际发生的 gas，按张回写；同一次操作只记一次；项目合约部署的 gas 不记入 |
| 对账差异 | 是 / 否，由后台对账判定 | 为“是”时冻结该代币一切新动作，且不计入质押价值 |
| 撤回预扣 | 是 / 否 | 有效抵押物撤回进入处理中时为“是”，该张价值立即从有效质押价值扣除；失败回滚时清除 |
| 待提取 | 是 / 否 | 已释放且链上仍在合约内时为“是”；该代币不属于任何项目、不能再质押 |

## 10. 发布与管理融资需求（F-LS-02）

适用角色与前提：本企业资产方，从项目详情的“融资”办理。

- 项目通过审核后，发布入口持续可见；但必须已有通过审核的质押，空池不能发布。
- 提交时重新核实当前身份和最新额度：项目未到期、未进入终态，有效质押价值大于 0，金额不超过可融金额，才能成功。
- 本环节未结束不能发布新一轮：上一轮须已终结，且其成交业务已完成放款确认。
- 待审质押额再大也不能用来发布。

| 办理 | 规则与结果 |
| --- | --- |
| 发布 | 必填 USD 需求金额，正数、最多两位小数，没有默认建议金额。参考结算币种只读带出创建时的选择。办理时给出当场的可融金额，超出时给出差额。成功后生成本轮融资申请编号，金额计入项目在途金额，状态为待报价；生效日与到期日不因发布改变 |
| <a id="F-LS-03"></a><a id="f-ls-03"></a>修改金额（F-LS-03） | 仅限尚未收到报价、仍可修改的当前轮。带出原金额，按最新额度复核本轮更新后的占用，不把原占用重复计算。成功后保留原融资申请编号；已锁定或进入履约的条款不能在此改写 |
| 撤下 | 仅限尚未收到报价、仍有效的当前轮；已收到报价的须先拒绝该报价，本轮回到待报价后才能撤下。确认后终结本轮、释放其在途占用，保留原编号和原因；不清除其他债务或整池质押 |
| <a id="D-FIN-76"></a><a id="d-fin-76"></a>再次发布 | 原需求终结且本环节已结束后，没有冷却期；项目未到期、未终态并重新满足发布条件时，生成新一轮和新编号。旧报价与成交记录保留；不重建项目，不改变到期日，不清除存量债务 |

- 发布成功即结束本次办理，回到融资申请信息清单中的这一轮记录，不自动打开报价。
- 发布失败保留输入和原因，不回滚已完成的质押，不再次收费。
- 项目首次发布成功之前保持可用状态，对外不可见。

### 10.1 发布入口与再次发布条件（D-LS-69）

一轮需求成交后，资产方确认放款到账即本环节结束；此后只要项目仍满足发布条件，就可以直接发布新一轮，不需要等该笔还款结清。发布入口按当前事实呈现：

| 当前情况 | 发布入口 |
| --- | --- |
| 空池（有效质押价值为 0） | 可见但不能提交，说明“本项目暂无有效质押，请先完成代币质押后再发布” |
| 本轮待报价或已报价待确认 | 不能发布新一轮；本轮可按规则修改或撤下 |
| 本轮已接受报价，放款尚未确认（待放款、待放款确认） | 可见但不能提交，说明本轮放款确认后才能发布新一轮 |
| 本轮已放款确认，或本轮已撤下、已失效 | 可以发布新一轮，办理时给出当场可融金额；成功生成新的融资申请编号，上一轮及其放款、还款记录不变 |
| 可融金额为 0 | 可见但不能提交，说明可融金额为 0 |
| 质押不足 | 可见但不能提交，说明当前质押不足 |
| 项目已到期 | 可见但不能提交，说明项目已到期 |
| 项目已关闭或已结清 | 不提供发布入口 |

<a id="F-LS-09"></a><a id="f-ls-09"></a><a id="INV-FIN-01"></a><a id="inv-fin-01"></a>
### 11.1 占用规则（F-LS-09）

<a id="water-level"></a>
- **质押水位（INV-FIN-01）**：有效质押额 ≥ 项目融资余额＋项目在途金额时为水位安全；有效质押额低于项目融资余额＋项目在途金额时为水位不安全。两者相等时仍为安全。本册凡说“水位安全”“水位不安全”，都指这一条。
- 任何新增占用后都须保持水位安全。
- 水位不安全时，同时发生三件事，判据相同：
  - 不能新增占用；
  - 融资需求按[需求因质押不足失效（F-LS-19）](#f-ls-19)失效；
  - 合约内已通过审核的代币不能转出，见[解除质押与提取（F-LS-06）](#f-ls-06)。
- 项目在途金额包括已接受报价、尚未放款确认的业务金额；这部分不会因需求失效而释放。因此需求失效之后，水位仍可能不安全，直到放款确认、追加质押通过审核或其他事实变化使水位恢复。
- 已发布需求的报价只校验已有的有效质押额与授信条件，不因可融金额为 0 单独禁止报价。
- 放款确认时，本笔金额同时从在途移出、计入项目融资余额，中间没有两边都不计的空档。
- 占用不从有效质押价值里扣减。
- 勾选或改额时可以先预览；提交以当场的权威重算为准，不用旧的预览数字放行。
- 以下事件都会触发重算：项目审核通过、质押上链结果与审核结论、发布与改额与撤下、质押变化、报价与接受与失效、放款及确认、还款结清、项目终态与到期、代币状态及对账差异变化。

<a id="project-state"></a>
## 12. 项目状态与后续业务

项目状态（FP-04）：待审核、已退回、可用、募集中、已锁定、融资中、已关闭、已结清。状态转换见[融资项目状态机（ST-LS-01）](./02-融资需求与代币质押-流程图与状态机.md#st-ls-01)。

- 创建提交后为待审核；审核通过（合约部署成功）转为可用；审核退回为已退回，修改重提回到待审核。
- 待审核与已退回不出现在广场，不能质押或发布，可以由资产方主动关闭；合约部署进行中除外，见[部署进行中暂不可关闭（D-LS-71）](#d-ls-71)。
- 发布后为募集中；资金方报价后为已锁定；拒绝报价后，需求仍有效且项目未到期时回到募集中；接受报价后为融资中。
- 撤下或失效后，没有其他在途与未结清业务时回到可用。
<a id="unfinished-business"></a>
- **未处理完成的业务**：以下任一存在时，项目不能关闭，也不会转为已结清：
  - 已收到报价、待资产方确认的融资需求；
  - 已接受报价、尚未放款确认的业务（待放款、待放款确认）；
  - 尚未结清的融资业务，包括逾期的；
  - 本项目合约内仍在处理中的链上操作（质押上链、解押、撤回，结果尚未回写或待核实）。
- 尚未收到报价的融资需求不算阻断：关闭项目时一并终结，终结原因为项目关闭。
- 逐张质押审核中的代币也不算阻断：项目进入终态时，由代币质押审核模块默认审核不通过，资产方自助解押取回。
- 可用、募集中的项目，没有未处理完成的业务时可以主动关闭；到期后同样只有在全部业务处理完成后才能关闭。
- 到期是并行标记（FP-05）：到期后不能发布新需求、不接受新报价，存量业务继续履约，按正常中性状态展示。
- 只有全部业务处理完成、项目实际关闭或结清时，才整池业务释放：池内已通过审核的代币变为已释放待提取，资产方才可提取。项目到期但仍有未处理完成的业务时，不整池释放。
- 终态项目仍可解押或提取未取回的代币，不能追加质押或再次关闭。

<a id="D-LS-64"></a><a id="d-ls-64"></a>**单笔融资业务没有中途终止出口。**

- 进入待放款后，本笔在途占用只会在放款确认时转为项目融资余额；平台没有任何动作能提前释放它，也不新增终止或审批入口。业务后果见[按用户决定保留的业务限制](#accepted-limits)。
- 各笔债务、在途与履约互不牵连：某笔停在待放款不影响其他笔履约，也不因此回到募集中或释放整池质押。
- 未到期、未终态的项目按剩余的全部事实重新判断资格。

<a id="application-detail"></a>
### 13.1 融资申请详情

- 依次包含：金额与申请状态、需求信息、当前报价及授信摘要、报价历史、协议文件。
- 需求信息含申请与项目标识、企业、本轮金额、参考结算币种、时间和项目有效期。
- 申请状态展示待报价、已报价待确认、放款中、已放款、已失效或已关闭五类事实；终结时同时说明原因。不拼入还款逾期或结清状态。
- 只呈现当前有效或已接受的一笔报价；历史报价按需查看，各自展示自己的条款，不提供恢复或接受旧报价的动作。
- 授信摘要只给当前报价机构对本企业的总授信与已用授信，不等于本项目额度，也不提供历次授信明细。
- 查看报价时可以看到预计还款计划，明确标注“预计·未生效”。报价与授信的完整规则见[授信报价](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md)。
- 协议按文件逐条给出名称、用途、所属业务与版本、上传时间，可以下载；当前适用版本与历史版本可以区分。无文件、无权限、读取失败分别反馈。

<a id="fulfilment"></a>
### 13.2 放款与还款详情

- 放款详情依次给出金额、阶段与当前处理方、放款信息、凭证与 Hash、账户、适用协议；融资申请编号只作展示，不提供跨业务跳转。
- 放款展示状态只有待放款、待放款确认、已放款三种，规则沿[放款与放款确认](../07-借贷广场-放款与放款确认/01-放款与放款确认-PRD.md)。登记不等于到账，待放款确认不冒充已放款。资产方确认到账后，该笔在放款清单中保持“已放款”；之后的还款、逾期、结清归还款信息。
- 还款详情给出本期应还或待确认摘要、定稿计划（一期一条）、账户与还款及确认记录；选期只办理本期。正式计划生成中、没有待还期次、已全部结清分别说明，不填虚假金额，不拿预计计划充当正式计划。规则见[还款计划与还款确认](../08-借贷广场-还款计划与还款确认/01-还款计划与还款确认-PRD.md)。
- 放款收款账户属资产方，在接受报价时确认、放款沿用；还款收款账户属资金方，在放款登记时确定、还款沿用。账户在企业账户模块维护，办理时下拉选用，办理过程中不能临时新增。

<a id="withdraw"></a><a id="F-LS-06"></a><a id="f-ls-06"></a>
## 14. 解除质押与提取（F-LS-06）

适用角色与前提：本企业资产方，从项目详情的“质押—解除质押”进入；项目处于任何已通过审核的状态，包括已关闭和已结清。

- 解押与提取都不经运营审核，由资产方自行向本项目质押合约签名发起；gas 由资产方承担，失败不退。
- 合约按记录把这份数量整体转回质押前的原持有地址；不能只转出一部分，平台不代签、不代付，也不能指定其他地址。
- 每张代币标明所属类别：待审代币、已驳回代币、已失效代币、有效抵押物、已释放待提取，互不混淆。

**到期后的转出。** 项目到期但仍有未处理完成的业务时，项目不终结、不整池释放；已通过审核的代币仍按下方的质押水位与可撤回上限规则转出。“终结”只指项目关闭或结清。

**转出与质押水位。** [质押水位（INV-FIN-01）](#water-level)不安全时，合约内所有已通过审核的代币一律不能转出，包括有效抵押物和已失效代币；判据与需求失效相同。水位恢复安全后按下表各类条件办理。

| 类别 | 能否转出 | 转出成立后 |
| --- | --- | --- |
| 待审代币 | 审核尚未裁定即可自助撤回；不受额度和质押水位约束 | 本笔审核终结为已撤回，该张从待审质押额移出 |
| 已驳回代币 | 驳回后（含项目终态默认不通过）须自助解押取回；不受额度和质押水位约束 | 从待审质押额移出；取回且无占用后恢复可质押、可用于其他项目 |
| 有效抵押物 | 已通过审核且有效。水位不安全时不能转出；水位安全时须满足“剩余有效质押价值 × 项目质押率 ≥ 项目融资余额＋项目在途金额”，即拟撤回价值不超过可撤回上限 | 发起即预扣该张有效价值；成功按真实转出移出项目，失败保持在池并撤销预扣 |
| 已失效代币 | 已通过审核、但发行平台已判失效，不计入有效质押。水位不安全时不能转出；水位安全时（含质押持平）不受可撤回上限约束 | 移出项目；有效质押价值、有效质押额、可融金额不变 |
| <a id="F-LS-17"></a><a id="f-ls-17"></a>已释放待提取（F-LS-17） | 只有全部[未处理完成的业务](#unfinished-business)处理完成、项目实际关闭或结清时，池内业务关系即时解除（零 gas、无链上动作）；之后资产方自助提取，可批量，没有时间限制 | 转回原持有地址；失败仍为已释放待提取，不恢复项目占用 |

- 所有类别仍受真实占用、处理中和对账差异保护：上链或解押处理中、带对账差异的代币不能转出。
- 已释放待提取的代币不属于任何项目、不计任何额度，也不能再质押。
- 有待提取或待解押的代币时，解除质押入口提示张数与金额，并说明 gas 自担、可批量、代币不会自动回到钱包。
- 单笔业务结清只降低项目融资余额、提高可撤回上限，不自动释放“对应”的代币。
- 已通过审核代币的撤回发起后，并发报价按预扣后的项目价值判断。
- 记录保留实际凭证、时间、gas 和原因；未知或冲突按[异常只提示联系客服（D-LS-63）](#d-ls-63)处理，不自动重试。
- 流程见[解除质押与提取图（FL-LS-03）](./02-融资需求与代币质押-流程图与状态机.md#fl-ls-03)。

<a id="D-LS-70"></a><a id="d-ls-70"></a>
### 14.1 解押与提取签名办理（D-LS-70）

与[一步签名（D-LS-68）](#d-ls-68)同一方式：勾选代币与签名在同一次办理内完成，不设单独的核对、费用确认或二次确认步骤。

- **同一地址批量**：一次签名只能包含同一个原持有地址的份额，与质押一致；因为每个原持有地址都要分别执行一次链上操作。勾选了某个原持有地址的份额后，其他地址的份额不能同时勾选，并说明原因；要处理其他地址的份额，另行发起一次。
- 主动作名称：项目未进入终态时为“签名并解除质押”（Sign and release）；项目已关闭或已结清时为“签名并提取”（Sign and collect）。未勾选时不可用；点击即唤起钱包签名，钱包内的签名就是最终确认，点击即视为本企业确认承担本次 gas。
- 可选范围：本项目合约内的待审、已驳回、已失效与有效抵押物代币，以及已释放待提取代币；按[质押水位（INV-FIN-01）](#water-level)不能转出的代币不可选，并说明原因。可同次多选、跨类别多选。
- 办理最上方的告知（打开即可见、随勾选即时更新、签名前一直可见）包括：
  - 已选份数、持有数量与份额价值合计；
  - 预估 gas：只给一个合计及费用币种，清单与告知中都不逐份列出；
  - 本次签名对应的原持有地址；
  - 本次目标[质押合约地址（FP-33）](#fp-33)；
  - 代币转回质押前的原持有地址，不能更改；
  - 需本人签名，gas 自担，失败不退；
  - 撤回待审代币将终结该笔审核；
  - 项目未进入终态时，拟撤回的有效抵押物价值与当前可撤回上限的实时对照；
  - 水位不安全时，说明已通过审核的代币暂不能转出及原因；
  - 24 小时内本企业链上提交超过 5 次时，提示频繁操作会产生较多 gas，不阻断。
- 超限：所选有效抵押物价值超过可撤回上限时，给出拟撤回价值、当前上限、差额三个数，以及“减少勾选”“等待还款释放余额”两条出路；主动作不可用。减少有效抵押物的勾选即可继续。
- 资格变化：点击时逐张复核，规则同[点击时逐张复核（D-LS-51）](#d-ls-51)；有变化则不唤起签名，指出变化的代币并更新选择与预估 gas，用户再次点击才发起。
- 入口可用性：只要存在任一可以转出的代币，解除质押入口即可进入；有效抵押物的额度不足或水位不安全，不能挡住待审、已驳回或待提取代币的办理。
- 解押成功后，待审与已驳回代币直接从待审质押额移出。

<a id="coverage"></a>
## 15. 质押情况变化与需求失效

发行平台判代币失效或后台标记对账差异后，先从有效质押价值中排除并权威重算，再判断现有需求和债务的质押情况。代币失效不会自动转出，资产方可按[解除质押](#withdraw)清出。

| 质押情况 | 判据 | 用户结果 |
| --- | --- | --- |
| 质押充足 | 有效质押额足以覆盖项目融资余额与在途，且可融金额大于 0 | 按资格正常办理 |
| 质押持平 | 可融金额为 0，且有效质押额不低于项目融资余额 | 不能新增发布；有效抵押物的可撤回上限为 0；已发布需求的报价按已有有效质押额与授信条件判断，不一概禁止。其中有效质押额低于“项目融资余额＋项目在途金额”的，水位不安全，按[质押水位（INV-FIN-01）](#water-level)处理 |
| 质押不足 | 有效质押额小于项目融资余额，即已有债务本身不足 | 禁止新增占用；水位必然不安全，已通过审核的代币不能转出；触发质押不足提醒 |

- 需求失效与债务提醒是两件事：需求失效与转出拦截按[质押水位（INV-FIN-01）](#water-level)，比较“项目融资余额＋项目在途金额”；质押不足提醒只比较“项目融资余额”。需求失效后债务可能仍被覆盖；没有在途需求时债务也可能不足。

<a id="invalidation"></a><a id="F-LS-19"></a><a id="f-ls-19"></a>
### 15.1 需求因质押不足失效（F-LS-19）

- 重算后[质押水位（INV-FIN-01）](#water-level)不安全时，立即按发布时间倒序使最少必要的需求失效；每失效一笔释放其在途并重算，水位恢复安全即停止。
- 等价判断：按发布时间正序保留较早的需求，对每笔比较“有效质押额 − 项目融资余额 − 更早已保留的金额”是否足够。本期一个项目只有一轮在途需求，同样按此口径。
- 没有需求可失效而水位仍不安全时就停止（例如剩余在途来自已接受、尚未放款确认的业务）；此时已通过审核的代币仍不能转出，债务不足时保留质押不足提醒。
<a id="D-FIN-75"></a><a id="d-fin-75"></a>
- 该轮需求与其在途报价在同一次事实变更内失效，用户不会看到需求已失效而报价仍可接受。
- 记录原编号与终结原因“自动失效·质押不足”；不新增项目状态、缓冲期或补质押倒计时。原轮不能恢复，满足资格即可立即发布新一轮。
- 通知：本模块发送[融资需求终结通知（N-LS-05）](./03-融资需求与代币质押-消息通知.md#n-ls-05)；授信报价模块不为同一原因再发报价失效信。流程见[需求因质押不足失效图（FL-LS-04）](./02-融资需求与代币质押-流程图与状态机.md#fl-ls-04)。

<a id="F-LS-16"></a><a id="f-ls-16"></a>
### 15.2 质押不足提醒（F-LS-16）

- 质押不足时显示质押缺口（项目融资余额 − 有效质押额）和需追加资产价值（质押缺口 ÷ 项目质押率）。
- 资产方在项目与控制台都能看到提示、待办和追加入口，并被明确告知“追加质押须先上链、再经审核通过才计入有效质押额，上链成功不即时生效”。
- 债权机构可见缺口和触发时间；平台运营有既有待办与监控。借贷广场列表对所有身份展示中性的质押情况；项目详情中的质押情况按[项目详情按身份的可见范围（F-LS-82）](#f-ls-82)。
- 条件反转时自动解除，无需人工确认。触发与解除都保留时间、当时的有效质押价值、有效质押额、项目融资余额、诱因和解除时间。
- 通知：触发与解除分别发送[质押不足通知（N-LS-06）](./03-融资需求与代币质押-消息通知.md#n-ls-06)与[质押不足解除通知（N-LS-07）](./03-融资需求与代币质押-消息通知.md#n-ls-07)。流程见[质押不足触发与解除图（FL-LS-06）](./02-融资需求与代币质押-流程图与状态机.md#fl-ls-06)。

<a id="navigation"></a><a id="F-LS-13"></a><a id="f-ls-13"></a>
## 16. 从控制台、资产广场与消息进入（F-LS-13）

- 控制台、资产广场与消息都能定位到项目，以及原来的申请、业务或期次；终态项目仍可寻址。
- 质押的进入通道在控制台的融资项目，办理在项目详情内完成。
- 一次只进入一个明确对象的查看或办理，不自动勾选或执行。
- 每次进入都重新核验权限与阶段：对象已完成或已失效时显示它当前的事实与原因，不跳到新一轮，也不把用户带到空白结果或静默送回起点。
- 待审核与已退回的项目仍不暴露存在性，非本企业不能进入私有办理。
- 从控制台进入时提供返回原位置的入口，其他来源不提供。资产广场可以单向进入项目，本模块不新设反向入口。

<a id="accepted-limits"></a>
## 17. 按用户决定保留的业务限制

以下是用户裁定后的既定结果及其业务后果；测试按此预期，不判为缺陷。

| 限制 | 业务后果 |
| --- | --- |
| 平台不采集、不校验收款人名称 | 平台不能自动校验“收款账户属于本企业”；账户核对只依据账户备注名、账号等信息，受益人名称由业务双方在平台外补充 |
| 部署进行中暂不可关闭项目 | 部署结果长期待核实时，资产方只能看到项目待审核、无法自行关闭，需等运营端回写结果，见[部署进行中暂不可关闭（D-LS-71）](#d-ls-71) |
| 报价一经提交，资金方无法撤回 | 退出路径只有资产方拒绝；“撤下需先拒绝报价”是本轮需求退出的唯一方式 |
| 待放款阶段没有终止出口 | 线下协商不放款时，平台没有任何动作能终结该笔业务：业务持续停留在待放款，本项目因“本环节未结束”不能发布新一轮，对应代币持续被占用 |
| 水位不安全时已通过审核的代币全部不能转出 | 有效质押额低于“项目融资余额＋项目在途金额”期间，资产方不能取回任何已通过审核的代币，包括已失效、不计入有效质押的代币。在途来自已接受未放款的业务时，这一状态会持续到放款确认或水位因其他事实恢复 |

<a id="dependencies"></a>
## 18. 待确认事项与依赖

本模块当前没有待确认事项。

依赖：

- **代币质押审核**（运营端）：逐张审核结论、协议与原因与本册一致；项目终态时仍待审核的笔默认审核不通过（系统结论），是否发送驳回通知由该模块待确认事项[Q-PR-16](../../运营端/06-代币质押审核/01-代币质押审核-PRD.md#q-pr-16)决定，裁定前不发送。
- **审核通过时的解冻授权**（代币质押审核）：运营通过一笔质押时须连接钱包、以运营端配置的地址签名，授权质押合约解除该代币的冻结。授权上链失败或结果待核实时本笔算不算通过、授权处理中资产方能否撤回，由该模块待确认事项[Q-PR-17](../../运营端/06-代币质押审核/01-代币质押审核-PRD.md#q-pr-17)决定。本册按“通过结论生效即计入有效质押额”书写，裁定后按结论同步[逐张审核结果（F-LS-21）](#f-ls-21)。
- **合约部署的签名方式**（项目合约管理）：本册按“平台统一钱包部署、运营人员不签名”书写；是否改为运营连接钱包签名部署，由该模块待确认事项[Q-CM-11](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#q-cm-11)决定，资产方侧看到的结果不受影响。
- **项目合约管理**（运营端）：项目审核与合约部署的入口、权限与操作记录由该模块定义，结论只有通过与退回；本册只定义面客端可见的结果。
