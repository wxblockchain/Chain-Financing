## 1. 模块是什么

资产方在借贷广场创建融资项目，项目通过审核时，运营从所属“区块链网络＋代币类型”下预先部署的质押合约中为它选用一份，平台同时为本项目部署放款合约与还款合约，合约配置成功即审核通过；资产方先按本次所选数量签名授权本项目所配置的质押合约调取这些代币，授权上链后再签名一笔质押交易把所选代币批量转入该合约，上链成功即质押成功，代币随即计入可用于融资的额度；资产方据此用登录钱包签名发布融资需求，平台执行钱包随即在质押合约中冻结本轮需求对应的质押价值；资金方授权放款合约后报价，资产方签名接受即链上放款，随后进入还款。一个融资项目就是一只资产池，可以先后承接多轮融资需求和多笔存量业务。本模块负责项目、代币质押、额度、冻结与质押情况的判断，以及项目详情里三类记录的查看与办理入口。

基本原则：

- 只有通过[代币准入审核](../../运营端/06-代币准入审核/01-代币准入审核-PRD.md)的代币才进入借贷业务：创建项目的代币类型与可质押清单都只来自已准入代币。
- 项目审核与代币质押是两件独立的事：项目审核决定项目能不能用，审核通过即为项目完成合约配置；代币质押由资产方授权并签名、合约执行上链，执行成功即质押成功、直接计入有效质押，不经运营审核（用户 2026-10-21 裁定）。
- 质押合约按组合预先部署、可以共用：同一组合（区块链网络＋代币类型）下可以有多份质押合约，运营在项目审核时为项目选用一份，同一份质押合约可以由多个项目使用；合约内的质押份额、额度与冻结分别归属各自项目，互不计入（用户 2026-10-21 裁定）。放款合约与还款合约每个项目一份（用户 2026-10-26 要求，见[审核对象（D-CM-03）](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#d-cm-03)）。
- 授权、质押、解押与提取由资产方本人用持有地址签名并发送交易，gas 由资产方承担、失败不退；平台不代签、不代付。
- 发布与改额由资产方用登录钱包签名确认，再由平台执行钱包签名执行冻结上链（用户 2026-10-21 裁定签名链路）；冻结交易由平台执行钱包发送，gas 随之由该钱包承担；冻结解除与合约配置由平台执行，资产方不签名、不付费。
- 只有有效质押才能支撑融资；新增占用必须始终满足“有效质押额 ≥ 项目融资余额＋项目在途金额”。
- 质押合约内有本项目的池水位管控，包括可撤回上限；代币释放由质押合约与平台业务双重判断（用户 2026-10-21 裁定）。
- 质押与释放都按批办理，不逐张操作（用户 2026-10-21 裁定）。
- 全流程没有倒计时：项目审核、报价都不因等待而自动改变结论。
- 链上结果长期未知、冲突等异常只提示联系平台客服，本期不建设异常处置流程。

**一个完整的例子。** 资产方甲持有若干已通过准入审核的 Ethereum 代币。甲从借贷广场点击“创建融资项目”，核对固定网络 Ethereum，代币类型候选中出现“ERC-3525-应收账款”（该组合运营已配置参数），甲选中它，填写质押率 70%（不超过该组合的最高质押率）、选择一年内的到期日、点选参考结算币种 USDT 后提交；项目进入待审核，此时不签名、不付费。运营核对后从“Ethereum＋ERC-3525-应收账款”下预先部署的质押合约中为项目选定一份并确认，平台随即为本项目部署放款合约与还款合约，两份都部署成功即合约配置成功、审核通过，项目变为可用，甲收到“项目审核通过”站内信，信中带质押合约地址。甲进入项目详情，勾选地址 A 上的 10 笔代币（同一个代币发行合约铸造、资产槽位各不相同），先用地址 A 在钱包签名授权这 10 笔的数量合计，授权上链成功后点击“签名并发起质押”再签名一次；两次签名前都能在签名按钮旁核对本项目的质押合约（Ethereum 与完整地址）和一句签名用途；一笔质押交易把 10 笔一起转入合约，上链成功即质押成功，直接计入有效质押额；打开其中任一份的代币详情，操作记录中可见这笔质押交易哈希的缩写，点击即复制，也可跳转区块链浏览器。甲在项目办理区看到当前可融金额，填写 50 万 USDT 的融资需求，从企业账户已登记的 Ethereum 数币账户中选定融资收款地址，签名按钮旁同样给出执行冻结的质押合约与签名用途，甲用登录钱包签名确认本轮金额与融资收款地址；平台执行钱包随即发起冻结交易，冻结上链成功即发布成功，需求进入待报价，融资申请详情最下方的操作记录多出“发布冻结”一条，含这笔冻结交易的哈希。资金方乙授权放款合约后报价，甲核对后签名接受，平台执行钱包执行链上放款，结算金额从乙的放款地址转入甲的融资收款地址，放款成功即这一轮结束；乙的报价授权与这笔链上放款也在同一份操作记录中各留下一条；之后甲可以按当时的可融金额发布下一轮。项目到期、还款全部结清后，冻结全部解除，项目自动转为已结清，池内代币变为“已释放待提取”，甲签名提取回原地址。

### 1.1 本期不做

- <a id="q-ls-03"></a>本期不要求、不展示逐笔质押协议文件。

- 代币准入审核：归[运营端代币准入审核](../../运营端/06-代币准入审核/01-代币准入审核-PRD.md)，本模块只消费准入结果。
- 在面客端选择或更换项目的合约：质押合约由运营在项目审核时选用，放款合约与还款合约由平台为本项目部署。
- 部分数量质押：资产方在一个持有地址上持有的某笔代币，只能整份质押，不能拆出一部分数量质押。
- 在质押办理中撤销授权：撤销统一在[我的控制台的链上授权](../09-我的控制台/01-我的控制台-PRD.md#revoke)办理。
- 单独的冻结或解冻入口：冻结只随发布与改额发生；冻结按价值记在项目名下，不由资产方指定具体份额（用户 2026-10-21 裁定，[Q-LS-25](#q-ls-25)）。
- 平台代资产方签名，或代付、垫付授权、质押、解押与提取的 gas。
- 抵押物处置或变现。
- 异常处置系统：工单、自动升级、人工改判、强制释放、补偿。
- 指定代币转出的目的地址：一律转回质押前的原持有地址。
- 单笔融资业务的中途终止。
- 全项目操作日志、公开批量导出。
- 健康评分、风险等级、黑名单等评价性标签。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 融资项目（资产池） | 资产方创建的一个融资单位，审核通过时绑定运营选用的一份质押合约，以及平台为本项目部署的放款合约与还款合约，可承接多轮融资需求 |
| 项目发布方 | 创建并发布这个融资项目的资产方企业。它不是代币的发行方或持有方：一个项目内的代币可以来自不同发行方 |
| 已准入代币 | 通过运营端[代币准入审核](../../运营端/06-代币准入审核/01-代币准入审核-PRD.md)的代币；待审核、已退回的代币在本模块任何地方都不出现 |
| 组合 | 一个区块链网络与一个代币类型的搭配。融资参数（最高质押率、最长项目期限）按组合配置，质押合约也按组合预先部署 |
| 质押合约 | 资产方把代币质押进这里。由开发人员按组合预先部署并维护，同一组合下可以有多份；运营在项目审核时为本项目选用其中一份。同一份质押合约可以由同组合的多个项目使用，合约内的质押份额、额度与冻结分别归属各自项目。见[项目合约管理的术语](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#terms) |
| 放款合约、还款合约 | 每个项目各一份，只属于本项目，在项目审核通过时由平台为本项目部署；按授信报价与接受拒绝、链上还款两个模块的规则使用，本模块不展示 |
| 合约配置 | 运营为项目选定其组合下的一份质押合约并确认，平台为本项目部署放款合约与还款合约；两份都部署成功、所选质押合约对本项目生效才算配置成功，配置成功即审核通过；资产方与运营都不签名。办理规则见[通过并部署合约（F-CM-09～F-CM-11）](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#m3) |
| 持有方 | 当前持有一笔代币某一部分数量的链上地址，口径同[资产广场](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-14)。一笔代币可以有多个持有方，各持一部分，可以分属不同融资项目 |
| 质押份额（张） | 本企业的一个持有地址上持有的某笔代币的全部数量，是质押、解押与提取的最小单位，只能整份办理，不能拆分数量。本册所说的“一张代币”“逐张”“张数”都指质押份额，不是一笔代币的全部数量 |
| 份额价值 | 一份质押份额的价值 = 持有数量 × 该笔代币价值 ÷ 该笔代币数量，USD，按签发价值折算，口径同资产广场的“对应价值” |
| 项目审核 | 运营核对创建信息并完成合约配置；配置成功即审核通过，结论只有通过与退回 |
| 空池 | 项目已可用，但有效质押价值为 0，例如还没有任何一张质押成功的代币 |
| 代币发行合约 | 铸造代币的链上合约。同一个代币发行合约可以铸造多笔代币，各笔的资产槽位（slot）不同 |
| 授权 | 资产方用持有地址签名并上链的交易，允许本项目所配置的质押合约从该地址调取本次所选数量的代币；按“持有地址＋代币发行合约＋质押合约”给出，授权数量等于本次从该发行合约所选份额的数量合计，授权本身不转移代币。规则见[授权与签名（D-LS-68）](#d-ls-68) |
| 质押上链 | 授权上链成功后，资产方用同一持有地址再签名一笔质押交易，把所选份额一次性转入本项目的质押合约 |
| 平台执行钱包 | 平台配置的钱包地址，在资产方签名确认后，代为签名执行发布与改额的冻结；也执行冻结解除，以及把代币失效与对账差异标记同步到质押合约；gas 由该钱包承担 |
| 冻结 | 发布或改额时，资产方签名确认、平台执行钱包上链，在质押合约中冻结本轮需求对应的质押价值；冻结的价值不能从合约转出 |
| 冻结质押价值 | 本项目在质押合约内处于冻结中的质押价值合计，USD；口径见[额度口径（F-LS-07）](#f-ls-07) |
| 自助解押 | 资产方签名把合约内的代币转回原持有地址，不经运营处理 |
| 提取 | 项目关闭或结清后，资产方签名取回“已释放待提取”的代币 |
| 总质押额 | 质押合约内归属本项目的全部质押份额的份额价值合计，含失效的份额 |
| 有效质押价值 | 质押成功、实际在池、发行平台判有效且无差异的质押份额的份额价值合计 |
| 有效质押额 | 有效质押价值 × 项目质押率，即本项目能支撑的融资上限 |
| 项目融资余额 | 本项目已放款、尚未偿还的本金合计（项目统计中显示为“已融资余额”） |
| 项目在途金额 | 已发布、尚未终结的融资需求金额合计 |
| 可融金额 | 有效质押额减去项目融资余额和项目在途金额，最小为 0 |
| 可撤回上限 | 可融金额 ÷ 项目质押率，只约束有效抵押物撤回 |
| 质押情况 | 项目级判断：有效质押额是否足以覆盖融资余额与在途，取值质押充足、质押持平、质押不足。不同于单张代币的“质押状态” |
| 质押缺口 | 质押不足时，项目融资余额减有效质押额 |
| 质押水位 | 有效质押额与“项目融资余额＋项目在途金额”的比较。前者不低于后者为水位安全，低于为水位不安全；水位不安全时需求失效、合约内的代币不能转出 |
| 一轮融资需求（融资申请） | 资产方发布的一次融资需求，有自己的融资申请编号；一个项目同一时刻只有一轮在途 |
| 本环节 | 一轮融资需求从发布到终结（撤下、失效、到期，或报价被接受、链上放款成功）的过程；本环节结束前不能发布下一轮 |
| 质押链 / 结算收款链 | 质押链是代币与质押合约所在的链，即创建项目时选择的区块链网络，本期仅 Ethereum；结算收款链是数币收款地址所在的链，由企业账户模块定义，当前仅 Ethereum。两者是两个概念，互不决定 |
| 融资收款地址 | 资产方发布融资需求时选定的、本轮融资放款的收款地址；只能从本企业在企业账户中已登记的数币账户（Ethereum 网络）中选 |
| 登录未绑定角色 | 已用钱包登录，但本平台既不是资金方、也调取不到上游资产方账户的用户 |

## 3. 共同规则

<a id="roles"></a>
### 3.1 角色与可见范围

| 角色 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| 游客（未登录） | 浏览借贷广场列表；在项目详情只看到项目基本信息，规则见[项目详情按身份的可见范围（F-LS-82）](#f-ls-82) | 任何写操作；看到项目基本信息以外的详情内容；看到待审核、已退回或尚未发布的项目 |
| 登录未绑定角色 | 浏览借贷广场列表；在项目详情只看到项目基本信息，规则见[项目详情按身份的可见范围（F-LS-82）](#f-ls-82) | 创建融资项目；看到项目基本信息以外的详情内容；任何写操作 |
| 资产方 | 创建项目并提交审核；授权并签名发起质押，签名发起解押与提取；签名发布和修改融资需求，撤下需求；签名接受或拒绝报价；关闭项目；办理本方的还款；本企业项目的详情全部可见 | 其他企业的项目只看到基本信息；看到或办理其他企业的私有项目与资料 |
| 资金方 | 浏览借贷广场列表；查看所有已发布项目的详情；按本机构资格办理报价（含授权放款合约）与还款确认 | 资产方的私有资料与私有待办；其他机构的报价、授信、账户与协议；未认证或审核中不等于可以出资 |
| 平台运营 | 在运营端做代币准入审核、融资参数配置、项目审核与合约配置，查看既有待办与监控 | 在面客端裁定审核或代资产方执行；对质押作结论 |

- 个人与企业账户档案只有本人能看。业务必要的项目、企业名称、代币信息按本业务权限展示，不能因此开放对方的整份账户档案。
- 授信、账户、协议、凭证、联系方式、底层合同号与发票号、运营诊断都不是公开融资信息。
- 查看、下载和直接提交都由服务端检查权限；隐藏入口不能代替权限控制。
- 登录资格与本人资料沿[登录主干](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md)和[资金方账户](../02-资金方登录与账户体系/01-资金方登录与账户体系-PRD.md)；上游代币事实沿[资产广场](../04-资产广场-已上架代币只读域/01-资产广场-PRD.md)。

### 3.2 查看与办理分开（F-LS-20）

项目详情同时提供三类记录：质押代币清单、融资申请信息、还款信息，按此顺序讲述，边界见[查看三类记录](#records)；定位到其中一类时，其余两类仍可得。办理按质押、融资、还款三类业务归集，三类入口在项目详情始终可达。以上只适用于能看到项目完整详情的身份（本企业资产方、资金方），其他身份见[项目详情按身份的可见范围（F-LS-82）](#f-ls-82)。各清单独立保留筛选和页码，空态与读取失败分别呈现。

| 用户动作 | 结果 |
| --- | --- |
| 从记录查看详情 | 只读呈现当前记录、历史、计划、账户和文件；不提供办理、跨业务跳转或重复的查看入口。历史与预览在本次查看内展开，文件按权限下载 |
| 从办理入口办理 | 先明确是哪一轮申请、哪一笔业务或哪一期，再进入本次办理；多笔待办时不默认代选最新一笔。步骤、必要确认与放弃修改都在本次办理内完成，不再叠加下一层办理 |
| 返回或关闭 | 返回上一步时保留已填内容和已成功的附件；有未提交的编辑时就地确认是否放弃。关闭后回到来源，保留原筛选、分页与所在位置；关闭只读详情不改变业务 |
| 成功、失败或结果未知 | 成功只更新本笔及相关办理入口，不自动打开详情、下一笔或下一阶段。失败保留可复用的输入；结果未知显示待核实，不假报成功，也不引导重复提交 |

- 操作页只保留完成当前动作所需的输入、识别与核对信息、校验结果、费用及必要后果说明；完整资料、历史和非本步信息在有权查看的详情中展示，不在操作页重复（用户 2026-10-23 要求）。各动作的必要信息以对应功能为准。
- 发布或改额签名发起、质押签名发起、报价成功后都结束本次办理。授信保存成功同样结束本次办理并提示“已授信，请继续报价”，需要用户再次发起报价。
- 报价、授权、发起质押、发布、修改金额、撤下、解除质押与提取都不设二次确认，需要签名的以钱包内的签名为最终确认；其余动作保留原有的必要确认。
<a id="D-LS-61"></a><a id="d-ls-61"></a>
- **自动带入（D-LS-61）**：平台已知且有权使用的本笔信息自动带入，优先本笔已确认的事实，其次是同企业、同用途、同币种的有效登记资料；只补业务必需的缺项。只读事实不能改写，可编辑项仍要校验，规定的逐笔确认不能省略。不得串用不同机构、企业或用途的账户，也不得把旧合同、旧转账凭证默认用于新业务；资料缺失或读取失败时不填示例值或零值。

### 3.3 日期、金额与展示

- 业务日期一律按 UTC 判定；展示按用户偏好时区，游客按浏览器时区，时间都标注时区。切换时区不改变任何业务日期。
- 融资需求金额、项目在途金额、项目融资余额与可融金额以 USDT 计（用户 2026-10-22 裁定）；份额价值、质押价值、有效质押额与冻结质押价值按签发价值以 USD 计。两者比较与相减时按 1 USDT = 1 USD 计，不引入汇率（用户 2026-10-22 裁定，[Q-LS-28](#q-ls-28)）。
- 金额按两位小数展示，计算过程不提前舍入；代币数量、签发价值和原币应收金额不能混加。
- 实际 gas 按费用资产自身的精度展示，未知时标“待核实”，不填 0。
- 界面支持中英双语，默认英文，切换语言即时生效。状态都有文字表达，不只靠颜色区分；代币编号、价值、状态和质押情况在任何展示条件下都不被省略。
- 内部状态编号（如 PS-、CT-）不出现在面客文案或访问地址中。
- 正常浏览不受影响；异常高频访问受限并提示必要验证；不提供公开批量导出。

<a id="facts"></a>
### 3.4 事实来源、合约与交易哈希

- 代币、持有地址与失效状态取本平台只读代币域，本平台不回查上游或读链。只读代币域中只有准入状态为已通过的代币进入本模块；准入通过后代币变为失效、持有地址变化，仍按上游最新事实反映，不改变准入结论。
- 本期代币为 ERC-3525 代币，一笔代币（一个代币编号）对应一个资产槽位；代币类型形如“ERC-3525-应收账款”，字段不写死任何代币标准。
- 质押事实以本平台为准，并回传发行平台；本平台不读取上游带来的质押状态。
- 本模块的合约由本平台为项目配置，链上交易都经本平台发起（资产方在平台办理中签名，或由平台执行钱包执行）。展示规则见[所交互的合约、签名用途与交易哈希](#chain-display)。
- 质押链本期仅 Ethereum，只展示、不提供选择；与结算收款链分别表达，不共用同一个“链”字段。
- 网络名称一律展示为“Ethereum”，中文界面同样如此，不译为“以太坊”，也不用“ETH”缩写，避免与同名的币混淆（用户 2026-10-22 裁定）。

<a id="chain-display"></a>
**所交互的合约、签名用途与交易哈希**（用户 2026-10-26 要求，与[授信报价与接受拒绝](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md)同一口径）：

- 所交互的合约：需要资产方签名、并会作用到合约的办理，在签名主动作旁同时给出本次涉及的合约，即本项目所配置的质押合约：合约名称“质押合约”、网络“Ethereum”与完整合约地址，与项目详情所示[质押合约地址（FP-33）](#fp-33)一致。适用的办理有：授权签名、质押交易签名、发布、修改金额、撤下、解除质押与提取，各自要求见对应功能。
- 合约地址可复制完整值，也可在区块链浏览器新窗口打开该合约地址核对；合约只取本项目的配置结果，用户不能填写或选择。读取失败或与项目详情所示不一致时不唤起钱包、不能签名，说明暂时不可用并可重试。
- 本次签名用途：签名主动作旁用一两句话说明这次签名做什么，与已有的后果说明合并，不另设确认弹窗或勾选；具体文字由设计决定，须包含对应功能列出的要点。
- 签名办理中展示合约是签名前的核对。各类详情中，合约只在项目详情的[质押合约](#f-ls-81)一处展示；代币详情、融资申请详情与操作记录都不重复合约地址。
- 交易哈希：只有已发出的链上交易才有交易哈希。资产方对发布、改额、撤下与接受报价的签名都不是链上交易，不显示为交易哈希，也不进入操作记录。

<a id="operation-records"></a>
**详情中的交易哈希只在操作记录展示**（用户 2026-10-26 要求整合，避免同一信息多处展示）：

- 每个链上对象的详情有一份操作记录，是该对象交易哈希在详情中唯一的展示位置：一轮融资申请的链上交易在[融资申请详情的操作记录](#application-detail)；一份质押份额的链上交易在[代币详情的操作记录](#token-detail-scope)。
- 清单、当前报价、报价历史、链上放款记录等其他详情内容只展示业务事实，不再重复交易哈希。
- 办理过程中的结果可以即时给出本次已取得的交易哈希，这是当次反馈；离开办理后统一在操作记录查看。
- 格式统一：按时间倒序，每笔已发出的链上交易一条，给出时间（标注时区）、操作、地址、交易哈希四项。“操作”写明这一笔是什么交易，如发布冻结、报价授权、链上放款、质押、解押。
- 地址取签名确认这笔操作的地址；没有用户签名、由平台直接执行的，取平台执行钱包地址。各操作的地址见对应操作记录。地址缩写，点击即复制完整地址，见[钱包地址的展示](#wallet-address)。
- 尚未成功的一笔在操作旁标明处理中、未成功或待核实；状态变化只更新这一条，同一笔交易不出现两条。
- 操作记录逐条按该笔交易的可见范围展示，不因合并到同一份记录而扩大可见范围。
- 交易哈希缩写展示（保留开头与结尾，位数由设计统一）；点击即复制完整值并提示已复制，复制失败时给出完整值供手动复制；另可跳转 Ethereum 区块链浏览器中该笔交易，在新窗口打开，原页面位置与办理进度保留。缩写只影响展示，复制与跳转都使用完整值。
- 交易哈希在平台取得后才展示，未取得时不显示占位值。处理中、明确失败（交易已发出）与结果待核实的一笔，办理结果与操作记录都标明当前状态并给出已取得的哈希；未签名、取消，或点击时校验、签名后核验未通过时没有链上交易，不显示交易哈希，也不产生操作记录。
- 区块链浏览器只供自行核对，打开它不改变任何业务状态；结论以平台确认的结果为准，链上与平台事实不一致时按[异常只提示联系客服（D-LS-63）](#d-ls-63)处理。

<a id="wallet-address"></a>
**钱包地址的展示**：持有地址、原持有地址、融资收款地址、放款地址、资金方还款收款地址，以及操作记录中的地址，在详情中完整展示并可复制；在可质押清单、质押代币清单、解除质押与提取清单和操作记录中缩写，点击即复制完整地址。规则见[钱包地址展示](../../00-钱包地址展示.md)。发布时选择融资收款地址的下拉选项按[融资收款地址（FP-40）](#fp-40)。

### 3.5 异常只提示联系客服（D-LS-63）

- 链上结果长期未知、已发起但项目已进入终态、事实冲突，以及结果待核实的那笔交易涉及的各份，提示“链上结果待核实，请联系平台客服人员”，并保留业务编号、代币、动作、已知 gas、已取得的交易哈希和保护限制。授权、发布或改额的冻结、平台执行的解冻长期没有结果时同样处理。
- 带对账差异的代币不计入有效质押，冻结它的一切新动作，并触发重算。
- 不提供工单、自动升级、人工改判或补记、强制释放、补偿、换地址或恢复资格流程；不编造联系方式或处理时限。客服介入不等于自动完成、退款或恢复。
- 普通的晚到结果（不跨期、不冲突）按原笔更新。项目已进入终态后才到达的转入结果，只记录代币的真实持有位置，不恢复项目或有效质押。

## 4. 借贷广场项目列表（F-LS-10）

适用角色：所有人，包括游客和登录未绑定角色。

- 一条记录一个项目；只列出已发布过融资需求的项目，待审核、已退回、可用但从未发布的项目不出现，也不暴露是否存在。发布以冻结上链成功为准，首次发布仍在处理中或失败的项目同样不出现。
- 游客、登录未绑定角色、资产方、资金方看到的条目、列表信息、筛选项与排序方式完全相同。
- 每条展示：[区块链网络（FP-39）](#fp-39)、项目名称、项目发布方、有效质押额、当前需求金额与币种及其状态、质押情况（质押不足时附质押缺口）、[项目状态（FP-04）](#fp-04)、[发布时间（FP-08）](#fp-08)。没有当前需求时显示“暂无融资需求”。发布时间按[日期、金额与展示](#quality)的时区规则展示并标注时区。
- 只显示中性的质押情况与缺口，不显示评价性标签。
- 支持以下筛选，条件可以组合使用：
  - 币种。
  - 项目期限：按[项目期限（FP-35）](#fp-35)的时长分档筛选；分档由设计决定，档位覆盖项目期限的全部可选范围（3 个月～1 年）且互不重叠。
  - 项目状态：多选，取值为列表中可能出现的状态：可用、募集中、已锁定、融资中、已关闭、已结清。
  - 可报价：是或否。“是”指项目当前一轮融资需求处于待报价（项目为募集中）且没有报价处理中、撤下处理中，项目未到期、未进入终态，且[质押水位](#water-level)安全；只按项目当时的事实判断，不按查看者的身份、机构资格或授信判断。能否实际报价，仍以报价办理时的校验为准。
  - 关键词：命中项目名称、项目编号、融资申请编号或项目发布方。
  - 代币类型：按[代币类型（FP-29）](#fp-29)筛选。
  - 质押不足：是或否，按项目当前的[质押情况（FP-20）](#fp-20)是否为质押不足判断。
  - 有效质押额区间：USD，按项目当前的有效质押额筛选。
  - 融资需求金额区间：USDT，按项目当前一轮需求的金额筛选；设置了任一端时，没有当前需求的项目不在结果中。
  - 两个金额区间都含两端，只填一端时为单侧限制；下限大于上限时提示调整，不执行筛选。
- 默认按发布时间倒序，可按需求金额、有效质押额排序；不按列表未展示的量排序。
- <a id="list-overview"></a>**市场概览**：列表上方给出以下几项，范围是当前筛选与搜索条件匹配的全部项目，不是已加载的部分：
  - 待报价需求金额合计与笔数：当前一轮需求处于待报价的项目，其需求金额相加（USDT），并给出笔数。
  - 有效质押额合计：各项目有效质押额相加（USD）。
  - 项目状态分布：可用、募集中、已锁定、融资中、已关闭、已结清各有多少个项目。
  - 四种身份看到的概览相同；改变筛选或搜索时随结果一起更新，排序与继续加载不改变概览；读取失败时显示不可用，不当作 0。
  - 概览不包含项目融资余额（已融资余额）的合计：该值属于项目统计，只向[项目详情按身份的可见范围（F-LS-82）](#f-ls-82)中能看到完整详情的身份开放。
- 每批 20 条，已显示的数量可得；继续浏览时自动追加下一批，已加载内容不丢失。不能按页码定位，也不能改变每批条数。换排序或重置筛选时从新条件的第一批重新开始。
- 从条目可进入项目详情；列表不提供逐条办理动作。从详情返回时保留原筛选、排序与已加载范围，并回到原来所在的条目。
- 暂无项目、筛选无结果、读取失败分别呈现；后两种分别提供清空筛选与重试。

<a id="F-LS-11"></a><a id="f-ls-11"></a>
## 5. 项目详情（F-LS-11）

适用角色：本企业资产方看本企业项目的全部详情，包括待审核、已退回和可用项目；资金方看所有已发布项目的详情；游客、登录未绑定角色和其他企业的资产方只看到基本信息，见[项目详情按身份的可见范围（F-LS-82）](#f-ls-82)。

- 项目摘要包含：项目名称、项目编号、项目发布方、代币类型、本项目质押合约（见[项目详情展示质押合约（F-LS-81）](#f-ls-81)）、项目期限与到期日、项目状态；项目详情同时展示[参考结算币种（FP-30）](#fp-30)、平台定值的[还款方式（FP-36）](#fp-36)，以及“发布时间（未发布时为创建时间）”：项目发布过时显示[发布时间（FP-08）](#fp-08)，从未发布时显示项目创建时间（只有本企业资产方能看到未发布的项目），时间按[日期、金额与展示](#quality)的时区规则标注时区。
- 当前需求金额与需求状态单独可辨，不与项目状态混为一项。
- 详情同时提供三类记录与三类办理入口，规则见[查看与办理分开（F-LS-20）](#f-ls-20)；资金方只看到本机构可办理的事项，不展示资产方的私有待办。

<a id="F-LS-18"></a><a id="f-ls-18"></a>
### 5.1 项目统计（F-LS-18）

- 项目统计固定五项：总质押额、有效质押额、本轮融资需求、已融资余额（即项目融资余额）、项目质押率。
- 上链处理中的代币不计入任何一项；上链成功即计入总质押额，代币有效且无对账差异的同时计入有效质押额。
- 项目在途金额不作常态展示。
- 可融金额不进入项目统计，只向本企业资产方在两处给出：一是项目办理区的发布融资需求环节，在没有进行中需求时常驻展示当前可融金额；二是发布或改额时填写的金额超出可融金额，提示当场重算的可融金额与差额。游客、资金方和其他企业在任何位置都看不到可融金额。
- 两者都不另行提供换算说明。

<a id="F-LS-81"></a><a id="f-ls-81"></a>
### 5.2 项目详情展示质押合约（F-LS-81）

每个项目审核通过时配置一份质押合约：运营从同一组合（区块链网络＋代币类型）下预先部署的质押合约中选用一份，同一份质押合约可以由多个项目使用。在整个项目详情中，读者始终能辨认本项目所配置的那一份质押合约：定位到任一类记录或打开只读详情时，合约信息都仍然可得；这是各类详情中唯一展示合约的位置，代币详情、融资申请详情不重复合约地址；各项签名办理按[所交互的合约、签名用途与交易哈希](#chain-display)展示同一质押合约。

| 信息 | 谁能看到 | 规则 |
| --- | --- | --- |
| [质押合约地址（FP-33）](#fp-33) | 能看到本项目完整详情的身份（本企业资产方、资金方） | 给出完整值，可复制，可在区块链浏览器打开核对；不能只给缩略值 |
| 质押链 | 能看到本项目完整详情的身份（本企业资产方、资金方） | 即创建时选择的[区块链网络（FP-39）](#fp-39)，本期仅 Ethereum |
| [合约配置完成时间（FP-38）](#fp-38) | 能看到本项目完整详情的身份（本企业资产方、资金方） | 合约配置成功（即审核通过）的时刻，标注时区 |

- 同一份质押合约下其他项目的名称、份额、额度或冻结不在本项目展示；本项目的统计、清单与额度只计归属本项目的份额。定位项目一律用项目编号，不用合约地址。
- 待审核与已退回的项目只有本企业资产方能看到，此时还没有合约：只说明“审核通过后由平台为本项目配置质押合约”，不显示地址占位值、配置时间或候选合约。合约配置处理中、配置失败后再次发起期间同样如此。
- 项目已关闭或已结清后，合约信息照常展示，因为未提取的代币仍在合约内。
- 资产方授权、发起质押、自助解押或提取时，交易的目标都是本项目所配置的质押合约，即项目详情所示地址；发布与改额的冻结由平台执行钱包作用于同一份合约。授权签名、质押交易签名、发布、修改金额、撤下、解除质押与提取都在签名主动作旁展示这份合约，供签名前核对（用户 2026-10-22、2026-10-26 要求）；不向其他组合的合约发起。关闭项目不需要签名，办理中不展示合约，保留本次动作的必要后果与校验提示（用户 2026-10-23 要求）。
- 本项目同时配置的放款合约与还款合约（每个项目各一份，由平台为本项目部署），按放款、还款两个模块的规则使用与展示，本模块不展示。

<a id="F-LS-82"></a><a id="f-ls-82"></a>
### 5.3 项目详情按身份的可见范围（F-LS-82）

项目详情的可见范围按当前身份与项目归属决定：

| 身份 | 看到什么 | 不可见处的说明与入口 |
| --- | --- | --- |
| 游客（未登录，含登录时身份调取失败、本次登录未成立） | 只看到项目基本信息 | 说明需登录后才能查看，并提供登录入口（即[登录主干的登录入口](../01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#f-l02)“连接钱包”）；登录后回到本项目，按新身份重新判断 |
| 登录未绑定角色 | 只看到项目基本信息 | 统一说明“以下信息仅供资金方查看”，并提供“申请成为资金方”入口 |
| 资产方查看本企业的项目 | 全部信息，包括本企业待审核、已退回和可用的私有项目 | 不适用 |
| 资产方查看其他企业的项目 | 只看到项目基本信息 | 统一说明“非自身项目，无法查看”；不提示申请成为资金方，也不提供其他入口 |
| 资金方 | 所有已发布项目的详情：项目摘要、项目统计、质押情况与缺口、质押合约、三类记录 | 不适用；私有内容仍按当事方开放，见下方 |

- **项目基本信息**：项目名称、项目编号、项目发布方、项目状态、代币类型、项目期限（生效日～到期日）。
- 只看到基本信息的身份，其余内容一律不展示，也不能通过直接访问取得，包括：项目统计、质押情况与质押缺口、质押合约信息、参考结算币种、三类记录及其详情、办理入口与待办。
- 待审核、已退回和尚未发布的项目只有本企业资产方能看到；资金方在内的其他身份都看不到，也不暴露是否存在。
- 凡已绑定资金方角色的账号都按资金方的范围查看，包括入驻审核中或已驳回的；可看不等于可以出资。
- **资金方看到的私有边界**：资金方能看所有已发布项目的详情，但以下内容仍只对相应当事方开放：
  - 报价条款、授信、账户、协议与凭证，只对该笔业务的资产方与报价机构开放；
  - 可融金额只对本企业资产方给出；
  - 每份质押的当前去向、上链结果与 gas 只对本企业资产方开放，资金方只看到代币是否计入有效质押。
- “申请成为资金方”进入资金方入驻流程，规则沿[资金方账户的入驻引导与返回](../02-资金方登录与账户体系/01-资金方登录与账户体系-PRD.md#F-L57)；取消入驻回到本项目详情，仍只看到基本信息。提交入驻申请后即为资金方，按资金方的范围查看；入驻审核尚未通过不等于可以出资。
- 借贷广场列表不按身份收窄：所有身份看到的列表字段相同，见[借贷广场项目列表（F-LS-10）](#f-ls-10)。

## 6. 创建融资项目并提交审核

<a id="create-entry"></a><a id="F-LS-80"></a><a id="f-ls-80"></a>
### 6.1 创建入口（F-LS-80）

- 借贷广场的“创建融资项目”入口只对判定为资产方的用户显示。
- 游客（含登录时身份调取失败、本次登录未成立的情况）、登录未绑定角色和资金方都看不到这个入口。
- 不具备资产方身份时，直接访问创建地址或直接提交创建一律被拒绝，且不暴露任何企业的项目。
- 资产方也可从控制台进入创建，控制台入口沿控制台现有的可见范围。

<a id="F-LS-01"></a><a id="f-ls-01"></a>
### 6.2 填写创建信息并提交（F-LS-01）

适用角色与前提：本企业资产方。

- 创建时以简短提示说明固定网络 Ethereum 与项目生效日；资产方填写项目名称、选择代币类型、填写项目质押率、选择项目到期日、点选参考结算币种后提交。还款方式在项目详情查看，不作为创建页的展示项（用户 2026-10-23 要求）。
- 项目质押率与到期日的上限取所选组合在[运营端融资参数配置](../../运营端/02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#f-o-fc-05)中的当前参数；以资产方提交创建时刻的参数为准，校验与锁定用同一份值，办理中运营改了参数也按提交时刻的值。
- 提交即进入项目审核。创建本身不勾选代币、不发生链上操作、不需要签名、不产生任何费用；提交前的说明首句就讲清这一点。
- 一个融资项目对应一份质押合约。
- 创建与质押是两次独立的办理，不串成一次连续流程；创建过程也不包含发布步骤。

| 创建信息 | 含义与类型 | 必填与默认 | 可编辑范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| <a id="FP-39"></a><a id="fp-39"></a>区块链网络（FP-39） | 单选，本项目的质押链：本项目的质押合约、放款合约与还款合约都在这条网络上，只有铸造链为该网络的代币可以质押；按链 ID 区分 | 本期只有 Ethereum 一个选项，默认选中 | 本期不可更改；创建时随项目锁定，之后只读 | 选项增加前不提供其他网络；不能为空。融资参数配置中出现其他网络的组合，也要等本模块开放该网络后才能选用 |
| <a id="FP-02"></a><a id="fp-02"></a>项目名称（FP-02） | 文本 | 必填，1～60 个字符 | 待审核期间不能修改；已退回时可修改并随重提一并提交；合约配置完成后只读 | 同企业不要求唯一，同名项目以项目编号区分；空值或超过 60 个字符不能提交 |
| <a id="FP-29"></a><a id="fp-29"></a>代币类型（FP-29） | 单选，形如“ERC-3525-应收账款”（代币标准与底层资产类型合为一个字段） | 必选；可选值见下方“代币类型的候选” | 已退回时可在同一规则内重选；合约配置完成后只读，本项目此后只接受同类型代币 | 不能自定义输入；没有可选类型时不能提交，并按下方两种原因分别说明。字段须能容纳其他代币标准，不写死 ERC-3525 或任何代币标准 |
| <a id="FP-34"></a><a id="fp-34"></a>项目质押率（FP-34） | 百分比，资产方自填 | 必填 | 待审核期间不能修改；已退回时可修改，重提时按重提当时该组合的最高质押率重新校验；合约配置完成后锁定终身、只读 | 大于 0、不超过运营对所选组合（区块链网络＋代币类型）配置的[最高质押率（FC-02）](../../运营端/02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#fc-02)，最多两位小数。超过上限不能提交并给出当前上限；0、负数或超过两位小数不能提交并给出允许范围，不自动四舍五入。锁定后运营调整配置不影响本项目，全部额度计算都用锁定值 |
| <a id="FP-35"></a><a id="fp-35"></a>项目期限（FP-35） | 生效日～到期日。生效日就是项目创建日，自动带出、只读；到期日用日期选择，不提供月数或天数输入 | 到期日必选 | 合约配置完成后只读；审核退回重提时可在同一规则内重选 | 见下方“到期日规则” |
| <a id="FP-30"></a><a id="fp-30"></a>参考结算币种（FP-30） | 多选：USDT、USDC | 必选至少一项，首次默认空 | 待审核期间不能修改；已退回时可修改；合约配置完成后锁定，各轮需求沿用；在项目详情与融资申请详情中查看，发布和改额办理中不展示 | 不支持的币种不能提交。它只供参考，不限制资金方选择任何已支持的报价币种，也不决定实际币种、额度或合同 |
| <a id="FP-36"></a><a id="fp-36"></a>还款方式（FP-36） | 平台定值：按季付息、到期还本付息 | 项目自动沿用平台定值，在项目详情展示 | 只读，不提供选择 | 不按企业或项目区分；创建办理不展示 |
| 企业与项目编号 | 企业取当前登录企业；项目编号创建时生成 | 系统生成 | 只读 | 项目编号全局唯一、终身不变 |

<a id="token-type-options"></a>**代币类型的候选。** 在所选区块链网络下，同时满足以下两条的代币类型才可选：

1. 本企业在该网络上持有（持有地址归属本企业）该类型的已准入代币。
2. 该代币类型与所选网络组成的组合，在融资参数配置中为已配置。

| 本企业在所选网络上的情况 | 结果 |
| --- | --- |
| 持有该类型的已准入代币，组合已配置 | 该类型可选，按该组合的参数校验 |
| 持有该类型的已准入代币，组合未配置 | 该类型不可选、不能用它提交；资产方能看出原因是“该代币类型暂未开放融资”，而不是没有代币。运营配置后，资产方重新进入或刷新即可选到，不需要重新准入或重新发行 |
| 没有任何已准入代币（含代币仍在准入审核中或被退回） | 没有可选类型，不能提交；说明本企业在该网络上暂无已通过准入审核的代币 |
| 组合或参数读取失败 | 说明暂不可办理并可重试；不以默认值或无上限继续 |

- 资产方看不到组合的配置状态、参数变更记录或运营端入口，只看到可选的类型与当前上限。
- 同一代币类型在不同网络上是不同组合，按项目所选网络取对应组合。

<a id="D-LS-66"></a><a id="d-ls-66"></a>**到期日规则。** 可选的到期日同时满足以下三条：

1. 不早于创建日 + 3 个月。
2. 不晚于创建日 + 所选组合的[最长项目期限（FC-03）](../../运营端/02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#fc-03)（整月数），且不超过创建日 + 1 年；两端都可选。
3. 晚于当前日期，当天和过去的日期都不可选。

- “加 N 个月”取目标月的同一天；目标月没有这一天时取该月最后一天。例如 11 月 30 日加 3 个月为次年 2 月的最后一天。
- 日期按 UTC 业务日期判定。
- 可选范围外的日期不能选；提交时按当刻条件复核，越界不能提交，并给出当前可选的起止日。
- 所选组合的参数读取失败时不能提交，说明暂不可办理并可重试；不以无上限或默认值继续。
- 审核退回后修改重提：生效日仍是原创建日，不重新起算；第 1、2 条仍按创建时锁定的最长项目期限，第 3 条按重提当日判断。三条不能同时满足时本项目不能重提，可另建项目。

<a id="F-LS-12"></a><a id="f-ls-12"></a>
### 6.3 待审核、退回重提与空池（F-LS-12）

- 提交后项目进入待审核，属本企业私有：不出现在广场，不暴露存在性；不能发起质押，也不能发布融资需求；创建信息不能修改。
- 审核通过（即合约配置成功）后项目转为可用，资产方可在项目详情[发起代币质押](#pledge-apply)。审核通过后不自动进入质押办理，也不自动勾选代币。
- 审核退回时给出面客可读的原因，资产方可以修改后重新提交；重提不产生新项目、不产生新项目编号，生效日不变。
- 待审核或已退回的项目到达有效期至时自动关闭，见[待审核或已退回时到期自动关闭（D-LS-72）](#d-ls-72)。
- 项目通过审核后、有效质押价值仍为 0 时是空池（如尚无代币质押成功）：发布入口可见但不能提交，并说明“本项目暂无有效质押，请先完成代币质押后再发布”。
- 项目可以长期停留在空池，随时可以发起质押或按条件关闭；不会因未质押被自动关闭、清除或催办。到期时与其他项目一样按[项目状态](#project-state)规则自动终结。
- 同一企业可同时存在的空池项目不设数量上限，创建不因已有空池项目被拦截或提示。
- 质押全部上链失败，或已质押的代币全部转出或失效后，项目回到空池，可以重新发起质押。
- 创建、质押、发布各自可以中断后再继续，不要求重复质押或重复付费。

<a id="project-review"></a><a id="F-LS-22"></a><a id="f-ls-22"></a>
## 7. 项目审核与合约配置（F-LS-22）

适用角色：运营在运营端办理，规则见[运营端项目合约管理](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md)；本节只写面客端看到的结果。

- 审核与合约配置是同一步：运营核对通过后，从区块链网络、代币类型都与本项目一致的预先部署的质押合约中选用一份并确认，平台随即为本项目部署放款合约与还款合约；两份都部署成功、所选质押合约对本项目生效才算配置成功，配置成功即视为审核通过（用户 2026-10-21 裁定配置成功即审核通过；合约来源按用户 2026-10-26 要求，办理规则见[通过并部署合约（F-CM-09～F-CM-11）](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#m3)）。
- 本项目从此绑定所选的质押合约与为本项目部署的放款合约、还款合约，终身不变。同一份质押合约可以由同组合的多个项目使用，放款合约与还款合约只属于本项目（见[审核对象（D-CM-03）](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#d-cm-03)）。
- 审核结论只有通过与退回两种，没有时限：不会因等待而自动通过或自动失败。
- 退回必须给出面客可读的原因；资产方修改后重新提交，仍走同一条审核与合约配置流程。重提时改了代币类型的，审核通过时从新组合下的质押合约中选用。
- 配置失败（放款合约或还款合约未部署成功，或所选质押合约未能对本项目生效）或结果待核实视为审核未完成，项目仍为待审核，由运营再次发起部署；不需要资产方重新提交，不改变生效日，不产生第二个项目，也不向资产方发消息。该组合暂无可选的质押合约而不能通过时，资产方同样只看到待审核。
- 合约配置由平台执行（放款合约与还款合约由平台签名地址部署），运营人员不签名；资产方不签名、不付费（用户 2026-10-21 裁定）。
- 通知：审核通过与审核退回各由运营端项目合约管理发送一条站内信，模板见[消息通知册](./03-融资需求与代币质押-消息通知.md#t-ls-09)。

<a id="D-LS-71"></a><a id="d-ls-71"></a>**合约配置进行中暂不可关闭（D-LS-71）。**

- 运营已提交通过、平台正在配置合约而结果尚未回写期间（含结果待核实），资产方不能关闭项目。
- 此时项目对资产方仍显示待审核；关闭入口可见但不能提交，并说明暂不可关闭，不透露配置失败或重试等运营端细节。直接提交关闭同样被拒绝，项目与代币都不变化。
- 配置结果回写后按结果处理：配置成功即审核通过，项目转为可用，此后按可用状态的条件关闭；配置失败则项目仍为待审核，可以关闭。
- 资产方关闭与运营提交通过同时发生时，只有先生效的一笔成立。
- 运营端的对应规则见[配置处理中资产方不能关闭项目（D-CM-21）](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#d-cm-21)。

| 项目审核信息 | 含义与类型 | 何时有值 | 可见范围 | 规则 |
| --- | --- | --- | --- | --- |
| <a id="FP-33"></a><a id="fp-33"></a>质押合约地址（FP-33） | 文本，运营为本项目选用的质押合约地址 | 审核通过后必有；配置完成前为空 | 本企业资产方、资金方 | 终身不变、只读；不显示占位值。同一份质押合约可以由同组合的多个项目使用，多个项目可能显示同一地址，因此它不是项目的唯一标识，定位项目用项目编号 |
| <a id="FP-38"></a><a id="fp-38"></a>合约配置完成时间（FP-38） | 时间，合约配置成功即审核通过的时刻 | 审核通过后必有 | 本企业资产方、资金方 | 取运营端回写的配置事实，只读、终身不变；配置失败和再次发起不产生该时间 |

<a id="pledge-apply"></a><a id="F-LS-05"></a><a id="f-ls-05"></a>
## 8. 发起代币质押（F-LS-05）

适用角色与前提：本企业资产方；项目已通过审核，处于可用、募集中、已锁定或融资中。待审核、已退回、已关闭、已结清的项目不能发起质押。

- 资产方从控制台的融资项目进入本项目，在项目详情内办理。首笔质押与追加质押共用同一个入口、同一条流程和同一套规则。
- 一次质押办理依次为：批量选择份额 → 按本次所选数量授权本项目的质押合约（已有数量相同、尚未使用的授权时沿用） → 签名一笔质押交易批量转入；上链成功即质押成功，直接计入有效质押，不经审核（用户 2026-10-21 裁定）。
- 从可质押清单批量勾选质押份额：至少一份、不重复；每份按其全部持有数量整份勾选，没有数量输入，不能拆分。
<a id="same-address"></a>
- **同一地址批量**：一次办理（授权与签名）只能包含同一个持有地址上的份额。勾选了某个地址的份额后，其他地址的份额不能同时勾选，并说明原因；要质押其他地址的份额，另行发起一次。
- 同一笔代币在本企业的多个地址上都有持有时，每个地址上的持有各是一份，各自整份质押，可以分别进入不同项目。
- 清单默认按本项目代币类型过滤，一份一行，展示代币编号、持有地址、持有数量与代币符号、份额价值；同一笔代币在本企业多个地址上的持有，分别列为多份。资格仍按[哪些代币可以质押（F-LS-04）](#f-ls-04)判断，选币清单不再单列有效性、账期、买方、合同号或发票号。
- <a id="candidate-token-detail"></a>**选币时查看代币。** 点击候选代币编号，可只读查看这份代币的编号、持有地址、持有数量与单位、份额价值、底层应收账款账期和买方；只向本企业资产方开放本企业当前可质押份额，不展示未发生的本项目质押记录。返回选币时保留勾选与原位置，查看不触发质押、不改变授权，也不增加跨模块入口。已质押份额的详情范围见[质押代币清单与代币详情（D-LS-67）](#d-ls-67)。

<a id="eligibility"></a><a id="F-LS-04"></a><a id="f-ls-04"></a>
### 8.1 哪些代币可以质押（F-LS-04）

一份质押份额同时满足以下七条才可选：

1. 所属代币已通过[代币准入审核](../../运营端/06-代币准入审核/01-代币准入审核-PRD.md#f-ta-07)（已准入代币）。
2. 持有地址归属当前企业（按只读代币域给出的企业归属，不按地址形态猜测）。
3. 这份数量不在任何质押合约内，也没有其他进行中的质押或解押占用。
4. 发行平台判为有效。
5. 与本项目代币类型一致。
6. 代币的铸造链与本项目的[区块链网络（FP-39）](#fp-39)一致。
7. 没有对账差异标记。

- 代币准入通过后，本企业持有的份额即出现在可质押清单；待审核、已退回的代币不出现。同一笔代币中由其他持有方持有、或已在质押合约中的部分，不影响本企业其他份额的可选性。
- 其他企业持有的份额不可见，直接提交一律被拒绝。
- 被进行中的质押或解押占用、已释放尚未提取的代币不可选，可以只读提示占用来源。
- 并发选择同一份额时，只有一笔成立；同一份额同一时刻只能在一个项目中。同一笔代币的不同份额可以分属不同项目。
<a id="D-LS-62"></a><a id="d-ls-62"></a>
- **每份一个当前持有地址**：每份质押份额只有一个当前真实的链上持有地址，对应该份的持有数量与份额价值。企业归属、当前地址、质押前原持有地址分别表达；已释放未提取的份额不能提前改回企业地址，原地址和合约地址不重复计量。地址、归属或数量价值不可靠时不放行。份额价值按签发价值折算，不重估；失效只取发行平台的结果，一笔代币失效时它的所有份额同时失效。

<a id="execution"></a><a id="F-LS-08"></a><a id="f-ls-08"></a>
### 8.2 授权并签名发起质押（F-LS-08）

<a id="F-LS-14"></a><a id="f-ls-14"></a>
- 一次质押有两次签名，按顺序进行：先用所选份额的持有地址签名授权，授权交易上链成功后，再用同一地址签名质押交易（用户 2026-10-21 裁定）。两次都是资产方本人在钱包确认，平台不代签、不代付、不垫付。
- 授权与质押产生的链上 gas 都由资产方承担，平台不收服务费、不返还；失败时已经产生的 gas 同样不退（F-LS-14）。

<a id="D-LS-68"></a><a id="d-ls-68"></a>**授权与签名（D-LS-68）。**

- **批量办理，不逐张操作**：质押与释放都按批办理（用户 2026-10-21 裁定）。一次办理勾选同一持有地址上的多份，每个涉及的代币发行合约授权签名一次，质押签名一次，一笔质押交易把所选份额全部转入；不逐张授权、不逐张签名。
- **授权按本次所选数量给出**（用户 2026-10-26 要求，与[我的控制台的质押授权数量（D-MC-218）](../09-我的控制台/01-我的控制台-PRD.md#d-mc-218)一致）：
  - 授权对象是本项目所配置的质押合约，以“持有地址＋代币发行合约”为单位。
  - 授权数量等于本次从该代币发行合约所选份额的数量合计，以代币数量与单位表示；质押合约只能调取不超过授权数量的代币。
  - 授权只覆盖本次所选份额。该地址之后新增或新收到的代币、追加质押（含质押不足后的补充质押），都按当次所选数量再次授权。例如：地址 A 持有 100 枚，本次授权 100 枚并质押成功；之后地址 A 又有 50 枚，质押这 50 枚时须再次授权 50 枚。
  - 授权数量严格等于本次所选数量，不提供放大授权或不限量授权。
- **链上限制**：授权记录在代币发行合约上。所选份额来自几个代币发行合约，就有几笔授权，资产方逐个在钱包确认。全部所需授权都上链成功后，“签名并发起质押”才可用。
- **沿用与重新授权**：
  - 该地址对这份质押合约、同一代币发行合约已有一笔已授权且尚未使用的授权，数量与本次所选数量相同时（例如质押上链明确失败后按原选择重试），沿用这笔授权，不再签名授权。
  - 数量不同时，按本次所选数量重新授权。授权不叠加：重新授权上链成功后，此前尚未使用的那笔授权不再有效（已被取代）。
  - 质押上链成功后，这笔授权按质押数量用完（已使用），不能再被其他质押沿用。
  - 授权的已被取代、已使用等状态在[我的控制台的链上授权](../09-我的控制台/01-我的控制台-PRD.md#f-mc-14)集中查看。
- **授权范围与后果**：授权后，这份质押合约只能按本次授权数量调取该地址在该发行合约下的代币，用于本次质押；授权用完或被取代后即失效，未使用时一直有效，直到资产方撤销。撤销由[我的控制台的链上授权](../09-我的控制台/01-我的控制台-PRD.md#revoke)统一承载，本模块的质押办理不提供撤销入口。质押合约只在该地址签名发起的质押交易中转入代币，转入哪些以该笔交易所列为准。授权时的签名用途须讲清这一范围。
- 授权不转移代币，不改变份额的质押状态，不计入任何额度或融资金额，也不占用份额。授权不属于某一个项目：同一份质押合约下任一项目的质押，都按上述规则沿用或重新授权。
- **单次份数上限**：一笔质押交易能容纳的份数受链上限制，上限由研发按链上能力确定；达到上限后不能继续勾选并说明原因，其余份额另行发起。
- **三步办理**（用户 2026-10-22 要求）：第一步只选择代币；第二步授权签名；第三步交易签名。链上执行成功即交易成功、质押成功。每一步只展示本步需要的信息，具体呈现由设计决定。

| 步骤 | 资产方做什么 | 本步必须看到的信息 |
| --- | --- | --- |
| 第一步：选择代币 | 在可质押清单中勾选同一持有地址上的份额 | 已选份数与份额价值合计，随勾选即时更新 |
| 第二步：授权签名 | 对需要授权的代币发行合约逐个在钱包确认授权，每笔授权上链成功后才能进入第三步；所选数量都有可沿用的授权时，本步无需签名，直接进入第三步 | 每笔授权的本次授权数量（该发行合约下所选份额的数量合计与单位）及所选份额价值合计（USD，供核对）；被授权的质押合约（名称、网络与完整地址）及本笔授权所在的代币发行合约地址；签名用途：用本持有地址授权这份质押合约调取本次所选数量的代币，用于本次质押，用完或被新的授权取代即失效，授权本身不转移代币；这是链上交易，gas 由本企业承担、失败已产生的不退，与登录无关；本步预估 gas 及费用币种 |
| 第三步：交易签名 | 点击“签名并发起质押”（Sign and pledge），在钱包确认质押交易 | 已选份数与份额价值合计、质押合约（名称、网络与完整地址）、本步预估 gas 及费用币种；签名用途与后果：签名后发起交易，将所选代币从本持有地址转入所示质押合约，上链成功才完成质押并计入有效质押额；gas 由本企业承担、失败已产生的不退，与登录无关 |

- 本次授权数量就是链上授权的上限，只覆盖本次所选份额；所选份额价值合计（USD）只供核对，不是授权上限，也不是实际融资金额。沿用已有授权时，同样展示被沿用授权的数量。
- 进入下一步不算确认、不提交任何内容；返回上一步时保留已选份额，已上链的授权不撤销；重选后本次授权数量、所选摘要、尚需授权与各步预估 gas 随当前选择更新；重选后所选数量与已上链的未使用授权不同的，须按新数量重新授权。
- 授权与质押签名各是本步唯一的确认：点击即唤起钱包，钱包内的确认就是最终确认，点击本身即视为本企业确认承担本步 gas。点击前后都不再出现确认弹窗、费用确认或“我已知晓”之类的勾选。授权的动作名称由设计决定；未勾选时不能进入第二步。
- 预估 gas 只给合计及费用币种，可质押清单中不逐份列出。
- 办理中不单列本次签名地址或持有数量合计。持有地址在清单中逐份标明，用于同一地址批量；质押合约必须在授权签名与质押交易签名两步展示，且与项目详情一致，展示规则见[所交互的合约、签名用途与交易哈希](#chain-display)。授权需要对多个代币发行合约逐个确认时，标明当前这一笔授权的是哪一个发行合约。
- 项目详情的质押入口不再另设一处同样内容的告知；创建页不出现任何质押或 gas 告知。

**授权结果（每笔授权交易）。**

| 授权结果 | 份额与后续 | 资产方看到什么 |
| --- | --- | --- |
| 成功 | 该地址对本质押合约有了该代币发行合约下本次所选数量的授权（已授权、未使用），代币仍在原持有地址、仍可质押；同一地址此前未使用的同类授权被取代；所需授权全部成功后可以签名质押 | 授权完成及授权交易哈希；仍需授权的发行合约（如有）与“签名并发起质押”是否可用 |
| 明确失败 | 该发行合约没有授权，来自它的份额不能签名质押；份额保持可质押 | 可读原因、是否已产生 gas 及金额，交易已发出的给出授权交易哈希；可以重新授权，或取消勾选这些份额后对其余份额继续 |
| 未签名、取消或钱包不可用 | 未发生链上操作、未产生 gas；份额保持可质押 | 说明本次未授权 |
| 处理中或结果未确认 | 不能签名质押，也不能对同一发行合约重复发起授权；其他办理照常 | 已等待时长、已知 gas 与已取得的授权交易哈希，未知标“待核实”；离开不撤销授权，回来后按当时结果继续，长期未知按[异常只提示联系客服（D-LS-63）](#d-ls-63) |

- 授权成功后资产方未签名质押、取消质押签名或离开的，授权保留在链上（已授权、未使用），份额仍可质押；下次按相同数量质押时沿用，数量不同时重新授权。
- 授权结果不发送站内信。授权交易哈希只在本次办理的结果中给出；授权的集中查看与撤销在[我的控制台的链上授权](../09-我的控制台/01-我的控制台-PRD.md#revoke)。

<a id="D-LS-75"></a><a id="d-ls-75"></a>**提交给质押合约的信息（D-LS-75）。**

质押交易：

| 信息 | 来源 | 规则 |
| --- | --- | --- |
| 目标项目 | 本项目在质押合约中的项目标识 | 必有。同一份质押合约可以由多个项目使用，靠它把份额归属到本项目；不能填写或改为其他项目 |
| 逐份代币标识 | 每份的代币发行合约地址、链上代币 ID（tokenId）与资产槽位（slot） | 必有，取只读代币域；三项须与代币发行合约中的链上事实一致，不一致时该笔交易不执行；合约逐份记录 |
| 逐份持有数量 | 这一份的全部持有数量 | 必有，整份转入；以链上事实为准 |
| 原持有地址 | 签名并发送质押交易的地址 | 不另行填写；合约记录为转出时的唯一去向 |
| 逐份份额价值（USD） | 平台按签发价值折算 | 合约据此做池水位管控与可撤回上限判断；只能由平台给出，资产方不能填写或改动 |
| 本次动作标识 | 平台生成 | 用于回写结果与防止重复执行；同一标识只执行一次 |

释放交易（解押、撤回与提取）：目标项目、逐份代币标识（代币发行合约地址、链上代币 ID、资产槽位）与本次动作标识；去向固定为合约记录的原持有地址，不另行填写。

平台另外同步给质押合约的业务事实（由平台执行钱包执行，资产方不签名、不付费）：本项目的冻结与解除（见[发布签名与冻结（D-LS-74）](#d-ls-74)），以及池内代币的失效与对账差异标记。合约据这些事实计算合约口径的有效质押价值，用于[合约与平台双重判断（D-LS-76）](#d-ls-76)。

- 不上链的信息：质押率、额度、企业名称与主体信息、买方、合同号、发票号与准入资料。链上数据公开可查，私有业务信息不写入合约。
- 份额价值以资产方无法篡改的方式交给合约，具体方式由研发确定，见[依赖](#dependencies)。

<a id="D-LS-51"></a><a id="d-ls-51"></a>**点击时复核所选份额。**

- 点击授权与点击“签名并发起质押”时，都对所选的每一份复核资格，并复核预估 gas。
- 有任何变化时不唤起钱包，此时任何一张都未发起：指出变化的代币，更新选择、已选汇总与预估 gas，保留仍有效的选择，由用户再次点击才发起。这是资格变化时的必要处理，不是常规的二次确认；不静默剔除或补选。
- 未签名、取消签名或钱包不可用时，说明本次未发生链上操作、未产生 gas，代币保持可质押。

**质押上链结果（一笔交易同成同败）。** 一次签名就是一笔质押交易，交易内的全部份额同时成功或同时失败；结果在每份上分别呈现。

| 上链结果 | 代币与额度的变化 | 资产方看到什么 |
| --- | --- | --- |
| 明确成功 | 本笔交易的全部份额质押成功：进入本项目所配置的质押合约并归属本项目，质押状态为已质押；计入总质押额，代币有效且无对账差异的同时计入有效质押价值，不经审核（用户 2026-10-21 裁定，[Q-LS-01](#q-ls-01)）；本笔所用授权按质押数量用完 | 完成时间、本笔交易的实际 gas、[质押交易哈希（PL-08）](#pl-08)。上链成功不发通知（用户 2026-10-21 裁定，[Q-LS-02](#q-ls-02)） |
| 明确失败 | 本笔交易的全部份额都未进入合约，不计任何额度，按当前资格可以重新发起；已给出的授权仍有效且未使用，按原选择重新发起不必再授权，改变所选数量的须重新授权 | 可读原因、是否已产生 gas 及金额、交易已发出的质押交易哈希、下一步；发送一条[链上操作失败通知（N-LS-04）](./03-融资需求与代币质押-消息通知.md#n-ls-04)，列出本笔涉及的全部代币 |
| 结果未确认 | 本笔交易的全部份额处理中，不计任何额度；不能重押、解押或重复发起 | 已等待时长、已知 gas 与已取得的质押交易哈希，未知标“待核实”；其他份额和项目的其他办理照常，不锁整池 |

- 不出现同一笔交易部分份额成功、部分失败的结果；不同的交易各自独立，一笔失败不影响另一笔已成功的质押。
- 重复点击、刷新或重复提交同一次操作，链上只产生一笔授权或一笔质押交易，gas 只记一次。
- 资产方质押签名成功即结束本次办理，回到质押代币清单查看结果。

<a id="F-LS-21"></a><a id="q-ls-02"></a><a id="f-ls-21"></a>
## 9. 质押结果与质押代币清单（F-LS-21）

适用角色：本企业资产方；资金方的可见范围见下方清单。

- 代币质押没有审核环节：资产方授权并签名发起质押，合约执行上链，执行成功即质押成功、直接计入有效质押（用户 2026-10-21 裁定）。运营不对逐张质押作结论，资产方也不为质押结果另行确认。
- 一次签名发起的多份属于同一笔质押交易，同成同败；提交批次即这笔交易，用于追溯。不同交易的结果互不影响。
- 质押成功后的后续动作只有按条件转出，以及项目终态后的提取，都从[解除质押](#withdraw)办理。

| 本笔当前去向 | 代币与额度 | 资产方看到什么与后续 |
| --- | --- | --- |
| 已计入有效质押额 | 代币在合约内，计入总质押额与有效质押额，参与质押情况判断 | 质押成功时间；之后没有任何截止或二次确认；按有效抵押物的条件转出 |
| 解押处理中 | 资产方已签名发起转出，结果尚未回写；有效抵押物撤回发起即预扣其有效价值 | 已等待时长与已知 gas；不能重复发起 |
| 已解押退回 | 转出成功，代币回到原持有地址，本笔终结 | 转出时间与转出交易哈希；按当前资格可以重新发起质押 |

- 代币在合约内但已失效或带对账差异的，仍为已质押，只是不计入有效质押价值，展示见[质押代币清单与代币详情（D-LS-67）](#d-ls-67)。
- 重新发起同一份额生成新的一笔，旧记录留在该份额代币详情的操作记录中。

### 9.1 质押代币清单与代币详情（D-LS-67）

- 一份质押份额一条记录，包括当前在本项目合约内或正在上链处理的份额（已质押、已释放待提取），默认按上链时间倒序。同一笔代币有多份在本项目时分别成行。
- 代币列只展示代币标识；质押数量独立成列，展示该份数量与代币单位，不再附在代币列中（用户 2026-10-23 要求）。同一代币的不同份额仍各自展示数量，不合并、不改变统计口径。
- 上链处理中的代币只对本企业资产方显示。
- 本企业资产方可以按当前去向、代币编号筛选并重置；筛选可以查到已移出本项目的代币。
- 清单的“当前去向”以[本笔当前去向（PA-15）](#pa-15)为基础，按这份份额此刻的事实呈现：已质押、但代币已失效或有对账差异的，显示“已质押·不计入有效质押”，不显示“已计入有效质押额”；项目终态整池释放后显示“已释放待提取”；提取处理中、提取成功分别显示“解押处理中”“已解押退回”。PA-15 本身的取值不变。
- 清单不提供勾选，也不提供逐条办理动作；质押、解除质押、提取都从对应办理入口进入。
- 每页固定 5 条，不提供条数切换。
- 持有地址指质押前持有这份数量、解押或提取后转回的本企业地址；代币在合约内期间，链上的当前持有方是本项目质押合约。

| 清单信息 | 本企业资产方 | 资金方 |
| --- | --- | --- |
| 代币编号、持有地址、质押数量与代币符号、份额价值（USD）、有效或失效 | 可见 | 可见 |
| 是否计入有效质押 | 可见 | 可见，只给结果、不给原因 |
| [本笔当前去向（PA-15）](#pa-15) | 每份可见 | 不可见 |
| 链上执行状态 | 可见，处理中显示已等待时长 | 不可见 |

<a id="q-ls-26"></a><a id="token-detail-scope"></a>点击一张代币进入只读的代币详情，详情内没有办理动作。借贷广场的代币详情只回答“这份代币在本项目质押得怎样”：识别这份代币所需的信息、它对本项目额度的贡献与本项目内的质押事实；代币的完整资料（代币基本信息、底层资产与链上存证、全部持有方、准入资料）不在本模块展示，代币详情也不提供前往资产广场、我的控制台或其他位置的入口；用户需要更详细的信息时，自行从导航进入相应模块查看（用户 2026-10-21 裁定，[Q-LS-26](#q-ls-26)）。

| 详情内容 | 谁能看到 | 内容 |
| --- | --- | --- |
| 代币信息 | 本企业资产方、资金方 | 清单信息，加底层应收账款账期、买方；不显示合同号或发票号。这份质押份额的数量小于该笔代币的全部数量时，另显示“该笔代币数量与价值”：该笔代币的全部数量与代币符号、该笔代币价值（USD），供与份额价值对照；份额就是整笔时不另显示。这份代币所在的就是项目详情所示的本项目质押合约，代币详情不重复合约地址 |
| 当前去向与下一步 | 仅本企业资产方 | 用文字说明有效抵押物按条件可转出、已失效代币可清出、已释放待提取等下一步；办理仍从解除质押入口进入 |
| 操作记录 | 本企业资产方看全部；资金方只看到本份当前这次质押的“质押”一条 | 本份在本项目每笔已发出的链上交易一条，格式按[详情中的交易哈希只在操作记录展示](#operation-records)；操作为质押、解押、撤回或提取；地址为签名并发送这笔交易的原持有地址；本企业资产方另可见每条的实际 gas 及币种，未知标“待核实”。历次质押都保留，新一次不覆盖旧记录 |

- 代币详情不另设上链事实或逐币历史：同一笔交易的时间、gas 与交易哈希都在操作记录中，只出现一次。提交批次编号与[单笔申请标识（PA-11）](#pa-11)仍作为记录字段保留，用于追溯，不在面客端另列。
- 授权按“持有地址＋代币发行合约＋质押合约”及本次数量给出，不属于某一份代币，不进入代币详情的操作记录；授权交易哈希在本次授权办理的结果中给出，集中查看在[我的控制台的链上授权](../09-我的控制台/01-我的控制台-PRD.md#revoke)。

| 失败说明 | 文本与分类 | 执行失败时必有，面向业务人员可读：为什么没成、是否已产生费用、下一步能做什么；不透出运营端诊断信息 |
| 底层资产失效 | 是 / 否，取只读代币域的代币状态 | 为“是”时不计入有效质押价值，解押规则见[解除质押](#withdraw) |

| 待提取 | 是 / 否 | 已释放且链上仍在合约内时为“是”；该代币不属于任何项目、不能再质押 |

### 10.1 发布签名与冻结（D-LS-74）

**签名链路**（用户 2026-10-21 裁定）：

1. 资产方填写金额，点击签名，平台核实资格与额度。
2. 资产方用当前登录的钱包地址在钱包中签名确认本次发布或改额。这一签名本身不上链、不产生 gas。
3. 平台核验签名：签名地址为当前登录地址，签名内容与本次办理一致，资格与额度在此刻仍满足。
4. 核验通过后，由平台执行钱包签名并发送冻结交易，在本项目所配置的质押合约中冻结本轮质押价值；gas 由平台执行钱包承担，资产方不付费。
5. 冻结上链成功即发布或改额成功。

- **签名内容**：资产方在钱包中签名的内容须包含项目编号、本次操作（发布或修改金额）、本轮金额（改额时为新金额，并带原融资申请编号）、本轮将冻结的质押价值与融资收款地址，供资产方在钱包中核对；签名只对这一次办理有效，不能被重复使用。
- **签名后核验不通过**（如资格或额度已变化、签名地址与登录地址不一致）：不上链、不冻结、不预占，就地说明原因，保留输入；不发送消息。
- **冻结多少**：本轮冻结质押价值 = 本轮需求金额 ÷ 项目质押率，USD，按份额价值口径计算、不提前舍入。例如项目质押率 70%、需求 500,000.00 USDT，冻结 714,285.71 USD 的质押价值（按 1 USDT = 1 USD）。
- **冻结什么**：冻结按价值记在本项目名下，不指定具体份额，也不在代币上逐张标记；冻结后本项目的冻结质押价值合计不超过有效质押价值（与“金额不超过可融金额”是同一条件）（用户 2026-10-21 裁定，[Q-LS-25](#q-ls-25)）。
- **冻结的效果**：冻结中的价值不能从质押合约转出，解押与撤回因此受限，见[解除质押与提取（F-LS-06）](#f-ls-06)。冻结不改变代币的质押状态，不改变总质押额、有效质押价值或有效质押额。
- **唯一确认**：点击签名即唤起钱包，钱包内的签名就是最终确认；点击前后都不再出现确认弹窗或勾选确认。
- **办理中展示的信息**（用户 2026-10-22 要求）：填写与核对的只有需求金额与融资收款地址两项，填好后签名执行链上操作。不展示本轮将冻结的质押价值，也不常驻展示可融金额；只有填写的金额超出可融金额时，才提示当场可融金额与差额，此时不能签名。改额时金额带出原值，融资收款地址只读。
- **所交互的合约与签名用途**（用户 2026-10-26 要求）：签名主动作旁另给出执行冻结的质押合约（名称、网络与完整地址），以及一两句签名用途：用登录地址确认本轮金额（改额为新金额）与融资收款地址，平台执行钱包随即在上述质押合约中冻结本轮对应的质押价值，冻结上链成功即发布（或改额）成功；这一签名本身不上链、不产生费用。展示规则见[所交互的合约、签名用途与交易哈希](#chain-display)。

**冻结上链结果。**

| 结果 | 需求与额度 | 资产方看到什么 |
| --- | --- | --- |
| 未签名、取消或钱包不可用 | 未发生链上操作；没有预占，没有生成需求，改额时保持原值 | 说明本次未发布或未修改 |
| 处理中（平台执行钱包已发送冻结交易） | 本轮金额（改额时为新金额）先按在途预占，可融金额相应减少；发布尚未成立：不出现在借贷广场、不能报价，项目状态不变；不能再次发布、改额或撤下 | 已等待时长；已取得时给出冻结交易哈希 |
| 明确成功 | 发布：生成融资申请编号，状态待报价，项目转为募集中，借贷广场可见。改额：新金额与新冻结同时生效 | 完成时间与冻结交易哈希；本次操作计入融资申请详情的[操作记录](#application-detail) |
| 明确失败 | 发布：不生成需求、不冻结，预占释放。改额：本轮保持原金额与原冻结 | 可读原因、下一步，交易已发出的给出冻结交易哈希；发送[融资需求链上操作失败通知（N-LS-11）](./03-融资需求与代币质押-消息通知.md#n-ls-11) |
| 长期未知或冲突 | 保持预占，不能重复发起 | 按[异常只提示联系客服（D-LS-63）](#d-ls-63) |

- 重复点击、刷新或重复提交同一次发布或改额，链上只产生一笔冻结。
- 冻结处理中遇到质押水位不安全时，等冻结结果回写后，再按[需求因质押水位不足失效（F-LS-19）](#f-ls-19)判断。

### 10.2 冻结的解除

用户 2026-10-21 裁定按以下口径执行（[Q-LS-25](#q-ls-25)）：

- 资产方撤下本轮：须资产方用质押时签名的地址签名后执行链上解冻，见[撤下签名与解冻（D-LS-77）](#d-ls-77)。
- 本轮因质押水位不足失效、项目到期或项目关闭而终结：平台随即解除本轮冻结。
- 本轮成交（链上放款成功）后，冻结随该笔业务保留，直到该笔业务结清时解除。
- 除撤下外，解除由平台执行钱包按业务事实在链上执行，资产方不需要签名、不承担 gas。
- 解除处理中或结果待核实期间，这部分价值仍视为冻结，不能转出；解除结果不发送站内信。
- 项目关闭或结清时，未解除的冻结随之全部解除；解除完成前，池内代币暂不能提取，并说明原因。
- 按以上口径，没有处理中的冻结或解除时，项目的冻结质押价值合计等于（项目融资余额＋项目在途金额）÷ 项目质押率；有效抵押物的[可撤回上限（FP-16）](#fp-16)因此等于有效质押价值减去冻结质押价值，平台额度规则与合约冻结给出同一结论。

<a id="D-LS-77"></a><a id="q-ls-30"></a><a id="d-ls-77"></a>
**撤下签名与解冻（D-LS-77）。** 撤下需要执行链上操作，释放本轮在质押合约内冻结的质押价值（用户 2026-10-22 要求）。撤下用质押时签名的地址签名（用户 2026-10-22 裁定，[Q-LS-30](#q-ls-30)）：

1. 资产方点击撤下，平台核实本轮仍可撤下（尚未收到报价、没有报价处理中、仍有效）。
2. 资产方用质押时签名的地址在钱包中签名确认撤下，即本项目合约内份额的原持有地址；本项目有多个原持有地址的，用其中任一个即可。钱包当前地址不是这些地址时，不能签名，并说明需要切换到质押时使用的地址。这一签名只用于本次撤下，与登录无关，不切换、不结束当前登录。签名内容含项目编号、融资申请编号与本次操作；签名本身不上链、不产生 gas，钱包内的签名就是最终确认，不另设确认弹窗。签名主动作旁给出执行解冻的质押合约（名称、网络与完整地址），以及一两句签名用途：用质押时签名的地址确认撤下本轮，平台执行钱包随即在上述质押合约中解除本轮冻结，解冻上链成功即撤下成功；这一签名本身不上链、不产生费用，与登录无关（用户 2026-10-26 要求，展示规则见[所交互的合约、签名用途与交易哈希](#chain-display)）。
3. 平台核验签名地址是本项目的原持有地址之一、签名内容与本次一致、本轮状态仍可撤下，通过后由平台执行钱包签名执行解冻交易；gas 由平台执行钱包承担。
4. 解冻上链成功即撤下成功。

| 结果 | 本轮与额度 | 资产方看到什么 |
| --- | --- | --- |
| 未签名、取消或钱包不可用 | 未发生链上操作，本轮不变 | 说明本次未撤下 |
| 签名后核验不通过（如签名地址不是本项目的原持有地址、本轮已收到报价或已终结） | 不上链，本轮不变 | 就地说明原因；不发送消息 |
| 处理中 | 本轮暂停报价，借贷广场显示为不可报价，不能修改金额或再次撤下；在途与冻结保持 | 已等待时长；已取得时给出解冻交易哈希 |
| 明确成功 | 本轮终结，原因“资产方撤下”；释放在途，冻结解除；项目状态按剩余事实判定 | 完成时间与解冻交易哈希；本次操作计入融资申请详情的操作记录 |
| 明确失败 | 本轮恢复为待报价，在途与冻结保持 | 可读原因与下一步，交易已发出的给出解冻交易哈希；发送[融资需求链上操作失败通知（N-LS-11）](./03-融资需求与代币质押-消息通知.md#n-ls-11) |
| 长期未知或冲突 | 保持处理中，不能重复发起 | 按[异常只提示联系客服（D-LS-63）](#d-ls-63) |

### 10.3 发布入口与再次发布条件（D-LS-69）

一轮需求成交（资产方签名接受、链上放款成功）即本环节结束；此后只要项目仍满足发布条件，就可以直接发布新一轮，不需要等该笔还款结清。发布入口按当前事实呈现：

| 当前情况 | 发布入口 |
| --- | --- |
| 空池（有效质押价值为 0） | 可见但不能提交，说明“本项目暂无有效质押，请先完成代币质押后再发布” |
| 本轮发布或改额的冻结、撤下的解冻仍在处理中或结果待核实 | 可见但不能提交，说明本轮链上结果确定后才能办理 |
| 本轮报价处理中（资金方授权已发出、尚未上链确认） | 不能发布新一轮；本轮不能修改金额或撤下，等报价结果确定 |
| 本轮待报价或已报价待确认 | 不能发布新一轮；本轮可按规则修改或撤下 |
| 本轮报价已签名接受、链上放款处理中或结果待核实 | 可见但不能提交，说明本轮放款结果确定后才能发布新一轮 |
| 本轮已放款（链上放款成功），或本轮已撤下、已失效 | 可以发布新一轮，办理时给出当场可融金额；成功生成新的融资申请编号，上一轮及其放款、还款记录不变 |
| 可融金额为 0 | 可见但不能提交，说明可融金额为 0 |
| 质押不足 | 可见但不能提交，说明当前质押不足 |
| 项目已到期 | 可见但不能提交，说明项目已到期 |
| 项目已关闭或已结清 | 不提供发布入口 |

<a id="F-LS-09"></a><a id="f-ls-09"></a><a id="INV-FIN-01"></a><a id="inv-fin-01"></a>
### 11.1 占用规则（F-LS-09）

<a id="water-level"></a>
- **质押水位（INV-FIN-01）**：有效质押额 ≥ 项目融资余额＋项目在途金额时为水位安全；有效质押额低于项目融资余额＋项目在途金额时为水位不安全。两者相等时仍为安全。本册凡说“水位安全”“水位不安全”，都指这一条。
- 任何新增占用后都须保持水位安全。
- 水位不安全时，同时发生三件事，判据相同：
  - 不能新增占用；
  - 融资需求按[需求因质押水位不足失效（F-LS-19）](#f-ls-19)失效；
  - 合约内的代币不能转出，见[解除质押与提取（F-LS-06）](#f-ls-06)。
- 需求失效会释放其在途金额；失效之后水位仍不安全，只可能是项目融资余额本身已超出有效质押额（质押不足），直到追加质押成功、还款结清或其他事实变化使水位恢复。
- 已发布需求的报价只校验已有的有效质押额与授信条件，不因可融金额为 0 单独禁止报价。
- 链上放款成功（接受成功）时，本笔金额同时从在途移出、计入项目融资余额，中间没有两边都不计的空档；签名、放款处理中与放款失败时都不转移。
- 占用与冻结都不从有效质押价值里扣减。
- 勾选或改额时可以先预览；提交以当场的权威重算为准，不用旧的预览数字放行。
- 以下事件都会触发重算：项目审核通过、质押上链结果、发布与改额的冻结结果、撤下、冻结解除、质押变化、报价、接受的链上放款结果与失效、还款结清、项目终态与到期、代币状态及对账差异变化。

<a id="project-state"></a>
## 12. 项目状态与后续业务

项目状态（FP-04）：待审核、已退回、可用、募集中、已锁定、融资中、已关闭、已结清。状态转换见[融资项目状态机（ST-LS-01）](./02-融资需求与代币质押-流程图与状态机.md#st-ls-01)。

- 创建提交后为待审核；审核通过（合约配置成功）转为可用；审核退回为已退回，修改重提回到待审核。
- 待审核与已退回不出现在广场，不能质押或发布，可以由资产方主动关闭；合约配置进行中除外，见[合约配置进行中暂不可关闭（D-LS-71）](#d-ls-71)。
- <a id="D-LS-72"></a><a id="d-ls-72"></a>**待审核或已退回时到期自动关闭（D-LS-72）**，用户 2026-10-16 裁定：
  - 待审核或已退回的项目到达有效期至时自动关闭，关闭原因为“有效期到期”；此后不能修改重提，也不再进入审核。
  - 运营提交通过时项目已到期的，通过被拒，不配置合约。
  - 合约配置进行中跨过有效期至的，等配置结果回写后处理：配置成功即审核通过，项目转为可用后按下方“到期后自动终结”立即终结为已关闭（有效期到期）；配置失败则随即自动关闭。
  - 运营端的对应规则见[运营端项目合约管理](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#expiry)。
- 发布成功（冻结上链成功）后为募集中，发布处理中项目状态不变；资金方报价后为已锁定；拒绝报价后，需求仍有效且项目未到期时回到募集中；资产方签名接受、链上放款成功（接受成功）后为融资中，放款处理中与放款失败时仍为已锁定。
- 当前轮终结（撤下、自动失效或到期）后：仍有未结清业务时为融资中，否则回到可用。已锁定时需求因质押水位或到期终结，该轮报价同时失效，同样按此判定。
<a id="unfinished-business"></a>
- **未处理完成的业务**：以下任一存在时，项目不能关闭，也不会转为已结清：
  - 已收到报价、待资产方确认的融资需求；
  - 资产方已签名接受、链上放款仍在处理中或结果待核实的报价；
  - 尚未结清的融资业务，包括逾期的；
  - 本轮报价处理中（资金方授权已发出、尚未上链确认）；
  - 本项目仍在处理中的链上操作（质押上链、解押、撤回、发布或改额的冻结、撤下的解冻，结果尚未回写或待核实）。
- 尚未收到报价的融资需求不算阻断：关闭项目时一并终结，终结原因为项目关闭。
- 可用、募集中的项目，没有未处理完成的业务时可以主动关闭。
- **未到期时全部结清**：融资中的项目全部业务结清、且项目未到期时，回到可用；可以再次发布新一轮，也可以主动关闭。
- **到期后自动终结**：项目到期且没有未处理完成的业务时，自动终结——有过成交业务的转为已结清，从未成交的转为已关闭（关闭原因“有效期到期”）。到期时仍有未处理完成的业务的，最后一项处理完成时按同一规则自动终结。到期后不再提供主动关闭。
- 到期是并行标记（FP-05）：到期后不能发布新需求、不接受新报价，存量业务继续履约，按正常中性状态展示。到期时尚未成交的当前轮随即终结，终结原因为项目到期，该轮在途报价（含待资产方确认的）同时失效，发送[融资需求终结通知（N-LS-05）](./03-融资需求与代币质押-消息通知.md#n-ls-05)。
- 只有全部业务处理完成、项目实际关闭或结清时（含到期自动终结），才整池业务释放：池内全部质押代币变为已释放待提取，资产方才可提取。项目到期但仍有未处理完成的业务时，不整池释放。
- 终态项目仍可提取未取回的代币，不能追加质押或再次关闭。

<a id="D-LS-64"></a><a id="d-ls-64"></a>**单笔融资业务没有中途终止出口。**

- 链上放款成功后，本笔即进入还款，只能按还款计划还款直至结清；平台没有提前终止、撤销或退回放款的动作，也不新增终止或审批入口。
- 各笔债务与履约互不牵连：某笔逾期不影响其他笔履约，也不因此回到募集中或释放整池质押。
- 未到期、未终态的项目按剩余的全部事实重新判断资格。

## 13. 查看三类记录

适用角色：按[角色与可见范围](#roles)；私有字段始终按本笔当事方授权。

报价与放款合为一步后（资产方接受即链上放款，见[授信报价与接受拒绝](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#f-ls-29)），项目详情的记录按以下边界划分（用户 2026-10-22 裁定，[Q-LS-29](#q-ls-29)）：

- 不再单设“融资放款信息”清单。一笔业务的报价、接受与链上放款都属于同一轮融资申请，在融资申请信息及其详情中查看；放款成功后的履约（还款计划、期次、逾期、结清）只在还款信息中查看。
- 每类信息只在一个位置展示明细，其他位置只放识别用的编号与状态：

| 信息 | 展示明细的位置 | 其他位置只显示 |
| --- | --- | --- |
| 质押份额、上链事实与去向 | 质押代币清单及代币详情 | 不在其他清单出现 |
| 需求、冻结、报价、接受与链上放款记录 | 融资申请信息及融资申请详情 | 还款信息只显示融资申请编号、融资业务编号与放款编号，用于识别与检索 |
| 还款计划、期次、逾期与结清 | 还款信息及还款详情 | 融资申请信息只显示“已放款”，不拼入还款、逾期或结清状态 |
| 链上交易哈希 | 所属对象详情的操作记录：一轮申请的在融资申请详情，一份质押份额的在代币详情 | 清单、当前报价、报价历史与链上放款记录都不重复 |
| 本项目质押合约 | 项目详情的质押合约 | 代币详情、融资申请详情与操作记录都不重复 |

- 融资申请清单的申请状态列只展示本轮状态及必要的状态说明；放款编号与放款成功时间在独立的“放款信息”列展示，不放在申请状态列（用户 2026-10-23 要求）。只有链上放款成功后才展示实际编号与成功时间，未成功时留空，不用处理时间或预计时间替代；两项仍遵守原有业务当事方权限，分列不扩大可见范围。
- 融资申请、还款两类清单每页固定 5 条，不提供条数切换，各自保留页码。质押代币清单见[质押代币清单与代币详情（D-LS-67）](#d-ls-67)。
- 全部使用真实编号：项目编号标识项目；融资申请编号为“项目编号＋两位轮次序号”；融资业务、放款、还款期次和还款提交各有自己的稳定编号，不互相替代。
- 代币符号取上游配置，不自造；未确定时取合约名称。

| 清单 | 一条记录与排序 | 展示信息 |
| --- | --- | --- |
| 融资申请信息 | 一轮申请，按发布时间倒序 | 融资申请编号、本轮金额与币种（USDT）、申请状态、当前有效或已接受报价的机构与年化利率（按报价信息的查看权限）、本轮发布时间；已放款的另给出放款编号与放款成功时间。改额不新增记录；没有有效报价时明确空态。发布处理中与发布未成功的记录只对本企业资产方显示，没有融资申请编号、不算一轮，以金额、发起时间与结果识别 |

| 操作 | 地址 | 谁能看到 |
| --- | --- | --- |
| 发布冻结 | 签名确认的登录地址 | 本企业资产方 |
| 修改金额（冻结调整） | 签名确认的登录地址 | 本企业资产方 |

- 查看报价时可以看到预计还款计划，明确标注“预计·未生效”。报价、接受与授信的完整规则见[授信报价与接受拒绝](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md)。
- 协议文件现只有授信协议，按文件给出文件名、所属业务与文件状态，文件名可直接下载，只对该次授信的双方展示；无文件、无权限、读取失败分别反馈。字段与规则沿[授信报价与接受拒绝的融资申请详情](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#f-ls-32)，本模块不另定。

<a id="withdraw"></a><a id="F-LS-06"></a><a id="f-ls-06"></a>
## 14. 解除质押与提取（F-LS-06）

适用角色与前提：本企业资产方，从项目详情的“质押—解除质押”进入；项目处于任何已通过审核的状态，包括已关闭和已结清。

- 解押与提取都不经运营审核，由资产方用原持有地址向本项目所配置的质押合约签名发起；gas 由资产方承担，失败不退。只能转出归属本项目的份额。
- 释放按批办理：解押与提取不需要授权，代币在质押合约内，由合约直接转回。同一原持有地址的多份（含同一代币发行合约下资产槽位不同的多笔，以及来自不同代币发行合约的份额）可以一次签名、一笔交易一起转出，单次份数上限同[授权与签名（D-LS-68）](#d-ls-68)。
- 一笔转出交易内的全部份额同成同败；不同交易互不影响。
- 释放交易提交给质押合约的信息见[提交给质押合约的信息（D-LS-75）](#d-ls-75)；能否转出由质押合约与平台业务双重判断，见[合约与平台双重判断（D-LS-76）](#d-ls-76)。
- 合约按记录把这份数量整体转回质押前的原持有地址；不能只转出一部分，平台不代签、不代付，也不能指定其他地址。
- 每张代币标明所属类别：有效抵押物、已失效代币、已释放待提取，互不混淆。

**到期后的转出。** 项目到期但仍有未处理完成的业务时，项目不终结、不整池释放；合约内的代币仍按下方的质押水位与可撤回上限规则转出。“终结”只指项目关闭或结清。

**转出与质押水位。** [质押水位（INV-FIN-01）](#water-level)不安全时，合约内的代币一律不能转出，包括有效抵押物和已失效代币；判据与需求失效相同。水位恢复安全后按下表各类条件办理。

**转出与冻结。** 有效抵押物转出后，本项目剩余的有效质押价值不能低于[冻结质押价值](#f-ls-07)；冻结或解除仍在处理中时，按处理中的冻结仍然有效判断。按用户裁定的冻结口径（[Q-LS-25](#q-ls-25)），这与下表“不超过可撤回上限”是同一条件，资产方看到的限制与出路不变。已失效代币不计入有效质押价值，水位安全时转出不受冻结影响。以上规则由平台与质押合约各自判断一次，见[合约与平台双重判断（D-LS-76）](#d-ls-76)。

| 类别 | 能否转出 | 转出成立后 |
| --- | --- | --- |
| 有效抵押物 | 已质押且有效。水位不安全时不能转出；水位安全时须满足“剩余有效质押价值 × 项目质押率 ≥ 项目融资余额＋项目在途金额”，即拟撤回价值不超过可撤回上限 | 发起即预扣该张有效价值；成功按真实转出移出项目，失败保持在池并撤销预扣 |
| 已失效代币 | 已质押、但发行平台已判失效，不计入有效质押。水位不安全时不能转出；水位安全时（含有效质押额恰好等于项目融资余额＋项目在途金额）不受可撤回上限约束 | 移出项目；有效质押价值、有效质押额、可融金额不变 |
| <a id="F-LS-17"></a><a id="f-ls-17"></a>已释放待提取（F-LS-17） | 只有全部[未处理完成的业务](#unfinished-business)处理完成、项目实际关闭或结清时，池内业务关系即时解除（零 gas、无链上动作）；之后资产方自助提取，可批量，没有时间限制 | 转回原持有地址；失败仍为已释放待提取，不恢复项目占用 |

- 所有类别仍受真实占用、处理中和对账差异保护：上链或解押处理中、带对账差异的代币不能转出。
- 已释放待提取的代币不属于任何项目、不计任何额度，也不能再质押。
- 有待提取的代币时，解除质押入口提示张数与金额，并说明 gas 自担、可批量、代币不会自动回到钱包。
- 单笔业务结清降低项目融资余额、解除该笔的冻结、提高可撤回上限，但不自动释放或转回“对应”的代币，转出仍由资产方办理。
- 有效抵押物的撤回发起后，并发报价按预扣后的项目价值判断。
- 记录保留转出交易哈希、时间、gas 和原因；处理中、明确失败（交易已发出）与结果待核实的结果中给出已取得的转出交易哈希；未知或冲突按[异常只提示联系客服（D-LS-63）](#d-ls-63)处理，不自动重试。
- 流程见[解除质押与提取图（FL-LS-03）](./02-融资需求与代币质押-流程图与状态机.md#fl-ls-03)。

### 14.1 合约与平台双重判断（D-LS-76）

质押合约内有本项目的池水位管控，包括可撤回上限；释放能否成立由质押合约与平台业务各自判断一次，两边都允许才转出（用户 2026-10-21 裁定）。

| 判断方 | 判断什么 | 何时判断 | 不允许时 |
| --- | --- | --- | --- |
| 平台业务 | 本节以上全部规则：份额归属本项目、[质押水位（INV-FIN-01）](#water-level)、可撤回上限、冻结、失效与对账差异、处理中占用、项目是否终态 | 勾选时与点击签名时 | 不可选或不唤起钱包，说明原因；未发生链上操作、未产生 gas |
| 质押合约 | 份额归属本项目、签名地址是该份的原持有地址；合约口径的池水位：合约口径的有效质押价值不低于冻结质押价值，不满足时池内代币一律不能转出；合约口径的可撤回上限：有效抵押物转出后，剩余的合约口径有效质押价值不低于冻结质押价值；带对账差异标记的不能转出 | 交易上链执行时 | 交易执行失败，全部所选份额仍在合约内，按[链上操作失败通知（N-LS-04）](./03-融资需求与代币质押-消息通知.md#n-ls-04)处理；已产生的 gas 不退 |

- **合约口径的有效质押价值**：本项目在合约内的份额中，未标失效、未标对账差异的份额价值合计；口径与[有效质押价值（FP-11）](#fp-11)一致，依赖平台按[提交给质押合约的信息（D-LS-75）](#d-ls-75)同步的标记与冻结。
- 平台与合约口径一致时，两边结论相同。平台已知、合约尚未收到的事实（例如刚判失效、冻结或解除仍在处理中）以更严的一方为准，这时可能出现平台不允许、合约允许的情况，平台照常拦截。
- 绕过平台页面、直接向质押合约发送的释放交易，仍须通过合约的判断；合约不允许的，交易执行失败。
- 平台允许、合约不允许的，交易在链上失败，资产方看到可读原因与已产生的 gas，代币与额度不变。
- 已释放待提取的代币（项目已关闭或已结清、冻结已全部解除）只需判断归属与原持有地址，不受池水位约束。

<a id="D-LS-70"></a><a id="d-ls-70"></a>
### 14.2 解押与提取签名办理（D-LS-70）

**两步办理**（用户 2026-10-22 要求）：第一步选择代币；第二步钱包签名执行链上操作，不需要授权。签名主动作是本次办理唯一的确认，点击即唤起钱包签名，点击前后不再出现确认弹窗、费用确认或勾选确认。进入第二步不提交任何内容，返回时保留已选份额。

- **同一地址批量**：一次签名只能包含同一个原持有地址的份额，与质押一致；因为每个原持有地址都要分别执行一次链上操作。清单逐份标明原持有地址；勾选了某个原持有地址的份额后，其他地址的份额不能同时勾选，并说明原因；要处理其他地址的份额，另行发起一次。
- 主动作名称：项目未进入终态时为“签名并解除质押”（Sign and release）；项目已关闭或已结清时为“签名并提取”（Sign and collect）。未勾选时不可用；点击即视为本企业确认承担本次 gas。按钮名称随项目状态；结果与失败通知按项目状态区分：已关闭或已结清项目中的转出按提取，其余按解押。
- 可选范围：质押合约内归属本项目的有效抵押物与已失效代币，以及已释放待提取代币；按[质押水位（INV-FIN-01）](#water-level)不能转出的代币不可选，并说明原因（说明一次即可，不必逐行重复）。可同次多选、跨类别多选。
- 第一步必须看到：已选份数与份额价值合计，随勾选即时更新。
- 第二步必须看到：预估 gas 合计及费用币种（清单中不逐份列出）；所交互的质押合约（名称、网络与完整地址）；一两句签名用途与后果：用原持有地址签名发起交易，从上述质押合约把所选代币转回质押前的原持有地址；这是链上交易，gas 自担、失败不退，与登录无关（用户 2026-10-26 要求，展示规则见[所交互的合约、签名用途与交易哈希](#chain-display)）。
- 以下几项只在适用时出现：
  - 项目未进入终态且所选含有效抵押物：拟撤回价值与当前可撤回上限的对照；
  - 24 小时内本企业链上提交超过 5 次：提示频繁操作会产生较多 gas，不阻断。
- 办理中不单列本次签名的原持有地址与持有数量合计。
- 超限：所选有效抵押物价值超过可撤回上限时，给出拟撤回价值、当前上限、差额三个数，以及“减少勾选”“等待还款释放余额”两条出路；主动作不可用。减少有效抵押物的勾选即可继续。
- 资格变化：点击时复核所选的每一份，规则同[点击时复核所选份额（D-LS-51）](#d-ls-51)；有变化则不唤起签名，指出变化的代币并更新选择与预估 gas，用户再次点击才发起。
- 入口可用性：只要存在任一可以转出的代币，解除质押入口即可进入；有效抵押物的额度不足，不能挡住已失效代币或待提取代币的办理。

<a id="coverage"></a>
## 15. 质押情况变化与需求失效

发行平台判代币失效或后台标记对账差异后，先从有效质押价值中排除并权威重算，再判断现有需求和债务的质押情况。代币失效不会自动转出，资产方可按[解除质押](#withdraw)清出。

| 质押情况 | 判据 | 用户结果 |
| --- | --- | --- |
| 质押充足 | 有效质押额足以覆盖项目融资余额与在途，且可融金额大于 0 | 按资格正常办理 |
| 质押持平 | 可融金额为 0，且有效质押额不低于项目融资余额 | 不能新增发布；有效抵押物的可撤回上限为 0；已发布需求的报价按已有有效质押额与授信条件判断，不一概禁止。其中有效质押额低于“项目融资余额＋项目在途金额”的，水位不安全，按[质押水位（INV-FIN-01）](#water-level)处理 |
| 质押不足 | 有效质押额小于项目融资余额，即已有债务本身不足 | 禁止新增占用；水位必然不安全，合约内的代币不能转出；触发质押不足提醒 |

- 需求失效与债务提醒是两件事：需求失效与转出拦截按[质押水位（INV-FIN-01）](#water-level)，比较“项目融资余额＋项目在途金额”；质押不足提醒只比较“项目融资余额”。需求失效后债务可能仍被覆盖；没有在途需求时债务也可能不足。

<a id="invalidation"></a><a id="F-LS-19"></a><a id="f-ls-19"></a>
### 15.1 需求因质押水位不足失效（F-LS-19）

- 重算后[质押水位（INV-FIN-01）](#water-level)不安全时，立即按发布时间倒序使最少必要的需求失效；每失效一笔释放其在途并重算，水位恢复安全即停止。
- 等价判断：按发布时间正序保留较早的需求，对每笔比较“有效质押额 − 项目融资余额 − 更早已保留的金额”是否足够。本期一个项目只有一轮在途需求，同样按此口径。
- 资产方已签名接受、链上放款处理中的需求，等放款结果回写后再判断：放款先成功的转为项目融资余额，不再失效；放款未成功的按本节失效，报价连带失效（与[授信报价与接受拒绝](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#f-ls-29)一致）。
- 没有需求可失效而水位仍不安全时就停止（例如项目融资余额本身已超出有效质押额）；此时合约内的代币仍不能转出，债务不足时保留质押不足提醒。
<a id="D-FIN-75"></a><a id="d-fin-75"></a>
- 该轮需求与其在途报价在同一次事实变更内失效，用户不会看到需求已失效而报价仍可接受。
- 记录原编号与终结原因“自动失效·质押水位不足”；不新增项目状态、缓冲期或补质押倒计时。原轮不能恢复，满足资格即可立即发布新一轮。
- 失效的这一轮释放在途占用，其冻结按[冻结的解除](#freeze-release)解除。
- 通知：本模块发送[融资需求终结通知（N-LS-05）](./03-融资需求与代币质押-消息通知.md#n-ls-05)；授信报价模块不为同一原因再发报价失效信。流程见[需求因质押水位不足失效图（FL-LS-04）](./02-融资需求与代币质押-流程图与状态机.md#fl-ls-04)。

<a id="F-LS-16"></a><a id="f-ls-16"></a>
### 15.2 质押不足提醒（F-LS-16）

- 质押不足时显示质押缺口（项目融资余额 − 有效质押额）和需追加资产价值（质押缺口 ÷ 项目质押率）。
- 资产方在项目中能看到提示和追加入口，在控制台融资项目清单中该项目标为[待处理“追加质押”](../09-我的控制台/01-我的控制台-PRD.md#todo-types)，并被明确告知“追加质押上链成功即计入有效质押额，上链处理中不计入”。
- 债权机构可见缺口和触发时间；平台运营有既有待办与监控。借贷广场列表对所有身份展示中性的质押情况；项目详情中的质押情况按[项目详情按身份的可见范围（F-LS-82）](#f-ls-82)。
- 条件反转时自动解除，无需人工确认。触发与解除都保留时间、当时的有效质押价值、有效质押额、项目融资余额、诱因和解除时间。
- 通知：触发与解除分别发送[质押不足通知（N-LS-06）](./03-融资需求与代币质押-消息通知.md#n-ls-06)与[质押不足解除通知（N-LS-07）](./03-融资需求与代币质押-消息通知.md#n-ls-07)。流程见[质押不足触发与解除图（FL-LS-06）](./02-融资需求与代币质押-流程图与状态机.md#fl-ls-06)。

<a id="navigation"></a><a id="F-LS-13"></a><a id="f-ls-13"></a>
## 16. 从控制台、资产广场与消息进入（F-LS-13）

- 控制台、资产广场与消息都能定位到项目，以及原来的申请、业务或期次；终态项目仍可寻址。
- 控制台的融资项目记录直接打开本项目详情；控制台的其他摘要详情与[待处理记录上的动作](../09-我的控制台/01-我的控制台-PRD.md#todo-target)经唯一项目导航定位原对象只读阅读；需要质押或其他办理时，从项目既有业务入口独立发起，控制台详情和来源只读详情不转办。具体边界沿[控制台导航与返回](../09-我的控制台/01-我的控制台-PRD.md#f-mc-09)，原对象定位按[原对象阅读定位建议（Q-MC-60）](../09-我的控制台/01-我的控制台-PRD.md#q-mc-60)建议执行、待确认，未具备时显式降级同项目，不静默换新对象。
- 一次只进入一个明确对象的查看或办理，不自动勾选或执行。
- 每次进入都重新核验权限与阶段：对象已完成或已失效时显示它当前的事实与原因，不跳到新一轮，也不把用户带到空白结果或静默送回起点。
- 待审核与已退回的项目仍不暴露存在性，非本企业不能进入私有办理。
- 从控制台进入时提供返回原位置的入口，其他来源不提供。资产广场可以单向进入项目，本模块不新设反向入口。

<a id="accepted-limits"></a>
## 17. 按用户决定保留的业务限制

以下是用户裁定后的既定结果及其业务后果；测试按此预期，不判为缺陷。

| 限制 | 业务后果 |
| --- | --- |
| 平台不采集、不校验收款人名称 | 平台不能自动校验“收款账户属于本企业”；账户核对只依据账户备注名、账号等信息，受益人名称由业务双方在平台外补充 |
| 待审核或已退回的项目到期自动关闭 | 项目审核没有时限，运营在有效期至之前没有作出结论的，项目会被自动关闭（有效期到期），资产方只能另建项目，见[待审核或已退回时到期自动关闭（D-LS-72）](#d-ls-72) |
| 合约配置进行中暂不可关闭项目 | 配置结果长期待核实时，资产方只能看到项目待审核、无法自行关闭，需等运营端回写结果，见[合约配置进行中暂不可关闭（D-LS-71）](#d-ls-71) |
| 质押合约可以由多个项目使用 | 一份质押合约出现问题时，配置在它上面的全部项目都受影响；本期没有为已配置项目更换或迁移合约的能力。某组合下没有预先部署的质押合约时，该组合的项目都不能通过审核，只能等开发人员部署。放款合约与还款合约每个项目各一份，一个项目的部署结果不影响其他项目（见[审核对象（D-CM-03）](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#d-cm-03)） |
| 报价一经提交，资金方无法撤回 | 退出路径只有资产方拒绝；“撤下需先拒绝报价”是本轮需求退出的唯一方式 |
| 水位不安全时合约内的代币全部不能转出 | 有效质押额低于“项目融资余额＋项目在途金额”期间，资产方不能取回合约内的任何代币，包括已失效、不计入有效质押的代币；这一状态会持续到追加质押成功、还款结清或水位因其他事实恢复 |

<a id="dependencies"></a>
## 18. 待确认事项与依赖

<a id="open-items"></a>
### 18.1 待确认事项

本模块当前没有待确认事项。

### 18.2 依赖

- **代币准入审核**（运营端）：只有准入通过的代币进入本模块；提供准入结果，以及准入后代币状态与持有地址的最新事实。[平台代币标识的对外使用（Q-TA-13）](../../运营端/06-代币准入审核/01-代币准入审核-PRD.md#q-ta-13)确认前，本模块仍以代币编号定位代币。
- **融资参数配置**（运营端）：按组合提供已配置的代币类型、当前最高质押率与最长项目期限；读取失败时创建不可办理。
- **项目合约管理**（运营端）：项目审核与合约配置的入口、权限与操作记录由该模块定义，结论只有通过与退回；为项目选用其组合下预先部署的一份质押合约，并由平台签名地址为本项目部署放款合约与还款合约，运营人员不签名（用户 2026-10-21 裁定不签名，2026-10-26 要求合约来源）。项目与合约的对应关系、合约配置的办理与结果以该模块为准，见[审核对象（D-CM-03）](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#d-cm-03)、[通过并部署合约（F-CM-09～F-CM-11）](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#m3)、[质押合约台账（F-CM-16～F-CM-17）](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#m6)。本册只定义面客端可见的结果。
- **质押合约的能力**：同一份质押合约内各项目的份额、额度与冻结分别归属；接受按“持有地址＋代币发行合约＋质押合约”给出、限定本次数量的授权（链上授权记录在各代币发行合约上），只按授权数量调取，一笔交易批量转入或转出多份；按项目冻结与解除；按本项目做池水位管控与可撤回上限判断，接收平台同步的失效与对账差异标记；逐笔回写结果、实际 gas、时间与交易哈希。单笔交易可容纳的份数上限，以及按数量授权在代币标准上的实现方式（如须逐个代币标识授权数量时，授权签名次数随之增加），由研发按链上能力确定，提测前须明确。质押合约由开发人员按组合预先部署并维护，实现与验证归研发、测试；做不到时不能假报闭环。
- **企业账户**：提供本企业已登记的数币账户（当前仅 Ethereum 网络）、信息完整性与选用规则，融资收款地址按其[业务办理中选用账户（F-EA-07）](../03-企业账户/01-企业账户-PRD.md#f-ea-07)选用；本模块不定义账户字段。
- **授信报价与接受拒绝**：报价、接受与链上放款（接受即放款）由该模块定义；接受时只读沿用融资收款地址（FP-40）。本模块据其链上放款结果派生需求对外状态，并在放款成功时把项目在途金额转为项目融资余额；放款处理中遇到需求终结时，按该模块等结果回写后再判断。
- **还款**：链上放款成功的业务交[链上还款](../08-借贷广场-链上还款/01-链上还款-PRD.md)；本模块按其业务结清事实降低项目融资余额、解除冻结，不重复定义还款签名或期次结清规则。
- **我的控制台**：汇总本模块提供的项目、代币与当前需求事实，沿[项目详情记录边界](#records)定位原对象；授权的集中查看与撤销由控制台定义。
- **资产方签名与链上结果**：钱包适配、授权与签名承载、gas 估算与链上结果回写由研发实现。
- **平台执行钱包**：执行发布与改额的冻结、冻结解除、失效与对账差异标记的同步，并承担这部分 gas；标记同步未完成期间按[合约与平台双重判断（D-LS-76）](#d-ls-76)以更严的一方为准；钱包的配置、保管与余额保障属实现侧，不可用时发布与改额停在核验后不能上链，须如实说明，不能假报发布成功。
- **只读代币域的链上标识**：每份质押份额须能取到其代币发行合约地址、链上代币 ID 与资产槽位；取不到时该份不能质押。
- **份额价值与标记的可信传递**：份额价值、失效与对账差异标记都由平台给出，资产方不能篡改；如何保证（如平台签发的数据随交易提交，或由平台执行钱包写入）由研发确定，提测前须明确。实现与验证归研发、测试。
- **质押合约提供**（运营端项目合约管理）：开发人员按组合预先部署的每一份质押合约都须具备上述池水位管控、可撤回上限判断与标记接收能力；质押合约的部署与维护见[项目合约管理的依赖](../../运营端/04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#dependencies)。
- **企业主体对应**：登录身份与只读代币域的企业归属须稳定比对，不能用名称或钱包猜测；缺失时不放行质押。
- **代币事实与对账差异**：失效、真实持有地址、数量价值由上游及时同步；对账差异由既有后台判定，本模块只消费保护结果。
- **消息中心**：本模块事件的分类登记、双语模板适配、原对象跳转与 60 秒可见由消息中心承接。
- **客服**：使用平台真实客服渠道；未提供时不编造号码、时限或自动处理能力。
