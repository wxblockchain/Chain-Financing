# 放款与放款确认 · 消息通知

2026-10-19｜需求评审稿

本册写本模块发送的站内信，规则以[功能与业务规则](./01-放款与放款确认-PRD.md)为准；验收见[验收](./04-放款与放款确认-验收.md#notice)。只有站内信，没有邮件、短信、浏览器推送或运营广播。

- 本模块自己发送 2 类：放款记录已提交、资产方已确认放款到账。
- 资产方接受报价、本笔进入待放款，由授信报价模块的[融资报价已接受（N-CR-04）](../06-借贷广场-授信报价与接受拒绝/03-授信报价与接受拒绝-消息通知.md#n-cr-04)告知资金方；本模块不为同一次接受补发消息。
- 我的控制台和消息中心展示同一事实，不各自补发。
- 本期一个企业只有一个账号；发给“资产方”的消息即发给该企业的唯一账号。

编号说明：事件编号（N-LN-*）与模板编号（T-LN-*）被其他模块引用，沿用原值；已删除的事件与模板不再占号，缺号不代表遗漏。

<a id="events"></a>
## 1. 本模块发送的消息

<a id="n-ln-01"></a>
### 放款记录已提交（N-LN-01）

- **所在功能与触发环节**：[放款记录与资金方收款账户（F-LS-49）](./01-放款与放款确认-PRD.md#f-ls-49)；资金方的放款记录正式提交成功、生成放款编号、本笔进入待放款确认时。
- **不触发**：资金方点击提交、提交进行中、提交失败或结果未知；质押水位不安全或额度结论不可用被拒绝；不给提交的资金方发“提交成功”回执。
- **收件人**：本笔融资业务所属企业的资产方账号。不发给资金方、运营、SPV 机构或其他企业。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、资金方名称、放款金额与币种、提交时间；请自行核实到账后再确认，未到账先与对方线下核实；平台未核验付款真实性，也不会代为或自动确认。不出现任何确认截止、剩余时长或倒计时。
- **打开后去哪**：本项目，定位到原融资申请与本笔融资业务，进入本笔到账确认办理；进入时重新判断权限与状态。
- **原业务已变化时**：本笔已确认到账的，只展示同一笔的放款结果，不再次打开确认；消息不会因时间经过而失效，资产方随时可以从现行办理入口确认。无权时按消息中心的无权限说明处理，不泄露私有记录。
- **模板**：[T-LN-01](#t-ln-01)。

<a id="n-ln-04"></a>
### 资产方已确认放款到账（N-LN-04）

- **所在功能与触发环节**：[确认到账与金额转移（F-LS-52）](./01-放款与放款确认-PRD.md#f-ls-52)；资产方确认到账正式成功、两个维度的金额转移成立、本笔进入还款中时。
- **不触发**：资产方点击确认、确认进行中、确认未成功或结果未知；不给确认的资产方发回执；还款计划之后生成成功或恢复时不重发。
- **收件人**：本笔资金方账号，即提交本笔放款记录的账号（提交人，LN-14）。不发给资产方、运营、SPV 机构或其他机构。
- **推送内容要点**：融资申请编号、融资业务编号、放款编号、确认时间；本笔已进入还款阶段；还款计划的真实进度——已定稿或仍在生成中，二者按发信时的实际情况取一，不把生成中说成已生成。
- **打开后去哪**：还款信息中的同一笔，以融资业务编号及其关联的融资申请编号、放款编号定位；计划生成中也可进入查看进度，不要求先有计划编号。
- **原业务已变化时**：计划已定稿的查看实际计划，之后的还款、逾期、结清看该笔当前事实；不自动选择期次或提交还款，不改变放款清单的“已放款”展示。
- **模板**：计划已定稿用 [T-LN-04A](#t-ln-04a)，仍在生成中用 [T-LN-04B](#t-ln-04b)；一位收件人对同一事件只收一个。

<a id="excluded"></a>
## 2. 不发送的场景

| 场景 | 处理 |
| --- | --- |
| 资产方接受报价、本笔进入待放款 | 由授信报价模块的融资报价已接受（N-CR-04）唯一告知；放款清单入列不是新事件 |
| 资金方暂时不付款，本笔长期停在待放款 | 没有可登记的动作，不发信、不催办 |
| 资产方长期未确认到账 | 没有确认时限，不发临期提醒、超期通知或周期催办；等待事实在业务页面中性可读 |
| 合同版本或条款争议 | 合同不进入平台，争议线下解决，不发相关消息 |
| 阅读详情、下载文件、选用账户、上传凭证 | 在办理或详情中反馈，不发信 |
| 质押水位不安全、额度结论不可用、项目期限或代币事实变化 | 质押与项目事件归融资需求与代币质押模块；已进入待放款或待放款确认的业务不因此失效，本模块不另发 |
| 表单失败、凭证或交易标识格式错误、所选账户已变更、通知发送失败 | 原场景说明原因与恢复路径，不发失败广播 |
| 还款计划生成中、生成恢复 | 本模块不补发第二次确认信；还款计划定稿由还款模块只发给资产方，资金方不收第二份定稿提醒 |
| 客服邮件往来、运营日常查看 | 本模块没有审批、裁决或代确认职责，不生成运营消息 |

<a id="ownership"></a>
## 3. 同一事实由一个模块发送

| 事实 | 谁发送 | 相邻模块怎么做 |
| --- | --- | --- |
| 接受报价、进入待放款 | 授信报价模块：融资报价已接受（N-CR-04） | 本模块、我的控制台和消息中心只展示事实，不发同义消息 |
| 放款记录提交、确认到账 | 本模块：放款记录已提交（N-LN-01）、资产方已确认放款到账（N-LN-04） | 我的控制台、清单与消息中心只承接，不另发 |
| 需求因项目到期或质押水位不足终结 | 融资需求与代币质押模块 | 已进入待放款或待放款确认的业务不因此失效，本模块不发终止类消息 |
| 还款计划定稿 | 还款模块，只发资产方 | 资金方从资产方已确认放款到账（N-LN-04）查看同一笔的实际进度 |
| 还款登记、还款确认、逾期、结清 | 还款模块 | 放款清单确认到账后固定显示“已放款”，本模块不再发信 |

<a id="rules"></a>
## 4. 共同规则

- **收件归属**：收件账号须能由本笔可靠确定，消息归该账号；没有可靠归属时不由当前登录者或其他人补位；账号停用、换角色或失权不自动转给他人；历史消息不随后来的办理者改投。同钱包、同邮箱或跨端身份不串信。
- **同一事件只一条**：同一账号 + 同一融资业务编号 + 同一事件只发一条；重复到达或补处理不新增、不置顶、不恢复未读、不改发生时间。同一融资申请下的新融资业务有自己的消息，不覆盖旧业务的消息。
- **内容是发生时的事实**：保留事件发生时的机构、金额、时间与结果。“已提交”只表示平台已登记，不代表资金已到账、已由平台核验或已在链上确认。金额来自本笔锁定的条款，不按当前汇率重算。
- **阅读不等于办理**：读信或全部已读不是确认到账，也不是还款；点击消息不代替在办理中点击提交或确认到账，办理仍需当前权限与条件。
- **每次点击重新判权**：重新判断身份、归属、对象、状态与文件权限；未登录先登录并保留合法目标；无权或不存在不泄露存在性；原业务定位未就绪时保留可读消息并说明暂不可查看，不猜测地址、不静默跳首页。
- **发送失败**：不回滚已提交或已确认的事实，不重置额度；用户仍可在页面查看本笔结果。
- **时间展示**：业务日期按 UTC，时刻按收件人偏好时区展示并标注时区；没有偏好时按平台规则。
- **消息内不出现**：账号、钱包地址、交易标识、凭证或协议正文、客服邮箱、内部备注；必要的企业名称不开放对方账户档案。

## 5. 登记信息与中英模板

<a id="registration"></a>
### 5.1 登记信息

按[面客消息中心的来源接入登记要求](../10-面客消息中心/01-面客消息中心-PRD.md#rg-nc-01)登记。两类消息的平台与端都是借贷平台面客端，发送来源都是本模块，打开后去哪都是原业务；适配状态均为“待适配”，不等于已完成共享登记或真实送达。分类取值由消息中心最后统一核对。

| 消息 | 业务类型标识 | 分类 | 模板 | 同一事件的区分依据 | 消息有效期 |
| --- | --- | --- | --- | --- | --- |
| 放款记录已提交（N-LN-01） | financing.disbursement.submitted | 业务办理进度 | T-LN-01 | 收件账号 + 本笔融资业务编号 + 放款提交 | 不设有效期；本笔确认到账后停止引导办理，历史保留 |
| 资产方已确认放款到账（N-LN-04） | financing.deal.confirmed | 业务办理进度 | T-LN-04A / T-LN-04B 按计划进度取一 | 收件账号 + 本笔融资业务编号 + 到账确认 | 结果消息，不设有效期；计划恢复不重发 |

模板标题与正文成对登记；同一账号同一事件不收两封。

<a id="variables"></a>
### 5.2 模板变量

| 变量 | 业务含义 | 用在哪些模板 | 要求 |
| --- | --- | --- | --- |
| demand_id | 原融资申请编号（FP-28） | 全部 | 不能用同一项目的新申请代替 |
| business_id | 本笔融资业务编号（FD-01） | 全部 | 始终指原笔，不换成同申请的新业务 |
| disbursement_id | 放款编号（LN-01） | 全部 | 不用虚构编号补位 |
| institution_name | 本笔资金方企业的可展示名称 | T-LN-01 | 不用个人姓名、邮箱或钱包地址 |
| amount / currency | 本笔放款金额（LN-04）与放款币种（LN-03） | T-LN-01 | 与报价锁定的数值一致；不按行情重算，展示截断不改变金额 |
| submitted_at | 放款记录提交时间（LN-06） | T-LN-01 | 不取送达或阅读时间 |
| confirmed_at | 确认到账时间（FD-35） | T-LN-04A、T-LN-04B | 不是发放时间、上传时间或计划恢复时间 |

- 必要变量或收件归属缺失时，不用演示值、空白消息、假编号或裸占位符补齐，按来源补齐后再发；单条缺失不影响整个消息列表可用。
- 中英模板的变量名称与数量一致；时间与金额按平台统一格式展示。
- 任何模板都不出现确认截止、剩余时长、催办措辞或客服邮箱。

## 6. 依赖

- **面客消息中心**：两类事件的分类、模板与原业务定位须完成共享登记与真实送达验证；未完成前为“待适配”，不能称已上线。送达时效沿[送达时效（IF-NC-01）](../10-面客消息中心/01-面客消息中心-PRD.md#if-nc-01)。
- **链上还款**：计划定稿通知的触发、收件与内容以该模块为准。
- **授信报价与接受拒绝**：融资报价已接受（N-CR-04）的触发、收件与内容以该模块为准。
