<a id="scope"></a>
## 1. 模块是什么

资产方接受报价后，本笔融资业务进入待放款。本笔资金方在平台外完成付款，再到平台登记放款记录并选定将来收还款的账户；本项目资产方自行核实到账后确认到账。确认成功的同一时刻，本笔金额从“在途”转为“本金”，并交还款计划与还款确认模块生成正式还款计划。平台不执行转账，不核验付款、合同或交易的真实性。

基本原则：

- 只有两步：资金方登记放款，资产方确认到账。待放款和待放款确认都没有时限、没有终止出口，也没有暂缓、重传或异议之类的中间动作；争议由双方线下解决。
- 登记放款不等于到账。只有资产方确认到账，金额才转为本金、还款计划才生成。
- 账户只能从企业账户中已登记的账户里选用：资产方收放款的账户在接受报价时已定，本模块只读沿用；资金方收还款的账户在登记放款时选定。办理中不新增、不编辑账户，平台不采集收款人名称。
- 放款金额与币种复用报价时锁定的条款，不重新取价，也不能修改。
- 登记放款与确认到账都是点击即提交，不另设二次确认；不可撤销的后果在提交前的办理中告知。
- 全流程没有倒计时；时间流逝本身不改变任何业务结论，也不释放任何占用。

**一个完整的例子。** 资产方甲接受了资金方乙对融资申请 P01-01 的报价（融资业务编号 FD-001，融资金额 150 万 USD，结算币种 USDT），甲接受时选了本企业一个 ETH 数币账户收款。同一笔立即出现在项目详情的融资放款信息中，显示“待放款”和“尚未提交放款记录”。乙在平台外向甲的 ETH 地址转出 1,500,000 USDT，然后从项目的融资办理入口进入本笔放款：核对已接受的商务条款和甲的收款地址，填写实际付款时间和交易标识，从本机构已登记的数币账户中选一个同在 ETH 上的地址作为将来收还款的账户，看过“提交后不可修改、平台不核验付款、不启动任何倒计时”的告知后点击提交，提交即生效。平台生成放款编号，本笔变为“待放款确认”，甲收到“放款记录已提交”站内信。甲到账后从站内信进入确认，看到“到账金额会少于融资金额，本金仍按 150 万 USD 计算”的告知，点击“确认到账”即生效。本笔变为还款中，放款清单显示“已放款”，项目在途金额与机构在途报价金额各减少 150 万 USD、项目融资余额与授信占用额各增加 150 万 USD；乙收到“资产方已确认放款到账”站内信，同一笔出现在还款信息中，等待还款计划生成。每次成功后都结束本次办理、回到原来的项目位置，不自动打开详情。

<a id="out-of-scope"></a>
### 1.1 本期不做

- 平台代为转账、代付、归集，或链上自动核验付款。
- 合同盖章件的上传、核验与重传；合同由双方线下签署，不进入平台。
- 待放款阶段的暂不放款、要求重传、放款前终止；待放款确认阶段的异议、驳回、申诉。
- 放款确认时限、临期提醒、超期标记、催办与自动确认。
- 部分或分次放款，放款记录的修改与撤回，确认到账的撤销。
- 在本模块新增、修改或删除企业账户（归[企业账户](../03-企业账户/01-企业账户-PRD.md)）。
- 还款计划的生成规则、计息、期次与还款确认（归[还款计划与还款确认](../08-借贷广场-还款计划与还款确认/01-还款计划与还款确认-PRD.md)）。
- 运营或 SPV 机构参与放款登记、确认、裁决或代确认；本模块向运营发送的消息。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 融资业务 | 一笔已接受报价形成的业务，以融资业务编号（FD-01）识别；一轮融资申请（FP-28）下先后可以有多笔 |
| 待放款 | 资产方接受报价后、资金方提交放款记录之前的业务状态（S-FD-3） |
| 待放款确认 | 资金方提交放款记录后、资产方确认到账之前的业务状态（S-FD-4） |
| 还款中 | 资产方确认到账后的业务状态（S-FD-6），本模块到此交给还款模块；不表示业务结清 |
| 放款记录 | 资金方登记的一次放款事实，成功提交时生成放款编号（LN-01）；一笔融资业务只有一条 |
| 发放时间 | 资金方自己填写的平台外实际付款时间（LN-05），只供对账参考 |
| 提交时间 | 平台记录放款记录提交成功的时刻（LN-06），是还款计划起息日的取值依据 |
| 交易标识 | 数币付款时资金方提交的链上交易编号（LN-08），平台只校验格式 |
| 结算收款链 / 质押链 | 结算收款链是数币账户地址所在的链（ETH 或 TRON），本模块只用这一个；一笔数币业务只有一条结算收款链，资产方收款账户与资金方数币收款账户都在这条链上；质押链是代币与质押合约所在的链，与本模块无关。两者互不决定 |
| 资产方收款账户 | 资产方接收本笔放款的本企业账户，接受报价时选定，本模块只读沿用（LN-10） |
| 资金方收款账户 | 资金方将来接收本笔还款的本机构账户，登记放款时选定：USD 为法币账户（LN-15），USDT/USDC 为数币账户（LN-16） |
| 在途报价金额 / 授信占用额 | 机构维度：已报价、尚未转为本金的金额 / 已放款确认、尚未偿还的本金，定义沿[授信报价与接受拒绝](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#glossary) |
| 项目在途金额 / 项目融资余额 | 项目维度：已发布、尚未完成放款确认的需求金额 / 已放款确认、尚未偿还的本金，定义沿[融资需求与代币质押](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#inv-fin-01) |
| 质押水位 | 有效质押额不低于“项目融资余额＋项目在途金额”为水位安全，低于为水位不安全；定义沿[质押水位（INV-FIN-01）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#water-level) |
| 固定折算 | 本期平台业务规则 1 USD = 1 USDT = 1 USDC，在报价时锁入本笔快照；不是外部市场价格 |

## 3. 共同规则

<a id="roles"></a>
### 3.1 角色与可见范围

| 角色 | 可以做什么 | 能看到什么 | 不能做什么 |
| --- | --- | --- | --- |
| 本笔资金方（原报价机构） | 待放款时登记放款并选定资金方收款账户；查看本笔全部放款信息 | 本笔全部放款信息、资产方收款账户与资金方收款账户的完整账号或地址（可查看与复制）、凭证与交易标识 | 待放款确认之后的任何本模块写动作；修改或撤回放款记录 |
| 本项目资产方 | 待放款确认时确认到账，不设时限 | 本笔全部放款信息、资产方收款账户与资金方收款账户的完整账号或地址（可查看与复制）、凭证与交易标识 | 代资金方登记放款；撤销确认 |
| 非本笔当事的资金方（含入驻审核中或已驳回） | 无本模块动作 | 融资放款信息清单中每笔的融资申请编号、融资业务编号、报价机构名称与放款展示状态 | 看到放款金额与币种、账户、凭证、交易标识、发放时间、备注与补充材料；任何写动作 |
| 资产方查看其他企业的项目 | 无 | 只看到项目基本信息，看不到融资放款信息 | 看到本模块任何内容 |
| 游客（未登录）、登录未绑定角色 | 无本模块动作；按[项目详情按身份的可见范围（F-LS-82）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-82)登录或申请成为资金方 | 只看到项目基本信息，看不到融资放款信息 | 看到本模块任何内容 |
| 运营、SPV 机构 | 无面客动作 | 本模块不增加其资料可见权 | 代付、归集、放款登记、确认、裁决或代确认 |

- 放款金额与放款币种就是本笔报价的融资金额、结算币种与结算金额。它们对谁可见，沿[报价信息的查看权限](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#non-party)：只对本笔资产方与报价机构开放。本模块不另定一套。
- 本期一个企业只有一个员工账号，由该账号代表企业执行其角色的动作。登录成功不等于成为某笔业务的当事方。
- 查看、下载与提交都在服务端判权；隐藏或禁用入口不能代替权限控制，直接访问或直接提交同样被拒绝。
- 无权或不存在的对象不暴露是否存在，不报错页、不空白、不静默跳回首页。

<a id="view-and-act"></a>
### 3.2 查看与办理

查看与办理分开，以及返回、关闭、成功与失败后的去向，沿[查看与办理分开（融资需求与代币质押 F-LS-20）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-20)。本模块补充：

- 资金方登记放款、资产方确认到账，从项目的“融资”业务入口或有效站内信进入办理，不从只读详情转办。控制台仅显示行级业务事实，经摘要详情唯一导航到原项目及原 FD 的只读位置；需要办理时从项目既有入口独立发起，按[控制台原对象阅读定位建议（Q-MC-60）](../09-我的控制台/01-我的控制台-PRD.md#q-mc-60)建议执行、待确认；[控制台待办](../09-我的控制台/01-我的控制台-PRD.md#todo)同样定位原 FD 只读位置，不办理直达。
- 登记放款与确认到账都是点击提交即生效，不另设二次确认（用户要求）；办理在本次办理内完成，不再叠加下一层办理。
- 提交或确认成功后结束本次办理，回到来源并刷新本笔记录与办理入口，不自动打开详情或下一阶段（用户要求）。
- 只提供当前可以办理的动作；当前不能办理时用说明告知原因，例如质押水位不安全、额度结论暂时不可用、本笔已由对方处理。
- 不向用户展示条款号、字段来源或内部判据。

<a id="profile"></a>
### 3.3 业务资料与本人档案

- 个人与企业的账户档案只对本人开放；对方不能借核对本笔资料读取完整账户档案、证件、认证材料或私人联系方式。
- 本笔必需的企业名称、约定条款与付款资料自动取得：优先取本笔已确认的事实，其次取同一企业、同一用途的有效登记资料。
- 资料缺失、读取中、读取失败分别说明；读取失败可重试，不说成“尚未登记”，不要求用户手填对方资料，也不用示例值或零值补齐。
- 关键主体归属或必要付款资料不能确认时，不放行相关提交。
<a id="full-value"></a>
- 账号、地址和交易标识可以脱敏展示；凡是展示脱敏值的位置，本笔资金方与本项目资产方都有查看完整值的操作，并可复制（用户要求）。融资双方都能查看两侧收款账户（资产方收款账户、资金方收款账户）的完整账号或地址，以及交易标识的完整值。
- 非本笔当事方、运营与 SPV 机构没有查看完整值的操作，直接访问同样被拒绝。脱敏的具体形式与查看操作的呈现由设计决定。

<a id="time-and-money"></a>
### 3.4 时间、金额与时效

- 业务日期、放款编号中的日期与起息日使用 UTC；发放时间、提交时间、确认时间等时刻按用户偏好时区展示并标注时区，没有偏好按平台规则，游客按浏览器时区。
- 切换时区、跨日、夏令时或切换语言都不改变任何业务日期或业务事实。本模块没有任何截止时刻或剩余时长。
- 金额一律带币种。USD 最多两位小数，以两位展示。USDT/USDC 金额按 1:1 复用报价锁定值；展示截断不改变付款金额。
- 界面默认英文，支持中文。同一场景术语一致：放款环节称“放款确认”，不与报价环节的接受混称。
- 已确认的时效目标：打开放款办理到本笔条款与账户可读 2 秒内；放款提交、确认到账的处理各 2 秒内。实现与验证归研发、测试。
- 放款登记、确认到账及金额转移都可追溯到业务、主体、操作账号与时间。

<a id="f-ls-56"></a>
## 4. 融资放款信息：清单、详情与办理入口（F-LS-56）

适用角色与前提：能看到本项目完整详情的身份（本企业资产方、资金方），可见内容按[角色与可见范围](#roles)。融资需求与代币质押模块对本清单与详情的描述只是概述，以本节为准。流程见[放款清单、只读详情与办理（P-L7-00）](./02-放款与放款确认-流程图与状态机.md#p-l7-00)。

<a id="list"></a>
### 4.1 清单

- 资产方接受报价、本笔进入待放款时，即进入项目详情的融资放款信息清单；不等成功提交放款后才出现。
- 每笔融资业务（FD-01）是一条独立记录，按接受时间倒序；每页条数、分页与清单间的切换沿[查看四类记录](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#records)。
- 确认到账后保留原记录，并由还款信息清单以同一笔编号承接。确认到账后本清单的放款展示状态固定为“已放款”，之后的还款中、逾期与结清只在还款信息中表达，不回写本清单。
- 没有记录时保留清单并说明“接受报价后在此查看放款业务”；读取失败与无记录分别说明。不得用演示记录代替。
- 融资申请编号、融资业务编号、放款编号都能定位到同一条记录；只有已经生成的放款编号才能按放款编号检索。
- 清单记录只能打开只读详情，不承载办理或跨业务跳转。

| 清单信息 | 含义与展示口径 | 谁能看到 |
| --- | --- | --- |
| 融资申请编号（FP-28） | 原需求编号，只读，不生成新号 | 本企业资产方、所有资金方 |
| 融资业务编号（FD-01） | 本笔定位依据；同一申请重新报价形成的新业务另有新编号，不覆盖原记录 | 本企业资产方、所有资金方 |
| 报价机构 | 本笔资金方企业的可展示名称 | 本企业资产方、所有资金方 |
| 放款编号（LN-01） | 成功提交放款记录后才有；待放款时显示“尚未提交放款记录”，不预生成，也不拿融资业务编号代替 | 本企业资产方、所有资金方 |
| 放款展示状态 | 待放款（S-FD-3）、待放款确认（S-FD-4）、已放款（确认到账后，之后不再变化）三种；不出现终止、暂缓、待重传、确认超期或任何倒计时 | 本企业资产方、所有资金方 |
| 放款金额与币种 | 提交前标明为“约定放款金额”，不冒充已实际放款；提交后为放款记录的金额与币种 | 本笔资产方与报价机构 |
| 提交时间、确认时间 | 分别取放款记录提交时间（LN-06）与确认到账时间（FD-35）；未发生显示“未提交”或“未确认”，不填预计时间 | 本笔资产方与报价机构 |

<a id="detail"></a>
### 4.2 只读详情

融资放款详情一次给全下列信息，按此顺序讲述：

1. 放款信息：放款金额与币种、业务状态、当前处理方、融资申请编号、融资业务编号与放款编号、发放时间、提交时间与确认时间；凭证或交易标识按权限查看。
2. 资金方收款账户（LN-15 / LN-16），明确用途是将来收还款；待放款时显示“待资金方提交”。
3. 资产方收款账户（LN-10），明确用途是接收本笔放款。
4. 本笔已接受的商务条款摘要，内容与可见范围沿[报价信息的查看权限](../06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#non-party)。
5. 协议文件：只有授信协议（融资合同不进入平台），授信协议为选填，没有时说明“本笔未提供”，不显示待上传或待审核；文件可直接下载，提供预览时不改变当前查看对象、可以返回。

- 非本笔当事的资金方打开详情，只看到清单中对其可见的信息（编号、报价机构与放款展示状态），其余内容不展示，也不能通过直接访问取得。
- 以同一笔展示“资金方放款 → 资产方确认到账”两步的完成情况、当前处理方，以及“轮到您”或“等待对方”；非当事方看不到私有办理进度。
- 账户只展示企业账户已定义的字段，不补造出账账户，不把资金方收款账户称作放款出账账户。
- 关联编号只读展示，不提供查看申请或还款的跳转动作；不复制全套申请、多轮报价与还款计划。
- 待放款确认的详情中可复制客服邮箱，见[未到账与线下出口（F-LS-54）](#f-ls-54)。

<a id="entry-exceptions"></a>
### 4.3 入口与异常

- 从清单、控制台摘要导航与站内信进入，都落到同一笔业务、相同权限与最新状态；每次进入都重新判断权限与状态。
- 旧入口或旧消息遇到本笔已提交放款或已确认到账时，仍落到同一笔的当前详情并说明结果，不重开已完成的办理，不切换到同申请的新业务。
- 质押水位不安全或额度结论暂时不可用，只阻止资金方提交放款，不阻止查看本笔资料。
- 提交放款仅表明资金方已登记付款，不代表资产方已确认到账。

- USDT/USDC 的放款金额数值与对应 USD 本金相同，币种仍须明确。
- 本笔折算依据或关键金额缺失时，说明暂时无法核对本笔条款，不能提交；不用固定比值猜补历史事实。

**提交与结果。**

- 资金方点击提交即生效，不另设二次确认（用户要求）。提交前，办理中须始终可得以下告知：放款记录与所选资金方收款账户提交后不可修改、不可撤回；平台不核验付款真实性；提交不启动任何倒计时，资产方何时确认由双方线下商定。所选资金方收款账户在提交前须能辨认（账户备注名等），使资金方知道将来的还款打入哪个账户。
- 提交时再校验一次所选资金方收款账户：已被删除或修改的，本次提交不成立，说明账户已变更并要求重新选用；数币账户不在本笔结算收款链上的（包括绕过选用直接提交），本次提交不成立，说明须选用该链上的数币账户。
- 提交成功的结果同时成立：
  - 生成唯一放款编号，本笔从待放款变为待放款确认；
  - 记录提交时间、提交人与企业主体；
  - 所选资金方收款账户随放款记录固定为快照，见[已提交业务的账户快照](../03-企业账户/01-企业账户-PRD.md#snapshot)；
  - 项目在途金额、项目融资余额、在途报价金额、授信占用额四者都不变；
  - 资产方收到一条“放款记录已提交”站内信，见[本模块发送的站内信（F-LS-57）](#f-ls-57)；
  - 结束本次办理，回到来源并刷新本笔记录与办理入口，不自动打开详情。
- 放款记录只能查看，不能修改、撤回，也不能再新增第二条。
- 失败时分别说明原因：必填缺失、凭证不合格、发放时间晚于提交时刻、交易标识格式错误、未选资金方收款账户、所选账户已变更、所选数币账户不在本笔结算收款链上、质押水位不安全或额度结论不可用。失败不生成记录，不改变业务状态，保留已填内容与已成功上传的文件。
- 两人同时提交同一笔时只有一次成功，后到者说明已有放款记录并落到当前详情。
- 记录填错时走客服线下核实，不引导尚未到账的资产方先确认。

<a id="f-ls-50"></a>
### 5.2 提交时复核质押水位（F-LS-50）

适用角色与前提：本笔资金方提交放款记录时。

- 提交时按当场的权威结论判断本项目[质押水位（INV-FIN-01）](../05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#water-level)；打开办理时看到的旧结论不能代替提交时的判断。
- 水位不安全时，不接受放款提交，不生成记录，不改变业务状态；说明当前质押水位不安全，并给出追加质押的指引。指引须写明：追加质押要先上链、再经审核通过才计入有效质押额，上链成功不即时生效。
- 水位不安全时本笔资料仍可查看；资产方追加质押使水位恢复安全后，提交入口自动恢复，资金方不必重新进入详情。
- 无法取得可信的当前结论时，同样不接受放款提交，说明“暂时无法完成额度校验”并可重试；不把“未知”当作不安全、安全或业务失效。
- 已进入待放款或待放款确认的业务，不因质押情况变化、代币失效或项目到期而自动失效或终止。项目到期后，存量的放款与确认照常办理，按正常中性状态展示；到期不开放新报价。
- 资产方确认到账不受质押水位或额度结论的额外拦截。
- 质押与解押的链上执行结果未知、部分成功等异常，提示联系平台客服；本模块不建设异常处置、人工改成功或自动放行路径，不发起任何链上签名或 gas 动作。
- 水位不安全时，本笔只能等资产方追加质押并通过审核；资产方不追加时本笔一直停在待放款，后果见[按用户决定保留的业务限制](#limits)。

<a id="f-ls-51"></a>
### 5.3 交易标识格式与自行查验（F-LS-51）

适用角色与前提：数币放款时，本笔资金方填写交易标识；本笔双方查看。

- 只按本笔结算收款链校验交易标识的格式，不判断交易是否存在、是否成功或是否到账：

| 结算收款链 | 交易标识格式 | 查验入口 |
| --- | --- | --- |
| ETH | `0x` 后接 64 位十六进制字符 | 该交易在 ETH 区块浏览器中的页面 |
| TRON | 64 位十六进制字符，不带 `0x` | 该交易在 TRON 区块浏览器中的页面 |

- 链取自结算收款链（LN-09），用户不能改选。格式错误时说明本链的格式要求，不说成“交易不存在”。
- 格式正确但实际没有这笔交易时，平台也不能把它标成已核验。
- “平台未核验该交易，链接仅供自行查验”须与查验链接同时可得。
- 查验链接不可用时不提供死链接，保留有权限者复制交易标识的能力。平台外的查验结果不会自动确认到账。
- USDT/USDC 在各链上的代币标准按该链既有事实展示，不写死单一标准。

<a id="confirm"></a>
## 6. 资产方确认到账

<a id="f-ls-52"></a>
### 6.1 确认到账与金额转移（F-LS-52）

适用角色与前提：本项目资产方；本笔处于待放款确认（S-FD-4）。没有时限；项目到期、质押水位不安全都不取消确认资格。流程见[到账确认与还款交接（P-L7-03）](./02-放款与放款确认-流程图与状态机.md#p-l7-03)。

- 办理中给出本次判断所需的信息：放款金额与币种、发放时间（标明资金方填写）与提交时间（标明平台记录）、法币凭证或数币交易标识与查验链接、资产方收款账户要点、当前处理方、到账差额告知。发放时间与提交时间须同时可得且来源可分辨。
- 资金方收款账户、完整商务条款、提交人等弱关联信息留在只读详情，办理中不重复提供。
- 唯一主动作是“确认到账”，点击即生效，不另设二次确认（用户要求）。点击前，办理中须始终可得以下告知：已自行核实到账才可确认、平台未核验付款、确认后不可撤销、确认后进入还款。
- 尚未到账时不点击确认、直接关闭办理即可，本笔保持待放款确认，资产方线下核实；不提供异议或驳回入口。
- 确认成功的结果同时成立（以 X 表示本笔融资金额 QT-03，USD）：
  - 本笔从待放款确认变为还款中（S-FD-6），记录确认时间（FD-35）；
  - 两个维度的金额同时转移，见下表；项目保持融资中；
  - 形成还款模块生成还款计划的依据，见[交接还款计划与我的控制台（F-LS-55）](#f-ls-55)；
  - 资金方收到一条“资产方已确认放款到账”站内信；
  - 结束本次办理，回到来源并刷新本笔记录与办理入口，不自动打开放款详情或还款详情。
- 确认成功后不再提供确认动作；再次进入时说明已有结果。

- 转移一律按融资本金，不按资产方实际到账金额、不按当日汇率；不改变授信额度、有效质押额或质押价值。同一事件不能使同笔金额遗漏或重复计量。
- 例：本金 150 万 USD、有效质押额 200 万 USD、其他融资余额为 0。放款提交后可融金额仍为 50 万 USD；确认到账后仍为 50 万 USD，只是这 150 万 USD 从项目在途金额转为项目融资余额。
- 确认本身未成功时，本笔保持待放款确认，四个金额保持原值，可以再次确认；不出现半成功。重复确认不重复转移金额，也不重复触发还款计划。
- 还款计划尚未生成不算确认失败，见[交接还款计划与我的控制台（F-LS-55）](#f-ls-55)。

<a id="f-ls-58"></a>
### 6.2 到账差额告知（F-LS-58）

适用角色与前提：本项目资产方，确认到账时。

- 确认动作之前须始终可得以下告知，不得被隐藏、遮盖或弱化：“到账金额会少于融资金额（跨境手续费由您承担）；您需要偿还的本金仍按融资金额 {X} USD 计算。”
- 沿用已确认的手续费口径：不预估手续费金额，平台不代收、不垫付。
- 确认到账不采集实际到账金额，也不与融资金额比较或对账；差额不提示异常、不阻断确认。
- 例：融资金额 1,500,000 USD，扣除跨境手续费后实际到账 1,499,750 USD，资产方照常确认，全部本金与金额转移仍按 1,500,000 USD。
- 实际未到账时，不能因为有这条差额告知而被引导确认。

<a id="f-ls-54"></a>
### 6.3 未到账与线下出口（F-LS-54）

适用角色与前提：本笔双方，待放款确认期间。

- 确认到账的办理与融资放款详情两处提供可复制的客服邮箱，并提示邮件注明融资申请编号（FP-28）与融资业务编号（FD-01）。客服邮箱的取值在代码中固定、随版本发布，平台不提供维护或配置入口；邮箱不进入任何站内信。
- 说明平台不会代为确认或自动确认，也不会自动作废业务；不承诺线下处理的时效或结果。
- 未到账、凭证有误、金额有疑问时，资产方可以保持未确认并联系对方或客服；平台没有强制终止、代确认或申诉裁决入口。线下核实后仍由资产方回本笔办理入口确认，结果与任何时点的确认相同。不得要求“先确认再处理”。
- 若一直不确认，本笔一直停在待放款确认：还款计划不生成，项目在途金额与在途报价金额继续占用，质押不释放，项目到期也不能据此结束存量业务。详情须让双方理解这些后果，但不以倒计时、超期标记或催办表达。
- 客服沟通不新增状态、计时或运营待办。

<a id="f-ls-55"></a>
## 7. 交接还款计划与我的控制台（F-LS-55）

适用角色与前提：确认到账成功后。流程见[到账确认与还款交接（P-L7-03）](./02-放款与放款确认-流程图与状态机.md#p-l7-03)。

- 确认成功时，本模块向[还款计划与还款确认](../08-借贷广场-还款计划与还款确认/01-还款计划与还款确认-PRD.md)提供：确认事实、融资金额（QT-03）、折算比值（QT-04）、结算币种与结算金额、提交时间（LN-06）、确认时间（FD-35）、资金方收款账户（LN-15 / LN-16）。
- 起息日取提交时间（LN-06）的 UTC 日期，还款计划定稿的触发取确认时间（FD-35）；发放时间（LN-05）不用于计息。计划生成、还款方式、期数、计息、开窗、逾期与结清都归还款模块。
- 确认成功即触发计划生成，本笔同时出现在还款信息清单，以融资业务编号唯一承接融资申请编号与放款编号。
- 触发不等于生成完成。计划尚未就绪时，保留还款中与已成立的金额结果，展示“还款计划生成中”；恢复后提供同一笔唯一的一套定稿计划。
- 计划生成中不回到待确认、不要求资产方再次确认、不展示虚构计划、不承诺“计划已生成”，也不把报价时的预计计划当作定稿计划；计划恢复不重复转移金额。
- 我的控制台只读复用本模块的记录与状态。控制台行级事实对资金方为“待放款”、对资产方为“待我确认”，并分别形成[控制台待办](../09-我的控制台/01-我的控制台-PRD.md#todo-types)“登记放款”“确认到账”；都不附时限、倒计时或超期标记。还款模块与控制台不另建本金、账户或状态口径。本模块不释放质押。

## 8. 本模块发送的站内信（F-LS-57）

- 本模块发送两类站内信：放款记录已提交（N-LN-01，发资产方）、资产方已确认放款到账（N-LN-04，发本笔资金方）。触发、收件、内容与落点见[消息通知](./03-放款与放款确认-消息通知.md)。
- 资产方接受报价后进入待放款，由授信报价模块的[融资报价已接受（N-CR-04）](../06-借贷广场-授信报价与接受拒绝/03-授信报价与接受拒绝-消息通知.md#n-cr-04)告知资金方，本模块不为同一次接受补发消息。
- 还款计划定稿由还款模块只发给资产方；资金方只收本模块的到账确认信，不收第二份定稿提醒。
- 没有临期提醒、超期、暂缓、重传、终止或周期催办消息；同一账号、同一笔、同一事件只发一条；通知发送失败不回滚业务，用户仍可在页面查看本笔结果。

<a id="limits"></a>
## 9. 按用户决定保留的业务限制

以下是用户明确裁定后的既定结果，如实记录业务后果，供研发与测试知悉，不作为缺陷处理。

1. **平台不采集收款人名称，也不校验账户归属。** 法币与数币账户都没有收款人名称，受益人名称由双方在平台外补充；平台不能自动校验“收款账户属于本企业”，账户选错的后果由双方线下承担。
2. **报价一经提交，资金方无法撤回。** 进入本模块的都是已接受的业务，资金方在待放款阶段没有任何撤出动作。
3. **待放款与待放款确认都没有终止出口和时限。** 待放款的唯一出口是资金方提交放款，待放款确认的唯一出口是资产方确认到账。若线下协商结果是不放款，平台侧没有任何动作能终结该笔业务：本笔持续停留，机构与项目两个维度的在途金额持续保留，资产方不能发布新一轮需求，对应质押代币持续被占用。
4. **质押水位不安全时，待放款只能等资产方追加质押。** 提交放款须质押水位安全，而本笔金额已计入项目在途金额，放款提交与确认到账都不改变“项目融资余额＋项目在途金额”。因此水位一旦不安全，只有资产方追加质押并通过审核才能恢复；资产方不追加时，资金方无法提交放款，本笔会一直停在待放款，项目也不能发布新一轮。
