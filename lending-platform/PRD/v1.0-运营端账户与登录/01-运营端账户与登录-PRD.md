# 运营端账户与登录 · PRD

2026-09-24｜运营管理平台 · 运营端｜需求评审稿，真实未决项见第 5 节。

## 1. 目标与阅读入口

运营人员用平台建设方交付的工作邮箱与密码登录运营管理平台，完成首次强制改密后，按已配置的功能权限执行各项运营动作，并自助维护本人密码、工作邮箱与语言时区偏好。

本期包含：账号来源与首登强制改密、工作邮箱密码登录、忘记密码两步找回、账户设置（账号信息、本人改密、本人改邮箱、语言与时区）、覆盖运营各业务模块的功能权限矩阵、会话与锁定、发码前的滑块人机校验与限频、账户安全通知的触发口径、登录后落地的总览壳子。相邻模块负责：各审核、配置、协议、消息动作的业务规则（WS-381／WS-382／WS-383／WS-384／WS-387／WS-388），站内消息的承载与未读语义（WS-383），语言、时区、数字、金额、链上地址与脱敏的正文口径（三平台共享国际化基线）。本期不包含第 1.2 节 `X-AL-*` 各项。

有效依据：需求方 2026-09-18 确认（SPV 与运营机构同一主体、初始邮箱与密码由建设方提供、首次登录强制改密、允许本人修改邮箱、本期不实现邀请员工）；2026-09-20 确认的交互（验证码输入与获取动作须同时可得、密码可由本人切换显示或隐藏、两次密码不一致须在提交前就地提示、首登只填新密码与确认密码、账户设置同时承载账号信息与偏好信息且不展示权限清单）；2026-09-21 确认获取邮箱验证码必须先通过滑块；WS-346 用户 P04、P12 决策（SPV 同运营；协议历史版本管理员可读、操作记录全员可看；维护/发布包含必要查询）；后续确认账户信息不在管理端导航中重复展示（入口仍可达）、各管理模块共用同一套功能入口信息。

阅读顺序：第 2 节角色与共同规则 → 第 3 节完整功能 → 第 4 节同序验收 → 第 5 节依赖、风险与待决。

配套（须共同阅读）：[流程图与状态机](02-运营端账户与登录-流程图与状态机.md)、[消息通知](03-运营端账户与登录-消息通知.md)。

## 2. 角色、账号与共同业务规则

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

沿用的名称中，「运营端消息入口」指该入口由管理端共享导航承接、不由本模块自建，与其在界面上的位置无关；「滑块拼图人机校验」指用户已确认的这一类人机校验机制本身，不指定其承载形式与视觉反馈；「层级路径导航」指当前所处层级及可回到的上级这一事实，不指定其呈现方式。

### 2.1 主体、账号与角色

| 编号 | 口径 | 结论 |
| --- | --- | --- |
| <a id="d-al-02"></a>`D-AL-02` | 部署边界与账号归属 | 运营管理平台是独立部署单元；运营账号与代币发行平台运营端不共用，不做跨平台单点登录，不做账号同步 |
| <a id="d-al-03"></a>`D-AL-03` | SPV 与运营机构的关系 | SPV 与运营人员按同一运营身份体系处理。不新增第二类账号、机构维度的功能入口或数据域；身份同一不产生资金代付、代收或代登记/确认权限 |
| <a id="d-al-04"></a>`D-AL-04` | 账号来源 | 只有一套运营账号体系，初始工作邮箱与密码由平台建设方提供；产品内无注册、邀请员工、新增账号、申请开通入口 |
| <a id="d-al-05"></a>`D-AL-05` | 数据可见范围 | 不做机构级数据隔离；在获准的业务对象范围内不按所属机构或本人经办筛选。功能权限与对象限制仍适用，不能据「全量」读取管理员专属协议历史、他人账户档案或本人专属安全消息 |
| <a id="d-al-06"></a>`D-AL-06` | 主体分家的边界说明 | 主体后续若分家（SPV 独立为另一家法律主体），届时按「多机构 / 租户」独立立项处理；本期不为此预先设计租户隔离、机构维度字段或数据域切分。本条只作边界说明，不产生本期设计要求 |
| <a id="d-al-30"></a>`D-AL-30` | 术语 | 本册「运营端」专指运营管理平台的运营端；对外角色称谓统一为「运营管理员 / Operations Administrator」「运营专员 / Operations Specialist」，界面上不出现「SPV 机构」作为账号类型 |
| <a id="d-al-31"></a>`D-AL-31` | 与面客端账号的关系 | 运营账号与面客端资产方 / 资金方账号完全独立：运营账号不能登录面客端，面客端账号不能登录运营端 |

| 角色 | 描述 | 在本模块内的核心诉求 |
| --- | --- | --- |
| 运营管理员（`RO-AL-1`） | 拥有本期全部业务权限的运营人员 | 按交付的初始账密完成首登改密，使用业务功能并维护本人密码与邮箱；其他设备的登录在改密后立即失效 |
| 运营专员（`RO-AL-2`） | 按交付配置承担运营 / SPV 职责的人员 | 完成首登改密，界面上只出现已授权的事；忘记密码时能通过工作邮箱自助重置，工作邮箱变更后能自行更新登录与找回地址 |
| 平台建设方 / 运维 | 交付初始账号、角色与权限配置，提供异常人工恢复 | 配置依据明确；产品内没有账号管理界面 |
| 非中文运营成员 | 运营团队中不使用中文的成员 | 打开就是英文，不必先找语言开关；切成中文后换设备登录仍是上次所选 |

<a id="d-al-13"></a>`D-AL-13`【SPV 职责的落法】：SPV 不是一类账号，而是一组职责，按职能落在运营人员的功能权限项上。现阶段已规划的运营动作（认证审核、质押审核、项目审核与合约部署、融资参数配置、协议管理、消息查看、业务查询）即为其可授权范围。不增加 SPV 专属动作，不赋予资金代付、代收、代登记、代确认或代替当事方办理的能力，也不因此开放私人付款资料；后续若确需新增，须先由对应业务模块确认职责与权限，不能仅凭同主体追加授权。

<a id="2-4-账号状态会话与验证码状态"></a>
### 2.4 账号状态、会话与验证码状态

**账号状态**（图示 [SM-AL-01](02-运营端账户与登录-流程图与状态机.md#sm-al-01)）

| 编号 | 状态 | 含义与行为 |
| --- | --- | --- |
| `ST-AL-1` | 待首登改密 | 建设方已交付初始账密，本人尚未完成首次登录强制改密。登录验证通过后仅可改密、退出与切换语言，不可执行业务动作 |
| `ST-AL-2` | 正常 | 已完成首登改密，按交付配置的权限使用业务功能 |
| `ST-AL-3` | 锁定 | 连续密码校验失败达到阈值，不可登录或完成找回，无提前解锁通道；到期回到锁定前状态 |

| 从 → 到 | 触发 | 附带结果 |
| --- | --- | --- |
| 待首登改密 → 正常 | 完成 `P-O-AL-03` 强制改密 | 初始密码失效、触发密码变更通知、全部会话失效并要求重新登录 |
| 正常 / 待首登改密 → 锁定 | 连续密码失败达 `N-AL-01`（含账户设置内再认证失败） | 登录与找回不可完成，已有登录不得执行业务动作；不发通知 |
| 锁定 → 锁定前状态 | 锁定到期自动解除 | 登录页表单自动恢复可用，无需刷新 |

忘记密码不会让待首登改密账号直接转正常（见 [3.4](#f-al-05)）。本期没有产品内新增账号、停用 / 启用、他人改密或重新开通的状态转换。人工重新初始化属建设方 / 运维的线下兜底，重新交付后仍以待首登改密进入上述流程，也不得用于提前解除既有锁定。

**登录会话**（图示 [SM-AL-02](02-运营端账户与登录-流程图与状态机.md#sm-al-02)，规则见 [3.11](#f-al-12)）；**验证码状态**（图示 [SM-AL-03](02-运营端账户与登录-流程图与状态机.md#sm-al-03)）

| 状态 | 含义 | 转换 |
| --- | --- | --- |
| 已签发 | 发往对应目标邮箱且仍有效 | → 已使用 / 已过期 / 已作废 |
| 已使用 | 此次验证与对应操作已完成 | 终态，不可重复使用 |
| 已过期 | 超过 `N-AL-03` | 终态，按原入口重新发码 |
| 已作废 | 同用途重新发码、超过错误上限、完成密码变更；或邮箱修改生效使旧邮箱找回验证码失效 | 终态，不再可用 |

验证码状态仅适用于找回密码与修改邮箱，不含邀请凭据。同一账号同一用途仅最新验证码有效，不能跨用途或目标邮箱使用；换新邮箱后旧目标的码不能用于新目标。密码变更导致会话全局失效时，未使用的验证码与滑块人机校验结果一并失效。

<a id="pm-matrix"></a>
### 2.5 功能权限的组织方式

| 编号 | 口径 | 结论 |
| --- | --- | --- |
| <a id="d-al-07"></a>`D-AL-07` | 权限组织方式 | 权限按功能权限组织：每个审核、配置、查询动作是一个独立的可授权项（`PM-AL-*`），按「角色 → 功能权限项」授权，不按机构维度切数据 |
| <a id="d-al-08"></a>`D-AL-08` | 本期预置角色 | `RO-AL-1` 运营管理员与 `RO-AL-2` 运营专员，作为建设方交付配置的角色。管理员拥有本期全部业务权限，专员按职责配置；两者均无产品内账号与授权管理能力 |
| <a id="d-al-09"></a>`D-AL-09` | 角色与权限项的关系 | 角色提供默认集合，建设方在交付时按矩阵配置。管理员固定拥有本期全部权限；专员固定拥有本人账户设置与协议操作记录查看，默认拥有消息查看、运营业务数据查询，其余可配置项按职责交付。协议历史读取仅管理员可有；维护 / 发布须配套当前内容查询 |
| <a id="d-al-10"></a>`D-AL-10` | 配置责任与产品边界 | 账号、角色绑定及初始授权由建设方交付配置；运营人员可查看本人角色，不展示权限清单，不能在产品内为自己或他人授权 |

权限的基本单位是功能权限项，区分可配置、固定开通与角色专属：固定开通或角色专属项不得按一般可选权限收回或扩给其他角色。矩阵里没有机构维度，不存在「本机构的」「其他机构的」这类过滤条件，也没有机构字段参与判定。权限项的业务规则定义权不在本模块——本模块定义「这是何种权限项、谁可有或固定有、获准后能访问哪些对象」，动作本身怎么算通过、怎么算驳回由对应业务模块定义。

### 3.1 初始账密交付与首登强制改密（F-AL-03）

适用角色与前提：全部运营账号。流程见 [FL-AL-02](02-运营端账户与登录-流程图与状态机.md#fl-al-02)。

<a id="d-al-15"></a>`D-AL-15`：建设方交付初始邮箱与密码；所有新账号首次登录必须进入 `P-O-AL-03`，完成改密后才能使用业务功能。这是唯一路径，无邀请或开通方式选择字段。初始密码按既有规则线下交付，产品不通过邮件或站内消息下发明文密码。

<a id="d-al-16"></a>`D-AL-16`：建设方交付全部初始账号并依据 [2.5 矩阵](#pm-default)配置角色和权限，是可登录使用的前提；产品无安装向导、自助初始化、账号维护界面。初始密码过期或无法自助找回时，只能由建设方 / 运维在数据层重新初始化——这是本期已知限制，不是运营管理员的产品操作。

**第一步 `P-O-AL-04` 提交工作邮箱**

### 3.5 设置密码的共同规则（D-AL-23）

适用于全部设置密码的入口：[首登强制改密](#f-al-03)、[忘记密码重置](#f-al-05)、[账户设置内修改密码](#f-al-08)。建设方交付的初始密码也须满足长度、复杂度和空格规则。

| 项 | 规则 |
| --- | --- |

| 复杂度 | 至少 1 个英文字母 + 1 个数字 |

| 判定归属 | <a id="e-al-08"></a>`E-AL-08`：提交时校验与原密码、初始密码不同，不符合则由服务端拒绝变更并给出对应提示，原密码不变，用户换一个新密码 |
| 明文 | 除本人在密码输入框主动切换显示外，界面、日志、邮件和站内消息均不得泄露明文密码；初始账密由建设方按线下交付约定提供 |

### 3.6 获取与重发邮箱验证码：滑块前置与发送限频（F-AL-13 之发码部分、D-AL-22）

<a id="d-al-22"></a>`D-AL-22`【用户已确认的强制要求】：忘记密码与本人修改邮箱的每次获取 / 重发邮箱验证码，均先完成 `C-O-AL-01` 滑块拼图校验，再检查发送限频，全部通过才发码。不能以之前通过、已登录或发送失败重试为由跳过；未通过、取消、加载失败、冷却中均不发码。直接依据资产可信平台《安全与风控》§12.3 与《验收标准》§18.11。共用流程见 [FL-AL-08](02-运营端账户与登录-流程图与状态机.md#fl-al-08)。

| 适用入口 | 发送目标 | 与业务流程的衔接 |
| --- | --- | --- |
| `P-O-AL-04` 忘记密码，含重发 | 当前工作邮箱 | 不新增验证码登录方式；验证码通过后才判定账号锁定 |
| `P-O-AL-06` 本人修改邮箱，含重发 | 此次填写的新邮箱 | 保留当前密码再认证和新邮箱校验；不要求旧邮箱验证码 |

| 环节 / 状态 | 产品行为与可验收结果 |
| --- | --- |
| 发起 | 验证码输入与获取 / 重发动作须同时可得，初始即可见；邮箱格式等前置校验通过后发起获取 / 重发即进入滑块拼图人机校验，尚不发码 |
| 校验中 | 用户须完成一次拼图对齐操作，释放后才判定；等待结果期间不能重复提交，不能凭拖动距离直接判定通过 |
| 通过 | 明确告知「验证通过 / Verified」并结束本次校验；随后检查发送限频，仅通过后才发码。滑块通过不等于邮件已发送 |
| 单次失败 | 提示「验证失败，请重试」并自动更换题目；本次校验不结束、不发码，可立即重新校验 |
| 连续失败 | 连续 3 次失败后提示可主动更换题目；连续 5 次失败进入 60 秒冷却（`N-AL-07`），校验不可发起并告知剩余时间；冷却中不能通过重新发起校验或刷新页面绕过限制，到期才可重新校验 |
| 关闭 / 取消 | 不发码，返回原办理上下文；获取 / 重发动作恢复可发起，已填邮箱和表单内容保留。再次获取仍须重新过滑块 |
| 题目加载失败 | 提示「加载失败，点击重试」，不发码、不告知验证通过，保留原表单；资源恢复后重新校验 |
| 结果适用范围 | 一次通过仅用于随后一次相同目标邮箱、相同发码用途及相同请求来源的发送，2 分钟内有效（`N-AL-13`）；已使用、过期或换邮箱 / 用途 / 来源均不能沿用。绕过界面发起发码也必须满足同样条件 |
| 获取、重发与发送失败重试 | 每次都重新通过滑块。邮件发送失败仍允许立即重试 1 次且不计发送额度，但该重试不免除滑块验证 |
| 发送限频 | 沿用 `N-AL-08` 的邮箱、网络 IP、设备额度；不同用途共享同一邮箱额度，不能通过换入口绕过。参考规则中设备识别不可用时不阻断发送，邮箱与网络限制仍适用 |
| 限频与发送结果 | 间隔未满时获取 / 重发不可发起并给出剩余时间；小时 / 日超限给出可读等待时长，网络 / 设备超限提示稍后重试，均不发码。发送成功后进入重发倒计时；刷新页面不能重置等待时间；提示不因邮箱是否已有账号变化 |
| 可访问性 | 全程键盘可达：可聚焦、可用键盘完成位移与提交；提供更换题目与求助入口。无障碍替代方案仍按本期已知限制处理（[`R-AL-03`](#risks)） |

异常与边界：<a id="e-al-09"></a>`E-AL-09` 滑块失败、取消、加载失败或冷却中均不发码，分别按上表更换题目、返回原表单、加载重试或冷却倒计时处理，用户在原入口重试或等待，不绕过滑块；<a id="e-al-10"></a>`E-AL-10` 限频超限不发码，提示稍后再试或剩余等待时间，提示不因该邮箱是否存在而变化；<a id="e-al-11"></a>`E-AL-11` 邮件发送失败可立即重试一次且不计入发送额度，重试仍重新验证滑块。

滑块失败冷却与密码错误导致的账号锁定是两种状态，不将滑块失败计入密码失败次数。本册只定义用户行为和安全结果，不展开坐标、轨迹算法、票据字段或接口实现；基线 `D-27` 的自研滑块及 §12.3.3 的校验约束继续适用，其呈现与反馈形式按[统一条款](#design-boundary)由设计决定。

<a id="f-al-19"></a>
### 3.9 本人修改工作邮箱（F-AL-19）

<a id="d-al-25"></a>`D-AL-25`：允许本人修改为用户已确认，入口在账户设置；其中获取验证码前必须过滑块也是用户已确认要求。其余校验衔接沿用可调整的默认口径：当前密码再认证 → 填新邮箱 → 每次获取码先过滑块及限频，向新邮箱发送验证码 → 校验通过且本运营端内唯一后生效 → 向新旧邮箱发送安全通知。新邮箱生效后作为登录账号、找回密码与安全通知地址；失败或取消时旧邮箱继续有效。流程见 [FL-AL-07](02-运营端账户与登录-流程图与状态机.md#fl-al-07)。

| 项 | 产品行为 |
| --- | --- |
| 角色与前置 | 两个运营角色均可在本人账户设置中修改；账号须正常且已完成首登改密，仅能修改本人的邮箱 |
| 入口与顺序 | 在账户设置的工作邮箱项发起「修改」→ 验证当前密码 → 填写新邮箱 → 发起获取 / 重发验证码 → 滑块拼图人机校验（每次均按 [3.6](#f-al-13a)）→ 发送限频校验 → 向新邮箱发验证码 → 输入验证码并提交；在本次办理内完成，不再叠加下一层办理 |
| 再认证 | 当前密码输错计入既有登录失败计数，达到阈值按既有阶梯锁定；再认证有效期沿用 `N-AL-10`，过期需重新验证，不能继续提交邮箱修改 |
| 新邮箱 | 邮箱格式、长度、去空格、大小写不敏感沿用 [2.3](#2-3-运营账号的业务字段)；不得与当前邮箱相同，须在本运营端内唯一。格式错误、相同或不可用时给出对应提示；不可用提示不暴露占用账号身份或状态 |
| 新邮箱验证 | 验证码只发往此次新邮箱，不要求旧邮箱收码。验证码规则、有效期、错误次数、滑块人机校验与限频均沿用既有参数；与找回密码的验证码不可混用。更换新邮箱后，原目标的验证码不可用于新目标 |
| 生效条件 | 当前再认证仍有效、验证码属于本人本次新邮箱修改且校验通过、账号仍正常、新邮箱在提交时仍唯一，全部满足才生效；期间被其他账号占用则拒绝变更并提示该邮箱不可用 |
| 成功结果 | 显示成功提示，账户设置及账号入口更新为新邮箱；之后仅新邮箱可用于本账号登录、找回与接收安全通知，旧邮箱不再是本账号登录或找回地址。账号身份、姓名、角色、权限及偏好保持原值 |
| 当前登录与旧验证码 | 默认保留现有登录状态，不因仅修改邮箱额外退出；发往旧邮箱但尚未使用的找回验证码失效，后续找回只认新邮箱；旧邮箱提交找回仍返回统一中性提示 |
| 安全通知 | 生效后向新旧邮箱各发一封安全通知，见 [3.14](#f-al-18) 与[消息通知册](03-运营端账户与登录-消息通知.md#nt-al-02) |
| 未成功 | <a id="e-al-18"></a>`E-AL-18`：验证码错误 / 过期 / 超过错误上限，账号锁定、再认证失效、发送失败、取消或未完成流程时，邮箱保持原值，不得提示修改成功；密码错误仍计入既有锁定规则。用户可按对应错误重新验证、填写其他邮箱或按限频重试 |
| 会话失效 | 操作期间登录失效时返回登录页，未生效的修改不保留为已完成；重新登录后重新发起修改 |
| 已知限制 | 旧邮箱不可达但仍能正常登录、完成当前密码验证时可自助换邮箱；密码丢失且当前邮箱不可达时，只能由建设方 / 运维重新初始化，无产品内他人改密或改邮箱入口 |

### 3.10 界面语言与时区偏好（F-AL-10、F-AL-11）

规则正文在三平台共享国际化基线（[`D-AL-18`](#d-al-18)），本节定义本模块的可观察行为。

| 项 | 产品行为 |
| --- | --- |
| 默认语言 | 界面默认英文，不读浏览器语言；语言切换（`C-O-AL-02`）在未登录与已登录状态下均须可得 |
| 切换即时生效 | 当前页面不刷新即完成全部文案替换，含各级功能入口、层级路径、轻提示、办理过程与倒计时；已填表单内容不丢失 |
| 偏好持久化 | 未登录态与已登录态双态持久化：未登录切换后关闭浏览器重开仍生效，已登录切换后换设备登录仍生效；退出登录后本地语言偏好保留 |
| 时区写入 | 首次登录成功时按浏览器推断并写入时区偏好，推断失败兜底 UTC；本人可在账户设置内改 |
| 时间展示 | 时间存 UTC；界面所有时间点按本人时区偏好展示并带时区标注 |
| 文案要求 | 无未翻译的硬编码文案；缺失翻译回落英文而非显示文案键名；中英两种语言下按钮与标签均不截断；角色称谓按 [`D-AL-30`](#d-al-30) |
| 通知 | 语言与时区偏好变更不产生任何通知（[`D-AL-27`](03-运营端账户与登录-消息通知.md#d-al-27)） |

<a id="f-al-12"></a>
### 3.11 会话有效期、无操作登出与全局失效（F-AL-12）

| 编号 | 口径 | 结论 |
| --- | --- | --- |
| <a id="d-al-19"></a>`D-AL-19` | 会话 | 会话有效期与无操作自动登出沿用基线管理端口径（`N-AL-09`）；不提供「记住我」；到期前给出续期确认，可选择继续保持登录或立即退出 |
| <a id="d-al-20"></a>`D-AL-20` | 会话全局失效 | 退出登录、本人修改密码、重置密码、完成首登强制改密，该账号的全部会话（含当前设备）立即失效 |

| 项 | 产品行为 |
| --- | --- |
| 建立 | 登录成功时建立；待首登改密账号首登时建立的是受限会话，只能完成改密、退出登录与切换语言 |
| 「用户操作」的判定 | 只有真实的用户交互（点击、键盘输入、表单提交、导航跳转）才重置无操作计时；后台轮询、心跳、预取一律不计，否则无操作登出永远不会触发 |
| 失效范围 | 该账号的全部会话（含当前设备）；未使用的验证码与滑块人机校验凭据一并失效 |
| 失效后的表现 | <a id="e-al-16"></a>`E-AL-16`：停止受保护操作（语言偏好保留）、以轻提示告知原因、回到登录入口并记住原目标；同一浏览器多标签页一并失效，用户重新登录 |
| 后台请求遇到失效 | 与前台请求一视同仁触发统一的失效处理，不得静默忽略，避免「界面仍可操作、登录态已无」的假活状态 |
| 邮箱修改 | 默认保留现有会话，不因仅修改邮箱额外退出（[3.9](#f-al-19)） |

<a id="f-al-13b"></a>
### 3.12 失败计数与阶梯锁定（F-AL-13 之锁定部分）

<a id="d-al-21"></a>`D-AL-21`：连续密码校验失败达阈值后账号锁定，锁定期间登录与忘记密码全部不可用，无提前解除通道，到期自动解除；锁定时长按阶梯递进。

| 项 | 产品行为 |
| --- | --- |
| 计数范围 | 登录页密码错误与账户设置内当前密码再认证失败共用同一计数器；滑块失败不计入密码失败次数 |
| 提示 | 失败次数达 `N-AL-05` 后开始提示剩余次数；第一档锁定的提示中告知再次触发时间会更长 |
| 锁定阶梯 | 锁定时长按 `N-AL-02` 阶梯递进；距上次触发满归零窗口后回到第一档 |
| 锁定表现 | <a id="e-al-02"></a>`E-AL-02`：账号锁定后登录与找回全通道不可用；登录页内展示剩余时间并实时倒计时，归零后表单自动恢复可用、无需刷新。用户只能等待锁定到期 |
| 锁定与找回 | 锁定账号仍可收到找回验证码邮件，但验证码正确后被告知锁定与剩余时间，流程终止（[3.4](#f-al-05)） |
| 通知 | 账号锁定与自动解除均不发通知（[`D-AL-27`](03-运营端账户与登录-消息通知.md#d-al-27)），由当事人从登录提示感知，并保留安全留痕 |

<a id="f-al-17"></a>
### 3.13 按权限收敛入口与协议读取边界（F-AL-17）

适用角色与前提：全部已登录运营账号。组织方式与矩阵见 [2.5](#pm-matrix)，读取路径见 [FL-AL-09](02-运营端账户与登录-流程图与状态机.md#fl-al-09)。

| 规则 | 口径 |
| --- | --- |
| 配置责任 | 建设方交付账号、角色绑定和初始授权；运营人员可查看本人角色，不展示权限清单。产品无新增账号、授权调整、停用 / 启用或他人改密入口 |
| 界面与动作一致 | 未授权功能入口不出现，绕过界面发起相同动作仍被拒绝 |
| 越权表现 | <a id="e-al-15"></a>`E-AL-15`：统一提示无权限，不透露该功能下是否存在具体业务记录；配置问题联系建设方核对交付结果 |
| 状态前提 | 仅正常账号的业务权限生效；待首登改密、锁定状态不可执行业务动作，即使此前已被授权 |
| 角色差异 | 管理员固定具有本期全部业务权限；专员固定有本人设置及协议操作记录，其他按 [2.5 默认授权](#pm-default) 配置且不得获得协议历史权；账号管理权限不属于本期任一角色 |
| 入口可达 | 同一业务模块有部分可读能力时应能到达该能力；不得因缺少协议内容查询权隐藏全部协议记录入口。可达方式由设计决定，不借入口开放其他动作 |
| 非法配置 | 专员误配历史读取仍不得读取；维护 / 发布缺必要查询时不得执行。交付由建设方核对修正，不新增运营人员自助授权 |
| 数据可见范围 | 同一主体不按机构隔离（[`D-AL-05`](#d-al-05)）；在该权限和业务对象允许范围内查询，不自动获得其他权限下的数据。协议记录全员可读不等于协议历史全员可读，也不扩大私人档案或本人安全消息范围 |
| 不存在的过滤 | 「只看与本机构相关的项目」「只看本人负责的申请」「按机构切分的数据域」本期均不存在，也不预留机构字段（[`D-AL-06`](#d-al-06)） |
| 与面客端的关系 | 运营人员仅查看其职责已明确允许的业务信息，不因同主体取得面客私人档案或付款资料，也不能以运营身份代替资产方 / 资金方办理。面客公开协议的读取沿来源业务规则，不使用运营管理授权 |

<a id="d-al-33"></a>`D-AL-33`【协议读取边界】：历史版本及下线前旧版本仅 `RO-AL-1` 运营管理员可读；协议操作记录由本运营端全员（`RO-AL-1`、`RO-AL-2`）查看。全员仍须正常账号、完成首登改密且登录有效，不包括面客或其他平台账号。记录可读不授予历史文件、当前内容、维护或发布权限。依据 WS-346 用户 P12；SPV 沿同一角色体系，不扩大到面客人员、游客或其他平台运营人员。

| 阅读对象 / 场景 | 权限及可观察结果 |
| --- | --- |
| 当前内容、草稿和待生效工作版本 | 按 `PM-AL-09` 查询；业务状态是否仍允许办理，由 WS-384 判定。历史列表不能因夹有工作版本而全部对专员开放 |
| 历史版本与下线前旧版本 | 仅管理员具 `PM-AL-15` 可查看内容、预览和读取文件；专员即使已有查询、维护、发布权限也不可读。协议下线或重新上线不将旧内容改为普通当前内容，不能借记录链接或旧地址绕过 |
| 协议操作记录 | `PM-AL-16` 固定向两角色开放；不要求 `PM-AL-09`，不按本人经办或所属机构过滤。操作类型、时间、当时操作者、版本标识及结果等已定义记录信息可读；记录字段与历史身份呈现按运营端协议管理现行正文 |
| 从记录、消息进入版本 | 记录或消息本身可读，不代表目标可读；跳转当前工作版本核验 `PM-AL-09`，跳转历史核验管理员历史权。无权时不展示内容、预览或文件，给出可理解提示并可返回原记录 / 消息；不能把正文或附件复制进记录绕过权限 |
| 下线、重新上线及旧记录 | 旧历史与操作记录的权限分别保持，不因重新上线继承旧协议的当前内容或发布计划；下线取消、重新上线独立及旧记录定位的完整业务流程由 WS-384 接续，本册不恢复版本回溯动作 |
| 身份与消息 | 操作记录「全员可看」不等于全员收信，也不扩大本人密码 / 邮箱安全通知收件人；SPV 同运营不产生资金动作、私人资料或面客消息抄送权 |

**交接 WS-384**：其现行正文中操作记录权限及维护 / 发布配套查询的旧待决口径，以本册矩阵收口；历史、旧文件、记录与消息目标应分别应用权限。其余版本业务规则仍由该模块修订，本册不改写其文件，也不代定承载形式。

<a id="f-al-18"></a>
### 3.14 账户安全通知（F-AL-18）

本模块只定义发什么、何时发；站内消息的承载、未读语义与可见范围归 WS-383。完整事件定义、收件范围、文案要素与异常见[消息通知册](03-运营端账户与登录-消息通知.md)。

| 事件 | 触发时点与收件范围 |
| --- | --- |
| [密码变更通知](03-运营端账户与登录-消息通知.md#nt-al-01) | 首登强制改密、忘记密码重置、账户设置内本人改密三种情形均触发；邮件与站内消息告知本人，触发时点为新密码生效之后、会话批量失效之前 |
| [邮箱变更安全通知](03-运营端账户与登录-消息通知.md#nt-al-02) | 本人修改工作邮箱生效后，向新旧地址各发一封安全通知邮件；投递失败不回滚已生效的修改 |
| [账户功能邮件（验证码）](03-运营端账户与登录-消息通知.md#nt-al-03) | 找回验证码发往当前工作邮箱，修改邮箱验证码发往新邮箱；文案中性，不透露账号信息，无一键登录链接，验证码不出现在邮件主题与预览文本中 |

通知不含密码或验证码原文以外的账号信息；账号锁定、自动解锁、登录成功 / 失败、语言与时区偏好变更均不发通知。<a id="e-al-19"></a>`E-AL-19`：邮箱修改后新或旧地址的安全邮件投递失败，不回滚已生效邮箱、不误报验证失败；与「验证邮件未完成验证则不得生效」是两件事，已生效的新邮箱继续作为登录与找回地址。

<a id="overview-shell"></a>
### 3.15 运营端总览页壳子（`P-O-AL-07`）

登录成功后的默认落地目标。本模块只提供落地壳子与简短说明文字（而非无任何信息），不预先编造业务内容、统计数字或待办对象；内容由后续业务模块补入，功能入口沿用管理端共享导航信息。是否作为共享导航中的独立条目不由本册预定。

<a id="4-验收需求"></a>
## 4. 验收需求

与第 3 节同序。每条验收映射到对应功能，与功能正文冲突时以功能正文为准；本节给出业务行为与可观察结果，不含测试执行步骤与用例数据。

**全章适用的业务前提**：运营管理平台是独立部署单元；运营账号与代币发行平台运营端、借贷面客端均不共用；SPV 机构与运营机构是同一家主体，运营端只有一套账号体系、不做机构级数据隔离。

### 4.5 设置密码的共同规则（关联 [3.5](#d-al-23)；适用 [3.1](#f-al-03)、[3.4](#f-al-05)、[3.8](#f-al-08) 三个入口）

| 场景与前提 | 应观察到的结果 | 验收定位 |
| --- | --- | --- |
| 输入长度不足 8 或超过 20 的密码 | 被拒绝 | `AC-AL-36` |
| 输入仅字母或仅数字的密码 | 被拒绝（须至少 1 字母 + 1 数字） | `AC-AL-37` |
| 密码前后带空格 / 中间带空格 | 前后自动去除；中间不被接受 | `AC-AL-38` |
| 输入新密码及确认密码 | 各项密码规则是否满足实时可见；两次密码不一致时在确认密码处提示并阻止提交，改为一致后清除错误；不表达强弱分档 | `AC-AL-39` |
| 新密码与原密码或初始密码相同 | 提交后被拒绝并给出对应提示，原密码不变 | `AC-AL-40` |
| 检查密码展示 | 除本人主动切换密码输入框显示外，界面、日志、邮件与站内消息均不泄露明文密码；初始账密按线下交付约定提供 | `AC-AL-41` |

### 4.6 获取与重发邮箱验证码（关联 [3.6](#f-al-13a)）

两入口均须覆盖：`P-O-AL-04` 忘记密码、`P-O-AL-06` 修改邮箱；首次获取、重发和邮件发送失败后的重试均适用。

| 场景与前提 | 应观察到的结果 | 验收定位 |
| --- | --- | --- |
| 发起获取 / 重发，完成拼图对齐并释放 | 未通过前不发码；对齐并通过后明确告知验证通过、结束本次校验，然后检查限频；拖到末端本身不代表通过 | `AC-AL-122` |
| 单次失败，继而连续失败达到提示及冷却阈值 | 单次失败给出失败反馈并自动更换题目，本次校验不结束；连续 3 次提示可主动更换题目，5 次进入 60 秒冷却，校验不可发起并倒计时；刷新或重新发起不能绕过，到期才可重新校验 | `AC-AL-123` |
| 验证前取消滑块校验 | 不发码，返回原办理上下文，保留已填内容、获取 / 重发恢复可发起；再次发起仍需滑块 | `AC-AL-124` |
| 校验题目加载失败 | 明确提示加载失败并可重试，不发码、不告知通过；原表单仍保留 | `AC-AL-125` |
| 无有效通过结果、已使用或超过有效期后发码，或换目标邮箱 / 用途 / 请求来源 | 均被拒绝，重新验证后才能按新目标 / 用途发码；每次获取与重发仅可使用本次有效通过结果，不能绕过界面限制 | `AC-AL-126` |
| 滑块通过，但邮箱 / 网络 / 设备发送限频超限 | 不发码；间隔以剩余时间表达，小时 / 日超限为可读等待时长，网络 / 设备超限提示稍后再试；刷新后等待仍准确，提示不区分邮箱是否已有账号 | `AC-AL-127` |
| 同一目标邮箱在不同用途间切换获取码 | 仍共享同一邮箱发送额度，不能多得一次额度或跳过滑块；设备识别不可用时不阻断发码，其他限频条件仍须满足 | `AC-AL-128` |
| 滑块通过后邮件发送失败，再次获取 | 允许立即重试一次且不计发送额度，但仍须重新过滑块；成功才进入发送成功 / 重发倒计时状态 | `AC-AL-129` |
| 键盘使用滑块与求助 | 全程键盘可达：可聚焦、可位移、可提交；更换题目和求助入口可达，中英文的通过、失败、冷却及加载异常提示一致 | `AC-AL-130` |
| 滑块失败、邮箱验证码输错及锁定账号找回 | 滑块失败走自身冷却、验证码错误走单码上限，不计入密码失败次数；找回仍仅在验证码正确后告知锁定，不能将滑块提前校验变成账号枚举提示 | `AC-AL-131` |

<a id="ac-9"></a>
### 4.9 本人修改工作邮箱（关联 [3.9](#f-al-19)）

获取新邮箱验证码前先过滑块为用户已确认要求；其余衔接按 [3.9](#f-al-19) 既有默认口径验收。「允许本人修改」不是待确认项。

| 场景与前提 | 应观察到的结果 | 验收定位 |
| --- | --- | --- |
| 两个运营角色查看本人账户设置 | 均可发起本人邮箱修改，无修改他人邮箱入口；每次获取新邮箱验证码必须过滑块 | `AC-AL-44` |
| 正常且已完成首登改密的本人，当前密码正确 | 再认证通过后可填新邮箱；密码错误计入既有失败次数，达阈值锁定；再认证过期必须重新验证 | `AC-AL-111` |
| 新邮箱格式错误、超过 254 字符、等于原邮箱或被占用 | 不变更邮箱；按去除前后空格、大小写不敏感后的值校验；提示占用时不泄露其他账号身份 / 状态 | `AC-AL-112` |
| 在修改邮箱办理中获取或重发新邮箱验证码 | 验证码输入与获取动作同时可得；每次先过滑块再检查限频，仅向新邮箱发码；不要求旧邮箱码；连续失败、取消、冷却等共用规则见 [4.6](#ac-6) | `AC-AL-113` |
| 使用错误、过期、超限、已使用、旧目标邮箱或其他用途的验证码 | 不生效，旧邮箱仍有效；同用途重发后旧码不可用；可在既有限频约束下重试 | `AC-AL-114` |
| 验证码正确，提交时新邮箱被其他账号占用 / 再认证失效 / 账号锁定 | 拒绝修改，邮箱仍为旧值；按具体原因提示重新验证、等待或换邮箱 | `AC-AL-115` |
| 新邮箱验证及所有条件通过后提交 | 账户设置和账号入口显示新邮箱；新邮箱可登录与找回，旧邮箱不再作为本账号入口；身份、角色、权限、姓名、偏好不变；默认保留已有登录状态 | `AC-AL-116` |
| 修改邮箱生效后，使用旧邮箱未完成的找回验证码 | 旧码不能重置该账号密码；新发找回码只投递当前新邮箱；以旧邮箱提交找回仍得到统一中性提示 | `AC-AL-117` |

| `DEP-AL-08` | 来源通知与后续汇总 | 沿 WS-379 [《03-面客消息中心-消息通知》](../v1.0-面客消息中心/03-面客消息中心-消息通知.md)现行正文（本轮已核对，同题待决项在该册延续）。收件责任 `Q-LS-N01`、真实公共客服邮箱、数币精度 / 尾差和资料规则、共享登记 / 分类与可选通知清单仍由来源补齐；`Q-NC-04` 的 60 秒 / 5 分钟时效冲突及真实投递验收未完成。当前只承接依赖，不重开来源 / 控制台队列，不把其面客收件范围扩大到运营端；WS-383 及全模块最终核对在后续串行阶段完成 |

### 5.2 风险

| 编号 | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| `R-AL-01` | 未完成初始账号交付配置 | 运营人员无法登录或权限不匹配 | 建设方交付时核对邮箱、角色和权限矩阵，无产品安装向导 |
| `R-AL-02` | 任何运营人员密码丢失且邮箱不可达，或初始密码已过期 | 无法自助恢复，本期无账号管理与他人改密入口 | 只能由平台建设方 / 运维在数据层重新初始化；重新交付后仍须首登改密。此人工依赖为本期已知限制，不可用于提前解除锁定 |
| `R-AL-03` | 依赖读屏的运营人员无法自助找回 | 滑块人机校验无替代渠道 | 支持键盘操作并提供求助入口，无法自助时由建设方 / 运维重新初始化，本期不提供产品内他人代办 |
| `R-AL-04` | 锁定可被用于骚扰 | 知道工作邮箱者可连续尝试错误密码触发锁定 | 沿用阶梯锁定、无提前解锁通道；不对外公开运营账号信息 |
| `R-AL-05` | 锁定时无外部通知 | 当事人从登录提示感知 | 保持既有不通知规则与安全留痕，观测 `M-AL-05` |
| `R-AL-06` | 权限粒度与业务模块定稿不一致 | 交付配置与业务动作不对应 | 按各模块定稿校对权限矩阵，不增设授权界面 |
| `R-AL-07` | 主体将来分家 | 需要机构维度时本期设计不支持 | 需求方已确认本期不预先设计（[`D-AL-06`](#d-al-06)）；届时按「多机构 / 租户」独立立项 |
| `R-AL-08` | 共享国际化基线尚未落盘 | 本模块的语言、时区与脱敏口径暂无可引用的库内地址 | 事实源明确（参考基线原文），内容不变；落盘后只需替换引用路径（[`Q-AL-01`](#q-al-01)） |

### 5.5 术语

| 术语 | 口径 |
| --- | --- |
