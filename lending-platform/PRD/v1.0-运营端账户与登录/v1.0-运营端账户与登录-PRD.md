## 3. 背景与目标

### 3.1 背景

三平台重划分后，借贷平台分为**面客端**与**运营管理平台（管理端）**两个相互独立部署的单元。运营管理平台承接的是需要平台侧人工介入的全部动作：资金方机构认证审核、代币质押审核、协议管理、运营端消息通知等（分别归 WS-358、WS-359、WS-361、WS-360）。这些模块都要回答同一个前置问题——**谁能进来、进来以后能做哪些动作**。本模块就是这个前置：运营端的账号体系、登录与权限。

WS-357 原描述把运营端列为「运营人员 + SPV 机构」两类角色，并把 SPV 的定位、准入与权限口径列为阻塞项。**需求方 2026-09-18 已裁定：SPV 机构与运营机构默认是同一家主体。** 因此本模块不再按「两类租户」设计，而是**一套运营账号体系 + 一张按功能权限组织的矩阵**：SPV 相关职责作为职能落在运营人员的功能权限项上，不另起一类账号，也不做机构级数据隔离。

### 3.2 产品定位

| 项 | 口径 |
| --- | --- |
| 一句话 | 运营管理平台的**唯一入口与授权底座**：谁能登录、以什么身份登录、登录后能执行哪些运营动作 |
| 主对象 | **运营账号**（一个自然人一个账号），不是机构、不是租户 |
| 账号来源 | **平台创建 / 邀请开通**，**不设机构自注册入口**（`D-AL-04`） |
| 数据可见范围 | **同一主体，运营端数据全量可见**；不做「只看本机构相关项目」的机构级隔离（`D-AL-05`） |
| 权限组织方式 | **按功能权限组织**：各审核、配置、查询动作各自成为一个可授权项，按角色与逐项授权开通（`D-AL-07`） |
| 与代币发行平台运营端的关系 | **两套账号、两个部署单元，互不相通**（`D-AL-02`） |
| 产品形态 | 控制台画布形态（固定侧栏 + 紧凑顶栏 + 高密度表格），桌面优先，沿用本平台管理端设计规范 |
| 页面数 | **9**：登录、开通设置密码、首登强制改密、忘记密码两步、账户设置、总览页壳子、账号列表、账号详情与授权 |

### 3.3 本期目标

| # | 目标 | 达成口径 |
| --- | --- | --- |
| `G-AL-1` | 运营人员能安全地拿到账号并上岗，全程不出现明文初始密码在线下发 | 邀请开通为默认方式（`F-AL-02`）；初始密码开通为备选且强制首登改密（`F-AL-03`） |
| `G-AL-2` | 运营端只有一套账号体系，来源可控、无自助注册 | `D-AL-03`、`D-AL-04`；界面无注册入口（`AC-AL-11`） |

## 4. 范围

### 4.1 本期做（含）

- 运营账号的开通方式：**邀请开通**（默认）与**初始密码开通**（备选），两种方式收敛到同一套账号状态
- 工作邮箱 + 密码登录；登录失败提示、阶梯锁定与锁定态展示
- 忘记密码两步找回（提交工作邮箱 → 人机校验 → 验证码 → 设置新密码）
- 账户设置：账号信息查看、修改本人密码、界面语言与时区偏好
- **账号与权限管理**：创建 / 邀请账号、停用与启用、分配预置角色、逐项授权功能权限、重置他人账号的开通凭据
- **功能权限矩阵**：覆盖本模块与已规划的运营业务模块（L4 / L11 / L14 / L15）的可授权动作
- 会话有效期、无操作登出、会话全局失效
- 密码变更类通知的**发什么、何时发**（展示形态归 WS-360）
- 总览页壳子，作为登录成功后的落地目标

## 5. 硬口径与红线

> 本章是全模块规则的收口处。**分册 01 的详细规则、分册 02 的验收条款、图册 的图示，一律以本章为准**；出现表述不一致时以本章条款回溯。

### 5.1 主体、账号与数据可见范围（本轮新增口径）

| 编号 | 口径 | 结论 | 来源 |
| --- | --- | --- | --- |
| `D-AL-02` | **部署边界与账号归属** | 运营管理平台是**独立部署单元**；运营账号**与代币发行平台运营端不共用**，不做跨平台单点登录，不做账号同步 | WS-357 描述（重构要点） |
| `D-AL-03` | **SPV 与运营机构的关系** | **默认是同一家主体**。运营端不存在第二类机构身份，不按机构切分账号、菜单或数据 | **需求方 2026-09-18 确认** |
| `D-AL-04` | **账号来源** | **只有一套运营账号体系**，账号由**平台创建或邀请开通**；**不设机构自注册入口**，界面上不存在注册、入驻、申请开通类入口 | **需求方 2026-09-18 确认** |
| `D-AL-05` | **数据可见范围** | **不做机构级数据隔离**：同一主体下运营端数据全量可见，不存在「SPV 只看与本机构相关的项目」这类过滤。**看得到什么由功能权限决定，不由机构归属决定** | **需求方 2026-09-18 确认** |
| `D-AL-06` | **主体分家的边界说明** | 主体后续若分家（SPV 独立为另一家法律主体），届时按「多机构 / 租户」独立立项处理，**本期不为此预先设计租户隔离、机构维度字段或数据域切分机制**。本条只作边界说明，不产生任何本期设计要求 | **需求方 2026-09-18 确认** |
| `D-AL-07` | **权限组织方式** | 权限**按功能权限组织**：每个审核、配置、查询动作是一个独立的可授权项（`PM-AL-*`），按「角色 → 功能权限项」授权，**不按机构维度切数据** | **需求方 2026-09-18 确认** |

### 5.2 角色与授权

| 编号 | 口径 | 结论 |
| --- | --- | --- |
| `D-AL-08` | **本期预置角色** | 两个：`RO-AL-1` 运营管理员、`RO-AL-2` 运营专员。**真实差异只有一条——是否掌握账号与授权**；除此之外的分工一律通过功能权限项逐项授权表达，不再造权限雷同的空壳角色（沿用基线 `D-O02` 的做法） |
| `D-AL-09` | **角色与权限项的关系** | 角色是功能权限项的**默认集合**，不是权限的唯一来源。运营管理员固定拥有全部权限项；运营专员的权限项**逐项授权**，默认只有本人账户设置与消息查看 |
| `D-AL-10` | **授权动作的唯一入口** | 只有运营管理员可以创建 / 邀请账号、停用启用账号、分配角色、授权或收回功能权限项（`PM-AL-01`～`PM-AL-03`）。**运营专员不能给自己或他人授权** |
| `D-AL-11` | **授权变更的生效时点** | 授权或收回**立即生效**：被调整人在下一次操作时即按新权限判定，不必等待重新登录；被收回权限的入口从菜单与页面上消失，绕过界面直接发起该动作同样被拒绝 |
| `D-AL-12` | **最后一个运营管理员保护** | **不允许**把系统内最后一个处于「正常」状态的运营管理员停用、降级或收回其账号与权限管理权限；界面给出明确拒绝提示。（基线中该规则不适用，是因为基线不做账号管理界面；本期做了，就必须有这条不变量） |
| `D-AL-13` | **SPV 职责的落法** | SPV 相关职责按职能落在运营人员的功能权限项上：现阶段已规划的运营动作（认证审核、质押审核、协议管理、消息查看、业务查询）即为其可授权范围。**当前没有任何 SPV 专属动作被任何模块定义**，本模块不臆造；后续若产生，按 `PM-AL-*` 段位扩展，**不新增账号类型、不引入机构维度**（`Q-AL-02`） |

### 5.3 登录、开通与安全（沿用基线，按独立部署收口）

| 编号 | 口径 | 结论 |
| --- | --- | --- |
| `D-AL-14` | **登录方式** | **工作邮箱 + 密码，唯一方式**。无验证码登录、无钱包登录、无第三方登录、无自动建号、无协议勾选、无「记住我」 |
| `D-AL-15` | **账号开通** | 默认走**邀请开通**：平台创建账号后向工作邮箱发出开通邀请，本人自行设置密码后账号转为正常，**系统不在任何在线渠道下发明文密码**。备选的**初始密码开通**由平台线下交付初始密码，**首次登录强制改密**后才能使用其他功能 |
| `D-AL-16` | **首个账号** | 由部署初始化写入，「初始化第一个运营管理员账号」是**部署前置条件**。运营端**不提供任何绕过登录的首次配置页或安装向导**；未执行则无人可登录，且系统不提供自救入口 |

| `D-AL-21` | **锁定** | 连续密码校验失败达阈值后账号锁定，**锁定期间登录与忘记密码全部不可用**，无提前解除通道，到期自动解除；锁定时长按阶梯递进 |

| `D-AL-23` | **密码规则** | 8～20 字符，至少 1 个英文字母 + 1 个数字；前后空格自动去除、中间不接受空格；**不得与原密码相同**，也**不得与平台发放的初始密码相同** |
| `D-AL-24` | **账号信息字段** | 本期为工作邮箱、姓名、角色、功能权限、账号状态五项，**不扩充部门、岗位等组织字段** |
| `D-AL-25` | **工作邮箱只读** | 工作邮箱即登录账号，本人**不可自助修改**；界面无修改入口，绕过界面发起修改同样被拒绝。确需变更时由运营管理员停用原账号、另行开通 |

## 6. 业务角色与场景

### 6.1 业务角色

| 角色 | 描述 | 在本模块内的核心诉求 |
| --- | --- | --- |
| **运营管理员**（`RO-AL-1`） | 运营机构（即 SPV 主体）内负责账号与授权的人。拥有全部功能权限 | 给新同事开通账号、按职责授权、人走时立刻停用；自己也能正常登录与改密 |
| **运营专员**（`RO-AL-2`） | 运营机构内执行具体运营动作的人：认证审核、质押审核、协议维护、业务查询。**SPV 相关职责由该角色按功能权限承担** | 拿到邀请后顺利上岗；只看到自己被授权的入口；忘记密码能自助找回 |
| 平台部署 / 运维 | 负责首个运营管理员账号的初始化与发信配置 | 有明确的部署前置清单可依循 |
| 非中文运营成员 | 运营团队中不使用中文的成员 | 打开就是英文，不必先找语言开关 |

> **为什么只预置两个角色**（`D-AL-08`）：运营端真实存在的角色差异只有一条——**是否掌握账号与授权**。审核、配置、查询这些动作之间的分工，是同一类人不同的职责范围，用功能权限项逐项授权表达即可，硬造三五个角色只会得到几个权限雷同的空壳，而每新增一类业务动作又要回改角色定义。这是基线在单角色情形下采用的同一条思路：**权限按能力组织，角色只承担默认集合**。

> **SPV 职责在哪里**（`D-AL-13`）：需求方已确认 SPV 与运营机构是同一家主体，因此 SPV 不是一类账号，而是一组职责。这组职责当前对应的可授权动作，就是第 8 章功能目录与分册 01 第 10 章矩阵里已登记的运营动作。**现阶段没有任何模块定义过 SPV 专属的业务动作**，本册不替它们编造；将来出现时按 `PM-AL-*` 扩展一项即可，账号体系与数据可见范围都不需要改。

## 7. 业务流程说明

> 全部流程图与状态机集中在分册 [`v1.0-运营端账户与登录-流程图与状态机.md`](v1.0-运营端账户与登录-流程图与状态机.md)。本节保留业务说明与关键分支，图号一一对应；规则细节在分册 01。

| 图号 | 名称 | 业务说明 |
| --- | --- | --- |
| `FL-AL-01` | 账号开通（邀请方式） | 运营管理员创建账号并选择角色与功能权限 → 系统向工作邮箱发出开通邀请 → 本人打开邀请、设置本人密码 → 账号从**待开通**转为**正常** → 可正常登录。邀请在有效期内未完成可由运营管理员重发；重发后旧邀请立即失效 |
| `FL-AL-02` | 账号开通（初始密码方式） | 运营管理员创建账号并标记为初始密码开通 → 初始密码**线下交付**本人 → 本人首次登录被强制进入改密页 → 改密成功后账号转为**正常**，全部会话失效并要求重新登录 |
| `FL-AL-03` | 日常登录 | 工作邮箱 + 密码 → 凭据校验 → 账号状态判定：**待开通**（初始密码方式）进改密页、**正常**进总览页、**锁定**在登录页内展示锁定提示与剩余时间、**停用**提示联系运营管理员。连续失败达阈值触发锁定 |
| `FL-AL-04` | 忘记密码 | 登录页进入 → 提交工作邮箱 → 人机校验 → 发送限频校验 → 发送验证码 → 输入验证码 → **验证码通过后才做锁定判定**（锁定则终止并告知剩余时间）→ 设置新密码 → 全部会话失效 → 回到登录页。全程不透露该邮箱是否为有效账号 |
| `FL-AL-05` | 账号与权限授权 | 运营管理员进入账号列表 → 打开某账号 → 调整角色或逐项勾选功能权限 → 保存 → **立即生效**。涉及最后一个运营管理员的降级、停用或权限收回被拒绝 |
| `FL-AL-06` | 本人修改密码 | 账户设置内发起 → 再认证当前密码 → 设置新密码（不得与原密码、初始密码相同）→ 保存成功 → 全部会话失效 → 回到登录页重新登录 |
