## 3. 背景与目标

### 3.1 背景

三平台重划分后，借贷平台分为**面客端**与**运营管理平台（管理端）**两个相互独立部署的单元。运营管理平台承接的是需要平台侧人工介入的全部动作：资金方机构认证审核、代币质押审核、协议管理、运营端消息通知等（分别归 WS-358、WS-359、WS-361、WS-360）。这些模块都要回答同一个前置问题——**谁能进来、进来以后能做哪些动作**。本模块就是这个前置：运营端的账号体系、登录与权限。

WS-357 原描述把运营端列为「运营人员 + SPV 机构」两类角色，并把 SPV 的定位、准入与权限口径列为阻塞项。**需求方 2026-09-18 已裁定：SPV 机构与运营机构默认是同一家主体。** 因此本模块不再按「两类租户」设计，而是**一套运营账号体系 + 一张按功能权限组织的矩阵**：SPV 相关职责作为职能落在运营人员的功能权限项上，不另起一类账号，也不做机构级数据隔离。

### 3.2 产品定位

| 项 | 口径 |
| --- | --- |
| 一句话 | 运营管理平台的**唯一入口与授权底座**：谁能登录、以什么身份登录、登录后能执行哪些运营动作 |
| 主对象 | **运营账号**（一个自然人一个账号），不是机构、不是租户 |
| 账号来源 | **平台建设方交付初始工作邮箱与密码**，账号、角色绑定与初始授权交付时配置；本产品内无账号开通入口 |
| 数据可见范围 | **同一主体，运营端数据全量可见**；不做「只看本机构相关项目」的机构级隔离（`D-AL-05`） |
| 权限组织方式 | **按功能权限组织**：各审核、配置、查询动作各自成为一个可授权项，由建设方依据角色与权限矩阵交付配置（`D-AL-07`） |
| 与代币发行平台运营端的关系 | **两套账号、两个部署单元，互不相通**（`D-AL-02`） |
| 产品形态 | 控制台画布形态（固定侧栏 + 紧凑顶栏 + 高密度表格），桌面优先，沿用本平台管理端设计规范 |
| 页面数 | **6**：登录、首登强制改密、忘记密码两步、账户设置、总览页壳子 |

### 3.3 本期目标

## 4. 范围

### 4.1 本期做（含）

- 建设方交付初始账密；首次登录强制改密，完成前其他功能不可用
- 工作邮箱 + 密码登录；登录失败提示、阶梯锁定与锁定态展示
- 忘记密码两步找回（提交工作邮箱 → 人机校验 → 验证码 → 设置新密码）
- 账户设置：账号信息查看、修改本人密码、**修改本人工作邮箱**、界面语言与时区偏好
- **功能权限矩阵**：覆盖本模块与已规划的运营业务模块（L4 / L11 / L14 / L15）的可授权动作
- 会话有效期、无操作登出、会话全局失效
- 密码变更通知的**发什么、何时发**（站内展示形态归 WS-360），以及邮箱修改生效后的新旧地址安全邮件通知
- 总览页壳子，作为登录成功后的落地目标

| 本模块 → 部署 / 运维 | 全部初始账号、角色绑定与初始授权的交付配置；异常时的人工重新初始化；运营端发信配置 | 见 `D-AL-16`、分册 02 第 18 章 |

### 5.3 登录、首登改密与安全（沿用基线，按独立部署收口）

| 编号 | 口径 | 结论 |
| --- | --- | --- |
| `D-AL-14` | **登录方式** | **工作邮箱 + 密码，唯一方式**。无验证码登录、无钱包登录、无第三方登录、无自动建号、无协议勾选、无「记住我」 |
| `D-AL-15` | **初始账密与首登改密** | 建设方交付初始邮箱与密码；所有新账号首次登录必须进入 `P-O-AL-03`，完成改密后才能使用业务功能。**这是唯一路径，无邀请或开通方式选择字段**。初始密码按既有规则线下交付，产品不通过邮件或站内消息下发明文密码 |
| `D-AL-16` | **交付初始化** | 建设方交付全部初始账号并依据矩阵配置角色和权限，是可登录使用的前提；产品无安装向导、自助初始化、账号维护界面。初始密码过期或无法自助找回时，只能由建设方/运维在数据层重新初始化；这是本期已知限制，不是运营管理员的产品操作 |
| `D-AL-17` | **防账号枚举** | 登录与忘记密码两处，**该邮箱是否为有效运营账号不得从提示文案、页面表现或响应快慢中被区分出来**；账号锁定的告知只出现在凭据校验通过之后 |
| `D-AL-18` | **国际化与展示基线** | **外移为三平台共享基线，本模块只引用不复制正文**：界面默认英文、中英可切换、切换即时生效、偏好双态持久化，时间存 UTC 展示带时区标注，数字、金额、链上地址与哈希、脱敏口径一律以共享基线为准 |
| `D-AL-19` | **会话** | 会话有效期与无操作自动登出沿用基线管理端口径（`N-AL-09`）；**不提供「记住我」**；到期前给出续期确认 |
| `D-AL-20` | **会话全局失效** | 退出登录、本人修改密码、重置密码、完成首登强制改密，**该账号的全部会话（含当前设备）立即失效** |
| `D-AL-21` | **锁定** | 连续密码校验失败达阈值后账号锁定，**锁定期间登录与忘记密码全部不可用**，无提前解除通道，到期自动解除；锁定时长按阶梯递进 |
| `D-AL-22` | **人机校验与发码限频** | 界面上只要出现「发送验证码」动作，**必须先过人机校验、再过发送限频**，无入口豁免；绕过界面直接发起也必须满足相同要求 |
| `D-AL-23` | **密码规则** | 8～20 字符，至少 1 个英文字母 + 1 个数字；前后空格自动去除、中间不接受空格；**不得与原密码相同**，也**不得与平台发放的初始密码相同** |
| `D-AL-24` | **账号信息字段** | 本期为工作邮箱、姓名、角色、功能权限、账号状态五项，**不扩充部门、岗位等组织字段** |
| `D-AL-25` | **本人修改工作邮箱** | **允许本人修改，用户已确认**，入口在账户设置。**默认口径、可由用户调整**：当前密码再认证 → 填新邮箱 → 向新邮箱发送验证码 → 校验通过且本运营端内唯一后生效 → 向新旧邮箱发送安全通知。新邮箱生效后作为登录账号、找回密码与安全通知地址；失败或取消时旧邮箱继续有效。完整规则见分册 01 §9.6.1 |
