# 运营端账户与登录 · 消息通知

版本：V1.0｜配套正文与图册：[01-运营端账户与登录-PRD.md](01-运营端账户与登录-PRD.md) V1.2、[02-运营端账户与登录-流程图与状态机.md](02-运营端账户与登录-流程图与状态机.md) V1.2｜日期：2026-09-22。

本模块只有账户安全类事件，全部只发给账号本人。本册定义发什么、何时发、发给谁；站内消息的页面、未读语义与可见范围归 [WS-360 运营端消息通知](../v1.0-运营端消息通知/v1.0-运营端消息通知-PRD.md)，本册不重复定义。事件编号 `NT-AL-*` 为本模块首次登记，供 WS-360 及共享登记引用（此前来源侧记为「待来源登记」）。

## 1. 本模块通知范围

<a id="d-al-26"></a>`D-AL-26`【本模块触发的通知】：密码变更（首登改密 / 忘记密码重置 / 本人改密）经邮件与站内消息告知本人；邮箱修改生效后向新旧地址各发安全通知邮件。通知不含密码或验证码；安全通知投递失败不回滚已生效的修改；验证邮件未完成验证则不得生效。

<a id="d-al-27"></a>`D-AL-27`【明确不产生通知的事件】：账号锁定、锁定自动解除、登录成功、登录失败、语言与时区偏好变更均不发通知。账号交付、角色或权限配置变化也不在产品内产生消息——这些由建设方线下交付（[`D-AL-04`](01-运营端账户与登录-PRD.md#d-al-04)）。不为通知开关编造事件，不新增运营广播、每日摘要、短信或浏览器推送。

<a id="d-al-29"></a>`D-AL-29`【展示归属】：站内消息的页面、铃铛、未读语义与可见范围归 WS-360；本册只定义触发与内容。WS-360 未上线时邮件通道仍独立可用，核心告知能力不丢（[`DEP-AL-03`](01-运营端账户与登录-PRD.md#5-1-依赖)）。

| 事件编号 | 业务名称 | 渠道 | 收件人 |
| --- | --- | --- | --- |
| [`NT-AL-01`](#nt-al-01) | 密码变更通知 | 邮件 + 站内消息 | 账号本人 |
| [`NT-AL-02`](#nt-al-02) | 邮箱变更安全通知 | 邮件 | 账号本人的新邮箱与旧邮箱各一封 |
| [`NT-AL-03`](#nt-al-03) | 账户功能邮件（找回与新邮箱验证码） | 邮件 | 本次用途的目标邮箱 |

<a id="nt-al-01"></a>
## 2. 密码变更通知（`NT-AL-01`）

关联功能 [3.14 账户安全通知](01-运营端账户与登录-PRD.md#f-al-18)，触发来源为 [3.1 首登改密](01-运营端账户与登录-PRD.md#f-al-03)、[3.4 忘记密码重置](01-运营端账户与登录-PRD.md#f-al-05)、[3.8 本人修改密码](01-运营端账户与登录-PRD.md#f-al-08)。

| 项目 | 产品规则 |
| --- | --- |
| 触发 / 不触发 | 新密码真实生效即触发，三种情形各触发一次：首次登录强制改密（设置）、忘记密码重置（重置）、账户设置内本人修改（修改）。密码校验失败、再认证失败、流程取消、会话失效均不触发；账号锁定与自动解除不触发 |
| 收件人 | 仅该账号本人。不改投运营管理员，不扩为全员，不因 SPV 与运营同主体再发一份，不抄送面客账号 |
| 发送时点 / 渠道 | 新密码生效之后、会话批量失效之前；邮件与站内消息各一条。先完成生效通知安排，再按 [3.11](01-运营端账户与登录-PRD.md#f-al-12) 使全部会话失效 |
| 同次事实与再次发生 | 一次密码生效是一条事实，只发一次；重试、重新登录、多设备失效不构成新事实。下一次真实的密码变更才是新事件 |
| 阅读与操作 | 站内消息在本运营端消息中心阅读（`PM-AL-12`），阅读不改变账号状态、不撤销已生效的密码。跨端不可见：本端消息看不到代币发行平台运营端或面客端的任何消息，也不提供跨平台查看入口 |
| 失败 / 离线 / 偏好 | 通知投递失败不回滚已生效的新密码，也不阻断会话失效；本模块不提供该事件的订阅开关，本人不可关闭安全通知 |

<a id="nt-al-02"></a>
## 3. 邮箱变更安全通知（`NT-AL-02`）

关联功能 [3.9 本人修改工作邮箱](01-运营端账户与登录-PRD.md#f-al-19)，流程见 [FL-AL-07](02-运营端账户与登录-流程图与状态机.md#fl-al-07)。

| 项目 | 产品规则 |
| --- | --- |
| 触发 / 不触发 | 新邮箱通过验证并真实生效后触发。再认证失败、验证码无效或过期、新邮箱被占用、账号锁定、取消或未完成流程时邮箱未变更，一律不发；验证码邮件未完成验证不等于邮箱已修改 |
| 收件人 | 新邮箱与旧邮箱各一封，仅限本账号的这两个地址。不改投管理员、不发给其他运营人员 |
| 发送时点 / 渠道 | 新邮箱生效之后；仅邮件渠道，本模块未定义对应站内信，WS-360 不自行补发 |
| 内容 | 告知邮箱已修改、发生时间，以及非本人操作时的求助方式；不含密码、验证码或其他账号资料 |
| 同次事实与再次发生 | 一次生效对应一组（新 + 旧）通知；同一次修改不重复发送。再次修改邮箱才是新事件 |
| 失败 / 离线 | <a id="e-al-19-note"></a>某一地址投递失败不回滚已生效的修改、不误报验证失败（[`E-AL-19`](01-运营端账户与登录-PRD.md#e-al-19)）；已生效的新邮箱继续作为登录、找回与安全通知地址 |
| 与消息中心的关系 | 邮箱修改不会创建新的接收身份、不清空已读、不把历史消息移交新邮箱所属的其他账户；顶栏与账户设置更新为本人当前邮箱 |

<a id="nt-al-03"></a>
## 4. 账户功能邮件：验证码（`NT-AL-03`）

<a id="d-al-28"></a>`D-AL-28`【验证码投递】：找回验证码发往当前工作邮箱，修改邮箱验证码发往新邮箱。

| 项目 | 产品规则 |
| --- | --- |
| 触发 / 不触发 | 每次滑块人机校验与发送限频全部通过后才发送（[3.6](01-运营端账户与登录-PRD.md#f-al-13a)）。滑块未通过、取消、加载失败、冷却中、限频超限均不发；发送失败可立即重试一次且不计额度，该重试仍须重新通过滑块 |
| 收件人 / 目标 | 本次用途的目标邮箱：找回为当前工作邮箱，修改邮箱为此次填写的新邮箱。不要求旧邮箱收码，两种用途的验证码不可混用 |
| 内容与防枚举 | 文案中性，不透露该邮箱是否已有运营端账号；无一键登录链接；验证码不出现在邮件主题与预览文本中 |
| 有效性 | 有效期 `N-AL-03`、单码错误上限 `N-AL-04`；同账号同用途仅最新验证码有效。使用后、过期后、作废后不可重复使用，状态见 [SM-AL-03](02-运营端账户与登录-流程图与状态机.md#sm-al-03) |
| 失败 | 投递失败时用户在原入口重试；页面提示不因该邮箱是否存在而变化 |

## 5. 收件边界与权限

账户安全通知只告知本人：密码变化告知本人，邮箱变化告知本人的新旧地址。协议操作记录「全员可看」不等于全员收信，也不扩大本人密码 / 邮箱安全通知的收件人；收到业务消息也不能绕过目标对象的权限（[3.13](01-运营端账户与登录-PRD.md#f-al-17)）。SPV 与运营同主体不产生资金动作、私人资料读取或面客消息抄送权。本轮身份与协议读取修订不新增通知事件、抄送人或通知开关。

本端站内消息的查看仍需 `PM-AL-12`；个人账户安全消息只有本人可见，管理员不能查看他人的个人安全消息。会话到期、无操作超时、改密导致的失效按 [3.11](01-运营端账户与登录-PRD.md#f-al-12) 处理，停止受保护访问并回本端登录页。

## 6. 文案要素

界面与邮件语言范围为中英双语，按本人语言偏好呈现，规则沿三平台共享国际化基线（[`D-AL-18`](01-运营端账户与登录-PRD.md#d-al-18)）；品牌与合规信息（产品名、发信地址、客服邮箱、公司主体与地址、隐私政策与服务条款链接）的实际取值由需求方提供（[`DEP-AL-07`](01-运营端账户与登录-PRD.md#5-1-依赖)），上线前须到位。

| 事件 | 必须表达的业务信息 | 不得出现 |
| --- | --- | --- |
| `NT-AL-01` | 本账号密码已「设置 / 修改 / 重置」（区分三种情形）、发生时间（按本人时区并带时区标注）、非本人操作时的求助方式 | 明文密码、初始密码、验证码、他人账号信息、一键登录链接 |
| `NT-AL-02` | 工作邮箱已修改、发生时间、非本人操作时的求助方式；新旧两封内容可各自表述，但同指这一次修改 | 明文密码、验证码、占用该邮箱的其他账号身份或状态 |
| `NT-AL-03` | 本次验证码、用途、有效期、未本人操作时忽略该邮件的提示 | 账号是否存在的暗示、一键登录链接；验证码不得置于主题或预览文本 |

## 8. 依赖与未决

- `DEP-AL-02` 邮件服务：运营端发信地址的域名认证配置须在首次发信前完成，与另两个平台分开维护。
- `DEP-AL-03` WS-360：站内消息的页面与未读语义；本册登记的 `NT-AL-01` 供其接收边界引用，`NT-AL-02`、`NT-AL-03` 为邮件事件，不由 WS-360 发送。
- `DEP-AL-08` 来源通知与后续汇总：`Q-LS-N01` 多成员收件责任与停用 / 交接分支、真实公共客服邮箱、数币精度与尾差及资料规则、`Q-NC-01` 共享登记与分类及可选通知清单、`Q-NC-04` 的 60 秒可见要求与来源最坏 5 分钟判定的时效冲突，仍由来源补齐。不改计时起点、不相加放宽、不宣称已达标；本册只承接依赖，不重开来源或控制台通知队列，不把面客收件范围扩大到运营端。WS-360 管理端衔接及全模块最终比对留后续阶段。
