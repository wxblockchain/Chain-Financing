# 代币质押审核 · 流程图与状态机

2026-09-24｜需求评审稿｜配套本模块当前[主 PRD](01-代币质押审核-PRD.md#entry)与[消息通知](03-代币质押审核-消息通知.md)。

<a id="entry"></a>
开发、测试、设计共同参考。业务规则与同序验收见主 PRD，通知事件见消息通知册。本册只表达角色、用户路径和业务状态，不表示页面或组件，承载形式由设计决定（见[统一条款](01-代币质押审核-PRD.md#design-boundary)）；与正文不一致时以正文为准。

本批链路已反转：**代币先由资产方以持有地址签名上链进入质押合约，上链成功才形成待审申请**；运营审核**无时效**，通过才计入有效质押额；驳回或撤回后由资产方自助解押，解押成功前代币持续占用。每笔是一张代币的一次质押申请，重新质押形成新笔，历史与协议不覆盖。连线为已确认业务分支：链上异常仅提示联系平台客服，不画工单、升级、改判或强制解押流程。日期判定与统计统一 UTC，时点按偏好时区显示并标注。原按 48 小时定义的截止与自动超时分支、入池确认与七天入池期限分支已随本批废止，不再出现在任何图中（废止清单见[主 PRD 5.4 节](01-代币质押审核-PRD.md#retired)）。

<a id="fl-pr-01"></a>
## FL-PR-01 质押上链、逐笔审核及两端结果

规则回查：[单笔审核队列](01-代币质押审核-PRD.md#m1)、[单笔事实与批次历史](01-代币质押审核-PRD.md#m2)、[逐笔通过与协议维护](01-代币质押审核-PRD.md#m3)、[逐笔驳回与唯一结论](01-代币质押审核-PRD.md#m4)、[留痕与通知触发](01-代币质押审核-PRD.md#m7)。

```mermaid
flowchart TD
  S["项目已通过审核并完成合约部署"] --> A["资产方在项目内选定 A / B / C 三张代币"]
  A --> T["以代币持有地址签名，向质押合约发起质押上链<br/>gas 自担"]
  T -- "上链失败" --> TF["不形成申请、不进入审核队列<br/>gas 已消耗且不退，可重新发起"]
  T -- "上链成功" --> B["一个批次、三笔独立待审申请<br/>代币已在合约内并占用<br/>计入总质押额与待审质押额，不计入有效质押额"]
  B --> C["运营逐笔查看事实与项目、批次上下文<br/>线下判断，线上维护当前笔结论"]
  C --> D{"当前笔仍待审核<br/>查询与处置权限有效？无截止条件"}
  D -- "否" --> E["不能提交结论<br/>展示当前事实或无权说明"]
  D -- "是" --> F{"仅裁定当前笔"}
  F -- "通过" --> G["通过办理：回显代币、项目、批次与链上事实<br/>上传本笔协议、确认知悉业务后果"]
  F -- "驳回" --> H["填写本笔原因并全文预览"]
  G -- "在本次办理内一次提交" --> I["提交生效时仍满足材料、权限与状态<br/>提交中不可重复，失败保留本笔输入"]
  H --> R["驳回二次确认对象及原因"]
  R --> I
  I -- "条件已变化" --> E
  I -- "本笔通过" --> J["本笔留存审核人、时间与协议<br/>额度归属变化见 FL-PR-02"]
  I -- "本笔驳回" --> K["本笔留存审核人、时间与原因<br/>代币仍在合约内占用，需自助解押"]
  J --> L["面客逐笔展示并通知本笔通过<br/>无需另行确认入池或付平台费用"]
  K --> M["面客原样展示本笔原因<br/>提示自助解押后方可再质押，gas 自担"]
  K --> X["解押路径见 FL-PR-03"]
  B -- "待审期间资产方自行向合约发起解押" --> N["解押成功即本笔已撤回<br/>占用解除，平台不收费，gas 自担"]
  N --> X
  B -- "无人裁定" --> W["无限期停留在待审核<br/>无截止、无倒计时、无自动失败"]
  W --> C
  J --> V["回到本笔详情<br/>操作记录出现通过，见 FL-PR-04"]
  J --> Q["批次只汇总四类单笔数量与留存摘要<br/>其他笔待审或驳回不回滚已审笔"]
  K --> Q
  N --> Q
```

同批可以 A 通过、B 驳回、C 待审；不同运营可分别办理不同笔，同一笔只有一个生效结果。共用协议须确实适用各笔并逐笔明确选用，不自动通过。切换当前笔不能携带上一笔未提交材料或原因。

**审核不设时效**：等待时长只作事实陈述，任何时间流逝都不改变审核状态，也不产生催办或超时通知。每笔通知独立定位，不以批次及结论类型合并掉另一笔。批次统计只供追溯，面客清单始终按代币。

## FL-PR-02 通过后的额度归属与占用延续

规则回查：[三项额度与审核动作的关系](01-代币质押审核-PRD.md#quota)、[质押上链事实与解押追踪](01-代币质押审核-PRD.md#m6)。本图只描述额度归属的业务变化，公式与派生的权威定义归融资需求与代币质押。

```mermaid
flowchart TD
  A["该张上链成功"] --> B["计入总质押额<br/>计入待审质押额 · 待裁定分项<br/>不计入有效质押额"]
  B --> C{"运营裁定"}
  C -- "通过" --> D["从待审质押额转出"]
  D --> E{"借贷平台按既有排除项判定<br/>转入成功、发行平台判有效、无差异、未撤回预扣、底层资产未失效？"}
  E -- "全部满足" --> F["计入有效质押价值<br/>有效质押额＝有效质押价值 × 项目锁定质押率，随之重算"]
  E -- "任一不满足" --> G["不计入有效质押价值<br/>如实展示判定结果，审核结论仍为通过"]
  C -- "驳回" --> H["留在待审质押额 · 已驳回未解押分项<br/>不计入有效质押额"]
  F --> I["代币继续占用在质押合约内<br/>运营不因通过触发任何链上动作"]
  G --> I
  H --> J["代币继续占用<br/>不允许用于其他项目质押，见 FL-PR-03"]
  B -- "待审期间撤回并解押成功" --> K["退出总质押额与待审质押额"]
  J -- "自助解押成功" --> K
```

总质押额含失效代币，只作展示、不参与准入。**审核通过是计入有效质押价值的必要条件而非充分条件**：是否实际计入仍由借贷平台按既有排除项判定，本模块如实展示判定结果、不预告。待审质押额的两个分项对额度影响相同，但下一步动作不同，明细须能区分，不能只给合计数。

<a id="fl-pr-03"></a>
## FL-PR-03 撤回与驳回后的自助解押

规则回查：[终结方式收敛](01-代币质押审核-PRD.md#d-pr-23)、[驳回后的自助解押与再质押](01-代币质押审核-PRD.md#d-pr-24)、[链上异常与客服边界](01-代币质押审核-PRD.md#d-pr-38)。运营端在本流程中只读追踪，没有任何发起、重试或强制退回的动作。

```mermaid
flowchart TD
  A{"该张需要退出质押合约"} 
  A -- "仍待审核：资产方主动撤回" --> B["资产方以持有地址签名<br/>向质押合约发起解押，自付 gas"]
  A -- "已驳回：资产方自助解押" --> B
  B --> C["解押处理中<br/>不得重复发起，不推定成功或失败"]
  C -- "解押成功" --> D["代币退回持有地址<br/>退出总质押额与待审质押额"]
  D --> E{"本笔原审核状态"}
  E -- "此前仍待审" --> F["本笔转为已撤回<br/>无人工结论，不可补裁定"]
  E -- "此前已驳回" --> G["驳回结论与记录保留不变"]
  F --> H["按当前资格可重新发起质押<br/>新笔、新标识、新上链时点"]
  G --> H
  C -- "解押失败" --> I["保持占用与真实事实<br/>gas 已消耗不退，可再次发起"]
  C -- "长期无结果或与原记录冲突" --> J["保持占用，保留真实事实与凭据<br/>提示结果待核实、联系平台客服"]
  J --> K["无工单、升级、改判、强制解押或恢复资格入口<br/>联系客服不改变业务状态与限制"]
```

未解押的代币一直留在质押合约内，**不允许用于其他项目质押**；平台侧没有任何动作能替资产方解押。若资产方长期不解押，该张持续占用并持续计入待审质押额的已驳回分项——这是用户裁定后的既定结果，按[既定业务限制](01-代币质押审核-PRD.md#limits)理解，不判为缺陷。撤回与人工裁定竞合只生效一个结果：人工结论先生效则本笔按结论处理，链上解押另按其真实结果记录。

## FL-PR-04 操作记录与后续进度的查看

规则回查：[操作记录与进度的统一来源](01-代币质押审核-PRD.md#d-pr-34)、[已上传文件的信息与动作要求](01-代币质押审核-PRD.md#d-pr-36)、[质押上链事实与解押追踪](01-代币质押审核-PRD.md#m6)、[留痕与通知触发](01-代币质押审核-PRD.md#m7)。本图是查看和呈现流程，不新增审核或留存状态。

```mermaid
flowchart TD
  A["运营进入本笔详情<br/>旧操作记录入口定位本笔记录"] --> B["申请、代币与链上事实、审核结论与凭据同处可得"]
  B --> C["本笔操作记录<br/>本笔事件与后续进度的唯一来源"]
  D["质押上链、人工结论、撤回等本笔事实"] --> C
  E["解押发起、解押结果与差异等后续变化"] --> C
  C --> F["按发生时间倒序查看事件与结果<br/>操作人与时间为附随信息，原因、gas、凭据可完整取得"]
  F --> R{"本笔是否已有人工结论？"}
  R -- "否" --> K["继续查看或返回队列<br/>保留本笔及原筛选、分页与所在位置"]
  R -- "是" --> G{"是否有已确认的解押结果？"}
  G -- "有" --> H["展示本次解押结果、实际 gas 与凭据<br/>保留原审核结论与历史事件"]
  G -- "无" --> I["展示占用中或解押处理中等已知进度<br/>不生成虚假完成记录或零 gas"]
  F --> J["查看文件：文件名与状态可得<br/>支持预览则预览与下载均可执行，否则仅下载"]
  H --> K
  I --> K
  J --> K
```

操作记录只记录本笔事实，同一事件重复到达不重复生成记录；当前进度不覆盖历史。无权、加载中、暂无记录及读取失败按正文分别说明。冲突迟到事实保留差异保护，不因展示在操作记录中视为已关闭，不新增强制解押或手工完成入口。文件预览失败、不可得及访问权限按[已上传文件的信息与动作要求](01-代币质押审核-PRD.md#d-pr-36)，不把不支持预览与本次预览失败混为一类。

## ST-PR-01 单笔审核轴 RV-20

规则回查：[逐笔通过与协议维护](01-代币质押审核-PRD.md#m3)～[等待时长、待审撤回与解押](01-代币质押审核-PRD.md#m5)、[状态、额度与外部口径](01-代币质押审核-PRD.md#states)。面客单笔审核状态与本轴同源，面客单笔申请标识对应 `RV-19`。

```mermaid
stateDiagram-v2
  state "待审核" as Pending
  state "通过" as Approved
  state "驳回" as Rejected
  state "已撤回" as Withdrawn
  [*] --> Pending: 该张质押上链成功
  Pending --> Approved: 本笔通过办理内一次有效提交且协议齐备
  Pending --> Rejected: 本笔有效驳回且原因齐备
  Pending --> Withdrawn: 资产方待审期间自行发起解押并解押成功
  Approved --> [*]
  Rejected --> [*]
  Withdrawn --> [*]
  note right of Pending
    无截止、无倒计时
    时间流逝不改变审核状态
    只能由人工结论或资产方撤回终结
  end note
  note right of Approved
    本图仅结束审核轴
    无通过二次确认状态
    额度归属见 FL-PR-02
    代币仍在合约内，留存轴见 ST-PR-02
  end note
  note right of Rejected
    驳回不自动解押
    代币继续占用直至资产方自助解押
    解押事实记入留存轴，不改写本结论
  end note
```

撤回没有人工审核人或伪造的人工结论。重新质押生成新笔，不回到原待审核。解押结果只改变留存轴，不把历史结论改写为其他值。

批次无"整批通过 / 驳回"状态机。全部待审＝待审核；部分待审且已有笔终结审核＝审核进行中；没有待审＝审核已结束。审核四类数量之和等于总笔数；留存摘要独立汇总占用中 / 解押处理中 / 已退回，差异标记不重复加入总数。详见正文[批次汇总](01-代币质押审核-PRD.md#d-pr-31)。

## ST-PR-02 本笔当前去向与自助解押

规则回查：[质押上链事实与解押追踪](01-代币质押审核-PRD.md#m6)、[占用与解除的语义边界](01-代币质押审核-PRD.md#d-pr-32)。本轴取面客[本笔当前去向 `PA-15`](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#pa-15) 的取值，与审核轴并列记录，不替代审核结论、不改写额度公式。质押状态（`PL-06`）与链上执行状态（`PL-07`）同样由融资需求与代币质押定义，本册只读消费。

```mermaid
stateDiagram-v2
  state "待审核" as Pending
  state "已计入有效质押额" as Counted
  state "待自助解押" as ToRelease
  state "解押处理中" as Releasing
  state "已解押退回" as Returned
  [*] --> Pending: 质押上链成功
  Pending --> Counted: 审核通过且满足有效性等既有条件
  Pending --> ToRelease: 审核驳回
  Pending --> Releasing: 待审期间资产方自助解押
  ToRelease --> Releasing: 资产方自助解押
  Releasing --> Returned: 解押真实成功结果确认
  Releasing --> ToRelease: 解押真实失败结果确认，gas 不退
  Counted --> [*]
  Returned --> [*]
  note right of Pending
    计入待审质押额的待裁定分项
    不计入有效质押额
  end note
  note right of ToRelease
    计入待审质押额的已驳回分项
    不允许用于其他项目质押
    运营端无强制解押或代发起入口
  end note
  note right of Releasing
    无结果不能直接判成功或失败
    不得重复发起
    长期未知或冲突仅联系客服，无异常处置
  end note
```

已计入有效质押额与已解押退回是本轴的两个终态，互不转化；解押成功的张不因同批其他张失败而回滚，退回后按当前资格可重新发起质押，新笔新上链不覆盖旧记录。未知 gas 标待核实。本图只确定真实结果的正常流转，不存在任何基于时长的自动失败或自动放开。冲突迟到事实遵循 [`FL-PR-03`](#fl-pr-03) 的差异保护，本期仅联系客服，不建设异常关闭或恢复流程。
