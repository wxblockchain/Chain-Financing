# 代币质押审核 · PRD

版本：V1.5｜日期：2026-09-22｜运营管理平台 · 运营端｜状态：当前需求稿，真实未决项见第 5 节。

## 1. 目标与阅读入口

资产方在融资项目详情页一次提交多张代币的质押申请，运营人员在运营管理平台逐笔审核。同一批提交内不同代币可以由不同运营人员在不同时间通过或驳回；已通过的单笔可独立进入资产方确认与链上执行，不等整批审完。

本期包含：单笔审核队列与统计筛选、单笔事实与批次历史、逐笔通过与协议维护、逐笔驳回与唯一结论、逐笔审核时限与撤回、单笔执行结果只读追踪、权限留痕与通知触发。相邻模块负责：面客提交与按代币组织的确认入池（融资需求与代币质押）、面客站内消息的页面与未读语义（面客消息中心）、功能权限矩阵与账号状态（运营端账户与登录）。本期不包含第 [1.2 节](#1-2-本期不包含) 各项。

有效依据（用户已确认）：资产方批量提交、运营逐笔审核，同批可有不同结论；审核时限为提交成功起连续 48 小时，到期仍待审的单笔自动质押失败并解除该笔申请占用，本期不做异常释放；执行异常一律提示联系平台客服人员，本次不实现异常处置（P03）；业务日期统一 UTC，具体时点按用户偏好时区展示，连续时长不变（P10）；单笔概览底部以时间线呈现操作记录、最新在前，事件与结果突出；通过路径在同一表单直接提交；已上传文件的预览与下载置于文件行右侧。

阅读顺序：第 2 节角色、对象与共同口径 → 第 3 节完整功能 → 第 4 节同序验收 → 第 5 节依赖、风险与待决。

## 2. 角色、对象与共同口径

<a id="d-pr-29"></a>
### 2.1 审核对象与角色

`D-PR-29`【逐笔审核的统一来源】：

| 对象 | 含义与范围 |
| --- | --- |
| 提交批次 | 资产方一次面客提交形成的分组；同一资产方、同一融资项目、同一申请类型及提交时间，沿用面客的提交批次编号与关联信息。批次含一笔或多笔 |
| 单笔质押申请 | 批次内**一张代币的一次质押申请**。具有稳定单笔标识，关联批次与代币编号；是审核、撤回、截止、协议、原因和通知的最小单位。标识的编码格式不在 PRD 定义 |
| 单笔审核结论 | 每笔至多一个有效人工结论：通过 / 驳回；时间、审核人、协议或原因各自独立。未审、撤回、审核超时均没有伪造的人工结论 |
| 单笔执行结果 | 仅这笔审核通过、资格复核合格、资产方确认后才有执行；成功、失败、未有结果与审核结论分开，不改写"通过" |
| 批次进度 | 只做单笔事实的数量汇总，不再有统管全批的通过 / 驳回结论、审核人、结论时间、原因、入池截止或"已入池"终态，见 [2.4 节](#states) |

同一批次内一张代币只能出现一笔，仍为整张质押，不拆数量。再次质押是新的提交及新的单笔标识，保留与原记录的关联，不复用原结论。同一代币在不同提交中的记录不可仅凭代币编号合并。单笔审核态属于质押业务申请，不写回代币本体。

| 参与方 | 本模块责任 |
| --- | --- |
| 运营人员 | 按功能权限查看全部单笔；在线下判断后，在线逐笔提交证据与结论；不按运营机构隔离 |
| 资产方 | 面客批量提交，查看每笔结论；撤回仍待审的单笔，确认各已通过笔的费用和执行；可将同一项目、不同提交中的合格代币一同确认；清单一行一张当前代币，历史按笔可查，不能带入未审 / 驳回笔 |
| 借贷平台 | 拥有申请、质押记录和质押事实；提供逐笔期限、入池前复核、结果消费及覆盖判定 |
| 代币发行平台 | 拥有代币事实并承担链上执行；按张提供结果，运营审核无代币维护权 |

本期两个页面：审核队列（`P-O-PR-01`）、单笔审核详情（`P-O-PR-02`，可查看批次上下文）。保留协议上传、历史、时限、通知与执行结果只读追踪；异常仅提示联系平台客服。

<a id="d-pr-05"></a>
### 2.2 权限与账号准入

<a id="d-pr-06"></a>`D-PR-05` / `D-PR-06`：按[运营端账户与登录](../v1.0-运营端账户与登录/01-运营端账户与登录-PRD.md)交付的功能权限执行，本模块不新增授权管理；管理员与被配置业务权限的专员均可按权限办理。两端账号分开不等于已证明跨端同一自然人绝不自审；本期不新增身份关联互斥或双人复核。

| 能力 | 仅有代币质押申请查询（`PM-AL-07`） | 同时有代币质押审核处置（`PM-AL-08`） |
| --- | --- | --- |
| 队列、单笔详情、批次上下文、协议、留痕 | 可查全部授权业务范围，不按机构或本人分配过滤 | 同左 |
| 上传并正式关联协议、通过 / 驳回 | 不显示处置入口，绕过界面仍拒绝 | 仅当前笔待审核且未到截止时可执行 |
| 改结论、改代币、发链上操作、手工确认释放 | 不可 | 不可 |
| 运营站内消息 | 另需运营端消息查看（`PM-AL-12`），不由本模块赠予 | 同左；读消息不表示有处置权限 |

只有处置而无查询权限不能进入本流程，联系建设方核对配置。账号待首登改密、锁定、登录失效或当前无权限时，旧页面提交及下载同样拒绝。已授权但业务终结的对象保留可读原因；无权入口不展示且不泄露记录存在性。

<a id="d-pr-37"></a>
### 2.3 时间、日期与金额口径

`D-PR-37`【统一业务日期与截止】：

- **审核截止**：批次提交成功时点起连续 48 小时，按实际经过时长判定，不按自然日、工作日或本地午夜计数。
- **入池截止**：本笔通过时点按 UTC 增加七个自然日，保留时分秒；不改成当地日末、工作日或从浏览时起算。
- **业务日期边界**：近七个自然日统计、按日期筛选等统一 UTC；日期筛选需让操作者识别其 UTC 口径。
- **展示**：具体时点按用户偏好时区显示并标注。切换显示时区、跨周末或夏令时不改变截止、统计事实或事件顺序。
- **自动事件时间**：自动超时记录采用真实截止发生时点，不用打开页面的时间替代。
- **金额**：代币价值为 USD 两位小数，费用用实际发生币种；未知不填 0，不编造数币精度。

<a id="states"></a>
### 2.4 状态、汇总与外部状态

`RV-20`【单笔审核轴】枚举，必有，默认待审核：待审核 / 通过 / 驳回 / 已撤回 / 质押失败（审核超时）。通过和驳回是人工结论，撤回和审核超时是未获人工结论的终结事件。通过后的复核与执行变化不把 `RV-03` 的历史"通过"改成驳回。

| 对象与状态 | 触发及允许行为 |
| --- | --- |
| 单笔待审核 | 提交后未终结；有权限且未到期可裁定；面客可撤回本笔 |
| 单笔通过 | 在通过表单一次有效提交且协议齐备，不经过二次确认；可进入本笔复核与资产方确认，运营不得二次裁定 |
| 单笔驳回 | 有效提交驳回且原因齐备；保留记录，结束本笔占用；可新笔再申请 |
| 单笔已撤回 | 资产方待审时有效撤回；无补审、不收费 |
| 单笔质押失败（审核超时） | 本笔到审核截止仍无有效人工结论；自动失败，不能迟到补审 |
| 通过后：待确认入池 | 有效通过且未发起；按本笔入池截止判断 |
| 通过后：结论已作废 | 本笔复核不通过；不执行，原审核与协议存档 |
| 通过后：结论已失效 | 已到本笔七天期限且未发起执行；已发起后跨期按 [`D-PR-38`](#d-pr-38) |
| 通过后：执行中 / 成功 / 失败 | 本笔实际结果；成功且满足资格才是本张已入池；失败不把同批成功笔回滚 |
| 差异 | 并列事实标记，不覆盖人工审核结论；异常仅客服指引，本期没有差异关闭或恢复动作 |

<a id="d-pr-31"></a>`D-PR-31`【批次汇总】：审核进度仅使用"待审核"（全部未处理）、"审核进行中"（仍有待审且至少一笔已终结审核）、"审核已结束"（无待审）。同时列待审、通过、驳回、撤回、质押失败（审核超时）五类笔数，合计等于本批总笔数；"审核已结束"不等于全部通过或质押成功。

执行摘要另列未发起、处理中、成功、失败的笔数，合计取已获通过的笔；复核作废、过期未发起在未发起类别中给明细原因，差异等为可叠加标记、不重复加总。尚未得到明确执行结果的张不能算入失败或成功。"全部已入池"仅全批每笔都实际成功、满足有效性等入池资格且无待核实事实时才可作事实描述，不另造全批质押终态。

质押事实 `PS-1` 可质押 / `PS-2` 已质押 / `PS-4` 已释放由借贷平台维护（`PS-3` 为作废占位，`PS-0` 非法）；执行状态 `CT-0` 未发起 / `CT-1` 处理中 / `CT-2` 成功 / `CT-3` 失败由发行平台结果驱动。运营审核动作不直接改写 `PS`；申请占用结束及质押事实由借贷平台统一维护，可再次选择还受实际占用、差异、资产有效性约束。不以审核超时扩展 `CT` 失败。内部状态号不出现在界面文案。

面客侧同源消费：单笔申请标识对应 `RV-19`，面客单笔审核状态对应 `RV-20`，面客逐笔原因与复核对应 `RV-13` / `RV-21`，面客协议与截止对应 `RV-05` / `RV-15` / `RV-22`。两端按此同源消费，不退回整批结论。

状态图见[单笔审核轴](02-代币质押审核-流程图与状态机.md#st-pr-01)与[单笔转入执行结果](02-代币质押审核-流程图与状态机.md#st-pr-02)。

### 2.5 共同质量要求

| 维度 | 可观察要求 |
| --- | --- |
| 一致性 | 两端同笔结论、原因、时间、截止一致；批次进度由同一组单笔事实汇总，不能因局部刷新把某笔归给其他批次 |
| 反馈 | 加载、无数据、筛选无结果、读取失败、无权、上传中、提交中、结果不确定分别可辨；失败不丢当前有效输入，跨笔不串材料 |
| 性能 | 常规数据量下队列含统计及详情 2 秒内可交互、筛选翻页 1 秒内返回；单笔数量与测量场景提测前明确，不声称未经实测达标；上传有进度、不冻结其他字段 |
| 展示 | 时间与金额按 [2.3 节](#d-pr-37)；共享国际化与脱敏口径沿用，不以内部状态代码作界面标签 |
| 桌面与可访问性 | 1280 / 1440 / 1920 操作可达、无页面横向溢出；状态有文本、键盘可用、错误能定位；不冒称规范外窄屏支持 |
| 安全 | 无权用户不可读取申请及附件；绕过界面的写操作亦拒绝；结论和留痕不可篡改，无代币编辑、代签代付能力 |

## 3. 完整功能

<a id="m1"></a>
### 3.1 单笔审核队列（`F-PR-01`～`05`）

前置为正常运营账号且有代币质押申请查询权限；侧栏"质押审核"进入审核队列。列表**一行一笔代币质押申请**，不是一行批次；同批关系可识别。独立队列不依附已移交的代币管理。列表仅提供查看，不提供多选裁定。

| 内容 | 产品规则 |
| --- | --- |
| 默认 | 单笔审核状态＝待审核，批次提交时间升序；同时间按稳定单笔顺序，刷新不跳动。不做风险优先排序 |
| <a id="d-pr-14"></a>筛选（`F-PR-03` / `D-PR-14`） | 审核状态（全部 / 待审核 / 通过 / 驳回 / 已撤回 / 质押失败（审核超时））、资产方、项目、申请类型（全部 / 首笔质押 / 追加质押）、提交时间范围、关键词（批次编号 / 单笔标识 / 代币编号 / 企业名）。默认除待审核外均为空或全部；组合生效，起止含边界，起点不得晚于终点；关键词忽略首尾空白 |
| 后续情况筛选 | 全部 / 待确认入池 / 复核作废 / 未发起已过有效期 / 执行中 / 执行成功 / 执行失败 / 结果待核实 / 对账差异，命中相应单笔；不是新增人工审核结论 |
| 列 | 单笔标识、批次编号、代币编号、资产方、目标项目、申请类型、该张代币价值（USD）、提交时间、审核等待及截止、审核状态、后续情况、查看。批次合计不得冒充这一张的价值 |
| 三张统计卡（`F-PR-02`） | 待审核**笔数**、质押失败（审核超时）**笔数**、近 7 个自然日人工审结**笔数**。应用主体 / 项目 / 类型 / 提交时间 / 关键词条件，不应用状态和后续情况筛选；各卡按自身状态定义计数并标明范围。人工审结只计通过 / 驳回，不计自动超时 |
| 排序与分页（`F-PR-04`） | 提交时间、审核等待、单张价值可升降序；带总数常规分页。筛选改变回首页、重置回默认。页容量沿用平台现行组件值，不另造值。返回与后退保留筛选、排序、页码；原页为空回最后有效页并说明 |
| 空与失败 | 待审为空、筛选无结果、读取失败分别反馈；失败可重试，不假报 0。无查询权限不显示入口，直接访问亦拒绝 |

申请类型的取值与派生规则由面客侧定义：按提交时本项目是否已有有效质押派生为首笔质押或追加质押，两者入口、链路与审核规则完全相同，仅用于展示与检索。

`F-PR-05`：点某行详情只进入该笔单笔审核详情；已结论或终结仍可只读回看。批次含 3 笔只审 1 笔后，待审数减少 1，另 2 笔仍在队列。流程见[批量提交、逐笔审核及两端结果](02-代币质押审核-流程图与状态机.md#fl-pr-01)。

### 3.2 单笔事实与批次历史（`F-PR-06`～`08`、`17`）

<a id="d-pr-20"></a>`D-PR-20` / `D-PR-21`：线下完成判定，线上维护证据与结论。页面中性说明"本页信息供线下判定参考，结论由审核人线下作出后在此维护"；不提供评分、风险灯、建议通过 / 驳回、自动筛出不合格资产。格式必填、权限、状态及截止校验照常生效。

| 区块 / 字段 | 业务含义、类型、必填与校验 |
| --- | --- |
| <a id="rv-19"></a>单笔定位（`RV-19`） | 稳定文本标识，提交成功即有；关联一个批次、一个代币、一家资产方、一个项目；只读，无默认空值。重新提交生成新标识 |
| 批次上下文 | 批次编号、项目、申请类型、提交时间必有，只读；完整批次清单可查，不能修改；本笔清晰定位，不将批次所有代币列为本次裁定对象 |
| 资产方与项目 | 企业名称、稳定主体标识、项目编号 / 名称 / 状态 / 类型；只读，不以名称替代归属判定。缺失标"待核实"，不得猜测，见[`Q-PR-07`](#q-pr-07) |
| 本张代币事实 | 编号、数量及币种、USD 代币价值、底层账期、买方企业、有效 / 已失效状态；读取同一只读代币域，缺失不用 0 或"有效"填充，不二次折算 |
| 审核信息 | 本笔审核状态（`RV-20`）、人工结论（`RV-03`，存在时）、结论时间（`RV-04`）、审核人（`RV-07` / `RV-08`）、协议或驳回原因；不同笔各自展示 |
| 期限 | 本笔审核截止（`RV-15`）；通过后的入池截止（`RV-22`）；名称和时区明确，不能给全批一个通过时间或入池倒计时 |
| 后续信息 | 本笔复核（`RV-21`）、执行及差异结果在概览底部操作记录中作为进度呈现，见 [`D-PR-34`](#d-pr-34) 与 [3.6 节](#m6)。尚无结果标未复核 / 未发起 / 暂无结果，不编造失败 |

`F-PR-08`：同项目同资产方的历史按提交批次可回溯，进入后逐笔看代币、状态、审核人、时间、原因全文及关联的再申请。单笔事件按发生时间倒序；没有人工结论的终结显示撤回 / 自动超时及发生时间，不冒充人工裁定。摘要可收起，详情原因必须完整。跨项目再申请仅在有明确关联时展示，不凭代币相同推定关联。

<a id="d-pr-34"></a>`D-PR-34`【操作记录与进度的统一入口，覆盖 `F-PR-06`、`08`、`13`、`18`】：单笔审核详情的"概览"在申请信息、代币事实、审核结论与凭据之后，以"操作记录"时间线式列表作为最下方内容区；不再以独立"操作记录"页签承载。关联申请保留原入口；旧操作记录入口进入当前笔概览并定位该列表，不丢失单笔或返回队列上下文。审后"后续情况"详情合并至列表，不另设重复明细卡；队列的后续情况筛选、必要的当前状态及入池截止摘要仍可保留，均与时间线同源。事件标题和结果突出，操作人与时间作为辅助信息，原因、实际费用及凭据在对应节点下展开；按倒序排列。

| 列表内容 | 含义与展示要求 |
| --- | --- |
| 事件 / 进度 | 必有文本，区分提交、审核通过 / 驳回、撤回、审核超时，以及通过后的复核、待确认入池、许可失效、执行与差异；只展示本笔事实，不混入同批其他笔 |
| 发生时间 | 已发生事件展示真实时间与时区；按发生时间倒序，同时间保持稳定顺序。时间暂缺标"待核实"，不得用页面打开时间代替；未发生的步骤不生成完成记录 |
| 操作主体 | 人工事件显示当时审核人；自动事件标"系统"，来自资产方的动作标"资产方"；未提供主体时标"待核实"，不推定为审核人 |
| 结果与说明 | 该事件的结果、前后状态及原因；原因可展开全文。进行中明确"处理中"及已知事实，未来步骤不预写成功；详情字段按 [3.6 节](#m6) |
| 关联凭据 | 有则提供对应本笔的协议或执行凭据，遵守权限及文件规则；没有则说明暂无，不伪造材料或重复关联其他申请 |
| 列表反馈 | 加载、暂无记录、读取失败分别展示；失败可重试且不伪装为空。记录只读，不提供编辑、删除或手工完成进度动作 |

历史事件与当前进度均可查，新增进度不覆盖原审核事实；同一业务事件重复到达只显示一次，不因刷新重复插入。关联申请历史与本笔操作记录范围分开。流程见[概览底部操作记录与审后进度](02-代币质押审核-流程图与状态机.md#fl-pr-04)。

同批不同笔可直接查看或切换；切换前有未提交输入需选择留在当前笔继续编辑或放弃后切换，不提供跨笔自动保存草稿，不能将上一笔原因、协议选择、备注及确认勾选自动带入下一笔。通过 / 驳回弹层始终回显单笔、代币、批次和项目。已审笔只读，**不使同批待审笔只读**。

<a id="d-pr-15"></a>`D-PR-15` / `D-PR-16`：入池前复核只读，不提供运营复核按钮；审核不读取或修改覆盖派生量。代币失效、项目终结显示客观事实，不自动替审核人驳回，也不保证该笔后续能入池。实际入池仍受面客资格判定。

### 3.3 逐笔通过与协议维护（`F-PR-09`、`10`）

<a id="d-pr-01"></a>`D-PR-01`：每次审核针对当前单笔。可以只通过批次内 A、驳回 B、保留 C 待审；不再要求整批同结论。通过 A 不代表批准 B/C，其他笔无需重新提交或重新计时。本期不提供一次点击为多笔生成结论。

<a id="d-pr-35"></a>`D-PR-35`【通过直接提交】：前置为有查询与处置权限，当前笔仍待审核且未到截止。线下判定后：本笔"通过" → 通过表单（`C-O-PR-01`）回显本笔代币、项目、批次 → 上传本笔适用协议 → 可填内部备注 → 在同一表单勾选知悉通过不等于质押成功 → 点击"通过本笔申请"直接提交。通过路径没有"核对结论 / 确认审核结论"后续步骤，不弹二次确认，不新增第二位审核人。此路径不改变逐笔驳回的原因预览与二次确认，也不改变资产方面客入池确认。

提交前取消不产生结论，跨笔不携带材料；提交中明确反馈且不可重复点击。材料、权限、状态或截止不满足时就地说明，不产生通过记录；保存失败保留当前笔有效输入可重试。结果不确定先查当前事实，不展示成功或引导重复裁定。成功后关闭表单、回到本笔概览，结论及底部操作记录出现本次通过，当前笔只读，其他待审笔仍可办理。

| 编号 | 规则 |
| --- | --- |
| <a id="d-pr-03"></a>`D-PR-03` / `N-PR-03` | 每笔通过必须有 PDF / JPG / PNG 协议，1～5 个，单文件 ≤10 MB；默认未关联任何文件。未上传完或保留文件失败不能通过；错误逐文件指出、可修复、不丢其他输入。只校验规格与有无，不认定内容或法律效力 |
| <a id="d-pr-04"></a>`D-PR-04` / `D-PR-30` | 协议按**本笔结论**关联和锁定。同一线下协议确实覆盖同批多张时，可逐笔明确选用同一文件，须能从协议内容识别本笔代币；不自动给其余笔挂协议、不自动通过。是否适用由运营线下核对，平台不做内容识别。每笔仍分别确认 |
| 协议生命周期 | 未提交前可增删替换；已通过的本笔关联不可删改。其他笔修改其未提交材料不能影响已通过笔；本笔失效 / 作废只把本笔凭据关联标为"已失效 · 仅存档"，同文件对另一正常笔的关联不跟着失效。再次质押的新笔必须重新明确关联，不自动复用 |
| <a id="d-pr-13"></a>`D-PR-13` | 当前笔通过不等于质押成功；显示本笔结论时间及其后 7 个自然日入池截止。已通过 A 可独立给资产方确认，不等待 B/C 审完。运营不代确认费用、不触发链上转入 |
| <a id="d-pr-16"></a>`D-PR-16` | 审核通过不直接计入覆盖，不修改代币事实或质押 / 执行状态；后续借贷平台仅按满足条件的实际成功张计入 |

<a id="d-pr-36"></a>`D-PR-36` / `F-PR-10`【已上传文件的通用展示要求】：本模块协议上传完成项及正式协议、存档文件均使用同一文件行表达，沿用[管理端组件规范](../../页面原型/_shared/design-system/管理端组件规范.md)，本册不修改该规范。

| 要素 / 场景 | 产品行为与边界 |
| --- | --- |
| 文件信息与动作 | 左侧展示文件名及已有状态（如已上传、已关联本笔结论、已失效 · 仅存档）；最右侧为操作区。"预览""下载"按此顺序并排，不能放在左侧文件信息下方；多文件逐项对应，长文件名不挤走按钮，完整名称可查看 |
| 支持预览 | 已上传完成且具备预览能力的文件显示预览与下载；打开及关闭预览保留当前申请、列表位置和未提交输入。PDF / JPG / PNG 仍为本模块允许上传类型，通用展示规则不扩展上传白名单 |
| 不支持预览 | 仅保留下载，不显示预览按钮、灰色占位或点击后才告知不支持；其他模块采用通用组件时按其既有文件范围判断，不强制支持所有文件格式 |
| 预览失败 | 对原本支持预览的文件提示本次预览失败，提供下载兜底；区别于已知不支持预览。文件暂不可得或下载失败明确提示并允许重试，不假报无协议或下载成功 |
| 上传中 / 上传失败 | 分别显示进度或错误，不冒充已上传文件，不提供可用的预览与下载；保留既有修复及移除能力。上传完成后才按能力展示文件动作 |
| 编辑与存档 | 未提交材料仍可按原规则移除、替换；正式关联后不可删改。存档标签不等于文件不可读，也不等于质押成功；有访问权限时仍按能力提供预览与下载 |
| 权限与可达性 | 文件访问沿用所属业务权限，下载不绕过权限；动作文字清晰、键盘可达，1280 / 1440 / 1920 下右侧操作不被文件名遮挡或挤出页面 |

正式附件仅授权运营与所属企业资产方可访问，游客、其他企业、资金方不可访问。驳回 / 撤回 / 超时导致本次通过未生效时，未提交的文件选择不成为本笔正式协议；同文件已经在其他笔生效的关联不受影响。

| 字段 | 类型与业务校验；全部默认无人工结论 |
| --- | --- |
| `RV-01` 结论记录编号 | 文本，有效人工结论生效时生成，稳定只读；每笔至多一条，不再按整个批次限制一条 |
| `RV-02` 关联提交批次 | 引用，必有、只读；与[`RV-19`](#rv-19)一起定位本次单笔结论，仅批次编号不足以指向结论 |

| `RV-07` / `RV-08` 审核身份 | 当前运营账号标识及结论时姓名 / 工作邮箱，必有、不可编辑，后续账号资料变化不覆盖历史 |

| `RV-22` 本笔入池截止 | 时间，仅本笔通过后生成＝`RV-04` 后 7 个自然日；只读，带业务时区，未通过为空 |

### 3.4 逐笔驳回与唯一结论（`F-PR-11`、`12`）

前置与通过相同。本笔"驳回"打开驳回表单（`C-O-PR-02`）：回显本笔代币 → 填原因，可选归类 → 完整预览 → 二次确认对象及原因 → 提交。

<a id="d-pr-02"></a>`D-PR-02` / `D-PR-10`：驳回只结束本笔，原因针对本笔；同批 A 通过、B 驳回、C 待审是正常结果，资产方可只重新申请 B，不重复提交 A/C。

| 字段 | 含义、必填、默认与校验 |
| --- | --- |
| `RV-13` 原因说明 | 驳回必填自由文本，去首尾空白后 10～500 字，禁止纯空白或仅标点；默认空。平台不改写措辞或判断真伪 |
| `RV-12` 问题代币标注 | 本笔代币只读回显，取[`RV-19`](#rv-19)所关联代币，不再从全批勾选问题子集；不能借此驳回其他笔 |
| <a id="d-pr-22"></a>`RV-11` 归类标签（`D-PR-22`） | 选填、默认空：代币归属或主体存疑 / 底层应收账款存在问题 / 代币与目标项目不匹配 / 申请材料不完整或不一致 / 其他。仅统计，不影响是否可提交 |
| `RV-14` 驳回原因全文 | `RV-13` 为主体，标签或本笔点名文字可辅助生成、可编辑；最终预览文本原样用于本笔面客原因与通知。选填部分不挤占 10～500 字的说明空间，不截断、不自动套到全批 |

<a id="d-pr-07"></a>`D-PR-07`：同笔并发，只先有效完成的一次裁定生效；后者展示本笔已有结论、时间与审核人，不覆盖。**不同笔并发互不争抢整批结论**，A/B 可分别成功提交。重复同笔同次操作不增加结论、不改时间、不重复通知。结果不确定先显示待确认并可查当前事实，不引导重新制造结论。

<a id="d-pr-12"></a>`D-PR-12`：两端按稳定单笔标识同步该笔结论、时间、原因；批次仅汇总。不因某笔结论而覆盖批次其余笔的待审、驳回或通过结果。已撤回、审核超时或已有人工结论的笔不能再裁定，旧弹层提交亦拒绝。正常未执行的驳回仅解除本笔申请占用，本次零费用，不触发链上释放；实际已转入的差异仅只读及保护限制，本期不提供异常释放，不把已通过改成驳回来启动新动作。

<a id="m5"></a>
### 3.5 逐笔时限与撤回（`F-PR-14`、`15`）

<a id="d-pr-08"></a>`N-PR-01` / `D-PR-08`：审核时限为**提交成功时点起连续 48 小时**，判定与展示口径见 [2.3 节](#d-pr-37)。批次内各笔继承同一提交时间与审核截止；点开审核、切换、某笔裁定都不重置其余笔时钟。

| 字段 / 时钟 | 规则 |
| --- | --- |
| `RV-15` 本笔审核截止 | 时间，提交成功必有、只读，取批次提交成功时点加 48 小时；队列及详情展示明确时点与时区 |
| `N-PR-02` 已等待 | 待审笔从提交起计；不足 1 小时按分钟、不足 24 小时按小时、之后天＋小时；人工结论、撤回或审核超时生效即停止审核等待 |
| `RV-16` 审核超时事实 | 本笔到期无结论才产生：发生时间＋"48 小时未完成审核"；自动事件无人工审核人、无伪造驳回 |
| <a id="d-pr-09"></a>`D-PR-09` 入池有效期 | 各笔从自己的通过时点按 UTC 增加 7 个自然日；不是用户当地日期日末。先通过的 A 不因后来 B 通过延长。已发起后跨期按 [`D-PR-38`](#d-pr-38) |
| 执行等待 | 仅实际发起后按该笔起算，独立于审核 48 小时和入池七天；本期不设执行超时自动失败或异常处置阈值。未知、跨期与冲突按 [`D-PR-38`](#d-pr-38) 联系客服 |

七天只限制未发起笔的新发起，已发起后的跨期按 [`D-PR-38`](#d-pr-38)，不自动解除在途占用。

<a id="d-pr-23"></a>`D-PR-23`：到达审核截止，仅仍待审笔自动质押失败（审核超时）；截止前已通过 / 驳回 / 撤回的笔保持原结果。正在上传、提交尚未生效、线下已决定但未在线提交均不算已审核；恰在截止提交也不能补审。已生效撤回不改成超时；先超时后不能补撤回。每笔只有一个有效审核结果，不影响同批其他笔。

<a id="d-pr-24"></a>`D-PR-24`：本笔审核超时记录保留；正常未执行张解除该笔待审占用，保持 / 恢复可质押，按最新资格可立即重新提交到同一或其他项目，无冷却。旧笔不恢复、不删除，新笔新标识、新提交时点。其他独立占用、失效或差异仍约束可选性，不能由旧笔到期覆盖。

资产方可在面客端撤回仍待审的单笔；如支持多选撤回，只可逐项列明当前可撤回代币，已裁定笔不纳入，不得撤销整批全部结果。撤回与审核同笔竞合只生效一个结果，其他笔照常。单笔通过后不再提供"撤回申请"，已质押后的资产退出属[面客正常解除质押](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#execution)。

例如同批 A 已通过并执行、B 已驳回、C 仍待审：截止只使 C 超时、释放 C 的本次占用，不能回退 A、重写 B 或对全批宣称零费用。审核驳回 / 超时零费用的表述只指该笔本次未执行申请。期限展示区（`C-O-PR-04`）分别显示审核截止、入池截止和执行等待。图见[单笔审核轴](02-代币质押审核-流程图与状态机.md#st-pr-01)。

<a id="m6"></a>
### 3.6 单笔执行结果与释放边界（`F-PR-18`）

<a id="d-pr-25"></a>`F-PR-18` / `D-PR-25`：一笔通过即可由资产方确认该笔，无需等同批未审笔。执行资格仅限自身有效通过、复核合格、未重复占用且未发起的笔；资产方可从代币维度清单中，跨提交批次选择同一项目的多个合格代币；一张仅对应当前有效单笔，历史申请独立可查。项目、代币、逐张费用及合计在一个确认弹窗核对，点击一次确认即发起，不再重复费用确认。列表须明确本次参与张数、逐张对象和费用，**未审、驳回、撤回、审核超时、失效 / 作废笔不得被批次通过摘要带入执行**。

<a id="d-pr-11"></a>`D-PR-11`：本端只读追踪，不提供代签、代付、重发或修改代币、质押事实、执行状态的能力。

审核通过后的复核、待确认、未发起到期、执行与差异均作为概览底部操作记录的进度（[`D-PR-34`](#d-pr-34)）。通过即记录"审核通过 / 待资产方确认入池"，不伪造确认或执行事件；实际发生后追加对应进度，已有审核记录保留。每项进度可展开查看下表的时间、原因、费用及凭据，原独立后续情况明细不再重复承载。

`RV-21` 为本笔入池前复核：未复核 / 通过 / 不通过及原因，默认未复核，发生后只读。复核不通过仅使该笔结论不可用于入池，保留人工审核历史、文件存档；该笔未执行、无费用。复核其他笔仍可通过，不取消全批。入口不可用且未实际发起时，不标处理中或执行失败。

| 逐笔执行字段 | 业务含义及校验 |
| --- | --- |
| 关联 | 单笔标识、批次、项目、代币必有、只读；不能仅用批次和一个结果定位 |
| 执行状态 | 未发起 / 处理中 / 成功 / 失败，分别承接 `CT-0`～`CT-3`；实际发起后才处理中；无结果不擅填失败。"结果待核实"为事实提示，不自造终态 |
| 时间 | 实际发起、确认完成、发现差异的各自时点及业务时区；没有结果不伪造完成时间 |
| 原因与下一步 | 执行失败或差异有可读原因；处理中不能重复发起；普通已确认失败且无占用、资格允许可新建申请；差异保持本张限制并提示联系客服，本端没有处置入口 |
| 费用 | 实际是否产生、金额及币种只读；资产方承担，已产生费用含失败张不退。未提供写"费用待核实"，不填 0、不因另一张零费用推断全批零费用 |
| 凭据 | 成功有可查验凭据，缺失不编造；可复制查验，展示沿共享口径，不以有凭据替代业务确认 |
| `RV-17` 差异事实 | 相关单笔、代币、原记录、迟到或冲突事实与发现时间；无差异不生成；不得关联到同代币的新申请而覆盖旧事实 |
| `RV-18` 释放跟踪 | 本期停用、编号保留；不新增异常释放跟踪字段、待办或操作。正常解除质押的展示使用面客既有记录 |

**按张执行独立**：人工通过 A/B 后若 A 执行成功、B 执行失败，二者审核结论仍通过，后续结果不同；B 不影响 A。成功张还须满足有效性等既有规则才计覆盖，待审、通过待执行、处理中和差异均不计覆盖。只约束相关张，不锁全项目。

<a id="d-pr-26"></a><a id="d-pr-38"></a>`D-PR-26` / `D-PR-38`【执行异常与客服边界】：适用于长期无结果、已发起跨过入池期限或项目终态、结果与原记录冲突，以及混合结果中仍待核实的笔。两端保留真实单笔、代币、批次 / 项目、本次动作、等待时长、已知费用和凭据，告知"执行结果待核实，请联系平台客服人员"。沿平台已有真实客服联系方式能力提供指引；资料不可得时如实说明联系方式暂不可用，不编造邮箱、电话、核实天数或承诺。客服信息用于联系，不是异常处置入口。本规则与[面客异常口径](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#exceptions)同源。

没有明确执行结果仍为"处理中 / 结果待核实"，不推断失败、资产已转回、费用为零、可重复执行或可以重新质押；仅相关张受限制，其他明确成功且合格的张正常成立。审核的 48 小时不能套为执行失败期限。本期不建立工单、异常待办、升级阈值、客服处理进度、人工改判 / 补记、强制释放、补偿、代付或恢复资格流程；联系客服、查看记录或已读通知均不改变业务状态与限制。

普通晚到且没有跨期 / 冲突的真实结果，归本笔正常呈现。迟到成功与原记录冲突时保留原事实并关联旧笔、新申请或新池，不翻转原执行终态、不自动改回已质押、不双池计入覆盖，保留相关张的新动作限制并提示联系客服。已有真实差异标记仍可只读查看，不因取消异常处置功能而清掉保护；不生成差异处理任务。已发起跨七天的笔不按"未发起过期"失效，不解除在途占用、不重置期限；跨项目终态返回的真实转入位置可查，但不恢复项目、不新增有效覆盖、不自动异常退回，仍按客服边界处理。审核通过的历史与实际费用继续保留。

混合结果按张独立：正常明确失败且确认没有占用、当前资格允许的张可新笔重提；正常成功张按有效性计覆盖；未知、跨期或冲突张不因同批其他张已结束就自动恢复资格。正常业务解除质押与提取仍由面客承接，不作为本端异常处置。

<a id="d-pr-27"></a><a id="d-pr-32"></a>`D-PR-27` / `D-PR-32`【释放语义与本期范围】：

| 场景 | 本期范围及可观察结果 |
| --- | --- |
| 本笔提交后连续 48 小时无有效通过 / 驳回、仍待审 | 自动显示"质押失败（审核超时）"，原因说明 48 小时未完成审核；释放该笔申请占用，代币从未转入，不产生 gas、不触发链上释放、不进入待提取。原记录保留、可按最新资格再次质押 |
| 查看详情、上传材料或编辑未提交 | 不算完成审核，不重置 48 小时；截止前有效通过 / 驳回 / 撤回的笔不再超时。不是每次点击后重新计 48 小时 |
| 正常未执行的驳回 / 待审撤回 | 解除对应笔申请占用、零费用，不作链上释放 |
| 正常入池后的额度允许撤回、项目终态业务释放及自助提取 | 仍在面客范围；已释放待提取与审核失败解除占用区分，不因本次排除异常释放而删除正常退出 |
| 审核记录与已转入事实冲突后的异常释放 | **本期不做**（[`X-PR-01`](#1-2-本期不包含)）。不设计异常释放入口、待办、自动转回、费用分配或恢复资格流程。已有事实差异只读与不重复操作限制保留，不代表支持异常释放 |

<a id="d-pr-33"></a>`D-PR-33`【面客按代币组织与批量确认】：清单以代币为单位，不以提交分组要求资产方逐批操作；同项目不同提交的合格笔可一起确认，未通过笔不可混入。同一确认内逐笔保留原结论、协议与截止；不生成新审核结论、不重置计时。提交前资格变化要指出失效张、更新选择与费用，在同一个弹窗由用户再次明确确认当前集合后才发起，不能静默少执行一张或多收费用。具体面客规则同源于[同项目批量确认，逐张执行](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#execution)。

流程见[已通过代币批量确认、执行及未知结果](02-代币质押审核-流程图与状态机.md#fl-pr-02)、[审核失败释放占用与正常退出边界](02-代币质押审核-流程图与状态机.md#fl-pr-03)；执行轴见[单笔转入执行结果](02-代币质押审核-流程图与状态机.md#st-pr-02)。

<a id="m7"></a>
### 3.7 留痕与通知触发（`F-PR-13`、`16`）

`F-PR-13`：留痕关联**批次＋单笔＋代币**，包含提交、撤回、人工结论、正式协议关联、自动超时、复核、执行与差异事实、重新申请关联；记录事件、时间、主体、前后状态、原因与凭据。人工取当时身份，自动事件不伪造审核人；不可编辑删除，重新申请不覆盖旧笔；不同审核人的结果可在同批并存。展示位置、列表字段与审后进度统一按 [`D-PR-34`](#d-pr-34)；同一事件不得同时生成重复的操作行和进度行。

<a id="d-pr-17"></a>`D-PR-17`～`D-PR-19` / `F-PR-16`：沿用既有面客事件名称和消息端别，**事件归属为单笔，不以批次＋结论类型合并掉第二笔同类结果**；同一笔同一事件重复送达不形成重复消息。页内结果始终保底，投递失败不回滚。通知必须定位本笔代币及所属批次；不等待整批审完才触达。是否采用视觉聚合由消息及设计模块决定，但每笔内容、截止及操作不能丢失。

| 事件 | 收件方与内容 / 落点 |
| --- | --- |
| 质押审核通过（`financing.pledge.review_approved`） | 面客提交资产方；本笔、代币、项目、通过时间与本笔入池截止；进入审核结果中该笔的确认位置，不自动执行 |
| 质押审核驳回（`financing.pledge.review_rejected`） | 同上；明确仅该笔驳回，原因全文原样，其他笔不受影响；可按资格重提本笔 |
| 质押审核超时（`financing.pledge.review_timeout`） | 同上；只指到期未审核的这一笔，说明保留记录、该笔本次零费用、可按资格再申请；不把同批已执行笔说成零费用 |
| 执行失败 / 差异 | 使用面客模块的逐张事实；本端不重复发送另一套结果；执行未知、跨期或冲突不新增失败、催办或客服进度消息 |
| 运营队列与只读事实 | 审核队列仍逐笔；已超时只能追溯、不能补审。执行失败或差异在原笔记录可查，本期不新增异常处置待办、升级或运营广播；详情权限不等于消息收件资格 |

正常新申请不额外全员广播，通过 / 驳回不重复通知刚裁定的运营。内部备注不进入面客原因或通知。<a id="d-pr-28"></a>`D-PR-28`：已读 / 已查看不等于差异已关闭或限制解除。仅资产方本企业可看其材料及执行信息，资金方和游客不能读取审核记录。

通知事件、模板、收件、失效和验收统一见[消息通知第 2～5 节](03-代币质押审核-消息通知.md#notice-rules)及[第 6 节验收](03-代币质押审核-消息通知.md#notice-acceptance)；本模块不另造事件副本。

<a id="acceptance"></a>
## 4. 同序验收

前置：资产方一次向同项目提交 A/B/C 三张；另有同代币新提交记录、不同资产方记录；运营有查询＋处置、仅查询和无权三组身份。审核结论、面客结果及逐张执行可分别观察。以下为业务验收要求，未决分支按[第 5 节](#open-items)限制，不以模拟结果冒充已上线能力。

### 4.1 单笔审核队列（对应 [3.1](#m1)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-PR-01`～`02` 队列按笔生成与统计随实际笔数变化 | 一次提交三张形成三笔队列记录和待审计数 3；按提交时间升序。仅通过 A 后待审为 2、近七日人工审结加 1；自动超时不计人工审结 |
| `AC-PR-03`～`04` 筛选排序生效且卡片范围不被状态筛选影响 | 基础条件组合、单笔后续情况筛选及三列排序生效；申请类型可按首笔质押 / 追加质押筛选；起止错误就地提示，重置回默认，卡片范围不被状态筛选误清零 |
| `AC-PR-05`～`06` 翻页往返保留上下文且失败不假报为空 | 翻页与详情往返保留上下文，行查看进入指定单笔，列表无批量裁定入口；加载失败不显示为零条 |
| `AC-PR-51` 同批已审笔不遮蔽剩余待审笔 | 同批 A 已审、B/C 待审时，B/C 仍可检索和打开办理；查询批次可看全三笔，不把批次剩余待审藏进已审历史 |

### 4.2 单笔事实及历史（对应 [3.2](#m2)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-PR-07`～`09` 单笔与批次事实只读可回溯 | 当前笔和批次关联清晰、完整清单可回查；代币事实只读、无增删替换，缺失不补 0；历史原因可展开全文，自动事件无伪造审核人 |
| `AC-PR-36`～`39` 线下判定载体无系统建议且校验仍生效 | 线下判定说明存在，无系统建议、评分或风险排序；客观有效性和执行差异可展示；格式、权限、状态及期限校验仍有效 |
| `AC-PR-62` 概览底部时间线承载全部操作记录 | 待审、通过、驳回、撤回及超时详情的操作记录均在概览最下方以时间线式列表展示，事件与结果突出、操作人与时间为辅助信息，原因 / 费用 / 凭据在节点下展开，无独立操作记录页签；按时间倒序可查全文、主体及凭据，自动事件无伪造审核人；旧入口能定位本笔列表，返回队列保留上下文；加载、空与失败可辨 |
| `AC-PR-52` 跨笔切换不串输入也不回写旧笔 | 从 A 切到 B 时未提交原因 / 材料不串入 B；对同代币新申请的结论不会回写旧笔；同批不同审核人及时间可分别回溯 |

### 4.3 逐笔通过与协议（对应 [3.3](#m3)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-PR-10`～`13` 通过只结论当前笔且须协议齐备 | 通过 A 必须有适用协议并在本表单勾选知悉通过不等于质押成功；点击"通过本笔申请"直接提交，无核对结论或二次确认弹层；只有 A 生效且可给资产方确认，B/C 不必先审完；提交前取消无结论 |
| `AC-PR-14` 协议规格校验的边界值 | 无文件、6 个文件、类型错误、单文件大于 10 MB 或上传未完成不能通过；1～5 个合规文件及恰好 10 MB 可提交；失败可修复、不丢其他输入 |
| `AC-PR-15`～`16` 协议按笔锁定且不跨笔连带 | 通过前可替换，之后不能改本笔关联；同文件明确覆盖 A/B 时分别选择并确认，B 作废不使 A 关联失效；新笔不自动继承协议 |
| `AC-PR-24` 通过不直接改写代币与覆盖 | 无其他业务变化时，通过 A 不立即增加覆盖、不修改代币或质押 / 执行状态；后续按真实成功张判定 |
| `AC-PR-63` 通过表单一次提交的成功与失败路径 | 通过表单合规提交仅一次操作；提交中禁止重复，失败保留本笔输入，结果不确定不假报成功。无协议、上传未完、权限失效、已被裁定 / 撤回或恰到截止均不产生本次通过结论，已有结果不被覆盖；成功回概览且记录一次，同批其他笔不变；驳回及面客确认流程保持原规则 |
| `AC-PR-64` 文件行的信息与动作分区 | 上传完成文件与正式 / 存档协议均左侧信息、最右侧预览和下载并排；不支持预览的文件仅下载。长文件名、多文件、中英文及三档桌面均不遮挡动作；开关预览不丢编辑内容及位置，未提交材料可移除，正式关联不可删改 |
| `AC-PR-65` 预览失败与权限的兜底反馈 | 支持预览但本次失败时有错误说明与下载兜底；文件不可得、下载失败不假报成功；上传中 / 失败不提供可用文件动作。无权限者不能预览或下载；组件复用不放宽本模块 PDF / JPG / PNG、数量及大小限制 |
| `AC-PR-53` 各笔通过时间与截止彼此独立 | A/B 不同时间通过，各自形成结论、审核人、时间和七天截止；后通过 B 不刷新 A 的截止，A 通过不自动给 B 关联协议 |

### 4.4 逐笔驳回与唯一结论（对应 [3.4](#m4)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-PR-17`～`20`、`AC-PR-40` 驳回原因校验与只点名本笔 | B 原因空、纯标点或不足 10 / 超过 500 字被阻止，边界 10 / 500 字可通过；归类选填，全文预览与面客原因逐字一致，只点名 B，不给全批套原因；二次确认对象正确 |
| `AC-PR-21`～`23` 同笔并发只生效一次、跨笔并发互不争抢 | 两人同时裁定 B 仅一个生效，后者显示已决结果；两人分别裁定 A/B 可各自成功；重复同笔操作不增加结论、通知或刷新时间 |
| `AC-PR-54` 三种结论并存时重提只影响相关笔 | A 通过、B 驳回、C 待审的三种事实同时可见；只重提 B 形成新笔，A 不重新审核或收费，C 时钟不变；本次 B 未执行则零费用 |

### 4.5 时限与撤回（对应 [3.5](#m5)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-PR-28`～`29`、`AC-PR-33` 审核与入池两个时钟各自独立 | 三笔继承批次提交时间，审核截止不因某笔被处理而延长；七天入池各从本笔通过起算；无人打开页面仍自动使截止未审笔失败 |
| `AC-PR-41` 恰好截止与并发竞合的唯一结果 | 截止前有效通过 / 驳回 / 撤回保留；正在上传、提交未生效和恰好截止的迟到裁定不能补审。同笔撤回与裁定只生效一个，其他笔不受影响 |
| `AC-PR-42`～`43` 超时笔可立即重提且费用表述限于本笔 | 超时 C 的旧记录可查、不恢复，正常未执行 C 可立即新笔再申请至同一或另一项目；面客原因明确运营未按时审核，C 本次零费用，不能把 A 已执行费用抹为零 |
| `AC-PR-59` 48 小时按实际经过时长判定 | 提交后第 47 小时 59 分仍待审，第 48 小时自动失败并释放该笔占用；换时区、跨周末、反复查看与上传均不延长。恰好截止的新裁定不生效，无人打开页面亦自动处理 |
| `AC-PR-55` 到期只影响仍待审笔 | 批次 A 已通过执行、B 已驳回、C 待审，到期只 C 失败；若用户只撤回 C，A/B 保留。批次撤回不得包含已审笔；审核统计和摘要随实际笔数变化 |
| `AC-PR-68` 跨时区查看不改变两个截止事实 | 同一笔在不同时区查看，审核截止仍为提交成功后连续 48 小时；入池截止为本笔 UTC 通过时点加七个自然日，保留时分秒，恰好截止不能新发起。跨周末或夏令时不改变截止；两端、记录及通知显示同一事实并带时区 |
| `AC-PR-69` 统计与筛选的 UTC 口径稳定 | 近七日自然日统计及日期筛选采用 UTC，切换显示时区不改统计归属、事件先后或审核数量；自动超时时间为实际截止，不以打开页面时刻补记 |

### 4.6 执行结果与释放边界（对应 [3.6](#m6)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-PR-44`～`45` 通过笔可独立执行且结果按张呈现 | 只获通过的 A 可确认执行，不等待 B/C；未审或驳回笔不可混入。获通过 A/B 的执行结果一成一败时，各自展示结果与费用，审核结论均仍通过，成功张不回滚 |
| `AC-PR-46` 无结果时只给事实与客服指引 | 没有执行结果时显示等待及已知事实，不擅填失败、零费用或可重押；提供真实客服指引且不建设异常处置，不用审核 48 小时判定执行失败，不新增未决升级阈值 |
| `AC-PR-47` 冲突迟到结果保留原事实并维持保护 | 迟到成功与原记录冲突时关联正确单笔、原记录保留、不自动双池计入，相关张暂停新动作并提示联系客服；其他张正常。无异常待办、关闭或恢复入口，客服介入不解除保护 |
| `AC-PR-48` 审核失败的释放不触及链上与退款 | 审核失败解除申请占用不调用链上释放、不出现待提取或退款；本期无异常释放入口、待办、进度和费用规则，正常解除质押及终态提取仍走面客 |
| `AC-PR-60` 跨提交的合格笔可一次确认 | 面客同项目的 A/B 来自不同提交且均通过，可在一个代币清单勾选、一次确认后发起；原协议与截止分别保留。C 待审不可被一起发起，旧笔只留历史 |
| `AC-PR-61` 确认前资格变化须再次明确确认 | 确认前某张过期或资格变化，明确指出并更新清单与费用；用户确认更新后的集合才发起。取消不执行，已执行成功张不因其他张失败回滚；无异常释放入口 |
| `AC-PR-66` 审后进度在同一时间线呈现 | 通过后的待确认、复核不通过、未发起到期、执行中及成功 / 失败均在本笔概览操作记录中体现进度，可查看原后续详情中的时间、原因、实际费用与凭据；没有独立重复的后续明细卡。通过不生成虚假执行事件，后续结果不覆盖原审核通过，其他笔不混入 |
| `AC-PR-67` 进度重复到达与未知结果的呈现约束 | 进度重复送达或刷新不重复生成行；尚无结果不补完成时间、失败或零费用；普通无跨期 / 冲突的迟到结果归本次执行，冲突另记差异并保留历史，不覆盖新申请或解除限制。查看记录不表示关闭差异，不新增异常释放入口或手工完成进度 |
| `AC-PR-56` 复核作废与跨期在途各自限定范围 | 本笔复核不通过不作废其他已通过笔；处理中该张不能重复发起而其他张不锁。未执行笔七天失效可明确验，已发起跨七天按 `D-PR-38` 保留实际事实与在途限制，提示联系客服，不伪称零费用或自动失效 |
| `AC-PR-70` 待核实笔只展示事实与联系方式 | 长期未知、跨期、冲突或部分待核实笔展示原笔 / 代币、实际动作、已知费用与凭据及联系客服说明；不猜结果或费用、不自动释放 / 重押、不重发执行，不提供工单、异常待办、升级、改判、补偿、释放或恢复入口。已知成功 / 失败张仍按各自真实条件处理 |
| `AC-PR-71` 跨期在途与终态返回不改写资格 | 已发起跨七天不按未发起过期解除占用；项目终态后返回转入事实不恢复项目或新增覆盖。联系客服、读记录不关闭差异；客服联系方式真实可用，缺失不造地址或处理天数，并如实提示。普通无跨期 / 冲突的晚到结果仍归原笔 |

### 4.7 权限、留痕、通知与通用质量（对应 [3.7](#m7)、[2.2](#d-pr-05)、[2.4](#states)、[2.5](#2-5-共同质量要求)）

| 验收 | 场景与预期 |

| `AC-PR-25`～`27`、`AC-PR-49` 权限分离与留痕不可篡改 | 所有事件按批次和单笔回溯，不可改删；只查不能审、只有处置不赠查询，账号非正常或无权时旧页操作和下载拒绝；无代币修改或代发能力 |
| `AC-PR-30` 术语不混淆审核、执行与释放 | 区分审核、执行、释放与批次进度；不把通过叫质押成功，不把"审核已结束"叫全部已入池，不用"担保"替代质押 |
| `AC-PR-31`～`32` 通知按笔触达且不重复 | A/B 分别通过会分别触达，不因同批同类而漏掉 B；重复 A 事件不重复通知。每笔带自己的截止 / 原因，投递失败不回滚；不等全批审完才通知 |
