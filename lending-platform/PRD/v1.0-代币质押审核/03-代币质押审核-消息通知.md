# 代币质押审核 · 消息通知

版本：V1.5｜配套正文与图册：[01-代币质押审核-PRD.md](01-代币质押审核-PRD.md) V1.5、[02-代币质押审核-流程图与状态机.md](02-代币质押审核-流程图与状态机.md) V1.5｜日期：2026-09-22。

## 1. 范围与阅读入口

本模块只有三类审核结果事件，全部发给提交该笔申请的资产方本平台账号，只走"借贷平台 · 面客端"站内信。本册定义发什么、何时发、发给谁、打开到哪里；站内消息的页面、铃铛、未读语义与可见范围归[面客消息中心](../v1.0-面客消息中心/01-面客消息中心-PRD.md)，本册不重复定义，也不规定消息接口或投递实现。

业务完整规则回查[留痕与通知触发](01-代币质押审核-PRD.md#m7)、[逐笔时限与撤回](01-代币质押审核-PRD.md#m5)、[单笔执行结果与释放边界](01-代币质押审核-PRD.md#m6)，流程回查[批量提交、逐笔审核及两端结果](02-代币质押审核-流程图与状态机.md#fl-pr-01)。

三类事件沿用面客侧既有事件编号 `N-LS-01`～`N-LS-03` 与模板 `T-LS-01`～`T-LS-03`，本模块是审核结果的**唯一发送来源**；[融资需求与代币质押](../v1.0-借贷广场-融资需求与代币质押/03-融资需求与代币质押-消息通知.md)承接面客页面展示，不发同义副本。分类语义为"业务办理进度"。不新增邮件、短信、浏览器推送、每日催办、执行成功通知或客服进度通知。

## 2. 三项事件与发送边界

| 通知 / 业务类型 / 模板 | 触发条件与必须告知的结果 | 收件与目标 |
| --- | --- | --- |
| `N-LS-01` / `financing.pledge.review_approved` / [`T-LS-01`](#templates) | 当前单笔有效通过后立即形成通知，不等同批其他笔；带本笔通过时间、独立入池截止，说明仍须资产方确认并承担执行费用，通过不等于已入池 | 原提交该笔申请的资产方本平台账号；进入项目质押审核与确认，定位该笔及代币。符合当前资格方可主动确认，不自动勾选或执行 |
| `N-LS-02` / `financing.pledge.review_rejected` / [`T-LS-02`](#templates) | 当前单笔有效驳回；完整面客原因与正文 `RV-14` 原文一致，本笔正常未执行、零费用，历史保留，可按当前资格新笔重提，不给整批套同一原因 | 同上；原单笔历史及完整原因，不覆盖重新提交的新笔 |
| `N-LS-03` / `financing.pledge.review_timeout` / [`T-LS-03`](#templates) | 成功提交后连续 48 小时仍待审，本笔正式判定"质押失败（审核超时）"；明确运营未按时审核、正常未执行、零费用、本笔申请占用释放、记录保留及按资格可再申请 | 同上；原笔历史。已通过、驳回、撤回笔不再超时，也不把同批已执行笔费用写成零 |

未提交的原因、上传材料、仅打开表单、并发未生效的裁定不触发消息。恰好截止的新裁定不生效，只按该笔真实终结结果通知。审核超时只释放未上链的申请占用，不是链上退款或待提取；真实事实已存在冲突时不能用普通零费用 / 可重提措辞掩盖异常，按正文保护与客服指引呈现，不另造异常结果通知。

通过、驳回后不能再次修改同笔结论。审核历史不随执行成功、失败、失效或作废被重写，也不因后续事件再次发送同笔审核结果。

| 本期不新增的通知 | 保留的业务能力 |
| --- | --- |
| 新申请全员广播、给刚裁定运营再发结果副本、全批审完汇总 | 逐笔审核队列、五类结果和批次数量统计仍可查 |
| 七天内催办、未发起过期或复核不通过的新通知 | 原笔展示准确截止、许可失效 / 作废原因，保留原审核通过 |
| 执行未知、跨期、冲突、部分待核实的升级、工单、异常处置或客服进度消息 | 页内真实事实及保护，提示"执行结果待核实，请联系平台客服人员" |
| 执行结果的第二套消息 | 明确执行失败由[融资需求与代币质押通知](../v1.0-借贷广场-融资需求与代币质押/03-融资需求与代币质押-消息通知.md)发送一次，项目与覆盖事件同归该册；本模块只读，不重复发送 |

## 3. 收件、去重、时间与可读性

**收件。** 每笔固定原提交账号，不按企业全员、不任选管理员或当前查看人；资金方、游客和运营不收这三类结果副本。运营有代币质押申请查询 / 审核处置权限可看、可办审核，不因此成为面客消息收件人；运营端消息查看权限也不赋予读取他人面客信件的资格。提交账号停用、交接或归属缺失按来源及消息框架依赖处理，不猜新收件人、不转移历史、不暂停业务计时。项目级多成员责任账号属面客侧依赖，不影响本模块已明确的原提交账号规则。

**同一事实。** 按面客端、收件账号、通知类型和本笔事实区分。同笔同事件重复送达不新增消息 / 未读、不把已读恢复未读、不刷新发生时间或重新置顶。同批 A/B 分别通过保留两笔消息，不按"批次＋通过"合并掉第二笔；重新申请是新笔，新结果可有新通知，旧记录不覆盖。消息展示是否分组由设计决定，但每笔截止、原因及定位不能丢失。

**时间。** 通知使用业务给定的真实发生时间及截止，不自行重新计算、不以发送 / 阅读时间重置。审核超时发生于成功提交后连续 48 小时；通过后的七天按本笔 UTC 通过时点增加七个自然日，保留时分秒，不是当地日末。时点按收件人偏好时区展示并标注，切换时区或夏令时不改通知事实和业务资格。通过的办理资格可过期，原消息和原审核事实不因到期删除。

**打开目标。** 查看目标只读；办理必须由用户主动进入原有对应操作，消息不直接打开办理或替用户确认。进入时核对当前身份、权限与原对象状态，不能绕过业务准入。旧入池动作因已办理、已过期、作废或项目状态变化而不可用时，仍按当前权限展示原笔历史和不可办理原因，不跳到同代币新申请并误发起。正常登录失效须登录后再按当前资格进入；无权不泄露对象、文件或私有账户信息。目标尚未登记时按消息框架采用可读无跳转的降级，不把默认首页当成准确定位。

消息已读只改变消息状态，不完成审核、确认入池、关闭差异或解除保护。内部备注、私有账户资料、协议原文件内容和可越权链接不进入通知；业务原因保留全文。公共客服联系方式仅使用已有真实公开值，可按共享能力查看或复制，不套私有邮箱隐藏规则，也不编造地址。

## 4. 消息内容与模板

以下业务信息随单笔结果提供，必填表示该事件成立时必须有真实值，不得用演示数据补齐。本册不定义编号编码、传输结构或表结构。

| 业务信息 | 类型、必填与校验 |
| --- | --- |
| 本笔、批次、项目、代币 | 业务标识文本，三事件必有且能定位；本笔取面客单笔申请标识（即正文 `RV-19`），批次取提交批次编号。不能仅靠代币编号定位历次申请，项目名称不能替代项目编号 |
| 收件与业务发生时间 | 原提交账号及真实时点，必有；不能取审核员或阅读时刻 |
| `project_name` / `project_id` / `token_id` | 模板使用者必有；沿业务原值，不替换缺项或暴露钱包 / 私人账号。保持同一笔，不移用其他项目 |
| `approved_at` / `entry_deadline` | `T-LS-01` 必有，为本笔实际通过时点及 UTC 七天截止；未通过不造值，不取同批其他笔时间 |
| `reason` | `T-LS-02` 必有，为 `RV-14` 原文；沿正文既定 10～500 字校验，完整可读，不用内部备注代替，不因摘要省略而丢失全文；英文界面不假称人工中文原因已翻译 |

<a id="templates"></a>本册复用面客侧 `T-LS-01`～`T-LS-03` 的完整双语模板，不新建另一组名称；标题和正文为成对文本，变量同名同数量。模板名称沿既有 `msg.<业务类型>.title` / `msg.<业务类型>.body` 约定。

| 模板 | 中文标题 / 正文 | English title / body |
| --- | --- | --- |
| `T-LS-01` | 质押审核通过，待确认入池 / 项目 {project_name}（{project_id}）的代币 {token_id} 本笔申请已于 {approved_at} 审核通过。请在 {entry_deadline} 前按当前资格确认入池并承担执行费用；审核通过不代表已入池。 | Pledge approved — confirmation required / The current pledge application for token {token_id} in project {project_name} ({project_id}) was approved at {approved_at}. Confirm deposit by {entry_deadline}, subject to current eligibility, and pay the execution fees. Approval does not mean the token has been deposited. |
| `T-LS-02` | 本笔质押申请未通过 / 项目 {project_name}（{project_id}）的代币 {token_id} 本笔申请未通过。原因：{reason}。本笔尚未执行，不产生执行费用；记录保留，可按当前资格重新申请。其他代币按各自结果处理。 | Pledge application rejected / The current pledge application for token {token_id} in project {project_name} ({project_id}) was rejected. Reason: {reason}. This application was not executed and incurred no execution fees. Its record is retained; you may reapply subject to current eligibility. Other tokens retain their own outcomes. |
| `T-LS-03` | 质押审核超时，本笔失败 / 项目 {project_name}（{project_id}）的代币 {token_id} 本笔申请因运营端未在提交成功后 48 小时内完成审核，已判定质押失败。本笔未执行、零费用，申请占用已释放，记录保留；可按当前资格再次申请。 | Pledge review timed out / The current pledge application for token {token_id} in project {project_name} ({project_id}) failed because the review was not completed within 48 hours of successful submission. No execution occurred and no execution fees were incurred for this application. Its reservation was released and its record retained. You may reapply subject to current eligibility. |

标题、正文、账号或本笔业务事实不足时不得伪造可用消息；非关键跳转配置缺失按框架降级，不把所有缺项一律等同丢弃整条消息。原文原因作为业务文本完整展示，不扩展成其他通知或动作。

## 5. 时效、偏好与依赖

关键结果在真实业务发生或应到时点后的 **60 秒**内可见，未读和列表同步；不能把接收完成才作为起点，也不以刷新页面作为前提。消息失败不回滚已生效结论、不重审或重执行，业务页面始终可查。本册不设计重试方案。

本期三个审核结果未列入可关闭事件，不自行新增关闭或补送策略；沿消息框架既有偏好规则。分类筛选不是退订，业务进度分类不等于允许屏蔽。没有明确可选事件时不制造新通知来填充开关。

剩余依赖：共享消息分类值与正式登记、端到端时效（部分来源为"60 秒与最坏 5 分钟"）的冲突与真实联验仍在面客消息框架侧，本模块保持 60 秒要求，不声称全平台冲突已解决；原提交账号真实对应、停用交接分支及客服真实联系方式仍需能力输入。异常升级 / 关闭责任不是本期功能待决；本册不重新建设来源或控制台队列。

## 6. 验收要求

沿正文[留痕与通知触发](01-代币质押审核-PRD.md#m7)及 `AC-PR-31`～`32`、`AC-PR-58`，同批 A/B/C 与同代币新申请用于区分单笔事实。以下是可观察结果，不是详细测试步骤。

| 编号 | 验收结果 |
| --- | --- |
| `AC-PR-N01` 逐笔结果分别触达原提交账号 | A 生效通过、B 生效驳回、C 待审，仅原提交账号分别收到 A/B 结果；无整批通过摘要，不等待全批，原因全文及 A 自身截止准确 |
| `AC-PR-N02` 超时通知只覆盖仍待审的那一笔 | 成功提交满连续 48 小时仍待审的 C 收到审核超时结果；已审 / 已撤回笔不误收。明确 C 未执行、零费用、只释放本笔申请占用，不说全批零费用、退款或待提取 |
| `AC-PR-N03` 同一事实去重且不互相吞并 | A 同一结果重复到达只有一条消息，不新增未读 / 置顶 / 发生时间；A/B 两笔相同结果不相互吞并，新申请新结果保留独立历史 |
| `AC-PR-N04` 两端时点与时区展示一致 | 两端及消息中的通过 / 截止指向同一时点，UTC 七天保留时分秒；切换展示时区、夏令时不延长连续 48 小时或七天，不以阅读时间重算 |
| `AC-PR-N05` 过期消息可读但不误触发办理 | 原通过消息过期或业务已办理后仍可按权限读原笔，不可用的动作停止，不误定位同代币新笔；无权者不能读私有结果 / 附件，读消息不完成业务或解除差异 |
| `AC-PR-N06` 事件范围限于三类审核结果 | 本模块只有既有三类审核事件；明确执行失败由面客模块原事件发送一次。未知、跨期、冲突与客服指引不触发执行失败、升级、异常处置或运营广播；本模块权限不按机构认证的不分权口径改写 |
| `AC-PR-N07` 模板变量完整且不泄露内部信息 | 三组中英标题正文变量一致，完整原因保留，不泄露内部备注或私有文件；时间缺失、真实客服不可用不以演示值 / 假地址补齐，消息投递失败不回滚已生效业务 |
| `AC-PR-N08` 可见时效以真实投递为准 | 从真实业务发生或应到时点观察 60 秒可见目标；未登记、真实收件依赖或时效冲突如实标未完成，不能以文档模板核对替代实际投递验收；三个结果不因未定义的可选开关被屏蔽 |
