# 代币质押审核 · 消息通知

2026-09-24｜需求评审稿｜配套本模块当前[主 PRD](01-代币质押审核-PRD.md#entry)与[图册](02-代币质押审核-流程图与状态机.md)。

## 1. 范围与阅读入口

本模块只有**两类**审核结果事件——质押审核通过与质押审核驳回，全部发给发起该笔质押的资产方本平台账号，只走"借贷平台 · 面客端"站内信。本册定义发什么、何时发、发给谁、打开到哪里；通知的承载形式与视觉由设计决定（见[统一条款](01-代币质押审核-PRD.md#design-boundary)）。站内消息的阅读入口、未读语义与可见范围归[面客消息中心](../v1.0-面客消息中心/01-面客消息中心-PRD.md)，本册不重复定义，也不规定消息接口或投递实现。

**本批变化**：用户 2026-09-24 确认审核无时效管控，原第三类事件"质押审核超时"（`N-LS-03` / `financing.pledge.review_timeout` / `T-LS-03`）**随之废止**，本模块不再发送该事件，相关验收 `AC-PR-N02` 一并废止（见[主 PRD 5.4 节](01-代币质押审核-PRD.md#retired)）。同时链路已反转：代币在审核前已上链并占用，通过不再需要资产方确认入池或支付平台费用，驳回后需资产方自助解押；两条模板文案按此改写。

业务完整规则回查[留痕与通知触发](01-代币质押审核-PRD.md#m7)、[等待时长、待审撤回与解押](01-代币质押审核-PRD.md#m5)、[质押上链事实与解押追踪](01-代币质押审核-PRD.md#m6)，流程回查[质押上链、逐笔审核及两端结果](02-代币质押审核-流程图与状态机.md#fl-pr-01)。

两类事件沿用面客侧既有事件编号 `N-LS-01`～`N-LS-02` 与模板 `T-LS-01`～`T-LS-02`，本模块是审核结果的**唯一发送来源**；[融资需求与代币质押](../v1.0-借贷广场-融资需求与代币质押/03-融资需求与代币质押-消息通知.md)承接面客侧的结果查看，不发同义副本。分类语义为"业务办理进度"。不新增邮件、短信、浏览器推送、催办、上链成功通知、解押结果通知或客服进度通知。

<a id="notice-rules"></a>
## 2. 两项事件与发送边界

| 通知 / 业务类型 / 模板 | 触发条件与必须告知的结果 | 收件与目标 |
| --- | --- | --- |
| `N-LS-01` / `financing.pledge.review_approved` / [`T-LS-01`](#templates) | 当前单笔有效通过后立即形成通知，不等同批其他笔；带本笔通过时间，说明该张已按有效性判定计入有效质押额，**无需另行确认入池、不产生平台费用**；代币继续留在质押合约内 | 发起该笔质押的资产方本平台账号；进入本项目的质押记录，定位该笔及代币。不自动勾选或执行任何动作 |
| `N-LS-02` / `financing.pledge.review_rejected` / [`T-LS-02`](#templates) | 当前单笔有效驳回；完整面客原因与正文 `RV-14` 原文一致，说明**代币仍在质押合约内、需自助解押且 gas 自担**，解押成功后按当前资格可重新发起质押，不给整批套同一原因 | 同上；原单笔历史及完整原因，不覆盖重新发起的新笔 |

未提交的原因、上传材料、仅打开办理、并发未生效的裁定不触发消息。**质押上链成功、待审等待、资产方撤回、解押发起与解押结果均不由本模块发消息**——上链与解押是资产方自己发起的动作，其结果由面客侧承接呈现。真实事实已存在冲突时不能用普通措辞掩盖异常，按正文保护与客服指引呈现，不另造异常结果通知。

通过、驳回后不能再次修改同笔结论。审核历史不随解押成功、失败或差异被重写，也不因后续事件再次发送同笔审核结果。**任何时间流逝都不触发通知**：没有临期提醒、没有超时告知、没有待审催办。

| 本期不新增的通知 | 保留的业务能力 |
| --- | --- |
| 审核超时通知（本批废止）、待审临期提醒、审核催办 | 面客可随时查看本笔当前审核状态与已等待时长 |
| 新申请全员广播、给刚裁定运营再发结果副本、全批审完汇总 | 逐笔审核队列、四类结果和批次数量统计仍可查 |
| 质押上链成功、解押发起、解押成功 / 失败的第二套消息 | 面客侧按自身规则呈现这些链上结果，本模块只读，不重复发送 |
| 解押未知、冲突、部分待核实的升级、工单、异常处置或客服进度消息 | 页内真实事实及保护，提示"结果待核实，请联系平台客服人员" |

## 3. 收件、去重、时间与可读性

**收件。** 每笔固定发起该笔质押的账号，不按企业全员、不任选管理员或当前查看人；资金方、游客和运营不收这两类结果副本。运营有代币质押申请查询 / 审核处置权限可看、可办审核，不因此成为面客消息收件人；运营端消息查看权限也不赋予读取他人面客信件的资格。本期一个企业只有一个员工，原多成员资产方的收件归属问题自然消解，不再作为待决项；账号停用、交接或归属缺失仍按来源及消息框架依赖处理，不猜新收件人、不转移历史。

**同一事实。** 按面客端、收件账号、通知类型和本笔事实区分。同笔同事件重复送达不新增消息 / 未读、不把已读恢复未读、不改变发生时间或原有次序。同批 A/B 分别裁定保留两条消息，不按"批次＋结论"合并掉第二条；重新质押是新笔，新结果可有新通知，旧记录不覆盖。是否分组呈现由设计决定，但每笔原因及定位不能丢失。

**时间。** 通知使用业务给定的真实发生时间，不自行重新计算、不以发送 / 阅读时间重置。**本模块不再有任何截止或期限类时间**：不发送截止、不计算剩余时长、不因到期删除或改写原消息。时点按收件人偏好时区展示并标注，切换时区或夏令时不改通知事实和业务资格。

**打开目标。** 查看目标只读；办理必须由用户主动进入原有对应操作，消息不直接打开办理或替用户确认。进入时核对当前身份、权限与原对象状态，不能绕过业务准入。原对象因已解押、项目状态变化等原因不可再办理时，仍按当前权限展示原笔历史和不可办理原因，不跳到同代币新申请并误发起。正常登录失效须登录后再按当前资格进入；无权不泄露对象、文件或私有账户信息。目标尚未登记时按消息框架采用可读无跳转的降级，不把默认首页当成准确定位。

消息已读只改变消息状态，不完成审核、不触发解押、不关闭差异或解除占用。内部备注、私有账户资料、协议原文件内容和可越权链接不进入通知；业务原因保留全文。公共客服联系方式仅使用已有真实公开值，可按共享能力查看或复制，不套私有邮箱隐藏规则，也不编造地址。

## 4. 消息内容与模板

以下业务信息随单笔结果提供，必填表示该事件成立时必须有真实值，不得用演示数据补齐。本册不定义编号编码、传输结构或表结构。

| 业务信息 | 类型、必填与校验 |
| --- | --- |
| 本笔、批次、项目、代币 | 业务标识文本，两事件必有且能定位；本笔取面客单笔申请标识（即正文 `RV-19`），批次取提交批次编号。不能仅靠代币编号定位历次申请，项目名称不能替代项目编号 |
| 收件与业务发生时间 | 发起该笔质押的账号及真实时点，必有；不能取审核员或阅读时刻 |
| `project_name` / `project_id` / `token_id` | 模板使用者必有；沿业务原值，不替换缺项或暴露钱包私钥、持有地址以外的私人账号信息。保持同一笔，不移用其他项目 |
| `approved_at` | `T-LS-01` 必有，为本笔实际通过时点；未通过不造值，不取同批其他笔时间 |
| `reason` | `T-LS-02` 必有，为 `RV-14` 原文；沿正文既定 10～500 字校验，完整可读，不用内部备注代替，不因摘要省略而丢失全文；英文界面不假称人工中文原因已翻译 |

<a id="templates"></a>本册复用面客侧 `T-LS-01`～`T-LS-02` 的完整双语模板，不新建另一组名称；标题和正文为成对文本，变量同名同数量。模板名称沿既有 `msg.<业务类型>.title` / `msg.<业务类型>.body` 约定。`T-LS-03` 随超时事件废止，不再使用、不改作他用。

| 模板 | 中文标题 / 正文 | English title / body |
| --- | --- | --- |
| `T-LS-01` | 质押审核通过 / 项目 {project_name}（{project_id}）的代币 {token_id} 本笔质押申请已于 {approved_at} 审核通过，该代币已按有效性判定计入本项目有效质押额。无需另行确认，平台不收取费用；代币继续留在质押合约内。 | Pledge approved / The pledge application for token {token_id} in project {project_name} ({project_id}) was approved at {approved_at}. Subject to the eligibility check, the token now counts towards this project's effective pledge amount. No further confirmation is required and the platform charges no fee; the token remains held in the pledge contract. |
| `T-LS-02` | 本笔质押申请未通过 / 项目 {project_name}（{project_id}）的代币 {token_id} 本笔质押申请未通过。原因：{reason}。该代币仍在质押合约内，不计入有效质押额；请自助发起解押（gas 由您承担），解押成功后可按当前资格重新申请。其他代币按各自结果处理。 | Pledge application rejected / The pledge application for token {token_id} in project {project_name} ({project_id}) was rejected. Reason: {reason}. The token remains held in the pledge contract and does not count towards the effective pledge amount. Please release it yourself (you bear the gas); once the release succeeds you may reapply subject to current eligibility. Other tokens retain their own outcomes. |

标题、正文、账号或本笔业务事实不足时不得伪造可用消息；非关键跳转配置缺失按框架降级，不把所有缺项一律等同丢弃整条消息。原文原因作为业务文本完整展示，不扩展成其他通知或动作。

## 5. 时效、偏好与依赖

关键结果在真实业务发生后的 **60 秒**内可见，未读计数同步更新；不能把接收完成才作为起点，也不以用户重新取数作为前提。消息失败不回滚已生效结论、不重审、不触发或撤销任何链上动作，业务结果始终可查。本册不设计重试方案。

本期两个审核结果未列入可关闭事件，不自行新增关闭或补送策略；沿消息框架既有偏好规则。分类筛选不是退订，业务进度分类不等于允许屏蔽。没有明确可选事件时不制造新通知来填充开关。

剩余依赖：共享消息分类值与正式登记、端到端时效（部分来源为"60 秒与最坏 5 分钟"）的冲突与真实联验仍在面客消息框架侧，本模块保持 60 秒要求，不声称全平台冲突已解决；发起账号真实对应及客服真实联系方式仍需能力输入。异常升级 / 关闭责任不是本期功能待决；本册不重新建设来源或控制台队列。原多成员收件归属依赖随"一个企业一个员工"闭合。

## 6. 验收要求

沿正文[留痕与通知触发](01-代币质押审核-PRD.md#m7)及 `AC-PR-31`～`32`、`AC-PR-58`，同批 A/B/C 与同代币新发起用于区分单笔事实。以下是可观察结果，不是详细测试步骤。`AC-PR-N02` 随超时事件废止，编号保留占位、不再分配新含义。

| 编号 | 验收结果 |
| --- | --- |
| `AC-PR-N01` 逐笔结果分别触达发起账号 | A 生效通过、B 生效驳回、C 待审，仅发起账号分别收到 A/B 结果；无整批摘要，不等待全批；A 的通过文案明确无需另行确认且平台不收费，B 的原因全文准确并提示需自助解押 |
| `AC-PR-N02` | **本批废止**（原：审核超时通知）。审核无时效，本模块不再有超时事件、超时模板与对应验收；编号保留占位 |
| `AC-PR-N03` 同一事实去重且不互相吞并 | A 同一结果重复到达只有一条消息，不新增未读计数、不改变原有次序或发生时间；A/B 两笔相同结果不相互吞并，重新质押的新结果保留独立历史 |
| `AC-PR-N04` 时点与时区展示一致且无期限类时间 | 两端及消息中的通过时点指向同一时刻并带时区标注；消息中不出现任何截止、剩余时长或倒计时；切换展示时区、夏令时不改变已发生事实，不以阅读时间重算 |
| `AC-PR-N05` 历史消息可读但不误触发办理 | 原消息在业务已变化后仍可按权限读原笔，不可用的动作停止，不误定位同代币新笔；无权者不能读私有结果 / 附件，读消息不完成业务、不触发解押、不解除占用 |
| `AC-PR-N06` 事件范围限于两类审核结果 | 本模块只有通过与驳回两类事件；上链成功、撤回、解押发起与解押结果均不由本模块发送。未知、冲突与客服指引不触发升级、异常处置或运营广播 |
| `AC-PR-N07` 模板变量完整且不泄露内部信息 | 两组中英标题正文变量一致，完整原因保留，不泄露内部备注、私有文件或持有地址以外的私人账号信息；时间缺失、真实客服不可用不以演示值 / 假地址补齐，消息投递失败不回滚已生效业务 |
| `AC-PR-N08` 可见时效以真实投递为准 | 从真实业务发生时点观察 60 秒可见目标；未登记、真实收件依赖或时效冲突如实标未完成，不能以文档模板核对替代实际投递验收；两个结果不因未定义的可选开关被屏蔽 |
