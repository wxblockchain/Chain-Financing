## FL-PR-01 审核与两端结论闭环

规则回查：[M1 队列](v1.0-代币质押审核-PRD.md#m1)、[M2 详情](v1.0-代币质押审核-PRD.md#m2)、[M3 通过](v1.0-代币质押审核-PRD.md#m3)、[M4 驳回](v1.0-代币质押审核-PRD.md#m4)、[M5 到期](v1.0-代币质押审核-PRD.md#m5)、[M7 权限留痕](v1.0-代币质押审核-PRD.md#m7)。

```mermaid
flowchart TD
  A["资产方：提交首笔或追加申请<br/>代币未转入，本次零费用"] --> B["运营端：待审核队列<br/>显示提交时间与审核截止"]
  B --> C["有查询权限的运营：查看申请、代币事实与历史"]
  C --> D["运营：线下完成判定"]
  D --> E{"查询与处置权限有效<br/>申请待审核且未到截止？"}
  E -- "否" --> V["拒绝新结论<br/>显示当前事实或无权说明"]
  E -- "是" --> F{"维护结论"}
  F -- "整单通过" --> G["上传协议，确认通过不等于质押成功"]
  F -- "整单驳回" --> H["填原因，选填点名与标签<br/>预览将发给资产方的全文"]
  G --> I["运营：二次确认并提交"]
  H --> I
  I --> J{"提交生效时仍符合权限、状态及期限？"}
  J -- "否：已裁定、已撤回或已超时" --> V
  J -- "是：通过" --> K["申请：审核通过 · 待入池<br/>保留审核人、时间与协议"]
  J -- "是：驳回" --> L["申请：已驳回<br/>保留审核人、时间与原因"]
  K --> M["面客端：一致显示通过与入池截止<br/>通知资产方回来确认费用和执行"]
  M --> X["后续逐张执行见 FL-PR-02"]
  L --> N["面客端：原样展示驳回原因<br/>正常未执行申请解除占用、零费用"]
  N --> O["资产方：按最新资格重新提交<br/>生成新申请，原申请保留"]
  B -- "截止前资产方撤回已生效" --> P["申请：已撤回<br/>本次零费用，运营不再裁定"]
  B -- "提交满两自然日仍无生效结论" --> Q["平台：自动超时失败<br/>无需任何人点击，不再补审"]
  Q --> R["两端：记录保留，明确未按时审核<br/>本次未产生费用，正常未执行张可重新质押"]
  R --> O
  Q --> S["运营：超时历史与待办可查<br/>旧结论迟到不得翻转"]
```

到期不以是否有人打开页面为条件；弹层打开、上传完成、线下已判定都不能延长截止。正常驳回无链上释放；实际已转入差异另见 FL-PR-03。消息失败不改变已经生效的业务结论。

## FL-PR-02 逐张执行、超时与迟到结果

规则回查：[M6](v1.0-代币质押审核-PRD.md#m6)，承接 WS-351 D-LS-30～33、47；验收 AC-PR-44～47。运营端在以下流程均只读追踪，不代签名、发起或更正。

```mermaid
flowchart TD
  A["申请已审核通过 · 待入池"] --> B["资产方回到面客端<br/>借贷平台复核可质押资格"]
  B -- "复核不通过" --> C["结论已作废<br/>未执行、无费用、协议存档"]
  B -- "复核通过" --> D["资产方获知内容与费用<br/>明确确认承担后发起"]
  D -- "尚未确认或入口不可用" --> E["未发起，不显示处理中<br/>不产生本次执行费用"]
  D -- "已实际发起" --> F["代币发行平台：执行<br/>借贷平台：每张处理中，不计覆盖"]
  F --> G{"每张的结果"}
  G -- "成功" --> H["该张已质押 PS-2<br/>按有效性等规则判断覆盖"]
  G -- "失败" --> I["该张失败，回 PS-1<br/>按资格可新建质押申请"]
  G -- "发起满两自然日无结果：总控延伸" --> J["该张执行超时失败<br/>保留记录，当前沿用回 PS-1 与可重提"]
  H --> K["两端逐张呈现结果、费用与下一步<br/>成功张不因其他张失败回滚"]
  I --> K
  J --> K
  J -- "成功迟到" --> L["原失败不翻转，不自动计入覆盖<br/>相关张标记差异、暂停新动作、运营待办"]
  L --> M["关联旧申请及已发生的新申请事实<br/>不得同时计入两个池"]
  M -. "Q-PR-05" .-> N["差异更正、重提后的处理及恢复权限<br/>待业务与跨平台能力确认"]
  J -. "Q-PR-05" .-> P["安全重提条件与费用缺失的确认<br/>不能由超时推定已转回原地址"]
  A -- "七天届满且未发起执行" --> O["结论已失效<br/>未执行零费用，协议仅存档"]
  F -. "已发起后遇七天届满或项目终态" .-> Q["Q-PR-06：业务优先次序待统一<br/>不得擅自宣称零费用或解除占用"]
```

审核是整单结论，执行是逐张结果；本图的成功、失败、超时可在同一申请中并存。审核两天自申请提交起算；执行两天自该张实际发起起算；入池七天自通过结论起算。该张的终态不代表整单审核变成失败。

## FL-PR-03 驳回与异常释放的适用边界

规则回查：[M4](v1.0-代币质押审核-PRD.md#m4)、[M6 D-PR-27](v1.0-代币质押审核-PRD.md#m6)；验收 AC-PR-48。此图不新增自动释放授权。

```mermaid
flowchart TD
  A["申请驳回或发现驳回关联资产差异"] --> B{"有已转入的事实？"}
  B -- "正常先审核后上链：没有" --> C["结束本次申请占用<br/>无 X-05 链上释放、本次零费用"]
  C --> D["资产方按最新资格重新提交<br/>旧申请保留"]
  B -- "存在真实已转入差异" --> E["异常边界：该张需释放处理<br/>不计覆盖，不可重复质押，保留记录"]
  E --> F["运营详情：关联申请、代币与位置事实<br/>产生需释放处理的待办"]
  F -. "Q-PR-05：触发主体、确认及费用未定" .-> G["需由 X-05 业务能力承接释放<br/>本端不提供代签、代付或手工置成功"]
  G -. "取得合法释放动作的实际结果后" .-> H{"逐张释放结果"}
  H -- "未完成或失败" --> I["只读显示释放未完成及原因<br/>不能声称已归还，不允许再质押"]
  H -- "确认成功" --> J["确认转回质押前原持有地址<br/>借贷平台按最新资格判断能否再质押"]
```

正常通过后的撤回及项目终态业务释放归 WS-351，不走审核驳回。已经通过的申请不可改成驳回来启动本图；旧流程存量是否存在没有被本册预设。虚线仅表示需承接能力，未决前不把它做成可操作的释放按钮。

## ST-PR-01 质押申请 PA-05 的运营视角

规则回查：[M3～M5](v1.0-代币质押审核-PRD.md#m3)、[正文状态表](v1.0-代币质押审核-PRD.md#states)。这里引用 WS-351 申请状态，不另定义代币状态。

```mermaid
stateDiagram-v2
  state "待审核" as Pending
  state "审核通过 · 待入池" as Approved
  state "已驳回" as Rejected
  state "已撤回" as Withdrawn
  state "超时失败" as Timeout
  state "结论已失效" as Expired
  state "结论已作废" as Voided
  state "已入池" as Settled
  [*] --> Pending: 资产方提交
  Pending --> Approved: 截止前运营有效通过且协议齐备
  Pending --> Rejected: 截止前运营有效驳回且原因齐备
  Pending --> Withdrawn: 资产方有效撤回
  Pending --> Timeout: 满两自然日无有效结论，平台自动判定
  Approved --> Expired: 七天未入池且未发起执行的明确分支
  Approved --> Voided: 入池前复核不通过
  Approved --> Settled: 引用 WS-351，代币按张结算完毕
  Rejected --> [*]
  Withdrawn --> [*]
  Timeout --> [*]
  Expired --> [*]
  Voided --> [*]
  Settled --> [*]
```

“已入池”引用输入现名，必须附逐张结果，不表示全部成功；全失败 / 混合执行超时汇总状态及已执行跨七天边界有歧义，见 Q-PR-06，未在图中擅定。Timeout 专指审核自动超时，不把某张执行失败串成整单驳回。所有重新提交都是另一份申请，不画回到原 Pending 的箭头。

## ST-PR-02 一张代币的一次转入执行结果

规则回查：[M6 D-PR-25～26](v1.0-代币质押审核-PRD.md#m6)；验收 AC-PR-44～47。状态主体是一张代币的一次执行，审核结论、PS 质押事实、差异标记分别保留，不能合并成一个审核状态。

```mermaid
stateDiagram-v2
  state "未发起 CT-0" as NotStarted
  state "处理中 CT-1" as Processing
  state "成功 CT-2" as Succeeded
  state "失败 CT-3" as Failed
  state "执行超时失败（失败原因）" as TimedOut
  [*] --> NotStarted
  NotStarted --> Processing: 有效通过、复核合格、资产方确认并实际发起
  Processing --> Succeeded: 该张成功结果确认
  Processing --> Failed: 该张失败结果确认
  Processing --> TimedOut: 两自然日无结果，沿用总控延伸
  Succeeded --> [*]
  Failed --> [*]
  TimedOut --> [*]
  note right of TimedOut
    原失败终态保留
    成功迟到另记差异事实
    不翻转本次结果
    暂停相关张新动作，不计覆盖
    后续处理见 Q-PR-05
  end note
```

成功张不因其他张失败回滚；处理中只限制该张，不锁整个项目。执行超时后回 PS-1 是 WS-351 当前衔接口径，不能解读为已证明链上资产位置。新申请、新执行不覆盖旧记录；不得从 TimedOut 直接画回 Succeeded 来表示迟到成功。
