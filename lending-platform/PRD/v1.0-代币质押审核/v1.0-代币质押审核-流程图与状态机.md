## FL-PR-01 批量提交、逐笔审核及两端结果

规则回查：[M1 队列](v1.0-代币质押审核-PRD.md#m1)、[M2 详情](v1.0-代币质押审核-PRD.md#m2)、[M3 通过](v1.0-代币质押审核-PRD.md#m3)、[M4 驳回](v1.0-代币质押审核-PRD.md#m4)、[M5 时限](v1.0-代币质押审核-PRD.md#m5)、[M7 通知](v1.0-代币质押审核-PRD.md#m7)。

```mermaid
flowchart TD
  A["资产方批量提交 A / B / C"] --> B["一个批次、三笔独立待审申请<br/>各笔关联批次与代币，共用提交时点"]
  B --> C["运营逐笔查看事实与批次上下文<br/>线下判断，线上维护当前笔结论"]
  C --> D{"当前笔待审、未到截止<br/>查询与处置权限有效？"}
  D -- "否" --> E["不能提交结论<br/>展示当前事实或无权说明"]
  D -- "是" --> F{"仅裁定当前笔"}
  F -- "通过" --> G["通过本笔申请表单<br/>上传本笔协议、知悉通过不等于质押成功"]
  F -- "驳回" --> H["填写本笔原因并全文预览"]
  G -- "点击通过本笔申请，直接提交" --> I["提交生效时仍满足材料、权限、状态与期限<br/>提交中不可重复，失败保留本笔输入"]
  H --> R["驳回二次确认对象及原因"]
  R --> I
  I -- "条件已变化" --> E
  I -- "本笔通过" --> J["本笔留存审核人、时间与协议<br/>独立七天入池期限开始"]
  I -- "本笔驳回" --> K["本笔留存审核人、时间与原因<br/>正常未执行则零费用、结束占用"]
  J --> L["面客立即展示并通知本笔通过<br/>可独立确认执行，不等全批审完"]
  L --> X["后续执行见 FL-PR-02"]
  K --> M["面客原样展示本笔原因<br/>可按资格只重提相关张，旧笔保留"]
  B -- "资产方有效撤回待审笔" --> N["仅本笔已撤回<br/>零费用，不可补审"]
  B -- "提交成功起满连续 48 小时，仅仍待审笔" --> O["自动质押失败（审核超时）<br/>保留记录，不得迟到补审"]
  O --> P["逐笔通知未按时审核、本次零费用<br/>正常未执行张可按资格再次质押"]
  J --> V["回到本笔概览<br/>底部操作记录展示通过及待确认进度，见 FL-PR-04"]
  J --> Q["批次只汇总单笔进度与数量<br/>其他笔待审、驳回或超时不回滚已审笔"]
  K --> Q
  N --> Q
  O --> Q
```

同批可以 A 通过、B 驳回、C 待审；不同运营可分别办理不同笔，同一笔只有一个生效结果。共用协议须确实覆盖各笔并逐笔明确选用，不自动通过。切换当前笔不能携带上一笔未提交材料或原因。

48 小时审核时钟自批次提交成功起算，局部审核、上传、弹层打开均不延长期限。超时只影响未审笔，不把同批已执行费用改为零。每笔通知独立定位，不以批次及结论类型合并掉另一笔。批次统计只供追溯，面客主清单始终按代币；同项目跨提交勾选，不按批次要求分别确认，见正文 D-PR-33。

## FL-PR-02 已通过代币批量确认、执行及未知结果

规则回查：[M6](v1.0-代币质押审核-PRD.md#m6)、[M5](v1.0-代币质押审核-PRD.md#m5)；验收 AC-PR-44～47、53、56。运营在概览底部操作记录列表只读追踪，详见 FL-PR-04；后续变化不改写人工“通过”。

```mermaid
flowchart TD
  A["当前单笔审核通过<br/>自己的协议、通过时间与七天截止"] --> B["资产方回到面客端<br/>借贷平台复核本笔资格"]
  B -- "不通过" --> C["仅本笔入池许可作废<br/>历史与协议存档，未执行无费用"]
  B -- "通过且仍有效" --> D["资产方确认本次对象与逐张费用<br/>同项目跨提交按代币勾选，内容费用合并一次确认"]
  D -- "未实际发起" --> E["仍未发起，不产生执行费用"]
  D -- "资格变化：更新选择费用，再明确确认" --> D
  D -- "实际发起" --> F["发行平台执行本张<br/>本笔处理中，相关张不得重复发起"]
  F --> G{"本次实际结果"}
  G -- "成功确认" --> H["本笔成功<br/>满足有效性等既有资格才计覆盖"]
  G -- "失败确认" --> I["本笔失败<br/>无占用且资格允许时可新笔申请"]
  G -- "尚无明确结果" --> J["保持等待与已知事实<br/>不能推定失败、零费用或已回原地址"]
  H --> K["两端逐笔呈现结果与实际费用<br/>其他笔失败不回滚成功笔"]
  I --> K
  J -. "Q-PR-05A：阈值与收口待裁定" .-> U["推荐逾期待核实、暂停相关张重押<br/>核实失败且无占用后才可重提"]
  F -- "迟到结果与原记录冲突" --> L["保留原记录，关联本笔与已有新申请<br/>暂停该张新动作，不自动翻转或双池计覆盖"]
  L -. "Q-PR-05A" .-> N["差异关闭责任待定<br/>异常释放不在本期，不增代付或置成功动作"]
  A -- "本笔七天届满仍未发起" --> O["仅本笔入池许可失效<br/>保留审核历史、协议存档，未执行零费用"]
  F -. "已发起后遇七天届满或项目终态" .-> P["Q-PR-06 待裁定<br/>不先解除在途占用，不宣称零费用"]
```

两笔先后通过有各自七天截止；后通过 B 不刷新 A。普通晚到且不与原记录冲突的真实结果按本次执行归属呈现；只有相冲突的事实进入差异处理。旧执行两天失败规则尚未裁定，图中没有自动失败、自动放开重押分支。

## FL-PR-03 审核失败释放占用与正常退出边界

规则回查：[M5 审核期限](v1.0-代币质押审核-PRD.md#m5)、[M6 D-PR-32](v1.0-代币质押审核-PRD.md#m6)；验收 AC-PR-48、59～61。异常释放移出本期，不画补偿或处置流程。

```mermaid
flowchart TD
  A["单笔提交成功、仍待审"] --> B{"提交后连续 48 小时<br/>是否已有有效审核或撤回？"}
  B -- "已有通过、驳回或撤回" --> C["保持该笔事实<br/>不按未审超时回退"]
  B -- "到期仍待审" --> D["自动质押失败：48 小时未完成审核<br/>保留记录，释放该笔申请占用"]
  D --> E["代币从未上链，PS-1 可按资格再申请<br/>无 gas、无退款、无待提取"]
  F["另一个正常已入池代币"] --> G["额度允许撤回或项目终态正常退出<br/>沿 WS-351 解除质押及自助提取"]
```

仅查看、上传或编辑不算审核完成，不重置 48 小时。同批其他笔不受影响。正常退出使用原有 WS-351 规则；本图不将审核失败说成从合约转回。审核与真实转入冲突后的异常释放入口、待办、进度及费用均不在本期。

## ST-PR-01 单笔审核轴 RV-20

规则回查：[M3～M5](v1.0-代币质押审核-PRD.md#m3)、[状态与 D-PR-31](v1.0-代币质押审核-PRD.md#states)。WS-351 PA-05 已同步为单笔审核轴，PA-11 对应 RV-19；见正文 [9.2](v1.0-代币质押审核-PRD.md#open-items)。

```mermaid
stateDiagram-v2
  state "待审核" as Pending
  state "通过" as Approved
  state "驳回" as Rejected
  state "已撤回" as Withdrawn
  state "质押失败（审核超时）" as Timeout
  [*] --> Pending: 批次提交中生成本笔
  Pending --> Approved: 截止前本笔表单直接有效提交通过且协议齐备
  Pending --> Rejected: 截止前本笔有效驳回且原因齐备
  Pending --> Withdrawn: 资产方有效撤回仍待审的本笔
  Pending --> Timeout: 提交成功起满连续 48 小时仍未审，自动终结本笔
  Approved --> [*]
  Rejected --> [*]
  Withdrawn --> [*]
  Timeout --> [*]
  note right of Approved
    本图仅结束审核轴
    无通过二次确认状态
    复核、许可过期及执行记入概览底部操作记录
    不将历史通过改为驳回或执行成功
    本笔可先执行，不等同批其他笔
  end note
```

撤回、审核超时没有人工审核人或伪造的人工结论。重新申请生成新笔，不回到原 Pending。七天未发起失效、复核不通过只影响本笔入池许可及凭据关联，保留原人工审核事实。

批次无“整批通过 / 驳回”状态机。全部待审＝待审核；部分待审且已有笔终结审核＝审核进行中；没有待审＝审核已结束。审核五类数量之和等于总笔数；执行摘要独立汇总已通过笔的未发起 / 处理中 / 成功 / 失败，差异标记不重复加入总数。详见正文 D-PR-31、AC-PR-57。

## ST-PR-02 单笔转入执行结果 CT

规则回查：[M6 D-PR-25～26](v1.0-代币质押审核-PRD.md#m6)；验收 AC-PR-44～47、56。本轴不替代审核结论、PS 事实或差异标记；发生后的进度按 FL-PR-04 展示，不因合入操作记录而改变流转条件。

```mermaid
stateDiagram-v2
  state "未发起 CT-0" as NotStarted
  state "处理中 CT-1" as Processing
  state "成功 CT-2" as Succeeded
  state "失败 CT-3" as Failed
  [*] --> NotStarted
  NotStarted --> Processing: 本笔有效通过、复核合格、资产方确认并实际发起
  Processing --> Succeeded: 本次真实成功结果确认且无冲突
  Processing --> Failed: 本次真实失败结果确认且无冲突
  Succeeded --> [*]
  Failed --> [*]
  note right of NotStarted
    未审或驳回不可发起
    过期或复核作废仍未发起
    另显原因，不假报执行失败
  end note
  note right of Processing
    无结果不能直接判失败
    相关张不得重复发起
    逾期收口见 Q-PR-05A
    已发起跨七天见 Q-PR-06
  end note
  note right of Failed
    冲突迟到结果另记差异
    不自动翻转历史结果
    不自动开放重押或双池覆盖
    差异关闭见 Q-PR-05A
  end note
```

成功张不因同批其他张失败回滚；未知费用标待核实；新笔新执行不覆盖旧记录。本图只确定实际结果的正常流转，未画“执行两天＝失败”已定边。冲突迟到事实遵循 FL-PR-02 的差异保护，关闭须先完成业务决策。
