## 3. 业务目标、对象与角色

目标：资产方一次提交多张，运营逐笔维护结论；同批不同代币可以由不同运营人员在不同时间通过或驳回，已通过的单笔可独立进入后续确认，不等整批审完。

**对象口径 D-PR-29（逐笔审核的统一来源）**：

| 对象 | 含义与范围 |
| --- | --- |
| 提交批次 | 资产方一次面客提交形成的分组；同一资产方、同一融资项目、同一申请类型及提交时间；沿用 PA-01 批次定位及 PA-02 / 03 / 04 的关联。批次含一笔或多笔 |
| 单笔质押申请 | 批次内**一张代币的一次质押申请**。具有稳定单笔标识，关联批次与代币编号；是审核、撤回、截止、协议、原因和通知的最小单位。标识的编码格式不在 PRD 定义 |
| 单笔审核结论 | 每笔至多一个有效人工结论：通过 / 驳回；时间、审核人、协议或原因各自独立。未审、撤回、审核超时均没有伪造人工结论 |
| 单笔执行结果 | 仅这笔审核通过、资格复核合格、资产方确认后才有执行；成功、失败、未有结果与审核结论分开，不改写“通过” |
| 批次进度 | 只做单笔事实的数量汇总，不再有统管全批的通过 / 驳回结论、审核人、结论时间、原因、入池截止或“已入池”终态；详见第 7 章 |

同一批次内一张代币只能出现一笔，仍为整张质押，不拆数量。再次质押是新的提交及新的单笔标识，保留与原记录的关联，不复用原结论。同一代币在不同提交中的记录不可仅凭代币编号合并。单笔审核态属于质押业务申请，不写回代币本体。

| 参与方 | 本模块责任 |
| --- | --- |
| 运营人员 | 按功能权限查看全部单笔；在线下判断后，在线逐笔提交证据与结论；不按运营机构隔离 |
| 资产方 | 面客批量提交，查看每笔结论；撤回仍待审的单笔，确认各已通过笔的费用和执行；可将同一项目、不同提交中的合格代币一同确认；清单一行一张当前代币，历史按笔可查，不能带入未审 / 驳回笔 |
| 借贷平台 | 拥有申请、质押记录和 PS 质押事实；提供逐笔期限、入池前复核、结果消费及覆盖判定 |
| 代币发行平台 | 拥有代币事实并承担链上执行；按张提供结果，运营审核无代币维护权 |

本期两个页面：P-O-PR-01 审核队列，P-O-PR-02 单笔审核详情（可查看批次上下文）。保留协议上传、历史、时限、通知与执行结果只读追踪；本期不考虑异常释放，不提供其待办、发起、进度、费用或恢复资格流程。不新增批量一键通过 / 驳回、双人复核、转派、风控评分、原型、链上代签代付、对账更正台、清算或协议模板库。

## 5. 功能需求说明（开发主阅读）

<a id="m1"></a>
### 5.1 M1 单笔审核队列

前置为正常运营账号且有 PM-AL-07 查询权限；侧栏“质押审核”进入 P-O-PR-01。列表**一行一笔代币质押申请**，不是一行批次；同批关系可识别。独立队列不依附已移交的代币管理。列表仅提供查看，不提供多选裁定。

| 内容 | 产品规则 |
| --- | --- |
| 默认 | 单笔审核状态＝待审核，批次提交时间升序；同时间按稳定单笔顺序，刷新不跳动。不做风险优先排序 |
| 筛选 F-PR-03 / D-PR-14 | 审核状态（全部 / 待审核 / 通过 / 驳回 / 已撤回 / 质押失败（审核超时））、资产方、项目、申请类型（全部 / 建池首笔 / 追加）、提交时间范围、关键词（批次编号 / 单笔标识 / 代币编号 / 企业名）。默认除待审核外均为空或全部；组合生效，起止含边界，起点不得晚于终点；关键词忽略首尾空白 |
| 后续情况筛选 | 全部 / 待确认入池 / 复核作废 / 未发起已过有效期 / 执行中 / 执行成功 / 执行失败 / 结果待核实 / 对账差异，命中相应单笔；不是新增人工审核结论 |
| 列 | 单笔标识、批次编号、代币编号、资产方、目标项目、申请类型、该张代币价值（USD）、提交时间、审核等待及截止、审核状态、后续情况、查看。批次合计不得冒充这一张价值 |
| 三张统计卡 F-PR-02 | 待审核**笔数**、质押失败（审核超时）**笔数**、近 7 个自然日人工审结**笔数**。应用主体 / 项目 / 类型 / 提交时间 / 关键词条件，不应用状态和后续情况筛选；各卡按自身状态定义计数并标明范围。人工审结只计通过 / 驳回，不计自动超时 |
| 排序与分页 F-PR-04 | 提交时间、审核等待、单张价值可升降序；带总数常规分页。筛选改变回首页、重置回默认。页容量沿用平台现行组件值，不另造值。返回与后退保留筛选、排序、页码；原页为空回最后有效页并说明 |
| 空与失败 | 待审为空、筛选无结果、读取失败分别反馈；失败可重试，不假报 0。无查询权限不显示入口，直接访问亦拒绝 |

F-PR-05：点某行详情只进入该笔 P-O-PR-02；已结论或终结仍可只读回看。批次含 3 笔只审 1 笔后，待审数减少 1，另 2 笔仍在队列。流程见 [FL-PR-01](v1.0-代币质押审核-流程图与状态机.md#fl-pr-01)。

### 5.2 M2 单笔事实与批次历史

D-PR-20 / 21：线下完成判定，线上维护证据与结论。页面中性说明“本页信息供线下判定参考，结论由审核人线下作出后在此维护”；不提供评分、风险灯、建议通过 / 驳回、自动筛出不合格资产。格式必填、权限、状态及截止校验照常生效。

| 区块 / 字段 | 业务含义、类型、必填与校验 |
| --- | --- |
| 单笔定位 RV-19 | 稳定文本标识，提交成功即有；关联一个批次、一个代币、一家资产方、一个项目；只读，无默认空值。重新提交生成新标识 |
| 批次上下文 | PA-01 批次编号、PA-02 项目、PA-04 首笔 / 追加、PA-06 提交时间必有，只读；完整 PA-03 清单可查，不能修改；本笔清晰定位，不将批次所有代币列为本次裁定对象 |
| 资产方与项目 | 企业名称、稳定主体标识、项目编号 / 名称 / 状态 / 类型；只读，不以名称替代归属判定。缺失标“待核实”，不得猜测，见 Q-PR-07 |
| 本张代币事实 | 编号、数量及币种、USD 代币价值、底层账期、买方企业、有效 / 已失效状态；读取同一只读代币域，缺失不用 0 或“有效”填充，不二次折算 |
| 审核信息 | 本笔 RV-20 审核状态、RV-03 人工结论（存在时）、RV-04 结论时间、RV-07 / 08 审核人、协议或驳回原因；不同笔各自展示 |
| 期限 | 本笔审核截止 RV-15；通过后的入池截止 RV-22；名称和时区明确，不能给全批一个通过时间或入池倒计时 |
| 后续信息 | 本笔复核 RV-21、执行及差异结果在概览底部操作记录中作为进度呈现，见 D-PR-34 与 M6。尚无结果标未复核 / 未发起 / 暂无结果，不编造失败 |

F-PR-08：同项目同资产方的历史按提交批次可回溯，进入后逐笔看代币、状态、审核人、时间、原因全文及关联的再申请。单笔事件按发生时间倒序；没有人工结论的终结显示撤回 / 自动超时及发生时间，不冒充人工裁定。摘要可收起，详情原因必须完整。跨项目再申请仅在有明确关联时展示，不凭代币相同推定关联。

**D-PR-34 / F-PR-06、08、13、18 操作记录与进度的统一入口**：P-O-PR-02 的“概览”在申请信息、代币事实、审核结论与凭据之后，以“操作记录”列表作为最下方内容区；不再以独立“操作记录”页签承载。关联申请保留原入口；旧操作记录入口进入当前笔概览并定位该列表，不丢失单笔或返回队列上下文。审后“后续情况”详情合并至列表，不另设重复明细卡；队列的后续情况筛选、必要的当前状态及入池截止摘要仍可保留，均与列表同源。

| 列表内容 | 含义与展示要求 |
| --- | --- |
| 事件 / 进度 | 必有文本，区分提交、审核通过 / 驳回、撤回、审核超时，以及通过后的复核、待确认入池、许可失效、执行与差异；只展示本笔事实，不混入同批其他笔 |
| 发生时间 | 已发生事件展示真实时间与时区；按发生时间倒序，同时间保持稳定顺序。时间暂缺标“待核实”，不得用页面打开时间代替；未发生的步骤不生成完成记录 |
| 操作主体 | 人工事件显示当时审核人；自动事件标“系统”，来自资产方的动作标“资产方”；未提供主体时标“待核实”，不推定为审核人 |
| 结果与说明 | 该事件的结果、前后状态及原因；原因可展开全文。进行中明确“处理中”及已知事实，未来步骤不预写成功；详情字段按 M6 展示 |
| 关联凭据 | 有则提供对应本笔的协议或执行凭据，遵守权限及文件规则；没有则说明暂无，不伪造材料或重复关联其他申请 |
| 列表反馈 | 加载、暂无记录、读取失败分别展示；失败可重试且不伪装为空。记录只读，不提供编辑、删除或手工完成进度动作 |

历史事件与当前进度均可查，新增进度不覆盖原审核事实；同一业务事件重复到达只显示一次，不因刷新重复插入。关联申请历史与本笔操作记录范围分开。流程见 [FL-PR-04](v1.0-代币质押审核-流程图与状态机.md#fl-pr-04)。

同批不同笔可直接查看或切换；切换前有未提交输入需选择留在当前笔继续编辑或放弃后切换，不提供跨笔自动保存草稿，不能将上一笔原因、协议选择、备注及确认勾选自动带入下一笔。通过 / 驳回弹层始终回显单笔、代币、批次和项目。已审笔只读，**不使同批待审笔只读**。

D-PR-15 / 16：入池前复核只读，不提供运营复核按钮；审核不读取或修改覆盖派生量。代币失效、项目终结显示客观事实，不自动替审核人驳回，也不保证该笔后续能入池。实际入池仍受面客资格判定。

### 5.3 M3 逐笔通过与协议维护

**D-PR-01**：每次审核针对当前单笔。可以只通过批次内 A、驳回 B、保留 C 待审；不再要求整批同结论。通过 A 不代表批准 B/C，其他笔无需重新提交或重新计时。本期不提供一次点击为多笔生成结论。

**D-PR-35 通过直接提交**：前置为有查询与处置权限，当前笔仍待审核且未到截止。线下判定后：本笔“通过” → C-O-PR-01“通过本笔申请”回显本笔代币、项目、批次 → 上传本笔适用协议 → 可填内部备注 → 在同一表单勾选知悉通过不等于质押成功 → 点击“通过本笔申请”直接提交。删除通过路径的“核对结论 / 确认审核结论”后续步骤，不再弹二次确认，不新增第二位审核人。此调整不改变 M4 驳回的原因预览与二次确认，也不改变资产方面客入池确认。

提交前取消不产生结论，跨笔不携带材料；提交中明确反馈且不可重复点击。材料、权限、状态或截止不满足时就地说明，不产生通过记录；保存失败保留当前笔有效输入可重试。结果不确定先查当前事实，不展示成功或引导重复裁定。成功后关闭表单、回到本笔概览，结论及底部操作记录出现本次通过，当前笔只读，其他待审笔仍可办理。

### 5.4 M4 逐笔驳回与唯一结论

前置与通过相同。本笔“驳回”打开 C-O-PR-02：回显本笔代币 → 填原因，可选归类 → 完整预览 → 二次确认对象及原因 → 提交。**D-PR-02 / 10**：驳回只结束本笔，原因针对本笔；同批 A 通过、B 驳回、C 待审是正常结果，资产方可只重新申请 B，不重复提交 A/C。

| --- | --- |
| RV-13 原因说明 | 驳回必填自由文本，去首尾空白后 10～500 字，禁止纯空白或仅标点；默认空。平台不改写措辞或判断真伪 |
| RV-12 问题代币标注 | 本笔代币只读回显，取 RV-19 所关联代币，不再从全批勾选问题子集；不能借此驳回其他笔 |
| RV-11 归类标签 / D-PR-22 | 选填、默认空：代币归属或主体存疑 / 底层应收账款存在问题 / 代币与目标项目不匹配 / 申请材料不完整或不一致 / 其他。仅统计，不影响是否可提交 |

D-PR-07：同笔并发，只先有效完成的一次裁定生效；后者展示本笔已有结论、时间与审核人，不覆盖。**不同笔并发互不争抢整批结论**，A/B 可分别成功提交。重复同笔同次操作不增加结论、不改时间、不重复通知。结果不确定先显示待确认并可查当前事实，不引导重新制造结论。

D-PR-12：两端按稳定单笔标识同步该笔结论、时间、原因；批次仅汇总。不因某笔结论而覆盖批次其余笔的待审、驳回或通过结果。已撤回、审核超时或已有人工结论的笔不能再裁定，旧弹层提交亦拒绝。正常未执行驳回仅解除本笔申请占用，本次零费用，不触发 X-05；实际已转入差异仅只读及保护限制，本期不提供异常释放，不将已通过改成驳回来启动新动作。

### 5.5 M5 逐笔时限与撤回

N-PR-01 / D-PR-08：审核时限为**提交成功时点起连续 48 小时**，按实际经过时长判定，不按自然日、工作日或本地午夜计数；展示时区不改变截止时刻。批次内各笔继承同一提交时间与审核截止；点开审核、切换、某笔裁定都不重置其余笔时钟。具体展示时区沿平台规范，七天入池期限的业务时区仍见 Q-PR-04。

| 字段 / 时钟 | 规则 |
| --- | --- |
| RV-15 本笔审核截止 | 时间，提交成功必有、只读，取批次提交成功时点加 48 小时；队列及详情展示明确时点与时区 |
| N-PR-02 已等待 | 待审笔从提交起计；不足 1 小时按分钟、不足 24 小时按小时、之后天＋小时；人工结论、撤回或审核超时生效即停止审核等待 |
| RV-16 审核超时事实 | 本笔到期无结论才产生：发生时间＋“48 小时未完成审核”；自动事件无人工审核人、无伪造驳回 |
| D-PR-09 入池有效期 | 各笔从自己的通过时间起 7 个自然日；先通过的 A 不因后来 B 通过延长，也不从批次提交起算。已执行跨期问题见 Q-PR-06 |
| 执行等待 | 仅实际发起后按该笔起算，独立于审核 48 小时和入池七天；执行逾期取值及处置尚待 Q-PR-05A，不自动套审核期限 |

D-PR-23：到达审核截止，仅仍待审笔自动质押失败（审核超时）；截止前已通过 / 驳回 / 撤回的笔保持原结果。正在上传、提交尚未生效、线下已决定但未在线提交均不算已审核；恰在截止提交也不能补审。已生效撤回不改成超时；先超时后不能补撤回。每笔只有一个有效审核结果，不影响同批其他笔。

D-PR-24：本笔审核超时记录保留；正常未执行张解除该笔待审占用，保持 / 恢复 PS-1，按最新资格可立即重新提交到同一或其他项目，无冷却。旧笔不恢复、不删除，新笔新标识、新提交时点。其他独立占用、失效或差异仍约束可选性，不能由旧笔到期覆盖。

资产方可在面客端撤回仍待审的单笔；如支持多选撤回，只可逐项列明当前可撤回代币，已裁定笔不纳入，不得撤销整批全部结果。撤回与审核同笔竞合只生效一个结果，其他笔照常。单笔通过后不再提供“撤回申请”，已质押后的资产退出仍属 WS-351 解除质押。

例如同批 A 已通过并执行、B 已驳回、C 仍待审：截止只使 C 超时、释放 C 的本次占用，不能回退 A、重写 B 或对全批宣称零费用。审核驳回 / 超时零费用的表述只指该笔本次未执行申请。C-O-PR-04 分别显示审核截止、入池截止和执行等待。图见 [ST-PR-01](v1.0-代币质押审核-流程图与状态机.md#st-pr-01)。

### 5.6 M6 单笔执行结果与释放边界

F-PR-18 / D-PR-25：一笔通过即可由资产方确认该笔，无需等同批未审笔。执行资格仅限自身有效通过、复核合格、未重复占用且未发起的笔；资产方可从代币维度清单中，跨提交批次选择同一项目的多个合格代币；一张仅对应当前有效单笔，历史申请独立可查。项目、代币、逐张费用及合计在一个确认弹窗核对，点击一次确认即发起，不再重复费用确认。列表须明确本次参与张数、逐张对象和费用，**未审、驳回、撤回、审核超时、失效 / 作废笔不得被批次通过摘要带入执行**。本端只读追踪，不提供代签、代付、重发或改代币 / PS / CT 的能力（D-PR-11）。

审核通过后的复核、待确认、未发起到期、执行与差异均作为概览底部操作记录的进度（D-PR-34）。通过即记录“审核通过 / 待资产方确认入池”，不伪造确认或执行事件；实际发生后追加对应进度，已有审核记录保留。每项进度可展开查看下表的时间、原因、费用及凭据，原独立后续情况明细不再重复承载。

RV-21 为本笔入池前复核：未复核 / 通过 / 不通过及原因，默认未复核，发生后只读。复核不通过仅使该笔结论不可用于入池，保留人工审核历史、文件存档；该笔未执行、无费用。复核其他笔仍可通过，不取消全批。入口不可用且未实际发起，不标处理中或执行失败。

| 逐笔执行字段 | 业务含义及校验 |
| --- | --- |
| 关联 | 单笔标识、批次、项目、代币必有、只读；不能仅用批次和一个结果定位 |
| 执行状态 | 未发起 / 处理中 / 成功 / 失败，分别承接 CT-0～3；实际发起后才处理中；无结果不擅填失败。“结果待核实”为事实提示，不自造 CT 终态 |
| 时间 | 实际发起、确认完成、发现差异的各自时点及业务时区；没有结果不伪造完成时间 |
| 原因与下一步 | 执行失败或差异有可读原因；处理中不能重复发起；普通已确认失败且无占用、资格允许可新建申请；差异须先处理 |

| RV-17 差异事实 | 相关单笔、代币、原记录、迟到或冲突事实与发现时间；无差异不生成；不得关联到同代币的新申请而覆盖旧事实 |
| RV-18 释放跟踪 | 本期停用、编号保留；不新增异常释放跟踪字段、待办或操作。正常解除质押的展示使用 WS-351 既有记录 |

**按张执行独立**：人工通过 A/B 后若 A 执行成功、B 执行失败，二者审核结论仍通过，后续结果不同；B 不影响 A。成功张还须满足有效性等既有规则才计覆盖，待审、通过待执行、处理中和差异均不计覆盖。只约束相关张，不锁全项目。

**D-PR-26 执行未知、逾期与迟到事实**：没有执行结果时，运营明确看到“处理中 / 结果待核实”、已等待时长和已知费用事实，不能以无结果证明已失败、已转回或可再次质押。原 WS-351 的“执行两天即失败并开放重押”只记录为待裁定旧建议，不作为本册已确认验收前提；阈值及收口方案见 Q-PR-05A。

仍在等待且没有相冲突记录的晚到结果，按本笔实际执行结果呈现，不仅因等待较久就视为差异。出现与原记录冲突的迟到成功时，沿已明确的差异保护建议：保留原记录、关联本笔，不自动改回已质押、不重复计入覆盖，暂停该张新动作并形成运营待办；如已有新申请或新池，全部关联事实可查，不覆盖新单、不双池计入。其他无差异张继续正常。迟到信息不重复制造转移或费用，运营无手工置成功 / 恢复按钮；差异关闭的跨平台责任仍待 Q-PR-05A；异常释放流程不在本期。

**D-PR-27 / D-PR-32 释放语义与本期范围**：

| 场景 | 本期范围及可观察结果 |
| --- | --- |
| 本笔提交后连续 48 小时无有效通过 / 驳回、仍待审 | 自动显示“质押失败（审核超时）”，原因说明 48 小时未完成审核；释放该笔申请占用，代币从未转入，不产生 gas、不执行 X-05，不进入 PS-4 待提取。原记录保留、可按最新资格再次质押 |
| 查看详情、上传材料或编辑未提交 | 不算完成审核，不重置 48 小时；截止前有效通过 / 驳回 / 撤回的笔不再超时。不是每次点击后重新计 48 小时 |
| 正常未执行驳回 / 待审撤回 | 解除对应笔申请占用、零费用，不作链上释放 |
| 正常入池后的额度允许撤回、项目终态业务释放及自助提取 | 仍在 WS-351 范围；PS-4 待提取与审核失败解除占用区分，不因本次排除异常释放而删除正常退出 |
| 审核记录与已转入事实冲突后的异常释放 | **本期不做**。不设计异常释放入口、待办、自动转回、费用分配或恢复资格流程；不将其列为本期待确认后必须补齐的功能。已有事实差异只读与不重复操作限制保留，不代表支持异常释放 |

**D-PR-33 面客按代币组织与批量确认**：清单以代币为单位，不以提交分组要求资产方逐批操作；同项目不同提交的合格笔可一起确认，未通过笔不可混入。同一确认内逐笔保留原结论、协议与截止；不生成新审核结论、不重置计时。提交前资格变化要指出失效张、更新选择与费用，在同一个弹窗由用户再次明确确认当前集合后才发起，不能静默少执行一张或多收费用。具体面客规则同源于 [WS-351 D-LS-49～51](../v1.0-借贷广场-融资需求与代币质押/01-功能需求说明.md#943-按代币查看审核结果与撤回f-ls-21)。

流程见 [FL-PR-02](v1.0-代币质押审核-流程图与状态机.md#fl-pr-02)、[FL-PR-03](v1.0-代币质押审核-流程图与状态机.md#fl-pr-03)；执行轴见 [ST-PR-02](v1.0-代币质押审核-流程图与状态机.md#st-pr-02)。

## 7. 状态与字段的统一口径

**审核轴 RV-20（枚举，必有，默认待审核）**：待审核 / 通过 / 驳回 / 已撤回 / 质押失败（审核超时）。通过和驳回是人工结论，撤回和审核超时是未获人工结论的终结事件。通过后复核、执行变化不把 RV-03 的历史“通过”改成驳回。

| 对象与状态 | 触发及允许行为 |
| --- | --- |
| 单笔待审核 | 提交后未终结；有权限且未到期可裁定；面客可撤回本笔 |
| 单笔通过 | 在通过表单一次有效提交＋协议，不经过二次确认；可进入本笔复核与资产方确认，运营不得二次裁定 |
| 单笔驳回 | 有效提交驳回＋原因；保留记录，结束本笔占用；可新笔再申请 |
| 单笔已撤回 | 资产方待审时有效撤回；无补审、不收费 |
| 单笔质押失败（审核超时） | 本笔到审核截止仍无有效人工结论；自动失败，不能迟到补审 |
| 通过后：待确认入池 | 有效通过且未发起；按本笔入池截止判断 |
| 通过后：结论已作废 | 本笔复核不通过；不执行，原审核与协议存档 |
| 通过后：结论已失效 | 已到本笔七天期限且未发起执行的明确分支；已执行跨期见 Q-PR-06 |
| 通过后：执行中 / 成功 / 失败 | 本笔实际结果；成功且满足资格才是本张已入池；失败不把同批成功笔回滚 |
| 差异 | 并列事实标记，不覆盖人工审核结论；恢复动作必须有对应业务处置依据 |

**D-PR-31 批次汇总**：审核进度仅使用“待审核”（全部未处理）、“审核进行中”（仍有待审且至少一笔已终结审核）、“审核已结束”（无待审）。同时列待审、通过、驳回、撤回、质押失败（审核超时）五类笔数，合计等于本批总笔数；“审核已结束”不等于全部通过或质押成功。

执行摘要另列未发起、处理中、成功、失败的笔数，合计取已获通过的笔；复核作废、过期未发起在未发起类别中给明细原因，差异等为可叠加标记、不重复加总。对于尚未得到明确执行结果的张，不能算入失败或成功。“全部已入池”仅全批每笔都实际成功、满足有效性等入池资格且无待核实事实时才可作事实描述，不另造全批质押终态；单笔不全成功时始终保留逐笔结果。

PS-1 可质押 / PS-2 已质押 / PS-4 已释放仍由借贷平台维护；PS-3 作废占位、PS-0 非法。运营审核动作不直接改写 PS；申请占用结束及质押事实由借贷平台统一维护；可再次选择还受实际占用、差异、资产有效性约束。CT 记录执行，不以审核超时扩展 CT 失败。

单笔字段 RV-19 / 20 / 21 / 22 与 RV-01～18 的完整含义见 M2～M6；本册引用 PA-01～04 的提交上下文及 PA-06 时间；WS-351 PA-11 对应 RV-19，PA-05 对应 RV-20，PA-07 / 08 为逐笔原因 / 复核，PA-13 / 14 为协议 / 截止。两端按此同源消费，不退回整批结论。
