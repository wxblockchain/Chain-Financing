## 3. 目标、范围与角色

目标是让运营人员在同一工作入口查申请、核对事实、维护线下裁定及凭据，让资产方收到一致的审核结论；到期申请可追溯且不能补审翻转，执行进展逐张可查。

本期包含两个页面：`P-O-PR-01` 质押审核列表、`P-O-PR-02` 质押审核详情。首笔建池与追加质押走相同审核；通过、驳回、协议、留痕、超时及执行异常追踪属于完整闭环。新申请由面客端创建，本端不代建。

不包含面客建池与质押操作界面、运营代签名或代付、代币上架与代币信息维护、风控评分与审核标准引擎、双人复核、认领转派、批量裁定、复议改判、对账更正操作台、清算及协议模板库。质押协议是该申请的业务凭据，不是 WS-361 的版本化平台协议。

| 业务角色 / 参与方 | 责任与可见范围 |
| --- | --- |
| 运营人员 | 在权限范围内查看全部申请；有处置权限时维护线下结论。包括运营管理员及被授权的运营专员；不做运营机构级数据隔离 |
| 资产方 | 面客端提交、结论前撤回、查看本企业结论、通过后确认费用及发起执行、失败后重新提交；不进入运营审核界面 |
| 借贷平台 | 拥有 PA 申请、PL 质押记录、PS 质押状态；提供期限判定、入池前复核、逐张结果消费、有效质押价值判断 |
| 代币发行平台 | 代币事实权威与链上执行方；提供 X-04 / X-05 的逐张执行结果；运营审核不能替它修改代币事实 |

术语：**审核结论**仅为通过 / 驳回；**申请状态**为 PA-05 的生命周期；**逐张执行结果**为 PA-10 的一次执行结果；**质押状态**为 PS；**代币状态**为上游有效 / 失效。它们不是同一状态轴。“业务释放”不等于资产已经转回，只有确认转回才能展示该事实。

## 5. 功能需求说明（开发主阅读）

### 5.1 M1 查询审核队列

**入口与前置**：正常登录且有 PM-AL-07，从管理端侧栏“质押审核”进入 P-O-PR-01。它是独立工作队列，放在协议管理之前，不依附已移交的“代币管理”。只读用户也可进入；列表无裁定按钮，无批量通过 / 驳回。

| 内容 | 产品行为与校验 |
| --- | --- |
| 默认视图 | F-PR-01：申请状态＝待审核，提交时间升序；页面初始不选企业、项目、类型或时间范围，不填关键词 |
| 筛选 | F-PR-03：申请状态（全部或第 7 章八值，单选）；资产方企业、目标项目（按实际对象选择）；申请类型（全部 / 建池首笔 / 追加质押）；提交时间范围（起止含边界，开始不得晚于结束）；关键词（申请编号或企业名，忽略首尾空白）。条件组合生效，修改筛选回首页，重置恢复默认视图 |
| 排序分页 | F-PR-04：提交时间、已等待时长、代币价值合计可切升降序；采用管理端带总数的常规分页，页容量沿用共享组件，不套面客滚动加载。页容量未有明确数值时不在本册另设常量；详情往返及后退保留筛选、排序、页码。原页已无数据时回最后有效页并说明 |
| 列 | 申请编号、资产方企业、目标项目、申请类型、代币张数、代币价值合计、提交时间、审核已等待时长 / 截止时点、申请状态、查看详情。价值合计只读取借贷业务值，不乘质押率、不二次折算（D-PR-16） |
| 三张统计卡 | F-PR-02：待审核数；审核超时失败数（替代旧版仍待审的“已超时数”）；近 7 日人工审结数（通过与驳回，按结论时间）。卡片均应用企业、项目、类型、提交时间和关键词条件，**不应用状态筛选**；各自按标题规定状态计数。标题下注明范围，防止默认待审核筛选把其余两卡永远置零。近 7 日窗口为当前展示时点往前 7 个自然日，边界含起点、不含未来 |
| 状态筛选 D-PR-14 | 原样采用 PA-05 的八个状态；执行超时不作为“整单驳回”筛选值。增加执行情况辅助筛选（全部 / 处理中 / 有失败 / 执行超时 / 对账差异 / 释放未完成），按申请内至少一张命中，允许同一申请命中多个条件，不是新申请状态 |
| 空与失败 | 待审为空显示“当前没有待审核的质押申请”；筛选无结果提供重置；读取失败给原因与重试，不能显示为零条；失败时统计不冒充 0 |

F-PR-05：行“查看详情”打开 P-O-PR-02；从历史或通知直达也重新检查权限，申请已终结仍可只读回看。业务流程见 [FL-PR-01](v1.0-代币质押审核-流程图与状态机.md#fl-pr-01)。

### 5.2 M2 查看申请事实与历史

**D-PR-20 / D-PR-21**：审核判定在线下完成，线上维护结论与证据。详情顶部中性说明“本页信息供线下判定参考，结论由审核人线下作出后在此维护”。不给系统评分、建议通过 / 驳回、风险排序或代币风险着色。权限、必填格式、当前状态与时限校验仍须成立；两天自动超时是申请期限处理，不是系统判断资产是否合格。

| 区块 / 字段 | 含义、业务类型、必填与默认 | 可编辑性与校验 |
| --- | --- | --- |
| PA-01 申请编号 | 文本，提交成功即有，全局稳定，无空默认 | 只读；作为本次审核与回溯依据 |
| PA-02 目标项目 | 引用，必有；展示项目编号、名称、项目状态、代币类型 | 只读；历史项目终结仍保留关联 |
| 资产方主体 | 企业名称与唯一主体标识，必有；不是审核人的运营机构 | 只读；不得用名称替代归属判断；标识缺失标“待核实”，不伪造，见 Q-PR-07 |
| PA-03 申请代币清单 | 至少 1 张，引用集合；展示提交所选完整清单 | 只读；不得增删、换张或只通过子集 |
| PA-04 申请类型 | 必有；建池首笔 / 追加质押 | 只读；规则一致 |
| PA-05 申请状态 | 必有，第 7 章八值；新申请默认待审核 | 仅可通过合法结论或对应业务事件变化；无状态编辑器 |
| PA-06 提交 / 结论时间 | 时间，提交时间必有；有效人工结论产生前结论时间为空 | 只读、带时区；审核超时另有发生时间，不伪装成人工结论时间 |
| 代币张数与价值合计 | 正整数 / USD 金额；取本申请业务数据 | 只读；不等同于成功张数或有效质押价值 |
| 明细列 | 代币编号（文本）、数量及币种（数值及币种）、代币价值（USD）、底层账期（日期信息）、买方企业（文本）、代币状态（有效 / 已失效 · 不计入覆盖） | 均取同一只读代币域，不补算代币价值或失效规则；信息缺失明确“暂无数据”，不能填 0 或默认有效 |
| PA-08 入池前复核结果 | 条件有值：通过 / 不通过及原因；尚未复核为“未复核” | D-PR-15：仅只读，运营无人工复核或改判入口；原驳回原因字段是 PA-07，不是 PA-08 |
| PA-10 逐张执行结果 | 执行后按张呈现，未发起时不生成成功 / 失败 | 见 M6；与审核结论分区 |

**F-PR-08 历史**：按同一资产方、同一项目查看历史申请，已结论按结论时间倒序；无人工结论的终结记录用终结发生时间并明确事件类型。展示申请编号、状态、结论 / 终结事件、时间、审核人（自动事件写“平台自动判定”）、原因摘要与查看原申请。摘要可收起，详情必须提供全文；无历史有明确空态。跨项目重新质押不自动拼成同项目历史，关联明确时才展示，不凭相同代币推定业务关联。

已裁定、已撤回、超时失败、结论已失效 / 作废的详情保留事实和记录，顶部 C-O-PR-03 说明当前状态与原因；不得再提供可提交裁定。代币中途失效或项目已关闭只读展示客观事实，不自动生成审核驳回、也不暗示可以继续入池；最终入池资格由 WS-351 复核承担，项目终态与在途执行相遇见 Q-PR-06。

<a id="m3"></a>
### 5.3 M3 通过与协议维护

**前置**：具备查询与处置权限、申请仍待审核且未到审核截止时点。线下判定已完成，运营通过详情“通过”打开 C-O-PR-01。

动作顺序：回显申请编号、企业、项目与全部代币张数 → 上传线下签署协议 → 可填内部备注 → 勾选“已知悉通过不等于质押成功” → 二次确认对象、文件和后果 → 提交。取消二次确认回编辑态，保留本次输入；确认成功后只读显示审核人、结论时间、协议与入池截止时点。

### 5.4 M4 驳回与唯一结论

**前置与动作**：与通过相同。详情“驳回”打开 C-O-PR-02，先填写原因说明，可选点名本申请内问题代币、添加归类标签；展示将发送给资产方的完整文本；二次确认回显申请与原因首行，可展开全文。成功后整单已驳回，原申请留存，资产方可立即按资格重新提交新申请，不能在旧单就地修改（D-PR-10）。

| 字段 / 编号 | 含义、枚举、必填、默认与校验 |
| --- | --- |
| RV-13 原因说明 / D-PR-02 | 自由文本，驳回必填，无默认；10～500 字，去除首尾空白后校验，禁止纯空白或仅标点。平台不判断内容真伪、不做自动措辞改写；需能讲明线下结论与问题 |
| RV-12 问题代币 | 选填引用集合，默认空，只能从本申请勾选；用于生成可编辑的点名文字，不缩小整单驳回范围、不改变申请清单 |
| RV-11 归类标签 / D-PR-22 | 选填、默认空：代币归属或主体存疑 / 底层应收账款存在问题 / 代币与目标项目不匹配 / 申请材料不完整或不一致 / 其他。仅供事后统计，不是判断标准；不选择不阻止提交 |
| RV-14 驳回原因全文 | 以 RV-13 为主体、选填项非空时可加入标签和点名文字；生成文字允许修改或删除，最终全文预览为发送原文；选填为空时只有自由文本。不截断、不追加平台解释，原样成为 PA-07、面客详情及通知的原因正文；选填生成部分不挤占原因说明 10～500 字的空间 |

**D-PR-07 唯一结论**：同一申请只能有一次有效人工裁定。两人同时裁定，先有效完成者生效；后者看到当前结论、时间和审核人，不能覆盖。重复同一次提交不生成第二条结论、不刷新结论时间、不重复通知。提交期间不确定是否成功时，先呈现结果待确认并允许查看最新申请，不能直接宣布失败后再造一份结论。

**D-PR-12 结论衔接**：通过 → PA-05“审核通过 · 待入池”；驳回 →“已驳回”。两端共用申请事实，结论、时间、驳回原因一致；审核人、协议是附带的审计与凭据内容，不是新审核状态。结论未生效不得提前通知成功；通知失败不撤销已经生效的结论。提交发现已撤回 / 已超时 / 已被裁定即拒绝本次操作，刷新为只读，保留当前有效事实。

**标准驳回零费用**：先审核后上链的申请没有进入转入环节；驳回只是结束本次申请占用，不需要做链上释放，不显示“费用不退”。同一代币其他历史执行产生的费用不归入本次驳回。若实际发现申请关联资产已转入，进入 M6 的异常边界，不能套用“已经回到原地址”的正常文案。

### 5.5 M5 到期失败与撤回衔接

**N-PR-01 / D-PR-08 现行审核时限**：沿用 WS-351 最新落实口径，自 PA-06 提交时点起满 **2 个自然日**，到期仍无生效审核结论则自动置 PA-05“超时失败”，不等人工点击、不再补审。自然日按平台统一业务时区的对应时点计算，不跳过周末、节假日，不使用旧版“2 个工作日”或运营可任意改时限。平台统一时区尚未明确到具体取值，按 Q-PR-04 闭合，不由浏览器时区决定截止。

| 时钟 / 字段 | 起点、对象与展示 | 终止或结果 |
| --- | --- | --- |
| 审核等待 / RV-15 审核截止时点 | 提交时间起，申请级，只读时间；待审核必有。列表和详情展示已等待与明确截止时点、时区 | 结论生效、撤回或审核超时即停止累计审核等待；N-PR-02：不足 1 小时按分钟、不足 24 小时按小时、之后天＋小时 |
| RV-16 审核超时发生时间与原因 | 自动事件，超时后必有，只读；原因为“运营端未在时限内完成审核” | 保留原提交时间，无人工审核人、无伪造通过 / 驳回结论 |
| 入池有效期 | D-PR-09：通过结论时间起 7 个自然日，申请级；名称必须写全 | 未发起且届满 → 结论已失效；执行已发起的跨期冲突按 Q-PR-06，不宣称执行费用为零 |
| 执行结果等待 | 每张实际发起执行时点起；当前沿用 2 个自然日，注明总控延伸 | 见 M6，不与审核时钟串算，也不从通过时点计时 |

**D-PR-23 到期边界**：在截止前已生效的通过 / 驳回保留；截止时点仍未生效（包括正在上传、已打开二次确认、线下已决定但未在线提交）按超时。恰好在截止时点提交也不能补审。已完成的撤回保留已撤回；到期后再撤回不能把超时记录改成撤回。并发下仅产生一个有效结果，两个页面不能各呈现自己的成功。

**D-PR-24 失败后的闭环**：原 PA 保留在历史与超时筛选里；正常未执行申请解除本次占用，代币回 PS-1，可按最新资格选入同一或其他项目并生成新申请，不设审核失败冷却。旧申请无“恢复待审”、补通过或删除入口。全程未发生本次链上动作、未产生费用；面客反馈和通知必须说明未按时审核，不能写费用不退、转入失败或“已撤回”。已有其他占用、代币失效、对账差异等独立事实仍遵守 WS-351 资格规则，不由旧申请超时覆盖。

**资产方撤回**：仅待审核且仍可撤回时由面客端发起。本端打开旧详情或尚未提交的弹层，后续提交必须尊重已撤回事实并只读刷新。首笔建池超时 / 驳回 / 撤回后，项目是否为空池草稿由 WS-351 判定，本端不关闭项目。

C-O-PR-04 区分“审核待处理”“审核超时失败”和“执行结果等待”；到期后该条从待审核队列退出、进入历史超时筛选，不出现“已超时仍可补审”的按钮。图见 [ST-PR-01](v1.0-代币质押审核-流程图与状态机.md#st-pr-01)。

### 5.6 M6 查看逐张执行与异常释放

**F-PR-18 / D-PR-25**：运营在原申请详情只读查看 PA-08 / PA-10 及相关记录。通过后资产方回面客端确认，借贷平台重新核对可质押资格，代币发行平台承担执行。复核失败为结论已作废，不发起、不收费；执行入口不可用且尚未发起时展示“未发起”，不可假装已进入处理中。**D-PR-11**：本端不提供签名、付费、重新执行、改清单或修改 PS / CT 的按钮，直接尝试这些操作同样不得获准。

| 逐张展示项 | 类型、条件、默认与校验 |
| --- | --- |
| 申请 / 项目 / 代币编号 | 文本与引用，必有、只读；任何结果必须可归到对应申请和该张代币，不用企业名或汇总数量代替 |
| 执行状态 | 只读：未发起 / 处理中 / 成功 / 失败；对应 CT-0～3。超时失败作为本次失败原因可辨识，不新建 CT 编号；默认仅在确定未发起时为未发起 |
| 发起、完成与超时时点 | 时间；发起后才有等待与截止，完成或超时后记录各自发生时间，带时区；无回写不伪造执行完成时间 |
| 业务可读原因、下一步 | 失败或异常时必有；不只写“操作失败”。成功可查记录；普通失败可重新提交，处理中不能重发；对账差异不能继续新动作 |
| 费用 | 是否产生、金额及币种，来自执行结果；已产生费用由资产方承担且不退，成功和失败都逐张呈现。不预设 gas 为 USD；来源未提供时写“费用待核实”，不能填 0，详见 Q-PR-05 |
| 链上凭据 | 成功结果有可查验凭据，只读；未知不虚构。展示遵守共享规则，不以看到凭据替代业务结果认定 |
| RV-17 差异事实 | 条件只读：相关代币、原失败事件、迟到结果与发现时间；无差异时不出块。列明“不计入覆盖、暂停新动作、待对账处理” |
| RV-18 释放跟踪 | 条件只读：相关申请与代币、已确认的位置事实、释放是否有结果、业务可读失败原因、结果时间；无释放事件不生成记录，不猜测缺失结果 |

**按张与覆盖**：同申请 3 张、2 成 1 败，成功 2 张保持 PS-2，失败张退回 PS-1，可按资格重新选池；运营结论仍为“通过”，不改“部分通过”或驳回整单。审核期、通过待入池、处理中与差异张均不计入覆盖；成功还需满足 WS-351 对代币有效性等条件。只约束相关张，项目其他动作依各自规则继续。PA-05“已入池”在最新图册表示按张结算结束，不保证全成；**详情始终同屏给成功 / 失败 / 处理中张数及逐张明细，不能只显示已入池**。全失败、执行超时混合批次的汇总命名冲突保留 Q-PR-06。

**D-PR-26 执行超时及迟到结果（沿用总控延伸）**：每张发起满 2 个自然日仍无结果，按 WS-351 D-LS-33 / E-5 暂沿用该张失败、回 PS-1、记录保留、可重新质押；失败原因写“链上执行结果未在时限内回写”。到期前保持处理中，不能自动重发或给运营重试入口。此处**不是用户确认的审核两天规则**，也不表示已证实资产在原地址；X-04 的最终结果、安全重提条件与费用可得性仍须 Q-PR-05 收口。

迟到成功沿用 D-LS-47：保留原失败记录、不自动变回已质押、不追加有效质押价值；该张标记对账差异、暂停其新动作并形成运营待办。若已重新申请到另一项目，展示相关申请 / 项目及差异，不以迟到成功覆盖新单、不把同一张计入两个池。其他已成功且无差异的张不回滚。相同迟到信息不重复制造待办或费用；迟到失败不再生成第二次失败通知、仅保留可追溯事实。**谁有权确认差异关闭、如何处理新申请和恢复动作均未定，本端无“手工修正为成功”入口**。

**F-PR-19 / D-PR-27 “驳回时若已转入则释放”的适用边界**：

| 场景 | 本期明确行为 | 不可宣称的结果 / 未决部分 |
| --- | --- | --- |
| 本期正常先审后执行；审核驳回或审核超时 | 仅结束申请占用，未发生转入、不需要链上释放，本次零费用 | 不发起 X-05，不显示“释放已完成”来替代驳回 |
| 有已转入事实却出现应终结为驳回的申请；例如旧流程存量或跨平台事实错配 | 仅在实际发现时按异常处理，不假定本期必有存量。不让资产继续计入覆盖或重复质押；形成该张“需释放处理”的运营待办，关联申请、转入事实与原持有地址的只读信息；X-05 释放语义必须被后续承接 | 不能把已经通过的申请改成驳回来触发释放；不能在驳回按钮后自动代资产方签名 / 付费；触发人、确认方式、费用与失败处置待 Q-PR-05 明确 |
| 释放结果尚未确认或执行失败 | 明确显示释放未完成及已知原因，保留跟踪；该张仍不可当作已归还、不可再次质押 | 不先写 PS-1、不标“零费用”或“已回钱包”；已发生费用只按真实结果展示 |
| 已有合法释放动作且取得成功结果 | 只读展示已转回质押前原持有地址；是否可重新质押由借贷平台最新资格判断 | 无人工指定其他转出地址，无本端“点一下置为释放” |
| 正常已质押后的撤回或项目终态业务释放 | 属 WS-351 解除质押，不重新审核；项目终态 PS-4“已释放 · 待提取”仍不等于已转回 | 不把它写成审核驳回；未提取不得再质押 |

业务流程见 [FL-PR-02](v1.0-代币质押审核-流程图与状态机.md#fl-pr-02)、[FL-PR-03](v1.0-代币质押审核-流程图与状态机.md#fl-pr-03)，逐张结果见 [ST-PR-02](v1.0-代币质押审核-流程图与状态机.md#st-pr-02)。本节定义观察、限制和需承接的业务结果，不定义跨平台报文、重试或补偿方案。

| 上传正式通过凭据、提交通过或驳回 | 不可，隐藏处置入口；绕过界面尝试则提示无权 | 待审核且未到截止才可 | 只有 PM-AL-08 而无查询权限不能进入本审核流程，联系建设方核对配置，不隐式赠予 |
| 修改结论、代币、执行、释放结果 | 不可 | 不可 | 处置权限只允许提交本模块两类审核结论 |
| 查看运营消息 | 按 PM-AL-12 独立授权 | 同左 | 有消息权限不等于有审核权限；读消息不算处理业务 |

账号待首登改密、锁定、登录失效或当前交付配置不具备权限时，即使旧页面仍开着，也不能继续提交或下载；保留已发生的合法结论。未登录、越权、对象不存在分别给适用的返回 / 登录指引，不泄露无权数据。角色默认开通情况以 WS-357 为准，未授权入口不展示；已授权但因业务状态不可提交的入口按当前状态给说明。

**F-PR-13 留痕**：申请进入待审、撤回、结论、正式协议提交、重新提交关联、自动超时、逐张执行结果、差异与释放结果均按申请可追溯。展示事件、发生时间、动作主体、前后业务状态、关联申请 / 项目 / 代币、原因及凭据；人工记录取当时身份，自动事件不伪造审核人。记录不可编辑删除；新申请不覆盖旧申请。网络失败未生效的结论不计入审结记录；原失败和迟到事实分开保留，不重写旧事实。

**D-PR-17～19 / F-PR-16 通知**：沿用 WS-351 已登记的事件含义，同一事件只形成一次有效通知；不是本端与面客端各投一遍。由审核有效结论 / 平台期限事实触发，面客消息中心展示，页面状态始终保底。共享分类及新平台登记尚未确认时按 Q-PR-09，不声称旧版登记已覆盖本平台。

## 7. 状态与边界的统一口径

| PA-05 申请状态 | 来源与条件 | 运营端允许行为 |
| --- | --- | --- |
| 待审核 | 面客提交；结论、撤回与超时尚未生效 | 查看；有权限且未到期可通过 / 驳回 |
| 审核通过 · 待入池 | 本端有效通过 | 查看通过、协议、入池截止及逐张结果；不可二次裁定 |
| 已驳回 | 本端有效驳回 | 查看原原因；不可改清单 / 改判 |
| 已撤回 | 资产方在结论前成功撤回 | 查看撤回事实；无补审 |
| 超时失败 | **审核**到期无有效结论，平台自动判定 | 查看失败原因与时间；无补审、无恢复 |
| 结论已失效 | WS-351 入池有效期届满 | 只读，协议存档；已执行跨期的范围按 Q-PR-06 |
| 结论已作废 | WS-351 入池前复核不通过 | 查看原因、协议存档，无人工复核入口 |
| 已入池 | WS-351 当前定义：申请的代币已按张结算完毕 | 只读并同屏给逐张结果，不推断全部成功；汇总歧义见 Q-PR-06 |

人工审核结论 RV-03 只有通过 / 驳回；无结论的自动超时不是第三种人工结论。审核终结不可被迟到裁定翻转；执行终结不可被迟到结果自动翻转。PS-1 可质押 / PS-2 已质押 / PS-4 已释放仍由借贷平台维护，PS-3 作废占位、PS-0 非法，不在本端另建枚举；PS-1 仍需结合实际占用、差异与有效性判断是否可选。

| 关键异常 | 页面与业务结果 |
| --- | --- |
| 已撤回 / 已被裁定 / 已超时仍尝试裁定 | 拒绝新结论，显示当前事实并只读刷新，无第二条通知、无正式遗留协议 |
| 协议格式超限、上传失败、原因不合格 | 就地明确原因并保留其他输入，结论不生效 |
| 通过后材料或资格变化 | 原审核事实可查，复核结果只读；不能由运营改代币或强行入池 |
| 两天审核失败后又收到旧通过 | 原申请仍超时失败、新申请独立；无新通过通知，不重新占用代币 |
| 执行超时后成功迟到 | 原失败保留，差异张不计入覆盖、暂停新动作；进入对账待办，不自动改回成功 |
| 驳回相关资产实际已转入 | 按 M6 异常释放边界，不假装普通零成本驳回已归还；具体释放发起规则待确认 |
