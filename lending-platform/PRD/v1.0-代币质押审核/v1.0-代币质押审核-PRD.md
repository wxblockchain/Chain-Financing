## 3. 业务目标、对象与角色

目标：资产方一次提交多张，运营逐笔维护结论；同批不同代币可以由不同运营人员在不同时间通过或驳回，已通过的单笔可独立进入后续确认，不等整批审完。

**对象口径 D-PR-29（本轮逐笔审核的统一来源）**：

| 对象 | 含义与范围 |
| --- | --- |
| 提交批次 | 资产方一次面客提交形成的分组；同一资产方、同一融资项目、同一申请类型及提交时间；沿用 PA-01 批次定位及 PA-02 / 03 / 04 的关联。批次含一笔或多笔 |
| 单笔质押申请 | 批次内**一张代币的一次质押申请**。具有稳定单笔标识，关联批次与代币编号；是审核、撤回、截止、协议、原因和通知的最小单位。标识的编码格式不在 PRD 定义 |
| 单笔审核结论 | 每笔至多一个有效人工结论：通过 / 驳回；时间、审核人、协议或原因各自独立。未审、撤回、审核超时均没有伪造人工结论 |
| 单笔执行结果 | 仅这笔审核通过、资格复核合格、资产方确认后才有执行；成功、失败、未有结果与审核结论分开，不改写“通过” |
| 批次进度 | 只做单笔事实的数量汇总，不再有统管全批的通过 / 驳回结论、审核人、结论时间、原因、入池截止或“已入池”终态；详见第 7 章 |

同一批次内一张代币只能出现一笔，仍为整张质押，不拆数量。再次质押是新的提交及新的单笔标识，保留与原记录的关联，不复用原结论。同一代币在不同提交中的记录不可仅凭代币编号合并。单笔审核态属于质押业务申请，不写回代币本体。

| 参与方 | 本模块责任 |
| --- | --- |
| 运营人员 | 按功能权限查看全部单笔；在线下判断后，在线逐笔提交证据与结论；不按运营机构隔离 |
| 资产方 | 面客批量提交，查看每笔结论；撤回仍待审的单笔，确认各已通过笔的费用和执行；可将合格单笔一同确认，但不能带入未审 / 驳回笔 |
| 借贷平台 | 拥有申请、质押记录和 PS 质押事实；提供逐笔期限、入池前复核、结果消费及覆盖判定 |
| 代币发行平台 | 拥有代币事实并承担链上执行；按张提供结果，运营审核无代币维护权 |

本期两个页面：P-O-PR-01 审核队列，P-O-PR-02 单笔审核详情（可查看批次上下文）。保留协议上传、历史、时限、通知与执行异常追踪。不新增批量一键通过 / 驳回、双人复核、转派、风控评分、原型、链上代签代付、对账更正台、清算或协议模板库。

## 5. 功能需求说明（开发主阅读）

<a id="m1"></a>
### 5.1 M1 单笔审核队列

前置为正常运营账号且有 PM-AL-07 查询权限；侧栏“质押审核”进入 P-O-PR-01。列表**一行一笔代币质押申请**，不是一行批次；同批关系可识别。独立队列不依附已移交的代币管理。列表仅提供查看，不提供多选裁定。

| 内容 | 产品规则 |
| --- | --- |
| 默认 | 单笔审核状态＝待审核，批次提交时间升序；同时间按稳定单笔顺序，刷新不跳动。不做风险优先排序 |
| 筛选 F-PR-03 / D-PR-14 | 审核状态（全部 / 待审核 / 通过 / 驳回 / 已撤回 / 审核超时失败）、资产方、项目、申请类型（全部 / 建池首笔 / 追加）、提交时间范围、关键词（批次编号 / 单笔标识 / 代币编号 / 企业名）。默认除待审核外均为空或全部；组合生效，起止含边界，起点不得晚于终点；关键词忽略首尾空白 |
| 后续情况筛选 | 全部 / 待确认入池 / 复核作废 / 未发起已过有效期 / 执行中 / 执行成功 / 执行失败 / 结果待核实 / 对账差异 / 释放未完成，命中相应单笔；不是新增人工审核结论 |
| 列 | 单笔标识、批次编号、代币编号、资产方、目标项目、申请类型、该张代币价值（USD）、提交时间、审核等待及截止、审核状态、后续情况、查看。批次合计不得冒充这一张价值 |
| 三张统计卡 F-PR-02 | 待审核**笔数**、审核超时失败**笔数**、近 7 个自然日人工审结**笔数**。应用主体 / 项目 / 类型 / 提交时间 / 关键词条件，不应用状态和后续情况筛选；各卡按自身状态定义计数并标明范围。人工审结只计通过 / 驳回，不计自动超时 |
| 排序与分页 F-PR-04 | 提交时间、审核等待、单张价值可升降序；带总数常规分页。筛选改变回首页、重置回默认。页容量沿用平台现行组件值，不另造值。返回与后退保留筛选、排序、页码；原页为空回最后有效页并说明 |
| 空与失败 | 待审为空、筛选无结果、读取失败分别反馈；失败可重试，不假报 0。无查询权限不显示入口，直接访问亦拒绝 |

F-PR-05：点某行详情只进入该笔 P-O-PR-02；已结论或终结仍可只读回看。批次含 3 笔只审 1 笔后，待审数减少 1，另 2 笔仍在队列。流程见 [FL-PR-01](v1.0-代币质押审核-流程图与状态机.md#fl-pr-01)。

### 5.2 M2 单笔事实与批次历史

D-PR-20 / 21：线下完成判定，线上维护证据与结论。页面中性说明“本页信息供线下判定参考，结论由审核人线下作出后在此维护”；不提供评分、风险灯、建议通过 / 驳回、自动筛出不合格资产。格式必填、权限、状态及截止校验照常生效。

| 区块 / 字段 | 业务含义、类型、必填与校验 |
| --- | --- |
| 单笔定位 RV-19 | 稳定文本标识，提交成功即有；关联一个批次、一个代币、一家资产方、一个项目；只读，无默认空值。重新提交生成新标识 |
| 批次上下文 | PA-01 批次编号、PA-02 项目、PA-04 首笔 / 追加、PA-06 提交时间必有，只读；完整 PA-03 清单可查，不能修改；本笔清晰定位，不将批次所有代币列为本次裁定对象 |
| 资产方与项目 | 企业名称、稳定主体标识、项目编号 / 名称 / 状态 / 类型；只读，不以名称替代归属判定。缺失标“待核实”，不得猜测，见 Q-PR-07 |
| 本张代币事实 | 编号、数量及币种、USD 代币价值、底层账期、买方企业、有效 / 已失效状态；读取同一只读代币域，缺失不用 0 或“有效”填充，不二次折算 |
| 审核信息 | 本笔 RV-20 审核状态、RV-03 人工结论（存在时）、RV-04 结论时间、RV-07 / 08 审核人、协议或驳回原因；不同笔各自展示 |
| 期限 | 本笔审核截止 RV-15；通过后的入池截止 RV-22；名称和时区明确，不能给全批一个通过时间或入池倒计时 |
| 后续信息 | 本笔复核 RV-21、执行及差异 / 释放结果，见 M6。尚无结果标未复核 / 未发起 / 暂无结果，不编造失败 |

F-PR-08：同项目同资产方的历史按提交批次可回溯，进入后逐笔看代币、状态、审核人、时间、原因全文及关联的再申请。单笔事件按发生时间倒序；没有人工结论的终结显示撤回 / 自动超时及发生时间，不冒充人工裁定。摘要可收起，详情原因必须完整。跨项目再申请仅在有明确关联时展示，不凭代币相同推定关联。

同批不同笔可直接查看或切换；切换前有未提交输入需选择留在当前笔继续编辑或放弃后切换，不提供跨笔自动保存草稿，不能将上一笔原因、协议选择、备注及确认勾选自动带入下一笔。通过 / 驳回弹层始终回显单笔、代币、批次和项目。已审笔只读，**不使同批待审笔只读**。

D-PR-15 / 16：入池前复核只读，不提供运营复核按钮；审核不读取或修改覆盖派生量。代币失效、项目终结显示客观事实，不自动替审核人驳回，也不保证该笔后续能入池。实际入池仍受面客资格判定。

<a id="m3"></a>
### 5.3 M3 逐笔通过与协议维护

**D-PR-01**：每次审核针对当前单笔。可以只通过批次内 A、驳回 B、保留 C 待审；不再要求整批同结论。通过 A 不代表批准 B/C，其他笔无需重新提交或重新计时。本期不提供一次点击为多笔生成结论。

前置：有查询与处置权限，当前笔仍待审核且未到截止。线下判定后：本笔“通过” → C-O-PR-01 回显本笔代币、项目、批次 → 上传或明确选择适用协议 → 可填内部备注 → 勾选知悉通过不等于质押成功 → 二次确认 → 提交。取消二次确认回编辑，输入保留；成功后本笔只读，其余待审笔可继续办理。

| 编号 | 规则 |
| --- | --- |
| D-PR-03 / N-PR-03 | 每笔通过必须有 PDF / JPG / PNG 协议，1～5 个，单文件 ≤10 MB；默认未关联任何文件。未上传完或保留文件失败不能通过；错误逐文件指出、可修复、不丢其他输入。只校验规格与有无，不认定内容或法律效力 |

### 5.4 M4 逐笔驳回与唯一结论

前置与通过相同。本笔“驳回”打开 C-O-PR-02：回显本笔代币 → 填原因，可选归类 → 完整预览 → 二次确认对象及原因 → 提交。**D-PR-02 / 10**：驳回只结束本笔，原因针对本笔；同批 A 通过、B 驳回、C 待审是正常结果，资产方可只重新申请 B，不重复提交 A/C。

| 字段 | 含义、必填、默认与校验 |
| --- | --- |
| RV-13 原因说明 | 驳回必填自由文本，去首尾空白后 10～500 字，禁止纯空白或仅标点；默认空。平台不改写措辞或判断真伪 |
| RV-12 问题代币标注 | 本笔代币只读回显，取 RV-19 所关联代币，不再从全批勾选问题子集；不能借此驳回其他笔 |
| RV-11 归类标签 / D-PR-22 | 选填、默认空：代币归属或主体存疑 / 底层应收账款存在问题 / 代币与目标项目不匹配 / 申请材料不完整或不一致 / 其他。仅统计，不影响是否可提交 |
| RV-14 驳回原因全文 | RV-13 为主体，标签或本笔点名文字可辅助生成、可编辑；最终预览文本原样用于本笔面客原因与通知。选填部分不挤占 10～500 字的说明空间，不截断、不自动套到全批 |

D-PR-07：同笔并发，只先有效完成的一次裁定生效；后者展示本笔已有结论、时间与审核人，不覆盖。**不同笔并发互不争抢整批结论**，A/B 可分别成功提交。重复同笔同次操作不增加结论、不改时间、不重复通知。结果不确定先显示待确认并可查当前事实，不引导重新制造结论。

D-PR-12：两端按稳定单笔标识同步该笔结论、时间、原因；批次仅汇总。不因某笔结论而覆盖批次其余笔的待审、驳回或通过结果。已撤回、审核超时或已有人工结论的笔不能再裁定，旧弹层提交亦拒绝。正常未执行驳回仅解除本笔申请占用，本次零费用，不触发 X-05；实际已转入差异走 M6，不将已通过改成驳回以发起释放。

### 5.5 M5 逐笔时限与撤回

N-PR-01 / D-PR-08：审核时限仍为**提交起两天**，沿既有落实口径按 2 个自然日、平台统一业务时区的对应时点判定，不跳过节假日。批次内各笔继承同一提交时间与审核截止；点开审核、切换、某笔裁定都不重置其余笔时钟。具体业务时区见 Q-PR-04。

| 字段 / 时钟 | 规则 |
| --- | --- |
| RV-15 本笔审核截止 | 时间，提交成功必有、只读，取批次提交时点后 2 个自然日；队列及详情展示明确时点与时区 |
| N-PR-02 已等待 | 待审笔从提交起计；不足 1 小时按分钟、不足 24 小时按小时、之后天＋小时；人工结论、撤回或审核超时生效即停止审核等待 |
| RV-16 审核超时事实 | 本笔到期无结论才产生：发生时间＋“运营端未在时限内完成审核”；自动事件无人工审核人、无伪造驳回 |
| D-PR-09 入池有效期 | 各笔从自己的通过时间起 7 个自然日；先通过的 A 不因后来 B 通过延长，也不从批次提交起算。已执行跨期问题见 Q-PR-06 |
| 执行等待 | 仅实际发起后按该笔起算，独立于审核两天和入池七天；执行逾期取值及处置尚待 Q-PR-05，不自动套审核期限 |

D-PR-23：到达审核截止，仅仍待审笔自动审核超时失败；截止前已通过 / 驳回 / 撤回的笔保持原结果。正在上传、二次确认未生效、线下已决定但未在线提交均不算已审核；恰在截止提交也不能补审。已生效撤回不改成超时；先超时后不能补撤回。每笔只有一个有效审核结果，不影响同批其他笔。

D-PR-24：本笔审核超时记录保留；正常未执行张解除本笔占用，回 PS-1，按最新资格可立即重新提交到同一或其他项目，无冷却。旧笔不恢复、不删除，新笔新标识、新提交时点。其他独立占用、失效或差异仍约束可选性，不能由旧笔到期覆盖。

资产方可在面客端撤回仍待审的单笔；原有整批撤回入口如保留，只可逐项列明当前可撤回笔，已裁定笔不纳入，不得撤销整批全部结果。撤回与审核同笔竞合只生效一个结果，其他笔照常。单笔通过后不再提供“撤回申请”，已质押后的资产退出仍属 WS-351 解除质押。

例如同批 A 已通过并执行、B 已驳回、C 仍待审：截止只使 C 超时、释放 C 的本次占用，不能回退 A、重写 B 或对全批宣称零费用。审核驳回 / 超时零费用的表述只指该笔本次未执行申请。C-O-PR-04 分别显示审核截止、入池截止和执行等待。图见 [ST-PR-01](v1.0-代币质押审核-流程图与状态机.md#st-pr-01)。

### 5.6 M6 单笔执行及异常释放追踪

F-PR-18 / D-PR-25：一笔通过即可由资产方确认该笔，无需等同批未审笔。执行资格仅限自身有效通过、复核合格、未重复占用且未发起的笔；资产方可同时确认多个合格笔，但列表须明确本次参与张数、逐张对象和费用，**未审、驳回、撤回、审核超时、失效 / 作废笔不得被批次通过摘要带入执行**。本端只读追踪，不提供代签、代付、重发或改代币 / PS / CT 的能力（D-PR-11）。

RV-21 为本笔入池前复核：未复核 / 通过 / 不通过及原因，默认未复核，发生后只读。复核不通过仅使该笔结论不可用于入池，保留人工审核历史、文件存档；该笔未执行、无费用。复核其他笔仍可通过，不取消全批。入口不可用且未实际发起，不标处理中或执行失败。

| 逐笔执行字段 | 业务含义及校验 |
| --- | --- |
| 关联 | 单笔标识、批次、项目、代币必有、只读；不能仅用批次和一个结果定位 |
| 执行状态 | 未发起 / 处理中 / 成功 / 失败，分别承接 CT-0～3；实际发起后才处理中；无结果不擅填失败。“结果待核实”为事实提示，不自造 CT 终态 |
| 时间 | 实际发起、确认完成、发现差异的各自时点及业务时区；没有结果不伪造完成时间 |
| 原因与下一步 | 执行失败或差异有可读原因；处理中不能重复发起；普通已确认失败且资格允许可新建申请；差异须先处理 |
| 费用 | 实际是否产生、金额及币种只读；资产方承担，已产生费用含失败张不退。未提供写“费用待核实”，不填 0、不因另一张零费用推断全批零费用 |
| 凭据 | 成功有可查验凭据，缺失不编造；可复制查验，展示沿共享口径，不以有凭据替代业务确认 |
| RV-17 差异事实 | 相关单笔、代币、原记录、迟到或冲突事实与发现时间；无差异不生成；不得关联到同代币的新申请而覆盖旧事实 |
| RV-18 释放跟踪 | 条件有值：相关单笔、已确认资产位置、释放结果是否确认、原因及时间；未知不写成功 |

**按张执行独立**：人工通过 A/B 后若 A 执行成功、B 执行失败，二者审核结论仍通过，后续结果不同；B 不影响 A。成功张还须满足有效性等既有规则才计覆盖，待审、通过待执行、处理中和差异均不计覆盖。只约束相关张，不锁全项目。

**D-PR-26 执行未知、逾期与迟到事实**：没有执行结果时，运营明确看到“处理中 / 结果待核实”、已等待时长和已知费用事实，不能以无结果证明已失败、已转回或可再次质押。原 WS-351 的“执行两天即失败并开放重押”只记录为待裁定旧建议，不作为本册已确认验收前提；阈值及收口方案见 Q-PR-05。

仍在等待且没有相冲突记录的晚到结果，按本笔实际执行结果呈现，不仅因等待较久就视为差异。出现与原记录冲突的迟到成功时，沿已明确的差异保护建议：保留原记录、关联本笔，不自动改回已质押、不重复计入覆盖，暂停该张新动作并形成运营待办；如已有新申请或新池，全部关联事实可查，不覆盖新单、不双池计入。其他无差异张继续正常。迟到信息不重复制造转移或费用，运营无手工置成功 / 恢复按钮；谁确认差异关闭仍待 Q-PR-05。

F-PR-19 / D-PR-27 的释放场景边界：

| 场景 | 本期明确结果与限制 |
| --- | --- |
| 正常未执行的单笔驳回 / 审核超时 | 仅结束本笔占用，本次零费用；无 X-05 释放，不说“已执行退款 / 费用不退” |
| 真实已转入但关联审核终结记录不符 | 作为该笔事实差异，形成“需释放处理”待办，不计覆盖、不准重复质押；并不预设有旧存量，不把正常已通过笔改成驳回来触发释放 |
| 释放未完成或失败 | 只读显示真实结果、原因、费用，保留跟踪；不先置可质押，不承诺已回原地址 |
| 有合法释放动作且成功已确认 | 展示转回质押前原持有地址的事实，可否再质押由最新资格决定；不允许人工指定其他地址 |
| 正常质押后的撤回、项目终态释放 | 归 WS-351，不再审核；PS-4“已释放 · 待提取”不是已经回到原地址，未提取不可重押 |

异常释放的发起人、资产方确认、费用责任、失败后的接续和恢复权限是 Q-PR-05 的重大业务问题，本册不自行补成自动释放方案。流程见 [FL-PR-02](v1.0-代币质押审核-流程图与状态机.md#fl-pr-02)、[FL-PR-03](v1.0-代币质押审核-流程图与状态机.md#fl-pr-03)；执行轴见 [ST-PR-02](v1.0-代币质押审核-流程图与状态机.md#st-pr-02)。

F-PR-13：留痕关联**批次＋单笔＋代币**，包含提交、撤回、人工结论、正式协议关联、自动超时、复核、执行、差异与释放结果、重新申请关联；记录事件、时间、主体、前后状态、原因与凭据。人工取当时身份，自动事件不伪造审核人；不可编辑删除，重新申请不覆盖旧笔；不同审核人的结果可在同批并存。

D-PR-17～19 / F-PR-16：沿用面客已登记事件名称和消息端别，**事件归属改为单笔，不以批次＋结论类型合并掉第二笔同类结果**；同一笔同一事件重复送达不形成重复消息。页内结果始终保底，投递失败不回滚。通知必须定位本笔代币及所属批次；不等待整批审完才触达。是否采用视觉聚合由消息及设计模块决定，但每笔内容、截止及操作不能丢失。

| 事件 | 收件方与内容 / 落点 |
| --- | --- |
| `financing.pledge.review_approved` | 面客提交资产方；本笔、代币、项目、通过时间与本笔入池截止；进入审核结果中该笔的确认位置，不自动执行 |
| `financing.pledge.review_rejected` | 同上；明确仅该笔驳回，原因全文原样，其他笔不受影响；可按资格重提本笔 |

| 运营待办 | 审核队列是逐笔；自动超时、执行失败、差异、需释放处理可按单笔定位；超时待办只追溯，不能补审。是否追加站内提醒及负责方见 Q-PR-09 |

正常新申请不额外全员广播，通过 / 驳回不重复通知刚裁定的运营。内部备注不进入面客原因或通知；D-PR-28：已读 / 已查看不等于差异已关闭或释放已完成。仅资产方本企业可看其材料及执行信息，资金方和游客不能读取审核记录。

## 7. 状态与字段的统一口径

**审核轴 RV-20（枚举，必有，默认待审核）**：待审核 / 通过 / 驳回 / 已撤回 / 审核超时失败。通过和驳回是人工结论，撤回和审核超时是未获人工结论的终结事件。通过后复核、执行变化不把 RV-03 的历史“通过”改成驳回。

| 对象与状态 | 触发及允许行为 |
| --- | --- |
| 单笔待审核 | 提交后未终结；有权限且未到期可裁定；面客可撤回本笔 |
| 单笔通过 | 有效提交通过＋协议；可进入本笔复核与资产方确认，运营不得二次裁定 |
| 单笔驳回 | 有效提交驳回＋原因；保留记录，结束本笔占用；可新笔再申请 |
| 单笔已撤回 | 资产方待审时有效撤回；无补审、不收费 |
| 单笔审核超时失败 | 本笔到审核截止仍无有效人工结论；自动失败，不能迟到补审 |
| 通过后：待确认入池 | 有效通过且未发起；按本笔入池截止判断 |
| 通过后：结论已作废 | 本笔复核不通过；不执行，原审核与协议存档 |
| 通过后：结论已失效 | 已到本笔七天期限且未发起执行的明确分支；已执行跨期见 Q-PR-06 |
| 通过后：执行中 / 成功 / 失败 | 本笔实际结果；成功且满足资格才是本张已入池；失败不把同批成功笔回滚 |
| 差异 / 释放未完成 | 并列事实标记，不覆盖人工审核结论；恢复动作必须有对应业务处置依据 |

**D-PR-31 批次汇总**：审核进度仅使用“待审核”（全部未处理）、“审核进行中”（仍有待审且至少一笔已终结审核）、“审核已结束”（无待审）。同时列待审、通过、驳回、撤回、审核超时失败五类笔数，合计等于本批总笔数；“审核已结束”不等于全部通过或质押成功。

执行摘要另列未发起、处理中、成功、失败的笔数，合计取已获通过的笔；复核作废、过期未发起在未发起类别中给明细原因，差异等为可叠加标记、不重复加总。对于尚未得到明确执行结果的张，不能算入失败或成功。“全部已入池”仅全批每笔都实际成功、满足有效性等入池资格且无待核实事实时才可作事实描述，不另造全批质押终态；单笔不全成功时始终保留逐笔结果。

PS-1 可质押 / PS-2 已质押 / PS-4 已释放仍由借贷平台维护；PS-3 作废占位、PS-0 非法。审核本身不写 PS；可再次选择还受实际占用、差异、资产有效性约束。CT 记录执行，不以审核超时扩展 CT 失败。

单笔字段 RV-19 / 20 / 21 / 22 与 RV-01～18 的完整含义见 M2～M6；本册引用 PA-01～04 和 PA-06 的提交事实。WS-351 原 PA-05 / 07 / 08 的批次级状态、原因、复核无法容纳上述事实，需要扩展为逐笔消费，具体衔接见 9.2，不能退回整批处理作为临时兼容。
