# 企业账户 · PRD

版本：2026-09-24，本批新建，状态待评审。任务：企业账户（WS-386）。适用：借贷平台桌面 Web 面客端，资产方与资金方双侧。

有效依据：用户 2026-09-24 裁定的企业账户口径（双侧覆盖含还款收款账户、一企业一员工不开放员工管理、变更不需审核、数币地址先选链再填地址并用被添加地址签名、法币与数币均取消收款人名称、业务办理不支持临时新增账户）与需求诊断简报 V4 第 4.6 节。业务名称以[字段命名与术语对照表](../00-字段命名与术语对照表.md)为基线；已入库的选用侧口径见[授信报价与接受拒绝](../v1.0-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#respond-account)与[放款与放款确认](../v1.0-借贷广场-放款与放款确认/01-放款与放款确认-PRD.md#f-ls-49)。

<a id="reading"></a>
## 1. 目标与阅读入口

企业在一个地方维护本企业的收款账户，业务办理时只从已登记账户中下拉选用。资产方用它收放款，资金方用它收还款；两侧是同一套字段、同一套维护规则，差别只在账户的资金用途。

本期包含：法币收款账户与数币收款账户的账户总览、新增、修改、删除与默认标记；数币账户的选链、填址与地址所有权签名；账户被业务选用后的快照与后续影响；本模块需要的权限项与入口挂载要求。

相邻模块负责：入口挂载与主干权限矩阵取值（登录主干与资产方SSO接入）、资金方账户设置与认证资格（资金方登录与账户体系）、资产方收放款账户的逐笔选用与确认（授信报价与接受拒绝）、资金方还款收款账户的登记与选用（放款与放款确认）、还款期次对账户快照的引用（还款计划与还款确认）、只读摘要（我的控制台）。

本期不包含：员工与成员管理、账户变更审核、出账（付款）账户的采集与必填、业务办理内临时新增或就地编辑账户、收款人名称及以其做归属校验、银行账户真实性与汇路可达性验证、跨企业的账户唯一性校验、运营端查看或代维护企业账户、代币与地址的链上转账能力。

阅读顺序：共同规则（第 2 章）→ 完整功能（第 3 章）→ 与相邻模块的接口口径（第 4 章）→ 依赖与待决（第 5 章）→ 既定业务限制（第 6 章）→ 同序验收（第 7 章）。配套：[流程图与状态机](./02-企业账户-流程图与状态机.md)、[消息通知](./03-企业账户-消息通知.md)。

## 2. 共同规则

<a id="D-EA-01"></a><a id="d-ea-01"></a>
**账户归属与单员工（D-EA-01）**：账户归属企业，不归属某个自然人。本期一个企业只有一个账号，该账号即唯一维护人与查看人；不提供成员邀请、角色分配、维护人与查看人分离或交接功能，也不显示“由谁维护”。后续若恢复多员工，须先由登录与账户体系定义企业内的责任账号，本册不自行挑选任一成员。

<a id="D-EA-02"></a><a id="d-ea-02"></a>
**双侧同规则、用途按业务区分（D-EA-02）**：资产方与资金方使用同一套账户类型、字段、校验与维护动作。资金用途由使用它的业务决定——资产方在接受报价时选定的是收放款账户，资金方在登记放款时选定的是还款收款账户；本模块不给账户预设用途标签，也不按用途限制可选范围。同一个账户可被多笔业务、两种用途重复选用。本期只维护收款账户，不采集、不必填任何出账（付款）账户，也不把收款账户默认当作出账账户。

<a id="D-EA-03"></a><a id="d-ea-03"></a>
**两个链概念不混用（D-EA-03）**：本模块只使用**结算收款链**——数币收款地址所在链，本期支持 ETH 与 TRON，地址格式与签名按链分别定义。代币与质押合约所在的**质押链**（本期仅 ETH）属融资需求与代币质押模块，与结算收款链互不决定。两者不共用同一个“链”字段，数币收款地址也不取代币的当前链上持有地址或质押合约地址。

<a id="D-EA-04"></a><a id="d-ea-04"></a>
**不采集收款人名称，平台不校验账户归属（D-EA-04）**：法币与数币账户**均不设收款人名称字段**，账户以账户备注名（EA-01）、账号 / IBAN（EA-04）或收款地址（EA-22）等关键信息辨识。原“收款人名称须与本企业法定名或已登记英文名一致”的硬校验不在本模块恢复，也不得用账户备注名、企业信息或任何其他字段变相实现。平台不具备“收款账户必须属于本企业”的自动校验能力，受益人名称由业务双方在平台外补充；后果见[既定业务限制](#limits)。唯一性只在本企业内校验，不做跨企业校验，也不据此推断归属。

<a id="D-EA-05"></a><a id="d-ea-05"></a>
**变更不需审核，保存即生效（D-EA-05）**：新增、修改、删除与默认标记都不进入任何审核队列，不产生待办，不需要运营确认；校验通过即生效并在本企业的账户总览与业务选用列表中立即可用或消失。保存进行中须让用户知道处理尚未完成，同值不重复保存；保存失败时账户保持上一次成功状态并可重试，不留半条账户。

<a id="D-EA-06"></a><a id="d-ea-06"></a>
**已选用账户的快照（D-EA-06）**：账户被业务选定并成功提交后，业务记录保存的是当时的账户快照，随记录固定。之后在本模块修改或删除该账户，都不回改、不补正、不撤回任何已提交的业务记录；已提交记录仍按其快照只读展示。尚未提交的办理若已选中被修改或删除的账户，下次进入该办理时说明该账户已变更或已删除，并要求重新选用，不静默替换成另一个账户，也不拿默认账户顶替。

<a id="D-EA-07"></a><a id="d-ea-07"></a>
**本人可见与脱敏（D-EA-07）**：企业账户属本企业档案，只有本企业账号可查看与维护。交易对手方不能从本模块读取账户；对手方在具体业务中按该笔当事方权限读取业务记录里的账户快照，与本模块无关。运营人员与 SPV 在任何场景都不可读取本模块账户、不可代维护、不可代选用。本企业本人在本模块查看与核对自己的账户时须能看到完整信息并可复制，不得只给掩码而让本人无法核对；业务侧的普通摘要仍按各业务已定的脱敏规则展示。

<a id="D-EA-08"></a><a id="d-ea-08"></a>
**账户可用的前提（D-EA-08）**：正常登录、角色已绑定、且当前业务资格为已认证时才能维护账户。账户被停用、登录失效、上游登记地址变更导致登录终止等情况下无有效会话，不能维护；恢复正常登录后账户数据不变、不需重登记。资格由服务端权威判定，界面隐藏不能代替服务端拒绝。

<a id="D-EA-09"></a><a id="d-ea-09"></a>
**时间与语言（D-EA-09）**：登记时间、修改时间取平台既定同源 UTC 时点，按用户时区展示并标注时区；显示偏好不改变先后顺序。界面语言沿既有面客双语基线，不为本模块新增语言范围。

**运营端不新增权限项（P-EA-02）**：本模块不向运营端新增任何功能权限项。运营既不查看也不维护企业账户，与 SPV 职责边界（不赋予资金代付、代收、代登记、代确认的能力）一致；运营端也不因本模块引入钱包、签名或链上动作。运营端权限清单在其批次回改时，无需为本模块增行。

## 3. 完整功能

<a id="f-ea-01"></a><a id="F-EA-01"></a>
### 3.1 企业账户入口与账户总览（F-EA-01）

验收：[企业账户总览验收](#ac-overview)。

**适用角色与前提**：已认证资产方、已认证资金方，正常登录。未认证的两侧可进入并看到本模块用途说明与补齐引导，看不到也不返回任何账户数据（本企业尚无账户时同样不虚构空账户）。

**正常流程**：进入企业账户 → 按**法币收款账户**与**数币收款账户**两类分别看到本企业已登记账户 → 对某个账户查看完整信息、修改、删除或设为默认 → 新增一个账户。

**关键规则**：两类账户分开呈现，不混列在同一份清单里。每个账户至少可辨识：账户备注名、类别（法币 / 数币）、法币的账号 / IBAN 与收款行名称或数币的结算收款链与收款地址、是否为默认、登记时间。本期不限制账户数量；确需上限须另行裁定，本册不设数值。列表顺序以本企业可稳定预期的顺序呈现（默认账户在前，其余按登记时间），不因一次读取失败改变顺序。

**异常与边界**：本企业尚无账户时给出明确空态并直接提供新增出路，不给空白表格假装有数据。读取账户失败时说明暂时不可用并可重试，**不把读取失败表达成尚未登记**，也不因此让用户重新录入一遍。账户被停用或会话失效时按[账户可用的前提（D-EA-08）](#d-ea-08)处理。

**通知**：无。本模块本期不发送任何站内信，见[消息通知](./03-企业账户-消息通知.md)。

流程参见：[账户总览与新增入口（图 1）](./02-企业账户-流程图与状态机.md#fig-1)。

<a id="f-ea-02"></a><a id="F-EA-02"></a>
### 3.2 新增法币收款账户（F-EA-02）

验收：[法币账户新增验收](#ac-fiat)。

**适用角色与前提**：已认证资产方或已认证资金方。法币结算币种本期只有 USD，法币账户即 USD 账户。

**正常流程**：新增法币账户 → 填写下表信息 → 提交 → 校验通过即登记成功，立即出现在账户总览与业务选用列表。

**关键规则**：**没有收款人名称字段**，见[不采集收款人名称（D-EA-04）](#d-ea-04)。提交不进审核，保存即生效。本企业内不允许重复登记同一账户：账号 / IBAN 与 SWIFT / BIC 同时相同即视为同一账户并拒绝，提示已存在并可直接去查看那一条。

| --- | --- | --- | --- | --- |

| <a id="ea-02"></a><a id="EA-02"></a>EA-02 账户币种 | 该账户可收款的法币币种，枚举 | 必有，本期定值 USD，只读 | 本企业本人只读 | 本期不提供选择；业务选用时按结算币种匹配，USD 业务只能选法币账户 |

**异常与边界**：必填缺失、SWIFT / BIC 格式错误、中转行填一半、本企业内重复账户分别给出具体原因并定位到该项，不笼统报“保存失败”。保存失败时不产生半条账户；用户取消或离开时不保留未提交内容（本模块不设草稿）。平台不验证银行账户真实性与汇路可达性，任何位置都不显示“账户已验证”。

### 3.3 新增数币收款账户（F-EA-03）

验收：[数币账户新增与地址所有权验收](#ac-crypto)。

**适用角色与前提**：已认证资产方或已认证资金方，且能用**被添加的那个地址**完成一次签名。

**正常流程**：新增数币账户 → 选择结算收款链（ETH 或 TRON）→ 填写该链的收款地址 → 用该地址签名确认地址所有权 → 签名通过即登记成功。三步顺序固定：**没有选链不能填地址，没有签名通过不算登记成功**。

**地址所有权签名的边界**：签名只证明本企业持有该地址的私钥。它**不建立登录会话、不切换登录钱包、不参与登录地址匹配、不改变已绑定角色，也不改绑登录凭据**；被添加地址可以与登录地址不同，也可以在另一条链上（例如登录地址为 ETH 而登记 TRON 地址）。签名请求前须说明本次用途是“证明这个地址归你所有”，不得表现为登录或身份切换。签名拒绝、失败、超时或中途更换了钱包地址时，本次不登记，可重试；重试不影响当前登录与已有账户。此处与主干“登录状态下不提供切换钱包入口”的关系见[本模块需要的权限项（P-EA-01）](#p-ea-01)与[依赖与待决](#dependencies)。

**只能登记本企业能签名的地址**：由签名要求直接产生的业务约束是——交易所充值地址、第三方托管地址、以及无法签名的合约地址都无法登记。这一点须在填写地址**之前**告知，不能等用户签名失败才解释。

| --- | --- | --- | --- | --- |

| <a id="ea-24"></a><a id="EA-24"></a>EA-24 可接收代币 | 该地址可接收的数币，枚举：USDT、USDC | 必有，本期两者皆可，只读 | 本企业本人只读 | 本期不按代币分别登记地址，同一地址可接收 USDT 与 USDC；业务选用时按结算收款链匹配，不按代币区分。此项口径见[依赖与待决](#dependencies) |

**通知**：无，见[消息通知](./03-企业账户-消息通知.md)。

### 3.4 修改账户（F-EA-04）

验收：[账户修改验收](#ac-edit)。

**适用角色与前提**：已认证资产方或已认证资金方，账户属本企业且未删除。

**正常流程**：在账户总览选择某账户 → 修改可编辑项 → 提交 → 校验通过即生效。

**关键规则**：法币账户除账户币种（[EA-02](#ea-02)）外全部可改，校验与新增一致。数币账户**只有账户备注名可改**；结算收款链（[EA-21](#ea-21)）与收款地址（[EA-22](#ea-22)）登记后不可修改——地址所有权是对那一个地址签名的结果，改地址等于登记另一个账户，须走[新增数币收款账户（F-EA-03）](#f-ea-03)并重新签名，旧账户可另行删除。修改不需审核、不重新签名（备注名不涉及所有权）、保存即生效。修改不回改任何已提交业务记录，见[已选用账户的快照（D-EA-06）](#d-ea-06)。

**异常与边界**：校验失败时保持账户原值并定位到该项；修改后与本企业另一账户构成重复（法币同账号 / IBAN 与 SWIFT）时拒绝并说明。取消或离开不改变原值。不提供“批量修改”“导入覆盖”这类本期未确认的能力。

**通知**：无。数币地址不可改这一点使得“地址被静默篡改”不成立；法币账户被改动是否需要安全告知尚待裁定，见[依赖与待决](#dependencies)。

流程参见：[法币账户新增与修改（图 2）](./02-企业账户-流程图与状态机.md#fig-2)。

<a id="f-ea-05"></a><a id="F-EA-05"></a>
### 3.5 删除账户（F-EA-05）

验收：[账户删除与快照验收](#ac-delete)。

**适用角色与前提**：已认证资产方或已认证资金方，账户属本企业。

**正常流程**：选择账户 → 删除 → 显式确认（说明删除后不再出现在任何选用列表、已提交业务记录不受影响）→ 删除生效。

**关键规则**：删除是“不再可选用”，不是抹除历史。删除后该账户不出现在账户总览与任何业务的选用列表；已提交业务记录中的账户快照不变，双方仍可按各业务权限只读查看，见[已选用账户的快照（D-EA-06）](#d-ea-06)。若被删除的账户是某类的默认账户，删除后该类没有默认，不自动把另一个账户提升为默认。删除不需审核，也不因该账户正被进行中业务引用而被禁止——尚未提交的办理按 D-EA-06 要求重新选用。

**异常与边界**：删除最后一个可用账户是允许的，但须在确认时告知“删除后该币种／该链暂无可选账户，相关业务办理将无法提交，需要时可重新登记”。删除失败保持原状可重试。删除不可撤销，不提供回收站；需要恢复时重新登记（数币须重新签名）。

**通知**：无，见[消息通知](./03-企业账户-消息通知.md)。

流程参见：[删除账户与已提交记录的关系（图 4）](./02-企业账户-流程图与状态机.md#fig-4)、[收款账户生命周期状态机](./02-企业账户-流程图与状态机.md#state-2)。

### 3.6 默认收款账户（F-EA-06）

验收：[默认标记验收](#ac-default)。

**适用角色与前提**：已认证资产方或已认证资金方，本企业至少有一个该类账户。

**正常流程**：在账户总览把某账户设为默认 → 立即生效 → 同类中原默认自动取消。

**关键规则**：<a id="ea-30"></a><a id="EA-30"></a>**默认收款账户（EA-30）** 按类分别设置——法币最多一个默认、每条结算收款链最多一个默认；不设跨类的“全局默认”。默认标记只是**业务带出的兜底**：业务模块自己的带出顺序优先（例如接受报价时先带出本笔已确认的选择，其次本企业最近一次成功接受中同币种的账户），两者都不适用时才带出默认账户。**默认不等于已选定**：任何业务仍须按各自规则显式确认本笔账户，不因存在默认账户而自动勾选或跳过确认。可以取消默认而不删除账户；没有默认账户不阻塞任何业务。

**异常与边界**：设置失败保持原默认；同类不会出现两个默认。删除默认账户后该类无默认，见[删除账户（F-EA-05）](#f-ea-05)。

**通知**：无。

<a id="f-ea-07"></a><a id="F-EA-07"></a>
### 3.7 业务办理侧的选用与回流（F-EA-07）

验收：[选用与回流验收](#ac-select)。

**适用角色与前提**：在具体业务办理中需要指定收款账户的当事方；本模块只定义被选用侧须满足什么，选用动作本身归相应业务模块。

**关键规则**：

1. **办理内只选不建**。业务办理过程中不提供新增、就地编辑或删除账户的入口，也不允许手输账户信息替代已登记账户。需要新账户时前往企业账户维护，再回到本笔选用。
2. **按结算币种与链匹配可选范围**。USD 业务只能选法币账户；USDT / USDC 业务只能选数币账户，并带出该账户的结算收款链（[EA-21](#ea-21)）与收款地址（[EA-22](#ea-22)），在本笔只读，办理中不切链、不改址、不换钱包。
3. **无可用账户时不给空白表单**。直接说明本企业尚未登记可用账户并指向企业账户，登记完成后回到原办理的原位置继续，已填内容不丢失。
4. **读取失败不等于未登记**。读取本企业账户失败时说明暂时不可用并可重试，不把它表达成尚未登记而要求用户重填，也不因此放行缺账户的提交。
5. **提交即快照**。成功提交后账户信息随业务记录固定，见[已选用账户的快照（D-EA-06）](#d-ea-06)。

**异常与边界**：所选账户在提交瞬间已被删除或修改时，本次提交不成立，说明账户已变更并要求重新选用，不拿旧值提交；同一账户被多笔业务同时选用是允许的，不互相锁定。

流程参见：[业务办理侧选用与回流（图 5）](./02-企业账户-流程图与状态机.md#fig-5)。

<a id="limits"></a>
## 6. 既定业务限制（供研发与测试知悉）

以下三项是用户明确裁定后的既定结果，此处如实记录其业务后果，不作为异议保留。

1. **平台不再采集与校验收款人名称。** 法币与数币账户均取消收款人名称，原“收款账户必须属于本企业”的硬校验一并删除。后果：受益人名称需由业务双方在平台外补充；平台不具备该项自动校验能力，本模块也不得以账户备注名或其他字段变相恢复。账户填错或选错的后果由双方线下承担。
2. **只能登记本企业能签名的地址。** 地址所有权签名带来的必然限制是：交易所充值地址、第三方托管地址、无法签名的合约地址都无法作为收款地址登记。后果：使用托管钱包收款的企业无法在本平台登记该地址，须改用自持地址；该限制须在填写地址前告知，不能等签名失败才解释。
3. **本期一个企业只有一个员工。** 不提供员工管理、权限分配与交接。后果：该账号一旦不可用，本企业没有第二个人能维护收款账户；这不是缺陷，测试按此预期设计用例。恢复多员工须先由登录与账户体系定义企业内的责任账号。
