# 融资台账 · 功能与业务规则

2026-10-26｜运营端：运营管理员｜需求评审稿，所属端、查询范围与信息结构已由用户确认，见末节

本模块共三册：本册定义功能与业务规则；[流程图与状态机](02-融资台账-流程图与状态机.md)说明记录何时出现在清单与详情中、查看与穿透；[验收](04-融资台账-验收.md)供测试使用。融资台账只读、自身不发送消息，所以没有 03 消息通知册，并非缺失。功能编号沿用原值，已删除的编号不再占用，缺号不代表遗漏。

<a id="design-boundary"></a>
本册只定义信息需求与业务行为。用户已指定的设计约束：

- 融资台账是一个菜单，菜单内有融资项目清单与融资需求清单两个清单。
- 记录详情以 tab 承载各部分信息。
- 清单中的状态保持简洁：链上处理中、链上结果待核实等过程信息不在清单中呈现，只在详情中展示。

清单与详情的版式、tab 的排列与默认打开项、详情内记录的展开方式、筛选与跳转的交互承载由 Hallmark 决定。业务名称以[字段命名与术语对照表](../../00-字段命名与术语对照表.md)为基线。

## 1. 模块是什么

运营管理员在运营端“融资台账”菜单中，逐笔查看全平台的融资业务。台账有两个清单：

- **融资项目清单**：一条记录一个已通过审核的项目。项目详情可读项目基本信息、本项目的代币质押，以及本项目的各轮融资需求。
- **融资需求清单**：一条记录一轮融资需求。需求详情可读需求信息、本轮的报价放款，以及成交后的还款。

一轮需求最多成交一笔：报价被接受、链上放款成功即本轮结束，因此每轮需求对应若干笔报价，其中最多一笔完成放款，并最多对应一份还款计划。台账只读，全部数据取来源模块的当前事实，用于对账、业务跟踪和协助客户核实链上结果；办理仍由资产方、资金方在面客端完成。

基本原则：

- **按项目看，按需求查。** 项目清单回答“这个项目整体怎样”，需求清单回答“全平台的融资业务进行到哪一步”；两者都能穿透到同一份需求详情。
- **报价与放款合为一个对象。** 一笔报价及其链上放款结果在同一条“报价放款”记录中阅读，不再分开查看。
- **清单简洁，详情完整。** 清单只给识别信息、关键金额与业务状态；链上处理进展、待核实、原因说明与完整条款都在详情中阅读。
- **只读。** 台账不提供审核、代办、修改、撤销、关闭、催办或补记等任何动作，不改变任何业务状态，不发送消息。
- **不另定口径。** 字段、状态、金额、计息、逾期和质押情况全部采用来源模块当前结果；来源口径调整时台账随之一致。
- **全平台范围。** 同一主体不按机构隔离（[数据可见范围（D-AL-05）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-05)），查看需要本模块的[融资台账查询（PM-LG-01）](#pm-lg-01)。
- **与既有运营模块分工。** 项目审核与合约配置在[项目合约管理](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md)，平台合计与待办在[运营端总览](../08-运营端总览/01-运营端总览-PRD.md)；台账不重复审核队列，也不替代总览的统计。

**一个完整的例子。** 运营管理员打开“融资台账”，默认看到融资项目清单。甲企业的项目 P1 显示为融资中，有效质押额 1,000,000.00 USD，项目融资余额 500,000.00 USDT，质押情况为质押充足。管理员打开 P1 的项目详情：项目基本信息中可读三份合约地址与额度；代币质押中列出 12 条质押记录；融资需求中列出两轮，第 1 轮已失效，第 2 轮已放款。

点开第 2 轮进入需求详情：
- 报价放款中有两笔：一笔已拒绝，可读拒绝原因；一笔已接受，同一条记录里可读报价机构乙、融资金额 500,000.00 USDT、结算币种 USDC、年化融资利率 8%，以及放款编号、放款金额 500,000.00 USDC 与放款成功时间；这笔报价的授权交易哈希与放款交易哈希在需求详情的操作记录中。
- 还款中可读未偿本金 500,000.00 USDT 和 2 期计划：第 1 期期次状态为还款上链确认中、已逾期 3 天，可读提交时间与已等待时长；这笔还款交易的哈希在需求详情的操作记录中，标为处理中，可复制，也可到区块链浏览器核对。

另一天，甲企业客户只报出一个放款编号询问还款结果。管理员切到融资需求清单，用放款编号检索到这一轮。清单中只显示申请状态“已放款”、还款状态“逾期”，链上确认中的进展在需求详情的还款中阅读。台账不提供任何处理动作；管理员返回清单，原来的筛选和页码保持不变。

### 1.1 本期不做

- 任何办理或处置动作：审核、代签名、代付、代报价、代接受、代还款、撤销授权、关闭项目、强制释放、补记或改判。
- 导出、打印与批量下载，见[台账导出（Q-LG-04）](#q-lg-04)。
- 统计图表、比率、排行与自定义指标；平台合计仍以运营端总览为准。
- 独立的代币质押、报价、放款或还款期次清单：跨项目只能按融资需求查询，质押与期次在详情中阅读（用户 2026-10-26 确认）。
- 待审核、配置处理中、已退回以及审核通过前已关闭的项目，这些在项目合约管理中查看。
- 质押、发布、报价、放款或还款上链明确失败、未形成业务对象的发起记录。
- 授信关系、授信额度与占用、授信备注与授信协议文件。
- 企业账户档案（含法币账户与数币账户的账户备注名）、个人档案、机构认证资料、底层合同号与发票号。
- 链上授权清单与撤销授权；各类链上交易的 gas。
- 面客端的台账视图（用户已确认只做运营端，见[所属端与可见范围（Q-LG-01）](#q-lg-01)）。

## 2. 术语

| 术语 | 本册含义 |
| --- | --- |
| 融资台账 | 运营端模块与导航菜单名（英文 Financing ledger），以融资项目清单与融资需求清单逐笔查看全平台融资业务 |
| 清单 | 融资台账菜单下的融资项目清单或融资需求清单 |
| 详情 | 一条清单记录的只读完整信息，即项目详情或需求详情，内部以 tab 分部分展示 |
| 报价放款 | 一笔报价及其链上放款结果合成的一条记录；报价被接受、链上放款成功后，放款信息并入同一条记录 |
| 还款状态 | 本册为融资需求清单定义的成交后业务摘要：还款中、逾期、已结清；取值规则见[融资需求清单](#f-lg-05) |
| 链上处理中 | 来源模块已发起、链上结果尚未回写的过程，例如发布冻结处理中、报价上链确认中、链上放款处理中、还款上链确认中；不是新的业务状态，只在详情中展示 |
| 链上结果待核实 | 来源模块对长期未知或冲突的链上结果给出的事实，面客端此时提示“链上结果待核实，请联系平台客服人员”；台账只在详情中如实展示，不提供处理动作 |
| 筛选结果合计 | 当前清单在当前筛选条件下全部记录的数量与金额合计，不是当前页合计 |

## 3. 进入融资台账与权限（F-LG-01）

适用角色与前提：本期唯一角色为运营管理员，须完成首登改密、账号正常且会话有效，遵守[权限底线（F-AL-17）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#f-al-17)。

- 运营端共享导航中提供“融资台账”菜单（英文 Financing ledger）；进入后默认打开融资项目清单。
- 菜单下两个清单的顺序为：融资项目清单、融资需求清单。
- 会话失效、待首登改密或账号不可用时，立即停止展示台账数据并按账户模块引导；重新登录后重新判定权限，不直接恢复旧数据。

<a id="pm-lg-01"></a>**融资台账查询（PM-LG-01）。** 按[权限组织方式（D-AL-07）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-07)，本模块定义一项权限：

| 权限项 | 覆盖的业务能力 |
| --- | --- |
| 融资台账查询（PM-LG-01） | 进入融资台账，查看两个清单、筛选结果合计、项目详情与需求详情的全部 tab；不含任何办理或处置动作 |

- 本期运营管理员固定具有（[本期预置角色（D-AL-08）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-08)），见[运营端逐笔查询权限（Q-LG-02）](#q-lg-02)。
- 缺少该权限时不出现菜单；直接访问台账或任一详情统一提示无权限，不透露记录是否存在。
- 其他权限项（如[融资项目审核查询（PM-AL-17）](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#permissions)、[平台融资统计查询（PM-OV-01）](../08-运营端总览/01-运营端总览-PRD.md#pm-ov-01)）都不覆盖本模块；本模块权限也不覆盖其他模块。
- 本模块权限只开放本册列明的信息，不因此取得企业账户档案、授信、个人档案或面客端办理能力。

## 4. 两个清单与共同展示规则（F-LG-02）

适用角色与前提：满足[进入融资台账与权限（F-LG-01）](#f-lg-01)。

**信息结构。**

| 清单 | 一条记录是 | 纳入范围 | 详情中的 tab |
| --- | --- | --- | --- |
| [融资项目清单](#f-lg-03) | 一个融资项目（FP-01） | 审核通过（合约配置成功）的项目，含之后关闭或结清的；不含待审核、配置处理中、已退回、审核通过前已关闭的项目 | [项目基本信息](#f-lg-03)、[代币质押](#f-lg-04)、[融资需求](#project-demands) |
| [融资需求清单](#f-lg-05) | 一轮融资需求（FP-28） | 发布成功的各轮，含已终结的；以及发布冻结处理中或结果待核实、尚未生成编号的发起；不含发布冻结明确失败、未签名或取消的发起 | [需求信息](#f-lg-05)、[报价放款](#f-lg-06)、[还款](#f-lg-08) |

**清单与详情的分工。**

- 各字段表的“清单 / 详情”列说明该信息在清单中直接可读，还是只在详情中可读；清单中可读的信息在详情中同样可读。
- 清单中每条记录只显示业务状态（项目状态、质押情况、申请状态、还款状态），且每项只显示状态文字，不附加标签或说明。
- 链上处理中、链上结果待核实、已等待时长、终结原因、关闭原因、逾期天数、质押缺口等过程与说明信息，只在详情中展示。
- 详情中各 tab 内的记录列表（质押记录、本项目各轮需求、报价放款、还款期次）属于详情，可以展示链上处理中与链上结果待核实。
- 清单不提供链上处理中或链上结果待核实的筛选项。

**共同展示规则。**

- 金额一律带单位：份额价值、总质押额、有效质押额等质押价值以 USD 计；融资需求金额、融资金额、项目在途金额、项目融资余额、本金、利息、应还合计以 USDT 计；结算金额、放款金额、还款金额以本笔结算币种（USDT 或 USDC）计。金额两位小数、千分位，按来源取值，不重新计算或换算；USD 与 USDT 只在来源已给出的质押情况判断中按 1:1 比较，台账不另做比较。
- 业务日期（有效期至、应还日、起息日、最终还款日等）为 UTC 日期并标注 UTC；具体时刻按本人偏好时区显示并标注时区，规则沿[界面语言与时区偏好（F-AL-10、F-AL-11）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#f-al-10)。切换时区不改变业务日期或排序。
- 网络以图标与名称同时展示，名称一律为“Ethereum”，中英文界面都不写“以太坊”或“ETH”。
- 业务地址（原持有地址、融资收款地址、放款地址、还款收款地址、资产方收款地址、出账地址）在详情中给出网络与完整地址，可复制；在清单、展开中的记录表与操作记录中缩写，点击即复制完整地址，规则见[钱包地址展示](../../00-钱包地址展示.md)；运营可见范围见[运营可见的地址与交易信息（Q-LG-03）](#q-lg-03)。
- 合约地址与交易哈希的展示见下方[合约地址、交易哈希与操作记录](#chain-display)。
- 来源没有值时显示“—”，未知的链上结果标“待核实”；不以 0、示例值或其他记录的值补位。真实为 0 的金额显示 0.00。
- 状态都有文字，不只靠颜色区分。链上处理中、链上结果待核实与业务状态分开表达，不合成新的状态。
- 链上处理中的记录可读已等待时长；它只是如实计时，不表示超时或剩余时间，台账不展示任何截止时刻或倒计时。

<a id="chain-display"></a>**合约地址、交易哈希与操作记录。** 与面客端[所交互的合约、签名用途与交易哈希](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#chain-display)及[详情中的交易哈希只在操作记录展示](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#operation-records)同一口径（用户 2026-10-26 裁定、要求），见[合约与交易哈希的展示（Q-LG-06）](#q-lg-06)：

- 合约由本平台为项目配置，链上交易都经本平台发起，合约地址与交易哈希都不标注“平台未核验”。
- 合约地址只在项目详情的项目基本信息中展示（本项目的质押合约、放款合约、还款合约）：给出完整值，可复制，也可在 Ethereum 区块链浏览器新窗口打开该合约地址核对。其他详情、记录与操作记录不重复合约地址。
- 统一称“交易哈希”，按交易类别称冻结交易哈希、授权交易哈希、放款交易哈希、质押交易哈希、转出交易哈希、还款交易哈希；与来源模块的[授信报价与接受拒绝](../../面客端/06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md)的授权交易哈希（QT-19）、[放款交易哈希（LN-08）](../../面客端/06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#ln-08)、[质押交易哈希（PL-08）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#pl-08)、[交易哈希（RM-08）](../../面客端/08-借贷广场-链上还款/01-链上还款-PRD.md#rm-08)同一事物。
- 详情中的交易哈希只在操作记录展示。台账有两类操作记录：每条质押记录一份（见[项目详情中的代币质押](#f-lg-04)），每轮融资需求一份（见[需求详情的操作记录](#demand-operations)）。清单、报价放款、还款期次与还款记录只展示业务事实，不重复交易哈希。
- 操作记录按时间倒序，每笔已发出的链上交易一条，给出时间（标注时区）、操作、地址、交易哈希四项。地址取签名确认这笔交易的地址；由平台直接执行的取平台执行钱包地址。地址缩写，点击即复制完整地址，按[列表与清单中的钱包地址（F-WA-02）](../../00-钱包地址展示.md#F-WA-02)。
- 尚未成功的一笔在操作旁标明处理中、未成功或待核实；状态变化只更新这一条，同一笔交易不出现两条。重新办理产生的新交易另起一条，原未成功的一条保留。没有发出交易的签名、取消或校验未通过不产生记录。
- 交易哈希缩写展示，保留开头与结尾，位数由设计统一；点击即复制完整值并提示已复制，复制失败时给出完整值供手动复制；另可跳转 Ethereum 区块链浏览器中该笔交易，在新窗口打开，原页面位置保留。区块链浏览器入口暂不可用时不提供死链接，仍可复制。缩写只影响展示，复制与跳转都使用完整值。
- 交易哈希在平台取得后才展示，未取得时不显示占位值。区块链浏览器只供核对，结论以平台确认的结果为准。

## 10. 详情穿透与返回（F-LG-09）

适用角色与前提：满足[进入融资台账与权限（F-LG-01）](#f-lg-01)。

- 两个清单的每条记录都能打开详情；已终结、已结清、已关闭的记录同样可以打开。详情只读，不提供任何办理动作。
- 项目详情以项目名称与项目编号识别，需求详情以融资申请编号及所属项目识别；尚未生成编号的发布冻结处理中记录，以所属项目、金额与发起时间识别。
- 穿透关系：

| 从 | 可前往 |
| --- | --- |
| 融资项目清单的一条记录 | 该项目的项目详情 |
| 融资需求清单的一条记录 | 该轮的需求详情 |
| 项目详情的融资需求 tab 中的一轮 | 该轮的需求详情 |
| 需求详情中的所属项目 | 所属项目的项目详情 |
| 项目详情 | 项目合约管理中该项目的审核详情，仅对同时具有[融资项目审核查询（PM-AL-17）](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#permissions)的账号提供 |

- 质押记录、报价放款记录与还款期次在所属 tab 内展开阅读，不另设独立详情。
- 详情不提供台账与项目审核详情以外的入口，不进入面客端页面。
- 返回时回到来源：来源为清单时，保留原来的筛选、排序、页码与所在位置；来源为详情时，回到原详情及原 tab。来源记录因数据更新不再满足清单筛选时，说明记录已更新并可清除筛选。

流程见[查看、穿透与返回（FL-LG-02）](02-融资台账-流程图与状态机.md#fl-lg-02)。

## 11. 浏览、筛选与视图保持（F-LG-10）

适用角色与前提：满足[进入融资台账与权限（F-LG-01）](#f-lg-01)。

| 视图条件 | 类型与默认 | 规则 |
| --- | --- | --- |
| 当前清单 | 单选，默认融资项目清单 | 只允许两个清单之一；非法值回到默认清单 |
| 筛选 | 各清单定义的条件，均可不选，默认不限 | 多个条件取交集；日期范围按 UTC 日期，起止都包含当天，起点晚于终点时就地提示、不执行；筛选变化回到第 1 页 |
| 关键词 | 单行文本，默认空 | 去除首尾空格；编号按完整值精确匹配，名称可部分匹配，地址按完整值匹配；与筛选取交集；变化回到第 1 页 |
| 排序 | 各清单定义的字段与升降序 | 金额与时间按精确值排序；值相同时按本清单对象编号升序，保持稳定；变化回到第 1 页 |
| 页码 | 默认第 1 页；每页固定 20 条，沿用运营端现行取值，不提供条数切换 | 显示按当前筛选计算的总数；超出最新总页数时回到最后一个有内容的页并说明 |
| 当前详情与 tab | 打开详情时的对象与 tab | 默认打开哪个 tab 由设计决定；返回或刷新时保持原对象与原 tab |

- 两个清单各自保留自己的筛选、排序与页码，切换时不互相带入。详情 tab 内的筛选与页码只在本次查看该详情时保留。
- 浏览器刷新或复制当前地址后再打开，恢复当前清单与全部条件，或当前详情与 tab；地址不转让权限，打开时仍按当前账号判权。
- 有筛选或关键词时，当前生效的条件可见，并可一次清除全部条件。
- 筛选结果合计按当前筛选条件下的全部记录计算，不随翻页变化；不同单位分别给出，不相加。筛选结果为空时，记录数为 0、金额合计为 0.00。
- 筛选结果合计只是台账查询结果，不替代运营端总览的平台统计；两者口径与统计范围以各自定义为准。

## 12. 读取状态与异常（F-LG-11）

适用角色与前提：满足[进入融资台账与权限（F-LG-01）](#f-lg-01)。进入台账、切换清单、改变视图条件、打开详情或切换 tab、浏览器刷新和从详情返回时读取当前事实；不设自动刷新周期。

| 情形 | 可观察结果 | 可继续的动作 |
| --- | --- | --- |
| 读取中 | 明确正在获取，未取得的数量与金额不先显示 0 | 等待结果 |
| 清单或 tab 本身没有记录 | 说明当前没有该类记录，例如“暂无融资需求”“本轮尚未放款” | 可切换其他清单或 tab |
| 筛选无结果 | 说明当前筛选未匹配，不说成平台没有该类业务 | 清除筛选 |
| 清单、合计或某个 tab 读取失败 | 仅失败部分显示暂不可用，不显示成空或 0；其他已成功的部分照常可读 | 重试 |
| 记录不存在或无权查看 | 统一提示内容不存在或无权访问，不透露对象是否存在 | 返回来源清单 |
| 链上结果待核实 | 只在详情中如实展示“链上结果待核实”与已等待时长，已取得的交易哈希在操作记录中标为待核实；不推定成功或失败 | 无处理动作 |
| 权限在查看中被收回或会话失效 | 立即停止展示台账数据 | 按账户模块处理 |

- 记录状态在浏览期间被来源改变时，下次读取按新事实展示；不保留过期结果凑原位置。
- 台账不修改来源数据，读取失败不影响任何业务。

流程见[读取与异常（FL-LG-03）](02-融资台账-流程图与状态机.md#fl-lg-03)。
