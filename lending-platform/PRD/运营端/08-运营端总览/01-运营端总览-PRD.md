# 运营端总览 · 功能与业务规则

2026-10-26｜运营管理平台 · 运营管理员｜需求评审稿

本模块共三册：本册定义功能与业务规则；[流程图与状态机](02-运营端总览-流程图与状态机.md)说明查看与办理后的回流；[验收](04-运营端总览-验收.md)供测试使用。总览自身不发送消息，所以没有 03 消息通知册，并非缺失。功能编号沿用原值，新增功能接续编号，因此章节顺序与编号顺序不一致，缺号不代表遗漏。

## 1. 模块是什么

运营管理员登录后，通过总览了解平台当前的资产与融资规模、每日新增情况和近期审结情况，并找到当前需要人工处理的审核与融资参数配置。总览沿用账户模块的总览页（P-O-AL-07），只提供业务摘要和原功能入口，办理仍在各来源模块完成。

总览的信息分为四组：

- 平台统计：三项金额统计（代币价值、融资需求金额、已融资余额）与三项核心统计（已准入代币、已通过项目、已认证资金方机构）。
- 每日新增：三项金额统计按 UTC 日的新增情况。
- 近期审结：代币准入与融资项目近 7 个自然日的审结数。
- 待办事项：四类待办的当前数量与办理入口。

用户 2026-10-26 指定的设计约束：平台统计位于页面最上方；待办事项位于右上角或右下角区域；整体视觉为 web3 平台风格。每日新增可用柱状图或折线图呈现。除此之外的布局、图形与视觉承载由 Hallmark 决定。

基本原则：

- 平台统计与待办事项不重复呈现同一数量：待审核、未配置等待办数量只在待办事项中出现。
- 金额只汇总来源模块已定义的金额，沿用来源的计价单位与快照规则；不同单位的金额不相加、不互相换算。
- 统计与待办按读取时的当前业务事实计数；近期审结沿用来源模块已定义的统计口径。消息未读不等于待办。
- 查询与办理沿用来源权限、状态和规则，查看总览不产生审核结论或业务变更。

**一个完整的例子。** 管理员登录后，页面最上方显示代币价值 3,200,000.00 USD、融资需求金额 600,000.00 USDT、已融资余额 1,500,000.00 USDT，以及已准入代币 30 笔、已通过项目 12 个、已认证资金方机构 4 家。每日新增显示近 14 个 UTC 日的数据：今天（UTC，尚未结束）新准入代币价值 200,000.00 USD、新发布融资需求 150,000.00 USDT、新增放款 0.00 USDT。近期审结显示代币近 7 个自然日（UTC）通过 6、退回 1，项目人工审结 4。待办中待审核项目为 3 个，其中 1 个配置失败待再次发起。资金方随后接受了一笔 150,000.00 USDT 的报价并链上放款成功，下一次读取时融资需求金额减少 150,000.00 USDT，已融资余额增加 150,000.00 USDT，今天的新增放款变为 150,000.00 USDT。管理员打开项目待审核队列再次发起配置，返回总览时待审核项目变为 2 个。

### 1.1 本期不做

- 不展示比率指标（通过率、退回率、配置成功率等）和环比、同比涨跌。
- 不展示收益、利息、逾期、授信额度与占用、质押额、排行榜，不汇总应收账款原币金额。
- 不提供日期、机构、网络或币种等统计筛选，不提供导出、钻取与自定义指标；平台统计、每日新增与近期审结只读，不从这些数字跳转列表。
- 不展示逐笔融资、放款、还款或代币明细，不开放运营端对融资需求、报价、放款的逐笔查询。
- 不展示各来源的状态构成，不展示逐条待办对象、已等待时长或个人经办量；不复制审核列表、消息预览或协议操作记录，不新增批量审核、待办认领、催办和手工完成。
- 协议到点生效结果及其失败告警继续由既有协议管理和运营端消息通知承接，不在总览再建一套提醒或日程。

## 2. 术语

| 术语 | 本册含义 |
| --- | --- |
| 核心统计 | 当前记录中已准入代币、已通过项目、已认证资金方机构的数量，不是期间新增量 |
| 金额统计 | 平台当前代币价值、融资需求金额、已融资余额三项合计，各自沿用来源模块的金额定义与单位 |
| 每日新增 | 某一 UTC 日内新发生的准入通过、需求发布或链上放款所对应的金额合计 |
| UTC 日 | 按 UTC 时间划分的自然日；“今天”指当前所在的 UTC 日，尚未结束 |
| 近期审结 | 来源模块已定义的近 7 个自然日审结统计，按 UTC 日期计算 |
| 待办 | 当前仍需运营审核或补齐融资参数的业务对象；同一对象在同一类别只计一次 |
| 融资参数组合 | 区块链网络与代币类型的组合，按融资参数配置模块定义产生并保留 |

## 3. 进入总览与权限范围（F-OV-01）

适用角色与前提：本期唯一角色为运营管理员，须完成首登改密、账号正常且会话有效，遵守[权限底线（F-AL-17）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#f-al-17)。

- 无原目标的登录按[登录后落地与回跳（F-AL-06）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#f-al-06)进入总览；已有合法原目标时沿用账户模块的回跳规则。
- 已登录运营人员可从管理端共享导航进入总览；导航承载、布局与视觉由 Hallmark 决定。
- 总览入口不新增独立权限项；每项数字须具有下表对应的查询权限，本期运营管理员固定具有全部业务权限（[角色差异（D-AL-08）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-08)），因此已全部开通。
- 缺少某项查询权限时，依赖该权限的全部数字与业务入口均不展示；直接访问目标仍由来源模块拒绝，不以 0 或空列表透露对象是否存在。
- 具有查询权限但不具备处置权限时，可以查看数量并进入原查询列表，实际办理按来源模块权限拒绝；总览不补授权限。
- 会话失效、待首登改密或账号不可用时，停止展示受保护数据并按账户模块引导。

| 来源 | 总览读取所需查询权限 | 依赖该权限的总览信息 | 原业务办理权限与配套要求 |
| --- | --- | --- | --- |
| 代币准入审核 | [代币准入审核查询（PM-TA-01）](../06-代币准入审核/01-代币准入审核-PRD.md#pm-ta) | 代币价值及其每日新增、已准入代币数、代币近期审结、待审核代币 | 代币准入审核处置（PM-TA-02），配套查询权限 |
| 项目合约管理 | [融资项目审核查询（PM-AL-17）](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#permissions) | 已通过项目数、项目近期审结、待审核项目 | 融资项目审核与合约配置处置（PM-AL-18），配套查询权限 |
| 资金方机构认证审核 | [申请与材料查询（PM-AL-05）](../05-资金方机构认证审核/01-资金方机构认证审核-PRD.md#ops-permissions) | 已认证资金方机构数、待审核资金方机构 | 审核处置（PM-AL-06），身份与当前提交条件沿用来源规则 |
| 融资参数配置 | [融资参数查询（PM-AL-19）](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#d-o-fc-02) | 待配置融资参数 | 融资参数维护（PM-AL-20），配套查询权限 |
| 融资需求与链上放款 | <a id="pm-ov-01"></a>平台融资统计查询（PM-OV-01），本模块新增，见下方说明 | 融资需求金额、已融资余额及二者的每日新增 | 无；运营端没有融资需求、报价与放款的办理动作 |

<a id="pm-ov-01-rule"></a>**平台融资统计查询（PM-OV-01）。** 运营端此前没有读取融资需求与链上放款数据的查询权限，本模块新增这一项，只用于总览：

- 允许读取全平台融资需求金额、已融资余额与每日新增的合计值。
- 不开放逐笔融资需求、报价、放款、还款或任一企业、机构的明细，也不开放面客端项目详情中按身份限制的信息。
- 本期运营管理员固定具有。缺少时，融资需求金额、已融资余额及二者的每日新增不展示，其他信息不受影响。
- 是否新增这一权限待用户确认，见[平台融资统计查询权限（Q-OV-04）](#q-ov-04)。

同一主体内不按机构隔离数据，当前来源模块允许查询的全部记录是总览的统计范围；来源列表中曾使用的搜索、日期和分页条件不带入总览。界面默认语言、语言切换与时区沿用[界面语言与时区偏好（F-AL-10、F-AL-11）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#f-al-10)，数字沿用本平台既有展示规范，不新增国际化口径。

## 4. 三项金额统计（F-OV-07）

适用角色与前提：满足[进入总览与权限范围（F-OV-01）](#f-ov-01)，且具备对应的查询权限。三项均为只读的当前合计，不提供跳转。

| 统计名称 | 计数对象与纳入条件 | 单位与来源口径 |
| --- | --- | --- |
| 代币价值 | 当前准入状态为已通过、且代币状态为有效的准入记录，每笔取其代币价值相加；代币变为失效后退出合计 | USD，两位小数；代币价值为各笔签发时的 USD 价值快照，不是实时市值，也不再次折算。沿用[资产广场头部汇总（F-AM-02）](../../面客端/04-资产广场-已上架代币只读域/01-资产广场-PRD.md#totals)的汇总规则 |
| 融资需求金额 | 全平台各项目的项目在途金额相加，即已发布且未终结的融资需求金额，含发布或改额冻结处理中的预占 | USDT，两位小数；按[项目在途金额（FP-14）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-14) |
| 已融资余额 | 全平台各项目的项目融资余额相加，即已链上放款成功、尚未偿还的本金 | USDT，两位小数；按[项目融资余额（FP-13）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-13)。口径待用户确认，见[已融资金额的口径（Q-OV-03）](#q-ov-03) |

- 代币价值须说明是按各笔签发时汇率折算的签发价值。代币价值缺失的记录不计入合计，也不当作 0；存在这类记录时，说明有多少笔因缺少代币价值未计入。
- 本期只有一个代币类型。出现第二个代币类型或第二份发行合约时，按资产广场规则分组汇总或停止混合求和，不在总览另定。
- 融资需求金额与已融资余额都以 USDT 计；结算币种为 USDC 的业务，其融资金额本身仍是 USDT，不再按汇率换算。
- 代币价值（USD）与融资金额（USDT）是两种量，不相加，不展示二者的比值。
- 一笔链上放款成功时，对应金额同时从融资需求金额移入已融资余额；还款结清本金后已融资余额相应减少。两项都按读取时的当前事实展示。
- 金额可以按设计采用紧凑写法（例如以 M 表示百万），但须能取得两位小数的准确值，单位始终可见。

## 5. 三项核心统计（F-OV-02）

适用角色与前提：满足[进入总览与权限范围（F-OV-01）](#f-ov-01)，且具备相应来源的查询权限。三项均为只读统计，不提供从核心统计跳转列表的动作。

| 统计名称 | 计数对象与纳入条件 | 业务边界与来源 |
| --- | --- | --- |
| 已准入代币数 | 当前准入状态为已通过的准入记录，每条记录计一笔 | 包含通过后失效的代币与通过后资料变更的记录，因此可能多于代币价值所覆盖的笔数；不代表当前可质押或对外实际展示数量。按[准入状态与叠加标记](../06-代币准入审核/01-代币准入审核-PRD.md#states)判定，不按持有地址、代币数量或提交次数累加 |
| 已通过项目数 | 当前审核轴为已通过、配置执行状态为配置成功的项目，每个项目计一次 | 包含通过后已关闭或已结束融资的项目，不表示正在融资项目数。配置处理中、结果待核实、配置失败均不算通过；见[项目两条状态轴](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#states) |
| 已认证资金方机构数 | 当前注册状态为已认证的资金方机构，每家机构计一次 | 历史曾通过但当前变更重审或被驳回的不计入；见[结果、分档与通知（F-L85）](../05-资金方机构认证审核/01-资金方机构认证审核-PRD.md#f-l85)。机构唯一性仍按来源规则，不按历史审核节点累加 |

<a id="f-ov-08"></a>
## 6. 每日新增（F-OV-08）

适用角色与前提：满足[进入总览与权限范围（F-OV-01）](#f-ov-01)，且具备对应的查询权限。每日新增按 UTC 日展示三项金额统计的新增量，只读，不提供跳转或钻取。

| 序列名称 | 每个 UTC 日计入的内容 | 单位与来源 |
| --- | --- | --- |
| 新准入代币价值 | 当日审核通过的准入记录，其代币价值相加；按通过结论时间归日，通过后又失效的不回减 | USD，两位小数；结论时间取自[操作记录（F-TA-11）](../06-代币准入审核/01-代币准入审核-PRD.md#f-ta-11)，代币价值规则同代币价值统计 |
| 新发布融资需求金额 | 当日发布成功的各轮融资需求，按发布成功时的需求金额相加；改额不计入新增，之后撤下、失效或成交也不回减 | USDT，两位小数；发布规则见[融资需求金额（FP-06）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-06) |
| 新增放款金额 | 当日链上放款成功的各笔融资金额相加；按放款成功时间归日，之后还款不回减 | USDT，两位小数；按[链上放款记录（LN-01）](../../面客端/06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#ln-01)及其放款成功时间 |

- 展示范围为最近 14 个 UTC 日，含今天；今天须标明尚未结束。范围与日界待用户确认，见[每日新增的范围与日界（Q-OV-05）](#q-ov-05)。
- 当日确实没有发生时显示 0；某一日或某一序列未取得数据时明确暂不可用，不以 0 代替。
- 设计可在三项金额统计旁标出今天新增，其值须与本节今天的数值一致。
- USD 与 USDT 序列不叠加成同一个总量；呈现为柱状图或折线图由设计决定，单位须可辨。
- 每日新增是当日发生量，不是当日末余额，因此相邻两日之差不等于金额统计的变化；不展示环比、同比涨跌。
- 每个 UTC 日的数据日期以 UTC 标注；数据更新时间仍按偏好时区显示。切换时区不改变归日。

## 7. 近期审结（F-OV-06）

适用角色与前提：满足[进入总览与权限范围（F-OV-01）](#f-ov-01)，且具备相应来源的查询权限。近期审结只读，直接沿用来源模块已有统计，总览不另定口径。

| 来源 | 展示内容 | 口径来源 |
| --- | --- | --- |
| 代币准入审核 | 近 7 个自然日审结数，通过数与退回数分别给出 | [准入审核清单（F-TA-02）](../06-代币准入审核/01-代币准入审核-PRD.md#f-ta-02)中的近 7 个自然日审结数 |
| 项目合约管理 | 近 7 个自然日人工审结项目数，为通过与退回之和；配置失败不计入 | [项目审核队列](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#m1)中的近 7 个自然日人工审结项目数 |

- 统计范围为来源未设置任何筛选条件时的全部范围，不受来源列表中曾使用的条件影响。
- 近 7 个自然日按 UTC 日期计算，统计上标注 UTC；数据更新时间仍按偏好时区显示。切换时区不改变统计归属。
- 计数单位与时间边界沿用来源统计，来源口径调整时总览随之一致，不在总览另行换算。
- 资金方机构认证审核的来源模块没有近 7 日审结统计，本期不展示，见[资金方机构近期审结（Q-OV-01）](#q-ov-01)；融资参数配置没有审核结论，不适用。

<a id="f-ov-03"></a>
## 8. 四类待办与去向（F-OV-03）

适用角色与前提：满足[进入总览与权限范围（F-OV-01）](#f-ov-01)，且具备相应来源的查询权限。待办展示分类名称、当前数量与进入原业务列表的入口，不展示逐条对象、等待时长或个人经办量。待办数量只在本组呈现，平台统计中不重复展示待审核或未配置数量。

| 待办名称 | 计数条件与排除项 | 打开后的业务位置 |
| --- | --- | --- |
| 待审核代币 | 当前准入状态为待审核的记录数；已失效但仍可退回的待审核记录仍计入；已退回及已通过后的资料变更提醒不计入 | [准入审核清单（F-TA-02）](../06-代币准入审核/01-代币准入审核-PRD.md#f-ta-02)，限定待审核 |
| 待审核项目 | 当前审核轴为待审核且未关闭的项目数；含配置失败后可再次发起的项目；配置处理中、结果待核实、已退回、已通过、已关闭项目不计入 | [项目审核队列](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#m1)，限定待审核且未关闭 |
| 待审核资金方机构 | 当前最新成功提交仍为待审核的申请数；首次申请、驳回重提、已认证资料变更均按当前申请计一次；未提交草稿、历史提交和审核节点不计入 | [运营审核列表与详情（F-L83）](../05-资金方机构认证审核/01-资金方机构认证审核-PRD.md#f-l83)的申请查询，限定待审核 |
| 待配置融资参数 | 当前配置状态为未配置的网络与代币类型组合数，每个组合计一次；已配置组合不计入 | [融资参数列表与检索（F-O-FC-01）](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#f-o-fc-01)，限定未配置 |

- 待审核项目存在配置失败时，在该项数量旁附带说明其中有多少项目配置失败、可再次发起；该数量是待审核项目的子集，不另外增加一类或重复累计。为 0 时不展示这项附带说明。
- 待配置融资参数沿用来源的全部未配置组合，包括当前创建项目尚未开放的网络、或已没有有效代币的组合；不在总览新增移除或自动忽略规则。
- 有权查看的四类数量均保留，真实为 0 时显示 0；全部成功读取且均为 0 时，明确当前没有这四类待办。
- 不展示四类相加的“总待办数”，避免把代币、项目、申请与参数组合混为同一业务量。
- 进入来源列表时应用本次待办限定条件，清除与该条件冲突的历史筛选并从第一页开始；来源模块继续提供原有检索、排序、详情和办理能力，不在总览直接提交审核或配置。
- 来源列表按进入时的当前事实展示，数量可因他人办理或业务到期与离开总览时不同；无匹配时使用来源空态，不补造任务，也不允许办理已失效的旧状态。
- 来源列表和详情须保留返回总览的可达路径；完成办理或查看后返回总览，重新读取当前数量。

待办的增加与移除只跟随上述来源状态；阅读消息、标记全部已读和查看详情均不完成待办。流程见[查看与办理回流（FL-OV-01）](02-运营端总览-流程图与状态机.md#fl-ov-01)。

<a id="f-ov-04"></a>
## 9. 数据展示、刷新与异常（F-OV-04）

适用角色与前提：满足[进入总览与权限范围（F-OV-01）](#f-ov-01)。进入总览、主动刷新和从原业务返回时，重新读取有权查看的数据；不设置本期没有依据的自动刷新周期或延迟承诺。

| 业务信息 | 含义与类型 | 默认、编辑与校验 |
| --- | --- | --- |
| 统计、序列、近期审结或待办名称 | 固定业务名称，取自本册各统计、每日新增、近期审结与待办表 | 必有，只读；具体中英文表达由设计与国际化按业务含义呈现 |
| 数量与单位 | 非负整数；代币为笔、项目为个、资金方机构为家、融资参数为个组合；近期审结单位沿用来源统计 | 成功读取后必有，只读，不缩写为约数；实际无记录为 0，未取得数据时没有默认数字 |
| 金额与单位 | 非负金额，两位小数；代币价值为 USD，融资需求金额、已融资余额及其每日新增为 USDT | 成功读取后必有，只读；可紧凑书写但准确值须可得，单位始终可见；实际无金额为 0.00，未取得数据时没有默认数字 |
| 未计入代币价值的笔数 | 已准入且有效、但缺少代币价值的记录数 | 只读；只在大于 0 时展示 |
| 配置失败项目子集数量 | 待审核项目中配置执行状态为配置失败的项目数 | 只读；只在成功取得且大于 0 时展示，不能大于同期待审核项目数；子集读取失败时明确其暂不可用，不能显示“含 0 个”或暗示没有失败项目 |
| 统计期与数据日期 | 近期审结为近 7 个自然日，每日新增为最近 14 个 UTC 日，均按 UTC 日期 | 只读，须标注 UTC；今天须标明尚未结束 |
| 数据更新时间 | 本项成功读取的数据所对应的时点 | 成功读取后必有，只读，按偏好时区标注；若各项对应时点不同须分别可辨，不能用刷新点击时间冒充全部数据已更新 |
| 办理入口 | 四类待办对应原业务列表的入口 | 具备来源查询权限时可得；平台统计、每日新增和近期审结只读，查看不变更业务状态 |

| 读取状态 | 数量与时间的表现 | 可继续的动作 |
| --- | --- | --- |
| 首次读取中 | 显示正在获取，未取得的数字不先填 0 | 等待读取结果 |
| 成功且数值大于 0 | 显示准确数值、单位和本项数据更新时间 | 可刷新；待办可进入来源列表 |
| 成功且数值为 0 | 显示 0 或 0.00 和本项数据更新时间 | 可刷新；来源查询入口仍可达 |
| 首次读取失败 | 失败项明确暂不可用；不显示成 0，不宣告全部待办清空；每日新增中失败的日期或序列同样暂不可用 | 可重试，其他成功项继续可读；有权的来源查询入口仍可达 |
| 刷新中或刷新失败且有上次成功数据 | 可保留上次成功数值与原数据时间，明确正在更新或本次更新失败，不标成最新 | 可重试或进入有权查看的来源列表 |
| 查询权限已失效 | 隐藏依赖该权限的全部数字、保留数据与入口，不将无权限显示成 0 | 按账户模块权限底线处理直接访问 |

总览不改变任何来源业务状态，不生成新消息，不保存用户可编辑的统计值或待办状态。流程见[数据读取与重试（FL-OV-02）](02-运营端总览-流程图与状态机.md#fl-ov-02)。

## 10. 依赖

- 账户与登录提供总览入口、登录落地、偏好和权限底线；本模块承接原总览页的业务内容，不新建第二个运营首页。
- 代币准入、项目合约、机构认证及融资参数模块提供其当前对象、状态、准确计数与既有查询入口；代币准入另提供代币价值、代币状态与通过结论时间，代币准入与项目合约另提供近 7 个自然日审结统计。
- [融资需求与代币质押](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)提供各项目的项目在途金额、项目融资余额，以及每轮融资需求的发布成功时间与发布金额。
- [授信报价与接受拒绝](../../面客端/06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md)提供链上放款成功的融资金额与放款成功时间；[链上还款](../../面客端/08-借贷广场-链上还款/01-链上还款-PRD.md)的本金偿还通过项目融资余额体现，总览不另读还款明细。
- 当前状态或金额不能确认时按[数据展示、刷新与异常（F-OV-04）](#f-ov-04)展示不可用，不从消息记录推断。
- [运营端消息通知](../07-运营端消息通知/01-运营端消息通知-PRD.md)仍独立承接各来源消息；总览不需要消息查看权限来计算业务待办，也不汇总消息数量。
