# 运营端总览 · 功能与业务规则

2026-10-26｜运营管理平台 · 运营管理员｜需求评审稿

本模块共三册：本册定义功能与业务规则；[流程图与状态机](02-运营端总览-流程图与状态机.md)说明查看与办理后的回流；[验收](04-运营端总览-验收.md)供测试使用。总览自身不发送消息，所以没有 03 消息通知册，并非缺失。功能编号沿用原值，新增功能接续编号，因此章节顺序与编号顺序不一致，缺号不代表遗漏。

## 1. 模块是什么

运营管理员登录后，通过总览了解平台在代币准入、融资项目审核、资金方机构认证和融资参数配置上的规模与构成、近期审结情况，并找到当前需要人工处理的审核与融资参数配置。总览沿用账户模块的总览页（P-O-AL-07），只提供业务摘要和原功能入口，办理仍在各来源模块完成。

总览的信息分为三组，分组的布局与视觉承载由 Hallmark 决定：

- 业务规模：三项核心统计，以及四个来源各自的状态构成。
- 近期审结：代币准入与融资项目近 7 个自然日的审结数。
- 待办事项：四类待办的当前数量与办理入口。

基本原则：

- 只展示按业务对象计数的整数，不展示金额、比率或逐笔明细。
- 统计、构成和待办都按读取时的当前业务事实计数；近 7 日审结沿用来源模块已定义的统计口径。消息未读不等于待办。
- 查询与办理沿用来源权限、状态和规则，查看总览不产生审核结论或业务变更。

**一个完整的例子。** 管理员登录后看到已准入代币 30 笔、已通过项目 12 个、已认证资金方机构 4 家。代币准入构成显示待审核 5、已通过 30、已退回 3，合计 38 条准入记录，提醒中有 2 笔已通过代币已失效；融资项目构成显示待审核 3（其中 1 个配置失败）、配置处理中 1、已通过 12、已退回 2、未通过已关闭 1，合计 19 个项目。近期审结显示代币近 7 个自然日（UTC）通过 6、退回 1，项目人工审结 4。待办中待审核项目为 3 个，其中 1 个配置失败待再次发起。管理员打开项目待审核队列，在原详情核对后再次发起配置，返回总览时该项目已进入配置处理中：待审核项目变为 2 个，项目构成中配置处理中变为 2，合计仍为 19。配置成功后再次读取，已通过项目变为 13 个，近 7 日项目人工审结变为 5；若配置失败，该项目重新回到待审核并重新计入待办。同事已处理、项目到期关闭等变化，都按读取时的当前状态呈现。

### 1.1 本期不做

- 不新增金融经营报表；不展示融资、放款、还款或代币价值等金额及其汇总，不展示余额、收益、逾期率和排行榜。
- 不展示趋势图、按日序列、环比或同比涨跌，不展示通过率、退回率、配置成功率等比率指标。是否扩展见[趋势与比率类展示（Q-OV-02）](#q-ov-02)。
- 不提供日期、机构或网络等统计筛选，不提供导出、钻取与自定义指标；核心统计、状态构成与近期审结只读，不从这些数字跳转列表。
- 不展示逐条对象清单、已等待时长或个人经办量；不复制审核列表、消息预览或协议操作记录，不新增批量审核、待办认领、催办和手工完成。
- 协议到点生效结果及其失败告警继续由既有协议管理和运营端消息通知承接，不在总览再建一套提醒或日程。

## 2. 术语

| 术语 | 本册含义 |
| --- | --- |
| 核心统计 | 当前记录中已准入代币、已通过项目、已认证资金方机构的数量，不是期间新增量或资金规模 |
| 状态构成 | 某一来源的全部业务对象按当前状态分成互不重叠的几项后，各项的数量及合计 |
| 提醒数 | 某一来源中带有特定叠加标记的对象数量；只作提示，不属于待办，也不计入状态构成合计 |
| 近期审结 | 来源模块已定义的近 7 个自然日审结统计，按 UTC 日期计算 |
| 待办 | 当前仍需运营审核或补齐融资参数的业务对象；同一对象在同一类别只计一次 |
| 融资参数组合 | 区块链网络与代币类型的组合，按融资参数配置模块定义产生并保留 |

## 3. 进入总览与权限范围（F-OV-01）

适用角色与前提：本期唯一角色为运营管理员，须完成首登改密、账号正常且会话有效，遵守[权限底线（F-AL-17）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#f-al-17)。

- 无原目标的登录按[登录后落地与回跳（F-AL-06）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#f-al-06)进入总览；已有合法原目标时沿用账户模块的回跳规则。
- 已登录运营人员可从管理端共享导航进入总览；导航承载、布局与视觉由 Hallmark 决定。
- 总览入口不新增独立权限项；某一来源的核心统计、状态构成、提醒数、近期审结、待办数量与去向，都须具有下表该来源的查询权限，本期正常运营管理员已全部开通。
- 缺少某来源查询权限时，该来源的全部数字与业务入口均不展示；直接访问目标仍由来源模块拒绝，不以 0 或空列表透露对象是否存在。
- 具有查询权限但不具备处置权限时，可以查看数量并进入原查询列表，实际办理按来源模块权限拒绝；总览不补授权限。
- 会话失效、待首登改密或账号不可用时，停止展示受保护数据并按账户模块引导。

| 来源 | 总览读取所需查询权限 | 原业务办理权限与配套要求 |
| --- | --- | --- |
| 代币准入审核 | [代币准入审核查询（PM-TA-01）](../06-代币准入审核/01-代币准入审核-PRD.md#pm-ta) | 代币准入审核处置（PM-TA-02），配套查询权限 |
| 项目合约管理 | [融资项目审核查询（PM-AL-17）](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#permissions) | 融资项目审核与合约配置处置（PM-AL-18），配套查询权限 |
| 资金方机构认证审核 | [申请与材料查询（PM-AL-05）](../05-资金方机构认证审核/01-资金方机构认证审核-PRD.md#ops-permissions) | 审核处置（PM-AL-06），身份与当前提交条件沿用来源规则 |
| 融资参数配置 | [融资参数查询（PM-AL-19）](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#d-o-fc-02) | 融资参数维护（PM-AL-20），配套查询权限 |

同一主体内不按机构隔离数据，当前来源模块允许查询的全部记录是总览的统计范围；来源列表中曾使用的搜索、日期和分页条件不带入总览。界面默认语言、语言切换与时区沿用[界面语言与时区偏好（F-AL-10、F-AL-11）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#f-al-10)，数字沿用本平台既有展示规范，不新增国际化口径。

<a id="f-ov-02"></a>
## 4. 三项核心统计（F-OV-02）

适用角色与前提：满足[进入总览与权限范围（F-OV-01）](#f-ov-01)，且具备相应来源的查询权限。三项均为只读统计，不提供从核心统计跳转列表的动作。

| 统计名称 | 计数对象与纳入条件 | 业务边界与来源 |
| --- | --- | --- |
| 已准入代币数 | 当前准入状态为已通过的准入记录，每条记录计一笔 | 包含通过后失效的代币与通过后资料变更的记录；不代表当前可质押或对外实际展示数量。按[准入状态与叠加标记](../06-代币准入审核/01-代币准入审核-PRD.md#states)判定，不按持有地址、代币数量或提交次数累加 |
| 已通过项目数 | 当前审核轴为已通过、配置执行状态为配置成功的项目，每个项目计一次 | 包含通过后已关闭或已结束融资的项目，不表示正在融资项目数。配置处理中、结果待核实、配置失败均不算通过；见[项目两条状态轴](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#states) |
| 已认证资金方机构数 | 当前注册状态为已认证的资金方机构，每家机构计一次 | 历史曾通过但当前变更重审或被驳回的不计入；见[结果、分档与通知（F-L85）](../05-资金方机构认证审核/01-资金方机构认证审核-PRD.md#f-l85)。机构唯一性仍按来源规则，不按历史审核节点累加 |

这三项分别回答已准入多少代币、已有多少项目完成审核与合约配置、当前有多少资金方机构获得认证。它们与各来源[状态构成（F-OV-05）](#f-ov-05)中的已通过或已认证项是同一个数。

## 5. 各来源状态构成与提醒（F-OV-05）

适用角色与前提：满足[进入总览与权限范围（F-OV-01）](#f-ov-01)，且具备相应来源的查询权限。状态构成回答“这一来源的全部对象现在分别处在什么状态”，只读，不提供跳转。

共同规则：

- 每个来源的构成项互不重叠，一个对象只属于其中一项；构成项之和即该来源的合计。
- 构成项与核心统计或待办是同一业务数时，二者取自同一次读取且数值一致；该数在总览中可只呈现一处，由设计决定承载，但每一构成项及合计都必须可得。
- 每一项都显示准确整数，真实为 0 时显示 0。设计可以用占比辅助呈现构成，占比只能由同一组构成数计算，各项准确数量仍须可得，不能称为通过率、认证率等业务比率。
- 某一构成项未取得数据时，该项与该来源合计都明确暂不可用，不以 0 代替，也不用其余项之和冒充合计。
- 提醒数不计入合计，不属于待办，也不改变来源模块中可做的动作。

### 5.1 代币准入构成

计数对象为准入记录，单位为笔；合计为全部准入记录数。状态与标记的定义见[准入状态与叠加标记](../06-代币准入审核/01-代币准入审核-PRD.md#states)。

| 构成项 | 计数条件 | 与其他数字的关系 |
| --- | --- | --- |
| 待审核 | 当前准入状态为待审核的记录，含代币已失效的待审核记录 | 与待审核代币待办同数 |
| 已通过 | 当前准入状态为已通过的记录 | 与已准入代币数同数 |
| 已退回 | 当前准入状态为已退回、等待发行平台重新推送的记录 | 仅在构成中出现 |

| 提醒名称 | 计数条件 |
| --- | --- |
| 待审核中有重复提醒 | 准入状态为待审核，且带链上代币重复或代币编号重复提醒的记录；两种提醒同时存在只计一次，判定见[重复提醒](../06-代币准入审核/01-代币准入审核-PRD.md#duplicate) |
| 已通过但代币已失效 | 准入状态为已通过，且代币状态为失效的记录 |
| 已通过后资料有变更 | 准入状态为已通过，且带通过后资料有变更标记的记录，见[通过后的资料变更（F-TA-10）](../06-代币准入审核/01-代币准入审核-PRD.md#f-ta-10) |

### 5.2 融资项目构成

计数对象为项目，单位为个；合计为运营端可查询的全部项目数。状态定义见[项目两条状态轴](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#states)与[待审核或已退回时到期自动关闭](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#expiry)。

| 构成项 | 计数条件 | 与其他数字的关系 |
| --- | --- | --- |
| 待审核 | 审核轴为待审核且未关闭的项目；其中配置执行状态为配置失败的数量单独给出 | 与待审核项目待办及其配置失败子集同数 |
| 配置处理中 | 审核轴为配置处理中的项目，含配置执行状态为结果待核实的项目；其中结果待核实的数量单独给出 | 仅在构成中出现；结果待核实是配置处理中的子集，不另加 |
| 已通过 | 审核轴为已通过、配置执行状态为配置成功的项目，含通过后关闭的项目 | 与已通过项目数同数 |
| 已退回 | 审核轴为已退回且未关闭的项目 | 仅在构成中出现 |
| 未通过已关闭 | 审核轴为待审核或已退回且项目已关闭的项目，关闭原因为资产方主动关闭或有效期到期 | 仅在构成中出现 |

配置失败子集与结果待核实子集为 0 时可不展示附带说明；子集读取失败时明确暂不可用，不显示“含 0 个”。

### 5.3 资金方机构认证构成

计数对象为资金方机构申请，每个资金方账户按当前最新成功提交计一条，单位为家；合计为已成功提交过的申请数，未提交草稿不计入。状态定义见[结果、分档与通知（F-L85）](../05-资金方机构认证审核/01-资金方机构认证审核-PRD.md#f-l85)。

| 构成项 | 计数条件 | 与其他数字的关系 |
| --- | --- | --- |
| 待审核 | 当前注册状态为审核中，即最新成功提交仍待审核；含首次申请、驳回重提与已认证资料变更 | 与待审核资金方机构待办同数 |
| 已认证 | 当前注册状态为已认证 | 与已认证资金方机构数同数 |
| 已驳回 | 当前注册状态为已驳回 | 仅在构成中出现 |

### 5.4 融资参数配置构成

计数对象为融资参数组合，单位为个组合；合计为全部组合数。配置状态定义见[配置状态（FC-04）](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#fc-04)。

| 构成项 | 计数条件 | 与其他数字的关系 |
| --- | --- | --- |
| 已配置 | 配置状态为已配置的组合 | 仅在构成中出现 |
| 未配置 | 配置状态为未配置的组合，含当前创建项目尚未开放的网络或已没有有效代币的组合 | 与待配置融资参数待办同数 |

<a id="f-ov-06"></a>
## 6. 近期审结（F-OV-06）

适用角色与前提：满足[进入总览与权限范围（F-OV-01）](#f-ov-01)，且具备相应来源的查询权限。近期审结只读，直接沿用来源模块已有统计，总览不另定口径。

| 来源 | 展示内容 | 口径来源 |
| --- | --- | --- |
| 代币准入审核 | 近 7 个自然日审结数，通过数与退回数分别给出 | [准入审核清单（F-TA-02）](../06-代币准入审核/01-代币准入审核-PRD.md#f-ta-02)中的近 7 个自然日审结数 |
| 项目合约管理 | 近 7 个自然日人工审结项目数，为通过与退回之和；配置失败不计入 | [项目审核队列](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#m1)中的近 7 个自然日人工审结项目数 |

- 统计范围为来源未设置任何筛选条件时的全部范围，不受来源列表中曾使用的条件影响。
- 近 7 个自然日按 UTC 日期计算，统计上标注 UTC；数据更新时间仍按偏好时区显示。切换时区不改变统计归属。
- 计数单位与时间边界沿用来源统计，来源口径调整时总览随之一致，不在总览另行换算。
- 资金方机构认证审核的来源模块没有近 7 日审结统计，本期不展示，见[资金方机构近期审结（Q-OV-01）](#q-ov-01)；融资参数配置没有审核结论，不适用。

## 7. 四类待办与去向（F-OV-03）

适用角色与前提：满足[进入总览与权限范围（F-OV-01）](#f-ov-01)，且具备相应来源的查询权限。待办展示分类名称、当前数量与进入原业务列表的入口，不展示逐条对象、等待时长或个人经办量。

| 待办名称 | 计数条件与排除项 | 打开后的业务位置 |
| --- | --- | --- |
| 待审核代币 | 当前准入状态为待审核的记录数；已失效但仍可退回的待审核记录仍计入；已退回及已通过后的资料变更提醒不计入 | [准入审核清单（F-TA-02）](../06-代币准入审核/01-代币准入审核-PRD.md#f-ta-02)，限定待审核 |
| 待审核项目 | 当前审核轴为待审核且未关闭的项目数；含配置失败后可再次发起的项目；配置处理中、结果待核实、已退回、已通过、已关闭项目不计入 | [项目审核队列](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#m1)，限定待审核且未关闭 |
| 待审核资金方机构 | 当前最新成功提交仍为待审核的申请数；首次申请、驳回重提、已认证资料变更均按当前申请计一次；未提交草稿、历史提交和审核节点不计入 | [运营审核列表与详情（F-L83）](../05-资金方机构认证审核/01-资金方机构认证审核-PRD.md#f-l83)的申请查询，限定待审核 |
| 待配置融资参数 | 当前配置状态为未配置的网络与代币类型组合数，每个组合计一次；已配置组合不计入 | [融资参数列表与检索（F-O-FC-01）](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#f-o-fc-01)，限定未配置 |

- 待审核项目存在配置失败时，在该项数量旁附带说明其中有多少项目配置失败、可再次发起；该数量是待审核项目的子集，不另外增加一类或重复累计。为 0 时不展示这项附带说明。
- 待配置融资参数沿用来源的全部未配置组合，包括当前创建项目尚未开放的网络、或已没有有效代币的组合；不在总览新增移除或自动忽略规则。
- 有权查看的四类数量均保留，真实为 0 时显示 0；全部成功读取且均为 0 时，明确当前没有这四类待办。
- 不展示四类相加的“总待办数”，避免把代币、项目、申请与参数组合混为同一业务量；提醒数也不计入待办。
- 进入来源列表时应用本次待办限定条件，清除与该条件冲突的历史筛选并从第一页开始；来源模块继续提供原有检索、排序、详情和办理能力，不在总览直接提交审核或配置。
- 来源列表按进入时的当前事实展示，数量可因他人办理或业务到期与离开总览时不同；无匹配时使用来源空态，不补造任务，也不允许办理已失效的旧状态。
- 来源列表和详情须保留返回总览的可达路径；完成办理或查看后返回总览，重新读取当前数量。

待办的增加与移除只跟随上述来源状态；阅读消息、标记全部已读和查看详情均不完成待办。流程见[查看与办理回流（FL-OV-01）](02-运营端总览-流程图与状态机.md#fl-ov-01)。

<a id="f-ov-04"></a>
## 8. 数据展示、刷新与异常（F-OV-04）

适用角色与前提：满足[进入总览与权限范围（F-OV-01）](#f-ov-01)。进入总览、主动刷新和从原业务返回时，重新读取有权查看的数据；不设置本期没有依据的自动刷新周期或延迟承诺。

| 业务信息 | 含义与类型 | 默认、编辑与校验 |
| --- | --- | --- |
| 统计、构成项、提醒、近期审结或待办名称 | 固定业务名称，取自本册各统计、构成、提醒、近期审结与待办表 | 必有，只读；具体中英文表达由设计与国际化按业务含义呈现 |
| 数量与单位 | 非负整数；代币为笔、项目为个、资金方机构为家、融资参数为个组合；近期审结单位沿用来源统计 | 成功读取后必有，只读，不缩写为约数；实际无记录为 0，未取得数据时没有默认数字 |
| 构成合计 | 同一来源各构成项之和，与该来源当前全部对象数一致 | 只读；只在该来源全部构成项都成功取得时展示 |
| 配置失败项目子集数量 | 待审核项目中配置执行状态为配置失败的项目数 | 只读；只在成功取得且大于 0 时展示，不能大于同期待审核项目数；子集读取失败时明确其暂不可用，不能显示“含 0 个”或暗示没有失败项目 |
| 结果待核实项目子集数量 | 配置处理中项目中配置执行状态为结果待核实的项目数 | 只读；不能大于同期配置处理中项目数；读取失败时明确暂不可用 |
| 近期审结统计期 | 近 7 个自然日，按 UTC 日期 | 只读，须标注 UTC |
| 数据更新时间 | 本项成功读取的数据所对应的时点 | 成功读取后必有，只读，按偏好时区标注；若各项对应时点不同须分别可辨，不能用刷新点击时间冒充全部数据已更新 |
| 办理入口 | 四类待办对应原业务列表的入口 | 具备来源查询权限时可得；统计、构成、提醒和近期审结只读，查看不变更业务状态 |

| 读取状态 | 数量与时间的表现 | 可继续的动作 |
| --- | --- | --- |
| 首次读取中 | 显示正在获取，未取得的数字不先填 0 | 等待读取结果 |
| 成功且数量大于 0 | 显示准确数量、单位和本项数据更新时间 | 可刷新；待办可进入来源列表 |
| 成功且数量为 0 | 显示 0 和本项数据更新时间 | 可刷新；来源查询入口仍可达 |
| 首次读取失败 | 失败项明确暂不可用；不显示成 0，不宣告全部待办清空；构成项失败时该来源合计同样不可用 | 可重试，其他成功项继续可读；有权的来源查询入口仍可达 |
| 刷新中或刷新失败且有上次成功数据 | 可保留上次成功数字与原数据时间，明确正在更新或本次更新失败，不标成最新 | 可重试或进入有权查看的来源列表 |
| 来源查询权限已失效 | 隐藏该来源的全部数字、保留数据与入口，不将无权限显示成 0 | 按账户模块权限底线处理直接访问 |

总览不改变任何来源业务状态，不生成新消息，不保存用户可编辑的统计值或待办状态。流程见[数据读取与重试（FL-OV-02）](02-运营端总览-流程图与状态机.md#fl-ov-02)。

## 9. 依赖

- 账户与登录提供总览入口、登录落地、偏好和权限底线；本模块承接原总览页的业务内容，不新建第二个运营首页。
- 代币准入、项目合约、机构认证及融资参数模块提供其当前对象、状态、叠加标记、准确计数与既有查询入口；代币准入与项目合约另提供近 7 个自然日审结统计。当前状态不能确认时按[数据展示、刷新与异常（F-OV-04）](#f-ov-04)展示不可用，不从消息记录推断。
- [运营端消息通知](../07-运营端消息通知/01-运营端消息通知-PRD.md)仍独立承接各来源消息；总览不需要消息查看权限来计算业务待办，也不汇总消息数量。
- 总览读取不依赖代币的 USD 估值、融资金额汇总、还款结清统计或钱包连接；各来源原有未决项仍由所属模块维护，不在本册另定数值和业务结论。
