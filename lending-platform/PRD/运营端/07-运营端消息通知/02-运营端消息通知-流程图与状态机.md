<a id="fl-o01"></a>
## 入口、列表、详情、已读与返回（FL-O01）

```mermaid
flowchart TD
    A["运营人员位于运营端任一业务页面"] --> B{"已登录、已完成首登改密、有消息查看权限？"}
    B -->|否| X["按账户规则登录或拒绝，不展示消息入口"]
    B -->|是| C["消息入口与账户菜单"]
    C -->|消息入口| D["最近消息预览 10 条，只打开不变已读"]
    C -->|账户菜单“消息中心”| E["完整消息列表：分类与阅读状态筛选，每次加载 20 条"]
    D -->|查看全部| E
    D -->|选择一条| F["打开消息详情，判断是否本人可见"]
    E -->|选择一条| F
    F -->|不可见或不存在| N["与不存在相同，不透露是否存在"]
    F -->|加载失败| R["仍为未读，可重试或返回"]
    R --> F
    F -->|内容展示成功| G["对本人自动变为已读，各业务页面同步"]
    G -->|前往原业务| H["按 FL-O03 与 FL-O05 处理"]
    G -->|前往本人账户设置| I["可回到这条消息"]
    I --> G
    G -->|返回列表| J["回到原列表：筛选、已加载批次与所在位置不变"]
    J --> E
```

预览不提供全部已读；列表不提供逐条标为已读。刷新详情后仍是同一条消息。切换账号后不显示前一个账号的内容。各业务页面共用本人的已读状态，不代表与其他人或其他端共享。

<a id="fl-o02"></a>
## 一条消息从来源发出到运营人员阅读（FL-O02）

```mermaid
flowchart TD
    A["来源业务的事实正式成立"] --> B{"来源规定要告知运营端？"}
    B -->|否，或只告知面客端| C["只在业务页面反馈，本端不收消息"]
    B -->|是| E{"必填接入字段齐全且去向符合要求？"}
    E -->|否| F["由来源补齐或纠正后再发，不猜收件范围、不用虚假信息补位"]
    E -->|是| G{"同一收件范围已收到过同一事实？"}
    G -->|是| H["保留原消息：不新增、不改顺序、不变回未读、不改发生时间"]
    G -->|否| I["新增一条消息，对每个可见的人都是未读"]
    I --> J["业务事件后 60 秒内出现在列表，未读数同步；到点触发的事件从应到时点起最晚 6 分钟"]
    H --> K{"收件范围"}
    J --> K
    K -->|全体运营| L["所有有消息查看权限的运营人员可见，各自记录已读"]
    K -->|本人| M["只有该运营账号可见"]
    L --> N["按 FL-O01 阅读并前往原业务"]
    M --> N
```

发什么、何时发、发给哪种收件范围，由来源模块在其消息通知册中规定。本图表示消息的业务承接过程，不表示技术接入流程。字段取值与必填条件见[接入字段](./01-运营端消息通知-PRD.md#intake-fields)：发生时间取业务事实时刻，到点事件取应到时点；去向为原业务或固定页面时须有定位，去向为原业务时还须有查看与办理条件。适配状态默认待适配，完成共享登记、收件范围、文案及真实送达验证后才为已适配。

类型有值但未登记、分类无法识别及已收到消息的内容或去向异常，按[内容与去向异常](./01-运营端消息通知-PRD.md#intake-fallback)承接：保留可读与计数规则，未登记或缺失的去向不提供入口。接入时缺少必填信息与展示时发生异常分别处理；本模块不发邮件或其他站外消息。

## 前往原业务（FL-O03）

```mermaid
flowchart TD
    A["运营人员打开一条本人可见的消息"] --> B{"打开后去哪？"}
    B -->|不跳转、类型未登记、去向缺失或未登记| C["只看正文，没有前往入口，也不提示错误"]
    B -->|运营端固定页面| D["可以前往，由目标页面判断权限"]
    B -->|原业务| E{"按当前权限检查原业务"}
    E -->|不存在或无权| F["不能前往，显示“相关内容暂不可访问”"]
    E -->|超过 3 秒或检查失败| G["仍可前往，由原业务页面判断权限"]
    E -->|可以查看| H{"消息仍有效，且提示的动作仍可办理？"}
    H -->|是| I["前往原业务查看或办理"]
    H -->|否| J["前往查看这一笔的当前结果，不再提供旧动作"]
    D --> K["运营人员主动前往，目标页面按运营端权限矩阵重新判断"]
    G --> K
    I --> K
    J --> K
    K -->|有权| L["看到原业务的当前事实和当前可做的动作"]
    K -->|无权| M["原业务页面拒绝，不展示无权内容"]
```

始终定位到消息所说的那一笔，不换成最新一笔。消息正文说的是当时的事实，原业务页面展示的是当前的事实。超时不放宽任何权限。

<a id="fl-o04"></a>
## 全部已读（FL-O04）

```mermaid
flowchart TD
    A["在消息列表发起全部已读"] --> B{"当前筛选下有未读消息？"}
    B -->|否| C["操作不可用，并说明原因"]
    B -->|是| D["确认：写明当前筛选条件和将被标为已读的条数，包括尚未加载的部分"]
    D -->|取消| E["所有消息保持不变"]
    D -->|确认| F["处理本人在当前筛选下的全部未读，期间不能重复提交"]
    F -->|成功| G["按实际处理结果反馈，本人的已读与未读数同步更新"]
    F -->|失败| H["全部保持原状，不提示成功，可以重试"]
    F -->|登录失效| I["回到登录；重新登录后按实际已读结果展示"]
    G --> J["其他运营人员的已读不变；确认之后新到的消息仍为未读"]
```

全部已读只改变本人的阅读状态，与业务是否办完无关。

<a id="fl-o05"></a>
## 消息准入与原业务权限分别判断（FL-O05）

```mermaid
flowchart TD
    A["访问消息"] --> B{"已登录且完成首登强制改密？"}
    B -->|否| C["进入运营端账户流程，不展示正文"]
    B -->|是| D{"有消息查看权限？"}
    D -->|否| E["拒绝使用消息；本人其他业务功能按其自身权限"]
    D -->|是| F{"属于运营端，且是全体运营或本人的消息？"}
    F -->|否| G["与不存在相同"]
    F -->|是| H["可以阅读消息"]
    H --> I["前往原业务时，按运营端权限矩阵判断能否查看、能否办理"]
    I -->|无权或不存在| J["统一显示“相关内容暂不可访问”"]
    I -->|有权| K["进入原业务，按当前状态办理"]
```

消息查看权限只决定能否使用本模块，不带来任何原业务的权限；没有消息查看权限，也不影响本人从业务页面访问自己有权限的内容。管理员的称谓不带来查看他人本人消息的权限。

<a id="st-o01"></a>
## 消息有效期（ST-O01）

一条消息是否仍在有效期内，与是否已读、原业务能否办理是三件互相独立的事。

```mermaid
stateDiagram-v2
    [*] --> 有效: 消息产生
    有效 --> 已过期: 到达来源设定的有效期
    note right of 有效
        未读时计入未读数
    end note
    note right of 已过期
        不计入未读数，仍可查看，标示“已过期”
        原业务还能否办理，以原业务当前状态为准
    end note
```

没有设定有效期的消息一直有效。重复送达不会让过期的消息恢复有效。原业务被删除、本人无权、原动作已办完，都不会让消息变为过期。

<a id="st-o02"></a>
## 本人阅读状态（ST-O02）

对象是一个运营账号对一条消息的阅读状态。“全体运营”消息每个人各有一个阅读状态。

```mermaid
stateDiagram-v2
    [*] --> 未读: 消息进入本人可见范围
    未读 --> 已读: 详情展示成功且已读保存成功
    未读 --> 已读: 全部已读成功且在本次确认范围内
    未读 --> 未读: 只打开预览、详情加载失败、已读保存失败或同一事实重复送达
    已读 --> 已读: 再次阅读、同一事实重复送达或本人修改邮箱
    note right of 已读
        不能改回未读
        首次阅读时间不变
        不影响其他运营人员和其他端
    end note
```

新的事实是一条新消息，有自己的阅读状态，不会把旧消息改回未读。已读不代表审核、发布或其他业务已经完成。没有消息查看权限期间不能阅读；权限恢复后沿用原来的阅读状态。
