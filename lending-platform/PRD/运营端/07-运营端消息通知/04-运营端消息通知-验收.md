# 运营端消息通知 · 验收

2026-10-28｜需求评审稿｜供测试使用

本册列出运营端消息通知的验收标准：在什么前提下、做什么、应该看到什么结果。规则的完整说明见[功能与业务规则](./01-运营端消息通知-PRD.md)，各节顺序与功能册一致，每节开头链接到对应的功能章节。本册只写验收标准，具体测试用例与执行步骤由测试小队编写。

怎么读这本册：

- 共 106 条验收。编号沿用原值，已删除的条目不再占号，所以编号不连续、按功能顺序而非数字顺序排列；缺号不代表遗漏。
- 一条验收写了多个场景（用“另”“再”分隔）时，**全部场景都满足才算通过**。
- 本模块没有消息通知册（03），故验收册编为 04，与其他模块的册序一致。

## 0. 验收前准备

**账号。** 以下每类至少准备一个：

- 运营管理员两个（本期唯一角色），均已完成首登强制改密；其中至少一个承担 SPV 职责；
- 一个尚未完成首登强制改密的运营账号。本期每个正常运营账号都有消息查看权限，不准备无此权限的账号，见[本期单一角色](./01-运营端消息通知-PRD.md#single-role)；
- 一个面客端账号，以及一个代币发行平台运营端账号（用于确认其他端的消息不进入本模块）；
- 未登录状态。

**消息。** 使用各来源模块消息通知册中定义的真实消息，覆盖“全体运营”和“本人”两种收件范围；另需准备：

- 一条业务类型尚未登记的消息、一条分类无法识别的消息、一条来源设为不跳转的消息；
- 一条当前语言缺失、一条中英文都无法展示的消息；
- 一条设有有效期且已过期的消息；
- 原业务已流转（提示的动作已不适用）、原业务不存在、本人无权查看三种情况的消息各一条；
- 同一事实重复送达的消息，以及同一笔业务上的两次不同事实；
- 超过 99 条的未读消息，用于验证“99+”；超过 20 条的消息，用于验证“加载更多”；
- 一个新开通的运营账号，以及在它开通前已经存在的“全体运营”消息。
- 缺少必填字段、去向混合多种类型、指向本端以外、缺少条件必填的定位或权限条件的来源消息；与只缺少可选名称或编号的消息分别准备。
- 发生后延迟送达、到点触发、不同语言与时区、按结果选择文案的消息；同一事实补充信息与多个结果按来源规则合并的样本。
- 涉及敏感信息的数据样本，用于确认消息只展示来源已授权的必要业务信息。

**时效与性能。** [送达时效](./01-运营端消息通知-PRD.md#delivery-time)要求业务事件后 60 秒内可见、到点触发的事件最晚 6 分钟内可见，属于硬性验收项（AC-O115）；未读数读取、列表、预览、详情、全部已读与原业务检查的性能目标见功能册的[待确认事项与依赖](./01-运营端消息通知-PRD.md#shared-validation)，须以真实环境数据验证，不能以文档或原型自测代替。

**来源适配依赖。** 来源的共享登记、收件范围与账号隔离、真实送达及目标权限验证完成前，涉及这些依赖的验收待验，不判通过，见[共享登记与真实送达依赖](./01-运营端消息通知-PRD.md#shared-validation)。字段要求和演示数据不能代替真实来源已适配的结论。

| AC-O47 | 知道其他端某条消息的编号或链接 | 直接打开 | 结果与打开不存在的消息、他人的本人消息完全相同 |
| AC-O48 | 运营账号甲已登录 | 尝试把他人的消息标为已读 | 操作不成功；甲和他人的已读状态都不变 |

| AC-O54 | 一条“全体运营”消息已被部分人阅读 | 查找谁读过的信息 | 不提供查看他人阅读情况的功能 |
| AC-O55 | 已登录 | 查找查看面客端或其他平台消息的入口 | 不存在这样的入口 |
| AC-O56 | 已登录 | 猜测连续编号或批量访问消息 | 取不到任何他人或其他端的消息，也看不出它们是否存在 |
| AC-O75 | 一条“全体运营”消息尚无人阅读，随后同一事实重复送达 | 各运营人员分别查看 | 不显示任何人已读；重复送达不改变已读状态和发生时间；每人的已读互不影响 |
| AC-O77 | 一条“全体运营”消息 | 查看可见范围与原业务权限 | 只对有消息查看权限的运营人员可见；不扩大到其他端，也不因此带来任何原业务的办理权限 |
| AC-O97 | 存在一条不属于运营端的异常消息记录 | 查看列表、筛选、未读数，并用链接直接打开它 | 不展示、不计数，直接打开也看不到 |
| AC-O98 | 面客端或其他平台新增了消息 | 查看运营端未读数 | 运营端未读数不变，也没有跨端汇总 |
| AC-O99 | 知道其他端某条消息的链接 | 直接打开 | 与打开不存在的消息完全相同，不显示“无权限” |
| AC-O100 | 来源明确规定某事件运营端和面客端分别通知；另一个事件只通知面客端 | 分别在两端查看 | 前者两端各有一条、各自已读；后者不出现在运营端 |
| AC-O101 | 运营账号没有消息查看权限（本期不可验，见[本期单一角色](./01-运营端消息通知-PRD.md#single-role)） | 查看各业务页面，并用链接直接打开列表、详情或执行已读 | 没有消息入口，账户菜单也没有“消息中心”；直接打开被拒绝；本人其他有权限的业务功能正常 |
| AC-O102 | 运营账号的消息查看权限被收回，之后又被重新授予（本期不可验，见[本期单一角色](./01-运营端消息通知-PRD.md#single-role)） | 收回后再次访问；重新授予后再访问 | 收回后立即被拒绝，不能继续使用已打开的内容；重新授予后，历史消息按资格恢复，原来的已读状态不变；本模块不提供授权功能 |
| AC-O103 | 两个运营管理员账号，其中一个承担 SPV 职责 | 分别查看“全体运营”消息 | 两者看到的范围相同，SPV 没有另一份消息；本人消息仍只属于本人 |

## 2. 来源接入字段要求

对应功能：[来源接入字段要求](./01-运营端消息通知-PRD.md#f-o18)

| AC-O72 | 来源的消息使用了一个本人此前没有消息的分类 | 查看分类筛选 | 该分类出现在筛选中；没有消息的分类不出现 |
| AC-O76 | 来源已规定消息的统一分类及“全体运营”或“本人”收件范围 | 由对应运营账号查看消息与分类 | 分类按来源选择的统一分类展示；只在规定的收件范围内可见，不因分类扩大收件范围 |
| AC-O80 | 本模块的各项操作 | 阅读、筛选、全部已读、前往原业务等 | 本模块不发送邮件、短信或其他站外消息；运营端账户与登录自己的安全邮件与验证码邮件照常 |
| AC-O81 | 一条来源消息带有已授权的原业务名称、编号与金额 | 打开详情 | 来源提供的必要业务信息完整展示，编号可复制；缺失信息不以其他业务或虚假值补位 |
| AC-O82 | 已登录 | 查找发布消息、编辑公告、按人群发送、通知设置、异常升级或关闭的入口 | 都不存在 |
| AC-O90 | 一条当前语言缺失的消息；另一条中英文都无法展示的消息 | 分别在列表和详情查看 | 前者显示另一种语言；后者用分类、发生时间和通用标题“通知 / Notification”展示，不出现内部标识，不影响其他消息 |
| AC-O115 | 来源业务事件真实发生；另有一条由时间到点触发的事件；再有一条跨时区展示的消息 | 记录事件发生时刻或应到时点，观察列表与未读数；再切换时区与语言查看 | 普通事件 60 秒内出现在列表、未读数同步更新，从业务事件发生时起算；到点触发的事件从应到时点起算，最晚 6 分钟内可见。业务日期按 UTC，金额、币种与原发生时点不因展示或阅读而改变 |
| AC-O116 | 来源待发送消息缺少必填的业务类型标识、发送来源、收件范围、发生时间或可读标题正文等接入信息 | 业务事实发生，来源尝试发送 | 补齐后再发，不生成空白消息，不用 0、虚假编号、演示值或其他业务的信息补齐；与类型有值但未登记的兼容展示分别处理 |
| AC-O117 | 来源未明确收件范围；另一条选择“本人”但无法确定运营账号 | 业务事实发生，来源尝试发送 | 不发送；不按邮箱、钱包、机构或最近操作人猜账号，也不改投全体运营 |
| AC-O118 | 一条消息只缺少可选的原业务名称或编号，必填去向与定位完整 | 查看详情并前往 | 缺项不显示，消息仍可读、计数和已读；仍可前往登记的那一笔，不用其他业务信息补位 |
| AC-O119 | 一条业务事实发生一段时间后才送达的消息；另一条由时间到点触发 | 查看列表与详情，再阅读、切换偏好时区、重复送达 | 发生时间分别为业务事实发生时刻和应到时点，不能用送达或阅读时间代替；按偏好时区展示并标明，无偏好时按 UTC；阅读、切换时区和重复送达不改变原时点，排序仍按创建时间 |
| AC-O120 | 一条已收消息有完整中英文内容；另有按结果采用不同文案的消息 | 各收件人查看，再切换界面语言 | 历史标题与正文随语言切换；金额、币种、日期、时刻、版本和业务编号保持原事实，不按当前汇率或计划重算；每人只收符合条件的一条，不因存在两套文案多收一条 |
| AC-O121 | 同一事实重复送达或补充信息；同一业务又发生不同次提交、审核或其他新事实 | 在原消息未读和已读时分别查看 | 重复和补充不新增、不改排序位置、发生时间或已读；补充不倒退事实；不同事实各自一条，不按同一业务或同一版本号覆盖 |
| AC-O122 | 来源明确规定一次操作多个结果合并；另一来源没有登记合并规则 | 事实发生后查看收到的消息 | 前者只有一条且保留来源规定的全部必要事实；后者各结果分别一条，不按同一天、同一业务或同一个人自行合并 |
| AC-O123 | 来源消息涉及账户、钱包、材料或人员信息 | 查看标题、正文与关联业务信息 | 不出现密码、验证码、完整钱包地址、证件号、IP、材料原件或下载地址、完整银行账户或凭证、客服邮箱；不复制他人完整档案或私人联系方式，不披露按来源规则须匿名的审核员身份；只保留已授权的必要业务名称、金额和编号 |
| AC-O124 | 新接入消息去向为原业务或固定页面但缺少定位；另一条去向为原业务但缺少查看与办理条件；另有不跳转消息 | 来源尝试发送，收件人查看可接收的消息 | 前两者须补齐后再发，不猜原业务或权限；不跳转消息不要求原业务定位和办理条件，正常可读、计数和已读；缺少可选名称或编号不等于缺少必填定位 |

## 3. 消息入口、最近预览与未读数

对应功能：[消息入口、最近预览与未读数](./01-运营端消息通知-PRD.md#f-o01)

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| AC-O01 | 有消息查看权限的运营人员；另有未登录状态 | 依次进入运营端各业务页面 | 每个业务页面都有消息入口和未读数；未登录时不展示 |
| AC-O02 | 有消息查看权限的运营人员 | 在各业务页面之间切换 | 消息入口与账户菜单的行为在各页面一致，切换后不丢失通知 |
| AC-O03 | 本人没有有效的未读消息 | 查看未读数 | 不显示数字 0 |
| AC-O04 | 本人有效未读分别为 1～99 条、超过 99 条 | 查看未读数 | 前者显示实际条数，后者显示“99+” |
| AC-O05 | 一条设有有效期且已过期的未读消息 | 查看未读数、列表和详情 | 不计入未读数；仍可在列表和详情中找到，并标示“已过期” |
| AC-O06 | 原业务已删除、已办完，或本人对原业务无权 | 查看未读数与这条消息 | 消息不因此变为过期或已读；仍有效且未读时计入未读数 |
| AC-O07 | 有消息查看权限的运营人员 | 从账户菜单进入“消息中心” | 直接进入不带筛选的完整消息列表，不先经过预览 |
| AC-O08 | 本人有 10 条以上消息，已读未读都有 | 从消息入口打开最近消息预览 | 展示最近 10 条，已读和未读都包括；可以关闭预览 |
| AC-O09 | 预览中有未读消息 | 只打开预览、浏览经过；再选择其中一条进入详情 | 前者不改变已读状态；后者在详情展示成功后才变为已读 |
| AC-O10 | 未读数读取失败；另有读取时登录已失效 | 观察未读数 | 前者保留上一次的数字，不清零；后者按登录失效统一处理 |
| AC-O74 | 本人同时有“全体运营”和“本人”两种消息，有效、过期、已读、未读都有 | 查看未读数 | 等于两种消息中有效且未读的条数之和，全部分类合计；开通前已有的“全体运营”消息不计入 |
| AC-O105 | 同一账号在多个业务页面和浏览器标签中打开 | 在其中一处阅读消息；另在某业务页面有尚未保存的内容时打开预览 | 当前位置即时更新，其他页面和标签最晚 60 秒内一致；尚未保存的业务内容不被清空 |
| AC-O106 | 修改本人邮箱 | 查看账户菜单与消息 | 账户菜单显示新邮箱和角色“运营管理员 / Operations Administrator”，不出现“运营专员”；消息与已读状态不变 |

## 4. 消息列表与筛选

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |

| AC-O16 | 有多条创建时间相同的消息，总数超过 20 条 | 连续加载 | 同一时间的顺序固定；连续加载不重复、不遗漏 |
| AC-O17 | 本人有超过 20 条消息 | 打开列表并加载到底 | 每次加载 20 条，追加到已加载内容之后；没有页码跳转，也不能改变每次条数；没有更多时明确提示 |
| AC-O18 | 已加载部分消息并向下浏览，设置了某个分类筛选；另在“未读”筛选下已读过一条 | 到达一条符合当前筛选的新消息和一条不符合的；另有同一事实重复送达；再继续加载更多 | 符合筛选的新消息自动出现在列表顶部，不需要操作，当前阅读位置不变；不符合筛选的不插入；重复送达不增加条目；“未读”筛选下读过的消息不因新消息插入而被移走；已加载与后续加载的结果不重复、不遗漏 |
| AC-O19 | 无消息查看权限的账号（本期不可验，见[本期单一角色](./01-运营端消息通知-PRD.md#single-role)）；从未收到消息的账号；有消息但当前筛选无结果的账号 | 分别打开消息列表 | 三种情况可以区分：第一种按功能拒绝处理；第二种说明还没有任何消息；第三种说明当前筛选下没有消息，并可一键清除筛选 |
| AC-O20 | 第一批加载失败；另有“加载更多”失败 | 观察列表 | 前者可以重试；后者保留已加载内容和所在位置，可以重试；加载过程中和失败后都不显示为空列表 |
| AC-O21 | 同一批中有一条内容异常的消息 | 查看列表，并打开这一条 | 只有这一条按兜底规则展示，其他消息照常；这一条仍能打开详情 |
| AC-O85 | 不带筛选打开列表；另设置了非默认筛选 | 分别刷新 | 不带筛选时始终是同一个默认列表；非默认筛选刷新后保持 |
| AC-O86 | 网址中带有无效的筛选条件 | 打开列表 | 按默认条件展示并正常加载，不显示为没有消息 |
| AC-O89 | 正在加载更多 | 再次触发加载更多 | 不会重复加载；已加载内容保持；加载完成或失败后可以再次加载 |

## 5. 消息详情、已读与全部已读

对应功能：[消息详情、已读与全部已读](./01-运营端消息通知-PRD.md#f-o10)

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| AC-O22 | 一条本人可见的消息 | 通过链接直接打开详情；再刷新 | 详情有独立网址，可直接打开；刷新后仍是同一条消息 |
| AC-O23 | 一条消息含业务日期与具体时刻 | 打开详情；再切换本人偏好时区 | 显示带时区的发生时间；业务日期按 UTC；切换时区不改变事实 |
| AC-O24 | 一条正文中含标签或脚本字样的消息 | 打开详情 | 正文按纯文本显示，不执行；来源提供的已授权内容完整可读 |
| AC-O25 | 一条未读消息；另一条详情加载失败的未读消息 | 分别打开详情 | 前者展示成功后变为已读；后者仍为未读 |
| AC-O26 | 详情展示成功但已读保存失败；另有一条已读消息 | 观察前者并重试；再次打开后者 | 前者仍显示未读、正文照常可读，重试只处理已读，不重发消息也不执行业务；后者不重复扣减未读数，首次阅读时间不变 |
| AC-O27 | 列表中有未读消息 | 查找逐条“标为已读”的操作 | 不提供；点击消息进入详情即可；变为已读的方式只有打开详情和全部已读 |
| AC-O28 | 一条已读消息 | 查找“标为未读”的操作 | 不提供 |
| AC-O29 | 从设置了筛选、加载了多批的列表进入详情 | 返回列表 | 回到原列表，筛选条件、已加载的批次和所在位置都不变 |
| AC-O30 | 在“未读”筛选下打开一条消息 | 返回列表；再重新筛选或刷新 | 返回后这条仍在当前结果中并显示已读；重新筛选或刷新后才按条件移除 |
| AC-O31 | 当前筛选下有 300 条未读，已加载 20 条 | 执行全部已读 | 作用于全部 300 条，不只是已加载的 20 条，也不包括其他筛选下的消息 |
| AC-O32 | 当前筛选下有未读消息，包含尚未加载的部分 | 发起全部已读；另取消确认 | 先确认，写明当前筛选条件和将被标为已读的未读条数，包含尚未加载的部分；具体措辞与确认方式由设计确定；取消后消息不变 |
| AC-O33 | 全部已读执行失败；另有当前筛选下没有未读的情况 | 观察结果 | 前者全部保持原状，不提示成功、不清零，可以重试；后者全部已读不可用，并说明原因 |
| AC-O87 | 当前筛选命中 300 条消息，其中 200 条已读 | 查看列表，并发起全部已读 | 列表不显示包含已读的总条数；确认时给出的条数是 100；待处理的数量以未读数为准 |
| AC-O92 | 一条消息的详情加载失败 | 打开详情 | 说明尚未标为已读，提供重试和返回列表 |
| AC-O94 | 全部已读正在执行 | 再次确认或取消 | 不能重复提交，确认与取消暂不可用；完成或失败后恢复可用 |
| AC-O108 | 同一事实重复送达；另一笔业务上的新事实到达；全部已读执行期间有新消息到达；部分消息已在其他页面读过 | 分别查看列表与执行结果 | 重复送达不新增、不改变已读状态、时间和位置；新事实单独一条；确认之后新到的消息仍为未读；已在其他页面读过的不重复计算 |
| AC-O109 | 从列表进入详情，再前往本人账户设置；另刷新详情 | 返回 | 可以回到这条消息，再回到原列表，筛选、批次与所在位置不变；登录账号或权限已变化时重新判断，不恢复旧内容 |

## 6. 前往原业务

对应功能：[前往原业务](./01-运营端消息通知-PRD.md#f-o14)

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| AC-O34 | 一条去向为原业务、一条去向为固定页面的消息 | 分别前往 | 只前往来源登记的原业务或运营端固定页面，不使用消息中携带的任意地址 |
| AC-O35 | 来源待发送消息同时指定多种去向，或指定站外地址；另有已存在的混合去向异常消息 | 来源尝试发送；再打开已存在异常消息 | 前者不接收、不新增消息或未读数；后者保留正文，不提供前往入口；与未登记类型或去向分别处理 |
| AC-O36 | 一条来源设为不跳转的消息 | 打开详情 | 正常阅读；没有前往入口，也不提示“无法跳转” |
| AC-O37 | 一条业务类型尚未登记的消息；另一条来源要求给出“暂不可查看详情”提示的消息 | 分别打开详情 | 前者可正常阅读、计数和已读，没有前往入口；后者按来源保留该提示，不伪装为可以前往 |
| AC-O38 | 一条已进入本人可见范围、但去向缺失的消息 | 打开详情 | 消息正常可读、计数和已读，不隐藏；没有前往入口，不跳到默认页或错误页；新接入消息缺少必填去向时仍须补齐后再发 |
| AC-O73 | 一条业务类型已登记、但去向尚未登记的消息 | 打开详情 | 正常阅读、计数和已读；没有前往入口，不伪装为可以前往 |
| AC-O39 | 一条去向为固定页面的消息，本人对该页面无权 | 前往 | 由该页面按本人当前权限判断并拒绝 |
| AC-O40 | 列表中有多条去向为原业务的消息 | 打开列表；再打开其中一条详情 | 列表不逐条检查原业务；进入详情时才检查；能否办理以原业务当前状态为准 |
| AC-O41 | 原业务检查超过 3 秒或检查失败 | 前往原业务 | 允许前往；原业务页面重新判断权限，无权时拒绝查看或办理，超时不放宽任何权限 |
| AC-O42 | 消息已过期；原动作已办完；原业务已删除；本人对原业务无权 | 分别打开详情并前往 | 过期时标示“已过期”，仍可查看原业务；原动作办完时可查看当前结果，不再提供旧动作；已删除与无权两种情况都显示同样的“相关内容暂不可访问” |
| AC-O43 | 前往原业务的各种失败情况 | 打开详情 | 消息的标题、正文与发生时间都照常保留 |
| AC-O50 | 一条本人可见消息，原业务不存在；另一条本人可见消息，本人对原业务无权；再有一条不属于本人的消息 | 分别打开 | 前两者显示同样的“相关内容暂不可访问”，无法据此判断原业务是否存在；第三者按不存在处理 |
| AC-O57 | 来源待发送消息指向面客端或其他平台；另有已存在的跨端异常去向消息 | 来源尝试发送；再打开已存在异常消息 | 前者不接收、不新增消息或未读数；后者不提供前往入口；固定页面必须是运营端已登记的页面 |
| AC-O91 | 一条已过期的消息，原业务仍可查看 | 打开详情并前往 | 列表与详情都标示“已过期”；可以查看原业务；原业务还能否办理以其当前状态为准，旧动作不因消息而恢复 |
| AC-O110 | 一条消息提示的那次提交已被他人处理；另一条消息提示的动作已过期 | 分别打开并前往 | 消息照常可读；能查看原业务时可以看到那一次的当前结果；不能改为指向新的一笔，也不能重开或再次办理旧动作；读消息不完成原业务 |
| AC-O111 | 一个有消息查看权限但对某原业务无权的账号；另一个没有消息查看权限、但对某业务页面有权的账号（两种账号本期都不存在，本期不可验，见[本期单一角色](./01-运营端消息通知-PRD.md#single-role)） | 前者从消息前往原业务；后者从业务页面直接访问 | 前者由原业务按其所属模块的功能权限项拒绝，消息查看权限不带来原业务权限；后者正常访问有权的业务内容，但仍没有消息入口 |
