# 运营端项目合约管理 · 消息通知

2026-10-14｜配套[主 PRD](./01-运营端项目合约管理-PRD.md#entry)与[图册](./02-运营端项目合约管理-流程图与状态机.md)。

<a id="notify-entry"></a>
## 1. 范围

本模块只有两类事件——**项目审核通过**与**项目审核退回**，只发给创建该项目的资产方本平台账号，只走"借贷平台 · 面客端"站内信，分类语义为"业务办理进度"。两类事件沿用面客侧既有编号 `N-LS-09`／`N-LS-10` 与模板 [`T-LS-09`](../../面客端/05-借贷广场-融资需求与代币质押/03-融资需求与代币质押-消息通知.md#t-ls-09)／[`T-LS-10`](../../面客端/05-借贷广场-融资需求与代币质押/03-融资需求与代币质押-消息通知.md#t-ls-10)，**本模块是唯一发送来源**；面客承接与双语模板正文以[融资需求与代币质押消息通知](../../面客端/05-借贷广场-融资需求与代币质押/03-融资需求与代币质押-消息通知.md)为准，本册不复制、不改写。阅读入口、未读、去重与可见时效沿[面客消息中心](../../面客端/10-面客消息中心/01-面客消息中心-PRD.md)。

**本模块不产生任何运营端站内消息**：新项目待审不广播，裁定后不给运营发回执，部署失败与待核实不告警。本册不新增邮件、短信、推送、催办或部署进度通知。

<a id="notice-rules"></a>
## 2. 事件与发送边界

| 事件 | 触发与必须告知的内容 | 打开目标 |
| --- | --- | --- |
| `N-LS-09` 项目审核通过（`financing.project.review_approved`） | **合约部署成功时发送一次**（部署成功即审核通过）。告知项目已可用、[质押合约地址](./01-运营端项目合约管理-PRD.md#cf-08)、现在可在项目详情发起代币质押（需本人签名、gas 自担） | 对应项目；质押须用户主动发起，消息不代办 |
| `N-LS-10` 项目审核退回（`financing.project.review_returned`） | **退回结论生效即发送，每次退回各一次**。带[退回原因](./01-运营端项目合约管理-PRD.md#cf-06)全文，告知可修改后重提、项目期限不重新起算、项目编号不变 | 对应项目的创建信息；已重提的显示当前状态，不回到旧版本 |

**不发送**：提交通过后的部署处理中（此时尚无结论，不得提前发通过）、部署失败、再次发起、结果待核实、未提交的原因、并发未生效的裁定、任何时间流逝。

**收件与去重**：固定发给创建该项目的账号，不按企业全员、管理员或当前查看人扩发；资金方、游客与运营不收。按收件账号、事件与本次结论区分：同一次结论重复送达只算一条，不新增未读、不改发生时间；同一项目的多次退回与最终通过各自保留，不按"项目＋结论类型"合并。账号停用或归属缺失时不猜测新收件人，沿消息框架处理。

**时间**：通过取部署成功回写的真实时点（即[合约部署完成时间 `FP-38`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-38)），不取部署发起或提交时刻；退回取结论生效时点。时点按收件人偏好时区标注，不出现任何截止或剩余时长。

**内容边界**：变量 `project_name`、`project_id`、`approved_at`、`contract_address`、`reason` 的必填与缺失处理按面客模板定义；`approved_at` 与 `contract_address` 必须是部署成功回写的真实值，缺失时不发送该条，不以占位值补齐。不进入消息：部署失败原因、原始技术报错、内部信息、SPV机构名称、平台统一钱包地址。

**读消息不改变业务**：已读不完成审核、不发起质押、不撤销合约、不改变项目状态；投递失败不回滚已生效结论。

## 3. 时效与依赖

关键结果在真实业务发生后 **60 秒**内可见。共享消息分类登记、端到端时效冲突（部分来源为"60 秒与最坏 5 分钟"）与真实投递仍待消息框架侧核验；部署结果真实回写见[`Q-CM-02`](./01-运营端项目合约管理-PRD.md#q-cm-02)，回写缺失时不得提前发送通过通知。两类事件不设可关闭开关。

<a id="notice-acceptance"></a>
## 4. 验收

前置：P1 退回一次后重提并部署成功；P2 部署失败后再次发起；P3 停留在已退回。

| 编号 | 验收结果 |
| --- | --- |
| `AC-CM-N01` 两类结果分别触达创建账号 | P1 的退回与其后的通过各一条、互不吞并；P3 的退回一条；仅创建该项目的账号收到，资金方、游客与运营不收。通过含真实合约地址并说明现在可发起质押；退回原因全文准确，并说明期限不重算、编号不变 |
| `AC-CM-N02` 部署未成功不发送 | 部署处理中不发送；P2 的部署失败、再次发起与结果待核实全程不向资产方发送任何消息，面客只见待审核；部署成功后才发送通过 |
| `AC-CM-N03` 去重且多次结论各自保留 | 同一次通过重复到达只有一条，不新增未读、不改次序与时间；同一项目的历次退回与最终通过分别保留 |
| `AC-CM-N04` 时点正确且无期限类时间 | 通过时点等于合约部署完成时间并带时区标注，不取部署发起或提交时刻；消息中无截止、剩余时长或倒计时；切换时区不改事实 |
| `AC-CM-N05` 历史消息可读但不误办理 | 项目关闭或已重提后，原消息仍可按权限阅读本次原因，不回到旧版本；读消息不完成审核、不发起质押、不撤销合约；无权者不能读私有项目信息 |
| `AC-CM-N06` 事件范围限于两类且无运营端消息 | 只有通过与退回两类事件；运营端无新项目待审广播、裁定回执、部署失败告警或钱包余额类消息 |
| `AC-CM-N07` 变量完整且不泄露内部信息 | 中英模板变量完整，原因全文保留；不出现部署失败原因、原始技术报错、SPV机构名称或平台统一钱包地址；合约地址或通过时点缺失时不发送该条 |
| `AC-CM-N08` 时效以真实投递为准 | 从真实业务发生时点观察 60 秒可见；未登记或时效冲突如实标未完成，不以模板核对替代实际投递验收 |
