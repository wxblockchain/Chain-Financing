## FL-CM-02 部署失败、结果待核实与再次发起

```mermaid
flowchart TD
  A["部署处理中"] --> B{"真实链上结果"}
  B -- "明确成功" --> E["部署成功 = 审核通过<br/>转 FL-CM-01"]
  B -- "签名或部署明确失败" --> C["部署失败 · 审核轴回到待审核<br/>计入部署失败待再次发起"]
  B -- "长期无结果或事实冲突" --> D["结果待核实 · 审核轴停在部署处理中<br/>保留已知凭证，处置入口不可用"]
  C --> C1["运营端展示失败原因、时点、已消耗 gas<br/>原因不进入面客"]
  C1 --> C2{"处置人选择"}
  C2 -- "再次发起" --> C3["同一项目、同一次提交<br/>新的部署尝试"]
  C3 --> A
  C2 -- "改为退回" --> R["按 FL-CM-01 退回"]
  C2 -- "暂不处理" --> C4["停留在待审核<br/>不自动重试、退回或通过"]
  D --> D2["回写真实结果后按成功或失败继续"]
  D2 --> B
  C --> X["不向资产方发送任何消息<br/>面客只见待审核"]
  D --> X
```

<a id="st-cm-01"></a>
## ST-CM-01 项目审核轴

```mermaid
stateDiagram-v2
  PENDING: 待审核 · 面客 S-FP-7
  DEPLOYING: 部署处理中 · 面客仍为 S-FP-7 · 非结论 · 资产方不可关闭
  APPROVED: 已通过 · 面客 S-FP-1 · 终态
  RETURNED: 已退回 · 面客 S-FP-8
  [*] --> PENDING: 资产方提交审核
  PENDING --> DEPLOYING: 提交通过 · 平台统一钱包发起部署
  DEPLOYING --> APPROVED: 部署成功 = 审核通过
  DEPLOYING --> PENDING: 部署失败 · 由管理人员再次发起或改为退回
  DEPLOYING --> DEPLOYING: 结果待核实
  PENDING --> RETURNED: 退回并给出原因
  RETURNED --> PENDING: 资产方修改重提 · 期限不重算
  APPROVED --> [*]
```

资产方在待审核或已退回期间关闭项目时，审核轴保留原值并标"项目已关闭"，不再可裁定；部署处理中资产方不能关闭，部署结果回写后按结果处理（[部署处理中资产方不能关闭项目（D-CM-21）](./01-运营端项目合约管理-PRD.md#d-cm-21)）。

<a id="st-cm-02"></a>
## ST-CM-02 合约部署执行状态

```mermaid
stateDiagram-v2
  NONE: 未发起
  RUNNING: 部署处理中
  SUCCESS: 部署成功 · 回写地址与凭证
  FAILED: 部署失败
  UNKNOWN: 结果待核实
  [*] --> NONE: 项目提交审核
  NONE --> RUNNING: 提交通过
  RUNNING --> SUCCESS: 链上明确成功
  RUNNING --> FAILED: 签名或部署明确失败
  RUNNING --> UNKNOWN: 长期无结果或事实冲突
  FAILED --> RUNNING: 再次发起
  UNKNOWN --> SUCCESS: 回写为成功
  UNKNOWN --> FAILED: 回写为失败
  SUCCESS --> [*]
```

部署成功后不再发起部署；地址只读，无录入、修改、解绑或重新部署入口。
