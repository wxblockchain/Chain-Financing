# 运营端项目合约管理 · PRD

2026-10-14｜运营管理平台 · 运营端｜需求评审稿，真实未决项见第 5 章。导航菜单名称：**项目合约管理**（Project contracts）。

<a id="entry"></a>
## 1. 目标与阅读入口

资产方在面客端创建融资项目并提交审核后，运营人员在本模块核对创建信息：**核对通过即由平台统一钱包发起本项目质押合约部署，部署成功就是审核通过**，同时产生本项目唯一的质押合约地址；也可退回并给出面客可读原因。已部署的合约在本模块的质押合约台账中只读可查。项目审核与合约是同一件事的两面，故本模块以"项目合约"命名。

本期包含：项目审核队列与统计筛选、审核详情与创建信息核对、通过并部署合约、退回与唯一结论、部署失败与结果待核实的再次发起、质押合约台账、留痕与通知触发。本期不包含第 [1.2 节](#1-2-本期不包含) 各项。

有效依据为用户 2026-09-24 批已确认口径（项目与合约 1:1、审核与部署合为一步、结论只有通过与退回、退回可修改重提且项目期限不重新起算、平台统一钱包取值在代码层面维护、gas 由管理端承担且充值不在本系统范围、运营人员不签名、全链路无审核时限），以及 2026-10-08 用户裁定的运营端本期单一角色。各条在第 2、3 章对应处落地，不在此重复。

<a id="d-cm-02"></a>`D-CM-02`【承接边界】：本册只写**运营端这一侧**——运营人员看到什么、能做什么、做完之后两端各变成什么。项目审核的业务判定（[项目审核 `F-LS-22`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-22)）、创建信息字段及其校验、项目状态与面客结果均由融资需求与代币质押定义，本册只读消费、不复制、不改写；两册口径不一致时以该册为准，差异列入[第 5 章](#open-items)交用户裁定。

阅读顺序：第 2 章共同口径 → 第 3 章完整功能 → 第 4 章同序验收 → 第 5 章依赖与待决。配套须共同阅读：[流程图与状态机](./02-运营端项目合约管理-流程图与状态机.md)、[消息通知](./03-运营端项目合约管理-消息通知.md)。

### 2.1 审核对象、角色与信息域

`D-CM-03`【审核对象】：

| 对象 | 含义与范围 |
| --- | --- |
| 待审核项目 | 资产方已提交审核、尚无有效结论的一个融资项目。**审核对象是项目本身，不是代币、不是批次**；一个项目在队列中始终只有一条记录 |
| 本次提交 | 首次提交与每次退回后的重新提交各算一次，按发生时间形成提交序次；重新提交走同一条审核与部署链路，不产生新的项目编号 |
| 审核结论 | 每次提交至多一个有效结论：**通过**（成立条件是合约部署成功）或**退回**（须有面客可读原因）。签名或部署失败不是结论 |
| 质押合约 | 部署成功产生的本项目质押合约，与项目一一对应、终身稳定；一个项目只部署一份 |

| 参与方 | 本模块责任 |
| --- | --- |
| 运营人员 | 查看项目与合约信息；线下判断后在线提交通过或退回、在部署失败后再次发起。**不签名、不代付 gas、不发起或撤销任何链上动作**，不修改创建信息，不按运营机构隔离 |
| 资产方 | 在面客端创建、提交、按退回原因修改重提、主动关闭项目；审核期间不付费、不签名、无链上动作 |
| 借贷平台 | 受理通过后由平台统一钱包发起部署并承担 gas；按真实链上结果回写部署事实与合约地址，派生项目状态 |
| 平台统一钱包 | 部署的唯一发起方；取值在代码层面维护、随版本发布，面客端与运营端都没有维护、配置、切换或审批入口，范式同[SPV机构名称 `FP-31`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-31) |

<a id="d-cm-11"></a>
### 2.3 时间、日期与金额口径

`D-CM-11`：

- **业务日期**：近七个自然日统计与按日期筛选统一 UTC，并让操作者可识别其 UTC 口径；具体时点按用户偏好时区显示并标注。切换时区、跨周末或夏令时不改变已发生事实、统计归属或事件先后。
- **无审核时效**：不设截止、不设倒计时，任何状态都不因时间流逝改变；已等待时长只作事实陈述，不触发催办或超时通知。
- **项目期限**：按[项目期限 `FP-35`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-35) 呈现为"生效日～到期日"（生效日即创建日）。本模块不决定也不改变起算点，审核耗时不延长项目有效期。
- **费用**：审核阶段资产方零费用；部署 gas 按真实币种如实展示，未知标"待核实"，不填 0、不编造精度。

<a id="states"></a>
### 2.4 两条状态轴

<a id="d-cm-04"></a><a id="cf-03"></a>`D-CM-04`【项目审核轴 `CF-03`】枚举，必有，默认待审核：**待审核 / 部署处理中 / 已通过 / 已退回**。已通过与已退回是结论；部署处理中是提交通过后等待链上结果的过渡态，**不是结论**。项目状态的权威定义归[融资项目状态](../../面客端/05-借贷广场-融资需求与代币质押/02-融资需求与代币质押-流程图与状态机.md#st-ls-01)，本册只读对应：

| 审核轴 | 面客项目状态 | 允许的运营动作 |
| --- | --- | --- |
| 待审核 | `S-FP-7` 待审核 | 通过并部署、退回；无截止 |
| 部署处理中 | 仍为 `S-FP-7` | 无。不得重复发起、不得改判为退回，不推定成功或失败；**资产方此时不能关闭项目** |
| 已通过 | `S-FP-1` 可用（空池） | 无。结论终态，不可撤销、不可二次裁定 |
| 已退回 | `S-FP-8` 已退回 | 无。等资产方修改重提后回到待审核 |

资产方在待审核或已退回期间主动关闭项目（面客 `S-FP-5`）后，审核轴保留关闭前的取值并标"项目已关闭"，不再可裁定。<a id="d-cm-21"></a>`D-CM-21`【部署处理中不可关闭】：用户 2026-10-14 裁定，审核轴为部署处理中（含部署执行状态为结果待核实）期间，资产方不能关闭项目，面客规则见[部署进行中暂不可关闭 `D-LS-71`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-71)。部署结果回写后按结果处理：部署成功则项目已通过，此后的关闭按面客可用状态的既有条件，与本模块无关；部署失败则回到待审核，资产方可以关闭。

<a id="d-cm-07"></a><a id="cf-07"></a>`D-CM-07`【合约部署执行状态 `CF-07`】枚举，必有，默认未发起：**未发起 / 部署处理中 / 部署成功 / 部署失败 / 结果待核实**。这是链上执行事实，与审核轴独立：部署成功推动审核轴到已通过；部署失败把审核轴退回待审核；结果待核实时审核轴停留在部署处理中。各值的处理见[部署失败、结果待核实与再次发起](#m5)。

<a id="d-cm-05"></a>`D-CM-05`【项目与合约 1:1】：部署成功产生的质押合约地址全局唯一、与项目一一对应、终身稳定、只读；本模块不提供录入、修改、解绑或重新部署。部署成功后创建信息全部只读。

<a id="d-cm-06"></a>`D-CM-06`【运营端不代资产方动作】：修改创建信息、重新提交、关闭项目都是资产方动作，运营端没有对应入口；退回是运营端唯一能让项目回到资产方手上的结论。

<a id="chain"></a>`D-CM-15`【只涉及质押链】：合约部署、合约地址与部署凭证均属**质押链**（本期 ETH）事实。**结算收款链**与企业账户不进入本模块，不读取、不校验、不展示任何收款账户或收款地址。

状态图见[项目审核轴 `ST-CM-01`](./02-运营端项目合约管理-流程图与状态机.md#st-cm-01)与[合约部署执行状态 `ST-CM-02`](./02-运营端项目合约管理-流程图与状态机.md#st-cm-02)。

### 3.1 项目审核队列（`F-CM-01`～`05`）

前置：具备融资项目审核查询。队列一条记录对应一个项目，退回重提仍是同一条。

| 内容 | 产品规则 |
| --- | --- |
| 默认（`F-CM-01`） | 审核轴＝待审核且项目未关闭，本次提交时间升序；同时间按稳定顺序。不做风险优先排序 |
| 须可得的信息（`F-CM-02`） | 项目编号、项目名称、资产方企业、代币类型、项目质押率、项目期限、本次提交时间与提交序次、已等待时长、审核轴、部署执行状态、是否已关闭；已通过的另可得质押合约地址 |
| <a id="d-cm-13"></a>筛选（`F-CM-03` / `D-CM-13`） | 审核轴（全部 / 待审核 / 部署处理中 / 已通过 / 已退回）、部署执行状态（全部及五个取值）、资产方企业、代币类型、提交时间范围、关键词（项目编号 / 项目名称 / 企业名称 / 质押合约地址）。组合生效，起止含边界，起点不得晚于终点；关键词忽略首尾空白；重置回默认 |
| 三项统计（`F-CM-04`） | **待审核项目数**（审核轴＝待审核且未关闭，含部署失败待再次发起的项目）、**其中部署失败待再次发起项目数**（前者的子集，不与前者相加）、**近 7 个自然日人工审结项目数**（结论为通过或退回，按结论时间计；部署失败不计）。统计应用企业、代币类型、提交时间与关键词条件，不应用审核轴与部署执行状态筛选，并标明范围 |
| 排序与分页（`F-CM-05`） | 本次提交时间、已等待时长可升降序；带总数常规分页，每页条数沿用平台现行取值。筛选改变回首页；返回保留筛选、排序、页码，原页为空回最后有效页并说明 |

队列只提供查看，不提供逐条裁定或批量选择，进入详情才能办理。空、无结果与读取失败按 [2.5 节](#2-5-共同质量要求)。流程见[项目审核与合约部署 `FL-CM-01`](./02-运营端项目合约管理-流程图与状态机.md#fl-cm-01)。

### 3.2 审核详情与创建信息核对（`F-CM-06`～`08`）

<a id="d-cm-12"></a>`D-CM-12`【线下判定、线上留证】：详情中性说明"本处信息供线下判定参考，结论由审核人线下作出后在此维护"；不提供评分、风险灯、建议结论或自动筛出。格式、权限与状态校验照常生效。

`F-CM-06`：审核详情使下列信息同处可得，并始终可定位当前项目编号与提交序次。

| 区块 / 字段 | 业务含义、类型与规则 |
| --- | --- |
| <a id="cf-01"></a>项目定位（`CF-01`） | 项目编号与项目名称，只读、必有；不以名称替代编号定位 |
| <a id="cf-02"></a>本次提交（`CF-02`） | 本次提交的真实时点与提交序次（第 N 次），只读、必有 |
| 创建信息 | 项目名称、代币类型、项目质押率、项目期限（生效日～到期日）、参考结算币种、还款方式、SPV机构名称，按[创建信息](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#create)原值只读呈现，运营端不可编辑、不二次校验。还款方式标"平台定值"，参考结算币种标"只供参考，不限制资金方报价币种"：两者是核对带出值，审核人只需确认其为平台带出的现行取值 |
| 资产方 | 企业名称与稳定主体标识，只读；主体标识缺失标"待核实"、不放行，不以名称替代归属判定（[`Q-CM-05`](#q-cm-05)） |
| <a id="cf-11"></a>参数上下文（`CF-11`） | 该代币类型当前的最高质押率与最长项目期限，只读、标明取数时点，**仅作背景参考**，与创建时锁定值并列并标出是否一致，按 [`D-CM-17`](#d-cm-17) 处理 |
| <a id="cf-04"></a><a id="cf-05"></a>审核信息 | 审核轴（`CF-03`）；每次结论的结论时间（`CF-04`，通过即[合约部署完成时间 `FP-38`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-38)）、审核人（`CF-05`，取当时身份）与退回原因（`CF-06`）；历次结论各自保留 |
| <a id="cf-08"></a>质押合约地址（`CF-08`） | 即 [`FP-33`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-33)：部署成功后必有，可复制完整值并自行到区块链浏览器查验，平台不做链上核验；部署完成前为空，不显示占位值 |
| <a id="cf-09"></a>部署链上事实（`CF-09`） | 质押链（本期 ETH）、合约部署完成时间（`FP-38`）、部署交易凭证、实际 gas 与币种、部署发起地址（即平台统一钱包地址）；均为只读回写事实，运营端无维护、配置或切换入口；未提供的项标"待核实"，不填 0 |
| 操作记录 | 按 [`D-CM-18`](#d-cm-18) |

<a id="d-cm-17"></a>`D-CM-17`【核对对象是创建时的快照】：项目质押率与项目期限创建时锁定终身。审核核对的是资产方提交创建时锁定的快照，沿[`D-O-FC-03`](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#d-o-fc-03) 的"审核核对用快照"：**审核期间运营调高或调低参数配置，不改变在审项目的核对结论，也不改变退回后重提的核对基准，本身不构成退回理由**。锁定值与当前配置不一致时如实并列并标出差异，不自动拦截、不改写锁定值、不自动退回、不产生整改待办，也不使项目变为违规；当前配置不可读时标"待核实"，不阻断审核。

<a id="d-cm-18"></a>`D-CM-18`【操作记录是唯一的进度与历史来源】：本项目全部事实只记在一条按发生时间倒序的操作记录里，**不另设"审核历史"或第二套进度明细**。

| 记录内容 | 信息要求 |
| --- | --- |
| 事件 | 必有，区分：提交审核、提交通过并发起部署、部署成功（即审核通过）、部署失败、结果待核实、再次发起部署、审核退回、资产方修改重提、资产方关闭项目；只含本项目事实 |
| 时间与主体 | 真实发生时间与时区；暂缺标"待核实"，不用访问时刻代替。人工事件显示当时审核人，资产方动作标"资产方"，链上结果回写标"系统"；主体未提供标"待核实"，不推定为审核人 |
| 结果与凭据 | 事件结果、前后状态与原因全文；部署相关事件附对应链上凭证与合约地址；没有则说明暂无，不伪造、不复用其他项目的凭证 |
| 反馈 | 加载中、暂无记录、读取失败分别说明；记录只读，无编辑、删除或手工完成动作 |

`F-CM-07`【审核历史在操作记录中读取】：历次提交、结论、退回原因全文、审核人与时间、历次部署尝试与结果均可从操作记录取得；摘要可收起，退回原因可展开全文。重新提交不覆盖既往原因，也不把上一次结论改写为本次结论。

`F-CM-08`：同一事件重复到达只保留一条，新增进度不覆盖既往事实。从队列或台账进入详情只进入该项目，返回保留来源的筛选、排序、分页与所在位置。流程见[详情、操作记录与合约台账的查看 `FL-CM-03`](./02-运营端项目合约管理-流程图与状态机.md#fl-cm-03)。

<a id="m3"></a>
### 3.3 通过并部署合约（`F-CM-09`～`11`）

<a id="d-cm-08"></a><a id="d-cm-09"></a>`D-CM-08` / `D-CM-09`【审核与部署合为一步】：前置为具备处置权限，**当前项目为待审核、未关闭、且无部署处理中**（无截止条件）。通过办理（`C-O-CM-01`）为：回显创建信息与上下文 → 确认知悉"提交后由平台统一钱包发起本项目质押合约部署；部署成功即审核通过，项目与合约一一对应，不可撤销" → 提交。**提交即发起部署，运营人员不签名、不付费**；没有第二步确认，也不新增第二位审核人。

| 编号 | 规则 |
| --- | --- |
| `F-CM-09` | 取消不产生结论、不发起部署；提交中明确反馈且不可重复点击。提交生效时权限或状态已变化（已关闭、已被他人裁定、已在部署处理中）则就地说明并拒绝。与资产方关闭项目同时发生时只成立先生效的一笔：关闭先生效则本次通过被拒；通过先生效则进入部署处理中，资产方的关闭被拒（[`D-CM-21`](#d-cm-21)） |
| <a id="d-cm-19"></a>`F-CM-10` / `D-CM-19` | 提交成功即结束本次办理，回到详情：审核轴与部署执行状态转为**部署处理中**，操作记录出现"提交通过并发起部署"，该项目离开待审核统计。此时**尚未形成结论**：界面不得出现"已通过"，面客仍为待审核、不得引导发起质押；处置入口不可用，并发提交只有一笔成立 |
| `F-CM-11` | **部署成功即审核通过**：回写质押合约地址与部署链上事实，审核轴转为已通过并记录审核人（提交通过的运营）与结论时间（即合约部署完成时间），人工审结数加一；面客项目转为可用（空池），可发起代币质押。结论终态：不可撤销、不可改判为退回、不再部署第二份合约。发送一条[项目审核通过](./03-运营端项目合约管理-消息通知.md#notice-rules)站内信 |
| <a id="d-cm-20"></a>`D-CM-20` | 审核通过不改创建信息、不改代币事实、**本身不产生任何质押额**；三项额度归融资需求与代币质押，本模块不展示、不计算 |

<a id="m4"></a>
### 3.4 退回与唯一结论（`F-CM-12`～`13`）

`F-CM-12`：前置同 [3.3 节](#m3)。退回办理（`C-O-CM-02`）为：填写退回原因 → 全文预览与二次确认 → 提交。退回**不发起部署、不产生合约地址、不消耗 gas**。

| 编号 | 规则 |
| --- | --- |
| <a id="cf-06"></a>`F-CM-13` / `CF-06` | 退回原因必填，10～500 字（沿本平台审核驳回原因的现行校验），即[审核退回原因 `FP-37`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-37) 的面客可读原文，原样进入面客与站内信；不得写入内部代号、内部备注或本项目之外的信息；提交后不可编辑或删除 |
| 唯一结论 | 一次提交至多一个有效结论；并发裁定只有一笔成立，败方告知已有结论并展示现状，不覆盖原因 |
| 退回后 | 审核轴转为已退回（面客 `S-FP-8`），人工审结数加一；资产方能否重提、重提时的校验由面客[创建信息](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#create)判定。重提后回到待审核与队列，项目编号不变、项目期限不重新起算 |
| 多次退回 | 次数不设上限；平台不自动终结、不自动通过、不限制重提次数 |

取消不产生结论，跨项目不携带原因；提交中不可重复点击，保存失败保留输入可重试；结果不确定时先查当前事实，不展示成功或引导重复裁定。成功后结束本次办理回到详情，并发送一条[项目审核退回](./03-运营端项目合约管理-消息通知.md#notice-rules)站内信。

### 3.5 部署失败、结果待核实与再次发起（`F-CM-14`～`15`）

<a id="d-cm-16"></a>`D-CM-16`【失败与待核实都不是结论】：二者都不要求资产方重新提交、不改变项目期限起算点、不产生第二个项目或第二份合约，**也不向资产方发送任何消息**——面客始终只见待审核。

| 情形 | 业务变化与运营端动作 |
| --- | --- |
| 部署失败（`F-CM-14`） | 签名或部署明确失败：审核轴回到待审核，计入"部署失败待再次发起"统计。展示<a id="cf-10"></a>部署失败原因（`CF-10`，运营端可读的失败事实原文，**不进入面客、站内信或退回原因**）、失败时点与已消耗 gas（未知标"待核实"）。主操作为再次发起部署；处置人也可改为退回 |
| 再次发起（`F-CM-15`） | 复用同一项目编号与同一次提交，形成新的部署尝试并进入部署处理中；历次尝试与结果都留在操作记录。次数不设上限，平台不自动重试、不自动退回、不自动通过 |
| 结果待核实 | 长期无确定结果或事实冲突：标"待核实"，保留已知凭证与事实；**不推定成功或失败、不重复发起、不自动改判或回滚**，处置入口不可用并给出说明。真实结果回写后按成功或失败继续（[`Q-CM-02`](#q-cm-02)） |

本期不提供工单、升级、人工改判或补记、强制回滚、补偿或手工录入合约地址；无法自行处理时联系建设方核实链上与配置，产品内不编造处理时限。流程见[部署失败、结果待核实与再次发起 `FL-CM-02`](./02-运营端项目合约管理-流程图与状态机.md#fl-cm-02)。

### 3.6 质押合约台账（`F-CM-16`～`17`）

`F-CM-16`：台账（`P-O-CM-03`）一条记录对应一个**已部署成功**的项目及其唯一合约；未部署成功的项目不出现。前置：具备融资项目审核查询。

| 内容 | 产品规则 |
| --- | --- |
| 须可得的信息 | 项目编号、项目名称、资产方企业、代币类型、质押合约地址、质押链、合约部署完成时间、审核人、项目当前状态（只读消费面客项目状态） |

### 3.7 留痕与通知触发（`F-CM-18`～`19`）

`F-CM-18`：[3.2 节](#d-cm-18)所列事件全部留痕，关联项目与本次提交，含时间、主体、前后状态、原因与凭据；不可编辑删除，重新提交不覆盖旧结论，同一事件不重复记录。

<a id="d-cm-14"></a>`F-CM-19` / `D-CM-14`：本模块是面客事件"项目审核通过"（`N-LS-09`）与"项目审核退回"（`N-LS-10`）的**唯一发送来源**，各在结论生效时发一条给创建该项目的资产方账号；失败、再次发起、待核实不发送；**不产生任何运营端站内消息**。事件、收件、内容与验收全部见[消息通知](./03-运营端项目合约管理-消息通知.md#notice-rules)。

## 4. 同序验收

前置：资产方提交项目 P1、P2、P3；运营管理员账号一个，另备一个仅开通处置、缺配套查询的交付配置；平台统一钱包的部署可分别产生成功、失败与长期无结果三种结果。以下为业务验收要求，未决分支按[第 5 章](#open-items)，不以模拟结果冒充已上线能力。

### 4.1 项目审核队列（对应 [3.1](#m1)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-CM-01` 一个项目一条记录 | P1 提交后出现一条记录，默认待审核、提交时间升序；P1 退回重提后仍是同一条、同一项目编号，提交序次为第 2 次 |
| `AC-CM-02` 三项统计口径正确 | P2 部署失败后计入待审核项目数，并计入其中"部署失败待再次发起"，两数不相加；P2 不计入近 7 日人工审结。P1 通过、P3 退回后人工审结加 2。切换审核轴或部署执行状态筛选不改变统计 |
| `AC-CM-03` 筛选取值与组合 | 审核轴只有四个取值、无第三种结论或超时项；部署执行状态五个取值；企业、代币类型、提交时间区间、关键词组合生效，起止错误就地提示，重置回默认 |
| `AC-CM-04` 往返保留上下文且失败不假报 | 翻页与详情往返保留原筛选、排序、分页与位置；队列无逐条裁定与批量选择；读取失败不显示为零条，可重试 |
| `AC-CM-05` 已关闭项目不可裁定但可回看 | P3 在已退回期间被资产方关闭：不计入待审核、默认视图不出现、不可裁定；按条件仍可检索并只读回看，标"项目已关闭"；运营端无关闭与恢复入口 |

### 4.2 审核详情与创建信息核对（对应 [3.2](#m2)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-CM-06` 创建信息完整只读 | 七项创建信息按面客原值只读可见，项目期限为"生效日～到期日"；还款方式标平台定值、参考结算币种标只供参考；运营端无编辑、代改或代提交入口 |
| `AC-CM-07` 核对以创建快照为准 | P1 在审期间运营把最高质押率调低到 P1 锁定值以下：详情并列锁定值与当前值并标出差异；提交不被拦截、锁定值不变、不自动退回、不产生整改待办、不标违规；退回后重提的核对基准不变；当前配置不可读时标"待核实"且不阻断 |
| `AC-CM-08` 历史在操作记录中累积不覆盖 | P1 两次退回后通过：操作记录倒序可见三次提交、两条退回原因全文与一次部署成功；没有另一份审核历史列表；不覆盖、不改写既往结论 |
| `AC-CM-09` 操作记录事件与主体可辨 | 所列九类事件均可出现；"提交通过并发起部署"与"部署成功（即审核通过）"是两个事件；链上回写标"系统"、资产方动作标"资产方"，不伪造审核人；重复到达只留一条；加载中、无记录、读取失败可分辨 |
| `AC-CM-10` 缺失事实不猜测 | 主体标识缺失标"待核实"且不放行；部署 gas 或凭证缺失标"待核实"，不填 0、不造值 |

### 4.3 通过并部署合约（对应 [3.3](#m3)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-CM-11` 一次提交且提前告知后果 | 通过办理回显上下文并告知"部署成功即审核通过、一一对应、不可撤销"；提交后无第二步确认、无第二位审核人；取消不产生结论也不部署 |
| `AC-CM-12` 部署处理中不是结论 | 提交后两轴均为部署处理中、项目离开待审核统计；界面无"已通过"，面客仍为待审核且不能发起质押；处置入口不可用，重复或并发提交只成立一笔、不产生第二次部署 |
| `AC-CM-34` 部署处理中资产方不能关闭项目 | 提交通过后、部署结果回写前（含结果待核实），资产方关闭项目被拒，审核轴与项目都不变化；部署失败回到待审核后资产方可以关闭，关闭后本项目标"项目已关闭"、不可再次发起部署；运营提交通过与资产方关闭同时发生时只成立先生效的一笔 |
| `AC-CM-13` 部署成功即通过且地址唯一 | 部署成功后审核轴为已通过，审核人与结论时间（等于合约部署完成时间）可见；合约地址、质押链、部署凭证回写且与项目一一对应；面客项目可用（空池）可发起质押；人工审结加一；无再次部署入口 |
| `AC-CM-14` 通过终态且不产生额度 | 已通过项目不可撤销、不可改判、不可二次裁定；本模块不出现三项额度 |
| `AC-CM-15` 不签名、不付费、无钱包入口 | 通过办理不要求运营签名或付费；全平台无平台钱包的维护、配置、切换、余额或充值入口；绕过界面的写操作同样拒绝 |

<a id="limits"></a>
### 5.2 按用户决定保留的业务后果（供研发与测试知悉）

1. **通过不可撤销**：部署成功即产生合约，平台没有动作能撤销结论或销毁合约；创建信息有误只能另建项目。
2. **项目审核无时效**：待审项目可无限期停留；项目期限自创建起算，审核耗时实际占用项目有效期。
3. **部署失败对资产方不可见**：面客始终只见待审核、无任何消息；持续失败时资产方无法自行判断原因。
4. **平台钱包与 gas 充值不在本系统范围**：无余额展示、充值入口或余额告警；余额不足导致的失败只能如实展示原因，由建设方在系统外处理。
5. **部署处理中资产方不能关闭项目**：结果长期待核实时，资产方会一直看到待审核且无法关闭，只能等运营端回写结果。

第 3、4 条的入口是否补充仍在用户手上，本册按现行裁定执行。

### 5.4 后续衔接

开发主读第 2～3 章，测试主读第 4 章与消息通知第 4 节，三册共同阅读。设计重点：菜单名"项目合约管理"下的队列、详情、台账三个信息域；待审核统计与其子集；创建信息只读核对与锁定值并列；两条状态轴分开呈现（部署处理中不是结论，且资产方不能关闭）；部署失败与再次发起；结果待核实的保护态；退回原因的全文确认；已关闭项目的只读标记；台账只读边界。
