## 1. 模块是什么

资产方在面客端创建融资项目并提交审核后，运营管理员在本模块核对项目的创建信息，然后作出结论：**通过**或**退回**。合约不再按项目单独部署：同一代币类型、同一区块链网络下的所有项目，共用一套合约——质押合约、放款合约、还款合约各一份（用户 2026-10-21 裁定）。通过时，运营管理员按项目提交的代币类型和区块链网络，选定对应的三份合约并确认，由平台在链上为本项目完成配置，运营人员不需要钱包签名；**链上执行成功才算配置成功，配置成功即审核通过**。退回则把项目连同面客可读的原因交还资产方修改。本模块另有共用合约台账，只读查看各套合约及配置在上面的项目。项目审核与合约配置是同一件事的两面，所以本模块叫“项目合约管理”。

本模块只写运营端这一侧：运营人员看到什么、能做什么、做完之后两端各变成什么。创建信息各字段及其校验、项目状态与资产方看到的结果，由[融资需求与代币质押](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)定义，本册只读使用、不改写。该册现行正文仍按“一个项目一份质押合约、运营用平台统一钱包签名部署、部署成功即审核通过”书写；项目与合约的对应关系、合约配置的办理与结果以本册为准，各册差异列入[面客端及其他模块待同步（Q-CM-04）](#q-cm-04)。

审核对象（D-CM-03）：

- 审核对象是**一个融资项目**，不是代币，也不是批次；一个项目在审核队列中始终只有一条记录。
- 资产方首次提交与每次退回后的重新提交，各算一次“提交”，按发生时间编为第 1 次、第 2 次……；重新提交不产生新的项目编号。
- 每次提交至多一个有效结论：通过（成立条件是合约配置成功）或退回（必须有面客可读原因）。配置失败不是结论。
- 一个项目配置成功后绑定一套共用合约（质押、放款、还款各一份），绑定终身不变；同一套合约由同一代币类型、同一区块链网络下的多个项目共用。

基本原则：

- **合约按“代币类型＋区块链网络”共用。** 一个项目只能配置与自己代币类型、区块链网络都一致的那套合约；不为单个项目部署合约。
- **配置处理中不是结论。** 确认提交后到配置结果回写前，项目既不是“已通过”，也不能被再次裁定。
- **配置不需要钱包签名。** 运营人员选定合约并确认后，由平台在链上执行配置；运营人员不连接钱包、不签名、不付费（用户 2026-10-21 裁定）。
- **运营端只选用共用合约，不维护合约。** 每个适用组合的一套合约由开发人员在代码层面写好并维护，随版本发布；运营端只能查看和选用。每个组合同时只有一套在用，本期不提供更换（用户 2026-10-21 裁定）。
- **没有审核时限，但项目有有效期。** 项目可以一直待审，不会因等待自动通过、自动失败或被催办；只有到达项目的有效期至时，待审核或已退回的项目才会自动关闭。
- **结论只有通过与退回两种。** 没有驳回终结、作废、冻结或暂缓。
- **核对对象是资产方最近一次提交的那份信息。** 审核期间运营调整融资参数，不改变核对基准。

**一个完整的例子。** 甲企业的资产方创建融资项目 P1（区块链网络以太坊，代币类型 ERC-20-应收账款，项目质押率 70%，项目期限 2026-10-15～2027-04-15）并提交审核。运营管理员打开“项目合约管理”，在默认的待审核队列里看到 P1（第 1 次提交，已等待 2 小时），进入审核详情：创建信息八项只读展示，参数上下文显示该代币类型当前的最高质押率为 75%，与 P1 锁定的 70% 并列；“适用的共用合约”列出“ERC-20-应收账款＋以太坊”这一套下的质押合约、放款合约、还款合约。管理员线下核对后选择通过，逐类选定这三份合约，确认知悉“配置成功即审核通过，不可撤销”后提交，全程不需要连接钱包或签名。P1 进入配置处理中：队列中它离开待审核，详情不显示“已通过”，甲企业在面客端仍看到“待审核”，此时也不能关闭项目。几分钟后配置成功回写：P1 变为已通过，详情出现三份合约的地址与合约配置完成时间，操作记录先后有“提交通过并发起配置”和“配置成功（即审核通过）”两条；甲企业收到“融资项目审核通过”站内信，信中是这套质押合约的地址，甲企业在面客端看到项目可用，可以开始质押代币。共用合约台账中“ERC-20-应收账款＋以太坊”这一套的已配置项目增加 P1；此前已配置在这套合约上的乙企业项目 P0 不受影响。管理员返回队列，原来的筛选和页码保持不变。如果管理员当初选择退回，就要填写 10～500 字的原因，甲企业收到“融资项目审核退回”站内信，修改后重新提交，P1 以第 2 次提交回到队列。

<a id="out-of-scope"></a>
### 1.1 本期不做

- 运营人员为合约配置连接钱包或签名（用户 2026-10-21 裁定配置合约不需要钱包签名）；配置费用的展示、充值或余额告警。
- 运营端代资产方签名，或代资产方发起、撤销任何链上动作。
- 为单个项目部署专属合约。
- 在运营端部署、登记、修改、停用或删除共用合约（由开发人员在代码层面维护）；合约模板与代码、合约升级、暂停、销毁、迁移，链与网络配置，链上确认数设置。
- 同一组合同时启用多套合约；为已配置成功的项目更换合约、增加第二套合约或解除配置；人工录入或修改项目的合约地址。
- 放款与还款经合约执行的具体规则（归放款与放款确认、链上还款两个模块）。
- 批量审核、一键通过或退回、跨项目批量配置。
- 双人复核、审核与复核分离、转派或审批链。
- 第三种审核结论；任何审核时限、倒计时、催办、超时通知或超时统计。
- 运营端关闭项目、修改创建信息、代资产方重新提交、调整项目期限起算点。
- 代币类型、最高质押率、最长项目期限的配置（归[运营端融资参数配置](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md)）。
- 逐笔代币质押的查询与处置：代币质押由资产方签名、合约执行，不经运营审核，运营端不设逐笔质押入口（用户 2026-10-21 裁定）；总质押额、有效质押额的展示与计算。
- 风控评分、风险提示、建议结论或自动筛出不合格项目。
- 配置异常的处置系统：工单、异常待办、自动升级、人工改判或补记、强制回滚、补偿。
- 审核内部备注与审核附件。
- 企业账户（法币与数币账户）及结算收款链的任何信息。
- 发给运营人员的站内信。

<a id="terms"></a>
## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 共用合约 | 同一代币类型、同一区块链网络下所有融资项目共用的一套链上合约，由质押合约、放款合约、还款合约三份组成；由开发人员在代码层面写好并维护，随版本发布，每个组合同时只有一套在用（用户 2026-10-21 裁定） |
| 适用组合 | 一套共用合约服务的“代币类型＋区块链网络”。项目的适用组合取自其创建信息中的[代币类型（FP-29）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-29)与[区块链网络（FP-39）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-39) |
| 质押合约 | 共用合约中的一份，资产方把代币质押进这里；各项目的质押份额在同一份合约中分别归属本项目 |
| 放款合约、还款合约 | 共用合约中的另两份。后续放款、还款都通过合约执行（用户 2026-10-21 裁定），具体规则由放款与放款确认、链上还款两个模块定义；本模块只负责为项目选定并配置 |
| 合约配置 | 运营管理员为一个项目选定适用组合下的三份合约并确认，由平台在链上为本项目完成配置；运营人员不需要钱包签名。三份都在链上执行成功才算配置成功 |
| 质押链（区块链网络） | 共用合约所在的链，即资产方创建项目时选择的区块链网络，本期仅以太坊（ETH）；本模块各处统一以“区块链网络”展示。与企业账户使用的结算收款链是两回事 |
| 审核轴 | 运营端看到的项目审核进度：待审核、配置处理中、已通过、已退回 |
| 配置执行状态 | 合约配置的链上执行事实：未发起、配置处理中、配置成功、配置失败、结果待核实 |
| 提交序次 | 资产方对同一项目第几次提交审核；首次为第 1 次，每次退回后重提加一 |
| 人工审结 | 一次提交得出了结论（通过或退回）；配置失败不算 |
| 参数上下文 | 审核时并列展示的、该代币类型在融资参数配置中的当前最高质押率与最长项目期限，仅作背景参考 |

## 3. 通用规则：权限、时间与费用

适用于本模块全部功能。

**权限。** 按[权限组织方式（D-AL-07）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-07)，本模块定义以下两项权限，编号沿用原值：

| 权限项 | 覆盖的业务能力 |
| --- | --- |
| 融资项目审核查询（PM-AL-17） | 查看项目审核队列与统计、审核详情（含创建信息、参数上下文、适用的共用合约、操作记录）、共用合约台账；不含任何裁定动作 |
| 融资项目审核与合约配置处置（PM-AL-18） | 提交通过并发起合约配置、提交退回、配置失败后再次发起；必须同时具备融资项目审核查询（PM-AL-17），否则不能进入本流程 |

- 本期运营端只有运营管理员一个角色，固定具备上述两项（见[本期预置角色（D-AL-08）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-08)）。
- 只开通处置、缺少查询的交付配置，进入即被拒绝，并提示联系建设方修正配置。
- 其他权限项（如运营业务数据查询（PM-AL-13）、其他模块的查询权限）都不覆盖本模块，不能据此进入。
- 账号待首登改密、被锁定或登录失效后，此前已打开页面中的提交同样被拒绝，不产生结论、不发起配置。
- 任何权限都不提供：改已生效结论、改创建信息、代资产方发起或撤销链上动作、手工录入合约地址、维护共用合约、关闭项目、读取企业账户。
- 待审核与已退回的项目属资产方私有（[待审核项目的私有性（F-LS-12）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-12)）。运营端能看到它们来自功能权限，不改变其对游客和其他企业不可见。无权的入口不展示，也不泄露记录是否存在。

**时间与日期。**

- 近 7 个自然日统计、按日期筛选都按 UTC 日期计算，统计与日期条件上标注 UTC；具体时点按用户偏好时区显示并标注时区。切换时区、跨周末或夏令时不改变已发生的事实、统计归属或先后顺序。
- 没有审核时限：已等待时长只作事实陈述，不触发任何提醒，审核状态不因等待而改变；项目到达有效期至时的自动关闭见[待审核或已退回时到期自动关闭](#expiry)。
- 项目期限按[项目期限（FP-35）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-35)展示为“生效日～到期日”，生效日即项目创建日。本模块不决定也不改变起算点，审核耗时不延长项目有效期。

**费用。** 审核阶段资产方零费用；合约配置由平台执行，运营人员个人不付费。本模块不展示配置费用。

**反馈。** 加载中、无数据、筛选无结果、读取失败、无权限、提交中、配置处理中、结果待核实，各自有可辨认的呈现；读取失败可重试，不显示成 0 条；提交失败保留已填内容与已选合约；不同项目之间不串用已填原因或已选合约。

**界面说明的范围**（用户 2026-10-16 要求）：界面只保留办理所需的事实、限制原因与提交前的关键后果确认。本册写明的费用承担、已等待时长不是期限、信息只读等规则照常生效，但不作为常驻提示或重复说明展示。

<a id="states"></a>
## 4. 两条状态轴

一个项目同时有两条互相独立的状态：**审核轴**表示审核走到哪一步，**配置执行状态**表示链上配置的事实。另有一个叠加标记“项目已关闭”，来自资产方主动关闭，或待审核、已退回时到期自动关闭，关闭原因随之展示。项目状态的权威定义归[融资项目状态（ST-LS-01）](../../面客端/05-借贷广场-融资需求与代币质押/02-融资需求与代币质押-流程图与状态机.md#st-ls-01)，本册只读对应。

审核轴（必有，默认待审核）：

| 审核轴 | 资产方看到的项目状态 | 运营可做的动作 |
| --- | --- | --- |
| 待审核 | 待审核（S-FP-7） | 通过并配置合约、退回；没有截止 |
| 配置处理中 | 待审核（S-FP-7） | 无。不能重复发起、不能改判为退回；不推定成功或失败 |
| 已通过 | 可用（S-FP-1），尚无质押 | 无。结论终态，不可撤销、不可二次裁定 |
| 已退回 | 已退回（S-FP-8） | 无。等资产方修改重提后回到待审核 |

配置执行状态（必有，默认未发起）：未发起、配置处理中、配置成功、配置失败、结果待核实。

两条轴与“项目已关闭”的组合：

| 审核轴 | 配置执行状态 | 项目已关闭 | 运营看到与能做的 | 资产方能否关闭项目 |
| --- | --- | --- | --- | --- |
| 待审核 | 未发起 | 否 | 可通过或退回 | 可以 |
| 配置处理中 | 配置处理中 | 否 | 显示配置处理中，不显示“已通过”，无处置入口 | 不可以，见下方配置处理中资产方不能关闭项目（D-CM-21） |
| 配置处理中 | 结果待核实 | 否 | 显示结果待核实与已知凭证，无处置入口并说明原因 | 不可以，见下方配置处理中资产方不能关闭项目（D-CM-21） |
| 已通过 | 配置成功 | 否 | 显示所配置的三份合约与配置事实，无处置入口 | 按面客端可用状态的既有条件，与本模块无关 |
| 待审核 | 配置失败 | 否 | 显示失败原因，可再次发起配置或改为退回 | 可以 |
| 已退回 | 未发起 | 否 | 显示退回原因，无处置入口 | 可以 |
| 待审核 | 未发起 | 是 | 保留关闭前的审核轴，标“项目已关闭”及关闭原因（资产方主动关闭或有效期到期），只读，不可裁定 | 已关闭 |
| 待审核 | 配置失败 | 是 | 保留关闭前的审核轴，标“项目已关闭”及关闭原因（资产方主动关闭或有效期到期），只读，不可再次发起配置 | 已关闭 |
| 已退回 | 未发起 | 是 | 保留关闭前的审核轴，标“项目已关闭”及关闭原因（资产方主动关闭或有效期到期），只读 | 已关闭 |

<a id="d-cm-21"></a>
**配置处理中资产方不能关闭项目（D-CM-21）。** 用户 2026-10-14 裁定：审核轴为配置处理中（包括配置执行状态为结果待核实）时，资产方不能关闭项目；面客端规则见[部署进行中暂不可关闭（D-LS-71）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-71)，该条措辞待随[面客端及其他模块待同步（Q-CM-04）](#q-cm-04)改为合约配置。配置结果回写后按结果处理：配置成功则项目已通过，此后能否关闭按面客端可用状态的既有条件；配置失败则回到待审核，资产方可以关闭。

<a id="expiry"></a>
**待审核或已退回时到期自动关闭。** 用户 2026-10-16 裁定：

- 审核轴为待审核或已退回的项目，到达有效期至（到期判定同[项目状态与后续业务](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#project-state)）时自动关闭，关闭原因为“有效期到期”。项目离开默认审核队列、不再计入待审核统计，不能再裁定，也不能再次发起配置。
- 运营提交通过时项目已到期的，提交被拒并说明项目已到期，不产生结论、不发起配置。
- 配置处理中（含结果待核实）跨过有效期至的，不在此时关闭，等配置结果回写后处理：配置成功即审核通过，项目转为可用后，按可用状态的到期规则立即自动终结为已关闭（有效期到期）；配置失败则按第一条自动关闭，不可再次发起配置。
- 自动关闭不发送本模块的站内信。配置成功后立即终结的项目，仍按规则发送一条“融资项目审核通过”，资产方打开后看到项目的当前状态。
- 面客端规则见[待审核或已退回时到期自动关闭（D-LS-72）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-72)。

**项目与合约的对应。**

- 配置成功后，本项目绑定所选的质押、放款、还款三份合约，终身不变、只读；创建信息全部只读。
- 同一份合约可以对应多个项目，合约地址不再是项目的唯一标识；定位项目一律用项目编号。
- 各项目在同一份质押合约中的质押份额、额度与质押情况分别归属本项目，互不计入；面客端口径待[面客端及其他模块待同步（Q-CM-04）](#q-cm-04)。
- 一个项目的配置成功、失败或待核实，不改变同一套合约上其他项目的状态。

**运营端不代资产方动作。** 修改创建信息、重新提交、关闭项目都是资产方的动作，运营端没有对应入口；退回是运营端唯一能把项目交还资产方的方式。

流程参见：[项目审核轴（ST-CM-01）](./02-运营端项目合约管理-流程图与状态机.md#st-cm-01)、[合约配置执行状态（ST-CM-02）](./02-运营端项目合约管理-流程图与状态机.md#st-cm-02)。

## 5. 项目审核队列（F-CM-01～F-CM-05）

适用角色与前提：具备融资项目审核查询。队列是项目审核队列（P-O-CM-01），一条记录对应一个项目，退回重提后仍是同一条。

- 默认只列审核轴为待审核、且未关闭的项目，按本次提交时间从早到晚排列；时间相同时保持稳定顺序。不做风险优先排序。（F-CM-01）
- 每条记录展示：项目编号、项目名称、项目发布方、区块链网络、代币类型、项目质押率、项目期限（生效日～到期日）、本次提交时间与提交序次、已等待时长、审核轴、配置执行状态、是否已关闭；已通过的另展示所配置的质押合约地址。（F-CM-02）
- 可按以下条件组合筛选（F-CM-03）：
  - 审核轴：全部、待审核、配置处理中、已通过、已退回。
  - 配置执行状态：全部、未发起、配置处理中、配置成功、配置失败、结果待核实。
  - 项目发布方、代币类型、区块链网络。
  - 提交时间范围：起止都包含当天，起点不能晚于终点，否则就地提示。
  - 关键词：可匹配项目编号、项目名称、项目发布方名称、所配置的任一合约地址，忽略首尾空格；用合约地址检索时，列出配置在这份合约上的全部项目。
  - 重置后回到默认条件。
- 队列上方有两项统计（F-CM-04）：
  - **待审核项目数**：审核轴为待审核且未关闭的项目数，其中单独标出**配置失败待再次发起**的项目数；后者是前者的一部分，两者不相加。
  - **近 7 个自然日人工审结项目数**：结论时间落在近 7 个自然日内的通过与退回之和；配置失败不计入。
  - 统计跟随项目发布方、代币类型、区块链网络、提交时间与关键词条件变化，不跟随审核轴与配置执行状态筛选变化；完整的统计口径可展开查看。
- 可按本次提交时间、已等待时长升序或降序排列；带总数分页，每页条数沿用平台现行取值。筛选条件改变后回到第一页；从详情返回时保留筛选、排序和页码，原页已空时回到最后一个有内容的页并说明。（F-CM-05）
- 队列只用于查看，不提供逐条裁定或批量选择；进入详情才能办理。

## 6. 审核详情与创建信息核对（F-CM-06～F-CM-08）

适用角色与前提：具备融资项目审核查询。审核详情是项目审核详情（P-O-CM-02），可从队列或共用合约台账进入。

- 详情中性说明“本处信息供线下判定参考，结论由审核人线下作出后在此维护”；不提供评分、风险提示、建议结论或自动筛出。
- 详情始终能看到当前项目编号和提交序次，以下信息同处可得。（F-CM-06）

<a id="d-cm-17"></a>
**核对对象是提交时的快照（D-CM-17）。**

- 审核核对的是资产方最近一次提交（含退回重提）时的项目质押率与项目期限，审核期间运营调整参数不改变核对基准。退回重提时，项目质押率按重提当时的最高质押率重新校验，项目期限仍按创建时锁定的最长项目期限；合约配置成功后两者锁定终身。沿[生效与存量隔离（D-O-FC-03）](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#d-o-fc-03)中的“审核核对用快照”。
- 审核期间运营调高或调低参数配置，不改变在审项目的核对结论，也不改变退回后重提的核对基准，本身不构成退回理由。
- 锁定值与当前配置不一致时，如实并列并标出差异；不自动拦截提交、不改写锁定值、不自动退回、不产生整改待办，也不把项目标为违规。

**操作记录是唯一的进度与历史来源。** 本项目的全部事实只记在一条按发生时间倒序的操作记录里，不另设“审核历史”或第二套进度明细。（F-CM-07）

- 记录的事件共十类：提交审核、提交通过并发起配置、配置成功（即审核通过）、配置失败、结果待核实、再次发起配置、审核退回、资产方修改重提、资产方关闭项目、项目到期自动关闭。只记本项目的事实，同一套合约上其他项目的事件不进入本项目记录。
- 每条记录有真实发生时间与时区；时间缺失标“待核实”。
- 每条记录有主体：人工事件显示当时的审核人，资产方动作标“资产方”，链上结果回写与到期自动关闭标“系统”；主体缺失标“待核实”，不推定为审核人。
- 每条记录写明结果、前后状态与原因全文；配置相关事件附本次所选的三份合约地址与对应链上凭证，没有则说明暂无，不复用其他项目的凭证。
- 历次提交、结论、退回原因全文、审核人与时间、历次配置尝试及所选合约与结果都能从操作记录取得；摘要可收起，原因可展开全文。重新提交不覆盖以前的原因，也不把上一次结论改写为本次结论。
- 记录只读，不可编辑、删除或手工补完。

**往返与去重。** 同一事件重复到达只保留一条，新进度不覆盖以前的事实。从队列或台账进入详情只进入该项目；返回时保留来源页的筛选、排序、页码和所在位置。（F-CM-08）

## 7. 通过并配置合约（F-CM-09～F-CM-11）

适用角色与前提：具备处置权限；当前项目为待审核、未关闭、未到期，且不在配置处理中。

- 通过办理依次为：查看创建信息与上下文 → 选定本项目的三份合约 → 确认知悉“配置成功即审核通过，不可撤销”并提交。不需要连接钱包或签名（用户 2026-10-21 裁定），没有第二步确认，也不增加第二位审核人。

**选定合约**（用户 2026-10-21 裁定：按项目提交的代币类型和网络选择质押、放款、还款合约）：

- 候选只来自本项目适用组合在用的那套共用合约，按质押合约、放款合约、还款合约三类分别列出；代币类型或区块链网络与本项目不一致的合约不出现在候选中，也不能通过其他方式选入。
- 三类各选定一份，缺任一类都不能提交。
- 适用组合下任一类合约在代码中尚未提供时，不能通过，就地说明缺少哪一类；处置人可以改为退回或稍后办理，项目仍为待审核，不产生结论。
- 确认时展示所选三份合约的类别、地址与适用组合，供提交前核对。

**提交与结果：**

- 取消不产生结论、不发起配置。提交中有明确反馈，不能重复提交。（F-CM-09）
- 提交生效时权限或状态已变化（项目已关闭、已到期、已被他人裁定、已在配置处理中），就地说明并拒绝，不产生结论、不发起配置。
- 运营提交通过与资产方关闭项目同时发生时，只成立先生效的一笔：关闭先生效，则本次通过被拒；通过先生效，则项目进入配置处理中，资产方的关闭被拒（见[配置处理中资产方不能关闭项目（D-CM-21）](#d-cm-21)）。
- 提交成功即结束本次办理并回到详情：审核轴与配置执行状态都变为配置处理中，操作记录新增“提交通过并发起配置”，该项目离开待审核统计。此时尚未形成结论：界面不出现“已通过”，资产方仍看到待审核且不能发起质押；处置入口不可用；同时提交多次只成立一笔。（F-CM-10）
- **配置成功即审核通过**：所选三份合约都在链上执行成功，才算配置成功。回写三份合约的配置事实；审核轴变为已通过，记录审核人（提交本次通过的运营管理员）与结论时间（即合约配置完成时间）；人工审结数加一；资产方的项目变为可用、尚无质押，可以向所配置的质押合约发起代币质押；本项目计入共用合约台账中对应一套的已配置项目。结论终态：不可撤销、不可改判为退回、不可更换合约。（F-CM-11）
- 审核通过不改创建信息、不改代币事实，本身不产生任何质押额，也不改变同一套合约上其他项目的任何状态或额度。

通知：配置成功时，向创建该项目的资产方发送[融资项目审核通过](./03-运营端项目合约管理-消息通知.md#notice-rules)。
流程参见：[项目审核与合约配置（FL-CM-01）](./02-运营端项目合约管理-流程图与状态机.md#fl-cm-01)。

## 8. 退回（F-CM-12～F-CM-13）

适用角色与前提：同[通过并配置合约](#m3)。

- 办理入口与结论在运营端统一称“退回”（不称“退回资产方”）；界面上把创建该项目的资产方称为申请方，把本次提交称为申请（用户 2026-10-16 要求）。
- 退回办理依次为：填写退回原因 → 全文预览并再次确认 → 提交。退回不选合约、不发起配置。（F-CM-12）
- 退回原因必填，10～500 字（沿本平台审核驳回原因的现行校验）；空白、仅空格或超长不能提交。原因即[审核退回原因（FP-37）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-37)，原样进入面客端与站内信，因此不得写入内部代号、内部备注或本项目以外的信息；提交后不可编辑或删除。（F-CM-13）
- 一次提交至多一个有效结论；两人同时裁定只成立一笔，后到的一方被告知已有结论并看到现状，原因不被覆盖。
- 退回后审核轴变为已退回，人工审结数加一。资产方能否重提、重提时的校验，由面客端[创建信息](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#create)判定；重提后项目以新的提交序次回到待审核与队列，项目编号不变，项目期限不重新起算。重提时资产方改了代币类型的，适用组合随之改变，候选合约按新的代币类型列出。
- 退回次数不设上限；平台不自动终结、不自动通过、不限制重提次数。
- 取消不产生结论，不同项目之间不携带原因；保存失败保留已填原因可重试；结果不确定时先查当前事实，不显示成功、不引导重复裁定。

通知：退回生效时，向创建该项目的资产方发送[融资项目审核退回](./03-运营端项目合约管理-消息通知.md#notice-rules)。

## 9. 配置失败、结果待核实与再次发起（F-CM-14～F-CM-15）

适用角色与前提：合约配置已发起；再次发起须具备处置权限。

- 配置失败与结果待核实都**不是结论**：不要求资产方重新提交，不改变项目期限起算点，不产生第二个项目，不影响同一套合约上的其他项目，也不向资产方发送任何消息——资产方始终只看到待审核。
- **配置失败**（链上执行明确失败；三份合约中只要有一份没有执行成功，就算配置失败）：审核轴回到待审核，计入“配置失败待再次发起”。详情展示配置失败原因（仅运营端可读的失败事实原文，不进入面客端、站内信或退回原因）、失败时点、三份合约各自的执行结果（未知标“待核实”）。处置人可以再次发起配置，也可以改为退回。（F-CM-14）
- **再次发起**：按[通过并配置合约](#m3)同样的规则选定三份合约并确认提交，不需要钱包签名；沿用同一项目编号与同一次提交，形成新的配置尝试并进入配置处理中；历次尝试、所选合约与结果都留在操作记录。次数不设上限；平台不自动重试、不自动退回、不自动通过。本项目以最终配置成功那次所选的三份合约为准。（F-CM-15）
- **结果待核实**（长期没有确定结果，或事实冲突）：标“待核实”并保留已知凭证与事实；不推定成功或失败，不重复发起，不自动改判或回滚；处置入口不可用并说明原因。真实结果回写后，按成功或失败继续（见[依赖](#dependencies)中的配置结果回写）。
- 本期不提供工单、升级、人工改判或补记、强制回滚、补偿或手工录入合约地址；无法自行处理时，联系建设方核实链上与配置，产品内不编造处理时限。

流程参见：[配置失败、结果待核实与再次发起（FL-CM-02）](./02-运营端项目合约管理-流程图与状态机.md#fl-cm-02)。

## 10. 共用合约台账（F-CM-16～F-CM-17）

适用角色与前提：具备融资项目审核查询。台账是共用合约台账（P-O-CM-03），只读。

- 一条记录对应一套共用合约，即一个适用组合（代币类型＋区块链网络）。（F-CM-16）
- 每条记录展示：代币类型、区块链网络、质押合约地址、放款合约地址、还款合约地址、已配置项目数（配置成功的项目）。某一类在代码中尚未提供时标“暂无”，并说明该组合下的项目暂时不能通过。
- 可按代币类型、区块链网络、关键词（任一合约地址）筛选；分页与返回规则与[项目审核队列](#m1)相同。
- 合约地址可复制完整值；平台不声称地址在链上的当前状态。台账没有登记、编辑、停用、更换或解除配置等业务动作（合约由开发人员在代码层面维护），也不展示逐笔质押、额度或质押情况。
- 从一套合约可查看配置在它上面的项目：项目编号、项目名称、项目发布方、合约配置完成时间、审核人、项目当前状态（按面客端项目状态展示），默认按合约配置完成时间从晚到早排列，可升降序。未配置成功的项目（含配置处理中、配置失败、结果待核实）不在其中。（F-CM-17）
- 从项目可进入该项目的审核详情，返回时保留台账原来的筛选、排序与页码。

### 12.2 按用户决定保留的业务后果

供研发与测试知悉，不判为缺陷：

1. 通过不可撤销：配置成功即绑定合约，平台没有动作能撤销结论、更换合约或解除配置；创建信息有误只能另建项目。
2. 项目审核没有时限：待审项目可以无限期停留；项目期限自创建起算，审核耗时实际占用项目有效期。
3. 配置失败对资产方不可见：资产方始终只看到待审核、收不到消息；持续失败时资产方无法自行判断原因。
4. 配置处理中资产方不能关闭项目：结果长期待核实时，资产方会一直看到待审核且无法关闭，只能等运营端回写结果。
5. 待审核或已退回的项目到期自动关闭：审核没有时限，如果运营在有效期至之前没有作出结论，项目会被自动关闭，资产方只能另建项目。
6. 合约按组合共用：一套合约出现问题时，影响该代币类型与区块链网络下全部已配置项目；本期没有为已配置项目更换或迁移合约的能力。某组合缺少任一类合约时，该组合下的项目都不能通过，只能等开发人员在代码中补齐并发版。

### 12.3 依赖

- 融资需求与代币质押提供创建信息、项目状态和面客端结果；本模块产生的“项目已通过审核并完成合约配置”是资产方发起代币质押的前提；质押由资产方签名、合约执行，上链成功即质押成功，不再经过运营端。该模块的合约口径待[面客端及其他模块待同步（Q-CM-04）](#q-cm-04)。
- 运营端融资参数配置提供参数上下文的当前值；读不到时标“待核实”，不阻断审核。代币类型的取值域也来自该模块，新增代币类型后须有对应的一套共用合约，该类型的项目才能通过。
- 运营端账户与登录提供账号、会话与角色。
- **共用合约提供**（用户 2026-10-21 裁定）：每个适用组合的三份合约由开发人员在代码层面写好并维护，随版本发布；本模块据此列出候选。新增代币类型或网络时，须先由开发人员补齐对应的一套合约。
- **配置结果回写**：成功回写三份合约的配置凭证与完成时间、失败回写原因与各份合约的执行结果、长期没有结果标“结果待核实”。回写缺失时只停留在配置处理中或结果待核实，不推定结论；需联调验证。
- **企业主体对应**（用户 2026-10-16 确认）：跨平台企业主体须稳定对应，不能只用名称匹配；主体标识缺失时不能通过；需联调验证真实归属与访问范围。
- 共用合约的代码、部署与维护，平台在链上为项目执行配置的方式与所需权限（运营人员不签名），同一份质押合约内各项目份额分别归属的能力，配置失败后再次发起能完成三份合约的整体配置，链与网络配置，链上确认数，由研发负责；链上确认数决定“配置成功”的判定时点，提测前须明确。实现与验证归研发、测试。
