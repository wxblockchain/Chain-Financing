## 1. 模块是什么

资产方在面客端创建融资项目并提交审核后，运营管理员在本模块核对项目的创建信息，然后作出结论：**通过**或**退回**。通过不是点一下就结束——提交通过即由平台统一钱包发起本项目质押合约的部署，**部署成功才算审核通过**，同时产生本项目唯一的质押合约地址；退回则把项目连同面客可读的原因交还资产方修改。已部署的合约在本模块的质押合约台账中只读可查。项目审核与质押合约是同一件事的两面，所以本模块叫“项目合约管理”。

本模块只写运营端这一侧：运营人员看到什么、能做什么、做完之后两端各变成什么。项目审核的业务判定（[项目审核（F-LS-22）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-22)）、创建信息各字段及其校验、项目状态与资产方看到的结果，由[融资需求与代币质押](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)定义，本册只读使用、不改写；两册不一致时以该册为准，差异列入[待确认事项](#open-items)。

审核对象（D-CM-03）：

- 审核对象是**一个融资项目**，不是代币，也不是批次；一个项目在审核队列中始终只有一条记录。
- 资产方首次提交与每次退回后的重新提交，各算一次“提交”，按发生时间编为第 1 次、第 2 次……；重新提交不产生新的项目编号。
- 每次提交至多一个有效结论：通过（成立条件是合约部署成功）或退回（必须有面客可读原因）。签名或部署失败不是结论。
- 一个项目只部署一份质押合约，项目与合约一一对应、终身不变。

基本原则：

- **部署处理中不是结论。** 提交通过后到部署结果回写前，项目既不是“已通过”，也不能被再次裁定。
- **运营人员不签名、不付费。** 部署由平台统一钱包发起，gas 由管理端承担；运营人员只做业务操作。
- **没有任何审核时限。** 项目可以一直待审，不会因时间流逝自动通过、自动失败或被催办。
- **结论只有通过与退回两种。** 没有驳回终结、作废、冻结或暂缓。
- **核对对象是资产方提交时锁定的那份信息。** 运营此后调整融资参数，不改变核对基准。

**一个完整的例子。** 甲企业的资产方创建融资项目 P1（代币类型 ERC-20-应收账款，项目质押率 70%，项目期限 2026-10-15～2027-04-15）并提交审核。运营管理员打开“项目合约管理”，在默认的待审核队列里看到 P1（第 1 次提交，已等待 2 小时），进入审核详情：创建信息八项只读展示（区块链网络为以太坊），参数上下文显示该代币类型当前的最高质押率为 75%，与 P1 锁定的 70% 并列。管理员线下核对后选择通过，确认知悉“提交后由平台统一钱包部署质押合约，部署成功即审核通过，不可撤销”，提交。P1 进入部署处理中：队列中它离开待审核，详情不显示“已通过”，甲企业在面客端仍看到“待审核”，此时也不能关闭项目。几分钟后部署成功回写：P1 变为已通过，详情出现质押合约地址与合约部署完成时间，操作记录先后有“提交通过并发起部署”和“部署成功（即审核通过）”两条；甲企业收到“融资项目审核通过”站内信，在面客端看到项目可用，可以开始质押代币；P1 同时出现在质押合约台账。管理员返回队列，原来的筛选和页码保持不变。如果管理员当初选择退回，就要填写 10～500 字的原因，甲企业收到“融资项目审核退回”站内信，修改后重新提交，P1 以第 2 次提交回到队列。

### 1.1 本期不做

- 平台统一钱包的维护、配置、切换或多钱包管理；钱包余额展示、gas 充值或余额告警（另见待确认 [Q-CM-10](#q-cm-10)）。
- 运营端在项目审核中签名、代签、代付 gas，或代资产方发起、撤销任何链上动作。
- 合约模板与代码、合约升级、暂停、销毁、迁移，链与网络配置，部署确认数设置。
- 人工录入、修改或解绑质押合约地址；为同一项目部署第二份合约。
- 批量审核、一键通过或退回、跨项目批量部署。
- 双人复核、审核与复核分离、转派或审批链。
- 第三种审核结论；任何审核时限、倒计时、催办、超时通知或超时统计。
- 运营端关闭项目、修改创建信息、代资产方重新提交、调整项目期限起算点。
- 代币类型、最高质押率、最长项目期限的配置（归[运营端融资参数配置](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md)）。
- 逐笔代币质押的查询与处置（归[代币质押审核](../06-代币质押审核/01-代币质押审核-PRD.md)）；总质押额、待审质押额、有效质押额的展示与计算。
- 风控评分、风险提示、建议结论或自动筛出不合格项目。
- 部署异常的处置系统：工单、异常待办、自动升级、人工改判或补记、强制回滚、补偿。
- 审核内部备注与审核附件。
- 企业账户（法币与数币账户）及结算收款链的任何信息。
- 发给运营人员的站内信。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 平台统一钱包 | 部署所有项目质押合约的唯一发起方。取值在代码层面维护、随版本发布，面客端与运营端都没有维护、配置或切换入口（另见待确认 [Q-CM-10](#q-cm-10)） |
| 质押合约 | 部署成功时产生的、属于一个融资项目的链上合约，资产方此后把代币质押进这里 |
| 质押链 | 质押合约所在的链，本期仅 ETH。与企业账户使用的结算收款链是两回事 |
| 审核轴 | 运营端看到的项目审核进度：待审核、部署处理中、已通过、已退回 |
| 部署执行状态 | 合约部署的链上执行事实：未发起、部署处理中、部署成功、部署失败、结果待核实 |
| 提交序次 | 资产方对同一项目第几次提交审核；首次为第 1 次，每次退回后重提加一 |
| 人工审结 | 一次提交得出了结论（通过或退回）；部署失败不算 |
| 参数上下文 | 审核时并列展示的、该代币类型在融资参数配置中的当前最高质押率与最长项目期限，仅作背景参考 |

## 3. 通用规则：权限、时间与费用

适用于本模块全部功能。

**权限。** 按[运营端账户与登录](../01-运营端账户与登录/01-运营端账户与登录-PRD.md)执行，本模块不新增授权管理，使用两项已登记的权限：

| 权限项 | 覆盖的业务能力 |
| --- | --- |
| 融资项目审核查询（PM-AL-17） | 查看项目审核队列与统计、审核详情（含创建信息、参数上下文、操作记录）、质押合约台账；不含任何裁定动作 |
| 融资项目审核与合约部署处置（PM-AL-18） | 提交通过并发起部署、提交退回、部署失败后再次发起；必须同时具备融资项目审核查询，否则不能进入本流程 |

- 本期运营端只有运营管理员一个角色，固定具备上述两项（该册[本期预置角色（D-AL-08）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-08)）。
- 交付配置开通了处置却缺查询时，进入即被拒绝，提示联系建设方修正配置；组合规则见该册[本批新增权限项的组合与边界（D-AL-35）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-35)。
- 运营业务数据查询（PM-AL-13）、代币质押申请查询（PM-AL-07）都不覆盖本模块，不能据此进入。
- 账号待首登改密、被锁定或登录失效后，此前已打开页面中的提交同样被拒绝，不产生结论、不发起部署。
- 任何权限都不提供：改已生效结论、改创建信息、签名、发起或撤销链上动作、手工录入合约地址、平台钱包维护、关闭项目、读取企业账户。
- 待审核与已退回的项目属资产方私有（[待审核项目的私有性（F-LS-12）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-12)）。运营端能看到它们来自功能权限，不改变其对游客和其他企业不可见。无权的入口不展示，也不泄露记录是否存在。

**时间与日期。**

- 近 7 个自然日统计、按日期筛选都按 UTC 日期计算，并让操作者能看出是 UTC 口径；具体时点按用户偏好时区显示并标注时区。切换时区、跨周末或夏令时不改变已发生的事实、统计归属或先后顺序。
- 没有审核时限：已等待时长只作事实陈述，不触发任何提醒，状态不因时间流逝改变。
- 项目期限按[项目期限（FP-35）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-35)展示为“生效日～到期日”，生效日即项目创建日。本模块不决定也不改变起算点，审核耗时不延长项目有效期。

**费用。** 审核阶段资产方零费用。部署 gas 按真实币种如实展示；未知时标“待核实”，不填 0，不编造精度。

**反馈。** 加载中、无数据、筛选无结果、读取失败、无权限、提交中、部署处理中、结果待核实，各自有可辨认的呈现；读取失败可重试，不显示成 0 条；提交失败保留已填内容；不同项目之间不串用已填原因。

## 4. 两条状态轴

一个项目同时有两条互相独立的状态：**审核轴**表示审核走到哪一步，**部署执行状态**表示链上部署的事实。另有一个叠加标记“项目已关闭”，来自资产方的关闭动作。项目状态的权威定义归[融资项目状态（ST-LS-01）](../../面客端/05-借贷广场-融资需求与代币质押/02-融资需求与代币质押-流程图与状态机.md#st-ls-01)，本册只读对应。

审核轴（必有，默认待审核）：

| 审核轴 | 资产方看到的项目状态 | 运营可做的动作 |
| --- | --- | --- |
| 待审核 | 待审核（S-FP-7） | 通过并部署、退回；没有截止 |
| 部署处理中 | 待审核（S-FP-7） | 无。不能重复发起、不能改判为退回；不推定成功或失败 |
| 已通过 | 可用（S-FP-1），尚无质押 | 无。结论终态，不可撤销、不可二次裁定 |
| 已退回 | 已退回（S-FP-8） | 无。等资产方修改重提后回到待审核 |

部署执行状态（必有，默认未发起）：未发起、部署处理中、部署成功、部署失败、结果待核实。

两条轴与“项目已关闭”的组合：

| 审核轴 | 部署执行状态 | 项目已关闭 | 运营看到与能做的 | 资产方能否关闭项目 |
| --- | --- | --- | --- | --- |
| 待审核 | 未发起 | 否 | 可通过或退回 | 可以 |
| 部署处理中 | 部署处理中 | 否 | 显示部署处理中，不显示“已通过”，无处置入口 | 不可以，见下方部署处理中资产方不能关闭项目（D-CM-21） |
| 部署处理中 | 结果待核实 | 否 | 显示结果待核实与已知凭证，无处置入口并说明原因 | 不可以，见下方部署处理中资产方不能关闭项目（D-CM-21） |
| 已通过 | 部署成功 | 否 | 显示合约地址与部署事实，无处置入口 | 按面客端可用状态的既有条件，与本模块无关 |
| 待审核 | 部署失败 | 否 | 显示失败原因，可再次发起部署或改为退回 | 可以 |
| 已退回 | 未发起 | 否 | 显示退回原因，无处置入口 | 可以 |
| 待审核 | 未发起 | 是 | 保留关闭前的审核轴并标“项目已关闭”，只读，不可裁定 | 已关闭 |
| 待审核 | 部署失败 | 是 | 保留关闭前的审核轴并标“项目已关闭”，只读，不可再次发起部署 | 已关闭 |
| 已退回 | 未发起 | 是 | 保留关闭前的审核轴并标“项目已关闭”，只读 | 已关闭 |

<a id="d-cm-21"></a>
**部署处理中资产方不能关闭项目（D-CM-21）。** 用户 2026-10-14 裁定：审核轴为部署处理中（包括部署执行状态为结果待核实）时，资产方不能关闭项目；面客端规则见[部署进行中暂不可关闭（D-LS-71）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-71)。部署结果回写后按结果处理：部署成功则项目已通过，此后能否关闭按面客端可用状态的既有条件；部署失败则回到待审核，资产方可以关闭。

**项目与合约一一对应。** 部署成功产生的质押合约地址全局唯一、与项目一一对应、终身不变、只读。部署成功后创建信息全部只读。

**运营端不代资产方动作。** 修改创建信息、重新提交、关闭项目都是资产方的动作，运营端没有对应入口；退回是运营端唯一能把项目交还资产方的方式。

流程参见：[项目审核轴（ST-CM-01）](./02-运营端项目合约管理-流程图与状态机.md#st-cm-01)、[合约部署执行状态（ST-CM-02）](./02-运营端项目合约管理-流程图与状态机.md#st-cm-02)。

## 5. 项目审核队列（F-CM-01～F-CM-05）

适用角色与前提：具备融资项目审核查询。队列是项目审核队列（P-O-CM-01），一条记录对应一个项目，退回重提后仍是同一条。

- 默认只列审核轴为待审核、且未关闭的项目，按本次提交时间从早到晚排列；时间相同时保持稳定顺序。不做风险优先排序。（F-CM-01）
- 每条记录展示：项目编号、项目名称、项目发布方、代币类型、项目质押率、项目期限（生效日～到期日）、本次提交时间与提交序次、已等待时长、审核轴、部署执行状态、是否已关闭；已通过的另展示质押合约地址。（F-CM-02）
- 可按以下条件组合筛选（F-CM-03）：
  - 审核轴：全部、待审核、部署处理中、已通过、已退回。
  - 部署执行状态：全部、未发起、部署处理中、部署成功、部署失败、结果待核实。
  - 项目发布方、代币类型。
  - 提交时间范围：起止都包含当天，起点不能晚于终点，否则就地提示。
  - 关键词：可匹配项目编号、项目名称、项目发布方名称、质押合约地址，忽略首尾空格。
  - 重置后回到默认条件。
- 队列上方有两项统计（F-CM-04）：
  - **待审核项目数**：审核轴为待审核且未关闭的项目数，其中单独标出**部署失败待再次发起**的项目数；后者是前者的一部分，两者不相加。
  - **近 7 个自然日人工审结项目数**：结论时间落在近 7 个自然日内的通过与退回之和；部署失败不计入。
  - 统计跟随项目发布方、代币类型、提交时间与关键词条件变化，不跟随审核轴与部署执行状态筛选变化，并标明统计范围。
- 可按本次提交时间、已等待时长升序或降序排列；带总数分页，每页条数沿用平台现行取值。筛选条件改变后回到第一页；从详情返回时保留筛选、排序和页码，原页已空时回到最后一个有内容的页并说明。（F-CM-05）
- 队列只用于查看，不提供逐条裁定或批量选择；进入详情才能办理。

流程参见：[项目审核与合约部署（FL-CM-01）](./02-运营端项目合约管理-流程图与状态机.md#fl-cm-01)。

## 6. 审核详情与创建信息核对（F-CM-06～F-CM-08）

适用角色与前提：具备融资项目审核查询。审核详情是项目审核详情（P-O-CM-02），可从队列或质押合约台账进入。

- 详情中性说明“本处信息供线下判定参考，结论由审核人线下作出后在此维护”；不提供评分、风险提示、建议结论或自动筛出。
- 详情始终能看到当前项目编号和提交序次，以下信息同处可得。（F-CM-06）

<a id="d-cm-17"></a>
**核对对象是提交时的快照（D-CM-17）。**

- 审核核对的是资产方最近一次提交（含退回重提）时的项目质押率与项目期限，审核期间运营调整参数不改变核对基准。退回重提时，项目质押率按重提当时的最高质押率重新校验，项目期限仍按创建时锁定的最长项目期限；合约部署后两者锁定终身。沿[生效与存量隔离（D-O-FC-03）](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#d-o-fc-03)中的“审核核对用快照”。
- 审核期间运营调高或调低参数配置，不改变在审项目的核对结论，也不改变退回后重提的核对基准，本身不构成退回理由。
- 锁定值与当前配置不一致时，如实并列并标出差异；不自动拦截提交、不改写锁定值、不自动退回、不产生整改待办，也不把项目标为违规。

**操作记录是唯一的进度与历史来源。** 本项目的全部事实只记在一条按发生时间倒序的操作记录里，不另设“审核历史”或第二套进度明细。（F-CM-07）

- 记录的事件：提交审核、提交通过并发起部署、部署成功（即审核通过）、部署失败、结果待核实、再次发起部署、审核退回、资产方修改重提、资产方关闭项目。只记本项目的事实。
- 每条记录有真实发生时间与时区；时间缺失标“待核实”。
- 每条记录有主体：人工事件显示当时的审核人，资产方动作标“资产方”，链上结果回写标“系统”；主体缺失标“待核实”，不推定为审核人。
- 每条记录写明结果、前后状态与原因全文；部署相关事件附对应的链上凭证与合约地址，没有则说明暂无，不复用其他项目的凭证。
- 历次提交、结论、退回原因全文、审核人与时间、历次部署尝试与结果都能从操作记录取得；摘要可收起，原因可展开全文。重新提交不覆盖以前的原因，也不把上一次结论改写为本次结论。
- 记录只读，不可编辑、删除或手工补完。

**往返与去重。** 同一事件重复到达只保留一条，新进度不覆盖以前的事实。从队列或台账进入详情只进入该项目；返回时保留来源页的筛选、排序、页码和所在位置。（F-CM-08）

## 7. 通过并部署合约（F-CM-09～F-CM-11）

适用角色与前提：具备处置权限；当前项目为待审核、未关闭、且不在部署处理中。没有截止条件。

- 通过办理依次为：查看创建信息与上下文 → 确认知悉“提交后由平台统一钱包发起本项目质押合约部署；部署成功即审核通过，项目与合约一一对应，不可撤销” → 提交。提交即发起部署，运营人员不签名、不付费；没有第二步确认，也不增加第二位审核人。
- 取消不产生结论、不发起部署。提交中有明确反馈，不能重复提交。（F-CM-09）
- 提交生效时权限或状态已变化（项目已关闭、已被他人裁定、已在部署处理中），就地说明并拒绝，不产生结论、不发起部署。
- 运营提交通过与资产方关闭项目同时发生时，只成立先生效的一笔：关闭先生效，则本次通过被拒；通过先生效，则项目进入部署处理中，资产方的关闭被拒（见[部署处理中资产方不能关闭项目（D-CM-21）](#d-cm-21)）。
- 提交成功即结束本次办理并回到详情：审核轴与部署执行状态都变为部署处理中，操作记录新增“提交通过并发起部署”，该项目离开待审核统计。此时尚未形成结论：界面不出现“已通过”，资产方仍看到待审核且不能发起质押；处置入口不可用；同时提交多次只成立一笔。（F-CM-10）
- **部署成功即审核通过**：回写质押合约地址与部署链上事实；审核轴变为已通过，记录审核人（提交通过的运营管理员）与结论时间（即合约部署完成时间）；人工审结数加一；资产方的项目变为可用、尚无质押，可以发起代币质押。结论终态：不可撤销、不可改判为退回、不再部署第二份合约。（F-CM-11）
- 审核通过不改创建信息、不改代币事实，本身不产生任何质押额。

通知：部署成功时，向创建该项目的资产方发送[融资项目审核通过](./03-运营端项目合约管理-消息通知.md#notice-rules)。
流程参见：[项目审核与合约部署（FL-CM-01）](./02-运营端项目合约管理-流程图与状态机.md#fl-cm-01)。

## 8. 退回（F-CM-12～F-CM-13）

适用角色与前提：同[通过并部署合约](#m3)。

- 退回办理依次为：填写退回原因 → 全文预览并再次确认 → 提交。退回不发起部署、不产生合约地址、不消耗 gas。（F-CM-12）
- 退回原因必填，10～500 字（沿本平台审核驳回原因的现行校验）；空白、仅空格或超长不能提交。原因即[审核退回原因（FP-37）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-37)，原样进入面客端与站内信，因此不得写入内部代号、内部备注或本项目以外的信息；提交后不可编辑或删除。（F-CM-13）
- 一次提交至多一个有效结论；两人同时裁定只成立一笔，后到的一方被告知已有结论并看到现状，原因不被覆盖。
- 退回后审核轴变为已退回，人工审结数加一。资产方能否重提、重提时的校验，由面客端[创建信息](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#create)判定；重提后项目以新的提交序次回到待审核与队列，项目编号不变，项目期限不重新起算。
- 退回次数不设上限；平台不自动终结、不自动通过、不限制重提次数。
- 取消不产生结论，不同项目之间不携带原因；保存失败保留已填原因可重试；结果不确定时先查当前事实，不显示成功、不引导重复裁定。

通知：退回生效时，向创建该项目的资产方发送[融资项目审核退回](./03-运营端项目合约管理-消息通知.md#notice-rules)。

## 9. 部署失败、结果待核实与再次发起（F-CM-14～F-CM-15）

适用角色与前提：部署已发起；再次发起须具备处置权限。

- 部署失败与结果待核实都**不是结论**：不要求资产方重新提交，不改变项目期限起算点，不产生第二个项目或第二份合约，也不向资产方发送任何消息——资产方始终只看到待审核。
- **部署失败**（签名或部署明确失败）：审核轴回到待审核，计入“部署失败待再次发起”。详情展示部署失败原因（仅运营端可读的失败事实原文，不进入面客端、站内信或退回原因）、失败时点与已消耗 gas（未知标“待核实”）。处置人可以再次发起部署，也可以改为退回。（F-CM-14）
- **再次发起**：沿用同一项目编号与同一次提交，形成新的部署尝试并进入部署处理中；历次尝试与结果都留在操作记录。次数不设上限；平台不自动重试、不自动退回、不自动通过。（F-CM-15）
- **结果待核实**（长期没有确定结果，或事实冲突）：标“待核实”并保留已知凭证与事实；不推定成功或失败，不重复发起，不自动改判或回滚；处置入口不可用并说明原因。真实结果回写后，按成功或失败继续（[Q-CM-02](#q-cm-02)）。
- 本期不提供工单、升级、人工改判或补记、强制回滚、补偿或手工录入合约地址；无法自行处理时，联系建设方核实链上与配置，产品内不编造处理时限。

流程参见：[部署失败、结果待核实与再次发起（FL-CM-02）](./02-运营端项目合约管理-流程图与状态机.md#fl-cm-02)。

## 10. 质押合约台账（F-CM-16～F-CM-17）

适用角色与前提：具备融资项目审核查询。台账是质押合约台账（P-O-CM-03）。

- 一条记录对应一个**已部署成功**的项目及其唯一合约；未部署成功的项目不出现。（F-CM-16）
- 每条记录展示：项目编号、项目名称、项目发布方、代币类型、质押合约地址、质押链、合约部署完成时间、审核人、项目当前状态（按面客端项目状态展示）。
- 可按项目发布方、代币类型、合约部署完成时间范围、关键词（项目编号、项目名称、合约地址）筛选；默认按合约部署完成时间从晚到早排列，可升降序；分页与返回规则与[项目审核队列](#m1)相同。
- 合约地址可复制完整值；平台不声称地址在链上的当前状态。台账没有编辑、解绑、重新部署等业务动作，也不展示逐笔质押、额度或质押情况。
- 从一条记录可进入该项目的审核详情，返回时保留台账原来的筛选、排序与页码。（F-CM-17）

## 11. 留痕与通知（F-CM-18～F-CM-19）

- [操作记录](#m2)所列事件全部留痕，关联项目与提交序次，包含时间、主体、前后状态、原因与凭据；不可编辑删除，重新提交不覆盖旧结论，同一事件不重复记录。（F-CM-18）

| <a id="q-cm-11"></a>Q-CM-11 | **合约部署是否也改为运营连接钱包签名。** 若平台地址的私钥由运营人员通过钱包持有，部署合约同样需要该地址签名，那么“提交通过即由平台统一钱包发起部署、运营人员不签名”就要改为运营连接钱包签名部署。推荐：与解冻授权统一为运营连接配置地址的钱包签名，签名取消或地址不符时不发起部署；部署成功即审核通过的口径不变 | 裁定前，本册按“运营人员不签名、提交即发起部署”编写。若改，影响[通过并部署合约](#m3)、[部署失败与再次发起](#m5)及面客端[项目审核（F-LS-22）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-22)中“运营人员不签名”的表述 |
| <a id="q-cm-02"></a>Q-CM-02 | 部署结果的真实回写能力：成功回写地址与凭证、失败回写原因、长期无结果标待核实 | 回写缺失时只能停留在部署处理中或结果待核实，不推定结论；需联调验证 |
| <a id="q-cm-05"></a>Q-CM-05 | 跨平台企业主体须稳定对应，不能只用名称匹配 | 主体标识缺失时不能通过；需联调验证真实归属与访问范围 |

代币质押审核侧解冻授权本身的结果口径（签名取消、上链失败、结果待核实时结论如何、gas 由谁承担、授权期间资产方能否撤回），列在[代币质押审核](../06-代币质押审核/01-代币质押审核-PRD.md)的待确认事项中，不在本册重复。

### 12.2 按用户决定保留的业务后果

供研发与测试知悉，不判为缺陷：

1. 通过不可撤销：部署成功即产生合约，平台没有动作能撤销结论或销毁合约；创建信息有误只能另建项目。
2. 项目审核没有时限：待审项目可以无限期停留；项目期限自创建起算，审核耗时实际占用项目有效期。
3. 部署失败对资产方不可见：资产方始终只看到待审核、收不到消息；持续失败时资产方无法自行判断原因。
4. 平台钱包与 gas 充值不在本系统范围：没有余额展示、充值入口或余额告警；余额不足导致的失败只能如实展示原因，由建设方在系统外处理。
5. 部署处理中资产方不能关闭项目：结果长期待核实时，资产方会一直看到待审核且无法关闭，只能等运营端回写结果。

### 12.3 依赖

- 融资需求与代币质押提供创建信息、项目状态和面客端结果；本模块产生的“项目已通过审核并完成合约部署”是资产方发起代币质押的前提，[代币质押审核](../06-代币质押审核/01-代币质押审核-PRD.md)据此受理逐笔质押。
- 运营端融资参数配置提供参数上下文的当前值；读不到时标“待核实”，不阻断审核。
- 运营端账户与登录提供账号、会话与权限项。
- 合约模板与代码、部署脚本、链与网络配置、部署确认数、平台钱包密钥保管与 gas 充值，由研发负责；部署确认数决定“部署成功”的判定时点，提测前须明确。实现与验证归研发、测试。
