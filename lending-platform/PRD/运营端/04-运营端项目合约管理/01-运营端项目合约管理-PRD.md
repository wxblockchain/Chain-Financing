## 1. 模块是什么

资产方在面客端创建融资项目并提交审核后，运营管理员在本模块核对项目的创建信息，然后作出结论：**通过**或**退回**。项目用到三份合约，来源不同（用户 2026-10-26 要求）：

- **质押合约**由开发人员预先部署好，同一区块链网络、同一代币类型下可以有多份；运营管理员在通过时为本项目选定其中一份，同一份质押合约可以由多个项目共用。
- **放款合约、还款合约**每个项目各一份，在通过时由平台为本项目部署：使用开发人员在代码中配置好的平台签名地址签名并执行链上操作，运营人员不需要钱包签名。

运营管理员点击“通过并部署合约”，选定质押合约并确认后，平台为本项目部署放款合约与还款合约；**放款合约与还款合约都部署成功，合约配置才算成功，配置成功即审核通过**，通过后详情中才展示本项目的三份合约地址。部署失败可以再次发起部署。退回则把项目连同面客可读的原因交还资产方修改。本模块另有质押合约台账，只读查看各份质押合约及配置在上面的项目。项目审核与合约配置是同一件事的两面，所以本模块叫“项目合约管理”。

本模块只写运营端这一侧：运营人员看到什么、能做什么、做完之后两端各变成什么。创建信息各字段及其校验、项目状态与资产方看到的结果，由[融资需求与代币质押](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)定义，本册只读使用、不改写。项目与合约的对应关系、合约配置的办理与结果以本册为准。

审核对象（D-CM-03）：

- 审核对象是**一个融资项目**，不是代币，也不是批次；一个项目在审核队列中始终只有一条记录。
- 资产方首次提交与每次退回后的重新提交，各算一次“提交”，按发生时间编为第 1 次、第 2 次……；重新提交不产生新的项目编号。
- 每次提交至多一个有效结论：通过（成立条件是合约配置成功）或退回（必须有面客可读原因）。配置失败不是结论。
- 一个项目配置成功后，绑定所选的一份质押合约，以及为本项目部署的一份放款合约、一份还款合约，绑定终身不变。质押合约可以由同一区块链网络、同一代币类型下的多个项目共用；放款合约与还款合约只属于本项目。

基本原则：

- **质押合约预先部署，由运营选用。** 同一区块链网络＋代币类型下可以有多份质押合约，由开发人员预先部署并维护；运营端只能查看和选用，不部署、不登记、不修改。一个项目只能选用与自己区块链网络、代币类型都一致的质押合约。
- **放款合约、还款合约每个项目一份，由平台部署。** 平台使用开发人员在代码中配置的平台签名地址签名并在链上部署；运营人员不连接钱包、不签名、不付费。
- **合约配置在通过办理中进行。** 项目待审核、尚未发起部署时，详情不展示合约配置内容；运营管理员点击“通过并部署合约”后才选定质押合约。
- **配置处理中不是结论。** 确认提交后到部署结果回写前，项目既不是“已通过”，也不能被再次裁定。
- **部署失败可以再次发起。** 放款合约或还款合约部署失败时，项目回到待审核，运营管理员可以再次发起部署，也可以改为退回。
- **没有审核时限，但项目有有效期。** 项目可以一直待审，不会因等待自动通过、自动失败或被催办；只有到达项目的有效期至时，待审核或已退回的项目才会自动关闭。
- **结论只有通过与退回两种。** 没有驳回终结、作废、冻结或暂缓。
- **核对对象是资产方最近一次提交的那份信息。** 审核期间运营调整融资参数，不改变核对基准。

**一个完整的例子。** 甲企业的资产方创建融资项目 P1（区块链网络 Ethereum，代币类型 ERC-3525-应收账款，项目质押率 70%，项目期限 2026-10-15～2027-04-15）并提交审核。运营管理员打开“项目合约管理”，在默认的待审核队列里看到 P1（第 1 次提交），进入审核详情：创建信息八项只读展示，参数上下文显示该组合当前的最高质押率为 75%，与 P1 锁定的 70% 并列；此时详情中没有合约内容。管理员线下核对后点击“通过并部署合约”，看到“Ethereum＋ERC-3525-应收账款”下预先部署的两份质押合约 SC1、SC2 及各自已配置的项目数，选定 SC1，确认知悉“配置成功即审核通过，不可撤销”后提交，全程不需要连接钱包或签名。P1 进入配置处理中：队列中它离开待审核，详情显示部署进行中、不显示“已通过”，甲企业在面客端仍看到“待审核”，此时也不能关闭项目。平台用平台签名地址为 P1 部署放款合约与还款合约，几分钟后两份都部署成功并回写：P1 变为已通过，详情出现 SC1、P1 的放款合约、P1 的还款合约三份地址与合约配置完成时间，操作记录先后有“提交通过并发起部署”和“配置成功（即审核通过）”两条；甲企业收到“融资项目审核通过”站内信，信中是 SC1 的地址，甲企业在面客端看到项目可用，可以开始质押代币。质押合约台账中 SC1 的已配置项目增加 P1；此前已配置在 SC1 上的乙企业项目 P0 不受影响，它有自己的放款合约与还款合约。如果放款合约部署失败，P1 回到待审核，详情展示失败原因，管理员可以再次发起部署。管理员返回队列，原来的筛选和页码保持不变。如果管理员当初选择退回，就要填写 10～500 字的原因，甲企业收到“融资项目审核退回”站内信，修改后重新提交，P1 以第 2 次提交回到队列。

<a id="out-of-scope"></a>
### 1.1 本期不做

- 运营人员为合约部署或配置连接钱包、签名（用户 2026-10-21 裁定配置不需要运营人员钱包签名）；部署费用的展示、充值或平台签名地址的余额告警。
- 运营端代资产方签名，或代资产方发起、撤销任何链上动作。
- 在运营端部署、登记、修改、停用或删除质押合约（由开发人员预先部署并维护）；在运营端查看或维护平台签名地址；合约模板与代码、合约升级、暂停、销毁、迁移，链与网络配置，链上确认数设置。
- 系统推荐或自动分配质押合约；质押合约的名称、备注或用途说明；质押合约的容量上限（用户 2026-10-26 裁定）。
- 为已配置成功的项目更换质押合约、重新部署放款合约或还款合约、增加合约或解除配置；人工录入或修改项目的合约地址。
- 放款与还款经合约执行的具体规则（归授信报价与接受拒绝、链上还款两个模块）。
- 批量审核、一键通过或退回、跨项目批量部署。
- 双人复核、审核与复核分离、转派或审批链。
- 第三种审核结论；任何审核时限、倒计时、催办、超时通知或超时统计。
- 运营端关闭项目、修改创建信息、代资产方重新提交、调整项目期限起算点。
- 代币类型、最高质押率、最长项目期限的配置（归[运营端融资参数配置](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md)）。
- 逐笔代币质押的处置：代币质押由资产方签名、合约执行，不经运营审核，运营端不对质押作结论（用户 2026-10-21 裁定）。本模块也不展示逐笔质押、总质押额与有效质押额；运营端的逐笔质押与项目额度只读查询在[融资台账](../09-融资台账/01-融资台账-PRD.md)中（用户 2026-10-26 确认）。
- 风控评分、风险提示、建议结论或自动筛出不合格项目。
- 配置异常的处置系统：工单、异常待办、自动升级、人工改判或补记、强制回滚、补偿。
- 审核内部备注与审核附件。
- 企业账户（法币与数币账户）及结算收款链的任何信息。
- 发给运营人员的站内信。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 适用组合 | 项目的“区块链网络＋代币类型”，取自其创建信息中的[区块链网络（FP-39）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-39)与[代币类型（FP-29）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-29)。决定本项目可以选用哪些质押合约，也决定参数上下文取哪一条配置 |
| 质押合约 | 资产方把代币质押进这里。由开发人员预先部署并维护，每份属于一个区块链网络＋代币类型，同一组合下可以有多份；运营管理员在通过时为项目选定一份。同一份质押合约可以由多个项目共用，各项目的质押份额在合约中分别归属本项目 |
| 放款合约、还款合约 | 每个项目各一份，只属于本项目，在通过时由平台为本项目部署。后续放款、还款都通过合约执行（用户 2026-10-21 裁定），具体规则见[授信报价与接受拒绝](../../面客端/06-借贷广场-授信报价与接受拒绝/01-授信报价与接受拒绝-PRD.md#scope)与[链上还款](../../面客端/08-借贷广场-链上还款/01-链上还款-PRD.md#scope) |
| 平台签名地址 | 开发人员在代码中配置的平台地址，用于签名并执行放款合约、还款合约的部署；运营端不展示、不维护 |
| 合约配置 | 为一个项目选定质押合约，并部署本项目的放款合约与还款合约。放款合约与还款合约都部署成功、所选质押合约对本项目生效，才算配置成功 |
| 质押链（区块链网络） | 合约所在的链，即资产方创建项目时选择的区块链网络，本期仅 Ethereum；本模块各处统一以“区块链网络”展示，网络名称见[展示约束](#display)。与企业账户使用的结算收款链是两回事 |
| 审核轴 | 运营端看到的项目审核进度：待审核、配置处理中、已通过、已退回 |
| 配置执行状态 | 合约配置的链上执行事实：未发起、配置处理中、配置成功、配置失败、结果待核实 |
| 项目已关闭 | 叠加在审核轴之上的标记，来自资产方主动关闭，或待审核、已退回时到期自动关闭；关闭原因为“资产方主动关闭”或“有效期到期” |
| 提交序次 | 资产方对同一项目第几次提交审核；首次为第 1 次，每次退回后重提加一 |
| 人工审结 | 一次提交得出了结论（通过或退回）；配置失败不算 |
| 参数上下文 | 审核时并列展示的、本项目适用组合在融资参数配置中的当前最高质押率与最长项目期限，仅作背景参考 |

## 3. 通用规则：权限、时间、费用与展示

适用于本模块全部功能。

**权限。** 按[权限组织方式（D-AL-07）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-07)，本模块定义以下两项权限，编号沿用原值：

| 权限项 | 覆盖的业务能力 |
| --- | --- |
| 融资项目审核查询（PM-AL-17） | 查看项目审核队列与统计、审核详情（含创建信息、参数上下文、合约与部署信息、项目关闭信息、操作记录）、质押合约台账；不含任何裁定动作 |
| 融资项目审核与合约配置处置（PM-AL-18） | 通过并部署合约、提交退回、部署失败后再次发起部署；必须同时具备融资项目审核查询（PM-AL-17），否则不能进入本流程 |

- 本期运营端只有运营管理员一个角色，固定具备上述两项（见[本期预置角色（D-AL-08）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-08)）。
- 只开通处置、缺少查询的交付配置，进入即被拒绝，并提示联系建设方修正配置。
- 其他模块的权限项都不覆盖本模块，不能据此进入。
- 账号待首登改密、被锁定或登录失效后，此前已打开页面中的提交同样被拒绝，不产生结论、不发起部署。
- 任何权限都不提供：改已生效结论、改创建信息、代资产方发起或撤销链上动作、手工录入合约地址、部署或维护质押合约、为已通过项目更换或重新部署合约、关闭项目、读取企业账户。
- 待审核与已退回的项目属资产方私有（[待审核项目的私有性（F-LS-12）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-12)）。运营端能看到它们来自功能权限，不改变其对游客和其他企业不可见。无权的入口不展示，也不泄露记录是否存在。

**时间与日期。**

- 近 7 个自然日统计、按日期筛选都按 UTC 日期计算，统计与日期条件上标注 UTC；具体时点按用户偏好时区显示并标注时区。切换时区、跨周末或夏令时不改变已发生的事实、统计归属或先后顺序。
- 没有审核时限：审核状态不因等待而改变，也不因等待触发提醒；本模块不展示等待时长。项目到达有效期至时的自动关闭见[待审核或已退回时到期自动关闭](#expiry)。
- 项目期限按[项目期限（FP-35）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-35)展示为“生效日～到期日”，生效日即项目创建日。本模块不决定也不改变起算点，审核耗时不延长项目有效期。

**费用。** 审核阶段资产方零费用；放款合约与还款合约由平台签名地址签名部署，运营人员个人不付费。本模块不展示部署费用。

**反馈。** 加载中、无数据、筛选无结果、读取失败、无权限、提交中、配置处理中、结果待核实，各自有可辨认的呈现；读取失败可重试，不显示成 0 条；提交失败保留已填内容与已选质押合约；不同项目之间不串用已填原因或已选质押合约。

**界面说明的范围**（用户 2026-10-16 要求）：界面只保留办理所需的事实、限制原因与提交前的关键后果确认。本册写明的费用承担、没有审核时限、信息只读等规则照常生效，但不作为常驻提示或重复说明展示。

<a id="display"></a>
**展示约束**（用户指定，作为设计约束保留）：

- 区块链网络与代币类型同时出现时，先展示区块链网络，再展示代币类型（2026-10-26）；“适用组合”也按“区块链网络＋代币类型”的顺序书写。
- 区块链网络同时显示网络图标与网络名称，不以图标代替名称（2026-10-23）；网络名称沿[区块链网络（FP-39）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-39)，中文环境与英文环境都显示英文名称 Ethereum，不译为中文，也不以 ETH 代替网络名称（2026-10-26）。
- 代币类型按创建信息原值展示，统一名称为“ERC-3525-应收账款”，不使用其他写法或简称（2026-10-26）。
- 列表中，区块链网络在第一列，代币类型紧随其后；项目发布方、代币类型各自独立成列，与区块链网络分开（2026-10-23、2026-10-26）。
- 队列与详情不展示等待时长，本次提交时间与提交序次照常展示（2026-10-23）。
- 通过并部署合约、再次发起部署时，质押合约以下拉方式选择（2026-10-26）。

## 4. 两条状态轴

一个项目同时有两条互相独立的状态：**审核轴**表示审核走到哪一步，**配置执行状态**表示合约部署的链上事实。另有一个叠加标记“项目已关闭”，来自资产方主动关闭，或待审核、已退回时到期自动关闭。项目状态的权威定义归[融资项目状态（ST-LS-01）](../../面客端/05-借贷广场-融资需求与代币质押/02-融资需求与代币质押-流程图与状态机.md#st-ls-01)，本册只读对应。

审核轴（必有，默认待审核）：

| 审核轴 | 资产方看到的项目状态 | 运营可做的动作 |
| --- | --- | --- |
| 待审核 | 待审核（S-FP-7） | 通过并部署合约、退回；没有截止 |
| 配置处理中 | 待审核（S-FP-7） | 无。不能重复发起、不能改判为退回；不推定成功或失败 |
| 已通过 | 可用（S-FP-1），尚无质押 | 无。结论终态，不可撤销、不可二次裁定 |
| 已退回 | 已退回（S-FP-8） | 无。等资产方修改重提后回到待审核 |

配置执行状态（必有，默认未发起）：未发起、配置处理中、配置成功、配置失败、结果待核实。

两条轴与“项目已关闭”的组合（列表中审核轴一列只显示审核轴取值，“项目已关闭”与关闭原因只在详情展示，见[项目审核队列](#m1)）：

| 审核轴 | 配置执行状态 | 项目已关闭 | 运营在详情中看到与能做的 | 资产方能否关闭项目 |
| --- | --- | --- | --- | --- |
| 待审核 | 未发起 | 否 | 不展示合约内容；可通过并部署合约或退回 | 可以 |
| 配置处理中 | 配置处理中 | 否 | 显示部署进行中，不显示“已通过”，无处置入口 | 不可以，见下方配置处理中资产方不能关闭项目（D-CM-21） |
| 配置处理中 | 结果待核实 | 否 | 显示结果待核实与已知凭证，无处置入口并说明原因 | 不可以，见下方配置处理中资产方不能关闭项目（D-CM-21） |
| 已通过 | 配置成功 | 否 | 显示本项目的质押合约、放款合约、还款合约地址与配置事实，无处置入口 | 按面客端可用状态的既有条件，与本模块无关 |
| 待审核 | 配置失败 | 否 | 显示部署失败原因，可再次发起部署或改为退回 | 可以 |
| 已退回 | 未发起 | 否 | 显示退回原因，不展示合约内容，无处置入口 | 可以 |
| 待审核 | 未发起 | 是 | 保留关闭前的审核轴，标“项目已关闭”及关闭原因（资产方主动关闭或有效期到期），只读，不可裁定 | 已关闭 |
| 待审核 | 配置失败 | 是 | 保留关闭前的审核轴，标“项目已关闭”及关闭原因（资产方主动关闭或有效期到期），只读，不可再次发起部署 | 已关闭 |
| 已退回 | 未发起 | 是 | 保留关闭前的审核轴，标“项目已关闭”及关闭原因（资产方主动关闭或有效期到期），只读 | 已关闭 |

<a id="d-cm-21"></a>
**配置处理中资产方不能关闭项目（D-CM-21）。** 用户 2026-10-14 裁定：审核轴为配置处理中（包括配置执行状态为结果待核实）时，资产方不能关闭项目；面客端规则见[合约配置进行中暂不可关闭（D-LS-71）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-71)。部署结果回写后按结果处理：配置成功则项目已通过，此后能否关闭按面客端可用状态的既有条件；配置失败则回到待审核，资产方可以关闭。

<a id="expiry"></a>
**待审核或已退回时到期自动关闭。** 用户 2026-10-16 裁定：

- 审核轴为待审核或已退回的项目，到达有效期至（到期判定同[项目状态与后续业务](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#project-state)）时自动关闭，关闭原因为“有效期到期”。项目离开默认审核队列、不再计入待审核统计，不能再裁定，也不能再次发起部署。
- 运营提交通过时项目已到期的，提交被拒并说明项目已到期，不产生结论、不发起部署。
- 配置处理中（含结果待核实）跨过有效期至的，不在此时关闭，等部署结果回写后处理：配置成功即审核通过，项目转为可用后，按可用状态的到期规则立即自动终结为已关闭（有效期到期）；配置失败则按第一条自动关闭，不可再次发起部署。
- 自动关闭不发送本模块的站内信。配置成功后立即终结的项目，仍按规则发送一条“融资项目审核通过”，资产方打开后看到项目的当前状态。
- 面客端规则见[待审核或已退回时到期自动关闭（D-LS-72）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-72)。

**项目与合约的对应。**

- 配置成功后，本项目绑定所选的质押合约，以及为本项目部署的放款合约、还款合约，终身不变、只读；创建信息全部只读。
- 同一份质押合约可以对应多个项目，质押合约地址不是项目的唯一标识；放款合约与还款合约只对应本项目。定位项目一律用项目编号。
- 各项目在同一份质押合约中的质押份额、额度与质押情况分别归属本项目，互不计入；面客端计算口径见[总质押额（FP-10）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-10)。
- 一个项目的配置成功、失败或待核实，不改变同一份质押合约上其他项目的状态。

**运营端不代资产方动作。** 修改创建信息、重新提交、关闭项目都是资产方的动作，运营端没有对应入口；退回是运营端唯一能把项目交还资产方的方式。

流程参见：[项目审核轴（ST-CM-01）](./02-运营端项目合约管理-流程图与状态机.md#st-cm-01)、[合约配置执行状态（ST-CM-02）](./02-运营端项目合约管理-流程图与状态机.md#st-cm-02)。

## 5. 项目审核队列（F-CM-01～F-CM-05）

适用角色与前提：具备融资项目审核查询。队列是项目审核队列（P-O-CM-01），一条记录对应一个项目，退回重提后仍是同一条。

- 默认只列审核轴为待审核、且未关闭的项目，按本次提交时间从早到晚排列；时间相同时保持稳定顺序。不做风险优先排序。（F-CM-01）
- 每条记录展示：区块链网络、代币类型、项目编号、项目名称、项目发布方、项目质押率、项目期限（生效日～到期日）、本次提交时间与提交序次、审核轴、配置执行状态。列顺序与网络、代币类型的写法见[展示约束](#display)。（F-CM-02）
- 列表的审核轴只显示审核轴取值（待审核、配置处理中、已通过、已退回），不显示“项目已关闭”标记，也不显示关闭原因（资产方主动关闭、有效期到期）；这些在[审核详情](#m2)中展示（用户 2026-10-26 要求）。已关闭的项目不在默认视图中，按条件检索到时，列表照常显示其关闭前的审核轴取值。
- 列表不展示任何合约地址；本项目的合约地址在审核详情中查看（用户 2026-10-26 要求）。
- 可按以下条件组合筛选（F-CM-03）：
  - 审核轴：全部、待审核、配置处理中、已通过、已退回。
  - 配置执行状态：全部、未发起、配置处理中、配置成功、配置失败、结果待核实。
  - 区块链网络、代币类型、项目发布方。
  - 提交时间范围：起止都包含当天，起点不能晚于终点，否则就地提示。
  - 关键词：可匹配项目编号、项目名称、项目发布方名称、本项目已配置的任一合约地址，忽略首尾空格；用质押合约地址检索时，列出配置在这份质押合约上的全部项目。
  - 重置后回到默认条件。
- 队列上方有两项统计（F-CM-04）：
  - **待审核项目数**：审核轴为待审核且未关闭的项目数，其中单独标出**配置失败待再次发起**的项目数；后者是前者的一部分，两者不相加。
  - **近 7 个自然日人工审结项目数**：结论时间落在近 7 个自然日内的通过与退回之和；配置失败不计入。
  - 统计跟随区块链网络、代币类型、项目发布方、提交时间与关键词条件变化，不跟随审核轴与配置执行状态筛选变化；完整的统计口径可展开查看。
- 可按本次提交时间升序或降序排列，不提供等待时长排序；带总数分页，每页条数沿用平台现行取值。筛选条件改变后回到第一页；从详情返回时保留筛选、排序和页码，原页已空时回到最后一个有内容的页并说明。（F-CM-05）
- 队列只用于查看，不提供逐条裁定或批量选择；进入详情才能办理。

流程参见：[项目审核与合约配置（FL-CM-01）](./02-运营端项目合约管理-流程图与状态机.md#fl-cm-01)。

## 6. 审核详情与创建信息核对（F-CM-06～F-CM-08）

适用角色与前提：具备融资项目审核查询。审核详情是项目审核详情（P-O-CM-02），可从队列或质押合约台账进入。

- 详情中性说明“本处信息供线下判定参考，结论由审核人线下作出后在此维护”；不提供评分、风险提示、建议结论或自动筛出。
- 详情始终能看到当前项目编号和提交序次，以下信息按各自的展示条件同处可得。（F-CM-06）

| 业务信息 | 含义 / 类型 | 展示条件 / 默认 | 可编辑 | 缺失或异常时 |
| --- | --- | --- | --- | --- |
| 项目编号、项目名称 | 文本，定位项目 | 必有 | 只读 | 不以名称或合约地址代替编号定位 |
| 本次提交 | 本次提交的真实时点与提交序次 | 必有 | 只读 | 时点缺失标“待核实”，不用访问时刻代替 |
| 创建信息 | [区块链网络（FP-39）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-39)（本期 Ethereum）、代币类型、项目名称、项目质押率、项目期限（生效日～到期日）、参考结算币种、还款方式、SPV机构名称；取值与校验按[创建信息](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#create)，按原值展示，网络与代币类型的写法见[展示约束](#display) | 必有 | 只读，运营端不改、不二次校验 | 还款方式标“平台定值”，参考结算币种标“只供参考，不限制资金方报价币种”；审核人只需确认二者是平台带出的现行取值 |
| 项目发布方 | 创建本项目的资产方企业：企业名称与稳定主体标识（即[项目发布方（FP-03）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-03)） | 必有 | 只读 | 主体标识缺失标“待核实”且不能通过，不以企业名称代替归属判定（见[依赖](#dependencies)中的企业主体对应） |
| 参数上下文 | 本项目适用组合当前的[最高质押率（FC-02）](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#fc-02)与[最长项目期限（FC-03）](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#fc-03)，标明取数时点 | 有配置时展示 | 只读 | 与创建时锁定值并列并标出是否一致；当前配置读不到时标“待核实”，不阻断审核 |
| 审核信息 | 审核轴；每次结论的结论时间、审核人（取当时身份）、退回原因全文 | 有结论时必有 | 只读 | 历次结论各自保留，不互相覆盖 |
| 项目关闭信息 | “项目已关闭”标记、关闭原因（资产方主动关闭、有效期到期）与关闭时间 | 项目已关闭时必有；未关闭时不展示 | 只读 | 关闭时间缺失标“待核实”；列表不展示本项，只在详情展示 |
| 部署进度与结果 | 本次提交最近一次部署尝试的配置执行状态；配置失败时另有失败原因（仅运营端可读的失败事实原文）、失败时点、放款合约与还款合约各自的部署结果；部署交易凭证 | 本次提交已发起过部署时展示；待审核且未发起、已退回时不展示 | 只读 | 未提供的项标“待核实”，不填 0、不造值 |
| 所配置的合约 | 质押合约地址（所选的预先部署合约，可能与其他项目共用；即面客端的[质押合约地址（FP-33）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-33)）、放款合约地址、还款合约地址（本项目专属），各标合约类别；合约配置完成时间（配置成功即审核通过的时刻） | 配置成功（已通过）后必有；此前不展示 | 只读，可复制完整值；可从质押合约进入质押合约台账中的这一份 | 不显示占位值 |
| 操作记录 | 见下方操作记录规则 | 有事件时必有 | 只读 | 加载中、暂无记录、读取失败分别说明 |

<a id="d-cm-17"></a>
**核对对象是提交时的快照（D-CM-17）。**

- 审核核对的是资产方最近一次提交（含退回重提）时的项目质押率与项目期限，审核期间运营调整参数不改变核对基准。退回重提时，项目质押率按重提当时该组合的最高质押率重新校验，项目期限仍按创建时锁定的最长项目期限；合约配置成功后两者锁定终身。沿[生效与存量隔离（D-O-FC-03）](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md#d-o-fc-03)中的“审核核对用快照”。
- 审核期间运营调高或调低参数配置，不改变在审项目的核对结论，也不改变退回后重提的核对基准，本身不构成退回理由。
- 锁定值与当前配置不一致时，如实并列并标出差异；不自动拦截提交、不改写锁定值、不自动退回、不产生整改待办，也不把项目标为违规。

**操作记录是唯一的进度与历史来源。** 本项目的全部事实只记在一条按发生时间倒序的操作记录里，不另设“审核历史”或第二套进度明细。（F-CM-07）

- 记录的事件共十类：提交审核、提交通过并发起部署、配置成功（即审核通过）、配置失败、结果待核实、再次发起部署、审核退回、资产方修改重提、资产方关闭项目、项目到期自动关闭。只记本项目的事实，同一份质押合约上其他项目的事件不进入本项目记录。
- 每条记录有真实发生时间与时区；时间缺失标“待核实”。
- 每条记录有主体：人工事件显示当时的审核人，资产方动作标“资产方”，链上结果回写与到期自动关闭标“系统”；主体缺失标“待核实”，不推定为审核人。
- 每条记录写明结果、前后状态与原因全文；部署相关事件附本次所选的质押合约地址、已部署成功的放款合约或还款合约地址与对应链上凭证，没有则说明暂无，不复用其他项目的凭证。
- 历次提交、结论、退回原因全文、审核人与时间、历次部署尝试及所选质押合约与结果都能从操作记录取得；摘要可收起，原因可展开全文。重新提交不覆盖以前的原因，也不把上一次结论改写为本次结论。
- 记录只读，不可编辑、删除或手工补完。

**往返与去重。** 同一事件重复到达只保留一条，新进度不覆盖以前的事实。从队列或台账进入详情只进入该项目；返回时保留来源页的筛选、排序、页码和所在位置。（F-CM-08）

流程参见：[详情、操作记录与质押合约台账的查看（FL-CM-03）](./02-运营端项目合约管理-流程图与状态机.md#fl-cm-03)。

## 7. 通过并部署合约（F-CM-09～F-CM-11）

适用角色与前提：具备处置权限；当前项目为待审核、未关闭、未到期，且不在配置处理中。

- 通过办理依次为：点击“通过并部署合约” → 选定本项目的质押合约 → 确认知悉“配置成功即审核通过，不可撤销”并提交 → 平台为本项目部署放款合约与还款合约。运营人员不需要连接钱包或签名，没有第二步确认，也不增加第二位审核人。

**选定质押合约**（用户 2026-10-26 要求：质押合约预先部署，同一代币类型下有多份，由运营管理员选择；区分与选用方式由用户同日裁定）：

- 候选只来自与本项目区块链网络、代币类型都一致的、开发人员预先部署的质押合约；每份以合约地址与已配置项目数（配置成功的项目）区分，不设合约名称或备注，也不设容量上限。网络或代币类型与本项目不一致的质押合约不出现在候选中，也不能通过其他方式选入。
- 必须选定一份才能提交；由处置人自行选择，系统不推荐、不自动分配。
- 本项目适用组合下没有可选的质押合约时，不能通过，就地说明该组合暂无可选质押合约；处置人可以改为退回或稍后办理，项目仍为待审核，不产生结论。
- 放款合约与还款合约不需要选择，由平台为本项目新部署。
- 确认时展示：适用组合（区块链网络＋代币类型）、所选质押合约地址，并说明提交后由平台为本项目部署放款合约与还款合约，供提交前核对。

**提交与结果：**

- 取消不产生结论、不发起部署。提交中有明确反馈，不能重复提交。（F-CM-09）
- 提交生效时权限或状态已变化（项目已关闭、已到期、已被他人裁定、已在配置处理中），或所选质押合约已不可选用，就地说明并拒绝，不产生结论、不发起部署。
- 运营提交通过与资产方关闭项目同时发生时，只成立先生效的一笔：关闭先生效，则本次通过被拒；通过先生效，则项目进入配置处理中，资产方的关闭被拒（见[配置处理中资产方不能关闭项目（D-CM-21）](#d-cm-21)）。
- 提交成功即结束本次办理并回到详情：审核轴与配置执行状态都变为配置处理中，操作记录新增“提交通过并发起部署”，该项目离开待审核统计。平台使用平台签名地址，在链上为本项目部署放款合约与还款合约，并使所选质押合约对本项目生效。此时尚未形成结论：界面不出现“已通过”，也不展示所配置的合约；资产方仍看到待审核且不能发起质押；处置入口不可用；同时提交多次只成立一笔。（F-CM-10）
- **配置成功即审核通过**：放款合约与还款合约都部署成功、所选质押合约对本项目生效，才算配置成功。回写三份合约的地址、部署凭证与合约配置完成时间；审核轴变为已通过，记录审核人（提交本次通过的运营管理员）与结论时间（即合约配置完成时间）；详情展示本项目的质押合约、放款合约、还款合约地址；人工审结数加一；资产方的项目变为可用、尚无质押，可以向所选的质押合约发起代币质押；本项目计入质押合约台账中这份质押合约的已配置项目。结论终态：不可撤销、不可改判为退回、不可更换合约。（F-CM-11）
- 审核通过不改创建信息、不改代币事实，本身不产生任何质押额，也不改变同一份质押合约上其他项目的任何状态或额度。

通知：配置成功时，向创建该项目的资产方发送[融资项目审核通过](./03-运营端项目合约管理-消息通知.md#notice-rules)。
流程参见：[项目审核与合约配置（FL-CM-01）](./02-运营端项目合约管理-流程图与状态机.md#fl-cm-01)。

## 8. 退回（F-CM-12～F-CM-13）

适用角色与前提：同[通过并部署合约](#m3)。

- 办理入口与结论在运营端统一称“退回”（不称“退回资产方”）；界面上把创建该项目的资产方称为申请方，把本次提交称为申请（用户 2026-10-16 要求）。
- 退回办理依次为：填写退回原因 → 全文预览并再次确认 → 提交。退回不选合约、不发起部署。（F-CM-12）
- 退回原因必填，10～500 字（沿本平台审核驳回原因的现行校验）；空白、仅空格或超长不能提交。原因即[审核退回原因（FP-37）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-37)，原样进入面客端与站内信，因此不得写入内部代号、内部备注或本项目以外的信息；提交后不可编辑或删除。（F-CM-13）
- 一次提交至多一个有效结论；两人同时裁定只成立一笔，后到的一方被告知已有结论并看到现状，原因不被覆盖。
- 退回后审核轴变为已退回，人工审结数加一。资产方能否重提、重提时的校验，由面客端[创建信息](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#create)判定；重提后项目以新的提交序次回到待审核与队列，项目编号不变，项目期限不重新起算。重提时资产方改了代币类型的，适用组合随之改变，候选质押合约按新的代币类型列出。
- 退回次数不设上限；平台不自动终结、不自动通过、不限制重提次数。
- 取消不产生结论，不同项目之间不携带原因；保存失败保留已填原因可重试；结果不确定时先查当前事实，不显示成功、不引导重复裁定。

通知：退回生效时，向创建该项目的资产方发送[融资项目审核退回](./03-运营端项目合约管理-消息通知.md#notice-rules)。

## 9. 配置失败、结果待核实与再次发起部署（F-CM-14～F-CM-15）

适用角色与前提：合约部署已发起；再次发起须具备处置权限。

- 配置失败与结果待核实都**不是结论**：不要求资产方重新提交，不改变项目期限起算点，不产生第二个项目，不影响同一份质押合约上的其他项目，也不向资产方发送任何消息——资产方始终只看到待审核。
- **配置失败**（链上执行明确失败：放款合约、还款合约中只要有一份没有部署成功，或所选质押合约未能对本项目生效，就算配置失败）：审核轴回到待审核，计入“配置失败待再次发起”。详情的部署进度与结果展示失败原因（仅运营端可读的失败事实原文，不进入面客端、站内信或退回原因）、失败时点、放款合约与还款合约各自的部署结果（未知标“待核实”）。处置人可以再次发起部署，也可以改为退回。（F-CM-14）
- **再次发起部署**（用户 2026-10-26 要求：放款合约和还款合约部署失败可再次发起部署）：按[通过并部署合约](#m3)同样的规则选定质押合约（可以与上次相同，也可以改选同组合下的另一份；配置成功前质押合约尚未绑定本项目）并确认提交，不需要钱包签名；沿用同一项目编号与同一次提交，形成新的部署尝试并进入配置处理中；历次尝试、所选质押合约与结果都留在操作记录。次数不设上限；平台不自动重试、不自动退回、不自动通过。（F-CM-15）
- 本项目以最终配置成功那次所选的质押合约、所部署的放款合约与还款合约为准；失败尝试中产生的合约地址只留在操作记录，不作为所配置的合约展示。
- **结果待核实**（长期没有确定结果，或事实冲突）：标“待核实”并保留已知凭证与事实；不推定成功或失败，不重复发起，不自动改判或回滚；处置入口不可用并说明原因。真实结果回写后，按成功或失败继续（见[依赖](#dependencies)中的部署结果回写）。
- 本期不提供工单、升级、人工改判或补记、强制回滚、补偿或手工录入合约地址；无法自行处理时，联系建设方核实链上与部署情况，产品内不编造处理时限。

流程参见：[配置失败、结果待核实与再次发起部署（FL-CM-02）](./02-运营端项目合约管理-流程图与状态机.md#fl-cm-02)。

## 10. 质押合约台账（F-CM-16～F-CM-17）

适用角色与前提：具备融资项目审核查询。台账是质押合约台账（P-O-CM-03），只读（用户 2026-10-26 裁定保留）：运营选用前可以看到同组合下各份质押合约的使用情况，一份质押合约出问题时可以查到受影响的项目。

- 一条记录对应一份预先部署的质押合约。同一区块链网络＋代币类型下有几份质押合约，就有几条记录。（F-CM-16）
- 每条记录展示：区块链网络、代币类型、质押合约地址、已配置项目数（配置成功的项目）。列顺序与网络、代币类型的写法见[展示约束](#display)。
- 放款合约与还款合约每个项目一份，不进入台账，在项目的审核详情中查看。
- 可按区块链网络、代币类型、关键词（质押合约地址）筛选；分页与返回规则与[项目审核队列](#m1)相同。
- 合约地址可复制完整值；平台不声称地址在链上的当前状态。台账没有部署、登记、编辑、停用、更换或解除配置等业务动作（质押合约由开发人员预先部署并维护），也不展示逐笔质押、额度或质押情况。
- 从一份质押合约可查看配置在它上面的项目：项目编号、项目名称、项目发布方、合约配置完成时间、审核人、项目当前状态（按面客端项目状态展示），默认按合约配置完成时间从晚到早排列，可升降序。未配置成功的项目（含配置处理中、配置失败、结果待核实）不在其中。（F-CM-17）
- 从项目可进入该项目的审核详情，返回时保留台账原来的筛选、排序与页码。

## 12. 业务后果与依赖

### 12.1 按用户决定保留的业务后果

供研发与测试知悉，不判为缺陷：

1. 通过不可撤销：配置成功即绑定合约，平台没有动作能撤销结论、更换质押合约、重新部署放款合约或还款合约、解除配置；创建信息有误只能另建项目。
2. 项目审核没有时限：待审项目可以无限期停留；项目期限自创建起算，审核耗时实际占用项目有效期。
3. 配置失败对资产方不可见：资产方始终只看到待审核、收不到消息；持续失败时资产方无法自行判断原因。
4. 配置处理中资产方不能关闭项目：结果长期待核实时，资产方会一直看到待审核且无法关闭，只能等运营端回写结果。
5. 待审核或已退回的项目到期自动关闭：审核没有时限，如果运营在有效期至之前没有作出结论，项目会被自动关闭，资产方只能另建项目。
6. 质押合约可以共用：一份质押合约出现问题时，影响配置在它上面的全部项目；本期没有为已配置项目更换或迁移质押合约的能力。某组合下没有预先部署的质押合约时，该组合的项目都不能通过，只能等开发人员部署。放款合约与还款合约每个项目各一份，一个项目的部署结果不影响其他项目。
7. 列表不展示关闭信息：已关闭项目按条件检索到时，列表只显示其关闭前的审核轴取值（例如“待审核”“已退回”），是否已关闭及原因须进入详情查看。

<a id="dependencies"></a>
### 12.2 依赖

- 融资需求与代币质押提供创建信息、项目状态和面客端结果；本模块产生的“项目已通过审核并完成合约配置”是资产方发起代币质押的前提；质押由资产方签名、合约执行，上链成功即质押成功，不再经过运营端。项目的份额与额度按本项目分别归属，见[总质押额（FP-10）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-10)。
- 运营端融资参数配置按项目适用组合提供参数上下文的当前值；读不到时标“待核实”，不阻断审核。代币类型的取值域也来自该模块，新增代币类型后须有对应的预先部署的质押合约，该类型的项目才能通过。
- 运营端账户与登录提供账号、会话与角色；项目审核与合约配置的权限及结果由本模块定义，运营人员不签名。
- **质押合约提供**（用户 2026-10-26 要求）：质押合约由开发人员预先部署并维护，每份标明所属区块链网络与代币类型；本模块据此列出候选。新增代币类型或网络时，须先由开发人员部署对应的质押合约。
- **平台签名地址**（用户 2026-10-26 要求）：由开发人员在代码中配置，用于签名部署每个项目的放款合约与还款合约；该地址不可用导致部署失败时，按配置失败处理，可以再次发起部署。
- **部署结果回写**：成功回写质押合约地址、放款合约与还款合约地址、部署凭证与完成时间；失败回写原因与放款合约、还款合约各自的部署结果；长期没有结果标“结果待核实”。回写缺失时只停留在配置处理中或结果待核实，不推定结论；需联调验证。
- **企业主体对应**（用户 2026-10-16 确认）：跨平台企业主体须稳定对应，不能只用名称匹配；主体标识缺失时不能通过；需联调验证真实归属与访问范围。
- 质押合约的代码、部署与维护，放款合约与还款合约的代码与部署方式，平台签名地址的配置与链上费用，所选质押合约如何对本项目生效，同一份质押合约内各项目份额分别归属的能力，再次发起部署时已部署成功的合约如何处理，链与网络配置，链上确认数，由研发负责；链上确认数决定“配置成功”的判定时点，提测前须明确。实现与验证归研发、测试。
