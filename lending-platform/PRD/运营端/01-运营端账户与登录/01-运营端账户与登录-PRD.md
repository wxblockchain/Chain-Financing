# 运营端账户与登录 · PRD

2026-10-28｜运营管理平台 · 运营端｜需求评审稿；真实未决项见第 4 节。

## 1. 目标与阅读入口

运营人员用平台建设方交付的工作邮箱与密码登录运营管理平台，完成首次强制改密后，按各业务模块定义的功能权限执行各项运营动作，并自助维护本人密码、工作邮箱与语言时区偏好。
**一个完整的例子。** 建设方交付运营管理员的工作邮箱与初始密码。运营人员首次登录后只能设置新密码，改密成功后重新登录，进入运营端总览并按业务模块权限办理审核；从账户设置修改本人偏好，返回原业务继续工作，主动退出后不能继续读取受保护业务。


本期包含：账号来源与首登强制改密、工作邮箱密码登录、忘记密码两步找回、账户设置（账号信息、本人改密、本人改邮箱、语言与时区）、运营角色与各模块共同遵守的权限底线、会话与锁定、发码前的滑块人机校验与限频、账户安全通知的触发口径、登录后落地的总览入口。相邻模块负责：各审核、配置、协议、消息动作的业务规则，以及这些功能自己的权限项、覆盖动作、组合要求和角色可用范围（WS-381／WS-383／WS-384／WS-387／WS-388／WS-439／WS-464），站内消息的承载与未读语义（WS-383），[运营端总览](../08-运营端总览/01-运营端总览-PRD.md)的统计与待办，语言、时区、数字、金额、链上地址与脱敏的正文口径（三平台共享国际化基线）。本期不包含第 1.2 节 `X-AL-*` 各项。


本模块共四册：本册定义功能与业务规则；[流程图与状态机](./02-运营端账户与登录-流程图与状态机.md)、[消息通知](./03-运营端账户与登录-消息通知.md)及[验收](./04-运营端账户与登录-验收.md)配套阅读。编号沿用原值，缺号不代表遗漏。

## 2. 角色、账号与共同业务规则

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

沿用的名称中，「运营端消息入口」指该入口由管理端共享导航承接、不由本模块自建，与其在界面上的位置无关；「滑块拼图人机校验」指用户已确认的这一类人机校验机制本身，不指定其承载形式与视觉反馈；「层级路径导航」指当前所处层级及可回到的上级这一事实，不指定其呈现方式。

### 2.1 主体、账号与角色

| 编号 | 口径 | 结论 |
| --- | --- | --- |
| <a id="d-al-02"></a>`D-AL-02` | 部署边界与账号归属 | 运营管理平台是独立部署单元；运营账号与代币发行平台运营端不共用，不做跨平台单点登录，不做账号同步 |
| <a id="d-al-03"></a>`D-AL-03` | SPV 与运营机构的关系 | SPV 与运营人员按同一运营身份体系处理。不新增第二类账号、机构维度的功能入口或数据域；身份同一不产生资金代付、代收或代登记/确认权限 |
| <a id="d-al-04"></a>`D-AL-04` | 账号来源 | 只有一套运营账号体系，初始工作邮箱与密码由平台建设方提供；产品内无注册、邀请员工、新增账号、申请开通入口 |
| <a id="d-al-05"></a>`D-AL-05` | 数据可见范围 | 不做机构级数据隔离；在获准的业务对象范围内不按所属机构或本人经办筛选。功能权限与对象限制仍适用，不能据「全量」读取所属模块限定角色的对象、他人账户档案或本人专属安全消息 |
| <a id="d-al-06"></a>`D-AL-06` | 主体分家的边界说明 | 主体后续若分家（SPV 独立为另一家法律主体），届时按「多机构 / 租户」独立立项处理；本期不为此预先设计租户隔离、机构维度字段或数据域切分。本条只作边界说明，不产生本期设计要求 |
| <a id="d-al-30"></a>`D-AL-30` | 术语 | 本册「运营端」专指运营管理平台的运营端；本期对外角色称谓只出现「运营管理员 / Operations Administrator」，「运营专员 / Operations Specialist」为保留称谓、本期不出现；界面上不出现「SPV 机构」作为账号类型 |
| <a id="d-al-31"></a>`D-AL-31` | 与面客端账号的关系 | 运营账号与面客端资产方 / 资金方账号完全独立：运营账号不能登录面客端，面客端账号不能登录运营端 |

| 角色 | 描述 | 在本模块内的核心诉求 |
| --- | --- | --- |
| 运营管理员（`RO-AL-1`） | 拥有本期全部业务权限的运营人员 | 按交付的初始账密完成首登改密，使用业务功能并维护本人密码与邮箱；其他设备的登录在改密后立即失效 |
| 平台建设方 / 运维 | 交付初始账号、角色与权限配置，提供异常人工恢复 | 配置依据明确；产品内没有账号管理界面 |
| 非中文运营成员 | 运营团队中不使用中文的成员 | 打开就是英文，不必先找语言开关；切成中文后换设备登录仍是上次所选 |

<a id="d-al-13"></a>`D-AL-13`【SPV 职责的落法】：SPV 不是一类账号，而是一组职责，按职能落在运营人员的功能权限项上。现阶段已规划的运营动作（认证审核、代币准入审核、项目审核与合约配置、融资参数配置、融资台账查询、协议管理、消息查看）即为其可授权范围，各动作的权限由所属模块定义。不增加 SPV 专属动作，不赋予资金代付、代收、代登记、代确认或代替当事方办理的能力，也不因此开放私人付款资料；后续若确需新增，须先由对应业务模块确认职责与权限，不能仅凭同主体追加授权。

### 2.2 信息域与功能入口

本期共 6 个信息域，编号沿用既有 `P-O-AL-*`；本人修改邮箱在账户设置域内完成。下表说明每个域承载哪些功能与准入条件，不规定承载形式（见[统一条款](#design-boundary)）。

| 编号 | 信息域 | 承载功能与准入 |
| --- | --- | --- |
| `P-O-AL-01` | 运营端登录 | [工作邮箱与密码登录](#f-al-04)；无注册入口、无协议勾选、无「记住我」、无验证码登录、无钱包登录。提供「忘记密码」入口；账号锁定时在同一登录入口给出锁定提示与剩余时间，不要求用户另行查找 |
| `P-O-AL-03` | 首次登录 · 强制改密 | [首登强制改密](#f-al-03)；未完成改密不得访问其他任何功能，只保留退出登录与语言切换两个出口 |
| `P-O-AL-04` | 忘记密码 · 提交工作邮箱 | [忘记密码第一步](#f-al-05)：输入工作邮箱 → 滑块拼图人机校验 → 发送验证码 |

<a id="2-4-账号状态会话与验证码状态"></a>
### 2.4 账号状态、会话与验证码状态

**账号状态**（图示 [SM-AL-01](02-运营端账户与登录-流程图与状态机.md#sm-al-01)）

| 编号 | 状态 | 含义与行为 |
| --- | --- | --- |
| `ST-AL-1` | 待首登改密 | 建设方已交付初始账密，本人尚未完成首次登录强制改密。登录验证通过后仅可改密、退出与切换语言，不可执行业务动作 |
| `ST-AL-2` | 正常 | 已完成首登改密，按交付配置的权限使用业务功能 |
| `ST-AL-3` | 锁定 | 连续密码校验失败达到阈值，不可登录或完成找回，无提前解锁通道；到期回到锁定前状态 |

| 从 → 到 | 触发 | 附带结果 |
| --- | --- | --- |
| 待首登改密 → 正常 | 完成 `P-O-AL-03` 强制改密 | 初始密码失效、触发密码变更通知、全部会话失效并要求重新登录 |
| 正常 / 待首登改密 → 锁定 | 连续密码失败达 `N-AL-01`（含账户设置内再认证失败） | 登录与找回不可完成，已有登录不得执行业务动作；不发通知 |
| 锁定 → 锁定前状态 | 锁定到期自动解除 | 登录页表单自动恢复可用，无需刷新 |

忘记密码不会让待首登改密账号直接转正常（见 [3.4](#f-al-05)）。本期没有产品内新增账号、停用 / 启用、他人改密或重新开通的状态转换。人工重新初始化属建设方 / 运维的线下兜底，重新交付后仍以待首登改密进入上述流程，也不得用于提前解除既有锁定。

**登录会话**（图示 [SM-AL-02](02-运营端账户与登录-流程图与状态机.md#sm-al-02)，规则见 [3.11](#f-al-12)）；**验证码状态**（图示 [SM-AL-03](02-运营端账户与登录-流程图与状态机.md#sm-al-03)）

| 状态 | 含义 | 转换 |
| --- | --- | --- |
| 已签发 | 发往对应目标邮箱且仍有效 | → 已使用 / 已过期 / 已作废 |
| 已使用 | 此次验证与对应操作已完成 | 终态，不可重复使用 |
| 已过期 | 超过 `N-AL-03` | 终态，按原入口重新发码 |
| 已作废 | 同用途重新发码、超过错误上限、完成密码变更；或邮箱修改生效使旧邮箱找回验证码失效 | 终态，不再可用 |

验证码状态仅适用于找回密码与修改邮箱，不含邀请凭据。同一账号同一用途仅最新验证码有效，不能跨用途或目标邮箱使用；换新邮箱后旧目标的码不能用于新目标。密码变更导致会话全局失效时，未使用的验证码与滑块人机校验结果一并失效。

<a id="f-al-03"></a>
### 3.1 初始账密交付与首登强制改密（F-AL-03）

适用角色与前提：全部运营账号。流程见 [FL-AL-02](02-运营端账户与登录-流程图与状态机.md#fl-al-02)。

<a id="d-al-15"></a>`D-AL-15`：建设方交付初始邮箱与密码；所有新账号首次登录必须进入 `P-O-AL-03`，完成改密后才能使用业务功能。这是唯一路径，无邀请或开通方式选择字段。初始密码按既有规则线下交付，产品不通过邮件或站内消息下发明文密码。

<a id="d-al-16"></a>`D-AL-16`：建设方交付全部初始账号并按[本期预置角色（D-AL-08）](#d-al-08)配置角色和权限，是可登录使用的前提；产品无安装向导、自助初始化、账号维护界面。无法自助找回时，只能由建设方 / 运维在数据层重新初始化——这是本期已知限制，不是运营管理员的产品操作。

| 项 | 产品行为 |
| --- | --- |
| 触发 | 全部交付账号首次登录验证成功后立即进入 `P-O-AL-03`，不经过总览页 |
| 拦截范围 | <a id="e-al-07"></a>`E-AL-07`：未完成改密前，除本域、退出登录与语言切换外，运营端任何功能与任何业务动作都不可用；绕过界面直接发起业务动作同样被拒绝，不依赖界面拦截作为唯一防线 |
| 信息与动作 | 新密码、确认新密码（不再次输入当前密码，使用本次首登已验证身份）、密码规则实时校验结果；无任何勾选项；除退出登录与语言切换外不提供其他功能入口 |
| 密码校验 | 见 [3.5](#d-al-23)；新密码不得与初始密码相同，提交后给出对应校验结果 |
| 完成后 | 账号转为正常 `ST-AL-2`，初始密码失效 → 触发[密码变更通知](#f-al-18) → 全部会话失效 → 回到登录页重新登录 |
| 产品范围 | 不存在自助注册、机构入驻或申请开通入口；未登录访问任何受保护功能都被引导到登录页，不存在绕过登录的首次配置页或安装向导 |

### 3.2 工作邮箱与密码登录（F-AL-04）

<a id="d-al-14"></a>`D-AL-14`：工作邮箱 + 密码是唯一登录方式。无验证码登录、无钱包登录、无第三方登录、无自动建号、无协议勾选、无「记住我」。运营端没有连接钱包的业务场景：[运营端项目合约管理的通过并部署合约](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md#m3)中，放款合约与还款合约由平台签名地址部署，运营人员不连接钱包、不签名。

| 项 | 产品行为 |
| --- | --- |
| 入口 | 运营端任意受保护功能在未登录时均引导到本页，并记住原本要去的目标 |
| 信息与动作 | 工作邮箱、密码（可由本人切换显示或隐藏，保留无障碍名称与键盘操作）、登录动作、「忘记密码」入口、语言切换 |
| 校验失败 | <a id="e-al-01"></a>`E-AL-01`：邮箱不存在与密码错误返回完全一致的提示与可观察表现，不可从提示文案或响应快慢区分（[`D-AL-17`](#d-al-17)）；用未知邮箱登录不会自动创建账号。用户可走忘记密码，无法自助时联系建设方 / 运维 |
| 失败计数 | 密码错误计入失败计数（与账户设置内再认证共用同一计数器）；达到提示阈值 `N-AL-05` 后开始提示剩余次数；第一档锁定的提示中告知「若再次触发，锁定时间会更长」。详见 [3.12](#f-al-13b) |
| 账号状态分支 | 待首登改密 → 凭据验证通过后强制进入 `P-O-AL-03`；正常 → 进入落地页；锁定 → 仅在凭据校验通过后显示锁定提示与倒计时，到期表单自动恢复、无需刷新 |
| 首次登录成功 | 按浏览器推断并写入时区偏好，推断失败兜底 UTC（见 [3.10](#f-al-10)） |

### 3.4 忘记密码两步找回（F-AL-05）

适用角色与前提：任意访问者，入口在登录页「忘记密码」。流程见 [FL-AL-04](02-运营端账户与登录-流程图与状态机.md#fl-al-04)。

**第一步 `P-O-AL-04` 提交工作邮箱**

| 项 | 产品行为 |
| --- | --- |
| 顺序 | 输入工作邮箱 → 发起获取 / 重发验证码 → 滑块拼图人机校验（`C-O-AL-01`）→ 发送限频校验 → 向当前工作邮箱发送验证码。每次均按 [3.6](#f-al-13a) 执行，不得复用上次验证通过状态 |
| 提示文案 | 中性表述：「若该邮箱为运营端账号，验证码已发送」。已注册与未注册邮箱得到完全一致的响应，含可观察表现与响应快慢 |
| 滑块人机校验失败 | 按 [3.6](#f-al-13a) 就地给出失败反馈并自动更换题目，本次校验不结束；连续失败达 `N-AL-07` 进入冷却；不发码 |
| 限频超限 | 不发码，提示稍后再试或给出剩余等待时间；提示内容不因该邮箱是否存在而变化 |
| 发信失败 | 允许立即重试一次且不计入限频额度；该重试仍须重新通过滑块 |

**第二步 `P-O-AL-05` 设置新密码**

| 项 | 产品行为 |
| --- | --- |
| 前置 | 验证码校验通过 |
| 锁定判定时点 | <a id="e-al-13"></a>`E-AL-13`：必须在验证码校验通过之后，不得提前到输入邮箱或发码阶段——提前会重新打开账号枚举通道。锁定中则提示账号锁定与本次剩余时间，流程终止、不进入设置新密码，密码不变，用户等待锁定到期 |
| 验证码异常 | <a id="e-al-12"></a>`E-AL-12`：验证码错误、过期或超出单码错误上限时提示验证码无效，不透露账号是否存在；可重新输入或重发 |
| 信息与动作 | 新密码、确认新密码、密码规则实时校验结果 |
| 密码校验 | 见 [3.5](#d-al-23)，含「不得与原密码相同」「不得与初始密码相同」双重比对 |
| 成功后 | 新密码生效，触发[密码变更通知](#f-al-18)，全部会话失效，回到登录页 |
| 与首登的衔接 | 默认衔接口径：尚未完成首登改密的账号找回后仍为待首登改密，下一次登录继续进入 `P-O-AL-03`，找回不跳过强制首登环节 |
| 无法自助的兜底 | 当前工作邮箱不可达且无法登录时没有替代自助渠道，只能联系平台建设方 / 运维在数据层重新初始化（[`R-AL-02`](#risks)）；所有运营角色相同，本期不存在由运营管理员操作的恢复入口 |

<a id="d-al-23"></a>
### 3.5 设置密码的共同规则（D-AL-23）

适用于全部设置密码的入口：[首登强制改密](#f-al-03)、[忘记密码重置](#f-al-05)、[账户设置内修改密码](#f-al-08)。建设方交付的初始密码也须满足长度、复杂度和空格规则。

| 项 | 规则 |
| --- | --- |
| 长度 | 8～20 字符 |
| 复杂度 | 至少 1 个英文字母 + 1 个数字 |
| 空格 | 前后空格自动去除；中间不接受空格 |
| 与原密码 | 不得与原密码相同 |
| 与初始密码 | 不得与平台发放的初始密码相同 |
| 密码显隐 | 全部密码输入均可由本人切换显示或隐藏，保留无障碍名称与键盘操作 |
| 校验呈现 | 输入过程中实时表达各项规则是否满足（`C-O-AL-06`），全部满足方可提交；两次输入不一致时在确认密码处提示并阻止提交，改为一致后清除错误；不表达强弱分档 |
| 判定归属 | <a id="e-al-08"></a>`E-AL-08`：提交时校验与原密码、初始密码不同，不符合则由服务端拒绝变更并给出对应提示，原密码不变，用户换一个新密码 |
| 明文 | 除本人在密码输入框主动切换显示外，界面、日志、邮件和站内消息均不得泄露明文密码；初始账密由建设方按线下交付约定提供 |

<a id="f-al-13a"></a>
### 3.6 获取与重发邮箱验证码：滑块前置与发送限频（F-AL-13 之发码部分、D-AL-22）

<a id="d-al-22"></a>`D-AL-22`【用户已确认的强制要求】：忘记密码与本人修改邮箱的每次获取 / 重发邮箱验证码，均先完成 `C-O-AL-01` 滑块拼图校验，再检查发送限频，全部通过才发码。不能以之前通过、已登录或发送失败重试为由跳过；未通过、取消、加载失败、冷却中均不发码。共用流程见 [FL-AL-08](02-运营端账户与登录-流程图与状态机.md#fl-al-08)。

| 适用入口 | 发送目标 | 与业务流程的衔接 |
| --- | --- | --- |
| `P-O-AL-04` 忘记密码，含重发 | 当前工作邮箱 | 不新增验证码登录方式；验证码通过后才判定账号锁定 |
| `P-O-AL-06` 本人修改邮箱，含重发 | 此次填写的新邮箱 | 保留当前密码再认证和新邮箱校验；不要求旧邮箱验证码 |

| 环节 / 状态 | 产品行为与可验收结果 |
| --- | --- |
| 发起 | 验证码输入与获取 / 重发动作须同时可得，初始即可见；邮箱格式等前置校验通过后发起获取 / 重发即进入滑块拼图人机校验，尚不发码 |
| 校验中 | 用户须完成一次拼图对齐操作，释放后才判定；等待结果期间不能重复提交，不能凭拖动距离直接判定通过 |
| 通过 | 明确告知「验证通过 / Verified」并结束本次校验；随后检查发送限频，仅通过后才发码。滑块通过不等于邮件已发送 |
| 单次失败 | 提示「验证失败，请重试」并自动更换题目；本次校验不结束、不发码，可立即重新校验 |
| 连续失败 | 连续 3 次失败后提示可主动更换题目；连续 5 次失败进入 60 秒冷却（`N-AL-07`），校验不可发起并告知剩余时间；冷却中不能通过重新发起校验或刷新页面绕过限制，到期才可重新校验 |
| 关闭 / 取消 | 不发码，返回原办理上下文；获取 / 重发动作恢复可发起，已填邮箱和表单内容保留。再次获取仍须重新过滑块 |
| 题目加载失败 | 提示「加载失败，点击重试」，不发码、不告知验证通过，保留原表单；资源恢复后重新校验 |
| 结果适用范围 | 一次通过仅用于随后一次相同目标邮箱、相同发码用途及相同请求来源的发送，2 分钟内有效（`N-AL-13`）；已使用、过期或换邮箱 / 用途 / 来源均不能沿用。绕过界面发起发码也必须满足同样条件 |
| 获取、重发与发送失败重试 | 每次都重新通过滑块。邮件发送失败仍允许立即重试 1 次且不计发送额度，但该重试不免除滑块验证 |
| 发送限频 | 按 `N-AL-08` 的邮箱与网络 IP 额度（同一邮箱重发间隔 60 秒、24 小时内最多 10 次；同一 IP 每小时最多 20 次）；不同用途共享同一邮箱额度，不能通过换入口绕过 |
| 限频与发送结果 | 间隔未满时获取 / 重发不可发起并给出剩余时间；邮箱 24 小时额度超限给出可读等待时长，网络 IP 每小时额度超限提示稍后重试，均不发码。发送成功后进入重发倒计时；刷新页面不能重置等待时间；提示不因邮箱是否已有账号变化 |
| 可访问性 | 全程键盘可达：可聚焦、可用键盘完成位移与提交；提供更换题目与求助入口。无障碍替代方案仍按本期已知限制处理（[`R-AL-03`](#risks)） |

异常与边界：<a id="e-al-09"></a>`E-AL-09` 滑块失败、取消、加载失败或冷却中均不发码，分别按上表更换题目、返回原表单、加载重试或冷却倒计时处理，用户在原入口重试或等待，不绕过滑块；<a id="e-al-10"></a>`E-AL-10` 限频超限不发码，提示稍后再试或剩余等待时间，提示不因该邮箱是否存在而变化；<a id="e-al-11"></a>`E-AL-11` 邮件发送失败可立即重试一次且不计入发送额度，重试仍重新验证滑块。

滑块失败冷却与密码错误导致的账号锁定是两种状态，不将滑块失败计入密码失败次数。本册只定义用户行为和安全结果，不展开坐标、轨迹算法、票据字段或接口实现；滑块为自研人机校验，校验约束以本节及[可调参数（2.7）](#n-params)为准，其呈现与反馈形式按[统一条款](#design-boundary)由设计决定。

<a id="f-al-19"></a>
### 3.9 本人修改工作邮箱（F-AL-19）

<a id="d-al-25"></a>`D-AL-25`：允许本人修改为用户已确认，入口在账户设置；其中获取验证码前必须过滑块也是用户已确认要求。其余校验衔接沿用可调整的默认口径：当前密码再认证 → 填新邮箱 → 每次获取码先过滑块及限频，向新邮箱发送验证码 → 校验通过且本运营端内唯一后生效 → 向新旧邮箱发送安全通知。新邮箱生效后作为登录账号、找回密码与安全通知地址；失败或取消时旧邮箱继续有效。流程见 [FL-AL-07](02-运营端账户与登录-流程图与状态机.md#fl-al-07)。

| 项 | 产品行为 |
| --- | --- |
| 角色与前置 | 运营人员（本期即运营管理员）可在本人账户设置中修改；账号须正常且已完成首登改密，仅能修改本人的邮箱 |
| 入口与顺序 | 在账户设置的工作邮箱项发起「修改」→ 验证当前密码 → 填写新邮箱 → 发起获取 / 重发验证码 → 滑块拼图人机校验（每次均按 [3.6](#f-al-13a)）→ 发送限频校验 → 向新邮箱发验证码 → 输入验证码并提交；在本次办理内完成，不再叠加下一层办理 |
| 再认证 | 当前密码输错计入既有登录失败计数，达到阈值按既有阶梯锁定；再认证有效期沿用 `N-AL-10`，过期需重新验证，不能继续提交邮箱修改 |
| 新邮箱 | 邮箱格式、长度、去空格、大小写不敏感沿用 [2.3](#2-3-运营账号的业务字段)；不得与当前邮箱相同，须在本运营端内唯一。格式错误、相同或不可用时给出对应提示；不可用提示不暴露占用账号身份或状态 |
| 新邮箱验证 | 验证码只发往此次新邮箱，不要求旧邮箱收码。验证码规则、有效期、错误次数、滑块人机校验与限频均沿用既有参数；与找回密码的验证码不可混用。更换新邮箱后，原目标的验证码不可用于新目标 |
| 生效条件 | 当前再认证仍有效、验证码属于本人本次新邮箱修改且校验通过、账号仍正常、新邮箱在提交时仍唯一，全部满足才生效；期间被其他账号占用则拒绝变更并提示该邮箱不可用 |
| 成功结果 | 显示成功提示，账户设置及账号入口更新为新邮箱；之后仅新邮箱可用于本账号登录、找回与接收安全通知，旧邮箱不再是本账号登录或找回地址。账号身份、姓名、角色、权限及偏好保持原值 |
| 当前登录与旧验证码 | 默认保留现有登录状态，不因仅修改邮箱额外退出；发往旧邮箱但尚未使用的找回验证码失效，后续找回只认新邮箱；旧邮箱提交找回仍返回统一中性提示 |
| 安全通知 | 生效后向新旧邮箱各发一封安全通知，见 [3.14](#f-al-18) 与[消息通知册](03-运营端账户与登录-消息通知.md#nt-al-02) |
| 未成功 | <a id="e-al-18"></a>`E-AL-18`：验证码错误 / 过期 / 超过错误上限，账号锁定、再认证失效、发送失败、取消或未完成流程时，邮箱保持原值，不得提示修改成功；密码错误仍计入既有锁定规则。用户可按对应错误重新验证、填写其他邮箱或按限频重试 |
| 会话失效 | 操作期间登录失效时返回登录页，未生效的修改不保留为已完成；重新登录后重新发起修改 |
| 已知限制 | 旧邮箱不可达但仍能正常登录、完成当前密码验证时可自助换邮箱；密码丢失且当前邮箱不可达时，只能由建设方 / 运维重新初始化，无产品内他人改密或改邮箱入口 |

<a id="f-al-10"></a>
### 3.10 界面语言与时区偏好（F-AL-10、F-AL-11）

规则正文在三平台共享国际化基线（[`D-AL-18`](#d-al-18)），本节定义本模块的可观察行为。

| 项 | 产品行为 |
| --- | --- |
| 默认语言 | 界面默认英文，不读浏览器语言；语言切换（`C-O-AL-02`）在未登录与已登录状态下均须可得 |
| 切换即时生效 | 当前页面不刷新即完成全部文案替换，含各级功能入口、层级路径、轻提示、办理过程与倒计时；已填表单内容不丢失 |
| 偏好持久化 | 未登录态与已登录态双态持久化：未登录切换后关闭浏览器重开仍生效，已登录切换后换设备登录仍生效；退出登录后本地语言偏好保留 |
| 时区写入 | 首次登录成功时按浏览器推断并写入时区偏好，推断失败兜底 UTC；本人可在账户设置内改 |
| 时间展示 | 时间存 UTC；界面所有时间点按本人时区偏好展示并带时区标注 |
| 文案要求 | 无未翻译的硬编码文案；缺失翻译回落英文而非显示文案键名；中英两种语言下按钮与标签均不截断；角色称谓按 [`D-AL-30`](#d-al-30) |
| 通知 | 语言与时区偏好变更不产生任何通知（[`D-AL-27`](03-运营端账户与登录-消息通知.md#d-al-27)） |

<a id="f-al-12"></a>
### 3.11 会话有效期、无操作登出与全局失效（F-AL-12）

| 编号 | 口径 | 结论 |
| --- | --- | --- |
| <a id="d-al-19"></a>`D-AL-19` | 会话 | 会话绝对有效期与无操作自动登出时长按 `N-AL-09`（4 小时 / 30 分钟）；不提供「记住我」；无操作登出前给出续期确认，可选择继续保持登录或立即退出；继续保持登录只重置无操作计时，不延长绝对有效期，到达绝对有效期须重新登录 |
| <a id="d-al-20"></a>`D-AL-20` | 会话全局失效 | 退出登录、本人修改密码、重置密码、完成首登强制改密，该账号的全部会话（含当前设备）立即失效 |

| 项 | 产品行为 |
| --- | --- |
| 建立 | 登录成功时建立；待首登改密账号首登时建立的是受限会话，只能完成改密、退出登录与切换语言 |
| 「用户操作」的判定 | 只有真实的用户交互（点击、键盘输入、表单提交、导航跳转）才重置无操作计时；后台轮询、心跳、预取一律不计，否则无操作登出永远不会触发 |
| 失效范围 | 该账号的全部会话（含当前设备）；未使用的验证码与滑块人机校验凭据一并失效 |
| 失效后的表现 | <a id="e-al-16"></a>`E-AL-16`：停止受保护操作（语言偏好保留）、以轻提示告知原因、回到登录入口；同一浏览器标签页内记住原目标，在该标签页重新登录后返回原目标；刷新页面或在新标签页打开登录页时不保留原目标，登录后进入默认首页（总览页 `P-O-AL-07`）。同一浏览器多标签页一并失效，用户重新登录 |
| 后台请求遇到失效 | 与前台请求一视同仁触发统一的失效处理，不得静默忽略，避免「界面仍可操作、登录态已无」的假活状态 |
| 邮箱修改 | 默认保留现有会话，不因仅修改邮箱额外退出（[3.9](#f-al-19)） |

<a id="f-al-13b"></a>
### 3.12 失败计数与阶梯锁定（F-AL-13 之锁定部分）

<a id="d-al-21"></a>`D-AL-21`：连续密码校验失败达阈值后账号锁定。锁定期间不可登录；忘记密码可收到验证码但不能完成——验证码正确后告知账号锁定与剩余时间并终止，密码不变。无提前解除通道，到期自动解除；锁定时长按阶梯递进。

| 项 | 产品行为 |
| --- | --- |
| 计数范围 | 登录页密码错误与账户设置内当前密码再认证失败共用同一计数器；滑块失败不计入密码失败次数 |
| 提示 | 失败次数达 `N-AL-05` 后开始提示剩余次数；第一档锁定的提示中告知再次触发时间会更长 |
| 锁定阶梯 | 锁定时长按 `N-AL-02` 阶梯递进：首次 15 分钟、再次 30 分钟、之后每次 60 分钟；仅登录成功后阶梯归零、回到第一档 |
| 锁定表现 | <a id="e-al-02"></a>`E-AL-02`：账号锁定后不可登录，忘记密码不能完成（见下行锁定与找回）；登录页内展示剩余时间并实时倒计时，归零后表单自动恢复可用、无需刷新。用户只能等待锁定到期 |
| 锁定与找回 | 锁定账号仍可收到找回验证码邮件，但验证码正确后被告知锁定与剩余时间，流程终止，密码不变（[忘记密码两步找回（3.4）](#f-al-05)） |
| 通知 | 账号锁定与自动解除均不发通知（[`D-AL-27`](03-运营端账户与登录-消息通知.md#d-al-27)），由当事人从登录提示感知，并保留安全留痕 |

<a id="f-al-17"></a>
### 3.13 按权限收敛入口与越权处理（F-AL-17）

适用角色与前提：全部已登录运营账号。本节是各业务模块共同遵守的权限底线；某项业务功能要哪些权限、组合与角色可用范围，由该功能所属模块定义（[权限组织方式（D-AL-07）](#d-al-07)）。

| 规则 | 口径 |
| --- | --- |
| 配置责任 | 建设方交付账号、角色绑定和初始授权；运营人员可查看本人角色，不展示权限清单。产品无新增账号、授权调整、停用 / 启用或他人改密入口 |
| 状态前提 | 仅正常、已完成首登改密且登录有效的账号，业务权限才生效；待首登改密、锁定状态不可执行业务动作，即使此前已被授权 |
| 界面与动作一致 | 未授权功能入口不出现，绕过界面发起相同动作仍被拒绝 |
| 越权表现 | <a id="e-al-15"></a>`E-AL-15`：统一提示无权限，不透露该功能下是否存在具体业务记录；配置问题联系建设方核对交付结果 |
| 缺必须配套的权限 | 所属模块要求配套的权限缺失时，对应动作被拒绝，并说明须由建设方修正交付配置；不静默通过，不自动补授权 |
| 部分可用时的入口 | 某模块只对账号开放其中部分能力时，该模块入口仍须能到达这部分能力；不借入口开放其他动作，具体由所属模块定义 |
| 角色差异 | 本期只有运营管理员，固定具有全部业务权限（[`D-AL-08`](#d-al-08)）；账号管理权限不属于本期任一角色 |
| 数据可见范围 | 同一主体不按机构隔离（[`D-AL-05`](#d-al-05)）；在该权限和业务对象允许范围内查询，不自动获得其他权限下的数据，也不扩大到他人账户档案或本人安全消息 |
| 不存在的过滤 | 「只看与本机构相关的项目」「只看本人负责的申请」「按机构切分的数据域」本期均不存在，也不预留机构字段（[`D-AL-06`](#d-al-06)） |
| 与面客端的关系 | 运营人员仅查看其职责已明确允许的业务信息，不因同主体取得面客私人档案或付款资料，也不能以运营身份代替资产方 / 资金方办理 |
| 从消息或记录跳转 | 消息或记录本身可读，不代表目标可读；打开目标时按目标所属模块的权限重新判定，无权时按 `E-AL-15` 提示并可返回 |

<a id="f-al-18"></a>
### 3.14 账户安全通知（F-AL-18）

本模块只定义发什么、何时发；站内消息的承载、未读语义与可见范围归 WS-383。完整事件定义、收件范围、文案要素与异常见[消息通知册](03-运营端账户与登录-消息通知.md)。

| 事件 | 触发时点与收件范围 |
| --- | --- |
| [密码变更通知](03-运营端账户与登录-消息通知.md#nt-al-01) | 首登强制改密、忘记密码重置、账户设置内本人改密三种情形均触发；邮件与站内消息告知本人，触发时点为新密码生效之后、会话批量失效之前 |
| [邮箱变更安全通知](03-运营端账户与登录-消息通知.md#nt-al-02) | 本人修改工作邮箱生效后，向新旧地址各发一封安全通知邮件；投递失败不回滚已生效的修改 |
| [账户功能邮件（验证码）](03-运营端账户与登录-消息通知.md#nt-al-03) | 找回验证码发往当前工作邮箱，修改邮箱验证码发往新邮箱；文案中性，不透露账号信息，无一键登录链接，验证码不出现在邮件主题与预览文本中 |

通知不含密码或验证码原文以外的账号信息；账号锁定、自动解锁、登录成功 / 失败、语言与时区偏好变更均不发通知。<a id="e-al-19"></a>`E-AL-19`：邮箱修改后新或旧地址的安全邮件投递失败，不回滚已生效邮箱、不误报验证失败；与「验证邮件未完成验证则不得生效」是两件事，已生效的新邮箱继续作为登录与找回地址。

<a id="overview-shell"></a>
### 3.15 运营端总览入口（`P-O-AL-07`）

登录成功后的默认落地目标，本模块负责登录回跳及账号准入。[运营端总览](../08-运营端总览/01-运营端总览-PRD.md)定义本页的统计、待办及数据读取规则；已登录用户可从[运营端业务菜单](#ops-menu)的“总览”进入同一总览。页面标识沿用本值，统计口径与来源权限不在账户册重复定义。

| 功能权限项 | 运营能力的授权单位，由所属业务模块定义；本模块只定义[本人账户设置（PM-AL-14）](#pm-al-14)，为全员固定开通 |
| SPV 机构 | 与运营机构同一家主体（[`D-AL-03`](#d-al-03)）。不是账号类型、不是数据域，界面上不作为账号类别出现 |
| 首登改密 | 账号从待首登改密转为正常的唯一产品流程，由 `P-O-AL-03` 完成 |
| 全局失效 | 使某账号的全部会话（含当前设备）立即失效 |

**本模块不定义**：各业务动作的审核规则、结果口径、状态流转及其功能权限（WS-381 / WS-383 / WS-384 / WS-387 / WS-388 / WS-439 / WS-464）；站内消息的承载、未读语义与可见范围（WS-383）；语言、时区、数字、金额、链上地址与哈希、脱敏口径的正文（三平台共享国际化基线）；运营端各业务模块的功能入口与业务内容（各业务模块自行登记）。
