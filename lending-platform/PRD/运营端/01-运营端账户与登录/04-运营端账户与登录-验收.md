# 运营端账户与登录 · 验收

2026-10-23｜需求评审稿｜供测试使用

本册只列验收标准，业务规则见[功能与业务规则](01-运营端账户与登录-PRD.md)；一条验收包含多个场景时全部满足才算通过。编号沿用原值，缺号不代表遗漏。

## 验收前准备

- 账号：待首登改密、正常、各档锁定和会话失效的运营管理员账号；未知工作邮箱。
- 数据：密码、邮箱与验证码边界、滑块失败、限频、邮件投递异常、原目标访问及安全通知样本。

<a id="4-验收需求"></a>
## 验收标准

与第 3 节同序。每条验收映射到对应功能，与功能正文冲突时以功能正文为准；本节给出业务行为与可观察结果，不含测试执行步骤与用例数据。

**全章适用的业务前提**：运营管理平台是独立部署单元；运营账号与代币发行平台运营端、借贷面客端均不共用；SPV 机构与运营机构是同一家主体，运营端只有一套账号体系、不做机构级数据隔离。

## 6. 获取与重发邮箱验证码

对应功能：[获取与重发邮箱验证码](01-运营端账户与登录-PRD.md#f-al-13a)。

两入口均须覆盖：`P-O-AL-04` 忘记密码、`P-O-AL-06` 修改邮箱；首次获取、重发和邮件发送失败后的重试均适用。

| 编号与场景 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| <a id="ac-al-122"></a>`AC-AL-122` | 本节功能适用的账号与数据 | 发起获取 / 重发，完成拼图对齐并释放 | 未通过前不发码；对齐并通过后明确告知验证通过、结束本次校验，然后检查限频；拖到末端本身不代表通过 |
| <a id="ac-al-123"></a>`AC-AL-123` | 单次失败，继而连续失败达到提示及冷却阈值 | 查看或办理获取与重发邮箱验证码 | 单次失败给出失败反馈并自动更换题目，本次校验不结束；连续 3 次提示可主动更换题目，5 次进入 60 秒冷却，校验不可发起并倒计时；刷新或重新发起不能绕过，到期才可重新校验 |
| <a id="ac-al-124"></a>`AC-AL-124` | 验证前取消滑块校验 | 查看或办理获取与重发邮箱验证码 | 不发码，返回原办理上下文，保留已填内容、获取 / 重发恢复可发起；再次发起仍需滑块 |
| <a id="ac-al-125"></a>`AC-AL-125` | 校验题目加载失败 | 查看或办理获取与重发邮箱验证码 | 明确提示加载失败并可重试，不发码、不告知通过；原表单仍保留 |
| <a id="ac-al-126"></a>`AC-AL-126` | 无有效通过结果、已使用或超过有效期后发码，或换目标邮箱 / 用途 / 请求来源 | 查看或办理获取与重发邮箱验证码 | 均被拒绝，重新验证后才能按新目标 / 用途发码；每次获取与重发仅可使用本次有效通过结果，不能绕过界面限制 |
| <a id="ac-al-127"></a>`AC-AL-127` | 滑块通过，但邮箱或网络 IP 发送限频超限 | 查看或办理获取与重发邮箱验证码 | 不发码；间隔以剩余时间表达，邮箱 24 小时额度超限为可读等待时长，网络 IP 超限提示稍后再试；刷新后等待仍准确，提示不区分邮箱是否已有账号 |
| <a id="ac-al-128"></a>`AC-AL-128` | 同一目标邮箱在不同用途间 | 切换获取码 | 仍共享同一邮箱发送额度，不能多得一次额度或跳过滑块 |
| <a id="ac-al-129"></a>`AC-AL-129` | 滑块通过后邮件发送失败，再次 | 获取 | 允许立即重试一次且不计发送额度，但仍须重新过滑块；成功才进入发送成功 / 重发倒计时状态 |
| <a id="ac-al-130"></a>`AC-AL-130` | 键盘使用滑块与求助 | 查看或办理获取与重发邮箱验证码 | 全程键盘可达：可聚焦、可位移、可提交；更换题目和求助入口可达，中英文的通过、失败、冷却及加载异常提示一致 |
| <a id="ac-al-131"></a>`AC-AL-131` | 滑块失败、邮箱验证码输错及锁定账号找回 | 查看或办理获取与重发邮箱验证码 | 滑块失败走自身冷却、验证码错误走单码上限，不计入密码失败次数；找回仍仅在验证码正确后告知锁定，不能将滑块提前校验变成账号枚举提示 |

获取新邮箱验证码前先过滑块为用户已确认要求；其余衔接按 [3.9](01-运营端账户与登录-PRD.md#f-al-19) 既有默认口径验收。「允许本人修改」不是待确认项。

| 编号与场景 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| <a id="ac-al-44"></a>`AC-AL-44` | 运营管理员 | 查看本人账户设置 | 可发起本人邮箱修改，无修改他人邮箱入口；每次获取新邮箱验证码必须过滑块 |
| <a id="ac-al-111"></a>`AC-AL-111` | 正常且已完成首登改密的本人，当前密码正确 | 查看或办理本人修改工作邮箱 | 再认证通过后可填新邮箱；密码错误计入既有失败次数，达阈值锁定；再认证过期必须重新验证 |

## 16. 非功能与安全

| 维度 | 要求 |
| --- | --- |
| 性能 · 首次可交互 | 登录入口首次可交互 ≤ 2s（正常网络，目标值） |

| 浏览器兼容 | Chrome / Edge / Firefox / Safari 最近两个大版本 |
| 多终端 | 登录、首登改密、找回、账户设置全流程在桌面与移动端均可完整完成，关键信息不丢失；滑块人机校验支持触屏操作。具体断点与呈现由设计决定 |

| 可访问性 | 表单标签可关联、键盘全流程可达、对比度符合 WCAG AA、仅以图形表达的动作可被读屏识别、轻提示可被读屏播报 |
| 已知无障碍缺口 | 滑块人机校验不提供无障碍替代方案，且运营端没有第二条找回路径。缓解：滑块支持键盘操作；校验过程中提供求助入口，不静默失败；依赖读屏的运营人员可由建设方 / 运维在数据层重新初始化（[`R-AL-03`](01-运营端账户与登录-PRD.md#risks)） |
| 可观测 | 首登改密完成率、登录成功率、发码成功率、邮件送达率、锁定触发量与档位分布需可监控 |
| 部署前置 | 建设方交付初始账号、角色绑定与权限配置是系统可用的部署前置条件，须写入部署清单并在上线检查中确认 |
| 部署前置 | 运营端发信地址的域名认证配置须在首次发信前完成，与另两个平台分开维护 |
