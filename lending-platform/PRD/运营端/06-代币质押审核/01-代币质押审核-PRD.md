## 1. 目标与阅读入口

资产方在已通过审核的融资项目内选定代币，**由该代币的持有地址签名，向质押合约发起质押上链**。上链成功才形成一笔待审质押申请：代币此时已在质押合约内，计入总质押额与待审质押额，但**尚不计入有效质押额**。运营人员在运营管理平台逐笔审核，**通过才计入有效质押额**；驳回后由资产方自助解押。审核**不设时效管控**。

本期包含：单笔审核队列与统计筛选、单笔事实与项目/批次上下文、逐笔通过与协议维护、逐笔驳回与唯一结论、待审撤回与解押的只读追踪、质押上链与占用事实的只读追踪、权限留痕与通知触发。相邻模块负责：面客质押发起与解押办理、项目与额度口径（融资需求与代币质押），项目审核与合约部署（运营端项目合约管理），代币类型的最高质押率与最长项目期限（运营端融资参数配置），面客站内消息的阅读入口与未读语义（面客消息中心），功能权限矩阵与账号状态（运营端账户与登录）。本期不包含第 [1.2 节](#1-2-本期不包含) 各项。

有效依据（用户已确认）：质押上链由资产方以代币持有地址签名发起，gas 自担、失败不退；上链后先不计入有效质押额，须审核通过才计入；**审核无时效管控**；待审期间资产方可自由撤回，自行向质押合约发起申请、自付 gas，合约按记录转回质押前原持有地址；审核驳回后资产方自助解押，路径相同；未解押的代币一直留在质押合约内，不允许用于其他项目质押；运营人员不签名，只做业务操作；先建池并通过审核，才能发起质押。运营端本期只有运营管理员一个角色（2026-10-08）；代币质押审核的功能入口放在项目合约管理（含项目审核）之后（2026-10-14）；资产方撤回所发起的解押处理中时暂不可裁定，解押成功转为已撤回、失败恢复为可裁定（2026-10-14）；项目进入终态时仍待审核的笔无需再审核，直接关闭并说明原因（2026-10-14）。沿用的既有口径：同批可有不同结论、逐笔独立；异常一律提示联系平台客服人员，不实现异常处置；业务日期统一 UTC、具体时点按用户偏好时区展示；单笔详情以按发生时间倒序的操作记录承载本笔全部事实；通过在本次办理内一次提交；已上传文件须可预览与下载。

阅读顺序：第 2 章角色、对象与共同口径 → 第 3 章完整功能 → 第 4 章同序验收 → 第 5 章依赖、既定限制与待决。

<a id="d-pr-29"></a>
### 2.1 审核对象与角色

`D-PR-29`【逐笔审核的统一来源】：

| 对象 | 含义与范围 |
| --- | --- |
| 提交批次 | 资产方一次质押发起形成的分组；同一资产方、同一融资项目、同一申请类型及发起时间，沿用面客的提交批次编号与关联信息。批次含一笔或多笔 |
| 单笔质押申请 | 批次内**一张代币的一次质押申请**，**以该张代币上链成功为成立前提**。具有稳定单笔标识，关联批次与代币编号；是审核、撤回、协议、原因、解押和通知的最小单位。标识的编码格式不在 PRD 定义 |
| 单笔审核结论 | 每笔至多一个有效人工结论：通过 / 驳回；时间、审核人、协议或原因各自独立。未审、撤回与项目终态关闭都没有伪造的人工结论 |
| 代币在合约内的留存 | 上链成功起，该张代币留在质押合约内并占用，直到资产方自助解押成功、按记录转回质押前原持有地址。留存是链上事实，以本笔当前去向（[2.4 节](#states)）表达，与审核结论分开记录 |
| 批次进度 | 只做单笔事实的数量汇总，不再有统管全批的通过 / 驳回结论、审核人、结论时间或原因，见 [2.4 节](#states) |

同一批次内一张代币只能出现一笔，仍为整张质押，不拆数量。上链失败不形成申请，也不进入审核队列；该次 gas 已消耗且不退还，由资产方承担。再次质押是新的发起及新的单笔标识，保留与原记录的关联，不复用原结论。同一代币在不同发起中的记录不可仅凭代币编号合并。单笔审核态属于质押业务申请，不写回代币本体。

| 参与方 | 本模块责任 |
| --- | --- |
| 运营人员 | 按功能权限查看全部单笔；在线下判断后，在线逐笔提交证据与结论。**不签名、不代付 gas、不发起或撤销任何链上动作**；不按运营机构隔离 |
| 资产方 | 以代币持有地址签名发起质押上链并自担 gas；查看每笔结论；待审期间可自行向质押合约发起撤回；驳回后自助解押。解押成功前该代币不可用于其他项目质押 |
| 借贷平台 | 拥有申请、质押记录与三项额度的派生；提供审核结果消费、有效质押价值与有效质押额的重算 |
| 代币发行平台 / 质押合约 | 承载链上事实：质押转入、合约内留存与解押退回；按张提供结果，运营审核无代币维护权 |

本期两个信息域：审核队列（`P-O-PR-01`）、单笔审核详情（`P-O-PR-02`，可查看项目与批次上下文）；编号与归属不变，承载形式由设计决定。<a id="entry-order"></a>**功能入口位置**：本模块入口挂在管理端共享导航中，紧接在项目合约管理（含项目审核）之后，二者是两个独立入口、两条队列（用户 2026-10-14 确认）；入口可见性按 [2.2 节](#d-pr-05)权限判定，导航的承载与样式由设计决定。保留协议上传、历史、通知与链上事实只读追踪；异常仅提示联系平台客服。

<a id="d-pr-37"></a>
### 2.3 时间、日期与金额口径

`D-PR-37`【统一业务日期与展示】：

- **业务日期边界**：近七个自然日统计、按日期筛选等统一 UTC；日期筛选需让操作者识别其 UTC 口径。
- **展示**：具体时点按用户偏好时区显示并标注。切换显示时区、跨周末或夏令时不改变已发生事实、统计归属或事件先后。
- **无审核时效**：审核不设截止、不设倒计时、不因时间流逝改变任何审核状态；等待时长只作事实陈述，不构成期限（[`N-PR-02`](#n-pr-02)）。
- **金额**：代币价值为 USD 两位小数，gas 与费用用实际发生币种；未知不填 0，不编造数币精度。

### 2.4 状态、额度与外部口径

`RV-20`【单笔审核轴】枚举，必有，默认待审核：**待审核 / 通过 / 驳回 / 已撤回 / 已关闭**（五类）。通过和驳回是人工结论；撤回是资产方在待审期间自行发起链上解押并成功后形成的终结事件；已关闭是所属项目进入终态时对仍待审核的笔作出的系统终结，附关闭原因，不是人工结论（[`D-PR-41`](#d-pr-41)）。审核轴不因时间流逝自动改变。审核轴与代币在合约内的去向是两条独立的轴：后者取面客[本笔当前去向 `PA-15`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#pa-15) 的取值，本册只读消费、不另造一套。

| 对象与状态 | 触发及允许行为 |
| --- | --- |
| 单笔待审核 | 上链成功后未终结；有权限可随时裁定，无截止；资产方可自行发起撤回。**撤回所发起的解押处理中时暂不可裁定**，解押失败即恢复可裁定（[`D-PR-40`](#d-pr-40)） |
| 单笔通过 | 在通过办理内一次有效提交且协议齐备；该张随即计入有效质押价值并触发有效质押额重算，运营不得二次裁定 |
| 单笔驳回 | 有效提交驳回且原因齐备；保留记录，该张不计入有效质押额，仍留在质押合约内直至资产方自助解押 |
| 单笔已撤回 | 资产方在待审期间自行向质押合约发起并解押成功；无人工结论，平台不收费，gas 由资产方承担 |
| 单笔已关闭 | 所属项目进入终态（已关闭或已结清）时本笔仍待审核；不再审核，系统直接关闭并记录关闭原因与关闭时间；无人工结论、无审核人，不可补裁定。代币此后的去向待用户裁定（[`Q-PR-15`](#q-pr-15)） |
| 本笔当前去向：待审核 | 上链成功、尚未裁定；计入待审质押额的待裁定分项 |
| 本笔当前去向：已计入有效质押额 | 审核通过且满足有效性等既有条件；代币继续在合约内 |
| 本笔当前去向：待自助解押 | 审核已驳回、资产方尚未发起解押，或解押失败后待再次发起；计入待审质押额的已驳回分项，不可用于其他项目质押 |
| 本笔当前去向：解押处理中 | 资产方已发起解押、尚无确认结果；不得重复发起，不推定成功或失败 |
| 本笔当前去向：已解押退回 | 解押成功、代币按记录转回质押前原持有地址；该张退出总质押额与待审质押额，按当前资格可再质押 |
| 差异 | 并列事实标记，不覆盖人工审核结论；异常仅客服指引，本期没有差异关闭或恢复动作 |

<a id="d-pr-31"></a>`D-PR-31`【批次汇总】：审核进度仅使用"待审核"（全部未处理）、"审核进行中"（仍有待审且至少一笔已终结审核）、"审核已结束"（无待审）。同时列待审、通过、驳回、已撤回、已关闭**五类**笔数，合计等于该批总笔数；"审核已结束"不等于全部通过。去向摘要另列待自助解押、解押处理中、已解押退回的笔数，差异为可叠加标记、不重复加总。尚无明确解押结果的张不能算入已解押退回。

<a id="quota"></a>**三项额度与审核动作的关系**（名称与公式的权威定义归[融资需求与代币质押](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)，编号锚点不变，本册只消费、不自行定义）：

| 额度 | 本册消费口径 |
| --- | --- |
| 总质押额（[`FP-10`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-10)） | 本项目质押合约内全部代币的签发价值合计，**含失效代币与尚未通过审核的代币**；只作展示，不参与准入。上链成功即计入，解押成功即退出 |
| 待审质押额（[`FP-32`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-32)） | **已在本项目质押合约内、尚未计入有效质押价值**的签发价值合计，同时涵盖：①审核尚未裁定的；②审核已驳回但尚未解押的。两者对额度的影响相同，故合成一个数值；但两者下一步动作不同（待审可等待或撤回，已驳回需解押），**明细必须能区分这两种状态**，不能只给一个合计数 |
| 有效质押额（[`FP-12`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-12)） | ＝有效质押价值（`FP-11`）× 项目质押率（[`FP-34`](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-34)）。有效质押价值为同时满足审核通过、实际转入成功、发行平台判有效、无对账差异、未撤回预扣的在池价值；底层资产失效的部分不计入 |

各审核动作与链上动作对三项额度的影响只在[占用与解除的语义边界（D-PR-27 / D-PR-32）](#d-pr-32)定义一次。运营审核动作只产生结论，不直接改写代币事实、质押状态或链上执行状态；这些由借贷平台与发行平台维护，本册只读消费，其状态号不出现在界面文案。

<a id="chain"></a>**两处链概念分开表述**：本模块涉及的是**质押链**——代币与质押合约所在链，本期仍为 ETH；质押上链、合约内留存与解押退回均发生在质押链，转回地址即该代币质押前的原持有地址，平台不能人工指定其他地址。**结算收款链**（数币收款地址所在链，本期支持 ETH 与 TRON）与本模块无关，审核不读取、不校验、不展示结算收款地址。

状态图见[单笔审核轴](./02-代币质押审核-流程图与状态机.md#st-pr-01)与[本笔当前去向与自助解押](./02-代币质押审核-流程图与状态机.md#st-pr-02)。

### 3.1 单笔审核队列（`F-PR-01`～`05`）

前置为正常运营账号且有代币质押申请查询权限，从[功能入口](#entry-order)进入。队列中**一条记录对应一笔已上链成功的代币质押申请**，不是一个批次；同批关系可识别。本队列独立，不依附已移交的代币管理，只提供查看，不提供多选裁定。上链失败的发起不产生记录。

<a id="d-pr-34"></a>`D-PR-34`【操作记录与进度的统一来源，覆盖 `F-PR-06`、`08`、`13`、`18`】：单笔审核详情须使申请信息、代币与链上事实、审核结论与凭据、操作记录同处可得。操作记录是本笔全部事件与后续进度的唯一来源，不另设第二套进度来源或重复的明细。关联申请保留原入口；来自旧操作记录入口的访问仍定位到本笔操作记录，不丢失单笔标识，返回时保留队列原有的筛选、分页与所在位置。队列的本笔当前去向筛选、当前状态摘要与操作记录同源。事件与结果须可辨，操作人与时间为附随信息；原因、实际 gas 与凭据须可完整取得。记录按发生时间倒序。

| 记录内容 | 含义与信息要求 |
| --- | --- |

| 关联凭据 | 有则提供对应本笔的协议或链上凭据，遵守权限及文件规则；没有则说明暂无，不伪造材料或重复关联其他申请 |
| 记录反馈 | 加载中、暂无记录、读取失败须分别说明；失败可重试且不伪装为空。记录只读，不提供编辑、删除或手工完成进度动作 |

历史事件与当前进度均可查，新增进度不覆盖原审核事实；同一业务事件重复到达只保留一条，不因重新取数重复生成。关联申请历史与本笔操作记录范围分开。流程见[操作记录与后续进度的查看](./02-代币质押审核-流程图与状态机.md#fl-pr-04)。

<a id="d-pr-15"></a>`D-PR-15` / `D-PR-16`：额度派生量只读，本模块不提供任何调整入口；审核不读取或修改额度公式本身。代币失效、项目终结显示客观事实，不自动替审核人驳回。**审核通过是该张计入有效质押价值的必要条件，不是充分条件**——是否实际计入仍由借贷平台按有效性等既有排除项判定，本模块如实展示判定结果而不预告。

### 3.3 逐笔通过与协议维护（`F-PR-09`、`10`）

<a id="d-pr-01"></a>`D-PR-01`：每次审核针对当前单笔。可以只通过批次内 A、驳回 B、保留 C 待审；不再要求整批同结论。通过 A 不代表批准 B/C，其他笔无需重新发起。本期不提供一次点击为多笔生成结论。

<a id="d-pr-35"></a>`D-PR-35`【通过直接提交】：前置为有查询与处置权限，**当前笔仍待审核、不在解押处理中、所属项目未进入终态**（无截止条件）。线下判定后的通过办理（`C-O-PR-01`）依次为：回显本笔代币、项目、批次与链上事实 → 上传本笔适用协议 → 可填内部备注 → 确认知悉本次结论的业务后果 → 提交。通过在本次办理内完成、不再叠加下一层办理，也没有"核对结论 / 确认审核结论"的后续步骤，不新增第二位审核人。此路径不改变逐笔驳回的原因预览与二次确认。

提交前取消不产生结论，跨笔不携带材料；提交中明确反馈且不可重复点击。材料、权限或状态不满足时就地说明，不产生通过记录；办理中途本笔进入解押处理中或被关闭的，提交被拒并说明原因，已填输入保留；保存失败保留当前笔有效输入可重试。结果不确定先查当前事实，不展示成功或引导重复裁定。成功后结束本次办理并回到本笔详情，结论与操作记录出现本次通过，当前笔只读，其他待审笔仍可办理。

### 3.4 逐笔驳回与唯一结论（`F-PR-11`、`12`）

前置与通过相同。本笔"驳回"打开驳回办理（`C-O-PR-02`）：回显本笔代币 → 填原因，可选归类 → 完整预览 → 二次确认对象及原因 → 提交。

<a id="d-pr-02"></a>`D-PR-02` / `D-PR-10`：驳回只结束本笔审核，原因针对本笔；同批 A 通过、B 驳回、C 待审是正常结果。**驳回不自动解押**——该张仍留在质押合约内并占用，由资产方自助解押；驳回本身不产生平台费用，解押 gas 由资产方承担。

| --- | --- |

| `RV-12` 问题代币标注 | 本笔代币只读回显，取[`RV-19`](#rv-19)所关联代币，不再从全批勾选问题子集；不能借此驳回其他笔 |

<a id="d-pr-12"></a>`D-PR-12`：两端按稳定单笔标识同步该笔结论、时间、原因；批次仅汇总。不因某笔结论而覆盖批次其余笔的待审、驳回或通过结果。已撤回、已关闭或已有人工结论的笔不能再裁定，处于解押处理中的待审笔暂不可裁定，已打开的旧办理提交亦拒绝。驳回不触发链上动作；已上链事实与占用只读展示，本期不提供由运营发起的强制解押，不把已通过改成驳回来启动新动作。

<a id="m5"></a>
### 3.5 等待时长、待审撤回与解押（`F-PR-14`～`15`、`F-PR-19`）

<a id="n-pr-02"></a>`N-PR-02`【已等待时长】：待审笔从上链成功起计；不足 1 小时按分钟、不足 24 小时按小时、之后天＋小时。等待时长是**事实陈述，不是期限**：不设截止、不倒计时、不触发任何自动状态变化，也不构成催办依据。人工结论或撤回生效即停止计时。

<a id="d-pr-08"></a>`D-PR-08`【审核无时效管控】：用户 2026-09-24 确认审核不设时限。待审笔可无限期停留在待审核，只能由人工结论或资产方撤回终结；不存在审核截止、到期自动失败、迟到补审拒绝或超时通知。原按 48 小时定义的截止、超时事实与自动终结条款一并废止，见 [5.4 节](#retired)。

<a id="d-pr-23"></a>`D-PR-23`【终结方式收敛】：单笔只有四种终结方式——通过、驳回、资产方撤回、项目终态关闭。任何时间流逝都不改变审核状态。正在上传、提交尚未生效、线下已决定但未在线提交均不算已审核；已生效撤回或关闭后不能补裁定，已有人工结论后撤回不再适用于审核轴。每笔只有一个有效审核结果，以先生效者为准，不影响同批其他笔。

**待审撤回**：资产方在待审期间可自行向质押合约发起解押申请，自付 gas，合约按记录将该张转回其质押前原持有地址。撤回不经运营审批、不需要运营在本模块执行任何动作；解押成功即本笔审核状态转为已撤回，占用解除。撤回与审核同笔竞合只生效一个结果——若人工结论已先生效，本笔按结论处理，已通过的不能借撤回取消结论，此后的转出按面客[解除质押](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#withdraw)规则办理；其他笔照常。

<a id="d-pr-40"></a>`D-PR-40`【撤回解押处理中暂不可裁定】：资产方对待审笔发起撤回后，本笔去向为解押处理中，此期间运营**暂不可裁定**——不提供可执行的通过 / 驳回，办理中途进入该状态的提交被拒并说明"资产方撤回处理中"，已填输入保留。解押**成功**即本笔转为已撤回，不可再裁定；解押**失败**即本笔恢复待审核、可正常裁定，去向回到待审核，gas 不退。结果待核实时保持暂不可裁定，按 [`D-PR-38`](#d-pr-38) 提示联系客服。这样不会出现链上已经转出、又要撤销人工结论的情况。人工结论已先生效、此后才发起的转出不属本条，按面客[解除质押](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#withdraw)规则办理。

<a id="d-pr-41"></a>`D-PR-41`【项目终态时关闭待审笔】：所属项目进入终态（[已关闭或已结清](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-23)）时，本项目仍待审核的笔**不再审核，由系统直接关闭**，审核状态转为已关闭：

- 记录关闭时间（取项目进入终态的时刻）与关闭原因"所属项目已关闭"或"所属项目已结清"，并带出项目的关闭原因（`FP-23`）；关闭原因在本笔详情、操作记录与面客本笔记录中可见。
- 无人工结论、无审核人、不产生协议关联；不可补裁定，已打开的办理提交被拒并说明本笔已关闭。
- 已有人工结论（通过 / 驳回）或已撤回的笔不受影响，保留原结果。
- 关闭时处于解押处理中的待审笔同样关闭；此后解押的真实结果只更新去向，不把已关闭改为已撤回。
- 关闭不触发链上动作、不产生平台费用。关闭后代币的去向与后续办理待用户裁定，见 [`Q-PR-15`](#q-pr-15)；在裁定前本册不规定其额度归属与去向取值。

<a id="d-pr-24"></a>`D-PR-24`【驳回后的自助解押与再质押】：驳回记录保留；该张仍在质押合约内，资产方按与撤回相同的路径自助解押，自付 gas，合约按记录转回质押前原持有地址。**解押成功前该代币不允许用于其他项目质押**（既定业务限制，见 [5.2 节](#limits)）。解押成功后，按最新资格可重新发起质押到同一或其他项目，无冷却；旧笔不恢复、不删除，新笔新标识、新上链时点。其他独立占用、失效或差异仍约束可选性。

例如同批 A 已通过、B 已驳回、C 仍待审：A 的代币按有效质押价值口径计入并继续占用，B 的代币在解押成功前仍占用且计入待审质押额的已驳回分项，C 无限期等待直到被裁定或撤回。零费用的表述只指平台不收费，不代表资产方未承担 gas。图见[单笔审核轴](./02-代币质押审核-流程图与状态机.md#st-pr-01)。

<a id="m6"></a>
### 3.6 质押上链事实与解押追踪（`F-PR-18`）

<a id="d-pr-25"></a>`F-PR-18` / `D-PR-25`【只读追踪的范围】：本模块对链上事实只读追踪，不提供任何发起、重试、撤销或代付能力。可追踪的链上事实有两类：**质押上链**（该张进入质押合约，是本笔申请成立的前提）与**自助解押**（撤回或驳回后由资产方自助发起，成功即按记录转回质押前原持有地址）。两类都由资产方以持有地址签名发起、自担 gas，失败不退。

<a id="d-pr-11"></a>`D-PR-11`：本端不提供签名、代签、代付、重发或修改代币事实、质押状态号、执行状态号的能力；运营人员不参与任何链上动作。

质押上链与解押的事实均作为本笔操作记录的进度呈现（[`D-PR-34`](#d-pr-34)）。上链成功即记录"质押上链成功 / 待审核"；实际发生解押动作后追加对应进度，已有审核记录保留。每项进度须可取得下表的时间、原因、gas 与凭据；不另设重复的明细。

| 链上事实字段 | 业务含义及校验 |
| --- | --- |
| 关联 | 单笔标识、批次、项目、代币、质押链、质押合约地址与质押前原持有地址必有、只读；不能仅用批次和一个结果定位 |
| 本笔当前去向 | 待审核 / 已计入有效质押额 / 待自助解押 / 解押处理中 / 已解押退回，取面客 `PA-15` 的取值；实际发起解押后才处理中；无结果不擅填失败。"结果待核实"与对账差异为并列事实提示，不自造终态 |
| 时间 | 上链成功、解押发起、解押完成、发现差异的各自时点及业务时区；没有结果不伪造完成时间 |
| 原因与下一步 | 解押失败或差异有可读原因；处理中不能重复发起；差异保持本张限制并提示联系客服，本端没有处置入口 |
| gas | 由资产方承担，实际是否产生、金额及币种只读；失败不退。未提供写"gas 待核实"，不填 0、不因另一张零 gas 推断全批零 gas。平台不收取质押或解押的服务费、不代付、不垫付、不返还 |
| 凭据 | 成功有可查验凭据，缺失不编造；可复制查验，展示沿共享口径，不以有凭据替代业务确认 |
| `RV-17` 差异事实 | 相关单笔、代币、原记录、迟到或冲突事实与发现时间；无差异不生成；不得关联到同代币的新申请而覆盖旧事实 |
| <a id="rv-18"></a>`RV-18` 解押跟踪 | 本笔自助解押的发起时点、结果、gas 与凭据，只读承接；不提供由运营发起的解押、重试或强制退回。原"异常释放跟踪"含义废止，本编号改指[自助解押](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#withdraw)的只读事实 |

**按张独立**：同批 A/B 的审核结论与解押结果彼此独立；B 解押失败不影响 A 的通过结论与额度归属。只约束相关张，不锁全项目。

<a id="d-pr-26"></a><a id="d-pr-38"></a>`D-PR-26` / `D-PR-38`【链上异常与客服边界】：适用于长期无解押结果、结果与原记录冲突，以及混合结果中仍待核实的笔。两端保留真实单笔、代币、批次 / 项目、本次动作、等待时长、已知 gas 和凭据，告知"结果待核实，请联系平台客服人员"。沿平台已有真实客服联系方式能力提供指引；资料不可得时如实说明联系方式暂不可用，不编造邮箱、电话、核实天数或承诺。客服信息用于联系，不是异常处置入口。本规则与[面客异常口径](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#exceptions)同源。

没有明确解押结果仍为"处理中 / 结果待核实"，不推断失败、资产已转回、gas 为零、可重复发起或可以重新质押；仅相关张受限制，其他明确成功且合格的张正常成立。本期不建立工单、异常待办、升级阈值、客服处理进度、人工改判 / 补记、强制解押、补偿、代付或恢复资格流程；联系客服、查看记录或已读通知均不改变业务状态与限制。

普通晚到且无冲突的真实结果，归本笔正常呈现。迟到结果与原记录冲突时保留原事实并关联旧笔或新申请，不翻转原终态、不自动改回待审核或已计入有效质押额、不双重计入额度，保留相关张的新动作限制并提示联系客服。已有真实差异标记仍可只读查看，不因取消异常处置功能而清掉保护；不生成差异处理任务。

混合结果按张独立：正常明确解押成功的张按当前资格可再质押；未知或冲突张不因同批其他张已结束就自动恢复资格。

<a id="d-pr-27"></a><a id="d-pr-32"></a>`D-PR-27` / `D-PR-32`【占用与解除的语义边界】：

| 场景 | 本期范围及可观察结果 |
| --- | --- |
| 上链成功、等待审核 | 该张在合约内，计入总质押额与待审质押额的待裁定分项，不计入有效质押额。无期限，不会因等待而自动失败 |
| 审核通过 | 占用继续（即正常质押占用）；该张从待审质押额转出，在满足有效性等条件时计入有效质押价值，有效质押额按项目质押率重算；总质押额不变。运营不因通过而触发任何链上动作 |
| 审核驳回、尚未解押 | 占用继续，计入待审质押额的已驳回分项，不计入有效质押额；该张不允许用于其他项目质押 |
| 待审撤回或驳回后解押成功 | 代币按记录转回质押前原持有地址，退出总质押额与待审质押额；平台不收费，gas 由资产方承担且不退 |
| 解押失败或长期无结果 | 保持占用与真实事实，按 [`D-PR-38`](#d-pr-38) 提示联系客服；不推定已解押退回、不自动重发、不解除限制 |
| 链上事实与记录冲突后的强制处置 | **本期不做**（[`X-PR-01`](#1-2-本期不包含)）。不设强制解押入口、待办、自动转回、费用分配或恢复资格流程。已有事实差异只读与不重复操作限制保留 |

流程见[质押上链、逐笔审核及两端结果](./02-代币质押审核-流程图与状态机.md#fl-pr-01)、[撤回与驳回后的自助解押](./02-代币质押审核-流程图与状态机.md#fl-pr-03)；去向轴见[本笔当前去向与自助解押](./02-代币质押审核-流程图与状态机.md#st-pr-02)。

### 3.7 留痕与通知触发（`F-PR-13`、`16`）

`F-PR-13`：留痕关联**批次＋单笔＋代币**，包含质押上链、撤回、项目终态关闭及原因、人工结论、正式协议关联、解押发起与结果、差异事实、重新质押关联；记录事件、时间、主体、前后状态、原因与凭据。人工取当时身份，链上与系统事件不伪造审核人；不可编辑删除，重新质押不覆盖旧笔；不同审核人的结果可在同批并存。记录内容与后续进度统一按 [`D-PR-34`](#d-pr-34)；同一事件不得同时生成重复的操作记录与进度记录。

<a id="d-pr-17"></a>`D-PR-17`～`D-PR-19` / `F-PR-16`：沿用既有面客事件名称和消息端别，**事件归属为单笔，不以批次＋结论类型合并掉第二笔同类结果**；同一笔同一事件重复送达不形成重复消息。页内结果始终保底，投递失败不回滚。通知必须定位本笔代币及所属批次；不等待整批审完才触达。是否聚合呈现由消息模块与设计决定，但每笔内容、原因及可执行动作不能丢失。

| 事件 | 触发概述（收件、内容与模板见[消息通知](./03-代币质押审核-消息通知.md#notice-rules)） |
| --- | --- |
| 质押审核通过（`N-LS-01`） | 本笔通过结论生效即发给发起该笔质押的资产方账号 |
| 质押审核驳回（`N-LS-02`） | 本笔驳回结论生效即发给同一账号，带原因全文 |
| 撤回、解押与链上结果 | 资产方自行发起的动作，由面客侧呈现；本模块不发送 |
| 运营队列与只读事实 | 审核队列逐笔且无时效；解押失败或差异在原笔记录可查，不新增异常处置待办、升级或运营广播；详情权限不等于消息收件资格 |

正常新申请不额外全员广播，通过 / 驳回不重复通知刚裁定的运营。内部备注不进入面客原因或通知。<a id="d-pr-28"></a>`D-PR-28`：已读 / 已查看不等于差异已关闭或限制解除。仅资产方本企业可看其材料及链上信息，资金方和游客不能读取审核记录。

通知事件、模板、收件、失效和验收统一见[消息通知第 2～5 节](./03-代币质押审核-消息通知.md#notice-rules)及[第 6 节验收](./03-代币质押审核-消息通知.md#notice-acceptance)；本模块不另造事件副本。

## 4. 同序验收

前置：资产方在同一已审核通过的项目内一次发起 A/B/C 三张并全部上链成功；另有同代币新发起记录、不同资产方记录；本期运营账号均为运营管理员（[本期单一角色](#single-role)），按权限差异的分支保号待后续细分角色，相应验收已逐条标注。审核结论、面客结果、额度归属及逐张解押可分别观察。以下为业务验收要求，未决分支按[第 5 章](#open-items)限制，不以模拟结果冒充已上线能力。

### 4.1 单笔审核队列（对应 [3.1](#m1)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-PR-01`～`02` 队列按笔生成与统计随实际笔数变化 | 一次发起三张且全部上链成功形成三笔队列记录和待审计数 3；按提交时间升序。上链失败的那张不产生记录。仅通过 A 后待审为 2、近七日人工审结加 1 |
| `AC-PR-03`～`04` 筛选排序生效且统计范围不被状态筛选影响 | 基础条件组合、本笔当前去向筛选及三项排序生效；去向取值与面客一致；审核状态只有待审核 / 通过 / 驳回 / 已撤回 / 已关闭五个可选值，无"质押失败（审核超时）"；申请类型可按首笔质押 / 追加质押筛选；起止错误就地提示，重置回默认，统计范围不被状态筛选误清零 |
| `AC-PR-05`～`06` 入口位置、翻页往返与失败反馈 | 管理端共享导航中，代币质押审核入口紧接在项目合约管理（含项目审核）之后，两者是独立入口、进入各自队列；翻页与详情往返保留原筛选、分页与所在位置，从记录进入指定单笔，队列无批量裁定入口；加载失败不显示为零条 |
| `AC-PR-51` 同批已审笔不遮蔽剩余待审笔 | 同批 A 已审、B/C 待审时，B/C 仍可检索和打开办理；查询批次可看全三笔，不把批次剩余待审藏进已审历史 |

### 4.5 等待、撤回与解押（对应 [3.5](#m5)）

| 验收 | 场景与预期 |
| --- | --- |
| `AC-PR-28`～`29`、`AC-PR-33` 审核无时效 | C 长期待审：无论经过多久都不出现截止、倒计时、自动失败或超时提示，审核状态始终为待审核，随时仍可正常裁定；已等待时长如实增长且只作事实陈述；无人访问也不会产生任何自动状态变化 |
| `AC-PR-41` 撤回与裁定竞合只生效一个 | 人工结论先生效则本笔按结论处理，已通过的不能借撤回取消；资产方先发起撤回则本笔进入解押处理中、运营暂不可裁定（见 `AC-PR-72`）；解押成功为已撤回且不可补裁定。其他笔不受影响 |

### 5.2 按用户决定保留的业务限制（供研发与测试知悉）

以下为用户明确裁定后的既定结果，如实记录其业务后果，不作为异议保留。

**本模块直接承担的限制：**

1. **驳回或撤回后须资产方自助解押，代币在解押成功前持续占用。** 未解押的代币一直留在质押合约内，不允许用于其他项目质押；平台侧没有任何动作能替资产方解押。若资产方长期不解押，该张将持续占用且持续计入待审质押额的已驳回分项。测试应按此预期设计用例，不将其判为缺陷。
2. **gas 由资产方承担且失败不退。** 质押上链失败不形成申请、不进入审核队列，该次 gas 已消耗；解押失败同样不退还 gas。平台不代付、不垫付、不返还。
3. **审核无时效。** 待审笔可无限期停留在待审核，平台不催办、不自动终结。若运营长期不处理，资产方的唯一出路是自行撤回（自付 gas）。

**同期确认、写入以供全局知悉的限制（归属他册，本模块不承担）：**

4. **平台不再采集与校验收款人名称。** 法币与数币账户均取消收款人名称，受益人名称需由业务双方在平台外补充；平台不再具备"收款账户必须属于本企业"的自动校验能力。
5. **报价一经提交，资金方无法撤回。** 取消报价有效期后，退出路径仅为资产方拒绝；资金方提交报价即被锁定至资产方处理为止。
6. **待放款阶段无终止出口。** 待放款的唯一出口是资金方提交放款。若线下协商结果是不放款，平台侧没有任何动作能终结该笔业务，业务将持续停留在待放款，资产方无法另起一轮，**对应质押代币持续被占用**。该后果与本模块的占用口径直接相关：此类占用不因审核结论或时间流逝解除。
