<a id="entry"></a>
## 1. 模块是什么

资产方在已通过审核的融资项目内，用本企业一个持有地址签名，把若干质押份额转入本项目的质押合约。**上链成功才形成待审的质押申请**：份额此时已在合约内，计入总质押额与待审质押额，但还不计入有效质押额。运营人员在本模块逐张审核：**通过才计入有效质押额**；驳回后份额仍留在合约内，由资产方自助解押取回。审核**没有时限**。

本模块只写运营端这一侧：运营人员看到什么、能做什么、做完之后两端各变成什么。质押的发起、资产方看到的结果、解押与提取的办理、三项额度的定义与计算，由[融资需求与代币质押](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)定义，本册只读使用、不改写；两册不一致时以该册为准，差异列入[待确认事项](#open-items)。

基本原则：

- **审核对象是一张，不是一批。** 一张指一份质押份额的一次质押申请；同一次发起的几张可以有不同的审核人、结论和协议，一张通过即生效，不等全批。
- **上链、审核、去向是三件独立的事。** 上链结果决定份额在不在合约里，审核结论决定它算不算有效质押，去向说明份额此刻在哪、下一步是什么。份额在合约内不等于已通过审核。
- **没有审核时限。** 不设截止、不倒计时、不催办，任何时间流逝都不改变审核状态。
- **运营只做业务判断。** 质押、撤回、解押都由资产方用持有地址签名发起、gas 自担；运营人员唯一涉及的链上动作是审核通过时连接平台统一钱包签名的解冻授权（见[通过办理（D-PR-35）](#d-pr-35)）。
- **解冻授权上链成功才算通过。** 授权处理中、授权失败或结果待核实时，本张仍是待审核，不计入有效质押额。
- **异常只提示联系客服。** 链上结果长期未知、与记录冲突时只保留事实与保护，本期不建设异常处置。

**一个完整的例子。** 资产方甲在已部署合约的项目 P1 内，用持有地址 0xA1 签名发起质押 A、B、C 三张，三张上链成功，形成一个提交批次、三张待审申请。运营管理员从导航中“项目合约管理”下方的“代币质押审核”进入，默认的待审核队列里出现这三张（提交时间相同，已等待 1 小时）。管理员打开 A：查看份额价值、持有地址、质押合约地址、项目质押率等事实，线下核对后选择通过，上传一份协议、确认知悉后果，连接平台统一钱包签名解冻授权并提交；A 进入解冻授权处理中，授权上链成功后 A 变为通过，从待审质押额转出并计入有效质押额，甲收到“质押审核通过”站内信。管理员打开 B，填写 30 字原因驳回；B 仍在合约内，计入待审质押额的已驳回部分，甲收到带原因的“质押审核驳回”站内信，之后自助解押取回 B。C 暂不处理；甲在面客端对 C 发起撤回，C 进入解押处理中，管理员此时打开 C 只能查看、不能裁定；解押成功后 C 变为已撤回。管理员返回队列，原来的筛选与页码保持不变。

<a id="out-of-scope"></a>
### 1.1 本期不做

- 整批一键通过或驳回、跨张批量裁定。
- 双人复核、审核与复核分离、转派或审批链。
- 风控评分、风险提示、建议结论或自动筛出不合格份额。
- 任何审核时限：截止、倒计时、到期自动失败、催办、超时通知或超时统计。
- 运营端代签、代付资产方 gas、代资产方发起或撤销质押、撤回、解押或提取，修改代币事实与质押状态；解冻授权之外的任何运营端签名。
- 强制解押、异常处置系统（工单、异常待办、自动升级、人工改判或补记、补偿、恢复资格）。
- 项目审核与合约部署（归[运营端项目合约管理](../04-运营端项目合约管理/01-运营端项目合约管理-PRD.md)），代币类型的最高质押率与最长项目期限配置（归[运营端融资参数配置](../02-运营端融资参数配置/01-运营端融资参数配置-PRD.md)）。
- 三项额度的计算与调整；本模块只读展示结果。
- 对账更正、清算、协议模板库、抵押物处置。
- 结算收款链与企业账户的任何信息。
- 发给运营人员的站内信。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 质押份额（张） | 本企业一个持有地址上持有的某笔代币的全部数量，是质押、审核与解押的最小单位，只能整份办理。本册说的“一张”“逐张”都指质押份额，口径同[融资需求与代币质押](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md) |
| 份额价值 | 一份质押份额的价值 = 持有数量 × 该笔代币价值 ÷ 该笔代币数量，USD，按签发价值折算 |
| 质押申请（一张申请） | 一份质押份额的一次质押上链成功后形成的审核对象，有自己的单笔申请标识；再次质押同一份额会生成新的一张 |
| 提交批次 | 资产方一次签名发起所含的份额；同一批的份额都来自同一个持有地址、同一个项目，提交时间相同。只用于追溯和查看同批关系 |
| 持有地址 | 质押前持有这份数量、解押后转回的本企业地址 |
| 质押链 | 代币与质押合约所在的链，即项目的区块链网络（FP-39），本期仅以太坊（ETH） |
| 解冻授权 | 审核通过时，运营人员连接平台统一钱包签名，授权质押合约解除该份额的冻结；解除冻结即该份额从待审质押额转为有效质押额，份额仍留在合约内（用户 2026-10-15、2026-10-16 裁定）。平台统一钱包的地址在代码层面写死，私钥由运营人员个人持有 |
| 解冻授权状态 | 一张申请的解冻授权链上执行事实：未发起、授权处理中、授权成功、授权失败、结果待核实 |
| 待审撤回 | 资产方在本张尚未裁定时自助解押取回 |
| 项目终态 | 所属项目已关闭或已结清（含到期自动终结） |
| 总质押额、待审质押额、有效质押额 | 见[三项额度](#quota)，定义归融资需求与代币质押 |

## 3. 通用规则

<a id="entry-order"></a>
### 3.1 功能入口

- 本模块入口挂在管理端共享导航中，紧接在“项目合约管理”（含项目审核）之后；两者是两个独立入口、两条队列（用户 2026-10-14 确认）。
- 入口可见性按[权限](#d-pr-05)判定；导航的承载与样式由设计决定。
- 本期两个信息域：审核队列（P-O-PR-01）、单笔审核详情（P-O-PR-02）。

<a id="d-pr-05"></a><a id="d-pr-06"></a>
### 3.2 权限与账号准入（D-PR-05、D-PR-06）

- 本期运营端只有运营管理员一个角色（[本期预置角色（D-AL-08）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-08)），代币质押申请查询（PM-AL-07）与代币质押审核处置（PM-AL-08）对每个正常登录的运营账号全部开通：可以查看全部单张，也可以通过、驳回。
- 两项权限仍分开登记，作为后续细分角色时的授权单位；本期不产生“只能查看”“只能处置”的实际差异。
- 本模块不新增授权管理，不按运营机构或本人分配过滤数据。
- 读运营站内信另需运营端消息查看（PM-AL-12），本模块不赠予。
- 账号待首登改密、锁定、登录失效时，所有查看、提交与下载都被拒绝，已打开的办理也不能提交。
- 无权访问时不展示入口，直接访问被拒绝，不泄露记录是否存在。
- 两端账号分开不等于已证明不是同一自然人；本期不做身份互斥或双人复核。

### 3.3 时间、金额与展示

- 业务日期统一按 UTC 判定：近 7 个自然日统计、按日期筛选都按 UTC，日期筛选须让操作者知道是 UTC 口径。
- 具体时点按用户偏好时区显示并标注时区；切换时区、跨周末或夏令时不改变已发生的事实、统计归属和事件先后。
- 份额价值以 USD 两位小数展示；gas 按实际发生的币种展示。未知金额标“待核实”，不填 0。
- 内部状态号不作为界面文案。
- 两端对同一张的结论、原因、时间与去向一致。

<a id="states"></a>
## 4. 状态与额度

### 4.1 单笔审核状态（RV-20）

| 状态 | 怎么形成 | 运营能做什么 |
| --- | --- | --- |
| 待审核 | 份额上链成功即形成，默认值；解冻授权处理中、授权失败或结果待核实时也仍是待审核 | 可以通过或驳回；撤回解押处理中、解冻授权处理中或结果待核实时暂不可裁定（[D-PR-40](#d-pr-40)、[D-PR-35](#d-pr-35)） |
| 通过 | 运营签名的解冻授权上链成功 | 只读，不能改判 |
| 驳回 | 运营在驳回办理中有效提交；或所属项目进入终态时系统默认作出（[D-PR-41](#d-pr-41)） | 只读，不能改判 |
| 已撤回 | 资产方待审撤回、解押成功 | 只读，不能补裁定 |

- 每张至多一个有效结论；结论生效后不可修改。
- **结论来源**：人工 / 项目终态默认。通过只能是人工；驳回分人工驳回与项目终态默认不通过两种，用结论来源区分，结论值都是驳回。
- 审核状态不因时间流逝改变。

<a id="whereabouts"></a>
### 4.2 本笔当前去向

取面客[本笔当前去向（PA-15）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#pa-15)的取值，本册只读使用：

| 去向 | 含义 |
| --- | --- |
| 待审核 | 份额在合约内，尚未裁定 |
| 已计入有效质押额 | 审核通过，且满足有效性等条件 |
| 待自助解押 | 已驳回（含项目终态默认不通过），或驳回后的解押失败，等资产方再次发起 |
| 解押处理中 | 资产方已发起待审撤回或驳回后的解押，尚无确认结果 |
| 已解押退回 | 解押成功，份额已转回原持有地址 |

“结果待核实”与“对账差异”是并列提示，不是去向取值。

<a id="combination"></a>
### 4.3 审核状态与去向的组合

| 审核状态 | 去向 | 运营看到什么 | 运营能否裁定 |
| --- | --- | --- | --- |
| 待审核 | 待审核 | 已等待时长；可办理 | 能 |
| 待审核 | 解押处理中（待审撤回） | 已等待时长；说明“资产方撤回处理中，暂不可裁定” | 不能，直到解押有结果 |
| 待审核（解冻授权处理中） | 待审核 | 说明“解冻授权处理中”；资产方此时不能撤回 | 不能，直到授权有结果 |
| 待审核（解冻授权失败） | 待审核 | 授权失败原因、时点与已消耗 gas；已上传的协议与备注保留 | 能：再次签名授权，或改为驳回 |
| 待审核（解冻授权结果待核实） | 待审核 | 已知凭证；提示联系客服；资产方不能撤回 | 不能，直到真实结果回写 |
| 通过 | 已计入有效质押额 | 结论、审核人、协议 | 不能 |
| 通过 | 已计入有效质押额以外（代币失效或有对账差异） | 结论、审核人、协议；说明本张不计入有效质押价值的原因 | 不能 |
| 驳回（人工） | 待自助解押 / 解押处理中 / 已解押退回 | 结论、审核人、原因全文；解押进度 | 不能 |
| 驳回（项目终态默认） | 待自助解押 / 解押处理中 / 已解押退回 | 审核主体“系统”、默认原因与项目关闭原因；解押进度 | 不能 |
| 已撤回 | 已解押退回 | 撤回时间 | 不能 |

<a id="d-pr-31"></a>
### 4.4 批次汇总

- 批次的审核进度只有三种：待审核（全部未处理）、审核进行中（仍有待审，且至少一张已终结）、审核已结束（没有待审）。“审核已结束”不等于全部通过。
- 同时列出待审、通过、驳回、已撤回四类张数，合计等于该批总张数；驳回含项目终态默认不通过。
- 去向摘要另列待自助解押、解押处理中、已解押退回的张数；对账差异是可叠加的提示，不重复加总。尚无明确解押结果的不算入已解押退回。

<a id="quota"></a>
### 4.5 三项额度与审核的关系

名称与公式的权威定义归融资需求与代币质押，本册只读使用：

- 总质押额（[FP-10](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-10)）：合约内全部质押份额的份额价值合计，含失效和未通过审核的份额；只展示、不参与准入。
- 待审质押额（[FP-32](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-32)）：已在合约内、尚未计入有效质押价值的份额价值，含待审核与已驳回未解押两部分，明细须能区分这两部分。
- 有效质押额（[FP-12](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-12)）：有效质押价值 × 项目质押率（[FP-34](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-34)）。

各动作对额度的影响：

| 动作 | 总质押额 | 待审质押额 | 有效质押额 |
| --- | --- | --- | --- |
| 上链成功 | 计入 | 计入待审核部分 | 不计入 |
| 审核通过 | 不变 | 转出 | 满足有效性等条件时计入并重算；代币失效或有对账差异时不计入 |
| 审核驳回（人工或项目终态默认） | 不变 | 由待审核部分转入已驳回部分 | 不计入 |
| 解押成功（待审撤回或驳回后） | 退出 | 退出 | 不涉及 |

<a id="d-pr-15"></a>**额度只读，通过是必要条件（D-PR-15）。**

- 本模块不提供任何额度调整入口，审核也不改写额度公式。
- 审核通过是计入有效质押价值的必要条件，不是充分条件；是否实际计入由借贷平台按有效性等既有排除项判定，本模块如实展示结果。
- 代币失效、项目终态等客观事实如实展示，不替审核人自动驳回（项目终态时的默认不通过除外，见[D-PR-41](#d-pr-41)）。
- 审核结论不修改代币事实与质押状态；除本张的解冻授权外不触发链上动作。

## 7. 通过与协议（F-PR-09、F-PR-10）

适用角色与前提：有代币质押审核处置权限；本张仍待审核、不在撤回解押处理中、所属项目未进入终态。没有截止条件。

- 每次只裁定当前这一张；可以只通过批次内 A、驳回 B、保留 C 待审，不要求整批同结论，也不提供一次为多张生成结论。

<a id="d-pr-35"></a>**通过办理（D-PR-35）。** 线下判定后依次：

1. 回显本张的代币编号、持有地址、份额价值、项目、批次与链上事实。
2. 上传本张适用的协议（规则见下方）。
3. 可以填写内部备注。
4. 确认知悉本次结论的业务后果：本张将计入有效质押额（满足有效性等条件时），没有入池确认、没有截止、不向资产方收取平台费用，结论不可修改。
5. 连接平台统一钱包，签名解冻授权：授权质押合约解除本张的冻结（用户 2026-10-15 裁定）。平台统一钱包的地址在代码层面写死，运营端没有配置入口；私钥由运营人员个人持有，运营人员连接该钱包签名（2026-10-16 裁定）。授权的 gas 由平台统一钱包承担，运营人员个人不付费。
6. 提交。

- 连接的钱包地址与平台统一钱包地址不一致时不能签名，就地说明；取消签名、钱包不可用或签名失败时不产生结论，已填材料保留。
- **解冻授权上链成功才算通过**（用户 2026-10-16 裁定）。签名并提交后，本张进入解冻授权处理中，仍是待审核，不计入有效质押额、不发通知，暂不可裁定：
  - 授权上链成功：通过成立，结论时间取授权上链成功的时点，审核人为签名的运营人员；本张从待审质押额转为有效质押额（满足有效性等条件时），发送通过通知。
  - 授权上链失败：不算通过，本张回到可裁定的待审核；展示失败原因、时点与已消耗 gas，已上传的协议与备注保留；运营人员可以再次连接平台统一钱包签名授权，也可以改为驳回；不通知资产方。
  - 长期没有结果：标“结果待核实”，不算通过，不推定成功或失败，不能重复签名；真实结果回写后按成功或失败处理，规则同[链上异常](#d-pr-38)。
- **授权处理中资产方不能撤回**（用户 2026-10-16 裁定）：本张处于解冻授权处理中或结果待核实时，资产方不能发起待审撤回；面客规则见[解冻授权处理中暂不可撤回（D-LS-73）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#d-ls-73)。资产方撤回与运营签名提交同时发生时，只成立先生效的一笔：撤回先生效则本次授权不发起，按[撤回解押中暂不可裁定](#d-pr-40)处理；授权先生效则资产方的撤回被拒。
- 通过在本次办理内完成，没有“核对结论”的后续步骤，也不需要第二位审核人。
- 提交前取消不产生结论；提交中有明确反馈且不能重复提交。
- 材料、权限或状态不满足时就地说明，不产生通过记录；办理中途本张进入撤回解押处理中或被项目终态默认不通过的，提交被拒并说明原因，已填内容保留。
- 保存失败保留本张的有效输入，可以重试；结果不确定时先查当前事实，不展示成功，也不引导重复裁定。
- 成功后回到本张详情，结论与操作记录出现本次通过；本张只读，同批其他待审张仍可办理。
- 同一张被两人同时裁定时，只有先完成的一次生效；后者看到本张已有的结论、时间与审核人，不覆盖。不同张的并发裁定互不影响。重复提交同一次操作不增加结论、不改时间、不重复通知。

## 8. 驳回（F-PR-11、F-PR-12）

适用角色与前提：同通过。

**驳回办理：** 回显本张代币编号与持有地址 → 填写原因，可选归类 → 完整预览将展示给资产方的原因 → 确认驳回对象与原因 → 提交。

| 字段 | 规则 |
| --- | --- |
| 原因说明 | 必填，去掉首尾空格后 10～500 字，不能只有空格或标点；平台不改写措辞 |
| 归类 | 选填：代币归属或主体存疑 / 底层应收账款存在问题 / 代币与目标项目不匹配 / 申请材料不完整或不一致 / 其他；只用于统计，不影响能否提交 |
| 驳回原因全文 | 以原因说明为主体，归类可以辅助生成、可编辑；预览确认后的文本原样用于面客原因与通知，不截断，不套到其他张 |

- 驳回只结束本张的审核，原因只针对本张；同批 A 通过、B 驳回、C 待审是正常结果。
- **驳回不自动解押**：份额仍留在合约内，计入待审质押额的已驳回部分，不能用于其他项目质押，由资产方自助解押；驳回不产生平台费用，解押 gas 由资产方承担。
- 驳回不触发链上动作；本期运营端没有强制解押，也不能把已通过改成驳回。
- 并发、重复提交与结果不确定时的处理同[通过](#m3)。

**两端同步（F-PR-12）：**

- 两端按单笔申请标识同步本张的结论、时间与原因；批次只做汇总，一张的结论不覆盖同批其他张。
- 已撤回或已有结论（含项目终态默认不通过）的张不能再裁定；撤回解押处理中的待审张暂不能裁定；已打开的旧办理提交也被拒绝。

<a id="m5"></a>
## 9. 待审撤回与项目终态（F-PR-20）

**审核没有时限。** 待审张可以一直停留在待审核，只能由人工结论、资产方待审撤回或项目终态默认不通过终结；不存在截止、到期自动失败、迟到补审拒绝或超时通知。

**终结方式：**

- 每张只有四种终结方式：人工通过、人工驳回、资产方待审撤回、项目终态默认不通过。
- 正在上传、提交尚未生效、线下已决定但未在线提交，都不算已审核。
- 每张只有一个有效结果，先生效的为准；不影响同批其他张。

**待审撤回：**

- 资产方在本张尚未裁定时，可以自行向质押合约发起解押取回，自付 gas；不需要运营审批，运营在本模块没有任何动作。本张处于解冻授权处理中或结果待核实时不能撤回，见[通过办理](#d-pr-35)。
- 合约按记录把份额转回质押前的原持有地址；平台不能指定其他地址。
- 人工结论已经先生效的，本张按结论处理，已通过的不能借撤回取消；此后的转出按面客[解除质押](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#withdraw)规则办理。

<a id="d-pr-40"></a>**撤回解押中暂不可裁定（D-PR-40）：**

- 资产方发起待审撤回后，本张去向为解押处理中；此时仍是待审核，计入待审核张数，可以查看，但运营不能通过或驳回。
- 办理中途进入该状态的，提交被拒并说明“资产方撤回处理中”，已填内容保留。
- 解押成功：本张转为已撤回，不能再裁定。
- 解押失败：本张恢复为待审核、可以正常裁定，去向回到待审核；gas 不退。
- 结果待核实：保持暂不可裁定，按[链上异常](#d-pr-38)提示联系客服。

<a id="d-pr-41"></a>**项目终态时待审张默认不通过（D-PR-41）：**

所属项目进入终态（[已关闭或已结清](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-23)，含到期自动终结）时，本项目仍待审核的张不再审核，默认审核不通过：

- 审核状态转为驳回，结论来源记为项目终态默认；结论时间取项目进入终态的时刻。
- 原因由系统生成：“所属项目已关闭，未审核的质押默认不通过”或“所属项目已结清，未审核的质押默认不通过”，并带出项目的关闭原因。原因在本张详情、操作记录与面客本张记录中都可见。
- 审核主体显示“系统”；没有审核人、协议、归类与内部备注；不可补裁定或改判，已打开的办理提交被拒并说明原因。
- 已有人工结论或已撤回的张不受影响。
- 解冻授权处理中或结果待核实属于本项目未处理完成的链上操作，项目此时不会进入终态；授权失败回到待审核的张，按本条默认不通过。
- 进入终态时正处于撤回解押处理中的待审张，同样默认不通过；此后解押结果只更新去向，不把驳回改为已撤回。
- 份额仍在本项目合约内，由资产方自主解押取回：去向为待自助解押，与人工驳回同一路径，计入待审质押额的已驳回部分，不参与项目终态时的整池释放，不转为已释放待提取。
- 不触发链上动作，不产生平台费用。
- <a id="q-pr-16"></a>向资产方发送质押审核驳回通知（N-LS-02），原因取系统生成的默认原因，逐张发送、同一事实去重（用户 2026-10-16 裁定）。

<a id="d-pr-24"></a>**驳回后的自助解押与再次质押（D-PR-24）：**

- 驳回记录保留；资产方按与待审撤回相同的方式自助解押，自付 gas，合约按记录转回原持有地址。
- 解押成功前，这份份额不能用于其他项目质押。
- 解押成功后，按当前资格可以立即重新发起质押到同一或其他项目，没有冷却期；旧的一张不恢复、不删除，新的一张有新标识与新的上链时间。
- 其他独立的占用、失效或对账差异仍会约束能否再次质押。

<a id="m6"></a>
## 10. 链上事实的只读追踪（F-PR-18）

- 本模块对两类链上事实只读追踪：**质押上链**（份额进入合约，是本张成立的前提）与**解押**（待审撤回或驳回后由资产方发起，成功即转回原持有地址）。两类都由资产方用持有地址签名发起，gas 自担、失败不退。
- 本端不提供发起、重试、撤销或代付；不修改代币事实与质押状态。运营唯一涉及的链上动作是通过时的[解冻授权](#d-pr-35)。
- 链上事实作为本张[操作记录](#d-pr-34)的进度呈现；上链成功即记录“质押上链成功 / 待审核”，解押发生后追加进度，已有审核记录保留。

| 字段 | 规则 |
| --- | --- |
| 关联 | 单笔申请标识、批次、项目、代币编号、持有地址、质押链、质押合约地址；不能只用批次和一个结果定位 |
| 去向 | 取本笔当前去向；实际发起解押后才显示解押处理中；没有结果不填失败 |
| 时间 | 上链成功、解押发起、解押完成、发现差异各自的时点；没有结果不伪造完成时间 |
| 原因与下一步 | 解押失败或对账差异有可读原因；处理中不能重复发起；有对账差异时保持本张限制并提示联系客服 |
| gas | 资产方承担的实际 gas 金额与币种，只读；失败不退；未提供写“待核实”，不填 0，不因另一张没有 gas 推断全批没有；平台不收服务费、不代付、不垫付、不返还 |
| 凭证 | 成功时有可查验的凭证，缺失不编造 |
| 对账差异 | 相关张、原记录、迟到或冲突的事实与发现时间；没有差异不生成；不关联到同一份额的新申请而覆盖旧事实 |
| 解押跟踪 | 本张解押的发起时点、结果、gas 与凭证，只读；运营端没有发起、重试或强制退回 |

- 同批各张的结论与解押结果互不影响；一张解押失败不影响另一张的通过结论与额度归属。限制只作用于相关的那一张，不锁整个项目。

<a id="d-pr-38"></a>**链上异常只提示联系客服（D-PR-38）：**

- 适用于：长期没有解押结果、结果与原记录冲突、混合结果中仍待核实的张。
- 两端保留真实的单笔申请标识、代币、批次与项目、本次动作、等待时长、已知 gas 与凭证，并提示“结果待核实，请联系平台客服人员”。
- 客服联系方式沿用平台已有的真实能力；资料不可得时如实说明联系方式暂不可用，不编造邮箱、电话、处理天数或承诺。
- 没有明确结果时保持“处理中 / 结果待核实”，不推断失败、已转回、gas 为零、可以重复发起或可以重新质押。
- 普通晚到且无冲突的真实结果，归本张正常呈现。迟到结果与原记录冲突时，保留原事实并关联旧张或新申请，不翻转原结果、不重复计入额度，保留相关张的限制并提示联系客服。
- 本期不建立工单、异常待办、升级阈值、客服处理进度、人工改判或补记、强制解押、补偿或恢复资格；联系客服、查看记录、已读通知都不改变业务状态与限制。规则与面客[异常只提示联系客服](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#exceptions)一致。

**占用与解除：**

| 情形 | 份额与额度的结果 |
| --- | --- |
| 上链成功、待审核 | 在合约内，计入总质押额与待审质押额的待审核部分，不计入有效质押额；不会因等待自动失败 |
| 解冻授权处理中、授权失败或结果待核实 | 继续在合约内，仍计入待审质押额的待审核部分，不计入有效质押额 |
| 审核通过（解冻授权上链成功） | 继续在合约内；从待审质押额转出，满足有效性等条件时计入有效质押额；运营不因通过触发解冻授权之外的链上动作 |
| 审核驳回、尚未解押 | 继续在合约内，计入待审质押额的已驳回部分，不计入有效质押额，不能用于其他项目 |
| 待审撤回或驳回后解押成功 | 转回原持有地址，退出总质押额与待审质押额；平台不收费，gas 由资产方承担且不退 |
| 解押失败或长期没有结果 | 保持在合约内与真实事实，提示联系客服；不推定已退回、不自动重发、不解除限制 |

## 11. 留痕与通知（F-PR-13、F-PR-16）

**留痕（F-PR-13）：**

- 留痕关联批次、单张与代币，包括质押上链、待审撤回、人工结论、项目终态默认不通过及原因、协议关联、解冻授权的签名发起与结果（成功、失败、结果待核实）、解押发起与结果、对账差异、再次质押关联。
- 每条记录事件、时间、主体、前后状态、原因与凭证；人工取当时身份，系统事件不伪造审核人。
- 留痕不可编辑删除；再次质押不覆盖旧张；同批不同审核人的结果可以并存。
- 展示统一按[操作记录](#d-pr-34)，同一事件不重复生成两条。

**通知（F-PR-16）：**

- 本模块是两类审核结果站内信的唯一发送方：质押审核通过（N-LS-01）、质押审核驳回（N-LS-02），收件人是发起本张质押的资产方账号。
- 通知逐张发送，不等全批审完，也不按批次合并同类结果；同一张同一事件重复到达不重复发送；投递失败不回滚已生效的结论。
- 项目终态默认不通过同样发送质押审核驳回通知（N-LS-02），原因取系统默认原因。
- 通知只告知本张通过或不通过的结论；解冻授权处理中、授权失败、结果待核实都不通知，通过通知也不补充有效性条件等说明（用户 2026-10-16 裁定）。
- 待审撤回、解押、上链结果由面客侧呈现，本模块不发送。
- 不向运营人员发站内信，不做新申请广播；详情查看权限不等于消息收件资格。
- 已读或已查看不等于对账差异已关闭或限制解除。
- 触发、收件、内容与验收见[消息通知](./03-代币质押审核-消息通知.md)。

## 12. 待确认事项与依赖

### 12.1 待确认事项

当前没有待确认事项。解冻授权的结果口径与项目终态默认不通过的通知已由用户 2026-10-16 裁定，分别写入[通过办理（D-PR-35）](#d-pr-35)与[项目终态时待审张默认不通过（D-PR-41）](#d-pr-41)；通过通知只告知通过的结论，不补充有效性条件等说明（同日裁定）。

### 12.2 按用户决定保留的业务后果

供研发与测试知悉，不判为缺陷：

1. **驳回或待审撤回后须资产方自助解押，解押成功前份额持续占用。** 平台没有任何动作能替资产方解押；资产方长期不解押时，这份份额一直占用并计入待审质押额的已驳回部分，也不能用于其他项目质押。
2. **gas 由资产方承担且失败不退。** 质押上链失败不形成申请、不进入审核队列，已产生的 gas 不退；解押失败同样不退。平台不代付、不垫付、不返还。
3. **审核没有时限。** 待审张可以无限期停留在待审核，平台不催办、不自动终结；运营长期不处理时，资产方唯一的出路是自行撤回（自付 gas）。项目终态时仍待审的张默认不通过，份额仍须资产方自助解押。
4. **平台统一钱包的私钥由运营人员个人持有。** 只有持有该钱包的运营人员能完成通过；持有人不可用时待审张无法通过。地址写死在代码中，私钥泄露或需要更换时只能修改代码并发版。

其他模块的既定业务后果（例如待放款阶段没有终止出口、水位不安全时已通过审核的代币不能转出）见融资需求与代币质押的[按用户决定保留的业务限制](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#accepted-limits)，本册不重复。
