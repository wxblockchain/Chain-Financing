<a id="entry"></a>
## 1. 模块是什么

借贷平台对接一个或多个代币发行平台。代币发行平台把已铸造的代币连同代币信息、底层应收账款信息和法律协议文件推送到借贷平台，形成一条**准入申请**；运营管理员在本模块逐笔核对这些信息，作出**通过**或**退回**的结论。只有通过准入的代币，才会出现在面客端的资产广场和借贷广场，成为后续融资的合格资产；未通过准入的代币在面客端任何地方都不出现。

基本原则：

- **先审后展示。** 代币进入借贷平台的唯一入口是准入审核通过；待审核与已退回的代币对面客端完全不可见，也不能被质押。
- **审核对象是一笔代币。** 本期代币为 ERC-3525 代币，一笔代币（一个代币编号）对应一个资产槽位（slot）。平台按[代币识别四项](#identity)（链 ID、代币发行合约地址、资产槽位、代币编号）识别一笔代币，并据此提醒疑似重复；形成准入记录时生成[平台代币标识](#platform-token-id)，在借贷平台内唯一定位这条记录；同一笔代币在发行平台修改后重新推送，仍是同一条记录的新一次提交，不产生第二条记录。审核不按持有地址或质押份额拆分。
- **结论只有通过与退回。** 通过是终态，本期不可撤销、不下架；退回必须写明原因并回传代币发行平台，发行平台修改后可以重新推送。
- **本模块只核对，不改写。** 代币事实以代币发行平台为准，底层资产事实与存证以资产可信平台为准；运营端不编辑、不补录、不重算任何推送来的信息，系统也不判断资料是否齐全，不对代币或文件做链上或法律上的真伪认定，结论由审核人线下判断后在此维护。
- **准入资格与代币是否有效是两回事。** 准入通过后，代币之后变为失效、持有地址变化，都按上游事实如实反映，不改变准入结论。

**一个完整的例子。** 代币发行平台 A 为甲企业的一笔应收账款（卖方甲企业、买方乙企业，金额 1,000,000.00 USD，账期 2026-10-01～2027-03-31）铸造了 ERC-3525 代币 TK20261021000001，并把这笔代币推送到借贷平台。运营管理员打开“代币准入审核”，默认的待审核清单里看到这条记录：来源发行平台 A、发行方甲企业、代币标准 ERC-3525、代币数量 1,000,000.00 枚、第 1 次提交，以及形成记录时生成的平台代币标识 PT20261021000001。管理员进入审核详情，依次核对代币基本信息（发行方、资产槽位、代币发行合约地址、铸造交易哈希、签发汇率与代币价值）、底层资产信息（买卖双方、金额、账期、合同号与发票号、确权结论、链上存证），并通过附件下载链接下载附件包，阅读其中的应收账款转让协议、债权转让通知及债务人确认、代币发行说明书、法律意见书等；发票号上游没有提供，详情中该字段为空值。管理员发现法律意见书缺少签署页，于是填写退回原因“法律意见书缺少签署页，请补充完整签署版本后重新提交”并直接退回。记录变为已退回，原因回传发行平台 A；面客端看不到这笔代币。发行平台 A 补充文件后重新推送，记录以第 2 次提交回到待审核。管理员再次核对后点击通过。记录变为已通过，这笔代币随即出现在资产广场的代币列表中，甲企业在借贷广场创建项目时也可以选择它质押；审核结果回传发行平台 A。管理员返回清单，原来的筛选与页码保持不变。

<a id="out-of-scope"></a>
### 1.1 本期不做

- 运营端新建、编辑、补录或删除代币信息、底层资产信息和法律协议文件；运营端上传文件。
- 系统判断资料是否齐全，或对缺少的字段、文件作出提示。
- 逐份分列展示或在线预览附件；平台读取、拆分或核对附件包内的文件（用户 2026-10-21 确认，附件改为一个下载链接）。
- 代币铸造、销毁、冻结或合约操作；任何链上签名。
- 撤销已通过的准入、暂停或下架面客端展示（用户 2026-10-21 确认）。
- 对通过后上游变更的资料重新审核（用户 2026-10-21 确认，只标记提醒，见[通过后的资料变更（F-TA-10）](#f-ta-10)）。
- 代币发行平台撤回尚在审核中的申请。
- 批量审核、一键通过或退回；双人复核、转派或审批链。
- 审核时限、倒计时、催办、超时统计或超时自动处理。
- 风控评分、估值、评级、风险提示或建议结论；自动筛出不合格代币；代币价值与应收账款金额的一致性核对。
- 对链上合约、交易、文件签章的真伪核验，以及对法律文件的合规认定。
- 审核内部备注与审核附件。
- 本模块发出的站内信或邮件。
- 资产广场与借贷广场中代币如何展示、可以如何质押（分属[资产广场](../../面客端/04-资产广场-已上架代币只读域/01-资产广场-PRD.md)与[融资需求与代币质押](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)）。
- 信息如何从上游取得、何时刷新、审核结果如何回传，由研发决定；本册只定义需要哪些信息和业务结果。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 代币准入审核 | 运营端对代币发行平台推送来的代币逐笔核对并作出通过或退回结论的环节；也是本模块名称。英文建议 Token admission |
| 准入申请 | 代币发行平台对一笔代币的一次推送。首次推送与每次退回后的重新推送各算一次提交 |
| 准入记录 | 一笔代币在本模块中的唯一记录，承载这笔代币历次提交、结论与操作记录 |
| 准入状态 | 一条准入记录的审核进度：待审核、已通过、已退回 |
| 提交序次 | 同一笔代币第几次提交准入申请；首次为第 1 次，每次退回后重新推送加一 |
| 来源发行平台 | 推送这笔代币的代币发行平台。借贷平台可以对接多个代币发行平台 |
| 代币标准 | 代币所遵循的链上标准。本期只有 ERC-3525（半同质化代币标准），后期会增加其他代币标准 |
| 资产槽位（slot） | ERC-3525 代币在链上用来归集同一类资产的标识，由代币发行合约自行编排，只在同一份合约内唯一。一笔代币（一个代币编号）对应一个 slot |
| 链 ID | 区块链网络的数字标识，如以太坊主网为 1；与链名不同，测试网与主网的链 ID 不同 |
| 区块链网络 | 本模块清单中展示的代币铸造链，与详情中的“铸造链”指同一业务事实；以链 ID 区分网络，与底层资产的存证链不同 |
| 代币识别四项 | 链 ID、代币发行合约地址、资产槽位、代币编号。前三项合起来是链上唯一的一笔代币，代币编号由代币发行平台给出 |
| 平台代币标识 | 借贷平台在形成准入记录时为该记录生成的唯一标识，一条准入记录一个；与代币编号不同，代币编号由代币发行平台给出，不同发行平台之间可能重复 |
| 底层资产 | 代币所对应的应收账款，本期只有应收账款一种 |
| 法律协议文件 | 支撑这笔代币发行与持有人权利的法律文件，如应收账款转让协议、代币发行说明书、法律意见书 |
| 附件下载链接 | 来源发行平台随推送提供的一个链接，本次提交的全部附件（底层资产佐证材料与法律协议文件）合并在里面，按需下载 |
| 已准入代币 | 准入状态为已通过的代币，即面客端资产广场所说的“已上架代币” |
| 发行方 | 发行这笔代币的企业；一笔代币有且只有一个发行方，口径同[资产广场](../../面客端/04-资产广场-已上架代币只读域/01-资产广场-PRD.md#token-fields) |
| 持有地址 | 当前持有这笔代币某一部分数量的链上地址，口径同[资产广场持有方](../../面客端/04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-14) |

## 3. 通用规则：权限、时间与界面反馈（F-TA-12）

适用于本模块全部功能。

<a id="pm-ta"></a>**权限。** 按[权限组织方式（D-AL-07）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-07)，各业务模块自行定义本模块的权限项，一个查询动作、一个裁定动作各为一个可授权项，并遵守[权限底线（F-AL-17）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#f-al-17)。本模块定义以下两项：

| 权限项 | 覆盖的业务能力 |
| --- | --- |
| 代币准入审核查询（PM-TA-01） | 查看准入审核清单与统计、审核详情（含代币与底层资产信息、附件下载、操作记录）；不含任何裁定动作 |
| 代币准入审核处置（PM-TA-02） | 通过、退回、确认已知悉通过后的资料变更；必须同时具备代币准入审核查询（PM-TA-01），否则不能进入审核办理 |

- 本期运营端只有运营管理员一个角色，固定具备上述两项（见[本期预置角色（D-AL-08）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-08)）。
- 只开通处置、缺少查询的交付配置，进入即被拒绝，并提示联系建设方修正配置。
- 其他模块的权限项（如融资项目审核查询（PM-AL-17））都不覆盖本模块，不能据此进入。
- 账号待首登改密、被锁定或登录失效后，此前已打开页面中的提交同样被拒绝，不产生结论。
- 无权限时不展示入口，也不泄露某笔代币是否存在。
- 待审核与已退回的代币只在本模块可见；运营端能看到它们来自功能权限，不改变它们对面客端不可见。

<a id="time-and-date"></a>
**时间与日期。**

- 近 7 个自然日统计、按日期筛选都按 UTC 日期计算，统计与日期条件上标注 UTC；具体时点按运营人员偏好时区显示并标注时区。
- 没有审核时限：已等待时长只作事实陈述，不触发提醒，准入状态不因等待而改变，也不自动通过或退回。
- 已等待时长仅在详情的[审核概况](#review-overview)展示；从本次提交时间开始，待审核期间持续计时，通过或退回结论生效时停止，重新提交后按新一次提交重新计时；待审核期间资料更新不重新起算。

**金额与数量。**

- 代币数量单位“枚”、代币价值单位 USD、应收账款金额为原币，三者是不同的量，不相加、不互相换算展示；签发汇率只按上游快照原值展示。
- 金额与数量按上游原值展示，本模块不截断、不四舍五入。

<a id="empty-value"></a>
**无数据的字段。** 上游没有提供的字段与文件，详情中对应位置展示空值；不填 0、不猜测内容、不提示缺失，也不影响审核办理。

**反馈。** 加载中、无数据、筛选无结果、读取失败、无权限、提交中、附件下载失败，各自有可辨认的呈现；读取失败可重试，不显示成 0 条；提交失败保留已填内容；不同代币之间不串用已填原因。

**界面说明的范围。** 界面只保留办理所需的事实和不能通过的原因；本册写明的“信息只读”“结论由审核人线下判断”等规则照常生效，但不作为常驻说明重复展示。

<a id="states"></a>
## 4. 准入状态与叠加标记

一条准入记录有一个准入状态，另有三个独立的叠加标记。准入状态的转换见[准入状态（ST-TA-01）](./02-代币准入审核-流程图与状态机.md#st-ta-01)。

准入状态（必有，首次推送时为待审核）：

| 准入状态 | 含义 | 面客端 | 运营可做的动作 |
| --- | --- | --- | --- |
| 待审核 | 发行平台已提交、尚无本次结论 | 不可见、不可质押 | 通过（代币状态为有效，且同一链上代币没有其他已通过记录时）、退回 |
| 已通过 | 准入通过，终态 | 按资产广场与融资需求规则展示和质押 | 无，本期不可撤销 |
| 已退回 | 本次提交被退回，等待发行平台修改后重新推送 | 不可见、不可质押 | 无 |

叠加标记（各自独立，不合成新的准入状态）：

| 标记 | 取值 | 来源与含义 |
| --- | --- | --- |
| 代币状态 | 有效／失效 | 代币发行平台的最新事实，口径同[资产广场代币状态](../../面客端/04-资产广场-已上架代币只读域/01-资产广场-PRD.md#token-fields)；本模块不自行判断 |
| 重复提醒 | 无／链上代币重复／代币编号重复（两种可同时有） | 按[代币识别四项](#identity)发现另一条准入记录与本笔疑似重复 |
| 通过后资料有变更 | 有／无 | 已通过后发行平台又推送了准入资料的变更，见[通过后的资料变更（F-TA-10）](#f-ta-10) |

准入状态与代币状态的组合下，运营看到与能做的：

| 准入状态 | 代币状态 | 运营看到与能做的 |
| --- | --- | --- |
| 待审核 | 有效 | 可以通过，也可以退回 |
| 待审核 | 失效 | 不能通过，看到代币已失效及对应应收账款到期日；可以退回 |
| 已通过 | 有效 | 只读；面客端按规则展示，可被质押 |
| 已通过 | 失效 | 只读；面客端仍展示并标失效，失效代币不可新质押（按融资需求规则） |
| 已退回 | 有效 | 只读，展示退回原因；等待重新推送 |
| 已退回 | 失效 | 只读，展示退回原因与已失效；发行平台是否还会重新推送由其决定 |

- 代币编号重复与通过后资料有变更只作提醒，不改变运营能做的动作。
- 链上代币重复的记录按[同一链上代币只能通过一条](#one-approval)限制通过。

<a id="f-ta-01"></a>
## 5. 接收准入申请（F-TA-01）

适用对象：已对接的代币发行平台；本节是系统行为，没有运营动作。

- 代币发行平台对一笔已铸造成功的代币发起推送，借贷平台收到后形成或更新这笔代币的准入记录，准入状态为待审核。
- <a id="identity"></a>**代币识别四项**：链 ID、代币发行合约地址、资产槽位（slot）、代币编号。比较时按指向的链上对象判断：合约地址不区分大小写，链 ID 与 slot 按数值比较，写法不同但指向同一对象的视为相同。
- **同一笔代币的判定**：同一来源发行平台推送、四项全部相同的，是同一笔代币的再次推送，归入原准入记录。
- **四项缺任一项**：无法识别为一笔代币，不形成准入记录。
- **首次推送**：新建准入记录，提交序次为第 1 次，同时生成平台代币标识。
- **已退回后重新推送**：同一条记录，提交序次加一，准入状态回到待审核；以前的提交、结论与退回原因全部保留在操作记录中，不被覆盖。
- **待审核期间再次推送**：视为本次提交的资料更新，不增加提交序次；审核详情改为展示最新资料，操作记录新增“资料更新”。若审核人正在办理，按[通过](#f-ta-07)与[退回](#f-ta-08)中“资料已更新”的规则处理。
- **已通过后再次推送**：不改变准入状态，按[通过后的资料变更（F-TA-10）](#f-ta-10)处理。
- 同一推送重复到达只记一次；较早的推送不能覆盖较新的资料。
- 推送中缺少的字段或文件不影响接收，照常进入待审核清单，详情中对应位置展示空值。
- 本模块不向代币发行平台发起索取资料；资料补充只能通过退回后的重新推送，或待审核期间发行平台主动更新。

<a id="platform-token-id"></a>**平台代币标识**（用户 2026-10-21 新增）。

- 生成时机：形成准入记录时生成，与准入记录同时出现。四项缺任一项的推送不形成准入记录，也不生成平台代币标识。
- 一条准入记录一个平台代币标识，在借贷平台内唯一。归入原记录的再次推送（资料更新、重新提交、通过后资料变更）不重新生成，准入状态如何变化也不改变它。
- 格式：PT + 生成当天的 UTC 日期 yyyyMMdd + 6 位序号，共 16 位，序号按 UTC 日逐日从 000001 编起。生成后不可修改，已生成的标识不再分配给其他记录。
- 与代币编号的关系：代币编号是代币发行平台给出的编号，仍是代币识别四项之一，用于判断同一笔代币与重复提醒；平台代币标识不参与识别与重复判断，只用于在借贷平台内定位一条准入记录。标重复提醒的两条记录各有自己的平台代币标识，可以据此区分。
- 平台代币标识在本模块以外如何使用，见[平台代币标识的对外使用（Q-TA-13）](#q-ta-13)。

<a id="duplicate"></a>**重复提醒。** 新形成准入记录时，与已有准入记录逐条比对，命中以下任一情形，两条记录都标重复提醒并写明原因；各自形成准入记录、互不合并：

| 情形 | 重复原因 | 说明 |
| --- | --- | --- |
| 链 ID、代币发行合约地址、资产槽位三项相同，代币编号不同 | 链上代币重复 | 链上是同一笔代币，却以不同的代币编号推送 |
| 四项全部相同，来源发行平台不同 | 链上代币重复 | 链上是同一笔代币，由两个发行平台分别推送 |
| 代币编号相同，链 ID、代币发行合约地址、资产槽位三项中至少一项不同 | 代币编号重复 | 链上是两笔不同的代币，使用了同一个代币编号 |

- 提醒标在两条记录上，各自可进入对方的审核详情；后续任一条被退回、重新推送或通过，都不清除提醒。
- 代币编号重复只作提醒，不影响通过。
- <a id="one-approval"></a>**同一链上代币只能通过一条**（用户 2026-10-21 确认）：同一笔链上代币已有一条准入记录通过后，其他标“链上代币重复”的记录不能再通过，只能退回。都还没有通过时，先生效的通过成立，其余记录随即只能退回。

流程参见：[准入审核主流程（FL-TA-01）](./02-代币准入审核-流程图与状态机.md#fl-ta-01)、[推送更新与重新提交（FL-TA-02）](./02-代币准入审核-流程图与状态机.md#fl-ta-02)。

## 6. 准入审核清单（F-TA-02）

适用角色与前提：具备代币准入审核查询。清单是准入审核清单（P-O-TA-01），一条记录对应一笔代币，退回后重新推送仍是同一条。

- 默认只列准入状态为待审核的记录，按本次提交时间从早到晚排列；时间相同时保持稳定顺序。
- 每条记录展示：区块链网络及网络图标、平台代币标识、代币编号、代币名称及代币图标、来源发行平台、发行方、代币标准、代币数量（枚）、代币价值（USD）、底层应收账款到期日、本次提交时间与提交序次、准入状态、代币状态；已通过的另展示通过时间。有重复提醒（及其原因）、通过后资料有变更的，分别标出。已等待时长不在清单中展示，查看该值须进入详情。
- 可按以下条件组合筛选：
  - 准入状态：全部、待审核、已通过、已退回。
  - 代币状态：全部、有效、失效。
  - 来源发行平台、发行方、代币标准。
  - 重复提醒：全部、链上代币重复、代币编号重复、无。
  - 通过后资料有变更：全部、有、无。
  - 提交时间范围：起止都包含当天，起点不能晚于终点，否则就地提示。
  - 关键词：可匹配平台代币标识、代币编号、代币名称、发行方名称、代币发行合约地址、应收账款编号，忽略首尾空格。
  - 重置后回到默认条件。
- 清单上方有两项统计：
  - **待审核代币数**：准入状态为待审核的记录数。
  - **近 7 个自然日审结数**：结论时间落在近 7 个自然日内的通过数与退回数，分别给出。
  - 统计跟随来源发行平台、发行方、代币标准、提交时间与关键词条件变化，不跟随准入状态、代币状态筛选变化。
- 可按本次提交时间、已等待时长、代币价值、到期日升序或降序排列；带总数分页，每页条数沿用平台现行取值。筛选条件改变后回到第一页；从详情返回时保留筛选、排序和页码，原页已空时回到最后一个有内容的页并说明。
- 清单只用于查看，不提供逐条裁定或批量选择；进入详情才能办理。
- 无数据、筛选无结果、读取失败分别说明；读取失败可重试。

<a id="list-presentation"></a>
**清单列与图标要求。** 用户 2026-10-23 明确以下设计约束，适用于待审核、已通过、已退回各类记录：

- 第一列为“区块链网络”，展示网络图标与网络名称；网络取本笔代币的[铸造链](#minting-network)，按上游原值展示名称，不与存证链混用，也不以图标代替名称。
- 第二列将“平台代币标识”和“代币编号”合在同一列，两项分别标明含义并完整可得；它们仍是两个独立业务标识，不拼成新的编号，不改变各自搜索、定位与重复判断规则。
- “代币名称”独立成列，同时展示[代币标识图](#token-logo)作为代币图标；没有图标时按设计采用中性占位，仍以名称和编号辨识，不猜测或冒用其他代币图标。没有名称时按[无数据的字段](#empty-value)展示空值，不影响审核。
- 网络图标沿用共享规范；未收录网络图标时可使用通用网络图标，网络名称仍按原值展示。新增网络信息展示不增加网络筛选，也不改变代币识别四项。

## 7. 审核详情（F-TA-03）

适用角色与前提：具备代币准入审核查询。审核详情是准入审核详情（P-O-TA-02），从清单进入。

- 详情完整给出五部分信息：**审核概况**、**代币基本信息**、**底层资产信息**、**附件下载**、**操作记录**。代币与底层资产两组信息都要完整可得，不能只给摘要；附件以一个下载链接提供，按需下载。
- 详情不提供评分、风险提示或建议结论。
- 全部信息只读，按上游原值展示；没有手填项，也没有虚构的默认值。上游没有提供的字段按[无数据的字段](#empty-value)展示空值。
- 地址、哈希可以缩略展示，但都能复制完整值；铸造交易哈希、链上存证交易哈希、代币发行合约地址可以打开对应链的区块浏览器自行查验，链接旁给出“平台未核验，链接仅供自行查验”。区块浏览器在新窗口打开，不丢失当前位置。
- 详情始终能看到当前平台代币标识、代币编号、准入状态与提交序次。

<a id="review-overview"></a>
**审核概况。**

| 业务信息 | 含义 / 类型 |
| --- | --- |
| 平台代币标识 | 本条准入记录的平台代币标识，完整展示、可复制；规则见[平台代币标识](#platform-token-id) |
| 代币编号、代币名称、代币标识图 | 定位与辨识这笔代币；不以名称代替编号定位 |
| 来源发行平台 | 推送这笔代币的代币发行平台名称 |
| 准入状态 | 待审核／已通过／已退回 |
| 本次提交 | 本次提交时间与提交序次；待审核期间有资料更新的，另给最近更新时间 |
| 已等待时长 | 仅在本详情展示；计时口径见[时间与日期](#time-and-date)，不代表审核期限 |
| 代币状态 | 有效／失效；失效时给出对应应收账款到期日 |
| 审核结论 | 已有结论时：结论、结论时间、审核人（取当时身份）、退回原因全文；历次结论各自保留 |
| 提醒 | 有重复提醒时，给出重复原因，以及另一条记录的平台代币标识、来源发行平台、代币识别四项与准入状态，并可进入另一条记录的审核详情；通过后资料有变更时标出，并可定位到操作记录中的变更 |

### 7.1 代币基本信息（F-TA-04）

回答“这笔代币是谁、在哪条链、按什么标准、发了多少、值多少”。以代币发行平台为准。

**发行与发行方**

| 业务信息 | 含义 / 类型或枚举 |
| --- | --- |
| 发行方 | 发行这笔代币的企业名称 |
| 发行方主体标识 | 发行方在资产可信平台企业认证中的稳定主体标识；不以企业名称代替 |
| 发行方注册国家或地区 | 发行方登记所在国家或地区 |
| 发行方与底层资产卖方的关系 | 发行方是否就是底层应收账款的卖方；不一致时（如由 SPV 发行）如实并列两者名称，不自动判定合格与否 |

**代币属性**

| 业务信息 | 含义 / 类型或枚举 |
| --- | --- |
| 代币编号 | 代币发行平台给出的编号；现行格式 TK + UTC 日期 yyyyMMdd + 6 位序号，不是链上代币标识；代币识别四项之一 |
| 代币名称 | 合约配置的代币名称；没有名称配置时为合约名称 |
| 代币符号 | 合约配置的简称符号；不自造符号 |
| <a id="token-logo"></a>代币标识图 | 发行平台下发的标识图，清单中称代币图标；没有时采用中性占位，以代币名称和编号辨识，不影响审核 |
| 代币标准 | 本期为 ERC-3525；取上游原值，不写死 |
| 代币类型 | 代币标准与底层资产类型合并的单一字段，口径同[代币类型（FP-29）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#fp-29)；取上游原值，不写死 |
| 资产槽位（slot） | 本笔代币对应的 slot；代币识别四项之一 |
| 代币 ID（tokenId） | 本笔代币 slot 下的链上代币 ID，上游提供时展示 |
| 精度 | 合约定义的小数位数 |

**数量与价值**

| 业务信息 | 含义 / 类型或枚举 |
| --- | --- |
| 代币数量 | 本笔签发数量，单位枚；按上游原值，不截断 |
| 代币价值 | 本笔签发时的 USD 价值（签发价值），不是实时市值；按上游原值，不截断 |
| 签发汇率 | 签发时应收账款原币对 USD 的汇率、汇率生效时间与来源说明，取上游快照 |

**链上与发行事实**

| 业务信息 | 含义 / 类型或枚举 |
| --- | --- |
| <a id="minting-network"></a>铸造链 | 代币铸造所在的链，清单中称“区块链网络”，与链 ID 对应；口径同[资产广场铸造链](../../面客端/04-资产广场-已上架代币只读域/01-资产广场-PRD.md#token-fields) |
| 链 ID | 铸造链的链 ID；代币识别四项之一 |
| 代币发行合约 | 代币实际部署的发行合约名称与地址；地址完整展示、可复制；地址是代币识别四项之一 |
| 铸造交易哈希 | 本笔铸造的链上交易哈希 |
| 铸造时间 | 代币在铸造链上完成铸造的时间 |
| 初始收币地址 | 铸造时代币到账的地址 |
| 持有地址 | 当前全部持有地址及各自持有数量，口径同[资产广场持有方](../../面客端/04-资产广场-已上架代币只读域/01-资产广场-PRD.md#F-AM-14)；按上游原值列出，不填 0、不自行补算 |
| 代币状态 | 有效／失效，见[准入状态与叠加标记](#states) |
| 智能合约审计 | 代币发行合约是否经第三方审计、审计机构与报告日期；报告文件在[附件包](#f-ta-06)中 |

<a id="f-ta-06"></a>
### 7.3 附件下载（F-TA-06）

回答“这笔代币凭什么代表应收账款的权益、发行有没有法律与贸易依据”。用户 2026-10-21 确认：附件多会加大接口压力，平台不再逐份分列展示附件，改为所有附件合并到一个下载链接，按需下载。

- **附件范围**：本次提交随准入申请提供的全部文件，包括底层资产佐证材料与法律协议文件，合并成一个附件包。
- **链接由谁提供**：来源发行平台随推送提供附件下载链接，一次提交一个。平台只展示这个链接，不读取、不拆分、不逐份展示附件包里的文件，也不核对其中有哪些文件。
- **详情展示**：附件下载链接，以及它随哪一次提交、在什么时间提供。上游没有提供链接时为空值，不影响审核办理。
- **按需下载**：审核人需要时点击链接下载整个附件包。链接只对具备代币准入审核查询（PM-TA-01）的运营人员展示，面客端任何地方都不出现。
- **链接无法下载**（失效、过期或打不开）：说明下载失败并可重试，不改变当前位置。平台不自行修复或重新生成链接；需要发行平台重新提供时，审核人可以退回并在原因中写明，发行平台重新推送后链接随之更新。
- **链接更新**：资料更新与重新推送时，链接按最新一次推送展示；以前的链接不再作为本次审核对象，链接的更换记入操作记录。已通过后链接发生变化，按[通过后的资料变更（F-TA-10）](#f-ta-10)处理。
- 附件是否在面客端公开不由本模块决定；资产广场现行规则不展示附件影像。

<a id="f-ta-07"></a>
## 8. 通过（F-TA-07）

适用角色与前提：具备代币准入审核处置；准入状态为待审核、代币状态为有效，且同一笔链上代币没有其他已通过的记录。

- 代币状态不是有效时，通过不可用，并说明原因（失效时给出到期日）；退回仍可用。
- 同一笔链上代币已有其他记录通过时，通过不可用，说明已通过的那条记录（来源发行平台、代币编号）并可进入其审核详情；退回仍可用。规则见[同一链上代币只能通过一条](#one-approval)。
- 字段或附件下载链接为空值、代币编号重复的提醒，都不影响通过。
- 审核人核对三组信息后点击通过即提交（用户 2026-10-21 确认），不设确认步骤或知悉勾选；没有第二位审核人。
- 提交中有明确反馈，不能重复提交；同时提交多次只成立一笔。
- 提交生效时以下任一情形成立，就地说明并拒绝，不产生结论，详情刷新为最新事实：
  - 已被他人作出结论；
  - 资料已更新（审核人打开详情后发行平台又推送了资料更新）——须看过最新资料后重新办理；
  - 代币已失效；
  - 同一笔链上代币的另一条记录已先通过；
  - 权限或账号状态已变化。
- 通过生效后：
  - 准入状态变为已通过，记录审核人与结论时间；近 7 日审结数中的通过数加一，待审核代币数减一。
  - 这笔代币成为已准入代币，此后按[资产广场](../../面客端/04-资产广场-已上架代币只读域/01-资产广场-PRD.md)规则展示，按[哪些代币可以质押（F-LS-04）](../../面客端/05-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md#f-ls-04)可被质押；两模块的衔接见[准入结果的去向（F-TA-09）](#f-ta-09)。
  - 审核结果回传来源发行平台。
  - 结论终态：不可撤销、不可改判为退回。
- 通过不改变代币事实、底层资产事实与文件，本身不产生质押或融资额度。

流程参见：[准入审核主流程（FL-TA-01）](./02-代币准入审核-流程图与状态机.md#fl-ta-01)。

<a id="f-ta-08"></a>
## 9. 退回（F-TA-08）

适用角色与前提：具备代币准入审核处置；准入状态为待审核。代币失效时也可以退回。

- 审核人填写退回原因后直接提交退回（用户 2026-10-21 确认），不设原因预览或再次确认。
- 退回原因必填，10～500 字（沿本平台审核退回原因的现行校验）；空白、仅空格或超长不能提交。原因原样回传来源发行平台，因此不得写入内部代号、内部备注或这笔代币以外的信息；提交后不可编辑或删除。
- 提交生效时已被他人作出结论、资料已更新或权限已变化的，就地说明并拒绝，不产生结论，已填原因保留，不串到其他代币。
- 退回生效后：
  - 准入状态变为已退回，记录审核人、结论时间与原因全文；近 7 日审结数中的退回数加一，待审核代币数减一。
  - 退回原因与结论回传来源发行平台；面客端始终看不到这笔代币。
  - 发行平台修改后重新推送，记录以新的提交序次回到待审核；退回次数不设上限，平台不自动终结。
- 填写中放弃退回不产生结论；保存失败保留已填原因可重试；结果不确定时先查当前事实，不显示成功、不引导重复裁定。

<a id="f-ta-09"></a>
## 10. 准入结果的去向（F-TA-09）

本节说明准入结果对其他模块和外部平台的影响；各模块内的展示与办理规则以各自正文为准，本册不改写。

| 去向 | 准入通过后 | 待审核或已退回时 |
| --- | --- | --- |
| 资产广场（代币列表、代币详情、头部汇总、搜索） | 这笔代币按资产广场规则展示并计入汇总 | 不展示、不计入汇总 |
| 借贷广场（创建项目的代币类型候选、可质押清单） | 这笔代币的持有份额可以按质押规则被选用 | 不出现在可质押清单中，不作为代币类型候选的来源 |
| 我的控制台、面客消息中心 | 按各自规则承接已准入代币的业务 | 不出现 |
| 来源发行平台 | 收到通过结果 | 退回时收到退回结果与原因全文 |

- 代币发行平台能接收审核结果，也能对退回的代币修改后重新推送（用户 2026-10-21 确认按此定义）。结果回传失败时，结论照常生效、不回滚，操作记录标出“审核结果回传失败”。
- 准入通过之后，代币失效、持有地址变化、质押与解押等都是上游或借贷业务的事实，不回到本模块重新审核。
- 本模块没有下架动作；已通过的代币从面客端消失只可能来自其他模块已定义的规则（如资产广场对缺关键字段代币的不展示），不由本模块触发。

<a id="f-ta-10"></a>
## 11. 通过后的资料变更（F-TA-10）

适用对象：准入状态为已通过的代币，发行平台又推送了准入资料（代币基本信息、底层资产信息、附件下载链接）的变更。用户 2026-10-21 确认：本期不重审，保持已通过并照常展示，只标记提醒运营。

- 代币状态（有效／失效）与持有地址变化是动态事实，不算资料变更，不做标记。
- 其他准入资料的变更：准入状态保持已通过，面客端照常展示（展示内容以上游最新事实为准）；记录标“通过后资料有变更”，操作记录新增“通过后资料变更”，并能看到变更前后的值或链接。
- 运营人员查看变更后，可以把该标记确认为已知悉；确认只清除清单中的提醒，不产生结论、不改变准入状态，操作记录保留确认人与时间。

流程参见：[推送更新与重新提交（FL-TA-02）](./02-代币准入审核-流程图与状态机.md#fl-ta-02)。

<a id="f-ta-11"></a>
## 12. 操作记录（F-TA-11）

本笔代币的全部事实只记在一条按发生时间倒序的操作记录里，不另设审核历史或第二套进度明细。

- 记录的事件：提交准入申请（含提交序次）、资料更新、审核通过、审核退回、重新提交、代币变为失效、通过后资料变更、确认已知悉变更、审核结果回传失败。
- 每条记录有真实发生时间与时区；时间缺失标“待核实”。
- 每条记录有主体：审核结论与确认已知悉显示当时的审核人，发行平台推送标“来源发行平台”及平台名称，系统判定标“系统”；主体缺失标“待核实”，不推定为审核人。
- 每条记录写明结果、前后状态与原因全文；资料更新与资料变更写明变化的信息项与附件下载链接。
- 历次提交、结论、退回原因全文、审核人与时间都能从操作记录取得；重新提交不覆盖以前的原因，也不把上一次结论改写为本次结论。
- 记录只读，不可编辑、删除或手工补完；同一事件重复到达只保留一条。
- 加载中、暂无记录、读取失败分别说明。
