<a id="entry"></a>
## 1. 模块是什么

平台预置了若干份协议（例如服务条款、隐私政策一类），面客端任何角色（含未登录的访客）都可以阅读协议文本。本模块让运营人员维护这些协议的**内容与版本**：上传新的协议文件，立即或定时生效，调整唯一的待生效版本，查看版本历史与操作记录；同时保证面客端随时能取到本平台当前生效的那一版。

协议本身（叫什么、给哪些业务环节用、允许什么文件格式）由平台建设方预置，运营端只读；本模块不创建、不编辑、不下线协议。本平台本期不收取任何协议同意（[登录主干的协议口径](../../面客端/01-登录主干与资产方SSO接入/01-登录主干与资产方SSO接入-PRD.md#agreement)），协议文本只供阅读。

基本原则：

- **一份协议同一时刻最多一个草稿、一个待生效、一个已生效版本。** 草稿与待生效是同一个待完成版本的先后阶段；有待生效时，所有更新都在这一个待生效版本上进行，不另建版本。
- **更新入口只有一个。** 不论协议处在什么状态，动作都叫“更新协议”，系统按当前情况决定打开草稿、待生效版本还是新建草稿。
- **已生效和已归档的内容永远不能就地修改。** 想换内容只能经新版本生效；旧版本到另一版本生效或协议下线时自动归档。
- **版本历史只读。** 历史版本只能查看和下载，不能恢复、复制成新版本或删除。
- **下线由建设方执行，重新上线是一份全新的协议。** 下线直接取消一切未完成的计划；重新上线不继承旧协议的任何版本、计划或记录。
- **本平台的协议与另两个平台互不影响。** 同一份规格由运营管理平台、代币发行平台、资产可信平台各自使用，内容、版本与生效各自独立（见[平台独立](#platforms)）。

**一个完整的例子。** 某份已上线协议当前生效版本是 v2。运营管理员从共享导航进入“协议管理”，在列表中找到它，进入协议详情：基本信息里先是协议定义，后是操作进度。管理员点“更新协议”，系统新建 v3 草稿并带入 v2 的文件；管理员换上新文件、填写变更说明，选择定时生效、计划时间为次日 10:00（距现在不少于 5 分钟），在发布确认中核对协议名称、版本号、文件与带时区的计划时间后确认。v3 成为唯一的待生效版本，v2 仍在生效，面客端仍读到 v2；管理员回到协议详情，操作进度新增一条“发布（定时）”。当天下午发现文件有错字，管理员再点“更新协议”，直接打开的就是 v3 这一个待生效版本，换文件后确认更新——仍是 v3、计划不变，操作进度记下这次调整前后的文件名。次日 10:00 到点，v3 自动生效、v2 自动归档，面客端最迟 5 分钟内读到 v3；全体运营收到“定时生效成功”告警，从告警打开即进入 v3 的版本详情，读完返回原消息。

<a id="out-of-scope"></a>
### 1.1 本期不做

- 运营创建、编辑、下线或删除协议及协议类型；协议定义由建设方预置。
- 在线编辑协议正文、协议正文分语种版本（一个版本只有一个文件）。
- 恢复历史版本、以历史版本为底复制新建、手动归档、删除已生效或已归档版本。
- 审批、复核、双人确认。
- 面客侧的协议同意、同意记录、强制重新同意（本平台本期不收取协议同意）。
- 协议相关的邮件、短信或推送；发给资产方、资金方的协议更新通知。
- 跨平台总控台、在本端切换或批量管理另两个平台的协议。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 协议 | 建设方预置的一份协议对象，有固定的协议标识；运营只维护它的内容与版本 |
| 版本 | 协议的一份内容，含一个协议文件；版本号形如 v1、v2，只在本协议内计数 |
| 草稿 | 尚未发布的版本，可反复保存、替换文件 |
| 待生效 | 已定时发布、尚未到点的版本；同一协议最多一个 |
| 已生效 | 面客端当前读到的那一版；同一协议最多一个 |
| 已归档 | 曾经生效、已被新版本替换或因协议下线而退出的版本 |
| 已取消 | 协议下线时尚未生效的草稿或待生效版本所转入的只读终态；与运营“撤销待生效”不同 |
| 工作版本 | 当前办理所需的草稿或待生效版本 |
| 待生效调整 | 在同一个待生效版本上修改文件、说明、生效方式或计划时间并确认；版本号不变 |
| 撤销待生效 | 运营主动取消待生效计划，该版本退回同号草稿 |
| 下线 | 建设方停止某份协议的使用；协议转为已下线并只读留存 |
| 重新上线 | 建设方以完整的新定义上线一份新协议；与已下线的旧协议是两个对象 |
| 文件内容指纹 | 标识某个协议文件内容的指纹值，用于核对读到的文件就是这一版（原称“内容凭据”） |
| 操作进度 | 某份协议已发生的全部操作及其结果的记录，即协议操作记录 |

## 3. 通用规则

<a id="entry-order"></a>
### 3.1 功能入口与信息域

- 本模块入口是管理端共享导航中的“协议管理 / Agreements”；入口可见性按[权限](#permissions)判定，导航的承载与样式由设计决定。
- 本期四个信息域：协议列表（P-O-AG-01）、协议详情（P-O-AG-02，含“基本信息”与“版本历史”）、更新协议（P-O-AG-03）、版本详情（P-O-AG-04）。“基本信息”“版本历史”“版本详情”“操作进度”是信息域名称，“更新协议”“发布确认”“确认更新”是业务动作与其确认环节，均与界面上的位置和承载形式无关。
- 办理完成或返回时，回到来源并保留原筛选、排序、分页与所在位置。

<a id="permissions"></a>
### 3.2 权限与账号准入

- 本期运营端只有运营管理员一个角色（[本期预置角色（D-AL-08）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-08)），以下五项协议权限对每个正常登录的运营账号全部开通。
- 五项权限仍分开登记，作为后续细分角色时的授权单位；本期不产生按角色的差异。后续细分角色时，沿运营端账户与登录已确认的边界执行（协议历史读取仅运营管理员、操作记录全员可看、维护与发布须配套当前内容查询，见[协议读取边界（D-AL-33）](../01-运营端账户与登录/01-运营端账户与登录-PRD.md#d-al-33)）。

| 阅读或动作 | 所需权限 |
| --- | --- |
| 协议列表、协议定义、当前生效内容、草稿与待生效版本 | 协议当前内容与工作版本查询（PM-AL-09） |
| 更新内容、保存或丢弃草稿、填写待生效调整 | 协议内容与版本维护（PM-AL-10），并须同时具备 PM-AL-09 |
| 发布草稿、确认待生效调整、撤销待生效 | 协议版本发布（PM-AL-11），并须同时具备 PM-AL-09；确认待生效调整还须 PM-AL-10 |
| 版本历史、已归档与已取消版本、被调整替换掉的旧文件的查看、预览与下载 | 协议历史版本读取（PM-AL-15） |
| 操作进度 | 协议操作记录查看（PM-AL-16）；不以 PM-AL-09 或运营端消息查看（PM-AL-12）为前提 |
| 协议告警站内信 | 运营端消息查看（PM-AL-12）；按[运营端消息通知](../07-运营端消息通知/01-运营端消息通知-PRD.md)阅读，不替代目标版本的权限 |

- 交付配置中维护或发布未配套 PM-AL-09 时，对应动作被拒绝，并说明须由建设方修正交付配置；不静默通过，也不自动补授权。
- 共享账户菜单展示本人当前邮箱与真实角色；展示内容不改变授权。
- 本模块不新增人员或授权管理功能，不按运营机构或本人经办过滤数据。SPV 沿同一运营角色体系，不新增账号类型、机构过滤或跨平台权限。
- 账号未登录、登录失效、待首登改密或已锁定时，不开放任何协议内容与记录，按运营端账户与登录引导；已打开的办理也不能提交。
- 无权访问时不展示对应入口；直接访问被拒绝，不泄露记录是否存在，并可返回原入口。
- 内容查询、历史读取、记录读取分别判定；进入信息域、下载文件、从操作记录或消息跳转都不得绕过。
- 游客、面客账号与另两个平台的账号不属于本端运营人员，不能读取任何管理侧内容；公开读取只有[当前生效版本](#f-o-ag-11)。

<a id="platforms"></a>
### 3.3 平台独立

- 本规格由运营管理平台、代币发行平台、资产可信平台三个平台各自使用；各平台有自己的协议定义、文件、版本、当前生效版本、操作记录与消息，同名协议或相同协议标识不表示共用内容。
- 协议标识只在本平台内唯一；另一平台有相同标识不构成冲突，运营人员无需添加平台前缀，也无需填写或选择平台维度。
- 本端的发布、撤销、到点生效、生效失败或下线，都不改变另两个平台的版本、文件、计划、消息或其面客端读到的内容；反之亦然。
- 本端列表、管理入口与读取只服务本端协议，不提供平台列、平台切换或跨平台批量读取。
- 本端登录或授权不能取得另两个平台的管理权限；SPV 与运营同一主体也不代表跨平台授权。
- 本平台的协议由运营管理平台维护、借贷面客端读取；另两个平台的实际协议清单、角色与信息域由各自登记，见[依赖](#dependencies)。

### 3.4 时间、语言与展示

- 所有时点按本人偏好时区展示并标注时区；计划生效时间按同一真实时刻判断，切换时区只改变显示，不改变计划。
- 界面默认英文，支持中英即时切换；切换不清空已填内容，也不改变任何协议文件。规则沿三平台共享国际化基线。
- 关键状态的英文名称：Draft 草稿、Scheduled 待生效、Active 已生效、Archived 已归档、Cancelled 已取消、Unpublished 未发布、Offline 已下线；动作的英文名称：Update agreement 更新协议、Save draft 保存草稿、Publish 发布、Confirm update 确认更新。字段英文对照见[字段命名与术语对照表](../../00-字段命名与术语对照表.md)第 7 节。
- 长名称、协议标识与文件名的完整值须可获得；文件内容指纹可复制。
- 状态须有文字表达，不只靠颜色区分。
- 操作记录与通知中的人员邮箱按共享脱敏规则展示，不展示完整 IP。

<a id="states"></a>
## 4. 状态

### 4.1 版本状态

| 版本状态 | 允许的业务动作（另需权限，且协议已上线） | 谁能读取内容 |
| --- | --- | --- |
| 草稿 | 编辑、保存、发布、确认丢弃 | 按 PM-AL-09；不公开 |
| 待生效 | 在同一版本上调整并确认，或撤销待生效 | 按 PM-AL-09；被调整替换掉的旧文件按 PM-AL-15；不公开 |
| 已生效 | 本版本不能修改；可经“更新协议”准备下一版本 | 按 PM-AL-09；面客端公开读取 |
| 已归档 | 无任何写动作 | 按 PM-AL-15；不公开 |
| 已取消 | 无任何写动作，不能恢复 | 按 PM-AL-15；不公开 |

- 定时生效失败的待生效版本仍是待生效，在状态上附加“生效失败”，不另设版本状态。
- 取消编辑、并发提交被拒、提交失败都不是版本状态。

### 4.2 协议上线状态与协议状态

协议上线状态（已上线 / 已下线）描述协议对象本身，版本状态描述单个版本，二者是两个量。协议列表展示的“协议状态”由二者组合得出：

| 协议上线状态 | 版本情况 | 协议状态 | 更新协议打开什么 | 面客端公开读取得到 |
| --- | --- | --- | --- | --- |
| 已下线 | 任意 | 已下线 / Offline | 不可用，全部维护与发布动作不可执行 | 协议已下线 |
| 已上线 | 有已生效版本，可同时有草稿或待生效版本 | 已生效 / Active | 有待生效时打开该待生效版本；无待生效、有草稿时打开该草稿；都没有时新建下一编号草稿 | 当前生效版本 |
| 已上线 | 无已生效版本，有待生效版本 | 待生效 / Scheduled | 该待生效版本 | 暂无生效版本 |
| 已上线 | 无已生效与待生效版本，有草稿 | 草稿 / Draft | 该草稿 | 暂无生效版本 |
| 已上线 | 无任何版本 | 未发布 / Unpublished | 新建空白首份草稿 | 暂无生效版本 |
| 定义已被建设方移除 | 原有版本全部留存 | 不在当前协议列表中出现，管理侧仍可按原协议定位留存 | 不可用 | 协议不存在 |

- 待生效版本存在时，列表须能获知其版本号与计划时间，但不能把它当作当前生效版本；“当前生效版本”一栏仍为“—”。

状态图见[单个版本状态机（ST-O-AG-01）](./02-运营端协议管理-流程图与状态机.md#st-o-ag-01)与[协议对象的上线与下线（ST-O-AG-02）](./02-运营端协议管理-流程图与状态机.md#st-o-ag-02)。

## 5. 协议定义、列表与检索（F-O-AG-01～F-O-AG-03）

适用角色与前提：正常登录的运营人员，具 PM-AL-09；从[功能入口](#entry-order)进入协议列表（P-O-AG-01），从列表中的协议进入协议详情（P-O-AG-02）。

### 5.1 协议详情的组成

- 协议详情包含“基本信息”与“版本历史”两个信息域；版本历史按 PM-AL-15 开放。首次从列表进入默认落在基本信息；重新取数和浏览器前进后退保留当前所在的信息域。
- 基本信息由“协议定义”与“操作进度”构成，二者须同时可得，顺序为先定义后进度。当前版本与待生效计划不另立独立信息域，操作记录也不另设独立信息域。
- 基本信息指当前所选协议的定义，不是某个版本的摘要。
- 当前生效版本与工作版本须有可达的只读查询入口，按 PM-AL-09 进入版本详情（P-O-AG-04）。
- 更新动作统一叫“更新协议 / Update agreement”，不随草稿状态改名；规则见[更新协议与内容维护](#f-o-ag-04)。

### 5.2 协议定义字段

协议定义全部只读，运营端不提供新增、编辑、下线、删除协议及协议类型的入口。下表的“必填”指协议定义是否完整，不是运营可编辑的内容；没有提供的默认值不能补成真实业务值。

| 业务信息 | 含义与类型 | 必填与校验 | 默认值 |
| --- | --- | --- | --- |
| 协议标识 | 文本；引用该协议的固定标识 | 必填；本平台内唯一；上线后不可变；字符与长度限制待确认（[协议定义供给（Q-O-AG-05）](#q-o-ag-05)） | 无 |
| 协议类型编码 | 文本；本平台自定义的协议分类编码 | 必填；取本平台定义，不套用他平台类型清单 | 无 |
| 协议类型名称（中／英） | 文本；协议分类的双语名称，列表与筛选依据 | 两种语言均必填 | 无 |
| 协议名称（中／英） | 文本；按界面语言显示的协议名称 | 两种语言均必填；只表示名称双语，不表示协议文件分语种 | 无 |
| 协议用途说明 | 文本；供运营理解该协议用途的内部说明 | 可选；不对外公开；长度限制待确认（[协议定义供给（Q-O-AG-05）](#q-o-ag-05)） | 空 |
| 适用业务环节 | 环节清单；每项含编码与中英文名称 | 必填；写明本平台面客端在哪些环节取用本协议；实际清单与字段限制待确认（[协议定义供给（Q-O-AG-05）](#q-o-ag-05)） | 无 |
| 允许上传格式 | 格式清单；本协议可上传的文件格式 | 必填；按协议逐项明确；适用业务环节需要在线阅读时应选择可在线呈现的格式 | 无全局兜底 |
| 单文件大小上限 | 文件容量；单个文件可接受的最大容量 | 必填；按协议明确数值与单位，上传前须可获知；未明确不得上线 | 无全局兜底 |
| 协议上线状态 | 二值：已上线 / 已下线 | 必填；运营只读；已下线仍保留历史 | 无 |
| 默认排序值 | 数值；协议列表的默认排列依据 | 可选；缺值时的顺序与取值范围待确认（[协议定义供给（Q-O-AG-05）](#q-o-ag-05)） | 待确认 |

- 协议定义由研发随既定配置发布提供，本册不展开实现。新定义可用后以“未发布”出现在列表。
- 缺允许上传格式或单文件大小上限的定义不得上线，不作为可用协议出现在列表。
- 协议由系统预置、本模块只维护内容与版本，这一点须在协议列表与协议定义处可获知。
- 已下线与定义被移除的结果见[协议下线、留存与重新上线](#offline)。

### 5.3 协议列表

- 每条协议须可得：协议名称、协议标识、协议类型、适用业务环节、当前生效版本、生效时间、版本数、协议状态、最近更新，以及进入协议详情的动作。
- 无当前生效版本或从未有操作时，对应值取“—”；版本数不含草稿。
- 适用业务环节较多时列表可不展示全部，但完整清单须可获得；协议详情完整展示。
- 协议状态按[协议上线状态与协议状态](#states)的组合表判定。
- 列表只含本平台协议；没有新建协议的入口。

### 5.4 检索、排序与分页

| 条件 | 规则 |
| --- | --- |
| 关键词 | 同时模糊匹配协议名称（中英）与协议标识；忽略大小写与首尾空格 |
| 协议类型 | 多选 |
| 适用业务环节 | 多选 |
| 协议状态 | 多选 |
| 更新时间 | 按最近操作时间筛选，按本人时区展示；起止端点与只填一侧时的规则待确认（[协议定义供给（Q-O-AG-05）](#q-o-ag-05)） |

- 不同条件取交集，同一条件多选取并集；“查询”应用条件，“重置”清空条件并回到第 1 页。
- 默认先按默认排序值，再按最近更新时间从新到旧；生效时间、版本数可排序。
- 默认每页 20 条，可切 50、100；重新取数与浏览器前进后退保留筛选与分页。
- 取数进行中须可识别；取数失败可重试并保留条件，不把失败显示成没有协议。
- 两种空结果须可区分：本端尚无协议定义时说明“暂无协议，协议由系统预置”；筛选无匹配时说明没有符合条件的协议并提供重置。两种情形都没有新建协议的入口。

## 6. 更新协议与内容维护（F-O-AG-04、F-O-AG-05）

适用角色与前提：协议为已上线对象；运营人员具 PM-AL-09，并具维护或发布权限。下线留存的协议不能再编辑或发布；重新上线的新协议从空白首版开始。

### 6.1 更新协议打开什么

协议详情的“更新协议”统一进入更新协议（P-O-AG-03）。只有查询权限时不提供该动作。更新指协议内容与生效计划；协议定义仍不可编辑。版本历史与版本详情中没有更新入口。

| 进入时的协议情况 | 打开的版本与默认内容 | 结果约束 |
| --- | --- | --- |
| 有待生效版本 | 直接载入这一个待生效版本的文件、变更说明、生效方式、计划时间和需重新同意标记；须明确告知版本号与待生效状态 | 不创建另一版本，不先撤销为草稿，不出现“撤销并发布”或覆盖另一草稿的流程 |
| 无待生效版本，有未完成草稿 | 继续该草稿 | 不创建第二个草稿 |
| 无待生效版本与草稿，有当前生效版本 | 新建下一编号草稿，复制当前生效文件；变更说明为空；生效方式默认立即生效；需重新同意标记默认为否 | 当前生效文件保持原样，修改只发生在新草稿 |
| 从未有过版本 | 新建空白首份草稿 | 保存时可暂缺文件，发布时必须完整 |

- 只有维护权限才能编辑内容。只有发布权限时，打开现有草稿为只读发布、打开待生效版本为只读计划处置；没有可处置的版本时不创建空草稿，并说明暂无可发布内容。
- 调整待生效版本的文件、说明、时间或生效方式并正式确认，须同时具有维护与发布权限。
- 若既有数据同时存在草稿与待生效版本，优先打开待生效版本，保留另一草稿，不自动发布或覆盖；撤销会导致出现两个草稿时阻断撤销，提示先处理冲突，不静默丢弃资料。

### 6.2 文件规则

- 一个版本只对应一个当前文件；没有语种选择，也没有正文在线编辑。
- 一次只提交一个文件；一次选多个文件、空文件、改扩展名伪装的文件均被拒绝。
- 格式与大小按本协议定义；大小等于上限可接受，超过才拒绝。错误须说明本协议实际的格式要求或大小上限。
- 已上传的文件须可获知原始文件名、大小、上传时间，并可替换和下载。
- 上传进行中须可识别；上传失败保留原文件与其他已填内容，可重试。
- 草稿反复替换文件不生成新版本；替换成功后旧草稿文件不保留。
- 调整待生效版本时，新选文件与其他改动在“确认更新”成功前只是本次未提交的内容，不改变已确认的文件与既有生效计划；离开办理不会暂停定时计划。

### 6.3 版本字段

| 业务信息 | 含义与类型 | 必填、可编辑与校验 | 默认值 |
| --- | --- | --- | --- |
| 版本号 | 文本，形如 v1、v2 | 系统生成、只读；新建版本取更大且从未用过的编号；待生效调整与撤销后再发布保持原版本号；丢弃后编号不复用 | 现有草稿或待生效版本取原值；新建时自动递增 |
| 协议文件 | 文件；协议正文或模板 | 保存草稿时可缺；发布或确认待生效调整时必须已成功上传且符合本协议限制；只有维护权限可替换 | 按[更新协议打开什么](#f-o-ag-04)载入 |
| 生效方式 | 枚举：立即生效 / 定时生效 | 发布或确认调整时必填；修改需维护权限，正式提交另需发布权限 | 新草稿为立即生效；待生效版本沿用定时生效 |
| 计划生效时间 | 时间点，精确到分钟 | 定时发布或调整后仍为定时时必填；提交时须晚于当前时间至少 5 分钟，恰好 5 分钟有效；按本人时区输入并标注时区 | 新草稿为空；待生效版本载入原计划 |
| 变更说明 | 文本；说明这次内容或计划的变化 | 保存草稿时可缺；发布或确认调整时去掉首尾空白后不能为空，最多 500 字符 | 新草稿为空；待生效版本载入原说明 |
| 需重新同意标记 | 是 / 否 | 可选；只随公开的当前生效版本一并提供，不触发任何面客提示、通知或强制流程；本期本平台不收取协议同意，该标记是否保留待确认（[需重新同意标记的去留（Q-O-AG-08）](#q-o-ag-08)） | 新草稿为否；待生效版本沿用原值 |

### 6.4 草稿办理

- 提供保存草稿、发布、丢弃草稿三个动作，按权限开放。
- 保存允许缺文件、变更说明与计划时间，但已填内容仍受格式与 500 字符上限约束；保存成功后本次办理可继续，并明确告知已保存。
- 发布规则见[发布、待生效调整与生效](#f-o-ag-06)。
- 丢弃草稿须二次确认，取消则无任何变化；确认后移除草稿与草稿文件，不影响已生效或已归档的内容。曾由待生效退回的草稿被丢弃时，其已确认过的调整与撤销记录继续保留在操作进度中。

### 6.5 待生效版本办理

- 主动作为“确认更新 / Confirm update”；不提供保存草稿、新建另一版本、丢弃待生效版本。
- 确认更新须同时具有维护与发布权限；没有任何改动时不可提交。
- “撤销待生效”在本次办理内提供，由发布权限控制，须单独二次确认；结果见[发布、待生效调整与生效](#f-o-ag-06)。
- 取消编辑或离开只放弃本次未提交的输入，撤销待生效才取消已确认的计划；两者的后果须分别说明。
- 有维护、没有发布权限时可准备内容与核对文件，但不能正式保存待生效调整；须明确告知这一限制，不伪装成保存成功。

### 6.6 异常与边界

- 离开办理时若有未提交内容须先确认；取消则继续本次办理，确认才放弃输入。
- 重新取数将丢弃已填内容时先确认。
- 草稿或待生效版本已被他人修改时，后提交的旧内容被拒，提示重新取数；失败保留可重试的输入。
- 提交进行中不重复执行。
- 待生效版本已到点生效时，旧内容不能再覆盖，提示“该版本已生效，请返回协议详情后更新协议”；本次输入可供复制核对，但不会自动变成已生效内容或另一已发布版本。

流程参见[按对象读取与统一更新入口（FL-O-AG-01）](./02-运营端协议管理-流程图与状态机.md#fl-o-ag-01)，状态参见[单个版本状态机（ST-O-AG-01）](./02-运营端协议管理-流程图与状态机.md#st-o-ag-01)。

## 7. 发布、待生效调整与生效（F-O-AG-06）

适用角色与前提：发布已保存的草稿须具 PM-AL-09 与 PM-AL-11；本次提交中如有内容变化，另须 PM-AL-10。不要求第二人复核，但发布权限不能绕过维护权限。

### 7.1 提交前校验与确认

- 文件、变更说明、计划时间均做完整校验；缺文件或任一字段不符合规则时，须能定位到具体项。
- 草稿发布使用“发布确认”，待生效调整使用“确认更新”。两者都须展示协议名称、版本号、文件名与大小、生效方式、带时区的生效时间，以及需重新同意标记不会引发任何面客动作的说明。
- 确认更新另须展示变化前后的文件名、计划时间、生效方式与变更说明；未变化的项无需重复对照。
- 确认后按完整成功结果执行；取消则不改变已确认的内容与计划。
- 成功后回到协议详情的基本信息，操作进度随之更新。

### 7.2 各情形的结果

| 情形 | 成功结果与边界 |
| --- | --- |
| 草稿立即发布 | 本版本成为已生效，原已生效版本同时自动归档；实际生效时间为本次发布成功的时刻 |
| 草稿定时发布 | 本版本成为唯一的待生效版本，原已生效版本不变；首版定时等待期间，面客端公开读取仍是暂无生效版本 |
| 待生效调整后仍为定时 | 在同一待生效版本上采用新确认的文件、说明或时间；版本号不变；新计划整体替代原计划，原时间不再触发生效；版本历史不新增一条，原版本也不退回草稿 |
| 待生效改为立即生效 | 确认时提示将立即替换当前生效版本；成功后该版本直接成为已生效，旧生效版本归档，原定时计划结束；版本号不变 |
| 到点自动生效 | 按最近一次确认成功的内容与时间生效，原已生效版本同时归档；不以运营人员是否在线为条件 |
| 撤销待生效 | 只能在更新协议中执行；撤销确认须明确版本号、计划时间及后果。确认后退回同一编号的草稿，保留已确认的文件，取消计划；当前已生效版本不变；未提交的编辑内容不随之保存。已有其他草稿时按[更新协议打开什么](#f-o-ag-04)的冲突规则阻断 |
| 提交失败或校验失败 | 既有待生效版本的文件与计划全部保持原样，当前生效版本不变；须说明失败并保留输入；不会出现一部分用新文件、一部分仍用旧计划 |
| 办理期间到点生效 | 到点生效先完成时，确认更新或撤销被拒绝，转为只读并提示返回；调整先确认成功时，只按新计划生效。两种结果必须明确，不出现生效后被旧内容改写 |
| 到点生效失败 | 保留待生效版本并附加“生效失败”，旧生效版本不变；首版仍无当前生效版本；记录失败并发送站内信。再点“更新协议”仍打开这一版本，可重新设定未来时间或改为立即生效，无需先撤销 |

### 7.3 版本数量、编号与内容固定

- 同一协议任意时刻最多一个待生效、一个已生效版本；正常替换不得出现同时两份生效或暂时没有生效版本的中间结果。
- 有待生效版本时，所有更新都复用这一个版本。
- 版本号在新建草稿时分配，此后编辑、保存、定时、调整、撤销后再发布都不改变；新建版本取更大且从未用过的编号，丢弃后允许出现编号空档，不能人工指定或复用。重新上线的新协议从 v1 开始，与旧协议同号不代表同一版本。
- 已生效、已归档、已取消版本的内容与文件内容指纹固定不变。
- 待生效版本可经授权确认调整；每次确认的文件、文件内容指纹、时间与操作人都保留可追溯的调整记录，不覆盖前一次确认的事实。
- 生效时冻结最终实际生效的文件及其文件内容指纹；此后读取历史时不会变成曾被替换掉的待生效文件。被替换掉的旧文件属于历史内容，读取须 PM-AL-15。
- 计划按同一真实时刻判断；下线与计划或编辑相遇时按[协议下线、留存与重新上线](#offline)处理，不采用“暂停后恢复原计划”的做法。

通知：到点生效成功、到点生效失败、撤销待生效三处向全体运营发送站内信，见[消息通知](#notifications)。
流程参见[草稿发布与原待生效版本调整（FL-O-AG-02）](./02-运营端协议管理-流程图与状态机.md#fl-o-ag-02)。

## 8. 协议下线、留存与重新上线（F-O-AG-06、F-O-AG-07、F-O-AG-09、F-O-AG-11）

适用前提：下线与重新上线由建设方执行（需求方 P12 裁定，开发层面直接取消）；运营端不新增上下线动作、审批或人工撤销步骤。本节只定义运营人员与面客端可观察到的结果。

### 8.1 下线的结果

| 情形 | 结果 |
| --- | --- |
| 下线成功 | 原协议停止对外提供当前内容；全部待生效计划直接取消，到原计划时间也不会生效；原草稿与待生效版本结束办理并只读留存，不退回可编辑草稿、不等待恢复 |
| 原来有已生效版本 | 转为已归档，保留原实际生效时间、文件与归档时间；这不是运营手动归档 |
| 原来有草稿或待生效版本 | 转为已取消；原状态、原计划与取消原因“协议下线”在版本详情与操作进度中可查；从未生效的版本实际生效时间为空，不伪造生效或归档经历 |
| 到点生效失败后再下线 | 原失败事实保留，未完成的计划按下线取消；不能再尝试原计划，取消也不报告成生效失败或成功 |
| 办理、发布、撤销或到点生效与下线相遇 | 下线成立后，保存、发布、确认更新与原计划都不能再成功；旧的办理提交须告知协议已下线并提供返回，未提交输入不转为新协议。若到点生效先成功，保留这次真实生效记录，再按下线归档；下线后旧内容不会重新成为当前可用版本 |
| 下线结果未成功或未明 | 不展示已下线或已取消；说明结果尚未确认，重新读取可信状态；不把未确认的结果写成记录或通知 |
| 定义被移除 | 保留原协议身份与必要的历史信息；版本历史与操作进度仍可按原协议定位；面客端不再取用原内容，公开读取得到“协议不存在”；不因定义消失删除历史，也不误指新协议 |

- “已取消”只表示因下线而终止的草稿或未生效版本，是只读终态；与运营主动撤销待生效不同，后者在已上线协议内退回同号草稿。
- 下线留存的版本仍按原版本号从新到旧排列。

### 8.2 重新上线

- 建设方提供完整的新定义，成为一份独立的新协议：初始为未发布，无当前生效版本、无待生效计划、无旧草稿。
- 首次更新新建空白 v1，文件与说明重新准备，发布仍按既定校验。
- 新协议有独立的协议与版本标识；名称或用途相同也不继承旧协议的文件、版本序列、计划、操作记录或消息归属，不以“恢复旧版”或复制旧版本代替全新上线。

### 8.3 旧地址与留存

- 旧版本、旧操作记录与旧消息仍指向原协议；版本内容按 PM-AL-15 读取，操作记录按 PM-AL-16 读取；无权时说明并可返回。任何情况下都不自动转向同名新协议或其 v1。
- 下线的留痕包括原协议、关联版本（如有）、原计划（如有）、发生时间、执行方、结果与原因“协议下线”；无版本的定义下线关联版本取“—”，不造 v0 或其他版本。自动取消与自动归档的执行方记为“系统”，不冒记为某位运营人员。
- 旧记录与旧文件永久保留、不可篡改；留存不等于公开。用户已下载的文件不在本模块追回范围。
- 重新上线的新协议单独计数，旧记录不混入新协议的操作进度。

流程参见[下线、旧对象留存与全新上线（FL-O-AG-06）](./02-运营端协议管理-流程图与状态机.md#fl-o-ag-06)。

## 9. 版本历史与版本详情（F-O-AG-07）

### 9.1 版本历史

适用角色与前提：具 PM-AL-15 的运营人员，从协议详情的“版本历史”进入。

- 按版本号从新到旧，包含草稿、待生效、已生效、已归档与已取消的版本；当前已生效的是哪一条须可识别。
- 版本历史只承载辨认版本所需的信息与打开内容的动作，完整信息在版本详情。

| 业务信息 | 取值与空值 |
| --- | --- |
| 版本号 | v{n}，本协议内唯一；待生效版本多次调整仍是同一条 |
| 版本状态 | 草稿、待生效、已生效、已归档、已取消；生效失败的待生效版本附加“生效失败” |
| 生效时间 | 待生效版本取最近确认的计划时间并标明是计划；已生效与已归档版本取实际生效时间；草稿与从未生效的已取消版本取“—”，原计划到版本详情与操作进度查看；均带时区 |
| 可做的动作 | 只有“查看”与“下载协议”；尚无文件时下载不可用并说明原因，查看仍可用 |

- 版本历史中没有更新、编辑、发布、撤销、丢弃、删除、手动归档、恢复或“以此新建版本”；没有任何版本时也不出现这些动作。维护内容回到协议详情的“更新协议”。持有全部写权限也不改变这一范围。
- 已生效版本在另一版本生效成功或协议下线时自动归档，没有手动归档入口。

### 9.2 版本详情

适用角色与前提：当前生效版本与工作版本按 PM-AL-09 读取；已归档、已取消版本与被替换掉的旧文件按 PM-AL-15 读取。可从协议详情的当前查询入口、版本历史、操作进度或消息进入。

- 版本详情（P-O-AG-04）是独立的只读信息域，有可直接访问的地址，关联指定协议的指定版本；不能用当前生效内容冒替被查看的版本。
- 除查看内容、复制文件内容指纹、下载与返回外，没有写动作。

| 业务信息 | 含义与取值 |
| --- | --- |
| 协议标识、版本标识与版本号 | 系统提供，必有、只读；必须对应打开的那一版 |
| 版本状态 | 草稿、待生效、已生效、已归档、已取消；由[发布、待生效调整与生效](#f-o-ag-06)与[下线](#offline)决定，不能手动修改 |
| 文件信息 | 文件实际名称、格式、大小、上传时间；只读；没有文件时为空 |
| 生效方式与计划 / 实际生效时间 | 带时区；计划与实际明确区分；未发生的时点为空 |
| 归档时间 | 只读；未归档时为空 |
| 取消时间、取消前状态与取消原因 | 只对已取消版本；须有真实取消时点；原计划只在曾经定时时有值 |
| 最近草稿保存时间与保存人、首次发布时间与发布人、最近确认调整时间与操作人 | 只读；尚未发生时不填造时间或人员；邮箱脱敏 |
| 变更说明 | 只读 |
| 需重新同意标记 | 只读 |
| 文件内容指纹 | 对应所展示的协议文件；只读、可复制；待生效版本标明“尚未生效，仍可经确认调整”，已生效与已归档版本固定 |

- 文件可在线呈现时提供预览与下载，不能呈现时说明并提供下载；预览失败可重试或下载；没有文件时明确“尚未上传文件”，不提供空下载。
- 返回时回到来源并保留原筛选、分页与所在位置：从版本历史进入的回到版本历史，从当前查询、操作进度或消息进入的回到各自来源；不能把无历史权限的人带入版本历史。
- 重新取数与浏览器前进后退仍指向原指定版本。
- 取数失败可重试；版本不存在或无权限时给出明确说明与可用的返回路径，不默认显示第一条样本。

流程参见[当前查询、版本历史与原来源返回（FL-O-AG-03）](./02-运营端协议管理-流程图与状态机.md#fl-o-ag-03)。

## 10. 操作进度与留痕（F-O-AG-09、F-O-AG-10）

适用角色与前提：具 PM-AL-16 的运营人员；不以 PM-AL-09 或 PM-AL-12 为前提。操作进度位于协议详情的基本信息中，排在协议定义之后。

- 操作进度表达该协议已发生的操作与结果，覆盖全部版本，不只取当前生效版本；不新建审批流，也不虚构完成百分比。
- 不按本人经办或所属机构过滤。

| 业务信息 | 含义与取值 |
| --- | --- |
| 操作类型 | 实际发生的业务动作：新建或保存草稿、上传或替换文件、丢弃、发布、确认待生效调整、撤销待生效、系统生效、系统归档、到点生效失败、协议下线、关联计划取消 |
| 关联版本 | 本次动作关联的版本号；版本动作必有；无版本的定义下线取“—”；始终关联原协议，不能只靠 v1 这类同号辨认新旧协议 |
| 操作人 | 实际姓名与脱敏工作邮箱；自动动作记为“系统 / System”，不冒记为发布人 |
| 操作时间 | 动作发生的时点，带时区；默认按发生时间从新到旧 |
| 结果 | 成功 / 失败；取消确认、只打开查看、未提交的输入不记为成功变更；到点生效失败明确为失败 |
| 变更摘要 | 一句话说明实际变化，完整内容须可获得；替换文件时含旧、新文件名；待生效调整时含变化前后的计划时间或生效方式；撤销时说明计划已取消并退回草稿 |

- 记录只读、由系统生成；操作类型、原协议、执行方、操作时间、结果、变更摘要均必有，关联版本按上表条件必有。
- 人工动作以发生时的姓名与脱敏邮箱为归属，之后改邮箱不改写已有记录；系统动作不填造邮箱。来源地点只展示地区摘要，不展示完整 IP。
- 每次确认的待生效调整都单独留痕，可核对当次确认前后的文件名、计划与说明；不把调整留痕伪装成多个待生效版本。
- 操作记录中不出现协议正文、附件、文件内容指纹或可取文件的地址；读取旧文件须 PM-AL-15，当前工作文件按 PM-AL-09。记录只显示脱敏的业务身份，不链接他人账户档案。
- 未发布草稿的反复替换按[文件规则](#f-o-ag-04)处理，不要求保留每一次草稿文件。
- 默认每页 20 条，可选 50、100；日期排序不因语言或时区改变实际先后。
- 三种情形须可区分：本协议尚无操作时说明“暂无操作记录”；取数失败时只影响操作进度本身、可重试，不当作没有记录；登录失效或账号不正常时按账户准入处理，不伪装成空记录。

**变更约束（F-O-AG-10）：**

- 记录只增不改、永久保留；已生效与已归档文件永久保留、不可修改或删除。
- 下线后的已取消版本与已确认调整的留存，同样按 PM-AL-15 控制读取。
- 越权、修改协议定义、覆盖已生效内容、篡改操作记录在实际执行时同样被拒绝，不能只靠不提供入口实现。

流程参见[按对象读取与统一更新入口（FL-O-AG-01）](./02-运营端协议管理-流程图与状态机.md#fl-o-ag-01)与[草稿发布与原待生效版本调整（FL-O-AG-02）](./02-运营端协议管理-流程图与状态机.md#fl-o-ag-02)。

## 11. 当前生效版本的公开读取（F-O-AG-11）

适用角色与前提：本平台面客端任何角色（含未登录的访客）阅读协议文本时读取；按协议标识读取，也可一次取多份或按协议类型取已上线协议的当前生效版本。本模块只定义取到什么与异常结果；面客侧在哪里展示协议由各消费模块定义。

| 情形 | 结果 |
| --- | --- |
| 已上线，有当前生效版本 | 取得本平台该版本的协议名称、协议标识、协议类型、适用业务环节、版本标识与版本号、文件信息与文件、文件内容指纹、生效与发布时间、需重新同意标记；版本、文件与文件内容指纹对应同一已生效内容 |
| 草稿或待生效版本 | 不作为当前版本返回；直接指定版本或访问文件也取不到未生效内容 |
| 已归档、已取消版本或被替换掉的旧文件 | 不公开提供；直接指定历史版本或旧文件地址同样不可读，不能借公开读取绕过 PM-AL-15 |
| 协议不存在（未定义或定义已移除）、协议已下线、暂无生效版本（含重新上线后尚未发布）、版本不存在 | 四种结果分别可识别，不表现为成功取得空白文件；暂无生效版本时不从旧协议或另一平台补取 |
| 读取失败 | 明确说明读取失败，不当作没有协议 |
| 另一平台有同名或同标识协议 | 始终取本平台的版本；本平台没有可用版本时不借用另两个平台的版本 |

- 公开内容不含协议用途说明、运营人员身份、操作记录或未生效草稿；不提供正文语种切换、在线富文本或平台切换。
- 当前生效版本切换后，面客端最迟 5 分钟内显示新版本（沿协议管理基线）。
- 需重新同意标记只随当前生效版本提供，本期不据此新增任何面客提示、通知或强制阻断。
- 读取字段映射与文件内容指纹约束沿协议管理基线第 9 节，本册不复制接口、参数或访问路径。

流程参见[公开当前版本读取（FL-O-AG-04）](./02-运营端协议管理-流程图与状态机.md#fl-o-ag-04)。

- **运营端账户与登录**：提供账号、会话、本期单一角色与协议相关权限项（PM-AL-09～PM-AL-11、PM-AL-15、PM-AL-16）及运营端消息查看（PM-AL-12）。
