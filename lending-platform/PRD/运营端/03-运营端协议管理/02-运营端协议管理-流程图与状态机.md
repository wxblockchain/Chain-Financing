<a id="fl-o-ag-01"></a>
## FL-O-AG-01 按对象读取与上传协议

本期唯一角色运营管理员持有全部五项协议权限；图中的权限判断对应交付配置中的各权限项（见[权限与账号准入](./01-运营端协议管理-PRD.md#permissions)）。

```mermaid
flowchart TD
    A[运营账号进入协议管理] --> B{账号正常 已完成首登改密且登录有效}
    B -->|否| C[按账户状态引导 不开放任何协议内容与记录]
    B -->|是| D{要读取什么}
    D -->|操作进度| E{具协议操作记录查看}
    D -->|基本信息 当前与待生效版本| F{具协议当前内容与工作版本查询}
    D -->|已归档与已取消版本| G{具协议历史版本读取}
    E -->|否| H[不展示 直接访问被拒绝]
    F -->|否| H
    G -->|否| H
    E -->|是| I[读取原协议的操作进度]
    G -->|是| J[版本历史中列出并可下载 见 FL-O-AG-03]
    F -->|是| K[查看基本信息 版本历史中的当前与待生效版本]
    K --> L{协议已上线 且具维护与发布权限}
    L -->|否| M[只读 不提供更新协议]
    L -->|是| N[更新协议 上传弹窗 选择文件并填写说明 见 FL-O-AG-02]
```

协议详情依次是基本信息、版本历史、操作进度，三部分同时可得。基本信息只有协议名称、协议类型、适用业务环节、协议用途说明。更新协议只采集文件与变更说明并给出格式与大小要求，没有生效时间、立即生效或草稿可选；撤销待生效是协议详情上的独立动作。

<a id="fl-o-ag-02"></a>
## FL-O-AG-02 上传、覆盖与到点生效

生效日界为每天 UTC 24:00。只有撤销待生效需要二次确认，上传直接提交。

```mermaid
flowchart TD
    A[更新协议 选择文件并上传] --> B{校验文件与权限 协议仍已上线}
    B -->|否| C[拒绝 说明原因 既有版本不变]
    B -->|是| D{已有待生效版本}
    D -->|否| E[新建下一编号的待生效版本 当天 24:00 生效]
    D -->|是| F[覆盖上传 替换待生效文件 版本号与生效时间不变 旧文件不保留]
    E --> G[待生效]
    F --> G
    G -->|24:00 前再次上传| F
    G -->|24:00 前撤销 经二次确认| H[移除待生效版本与文件 当前生效版本不变 发撤销告警]
    G --> I{24:00 到达时协议仍已上线}
    I -->|生效成功| J[成为已生效 原生效版本归档 发生效成功告警]
    I -->|生效失败| K[仍为待生效 附加生效失败 当前版本不变 发生效失败告警]
    K -->|下一个 24:00 再次生效| I
    I -->|已下线| L[待生效版本已取消 不生效 不发告警]
```

以 24:00 那一刻的待生效文件为准生效；24:00 之后提交的上传归入下一个生效日界。撤销告警是否保留待用户确认（Q-O-AG-14，推荐删除）。三类告警见[消息通知](./03-运营端协议管理-消息通知.md)。

<a id="fl-o-ag-03"></a>
## FL-O-AG-03 版本历史与下载

```mermaid
flowchart TD
    A[打开协议详情 或从消息进入] --> B[版本历史 按版本号从新到旧]
    B --> C{该版本此刻属于}
    C -->|已生效或待生效| D{具协议当前内容与工作版本查询}
    C -->|已归档或已取消| E{具协议历史版本读取}
    D -->|否| F[不列出 说明需相应权限]
    E -->|否| F
    D -->|是| G[列出版本记录 版本号 状态 生效时间 文件名 变更说明]
    E -->|是| G
    G --> H[下载该版本文件]
    H --> I{下载结果}
    I -->|成功| J[取得与该版本一致的文件]
    I -->|失败| K[说明失败 可重试]
    I -->|版本已不存在| L[说明不可下载 不改取其他版本]
```

版本历史只列版本记录并提供下载，没有查看详情、在线预览或任何写动作；持有全部写权限也不能在此恢复、上传、撤销或删除。被覆盖的文件与被撤销的版本不出现。上传人、归档与取消等经过在操作进度中查看。

<a id="fl-o-ag-04"></a>
## FL-O-AG-04 公开当前版本读取

```mermaid
flowchart TD
    A[本平台面客端读取协议] --> B{是否为公开的当前内容}
    B -->|否 历史版本或旧文件| C[不公开提供 不泄露非公开内容]
    B -->|是| D{协议定义情况}
    D -->|未定义或已移除| E[协议不存在]
    D -->|已下线| F[协议已下线]
    D -->|已上线| G{有当前生效版本}
    G -->|否| H[暂无生效版本 不从旧协议或其他平台补取]
    G -->|是| I[取得当前文件与对应信息]
    I --> J[面客端只读阅读协议文本]
```

本平台本期不收取协议同意，公开读取只用于阅读协议文本。当前生效版本切换后，面客端最迟 5 分钟内显示新版本。重新上线的新协议尚未发布时为暂无生效版本，不继承旧内容。

<a id="fl-o-ag-05"></a>
## FL-O-AG-05 事件告知、阅读与目标权限

```mermaid
flowchart TD
    A[协议业务事实] --> B{事实种类}
    B -->|上传 覆盖上传| C[办理结果与操作进度告知 不发站内信]
    B -->|下线自动取消 重新上线 记录查看 历史下载| C
    B -->|到点生效成功 到点生效失败 撤销待生效| D[向本端全体运营发送站内信]
    D --> E{是否同一事实再次送达}
    E -->|是| F[不新增 保留原消息]
    E -->|否 下一个 24 点再次失败等| G[作为新事实另发一条 不覆盖旧消息]
    F --> H[运营人员打开消息]
    G --> H
    H --> I[前往该协议的协议详情]
    I --> J{消息所指版本此刻 见 FL-O-AG-03}
    J -->|有权且版本仍在| K[版本历史中可辨认该版本 说明此后已发生的状态变化]
    J -->|无权或版本已不存在| L[说明原因 不提供受限文件 不转到新协议]
    K --> M[回到原消息]
    L --> M
```

下线自动取消不是撤销待生效，不发撤销告警；取消也不报告成生效失败。旧消息不迁到重新上线的新协议。消息的阅读、未读与跳转规则归[运营端消息通知](../07-运营端消息通知/01-运营端消息通知-PRD.md)。

<a id="fl-o-ag-06"></a>
## FL-O-AG-06 下线、旧对象留存与全新上线

下线与重新上线由建设方执行，运营端没有对应的办理动作。

```mermaid
flowchart TD
    A[建设方执行原协议下线] --> B{下线结果已成立}
    B -->|否或未知| C[不展示已下线 重新读取可信状态]
    B -->|是| D[原协议停止公开当前内容与全部办理]
    D --> E[待生效版本直接取消 转为已取消]
    D --> F[原已生效版本归档 保留真实生效经历]
    E --> G[按原协议保留文件与操作记录]
    F --> G
    G --> H[版本文件按历史读取权限下载 操作记录按记录查看权限]
    H --> I[旧地址与旧消息仍指向原协议]
    J[建设方另行提供完整的新协议定义] --> K[独立新协议 未发布 无旧文件]
    K --> L[运营上传 v1 当天 24 点生效]
```

两条流程之间没有“恢复旧协议”的箭头：原协议下线后不再回到已上线，新协议单独开始。到点生效先成功时，先记录真实生效，再按下线归档；下线先成立时，待生效版本不再生效。定义被移除后，版本历史与操作记录仍可按原协议定位。

<a id="st-o-ag-01"></a>
## ST-O-AG-01 单个版本状态机

图中是同一协议内的同一个版本；覆盖上传只替换文件，不产生新版本。

```mermaid
stateDiagram-v2
    state "待生效" as Scheduled
    state "已生效" as Active
    state "已归档" as Archived
    state "已取消" as Cancelled
    [*] --> Scheduled: 协议已上线且无待生效版本时上传
    Scheduled --> Scheduled: 24 点前覆盖上传 版本号不变 旧文件不保留
    Scheduled --> Scheduled: 24 点生效失败 附加生效失败 下一个 24 点再生效
    Scheduled --> [*]: 24 点前撤销 版本与文件移除 编号不复用
    Scheduled --> Active: 24 点生效成功
    Active --> Archived: 另一版本生效成功 或协议下线
    Scheduled --> Cancelled: 协议下线 不再生效
    note right of Archived
        文件固定 按历史读取权限下载
        不能恢复 不能修改
    end note
    note right of Cancelled
        原生效时间与取消原因记入操作进度
        不能恢复
    end note
```

每份已上线协议最多一个待生效、一个已生效版本。各状态允许的动作与读取权限见[版本状态](./01-运营端协议管理-PRD.md#states)。

<a id="st-o-ag-02"></a>
## ST-O-AG-02 协议对象的上线与下线

与单个版本状态分开；协议列表中的待生效、未发布等协议状态由协议上线状态与版本情况组合得出（见[协议上线状态与协议状态](./01-运营端协议管理-PRD.md#states)）。

```mermaid
stateDiagram-v2
    state "已上线" as Online
    state "已下线 只读留存" as Offline
    [*] --> Online: 建设方上线完整定义 初始未发布
    Online --> Online: 按权限上传与更新内容
    Online --> Offline: 建设方下线成立 终止内容使用与待生效版本
    note right of Offline
        没有回到已上线的转换
        定义被移除也保留历史与记录
        重新上线是另一份新协议
    end note
```

重新上线的新协议单独从初始状态进入已上线、未发布，不从旧协议连线，也不携带旧版本或记录。
