<a id="fl-o-ag-01"></a>
## FL-O-AG-01 按对象读取与统一更新入口

本期唯一角色运营管理员持有全部五项协议权限；图中的权限判断对应交付配置中的各权限项（见[权限与账号准入](./01-运营端协议管理-PRD.md#permissions)）。

```mermaid
flowchart TD
    A[运营账号进入协议管理] --> B{账号正常 已完成首登改密且登录有效}
    B -->|否| C[按账户状态引导 不开放任何协议内容与记录]
    B -->|是| D{要读取什么}
    D -->|操作进度| E{具协议操作记录查看}
    D -->|当前内容与工作版本| F{具协议当前内容与工作版本查询}
    D -->|版本历史与旧版本| G{具协议历史版本读取}
    E -->|否| H[不展示入口 直接访问被拒绝]
    F -->|否| H
    G -->|否| H
    E -->|是| I[读取原协议的操作进度]
    G -->|是| J[版本历史只读查看与下载 见 FL-O-AG-03]
    F -->|是| K[查看协议定义与当前及工作版本]
    K --> L{协议已上线 且具维护或发布权限}
    L -->|否| M[只读 不提供更新协议]
    L -->|是| N[更新协议]
    N --> O{已有待生效版本}
    O -->|是| P[打开该待生效版本 不暂停原计划]
    O -->|否| Q{已有草稿}
    Q -->|是| R[打开该草稿]
    Q -->|否| S[新建下一编号草稿]
    S --> R
    P --> U[按权限办理 见 FL-O-AG-02]
    R --> U
```

协议定义与操作进度同属基本信息，须同时可得，先定义后进度。重新上线的新协议没有旧内容可复制，首次更新从空白 v1 开始。

<a id="fl-o-ag-02"></a>
## FL-O-AG-02 草稿发布与原待生效版本调整

修改内容需维护权限，发布、确认更新与撤销需发布权限（均须配套当前内容查询）。只有立即生效、撤销待生效、丢弃草稿三处二次确认；定时发布与调整后仍为定时直接提交。

```mermaid
flowchart TD
    A[更新协议] --> B{打开的是}
    B -->|草稿| C[准备或修改内容]
    B -->|待生效版本| D[调整原版本的文件 说明与计划]
    C --> E[发布]
    D --> F[确认更新]
    D --> G[取消编辑或离开]
    G --> H[确认放弃未提交输入 原计划继续]
    E --> I{提交时仍符合权限 字段 时间与状态}
    F --> I
    I -->|否| J[拒绝 说明原因 保留输入]
    I -->|是| X{是否立即生效}
    X -->|是| Y[二次确认 写明将替换的当前生效版本]
    X -->|否 定时| K{提交结果}
    Y -->|确认| K
    Y -->|取消| H
    K -->|失败| L[已确认的文件与计划保持原样]
    K -->|成功且立即生效| M[本版本生效 旧生效版本归档 原计划结束]
    K -->|成功且定时生效| N[同一版本为唯一待生效 采用最新确认内容]
    N --> O{到点时协议仍已上线}
    O -->|生效成功| P[本版本生效 旧版本归档 留痕并发生效成功告警]
    O -->|生效失败| Q[保留待生效与原生效版本 留痕并发生效失败告警]
    O -->|已下线| R[原计划已取消 不执行 不发告警]
    Q --> A
    B -->|撤销待生效| S[单独二次确认]
    S -->|取消| H
    S -->|仍已上线且仍待生效| T[退回同号草稿 保留文件 取消计划 留痕并发撤销告警]
    S -->|已生效或已下线| J
```

取消确认、提交失败或未提交的修改都不改变已确认的文件与计划。办理期间到点生效先成功时，旧内容不能覆盖已生效内容；下线已成立时，旧的办理提交不能继续。调整成功后只按新计划运行，版本历史不新增另一个待生效版本。三类告警见[消息通知](./03-运营端协议管理-消息通知.md)。

<a id="fl-o-ag-03"></a>
## FL-O-AG-03 当前查询、版本历史与原来源返回

```mermaid
flowchart TD
    A[从当前查询 版本历史 操作进度或消息进入某一版本] --> B{该版本此刻属于}
    B -->|当前生效或工作版本| C{具协议当前内容与工作版本查询}
    B -->|已归档 已取消或被替换的旧文件| D{具协议历史版本读取}
    C -->|否| E[说明无权 不展示内容 预览或文件]
    D -->|否| E
    C -->|是| F[版本详情 读取指定版本]
    D -->|是| F
    F --> G{取数结果}
    G -->|失败| H[说明取数失败 可重试]
    G -->|版本确实不存在| I[说明不可用 不转到同名新协议]
    G -->|成功| J[只读展示完整版本信息]
    J --> K{文件情况}
    K -->|可在线呈现| L[只读预览 可下载]
    K -->|不能呈现或预览失败| M[说明情况 可重试或下载]
    K -->|没有文件| N[说明尚未上传 不提供空下载]
    E --> O[回到原来源 保留原筛选 分页与所在位置]
    I --> O
    J --> O
```

版本历史只承载辨认版本所需的信息与查看、下载两个动作，完整信息在版本详情；持有全部写权限也不能在版本历史中恢复、发布或删除。从消息或操作进度进入时回到该来源；旧地址始终指向原协议的原版本。

<a id="fl-o-ag-04"></a>
## FL-O-AG-04 公开当前版本读取

```mermaid
flowchart TD
    A[本平台面客端读取协议] --> B{是否为公开的当前内容}
    B -->|否 历史版本或旧文件| C[不公开提供 不泄露非公开内容]
    B -->|是| D{协议定义情况}
    D -->|未定义或已移除| E[协议不存在]
    D -->|已下线| F[协议已下线]
    D -->|已上线| G{有当前生效版本}
    G -->|否| H[暂无生效版本 不从旧协议或其他平台补取]
    G -->|是| I[取得当前文件与对应信息]
    I --> J[面客端只读阅读协议文本]
```

本平台本期不收取协议同意，公开读取只用于阅读协议文本。当前生效版本切换后，面客端最迟 5 分钟内显示新版本。重新上线的新协议尚未发布时为暂无生效版本，不继承旧内容。

<a id="fl-o-ag-05"></a>
## FL-O-AG-05 事件告知、阅读与目标权限

```mermaid
flowchart TD
    A[协议业务事实] --> B{事实种类}
    B -->|发布 立即生效 调整确认 定时发布提交| C[办理结果与操作进度告知 不发站内信]
    B -->|下线自动取消 重新上线 记录查看 历史下载| C
    B -->|到点生效成功 到点生效失败 撤销待生效| D[向本端全体运营发送站内信]
    D --> E{是否同一事实再次送达}
    E -->|是| F[不新增 保留原消息]
    E -->|否 新确认的计划再次失败等| G[作为新事实另发一条 不覆盖旧消息]
    F --> H[运营人员打开消息]
    G --> H
    H --> I[前往该协议的对应版本]
    I --> J{按该版本此刻的状态判断权限 见 FL-O-AG-03}
    J -->|有权且版本可得| K[查看 说明此后已发生的状态变化]
    J -->|无权或版本不可得| L[说明原因 不展示受限文件 不转到新协议]
    K --> M[回到原消息]
    L --> M
```

下线自动取消不是撤销待生效，不发撤销告警；取消也不报告成生效失败。旧消息不迁到重新上线的新协议。消息的阅读、未读与跳转规则归[运营端消息通知](../07-运营端消息通知/01-运营端消息通知-PRD.md)。

<a id="fl-o-ag-06"></a>
## FL-O-AG-06 下线、旧对象留存与全新上线

下线与重新上线由建设方执行，运营端没有对应的办理动作。

```mermaid
flowchart TD
    A[建设方执行原协议下线] --> B{下线结果已成立}
    B -->|否或未知| C[不展示已下线 重新读取可信状态]
    B -->|是| D[原协议停止公开当前内容与全部办理]
    D --> E[未完成计划直接取消 草稿与待生效版本转为已取消]
    D --> F[原已生效版本归档 保留真实生效经历]
    E --> G[按原协议保留文件 计划事实与操作记录]
    F --> G
    G --> H[版本内容按历史读取权限 操作记录按记录查看权限]
    H --> I[旧地址与旧消息仍指向原协议]
    J[建设方另行提供完整的新协议定义] --> K[独立新协议 未发布 无旧文件或计划]
    K --> L[运营准备空白 v1 并发布]
```

两条流程之间没有“恢复原计划”的箭头：原协议下线后不再回到已上线，新协议单独开始。到点生效先成功时，先记录真实生效，再按下线归档；下线先成立时，原计划不再执行。定义被移除后，版本历史与操作记录仍可按原协议定位。

<a id="st-o-ag-01"></a>
## ST-O-AG-01 单个版本状态机

图中是同一协议内的同一个版本；待生效调整的留痕不是另一个版本。

```mermaid
stateDiagram-v2
    state "草稿" as Draft
    state "待生效" as Scheduled
    state "已生效" as Active
    state "已归档" as Archived
    state "已取消" as Cancelled
    [*] --> Draft: 协议已上线 且无草稿与待生效版本时新建
    Draft --> Draft: 保存或替换文件
    Draft --> [*]: 确认丢弃 编号不复用 留痕保留
    Draft --> Active: 立即发布成功
    Draft --> Scheduled: 定时发布成功
    Scheduled --> Scheduled: 确认调整成功且仍为定时 版本号不变
    Scheduled --> Scheduled: 到点生效失败 附加生效失败
    Scheduled --> Draft: 协议已上线时撤销待生效 保留版本号与文件
    Scheduled --> Active: 最新计划到点成功 或确认改为立即生效
    Active --> Archived: 另一版本生效成功 或协议下线
    Draft --> Cancelled: 协议下线 结束办理
    Scheduled --> Cancelled: 协议下线 直接取消计划
    note right of Archived
        文件固定 按历史读取权限查看
        不能恢复 不能修改
    end note
    note right of Cancelled
        保留原状态与原计划等事实
        不恢复为草稿 原计划不再执行
    end note
```

每份已上线协议最多一个草稿、一个待生效、一个已生效版本；有待生效版本时不新建草稿。各状态允许的动作与读取权限见[版本状态](./01-运营端协议管理-PRD.md#states)。

<a id="st-o-ag-02"></a>
## ST-O-AG-02 协议对象的上线与下线

与单个版本状态分开；协议列表中的草稿、待生效等协议状态由协议上线状态与版本情况组合得出（见[协议上线状态与协议状态](./01-运营端协议管理-PRD.md#states)）。

```mermaid
stateDiagram-v2
    state "已上线" as Online
    state "已下线 只读留存" as Offline
    [*] --> Online: 建设方上线完整定义 初始未发布
    Online --> Online: 按权限维护 发布与更新内容
    Online --> Offline: 建设方下线成立 终止内容使用与未完成计划
    note right of Offline
        没有回到已上线的转换
        定义被移除也保留历史与记录
        重新上线是另一份新协议
    end note
```

重新上线的新协议单独从初始状态进入已上线、未发布，不从旧协议连线，也不携带旧版本、计划或记录。
