# 面客消息中心 — 流程图与状态机 **V1.0**

> 本文件是《借贷平台 · 面客端 · 面客消息中心 PRD》的图册，**与三册同批交付**，开发与测试共同参考。
> 入口与全文导航见主册 [`v1.0-面客消息中心-PRD.md`](v1.0-面客消息中心-PRD.md)；功能规则见 [`01-功能需求说明.md`](01-功能需求说明.md)；验收见 [`02-验收需求说明.md`](02-验收需求说明.md)。
>
> **本图册的四条纪律**：
>
> 1. **不另造业务口径。** 图只画已在正文中明确的规则；图与正文冲突时**以正文为准**，并按正文修图。
> 2. **只画业务。** 流程图表达业务角色、触发入口、主流程、关键分支与异常出口；**不画报文、不画调用链、不画存储与缓存刷新**。
> 3. **零触发口径。** 图中不出现任何具体业务类型取值、任何具体业务事件、任何一条消息的文案；业务侧一律以「业务模块」「业务事件」表示。
> 4. **双向引用。** 每张图带稳定图号、关联需求编号与回指章节；正文在对应模块直接链接图号。

## `FIG-NC-01` 消息从产生到被消费

**关联需求**：`F-NC-01`（承接范围）、`F-NC-02`（可见范围）、`F-NC-03`（未读计数）、`IF-NC-01`～`IF-NC-06`（对来源方的业务要求）
**正文出处**：主册 5.1、5.3、5.7；分册 01 第 9 章

```mermaid
flowchart TD
    EV["业务模块：<br/>某个业务事件发生"] --> SUB["按触发登记表提交一条消息<br/>（业务类型 · 分类 · 收件人 ·<br/>跳转形态 · 去重标识 · 文案模板）"]

    SUB --> C1{"关键要素齐备？<br/>收件人 / 业务类型 / 文案<br/>IF-NC-02"}
    C1 -->|否| REJ["不入池<br/>来源方可感知<br/>用户列表不出现空白条目"]

    C1 -->|是| C2{"归属属于<br/>借贷平台面客端？<br/>D-NC-08"}
    C2 -->|否| NOTMINE["不进入本池<br/>（由来源方路由到对应池）"]

    C2 -->|是| C3{"跳转形态合法？<br/>三选一互斥 · 落点属本平台<br/>IF-NC-08"}
    C3 -->|否| REJ

    C3 -->|是| C4{"去重标识<br/>命中已有消息？<br/>IF-NC-04"}
    C4 -->|命中| MERGE["合并更新：不新增条目<br/>已读可恢复为未读<br/>旧内容不覆盖新内容 IF-NC-06"]
    C4 -->|未命中| POOL["入池<br/>非关键要素缺失照常入池 IF-NC-03"]

    MERGE --> VIS
    POOL --> VIS["N-NC-01（60 秒）内<br/>未读角标与列表<br/>同时体现 IF-NC-01"]

    VIS --> U1["用户在任意页面<br/>看到未读角标"]
    U1 -->|"点顶栏入口"| PANEL["快捷面板：最近 10 条<br/>仅展开不算已读"]
    U1 -->|"账号下拉 → 消息中心"| LIST["消息中心列表"]
    PANEL -->|"查看全部"| LIST
    PANEL -->|"点单条"| DETAIL
    LIST -->|"点单条"| DETAIL["消息详情<br/>渲染成功后转已读"]
    DETAIL --> JUMP["跳转或返回列表<br/>见 FIG-NC-04"]

    U1 -.->|"会话失效"| FALL["回落游客态<br/>见 SM-NC-03"]
    LIST -.->|"会话失效"| FALL
    DETAIL -.->|"会话失效"| FALL
```

> **两处必须看懂的判定**：
>
> - **`C1` 与 `C3` 的「不入池」是有意的**：一条没有内容、或跳不到合法落点的消息进了列表，用户无法判断发生了什么（`IF-NC-02`、`IF-NC-08`）。**但 `IF-NC-03` 的非关键要素缺失走的是另一条路——照常入池**，丢消息比展示不全严重得多。
> - **`C4` 的合并只按来源方声明的去重标识判定**，本模块**不自行推导**（`IF-NC-05`）。接入方复用同一标识时的覆盖后果由来源方承担。

## `FIG-NC-02` 面客端页面流

**关联需求**：`F-NC-11`～`F-NC-21`、`F-NC-27`
**正文出处**：分册 01 11.1～11.5

```mermaid
flowchart TD
    G["游客<br/>（未登录 / 会话已失效 / 受限会话）"]
    G -->|"访问消息中心列表或详情地址"| BACK["走本平台既定登录回跳<br/>D-NC-30 · 本模块不自建解析"]
    BACK -->|"登录成功"| ORIG["回到原处<br/>列表回列表 · 详情回该条详情"]
    ORIG --> LIST

    A["已登录任意页面<br/>顶栏 C-F-MC-01 + 未读角标"]
    A -->|"点入口"| P["快捷面板 C-F-MC-02<br/>最近 10 条 · 不区分已读未读"]
    A -->|"账号下拉 → 消息中心"| LIST["P-F-MC-01 消息中心列表"]
    P -->|"查看全部（无筛选）"| LIST
    P -->|"点单条"| D
    LIST -->|"点单条"| D["P-F-MC-02 消息详情<br/>整页 · 独立地址"]
    LIST -->|"行内标为已读"| LIST
    LIST -->|"全部已读"| AR["见 FIG-NC-03"]
    LIST -->|"加载更多（追加 20 条）"| LIST
    LIST -->|"切换分类 / 状态筛选"| LIST
    D -->|"返回列表"| RET["保留筛选 · 已加载批次 · 滚动位置<br/>已读就地更新不重排"]
    RET --> LIST
    D -->|"跳转"| JUMP["见 FIG-NC-04"]

    A -.->|"会话失效"| G
    P -.->|"会话失效"| G
    LIST -.->|"会话失效"| G
    D -.->|"会话失效：整页卸载"| G
```

> **图里刻意没有的三样东西**：① 没有任何「发消息 / 新建通知 / 通知设置」入口（主册 4.2）；② 没有分页器（列表只有「加载更多」，`AC-NC-47`）；③ 快捷面板里没有「全部已读」（范围不一致必然被误解，分册 01 11.2）。
>
> **`RET` 这一步最容易漏**：「加载更多」形态必须记住**已加载到第几批**，否则用户加载了 5 批、点进详情、返回后只剩第 1 批（`AC-NC-58`）。

## `FIG-NC-03` 全部已读

**关联需求**：`F-NC-19`
**正文出处**：分册 01 11.5

```mermaid
flowchart LR
    A["用户在 P-F-MC-01<br/>（可能带筛选）"] --> B["点「全部已读」"]
    B --> C["C-F-MC-04 二次确认<br/>必须说明条数 + 当前筛选"]
    C -->|"取消"| A
    C -->|"确认"| D["作用范围强制收敛为<br/>本人可见范围 ∩ 当前筛选"]
    D -->|"成功"| E["角标按新未读数更新<br/>列表行就地变已读<br/>不重排 · 不移除"]
    D -->|"失败"| F["提示失败并保留原状态<br/>不做部分成功的静默处理"]
```

> **为什么二次确认必须说明筛选**：用户在「未读 + 某分类」筛选下点「全部已读」，若不说明，会以为清掉的是全部消息；反过来在无筛选下点，也可能以为只清掉了眼前这一屏。

## `FIG-NC-04` 跳转执行与四类降级

**关联需求**：`F-NC-23`（跳转形态）、`F-NC-24`（失效与降级）
**正文出处**：分册 01 11.6、11.7

```mermaid
flowchart TD
    D["用户进入消息详情"] --> F{"跳转形态？<br/>三选一互斥"}

    F -->|"无跳转"| NONE["不渲染跳转按钮<br/>不展示任何说明文案<br/>正文完整展示<br/>操作区只有「返回列表」"]

    F -->|"静态页面目标<br/>lending:P-xxx"| STATIC["直达该页面<br/>不做预判"]

    F -->|"业务对象目标"| MAP{"该业务类型<br/>已登记到前端？"}
    MAP -->|"否（未登记）"| UNREG["界面表现与「无跳转」完全一致<br/>+ 记录一次未知业务类型<br/>仍计入未读"]
    MAP -->|"是"| EXP{"已到失效时点？"}

    EXP -->|"是（已过期）"| EXPIRED["不渲染跳转按钮<br/>不展示说明条<br/>带「已过期」标签<br/>正文完整展示 · 不计入未读"]
    EXP -->|"否"| PRE["进入详情时预判一次<br/>超时 N-NC-05（3 秒）按失败处理并放行"]

    PRE -->|"目标已删除"| DIS["按钮禁用而非隐藏<br/>+ 说明条<br/>正文完整展示 · 仍计入未读"]
    PRE -->|"目标状态已流转"| DIS
    PRE -->|"无权限"| DIS
    PRE -->|"通过"| OK["跳转按钮可用"]

    STATIC --> LAND
    OK -->|"用户点击"| LAND{"落地重新判权<br/>D-NC-56"}
    LAND -->|"有权限"| PAGE["目标页面<br/>（承载单元落点则同时打开该单元）"]
    LAND -->|"已登录但权限不足"| GUIDE["本平台受限引导<br/>不是错误页 · 不是报错提示"]
    LAND -->|"落地时已非登录态"| LOGIN["落地页按本平台既定<br/>未登录表现处理"]
```

> **三条不可削弱的口径**：
>
> 1. **内容一律完整展示。** 失效影响的只是「能不能跳过去」，不影响「能不能读」（`D-NC-55`）。
> 2. **「未登记」与「无跳转」在界面上完全一致**，差别只在是否记录（`D-NC-46`）。
> 3. **跳转按钮不得因为「可能落到无权限」而提前置灰或隐藏**（`AC-NC-72`）。跳转照常发起，落地态由落地页自己表达。

## `SM-NC-01` 单条消息的可用性状态

**状态对象**：**一条消息**（不是收件人、不是会话）
**关联需求**：`F-NC-24`
**正文出处**：分册 01 9.4、11.7

```mermaid
stateDiagram-v2
    [*] --> 可跳转: 入池且跳转目标已登记
    [*] --> 无跳转: 入池且未声明跳转目标
    [*] --> 未登记: 入池但业务类型尚未登记到前端

    可跳转 --> 目标已删除: 进入详情时预判
    可跳转 --> 目标状态已流转: 进入详情时预判
    可跳转 --> 目标无权限: 进入详情时预判
    可跳转 --> 已过期: 到达失效时点
    无跳转 --> 已过期: 到达失效时点
    未登记 --> 可跳转: 前端补齐登记
    未登记 --> 已过期: 到达失效时点

    note right of 无跳转
        按钮不渲染 · 无说明文案
        正文完整展示 · 计入未读
    end note
    note right of 未登记
        界面表现与「无跳转」完全一致
        差别只在记录一次未知业务类型
    end note
    note right of 已过期
        按钮不渲染 · 带「已过期」标签
        正文完整展示 · 不计入未读
    end note
```

> **「目标已删除 / 目标状态已流转 / 目标无权限」三态的共同表现**：按钮**禁用而非隐藏** + 说明条 + 正文完整展示 + **计入未读**（分册 01 11.7）。
>
> **「已过期」与另外三类的差别**：过期是消息自身的属性（池中已知），三类失效是**进入详情时的实时判定**——所以过期不计入角标、三类失效计入（`D-NC-22`、`D-NC-23`）。

## `SM-NC-02` 单个收件人对单条消息的已读状态

**状态对象**：**一个收件人对一条消息**（与 `SM-NC-01` 的状态名不混用）
**关联需求**：`F-NC-18`、`F-NC-19`
**正文出处**：分册 01 11.5

```mermaid
stateDiagram-v2
    [*] --> 未读: 消息投递给该收件人
    未读 --> 已读: 打开详情（渲染成功后）
    未读 --> 已读: 列表行内「标为已读」
    未读 --> 已读: 「全部已读」命中当前筛选
    已读 --> 未读: 去重标识命中后的合并更新<br/>（系统触发，非用户操作）

    note right of 未读
        展示未读圆点（须可被读屏获取）
        计入未读角标
    end note
    note right of 已读
        本期不提供「标为未读」
        已读不参与排序，行位置不变
    end note
```

> **唯一的「已读 → 未读」路径是系统触发的合并更新**，不是用户操作。界面上**不存在「标为未读」入口**（`AC-NC-57`）。
>
> **快捷面板展开、滚动经过都不产生已读**（`AC-NC-40`）。

## `SM-NC-03` 会话态与消息中心可达性

**状态对象**：**一个会话**
**关联需求**：`F-NC-27`
**正文出处**：主册 5.5、分册 01 11.1
