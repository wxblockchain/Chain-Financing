# 面客消息中心 · 消息通知与来源衔接

2026-09-24｜需求评审稿｜配套本模块当前主 PRD 与图册。本批按需求诊断简报 V4 逐条对齐来源事件的增删：项目审核两类事件新增承接，质押审核超时、报价临期与到期失效、放款确认临期与超期、要求重传、放款前终止、还款确认临期与超期共九类事件随对应业务能力取消而废止，登录主干的钱包绑定待重新确认同批停用；借贷广场四册（L5～L8）现行事件 20 类，废止保号清单见[第 7 节](#retired-notify)。本批另补齐第 1 节此前缺列的资金方侧两个来源。

**面客消息中心没有独立发送事件、没有新增业务模板。** 本册承接已经完成的来源通知，核对框架能否正确接收、阅读与跳转；通知的承载形式与视觉由设计决定（见[统一条款](01-面客消息中心-PRD.md#design-boundary)）。具体发送时点、收件归属和中英全文仍在各模块最新通知册；不将它们复制成另一套权威事件表。

### 2.2 资料、金额与日期

P01：本人账户档案不扩大可见范围，业务必要名称、编号及金额自动同源展示；原凭证、完整账户和私人资料去原业务按权限读取，不复制到通知正文。

P02/P03：代币在质押链上的单一持有地址与实际执行结果归来源，消息不新增地址编辑、异常工单或自动客服处置；未知不能写成功、失败、退还或已恢复资格。结算收款链上的收款地址归企业账户模块，两者是不同概念，通知正文都不展示完整地址。

P04：SPV按运营处理，不新增付款、代确认或消息抄送权。P05/P06：固定1:1:1与授信五年期限起算由来源业务核定，通知只用该事件的固化结果，不重新算汇率或授信。P07 原承接的“单笔放款前终止后的项目资格消费”随放款前终止能力取消而不再发生，框架不保留对应的资格恢复或再次融资类消息。

P08/P09按2.1承接；P10统一UTC业务日期与连续时长，具体时刻按偏好显示并标注。数币精度与尾差没有批准取值就保持依赖。P11/P12归审核、协议与运营模块，本册不编造机构审核政策、运营访问权或协议下线通知。
