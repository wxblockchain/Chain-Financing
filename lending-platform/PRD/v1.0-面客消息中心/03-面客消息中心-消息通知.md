### 2.1 唯一发送与必要合并

### 2.2 资料、金额与日期

P01：本人账户档案不扩大可见范围，业务必要名称、编号及金额自动同源展示；原凭证、完整账户和私人资料去原业务按权限读取，不复制到通知正文。

P02/P03：单一链上持有地址与实际执行结果归来源，消息不新增地址编辑、异常工单或自动客服处置；未知不能写成功、失败、退还或已恢复资格。

P04：SPV按运营处理，不新增付款、代确认或消息抄送权。P05/P06/P07：固定1:1:1、五年期限起算、单笔终止后的资格由来源业务核定，通知只用该事件的固化结果，不重新算汇率、授信或资格。

P08/P09按2.1承接；P10统一UTC业务日期与连续时长，具体时刻按偏好显示并标注。数币精度与尾差没有批准取值就保持依赖。P11/P12归审核、协议与运营模块，本册不编造机构审核政策、运营访问权或协议下线通知。

## 4. 开关、收件与来源目标

账户开关政策以[D-NC-59](01-面客消息中心-PRD.md#d-nc-59)及[登录主干与账户体系](../v2.0-登录与账户体系/01-登录主干与资产方SSO接入-PRD.md) D-L120 为准。来源要允许关闭某类事件，必须先明确具体种类、接收人、默认及补送政策；分类筛选不是退订设置。“业务提醒”分类不能自动等同可选通知。没有可选事件时不靠新增日常提醒为开关制造用途。

| 角色／情况 | 当前承接 |
| --- | --- |
| 资产方 | 单笔审核/执行沿原提交或发起账号；多成员需求、项目与融资业务责任账号沿Q-LS-N01，不猜为报价接受人、还款提交人、管理员或全员 |
| 资金方 | L6相关消息发原报价账号；L7/L8沿本笔放款登记账号LN-14，其他员工办理不自动改投或增加副本；L5按其相关报价/债权范围并对同账号同项目事件去重 |
| 运营/SPV | 当前L5～L8面客事件不因此产生运营广播，控制台和本模块无独立发送；代币质押审核模块已有的审核职责与管理消息不能由本册删除或扩权 |
| 停用、交接、归属不明 | 不任意改投，不转移历史。来源明确该分支后再验收，不暂停业务计时或回滚业务事实 |

目标沿来源原项目、原申请、原业务以及必要的原单笔申请、执行动作、RP期次/重传要求。状态变化时旧动作停用、原对象按当前权限可读；未登记仍可读无跳转，不把通用默认页当成已经准确定位。若来源目标为控制台，保留其只读详情与唯一“前往借贷广场”业务导航，不从消息框架恢复列表的借贷广场直达入口、页内重新取数动作或办理入口。

## 6. 剩余依赖

框架已经承接重复到达、旧对象可读、公共客服边界、条件模板、完整计划对照、通知偏好及最新交互；L8 三段式拼写核验无需新增产品决策。仍需完成：

- 来源Q-LS-N01多成员资产方责任、停用/交接账号分支；不替来源裁定。
- [Q-NC-01](01-面客消息中心-PRD.md#q-nc-01)唯一共享登记位置与正式分类值；所有来源仍按证据标待适配。
- [Q-NC-04](01-面客消息中心-PRD.md#q-nc-04)时效冲突统一及真实端到端验收；不改60秒起点或默认放宽为5分钟。
- 真实公共客服邮箱、数币精度与尾差、地区账户/掩码规则及真实主体资料等来源依赖；本模块不新造取值。
- 各来源明确可选通知政策，以及管理端与全模块的最终比对；不能把面客框架修订说成整轮通知汇齐。
