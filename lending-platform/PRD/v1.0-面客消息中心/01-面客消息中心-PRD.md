# 面客消息中心 · PRD

2026-09-23｜面客端：资产方、资金方｜需求评审稿，真实依赖见第 5 节。

## 1. 目标与阅读入口

消息中心承接借贷平台面客端的本人站内信：用户在任何已登录页面从壳层消息入口获知未读数，进入完整消息列表筛选和加载，打开单条消息详情读完整事实，必要时前往原业务对象，再沿原路返回列表。

用户需要知道发生过什么，并能查看相关原业务或在仍可办理时主动进入办理。消息不是业务本身，也不是已办凭证：读信与业务提交、付款、确认、审核互不替代。各业务模块决定发生什么事件、何时告知、告知谁；**本模块没有独立发送事件、没有新增业务模板**。接入一个已符合本框架的新业务，只更新来源通知与共享登记，不在本模块正文追加业务事件章节。

本平台已经有实际业务通知需求，本期不能再以“接入方为零”推断全链路可上线。框架可用、文档登记完整、真实账号与投递可用是不同结果，验收分别给证据；来源未决项只阻塞相应分支，不阻塞其余交付。

阅读顺序：第 2 节共同规则 → 第 3 节完整功能 → 第 5 节依赖 → 第 4 节同序验收。配套两册须共同使用：[流程图与状态机](02-面客消息中心-流程图与状态机.md)、[消息通知与来源衔接](03-面客消息中心-消息通知.md)。

## 2. 角色、信息域与共同业务规则

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

沿用的名称中，“壳层消息入口”指该入口归平台壳层承接、不由本模块自建，与其在界面上的位置无关；“最近消息预览”指进入完整列表前可先获知的最近若干条，不指定其承载形式；“未读计数”指本人未读条数这一事实本身，不指定其呈现方式。

### 2.1 角色与可见范围

资产方、资金方分别接收来源明确的本人事件，均可通过壳层消息入口预览或进入完整列表；游客无入口，直达需先登录；受限会话先完成必办前置。运营、SPV 不因管理身份访问面客池，也不因客服、线下核实或三方核对收到面客副本。新消息到达不打断用户当前操作、不夺取当前焦点。

### 2.3 消息正文的事实口径

消息保留事件时点事实，相关业务页面显示当前状态。后续业务变化不能覆盖旧消息的金额、时间、原因和原对象身份。来源明确的事实补齐可沿同一条完善，但不能倒退、改变其原有次序或恢复未读；不同事实不得借补齐覆盖。读取失败或未知结果不得显示为 0、失败或成功。

<a id="d-nc-61"></a>`D-NC-61`：业务日期统一 UTC；连续时长不受时区、送达或阅读影响。具体时刻沿平台偏好展示并标注时区，无明确偏好时沿平台规则、缺省 UTC；相对时间不改变绝对截止。历史金额、期限、币种取事件时点事实，带币种呈现，不能按当前行情或当前计划重算，也不把 USD/USDT/USDC 固定 1:1:1 解释为可任意改写历史金额。来源未定的数币精度与尾差保持未定。语言沿账户与平台偏好，不另立判定链；切换语言后历史正文随之切换，原事实值不变。不得通过语言切换、更改时区或原业务刷新改变历史消息事实。

## 3. 功能需求说明

<a id="f-nc-01"></a>
### 3.1 消息池、归属与未读计数（F-NC-01～F-NC-05）

<a id="f-nc-02"></a><a id="f-nc-03"></a><a id="f-nc-04"></a><a id="f-nc-05"></a>

**承接范围与权限（F-NC-01、F-NC-02）。** 资产方、资金方在正常登录态可读本人借贷平台面客消息；同企业其他成员、管理端及其他平台身份不可共享该条或其未读数。<a id="d-nc-40"></a>`D-NC-40`：任何入口、筛选、深链均不得扩大账号或端范围。<a id="d-nc-41"></a>`D-NC-41`：没有跨平台聚合入口。<a id="d-nc-42"></a>`D-NC-42`：全部已读仅作用于本人可见范围与当前筛选的交集。<a id="d-nc-43"></a>`D-NC-43`：目标无权与不存在不得泄露可区分的私有信息。

消息可读资格、目标可读资格与目标可办理资格分别判断。主体或账号未明时不能猜测收件人；资质变化不自动转移历史消息。个人／企业档案与必要业务信息按 [D-NC-60](#d-nc-60) 处理。消息不得被用来绕过原业务的账户、材料与凭证权限。

**同一事件与历史。** 来源定义每次独立业务事实的区分范围。重复到达、重试、刷新、重新登录、同事实补送均不得新增条目、改变其原有次序、恢复未读或替换原发生时间。可确认的同事实补齐仍在原条内；后到旧内容不能覆盖较新事实，不因补齐费用、原因而再催一次。真实新轮次、新动作、新期次或新节点按来源分别保留。来源登记无法区分不同事件时须补齐，不能按时间窗、企业或相同项目自行猜测并合并；来源明示的同次结果合并仍遵循其完整通知条件。对应 [IF-NC-04～06](#if-nc-01) 与 [FIG-NC-01](02-面客消息中心-流程图与状态机.md#fig-nc-01)。

| <a id="d-nc-23"></a>`D-NC-23` | 原动作失效、对象不可访问、业务类型未登记本身不等于消息过期，仍按消息有效性计未读 |
| <a id="d-nc-24"></a>`D-NC-24` | 0 不展示未读计数，超过 99 展示 99+ |
| <a id="d-nc-25"></a>`D-NC-25` | 读取失败保留最后一次已知值，不清零、不干扰当前操作 |

<a id="d-nc-44"></a>`D-NC-44`：消息自动更新不续期会话；发现失效立即清本人内容。前台应在 [N-NC-01](#n-nc-01) 的 60 秒约束内取得一致的列表与未读计数，切回页面恢复更新，后台自动更新不干扰用户当前操作。更新失败保留最近已知计数；同设备各标签阅读状态与未读计数应一致，同步暂不可用时沿平台既有更新能力恢复，不能长期保留互相矛盾的已读数。

消息提醒有效性只有“有效／已过期／已主动失效”三态；已读状态单独记录，目标可读／可办性单独判断。到期不删除正文、不把业务本身判为失败，也不取消原业务仍允许的超期办理。见 [SM-NC-01](02-面客消息中心-流程图与状态机.md#sm-nc-01)。

**保留与异常（F-NC-04、F-NC-05）。** 本期长期保留，不设自动清理、归档、用户删除或清空；已过期历史仍可在列表与详情查到并标识过期，用户可读原事实。<a id="d-nc-45"></a>`D-NC-45`：非本池异常记录不展示、不计未读、不可经详情打开；来源可排查，不兼容为跨端信。关键要素缺失不形成空白消息；已接收的单条翻译／展示异常按 [3.3](#f-nc-07) 降级，不拖垮列表。框架可选字段缺失不丢信，但来源定义的必要业务信息未齐，不可宣称该通知完整合格。

<a id="f-nc-06"></a>
### 3.2 来源触发登记与对来源的要求（F-NC-06、F-NC-10）

<a id="f-nc-10"></a>

来源模块通知册是其发送时点、收件责任、模板和业务目标的统一来源；本节只定义登记项和通用结果，不维护第二份完整事件表。共享登记权威位置尚未确定（[Q-NC-01](#q-nc-01)）；[消息通知与来源衔接](03-面客消息中心-消息通知.md)记录已核对来源及差异，不能当作已生效共享登记。各来源先完整登记，统一汇入共享登记并核验真实投递后才标已适配；本期有实际通知需求，不能用“空池可上线”替代真实接入验收。新增同类业务或分类不需要改本模块规则及页面功能。

<a id="if-nc-01"></a>

| 编号 | 必须满足的产品结果 |

| <a id="if-nc-06"></a>`IF-NC-06` | 重复与迟到旧结果不倒退事实，不改已读；业务真实新事件独立保留。通知合并只按来源已确认规则，不因同日、同项目或同收件人自行合并 |

| <a id="if-nc-08"></a>`IF-NC-08` | 业务对象、静态页面、无跳转三选一；目标属本平台且按登记承接，不接受任意外部地址。业务类型尚未登记按可读降级，不混同非法目标 |

| <a id="if-nc-10"></a>`IF-NC-10` | 禁止未脱敏私人邮箱、完整钱包地址、证件号、IP 及完整账户、凭证进入消息。经业务负责人核实且专供用户联系的公共客服邮箱可按来源要求完整展示及复制；不能由用户自由文本或模拟地址代替，实际值缺失继续待验 |

<a id="rg-nc-01"></a>

| <a id="rg-nc-04"></a>`RG-NC-04` | 收件人 | 必填，本平台账号及其来源业务归属；多人各自一条；未定不得以企业、邮箱、钱包、最近操作人或全员代填 |
| <a id="rg-nc-05"></a>`RG-NC-05` | 负责来源 | 必填，业务模块及议题，说明唯一发送责任；不得由页面展示方另发同义信 |
| <a id="rg-nc-06"></a>`RG-NC-06` | 目标形态 | 必填，业务对象／本平台静态页面／无跳转互斥；未提供具体目标时允许无跳转 |
| <a id="rg-nc-07"></a>`RG-NC-07` | 原目标及可读结果 | 有目标时必填，标明原项目、申请、业务及必要期次／动作的定位关系，业务状态变化后的可读结果；静态页面沿 `lending:` 前缀，不存任意外部地址，不为承载单元新造页面编号 |
| <a id="rg-nc-08"></a>`RG-NC-08` | 目标可用性条件 | 业务目标需声明访问及办理条件；默认进入详情检查，静态页不预判；未明不能推定具有办理权 |
| <a id="rg-nc-09"></a>`RG-NC-09` | 同一事件的业务区分 | 必填，明确账号、原对象、事件及必要次数／节点／期次；不得误合并不同真实事件；不是要求开发采用某一种算法 |
| <a id="rg-nc-10"></a>`RG-NC-10` | 完整双语模板 | 必填，标题正文成对；角色／状态变体按 [3.3](#f-nc-09)；必需业务信息、类型、校验和缺失处理由来源给出 |
| <a id="rg-nc-11"></a>`RG-NC-11` | 消息自身有效期 | 可选，来源明确才采用；未定义不臆造到期日。消息提醒截止与业务办理截止不能混用 |

| <a id="rg-nc-13"></a>`RG-NC-13` | 通知偏好政策 | 来源须说明强制／可选／尚未明确；可选需有具体种类和实际作用，默认开启。未明不能成为可退订项，不把分类直接当退订种类 |
| <a id="rg-nc-14"></a>`RG-NC-14` | 同次结果合并与迟到处理 | 存在相关分支时必填；声明合并条件、保留哪些事实、何时抑制过时催办。未声明不得自行合并、补发历史全集或生成每日提醒 |

<a id="d-nc-59"></a>`D-NC-59`【通知偏好】：通知偏好无历史值默认开启，只影响来源明确列出的可选通知；强制通知始终接收。未明确可选的关键事件不能被笼统“关闭通知”屏蔽，也不由本册将所有事件永久归类为强制。当前没有已确认可选清单时，账户不提供无实际效果的可操作开关，消息中心不另建一个。关闭不删除旧信、不改已读、不隐藏业务提醒、不停业务计时；重新开启不自动批量追补，后续可选事件须由来源明确其补送政策。分类筛选不是退订设置。

**接入的产品流程。** 来源给出完整通知规则与登记 → 核对唯一事件、分类、收件与目标 → 对有差异的分支完成业务确认 → 汇入共享登记 → 按实际角色验证双语、原对象定位、计数、去重及可见时效 → 记录适配结果。未满足的分支明确标注，不把“未登记仍可读”的容错当作完成。见 [FIG-NC-06](02-面客消息中心-流程图与状态机.md#fig-nc-06)。

**增量接入零改框架（F-NC-10）。** 选取未在本模块出现的虚构业务，提供符合上述规则的来源通知与登记；新增分类、模板变体、原对象落点或可变条目后，本模块规则及既有页面功能无需变更。通用性与真实业务通知验收分别进行，虚构消息不能代替当前业务联验。

<a id="f-nc-07"></a>
### 3.3 分类、双语模板与内容降级（F-NC-07～F-NC-09）

<a id="f-nc-08"></a><a id="f-nc-09"></a>

**分类与未登记降级（F-NC-07、F-NC-08）。** <a id="d-nc-46"></a>`D-NC-46`：展示支持登记中新增类型与分类，不因新增业务更改页面规则；分类筛选为“全部”及本人实际拥有消息的分类。<a id="d-nc-47"></a>`D-NC-47`：分类未登记显示“其他 / Other”，不隐藏消息。<a id="d-nc-48"></a>`D-NC-48`：业务类型未登记仍展示内容、可阅读、计未读，不提供业务跳转动作，也不给“暂不支持跳转”提示；不跳错误页、默认页或伪造目标，缺登记可供来源排查。

类型尚未适配与非法外部目标是不同问题：前者按可读降级，后者按 [IF-NC-08](#if-nc-08) 不接收。未登记不是业务失败，不改变消息原分类以外的业务事实。

**完整正文与条件模板（F-NC-09）。** 来源使用完整中英标题和正文，不能传动词、状态词等片段拼句；用户填写的原因原文仍是原文，不声称自动译为英文。

<a id="d-nc-62"></a>`D-NC-62`：同一事件可以按收件角色或事件时点真实结果选择一套完整模板。各变体在同一事件登记项中明确唯一选择条件，保留来源 T-* 变体号供文档识别；变体不是新事件，同一收件人不能因有两套文案多收一封。两种语言的同一变体具有相同变量与事实；不同角色变体可以承载各自必需信息。条件后续变化不把原信改成新的业务结果。

<a id="d-nc-63"></a>`D-NC-63`：来源要求逐项对照的通知，在同封完整正文中提供全部条目；顺序、两侧缺项与条件沿来源。允许多条完整文本段落承载，不需要富文本。摘要可精简，完整详情不能截掉对照、原因、金额币种、准确截止或客服出口，也不能只以“去详情看”替代必需正文；条目不拆成多封消息。

| 信息 | 业务类型与可编辑性 | 必填、校验与缺省 |
| --- | --- | --- |
| 标题、正文 | 只读纯文本 | 有可读内容才可接收，不允许空白或技术标识；来源模板必需值不能用假值或 0 代替 |
| 分类 | 只读分类 | 无法识别时“其他”，不隐藏消息 |
| 消息发生时间 | 只读时刻 | 必须能准确说明原事件时间；不得因重投、阅读、时区改变。列表可相对显示，详情为带时区绝对时刻 |
| 已读状态 | 未读／已读 | 新有效消息默认未读；阅读或全部已读成功后已读，无反向入口 |
| 原业务名称、编号 | 只读文本 | 通用可选，来源必需时按来源；编号存在可复制，不能用当前默认对象补位 |
| 金额与币种 | 只读数值及币种 | 依来源必填；零只表示真实零，未知不填 0；数值与原事实一致，不由消息中心折算或舍入计算业务结果 |
| 期限与业务日期 | 只读日期／时刻 | 依来源，业务日期 UTC，具体时刻带时区；不从送达或阅读起算 |
| 业务原因 | 只读原文 | 依来源长度与权限；详情完整阅读，敏感内容按 [IF-NC-10](#if-nc-10) 保护；不把内部错误堆栈变成面客原因 |
| 进度节点、状态、步序 | 只读 | 节点与业务名称成组；状态限四态，步序同时存在且正整数、当前步不大于总步才展示；缺项不伪造 |
| 公共客服邮箱 | 只读联系信息 | 来源要求时必填，经核实的公共地址完整可读可复制；未知不得填模拟值或无效掩码，不代表平台自动发邮件 |

**模板缺失处理。** 当前语言缺失回落另一支持语言；已接收消息两份均无法展示时，以分类、原时间、通用标题“通知 / Notification”降级，单条不影响其他消息。可选变量缺失不显示裸占位符；必需变量缺失须可感知内容不完整，不能靠空字符串得到语义错误的成功通知，也不允许把这种降级算作来源通知验收通过。

`T-1`：中英均齐备；`T-2`：同一变体的业务信息与变量一致；`T-3`：使用面客术语。标题、正文、变量均遵守 [IF-NC-10](#if-nc-10)；允许公共客服邮箱不等于允许私人邮箱或完整账户。

<a id="f-nc-11"></a>
### 3.4 壳层消息入口、最近消息预览与未读计数（F-NC-11～F-NC-13）

<a id="f-nc-12"></a><a id="f-nc-13"></a>

登录且完成必办前置后，平台壳层提供带未读计数的消息入口 `C-F-MC-01` 及账号菜单“消息中心”。消息入口打开最近消息预览 `C-F-MC-02`，账号菜单直接进入无筛选消息列表。<a id="d-nc-49"></a>`D-NC-49`：消息入口由平台壳层承接，本模块不新增平台级业务板块；平台默认落地资产广场，无首页入口。

游客、受限会话无消息入口与未读计数；游客深链先登录、受限会话先完成前置，随后回原合法目标。失效时入口、预览、列表、详情及计数同时清除，迟到消息不得重新展示。资产方认证不足只限制来源业务操作，不把本人消息整体当作未登录。见 [SM-NC-03](02-面客消息中心-流程图与状态机.md#sm-nc-03)。

新消息可见时未读计数与列表一致（F-NC-13），不打断用户当前操作、不夺取当前焦点；另一标签已读同步更新，失败不假清零。阅读不代替任何办理。

**最近消息预览（F-NC-12）。** 取最近 10 条，含已读与未读，每条可得标题、摘要、分类、时间及阅读状态；进度型保留识别业务与当前节点所需信息。仅打开预览或浏览经过不自动已读，选择某条进入详情。可经同一入口再次操作关闭，也可用键盘关闭，键盘可逐条遍历。“查看全部”进入无筛选完整列表；预览不提供全部已读，避免将最近 10 条与全部范围混淆。无消息仍给出明确空态。对应 [FIG-NC-02](02-面客消息中心-流程图与状态机.md#fig-nc-02)。

<a id="f-nc-14"></a>
### 3.5 完整消息列表与筛选（F-NC-14～F-NC-17）

<a id="f-nc-15"></a><a id="f-nc-16"></a><a id="f-nc-17"></a>

`P-F-MC-01` 与最近消息预览分开，是有独立可深链、可刷新地址的完整列表，展示范围不受预览的 10 条限制。每条消息条目 `C-F-MC-03` 可得标题、摘要或进度、分类、时间、已读／未读状态，从消息条目即可进入详情，键盘同样可打开；不提供逐条标为已读的动作。消息信息与其所属消息须可明确对应。

| 项目 | 规则与结果 |
| --- | --- |
| 分类筛选（F-NC-14） | 全部＋实际拥有分类，未知归其他，不写死业务清单 |
| 已读筛选（F-NC-15） | 全部／未读／已读，默认全部，与分类取交集；刷新当前地址保持筛选。改筛选回首批和列表起点 |
| 加载（F-NC-16） | <a id="d-nc-50"></a>`D-NC-50`：每次 20 条，续取结果追加到已加载结果之后，不改为按页码跳转，也不由用户改变每次条数；无更多给结束反馈 |
| 排序 | 原消息创建次序倒序，同一时间稳定排序；重复投递不改变原有次序，阅读不重排。当前已加载未读结果中的消息变已读后就地保留，重新筛选或刷新才按最新条件重取 |
| 新消息与加载 | 新增消息与续载不重复不漏项，不强制改变用户当前所在位置 |
| 无消息 | 首次空态说明还无消息；筛选空态说明无匹配且提供清除筛选 |
| 加载失败（F-NC-17） | 首批取数失败可重试；续载失败保留已加载内容与所在位置；加载中不得先判为空态，单条异常不影响其他消息 |

<a id="f-nc-18"></a>
### 3.6 消息详情、阅读已读与返回（F-NC-18～F-NC-21）

<a id="f-nc-19"></a><a id="f-nc-20"></a><a id="f-nc-21"></a>

**详情与返回（F-NC-20、F-NC-21）。** <a id="d-nc-51"></a>`D-NC-51`：`P-F-MC-02` 有独立、可深链、可刷新的地址。须可得完整标题、分类、带时区时间、正文，以及来源必要业务信息。正文阅读、业务信息、状态和业务操作须可分辨；不可操作原因与对应操作有明确关联，自动已读失败的反馈须与业务失败可区分。返回列表只保留一个统一入口，不重复提供同义返回。

从列表进入后，详情返回与平台返回都回到同一列表上下文，保留分类、状态筛选、已加载批次、所在位置、当前消息与焦点。刚读的消息就地更新，不重排、不移除。由业务目标后退可回消息，不被中转页再次自动带回业务。直接深链且无列表上下文时，返回无筛选列表。浏览器刷新详情仍是同一条，不能改为最新消息。

**阅读自动已读（F-NC-18）。** 详情可读内容成功展示后自动将该条设为已读，列表和未读计数同步。详情载入或渲染失败不已读；自动已读保存失败时保留真实未读状态并提供明确重试，不关掉已读正文，也不把业务目标禁用。重试仅完成该条阅读状态，不重发通知、不执行业务。已读消息再次打开不重复扣减；仅打开预览、浏览经过、复制都不改变已读。见 [SM-NC-02](02-面客消息中心-流程图与状态机.md#sm-nc-02)。

**全部已读（F-NC-19）。** 作用于本人当前筛选命中的全部未读，包括尚未加载的条目，不是仅当前已加载范围，也不是忽略筛选的全池。执行前通过 `C-F-MC-04` 确认，说明分类、阅读筛选及实际将改变的未读条数；取消不改。确认中避免重复提交，成功就地已读并同步计数，失败保留原状态并可重试，不静默部分成功。确认范围内没有未读时不能提示清除了其他消息；处理期间新到且不在本次确认范围的消息仍未读。见 [FIG-NC-03](02-面客消息中心-流程图与状态机.md#fig-nc-03)。

本期没有逐条标为已读的常规入口，也没有标为未读；失败重试只重做该条的阅读状态，不等于恢复逐条标记动作。通知重复、模板语言修正或业务已办理均不把已读转回未读。

<a id="f-nc-22"></a>
### 3.7 进度信息承接（F-NC-22）

来源明确的进度信息包含业务名称、当前节点及封闭四态：进行中、待用户处理、已完成、已失败；英文为 In progress、Action required、Completed、Failed。业务细分由来源节点说明，不添加第五种状态。状态未知或非法时不假装成功，降级为普通消息并保留可读正文，来源修正后再验收。

业务编号可选，有则可复制；当前步／总步同时有效才展示，缺任一不造值。同业务不同真实节点各自保留消息，重复同一节点不增加。进度描述事件时点，当前办理结果看原业务。

<a id="f-nc-23"></a>
### 3.8 业务目标形态与可访问性（F-NC-23、F-NC-24）

<a id="f-nc-24"></a>

**目标形态（F-NC-23）。** <a id="d-nc-52"></a>`D-NC-52`：业务对象、本平台静态页面、无跳转互斥；不使用任意完整外部地址。<a id="d-nc-53"></a>`D-NC-53`：可定位原详情中的合法办理场景，不因承载形式不同而另造页面编号；动作已不适用时，有权用户可查看原对象结果，不强行打开办理。<a id="d-nc-54"></a>`D-NC-54`：静态页使用已登记且带 `lending:` 前缀的本平台编号。

业务目标必须定位原对象及必要原期次／原动作；不得换成最新业务、下一期或当前默认选择。具体查看／办理归来源定义，消息页本身不提交业务。无跳转和未登记均保留正文与返回，不提供伪业务入口，也不给“暂不支持”错误说明。

**目标可读、可办与异常（F-NC-24）。** <a id="d-nc-64"></a>`D-NC-64`：消息提醒到期、原动作失效与原对象不可访问分别处理。进入详情时检查业务目标当前可用性，列表不逐条检查；静态页不预判；等待超过 [N-NC-05](#n-nc-05) 的 3 秒或检查失败时仍可尝试前往，由目标页重新判断，不假装已经通过。

| 当前情况 | 业务入口与可观察结果 | 消息正文／未读计数 |
| --- | --- | --- |
| 原对象有权、原动作仍适用 | 按来源进入原对象查看或可办理场景，由用户主动操作 | 正文保留；按有效性与已读计数 |
| 原动作已处理／流转，但原对象可读 | 提供原对象结果查看，不保留失效动作，不换其他对象 | 正文保留当时事实，不把阅读说成办理 |
| 消息自身到期，但原对象可读 | 标识提醒过期；原办理提醒停用，可查看原对象。目标若仍允许超期办理，由目标真实状态决定 | 历史可读，不计未读计数，不删除 |
| 目标不可访问（不存在或无权） | 不可执行业务，采用同一不可用说明，不据此泄漏私有资源存在性；已确认不可访问时入口禁用且原因可理解 | 仅本人合法消息的正文可读，仍受脱敏；未到期未读仍计数 |
| 类型未登记或无目标 | 无业务跳转，不显示错误说明；可返回 | 正常可读与计数 |

<a id="d-nc-55"></a>`D-NC-55`：本人消息的可读内容不因原动作失效而删除，敏感信息保护不因历史保留而失效；禁用及原因须可被键盘与读屏获取。<a id="d-nc-56"></a>`D-NC-56`：实际落地重判权限；只因可能无权或检查未完成不提前封死入口。已登录无权走既定受限引导，未登录走既定登录与回跳；不可读的原业务不给详情，不泄漏存在性。业务对象已删除和无权统一说明“相关内容暂不可访问 / The related content is unavailable”。原对象只读可查不是越权例外。图示见 [FIG-NC-04](02-面客消息中心-流程图与状态机.md#fig-nc-04)。

## 4. 验收需求

按功能顺序验收。除明确相反场景外，资产方、资金方分别以正常登录账号验收；至少包括同企业另一员工、无关企业、同钱包不同身份、游客及受限会话。消息、业务对象、可办理状态分别准备正常与失效情形。虚构业务验证框架扩展，真实来源验证实际接入，两者不可替代。

列表与未读计数须一致，业务事件后 60 秒可见为既有硬要求；时效冲突沿 [Q-NC-04](#q-nc-04) 保留，不改起点，也不把来源 5 分钟与消息 60 秒相加放宽。原读取 P95 目标（未读计数 300ms、列表首批与详情 800ms）仅作为既有目标引用，不据文档或原型自测宣称已达；真实性能、投递及跨平台结果需实际证据。

共用安全与可用性条件：本人消息隔离、失效不残留、纯文本安全显示、敏感资料受保护；键盘可打开消息条目、键盘可关闭预览、状态与禁用原因可被读屏理解；长正文与两种语言下关键内容均不丢失。来源侧的联合验收对照见[消息通知与来源衔接](03-面客消息中心-消息通知.md#notify-acceptance)。

`CR-NC-01` 沿用 `lending:` 页面编号作为跨平台输入；`CR-NC-02` 保留 [IF-NC-01～10](#if-nc-01) 结果要求；`CR-NC-03` 承接共享登记位置及适配；`CR-NC-04` 以 [B-1～5](#b-1) 与控制台当前三册衔接，不恢复待办对象。跨平台契约未编制不能成为丢消息、越权或延迟达标的豁免。

框架功能可独立验收，但本平台全链路通知需要真实来源、收件账号、完整模板、原对象映射和时间结果。某分支依赖未明可记录待验，不把整个模块重新列为业务决策未定，也不把待验标成通过。

### 5.4 观察指标

`M-NC-01` 消息打开率、`M-NC-02` 业务目标进入率、`M-NC-03` 未登记类型出现率、`M-NC-04` 内容缺失率、`M-NC-05` 全部已读使用率、`M-NC-06` 列表与未读读取表现继续观察。指标用于发现接入缺口和干扰，不凭“打开率低”增加催促，不把正文降级的可读性当作业务完整性合格。

### 5.5 设计与后续交接

设计使用本模块当前三册。重点状态包括游客／受限会话／正常登录准入、最近消息预览与未读计数、列表首次空态与筛选空态、首批取数与续载失败、进入详情后自动已读及其失败重试、当前筛选全部已读确认、详情返回上下文恢复、进度四态与缺项降级、原动作失效但原对象可读、目标不可访问与类型未登记降级。页面布局与组件按[统一条款](#design-boundary)处理，界面不展示条款编号或来源论证。

研发、测试使用需求评审明确通过的 PRD 与原型版本；文档更新不自动等于评审通过，真实投递、权限联调与性能结果需实际证据。
