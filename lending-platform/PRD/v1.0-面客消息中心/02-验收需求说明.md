## 14. 非功能需求

### 14.1 性能（**目标值**，联调与灰度阶段校准，不影响功能逻辑与验收通过与否）

| 项 | 目标值 | 说明 |
| --- | --- | --- |
| 未读数取数 P95 | ≤ 300 ms | 常驻刷新，是面客端调用量最大的一处 |
| 列表首屏 P95 | ≤ 800 ms | 含分类元数据 |
| 详情打开 P95 | ≤ 800 ms | 含进入详情时的一次跳转预判 |
| **端到端可见时延** | **≤ `N-NC-01`（60 秒）** | 业务事件发生 → 未读角标与列表**同时**体现（`IF-NC-01`）。**这一条不是目标值，是硬性业务要求**，见 18.3 |

### 14.2 安全

| 项 | 要求 |
| --- | --- |
| 越权 | 一律「不存在」语义，**不返回「无权限」**，不可与「消息确实不存在」相区分（`D-NC-18`） |
| 枚举 | **消息标识不可枚举**；不提供批量取消息入口 |
| 预判 | 跳转预判**不得泄漏目标资源的存在性**（`D-NC-43`） |
| 会话 | 未读数刷新**不得续期或保活会话**，也不得计入任何用户活跃判定（`D-NC-31`） |
| 残留 | 会话失效后页面**不得残留任何消息内容**（`D-NC-26`） |
| 脱敏 | 敏感信息不得进入消息内容（`IF-NC-10`） |
| 渲染 | 正文一律**纯文本渲染并转义**，不支持富文本 |

### 14.3 兼容性与可用性

| 项 | 要求 |
| --- | --- |
| 端 | 桌面 + 移动自适应（借贷平台面客端母版） |
| 中断 | 新消息到达**不打断当前操作、不弹层、不抢焦点**（场景 1） |
| 降级 | 单条内容异常只影响该行，**不影响同列表其他行**（`E-NC-04`） |
| 网络抖动 | 未读数取数失败时角标保留上一次数值（`E-NC-01`）；加载更多失败不清空已加载内容（`E-NC-03`） |

### 14.4 可访问性

| 项 | 要求 |
| --- | --- |
| 未读标识 | 未读圆点**须可被读屏获取**，不是纯视觉 |
| 禁用态 | 跳转按钮的禁用状态与**禁用原因**须可被键盘与读屏获取，不能只靠视觉置灰（`D-NC-55`） |
| 面板 | 快捷面板可用 **Esc** 收起，可键盘遍历 |
| 时间 | 界面上**不出现裸时间**，一律带时区标注 |

## 15. 指标

| 编号 | 指标 | 口径 | 用途 |
| --- | --- | --- | --- |
| `M-NC-01` | 未读消息的打开率 | 一段时间内被打开的未读条数 / 新增未读条数 | 判断消息是否被真正消费，而不是被无视 |
| `M-NC-02` | 从消息到目标页的跳转率 | 有跳转目标的消息中，跳转按钮被点击的比例 | 判断跳转落点是否选对 |
| `M-NC-03` | **未登记业务类型出现率** | 记录到「未知业务类型」的条数 / 总投递条数 | **灰度期不为零是预期的**，应随接入方登记完成收敛到零（`R-NC-06`） |
| `M-NC-04` | 文案缺失率 | 触发回落的条数 / 总投递条数 | 目标为零；构建期已有校验，线上出现即为流程漏洞 |
| `M-NC-05` | 「全部已读」使用率 | 使用「全部已读」的会话数 / 打开过消息中心的会话数 | 持续偏高说明消息过载，需回头看触发口径而非改本模块 |
| `M-NC-06` | 列表与未读数接口 P95 | 上线即监控，不等出现退化趋势才建 | 本平台消息增速由**接入方数量**决定，曲线是**阶跃**的，不是平滑的 |

## 16. 依赖与风险

### 16.1 依赖

| 编号 | 依赖 | 依赖什么 | 不满足的影响 |
| --- | --- | --- | --- |
| `DEP-NC-01` | 本平台账户与登录模块 | **登录态判定与账号标识**（归属唯一依据） | 归属无法判定，可见范围与未读数均不成立 |
| `DEP-NC-02` | 本平台账户与登录模块 | **登录回跳机制** | 深链落点无法回到原处；本模块**不自建**（`D-NC-57`） |
| `DEP-NC-03` | 本平台面客端壳层 | **受限引导**与**对端白名单 / 离站告知**机制 | 跳转被拦下时无处可落；跨平台跳转将来无从复用 |
| `DEP-NC-04` | 本平台账户与登录模块 | **默认语言与语言判定链**口径 | 文案回落无基准（`Q-NC-02`） |
| `DEP-NC-05` | 本平台账户与登录模块 | **收件人时区**判定口径 | 时间展示无基准，本期按 UTC 兜底并必须带标注（`R-NC-03`） |
| `DEP-NC-06` | 本平台脱敏基线与对外术语表 | 脱敏字段清单、术语取词 | 文案规范无依据；本模块**不自建第二张表** |
| `DEP-NC-07` | 本平台面客端壳层 | **顶栏挂载点**与页面登记表 | 消息入口无处挂载；页面编号无处登记 |
| `DEP-NC-08` | 本平台共享登记处 | **触发登记表**与**分类定义表**的落库位置 | 接入方无处登记（`Q-NC-01`）。**本期接入方为零，不阻塞上线** |

### 16.2 风险

| 编号 | 风险 | 影响 | 本期处置 |
| --- | --- | --- | --- |
| `R-NC-01` | 「同企业成员看不到、铃铛为 0 而待办带有事」被当成缺陷反复上报 | 客诉与无效工单 | **写明了的正确**：PRD、对客文案与帮助中心同口径（`D-NC-19`）；验收 `AC-NC-20` |
| `R-NC-02` | 跨平台跳转本期不做，被按不存在的能力验收 | 验收争议 | 正面写在主册 4.4、12.3；反向验收 `AC-NC-63` |
| `R-NC-03` | 收件人时区口径未定 | 时间显示有歧义 | 按 UTC 兜底且**必须带时区标注**（11.11）；登记 `Q-NC-03` |
| `R-NC-04` | 接入方复用同一去重标识 | **用户永久丢失中间进度** | `IF-NC-05` + 自查清单 + 验收 `AC-NC-28`；本模块**不兜底、不自行推导** |
| `R-NC-05` | 登记表与代码常量不同批上线 | 用户看得到内容但点不过去 | 10.6 第 4 步强制同批；`M-NC-03` 监控 |
| `R-NC-06` | 灰度期未登记率不为零 | 部分消息暂无跳转 | **预期内**，`M-NC-03` 跟踪收敛；`D-NC-48` 保证不丢消息 |
| `R-NC-07` | 契约册成立后与本册口径冲突 | 返工 | 本册 `IF-NC-*` 与平台标识口径作为**输入**登记（17.2）；冲突由需求方裁定，**本模块不自行改口径** |

## 18. 验收标准汇总

> **逐条可独立执行。**【红线】= 不可削弱；【反向】= 检查「不存在」，构造出即不通过。
> 角色：除特别注明外，**资产方与资金方各跑一遍**；前置条件：已登录且非受限会话，池中有可用消息数据。
> 本期接入方为零，因此下列需要具体消息的用例**一律用虚构的测试业务类型构造**，不得依赖任何真实业务模块。

### 18.1 框架通用性与增量登记（`F-NC-06`、`F-NC-10`；规则见分册 01 第 10 章）

> **本组是本 PRD 的第一组硬性验收。** 对应需求方本轮的框架形态要求：**接入新业务只在触发登记表加一行，不改正文。**

| 编号 | 条款 |
| --- | --- |
| `AC-NC-01` | **通用性底线**：拿一个**未在本 PRD 中出现过的虚构业务模块**，只读分册 01 第 10 章，走完 10.6 的全流程（登记业务类型 + 分类 + 跳转 + 文案模板 + 去重标识）。**全程不修改本模块 PRD 的任何一个字、不修改本模块任何代码**即为通过 |
| `AC-NC-02` |【红线】**登记表不在正文**：本模块四份文件中**不存在任何一行已登记内容**——没有具体业务类型取值、没有具体分类取值清单、没有具体文案标识。构造「新增一个业务类型」，改动落点**只有共享登记表**，四份文件 diff 为空 |
| `AC-NC-03` |【反向】**正文零触发口径**：全文检索四份文件，**不存在任何具体 `biz_type` 取值、任何具体业务事件、任何发送时点、任何一条业务消息的文案**。凡示意处均为占位形态（`{业务域}.{对象}.{动作}`）且标注为非登记项 |
| `AC-NC-04` |【反向】**不另维护第二张表**：本模块四份文件中**不存在**第二份分类定义表、第二份页面段位表、第二份触发登记表 |
| `AC-NC-05` | **不代做决定**：本模块**不替任何尚未登记的接入方预填内容**，也**不代取业务类型名** |
| `AC-NC-06` | **展示层不写死**：前端代码中**不存在写死的分类清单**，也**不存在写死的业务类型到落点的硬编码分支**；两者一律由分类元数据与共享登记表驱动。构造「分类定义表新增一个分类」→ **不改任何页面逻辑**即可在筛选器中出现 |
| `AC-NC-07` | 本 PRD 使用的全部前缀与任何已入库文档的编号**零重复**；本 PRD **不新增、不改写**其他模块或其他平台前缀下的编号 |

### 18.2 消息池、承接范围与平台隔离（`F-NC-01`～`F-NC-05`；规则见主册 5.1、分册 01 第 9 章）

| 编号 | 条款 |
| --- | --- |
| `AC-NC-08` |【红线】**提交侧**：构造归属为资产可信平台 / 代币发行平台 / 本平台管理端的消息各一条 → **均不出现在本平台面客端消息池**；不存在「被本模块接收后再过滤掉」这条路径 |
| `AC-NC-09` |【红线】**查询侧**：列表、详情、未读数、标已读、全部已读、跳转预判**六处**均以「本平台面客端 ∧ 当前登录账号」为强制范围；在请求中显式传入其他平台标识、空值、数组等形态，返回结果**完全不变** |
| `AC-NC-10` |【红线】**异常数据**：人工在池中植入一条不属于本平台面客端的记录 → **列表不渲染、未读数不计入、详情深链打不开**，并记录一次数据异常。**不出现任何兼容展示或降级展示** |
| `AC-NC-11` |【反向】全文检索本 PRD 与实现，**不存在**任何「合并其他平台消息」「跨平台未读数」「全平台消息」的入口、菜单、开关、配置项或请求参数 |
| `AC-NC-12` | **两个消息中心是预期形态**：同一自然人在资产可信平台与借贷平台各自登录 → 两边**各有一个入口、各有一套未读数、各有一份已读状态**，互不影响；在一边标已读，另一边未读数**不变**。该表现**在产品文档与对客口径中被写明**，不作为缺陷记录 |
| `AC-NC-13` | **保留与清理**：消息**不因时间流逝被删除或隐藏**；界面上**不存在**手动删除、归档、清空入口；已过期消息**仍可在列表中查到并可进详情** |
| `AC-NC-14` |【反向】**只做收不做发**：全文检索本 PRD、原型与实现，**不存在任何「发消息」「新建通知」「通知设置」「消息偏好」入口**；清点界面上所有可点击元素，动作**只有六个**（看、筛、加载更多、标已读、跳过去、返回），**不存在第七种** |

### 18.3 对消息来源方的业务要求（`IF-NC-01`～`IF-NC-10`；规则见主册 5.7）

> **本组是本 PRD 的第二组硬性验收，也是「契约外移」这条裁定的兑现处。**
> **这十条不因跨平台契约册未定而免验。** 契约层未定只意味着「报文长什么样还没写」，不意味着「用户多久能看到消息、缺字段怎么办、重复事件会不会刷屏」可以没有答案。

| 编号 | 场景与预期结果 |
| --- | --- |
| `AC-NC-15` |【红线】**`IF-NC-01` 可见时效**：构造一个业务事件 → **`N-NC-01`（60 秒）内**该消息在本平台面客端可见，且**未读角标与列表同时体现**。构造「角标已加但列表里没有」或「列表里有但角标未加」任一中间态，即不通过 |
| `AC-NC-16` |【红线】**`IF-NC-02` 关键要素缺失即不入池**：分别构造缺收件人、缺业务类型标识、缺可渲染文案的三条消息 → **三条均不入池**，来源方可感知。**用户列表中不出现空白标题、空白正文或占位符形态的条目** |
| `AC-NC-17` | **`IF-NC-03` 非关键要素缺失照常入池**：分别构造缺跳转目标、缺业务编号、缺进度步序、缺失效时点的消息 → **四条均照常入池、照常展示、照常计入未读**，缺项按既定降级表现（不渲染跳转按钮、不展示步序等），**不丢消息、不隐藏整条** |
| `AC-NC-18` |【红线】**`IF-NC-04` 重复事件不产生重复消息**：同一业务事件按同一去重标识重复送达 3 次 → 用户列表中**只有一条**，未读数只加一 |
| `AC-NC-19` | **`IF-NC-06` 幂等与乱序**：同一条消息重复送达 → 不产生第二条、不改变已有展示；先送新内容再送旧内容 → **旧内容不覆盖新内容**，展示仍为新内容 |
| `AC-NC-20` |【红线】**`IF-NC-07` 收件人归属**：构造同一钱包地址同时是资产方与资金方的双身份账号 → 两个身份的消息与未读数**完全隔离、互不可见**；服务侧查询条件中**不出现邮箱、钱包地址、资质状态**。另构造同企业两个成员，由成员甲触发一条消息 → 成员乙**待办带有事、未读数为 0**，且该表现在文档中**被写明**，不作为缺陷记录 |
| `AC-NC-21` | **`IF-NC-07` 单收件人**：一条消息只有一个收件人；需要两方都知道时构造为**两条**，各自计入各自未读数 |
| `AC-NC-22` |【红线】**`IF-NC-08` 跳转目标已登记且属于本平台**：构造跳转目标为其他平台标识的消息 → **不接收**；构造同时声明「业务对象」与「静态页面」两种形态的消息 → **不接收**；构造直接给完整外部地址的消息 → **不接收**。消息实体中**不存在完整地址** |
