# 面客消息中心 · 功能需求说明 V1.1

开发主读。入口：[主册](v1.0-面客消息中心-PRD.md)；对应[验收册](02-验收需求说明.md)；全部流程在[独立图册](v1.0-面客消息中心-流程图与状态机.md)。本册定义完整产品行为，来源事件与模板由其独立通知册持有，本模块只承接通用能力。

## 9. 消息池（F-NC-01～05）

### 9.1 承接、归属与权限

资产方、资金方在正常登录态可读本人借贷平台面客消息；同企业其他成员、管理端及其他平台身份不可共享该条或其未读数。`D-NC-40`：任何入口、筛选、深链均不得扩大账号或端范围。`D-NC-41`：没有跨平台聚合入口。`D-NC-42`：全部已读仅作用于本人可见范围与当前筛选的交集。`D-NC-43`：目标无权与不存在不得泄露可区分的私有信息。

消息可读资格、目标可读资格与目标可办理资格分别判断。主体或账号未明时不能猜测收件人；资质变化不自动转移历史消息。个人/企业档案与必要业务信息按主册D-NC-60处理。消息不得被用来绕过原业务的账户、材料与凭证权限。

### 9.2 同一事件与历史

来源定义每次独立业务事实的区分范围。重复到达、重试、刷新、重新登录、同事实补送均不得新增条目、置顶、恢复未读或替换原发生时间。可确认的同事实补齐仍在原条内；后到旧内容不能覆盖较新事实，不因补齐费用、原因而再催一次。真实新轮次、新动作、新期次或新节点按来源分别保留。

来源登记无法区分不同事件时须补齐，不能按时间窗、企业或相同项目自行猜测并合并。来源明示的同次结果合并仍遵循其完整通知条件，不把不同事件乱序当成同一事件更新。对应IF-NC-04～06、[FIG-NC-01](v1.0-面客消息中心-流程图与状态机.md#fig-nc-01)。

### 9.3 未读与消息有效性

未读数按主册D-NC-20～25。未登记、无跳转、原动作失效、目标不可访问都不能单独扣减未读；消息自身过期或主动失效才退出角标计数。读过的消息始终保留，不提供重新标未读。

`D-NC-44`：消息自动更新不续期会话；发现失效立即清本人内容。前台应在既有60秒约束内取得一致的列表与角标，切回页面恢复更新；后台不干扰用户。更新失败保留最近已知计数，同设备各标签阅读状态与角标应一致；同步暂不可用时沿平台既有更新能力恢复，不能长期保留互相矛盾的已读数。

消息提醒有效性只有“有效／已过期／已主动失效”；已读状态单独记录，目标可读/可办性单独判断。到期不删除正文、不把业务本身判为失败，也不取消原业务仍允许的超期办理。见[SM-NC-01](v1.0-面客消息中心-流程图与状态机.md#sm-nc-01)。

### 9.4 保留与异常

本期长期保留，不设自动清理、归档、用户删除或清空。已过期历史仍可在列表与详情查到并标识过期，用户可读原事实。`D-NC-45`：非本池异常记录不展示、不计未读、不可经详情打开；来源可排查，不兼容为跨端信。

关键要素缺失不形成空白消息；已接收的单条翻译/展示异常按10.5降级，不拖垮列表。框架可选字段缺失不丢信，但来源定义的必要业务信息未齐，不可宣称该通知完整合格。

## 10. 触发登记与通用内容（F-NC-06～10）

### 10.1 来源与权威位置

来源模块通知册是其发送时点、收件责任、模板和业务目标的统一来源。本册只定义登记项和通用结果，不维护第二份完整事件表。共享登记权威位置尚未确定（Q-NC-01）；本轮[通知衔接册](03-面客消息中心-消息通知.md)记录已核对来源及差异，不能当作已生效共享登记。

各来源先完整登记，统一汇入共享登记并核验真实投递后才标已适配。本期有实际通知需求，不能用“空池可上线”替代真实接入验收。新增同类业务或分类不需要改本模块四册规则及页面功能。

### 10.2 登记项及校验

以下是业务登记信息，不是接口字段要求。内部传输与保存方式不在PRD中规定；对外无需显示登记编码。

| 编号 | 登记内容 | 必填、校验、默认及使用规则 |
| --- | --- | --- |
| RG-NC-01 | 业务类型标识 | 必填；沿既有三段式“业务域.对象.动作”，作为稳定来源引用；动作中的下划线不增加段数，已登记名不改名 |
| RG-NC-02 | 分类 | 必填；取平台分类定义的中英语义，不按读者或新事件任意改类；正式值未定标待适配，无默认把全部塞进进度 |
| RG-NC-03 | 平台与端 | 必填，固定借贷平台面客端；管理端由另一框架承接 |
| RG-NC-04 | 收件人 | 必填，本平台账号及其来源业务归属；多人各自一条；未定不得以企业、邮箱、钱包、最近操作人或全员代填 |
| RG-NC-05 | 负责来源 | 必填，业务模块及issue，说明唯一发送责任；不得由页面展示方另发同义信 |
| RG-NC-06 | 目标形态 | 必填，业务对象／本平台静态页面／无跳转互斥；未提供具体目标时允许无跳转 |
| RG-NC-07 | 原目标及可读结果 | 有目标时必填，标明原项目、申请、业务及必要期次/动作的定位关系，业务状态变化后的可读结果；静态页面沿lending前缀，不存任意外部地址，不为承载单元新造页面编号 |
| RG-NC-08 | 目标可用性条件 | 业务目标需声明访问及办理条件；默认进入详情检查，静态页不预判；未明不能推定具有办理权 |
| RG-NC-09 | 同一事件的业务区分 | 必填，明确账号、原对象、事件及必要次数/节点/期次；不得误合并不同真实事件；不是要求开发采用某一种算法 |
| RG-NC-10 | 完整双语模板 | 必填，标题正文成对；角色/状态变体按10.5；必需业务信息、类型、校验和缺失处理由来源给出 |
| RG-NC-11 | 消息自身有效期 | 可选，来源明确才采用；未定义不臆造到期日。消息提醒截止与业务办理截止不能混用 |
| RG-NC-12 | 适配状态 | 必填，默认待适配；共享登记、账号、目标、模板与真实投递验收完成才为已适配；有依赖的分支不能用文档完成替代 |
| RG-NC-13 | 通知偏好政策 | 来源须说明强制／可选／尚未明确；可选需有具体种类和实际作用，默认开启。未明不能成为可退订项，不把分类直接当退订种类 |
| RG-NC-14 | 同次结果合并与迟到处理 | 存在相关分支时必填；声明合并条件、保留哪些事实、何时抑制过时催办。未声明不得自行合并、补发历史全集或生成每日提醒 |

### 10.3 接入的产品流程

来源给出完整通知规则与登记 → 核对唯一事件、分类、收件与目标 → 对有差异的分支完成业务确认 → 汇入共享登记 → 按实际角色验证双语、原对象定位、计数、去重及可见时效 → 记录适配结果。未满足的分支明确标注，不把“未登记仍可读”的容错当作完成。见[FIG-NC-06](v1.0-面客消息中心-流程图与状态机.md#fig-nc-06)。

### 10.4 分类与未登记降级

`D-NC-46`：展示支持登记中新增类型与分类，不因新增业务更改页面规则。分类筛选为“全部”及本人实际拥有消息的分类。`D-NC-47`：分类未登记显示“其他 / Other”，不隐藏消息。`D-NC-48`：业务类型未登记仍展示内容、可阅读、计未读，无业务跳转按钮，也无“暂不支持跳转”提示；不跳错误页、默认页或伪造目标。缺登记可供来源排查。

类型尚未适配与非法外部目标是不同问题：前者按可读降级，后者按IF-NC-08不接收。未登记不是业务失败，不改变消息原分类以外的业务事实。

### 10.5 双语、条件模板与完整正文

既有命名约束仅引用：文案对与业务标识同源（`msg.<业务类型>.title/body`）；不扩展内部传输规范。来源使用完整中英标题和正文，不能传动词、状态词等片段拼句。用户填写的原因原文仍是原文，不声称自动译为英文。

`D-NC-62`：同一事件可以按收件角色或事件时点真实结果选择一套完整模板。各变体在同一事件登记项中明确唯一选择条件，保留来源T-*变体号供文档识别；变体不是新事件，同一收件人不能因有两套文案多收一封。两种语言的同一变体具有相同变量与事实；不同角色变体可以承载各自必需信息。条件后续变化不把原信改成新的业务结果。

`D-NC-63`：来源要求逐项对照的通知，在同封完整正文中提供全部条目；顺序、两侧缺项与条件沿来源。允许多条完整文本段落承载，不需要富文本。摘要可精简，完整详情不能截掉对照、原因、金额币种、准确截止或客服出口，也不能只以“去详情看”替代必需正文；条目不拆成多封消息。

| 信息 | 业务类型与可编辑性 | 必填、校验与缺省 |
| --- | --- | --- |
| 标题、正文 | 只读纯文本 | 有可读内容才可接收，不允许空白或技术标识；来源模板必需值不能用假值或0代替 |
| 分类 | 只读分类 | 无法识别时“其他”，不隐藏消息 |
| 消息发生时间 | 只读时刻 | 必须能准确说明原事件时间；不得因重投、阅读、时区改变。列表可相对显示，详情为带时区绝对时刻 |
| 已读状态 | 未读／已读 | 新有效消息默认未读；阅读或全部已读成功后已读，无反向入口 |
| 原业务名称、编号 | 只读文本 | 通用可选，来源必需时按来源；编号存在可复制，不能用当前默认对象补位 |
| 金额与币种 | 只读数值及币种 | 依来源必填；零只表示真实零，未知不填0；数值与原事实一致，不由消息中心折算或舍入计算业务结果 |
| 期限与业务日期 | 只读日期／时刻 | 依来源，业务日期UTC，具体时刻带时区；不从送达或阅读起算 |
| 业务原因 | 只读原文 | 依来源长度与权限；详情完整阅读，敏感内容按IF-NC-10保护；不把内部错误堆栈变成面客原因 |
| 进度节点、状态、步序 | 只读 | 节点与业务名称成组；状态限四态，步序同时存在且正整数、当前步不大于总步才展示；缺项不伪造 |
| 公共客服邮箱 | 只读联系信息 | 来源要求时必填，经核实的公共地址完整可读可复制；未知不得填模拟值或无效掩码，不代表平台自动发邮件 |

模板缺失处理：当前语言缺失回落另一支持语言；已接收消息两份均无法展示时以分类、原时间、通用标题“通知 / Notification”降级，单条不影响其他消息。可选变量缺失不显示裸占位符；必需变量缺失须可感知内容不完整，不能靠空字符串得到语义错误的成功通知，不允许把这种降级算作来源通知验收通过。切换语言后历史正文随之切换，原事实值不变。

`T-1`：中英均齐备；`T-2`：同一变体的业务信息与变量一致；`T-3`：使用面客术语。标题、正文、变量均遵守IF-NC-10；允许公共客服邮箱不等于允许私人邮箱或完整账户。

### 10.6 扩展验收

选取未在本模块出现的虚构业务，提供符合上述规则的来源通知与登记；新增分类、模板变体、原对象落点或可变条目后，四册框架规则及既有页面功能无需变更。通用性与真实业务通知验收分别进行，虚构消息不能代替当前业务联验。

## 11. 页面与完整交互

### 11.1 入口、会话与一致性（F-NC-11、F-NC-13、F-NC-27、F-NC-28）

登录且完成必办前置后，平台壳层提供消息图标及账号菜单“消息中心”。图标打开快捷面板，账号菜单直接进入无筛选消息列表。`D-NC-49`：消息不占主导航项；平台默认资产广场，无首页入口。位置和呈现复用已确认平台设计，本PRD不新增排版约束。

游客、受限会话无消息入口与数字；游客深链先登录、受限会话先完成前置，随后回原合法目标。失效时入口、面板、列表、详情及计数同时清除，迟到消息不得重新展示。资产方认证不足只限制来源业务操作，不把本人消息整体当作未登录。见[SM-NC-03](v1.0-面客消息中心-流程图与状态机.md#sm-nc-03)。

新消息可见时角标与列表一致，不弹层、不抢焦点；另一标签已读同步更新，失败不假清零。阅读不代替任何办理。

### 11.2 快捷面板（F-NC-12）

展示最近10条，含已读与未读，有标题、摘要、分类、时间及阅读状态；进度型保留识别业务与当前节点所需信息。仅打开或滚过不自动已读，选择某条进入详情。再次点入口、点外部或Esc可关闭，键盘可遍历。

“查看全部”进入无筛选完整列表；面板不提供全部已读，避免将最近10条与全部范围混淆。无消息仍展示明确空态。对应[FIG-NC-02](v1.0-面客消息中心-流程图与状态机.md#fig-nc-02)。

### 11.3 独立列表与筛选（F-NC-14～17）

`P-F-MC-01`为独立完整页面、采用整页滚动，保留已确认白底清晰分隔及阅读层次；不恢复定高内嵌列表。每条展示标题、摘要或进度、分类、时间、已读/未读标签，可点整行进入详情，键盘同样可打开；没有行内“标为已读”按钮。消息信息及状态需清晰对应，字段视觉顺序由设计决定。

| 项目 | 规则与结果 |
| --- | --- |
| 分类筛选F-NC-14 | 全部＋实际拥有分类，未知归其他，不写死业务清单 |
| 已读筛选F-NC-15 | 全部／未读／已读，默认全部，与分类取交集；刷新当前地址保持筛选。改筛选回首批和列表起点 |
| 加载F-NC-16 | D-NC-50：每次20条，加载更多追加，不用页码与每页条数切换；无更多给结束反馈 |
| 排序 | 原消息创建次序倒序，同一时间稳定排序；重复投递不置顶，阅读不重排。当前已加载未读结果中的消息变已读后就地保留，重新筛选或刷新才按最新条件重取 |
| 新消息与加载 | 新增消息与续载不重复不漏项，不强制打断当前位置 |
| 无消息 | 首次空态说明还无消息；筛选空态说明无匹配且提供清除筛选 |
| 加载失败F-NC-17 | 首屏错误可重试；续载失败保留已加载内容与位置；加载中不闪成空态，单条异常不影响其他行 |

### 11.4 独立详情与返回（F-NC-20、F-NC-21）

`D-NC-51`：`P-F-MC-02`为整页且有独立可刷新地址。展示完整标题、分类、带时区时间、正文，以及来源必要业务信息。正文阅读、业务信息、状态和业务操作须可分辨；不可操作原因与对应操作有明确关联，自动已读失败反馈独立于业务失败。保留最新面包屑返回，不强制新增重复返回入口；不新增内层卡片、分栏或固定按钮位置要求。

从列表进入后，面包屑及平台返回均回同一列表上下文，保留分类、状态筛选、已加载批次、滚动位置、当前消息与焦点。刚读的消息就地更新，不重排、不移除。由业务目标后退可回消息，不被中转页再次自动带回业务。直接深链且无列表上下文时，返回无筛选列表。浏览器刷新详情仍是同一条，不能改为最新消息。

### 11.5 阅读与全部已读（F-NC-18、F-NC-19）

详情可读内容成功展示后自动将该条设为已读，列表和角标同步。详情载入或渲染失败不已读；自动已读保存失败时保留真实未读状态并提供明确重试，不关掉已读正文，也不把业务目标禁用。重试仅完成该条阅读状态，不重发通知、不执行业务。已读消息再次打开不重复扣减；仅展开预览、滚动经过、复制都不改变已读。见[SM-NC-02](v1.0-面客消息中心-流程图与状态机.md#sm-nc-02)。

全部已读作用于本人当前筛选命中的全部未读，包括尚未加载的条目，不是仅本屏，也不是忽略筛选的全池。执行前通过既有C-F-MC-04确认，说明分类、阅读筛选及实际将改变的未读条数；取消不改。确认中避免重复提交，成功就地已读并同步计数，失败保留原状态并可重试，不静默部分成功。确认范围内没有未读时不能提示清除了其他消息；处理期间新到且不在本次确认范围的消息仍未读。见[FIG-NC-03](v1.0-面客消息中心-流程图与状态机.md#fig-nc-03)。

本期没有正常行内单条已读入口，也没有标为未读；失败重试不是恢复单条快捷标记按钮。通知重复、模板语言修正或业务已办理均不把已读转回未读。

### 11.6 目标形态（F-NC-23）

`D-NC-52`：业务对象、本平台静态页面、无跳转互斥；不使用任意完整外部地址。`D-NC-53`：可定位原详情中的合法办理场景，不为弹窗/抽屉另造页面；动作已不适用时，有权用户可查看原对象结果，不强行打开办理。`D-NC-54`：静态页使用已登记且带lending前缀的本平台编号。

业务目标必须定位原对象及必要原期次/原动作；不得换成最新业务、下一期或当前默认选择。具体查看/办理归来源定义，消息页本身不提交业务。无跳转和未登记均保留正文与返回，没有伪业务按钮和“暂不支持”错误说明。

### 11.7 目标可读、可办与异常（F-NC-24）

`D-NC-64`：消息提醒到期、原动作失效与原对象不可访问分别处理。进入详情时检查业务目标当前可用性；列表不逐条检查。静态页不预判；等待超过既有3秒或检查失败时仍可尝试前往，由目标页重新判断，不假装已经通过。

| 当前情况 | 业务入口与可观察结果 | 消息正文／角标 |
| --- | --- | --- |
| 原对象有权、原动作仍适用 | 按来源进入原对象查看或可办理场景，由用户主动操作 | 正文保留；按有效性与已读计数 |
| 原动作已处理/流转，但原对象可读 | 提供原对象结果查看，不保留失效动作，不换其他对象 | 正文保留当时事实，不把阅读说成办理 |
| 消息自身到期，但原对象可读 | 标识提醒过期；原办理提醒停用，可查看原对象。目标若仍允许超期办理，由目标真实状态决定 | 历史可读，不计角标，不删除 |
| 目标不可访问（不存在或无权） | 不可执行业务，采用同一不可用说明，不据此泄漏私有资源存在性；已确认不可访问时入口禁用且原因可理解 | 仅本人合法消息的正文可读，仍受脱敏；未到期未读仍计数 |
| 类型未登记或无目标 | 无业务跳转，不显示错误说明；可返回 | 正常可读与计数 |

`D-NC-55`：本人消息的可读内容不因原动作失效而删除，敏感信息保护不因历史保留而失效；禁用及原因须可被键盘与读屏获取。`D-NC-56`：实际落地重判权限；只因可能无权或检查未完成不提前封死入口。已登录无权走既定受限引导，未登录走既定登录与回跳；不可读的原业务不给详情，不泄漏存在性。

业务对象已删除和无权统一说明“相关内容暂不可访问 / The related content is unavailable”。原对象只读可查不是越权例外。图示见[FIG-NC-04](v1.0-面客消息中心-流程图与状态机.md#fig-nc-04)。

### 11.8 进度信息（F-NC-22）

来源明确的进度信息包含业务名称、当前节点及封闭四态：进行中、待用户处理、已完成、已失败；英文为In progress、Action required、Completed、Failed。业务细分由来源节点说明，不添加第五种状态。状态未知或非法时不假装成功，降级为普通消息并保留可读正文，来源修正后再验收。

业务编号可选，有则可复制；当前步/总步同时有效才显示，缺任一不造值。同业务不同真实节点各自保留消息，重复同一节点不增加。进度描述事件时点，当前办理结果看原业务；不固定进度区在正文上方，按最新详情阅读层次由设计组织。

### 11.11 时间、金额与语言

沿账户与平台语言偏好，不另立判定链；默认英文及中文切换承接现有平台。具体时刻带时区，日期边界依UTC；相对时间不改变绝对截止。金额带币种、依原事件快照，不将USD/USDT/USDC固定1:1:1解释为可任意改写历史金额，数币精度和尾差继续依来源。不得通过语言切换、更改时区或原业务刷新改变历史消息事实。

## 12. 深链的本平台行为（F-NC-25～26）

已登记本平台页面落原目标；未登录先登录再回原目标；无权走既定受限引导。未知平台或未知页落资产广场，不恢复首页。`D-NC-57`：复用登录域既有合法返回能力，本模块不另建一套。`D-NC-58`：消息本期不执行跨平台跳转，也不指派控制台恢复待办带；需要外部办理的原业务入口按其已确认规则承接。

消息跨平台“无跳转”不等于删除业务通知；也不限制目标业务模块自身经批准的外部办理能力。见[FIG-NC-05](v1.0-面客消息中心-流程图与状态机.md#fig-nc-05)。

## 13. 模块边界

来源负责事件、收件与业务事实；账户负责身份、语言偏好及通知偏好实际作用；壳层承接入口；控制台展示企业业务；消息中心承接本人历史告知。来源通知未闭合、账号未定或真实投递失败不回滚业务、不延长期限、不恢复额度和资格。本文所述登记是产品能力交接，不展开协议、接口、算法或存储。
