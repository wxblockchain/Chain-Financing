## 9. 消息池

> 消息池是本模块的第一块框架。它回答三个问题：**哪些消息进得来**、**谁看得到**、**看到的算几条**。三个答案都与「有哪些业务」无关，因此接入新业务时本章一个字都不用改。

### 9.1 承接范围（`F-NC-01`）

口径见主册 5.1（`D-NC-08`～`D-NC-13`）：池中**只有借贷平台面客端的消息**；资产可信平台、代币发行平台、本平台管理端的消息**一律不承接**（管理端消息属另一消息域，与面客端不共池、不合计未读）；**跨平台聚合不做、不预留、不开关控制**；归属由来源方在提交时决定，**本模块不参与路由**，不属于本池的消息根本不会进来。本节补两条落点：

`D-NC-40`：本模块的每一处查询都以「本平台面客端 ∧ 当前登录账号」为强制范围，**忽略请求侧任何形式的范围指定**，包括缺省、空值、数组与多值形态（`D-NC-12`）。

`D-NC-41`【反向】：本平台面客端**不存在**任何「合并其他平台消息」「跨平台未读数」「全平台消息」的入口、菜单、开关、配置项或请求参数。

### 9.2 可见范围与归属（`F-NC-02`）

口径见主册 5.3（`D-NC-14`～`D-NC-19`）：可见范围 = **本平台面客端 ∧ 收件人 = 当前登录账号**；归属依据是**本平台的账号标识**，不得用邮箱、钱包地址或其他平台账号原值——同一钱包地址允许同时是资产方与资金方，**用邮箱或钱包做归属会让合法的双身份用户串池**；**按人不按企业**，同企业其他成员看不到同一条消息；本模块**不读取账户原始资质状态**推导可见性；越权一律「不存在」语义，标识不可枚举，无批量取消息入口。

**必须做归属校验的六处**（缺一处即为越权面）：列表、详情、未读数、标记单条已读、全部已读、跳转预判。

`D-NC-42`：「全部已读」的作用范围强制收敛到「本人可见范围 ∩ 当前筛选」，构造越界参数**不得扩大作用范围**。

`D-NC-43`：跳转预判**不得泄漏目标资源的存在性**——对「不存在的资源」与「存在但无权限的资源」，返回结果不可据以区分两者。

### 9.3 未读计数（`F-NC-03`）

口径见主册 5.4（`D-NC-20`～`D-NC-25`）。展示侧两条落点：**刷新方式**为周期刷新 `N-NC-01`（60 秒）+ 切回前台立即取一次并重置计时 + 页面不可见时暂停，本期不引入长连接；**取数失败**时角标保留上一次数值（`N-NC-06`），不清零、不弹错误提示。

`D-NC-44`：**未读数刷新不得续期或保活会话，也不得计入任何用户活跃判定**（`D-NC-31`）；遇登录态失效**不得静默忽略**（`D-NC-32`）。本模块的周期刷新事实上会成为面客端唯一的常驻登录态探针——这正是它必须遵守这两条的理由。

### 9.4 消息的可用性状态（`F-NC-24` 的数据侧）

一条消息在池中的可用性状态见 [`SM-NC-01`](v1.0-面客消息中心-流程图与状态机.md#sm-nc-01)。文字口径：

| 状态 | 含义 | 计入未读 |
| --- | --- | --- |
| **可跳转** | 声明了跳转目标且该目标在本平台已登记 | ✅ |
| **无跳转** | 未声明跳转目标。**合法状态，不是缺陷** | ✅ |
| **未登记** | 声明了业务类型，但该类型尚未登记到前端 | ✅（未登记不是失效） |
| **已过期** | 已到声明的失效时点 | ❌ |
| **目标已删除 / 目标状态已流转 / 无权限** | 进入详情时的实时判定结果 | ✅ |

> **「已过期」与另外三类的差别**：过期是消息自身的属性（池中已知），三类失效是**进入详情时的实时判定**——所以过期不计入角标、三类失效计入。

### 9.5 保留与清理（`F-NC-04`）

**结论：本期不设保留期、不做自动清理、不做归档，消息长期保留。**

| 项 | 本期口径 |
| --- | --- |
| 保留期 | 无上限，消息不因时间流逝被删除或隐藏 |
| 自动清理 / 归档 | 不做（归档策略预留为 `N-NC-08`，本期不启用） |
| **用户手动删除** | **不提供** |
| 已过期消息 | **仍然保留、列表可见、可进详情**，只是不计入角标并带「已过期」标签 |
| 已读消息 | 与未读同等保留 |

**理由（在本平台同样成立）**：安全与合规类消息是事后回查「我的账号什么时候发生过什么」的唯一站内通道，设保留期等于给这条记录设了个静默的失效日期；在没有偏好中心、没有按分类退订能力的前提下，清理与删除都会变成逃避通知的出口，掩盖「消息过载」这个真正该解决的问题。

### 9.6 异常数据（`F-NC-05`）

`D-NC-45`：若池中出现不属于本平台面客端的记录，本模块**不渲染、不计入未读数、不可经由详情深链打开**，并记录一次数据异常。**不做兼容展示、不做降级展示**（`D-NC-13`）。

### 10.4 分类框架（`F-NC-07`）

| 项 | 规则 |
| --- | --- |
| 分类清单在哪 | **本平台的分类定义表**（10.1），**不在本册**。本册只定义「展示层如何消费它」 |
| 选项来源 | 筛选项**由服务侧返回的分类元数据渲染**。**前端代码中不存在写死的分类清单**（`D-NC-46`） |
| 渲染范围 | 「全部」+ **当前收件人实际拥有消息的分类**。给一个从没收到过某类消息的用户展示那个筛选项，点进去只会是空结果 |

| 新增一个分类要改什么 | 分类定义表加一行 + 一对中英文案 + 代码层枚举。**不需要改展示层任何页面逻辑，不需要改本册** |

### 10.5 文案模板与双语规范（`F-NC-09`）

> **本节定的是规则，不是内容。** 每条消息叫什么、写什么，由接入方在自己的 PRD 里登记。**本节不含任何一条业务消息的文案。**

| 项 | 规则 |
| --- | --- |
| 承载方式 | **模板 + 变量**（面客端默认，接入方须用这一种）。仅当每条内容都不同、无法模板化时才可用成品快照，且**必须在登记表里写明理由** |
| 为什么坚持模板 | 站内信在**展示时**按当前语言渲染；面客用户可随时切换语言，且历史消息长期保留（9.5）。**快照做不到「改模板即对历史消息一并生效」**——译文错了就永远错在那里 |
| 命名形态 | 与业务类型标识**同源**：`msg.<业务类型标识>.title` / `msg.<业务类型标识>.body`。形态示意（**非登记项**）：`msg.{业务域}.{对象}.{动作}.title` |
| 成对 | 标题与正文模板**必须成对**；只给其一视为接入错误（**不接收**） |
| 不得更名 | 业务类型标识一经登记不得更名，文案标识随之不得更名——历史消息会一直带着当初的标识 |
| 变量形态 | `{下划线小写}`。**时间传原值不自行格式化；金额传数值 + 币种不拼成字符串；链上地址与哈希传原值不自行缩略**——展示层按本平台统一格式渲染（`IF-NC-09`） |
| **禁止句子片段** | ❌ 不得把动词、状态、名词这类句子片段作为变量传进来再拼成一句话。**中英语序不同，片段拼接必然在某个语言下产生病句。** 需要不同措辞就用不同的模板 |
| 脱敏 | 完整邮箱、完整钱包地址、完整证件号、完整 IP **不得**进入标题、正文或变量（`IF-NC-10`） |
| 富文本 | **不支持**，一律纯文本渲染并转义 |

**双语一致性三条：**

| # | 要求 | 为什么 |
| --- | --- | --- |
| `T-1` | **中英两份必须同时齐备**，缺任一份即视为翻译缺失，按下表回落。不得因为「界面默认某一种语言」就只写那一种 | 默认呈现哪一份不改变文案工作量 |
| `T-2` | **两份的变量集合必须完全一致**（同名、同数量），**构建期校验，不一致即报错** | 否则切一次语言就出现「一种语言里有某个数字、另一种没有」的**静默信息丢失**，用户不会知道自己少看了什么 |
| `T-3` | **面客端文案不得使用管理端术语**，角色称谓、状态说法一律取本平台对外术语表（主册 `D-NC-06`） | 面客用户不知道也不该知道管理端的角色名 |

**缺失回落：**

| 情况 | 表现 |
| --- | --- |
| 当前语言的翻译缺失 | 回落到本平台面客端的另一种已支持语言；**构建期报告缺失项** |
| 两种语言都缺失 | 降级为「**分类标签 + 时间 + 通用标题**」的最小形态（通用标题见 11.10） |
| **任何情况** | **绝不把文案标识显示给用户** |
| 某个变量缺失 | 该占位渲染为**空字符串**并去除多余空格，**不显示 `{xxx}` 原文**；记一次告警 |
| 文案完全没提供 | **不接收**——一条没有任何内容的消息不能进用户的列表（`IF-NC-02`） |
| 单条降级的影响范围 | **只影响该行 / 该条详情，不影响同列表其他消息** |

### 10.6 谁批、批完写哪里（流程见 [`FIG-NC-06`](v1.0-面客消息中心-流程图与状态机.md#fig-nc-06)）

| 步 | 谁 | 做什么 |
| --- | --- | --- |
| 1 | **接入方** | 在自己的 PRD 里列出要用的业务类型全集 + 10.2 各列，自查是否与已登记项重复 |
| 2 | **接入方** | 走 10.8 的自查清单，**全部通过再提交**。重点是**去重标识会不会误合并**与**跳转落点是否属于本平台且已登记** |
| 3 | **本模块需求负责人** | 合入共享登记表 |
| 4 | **研发** | **同批**加代码层常量（分类枚举、业务类型常量、文案标识）。**不允许只改一处** |
| 5 | 需要新分类时 | 在分类定义表加一行 + 中英文案；**不需要改展示层任何页面逻辑** |
| 6 | 需要新的静态页面落点时 | 在本平台页面段位登记处申请，编号**必须带平台标识**（`D-NC-03`） |

> **第 4 步为什么强调「同批」**：登记表改了而代码常量没改，消息发得出去但前端认不出业务类型，会走 10.7 的未登记降级——用户看得到内容但点不过去，且只在异常记录里留下痕迹。

### 10.7 没来得及登记会怎样（**不会丢消息**，`F-NC-08`）

| 环节 | 表现 |
| --- | --- |
| 入池 | **照常接收并投递**，记一次告警 |
| 前端 | 认不出该业务类型 → **不渲染跳转按钮**，**消息内容正常展示** |
| 未读角标 | **仍然计入**（未登记不是失效，`D-NC-23`） |
| 分类筛选 | 仍归入其分类，**不被过滤掉** |
| 监控 | 记录一次「未知业务类型」 |
| 界面差异 | 与「无跳转」**完全一致**，区别只在是否记录（`D-NC-46`） |

`D-NC-48`【禁止】：❌ 跳「不存在」页；❌ 跳首页；❌ 展示一个点了没反应的按钮；❌ 隐藏整条消息；❌ 任何「暂不支持跳转」类文案。

> **登记滞后是流程问题，不该让用户承担。** 灰度期未登记率不为零是预期的（`R-NC-06`），它应随各接入方登记完成而收敛到零。

### 10.8 增量登记自检（**硬性验收**，`F-NC-10`）

**自检方式**：把「本平台某几个业务模块全部接进来」当成一次演练，逐条核对要改什么。

| 接入时会发生的事 | 要改哪里 | 要不要改本册正文 |
| --- | --- | --- |
| 新增若干个业务类型标识 | 共享登记表**加行** | ❌ **不用** |
| 每个业务类型选一个分类 | 无（从已定义的取值里选） | ❌ **不用** |
| 新增文案模板对与中英两份翻译 | 文案资源 + 登记表该行 | ❌ **不用**（命名规则在 10.5，本册不列具体文案标识） |
| 声明跳转形态与落点 | 登记表**该行的列** | ❌ **不用** |
| 需要跳本模块之外的某个固定页 | 在本平台页面段位登记处申请**自己模块**的段位 | ❌ **不用**（本册只登记 `P-F-MC` / `C-F-MC` 两段，不代管别人的段位） |
| 声明去重标识构造式 | 登记表该行 | ❌ **不用** |
| 声明是否需要预判 | 登记表该行 | ❌ **不用**（预判机制在 11.7，与具体业务无关） |
| 产生进度类消息 | 登记表该行 + 提供进度要素 | ❌ **不用**（11.8 已按通用形态实现，**不因本期无接入方而简化**） |
| 需要一个全新的分类 | 分类定义表**加行** + 代码层枚举与文案 | ❌ **不用**（10.4：筛选器由分类元数据驱动，前端不写死清单） |
| 需要一个全新的业务域 | 业务域登记处申请 | ❌ **不用** |

**自检结论：✅ 通过。** 业务模块接进来，本模块四份文件正文**零改动**，全部改动落在两张共享表与接入方自己的 PRD 上。

**这个结论靠三条结构决策换来，任何一条被破坏，结论就不再成立：**

| # | 结构决策 | 破坏它会怎样 |
| --- | --- | --- |
| 1 | **正文里没有任何具体业务类型、事件、时点、文案** | 只要正文里列了一条，下一个接入方就得来正文里加第二条，正文变成第二张登记表 |
| 2 | **本册不维护任何登记表 / 定义表 / 段位表的内容** | 两张表各自演进，跳转落点的唯一性校验会有两个依据 |
| 3 | **展示层不写死分类清单、不写死业务类型映射**，一律由元数据与共享表驱动 | 每接入一个新分类都要改前端页面逻辑 |

## 11. 页面与展示

> 这是本模块的第三块框架。**本章定义展示层如何承载任意一条消息，不定义任何一条具体消息。** 展示层**不因本期尚无接入方而做任何简化**。

### 11.1 入口与未读角标（`F-NC-11`、`F-NC-13`）

**两个入口：**

| 入口 | 形态 | 位置 | 点击后 | 是否产生已读 |
| --- | --- | --- | --- | --- |
| **顶栏消息入口 `C-F-MC-01`**（含未读角标） | 顶栏常驻图标 | **顶栏右侧、账号下拉之前**（若顶栏有语言切换器，则位于其左侧）。两种情况下位置都必须**固定且可预期** | 展开快捷面板 `C-F-MC-02` | ❌ |
| **账号下拉「消息中心」条目** | 下拉菜单项 | 账号下拉内，与账户设置等条目并列 | **直达 `P-F-MC-01`**，不经面板、不带筛选 | ❌ |

`D-NC-49`：**本模块不占顶栏主导航位。** 面客端顶栏主导航已由首页、资产广场、借贷广场、我的控制台占满；消息中心入口收敛在顶栏图标与账号下拉。

**登录态与入口可见性：**

| 登录态 | 消息入口 | 账号下拉「消息中心」 | 消息中心深链 | 未读数刷新 |
| --- | --- | --- | --- | --- |
| **游客** | ❌ 不渲染 | ❌ 无此条目 | 走登录回跳（`D-NC-30`） | ❌ **不得发起任何请求** |
| **受限会话** | ❌ 不渲染 | ❌ 无此条目 | **不放行**，走本平台必办前置 | ❌ 不发起 |
| **已登录** | ✅ 渲染 | ✅ 有 | ✅ 正常落地 | ✅ 按 `N-NC-01` 刷新 |
| **会话失效瞬间** | ❌ **立即消失** | ❌ 立即消失 | — | ❌ **立即停止并中止进行中的取数** |

**会话失效瞬间必须发生的五件事**（`F-NC-27`，逐条对应主册 `D-NC-26`～`D-NC-30`）：① 未读角标数字**从页面移除**（不是置 0、不是隐藏样式）；② 顶栏消息入口**不再渲染**，账号下拉条目消失；③ 快捷面板若展开，**内容清空并收起**；④ **停止刷新计时并中止进行中的取数**，游客态下不再发起；⑤ 详情页**整页卸载**，不是弹层遮挡。

**多标签一致性**：同设备多标签之间**同步已读与角标**；同步能力不可用时**降级为周期刷新**。在一个标签页把某条标为已读，其他标签页的角标与列表行状态应随之更新。

### 11.2 快捷面板（`C-F-MC-02`，`F-NC-12`）

| 项 | 规格 |
| --- | --- |
| 条数 | 最近 `N-NC-02`（**10**）条 |
| 是否区分已读未读 | **不区分**。未读条目有视觉标识，已读条目同样展示 |
| 已读行为 | **仅展开不产生任何已读**；滚动经过也不产生已读；点击面板内某条进入详情后该条才转已读 |
| 「全部已读」 | ❌ **面板内不提供**。面板只展示最近 10 条，而「全部已读」作用于当前筛选命中的全部消息，两者范围不一致，放在一起必然被误解为「把这 10 条标掉」 |
| 底部 | 「查看全部」→ `P-F-MC-01`，无筛选 |
| 收起方式 | 再次点击入口、点击面板外区域、按 **Esc** |
| 空态 | 面板内展示空态文案，**不隐藏面板** |
| 进度型消息 | 面板内同样展示节点状态标签（11.8），但省略业务名称之外的次要信息 |

### 11.3 消息中心列表（`P-F-MC-01`，`F-NC-14`～`F-NC-17`）

**页面结构（线框级）：**

```
┌──────────────────────────────────────────────────────────────┐
│  顶栏（主导航 · [语言切换] · 消息入口 C-F-MC-01 · 账号下拉）    │
├──────────────────────────────────────────────────────────────┤
│  消息中心                                    [ 全部已读 ]      │
│                                                              │
│  分类：[ 全部 ][ …由分类元数据渲染… ]  状态：[全部|未读|已读]   │
├──────────────────────────────────────────────────────────────┤
│  ● [分类标签]  {消息标题}                      {时间}          │
│                {消息正文摘要…}                  [标为已读]     │
├──────────────────────────────────────────────────────────────┤
│    [分类标签]  {消息标题}                      {时间}          │
│                {消息正文摘要…}                                │
├──────────────────────────────────────────────────────────────┤
│                      [ 加载更多 ]                             │
└──────────────────────────────────────────────────────────────┘
```

> 图中 `{消息标题}`、`{消息正文摘要}`、`[分类标签]` 均为**占位**，不是任何一条具体消息的文案。

**分类筛选（`F-NC-14`）**：规则见 10.4。要点——选项由分类元数据渲染、前端不写死；只渲染该收件人实际拥有消息的分类；未登记分类回落「其他」且不隐藏消息。

**已读 / 未读筛选（`F-NC-15`）**：三档 **全部 / 未读 / 已读**，默认「全部」，与分类筛选**可叠加**（与关系）。**筛选条件写入地址栏查询参数**，刷新后筛选态保持；切换筛选时回到首屏并把滚动位置带回顶部。

**加载更多与排序（`F-NC-16`）**：

| 项 | 规格 |
| --- | --- |
| 翻页形态 | **「加载更多」按钮，不是分页器**（`D-NC-50`）。无页码、无每页条数切换器 |
| 单次条数 | `N-NC-04`（20） |
| 排序 | **创建时间倒序**。已读状态**不参与排序**，标记已读后该行**位置不变、不被移除**（未读不置顶、已读不沉底） |
| 稳定次序 | 同一时间戳的多条以消息标识作稳定次级排序 |
| 翻页稳定性 | 加载期间有新消息插入顶部时**不出现重复项或漏项** |
| 已加载内容 | 「加载更多」**追加**在已有列表之后，**不替换** |
| 到底 | 没有更多时按钮变为「没有更多了」的终止态，**不再可点** |

> **为什么不是分页器**：管理端列表有「跳到某一页复查」的诉求，面客画布没有。

**空态、加载态与失败（`F-NC-17`）**：

| 状态 | 表现 |
| --- | --- |
| **首次空态** | 「还没有任何消息」类文案，**不提供「清除筛选」** |
| **筛选空态** | 与首次空态**文案不同**，且提供「清除筛选」，可一键回到无筛选状态 |
| 首屏加载中 | 骨架屏或加载态，不闪烁空态 |
| 首屏失败 | 错误态 + 重试 |
| **「加载更多」失败** | **当前已加载内容不清空**，按钮回到可点状态并提示可重试 |
| 单条内容异常 | 该行降级为「分类 + 时间 + 通用标题」最小形态（10.5），**不影响同列表其他行**，且仍可点击进入详情 |

### 11.4 消息详情（`P-F-MC-02`，`F-NC-20`、`F-NC-21`）

**形态：整页，不是抽屉、不是弹层**（`D-NC-51`）。三条理由：① **详情是深链的落点**，抽屉形态在直接打开时没有「背后的列表」可依附，刷新与回退行为割裂；② 详情内可能包含较长的正文与业务上下文（尤其进度类）；③ **会话失效时详情必须整页卸载**（`D-NC-29`），抽屉／弹层形态天然诱导「盖一层」的实现，而共用办公设备下「弹个框盖住」等于没登出。

**页面结构（线框级）：**

```
┌──────────────────────────────────────────────────────────────┐
│  顶栏                                                         │
├──────────────────────────────────────────────────────────────┤
│  ← 返回列表                                                   │
│                                                              │
│  [分类标签]  {消息标题}                                        │
│  {绝对时间 + 时区标注}                                         │
│  ── 进度区块（仅进度类消息，见 11.8）──────────────            │
│                                                              │
│  {消息正文}（纯文本，转义渲染，换行保留）                        │
│                                                              │
│  ── 失效说明条（仅三类失效时，见 11.7）─────────               │
│  [ 跳转按钮 ]    [ 返回列表 ]                                  │
└──────────────────────────────────────────────────────────────┘
```

**返回列表的状态同步（`F-NC-21`）**：返回后**保留筛选条件、已加载批次与滚动位置**；刚读过那条的已读状态**就地更新，不重排、不移除**。

> **「已加载批次」是面客形态特有的一条**：分页器形态只需记住页码，「加载更多」形态必须记住**已加载到第几批**，否则用户加载了 5 批、点进一条详情、返回后只剩第 1 批——这是面客形态最容易漏掉的返回态。

### 11.5 已读语义（`F-NC-18`、`F-NC-19`）

状态流转见 [`SM-NC-02`](v1.0-面客消息中心-流程图与状态机.md#sm-nc-02)。

**单条已读（`F-NC-18`）：**

| 触发 | 规格 |
| --- | --- |
| **打开详情即已读** | 详情**渲染成功后**才转已读；请求失败或渲染失败**不转已读** |
| **列表行内「标为已读」** | 显式操作，**不进入详情**；操作后该行就地变已读态，**位置不变** |
| 快捷面板内展开 | ❌ 不产生已读 |
| 滚动经过 | ❌ 不产生已读 |
| 已读不可撤销 | 本期**不提供「标为未读」**（`X-NC-11`）。唯一的未读恢复路径是**去重命中后的合并更新**，由系统触发，不是用户操作 |

**全部已读（`F-NC-19`，流程见 [`FIG-NC-03`](v1.0-面客消息中心-流程图与状态机.md#fig-nc-03)）：**

**作用范围**为**当前筛选命中的全部消息**——不是「当前已加载的那些」，也不是「全部消息」；执行前经 `C-F-MC-04` 弹层二次确认，**必须说明条数与当前筛选**；入口在列表页顶部，**快捷面板内不提供**；执行后角标按新未读数更新、列表行就地变已读态，**不重排、不移除**；失败时提示并保留原状态，**不做部分成功的静默处理**。

> **为什么必须说明筛选**：用户在「未读 + 某分类」筛选下点「全部已读」，若不说明，会以为清掉的是全部消息；反过来在无筛选下点，也可能以为只清掉了眼前这一屏。

### 11.6 跳转形态（`F-NC-23`）

> **本节只定义「跳转怎么执行、失败怎么降级」，不定义「哪条消息跳哪里」**——后者由接入方在登记表里声明（10.2）。

**三形态互斥：**

| 形态 | 承载 | 落地方式 |
| --- | --- | --- |
| **业务对象目标** | 业务类型标识 + 业务对象标识 | 按业务类型查前端登记映射得到落点模板，用对象标识填充 |
| **静态页面目标** | **带平台标识的页面编号**（`lending:P-F-MC-01` 形态） | 按本平台页面落点表直达，**不做预判** |
| **无跳转** | 三者都不填 | **合法状态**，见 11.7 |

`D-NC-52`：**同时声明两种形态的消息不接收；消息实体中不得存放完整地址**——地址会随路由调整失效，而消息长期保留。

`D-NC-53`：**落点可以是详情页内的承载单元（弹窗 / 抽屉），不只是「一个页面」。** 这类落点的跳转语义是「**落详情页 + 打开对应承载单元**」，锚点写在落点模板里（`RG-NC-07`）。**不得为一个承载单元申请独立页面编号——承载单元不是页面，不占页面段位。** 锚点未登记或目标承载单元在当前业务状态下不该打开时，**落详情页即可，不报错**——详情页本身永远是合法落点。**本模块不解析锚点语义、不校验锚点取值**，那是目标页的职责。

`D-NC-54`：静态页面目标的编号**必须是本平台已登记段位内的编号且带 `lending:` 平台标识**；平台标识不是本平台的，**本平台不接收**（`IF-NC-08`）。

### 11.7 跳转预判与降级（`F-NC-24`）

分支全貌见 [`FIG-NC-04`](v1.0-面客消息中心-流程图与状态机.md#fig-nc-04)。

**预判：**

| 项 | 规则 |
| --- | --- |
| 谁要预判 | **业务对象目标**。是否预判由登记表声明，**缺省视为需要预判** |
| 时机 | **进入详情页时执行一次**（不是点击时），使失效状态能提前体现在按钮上 |
| 列表页 | **不做预判**（不做全量预判） |
| 超时 | `N-NC-05`（3 秒）。**超时按预判失败处理，放行跳转**，由目标页按自己的规则处理 |
| 结果 | 目标已删除 / 目标状态已流转 / 无权限，**三选一** |
| 安全 | 预判**不得泄漏目标资源的存在性**（`D-NC-43`） |

**四类失效的表现：**

| 类型 | 跳转按钮 | 说明条 | 正文 | 计入角标 |
| --- | --- | --- | --- | --- |
| **已过期** | **不渲染** | 列表带「已过期」标签 | **完整展示** | ❌ |
| 目标已删除 | **禁用而非隐藏** | ✅ 有说明条 | **完整展示** | ✅ |
| 目标状态已流转 | **禁用而非隐藏** | ✅ 有说明条 | **完整展示** | ✅ |
| 无权限 | **禁用而非隐藏** | ✅ 有说明条 | **完整展示** | ✅ |

`D-NC-55`：**内容一律完整展示。** 失效影响的只是「能不能跳过去」，不影响「能不能读」。禁用状态与**禁用原因**须可被键盘与读屏获取，不能只靠视觉置灰。

**「无跳转」与「未登记」的表现（两者在界面上完全一致）：**

| 位置 | 表现 |
| --- | --- |
| **详情页** | **不渲染跳转按钮**——既不展示可点的、也不展示置灰的；标题、正文、时间、分类标签**完整展示**；**不展示任何说明文案**；操作区只留「返回列表」 |
| **列表 / 快捷面板** | 该条**正常展示、正常可点进详情**；**不因此隐藏、置灰或改变样式** |
| **分类筛选** | 仍归入其分类，**不被过滤掉** |
| **未读角标** | **仍然计入** |
| 差别 | 仅「未登记」记录一次未知业务类型（`D-NC-46`） |

`D-NC-56`：**落地时必须重新判权。** 预判通过不等于跳过去就有权限——面客端有多种身份与资质档位，目标能力可能正好是权限上的硬卡点。被拦下时：**已登录但权限不足** → 落本平台受限引导，**不是错误页、不是报错提示**；**落地时已非登录态** → 落地页按本平台既定的未登录表现处理。**落地页长什么样归目标模块，本模块不实现、不校验、不兜底**；本条只定一件事——**消息的跳转按钮不得因为「可能落到无权限」而提前置灰或隐藏**，跳转照常发起，落地态由落地页自己表达。

### 11.8 业务办理进度展示（`F-NC-22`）

> **本节只定义展示层如何承载进度类消息，不定义有哪些业务节点、也不定义推送时机**——那由各业务模块在自己的 PRD 里定义。**展示层不因本期尚无接入方而做任何简化。**

**列表中的进度型列表项（`C-F-MC-03` 进度变体）：**

```
┌──────────────────────────────────────────────────────────────┐
│ ● [业务办理进度]  {业务名称}                      {时间}       │
│                   {当前节点} · [节点状态标签]     第 2/5 步     │
└──────────────────────────────────────────────────────────────┘
```

| 位置 | 承载的业务含义 | 规则 |
| --- | --- | --- |
| 分类标签 | 该消息的分类 | 进度类消息固定归入「业务办理进度」分类 |
| 标题位 | **业务名称** | 由文案模板渲染。**本册不列举任何业务名称** |
| 节点 | **当前节点名称** | 同上 |
| 节点状态标签 | **节点当前状态** | **封闭四态**：进行中 / 待用户处理 / 已完成 / 已失败。**不得扩展**；业务侧的细分状态由节点名称的文案表达 |
| 步骤 | **第几步 / 共几步** | **两者同时提供时**展示「第 N/M 步」，**缺任一则不展示** |

**详情中的进度区块**：在正文**之上**增加一个区块，展示业务名称、**业务编号**（可选，**支持复制**）、当前节点、节点状态标签。

**每次进度更新是一条独立消息，不做同业务合并：**

| 项 | 口径 |
| --- | --- |
| 展示 | 同一笔业务的多次节点更新在列表中是**多条独立消息**，按时间倒序各占一行 |
| **去重硬约束** | 进度类消息的去重标识**必须同时包含业务标识与节点标识**（`IF-NC-05`）。本模块**只按声明的去重标识判重，不自行推导**——若接入方对同一业务的不同节点复用同一标识，**第二个节点的更新会就地覆盖第一条，用户永久丢失中间进度** |
| 不冲突 | 「不合并」说的是**不同节点**；「去重」说的是**同一节点被重复送达** |

**本期不做**：完整进度条 / 步骤条（`X-NC-10`）；进度类消息的单独角标或单独入口（角标不分分类，`D-NC-21`）。

## 12. 跨平台深链：本平台侧的行为要求

> **本章只写本平台的行为，不写解析实现**（`D-NC-39`）。图示见 [`FIG-NC-05`](v1.0-面客消息中心-流程图与状态机.md#fig-nc-05)。

### 12.1 编号形态（本平台侧口径）

| 项 | 口径 |
| --- | --- |
| 形态 | `<平台标识>:<页面编号>`，本平台标识为 **`lending`**（`D-NC-03`） |
| 示例 | `lending:P-F01`、`lending:P-F-MC-01`、`lending:P-F-AM-01` |

| 本模块的自有编号 | `lending:P-F-MC-01`（消息中心列表）、`lending:P-F-MC-02`（消息详情） |

### 12.2 本平台作为**被跳转方**（`F-NC-25`）

| 编号 | 行为要求 | 可观察结果 |
| --- | --- | --- |
| `D-NC-34` | 平台标识为 `lending` 且页面编号已登记 → 带用户到**对应的那个页面**；落点需要登录而当前未登录时，走本平台既定登录回跳，**登录后回到该落点** | 落点正确，不落首页、不落列表页；登录成功后落在原落点 |
| `D-NC-35` | 落地时**重新判权**，当前身份无权限 → 落**本平台受限引导** | **不是错误页、不是报错提示** |
| `D-NC-36` | 平台标识不是 `lending`，或页面编号在本平台未登记 → **落本平台面客端首页**并记录一次未知落点 | **不给「不存在」页、不白屏、不静默无反应** |
| `D-NC-57` | 全过程**本模块不自建回跳解析、不自拼回跳参数**，一律复用本平台面客端既定机制（`DEP-NC-02`） | 地址栏与请求中不出现本模块自造的回跳参数 |

### 12.3 本平台作为**发起方**（`F-NC-26`）

`D-NC-37`：**本期**，需要用户去其他平台办的事，本平台产出的消息一律是**「无跳转」**形态——内容照常完整展示，详情页**只留「返回列表」，不给任何说明文案**。
`D-NC-58`：用户的跨平台去向本期由**我的控制台待办带**承载，不由消息承载。
`D-NC-38`：将来实现跨平台跳转时，执行**一律复用本平台统一的对端白名单与离站告知机制，本模块不自建一套**（`DEP-NC-03`）。

> **这是本期能力边界，不是缺陷**（`R-NC-02`）。正面写出来，否则会被按不存在的能力验收。

## 13. 模块边界与术语

### 13.1 与我的控制台的边界

引用主册 5.6（`B-1`～`B-5`），**两边引用同一份判据，不各写一版**。

| 方向 | 条款 |
| --- | --- |
| 消息 → 待办 | 本模块**不产生待办、不计算待办、不渲染待办带**。待办带是控制台页面内的组件，不是壳层组件 |
| 待办 → 消息 | 控制台**不自建消息中心**，也不自建消息列表 / 未读角标 / 已读逻辑 |
| 两个计数 | 顶栏未读角标与控制台待办计数是**两个独立数字，任何操作下都不联动** |

### 13.3 术语
