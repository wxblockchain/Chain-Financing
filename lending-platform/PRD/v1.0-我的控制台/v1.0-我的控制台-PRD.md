## 3. 功能需求说明

<a id="f-mc-01"></a>
### 3.1 F-MC-01 统计区

资产方看到资产与融资全貌；资金方看到授信与出资全貌。所有指标限定当前主体全部业务，不因当前tab分页或筛选缩成当前页合计。进入页面、返回后刷新或手动刷新时更新；同一组数量、金额和副行保持同批事实一致。相关流程见[FL-MC-01](v1.0-我的控制台-流程图与状态机.md#fl-mc-01)。

| 业务字段／编号 | 类型与业务意义 | 范围、必有值与显示 |
| --- | --- | --- |
| 全部代币张数、代币价值合计 | 非负整数张数、USD金额；本平台快照中属于本企业且符合展示条件的代币总量 | 资产方必有；含失效；资金方不展示；正常空集合为0 |
| 其中已质押代币张数、代币价值合计 | 已满足本平台“已质押”口径的代币子集；账面金额含失效 | 以“其中”从属于全部代币，不能与总量画成互斥同级卡片（`D-MC-47`） |
| 其中已失效张数、金额 | 上述已质押子集中代币已失效的部分 | 必有副行，标注“不计入覆盖”；不能用全部代币失效量冒充此子集 |
| 总授信额度、授信笔数（`CR-05`） | USD金额、非负整数；资产方各机构授信／资金方授予各资产方的授信 | 双方可见；沿用授信域统计结果 |
| 已融额度、业务笔数（`FP-13`／`CR-08`） | 当前项目融资余额／本机构授信占用额与未结清融资业务数 | 双方可见；不把在途报价当成已融额度 |
| 剩余可用授信（`CR-11`） | 当前可用授信汇总，USD | 双方可见；不是“还能融资多少”的承诺 |

`D-MC-43`、`D-MC-44`、`D-MC-126`、`D-MC-127`：代币价值按各笔签发时既定金额汇总，旁注“按各笔签发时汇率折算”，不实时换汇。已质押账面值不等于项目有效质押价值，不能以简单减失效值强行对平；项目侧还受已确认有效覆盖条件约束。剩余可用授信旁说明“实际可融金额以发布需求时的核定结果为准”。

不常驻展示融资上限、可融金额、项目在途金额、可撤回上限，不做额度尺或规则公式区。动作受限时仍保留归属模块给出的必要差额、原因与出路（`H-03`），不能为隐藏中间量而删掉用户解决问题所需的信息。

指标失败时仅该组显示暂不可用与重试，不伪装成0；无机构主体按3.10整页引导，不进入正常统计空态。

### 3.2 F-MC-02 代币列表

仅资产方可见。范围为本平台只读代币域中“属于本企业”的集合，与资产广场是同一套事实的主体过滤视图。点击代币记录进入本控制台代币详情 `P-MC-02`；所属项目的广场链接另行标识。详情沿用本节字段边界，不因新增详情而开放额外资产资料，不扩展资产广场未约定的反向入口。

`D-MC-175`【数据边界】：代币事实由代币发行平台提供，本平台使用已同步快照；不设置运营上架闸门，不在打开控制台时临时访问上游。代币状态、价值取代币事实，质押结果取本平台借贷业务，不能回读上游旧质押结果。资产可信平台的应收账款信息随展示数据到位。来源为WS-350 `D-AM-47`～`D-AM-51`。

| 字段／既有编号 | 业务类型与含义 | 必有值、展示与校验 |
| --- | --- | --- |
| 代币编号（`D-TI-21`） | 唯一业务标识；16位 `TK` + 铸造日 + 6位序号 | 必有，完整可复制；关键缺失不得展示该记录 |
| 代币数量（`D-TI-11`） | 数值，最小0.01、2位小数 | 必有；符号只取已确认配置，不编造ticker；张数与此数值分开 |
| 代币价值（`D-TI-18`） | 固定USD金额，2位小数 | 必有；不二次折算；用“代币价值”标签 |
| 底层应收账款账期（`D-06`／`D-07`） | 起始日～到期日，`yyyy-MM-dd` | 只读；缺项显示“—”，不补造日期；有效数据不得起始日晚于到期日 |
| 买方企业名 | 对应底层应收账款债务方全称 | 只读；缺失显示“—”，不以本企业名替代 |
| 代币状态（`D-TI-22`） | “有效／失效”二值 | 必有；失效结果由上游判定，不根据本机日期自行翻转 |
| 质押状态（本平台 `PL-*`） | “未质押／已质押”二值 | 与代币状态分别标注，不复用上游 `D-TI-24` 旧口径；不是代币是否有效的判断 |
| 所属融资项目（`FP-01`／`FP-02`） | 项目稳定标识和名称 | 已质押时显示相应项目及深链；仅允许进入当前主体可访问项目，草稿可达性由L5判定，不暴露他方草稿 |
| 签发时间（`D-TI-07`） | 与资产广场“铸造时间”同一时刻 | 必有；显示时区；默认倒序排序，不另造第二个时间事实 |
| 铸造交易哈希（`D-TI-06`） | 铸造业务凭证，`0x`+64位十六进制 | 属共有数据完整性条件，本tab不因此新增哈希列或新的外链入口 |

`D-MC-176`【对外收敛】：已完成转入且本平台认定已质押时显示“已质押”；未质押、入池处理中、失败、已释放均按资产广场同源结果显示“未质押”。控制台不显示这些内部过程分支，也不自行翻译内部编号。失效与已质押可以同时成立；失效行显示“不计入覆盖”。详见[ST-MC-01](v1.0-我的控制台-流程图与状态机.md#st-mc-01)和[ST-MC-02](v1.0-我的控制台-流程图与状态机.md#st-mc-02)。

`D-MC-131`、`D-MC-177`：本tab不展示合同号、发票号、提单号、持有人地址、附件影像、运营诊断、链上过程态、gas或“已释放·待提取”第三种质押状态。原代币tab的可提取汇总提示不再放在本tab；本人的解除质押能力继续由融资项目行前往L5承接（3.3、3.9），不能借此重建待办区。质押审核状态不扩展为第三根代币轴，用户到项目业务查看审核结果。

`D-MC-178`【数据可用性】：代币编号、数量、价值、代币状态、铸造交易哈希、铸造时间任一缺失的记录不进入展示集合、不计入对应统计；本企业归属无法确认时不得展示或计入。非关键项缺失逐项“—”。这是与WS-350 `E-AM-10`同源的集合规则，不能两页一边显示一边统计排除。

### 3.7 F-MC-07 我的报价

| `P-MC-06` 还款期次详情；还款信息，双方 | 业务／需求及期次编号、应还日、本金／利息／合计和币种、期次状态、逾期事实、适用开启或确认时限 | 集中展示3.6该业务摘要与该期计划版本、计息区间、金额、还款性质、账户摘要、实际还款记录、凭证摘要及确认结果。单页对应稳定期次 `RP-01`，不可因同属一个业务跳到其他期次；历史初始计划须标明版本，当前操作依最新有效期次。可前往广场对应期次还款／确认，或查看该业务全计划与版本对照；控制台不编辑和重算计划。 |
| `P-MC-07` 报价详情；我的报价，资金方 | 业务编号、对应需求／项目、资产方、融资金额币种、业务状态和适用报价剩余时限 | 集中展示3.7商务条款、报价时间、锁定对象及起点、已锁定时长、到期时刻、有效期、项目覆盖事实与历史终结原因。等待阶段提供查看广场业务导航，不新增催办／撤回／修改。后续进入放款阶段可按3.9前往同一业务的适用操作；不再显示报价等待倒计时。 |

`D-MC-184`【共同详情行为】：标题明确对象类型，完整稳定编号可复制；内容按业务主题组织，区分当前事实、历史记录和缺失项。报价、放款可能沿用同一 `FD-01`，但进入时保留“报价详情／融资放款详情”的阅读侧重点；不能因此显示其他机构报价或另一业务。只读含义、完整字段、数据边界与对应列表相同；详情仍不得展示合同号、发票号、资产影像、内部执行态或机构不该看到的信息。代币铸造哈希的完整性条件不自动变成新增展示字段或外链。

`D-MC-185`【快捷操作】：详情有可识别的快捷导航区，文案区分“查看广场业务”和“去放款／去还款”等动作。所有业务动作沿用3.9三种资格表现，进入借贷广场后重新判断最新权限和状态；控制台不放业务表单、上传或确认提交。一个项目有多轮需求、一个业务有多期期次时，动作与对应轮次／期次放在一起或明确标出目标，不默认选择第一项。无可执行业务动作时保留适用的只读广场导航；目标无法确定时说明暂无可访问关联，可保留普通广场导航，不伪装成已定位业务。正常无关联与读取失败分别表达，读取失败可重试。

`D-MC-186`【返回与恢复】：从列表进入详情后，详情提供返回来源列表入口；浏览器后退同样恢复原tab、筛选、排序、页码、每页条数和记录附近位置。进入广场后完成或取消，再返回控制台时先回发起动作的详情，取得最新业务事实；继续返回列表才恢复列表位置。列表本身发起快捷动作时直接回列表。目标因更新不再匹配筛选时说明记录已更新，可清除过滤查看；不保留过期值凑旧位置。直接打开、刷新或分享详情仍定位同一类型和对象；没有来源列表上下文时，返回该类型对应tab的默认视图，不凭空恢复他人的筛选。最新业务已不可访问时按下条处理。

`D-MC-187`【详情状态与权限】：详情加载时明确加载中，切换对象不得把上一对象内容当作新对象展示；失败为暂不可用及重试，不能写成尚无业务。成功后按真实条件区分“尚无放款记录／尚无还款记录”等局部空内容。不存在、已不属本主体、当前角色不允许的对象统一“内容不存在或无权访问”，提供返回本人可访问列表的出路；不泄露对象存在性。未登录直达先按登录域认证，再回可访问的原详情；协议、主体不明或无主体沿用3.10。会话失效即时移除详情数据；重新认证后重新判定归属，不直接恢复旧敏感内容。正常业务终结不等于对象不可访问。

`D-MC-188`【设计与验收边界】：设计师可决定列表增列、精简、响应式排布及详情分组；列表必须保留识别对象、金额币种、状态和当前紧迫事项所需的信息，不能把超期与待重传等关键标记全部藏到详情。详情承担完整核心信息阅读；不以强制多行堆叠或全部字段平铺作为验收条件。本轮不改变统计、业务状态、字段权限、授信维度或原有操作资格。

业务闭环见[FL-MC-02](v1.0-我的控制台-流程图与状态机.md#fl-mc-02)和[FL-MC-04](v1.0-我的控制台-流程图与状态机.md#fl-mc-04)，详情状态见[ST-MC-05](v1.0-我的控制台-流程图与状态机.md#st-mc-05)；对应验收集中在4.13。
