# 授信报价与接受拒绝 · PRD

借贷平台面客端 · L6 / WS-375 · 2026-09-23 · 许楚清

资金方先检查对资产方的授信，必要时核定或追加，再对一轮融资需求提交全额报价。报价一经提交即锁定本轮需求，资金方不能撤回，持续有效直到资产方处理：资产方确认本笔收款账户、核对商务摘要后接受，或填写原因拒绝。所属融资需求因项目关闭、项目到期或覆盖不足而终结时，本笔在途报价连带失效。接受后转入放款，尚不代表资金到账。

**本文是产品、前后端研发及测试的共同入口。** 第2～6章按业务顺序讲功能，第8章按同序集中验收。按需打开[流程图与状态机](02-授信报价与接受拒绝-流程图与状态机.md)或[消息通知](03-授信报价与接受拒绝-消息通知.md)。开发主读第2～6章与第7章依赖，测试主读第8章及通知册验收。Hallmark同时读取三册。

<a id="scope"></a>
## 1. 范围、角色与共同入口

本模块负责授信核定与追加、报价锁定、接受/拒绝、报价连带失效以及相关记录和通知。没有授信审批、额度主动调低/冻结、多家同时报价、部分融资、报价修改/撤回/展期、报价有效期与自动到期、平台生成或审核合同、合同盖章件收取、收款账户的新增与维护。上述操作不触链、不产生gas；真实放款、还款由后续模块办理，企业收款账户由[企业账户](../v1.0-企业账户/01-企业账户-PRD.md)维护。

| 角色 | 可做与可见 |
| --- | --- |
| 资金方本企业登录员工 | 代表机构核定授信、报价；不可向本机构自己的需求报价，不可代资产方接受。只见本机构的授信与相关私有业务资料 |
| 资产方本企业登录员工 | 接受或拒绝本企业的报价；可查看各机构对本企业的授信及本方协议，不能查看机构内部备注 |
| 游客和其他企业 | 只看公开需求、商务条款和锁定事实。授信额度、账户、文件、私人档案、联系方式均非公开；游客唯一可办理的动作是“立即登录” |
| 运营（含SPV） | 保留既有异常授信待办与监控；无面客代报价、代接受入口，无本模块新增通知广播 |

沿用户已确认的查看与办理分离方式，项目记录的四类清单与办理入口沿[L5查看与办理](../v1.0-借贷广场-融资需求与代币质押/01-融资需求与代币质押-PRD.md)。办理从“融资”业务入口选定申请后进入本次办理；清单与详情只读，不提供办理或跨业务快捷入口。多个待办先明确对象，不能猜测“最新一笔”。无记录保留空态，读取失败可重试。融资办理保留“发布需求—机构报价—确认签署—融资放款”四阶段进度，分别识别已完成、当前和后续；已结束需求不标为进行中。接受办理的各步骤只是报价内的填写进度，不能替代项目融资进度。

<a id="d-cr-58"></a>`D-CR-58`
**D-CR-58 · 办理上下文。** 步骤、必要确认和放弃未保存修改都在本次办理内完成，不再叠加下一层办理。返回上一步保留输入和成功附件；有修改时关闭先确认放弃，无修改直接关闭。关闭后回到来源并保留原筛选、分页与所在位置。成功更新本笔与相关办理入口，不自动打开详情、下一笔或下一阶段；失败保留可复用内容，结果未知不假报成功。授信保存与报价提交的具体退出行为见下文。

个人/企业账户档案仅本人可查。业务需要的企业名称、编号、条款及适用账户自动取得：优先本笔已确认事实，其次同企业、用途和币种的有效登记资料；可编辑项仍校验，只读项不可改，逐笔确认不自动勾选。读取失败不伪装成未登记要求重填，不串企业、账户用途或历史文件；新授信协议、新合同不得默认套用他笔文件。

## 2. 先判断授信，再核定或追加

<a id="design-boundary"></a>
本册只定义信息需求与业务行为；页面布局、组件形态、层级与视觉由 Hallmark 设计决定。本册措辞与设计稿冲突时以设计稿为准，业务口径仍以本册为准。

流程见[授信与报价](02-授信报价与接受拒绝-流程图与状态机.md#fl-cr-01)，状态见[授信生命周期](02-授信报价与接受拒绝-流程图与状态机.md#st-cr-01)。授信是“一家资金方机构×一家资产方企业”的关系，跨该资产方所有项目共用，不按项目拆开。

### 2.2 核定和追加，提交即生效（F-LS-21）

验收：[核定与协议验收](#accept-credit)。

<a id="d-cr-11"></a>`D-CR-11` <a id="d-cr-15"></a>`D-CR-15` <a id="e-cr-01"></a>`E-CR-01`
机构自行决定授信，金额、日期、协议合格即生效，无审批。首次成功生成稳定授信编号，追加/重新核定保持同一关系和历次记录。成功即结束本次办理，提示“已授信，请继续报价”，授信摘要同步更新；须由用户再次发起报价才进入报价。授信本身不生成报价、不锁定需求；之后取消或报价失败也不回滚已生效授信及协议。

| 信息 | 必填、编辑和校验 |
| --- | --- |
| <a id="cr-03"></a>`CR-03` 授信对象 | 当前项目所属资产方，只读，不可另选；不能用代币买方、债务方或项目名替代 |
| <a id="cr-05"></a>`CR-05` 授信额度 | USD，必填且>0、最多两位小数；首次填总额，追加填正增加额，无默认金额。重新核定带出上一版额度，不得调低或低于已有已用额；无冻结/解冻 |
| <a id="cr-07"></a>`CR-07` 有效期至 | 按2.3规则填写；与报价有效期、最终还款日分别命名 |
| <a id="cr-12"></a>`CR-12` 备注 | 选填、最多200字、无默认值，仅本机构可见 |
| <a id="cr-14"></a>`CR-14` 本次授信协议 | **选填**，本次最多10份；每份≤10MB（含边界），PDF/JPG/JPEG/PNG，空文件无效。零份也可保存授信，不因此拦截报价 |
| 状态、首次核定时间、金额摘要 | 只读；首次核定时间不因追加被覆盖。展示授信占用额、在途报价金额、已用额及可用授信 |

<a id="d-cr-54"></a>`D-CR-54` <a id="c-f-ls-16"></a>
**识别授信对象所需资料。** 自动只读带入资产方法定名称、适用于本笔的已登记英文名、项目和融资申请编号；不自行翻译法定名。对方注册地区、登记号码、完整注册地址、个人证件与认证材料不在本步骤展示，也不提供完整档案入口。本笔付款所需名称/地址另按第4章权限使用。完整、暂未提供、加载中和读取失败分开表达，失败可重试；可选缺项不新增准入条件。名称缺失提示未提供，主体归属无法确认或无权时阻止提交，不让用户代填对方账户资料。

<a id="credit-files"></a>
<a id="d-cr-55"></a>`D-CR-55` <a id="d-cr-57"></a>`D-CR-57` <a id="c-f-ls-17"></a>
**协议与上传。** 10份是本次累计上限，不是每次选择上限，也不限制历次累计。选择前说明格式、大小和上限，已上传份数与上限（n/10）须可得；逐份给出名称、大小及当前状态。超额选择整批不加入，保留原列表并告知剩余名额；格式/大小不合格者不计数，其他成功文件保留。上传中可取消，未提交文件可移除重选、预览或下载；失败可重试或移除。有上传中或失败待处理的文件不能提交；处理完成后可以一份都不保留——协议为选填，零份同样能保存授信。不能把文件名当作上传完成。

校验和提交失败定位具体问题，保留金额、日期、备注及成功文件；提交中避免重复提交。文件操作不改变授信状态、额度或需求。当前过程保留内容，不承诺跨设备草稿；重新进入核对真实状态，丢失文件内容不能冒充已成功上传。

<a id="d-cr-56"></a>`D-CR-56`
本次协议随成功授信操作与金额、有效期、时间和机构对应留存，授信双方可查看/下载，其他企业与游客不可见。后续操作不覆盖历史，无删除已生效历史协议动作；存量缺协议显示“历史记录未提供协议”，不追溯补件或作废额度。每次新授信变更只保存本次实际上传的协议，不自动借用历史文件；本次未上传即该次无协议，不因此拦截后续报价。此处无盖章、一致性勾选、线上签署、合同生成或平台真伪/法律效力审核要求，不显示“协议已审核”。

### 2.3 有效期与到期（F-LS-22）

验收：[期限验收](#ac-cr-24)。

<a id="d-cr-19"></a>`D-CR-19` <a id="d-cr-20"></a>`D-CR-20`
首次、到期后正式重新核定：默认本次核定日+1年，最早+1年、最晚+5年，边界可选，越界拒绝并显示范围。普通追加可保持原日期或后延，不可提前、不强制延至追加日一年后；五年起点始终是首次或最近正式重新核定日，追加不重置，不开放提前重新核定入口。已到五年边界仍可只加金额；基点不可靠时不得猜测放行延期。

<a id="d-cr-62"></a>`D-CR-62`
核定日与范围按UTC业务日期；“有效期至”含当天，次日00:00 UTC进入已到期。加年取同月同日，目标年无该日取该月最后一日。正式重新核定建立新五年起点，原历史不变。授信只有“生效中/已到期”；到期只阻止新报价，既有在途、未偿本金和接受/放款/还款不受此到期阻断。项目到期不作废授信。

### 2.4 可用额度和再次校验（F-LS-23）

验收：[额度验收](#ac-cr-03)。

<a id="inv-cr-01"></a>`INV-CR-01` <a id="d-cr-17"></a>`D-CR-17`
授信占用额是本机构对该资产方的未偿本金；在途报价金额是尚未转成本金的报价；授信已用额为两者合计，不能再算作第四个占用量。可用授信显示为 `max(0, 授信额度−授信已用额)`。跨项目逐笔按各自锁定依据计量，必须满足 `授信占用额＋在途报价金额＋本次报价折USD金额 ≤ 授信额度`，不能扣减授信额度本身。

<a id="d-cr-21"></a>`D-CR-21` <a id="e-cr-02"></a>`E-CR-02` <a id="e-cr-11"></a>`E-CR-11` <a id="e-cr-12"></a>`E-CR-12`
再次点击立即报价和正式提交均重验授信、项目/需求状态及覆盖。其他项目占用导致不足时，重新显示金额、可用额、差额并进入追加，不重复增加上一笔额度；覆盖不足不能导向提额。若已用额已超过额度，停止该机构×企业全部新报价、形成既有运营待办，不自动改额度或抹金额。发现重复授信关系沿最早生效关系计量并交运营处理，不能把多条额度相加。每次变更可追溯由谁代表哪家企业、何时、因何项目改变了多少额度及有效期。

## 3. 提交报价，锁定需求与条款

前提：登录资金方不是该项目资产方；需求待报价且无在途融资业务；项目未到期；授信与当前覆盖同时通过。同一需求同刻只允许一家机构报价，先成功者锁定，不提供比价和部分融资。

### 3.1 报价表单与直接提交（F-LS-24）

验收：[报价提交验收](#ac-cr-11)。

仅保留识别申请、核对金额与必要授信摘要、本次输入和不可撤销后果所需信息；无完整授信/企业档案快捷入口，无报价时池快照。当前池况取L5。

| <a id="qt-02"></a>`QT-02` 结算币种 | 必选USD/USDT/USDC，无预设确认；机构独立选择，不受资产方参考币种限制，不改变USD记账 |
| <a id="qt-04"></a>`QT-04` <a id="qt-05"></a>`QT-05` 汇率与结算金额 | 选择币种后按3.2只读显示，不能手填汇率 |

| <a id="qt-12"></a>`QT-12` 报价有效期 | **本字段废止**（编号保留、不再采集）：报价有效期管控取消，报价提交后持续有效至资产方处理或所属需求终结，见[报价的持续有效与退出路径](#f-ls-34) |

<a id="d-cr-24"></a>`D-CR-24`
提交前可见“不可修改、不可撤回、锁定本轮需求、其他机构不能报价、机构在途增加金额、只能由资产方拒绝或所属需求终结才退出”的后果。提交即终检，不再二次确认；成功即结束本次办理并刷新原申请与相关办理入口，不自动打开详情。失败说明原因、保留可复用输入；项目已到期、需求已撤下或已被报价等状态变化明确显示，不用旧数值诱导继续提交。授信成功后报价失败仍保留授信，无新融资业务编号。

### 3.2 固定折算与逐笔快照（F-LS-26）

验收：[折算与快照验收](#accept-quote)。

折算与沿用见[流程图](02-授信报价与接受拒绝-流程图与状态机.md#fl-cr-04)。

<a id="d-fin-17"></a>`D-FIN-17`
本期仅USD、USDT、USDC，固定 **1 USD = 1 USDT = 1 USDC**，标明为本期平台业务规则，不是外部市场价格或兑换承诺。无人工改价、审核发布、行情获取和汇率过期流程；外部行情及其可用性不影响报价。

<a id="d-fin-80"></a>`D-FIN-80` <a id="d-fin-81"></a>`D-FIN-81`
报价成功锁定结算金额和本笔快照，由平台保留，之后不重算。须能追溯四要素：值为该币种对USD的1；真实规则生效时间；来源为平台固定折算规则；稳定版本标识。规则生效时间不同于本笔报价锁定时间，不能填虚构行情机构或刷新时间，不让用户补填。

<a id="d-fin-82"></a>`D-FIN-82`
例如100.25 USD融资，选择三种币种的结算数值均100.25、单位分别正确，不收折算差额，预览和最终条款一致。放款复用锁定本金金额；还款按本期应还本息和原快照折算，不能把融资本金当每期本息。相同原金额、相同标识重复引用得到相同值。每笔在途与未偿本金用自己的成功快照，不追溯改写旧业务，也不能将旧业务快照借给新报价。

<a id="d-cr-63"></a>`D-CR-63`

### 7.1 按用户决定保留的业务限制（供研发与测试知悉）

以下为用户 2026-09-24 明确裁定后的既定结果，如实记录其业务后果，不作为异议保留。

**本模块直接承担的限制：**

1. **报价一经提交，资金方无法撤回。** 报价有效期取消后，退出路径只有资产方拒绝，或所属需求因项目关闭/项目到期/覆盖不足而终结带来的连带失效。资金方提交即被锁定到资产方处理为止，平台不提供撤回、修改、催办或自动到期释放；若资产方长期不处理，该笔持续占用本机构在途报价金额，本轮需求也持续锁定。测试应按此预期设计用例，不将其判为缺陷。
2. **平台不再采集与校验收款人名称。** 法币与数币账户均取消收款人名称，[户名一致性硬校验](#respond-account)删除，受益人名称由业务双方在平台外补充；平台不再具备“收款账户必须属于本企业”的自动校验能力。账户选错或填错的后果由双方线下承担。
3. **待放款阶段没有终止出口。** 接受成功后，暂缓放款、要求重传与放款前终止全部取消，待放款的唯一出口是资金方提交放款；此后待放款确认同样没有时限，唯一出口是资产方确认到账。若线下协商结果是不放款，平台侧没有任何动作能终结该笔业务，本笔将持续停留在待放款，其机构在途与项目在途持续保留，资产方也无法另起一轮（本环节未结束不允许发布新需求），对应质押代币持续被占用。

<a id="accept-quality"></a>
### 8.6 共用质量与依赖边界

按[第7章](#dependencies)核验已定反馈时效、默认英文/中英切换、UTC与时区及币种口径；本模块不存在任何小时级时限，验收不得再引用168小时。连带失效的处理反馈延迟不能让已终结报价重新可接受；不得用旧覆盖值满足响应指标。状态、金额、主体和确认可追溯，无越权、重复编号/释放。[既定业务限制](#limits)三项按预期结果验证，不判为缺陷。

未决地区账户表、数币精度、真实业务资料、规则追溯及通知适配分别验证；账户字段按[企业账户](../v1.0-企业账户/01-企业账户-PRD.md)验证，本册只验本笔选用与逐笔确认。已有明确规则可先验，未就绪分支不能宣称通过。下游两维度转移与完整终结须联合验收，文档核对不等于产品实现通过。
