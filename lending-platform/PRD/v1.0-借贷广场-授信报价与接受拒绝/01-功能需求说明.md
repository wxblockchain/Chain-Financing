## 一、授信判定、核定、追加与有效期

关联 `F-LS-20`～`F-LS-23`。资金方从项目右侧“融资”操作区选择明确申请，点击“立即报价”后按当前授信资格进入授信或报价居中弹窗；清单及详情仅用于信息查看，无办理入口。仅登录资金方本企业员工可操作；无新增独立授信菜单。流程见 [FL-CR-01](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md#fl-cr-01)，状态见 [ST-CR-01](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md#st-cr-01)。

### 1.1 四分支与确认

| 进入时结果 | 用户先看到什么 | 确认后的行为 |
| --- | --- | --- |
| 无额度 | 尚未对本资产方核定授信，是否现在核定 | 新建模式，查看授信对象必要业务信息，填授信总额与有效期并上传授信协议 |
| 生效中但额度不足 | 本次报价金额、当前可用授信、差额，展示“本次报价 − 可用授信 ＝ 差额”；询问是否提额 | 追加模式，查看授信对象必要业务信息，填增加额并上传本次授信协议，展示当前额度与调整后额度 |
| 已到期 | 原到期日，询问是否重新核定 | 同一条授信关系重新核定，带出上一版额度供修改，重新填写有效期并上传本次授信协议 |
| 生效中且充足 | 直接进入报价表单 | 不出现授信确认或授信表单 |

`D-CR-46`～`D-CR-50`：前三支先在当前操作弹窗确认授信意图，再填写必要授信资料；同一操作内不叠层。取消关闭并回项目操作区，不自动打开申请详情。生效且充足直接打开报价弹窗；无额度、已到期和不足分别按本节处理。详情与办理的职责及关闭行为见 [L5 功能9.2](../v1.0-借贷广场-融资需求与代币质押/01-功能需求说明.md)。

`D-CR-49`：在授信意图步骤取消，关闭本次操作弹窗并回项目操作区，不生成授信记录、融资业务编号、任何金额计量变更或需求锁定，也不留下“曾取消”的业务记录；再次进入按当前事实重新判定。已成功核定授信之后放弃报价按 `D-CR-15` 处理，不能与确认前取消混同。

`D-CR-11`、`D-CR-15`：授信由资金方自行核定，金额、有效期及授信协议满足本节要求后提交即生效，无审批。保存成功关闭授信弹窗，toast提示“已授信，请继续报价”，刷新授信摘要与本申请的可办动作，不自动打开报价或详情。资金方再次点击“立即报价”才打开报价弹窗，并按 `AC-CR-04` 重验覆盖、项目/申请状态和授信；若因其他业务占用又不足，按当前事实提示差额并进入追加流程，不重复提交上一笔增加额。报价失败或放弃不回滚已生效授信；核定成功本身不产生报价或锁定。

### 1.2 授信业务输入与生命周期

`D-CR-10`：一对“资金方机构 × 资产方企业”只有一条授信关系，适用于该资产方全部项目，不能按项目拆开核定。首次核定生成稳定授信编号；追加、重新核定保留关系和历史。状态只有 `S-CR-1 生效中`、`S-CR-2 已到期`。

| 业务输入 / 展示 | 含义、必填、编辑与校验 |
| --- | --- |
| 授信对象（`CR-03`） | 由进入的项目带出资产方企业，只读且不可另选；资金方为当前企业 |
| 授信额度（`CR-05`） | 必填金额，USD，>0，最多两位小数。首次核定填总额；追加填增加额，必须>0；只允许增加，不提供调低、冻结、解冻。重新核定带出上一版额度，仍遵守不调低及不得低于已有授信已用额的要求 |
| 有效期至（`CR-07`） | 日期。首次及到期重新核定必填，默认核定日+1年；最早核定日+1年、最晚核定日+5年，越界拒绝且告知可选范围，无绕过。重新核定按本次核定日重算范围 |
| 追加时有效期 | 可选修改，不改保持原值；只能保持或后延，不能提前；五年上限从首次核定或最近一次正式重新核定的UTC日期起算，普通追加不重置起点；追加不强制延至一年以后（`D-CR-20`） |
| 备注（`CR-12`） | 选填文本，最多200字，仅本机构可见；无默认内容 |
| 授信协议附件（`CR-14`） | 首次、追加、重新核定均必填；本次提交1～10份，单份≤10MB，PDF/JPG/PNG。首次无默认文件；历史协议只读展示，不默认计入本次。完整交互与历史归属见1.4～1.5 |
| 授信状态与首次核定时间 | 只读。追加不覆盖首次核定时间；核定、追加、重新核定、到期的历史均可追溯 |
| 三项金额与可用授信 | `授信占用额`、`在途报价金额`、两者合计的`授信已用额`，以及当前可用授信。不可编辑，不把授信已用额再作为第四个独立占用量 |

基线未规定首次额度、增加额的默认数值，须由机构明确提交金额。`D-CR-20`、`Q-CR-07`按P06收口：五年起点为首次或最近一次正式重新核定日，不是本次追加日。有效期已在该五年边界时仍可仅增加金额，不能通过追加延期超过边界；追加不新增提前重新核定入口。核定基点无法可靠取得时，不能猜测放行延期，保留可查现状并提示核实。

`D-CR-62`（P10，参照L5 `D-LS-65`）：核定日及有效期范围按UTC业务日期判断；“有效期至”包含所选UTC日期，进入次日00:00 UTC后为已到期。按年加至同月同日，遇目标年无该日取该月最后一日；日期范围和到期时点应让用户可核对。正式重新核定以本次UTC核定日建立新五年起点，原历史不改写。项目最终还款日直接继承L5的UTC项目截止日期，不按查看者当地日期另生日期。业务时刻按用户偏好时区展示并标注，游客按浏览器时区并标注；日期字段明确UTC业务日期。报价期限仍是成功时刻后连续168小时，不按自然日末延长，跨时区、夏令时与切换语言均不改变截止。

`D-CR-13`、`D-CR-14`、`D-CR-42`、`D-CR-43`：授信到期只停止新增报价，既有在途报价与未偿本金按各自生命周期继续存在，不随到期归零；到期后新增报价先重新核定。项目到期不作废授信；授信到期不阻断既有报价的接受、放款与还款。页面提示授信步骤不触链、不产生 gas。

### 1.3 授信校验与异常

`AC-CR-03`：`授信占用额 + 在途报价金额 + 本次报价金额（折 USD） ≤ 授信额度`，全部按同一机构与资产方、跨项目合并。既有各笔按自己的锁定汇率计量。`授信已用额 = 授信占用额 + 在途报价金额`；可用授信显示为 `max(0, 授信额度 − 授信已用额)`。额度不足须在报价填写前给出本次金额、可用授信、差额与提额出路（`AC-CR-06`），不能仅说“额度不足”。

`INV-CR-01`：授信占用额与在途报价金额之和不得超过授信额度；报价只改变对应金额，不扣减授信额度本身（`D-CR-17`）。覆盖与授信是两道独立条件，同时通过才能报价（`D-CR-21`、`AC-CR-22`、L5 `AC-FIN-07`）。覆盖判断依据见[功能二](#quote)，不把覆盖不足导向授信追加。

| 异常编号 | 用户结果与处理 |
| --- | --- |
| `E-CR-01` | 授信成功但报价失败：保留授信，给出报价失败原因，无新融资业务编号；仍可报价时留在表单，状态已变则在当前操作区说明最新结果，不自动打开详情 |
| `E-CR-02` | 核定后因其他项目报价使可用授信减少：回追加模式，显示最新三个数，两道条件再次满足后方可报价 |
| `E-CR-11` | 授信已用额超过额度：停止该二元组一切新增报价，生成运营待办；不自动改额度、不自动抹掉既有金额 |
| `E-CR-12` | 发现重复授信关系：沿用基线，按最早生效关系计算并告知运营处理，不把多条额度相加放大可用授信 |

`D-CR-22`、`D-CR-23`：资产方可在只读授信视图查看各机构对本企业的当前额度与已用额；机构不可看到其他机构的授信。每次变更须可还原由谁代表哪家企业、何时、因哪个项目改变了多少额度及有效期；内部备注不对资产方披露。

### 1.4 授信对象必要业务信息与协议

`D-CR-54`（`F-LS-20`/`21`，`C-F-LS-16`，P01）：授信办理自动带出当前项目所属资产方企业，供机构确认本次业务对象，不开放对方个人或企业账户档案。原“企业基本信息”需求按本节收紧，信息范围如下：

| 信息 | 业务用途与可见边界 |
| --- | --- |
| 资产方企业法定名称 | 识别授信对象及合同当事方，自动只读带入；与项目归属一致，不能拿代币买方、债务方或项目名替代。已有且适用于本笔的登记英文名可展示，不自行翻译成法定名 |
| 当前项目与融资申请编号 | 确认此次授信的办理上下文，自动取得；授信关系仍跨项目共用，不因显示当前项目变成项目独享额度 |
| 当前机构对该企业的授信信息 | 按1.2展示必要额度、有效期与本次操作信息，仅对应授信双方有权查看；备注仅机构本方可见 |
| 企业注册地区、登记号码、完整注册地址；个人姓名、证件、联系方式及认证材料 | 属于个人/企业账户档案，本步骤无独立业务用途，不向对方资金方展示，也不提供完整档案入口。本人资料查看归账户模块；不能因曾出现在旧卡片而继续公开 |
| 本笔收款人名称、地址及账户资料 | 属于接受/后续付款所必需的交易资料，按3.2与当事方权限展示；不据此开放企业账户档案或将其他用途的账户资料作为授信必填 |

已知且有权用于本笔的业务信息自动获取，不让用户抄写或补填对方账户资料。完整、未提供、加载中、读取失败分别表达，失败可重试，不以演示值、零值或猜测补齐。可选信息缺失不新增授信准入条件；主体归属无法可靠确认或无操作权时阻止提交并说明。名称暂缺显示“企业名称暂未提供”，不借此伪造对象。`DEP-27`只待核验真实业务资料供给，不再把他方档案展示范围列为待开放权限。



`D-CR-55`（`F-LS-21`/`22`，`CR-14`、`C-F-LS-17`）：授信首次核定、追加、到期重新核定，由资金方上传适用于本次操作的授信协议。至少1份、最多10份，**每份不超过10MB（含边界）**；10份是本次提交合计上限，不是每次选择的上限，也不限制同一授信关系历次累计文件数。格式复用本模块既有附件能力PDF/JPG/PNG（含JPEG）；空文件不可计为有效附件。这里收取授信协议，不新增盖章、双方线上签署、一致性勾选、平台合同生成或审批要求；平台不审核协议真伪、法律效力或条款是否足以覆盖本次额度和期限，不显示“协议已审核”。

`D-CR-56`：协议随本次成功的授信操作保留，能在授信详情与历史中与本次金额、有效期、操作时间和操作机构对应查看/下载；后续追加、重新核定不替换旧文件或改写历史。继承对应授信记录的双方企业可见范围（`D-CR-22`/`23`），仅本机构与被授信资产方可见，其他机构、其他资产方及游客不可见；内部备注仍仅本机构可见。已有授信没有历史协议时显示“历史记录未提供协议”，不追溯补件、不作废额度；新发生的核定/追加/重新核定按本次附件要求办理。授信成功后取消报价，额度、有效期与本次协议均保留；后续直接报价不要求再次上传授信协议。每次新的授信变更需明确上传本次适用协议，不自动把历史文件当作新提交。

### 1.5 授信表单与上传交互

`D-CR-57`（`F-LS-21`/`22`）：授信办理显示授信对象、当前模式、额度与差额、有效期及本次协议等必要信息。已有且有权用于本笔的企业业务信息自动只读带入，不让资金方替对方重复填写；完整历史不通过本流程的快捷入口展开。追加保持原有效期并可按已定范围后延；到期重新核定带出上一版额度供确认，按核定规则填写新有效期。授信有效期、报价168小时有效期与最终还款日分别命名。本次不新增授信利率或还款方式字段，布局由设计决定。

| 环节 | 必须成立的用户结果 |
| --- | --- |
| 选择文件前 | 明确必填、支持格式、单份大小、最多10份；显示“已上传n/10”。不能把接受报价环节的“签署盖章件”标签用在此处 |
| 上传中 / 已上传 | 每份显示文件名、大小与文字状态；上传完成才计入可提交的有效文件。上传中可取消该文件，已上传但尚未提交可移除后重选；预览或下载能识别所选文件 |
| 格式、大小或数量不符 | 就地指出具体文件与原因。已选加本次选择超过10份时拒绝本次新选择、保留原列表，并告知剩余名额；不得默默丢弃超额项或覆盖已有文件。格式/大小不符的文件不计入有效份数，保留其他成功文件 |
| 部分失败 | 每份给出重试或移除入口，失败不清空成功文件、金额、日期和备注。存在上传中或失败待处理文件时不可提交；全部处理后还须至少1份成功文件；不能将文件名列表视为上传完成 |
| 核定前校验 / 提交失败 | 金额、有效期和附件问题就地可见，定位首个需处理项；保留本次已填写内容和成功附件，可修改后重试；失败不产生新授信变更、报价或锁定。提交中标明处理中并避免重复提交 |
| 取消 / 返回 | 尚未提交有修改时，在本次操作弹窗确认放弃；取消放弃继续编辑，确认放弃关闭回项目操作区，不打开申请详情、不生成授信变更。未编辑直接关闭，成功保存后关闭不撤销授信 |
| 提交成功 | 关闭授信弹窗并toast“已授信，请继续报价”；不自动报价、不自动开报价或详情。重新点击立即报价才重新校验并进入相应步骤；本次已生效授信和协议保留，后续失败或放弃不回滚 |

文件状态只是当前操作进度，不新增“待附件审核”授信状态，不锁定融资需求，不改变额度。文件移除仅作用于未提交的本次列表，不提供删除已经生效授信历史协议的动作。表单失败后的保留适用于当前办理过程，不承诺跨设备草稿；重新进入须重新核对业务状态，不能把丢失的文件内容显示为已上传成功。

## 二、报价、汇率、锁定与七天有效期

关联 `F-LS-24`～`F-LS-26`、`F-LS-31`、`F-LS-34`、`F-LS-36`。流程见 [FL-CR-01](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md#fl-cr-01)、[FL-CR-04](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md#fl-cr-04)。

### 2.1 入口、业务输入与提交

资金方登录且不是本项目资产方；需求处于 L5 下发的“待报价”、无在途融资业务、项目未到期、覆盖条件通过，方可提交新报价。一个需求同一时刻只有一家机构报价，先成功者锁定需求；不提供多家比价或部分融资。授信不足不把报价按钮永久禁用，而是在当前操作弹窗进入功能一。

`P-LS-05` 报价只呈现当前申请识别信息、需求金额、本机构必要授信摘要及本次报价输入，不提供查看企业完整资料或授信详情/历史的快捷入口。需求金额、企业、只读还款类型及最终还款日自动带入，不重复填写。可用授信、不足差额及报价后余量用于本次决策；既有总授信/已用/有效期仅在与当前操作有关时展示。完整私有业务资料仍按既有入口和权限查询；对方个人/企业账户档案不因交易关系开放。当前池况沿用L5，不恢复常驻融资上限等中间量或报价时池快照。

| 业务输入 / 展示 | 含义、必填、默认与校验 |
| --- | --- |
| 融资金额（`QT-03`） | 只读，等于本轮需求金额，USD；明确“不支持部分融资，金额不可修改” |
| 结算币种（`QT-02`） | 必选 `USD` / `USDT` / `USDC`，由资金方独立确定，不受L5参考结算币种限制，不因资产方偏好而自动确认；只决定结算币种，不改变 USD 记账；基线未指定默认选中项，不预设某币种为已确认选择 |
| 汇率与结算金额（`QT-04`/`QT-05`） | 只读，选择币种后显示“1 USD = 1 USDT = 1 USDC（本期平台固定折算规则）”及本币种结算金额；提交成功锁定本笔依据与金额。不是市场实时报价，机构不能编辑 |
| 融资利率（`QT-06`） | 必填年化百分比，`0 < 利率 ≤ 100`，最多两位小数，无默认报价；单复利、计息基数、起息日由还款模块承接，本模块不另定。表单提示“计息规则以双方签署的融资合同为准” |
| 还款类型（`QT-15`） | 业务枚举本期只有“按季付息；到期还本付息”，只读，无选择器；进入商务条款摘要（`D-CR-51`） |
| 最终还款日（`QT-16`） | 日期，只读，恒等于 L5 项目截止日；本期不能修改。跟随项目截止日，不建立独立业务维护入口（`D-CR-52`/`D-CR-53`） |
| 报价有效期与到期时刻（`QT-12`） | 只读168小时，从实际提交成功时起算；提交前的预计到期提示不能当作已经锁定的起点 |

`QT-07`/`QT-08` 保持作废：报价不采集、不展示、不校验资金方收还款账户；基线分册表单中的“还款账户”删除，以主册撤出裁定为准。不能因缺少该账户阻断报价或接受。

`AC-CR-11`、`D-CR-24`：报价不设第二次确认步骤。提交按钮前可见不可修改/撤回、锁定需求、其他机构不能报价、本机构增加的USD在途报价金额及168小时未处理失效释放等必要后果；点击提交即校验并提交，不再弹确认框。报价成功直接关闭报价弹窗、提示成功并刷新原申请及操作区，不自动打开融资申请详情。失败保留已填信息并说明原因；结果未知不得假报成功。该取消二次确认仅针对资金方提交报价，资产方接受报价的账户确认、摘要、盖章件和声明仍按功能三执行。

`D-FIN-79`：提交成功同一事件内生成稳定融资业务编号、锁定汇率、开始计时、增加本机构的在途报价金额、业务进入 `S-FD-1 待接受`，向 L5 提供锁定结果；`项目在途金额` 不变。失败不预占编号、不产生新在途报价金额、不锁定需求。覆盖不足被证实的情形还要按2.3使原需求失效，不能误读为“任何失败都不改变需求”。

### 2.2 本期固定折算与可追溯结果

`D-FIN-17`（P05）：本期仅支持USD、USDT、USDC，平台固定**1 USD = 1 USDT = 1 USDC**。不设置维护角色、人工改价、复核发布、行情更新或汇率过期规则，不取代币发行平台或其他外部行情。资金方只选择结算币种，不能手填汇率。固定值是本期业务约定，不保证外部市场价格或兑换结果。

`D-FIN-80`、`D-FIN-81`：报价成功时锁定该笔快照及结算金额，由本平台自持，之后不重算。仍需可追溯**汇率值、生效时间、来源说明、版本标识**：值为该币种对USD的1，来源说明为本期平台固定折算规则，生效时间和版本标识指向本笔采用的真实规则版本，不使用虚构行情机构或刷新时间。快照锁定时间为报价成功时间，不能混同规则生效时间。具体标识取正式业务登记，不要求用户或机构录入；未能形成完整依据按 `E-CR-18` 处理。

`D-FIN-82`：需求与额度按USD计量，本期结算金额数值与融资USD金额相同、单位为所选币种。例如融资100.25 USD，对应100.25 USD、USDT或USDC中的所选币种，不收折算差额。预览、最终条款与成功锁定金额一致，不能静默改成其他值。报价成功后放款复用本笔锁定的结算金额；还款按已定应还本息与本笔快照折算，不把本金金额当作每期本息金额。同一原金额、同一标识反复引用结果相同。

既有每笔在途报价和每笔未偿本金仍各用其成功时锁定的快照；本次固定规则不回写或追溯重算旧业务，也不能把旧业务快照借给新报价。重新报价是新编号、新锁定及新168小时期限，按本期固定规则形成自己的完整依据；已拒绝/失效报价只保留历史，不恢复为可放款业务。

`D-CR-63`（P10）：金额精度与汇率分别判断。下表是L6向放款/还款交接的统一业务口径，不能以原型显示位数代替结算规则：

| 对象 | 当前已确认的精度与使用方式 | 剩余边界 |
| --- | --- | --- |
| USD授信、需求与融资金额 | 输入最多两位小数；金额带币种，USD展示两位。额度计算不提前舍入，报价金额等于本轮需求金额 | 不新增机构可改融资金额或人为尾差 |
| USD每期利息 | 沿L8功能3.2：每期独立两位、四舍五入，利息尾差不跨期结转 | L6仅引用，预计/定稿计划由L8负责，不在本模块重新定义计息 |
| USD结算本金 | 固化报价的两位金额，后续放款同源复用 | 手续费不冲减约定本金 |
| USDT/USDC结算金额 | 固定1:1下报价金额数值已确定；锁定后放款复用，不能因展示截断改付款数。不得统一套用代币展示“六位”或原型“两位”作为币种结算上限 | 允许最大小数位、最终舍入和尾差仍需同一批准表，见Q-CR-09；正式数币结算边界验收在该表闭合前不能判通过 |

`E-CR-18`：若本笔固定折算依据缺失/不完整或实际结果不是本期1:1，拒绝新报价，提示“暂时无法确认本笔折算依据，请稍后重试”；无新编号、无新增在途金额、无需求锁定。不回退旧业务快照或外部行情，不让机构补填汇率。若当前覆盖事实无法取得，提示“暂时无法完成覆盖校验”，不把未知当覆盖不足而失效需求。固定规则没有日常行情取数依赖，外部行情不可用本身不能阻断报价；已锁定业务的完整原快照不因新报价依据暂不可用而改变。

Q-CR-10所指人工维护与生效治理问题按P05关闭；四要素留痕是已有交易可追溯要求，不恢复汇率维护功能。验收见[验收二](02-验收需求说明.md#quote)。

### 2.3 覆盖终检与并发

`AC-CR-20`～`AC-CR-22`、`D-CR-35`～`D-CR-39`、`D-CR-44`/`D-CR-45`：提交时按当前权威事实重算并执行 [L5 `AC-FIN-26` 与 `INV-FIN-01`](../v1.0-借贷广场-融资需求与代币质押/v1.0-借贷广场-融资需求与代币质押-PRD.md)。沿用 L5 的已乘质押率口径、逐笔累计口径、失效顺序与停止条件，不按原始池值、不省略更早已保留需求项、不用进入页面时的旧数值放行。本期报价承接已发布需求，不重复增加项目在途金额（L5 `AC-FIN-23`）。

失效判据成立时，需求当场失效，本次报价不成立；已有待接受报价同一事件内按功能四终结。提示“该融资需求已失效（池内覆盖不足）”，说明资产方补足覆盖并重新发布后可再次报价，不归咎提交机构。覆盖不足提醒不是失效的前置步骤，没有补足缓冲期。

`E-CR-03`/`AC-CR-13`：两机构同时报价只允许一笔成功；另一笔提示已被报价，无融资编号和新增在途报价金额。`E-CR-04`：若提交时项目已到期、需求已撤下或状态已变，拒绝并展示最新状态与原因，不能保留旧数值诱导继续提交。任何写操作均按当前身份、权限与事实判定，页面按钮不能替代判定。

### 2.4 锁定展示与七天有效期

`D-CR-25`～`D-CR-29`：有效期从平台确认报价成功的时刻起整168小时，精确到秒，不按第七天日末取整，也不从资产方查看或通知到达起算。无延长、续期、宽限。只在 `S-FD-1` 有效，接受或拒绝成功后停止计时；后续待放款等环节不受该七天时限约束。

`D-LS-20`/`D-LS-21`：项目列表与融资申请清单按L5保留对应摘要；机构全称、锁定起始时间、已锁定时长、剩余有效期与到期时刻在申请详情及对应资产方控制台详情查看，不在项目列表堆叠全部锁定说明。剩余时间通常到小时，不足24小时到分钟并加强提示；时间显式标注时区。锁定信息公开且中性，不贴恶意标签。资产方明确可随时拒绝，或届满自动失效。接受后不再继续显示“等待接受”的倒计时。

无人登录也须届满自动转 `S-FD-11 报价已失效`，与机构在途报价金额全额释放及向 L5 反馈需求解锁同一事件生效；仍有效需求回待报价，项目在途金额不变、质押不释放。处理延迟不延长报价效力，到期后接受不可用。具体并发与两类失效见功能四。

## 三、报价确认：账户、合同、接受与拒绝

关联 `F-LS-28`～`F-LS-30`。`P-LS-06` 由本企业资产方从右侧“融资”操作区选定目标申请后进入居中办理弹窗。只处理仍待接受且未届满的本企业报价。流程见 [FL-CR-02](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md#fl-cr-02)。

### 3.1 判断依据与三步进度

先展示报价机构业务名称及本笔允许公开的认证状态，不展开机构账户档案或认证材料；同时展示、融资业务编号、融资申请编号、金额与利率、结算币种与金额、锁定汇率、还款类型、最终还款日、报价时间和剩余有效期，以及 L5 当前池况与质押覆盖状态；不展示机构收还款账户、不恢复报价时池快照、不扩写 L5 详情页中间量。

`D-CR-60`：报价详情和报价确认接受视图提供预计还款计划原位展开，收起后保留原报价/原接受步骤，保留输入和文件。计划由 [L8 功能3.2](../v1.0-借贷广场-还款计划与还款确认/l8-repayment-prd.md#f-plan) 提供：报价提交日作预计放款日，整表标“预计 · 未生效”，日期标“预计还款日”，不产生有效期次或 RP 编号。接受前常驻告知放款确认后按实际放款日重算并记录告知展示时间，不新增勾选；预计计划可按需展开，但重算告知不能依赖展开才可见。已拒绝、已失效报价的预计内容只随对应历史只读，不成为当前应还或定稿计划；完整定稿计划到还款信息查看。本模块不另定计息和期次规则。

接受三步依次为：填写并确认收款账户 → 查看可复制/打印的商务条款摘要 → 上传线下签署盖章件并勾选条款一致性声明。中断后保留已确认账户和已完成进度，返回可续做，但七天计时不暂停，进度区常驻倒计时（`AC-LS-102`）。三步均属于待接受内的填写进度，不能新增业务状态（`D-FIN-77`）；仅最后“确认接受”成功才进入待放款。

### 3.2 资产方收款账户

本节确认的是资产方用于接收本笔放款的账户，接受成功后由L7按本笔承接；不是资产方后续还款的出账账户。资金方收还款账户由L7放款环节确定、L8承接。本轮不新增两类独立出账账户字段，不默认任何一方出账账户与收款账户相同；清单拆分不扩大完整账户、地址或附件的可见权限。

`D-FIN-94`/`D-FIN-95`：优先恢复本笔已经填写/确认的账户，其次自动填充本企业最近一次成功接受所用、用途和币种适用的账户；首次已有本企业有效登记收款资料也直接带入，仅无可用资料的必填项为空。允许编辑的字段可逐项修改并重新校验；本次成功接受的账户成为后续预填依据。已知业务必需信息直接带入，读取失败与真正未登记分开提示；不得把读取失败变成用户重复填写已知资料的任务。每笔必须显式确认，默认不勾选；确认针对本次所填内容，修改后不能沿用对旧内容的确认。无账户簿、多账户列表、“设为默认”或独立账户管理入口。

USD 结算使用法币账户，USDT/USDC 使用企业统一数币地址；账户须与结算币种匹配。`D-FIN-85`：数币地址只读，来自企业已登记收款用途的统一数币地址，不接受人工指定；代币当前链上持有地址属于L5资产事实，不能用质押后持有位置替换收款地址；地址为空不能确认接受，并引导完成企业地址登记。链按基线 WS-326 `D-LN-60` 固定ETH，只展示、无选择器；本模块不办理链上转账。

`D-FIN-96`～`D-FIN-101`：以下为接受表单业务要求，不是接口字段清单。法币前七项必填、可编辑，均无虚构默认数据；第八组为选填。

| 表单项 | 内容与校验 |
| --- | --- |
| 收款人名称 | 企业户名，须与本企业法定名称或已登记英文名/曾用名一致；比对忽略大小写、空格、常见公司后缀标点与缩写差异 |
| 收款人地址 | 国家/地区、城市和详址，不能缺失 |
| 收款账号 / IBAN | 单项文本，按收款行所在地填账号或IBAN；校验长度与字符格式，不判断账户真实性；具体格式范围未在基线给出，见待承接细项 |
| 收款行名称 | 银行名称，必填文本 |
| 收款行地址 | 至少有城市与国家/地区 |
| SWIFT / BIC | 8位或11位字母数字，格式不符拒绝 |
| 收款行所在国家 / 地区 | 必选地区；与SWIFT国家段不一致时提示但不阻断 |
| 中转行 / 代理行信息 | SWIFT、名称、在中转行账号，整组选填；默认折叠，标注“选填”。说明“若开户行需要通过中转行接收外币汇款，请填写；不确定时请咨询开户行” |

`D-FIN-98`：平台只做规定的格式与户名一致性检查，不核验银行账户真实性、不做银企联验、不判断汇路可达性、不判断是否需要中转行；能力边界须让用户可见，不能显示“账户已验证”。中转行有误本模块不自作真实性判断，相关汇款失败归放款环节。

`E-CR-20`/`E-CR-21`：户名不一致时拒绝且无绕过，显示填写户名与本企业已登记名称两组值，给主体资料补登英文名入口；没有登记英文名时不得猜测对应关系。关联公司名称不是本企业名称。账户为空、币种不匹配与户名不符的反馈应可区分。主体资料能力未就绪会阻断此类接受，不能放松校验掩盖依赖。

`D-FIN-98`的可见范围：普通列表、摘要按既有掩码显示账户；资产方在本笔接受确认时可核对自己的完整收款资料，报价已接受后，已确认的付款当事方在办理本笔放款时按权限核对完整收款账户（L7承接）。非当事方不可读取；不能因摘要脱敏而让有权付款方无法完成付款。银行账户、企业统一数币地址均不成为公开信息。地区账号/IBAN及中转行校验表仍待Q-CR-08补齐，不用统一猜测长度代替。

### 3.3 手续费、摘要与盖章件

`D-FIN-102`～`D-FIN-105`：跨境汇出、中转、入账手续费由资产方承担，到账金额会少于融资金额；债务本金与额度计量仍按融资金额。必须在确认接受前清楚、不折叠地告知“跨境手续费由您承担；到账金额会少于融资金额，但偿还本金仍按融资金额{X} USD计算”。告知写进摘要并可追溯展示时间，只做告知，不额外增加手续费确认勾选。平台不预知、代收或垫付，不展示预估手续费，本模块不采集实收金额。

`D-FIN-86`～`D-FIN-88`：合同由双方线下拟定与签署，本平台不生成合同、不提供合同模板下载、不依赖模板配置才允许接受。摘要可复制、打印，明确“本摘要不是合同，不产生法律效力”。摘要包含：融资业务编号、融资申请编号、融资项目编号、双方企业全称、融资金额USD、结算币种与金额、完整汇率快照及生效时间与来源、年化利率、当前抵押物概况、报价时间、还款类型、最终还款日以及手续费与本金告知。数字必须与本笔业务一致，不沿用旧“九项”数量限制漏掉新增内容。

`D-FIN-93`：此处为资产方接受本笔融资报价的融资合同签署盖章件，独立于资金方在授信时上传的协议（`CR-14`），不以授信协议抵替，不共享份数。接受前须上传至少1个线下签署盖章件，PDF/JPG/PNG、单文件≤10MB、最多5个；条款一致性声明默认不勾选，须确认“我确认所上传合同的商务条款与本页摘要一致”。缺少文件、未查看摘要或未确认声明均不可接受。文件失败就地说明格式、大小、数量或上传失败原因，保留其他成功文件（`E-CR-09`）。

`D-FIN-89`～`D-FIN-91`：平台只收取文件并检查格式、大小和数量，不审核真伪及法律效力，界面明确该边界。资金方在放款前核验，有问题时的暂不放款、要求重传或终止由放款模块承接；本模块无“待审核”中间态。盖章件仅向业务相关主体开放，不属于广场公开附件。

## 四、额度保持释放与需求失效联动

关联 `F-LS-27`、`F-LS-35`；流程见 [FL-CR-03](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md#fl-cr-03)，状态见 [ST-CR-02](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md#st-cr-02)。项目额度定义只引用 [L5 主册5.5](../v1.0-借贷广场-融资需求与代币质押/v1.0-借贷广场-融资需求与代币质押-PRD.md)，本节列事件结果，不重建额度模型。

### 4.1 事件责任与金额结果

`D-CR-16`～`D-CR-18`：报价产生在途报价金额，不产生授信占用额。在途报价金额包含待接受、待放款、待放款确认与放款异议处理中（`S-FD-1`/`3`/`4`/`5`）；放款确认前不能提前移出。已放款未偿本金计入授信占用额，逾期是并行标记，不因标记释放本金。

| 事件 | 机构维度结果 | 项目维度与业务结果 | 执行归属 |
| --- | --- | --- | --- |
| 成功报价 | 在途报价金额增加本次全额 | 项目在途金额不变；业务待接受，项目锁定 | L6报价，L5项目事实 |
| 接受 | 在途报价金额保持，不进授信占用额 | 项目在途金额保持；待放款 | L6接受，L5项目事实 |
| 拒绝 | 本笔在途报价金额全额释放，不进授信占用额 | 已拒绝；有效需求回待报价，项目在途金额不变、质押不释放 | L6拒绝，L5解锁 |
| 七天届满 | 同拒绝 | 报价已失效，原因“有效期届满”；有效需求回待报价，项目在途金额不变、质押不释放 | L6自动失效，L5解锁 |
| 需求因覆盖不足失效 | 其待接受报价在途报价金额全额释放 | 同一事件中报价已失效，原因“所属融资需求失效”；L5释放该需求的项目在途金额并提供终结原因 | L5判需求结果；**L6执行报价状态流转** |
| 放款确认完成 | 全额由在途报价金额转授信占用额 | 同笔全额由项目在途金额转项目融资余额，两维度在同一事件原子转移，无空档或双计 | 放款模块，承接 `AC-FIN-27` 与L5 `AC-FIN-25` |
| 放款异议裁决终止 | 尚在途则全额移出本笔在途报价金额，不进入授信占用额，不清除其他业务 | 项目侧引用L5 D-LS-64与放款模块；到期项目不恢复新融资，未到期按当前全部存量及覆盖判断，不自动回募集中或释放整池 | 放款/运营裁决，`AC-FIN-28` |
| 已放款业务裁决终止 | 按裁决终止规则释放本笔剩余未偿本金 | 与项目侧结果同源一致 | 后续模块承接基线终止路径 |
| 还款经机构确认 | 授信占用额按已偿本金逐期递减；结清时本笔剩余本金归零 | 项目融资余额按相同本金变化 | 还款模块 |

`AC-CR-09`：拒绝、报价超时、需求失效（含报价终检发现）、裁决终止、结清五条终结路径全部完成后，**该笔贡献的授信占用额与在途报价金额双双归零**。测试二元组无其他业务时，二元组两个合计量也均归零、可用授信恢复；有其他存量业务时不得误清其他业务金额。

明确不释放：授信额度到期、项目到期但存量业务仍处理、资产方接受、放款异议驳回后回待放款、逾期标记。需求已锁定时资产方不能主动撤下，项目尚有在途/未结清业务也不能通过主动关闭绕开释放条件。项目到期后的重新报价还须满足L5未到期条件，不能把“解锁”解释为允许到期项目重新报价。单笔终止后L6只消费L5 `D-LS-64` 的项目资格结果，不另算一套恢复规则。

### 4.2 需求失效与到期并发

`D-CR-30`/`D-CR-31`：消费 L5 `D-FIN-75` 的需求失效结论时，本模块使仍待接受报价落 `S-FD-11`，机构在途报价金额全额释放；与L5需求终结和项目在途金额释放**同一事件完成**。不得出现“需求已失效，报价还可接受”或“报价已失效，额度未回”的业务中间态。

`D-CR-32`、`D-FIN-92`：系统失效不同于资产方拒绝，不要求填拒绝原因、不计入拒绝率、不给机构负面记录。失效原因只有“有效期届满”与“所属融资需求失效”；前者时间取原到期时刻，后者取需求实际失效事件时刻，不能把尚未到期的需求失效记录到未来。历史报价与编号保留，不能消失。

`D-CR-38`～`D-CR-40`：没有覆盖不足缓冲期；只有报价168小时倒计时。追加质押不能恢复已经失效的报价，需按L5补足覆盖后重新发布，再以新业务重新报价。失效粒度、顺序、停止条件由L5决定，本册不重写。

`E-CR-13`～`E-CR-15`：同笔接受、拒绝与系统失效只允许一个最终结果，平台确认时刻裁定，但必须首先满足未届满条件；在到期时刻及之后不得接受，即使失效处理有延迟。到期前接受成功则不再受报价时限影响。重复触发失效不重复释放、不重复通知；一次事件的金额与状态结果整体一致，不能展示半完成结果。处理异常也不能恢复接受入口或把历史到期时刻往后移动。

`D-FIN-78`：拒绝与报价失效均为融资业务终态，原编号保留不回收。需求仍有效、项目未到期且重新满足报价条件时，任何机构包括原机构均可立即重报，无冷却和次数上限；新编号、新汇率快照、新168小时期限，不是续期。

## 五、页面增量、跳转与通知

关联 `F-LS-31`～`F-LS-33`。业务图见 [ST-CR-03](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md#st-cr-03)。只补L5页面增量，不重写列表、统计区或质押清单。

### 5.1 页面与对外状态

`D-CR-59`（`F-LS-32`）：申请清单与申请详情的结构、粒度和账户边界唯一来源为 [L5 功能9.2、11.7](../v1.0-借贷广场-融资需求与代币质押/01-功能需求说明.md)。本模块在其中承接报价内容：一轮申请沿用 `FP-28`，显示名称“融资申请编号”；不是新增编号或审核对象。一个申请可先后有多笔 `FD-01` 报价，成功报价才产生融资业务编号，拒绝或失效后仍保留；不能用最后一次报价覆盖此前业务。

申请详情按“金额与状态 → 融资申请资料 → 当前有效或已接受报价及授信摘要 → 默认折叠的报价历史记录 → 协议信息表”阅读。当前报价展示机构、报价金额与币种、利率、还款类型、最终还款日、报价状态及适用倒计时；长条款可在当前报价内展开。无当前有效或已接受报价时明确显示暂无当前报价，不拿最近已拒绝/失效报价充当当前报价。

授信摘要仅向有权用户显示当前报价机构对本企业的总授信与已用授信，跨项目合计且含在途报价与未偿本金，不是本申请独享额度或报价历史数值。申请详情只保留核心摘要，不提供“查看授信”、企业完整档案、授信历史/协议快捷入口；完整授信业务资料按既有有权只读入口查询；该入口不开放对方个人/企业账户档案。机构只见本机构授信，资产方仅见对本企业授信，内部备注仍仅本机构可见。必要的授信核定对象、有效期、差额和本次协议在授信操作中提供，不因信息精简取消必需输入或校验。

报价历史默认折叠，展开后按各笔报价展示机构、`FD-01`、报价时间、终结状态及原因；每条可继续展开自己的金额、币种、利率、期限和当时条款。历史条款保持当时事实，不能被当前授信总额或其他新报价覆盖；历史展开不替换上方当前报价，也不改变当前办理对象，不提供接受、修改或恢复历史报价的动作。

协议信息以表格展示本申请相关融资合同的文件名、对应业务及可用的文件状态，点击文件名直接下载；无文件时展示空态，下载失败就地可重试。历史融资合同须能对应原 `FD-01`，不能与当前报价混用。授信协议仍归授信记录，不因这张表而合并文件用途、数量上限或扩大权限；非当事方看不到私有文件。预览如提供，在同一容器切换后可返回，不叠加操作层。

`D-LS-28`～`D-LS-32`：本模块执行两次向前业务跃迁：报价成功推动“待报价→已报价待确认”；接受成功推动“已报价待确认→放款中”。拒绝和报价届满回退至有效需求的“待报价”；需求失效则消费L5“已失效／已关闭”及终结原因。“已放款”及后续由后续模块承接。**五值定义、派生与下发归L5**，列表、详情与控制台同源，不按内部状态自行拼装。

仅当前环节出可点按钮，按角色限制。游客操作区只有“立即登录”，公开内容继续可见。登录用户不可操作时区别本人需求、已被他人报价、项目已到期、覆盖不足等原因；非当前环节不给可点动作。需求已失效时融资报价与报价确认均不可操作且展示终结原因。

`D-LS-33`：页面呈现用户的金额、差额、时限、结果与可走路径；不展示内部判据公式、条款编号、字段来源、计算机制或规则论证。必须保留三个数的差额算式和锁定倒计时。术语、双语、时区与数字展示沿用L5及本平台面客基线，默认英文，不从原型演示代码复制内部说明文字。

`D-CR-58`（`F-LS-32`/`33`）：项目页记录区四类纵向清单与右侧固定办理区采用 [L5 功能9.2、11.7](../v1.0-借贷广场-融资需求与代币质押/01-功能需求说明.md) 的统一结构。报价、授信和接受拒绝属于“融资”办理区；清单入口与办理区入口指向同一申请/业务。多个待办先选目标，不按最近记录猜测。记录清单与右侧办理页签无业务时均保留对应空态，不让用户寻找消失的入口。

`P-LS-04`/`05`/`06` 为授信、报价和接受拒绝的办理场景，均从右侧操作区进入居中弹窗。只读申请详情不转入办理、不串联其他业务；授信保存关闭，用户再次点立即报价；报价提交无二次确认且成功关闭。接受流程保留当前步骤及完成情况，返回保留有效资料和成功文件，拒绝无需先上传。授信协议与融资合同分别标识用途、角色及上限，不混成同一附件集合。

`D-CR-61`：关闭/返回沿L5共同规则，未提交修改在当前弹窗确认放弃。报价成功刷新申请并关闭，不自动打开详情；接受/拒绝成功更新本笔结果和项目操作区，不增加跨业务快捷按钮。接受即在融资放款清单形成同一FD-01，尚无LN-01不表示放款完成。重新点击下一阶段操作时重新校验状态与权限。

长名称及文件名可读，错误与当前动作可达，语言切换不丢输入；不规定分栏、字段视觉顺序或尺寸。表单自动填充按L5 D-LS-61；已成功保存的本笔材料可继续用，新授信/新合同/新交易不能套用其他业务文件，自动填充不代替逐笔确认或一致性声明。业务流程见 [FL-CR-05](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md#fl-cr-05)。

### 5.2 跳转与跨主体隔离

沿用 [L5 `H-01`～`H-05`](../v1.0-借贷广场-融资需求与代币质押/01-功能需求说明.md)。资金方去报价落项目页并打开目标申请的居中报价办理弹窗，自动带授信判定；资产方去报价确认打开目标申请及当前 `FD-01` 的接受/拒绝办理视图；历史业务落该申请的对应报价历史条目。`D-LS-22`/`D-LS-23`：无单独“去授信”入口或独立授信落地页。

每次落地重新判权、核对对象和当前状态；已终结则落详情并解释，不能打开旧操作层，不报404、不白屏、不静默跳首页。游客看公开内容并登录引导；草稿与无权内容按L5隐藏存在性。控制台不执行授信、报价、接受、拒绝，只提供已有只读视图及按L5约定的业务跳转；从控制台进入保留返回相应位置的入口。授信金额不进入公开报价区或他方通知，盖章件不对游客公开。

### 5.3 关键站内信与发送边界

`D-LS-24`～`D-LS-27`：完整规则、收件人、五类事件及六对中英模板见[独立通知V1.1](03-授信报价与接受拒绝-消息通知.md)第1～6章。本册不重复模板，图示见[FL-CR-03](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md#fl-cr-03)。

| 成立事实 | 唯一发送归属与边界 |
| --- | --- |
| 报价成功、尚待接受且到期前24小时 | L6 N-CR-01/02发给明确关联的资产方收件账号，临期仅一次 |
| 报价自身168小时届满 | L6 N-CR-03向本笔相关资产方及原报价账号各一条，记录原到期时点；不声称释放项目在途或整池 |
| 需求覆盖不足并连带报价失效 | L5通知V1.1 N-LS-05一次告知双方需求和报价影响；L6不发financing.quote.expired，仍同事件完成报价状态流转和本笔机构占用释放 |
| 报价已接受 / 已拒绝 | L6 N-CR-04/05发给本笔原报价账号；接受只代表待放款，L7不重复发送同次“进入待放款” |

无授信核定/追加/到期消息，无多档临期提醒，无运营（含SPV）广播。收件账号与业务可操作人员不是同一概念：本企业员工可办理不等于全员收信；多成员资产方沿Q-LS-N01待确认，不默认广播。消息标题正文不含私人档案、完整账户、钱包地址或协议正文。

通知失败不改变业务、不停止168小时；重复事件不新增消息、不恢复未读或重新置顶。业务日期按D-CR-62，历史金额按本笔事实，不取外部行情重算。正式分类、账号映射与真实投递依DEP-17及通知第7章；账户通知开关只能控制经登记确定的可选类型，本模块不自行把关键事件变成可关闭项。

## 六、依赖、质量要求与待承接细项

### 6.1 已有质量要求

沿用基线：报价入口授信判定反馈≤1秒，报价提交终检与结果反馈≤2秒，当场覆盖判断目标≤1秒；依赖不可用按 `E-CR-18` 拒绝，不能用旧数值兜底。报价失效效力到168小时即成立；基线失效处理反馈目标≤1分钟、最坏≤5分钟，**不构成接受宽限**，异常延迟按 `E-CR-14` 显示原失效时刻。所有状态与金额结果一致可追溯，不能将处理延迟解释为允许部分结果先展示。

角色、归属和提交校验在平台执行，绕过页面仍不得越权；授信、报价、账户确认、摘要查看、文件上传、声明、接受、拒绝、失效以及相关金额变更均应能按融资业务追溯原因、主体与发生时间。无日志格式或存储要求。时间明确时区，金额带币种，继承L5的双语、响应式、键盘可达及非纯颜色状态表达；不增加本轮原型交付。
