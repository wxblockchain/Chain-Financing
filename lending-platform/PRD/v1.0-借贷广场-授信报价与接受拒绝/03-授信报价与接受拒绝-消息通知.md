# 授信报价与接受拒绝 · 消息通知

版本：V1.1｜所属模块：WS-352 / L6｜配套业务基线：L6 V1.4｜产品经理：许楚清。

**本模块发送五类关键站内信：收到报价、报价到期前24小时提醒、报价到期失效、报价已接受、报价已拒绝。** 覆盖不足造成需求及报价同步失效，由 L5 一次告知双方，L6 不重复发送。授信核定、追加和授信到期不发信；运营管理人员没有本模块新增站内信。

核对“何时发给谁”直接读第1章；开发主读第1～5章，测试主读第6章；收件归属依赖见第7章。本文件与[主册](v1.0-借贷广场-授信报价与接受拒绝-PRD.md)、[功能册](01-功能需求说明.md#presentation)、[验收册](02-验收需求说明.md#presentation)及[独立图册FL-CR-03](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md#fl-cr-03)同批使用；L5通知V1.1定义需求覆盖失效的唯一发送归属。

## 1. 哪个环节发送站内信

N-CR-01～05为本文件通知编号。融资申请编号为FP-28；每次成功报价的融资业务编号为FD-01。同一申请先后有多笔报价时，每笔均用自己的FD-01识别，不把“最新一笔”当作消息对象。

| 编号 | 发送节点与成立条件 | 收件人 | 必须知道什么 / 下一步 | 唯一发送归属 |
| --- | --- | --- | --- | --- |
| N-CR-01 | 报价提交成功，本笔进入待接受S-FD-1，金额、锁定及有效期已成立 | 该融资申请的资产方收件账号，归属约束见2.1 | 融资申请编号、业务编号、报价机构、金额、报价到期时刻；查看本笔并决定接受或拒绝 | WS-352 |
| N-CR-02 | 本笔报价距成功提交后168小时截止还剩24小时，仍为待接受且尚有效 | 同上 | 本笔准确到期时刻；未处理将自动失效。每笔只有这一次临期提醒 | WS-352 |
| N-CR-03 | 本笔因168小时有效期届满进入已失效S-FD-11，机构在途报价金额释放、需求锁定解除等结果一致 | 本笔相关资产方、原报价资金方，各自一条 | 原报价编号、原到期时刻、届满原因和本笔释放结果；旧报价不可继续接受，重新报价须满足当前条件 | WS-352；仅报价自身到期 |
| N-CR-04 | 资产方正式接受成功，本笔进入待放款S-FD-3 | 原报价资金方账号 | 本笔已接受、接受时间；查看融资放款清单中的同笔FD-01、盖章件并准备后续放款 | WS-352 |
| N-CR-05 | 资产方正式拒绝成功，本笔进入已拒绝S-FD-2，机构在途报价金额释放等结果一致 | 原报价资金方账号 | 哪笔被拒、拒绝时间、完整拒绝原因、本笔在途报价金额已释放；查看对应报价历史 | WS-352 |

报价成功、接受和拒绝均以正式业务结果成立为准。点击按钮、上传文件完成、显示提交中或操作结果未知，不构成发送依据。N-CR-01不另给资金方发送“提交成功”回执；N-CR-04/05不另给刚操作的资产方发送回执。

### 1.1 不发送的环节

| 场景 | 本期处理 |
| --- | --- |
| 首次授信、追加、重新核定、授信有效期届满、授信协议上传 | 依原业务展示结果；无授信消息、无运营审批消息。授信保存关闭并提示继续报价，不自动生成报价或通知 |
| 报价草稿、表单校验失败、本笔固定折算依据不完整、覆盖校验未知 | 原场景说明原因；未生成成功报价不发收到报价通知，也不以失败通知轰炸资金方 |
| 查看报价、填写收款资料、复制/打印摘要、上传盖章件、接受流程中途离开 | 展示当前进度，168小时仍继续；不发“已查看”“上传完成”“签署中”等过程消息 |
| 已锁定若干天、72小时/1小时提醒、每日催办、临期窗口内重复登录 | 不发送；报价只保留到期前24小时的一次提醒 |
| 已接受后原报价期限到点、已拒绝/已失效后旧计时到点 | 不再发报价临期或报价到期失效消息 |
| 项目到期但本笔存量报价仍在168小时内且有效 | 不提前发送报价失效；项目期限消息归L5，本笔继续按既定业务处理 |
| 外部行情变化、参考币种变化、授信摘要变化、下载/查询失败 | 不新增业务通知，不改写已锁定快照。本期USD/USDT/USDC固定1:1:1，无人工汇率维护或行情更新事件；业务金额仍取本笔成功事实 |
| 放款登记、到账确认、还款、确认到账、单笔结清 | 后续WS-353/354独立定义；不因共用项目页面再发一份L6消息 |
| 普通查看、四区定位、切换历史报价、复制、下载 | 无业务通知 |

## 2. 三方接收范围与跨模块发送归属

### 2.1 从业务角色落实到本人账号

| 角色 | 接收范围与限制 |
| --- | --- |
| 资产方 | 仅本融资申请所属企业的、已明确关联的本平台资产方收件账号。多成员企业具体代表账号沿Q-LS-N01待确认，建议需求类消息统一关联原发布账号；不能把建议直接实现成已定规则，不默认所有成员、企业管理员或最近查看者接收 |
| 资金方 | N-CR-03/04/05发送给本笔成功提交报价的本平台资金方账号，属于原报价机构；与L5“相关业务登记账号”衔接。不向该机构其他成员、曾报价但不是本笔的机构、浏览者或全体资金方广播；机构名不代替账号归属 |
| 运营管理人员（含SPV） | 授信与报价没有新增运营审核或处理职责；本模块五类事件均不抄送运营，也不设置每次接受/拒绝的全员播报。已有业务只读、监控及后续审核权限保留；待办存在不自动等于需要站内信 |
| 游客、其他平台、同钱包的另一身份 | 不是本笔收件人。借贷平台面客账号独立归属，同钱包或同邮箱不串信；管理端与面客端不共池 |

N-CR-R01：收件账号须可由本笔业务可靠确认，消息属于该自然人账号。账号归属缺失不以企业全员、任意管理员或当前登录者补位；补齐前不能将该收件分支判为可上线。停用、换角色、失去访问资格不自动转发给同事。历史消息不随另一人后续办理改投，读取和跳转仍检查当前权限。资产方已有唯一明确归属的场景可独立验收，不必等待多成员场景；多成员归属未决不影响业务本身的状态和计时。

### 2.2 同一事实由一个模块发送

| 事实 | 发送方与本轮结论 | 相邻模块承接 |
| --- | --- | --- |
| 成功报价、24小时临期、正常到期、接受、拒绝 | L6发送N-CR-01～05 | L5、控制台和消息中心展示业务事实，不额外发同义消息 |
| 需求因覆盖不足失效，连带本轮待接受报价失效 | L5按N-LS-05 / financing.demand.coverage_invalidated向相关双方各发一条，正文同时告知报价失效；L6不再向任一方发送financing.quote.expired | L6仍负责报价落S-FD-11及本笔机构在途释放，历史详情提供FD-01、实际失效时间、原因与释放结果；不因合并通知取消业务处理 |
| 先报价到期，之后需求因覆盖不足失效 | 两次真实终结事实分别按其归属处理；不是把同一事实重复发两遍 | L5只按后一次需求事件的真实受影响范围通知；已经到期、没有在途报价的原资金方不因历史报价再获需求通知 |
| 需求失效与报价到期/接受/拒绝竞争 | 以业务裁定的本笔唯一最终结果和原因通知，不同时宣告已接受、已拒绝和已失效 | 需求原因成立则由L5发；报价自身届满成立则由L6发。补处理不创造第二个报价终结结果 |
| 接受报价、随后放款流程 | L6仅告知“报价已接受，待放款” | L7不再为同一次接受补发“进入待放款”消息；真正新增放款/到账事件由L7定义，不能把接受当作已放款 |
| 后续还款/结清、项目覆盖与期限 | 各自所属模块发送 | L6不复制；单笔结清不代表整个项目结束 |

L6功能§5.3、验收AC-LS-108及图册FL-CR-03均采用本节同一发送归属。两类失效原因和L6状态/金额处理责任保留，不将通知合并误解为取消报价失效；本文件不新增状态机或重复事件。

## 3. 时限、历史语义与防重复

N-CR-R02：业务日期判断统一UTC，时刻按收件人偏好时区展示并标注；无偏好沿平台既有展示规则，不能改变截止事实。报价有效期自成功提交起连续168小时，精确到秒，不从读信、通知到达、上传盖章件或自然日末起算。N-CR-02在该截止前24小时触发，发送时已经接受、拒绝、因需求失效而终结或已过截止的，不能再补发催办。正常发送后才发生处理的，旧提醒作为历史保留，不能重新成为可办事项。未曾发送且发现时已过临期节点但仍待接受、尚未到期的，可补一次并显示准确截止，不宣称仍有完整24小时。

N-CR-R03：到期时刻及之后不得接受，没有通知宽限。失效处理延迟时，通知内的失效时点仍为原到期时刻，不能改成处理或送达时间。项目期限届满不提前结束仍有效的存量报价；接受成功后停止本报价计时，后续不再因原报价截止而失效。

N-CR-R04：同一借贷面客账号、同一FD-01、同一通知事件只收一次；临期节点固定为本笔24小时节点。重复送达、刷新、补处理不增加第二条、不重新置顶、不把已读恢复未读，也不改变原发生时间。接受/拒绝/失效先由业务裁定唯一终态，不能只靠不同消息名称分别通知。FP-28相同但FD-01不同的新报价是新业务，可产生自己的五类节点，不能覆盖或吞掉旧报价历史。

N-CR-R05：保留发生时的机构、金额、时间及结果事实；消息不是业务办理授权。到达乱序不得把已处理报价重新置为待接受；读信、标记全部已读不等于接受、拒绝、还款或签署。办理成功仍须满足现行账户、文件、声明及权限条件，消息点击不替用户勾选或提交。

N-CR-R06：通知无法展示或发送失败不回滚交易、不停止计时、不解锁/重置报价。页面仍能查询期限、结果和后续可办动作。符合发送条件且账号、模板均已闭合的通知沿面客中心IF-NC-01，在业务事件发生后60秒内于列表与未读数一致体现；实际延迟属于未达验收，不能改写事件时间掩盖。

## 4. 登记输入与中英模板

### 4.1 登记范围

沿WS-356功能§10的RG-NC-01～12提供本模块登记输入。以下五个业务类型继承L6原名；登记状态均为**待适配**，不等于已完成共享登记或真实投递。中文分类只表达语义，正式分类取值由消息中心最后统一核对，不能照搬旧平台枚举。

| 通知 | 业务类型标识 | 分类语义 | 模板对 | 去重的业务区分范围 | 消息时效 |
| --- | --- | --- | --- | --- | --- |
| N-CR-01 | financing.quote.submitted | 业务办理进度 | T-CR-01 | 本平台面客账号＋本笔FD-01＋本事件 | 办理指引截至本笔报价截止；提前终结时按当前结果停用办理 |
| N-CR-02 | financing.quote.expiring | 业务提醒 | T-CR-02 | 本平台面客账号＋本笔FD-01＋24小时提醒节点 | 同上；逾期不继续催办 |
| N-CR-03 | financing.quote.expired | 业务办理进度 | T-CR-03A / 03B | 本平台面客账号＋本笔FD-01＋本次届满终结 | 结果消息不另设失效时点 |
| N-CR-04 | financing.quote.accepted | 业务办理进度 | T-CR-04 | 本平台面客账号＋本笔FD-01＋本次接受 | 结果消息不另设失效时点 |
| N-CR-05 | financing.quote.rejected | 业务办理进度 | T-CR-05 | 本平台面客账号＋本笔FD-01＋本次拒绝 | 结果消息不另设失效时点 |

共同登记项：平台与端固定“借贷平台·面客端”；触发方为WS-352；收件范围按第2章；跳转形态均为本平台业务对象，准确落点见第5章，均需当前权限和状态预判。不把弹窗另注册成独立页面，不登记外部URL。消息过期与报价失效分开：前两类到报价截止后停止作为有效办理提醒，但消息历史不删除；结果类长期保留遵循消息中心既有规则。

模板标题、正文成对命名为msg.<业务类型>.title / msg.<业务类型>.body。T-CR-*只是本文对完整文案的引用编号，03A/03B按收件角色择一，不能使同一账号收两封。条件变体的正式登记沿共享框架核对；不为角色变体新增业务事件。

### 4.2 业务变量与校验

| 变量 | 业务含义、必填与校验 |
| --- | --- |
| demand_id | 原融资申请编号FP-28；全部模板必有，不能取同一项目的新申请代替 |
| business_id | 本笔融资业务编号FD-01；全部模板必有。接受时尚未产生LN-01，不用虚构放款编号补位 |
| institution_name | 本笔真实报价机构名称；01/02/03A必有。沿企业可展示名称，不以用户个人姓名、邮箱或钱包地址代替 |
| amount_usd | 本笔成功报价的融资金额，USD数值、大于0，沿L6金额精度展示；01必有，明确是融资金额，不把USDT/USDC结算金额标成USD |
| expires_at | 本笔已锁定的真实报价到期时刻；01/02必有。等于成功提交后168小时，按收件人展示时区且明确标注，不取通知阅读时间再计算 |
| expired_at | 本笔正常到期失效时刻；03A/03B必有，等于原expires_at。不得填需求失效时刻套入本模板 |
| accepted_at / rejected_at | 平台确认本笔接受/拒绝成功的真实时刻；04/05分别必有；不取点击或盖章件上传完成时间 |
| reason | 本次资产方填写的拒绝原因原文；05必有，沿原业务1～200字符要求，详情完整呈现；不以运营内部备注替代，不声称自动翻译了用户原文 |

金额、名称和时间来自同一本笔业务事实，不用当前汇率重算历史金额；参考币种是需求意向，不影响收件筛选。必要变量或归属缺失不得以演示值、空白消息、假编号或裸占位符补齐；按来源补齐，不能对整列表造成不可用。框架的单行语言降级继续有效。双语模板的变量名称、数量一致；时间和金额按平台统一格式展示，原用户原因纯文本保留，不拼接动态动词或状态片段。
