# 借贷广场 · 授信报价与接受拒绝 — 验收需求说明 V1.4

测试主读。完整规则以[功能册](01-功能需求说明.md)为准，范围与编号归属见[主册](v1.0-借贷广场-授信报价与接受拒绝-PRD.md)，流程与状态见[独立图册](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md)。本册沿用相同功能顺序和需求编号，给出可观察结果，不代写详细执行用例或接口测试清单。

通用背景：已发布的融资需求由L5提供，项目额度已在发布时计入；资金方对资产方的授信跨项目共用。验收须区分游客、资金方本企业、该项目资产方、其他企业，并区分本笔与二元组其他存量业务。下文未注明L5的原有条款编号均属L6，不得与L5同号条款混用。

## 一、授信判定、核定、追加与有效期

对应 `F-LS-20`～`F-LS-23`，规则见[功能一](01-功能需求说明.md#credit)，图 `FL-CR-01`、`ST-CR-01`。角色为资金方，前提为项目可报价；用不同授信状态验证同一个报价入口。

| 验收编号 | 场景与预期结果 |
| --- | --- |
| `AC-CR-05`、`AC-CR-07` | 无额度、额度不足、已到期均在同一业务容器进入授信流程，仅模式不同；生效且充足直接进报价。已到期不可用于新报价，无“再用一次”的宽限 |
| `AC-CR-06`、`AC-CR-10`、`AC-CR-26` | 不足时在填写报价前展示本次报价、可用授信、差额三个数；无额度说明尚未核定，到期说明原到期日。前三支先确认，未确认不可显示授信编辑；充足支不额外确认 |
| `AC-CR-27` | 取消授信意图关闭当前操作弹窗，回项目操作区，不打开申请详情；无授信变更、融资业务编号、占用或锁定，不留取消业务记录 |
| `AC-CR-28`～`AC-CR-30` | 授信意图、填写和放弃修改在同一居中操作弹窗，不叠层；保存成功关闭并toast“已授信，请继续报价”，不自动报价。再次点击立即报价才重验并打开报价/授信流程；他笔占用导致又不足时给最新差额，不重复增加上一笔授信 |
| `AC-CR-24`（映射 `D-CR-19`/`20`/`42`、`CR-07`） | 首次与重新核定默认一年，下限一年、上限五年，越界拒绝并告知日期范围；等于边界可通过。追加不改日期则保持、不得提前，不强制延至追加日一年后。追加上限取首次/最近正式重新核定UTC日期+5年，不取追加日；普通追加不重置起点，等于上限通过、超过拒绝 |
| `AC-CR-03`（映射 `D-CR-10`～`14`、`CR-05`） | 同机构×资产方跨项目只有一份额度；首次总额>0、最多两位，追加为正增加额。不可通过负增加额或其他入口调低；无审批/冻结/解冻流程。重新核定不得覆盖历史，不得抹掉旧业务金额 |
| `AC-CR-04` | 核定成功到报价之间，另一个项目产生在途报价使额度不足：再次点击立即报价时重新给出三个数并按授信意图进入追加模式；覆盖同时重新判定，不只验授信 |
| `AC-CR-03`、`INV-CR-01` | 授信占用200万、在途报价250万、当前报价80万、额度500万：拒绝新增报价，显示可用50万、差额30万；漏算在途报价而放行不通过。已有异常超额时禁止新增、运营可知，不自动改额度或抹金额 |
| `AC-CR-05`（映射 `D-CR-15`、`E-CR-01`） | 授信成功后取消报价或报价失败，授信仍生效，未自动生成报价；不能把核定与报价绑定回滚 |
| `AC-LS-106`、`AC-MC-11` | 授信对象只读、备注仅机构本方可见。资产方只见对本企业的额度；资金方不见其他机构额度。控制台只读，无就地核定或追加动作 |

### 授信对象必要业务信息、授信协议及填写体验

仍对应 `F-LS-20`～`23`，以首次核定、追加、到期重新核定三个模式分别验证。规则见功能1.4～1.5，流程见 `FL-CR-01`；不把页面上传进度当作授信新状态。

| 验收编号 / 规则 | 场景与预期结果 |
| --- | --- |
| `AC-CR-33` / `D-CR-54` | 自动取得项目所属资产方名称和本笔上下文，只读且不能另选企业或拿债务方/项目名替代；不向资金方提供对方注册地区、登记号码、完整注册地址、个人证件等账户档案或快捷入口。完整、未提供、加载与失败可区分，可重试；可选资料缺失不新增准入，主体归属无法确认则阻止提交，不能转为手填对方档案 |
| `AC-CR-34` / `D-CR-55` | 三种授信操作均须提交协议：0份不能成功，1份与10份有效附件可通过文件校验，第11份不能加入。累计选择受10份总数约束；已选8份再选3份，原8份保留，本批不加入，告知剩余2份。历史累计已超过10份不阻止本次1～10份有效提交 |
| `AC-CR-35` / `D-CR-55`/`57` | PDF、JPG（含JPEG）、PNG可用；单份等于10MB可通过，超过10MB、不支持格式、空文件均不计入有效附件并给出具体原因。只按单份大小判断，不将10MB当全部附件合计上限 |
| `AC-CR-36` / `D-CR-57` | 上传中或存在失败待处理文件不能提交；重试成功或移除失败项后，至少1份成功才可继续。部分失败保留其他成功文件与金额/日期/备注；移除全部成功文件重新变为缺少协议。无真实文件内容时不得仅凭文件名显示成功 |
| `AC-CR-37` / `D-CR-56`/`57` | 成功操作可追溯本次协议、金额、日期与操作主体；后续追加或重新核定不覆盖历史。仅授信双方可查看/下载，他方与游客不可见，备注仍机构内可见。新授信变更不默认复用历史文件；存量缺协议不被作废，也不阻断原本可以直接进行的报价 |
| `AC-CR-38` / `D-CR-57` | 金额、日期或提交错误保留可修改内容和成功文件并定位问题；未成功不生效，重复点击不重复增加额度。有未提交改动时取消/Escape先确认放弃，可继续编辑；放弃无新增记录或锁定，无嵌套弹层。提交成功后取消报价仍保留授信及协议；重验不足回追加时不重复上一笔增加额 |
| `AC-CR-39` / `D-CR-55`、`D-FIN-93` | 授信协议无新盖章、条款一致性勾选或审核中要求。接受报价仍须资产方上传至少1、最多5份融资合同盖章件并确认原有声明；已上传10份授信协议不能替代该步骤，也不占其5份额度。两类文件的数量、角色、归属、权限分别成立 |

授信有效期继续按 `AC-CR-24` 验收；该日期可填写不表示可突破1～5年或追加不得提前的约束。授信有效期与报价168小时、最终还款日分别显示。`Q-CR-07`已按P06关闭；不能把原型只读日期当作取消合规延长能力的依据。

### 授信金额连续算例（`AC-CR-03`、`AC-CR-09`）

单位为万USD，同一机构×资产方，其他事实保持不变。前三列是授信额度与两类业务金额，不能混同项目额度。

| 事件 | 授信额度 | 授信占用额 | 在途报价金额 | 可用授信 | 结果 |
| --- | --- | --- | --- | --- | --- |
| 起点已有未偿本金200 | 500 | 200 | 0 | 300 | 可报价 |
| P1报价150成功 | 500 | 200 | 150 | 150 | `200+0+150≤500` |
| P2报价100成功 | 500 | 200 | 250 | 50 | 两项目共用额度 |
| P3拟报价80 | 500 | 200 | 250 | 50 | 拒绝，差额30，不新增编号或金额 |
| 追加授信100 | 600 | 200 | 250 | 150 | 重验后P3的80满足授信，但本算例此处不提交P3 |
| P1被拒绝 | 600 | 200 | 100 | 300 | 释放150，不进本金 |
| P2放款确认完成 | 600 | 300 | 0 | 300 | 100原子转移，可用授信不跳变 |
| P2归还本金40并确认 | 600 | 260 | 0 | 340 | 只递减已偿本金40 |

算例不替代覆盖校验，任何一笔还须通过L5准入要求。

## 二、报价、汇率、锁定与七天有效期

对应 `F-LS-24`～`F-LS-26`、`F-LS-31`、`F-LS-34`、`F-LS-36`，规则见[功能二](01-功能需求说明.md#quote)，图 `FL-CR-01`、`FL-CR-04`、`ST-CR-02`。角色为资金方及公开查看者。

| 验收编号 | 场景与预期结果 |
| --- | --- |
| `AC-CR-11` | 报价表单在提交前展示不可改撤、锁定和占用及168小时后果；点击提交即校验，无二次确认弹窗。成功关闭并刷新原记录，不自动开详情；失败保留输入，无成功业务事实，资产方接受所需逐笔确认未被取消 |
| `AC-CR-13` | 两机构同时报价只成功一笔；失败方得知已被报价，无业务编号、无新增在途报价金额。成功方同一事件中取得业务编号、快照、起算时间、待接受状态与需求锁定结果 |
| `AC-FIN-23`（承接L5） | 需求发布时已计入项目在途金额；报价前后该值不变。拒绝/报价届满时也不因报价释放需求的项目在途金额，不发生重复计量 |
| `AC-CR-31`、`AC-CR-32` | 金额只读等于需求金额；结算币种仅USD/USDT/USDC；利率>0且≤100、最多两位小数。还款类型固定“按季付息；到期还本付息”，最终还款日等于项目截止日，均无编辑控件并进入摘要；报价办理只呈现本次必要授信信息与报价输入，不增加完整授信详情快捷入口 |
| `AC-LS-101` | 报价表单、提交校验、报价确认摘要均无机构收还款账户要求；未登记资金方收款账户也不影响本模块成功路径。`QT-07`/`QT-08`不能复活为隐藏必填项；无报价时池快照 |
| `AC-CR-20`、`AC-CR-21` | 页面打开后代币权威状态已变，报价提交不得沿用旧覆盖数值；当前L5失效判据成立时需求当场失效，已有待接受报价一并失效，本次不生成编号、不产生在途报价金额。提示覆盖不足及补足后重发路径，不归咎资金方 |
| `AC-CR-22`、`AC-FIN-07` | 授信足但覆盖不通过、覆盖通过但授信不足，均不能直接报价；前者提示资产方补足覆盖后重发，后者进入机构授信追加。两者不能合成“条件不满足” |
| L5 `AC-FIN-26`（L6执行） | 用已乘质押率的融资上限而非原始池值；按更早已保留需求累计项判断，不因本期单笔而删除该项。融资上限200、项目融资余额50、更早金额0、本笔150时失效判据不成立；上限降为140则本笔立即失效。不得另扣本笔发布金额使等额覆盖误判失败 |
| `AC-CR-15`、`AC-CR-16` | 双方均不登录，报价在成功时刻后168小时届满；本笔全额释放、业务已失效、有效需求解锁，项目在途金额和质押不变；无需点击或等通知阅读 |
| `AC-CR-19` | 处理延迟期间，到期报价不可接受；补完成结果中的失效时间仍是原到期时刻，不是后来处理时间；不存在零倒计时仍可接受的窗口 |
| `AC-LS-97` | 列表、详情、资产方控制台一致显示谁锁定、何时开始、已多久、还剩多久；不足24小时到分钟并加强提示，时区明确；接受/拒绝后停止待接受倒计时 |
| `AC-LS-101` | 无报价修改、撤回、有效期编辑、展期、续期或宽限入口；失效/被拒后重报是新编号、新快照、新期限，且项目未到期、需求仍有效等条件继续有效 |
| AC-CR-48 / L5 D-LS-60、D-LS-61 | 需求参考币种与机构选择币种不同时仍可正常报价；已知需求、企业、只读日期/类型及有效收款资料自动带入，缺项才补填，逐笔确认/声明仍未勾选；复用不串企业、用途或历史合同 |

## 三、报价确认：账户、合同、接受与拒绝

对应 `F-LS-28`～`F-LS-30`，规则见[功能三](01-功能需求说明.md#respond)，图 `FL-CR-02`、`ST-CR-02`。前提为本企业报价仍待接受且未到期，资金方只能查看自身相关资料，不能代资产方确认。

| 验收编号 | 场景与预期结果 |
| --- | --- |
| `AC-LS-111` | 法币首次无虚构预填，后续取本企业最近一次成功接受账户，八项可编辑、中转行选填且默认折叠；每笔明确确认、默认不勾选，未确认不可接受。改完账户不能沿用旧确认 |
| `AC-LS-99` | 法币七项必填，缺任何必填项不可接受；SWIFT非8/11位字母数字被拒，国家段不一致仅提示；账号/IBAN具体字符长度待 `Q-CR-08`，不得用未定范围宣称全量格式验收通过 |
| `AC-LS-113` | 已登记 `ABC Co., Ltd.` 时 `ABC CO.,LTD` 可通过；未登记关联方 `ABC Trading Ltd` 不通过，展示填写值与登记名称并提供补登出路；无跳过校验入口 |
| `AC-LS-99`、`AC-LS-112` | 法币账户/数币地址与币种匹配。数币为本企业统一地址、ETH只读；空地址不可接受，无人工输入任意钱包、无链选择控件；平台不声称已验证账户真实或汇路可达 |

## 六、质量与验收边界

按[功能册六](01-功能需求说明.md#dependencies)核验授信判定≤1秒、提交结果≤2秒、当场覆盖判断目标≤1秒；不能为了满足反馈时间用旧数据放行。到期效力立即成立，基线处理反馈目标≤1分钟、最坏≤5分钟不构成可继续接受的窗口。可追溯每笔状态、金额、账户确认、合同声明和锁定汇率，无越权执行、重复编号或金额重复释放。

默认英文、中英切换、时区标注、金额币种、窄屏操作、键盘可达、状态文字按平台既有基线验证。本轮只交PRD，未完成原型或运行系统验收；不得把文档检查写成产品功能已通过。

P01、P05、P06与UTC日期已明确，按本组功能规则组织验收，不再列为未决。`Q-CR-08`地区账号/中转行适用表、`Q-CR-09`数币结算精度、必要主体资料与英文名补登能力、固定规则真实追溯登记、通知账号与适配仍须承接。可先验证已明确行为；依赖未就绪不得宣称全量通过。通知测试主读[通知册第6章](03-授信报价与接受拒绝-消息通知.md)，五类事件与L5合并边界不能因登记未定而删除。
