# 借贷广场 · 授信报价与接受拒绝 — 验收需求说明 V1.1

测试主读。完整规则以[功能册](01-功能需求说明.md)为准，范围与编号归属见[主册](v1.0-借贷广场-授信报价与接受拒绝-PRD.md)，流程与状态见[独立图册](v1.0-借贷广场-授信报价与接受拒绝-流程图与状态机.md)。本册沿用相同功能顺序和需求编号，给出可观察结果，不代写详细执行用例或接口测试清单。

通用背景：已发布的融资需求由L5提供，项目额度已在发布时计入；资金方对资产方的授信跨项目共用。验收须区分游客、资金方本企业、该项目资产方、其他企业，并区分本笔与二元组其他存量业务。下文未注明L5的原有条款编号均属L6，不得与L5同号条款混用。

## 一、授信判定、核定、追加与有效期

对应 `F-LS-20`～`F-LS-23`，规则见[功能一](01-功能需求说明.md#credit)，图 `FL-CR-01`、`ST-CR-01`。角色为资金方，前提为项目可报价；用不同授信状态验证同一个报价入口。

| 验收编号 | 场景与预期结果 |
| --- | --- |
| `AC-CR-05`、`AC-CR-07` | 无额度、额度不足、已到期均在同一报价弹窗进入授信流程，仅模式不同；生效且充足直接进报价。已到期不可用于新报价，无“再用一次”的宽限 |
| `AC-CR-06`、`AC-CR-10`、`AC-CR-26` | 不足时在填写报价前展示本次报价、可用授信、差额三个数；无额度说明尚未核定，到期说明原到期日。前三支先确认，未确认不可显示授信编辑；充足支不额外确认 |
| `AC-CR-27` | 在授信意图确认处取消，关闭报价弹窗回详情，需求仍按当前事实可报价；无新授信记录、业务编号、在途报价金额或锁定，不留取消业务记录 |
| `AC-CR-28`～`AC-CR-30` | 确认有遮罩且底层不可操作，有确认与取消及后果说明；提示、额度编辑、报价在同一流程切换，不跳页、不套第二层。无遮罩的就地替换不通过 |
| `AC-CR-24`（映射 `D-CR-19`/`20`/`42`、`CR-07`） | 首次与重新核定默认一年，下限一年、上限五年，越界拒绝并告知日期范围；等于边界可通过。追加不改日期则保持、不得提前，不强制延至追加日一年后。追加五年上限日期基点待 `Q-CR-07` 明确，不把未定值判作通过 |
| `AC-CR-03`（映射 `D-CR-10`～`14`、`CR-05`） | 同机构×资产方跨项目只有一份额度；首次总额>0、最多两位，追加为正增加额。不可通过负增加额或其他入口调低；无审批/冻结/解冻流程。重新核定不得覆盖历史，不得抹掉旧业务金额 |
| `AC-CR-04` | 核定成功到报价之间，另一个项目产生在途报价使额度不足：重新给出三个数，回追加模式，不二次询问授信意图；覆盖同时重新判定，不只验授信 |
| `AC-CR-03`、`INV-CR-01` | 授信占用200万、在途报价250万、当前报价80万、额度500万：拒绝新增报价，显示可用50万、差额30万；漏算在途报价而放行不通过。已有异常超额时禁止新增、运营可知，不自动改额度或抹金额 |
| `AC-CR-05`（映射 `D-CR-15`、`E-CR-01`） | 授信成功后取消报价或报价失败，授信仍生效，未自动生成报价；不能把核定与报价绑定回滚 |
| `AC-LS-106`、`AC-MC-11` | 授信对象只读、备注仅机构本方可见。资产方只见对本企业的额度；资金方不见其他机构额度。控制台只读，无就地核定或追加动作 |

### 企业基本信息、授信协议及填写体验

仍对应 `F-LS-20`～`23`，以首次核定、追加、到期重新核定三个模式分别验证。规则见功能1.4～1.5，流程见 `FL-CR-01`；不把页面上传进度当作授信新状态。

| 验收编号 / 规则 | 场景与预期结果 |
| --- | --- |
| `AC-CR-33` / `D-CR-54` | 授信企业全称、注册国家/地区、企业登记号码、注册地址只读展示且指向项目所属资产方；不能选其他企业、拿债务方或项目名替代。完整、部分未提供、加载及加载失败有明确区别，失败可重试；基本信息缺项不擅自增加准入条件，主体归属无法确认则不可提交。无权资料及内部主体标识不展示 |
| `AC-CR-34` / `D-CR-55` | 三种授信操作均须提交协议：0份不能成功，1份与10份有效附件可通过文件校验，第11份不能加入。累计选择受10份总数约束；已选8份再选3份，原8份保留，本批不加入，告知剩余2份。历史累计已超过10份不阻止本次1～10份有效提交 |
| `AC-CR-35` / `D-CR-55`/`57` | PDF、JPG（含JPEG）、PNG可用；单份等于10MB可通过，超过10MB、不支持格式、空文件均不计入有效附件并给出具体原因。只按单份大小判断，不将10MB当全部附件合计上限 |
| `AC-CR-36` / `D-CR-57` | 上传中或存在失败待处理文件不能提交；重试成功或移除失败项后，至少1份成功才可继续。部分失败保留其他成功文件与金额/日期/备注；移除全部成功文件重新变为缺少协议。无真实文件内容时不得仅凭文件名显示成功 |
| `AC-CR-37` / `D-CR-56`/`57` | 成功操作可追溯本次协议、金额、日期与操作主体；后续追加或重新核定不覆盖历史。仅授信双方可查看/下载，他方与游客不可见，备注仍机构内可见。新授信变更不默认复用历史文件；存量缺协议不被作废，也不阻断原本可以直接进行的报价 |
| `AC-CR-38` / `D-CR-57` | 金额、日期或提交错误保留可修改内容和成功文件并定位问题；未成功不生效，重复点击不重复增加额度。有未提交改动时取消/Escape先确认放弃，可继续编辑；放弃无新增记录或锁定，无嵌套弹层。提交成功后取消报价仍保留授信及协议；重验不足回追加时不重复上一笔增加额 |
| `AC-CR-39` / `D-CR-55`、`D-FIN-93` | 授信协议无新盖章、条款一致性勾选或审核中要求。接受报价仍须资产方上传至少1、最多5份融资合同盖章件并确认原有声明；已上传10份授信协议不能替代该步骤，也不占其5份额度。两类文件的数量、角色、归属、权限分别成立 |

授信有效期继续按 `AC-CR-24` 验收；该日期可填写不表示可突破1～5年或追加不得提前的约束。授信有效期与报价168小时、最终还款日分别显示。`Q-CR-07` 仍只影响追加延长的上限基点，不能把原型当前只读日期当作取消业务延长能力的依据。

### 授信金额连续算例（`AC-CR-03`、`AC-CR-09`）

单位为万USD，同一机构×资产方，其他事实保持不变。前三列是授信额度与两类业务金额，不能混同项目额度。

| 事件 | 授信额度 | 授信占用额 | 在途报价金额 | 可用授信 | 结果 |
| --- | --- | --- | --- | --- | --- |
| 起点已有未偿本金200 | 500 | 200 | 0 | 300 | 可报价 |
| P1报价150成功 | 500 | 200 | 150 | 150 | `200+0+150≤500` |
| P2报价100成功 | 500 | 200 | 250 | 50 | 两项目共用额度 |
| P3拟报价80 | 500 | 200 | 250 | 50 | 拒绝，差额30，不新增编号或金额 |
| 追加授信100 | 600 | 200 | 250 | 150 | 重验后P3的80满足授信，但本算例此处不提交P3 |
| P1被拒绝 | 600 | 200 | 100 | 300 | 释放150，不进本金 |
| P2放款确认完成 | 600 | 300 | 0 | 300 | 100原子转移，可用授信不跳变 |
| P2归还本金40并确认 | 600 | 260 | 0 | 340 | 只递减已偿本金40 |

算例不替代覆盖校验，任何一笔还须通过L5准入要求。

## 二、报价、汇率、锁定与七天有效期

对应 `F-LS-24`～`F-LS-26`、`F-LS-31`、`F-LS-34`、`F-LS-36`，规则见[功能二](01-功能需求说明.md#quote)，图 `FL-CR-01`、`FL-CR-04`、`ST-CR-02`。角色为资金方及公开查看者。

| 验收编号 | 场景与预期结果 |
| --- | --- |
| `AC-CR-11` | 提交前显式确认不可改/撤、锁定需求、将增加多少USD在途报价金额、七天未处理自动失效、提前解除只能资产方拒绝；未确认不提交 |
| `AC-CR-13` | 两机构同时报价只成功一笔；失败方得知已被报价，无业务编号、无新增在途报价金额。成功方同一事件中取得业务编号、快照、起算时间、待接受状态与需求锁定结果 |
| `AC-FIN-23`（承接L5） | 需求发布时已计入项目在途金额；报价前后该值不变。拒绝/报价届满时也不因报价释放需求的项目在途金额，不发生重复计量 |
| `AC-CR-31`、`AC-CR-32` | 金额只读等于需求金额；结算币种仅USD/USDT/USDC；利率>0且≤100、最多两位小数。还款类型固定“按季付息；到期还本付息”，最终还款日等于项目截止日，均无编辑控件并进入摘要；报价弹窗仅授信信息与报价表单两段，无操作导航 |
| `AC-LS-101` | 报价表单、提交校验、报价确认摘要均无机构收还款账户要求；未登记资金方收款账户也不影响本模块成功路径。`QT-07`/`QT-08`不能复活为隐藏必填项；无报价时池快照 |
| `AC-CR-20`、`AC-CR-21` | 页面打开后代币权威状态已变，报价提交不得沿用旧覆盖数值；当前L5失效判据成立时需求当场失效，已有待接受报价一并失效，本次不生成编号、不产生在途报价金额。提示覆盖不足及补足后重发路径，不归咎资金方 |
| `AC-CR-22`、`AC-FIN-07` | 授信足但覆盖不通过、覆盖通过但授信不足，均不能直接报价；前者提示资产方补足覆盖后重发，后者进入机构授信追加。两者不能合成“条件不满足” |
| L5 `AC-FIN-26`（L6执行） | 用已乘质押率的融资上限而非原始池值；按更早已保留需求累计项判断，不因本期单笔而删除该项。融资上限200、项目融资余额50、更早金额0、本笔150时失效判据不成立；上限降为140则本笔立即失效。不得另扣本笔发布金额使等额覆盖误判失败 |
| `AC-CR-15`、`AC-CR-16` | 双方均不登录，报价在成功时刻后168小时届满；本笔全额释放、业务已失效、有效需求解锁，项目在途金额和质押不变；无需点击或等通知阅读 |
| `AC-CR-19` | 处理延迟期间，到期报价不可接受；补完成结果中的失效时间仍是原到期时刻，不是后来处理时间；不存在零倒计时仍可接受的窗口 |
| `AC-LS-97` | 列表、详情、资产方控制台一致显示谁锁定、何时开始、已多久、还剩多久；不足24小时到分钟并加强提示，时区明确；接受/拒绝后停止待接受倒计时 |
| `AC-LS-101` | 无报价修改、撤回、有效期编辑、展期、续期或宽限入口；失效/被拒后重报是新编号、新快照、新期限，且项目未到期、需求仍有效等条件继续有效 |

### 汇率业务验收（沿用条款，不另开契约分册）

| 关联需求 / 异常 | 场景与明确结果 |
| --- | --- |
| `F-LS-26`、`D-FIN-17` | 本平台报价汇率取代币发行平台唯一来源，不存在本平台维护第二套汇率的入口或自定汇率结果 |
| `F-LS-26`、`D-FIN-80` | 报价成功后可查汇率值、生效时间、来源说明、版本标识四要素；缺任一项不允许成功锁定报价。提交前预览发生变化时，不能静默锁定不同于用户确认的条款 |
| `F-LS-26`、`D-FIN-80`/`81` | 锁定后上游行情变动，原业务结算金额及对应USD金额不变。放款与还款分别引用同一标识，对相同原金额得到相同数；任一环节重新取最新行情替代不通过 |
| `F-LS-26`、`D-FIN-81` | 同一二元组的A、B两笔用不同版本快照，汇总在途与未偿本金时各用各自依据；不能全部套B的最新快照 |
| `F-LS-26`、`D-FIN-82` | 明确展示汇率方向。示例一单位结算币种=0.8USD、融资金额100USD，则结算金额125单位；按同一快照折回为100USD。例值仅验证方向，不是实际行情。币种精度边界待 `Q-CR-09` 同源确认 |
| `F-LS-26`、`E-CR-18` | 上游汇率不可用/超时/不完整时拒绝新报价，提示可重试；无新编号、无在途报价金额、无需求锁定，不以旧快照或缓存放行，也不因不可判断而失效需求 |
| `F-LS-26`、`D-FIN-80`/`81` | 上游暂不可用时，已锁定业务仍可查原四要素并按原快照处理；拒绝/失效后的历史可追溯，但该快照不得用于新业务。重新报价另取快照 |
| `F-LS-36`、`E-CR-18` | 当场覆盖判断数据不可得，显示与汇率失败可区分的原因；不把未知当覆盖不足、也不放行；随后成功取得当前事实才按正常分支处理 |

## 三、报价确认：账户、合同、接受与拒绝

对应 `F-LS-28`～`F-LS-30`，规则见[功能三](01-功能需求说明.md#respond)，图 `FL-CR-02`、`ST-CR-02`。前提为本企业报价仍待接受且未到期，资金方只能查看自身相关资料，不能代资产方确认。

| 验收编号 | 场景与预期结果 |
| --- | --- |
| `AC-LS-111` | 法币首次无虚构预填，后续取本企业最近一次成功接受账户，八项可编辑、中转行选填且默认折叠；每笔明确确认、默认不勾选，未确认不可接受。改完账户不能沿用旧确认 |
| `AC-LS-99` | 法币七项必填，缺任何必填项不可接受；SWIFT非8/11位字母数字被拒，国家段不一致仅提示；账号/IBAN具体字符长度待 `Q-CR-08`，不得用未定范围宣称全量格式验收通过 |
| `AC-LS-113` | 已登记 `ABC Co., Ltd.` 时 `ABC CO.,LTD` 可通过；未登记关联方 `ABC Trading Ltd` 不通过，展示填写值与登记名称并提供补登出路；无跳过校验入口 |
| `AC-LS-99`、`AC-LS-112` | 法币账户/数币地址与币种匹配。数币为本企业统一地址、ETH只读；空地址不可接受，无人工输入任意钱包、无链选择控件；平台不声称已验证账户真实或汇路可达 |
| `AC-LS-110`、`AC-CR-25` | 确认接受前非折叠展示跨境手续费由资产方承担、到账少于融资金额、本金仍按融资金额；摘要同样包含告知，展示可追溯，无额外手续费勾选。150万融资、实收1499750时，本金与额度计量仍为150万 |
| `AC-LS-112` | 无账户簿、多账户列表、“设为默认”、预估手续费数字、实收金额输入、中转行必填或数币地址编辑；可编辑本笔法币账户不等于创建账户管理模块 |
| `AC-LS-100`、`AC-CR-31` | 商务条款摘要与本笔业务逐项一致，包括两个新增只读还款项和四要素汇率；可复制打印，明确非合同、不产生法律效力；无下载合同/模板入口，无模板未配置导致无法接受 |
| `AC-LS-100`（映射 `D-FIN-93`、`E-CR-09`） | 盖章件至少1个最多5个，PDF/JPG/PNG、每个≤10MB；超限或上传失败给具体反馈并保留其他成功文件。无文件或未勾选条款一致性声明均不可接受；不要求完成平台合同审核 |
| `AC-LS-102` | 接受三步中途离开可续做，已确认账户与进度保留，状态仍待接受，计时不停；再次进入已失效则只能看终结结果，不能靠保留进度继续提交 |
| `AC-LS-100`（映射 `D-FIN-89`～`91`） | 接受完成直接待放款，无盖章件待审核状态；资金方能在放款前查看盖章件、后续模块承接问题处置；游客不能获取附件，界面无“平台已审核”暗示 |
| `AC-FIN-23`、`AC-FIN-27` | 接受不增加或释放项目在途金额，不释放机构在途报价金额、不提前生成授信占用额；放款确认才转移。接受后报价倒计时消失 |
| `AC-CR-12` | 无需填写接受三步即可拒绝；原因必填1～200字，对机构可见，无审核/冷却。已拒绝、需求解锁、在途报价全额释放、项目在途不变、质押不释放五项同次生效 |
| `AC-CR-07`（边界 `E-CR-05`） | 授信在报价成功后到期，仍可接受存量报价；不得把新报价的到期授信阻断规则错用于已锁定报价 |
| `AC-CR-18`（边界 `E-CR-06`/`19`） | 接受前覆盖提醒可见但不另设接受准入；先终结的报价不可接受，有效接受先完成则后续覆盖交放款闸门处理。任何竞争只有一个生效结果，不翻转已确认状态 |

<a id="lifecycle"></a>
## 四、额度保持释放与需求失效联动

对应 `F-LS-27`、`F-LS-35`，规则见[功能四](01-功能需求说明.md#lifecycle)，图 `FL-CR-03`、`ST-CR-03`。分别以只含一笔业务的二元组验证归零，再用有其他存量业务的二元组验证互不误清。

| 验收编号 | 场景与预期结果 |
| --- | --- |
| `AC-CR-09` | 拒绝、超时失效、需求失效、裁决终止、结清五条完整终结路径后，本笔在途报价金额和授信占用额贡献均归零；无其他业务时两合计量也归零，可用授信恢复。存在其他业务时只释放本笔，不把二元组整体清空 |
| `AC-CR-15`、`AC-LS-118` | 同额报价拒绝与届满两条路径，对在途报价金额、项目在途金额、质押的结果一致；区别是已拒绝与已失效、用户原因与系统原因。有效需求退回待报价且其他机构可立即报价 |
| `AC-CR-21`、L5 `D-FIN-75` | 需求被证实覆盖不足：L5需求终结/项目在途释放、L6报价落已失效/机构在途释放同事件完成，页面看不到中间态，不能要求L5代执行报价状态 |
| `AC-CR-23`、`AC-LS-115` | 需求失效无缓冲期或恢复倒计时，融资报价和报价确认均无可点按钮，终结原因可见；补足覆盖不能恢复旧报价，只能按L5重发并重新报价 |
| `AC-CR-18` | 接受、拒绝与到期失效竞争时只允许一个最终结果，金额只释放一次、消息只发一次；到期及之后不可接受，迟到操作得到可读解释 |
| `AC-CR-19` | 超时失效时间为原168小时截止；需求失效时间为实际需求终结时刻。不得把需求失效写成未来的报价到期时刻 |
| `AC-FIN-27` | 放款确认完成时，机构在途报价→授信占用、项目在途→项目融资余额同时转移；无双计、无两个量均未计入的空档，金额以融资金额而非实收计 |
| `AC-FIN-28` | 待接受报价拒绝或在途业务裁决终止，只移出相关在途报价金额，不转入授信占用额；项目侧释放按具体事件：拒绝保留需求项目在途金额，需求失效释放它，不能一概同时清零 |
| `AC-CR-09`（还款承接） | 机构确认单期已偿本金后授信占用额等额递减，结清后本笔归零；利息或手续费不得作为本金释放金额 |
| `AC-CR-09`（反向） | 授信到期、项目到期有存量、接受、放款异议驳回、逾期标记均不能提前释放；不存在以撤下已锁定需求或关闭有存量项目绕过约束的路径 |
| `AC-LS-118`（项目到期边界） | 报价被拒/届满可以解锁，但项目若已到期，新报价仍被拦截；不把“退回待报价”当作取消L5到期约束 |

下游动作未在本轮实施；上述全链路结果必须在放款/还款联合验收时观测，PRD入库不代表下游已实现。

## 五、页面增量、跳转与通知

对应 `F-LS-31`～`F-LS-33`，规则见[功能五](01-功能需求说明.md#presentation)，图 `ST-CR-03`。

| 验收编号 | 场景与预期结果 |
| --- | --- |
| `AC-LS-117` | L5下发的五值在列表、详情、控制台一致；成功报价推动已报价待确认，接受推动放款中，拒绝/届满对有效需求回待报价，需求失效用L5终结结果；无自建对外状态 |
| `AC-LS-119`、`AC-LS-103` | 三个承载单元均在详情页操作区，授信是报价内步骤；平台判定可做动作，非当前环节无可点按钮，角色不符不可执行；游客操作区只有立即登录 |
| `AC-LS-98`、`AC-LS-104` | 登录态下覆盖不足、他方已报价、项目到期、自有需求等原因可区分并给出出路；不只说“暂不可操作”。游客不再逐动作解释 |
| `AC-LS-105`、L5 `H-02` | 跳转重新判权；报价已处理落详情并解释，不开旧操作层；游客仍可看公开内容但不可写；草稿隐藏存在性，无白屏/静默跳首页 |
| `AC-LS-07`、`AC-MC-11` | 没有独立授信落地页或“去授信”入口；控制台不执行本模块写动作，已有业务跳转落广场详情；控制台来源可返回对应位置 |
| `AC-LS-106`、`AC-LS-107`、`AC-LS-116` | 授信额度、两类金额、状态与锁定信息同源，业务量使用全称，使用质押覆盖状态既定术语；不把合计量再当独立占用量 |
| `AC-LS-120` | 界面无内部判据、条款/字段编号、来源论证、运行机制说明；仍有本次报价/可用授信/差额三数算式、锁定与时限、失败出路，不能连用户金额也删掉 |
| `AC-LS-108` | 提交、临期、失效、接受、拒绝五类通知分别在对应事件发给指定主体；临期只在尚待接受且到期前24小时一次；重复提交/补做不重复发，新业务不被旧业务覆盖 |
| `AC-LS-108`（失效分因） | 届满与需求失效共用报价失效通知但原因、下一步不同；同一报价事件每位收件人一条，不代发或取消L5需求失效通知 |
| `AC-LS-109` | 核定、追加、授信到期不发授信消息；无周期锁定提醒或多档临期提醒。通知失败时页面倒计时与结果仍可见且不暂停期限 |
| `AC-LS-108`（跳转与隔离） | 通知只到借贷平台相关主体账号，无他方授信或公开附件泄露；到达后状态已变能看历史，不执行过时动作。消息分类/正式模板与共享登记适配完成后才能判该项整体通过 |

`AC-CR-40`（`D-CR-58`、`F-LS-32`/`33`）：企业→条件→协议的阅读顺序明确；报价页仍为两段且可查看企业资料和授信历史。二次确认返回、接受步骤往返、语言切换不丢有效输入或成功文件；不因回退暂停168小时。桌面及窄屏的长名称/地址/文件名可读，错误与主动作不被遮挡，键盘可达，无嵌套操作层。企业资料、授信协议、融资合同分别标识，不扩大公开范围；返回详情落回原发起处，已有L5动作和布局不受本轮增量改变。

## 六、质量与验收边界

按[功能册六](01-功能需求说明.md#dependencies)核验授信判定≤1秒、提交结果≤2秒、当场覆盖判断目标≤1秒；不能为了满足反馈时间用旧数据放行。到期效力立即成立，基线处理反馈目标≤1分钟、最坏≤5分钟不构成可继续接受的窗口。可追溯每笔状态、金额、账户确认、合同声明和锁定汇率，无越权执行、重复编号或金额重复释放。

默认英文、中英切换、时区标注、金额币种、窄屏操作、键盘可达、状态文字按平台既有基线验证。本轮只交PRD，未完成原型或运行系统验收；不得把文档检查写成产品功能已通过。

`Q-CR-07` 追加有效期上限基点、`Q-CR-08` 账号/IBAN格式、`Q-CR-09` 结算精度，以及主体英文名补登、企业基本资料供给与展示授权（`DEP-27`）、通知适配尚须承接。可先验证已明确行为；对应边界未定/依赖未就绪不得宣称全量通过。汇率四要素、复用、取数失败拒绝等硬要求不因此延期或降级。

## 七、既有业务指标

仅沿用基线观测口径，不增加达标阈值或采集实现。指标不改变上述验收条件，也不新增报价修改、冷却或审批能力。

| 原编号 | 观测内容 |
| --- | --- |
| `M-LS-14`～`M-LS-17` | 报价入口→表单→成功漏斗，授信四分支占比、授信不足放弃情况、机构及二元组授信额度利用率 |
| `M-LS-18`/`19`/`20`/`22` | 决策耗时分接受/拒绝/超时/需求失效，超时失效比例、接受与拒绝率、接受耗时；接受/拒绝率不将系统失效计入分母 |
| `M-LS-21`/`23` | 接受三步停留与流失、户名不匹配拦截及未登记英文名原因 |
| `M-LS-24`/`25` | 已终结业务仍有金额未释放、授信不变式异常，均应为零 |
| `M-LS-26`～`M-LS-29` | 临期提醒后24小时内处理比例、需求失效连带报价数及来源、同机构同项目30天重复报价数、失效后重发比例与间隔；重发观察窗口沿基线未指定，不自定数值 |
