## FL-CR-01 资金方授信与报价

关联需求：`F-LS-20`～`F-LS-26`、`F-LS-36`、`D-CR-54`～`57`、`AC-CR-33`～`39`、`AC-CR-03`/`04`/`13`/`20`～`22`。正文：[功能一](01-功能需求说明.md#credit)、[功能二](01-功能需求说明.md#quote)；验收：[一](02-验收需求说明.md#credit)、[二](02-验收需求说明.md#quote)。

```mermaid
flowchart TD
  A["资金方：详情页当前环节点融资报价"] --> B{"当前身份与需求允许报价？"}
  B -- "否" --> X["留在详情，说明原因；游客仅登录引导"]
  B -- "是" --> C{"授信判定"}
  C -- "生效且充足" --> Q["同一弹窗：报价表单"]
  C -- "无额度 / 不足 / 已到期" --> D["有遮罩的确认：原因与后果<br/>不足时先展示三个数"]
  D -- "取消" --> E["关闭报价弹窗<br/>本次无新增授信、报价、金额变化或锁定"]
  D -- "确认" --> F["同一弹窗：核定 / 追加 / 重新核定"]
  F --> F1["查看企业基本信息<br/>填写金额与有效期，上传本次授信协议"]
  F1 --> F2{"输入合规且1至10份协议均上传成功？"}
  F2 -- "否" --> F3["就地说明问题，保留有效输入和成功文件<br/>修改、重试或移除后继续"]
  F3 --> F1
  F2 -- "是" --> G["资金方提交授信"]
  G -- "失败" --> F3
  F1 -- "取消，确认放弃未提交改动" --> E
  G -- "成功：授信生效，协议随本次留存" --> H{"当前覆盖与授信同时通过？"}
  H -- "授信仍不足" --> F
  H -- "需求失效或状态已变" --> X
  H -- "无法完成当前校验" --> U["拒绝继续提交，说明可重试<br/>已生效授信保留"]
  H -- "是" --> Q
  Q --> R["选择币种、填写利率<br/>查看只读金额、汇率、还款方式与期限"]
  R --> S["显式确认锁定需求、在途报价金额与七天期限"]
  S --> T{"提交时全部条件仍满足？"}
  T -- "汇率或覆盖数据不可得" --> U
  T -- "覆盖不足已证实" --> V["需求当场失效并按FL-CR-03联动<br/>本次无编号、无新增在途报价金额"]
  T -- "被他人报价 / 到期 / 已撤下" --> X
  T -- "授信不足" --> F
  T -- "满足且本笔成功" --> W["同一事件：新业务编号、锁定汇率、开始168小时<br/>在途报价金额增加，业务待接受，需求锁定<br/>项目在途金额不变"]
```

企业基本信息缺项不新增准入条件，归属无法确认仍不可提交。额度充足的直接报价分支不强制补交历史授信协议。上传失败/处理中不新增授信状态。

授信提交成功后是独立事实，后续报价取消或失败不回滚。图中数据不可得与覆盖不足已证实是不同出口，前者不得触发需求失效。

## FL-CR-02 资产方接受或拒绝

关联需求：`F-LS-28`～`F-LS-30`、`AC-CR-12`、`AC-LS-100`/`102`/`111`。正文：[功能三](01-功能需求说明.md#respond)；验收：[三](02-验收需求说明.md#respond)。

```mermaid
flowchart TD
  A["资产方：本企业详情页打开报价确认"] --> B{"本笔仍待接受且未届满？"}
  B -- "否" --> X["落详情，说明当前结果"]
  B -- "是" --> C["查看条款、当前池况、锁定信息与倒计时"]
  C --> D{"资产方决定"}
  D -- "拒绝" --> R["填写1至200字拒绝原因"]
  R --> R1{"仍可拒绝且原因有效？"}
  R1 -- "否" --> X
  R1 -- "是" --> R2["已拒绝；本笔在途报价金额释放<br/>向L5提供解锁结果<br/>项目在途金额与质押不变"]
  D -- "接受" --> E["填写法币账户或查看统一数币地址<br/>按本笔内容显式确认"]
  E --> F{"账户校验通过并已确认？"}
  F -- "否" --> E1["具体原因与可行动出路<br/>户名不符不可绕过"]
  E1 --> E
  F -- "是" --> G["查看商务条款摘要<br/>手续费与本金告知清楚可见"]
  G --> H["双方在线下拟定并签署合同"]
  H --> I["资产方上传本笔融资合同盖章件：1至5份<br/>单份不超过10MB，勾选条款一致性声明"]
  I --> J["资产方确认接受"]
  J --> K{"三步齐备且报价仍有效？"}
  K -- "状态已变或到期" --> X
  K -- "内容不完整" --> I
  K -- "是" --> L["待放款；报价计时停止<br/>两类在途金额保持<br/>资金方在放款环节核验合同"]
```

授信协议属于资金方授信操作，不能代替本图的融资合同盖章件；最多10份的授信要求不改变本图5份上限。三步可中断续做，但状态一直待接受、计时不停。拒绝不要求先完成三步。接受不新增覆盖准入，已失效报价仍不可接受；并发判定按正文 `E-CR-19`。

<a id="fl-cr-03"></a>
## FL-CR-03 两种失效与金额联动

关联需求：`F-LS-27`/`34`/`35`、`D-CR-30`/`31`、`AC-CR-09`/`15`/`18`/`19`，L5 `D-FIN-75`。正文：[功能四](01-功能需求说明.md#lifecycle)；验收：[四](02-验收需求说明.md#lifecycle)。

```mermaid
flowchart TD
  A["报价成功后168小时届满"] --> C{"该笔是否仍待接受？"}
  B["L5确认所属需求因覆盖不足失效<br/>包括L6报价终检发现"] --> C
  C -- "已接受 / 已拒绝 / 已失效" --> N["不按待接受报价再次处理<br/>不重复释放或通知"]
  C -- "仍待接受" --> D{"失效原因"}
  D -- "有效期届满" --> E["同一事件：L6报价已失效<br/>本笔在途报价金额全额释放<br/>L5解锁有效需求<br/>项目在途金额不变，质押不释放"]
  D -- "所属需求失效" --> F["同一事件：L5需求终结并释放其项目在途金额<br/>L6报价已失效并释放本笔在途报价金额"]
  E --> G["保留业务编号、历史快照与失效原因<br/>双方各收到本笔失效通知"]
  F --> G
  G --> H{"需求与项目仍允许新报价？"}
  H -- "是" --> I["任何机构可新报：新编号、新快照、新期限"]
  H -- "需求失效" --> J["资产方按L5补足覆盖并重发<br/>旧报价不能恢复"]
  H -- "项目到期等其他条件不满足" --> K["展示当前条件与不可报价原因"]
```

到期及之后不得接受；到期前接受已成功则不再按报价期限终结。需求先失效时其待接受报价不能随后成功接受。重复事件不改变已确定结果，不能产生半完成的状态和金额展示。

## FL-CR-04 汇率来源与业务沿用

关联需求：`F-LS-26`、`D-FIN-17`/`80`/`81`、`E-CR-18`。正文：[功能二2.2](01-功能需求说明.md#quote)；验收：[二·汇率业务验收](02-验收需求说明.md#quote)。

```mermaid
flowchart LR
  A["代币发行平台<br/>唯一汇率源"] -. "业务依据" .-> B["资金方查看结算金额与汇率方向"]
  B --> C{"提交时可取得完整依据？"}
  C -- "否" --> D["拒绝提交，无新报价<br/>不使用旧汇率或缓存放行"]

  E --> F["本笔放款沿用原快照"]
  E --> G["本笔还款沿用原快照"]

  A -. "后续行情不改写旧业务" .-> H
```

图表达业务依赖，不规定获取方式。相同标识、相同原金额在放款与还款得出相同折算值；报价锁定后上游不可用不改变本平台已持有的快照。

<a id="st-cr-01"></a>
## ST-CR-01 授信对象生命周期

关联需求：`F-LS-21`/`22`、`D-CR-10`～`15`/`19`/`20`/`42`、`D-CR-55`～`57`。正文：[功能一](01-功能需求说明.md#credit)；验收：[一](02-验收需求说明.md#credit)。

```mermaid
stateDiagram-v2
  state "S-CR-1 生效中" as ACTIVE
  state "S-CR-2 已到期" as EXPIRED
  [*] --> ACTIVE: 金额、有效期及协议齐备，首次核定成功
  ACTIVE --> ACTIVE: 正金额追加与本次协议齐备，日期保持或合规延长
  ACTIVE --> EXPIRED: 授信有效期届满
  EXPIRED --> ACTIVE: 报价流程内金额、日期及协议齐备，重新核定成功
```

一条授信关系对应机构×资产方，与单个项目无关。到期只关新增，不动存量；无冻结、停用、审核中状态。重新核定不覆盖历史，不因报价失败回滚。

## ST-CR-02 融资业务的本模块覆盖段

关联需求：`F-LS-25`/`27`～`30`/`34`/`35`、`D-FIN-77`/`78`/`92`。正文：[功能三](01-功能需求说明.md#respond)、[功能四](01-功能需求说明.md#lifecycle)；验收：[三](02-验收需求说明.md#respond)、[四](02-验收需求说明.md#lifecycle)。

```mermaid
stateDiagram-v2
  state "S-FD-1 待接受" as WAIT
  state "S-FD-2 已拒绝" as REJECTED
  state "S-FD-11 报价已失效" as EXPIRED
  state "S-FD-3 待放款" as FUNDING
  [*] --> WAIT: 成功报价，产生业务编号与在途报价金额
  WAIT --> WAIT: 账户确认、摘要查看、盖章件上传，仅填写进度
  WAIT --> REJECTED: 资产方有效拒绝，原因必填
  WAIT --> EXPIRED: 168小时届满仍待接受
  WAIT --> EXPIRED: 所属需求失效且本笔仍待接受
  WAIT --> FUNDING: 三步齐备且有效接受
  REJECTED --> [*]
  EXPIRED --> [*]
  note right of FUNDING
    后续状态与时限由放款、还款模块承接
    此处不是融资业务终态
  end note
```

已拒绝与报价已失效是不同终态，均保留编号且不能恢复。填写进度不是新状态；待放款仍属于在途报价金额，放款确认完成才转成授信占用额。

## ST-CR-03 L5对外五值的本模块协作视图

关联需求：`F-LS-31`/`32`、`D-LS-28`～`32`、`AC-LS-117`/`118`，L5 `AC-LS-93`。正文：[功能四](01-功能需求说明.md#lifecycle)、[功能五](01-功能需求说明.md#presentation)；验收：[四](02-验收需求说明.md#lifecycle)、[五](02-验收需求说明.md#presentation)。

**这不是另一套需求状态机。** 五值与派生规则唯一来源为[L5功能册11.6](../v1.0-借贷广场-融资需求与代币质押/01-功能需求说明.md)；图只标本模块提供哪些事实。

```mermaid
flowchart LR
  A["待报价"] -->|"L6报价成功"| B["已报价待确认"]
  B -->|"L6有效接受"| C["放款中"]
  B -->|"L6拒绝或报价届满<br/>需求仍有效"| A
  A -. "L5需求失效或关闭" .-> E["已失效／已关闭"]
  B -. "L5需求失效<br/>L6同事件终结报价" .-> E
  C -. "后续放款模块结果" .-> D["已放款"]
```

仅两个向前跃迁属于L6：成功报价与有效接受；回退与连带终结按正文对应结果协作。页面消费L5下发值，不能以这张简图重新推导完整映射。项目已到期时是否可新增报价仍受L5约束，回退标签不取消到期限制。
