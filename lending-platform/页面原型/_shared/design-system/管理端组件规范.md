# 管理端组件规范

## 1. 范围与视觉口径

本规范面向**运营管理平台**：账户设置及业务页使用 `layout: 'app'`；登录、首登改密、找回及重置密码使用 `layout: 'focus'`。范围包括运营端账户与登录、资金方机构认证审核、代币质押审核、消息通知、协议管理。

实现以 [`../base.css`](../base.css) 的 `.app` / `.sidebar` / `.topbar` / `.content` 与公共组件为准，token 以 [`../tokens.css`](../tokens.css) 为准；本文不复述数值。

核心特征：标准管理平台形态——固定左侧栏、紧凑顶栏、清晰的表格边界、高信息密度。与面客端**共用同一套色板与组件**，差别只在密度 token。

## 2. Shell

| 元素 | 规则 | 禁止用法 |
| --- | --- | --- |
| 应用框架 | 定宽左侧栏 + 右侧主内容区；侧栏全高、右边线清晰，内容区 `min-width: 0` | 把侧栏做成可无限展开的多级树 |
| 侧栏 | 品牌区、低强调分组标签、紧凑导航项、底部当前操作员上下文 | 模块自建菜单；把流程页登记成侧栏条目 |
| 顶栏 | sticky；轻量全局工具区靠右，不放面包屑 | 在顶栏堆业务操作 |
| 面包屑 | 位于页面内容区、标题上方，与正文左边界对齐并随内容滚动。按可用模块根页、父级、当前页逐级展示；上级可点、当前页不可点 | 放入顶部工具栏；同时附加「返回上级」按钮 |
| 画布 | 不设固定 `max-width`，铺满侧栏之外的可用宽度，只保留横向安全边距；标题区后接统计 / 筛选 / 内容卡，不压成一张巨型卡 | 用官网层的宽留白、展示型大标题或入口卡替代高密度画布 |

## 3. 页面形态

管理端的功能点基本是这几种，按一致的一套设计，不是各做各的：

| 形态 | 必须承载 |
| --- | --- |
| 列表 / 台账 | 与 PRD 筛选字段一一对应的筛选条、字段目录给的列集、排序、带总数的分页、行操作、需要时的批量操作、固定操作列 |
| 详情 | key / value 栅格、状态标记、附件预览与兜底、关联记录链接 |
| 表单 / 上传弹层 | 字段级校验与真实上限（大小、长度、格式）、被操作对象的只读反显、规则要求的二次确认、提交进度与幂等反馈 |
| 审批 / 复核 | 经办人提交 → 审核员复核、节点状态、驳回原因、每个角色在每个节点看到什么 |
| 记录 / 版本历史 | PRD 给的字段集与顺序、只增不改的语义、以及这本台账**不**记录什么 |
| 总览 | 只放 PRD 点名的卡片，不自造 KPI 砖 |

## 4. 组件

| 组件 | 规则 | 禁止用法 |
| --- | --- | --- |
| 数据表 | 浅色表头、大写小字距列名、紧凑行高、右对齐数值与结构化值、操作列固定在右 | 操作列在 1280px 下消失或被裁 |
| 行操作 | 文字链，主操作在前；不可用的操作保留并禁用，`title` 给出原因 | 把不可用的操作直接删掉，让不同行的操作列长短不一 |
| 筛选条 | 与表格同卡，位于表头之上 | 把筛选做成抽屉，让用户看不到当前条件 |
| 状态标记 | 色点 + 文字，语义色成套 | 只靠颜色区分状态 |
| 抽屉 / 弹窗 | 详情与二次确认用；弹窗层级高于抽屉 | 在抽屉里再开抽屉 |
| 空态 / 失败态 | 标题 + 一句原因 + 修复动作 | 用一张灰图配「暂无数据」四个字了事 |

## 5. 角色与权限

- 角色差异通过**可达的视图**体现：菜单、列集、操作、权限都要真的变。
- 越权写必须有可见反馈——按钮禁用并给原因，或提交后给明确拒绝提示，不是静默无事发生。
- 双人复核是要演示的流程，不是一句说明。

## 6. 必须覆盖的状态

默认 · 加载中 · 空数据 · 筛选无结果 · 加载失败可重试 · 无权限 · 提交中 · 提交失败 · 异步等待接口返回。只实现该功能实际适用的那些。

## 7. 响应式验收

管理端默认验收 1280 / 1440 / 1920 三档：无横向溢出、侧栏不压内容、操作列可达、无控件被裁。模块已确认的响应式范围优先：运营端账户与登录同时保留 375 / 414 / 768；其余模块不据此自动扩大范围。

## 8. 运营端账户与登录：已确认组合

本节由 WS-357 已确认原型（`bc056bd`）及用户反馈反向整理；实现见 [账户与登录](../../管理端/账户与登录/README.md)、[模块样式](../../管理端/账户与登录/账户与登录.css) 与 [交互](../../管理端/账户与登录/账户与登录.js)。通用母版不得覆盖下列已定内容，不要求其他模块照搬。

| 页面 / 组件 | 已确认结构与交互 |
| --- | --- |
| 登录与受限流程 | 使用公共 focus 壳层，仅品牌、语言及必要退出入口。初始邮箱与密码由建设方提供；无注册、邀请、开户或角色选择入口。首登受限时不能进入业务页 |
| 首登改密 | 只展示新密码和确认新密码；不再次输入当前密码。成功后重新登录。账户内改密、换邮箱仍先以当前密码再认证 |
| 密码框 | 眼睛／划线眼睛图标切换；动态无障碍名称说明下一步动作。保留输入值和键盘焦点，不用“显示／隐藏”文字占据框内空间 |
| 密码反馈 | 规则就近展示；确认密码不一致时就地提示并阻止提交，修改任一输入使两者匹配后清除。空错误区不占额外一行，错误出现时展开；提交失败后定位首个错误字段 |
| 邮箱验证码 | 从初始状态即呈现同一行：输入框在左、获取验证码按钮在右；验证／确认主按钮在下方。发码前保留人机校验，发送后显示重发倒计时，失败后可重试；找回与换邮箱使用同一组合 |
| 账户设置 | 整页纵向两组：账号信息在上，偏好信息在下，不改回左右布局。保留邮箱、姓名、角色、状态、密码、最近登录与创建时间；不展示已开通权限清单 |
| 分区导航 | 账号信息／偏好信息用于跳转到同页分区，两组同时存在；不是互斥 tab 面板。键盘激活后焦点到达目标分区 |
| 邮箱与密码修改 | 账户页文字操作进入居中弹窗；再认证后进入编辑，人机校验结束回到当前编辑上下文。沿用共享弹层、关闭和焦点约束，不改为抽屉或新增菜单 |
| 偏好与角色 | 语言、时区在下方偏好区修改；两类角色共用本人账户页面，权限差异由可用功能与实际校验体现，不增设账号授权管理界面或 SPV 专属账号 |
| 运营落点 | 普通登录进入现有运营总览或恢复原受保护页面；首登先改密。面客端资产广场默认入口不适用于运营端；账户设置仍由账号菜单进入 |

视觉继承公共 token、focus/app 壳层、输入框、按钮、状态标记和弹窗。侧栏品牌名与副标题分行显示，避免副标题被挤断；业务页面不出现规则编号、字段来源或内部交付说明。演示工具默认关闭，认证、邮件与安全策略仍是本地模拟。

## 消息通知阅读页

消息通知使用共享 `.nc-*` 阅读组件与 `.om-*` 管理端组合：独立整页列表和详情，白底分隔行、已读/未读标签、整行链接；不设置逐条标为已读按钮。分类与状态筛选置于同一列表卡顶部，页码与每页 20 / 50 / 100 条置于底部。全部已读在页头，经范围确认后执行。消息入口只在顶栏铃铛和账号菜单。此约定不修改其他模块的表格与抽屉形态。
