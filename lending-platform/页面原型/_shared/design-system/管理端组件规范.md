# 管理端组件规范

## 1. 范围与视觉口径

本规范面向**运营管理平台**（`layout: 'app'`）：运营端账户与登录、资金方机构认证审核、代币质押审核、消息通知、协议管理。

实现以 [`../base.css`](../base.css) 的 `.app` / `.sidebar` / `.topbar` / `.content` 与公共组件为准，token 以 [`../tokens.css`](../tokens.css) 为准；本文不复述数值。

核心特征：标准管理平台形态——固定左侧栏、紧凑顶栏、清晰的表格边界、高信息密度。与面客端**共用同一套色板与组件**，差别只在密度 token。

## 2. Shell

| 元素 | 规则 | 禁止用法 |
| --- | --- | --- |
| 应用框架 | 定宽左侧栏 + 右侧主内容区；侧栏全高、右边线清晰，内容区 `min-width: 0` | 把侧栏做成可无限展开的多级树 |
| 侧栏 | 品牌区、低强调分组标签、紧凑导航项、底部当前操作员上下文 | 模块自建菜单；把流程页登记成侧栏条目 |
| 顶栏 | sticky；面包屑在左、轻量工具区在右。面包屑按可用模块根页、父级、当前页逐级展示，上级可点；「返回上级」直达父级，根页不显示返回；当前页不可点 | 在顶栏堆业务操作 |
| 画布 | 不设固定 `max-width`，铺满侧栏之外的可用宽度，只保留横向安全边距；标题区后接统计 / 筛选 / 内容卡，不压成一张巨型卡 | 用官网层的宽留白、展示型大标题或入口卡替代高密度画布 |

## 3. 页面形态

管理端的功能点基本是这几种，按一致的一套设计，不是各做各的：

| 形态 | 必须承载 |
| --- | --- |
| 列表 / 台账 | 与 PRD 筛选字段一一对应的筛选条、字段目录给的列集、排序、带总数的分页、行操作、需要时的批量操作、固定操作列 |
| 详情 | key / value 栅格、状态标记、附件预览与兜底、关联记录链接 |
| 表单 / 上传弹层 | 字段级校验与真实上限（大小、长度、格式）、被操作对象的只读反显、规则要求的二次确认、提交进度与幂等反馈 |
| 审批 / 复核 | 经办人提交 → 审核员复核、节点状态、驳回原因、每个角色在每个节点看到什么 |
| 记录 / 版本历史 | PRD 给的字段集与顺序、只增不改的语义、以及这本台账**不**记录什么 |
| 总览 | 只放 PRD 点名的卡片，不自造 KPI 砖 |

## 4. 组件

| 组件 | 规则 | 禁止用法 |
| --- | --- | --- |
| 数据表 | 浅色表头、大写小字距列名、紧凑行高、右对齐数值与结构化值、操作列固定在右 | 操作列在 1280px 下消失或被裁 |
| 行操作 | 文字链，主操作在前；不可用的操作保留并禁用，`title` 给出原因 | 把不可用的操作直接删掉，让不同行的操作列长短不一 |
| 筛选条 | 与表格同卡，位于表头之上 | 把筛选做成抽屉，让用户看不到当前条件 |
| 状态标记 | 色点 + 文字，语义色成套 | 只靠颜色区分状态 |
| 抽屉 / 弹窗 | 详情与二次确认用；弹窗层级高于抽屉 | 在抽屉里再开抽屉 |
| 空态 / 失败态 | 标题 + 一句原因 + 修复动作 | 用一张灰图配「暂无数据」四个字了事 |

## 5. 角色与权限

- 角色差异通过**可达的视图**体现：菜单、列集、操作、权限都要真的变。
- 越权写必须有可见反馈——按钮禁用并给原因，或提交后给明确拒绝提示，不是静默无事发生。
- 双人复核是要演示的流程，不是一句说明。

## 6. 必须覆盖的状态

默认 · 加载中 · 空数据 · 筛选无结果 · 加载失败可重试 · 无权限 · 提交中 · 提交失败 · 异步等待接口返回。只实现该功能实际适用的那些。

## 7. 响应式验收

1280 / 1440 / 1920 三档：无横向溢出、侧栏不压内容、操作列可达、无控件被裁。**1280 以下不在范围内**，不花精力也不声称支持。

## 消息通知阅读页

消息通知使用共享 `.nc-*` 阅读组件与 `.om-*` 管理端组合：独立整页列表和详情，白底分隔行、已读/未读标签、整行链接；不设置逐条标为已读按钮。分类与状态筛选置于同一列表卡顶部，页码与每页 20 / 50 / 100 条置于底部。全部已读在页头，经范围确认后执行。消息入口只在顶栏铃铛和账号菜单。此约定不修改其他模块的表格与抽屉形态。
