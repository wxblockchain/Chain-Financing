# 管理端组件规范

## 1. 范围与视觉口径

本规范面向**运营管理平台**：账户设置及业务页使用 `layout: 'app'`；登录、首登改密、找回及重置密码使用 `layout: 'focus'`。范围包括运营端账户与登录、资金方机构认证审核、代币质押审核、消息通知、协议管理、合约管理、融资参数配置。

实现以 [`../base.css`](../base.css) 的 `.app` / `.sidebar` / `.topbar` / `.content` 与公共组件为准，token 以 [`../tokens.css`](../tokens.css) 为准；本文不复述数值。

核心特征：标准管理平台形态——固定左侧栏、紧凑顶栏、清晰的表格边界、高信息密度。与面客端**共用同一套色板与组件**，差别只在密度 token。

## 2. Shell

| 元素 | 规则 | 禁止用法 |
| --- | --- | --- |
| 应用框架 | 定宽左侧栏 + 右侧主内容区；侧栏全高、右边线清晰，内容区 `min-width: 0` | 把侧栏做成可无限展开的多级树 |
| 侧栏 | 品牌区、低强调分组标签、紧凑导航项；不展示底部账户信息。菜单由 `admin-menu.js` 统一声明 | 模块自建菜单；把流程页登记成侧栏条目 |
| 顶栏 | sticky；右侧依次为消息铃铛、语言、邮箱地址。账户悬浮菜单展示只读角色“管理员”（专员保留实际角色）、消息中心、账户设置、退出登录；复用 `admin-menu.js` 与 `admin-notifications.js` | 在顶栏堆业务操作；各模块复制账户或铃铛实现；用“我的账户”替代邮箱 |
| 面包屑 | 一级页面不展示面包屑或占位；详情位于页面内容区、标题上方，与正文左边界对齐并随内容滚动。只按真实父级、当前页逐级展示；上级可点、当前页不可点 | 放入顶部工具栏；同时附加「返回上级」按钮 |
| 画布 | 不设固定 `max-width`，铺满侧栏之外的可用宽度，只保留横向安全边距；标题区后接统计 / 筛选 / 内容卡，不压成一张巨型卡 | 用官网层的宽留白、展示型大标题或入口卡替代高密度画布 |

## 3. 页面形态

管理端的功能点基本是这几种，按一致的一套设计，不是各做各的：

| 形态 | 必须承载 |
| --- | --- |
| 列表 / 台账 | 与 PRD 筛选字段一一对应的筛选条、字段目录给的列集、排序、带总数的分页、行操作、需要时的批量操作、固定操作列 |
| 详情 | key / value 栅格、状态标记、附件预览与兜底、关联记录链接 |
| 表单 / 上传弹层 | 字段级校验与真实上限（大小、长度、格式）、被操作对象的只读反显、规则要求的二次确认、提交进度与幂等反馈 |
| 审批 / 复核 | 经办人提交 → 审核员复核、节点状态、驳回原因、每个角色在每个节点看到什么 |
| 记录 / 版本历史 | PRD 给的字段集与顺序、只增不改的语义、以及这本台账**不**记录什么 |
| 总览 | 只放 PRD 点名的卡片，不自造 KPI 砖 |

## 4. 组件

| 组件 | 规则 | 禁止用法 |
| --- | --- | --- |
| 数据表 | 浅色表头、大写小字距列名、紧凑行高、右对齐数值与结构化值、操作列固定在右 | 操作列在 1280px 下消失或被裁 |
| 行操作 | 文字链，主操作在前；不可用的操作保留并禁用，`title` 给出原因 | 把不可用的操作直接删掉，让不同行的操作列长短不一 |
| 筛选条 | 与表格同卡，位于表头之上 | 把筛选做成抽屉，让用户看不到当前条件 |
| 状态标记 | 色点 + 文字，语义色成套 | 只靠颜色区分状态 |
| 抽屉 / 弹窗 | 详情与二次确认用；弹窗层级高于抽屉 | 在抽屉里再开抽屉 |
| 空态 / 失败态 | 标题 + 一句原因 + 修复动作 | 用一张灰图配「暂无数据」四个字了事 |

## 5. 角色与权限

- 角色差异通过**可达的视图**体现：菜单、列集、操作、权限都要真的变。
- 越权写必须有可见反馈——按钮禁用并给原因，或提交后给明确拒绝提示，不是静默无事发生。
- 双人复核仅在对应模块明确要求时演示；不能据通用形态为 WS-358 增加查询岗、处置岗或复核岗。
- 处置类权限缺少配套查询权限时，动作被拒绝并说明须由建设方修正交付配置，不静默通过也不自动补授权。
- 同一业务模块只要还有一项可读能力，其入口仍须可达；能看到入口不等于能读取目标，目标权限在进入后单独判定。

## 6. 必须覆盖的状态

默认 · 加载中 · 空数据 · 筛选无结果 · 加载失败可重试 · 无权限 · 提交中 · 提交失败 · 异步等待接口返回。只实现该功能实际适用的那些。

## 7. 响应式验收

管理端默认验收 1280 / 1440 / 1920 三档：无横向溢出、侧栏不压内容、操作列可达、无控件被裁。模块已确认的响应式范围优先：运营端账户与登录同时保留 375 / 414 / 768；其余模块不据此自动扩大范围。

## 8. 运营端账户与登录：已确认组合

本节由 WS-357 已确认原型（`bc056bd`）及用户反馈反向整理；实现见 [账户与登录](../../管理端/账户与登录/README.md)、[模块样式](../../管理端/账户与登录/账户与登录.css) 与 [交互](../../管理端/账户与登录/账户与登录.js)。通用母版不得覆盖下列已定内容，不要求其他模块照搬。

| 页面 / 组件 | 已确认结构与交互 |
| --- | --- |
| 登录与受限流程 | 使用公共 focus 壳层，仅品牌、语言及必要退出入口。初始邮箱与密码由建设方提供；无注册、邀请、开户或角色选择入口。首登受限时不能进入业务页 |
| 首登改密 | 只展示新密码和确认新密码；不再次输入当前密码。成功后重新登录。账户内改密、换邮箱仍先以当前密码再认证 |
| 密码框 | 眼睛／划线眼睛图标切换；动态无障碍名称说明下一步动作。保留输入值和键盘焦点，不用“显示／隐藏”文字占据框内空间 |
| 密码反馈 | 规则就近展示；确认密码不一致时就地提示并阻止提交，修改任一输入使两者匹配后清除。空错误区不占额外一行，错误出现时展开；提交失败后定位首个错误字段 |
| 邮箱验证码 | 从初始状态即呈现同一行：输入框在左、获取验证码按钮在右；验证／确认主按钮在下方。发码前保留人机校验，发送后显示重发倒计时，失败后可重试；找回与换邮箱使用同一组合 |
| 账户设置 | 整页纵向两组：账号信息在上，偏好信息在下，不改回左右布局。保留邮箱、姓名、角色、状态、密码、最近登录与创建时间；不展示已开通权限清单 |
| 分区导航 | 账号信息／偏好信息用于跳转到同页分区，两组同时存在；不是互斥 tab 面板。键盘激活后焦点到达目标分区 |
| 邮箱与密码修改 | 账户页文字操作进入居中弹窗；再认证后进入编辑，人机校验结束回到当前编辑上下文。沿用共享弹层、关闭和焦点约束，不改为抽屉或新增菜单 |
| 偏好与角色 | 语言、时区在下方偏好区修改；两类角色共用本人账户页面，权限差异由可用功能与实际校验体现，不增设账号授权管理界面或 SPV 专属账号 |
| 运营落点 | 普通登录进入现有运营总览或恢复原受保护页面；首登先改密。面客端资产广场默认入口不适用于运营端；账户设置仍由账号菜单进入 |
| 发码前的人机校验 | 用共享组件 [`_shared/puzzle.js`](../puzzle.js)，运营端不再自持第二份实现。承载弹层、取消出口与通过后的发码归模块，题目、对齐校验、失败换题与冷却归组件；连续 3 次失败提示可换题、5 次进入 60 秒冷却并按绝对时间持久化，换入口、刷新或另开标签页都不能绕过 |
| 功能权限清单 | 权限项编号、业务名称与两个预置角色的默认值维护在账户模块一处，其他管理端模块通过 `CF.opsAuth.can` 读取，不各自另建一份 |

视觉继承公共 token、focus/app 壳层、输入框、按钮、状态标记和弹窗。侧栏品牌名与副标题分行显示，避免副标题被挤断；业务页面不出现规则编号、字段来源或内部交付说明。演示工具默认关闭，认证、邮件与安全策略仍是本地模拟。

## 9. 资金方机构认证审核：已确认组合

本节由 WS-358 用户确认的布局、本册现行正文与单框驳回原型反向整理；实现见 [模块说明](../../管理端/资金方机构认证审核/README.md)、[页面组合](../../管理端/资金方机构认证审核/资金方机构认证审核.html) 与 [交互](../../管理端/资金方机构认证审核/资金方机构认证审核.js)。不以通用详情母版替换下列结构。

| 页面 / 组件 | 已确认结构与交互 |
| --- | --- |
| 审核列表 | 六列：申请编号、机构标识 / 名称、提交时间、状态、结论时间、操作；不展示版本。筛选与列表同卡，提交时间升序，保留带总数的分页，不增设统计或批量审核 |
| 审核详情 | 独立整页及自然页面滚动；左侧依次为提交信息、机构资料、材料与结论，右侧仅审核操作。右栏固定宽度并随滚动保持可达，不放目录、版本或额外信息卡 |
| 字段展示 | 标签 / 值分组；注册地址与钱包地址整行展示，长值可换行。字段中英名称取自字段命名与术语对照表，标识类型显示业务全称（统一社会信用代码 USCC / 法人机构识别编码 LEI / 商业登记号 REG_NO）。复用共享 token、card、detail-stack，模块保持已确认的密度与间距 |
| 提交材料 | 一次提交可含多份机构证明材料：分区标题带份数，逐件一行文件行，各自预览 / 下载。单件读取失败只影响该件并可重试，其余文件照常可读；运营侧没有替换、移除入口 |
| 审核记录 | 详情所有分区之后的全宽“提交与审核记录”时间线：从早到晚，成功提交和有效审核各为独立节点，分别显示操作人及时间；首次为提交申请，驳回重提为修改后提交，认证变更为变更资料提交，原因跟随驳回节点。当前待审核只标在提交节点，不生成未来审核事件。无资料副本或旧材料入口。当前已出结论时隐藏操作栏，这是本模块对通用“不可用操作保留禁用”规则的已确认例外 |
| 列表与详情关联 | 行入口为可寻址链接。详情通过父级面包屑返回，不重复摆放返回按钮；保留状态、关键词、日期、页码，返回后恢复触发行焦点与同页浏览位置。原行因结论不再满足筛选时回到筛选区，不显示另一条申请冒充原记录 |
| 旧入口 | 不生成资料版本链接。收到旧版本地址时明确提示不再提供历史资料，给出独立的当前申请入口；未知申请显示不可用态，不把当前材料冒充旧材料 |
| 材料与确认 | 材料预览、通过确认、驳回输入及核对沿用居中弹窗，不改为抽屉。加载失败与未上传分开表达，原件不可用有兜底 |
| 单一驳回原因 | 只有一个必填多行框；无字段选择、分类、中英文分填或补充框。纯空白就地报错；核对后可返回修改且保留输入，取消不生效并将焦点还给审核入口。原文换行及字符在两端、修改页和审核记录一致展示，不自动翻译 |
| 权限来源 | 会话与功能权限只读运营端账户与登录的一处登记（`CF.opsAuth.can`）：机构认证申请与材料查询、审核处置。本模块按现行正文不分查询岗与处置岗——持申请查询即可查看并处置；仅持审核处置时拒绝访问并说明须由建设方修正交付配置；两项皆无为无权限空态。菜单条目按任一项可达，登录失效走共享运营登录并在重新登录后回到原申请查询或详情 |
| 角色与流程 | 正常运营会话可查看和处置当前待审核提交，不新增运营分权或 SPV 认证。审核中材料锁定；成功提交才覆盖当前资料并增记，草稿/失败不覆盖；已认证变更成功提交才转待审核；旧动作不能审核新提交，已有结论不可翻转 |
| 面客承接 | 继续使用资金方账户模块的注册 / 状态 / 修改页。演示工具才可切换运营与申请人，产品画面不出现跨端角色切换入口。面客结果保持上下分区、首屏原因与重提、提交信息内默认折叠提交与审核时间线，审核节点只显示运营审核，隐藏审核员身份，无历史资料切换。审核中提供“查询审核结果”，进行中、仍无结论与查询失败分别反馈且不改变申请状态；客服入口与驳回原因、原因缺失、加载异常同处 |

来源页面的确认组合优先于本规范其他通用规则。正式材料政策、审核判据及未确认上传阈值不由组件规范定稿；原型里的模拟会话与异步响应不是后端授权或并发实现。


## 10. 代币质押审核：已确认组合

本节由 WS-359 用户评论 `b7b51ec0-ff9e-480d-b48f-2c663d2aa5e1`、`ae116e7d-191b-4aa4-9282-e62a3649f71a` 与其后各轮原型反向整理，并按 WS-382（2026-09-24 批：质押链路反转、审核取消时效、驳回后自助解押）更新，实现见 [模块说明](../../管理端/代币质押审核/README.md)、[页面组合](../../管理端/代币质押审核/代币质押审核.html) 和 [交互](../../管理端/代币质押审核/代币质押审核.js)。本轮历史置底来自 WS-359 自身确认，不套用 WS-358 的取消分类或无运营分权等业务规则。

| 页面 / 组件 | 已确认结构与交互 |
| --- | --- |
| 队列与统计 | 一行一笔已上链成功的代币申请，不以批次代替审核对象。八列保留单笔 / 代币 / 批次、资产方 / 目标项目、申请类型、代币价值、上链时间与已等待时长、审核状态、留存情况、操作；审核状态与留存情况分列，不合成一格。保留三项按笔统计（待审核、已驳回待解押、近 7 个自然日人工审结）与其筛选范围提示，统计与区间筛选按 UTC 自然日 |
| 筛选 | 关键词与审核状态常驻；资产方、目标项目、申请类型、上链时间区间与留存情况向下展开，默认收起；提交后保留已应用条件。日期错误展开定位，Enter 可查询；排序（上链时间 / 已等待时长 / 代币价值升降序）与带总数分页沿用共享控件 |
| 详情 | 独立页面，顶部摘要为审核状态、代币价值与本笔当前去向；左侧概览 / 关联申请两页签，右侧粘性审核区。概览按申请概览（含额度归属）→ 项目参数 → 代币事实 → 质押链上事实 → 已有结论凭据 → 操作记录排列；右侧只保留权限与状态说明、已等待时长（标明是事实陈述而非期限）和处置按钮，后续明细并入记录，不重复设卡，不设任何截止或倒计时 |

| 办理弹窗 | 通过：回显创建信息与上下文 → 勾选知悉「部署成功即审核通过、项目与合约一一对应且不可撤销」→ 在本次办理内一次提交，无第二步确认、无第二位审核人。退回：填写 10～500 字面客可读原因 → 全文预览与二次确认 → 提交，确认页写明不部署、不消耗 gas、期限不重新起算、不产生新项目编号。提交中禁用表单与重复处置，失败保留输入 |
| 台账 | 只列已部署成功的项目，一个项目一条、一个合约地址；默认部署时点倒序可切升序，按企业、代币类型、部署时间区间与关键词筛选。只读，不承载逐笔质押、额度与覆盖事实，无编辑、解绑或重新部署入口；进入审核详情后面包屑按来源返回台账并保留原筛选、排序、分页与所在位置 |
| 权限来源 | 会话与功能权限只读运营端账户与登录的一处登记（`CF.opsAuth`）：`PM-AL-17` 融资项目审核查询、`PM-AL-18` 融资项目审核与合约部署处置。持查询可看、加持处置才显示通过 / 退回 / 再次发起；`PM-AL-18` 须配套 `PM-AL-17`，仅持处置时拒绝访问并说明须由建设方修正交付配置；两项皆无为无权限空态 |

| 跨模块边界 | 与企业账户无接口：不读取、不校验、不展示任何收款账户，结算收款链不进入本模块，只表述质押链。全平台无平台统一钱包的维护、配置、切换、余额或充值入口；运营端不签名、不代付 gas、不发起或撤销链上动作、不可编辑合约地址。项目审核不产生任何质押额，本模块不消费、不展示、不计算三项额度。不产生运营端站内消息，未改 `_shared/admin-message-data.js` |

## 14. 运营端融资参数配置：本批新建组合

本节由 WS-388 现行三册正文与本轮新建原型整理，实现见 [模块说明](../../管理端/融资参数配置/README.md)、[页面组合](../../管理端/融资参数配置/融资参数配置.html) 与 [交互](../../管理端/融资参数配置/融资参数配置.js)。本模块形态与协议管理的「台账 → 详情 → 维护」最接近，但业务规则以本册正文为准，不套用协议的版本、草稿与发布语义。

| 页面 / 组件 | 组合与关联约定 |
| --- | --- |
| 入口与层级 | 一个侧栏条目「融资参数配置」，落地页为融资参数列表（一级页面、不展示面包屑）；代币类型参数详情与参数维护是独立可寻址页面，沿真实父级链展示面包屑并原路返回，保留原筛选、排序、分页与所在位置。三页共用同一侧栏选中态（菜单条目的 `pages`） |
