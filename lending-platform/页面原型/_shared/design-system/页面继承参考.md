# 页面继承参考

## 1. 目的与强制边界

本文件用于后续页面的生成与调整。第 2 节列出的是**已经落库的现有页面**；后续页面必须以它们为母版做增量调整，而不是把它们当成可自由改写的灵感样张。

每个新页面都属于 `existing-system adaptation`，必须遵守：

1. 先选对部署单元和现有 shell；
2. 再选最接近的现有页面 archetype；
3. 复用已有 token、组件、状态表面与断点；
4. 只替换本页内容区和本页必要的局部组合；
5. 不重建全局导航、字体、配色、密度、响应式策略或另一端的布局模式。

本文件与组件规范配合使用：组件规范回答「控件如何画」，本文件回答「新页面从哪一种已存在的页面结构开始组合」。

## 2. 唯一现有页面基线

母版是本仓库里正在运行的原型，不是任何外部附件。

| 画布 | 已落库页面 | 用途 |
| --- | --- | --- |
| 面客端 官网层 + 工作区 · 管理端 控制台 | [`../样板/底座样板.html`](../样板/底座样板.html) | **四种 shell、公共组件、六种状态表面、未登录态与角色差异的唯一母版。** 它不是业务模块原型，字段集是够用的样例 |

样板覆盖的页面：首页（site）· 资产广场 / 借贷广场 / 我的控制台（portal）· 总览 / 协议管理（app）。业务模块的完整字段、流程与验收归各自子 issue。

样板版本、必读顺序和本轮实际页面继承表统一见[面客工作区组件规范 §0](面客工作区组件规范.md#0-必读入口顺序与样板版本)；内外滚动边界与待同步的加载策略见[§5.1](面客工作区组件规范.md#51-内嵌布局与数据加载必须分别决定)。后续 issue 应记录其实际读取的最新 commit，不沿用旧附件作为母版。

## 3. 使用顺序

新增或改造页面前，设计说明必须先写以下四项：

```text
继承部署单元：面客端 asset / 管理端 admin
继承 shell：site（整幅叙述）/ portal（顶栏工作区）/ app（侧栏控制台）/ focus（居中卡片）
继承 archetype：<本文件第 4 节的名称>
本页增量：<仅内容区、组件组合和状态差异>
```

若无法映射到任一 shell 或 archetype，先补页面设计说明与评审件；**不得直接生成一套新的页面语言**。新增整页骨架的权限只在 `base.css` 里，不在模块里。

## 5. 状态表面

六种状态由公共层统一提供，模块只传自己的空态文案与返回目标，不各写一套：

默认 · 加载中（骨架屏）· 空数据 · 筛选无结果 · 加载失败可重试 · 无权限。

提交中、提交失败、异步等待由具体表单或流程模块承担。

## 6. 演示工具

部署单元、身份与页面状态的切换器是**评审工具**，默认关闭，放在独立面板里，不占业务画布，也不冒充产品功能——两个部署单元分开上线，访客不会在页面里就地切身份。模块不得把它当成产品能力来设计。

## 7. 内容边界

原型里的领域名称、机构、数值、日期、地址、身份信息、权限与流程规则不构成通用页面内容，只能被同层级的真实页面需求替换。演示数据必须在页面上标注为演示数据，且不得出现真实企业、成交额、利率或合作机构标识。
