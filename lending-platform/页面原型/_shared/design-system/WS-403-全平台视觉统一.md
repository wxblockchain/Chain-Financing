## 视觉方向与实现落点

端/角色：面客四类身份、运营管理员 · 模块：6 个面客、7 个运营 · 功能点：现有 PAGE / FUNC 的 6 类视觉形态（列表、详情、表单、办理审核、记录、消息）· 状态：上表 · 视觉口径取自 `_shared/tokens.css` / `base.css` / `market.css`、现行 `design-system/` 与各模块实际组件。

不将广场的布局机械套给其他任务。保留 portal 顶栏、app 侧栏、focus 登录、纵向详情栈及各模块原有信息架构、菜单、字段与动作；复用共享运行时、文件组件、消息、语言、路由、弹层和离开保护。列表优先、紧凑筛选、字段对齐、轻分隔与明确办理区作为共同原则。

- 唯一 token 来源仍为 `tokens.css`：蓝白色板、Geist / Noto Sans SC 字体、数字 tabular、普通字段 / 标签 / 清单 / 标题 / 重点金额的语义字号。
- 两端同级组件同字号、颜色、圆角、控件高度与间距。普通操作 / 表单 44px；紧凑筛选 / 分页使用独立紧凑规格，触控设备保留最小点击面积。详情标签与值分级，不把普通数字、日期或字母自动放大。
- 通过既有 `base.css` 扩展共享组件；局部结构差异保留在已有模块样式。无第二套 token，无新业务 JS，无新评审壳层。
- 深色方案作为历史可选评审方案保留；本轮默认统一为已批准蓝白基线。合约、地址、风险与状态仍保留可辨识语义，不将所有文字改成蓝色。

共享字号为：主标题桌面 28px / 窄屏 24px（居中登录卡片标题 24px）、区块标题 16px、普通字段与输入 14px、清单 13px、标签与紧凑筛选 12px；统计金额 22px，中宽 20px，币种及数量单位 11px。两端统一普通控件 44px、紧凑控件 36px，卡片内边距 24px。具体取值只在 canonical token 维护。

页面专有修正：控制台详情的关联项目选择器复用 `.fb` 时离开了 filterbar，SVG 未限尺寸而撑高页头，本轮在既有控制台 CSS 补齐限宽与定位；控制台 JS 仅为金额与张数单位增加展示 span，沿用原 `CF.fmtAmt`、单位文案、求和表达式和空值分支。运营项目 / 质押 / 机构审核区以同一蓝色边界和标题强调，等待时长恢复普通字段字号，避免被误读为核心统计。

Chromium headless，使用现有演示身份、登记页面及场景，不修改业务函数来绕开守卫。

- **43 个实际页面编号，490 个默认页面布局组合**：面客端 322，运营常规页面 144，首次改密 / 找回后设置新密码 24；中英文。面客宽度为 320 / 375 / 414 / 768 / 1280 / 1440 / 1920；运营业务为 1280 / 1440 / 1920，账户与登录另检查 375 / 414 / 768。核对文档无横向溢出、非空页面、实际字体、标题 / 输入 / 普通值 / 清单 computed style。
- **116 组反馈场景、290 个布局组合**：按各模块实际登记的加载、空数据、无结果、读取失败和无权限状态检查布局；面客抽查 375 / 1440，运营检查三档桌面宽度。没有重造状态或移除拒绝反馈。
- **23 类弹层表面、246 个布局组合**：企业账户查看及法币 / 数币新增、代币详情、质押 / 解押、发布、授信 / 报价 / 回应、放款 / 到账、还款 / 确认、运营身份验证、参数保存核对、项目退回 / 通过、机构与质押审核。中英文与各端约定宽度下检查横向溢出、底部按钮可见、输入及只读字段字号。质押审核使用登记的待审核记录，已审结记录继续禁用写入。
