## 2. 字体与数字

- 正文使用 `--sans`：本地 Geist / Noto Sans SC，缺字按 token 的系统字体链回退；不得接入 CDN 或私自替换模块字体。
- `--display`、`--numeric`、`--mono` 当前均承接同一字族。`.mono` 是兼容的结构化值角色，不代表另用 SF Mono、JetBrains Mono 或强制所有字母等宽。
- 数量与金额使用 lining / tabular numbers，保持同列数字稳定。普通数值、日期、地址和字母继承所在字段字号，不因 `.num` / `.mono` 自动放大。
- 主标题、区块标题、普通字段、清单、标签、辅助单位有不同职责；统一的是同级角色，不把所有文字设置成同一字号或颜色。

以下为实现基线的验收快照，后续变更以 token 和实际 CSS cascade 为准，不据本文另写一套数值：

| 语义角色 | token / 实现 | 当前口径与例外 |
| --- | --- | --- |
| 页面主标题 | `--ui-page-title` | 桌面 28px；≤768px 为 24px；focus 登录卡及消息阅读标题为 24px |
| 常规区块、弹层标题 | `--ui-section-title` | 16px；项目办理区标题保留现有 19px 主操作强调，不扩散给普通信息区 |
| 普通字段值、表单输入、普通按钮 | `--ui-field-value` | 14px；详情日期、普通金额、编号与字母同级 |
| 紧凑清单普通值 | `--ui-row-value` | 13px；对象名称和金额卡片可按现有识别层级强调 |
| 字段标签、表头、紧凑筛选 | `--ui-field-label` | 12px；采用次级文字色，表头自然大小写 |
| 统计重点金额 | `--ui-stat-size` | 22px；901–1300px 为 20px；普通明细金额不套统计字号 |
| 币种小单位、辅助状态 | `--fs-11` | 当前金额单位与普通 Tag 为 11px；同屏保持一致，单位不隐藏 |

`--market-field-value` / `--market-field-label` / `--market-row-value` / `--market-section-title` / `--market-stat-size` 是共享语义 token 的广场别名，不是第二套字号系统。

资产详情的身份标题为 24px，普通事实字段不跟随标题放大；具体字号与金额变体见 §8。不要用本模块的详情 / 卡片密度覆盖所有页面。

## 3. 颜色、表面与边界

| 用途 | token | 使用原则 |
| --- | --- | --- |
| 页面画布 / 内容面 / 次级面 | `--bg` / `--card` / `--card-2` | 浅灰蓝画布、白色内容面；可填写控件使用白底，只读表单字段使用次级面，三态细则见 §4.2 |
| 主文 / 次文 / 辅助文 | `--text` / `--muted` / `--faint` | 数字和业务事实用主文；标签及解释降级；不把关键值设为低对比辅助文 |
| 主动作 / 当前项 | `--accent` / `--accent-strong` / `--accent-soft` / `--accent-border` | 蓝色用于可操作项、当前导航与办理区；统计沿用已批准的重点配色 |
| 成功 / 警告 / 危险 | `--ok*` / `--warn*` / `--danger*` | 沿用真实状态语义，并同时保留文字；不得用配色改写业务状态 |
| 普通分隔 / 强分隔 / 可编辑控件边界 | `--border` / `--border-strong` / `--control-border` | 轻分隔与输入边界分别承担职责；错误态使用危险色，焦点使用主色 |
| 链上值 | `--hash-text` / `--hash-bg` / `--hash-border` | 仅承载地址、Hash 等链上事实，不给普通业务文字套链上外观 |

普通卡片不叠加装饰阴影，浮窗 / 下拉沿用 `--shadow-lg`。卡片使用 `--radius-sm`，普通按钮与输入使用 `--radius-xs`；语言菜单等已确认胶囊组件继续使用自身形态。历史深色评审方案保留为可选方案，不作为当前双端默认。

## 4. 组件组合

| 组件 | anatomy 与视觉约定 | 状态与边界 |
| --- | --- | --- |
| Button | 标签及可选图标；普通操作 `--ctrl-h`（当前 44px），紧凑操作 `--ctrl-h-sm`（当前 36px）；一个信息区一个主要动作 | 保留 primary / secondary / ghost / danger / disabled / loading / focus；主按钮不能因统一而绕过禁用或确认步骤 |
| Input / Select | 标签在上，值用普通字段字号；三态、左侧必填星号与表单说明统一按 §4.2；输入与只读字段保持基线，错误紧邻字段 | placeholder 不代替标签；保留原生键盘选择、错误与 disabled；验证码等专用组合保留结构，沿用相同状态语义 |
| Filterbar | 紧凑矩形圆角、标签与查询角色一致；与列表相邻，保持当前条件可见 | 广场与运营复杂筛选的字段组织可不同；不机械互换筛选字段、提交策略和清空行为；窄屏 / 触控遵循现有最小点击面积 |
| Card / 区块 | 标题、内容、必要动作分层；内容默认 `--card-pad`（当前 24px），局部紧凑卡沿用已确认组合 | 不将每个统计值都包成卡；不把页面装进一张巨型卡；窄屏按现有规则收紧内边距 |
| Table | 表头为标签级、普通值为清单级；金额按列对齐；长值保留可读方式 | 运营操作列在最右可达；面客转卡或容器横滚按模块合同处理，不用根节点裁切掩盖缺列 |
| Tag | 色点 + 文字，轻语义底、较小圆角 | 颜色辅助语义；不凭视觉新增“健康度”、临期或倒计时状态 |
| 详情字段 | 标签用标签级，值用普通字段级；长地址和备注允许整行 / 换行，普通数字不放大 | 完整值与复制内容沿用原数据；窄屏标签和值上下排列按模块处理 |
| 抽屉 / 弹窗 | 复用共享宿主、标题、正文与底部操作；长正文内部滚动，头尾可达 | 不强制所有业务使用同一容器；保留焦点进入 / 返回、关闭与草稿保护，不新增确认层 |
| 文件行 | 名称 / 元信息 / 状态在前，动作在后，长文件名自然换行 | 视觉继承共享字体与按钮；材料政策、阈值、权限和文件状态继续按[文件规范](文件上传与展示组件规范.md) |
| 消息 | 标题 → 摘要 → 分类与时间；阅读状态与业务状态各归其位 | 面客连续阅读、运营分页及已读规则保留，不因视觉统一互换加载策略 |

### 4.1 币种与网络图标（项目共用）

- 图标唯一来源为 `asset-icons.js`。法币使用圆形国家 / 地区旗标（USD、EUR、GBP、JPY、CNY；HatScripts/circle-flags，MIT，固定版本 `379588b`）；数币与网络使用原有 spothq/cryptocurrency-icons 配色原图（CC0，固定版本 `1a63530`）。映射与许可证全文随源码及离线导出保留，新增覆盖在该源文件维护。
- 广场复用 `CF.market.currency` / `CF.market.network` / `CF.market.amount`，企业 / 机构账户复用 `CF.eaAssetIcon`；不再复制一份模块图标文件。原图 `.mk-coin-art` 不另加底色、边框或重绘品牌色；普通 UI 状态仍用 token。
- 网络以「图标 + 网络名」识别，币种保留可读代码；图标不代替代码、字段标签或无障碍名称。资产列表的网络指铸造链，详情的存证链是独立事实，两者不得因图标相同而混用。
- 国旗用于币种识别，不用于语言切换；语言切换继续使用地球图标与语言缩写。账户专属的多币种重叠图标、浮窗和选择行为仍按该模块规范，不扩散为所有页面的图标行为。

### 4.2 文本输入、只读与必填标识（项目共用）

#### 4.2.1 适用范围与实现依据

本节是 Hallmark 设计师与 UI 设计师后续设计本项目页面时共用的组件合同，覆盖面客端、运营端及其弹窗内的文本输入、文本域、选择控件与表单内只读字段。依据为 `cly-4.0.0` / `92856d57525f617897a626871ccc8729f1c0d8e6`（企业账户 v6）的实际实现：[账户 CSS](../../面客端/02-企业账户/企业账户.css) 中 `.ea-form` 三态、`.ea-required`、`.ea-readonly-label`，以及[账户 JS](../../面客端/02-企业账户/企业账户.js) 中字段 / 分组标签、只读账户名称；按本轮用户反馈取消独立必填说明。

**新页面按本节设计；清单中的旧表单已按用户授权迁移。** 共用实现为 [base.css](../base.css) 的 `.inp` 三态、`.field-static`、`.required-mark`、`.field-readonly-label`，以及 [shell.js](../shell.js) 的 `CF.fieldLabel(text, required, readonly)`、`CF.readOnlyBadge()`。`required` 省略时仅兼容旧标签末尾的星号；显式传入时按 PRD 及现有状态决定。辅助方法只生成字段标签及只读标识 HTML，不设置原生 required、不判断权限、不改变值或提交校验；新页面应显式传入必填条件。账户的 `.ea-*` 保留为既有参考实现，不要求其他模块依赖账户 CSS。共享 focus 样板 `#/sample/focus` 已提供三态与标签实例，旧离线附件需重新导出才会包含此次变更。

本节提升为项目规则的是状态与标识，不包括账户弹窗宽度、分栏、13px 输入或桌面 36px 控件等局部几何参数。字号、高度、圆角、间距仍按本规范 §2、§4 的语义角色及已确认变体；不得为了套用示例改变字段、默认值、必填条件、权限、校验或提交行为。

#### 4.2.2 三种状态

| 状态 | 表面与边界（沿用现有 token） | 文字、指针与状态标识 | 交互语义 |
| --- | --- | --- | --- |
| 可填写 | 白底 `--card`；原有可编辑控件实线边界，沿用 `--control-border` / 既有控件规则 | 字段值 `--text`，标签常驻；保留文本插入 / 原生选择指针 | 可编辑、键盘可达；原有 hover、focus 与错误态继续有效，不以浅灰底表示普通可填状态 |
| 只读 | 次级底 `--card-2`；`1px dashed var(--border-strong)` | 值用 `--text`，保持清晰可读；默认指针；标签旁标「只读 / Read only」，小号 `--muted` 文字配 `--gray-bg` 轻底 | 已知值可查看、选择 / 复制，不能编辑；保留原有焦点策略，不能用 disabled 代替 readonly |
| 禁用 | 灰底 `--gray-bg`；`1px solid var(--border)` 弱边界 | 值用 `--faint`，`cursor:not-allowed`，`opacity:1`，不再对整块叠加透明度 | 保留真实 `disabled` / 原生禁用语义与已有触发条件；禁止把颜色变灰当作禁用实现，原因说明沿用业务要求 |

只读表单字段与可填字段保持同组对齐、尺寸基线；文本不要截掉完整业务值。详情 / 审阅页已有 `dl`、普通文本事实和复制按钮可继续使用，不必把所有只读内容伪装成输入框；本表的虚线与「只读」标识用于**表单内呈控件形态的只读字段**。筛选条件可用同样的可填写白底，但不因采用输入组件而自动成为必填项。

#### 4.2.3 字段与分组的必填标识

- 中英文界面统一「`*` 字段名」：星号置于字段名**左侧**，标签与分组 `legend` 使用同一顺序。星号用 `--danger`、字重 600，以 `margin-inline-end:var(--sp-1)` 与字段名留距，不拼尾部星号，不按语言更换位置。这是本产品中英文（LTR）界面的设计约定，不宣称是国际标准强制位置；未来新增 RTL 语言需另核布局。
- 仅在具体字段名或选择组标题前标星号，不在页头、卡片或弹窗顶部另起独立必填说明。一个用户填项只出现一次可见标识，不在组标题与同一子字段重复标注；混合只读 / 可填的组合将星号放到实际必选子字段（如项目到期日），自动带出的生效日不加星号。字段级的条件说明、格式提示和错误继续保留。
- 字段是否必填只读各模块当前 PRD；标识覆盖**当前状态下用户必须填写 / 选择的项**，条件变化时跟随既有业务条件更新，不能凭视觉补出新的必填要求。自动带出的只读事实（如账户名称）不加用户填项星号；可选项不加星号，保留已有「选填 / Optional」说明。
- 币种、网络等选择组在组标题 / `legend` 前放一个星号，不给每个候选项加星；保留原生单选 / 多选与键盘操作，不因此预选、改选中值或增加确认步骤。
- 标签与控件通过 `for` / `id` 或既有可访问名称关联。装饰星号用 `aria-hidden="true"`，输入提供 `aria-required="true"`（已有原生 `required` 继续保留）；选择组在组名提供读屏可读的「必填 / Required」，如 v6 的 `.sr-only` 文本，不依赖读屏朗读星号。只读使用原生 `readonly`，或保留 v6 自定义只读事实的 `role="textbox"`、`aria-readonly="true"` 及关联标签；不要替换已有语义来改变交互。
- 字段提示、错误仍紧邻对应控件；错误保留 `aria-invalid` 及 `aria-describedby` 关联。星号不能替代具体错误、长度 / 格式要求和提交校验，不删除原有焦点环或错误描边。

#### 4.2.4 设计引用与验收

## 5. 金额与单位

- 广场首页汇总采用“币种图标 → 简写数值 → 小字号币种代码”，可原位展开完整金额；不能只有图标而没有明确币种。
- 广场卡片 / 表格保留完整数值与小字号币种代码，去掉重复币种图标；详情、表单与确认保留原完整精度和明确币种。资产广场代币详情（含持有方表格）的金额统一用 `CF.market.amount(value, code, {icon:true})`，即「币种图标 + 数字 + 小字号币种代码」，代码字号小于数字。数量不是货币，不加币种图标；资产列表数量单位移到表头 / 卡片标签，详情仍跟在数字后，详见 §8。10 月 15 日金额调整的历史记录见[金额层级与精简展示](WS-403-金额层级与精简展示.md)。
- 控制台通过 `.mc-money` / `.mc-number` / `.mc-unit` 和 `.mc-count-unit` 分开数值与单位。其他模块已确认的完整金额不因统一而自行缩写。
- 格式化、底层计算、排序、输入值、复制值、精度与币种含义保持原业务口径；禁止为了排版截断、四舍五入或给输入框加展示分隔符。
