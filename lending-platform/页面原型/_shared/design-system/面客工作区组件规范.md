## 1. 范围与视觉口径

本规范面向面客端**业务页**（`layout: 'portal'`）：借贷广场、资产广场、我的控制台、账户与机构信息，以及由它们带出的详情与流程承载单元。

实现以 [`../base.css`](../base.css) 的 `.portal*` 与公共组件为准，token 以 [`../tokens.css`](../tokens.css) 为准；本文不复述数值。

核心特征：与官网层同一根顶栏、同一套 token，**按官网密度而不是控制台密度排布**——更高的控件、更大的正文、更松的卡片内边距，但仍然承载表格台账、抽屉与分步流程。

## 2. Shell

| 元素 | 规则 | 禁止用法 |
| --- | --- | --- |
| 顶栏 | sticky、白色表面、1px 下边线；品牌左、主导航中、工具区右。未登录时工具区是语言切换 + 登录 + 申请入驻；已登录是语言切换 + 铃铛 + 账号下拉 | 引入左侧导航；在同一页里再放第二套导航；把账户级页面塞进主导航 |
| 主导航 | 项目由登记表渲染，模块不自建菜单；标签单行不换行，容不下整条横向滚动 | 把一条流程的中间页登记成顶级导航项 |
| 面包屑 | 顶栏下独立一条，只有「首页 / 当前页」两级 | 用面包屑表达流程进度 |
| 内容容器 | 居中于宽容器，两侧安全边距；窄屏收紧 | 使用 `100vw` 造成滚动条溢出 |
| 右栏（`.portal-cols` + `.portal-rail`） | 主内容 + 右侧辅助列，辅助列吸顶；窄屏收成单列且不再吸顶 | 用右栏堆放与主内容无关的推广 |
| 页脚 | 与官网层同一个页脚，业务页同样带 | 业务页省掉页脚 |

## 3. 未登录态

这是面客端的常态之一，不是异常分支。

- 游客可达路由直接渲染内容，不跳登录、不弹登录墙；字段按最新 PRD 权限矩阵显示或脱敏，不承诺全量公开。
- 受限动作保留在原位并置灰，仍可聚焦、可点击并读出受限原因；点击唤起类型选择引导，不执行原业务操作。
- 登录提示仅在用户主动点击右上角「登录」/「申请入驻」，或触发受限操作时出现；**不放常驻登录提示条**。
- 已登录但信息未补齐时使用 `C-L03` 壳层补全提示条：可折叠、不可永久关闭；最多一条，其余以计数与清单表达，与游客登录提示区分。

## 4. 基础组件

| 组件 | anatomy / 尺寸 | variants 与状态 | 禁止用法 |
| --- | --- | --- | --- |
| Button | 图标（可选）+ 单行标签，高度取面客端控件高，触控区不小于 44px | primary、secondary、ghost、sm；loading 保留可读标签 | 一个信息区里多个同级 primary；长标签换行 |
| Input / Select | label 在上，控件高与圆角取 token | default、hover、focus、error、disabled | 用 placeholder 代替 label；为了好看移除 select 的键盘能力 |
| 语言切换 | 地球图标 + 当前语言缩写的胶囊下拉 | 当前项带选中标记 | 用国旗表示语言 |
| Tag / 状态标记 | 色点 + 短文本 | neutral / accent / positive / warning / danger / violet | 用多枚彩色标记代替信息层级 |
| 链上值 | mono + 专用底色与描边 | — | 用它装普通业务文本 |
| 文字链 CTA | accent 文本 + 箭头，hover 时箭头轻微右移 | hover、focus-visible | 小于 44px 的独立触控目标 |

## 5. 数据展示

| 组件 | 布局 | 组合规则 |
| --- | --- | --- |
| 头部汇总 | 小号 label + 大号 mono 值 + 一行单位/辅助说明；下方一行口径标注 | 2–4 列，小屏 1 列；只放 PRD 点名的指标，不自造 KPI。**空态显示 0，不隐藏整块**；折算类数值必须在旁标注折算口径 |
| 资产标识块 | 24×24 圆角方形首字母块 + 名称 | 没有 logo 时用首字母块兜底，**不用通用占位图**；标识块取有区分度的字符，整列一模一样等于没有信息 |
| 筛选条 | 与表格同卡，字段左、动作右 | 字段与 PRD 的筛选字段一一对应；窄屏字段占满一行、动作按钮等分 |
| 可排序列头 | 整格可点的按钮，当前排序列显示方向箭头并写 `aria-sort` | 只给 PRD 允许排序的列；默认排序键与方向跟 PRD；精确值排序，不区间化 |
| 数据表 | 浅色表头、右对齐数值与结构化值、固定操作列 | **窄屏转卡片式**：表头隐藏，每格靠 `data-label` 回填列名，一个单元格里的主值与副值上下堆叠。不横向截断关键内容 |
| 列表尾部 | 两种形态二选一，见下 | 一个列表只用一种，不混用 |
| 详情组 | key / value 两列对齐 | 长值换行而不挤压 label；短值可用 mono |
| 空态 | 标题 + 一句原因 + 可选修复动作 | 区分「暂无数据」与「筛选无结果」，后者给「清空筛选」 |

### 5.1 内嵌布局与数据加载必须分别决定

**内嵌布局是容器契约；分页或滚动加载是数据与导航契约。采用分页不能成为删除 `.listbox` 的理由。** 两个广场均继承样板内嵌形态，不把范围收窄为借贷广场。

| 维度 | 规则 |
| --- | --- |
| 广场桌面容器 | 同一 `.card` 内，`.filters` 在 `.listbox` 外；列表用 `.tablewrap.listbox`，高度上限取 `--list-h`，由公共层负责 overflow 和 overscroll。短列表自然收高，不补虚假数据或空白占位 |
| 框内滚动 | 只滚动列表内容，表头在框内吸顶；页头、汇总、筛选的位置不随框内滚动改变。滚轮到框边界不连带滚动外页 |
| 外页滚动 | 页面仍保留自身滚动，以访问标题、汇总和页脚；“不跟着滚走”只指框内滚动，不代表这些区域在任何外页滚动下都固定。顶栏的 sticky 行为仍归 shell |
| 键盘 | 列表区域可聚焦并有可访问名称；方向键 / PageDown 可滚动。不能为了防滚动穿透而禁用页面或键盘滚动 |
| 窄屏 | ≤900px 沿用公共层释放内嵌高度、交还整页滚动；≤768px 沿用 `.tbl.resp` 转卡片。这是两个不同断点，必须分别验收，禁止混写成一个阈值。资产广场十列的模块适配在 ≤1200px 提前转为同形卡片（完整英文列宽所需），不改变 900px 滚动边界；≤600px 汇总改单列。其他模块不得直接照搬此字段密度例外 |
| 独立详情 | 走外页滚动，不套列表内滚框；返回列表恢复原视图与位置 |

加载策略与容器布局分开记录：

| 策略 | 当前适用与行为 |
| --- | --- |
| 样板滚动加载 | 两个广场样板每批 20 条；尾部在 `.listbox` 内。滚到底自动追加，保留可聚焦的「加载更多」及已显示数量；全部加载后显示末尾状态。按钮不能吸底；桌面哨兵以列表框为 root，窄屏以视口为 root；追加后保住内外位置 |
| 分页台账 | 我的控制台、管理端台账使用总数 / 页码 / 上下页，边界禁用 |
| 资产广场业务原型的待同步项（WS-350） | 当前 PRD V2.0 `F-AM-05` / `AC-AM-30` 要求固定每页 20 条，`D-AM-22` / `AC-AM-18` 与图 `ST-AM-03` 要求页码进 URL 并恢复；与样板连续追加冲突。**本轮恢复 `.listbox`，暂保留每页 20 条及框外同卡分页条**，没有双重加载入口。此为具名待同步项，不是把公共规范改为“只有借贷广场滚动加载”，也不等于业务规则已获修改授权。由产品负责人串行交 PRD 成员裁定加载策略并同步条款后，再更新模块 |

位置规则：筛选、搜索、换排序、重置及主动翻页回到新结果顶部（内框与外页同时复位）；普通重绘与追加加载保持当前内外位置；进入详情前保存列表状态，页面返回、浏览器后退/前进恢复对应 URL 的视图和内外位置。URL 负责可分享的业务状态，会话位置缓存负责当前会话的像素位置，不能用像素位置替代页码或筛选。

## 6. 反馈与浮层

| 组件 | 布局 | 行为 |
| --- | --- | --- |
| 抽屉 | 右侧定宽；**640px 以下转全屏** | 遮罩、Escape、关闭按钮均可退出；打开后焦点进入内容 |
| 弹窗 | 居中、展示级圆角、内容可滚动 | 层级高于抽屉——二次确认是从抽屉里点出来的 |
| Toast | 视口底部居中、深色小表面 | 短句，可自动消退，不抢焦点 |
| 行内提示 | 左侧强调线 + 浅色语义底 | 信息 / 提示 / 错误 / 成功都配文字，不只用色带；错误带 `role="alert"` |
| 骨架屏 | 与最终内容形状一致 | 带 `role="status"` 与可读标签，避免页面跳动 |

## 7. 必须覆盖的状态

默认 · 加载中 · 空数据 · 筛选无结果 · 加载失败可重试 · 无权限 · 未登录 · 提交中 · 提交失败。全局空态与筛选空态**必须可区分**，后者提供「重置筛选」。只实现该功能实际适用的那些；一个在覆盖表里出现却在原型里到不了的状态算缺口，不算细节。

## 8. 响应式验收

375 / 414 / 768 / 1280 / 1440 / 1920 全验，并检查 900/901 与 768/769 断点边界。无页面级横向滚动、操作列可达、抽屉在窄屏全屏、触控控件不小于 44px、焦点环可见。

交付前必须在实际浏览器执行，报告浏览器、视口与结果；源码检查不能替代：

- 记录目标分支头、样板文件 commit、每页继承关系与必要例外；确认读取本规范 §0 所有入口。
- 桌面滚动列表：记录 `.listbox` 的 clientHeight / scrollHeight / scrollTop，确认确实内滚；比较页头、汇总、筛选与表头坐标，确认框内滚动时未移动。
- 内框滚到底再次滚轮，确认外页没有被带动；指针移到外页后仍能访问页脚。键盘聚焦列表后可滚动，Tab 可离开。
- 修改筛选、搜索、排序、重置和翻页，确认结果回顶；按当前策略检查分页边界或追加保位，不得同时出现页码与加载更多。
- 非默认筛选下滚动，进入详情，再分别使用页面返回与浏览器后退/前进；核对 URL、筛选、排序、页码、首行内容及内外 scrollTop 都恢复。另验带参数冷启动、刷新和空结果。
- 窄屏确认内框不再独立滚动，≤768px 全列转卡片；桌面十列与编号完整可读，不以 `overflow-x:clip` 掩盖内容溢出。
- 默认、加载、空数据、筛选无结果、失败重试、三种身份和中英切换按模块实际范围检查；演示工具默认关闭。
- 导出的单文件也执行关键路径，确认无外部资源依赖、无脚本异常。未实测项与 PRD 冲突必须明确列出，不声称全部验收通过。
