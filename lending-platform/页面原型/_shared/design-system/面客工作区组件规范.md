## 1. 范围与视觉口径

本规范面向面客端**业务页**（`layout: 'portal'`）：借贷广场、资产广场、我的控制台、账户与机构信息，以及由它们带出的详情与流程承载单元。

实现以 [`../base.css`](../base.css) 的 `.portal*` 与公共组件为准，token 以 [`../tokens.css`](../tokens.css) 为准；本文不复述数值。

核心特征：与官网层同一根顶栏、同一套 token，**按官网密度而不是控制台密度排布**——更高的控件、更大的正文、更松的卡片内边距，但仍然承载表格台账、抽屉与分步流程。

## 2. Shell

| 元素 | 规则 | 禁止用法 |
| --- | --- | --- |
| 顶栏 | sticky、白色表面、1px 下边线；品牌左、主导航中、工具区右。未登录时工具区是语言切换 + 登录；已登录是铃铛 + 语言切换 + 账号下拉。申请入驻入口仅在资金方登录后提供，复用机构注册流程 | 引入左侧导航；在同一页里再放第二套导航；把账户级页面塞进主导航 |
| 主导航 | 资产广场、借贷广场、我的控制台三项由登记表渲染，默认资产广场，模块不自建菜单；标签单行不换行，容不下整条横向滚动 | 把一条流程的中间页登记成顶级导航项 |
| 面包屑 | 一级入口（资产广场、借贷广场、我的控制台、消息中心、账户设置等）不展示面包屑及占位；详情在顶栏下按「所属列表 › 当前页」展示真实父级；上级为链接、当前页为非链接；不附加与面包屑同义的页内返回按钮；取消、关闭及跨模块来源返回保留；窄屏保留直接上级与当前页 | 在一级入口前补资产广场等无关祖先；用面包屑表达流程进度 |
| 内容容器 | 居中于宽容器，两侧安全边距；窄屏收紧 | 使用 `100vw` 造成滚动条溢出 |
| 右栏（`.portal-cols` + `.portal-rail`） | 主内容 + 右侧辅助列，辅助列吸顶；窄屏收成单列且不再吸顶 | 用右栏堆放与主内容无关的推广 |
| 页脚 | 与官网层同一个页脚，业务页同样带 | 业务页省掉页脚 |

已登录顶栏账户入口显示缩写钱包地址（前 6 位含 `0x`、后 4 位；不超过 10 字符时完整显示），悬浮展开菜单或键盘聚焦可查看全文；菜单同时支持点击与键盘，Escape 关闭并恢复入口焦点。角色在菜单首行展示，不再作为顶栏按钮文字或字母头像。地址缺失时显示「我的账户」。资产方资料入口为「企业信息」，资金方为「用户信息」，账户设置和退出入口保持分开。共享壳层通过 `CF.portalAccount()` 读取当前登录账号，钱包插件切换或断开不改变登录账号展示；实际账户状态、路由和回跳由登录模块接管，独立模块使用演示身份，不能宣称已经完成会话集成。

## 3. 未登录态

这是面客端的常态之一，不是异常分支。

- 游客可达路由直接渲染内容，不跳登录、不弹登录墙；字段按最新 PRD 权限矩阵显示或脱敏，不承诺全量公开。
- 受限动作保留在原位并置灰，仍可聚焦、可点击并读出受限原因；点击唤起类型选择引导，不执行原业务操作。
- 登录提示仅在用户主动点击右上角「登录」，或触发受限操作时出现；**不放常驻登录提示条**。
- 已登录但信息未补齐时使用 `C-L03` 壳层补全提示条：可折叠、不可永久关闭；最多一条，其余以计数与清单表达，与游客登录提示区分。

### 5.1 内嵌布局与数据加载必须分别决定

**内嵌布局是容器契约，连续追加是加载契约。** 资产广场已按 `fc8c529` PRD 四册统一为内嵌连续追加，不存在分页例外。两个广场都继承内嵌母版；具体断点行为按最新业务 PRD 核对。

| 维度 | 规则 |
| --- | --- |
| 广场桌面容器 | 同一 `.card` 内，`.filters` 在 `.listbox` 外；列表用 `.tablewrap.listbox`，高度上限取 `--list-h`，由公共层负责 overflow 和 overscroll。短列表自然收高，不补虚假数据或空白占位 |
| 框内滚动 | 只滚动列表内容，表头在框内吸顶；页头、汇总、筛选的位置不随框内滚动改变。滚轮到框边界不连带滚动外页 |
| 外页滚动 | 页面仍保留自身滚动，以访问标题、汇总和页脚；“不跟着滚走”只指框内滚动，不代表这些区域在任何外页滚动下都固定。顶栏的 sticky 行为仍归 shell |
| 键盘 | 列表区域可聚焦并有可访问名称；方向键 / PageDown 可滚动。不能为了防滚动穿透而禁用页面或键盘滚动 |
| 窄屏 | 资产广场启用 `.listbox.listbox-contained`，所有断点保持内嵌滚动；≤1200px 九列改为同形摘要卡，≤600px 汇总单列。转卡片不改变滚动归属。公共 `.listbox` 未启用该修饰类的其他模块仍按各自现有规则核对，不从资产广场擅自扩展业务要求 |
| 独立详情 | 走外页滚动，不套列表内滚框；返回列表恢复原视图与位置 |

加载策略与容器布局分开记录：

| 策略 | 当前适用与行为 |
| --- | --- |
| 样板滚动加载 | 两个广场样板每批 20 条；尾部在 `.listbox` 内。滚到底自动追加，保留可聚焦的「加载更多」及已显示数量；全部加载后显示末尾状态。按钮不能吸底；资产广场所有宽度以列表框滚动为触发，不以外页滚动触发；其他样板按其滚动容器确定 root；追加后保住内外位置 |
| 分页台账 | 我的控制台、管理端台账使用总数 / 页码 / 上下页，边界禁用 |
| 资产广场业务连续追加（WS-350） | `F-AM-05` / `AC-AM-30` 及用户 2026-09-20 反馈：首批20条，内嵌下滑至末端自动追加20条，末批只取余量；正常状态不放「加载更多」按钮，也不放分页器、页码跳转或批量大小开关。首批骨架与汇总同批完成；追加中/失败均保留已有记录和位置，仅失败在末尾提供重试本批按钮，不自动循环失败请求；末尾无更多时停止追加。汇总始终对应筛选全集，不随已加载条数累加。正常加载不能依赖点击，须实测滚轮、触屏上滑和键盘连续下滚 |

位置规则：筛选、搜索、换排序、重置回到新结果首批顶部；普通重绘与追加保持当前内外位置。URL 包含筛选、排序、关键词、已加载范围及可恢复的滚动定位（如记录锚点与偏移），不以页码表示进度。刷新、**新会话打开分享链接**、前进后退、详情返回均先恢复范围再恢复位置，并能继续无重复追加；无恢复参数时从首批顶部进入。本地缓存只能作为优化，不能作为分享恢复的唯一依据。条件变化时取消或隔离旧请求，防止旧批次串入新条件。


### 5.2 资产广场编号与整行交互（2026-09-20）

资产广场当前九列，桌面表格与窄屏摘要卡均移除账期展示；详情资料保留。完整代币编号本身是可聚焦的文字按钮，鼠标、Enter、Space 复制完整值，必须阻止行跳转，并等待复制结果后显示成功或失败。列表不加第二个复制按钮；编号外其他区域含标识可进入详情，整行聚焦可由 Enter/Space 激活。复制动作和行导航必须分别做浏览器断言，不能只检验 onclick 源码。

三项汇总按 V2.1（`6f5b947`）以筛选、搜索匹配全集统计；代币数量及其中失效分别对对应记录的代币数量求和，单位「枚」、两位小数，不能使用记录数、地址数或项目数。加载追加时不累加汇总。详情占满现有 portal 内容区，无辅助内容时不留右栏。来源、版本与待同步业务条款见[资产广场 README](../../面客端/资产广场/README.md#2026-09-20--五点反馈增量)及[同步清单](../../面客端/资产广场/本轮反馈与PRD同步清单.md)。
