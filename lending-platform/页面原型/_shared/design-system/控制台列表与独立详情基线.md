实际覆盖区分本轮修改、继承与外部待验，详见[控制台 README](../../面客端/05-我的控制台/README.md#本轮-ui-覆盖与核验边界)。窄屏是既有原型重排，不新增移动钱包业务承诺。

## 列表与详情分工

列表用于识别、比较及发现当前事项。单元格一个主值，可带一条必要标识；相关期次并行事实须可发现。控制台详情只补充必要摘要；完整条款、历史、计划、账户核对及记录材料归借贷广场。摘要范围衔接最新用户意见与`313fe49` 的PRD修订（功能原型已由 `1c7a993` 衔接）；原对象定位和整笔代币统计沿当前来源处理。

| 清单 | 一行对象 | 主要信息与详情分工 |
| --- | --- | --- |
| 代币 | 一个代币 | 数量、USD价值、状态与质押状态分别呈现；完整账期、买方、签发时间和关联项目在详情 |
| 融资项目 | 一个项目 | 当前申请、融资余额、覆盖与截止日；记录直接打开借贷广场项目详情，控制台不另做项目摘要 |
| 授信 | 机构×企业 | 总额、已用、可用、状态及有效期；详情为对方名称标题、使用情况占比、当前使用记录、期限与本机构备注，资金方可修改授信 |
| 融资放款 | 一笔已接受FD | FP/FD识别、对方、融资额、约定/实际金额、放款展示状态/处理方和接受时间；展示状态只有待放款、待放款确认、已放款三值，还款中与已结清不覆盖放款结果。已有LN在列表可识别，提交、确认事实留在摘要详情，支持FP/FD/LN精确查找 |
| 还款 | 一笔已确认到账FD | FP为主识别、机构、本期应还、业务/计划状态、待确认情况并存；详情只保留本期、所有待确认、当前未结清逾期及明确指定原期，支持FP/FD/LN精确查找 |
| 报价 | 一笔本机构FD | 申请、项目、金额、结算币种与利率、业务状态及已锁定时长；报价没有有效期，提交后不可撤回。详情以项目名称为标题，只留客户融资需求、本机构报价与报价结果 |

还款筛选按“包含该状态期次”的业务集合计算总数，不重复业务行；进入详情保留本期、所有待确认与当前未结清逾期及明确原期，标明匹配项；完整计划在来源。计划生成中不产生虚构期次或金额，全部结清保留结清摘要，原指定期可读，不显示0元本期应还。列表默认20条，可切换50/100条；时间排序使用控制台三册已确定的各业务时间，不额外置顶。

## 单列详情组件

- 代币、授信、放款、还款、报价五类控制台详情保持独立路由和公共面包屑，不进入主导航（融资项目详情由借贷广场承载）；正文复用 `.detail-stack` / `.detail-section`，不使用 `.detail-layout` / `.detail-rail` 左右组合。
- 代币、放款、还款、报价详情页头摘要旁仅一个“前往借贷广场”（Go to lending marketplace）按钮，授信详情不设；窄屏自然换行；各内容分区不重复广场动作。零关联或无可访问目标禁用并给出原因；读取失败另行提示。多关联用有标签的原生选择框，仅列当前主体可访问的真实关联项目，选择前禁用，不自动选择首项。除资金方修改授信对话框外，控制台不出现业务表单、上传或提交确认按钮。
- `.mc-chapters` 横向章节导航固定于公共顶栏下。运行时测量顶栏及导航高度，章节滚动留出对应空间，不使用固定桌面像素猜测移动高度。
- 点击滚到章节并使标题可见；手动滚动同步当前位置，用 `aria-current="location"` 标示，键盘可操作，遵循 `prefers-reduced-motion`。窄屏仅导航自身横向滚动，正文不横向截断。
- 相关期次摘要逐个呈现RP、应还日、USD合计、结算金额币种、状态、处理方及末期本金标记；待确认保留RM和提交时间，冻结逾期与未结清并存。完整定稿计划、逐期本息/计息和材料在来源。选择某期仅更新阅读目标，不提供办理按钮。
- **控制台没有任何业务时限组件**：不出现截止时点、剩余时长、倒计时、临期强调或超期标记，也不据此改变标签色。等待一律表达为自平台记录时间起“已提交 N／已锁定 N”的中性累计，并在对应分区说明确认无时限、逾期天数冻结、平台不代确认。
- 放款、还款详情不再展示收款账户、协议与交易材料，均在借贷广场原笔按当事方权限阅读；控制台不另建账户字段。
- 项目指标沿用融资需求与代币质押模块的五项口径（总质押额、有效质押额、本轮融资需求、已融资余额、项目质押率；2026-10-21 起取消待审质押额），数值统一取 `D.numbers(p)`，需追加资产价值按项目质押率换算，不写死固定质押率。
- 固定导航只影响当前控制台详情；复用项目原有颜色、字号、间距、按钮、状态、空态与抽屉宿主，不新增token或第二套外壳。

## 定位与返回

列表 → 控制台详情 → 对应广场项目详情 → 同一控制台详情 → 原列表。列表只进本控制台详情，正常、空态、无结果和失败均不设广场快捷入口；保留壳层全局导航。详情唯一按钮携带项目、原对象及控制台返回地址，不传业务动作。已明确的申请/FD/RP在来源既有只读容器阅读，不能静默切新轮或本期；关闭只读记录后用户从项目原入口独立选择办理。没有来源定位能力时显式降级同项目并保留原编号与返回，此定位分支待验，不判通过。

详情仍为 `#/console/{tokens|projects|credits|loans|repayments|quotes}?id=...`。还款 `id` 使用FD；旧RP编号入口解析到同笔业务并打开原期次，显式选期用 `period=RP`。原期次已结清时展示该期当前结果，不跳到下一待还期。项目申请可用 `application=FP` 定位对应轮次。

URL保存tab、筛选（含代币类型）、编号检索、排序、页码、每页数、滚动与目标行。详情携带列表快照，跨模块携带 `mcReturn`，只接受登记的本地控制台路径。选择期次后返回保留目标期次及最新事实，记录不再匹配筛选时提示清除过滤。未知、无权或不属于该业务的RP采用统一不可用反馈。

真实主体、银行摘要掩码、数币精度、执行、消息与客服联验及性能条件仍归主PRD第5节，未完成分支待验、不判通过；组件规范不裁定业务规则。


企业代币全集与统计共用完整、归属明确且按编号去重的快照，不由项目或质押子集反推。无项目和失效代币仍可阅读。控制台统计、列表、详情、计划生成中和错误态都不设刷新、刷新状态或重试取数按钮；失败给出浏览器刷新当前网址的文字指引。刷新恢复 URL 条件、对象、选定申请/期次、来源视图与已选关联项目，失效页码同步收敛；复制、章节导航、过滤分页和详情阅读操作保留。

摘要详情的字段组使用 `.mc-facts / .mc-fact`：标签在上、值在下，两列等宽，≤600px 单列；账户快照通栏，章节与整体页面保持单列内容流。复用共享字号、色板和间距。当前实现、覆盖与运行方法见[控制台 README](../../面客端/05-我的控制台/README.md)。
