# WS-438 · 面客业务视觉统一

2026-10-23 · existing-system adaptation / 面客 console。目标分支 `cly-v5.0.0`；原型核验起点为 `99b7de8`，提交时衔接远端后续 PRD 更新。用户本轮明确排除首页：不调整首页布局、风格、动画或内容。

## 观察与落地

保留原蓝白主题、本地 Geist / Noto Sans SC、普通字段 14px、表单 44px、紧凑筛选 36px、既有模块布局。大部分已交付页面已采用这套基础语言，本轮修正实际发现的局部偏差：

| 观察 | 已完成 |
| --- | --- |
| 项目内同一筛选行的输入、选择器分别为 14px / 13px，消息分类为 13px，而广场筛选为 12px | 这些紧凑筛选统一为标签级 12px，普通表单和偏好字段保留原层级 |
| 消息页签为 56px，控制台页签还受上下内边距撑高；选中字重可能被公共样式覆盖 | 分类页签以业务变量 48px 为基线，选中态保留颜色、下划线并明确 600 字重；窄屏消息变体不改 |
| 账户与其他办理弹层的头尾间距来源分散，办理底栏与正文未形成一致分区 | 从业务作用域变量控制默认头尾间距与次级底栏；保留不同流程的宽度与窄屏组合 |
| 借贷弹层的关闭图形为文字乘号 | 改用共享 close SVG 与图标按钮，原关闭行为和可访问名称保留 |
| 项目基础信息卡标题使用 14px 局部值 | 改为 16px 分区标题 token，与普通资料卡一致 |
| 注册页完整钱包地址浮窗按短地址定位，320 / 390px 下展开会超出右边界 | 改由整行钱包信息定位并限制宽度，保留完整地址、复制与原生键盘展开 |

实现只涉及原型呈现 CSS、借贷关闭图标及面客组合层的业务作用域 class。未改业务数据、权限、状态转换、字段、校验或 PRD。

## 实际验证

- Chromium 无头浏览器、本地文件原型；17 个真实页面 / 角色入口 × 中英两种语言 × 320 / 390 / 768 / 1280 / 1440 / 1920px，204 组布局检查。机构注册通过既有演示工具的“首次入驻”状态核验，避免误把已认证状态页算作注册表单。
- 46 项行为与隔离检查通过：账户切换及非法地址、质押选择及签名资料、报价表单、弹层单层呈现和四档视口边界、消息筛选及返回、控制台切换和选中强调、钱包全文与键盘展开、本地字体等。关闭按钮保留原关闭及草稿保护入口。
- 四类列表（资产、借贷、账户、消息）的 loading / empty / error × 中英，共 24 个反馈场景核验，无脚本异常。
- 首页与运营代币审核：将修改前仓库源码导出为临时只读基线，在相同视口、时间、减少动态效果条件下，比对可见元素的字号、字重、颜色、表面、边距与尺寸，结果一致。这里只证明抽查条件下共享变更已隔离。
- 源码语法和 `git diff --check`；最终离线单文件另核对业务作用域、关键页面、字体及资源内联。

未做真实钱包、链、邮件、后端、真机或其他浏览器验收；未做全业务 AC、完整 WCAG 或全部金额 / 权限组合重验。演示数据及既有服务模拟边界保持。

## 运行与维护

仓库内保持 `页面原型/` 目录完整，可双击各模块 HTML；交付附件是源层导出的离线自包含 HTML，双击从资产广场进入。顶栏进入借贷广场和控制台，账号菜单进入用户资料、企业 / 机构资料与账户，消息铃进入消息中心；右下演示工具沿用既有角色和状态切换。首页导航保留原功能，首页本身未优化。

`body.portal-business` 只在业务页启用 `tokens.css` 中的组件组合变量；进入首页即移除。后续维护从[共享组件视觉规范 §4.4](共享组件视觉规范.md#44-面客业务组件统一2026-10-23--ws-438)读取合同，保持普通表单、紧凑筛选、分类页签与章节定位的不同语义。离线件由 `_shared/export.py` 生成，不回存源码目录。
