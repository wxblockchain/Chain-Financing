## 核查与优化

实际读取共享 tokens / base / market，以及资产、借贷、授信、放款、还款 CSS / JS，并在浏览器核对字段字号。发现项目基本信息为标签 11px / 值 12px，代币与业务明细为值 13px，资产详情为 14px；同级页标题存在 28 / 34 / 36px，重点金额存在 19 / 24px，列表日期也小于同列普通字段。这些差异由组件历史样式叠加造成，本轮按语义角色归一。

| 角色 | 当前口径 | 适用位置 |
| --- | --- | --- |
| 页面主标题 | 桌面 28px，窄屏 24px | 两广场、资产 / 项目详情、创建项目 |
| 普通区块标题 | 16px | 基本信息、记录区域、业务明细区块；右侧「项目办理」仍保留主操作区域的强调 |
| 普通字段值 / 表单输入 | 14px | 项目基本信息、代币详情、授信、放款与还款明细、创建及办理表单 |
| 字段标签 | 12px | 上述字段及卡片说明 |
| 紧凑清单值 | 13px | 两广场与记录表中的普通值、日期、网络名称；资产 / 项目名称仍为识别重点 |
| 重点金额 | 复用 `--market-stat-size` | 首页 / 项目统计，以及报价、放款、还款办理摘要；当前桌面 22px，中宽 20px |
| 辅助信息 | 沿用既有次级样式 | 提示、状态、地址 / Hash、币种小单位；选择汇总等紧凑摘要保留自身角色 |

普通数值与时间不再因为使用 `.num` / `.mono` 而自行放大。币种单位仍使用已确认的小字号，金额精度、时区与复制值不变；未更换字体或颜色。

字号职责集中在 canonical `tokens.css` 的四个语义别名及共享 `market.css`，未给每个业务文件复制一份覆盖。项目信息卡按新字号调整固定高度，典型数据不再因字号增大被截住；代币 / 申请 / 放款 / 还款四个记录模块仍保持固定高度，图表切换不推挤页面。超长内容继续由原内部滚动容器承接。
