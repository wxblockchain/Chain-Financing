## 两个部署单元、两种画布

| 部署单元 | 画布 | 读者 | 验收宽度 |
| --- | --- | --- | --- |
| 面客端 | 官网型：顶栏导航 + 宽容器 + 页脚，公开层与登录后同一套页面 | 资产方、资金方、未登录访客 | 375 / 414 / 768 / 1280 / 1440 / 1920 |
| 运营端 | 标准管理平台：固定侧栏 + 紧凑顶栏 + 高密度表格 | 运营管理员、SPV 机构 | 1280 / 1440 / 1920 |

两端**共用同一份 token 与同级组件规格**，按任务保留不同 shell 和信息布局；普通表单、紧凑筛选、清单等组件各有自己的密度角色，不按端建立两套字体、字号或色板。

## 四种整页骨架

模块按页面性质选一种，不自行拼第五种：

| 骨架 | 开启方式 | 用在哪 | 导航形态 |
| --- | --- | --- | --- |
| site（官网层） | 登记表 `layout: 'site'` | 历史整幅叙述组合；当前无独立首页 | 顶栏主导航 + 页脚，不挂面包屑 |
| portal（面客工作区） | 登记表 `layout: 'portal'` | 登录前后都可达的业务页 | 顶栏主导航 + 内容；详情显示面包屑，一级页面不显示，内容居中于宽容器 |
| app（运营端控制台） | 登记表 `layout: 'app'` | 运营端全部页面 | 固定左侧栏 + 全局工具顶栏 + 内容；仅有真实父级时显示内容区面包屑 |
| focus（居中卡片） | 登记表 `layout: 'focus'` | 登录、重置密码等未登录或强制中断页 | 只有品牌与轻量工具区，不放业务导航 |

site 与 portal 共用同一根顶栏与同一张登记表，差别只在内容区节奏与是否有面包屑。**任何一种骨架下模块都不得自建菜单。**

## token 总览

具体值以 `tokens.css` 为准，这里只说明每组的用途与取值纪律。

| 组 | 用途与纪律 |
| --- | --- |
| 字体 | 正文与标签用 sans；官网展示标题用 display（同族、更紧字距）；hash、金额、时间等结构化短值用 mono。**不加载远程字体**，字体装不上时回落系统字族，标题气质靠字重、字距与尺寸阶梯承担 |
| 表面 | 页底 / 浮起面 / 卡片 / 次级卡片 / hover 态 / 表格行线与行 hover，单一浅色体系，无深色底 |
| 边界 | 固定 1px；strong 用于输入控件，dash 用于分隔虚线 |
| 文字 | 主 / 次 / 弱三级，不得再新增中间级；主色上的反白文字用 `--on-accent` |
| 主色 | 主操作、当前项、强调背景与描边四档 |
| 语义 | 成功 / 提醒 / 错误 / 辅助分类 / 正向数值，每个语义色成套使用 |
| 中性块 | 无语义的标签与代码块 |
| 链上值 | 仅用于 hash / 地址 / 代币编号一类结构化短值 |
| 层级 | 普通卡片无装饰阴影；下拉 / 浮窗使用共享浮层阴影，遮罩仅用于原有模态场景；资产列表页内展开无浮层阴影或遮罩 |
| 圆角 | 展示卡 / 卡片 / 控件 / 小标记 / 胶囊，五档封闭，不得自定义 |
| 字号 | 阶梯封闭；最大两档只给官网层展示标题；正文默认字号由 `--fs-body` 承担 |
| 间距 | 4px 基准的封闭阶梯，最大两档只给官网层区块间距 |
| 浮层层级 | 粘性头部 → 抽屉遮罩 → 抽屉 → 弹窗遮罩 → 评审工具 → Toast，一条阶梯，不散落魔数。**弹窗必须高于抽屉**：二次确认是从抽屉里点出来的 |
| 控件与密度 | 两端共用语义规格，按普通表单 / 紧凑筛选 / 清单 / 统计区分角色；模块变体明示范围，不按端别另造正文与控件尺寸 |
| 动效 | 只动 `opacity` 与 `transform`；用具名缓动；尊重 `prefers-reduced-motion`；焦点环不参与动画 |

## 通用状态与无障碍

每个交互控件都需要 default、hover（只在精确指针下）、focus-visible、active、disabled、loading、error、success。可访问性是组件契约的一部分：

- 使用清晰可见的 label，不以 placeholder 替代；错误文本取代 helper 文本并使用 `aria-invalid`。
- `:focus-visible` 使用 2px、与背景和组件均至少 3:1 的焦点环；不得移除焦点样式。
- 触控可达组件的命中区域不小于 44px；纯图标操作提供可访问名称。
- 错误提示使用 `role="alert"`；加载态使用 `role="status"` 并给出可读标签。
- loading 保持原有布局与可读标签；error、disabled、success 不依赖颜色单独表达。
- **不可用的动作保留在原位并给出原因**，不隐藏——隐藏会让用户失去方向。
- 中英文、长标题和结构化值允许内容区换行；按钮、顶级导航和 tab 标签保持单行，父容器改为折行、横向滚动或收纳。

## 国际化

语言、时区、数字、金额、链上地址与哈希的展示口径，以及脱敏口径，一律引用 `cly-V1.0.0` 的 `financial-service-platform/prd/v1.0-账户与登录/01-国际化基线.md`，本目录不另行定义。落到实现上的三条硬约束：

- 默认英文，支持 `en` 与 `zh-CN`，**不读浏览器语言**；切换后当前页不刷新即完成全部文案替换，已填表单内容不丢失。
- 语言切换器用地球图标 + 当前语言缩写的下拉，**不用国旗**；已登录在顶栏右侧，未登录在页面右上角。
- 时间一律带时区标注；时区按浏览器推断，推断失败兜底 `UTC`，不硬编码任何具体时区。

## 组合总则

1. 每个信息区只保留一个视觉主操作；次操作使用低强调样式。
2. 卡片内边距、标题到内容、区块到区块一律取间距阶梯上的值。
3. 结构化短值保留 `.mono` / `.num` 角色并使用 tabular numbers；当前与正文共用 Geist / Noto Sans SC，不另换等宽字体，不放大普通数字 / 日期 / 字母。
4. 表格、卡片、筛选条、反馈表面是 layout primitive，不携带任何领域含义。
5. 小屏把多列卡片与分栏收为单列；数据表改为可读的卡片式布局，而非水平截断关键内容。
6. 同一个类名只能有一个含义。
7. 页面 ID 一律先在登记表登记再实现；模块不得自造未登记的 ID，也不得在模块内重建菜单。
8. 产品画面不出现 PRD 条款号、字段来源注释、规则论证或内部交付说明；评审工具独立且默认关闭。
