## 页面组合

**一个侧栏条目「合约管理」，两个列表视图。** 项目审核队列是模块落地页，质押合约台账是同一入口体系下的独立只读列表，页头用视图切换在两条可寻址路由间切换；两个列表各自保留自己的筛选、排序与页码，互不覆盖。两者都是一级页面，不展示面包屑。

**项目审核队列。** 一行一个融资项目，退回后重新提交仍是同一行、同一项目编号。八列：项目编号 / 项目名称、资产方企业 / 代币类型、项目质押率 / 项目期限、本次提交时间（附第 N 次提交）、已等待时长、审核轴、部署执行状态 / 质押合约地址、查看。默认审核轴＝待审核、本次提交时间升序，可按本次提交时间与已等待时长升降序，带总数分页 20 条。关键词与审核轴常驻，部署情况、资产方企业、代币类型、提交时间区间向下展开并回显已应用条件；起点晚于终点就地报错。三项统计（待审核、部署失败待再次发起、近 7 个自然日人工审结）按项目数计，只应用企业 / 代币类型 / 提交时间 / 关键词条件，不受审核轴与部署情况筛选影响，部署失败不计入人工审结；统计与日期筛选按 UTC 自然日。队列没有逐行裁定与批量选择，进入详情才能办理。

**项目审核详情。** 左主区自上而下：顶部摘要（审核轴、部署执行状态、本次提交序次与时间、面客项目状态）→ 项目定位 → 创建信息核对 → 资产方与参数上下文 → 质押合约与部署事实 → 操作记录；右侧粘性审核处理区。创建信息七项全部只读；还款方式标平台定值、参考结算币种标只供参考不限制资金方报价币种。参数上下文把创建时锁定的质押率 / 期限与当前配置上限并列，不一致时标出差异并写明锁定值继续有效、不拦截提交、不改写锁定值、不产生整改待办；当前配置不可读时标「待核实」且不阻断审核。质押合约与部署事实是随真实结果回写的只读链上事实，尚未发起部署时只保留质押链、部署执行状态与部署发起地址，不铺一排「—」。

**审核历史即操作记录。** 按正文「操作记录是本项目进度的唯一来源，不另设第二套进度来源或重复的明细」，历次提交、结论、退回原因全文、部署尝试与结果合并在同一条倒序时间线里，结论节点用语义色辅助区分、文字始终可读；退回原因、失败原因、gas 与链上凭证在节点下方展开。没有第二份「审核历史」列表，也没有编辑、删除或手工完成进度的入口。加载中、暂无记录、读取失败分别反馈并可重试。

**办理。** 通过：弹窗回显创建信息、资产方与参数上下文，勾选知悉「提交后由平台统一钱包发起部署、部署成功即审核通过、项目与合约一一对应且不可撤销」后在本次办理内一次提交，没有第二步确认、没有第二位审核人。退回：填写 10～500 字面客可读原因 → 全文预览与二次确认 → 提交，确认页写明不部署、不消耗 gas、期限不重新起算、不产生新项目编号。部署失败后主操作改为「再次发起部署」，复用同一项目编号与同一条审核记录。提交中禁用表单与重复处置，失败保留输入。

**两条轴分开。** 审核轴（待审核 / 部署处理中 / 已通过 / 已退回）与部署执行状态（未发起 / 部署处理中 / 部署成功 / 部署失败 / 结果待核实）在队列与详情分列展示。部署处理中界面不显示「已通过」、处置入口不可用、不接受第二次提交；部署失败视为审核未完成，审核轴回到待审核并展示失败原因原文、失败时点与已消耗 gas（未知标「待核实」，不填 0）；结果待核实只保留已知事实与保护说明，不推定结果、不重复发起、不自动改判。

**质押合约台账。** 只列已部署成功的项目，一个项目一条、一个合约地址；列为项目编号 / 项目名称、资产方企业 / 代币类型、质押合约地址 / 质押链、部署时点、部署审核人、项目当前状态、查看。默认部署时点倒序可切升序，按企业、代币类型、部署时间区间与关键词筛选，地址缩略展示并可复制完整值。台账只读，不承载逐笔质押、额度与覆盖事实，也没有编辑、解押、重新部署入口；从一条记录进入该项目的审核详情，面包屑按来源返回台账并保留原筛选、排序、分页与所在位置。

**无时效。** 全模块没有截止时点、剩余时长、倒计时、临期强调或超期标记。右侧只有「已等待时长」，并写明是事实陈述而非期限。

## 会话与功能权限

会话与功能权限只读运营端账户与登录的一处登记（`CF.deferOpsBoot` + `CF.opsAuth`），模块不维护 `permission` 假数据、不自造权限编号：`PM-AL-17` 融资项目审核查询可看队列、台账、详情与操作记录但不显示任何处置入口；加持 `PM-AL-18` 融资项目审核与合约部署处置才出现通过 / 退回 / 再次发起。`PM-AL-18` 按 `D-AL-35` 须配套 `PM-AL-17`，所以仅开通处置的账号进入即被拒绝并说明须由建设方修正交付配置；两项皆无为无权限空态且菜单条目不展示。登录失效走共享运营登录页，重新登录后回到原来的队列、台账或详情。

共享菜单新增两处通用能力以承接本模块，既有条目行为不变：条目可声明 `pages`（同一入口体系下的多个页面共用选中态）与 `reachable`（交付里勾了该项但缺配套查询权限时入口仍可达，让账号读到拒绝原因而不是静默消失）。离线包的路由归属同步支持条目的 `routes`，台账深链在单文件评审件里可直达。

## 边界

- 本模块与企业账户无接口：不读取、不校验、不展示任何收款账户，结算收款链不进入本模块，只表述质押链（本期 ETH）。
- 全平台无平台统一钱包的维护、配置、切换、余额或充值入口；运营端不签名、不代付 gas、不发起或撤销任何链上动作，也不可编辑合约地址。
- 本模块不产生运营端站内消息，未改 `_shared/admin-message-data.js`；面客两类事件（项目审核通过 / 项目审核退回）在演示工具里以「已发送的面客站内信」列出，签名或部署失败、再次发起与结果待核实全程不发消息。
- 项目审核不产生任何质押额，本模块不消费、不展示、不计算三项额度。
- 演示数据、异步反馈、部署结果与站内信均为浏览器本地模拟，刷新重置业务数据；地址只保存浏览上下文，不授予权限。真实部署链路、链上回写、消息投递与权限登记仍需实机联验。

## 演示工具

右下角演示工具默认关闭，与产品画面分离。可切交付的账号配置（管理员 / 未开通 / 仅查询 / 仅处置 / 查询＋处置）、页面状态（默认 / 加载中 / 空数据 / 筛选无结果 / 读取失败）、提交反馈（成功 / 失败 / 已被他人裁定 / 提交前资产方已关闭项目）、操作记录状态、融资参数配置是否可读；可对当前项目做链上回写（部署成功 / 部署失败 / 结果待核实）、重放最新事件检查去重，以及模拟资产方修改后重新提交与关闭项目、运营登录失效、重置演示。

## 未自行定夺的事项

- **合约部署失败是否给资产方补可见出口、平台钱包余额与 gas 是否展示**：按现行正文执行——失败仅运营端可见、面客始终待审核且收不到消息；全平台无钱包余额与充值入口，仅在运营端如实展示部署实际 gas 与已消耗 gas。待用户裁定。
- `PM-AL-07` / `PM-AL-08` 的分权粒度在哪一册收口仍由用户裁定；本模块只使用自己的 `PM-AL-17` / `PM-AL-18`，未改其他模块的登记粒度。
- 质押链上凭证与合约地址缩略展示并可复制，**不放区块浏览器外链**——查验入口取值属 `Q-L7-08` / `Q-L8-06`，用户尚未裁定。

## 内部核验

Chromium 实测源码与导出单文件，112 项检查全部通过，1280 / 1440 / 1920px 各跑一轮，中英两种语言：

- 队列默认排序与三项统计取值、统计不受审核轴与部署情况筛选影响、审核轴四值与部署情况五值、关键词 / 企业 / 代币类型 / 区间组合、起点晚于终点校验、重置、分页与总数、筛选无结果与空态、读取失败与加载中。
- 详情的创建信息七项、只读定值口径、资产方与参数上下文、锁定值与当前配置差异、参数不可读降级、质押链与部署事实、部署发起地址、操作记录倒序与事件去重。
- 通过办理的知悉勾选拦截与一次提交、部署处理中不显示已通过且处置入口不可用、链上回写成功后产生唯一合约地址与通过站内信、通过后无第二次部署入口；退回的 10～500 字校验、全文二次确认、退回后不产生合约地址；部署失败的原因原文 / 已消耗 gas / 再次发起 / 仍可退回；结果待核实与主体标识缺失时的不放行；资产方关闭后离开待审队列、只读可回看。
- 台账只含已部署成功项目、默认部署时点倒序、地址可复制、不含额度字样；台账 → 详情 → 面包屑返回台账并保留上下文。
- 提交失败保留输入并可重试、并发只有一笔成立并展示现状、提交生效时项目已被关闭则拒绝且不产生结论；重复事件去重、资产方修改后重新提交（编号不变、序次加一、既往原因保留）、资产方关闭后离开待审队列但仍可检索只读回看。
- 四种交付配置（管理员、未开通、仅查询、仅处置）与对应空态 / 拒绝说明、菜单可达性。
- 全流程未出现截止、倒计时、剩余时长、临期或超期字样，产品画面无条款编号、字段来源注释或规则论证；1280 / 1440 / 1920px 无横向溢出、操作列可达。
- 仓库内 13 个原型页面回归无脚本报错、无 HTTP(S) 请求；离线单文件与源码的跨模块导航、台账深链均可用。

以上为本地模拟原型核验，未接入真实鉴权、钱包、链上回写或消息服务，不能据此宣称跨平台联验完成。截图仅用于内部核验，不随交付。
