## 继承与维护

- 根据用户评论 `5ca15d12-8aaf-4365-b9da-9bbe0a7fa20d` 修订：审核列表不再展示版本；详情左侧集中展示资料与结论，右侧仅保留审核操作，版本历史改为页面最下方的全宽表格。旧版、已处理和只读权限隐藏操作栏；从底部切换版本后返回详情顶部。沿用已有一次性交付和入库授权。
- 仓库 `wxblockchain/Chain-Financing`，目标 `cly2.0.0`。起始头 `0dd8c7e`，开发期间同步至 `2b72db9`（含运营账户公共层接入）；实际读取的样板/内容源最新提交为 `5c6ad85`。旧分支未修改。
- 运营列表继承 `_shared/样板/底座样板.html` 与 `sample-pages.js` 的协议管理台账；详情继承公共 card / key-value / 状态 / 弹层，按本 PRD 使用独立详情路由。无批量审核或额外统计卡。
- 两端共用 `_shared/tokens.css`、`base.css`、`shell.js`。测得主色 `#1D4ED8`、底色 `#F7F8FB`、管理端控件高 36px、卡片圆角 12px、控件圆角 9px；取值始终引用公共 token。
- 按新落库的运营账户契约登记查询权限 5，处置检测权限 6；若装载 `CF.opsAuth` 则消费其有效权限。独立附件使用本地权限样例，不重做登录。
- 管理端登记 `P-L40`、`P-L41`，路由 `/ops/institution-reviews`、`/ops/institution-reviews/detail?application=...`。模块只显示本入口实际承载的审核导航；其他模块原有导航保持其源文件定义。
- 面客沿用 `面客端/登录与账户体系/` 的 `P-L21/P-L22/P-L23`，保留步骤、协议、账户邮箱验证、壳层与异常处理。资金方脚本增加本地审核衔接、字段级原因与版本快照；不重建面客页面。
- 两个入口共同使用现有登录样式：将原 HTML 内的样式原样提取到同目录 `登录与账户体系.css`，两端引用同一来源，避免复制第二份。原登录入口保持单独可开；增加延迟启动以支持组合评审入口。
- 管理端维护为薄 HTML + 模块 JS，附带本页组合样式；最终附件由现有 `_shared/export.py` 自动内联，不维护第二份单文件源码。

## 覆盖与边界

| 端 / 角色 | 页面与功能 | 本轮覆盖 |
| --- | --- | --- |
| 运营查询与处置 | 列表、详情、材料、通过、字段级驳回、历史 | 状态/编号/标识/名称/时间筛选、分页、返回保留条件；二次确认、多问题中英文原因、只读旧版、当前结论回写 |
| 运营只读 / 无查询权限 | 列表、详情与处置边界 | 隐藏处置、拒绝旧页面写入；无查询时隐藏入口与受保护内容；处置前权限收回反馈 |
| 资金方本人 | 注册材料、结果、修改重提、变更 | 共用原账户流程；审核中锁定、L2 编辑不重置、重提版本递增、变更提交成功才 L3→L1、旧通过不恢复当前权限 |
| 两端异常 | 查询 / 材料 / 处置 / 提交 | 加载、空态、无结果、日期错误、失败重试；重复机构冲突、24 小时成功提交限频、未知结果查询、他人已处理；演示模版升级与旧版不受影响 |

演示假设集中如下，不是正式采集或审核政策：

- 保留目标分支近期确认的机构类型、注册地址必填，以及监管机构、牌照编号选填。机构名称、注册地、机构标识、业务联系人邮箱和单个材料槽位沿用现有演示模版。标识类型补齐 USCC / LEI / 国家+登记号选项；真实生效模版的强校验、机构占用与身份访问控制仍须服务端实现。
- “信息不一致 / 材料不清晰 / 信息不完整”为演示原因目录，中英文原因均要求填写，不任设未确认字数上限。通过始终由运营确认，不按材料齐备自动通过。
- `DEMO-2` 只演示移除业务联系人邮箱、监管机构转必填，以及其他值保留、旧原因目标调整；不表示业务方已批准该模版变化。
- 内置材料可查看示意内容。本地选择文件仍沿用既有原型仅保存文件名/大小/上传状态的行为，不上传或保存原件，显示原件不可预览兜底；没有虚构正式格式、大小或数量限制。
- 正式材料清单、审核判据、上传限制、审核时长及客服联系方式仍待业务确认。页面不展示虚构工作日数，客服保持既有不可用反馈。
- 钱包、邮箱投递、原件鉴权、并发锁、查重、提交限频、通知及权限均是本地模拟；不能代替后端安全与正式业务验收。演示状态可从工具重置，单文件内双端互通不等于两个真实部署单元已打通。
- 本期不做 SPV 认证、钱包更换/运营换绑、审核中编辑或删除材料、撤回、批量审核、双人复核、运营账户配置、正式模版配置、认证结论直接翻转及真实交易。
