## 打开与体验

默认打开运营审核列表。右下角默认关闭的演示工具提供“资金方本人 / 运营端”和异常切换。主申请 `DEMO-REG-001` 与既有资金方账户共用本地状态，可走完审核、修改重提、再次通过、已认证变更；其他 7 条示例用于筛选、分页与独立审核。

最终 HTML 由共享导出器内联生成，双击即可操作，无服务、CDN 或远程字体依赖。共享运营导航及账户入口保留，其他模块产物本轮未修改。刷新审核入口会重置演示样例；地址保留浏览上下文，不承诺跨刷新保留本入口的审核结果。

## V2.3 同步

- 每个账号仅维护最新已成功提交的机构资料、材料信息，以及独立编辑草稿。草稿、上传失败、提交失败或尚未确认的提交不替换当前资料；确认收到只覆盖一次。成功重提清空本次审核信息并新增一条待审核记录。
- 审核记录只含内部提交次序、提交人、提交时间、审核人、审核时间、结果与原因，不附表单、字段值、文件或模版内容副本。旧演示数据读取时转为记录，并移除历史资料快照。内部次序仅用于拦截旧审核动作，不呈现为版本列表。
- 运营详情最下方为全宽“提交与审核记录”时间线，从早到晚排列；每次成功提交和审核各为一个节点，分别显示操作人和时区时间。驳回后为“修改后提交”，已认证变更为“变更资料提交”；当前待审核只标在提交节点，不生成尚未发生的审核。右侧仍只放当前审核操作。列表不展示版本；详情、材料及确认弹窗取消资料版本标签和历史查看入口。旧版本地址明确提示不再提供历史资料，另给当前申请入口，不将最新资料冒充旧资料。
- 面客状态页保持纵向布局、首屏驳回与重提。审核记录位于提交信息内、默认折叠，使用同一动作时间线，展示提交人、每个动作时间及结果/原因，审核节点仅显示“运营审核”，不展示审核员身份。已驳回修改直接进入资料步。
- 单框驳回、非空校验、二次确认、返回修改、取消与键盘焦点保留。原因原文及换行在两端与后续记录中可读；旧字段级原因仅保留原因文字。
- 已认证变更成功提交才转待审核。原机构绑定只存规范化标识，不存旧表单：新旧标识在重审期间占用；通过替换原绑定，驳回保留原绑定并释放候选标识，不恢复旧认证权限或旧资料。
- 列表筛选、页码、申请地址、返回原行焦点及滚动位置保留。旧提交次序、跨申请及离开页面后的审核响应不能处置新提交；正常登录及审核中锁定继续生效。

## 继承与边界

薄 HTML + 模块 JS 复用共享 token、壳层、运营菜单与账户模块。资料栈、字段分组、跨行地址、240px 操作栏沿用确认布局；审核记录组合同步至 `_shared/design-system/管理端组件规范.md` §9。面客仍复用 `面客端/登录与账户体系/资金方账户.js` 及现有 CSS，未另建注册流程。

本期字段和必填性按已确认资料保留。材料可接受证明与审核判据、上传格式/大小/数量阈值、其他未确认限制及真实客服渠道未自行定稿。`DEMO-2` 仅演示模版变化，不代表正式准入政策。材料只存演示文件名、大小、上传状态；内置文件可查看示意内容，本地选件不保存或上传真实原件。

登录、钱包、邮件、材料鉴权、审核、并发、查重、限频及通知均为本地模拟，不代表后端安全或真实业务验收。不新增 SPV 认证、运营分权、批量审核、撤回或钱包换绑，不操作真实数据库。

最终自包含 HTML 的 Chromium 54 项检查通过，覆盖提交→驳回→修改后提交→通过链路、认证变更接续、操作人/时区时间对应、面客隐藏审核员、草稿/失败不增记、旧动作拦截、单框驳回与长原因回显、同刻排序、空记录和面客独立入口。中英文 1280 / 1440 / 1920px 无横向溢出；无脚本错误或 HTTP 请求。已实际查看运营与面客时间线。提交成功覆盖、草稿与失败隔离、旧审核动作守卫及标识占用逻辑未改；时间线直接使用已有记录，不另存资料、重复记录或未来审核事件。

## 2026-09-24 · 按现行三册 PRD 重建（WS-381）

`existing-system adaptation / console`。基线为分支 `cly-v3.0.0` 上的三册现行正文（提交 `04394e1a`）与[字段命名与术语对照表](../../../PRD/00-字段命名与术语对照表.md)第 6 节，并衔接运营端账户与登录原型的入库结果（`54d0b91`）。业务口径未变的页面、流程与文案沿用上一轮结果，不回读旧版原型或旧评论。

**机构证明材料按多份集合重建（`D-L181`、`AC-L627`）。** 原来两端都只承载一份文件。现在一次提交是一个文件集合：面客资料步可一次选多份、逐件替换 / 移除 / 失败重试，新增不覆盖已选文件，移除后迟到的上传结果不再回写；提交门槛改为「至少一份成功且可读取，且本次全部拟提交文件均成功」，仍在上传或失败时定位到材料区并说明处置方式。核对弹窗、面客当前详情与运营详情展示同一集合，分区标题标注份数，逐件预览 / 下载；单件读取失败只影响该件（可重试、下载仍保留），不写成「申请人未上传」。未确认的格式、大小、数量上限仍不展示假数值。共同做法已写入[文件上传与展示组件规范](../../_shared/design-system/文件上传与展示组件规范.md#多份材料集合)。

**字段名称对齐对照表第 6 节。** 中文业务名称未变；英文改为 Account contact email、Legal entity name、Country of incorporation、Entity identifier type / Entity identifier、Institution type、Registered office address、Regulatory authority、Financial licence number、Business contact email、Institution supporting documents。标识类型不再显示裸代码，改为业务全称加代码：统一社会信用代码（USCC）、法人机构识别编码（LEI）、商业登记号（REG_NO）；选项文案同步说明适用范围。字段取值按键定位，切换语言只改标签、不改取值。

**会话与功能权限改为读运营端账户与登录一处登记。** 模块自带的模拟登录弹层已删除，页面加载共享账户模块：查询与详情按 `CF.opsAuth.can` 判定，登录失效直接进入共享运营登录页，重新登录后回到原来的申请查询或详情。本模块按现行正文不分查询岗与处置岗——账号持有机构认证申请与材料查询即可查看并处置；只持审核处置时拒绝访问并说明须由建设方修正交付配置（不静默通过、不自动补授权）；两项皆无为无权限空态。共享菜单条目改为按任一项可达，因此配置不完整的账号仍能看到入口并读到拒绝原因。演示工具新增「交付的账号配置」一组：运营管理员、未开通本模块、仅开通申请查询、仅开通审核处置；评审工具的状态列表增加「无权限」。

**运营详情不再展示模版版本。** 按 `D-L187`「不展示提交版本或模版版本」，申请详情去掉该字段；面客侧按 `D-L185` 保留适用模版（核对确认与提交信息各一处），提交次序仍不出现。面客审核中把「刷新状态」改为「查询审核结果」，进行中、仍无结论与查询失败分别反馈，查询不改变申请状态、不产生新提交；客服入口与驳回原因、原因缺失及加载异常同处可得。面客「提交时联系邮箱」改称「提交时账户联系邮箱」，与运营详情的「当前账户联系邮箱」区分。

**未自行定夺的一项。** `PM-AL-05`（申请与材料查询）／`PM-AL-06`（审核处置）的分权粒度在哪一册收口仍由用户裁定：本模块按本册「不做运营查询/处置分权」执行，权限清单仍只在运营端账户与登录维护、未改其登记粒度；若裁定改为按运营端分权，本模块只需把处置动作单独校验 `PM-AL-06`。
