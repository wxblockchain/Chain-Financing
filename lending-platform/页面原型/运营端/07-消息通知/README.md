## 2026-10-15 · 两端列表统一（方案 B）

按用户“按照方案B执行”及 PRD `7b7e719`（两端第 6 节新增“新消息”段、AC-O18 / AC-NC-48 同步）修订；沿用修订入库授权。

- **新消息自动插入列表顶部。** 去掉“重新加载”按钮。每次自动更新（60 秒、页面重新可见、其他标签页写入共享消息池）时，只把符合当前筛选、且比已加载内容更新的消息插到顶部；不重新筛选已加载结果，“未读”筛选下刚读过的消息留在原处。插入前记下视口顶端那一条，插入后放回原位置，阅读位置不跳；不符合当前筛选的不插入，切换筛选后才看到。已加载与后续加载不重复、不遗漏。
- **列表版面以面客端现版为准。** 筛选纳入列表白色内容面顶部：下划线阅读状态（全部 / 未读 / 已读）+「分类：当前选项」合一下拉，桌面端吸顶于运营端顶栏下；「全部已读」改为页标题右侧低强调动作，不可用时在其下说明“当前筛选下没有未读消息”。两端共用同一组 `.nc-inbox` 样式，删去运营端自有的筛选、行高与标题截断覆盖。
- **补原业务名称与编号行。** 每条消息在标题下显示来源提供的原业务名称与编号，用来区分同名消息；缺项不显示。
- **时间显示规则统一。** 列表与最近消息预览 24 小时内用相对时间、更早用完整时刻并带时区（共享 `CF.relTime`，悬停看完整时刻）；详情始终完整时刻。

Chromium 实测：1280 / 1440 / 1920 × 中英，列表、详情、全部已读确认无横向溢出、无脚本异常与外部请求；筛选栏吸顶位置正确。自动插入：下滑后到达新消息时锚点行位置不变（285 → 285）、新消息位于顶部；分类筛选不匹配时不插入；“未读”筛选下读过的消息保留；插入后再加载更多无重复。其余五个运营端模块的铃铛预览时间规则一致、无异常。

## 2026-10-15 · 详情页底部简化

按用户“详情页仅保留查看相关内容按钮，点击跳转到对应页面；无需返回列表、查看协议版本、查看协议操作记录等按钮，无需精确展示”修订，沿用修订入库授权，未改业务口径。

- 详情底部只保留一个“查看相关内容”，指向来源登记的那一笔原业务或固定页面；去掉“返回列表”“查看协议操作记录”及按目标类型变化的按钮文案。返回列表改由面包屑“消息中心”和浏览器返回承担，筛选、已加载批次、位置与来源消息焦点照常恢复；从账户设置回到原消息的链接保留。
- 原业务关联信息块改为正文下方的一行：原业务名称 + 可复制的业务编号（来源提供时才显示），不再逐项列出机构、提交次数、版本等定位字段，与面客消息中心的呈现方式一致。
- 不可前往时不再放无效按钮：原业务不存在或无权查看时，原按钮位置只显示“相关内容暂不可访问”；原动作已办完时保留入口并在左侧说明“该操作已不适用，可查看当前结果”；类型未登记或来源设为不跳转时底部不出现任何内容。原业务检查中按钮显示“正在检查…”，超时后仍可前往并附说明。
- 详情加载失败的空态仍保留“重试”和“返回列表”，这是该失败状态必需的出路，不属于本次简化的底部按钮区。
- 演示数据把逐项关联字段收敛为“名称 + 编号”，去掉协议操作记录的二级去向；演示工具的目标权限开关改为机构申请查询、协议当前内容查询、协议历史版本读取三项。

Chromium 实测：1280 / 1440 / 1920 下十一种详情分支的底部呈现、原业务检查超时、跳转到协议与账户设置、从账户设置回原消息、面包屑与浏览器返回后批次和位置恢复，均无横向溢出、脚本异常或外部请求。

## 2026-10-15 · 按两端统一后的三册更新

分类为 `existing-system adaptation / console`，在 `cly-4.0.0 @ 977ab8e` 上按本模块现行三册（01 功能与业务规则、02 流程图与状态机、04 验收，2026-10-15 需求评审稿）修订；本模块不发送消息，没有 03 册。沿用已有的直接修订与入库授权，未改业务口径。

- **列表改为“加载更多”。** 与面客端同为每批 20 条追加，不给页码、不能改每批条数、不显示含已读的总条数，到底时说明没有更多。地址只保存分类与阅读状态；修改筛选从第一批开始。加载更多失败保留已加载内容与位置，就地重试；加载中不能重复触发。新消息不挤动已加载的快照，“重新加载”后才纳入。从详情返回时恢复筛选、已加载批次、滚动位置与来源消息焦点。
- **统一分类。** 采用两端共用的六类：业务办理进度、业务提醒、认证与合规、账户安全、审核任务、运营告警。本端现有消息归入审核任务（机构资料待审核）、运营告警（协议三类告警）与账户安全（密码变更）；筛选只列出本人实际有消息的分类，无法识别时回落“其他 / Other”。共享消息池存储键升位，旧缓存不会带回旧分类。
- **前往原业务按当前情况处理。** 原业务不存在与本人无权统一显示“相关内容暂不可访问”，不给入口、不区分二者；原动作已办完时说明已不适用，主按钮改为“查看当前结果”；消息过期只在列表与详情标示“已过期”，不再收回查看原业务的入口；类型未登记或来源设为不跳转时不给入口，也不再给任何提示。进入详情时的原业务检查最长 3 秒，期间主按钮显示“正在检查”，超时或失败仍允许前往。
- **已读与失败反馈。** 已读保存失败时详情仍显示未读，就地给“重试”，重试只处理已读，不再在后台自动补标；详情加载失败说明“尚未标为已读”，同时给重试与返回列表。全部已读的确认改为“将把当前筛选下的 {count} 条未读消息标为已读。”并列出分类与阅读状态，默认焦点在取消；阅读状态“未读”按真实阅读事实筛选，过期未读同样在范围内。
- **其他。** 原业务关联中的申请编号可复制；两种语言都无法展示时标题兜底为“通知 / Notification”；无消息权限时的拒绝说明改为与其他运营端模块一致的交付配置口径。本期运营端只有运营管理员一个角色，演示工具里的“后期角色”与目标权限开关只用于预演后续细分角色后的入口收敛，不是本期产品功能。

Chromium 实测：1280 / 1440 / 1920 三宽度下列表、详情与中英文无横向溢出、无脚本异常、无外部请求。核验加载更多的加载中、失败重试、到底提示，返回后批次与位置恢复；十一种详情分支（可前往、协议告警、历史版本、原动作已办完、原业务不存在、无权查看、已过期、类型未登记、不跳转、内容异常、纯文本安全）；原业务检查超时；已读保存失败与重试；详情加载失败；编号复制入口；全部已读确认文案、默认焦点与执行；无消息权限拒绝与入口隐藏；后期角色预演下的统一不可访问；会话失效回登录且内容清除。融资参数配置、协议管理、项目合约管理、机构认证审核、代币质押审核五个模块页面加载共享消息池无异常、预览同步。离线单文件版已重新导出并抽查。真实消息服务、送达时效与后台鉴权仍未接入。

## 2026-09-25 · 按现行三册重建承接事件与业务目标

分类为 `existing-system adaptation / console`，在 `2cf3d46` 上按本模块现行 PRD 三册（2026-09-24 需求评审稿）修订，沿用已有的直接修订与入库授权。未改业务口径，未新增 PRD 未定义的能力。

**承接事件集重建。** 演示消息池按本册第 1 节现行登记重建为五类来源事实：全体运营为机构资料待审核，以及定时生效成功、定时生效失败、待生效计划撤销三类协议告警；本人为密码变更通知。原先泛化的“本期运营通知已发布”条目删除——本模块没有广播发布与公告编辑能力，该条目不对应任何已登记来源事件。本批废止的时点提醒（质押审核超时、报价与放款还款各类临期／超期、催办）在池内与文案中均不出现，也不因等待时长自造提醒。共享池存储键升位，旧浏览器缓存不会把旧事件带回。

**分类。** 收敛为审核待办／协议告警／账户安全，只列出本人实际有消息的分类；来源分类尚未登记时回落“其他”，合法消息不消失、不隐去。正式分类取值仍随来源共享登记未定。

**业务目标改为真实记录。** 三类目标各进真实页面，不再用示例抽屉代替：机构待审核进入机构认证审核的该申请详情并带上该模块的列表上下文；协议告警进入该协议的版本详情或协议详情，并按需另给协议操作记录入口；密码变更进入本人账户设置并保留返回原消息的入口。跨模块跳转走共享菜单的同一套导航与守卫，离线单文件版同样可达。正文之后新增“原业务关联”信息组，展示来源给出的定位事实（申请编号、机构名称、提交次数、协议名称与版本），无目标时不强造该组。

**目标逐项判权。** 消息准入仍只看运营端消息查看；目标分别按机构申请查询、协议当前内容查询、协议历史版本读取、协议操作记录查看判定，四者互不替代，权限取自共享账户模块的交付配置，本模块不另建权限清单、不自造编号。协议操作记录不以协议内容查询为前提：未开通协议内容查询的账号读到协议告警时，正文与操作记录仍可得，协议内容与历史版本给出“当前无权查看该记录”，消息本身继续可读并计数。

**目标可达性辅助判断。** 进入详情时对原业务对象做一次辅助判断，最长 3 秒；期间主按钮显示检查中，确认可达后恢复入口；超时或失败仍允许尝试进入并提示未能确认，目标页自身的权限与状态限制照常生效。静态页面目标不做该判断，列表不提前判断、不因此阻塞。

**失效与动作失效分开。** 结论已生效时说明原审核动作不再可用、保留原记录只读入口；目标删除、目标无权限、消息自身失效分别解释并停用入口；目标未登记时只说明尚未登记业务记录，不提供无效入口、不跳默认页；无目标不补“无法跳转”说明。
