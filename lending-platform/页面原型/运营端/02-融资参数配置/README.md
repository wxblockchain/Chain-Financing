## 页面组合

**一个侧栏条目「融资参数配置」，台账 → 详情 → 维护三层。** 列表是模块落地页、一级页面不展示面包屑；详情与维护沿真实父级链展示面包屑并原路返回，保留原筛选、排序、分页与所在位置。

**融资参数列表。** 一行一个代币类型，七列：代币类型、最高质押率、最长项目期限、配置状态、最近更新时间、最近更新人、操作。最高质押率一律按两位小数呈现（如 `70.00%`）；未配置行的两项参数、最近更新时间与最近更新人一律「—」，不显示 0、不显示平台默认值，行首以警示色竖条标识。存在未配置的代币类型时，表格上方给出数量提示「有 N 个代币类型尚未配置，暂不可用于创建融资项目」并可一键「只看未配置」。操作列为「查看」与「维护／配置」（未配置行显示配置），可从列表直达办理。关键词模糊匹配代币类型名称（忽略大小写与前后空格），配置状态可筛已配置 / 未配置，查询与重置成对；默认代币类型名称升序，代币类型与最近更新时间两列可升降序；每页条数（20 / 50 / 100）并入底部分页条。筛选、排序、页码与每页条数都写进地址，前进后退与从详情返回都保持原位置。列表没有新增、删除代币类型的入口，也没有逐笔质押、项目或代币的跳转。三种空结果分别表达：开发尚未新增任何代币类型（说明由开发在后端新增、缺少时联系开发，不提供新增入口）、筛选无匹配（给重置）、取数失败（可重试且保留条件）；无查询权限的空态保留给后续细分角色。

**代币类型参数详情。** 顺序固定为先当前参数后参数变更记录，不另立独立的记录页。当前参数六项：代币类型（只读、注明由开发在后端新增）、最高质押率、最长项目期限、配置状态、最近更新时间（带时区）、最近更新人（脱敏后的可读归属）。参数变更记录五列：发生时间、操作人、最高质押率、最长项目期限、本次结果；每次保存成功一条，按发生时间倒序、默认 20 条可继续加载，首次配置记为从「—」到新值，两项中未变的一项标「未变」而不写成一次改动。记录只读、不按本人经办过滤，不含项目、代币、质押笔或企业信息，也没有任何逐笔质押跳转。尚无记录、加载中、读取失败与登录失效分别表达。

**参数维护与保存确认。** 办理就地进行：维护页沿用详情的组合，以代币类型为标题，上方是可编辑的「维护参数」卡、下方保留参数变更记录作对照；一次只维护一个代币类型，代币类型只读，没有多行批量编辑、复制到其他类型与导入导出。最高质押率为带「%」后缀的输入框，按已裁定的「大于 0、最高 100%、最多两位小数」校验，旁注当前取值；最长项目期限改为 3～12 个月的下拉选择，杜绝越界与非整月输入。未配置时质押率为空、期限为「请选择」，不预填。失焦即校验该项并就地给出可定位的说明：为空、非数字、不大于 0（含负数）、超过 100%、小数超过两位分别有各自的提示且都附当前允许范围；恰为 100%、`0.01%`、`79.99%` 等边界值不报错；小数超过两位如实拒绝，不替用户四舍五入。改动按取值比较——把 `70` 改写成 `70.00` 不算改动；改过的项在标签旁标「已修改」，两项均未改动时保存不可用并给出原因。保存进入确认：回显代币类型与两项参数的变更前后，未改的一项只标「未变」；首次配置额外说明保存后即可用于创建融资项目；并写明「仅对此后新建项目生效，不改变存量项目」，「返回修改」回到表单且保留输入。保存成功回到详情，最新一条变更记录以「本次保存」标出。提交中禁用表单并拦截重复提交，结果按真实状态呈现——失败保留输入可重试；结果未知与他人先行修改时在表单内给出「重新取数」（有未提交内容先确认），对方的保存正常留痕；代币类型在办理期间被开发在后端移除则拒绝保存，说明未保存任何参数、已创建项目不受影响。离开办理在有未提交内容时先确认。

**代币类型的新增与移除。** 代币类型条目只由开发在后端新增或移除，不随代币发行与同步自动新增；运营端没有新增、改名或删除入口，列表与空态也不暗示类型会自动出现。本期只有一个条目 `ERC-20-应收账款`，列表按多行规格编写。开发新增的条目两项参数为空，以未配置出现在列表，配置完成前不可用于创建融资项目。代币域出现新类型而开发尚未新增时，列表不变。开发移除的条目离开列表、不再供给创建，已创建项目仍按锁定值运行；其参数变更记录在原地址保留可查，并注明已移除、不可维护；办理中被移除则拒绝保存。同名条目被移除后再由开发新增，按新的未配置条目处理，不恢复旧值。

**不做的事。** 本模块没有草稿、待生效、定时生效、生效计划或发布环节，也没有回滚、撤销与历史值恢复；没有存量项目清单、整改待办或强制关闭；没有利率、费率、额度、币种、链与审核类参数；没有截止时点、剩余时长、倒计时、临期强调或超期标记；不提供文件上传与下载。

## 会话与功能权限

会话与功能权限只读运营端账户与登录的一处登记（`CF.deferOpsBoot` + `CF.opsAuth`），模块不维护 `permission` 假数据、不自造权限编号。**本期单一角色**：按 WS-380 `D-AL-08`，本期运营端只有运营管理员一个角色，`PM-AL-19` 融资参数查询、`PM-AL-20` 融资参数维护对每个账号全部开通，产品画面始终是两权齐备的完整读取与办理。按权限差异的分支（仅查询权的只读详情、缺配套查询的拒绝说明、无查询权空态）按本册保留为后续细分角色的规则，只在默认关闭的演示工具「后期角色」预览中可见，本期不承载、不作验收。登录失效走共享运营登录页，重新登录后回到原来的列表、详情或办理页。

共享菜单沿用 WS-387 已有的 `pages` 字段，让三个页面共用同一个侧栏选中态，未新增第二套机制。

## 边界

- 本模块只供参数，不参与项目审核、不提供审核入口，也不把参数改动当作审核依据；项目合约管理只读引用当前配置值，并按创建时锁定的快照核对，两侧表述一致。
- 逐笔质押的查询与处置固定在代币质押审核，本模块没有入口、跳转与只读副本。
- 与机构账户无参数、字段或收件关系，不采集也不展示机构账户信息。
- 本模块零站内信事件、零模板，未改 `_shared/admin-message-data.js`；校验提示、保存结果、取数失败与重试是页面反馈，不是消息通知。
- 演示数据与异步反馈均为浏览器本地模拟，刷新重置业务数据；地址只保存浏览上下文，不授予权限。真实配置读写、开发后端的条目新增与移除与权限登记仍需实机联验。

- 列表保留原七列，按内容重新分配列宽。最高质押率、最长项目期限及其表头右对齐，使用等宽数字而不把普通业务名称设为代码字体；表格正文使用 `--fs-13`。更新人、带时区时间和操作均完整可达。总数与每页条数放在分页条左侧，翻页保留在右侧。

### 基线功能缺陷（交回 Hallmark）

在 `93cb656` 原始 HTML / JS 和本次视觉版本均复现：演示工具开发新增 TRC-20 条目 → 查看该条目详情 → 演示工具开发移除该条目 → 关闭工具，页面会显示仍有效的 ERC-20 条目，但 URL 仍指向 TRC-20。记录数据未被删除，问题在当前对象的呈现：评审目录 `route()` 在计算入口时把 `A.selected` 换成首个未移除条目，随后重绘读取了另一对象。此项涉及对象选择与交互逻辑，本轮未修；建议 Hallmark 将评审入口计算改为无副作用，并补验已移除对象的原地址、记录留存和关闭工具后的对象一致性。它不需要新的业务裁定。
