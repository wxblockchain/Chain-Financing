## 页面组合

**一个侧栏条目「项目合约管理 / Project contracts」，两个列表视图。** 项目审核队列是模块落地页，质押合约台账是同一入口体系下的独立只读列表，页头用视图切换在两条可寻址路由间切换；两个列表各自保留自己的筛选、排序与页码，互不覆盖。两者都是一级页面，不展示面包屑。

**项目审核队列。** 一行一个融资项目，退回后重新提交仍是同一行、同一项目编号。八列：项目编号 / 项目名称、项目发布方 / 代币类型、项目质押率 / 项目期限（生效日～到期日，UTC）、本次提交时间（附第 N 次提交）、已等待时长、审核轴、部署执行状态 / 质押合约地址、查看。默认审核轴＝待审核、本次提交时间升序，可按本次提交时间与已等待时长升降序，带总数分页 20 条。关键词与审核轴常驻，部署情况、项目发布方、代币类型、提交时间区间向下展开并回显已应用条件；起点晚于终点就地报错。统计为两张卡：「待审核」卡内列出「其中：部署失败待再次发起」，作为子集、不与之相加；另一张为近 7 个自然日人工审结（通过按合约部署完成时间计，部署失败不计）。统计只应用企业 / 代币类型 / 提交时间 / 关键词条件，统计与日期筛选按 UTC 自然日。队列没有逐行裁定与批量选择，进入详情才能办理。

**项目审核详情。** 页头为项目编号与项目名称；顶部摘要为审核轴（已有结论时附审核人与结论时间）、部署执行状态、本次提交序次与时间、面客项目状态。左主区自上而下：创建信息核对 → 项目发布方与参数上下文 → 质押合约与部署事实 → 操作记录；右侧粘性审核处理区。创建信息八项全部只读，第一项为区块链网络（本期固定以太坊，创建时锁定），项目期限按「生效日～到期日」呈现；还款方式标平台定值、参考结算币种标只供参考不限制资金方报价币种。参数上下文把创建时锁定的质押率 / 项目期限与当前配置的最高质押率 / 最长项目期限并列，不一致时标出差异并写明锁定值继续有效、不拦截提交、不改写锁定值、不产生整改待办；当前配置不可读时标「待核实」且不阻断审核。质押合约与部署事实是随真实结果回写的只读链上事实，时间只用「合约部署完成时间」一种叫法；尚未发起部署时只保留区块链网络、部署执行状态与部署发起地址，不铺一排「—」。

**审核历史即操作记录。** 只有一条操作记录：历次提交、结论、退回原因全文、部署尝试与结果合并在同一条倒序时间线里，审核历史从中读取。提交通过时记「提交通过并发起部署」，部署成功回写时另记「部署成功（即审核通过）」。结论节点用语义色辅助区分、文字始终可读；退回原因、失败原因、gas 与链上凭证在节点下方展开。没有编辑、删除或手工完成进度的入口。加载中、暂无记录、读取失败分别反馈并可重试。

**办理。** 通过：弹窗回显创建信息、项目发布方与参数上下文，勾选知悉「提交后由平台统一钱包发起部署、部署成功即审核通过、项目与合约一一对应且不可撤销」后在本次办理内一次提交，提交成功即结束办理并进入部署处理中，没有第二步确认、没有第二位审核人。退回：填写 10～500 字面客可读原因 → 全文预览与二次确认 → 提交，确认页写明不部署、不消耗 gas、期限不重新起算、不产生新项目编号。部署失败后主操作改为「再次发起部署」，复用同一项目编号与同一条审核记录，也可改为退回。提交中禁用表单与重复处置，失败保留输入。

**两条轴分开。** 审核轴（待审核 / 部署处理中 / 已通过 / 已退回）与部署执行状态（未发起 / 部署处理中 / 部署成功 / 部署失败 / 结果待核实）在队列与详情分列展示。部署处理中界面不显示「已通过」、处置入口不可用、不接受第二次提交；部署失败视为审核未完成，审核轴回到待审核并展示失败原因原文、失败时点与已消耗 gas（未知标「待核实」，不填 0）；结果待核实只保留已知事实与保护说明，不推定结果、不重复发起、不自动改判。

**已关闭项目。** 资产方关闭或有效期到期后，审核轴保留关闭前的取值并加「项目已关闭 · 关闭原因」标记（资产方主动关闭 / 有效期到期），不计入待审核、默认视图不出现、不可裁定、不可再次发起部署；按其他条件仍可检索并只读回看。部署处理中（含结果待核实）资产方不能关闭项目，详情的部署说明写明这一点；部署失败回到待审核后资产方可以关闭。待审核或已退回的项目到达有效期至时自动关闭，关闭原因为「有效期到期」，操作记录追加「项目到期自动关闭」（主体：系统），之后不可裁定、不可再次发起部署；通过或退回提交时项目已到期的，弹窗就地提示「项目已到期」并拒绝，不形成结论、不发起部署。部署处理中（含结果待核实）跨过有效期至的暂不关闭，详情写明等回写后处理：部署成功即审核通过、照常发出审核通过站内信，随即自动关闭；部署失败随即自动关闭。

**质押合约台账。** 只列已部署成功的项目，一个项目一条、一个合约地址；列为项目编号 / 项目名称、项目发布方 / 代币类型、质押合约地址 / 区块链网络、合约部署完成时间、审核人、项目当前状态、查看。默认合约部署完成时间倒序可切升序，按企业、代币类型、合约部署完成时间区间与关键词筛选，地址缩略展示并可复制完整值。台账只读，不承载逐笔质押、额度与质押情况，也没有编辑、解绑、重新部署入口；从一条记录进入该项目的审核详情，面包屑按来源返回台账并保留原筛选、排序、分页与所在位置。

**无时效。** 全模块没有截止时点、剩余时长、倒计时、临期强调或超期标记。右侧只有「已等待时长」，并写明是事实陈述而非期限。

## 会话与功能权限

会话与功能权限只读运营端账户与登录的一处登记（`CF.deferOpsBoot` + `CF.opsAuth`），模块不维护 `permission` 假数据、不自造权限编号。本期只有运营管理员一个角色，固定具备 `PM-AL-17` 融资项目审核查询与 `PM-AL-18` 融资项目审核与合约部署处置，产品画面不出现角色切换。`PM-AL-18` 须配套 `PM-AL-17`，仅开通处置的交付配置进入即被拒绝并说明须由建设方修正交付配置，这一拒绝态保留；两项皆无为无权限空态且菜单条目不展示。「只查询」等细分配置只在默认关闭的评审工具里作为后期角色预演。登录失效走共享运营登录页，重新登录后回到原来的队列、台账或详情。

共享菜单条目声明了 `pages`（同一入口体系下的多个页面共用选中态）与 `reachable`（交付里勾了该项但缺配套查询权限时入口仍可达，让账号读到拒绝原因而不是静默消失）；离线包的路由归属用条目的 `routes`，台账深链在单文件评审件里可直达。

## 边界

- 本模块与机构账户无接口：不读取、不校验、不展示任何收款账户，结算收款链不进入本模块；质押合约所在链统一称「区块链网络」（本期以太坊），与创建信息同一叫法。
- 全平台无平台统一钱包的维护、配置、切换、余额或充值入口；部署（通过与再次发起）由运营人员连接平台统一钱包签名，gas 由平台统一钱包承担、个人不付费；运营端不代资产方签名或发起、撤销链上动作，也不可编辑合约地址。
- 本模块不产生运营端站内消息，未改 `_shared/admin-message-data.js`；面客两类事件（项目审核通过 / 项目审核退回）在演示工具里以「已发送的面客站内信」列出，签名或部署失败、再次发起与结果待核实全程不发消息。
- 项目审核不产生任何质押额，本模块不消费、不展示、不计算三项额度。
- 演示数据、异步反馈、部署结果与站内信均为浏览器本地模拟，刷新重置业务数据；地址只保存浏览上下文，不授予权限。真实部署链路、链上回写、消息投递与权限登记仍需实机联验。

## 演示工具

右下角演示工具默认关闭，与产品画面分离。可切账号配置的后期角色预演（运营管理员 / 未开通 / 仅查询 / 仅处置 / 查询＋处置）、页面状态（默认 / 加载中 / 空数据 / 筛选无结果 / 读取失败）、提交反馈（成功 / 失败 / 已被他人裁定 / 资产方关闭先于本次提交生效——通过或退回弹窗就地提示「项目已关闭」并拒绝，不形成结论、不发起部署）、操作记录状态、融资参数配置是否可读；可对当前项目做链上回写（部署成功 / 部署失败 / 结果待核实）、重放最新事件检查去重，以及模拟资产方修改后重新提交与关闭项目（部署处理中点击即演示关闭被拒）、运营登录失效、重置演示。

## 未自行定夺的事项

- **合约部署失败是否给资产方补可见出口、平台钱包余额与 gas 是否展示**：按现行正文执行——失败仅运营端可见、面客始终待审核且收不到消息；全平台无钱包余额与充值入口，仅在运营端如实展示部署实际 gas 与已消耗 gas。
- 部署交易凭证与合约地址缩略展示并可复制，**不放区块浏览器外链**——查验入口取值属 `Q-L7-08` / `Q-L8-06`，用户尚未裁定。
