# 项目合约管理 · UI 视觉深化

`existing-system adaptation · console`，2026-10-16。基线为 `cly-4.0.0` 远端头 `571714a`，本模块上次业务原型修订 `dcb5d33`。按本 issue 已有入库授权直接提交到原分支，不新开 PR。

## 1. 视觉基线与范围

沿用 Harbour Credit 运营端的蓝色动作、白色表面、Geist / Noto Sans SC 本地字体、共享语义字号、36px 紧凑筛选、44px 普通操作和只读事实字段。参考 [运营端组件规范](../../_shared/design-system/运营端组件规范.md) 与 [共享组件视觉规范](../../_shared/design-system/共享组件视觉规范.md)。不调整全局 token、壳层和其他模块。

业务不变量：同一项目及同一审核记录、两条状态轴、统计和日期口径、创建信息八项、完整地址复制、审核权限、关闭与到期规则、退回原因与二次确认、连接平台统一钱包及签名、部署成功即审核通过。没有新增指标、字段、权限或步骤。

## 2. 本轮实现

- **队列**：两张统计卡改为紧凑的横向数字与单位，部署失败子集在待审核卡内以分隔线区分；完整统计说明原位保留。排序选择器与筛选控件统一紧凑高度，较窄画布下操作组换行。
- **表格**：统一单元格横向内距、项目标识字重、日期与次级文字行距。宽表设置1080px阅读下限，在列表容器内横向滚动，右侧查看操作固定；不等比缩小或删除列。两条状态轴继续分列、文字与语义色并用。台账补上原日期校验错误的可见展示，沿用原拦截条件与文案。
- **详情**：摘要四组事实之间增加轻分隔，≤1200px改两列；区块标题使用共享区块字号及底部分隔线，正文继续复用 `.ops-facts-*` 容器查询。右侧审核栏、等待事实及费用披露保持原有层级和行为。
- **办理**：弹窗最大宽度760px；核对事实使用有行分隔的两列组合，知悉勾选区使用主色浅底及完整键盘焦点。退回原因全文、确认步骤及取消后放弃确认保持原样。
- **维护**：将原 HTML 内联样式整理为同目录 `项目合约管理.css`，该文件是模块组合的唯一来源；JS 仅改变统计展示的标签嵌套、台账错误展示与宽表容器的键盘访问属性。宽表容器带可访问名称，可聚焦后用方向键滚动。单文件从共享导出器生成，不手改附件。

## 4. 核验与运行

Chromium headless，源码与导出离线单文件分别检查中文 / 英文、1280 / 1440 / 1920px，共213个呈现与关键路径检查；补测台账筛选展开、无效日期提示、关键词查询及详情返回保留条件、横滚末端操作列与审核栏吸顶。页面和弹窗无文档横向溢出，宽表仅在自己的容器内横滚，操作列始终可达。详情字段、长标签、说明、时区与原精度保留。本地字体实际加载，无外部网络请求或脚本报错。键盘抽查 Enter 开启、Esc 关闭回到原入口、Tab 焦点可见及宽表方向键滚动。截图仅用于内部核验。

通过路径实测至签名提交、部署处理中禁用重复操作和成功回写；退回核对返回保留完整输入。未做真实鉴权、钱包或链上联调、消息投递、全量业务 AC、Safari / Firefox / 真机或屏幕阅读器验收。运营端目标为桌面；已有窄容器字段适配继承，不将本轮称为移动端完整设计。
