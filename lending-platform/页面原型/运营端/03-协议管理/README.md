- **原型基线**：在 `d27a19e` 的交互精简上继续，`2040d9c` 的列表工具条、详情字段行和两卡办理页组合不变。
- **以本节为准**：下文各轮记录中的草稿、生效方式、定时 / 立即生效、确认对照和“调整前 / 确认后文件”都已被本节取代，只作历史记录。

### 现行交互

- **更新协议**：页面只做一件事，选择一个文件并上传。
  - “协议文件”卡：已有待生效版本时，先列出该版本的文件（可预览、下载），下面是“新文件”。新选的文件标为“尚未上传”，可以替换或移除。
  - “发布设置”卡：列出版本号（新版本 / 覆盖待生效版本）、生效时间（当天 UTC 24:00，按本人时区显示）、当前生效版本，以及选填的变更说明。
  - 没选文件时“上传”不可用。上传直接提交，不弹确认。成功后回到基本信息，提示中写明生效时间。
- **覆盖**：已有待生效版本时，页头提示写明它的生效时间，并说明再上传会覆盖文件、版本号与生效时间不变。上次生效失败时，提示会写明将在下一个 24:00 再次生效。提交时按协议当时的状态判断，所以别人先上传后，本次上传自动变成覆盖，以后提交的为准。
- **撤销待生效**：只在有待生效版本时出现，需二次确认。确认框列出协议、版本和原生效时间，并说明撤销后的结果：当前生效版本不变，或协议回到“未发布”。撤销后该版本及文件移除，版本号不复用；直接访问被撤销的版本会提示不存在。
- **离开保护**：已选文件，或改过变更说明时，离开会先确认。移除文件且没有其他改动时可直接离开。
- **状态**：去掉“草稿”。协议状态只剩已生效、待生效、未发布、已下线；版本状态为待生效、已生效、已归档、已取消，生效失败附在待生效上。
- **版本详情**：删除生效方式。待生效版本显示“计划生效时间”，已生效、已归档版本显示“实际生效时间”，已取消版本显示原计划生效时间、取消时间和原因。指纹说明改为“尚未生效，生效前可被覆盖”。
- **操作进度**：操作类型改为上传、覆盖上传、撤销待生效、系统生效、系统归档、到点生效失败、协议下线、关联取消。上传摘要带生效时间。覆盖上传展开后只对照文件名和变更说明，不再有文件内容指纹，也没有查看或下载旧文件的入口（PRD 第 10 节的旧差异已一并消除）。
- **权限**：上传需要维护和发布两项权限，撤销只需发布。
  - 缺发布权限：没有“更新协议”入口。
  - 缺维护权限、协议也没有待生效版本：同样没有入口。
  - 缺维护权限、协议有待生效版本：可以进入，但只能撤销。
- **演示工具**：“下次提交”可以模拟提交失败，对上传和撤销都有效；“模拟他人先上传”用于核验以后提交的为准。“每日 24:00 生效”可以模拟生效成功或失败；失败后顺延到下一个 24:00。
- **消息样本**：撤销告警改为指向协议详情，正文补上操作人、原生效时间和“已移除”；生效失败告警补上“下一个 24:00 再次生效”。这两处改的是共享消息样本 `_shared/admin-message-data.js` 里的协议条目，其他模块的消息没动。
