# 企业账户 · 前端交付说明

面向前端实现的页面口径。业务规则以 [PRD 三册](../../../PRD/面客端/03-企业账户/01-企业账户-PRD.md) 为准，本文只写界面怎么做。颜色、字号、间距、圆角一律取 `_shared/tokens.css` 的变量，组件取 `_shared/base.css` 的公共类，不另起样式值。原型源码：本目录 `企业账户.js`（页面与交互）、`企业账户.css`（本页增量）、`演示数据.js`（字段定义、校验与规范化，可直接对照实现）。

## 1. 页面、入口与命名

| 项 | 口径 |
| --- | --- |
| 路由 | `/company-accounts`；Tab 写在 query：`?type=fiat`（默认，可省略）/ `?type=crypto`。刷新、分享、浏览器前进后退都恢复当前 Tab |
| 壳层 | portal 顶栏工作区；不进主导航，不展示面包屑（一级入口） |
| 入口 | 只在账号菜单第三项。资产方显示 **Company accounts / 企业账户**，资金方显示 **Institution accounts / 机构账户**；页面标题、浏览器标题跟随同一展示名。两侧是同一页面、同一套字段与接口，接口与数据一律按“企业账户”命名 |
| 业务办理回流 | 从报价确认、放款登记的「前往企业账户 / 前往机构账户」进入时带 `return`（原页面路径）、`from`（`quote` / `loan`）、`business`（业务编号）。页面顶部显示回流条与「Back to the transaction / 返回原办理」，返回后重新打开原办理的原步骤，已填内容保留。`return` 只接受站内路径 |

**访问状态**

| 身份 | 表现 |
| --- | --- |
| 游客 | 空态「Sign in to view your accounts / 登录后查看本企业账户」+「Sign in」，登录后回到本页 |
| 登录未绑定角色 | 空态「This page is not available for your current role」+「Back to assets」；入口本身不展示 |
| 已绑定未认证 | 卡片「Verification required / 需要先完成认证」+ 补齐引导按钮（资产方：前往完成实名认证；资金方：去完成机构注册 / 查看审核进度）。不请求、不展示任何账户 |
| 已认证 | 正常页面 |

资格以服务端判定为准，界面隐藏不能代替接口拒绝。

## 2. 总览页

自上而下：页头 →（回流条）→ 账户卡。

**页头**：标题 `.page-title`（按侧展示名）；说明 `.page-desc` 一行：「Your company's bank and crypto accounts. When you accept a quote or record a disbursement, you choose one of the accounts saved here.」

**账户卡** `.card`，顶部为卡片内 Tab `.card-tabs`（`role="tablist"`）：

- 两个 Tab：**Fiat accounts / 法币账户**、**Crypto accounts / 数币账户**，标签后带数量徽标。键盘：Tab 进入当前项，← / → 切换并立即选中，Home / End 到首尾。
- Tab 栏右侧为当前 Tab 的主按钮：「Add fiat account / 新增法币账户」或「Add crypto account / 新增数币账户」。该 Tab 为空时不显示此按钮，由空态承担新增出口。
- 不设默认账户，界面不出现任何“默认”标记或“设为默认”。

**列表** `table.tbl.resp`（≤768px 自动转卡片，列名由 `data-label` 回填），按登记时间倒序，最近登记在前：

| 法币 Tab 列 | 内容与格式 |
| --- | --- |
| Account nickname / 账户备注名 | 粗体，可折行。信息不全时下方显示 `.tag.warn`「Incomplete」+ 小字「Add {缺失字段} to use it in transactions」 |
| Bank / 开户行 | 开户行名称；下方小字「开户行城市, 开户行国家」 |
| Account number / IBAN | 掩码 `•••• 末4位`，等宽 |
| SWIFT / BIC | 等宽；缺失显示「—」 |
| Added / 登记时间 | `yyyy-MM-dd HH:mm`，表头第二行小字标时区 |
| 操作 | 文字按钮 `.actlink`：View · Edit · Delete，`aria-label` 带账户名 |

| 数币 Tab 列 | 内容与格式 |
| --- | --- |
| Account nickname | 同上 |
| Network / 结算收款链 | `.tag.accent`：`ETH` / `TRON` |
| Wallet address / 数币地址 | 缩略 `前6…后4`，等宽 |
| Supported tokens / 适用代币 | `USDT · USDC` |
| Added | 同上 |
| 操作 | View · Edit · Delete |

**列表状态**

| 状态 | 表现 |
| --- | --- |
| 加载中 | 卡片内骨架 4 行 |
| 本类为空 | 法币：「No fiat accounts yet」/「Add a USD bank account to use it in USD transactions.」+「Add fiat account」；数币：「No crypto accounts yet」/「Add a wallet address on ETH or TRON to use it in USDT and USDC transactions.」+「Add crypto account」 |
| 读取失败 | 「We couldn't load your accounts」/「This doesn't mean no accounts are saved. Try again, or come back later.」+「Try again」。**不能显示成空态** |

## 3. 查看账户（右侧抽屉）

宽 `min(720px, 100vw)`。分节，每节 `.dl`，标签列统一 200px（≤600px 标签在上、值在下）：

- **法币**：Account（账户备注名、Currency `USD`）→ Bank details（开户行名称；账号 / IBAN 完整显示，IBAN 每 4 位空格分组，复制按钮复制无空格原值；SWIFT / BIC + 复制；开户行地址「城市, 国家」）→ Account holder address（详址, 城市, 国家）→ Intermediary bank（未填显示「Not provided」）→ Record（Added，修改过再加 Last updated，值后标时区）。
- **数币**：Account（备注名、Network、Supported tokens）→ Wallet address（完整地址等宽可折行 + 复制；Address ownership `.tag.ok`「Confirmed by signature」）→ Record。
- 本人在此看到完整账号与地址；其他位置（业务摘要、控制台）按各业务的脱敏规则。
- 底栏：左「Delete」，右「Close」「Edit（主按钮）」。

## 4. 新增 / 修改法币账户（右侧抽屉）

标题「Add fiat account / 新增法币账户」或「Edit fiat account / 修改法币账户」。≥820px 两列栅格，以下单列。

| 分组 | 字段（en / zh） | 控件与规则 |
| --- | --- | --- |
| Account | Account nickname / 账户备注名 | 必填，整行。与本企业已有账户重名时下方提示「Another account already uses this nickname…」，**不阻断** |
| | Currency / 账户币种 | 只读 `USD` |
| Account holder address / 账户持有人地址 | Country / region | 必选。下拉为 ISO 3166-1 全集，名称按界面语言（`Intl.DisplayNames`）并按名称排序，支持键入首字母跳转；`autocomplete="section-holder country"` |
| | City | 必填；`address-level2` |
| | Street address | 必填，整行；`street-address` |
| Bank details / 开户行信息 | Bank name / 开户行名称 | 必填，整行 |
| | Account number / IBAN | 必填。提示「Enter it exactly as your bank shows it. Spaces are ignored.」保存时去空格、转大写 |
| | SWIFT / BIC | 必填，8 或 11 位字母数字；失焦即去空格转大写 |
| | Bank city / 开户行城市 | 必填 |
| | Bank country / region / 开户行国家 / 地区 | 必选，同上全集下拉 |
| Intermediary bank (optional) / 中转行信息（选填） | 默认折叠为 `<details>`；已有值或有错误时展开 | 三项：Intermediary SWIFT / BIC（8 或 11 位）、Intermediary bank name、Account number at intermediary bank。填任一项则三项必填 |

全表**没有收款人名称**，也不出现“账户已验证”一类结论。

**校验顺序与反馈**（点击「Save」时）：

1. 必填缺失、SWIFT 格式、中转行三项不齐：逐项在字段下显示错误（`.err-msg`，`aria-invalid`），焦点移到第一个错误项；中转行有错误时自动展开。
2. 本企业内同「账号 / IBAN + SWIFT」（去空格、不区分大小写）已存在：抽屉底部 warn 提示「An account with this account number and SWIFT / BIC is already saved.」+「View that account」，不保存。
3. 开户行国家 ≠ SWIFT 第 5–6 位国家码：warn 提示「…does not match the country in the SWIFT / BIC code. If both are correct, save again to continue.」，主按钮变「Save anyway / 确认并保存」，再点即保存。修改 SWIFT 或开户行国家后重新判定。
4. 提交中主按钮显示「Saving…」并禁用全部按钮；失败在抽屉顶部 red 提示「We couldn't save your changes. Nothing was changed; please try again.」，已填内容保留。
5. 成功：关闭抽屉，toast「Fiat account added.」/「Changes saved.」，列表即时更新。不进审核、不发任何通知。

## 5. 新增 / 修改数币账户

**新增**为抽屉内三步，顶部步骤条（当前步 `aria-current="step"`）：

1. **Network**：先显示 warn 告知「Only add an address you can sign with. … Exchange deposit addresses, third-party custodial addresses and contract addresses that can't sign are not supported.」（必须在填地址之前出现）。下方两张单选卡 `ETH`（Ethereum · address starts with 0x）、`TRON`（TRON · address starts with T），**不预选**；未选点「Continue」提示「Select a network first.」。
2. **Address**：只读显示所选链与适用代币；填 Account nickname（必填）与 Wallet address（必填）。格式按所选链校验：ETH `^0x[0-9a-fA-F]{40}$`，TRON `^T[1-9A-HJ-NP-Za-km-z]{33}$`；错误文案只说本链规则。同链同地址已登记则提示「This address is already saved for your company.」+「View that account」。
3. **Verify ownership**：回显三项，说明「Sign with this address to confirm you own it. This signature doesn't change how you sign in, and it doesn't switch your login wallet.」主按钮「Sign with this address」唤起钱包签名；等待中显示「Waiting for signature…」。

签名结果：

| 结果 | 反馈（抽屉内 red 提示，可重试） |
| --- | --- |
| 拒签 / 未完成 | The signature wasn't completed, so the account wasn't saved. You can try again. |
| 签名地址与填写地址不一致 | The signing address doesn't match the address you're adding. Please sign with that address. |
| 钱包不可用 / 不支持该链 | Your wallet is unavailable or doesn't support this network. Reconnect it and try again. |
| 通过 | 关闭抽屉，切到数币 Tab，toast「Crypto account added.」 |

签名不建立会话、不切换登录钱包、不改变角色绑定。任何失败都不产生账户。

**修改**只开放账户备注名；结算收款链与地址只读展示，并说明「The network and address can't be changed. To use a different address, add a new crypto account and sign with it…」。

## 6. 删除（居中弹窗）

标题「Delete this account?」，显示账户名与关键标识（法币：开户行 · `•••• 末4位`；数币：链 · 缩略地址）。warn 说明：

- 「It will no longer be available to select in transactions. Transactions already submitted keep the account details they were submitted with.」
- 删除后该币种 / 该链再无可用账户时追加：「This is your only usable USD account. Until you add another, USD transactions can't be submitted.」或「…only usable account on {链}…」。
- 「This can't be undone.」数币追加「To use this address again, you'll need to add it and sign again.」

按钮「Cancel」「Delete account（主）」；进行中「Deleting…」；失败保留弹窗并 red 提示。成功关闭弹窗、toast「Account deleted.」、焦点回到当前 Tab。

## 7. 通用交互与文案

- 未保存离开：抽屉有改动时，关闭按钮、遮罩、Esc 都先弹「Discard your changes? / 放弃填写内容？」；本模块不保存草稿，离开页面即丢弃。
- 复制：成功 toast「Copied.」；剪贴板不可用时弹出只读输入框供手动复制。
- 时间：列表 `yyyy-MM-dd HH:mm`，时区在表头；详情值后标时区。按用户偏好时区，游客按浏览器时区。
- 中英文案成对写在 `企业账户.js` 的 `L(en, zh)` 中，默认英文。英文为句首大写（sentence case），避免缩写；字段名与 [字段命名与术语对照表](../../../PRD/00-字段命名与术语对照表.md) 的中文名一一对应。
- 所有可点元素有 `:focus-visible`；状态一律文字 + 色点，不只靠颜色。
- 页面不出现规则编号、数据来源说明、“收款账户”类别名或默认账户。

## 8. 数据与接口提示

字段键、必填项、校验与规范化见 `演示数据.js`：`EA.labels`（全部字段的中英名）、`EA.fiatRequired`、`EA.swiftValid`、`EA.addressValid`、`EA.compact`（去空格转大写）、`EA.groupIban`（展示分组）、`EA.duplicateFiat` / `EA.duplicateCrypto`（企业内去重口径）。业务侧（报价、放款、还款、控制台）读取的字段行与脱敏摘要统一由 `EA.rows(account, full)` / `EA.key(account)` 给出；已提交业务保存账户快照，之后的修改与删除不回改。

## 9. 演示件说明

评审件中的账户、银行、地址均为演示数据（页头标签与页脚已声明）。右下「演示工具」默认关闭，仅用于切换身份、页面状态与下次保存响应；模拟钱包对话框里的「Decline / Sign with another address / Wallet unavailable」三个按钮只用于演示签名分支。两者都不属于产品界面，前端不需实现。

## 10. 仍待 PRD 明确（前端实现前需要的取值）

- 各文本字段的最大长度（备注名、地址、银行名、账号等），以及地址类字段是否限定为 SWIFT 报文可用的拉丁字符集。
- 账号 / IBAN 的地区格式表（`Q-EA-02`）；在取得前只做非空校验。
- 账户数量上限（`Q-EA-06`）；本期不设。
