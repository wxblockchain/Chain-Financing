# 资金方登录与账户 · UI 视觉深化

2026-10-16 · WS-372 · existing-system adaptation / console。

基线为 `cly-4.0.0 @ 4a9ddb9` 的既有机构注册、申请状态与审核记录、资金方用户信息及关联弹窗。承接用户“进行 UI 设计”的直接优化要求；业务依据为当前 `PRD/面客端/02-资金方登录与账户体系/`，沿用已确认的单页入驻、邮箱弹窗、图标复制、只读资料和账号菜单入口。

交付前合入至 `633c3bc` 的同期消息、机构审核、登录与资产方资料 UI 更新，保留各自实现和说明；从合并后源码重新导出附件，并重跑资金方关键交互、弹窗与组合入口共 60 项检查通过。这 60 项属于上述核验的重跑，不累加为新的通过数量。

继承部署单元为面客端；shell 为 `portal`，验证与核对使用共享 modal。archetype 为连续表单、纵向只读详情、账户分组。字体、蓝白色板、语义字号、普通 44px 控件、输入三态与左侧必填星号均引用 `_shared/tokens.css`、`base.css` 和[共享组件视觉规范](../../_shared/design-system/共享组件视觉规范.md)；不新增私有 token 或全局字体覆盖。

## 变化与目的

- **机构注册**：全部分区继续同时展开。桌面使用 176px 分区标题列、右侧填写区和 32px 间隔；五区由轻分隔线串联。≤900px 标题回到内容上方，≤760px 机构字段单列。邮箱与机构字段在共同的内容起点对齐，减少只为标题和说明占用的纵向空间。
- **核对提交**：原有三项完成度合并到一个次级表面，提交动作在文末靠右。窄屏完成度按行展示，主按钮整行可达，视觉和键盘顺序一致；取消、保存边界和再审核披露保留。核对弹窗桌面最大宽度为 760px，字段桌面两列、窄屏一列；打开后从顶部摘要开始阅读，避免初始焦点落在材料操作而跳过资料。长字段和材料在原弹窗中滚动，头尾保持可达。
- **邮箱验证**：目标邮箱独立为轻底信息区；验证码输入保持单一六位控件，字号 24px、数字等宽排列，说明、即时状态和重发操作层级清楚。自动核验、错误、取消、重发和钱包再认证仍由原流程处理。
- **审核状态**：保留反馈 → 提交信息 → 机构资料的纵向顺序。驳回区用左侧危险边界，重提仍是首屏主动作；信息卡统一标题分隔。审核记录折叠入口增加轻底、44px 最小高度和可见键盘焦点。审核中复合提示按内容纵向排列，修正英文窄屏按钮裁切。
- **用户信息**：钱包、邮箱与状态采用标签 / 值对齐的事实行。语言与时区在桌面并列，窄屏单列；关键通知说明采用普通辅助文字，降低与可操作内容的竞争。

本轮只调整资金方模块的展示 DOM 与局部 CSS，不修改业务条件、数据、权限、默认值、校验、状态转换或路由。原本的字段级错误、只读状态、文件动作和焦点处理保留。全平台 token 与壳层保持现有定义。

## 运行与核验

打开右下“演示工具”，先选择登录身份，再搜索“机构注册”“申请状态与审核记录”或“用户信息”。资金方页面可从原账号菜单进入；首次入驻可使用“登录未绑定角色”身份并通过既有资金方动作分流。状态样例沿用演示工具的业务场景 / 高级模拟。首次演示验证码为 `123456`，成功重发后递增。
