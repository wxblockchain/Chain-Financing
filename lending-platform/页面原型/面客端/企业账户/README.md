# 企业账户原型（面客 · 资产方与资金方双侧）

业务依据为本模块现行三册：[主 PRD](../../../PRD/v1.0-企业账户/01-企业账户-PRD.md)、[流程图与状态机](../../../PRD/v1.0-企业账户/02-企业账户-流程图与状态机.md)、[消息通知](../../../PRD/v1.0-企业账户/03-企业账户-消息通知.md)。三册只定义信息需求与业务行为，页面布局、组件形态与交互由设计决定。

## 2026-09-24 · 模块首次建页并接管账户目录

基线 `e63a0c8`；existing-system adaptation / console，沿用既有修订入库授权。继承面客端 `portal` 壳层、`_shared/tokens.css` 与 `base.css` 的公共组件，只新增本页的账户行、表单栅格与登记步骤三处局部组合。

- **页面登记 `P-F-EA-01` → `#/account/receiving`**，资产方与资金方同一个入口、同一套字段与维护动作，不进主导航；从账号菜单「企业账户」和资金方账户设置的同名入口进入，此前两处的占位提示已改为真实跳转。
- **账户目录从报价模块移交到本模块**：`演示数据.js` 的 `CF.EA` 是面客端唯一一份收款账户目录与字段/校验定义，报价、放款、还款与控制台通过既有的 `CF.CQ.account*` 访问器读取同一份，不存在第二套并行目录；报价模块本地存储里的旧副本在启动时丢弃。
- **总览**按法币、数币两类分卡呈现，默认账户在前、其余按登记时间；每条给账户备注名、类别标识、关键标识、是否默认与登记时间，行内可查看完整信息、修改、设为／取消默认、删除。两类各自有空态与新增出路；读取失败单独成面并可重试，不表达为尚未登记。
- **法币新增／修改**按账户信息、收款人信息、收款行信息、中转行信息四组排布；账户币种 USD 只读，全表没有收款人名称。逐项定位必填缺失；SWIFT / BIC 非 8 或 11 位字母数字拒绝保存，收款行国家与 SWIFT 国家段不一致只提示、确认后可保存；中转行三项整组选填、填一项即须齐全；本企业内同账号 / IBAN 且同 SWIFT 拒绝并可直接查看已存在那一条。
- **数币新增**固定三步：选链（ETH / TRON，不预选）→ 填地址 → 用被添加的那个地址签名。可登记范围（交易所充值地址、第三方托管地址、无法签名的合约地址都不支持）在填址之前告知。签名由模拟钱包对话框给出结果，覆盖签名通过、拒绝签名、签名地址不一致与钱包不可用四种；未通过不产生账户、不改变当前登录。登记后链与地址不可编辑，只可改备注名，界面说明换地址须新增并重新签名。
- **删除**须显式确认，确认里说明不再出现在任何选用列表、已提交业务记录的账户快照不受影响；删到该币种／该链无可选账户、删除的是默认账户时分别追加告知。删除不可撤销，不提供回收站。
- **默认账户**按类分设：法币一个、每条结算收款链各一个，设新默认自动取消同类原默认，可取消而不删除账户。
- **选用侧回流**：报价「确认本笔收款账户」与放款「本笔还款收款账户」的「前往企业账户」改为真正进入本模块并带回流参数，本页给出返回原办理的入口；返回后报价回到原报价的确认步骤、放款回到原放款登记且已填内容保留。
- **已选账户被改动或删除**不再静默替换、也不拿默认账户顶替：重新进入该办理时说明账户已变更或已删除并要求重新选用；接受报价的提交瞬间再校验一次，不拿旧值提交。已提交业务记录保存的是当时的账户快照，本模块之后的修改与删除不回改。
- **本期零站内信**：新增、修改、删除、设为默认都不发消息、不产生运营待办，界面上也没有可操作的通知开关。

## 使用与维护

打开 `企业账户.html` 默认进入资产广场（与其他面客入口一致），通过账号菜单「企业账户」或直接打开 `#/account/receiving` 进入本页。右下角「演示工具」默认关闭；展开后按「登录状态 → 页面 → 状态」选择，本页状态为默认、尚未取得认证资格、加载中、空数据、加载失败。「更多模拟」里只有下次保存／删除响应与重置演示账户——签名结果在模拟钱包对话框内选择，不在评审面板重复一份。

所有账户、银行、地址与时间都是虚构演示数据。平台不验证银行账户真实性与汇路可达性，页面任何位置都不出现「账户已验证」一类结论。

源文件：`企业账户.html`（骨架）、`企业账户.js`（页面、抽屉与弹窗）、`企业账户.css`（本页局部组合）、`演示数据.js`（账户目录、字段定义与校验）。公共 token / 组件 / 运行时来自 `_shared/`，不手改导出件。

```bash
python3 _shared/export.py --source 面客端/企业账户/企业账户.html --output /tmp/借贷平台-企业账户-prototype.html
```

## 共享改动及影响

- `_shared/portal-entry.js` 增加本模块的样式与两个脚本；`演示数据.js` 在报价模块之前加载，`企业账户.js` 在还款模块之后、登录模块之前加载。共享层变更后旧的离线附件须重新导出。
- `登录与账户体系.js` 新增 `CF.portalEligible()`：当前身份的业务资格由主干一处判定并给出补齐引导，本模块读取它，不自建第二套判定；账号菜单「企业账户」由提示改为进入本页。
- `授信报价.js` 不再保管账户目录与字段定义，改为转发 `CF.EA`；新增 `CF.CQ.resumeSelection()` 回流入口与已选账户变更的重新选用要求。
- `放款与放款确认.js` 新增 `CF.L7.resumeAccounts()` 回流入口；往返企业账户期间保留本笔已填内容，其余离页仍按原有失效规则清理。
- 未改 token、壳层 JS、面客登记表主导航、权限规则或其他模块布局。

## 验证与边界

Chromium 实测（目录内源码）：零脚本异常、零控制台错误。覆盖总览双卡与排序、完整信息抽屉与复制、法币九项必填逐项定位、SWIFT 格式拒绝、国家段不一致提示后可保存、中转行整组校验、本企业内重复拒绝并可查看原条、数币三步顺序与未选链不可填址、按链分别的地址格式提示、同链同址重复拒绝、四种签名结果、保存与删除失败后账户保持原状、设为／取消默认的同类唯一、删除确认的三类告知、五种页面状态、资产方与资金方双侧、未登录与登录未绑定角色的引导、抽屉离页保护与钱包对话框关闭后回到原抽屉；报价与放款两条回流链路往返并保留已填内容；375 / 414 / 768 / 1280 / 1440 / 1920 六档无横向溢出、行操作可达。

未做：真实钱包与两链签名、服务端资格判定与幂等、真实投递与跨标签同步、导出单文件的浏览器复验。以下留在用户裁定前按现状呈现，界面未自行取值：收款账户变更是否强制安全站内信（`Q-EA-04`，本期零事件）、账号 / IBAN 的地区格式与长度表（`Q-EA-02`，只做字符与长度的通用校验，不编造地区规则）、数币是否按代币区分地址（`Q-EA-01`，按链匹配）、账户数量上限（`Q-EA-06`，不设上限）。

本期不做：员工与成员管理、账户变更审核、出账（付款）账户、办理内临时新增或就地编辑账户、收款人名称及以其做归属校验、跨企业唯一性校验、运营端查看或代维护企业账户、代币与地址的链上转账。
