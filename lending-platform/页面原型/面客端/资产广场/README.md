# 资产广场（已上架代币只读域）

面客端模块原型。**本目录是资产广场两个页面的唯一实现。**
`_shared/样板/底座样板.html` 里的资产广场片段是四种 shell 与公共组件的继承母版，字段集只是够用的样例，不是本模块的页面；两者不构成双源。

| 页面 | 编号 | 路由 | 导航 |
| --- | --- | --- | --- |
| 资产广场列表页 | `P-F-AM-01` | `#/assets`（视图状态进 query） | 顶栏 `navAssets`，已在 `registry.portal.js` 登记 |
| 代币详情页 | `P-F-AM-02` | `#/assets/{代币编号}` | 不进导航，由列表行与分享链接带出；登记在 `资产广场.js` 里 |

## 文件

```
资产广场.html    页面骨架 + 仅本模块的排布样式
资产广场.js      页面登记、文案、两个页面、交互
演示数据.js      演示数据（非真实企业、金额、应收账款或链上交易）
```

公共层照 [`../../_shared/README.md`](../../_shared/README.md) 的顺序加载：`tokens.css` → `base.css` → `registry.portal.js` → `shell.js` → 本模块。token、公共组件、整页骨架、状态表面与运行时一概复用，未覆盖任何一项；模块样式只补列宽、详情栅格与几处间距。

## 视图状态与寻址

筛选、排序、搜索关键词与页码全部写在 URL 上，URL 是视图状态的唯一事实源：刷新、分享、浏览器前进后退、从详情页返回都原样恢复。

公共路由 `pageFromHash()` 按登记表做精确匹配，带参数的详情地址与带查询串的列表地址都匹配不上。本模块**不改公共层**，改为把当前地址回写进 `CF.ENTRY`（`syncEntry()`），让公共路由继续按它自己的规则工作。三个在 `CF.boot()` 之前注册的监听器（`hashchange` / `click` / `change` + Enter）只做"把用户动作写回 URL"这一件公共层没有的事，不第二次渲染页面。

## 导出评审件

cd lending-platform/页面原型

  --source 面客端/资产广场/资产广场.html \
  --output ../../../deliverables/借贷平台-资产广场-原型.html

生成件不放回仓库。

## 留给底座维护方（WS-347）的三项

1. **公共路由只支持精确匹配**。加一处前缀 / 查询串匹配能力后，本模块的 `syncEntry()` 就可以删掉；借贷广场详情与我的控制台将来会撞上同一堵墙。
2. **组件规范 §5.1 与页面继承参考 §4 把"两个广场"都写成滚动加载**。资产广场按 PRD `F-AM-05` / `AC-AM-30` 固定每页 20 条、页码进 URL，用 `CF.pagerFoot`；这两处表述需收窄为"借贷广场"。
3. **单端评审件里的部署单元开关**。面客端模块只加载 `registry.portal.js`，演示工具切到管理端时公共层落不到任何页面（地址会变成 `#undefined`）。本模块在那种情况下给了一句说明，但更合适的处置在公共层。
