## 地址下拉修订（2026-10-23）

按用户评论 `2d617ee1`，报价第一步的放款地址、还款收款地址改为下拉选择，替代初版平铺的 radio 选项。复用共享 `data-icon-select`：备注名为主行，网络全名与缩写地址为次行，配网络图标；选项与选中值采用相同内容。网络取 `EA.chainName`，中文显示“以太坊”、英文显示“Ethereum”；地址沿用前六位（含 `0x`）加省略号、后四位，不额外展示全文。首个放款地址仍不预选，自动跟随与手动改选逻辑不变。

该次地址下拉修订仅覆盖报价第一步两处控件，当时未重排授权核对、接受、拒绝与只读详情；后续精简以上节为准。移除不用的 radio 私有样式，选择、键盘与焦点复用共享下拉；完整地址仍用于原业务快照与签名处理，不以缩写值提交。

实测中英文 × 320 / 390 / 768 / 1280 / 1440 / 1920px，共 12 组：空值、选中值、两处菜单的网络与缩写、菜单边界、方向键 / Enter / Escape、选中后回焦、缺放款地址时的错误定位、还款地址默认跟随及手动覆盖、下一步 / 返回保留填写均通过。另验证信息不全选项禁用并被键盘跳过、余额不足 / 查询失败仍阻止签名、正常报价成功后记录保存完整地址。五组源码与导出比对及两种签名表面 125% CSS zoom 检查通过，无脚本异常。以下 72 组布局及初版语义比对保留为先前 UI 交付与入库记录，不冒充本轮重测范围。

## 保留的业务约束

第一步仅校验与保留草稿；第二步“授权并报价”才签名提交，授权上链成功才成立。余额仍是弱提示，余额不足可进入第二步，最终校验仍阻止唤起钱包。还款收款地址默认跟随放款地址，手动改选后不再被覆盖。资产方仍须用本轮融资收款地址签名接受，上链成功才接受并放款成功。没有新增勾选、确认步骤或默认业务选项。

金额精度、汇率、状态、权限、错误、gas、不可撤回和锁定后果均继承；本轮未改动它们的判断和计算。PRD 原先保留的三项业务待确认也未由 UI 另行裁定。

## 打开与复现

评审 HTML 可双击打开，默认英文；右上角可切换中文。右下角“演示工具” → “更多模拟”，展开“选择流程起点 · 重置示例”，选择“3. 提交融资报价”或“4. 签名接受与放款”，再点“办理当前环节”。这些操作会重置演示数据并设置相应身份。

源码入口为同目录 `借贷广场.html#/marketplace`，需保留完整 `页面原型` 目录。重新生成附件：

```sh
python lending-platform/页面原型/_shared/export.py \
  --source lending-platform/页面原型/面客端/04-借贷广场/借贷广场.html \
  --output /tmp/授信报价与接受拒绝-UI设计.html \
  --entry-route /marketplace --market-tone blue --market-type refined
```

实现位于 `授信报价.js`、`借贷广场.css`，相关视觉组合记录于共享工作区规范 §5.6 的本轮已确认组合。其他模块在完整导出件中仍可访问，不能据此计为本轮已完成设计或核验。
