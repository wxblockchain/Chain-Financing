## 1. 这份原型做什么、不做什么

**做（可点）**
页面跳转 · 登录方式 Tab 切换 · 弹窗与抽屉开合 · 表单输入与校验反馈（邮箱格式、验证码必填、协议未勾选拦截 + 抖动、密码规则实时清单）· 语言切换（默认英文，可切中文，即时生效且不丢已填内容）· 每页的 PRD 面板。

**不做（不仿真）**
滑块拖拽轨迹与落点容差校验 · 60 秒倒计时与三维度发码限频状态机 · 登录失败计数器 · 30 分钟锁定倒计时 · 会话失效的真实触发链路。

**关键状态怎么看**：每个页面顶部有一个 **状态切换器**（标着 `Prototype · state` / `原型 · 状态`），直接切到那一种样子。滑块弹窗与钱包面板内部也各有一个。这些状态是**给前端看界面用的**，不代表原型实现了对应逻辑。

## 2. 覆盖范围（未变）

PRD 5.1 的全部页面与 9 个双端组件，一个不少：

- **资产端未登录**：P-A01（三种方式同页切换、协议勾选行全站唯一一处、无任何注册入口）、P-A03/P-A04 忘记密码、P-A05/P-A06 账户恢复、P-A07 锁定态（按 PRD 5.1 实现为登录页内的状态）。
- **资产端已登录**：建号确认 → P-A10 引导页 → LAND 落地页（C-08 / C-09 挂载位）、P-A11 安全、P-A12/13/14 变更流程、P-A15 偏好。

## 3. PRD 面板

每页页头（未登录页在顶部条）有 `PRD` 按钮，打开右侧抽屉，默认收起，紫色系与产品界面明确区分，固定中文——它是给前端开发看的规格。19 个页面各一份，只放这一页用得到的：

| 分组 | 取自 PRD v4 |
| --- | --- |
| ① 字段与校验规则 | 8.1 字段总表 / 8.2 邮箱 / 8.3 地址 / 8.4 密码 |
| ② 关键业务规则 | 该页所属模块章节（7.x / 12.x / 13.x），带 F-xx 与条款号 |
| ③ 状态与异常分支 | 第 9 章异常流程总表 + 第 10 章状态机 |
| ④ 中英双语文案 | 8.5 及 12.1.4 / 12.2.5 / 12.3.5，EN / 中文逐条对照 |
| ⑤ 验收标准 | 第 18 章 AC 编号 + 原文 |

判断标准是：**前端看着这一页的 PRD 面板就能把这一页写出来，不用再打开 PRD 文档**。三条强制安全条款的完整口径（滑块 12 条服务端要求、失败计数与锁定、会话失效的六种原因与例外）都在对应页面的面板里，原型不实现它们，但规格在原型上一眼可查。

## 5. 怎么看

双击 HTML，建议窗口 ≥ 1280px，默认落在资产端登录页。

- **换页**：已登录页面用产品自己的侧边导航；未登录页天然没有侧栏，从顶栏 `Pages / 页面` 抽屉进入。
- **看状态**：页面顶部的状态切换器。
- **看规格**：页头的 `PRD` 按钮。
- **换语言**：右上角或页脚的切换器，英文是默认。

## 7. 前端实现时要特别注意的（原型不体现行为，只体现界面）

1. **滑块必须真拦在所有发码入口之前**（PRD 12.3.1 的 9 个入口无一豁免），且服务端校验票据是唯一防线——原型里点「发送验证码」会弹出 C-01，但通过与否不做校验。
2. **失败计数** 密码与签名共用一个计数器，第 3 次起提示剩余次数，第 5 次锁定 30 分钟；锁定期间验证码登录与忘记密码仍可用——原型只提供这几种界面样子。
3. **会话失效** 改密 / 改邮箱 / 改钱包成功后全部会话失效；**首次绑定（从无到有）不触发失效**，这条例外由服务端按字段是否由空变非空判定。
4. **最后一个可用管理员保护** 前端置灰只是体验优化，服务端校验且与操作原子执行才是防线。
5. **语言** 默认英文、不读 `navigator.language`；双态持久化与冲突处理见 P-A15 的 PRD 面板。

## 8. 假设与边界

1. 落地页是**演示承载页**（PRD 未定义其形态），只为给 C-08 与 C-09 一个挂载位置。
2. 建号确认做成了独立画面再进 P-A10，比 PRD「显著、不能只做 Toast」的要求更强。
3. 管理端侧栏只有账户管理与修改密码两项，本模块的 PRD 功能点只到这里；审计日志查询归审计模块。
4. 管理端操作列用短动词（Disable / Delete / Unlock / Regenerate），完整操作名挂在 tooltip 与 PRD 面板里，避免 1280px 下操作列被文案撑爆。
5. 视觉口径来自竞品文件；目标仓库 `docs/design-system/` 下的既有规范本轮仍未读取（按委派要求）。若要与之对齐，需单独一轮适配。
6. 本轮按新口径不再维护自动化验证套件，改为人工逐页、逐状态过了一遍（19 个页面 × 全部状态 + 三个弹窗的全部状态，1440px 下无横向溢出、无控制台报错）。

## 9. 源码组织

交付的单文件是**产物**，不是维护形态。源码分层在工作区 `src/` 下：`10-tokens.css`（竞品 token）、`20-components.css`（组件层）、`30-body.html`（外壳）、`40-i18n.js`（中英文案表）、`45-prd.js`（每页 PRD 摘录）、`50-app.js`（路由与交互）；`build.sh` 机械内联成单文件。后续迭代改 `src/` 后重跑 `build.sh`，不要直接手改产物。
