## 1. 本轮四件事，逐条对照

### ① 配色整体换成竞品的浅色体系

全站单一浅色体系，**没有任何深色底，页面底部也不是深色**。token 直接取竞品口径（`src/10-tokens.css`）：

| token | 值 | token | 值 |
| --- | --- | --- | --- |
| `--bg` 页面底 | `#F6F7FA` | `--accent` 主色 | `#2557E8`（hover `#1E46C4`） |
| `--card` 卡片/浮层 | `#FFFFFF` | `--accent-soft` | `rgba(37,87,232,.08)` |
| `--card-hover` | `#F3F5F9` | `--ok` / `--warn` / `--danger` | `#087443` / `#B54708` / `#D92D20` |
| `--border` / `--border-strong` | `#E6E9F0` / `#D5DAE4` | `--radius` | `12px` |
| `--text` / `--muted` / `--faint` | `#101828` / `#5A6474` / `#8B94A6` | `--shadow` | `0 1px 2px rgba(16,24,40,.05), 0 1px 3px rgba(16,24,40,.06)` |

资产端与管理端**在同一套浅色体系内**，差异只体现在密度与圆角：资产端控件高 42px、字段间距 16px、卡片内边距 20px；管理端控件高 36px、字段间距 13px、内边距 16px。不再是"一端浅一端深"。

验证脚本里加了一条硬检查：19 个页面在 3 档宽度下逐个采样 `body` 背景亮度，任何一处均值低于 140 即判失败。

### ② 输出形态改成竞品那样的完整产品控制台

外层评审脚手架（`pc-rail` 中文导航 / `pc-crumb` 面包屑 / `pc-canvas` 画布 / 右下角 `pc-demo` 浮窗）**已整体删除**，CSS 里连对应的类名都不再存在。现在的结构与竞品一致：

- **已登录**：`.app` = `sidebar`（238px，产品自己的导航）+ `topbar`（面包屑 + 语言切换 + 入口）+ `content`（最大 1500px）。侧边导航文案**跟随语言切换**，不再固定中文。页面切换就是产品内部的路由切换，侧栏右侧标注对应的 PRD 页面编号。
- **未登录 / 管理端首登重置**：这几页天然没有侧边导航，按竞品的视觉语言做居中卡片式布局（同一套浅底、白卡片、蓝主色、字号与圆角），与控制台在同一个设计系统里。
- 侧栏底部是产品自己的账户区：当前登录标识、账户状态（`Incomplete` / `Active`）、退出登录。

**演示分支能力保留，但收进了产品内部**：顶栏的「Prototype」按钮（未登录页在页脚同位置）打开一个右侧抽屉，里面是端切换、页面直达、以及全部演示开关（滑块必败 / 滑块加载失败 / IP 层强制滑块 / 发码限频三维度 / 拒签 / 验签失败 / 未检测到钱包 / 网络不支持 / SDK 失败 / 账户停用 / 强制重新同意 / 六种会话失效原因 / 只剩一个可用管理员 / 服务端并发拒绝 / 区块浏览器降级 / 会话即将过期）。抽屉顶部写明"它不是产品功能，正式实现时整块移除"。P-M06 的列表状态开关同样留在页面工具栏里，并挂了一枚 `Prototype · list state` 标记。

### ③ 每个页面新增 PRD 面板

每页页头（未登录页在顶部条）有一个 `PRD` 按钮，打开右侧可展开/收起的面板，默认收起。面板用紫色系（`#5925DC` / `#F4F3FF`）与产品界面明确区分，固定中文——它是给前端开发看的规格，不是产品文案。

内容按五类组织，**只放这一页用得到的**：

| 分组 | 取自 PRD v4 | 说明 |
| --- | --- | --- |
| ① 字段与校验规则 | 8.1 字段总表 / 8.2 邮箱 / 8.3 地址 / 8.4 密码 | 字段名、类型、必填性、完整校验规则 |
| ② 关键业务规则 | 该页所属模块章节（7.x / 12.x / 13.x） | 带 F-xx / 条款号，可回溯 |
| ③ 状态与异常分支 | 第 9 章异常流程总表 + 第 10 章状态机 | 场景 → 系统行为 |
| ④ 中英双语文案 | 8.5 及 12.1.4 / 12.2.5 / 12.3.5 | EN / 中文逐条对照，含占位符 |
| ⑤ 验收标准 | 第 18 章 | AC 编号 + 原文 |

19 个页面各有一份，条目数在页头显示。举例：P-A01 有 5 字段 / 10 条规则 / 14 个异常分支 / 12 组文案 / 15 条 AC；P-M06 有 3 字段 / 7 条规则 / 7 个状态 / 7 组文案 / 14 条 AC。**没有做全局 PRD 阅读器**，也没有把整份 PRD 塞进面板——验证脚本对面板文本长度设了上限，超出即判为"疑似全量堆砌"。

### ④ 删除营销订阅勾选

登录页协议区现在只有用户协议一项。中英文案、`agree_marketing` 状态字段、相关校验一并删除。验证脚本在中英两种语言下分别取产品界面（`#focus` + `#app`）的可见文本，出现 `marketing` / `营销` / `product updates` 即判失败；并断言登录页的复选框数量恰好为 1。（PRD 面板里仍保留 N-04「本期删除」这条规则说明，那是规格记录，不是产品界面。）

## 2. 沿用上一轮、本轮未改动的部分

覆盖范围、三条强制安全条款、语言口径都按上一轮委派执行，此处只列结论：

- **页面覆盖**：资产端未登录 6（P-A01、P-A03/04、P-A05/06、P-A07 锁定态）+ 建号确认 + 资产端已登录 6（P-A10、P-A11、P-A12/13/14、P-A15）+ 落地页（演示承载）+ 管理端 6（P-M01～P-M06）+ 9 个双端组件（C-01～C-09，均在真实流程内被调用）。**没有注册页、没有任何注册入口或 `Sign up` 类术语**。
- **12.3 滑块与限频**：所有发码按钮走同一函数，点击先弹 C-01 再发码，通过后 60 秒倒计时；滑块为真拖拽（背景图运行时 canvas 生成），失败抖动+换图，连续 3 次升级提示、5 次进 60 秒冷却，支持键盘方向键与 Enter；限频三维度文案齐备；12.2.2 的 IP 层风控档也做了（命中后登录提交先过滑块）。
- **12.2 登录锁定**：密码与签名共用一个计数器，第 3、4 次提示剩余次数，第 5 次锁定 30 分钟并实时倒计时；锁定态下密码与钱包两个 Tab 禁用并标 `Locked`，验证码登录与忘记密码仍可用。
- **12.1 会话失效**：改密/改邮箱/改钱包成功后回登录页 + 成功文案 +「所有设备均已退出登录」；被踢出场景按六种原因分文案；12.1.1 的例外做对了——**首次绑定（从无到有）不触发会话失效**。
- **首次登录即建号**：独立的「Welcome! Your account has been created.」确认画面（带演示账户 ID），再进 P-A10，引导页顶部继续保留建号确认，主引导按建号路径分流，设置密码标 `Optional`，`Later` 与主操作等权重。
- **国际化**：默认英文、不读浏览器语言，切换即时生效且不刷新、不丢已填内容；本轮起**侧边导航与面包屑也跟随语言**；时间一律带时区标注。

## 4. 验证结果（实际跑过）

Playwright + Chromium 无头，两套脚本（`verify.py` / `verify-flows.py`，留在工作区，不作为交付附件）：

- **1280 / 1440 / 1920 三档 × 19 个页面**：无横向溢出、表格不裁剪、操作列完整可达、控制台零 error / 零 pageerror；每页 `body` 背景亮度采样确认无深色底；每页的 PRD 面板都能打开且有内容。
- **形态断言**：登录成功后出现产品侧边导航（`.app .sidebar`）；切换语言后侧边导航文案确实变化；登录页复选框数量为 1；中英两种语言下产品界面均无营销订阅文案。
- **流程断言**：滑块通过后按钮转 60s 倒计时且弹窗自动关闭；未勾协议不可提交；陌生邮箱登录出现建号确认；C-08 与 C-09 可触发；密码连续失败第 3 次提示剩余次数、第 5 次进锁定且密码/钱包 Tab 锁死而验证码 Tab 可用；管理端登录 → 账户管理 → 创建账号 → 初始密码仅展示一次。
- **分支断言**：限频超限、滑块连续失败 5 次冷却、滑块资源加载失败、单码 5 次作废、账户停用、强制重新同意（未滚到底点同意确实不放行）、忘记密码全流程、账户恢复对未绑定地址报错、改邮箱全流程 + 会话失效后退出控制台、最后一个管理员的前端拦截与服务端拒绝两条路径。

本轮修掉一个新发现的缺陷：滑块连续失败 5 次刚进入冷却的那一秒，消息区会短暂空白（重渲染把倒计时文案覆盖掉），已改为冷却期内固定渲染倒计时。

## 6. 假设与边界

1. **落地页是演示承载页**（PRD 未定义其形态），只为给 C-08 常驻提示条与 C-09 认证前置弹层一个挂载位置，侧栏中标为 `LAND`。
2. **建号确认做成了独立画面**再进 P-A10，比 PRD「显著、不能只做 Toast」的要求更强；如需退回到只在引导页顶部展示，改动很小。
3. **P-A07 锁定态实现为登录页内的状态**，PRD 5.1 明确允许（"可作为登录页内的状态态"）。
4. **管理端侧栏只有账户管理与修改密码两项**，因为本模块的 PRD 功能点只到这里；审计日志查询归审计模块，未画。
5. **管理端操作列用短动词**（Disable / Delete / Unlock / Regenerate），完整操作名（如「重新生成初始密码」）挂在 `title` 上并写在 PRD 面板里，避免操作列在 1280px 下被文案撑爆。
6. **视觉口径来自竞品文件，不是目标项目仓库**。目标仓库的 design 模块与现有 UI 本轮仍未读取（按委派要求）。若后续要与 `docs/design-system/` 下的既有规范对齐，需要单独一轮适配。

## 7. 源码组织

交付的单文件是**产物**，不是维护形态。源码分层在工作区 `src/` 下：`10-tokens.css`（竞品 token）、`20-components.css`（组件层）、`30-body.html`（外壳）、`40-i18n.js`（中英文案表）、`45-prd.js`（每页 PRD 摘录）、`50-app.js`（路由与交互）；`build.sh` 把它们机械内联成单文件。后续迭代改 `src/` 后重跑 `build.sh`，不要直接手改产物，否则快照与源码会悄悄分叉。
