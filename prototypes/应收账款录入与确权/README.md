## 1. Stage 2 设计方向与继承关系

**端/角色: 资产端企业用户（单据卖方/买方）+ 资产管理端人员 · 模块: 应收账款录入与确权 · 功能点: 18 个 · 页面: P-A20～P-A24、P-M40～P-M41 · 状态: 五态 + 9 类必达界面状态 · 视觉口径取自: `prototypes/_shared/`、`docs/design-system/`、`prototypes/账户与登录/`、`prototypes/消息通知/`、`prototypes/协议管理/`。**

| 页面 | 继承端别 / shell | archetype | 本页增量 |

| P-A20 我的应收账款 | asset / app | 资产端列表 | 两个入口之一、单一 USD 已确权总额、查看/编辑最小行操作 |

复用方案：

- shell / navigation：`_shared/shell.js` + `registry.js`；资产端在「用户中心」上方新增「应收账款」一级分组，常驻展开「我的应收账款 / 应收账款确权」两个二级入口。
- token / typography：只引用 `_shared/tokens.css`；模块样式无 `:root`、无字面色值、无平行 token。
- components：复用 `base.css` 的按钮、表单、表格、筛选、分页、Badge、Note、Modal、Toast、上传、Timeline、骨架屏、状态条。
- runtime：复用语言、路由、URL、Toast、Modal 宿主、面包屑与账号菜单；模块脚本只处理本业务状态。
- 既有页面：账户与登录、消息通知、协议管理全部保留，通过同一 registry 双向跨文件跳转。
- 公共层增量：`registry.js` 新增本模块页面、分组导航、归属和入口登记；`shell.js` 增加通用嵌套导航渲染并补充导航文案；`base.css` 增加对应的一级/二级导航样式。既有平级菜单和跨文件跳转行为保持不变，`tokens.css` 保持不变。

### 累计反馈落点

1. P-A21 的「保存草稿 / 提交」已从页头移到右侧「买卖双方」卡片下方。
2. P-A22 / P-A24 / P-M41 的操作时间线位于左侧主内容，并按最新要求排在贸易背景材料之后；右侧独立展示「买卖双方」。

5. 顶栏「页面」快捷抽屉覆盖 7 个 PAGE；每页 PRD 面板已扩展为页面级开发规格。
6. 三个列表统计区均只展示「已确权总金额」，统一折算为 USD；其余统计位置留空，列表金额仍展示原金额和原币种。

8. 每个 PAGE 的 PRD 面板均覆盖角色与前置条件、字段来源、展示交互、按钮权限、状态流转、前后端校验、接口输入输出、错误处理、异常/空态、关键文案和验收标准。独立 PRD 文件未修改。

## 2. 运行方式

### 仓库原生版

保留整个 `prototypes/` 目录结构，双击本目录 HTML。它以普通 `<link>` / `<script src>` 引用 `../_shared/`，不使用 CDN、远程字体、远程图片、ES module、`fetch` 或网络请求。

### Issue 附件版

交付时由仓库原生版**机械内联** `_shared/tokens.css`、`base.css`、`registry.js`、`shell.js` 生成同名快照。附件可单独双击打开；仓库内仍维护共享源文件，不手改内联快照。

默认进入 P-A20。左侧「应收账款」一级菜单下切换「我的应收账款 / 应收账款确权」；顶栏「页面」可在 7 个 PAGE 间快捷切换，`页面规格` 打开当前页开发级 PRD 面板；页面演示条可切至资产管理端；「原型 · 状态」用于直接查看必达状态。

## 5. 关键交互怎么验

1. **入口与快捷切换**：资产端「应收账款」分组含两个互斥入口；顶栏「页面」抽屉可直达 P-A20～P-A24 / P-M40～P-M41，`页面规格` 展示当前页开发级内容。
2. **合同号多值**：P-A21 输入后回车或「添加」；逗号/中文逗号/换行可批量拆分；规范化后重复值即时拒绝；第 11 个拒绝。
3. **重复硬阻断**：点演示条「填入重复合同号」后提交。C-41 只显示固定文案与被拦合同号，不显示企业、记录编号、金额、状态、时间或跳转。
4. **草稿**：空白字段可保存草稿；提交时才做全部必填与业务校验。
5. **驳回重提**：P-A20 仅点「查看」进入已驳回详情，再从右侧操作栏进入修改重提。保留原因全文；重提不触发重复校验；提交次数递增。
6. **整笔确权**：P-A23 仅点「查看」进入待确权详情，再从「买卖双方」下方操作栏点「确权通过」。C-43 只确认整笔金额，页面没有部分金额输入；确认后终态。
7. **驳回**：P-A24 点「驳回」。空字符串或纯空格会就地报错，无原因分类；成功后进入已驳回。
8. **币种与统计**：列表行保留原金额/原币种；统计区只显示已确权总金额并统一为 USD，其他统计位留空；未选单一原币种时金额排序禁用并解释；金额格式始终数值在前、代码在后。
9. **材料**：JPG/PNG/PDF 的预览与下载可点击；ZIP 预览按钮禁用并解释，下载保留；表单状态「材料拒绝」展示超 10M 的具体文件。
10. **只读管理端**：演示条切换管理端；列表无草稿，详情仅预览/下载，无新增、编辑、提交、确权、驳回、删除入口。
11. **时区**：时间带账户时区；到期、剩余时间与失效位置同屏写明「以 UTC+8 判定」。
12. **滚动操作区**：在 P-A21 / P-A22 / P-A24 滚动长表单或详情，右侧操作卡保持在可视区；窗口进入单栏时取消 sticky，避免遮挡内容。
13. **页面级 PRD**：逐页打开「页面规格」，确认 12 类必备规格及关键中英文案均可读；P-A20、P-A23、P-M40 的统计契约明确由后端返回 `confirmed_total_usd`，前端不自行换汇。

模块 `<style>` 只引用这些 token，不覆盖公共类。

## 10. 假设、差异与限制

1. 合同号命中信息面以本 issue 已冻结口径为准：**所有命中统一只显示被拦合同号**，不显示状态、编号、企业、金额或跳转；本轮仅在原型内落实，不修改独立 PRD 文件。
2. 发票号保留为非必填且不参与重复判定；合同号上限 10；已失效继续参与拦截；不设例外通道。
3. 消息中心与邮件内容不在本模块重复实现；界面仅表现事件触发结果和既有全局入口。
4. 原型不读取真实文件、不访问接口、不运行失效批处理；交互用本地状态模拟。
5. 品牌和合规占位符暂无实际值，原型不擅自填入。
6. 本轮页面统计接口只约定后端返回权威字段 `confirmed_total_usd`；原型不展示或计算汇率，演示记录内的 USD 折算值仅用于界面评审。
7. 本轮反馈只扩展**原型页面内 PRD 面板**；独立 PRD 文件保持原样，上一轮针对 PRD 文件的委派不作为输入。
8. 目标分支已确认为 `cly-V1.0.0`，按要求直接 push，不创建 PR。
