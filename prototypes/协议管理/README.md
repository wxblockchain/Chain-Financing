## 3. 功能点与规则可交互性

11 个功能点（F-40～F-50），逐条对应到界面上可点得动的东西。

| 编号 | 功能点 | 在原型里怎么验 |
| --- | --- | --- |
| F-40 | 菜单与列表 | 左侧一级菜单「协议管理」→ P-M10。**标题区没有主操作按钮，全页无任何"新建协议"入口**（AC-AG-04） |
| F-41 | 资产端使用环节展示 | 列表「资产端使用环节」列为 Tag 组，超 3 个折叠 `+N`，点 `+N` 展开、再点收起；详情基本信息区展示完整清单，全只读（AC-AG-06） |
| F-42 | 检索与筛选 | 关键词（匹配中英名称与 `agreement_key`）+ 类型/使用环节/状态三个多选下拉 + 更新时间范围 + 查询/重置；条件间「与」、多选值间「或」。**筛选与分页写进 URL**，浏览器前进后退可还原（AC-AG-09） |
| F-43 | 文件上传 | P-M13 上传区，helper 原样展示**该协议**的格式与大小（如用户协议 PDF / 10 MB、隐私政策 PDF·HTML / 5 MB、提现模版 DOCX·PDF / 20 MB），互不影响（AC-AG-25） |
| F-44 | 草稿与覆盖更新 | 已有草稿时按钮变「继续编辑草稿」，不生成第二个草稿（AC-AG-29）；替换文件写一条含旧新文件名的操作记录（AC-AG-55） |
| F-45 | 发布与生效时间 | 立即生效 / 定时生效两条路径都跑得通；发布后新版本转已生效或待生效，原生效版本自动归档 |
| F-46 | 历史版本查看 | 版本历史表 9 列齐全；任一版本可开抽屉看 `version_id`、`content_hash`、生效/归档时间、发布人、变更说明、来源版本 |
| F-47 | 版本回溯 | 对已生效/已归档版本点「以此版本为基础新建版本」→ 复制文件、生成**版本号更大的新草稿**、变更说明预填「回溯至 v{n} 的内容」、来源版本列显示「基于 v{n}」并可跳转（AC-AG-48/49） |

| F-50 | 对资产端输出口径 | 属接口契约，界面上只体现其来源字段：`version_id`、`content_hash`、生效时间、`require_reconsent` 都在版本详情抽屉里可见可复制 |

### 版本状态机是真的在跑

不是四张静态图。原型内维护了一份可变的版本数据，下列迁移都会真的改状态、真的写操作记录，在版本历史与操作记录里能立刻看到结果：

```
draft ──发布·立即生效──→ active   （原 active → archived，归档记为「系统」）
draft ──发布·定时生效──→ scheduled
scheduled ──撤销待生效──→ draft    （保留文件）
scheduled ──被新发布替换──→ draft  （E-06，两条动作各记一条记录）
scheduled ──到点──→ active         （「模拟到点生效」按钮，操作人记为「系统」）
active ──新版本生效──→ archived    （系统自动）
active / archived ──以此版本为基础新建──→ 新的 draft（版本号更大，记 source）
draft ──丢弃──→ 消失
```

**E-06「撤销并发布」分支怎么看**：用户协议已有待生效 v4 → 新建 v5 → 发布 → C-10 里出现 inline alert 写明 v4 及其生效时间，**主按钮文案变为「撤销并发布」** → 确认后 v4 退回草稿并保留文件、v5 生效，操作记录里能看到"退回"与"发布"两条（AC-AG-39/40）。

**C-11 草稿被覆盖的二次确认**：某协议同时存在草稿 v2 与待生效 v3 时，撤销 v3 会弹二次确认，说明原草稿将被退回的版本覆盖（E-06 后半段）。

### 异常分支

E-01 格式不符 / E-02 超出大小 / E-03 文件头校验失败 / E-04 上传失败可重试 —— 版本编辑页「原型控制」一行逐条可触发，提示里带的是**该协议的实际格式与上限值**，不是全局常量。
E-05 未传文件、E-07 变更说明为空、E-08 生效时间距当前不足 5 分钟 —— 直接点「发布」即被阻断并聚焦到对应控件。
E-09 并发编辑、E-10 定时生效失败（详情页 inline alert，且当前生效版本保持不变）、E-13 已下线协议（顶部 alert + 隐藏「新建版本」，历史与记录仍可查）—— 页面状态切换器里各占一档或由数据直接呈现。

## 4. 硬约束的落实情况（逐条可查）

| 约束 | 落实 |
| --- | --- |
| 不出现新增协议 / 新增·编辑·停用协议类型的入口 | 全文件搜不到任何"新建协议""编辑协议""停用"按钮。列表标题区无主操作按钮，两种空态里也没有新建入口 |
| 不出现富文本编辑器 | 版本编辑页只有「协议文件」上传区 + 「版本信息」区两张卡片，卡片头上写明"只允许上传文件，本期不提供富文本编辑器" |
| 协议内容不做中英切换 | 版本对象上没有 locale 字段、没有语言 tab、没有中英两份内容。语言切换器只切**管理端界面文案**，与 302 一致 |
| 版本号只读 | 版本号是只读展示件（非输入框），旁注"系统自动递增，只读" |
| 文件格式与大小不写成全局固定值 | 每个协议各带自己的 `allowed_file_types` / `max_file_size`，上传区 helper 与详情基本信息区都按"读取该协议定义"的形态展示；演示数据里 4 个协议的取值各不相同，用来证明它按协议取值 |

## 5. 怎么看

双击 HTML，建议窗口 ≥ 1280px，默认落在协议列表。

- **换页**：左侧菜单 → 协议管理；点「账户设置」会直接跳到 `../账户与登录/` 那份原型的对应页面（两份文件共用同一套菜单）；列表行或「查看」→ 详情；详情右上角「新建版本 / 继续编辑草稿」→ 版本编辑页；面包屑可逐级返回。
- **看状态**：每页顶部的状态切换器（标着 `原型 · 状态`）。版本编辑页的文件区另有一行「原型控制」，逐条触发 E-01～E-04。
- **看状态机**：直接操作即可（发布、撤销、丢弃、回溯）。定时生效用演示数据条上的「模拟到点生效」把时钟快进到生效时间。**改乱了点「重置演示数据」即可复原。**
- **看规格**：页头的 `PRD` 按钮（紫色面板，给前端看的，不属于产品界面）。
- **换语言**：右上角语言下拉，英文是默认。
- **URL**：筛选、分页、排序、当前页面都写在地址栏 hash 里，刷新和前进后退不丢。

## 6. 验证做了什么

用 Playwright（Chromium）在 **1280 / 1440 / 1920** 三档宽度下逐页逐状态跑了一遍，结果：

- 三档宽度、中英两种语言下**均无水平溢出**（文档级与表格卡片内均为 0px），侧栏不重叠，两张 9 列表格的**操作列始终完整可见**（列宽定死 + 折行，不靠横向滚动；880px 以下才启用卡片内滚动，届时操作列吸附在右侧）。
- 无控制台报错、无 pageerror。
- 断言覆盖：E-06 主按钮文案切换、E-07/E-08 发布阻断、草稿覆盖二次确认、离开未保存确认、E-13 已下线协议无「新建版本」、回溯变更说明预填、定时发布→到点生效→自动归档、URL 前进后退还原筛选、中文菜单生效、`:focus-visible` 为 2px 实线。

未做：真实文件读取与上传（原型不读盘）、跨浏览器矩阵、自动化无障碍审计（键盘可达与 focus 环是人工 + 抽样断言）。

## 8. 假设与边界

1. **协议清单是占位的**。真实清单由研发按 PRD 17.2 逐个补齐后才会出现在列表里；协议定义未落地前，本模块列表为空（对应"空数据"状态）。
2. **原型不读真实文件**。点「上传文件 / 替换文件」按"已选中一个合规文件"呈现；格式、大小、文件头校验按 PRD 的口径**在界面上演示**，服务端双重校验由前端与后端按 PRD 12.2 实现。
3. **时钟固定在 2026-09-08 09:30 (UTC+8)**，保证任何时候打开看到的时间线一致；"5 分钟"校验以此为基准。定时生效不做真实倒计时，用「模拟到点生效」演示切换结果。
4. **变更说明在演示数据里给了中英两份**，只是为了两种语言下都读得通。它是管理员填写的业务数据，不是界面文案，实际只有一份——版本编辑页里填什么就存什么。
5. **分页器按 6 条演示数据渲染**，因此是"第 1 / 1 页"。每页 20/50/100 的选择器、上下页禁用态都在，数据量上来后即为多页形态。
6. **无权限态**指未登录或首登未改密被服务端拒绝（PRD 11.1），不是角色差异——本期管理端只有一种角色。
7. **对资产端的输出口径（第 9 章）是接口契约**，没有界面，原型只呈现其来源字段。

## 9. 本期不做（PRD 2.3，界面上确实没有）

同意记录的查询筛选导出 · 强制重新同意的触发规则（`require_reconsent` 只存储不产生前台行为，勾选框旁已注明）· 资产端前台协议展示与勾选（归 WS-302）· 站内信与邮件模板 · 协议内容多语种 · 在线富文本编辑 · 协议类型字典页与新建协议入口。

## 11. 源码组织

本文件不再是自包含单文件，公共层已抽出到 `prototypes/_shared/`：
