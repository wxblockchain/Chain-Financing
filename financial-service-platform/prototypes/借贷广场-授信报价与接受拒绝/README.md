> **本模块零链上动作。** 授信核定、报价、接受、拒绝都只改平台侧的额度与状态，**不产生链上操作、不消耗 gas、不唤起签名 SDK**——三页都常驻明示这一点（6.1.2 费用提示）。因此上游的「五类链上失败各有独立页面态」这条红线在本模块**没有触发条件**，它的落点仍在 WS-324 的质押与提取。本模块对应的"失败必须可区分"由上表的**提交终检五结局**与**接受流程异常**承担，同样不允许只写"操作失败"。

## 2. 四个招牌件

它们是本模块与 WS-324 结构上的分野，也是这三页要站的立场。

| 件 | 服务的口径 | 为什么是这个形状 |
| --- | --- | --- |
| **授信尺** `.cq-crbar` | `AC-CR-03` | 与 WS-324 的额度尺（`.ls-meter`，**项目维度**）成对：那把尺量"这个池子还撑不撑得住"，这把尺量"这家机构还借不借得出"。段序固定为`授信占用额 → 在途报价金额 → 本次报价 → 可用授信`，**与不等式左端同序**；超出部分单列为斜纹 `over` 段，差额在尺上一眼可见。旁边的 `.cq-eq` 把不等式摆成可读算式，各项与尺上的段同色，结论在行尾。 |
| **两道闸门牌** `.cq-gates` | `AC-FIN-07` / `AC-CR-22` / `D-CR-21` | 两张判据牌**并置**——并置本身就是那条口径：两道独立、须同时通过。每张给`判据 · 当前取值 · 结论 · 谁来解决`。这是消灭"不满足条件"这句话的装置：覆盖不足是**资产方**的事，授信不足是**机构自己**的事，混成一句会让双方各自等对方动作。 |
| **锁定倒计时** `.cq-cd` / `.ls-lock` | `D-LS-13` / `AC-LS-85` | 四件事一个不少：被谁锁定 / 从什么时候开始 / 已锁定多久 / **还剩多久**，外加两条出路。条上两段（已锁定 + 剩余）**相加恒为 168 小时**，这条恒等式在屏幕上可以直接核——和 WS-324 的三数等式同一个手法：把口径做成可验算的读数，而不是一句话。不足 24 小时切分钟精度 + warn 档；业务离开 `S-FD-1` 后整块不渲染（`D-CR-28`）。 |
| **手续费差额条** `.cq-fee` | `D-FIN-103` / `D-FIN-104` | 三格对照：`融资金额 − 跨境手续费 → 实收金额`，**中间与右边两格故意没有数字**，因为平台不预知、不代收、不垫付、不展示预估。难点正是"把一个未知量呈现得可信"：用与金额同一档的字号排版一句"平台不预估金额"，而不是留白或写 0。不折叠、不做小字注脚，位置在「确认接受」之前。 |

## 5. v1.1 做了什么

### 5.1 授信前置确认：①②③ 三支都问（`D-CR-46` ～ `D-CR-50`）

**问题**：机构点的是「报价」，v1.0 会在授信不足时**直接**把他推到一张要他掏额度的表单前面 —— 一个报价动作毫无预告地变成了一个改变本机构敞口的写操作。这是 v1.0 交付说明里自己提到的那个口子。

**现在**：先问一句，确认之后才出表单。

> 派发时这一条只点名了分支②，并说分支①③ 等 PRD V6.0 的结论。**V6.0 在本轮进行中入库（`2434cd0`），`D-CR-47` 的结论是"一并要问"**，理由不是"保持一致"而是：① 是**建立一段全新的授信关系**、③ 是**把敞口窗口再开一年**，都比②「在已有关系上加码」更重。所以本轮三支一起做完，不再留一支等下一轮。

| 分支 | 问句 | 摆什么数 |
| --- | --- | --- |
| ① 无额度 | 「您尚未对 {资产方} 核定授信额度，是否现在核定？」 | 本次报价金额 + 「本机构对该资产方尚无授信记录」 |
| ② 额度不足 | 「当前授信额度不足，是否提额？」 | **三个数排成算式**：`本次报价 600,000.00 − 当前可用授信 240,000.00 ＝ 差额 360,000.00` |
| ③ 已到期 | 「您对 {资产方} 的授信额度已于 {原到期日} 到期，是否重新核定？」 | 本次报价金额 + 上一版额度 + 原到期日 |
| ④ 额度充足 | **不出现确认**（`D-CR-50`），直接进报价表单 | — |

| 项 | 落法 |
| --- | --- |
| 三个数为什么排成算式 | 差额不是一个孤立数字，它是前两个数减出来的。摆成算式，机构自己就能验，不必信平台——和本模块其它几处（授信尺、168 小时恒等式）同一个手法 |
| 两条出路 | 各说清后果。**确认** → 进对应表单（填什么、提交即生效、之后自动回报价并重跑两道校验、额度与报价解耦）；**取消**（`D-CR-49`）→ 回详情页操作区，「融资报价」按钮保持原样随时可再点，**什么都不留**：不生成编号、不产生授信记录与占用、不锁定需求，**也不记录"曾经取消过"** |
| 形态（`D-CR-48`） | 确认 → 授信表单 → 回报价表单是**同一个承载单元里的三个步骤**。就地替换表单的位置呈现，不新开页、**不叠第二层** —— 确认阶段 `.mask` 元素数 = 0（脚本断言）。`D-LS-30` 落地后这三步原样搬进那一个弹窗即可，**不会变成弹窗套弹窗** |
| 确认阶段 | **零录入控件**（脚本断言 `#content` 内 input / textarea 数 = 0）—— 这一步只做决定，不做录入 |
| 确认后 | 分支②的表单里保留一条**紧凑复述**（三个数 + 仍需补足），`AC-CR-10`「不得只显示一个空表单」仍成立；主视觉让给表单本身，不把三个数摆两遍大字 |

## 7. 假设、限制与需要上游处理的事

1. **公共壳层的 `onInput` 钩子没有实装。** `shell.js` 头部注释声明了模块接口 `onInput(n,k)`，但全文只挂了 `click`，没有 `input` / `change` 监听——`data-act` 挂在输入框上时，输入不会触发任何回调。本模块三页都是表单页，因此在 `cq-module.js` 末尾自挂了一层（只认本模块的 `data-act="cq.f"`，`input` 只回写状态不重绘、`change` 回写并重绘），**没有改 `_shared`**。**这是一条对公共层的修订请求**：要么在 `shell.js` 里实装 `onInput`，要么把该行注释删掉。WS-324 的项目名称 / 金额输入框也受同一问题影响。
2. **`P-LS-06` 的接受动作在原型内会真的改演示数据**（业务状态、项目状态），刷新页面即复位。授信核定同理。
3. **`FP-20260416-0007` 在两份原型里的表现不一致，这是已知且已登记的差异**：本模块按 PRD V7.0 的 `AC-FIN-26` 消费——`480,000 − 500,000 = −20,000 < 200,000`，该需求**已自动失效**，报价入口 `⊘`「需求已失效」；WS-324 原型的基线仍是 V5.0，其 README §5.6 已写明"自动失效尚未做页面"，因此那边它仍显示为在途需求 + 覆盖不足预警。**口径以 V7.0 为准**，待 WS-324 升到 V7.0 基线时两边自动对齐。本轮没有替它改，因为那属于重写 WS-324 的页面规格。
