# 借贷广场 · 授信、报价与接受/拒绝 — 原型（WS-325）

> **v1.3.1。** 设计基线继承 WS-324 借贷广场原型，不重新推导：token、公共组件、运行时、页面登记、面客 portal 顶栏骨架与视觉尺度全部沿用。
>
> **v1.3.1**（需求方 09-15）：**授信三支的提示维持居中弹窗**，不改抽屉。承载因此分成两种形态——
> **提示是居中弹窗**（额度不足 / 无额度 / 额度过期），**做事是右侧抽屉**（额度编辑、报价表单、报价确认）。
> 提示是一次要你表态的打断，居中比从边上滑出更像"停一下"；确认之后才划出抽屉去做事。
> **同一时刻只有一层**：要么弹窗、要么抽屉，不会同时在（全量遍历里挂了断言）。
>
> **v1.3 三处**（需求方 09-15）：① 报价环节**不再填机构收款账户**，报价表单唯一必填只剩利率；② 承载单元「接受 / 拒绝报价」更名为**「报价确认」**（WS-324 的入口名与 registry 页面名一并改）；③ 承载形态改为**右侧抽屉**，用公共 `.drawer` 一族，宽度 **760px**（提示见 v1.3.1，维持居中弹窗 560px）。
>
> **抽屉宽度为什么是 760**：公共 `.drawer` 的 440px 装不下报价确认里的条款网格与三步流程，每行只能排一列；整屏又等于变回一个页面,右侧划出的意义就没了。760px 在 1440 下约占一半——网格能排两到三列,身后详情页还留得下三分之一可见。窄屏收到 `92vw`。
>
> **v1.2.1 复盘整改三处**：撤掉顶栏那个被遮罩挡住、点不动的身份切换器（只留评审条上一个）；弹窗滚动区底部留白，正文不再被按钮条压住；清掉两道闸门牌与三占用对照撤下后残留的死 CSS。
>
> **v1.2 六处**：① 承载改回**弹窗**，授信提示做成**带遮罩的对话框**；② 弹窗内不放操作栏，顺序＝授信信息 → 报价表单；③ 新增两个只读字段；④ **平台内部规则一律不上界面**；⑤ 评审用承载单元切换器；⑥ 未登录态只出「立即登录」、对外状态改用五值。**WS-324 一并按同一标准过了一遍。**

| 类别 | 覆盖 |
| --- | --- |
| 通用页面态 | 默认 / 加载中（skeleton）/ 加载失败 / 无权访问 / 不存在或无权访问 / 不可报价（P-LS-05）。前三个走公共 `stateBar` 切换 |

> **本模块零链上动作。** 授信核定、报价、接受、拒绝都只改平台侧的额度与状态，**不产生链上操作、不消耗 gas、不唤起签名 SDK**——三页都常驻明示这一点（6.1.2 费用提示）。因此上游的「五类链上失败各有独立页面态」这条红线在本模块**没有触发条件**，它的落点仍在 WS-324 的质押与提取。本模块对应的"失败必须可区分"由上表的**提交终检五结局**与**接受流程异常**承担，同样不允许只写"操作失败"。

## 2. 四个招牌件

它们是本模块与 WS-324 结构上的分野，也是这三页要站的立场。

| 件 | 服务的口径 | 为什么是这个形状 |
| --- | --- | --- |
| **授信尺** `.cq-crbar` | `AC-CR-03` | 与 WS-324 的额度尺（`.ls-meter`，**项目维度**）成对：那把尺量"这个池子还撑不撑得住"，这把尺量"这家机构还借不借得出"。段序固定为`授信占用额 → 在途报价金额 → 本次报价 → 可用授信`，**与不等式左端同序**；超出部分单列为斜纹 `over` 段，差额在尺上一眼可见。旁边的 `.cq-eq` 把不等式摆成可读算式，各项与尺上的段同色，结论在行尾。 |
| **两道闸门牌** `.cq-gates` | `AC-FIN-07` / `AC-CR-22` / `D-CR-21` | 两张判据牌**并置**——并置本身就是那条口径：两道独立、须同时通过。每张给`判据 · 当前取值 · 结论 · 谁来解决`。这是消灭"不满足条件"这句话的装置：覆盖不足是**资产方**的事，授信不足是**机构自己**的事，混成一句会让双方各自等对方动作。 |
| **锁定倒计时** `.cq-cd` / `.ls-lock` | `D-LS-13` / `AC-LS-85` | 四件事一个不少：被谁锁定 / 从什么时候开始 / 已锁定多久 / **还剩多久**，外加两条出路。条上两段（已锁定 + 剩余）**相加恒为 168 小时**，这条恒等式在屏幕上可以直接核——和 WS-324 的三数等式同一个手法：把口径做成可验算的读数，而不是一句话。不足 24 小时切分钟精度 + warn 档；业务离开 `S-FD-1` 后整块不渲染（`D-CR-28`）。 |
| **手续费差额条** `.cq-fee` | `D-FIN-103` / `D-FIN-104` | 三格对照：`融资金额 − 跨境手续费 → 实收金额`，**中间与右边两格故意没有数字**，因为平台不预知、不代收、不垫付、不展示预估。难点正是"把一个未知量呈现得可信"：用与金额同一档的字号排版一句"平台不预估金额"，而不是留白或写 0。不折叠、不做小字注脚，位置在「确认接受」之前。 |

## 5. v1.2 做了什么

### 5.1 承载形态：三个承载单元都是详情页操作区里的弹窗

`P-LS-04 / 05 / 06` 不是页面。它们是详情页操作区的按钮打开的弹窗，**不跳离详情页、不新开页面、不弹窗套弹窗**。

**额度不足的动线**：点「立即报价」→ 弹窗内先出**对话框式提示** → 确认后**在同一个弹窗内**换到额度编辑步骤 → 回报价表单。三步同层，全程一层遮罩。

> **v1.1 错在哪**：那一版把提示做成了"遮罩层数 = 0 的就地替换"，看上去不像一次需要机构表态的动作——需求方指出的正是这一点。v1.1 的断言当时还把"遮罩 = 0"当成通过条件，**这一轮断言整个反过来**：提示阶段必须有遮罩、必须是对话框、必须只有一层。

| 项 | 落法 |
| --- | --- |
| 对话框形态 | 有遮罩、有问号标识、有明确问句、底部确认与取消两个按钮。提示阶段**零录入控件**（断言） |
| 只有一层 | 确认 → 额度编辑 → 报价表单三步换的是同一个弹窗的内容，`.mask` 恒为 1（断言） |
| 取消 | 关掉整个弹窗、回详情页操作区。**什么都不留**：不生成报价、不动额度、不锁定需求，也不记录"曾经取消过" |
| 三支都问 | ① 没额度 ②额度不够 ③额度过期，问句各不相同；④ 额度够用**不出提示**，直接进报价表单 |
| 只问一次 | 额度提交后重跑仍不够时直接回额度编辑，不再问第二遍 |

### 5.2 报价单元的版面

**弹窗内不放操作栏**，内容自上而下 = **授信信息 → 本次报价**（断言按 `h3` 顺序核）。

报价表单新增两个字段，**都是只读**：

| 字段 | 值 | 说明 |
| --- | --- | --- |

### 5.3 平台内部规则不上界面

判据公式、条款与验收编号、"实时重算不吃缓存""两道校验已一起重跑""授信与报价解耦"这类说明，**全部撤下**。同时撤掉的还有两张纯属平台内部的卡片：两道闸门判据牌、三个占用量对照表。

**但数字没跟着删**——撤的是规则，不是结果：

- **三个数的算式留着**（本次报价 − 可用授信 ＝ 差额），那是机构自己的数；
- **168 小时倒计时留着**，锁定必须可解释；
- 内部状态码改成对外说法（见 5.4）。

**怎么验的**：不写被禁的样例编号，改用**模式**判定——`[A-Z]{1,3}-[A-Z]{2,4}-\d+` 与 `S-[A-Z]{2}-\d+` 两条正则，在 126 组合的每一页渲染结果上跑，命中即失败。这样自查文件本身不会变成残留源。

### 5.4 未登录态与对外状态

- **未登录**：操作区只出一个「立即登录」，不再逐动作 `⊘` 附原因。公开信息照常全量可见。
- **对外状态五值**：`待报价 / 已报价待确认 / 放款中 / 已放款 / 已失效／已关闭`，与 WS-324 同一张表。界面不再出现内部状态机编号。

### 5.5 评审用承载单元切换器

需求方本轮明确要求加页面切换的快捷操作，**它覆盖了"原型不套评审脚手架"的默认约束**。做法：固定在视口底部的一条切换器，带身份切换与七个承载单元入口。

**它不改产品自己的导航**：不进顶栏、不进面包屑。产品里这三个单元的真实入口只有一个——详情页操作区的按钮。承载单元是弹窗，遮罩会挡住顶栏，所以身份切换也并进了这条，评审随时切得动。

### 5.6 WS-324 一并过了一遍

同一条红线在 WS-324 上也执行了：清掉界面上的条款编号、模块代号与内部状态码（240 处 → 0），逐条改成对外说法。业务规则一条未动，只动文案。

## 7. 假设、限制与需要上游处理的事

1. **公共壳层的 `onInput` 钩子没有实装。** `shell.js` 头部注释声明了模块接口 `onInput(n,k)`，但全文只挂了 `click`，没有 `input` / `change` 监听——`data-act` 挂在输入框上时，输入不会触发任何回调。本模块三页都是表单页，因此在 `cq-module.js` 末尾自挂了一层（只认本模块的 `data-act="cq.f"`，`input` 只回写状态不重绘、`change` 回写并重绘），**没有改 `_shared`**。**这是一条对公共层的修订请求**：要么在 `shell.js` 里实装 `onInput`，要么把该行注释删掉。WS-324 的项目名称 / 金额输入框也受同一问题影响。
2. **`P-LS-06` 的接受动作在原型内会真的改演示数据**（业务状态、项目状态），刷新页面即复位。授信核定同理。
3. **`FP-20260416-0007` 在两份原型里的表现不一致，这是已知且已登记的差异**：本模块按 PRD V7.0 的 `AC-FIN-26` 消费——`480,000 − 500,000 = −20,000 < 200,000`，该需求**已自动失效**，报价入口 `⊘`「需求已失效」；WS-324 原型的基线仍是 V5.0，其 README §5.6 已写明"自动失效尚未做页面"，因此那边它仍显示为在途需求 + 覆盖不足预警。**口径以 V7.0 为准**，待 WS-324 升到 V7.0 基线时两边自动对齐。本轮没有替它改，因为那属于重写 WS-324 的页面规格。
4. **本模块的演示数据是 WS-324 故事往前走了一步**：`FP-20260812-0031` 由 `S-FP-2` 进到 `S-FP-3`（北岸融资租赁已报价 `FD-20260908-0061`），并新增 `FP-20260722-0027`、`FP-20260628-0044` 两个项目以覆盖"他方锁定"与"额度已到期"两个分支。项目编号、名称、资产方、有效期与 WS-324 同源，两份原型讲的是同一件事。
5. **模块作用域版式与 WS-324 重复**：`.ls-phead` / `.ls-kgrid` / `.ls-fold` / `.ls-ro` 等是从 WS-324 模块文件逐行搬过来的，**类名一字不改**。它们是面客页档位的组合类，`base.css` 是管理端密度，规范禁止为单个页面改全局视觉密度，因此只能留在模块层。将来把这批组合上收 `base.css`（作为面客档位的一组修饰类）是机械操作——**建议在第三个面客模块出现前做掉**，否则会复制第三份。
6. **正文为中文单语**，与 WS-324 一致：registry 里给了页面名的 EN/ZH，正文只有中文；语言开关切 EN 时正文不变。i18n 按 WS-308『01-国际化基线』在实现阶段补。
7. **汇率快照值、账号、SWIFT、链上地址均为虚构**；`USDT` / `USDC` 的快照值只为走通"选中币种即时展示结算金额"，不代表任何真实行情。
8. **未做**（本期明确不做，不是遗漏）：报价撤回与修改、展期续期、授信调低/冻结/解冻、授信审批、盖章件审核态、合同模板与生成、多收款账户账户簿、实收金额、预估手续费。

**数据诚实性**：全部业务数据为演示数据。派生量（可用授信、差额、剩余有效期、已锁定时长、结算金额）都由页面上的常量按 PRD 公式现算，可逐项核对。
