## 1. v2.0 → v2.1：按 PRD V3.4 改了什么

需求方 09-15 09:35 给了四条（附截图，截的正是 v2.0 的第③段）。产品侧路由后确认：**四条里只有第③段属于本 issue**——三段式操作区的容器规范是 WS-324 的条款（主册 6.5.5 / `D-FIN-78` / `AC-LS-85`），第①段全局操作归 WS-324，第②段融资流程四环节跨 WS-325 / WS-326。本模块**只拥有第③段**（`D-RP-77`），①②只是复刻出来托住第③段，**一个字都没往本册写**。

| # | 需求方原话 | v2.1 落法 |
| --- | --- | --- |
| 1 | 将操作区分隔开，分成三个模块 | 第③段**独立成一张卡**：自己的区块标题「还款流程」、与②之间有明确分隔、**不与②的环节条混排、不共用②的当前环节高亮态**。另加一条 PRD 补的：**业务未进 `S-FD-6` 时整段不渲染**（不是空块、不是占位）——空块会被读成「还款流程坏了」，而此刻正确的事实是「还没走到这一步」 |
| 2 | 可以按照融资需求编号 / 放款编号进行选择；展示最近的一笔还款 | **一个选择器，不是两个切换器**（`D-RP-78`）：本期 `FP-28` → `FD-01` → `LN-01` 恒为 **1:1:1**，做成两级筛选等于把同一件事筛两遍。落法＝**主标识 `FP-28`** + **副行并排 `FD-01` / `LN-01`** + **检索框按任一编号命中同一选项**；只有一笔时**仍展示编号但不给选择控件**。卡片内容与需求方截图一致（期次 · 应还日 · 应还合计 · 期次状态 · 逾期天数） |
| 3 | 立即还款页展示信息精简，仅展示本期需要还款信息与填写内容 | 精简为**四类**：期次选择器 · 本期应还信息 · 机构收款账户 · 填写项。移走的**逐项写明去处**（见 §1.1），不写「不展示」了事 |
| 4 | 查看还款计划只查看定稿版即可，内容精简、突出重点；选定的项目 | **定稿版单版**：「预计 · 未生效」标识、「预计还款日」列名、两版 tab、差异高亮全部取消。主表**精简为 6 列**，本息拆分与计息区间**收进行内展开**（不是删掉——`AC-RP-04` 要求资产方能自行验算）。**当前应还期次默认高亮并滚动到可视区**。标题区带**需求编号 + 出资机构 + 业务/放款编号 + 币种**，**一次只呈现一笔**（`D-RP-81`） |

### 1.1 精简：移走的东西去哪了

`D-RP-79` 要求「不得只写不展示」——读者要能回答「那我在哪儿看」，否则精简就是丢功能。

| 原来在「立即还款」抽屉里的 | 移到哪儿 | 怎么到达 |
| --- | --- | --- |
| 完整还款计划表、计息规则全文、本期本息拆分与计息区间 | **「查看还款计划」抽屉** | 抽屉内一个文字链「查看完整还款计划」，一键打开；**同一时刻只有一层**，打开计划抽屉即关闭本抽屉 |
| 跨业务的期次全集 | 我的控制台还款信息 tab | 第③段按编号选笔，抽屉内只呈现选定笔的期次 |
| **五个拦截点说明、两条轴示意** | **不进生产界面** | 移到详情页的「**原型说明件**」区（`.ln-annot-card`，明写"不属于生产界面"）。它们是 PRD 条款与原型说明件，不是给终端用户看的界面元素 |
| 页脚「不产生链上操作」整段 | 保留，收为抽屉底部一行浅色注脚 | 它防的是「以为平台会代为转账」，成本一行、收益明确 |

**`D-RP-79` 的四条下限，一项都没砍**（`AC-RP-31` ①，逐项断言过）：① 机构收款账户（法币五项含中转行 / 数币地址 + 链常量）——**它是「填写所必需的核对信息」，看不见就无法打款，砍掉 `D-FIN-24` 整条作废**；② 本期应还合计与结算金额；③ 期次序号与应还日；④ **逾期时的逾期天数与「提交后即冻结」那句话**——`D-FIN-11` 的界面形态，精简成看不见等于取消这条保护。

**精简的是呈现，不是规则**：币种金额仍只读、还款时间仍不得晚于提交时刻、提交仍触发冻结与 168 小时计时、二次确认三件事一件不少。

### 1.2 两个招牌件的归属变了，说明一下

- **`.rp-vs` 两版计划对照 —— 退役**。需求方定「只查看定稿版即可」，两版同屏对照取消，样式一并删除、不留死代码。**业务规则一条没改**：报价期仍要拟定初始计划、放款确认后仍按实际放款日重算定稿并锁死。初始版**不是被删掉**，而是收敛回它本来的位置——**只在报价环节可见**（报价详情页与 `P-LS-06` 接受抽屉，见 WS-325 原型里的 `initialPlanCard`）。⚠️ **取消对照表 ≠ 取消告知**：定稿通知里的新旧对比仍然保留，它是资产方得知「日期整体后移」的唯一渠道。
- **`.rp-freeze` 两条轴、`.rp-stop` 五个拦截点 —— 移出生产界面**。PRD 把它们归为「PRD 条款与原型的说明件，不是给终端用户看的界面元素」。它们仍然要能被评审看到，因此落在详情页一张**明确标注「原型说明件 · 不属于生产界面」**的虚线卡里。界面上保留的是它们的**效果**：未开窗 `⊘` + 原因、金额只读、逾期天数那句冻结提示。

### 1.3 承载理由重写（`D-RP-72`）

计划抽屉仍是 **760px 抽屉**，但**理由换了**——v2.0 写的是「两版各 9 列要同屏比出差在哪，560px 装不下」，两版对照取消后这条论证不成立，本轮**不再沿用**。新理由按判据重过：提示类要求「零录入**且**只知悉**一件事**」；定稿计划表零录入没错，但它是 N 期 × 6 列的**表格型参考数据**，用户要按行定位「我在还哪一期、下一期什么时候」并与还款抽屉对照，属「一边看信息一边逐行核对」那一类；560px 放一张 6 列表每列都会被压到换行，逐行核对反而更费劲。

### 1.4 字段编号不上生产界面（`AC-RP-28` ④）

原型里为便于评审在标签上带了字段号（例如「逾期天数 · RP-11」，正是需求方截图里那一行）。那是**原型的标注约定，不是界面规格**。本轮已从**第③段与「立即还款」抽屉**的用户可见标签里去掉，只出业务名称。**确认抽屉与计划抽屉的注解行仍保留字段号**——它们是评审用的追溯线索；若要一并清掉，说一声即可，是纯机械改动。

## 3. 承载形态自检（`AC-RP-24` / `D-RP-76`，逐条实测）

| 要求 | 实测 |
| --- | --- |
| 三个做事类都是右侧抽屉 760px | 三个抽屉在 1280 / 1440 / 1920 实测宽度均为 **760px**（`min(760px,92vw)`） |
| 都不跳离详情页 | 抽屉开在详情页之上；关掉抽屉仍停在详情页，**不返回、不跳走** |
| 计划表在一个抽屉内完成（V3.4：单版） | **表头与期次序号列 `position:sticky`**；标题区（需求编号 + 出资机构）与计息规则条固定在抽屉顶部（`.u-fixed` sticky）；**当前应还期次默认高亮并滚动到可视区**；本息拆分与计息区间行内展开 |
| 不得拆页 / 跳新页 / 分步向导 / 卡片式逐期展开 | 单版单表、行内展开，未拆页 |
| 二次确认是居中弹窗 560px、零录入、只有两个按钮 | 实测宽度 **560px**；弹窗内无业务录入控件（仅勾选框与原型侧的结果模拟下拉） |
| 同一时刻只有一层 | 全部 174 组合下 `#layers` 里同时最多一层；弹窗出现时其下方内容整体被遮罩；**还款抽屉里的「查看完整还款计划」文字链是换层不是叠层**（打开计划抽屉即关闭还款抽屉，实测层数恒为 1） |
| 换选期次不得为此再开一层 | 就地切换，层数不变（实测点击前后层数相等） |
| 第③段按编号选笔、抽屉内按 `D-RP-22` 排序 | 两个选择并存且未合并；`FP-20260812-0031` 下两笔（出资机构不同）可切，切换后卡片与计划视图同步 |
| 进 `S-FD-8` 后第③段只剩查看 | 实测按钮集合 = `['查看还款计划']` |

⚠️ **实测发现一处公共层缺陷并在本模块内绕过**：公共 `.mask` 是 `z-index:200`，而 `.drawer-scrim` 是 `205`、`.drawer` 是 `210`，且 `shell.js` 把抽屉渲染在弹窗**之后**——抽屉开着时二次确认弹窗会被抽屉与它的遮罩整个盖住、点不到，直接违反 `D-RP-76`。本模块用**模块作用域修饰类** `.mask.rp-top{z-index:220}` 抬到抽屉之上，**没有改公共组件的默认值**。**WS-326 v2.0 有同一处缺陷**（实测 `mask:200 / scrim:205`），建议在公共层修一次、两个模块一起回归（见 §6 第 4 条）。

## 4. 红线与规则（逐条可验）

| 规则 | 在哪儿验 |
| --- | --- |
| **`D-FIN-11` / `D-RP-29`** 提交即停止计息与逾期累加 | `.rp-freeze` 两条轴（三个抽屉都有）；`P-LS-10` 第二区「逾期天数（已于 {提交时间} 冻结）」；超期态下逾期天数**恒为 5 不变**；提交二次确认第 ② 条。界面上**不存在**：确认后才更新逾期天数的表现、"确认前仍在计息"一类文案、把停止点画在确认时刻的时间线 |
| `D-RP-04`～`D-RP-08` 两版关系 | 两版对照：基准日各自来源、期数、末期应还日不变、利息差额与天数差逐项可核 |

### 4.1 五类链上失败：本模块没有触发条件，结清那一段有一个真的

还款转账发生在**平台之外**，平台只收哈希与链的文本记录；`X-LS-52` 明写质押的释放与提取不属于本模块，`D-RP-39` 明写本模块只输出「该笔业务已结清」这一个事实。因此链上执行失败的五种页面态**在本模块三个抽屉里没有触发点**，页脚照实写明，**不为凑红线造五个假页面态**。

`D-FIN-57` 的两段式：「业务释放」即时、无链上动作；「**链上提取**」由资产方自助发起自付 gas，**那一段有真实的链上失败**——它**已经在 WS-324 的提取环节实装**（`ls-module.js` 的五类失败文案 + 可提取代币卡 + `AC-LS-38` 常驻提示）。本模块在末期确认区把链路讲清并指过去，**不复制一份**。
