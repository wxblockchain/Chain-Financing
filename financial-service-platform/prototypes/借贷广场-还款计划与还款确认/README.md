## 1. v1.0 → v2.0：改了什么

### 1.1 五处对不上的地方（PRD 校对提出，逐条已改）

| # | v1.0 现状 | v2.0 落法 |
| --- | --- | --- |
| 1 | 4 处仍锚 `QT-07`/`QT-08`，文案写"机构**报价时**提供的" | 改锚 WS-326 **`LN-15`**（法币：户名 / 账号 / SWIFT / 开户行 / **中转行** 五项整组）/ **`LN-16`**（数币：资金方绑定钱包地址，只读）。文案改为"**资金方放款时登记的还款收款账户**"。**全文 `QT-07`/`QT-08` 归零** |
| 2 | 链写"只读 · 等于 `QT-08` 的链"，并有 `E-RP-05` 链不一致的演示结局 | 链是**常量 `ETH`**，只展示不录入、**界面不给任何选择控件**；`E-RP-05` 标**本期不可达**，提交结局下拉里**已移除 `chain` 分支**（不再构造用例）。USDT / USDC 即 ERC-20 |
| 3 | `REPAY_METHOD = '先息后本 · 到期还本付息'`（本模块自定义） | 改为只读引用 WS-325 **`QT-15`**「**按季付息；到期还本付息**」，**不在本模块定义、不做下拉**；补 **`QT-16` 最终还款日**（＝项目截止日，派生、**跟随不快照**，落 `FD-46`）。另按 `D-RP-13` 把原「还款类型」更名为 **`RP-13` 还款性质**（该词已由 `QT-15` 占用，`AC-RP-27`） |
| 4 | 三个承载单元是**整页**，`modal` 21 处 | 三者改为详情页操作区第③段内的**右侧抽屉 760px**；两处二次确认走**居中弹窗 560px**；`⊘` 原因与状态提示**内联 / Toast、不开层**；**同一时刻只有一层** |
| 5 | 质押释放那段残留 1 处旧词根 | 按 WS-324 `D-LS-17` 改名裁定改为「**质押覆盖**」，**grep 归零**（产品文案与原型注解都查过） |

### 1.2 第 4 处比"换个容器"大：原来是页，现在是抽屉

校对把它写成「承载仍是 `modal` → 改抽屉」，但 v1.0 的实际形态是**三个注册页面**（`P-LS-09` / `P-LS-10` / `P-LS-91`，走 `CF.go` 切页），`modal` 只用在两处二次确认上。PRD V3.0 把它们重定义为**详情页操作区第③段内的承载单元**（`D-RP-71`），因此本轮是一次结构重写，不是容器替换：

- 新增**宿主页**：融资项目详情页 + **三段式操作区**（全局操作 / 融资流程四环节 / **还款流程**），承接 WS-324 `D-FIN-79`/`AC-LS-85`。
- 第③段按 **`FP-28` 需求编号切换**，展示最近一笔还款的核心信息，三个入口一律开抽屉、**不跳离详情页**（`D-RP-66`）。
- ⚠️ 第③段按 `FP-28` 的切换与抽屉内按 `D-RP-22` 的期次排序**不是同一个**（`D-RP-74`）：进抽屉前选"哪一轮需求"，进抽屉后选"这一轮里哪一期"。两者并存、互不替代，演示数据里 `FP-20260812-0031` 下有 `-03`/`-04`/`-05` 三轮需求可切。
- **未登录时第③段只出「立即登录」**（`D-RP-67`）——不再逐动作 `⊘` + 独立原因，**连需求切换器也不出**，否则本段就不止一个可点的东西。服务端鉴权与跨主体隔离一条不减。
- **业务进 `S-FD-8` 后第③段只保留只读的「查看还款计划」**，两个动作按钮一律不再出现（`D-RP-73`）。
- 深链语义随之改为「**落详情页 + 定位第③段 + 打开对应抽屉（并选中对应期次）**」，四个锚点逐个验过。
- `P-LS-09` / `P-LS-10` / `P-LS-91` 在 `registry.js` 里**仍登记为页**，是因为公共壳层按 page 组织状态切换器；三个页 ID 渲染的是**同一张详情页**，区别只在 `syncScene()` 给 `S.drawer` 配了哪个抽屉。

## 3. 承载形态自检（`AC-RP-24` / `D-RP-76`，逐条实测）

| 要求 | 实测 |
| --- | --- |
| 三个做事类都是右侧抽屉 760px | 三个抽屉在 1280 / 1440 / 1920 实测宽度均为 **760px**（`min(760px,92vw)`） |
| 都不跳离详情页 | 抽屉开在详情页之上；关掉抽屉仍停在详情页，**不返回、不跳走** |
| 两版对照在一个抽屉内完成 | 同屏左右两版 + 差异列高亮；**表头与期次序号列 `position:sticky`**；计息规则条与版本标识固定在抽屉顶部（`.u-fixed` sticky）；tab 切换**不离开抽屉** |
| 不得拆页 / 跳新页 / 分步向导 / 卡片式逐期展开 | 三个版本都在同一个抽屉里由 `seg-mini` tab 就地切换 |
| 二次确认是居中弹窗 560px、零录入、只有两个按钮 | 实测宽度 **560px**；弹窗内无业务录入控件（仅勾选框与原型侧的结果模拟下拉） |
| 同一时刻只有一层 | 全部 168 组合下 `#layers` 里同时最多一层；弹窗出现时其下方内容整体被遮罩 |
| 换选期次不得为此再开一层 | 就地切换，层数不变（实测点击前后层数相等） |
| 第③段按 `FP-28` 切换、抽屉内按 `D-RP-22` 排序 | 两个切换并存；`FP-20260812-0031` 下三轮需求可切 |
| 进 `S-FD-8` 后第③段只剩查看 | 实测按钮集合 = `['查看还款计划']` |

⚠️ **实测发现一处公共层缺陷并在本模块内绕过**：公共 `.mask` 是 `z-index:200`，而 `.drawer-scrim` 是 `205`、`.drawer` 是 `210`，且 `shell.js` 把抽屉渲染在弹窗**之后**——抽屉开着时二次确认弹窗会被抽屉与它的遮罩整个盖住、点不到，直接违反 `D-RP-76`。本模块用**模块作用域修饰类** `.mask.rp-top{z-index:220}` 抬到抽屉之上，**没有改公共组件的默认值**。**WS-326 v2.0 有同一处缺陷**（实测 `mask:200 / scrim:205`），建议在公共层修一次、两个模块一起回归（见 §6 第 4 条）。

## 4. 红线与规则（逐条可验）

### 4.1 五类链上失败：本模块没有触发条件，结清那一段有一个真的

还款转账发生在**平台之外**，平台只收哈希与链的文本记录；`X-LS-52` 明写质押的释放与提取不属于本模块，`D-RP-39` 明写本模块只输出「该笔业务已结清」这一个事实。因此链上执行失败的五种页面态**在本模块三个抽屉里没有触发点**，页脚照实写明，**不为凑红线造五个假页面态**。

`D-FIN-57` 的两段式：「业务释放」即时、无链上动作；「**链上提取**」由资产方自助发起自付 gas，**那一段有真实的链上失败**——它**已经在 WS-324 的提取环节实装**（`ls-module.js` 的五类失败文案 + 可提取代币卡 + `AC-LS-38` 常驻提示）。本模块在末期确认区把链路讲清并指过去，**不复制一份**。
