### 1.3 `P-LS-91` 的页号说明（**请连同页号避让一起读**）

PRD 分册 6.6.1 把还款计划表定义为一张**跨页面共用的表**（`P-LS-06` 接受页 / `P-LS-09` 还款页 / 业务详情 / 控制台），**没有给它页号**。但 `F-LS-60` / `F-LS-62` / `F-LS-63` / `F-LS-64` 四个功能点都落在这张表上，其中 `F-LS-63`「定稿通知的新旧对比」本身就要求两版同屏，需要一个承载页。

因此原型侧给它一个**内部页 `P-LS-91`**，与 WS-324 的 `P-LS-90`「我的融资项目」同一处理：**号段取 90 段避让 PRD 连号段位**。已占用的号段是 `P-LS-01/02/03`（WS-324）、`P-LS-04/05/06`（WS-325）、`P-LS-07/08`（WS-326）、`P-LS-09/10`（本模块，取自 PRD）、`P-LS-90`（WS-324 原型侧内部页）。

**不要据此把 `P-LS-91` 当成 PRD 已定义的页面，也不要拿它去和 PRD 的页面清单对账。** 同理，`deal/{id}?action=schedule` 是原型侧为它自用的锚点，**不是 PRD 深链契约的一部分**，不要当成新增的跳转约定往下游传。

### 3.1 五类链上失败：本模块**没有触发条件**，但结清那一段有一个真的（照实写，不凑）

还款的转账发生在**平台之外**——资产方自己的钱包或银行——平台只收下哈希与链的文本记录，**不发起任何链上调用、不消耗 gas、不唤起签名 SDK**（承接 `D-FIN-67`，`X-LS-52` 明确质押的释放与提取不属于本模块）。因此链上执行失败的五种页面态**在本模块的三个页面上没有触发点**，页脚照实写明，并指回 WS-324 的质押与提取。**本模块不为凑红线造五个假页面态。**

**但结清确实牵出一件真的链上动作**：`D-FIN-57` 的质押释放两段式。本模块的处理是：

- 「**业务释放**」即时、无链上动作、不被链上失败阻塞——它不在本模块，由 WS-324 在**项目进入终态**时执行（`D-FIN-49`：不提供「某笔结清即释放对应代币」的部分释放）；
- 「**链上提取**」由资产方自助发起、自付 gas，**那一段有真实的链上失败**——它同样不在本模块，五类失败态与 gas 口径**已经在 WS-324 的提取环节实装**（`ls-module.js` 的 `CHAIN_FAIL` 五类文案 + 可提取代币卡 + `AC-LS-38` 常驻提示）。本模块只在末期确认区把这条链路讲清并给出直达链接，**不复制一份**。

复制一份会制造两套文案与两处维护点，而 `D-RP-39` 明确本模块只输出「该笔业务已结清」这一个事实。**这不是漏掉，是按 PRD 归位。** 若评审认为提取五态应当在本模块也能点到，那是 WS-324 页面的可达性问题，不是本模块新增页面态的问题。

### 3.2 消息事件（页面侧保底）

本模块产生的事件（分册 10.4）由 WS-329 承接投递：还款计划定稿、应还日前 3 天提醒、逾期、还款记录提交、`repayment.confirm_expiring`（到期前 24 小时一档）、`repayment.confirm_overdue`（到期时刻，**双方各一条、只发一次**）、期次结清、业务结清。**投递未就绪时，同样的信息在页面上以状态、标记、时限条与进度呈现**（保底，不是替代）。

## 5. 假设、限制与需要上游处理的事

1. **PRD 未入库。** 本原型的口径来自 WS-327 issue 附件上的 `v1.0-借贷广场-还款计划与还款确认-PRD.md` V1.0 与分册 V1.0。**建议先把两份 PRD（连同 WS-326 那两份）推进 `cly-V1.0.0` 再据仓库版复核一次**；在此之前，任何「页面与 PRD 对不上」的争议以附件版 V1.0 为准绳基线。
2. **模块作用域版式已是第四份拷贝，上收该做了。** `.ls-phead` / `.ls-kgrid` / `.ls-fold` / `.ls-ro` 等从 WS-324 / WS-325 / WS-326 逐行搬来，**类名一字不改**。WS-326 README §5.2 已经记过这条；到第四份，把这批组合上收 `base.css` 做成面客档位的一组修饰类**已经明显该做**。它是机械操作，但**影响四个已交付模块**，应单独一轮做完并回归四个模块，**本轮没有顺手夹带**。
3. **公共壳层的 `onInput` 钩子仍未实装**（`shell.js` 头部注释声明了 `onInput(n,k)`，全文只挂了 `click`）。本模块与前三个模块一样自挂了一层（只认 `data-act="rp.f"`），**没有改 `_shared`**，并**照 WS-326 的写法**把 `change` 触发的重绘推迟一拍（`setTimeout(…, 0)`）——`change` 常在 `blur` 的派发过程中触发，同步改写 `#content` 会抛 `The node to be removed is no longer a child of this node` 并可能吞掉紧随其后的那次点击。**这条修订请求已经四轮没处理，建议与第 2 条一起排一轮公共层维护。**
