### 3.1 五类链上失败：本模块**没有触发条件**（照实写，不凑）

放款的转账发生在**平台之外**——机构自己的钱包或银行——平台只收下哈希与链的文本记录，**不发起任何链上调用、不消耗 gas、不唤起签名 SDK**（承接 `D-FIN-67`）。因此链上执行失败的五种页面态在本模块没有触发点，页脚照实写明，并指回 WS-324 的质押与提取（那里才有真实的链上动作）。**本模块不为凑红线造五个假页面态。** 这与 WS-325 的结论一致，但理由不同：WS-325 是全程零链上动作，本模块是「有哈希、但哈希是别人链上动作的文本记录」。

### 3.2 消息事件（页面侧保底）

本模块产生 6 个 `biz_type`（分册 10.4），投递由 WS-329 承接：`disbursement.submitted` / `confirm_expiring` / `confirm_overdue` / `deal.confirmed` / `contract.reupload_required` / `deal.terminated`。**投递未就绪时，同样的信息在页面上以状态、标记与倒计时呈现**（保底，不是替代）。「暂不放款」本期**不推送**（`D-LN-43`），原因在资产方页面上常驻可见——原型里也是这么做的。

## 5. 假设、限制与需要上游处理的事

1. **PRD 未入库。** 本原型的口径来自 WS-326 issue 附件上的 `v1.0-借贷广场-放款与融资确认-PRD.md` V1.0 与分册 V1.0。**建议先把两份 PRD 推进 `cly-V1.0.0` 再据仓库版复核一次**；在此之前，任何"页面与 PRD 对不上"的争议以附件版 V1.0 为准绳基线。
2. **模块作用域版式已是第三份拷贝。** `.ls-phead` / `.ls-kgrid` / `.ls-fold` / `.ls-ro` 等从 WS-324 / WS-325 逐行搬来，**类名一字不改**。把这批组合上收 `base.css` 做成面客档位的一组修饰类是机械操作，但它**影响三个已交付模块**，应单独一轮做完并回归三个模块，本轮没做（与 WS-325 README §5.5 同一条）。
3. **公共壳层的 `onInput` 钩子仍未实装**（`shell.js` 头部注释声明了 `onInput(n,k)`，全文只挂了 `click`）。本模块与 WS-325 一样自挂了一层（只认 `data-act="ln.f"`），**没有改 `_shared`**。本模块在此基础上多做了一件事：**`change` 触发的重绘推迟一拍**（`setTimeout(…, 0)`）——`change` 常在 `blur` 的派发过程中触发，此时同步改写 `#content` 会抛 `The node to be removed is no longer a child of this node`，并可能把紧随其后的那一次点击吞掉。**这条也适用于 WS-325**，建议下次回归时一并修。
4. **`Q-LN-01` 客服邮箱地址未定**：页面与交互按 `F-LS-49` 做完，地址是占位常量 `{平台客服邮箱}`（`ln-module.js` 顶部一个变量）。拿到地址替换一个常量即可，不触及流程与页面结构。
5. **演示数据与上游的关系**：`FD-20260908-0061` 就是 WS-325 那笔被接受的业务（同编号、同金额、同利率、同双方），本模块把它接到 `S-FD-3 待放款`——三个模块讲的是同一件事。本模块新造的编号一律避开 WS-324 / WS-325 已用号。`ws324:false` 标记的项目是本模块为走通页面态新造的演示项目，WS-324 的项目表里没有它们。
