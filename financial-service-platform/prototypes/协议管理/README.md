# 金融服务平台 · 运营端 · 协议管理交互原型

Stage 4/4 · existing-system adaptation · console。用户已批准原型入库。本模块覆盖运营端协议管理的页面与交互，不是已接入后端的生产页面，也不代表整个运营平台已完成。

## 打开与操作

从完整仓库双击本目录的 [`v1.0-协议管理-原型.html`](v1.0-协议管理-原型.html)，不需要安装、启动服务或联网。请保留跨目录引用的公共文件；只下载此 HTML 会缺样式和运行时。需要单文件时，按文末命令导出。默认英文，可在右上角切换中文。

- 直接进入协议列表；点击行或“查看”进入详情，详情有基本信息、版本历史、操作记录三个标签。
- **演示协议 01**：包含已归档、生效中、待生效版本，适合检查发布冲突、撤销、自动归档和历史回溯。
- **演示协议 02 / 03**：已有草稿，可继续编辑；**04** 尚无版本，可查看完整空白新建流程；**05** 已下线，仅查看；**06** 首个版本等待生效。
- 编辑页可选择或拖入本地文件，也可点击“使用演示文件”。奇数编号协议允许 TXT/PDF、2 MB；偶数编号只允许 TXT、128 KB。以上均为演示定义，不是生产默认值。
- 保存草稿不要求补齐必填项；发布需文件、变更说明和合法的生效时间。已有待生效版本时会出现“撤销并发布”及第二次确认。
- 详情演示数据条的“模拟到点生效”使版本状态切换，并在操作记录中生成 System 记录。
- 展开页头“原型场景”可切换加载、空数据、失败、受限和提交状态，也可模拟下一次保存/发布失败。此区域是评审辅助，不是产品菜单。
- 版本详情抽屉可以预览 TXT；PDF 使用浏览器内置阅读器，不可显示时仍可下载。支持加载/失败/仅下载的预览场景。下载的是当前文件的真实字节。元数据区包含版本 ID、文件信息与上传时间、内容哈希、生效方式、生效与归档时间、发布人（姓名 + 工作邮箱）、变更说明、来源版本与「需重新同意」取值。
- 每个页面的页头右侧有「PRD」按钮，打开本页的 PRD 摘录面板（四类：字段与校验 / 关键业务规则 / 状态与异常分支 / 中英文案）。**P-O-AG-04 是抽屉不是路由页**，其摘录入口放在版本详情抽屉的标题栏；从那里打开 PRD、关闭后会回到版本详情抽屉。面板固定中文，是给前端开发看的规格说明，不属于产品界面。
- 演示时钟初始为 **2026-09-09 10:00（UTC+8）**，可切换 UTC 展示；定时校验相对演示时钟判断。模拟到点生效会推进演示时钟。
- 文件及编辑数据只在页面内存中存在，**刷新后重置**；列表筛选、分页、排序和页面位置由 URL 保持。“重置演示数据”可恢复样本。

## 跨模块交接与明确不做

消息参数采用已入库 WS-309 的 `end=fs_ops`、`recipient_scope=admin_all`，来源 `WS-310`。WS-310 PRD §12.3 用 `ops` / `ops_all` 指代这两个取值并声明字面量以 WS-309 为准（§3.5 回填项 1），原型按回填后的字面量输出，PRD 摘录面板里也写明了这层对应关系。原型中 `registry.end=admin` 仅代表控制台形态，两者不混用。模拟事件可在“原型场景”中查看，仅供契约评审，不实际投递站内信。

## 假设与限制

1. “仅有 scheduled，尚无 active/draft”在 PRD §7.2.3 未定义。原型沿母版兜底为 **Unpublished + 计划生效提示**，不擅增状态筛选项；这仍是待产品回填的口径。
2. 消息 `resource_id` 为版本 ID；原型按本地映射解析所属协议并进入版本历史。真实系统仍需提供该解析能力，不把协议 key 冒充版本 ID。
3. 保存草稿后留在编辑页，采用 §7.3.3 的详细规则；§5.3 流程图的返回详情口径未回改。
4. 文件在内存中处理、下载，保存/发布/通知/定时任务均为模拟；没有调用真实接口。刷新会重置业务演示，不作为持久存储。
5. 演示文件中均明确写明不构成法律文本；样本的初始记录用于展示结构，后续操作实时追加。协议清单和生产下载域仍未定义。
6. PDF 渲染依赖浏览器内置能力；已验证有效 PDF 的本地加载和预览挂载，未验证各浏览器 PDF 插件内部排版。TXT 预览与下载做了字节一致性验证。
