# 智能合约（WS-312）· 运营端原型

运营端只读模块「代币管理 → 智能合约」的交互原型。页面与前端状态已实现；真实部署配置、权限接口与日志服务未接入，运行期不发起任何链上 RPC。

对应 PRD：[`prd/v1.0-代币合约/v1.0-代币合约-PRD.md`](../../prd/v1.0-代币合约/v1.0-代币合约-PRD.md)。

## 打开与使用

保留仓库目录结构后直接打开本目录的 `v1.0-代币合约-原型.html`（公共 token、组件与运行时按相对路径引用，不复制第二份）。默认英文，右上角 EN 下拉切中文，语言与时区选择存本地浏览器。

默认进入「尚未部署」空态——这是本期的真实常态。右上角「原型场景」下拉切换本页的数据与异常状态，它是评审用的数据开关，不是产品的筛选条件，也不是页面目录。

| 场景 | 用途 |
| --- | --- |
| 尚未部署（默认） | 本期常态：空态 A，无搜索、无筛选、无分页 |
| 演示部署数据 | 三种规划类型各一条，含完整参数与详情 |
| **多份部署（分页）** | 26 条、两条链，**用于演示搜索 / 筛选 / 分页**；这一组数据正好越过 PRD 7.2.4 写死的补做触发条件 |
| 加载中 / 等待返回 / 加载失败 | 骨架屏、长等待、失败重试 |
| 无查看权限 / 会话已失效 / 合约不存在 | 权限与会话降级 |
| 类型尚未下发 / 配置异常 / 无参数定义 / 长内容 / 无浏览器映射 / 复制不可用 | 配置降级与边界渲染 |

## 本轮新增：列表搜索 / 筛选 / 分页

范围只有列表页 P-O-TC-01 的这三件，页面结构、菜单、详情页、空态 A 的措辞与只读形态一律沿用上一版。

**搜索**（关键词输入 + 「搜索」按钮，回车等价）

- 匹配**合约名称**（中英两种取值都参与匹配，因此中文环境下输入英文名也能命中）与**合约地址**。
- 地址匹配忽略大小写与 `0x` 前缀，支持只输入末几位（列表里地址是缩略展示的，运营多半只记得住尾号）。
- 不匹配 `contract_key`、链名与参数值。列表里 key 显示在名称下方，如需一并纳入匹配请提出，这是一处口径而不是实现难点。

**筛选**（三项，取 PRD 已定字段）

| 筛选项 | 可选值来源 |
| --- | --- |
| 合约类型 | 部署配置下发的合约类型，按列表排序口径排列；配置里出现未登记类型时补一项「类型定义缺失」，保证这些行仍可筛出 |
| 状态 | **本期恒为 `active`，所以可选值只有「有效」一个**；配置里真出现别的取值时按原值补进来，不臆造 PRD 未下发的枚举 |
| 所属链 | 当前结果集里实际出现过的链（链名 + Chain ID），不预置链清单 |

关键词与三个筛选项都是**草稿**，点「搜索」或回车才生效，「重置」一次清空——与相邻的协议管理列表同一套交互契约，不在同一个控制台里放两种筛选行为。

**分页**：每页 10 / 20 / 50（默认 20），页脚显示「第 a–b 条，共 n 条」与「第 p / t 页」。切换每页条数回到第 1 页。

**筛选条件写入 URL query**（PRD 7.2.4 的原文要求）：`q` / `type` / `status` / `chain` / `size` / `page`，刷新、前进后退、进详情再返回都保持同一视图；详情页 URL 也带着列表的筛选条件，返回时不用重筛一次。

**三种空态严格分开**，文案与可用操作都不同（同 AC-O-TC-38 对「加载失败 ≠ 尚未部署」的口径）：

| 形态 | 主文案 | 说明与操作 |
| --- | --- | --- |
| A · 尚未部署 | 平台尚未部署任何链上合约 | 保留「平台已规划的合约类型」说明行（不可点）；**不渲染搜索框、筛选器与分页器** |
| B · 筛选无结果 | 没有符合筛选条件的合约 | 提示调整关键词或清空筛选；**筛选栏保留**（否则没有清空入口），提供「清空筛选条件」按钮 |
| C · 加载失败 | 合约信息加载失败 | 重试按钮；不渲染筛选栏与分页器 |

工具区的出现规则只有一条：**筛选栏在「本次加载成功且配置里至少有一份合约」时出现，分页器跟着当前页的数据行走**。因此本期常态（零部署）下页面不会留一排筛不出任何东西的空控件——这正是 PRD 7.2.4 当初不做筛选的顾虑，规则保留了这份顾虑，只是不再因此整体不做。

### 与 PRD V1.0 的已知差异

PRD 7.2.4 写的是「本期不做筛选器、不做搜索框、不做分页」，并有验收项 **AC-O-TC-10：列表页不存在筛选栏、搜索框与分页器**。本轮按用户指令提前实现了这三件，**因此原型与 AC-O-TC-10 直接冲突，与 D-05、F-O-TC-02 的「无筛选无搜索无分页」描述也不一致**。差异如实保留，不改写 PRD 也不宣称通过该验收项；PRD 是否补一版增量修订由产品侧决定。实现口径刻意贴着 PRD 7.2.4 已经写死的未来方案（三个筛选项、Filter bar 组件、位置在表格卡片内表头下方、条件写入 URL query），以便补 PRD 时不必再推翻一次。

## 沿用不动的约束

- 只读：界面无任何写操作入口，也没有禁用态的写操作按钮。
- 运行期零链上 RPC、零 HTTP 请求；区块浏览器链接只在有映射时出现，且需用户主动点击。
- 地址与哈希：列表、日志、传输一律缩略（地址前 6 后 4、哈希前 10 后 8），**只有详情页链上身份卡的合约地址完整展示**。地址按 EIP-55 离线校验和渲染。
- PRD 标 `[待确认]` 的数据一律不编造：界面显示 `—` 加一行说明，界面上不出现 `[待确认]` 字面量。
- 不带 PRD tab、PRD 按钮或摘录面板。
- 演示数据不是平台真实部署，页面持续显示演示提示；PRD AC-O-TC-60 的生产禁伪造规则不受影响。

## 本期不做

新增 / 编辑 / 删除 / 启停 / 导入导出 / 批量操作（含禁用态按钮）；合约类型维护页；面客端与资产平台视图；实时链上数值、RPC、钱包、签名、调用流水；ABI / 源码 / 审计报告；埋点与告警；生产鉴权、部署日志、性能与浏览器全矩阵；1280 以下专项适配。列排序（点表头改排序）本轮也未做——PRD 7.2.2 的排序规则是写死的，改排序等于改那条规则，不在本轮范围。
