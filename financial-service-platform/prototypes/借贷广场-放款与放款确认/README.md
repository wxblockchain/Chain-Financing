## 1.2 v2.1 的两块增量（PRD V3.2）

### 链收敛：本期只有 ETH 一条链（`D-LN-60`～`D-LN-63`，反向验收 `AC-LN-27`）

| 位置 | 改成什么 |
| --- | --- |
| 放款抽屉 · 资产方收款地址下方的「链」 | **只读展示 `ETH`**，旁注"本期只支持 ETH——是**只有一条**，不是默认一条；USDT / USDC 本期即 **ERC-20**，没有可选项，也就不存在选错链" |
| 放款抽屉 · 还款收款地址（数币） | 同上，只读 `ETH` |
| 确认抽屉 · 交易哈希区 | 增一行只读读数：链 `ETH` · 代币标准 `ERC-20` · 格式校验 通过；区块浏览器取 **ETH 固定前缀**，"平台未核验该交易"的常驻标注不变 |
| 提交结局选择器 | **撤掉 `E-LN-05`（链不一致）这一档**——本期不可达（`D-LN-62`），按不可达路径处理，不构造用例 |

界面上**没有任何链的选择控件**：无下拉、无单选、无"默认 ETH 可改"。实测见 §4.2。旧的 `Ethereum` 字样也清干净了，链只以常量 `ETH` 出现、币种标注 `ERC-20`。

### 还款收款账户：放款时登记（6.3.4，`D-LN-64`～`D-LN-68`，字段 `LN-15`/`LN-16`，验收 `AC-LN-26`）

放在放款抽屉第二区的表单里、备注之前，标题「还款收款账户」，一句话说清它是什么：**这是您将来收还款的账户，与本次出账账户无关，平台不比对两者，提交后本期不可改。**

- **法币**：户名 / 账号 / SWIFT / 开户行 / **中转行** —— **五项整组必填**，缺一项主按钮就不可提交，底部"还缺"逐项点名。
  ⚠️ 这套**比资产方侧多一个中转行**，两侧规格**有意不同**（他们收放款、机构收还款，经手行不同）。字段说明里把这件事写明了，**不要为了两侧视觉对齐删掉它**。
- **数币**：取资金方登录时绑定的钱包地址，**只读展示、无任何录入控件**，链同为常量 `ETH`。绑定后不可更改，平台不在此另存一份可编辑副本。
- **放款后不可改**：提交前的二次确认里单列一条告知；提交后界面上**没有任何修改该账户的入口**。
- **不是回滚**：它与 WS-325 撤掉的报价时「机构收款账户」是两件事（时点、用途、归属环节都不同）。本模块不引用那两个已作废字段，代码里也没有它们的残留。

### 4.1 `AC-LN-03` 同屏比对在 760px 内成立

量的是「合同里的融资金额」与「对照单里的融资金额」两个元素：

| 视口 | 配比 | 两者同屏 | 水平间距 | 垂直间距 | 左栏 / 右栏宽 |
| --- | --- | --- | --- | --- | --- |
| 1280×860 | 均分 | **是** | 344px | 48px | 354 / 354 |
| 1280×860 | 侧重合同 | **是** | 416px | 65px | 430 / 277 |
| 1440×860 | 均分 | **是** | 344px | 48px | 354 / 354 |
| 1440×900 | 均分 | **是** | 344px | 48px | 354 / 354 |
| 1920×1080 | 均分 | **是** | 344px | 48px | 354 / 354 |

作为对照：上一轮提案件里按"上下排"实现时，同两个元素**垂直相距 560px，在 1440×860 下无法同屏**。760px 不动、改成左右分栏之后，这条红线成立。

**已知限制（如实记）**：354px 的合同栏把 A4 页按 **44%** 渲染，正文字号约 8px——**数字与关键行可辨，逐条读合同条款需要点 `100%` / `150%` 并横向滚动**，或切到「侧重合同」把左栏放到 430px。这是 760px 宽度下的物理限制，不是实现选择；若将来允许更宽的抽屉，这一条自然消失。原型里的合同是**按真实 PDF 的比例与字号排版后整体缩放**的占位，没有为了"看起来清楚"而放大字号——否则这张实测表会骗人。

## 5. 本模块不触达链上

放款的转账发生在**平台之外**（机构自己的钱包或银行），平台只收下哈希与链的文本记录，**不发起任何链上调用、不消耗 gas、不唤起签名**。因此链上执行失败的五种页面态在本模块**没有触发条件**，抽屉页脚照实写明并指回 WS-324 的质押与提取。**不为凑红线造五个假页面态。**

## 6. 假设、限制与需要上游处理的事

1. **分册 6.5 与主册 4.5 对不上**：分册标题仍是 V2.0、6.5 整章仍写「弹窗」，而同册 `AC-LN-21`、7.3 常量表与主册 4.5 已是右侧抽屉。本轮**按主册实现**，分册修订另派（见 §7）。

3. **`Q-LN-01` 客服邮箱未定**：页面与交互按 `F-LS-49` 做完，地址是占位常量 `{platform-support-mailbox}`（模块顶部一个变量）。
4. **`Q-LN-02` 业务终止的对外状态**：按 PRD 建议口径实现为**退回「待报价」**。若最终裁定不同，改一处映射即可。
5. **面客档位版式仍是各存一份**：`.ls-phead` / `.ls-kgrid` 等在三个模块里类名相同、各存一份。上收 `base.css` 是机械操作但影响三个已交付模块，**第五次记录，仍建议单独一轮**。
6. **`shell.js` 的 `onInput` 钩子仍未实装**（头部注释声明了，全文只挂 `click`）。三个模块各自挂了一层。本模块的 `change` 重绘**推迟一拍**（`setTimeout(…,0)`）：`change` 常在 `blur` 派发过程中触发，同步改写 `#content` 会抛 `The node to be removed is no longer a child of this node` 并吞掉紧随其后的那次点击——**WS-325 仍受这个问题影响**。
7. **未做**（本期明确不做）：提出异议 / 申诉 / 驳回、`S-FD-5`、运营端裁决台、撤销确认、修改或撤回放款记录、部分放款、延长确认时限、链上核验哈希、催办、平台侧盖章件审核态、到账金额一致性校验、预估手续费数字。
