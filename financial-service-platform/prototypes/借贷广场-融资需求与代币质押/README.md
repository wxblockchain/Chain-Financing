## 0. 本轮返工：对着参考件做的逐页对比

需求方的两条原话——「没有竞品好看」「信息展示比较杂乱，抓不到重点」——指向同一件事：**层级**。下面是量出来的差距，不是感觉。

### 0.1 差距在哪（1440 宽，实测）

| 指标 | 参考件 Harbour Credit | v1.0（上一版） | v1.1（本版） |
| --- | --- | --- | --- |
| 列表页字阶跨度 | **3.40×**（10 → 34px） | 2.36×（11 → 26px） | **3.40×**（10 → 34px） |
| 详情页字阶跨度 | **5.20×**（10 → 52px） | 2.48×（10.5 → 26px） | **4.40×**（10 → 44px） |
| 列表条目高度 | **55px**（表格行） | 427px（卡片） | **56px**（表格行） |
| 列表首屏可见条数 | 5 条（该页全部） | **2 条** | **6 条（全部）· 首屏容量 ≈ 8 行** |
| 详情页总高 | 1430px | 3941px | **2472px（−37%）** |
| 详情页卡片数 | 4 | 7 | **4** |
| 详情页着色面块数 | — | 13 | **8（−38%）** |

> 着色面块 = `#view` 内面积 ≥ 400px²、背景带色相的元素个数（状态徽标也计入）。用同一段脚本量两版，口径一致。

五个维度的具体诊断：

| 维度 | 上一版的问题 | 本版怎么改 |
| --- | --- | --- |
| **字阶跨度** | 最大 26px、最小 11px，全页只有 2.4 倍差。没有"最大的那个字"，眼睛没有落点 | 字阶重定为 8 级 `11 / 12 / 13.5 / 15 / 20 / 26 / 34 / 44`，跨度 4.0×。详情页的 `融资需求金额` 与 `融资上限` 各占一个 44px，其余一律 ≤ 26px |
| **留白节奏** | 卡片内边距 20px、卡间距 16px，所有块等距排列，读不出主次 | 卡片内边距 24px、卡间距 20～26px；**三数等式与额度尺从卡片里拿出来，裸露在页面底色上**——参考件的 stat strip 就是这么做的，不给框反而更重 |
| **分区边界** | 每块都是「带底色的标题条 + 分隔线 + 边框」，一页 7 个框，框比内容抢眼 | 卡片标题行去掉填色与分隔线，只留一行 15px 标签 + 右侧 12px 灰注；边界靠白底与留白，不靠额外框线。详情页 7 框 → 4 框 |
| **色彩克制度** | 主色洗底的三数格、8 格带网格线的键值表、3 个彩色档位块、每张卡一条五色额度尺、三种底色提示条 | 全页**主色只出现两处**：唯一主操作按钮 + `融资上限` 那个数。提示条只有「担保不足」保留填色，其余改白底 + 3px 左侧色规。键值表去掉网格线改留白分栏。档位块降为折叠层里的三行文字。列表行的额度尺合并为两色 |
| **每屏信息密度** | 列表是 427px 高的卡片流，一屏 2 条 | 改为台账式表格，行高 56px，一屏 8 行 |

### 0.2 顺带找到的根因（重要，见第 11 节第 1 条）

入库时看到：仓库 `asset-platform/prototypes/_shared/tokens.css` 的注释原文写着 **「面与描边（**竞品口径**）」「主色与语义色（**竞品口径**）」**，取值 `--bg:#F6F7FA` `--accent:#2557E8` `--border:#E6E9F0` —— **和参考件 `harbour-credit-portal-prototype.html` 的 `:root` 逐个相同**。仓库的设计规范文档也直接叫 `harbour-credit-portal-components.md`。

也就是说：**仓库里那套共用设计系统，本来就是照着这个参考件建的。** 我们按「不读 design 模块」的指令自建了一套，等于把已经对齐好的口径重新推导了一遍——"不好看"的根因就在这里。本版靠量参考件把层级追了回来，但要真正一致，应当直接接入。

## 3. P-LS-01 列表：按什么留、按什么降

**判准是资金方扫列表时要做的那个决定：值不值得点进去。**

| 留在主行 | 为什么 |
| --- | --- |
| 融资项目 / 资产方 / 编号 | 认人认项目 |
| **融资需求金额**（15px 等宽、右对齐） | 这一行最重要的数：要融多少 |
| 项目状态 | 这条需求现在处于什么阶段 |
| **担保状态 + 缺口** | 能不能报价的第一道闸 |
| 有效质押价值 + 张数（含失效张数） | 抵押物值多少、有没有水分 |
| **额度占用迷你尺 + 已占用 % + 可融金额** | 还有没有空间 |
| 有效期至 + 临近标记 | 什么时候截止 |
| 可报价 ✓ / ⊘ + 4～6 字短原因 | 不用点进去就知道能不能报 |

| 降级到详情页 | 去了哪一层 |
| --- | --- |
| 融资上限 / 项目融资余额 / 项目在途金额 | 详情页第一层：三数等式与额度尺图例 |
| 池内资产总额 / 失效代币价值 / 可撤回上限 / 担保缺口明细 / 已收到报价数 | 详情页第二层折叠「额度明细与判定口径」 |
| 逐张代币、合同号、发票号、买方企业名、链上哈希 | 详情页第三层次级视图「抵押物明细」 |
| ⊘ 的完整原因（含条款号与金额） | 行内保留短原因 + 悬浮 `title` + 点击 Toast；详情页 L6 给完整原因 |

**一个字段都没删。** 迷你额度尺把「余额 / 在途」合并成一段「已占用」，是因为 8px 高的条里塞三色只会变噪声——两个量的精确切分在详情页的完整额度尺与折叠层里逐个可读。

> 红线守住了：**信息缩减靠分层与折叠，没有删任何字段。** 游客 L1～L5 全量可见照旧——买方企业名、合同号、发票号、精确金额、逐张明细、链上哈希都在第三层原样展示。

### 4.1 操作区：主次与破坏性分级

| 层级 | 呈现 | 内容 |
| --- | --- | --- |
| **主操作（唯一）** | 44px 主色实心通栏按钮 | 资金方 = 立即报价；资产方 = 按状态取「填写金额并发布」/「再次发布 · 管理需求」，**担保不足档时自动切成「追加质押」**——此刻最该做的就是这件事 |
| 次操作 | ghost 通栏按钮，竖排 | 其余动作（再次发布 / 追加质押 / 关闭项目 / 提取已释放代币） |
| **破坏性 / 减少担保** | 独立分区，上方一条分隔线 + 「以下操作会减少池内担保，请先确认额度」，danger 描边按钮 | **撤回质押**——不再与主操作并排同权重 |

游客态下 5 个入口仍逐个可见可聚焦（L6 红线），但**同一条理由只写一次**，不再重复 4 遍。

### 4.2 融资进度（本轮新增）

环节名**全部取自 PRD 已有的融资项目状态机**，没有自创：

`S-FP-1 草稿` → `S-FP-2 募集中` → `S-FP-3 已锁定` ┊**本模块边界**┊ `S-FP-4 融资中` → `S-FP-6 已结清`

- 前三段实线轨，当前环节标「（当前）」并用主色。
- **后两段虚线轨 + 「· 后续环节」后缀 + 「由 WS-325 ～ WS-326 实现」「由 WS-327 实现」**，中间一条竖线标注「本模块边界」。
- 脚注写死边界：本模块只承载到 `S-FP-3 已锁定`（建池、质押、发布需求，以及"已被报价"这个状态落点）；报价与接受在 WS-325，放款与融资确认在 WS-326，还款结清在 WS-327，**此刻不可操作**。
- 当前环节即使落在后续区段也会标出（虚线 + 主色），不会出现"没有当前"的空档。
- 项目已到期时脚注补一行：并行标记「已到期 · 存量处理中」，停止接受新报价、不允许再次发布，存量照常履约（`D-FIN-43` 分支② / `D-FIN-47`，中性呈现）。

### 4.3 移除与改版

- **报价时的池快照整块移除**（原 `AC-LS-27`）：卡片、"机构报价时池况 / 实时池况并列"的说明、演示数据里的 `snapshot` 字段一并删掉，不留死代码。PRD 侧条款作废按你的安排下一轮由许楚清处理。
- **历史融资记录改列表**：原来的竖向时间线换成两张表——「融资业务」（编号 / 金额 / 状态 / 发生日 / 说明）与「项目事件与派生量变化」（日期 / 事件 / 有效质押价值 / 融资上限 / 项目融资余额 / 项目在途金额 / 依据）。后者每一行就是两张图上的一级台阶，图与表可以对着核。全页无时间线组件残留。

**内容不变，复述一遍口径：**
- **池内资产变动**：底层 `有效质押价值`（蓝，计入担保）＋ 上层 `失效代币价值`（中性灰 + 135° 斜纹，不计入担保），顶缘虚线 = `池内资产总额`。失效部分刻意不给系列色。

- 单一纵轴，无双轴；配色经 dataviz validator 在 `light · surface #FFFFFF · --pairs all` 全项通过；唯一对比度 WARN（绿色 2.82:1）以直标 + 数据表双重补偿。

## 6. 视觉口径（本版）

**按指令未读取仓库 `docs/design-system/` 与既有原型 UI 约定，独立建立。** 本节是新提出的一套：

| 项 | 取值 |

| **字阶（8 级，跨度 4.0×）** | 11 / 12 / 13.5 / 15 / 20 / 26 / 34 / **44** |
| 应用底色 / 卡片 / 下沉面 | `#F4F6FA` / `#FFFFFF` / `#F8FAFC` |
| 描边 | `#E5E9F0`（常规）/ `#EEF1F6`（表格行）/ `#CBD5E3`（强） |
| 墨色 | `#0C1420` / `#4A5567` / `#7A8698` / `#9BA5B4`（四级） |
| 主色 | `#1F53C4`——**整页只用两处**：唯一主操作按钮、`融资上限` 那个数 |
| 状态色 | good `#0C7A43` · warn `#8A5200` · critical `#AC2E29` · mute `#5A6578`，保留色，不充当数据系列 |
| 数据系列色 | `#2a78d6` / `#eb6834` / `#1baf7a`（validator 全通过）；失效部分中性灰 `#8D99A9` + 斜纹 |
| 卡片 | 12px 圆角、24px 内边距、标题行无填色无分隔线、卡间距 20px |
| 列表 | 行高 56px、表头 42px、行分隔用最浅描边 |
| 控件高 / 圆角 | 36px（sm 29 / lg 44）/ 6px |
| 字体 | 系统 sans；**所有金额、编号、日期用等宽 + tabular-nums** |
| 焦点环 | 2px 主色，offset 2px，立刻出现，不参与任何动效 |

全部颜色与字体只走命名 token，页面内没有裸色值。动效只用 `transform` / `opacity`，并响应 `prefers-reduced-motion`。

**两个招牌件**（后续模块复用，不要各自造一套）：
1. **三数等式** `.trio`——`① × ② = ③` 用真符号排成一行，裸露在页面底色上；`融资上限` 44px 主色，让"乘得平"一眼可验。
2. **额度尺** `.meter`——完整版四段（余额 / 缺口 / 在途 / 可融）+ 上限刻度线（带数值）；迷你版两段，用于列表行。它是 `INV-FIN-01` 的可视化读数。
