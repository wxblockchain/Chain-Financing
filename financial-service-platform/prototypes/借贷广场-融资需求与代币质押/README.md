## 1. v1.2 做了什么

### 1.1 接入共用设计体系（替代 v1.1 的自建基线）

| 层 | 唯一来源 | 本模块做法 |
| --- | --- | --- |
| token | `asset-platform/prototypes/_shared/tokens.css` | 直接引用，**零平行 token**。v1.1 自建的 `--paper/--ink/--accent…` 整套删除 |
| 公共组件 | `asset-platform/prototypes/_shared/base.css` | `.card` `.card-head` `.tbl` `.pill` `.note` `.btn` `.seg` `.statebar` `.stat` `.rows` `.hash` `.modal` `.toast` `.steps` `.filters` `.skel` 全部复用，不覆盖 |
| 公共运行时 | `asset-platform/prototypes/_shared/shell.js` | `CF.define` / `CF.boot` / 路由 / Toast / 弹层宿主 / 语言切换 / 面包屑 |
| 页面登记与导航 | `financial-service-platform/prototypes/_shared/registry.js` | 新增 `P-LS-01`～`P-LS-90` 与 `CF.NAV.asset`，**模块不自建菜单** |

**连带删掉的自建物**：v1.1 的 `src/` 十一个分层源码与 `build.sh`（自造的构建链）、底部那条 44px 演示条、自建的 token 与组件层。

- **身份切换**移到顶栏上下文操作区（portal 规范 §3「品牌、主导航、语言/上下文操作分区」），用共享 `.seg`。
- **数据状态切换**改用公共 `stateBar`（`pageHead()` 自动渲染），状态表在 `mod.states` 里声明。

**图表系列色直接取系统 token**：`--accent` / `--warn` / `--pos`，失效部分 `--faint` + 斜纹，担保不足区间 `--danger`。这三色跑过 dataviz validator（`light · surface #FFFFFF · --pairs all`）：**六项全通过，三项对比度均 ≥ 3:1**——比 v1.1 自建色更好（自建色有一项对比度 WARN）。

### 1.2 详情页版式（本轮三条裁定）

1. **左右两栏**：左栏「质押代币清单」+「融资信息清单」，右栏 `.portal-rail` 操作区。
2. **融资进度并入操作栏**，不再是主视图里独立的一块。环节名仍取自状态机 `S-FP-1` → `S-FP-2` → `S-FP-3` ┊本模块边界┊ `S-FP-4` → `S-FP-6`，后段虚线轨 + 「· 后续环节」+「由 WS-325 ～ WS-326 / WS-327 实现」，脚注写明此刻不可操作。
3. **两张图移到页面最下方**，排在两栏之下。

**「融资信息清单」= 申请记录清单**：一行 = 一笔融资需求，进行中与历史同表，用状态列区分（`募集中 · 在途占用` / `已被报价` / `已成交 · 转入项目融资余额`）。v1.1 里分开的「当前需求」与「历史融资记录」已合并，不再细分。

> **不另发号。** 融资需求不是独立对象——项目编号即广场上这条融资需求的编号（`D-LS-11` / `H-01`）。所以清单用「项目编号 · 第 N 次发布」做显示引用，不新造申请编号。

**「不要再细分」只作用于记录粒度，没有删字段**：逐张抵押物明细（L4）原样留在左栏第一张卡，9 张全量、不脱敏、不区间化、不限行数，游客照常可见（`D-LS-09`）。

## 5. 假设与遗留

1. **正文为中文单语。** 公共壳层是中英双语，本模块的导航名与页面名在 registry 里给了 EN/ZH，但**正文文案只有中文**——PRD 全文为中文、双语文案评审尚未开始。i18n 按 WS-308『01-国际化基线』在实现阶段补。语言开关切到 EN 时正文不变，这是已知限制。
2. **`P-LS-90` 是原型侧内部页，PRD 未定义此页**：WS-324 PRD 6.1 只写了「草稿在"我的项目"与控制台有继续发布入口」，没给页面编号。它只承载 `AC-LS-54` 所必需的最小续做入口，**不是 WS-328 我的控制台**。号段取 90 段是为了避让：`P-LS-04 / 05 / 06` 已被 **WS-325 PRD V4.0** 占用（授信核定 / 机构报价 / 接受拒绝），原型侧不得再占 PRD 连号段位。
3. **字号上限 28px**。v1.1 自建基线用过 44px 的 hero 数字，接入后回落到系统字号阶梯的上限 `--fs-28`——规范明确禁止「新建平行 token」与「为了单个页面改变全局视觉密度」。详情页字阶因此是 10 → 28（2.8×），低于 v1.1 的 4.4×，但与仓库其他模块一致。
4. **`AC-LS-27` 池快照**：原型自 v1.1 起已整块移除（含数据字段），PRD 条款仍在，两边不一致，待 PRD 侧作废。
5. gas 预估为虚构值；链上超时 30 分钟为 PRD 标注的假设值，均待开发确认。
6. **PRD V6.0 / V7.0 新增项尚无页面**：融资需求因担保不足自动失效（逐笔判据、判定即失效、无缓冲期）、通知按 WS-329 投递、报价 7 天有效期。补的时候基线是 **V7.0**。

**数据诚实性**：全部业务数据为演示数据，企业名带「（演示）」后缀，编号 / 金额 / 哈希均为虚构。派生量由事件流按 PRD 公式算出，可在每张图的数据表里逐时点核对。
