## 3. 本轮新增：详情页两张图

两张图与页面上的数字**同源**：都由同一条事件流 `seriesOf()` 推出，不存在「图一套、卡片一套」。

### 图 1 · 池内资产变动

- 堆叠阶梯面积：底层 **有效质押价值**（蓝，计入担保）＋ 上层 **失效代币价值**（中性灰 + 135° 斜纹，不计入担保），顶缘虚线即 **池内资产总额**。
- 失效部分用「中性灰 + 斜纹」而不是系列色，是刻意的：它不是第三个业务系列，它是「不顶用的那部分」。
- 台阶只在质押 / 追加 / 撤回 / 失效事件上变化，事件之间保持不变——这是业务的真实形状，不是插值曲线。
- 「底层资产失效 2026-08-19」在图上有独立竖线标注。

### 图 2 · 融资变动

- **融资上限**：蓝色阶梯线（＝有效质押价值 × 80%，图例里写明来源）。
- **项目融资余额**：橙色阶梯面积（已发生债务）。
- **项目在途金额**：绿色阶梯面积，**堆在余额之上**——两条线因此可分辨，堆叠顶即「已占用总额」。
- **可融金额**：面积顶到蓝线之间的空隙，末端有竖向标注（本演示项目当前为 0，故不显示）。
- **担保不足区间**：`融资上限 < 项目融资余额` 的连续区段整段 45° 红斜纹高亮，起点有跨线圆点 + 「担保不足区间 · 自 2026-08-19 起 / 融资上限跌破项目融资余额」双行标注。**判据只比项目融资余额、不含在途**，与准入闸门分开——这一点在图下的「读法」里写明。
- 单一纵轴，无双轴。四个量口径互不混用，图例文字直接写出各自定义。

### 两张图的通用处理

| 项 | 做法 |
| --- | --- |
| 配色 | 系列色 `#2a78d6 / #eb6834 / #1baf7a`，经 dataviz validator 在 `light · surface #FFFFFF · --pairs all` 下全项通过（最差 CVD ΔE 9.2、最差常色 ΔE 24.0）。唯一 WARN 是绿色对白底 2.82:1，按规则以**直标 + 数据表**双重补偿 |
| 状态色 | 担保不足用保留的 status critical，永不充当数据系列，且始终带文字标签 |
| 图例 | 两条以上系列必有图例，且每条同时有端点直标；数值文字一律用墨色 token，颜色只由色块承载 |
| 悬浮 | 十字线 + 全序列读数（精确到 2 位小数）+ 当日事件与条款编号 |
| 数据表 | 每张图配「数据表」开关，列出每个时点的全部数值与事件——这也是绿色系列对比度 WARN 的补偿通道 |
| 坐标轴 | 刻度压缩取整（`$480K`）仅为可读性；**所有精确值**见悬浮读数、数据表与 L3 键值区 |

| 状态 | 到达路径 |
| --- | --- |

| 空数据 | 演示条「空数据」 |
| 筛选无结果 | 演示条「筛选无结果」，或任一筛选组合无匹配 |
| 加载失败可重试 | 演示条「加载失败」 |
| 无权限 | 以游客 / 资金方身份进入 `#/project/new` 或任一 P-LS-03 |
| 内容不存在或无权访问 | 以非本方身份深链直达草稿 `#/project/FP-20260910-0051` |
| 异步等待接口返回 | 建池时选「超时未决」：代币停在 `CT-1 处理中`，不接受新动作 |
| 提交中 / 提交失败 | 建池 / 追加 / 撤回 / 提取的链上结果，见下表五类 |

### 分册 6.7.2 的五类失败与等待——每类都有独立页面态，**没有只写「操作失败」的兜底文案**

| 类别 | 页面结论 | 可执行动作 |
| --- | --- | --- |
| 未上链失败 · 未扣费 | 「提交失败，本次未产生链上费用，可直接重试」 | 直接重试 |
| 已上链失败 · 已扣费 | 「链上执行失败，本次 gas 已产生、不可退回」 | 重试（按钮文案写明「将产生新的 gas」） |
| 超时未决 | 「等待链上结果超过 30 分钟，当前结果未知」 | **只有「查询链上状态」，页面上不存在重试按钮**（`AC-LS-74`） |
| 在 SDK 内取消签名 | 「您取消了签名，本次未产生任何费用」 | 重新发起；**不产生任何记录变更** |
| gas 不足 | 「钱包余额不足以支付本次链上费用（预估 X）」 | 充值后重试 |
| （另）部分成功 | 「按张独立结算：N 张成功、M 张失败已退回」 | 只重试失败的那几张 |

> 每一类都同时回答了「钱扣了没有」和「重试要不要再付一次」。
> 五类在原型里通过 **外部签名 SDK 弹层内的「结果模拟」选择器** 到达——该选择器是原型内的演示装置，已就地标注，真实系统不存在。

## 5. 业务规则的可交互落点（逐条可验，不是只写在文档里）

| 规则 | 编号 | 在原型里怎么验 |
| --- | --- | --- |
| 三个数必须乘得平 | `AC-LS-53` | L3 / P-LS-03 第②段顶部的「三数等式」：① 有效质押价值 × ② 80% = ③ 融资上限，`×` 与 `=` 是真符号；第一项取**有效质押价值**不是账面总额，账面总额降为副行「池内资产总额 X USD，其中 Y USD 因底层资产失效不计入担保」 |
| 质押率不得暗示可调 | `D-MC-110`/`D-MC-111`/`AC-LS-56` | 质押率区**控件数为 0**（已脚本校验）：无输入框、下拉、滑块、步进器，无焦点态；旁注「本期固定，不可调整」；全页无「调整 / 设置 / 自定义」质押率字样 |
| 唤起外部 SDK 签名 | `D-FIN-71`/`AC-LS-32`/`AC-LS-75` | 二次确认弹层先展示操作内容 + 笔数 + 预估 gas + 承担方 + 「平台不收费」→ 才唤起 SDK（深色、标注「第三方界面 · 非平台页面」）；SDK 内取消 = 一次失败，回到本页且无记录变更 |
| gas 由资产方自付 | `D-FIN-46`/`X-LS-09` | 费用区常驻「gas 由区块链收取，平台不代付、不垫付，也不对质押 / 撤回 / 提取收取任何服务费；链上失败也可能已经产生费用」 |
| 批量降费 | `D-FIN-53` | 可质押清单支持「批量勾选全部」，费用区写明「N 笔已合并为一次提交」；撤回 / 提取同样支持批量 |

## 11. 假设与需要决断的事项

1. **与仓库既有原型体系的冲突（最要紧）**——目标仓库已有成体系的原型约定：`docs/design-system/` 共用设计规范、`asset-platform/prototypes/_shared/` 共用 token 与运行时、`financial-service-platform/prototypes/_shared/registry.js` 页面登记与导航配置。本轮按触发方的明确指令「不读取 design 模块与现有 UI 代码约定」独立建了一套基线，**因此本原型不接入 `_shared/registry.js`，与已入库的 WS-308/309/310/312/318 原型不共用壳层与 token**。这不是疏忽，是按指令执行的结果，但它有代价：WS-325～WS-329 到底是在本文件上继续加，还是回到仓库的共享壳层重做一遍，需要先定。**建议尽早定这条**，越晚改成本越高。
2. **`DEP-08` 与 WS-329 的矛盾按 PRD 现状实现**——担保不足预警、可提取提醒、到期提醒在本原型里全部只做**页面标记**，没有站内信 / 推送入口。若 WS-329 消息中心本期确实交付，PRD 需出修订版，原型侧再补触达入口（改动量小，主要是在三处提示块旁加一个「已通知」标记与消息中心跳转）。
3. **失效代币的处置能力仍无承接**——本原型按「通知 + 催追加」做：失效代币标「不计入担保」、可随时无限制撤回、在预警块里列为诱因。没有任何处置、变现、清算入口。
4. **gas 预估为虚构值**，仅用于走通费用区与二次确认的信息结构；真实取数与单位待链上实现确认。
5. **链上超时阈值 30 分钟**为 PRD 标注的假设值，原型按 30 分钟展示，待开发按真实链况确认。
6. **「我的融资项目」是最小续做入口**，不是 M-5 控制台。若 M-5 立项，这一页应当被控制台吸收，而不是并存两个入口。
7. **报价数据**在本原型中只呈现为「已收到报价 N 笔」与池快照；报价对象与其状态机属 WS-325。

## 12. 阶段披露

触发方要求「按四阶段流程走」，同时授权「Stage 4 最终交付完成后直接推库，不用等人工确认」。在本运行环境下无法在一次运行内取得三次人工闸门确认，因此 **Stage 1（设计基线）→ Stage 2（设计方向）→ Stage 3（可交互原型）→ Stage 4（最终交付）在一次运行内连续完成，三道闸门被合并**：Stage 1 的产物是本文第 2 节覆盖矩阵与第 1 节分类，Stage 2 的产物是第 6 节视觉口径与第 7 节结构方案，Stage 3 / Stage 4 的产物是本原型本身。若第 6 节的视觉基线或第 7 节的结构方案需要推翻重来，现在说，改动仍然便宜。
