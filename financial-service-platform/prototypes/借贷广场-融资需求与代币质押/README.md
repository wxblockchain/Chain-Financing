## 1. `D-LS-17` 质押覆盖状态 —— 按 PRD V9.0 的定稿走

**本轮开工时 `D-LS-17` 还是 PRD V8.0 里的唯一开放项，等设计师给标签。写到一半 PRD V9.0 落库（`1f67971`），需求分析师已经把它定稿了，并在分册 7.6 明确「这组是 PRD 术语，设计师按本 PRD 的标签走」。所以原型采用 PRD 的定稿，不用我自己那版。**

| | V8.0 旧名 | **V9.0 定稿（原型已采用）** |
| --- | --- | --- |
| 字段名 `FP-20` | 担保状态档位 | **Pledge coverage status ／ 质押覆盖状态** |
| 档位 ① | 正常 | **Ample ／ 覆盖有余** |
| 档位 ② | 额度用尽 | **At Capacity ／ 覆盖持平** |
| 档位 ③ | 担保不足预警 | **Insufficient ／ 覆盖不足** |
| 缺口 `FP-21` | 担保缺口 | **Coverage gap ／ 覆盖缺口** |
| 提醒 | 担保不足预警 | **Insufficient-coverage notice ／ 覆盖不足提醒** |

**判据一字未动**：③ 仍是「融资上限 < 项目融资余额」，② 仍是「可融金额 = 0 且 ① 成立」。原型里旧词根**零残留**（脚本断言：中英两个视图下全页 0 处「担保 / 抵押覆盖 / 不足预警 / 额度用尽」）。

**如实回报我原来的提案与差异**，供需求方判断是否还要调整：我给的是 **Collateral coverage ／ 抵押覆盖**，三档 `Sufficient 覆盖充足` / `Fully drawn 额度已用尽` / `Undercollateralised 覆盖不足`。两版**在同一个方向上**——都用「覆盖」做词根、都拒绝了 LTV 与 Health factor、都把「预警」降级。三处实质差异：

1. **`Pledge coverage` vs `Collateral coverage`。** PRD 用「质押」限定，和 `质押率`、`质押代币价值` 同族，模块内自洽性更好；我用 `Collateral` 是跟保理 / ABS 里 *collateral coverage ratio* 的现成叫法靠。两者都成立，**PRD 那版在本仓库内部更一致，采用它是对的**。
2. **档② `At Capacity` vs `Fully drawn`。** `At Capacity` 与另外两档同词根、可平行阅读，这是 PRD 的理由；`drawn / undrawn` 是授信业务里讲额度动用的现成说法，更直接说明「讲的是额度不是覆盖」。**这一处我仍然略偏好 `Fully drawn`**，但差别小于"平行阅读"的收益，按 PRD 走。
3. **档① `Ample` vs `Sufficient`。** `Ample`（有余）比 `Sufficient`（够）多一层"还有富余"的意思，正好对上判据里的「可融金额 > 0」——**PRD 这处比我准**。

**一处需要需求方注意的措辞风险**：`At Capacity` 在英文里既可读成"满负荷（正常）"也可读成"到顶了（受限）"，而档②恰恰是**不能再借**。原型已在统计区与提示块里用整句消歧（"There is 0.00 USD left to borrow, so no new commitment can be taken on… this is not an insufficient-coverage notice"），但如果将来要做纯标签的紧凑视图（比如通知列表），建议给它配一句固定副文案。

**第 9 条里三件容易做错的事，这里是怎么处理的：**

- **合并的是入口，不是判定。** 「解除质押」弹窗里仍然分三区：已失效（不做额度判定）、有效抵押物（受可撤回上限约束，`AC-FIN-13` 视角 C）、已释放待提取（两段式释放的第二段，`D-FIN-57`）。一次提交合成一笔链上交易。用户不需要先分清自己的代币在哪一边。
- **可提取代币不再单独做提示块**（`AC-LS-38` 改写）：改成「解除质押」按钮上的**角标**（张数）+ 一行副文案（金额与"业务上已释放、链上仍在合约内"）。原来的 `redeemBanner` 已删除。
- **四环节的弹窗是壳。** 报价 / 接受拒绝 / 放款 / 确认到账 / 还款属 WS-325～327，弹窗里只放**已经权威公开的事实**与「该环节要提交什么」的清单，按钮是「前往 WS-32x 完成」。**本模块没有替下游发明任何规则。** 只有「发布融资需求」是本模块自己的动作，弹窗里是真校验（`D-FIN-61` + `AC-LS-09` 的当场重算与差额提示）。

**第 1 条改名连带的一处登记**：WS-325 / 326 / 327 三个原型里有 10 余处「返回融资需求广场」的返回按钮文案，以及它们指向的 `#/plaza` 锚点。本模块**保留 `#/plaza` 的兼容读取**，所以这些链接一条都没变成死链；但**按钮文案仍是旧名**。按「其他 issues 暂不入库、也不调整」的指示，本轮不去改它们，登记在此。

**另一处同名不同义，必须先统一（分册 6.9 已登记）**：需求方四环节里的「**融资确认**」＝ 资产方**接受 / 拒绝报价**（放款**之前**）；附册与 WS-326 里的「融资确认」＝ 资产方**确认收到放款**（放款**之后**，`S-FD-4`）。**两个不同环节共用一个名字**，照字面实现会把接受报价和确认收款接反。原型按分册 6.9 的映射表承载（环节③＝接受/拒绝，环节④＝放款 + 确认到账），并在代码注释里标了这处冲突。

**本轮顺手修掉的一个真 bug（v1.2 起就在）**：公共 `shell.js` 的 `data-act` 事件委托**只挂在 `click` 上**，所以本模块此前所有 `<select>` 与 `<input>` 上的 `data-act` 从来没生效过——筛选下拉、项目名、需求金额三处输入实际是死的。WS-325 / 326 / 327 三个模块各自补过一段 `input` 委托，本模块漏了。现在按同样写法补上（只挂 `input`，不挂 `change`：按钮点击引起的 blur 会在同一拍里触发第二次重渲，把正在处理的节点换掉）。

**另外两条模块作用域的 CSS 补丁**（不改公共实现）：`.mask > .modal{max-height:calc(100vh - 48px)}` 与 `.modal > .modal-b{flex:1 1 auto;min-height:0}`——公共 `.modal` 是 flex 列且 `max-height:100%`，但百分比高度在 grid 容器里解析不出来、`.modal-b` 又没有 `min-height:0`，内容一长（解除质押弹窗里可能有三张清单）页脚就被顶出视口。

## 8. 假设与遗留

1. **默认英文已落地，但正文英文是设计师产出的，不是评审过的译文。** `G` 表里的术语按 §1 的理由选定；长段口径说明的英文由本轮一并写出，**建议在实现前过一次业务方 review**——尤其是 `outstanding financing` / `committed demand` / `available to borrow` 三个映射，它们对应的中文是 `D-FIN-06` 明确点名的红线术语。
2. **代币符号是占位。** 分册 7.5.1 明确 WS-318 的代币符号配置本期仍为「待确认」且**不自造**，所以清单里显示 `[TBC] ／［待确认］`。等 WS-318 定了取值直接换 `TOKEN_SYM` 一处。
3. **`P-LS-90` 是原型侧内部页，PRD 未定义此页**：只承载草稿续做与本方台账，**不是 WS-328 我的控制台**。号段取 90 段是为了避让 `P-LS-04/05/06`（WS-325）、`P-LS-07/08`（WS-326）、`P-LS-09/10`（WS-327）。
4. **四环节的当前环节由前端按状态推导**，真实实现必须改为取服务端返回的当前环节与 `available_actions`（`AC-LS-87` 明令前端不得自行推断）。原型里这是演示便利，代码注释已标。
5. gas 预估为虚构值；链上超时 30 分钟为 PRD 标注的假设值，均待开发确认。
6. **`AC-LS-27` 池快照**：原型自 v1.1 起已整块移除（含数据字段），PRD 主册 6.5.2 的条款仍在，两边不一致，待 PRD 侧作废。
7. **自动失效后摘要区显示什么，PRD 没写。** `FP-20260416-0007` 的第 2 笔需求已按 `AC-FIN-26` 标成 `Void / closed ／ 已失效／已关闭` + 原因 `自动失效 · 覆盖不足`，与"判定即失效"对齐；但页头摘要区仍显示 200,000.00 USD 的需求金额（它是最后一次发布的金额，不是一笔还能被报价的要约）。这会让人以为还能报价——**建议 PRD 补一句"需求终结后摘要区金额如何呈现"**，在那之前原型保持现状并靠状态标签消歧。

**数据诚实性**：全部业务数据为演示数据，企业名带「（演示）／(demo)」后缀，编号 / 金额 / 哈希均为虚构。派生量由事件流按 PRD 公式算出，可在每张图的数据表里逐时点核对。
