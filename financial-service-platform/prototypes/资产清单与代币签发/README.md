## 1. 它是什么

**它直接就是运营端控制台本身**，不是评审脚手架：真实的左侧导航、真实的页面切换与深链、真实的面包屑。没有演示导航菜单、没有浮层演示控制台、没有把页面摆在画布上挑选的壳。顶栏右侧的三个开关（权限视图 / 链上回执情景 / 演示时钟）沿用兄弟模块「代币合约」把演示开关放顶栏的做法；页面标题下的「原型 · 状态」条是公共运行时 `shell.js` 自带的状态切换条，不是本模块另加的。

设计基线沿用仓库既有设计系统，不另起一套 token（详见第 7 节）。

## 4. 建议评审路径

1. **缺汇率闭环（L-01～L-04）**：汇总条点「需处理 N 笔」→ KYD 行的「去配置汇率」→ 表单币种已预填 **KYD 且不可改** → 填 `1.200000` 与来源说明 → 下一步看「当前值 → 新值」对照与影响面 → 确认 → 顶部提示条消失 → 点「返回资产清单」，**原异常筛选与分页仍在** → 该行点「重试」。
2. **两个动作不是同一个按钮**：`S-TI-5` 行只有「查询链上状态」、**没有重试**；把顶栏「回执情景」切到「提交失败」再查询，结果为「未上链」，**此时才出现重试**。切到「回执超时」时查询失败，状态**保持 `S-TI-5` 不变**。
3. **两笔链上交易（红线 AC-TI-60）**：任一已签发资产的详情页，① 链上存证凭证（资产平台 · 收单之前）与 ② 代币与铸造凭证（运营端 · 签发时）是两张分开的卡片，各带序号与左侧色带；哈希字段分别叫「**存证**交易哈希」「**铸造**交易哈希」，页面任何位置都不出现无限定词的「交易哈希」。
4. **换算过程**：`AR-20260909-0003`（HKD 1,234.56 × 0.127838）演示有截断的情形，截断值 `0.003681 USD` 显式展示；`AR-20260908-0002` 演示无截断；`AR-20260910-0006`（NGN 5.00）演示换算后 < 0.01 USD 落 `S-TI-6`，详情页仍展示完整换算过程与截断值。
5. **批量只在兜底重试**：汇总条切「全部」→ 点「签发失败」→ 表头全选（213 笔）→「批量重试」→ 确认弹层展示条数、按币种分组金额、缺汇率条数，并因**超过 200 条**禁用提交。取消部分勾选后提交，逐条结果面板区分已提交 / 失败 / 被跳过。
6. **自动签发与补扫（AC-TI-26）**：配好 KYD 汇率后点顶栏「＋10 分」，**校验类** `S-TI-4`（缺汇率）与滞留的 `S-TI-1` 被自动重发；**链上类** `S-TI-4` 与 `S-TI-5` 三轮都不动。
7. **汇率不可追溯**：已生效行点汇率值会给「新增一个更晚生效版本」的引导，而不是只把按钮禁掉；停用 CNY 的二次确认展示实时影响面；停用后回到任一已签发资产的详情页，换算快照**一个字不变**。
8. **代币清单单向动线**：代币管理 → 代币清单 → 「查看对应资产」精确定位并高亮 → 「返回代币清单」保留筛选与分页；资产侧没有「查看对应代币」的反向入口。
9. **【V1.2】代币详情与逐层返回**：代币清单某行「查看代币详情」→ 概览区看 logo、代币编号、代币状态（旁边小字给出判定依据）与融资质押状态 → 「前往资产清单」精确定位 → 「返回代币详情」→ 「返回代币清单」，**每一层都保留状态**，代币清单的筛选与分页原样还在。
10. **【V1.2】两根轴分两列**：代币状态可筛选（切「失效」只剩 `TK20260820000001` 一行；切「已销毁」为空）；**融资质押状态没有筛选器**——它恒为单一取值，给筛选等于暗示这里能筛出已质押的代币。
11. **【V1.2】logo 兜底**：代币清单或代币详情切到「logo 配置未下发」状态，24×24 / 48×48 都变成**首字母块**（`R`），不是破图、不是通用占位图；页面其他内容不受影响。
12. **权限**：顶栏切五种权限视图，观察行内动作**不渲染**（不灰化）与「去配置汇率」**置灰并说明原因**（不隐藏）这两种不同处理。

## 4b. 【V1.2】代币详情与资产详情的职责边界

这是本轮最容易画错的地方，因此在实现上按「页面上真的没有」来交付，而不是在页面上写一句「本页不含 XX」——后者会把不该出现在代币侧的词又搬回代币侧。

| | 代币详情 `P-O-TI-02` | 资产详情 `P-O-DS-02` |
| --- | --- | --- |
| 回答什么 | 这枚代币是什么 | 它背后那笔债权是什么、为什么是这个数 |
| 有什么 | 代币 logo、代币编号、名称/符号、铸造数量、所属合约（完整地址可复制）、所属链、实际收币地址、**代币状态**（带判定依据）、**融资质押状态**、**铸造**交易哈希、铸造时间、本笔铸造的链上结果 | 应收金额与币种、到期日、资产方、链上存证凭证、代币与铸造凭证、换算过程、签发时间线、签发状态与拦截原因、数币地址 |
| 没有什么 | 资产属性一条不放；签发过程一条不放；**不出现链上存证凭证** | 不提供任何指向代币侧的入口 |
| 怎么去对方 | 页内唯一跳出口「前往资产清单」，精确定位后再进资产详情 | 不去 |

代币状态的判定依据以小字写在标签旁（「对应应收账款已于 2026-09-05 到期」），让运营人员对外应答时不用查文档——这句是 PRD 10.7 要求的，不是把「到期日」这个资产字段搬了过来。

## 9. 假设与限制

- **全部数据均为演示数据**，页面顶部有「演示数据」标记。企业名带「（演示）」后缀；地址与哈希是格式合法的示意值，不对应任何真实链上交易；汇率值仅用于说明计算口径，不是业务定值。
- **后端、链上与定时行为全部是前端模拟**：回执缩短为秒级，补扫由顶栏「演示时钟」手动推进，没有真实调度。修改只保留在内存，刷新即重置。真实的持久化、并发唯一约束、重启恢复、服务端权限与性能须开发接入后验证。
- **区块浏览器映射表本期为空表**，两处跳转入口均置灰并写明原因，凭证照常展示（与 `AC-TI-61` 同口径）。不伪造真实浏览器 URL。
- 合约按已部署、`decimals ≥ 2` 处理（简报 Q-F 定值）。若开发确认为 `0`，只改「保留位数」一行，页面结构不变。
- `D-TI-19` 被截断部分最多 6 位小数：`1,234.56 × 0.127838` 的完整未截断结果是 `157.82368128`，截断部分完整值 `0.00368128`，按 6 位小数（向下截断）展示为 `0.003681`，与 PRD 13.3 一致。
- **汇总条的「当日 / 全部」只切换统计的时间口径（按收单时间），不过滤下方列表**——这是 PRD 9.3 的口径（汇总条是统计，不是筛选）。页面上已写明这一点。
- 列表里额外生成了 210 条 09-02 收单的演示记录，用于让分页与「单次最多 200 条」这条验收项真的走得到。它们的收单日不是当日，因此不进入默认的当日汇总口径。
- 业务页中文完整，公共壳层保留双语入口，英文文案未逐句打磨。
- **【V1.2】logo 的「有配置 / 缺配置」两种形态用页面状态切换来展示，不是同时摆在数据里**。PRD 9.11 写明本期只有一个合约、因此全平台只有一个 logo，两种形态在数据上不可能并存；伪造第二个合约会与「所属合约本期恒为应收账款铸币合约」冲突。切到「logo 配置未下发」即可看到首字母块兜底。
- **【V1.2】代币状态的「已销毁」与融资质押状态的「已质押」在演示数据里刻意构造不出**（`AC-TI-78`）：前者需资产方发起销毁后链上回流，后者本期没有质押流程。筛选「已销毁」返回空结果是正确行为，不是缺数据。
- **【V1.2】代币编号在原型里也只用于展示与检索**：重复触发与重试的判重仍然只看来源资产 ID，与 `AC-TI-70` 一致。
- **【V1.2】代币清单 11 列在 1150px 左右的内容区里必然要横向滚动**（`.tablewrap` 内部滚动，页面本身不溢出，操作列 sticky 保持可达，这是仓库 `.tbl.wide` 的既定行为）。列序按「身份 → 两根状态轴 → 链上细节 → 操作」排，让「这枚代币还算不算数、有没有被质押」落在首屏可见处；**PRD 9.7 的字段表是字段清单不是渲染顺序，列一个不少、名称一个不改**。
- **已知的既有系统问题（不在本模块修）**：侧栏底部的画布标签对运营端显示为「管理端」——`brand-sub` 取自公共层 `end:'admin'` 的文案，四个兄弟模块表现一致。改它会动到资产平台真正的管理端，属平台级改动，此处只记录不修改。
