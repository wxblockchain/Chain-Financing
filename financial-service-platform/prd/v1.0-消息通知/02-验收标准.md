# 金融服务平台 · 运营端 · 消息通知 PRD · 02 验收标准

> 本文件是《金融服务平台 · 运营端 · 消息通知 PRD》的分册。
> 入口与全文导航见主文档 [`v1.0-消息通知-PRD.md`](./v1.0-消息通知-PRD.md)。

**本文件讲什么**：运营端消息通知的全部验收条目 **AC-O01～AC-O96**，按入口与角标、列表筛选与分页、详情与已读、跳转与失效、权限与消息池隔离、会话与登录态、非功能可访问性与监控、平台通用性与边界、对齐已实现原型的补充项**九组**组织。

**本文件不讲什么**：每条验收对应的规则本身。规则在 [`v1.0-消息通知-PRD.md`](./v1.0-消息通知-PRD.md) 与 [`01-页面与展示.md`](./01-页面与展示.md) 中；数据契约的规则在 WS-304 [`02-数据契约与字段.md`](../../../asset-platform/prd/v1.0-消息通知/02-数据契约与字段.md)。**本文件只列判定口径。**

**三条使用说明：**

1. **`AC-O*` 编号仅本文档内唯一**，是运营端自起的一套，**与 WS-304 的 `AC-N*` 无对应关系**，不要按序号互相映射。
2. **本文件不验收任何触发口径**——不会出现「某某操作后应发某某消息」这类条目。运营端有哪些消息、什么时点发、文案怎么写，由各业务 issue 在自己的 PRD 里验收。
3. **本文件不重复验收数据契约本身**（字段必填性、`dedupe_key` 构造、`biz_type` 命名规范等由 WS-304 `03-验收标准.md` 覆盖）。这里只验收**契约在运营端的落地结果**。

## 16. 验收标准

### 16.1 入口与角标（F-O01～F-O05）

| # | 验收项 |
| --- | --- |
| AC-O01 | 已登录运营端**任意页面**，顶部导航栏均展示通知铃铛 C-O20，位置固定；未登录页面不展示铃铛 |
| AC-O02 | 铃铛位于**语言切换器左侧、账号下拉之前**；若运营端不提供语言切换器，则位于**顶栏右侧、账号下拉之前**——两种情况下位置都必须固定且可预期 |
| AC-O03 | 无未读时铃铛不展示角标，**也不展示 `0`** |
| AC-O04 | 有未读时角标数与服务端未读数一致；未读数超过 99 时展示 `99+`，且 `99+` 状态下不展示精确数字 |
| AC-O05 | **已过期的未读消息不计入角标**，但仍能在列表中看到并带「已过期」标签 |
| AC-O06 | 「目标资源已删除 / 状态已流转 / 无权限」三类跳转失效的未读消息**仍然计入角标**（这三类是预检的实时结果，不做全量预检） |
| AC-O07 | 账号下拉内存在「消息中心」条目，点击**直达 P-O20**（不经快捷面板、不带筛选条件）；若运营端顶栏无账号下拉，该入口取消，消息中心仍可从铃铛面板底部「查看全部」到达 |
| AC-O08 | 点击铃铛展开快捷面板 C-O21，展示最近 **10 条（含已读）**；再次点击铃铛、点击面板外区域、按 Esc 均可收起 |
| AC-O09 | 快捷面板**仅展开不产生任何已读**；滚动经过也不产生已读；点击面板内某条进入详情后该条才变已读 |
| AC-O10 | 页面切到后台时未读数轮询**暂停**；切回前台**立即拉取一次**并重置轮询计时器；未读数接口失败时角标**保留上一次数值**，不清零、不弹错误提示 |

### 16.2 列表、筛选与分页（F-O06～F-O09）

| # | 验收项 |
| --- | --- |
| AC-O11 | 分类筛选项由服务端返回的分类元数据渲染，**前端代码中不存在写死的分类清单** |
| AC-O12 | **只渲染当前运营管理员实际拥有消息的分类**，不展示会必然为空的筛选项 |
| AC-O13 | 分类筛选与已读/未读筛选**可叠加**，结果为两者的与关系；状态筛选三档为 全部 / 未读 / 已读，默认「全部」 |
| AC-O14 | 筛选条件**写入 URL 查询参数**，刷新后筛选态保持；切换筛选时回到第 1 页且滚动位置回到顶部 |
| AC-O15 | 列表按**创建时间倒序**；标记某条已读后该行**位置不变、不被移除**（未读不置顶、已读不沉底） |
| AC-O16 | 同一创建时间戳的多条消息以消息 ID 作稳定次级排序键，翻页时**不重复、不漏项** |
| AC-O17 | 列表分页形态为**分页器**（页码 + 每页条数），**不是「加载更多」**；每页条数默认 20，可切换 **20 / 50 / 100** |
| AC-O18 | 分页游标基于 `created_at + message_id`，**不使用 offset**；翻页期间有新消息插入顶部时不出现重复项或漏项 |
| AC-O19 | **首次空态与筛选空态文案不同**，且筛选空态提供「清除筛选」并可一键回到无筛选状态 |
| AC-O20 | 首屏失败展示错误态与重试；**翻页失败时当前页已加载内容不清空**，可重试 |
| AC-O21 | 单条消息内容异常（如文案模板 key 缺失）时该行降级为「标题 + 时间」最小形态，**不影响同页其他行**，且仍可点击进入详情 |

### 16.3 详情与已读（F-O10～F-O13）

| # | 验收项 |
| --- | --- |
| AC-O22 | 消息详情为**整页 + 独立路由**，支持深链直接打开；不使用抽屉或弹窗 |
| AC-O23 | 详情页时间**一律绝对时间 + 时区标注**，不使用相对时间；列表时间为 24 小时内相对时间、超过则绝对时间 |
| AC-O24 | 详情正文按**纯文本渲染并转义**；提交含 HTML 标签的正文或参数时，页面上原样显示为文本，**不被解析执行** |
| AC-O25 | 已读标记在**详情内容请求成功并渲染之后**才发起；详情加载失败时**不产生任何已读记录** |
| AC-O26 | 已读请求失败时**不阻断详情阅读**、不弹错误；重复标记同一条消息不报错，**首次已读时间不被覆盖** |
| AC-O27 | 列表行悬浮出现「标为已读」按钮，点击后**不进入详情**即就地标记；已读项不再展示该按钮 |
| AC-O28 | 界面上**不存在**「标为未读」的手动操作入口 |
| AC-O29 | 从详情返回列表（面包屑上级 / 「返回列表」/ 浏览器后退，三者行为一致）后，**保留筛选条件、页码、每页条数与滚动位置**，不跳回第 1 页 |
| AC-O30 | 返回列表后刚读过的那条**就地变为已读样式**，不重排、不移除；在「只看未读」筛选下该条**仍留在列表中**显示为已读样式，直到主动刷新或切换筛选才消失 |
| AC-O31 | 「全部标为已读」作用于**当前筛选命中的全部消息**：当前页显示 20 条、实际命中 300 条时，执行后 300 条全部变已读，**不是只标记当前页** |
| AC-O32 | 「全部标为已读」**必须二次确认**，弹窗内**明确展示条数**；存在筛选条件时**追加一行说明当前筛选**；弹窗默认焦点在「取消」上 |
| AC-O33 | 「全部标为已读」失败时**列表与角标不做任何变更**（不做乐观更新），可重试；当前筛选下无未读时按钮禁用并 tooltip 说明 |

### 16.4 跳转与失效（F-O14、F-O15）

| # | 验收项 |
| --- | --- |
| AC-O34 | 消息实体中**不存放任何 URL**；跳转路径由前端在展示时按 `biz_type` 或 `page_target` 解析得到 |
| AC-O35 | 三种跳转形态**互斥**：同时携带 `biz_ref` 与 `page_target` 的消息被**服务端拒收** |
| AC-O36 | **「无跳转」是合法状态**：既无 `biz_ref` 也无 `page_target` 的消息正常展示，详情页不渲染跳转按钮，**且不展示任何说明文案**。与 AC-O37 的映射缺失**界面表现完全一致**——两者的差别只在后台是否上报日志 |
| AC-O37 | **映射缺失**（携带 `biz_type` 但前端登记表无对应条目）时：详情页**不渲染跳转按钮**、**不展示任何说明文案**（操作区只剩「返回列表」），并上报一次「未知业务类型」日志；消息在列表与面板中**正常展示、可进详情、不被分类筛选过滤掉** |
| AC-O38 | 映射缺失时**不出现**以下任何一种：跳 404 页、跳首页、展示点了没反应的按钮、隐藏整条消息 |
| AC-O39 | `page_target` 形态**不做预检**，直接跳转；`biz_ref` 形态是否预检由业务类型登记表声明，默认「需要预检」 |
| AC-O40 | 预检在**进入详情页时执行一次**（不是点击时才执行）；**列表页不做任何预检** |
| AC-O41 | 预检接口本身失败或超时（3 秒）时**放行跳转**，按钮保持可用，由目标页自行处理 |
| AC-O42 | 四类失效各有**独立文案**（不使用一句笼统的「该消息已失效」）；`expired` 的跳转按钮**不渲染**，其余三类**按钮禁用而非隐藏**并带 hover tooltip 说明原因 |
| AC-O43 | 四类失效下消息的**标题、正文、时间均完整展示**，消息不被删除、不被隐藏；失效说明条 C-O23 为浅底信息条、不可关闭、**不使用错误红色** |

### 16.5 权限与消息池隔离（F-O16、F-O17，**强制条款**）

| # | 验收项 |
| --- | --- |
| AC-O44 | 列表接口**忽略请求参数中任何形式的接收者标识与 `end` 参数**，只按会话身份 + `end = fs_ops` 返回消息 |
| AC-O45 | 运营端接口**只返回 `end = fs_ops` 的消息**；构造请求尝试取回 `asset` / `admin` / `fs` 池的消息均不成功，**四端不串池** |
| AC-O46 | 用他人个人消息（`admin_account`）的 ID 访问详情接口返回 **404 语义**，与「消息 ID 不存在」的返回**完全一致，无法区分** |
| AC-O47 | 用非 `fs_ops` 消息的 ID 访问运营端详情接口，同样返回 404 语义，且与上一条**不可区分** |
| AC-O48 | 用他人消息 ID 调用标记已读接口被拒绝，且**不产生任何已读记录** |
| AC-O49 | 全部已读接口**不接受前端传入的消息 ID 列表**，范围由服务端按会话身份 + `end = fs_ops` + 筛选条件圈定；传入 ID 列表时返回参数不合法 |
| AC-O50 | 跳转预检接口**同时校验**消息归属与目标资源的业务权限；消息不属于本人 → 404 语义，消息属于本人但目标无权 → 返回 `no_permission` 并走失效第 4 类 |
| AC-O51 | **运营管理员 A 读一条共享池消息后，B 的未读数不变**，该消息对 B 仍是未读且仍在列表中；A 执行「全部已读」同样不影响 B |
| AC-O52 | 个人消息（`admin_account`）**只对归属的那一个运营管理员可见**：其他运营管理员的列表中不出现该条，未读数不包含该条，直接访问其 ID 返回 404 语义 |
| AC-O53 | 新建的运营管理员账号首次登录时，其**创建时间之前**的历史消息**不计入未读**，但仍可在列表中查到 |
| AC-O54 | 界面上**不存在**「谁读过这条消息」的任何展示 |
| AC-O55 | 运营端界面**不存在**任何查看资产平台消息或金融服务端用户消息的入口 |
| AC-O56 | 消息 ID 为**不可枚举**的标识（非自增序号）；系统**不提供**「按 ID 列表批量取消息」的接口 |
| AC-O57 | 服务端**拒收** `page_target` 所属端与消息 `end` 不一致的消息；运营端消息的 `page_target` 只能取共享段位表中已登记的 `P-O*` 编号 |

### 16.6 会话与登录态

| # | 验收项 |
| --- | --- |
| AC-O58 | 未登录访问 `/ops/messages` 或 `/ops/messages/{id}` 时，跳 **`/ops/login?redirect=<原路径>`**，登录成功后回跳原页面；**不落到资产管理端登录页 `P-M01`** |
| AC-O59 | 未登录访问详情深链时，登录前页面**不泄漏任何消息内容，也不泄漏该消息是否存在** |
| AC-O60 | 深链登录成功后，若该消息不属于该账号，落到「消息不存在」页，**不提示「你登录了错误的账号」** |
| AC-O61 | 会话到期（2 小时）或 30 分钟无操作自动登出后，停留在消息模块内的页面按 WS-308 的统一会话失效处理：清除登录态、**中止进行中的请求（含未读数轮询）**、跳登录页并携带原路径 |
| AC-O62 | 「全部已读」执行中会话失效时**不展示「操作成功」**；重新登录后未读数**以服务端为准** |
| AC-O63 | 未读数轮询遇 401 时**触发统一的会话失效处理，不被静默忽略**（不出现「页面还在、角标还在刷、但登录态已没了」的假活状态） |
| AC-O64 | **未读数轮询不被计入「30 分钟无操作」的活跃度判定**：一个只开着消息中心、不做任何操作的标签页，在 30 分钟后仍会被自动登出 |

### 16.7 非功能、可访问性与监控

| # | 验收项 |
| --- | --- |
| AC-O65 | 列表接口与未读数接口的 P95 响应时间**在上线时即已接入监控**并可查询时间序列，不是等出现退化趋势后才补建（对应主文档 2.5.3） |
| AC-O66 | 性能目标值达成：未读数 P95 < 300ms、列表首屏 P95 < 1s（20 条）、面板展开 P95 < 800ms、详情 P95 < 800ms、全部已读 P95 < 2s（1000 条内）；**页面不可见时轮询开销为 0** |
| AC-O67 | 1280 / 1440 / 1920px 三个断点下无水平溢出，铃铛面板不被导航栏裁切；低于 1280px 时摘要可折行或省略，但**标题、分类标签与时间不得隐藏** |
| AC-O68 | 铃铛、面板内每条消息、列表项、行内「标为已读」、筛选器、分页器、跳转按钮**全部可 Tab 到达**并具备可见的 `focus-visible`；所有图标按钮具备 `aria-label` |
| AC-O69 | 铃铛面板展开后焦点进入面板，**Tab 循环限制在面板内**，Esc 关闭并把焦点还给铃铛；角标数值变化通过 `aria-live="polite"` 播报，不抢焦点 |
| AC-O70 | 未读状态**不以颜色为唯一提示**（同时使用圆点与字重），且对屏幕阅读器可感知；支持 `prefers-reduced-motion` |

### 16.8 平台通用性与边界

> 这一组验收的对象不是某个功能，而是**本模块的通用程度与边界是否守住**。判定方法：拿一个**未在本 PRD 中出现过的虚构运营端业务模块**（如「对账差异处理」）走一遍接入，看是否需要改动本模块。

| # | 验收项 |
| --- | --- |
| AC-O71 | 用一个**虚构的运营端业务模块**走通接入：登记 `biz_type` → 产出消息 → 列表展示 → 已读 → 跳转 → 失效降级，**全程不修改本模块的任何页面逻辑、数据模型与 PRD 条款** |
| AC-O72 | 新增一个 `category` 只需登记 + 研发加枚举值与中英文案 key，**不需要改动本模块任何页面逻辑**；本期无消息的分类**不出现在筛选器中**，不产生空筛选项 |
| AC-O73 | 未登记的 `biz_type` 消息仍被**接收、投递、展示与已读**，仅跳转按钮不渲染并记录告警——**不丢消息** |
| AC-O74 | 未读计数按「可见集 − 已读集」计算，对 `admin_all` 与 `admin_account` 两种已实现的 `recipient_scope` 结果正确；**新增一种 scope 时未读计数算法不需要改动** |
| AC-O75 | 已读状态为**独立实体，不预生成未读记录**：一条 `admin_all` 消息在 N 个运营管理员均未读时，已读表中该消息的记录数为 **0** |
| AC-O76 | 本 PRD 及其实现中**不存在**任何 WS-304 契约里没有的 `Message` 字段或枚举取值；运营端消息的 `end` 取值为 **`fs_ops`**，`asset` / `admin` 两个既有取值的语义与已登记条目**未被改动** |
| AC-O77 | `admin_all` 的既有语义**未被本模块改动**（资产管理端对该取值的行为与本模块上线前完全一致） |
| AC-O78 | 本 PRD 目录下**不存在**数据契约文件与接入指南文件；两者以显式引用的形式指向 WS-304 与 `docs/notification-contract/`，**仓库内不存在第二份**内容重复的接入指南或 `biz_type` 登记表 |
| AC-O79 | `P-O20`～`P-O21` 与 `C-O20`～`C-O23` 已登记进**共享的编号段位表**；本 PRD 内**不另维护**一张段位表；这六个编号在全平台不与任何其他编号重复 |
| AC-O80 | 本模块的任何接口、任务与告警**不产生任何邮件 / 短信投递行为**，也不记录站外渠道的送达结果；消息负载中携带渠道类字段时被**忽略**，不影响该条站内消息的正常投递与展示 |
| AC-O81 | 运营端**不产生**带 `progress` 结构的消息，界面上不出现「业务办理进度」类展示；但该分类、`progress` 字段与进度型组件变体**在契约与代码中仍然存在**，未被删除 |
| AC-O82 | 本模块**不提供**任何消息发布 / 人群圈选 / 公告编辑的界面；`broadcast` 本期不实现，但契约中的 `broadcast` 取值、`visible_from` 与 `subscribable` 字段位**保留未删** |
| AC-O83 | 运营端左侧菜单中**不存在**「消息中心」一级入口 |
