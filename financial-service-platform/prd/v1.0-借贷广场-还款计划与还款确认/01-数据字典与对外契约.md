### 6.6.1 还款计划表（两版共用一套结构；出现在 `P-LS-06` 接受抽屉 / 还款计划查看抽屉 / `P-LS-09` 还款抽屉 / 控制台）

| 区 | 建议结构 |
| --- | --- |
| 表头：**版本标识** | **初始版**：整表带「**预计 · 未生效**」中性标识 + 表下常驻一句"实际还款日将在放款确认后按实际放款日重算并定稿"（`D-RP-06`）。**定稿版**：带「已定稿」标识 + 定稿时间 + 计息规则全文（`RP-18`） |
| 表体：**每期一行** | 期次序号 → **应还日**（初始版列名为「**预计还款日**」）→ **计息区间与天数**（`起 ~ 止`，`N 天`）→ 本期应还本金 → 本期应还利息 → **本期应还合计（USD）** → 结算金额（`QT-02` 币种）→ 期次状态 → **逾期标记与逾期天数**（若有）。**末期行须显式标注"含本金 · 到期还本付息"**，并在计息天数旁标注末期并期规则（`D-RP-14`），避免资产方以为金额算错 |
| 表尾：**合计** | **只给 USD 口径的合计**（应还本金合计、应还利息合计、应还合计）；**结算币种金额不参与任何合计**（`D-RP-40`）。多笔业务的汇总视图同样只给 USD |
| 常驻：**计息规则** | 定稿版必须常驻一行可读的规则全文：「年化单利，实际天数 ÷ 360，起息日计息、应还日不计息；起息日 = {实际放款日}」（`RP-18`、`AC-RP-04`） |
| 常驻：**利率** | 利率展示**始终带"年化"二字**（`D-RP-16`/`AC-RP-04`），不得只写一个百分数 |

### 6.6.2 `P-LS-09` 还款录入（资产方，**右侧抽屉 760px**）

| 区 | 建议结构 |
| --- | --- |
| 顶部：**期次选择器** | 默认选中「最近一笔应还」（`D-RP-21`～`D-RP-24`）。下拉**分两组**：上组「**已逾期**」（带「已逾期 N 天」中性标记），下组「**待还款**」；组内按应还日升序、同日按放款日升序（`D-RP-22`）。**未开窗的期次可见但 `⊘`**，附"该期还款入口将于 {日期} 开启；本期不支持提前还款"（`D-RP-26`）。**不存在多选、不存在"全选"、不存在"提前结清"入口**（`AC-RP-07`） |
| 第一区：**本期计划信息（只读）** | 融资业务编号、还款计划编号、期次序号、应还日、计息区间与天数、本息拆分、应还合计（USD）与结算金额、还款方式（只读文本）、还款类型（系统派生）；若已逾期：**逾期天数 + 一句"提交还款记录后逾期天数即冻结"**（`D-FIN-11` 的界面侧告知） |
| 第二区：**机构收款账户（只读带出）** | 法币：户名 / 账号 / SWIFT / 开户行 / **中转行**（取 WS-326 `LN-15`）；数币：地址（取 `LN-16`，资金方绑定钱包），**链为常量 `ETH` 只展示**。按 WS-308 脱敏基线展示。**字段旁常驻"该账户为资金方放款时登记的还款收款账户，不可在此修改"**（`D-FIN-24`；来源改锚见主册 1.3） |
| 第三区：**还款表单** | 币种（只读）→ 金额（只读）→ 还款时间（可填，**不得晚于提交时刻**，旁注"仅作对账参考，时效与计息不使用该时间"）→ 法币：**银行支付凭证**上传（PDF/JPG/PNG，单文件 ≤ 10 MB，1～5 个）/ 数币：交易哈希（**链为常量 `ETH`、只展示不给选择控件**，`RM-09`）+ 补充材料（选填 ≤ 5 个）→ 还款备注（选填 ≤ 200 字）→「提交还款记录」→ 二次确认弹窗 |
| 页脚 | "本步骤不产生任何链上操作、不消耗 gas"——避免资产方误以为平台会代为发起转账 |

## 6.7 异常分支与边界

| # | 异常 | 处理 |
| --- | --- | --- |
| `E-RP-01` | **放款确认完成但还款计划生成失败** | **不得回滚** WS-326 的额度转移与状态迁移（承接 `E-LN-13`）：钱已到账、债务已成立是事实。业务详情展示"还款计划生成中"，**不展示错误**；生成动作可重试且**必须幂等**——重试不得产生第二套期次 |
| `E-RP-02` | **两个员工并发提交同一期次的还款** | 串行结算，先落库者成功；后到者提示"该期已提交还款记录"并落详情页，**不产生第二条记录**（`D-RP-44`） |
| `E-RP-03` | **提交时该期次尚未开窗**（前端绕过或页面停留过久） | 服务端终检拒绝，返回该期的开启日期与"本期不支持提前还款"；**不产生还款记录、不改状态**（`D-RP-26`/6.2.2 第 5 条） |
| `E-RP-04` | **交易哈希格式不合法** | 就地提示格式要求（`0x` + 64 位十六进制），**不得提示"该交易不存在"**——平台没有这个判断能力（`D-FIN-22`） |
| ~~`E-RP-05`~~（**V3.1：本期不可达**） | ~~填写的链与机构数币收款地址的链不一致~~ | **本期不可达**：链是常量 `ETH`、用户无从选择，这个异常造不出来（WS-326 `D-LN-62` 同一处置）。**条文保留不删**——多链恢复时原样回来（拒绝提交并说明，不提供"仍要继续"）；**本期下游不得为它准备文案与分支，验收清单里标注即可** |
| `E-RP-06` | **支付凭证上传失败 / 超出格式或大小限制** | 就地提示具体原因（格式 / 大小 / 数量），已上传的其他文件保留（沿用 `E-LN-06`） |
| `E-RP-07` | **还款时间晚于提交时刻** | 拒绝提交并说明。**时间可以填过去，不能填未来**——未来的还款时间意味着钱还没打 |
| `E-RP-08` | **提交时该期次已不在 `S-RP-1`**（例如同事刚提交过） | 按提交时刻的权威状态结算并拒绝；落详情页 + Toast 说明，**不报错、不白屏**（承接 `H-02` 三条边界） |
| `E-RP-09` | **确认的同一时刻该期次已不在 `S-RP-2`** | 本期不存在合法的并发路径（`S-RP-2` 段只有机构一个写动作），若发生则视为数据异常：按权威状态结算、落详情页 + Toast，并生成运营告警 |
| `E-RP-10` | **逾期判定任务延迟执行** | **逾期的效力以应还日次日 00:00 为准，不以任务实际执行时刻为准**：补跑时按应到时刻回算逾期天数。**补跑必须幂等**：同一期次重复判定只产生一条通知、一个标记 |
| `E-RP-11` | **确认的结算部分失败**（期次已结清、额度未减，或反之） | 该结算必须**整体成功或整体不发生**；落库失败时保持 `S-RP-2` 并重试，**禁止出现"已确认但额度未减"或"末期已结清但业务仍显示还款中"**。重试期间对外仍按未确认呈现（`AC-RP-13`） |
| `E-RP-12` | **还款确认时限届满的判定任务延迟执行** | 同 `E-LN-12`：效力以 `RM-15` 为准，补跑幂等，同一期次只产生一条通知、一个标记 |
| `E-RP-13` | **资产方声称已还、机构声称未收到** | 本期无异议入口（`X-LS-42`）：走客服邮箱线下核实（主册 6.5.3）。**不得引导机构"先确认再说"**——确认不可撤销且会释放授信额度；**同样不得因此解冻资产方的逾期天数**（`D-FIN-11`） |
| `E-RP-14` | **机构因跨境手续费导致实收少于应还而拒绝确认** | 本期无差额说明字段（金额只读，主册 6.3.1）：走客服邮箱线下核实。**平台不判定谁对谁错**；资产方的逾期天数保持冻结（`R-LS-46`） |

**留下这八条的理由**：

| 事件 | 收件人拿到它要做什么 |
| --- | --- |
| `plan_ready` | 资产方要知道自己的付息节奏从这一刻起被确定了，**尤其是日期与期数相对报价期发生了变化**——正文必须带新旧对比（`D-RP-07`）。**资金方不发**：WS-326 的 `financing.deal.confirmed` 已经告诉它"还款计划已生成、去看还款安排"，重复推等于同一件事说两遍 |

| `confirm_overdue` | **本期唯一能把当事人拉回线下沟通的触达**（`R-LS-45`）。双方各一条：资金方要么去确认要么去发邮件，**资产方要知道自己被拖着、同时知道自己的逾期天数已经冻结**（正文必须写明这一点） |
| `confirmed` | 资产方的这一期义务正式了结。**这是他唯一能确认"钱对方认下来了"的凭据** |
| `settled` | 双方都要知道这笔业务结清了：资产方要去看质押能不能提取（**跳转正文须引导至 WS-324 的提取入口，`AC-LS-38`**），资金方的授信额度已经回来了、可以去做下一笔 |
