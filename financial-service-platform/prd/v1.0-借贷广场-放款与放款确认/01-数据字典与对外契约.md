## 6.5 承载单元规格（做事走**右侧抽屉 760px**、提示走**居中弹窗 560px**）

> 本节是主册第 6 章的一部分，因读者是设计与测试而随本册交付。业务口径以主册 6.1～6.4 为准。只给线框级信息架构建议，不产出视觉稿。
>
> **形态（主册 4.5，`D-LN-48`）**：`P-LS-07`／`P-LS-08` 不是独立页面，而是**详情页操作区「融资放款」环节内的两个右侧抽屉（760px）**，操作不跳离详情页（WS-324 `D-FIN-79`/`AC-LS-85`）。**编号保留、字段与校验原样成立**，下表的"区"是抽屉内的分区；内容较长时**在抽屉内滚动**，不得拆成多页或跳转新页。
> **提示类是居中弹窗 560px**（三处二次确认），出现时其下方含抽屉内容整体被遮罩、不可交互，**同一时刻只有一层**（`D-LN-54`）。
> **抽屉宽度不分档**（需求方 09-15 裁定 1）：三个承载单元一律 760px，与 WS-325 保持同一个数，**不按职责给不同宽度**（`D-LN-57`）。

### 6.5.1 `P-LS-07` 放款抽屉（资金方，760px，含核验区与三个处置动作）

| 区 | 建议结构 |
| --- | --- |
| 顶部：业务摘要 | **需求编号 `FP-28`**（`D-LN-49`）、融资业务编号、资产方企业主体、融资项目编号、融资金额（USD）与结算金额、年化利率、接受时间；**当前质押覆盖状态与覆盖缺口**（若处于覆盖不足，`D-FIN-56`）；项目若带「已到期 · 存量处理中」标记，**中性呈现**（`D-FIN-47`） |

## 6.6 异常分支与边界

| # | 异常 | 处理 |
| --- | --- | --- |
| `E-LN-01` | **提交放款的瞬间质押覆盖跌破 `INV-FIN-01`** | 服务端终检拒绝，返回当前质押覆盖状态、缺口与追加指引；**不产生放款记录、不改状态**。机构可改走「暂不放款」或「终止业务」 |
| `E-LN-02` | **两个员工并发提交同一笔业务的放款** | 串行结算，先落库者成功；后到者提示"该业务已提交放款记录"并落详情页，**不产生第二条记录**（`D-LN-29`） |
| `E-LN-03` | **提交放款时业务已不在 `S-FD-3`**（例如同事刚终止了它） | 按提交时刻的权威状态结算并拒绝；落详情页 + Toast 说明，**不报错、不白屏**（承接 `H-02` 三条边界） |
| `E-LN-04` | **交易哈希格式不合法** | 就地提示格式要求（`0x` + 64 位十六进制），**不得提示"该交易不存在"**——平台没有这个判断能力（`D-FIN-22`） |
| `E-LN-05` | **填写的链与资产方数币收款地址 `FD-06` 的链不一致** | 拒绝提交并说明"链须与报价时约定的一致"，**不提供"仍要继续"**。钱打到另一条链不是这笔业务约定的交付方式 |
| `E-LN-06` | **转账凭证上传失败 / 超出格式或大小限制** | 就地提示具体原因（格式 / 大小 / 数量），已上传的其他文件保留（沿用 `E-CR-09`） |
| `E-LN-07` | **发放时间晚于提交时刻** | 拒绝提交并说明。**时间可以填过去，不能填未来**——未来的发放时间意味着钱还没打，那就不该提交放款记录 |
| `E-LN-08` | **资产方在「待重传」标记下重复上传** | 允许，每次都是新版本、历史保留（`D-LN-23`）；标记在第一次成功上传时即清除，后续上传不再重复清除、不产生第二条通知 |
| `E-LN-09` | **机构点终止的同一时刻资产方正在重传** | 以**服务端落库时刻**为准并串行结算：终止先落库则重传返回"该业务已终止"并落详情页；重传先落库则终止照常执行（重传不构成对终止的阻断）。**任何情况下额度只释放一次** |
| `E-LN-10` | **确认到账的同一时刻业务已不在 `S-FD-4`** | 本期不存在合法的并发路径（`S-FD-4` 段无其他写动作），若发生则视为数据异常：按权威状态结算、落详情页 + Toast，并生成运营告警 |
| `E-LN-11` | **放款确认的结算部分失败**（状态已改、额度未转，或反之） | 该结算必须**整体成功或整体不发生**；落库失败时保持 `S-FD-4` 并重试，**禁止出现"已确认但额度未转"或"额度已转但还款计划没生成"**。重试期间对外仍按未确认呈现（`AC-LN-10`） |
| `E-LN-12` | **确认时限届满的判定任务延迟执行** | **超期的效力以到期时刻为准，不以任务实际执行时刻为准**：补跑时按到期时刻记录 `FD-36`。延迟期间页面倒计时已归零，此时页面即按超期呈现（前端按服务端给的到期时刻判断）。**补跑必须幂等**：同一笔业务重复判定只产生一条通知、一个标记 |
| `E-LN-13` | **确认完成时 WS-327 尚未就绪、还款计划生成失败** | **额度转移与状态迁移不得因此回滚**（钱已到账、债务已成立是事实）；还款计划改为可重试的后续动作，业务详情页在计划就绪前展示"还款计划生成中"，**不展示错误**。该缺口登记为 `DEP-37` |

## 6.7 深链契约增量（**照 `AC-LS-07` 消费，不新开一套跳转约定**）

`H-01`～`H-05` 已由 WS-324 分册 6.6 定稿并对本模块生效。本模块**不新增契约条款**，只补 `available_actions` 取值与锚点。

### 6.7.1 新增锚点（**语义：落详情页 + 打开对应抽屉**）

> 承载形态是抽屉（主册 4.5），锚点**不指向独立页面**：一律落到该融资项目的详情页，并自动打开操作区「融资放款」环节内的对应**右侧抽屉**；关闭抽屉即停留在详情页，**不返回、不跳走**。`H-02` 的三条落地边界不变。

| 锚点 | 落到哪里 | 谁可用 |
| --- | --- | --- |
| `deal/{id}?action=disburse` | 详情页 + 打开 `P-LS-07` 放款抽屉（**含核验区与三个处置动作**） | 该笔业务的资金方 |
| `deal/{id}?action=confirm_disbursement` | 详情页 + 打开 `P-LS-08` 确认到账抽屉 | 该项目的资产方 |
| `deal/{id}?action=reupload_contract` | 详情页 + 打开**盖章件重传抽屉** | 该项目的资产方，且 `FD-31 = true` |

| 编号 | 条款 |
| --- | --- |
| `D-LN-39` | **三个处置动作不各占一个锚点。** 它们是放款流程内的分支（同 `D-LS-15` 对"去授信"的处置）：给每个动作一个独立锚点等于把"核验"做成一个独立环节，而它本就不是一个状态（`D-LN-01`），也没有独立的待办来源。**服务端在返回 `disburse` 时一并给出当前的两个标记（`FD-31`/`FD-32`）与覆盖闸门结论**，页面据此渲染 |
| `D-LN-40` | **不新增 `disbursement/{id}` 这一层锚点**（同 `H-02` 对 `demand/{id}` 的处置）：放款记录没有需要被深链直达的独立页面，它永远在融资业务详情里呈现 |

### 6.7.2 新增 `available_actions` 取值

| 取值 | 含义 | 出现条件 | 不满足时 |
| --- | --- | --- | --- |
| `disburse` | 去放款（含核验与三个处置动作） | 业务 `S-FD-3` 且当前用户为该笔业务的资金方 | 业务已离开 `S-FD-3` 时不返回。**覆盖不足时照常返回**，但其中的"提交放款"以 `⊘` + 缺口原因呈现、三个处置动作可用（`AC-LN-08`） |

### 10.4 消息事件登记（需求方 08:17 裁定 7：**走 WS-329，只在核心环节，信息不宜过多**）

> 接入指南（`docs/notification-contract/接入指南.md` 3.3 第 1 步）要求每个业务模块在自己的 PRD 里列出要用的 `biz_type` 全集。以下为本模块产生的事件，`end = fs`（金融服务端），一级域取已规划的 `financing`。**投递由 WS-329 承接**；投递未就绪时，同样的信息在页面上以状态、标记与倒计时呈现（**保底，不是替代**）。

**留下这六条的理由**：

| 事件 | 收件人拿到它要做什么 |
| --- | --- |
| `submitted` | 资产方要在 168 小时内确认。**不发这条，就是在跟一个不知道自己在倒计时的人计时** |
| `confirm_expiring` | 最后的提醒窗口。它是 168 小时时限的配套件——**到期不会自动确认，所以这条的价值不是催他别被作废，而是别让一笔已到账的钱悬着** |
| `confirm_overdue` | **本期唯一能把当事人拉回线下沟通的触达**（`R-LS-35`）。双方各一条：资产方要么去确认要么去发邮件，资金方要知道自己的钱还没被对方认下来 |
| `confirmed` | 资金方的债权正式成立、还款计划已生成，他要去看还款安排 |
| `reupload_required` | **资产方必须做一件他本来不会做的事**：回来重传盖章件。不发这条，业务会静静地卡在 `S-FD-3` |
