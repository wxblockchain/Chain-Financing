## 6.9 与面客消息中心（WS-329）的边界

**`B-1`～`B-5` 引用 WS-329 PRD 主文档 `3.3`，不重新讨论、不各写一版。** ⚠️ **V3.0：待办带撤除后 `B-4`/`B-5` 的前提变了**，本节给出控制台侧的处置与对 WS-329 的修订请求。

| # | 判据 | V3.0 后的状态 | 控制台侧落点 |
| --- | --- | --- | --- |
| `B-1` | 消息 = 告知，待办 = 当前状态 | **不受影响** | `D-MC-117` |
| `B-2` | 没有需要用户执行的动作，就不是待办 | **不受影响** | `D-MC-118` |
| `B-3` | 待办由业务状态派生、不落库，不需要「已办归档」 | **不受影响**——判据仍然派生，只是呈现在行上 | `D-MC-117`、`AC-MC-29` |
| **`B-4`** | 未读数与待办计数分开显示、**不合并成一个红点** | ⚠️ **前提失效**：撤带后**"待办计数"在界面上已无载体** | `D-MC-157` 改写，见下 |
| **`B-5`** | 未读数按 `account_id`、**待办按 `entity_id`**，两个**计数**归属维度不同 | ⚠️ **一半失效**：**归属维度的事实不变**，失效的是"计数"这个载体 | `D-MC-162` 改写，见下 |

| 编号 | 条款（**V3.0 裁定**） |
| --- | --- |
| **`D-MC-157`（改写）【`B-4` 的处置】** | **控制台不产生任何计数角标**——撤带后它没有第二个计数了，**铃铛未读数是面客侧唯一的计数角标**。<br>**`B-4` 的实质红线保留并收紧为一句**：**不得把业务待办并进未读数**，也不得在控制台另造第二个计数（包括 tab 上的数字角标、统计区里的"待处理 N 件"）。理由不变——用户清掉红点却发现事情没办完；现在连"红点"都只剩一个，更不能让它承载两种语义。<br>**建议 WS-329 把 `B-4` 改写为**：「**未读数是面客侧唯一的计数角标；业务待办不得并入未读数，接入方也不得另造第二个计数**」，其 `AC-F933` 随之从"两个计数分开"改为"**全站只有一个计数角标，且它只计未读消息**" |
| **`D-MC-162`（改写，位置改变）【`B-5` 的处置】** | **归属维度的事实一条没变**：**未读消息按 `account_id`（自然人账号）**，**控制台的一切业务数据——含 14 类判据派生出的行级状态与时限——按 `entity_id`（企业主体）**。<br>**变的只是表现形式**：同企业员工甲发起动作、员工乙登录后，原来是"**待办带上有事、铃铛却是 0**"，**现在是"tab 行上有待我处理的标记、铃铛却是 0"**——**同一个客诉，换了个位置**，因此那句常驻说明**必须跟着挪，不能丢**：从待办带头部挪到**各 tab 列表区顶部的说明位**，文案改为「本页数据按企业展示，**同企业任一员工都看得到**；消息只发给发起操作的那个人」。<br>**两条禁止不变**：① **不得为"对齐"把行级数据按 `account_id` 过滤**（与 `D-MC-105` 同企业员工不分级冲突）；② **不得把消息未读数按企业聚合**（那是 WS-329 的可见集定义，控制台无权改）。<br>**建议 WS-329 把 `B-5` 改写为**：「**未读数按 `account_id` 计；接入方页面上的业务数据按 `entity_id` 归属。两者归属维度不同是设计，不是缺陷，接入方必须在页面上写明**」，其 `AC-F937` 随之从"两个计数归属维度不同"改为"**构造同企业跨员工用例，断言业务数据可见而未读数为 0，且页面上存在解释这一点的常驻说明**" |
| `D-MC-163` | **控制台不自建消息中心、消息列表、未读角标、已读逻辑**（`X-MC-03`）。铃铛 `C-F-MC-01`、快捷面板 `C-F-MC-02`、消息中心页 `P-F-MC-01/02` 都是壳层与 WS-329 的组件 |
| `D-MC-164`【轮询归属】 | **未读数轮询是 WS-329 的壳层能力，不违反 `X-MC-04`**。三条共存条件**一律引用 WS-329 `8.3.4`，本册不写第二版**：① 该轮询不是保活心跳、不得续期会话；② **控制台自己不新建任何轮询**，会话失效仍以 **401 即时感知**；③ 它遇 401 必须立即触发统一的回落游客态处理。<br>**控制台的数据刷新只有三个触发点**：进入页面、从广场返回（`H-05`）、用户手动刷新（`AC-MC-37`） |
| `D-MC-165` | 消息 `page_target` 指向控制台时，**按 `D-MC-147` 的 URL 视图状态接住**（带 tab 与过滤）并显示过滤条带。**控制台不为消息新增一套落点约定** |

> **本节只给裁定与建议改法，`B-1`～`B-5` 的正文由 WS-329 修改；本模块不改他册**（请求登记在分册 02 · 10.3 第 7 条）。

## 6.10 异常分支与边界

| # | 异常 | 处理 |
| --- | --- | --- |
| `E-MC-01` | 某个 tab 的上游取数超时或失败 | 该 tab 就地展示可重试错误态与原因，**其余 tab 与统计区照常可用**；**不得整页 500、不得把失败伪装成空态** |
| `E-MC-02` | 统计区某一组指标取不到 | 该组展示"暂时取不到"占位 + 重试，**不展示 0**；其余组照常 |
| `E-MC-03` | 点击快捷按钮时业务状态已变 | 照 `H-02` 边界②：落详情页 + Toast；返回后重取，行上的状态列与时限列随之更新（`AC-MC-38`） |
| `E-MC-04` | `available_actions` 含控制台不认识的取值 | **忽略该取值、不渲染按钮**，上报一次"未知动作取值"事件；**不得自己猜跳转目标** |
| `E-MC-05` | 跨域落地页不可达（代币列表空态 CTA） | 离站告知照常展示；落地失败时给出可读说明与"稍后再试"，**不把用户扔在空白页上** |
| `E-MC-06` | 同一笔业务在两个 tab 里数字不一致 | 服务端同源被破坏的信号（`AC-MC-10` 的告警对象）。控制台**照实展示、不自行调平**，上报一次一致性异常事件 |
| `E-MC-07` | 会话在页面停留期间失效 | 按 `D-MC-11` 立即清 DOM 并回落游客态；中止进行中的请求；**不弹登录框、不进错误页** |
| `E-MC-08` | `entity_id` 在会话期内从 `null` 变为有值 | 下一次取数即按新主体返回；**不缓存上一次的空态结论** |
| `E-MC-09` | 同企业两人同时在看，其中一人办掉了一件事 | 另一人在下一次取数时该行的状态列与时限列更新。**控制台不做实时推送、不做轮询**（`X-MC-04`） |
| `E-MC-10` | 深链目标对象已被硬删除或从未存在 | 落"内容不存在或无权访问"，**不暴露存在性** |
