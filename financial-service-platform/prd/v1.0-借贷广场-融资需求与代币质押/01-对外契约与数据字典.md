## 6.6 深链契约 H-01～H-05（**本模块对我的控制台与后续模块的正式交付**）

控制台（M-5）零业务写操作，其八个快捷按钮全部深链跳广场执行。以下五条是广场对控制台的**义务**，也是 M-2～M-4 必须共同遵守的接口约束。

| 编号 | 契约 | 落地要求 |
| --- | --- | --- |
| **`H-01` 稳定的业务对象 ID** | 融资项目（资产池）、质押记录、融资业务等对象拥有**全局唯一、终身稳定**的标识，**不随状态变化、不随再次发布而变更**，进入终态后仍可寻址 | 编号规则建议沿用 WS-305 模式（前缀 + 日期 + 序号）：项目 `FP...`、质押 `PL...`、融资业务 `FD...`。按合一结论（主册 6.5.0），**项目编号即广场上这条融资需求的编号，不另发号** |
| **`H-02` 可寻址锚点** | 本模块交付：`project/new`（建池）、`project/{id}`（详情）、`project/{id}?action=pledge`（追加质押）、`project/{id}?action=withdraw`（撤回）、`project/{id}?action=publish`（填金额并发布 / 再次发布）、`project/{id}?action=redeem`（提取已释放代币）。**不新增 `demand/{id}` 这一层。** 落地三条边界：① **服务端重新判权**；② **状态已变**时落详情页 + Toast（"该项目已关闭""可撤回额度已变化"），**不报 404、不白屏、不静默跳首页**；③ 游客深链直达广场页面照常全量可见，但**草稿项目一律返回"内容不存在或无权访问"**（`D-FIN-64`） |
| **`H-03` 服务端返回 `available_actions`** | 每次读取由**服务端**返回当前可执行动作清单，前端按其渲染、**不自行依据状态推断**；须区分"不可见"与"可见不可点（`⊘`）"，后者附原因。**额度不足时"撤回质押"必须以 `⊘` + 原因（含可撤回上限）返回，而不是直接隐藏**——隐藏会让资产方以为功能没了 | 与 `D-FIN-25`、`AC-LS-01` 一致：前端隐藏/置灰不构成校验 |
| **`H-04` 数据回流** | 广场侧写操作成功后，控制台可见字段与派生量必须来自**同一数据源、同一算法**（`AC-MC-12`/`AC-FIN-15`）；状态枚举一处定义两处引用（`AC-MC-14`/`D-FIN-28`）。**六个派生量、担保状态档位、质押四态与链上转移状态，均由本模块权威输出**，控制台只读引用 | 本模块是唯一写入方 |
| **`H-05`「返回我的控制台」** | 从控制台深链进入的页面须提供返回入口，动作完成后引导回控制台对应 tab 与锚点（质押完成 → 代币列表 tab；发布完成 → 融资项目 tab）；来源上下文由**服务端暂存**，不拼进 URL | 非深链来源时不展示 |

| 编号 | 验收 |
| --- | --- |
| `AC-LS-07` | H-01～H-05 对 M-2～M-4 同样生效；后续模块新增动作须同步补 `available_actions` 取值与锚点，**不得新开一套跳转约定** |
| `AC-LS-71`（**新**） | 本模块新增的 `action=redeem`（提取）必须同样出现在 `available_actions` 中，并在无可提取代币时不返回该动作——**不得让页面自行判断是否显示提取入口** |

## 6.7 链上质押的调用说明与产品要求

**产品级说明**：本模块的**质押与解除质押需要调用质押合约**——质押 = 把代币从资产方地址转入质押合约；解除质押（撤回、提取）= 从质押合约转回其质押前的原持有地址。**合约本身的设计、部署、接口、参数与权限模型由开发负责，本 PRD 不作规定。** 本节只写本模块对这次调用在**产品上**的要求：用户会感知到什么、会花到什么钱、失败了看到什么。

**资产方侧的签名与付费**：资产方已具备该能力，**由页面唤起外部 SDK 服务**完成签名与 gas 支付（`D-FIN-71`）。本模块不设计钱包连接组件。

**参考实现**：WS-318 的代币铸造链路已有一条可参考的结果回写实现（提交交易 → 跟踪回执 → 成功 / 失败 / 结果待确认 → 查询链上状态 → 人工重试），本模块的 `CT` 轴与超时处理沿用其口径。

### 6.7.1 本模块对链上调用的产品要求

| 编号 | 要求 | 为什么是产品要求 |
| --- | --- | --- |
| **`D-FIN-67`** | **链上调用只发生在三个动作上**：入池（质押 / 追加）、撤回、提取。**额度动作一律不触达链上**——发布需求、报价、接受、放款、占用与释放、担保预警的触发与解除，都在平台侧完成 | 这是 gas 成本的控制点。把额度动作做成链上操作，资产方每走一步业务都要付一次钱 |
| **`D-FIN-68`** | **同一次操作重复提交，不得产生第二次链上转移、不得二次扣 gas。** 用户重复点击、页面刷新、网络重试、并发提交，都必须只产生一笔真实转移；具体用什么机制由开发决定，本 PRD 只要求结果 | gas 是资产方真金白银付的。多扣一次就是多花一次钱，属产品底线，不是技术细节 |
| **`D-FIN-69`** | **失败必须分得清三类，并各自给出用户能看懂的结论与下一步**（文案见 6.7.2） | 用户第一个问题永远是"钱扣了没有、要不要再付一次"。三类混成一句"操作失败"，客服无法回答，用户只能反复重试、反复扣费 |
| **`D-FIN-70`** | **等待超时有明确的页面呈现与可执行动作**：超时不等于失败，**不得直接重试**，须先查链上状态确认未上链（沿用 WS-318 `S-TI-5` 红线）。阈值 **30 分钟为假设值，待开发按真实链况确认** | 超时态下直接重试是二次扣费的最大来源 |
| **`D-FIN-71`** | **签名与付费由页面唤起外部 SDK 服务完成**，本模块不自建钱包连接；唤起前必须先展示本次操作内容与 gas 预估（`AC-LS-32`），用户在 SDK 内取消视为一次失败而非异常 | 唤起第三方界面前不说清楚要签什么、要花多少钱，用户只会取消 |
| **`D-FIN-46`** | **gas 由资产方自付**：质押与解除质押（撤回、提取）的链上费用均由资产方承担，**平台不代付、不垫付、不加收任何服务费**（`X-LS-09`） | 需求方裁定，落为常规条款 |

### 6.7.2 失败与等待的界面文案（`D-FIN-69`/`D-FIN-70` 的落点）

| 类别 | 用户看到的结论 | 可执行动作 | 提示语（示意，最终以文案评审为准） |
| --- | --- | --- | --- |
| **未上链失败** | 交易没有发出去，**没有产生费用** | 直接重试 | 「提交失败，本次未产生链上费用，可直接重试。原因：{原因}」 |
| **已上链失败** | 交易上链了但执行失败，**这次的 gas 已经产生** | 重试（会产生新的 gas） | 「链上执行失败，本次 gas 已产生、不可退回；重试将发起一笔新交易并**再次产生 gas**。原因：{原因}」 |
| **超时未决** | 结果还不知道，**不要重复提交** | 仅「查询链上状态」，**不提供重试按钮** | 「等待链上结果超过 {N} 分钟，当前结果未知。请先查询链上状态，确认未上链后再重试——直接重试可能造成重复转移与重复扣费」 |
| **用户在 SDK 内取消** | 没有签名，**没有产生费用** | 重新发起 | 「您取消了签名，本次未产生任何费用」 |
| **gas 不足** | 钱包余额不够支付本次链上费用 | 充值后重试 | 「钱包余额不足以支付本次链上费用（预估 {X}），请充值后重试」 |

| 编号 | 验收 |
| --- | --- |
| `AC-LS-72` | **重复提交只产生一笔链上转移**：连续点击、刷新后重复提交、并发提交同一操作，链上只出现一笔交易，`实际 gas` 只记一次 |
| `AC-LS-73` | 上表五类情形**各自可区分**，提示语都回答了"钱扣了没有"与"重试要不要再付一次"；**不存在只说"操作失败"的兜底文案** |
| `AC-LS-74` | **超时态页面不出现重试按钮**，只提供「查询链上状态」；查得未上链后才出现重试入口 |
| `AC-LS-75` | 唤起外部 SDK 前先展示本次操作内容与 gas 预估并二次确认；SDK 内取消回到原页面且不产生任何记录变更 |

### 6.7.3 本模块的消费规则

| 编号 | 规则 |
| --- | --- |
| `AC-LS-28` | **只有链上回写为"成功"的代币才计入有效质押价值**；处理中与失败一律不计入（`D-FIN-54` ①） |
| `AC-LS-29` | **额度动作不触达链上**（`D-FIN-67`），只有入池、撤回、提取产生链上转移 |
| `AC-LS-30` | 平台侧质押记录**永远不领先于**链上事实——撤回不得先置已释放再等确认（E-3）。**唯一例外是系统释放的第一段**（`D-FIN-57`），它是业务关系的解除而非资产位置的变更，且对外明确标注为"待提取" |
| `AC-LS-31` | **链上持仓查询与对账不在本模块实现**（`X-LS-11`，后台自动进行）。后台判定存在差异并置标记时，本模块按 E-11 保守处理：该代币不计入有效质押价值、冻结其新动作、触发派生量重算 |

### 7.2 质押记录 Pledge

| `PL-02` | 所属融资项目 | 引用 | 系统 | 一条记录只属于一个项目 |

| `PL-08` | 入池交易哈希 | 文本 | 条件 | `CT-2` 时必填；`0x` + 64 位十六进制（沿用 `D-TI-06` 格式规则）。**本期只做格式校验，不做链上核验**（`D-FIN-22`） |
| `PL-09` | 转出交易哈希 | 文本 | 条件 | 撤回/提取成功时必填，同上格式 |
| `PL-10` | 移出触发原因 | 枚举 | 条件 | `资产方撤回`/`失效代币清出`/`项目关闭释放`/`项目结清释放` |

### 7.4 链上 gas（`D-FIN-46`）

| 编号 | 条款 |
| --- | --- |
| `D-FIN-46` | **链上 gas 由质押方（资产方）承担，平台不代付、不垫付、不返还，且平台对质押/撤回/提取不额外收取任何服务费**（`X-LS-09`）。系统触发的释放改由 `D-FIN-57` 两段式解决，**不依赖代付** |
| `AC-LS-32` | **提交前必须展示费用**：本次链上操作笔数、预估 gas、承担方（本企业）、"gas 由区块链收取、平台不收费"、"链上失败也可能已经产生费用"，并**二次确认**后才发起 |
| `AC-LS-33` | **重试按新的一次收费**：已上链但执行失败已消耗 gas，重试是一笔新交易、产生新的 gas，失败提示与重试按钮旁必须写明；未上链即失败不产生费用，同样要讲清楚 |
| `D-FIN-53` | **撤回/提取频次不设硬性阻断，改用三道软约束**：① 支持**批量一次提交**（把 N 笔合成 1 笔是最有效的降费手段）；② 每次提交前展示张数与预估 gas；③ **24 小时内提交超过 5 次**时提示"频繁链上操作会产生较多 gas"，**不阻断**。理由：撤回与提取是资产方对自有资产的处置权，硬阻断会造成"想撤撤不了"的客诉；费用自担已构成天然抑制 |

## 9. 指标

| 编号 | 指标 | 口径 |
| --- | --- | --- |
| `M-LS-01` | **建池转化率 / 发布转化率** | 创建草稿 → 成功发布的比例；**两段各统计一次**，用于判断两段式是否在第二段流失 |
| `M-LS-02` | 平均池内资产价值 / 平均质押张数 | 按已发布项目统计 |
| `M-LS-03` | 额度利用率 | Σ项目融资余额 ÷ Σ融资上限 |
| `M-LS-04` | **链上转移成功率** | `CT-2` ÷（`CT-2` + `CT-3`），入池 / 撤回 / 提取分开统计 |
| `M-LS-05` | **单位融资额的 gas 成本** | Σ实际 gas ÷ Σ融资发生额，衡量资产方的真实成本负担 |
| `M-LS-06` | **担保不足预警发生率与平均持续时长** | 触发次数 ÷ 活跃项目数；从触发到解除的时长 |
| `M-LS-07` | **预警诱因分布** | 代币失效 / 对账差异 / 其他，用于判断是不是估值口径出了问题 |
| `M-LS-08` | 撤回被拒率 | 因 `AC-FIN-13` 未通过而被拒的撤回占比，用于判断"可撤回上限"是否展示得够清楚 |
| `M-LS-09` | **待提取代币滞留量与时长** | 已释放未提取的张数、金额与平均滞留天数——gas 自担下这个数会真实反映"用户嫌贵不提" |
| `M-LS-10` | 游客→注册转化 | 从 P-LS-01/02 的 `⊘` 引导进入注册的转化 |

| `M-LS-12`（**新**） | **空池草稿占比** | 因首笔质押链上失败而产生的空池草稿数 ÷ 新建项目数，反映链上失败对建池体验的实际冲击 |

### 10.3 恶意锁仓：**本期明确接受的风险**（演进备注）

需求方 2026-09-11 07:01 第 6 条裁定**本期暂不考虑恶意锁仓**。前版对 M-2「报价有效期为必须项」的硬要求据此**撤销**。这不是问题消失，**放弃的是下面这三样**，如实记录：

| # | 本期放弃了什么 |
| --- | --- |
| 1 | **无人值守时的自动收敛**。串行承载（`D-FIN-33`）下，项目在 `S-FP-3 已锁定` 期间不接受新报价；机构报一个不合理高价又不撤回时，**唯一的解除手段是资产方主动拒绝**。资产方休假、换人、没登录（`G-02` 消息中心无立项，本期只有页面标记）时，项目档期与对应额度会被**无限期占用** |
| 2 | **额度的自动回收**。在途占用只在需求终结时释放（`AC-FIN-23`），没有"占用超时自动释放"的机制——本模块也**不自行发明**一个：占用是需求与报价的伴生状态，本模块单方面释放会造成"报价还在、额度没了"的割裂，收敛点必须在报价对象上，即 M-2 的报价有效期 |
| 3 | **对反复报价的抑制**。同一机构可以在被拒绝后立即再报，本期不设冷却与次数限制 |

**演进切入点**：出现实际锁仓投诉时，在 M-2 引入 `Q-FIN-11` 报价有效期（到期自动失效、需求自动放开），本模块无需改动——`AC-FIN-23` 已把"需求终结即释放占用"写成通用规则，报价失效属于其中一种终结方式。

**本期仍然成立的人工手段**（不是自动机制，写清以免被当作已解决）：资产方可随时拒绝在途报价、拒绝即释放锁定，服务端**不设冷却期、不做理由审核**；冻结期内追加质押不受限（`D-FIN-48`）；P-LS-02 展示报价提交时间与已占用时长，让资产方有判断依据。

## 11. 验收标准汇总

> 与本模块相关的全部验收项集中在此；分册不再重复列举，只在条款处引用。

| 编号 | 验收标准 |
| --- | --- |
| `AC-LS-57` | **创建项目必须至少质押一张代币**：未勾选任何代币时创建不可提交；创建成功后项目落草稿且**广场不可见、深链不暴露存在性** |
| `AC-LS-58` | **创建不等待链上确认**：提交后页面即返回草稿项目，链上处于处理中时项目照常存在，有效质押价值为 0 且发布入口 `⊘` |
| `AC-LS-59` | **发布校验认链上事实**：有效质押价值 = 0 时发布必被拒；至少一张 `CT-2` 且需求金额 ≤ 可融金额时发布成功 |
| `AC-LS-54`/`AC-LS-55` | 两段式可中断可续做；第二段失败不回滚已完成的质押，不重复收 gas |
| `AC-LS-60` | **发布成功后 `项目在途金额` 立即等于需求金额**、可融金额同步减少；同一份质押无法连发两笔吃满额度的需求 |
| `AC-LS-61` | **报价提交后 `项目在途金额` 不变**（占用只有发布这一个来源）；报价被拒绝后仍为需求金额；需求撤下或项目关闭后归零 |
| `AC-LS-62` | **融资确认完成的同一时刻**，该笔金额从在途移出并计入项目融资余额，中间不存在两边都不计的空档 |
| `AC-LS-10` | 同一张代币无法同时出现在两个项目的资产池中（并发提交时只有一笔成功） |
| `AC-LS-11` | 代币清单中不出现：非本企业、未签发、已被占用、**已释放待提取**、底层已失效、非应收账款类、与本池已有类型不一致的代币 |
| `AC-LS-12` | 质押清单不提供数量输入，粒度为"张"，且支持批量一次提交 |
| `AC-LS-13` | 链上转入失败的代币不计入质押价值且退回可质押；界面可见失败原因、是否已扣 gas、重试将产生新 gas |
| `AC-LS-63` | **撤回按额度判定**：构造"撤回后 `INV-FIN-01` 不成立"的用例必被拒绝并给出三个数；构造"额度充足"的用例**即使项目有在途报价也必须放行** |
| `AC-LS-64` | **失效代币撤回不受任何额度限制**，且撤回前后有效质押价值、融资上限、可融金额**三个数完全不变** |
| `AC-LS-36` | 撤回页面分两区，有效抵押物区常驻显示可撤回上限并实时累计对照 |
| `AC-LS-65` | **追加质押在任何项目状态下均可成功**（含有在途报价时），成功后各派生量同步增加 |
| `AC-LS-66` | **代币失效后**：有效质押价值立即扣减、失效代币价值同步增加、派生量重算；若跌破预警线则档位转「担保不足预警」并推送 |
| `AC-LS-39`/`AC-LS-40` | 预警状态下报价入口 `⊘` 并说明原因；预警触发与解除自动进行、双方页面一致、留痕可回溯 |
| `AC-LS-67` | **广场公开担保状态档位与缺口**，文案为中性事实描述，**全站不存在"违约""高危""风险企业"等评价性标签，也不存在排行榜或黑名单** |
| `AC-LS-17` | 额度占用/释放、预警触发/解除**不产生链上交易**；入池/撤回/提取**必须**产生链上交易并留存哈希 |
| `AC-LS-18` | 撤回链上失败后代币回到在池、预扣撤销，不出现"账面已释放、链上仍在合约"的错配 |
| `AC-LS-68` | **项目关闭/结清时业务即时释放**，代币置「已释放 · 待提取」；提取由资产方自助发起并自付 gas，可批量；未提取代币不计入任何池且不可再质押 |
| `AC-LS-38` | 存在可提取代币时常驻提示"您有 N 张（合计 X USD）可提取"，并说明需自付 gas |
| `AC-LS-20` | 到期且无在途/未结清业务 → 自动 `S-FP-5` 并释放；到期但有未结清业务 → 不关闭、不接受新报价、不可再次发布，且**以中性样式呈现** |
| `AC-LS-21`～`AC-LS-23` | 游客 L1～L5 全量可见、L6 全部 `⊘`；游客调用写接口一律拒绝且响应不含业务数据；草稿项目不可见且不暴露存在性 |
| `AC-LS-53`/`AC-LS-56` | 三数在页面上乘得平；质押率无任何可编辑控件或可调暗示 |
| `AC-LS-24` | 界面全文检索：不存在无限定词的"融资余额"；不存在质押率与有效期的可编辑入口；**不存在"冻结代币""选择冻结范围""待确认融资金额""有效代币资产"等已作废或已映射的说法** |
| `AC-LS-41` | L3 同时展示池内资产总额与有效质押价值，差额标注为"失效代币不计入担保" |
| `AC-LS-25` | 控制台与广场读到的同一项目的各派生量、担保档位、状态文案完全一致（`H-04`） |
| `AC-LS-26` | 服务端返回 `available_actions`；额度不足时"撤回质押"以 `⊘` + 原因（含可撤回上限）返回而非隐藏 |
| `AC-LS-34` | 广场上**一个项目只对应一张卡片、一个详情页、一个编号**，不存在并列的"融资需求"对象或 `demand/{id}` 锚点 |
| `AC-LS-69` | **并发一致性**：撤回处理中并发报价时，报价看到的是已预扣的池值；撤回失败回滚后池值恢复且已通过的报价不受影响 |
| `AC-LS-70`（**反向**） | **界面上不存在**：代币级冻结/锁定入口、"选择要冻结的代币"、部分数量质押输入、有效期编辑、质押率编辑、平台代付 gas 的任何表述、抵押物处置/变现入口 |
| `AC-LS-72` | **重复提交只产生一笔链上转移**：连续点击、刷新后重复提交、并发提交同一操作，链上只出现一笔交易，`实际 gas` 只记一次 |
| `AC-LS-73` | 6.7.2 五类失败情形**各自可区分**，提示语都回答了"钱扣了没有"与"重试要不要再付一次"；**不存在只说"操作失败"的兜底文案** |
| `AC-LS-74` | **超时态页面不出现重试按钮**，只提供「查询链上状态」；查得未上链后才出现重试入口 |
| `AC-LS-75` | 唤起外部签名 SDK 前先展示操作内容与 gas 预估并二次确认；SDK 内取消回到原页面、不产生任何记录变更、不产生费用 |
