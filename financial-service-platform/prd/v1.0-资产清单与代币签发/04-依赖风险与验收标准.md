## 18. 风险

| 编号 | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| R-TI-01 | **数币地址的主体口径未定**（账号维度 vs 企业维度，DEP-TI-06）。在本模块之前它"只存不用"，现在它是**必填且用于不可逆铸造**的收币地址 | 代币铸给错误的主体，**不可逆、无法回收** | **风险等级由低升为高，且已成为开发前的阻塞项。** 须在开发启动前由资产平台答复；本模块以 D-TI-20「实际收币地址」与 D-DS-05 并列展示、不一致时高亮，作为事后可发现的兜底 |
| R-TI-02 | 汇率配错（多一个零、方向填反）导致铸造数量严重偏离 | 铸造不可逆，超发无法回收 | ① 新增/停用二次确认展示"当前值 → 新值"对照与影响面笔数；② 汇率值方向在表单上写死为 `1 <源币种> = X USD` 的句式，不给用户选方向；③ 换算过程整组快照 + 详情页展示，错误可被 J-4 应答时发现；④ 全部操作留痕可追责 |
| R-TI-03 | `S-TI-5` 被误当成失败而重试，造成**超发** | 同一资产铸两次，红线事故 | 【红线】`S-TI-5 → S-TI-2` 边不存在；界面不渲染重试按钮；服务端拒绝；补扫不处理 `S-TI-5`；反向验收 AC-TI-42 |
| R-TI-04 | 定时补扫自动重发已提交过交易的资产，造成超发 | 同上 | 【裁定】补扫**只处理从未提交过链上交易的资产**（分册一 11.2），链上类 `S-TI-4` 与 `S-TI-5` 一律不自动处理 |
| R-TI-05 | 合约 `decimals = 0`，2 位小数的换算结果无法铸造 | 签发全线失败 | DEP-TI-04 一句话确认即可；两种取值下页面结构与流程不变，只改一行取整规则 |
| R-TI-06 | **存量无地址资产**在本模块上线时仍存在，落入 `S-TI-6` 终态且运营端无处置手段 | 一批资产永久发不出去 | 主文档 3.4 的一次性数据体检作为**上线前置条件**；不变量由 AC-TI-44【红线】守住 |
| R-TI-07 | 汇率停用后大批资产被拦截，运营人员未察觉 | 资产滞留、资产方投诉 | 汇率列表顶部常驻「N 个币种无有效汇率，共 M 笔资产因此待签发」提示条；停用二次确认展示影响面；异常筛选覆盖。**本期不发站内信**（N-07），可见性靠页面承载 |
| R-TI-08 | 合并式下资产清单列数变多，可读性下降 | 使用效率下降 | 列表只放签发状态、原因、代币数量、重试次数四列；合约、链、哈希、地址、换算过程一律放详情页的独立区块 |
| R-TI-09 | 日后运营端取得代币生命周期职责（冻结/质押/赎回），需要把签发结果拆成独立实体 | 一次数据迁移 | 本期把 `D-TI-01`～`D-TI-20` 设计成**内聚的一组**，可整组迁出；且定论 10 显示职责正在离开运营端，风险方向与拆分预期相反 |
| R-TI-10 | 链上交易长时间无回执，`S-TI-5` 大量堆积，人工逐条查询成本高 | 运营负担 | 本期 `S-TI-5` 保留逐条人工查询（这是定论 9 的红线要求）；若上线后堆积明显，下一期再评估"批量查询链上状态"——**批量查询不等于批量重试**，不触碰红线 |

## 19. 验收标准

> 编号连续、跨分册唯一。`AC-TI-xx` 为签发侧，`AC-FX-xx` 为汇率侧，`AC-TI-41` 起为红线与反向验收。

### 19.1 资产清单列表页

| 编号 | 验收项 |
| --- | --- |
| AC-TI-01 | 清单新增「签发状态」列，值域为 `S-TI-1`～`S-TI-6`，且可作为多选筛选维度；筛选结果与条件一致 |
| AC-TI-02 | 「代币数量」列仅在 `S-TI-3` 有值，其余状态一律展示 `—`，**不展示预估值也不展示 0** |
| AC-TI-03 | 签发概况汇总条展示当前筛选条件下六个状态的笔数，切换筛选后同步刷新；**汇总条不出现任何金额**，页面任何位置不出现跨币种总额 |
| AC-TI-04 | 「需处理 N 笔」按钮点击后筛出 `S-TI-4` + `S-TI-5`，且筛选条件在筛选区可见、可清除 |
| AC-TI-05 | 仅 `S-TI-5` 行渲染「查询链上状态」，且该行**不渲染重试按钮** |
| AC-TI-06 | 仅 `S-TI-4` 行渲染「重试」，且仅 `S-TI-4` 行的勾选框可勾选；其余状态勾选框禁用并给出 hover 说明 |
| AC-TI-07 | 批量重试确认弹层展示勾选条数、按币种分组的金额合计、其中因缺汇率失败的条数 |
| AC-TI-08 | 批量重试勾选超过 200 条时提交按钮禁用并提示分批处理 |
| AC-TI-09 | 批量重试逐条独立成败，部分失败时成功条目正常进入 `S-TI-2`，**不整体回滚**；结果面板逐条给出结果与原因，可展开并跳转对应资产详情 |
| AC-TI-10 | 列表时间均带时区标注，无裸时间；金额与数字格式符合国际化基线 |
| AC-TI-11 | 无 `asset_inventory.issue_retry` 权限的账号，重试与查询链上状态按钮不渲染；直接调用接口被服务端拒绝 |
| AC-TI-12 | 「同步状态」仍不作为清单筛选项（不推翻 WS-313 AC-DS-39），签发状态是独立的另一维度 |

### 19.3 自动签发、重试与状态机

| 编号 | 验收项 |
| --- | --- |
| AC-TI-24 | 资产收单成功后 5 秒内发起签发前置校验；条件具备的资产全程无人工操作即进入 `S-TI-3` |
| AC-TI-25 | 定时补扫每 10 分钟一轮，处理滞留的 `S-TI-1` 与**校验类** `S-TI-4`（缺汇率） |
| AC-TI-26 | **补扫不处理链上类 `S-TI-4`、不处理 `S-TI-5`**；构造这两类数据后连续观察三轮补扫，状态与链上交易数均不变 |
| AC-TI-27 | 到期日当天的资产**仍可签发**；到期日次日（UTC）的资产落 `S-TI-6 · 应收账款已到期` |
| AC-TI-28 | `S-TI-1` 资产在等待期间跨过到期日的，由补扫转为 `S-TI-6` |
| AC-TI-29 | 换算后 < 0.01 USD 的资产落 `S-TI-6 · 换算后金额小于 0.01 USD`，且详情页仍展示完整换算过程与截断值 |
| AC-TI-30 | 该币种无有效汇率时落 `S-TI-4 · 缺该币种有效汇率`，且**未向链上提交任何交易** |
| AC-TI-31 | 补配该币种汇率并立即生效后，对该资产点「重试」即可成功；不点也可，下一轮补扫自动重发成功 |
| AC-TI-32 | `S-TI-5` 查询链上结果为"已上链成功"时转 `S-TI-3` 并补全哈希、实际收币地址、完成时间 |
| AC-TI-33 | `S-TI-5` 查询链上结果为"未上链"时转 `S-TI-4`，**此时才出现重试按钮** |

| AC-TI-35 | 重试不限次数，每次累加重试次数并在时间线留痕；**补扫自动重发不计入重试次数**，但在时间线留痕 |
| AC-TI-36 | 资产处于 `S-TI-2` 期间，任何新的触发或重试请求被拒绝并提示「该资产已有在途交易」 |
| AC-TI-37 | 服务重启后 `S-TI-2` 资产由补扫按链上状态归位，**不重新提交交易** |
| AC-TI-38 | 链上交易 30 分钟未取得回执即落 `S-TI-5` |
| AC-TI-39 | 终态（`S-TI-3` / `S-TI-6`）资产在界面与接口上均无任何可改回其他状态的手段 |

### 19.4 红线

| 编号 | 验收项 |
| --- | --- |
| AC-TI-40 | 【红线】**同一份资产在任何路径下只能成功铸造一次。** 对同一资产并发触发 10 次、连续重试 5 次、服务重启后补扫接管，链上成功交易始终只有 1 笔，`S-TI-3` 记录始终只有 1 条 |
| AC-TI-41 | 【红线】换算快照在**提交链上交易之前**落库；构造"快照后、提交前"中断的场景，记录中仍能查到完整的换算快照 |
| AC-TI-42 | 【红线】**`S-TI-5` 不存在通往 `S-TI-2` 的路径。** 直接绕过前端向服务端发起 `S-TI-5` 资产的重试请求，被拒绝且不产生任何链上交易 |
| AC-TI-43 | 【红线】数币地址缺失或格式非法的资产**收单即被拒收**：不写入资产清单、不写入任何失败记录表，运营端任何页面、任何筛选项均查不到该资产；绕过资产管理端前端直接调用收单同样被拒 |
| AC-TI-44 | 【红线】资产清单中**不存在**数币地址为空或非 `0x` + 40 位十六进制的记录。上线前的一次性数据体检须证明该集合为空 |

| AC-FX-13 | 从资产清单深链进入新增表单时，币种已预填且**不可修改**；保存后可返回资产清单并保留原筛选与分页状态 |

| AC-FX-17 | 资产详情的换算快照可反查到对应的汇率历史版本 |
| AC-FX-18 | USD 内置行不可新增、编辑、停用、删除，列表中标注「系统内置」 |

| AC-FX-22 | 【反向】本模块**不接外部行情源**，不存在自动取价、定时刷新汇率的任何逻辑 |
