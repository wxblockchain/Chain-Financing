## 12. 汇率管理（P-O-FX-01 / P-O-FX-02）

### 12.1 模块定位与边界

| 项 | 内容 |
| --- | --- |
| 定位 | 运营端的**平台级配置模块**：维护一张"各币种 → 美元"的汇率表，供代币签发在换算时消费 |
| 与签发的关系 | **正交**。汇率管理不感知任何一笔资产，签发消费汇率但不修改汇率 |
| 菜单位置 | **一级菜单**，与「代币管理」「协议管理」平级（IA-02） |
| 使用者 | 运营管理员（`fx_rate.view` / `fx_rate.manage`） |
| 本期不做 | 不接外部行情源、不做自动更新、不做多目标币种（目标币种恒为 USD）、不做汇率的审批流、不发通知 |

**为什么目标币种恒为 USD**：定论 4 已定死"应收账款金额先换算为美元，1 美元 = 1 代币"。本期不存在第二个目标币种，因此汇率表是一维的（源币种 → USD），不做币种对矩阵。

### 12.2 核心概念：币种、版本、有效汇率

| 概念 | 定义 |
| --- | --- |
| **币种** | 汇率表的组织维度。值域取 WS-313 D-DS-07 币种枚举：**CNY / HKD / USD / KYD / NGN**。**不允许自定义币种**——币种枚举的定义方是上游，本模块只消费 |
| **汇率版本** | 一条记录 = 某币种在某个生效时间点起适用的汇率值。同一币种可以有多个版本 |
| **当前生效版本** | 该币种下满足「**生效时间 ≤ 当前时刻** 且 **启用** 且 生效时间最晚」的那一个版本 |
| **待生效版本** | 生效时间 > 当前时刻的版本。同一币种**至多允许存在 1 个待生效版本**——允许排队多个会让"下一次改成多少"变得不可一眼判断 |
| **有效汇率** | 「当前生效版本存在」即该币种有有效汇率。不存在时该币种进入**无有效汇率**，其资产签发会被拦截（分册一 11.3 第 5 步） |

**版本的不可变性【红线】**：一个版本一旦**生效**，其汇率值、生效时间、来源说明**永久不可修改、不可删除**。要改只能新增一个生效时间更晚的版本，或者把该币种停用。理由：已生效的版本可能已经被某些签发引用过，改它等于事后篡改铸造依据。

### 12.3 汇率列表页（P-O-FX-01，F-FX-01）

| 项 | 规则 |
| --- | --- |
| 组织方式 | **按币种一行**，而不是按版本一行。运营人员的心智是"NGN 现在是多少"，不是"翻版本流水" |
| 列 | 币种代码 + 币种名称、当前生效汇率值、当前版本生效时间、来源说明、启用状态、待生效版本（有则展示"值 + 生效时间"，无则 `—`）、最近修改人、最近修改时间、操作 |
| 排序 | 按币种代码字典序固定排列；**USD 恒在首位** |
| 筛选 | 币种（多选）、启用状态、是否无有效汇率 |
| 「无有效汇率」高亮 | 该币种当前无生效版本或被停用时，整行以警示样式标出，并在币种旁展示「无有效汇率，该币种资产将被拦截签发」 |
| 顶部提示条 | 存在「无有效汇率」的币种时，页面顶部常驻提示：「N 个币种当前无有效汇率，共 M 笔资产因此待签发」，M 点击后跳转资产清单并预置「签发失败 · 缺该币种有效汇率」筛选 |
| 空态 | 首次进入、尚未配置任何币种时，展示 USD 内置行 + 空态引导「尚未配置任何汇率，非美元币种的资产将无法签发」 |
| 只读态 | 无 `fx_rate.manage` 权限时，所有写入口不渲染，页面为纯查看 |
| 展示基线 | 时间一律 UTC 存储、按账户时区渲染并带时区标注；数字格式沿用 WS-308『01-国际化基线.md』第 4 节 |

### 12.4 新增汇率版本（F-FX-02，`C-O-FX-01`）

**表单字段与校验：**

| 字段 | 必填 | 规则 | 校验不通过的提示 |
| --- | --- | --- | --- |
| 币种 | 是 | 单选，取自币种枚举；从资产清单深链进入时**预填且不可修改**（L-02） | 「请选择币种」 |
| 汇率值 | 是 | `1 <源币种> = X USD`。**正数，最多 6 位小数**，不接受 0 与负数 | 「汇率值必须大于 0，最多 6 位小数」 |
| 生效时间 | 是 | 精确到分钟。**允许"立即生效"**（取提交时刻）与"指定未来时间"；**不允许早于当前时刻**（禁止追溯生效） | 「生效时间不能早于当前时间」 |
| 来源说明 | 是 | 文本，≤ 100 字。例如「XX 银行 2026-09-10 中间价」。**必填**——这是换算快照里要展示给资产方看的那一行，留空等于事后无法自证 | 「请填写汇率来源说明」 |
| 备注 | 否 | 文本，≤ 200 字，仅内部可见，不进入换算快照 | — |

**其他规则：**

| 项 | 规则 |
| --- | --- |
| 禁止追溯生效 | 生效时间不得早于当前时刻。**追溯生效会让"某笔签发当时用的是哪个版本"变得不可复现** |
| 待生效版本唯一 | 该币种已有待生效版本时，新增会提示「该币种已有一个待生效版本（值 / 生效时间），继续新增将替换它」，确认后替换（被替换的版本进历史留痕，标注「已被替换」） |
| 二次确认 | 提交前展示对照：该币种当前生效值 → 新值、生效时间、**当前有多少笔该币种资产处于待签发或因缺汇率失败**（影响面提示） |
| 立即生效的即时效果 | 保存后立即成为当前生效版本；**已签发记录不受影响**（F-FX-08【红线】）；因缺汇率而失败的该币种资产可立即重试，或等下一轮补扫自动重发（分册一 11.2） |
| USD | **不可新增 USD 版本**，USD 为系统内置只读行（12.8） |

### 12.5 编辑与删除（F-FX-03 / F-FX-05）

| 对象 | 可编辑 | 可删除 |
| --- | --- | --- |
| **当前生效版本** | ❌ **不可** | ❌ **不可** |
| **历史版本** | ❌ 不可 | ❌ 不可 |
| **待生效版本** | ✅ 可编辑汇率值、生效时间、来源说明、备注 | ✅ 可删除 |
| USD 内置行 | ❌ 不可 | ❌ 不可 |

- 编辑待生效版本的表单与校验与 12.4 完全一致，生效时间仍不得早于当前时刻。
- 删除待生效版本需二次确认，删除后在历史版本中留一条「待生效版本已删除」的留痕（**留痕不可删**）。
- 要"改"一个已生效的汇率，正确路径是**新增一个生效时间更晚的版本**；界面在用户点击已生效行的时候直接给出这条引导，而不是简单地禁用按钮。

### 12.6 启用 / 停用（F-FX-04，`C-O-FX-02`）

| 项 | 规则 |
| --- | --- |
| 粒度 | **按币种**停用，不是按版本。停用即"该币种当前不参与换算" |
| 停用的后果 | 该币种立即进入**无有效汇率**；此后该币种资产的签发前置校验第 5 步不通过，落 `S-TI-4 签发失败 · 缺该币种有效汇率` |
| 二次确认必须展示影响面 | 「停用后，该币种当前 **N 笔**待签发资产将被拦截，已签发的 **M 笔**不受影响」。N、M 为实时统计值 |
| 对已签发记录 | **无影响**（F-FX-08【红线】） |
| 对在途交易 | **无影响**。已进入 `S-TI-2` 的交易照常等待回执——换算快照已在提交前完成（分册一 10.2） |
| 重新启用 | 启用后恢复停用前的当前生效版本；若停用期间新增过版本，按 12.2 的规则重新判定当前生效版本 |
| 留痕 | 停用 / 启用各记一条，含操作人、时间、当时的影响面统计值 |
| USD | 不可停用（12.8） |

### 12.7 历史版本与留痕（P-O-FX-02，F-FX-06 / F-FX-07）

| 项 | 规则 |
| --- | --- |
| 入口 | 汇率列表行的「历史版本」；支持按币种深链 |
| 展示 | 该币种全部版本，按生效时间**倒序**。当前生效版本以标记突出 |
| 每条含 | 汇率值、生效时间、来源说明、备注、状态（当前生效 / 历史 / 待生效 / 已被替换 / 已删除）、创建人、创建时间 |
| 操作留痕表 | 与版本列表并列的第二个区块，按时间倒序记录该币种的全部操作：新增 / 编辑 / 删除待生效 / 启用 / 停用，每条含操作人、操作时间、变更前值、变更后值 |
| 【红线】只增不改 | 版本记录与操作留痕**均不可编辑、不可删除**，包括被替换与被删除的待生效版本 |
| 保留期 | 永久保留，不做归档清理 |
| 导出 | 本期不做导出 |

### 12.8 USD 的特例（F-FX-09）

| 项 | 规则 |
| --- | --- |
| 汇率值 | 恒为 `1.000000`，系统内置 |
| 来源说明 | 「系统内置」 |
| 可维护性 | **不可新增、不可编辑、不可停用、不可删除**；列表中以只读行展示并标注"系统内置" |
| 签发时 | USD 资产不走换算，但**仍写入换算快照**（汇率 `1.000000`、来源「系统内置」、生效时间取该资产的签发时刻），保持记录结构一致（分册一 10.2） |

### 12.9 【红线】汇率改动不影响已签发记录（F-FX-08）

**这是本模块最重要的一条口径，需求方已确认按"不影响"执行。**

| 项 | 规则 |
| --- | --- |
| 原理 | 签发时已把**整组换算过程快照**落库（分册一 10.2），已签发记录展示的是快照，不是对当前汇率表的实时查询 |
| 结论 | 汇率的新增、修改（待生效版本）、启用、停用、删除，**一律只对之后发生的签发生效**；任何已完成的签发记录的汇率值、生效时间、来源、美元金额、代币数量、截断值**永不改变** |
| 已铸代币 | 链上已铸造的代币数量**不因汇率变动而调整**——铸造不可逆，也不存在补铸与回收 |
| 在途交易 | `S-TI-2` 期间汇率变动不影响该笔交易，快照先于提交 |
| 重试 | **重试是一次新的签发尝试**，会**重新取当时的有效汇率并重新快照**。这不是"改已签发记录"——重试的前提是上一次没有成功签发 |
| 页面告知 | 汇率新增 / 停用的二次确认弹层中固定展示一行：「本次改动不影响已签发的 M 笔记录，仅对之后的签发生效」 |
| 验收 | AC-FX-14【红线】 |

## 13. 金额换算与代币数量

> 本章规则**沿用简报 V1.1 第 4 章，未作修改**；变化的只是汇率的来源从"系统配置项"改为"汇率管理模块"（第 12 章）。

### 13.1 换算链路

```text
应收账款金额（D-DS-08） + 币种（D-DS-07）
        │
        ├─ 取该币种的当前生效汇率版本（12.2）
        │      └─ 缺失 → S-TI-4 签发失败 · 缺该币种有效汇率
        ▼
美元金额 = 原金额 × 汇率值
        │
        ├─ 保留 2 位小数，向下截断（13.2）
        │      └─ 截断后 < 0.01 USD → S-TI-6 不予签发 · 换算后金额小于 0.01 USD
        ▼
代币数量 = 截断后的美元金额        （1 美元 = 1 代币，不可人工调整）
        │
        ▼
整组快照落库 → 提交链上铸造交易
```

### 13.2 精度与取整规则

| 项 | 规则 | 理由 |
| --- | --- | --- |
| 汇率值精度 | **6 位小数** | 覆盖 NGN 这类与美元数量级差距大的币种，避免精度损失被放大 |
| 中间计算 | 不得提前截断，**在最终结果处一次性截断** | 分步截断会累积误差 |
| 换算结果保留位数 | **2 位小数** | 与 WS-313 法币金额 2 位小数的口径一致，语义连贯 |
| 取整方式 | **向下截断（舍去，不四舍五入）** | 保证链上代币总量**不超过**真实债权金额。宁少勿多与防超发红线同向；四舍五入存在铸出多于债权的情形 |
| 被舍去的部分 | 在详情页换算区块**显式展示**（如「截断 0.004 USD」） | 数量不可人工调整，运营人员无法纠正，那就必须让他看得见、解释得清 |
| 零值与极小额 | 截断后 < 0.01 USD → 代币数量为 0 → **不予签发**（`S-TI-6`），并给出明确原因 | 铸 0 个代币无意义，且会产生一条无法解释的链上记录 |
| 负数与零金额 | 不存在——WS-313 收单校验已要求金额 > 0 | — |

**合约 `decimals` 的技术输入（简报 Q-F 定值）**：本 PRD 按已部署的应收账款铸币合约 `decimals ≥ 2` 撰写。若开发确认为 `0`（只支持整数代币），**仅"换算结果保留位数"一行改为"取整到整数、向下截断"**，其余规则、页面结构、状态机、验收项均不变。这是技术输入，不阻塞设计与开发启动。

### 13.4 换算快照的字段组

签发时必须整组落库、整组展示，缺一不可（字段定义见分册三 14.2）：

| # | 快照项 | 来源 |
| --- | --- | --- |
| 1 | 原金额 | 资产字段 D-DS-08 |
| 2 | 原币种 | 资产字段 D-DS-07 |
| 3 | 汇率值 | 签发时刻的当前生效版本 |
| 4 | 汇率生效时间 | 同上版本 |
| 5 | 汇率来源说明 | 同上版本 |
| 6 | 汇率版本标识 | 同上版本（用于反查历史版本页） |
| 7 | 换算后美元金额 | 截断后的值 |
| 8 | 代币数量 | = 第 7 项 |
| 9 | 被截断部分 | 未截断结果 − 截断后结果 |

**【红线】快照落库必须先于链上交易提交。** 先快照后提交，保证不存在"交易已发出但换算依据丢失"的记录。
