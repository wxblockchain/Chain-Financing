## 8. 收单准入与数币地址（F-TI-16）

> 本章是【修正 V1.1】修正一的落地。它改动的是**运营端自己的收单逻辑**，不对资产管理端发起任何调用；资产管理端侧需要同步修订的条款另见交付到 WS-313 的《D-DS-05 一致性修订说明》，本 PRD 不重复。

### 8.1 数币地址的定性

| 项 | 口径 |
| --- | --- |
| 字段来源 | 即 WS-313 推送报文的 **D-DS-05 资产方钱包地址**，随资产一并推送到运营端。**本模块不新增字段、不新增接口** |
| 用途 | 代币铸造完成时的**收币地址**——代币直接进入该地址，不经运营端托管 |
| 必填性 | **必填**。这是相对 WS-313 原文的修正 |
| 格式 | `0x` + 40 位十六进制字符，大小写不敏感 |
| 校验时点 | **收单环节**（运营端 F-DS-10 收单校验链） |

### 8.2 收单校验（在 WS-313 8.1 收单校验链上的增补）

WS-313 的收单按逐条处理、任一步失败即终止该条。本模块在该链路上把数币地址纳入必填与格式校验：

| 编号 | 校验项 | 判定 | 未通过的处置 |
| --- | --- | --- | --- |
| V-TI-01 | 数币地址非空 | D-DS-05 非空 | **该条收单失败**，不写入资产清单，回执原因码 `E-DS-02`，字段名「资产方钱包地址」 |
| V-TI-02 | 数币地址格式 | 符合 `0x` + 40 位十六进制 | 同上 |

**处置口径完全沿用 WS-313 8.1 的收单失败规则，不另立一套：**

| 项 | 规则 |
| --- | --- |
| 数据 | **不写入资产清单、不写入任何失败记录表。** 运营端不因一次失败的收单产生任何可查询数据 |
| 展示 | 运营端**任何页面、任何筛选项都不出现该条资产**，包括清单、详情与空态提示 |
| 回执 | 逐条返回原因码与文案给资产管理端；失败的可见性与处置全部落在资产管理端 |
| 服务端日志 | 仍须记入运营端服务日志用于排障，但**日志不是产品功能**，不提供运营端页面入口 |
| 服务端强制 | 即使绕过资产管理端前端直接调用收单，服务端仍执行 V-TI-01 / V-TI-02，**无例外** |

### 8.3 补齐路径为什么不需要动幂等规则

【修正 V1.1】简报 5.3 / Q-A 建议"幂等命中时允许刷新数币地址字段"。**本 PRD 不采纳，WS-313 8.2 的幂等规则维持原文不改。**

理由是一条闭环推理：

1. 缺地址的资产在收单环节被**拒收**，因此**不入库**（8.2）；
2. 不入库意味着运营端不存在这条记录；
3. 资产方在资产平台补齐地址后，资产管理端重推该资产时，运营端按「来源系统标识 + 来源资产 ID」查重**查不到**，因此**不会命中幂等**；
4. 该条走正常入库路径，地址随报文一并带入。

**结论**：补齐路径天然成立，不需要"幂等命中时刷新字段"这类例外。保留幂等规则的原样，也保住了 WS-313 那条红线的完整性——"幂等命中不更新已有记录的任何字段"没有任何缺口。

### 8.4 不做人工补录

运营端**不提供**数币地址的人工补录入口（N-09）。运营人员手录的地址与资产方在资产平台注册绑定的地址可能不一致，而**铸错地址不可逆**，风险与收益不成比例。地址的唯一权威来源是资产平台。

## 9. 资产清单列表页（P-O-DS-01）

> 本页为 WS-313 已定义的页面，本模块**在其上增补**。WS-313 已定的数据范围、原有列、原有筛选、按币种分组汇总、时区标注、脱敏基线等口径**继续有效，本章不重复也不推翻**。

### 9.1 本模块新增的列

| 列 | 口径 | 空值表现 |
| --- | --- | --- |
| **签发状态**（F-TI-01） | 取 D-TI-01，值域 `S-TI-1`～`S-TI-6`，以状态标签展示 | 不存在空值——资产入库即为 `S-TI-1` |
| **拦截 / 失败原因**（F-TI-12） | 仅 `S-TI-4` / `S-TI-6` 有值，展示原因文案（分册三 15.1）。列表内为一行截断展示，完整文案在详情页 | 其余状态展示 `—` |
| **代币数量**（F-TI-02） | 仅 `S-TI-3` 有值，展示实际铸造数量 + 单位 | 其余状态一律展示 `—`。**不展示预估值、不展示 0** |
| **重试次数**（F-TI-06 关联） | 该资产被人工重试的累计次数，初始 0 | 0 时展示 `—`，避免噪声 |

> **不新增"同步状态"筛选项**——WS-313 AC-DS-39 明确清单不设该筛选项，本模块不改这一条。签发状态是本模块新增的**另一个**筛选维度，两者不冲突。

### 9.2 本模块新增的筛选与排序

| 项 | 规则 |
| --- | --- |
| 签发状态筛选 | 多选，值域 `S-TI-1`～`S-TI-6`；**这是本模块的主要筛选维度** |
| 异常筛选快捷入口（F-TI-04） | 汇总条上的一个按钮，等价于「签发状态 ∈ {S-TI-4, S-TI-5}」，点击后筛选条件在筛选区可见、可清除。**不做成隐藏的特殊视图** |
| 签发时间区间 | 按签发完成时间（D-TI-07）筛选，仅对 `S-TI-3` 有意义 |
| 排序 | 默认按收单时间倒序（沿用 WS-313）。**金额排序仍受 WS-313 CU-06 约束**：未选定单一币种时禁用 |

### 9.3 签发概况汇总条（F-TI-03，`C-O-TI-01`）

| 项 | 规则 |
| --- | --- |
| 位置 | 清单顶部，位于 WS-313 已有的按币种分组金额汇总**之上**，不替换它 |
| 统计口径 | 当前**筛选条件下**的各状态笔数：已签发 / 待签发 / 签发中 / 签发失败 / 结果待确认 / 不予签发。切换筛选时同步刷新 |
| 时间维度 | 默认统计当日（按账户时区的自然日，带时区标注）；提供「当日 / 全部」切换 |
| 交互 | 每个状态数字可点击，等价于把该状态加入筛选 |
| 金额 | **汇总条只统计笔数，不出现金额。** 金额汇总维持 WS-313 的按币种分组口径，**页面任何位置不得出现跨币种总额**（CU-01～CU-05）。代币数量同理不与法币金额混算 |
| 异常入口 | 「需处理 N 笔」按钮，N = 签发失败 + 结果待确认，点击执行 F-TI-04 |

### 9.4 列表行上的动作

| 状态 | 可见动作 | 权限 |
| --- | --- | --- |
| S-TI-1 待签发 | 无 | — |
| S-TI-2 签发中 | 无 | — |
| S-TI-3 已签发 | 「查看凭证」（进详情页锚定到代币与链上凭证区块） | `asset_inventory.view` |
| S-TI-4 签发失败 | 「重试」；原因为缺汇率时**额外**出现「去配置汇率」 | `asset_inventory.issue_retry` / `fx_rate.manage` |
| S-TI-5 结果待确认 | 「查询链上状态」。**不渲染重试按钮** | `asset_inventory.issue_retry` |
| S-TI-6 不予签发 | 无 | — |

- 行内动作对**无权限账号不渲染**（不做灰化，避免暗示可用），唯一例外是 L-03 定义的「去配置汇率」。
- 勾选框**仅 `S-TI-4` 行可勾选**，其余状态勾选框禁用并给出 hover 说明（沿用 WS-313 AC-DS-04 的手法）。

### 9.5 空态与边界

| 情形 | 表现 |
| --- | --- |
| 清单无任何资产 | 沿用 WS-313 空态文案「暂无已同步的资产」，不提示失败与异常 |
| 筛选后无结果 | 「没有符合条件的资产」+ 清除筛选入口 |
| 异常筛选结果为 0 | 汇总条「需处理 0 笔」按钮置为不可点，并展示「当前没有需要处理的签发异常」 |

## 10. 资产详情页（P-O-DS-02）

> 同样是 WS-313 已定义的页面。WS-313 已有的全量业务字段、确权信息快照、钱包地址脱敏缩略展示、同步链路时间线**继续有效**。本模块在其下**新增三个区块**，顺序如下。

### 10.1 代币与链上凭证区块（F-TI-08）

| 字段 | 展示规则 |
| --- | --- |
| 铸造数量 | 已签发时展示实际铸造数量 + 单位；未签发展示「尚未签发」 |
| 所属合约 | 默认**应收账款铸币合约**，展示合约名称 + 合约地址（脱敏缩略 + 可复制） |
| 所属链 | 链名称 |
| 交易哈希 | 脱敏缩略 + 可复制 + **区块浏览器跳转**（新窗口） |
| **实际收币地址** | 取自链上交易的实际到账地址，与 10.3 推送来的数币地址**并列展示**，便于事后核对 |
| 签发完成时间 | 链上确认时间，UTC 存储，按账户时区渲染并带时区标注 |

**展示口径整段引用 WS-308『01-国际化基线.md』第 5 / 6 / 8 节，本模块不另定义。** 未签发时整个区块保留但内容为空态，不隐藏——隐藏会让运营人员误以为字段不存在。

**不做实时读链**：本区块所有数值取自签发时落库的记录，不在页面打开时调用链上接口查询余额或总量（N-06）。

### 10.2 换算过程区块（F-TI-09）——**本模块可追溯性的核心**

按固定顺序、单向展示一条完整链路，**每一段都取自签发时刻的快照，不重算**：

| 顺序 | 展示项 | 说明 |
| --- | --- | --- |
| 1 | 原金额 + 币种 | 取资产字段 D-DS-08 / D-DS-07 |
| 2 | 所用汇率值 | 6 位小数，`1 <原币种> = X USD` |
| 3 | 汇率生效时间 | 该汇率版本的生效时间，带时区标注 |
| 4 | 汇率来源说明 | 运营人员在汇率管理里填写的来源文本 |
| 5 | 换算后美元金额 | 截断后的 2 位小数值 |
| 6 | 代币数量 | 1 美元 = 1 代币 |
| 7 | **被截断部分** | 显式展示，如「截断 0.004 USD」；无截断时展示「无截断」 |

| 项 | 规则 |
| --- | --- |
| 快照时机 | **提交链上交易之前**完成快照并落库。先快照后提交，避免交易已发出而换算依据丢失 |
| 不重算【红线】 | 快照落库后，无论汇率表如何变化，本区块的展示值**永不改变**。见 AC-FX-14 |
| USD 资产 | 不走换算，但**仍写入并展示汇率快照**（汇率值记 `1.000000`，来源记「系统内置」），保持记录结构一致 |
| 未签发资产 | 区块保留，展示「尚未签发，暂无换算记录」；**不展示按当前汇率预估的数量**——预估值会被误当成承诺 |
| 重试后 | 每次重试**重新取当时的有效汇率并重新快照**，覆盖上一次的快照值；历史快照在签发时间线中留痕（F-TI-11） |

### 10.3 数币地址区块（F-TI-10）

| 项 | 规则 |
| --- | --- |
| 展示内容 | 推送来的数币地址（D-DS-05） |
| 脱敏 | 缩略前 6 位 + `…` + 后 4 位，提供复制按钮取完整值，hover 展示完整地址（沿用 WS-313 与 WS-308 脱敏基线） |
| 缺失时 | **本区块不存在"缺失"分支**——缺地址的资产不会入库（第 8 章）。若因存量脏数据出现空值，按 11.5 的防御口径展示「地址缺失，已拦截签发」并标红 |
| 已签发后 | 与 10.1 的「实际收币地址」并列展示；**两者不一致时页面显式高亮提示**，供运营人员对外应答时说明 |
| 日志 | 完整地址**不得进入日志与任何通知参数**（沿用 WS-313 契约级约束 5） |

### 10.4 签发时间线（F-TI-11）

| 项 | 规则 |
| --- | --- |
| 形态 | 沿用 WS-313 8.3「同步链路时间线」的形态，作为**独立的第二条时间线**展示在同步链路时间线之下，两者不合并 |
| 顺序 | 按时间**正序** |
| 事件类型 | 收单成功 → 自动触发 → 交易提交（含哈希） → 链上确认成功 / 链上回执失败 / 超时 → 查询链上状态（含查询结果） → 人工重试（含操作人） → 状态变更为不予签发（含原因） |
| 留痕内容 | 每条含：时间（UTC 存储、按账户时区渲染带时区标注）、事件类型、操作人（系统事件记「系统」）、关键值（哈希 / 原因码 / 汇率版本） |
| 【红线】只增不改 | 时间线条目**不可编辑、不可删除**，任何状态回退也只追加新条目，不修改旧条目 |

## 11. 自动签发、重试与异常处置

### 11.1 触发时机（简报 Q-C 定值）

| 路径 | 规则 |
| --- | --- |
| **收单即触发** | 收单成功、资产写入清单后**立即**发起一次签发前置校验与触发。这是默认路径，正常情况下资产在 `S-TI-1` 停留极短 |
| **定时补扫** | 每 **10 分钟**一轮，兜住收单即触发未覆盖到的情形 |
| 补扫周期的可配置性 | 10 分钟为产品定值；如需调整属配置项变更，不改页面与流程 |

### 11.2 定时补扫的处理范围（**本 PRD 的裁定，防超发的关键约束**）

补扫**只处理从未提交过链上交易的资产**：

| 状态 | 补扫是否处理 | 理由 |
| --- | --- | --- |
| `S-TI-1` 待签发（滞留） | ✅ 处理 | 从未提交过交易，重新走前置校验并触发，无超发风险 |
| `S-TI-4` 签发失败 · **校验类**（缺该币种有效汇率） | ✅ 处理 | 该资产**从未提交过链上交易**，失败发生在提交之前。汇率补配之后条件已具备，系统应自动恢复，不必等人工点重试 |
| `S-TI-4` 签发失败 · **链上类**（链上回执失败） | ❌ **不处理** | 已向链上提交过交易。自动重发存在超发风险，只允许人工重试 |
| `S-TI-5` 结果待确认 | ❌ **不处理** | 见 7.2【红线】。必须先由人工查询链上状态 |
| `S-TI-2` / `S-TI-3` / `S-TI-6` | ❌ 不处理 | 在途或终态 |

> 换句话说：**系统只会自动重发"从没上过链"的资产**。这条区分是把"缺汇率"落在 `S-TI-4` 而不新增第七个状态的前提，也是补扫不会制造超发的保证。

### 11.3 签发前置校验（触发时执行，顺序固定）

任一步不通过即终止并落对应状态，不继续往下走：

| 顺序 | 校验项 | 判定 | 不通过的落点 |
| --- | --- | --- | --- |
| 1 | 已存在成功签发记录 | 该资产无 `S-TI-3` 记录 | 直接终止，不做任何事【红线】 |
| 2 | 存在在途交易 | 该资产当前不在 `S-TI-2` | 直接终止，不重复提交 |
| 3 | 数币地址（防御性复核） | 非空且格式合法 | `S-TI-6` 不予签发 · 数币地址缺失（见 11.5） |
| 4 | 是否已到期 | `当前 UTC 日期 ≤ 到期日 D-DS-10` | `S-TI-6` 不予签发 · 应收账款已到期 |
| 5 | 该币种有有效汇率 | 汇率表中该币种存在「生效时间 ≤ 当前时刻 且 启用」的版本 | `S-TI-4` 签发失败 · 缺该币种有效汇率 |
| 6 | 换算后金额 | 截断后 ≥ 0.01 USD | `S-TI-6` 不予签发 · 换算后金额小于 0.01 USD |

**到期判定的口径（简报 Q-E 定值）**：**到期日当天仍可签发**，判定为 `当前 UTC 日期 ≤ 到期日`。比较以 **UTC 日期**进行，以保证与链上时间口径一致；页面展示按账户时区渲染并带时区标注。到期判定在每次触发时实时执行——`S-TI-1` 资产在等待期间跨过到期日的，由下一轮补扫将其转为 `S-TI-6`。

### 11.4 人工重试（F-TI-06，简报 Q-G 定值）

| 项 | 规则 |
| --- | --- |
| 开放范围 | **仅 `S-TI-4`**。`S-TI-5` 不开放（【红线】），终态不开放 |
| 权限 | `asset_inventory.issue_retry` |
| 单条重试 | 行内「重试」按钮，二次确认后执行 |
| 批量重试 | 勾选多条 `S-TI-4` 资产 → 「批量重试」→ 确认弹层（`C-O-TI-02`）展示：勾选条数、按币种分组的金额合计、其中因缺汇率而失败的条数 → 提交 |
| 链上形态 | **N 笔独立交易**，逐条独立成败 |
| 部分成功 | **不整体回滚**。成功的落 `S-TI-2`→`S-TI-3`，失败的留在 `S-TI-4` 并更新原因 |
| 结果反馈 | 逐条结果面板（`C-O-TI-03`），区分成功 / 失败 / 被跳过，失败条目展示原因码与文案，可展开明细并跳转对应资产详情 |
| 批量上限 | 单次最多 **200 条**，超出时提交按钮禁用并提示分批处理 |
| 次数上限 | **不限次** |
| 留痕 | 每次重试记录操作人、时间、结果，累加重试次数（D-TI-09），并在签发时间线追加条目 |
| 并发保护 | 重试提交后该资产立即置 `S-TI-2`，期间任何新的重试请求（含批量中的重复勾选）一律被拒绝并提示「该资产已有在途交易」 |
| 缺汇率的资产被重试 | 若重试时该币种仍无有效汇率，立即返回失败并保持 `S-TI-4`，**不提交链上交易**，同时给出「去配置汇率」入口 |

### 11.5 链上状态查询（F-TI-05）与超时处置

| 项 | 规则 |
| --- | --- |
| 适用状态 | **仅 `S-TI-5`**，且这是 `S-TI-5` **唯一**可做的动作 |
| 动作 | 「查询链上状态」，结果以弹层（`C-O-TI-04`）展示 |
| 查询结果为**已上链且成功** | 资产转 `S-TI-3` 已签发，补全交易哈希、实际收币地址、签发完成时间 |
| 查询结果为**已上链但失败** | 资产转 `S-TI-4` 签发失败，原因取链上回执 |
| 查询结果为**未上链** | 资产转 `S-TI-4` 签发失败 · 链上未查到该交易。**此时才出现重试按钮** |
| 查询本身失败（链节点不可用等） | 状态**保持 `S-TI-5` 不变**，弹层提示「链上状态暂时查不到，请稍后重试查询」。**不得因查询失败而推断为未上链** |
| 留痕 | 每次查询在签发时间线追加一条，含查询时间、操作人、查询结果 |
| 【红线】 | 界面不为 `S-TI-5` 渲染重试按钮；服务端对 `S-TI-5` 的重试请求一律拒绝，绕过前端也不行 |

### 11.6 防御性兜底：存量无地址资产（对应主文档 3.4）

**这不是产品路径，是防御。** 常规情况下清单中不存在无地址资产。

| 项 | 规则 |
| --- | --- |
| 触发 | 签发前置校验第 3 步命中（地址为空或格式非法） |
| 处置 | 落 `S-TI-6` 不予签发 · 数币地址缺失（终态），**不自动重试、不提供页面补录入口** |
| 记录 | 记服务日志告警（该情形意味着不变量被破坏，属于需要技术侧介入的异常） |
| 页面 | 与其他 `S-TI-6` 原因同样展示原因文案；**不提供任何专门的补齐入口或引导** |
| 为什么落终态而不是可恢复状态 | 运营端没有合法的补齐手段（N-09），给一个可恢复状态等于承诺一条不存在的出路。该资产的正确处置是在资产平台补齐地址后重推——而重推会因为它已在库而命中幂等、不会更新。因此这批资产必须由 3.4 的一次性数据体检在上线前清零，而不是留在产品里当常态 |

### 11.7 异常与边界情形汇总

| 情形 | 处置 |
| --- | --- |
| 资产在 `S-TI-2` 期间服务重启 | 恢复后由补扫接管：查询链上状态，据结果落 `S-TI-3` / `S-TI-4` / `S-TI-5`；**不重新提交交易** |
| 同一资产被并发触发（收单即触发 与 补扫 撞车） | 由 11.3 第 1、2 步拦住，只有一笔能进入 `S-TI-2` |
| 汇率在校验通过后、提交交易前被停用 | 以**快照时刻**取到的汇率为准，交易照常提交。快照先于提交（10.2），不存在"用了一个已停用汇率但没记下来"的情形 |
| 到期日字段为空 | 该情形在 WS-313 收单校验中已被必填拦住，运营端不存在此数据；防御性处置同 11.5，落 `S-TI-6` 并记日志 |
| 币种不在枚举内 | 同上，收单已拦截 |
| 链上交易长时间无回执 | 超过**30 分钟**未取得回执即判为超时，落 `S-TI-5` |
| 运营人员在详情页停留期间状态发生变化 | 页面提供手动刷新；执行动作时服务端按**最新状态**二次判定，状态已变则拒绝该动作并提示「该资产状态已变化，请刷新后重试」 |
