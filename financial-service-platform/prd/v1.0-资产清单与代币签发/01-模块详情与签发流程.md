## 8. 收单准入与数币地址（F-TI-16）

> 本章是【修正·简报】修正一的落地。
> **【V1.1 修订】口径的定义方已经变了**：首版写这一章时，WS-313 还把 D-DS-05 定为选填，本章是运营端单方面加严。**WS-313 V1.3 已经把「钱包地址必填、缺失或格式非法即拒收」正式写进它自己的 `D-DS-05`、`V-DS-05` 与 8.1 收单校验链第 2 步**，两边口径现已一致且由 WS-313 承担定义。因此本章从「平行定义一套校验」改为**引用 WS-313 的定义 + 声明本模块对它的依赖**，只保留本模块自己要守的部分，避免两份定义日后漂移。

### 8.1 数币地址的定性

| 项 | 口径 |
| --- | --- |
| 字段来源 | 即 WS-313 推送报文的 **D-DS-05 资产方钱包地址**，随资产一并推送到运营端。**本模块不新增字段、不新增接口** |
| 用途 | 代币铸造完成时的**收币地址**——代币直接进入该地址，不经运营端托管 |
| 必填性 | **必填**。定义方为 WS-313 `D-DS-05`，本模块与之一致 |
| 格式 | `0x` + 40 位十六进制字符，大小写不敏感 |
| 校验时点 | **收单环节**（运营端 F-DS-10 收单校验链第 2 步，定义在 WS-313 8.1） |
| **【V1.1 新增】取值维度** | **企业维度——币归公司。** 取值规则**以 WS-313 `D-DS-05` 原文为唯一事实源**，本 PRD 不另写措辞：「取该资产方企业下**最初完成企业认证的那位成员**绑定的钱包地址（WS-302 `wallet_address`）」。对本模块的实质含义：**同一企业的所有资产，铸出来的代币都进同一个地址**——代币归属的是企业，不是提交资产的那个人 |
| **【V1.1 新增】运营端怎么用它** | **拿到哪个用哪个。** 地址由资产平台按上述规则取好后随报文推来，运营端签发时直接取该资产记录上的这一个值，**不做任何二次解析**：不去查「这个企业该用哪个地址」、不做多地址择一、不做跨资产比对。运营端也**无从判断**该地址是否真的来自最初认证的那位成员——报文里没有这个信息，**取值的正确性由资产平台侧保证**（见 `R-TI-12`） |
| **【V1.1 新增】与 WS-313 的关系** | **一致，无冲突，WS-313 一个字都不用改。** 本模块**不复制**该规则的措辞，只引用 `D-DS-05`——单一事实源在 WS-313，日后它改了这里自动跟随，不会两边漂移 |
| **【V1.1 新增】实务说明（非规则）** | 企业维度之下，「缺地址即拒收」这条规则**预期极少触发**：完成过企业认证的成员必然已绑定钱包地址。规则本身**不变、不放宽**（`AC-TI-43` 仍是红线），只是正常经营中不应看到它生效——真触发了就意味着上游数据异常，值得追查 |

### 8.2 收单校验（**【V1.1 修订】定义在 WS-313，本节只声明依赖**）

收单按逐条处理、任一步失败即终止该条。数币地址的必填与格式校验**由 WS-313 8.1 收单校验链第 2 步承担**，本模块不再平行定义一套：

| 编号 | 本模块的依赖声明 | 对应 WS-313 条款 | 未通过的处置 |
| --- | --- | --- | --- |
| V-TI-01 | 收单时数币地址必须非空 | WS-313 8.1 第 2 步（必填字段齐全，**含 D-DS-05**）、`V-DS-05` | **该条收单失败**，不写入资产清单，回执原因码 `E-DS-02`，字段名「资产方钱包地址」 |
| V-TI-02 | 收单时数币地址必须符合 `0x` + 40 位十六进制 | 同上 | 同上 |

> `V-TI-01` / `V-TI-02` **不是新的校验规则**，是本模块对 WS-313 既有校验的编号化引用，便于本 PRD 的验收项（`AC-TI-43`）指向它们。**规则本身改了以 WS-313 为准**，本 PRD 不得单方面加严或放宽。

**处置口径完全沿用 WS-313 8.1 的收单失败规则，不另立一套：**

| 项 | 规则 |
| --- | --- |
| 数据 | **不写入资产清单、不写入任何失败记录表。** 运营端不因一次失败的收单产生任何可查询数据 |
| 展示 | 运营端**任何页面、任何筛选项都不出现该条资产**，包括清单、详情与空态提示 |
| 回执 | 逐条返回原因码与文案给资产管理端；失败的可见性与处置全部落在资产管理端 |
| 服务端日志 | 仍须记入运营端服务日志用于排障，但**日志不是产品功能**，不提供运营端页面入口 |
| 服务端强制 | 即使绕过资产管理端前端直接调用收单，服务端仍执行 V-TI-01 / V-TI-02，**无例外** |
| **【V1.1 新增】上链前置** | WS-313 V1.3.1 已把**上链存证**设为推送的硬前置：未上链或上链失败的资产在资产管理端就推不出去，绕过前端也被服务端拒绝；收单校验另有一步校验五项链上凭证是否齐全、格式是否合规。**因此凡是进到资产清单的资产，必然已上链且凭证齐全**——这是本模块可以无条件展示凭证的前提，见 8.5 |

### 8.3 补齐路径为什么不需要动幂等规则

【修正·简报】简报 5.3 / Q-A 建议"幂等命中时允许刷新数币地址字段"。**本 PRD 不采纳，WS-313 8.2 的幂等规则维持原文不改。**

理由是一条闭环推理：

1. 缺地址的资产在收单环节被**拒收**，因此**不入库**（8.2）；
2. 不入库意味着运营端不存在这条记录；
3. 资产方在资产平台补齐地址后，资产管理端重推该资产时，运营端按「来源系统标识 + 来源资产 ID」查重**查不到**，因此**不会命中幂等**；
4. 该条走正常入库路径，地址随报文一并带入。

**结论**：补齐路径天然成立，不需要"幂等命中时刷新字段"这类例外。保留幂等规则的原样，也保住了 WS-313 那条红线的完整性——"幂等命中不更新已有记录的任何字段"没有任何缺口。

### 8.4 【V1.1 修订】存量脏数据不在本 PRD 定义

上线前的一次性存量数据体检**由 WS-313 `DEP-DS-07` 定义**，配套的 `R-DS-11`（为什么靠重推补不上）与 `AC-DS-78`（体检后归零）也在那边。本模块只保留两件事：**它是本模块的上线前置条件**（`DEP-TI-02`），以及**本模块自己的不变量**（`AC-TI-44`【红线】：清单中不存在地址为空或格式非法的记录）。首版在这里写过的那套体检流程已删除，不再复述，理由见主文档 3.4。

### 8.5 【V1.1 新增】随资产带入的链上存证凭证

WS-313 V1.3.1 的推送报文携带五项链上存证凭证（`D-DS-20` 存证哈希、`D-DS-21` 交易哈希、`D-DS-22` 区块高度、`D-DS-23` 链 ID、`D-DS-24` 存证时间），运营端以 `D-DS-36` 结构原样存储。

| 项 | 本模块的口径 |
| --- | --- |
| 归属 | **WS-313 的字段，本模块只消费。** 本模块不新增凭证字段、不重算、不补齐、不格式化——凭证一旦被中途加工，它就不再是链上那一份 |
| 完整性 | 凭证不全的资产在收单就被拒收，因此**清单内的凭证恒有值**，不存在「凭证缺失」的展示分支 |
| 展示 | 资产详情页的**链上存证凭证区**（WS-313 `F-DS-22` 已定义展示口径），本模块照引用不另定义；本模块要处理的只有一件事：**把它和本模块自己的铸造凭证区区分清楚**，见 10.5 |
| **【红线】不调链** | 运营端**不连链节点、不调区块浏览器 API、不比对存证哈希真伪**（与 WS-313 `AC-DS-74` 同向）。核查由人完成：点交易哈希跳区块浏览器自行核对 |
| 不引入上链状态 | 运营端**不新增**「上链中 / 上链失败 / 未上链」任何状态标签或筛选项（WS-313 `AC-DS-73`）。运营端只可能看到已上链且推送成功的资产 |

### 8.6 不做人工补录

运营端**不提供**数币地址的人工补录入口（N-09）。运营人员手录的地址与资产方在资产平台注册绑定的地址可能不一致，而**铸错地址不可逆**，风险与收益不成比例。地址的唯一权威来源是资产平台。

## 9. 列表页：资产清单（P-O-DS-01）与代币清单（P-O-TI-01）

> **【V1.1 说明】** 本章原本只写资产清单。代币清单（`P-O-TI-01`）同属列表页且与资产清单成对使用，因此以 9.6～9.9 追加在本章内；**9.1～9.5 的编号已被其他章节引用，本次不重排**（与 WS-313 在 7.8 追加上链章节的处理方式一致）。

> 本页为 WS-313 已定义的页面，本模块**在其上增补**。WS-313 已定的数据范围、原有列、原有筛选、按币种分组汇总、时区标注、脱敏基线等口径**继续有效，本章不重复也不推翻**。

### 9.1 资产清单：本模块新增的列

| 列 | 口径 | 空值表现 |
| --- | --- | --- |
| **签发状态**（F-TI-01） | 取 D-TI-01，值域 `S-TI-1`～`S-TI-6`，以状态标签展示 | 不存在空值——资产入库即为 `S-TI-1` |
| **拦截 / 失败原因**（F-TI-12） | 仅 `S-TI-4` / `S-TI-6` 有值，展示原因文案（分册三 15.1）。列表内为一行截断展示，完整文案在详情页 | 其余状态展示 `—` |
| **代币数量**（F-TI-02） | 仅 `S-TI-3` 有值，展示实际铸造数量 + 单位 | 其余状态一律展示 `—`。**不展示预估值、不展示 0** |
| **重试次数**（F-TI-06 关联） | 该资产被人工重试的累计次数，初始 0 | 0 时展示 `—`，避免噪声 |

> **不新增「同步状态」筛选项**——WS-313 AC-DS-39 明确清单不设该筛选项，本模块不改这一条。签发状态是本模块新增的**另一个**筛选维度，两者不冲突。
> **【V1.1 新增】也不新增「上链状态」列或筛选项**——上链状态是资产管理端独有的字段（WS-313 `D-DS-44`），运营端只可能看到已上链且推送成功的资产，给它一个状态列等于暗示这里能看到未上链的资产。与 WS-313 `AC-DS-73` 同向，反向验收见 `AC-TI-62`。

### 9.2 资产清单：本模块新增的筛选与排序

| 项 | 规则 |
| --- | --- |
| 签发状态筛选 | 多选，值域 `S-TI-1`～`S-TI-6`；**这是本模块的主要筛选维度** |
| 异常筛选快捷入口（F-TI-04） | 汇总条上的一个按钮，等价于「签发状态 ∈ {S-TI-4, S-TI-5}」，点击后筛选条件在筛选区可见、可清除。**不做成隐藏的特殊视图** |
| 签发时间区间 | 按签发完成时间（D-TI-07）筛选，仅对 `S-TI-3` 有意义 |
| 排序 | 默认按收单时间倒序（沿用 WS-313）。**金额排序仍受 WS-313 CU-06 约束**：未选定单一币种时禁用 |

### 9.3 资产清单：签发概况汇总条（F-TI-03，`C-O-TI-01`）

| 项 | 规则 |
| --- | --- |
| 位置 | 清单顶部，位于 WS-313 已有的按币种分组金额汇总**之上**，不替换它 |
| 统计口径 | 当前**筛选条件下**的各状态笔数：已签发 / 待签发 / 签发中 / 签发失败 / 结果待确认 / 不予签发。切换筛选时同步刷新 |
| 时间维度 | 默认统计当日（按账户时区的自然日，带时区标注）；提供「当日 / 全部」切换 |
| 交互 | 每个状态数字可点击，等价于把该状态加入筛选 |
| 金额 | **汇总条只统计笔数，不出现金额。** 金额汇总维持 WS-313 的按币种分组口径，**页面任何位置不得出现跨币种总额**（CU-01～CU-05）。代币数量同理不与法币金额混算 |
| 异常入口 | 「需处理 N 笔」按钮，N = 签发失败 + 结果待确认，点击执行 F-TI-04 |

### 9.4 资产清单：列表行上的动作

| 状态 | 可见动作 | 权限 |
| --- | --- | --- |
| S-TI-1 待签发 | 无 | — |
| S-TI-2 签发中 | 无 | — |
| S-TI-3 已签发 | 「查看凭证」（进详情页锚定到代币与铸造凭证区块） | `asset_inventory.view` |
| S-TI-4 签发失败 | 「重试」；原因为缺汇率时**额外**出现「去配置汇率」 | `asset_inventory.issue_retry` / `fx_rate.manage` |
| S-TI-5 结果待确认 | 「查询链上状态」。**不渲染重试按钮** | `asset_inventory.issue_retry` |
| S-TI-6 不予签发 | 无 | — |

- 行内动作对**无权限账号不渲染**（不做灰化，避免暗示可用），唯一例外是 L-03 定义的「去配置汇率」。
- 勾选框**仅 `S-TI-4` 行可勾选**，其余状态勾选框禁用并给出 hover 说明（沿用 WS-313 AC-DS-04 的手法）。

### 9.5 资产清单：空态与边界

| 情形 | 表现 |
| --- | --- |
| 清单无任何资产 | 沿用 WS-313 空态文案「暂无已同步的资产」，不提示失败与异常 |
| 筛选后无结果 | 「没有符合条件的资产」+ 清除筛选入口 |
| 异常筛选结果为 0 | 汇总条「需处理 0 笔」按钮置为不可点，并展示「当前没有需要处理的签发异常」 |

### 9.6 【V1.1 新增】代币清单：页面定位与边界（P-O-TI-01，F-TI-17）

| 项 | 口径 |
| --- | --- |
| 菜单位置 | **代币管理 → 代币清单**，与同菜单下的「智能合约」（WS-312，只读）平级 |
| 页面性质 | **纯只读视图。** 它是签发结果按「代币」这个视角的第二个切面，数据全部取自资产记录上的签发结果字段，**不新增任何实体、不新增任何字段** |
| 存在的理由 | 对外应答与台账查阅时，运营人员的问法有时是「这个合约今天铸了多少代币」而不是「这笔资产签发了没」。前者按代币视角查更直接 |
| **【红线】边界** | **页面上不存在任何写操作入口**：无签发、无重试、无查询链上状态、无编辑、无删除、无状态变更。凡是会改变资产或签发状态的动作**一律只在资产清单侧**。见 `F-TI-19`【反向】与 `AC-TI-58` |
| 与合并式主结论的关系 | **不冲突。** 合并式解决的是「签发结果这份数据归谁」——它仍然归资产、仍然只有一条记录。代币清单不改变归属，也不产生第二份数据 |
| 数据范围 | **只收录 `S-TI-3 已签发` 的资产所对应的代币。** 其余状态的资产在代币清单里不出现——它们还没有代币。空态文案「暂无已铸造的代币」 |
| 权限 | 沿用 `asset_inventory.view`。**不新增权限点**，也不新增 `token.*` 权限族——它没有独立的对象，也没有独立的动作 |

### 9.7 代币清单：列与筛选

| 列 | 口径 |
| --- | --- |
| 代币名称 | 取所属合约配置的代币名称 / 符号 |
| 数量 | 铸造数量（`D-TI-11`），单位随代币 |
| 所属合约 | 合约名称 + 合约地址（脱敏缩略 + 可复制） |

| 操作 | 「查看对应资产」（9.8），**此列只有这一个入口** |

| 项 | 规则 |
| --- | --- |
| 筛选 | 所属合约、链、铸造时间区间、关键词（代币名称 / 收币地址 / 铸造交易哈希 / 来源资产 ID） |

### 9.8 代币清单：「查看对应资产」跳转（F-TI-18）

| 项 | 规则 |
| --- | --- |

## 10. 资产详情页（P-O-DS-02）

> 同样是 WS-313 已定义的页面。WS-313 已有的全量业务字段、确权信息快照、钱包地址脱敏缩略展示、同步链路时间线**继续有效**。本模块在其下**新增三个区块**，顺序如下。

### 10.1 代币与铸造凭证区块（F-TI-08）

> **【V1.1 改名】** 首版叫「代币与链上凭证区块」。WS-313 V1.3.1 之后，资产详情页上同时存在**两组链上凭证**，再用「链上凭证」这个泛称会让人分不清在看哪一笔交易，因此本区块改名为**铸造凭证**。两者的区分见 10.5。

| 字段 | 展示规则 |
| --- | --- |
| 铸造数量 | 已签发时展示实际铸造数量 + 单位；未签发展示「尚未签发」 |
| 所属合约 | 默认**应收账款铸币合约**，展示合约名称 + 合约地址（脱敏缩略 + 可复制） |
| 所属链 | 链名称 |
| **铸造**交易哈希 | 脱敏缩略 + 可复制 + **区块浏览器跳转**（新窗口）。**这是代币铸造那笔交易的哈希，不是 WS-313 存证交易的哈希**（10.5） |
| **实际收币地址** | 取自链上交易的实际到账地址，与 10.3 推送来的数币地址**并列展示**，便于事后核对 |
| 签发完成时间 | 铸造交易的链上确认时间，UTC 存储，按账户时区渲染并带时区标注 |

**展示口径整段引用 WS-308『01-国际化基线.md』第 5 / 6 / 8 节，本模块不另定义。** 未签发时整个区块保留但内容为空态，不隐藏——隐藏会让运营人员误以为字段不存在。

**不做实时读链**：本区块所有数值取自签发时落库的记录，不在页面打开时调用链上接口查询余额或总量（N-06）。

### 10.2 换算过程区块（F-TI-09）——**本模块可追溯性的核心**

按固定顺序、单向展示一条完整链路，**每一段都取自签发时刻的快照，不重算**：

| 顺序 | 展示项 | 说明 |
| --- | --- | --- |
| 1 | 原金额 + 币种 | 取资产字段 D-DS-08 / D-DS-07 |
| 2 | 所用汇率值 | 6 位小数，`1 <原币种> = X USD` |
| 3 | 汇率生效时间 | 该汇率版本的生效时间，带时区标注 |
| 4 | 汇率来源说明 | 运营人员在汇率管理里填写的来源文本 |
| 5 | 换算后美元金额 | 截断后的 2 位小数值 |
| 6 | 代币数量 | 1 美元 = 1 代币 |
| 7 | **被截断部分** | 显式展示，如「截断 0.004 USD」；无截断时展示「无截断」 |

| 项 | 规则 |
| --- | --- |
| 快照时机 | **提交链上交易之前**完成快照并落库。先快照后提交，避免交易已发出而换算依据丢失 |
| 不重算【红线】 | 快照落库后，无论汇率表如何变化，本区块的展示值**永不改变**。见 AC-FX-14 |
| USD 资产 | 不走换算，但**仍写入并展示汇率快照**（汇率值记 `1.000000`，来源记「系统内置」），保持记录结构一致 |
| 未签发资产 | 区块保留，展示「尚未签发，暂无换算记录」；**不展示按当前汇率预估的数量**——预估值会被误当成承诺 |
| 重试后 | 每次重试**重新取当时的有效汇率并重新快照**，覆盖上一次的快照值；历史快照在签发时间线中留痕（F-TI-11） |

### 10.3 数币地址区块（F-TI-10）

| 项 | 规则 |
| --- | --- |
| 展示内容 | 推送来的数币地址（D-DS-05） |
| **【V1.1 新增】取值口径标注** | 区块内固定标注一句「**该地址为该资产方企业的统一收币地址**（取企业下最初完成企业认证的成员所绑定的钱包地址）」。这句话是为 J-4 对外应答准备的：资产方问「为什么没进我个人的地址」时，运营人员照这句答即可，**不需要再去查规则** |
| 脱敏 | 缩略前 6 位 + `…` + 后 4 位，提供复制按钮取完整值，hover 展示完整地址（沿用 WS-313 与 WS-308 脱敏基线） |
| 缺失时 | **本区块不存在"缺失"分支**——缺地址的资产不会入库（第 8 章）。若因存量脏数据出现空值，按 11.5 的防御口径展示「地址缺失，已拦截签发」并标红 |
| 已签发后 | 与 10.1 的「实际收币地址」并列展示；**两者不一致时页面显式高亮提示**，供运营人员对外应答时说明 |
| 日志 | 完整地址**不得进入日志与任何通知参数**（沿用 WS-313 契约级约束 5） |

### 10.4 签发时间线（F-TI-11）

| 项 | 规则 |
| --- | --- |
| 形态 | 沿用 WS-313 8.3「同步链路时间线」的形态，作为**独立的第二条时间线**展示在同步链路时间线之下，两者不合并 |
| 顺序 | 按时间**正序** |
| 事件类型 | 收单成功 → 自动触发 → 交易提交（含哈希） → 链上确认成功 / 链上回执失败 / 超时 → 查询链上状态（含查询结果） → 人工重试（含操作人） → 状态变更为不予签发（含原因） |
| 留痕内容 | 每条含：时间（UTC 存储、按账户时区渲染带时区标注）、事件类型、操作人（系统事件记「系统」）、关键值（哈希 / 原因码 / 汇率版本） |
| 【红线】只增不改 | 时间线条目**不可编辑、不可删除**，任何状态回退也只追加新条目，不修改旧条目 |

### 10.5 【V1.1 新增】两组链上凭证的区分（详情页最容易看错的一处）

WS-313 V1.3.1 之后，一条资产的详情页上会出现**两笔完全不同的链上交易**。它们都有交易哈希、都能跳区块浏览器，但含义、产生时点、产生方都不同。**必须在页面上区分清楚，否则运营人员对外应答时会给错哈希。**

| | **链上存证凭证区**（WS-313 `F-DS-22`） | **代币与铸造凭证区**（本模块 `F-TI-08`） |
| --- | --- | --- |
| 回答的问题 | 「**这笔债权数据没有被改过**」 | 「**代币铸出来了，铸了多少、给了谁**」 |
| 交易内容 | 关键字段的哈希存证 | 代币铸造 |
| 产生方 | **资产平台**（推送之前） | **运营端**（签发时） |
| 产生时点 | 收单**之前** | 收单**之后**，且仅 `S-TI-3` 有 |
| 字段归属 | WS-313 `D-DS-20`～`D-DS-24` | 本模块 `D-TI-06` / `D-TI-11`～`D-TI-20` |
| 恒有值吗 | **是**（凭证不全的资产收单被拒） | **否**，仅已签发资产有 |
| 交易哈希字段 | `D-DS-21` 存证交易哈希 | `D-TI-06` 铸造交易哈希 |

**页面上的四条硬要求：**

| # | 要求 |
| --- | --- |
| B-01 | 两个区块**分开呈现、各带明确标题**：「链上存证凭证」与「代币与铸造凭证」。**不得合并成一个"链上信息"区块**，也不得把两个交易哈希并排放在同一张表里不加区分 |
| B-02 | 两个区块的交易哈希字段**必须带限定词**——「存证交易哈希」「铸造交易哈希」，**页面上不允许出现无限定词的"交易哈希"** |
| B-03 | 顺序：**链上存证凭证区在前，代币与铸造凭证区在后**，与业务时序一致（先存证后铸造） |
| B-04 | 两个区块的区块浏览器跳转各自独立，按各自的链 ID 取基址；本模块的铸造交易链 ID 取自合约配置，**不复用 WS-313 的 `D-DS-23`**——存证链与铸币链未必是同一条 |

## 11. 自动签发、重试与异常处置

### 11.1 触发时机（简报 Q-C 定值）

| 路径 | 规则 |
| --- | --- |
| **收单即触发** | 收单成功、资产写入清单后**立即**发起一次签发前置校验与触发。这是默认路径，正常情况下资产在 `S-TI-1` 停留极短 |
| **定时补扫** | 每 **10 分钟**一轮，兜住收单即触发未覆盖到的情形 |
| 补扫周期的可配置性 | 10 分钟为产品定值；如需调整属配置项变更，不改页面与流程 |

### 11.2 定时补扫的处理范围（**本 PRD 的裁定，防超发的关键约束**）

补扫**只处理从未提交过链上交易的资产**：

| 状态 | 补扫是否处理 | 理由 |
| --- | --- | --- |
| `S-TI-1` 待签发（滞留） | ✅ 处理 | 从未提交过交易，重新走前置校验并触发，无超发风险 |
| `S-TI-4` 签发失败 · **校验类**（缺该币种有效汇率） | ✅ 处理 | 该资产**从未提交过链上交易**，失败发生在提交之前。汇率补配之后条件已具备，系统应自动恢复，不必等人工点重试 |
| `S-TI-4` 签发失败 · **链上类**（链上回执失败） | ❌ **不处理** | 已向链上提交过交易。自动重发存在超发风险，只允许人工重试 |
| `S-TI-5` 结果待确认 | ❌ **不处理** | 见 7.2【红线】。必须先由人工查询链上状态 |
| `S-TI-2` / `S-TI-3` / `S-TI-6` | ❌ 不处理 | 在途或终态 |

> 换句话说：**系统只会自动重发"从没上过链"的资产**。这条区分是把"缺汇率"落在 `S-TI-4` 而不新增第七个状态的前提，也是补扫不会制造超发的保证。

### 11.3 签发前置校验（触发时执行，顺序固定）

任一步不通过即终止并落对应状态，不继续往下走：

| 顺序 | 校验项 | 判定 | 不通过的落点 |
| --- | --- | --- | --- |
| 1 | 已存在成功签发记录 | 该资产无 `S-TI-3` 记录 | 直接终止，不做任何事【红线】 |
| 2 | 存在在途交易 | 该资产当前不在 `S-TI-2` | 直接终止，不重复提交 |
| 3 | 数币地址（防御性复核） | **取该资产记录上随报文带来的那一个地址**（企业维度，取值规则见 WS-313 `D-DS-05`，本模块只消费），非空且格式合法。**不按企业查表、不做多地址择一、不与同企业其他资产比对** | `S-TI-6` 不予签发 · 数币地址缺失（见 11.6） |
| 4 | 是否已到期 | `当前 UTC 日期 ≤ 到期日 D-DS-10` | `S-TI-6` 不予签发 · 应收账款已到期 |
| 5 | 该币种有有效汇率 | 汇率表中该币种存在「生效时间 ≤ 当前时刻 且 启用」的版本 | `S-TI-4` 签发失败 · 缺该币种有效汇率 |
| 6 | 换算后金额 | 截断后 ≥ 0.01 USD | `S-TI-6` 不予签发 · 换算后金额小于 0.01 USD |

**到期判定的口径（简报 Q-E 定值）**：**到期日当天仍可签发**，判定为 `当前 UTC 日期 ≤ 到期日`。比较以 **UTC 日期**进行，以保证与链上时间口径一致；页面展示按账户时区渲染并带时区标注。到期判定在每次触发时实时执行——`S-TI-1` 资产在等待期间跨过到期日的，由下一轮补扫将其转为 `S-TI-6`。

### 11.4 人工重试（F-TI-06，简报 Q-G 定值）

| 项 | 规则 |
| --- | --- |
| 开放范围 | **仅 `S-TI-4`**。`S-TI-5` 不开放（【红线】），终态不开放 |
| 权限 | `asset_inventory.issue_retry` |
| 单条重试 | 行内「重试」按钮，二次确认后执行 |
| 批量重试 | 勾选多条 `S-TI-4` 资产 → 「批量重试」→ 确认弹层（`C-O-TI-02`）展示：勾选条数、按币种分组的金额合计、其中因缺汇率而失败的条数 → 提交 |
| 链上形态 | **N 笔独立交易**，逐条独立成败 |
| 部分成功 | **不整体回滚**。成功的落 `S-TI-2`→`S-TI-3`，失败的留在 `S-TI-4` 并更新原因 |
| 结果反馈 | 逐条结果面板（`C-O-TI-03`），区分成功 / 失败 / 被跳过，失败条目展示原因码与文案，可展开明细并跳转对应资产详情 |
| 批量上限 | 单次最多 **200 条**，超出时提交按钮禁用并提示分批处理 |
| 次数上限 | **不限次** |
| 留痕 | 每次重试记录操作人、时间、结果，累加重试次数（D-TI-09），并在签发时间线追加条目 |
| 并发保护 | 重试提交后该资产立即置 `S-TI-2`，期间任何新的重试请求（含批量中的重复勾选）一律被拒绝并提示「该资产已有在途交易」 |
| 缺汇率的资产被重试 | 若重试时该币种仍无有效汇率，立即返回失败并保持 `S-TI-4`，**不提交链上交易**，同时给出「去配置汇率」入口 |

### 11.5 链上状态查询（F-TI-05）与超时处置

| 项 | 规则 |
| --- | --- |
| 适用状态 | **仅 `S-TI-5`**，且这是 `S-TI-5` **唯一**可做的动作 |
| 动作 | 「查询链上状态」，结果以弹层（`C-O-TI-04`）展示 |
| 查询结果为**已上链且成功** | 资产转 `S-TI-3` 已签发，补全交易哈希、实际收币地址、签发完成时间 |
| 查询结果为**已上链但失败** | 资产转 `S-TI-4` 签发失败，原因取链上回执 |
| 查询结果为**未上链** | 资产转 `S-TI-4` 签发失败 · 链上未查到该交易。**此时才出现重试按钮** |
| 查询本身失败（链节点不可用等） | 状态**保持 `S-TI-5` 不变**，弹层提示「链上状态暂时查不到，请稍后重试查询」。**不得因查询失败而推断为未上链** |
| 留痕 | 每次查询在签发时间线追加一条，含查询时间、操作人、查询结果 |
| 【红线】 | 界面不为 `S-TI-5` 渲染重试按钮；服务端对 `S-TI-5` 的重试请求一律拒绝，绕过前端也不行 |

### 11.6 防御性兜底：存量无地址资产（**清理流程定义在 WS-313 `DEP-DS-07`**，本节只写本模块的兜底行为）

**这不是产品路径，是防御。** 常规情况下清单中不存在无地址资产。

| 项 | 规则 |
| --- | --- |
| 触发 | 签发前置校验第 3 步命中（地址为空或格式非法） |
| 处置 | 落 `S-TI-6` 不予签发 · 数币地址缺失（终态），**不自动重试、不提供页面补录入口** |
| 记录 | 记服务日志告警（该情形意味着不变量被破坏，属于需要技术侧介入的异常） |
| 页面 | 与其他 `S-TI-6` 原因同样展示原因文案；**不提供任何专门的补齐入口或引导** |
| 为什么落终态而不是可恢复状态 | 运营端没有合法的补齐手段（N-09），给一个可恢复状态等于承诺一条不存在的出路。该资产的正确处置是在资产平台补齐地址后重推——而重推会因为它已在库而命中幂等、不会更新（**这条推理的完整版在 WS-313 `R-DS-11`，本 PRD 不复述**）。因此这批资产必须由 **WS-313 `DEP-DS-07`** 的一次性数据体检在上线前清零，而不是留在产品里当常态 |

### 11.7 异常与边界情形汇总

| 情形 | 处置 |
| --- | --- |
| 资产在 `S-TI-2` 期间服务重启 | 恢复后由补扫接管：查询链上状态，据结果落 `S-TI-3` / `S-TI-4` / `S-TI-5`；**不重新提交交易** |
| 同一资产被并发触发（收单即触发 与 补扫 撞车） | 由 11.3 第 1、2 步拦住，只有一笔能进入 `S-TI-2` |
| 汇率在校验通过后、提交交易前被停用 | 以**快照时刻**取到的汇率为准，交易照常提交。快照先于提交（10.2），不存在"用了一个已停用汇率但没记下来"的情形 |
| 到期日字段为空 | 该情形在 WS-313 收单校验中已被必填拦住，运营端不存在此数据；防御性处置同 11.6，落 `S-TI-6` 并记日志 |
| 币种不在枚举内 | 同上，收单已拦截 |
| 链上交易长时间无回执 | 超过**30 分钟**未取得回执即判为超时，落 `S-TI-5` |
| 运营人员在详情页停留期间状态发生变化 | 页面提供手动刷新；执行动作时服务端按**最新状态**二次判定，状态已变则拒绝该动作并提示「该资产状态已变化，请刷新后重试」 |
| **【V1.1 新增】同一企业的多笔资产带了不同的数币地址** | **运营端不拦截、不提示、不归并**，每笔按它自己带来的地址铸币。企业维度之下这**不应该发生**，若发生属于上游取值实现走样（`R-TI-12`）；但运营端没有判断依据（报文不含企业下的地址集合），**不做这件它做不了的事**，也不因此挡住签发 |
| **【V1.1 新增】认证成员改绑了钱包，前后资产地址不同** | 不拦截。地址是**随资产逐笔快照**过来的，历史资产按它当时带来的地址铸币，**不追溯、不更新已入库资产**——已铸的代币更不会因此变动 |
| **【V1.1 新增】资产方问「为什么币没进我个人绑定的地址」** | J-4 对外应答口径：**代币归属企业，不归属提交资产的个人账号**；收币地址按企业统一取值（WS-313 `D-DS-05`）。详情页的数币地址区块已标注这一口径（10.3） |
| **【V1.1 新增】链上存证凭证与铸造凭证的链 ID 不同** | 正常。存证链与铸币链未必是同一条，两个区块各按自己的链 ID 取区块浏览器基址（`B-04`） |
| **【V1.1 新增】某条链 ID 不在区块浏览器映射表内** | 跳转入口置灰并提示「该链暂未配置区块浏览器」，**凭证本身仍照常展示**（与 WS-313 `AC-DS-71` 同口径） |
