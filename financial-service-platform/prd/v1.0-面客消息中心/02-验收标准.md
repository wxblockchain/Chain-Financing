# 金融服务平台 · 金融服务端 · 面客消息中心 PRD · 02 验收标准

> 本文件是《金融服务平台 · 金融服务端 · 面客消息中心 PRD》的分册。
> 入口与全文导航见主文档 [`v1.0-面客消息中心-PRD.md`](./v1.0-面客消息中心-PRD.md)。

**本文件讲什么**：面客消息中心的全部验收条目 **`AC-F900`～`AC-F999`**，按入口与角标、列表筛选与加载更多、详情已读与进度、消息与待办边界、**端隔离与范围硬约束（反向验收）**、权限与消息池隔离、跳转与失效、会话与登录态、**平台通用性与增量登记**、国际化与文案、非功能可访问性与监控、**对齐 WS-324 V9.0** 共**十二组**组织。

**本文件不讲什么**：每条验收对应的规则本身。规则在主文档与 [`01-页面与展示.md`](./01-页面与展示.md) 中；数据契约的规则在 WS-304 [`02-数据契约与字段.md`](../../../asset-platform/prd/v1.0-消息通知/02-数据契约与字段.md)。**本文件只列判定口径。**

**四条使用说明：**

1. **`AC-F9xx` 编号仅本 PRD 内唯一**，与登录模块家族的 `AC-F01`～`AC-F60` / `AC-F001`～ 不在同一序列，**不要按序号互相映射**。取号依据见主文档 0.3.3。
2. **本文件不验收任何触发口径**——不会出现「某某操作后应发某某消息」这类条目。面客侧有哪些消息、什么时点发、文案怎么写，由各业务 issue 在自己的 PRD 里验收。凡需要构造消息的条目，一律用**虚构的占位业务**，不指名任何真实模块。
3. **本文件不重复验收数据契约本身**（字段必填性、`dedupe_key` 构造、`biz_type` 命名规范等由 WS-304 `03-验收标准.md` 覆盖）。这里只验收**契约在面客侧的落地结果**。
4. **16.5 与 16.9 是本 PRD 的两组硬性验收**，对应用户本轮的两条范围硬约束（只承接 `end = fs`、结构必须支持增量登记）。**这两组不通过，本 PRD 不算交付**。

## 16. 验收标准

### 16.1 入口与角标（`F-F-MC-01`～`F-F-MC-05`）

| # | 验收项 |
| --- | --- |
| `AC-F900` | 已登录面客侧**任意页面**，顶栏均展示通知铃铛 `C-F-MC-01`，位置固定；游客态与受限会话下**不展示** |
| `AC-F901` | 铃铛位于**语言切换器左侧、账号下拉之前**；若面客侧顶栏不提供语言切换器，则位于**顶栏右侧、账号下拉之前**——两种情况下位置都必须固定且可预期 |
| `AC-F902` | 无未读时铃铛**不展示角标，也不展示 `0`** |
| `AC-F903` | 有未读时角标数与服务端未读数一致；超过 `N-F-MC-03`（99）展示 `99+`，且 `99+` 状态下不展示精确数字 |
| `AC-F904` | **已过期的未读消息不计入角标**，但仍能在列表中看到并带「已过期」标签 |
| `AC-F905` | 「目标资源已删除 / 状态已流转 / 无权限」三类跳转失效的未读消息**仍然计入角标**；**映射缺失的消息也仍然计入** |
| `AC-F906` | 账号下拉内存在「消息中心」条目，点击**直达 `P-F-MC-01`**（不经快捷面板、不带筛选条件） |
| `AC-F907` | 点击铃铛展开快捷面板 `C-F-MC-02`，展示最近 **10 条（含已读）**；再次点击铃铛、点击面板外区域、按 **Esc** 均可收起 |
| `AC-F908` | 快捷面板**仅展开不产生任何已读**；滚动经过也不产生已读；点击面板内某条进入详情后该条才变已读。**面板内不存在「全部已读」** |
| `AC-F909` | 页面切到后台时未读数轮询**暂停**；切回前台**立即拉取一次**并重置轮询计时器；未读数接口失败时角标**保留上一次数值**，不清零、不弹错误提示 |

### 16.2 列表、筛选与加载更多（`F-F-MC-06`～`F-F-MC-09`）

| # | 验收项 |
| --- | --- |
| `AC-F910` | 分类筛选项由服务端返回的分类元数据渲染，**前端代码中不存在写死的分类清单** |
| `AC-F911` | **只渲染当前接收者实际拥有消息的分类**，不展示会必然为空的筛选项 |
| `AC-F912` | 构造一条 `category` 为**未登记取值**的消息：列表**正常展示**、分类标签显示「其他 / Other」、**消息不被隐藏**、仍可进详情 |
| `AC-F913` | 分类筛选与已读 / 未读筛选**可叠加**，结果为两者的与关系；状态筛选三档为 全部 / 未读 / 已读，默认「全部」 |
| `AC-F914` | 筛选条件**写入 URL 查询参数**，刷新后筛选态保持；切换筛选时回到首屏且滚动位置回到顶部 |
| `AC-F915` | 列表按**创建时间倒序**；标记某条已读后该行**位置不变、不被移除**（未读不置顶、已读不沉底） |
| `AC-F916` | 同一创建时间戳的多条消息以消息 ID 作稳定次级排序键，加载更多时**不重复、不漏项** |
| `AC-F917` | 列表翻页形态为**「加载更多」按钮**，**不是分页器**；页面上**不存在页码控件、不存在每页条数切换器**；单次加载 `N-F-MC-04`（20）条 |
| `AC-F918` | 加载游标基于 `created_at + message_id`，**不使用 offset**；加载期间有新消息插入顶部时不出现重复项或漏项；没有更多时按钮变为不可点的终止态 |
| `AC-F919` | **首次空态与筛选空态文案不同**，且筛选空态提供「清除筛选」并可一键回到无筛选状态 |
| `AC-F920` | 首屏失败展示错误态与重试；**「加载更多」失败时当前已加载内容不清空**，可重试 |
| `AC-F921` | 单条消息内容异常（如文案模板 key 缺失）时该行降级为「分类 + 时间 + 通用标题」最小形态，**不影响同列表其他行**，且仍可点击进入详情 |

### 16.3 详情、已读与进度展示（`F-F-MC-10`～`F-F-MC-14`）

| # | 验收项 |
| --- | --- |
| `AC-F922` | 消息详情是**整页 `P-F-MC-02` + 独立路由 `/messages/{id}`**，**不是抽屉、不是弹层**；可直接刷新、可后退 |
| `AC-F923` | 打开详情**渲染成功后**该条转已读；详情请求失败或渲染失败**不转已读** |
| `AC-F924` | 列表行内提供显式「标为已读」，操作后该行就地变已读、**不进入详情、位置不变** |
| `AC-F925` | 「全部已读」作用于**当前筛选命中的全部消息**（不是当前已加载的那些），执行前经 `C-F-MC-04` 二次确认，**确认文案说明条数与当前筛选** |
| `AC-F926` | 「全部已读」失败时提示失败并保留原状态，**不出现部分成功的静默处理** |
| `AC-F927` | 本期**不提供「标为未读」**；界面上不存在该入口 |
| `AC-F928` | 从详情返回列表后，**筛选条件、已加载条数与滚动位置全部保留**；刚读过那条就地更新为已读、不重排、不移除 |
| `AC-F929` | 在一个标签页把某条标为已读，其他已打开标签页的角标与列表行状态随之更新；本地广播不可用时降级为轮询同步 |
| `AC-F930` | 进度类消息（`category = business_progress`）在列表中展示**进度型列表项**：分类标签、业务名称、当前节点、**节点状态标签**；`node_index` 与 `node_total` **同时提供时**展示「第 N/M 步」，**缺任一则不展示** |
| `AC-F931` | 进度类消息在详情页**正文之上**展示进度区块；`biz_no` 存在时展示并**支持复制** |
| `AC-F932` | 节点状态标签只有**四个封闭取值**（`in_progress` / `action_required` / `succeeded` / `failed`）；构造第五种取值时不渲染出新的标签形态。**同一笔业务的多次节点更新在列表中是多条独立消息，不做同业务合并** |

### 16.4 消息与待办的边界（`B-1`～`B-5`，**跨 issue 共同验收**）

> 本组与 WS-328 共同验收。**两边引用同一份判据**（主文档 3.3），不各写一版。

| # | 验收项 |
| --- | --- |
| **`AC-F933`** | **`B-5` · 两个计数的归属维度不同：未读数按 `account_id` 计、待办按 `entity_id` 计。** 构造同企业两个员工账号，由员工甲触发一条消息：员工乙登录后**待办带有事、铃铛未读数为 0**，且这一表现**在产品文档与界面说明中被写明**，不作为缺陷记录 |
| `AC-F934` | **`B-1`** · 消息读过后**仍保留在列表里**；待办在业务状态变化后**自动消失**，且待办不存在「已读」状态 |
| `AC-F935` | **`B-2`** · 反向检查：待办带中**不存在**「没有任何可执行动作」的纯告知条目 |
| `AC-F936` | **`B-3`** · 界面上**不存在**待办的已读、待办的删除、待办的历史 / 已办归档入口 |
| `AC-F937` | **`B-4`** · 顶栏未读角标与控制台待办计数是**两个独立数字，任何操作下都不联动**；反向验收：不存在「标记消息已读导致待办消失」或「待办完成导致未读数减少」的路径 |

### 16.5 **端隔离与范围硬约束（反向验收，强制条款）**

> **本组是本 PRD 的第一组硬性验收。** 对应主文档 2.3.2 与 2.3.3。

| # | 验收项 |
| --- | --- |
| `AC-F938` | 提交一条 `end = fs` 且 `recipient_scope ∈ {admin_all, admin_account}` 的消息，**服务端返回拒收，且不落库**（查库确认无记录） |
| `AC-F939` | `end` 字段的独立校验：缺省、空值、未知取值、数组 / 多值形态**一律拒收**，**不按任何默认值兜底**；一条消息只能有一个 `end` |
| **`AC-F940`** | **提交侧**：消息落哪个池由 `end` 决定。构造 `end = asset` / `end = admin` / `end = fs_ops` 的消息各一条，**均不出现在面客侧消息池**；不存在「被本模块接收后再过滤掉」这条路径 |
| **`AC-F941`** | **查询侧**：面客侧**每一个**消息接口（列表、详情、未读数、标已读、全部已读、跳转预检）在服务端强制 `end = fs`；在请求中显式传入 `end=asset`、`end=fs_ops`、空值、数组等形态，返回结果**完全不变** |
| **`AC-F942`** | **异常数据**：人工在池中植入一条 `end ≠ fs` 的记录——**列表不渲染、未读数不计入、详情深链打不开**，并上报一次 `EV-F-MC-06` 数据异常事件。**不出现任何兼容展示或降级展示** |
| **`AC-F943`** | **反向检索**：全文检索本 PRD 与实现代码，`fs` 消息查询路径上**不存在**按 `end` 分支的聚合逻辑；**不存在**任何「合并其他端消息」「跨端未读数」「全平台消息」的入口、菜单、开关、配置项或请求参数 |
| **`AC-F944`** | **两个消息中心是预期形态**：同一自然人在资产平台与金融服务端各自登录，两边**各有一个铃铛、各有一套未读数、各有一份已读状态**，互不影响；在一边标已读，另一边的未读数**不变**。该表现**在产品文档中被写明为本期形态**，不作为缺陷记录 |
| **`AC-F945`** | **只做「收」不做「发」**：全文检索本 PRD、原型与实现，**不存在任何「发消息」「新建通知」「通知设置」「消息偏好」入口** |
| **`AC-F946`** | 本模块的全部界面动作**只有六个**：看、筛、加载更多、标已读、跳过去、返回。清点界面上所有可点击元素，**不存在第七种动作** |
| `AC-F947` | 本模块**不提供**消息内容编辑、人群圈选、发布与撤回、定时发送、站外触达（邮件 / 短信）的任何入口或配置 |

### 16.6 权限与消息池隔离（`F-F-MC-18`、`F-F-MC-19`，**强制条款**）

| # | 验收项 |
| --- | --- |
| `AC-F948` | 用户 A 的消息，用户 B 用**任何方式**（列表 / 详情 / 标已读 / 全部已读 / 跳转预检）访问一律 **404 语义**，**不可与「消息不存在」相区分，不返回 403** |
| `AC-F949` | 未读数接口在服务端强制以「会话 `account_id` + `end = fs`」为查询条件，**忽略请求参数里任何形式的接收者标识与 `end`** |
| `AC-F950` | **同一钱包地址同时注册为资产方与资金方**时，两个身份的消息与未读数**完全隔离，互不可见** |
| `AC-F951` | 服务端任何消息接口的查询条件里**不出现** `email` / `wallet_address` / `verification_status` / `application.status`；归属一律按对外契约四字段的 `account_id` 判定 |
| `AC-F952` | 「全部已读」的作用范围在服务端强制收敛到「本人可见集 ∩ 当前筛选」，构造越界参数不能扩大作用范围 |
| `AC-F953` | **消息 ID 不可枚举**；**不存在批量取消息接口** |
| `AC-F954` | 同企业其他员工**看不到**同一条消息（`recipient_scope = account` 的直接结果），且该表现被写明（见 `AC-F933`） |
| `AC-F955` | 跳转预检**不泄漏目标资源的存在性**：对不存在的资源与无权限的资源，预检返回不可据以区分两者 |
| `AC-F956` | **反向验收**：全文检索本 PRD 与实现代码，`end = fs` 的路径上**不存在 `admin_all` 分支** |
| `AC-F957` | `visible_from` 字段**保留在契约中未被删除**，且在面客侧恒不触发（构造任意面客消息，可见性不受该字段影响） |

### 16.7 跳转与失效（`F-F-MC-15`～`F-F-MC-17`）

| # | 验收项 |
| --- | --- |
| `AC-F958` | 提交一条 `end = fs` 且 `page_target` 取 `P-A*` / `P-M*` / `P-O*` 的消息，**服务端拒收** |
| `AC-F959` | `page_target` 取 `fs` 端已登记段位内的编号时跳转正常直达，**且不做预检** |
| `AC-F960` | 同时填写 `biz_ref` 与 `page_target` 的消息**服务端拒收**；消息实体中**不存在完整 URL 字段** |
| `AC-F961` | **构造一条 `biz_type` 未登记的 `fs` 消息**：列表正常展示、可进详情、**详情无跳转按钮、无任何说明文案**、角标计入、前端上报一次 `EV-F-MC-05` 事件 |
| `AC-F962` | **「无跳转」形态**：详情页不渲染跳转按钮、**不展示任何说明文案**，操作区只有「返回列表」；界面上与映射缺失**完全一致**（差别只在是否上报 `EV-F-MC-05`） |
| `AC-F963` | 预检在**进入详情页时执行一次**，**列表页不做预检**；预检超时 `N-F-MC-05`（3 秒）时按失败处理并**放行跳转** |
| `AC-F964` | 预检返回 `resource_deleted` / `state_changed` / `no_permission` 时按钮**禁用而非隐藏**，带说明条，**正文完整展示**；禁用原因**可被键盘与读屏获取** |
| `AC-F965` | 已过期消息：**不渲染跳转按钮、不展示说明条**、带「已过期」标签、**正文完整展示**、不计入角标、仍可在列表中查到 |
| `AC-F966` | **跳转落地页对当前三态无权限时，落受限引导（主干册二 5.2），不是 403 错误页、不是报错 Toast** |
| `AC-F967` | **反向验收**：界面与代码中**不存在任何跳向资产平台的跳转按钮或路径**；**不存在**本模块自建的跨域跳转实现（若将来实现，必须调用主干册一 3.4 的白名单机制与离站告知 `C-F04`）。**前端不存在为「`page_target` 端不一致」写的降级分支** |

### 16.8 会话与登录态（`F-F-MC-20`）

| # | 验收项 |
| --- | --- |
