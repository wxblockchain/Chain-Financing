## 9. 数据与字段

### 9.1 对象关系

| 对象 | 归属 | 本模块的能力 |
| --- | --- | --- |
| **质押申请 `PledgeApplication`（`WS-324 PA-01`～`PA-09`）** | WS-324 定义 | **只读**，外加对 `PA-05`（审核状态）、`PA-06`（结论时间）、`PA-07`（驳回原因）三个字段的**受限写入**——写入只能通过提交结论这一个动作发生 |
| **审核结论 `PledgeReviewDecision`（`RV-01`～`RV-14`）** | **本模块定义** | 完整读写（提交后不可改） |
| 代币 `PledgeRecord`（`WS-324 PL-*`）、代币三态 `PS-*`、链上轴 `CT-*` | WS-324 / WS-318 | **只读**，无任何写能力（`WS-324 D-FIN-84`） |
| 有效质押价值、融资上限、可融金额、质押覆盖状态 | WS-324 | **既不读也不写**（`D-PR-16`） |

**一条申请至多一条审核结论**（`WS-324 C-RV-03`「一次申请只允许一个终结结论」）；重新提交是新的申请编号，因而是新的一条结论记录。

### 9.2 审核结论 `PledgeReviewDecision`（`RV-*`，本模块新增）

| 编号 | 字段 | 类型 | 必填 | 口径 / 校验 | 默认值 |
| --- | --- | --- | --- | --- | --- |
| `RV-01` | 结论记录编号 | 文本 | 系统 | 提交结论时生成，全局唯一稳定；留痕与操作记录按它关联 | — |
| `RV-02` | 关联申请编号 | 引用 | 系统 | 指向 `WS-324 PA-01`；**一个申请编号至多一条结论记录**（唯一约束） | — |
| `RV-03` | 结论 | 枚举 | 是 | `通过` / `驳回`。**只有这两个取值**——不存在「部分通过」「退回修改」「待补正」（`D-PR-01`、`D-PR-10`） | 无 |
| `RV-04` | 结论时间 | 时间 | 系统 | 服务端落库时间，UTC 存储、按平台级国际化基线展示。**通过时它同时是 `WS-324 PA-06` 的结论时间**，即 7 个自然日入池有效期的起算点（`WS-324 D-FIN-81`） | — |
| `RV-05` | 质押协议文件 | 文件列表 | 条件 | **`RV-03 = 通过` 时必填**。PDF / JPG / PNG，单文件 ≤ 10 MB，**1～5 个**（`D-PR-03`）。结论提交后不可替换、不可删除。**不公开**：仅运营端与该申请的资产方可访问，下载须经服务端鉴权 | 空 |
| `RV-06` | 协议归档标记 | 枚举 | 系统 | `生效` / `已失效 · 仅存档`。申请因复核不通过或 7 天届满失效时置为后者（`D-PR-04`）；**该标记不改变文件本身，只改变呈现口径** | `生效` |
| `RV-07` | 审核人标识 | 引用 | 系统 | 运营端账号主键 `ops_admin_id`（`WS-308` 定义），不可变 | — |
| `RV-08` | 审核人姓名快照 | 文本 | 系统 | 结论时刻的姓名 + 工作邮箱快照。**取快照而不是实时关联**：账号改名或停用后，历史结论仍要显示当时是谁裁的 | — |
| `RV-09` | 代币价值合计快照 | 金额 | 系统 | 结论时刻本申请全部代币的代币价值合计（记账本位币 `USD`，取 WS-318 口径）。**只读快照、只用于留痕与指标**，不参与任何覆盖或额度计算（`D-PR-16`、`WS-324 D-FIN-82`） | — |
| `RV-10` | 内部备注 | 文本 | 否 | ≤ 200 字。**仅运营端可见，不透传给资产方**、不进任何通知 | 空 |
| `RV-11` | 归类标签 | 枚举 | **否** | `RV-03 = 驳回` 时**可选**填，取值见 9.4。**仅用于事后统计（`M-PR-03`），不参与任何校验、不影响能否提交、不构成判定口径**（`D-PR-22`）。界面标题为「归类标签（选填，仅用于统计）」，**不叫「驳回类型」** | 空 |
| `RV-12` | 问题代币标注 | 引用数组 | 否 | `RV-03 = 驳回` 时可从本申请代币清单勾选；勾选结果自动生成一行文本插入 `RV-14` 开头，审核人可编辑（`D-PR-02`） | 空 |
| `RV-13` | 原因说明 | 文本 | 条件 | `RV-03 = 驳回` 时**必填**，自由文本 **10～500 字**；禁止纯空白或仅标点。**这是驳回侧唯一的必填业务输入**——判定在线下完成，平台只收下审核人写的结论（`D-PR-20`）。系统**只做非空与长度校验，不校验内容真伪、不做措辞规范化** | 无 |
| `RV-14` | 驳回原因全文 | 文本 | 系统 | 由 `RV-11` + `RV-12` + `RV-13` 合成的一段文本（**`RV-13` 为主体，另外两项为空时对应行不生成**），**原样写入 `WS-324 PA-07` 并原样透传给资产方**（`WS-324 AC-LS-99`），不做二次加工、不截断 | — |

> **为什么合成文本而不是给 `PA-07` 加结构化子字段**：`WS-324 PA-07` 是文本字段且契约要求原样透传，加结构化字段会要求面客端同步改渲染——而本模块不改 WS-324 任何文件（issue 边界）。合成方案下资产方拿到的仍是一段完整、可读、点了名的原因。

**`RV-14` 的合成格式（示意，最终以文案评审为准）**：

```text
【{RV-11 归类标签}】                                    ← 仅在 RV-11 非空时生成
本次申请中以下代币存在问题：{RV-12 勾选到的代币编号，逗号分隔}   ← 仅在 RV-12 非空时生成
{RV-13 原因说明}                                        ← 始终存在，唯一必填
```

**只有第 3 行是必然存在的**——前两行分别在 `RV-11` / `RV-12` 为空时不生成，且生成后都可被审核人编辑或删除（他可能想换一种说法）。**最小形态就是一段纯自由文本**，这正是「线下判定、线上维护信息」下的常态（`D-PR-20`／`D-PR-22`）。

### 9.3 结论回写契约（落 `WS-324 C-RV-03`）

| 项 | 内容 |
| --- | --- |
| **回写字段** | 申请编号（`RV-02`）、结论（`RV-03`）、结论时间（`RV-04`）、审核人标识（`RV-07`）、驳回原因全文（`RV-14`，驳回时）、质押协议引用（`RV-05`，通过时） |
| **对 `WS-324 PA-05` 的影响** | `通过` → `审核通过 · 待入池`；`驳回` → `已驳回`。**只写这两个取值**，`已失效` / `已撤回` 不由本模块产生（`D-PR-12`） |
| **幂等** | 以「申请编号 + 结论」为幂等依据；重复回写**不产生第二条结论记录、不推第二条通知、不改结论时间**。服务端对已有终结结论的申请一律拒绝新结论（`D-PR-07`、`E-PR-3`） |
| **原子性** | 结论落库、`PA-05` 变更、留痕三者同一次事务；通知投递在事务提交后触发，**投递失败不回滚结论**（`E-PR-5`） |
| **不回写的东西** | 不回写代币三态、链上轴、有效质押价值、融资上限、可融金额、覆盖状态中的任何一个（`WS-324 D-FIN-82`/`D-FIN-84`） |

### 9.4 枚举与常量

| 项 | 取值 |
| --- | --- |
| **结论**（`RV-03`） | `通过` / `驳回` |
| **归类标签**（`RV-11`，**选填**） | `代币归属或主体存疑` / `底层应收账款存在问题` / `代币与目标项目不匹配` / `申请材料不完整或不一致` / `其他`。**它是事后统计用的归类，不是系统给出的判定口径**（`D-PR-22`）；不选也能提交，选了也不改变任何校验或流转 |
| **协议归档标记**（`RV-06`） | `生效` / `已失效 · 仅存档` |
| **审核状态**（筛选与展示，`D-PR-14`） | 直接用 `WS-324 PA-05` 的五个取值，**不另造运营端叫法**：`待审核` / `审核通过 · 待入池` / `已驳回` / `已失效` / `已撤回` |
| **申请类型**（展示） | 直接用 `WS-324 PA-04`：`建池首笔` / `追加质押`（两者走同一条审核链路，`WS-324 D-FIN-83`） |
| `N-PR-01` **审核时限** | **2 个工作日**（自提交时间起算）。**需求方 2026-09-17 确认的暂定值，可配置，调整不改任何业务逻辑**（`D-PR-08`） |
| `N-PR-02` 已等待展示粒度 | < 1 小时按分钟 / < 24 小时按小时 / ≥ 24 小时按天 + 小时 |
| `N-PR-03` 协议文件规格 | PDF / JPG / PNG，单文件 ≤ 10 MB，1～5 个（沿用 WS-305 第 6 节基线，**不另定一套**） |
| **入池有效期**（引用，非本模块定义） | 常量 **7 个自然日**（`WS-324 D-FIN-81`，起点 = 结论时间） |
| 记账本位币 | `USD`（`WS-324 D-FIN-13`） |

## 10. 通知契约与 `biz_type`

### 10.1 本模块的通知矩阵

本模块是两条审核结论通知的**触发方**；展示方是面客端（WS-329 消息中心 + WS-324 页面标记）。契约、投递字段与去重规则一律按 `docs/notification-contract/接入指南.md`，**本模块不自定义通知契约**。

| 事件 | 推送 | `biz_type` | `end` | 收件人 | 理由 |
| --- | --- | --- | --- | --- | --- |
| **质押审核通过 · 待入池** | ✅ **必推** | `financing.pledge.review_approved` | `fs` | 提交申请的资产方（`recipient_scope = account`） | 通过后**还要他回来签名付 gas 才算质押成功**；不推他不会知道要回来，7 天后结论就失效了（`WS-324 D-FIN-80`／`D-FIN-81`） |
| **质押审核驳回**（含原因） | ✅ **必推** | `financing.pledge.review_rejected` | `fs` | 同上 | 否定结论且需要重新提交，必须触达；原因（`RV-14`）**原样带上**，否则只能盲目重提（`WS-324 AC-LS-99`） |
| 运营端「有新申请待审」提醒 | ❌ **本期不推** | — | — | — | 见 10.3 |

### 10.2 `biz_type` 登记（本模块的全集，**已合入登记表**）

按接入指南 3.3 第 1 步，接入方须在自己的 PRD 里列出 `biz_type` 全集。**本表定稿，不得更名**（接入指南 3.1）；两条取值与其 `dedupe_key` 构造**已随本版合入** `docs/notification-contract/接入指南.md` 3.4 登记表（`REV-05` 已执行）。

| `biz_type` | `category` | `end` | 跳转形态 | `dedupe_key` 构造 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `financing.pledge.review_approved` | `business_progress` | `fs` | `biz_ref` → `P-LS-02` 操作区 | `{biz_type}:{申请编号 PA-01}` | 审核通过待入池。**一次申请只有一个终结结论**（`WS-324 C-RV-03` 幂等），键不需要带轮次 |
| `financing.pledge.review_rejected` | `business_progress` | `fs` | `biz_ref` → `P-LS-02` 操作区 | `{biz_type}:{申请编号 PA-01}` | 驳回，文案须带 `RV-14` 原文。**重新提交是新的申请编号，天然不撞键**（`WS-324 AC-LS-99`） |

| 编号 | 口径 |
| --- | --- |
| `D-PR-17` | **两个取值沿用 WS-324 V9.4 已公布的写法，逐字不改。** WS-324 分册 8.1.1 在 V9.4 时已把这两条写进它自己的 `biz_type` 全集；本模块作为**触发方**在此正式申请登记，**命名与之完全一致**。理由是硬的：接入指南 3.1「一经登记不得更名」，而 WS-324 已按这两个名字写完了它的通知矩阵与去重构造——换名字等于让一份已入库的 PRD 当场失准。**两份文档列同两条不是重复登记，是同一条契约的触发方与展示方各自声明**（接入指南 3.4 允许同一 `biz_type` 出现在多行） |
| `D-PR-18` | **`end = fs` 而不是 `fs_ops`。** 收件人是资产方，消息要进**金融服务端**的池子。运营端（`fs_ops`）本期不收这两条——审核人自己刚做完裁定，再给他推一条是纯噪声（与 `WS-324` 8.1「链上操作成功不推」同一判断） |
| `D-PR-19` | **登记表已合入，代码层枚举仍须同批跟上。** 未登记时服务端照常接收并投递、只记告警，但前端因映射表无条目而**不渲染跳转按钮**（接入指南 3.3）——资产方会收到一条点不进去的通过通知，而这条通知的全部价值就是把他带回去签名。文档侧的登记（`REV-05`）已随本版完成；按接入指南 3.3 第 3 步，**研发侧的代码层常量须与之同批合入**，这一条仍是提测前的硬前置（与 `WS-324 AC-LS-96` 同一要求） |

### 10.3 为什么本期不给运营端加「有新申请待审」提醒

| 项 | 内容 |
| --- | --- |
| **结论** | 本期**不新增**第三条 `biz_type`。运营端的待审感知靠 `P-O-PR-01` 的待审计数卡与侧栏菜单，不靠站内信 |
| **理由** | ① 审核队列**本身就是运营管理员的工作台**，他每天要打开它——给工作台上已经有的东西再推一条消息，属于接入指南反复强调的「信息过多」；② `recipient_scope` 只能选 `admin_all`（任何一个运营管理员都能处理，按接入指南 2.2 的判据），而 `admin_all` 会**污染所有运营账号的未读数**，每天几十笔申请就是几十条谁都不会点的消息；③ 本模块的 SLA 是 2 个工作日（`N-PR-01`），不是分钟级响应，不需要即时触达 |
| **将来要做的话** | 按接入指南 3.3 **另行申请**，不在本表预留、不预占名字——预留一个没人实现的取值，只会让登记表多一行假数据 |

## 11. 非功能需求

| 维度 | 要求 |
| --- | --- |
| **性能** | 列表首屏（含统计卡）与详情页在常规数据量下 **2 秒内**可交互（目标值，联调校准）；筛选与翻页 **1 秒内**返回；单个 10 MB 协议文件上传给明确进度反馈，**上传中不冻结弹层内其他字段的编辑**（管理端规范第 4 章 Input/Select 的 loading 口径） |
| **安全与鉴权** | ① 全部写动作**服务端鉴权**，界面隐藏或禁用**不构成校验**；② 质押协议文件**不公开**，下载须经服务端鉴权，仅运营端与该申请的资产方可访问，**不得使用可猜测的直链**；③ 结论提交的幂等校验在服务端，前端按钮置灰不作为唯一防线；④ 越权直调写接口一律拒绝且响应**不含业务数据** |
| **一致性** | 结论落库、`WS-324 PA-05` 变更、留痕三者同一事务（9.3）；同一申请在列表、详情、面客端读到的审核状态必须一致 |
| **兼容性** | 桌面基准 **1280 / 1440 / 1920px**：无水平溢出、侧栏不重叠、**表格操作区不裁切**；低于 1280px 时侧栏可收纳，不得把表格挤到不可读（管理端规范第 8 章） |
| **可用性** | 任何失败都必须落到可读原因，**不存在只说「操作失败」的兜底文案**；二次确认之前不产生任何不可逆变更；弹层内报错不丢已填内容（`E-PR-4`） |
| **可访问性** | 每个交互项有可见 `focus-visible`；状态不得**只用颜色**表达（超时标记、结论标签均带文本）；纯图标按钮须有 `aria-label`；支持减少动效 |
| **国际化与展示基线** | 语言、时区、日期、数字、金额、脱敏的展示口径**整段引用** `financial-service-platform/prd/v1.0-账户与登录/01-国际化基线.md` 第 4/5/6/8 节，**本模块不重新定义**；中英文各预留约 30% 文本扩展空间 |
| **留痕** | 结论提交、协议上传、申请入队、资产方重新提交四类动作均留痕（动作人、时间、前后状态、关联申请编号、变更摘要、IP），记录**不可编辑、不可删除** |

## 12. 指标

| 编号 | 指标 | 口径与用途 |
| --- | --- | --- |
| `M-PR-01` | **平均审核时长** | 结论时间 − 提交时间，按工作日口径。直接检验 `N-PR-01` 这个对外承诺是否兑现 |
| `M-PR-02` | **超时率** | 超过 `N-PR-01` 才出结论的申请数 ÷ 审结总数。持续走高说明单人单角色的产能不够，是引入分配或多角色的触发信号（`R-PR-01`） |
| `M-PR-03` | **驳回率与驳回归类分布** | 驳回率按结论统计（口径完整）；归类分布按 `RV-11` 分档，而 `RV-11` **是选填的**（`D-PR-22`），因此**分布只在已打标的样本内成立、不能当作全量**，解读时必须同时看打标覆盖率。某一类长期居高且覆盖率够，说明面客端的提交前校验漏了一道——该补在提交环节而不是靠人工挡 |
| `M-PR-04` | **通过后 7 日入池完成率** | 通过且在 7 天内完成签名入池的申请数 ÷ 通过总数。**这是「通过≠质押成功」这条口径的代价度量**：完成率低意味着大量审核工作最终作废（`R-PR-03`） |
| `M-PR-05` | **驳回后重提率与重提间隔** | 被驳回后重新提交的比例与平均间隔。重提率低说明驳回原因没写清楚、资产方直接放弃了，是 `D-PR-02` 有没有真起作用的唯一外部证据 |
| `M-PR-06` | **同一项目的重复驳回次数** | 同一资产方同一项目连续被驳回 ≥ 2 次的占比，反映「整单驳回 + 点名」是否真的帮资产方一次改对（`D-PR-01` 的代价度量） |
| `M-PR-07` | **归类标签打标覆盖率** | 填了 `RV-11` 的驳回数 ÷ 驳回总数。**这是 `M-PR-03` 的可信度前提**，也是判断「选填是否让统计彻底失效」的依据；长期偏低就只用自由文本做人工抽样，不要继续拿分布图做决策（`D-PR-22`） |
