## 15. 验收标准

### 15.0 issue 6 条验收口径对照

| # | issue 验收口径 | 对应 AC |
| --- | --- | --- |
| 1 | 两条入口回跳后的落地处理完全一致，不存在两套落地逻辑（D-F01） | **AC-F25、AC-F26** |
| 2 | 入口 B 跳转前有显式离站告知并展示目标平台名称（D-F02） | **AC-F21、AC-F22** |
| 3 | 影子账号映射键为不可变 `account_id`；服务端拒绝以邮箱或钱包作为映射键（6.2） | **AC-F09、AC-F10、AC-F11** |
| 4 | SSO 全部失败分支回落游客态 + Toast，无错误死胡同；配置类错误另触发运维告警（6.3） | **AC-F15、AC-F16、AC-F17、AC-F18、AC-F19** |
| 5 | 资产端触发全局会话失效后，本端会话在约定时间内失效（S-4，目标 100%） | **AC-F33、AC-F34、AC-F35** |
| 6 | 资产方在本端无法修改邮箱、钱包、企业信息，服务端拒绝（N-02） | **AC-F37、AC-F38、AC-F39** |

### 15.1 SSO 协议（F-F01 / F-F02）

| 编号 | 验收标准 |
| --- | --- |
| AC-F01 | `redirect_uri` 与预登记值做完整精确匹配；构造前缀相同但多一级路径或多一个查询参数的回调地址，服务端拒绝发起 / 拒绝回调 |
| AC-F02 | 同一 `state` 第二次提交被拒绝；同一 `nonce` 第二次出现被拒绝 |
| AC-F03 | 同一授权码第二次换取被拒绝 |
| AC-F04 | `id_token` 验签失败、`iss` / `aud` 不符、`exp` 过期，三种情况均被拒绝并归入 R3 |
| AC-F05 | `code_challenge_method` 为 `plain` 时拒绝发起授权；只接受 `S256` |
| AC-F06 | 时钟偏移在 `N-F13` 容忍范围内不误拒，超出后拒绝 |
| AC-F07 | 入口 B 在对端已有会话时，`prompt=none` 静默返回，用户无需再次输入凭据 |
| AC-F08 | 对端返回 `login_required` 时回退为完整授权，且**回退最多一次**，不出现授权循环 |

### 15.2 影子账号（F-F03 / F-F04）

| 编号 | 验收标准 |
| --- | --- |
| **AC-F09** | 影子账号以 `asset_account_id` 为唯一索引；对端修改邮箱后再次登录，本端仍识别为**同一账号**，不产生第二个账号 |
| **AC-F10** | 服务端**拒绝**任何以邮箱或钱包地址作为映射键的实现；对端钱包为空的用户可正常建号，且不与其他空钱包用户合并 |
| **AC-F11** | `asset_account_id` 建立后不可变，本端无任何修改路径 |
| AC-F12 | 每次 SSO 成功回跳后，快照字段被**整体覆盖**并更新 `last_synced_at`；对端已删除的字段值不会在本端残留 |
| AC-F13 | 快照字段在界面上带「来自资产平台」标注，与本端权威字段视觉可区分 |
| AC-F14 | 快照字段未出现在任何唯一索引中；同一邮箱同时存在资产方影子账号与资金方账号时互不冲突 |

### 15.3 SSO 结果与告警（F-F05 / F-F06）

| 编号 | 验收标准 |
| --- | --- |
| **AC-F15** | E-01～E-07、E-09、E-10 任一发生时，**均回落 T1 游客态 + Toast**，不进错误页 |
| **AC-F16** | 回落后用户停在原本要去的页面的**游客视图**并可继续浏览，不被强制送到首页，也不弹登录页 |

### 15.4 双入口与统一落地（F-F07 ～ F-F09）

### 15.6 会话与登出（F-F11 ～ F-F13）

| 编号 | 验收标准 |
| --- | --- |
| AC-F31 | 会话有效期为 4 小时；界面无「记住我」 |
| AC-F32 | 退出登录后回落 T1 游客态并可继续浏览，**不落到登录页**；对端会话不受影响 |
| **AC-F33** | 资产平台触发全局会话失效后，本端会话在 `N-F11` 内失效 |

| AC-F36 | 会话失效时不暂存表单草稿，仅 Toast 提示内容未保存；SSO 结果、协议同意、会话失效原因均有审计留痕，保留 180 天，且 `id_token` / 授权码 / `code_verifier` 不入日志 |

### 15.8 三态权限机制（F-F15 ～ F-F18）

| 编号 | 验收标准 |
| --- | --- |
| AC-F40 | 三态由「会话态 × 完备度」二维判定；「会话有效但认证被收回」与「认证有效但会话已失效」两种组合均被正确判定，不落进未定义状态 |
| AC-F41 | 契约四字段按册二 8.1 输出；展示类功能只消费四字段，**代码中不存在直读 `verification_status` 做放行判定的实现** |
| AC-F42 | 放行判定只认 `verified`；`partially_verified` 与 `action_required` 均判为 L0 |
| AC-F43 | 用户在对端完成认证后，本端在 `N-F12` 内刷新为 T3，**无需退出重登** |
| AC-F44 | `verified` → 非 `verified` 的降级**不静默**：发站内信且下次进入时显式说明；硬卡点执行前服务端实时复核，陈旧的 `verified` 快照不被放行 |
| AC-F45 | 置灰控件可聚焦、可点击并唤起引导弹层，读屏可读出受限原因；不存在点击无反应的灰按钮 |
| AC-F46 | 引导弹层按册二 8.5.1 入参调用，`return_to` 传入的是主干生成的句柄而非 URL 字符串；弹层不改变任何账户状态 |
| AC-F47 | 「发起融资申请」是资产方链路上**唯一**的硬卡点；T2 可正常浏览、进账户设置、看消息中心，不被全局封锁 |
| AC-F48 | 硬卡点在前端与服务端**双重校验**，服务端返回 403；T2 全局展示常驻补全提示条，可折叠但不可永久关闭 |
