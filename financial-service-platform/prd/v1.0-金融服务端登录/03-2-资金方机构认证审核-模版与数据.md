## 9. 机构信息模版机制 / Institution Form Template

> **用户口径：机构资料「按需自定义模版，后续有具体信息再完善」。** 因此本章定义的是**承载机制**，不是字段清单。字段增减不影响状态流转。

### 9.1 模版驱动 / Template-Driven Form（D-F62，**验收项**）

| 项 | 要求 |
| --- | --- |
| 字段定义来源 | 字段名、类型、必填与否、校验规则、所属分组（步骤）、是否为材料上传槽位、展示顺序、帮助文案、中英标签，**全部以模版配置形式维护并下发**，不固定写死在页面里 |
| 新增 / 调整字段 | = 增加或修改一份模版配置。**不需要改动登录、状态流转、审核流转、权限分档规则**（本条即验收标准 AC-F405 的前半句） |
| 一处定义多处复用 | 填写表单、预览页、只读详情页、驳回回显**共用同一份模版定义**，四处不得各写一套字段清单 |
| 配置缺失时 | 表单区展示错误态并提示联系客服，**不允许降级为「什么都不填也能提交」**（引用资产端 8.4.2 同一口径） |
| 校验强度 | 境内标识码做强校验；**境外编号一律宽松校验**（字符集 + 长度区间），提示但不阻断，以人工审核为准（引用资产端 8.4.3） |
| 材料必填标记 | 每份材料明确标注 `Required / 必填` 或 `Optional / 选填`，界面不使用模糊表述（引用资产端 8.4.3） |

**D-F140**：驳回问题项目录**随模版配置一同下发并绑定到模版字段**。资产端的预置问题项绑定六套固定法域模板，本端字段可自定义，固定目录必然对不上字段（差异见 [`03-3`](./03-3-资金方机构认证审核-分档与验收.md) Δ-6）。

### 9.2 模版版本化 / Template Versioning（D-F63，**验收项**）

| 项 | 规则 |
| --- | --- |
| 版本载体 | 每份模版有版本号；模版内容变更即产生新版本，旧版本保留可查 |
| 申请单记录 | 申请单**必须记录提交时所用的模版版本**；只读展示与审核回看一律按该版本呈现 |
| 变更不影响历史 | 模版变更**不影响已提交的历史申请**——旧申请不得因新模版新增了必填字段而被判定为「缺字段」 |
| 生效范围 | 新版本只对**新创建的草稿**与**新一轮提交**生效 |
| 唯一标识字段变更 | 若新版本更换了被指定为机构唯一标识的字段，历史申请已固化的唯一键**不变**（唯一键一经生成即不可变，引用资产端 9.1） |

**D-F142（草稿跨模版版本的迁移口径）**：用户草稿存在期间模版升级时——① 已填且在新版本仍存在的字段**保留**；② 新版本删除的字段**丢弃**（不再展示、不参与校验）；③ 新版本新增的必填字段**以未填状态呈现**，并在草稿页顶部提示 `The form has been updated. Please complete {N} new required item(s). / 表单已更新，请补充 {N} 项。`。**不静默丢数据，也不拿旧草稿去满足新必填**。

**D-F143（重提时的模版版本）**：驳回后重提按**重提当时生效的模版版本**呈现与校验，申请单的模版版本随之更新为该版本；驳回原因指向的字段已被新版本删除时，该问题项标注 `This field is no longer required. / 该字段已调整`，不阻断重提。

### 9.3 机构唯一标识 / Institution Unique Identifier（D-F64 / D-F65，**验收项**）

> 本节回答一个问题：**平台如何判定「这是同一家机构」**。它是重复申请拦截的依据。

| 编号 | 口径 |
| --- | --- |
| **D-F64** | 无论模版如何定义，**必须有且仅有一个字段被指定为「机构唯一标识」**，作为 D-F46 查重的依据。模版配置指定 0 个或 ≥2 个时**一律拒绝生效** |
| **D-F65** | 取值口径：**境内取统一社会信用代码（USCC）**；**境外取 LEI（全球法人识别编码）优先，其次「注册国家 + 商业登记号」组合** |

**判定原则**（引用资产端 [`02-企业认证与模板.md`](../../../asset-platform/prd/v1.0-实名认证与审核/02-企业认证与模板.md) 9.1，不重写）：唯一性来自**登记机关签发的编号**而非机构名称；编号必须**带作用域**（同一串数字在不同法域可能是两家机构）；比对用归一化值、展示用原样值；唯一键**一经生成即不可变**。

**唯一键构成 / Unique Key Composition**（沿用资产端 9.2 的 `{作用域}:{归一化标识}` 格式与 9.3 的归一化规则，**不改规则、不改数值**）：

| 场景 | 标识类型 | 作用域 | 唯一键示例 |
| --- | --- | --- | --- |
| 境内机构 | `USCC`（统一社会信用代码 / Unified Social Credit Code） | `CN` | `CN:91310000MA1K3XYZ8H` |
| 境外机构（有 LEI） | `LEI`（全球法人识别编码 / Legal Entity Identifier） | `LEI`（全球作用域） | `LEI:5493001KJTIIGC8Y1R12` |
| 境外机构（无 LEI） | `REG_NO`（注册国 + 商业登记号 / Country + registration number） | 注册国 ISO 3166-1 alpha-2 代码 | `SG:202312345K` |

**D-F144（与资产端的差异，见 [`03-3`](./03-3-资金方机构认证审核-分档与验收.md) Δ-4）**：LEI 是**全球唯一**的法人识别码，其唯一键**不带国别作用域**——把 LEI 再拼一个注册国前缀，会让同一法人在换注册地登记后被判成两家机构。资产端无 LEI 口径，这是本 PRD 新增。

**归一化规则**（引用资产端 9.3，六步：全角转半角 → 去首尾空白 → 剔除非字母数字字符 → 字母转大写 → 按模版剥离业务前缀 → 拼接作用域）：

- 归一化**只用于查重比对**；标识的**存储与展示一律保留用户原样输入**。
- 归一化后为空视为无效标识，提交被拦截（与必填校验合并提示）。

**查重时点与占用释放**（引用资产端 9.4，不重写）：

| 时点 | 规则 |
| --- | --- |
| 提交时查重（主拦截点） | 字段校验通过后、申请正式创建前，比对所有**占用中**的唯一键；命中则拦截提交、不创建申请、草稿保留（E-20） |
| 审核通过时二次查重（并发保护） | 运营端点击「通过」、结论正式生效前再查一次；命中则拒绝本次通过，由审核员按重复申请驳回。**这条是对 WS-308 的要求，不是本 PRD 的界面** |
| 占用 / 释放 | `draft` **不占用**（避免有人填一半就把机构占住）；`under_review` 占用；`approved` 占用；变更重审期间**不释放**；`rejected` 释放 |
| 命中提示（他人占用） | `This institution is already registered on the platform. If you believe this is an error, contact support. / 该机构已在平台注册，如有疑问请联系客服。`（**不透露占用方的账号、名称或联系方式**） |
| 命中提示（本账号占用） | `You have already submitted an application for this institution. / 你已提交过该机构的入驻申请。` 并引导至审核进度页 |

> 为什么「审核中」就占用：若只在通过后才占用，两个账号可以并行提交同一家机构，审核员会重复审两次同样的材料，最后还得驳回一个。把成本前置到提交这一刻更划算。

### 9.4 暂拟字段组 / Placeholder Field Groups（**占位示例，不作为验收项**）

| 组 | 字段示例 |
| --- | --- |
| A 机构主体 / Entity | 机构名称（中 / 英）、**机构标识码**、机构类型、注册国家或地区、注册 / 办公地址、成立日期、注册资本与币种、法定代表人或授权代表 |
| B 资质与牌照 / Licences | 营业执照（或等效注册证明）影像、金融业务许可证 / 牌照编号与影像、有效期、经营范围 |
| C 业务联系人 / Contact | 姓名、职务、**联系邮箱**、联系电话 |
| D 业务意向 / Intent | 拟出资规模区间、偏好资产类型、偏好账期（选填，非准入判据） |
| E 结算与链上 / Settlement | 对公结算账户（开户行 / 账号 / 户名）、链上收款地址（默认取已绑定钱包，可另填） |
| F 合规声明 / Compliance | 反洗钱 / 制裁名单声明、受益所有人（UBO）信息、授权书 |

> 本表**仅用于验证承载机制**（分组、必填、材料槽位、唯一标识指定各有样例），**不构成需求、不进验收标准、不得据此实现固定表单**。
