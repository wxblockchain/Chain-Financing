## 7. `DEP-M5` · 三态模型与对外契约字段

> **既定口径来源**：简报第 2 章、5.2、`D-F70`、`D-F47`、`ST-1` / `ST-2`。

### 7.1 三态

| 态 | 判定 |
| --- | --- |
| **T1 游客** | 无会话 |
| **T2 已登录** | 有会话，完备度未达标 |
| **T3 已激活** | 有会话，完备度达标（资产方：资产平台侧 `verified`；资金方：机构资料审核通过） |

| 编号 | 口径 |
| --- | --- |
| **`ST-1`**（简报） | **`T3 → T2` 降级不得静默**：须发站内信 + 下次进入时显式说明（载体见册二 5.5） |
| **`ST-2`**（简报） | **退出登录一律回落 T1 游客态**，不落到登录页（与 `D-F78` 同一条线） |

### 7.2 对外契约四字段（**不得新增第五个字段**）

| 字段 | 类型 | 取值枚举 | 必填 | 默认值 | 业务意义 |
| --- | --- | --- | --- | --- | --- |
| `session_state` | 枚举 | `guest` / `authenticated` | 是 | `guest` | 当前是否有有效会话。**只有两个取值**——「会话即将过期」「受限会话」等不在此字段表达 |
| `identity_type` | 枚举 | `null` / `asset_party` / `funder` | 是 | `null` | 身份类型。`session_state = guest` 时**必为 `null`**；`authenticated` 时**必不为 `null`**——`D-F06` 要求登录必须显式选身份，不存在「已登录但身份未知」 |
| `completeness_level` | 枚举 | `L0` / `L1` / `L2` / `L3` | 是 | `L0` | 完备度档位，**取值范围随身份分支不同**，见 7.3 |
| `account_id` | 标识 | 影子账号或资金方账号主键；游客为 `null` | 是 | `null` | 账户标识。`session_state = guest` 时**必为 `null`** |

| 编号 | 口径 |
| --- | --- |
| **`D-F70`**（简报） | 展示类功能**不得自行读取账户原始状态字段**（如 `verification_status`、`application.status`）做判定，**一律消费上述四项**。同构 WS-302 7.5.3 的既有边界声明——否则每个模块各自解释一遍状态，口径必然漂移 |
| **`D-F186`** | **四字段是一个整体，必须同时取用。** 只读 `completeness_level` 而不看 `identity_type` 会得到错误结论——`L0` 对资产方与资金方是两件不同的事（7.3） |

### 7.3 `completeness_level` 的分支边界（**最容易写错的一条**）

| 档 | **资产方分支** | **资金方分支** |
| --- | --- | --- |
| `L0` | 未完成实名认证 | 机构资料未提交（含从未填写、有草稿未提交、**凭据未齐**） |
| `L1` | **— 不适用** | 已提交，**审核中（锁定，不可编辑）** |
| `L2` | **— 不适用** | 被驳回 |
| `L3` | 已 `verified` | 审核通过 |

| 编号 | 口径 |
| --- | --- |
| **`D-F47`**（简报） | **`L0` / `L1` / `L2` 三档的信息可见性完全一致**；差异只在**提示文案与可执行动作**——L0 可填写与提交、**L1 只能查看进度**、L2 可编辑重提 |
| **`D-F187`** | **资产方分支只有 `L0` / `L3` 两个取值。** 消费方遇到 `identity_type = asset_party` 且 `completeness_level ∈ {L1, L2}`，应视为**数据异常并按 `L0` 保守处理，不得放行**。此条此前只写在 WS-314 册二，属主干口径，**本 PRD 是其定义处** |
| **`D-F188`** | **`L1 → L0` 的回边不存在**（`R-24` / `R-28`）：审核中是**单向锁定态**，只有审核结论能让它离开。任何文档出现 `L1 → L0` 的跃迁一律为过期内容 |

### 7.4 完备度由谁计算

| 编号 / 分支 | 口径 |
| --- | --- |
| **`D-F189`** | **完备度只由服务端计算并输出，前端不自行拼装三态**（同 WS-315 `AC-F285`、WS-316 `D-F131`） |
| 资产方分支的取值 | 由 **WS-314** 按其册二 8.1 从资产平台侧 `verification_status` 映射 |
| 资金方分支的取值 | **`L0` 的凭据未齐部分**由 **WS-315** 决定（`D-F14` 凭据门槛）；**`L0` 已提交与否 / `L1` / `L2` / `L3`** 由 **WS-316** 的审核结论决定 |
| 两侧同时判为未达标时 | 取**更低**的那一档。`L0` 是二者的公共下界，因此不会出现取值打架 |

> **这正是 `Q-F01` 当初不能把主干塞给 WS-315 或 WS-316 任一方的原因**：`completeness_level` 由两方共同决定，塞给任一方都会让另一方去别人的 issue 里改自己的取值。

### 7.5 展示类功能该读哪份文档

| 你要做的事 | 读这里 |
| --- | --- |
| 判断当前用户是谁、处于哪一档 | **本册 7.2**（四字段定义与枚举） |
| 判断某个能力现在可不可用 | **册二 6.3**（矩阵总表）+ `D-F77` |

> 本章只写**产品要定的业务口径**（取值、枚举、必填、校验、默认、业务意义）。存储结构、索引等由开发按本 PRD 自行设计。

### 8.1 回跳句柄登记项

登记内容见册一 3.2。补充校验口径：

| 项 | 校验 | 默认值 |
| --- | --- | --- |

| 编号 | 参数 | 取值 | 说明 |
| --- | --- | --- | --- |

## 9. 非功能需求

| 维度 | 要求 |
| --- | --- |
| **安全** | ① 册一 3.3 的六条判定规则**全部在服务端执行**，前端校验不构成防线；② 矩阵 ⊘ / ❌ 服务端强制（`D-F77`）；③ 脱敏服务端完成（`X-1`）；④ 句柄、`state`、授权码、`code_verifier` **不入日志**；⑤ **不得以 `Referer` / `Origin` 作为信任依据**；⑥ 判定失败原因**不回显给用户**，只进留痕 |
| **可用性** | 回跳失败一律**静默兜底 + Toast**，不报错、不白屏（`RT-5`）；本地存储不可用时静默降级（`E-96`） |
| **一致性** | `P-F50` 与 `C-F01` 文案必须**逐字一致**（`D-F07`）；四字段枚举四册一致（`L0`～`L3` 命名已由覆盖审计核对通过） |
| **可访问性** | 两张身份卡片可键盘操作，tab 顺序为「资产方 → 资金方」；提示条折叠控件有可读标签；弹层打开时焦点进入弹层、关闭后归还原触发元素 |
| **国际化** | 全部文案走平台级[国际化基线](../v1.0-账户与登录/01-国际化基线.md)，默认语言 `en`；**不跨平台引用资产平台的同类章节** |
| **兼容性** | 隐私模式 / 禁用本地存储下**全部主流程可用**，仅失去记忆便利 |

## 10. 指标

> 需求方已明确本期不考虑监控指标（与 WS-315 12.1 同口径）。本章只登记**日后要看时该看什么**，本期不建看板。

| # | 指标 | 为什么值得看 |
| --- | --- | --- |
| 1 | 回跳句柄的**生成数 / 成功消费数 / 兜底数** | 兜底率异常上升通常意味着某个业务前缀漏进了 `N-F30` 清单 |

## 12. 验收标准 `AC-F601`～`AC-F640`

> 每条可独立执行。**`AC-F601`～`AC-F618` 是安全关键项，建议在任何一条链路联调前先过。**

### 12.1 回跳（`DEP-M1`）

| 编号 | 验收点 | 怎么验 |
| --- | --- | --- |
| `AC-F601` | 游客在资产详情页触发受限操作 → 登录完成后**回到该资产详情页且被拦下的操作被重新执行**，无中间页 | 走一遍完整链路 |
| `AC-F602` | 目标为 `https://evil.example/` → **拒绝**，落首页 + Toast，不跳转 | 构造句柄生成请求 |
| `AC-F603` | 目标为 `//evil.example/`（协议相对）→ **拒绝** | 同上 |
| `AC-F604` | 目标为 `/\evil.example` 或含反斜杠的写法 → **拒绝** | 同上 |
| `AC-F605` | 目标为 `%2f%2fevil.example`（编码后仍是协议相对）→ **拒绝**（`D-F164` 一轮解码后判定） | 同上 |
| `AC-F606` | 目标为 `%252f%252fevil.example`（双重编码）→ **拒绝**，且**不做第二轮解码** | 同上 |
| `AC-F607` | 目标为 `/assetsx/1` → **拒绝**（`D-F165` 按完整路径段比较，不做字符串前缀包含） | 同上 |
| `AC-F608` | 目标为 `/assets/../../admin` → 规范化后不在清单内 → **拒绝** | 同上 |
| `AC-F609` | 目标为 `/assets/1@evil.example` → **拒绝** 且记安全留痕（`E-92`） | 同上 |
| `AC-F610` | 目标为 `/assets/1?token=xxx` → **拒绝**（`D-F166` / 册一 3.3.2） | 同上 |
| `AC-F611` | 目标为 `/assets/1?return_to=/x` → **拒绝**（防二次跳转） | 同上 |
| `AC-F612` | 目标为登录流程自身（`P-F50`）→ **拒绝**（`D-F169`），不形成循环 | 同上 |
| `AC-F613` | 句柄**不出现在任何可见 URL 参数、浏览器本地存储、非 `HttpOnly` Cookie 中**（`D-F161`） | 走一遍链路后检查客户端可见位置 |
| `AC-F614` | 同一句柄**消费两次**：第二次按失效兜底（`E-94`）+ 安全留痕 | 重放 |
| `AC-F615` | 在 A 会话生成的句柄拿到 B 会话消费 → **拒绝**（`E-93`） | 双浏览器 |
| `AC-F616`（**反向验收**） | WS-314 / WS-315 / WS-316 三册全文**不含**自建的 `return_to` 解析、跳转、同源白名单校验逻辑 | 三册全文检索 + 走查 |
| `AC-F617` | 句柄超过 `N-F33` 后消费 → 按 `E-91` 兜底，Toast，**不报错、不白屏** | 改配置或等待 |
| `AC-F618` | `Q-M01` 未闭合时发起跨域回跳 → **不跳转**，按兜底处理（`E-95`） | 走资产方入口 B |

### 12.2 类型选择与入口（`DEP-M2`）

| 编号 | 验收点 | 怎么验 |
| --- | --- | --- |
| `AC-F619` | `P-F50` 与 `C-F01` 的两张卡片标题、说明、按钮文案**逐字一致**（`D-F07`） | 文案比对 |
| `AC-F620` | 两张卡片视觉权重相同，**无默认选中、无高亮偏向**（`F-F82`） | 走查 |
| `AC-F621` | 未登录访问 `N-F30` 中标 ✅ 的任一路径 → **直接渲染内容**，无跳转、无遮挡式登录弹层、无登录墙（`D-F78`） | 逐前缀访问 |
| `AC-F622` | 右上角「登录」按钮在游客态**全站常驻**；登录后替换为账号下拉（`F-F84`） | 走查 |
