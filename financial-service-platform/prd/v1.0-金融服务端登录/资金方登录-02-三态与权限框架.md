## 9. 三态与权限框架（**只给框架，不给清单**）

> **本章的范围由需求方本轮口径直接限定：三态命名统一用 `游客` / `登录（未入驻）` / `登录（已入驻）`；本章只写每一态的判定依据与切换时机、登录后落地与回跳的表达、受限时的引导文案口径，以及一张留空的权限矩阵骨架。**
> **本章不列举任何具体功能项，不判定任何页面在某一态下可见或不可见**——需求方已明确这部分不在本 issue 确定。**任何在本章出现的功能条目都是超范围内容。**

### 9.1 三态定义与判定依据

三态的判定**必须在服务端完成**，通过父 issue WS-311 定义的接口契约输出。展示类功能只消费契约字段，**不得自行读取账户原始状态字段做判定**。

| 三态（用户口径） | 判定依据 | 简报对应 | 判定的数据来源 |
| --- | --- | --- | --- |
| **游客** | 无有效会话（契约 `session_state = guest`） | `T1` | 本册（会话，15.1） |
| **登录（未入驻）** | 有有效会话，且 `identity_type = funder`，且**入驻结论尚未生效** | `T2` 资金方 | 会话与身份类型来自本册；入驻结论来自 **WS-316** |
| **登录（已入驻）** | 有有效会话，且 `identity_type = funder`，且**入驻审核已通过且结论有效** | `T3` 资金方 | 同上 |

#### 9.1.1 与简报「会话态 × 完备度」二维矩阵的关系

简报第 2 章用「会话态 `T1`/`T2`/`T3` × 完备度 `L0`～`L3`」两个维度描述状态。**需求方本轮的三态口径取代它作为产品层与权限层的唯一口径**，映射如下：

| 三态 | 简报会话态 | 简报完备度档 | 说明 |
| --- | --- | --- | --- |
| 游客 | `T1` | — | |
| **登录（未入驻）** | `T2` | **`L0` 未提交 / `L1` 审核中 / `L2` 驳回，三档合并** | 与简报既定口径 `D-F47`「`L0`/`L1`/`L2` 三档的信息可见性完全一致」**方向一致**——简报本来就认为这三档权限相同，差异只在提示文案与可执行动作 |
| **登录（已入驻）** | `T3` | `L3` 审核通过 | |

> **[已确认 · 2026-09-10]** 需求方已明确：**按「未提交 / 审核中 / 驳回 在权限上统一算『登录（未入驻）』」处理**，即上表口径。依据是 `D-F47`。此项不再是待确认项，实现按上表执行。
>
> 需要强调的是：**三档合并只针对权限**。`L0` / `L1` / `L2` 各自的**提示文案与可执行动作**仍然不同（`L0` 可填写与提交、`L1` 只能查看进度、`L2` 可编辑重提），这些差异归 **WS-316**，本册不写。

#### 9.1.2 本册在判定中承担哪一部分

三态是本册与 WS-316 **共同**产出的结果，任何一方单独定义都是不完整的。

| 判定要素 | 定义方 | 本册的责任 |
| --- | --- | --- |
| 是否有有效会话 | **本册** | 会话建立、有效期、失效触发（15.1） |
| `identity_type = funder` | **本册** | 建号与登录时写入 |
| 账户是否可登录（`incomplete`/`active`/`locked`/`disabled`） | **本册** | 7.4、15.2；**注意：`incomplete` 不等于「未入驻」**，它只表示凭据未齐 |
| 入驻结论是否生效 | **WS-316** | 本册**只消费不定义**；本册不得复制一份申请状态机 |
| 契约字段的定义与输出格式 | **父 issue WS-311** | 本册按契约输出自己负责的字段 |

> **一处极易做错的地方**：`FunderAccount.status == incomplete`（凭据未齐）与「登录（未入驻）」**不是一回事**。凭据齐全但没提交资料的用户，账户是 `active`，三态仍是「登录（未入驻）」。用 `incomplete` 判三态会漏掉这批人——而他们恰恰是最主要的一批。

### 9.2 状态切换时机

| 从 | 到 | 触发时机（精确到某一步成功之后） | 责任方 |
| --- | --- | --- | --- |
| 游客 | 登录（未入驻） | 三方式任一登录成功、**会话建立之后**（含首登自动建号） | **本册** |
| 登录（未入驻） | 登录（已入驻） | WS-316 审核通过、入驻结论落库之后，**下一次会话状态刷新时生效** | WS-316 产出结论，本册刷新会话态 |
| 登录（已入驻） | 登录（未入驻） | 入驻资质被撤销 / 结论失效 | WS-316 产出结论 |
| 登录（任一） | 游客 | ① 主动退出登录；② 会话到期（`N-F02` 4 小时）；③ 改密码 / 设密码 / 重置密码 / 改邮箱触发的**全部会话失效**；④ 账号被停用 | **本册**（15.1） |

| 编号 | 既定口径 |
| --- | --- |
| **`ST-1`** | **「登录（已入驻）」→「登录（未入驻）」的降级不得静默**：须发站内信 + 用户下次进入时显式说明。降级结论由 WS-316 产出，**通知的触发时点与内容归产出方**；本册只保证会话态随之刷新 |
| **`ST-2`** | **退出登录一律回落游客态，不落到登录页。** 会话到期、会话被全局失效同样回落游客态 + Toast，**不弹登录框、不进错误页** |

> `ST-2` 的理由：本端游客态本来就能浏览。把退出登录做成「跳到只有登录框的页面」，等于把一个还愿意逛的用户挡在门外——而他刚刚做的动作只是退出账号，不是离开平台。

### 9.3 会话态刷新的时机

三态不是前端缓存的值。以下时机**必须**重新向服务端取一次：

| # | 时机 |
| --- | --- |
| 1 | 每次进入需要判定权限的页面 |
| 2 | 登录成功、退出登录、凭据补齐成功之后 |
| 3 | 收到入驻结论相关的站内信之后（由 WS-316 触发） |
| 4 | 会话被服务端判定失效时（接口返回失效 → 立即回落游客态，`ST-2`） |

### 9.4 登录后落地与回跳的表达（**表达归本册，实现归父 issue**）

**本册只定义「用户看到什么」，回跳的参数承载、白名单校验与跳转实现一律调用父 issue 的统一实现（`RT-1`～`RT-5`），本册不自行实现**（公共约束第 1 条）。同源白名单校验只做一边就是开放重定向漏洞。

**落地优先级（自上而下，命中即停）**：

| 优先级 | 条件 | 落地目标 | 用户看到的表达 |
| --- | --- | --- | --- |
| 1 | 存在有效回跳目标（用户是被某个受限操作引导来登录的） | **回到原触发点**，并**重新执行那个被拦下的操作** | 无中间页、无额外提示——用户感觉像「刚才那一下终于生效了」 |
| 2 | 本次是首登自动建号 | WS-316 入驻引导页 | 顶部为建号确认区块 + 凭据保管须知（7.2.6） |
| 3 | 其余 | **资金方默认落地页** | 正常进入 |
| — | 回跳目标校验不通过或已失效 | 按优先级 3 落地 + Toast | **不报错、不白屏**（`RT-5`、`E-15`） |

> **[已确认 · 2026-09-10]** 需求方已明确：**「资金方默认落地页」按平台首页写**。本册不再把它挂为待确认项。若父 issue 后续确定了资金方专属的业务落地页，按其结论替换即可——**替换的是这一格的取值，落地优先级的三条规则不变**。

**优先级 1 的一条硬要求**：回到原触发点后是**重新执行被拦下的操作**，不是「回到那个页面让用户自己再点一次」。用户在资产详情页点了「出资」被引导去登录，登录完回来应当直接进入出资流程——把他放回详情页顶部，他还得再找一遍那个按钮（`US-F08`）。

### 9.5 受限时的引导文案口径

**引导弹层组件 `C-F27` 的定义归父 issue，本册只提供「凭据未齐」这一种情形的内容**（公共约束第 3 条）。其余情形的文案归属如下，**本册不写**：

| 触发者 | 缺什么 | 文案归属 |
| --- | --- | --- |
| 游客 | 没有身份 | **父 issue**（类型选择弹层） |
| 登录（未入驻）· 凭据未齐 | 邮箱或钱包 | **本册**（`C-F22`，见分册 01 的 7.4.3） |
| 登录（未入驻）· 资料未提交 / 审核中 / 被驳回 | 入驻资料或审核结论 | **WS-316** |
| 资产方各态 | — | **WS-314** |

**文案原则（本册提供的文案必须满足，其余情形由各自归属方遵循同一组原则）**：

| 编号 | 原则 |
| --- | --- |
| `D-F71` | **说清缺什么**，不写「无权限」「请先登录」这类不含信息的文案 |
| `D-F72` | **给出可点的去处**，且**带回跳**（9.4） |
| `D-F73` | **说明补完之后能做什么**，成本与收益放在同一句 |
| `D-F74` | 跨平台跳转**必须显式告知即将离开本平台**（本册无跨平台跳转，此条对本册空适用） |
| `D-F75` | 常驻提示条可折叠，**但不可永久关闭**，直到补齐 |
| **`D-F76`** | **过期文案红线**：任何引导文案**不得暗示审核中可以修改或撤回**（如「如需修改请撤回」）。撤回机制已整段删除（简报 `R-24`）。本册的引导文案中不出现「撤回」二字 |
