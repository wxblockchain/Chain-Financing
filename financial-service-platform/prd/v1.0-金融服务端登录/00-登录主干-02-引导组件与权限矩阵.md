## 5. `DEP-M3` · 受限操作引导弹层与常驻补全提示条

> **既定口径来源**：简报第 14 章、`D-F71`～`D-F76`。

### 5.1 两个组件的分工

| 组件 | 触发 | 性质 | 能否关闭 |
| --- | --- | --- | --- |
| **`C-F02` 受限操作引导弹层** | 用户**主动触发**了一个受限能力 | **打断式**——用户此刻正想做这件事，说明缺什么最有效 | 可关闭（回到原页面，**不改变任何状态**） |
| **`C-F03` 常驻补全提示条** | 用户处于「缺东西」的状态，**与当前操作无关** | **非打断式**——持续提醒，但不挡路 | **可折叠，不可永久关闭**（`D-F75`），直到补齐 |

### 5.2 `C-F02` 引导弹层的本体规格

**视觉结构（线框级，自上而下四段，顺序固定）**：

```
┌────────────────────────────────────────┐
│ ① <标题：说清缺什么>                [×] │
│ ② <一句话：补完之后能做什么>            │
│                                        │
│ ③ [ 主按钮：去补齐 ]  ← 必须带回跳      │
│    次按钮 / 稍后再说                    │
│                                        │
│ ④ 补充信息区（仅 L1 / L2 两种情形有）   │
└────────────────────────────────────────┘
```

| 段 | 内容 | 强制口径 |
| --- | --- | --- |
| ① 标题 | **缺什么** | `D-F71`：**不得**写「无权限」「请先登录」这类不含信息的文案 |
| ② 说明 | **补完之后能做什么** | `D-F73`：**成本与收益放在同一句**（「完成实名认证后可发起融资」） |
| ③ 主按钮 | **可点的去处**，**必须带回跳** | `D-F72`；跨平台去处须先过 `C-F04` 离站告知（`D-F74` / `D-F172`） |
| ④ 补充区 | 驳回摘要 / 进度节点 / 客服入口 | 仅 L1、L2 两种情形有 |

**六种触发情形的完整规格**（行来自简报 14 章，「载体」「补充区」「归口文案」三列是本 PRD 补的本体口径）：

| 触发者 | 缺什么 | 载体 | 主按钮去向 | 补充区 | 文案归口 |
| --- | --- | --- | --- | --- | --- |
| **T1 游客** | 没有身份 | **`C-F01` 类型选择弹层**（不是 `C-F02`——此时问题不是「缺什么」而是「你是谁」） | 资产方 → WS-314 入口 B；资金方 → 资金方登录 / 申请入驻 | — | 册一 4.2 |
| **T2 资产方** | 资产平台侧实名认证 | `C-F02` + `C-F03` | **跨平台**跳资产平台用户中心（带 `RT-4`，先过 `C-F04`） | — | WS-314 册二 8.5.4 |
| **T2 资金方（凭据未齐）** | 邮箱或钱包 | **就地补齐弹层**（WS-315 `C-F22`）+ `C-F03` | **原地补齐，不跳走**，补完继续原操作 | — | WS-315 分册 02 的 9.5 |
| **T2 资金方（L0 未提交）** | 机构资料 | `C-F02` + `C-F03` | 入驻引导页（WS-316） | — | WS-316 `03-3` 10.3 |
| **T2 资金方（L1 审核中）** | 等结论 | `C-F02`（**纯只读说明**） | 查看进度 | **进度节点 + 预计时长 + 客服入口**（`D-F53'`） | WS-316 `03-3` 10.3 |
| **T2 资金方（L2 驳回）** | 修改资料 | `C-F02` + 驳回摘要 | 编辑重提 | **字段级驳回原因摘要**（`D-F52'`） | WS-316 `03-3` 10.3 |

| 编号 | 口径 |
| --- | --- |
| **`D-F76`**（简报，**红线**） | **L1 审核中的引导文案不得暗示可以修改**。「如需修改请撤回」属过期文案（`R-24`）；应写「审核中无法修改，如资料有误请联系客服」 |
| **`D-F183`** | **弹层不改变任何账户状态**。它只展示与跳转；**关闭弹层等同于「什么都没发生」** |
| **`D-F184`** | **组件归主干、文案归各链路。** 本 PRD 定义四段结构、按钮行为与回跳接入；每种情形的具体文字由拥有该情形的册提供（上表末列）。**本 PRD 不代写文案，各册也不另建组件** |
| **`D-F185`** | 主按钮点击时**先生成回跳句柄再跳转**（册一 3.2），句柄的「触发能力标识」取被拦下的那一行（6.3）。**顺序不得颠倒**——先跳走再补句柄，用户就回不来了 |

### 5.3 `C-F03` 常驻提示条的本体规格

| 项 | 规格 |
| --- | --- |
| **位置** | 全站壳层内、主内容区上方，**占位而不悬浮**——悬浮条会盖住页面底部内容，而它要长期存在 |
| **展开态** | 一行文案 + 一个主按钮 + 一个折叠控件 |
| **折叠态** | 收起为**一条细条 + 一个图标 + 计数**（多条并存时显示条数），点击重新展开。**折叠态必须仍然可见**——`D-F75` 要求「可折叠但不可永久关闭」，折叠成完全不可见等于关闭 |
| **折叠状态的记忆** | 记在**当前会话内**，会话结束即回到展开态。**不写入长期本地存储**——否则用户折叠一次就再也想不起来要补 |
| **消失条件** | **只有一种：对应的缺失被补齐。** 不提供「不再提示」 |
| **主按钮** | 与 `C-F02` 同样**先生成句柄再跳转**（`D-F185`） |

### 5.4 多条提示并存时的优先级与堆叠规则

**一个资金方可以同时缺凭据、又没提交机构资料**；再叠上降级说明，屏幕上可能出现三条。

| 编号 | 规则 |
| --- | --- |
| **`D-F79`**（**本 PRD 新发的简报级口径**） | **全站同一时刻最多展示一条常驻提示条**，其余以计数与清单表达，**不堆叠、不并列** |
| 优先级 | 自上而下取第一条命中的：① **凭据未齐**（挡住的操作面最广，且补起来最快）→ ② **L2 已驳回**（有明确待办且有时限压力）→ ③ **L0 未提交机构资料** → ④ **T2 资产方未实名认证** → ⑤ **`T3 → T2` 降级说明**（`ST-1`） |
| 多条并存的表达 | 当前条右侧显示「**还有 N 项待完成**」，点击展开一个**清单**（而不是再弹出几条提示条）。清单里每项各自带自己的主按钮 |
| 补齐后的行为 | 当前条消失，**队列中下一条立即接替、位置不变**——避免页面因为提示条消失又出现而跳动 |
| 与弹层的关系 | 提示条与引导弹层**可以同时存在**（一个常驻、一个打断式），但**同一时刻只有一个弹层**；弹层展开期间提示条不重绘 |

### 5.5 降级说明（`ST-1`）

**`T3 → T2` 降级不得静默**（简报 `ST-1`）：资产方认证失效、资金方入驻被撤销时，须发站内信 + **下次进入时显式说明**。显式说明的载体即 `C-F03`（优先级 ⑤），**文案由发生降级的那一册提供**（WS-314 / WS-316），符合 `D-F184`。

## 6. `DEP-M4` · 权限矩阵总表

> **既定口径来源**：简报第 13 章、`D-F77`；行归属映射来自统一段位分配表第 4 章。

### 6.1 取值语义（四档，**不得新增第五档**）

| 取值 | 语义 | 服务端行为 |
| --- | --- | --- |
| **✅** | 完整可见 / 可用 | 正常返回 |
| **◐** | 脱敏可见 | **服务端直接不返回敏感字段**（`X-1`），不是前端遮挡 |
| **⊘** | **置灰**：可见不可点，附引导 | **收到请求照样 403**（`D-F77`） |
| **❌** | 不可见 / 直接拒绝 | 403 |

| 编号 | 口径 |
| --- | --- |
| **`D-F77`**（简报；V4.1 勘误 `ERR-03` 重编，**带撇号的旧写法已作废**） | **⊘ 与 ❌ 全部由服务端强制。** ⊘ 只表示「前端仍画着这个按钮」，服务端收到请求照样 403。**前端隐藏不构成防线** |
| **`X-1`**（简报 5.4） | **脱敏必须在服务端完成**——接口对游客直接不返回敏感字段。前端隐藏在 F12 面前等于没有 |
| **`X-2`**（简报 5.4） | **游客态的排序与筛选只能按区间维度提供**。逐条脱敏会被聚合接口整体绕过：按金额精确排序可用二分法还原精确值 |

### 6.2 两种「空」必须区分（统一段位表 `A-1`，**硬性**）

| 记号 | 含义 |
| --- | --- |
| **⬜** | **「待业务 issue 填」**——这一格该有取值，只是还没人填 |
| **—** | **「不适用」**——该能力在这一列的身份下不存在这个语义（例如资产方没有「填写机构资料」） |

> **不区分的后果**：评审会把待填格当成遗漏，或者反过来把遗漏当成不适用。这是本章最容易被略过、也最容易在评审期造成返工的一条。**本图例必须随表出现，不得省略。**

### 6.4 行归属与冲突裁决流程（`F-F87`）

| 编号 | 规则 |
| --- | --- |
| **`D-F94`**（WS-314 册二已定） | 每一行由**该功能所属的 issue** 填；持表方只做合并与冲突裁决；**同一行不得在两个 issue 里各写一版** |
| **`A-2`**（统一段位表） | **`T2/T3 资金方`列的切分只有一条界线**：凡与**账号 / 凭据 / 会话**有关的行归 **WS-315**；凡与**机构资料 / 申请单 / 审核**有关的行归 **WS-316**。按此判定不会有第三种情况 |
| **`A-3`**（统一段位表） | **新增行由主干登记行号与归属之后，相应册才填取值。任何册不得自行往总表加行** |
| **`R-4`**（WS-315 已定） | 每一行必须能被**三态**唯一判定。若某一行需要区分「审核中」与「未提交」，说明三态不足以表达它——此类行**必须先回到本 PRD 讨论**，不得私自加列 |
| **`R-5`**（WS-315 已定） | 行的粒度是**能力 / 动作**，不是页面。同一页面内不同动作可以落在不同取值上 |
| **`R-6`**（WS-315 已定） | **◐ 的具体字段口径不在矩阵里定义**，由各展示类功能依册三第 7 章契约各自定义；矩阵只定到「该能力在该态下是脱敏的」 |

**冲突裁决流程：**

| 步 | 谁 | 做什么 |
| --- | --- | --- |
| 1 | 发现方 | 在主干所属 issue（WS-314）上登记冲突：**行标识 + 两个候选归属 + 各自的理由** |
| 2 | 持表方（主干） | 先用 `A-2` 判一次。**能判出来的当场判，不上升** |
| 3 | 持表方 | `A-2` 判不出来（既不属账号 / 凭据 / 会话，也不属机构资料 / 申请单 / 审核）——这说明**该行不是登录模块的行**，退回给业务 issue 并从总表移除 |
| 4 | 持表方 | 仍无法判定的，连同 `A-2` 的判定过程一起上交父 issue WS-311 裁决；**在裁决落定前该行保持 ⬜，不得由任一方先填** |

> **为什么禁止「先填了再说」**：一行被两边各填一版之后，评审看到的是两个都言之成理的取值，成本比空着高得多。

### 6.5 矩阵的消费方式

矩阵**不是一份给人看的表，而是服务端判定的依据**。展示类功能按册三第 7 章的四字段定位到列、按能力定位到行，取交叉格的取值。**任何模块不得自行读取账户原始状态字段来推断这张表的取值**（`D-F70`）。
