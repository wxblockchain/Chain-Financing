## 19. 验收标准

### 19.1 三种登录方式与自动建号（`AC-F201`～`AC-F215`）

| 编号 | 验收标准 |
| --- | --- |
| **`AC-F201` ★** | 用**未注册**邮箱走验证码路径登录成功后，系统**自动建号并登入**，`created_via = email_code`，该邮箱视为已验证，无需任何独立注册步骤 |
| **`AC-F202` ★** | 用**未绑定**的钱包地址走签名路径登录成功后，系统**自动建号并登入**，`created_via = wallet_signature` |
| **`AC-F203` ★** | 邮箱密码路径**在任何情况下都不建号**：用不存在的邮箱 + 任意密码提交，数据库中不新增任何 `FunderAccount` 记录 |
| **`AC-F204` ★** | 同一账户先用验证码登录、再用钱包签名登录、再用密码登录，三次登录进入的是**同一个 `funder_account_id`**，账户数据完全一致 |
| `AC-F205` | 三个登录 Tab 在 `P-F20` 同一页面内切换，切换时已填内容不清空、不跳页 |
| `AC-F206` | 登录页**不存在**「记住我」勾选项 |
| `AC-F207` | 登录页**不存在**任何「输入邮箱后自动判定用户类型」的形式：输入邮箱后不发起任何身份判定请求，页面不出现「检测到你是……」类文案 |
| `AC-F208` | 登录后的处理顺序为：凭据校验 → 建号（若首登）→ 停用判定 → 锁定判定 → 建会话 → 协议判定 → 落地。停用账户在**凭据校验通过后**才被告知停用（`E-24`） |
| `AC-F209` | 自动建号成功后**不发送邮件**，但**产出站内信** |
| `AC-F210` | 密码 Tab 下同时存在「忘记密码？」与「没有密码？设置密码」两个入口，点击后进入**同一个** `P-F21` 页面 |
| `AC-F211` | 首登建号完成后进入 WS-316 入驻引导页，页面顶部展示建号确认与**凭据保管须知**文案 |
| `AC-F212` | 在建号后引导页点「稍后再维护」，用户回落「登录（未入驻）」态并展示常驻补全提示条 `C-F23`，**不被封锁任何浏览类功能** |
| `AC-F213` | 会话有效期为 **4 小时**；超过后任意受保护接口返回失效，前端**回落游客态 + Toast**，不弹登录框、不进错误页 |
| `AC-F214` | 退出登录后落到**游客态可浏览的页面**，而不是只有登录框的页面 |
| `AC-F215` | 登录页协议勾选行存在（挂载点）；勾选结果写入 `agreement_version_accepted` |

### 19.2 「申请入驻」与「资金方登录」同链路（`AC-F216`～`AC-F220`）

| 编号 | 验收标准 |
| --- | --- |
| **`AC-F216` ★** | 从「申请入驻」与从「资金方登录」两个入口进入，落到的是**同一个页面** `P-F20`、**同一组接口**；抓包比对两条路径的请求，除入口标识外**完全一致** |
| **`AC-F217` ★** | 代码与 PRD 中**不存在两套凭据校验或建号逻辑**：搜索实现，注册 / 建号只有一处 |
| `AC-F218` | 两个入口的差异**只有** 7.3 表中列出的那几项（标题、副标题、默认 Tab）；其余行为逐项比对一致 |
| `AC-F219` | 从「申请入驻」入口进入但**已有账号**的用户，直接登录成功，不被要求「先注册」，也不产生重复账号 |
| `AC-F220` | 从「资金方登录」入口进入但**没有账号**的用户，用验证码或钱包签名即自动建号成功，不被要求「先去申请入驻」 |

### 19.3 密码与改邮箱（`AC-F221`～`AC-F235`）

| 编号 | 验收标准 |
| --- | --- |
| **`AC-F221` ★** | 密码登录在「邮箱不存在」「账户存在但未设密码」「密码错误」三种情形下，返回的**提示文案、HTTP 状态码与响应耗时量级完全一致**，无法区分 |
| **`AC-F222` ★** | 上述前两种情形**不增加** `failed_attempts`；连续尝试 10 次不会锁定账户 |
| `AC-F223` | 「忘记密码」与「设置密码」两个入口进入同一流程；`P-F22` 的标题**恒为**「设置登录密码」，不因账户是否已设密码而改变 |
| `AC-F224` | `P-F21` 提交邮箱后，**无论该邮箱是否注册**，都展示同一句中性提示并进入验证码输入步骤 |
| `AC-F225` | 密码复杂度校验为 8–20 字符、至少 1 个字母 + 1 个数字，且**不得与原密码相同**；规则清单在输入时实时更新 |
| `AC-F226` | 密码输入框提供**眼睛图标**切换显示 / 隐藏 |
| `AC-F227` | 修改密码成功后：该账户**全部会话失效（含当前设备）**、跳回 `P-F20`、向绑定邮箱发出 `EV-F02` 安全通知 |
| `AC-F228` | 账户原本无密码时，`P-F26` 标题变为「设置登录密码」，且**不出现「当前密码」输入项** |
| **`AC-F229` ★** | 改邮箱流程中**「验证旧邮箱」步骤不可跳过**：跳过该步直接调用提交接口，服务端拒绝 |
| **`AC-F230` ★** | 再认证弹窗展示该账户**当前可用的全部因子**供用户自选。用**钱包签名建号且从未设密码**的账户进入改邮箱流程，能够只用钱包签名完成再认证，**不被要求输入密码** |
| `AC-F231` | 再认证通过后 10 分钟内进行第二次敏感操作，**不重复要求再认证**；超过 10 分钟则重新要求 |
| `AC-F232` | 改邮箱成功后：全部会话失效、跳回 `P-F20` 并提示用新邮箱登录、**向新旧两个邮箱各发一封**通知（`EV-F03` + `EV-F04`） |
| `AC-F233` | 账户**原本无邮箱**时走同一入口，标题变为「绑定邮箱」、**跳过验证旧邮箱步骤**、且**不触发会话失效**，用户留在原页面 |
| `AC-F234` | 新邮箱已被其他账号占用时，提示邮箱不可用，且提示中**不包含**该邮箱属于谁的任何信息 |
| `AC-F235` | `P-F24` 与 `P-F25` 上均展示「这是登录邮箱，业务联系邮箱在入驻资料里单独维护」的说明文案 |

### 19.4 凭据完备性与就地补齐（`AC-F236`～`AC-F244`）

| 编号 | 验收标准 |
| --- | --- |
| `AC-F236` | 凭据门槛判定**只看邮箱与钱包是否同时非空**；已设密码但缺钱包的账户**仍被拦截**，未设密码但邮箱钱包齐全的账户**正常放行** |
| `AC-F237` | 缺凭据时点击「提交机构资料」，在**当前页面**弹出 `C-F22`，**不跳转到其他页面** |
| `AC-F238` | `C-F22` 有缺钱包 / 缺邮箱 / 两项都缺三种形态；两项都缺时在**同一弹层内**分两步完成并展示 `1/2`、`2/2` 步骤指示 |
| `AC-F239` | 在 `C-F22` 内补齐后，**原先被拦下的提交动作被重新执行**，用户已填的表单内容未丢失，且**不需要用户再点一次提交** |
| `AC-F240` | 关闭 `C-F22` 后回到原页面原状态：不产生草稿、不改变 `FunderAccount.status`、不增加任何计数 |
| **`AC-F241` ★** | **绕过前端**直接调用 WS-316 的提交接口，在凭据不完备时**服务端拒绝**——证明校验不只在前端 |
| `AC-F242` | 在 `C-F22` 内完成**首次**邮箱绑定，**不触发会话失效**，用户停留在当前页 |
| `AC-F243` | 凭据补齐后 `FunderAccount.status` 由 `incomplete` 变为 `active`，常驻提示条 `C-F23` 随即消失 |
| `AC-F244` | 凭据未齐时 `C-F23` 全局展示，**可折叠但无法永久关闭**：折叠后刷新页面仍会出现 |

### 19.5 钱包连接与签名（`AC-F245`～`AC-F259`）

| 编号 | 验收标准 |
| --- | --- |
| **`AC-F245` ★** | 钱包地址输入框**支持从剪贴板粘贴**，且粘贴内容的**前后空格被自动去除** |
| **`AC-F246` ★** | 服务端从签名中恢复签名者地址，与手填地址做**大小写不敏感的严格比对**；填入全大写、全小写、混合大小写的同一地址均能通过 |
| **`AC-F247` ★** | 手填地址与实际签名钱包**不一致**时，服务端**拒绝**：既不登录到手填地址对应的账户，也不用签名地址新建账户 |
| `AC-F248` | 前端可先行比对地址，但**关闭前端校验后服务端仍然拒绝**不一致的请求 |
| `AC-F249` | EIP-55 校验和不通过时**提示但不阻断**，全小写地址可正常提交 |
| **`AC-F250` ★** | 点击「签名」**之前**，本端页面上已显示「不发起交易、不消耗 gas、不转移任何资产」的说明文案 |
| `AC-F251` | 上述说明文案旁展示「该钱包地址绑定后不可更换，请确保长期可访问」 |
| **`AC-F252` ★** | 用户在钱包中**拒绝连接**、**拒绝签名**，以及**签名消息过期**、**SDK 加载失败**、**钱包已锁定**五种情形，`failed_attempts` **均不增加** |
| `AC-F253` | 签名消息包含域名、账户地址、链 ID、nonce、签发时间、有效期、用途声明七项；nonce **一次性**，5 分钟后失效 |
| `AC-F254` | 装有多个钱包插件时展示**钱包选择器**，不默认取第一个 provider |
| `AC-F255` | 使用硬件钱包时，UI **不设短超时**：签名耗时 2 分钟仍可成功（在 nonce 5 分钟有效期内） |
| `AC-F256` | 移动端无插件环境下走 WalletConnect 类方案，且页面上存在「改用邮箱登录」的可点入口 |
| `AC-F257` | 已绑定钱包的账户在签名过程中于钱包内**切换到另一个地址**：系统**明确拒绝并说明地址不可更换**，绝不静默改绑 |
| `AC-F258` | 目标地址**已被另一资金方账号绑定**时明确拒绝并提供客服入口，且**不增加** `failed_attempts` |
| **`AC-F259` ★** | 目标地址**已被某资产方影子账号使用**时**正常放行**并建立 / 登入资金方账号，两条记录互不影响 |

### 19.6 锁定与计数（`AC-F260`～`AC-F272`）

| 编号 | 验收标准 |
| --- | --- |
| **`AC-F260` ★** | `failed_attempts` **只统计**三类失败：密码登录失败、钱包验签失败、再认证失败。三者混合累计满 **5 次**触发锁定 |
| **`AC-F261` ★** | **邮箱验证码输错不增加** `failed_attempts`：同一验证码连续输错 **5 次**后**该码作废需重新获取**，账户**未被锁定**，重新获取验证码后可立即登录成功 |
| `AC-F262` | 三类失败**共用一个计数器**：密码错 3 次 + 验签错 2 次即触发锁定（而不是各自算 5 次） |
| `AC-F263` | 首次锁定 **10 分钟**，第 2 次 **30 分钟**，第 3 次及以后维持 **30 分钟** |
| `AC-F264` | 距上次锁定触发满 **24 小时**未再触发时，下次锁定回到 **10 分钟**首档 |
| `AC-F265` | 锁定期间**三种登录方式全部不可用**，且**设置 / 重置密码流程同样不可用**，无任何提前解除入口 |
| `AC-F266` | 锁定期间**不再下发签名消息**：请求签名接口直接被拒 |
| `AC-F267` | 从第 3 次失败起提示剩余可尝试次数 |
| `AC-F268` | 任一方式登录成功后 `failed_attempts` 清零 |
| **`AC-F269` ★** | **锁定判定位于凭据校验之后**：用一个**不存在**的邮箱反复尝试，永远不会得到「账户已锁定」的响应——该响应会泄漏账户存在性 |
| `AC-F270` | 同一 IP 1 小时内累计失败 **20 次**后，该 IP 的后续登录请求**强制先过滑块**；**该 IP 未被封禁**，过滑块后仍可正常提交 |
| `AC-F271` | 账户被锁定时发出 `EV-F05`，**只发邮件、不产出站内信** |
| `AC-F272` | 锁定**自动解除时不发送任何通知** |

### 19.7 滑块、限频与账户设置（`AC-F273`～`AC-F284`）

| 编号 | 验收标准 |
| --- | --- |
| `AC-F273` | **所有**发送邮箱验证码的入口都前置滑块 `C-F20`，无例外：登录页验证码 Tab、`P-F21`、`P-F25` 的旧 / 新邮箱两步、`C-F22` 缺邮箱形态、再认证的邮箱验证码因子 |
| `AC-F274` | 发送限频按邮箱（60 秒间隔 / 5 次每时 / 10 次每日）、IP（20 次每时 / 100 次每日）、设备（10 次每时 / 30 次每日）三维度生效；超限时展示提示与倒计时且**不计入锁定计数** |
| `AC-F275` | 验证码有效期 **10 分钟**，过期后无法使用 |
| `AC-F276` | `P-F24` 为单页 + tab 锚点滚动，「账号信息」与「偏好信息」在同一页 |
| `AC-F277` | `P-F24` 通过右上角账号下拉进入 |
| **`AC-F278` ★** | 钱包地址**已绑定**时，`P-F24` 上**不存在任何**「修改」「更换」「解绑」入口 |
| **`AC-F279` ★** | **绕过前端**直接调用修改钱包地址的接口，**服务端拒绝**，且该拒绝被写入安全审计日志 |
| `AC-F280` | `P-F24` 上**不出现机构资料的任何字段**，包括业务联系邮箱 |
| `AC-F281` | `P-F24` 的「入驻状态」条目为**只读展示**，点击跳转到 WS-316 的页面 |
| `AC-F282` | 账户状态为 `locked` 时展示本次锁定剩余时间；为 `disabled` 时展示客服入口 |
| `AC-F283` | 语言、时区的取值与切换行为符合金融服务平台国际化基线；切换语言后当前页面**不刷新**即完成全部文案替换，已填表单内容不丢失 |
| `AC-F284` | 邮箱、钱包地址在日志与展示中按脱敏基线处理；**验证码、密码明文、签名内容在任何日志中都查不到** |

### 19.8 三态与权限框架（`AC-F285`～`AC-F292`）

| 编号 | 验收标准 |
| --- | --- |
| `AC-F285` | 三态由**服务端**判定并通过主干分册的接口契约输出；前端不自行拼装三态 |
| `AC-F286` | 未登录时三态为**游客**；任一方式登录成功、会话建立后立即变为**登录（未入驻）** |
| `AC-F287` | 凭据齐全但**从未提交入驻资料**的用户，`FunderAccount.status = active`，三态仍为**登录（未入驻）**——**不得**因 `status = active` 就判为已入驻 |
| `AC-F288` | 凭据未齐（`status = incomplete`）的已登录用户，三态为**登录（未入驻）**——**不得**因 `incomplete` 就判回游客态 |
| `AC-F289` | WS-316 审核通过后，用户下次会话状态刷新时三态变为**登录（已入驻）** |
| `AC-F290` | 「登录（已入驻）」降级为「登录（未入驻）」时**不得静默**：产出站内信，且用户下次进入时得到显式说明 |
| `AC-F291` | 退出登录、会话到期、敏感变更触发的全局失效、账号被停用四种情形，**均回落游客态**（而非登录页） |
| `AC-F292` | 存在有效回跳目标时，登录完成后**回到原触发点并重新执行被拦下的操作**；回跳目标失效或校验不通过时落默认落地页 + Toast，**不报错、不白屏** |

### 19.9 风险缓解文案与其他（`AC-F293`～`AC-F296`）

| 编号 | 验收标准 |
| --- | --- |
| **`AC-F293`** | **企业邮箱提示**在四处均在位：建号后凭据保管须知、`P-F24` 登录邮箱条目下方、`C-F22` 缺邮箱形态、`P-F25` 首次绑定邮箱时 |
| **`AC-F294`** | **钱包长期可访问提示**在三处均在位：`C-F21` 请求签名前、`P-F24` 钱包地址条目下方、`C-F22` 缺钱包形态 |
| `AC-F295` | 全册**不存在**「撤回」相关的任何界面元素、状态或文案（`R-24`）；引导文案中不出现「如需修改请撤回」类表述 |
| `AC-F296` | 180 天无活跃且未提交资料的账户被**标记休眠**（记录未被删除）；该账户再次登录后自动恢复为正常状态 |

### 19.10 简报与 issue 点名的 9 条验收口径 → 本册编号对照

**这张表用于交叉核对，确保 issue 描述的验收口径一条不漏。**

| # | issue 描述中的验收口径 | 对应本册编号 |
