## 7. 模块详情

### 7.1 M1 · 首次登录即建号（资金方）

**规则与 `WS-302 7.1` 完全一致**，本节只列出资金方场景下的取值。

| 项 | 口径 | 引用 |
| --- | --- | --- |
| 适用范围 | 邮箱验证码、钱包签名**两条路径**承担首次建号；**取消独立注册流程** | `WS-302 D-01` / `7.1.1` |
| 邮箱密码为何不建号 | 若允许，攻击者可用任意邮箱 + 任意密码创建账户，并据此判断该邮箱此前是否已注册 | `WS-302 D-01` / `7.1.2`、`D-17`（**简报此处引 `D-05` 有误，见 0.4 第 1 条**） |
| 建号时写入的内容 | 规则一致，字段落在 `FunderAccount`（18.1）；`created_via` 取 `email_code` / `wallet_signature` | `WS-302 7.1.3` |
| 建号后的引导 | **移交 WS-316 的入驻引导页**（差异 D-5）；本册负责移交点与凭据保管须知文案（7.2.6） | 差异 D-5 |
| 建号是否发通知 | **不发邮件**（会泄漏该邮箱此前是否已有账户），**发站内信** | `WS-302 D-34` |

### 7.2 M2 · 三种登录方式并列

**既定口径 `D-F11`：三者并列，任一可登录同一账号，不做强制双因素。** 若日后需要二次验证，只对**出资等敏感动作**要求再认证（复用 `WS-302 7.6.2` 与 `N-16` 的 10 分钟有效期），**不加在登录上**。

| 方式 | 是否建号 | 前置 | 规则引用 |
| --- | --- | --- | --- |
| 邮箱验证码 | ✅ | 发送前过滑块 `C-F20` + 多维限频 | `WS-302 7.2.1`、`D-27`、`N-07`～`N-11`（**简报 8.2 此处引 `D-12` 有误，见 0.4 第 4 条**） |
| 邮箱密码 | ❌ | 无 | `WS-302 7.2.2`、`D-01`、`D-17` |
| 钱包地址签名 | ✅ | 手填 / 粘贴地址 + 连接钱包 + **本端用途说明** | `WS-302 7.2.3`、`D-05`；分册 03 第 14 章 |

#### 7.2.1 邮箱验证码登录（含首次建号，`F-F01`）

流程与 `WS-302 7.2.1` 一致。资金方场景下的两点确认：

- **无论邮箱是否已注册，都发码并放行**（建号或登录），因此**该路径天然不存在账户枚举面**（`D-F13`，同 `WS-302 D-17` 原文认定）。
- 验证码输错达 `WS-302 N-12`（5 次）时**该码作废、需重新获取，账户不锁定**（`D-F24`，论证见 3.7.2）。

#### 7.2.2 邮箱密码登录（不建号，`F-F03`）

- **「邮箱不存在」「账户存在但未设密码」「密码错误」三种情形，返回完全一致的提示**，且**前两者不计入锁定计数**（`D-F21` / `D-F25`，规则见 `WS-302 7.2.2`、`D-17`、`12.2.1`）。
- **锁定判定必须置于凭据校验之后**，计数与否不得体现在响应上（`D-F29`）。

#### 7.2.3 钱包签名登录（含首次建号，`F-F02`）

全链路见**分册 03 第 14 章**。本节只指出它在登录页内的位置：`P-F20` 的第三个 Tab，输入框 + 「链接外部钱包」按钮，唤起 `C-F21`。

#### 7.2.4 三方式同账户（`F-F04`）

规则与 `WS-302 7.2.4` 一致：三种方式指向同一个 `funder_account_id`，登录后数据完全一致。**该结论在 WS-302 中没有对应的 D 编号**，只有功能点 `F-05`（简报引 `D-04` 有误，见 0.4 第 2 条）。

#### 7.2.5 登录后的处理顺序

**顺序与 `WS-302 7.2.5` 完全一致，一步都不能调换**：

```
凭据校验 → 建号（若首登）→ 账户停用判定 → 账户锁定判定 → 建立会话 → 协议同意判定 → 落地
```

- **协议同意判定**：本端协议的正文、版本策略与强制重新同意的弹窗细则归 **WS-310**。本册只保留这一步的**挂载点**与勾选留痕字段 `agreement_version_accepted`（18.1），不定义协议内容（差异见 3.5）。
- **落地**：见 9.4。

#### 7.2.6 建号完成后向 WS-316 的移交点

本册的责任终点是「会话已建立且凭据状态已确定」。移交时本册须保证：

| # | 移交内容 | 说明 |
| --- | --- | --- |
| 1 | 会话已建立，三态已判定为**登录（未入驻）** | 9.1 |
| 2 | 凭据完备性状态已确定（邮箱 / 钱包各自是否具备） | 7.4.1 |
| 3 | **凭据保管须知文案**已随建号确认一并展示 | `WS-302 7.5.4` 告知方式第 1 条 + 本册 7.10 的企业邮箱建议 |
| 4 | 若用户点「稍后再维护」，回落到**登录（未入驻）**并展示常驻补全提示条 `C-F23` | 7.4.5；引导页本身归 WS-316 |

### 7.3 M3 · 「申请入驻」与「资金方登录」是同一条链路的两个入口标签

> **`D-F12` 必须显式写出。不写清楚会被拆成两套并行维护，页面数与状态数都会翻倍。**

| 编号 | 口径 |
| --- | --- |
| **`D-F12`** | 「申请入驻」与「资金方登录」**共用同一套凭据校验与建号逻辑**（`P-F20` 同一页面、同一组接口），差别**只在入口文案与建号后的引导**。**PRD 与代码中都不存在两套流程** |
| **`D-F13`** | 因为共用，**资金方登录路径不存在账户枚举面**：验证码路径无论邮箱是否已注册都发码并放行，天然不可区分；密码路径按 `WS-302 D-17` 返回三情形一致提示 |

**两个入口的全部差异（穷举，除此之外没有任何不同）**：

| 项 | 入口「申请入驻」 | 入口「资金方登录」 |
| --- | --- | --- |
| 入口位置 | 首页 / 资产详情页的「申请入驻」按钮、受限操作引导弹层 | 右上角「登录」→ 类型选择 → 资金方 |
| `P-F20` 页面标题 | `Apply to join / 申请入驻` | `Funder sign in / 资金方登录` |
| 页面副标题 | `Already have an account? Just sign in below — the steps are the same. / 已有账号？直接在下方登录即可，步骤相同。` | `New here? Signing in with a code or wallet creates your account automatically. / 第一次来？用验证码或钱包登录即自动创建账号。` |
| 默认选中的 Tab | 邮箱验证码 | 记忆上次选择（`D-F08` 的本地存储做法），无记录时取邮箱验证码 |
| 建号后的引导 | 直接进入 WS-316 入驻引导页 | 同左（**建号即首登，两个入口一致**） |
| 已有账号登录后的落地 | 按 9.4 落地（**两个入口一致**） | 同左 |
| 凭据校验、建号逻辑、接口、异常分支、锁定计数 | **完全相同** | **完全相同** |

> 两条副标题是有意互相对称的：无论用户从哪个入口进来，都会被明确告知「另一种情况也走这里」。这是 `D-F12` 在界面上唯一的表达方式——用户不会读 PRD，只会读这一行字。

### 7.4 M4 · 凭据完备性与就地补齐弹层（**本册对 WS-316 的交付物**）

#### 7.4.1 凭据的三种角色

规则与 `WS-302 7.5.1` 一致，资金方取值如下：

| 凭据 | 角色 | 是否作为门槛 | 可否更换 |
| --- | --- | --- | --- |
| **登录邮箱** | 身份标识 + 安全通知通道 + 密码找回通道 | **是** | 可修改，**须验证旧邮箱**（7.6） |
| **钱包地址** | 身份标识 + 链上业务主体 | **是** | **不可修改**（`D-F43`，7.7.4 与分册 03 的 14.4） |
| 登录密码 | 便利性登录方式 | **否**——任何时候都不作为门槛 | 可随时设置 / 修改（7.5） |

> 文档中任何位置都不存在「密码必须补全」的要求。

#### 7.4.2 硬门槛 `D-F14`（定义在本册，调用在 WS-316）

| 项 | 口径 |
| --- | --- |
| **校验内容** | 账户的 `email` 与 `wallet_address` 是否**同时非空**。**密码不参与判定** |
| **被拦截的动作** | **「提交机构入驻资料」**（差异 D-2；资产端对应的是「发起个人认证」，`WS-302 7.5.2`） |
| **校验时点** | 用户点击 WS-316 入驻引导页的「提交」按钮时 |
| **未通过时** | **不跳走**，在当前页面弹出 `C-F22` 就地补齐；补齐后**原地继续提交流程** |
| **服务端校验** | **两侧都要做**：本册在凭据变更接口上维护 `email` / `wallet_address` 状态；**WS-316 在提交接口上独立校验并拒绝**。前端弹层不是唯一防线 |
| **状态副作用** | 补齐成功后 `FunderAccount.status` 由 `incomplete` 变为 `active`，常驻提示条 `C-F23` 消失 |

#### 7.4.3 `C-F22` 凭据补齐弹层（组件规格）

行为规格逐条沿用 `WS-302 C-09` / `7.5.2`，本节给出资金方的三种形态与文案：

| 缺失项 | 弹层标题（EN / 中文） | 弹层内容 | 完成后 |
| --- | --- | --- | --- |
| 缺钱包 | `Link your wallet to continue` / `绑定钱包后继续` | 「链接外部钱包」按钮，走 `C-F21` 连接 + **用途说明** + 签名（分册 03 第 14 章）；下方展示 RISK-01 钱包提示（7.10） | 弹层关闭，**原地继续** |
| 缺邮箱 | `Add your email to continue` / `绑定邮箱后继续` | 邮箱输入 + 滑块 `C-F20` + 验证码；下方展示 RISK-01 企业邮箱提示（7.10） | 同上 |
| 两项都缺 | 同上，分步展示 | 在**同一弹层内**依次完成，带步骤指示（`1/2`、`2/2`）；顺序按用户点击时缺失的顺序，钱包在前 | 两步全部完成后关闭并原地继续 |

- 弹层**可关闭**，关闭后回到原页面，**不改变任何状态**（不产生草稿、不改账户状态、不计入任何计数）。
- 弹层内的邮箱绑定属**首次绑定**，因此**不触发会话失效**（`WS-302 D-15` 例外，`D-F32`）。
- 弹层内的钱包绑定完成后**即不可更换**（`D-F43`），绑定前必须展示 7.10 的第二条提示。

#### 7.4.4 补齐成功后的「原地继续」回调契约（**本册对 WS-316 的接口承诺**）

| 项 | 约定 |
| --- | --- |
| 调用方式 | WS-316 在提交动作被服务端以「凭据不完备」拒绝时唤起 `C-F22`，并传入一个**继续回调** |
| 回调时机 | 弹层内全部缺失项补齐、且**服务端确认状态已落库之后**触发 |
| 回调语义 | 「**重新执行刚才被拦下的那个动作**」，不是「跳转到某个页面」。用户已填的表单内容不得丢失 |
| 用户关闭弹层 | **不触发回调**，回到原页面原状态 |
| 回调失败 | 若重放的动作再次失败（例如同时命中了别的校验），按 WS-316 自身的错误处理，**不再次唤起 `C-F22`** |

#### 7.4.5 受限态收敛：跳过引导不做全局封锁（`F-F14`）

规则与 `WS-302 7.5.3` / `D-03` 一致：

- 跳过引导后用户**不进入任何全局受限态**：可正常浏览、进入账户设置、使用不依赖入驻结论的功能。
- **唯一的凭据硬卡点是 7.4.2 的「提交机构入驻资料」**。
- 凭据未齐时全局展示 `C-F23`，可折叠为小图标但**不可永久关闭**，直到补齐；带「Complete now / 立即补全」按钮，点击进入 `P-F24` 对应区块。

| 缺失项 | 提示条文案（EN / 中文） |
| --- | --- |
| 缺钱包 | `Link a wallet to be ready to apply. / 绑定钱包后即可提交入驻申请。` |
| 缺邮箱 | `Add an email to be ready to apply and to receive security notifications. / 绑定邮箱后即可提交入驻申请，并接收安全通知。` |
| 两项都缺 | `Add your email and link a wallet to be ready to apply. / 补齐邮箱与钱包后即可提交入驻申请。` |

> **边界声明（同构 `WS-302 7.5.3` 末段）**：各业务模块的功能放行**以三态判定为准，不以本册的凭据完备状态为准**。业务模块**不应自行读取 `FunderAccount.status == incomplete` 做拦截**——否则每个模块各自解释一遍状态，口径必然漂移。三态的唯一来源是父 issue 的接口契约（9.1）。

### 7.5 M5 · 密码：设置 / 重置 / 修改

#### 7.5.1 密码规则

**全部沿用 `WS-302 8.4`，数值不改**：

| 项 | 口径 | 引用 |
| --- | --- | --- |
| 复杂度 | 8–20 字符，至少 1 个英文字母 + 1 个数字 | `WS-302 D-18` / `N-20` |
| 新密码约束 | 不得与原密码相同 | `WS-302 D-18` / `8.4.2` |
| 显示 / 隐藏 | 眼睛图标 | `WS-302 D-26` |
| 实时提示 | 复杂度校验清单实时展示，含与原密码比对 | `WS-302 8.4.1` / `7.6.4` |
| 是否强制设置 | **否**——密码是可选凭据 | `WS-302 7.5.1`、`F-09` |

#### 7.5.2 设置 / 重置密码（未登录，`P-F21` → `P-F22`）

| 编号 | 口径 | 引用 |
| --- | --- | --- |
| `D-F17` | **「设置密码」与「忘记密码」复用同一套流程**（同页面、同接口、同验证码用途），仅**入口文案**与**校验通过后的标题**不同 | `WS-302 D-08` |
| `D-F18` | `P-F20` 的密码 Tab 下**同时提供**「忘记密码？」与「没有密码？设置密码」两个入口，指向同一流程 | `WS-302 7.2.2` |
| **`D-F21`** | **标题与提示必须中性**，不得因账户是否已设密码、邮箱是否存在而不同 | `WS-302 D-08` / `D-17` |

> `D-F21` 是本册承担的防枚举责任之一（公共约束第 2 条）。具体表现：提交邮箱后**无论该邮箱是否存在**，都展示同一句「验证码已发送至该邮箱（若该邮箱已注册）」类中性提示并进入下一步——**不得出现「该邮箱未注册」或「该账户尚未设置密码」这类分支文案**。

#### 7.5.3 修改 / 设置密码（已登录，`P-F26` 弹窗）

流程与 `WS-302 7.6.4` 完全一致：

```
再认证（7.6.1）→ 输入新密码 + 确认新密码（实时复杂度提示，含与原密码比对）
→ 提交 → 全部会话失效（含当前设备）→ 关闭弹窗并跳 P-F20 → 向绑定邮箱发安全通知
```

| 编号 | 口径 |
| --- | --- |
| `D-F19` | 上述顺序为强制条款，不得省略「全部会话失效」与「安全通知」两步 |
| `D-F20` | 账户**原本无密码**时，同一弹窗标题变为 `Set password / 设置登录密码`，此时**无原密码可比对**，其余步骤不变 |

### 7.6 M6 · 登录邮箱的修改与绑定，以及再认证

#### 7.6.1 再认证（多因子任选其一）

**规则与 `WS-302 7.6.2` 完全一致。本节存在的唯一目的，是防止实现时被写死成「必须输密码」。**

| 账户已有凭据 | 可用因子 |
| --- | --- |
| 有密码 | 输入当前密码 |
| 有钱包 | 钱包签名（用途声明 `Re-authenticate`） |
| 有邮箱 | 邮箱验证码（发送前同样过滑块 `C-F20` 与限频） |

- 弹窗内展示该账户**可用的全部因子**供用户自选；只有一种可用时直接进入该因子。
- 通过后 **10 分钟**内不重复要求（`WS-302 N-16`）；超时后需重新认证。
- **再认证失败计入登录失败计数**（`D-F23`）。

> **为什么不能写死成「必须输密码」**：按 `WS-302 D-01`，用钱包签名建号的资金方账号**可能从来没设过密码**。他没有密码可输，却完全有能力用钱包签名证明身份。写死密码会把这类账号永久锁在账户设置之外——而这恰恰是本端最典型的机构账号形态。

#### 7.6.2 修改登录邮箱（`P-F25` 弹窗，`F-F11`）

流程与 `WS-302 7.6.3` 完全一致：

| 步骤 | 内容 |
| --- | --- |
| 1 | **再认证**（7.6.1，多因子任选其一） |
| 2 | **验证旧邮箱**：向当前邮箱发送验证码（滑块 + 限频），**不可跳过** |
| 3 | 输入新邮箱 → 滑块 → **新邮箱验证码** → 校验通过 |
| 4 | 提交 → 邮箱替换 → **全部会话失效** → 关闭弹窗并跳 `P-F20`，提示用新邮箱登录 |
| 5 | **向旧邮箱与新邮箱各发一封安全通知**（`EV-F04` / `EV-F03`） |

#### 7.6.3 第 2 步不可跳过的已知代价

**必须在界面上讲清楚，不能让用户事后才发现**（`WS-302 7.5.4`）：失去旧邮箱访问权的用户**无法完成本流程**，邮箱将永久停留在旧地址。此时若账户已绑钱包，仍可用钱包签名登录、账户继续可用；若账户只有邮箱且未设密码，则将无法再登录。
