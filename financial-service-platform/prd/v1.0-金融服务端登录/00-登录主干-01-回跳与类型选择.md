# 金融服务平台 · 金融服务端登录 · **登录主干** PRD
## 册一 · 回跳与类型选择（`DEP-M1` / `DEP-M2`）

> **本 PRD 是三条登录链路共同经过的「主干」的本体规格。**
> WS-314 三册的 `3.2 外部依赖契约表`（`DEP-M1`～`DEP-M5`）写的是**「本册需要主干提供什么」**——那是接口约定，是对主干的**验收要求**；本 PRD 写的是**这五项本身长什么样、按什么规则判定**。两者不重复：契约表说「必须有同源白名单校验」，本 PRD 说「白名单具体怎么判」。
> **本 PRD 自解释，不依赖任何 PRD 入口文件。**

## 1. 背景与目标

### 1.1 为什么需要这一册

三条登录链路（资产方 SSO、资金方凭据、资金方入驻）在三个子 issue 里各自写完了自己的部分，但它们**共同经过的那一段**——用户先选身份、登录完要回到原处、页面按档位显示或置灰——三册都写成了「调用方契约」并声明**自己不实现**。

覆盖审计的结论是：**契约表把「需要什么」写全了，但没有任何一份文档在写「主干本身」**；简报 135 个编号里唯一的零落点 `D-F10` 也随主干一起悬空。本 PRD 补的就是这块。

| # | 内容 | 对应契约 | 位置 |

## 3. `DEP-M1` · 回跳 `return_to`（**安全关键章**）

> **既定口径来源**：简报 5.3 `RT-1`～`RT-5`。本章把这五条从「原则」落成「可判定的规则」。
> **唯一实现原则（`D-F99`）**：回跳的参数承载、白名单校验与跳转**只有本 PRD 这一处实现**。WS-314 / WS-315 / WS-316 一律调用，**不得自建**（三册均已写入反向验收：WS-314 `AC-F52`、WS-315 公共约束第 1 条、WS-316 `03-1` 不做清单第 8 行）。

### 3.1 为什么必须只有一处

同源校验是**否定式安全控制**：它要挡住的是「所有没被明确允许的目标」。同一条规则写三遍，只要有一遍漏了一种绕过写法（协议相对地址、反斜杠、编码后的 `@`、大小写混淆的域名……），攻击者就从那一处进来。

**三处实现的安全性等于其中最弱的那一处，不是三者的平均。** 这句话请在评审时直接引用。

### 3.2 回跳句柄的形态（`F-F80`）

| 编号 | 口径 |
| --- | --- |
| **`D-F160`** | 回跳目标**不以原始地址的形式在客户端流转**。主干在生成时把目标登记下来，只把一个**不透明句柄**交给调用方；句柄本身不含目标信息，拿到句柄也推不出目标（`RT-1`） |
| **`D-F161`** | 句柄的承载位置**只有两种，二选一，不得出现第三种**：① **服务端会话暂存**（同域链路默认用这种）；② **塞进 SSO 授权请求的 `state`**（仅跨平台链路用，WS-314 册一 `D-F98`）。**任何情况下都不得放进可见 URL 查询参数、不得放进浏览器本地存储、不得放进未加 `HttpOnly` 的 Cookie**（`RT-1`） |
| **`D-F162`** | 句柄**与登录 / 入驻流程同生命周期**：流程完成、放弃、或会话销毁时立即作废（`RT-3`） |

**句柄的登记内容（产品口径，不是存储结构）**：

| 项 | 说明 | 必填 | 业务意义 |
| --- | --- | --- | --- |
| 目标路径 | 已通过 3.3 校验的**站内路径**（跨域时为对端标识 + 对端路径） | 是 | 登录完要去哪 |
| 触发能力标识 | 被拦下的那个能力在矩阵里的行标识（册二 6.3） | 否 | 支撑 3.6「重新执行被拦下的操作」；也是引导文案取「缺什么」的依据。用户主动点「登录」而非被受限触发时为空 |
| 目标域标识 | `self`（本平台）或对端白名单中的一项 | 是 | 区分同域与跨域，决定走 3.3 还是 3.4 |
| 生成时间 | — | 是 | 判定有效期 |
| 绑定会话 | 生成时所在的浏览器会话 | 是 | 防止句柄被搬到另一个会话里消费（`D-F167`） |

### 3.3 同源白名单判定规则（`RT-2` · **本 PRD 最关键的一节**）

**判定顺序自上而下，任一条不通过即判定失败，直接走 3.7 的失效兜底。不得调换顺序、不得跳过任何一条。**

| # | 编号 | 判定 |
| --- | --- | --- |
| 1 | **`D-F163`** | **只接受站内相对路径**：目标必须以**单个正斜杠 `/`** 开头。以下一律拒绝，**不做任何「修正后再试」的兜底**——带协议头的绝对地址（`http://`、`https://` 及任何 `xxx:` 形式）、**协议相对地址 `//`**、以反斜杠开头或含反斜杠的写法（`\`、`/\`）、以 `.` 或 `..` 开头的相对写法 |
| 2 | **`D-F164`** | **先规范化再判定，且规范化只做一轮**：对目标做一次百分号解码 + 路径归一（消解 `.` 与 `..`）。**若规范化后与规范化前不一致、或一次解码后仍含 `%` 编码序列，一律判定失败**——多轮解码是绕过判定的标准手法，本平台不给第二轮机会 |
| 3 | **`D-F165`** | **路径前缀必须命中允许清单**（3.3.1）。命中判定按**完整路径段**比较，**不做字符串前缀包含判定**：`/assets` 命中 `/assets` 与 `/assets/123`，但**不命中** `/assetsx`、`/assets-admin` |
| 4 | **`D-F166`** | **目标不得含用户信息段或凭据段**：规范化后的路径中不得出现 `@`；查询串中不得出现任何形如令牌 / 验证码 / 签名 / 回跳的参数（清单见 3.3.2）。命中即判定失败并按 `E-92` 安全留痕 |
| 5 | **`D-F167`** | **句柄必须由生成它的那个会话消费**。跨会话、跨设备消费一律判定失败（`E-93`） |
| 6 | **`D-F168`** | **`Referer` / `Origin` 不得作为信任依据**，只能用于留痕（同 WS-314 册一强制条款⑨） |

### 3.5 有效期与作废时机

| 时机 | 处理 | 编号 |
| --- | --- | --- |
| **超过有效期**（`N-F33`，默认 **30 分钟**，可配置） | 句柄失效，按 3.7 兜底（`E-91`） | **`D-F174`** |
| **被成功消费一次之后** | **立即作废，一次性使用**。重放同一句柄按失效处理（`E-94`） | **`D-F174`** |
| 登录 / 入驻流程完成、用户中途放弃、会话销毁（含退出登录、会话过期、跨端失效 `S-4`） | 作废 | `D-F162` |
| **用户在流程中改变了身份类型** | **作废并重新生成**——原句柄记录的触发能力可能不再适用于新身份 | **`D-F175`** |

> `N-F33` 取 30 分钟的理由：它要覆盖「被拦下 → 选身份 → 收验证码 / 去对端登录 → 回来」这一整段，其中收邮箱验证码是最慢的一环；同时不宜长到让一个被遗忘的标签页在半天后仍能跳转。**这是可调参数，不是安全边界**——安全边界是 3.3 的判定规则。

| **`D-F179`** | **失效条件**（任一命中即清除）：① 写入后满 **`N-F34` = 90 天**；② 用户选择了另一种身份（覆盖写入）；③ 用户点了「切换身份」（4.5）；④ 用户主动清除浏览器数据。**退出登录不清除**——同一台电脑上的同一个人下次多半还是同一种身份 |
| **`D-F180`** | 记忆**只影响「多给一个快捷入口」，不影响默认选中，也不参与任何服务端判定**。有记忆时在两张卡片下方多出一行「上次你选择了 X · 直接继续」；**两张卡片本身仍然对等、仍然都要点一次**。记忆不得演变成自动跳转——那等于绕过了 `D-F06`；服务端在任何时点都以用户本次实际选择为准 |

> **为什么记忆不能做成自动跳转**：一台共用电脑上，上一个人是资金方，下一个人打开就被直接送进资金方登录——他会以为平台只有这一种身份。

### 4.4 `D-F10` 的落地表达（**M-06 唯一零落点，本节即其落点**）

> 简报 `D-F10`：**登录页可达但不是主入口**——平台默认游客态，右上角常驻「登录」按钮即可，不做强制跳转。

| 编号 | 规格 |
| --- | --- |
| **`D-F78`**（**本 PRD 新发的简报级口径**） | **平台的默认态是游客态。** 任何未登录用户访问游客态可达路由，**一律直接渲染内容——不得跳转到登录页、不得弹出遮挡性的登录弹层、不得用登录墙盖住内容**。登录的唯一常驻入口是全局壳层右上角的「登录」按钮（`P-F51`） |
| **`F-F84`** | **右上角常驻「登录」按钮**：全站壳层内固定位置，游客态可见；登录后替换为账号下拉（WS-315 `C-F26`）。点击 → `P-F50` |
| **`F-F85`** | **游客态路由白名单**：3.3.1 中标 ✅ 的前缀，游客态**全部可直接访问**。白名单外的路由对游客返回「不可见」而不是「跳登录」（矩阵 ❌ 的语义，册二第 6 章） |
| **`D-F181`** | **登录只在两种时机出现**：① 用户主动点右上角「登录」；② 用户触发了受限操作（册二第 5 章引导）。**除此之外不得出现任何形式的登录提示** |
| 「申请入驻」 | 是**同一条链路的另一个入口标签**（简报 8.3），不是第二个入口页：与「登录」指向同一个 `P-F50`，差异只在**入口文案**与**建号后的引导**（WS-315 `F-F34`）。**沿用简报原号，本 PRD 不另发** |

> **`D-F10` 为什么会成为唯一零落点**：它描述的是登录页在**整个平台**里的地位，三个子 issue 都认为不是自己的。它确实不是——它是主干的。

### 4.5 「切换身份」的返回路径（`F-F86`）

| 场景 | 「切换身份」出现在哪 | 点击后 |
| --- | --- | --- |
| 已选资产方、进到离站告知（`C-F04`）但还没跳走 | 弹层内的次要操作 | 关闭弹层 → 回 `P-F50`（经 `P-F52`） |
| 在资金方登录表单里（已选身份、还没登录成功） | 表单顶部返回区 | 回 `P-F50`，清除已填的凭据字段 |
| 从对端授权页返回、尚未建立会话 | 落地时 | 回 `P-F50` |
| **已登录成功之后** | **不提供** | 已登录用户要换身份，路径是**退出登录**（`ST-2` 回落游客态）后重新选择 |

| 编号 | 口径 |
| --- | --- |
| **`D-F182`** | **切换身份：保留回跳句柄、清除身份记忆、不清空入驻草稿。** 保留句柄是因为「用户想去哪」没变、变的只是「以什么身份去」（若身份实际改变则按 `D-F175` 重新生成）；清除记忆是因为用户刚刚用行动否定了上次那个选择；草稿归 WS-316 自身状态机，与身份选择无关 |

### 4.6 `D-F09` 否决项（**必须显式保留在 PRD 里**）

**方案**：用户输入邮箱，系统判定「这是资产方账户」并自动路由到对应链路。
**结论：维持否决，不得实现。**

| # | 否决理由 |
| --- | --- |
| 1 | 系统回答「这是资产方账户」，**等于确认该邮箱在资产平台存在**——直接违反 WS-302 `D-17` 账户枚举防护 |
| 2 | 类型选择现在**同时存在于登录页与受限操作弹层**，出现频率是全站级的。做成自动判定，枚举面随之全站化 |
| 3 | 该方案在评审中**极易被重新提出**（看起来省一次点击），因此简报要求把否决理由显式写进 PRD——本节即此要求的落点 |

> WS-315 主文档 3.7.1 从「登录表单」一侧留了同一条档；**本节是判定页一侧的定义处**。两处口径同源，不重复定义规则。
