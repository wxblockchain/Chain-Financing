**其他已落地的 PRD 变化。** 以下变化没有单独的业务评论编号，按 PRD 提交追溯：

- 上游不存在撤销确权或删除资产（`59f0f18`）：AC-AS-33 已删除，旧的撤销 / 删除提示用例作废，见第 5 节版本管理。
- 运营看到的企业用户证件号码按上游原值完整展示，不脱敏、不截断（`68c2e54`）；企业端、机构端仍不得拿到企业用户信息。
- 资产列表默认按进入本平台的时间由新到旧，企业列表按取得企业的时间由新到旧；分页、返回位置、空状态与读取失败按 5.8 业务列表通用规则（`a957f38`）。
- 点击“申请发行”时按最新信息再次判断，已不满足时留在可信资产（`29119f7`）。
- 历史申请接收地址、到期时点的下游用途、申请内部阶段映射已移出 M2（`29119f7`），本 Eval 不再检查。

**产品规则状态。** 01 册第 10 节无待确认产品事项。5.8 业务列表通用规则与两位小数截断规则仍定义在 M2；本 Eval 只评 M2 自有列表，其他模块的列表由各自的 Eval 评估。评估规模、发布门槛、人工抽样比例、联调环境与执行排期仍是第 3～5 节的建议或执行依赖，未经业务方批准，也不因此把产品规则改回待确认。金额预警与截断图标的视觉承载由设计负责；数据获取机制与接口协议由研发负责。

本模块自身不发送消息，所以没有 03 册（01 册开头已写明）。本 Eval 不另设消息维度，但对 AC-AS-44 保留“不触发消息”的负向检查。

**评估范围。** 本模块展示上游资产可信平台已确权的应收账款，并决定资产能否发起发行申请。规则是确定的，不含模型生成内容，所以本 Eval 要回答：**本模块交付后的产品表现，是否达到 PRD 的成功标准**，不评模型能力。具体包括五点：

- 每个角色是否只看到自己范围内的资产、申请、代币编号与企业；
- 回款状态是否只按已知信息和到期时点正确归并，发行状态是否只由发行模块返回结果推动，以及驳回后能否回到可发行；
- “申请发行”入口、点击与提交是否只对满足全部条件的资产开放，同一资产是否同时最多只有一笔处理中申请；
- 展示的资产信息是否与上游一致、分级是否正确、是否只读；
- 用户能否查找到资产，并看懂当前状态和不能发起的原因。

与 04 册的分工：04 册是逐条验收标准，测试用例与执行步骤由测试小队编写。本 Eval 在 04 册之上做三件事：

1. 按风险把验收归入维度，并划出阻断项；
2. 规定 case 的组织方式与通过线；
3. 规定标注、跑评节奏、失败回流与版本管理。

本 Eval 不替代测试用例。

**不在范围内：**

- 发行模块（M3a / M3b）内部的机构分配、申请处理、驳回主体、新申请的文件与签名、铸造执行，以及 M4a / M4b 的代币业务：本 Eval 只检查 M2 带入固定资产、返回原来源、申请编号与申请状态是否与同一申请一致、机构关联的只读消费、资产发行状态与代币编号入口；
- M1 的身份判定（已认证 / 未认证 / 游客）：本模块直接使用 M1 的判定结果，判定本身见 [M1 Eval](../../面客端/M1-企业登录与企业账户/企业登录与企业账户-Eval.md)；
- 上游平台自身数据的正确性，以及与上游的同步时效（01 册第 10 节写明本册不设时效要求）；
- 铸造数量换算、代币单位价值、合约精度与接口实现方式；其他模块对 5.5 截断规则、5.8 列表通用规则的执行；视觉与布局由 Hallmark 设计负责。

**判定方式用语：**

- **code-based**：自动化断言，包括接口响应、页面状态、数据库记录、响应体敏感字段扫描、文案字符串比对；
- **human**：人工按二元 rubric 判定；
- **LLM-as-judge**：本模块不用于任何阻断判定，只在第 4 节写明的条件下，作为文案批量初筛的辅助。

| 项 | 内容 |

| 定义 | 每个角色只能看到 PRD 允许的资产、申请、代币编号与企业信息。拒绝由平台判定，不靠隐藏入口；拒绝说明不透露资产是否存在 |
| 需求来源 | 01 册 5.1 无权查看、3.1 资产归属、3.3 / 3.4（只供运营）、8.4（金额预警只在运营端）、第 9 节（机构只看关联资产与本机构关联申请，代币编号只对名单内机构）、5.6（筛选在原可见范围内进行）；02 册图 6。对应验收 AC-AS-02、18、19、34、45、48，以及 AC-AS-31、37、40、44 中与可见范围有关的部分 |

## 3. 通过线

本模块是确定性规则，同一输入的结果固定，所以规则类维度的通过线贴近 100%，并不是照搬 99% 一类的经验值。另外两点：缺陷修复成本低，而一旦失败可能让不合格资产发行代币、一笔资产重复融资或数据越权，且不可逆。

下表数值除已标注“PRD 确定”或“业务方确认”的以外，都是**建议、待业务与测试确认**。

**单例判定。** 一条 case 只有在两个条件同时满足时才算通过：

- “预期行为”全部满足；
- “禁止行为”一项都没有出现。

一条验收写了多个场景时，拆成的每条原子 case 都通过，才算该验收通过。这与 04 册的读法一致。

**指标口径：**

- 维度通过率 = 本轮该维度判定为通过的 case 数 ÷ 本轮该维度有效执行的 case 数。
- **排除规则**：因环境故障而无法判定的 case 标为“无效”，比如上游 mock 宕机、上游测试环境不可用（不是 case 有意模拟的不可用）、M3a / M3b 结果或机构关联结果的测试替身不可用。无效 case 不计入分母，必须重跑。一轮中无效 case 超过 5%（建议值）时，整轮作废。
- **不能排除的情况**：产品行为错误不得标为无效，比如上游不可用期间未判为已逾期，或发行模块未返回新结果时状态被改变。
- **切片**：每个维度分两个切片单独统计，不合并。“模拟环境”切片用上游 mock、时间 mock 与发行模块测试替身；“真实联调”切片接上游平台测试环境与 M3a / M3b 实际提供的结果；只验证 M2 对结果的消费，不执行外部机构分配、申请处理或铸造。

**发布门槛：**

| 层级 | 门槛 | 依据 |
| --- | --- | --- |
| 关键阻断项 B1～B9 | 每一轮、每条相关 case 都是 0 失败。任何一次失败都阻断发布，不能用其他维度的高分抵消 | 失败会影响业务进程、接收范围，或构成资产与安全风险；B9 为按已确认 P0 口径的归类，发布数值门槛仍待确认 |

**P0 / P1 / P2 的划分：**

| 级别 | 口径 | 本模块中的典型情况 | 来源 |
| --- | --- | --- | --- |
| P0 | 影响业务进程，或危及平台安全 | B1～B9 全部阻断项；满足四项条件的资产因金额关系异常、状态信息未收到或曾被驳回而被拦截或无法提交；回款状态判错（任何会改变能否发起的错误，含出现第四种状态、时区改变判断、先逾期后结清判为已逾期）；发行状态推动错误（含驳回后未回到可发行、无新结果时改变）；申请状态与 M3a / M3b 同一申请不一致；L1 事实值（金额、币种、到期日、确权状态）与上游不一致；债务人下游交易被计入本笔；L1 缺失未拦下；运营看不到完整证件号码；D5 中 R2 | 口径为业务方 11-05 确认；典型情况由本 Eval 按口径归类 |

- 一条 case 涉及多个级别时，按其中最高的级别计。
- 判不准时就高不就低，由产品负责人仲裁。
- 每条 case 的最终级别由测试负责人在启动集评审时标注，产品负责人确认。

**随机性控制：**

- 依赖真实时序的 case，如并发提交、上游不可用跨过到期时点、点击前 / 提交前上游状态变化，每轮重复执行 3 次。P0 case 须 3 次全部通过，任何一次失败都按失败处理，直到查明原因。
- 到期判断类 case 一律用时间 mock 固定“当前时点”，不依赖执行时的真实时间。
- 不稳定的 case，只有在证明是环境问题后才能标为无效。

**统计与不确定性：**

- 规则类 case 不计算置信区间，逐条看是否失败。
- 小样本零失败不等于低风险。例如某个切片 50 条 0 失败，按 Wilson 方法计算的 95% 区间上界约为 7%，这是公式算出的说明值，不是评测结果。所以阻断项靠“每条 case 0 失败 + 绕过界面的变体 + 决策表全量组合”来覆盖，不靠通过率。
- D5 人工评分与 L3 线上比例指标，用 Wilson 区间报告。
- 版本比较只对规则未变化且输入相同的 case 作逐条配对；规则变化的 case（如 v1.3→v1.4 的 C6、C8 与证件号码展示）单列新旧预期，不把改判当作实现回归或提升。
- 本文没有任何执行数据，不填写任何分数或区间。

**失败兜底**（PRD 已确定，Eval 核对兜底是否存在）：

- 上游暂时不可用时，展示最近一次保存的信息，到达到期时点仍未收到已结清即判为已逾期；
- 结清、逾期状态或回款记录未收到时，按已知信息归并回款状态；发行模块没有新结果时，发行状态保持上一个状态；
- 到期日或来源时区缺失时，按 L1 缺失不能发起，回款状态按已知信息展示；
- 点击“申请发行”与提交时按最新信息重新判断，不满足时不进入填写或不能提交；
- 驳回后资产回到可发行，满足条件时可以重新发起；
- 材料无法打开时，可以重试，不影响其他信息；
- 筛选或企业列表读取失败时，保留条件，可以重试。

C2 的非阻断兜底：不校验金额关系、不改写源值，仅运营列表预警 / 详情说明；其他四项条件仍严格校验。C3 逐笔拒收非汽车贸易资产、不影响同批合格项，不能以隐藏或禁止申请代替拒收。

每条兜底至少对应 1 条 case。发布后如果出现阻断项，按第 5 节回流：先止血，再补 case。止血手段（例如暂停全部“申请发行”入口）**待业务确认**。

## 4. 标注方法

本模块大部分 case 由自动化断言判定。人工标注主要用在三处：

- 定义预期结果，把 PRD 转成可断言的期望，尤其是回款状态决策表每个组合的期望值；
- D5 呈现类判定，以及 D3 不能发起原因的完整性；
- 阻断项复核。

**角色：**

| 角色 | 职责 |

- 先由人工建立开发集与独立校准集，均与正式评测集隔离；提示词只用开发集调整，冻结后用未参与调参的校准集验收，不用正式评测集反复调参；
- 在校准集上，LLM 与人工判定的一致率达到约定门槛（**建议 95% 以上，待确认**），才能启用；
- 启用后，LLM 判为不通过的 case 一律转人工；LLM 判为通过的 case，人工抽 10% 复核；
- LLM 不参与任何阻断项的判定，也不参与 R2。

**L3 线上业务验证**（上线后，**只观察，不作为发布门槛**）。目的是区分“离线 case 全部通过”与“真实资产数据下确实判得对、用得顺”。

| 指标 | 口径（分子 ÷ 分母） | 用途 |
| --- | --- | --- |
| 状态依据未收到占比 | 结清或逾期状态未收到、按已知信息归并的资产数 ÷ 本平台资产数；按缺失项分层 | 上游供数质量；只用于排查，不改变展示状态 |

| L1 不完整资产占比 | L1 有缺失的资产数 ÷ 本平台资产数；按缺失字段分层（含到期日） | 发现上游必传字段的系统性缺口 |
| 申请发行转化率 | 提交成功的申请数 ÷ 点击“申请发行”入口的次数 | 入口与申请流程是否顺畅 |

| 材料打开失败率 | 材料查看或下载失败次数 ÷ 材料查看或下载次数 | 材料存储与上游文件可用性 |

关于 L3 指标：

- 比例指标按 Wilson 区间报告；
- 告警阈值与观察周期**待业务确认**；
- L3 的任何数值都不得反过来改写离线 case 的判定结果；
- L3 用真实流量统计，与第 2 节加重后的风险覆盖集分开解读。

**失败回流。** 来源有五类：线上工单、L3 异常、运营在业务核对中发现的资产信息或状态问题、安全告警、外部变化探索中发现的问题。处理流程：

1. 测试在约定时限内（**建议 3 个工作日，待确认**）脱敏并复现，确认属于 M2 行为问题，而不是上游数据本身错误；
2. 写成 case，放入“历史失败”类别，标注“真实”及来源编号，与合成 case 区分；
3. 涉及 B 类的问题，同时补一条绕过界面的变体；涉及回款状态的，同时补进决策表；
4. 确认是 PRD 规则缺口而不是实现缺陷时，交 PRD 负责人处理；本 Eval 不改 PRD。
