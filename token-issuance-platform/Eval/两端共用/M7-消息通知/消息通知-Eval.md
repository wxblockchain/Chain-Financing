## 1. 评估维度（3–5 个）

**需求来源与范围。** 本模块是规则确定的站内消息承接与阅读功能，不涉及被测模型。读取以下全部三册；没有 03 册是因为 M7 自己不发消息，并非文件缺失。具体业务事件的发送条件、收件人推导和中英文模板由来源模块评估，本模块核对统一承接契约与端到端衔接。邮件、短信、浏览器推送不进入消息中心；不评估视觉布局，不扩展删除、归档、退订、编辑、撤回或人工标记未读等功能。

### D1 收件归属、身份边界与会话隔离

| 项 | 内容 |
| --- | --- |
| 定义 | 四种收件范围与当前身份、端严格匹配；阅读和计数不泄露其他身份信息；企业换地址、管理账号换邮箱仍接续同一归属；企业归属变化后可见范围随之切换 |
| 来源 | 01 册 [MSG-01](../../../PRD/两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-01)、[登录状态与安全](../../../PRD/两端共用/M7-消息通知/01-消息通知-PRD.md#session)；02 册图 1；AC-M7-01～06、25、26、34、35、42、43 |
| 通过条件 | 未登录、游客、没有有效企业归属的企业用户、待首登改密和锁定账号都没有消息入口和未读数，不取到消息数据；有有效企业归属的未认证企业可读本企业消息；企业归属变化或被移除后，按 M1 C-AUTH-06 确认即不再展示原企业的消息、入口与未读数，缓存与迟到结果不恢复，取得新归属后只见新企业消息；本机构、全体运营、本人范围各自正确；运营不能看本机构专属消息；全体运营逐账号保存阅读状态，新运营开通前的消息直接已读；跨端不汇总；企业按上游稳定标识接续，邮箱修改不改变账号归属；机构停用后仍能登录，停用前后的本机构在途业务消息照常生成、可查看并前往，在途业务能否办理以原业务所属模块为准；退出、失效、切换身份清除所有消息视图、缓存中的可见数据及迟到结果；自动更新不延长会话 |
| 失败条件与后果 | 跨企业、机构、账号或端泄露消息正文、数量或存在性；没有企业归属仍显示入口或“还没有消息”，让人误判本企业没有消息；归属移除后仍可读原企业消息；前一身份的迟到响应出现；换地址丢消息或旧地址仍可读；停用错误阻断登录或在途查看。这些可能导致安全事故或业务中断 |
| 判定 | code-based：入口、直接链接、接口、响应字段与身份切换时序对照；安全人员复核泄露证据；M1 / M5 真实联调单独判定 |

### D2 来源承接、事实完整性与送达时效

| 项 | 内容 |
| --- | --- |
| 定义 | 消息与已登记的业务事实一致；同一事实不重复，不同事实不误合并；按 PRD 时效可见并计数 |
| 来源 | 01 册 [MSG-06](../../../PRD/两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-06)，尤其接入字段、同一事实、送达时效、内容要求；02 册图 1；AC-M7-21～24，并关联 36、37 的内容异常切片 |
| 通过条件 | 缺少必填接入信息须来源补齐后再发，不猜收件人、不用虚假编号；无收件范围不改发全体运营；重复送达、重试、刷新、重新登录不新增、不重排、不改发生时间、不恢复未读；同笔业务的新事实各自一条，只有来源登记合并规则才合并；来源补齐信息不覆盖原事实或变回未读；普通事件从事实发生起 60 秒内列表、预览可见且计数更新；到点事件从应到时点起最晚 6 分钟可见，来源判定最多 5 分钟、展示最多再用 60 秒；原业务后续变化不改写消息中的历史业务值；未知值不显示成 0 |
| 失败条件与后果 | 重复消息掩盖真实事项；错误合并或漏收新事实；消息展示了后来的金额或意见；计时从送达而非事实发生起算。可能造成漏办、误办或业务依据失真 |
| 判定 | code-based：已登记测试事件、消息记录与接收端计数对照，记录事实时间、应到时间、来源判定时间及三个可见面的时间；联调与模拟分别统计，来源故障不得直接归因 M7 |

### D3 阅读状态、未读计数与批量操作一致性

| 项 | 内容 |
| --- | --- |
| 定义 | 只有规定动作改变本人的阅读状态；计数与可见未读集合一致；全部已读的范围、原子性与并发边界可核对 |
| 来源 | 01 册 [MSG-02 / MSG-07](../../../PRD/两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-02)、[MSG-04 / MSG-09](../../../PRD/两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-04)；02 册图 4、6、状态机 1；AC-M7-04、05、07～10、14～16、40、41 |
| 通过条件 | 详情展示成功且已读保存成功才持久变已读；展示或保存失败仍未读，正文可读且只重试保存；预览、列表看到、复制编号均不改变未读；已读重复打开不重复减数；未读数含全部分类、已办完和不可访问业务，0 隐藏、超过 99 显示 99+；读取失败保留上次数字，同身份跨页签最晚 60 秒同步；全部已读确认写明筛选和含未加载部分的数量，取消不改变，执行中防重复；只处理确认范围内本人的未读，不处理确认后新到消息、不影响其他人；失败全部不变，登录失效不报成功；并发已读后按实际处理数反馈；读消息从不代表业务已处理 |
| 失败条件与后果 | 未读被错误清空、批量越界或影响同事；失败部分写入；读消息触发业务状态变更，可能隐藏待办或错误推进业务。显示数字暂时有偏差但可在列表核对的情况单独按影响定级 |
| 判定 | code-based：按账号核对阅读记录、计数和业务前后状态；故障与并发注入，产品人工核对确认范围及实际结果反馈 |

### D4 查找、跳转与业务连续性

| 项 | 内容 |
| --- | --- |
| 定义 | 用户可找回完整消息历史，进入正确的那笔业务，并且始终按当前权限和业务状态办理 |
| 来源 | 01 册 [MSG-03 / MSG-08](../../../PRD/两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-03)、[MSG-05](../../../PRD/两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-05)、MSG-04 返回规则；02 册图 4；AC-M7-11～14、17～20、38、39 |
| 通过条件 | 预览最近 10 条且含已读，列表每批 20 条无重漏、产生时间倒序且同时间顺序固定，展示发生时间；分类只列本人实际拥有者，两个筛选同时生效；刷新保留筛选，无效条件回默认；未读筛选中读过的条目当前保留，重筛或刷新才移除；新消息符合条件才插顶部且不跳动阅读位置；返回保留筛选、批次及位置，直链返回无筛选列表；定位消息指定业务而非最新一笔；原动作办完只能看当前结果，不能重开；无权与不存在均不能前往且提示一致；详情检查故障仍可前往，由目标页重新判权；固定页面也判当前权限 |
| 失败条件与后果 | 丢消息、进入错业务、以消息授予权限、重开已办动作，可能漏办或误办；仅返回位置丢失但仍能找到目标的体验偏差按 P1 建议处理 |
| 判定 | code-based：集合、排序、路由业务标识与目标页权限断言；human 复核阅读位置与返回路径。权限检查故障路径须同时证明目标页未放宽权限 |

### D5 内容安全、双语与时区、异常可理解性

| 项 | 内容 |
| --- | --- |
| 定义 | 消息可读、安全，语言与时区切换保留事实；异常和空状态可区分且有可用下一步 |
| 来源 | 01 册 [内容与语言](../../../PRD/两端共用/M7-消息通知/01-消息通知-PRD.md#content-rules)、[内容与去向异常](../../../PRD/两端共用/M7-消息通知/01-消息通知-PRD.md#intake-fallback)，MSG-03、04、07、09；AC-M7-10、13～15、20、23、36～38、41、44 |
| 通过条件 | 纯文本标签和脚本不执行；消息不含密码、验证码、签名内容、完整钱包地址、证件号、私人联系方式、协议原件及下载地址；按当前语言切换历史标题正文，业务值不变，用户原文不翻译；发生时间和正文中的时间按本人当前时区展示并标明时区，切换时区只改展示，不改变发生时间、顺序、编号与已读状态；缺当前语言退另一语言，双语不可展现则分类、发生时间和通用标题兜底，不暴露内部标识、不拖垮其他消息；未知分类归 Other；只缺识别信息则缺项不显示，不假造，定位完整仍可前往；去向缺失或本端外不提供入口；读取失败不显示为空，加载更多失败保留已加载内容，可重试；预览或更新不丢未保存业务内容 |
| 失败条件与后果 | 脚本执行、敏感信息泄露、外部恶意跳转危及安全；语言、时区或异常提示错误导致事实误判或业务中断；一般措辞瑕疵另按 P2 建议处理 |
| 判定 | code-based：文本、敏感字段、执行行为、目标地址和故障状态检查；human：第 4 节二元 rubric。启动不用 LLM-as-judge |

## 2. Case 数量与覆盖

**规模均为建议，由测试负责人确认。** 启动风险集计划 68 条原子 case：D1 18、D2 12、D3 14、D4 12、D5 12；比 v1.0 增加的 4 条覆盖没有企业归属、归属移除和时区。下表实际给出 33 条代表性场景卡，部分包含多项检查，不能视作已经完成的 68 条执行用例；其余场景与原子拆分由测试负责人补齐。覆盖优先于数量，如 37 条验收的全部子场景需要更多 case，应上调计划，不为凑数合并。稳态建议每维度 30～50 条，总计 150～250 条，主要扩充身份、端、收件范围、并发及异常矩阵；不以堆叠相同正常消息增加样本。

## 3. 通过线

**优先级口径。** P0 定义已由业务方确认；P1 / P2 定义与动态升级规则采用产品侧（PRD 负责方，2026-11-05）给出的口径；典型归类依据影响判断，最终 case 定级由产品与测试评审。所有评估数值与阻断执行方式均为**建议，由测试、研发、安全按职责确认**，不写入 PRD；已确认的产品原则是 P0 风险不可作为可接受偏差放行。PRD 已明确的 10 / 20 / 99+、60 秒 / 5 分钟 / 6 分钟等产品行为不属于新增待确认门槛。

| 级别 | 定义 | 本模块典型情况 |
| --- | --- | --- |
| P0 | 影响业务进程，或危及平台安全（业务方已确认） | 跨身份 / 跨端泄露；脚本或敏感字段；无法找回或进入指定业务、越权或重开旧动作；漏消息、误合并、错误业务事实、超出 PRD 送达时限；批量越界隐藏待办；阅读触发业务；换地址历史丢失；无企业归属仍有入口或可读企业消息；自动更新丢失业务表单 |
| P1 | 业务事实、权限、收件范围、目标业务、消息实际状态均正确，不涉及安全或数据丢失；问题只造成误解、多一步操作或可明确恢复的中断（产品口径） | 可用列表核对的计数显示偏差；已读保存失败提示不清但消息仍在；返回位置丢失；筛选刷新偏差；双语回退、时区标注或异常说明不清但可继续且事实安全；读取失败明确可重试，仅呈现有偏差 |
| P2 | 仅为措辞、样式或非关键信息呈现差异；信息仍完整、正确，不影响用户判断与操作（产品口径） | 可读且字段齐全条件下的预览摘要呈现瑕疵、非关键措辞不统一；不包括范围误导、读状态错误、业务事实和安全问题 |

**动态升级为 P0（产品口径）。** 无论默认标为 P1 还是 P2，只要实际结果造成消息漏收或隐藏待办、错误已读、错误定位或重复办理、未保存内容丢失、越权 / 泄露、业务事实错误，一律按 P0 判定。

一条 case 满足所有预期、没有禁止行为才通过；AC 下所有原子 case 通过才算该 AC 通过。条件不足或证据缺失记「待判定」，不得当通过；发现更高影响时按最高级别处理，不按上表的默认建议降级。

**指标口径。** 维度通过率 = 主维度内通过的唯一原子 case 数 ÷ 主维度内有效执行的唯一原子 case 数。联合风险另外展示，不用重复计数提高分数。报告端、角色、收件范围、普通 / 到点、模拟 / 真实联调、正常 / 故障 / 并发切片，安全与业务关键切片单独判定。分母同时列计划、执行、无效、待判数量；未执行或无效的 P0 必须补跑，不能靠缩小分母放行。

环境故障确实导致无法观察时可标「无效」并记录证据；产品自己超时、错误空状态、保存失败处理不当均属于产品判定，不排除。建议无效比例超过本轮计划执行数的 5% 时整轮补跑，由测试负责人确认。送达时延以事实 / 应到时点为起点，列表、预览、计数的最晚可见时点为终点；分别记录来源判定与承接耗时。全部相关样本逐条对照上限，不用平均值、P95 或重试成功抵消超时。

| 整体 | 上述条件同时满足；37 条 AC 的全部子场景和补充项已覆盖，所有 P0 有效完成且没有待判；同基线逐条配对无 P0 回归，P1 回归逐条解释 | 防止覆盖不全或改一处损一处；当前未有执行基线 |

**随机性与统计。** 确定性规则逐条判定；真实网络、并发、跨标签和时延场景建议每个时序重复 3 次且记录固定前置数据与时钟，任一次产品失败记该 case 失败，不能挑成功重试。次数与时钟校准精度由测试 / 研发确认。真实来源至少各有普通与到点事件的可用切片；来源能力不适用时明确列 N/A 与依据，不以模拟代替真实联调。没有真实到点来源时列联调缺口，不能宣称端到端完成。

版本比较用同一冻结 case 集与配对前置状态；新旧覆盖不同先报告差集，不直接比较总通过率。人工比例判定与 L3 流量比例可采用 Wilson 95% 置信区间，报告样本量 n、观察窗与分层；该置信水平为建议，由测试负责人确认，当前不填任何区间。确定性覆盖集不外推总体风险；小样本零失败不能证明低风险，也不能证明时效在真实流量下稳定。无实际数据，不写分数、提升或通过结论。

**失败兜底核对。** PRD 已要求：普通读取失败可重试且保留可用内容；已读保存失败保持未读、只重试保存；全部已读失败原子不变；登录失效统一清除且不提示成功；内容异常逐条隔离；原业务检查失败允许前往但目标页重新判权。发布前发现 P0 建议停止放行并复核修复；线上发生后由业务、安全、研发与运维决定限制批量操作或相关入口等止血方式，预案与责任人由上述角色确认，本 Eval 不自行执行停用或发布。

## 4. 标注方法

**启动。** 产品与测试负责人共同把 37 条 AC 和补充检查拆为原子 case；每条写主维度、端、角色、收件范围、事件 / 确认时间、预期阅读与业务状态、禁止行为、优先级、来源锚点和证据要求。产品确认业务预期，测试维护覆盖矩阵；安全角色复核 B1 / B2 / B3；来源模块研发说明真实事件与归属，M1 / M5 研发提供稳定身份和会话边界证据。此处只定义角色，不指派或调用其他 agent。

33 张合成场景卡全部须人工复核后才进入正式集；禁止把本文表格直接标为已执行。规则型结果依确定性证据二元判定，人工不得用「看起来正常」覆盖不符记录。证据包含必要的脱敏前置快照、消息 / 业务关联 ID、时戳、响应与页面状态；截图本身不足以证明持久化、权限隔离、去重与批量原子性。评估记录也须脱敏，不保留真实密码、签名或完整证件等内容。

**人工二元 rubric。** 每个适用项均为「是」且确定性检查通过才算该 case 通过；不适用项写理由，不能用于豁免关联的 P0 检查。

| 条目 | 判定问题 / 建议级别 | 正例锚点 | 反例锚点 |
| --- | --- | --- | --- |
| R1 安全一致 | 他人 / 不存在是否同样不可访问，不展示禁用的敏感信息或内部标识？P0 | 两种目标均返回相同不可访问信息、无业务字段 | 「该消息属于 Y」或通用标题中暴露内部 ID |
| R2 状态可分 | 无消息、筛选无结果、读取失败、已读保存失败能否区分并有下一步？P1；失败显示成无消息且无恢复入口升 P0 | 失败可重试；筛选空可清条件；保存失败正文可读但仍未读 | 所有错误均写「暂无消息」 |
| R3 操作范围 | 全部已读确认与实际范围、人数独立性、条数反馈是否一致？P0 | 当前分类 25 条含未加载，实际变更数反映并发已读 | 只提示「清空消息」或乙的状态也变化 |
| R4 事实、双语与时区 | 中英切换后业务事实不变、用户原文不译、降级清楚；时间标明时区且换算正确？通常 P1，事实误导办理升 P0 | 英文标题搭配中文原驳回意见、数量编号不变 | 将驳回意见改译为相反结论；未知数值补 0 |
| R5 办理边界 | 阅读是否只改变本人阅读状态，进入正确业务并按当前状态处理？P0 | 乙读到旧的失败处理提示后，只能看到甲已处理完的当前结果 | 显示「已审核」仅因为已读；仍能重复办理 |
| R6 连续性 | 更新、返回、更多加载故障后能否继续，不丢业务内容？P1；丢业务输入升 P0 | 阅读位置保留、表单未保存内容保留，重试可继续 | 读取更多失败清空列表；消息刷新覆盖表单 |

**分歧与复审。** 启动人工项由产品和测试独立判定，不先互看标签；分歧附证据交产品仲裁，安全分歧须安全负责人共同裁定；PRD 有歧义时列待确认并走 PRD 流程，本 Eval 不修改规则。扩展期建议产品复审新增 case 的 20%，所有 P0 与关键补充项全量复核；持续期每次 release 人工项建议抽 10% 二次盲审，发现口径漂移即修 rubric 并回看受影响 case。抽样比例及具体责任人由测试负责人确认，不需产品裁定。

**LLM-as-judge。** 启动不使用，本模块阻断与规则均不交由模型裁定。未来文案量增大时可建议仅用于 R2 / R4 的非安全初筛：先建立人工双标及仲裁的校准集，与日常评估集隔离；启用阈值、误放成本和抽查量另行评审，未确认前保持人工。引入后模型拒绝项全人工复核，模型放行项分层抽检；R1 / R3 / R5 及其他 P0 始终确定性判定加人工复核。当前没有校准结果，不声称 judge 可靠。

## 5. 跑评频率

以下仅为方案，频率、负责人、门禁与资源均为建议，由测试、研发、安全或运维按职责确认；没有执行评测、调用被测模型、创建自动化或线上实验。

| 层级与触发 | 范围 | 责任角色 | 计划产物 |
| --- | --- | --- | --- |
| L1，每次相关 commit | M7、消息承接、身份 / 会话或目标权限相关改动：收件矩阵、直连隔离、去重、阅读状态、批量范围 / 原子性、纯文本与敏感字段、去向检查；含 60 秒等可控时钟边界 | 研发与测试 | 逐例证据、失败 / 无效清单；建议 B 类失败阻止合入，待确认 |

比例指标同时报样本量、观察窗及建议 Wilson 区间；小切片样本不足时明确标识，不合并安全风险掩盖问题。流量权重、对账观察窗、异常响应时限与 L3 告警值待确认。离线全部通过也不等于线上业务收益已证实。

**失败回流与版本管理。** 从线上工单、来源对账、权限告警、联调及每月探索回流；建议 3 个工作日内由测试脱敏、定位归属并复现，P0 响应时限由安全与业务另定。真实失败带真实来源编号、时间和脱敏证据；未能复现记待查，不贴真实失败结论。复现后加入历史失败集，P0 同时补原路径和绕过 / 并发变体；来源问题保留端到端 case 并标责任边界，不归罪 M7，也不能把不完整端到端链路判通过。

case 集按 `Eval-M7-vX.Y` 版本管理，记录本次 PRD 提交、产品版本、来源通知册与身份 / 目标业务版本、数据与时钟条件、逐例证据和变更原因。PRD 或来源契约改变时，逐条更新 AC↔case 与补充检查映射；v1.1 起，v1.0 中“监管机构”称谓、未区分有无有效企业归属的企业用户预期，以及停用机构“按 M5 办理范围”的预期作废，按本版执行；旧规则 case 归档并注明作废依据，规则变更回归至少保留到下一 release 后（建议，待确认）。风险集按风险扩容，统计集跟随真实流量漂移分层更新；配对比较时冻结共同集。
