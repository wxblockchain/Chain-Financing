**范围。** 目标用户为面客端企业用户与游客；评估从连接钱包、身份判定、受限引导、原目标返回、上游变化同步、退出，到资料、偏好与唯一企业账户查看的 M1 闭环。M1 与消息通知模块（M7）的分界如下，依据 01 册[与相邻模块的分工][neighbors]与 03 册开头：

- 04 册中涉及企业消息能否查看的现象（[AC-M1-08][AC-M1-08]、[AC-M1-14][AC-M1-14]、[AC-M1-33][AC-M1-33]、[AC-M1-50][AC-M1-50]）：M1 核对身份结果与“不因登录成功获权”，消息侧执行结果引用 M7 的评估证据；M7 证据缺失时该子场景记待定，不在 M1 判通过。

其他业务模块只检查 M1 输出的契约，不在本文定义其业务流程、关键动作清单或业务签名。原型可以支持呈现评审，不能证明服务端权限、来源校验与真实联调合格。

## 2. Case 数量与覆盖

**数量与来源。** 建议启动预算 64 条原子 case（D1 18、D2 12、D3 18、D4 6、D5 10），由产品与测试按风险拆分后确认。本文实际给出 **34 条代表性用例模板**，全部为“根据上述 PRD 合成、待人工复核”，没有执行记录。模板中的“分别”须拆成独立执行 case；模板数不等于原子 case 数。64 是排期估算，不能作为砍掉必要变体的上限；满足全部 40 条验收场景、阻断风险及权限矩阵需要更多条时，以覆盖为准。

启动预算按正常 20、边界 18、异常与对抗 20、OOD 6 组织，总计 64；每条原子 case 设一个主类别，允许多个风险标签。这是有意提高异常权重的风险覆盖集，不代表真实流量。未收到可验证的真实失败资料，历史失败数为“当前输入未提供”，不能据此断言产品未上线或历史零失败。后续真实失败单列，不挤占阻断覆盖。

**扩展规则。** 测试先将 40 个 AC 中的每个并列条件拆开，建立 `AC → 模板 → 原子case → 证据` 映射；缺稳定标识的识别规则、跨企业探测、登录事件追溯等 01 册补充规则单独追溯，不能给它们编造 AC。每个 B 风险至少配合法路径和绕过界面或竞态反例。权限矩阵至少包含未登录、游客、无企业归属（含上游无企业标识）、有归属未认证、已认证本企业、已认证他企业六类，分别覆盖导航、直接 URL、接口，以及成功与拒绝响应是否泄露字段。企业消息的可见范围由 M7 的权限矩阵覆盖，本文只核对向 M7 输出的身份结果。其他业务模块以契约替身校验 M1 输出，业务实现用例留在对应模块。

稳态建议按风险扩展至约 120～180 条原子 case，由测试确认；不按维度机械平均分配。新增硬件钱包延迟、SDK 返回格式变化、上游字段缺失、地区资料差异作为 OOD；真实缺陷回流须有脱敏来源编号和复现证据。没有真实流量占比前不做“用户总体通过率”的加权推断。

## 3. 通过线

**单例。** 预期行为全部满足且禁止行为均未出现才通过；参数化模板的每个参数组合各判一次。结果为通过、失败、无效、未执行、待定。PRD 歧义或待研发验证的依赖记待定并记录问题编号，不能自行标为通过。产品错误不能归入环境无效。

**分母与完整性。** 维度通过率 = 该维度通过原子 case 数 ÷ 该维度有效执行原子 case 数；有效执行含通过与失败，不含环境无效、未执行、待定。同步报告计划数、执行数、待定数、无效数及覆盖完成率；排除不是放行依据。每个 P0、B 风险、必测 AC 场景都必须执行并有结论；缺失任何一项不能报告整体通过。跨维度 case 设唯一主归属，总体去重。

**发布政策（Q1，Eval 建议，待最终批准）。** PRD 的功能断言已确定；以下聚合门槛属于本 Eval 的发布建议。业务/发布负责人批准总体政策与遗留放行，测试负责人批准覆盖、分母与补跑口径，安全负责人批准安全证据清单及安全阻断处理。PRD 负责人协调解释与确认路径，不能代替这些批准。当前输入未提供书面批准证据。

**优先级。** 沿用“影响业务进程或危及平台安全属于 P0”。本次具体划分：错误身份或无法建立正常企业登录、越权、错误企业归属、非当前登录地址作为有效账户、确认失效或调取不到仍允许、漏发必发认证失效事件、敏感泄露为 P0；有明确恢复路径且不影响业务和安全的说明或偏好显示偏差为 P1；不影响判断与操作的非关键措辞、轻微呈现问题为 P2。模板只要一个变体危及安全就拆出 P0，不能把整个 D5 都视为低风险；没有有效出路、持续卡住业务的原 P1 也升为 P0。P1、P2 的细分按本次业务判断，发布数值门槛继续待确认。

**失败兜底核对。** 首次调取异常不建立登录并允许重试，原目标在有效期内不因此失效；建立企业用户失败显示错误码、重试和放弃并返回；已登录调取异常不降为游客且关键动作不放行；登录期间调取不到账户或锁定禁用即结束登录；唯一账户读取失败显示暂时无法获取而非旧地址；账户入口读不到地址显示“我的账户”；偏好保存失败恢复原值；通知失败不恢复认证资格。上述是 PRD 行为要求。发布后命中 B 风险的止血方式，建议限制受影响的 M1 登录与数据读取边界，由事故负责人依据实际影响选择；不预设本期不存在的账户操作开关。

**待确认与已解决事项。** Q1 仅保留上述发布政策、责任角色的最终批准及书面证据，不能把建议阈值写成已批准。原 Q2 的时间边界与异常调取规则已由 PRD 明确，T1～T6 为正式断言。01 册第 9 节写明本模块没有业务待确认事项；登录签名的网络校验待研发验证，列入第 5 节 Q3。Q3 的对接参数、真实环境与评估运行安排仍按第 5 节责任矩阵确认。

**稳定性与统计。** 规则断言逐条判定，不靠抽样平均掩盖失败。真实钱包和异步响应的关键时序场景建议每个变体重复 3 次，任一次失败按失败调查；固定 PRD、case 版本、钱包与 SDK、上游版本、时钟、网络条件与操作序列。只有独立证据证明是环境问题才能标无效；建议一轮无效超过 5% 时重建环境重跑，比例本身待测试确认。即使低于 5%，所有必测场景仍须补跑。

比例型 D5 和上线观察指标报告分子、分母、样本量与 95% Wilson 置信区间；零失败小样本不能证明罕见风险已消除。重复运行同一 case 不是独立用户样本，不能混入比例指标扩大样本量。版本比较使用同一冻结集逐例配对，另报新增、退役 case 和风险变化；目前没有执行基线，不填写分数、提升或显著性。

**追溯证据检查设计。** 对应 01 册[登录事件追溯][login-audit]：验签结果、上游调取结果、身份判定结果、资料同步、登录建立与结束及原因、锁定禁用与登录期间调取不到账户的发现与处理均须可追溯；来源异常、缺稳定标识与多账户异常须有相应告警证据。建议逐项核对脱敏记录、事件关联和服务端时间顺序；不要求或收集凭据、签名原文与真实敏感明文。具体记录字段、留存与访问口径、告警核验方式与证据充分性清单由安全负责人批准并由研发与对接方提供，当前待提供、待确认。缺少 PRD 必需证据时记缺证，按第 3 节安全发布阻断建议处理；不能为填表而扩大敏感日志。

| R4 双语和值一致 | NT-C09 标题、正文逐字符合 03 册；两语言均写 Ethereum；切语言不改地址、时间值、编号含义 | 少句、含动态地址、把网络写 ETH | 标题、正文、分类、归属、去向须全通过的单列门槛为 Eval 建议，待 Q1 最终批准；敏感载荷 P0，其余按影响分级 |
| R5 地址可信呈现 | 缩写保大小写，可核对与复制完整地址；唯一账户来自当前可信登录地址，错误时不冒充有效；读不到地址时入口显示“我的账户” | 复制得到缩写、显示钱包切换后的 B、读取失败显示旧地址、显示假地址 | 错误有效地址 P0；单纯呈现 P1 |
| R6 告知与偏好 | 平台签名前告知用途；偏好保存有反馈、失败回滚；时区不改变顺序与时限 | 仅靠钱包提示、偏好迟到写入另一用户、时区使登录续期 | 通常 P1；串用户、时限或业务阻断 P0 |

**校准、仲裁与复审。** 启动阶段产品和测试共同逐条审核模板来源，再由测试拆分原子 case；全部 B 风险由安全复核。D5 适用 case 由产品与双语审校独立标注，分歧按原文、输入与证据逐项仲裁，业务问题由产品决定，安全规则由安全负责人确认；留下理由和 rubric 修订。扩展阶段建议抽查非阻断新增 case 的 20%，阻断相关全查；持续阶段每轮人工结果建议至少抽 10% 第二人复判，小样本至少 1 条，分歧集中时扩大复审。比例为排期建议，待测试确认。

**模型 judge。** 当前没有引入必要。以后确有文案批量初筛需求，先建立人工金标准、正反锚点和独立校准集；校准集不得计入日常版本比较，另设未用于调提示词的验证集。门槛应按漏检成本另议，报告对安全反例的漏检与分歧，不能仅用总体一致率。模型仅提出待人工检查的文本问题，安全风险、精确规则与发布放行始终由确定性证据及责任人判断。本次无校准样本，不声称模型可靠，也未调用模型进行评测。

**L3 指标口径。** 保留离线与线上分工，不把人为加重的风险集当成真实流量统计集。

| 指标 | 分子 / 分母与切片 | 用途及限制 |
| --- | --- | --- |
| 身份建立率 | 最终建立企业用户或游客登录的尝试数 ÷ 发起登录的去重尝试数；用同一尝试标识衔接连接、签名、验签、身份判定 | 观察真实可用性；取消、验签失败、调取失败、锁定禁用分别列原因，不能把游客占比当正确率 |
| 重新调取失败率 | 技术失败与超时的调取次数 ÷ 调取总次数；首次登录与登录期间、普通与关键触发分开 | 定位上游依赖；来源不可信、缺关键字段、多账户单列异常，不能与确实调取不到混合 |
| 唯一账户有效读取率 | 正确返回可信当前地址的读取次数 ÷ 具备权限的企业账户读取尝试次数 | 观察已授权用户能否取得有效账户；明确权限拒绝不是技术失败，不能排除真正的产品读取错误 |
| 认证失效事件一致性 | 同企业失效事实中已正确产生单一 NT-C09 事件的数量 ÷ 可审计的失效事实数量；另外列误发与重复数 | 仅在已有独立可审计事实依据时统计，不能用“已发送数”反推分母；送达与阅读质量归 M7 |
| 支持与安全信号 | 登录受阻、账户异常工单数，来源异常、多账户、越权、敏感泄露发现数；保留来源编号 | 触发调查；工单关闭不等于用户问题解决。敏感泄露不等周报，立即进入事故流程 |

有足够独立样本时按钱包与 SDK、语言、企业状态、上游版本分层，比例报告 Wilson 区间和样本量；上线流量权重来自实际分布，另报关键风险切片，不用平均数盖掉故障。环境或流量组成变动时先核对漂移再比较版本；不将用户取消全部归为产品错误或全部排除以美化结果。

**回流与版本管理。** 真实问题由测试脱敏复现，保留工单或告警编号、发生环境、输入、可见损失及证据，确认属于 M1 后加入历史失败集；属于 M7 的消息可见范围与展示问题转 M7 评估集。高风险先处理事故，再补正向和绕过界面的反例。建议普通问题 3 个工作日内完成复现归档，高风险即时分派；时限与止血责任待 Q3 确认。需求歧义交 PRD 负责人，Eval 不替其补写业务规则。

本版代表性模板继续使用 `EV2-` 前缀保持追溯，case 版本更新为 v2.2。归档 v2.1 的 EV2-D2-05、EV2-D2-06（有效企业归属变化或移除）、EV2-D3-07、EV2-D4-04（登录地址变更），以及 v2.1 中两条已从验收册删除的验收映射，注明“现行 PRD 已删除对应规则”，不删除历史证据，也不计入本版通过率；归档 ID 不复用。新增 EV2-D1-08、EV2-D2-08、EV2-D3-11、EV2-D5-07。EV2-D1-04、D1-05、D1-06、D2-02、D3-03、D3-04、D3-06、D3-09、D5-01、D5-02 的预期已随 PRD 变化，须重审后才能与 v2.1 配对比较；证件号码相关 case 由“不展示明文”改为“向本人完整展示”，旧结果不可沿用。冻结版本记录 PRD 提交、case 版本和环境。每次 PRD 修改重新校对真实 AC 编号及全部场景，更新受影响模板；旧原子 case 只有预期不变才可配对比较。需求变更回归标签至少保留一个后续 release。风险覆盖集按风险扩充，线上统计集按真实流量漂移更新，两者分别版本化。
