2026-11-06｜设计稿 v2.0｜仅设计评估内容，未执行产品评测

## 1. 评估维度（3–5 个）

**需求版本与范围。** 依据 `cly-v6.0.0` 分支 M3a 三册，目录最后修改提交为 [`4c7d8c5b952c80848ef0023e58ff9e794e60e322`](https://github.com/wxblockchain/Chain-Financing/commit/4c7d8c5b952c80848ef0023e58ff9e794e60e322)。本次重写旧版评估预期，评估企业确定资产、选填申请文件、核对自动接收地址、签名提交及查看当前进度和结果。确定性业务使用 code-based 断言，知情确认和错误说明使用 human 二元 rubric；本模块不调用模型，不以 LLM 判定安全或业务正确性。

**M3a 没有新增产品待确认项。** 文件格式、大小口径、文件不参与业务签名、自动接收地址、三阶段进度和企业不展示操作记录均已明确。缺少 03 册是因为本模块不发送消息，不按文档缺失处理。评估门槛、排期、实现与联调证据仍由对应责任方确认，不能混作产品规则缺口。

**已有跨模块冲突单独保留。** 01 册 [SYNC-M3A-01](../../../PRD/面客端/M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#sync-m3a-01) 与 [SYNC-M3A-02](../../../PRD/面客端/M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#sync-m3a-02) 已给出建议：M3b 统一管理端处理事实和状态交接，接受已确认的企业文件规则，并在自身模块定义运营、机构文件权限。核对时 M3b 仍保留旧审核流程和文件待确认项。本 Eval 不把旧 M3b 规则反向覆盖 M3a，也不替它决定管理端规则；企业侧可独立评估，受影响的真实跨模块链路必须待验，不能宣称端到端通过。

本模块不评估机构分配与审核操作、管理端文件权限、合约参数录入、链上执行或重试实现、消息来源跳转、M4a 后续业务；只核对 M3b 提供给企业的当前处理事实和铸造结果。合约完整精度等真实性证据由 M3b/研发提供，不在本模块新增链上执行验收。页面位置、尺寸和紧凑样式由原型负责，不设为 Eval 业务通过线。

### D1 企业归属与访问隔离

| 项目 | 定义与判定 |
| --- | --- |
| 来源 | [访问规则](../../../PRD/面客端/M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#access)、C-ISSUE-08、06；AC-M3A-01、02、03、42 |
| 通过 | 游客拒绝访问，未认证企业只见认证引导；本企业可访问申请、文件、签名和结果，其他企业与不存在申请统一拒绝；直接 URL、接口、企业参数与申请编号篡改均不能绕过。申请归属企业，新登录地址能查看原记录，历史接收地址不变 |
| 失败 | 非授权身份拿到申请字段、文件元信息、文件内容或签名；响应业务说明透露资源是否存在；换地址后数据丢失、拆分到不同企业或改写旧地址 |
| 后果与 grader | 企业资产及文件泄露或归属错误，危及平台安全；code-based 按身份×资源×访问方式比对响应和数据，安全人员复核拒绝行为。只隐藏入口不算通过 |

### D4 四项业务签名与完整业务值

| 通过 | 当前登录地址在 Ethereum 钱包签名；仅签资产编号、完整资产价值、唯一到期时点、接收地址，不签机构、币种、时间、文件、初始单位价值。确认与钱包可核对完整金额和同一时点，业务值不可改；一次签名只用于当前申请当前提交尝试，失效和跨申请复用被拒；同次网络重发承接同一结果。各状态展示不可改的签名地址、时间和值，长值可核对；换时区/登录地址不改历史业务值 |

## 2. Case 数量与覆盖

**计划数量。** 建议启动 72 条原子 case：D1 10、D2 16、D3 18、D4 14、D5 14；稳态按矩阵和真实失败扩到每维度约 40～60 条。均是计划、待测试负责人确认，不是已生成或已执行数量。本文实际提供 **36 条代表性用例规格**（D1 5、D2 8、D3 8、D4 7、D5 8），全部为**合成、待人工复核**；含多个场景的规格必须拆成原子 case，不能以规格行数冒充原子覆盖数。范围扩充后以完整覆盖为先，72 不是封顶。

| 启动类别 | 计划条数 | 本模块覆盖 |
| --- | --- | --- |
| 正常 | 18 | 两入口、无文件提交、合规文件、自动地址、签名、四类企业状态和结果 |
| 边界 | 20 | 10 份、10 MB、同名、超过两位小数、截断为零的显示、跨时区跨日、登录变化、500 字符意见 |
| 异常与对抗 | 26 | 直接接口越权、篡改地址/参数/文件、假后缀、提交前资格变化、无效与复用签名、并发、上传/保存/读取失败 |
| OOD | 8 | 未兼容钱包响应、超长/特殊字符文件名、非常用但允许格式的真实内容、来源时间或金额格式兼容性；业务合法性仍按现行规则，不自创拒绝条件 |
| 历史失败 | 0 | 本次没有提供可核验真实失败，不能声称发生过线上故障；后续脱敏回流单列 |

上述 18+20+26+8=72，异常覆盖较高是因为文件、签名和提交的错误成本高，不照搬流量占比。风险集与真实流量统计集分开，风险集通过率不能解释整体用户体验。

## 3. 通过线

**分级。** P0 定义沿用业务方已确认口径：“影响业务进程，或危及平台安全”。本文按此归类越权、重复申请、错误接收地址、签名绕过、文件校验与冻结失效、关键进度/结果错误。P1 建议指存在明确恢复路径且不影响安全和业务事实的说明/读取恢复偏差；P2 建议指不改变判断和操作的非关键呈现细节。P1/P2 划分、具体归类和下述数值、阻断治理均为建议，待产品、测试、安全及发布责任方确认；它们不是新的 PRD 产品待决策项。多级场景按最高风险计，拆成原子 case 后逐条定级。

**单例判定。** 所有适用预期满足、禁止行为未发生且证据完整才通过；产品错误判失败。环境异常致无法判定标无效，未准备/未同步的来源或实现能力标待验/依赖阻塞。主动模拟上游不可用、文件失败等是有效测试输入，产品兜底错误不能当作环境无效。基于文件名或页面文案猜测后端已校验、把未显示当作响应未泄露，均不能判通过。

维度通过率 = 该维度通过的有效原子 case 数 ÷ 该维度有效执行的原子 case 数；按 P0/P1/P2、正常/对抗/OOD、单模块/真实联调分别列数，禁止将两个环境合并后平均掩盖缺口。无效、未执行、待验不计有效分母，但必须单列数量、原因和责任人；分母为零显示“未评”，不能填 100%。

覆盖完成率 = 已有效执行的必跑原子 case 数 ÷ 计划必跑原子 case 数。待验与无效仍在覆盖计划分母中，必须补证或重跑。依赖检查规格 V2-D5-08 的“已正确登记待验”只能说明评估记录合规，不算相关产品链路已执行或通过。

| --- | --- | --- |
| P0/B 类 | 全部必跑，覆盖完成率 100%，有效执行 100% 通过，0 未关闭失败 | 错误可破坏企业授权、材料完整性或业务结果，不接受平均分抵消 |
| 各维度 P1 | 有效通过率不低于 95%；未通过项须有缺陷、恢复路径与责任人书面评估 | 确定性规则应接近全通过；保留仅体验类偏差的受控放行，95% 是建议而非行业标准 |
| P2 | 记录问题并安排修复；不设单独数值门槛 | 不得将安全或阻断业务的问题降为 P2 |
| 联调 | AC-M3A-12、18、21、23、25 受影响部分在 SYNC-M3A-01 及实际结果来源同步后重新执行；文件跨端依赖跟踪 SYNC-M3A-02 | 单模块样本可以验证渲染；不得替代真实 M3b 来源/真实执行证据 |
| 整体交付验收 | P0/B 类无失败、必跑覆盖完整，P1 经确认门槛满足，所有发布范围内真实联调依赖关闭；上一版本仍有效的关键风险无回归 | 当前可以交付 Eval 设计文档；不等于产品可发布。待验未关闭时不能写“端到端验收通过” |

对于初始单位价值的小数范围、最大值和真实链上承载能力，本模块只消费 M3b 结果，不自行决定输入或链上边界。V2-D5-06 的 0.8 为现行 AC-M3A-23 提供的合成样本，仅用作企业侧映射与精确乘法基准，不代表全部单位价值范围已验证。来源缺失或超出研发可验证能力时，相关真实结果 case 待验，不能通过截断降级。

**重复与统计。** 建议并发、请求重放、地址变化和真实钱包场景每轮重复 3 次，任一次产品错误即失败，不挑最好一次。固定时钟、完整金额、来源时区，记录钱包/签名格式、来源契约和文件样本版本。版本比较采用同一有效用例集配对，需求已变更的旧 case 先归档再比较，不据此报告提升。风险覆盖集逐条判规则，不用置信区间证明安全；若统计 D5 人工比例及 L3 真实流量比例，记录有效 n、成功 k 并报告 Wilson 95% 区间，同时按企业、入口、格式及钱包分层。无可靠流量权重不计算总体加权结论；小样本零失败不证明低风险。本设计没有实测数据，不给分数、区间或显著性结论。

**失败兜底核对。** 资格无法确认拒绝提交；签名失效后重签；非法文件拒绝且保留其他成功文件；上传中等待或移除；保存失败留本次文件重试、不产生正式记录；单份文件/签名读取失败不拖垮其他信息；详情失败明确可重试；上游不可用不影响读取平台既有申请。线上 P0 出现时建议升级现有事故处置流程，具体止血权限与恢复手段由责任方确认，不假定存在“暂停申请”开关。

## 4. 标注方法

| 角色 | 标注与复核责任 |
| --- | --- |
| 产品负责人 | 确认每条规格的业务期望和优先级；涉及真实新产品缺口时向 PRD 提出最佳建议，不在 Eval 内补造规则 |
| 测试负责人 | 拆原子 case、维护 29 条 AC 映射与覆盖分母；分清单模块通过、产品失败、环境无效和依赖待验 |
| 安全/研发 | 复核越权、后缀伪装、文件冻结、签名失效/复用与地址篡改证据；定义签名格式、钱包兼容和实现验证证据 |
| 业务/中英文审校 | 复核当前进度、驳回原文、文件/错误说明、完整金额和来源时区可理解性 |
| M3b 联调责任人 | 提供同步后的处理事实契约、跨端文件规则与真实结果来源，关闭相应 SYNC 依赖 |

启动时产品与测试逐条独立核对规格，关键安全和所有 B 类由安全/研发复核。多场景拆分后记录输入、前态、动作、预期/禁止、AC、优先级、来源版本、环境切片及证据需求；不得记录真实企业敏感文件或完整可复用凭证。人工说明类建议双人独立判定，分歧由产品负责人仲裁并写明理由；鉴权、签名及实际文件格式事实由安全/研发提供证据，不能用文案意见代替。

**human 二元 rubric。** 仅对适用项判是/否，全部适用项为是才通过；不适用项写理由，不因画面简洁就省掉必要业务信息。

| 条目 | 正例锚点 | 反例锚点 |
| --- | --- | --- |
| R1 身份与归属不泄露 | 他企业和不存在申请使用相同业务拒绝说明，响应无数据 | “申请属于某公司”或展示他企业文件名 |
| R2 完整值知情确认 | 普通页“12,345.67，已截断”，可核对 12,345.675；确认/钱包完整值可逐项核对并识别时区 | 用户只见截断值却签完整值；到期来源不明 |
| R3 文件与恢复可理解 | 明确选填、格式/份数/大小；失败文件可重试/移除，改资产解释清空 | 要求必传、不说明为什么无法确认、普通返回文件消失 |
| R4 提交后果完整 | 提交前说明 1:1、不可撤回修改、运营驳回终止、接收地址、须签名及文件不在签名内 | 仍提示线下机构协议，或暗示文件已参与业务签名 |
| R5 当前进度足够且无内部记录 | 三阶段、当前状态明确；当前驳回/成功结果及时间可见 | 机构分配节点、独立操作记录、人员、内部重试；或删除当前驳回时间 |
| R6 语言、原文与长值 | 字段状态随语言变化，驳回意见保留原文，地址/签名可核对完整值 | 自动翻译驳回原文、截断 500 字意见、复制得到地址缩写 |
| R7 空态与读取失败可区分 | 无申请给发起入口；详情失败明确暂时无法获取并可重试 | 读取失败被说成不存在；展示缺字段详情冒充完整结果 |

不使用 LLM-as-judge 作本版判定。未来若人工文本量显著增长，可另行评审仅用于 R3/R7 的初筛方案：人工先建立标准，开发校准集与独立留出验证集分离，留出集不用来调提示词；启用阈值与抽查比例需另行确认，阻断项与任何业务/安全结论始终由断言和人员复核。本次无 judge 校准或可靠性结论。

持续阶段建议新增规格的 20% 及所有 B 类由第二人复核；每次版本抽查说明类人工判定的 10%，不一致时修订锚点并复核受影响集合。20%/10% 是待测试确认的工作量建议。依赖未闭合只签“待验原因已登记”，不能签产品通过。

## 5. 跑评频率

以下均为建议节奏，只定义触发、责任与产物，不创建或执行测试、CI、监控或线上实验。

| 层级/节奏 | 触发与范围 | 责任与产物 |
| --- | --- | --- |
| L1 每次相关实现提交 | 鉴权、资产入口、自动地址、文件识别/冻结、签名生命周期、精度/时区、当前状态映射有变更；快速断言相关 P0/B 类，检查响应无越权数据 | 研发拟执行；按用例列结果与证据，是否阻断合入由发布治理确认 |
| L2 每次候选发布 | 全量有效风险集、真实钱包、文件全边界、来源状态映射；时序类建议重复 3 次；人工 rubric 双人复核 | 测试牵头，产品/安全复核；输出维度×风险×环境结果、覆盖率、失败与待验清单及真实联调证据 |
| 每周跨模块回归 | M1 地址/认证、M2 发起条件、M3b 契约/结果/文件权限及 M4a 代币跳转变化，尤其 SYNC 关闭后立即重评受影响集合 | 测试及来源负责人；输出交接版本、依赖是否关闭与受影响 case，不能只改“待验”为“通过” |
| 每月或外部事件探索 | 钱包/浏览器/上传组件/存储访问机制变更，来源金额、日期、文件格式变化；不做无关模型探索 | 研发与测试；更新兼容/OOD 规格与证据需求，不用新兼容性测试扩大产品允许格式 |
| L3 上线后业务观察 | 观察真实企业是否能完成提交、读取材料并理解当前进度；与离线风险集分开，不据观察数据改写 PRD 或离线判定 | 业务与测试；按下表统计趋势和失败回流，频率/窗口/告警阈值待责任方确认 |

| L3 指标 | 分子/分母或计数口径 | 解读限制 |
| --- | --- | --- |
| 提交完成率 | 同一观察窗内提交成功的去重尝试数 ÷ 发起的去重申请尝试数，网络重发归同次 | 按可信资产/发行模块入口及有/无文件分层；只定位流失，不能证明签名和资格正确 |
| 文件添加失败率 | 各类添加失败次数 ÷ 文件添加尝试数，按类型、大小段、份数、校验/网络原因分层 | 合规拦截与上传服务故障分开，用户主动取消单列 |
| 签名拒绝率 | 各拒绝原因次数 ÷ 发起签名次数，按取消、地址/网络、无效、失效/复用分层 | 拒绝可能是正确安全行为，低拒绝率不是高安全性 |
| 读取失败率 | 各资源读取失败次数 ÷ 对应读取次数，文件/签名/列表/详情分别统计 | 以请求失败与实际用户恢复结果区分，不把工单关闭当作已恢复 |
| 一致性异常 | 重复申请、正式文件或签名缺失、接收地址/完整值/估值不一致、内部记录外显的事件数 | 一次 P0 线索即调查；观察到零不证明缺陷不存在 |

比例指标保留计数、观察窗和切片，按第 3 节方法表达不确定性。跨周期比较控制入口、文件和钱包分布；可靠流量权重存在时可按真实分布加权，同时保留各层结果。样本不足仅报告事实与待观察，不编造基线。

**失败回流与版本管理。** 线上工单、访问审计、业务投诉、兼容探索与 L3 线索先脱敏复现；建议普通问题 3 个工作日内形成案例，安全/业务阻断按现有事故时限处置，具体时限待确认。核实为真实失败后记来源编号、损失类型、来源版本和复现证据，加入独立历史失败集；权限/签名/文件风险补接口绕过变体，时序风险补相邻时点。无法复现或仅为需求变更的不得标为真实失败。

风险集版本使用 `Eval-M3a-v2.x`，固定 PRD 提交、AC 映射、来源契约、样本与 grader/rubric 版本。每次 PRD 变化先判定旧预期保留、替换或退役；旧资料保留在 Git 历史并记录迁移原因。真实流量集、风险集与未来 judge 校准/验证集隔离管理；线上钱包、文件和入口分布漂移时增补 OOD 与代表流量抽样，不用人为对抗比例解释线上总体表现。

**剩余确认与依赖。** 本版没有新增 M3a 产品裁定请求；SYNC-M3A-01/02 的管理端同步与真实联调证据、签名格式/钱包兼容、文件识别/冻结/鉴权实现证据及结果源完整精度由研发与对应模块补齐。P1/P2 分级、建议数值、必跑规模、跑评排期、事故止血与发布放行机制由评估/治理责任方确认。上述事项不影响本 Eval 设计入库，也不能被误写成产品已通过评测。
