2026-11-10｜设计稿 v3.0｜仅设计评估内容，未执行产品评测

## 1. 评估维度（3–5 个）

**需求版本与范围。** 依据 `cly-v6.0.0` 分支 M3a 三册，目录最后修改提交为 [`582780f5a8da946cd2f98754a48ec3d09420d473`](https://github.com/wxblockchain/Chain-Financing/commit/582780f5a8da946cd2f98754a48ec3d09420d473)；引用的 M1、M2、M3b 规则按同一分支 `7bf162c` 时点核对。本版相对 v2.1 重写：驳回后可用同一资产发起新申请、提交前按 M1 关键业务动作复查身份、钱包切换地址不结束登录、截断金额改为图标查看完整值、到期时点为来源时区到期日 24:00、铸造结果不展示资产价值，以及列表排序与分页。确定性业务使用 code-based 断言，知情确认和错误说明使用 human 二元 rubric；本模块不调用模型，不以 LLM 判定安全或业务正确性。

**M3a 没有需要产品确认的事项。** 01 册第 8 节写明本模块没有待确认或待同步事项；驳回后重新发起、截断提示方式、钱包切换处理和身份复查均已由产品确认并写入 PRD。缺少 03 册是因为本模块不发送消息，不按文档缺失处理。02 册图 3 仍写“未登录或游客：拒绝访问”，AC-M3A-40 预期仍提到“登录地址变化”，与 01 册第 3 节及 M1“登录地址本期不允许变更”不完全一致；规则本身没有分歧，本 Eval 按 01 册和 AC-M3A-01 判定，建议 PRD 下次修订时顺带统一措辞。

**评估边界。** 本模块不评估机构分配与审核操作、管理端和机构的文件权限、机构材料访问（由 M3b [AC-M3B-60](../../../PRD/管理端/M3b-代币发行-审核与铸造/04-代币发行-审核与铸造-验收.md#AC-M3B-60) 负责）、运营查看同一资产历史申请（AC-M3B-75）、驳回消息 NT-C04、合约参数录入、链上执行与重试、M4a 代币详情及发行机构文件；只核对 M3b 提供给企业的申请状态、驳回意见和铸造结果。页面位置、尺寸、悬浮窗样式和按钮文案由原型负责，不设为 Eval 业务通过线；签名环节只按 PRD 核对“点击提交 → 身份与资产复查 → 当前登录地址钱包签名 → 核对通过才提交”。

**需研发、测试确定的事项，仅记录。** 签名载荷格式与钱包兼容范围、到期时点“24:00”在签名中的编码方式、文件内容识别实现、提交幂等与并发控制机制、60 秒调取间隔的计时与观测方法、每页条数（由设计确定）、M3b 联调环境与来源契约，均由研发、测试提供实现与证据；Eval 只规定判定口径，不替其选择方案。

### D1 企业归属与访问隔离

| 项目 | 定义与判定 |
| --- | --- |
| 来源 | [访问规则](../../../PRD/面客端/M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#access)、C-ISSUE-08、06；AC-M3A-01、02、03、17、42 |
| 通过 | 未登录直接访问先登录，登录后按当前身份重新判断，登录成功不等于有权；游客看不到入口、按游客引导处理；未认证企业看得到入口，进入或发起时看到认证引导；三者都不返回申请数据。已认证企业只能访问本企业申请、文件、签名和结果，他企业与不存在申请统一说明“无权查看或申请不存在”。直接 URL、接口、参数、申请编号与文件标识篡改均不能绕过。申请归属企业而非登录地址，重新登录后记录完整，接收地址保持提交时记录 |
| 失败 | 非授权身份拿到申请字段、文件元信息、文件内容或签名；登录成功后直接放行原目标；响应说明可区分“他企业”与“不存在”；重新登录后数据丢失、按地址拆分或改写接收地址；已提交内容可经接口修改 |
| 后果与 grader | 企业资产与文件泄露、归属错误，危及平台安全；code-based 按身份×资源×访问方式比对响应和数据，安全人员复核拒绝行为。只隐藏入口不算通过 |

| 后果与 grader | 不合格发行、身份失效后仍办理业务、错误阻断合法补正；code-based 比对复查调用顺序与时点、请求、申请记录、签名和资产发行状态，构造提交前状态变化、并发和原请求重发。错误原因与继续路径由 human 复核 |

## 2. Case 数量与覆盖

**计划数量。** 建议启动 84 条原子 case：D1 10、D2 20、D3 18、D4 16、D5 20；稳态按矩阵和真实失败扩到每维度约 40～60 条。均是计划、待测试负责人确认，不是已生成或已执行数量。本文实际提供 **41 条代表性用例规格**（D1 5、D2 10、D3 8、D4 8、D5 10），全部为**合成、待人工复核**；含多个场景的规格必须拆成原子 case，不能以规格行数冒充原子覆盖数。范围扩充后以完整覆盖为先，84 不是封顶。

| 启动类别 | 计划条数 | 本模块覆盖 |
| --- | --- | --- |
| 正常 | 20 | 两入口、无文件提交、合规文件、自动地址、签名、重新发起、四类企业状态和结果 |
| 边界 | 22 | 10 份、10 MB、同名、超过两位小数与未截断值、跨时区跨日到期时点、60 秒复查间隔、分页与同时间排序、500 字符意见、多次驳回 |
| 异常与对抗 | 32 | 未登录/游客/他企业越权、上游身份七类异常、钱包切换与登录到期、篡改地址/参数/文件、假后缀、提交前资格变化、无效与复用签名、并发与重新发起竞争、上传/保存/读取失败 |
| OOD | 10 | 未兼容钱包响应、超长/特殊字符文件名、非常用但允许格式的真实内容、来源时区与金额格式兼容性；业务合法性仍按现行规则，不自创拒绝条件 |
| 历史失败 | 0 | 本次没有提供可核验真实失败，不能声称发生过线上故障；后续脱敏回流单列 |

## 3. 通过线

**分级。** P0 定义沿用业务方已确认口径：“影响业务进程，或危及平台安全”。本文按此归类越权、身份复查失效、重复或并存处理中申请、错误接收地址、签名绕过、文件校验与冻结失效、关键进度/结果错误，以及错误结束登录或错误拒绝合法重新发起。P1 建议指存在明确恢复路径且不影响安全和业务事实的说明、读取恢复或列表偏差；P2 建议指不改变判断和操作的非关键呈现细节。P1/P2 划分、具体归类和下述数值、阻断治理均为建议，待产品、测试、安全及发布责任方确认；它们不是新的 PRD 产品待决策项。多级场景按最高风险计，拆成原子 case 后逐条定级。

**单例判定。** 所有适用预期满足、禁止行为未发生且证据完整才通过；产品错误判失败。环境异常致无法判定标无效，未准备的来源或实现能力标未执行。主动模拟上游不可用、文件失败等是有效测试输入，产品兜底错误不能当作环境无效。基于文件名或页面文案猜测后端已校验、把未显示当作响应未泄露，均不能判通过。

| 建议阻断项 | 对应风险与规格 |
| --- | --- |
| B1 访问隔离失效 | 非授权申请、文件、签名泄露，登录成功即放行，资源存在性可区分；D1 |
| B2 身份复查或提交把关失效 | 旧认证结论放行、复查晚于签名、异常时登录处理错误、不合格资产提交、接收地址可篡改、无机构分配却无法办理；V3-D2-03～06、V3-D4-02、04 |
| B3 申请唯一与终态失效 | 重复申请或编号、同一资产两笔处理中申请、已提交或驳回原申请可改、重新发起改写原申请或被错误拒绝；V3-D2-07、09、10，V3-D1-05 |

维度通过率 = 该维度通过的有效原子 case 数 ÷ 该维度有效执行的原子 case 数；按 P0/P1/P2、正常/对抗/OOD、单模块/真实联调分别列数，禁止将两个环境合并后平均掩盖缺口。无效、未执行不计有效分母，但必须单列数量、原因和责任人；分母为零显示“未评”，不能填 100%。

覆盖完成率 = 已有效执行的必跑原子 case 数 ÷ 计划必跑原子 case 数。未执行与无效仍在覆盖计划分母中，必须补证或重跑。V3-D5-10 只在 M3b 现行实际来源下执行才计入；文档或契约对齐只说明设计一致，不算相关产品链路已执行或通过。

**重复与统计。** 建议并发、请求重放、身份复查时序、重新发起竞争和真实钱包场景每轮重复 3 次，任一次产品错误即失败，不挑最好一次。固定时钟、完整金额、来源时区与上游身份样本，记录钱包/签名格式、来源契约和文件样本版本。版本比较采用同一有效用例集配对，需求已变更的旧 case 先归档再比较，不据此报告提升。风险覆盖集逐条判规则，不用置信区间证明安全；若统计 D5 人工比例及 L3 真实流量比例，记录有效 n、成功 k 并报告 Wilson 95% 区间，同时按企业、入口、首次/重新发起、格式及钱包分层。无可靠流量权重不计算总体加权结论；小样本零失败不证明低风险。本设计没有实测数据，不给分数、区间或显著性结论。

**失败兜底核对。** 身份无法确认拒绝本次提交并保持登录；调取不到账户或锁定禁用时结束登录；资格无法确认拒绝提交；钱包地址或网络不符时提示切回并重签；签名失效后重签；非法文件拒绝且保留其他成功文件；保存失败留本次文件重试、不产生正式记录；单份文件或签名读取失败不拖垮其他信息；详情失败明确可重试；上游不可用不影响读取平台既有申请。线上 P0 出现时建议升级现有事故处置流程，具体止血权限与恢复手段由责任方确认，不假定存在“暂停申请”开关。

## 5. 跑评频率

以下均为建议节奏，只定义触发、责任与产物，不创建或执行测试、CI、监控或线上实验。

| 层级/节奏 | 触发与范围 | 责任与产物 |
| --- | --- | --- |
| L1 每次相关实现提交 | 鉴权、身份复查、资产入口、自动地址、文件识别/冻结、签名生命周期、钱包地址处理、截断与到期时点、状态映射、重新发起唯一性有变更；快速断言相关 P0/B 类，检查响应无越权数据 | 研发拟执行；按用例列结果与证据，是否阻断合入由发布治理确认 |
| L2 每次候选发布 | 全量有效风险集、真实钱包、文件全边界、身份复查七类结果、M3b 状态映射与重新发起；时序类建议重复 3 次；人工 rubric 双人复核 | 测试牵头，产品/安全复核；输出维度×风险×环境结果、覆盖率、失败与未执行清单及真实联调证据 |
| 每周跨模块回归 | M1 身份调取与登录规则、M2 发起条件/发行状态/截断与到期时点/列表规则、M3b 状态契约与结果、M4a 代币跳转变化；任一引用规则变化后立即重评受影响集合 | 测试及来源负责人；输出交接版本、受影响 case 与重评结果，不能只凭文档变更判为通过 |
| 每月或外部事件探索 | 钱包/浏览器/上传组件/存储访问机制变更，来源金额、时区、文件格式变化；不做无关模型探索 | 研发与测试；更新兼容/OOD 规格与证据需求，不用新兼容性测试扩大产品允许格式 |
| L3 上线后业务观察 | 观察真实企业能否完成提交、驳回后补正再申请并理解当前进度；与离线风险集分开，不据观察数据改写 PRD 或离线判定 | 业务与测试；按下表统计趋势和失败回流，频率、窗口、告警阈值待责任方确认 |

| L3 指标 | 分子/分母或计数口径 | 解读限制 |
| --- | --- | --- |
| 提交完成率 | 同一观察窗内提交成功的去重尝试数 ÷ 发起的去重申请尝试数，网络重发归同次 | 按可信资产/发行模块/驳回详情入口及有无文件分层；只定位流失，不能证明签名和资格正确 |
| 重新发起率 | 驳回后发起新申请的资产数 ÷ 同期被驳回且仍满足发起条件的资产数 | 只描述补正行为，不能据此评价驳回是否合理；观察窗需覆盖补正周期 |
| 提交拒绝原因分布 | 身份复查各结果、资产条件、钱包地址/网络、签名失效各自次数 ÷ 点击提交次数 | 拒绝可能是正确安全行为，低拒绝率不是高安全性；暂时无法确认的比例用于定位上游稳定性 |
| 文件添加失败率 | 各类添加失败次数 ÷ 文件添加尝试数，按类型、大小段、份数、校验/网络原因分层 | 合规拦截与上传服务故障分开，用户主动取消单列 |
| 读取失败率 | 各资源读取失败次数 ÷ 对应读取次数，文件/签名/列表/详情分别统计 | 区分请求失败与用户实际恢复结果，不把工单关闭当作已恢复 |
| 一致性异常 | 重复申请、同一资产并存处理中申请、正式文件或签名缺失、接收地址/完整值不一致、内部记录或资产价值外显的事件数 | 一次 P0 线索即调查；观察到零不证明缺陷不存在 |

比例指标保留计数、观察窗和切片，按第 3 节方法表达不确定性。跨周期比较控制入口、文件和钱包分布；可靠流量权重存在时可按真实分布加权，同时保留各层结果。样本不足仅报告事实与待观察，不编造基线。

**失败回流与版本管理。** 线上工单、访问审计、安全告警、业务投诉、兼容探索与 L3 线索先脱敏复现；建议普通问题 3 个工作日内形成案例，安全/业务阻断按现有事故时限处置，具体时限待确认。核实为真实失败后记来源编号、损失类型、来源版本和复现证据，加入独立历史失败集；权限、身份、签名、文件风险补接口绕过变体，时序风险补相邻时点。无法复现或仅为需求变更的不得标为真实失败。

风险集版本使用 `Eval-M3a-v3.x`，固定 PRD 提交、AC 映射、来源契约、样本与 grader/rubric 版本。每次 PRD 变化先判定旧预期保留、替换或退役；旧资料保留在 Git 历史并记录迁移原因。真实流量集、风险集与未来 judge 校准/验证集隔离管理；线上钱包、文件和入口分布漂移时增补 OOD 与代表流量抽样，不用人为对抗比例解释线上总体表现。

**剩余确认与依赖。** 本版没有 M3a 产品待确认项；02 册图 3 与 AC-M3A-40 的措辞残留不影响判定，建议 PRD 下次修订时统一。签名格式与钱包兼容、24:00 编码、文件识别与冻结实现、并发与幂等机制、60 秒计时观测、每页条数和 M3b 联调环境由研发、测试与对应模块补齐证据。P1/P2 分级、建议数值、必跑规模、跑评排期、事故止血与发布放行机制由评估/治理责任方确认。上述事项不影响本 Eval 设计入库，也不能被误写成产品已通过评测。
