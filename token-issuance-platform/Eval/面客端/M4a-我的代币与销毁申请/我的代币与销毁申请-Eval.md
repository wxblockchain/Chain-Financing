本模块没有模型输出。规则明确的行为优先 code-based 判定（未来由研发/测试实现断言）；异常说明、双语与信息层次用 human 二元 rubric。LLM-as-judge 不参与交易、权限、数值、资产托管、文件访问或发布阻断判断。

**本版变更。** 相对 v1.2 与 v1.3 候选稿：

- 销毁流程：销毁由铸造到账地址钱包一次交易签名并直接广播，取消平台业务预签名、授权标识、平台代签和运营审核/驳回/重试；失败结束原申请，企业重新校验后发起新申请、新交易。合法整枚转让为允许状态，精度用完整值，代币符号 COU。
- 资产托管：“监管”统一改为“资产托管”。每枚代币有且只有一家资产托管机构，按 M3b 名单分配时类型确定，由 M4b 承接；企业在托管中即可看到其当前名称，托管开始时间等于铸造成功时间。原 Q-M4A-01 已由 PRD `c3034d4` 关闭，相关预期转为正式判定。
- 发行机构文件：新增 AC-M4A-45。企业可只读查看、下载本代币锁定名单内机构材料，按托管、法律、审计分类；解除后可下载解除托管通知文件。M3b 已在 `c20da5e` 开放铸造成功后原发行企业的只读访问（AC-M3B-60），Q-M4A-05 已关闭。v1.3 中“禁止企业取得 M3b 机构材料”的预期作废，改为“只能取得本企业已铸造成功代币的材料、不能写、不暴露上传账号与访问记录”。
- 退出现行必需集的旧预期：已移除的风险暂停规则、监管协议、M4a 发 NT-A02。旧 case 由 v1.2 与 Git 历史保留，不混入本版判定。

## 2. Case 数量与覆盖

## 3. 通过线

**确认状态。** P0 定义沿用业务方已确认的口径：“影响业务进程，或危及平台安全”。以下为建议，待测试、安全与发布负责人确认：

- P1：有兜底、可绕行，且不阻断业务、不涉及安全的规则或理解偏差。
- P2：不影响判断与操作的呈现细节。
- 场景分级同样为建议。

一条代表场景包含多种后果时按最高风险定级；体验类场景若实质改变交易、金额、权限、文件访问或链上事实，升级为 P0。

单例只有在预期全部满足、禁止行为均未出现时才算通过；组合场景须全部子分支通过。产品待验、未执行、无效、失败分别记录，不互相替代。

维度通过率 = 有效判定为通过的原子 case 数 ÷ 本维度有效执行的原子 case 数。同时报告有效判定数 ÷ 本轮必需 case 数，以及未执行数、待验数和原因，防止通过率掩盖覆盖不足。

| 建议阻断项 | 内容与证据 | 来源 |
| --- | --- | --- |
| B1 权限泄露 | 企业取得他企业的数据或文件、文件上传/解除操作人、访问记录或内部执行详情；企业能写机构文件；无权对象可被探测 | D1；AC-01、02、08、25、45 |
| B2 平台资格错误 | 平台入口用旧值/未知值放行；正常转让或质押在外仍开放平台发起；条件明确齐备却因旧审核机制拒绝 | D2；AC-09～13、15、35、39、41、44 |
| B3 错误交易或双签 | 登录地址、受让地址或平台代替 H；平台代发；资格校验前签名；额外业务预签名；签名、记录、链上数量被截断或替换 | D3；AC-16、37、38；M6 F-CT-06 |

环境确实无法执行、且不是用例故意注入的故障时，标为无效，留存环境证据并补跑；产品自身的超时误报或错误结果不得剔除。建议一轮无效超过 5% 时不据该轮决定发布，具体比例由测试/发布确认。

时序、并发、钱包、文件下载类风险场景，建议每轮在固定条件下重复 3 次，任何一次 P0 失败都保留；重复次数由测试确认。精度、链确认深度、钱包兼容、超时与文件大小参数未指定的，Eval 不自行补数。

确定性覆盖逐项看失败，不用人为加重的风险集估计真实风险。人工比例与真实线上比例计划报告样本量、分子/分母及 Wilson 区间，置信水平待数据/测试确认；没有数据时不填区间。

版本比较只对 PRD 预期相同的 case 逐例配对。以下旧 case 先归档，不能据其结论声称提升或回归：旧版“登录地址业务签名/运营重试”，以及 v1.3 候选稿中的“禁止企业取得机构材料”“监管归属待验”。

| 角色 | 标注责任 |
| --- | --- |
| PRD 负责人 | 解释本模块业务预期；出现新的跨模块冲突时给出最佳建议，并推动对应模块同步。不承担钱包参数、发布比例或测试排期决策 |
| 测试负责人 | 拆分 43 条代表场景与 37 条验收，维护映射、优先级、执行切片和环境证据，评审启动预算 |
| 安全、链与钱包研发 | 复核访问权限、文件下载鉴权、交易调用次数、发送地址、完整数量、不可逆链上事实；提供可验证的事件证据方案及钱包/链配置 |
| 中英文审校/产品评审 | 独立二元判断异常说明、确认后果、状态、文件分类展示与导航；产品只仲裁业务歧义 |
| 数据/运营/发布 | 分别确定线上统计口径、告警处置和发布治理，不把工具参数转成产品待决策项 |

每条原子 case 记录以下字段：来源提交、功能/验收编号、合成/真实及来源标识、输入事实、预期与禁止行为、级别、证据要求、主维度、适用切片、状态。一个 case 只计入一个主维度，与其他维度只做关联，不重复计分。当前所有代表场景都是合成、待人工复核，没有实际执行标签。

**启动阶段。** 测试与业务预期评审逐条核对完整 case；交易、文件权限、数值由安全与研发复核；D5 由两名审校独立判定。

**分歧仲裁。** 保留双方判断和理由，按问题类型交由对应方：业务规则不清交 PRD；执行证据不清交研发/测试；发布处置交安全/发布。不用多数票填补业务规则空白。

**扩展与持续阶段。** 扩展后新增的高风险 case 建议全部复核，其余抽 20%；发布后的人工结果建议由第二人抽 10%，比例由测试确认。

| 二元 rubric | 正例锚点 | 反例锚点 |
| --- | --- | --- |
| R1 真实且不补造 | 托管信息取不到时明确显示“暂时无法确认”；链上已销毁仍保留成功事实 | 从名单首家补造托管机构；没取到结果却显示未融资或已解除托管 |
| R2 权限与签名用途清楚 | 说明由 H 一次交易签名、企业付 gas、平台不审核不代发、之后由资产托管机构解除 | 引导用当前登录地址代签，或要求等待运营批准 |

启动阶段不用模型 judge。后续如需对文案批量初筛，由测试/评估负责人以人工金标准建立调优集与隔离验收集，先约定可容忍的错误率并验证人机一致性；最终仍由人工判定，B 类不交给 judge。没有校准结果，不声称 judge 可靠。

## 5. 跑评频率

以下均为建议的触发条件、责任与产物，仅设计，不执行，不创建 CI 或监控。

| 层次与触发 | 范围 | 责任与产物 |
| --- | --- | --- |
| L1 每次相关提交 | 企业隔离、文件下载鉴权与不可写、当前资格、钱包 0/1 次调用、完整数值、来源与状态映射、托管字段承接、文件分类、重复消费 | 研发/测试；确定性检查清单与失败证据；是否阻断合入由安全/发布确定 |
| L2 每个发布候选 | 全量必需 case；模拟与真实钱包/测试链切片；错误地址、整枚转出/转回、未广播/未知/失败后新交易、非平台入口承接、解除后通知文件下载 | 测试、安全复核；逐例结果、各维度/切片比例、待验与未执行清单及版本配对；没有实际执行时不出通过结论 |
| 每周或跨模块变更时 | M1 身份/账户；M3b 铸造结果、锁定名单与机构材料访问范围；M4b 结果、单位价值、资产托管机构与解除记录；M5 机构名称/类型；M6 整枚转让与销毁约束；M7 旧消息落点 | 测试；周回归与变更映射记录，时间由测试排期 |
| 每月或外部版本变化时 | 支持的钱包、浏览器、链 RPC 更新；异常返回、精度、链上事实缺失/矛盾；文件存储/下载异常 | 研发/测试；兼容性与 OOD 补充建议；模型探索不适用于本模块 |

**L3 线上观察。** 与离线评估分开：

- 钱包签名/广播漏斗按同一申请意图去重；
- 未知结果解决率 = 已确定广播结果的意图数 ÷ 未知意图数；
- 重复申请、错误来源、已销毁仍显示有效，单独列为一致性事件；
- 数值/持有读取失败率 = 失败次数 ÷ 读取次数；
- 文件下载失败率 = 失败下载次数 ÷ 下载请求次数；越权下载拒绝只作安全审计信号，不当体验指标。

按钱包、语言、平台/非平台入口、阶段、依赖可用性分层统计。窗口、去重、超时、阈值、样本量与置信水平由数据/运营/研发确定。不填假基线，不从漏斗流失直接推断用户问题已解决，也不把风险集的样本占比当作权重。

**失败回流。** 测试接到工单、链上事实差异、运营审计或兼容性问题后：脱敏、复现、确认归属、附来源编号；真实失败与本稿合成 case 分开。交易、权限、文件泄露风险由安全与运营按既有流程处置，本 Eval 不恢复旧版已移除的风险暂停规则。来源或权限决策缺口交 PRD，Eval 不自动修订 PRD。回流时限建议 3 个工作日，最终由测试/运营确认。

**版本管理。** 按 `Eval-M4a-vX.Y` 管理，记录依据的 PRD 提交、case 版本、变更原因及废弃的预期。本版退出与进入现行必需集的内容：

- 退出：旧版授权标识、运营审核与重试、监管协议、NT-A02、风险暂停正向用例；v1.3 候选稿的“企业不得取得机构材料”和“监管归属待验”。
