**范围。** M5 只提供机构主数据、固定类型、唯一机构编号、机构状态和唯一账号。新关系仅可选择启用机构；何时分配业务对象、停用后既有对象是否可见/可办、材料和铸造等规则归 M2/M3b/M4b，不在本篇定结果，停用确认中的影响说明只核对 M5 写明的两句。基础资质是机构级资料，不能要求绑定申请或代币，也不能由上传自动推导业务权限。机构类型名称在其他模块页面与消息中的展示随所属模块验收，本篇只核对机构列表、详情与开通邮件。登录邮箱填错的纠正由开发人员在产品外执行，本篇评估其可观察结果（产品内无入口、凭据失效、邮箱归属、安全记录、不发消息），不评估开发人员的操作工具。本文不改写 PRD、原型，不执行测试或建设评测设施。

**与上一版（v2.0）的关系。** v2.0 中“附件按研发核实的通用文件策略、不预填限制”的口径作废：PRD 现已确认 PDF/JPG/JPEG/PNG、按实际内容识别格式、每份 ≤ 10 × 1024 × 1024 字节、每家最多 10 份。联系电话由单文本框改为“区号下拉 + 号码”，6～30 字只计号码。v2.0 同 ID case 的旧预期归档于 Git 历史，不把规则变更误报为实现回归。

code-based 为未来可用的接口、页面状态、数据记录、邮件事件或文件访问断言；human 为第 4 节人工二元判定。启动不使用 LLM-as-judge；模型不裁决权限或发布。

## 2. Case 数量与覆盖

建议启动 76 条原子 case：D1 16、D2 22、D3 10、D4 14、D5 14；由 19 条复合 AC 全子条件与字段、区号、文件边界、编号/邮箱竞态拆分，数量不足则扩充。稳态建议 180～280 条，优先补充访问方式、并发和真实回流；上述数量待测试确认，均为计划。风险集建议正常 24、边界 24、异常/对抗 22、OOD 6，共 76；未提供真实失败材料，历史失败暂 0，不能据此推断产品无缺陷。风险配比不代表线上流量。

**覆盖切片。** 三类型 × 启用/停用 × 待首登/正常/锁定，按风险组合；运营甲乙、机构、未登录、面客端拒绝身份；入口/直链/接口/文件；新生成/重复/伪造编号；名称 1/2/100/101 字、联系人 1/2/50/51 字、地址 1/2/300/301 字、说明 0/1000/1001 字、合法/无效邮箱、他账号当前/历史邮箱与大小写变体。联系电话：未选区号、号码空、号码 5/6/30/31 字（不含区号）、含字母或其他符号、只有空格/短横线/括号、共用区号（+1 美国/+1 加拿大）、自动带出后直接改国家、手动改区号后再改国家、编辑已保存“+65 新加坡”的机构；中英文界面。资质附件：四种格式各一、恰好 10 MiB 与超 1 字节、第 10/11 份、Office、压缩包、空文件、扩展名与内容不一致、仅改扩展名、上传失败重试、编辑时移除再添加。账号成功/业务失败/邮件失败/重复提交/并发；登录邮箱纠正（填错邮箱已收开通邮件并在他设备登录）。OOD 包括未知编号、伪造机构类型或区号值、区号清单之外的值、直接访问非当前身份对象。号码合法性以字符和长度规则为准，不擅加号码真实性审核。

## 3. 通过线

单例预期全部满足且禁止行为未发生才通过。模板的子场景分别执行计数；一条 AC 的任一子条件失败，该 AC 不通过。环境故障可凭研发证据和测试确认标无效，修复后重跑；依赖未就绪/未执行标未验证。产品超时、错投、半保存不得排为环境问题。

| 级别 | 定稿定义与归类 |
| --- | --- |
| P0 | 影响业务进程，或危及平台安全：越权、编号或邮箱错属、开通失败/重复/半保存、机构状态影响账号登录、凭据泄露、纠正后旧凭据仍有效、伪装文件被接受、错误扩权/改历史 |
| P1 | 规则执行偏差导致误解或额外绕行，但有明确恢复路径、不阻断业务且不涉及安全：可恢复的字段/区号/文件边界偏差、空/失败说明不清、非关键字段呈现不符、列表返回位置丢失 |
| P2 | 仅呈现/体验细节，不影响用户判断、操作结果或业务状态：非关键措辞、间距、辅助反馈细节 |

同 case 取最高风险。本文分级沿用既定口径，新增问题由产品仲裁实际业务影响；是否作为合入/发布门槛由测试、安全和发布方决定，不回写 PRD。

| 层级 | 建议门槛（全部待相关方确认） | 理由 |
| --- | --- | --- |
| B1～B6 | 每条相关 case 0 失败且无未验证，任一失败阻断 | 身份、账号、资料与安全损失高 |
| D1～D5 的 P0 | 每维度、每个必需切片 100% 通过 | 业务正向可用与安全拒绝同时满足 |
| P1 | 每维度通过率≥95%；剩余逐条缺陷及明确兜底，由测试、安全、发布方决定放行，产品提供业务影响说明 | 可恢复差错的受控评审 |
| P2 | 不单设发布率，记录缺陷与修复计划 | 不影响判断和操作 |
| 整体与联调 | 19 条 AC 子条件和字段/区号/文件规则均有映射，必需 case 无未验证；真实账号/邮件/文件存储依赖验证；P0 相对同集上一版本无回归 | 不以少跑或模拟代替真实接入 |

维度通过率=有效通过原子 case 数÷有效已执行原子 case 数；按类型、机构/账号状态、访问路径、界面语言、模拟/真实依赖和优先级分别列分子分母，不合并掩盖风险。未验证/无效另列数量、原因；建议无效数超计划执行数 5% 则停止放行结论、修环境重跑。并发/真实邮件/文件保存建议固定数据快照、依赖版本与操作时序重复 3 次，任一次产品失败即失败。规模、无效比例、重复次数均待测试确认。

规则断言逐例判，不靠置信区间放过；人工比例与 L3 比例建议报告样本量、Wilson 95% 区间，置信水平待确认。小样本零失败不能证明低风险；版本比较用同一 case 集、相同环境逐例配对，新规则单列；当前没有执行基线、分数、区间或提升结论。

**兜底。** 业务保存失败不建机构/账号、不发信、保留有效输入；邮件失败不回滚已开通账号、运营线下告知且平台不重发；编辑失败保留最近成功值；读取失败可重试；文件不合规或上传失败只影响该文件、可重试；登录邮箱填错走开发人员纠正，新初始密码线下告知。线上止血可建议暂停受影响开通/编辑或回退版本，不能擅自冻结所有账号或决定既有业务终止；具体方案、责任、时限待安全/研发运维/发布方确认。

L3 建议口径：完整建立机构+账号数÷合法开通提交事实数；重复开通事实产生多机构/账号数÷重复提交事实数；邮件受理事实数÷应发开通邮件事实数（收信另有证据）；机构启停误改账号/会话事实数÷启停事实数；保存后编号与档案一致事实数÷成功资料保存数；登录邮箱纠正次数÷新增机构数（用于观察添加环节录入质量，非产品缺陷率）。按类型/状态/依赖版本分层，样本量、观察窗口、告警、响应时限待测试/运营/安全/发布方确认，不用工单关闭代理账号可用，也不以风险集配比解释真实用户分布。

失败来源包括工单、异常告警、线上观察、OOD；建议 3 工作日内脱敏复现、标真实来源编号并回流（时限待确认），未经证实投诉标待核查。B 类补直链/接口或并发变体。集合按 `Eval-M5-RG-vX.Y` 版本化，当前依据 `506be2b3067aa6c894019aa7284b4876304bfebe`；PRD 更新对比功能、AC 与消息，旧 case 归档留因；风险覆盖集和真实统计集分开，分布漂移时重估覆盖。
