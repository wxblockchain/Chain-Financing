**与旧版及相邻模块的边界。**

- [M3b][m3b] 定义发行选择、默认值、提交复核、无合约时通过／驳回与重试；本稿只核对 M6 提供的最新合格范围与合约信息，不再以申请状态迁移或重试成功判 M6。
- [M4a][m4a]、[M4b][m4b] 定义销毁申请、平台入口校验、钱包连接与签名操作、gas 承担、不提供代签等替代路径和结果承接；本稿不判这些流程，也不要求运营审核销毁或平台代发。F-CT-06 只判链上校验：合约是否只接受铸造到账地址作为发送地址、五项链上条件是否全部核对，以及合约是否接受该地址直接提交的一笔销毁交易而无需平台代发或另签授权交易。最后一项在 PRD 第 9 节为研发待验证，见 D5。
- [M4b][m4b] 的[调整代币单位价值（A-TOKEN-02）][m4b-adjust]定义发起入口、可调整条件（如“有销毁中的申请时不可调整”）、新值校验、调整记录与结果展示；本稿不判这些平台侧条件。F-CT-07 只判合约侧能力：提交到原合约、仅接受平台指定更新地址、质押中及平台停用后仍可更新、已销毁拒绝、更新不改变持有／数量／质押等。M6 不提供更新入口。
- 合约只校验发送地址、完整持有、质押地址为空、完整数量、未销毁这五项销毁条件。到期、结清与下游融资结果是平台入口准入，不增为合约强制字段；直接调用可能绕过链下准入，这是 PRD 明示边界，不能将其混成合约校验失败或擅加字段。
- 后续完整受让地址可以合法持有代币，但没有销毁发起权；这不应一律标作“合约异常”。其他模块尚未同步的描述不作为本稿的新预期，按用户意见留待对应模块处理。
- COU 图标是平台内代币符号的识别图形，由设计提供、不写入合约、不作为第八项合约信息。本稿只判 M6 合约列表的“图标＋COU”及图标不可用时只显示 COU；其他模块在何处展示图标由各模块定义和验收。
- 平台指定更新地址的保管与更换归研发与安全管理，PRD 不定义；本稿只判合约是否仅接受该地址，不评估密钥管理制度。

### D5 合约链上约束：整枚转让、独占销毁与单位价值更新

| 项 | 内容 |
| --- | --- |
| 来源 | [F-CT-05][f5]、[F-CT-06][f6]、[F-CT-07][f7]、[依赖][deps]、[图 4][fig4]、[图 5][fig5]、[图 6][fig6]；[AC-CT-17][a17]～[AC-CT-20][a20] |
| 完整转让通过条件 | 每次仅一个接收地址、数量等于该枚代币发起时当前全部数量；成功后原地址无剩余且不产生拆分份额。部分数量或拆多地址必须由合约拒绝，前后持有和数量不变；普通地址与合约地址相同适用；直接调用不得绕过。授权本身不改变持有数量，不误作为转让；铸造、销毁、单位价值更新按其自身规则，不擅用转让校验替代 |
| 销毁通过条件（只判链上校验） | 必须同时满足交易发送地址为铸造到账地址 A、整枚完整在 A、质押地址为空、销毁完整数量、尚未销毁。当前登录地址 D、受让地址 B、平台地址 P 或其他地址不因角色得到替代权；A 也不能销毁仍在 B 的代币。整枚转回 A 后仍只接受 A 且再次核对全部条件。合约接受 A 直接作为发送地址提交的一笔销毁交易即完成销毁，不要求平台地址代发，也不要求事先另签独立授权交易（研发待验证）。每笔新交易重查条件，启停不放松限制。钱包连接、签名界面、gas 承担及替代路径归 M4a，不在本稿判 |
| 单位价值更新通过条件 | 更新提交到代币所属的原合约，不改选其他合约（含原合约停用而其他合约启用时）。合约只接受平台指定更新地址提交；持有地址、铸造到账地址、质押合约和其他地址直接调用一律拒绝，值不变。代币正常持有、位于质押合约中（含融资违约后仍留在质押合约）、所属合约被平台停用时，合约均接受更新。已销毁代币拒绝更新。成功只改该代币的单位价值，所属合约、持有地址、持有数量、质押状态、铸造到账地址和初始单位价值不变，不按转让处理；链上失败时保持原有效值 |
| 失败与后果 | 部分转让、拆分、多主体错误销毁、条件缺一仍放行、平台代发或须另签授权才能销毁；非指定地址可改单位价值、已销毁仍可更新、质押中或停用后无法更新、更新改写持有／数量／质押或提交到其他合约，均可能影响安全或业务进程，归 P0。链下到期／结清、“有销毁中申请不可调整”等平台侧条件不作为链上硬条件，不能把其绕过统计为本维度失败或“已被合约保护” |
| 判定 | code-based 计划核对直接调用及应用调用的交易发送地址、目标合约、数量、接收方、原始铸造地址与持有／质押／销毁／单位价值前后状态；human 由合约研发、安全和测试复核拒绝原因、一笔交易销毁证据和更新提交方限制。仅 mock、隐藏按钮或平台前置校验不证明合约强制成立；“一笔交易完成销毁”未验证记待验，不接受先授权再销毁或平台提交为默认替代 |

**关键阻断风险。** 按已确认 P0“影响业务进程，或危及平台安全”归类。以下是设计建议；具体发布阻断制度仍由测试、质量及发布治理确认，不用平均分抵消风险。

| 编号 | 风险事件 | 维度／追溯 |
| --- | --- | --- |
| B1 | 平台越权、越界修改或删除合约 | D1；AC-CT-01、02 |
| B2 | 名称或状态维护破坏已保存结果；回执不明误报生效、错误重放或冻结其他维护 | D3；AC-CT-10～14、16 |
| B3 | 新发行资格输出错误，维护改写既有绑定或触发自动业务，把平台启用当链上恢复 | D4；AC-CT-06～09、13、15 |

## 3. 通过线

**优先级。** P0 采用已确认定义“影响业务进程，或危及平台安全”。本稿按此给出风险归类；P1／P2 定义沿用原设计建议，分级制度及逐例分类仍待测试、质量确认，不能由产品代审批。

| 等级 | 口径 | 本模块例子 |
| --- | --- | --- |
| P0 | 影响业务进程，或危及平台安全（已确认定义） | B1～B7；错地址、合法维护阻断、资格错误、绑定改写、部分转让、非 A 或缺条件销毁、不能一笔交易完成销毁、非指定地址改单位价值、更新改写持有或质押 |
| P1 | 规则偏差造成误解或多走一步，但有可靠兜底、不阻断业务、不涉安全；建议待确认 | 单纯排序、分页返回位置、可重试读取说明、可准确识别的翻译偏差；若实际误选、泄露、遗漏合约或阻断则升 P0 |
| P2 | 呈现细节不影响判断与操作；建议待确认 | 辅助措辞或非关键朗读顺序，不以个人设计偏好新增要求 |

**单例判定。** 每条原子 case 的预期全部成立、禁止行为均未出现才判通过；所有子场景通过，父 AC 才可通过。通过依据包括实际保存值、资格集合、交易发送地址、目标合约、前后持有／数量／质押／销毁／单位价值状态及确切拒绝证据，不能仅凭页面提示、隐藏按钮或“交易失败”猜测合约保护。COU 业务取值已确认，部署字段不符不能通过改字母大小写掩盖。非指定地址被拒绝须在其余条件（代币未销毁、目标为原合约）满足时取证，避免把“已销毁”等其他原因的拒绝算作提交方限制有效。

回执不明是有效输入，不按超时推断失败未写入；完成预设重读与恢复分支才可判整例。链上交易未取得明确可判证据记待验，不能用待确认提示冒充执行成功。若已证明合约必须先授权再销毁或由平台地址发送，则记录违反 AC-CT-18 的不符合；仅尚无部署证据则待验，两者不能互换。“一笔交易完成销毁”是 PRD 依赖中的研发待验证项，不是重新选择产品规则；AC-CT-20 的非指定地址拒绝已是正式验收，不再待验。

维度通过率＝本轮该维度通过的有效原子 case 数÷有效执行的原子 case 数。每例主维度计一次，附加风险与环境分层展示。环境失效导致无法取证为无效，须补跑；产品超时、丢修改、合约错误放行不能改成环境无效。计划数、有效数、失败数、无效数、待验数分开列；不在本期范围的外部图标单列不适用，不进入分母，也不把技术待验从必需集删除后称全模块通过。

**建议发布门槛，均待测试、质量与发布负责人确认。**

本稿不作发布决策。原子输入与拒绝路径本身由 PRD 决定；次数、比例、环境与签字是执行制度。对竞争、回执丢失和链上状态变化，建议固定交错顺序每个重复 3 次，任一产品失败不投票忽略；次数待测试和质量确认。交易取证窗口、节点异常与最终结果判据待合约研发及测试明确，不新造业务超时规则。

**失败兜底核对。** 明确失败与取消不改值；回执不明按最新值核对且只限制同合约同项；无合格合约输出空集；维护保留绑定；链上非法转让／销毁拒绝且持有数量不变；非指定地址或已销毁代币的单位价值更新被拒绝且值不变，链上更新失败保持原有效值；平台启停不恢复链上异常、不自动发起业务。链上结果监测、调整记录与业务承接交 M4b，不在本稿增加平台重试、运营审核或全局暂停能力。线上证据保全、人工暂缓办理及处置授权待运维、安全和业务运营确认。

启动由测试组织样本复核；产品核对新旧 AC 预期，合约负责人和安全复核 D5，每条 P0 与 B 项设计为双人复核，安排待测试、质量及项目确认。每条即使获复核仍保留“合成”来源，只把状态从待复核改为人工确认。测试环境真实交易不是生产历史失败，不更改其来源类别。

**二元 rubric。** 适用项全部为“是”才通过；不适用须写原因，外部图标因不在本期范围标不适用，不作技术已验证证明。

本期不使用 LLM-as-judge。若未来只为双语说明初筛引入模型，须独立人工金标、隔离校准与正式集、固定 rubric 和版本，错判容忍度由测试／质量确定；模型不判权限、合约状态、交易发送者、交易数、更新提交方或任何 P0。无校准样本不宣称可靠。

## 5. 跑评频率

下表为设计建议；排期、资源、证据制度及责任人由测试、质量及项目确认，合入／发布授权由发布治理确认。本次不创建自动化，不执行评测或线上实验。

| L1，每次相关提交 | M6 权限、读取维护与资格输出、分页、名称 Unicode、回执三分支、并发、通知／自动业务副作用；合约逻辑改动时覆盖转让、销毁、单位价值更新的确定性约束设计 | 研发／合约与测试；逐例断言计划和差异证据；是否阻断合入待质量发布确认 |

| 每月或外部变化探索 | 新合约部署、节点／钱包版本、名称字符集、调用方式／合约接收方／质押合约变化与新 OOD；不开展无关模型探索 | 合约研发／测试／安全；兼容性证据与新增样本；实际执行窗口待确认 |

**失败回流与版本管理。** 来源含工单、联调、领域复核与真实记录观察。测试建议在 3 工作日内脱敏、确认来源与复现条件，时限待项目／测试确认；未核实不称真实失败。复现确证后追加“真实历史失败”，B 项补直接调用或相反交错变体；需要新产品规则时交 PRD，不在 Eval 偷改。证据访问与保留期限待测试、项目及数据治理确认，安全复核。
