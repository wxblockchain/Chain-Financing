本模块没有 03 册：查看、开发配置、名称编辑、启用停用均不发送消息或邮件。评估包括“不产生通知”的反向断言，不新增通知需求。

**已闭合的产品口径。** [名称规则][names]规定单行、首尾 Unicode 空白去除、内部普通空格保留不合并并计入长度；不允许换行、制表符、控制字符、零宽字符；长度按用户感知字符，组合字符或完整 emoji 各计 1，不能按字节、编码单元或码点累计。重名比较按去首尾空白、Unicode 规范等价、忽略大小写处理，包含停用合约，不扩大为所有视觉相似字符。[维护结果][maintenance]规定回执不明先显示“结果待核对”，重读最新值后分别确认成功、展示不同值重核对或继续等待读取恢复；暂限同一合约同一维护项，其他维护仍可办理。[代币符号][symbol]为小写 `cou`，按部署原文展示，不能自行改大小写。这些均不再列为产品待确认；技术可用性仍需研发、合约负责人和测试验证。

这是确定性业务规则评估，不评模型能力。本 Eval 组织风险、覆盖和判定方法，不替代 04 册与测试小队的执行用例。平台内不提供新增、删除合约或修改其他五项字段的能力；部署、升级、链上程序本身的正确性不属于 M6 的交付范围。链上字段与部署的一致性属于依赖核对，不能仅凭平台字段显示推断链上可执行。

跨模块边界遵守 04 册：M3b 上线前只核对 M6 的可选范围；二审提交、铸造重试随 [M3b][m3b] 验收，销毁与解除监管随 [M4a][m4a]、[M4b][m4b] 联调。未联调的场景记为待验证，不写跨模块通过结论。

判定方式：**code-based** 指将来基于响应、持久化状态、业务调用记录和页面状态的确定性核对；**human** 指按二元 rubric 的人工复核。本次只设计内容，不创建断言工具或执行评测；启动阶段不用 LLM-as-judge。

### D1 权限与维护边界

| 项 | 内容 |
| --- | --- |
| 定义与来源 | 只有账号正常、已登录的运营可查看、改名与切换状态；各运营内容相同。来源：[谁能使用][access]、[合约从哪里来][readonly]，关联 [M5 权限][m5]；[AC-CT-01][a01]、[AC-CT-02][a02] |
| 通过条件 | 监管机构导航不可见、直接访问拒绝且不返回合约内容；企业面客端无入口，伪造读取或维护请求被拒绝；未登录、权限失效的维护被拒绝。运营只能修改名称和平台状态；标准、符号、资产类型、网络、地址不能改，不能绕过界面新增或删除 |
| 失败条件与后果 | 未授权读取或维护成功；仅隐藏入口但请求能执行；运营改了受保护字段或删掉合约。可能泄露管理信息、改变铸造对象或破坏历史归属，按 P0 口径处理 |
| 判定方式 | code-based：身份 × 操作 × 访问方式矩阵；核对拒绝响应和操作前后数据。human：安全复核所有越权变体；菜单、URL 与接口分别取证 |

### D2 合约识别、展示与结果可理解性

| 项 | 内容 |
| --- | --- |
| 定义与来源 | 运营能准确识别所有已配置合约，区分空数据、读取失败与维护结果。来源：[F-CT-01][f1]、[合约的信息][fields]、[F-CT-03][f3]、[F-CT-04][f4]；[AC-CT-03][a03]～[AC-CT-05][a05]、[AC-CT-10][a10]、[AC-CT-13][a13] |
| 通过条件 | 列表含停用合约与七项字段；启用在前，同状态按配置时间从新到旧，反复打开一致。地址缩写保留大小写，可核对且复制完整地址，不提供浏览器跳转；无单独详情。名称、ERC-3525、cou、Ethereum、地址切换语言不变，资产类型和状态随语言变化。刷新能看到开发新增和其他运营维护结果；无数据与读取失败可区分，后者可重试。满足第 4 节 R1～R5 |
| 失败条件与后果 | 错配名称和地址、复制错误地址、隐藏停用记录，可能导致误选或无法识别既有归属；读取失败伪装成无合约造成误处理。单纯排序或措辞偏差若有可靠识别与绕行，建议列 P1；不影响判断的细节建议列 P2 |
| 判定方式 | code-based：配置快照与列表字段、完整地址复制值、刷新结果、双语不变量及排序核对；human：信息可识别、异常可区分、操作说明可理解。具体布局与缩写位数由设计确定，不设新的像素要求 |

### D3 名称与状态维护的完整性

| 项 | 内容 |
| --- | --- |
| 定义与来源 | 合法维护可保存，非法输入、取消、失败、重复与冲突不破坏已保存状态。来源：[F-CT-03][f3]、[名称规则][names]、[维护结果][maintenance]、[F-CT-04][f4]、[状态机][state]；[AC-CT-10][a10]～[AC-CT-14][a14]、[AC-CT-16][a16] |
| 通过条件 | 启用和停用都可改名；遵守本节已闭合的单行、字符、空白、60 用户感知字符与规范等价重名规则，自身仅改大小写或首尾空白可保存。不同合约同时改成同名时只允许先保存者成功。状态仅启用、停用；操作前核对名称、完整地址、当前与目标状态及二审影响，确认后提交。取消、明确失败不改原值；回执不明不推定原值未变、不提前显示目标已生效，重读等于目标则确认成功，不同则展示最新值重新核对，仍读不到则保持待核对、限制同一合约同项重复提交，读取恢复后按最新值解除；同合约另一项及其他合约仍可维护。重复无额外变化；已在目标状态不再转换。相同维护项冲突不覆盖；改名与改状态互不覆盖。维护不改变地址、配置时间、链上字段及业务归属 |
| 失败条件与后果 | 合法维护不可完成、校验绕过、丢失他人修改、并发产生重名、明确失败或未核对就显示生效、回执不明被误当未写入、同项重复提交或连带冻结其他维护、改变不应变化的字段。影响正常维护或新业务控制的归 P0；能可靠绕行的非阻断提示偏差建议列 P1 |
| 判定方式 | code-based：输入边界、前后状态快照、双运营交错提交、不同合约并发重名、重复与回执核对；human：失败、冲突及确认说明复核 |

### D4 新发行二审的合约可选性

| 项 | 内容 |
| --- | --- |
| 定义与来源 | 新二审只能选择启用、资产类型匹配且网络为 Ethereum 的合约，提交时再核对状态。来源：[F-CT-02][f2]、[图 2][fig2]；[AC-CT-06][a06]～[AC-CT-08][a08]、[AC-CT-13][a13] |
| 通过条件 | 三条件的全部组合按 01 册真值表返回可选范围，符合的全部可选，不预选。选好后被停用，提交通过不成立，申请保持待运营审核并要求改选；改选合格合约后可通过。无可选合约不能通过二审，驳回照常；匹配合约均停用时引导启用，无匹配或无配置时引导开发配置 |
| 失败条件与后果 | 过滤条件缺失、遗漏合格合约、预选导致未经主动选择即通过、停用后的旧选择仍提交成功、无合约却通过或无法驳回。可能用错合约或卡住发行流程，属于 P0 |
| 判定方式 | code-based：状态 × 类型匹配 × 网络的 8 个组合、提交与停用交错、申请状态与后续业务调用核对。M6 过滤核对和 M3b 联调分别记录；非 Ethereum、非应收账款只作为隔离环境 OOD 样本 |

### D5 既有业务延续与副作用控制

| 项 | 内容 |
| --- | --- |
| 定义与来源 | 平台停用只限制新选择，不改变既有合约归属、铸造销毁与手动重试资格；不制造自动业务或通知。来源：[停用与既有业务][inflight]、[F-CT-03][f3]、[F-CT-04][f4]、[相邻模块][neighbors]；[AC-CT-05][a05]、[AC-CT-09][a09]、[AC-CT-10][a10]、[AC-CT-13][a13]～[AC-CT-15][a15] |
| 通过条件 | 已二审通过的申请不撤销选择、不能改选；铸造中继续承接结果，铸造失败可沿原合约手动重试且不要求启用。已铸造代币满足原条件可提交、审核、执行销毁，失败沿原合约重试，成功后原机构继续解除监管；原合约、数量、地址与归属不因维护改变。启用不等于链上恢复，链上异常仍按对应业务失败规则处理，由开发恢复后运营手动重试。配置与维护不发消息邮件，也不自动二审、重试或销毁 |
| 失败条件与后果 | 停用卡住原合约业务、自动重试、改选或改原数量地址、越过销毁原条件、启用被当作链上恢复。可能中断业务或造成错误链上执行，属于 P0；单独误发维护通知且无敏感泄露、无业务影响时建议列 P1 |
| 判定方式 | code-based：各业务状态与原合约绑定快照、业务调用次数及入参、人工触发记录、消息和邮件产生记录；human：M3b / M4a / M4b 负责人共同复核交接边界。平台停用和实际链上异常分开构造 |

## 2. Case 数量与覆盖

**内容规划。** 启动集按 100 条原子 case 设计：D1 14、D2 15、D3 37、D4 18、D5 16。下表实际编写的是 **46 条代表性 case 设计**，不是完整启动集，也没有执行；一行含多个变体的，扩充时每个变体独立编号。相较 v1.0 增加的预算集中于名称 Unicode 边界、名称／状态各三类回执不明与符号依赖核对。执行资源与排期待测试、质量和项目负责人确认；本次不扩为可运行数据集。

稳态设计按 120～180 条扩容，依据是原子场景、权限矩阵、并发顺序与真实失败，不以凑每维度相同数量为目标。所有 16 条 AC 的每个场景均需映射；100 条不能覆盖时继续增加，不删减验收。类别按首要目的互斥归类，附加风险可多标签：启动配额正常 26、边界及异常 50、对抗 18、OOD 6，共 100；没有真实失败输入，历史失败数量为 0，后续真实回流另增。该分配用于风险覆盖，不代表生产流量。组合字符、完整 emoji 已属支持规则，按边界类而非未知预期处理。

## 3. 通过线

**优先级口径。** P0 定义已由业务方确认；本模块按此给出逐例风险建议。P1、P2 定义沿用 M1 的建议口径；分级制度与逐例分类由测试、质量负责人确认，均为**建议，待确认**。产品仅解释预期业务结果，不审批测试分级和发布制度。

| 级别 | 定义 | 本模块典型情况 |
| --- | --- | --- |
| P0 | 影响业务进程，或危及平台安全（业务方已确认） | 越权、字段或绑定错改；合法名称或启停无法完成；并发覆盖、规范等价重名校验绕过；回执不明未经核对显示生效、错误重复提交或冻结其他维护；新二审选择错误或无故阻断；停用卡住原业务；错误自动链上操作；复制地址错误导致合约识别风险 |
| P1 | 规则执行有偏差，用户会误解或多走一步，但有兜底或绕行，不阻断业务、不涉及安全 | 只影响顺序的排序错误；可重试的读取失败说明混用；双语名称呈现偏差但可可靠识别；无业务影响、无敏感泄露的误发通知 |
| P2 | 呈现与体验细节，不影响用户判断和操作 | 不影响核对与确认的辅助措辞、间距、朗读顺序细节。布局由设计负责，本 Eval 不用偏好制造缺陷 |

多风险取最高级；表中 P1 情况若实际阻断流程、导致误选或泄露，按 P0 处理；待明确的预期不计为失败或通过，交产品澄清。

**单例与指标。** 每条原子 case 的预期行为全部满足、禁止行为均未发生，才判通过。保留操作前后快照、角色、请求与回执、业务状态和调用证据；不能只看成功提示。维度通过率 = 该维度通过的有效 case 数 ÷ 该维度有效执行 case 数。拆分后的所有子场景通过，父 AC 才可判通过；跨维度 case 按主维度计算一次，附加切片单列。

环境故障导致无法取证记“无效”，不入有效分母，须重跑；产品超时、错误返回、丢失修改不得作为环境问题排除。回执不明本身是有效评估输入，正确进入待核对并完成预设恢复分支可判通过；省略读取恢复或无法取证时，不能据中间态宣告整例通过。明确失败才断言原值不变，回执不明须按最新已保存值判定，不能强制回滚到旧值。未接入 M3b/M4a/M4b 的部分记“待验证”，分别报告计划数、有效数、无效数、待验证数，不把范围缩小后的比例称整体通过。建议发布前所有必需场景都得到有效判定；无效超过 5% 时该轮不用于发布决策。以上环境判定、执行与数值门槛待测试、质量及发布负责人确认。

| M6 隔离验证 | 可验证过滤、维护、权限与副作用；不能据此宣告铸造销毁全链路合格 | 与 04 册阶段边界一致 |
| M3b/M4a/M4b 真实联调 | 相关跨模块 P0 全部有效并通过；使用 Ethereum 测试环境和隔离业务数据，不发起生产交易 | 模拟范围正确不能证明原合约重试和销毁确实可办 |
| 整体与版本回归 | 上述门槛同时满足；同一 case 版本配对比较，P0 不允许从通过变失败；P1 回归逐项说明并审批 | 避免名称、状态修复破坏相邻模块 |

**随机性与统计。** 对并发、回执不明、提交与停用竞争场景建议按明确交错顺序控制先后，每个顺序重复 3 次；任一次产品失败都不能投票忽略。真实联调的链上时延与失败原因单列，不把交易待确认直接算作产品成功。重复次数待测试、质量确认；收集窗口、链上等待与超时取证待研发、合约负责人及测试确认。规则覆盖看逐条结果和反向变体，不用小样本零失败证明低风险。D2 人工比例和第 5 节真实业务比例可计划报告 Wilson 95% 区间，按环境、角色与版本分层并提供有效样本数；重复运行同一 case 不算独立用户样本。无基线与执行数据，本设计不填写区间、提升、分数或显著性结论。

**失败兜底的核对。** PRD 已确定：取消、明确失败不改值；回执不明重读最新值，等于目标确认成功、不等展示最新值重核对、暂不可读则仅限制同一合约同一项，恢复后解除；冲突展示最新值重新核对；二审提交时合约已停用则留在待运营审核并重选；无可选合约仍可驳回；原业务不受平台停用阻断；链上异常由开发处理后运营手动重试。设计覆盖每项正向保护及绕过／并发变体。若线上发现 B 项，证据保全、人工暂缓受影响操作等处置和授权人待运维、安全及业务运营确认；不假设已有全局暂停、熔断功能，不因本 Eval 新增能力。不能将“一律停用合约”当作能停止既有链上业务的兜底。

**本节待确认：** 测试、质量与发布负责人确认分级制度、逐例风险分类、通过率及阻断制度、环境有效性与放行授权；研发、合约负责人及测试确认联调取证与链上等待窗口；运维、安全及业务运营确认线上处置权限。名称 Unicode／空白、回执不明处理和小写 `cou` 已由产品闭合，其单例预期直接按 PRD 判，不再向产品请求决策。

## 4. 标注方法

| 角色 | 职责 |
| --- | --- |
| 产品／PRD 负责人 | 复核预期业务结果与功能／AC 追溯，仅对新增规则歧义作业务解释；已闭合的 Unicode、回执不明和 cou 按 PRD 执行，不重复审批。需求缺口走 PRD 流程，本 Eval 不改 PRD |
| 测试负责人 | 拆分启动集、维护 AC↔case 映射和前后状态证据；区分产品失败、环境无效与未联调；按切片组织判定 |
| 质量／发布负责人 | 会同测试确认分级制度、逐例归类、门槛与复核比例；确定合入／发布授权人和签字程序，承担放行治理 |
| 研发与合约负责人 | 提供可核对的配置和部署字段、并发先后及链上异常证据；核对 symbol= cou 等与合约实现一致；解释环境故障，不单方更改预期 |
| 安全复核人 | 全量复核 D1 与 B1，复核越权、越界字段和调用副作用 |
| M3b/M4a/M4b 负责人 | 复核原合约、原数量、原地址与既有状态的延续，区分 M6 规则验证和联调事实 |
| 产品与中英文审校 | 独立判 D2/维护说明的二元 rubric；不以视觉风格偏好替代规则 |

**启动。** 46 条代表设计由测试组织样本复核，产品核对业务预期，研发／合约负责人核对字符样本与回执证据，质量复核分级，再扩成完整启动集；P0 与 B 项设计为全量双人核对预期和禁止行为，执行资源及复核安排由测试、质量确认。复核后保留“合成”来源，只将复核状态改为“人工确认”；在此之前统一保留“合成、待人工复核”。开发提供的真实测试环境配置不是生产失败案例，须单独标“测试配置”。

**D2 及维护说明的二元 rubric。** 适用项全部为“是”才判该 case 通过；不适用须记录原因。

| 条目 | 问题与级别 | 正例锚点 | 反例锚点 |
| --- | --- | --- | --- |
| R1 对象可靠 | 名称、七项字段和复制结果是否属于同一合约，完整地址是否可核对？P0 | 名称变更后地址仍为 K，复制 K 完整原地址 | 显示 K 名称、复制成 M 地址，或复制缩写 |
| R2 状态可区分 | 空配置、读取失败、明确维护失败、结果待核对、冲突与成功是否区分？P1；未经核对假成功或堵塞业务则 P0 | “结果待核对”且不提前显示目标生效；读到目标后才确认成功 | 超时就报失败并断言未写入；未重读却显示成功；读取失败写“暂无合约” |
| R3 下一步正确 | 无合约、停用、冲突、回执不明与链上异常的下一步是否符合边界？P1；堵塞或误办业务则 P0 | 待核对仅限制同合约同项，其他维护可办；恢复读最新值；无匹配引导开发 | 冻结所有维护；停用后原业务重试要求先启用；要求运营新增合约 |
| R4 双语不变量 | 资产类型、状态翻译且含义一致；名称、ERC-3525、cou、Ethereum 和地址保持原文？P1；误识别升级 P0 | 中文和英文均显示 Ethereum、cou | 翻译已保存名称，cou 变 COU，Ethereum 写成 ETH |
| R5 维护知情 | 状态操作前能否确认目标名称、完整地址、当前及目标状态，理解对新二审的影响？P0 | 停用说明限制新选择，目标地址可核对，确认后提交 | 错对象或未确认执行；声称停用自动停止既有铸造 |

**分歧与持续复核。** 记录评审人、结论、依据锚点、证据和仲裁理由；产品解释业务规则，安全／合约负责人复核领域风险，测试与质量裁定分级和证据充分性。建议扩展阶段由测试组织对新增非 P0 case 抽查 20%，需要业务解释的请产品复核，P0 全量双人复核；每次 release 的人工判定抽 10% 交第二人盲审，比例、人员和资源待测试、质量及项目负责人确认。分歧未仲裁的 case 不作为发布通过证据；修 rubric 后同时复核受影响旧 case。

**人机对齐。** 当前不使用 LLM-as-judge。若未来仅为双语说明初筛引入模型，应先建立人工金标校准集并与正式评估集隔离，锁定模型版本和 rubric；一致率门槛与错判成本须事先确认，模型判定不替代人工签字，更不能判任何 P0、权限、并发、链上状态或原合约归属。现无校准数据，不声称 judge 可用。

## 5. 跑评频率

以下为设计采用的建议节奏；实际排期、执行资源与负责人待测试、质量及项目负责人确认，合入／发布签字待发布治理确认。只描述方案，不创建自动化、运行评测或发起线上实验。

| 层级与节奏 | 触发与范围 | 责任／产物 |
| --- | --- | --- |
| L1，每次相关 commit | M6、M5 权限或合约配置读取改动：权限拒绝、只读边界、用户感知字符计数与规范等价重名、状态迁移、明确失败／回执不明三分支与并发、可选范围、无通知和无自动业务副作用 | 研发与测试；逐条判定、证据与差异清单；是否阻断合入待质量与发布负责人确认 |
| L2，每次 release | 启动／稳态集全量，双语 rubric、角色矩阵、各类字符和回执恢复交错顺序；M3b/M4a/M4b 已就绪时做真实联调，尚未就绪明确列待验证 | 测试组织，产品解释预期，安全及相邻模块复核；按维度、级别、环境的结果，B 项清单、AC 映射及质量／发布放行记录 |
| 每周回归 | 名称和状态维护、二审提交与停用竞争、原合约铸造销毁重试；相关模块变更时立即加跑，不等周例行 | 测试与相邻模块负责人；回归记录及失败回流 |
| 每月或外部变更探索 | 本模块不调用模型，采用配置与链环境变化探索：合约新增／部署版本、节点或依赖变动、名称字符集和并发访问模式变化 | 合约研发与测试；部署字段核对、OOD 补充和影响分析；不把平台启用当作链健康证明 |

**L3 真实业务验证。** 只设计上线后的观察口径，观察不发起生产交易；权限、数据可用性和采集授权待数据、运维与安全负责人确认。以下指标不替代离线阻断项，也不承诺业务收益。

| 指标 | 分子／分母与解释 |
| --- | --- |
| 有效维护完成率 | 合法、经运营确认提交且最终成功持久化或重读目标值确认成功的维护次数 ÷ 合法、经运营确认提交的维护尝试；按改名、启用、停用分层。权限拒绝、重名、主动取消、并发冲突单列；回执不明的尝试保留在分母中并单列未决数，恢复核对后更新归类，同一尝试不重复计数；观察截止窗口待数据与业务运营确认 |
| 二审停用竞争拦截比例 | 因所选合约在提交前停用而拒绝通过的次数 ÷ 选过合约的二审通过提交次数；用于发现竞争集中处，不能用“越低越好”削弱提交复核 |
| 无可选合约阻塞比例 | 因无可选合约不能通过的尝试数 ÷ 二审通过尝试数；分全停用、无匹配、无配置，分别核对引导；不把已关闭工单当作问题解决 |
| 原合约手动重试发起率 | 已满足对应业务重试条件且手动触发后成功进入处理的次数 ÷ 同类手动重试尝试数；按平台启用／停用和链上异常原因分层，链上最终成功率另报，二者不能互相替代 |
| 维护副作用事件数 | 可归因于 M6 配置／维护而产生的意外通知、自动业务调用、原绑定变动各自计数；仅事件数无比例分母，不从零事件推断风险极低 |

观察周期、最小样本和比例统计适用性待数据与业务运营确认；告警线、归因、处置授权和止血负责人待运维、安全与业务运营确认。真实流量比例按有效样本数与 Wilson 区间报告；风险覆盖集含人为加重的并发和 OOD，不能用于估算整体用户失败率。流量角色、资产类型或合约数量变化时先排查范围与配置，再决定补充统计切片。

**失败回流与版本管理。**

1. 来源包括真实工单、业务观察、安全复核与联调失败。建议测试在 3 个工作日内脱敏、确认来源编号和复现条件，时限待测试及项目负责人确认；先标未核验，不把猜测写作真实失败。
2. 复现并确认属于产品问题后，增为“真实历史失败”case；B 项同时补绕过界面或相反交错顺序。责任团队核对修复和回归，规则缺口交 PRD 负责人，当前文档不改 PRD。
3. case 集按 `Eval-M6-vX.Y` 管理，记录 PRD 提交、case 版本、类型、人工复核状态、功能与 AC 锚点；环境、部署地址使用脱敏标识，原始证据按平台权限保存。
4. 本模块或相邻 PRD 变化时，对比 01、02、04 册与依赖约定，更新受影响 case、追溯关系及 Eval 索引；过期 case 归档并注明规则变更提交，不无声删除。需求变更回归标签建议至少保留到下一次 release，期限待测试与质量确认。
5. 风险覆盖集与真实流量统计集分开管理；新旧版本比较使用同一冻结 case 版本、同一环境和同一交错顺序配对，新增或作废 case 单列，不据此捏造“提升”。

**待确认的执行事项与责任方。** 以下只保留其他方决策或技术验证；产品预期已按新 PRD 定稿。

| 事项 | 本设计建议或核对内容 | 确认／验证责任方 |
| --- | --- | --- |
| 质量与发布制度 | P1/P2 定义、逐例等级；P0 零失败、P1 至少 95%、无效上限 5%、三次重复；合入／发布阻断、例外及签字授权 | 测试、质量与发布负责人；安全参与风险复核 |
| 执行安排 | 100 条启动集资源、稳态扩容、每次提交／发布／周／月节奏；20%／10% 抽查和 P0 双人复核安排；3 工作日回流时限 | 测试、质量及项目负责人 |
| 联调与等待窗口 | M3b/M4a/M4b 就绪、Ethereum 测试环境、链上等待及取证窗口、故障与回执丢失的区分 | 研发、合约负责人和测试 |
| 部署依赖（待验证） | 已明确开发提供配置、测试验证；按闭合的初始名称规则、ERC-3525、Ethereum、地址及小写 cou 核对；链上符号与元数据实际可读性，不能据产品取值推断技术已可用 | 研发、合约负责人供证，测试验证；责任分工已明确，具体证据与验证安排待落实 |
| 线上观察与处置 | 采集权限、周期、截止窗口、样本量、告警线、归因、处置权限及责任人；不新增全局暂停功能 | 数据确认统计口径与样本；运维、安全确认采集和告警；业务运营共同确认观察窗口、归因与处置 |
| 证据和数据保留 | 复核、回流及版本证据的访问范围与保留期限 | 测试、项目及数据治理负责人，安全复核 |

设计终版不等于这些事项已获批准，也不等于联调或评测已完成。技术验证若发现部署符号不为 `cou` 或无法读取，研发须带证据记录依赖问题；不得由 Eval 擅改业务取值，确需改规则时再走产品决策流程。
