本版同步 WS-511 2026-11-10 裁定与相关跨模块修订：开发人员重新分配运营初始密码与重置机构账号凭据、锁定即结束全部登录且到期清零计数保留级别、锁定期间错误不计数、找回验证资格 10 分钟、外部原目标进入默认页、菜单矩阵（机构待办与解除托管仅机构可见，销毁审核改为销毁记录）、越权访问可追溯、IANA 时区、本人改邮箱提交确认、密码变更通知定稿文案，以及客服邮箱提供前通知省略求助句；v2.3 同步安全记录长期保留（不设期限、不自动删除）与机构初始密码由平台随机生成。v2.1 草稿提出的越权访问记录口径已由 PRD 定稿：越权访问被拒绝列入安全记录（见第 2 节），本模块无产品待确认项。

**判定方式。** code-based 指未来可通过接口、页面状态、事件记录、时间控制和敏感字段扫描进行确定性断言；human 指按第 4 节二元 rubric 人工复核。启动阶段不使用 LLM-as-judge，也不允许模型裁决权限、安全或放行。

## 2. Case 数量与覆盖

**数量是计划，尚无已执行 case。** 建议启动集 120 条原子 case（D1 24、D2 28、D3 26、D4 24、D5 18）；以 56 条 AC 的全部子条件拆分为下限，数量不足时扩容，不能为满足 120 条而漏场景。稳态建议每维度 40～80 条，总计 200～400 条，主要展开角色/状态/入口、时钟边界、并发与回流；数量待测试负责人确认。

启动风险覆盖集计划：正常 36、边界 38、异常与对抗 36、OOD 10，共 120 条；历史失败暂为 0，未提供真实失败材料，不据此断言产品没有失败。安全边界多，采用高比例异常和边界场景。此人为配比不能解释线上流量；L3 统计集独立。

**必需切片（展开时不承诺用全笛卡尔积）：**

- 运营甲/乙/丙与机构 X/Y/Z，未登录/待首登/正常/锁定；机构启用/停用与账号状态交叉；面客端身份作为拒绝样本；运营乙在正常、待首登、锁定中三种状态下被开发人员重新分配初始密码。

- 时钟：2 分钟、10 分钟（验证码、再验证、找回验证资格分开）、60 秒、2 小时、4 小时，安全记录超过 180 天后仍在，以及锁定 15/30/60 分钟与到期后计数归零；在边界前/恰好/后采样，按 01/04 册已明确的口径判定；测试时钟与测量精度由研发、测试确定。

## 3. 通过线

**单例。** 预期全部满足、禁止行为均未出现才通过；一行模板拆分后逐个判定，不以多数子场景通过代表整行通过。无法执行标未验证；环境原因导致无法判定标无效，需研发证据及测试确认，重跑后再计入。产品超时、发码失败误报成功等是有效失败，不能排除。

**优先级。** P0 口径由业务方确认；P1/P2 采用现版 Eval 的定义与具体归类定稿，不回写 PRD。本文代表场景及 rubric 的级别随本版定稿；同一 case 多风险按最高级，业务阻断或涉及权限、凭据、数据泄露即为 P0；新增问题的业务影响歧义由产品仲裁，发布决定由测试、安全及发布方负责。

| 级别 | 定义 | 本模块示例 |
| --- | --- | --- |
| P0 | 影响业务进程，或危及平台安全（已确认口径） | 登录/找回不可用、未完成首次密码设置即进入业务、失效或重置前凭据仍可用、会话残留（含锁定、重置时其他设备）、锁定或验证被绕过、跨机构/跨角色访问、开放跳转、通知错投、占位符或凭据外露、安全审计缺失、机构停用被误作账号锁定 |
| P1 | 规则执行有偏差，用户会误解或多走一步，但有明确兜底或绕行，不阻断业务、不涉及安全（本 Eval 定稿） | 有默认页可继续但原目标丢失；语言保存失败未回显原值；可重试但读取错误表述不清；已确认图标形式不符但行为可用；定稿文案非关键字面差异；改邮箱确认说明缺项 |
| P2 | 呈现与体验细节，不影响用户判断、操作结果及业务状态（本 Eval 定稿） | 非关键措辞/视觉间距差异、状态与结果均可获知时的辅助反馈细节；不含已确认的图标约束与定稿文案 |

**以下指标采用方式与门槛全部为建议，待测试、安全及发布负责人确认；研发负责技术可行性与环境，产品只仲裁业务预期、影响与兜底，不代定发布门槛。不能视为已获发布授权。**

| 层级 | 建议通过线 | 理由 |
| --- | --- | --- |
| B1～B7 阻断候选 | 所有关联 case 0 失败且无未验证；任一次失败阻断 | 安全与业务错误不能靠平均抵消 |
| D1～D5 的 P0 | 每维度、每个必需切片 100% 通过 | 口径覆盖业务进程和平台安全 |
| 每维度的 P1 | 通过率 ≥95%；其余逐条建缺陷，产品说明业务影响与兜底，由测试、安全及发布负责人决定是否放行 | 有明确恢复路径的非阻断偏差可评审 |
| P2 | 不单设发布率阈值，保留缺陷与修复计划 | 体验细节的错误成本较低 |
| 完整性与整体 | 56 条 AC 全子条件映射率 100%，必需 case 无未验证；P0 对上一版无回归；各门槛同时满足 | 覆盖是发布前置条件，不能少跑以提高通过率 |
| 真实依赖 | 邮件、M7 本人消息、多设备会话与权限联调的 P0 全部通过；客服邮箱提供前/后两种环境均验证 | 模拟通过不证明真实接入正确 |

维度通过率 = 有效通过原子 case 数 ÷ 有效已执行原子 case 数；分别列 P0/P1/P2、角色、账号/机构状态、入口、界面语言、客服邮箱提供前/后、模拟/真实依赖，不合并掩盖安全切片。未验证、无效、跳过另列数量与原因，未验证的必需项不能视为通过。建议无效占计划执行数超过 5% 时暂停本轮结论、修复环境后重跑，此比例待确认。

有真实时序/依赖的会话、并发和通知 case 建议重复 3 次，任一次产品失败该 case 即失败；固定账号快照、依赖版本、时间基点、请求顺序/延迟，记录环境。登录失败枚举需对有效/无效邮箱做随机交错的配对时延观察，记录样本量与时延分布，不能以一次响应看似相同判通过；测量窗口、重复次数、可区分时延容差待安全负责人确认，不声称绝无侧信道。规则断言逐条判定，无须用置信区间替代；人工比例和未来 L3 比例按有效分子/分母与 Wilson 95% 区间报告（置信水平建议、待确认），小样本零失败不证明低风险。版本比较固定同一 case 集与环境逐例配对，新增 case 单列，未有稳定基线前不报告提升。

**失败兜底。** 按 PRD 核对：保存失败原值保留；验证失效重新开始；验证码真实发送失败说明并允许一次立即重试；账号锁定等到期；变更通知失败不回滚生效凭据；重新分配/重置凭据后新初始密码线下告知。[安全通知求助方式][support]为需求方上线后提供的官方客服邮箱，提供前按规则省略求助句、其余照常发送，提供前已发出的不补发，因此客服邮箱缺失不再使相关 case 未验证，但两种环境须分别验证。线上出现 B 类风险时建议先停止相关变更入口/回退受影响版本并保留证据，具体止血方式、责任人与响应时限待安全、研发/运维及发布方确认，本篇不执行处置。
