## 2. Case 数量与覆盖

**数量是计划，尚无已执行 case。** 建议启动集 100 条原子 case（D1 22、D2 24、D3 18、D4 22、D5 14）；以 49 条 AC 的全部子条件拆分为下限，数量不足时扩容，不能为满足 100 条而漏场景。稳态建议每维度 40～80 条，总计 200～400 条，主要展开角色/状态/入口、时钟边界、并发与回流；数量待测试负责人确认。

启动风险覆盖集计划：正常 30、边界 32、异常与对抗 30、OOD 8，共 100 条；历史失败暂为 0，未提供真实失败材料，不据此断言产品没有失败。安全边界多，采用高比例异常和边界场景。此人为配比不能解释线上流量；L3 统计集独立。

**必需切片（展开时不承诺用全笛卡尔积）：**

- 运营甲/乙与监管 X/Y，未登录/待首登/正常/锁定；监管启用/停用与账号状态交叉；面客端身份作为拒绝样本。
- 页面入口/直接 URL/接口/文件/消息链接；本人/他人/不存在对象；双设备、双标签页、延迟响应。
- 密码 7/8/20/21 字符、仅字母/数字、内外空格、相同当前/最近初始密码；邮箱 254/255 字符、大小写及空格。
- 时钟：2 分钟、10 分钟（验证码与再验证分开）、60 秒、30 分钟、4 小时、180 天；在边界前/恰好/后采样，未精确定义的临界点交产品确认，不能擅自放行。验证码满 10 分钟失效已明确。
- 三套失败计数必须隔离：密码、验证码、人机校验；邮箱/IP 发送额度及失败重试单独核对；成功/失败通知顺序与归属。
- 模拟依赖与真实邮件/消息/多设备联调分开。OOD 包括浏览器时区不可推断、不常见标准时区/夏令时、未知对象、外部原目标；使用合成地址与测试邮箱，不使用真实凭据。

## 3. 通过线

**单例。** 预期全部满足、禁止行为均未出现才通过；一行模板拆分后逐个判定，不以多数子场景通过代表整行通过。无法执行标未验证；环境原因导致无法判定标无效，需研发证据及测试确认，重跑后再计入。产品超时、发码失败误报成功等是有效失败，不能排除。

**优先级。** P0 口径由业务方确认，以下具体归类供评审；P1/P2 为 M1 同口径建议、待确认。同一 case 多风险按最高级，不能确定由产品仲裁。

| 级别 | 定义 | 本模块示例 |
| --- | --- | --- |
| P0 | 影响业务进程，或危及平台安全（已确认口径） | 登录/找回不可用、首登绕过、失效凭据仍可用、会话残留、锁定或验证被绕过、跨机构/跨角色访问、通知错投、凭据泄漏、安全审计缺失、停用打断在途 |
| P1 | 规则执行有偏差，用户会误解或多走一步，但有兜底或绕行，不阻断业务、不涉及安全（建议，待确认） | 有默认页可继续但原目标丢失；语言保存失败未回显原值；可重试但读取错误表述不清；已确认图标形式不符但行为可用 |
| P2 | 呈现与体验细节，不影响用户判断和操作（建议，待确认） | 非关键措辞/视觉间距差异、状态与结果均可获知时的辅助反馈细节；不含已确认的图标约束 |

**指标与门槛全部为建议、待业务/测试/安全负责人确认，不能视为已获发布授权。**

| 层级 | 建议通过线 | 理由 |
| --- | --- | --- |
| B1～B7 阻断候选 | 所有关联 case 0 失败且无未验证；任一次失败阻断 | 安全与业务错误不能靠平均抵消 |
| D1～D5 的 P0 | 每维度、每个必需切片 100% 通过 | 口径覆盖业务进程和平台安全 |
| 每维度的 P1 | 通过率 ≥95%；其余逐条建缺陷并由产品/测试书面说明兜底后决定是否放行 | 有明确恢复路径的非阻断偏差可评审 |
| P2 | 不单设发布率阈值，保留缺陷与修复计划 | 体验细节的错误成本较低 |
| 完整性与整体 | AC 全子条件映射率 100%，必需 case 无未验证；P0 对上一版无回归；各门槛同时满足 | 覆盖是发布前置条件，不能少跑以提高通过率 |
| 真实依赖 | 邮件、M7 本人消息、多设备会话与权限联调的 P0 全部通过 | 模拟通过不证明真实接入正确 |

维度通过率 = 有效通过原子 case 数 ÷ 有效已执行原子 case 数；分别列 P0/P1/P2、角色、账号/机构状态、入口、模拟/真实依赖，不合并掩盖安全切片。未验证、无效、跳过另列数量与原因，未验证的必需项不能视为通过。建议无效占计划执行数超过 5% 时暂停本轮结论、修复环境后重跑，此比例待确认。

有真实时序/依赖的会话、并发和通知 case 建议重复 3 次，任一次产品失败该 case 即失败；固定账号快照、依赖版本、时间基点、请求顺序/延迟，记录环境。登录失败枚举需对有效/无效邮箱做随机交错的配对时延观察，记录样本量与时延分布，不能以一次响应看似相同判通过；测量窗口、重复次数、可区分时延容差待安全负责人确认，不声称绝无侧信道。规则断言逐条判定，无须用置信区间替代；人工比例和未来 L3 比例按有效分子/分母与 Wilson 95% 区间报告（置信水平建议、待确认），小样本零失败不证明低风险。版本比较固定同一 case 集与环境逐例配对，新增 case 单列，未有稳定基线前不报告提升。

**失败兜底。** 按 PRD 核对：保存失败原值保留；验证失效重新开始；验证码真实发送失败说明并允许一次立即重试；账号锁定等到期；变更通知失败不回滚生效凭据。安全通知“非本人操作的求助渠道”由需求方提供，不能用占位链接当作可用兜底。线上出现 B 类风险时建议先停止相关变更入口/回退受影响版本并保留证据，具体止血方式、责任人与响应时限待业务及安全确认，本篇不执行处置。

**二元 rubric：适用项全部“是”才通过；不适用须说明理由。**

| 项 | 级别 | 可判问题 | 正例锚点 | 反例锚点 |

## 5. 跑评频率

以下仅是方案，所有节奏、责任与采用范围待确认，不创建自动化、执行评测或线上实验。

| 层级/节奏 | 触发与范围 | 建议责任与产物 |
| --- | --- | --- |
| L1 每次相关 commit | 登录/会话、账号、验证码/人机校验、再验证、权限中间件、邮件事件有变更；确定性拒绝、时钟与计数、首登/找回状态、改邮箱唯一性、敏感字段扫描 | 研发与测试；逐例结果、AC 映射与 B 类清单；是否阻断合入待确认 |
| L2 每次 release | 全量启动/稳态集；两角色、多状态、启用/停用、真实邮件/M7/多设备；通知双语与安全人工复核 | 测试组织，产品/安全/审校复核；分维度切片结果、未验证清单、配对回归与发布签字 |
| 每周回归 | 会话失效、跨机构数据/文件、验证码额度、运营本人安全消息、停用在途业务；相邻模块变化即加跑 | 测试；跨模块回归记录及回流 case |
| 每月或外部变化时探索 | 本模块无被测模型，替代 frontier eval：邮件服务/人机服务、浏览器/标准时区、身份或权限接口变化 | 研发与测试；兼容/OOD 清单，新增风险说明 |
| L3 上线后业务观察 | 经正常上线流程采用后，按真实流量观察账号恢复、变更与业务可达；不在本次接入或开展实验 | 产品/测试/安全；脱敏统计和调查结论，不能由离线率推断真实业务收益 |

L3 建议口径：合法有效凭据登录完成数÷合法有效凭据登录尝试数（排除已证明的主动取消，失败原因单列）；找回后成功重新登录数÷成功重置数（观察窗口待确认）；改邮箱后唯一账号与业务归属保持数÷成功改邮箱数；邮件服务受理数÷应发邮件事实数；本人安全消息可见事实数÷应产生站内消息事实数；误拒合法在途操作数÷停用机构合法在途操作数。真实投递/用户可读须另有证据，不能以服务受理冒充；观察周期、样本下限、告警线和响应时限待确认。来源按角色、机构状态、流程步骤、客户端与依赖版本分层；身份合法性无法确认的请求单列未知，不能任意排除改善比率。

**回流与版本。** 工单、告警、线上指标异常和 OOD 探索发现的问题，建议 3 个工作日内脱敏、复现并落历史失败 case（时限待确认），标明真实来源编号、规则提交、失败条件与复核人；B 类补接口/直链变体。未经证实的投诉保留为待核查，不充当真实失败。集合使用 `Eval-M5-LG-vX.Y`，本版依据完整提交 `9fca0c6e23a41ea9c259d628a57ca60b78f025b6`；PRD 任一册更新需对比规则、AC 和消息变更，更新受影响映射与需求变更回归标签，作废 case 归档留因。风险覆盖集与真实流量统计集分开；流量/机构状态/失败原因分布漂移后重估覆盖配比，不按人工风险配比加权解释线上总体。

**本节待确认：** 相关代码提交触发范围及 L1 阻断策略；真实邮件/人机服务/M7/多设备与相邻模块联调环境；周回归时间和责任人；L3 窗口、可区分时延判断、监测采用范围；求助联系渠道的需求方交付人与时间。数量见第 2 节、发布和无效比例见第 3 节、复审及校准见第 4 节，均仍待确认。
