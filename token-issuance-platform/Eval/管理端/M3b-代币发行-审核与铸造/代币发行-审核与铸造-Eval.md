## 1. 评估维度（3–5 个）

**范围与追溯。** 本模块评确定性业务表现，不评模型能力。覆盖企业申请交入 M3b 后的机构分配、首次材料待办、追加材料与文件授权、运营驳回或发起铸造、超时与重试、发行结果交接及五类消息。M3a 的申请创建、M5 的账号建立与机构档案、M6 的合约维护、M7 的通用阅读交互和 M4 的铸造后业务只核对交接契约。原型尺寸与组件规范由设计负责；Eval 核对已确认的信息层级与可判断性，不规定像素、高度或配色。

**统一判定用语。** code-based 是将来可通过响应、状态、记录、文件授权、交易与消息事实作出的确定性判定；human 是按证据和二元 rubric 人工复核。本次只写设计，不执行测试、不创建脚本框架、不调用被测模型。LLM-as-judge 不参与业务、安全、链上或发布阻断结论。

### D1 数据授权、撤权与文件边界

| 项目 | 内容 |
| --- | --- |
| 定义 | 运营进入发行审核；机构仅从材料待办访问获分配申请，企业仅见本企业申请与企业可见结果；访问权随当前名单、铸造快照及终态锁定名单准确切换 |
| 来源 | 01 [access][access]、[file-access][files]、[handoff][handoff]，A-ISSUE-01～02、R-ISSUE-06；AC-M3B-01～06、38、41、49～51、57 |
| 通过条件 | 页面和直接请求都判权。机构看不到企业业务签名、完整机构名单、运营操作账号及内部失败说明；企业不见机构名单、机构材料与内部记录。未分配或已移除机构不能访问申请、企业文件及共享材料，旧页面和文件直链同样拒绝且不泄露数据；移除后历史材料由有权角色保留。铸造中 / 失败快照内机构仍可追加，驳回 / 成功锁定名单内仅历史只读；不由本模块授予代币、监管或铸造后材料权限 |
| 失败条件与后果 | 越界读取、旧链接继续下载、移除后仍能保存、企业或机构获得不允许的内部字段，均失败；造成资料泄露或未授权业务。仅隐藏菜单不能判通过 |
| Grader | code-based：身份 × 申请六状态 × 名单归属 × 入口 / 接口 / 文件请求；human：安全复核响应内容、撤权时序和文件访问记录 |

| --- | --- |
| 定义 | 至少一家机构决定运营能否处理；材料数量与待办不决定能否铸造或驳回。名单、权限、待办与申请状态一起生效，旧版本不覆盖新版本 |
| 来源 | 01 A-ISSUE-08、R-ISSUE-06、[status][status]；02 图 1、状态机 1～2；AC-M3B-05、07～08、42～51、53～56 |

| Grader | code-based：关系版本、状态迁移、待办计数、文件事实与原子性；human：检查待办完成未被当作审核通过，材料历史可追溯 |

### D3 运营处理、数量价值与链上字段

| 项目 | 内容 |
| --- | --- |
| 定义 | 只有正常运营在运营处理中且最新名单非空时能驳回或发起铸造；数量按完整资产价值 1:1，单位价值独立决定初始估值；参数与名单快照冻结，重试不改值 |
| 来源 | 01 A-ISSUE-04～05、[onchain-fields][onchain]；AC-M3B-07、25～28、37、40、42、47、50 |
| 通过条件 | 零材料也能办理。首次合约须启用、资产类型匹配、Ethereum且兼容完整业务值；初始单位价值默认 1 USD，可填大于 0 的兼容精度值。数量不除以单位价值；初始估值=完整数量×单位价值；数量、单位价值、计算结果不能无损承载时不提交。确认重新校验状态、名单、合约、地址与数值，原子记录参数和名单快照后进入铸造中。驳回意见去首尾空白后非空、1～500 字符；驳回终止、名单锁定、关闭待办、停止上传、历史保留、资产已驳回且不能再次申请 |
| 链上证据 | 按当前 PRD 核对至少承载资产编号、完整资产价值、唯一到期时点、提交时接收地址、企业签名值、完整代币数量、代币符号、初始单位价值，以及交易本身合约地址与哈希。企业资料、申请文件及摘要、机构名单、机构材料、驳回意见、操作账号和消息不上链。核对签名记录的地址、时间、值及所签四项业务值；不沿用旧版“仅五项上链”“不展示所签内容”的限制，也不另造合约必须验签的要求 |
| 失败条件与后果 | 无机构或错状态仍处理、按单位价值反算数量、截断/四舍五入后铸造、使用查看者本地日期替换唯一到期时点、错误交易参数或额外隐私上链，均失败；可造成不可逆错铸或披露 |
| Grader | code-based：申请快照、完整十进制业务值、签名四项、名单版本、实际交易字段载体和回执对照；human：链上研发与安全复核编码及证据。承载能力未验证则相关范围待验，不能用页面显示正确代替真实能力 |

### D4 铸造生命周期与唯一结果

| 项目 | 内容 |
| --- | --- |
| 定义 | 平台签名、提交与链上执行按事实收口，等待与失败区分；超时不开放重试，失败后运营沿原参数手动重试，最多成功一次 |
| 来源 | 01 A-ISSUE-06～07、[minting-progress][progress]、handoff-mint；02 图 2～3；AC-M3B-07、28～32、36、39～40、57 |
| 通过条件 | 已提交才有哈希；签名/提交明确失败进入铸造失败，无值不编造；关闭页面不影响处理。每次尝试从进入铸造中分别计时，10 分钟无明确结果仍铸造中、无驳回/重试/调整名单。失败重试沿用原合约、上链信息、数量、单位价值、地址和快照；仅平台停用不改写既有合约；恢复本身不自动重试。未记录的重试不新增失败事实，已记录且实际失败的新尝试分别记载。成功为终态，生成唯一代币编号、完整结果及锁定名单，关闭待办，终止材料追加 |
| 失败条件与后果 | 超时转失败、自动重试、已成功再次铸造、迟到失败回退成功、重复回调产生重复代币或消息、仅平台停用错误阻断既有业务，均失败；可能重复发行或长期停滞 |
| Grader | code-based：时间推进、并发、重复/乱序结果、签名或提交失败及恢复、原合约停用；human：链上真实事实、尝试记录与终态唯一性复核 |

| 失败条件与后果 | 进度与状态矛盾、缺业务历史或误把上传当审核、企业泄露内部过程、消息串企业/漏关键结果/重复事件、成功消息去旧申请页面，均失败。视觉装饰不替代信息判定；不把“已读”当已处理 |
| Grader | code-based：跨端字段/状态、事件和消息事实、模板/动态值/时区；human：第4节逐项二元rubric，核对上方紧凑、底部时间线的信息分工，尺寸实现由设计规范承载 |

**关键阻断候选（发布政策为建议，待确认）。** B1 授权或撤权失效（D1）；B2 名单/待办/材料状态错乱或材料门槛阻断发行（D2）；B3 未满足处理前提、错数量/单位价值/到期时点或隐私上链（D3）；B4 重复发行、超时重试、终态回退（D4）；B5 企业/机构泄露内部信息、跨端事实冲突或消息越界（D5）。各项都单列，不能用平均分抵消。具体来源和 AC 见上表与第2节。

| B1～B5与全部P0 | 所有适用case完整执行，所有有效重复均通过；任何一次失败阻断，待验不能签通过 | 授权与不可逆发行风险不能平均抵消 |
| 各维度P1 | 至少95%，失败逐条有缺陷、兜底与书面决定；该切片不足20条时建议逐条通过 | 沿用M1候选思路，避免小样本掩盖单项，不当行业硬标准 |
| P2 | 不设独立比例门槛，记录并排期；一旦影响业务/安全重分级 | 纯视觉体验由设计规范复核 |
| 全量验收 | 当前48条AC每个适用分支均有case与证据；无遗漏和未解决P0 | 不沿用旧版无效AC，不按代表例数量签全量覆盖 |
| 真实联调 | 首次发布及合约/编码/权限/名单/消息交接变化后，适用P0具备真实证据 | 模拟页不能证明合约、交易结果、文件授权和跨端收件真实成立 |
| 整体 | 上述同时满足，P0无回归，所有未判定项有明确处置，产品/测试/链上研发/安全共同决定 | 设计文档完成不是发布通过 |

**随机性、统计与比较。** 并发、撤权窗口、异步回调、超时、消息重投及真实链上路径建议每例重复3次（次数待确认），固定申请快照/合约/事件序列，再单独加入乱序变体；有效P0任何一次失败都记case失败，不多数票。只有经证据证明独立环境故障且复核同意才能排除，产品超时处理错不能标无效。链上最终性/确认数/重组和结果恢复的取证由研发说明，3次重复不是确认数。

版本比较用同一冻结case集逐条配对，旧基线无证据不虚构。规则覆盖逐条看；小样本零失败不证明罕见事故概率低。人工比例或L3真实统计可建议用95% Wilson区间并给分子/分母/切片/窗口（方法及置信水平待确认）；风险加重集不用于解释线上总体成功率，同一申请多次尝试不当独立用户样本。本次无执行数据，不填写分数、区间、提升或显著性结论。

**兜底核对。** 最新条件不满足则不生效并返回最新结果；保存失败不改变名单/权限/待办；读取失败不当空；无兼容合约/数值不无损则不提交；明确失败才人工原参数重试；超时等待；缺原因或哈希不编造。每种兜底均需case。若实际出现越权或重复发行，暂停新处理、接管与恢复的责任和时限由业务/安全制定处置预案，Eval不发明撤销链上交易功能。

本节保留的是评估与发布治理待确认：P1/P2细分、规模、阈值、重复和放行政策、最终性证据与事故处置。已确认的零材料可处理、文件上限、单位价值大于0和10分钟超时规则照PRD判，不因治理待确认而变成可选项。

## 4. 标注方法

**记录字段。** case保存ID、版本、主维度/类别/风险、功能和AC、来源（合成或真实及凭据）、角色/机构归属、申请状态、名单版本/快照、待办状态、文件元信息、完整数值及单位/唯一时点、签名四项、事件次序、期望/禁止、证据、判定及理由。真实协议/文件/签名不复制进公开文档，私钥不进入标注材料；证据在授权范围保存，权限和留存期由安全/测试确认。

| 角色 | 责任 |
| --- | --- |
| 产品/PRD负责人 | 解释已确认规则、确认风险标级、仲裁是否属规则缺口；只有出现真实未定产品规则时才请求PRD提供最佳建议，Eval不自行改规则 |
| 测试负责人 | 拆分48条AC所有场景，维护功能↔AC↔case↔证据，复核无效与环境问题 |
| 研发/链上研发 | 提供名单原子性、实际内容识别、交易编码/精度/价值和最终性的可检查证据 |
| 安全 | 复核文件直链、即时撤权、内部字段、不可篡改和隐私不上链 |
| 业务代表/双语审校/设计 | 复核角色是否能判断下一步、双语与时区、顶部概览/底部时间线分工；设计复核尺寸与组件规范 |

启动：40条代表例全部先人工核对；测试与产品共同确认正式集预期，安全复核D1和关键阻断，链上研发复核D3/D4。human项两人独立判，分歧查原文和证据后仲裁，证据不足保持未判定；不得投票代替事实。扩展建议非P0新增case抽20%产品复核，P0/真实失败全部复核；持续建议每轮非P0人工结论抽10%第二人复判，失败/分歧/阻断全复审。比例与角色排班属治理建议、待确认。

**二元rubric：所有适用项为“是”才通过；不适用给理由。锚点均为合成、待人工复核。**

| 条目 | 判定问题 | 正锚点 | 反锚点 |
| --- | --- | --- | --- |
| R1 角色与动作（P0） | 机构只补材料且角色动作与当前状态一致吗？ | 待分配不能铸造；零材料但名单非空可处理 | 机构给出审核通过，或等材料齐全才能铸造 |
| R2 名单与披露（P0） | 各入口按当时名单判权，企业/机构看不到禁止字段吗？ | 移除后旧文件链接拒绝，当前机构看不到签名 | 仅藏按钮；机构响应含全名单/账号；企业见内部时间线 |
| R3 数量与时点（P0） | 完整数量、单位价值、估值、地址和时点可分别核对吗？ | 12,345.675 COU×0.8 USD=9,876.54 USD；原地址及唯一时点不变 | 以0.8反算数量，或用两位显示值铸造 |
| R4 双层进度（通常P1，误导/阻断升P0） | 上方紧凑四阶段仅概览，底部按早到晚列适用操作和真实证据吗？ | 底部多次名单调整/失败/重试均可追溯；说明和哈希按取得情况显示 | 顶部占用大量细节且底部缺记录，或上传/访问被重复画成业务环节 |
| R5 原文与异常（通常P1，错判/泄露升P0） | 空/读取失败可分辨，双语不改动态原文，时间含时区吗？ | 无哈希不造值，英文驳回原文有原文说明 | 编造内部原因、把失败当无材料、时区改业务时点 |
| R6 消息与落点（P0） | 五类事件收件、去重、内容、落点与03册一致吗？ | C05去代币详情，A03不含内部原因，有哈希才附 | C05去旧申请页、分配发旧待审消息、向机构发告警 |
| R7 视觉细节（P2） | 在信息完整可判且业务可继续前提下，是否符合当前原型/组件样式？ | 概览节制，详细操作集中底部 | 纯装饰或非关键措辞偏差；不把事实错误藏在P2里 |

**模型judge。** 启动不用；未来如需批量文案初筛，先人工双标仲裁独立校准集，与日常评估集/提示优化样本分离。建议至少40条正反锚点、非P0文案一致率至少95%（待确认），另查漏判失败；机器失败全转人工，通过抽20%复核，P0与链上/授权不交机器放行。未经校准不宣称可靠，本次不调用模型。

## 5. 跑评频率

以下均为设计建议，只描述触发、责任和产物，不执行、不建立自动化、不发线上实验。没有模型迭代需求，探索重点是外部依赖与兼容性。

| 层级/触发 | 范围 | 责任与产物 |
| --- | --- | --- |
| L1，每次相关commit | 列表/写入/文件授权，名单和待办原子性，单次材料边界/实际类型，单位价值/完整数量/估值，业务字段，状态/超时，五类来源事件及不发事件 | 研发、测试；确定性case与未判定清单，合入阻断政策待确认 |
| L2，每次release候选 | 全量48条AC场景，模拟与真实联调分片，撤权/并发/乱序，真实交易承载，五消息和跨端映射；人工核对四阶段概览及底部操作进度 | 测试组织，产品/链上/安全/设计复核；逐例证据、切片结果、回归与放行决定 |
| 每周或相邻契约变化时 | 全部P0、历史失败、文件权限、机构停用/重分配、冻结名单、M3a企业阶段、M6资格和既有归属、M7事件/落点 | 测试及模块负责人；差异及待验清单 |
| 每月探索或外部依赖升级时 | 合约精度/数量/单位价值承载、节点延迟/最终性、文件内容识别新变体、语言/时区兼容、异常恢复 | 研发/安全/测试；依赖证据、OOD补例与兼容性记录 |

**L3真实业务观察方案。** 上线后在独立真实流量统计集中观察，不用离线风险集比例解释实际业务收益，不把已读、材料待办完成或工单关闭当作发行成功。建议每周固定队列汇总，窗口与告警阈值待责任方确认。

| 观察量 | 口径 | 限制 |
| --- | --- | --- |
| 名单/访问一致性 | 已移除后仍成功访问/写入的事件数；有效保存后关系、待办、权限不一致的申请数 | 单独调查，不由平均成功率抵消；仅用合规日志证据，不扩大采集范围 |
| 分配与处理等待 | 提交→首次有效分配、分配→运营处理的时长分布；未处理申请数和等待时长 | 材料完成不作为处理前提；不能据等待量擅自要求机构审批 |
| 铸造收敛 | 固定首次发起时间队列、窗口内唯一成功申请数÷该队列唯一发起申请数 | 同报仍未决/观察未完成；按首次/有重试分层，不静默剔除未决 |
| 尝试失败与超时 | 已明确失败尝试÷有明确结果尝试；满10分钟仍未决尝试÷已完整观察到10分钟或此前收口尝试 | 同报待定数量；首次/重试分别计，每次超时不是失败 |
| 来源消息异常 | 超出时效仍不可见事件-收件人对÷应可见事件-收件人对，另列越界/重复/错误落点计数 | 普通事件60秒；到点事件应到时点后最晚6分钟，按M7；业务超时事实仍从铸造开始10分钟计算 |
| 结果冲突 | 链上、申请、代币结果、锁定名单交接不一致的唯一申请数、重复成功计数 | 不从锁定名单推导监管归属或铸造后权限，不在本模块评M4内部功能 |

比例建议用Wilson区间并附原始计数和切片；同申请多尝试相关，比较按申请聚合/配对，不当独立样本。对机构分配数量/类型、材料份数、资产类型、合约、单位价值和等待时长做分布漂移检查，变化用于补风险例，不能把异常占比当新业务门槛。没有基线不虚构提升/显著性。

**回流与版本。** 工单、运营处置、对账或安全事件经脱敏、复现、归因后，建议3个工作日内补例（时限待确认）。有真实来源编号才标真实，否则保持合成/待核实；P0补直接请求、旧页或并发变体。确认存在未定产品规则时，交PRD负责人提出最佳建议，本Eval不修改PRD。

本版case集为 `Eval-M3b-v2.0`，记录PRD模块提交 `07841acb639185e985e676788e57aea1f4531c57`、共用依赖提交、被评实现版本、合约/编码/环境、事件序列和标注规则。v1.0旧的一审/二审、企业选机构、监管协议、仅五项上链、旧八类消息与监管/代币权限预期不再使用；原版本通过Git历史归档，不混入新分母。PRD或依赖更新需重做功能↔AC↔case映射，作废条目留原因与提交号。风险覆盖集和L3统计集独立版本化；比较固定同一集，不把新增难例造成的比率变化误说成版本退步。

本节仅保留执行与治理事项：联调/合约承载证据、L1/L2责任和放行安排、回归节奏、观察窗口、证据留存及事件处置预案待责任方落实。当前无新增产品待确认项；本次仅更新Eval内容，未执行产品评测，未修改PRD、原型或组件规范。
