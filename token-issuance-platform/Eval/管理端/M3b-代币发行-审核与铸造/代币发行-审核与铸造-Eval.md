## 1. 评估维度（3–5 个）

**需求版本与范围。** 依据 `cly-v6.0.0` 上本模块四册 PRD，目录最后修订提交为 [`3841bd61a01c94d43b9de6270e21d469a4f6c29d`](https://github.com/wxblockchain/Chain-Financing/commit/3841bd61a01c94d43b9de6270e21d469a4f6c29d)；引用的 M2、M3a、M4a、M4b、M5、M6、M7 规则按同一分支同一时点。v3.0 按当前四册重写：机构在申请详情可见除企业业务签名、内部铸造失败说明和同一资产其他申请以外的全部信息（AC-M3B-64）；资产价值按两位小数截断展示且只在发起铸造复核中出现（AC-M3B-68）；同一资产驳回后重新申请时各申请的机构关联互不扩大（AC-M3B-75、76）；铸造成功后的追加材料改由 M4b [R-TOKEN-02][r-token-02] 承接，本模块只评关闭待办、只读展示和入口边界。v2.2 中“机构不见完整名单和操作账号”“超时/失败后可驳回”“上链至少含数量与代币符号”“上游撤销确权提示”等预期按新规则作废。

本模块评确定性业务表现，不评模型能力。覆盖：运营与机构入口、申请详情逐区可见范围、文件与材料访问、机构分配与首次材料待办、已关闭申请历史、发起铸造与驳回、铸造超时/失败/重试与成功收口、向 M2 提供的机构关联结果、企业端状态映射及本模块六类消息。M3a 的申请创建与重新发起入口、M2 的资产展示与列表通用规则、M4a 的发行机构文件页面、M4b 的铸造后追加和资产托管、M5 的机构档案、M6 的合约资格定义、M7 的通用收件与阅读只核对交接契约。原型尺寸与组件规范由设计负责。

**统一判定用语。** code-based 指将来可依据响应、状态、记录、文件授权、交易与消息事实作出的确定性判定；human 指按证据和二元 rubric 人工复核。本次只写设计，不执行测试、不建脚本框架、不调用被测模型。LLM-as-judge 不参与业务、安全、链上或发布阻断结论。

### D1 数据授权与可见范围

| 项目 | 内容 |
| --- | --- |
| 定义 | 运营可见全部申请；机构只经“机构待办”进入获分配或曾在锁定名单内的申请，按阶段取当前名单、铸造快照或锁定名单判权；企业在本模块之外只见企业可见结果，铸造成功后才经 M4a 只读查看本次发行机构材料 |
| 来源 | 01 access、A-ISSUE-02、file-access、handoff、closed-history；AC-M3B-01～06、38、41、64、60、65 |
| 通过条件 | 页面与直接请求都判权，入口隐藏不算通过。机构不显示“发行审核”，运营不显示“机构待办”。名单内机构在申请详情可见申请概览（真实状态）、企业与资产、接收地址与申请文件、完整机构名单、共享材料、所选合约与初始代币单位价值、交易哈希、失败与重试记录、成功代币信息、驳回意见原文及操作进度中的角色与账号；企业业务签名、内部铸造失败说明、同一资产的其他申请三项不展示，直接请求也不返回。未分配或从未进入名单的机构与访问不存在申请得到相同拒绝。企业：铸造成功前与运营驳回的申请不展示机构材料，直接请求按无权处理且不透露材料是否存在；铸造成功后只在 M4a 发行机构文件只读查看、下载锁定名单内机构的全部材料（含经 M4b 追加的），每条只含上传机构、说明、时间、原文件名、格式、大小，不见访问记录，不能写；其他企业一律拒绝。提交后任何身份都不能补传、替换或删除企业申请文件 |
| 失败条件与后果 | 机构取得签名、内部失败说明或同一资产其他申请；机构被错误隐藏完整名单、操作账号等已允许信息；企业提前见机构材料或可推断其存在；未授权机构凭直链或旧页读取；任何身份改动企业文件或历史材料，均失败。前三类造成泄露或越权，“该见未见”影响机构判断 |
| Grader | code-based：身份（运营/当前、快照、锁定名单内机构/名单外机构/提交企业/其他企业/未登录）× 申请六状态 × 信息区/接口/文件请求；human：安全复核响应体、错误信息是否泄露存在性、文件访问记录 |

### D2 机构分配、待办与材料

| 项目 | 内容 |
| --- | --- |
| 定义 | 名单只增不减、每种机构类型最多一家，保存整次成功或整次失败；每个“机构 + 申请”一条首次材料待办，材料与运营处理并行且不构成处理前提；驳回或铸造成功后待办关闭、转入已关闭申请历史，本模块停止上传 |
| 来源 | 01 A-ISSUE-08、R-ISSUE-06、closed-history；02 图 1、图 3、状态机 2；AC-M3B-05、42～48、50、51、54～56、58、65、70、72、73、57 |
| 通过条件 | 候选只含 M5 当前启用且类型未在名单中的机构；保存前确认本次机构名称、类型及“保存后不能移除或替换”；未选、选停用、同次同类型、类型已占用、申请不可分配时整次失败，名单/权限/待办/状态不变。不提供移除/替换，直接提交拒绝；误分配只能驳回。首次保存后进入运营处理中且不再回到待分配机构；驳回或铸造中后不能新增。已分配机构停用后分配、待办、访问继续有效并占用类型；类型按分配时记录，M5 改类型不使名单失效，再新增按名单已存类型与候选最新类型判重。并发新增按最新名单重判。首次成功材料完成待办，追加不建新待办。每次追加：说明去首尾空白后必填；1～10 份、每份最大 10×1024×1024 字节；按实际内容只收 PDF/JPG/JPEG/PNG；有上传中或失败项不能保存；不设累计上限，不覆盖或删除历史。待办列表与已关闭申请历史的字段、查找、筛选取值、默认排序（分配时间/关闭时间由新到旧）、关闭时间口径、分页与读取失败符合 PRD；已关闭申请不在待办中，未进入锁定名单的申请不在历史中。铸造成功后本模块无追加入口，经 M4b 追加的材料在申请详情只读出现 |
| 失败条件与后果 | 同类型两家、部分保存、已分配机构被移除/替换或因停用/改类型失效、无确认即保存、首次待办重复或被追加重开、零材料阻断处理、累计份数被当单次上限、伪装文件落库、驳回或成功后仍可在本模块上传、历史列表混入待办或他人申请、读取失败显示为“暂无”，均失败 |
| Grader | code-based：名单版本、按分配时类型判重、状态迁移、待办计数与状态、文件实际类型与字节、列表结果集与排序；human：确认步信息完整、待办完成未被表达为审核通过、历史关闭时间与详情一致 |

### D3 运营处理、数值与上链字段

| 项目 | 内容 |
| --- | --- |
| 定义 | 只有正常运营在运营处理中、名单至少一家时可驳回；发起铸造另须名单中有一家资产托管机构。代币数量按原始资产价值 1:1，初始代币单位价值只决定资产价值；每次铸造写入链上的业务字段固定六项。驳回只终止本申请，资产回到可发行，企业可用同一资产另行申请 |
| 来源 | 01 A-ISSUE-04、onchain-fields、unit-value-display、A-ISSUE-05；02 图 2、图 3；AC-M3B-07、25～27、36、40、47、59、68、74、75 |
| 通过条件 | 资产托管机构前提按分配时类型判断，该机构之后停用或在 M5 改类型仍满足；没有时页面与直接提交都拒绝并说明须先新增，新增与驳回仍可用。合约只取 M6 F-CT-02 范围（启用、资产类型匹配、Ethereum），无合格合约、读取失败、未选、提交前停用、类型不符、非 Ethereum 均不发交易。初始代币单位价值默认 1、须大于 0 且不超过合约与业务共同支持的精度，各处以“1 COU = X USD”展示完整值，不补零、不截断、不四舍五入。数量不按单位价值反算；资产价值=完整数量×初始代币单位价值，按 M2 两位小数截断展示并可查看完整值，不上链，不因位数阻断，铸造成功记录不再展示。确认时重校状态、名单、合约资格和单位价值，原子记录参数与名单快照并进入铸造中。驳回不要求合约、资产托管机构或材料；意见去首尾空格后 1～500 字符；提交前提示本申请终止、企业可另行发起；成功后名单锁定、待办关闭、资产回到可发行。新申请为新编号、从待分配机构开始，原申请名单、待办、材料和关联不带入 |
| 上链证据 | 写入业务字段恰为资产编号、原始资产价值（完整值，等于代币数量）、唯一到期时点、提交时接收地址、企业业务签名值、初始代币单位价值六项，不增不减；代币符号由所属合约体现，不作为写入字段；合约地址与交易哈希记录在铸造结果中；申请文件及摘要、企业资料、机构名单、材料、驳回意见、操作账号和消息不上链；重试写入值不变 |
| 失败条件与后果 | 无资产托管机构仍铸造、驳回被该前提误挡、停用/改类型的资产托管机构被判不满足、按单位价值反算数量、单位价值被截断或补零、资产价值四舍五入或上链、多写或漏写上链字段、按查看者本地日期改写到期时点、驳回后资产未回到可发行或新申请继承旧名单，均失败；可造成不可逆错铸或披露 |
| Grader | code-based：申请与铸造快照、完整十进制值、展示字符串、交易解码字段集合与值、资产发行状态；human：链上研发与安全复核交易编码、精度与证据。合约承载与精度未经研发验证时相关 case 记为待验，不能用页面显示正确替代 |

### D4 铸造生命周期与唯一结果

| 项目 | 内容 |
| --- | --- |
| 定义 | 平台签名、提交与链上执行按事实收口；超时不是失败，平台不提供重试或驳回，由开发人员线下查明后按实际结果收口；铸造失败只有按原参数手动重试一个出口；每笔申请最多成功一次 |
| 来源 | 01 A-ISSUE-06、minting-progress、handoff-mint、mint-failed、A-ISSUE-07、依赖；02 图 2、状态机 1；AC-M3B-07、28～32、36、39、57、67 |
| 通过条件 | 展示“平台签名并提交”“等待链上结果”两阶段，已提交才有哈希，关闭页面不影响处理；签名或提交明确失败进入铸造失败。每次尝试从进入铸造中起计时，满 10 分钟无明确结果仍为铸造中，不提供重试、驳回或新增机构，企业仍见发行处理中、资产保持发行申请中；收口为成功或失败按对应规则处理。失败记录取得的说明和已产生的哈希，取不到不编造；只能按原合约、上链信息、单位价值、数量、地址和名单快照手动重试，不重校资产托管前提；原合约被平台停用不阻断重试；不提供驳回或终止（直接提交也拒绝），重试无法解决时申请长期保持铸造失败。重试未能记录则不生效、不提交交易、不发消息；已记录的每次尝试单独记录结果；平台不自动重试；并发重试仅第一笔生效。成功为终态：资产已发行，生成唯一代币编号与完整结果，名单快照成为锁定名单（含分配时类型、恰有一家资产托管机构），关闭待办，本模块不再接受名单修改或上传 |
| 失败条件与后果 | 超时转失败或开放重试/驳回、失败后可驳回或终止、自动重试、重试改值或换合约、未记录的重试仍发交易或消息、已成功再次铸造、迟到失败覆盖成功、重复回调产生重复代币或消息、编造哈希或失败原因，均失败；可能重复发行或无法收口 |
| Grader | code-based：时间推进、并发、重复/乱序结果、签名/提交/执行失败、重试记录失败、原合约停用、终态写请求；human：链上真实事实、尝试记录与终态唯一性复核。“开发人员查明结果”的平台录入方式与留痕由研发说明，未说明前相关 case 记为待验 |

### D5 跨端映射、进度、关联与消息

| 项目 | 内容 |
| --- | --- |
| 定义 | 运营能判断内部阶段与完整操作历史；企业只看四个企业状态；本模块向 M2 提供准确的机构关联结果；六类消息只由真实事实产生、发给正确收件范围并落到正确页面 |
| 来源 | 01 A-ISSUE-01、02、handoff、institution-link；03 全册；AC-M3B-08～11、13、15、16、33、34、37、53、61～63、66、69、71、76 |
| 通过条件 | 列表字段、搜索/筛选、默认排序（最近处理时间倒序、同时间申请编号倒序）、待分配机构与运营处理中分列、机构数量按当前/快照/锁定名单计；分页、返回位置、无数据/无匹配/读取失败按 M2 通用规则。详情上方紧凑四阶段只示完成/当前/未开始；底部操作进度从早到晚列提交、每次新增机构、驳回、首次发起、明确失败、重试、成功，含动作或结果、操作角色与账号、带时区时间、结果及已取得的意见/失败说明/哈希；材料上传与文件访问不进操作进度。债务人名称与英文名称和 M2 一致，未提供不补写。语言切换不改业务原值，时间换算并标时区。企业端：待分配与运营处理中均为“运营处理中”，铸造中/失败均为“发行处理中”，驳回同步意见原文。机构关联：待分配无关联；首次保存起建立，按阶段取当前名单/快照/锁定名单；驳回与成功后保留只读；停用、改名、改类型不解除；同一资产的新旧申请关联互不转入，不扩大代币查看范围，不授予审核、代币或资产托管权限 |
| 消息条件 | NT-C03 首次进入铸造、NT-C04 驳回成功（含意见原文与可重新发起提示）→ 申请所属企业的 M3a 申请详情；NT-C05 铸造成功（含申请号、代币号、完整数量和符号）→ 所属企业的 M4a 代币详情；NT-A03 每次明确失败、NT-A05 每次尝试满 10 分钟（提示联系开发人员）、NT-A07 提交成功进入待分配机构（含申请号与企业名称）→ 全体运营的 M3b 申请详情。机构不收六类消息；分配、新增、停用、待办与本模块上传不发消息；重试不重发 NT-C03；NT-A03 正文不含内部失败说明，有哈希才附；按同一事实去重，消息失败不触发业务重放 |

## 3. 通过线

**分级。** P0 定义为“影响业务进程，或危及平台安全”，沿用业务方已确认口径。以下细分与发布政策由责任方确认，不作为新的产品功能待确认：

| 等级 | 口径与本模块例子 |
| --- | --- |
| P0 | 越权与泄露（机构取得三项禁止信息、企业提前见材料、关联扩大）、既有分配被移除或失效、同类型多家、部分保存、无资产托管机构仍铸造、数量/单位价值/资产价值/上链字段错误、超时或失败开放驳回、改值或自动重试、重复发行、终态回退、本模块铸造后仍可上传、关键消息错发漏发 |
| P1（建议，待确认） | 有兜底、可继续且不涉及安全的信息组织偏差，例如待办/历史列表查找结果正确但排序或分页返回欠准、次要操作进度字段呈现不清；若可能误操作、无法推进或泄露则升 P0 |
| P2（建议，待确认） | 不影响判断与动作的纯体验细节；高度、间距、配色由设计规范复核，不设业务通过比例 |

case 含多项时取最高风险，由产品与测试确认；安全争议由安全复核。单例须全部期望满足、禁止行为未发生且证据充分才通过。无证据、环境不可用、合约承载未验证或开发人员查明结果的录入方式未说明时记为未判定/待验，不当通过。

**口径与门槛（均为建议，待责任方确认）。** 通过率 = 通过的独立 case 数 ÷ 有效已判定 case 数（通过 + 失败）；覆盖率 = 有效执行的适用 case 数 ÷ 计划适用 case 数。按维度、优先级、身份、申请状态、首次/重试、模拟/真实切片分别报告；未执行、待验、环境阻塞与确认无效的数量和原因一并报告，N/A 不写 100%。同一 case 重复不增加独立样本数，跨维标签不重复计入维度。

| 层级 | 候选线 | 理由 |
| --- | --- | --- |
| B1～B5 与全部 P0 | 所有适用 case 完整执行，所有有效重复均通过；任何一次失败即阻断，待验不能签通过 | 授权与不可逆发行风险不能被平均值抵消 |
| 各维度 P1 | 至少 95%，失败逐条有缺陷单、兜底与书面决定；切片不足 20 条时建议逐条通过 | 小样本比例不可靠，不当行业硬标准 |
| P2 | 不设独立比例，记录排期；影响业务或安全即重新分级 | 视觉由设计规范承载 |

| 整体 | 上述同时满足，P0 无回归，未判定项有明确处置，由产品、测试、链上研发、安全共同决定 | 设计文档完成不是发布通过 |

**随机性、统计与比较。** 并发、判权时点、异步回调、超时、重试记录失败、消息重投与真实链上路径建议每例重复 3 次（次数待确认），固定申请快照、合约与事件序列，另加乱序变体；有效 P0 任何一次失败即记失败，不取多数。只有经证据证明为独立环境故障并经复核同意才可排除。链上最终性、确认数与重组的取证由研发说明，3 次重复不是确认数。版本比较用同一冻结 case 集逐条配对，旧基线无证据不虚构。人工比例或 L3 真实统计可用 95% Wilson 区间并附分子、分母、切片与窗口（方法与置信水平待确认）；风险加重集不用于解释线上总体成功率；同一申请多次尝试不当独立样本。本次无执行数据，不填写分数、区间、提升或显著性。

**兜底核对。** 最新条件不满足则不生效并返回最新结果；保存失败不改名单、权限、待办；读取失败不当空；无资产托管机构或无合格合约不提交；超时等待开发人员查明，不开放驳回或重试；失败只按原参数手动重试；缺原因或哈希不编造；驳回后资产回到可发行。每种兜底均需 case。若实际发生越权或重复发行，暂停新处理、接管与恢复的责任和时限由业务、安全制定预案，Eval 不发明撤销链上交易功能。

本节保留的只是评估与发布治理事项：P1/P2 细分、规模、阈值、重复次数与放行政策、最终性证据和事故预案。已确认的产品规则照 PRD 判，不因治理待确认变成可选项。
