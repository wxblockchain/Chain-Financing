| 来源 | 01 册 [access][access]、R-ISSUE-01～03、A-ISSUE-01～03、[handoff][handoff]；02 册图 4；AC-M3B-01～05、11～12、17、29、37～38 |

| 判定 | code-based：身份 × 七种状态 × 归属 × 访问方式矩阵，检查响应与下载授权；human：安全复核拒绝响应、信息最小化和停用机构例外 |

### D2 审核状态、协议与操作原子性

| 项 | 内容 |
| --- | --- |
| 定义 | 一审 → 二审 → 铸造顺序不可绕过；审核不可撤销、不可改写；取消、保存失败与并发不产生半次业务事实 |
| 来源 | 01 册 [concurrency][concurrency]、[status][status]、R-ISSUE-04～05、A-ISSUE-04～05；02 册图 1～3；AC-M3B-06～08、12、19～27、33～34 |
| 通过条件 | 一审通过至少 1 份、最多 10 份成功上传的 PDF / JPG / JPEG / PNG，单份不超过 10MB、非空；上传中或失败文件未移除时不能通过，同名各算一份。监管意见选填，空白视为未填；两级驳回意见必填，均最多 500 字符。取消或离开不保存草稿，保存失败保留可重试输入但申请不变。五类操作均以最新权限、状态执行，只生效一次并留操作账号、角色、机构、时间及前后状态；驳回终止，资产已驳回、解除申请引用，不能重新申请；二审驳回保留协议；已提交记录不可改写 |
| 失败条件 / 后果 | 无协议通过、无有效驳回意见驳回、跳审、终态重开、并发覆盖、状态变了而文件未保存、保存失败却发消息或发链上交易，均失败；会使审核依据缺失、业务错误终止或资产重复发行 |
| 判定 | code-based：状态迁移与文件 / 意见边界、五类操作的重复请求和保存失败事实核对；human：不可撤销确认、协议开放及审计证据完整性复核 |

### D3 合约选择、平台签名与上链事实

| 项 | 内容 |
| --- | --- |
| 定义 | 二审只选符合条件的一个合约；平台按原申请和原合约铸造，链上事实可核对、签名可公开验证，不能多铸、错铸或夹带不应上链的业务信息 |
| 来源 | 01 册 A-ISSUE-04、A-ISSUE-06～07、[available-contracts][contracts]、[onchain-fields][onchain]、[handoff-signature][signature]；AC-M3B-25～26、28、31～32、36～37、40 |
| 通过条件 | 首次选择同时满足应收账款、Ethereum、启用，并能无损承载本申请完整小数精度与唯一到期时点；无预选，确认提交再核对。两步确认只读五项：接收地址、完整数量、唯一到期时点、资产编号、企业业务签名值；数量为申请完整资产价值 1:1、保留相同小数精度，单位为所选合约符号（当前 cou），不以 USD 为单位。运营不需要钱包、不接触私钥。实际交易的五项与申请一致，首次及重试相同；仅凭链上数据可验证企业签名并恢复为记录中的签名地址；企业名称、债务人、协议、审核意见、账号、申请编号、签名时间 / 地址、币种与价值文字等不上链；链本身产生的交易对象等不当作额外业务字段。驳回不发链上交易 |
| 失败条件 / 后果 | 合约已不可用仍首次通过、篡改地址 / 数量 / 到期日 / 编号 / 签名、重试换合约、签名不可验证、不应上链的信息进入交易或元数据、把交易已提交当作成功，均失败；资产错误不可逆，链上披露不能靠删除界面修复 |
| 判定 | code-based：对照申请快照、确认页、解码后的交易输入及实际承载的事件 / 属性 / 元数据，核对链上结果和签名恢复；human：链上研发与安全复核。具体编码、完整精度与唯一到期时点的无损承载、字段载体及交易成本为 PRD 已列的待开发验证依赖；未经研发验证，AC-M3B-25 的相关筛选 / 上链部分和 AC-M3B-40 须待验、不判通过；不能用两位截断值或查看者本地日期替代。不擅自规定合约必须验签 |

### D4 铸造生命周期、超时与重试收敛

| 项 | 内容 |
| --- | --- |
| 定义 | 二审成功后持续取得链上结果；铸造中、失败、成功和超时按事实区分，平台停用不切断既有业务，同一申请最多成功一次 |
| 来源 | 01 册 A-ISSUE-06～07、[minting-progress][progress]、[mint-timeout][timeout]；02 册图 2～3；AC-M3B-07、28～32、36、39 |
| 通过条件 | 二审已记录后平台签名失败或提交失败，转铸造失败，没有交易哈希；已上链失败保留真实哈希；未取得失败原因不编造。关闭进度不影响铸造。每次进入铸造中分别计时，未满 10 分钟不提醒，满 10 分钟无结果只提醒运营、仍铸造中，无自动失败、重试或驳回；结果返回后详情超时提醒消失，历史超时消息保留。仅铸造失败可由运营手动沿原合约重试；平台停用不要求重新启用，不改选；实际链上异常待开发处理，恢复本身不自动铸造。重试未记录不产生新失败，已记录但提交失败形成新失败。重复、并发或迟到结果不得使已成功申请再次铸造 |
| 失败条件 / 后果 | 超时误判失败开放重试、成功仍重试、自动重试、仅平台停用就阻断原申请、处理顺序错乱覆盖成功，均失败；可能重复铸造或使企业发行长期停滞 |
| 判定 | code-based：时间推进、返回结果乱序 / 重复、并发重试、签名与提交故障、平台停用及链上异常分别注入；human：链上事实与人工处置路径复核，不把“进度已关闭”作为完成证据 |

## 2. Case 数量与覆盖

**数量与组织。** 建议启动风险覆盖集至少 96 条独立 case：D1 18、D2 24、D3 18、D4 20、D5 16。43 条 AC 大多包含多场景，因此不把 43 当作 case 数；96 是初步排期量，若拆分后不够覆盖所有 AC 的全部场景须扩充，不能删场景凑数。稳态建议 180～260 条，优先扩展权限矩阵、异步时序、协议边界、跨端字段与真实失败。数量待测试负责人确认。

本文实际给出下表 **35 条代表性用例设计**，均为 **“合成、待人工复核”**，不是已建立或执行的数据集；其余启动条目和代表例中的参数分支由测试按映射拆分。没有收到可复现的真实生产失败材料，历史失败目前计划 0 条，不宣称产品尚未上线或没有线上缺陷。

## 3. 通过线

**优先级与口径。** 沿用 M1 定义；除 P0 的定义外，以下分级细化与全部发布门槛均为建议、待确认。

| 级别 | 定义 | 本模块例子 |
| --- | --- | --- |
| P0 | **影响业务进程，或危及平台安全**（业务方已确认） | 越权、资料泄露、跳审、错误终止、协议无效仍通过、并发覆盖、五项上链错误、重复铸造、超时重试、错误阻断在途业务、状态 / 引用冲突、关键待办丢失 |
| P1 | 规则执行有偏差，用户会误解或多走一步，但有兜底或绕行，不阻断业务、不涉及安全（建议，待确认） | 可恢复的空态提示混淆、已有明确正确结果时旧超时消息文案理解偏差、动态原文 / 时区呈现偏差且不影响业务判断。若可能错审或泄露按 P0 |
| P2 | 呈现与体验细节，不影响用户判断和操作（建议，待确认） | 非关键辅助措辞不一致、进度装饰反馈欠佳但阶段、结果和下一步均可获知 |

一条 case 按最高风险标级；产品与测试共同确认，安全相关争议交安全负责人。P1 / P2 不得绕开 P0 口径。

**单例与分母。** 预期行为全部满足、禁止行为未出现且证据充分才通过；任一违反判失败。证据缺失、环境不可用标“未判定 / 环境阻塞”，不是通过。case 通过率 = 通过独立 case 数 ÷（通过 + 失败独立 case 数），同时报告计划数、实际执行数、未执行 / 无效 / 阻塞数与原因。覆盖率 = 已执行有效 case 数 ÷ 本轮计划适用 case 数。环境无效只能经研发提供证据、测试负责人复核后排除；产品本身的超时、签名不可用处理错误、链上失败处理错误不得当作环境问题抹除。某类无样本标 N/A，不写成 100%。

维度、优先级、角色、环境（模拟 / 真实联调）、首次 / 重试各切片分别统计；同一 case 重复执行不增加独立样本数，属于多维度的 case 只进主维度分母。AC 通过需要对应的所有场景均被覆盖、均通过，不用“43 条中抽几条通过”代表整个模块。

| 关键阻断 B1～B7 | 每条相关 case、每次有效重复均 0 失败；未执行 / 无证据也不能视作满足 | 权限和资产错误不可平均抵消；仍须全量风险覆盖 |
| D1～D5 的 P0 | 各切片 100% 通过，计划适用 P0 100% 执行 | 确定性规则的已知错误会直接影响业务 / 安全，不能用业务容忍比例替代 |
| 各维度 P1 | 通过率至少 95%；未通过项须明确不影响业务 / 安全，有缺陷单、兜底与产品 / 测试书面决定；不足 20 条时建议逐条全通过 | 参照 M1 候选门槛，避免一个小集的单条失败被汇总掩盖；95% 并非行业硬标准 |
| P2 | 不设单独比例门槛，逐条记录和排期；一旦影响判断 / 操作立即重分级 | 对纯体验细节保留可审阅的处理决定 |
| 真实联调 | 首次上线以及合约、签名编码、链上结果获取、权限或跨端交接变化后，适用 P0 均具备真实联调证据 | 模拟环境不能证明真实 ERC-3525 承载字段、签名恢复、数量精度、结果获取及消息承接有效 |
| 整体发布 | 覆盖全部 43 条 AC 的全部适用场景；上列同时满足；无未解决 P0、无 P0 回归、未判定项逐条处置；产品、测试、链上研发与安全确认 | 建议放行流程，待业务确认；文档完成不构成发布通过 |

**重复与比较。** 建议对并发提交、消息重投、异步结果、超时、真实链上 E2E 各重复 3 次，固定申请快照和事件次序，另设乱序变体。任何一次有效 P0 失败即该 case 失败，不取多数票。重复次数及环境稳定标准待确认；链上确认数、重组 / 回执最终性和结果恢复证据由研发说明、测试与业务确认，不能把这里的 3 次当作确认数。版本比较用同一 case 集版本、相同申请 / 合约配置和时序作逐条配对，旧版本缺证据时不虚构基线。

**不确定性。** 规则覆盖逐条呈现，不用人为加重的风险集估算线上发生率；小样本零失败不能证明罕见损失足够低。人工判定比例、L3 真实流量比例如需推断，建议使用 95% Wilson 区间，同时给分子、分母、窗口与切片；区间置信水平待确认。重复同一 case 不充当独立样本。本设计无执行数据，不填写任何区间、分数、改善幅度或显著性结论。

**失败兜底的评估。** PRD 已规定：保存失败不推进、合约不可用重新选择、无可无损承载的合约时不能通过但可驳回、签名 / 提交失败进入铸造失败、仅运营人工沿原合约重试、超时仍铸造中并线下联系开发、无失败原因不编造、上游不可用用最近保存信息、消息失败不撤销业务。每条兜底须有正常与失败证据。若线上出现错铸 / 泄露 / 重复事实，是否暂停新二审、停用来源入口或由何角色接管为处置预案建议，待业务 / 安全确认，不假定存在撤销链上交易的功能。

本节待确认：P1 / P2 分级、B 类与 P0 发布阻断政策、P1 比例、覆盖要求、重复次数、真实联调放行职责、最终性证据及线上处置方案。业务规则中的 10 分钟、10 份、10MB、500 字符不是这里新增的统计门槛，仍按 PRD 判定。

## 4. 标注方法

**证据记录。** case 保存 ID、主维度 / 类别、风险级别、功能与 AC 编号、PRD / Eval 版本、合成或真实来源、前置申请状态、操作者及归属、五项完整业务值快照（含精度与唯一到期时点）、合约配置、事件次序、期望 / 禁止、实际观察证据、通过 / 失败 / 未判定及理由。协议用受控样本和文件指纹核对正式版本；签名与交易值在受控证据中核对，不把真实签名、协议或个人信息复制进公开文档；私钥绝不作为标注材料。

| 角色 | 职责 |
| --- | --- |
| 产品 / PRD 负责人 | 解释业务预期、确认优先级、仲裁规则歧义；规则变更走 PRD 流程 |

| 安全复核 | 复核权限、协议访问、私钥边界、上链最小化、重试并发和重复成功风险 |
| 运营 / 监管业务代表与中英文审校 | 核对提示能否据以判断下一步、消息对象和双语含义，不以主观喜好改业务事实 |

启动阶段：产品与测试逐条确认预期，链上研发复核 D3 / D4，安全复核 B1～B7；35 条合成代表例全部人工复核后才扩成正式集。human 项建议由两人独立标二元结果，分歧先查证据，再由产品仲裁，安全 / 链上事实需对应负责人共同确认；证据不足保持未判定，不投票强行判通过。扩展阶段建议产品抽查新增非 P0 的 20%，P0 与真实失败全部复核；持续阶段建议每轮复审非 P0 人工结论的 10%，所有失败 / 分歧 / 阻断项全部复审。比例均待确认。

**二元 rubric。** 所有适用条目均为“是”才通过；不适用须写理由。页面布局和装饰不在本 rubric 范围。

**模型 judge。** 启动阶段不用。若未来双语审校量大，才考虑仅辅助 R4 / R6 的非 P0 文案初筛，不能判链上事实或自动放行。先以人工双标仲裁集建立独立校准集，与日常评估集、提示优化样本分离；建议至少 40 条平衡的正反锚点、一致率至少 95%，均待确认，且单独检查失败样本漏判。机器判失败和所有 P0 转人工；机器判通过建议抽 20% 人工复审。校准集不得作为产品版本效果证据。本次无校准或模型调用，不声明 judge 可靠。

| L1，每次相关 commit | 权限 / 字段白名单、状态与协议边界、五类提交幂等、合约首次选择条件、数量与编码、五项字段及禁入字段、超时时间 / 事件去重、消息模板；以模拟故障与时序为主 | 研发准备证据，测试复核；逐例判定与覆盖 / 未判定清单。是否阻断合入待确认 |

**L3 线上业务验证方案。** 待上线后使用真实业务事实观察，不拿“离线 case 通过”代替业务成功，也不以“消息已读 / 告警关闭”视为申请已处理。统计窗口建议每周汇总，观察阈值与升级时限待业务确认。

| 观察指标 | 分子 / 分母或计数口径 | 解读与限制 |
| --- | --- | --- |
| 成功铸造收敛率 | 指定提交时间队列内、在约定观察窗口中已确认成功的唯一申请数 ÷ 该队列二审已通过的唯一申请数 | 按首次 / 有重试拆分；窗口未完结的申请标右删失 / 仍在观察，不能静默排除以抬高比例；窗口待确认 |
| 铸造尝试失败率 | 已确认失败的尝试数 ÷ 已得到成功或失败结论的尝试数 | 同时报告未决尝试数与等待时长，区分未签名 / 提交拒绝 / 链上失败；尝试不是唯一申请 |
| 超时发生率 | 曾满 10 分钟仍无结果的尝试数 ÷ 已完整观察至少 10 分钟或已取得结果的尝试数 | 首次 / 重试分别计数；重复提醒不增加尝试数，不把 10 分钟超时等同失败 |
| 重试后收敛与人工等待 | 有人工重试且最终成功的唯一申请数 ÷ 同队列有人工重试的唯一申请数；另列从失败到首次人工重试、从二审到成功的时长分布 | 固定队列、窗口并列未决；用于发现人工处置瓶颈，不能据此要求自动重试 |
| 事实冲突与重复成功 | 每窗口链上成功 / 申请 / 资产 / 代币 / 引用不一致的唯一申请数；重复成功事实计数 | 单独调查，不能被平均成功率掩盖；是否触发暂停新二审由预案确认 |
| 来源消息异常 | 业务事件未按依赖时效可见的事件-收件人对数 ÷ 应可见的事件-收件人对数；另列越界 / 重复计数 | 普通事件按 M7 的 60 秒；到点消息按应到时点最晚 6 分钟。NT-A05 的 10 分钟为超时事实时点，不能把送达窗口挪作允许继续静默铸造的规则 |

L3 比例建议报告分层 Wilson 区间及原始计数，真实流量统计集独立保存；每周检查机构、语言、金额范围、合约、失败原因与等待时间分布漂移。无流量基线时先建立观察基线，不虚构损失率或收益提升；若同一申请多个尝试相关，比较时按申请聚合或配对，不把相关尝试当独立证据。任何阈值、加权方式和线上止血动作均待业务确认。

**失败回流。** 来源包括工单、运营线下超时处置结论、链上事实对账、消息异常及安全事件。建议发现后 3 个工作日内由测试脱敏、复现和归因（时限待确认）；有来源编号和可复现证据才标“真实失败”，否则保留合成 / 待核实。补入相应维度，P0 增加绕过界面或并发 / 乱序变体；规则缺口交 PRD 负责人，不能由 Eval 暗改业务。一次重复成功或泄露应按预案及时处置，不等待每周统计。

**版本与数据集管理。** case 集使用 `Eval-M3b-vX.Y`；记录 PRD 模块提交（当前 `aed2fb8f8ba899bc3d58cb63d4eec52da1a169b9`）、共用依赖提交、Eval 提交、被评产品版本、合约地址 / 配置 / 编码版本、环境、事件序列及标注规则。PRD 或依赖更新后做差异审查，维护功能↔AC↔case↔证据；需求变更导致作废的 case 归档留原因，不删历史。新增或漂移样本经人工复核进入新版本，风险覆盖集按风险补充，真实统计集按流量更新。以同一冻结集比较版本，不把新增难例带来的比率变化说成版本退步。当前仅交付设计文档和追溯关系，无评测执行、分数或通过结论。
