## 2. Case 数量与覆盖

建议启动 64 条原子 case：D1 12、D2 16、D3 14、D4 14、D5 8。依据是 23 条复合验收拆分、六状态组合、并发与附件生命周期；64 是启动预算，全部 AC 子条件覆盖不足时继续增加，不因数量上限省略风险。稳态建议 150～250 条，每维度约 25～60 条，扩充状态/访问路径/文件边界与真实回流；计划数量待测试负责人确认，没有已执行样本。

启动风险集计划正常 20、边界 20、异常与对抗 20、OOD 4，共 64 条。历史失败 0：未提供真实失败材料，不代表产品没有历史缺陷。异常及边界占比较高，因为权限、停用时点和取消/失败原值保留是主要风险。此集按风险构造，不能充当真实流量分布或线上总体体验指标。

**必需覆盖切片：**

- 正常运营甲/乙及监管/企业/未登录/待首登/锁定账号；入口、直接 URL、接口、文件链接；企业可选机构接口只能含名称。
- 机构启用/停用 × 待首登/正常/锁定六组合，企业填表前/填表中/提交时停用、已提交在途、再次启用，核对相关业务/消息模块。
- 名称 100/101 字、空格/大小写重名；登录与联系邮箱 254/255 字；联系人 60/61 字、全空格；密码 7/8/20/21 位、仅字母/数字、内外空格。联系邮箱重复不应按登录邮箱唯一性拒绝。
- 内容可正常识别的 PDF/非 PDF/非 PDF 改成 PDF 后缀；单份 10,485,759/10,485,760/10,485,761 字节（分别为上限前、恰好上限、超过上限），10/11 份、已有+新增/先移除后添加；上传中/失败/成功未保存、保存失败/取消/离开、保存成功、读取失败/无附件。
- 同邮箱或同名称并发邀请、编辑与启停并发、重复提交/刷新、邮件受理成功/失败；没有机构/筛选空/读取失败；历史缺资料、时区不可推断/跨日展示、未知机构/文件编号作为 OOD。

**代表性用例。** 实际撰写 25 条代表场景（D1 4、D2 5、D3 5、D4 6、D5 5），全部 **合成、待人工复核**，不称为真实失败。代表表不是完整 64 条数据集；多变体行须先拆原子 case 后计数，其余由测试根据 04 册扩充。现有场景优先级按第 3 节定稿，人工复核用于确认合成前提与预期；拆分变体沿用同一口径，业务受阻或安全风险按 P0；grader 仅为拟采用方式。

## 3. 通过线

**单例判定。** 每个适用预期都满足且无禁止行为才通过；复合验收必须全部子场景通过。环境问题无法判定标无效，需证据与测试确认并重跑；未就绪/跳过标未验证，不记通过。产品读写错误、邮件失败却报成功、取消后数据改变均属有效失败，不能作为环境无效排除。

| 级别 | 定义 | 本模块典型情况 |
| --- | --- | --- |
| P0 | 影响业务进程，或危及平台安全（业务已确认口径） | 开通失败/重复账号、机构资料半保存/附件丢失、越权读写、运营代改凭据、停用后新提交误放/在途误挡、错投凭据、历史归属或审计损坏 |
| P1 | 规则执行有偏差，用户会误解或多走一步，但有明确兜底或绕行，不阻断业务、不涉及安全（本 Eval 定稿） | 结果正确但邮件失败指引不清、可恢复的附件边界校验偏差、筛选空/读取失败说明不清、详情时间时区遗漏但不改变判断 |
| P2 | 呈现与体验细节，不影响用户判断、操作结果及业务状态（本 Eval 定稿） | 非关键提示小差异、辅助反馈不统一但状态与操作可明确获知 |

P1/P2 定义、本文代表场景及 rubric 归类按本版定稿，不回写 PRD；B 类均维持 P0。同 case 按最高风险归类；新增问题的业务影响不明确时由产品仲裁。以下通过线均为建议，待测试、安全及发布负责人确认；研发负责技术可行性与环境，产品只提供业务影响和兜底判断，不代定发布门槛。

| 层级 | 建议门槛 | 依据 |
| --- | --- | --- |
| B1～B6 | 每个关联 case 0 失败，无未验证；任一失败阻断 | 权限、账号、路由和资料错误损失高 |
| D1～D5 的 P0 | 各维度、各必需切片 100% 通过 | 同时覆盖正向业务可用性和安全拒绝 |
| 各维度 P1 | 通过率≥95%；剩余逐条缺陷与兜底，产品说明业务影响与兜底，由测试、安全及发布负责人书面决定 | 有恢复路径的非阻断差错可评审 |
| P2 | 不单设发布率阈值，列出修复计划 | 不影响判断和操作的体验细节 |
| 覆盖和整体 | 23 条 AC 的全部子条件、六状态与新增规则均有映射；必需 case 无未验证；P0 相对上一版无回归；各项同时满足 | 防止省略风险或平均分掩盖失败 |
| 联调切片 | 真实邮件受理/测试收件箱、企业提交二次确认、在途审核/解除监管/M7 消息的 P0 均通过 | 状态表正确不证明真实业务衔接正确 |

维度通过率 = 本轮有效通过原子 case 数÷本轮有效已执行原子 case 数。分角色、机构×账号状态、直链/接口/文件、模拟/真实依赖、优先级单独列分子分母；无效/未验证数量与原因另列。建议无效数超过计划执行数的 5% 时停止本轮放行判断，修复环境后重跑，比例待确认。

并发邀请、启停竞态、附件保存、真实邮件 case 建议固定数据快照与依赖版本重复 3 次，任一次产品失败即记失败；记录操作顺序、提交时点、邮件事实编号、状态前后值，建议重复次数待确认。规则 case 逐条判，不靠置信区间放过；人工与 L3 比例建议报告样本量和 Wilson 95% 区间，置信水平待确认，小样本零失败不能推断风险低。版本比较固定相同 case 集、环境和预期逐例配对，新规则/新增 case 单列；当前没有实测基线、区间、分数或通过结论。

**兜底核对。** 邀请业务提交失败不建机构/不发信、保留输入；账号已建立但邮件未受理则线下告知，不回滚、不重发；编辑或附件保存失败保持原资料；状态已变展示最新状态；文件读取失败可重试。线上 B 类故障建议暂停受影响的邀请/编辑/附件入口或回退版本并调查，不应为止血随意终止所有停用机构的在途业务；具体处置、权限与时限待安全、研发/运维及发布方确认，本篇不执行线上操作。

**失败回流与版本。** 工单、权限/数据告警、线上指标异常及 OOD 探索问题由测试脱敏复现，建议 3 个工作日内完成 case 回流（待确认）。真实失败注明来源编号、前置状态、失败损失、规则提交和复核人，未证实投诉标待核查；B 类补直接接口/文件或并发变体。集合按 `Eval-M5-RG-vX.Y` 管理，当前依据完整提交 `3974bea82116b37d1e79a98975816e9b64461b3c`；PRD 任一分册修改后更新功能/AC/case/消息映射，规则作废的 case 归档留原因，不删除历史。与 LG、M3a、M3b、M4b、M7 联动变更时标受影响切片；风险集与真实流量统计集独立版本化，状态/文件/失败分布漂移时补 OOD，不把合成对抗占比解释为用户分布。
