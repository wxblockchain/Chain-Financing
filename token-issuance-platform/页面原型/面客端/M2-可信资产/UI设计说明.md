# M2 · 可信资产 UI 设计说明

2026-11-04｜existing-system adaptation；本轮为 console 的 delta prototype。基线 `194d78b`，按用户确认的“局部分区自适应三列、通用规则保持统一”修订。业务分类与规则沿用 [M2 可信资产 PRD](../../../PRD/两端共用/M2-可信资产/01-可信资产-PRD.md)，组件规范为 [v1.29](../../_shared/design-system/组件规范.md)。

本轮调整：资产基本信息与回款汇总采用短字段三列变体，其他信息组保持默认两列；交易双方名称、交付地址和确权凭证跨整行。所有分区继续共用标题、上下字段、间距、导航与表格规则，列数根据各自容器宽度响应。

## 2026-11-04 英文优先修订

本轮为 delta prototype（console），按 PRD `ff17875` 与用户“以英文呈现为主”的要求修订，范围为 M2 企业端与管理端；画面清单、路由与业务字段不变。

- **资产价值**：企业资产列表、运营全平台列表、运营企业详情内资产表、监管关联资产列表的金额列改为“资产价值 / Asset value”；详情与摘要仍为“应收账款金额 / Receivable amount”。
- **资产编号进入详情**：四处列表的资产编号改为链接，与同行“查看”打开同一详情（演示未覆盖的资产仍为同一说明提示）；“查看”保留。
- **英文列宽**：按英文表头与状态标签重新分配列宽。1440 px 起企业列表状态标签单行；含债权人的管理端列表在 1280–1440 px 下 “Application in progress” 仍折为两行，名称超宽时继续首尾保留、中间省略。
- **资产摘要**：宽屏时右侧三项状态按内容取宽，英文 “Application in progress”“Confirmation revoked” 在 1280 px 起不再折行；≤ 1100 px 仍上下排列。仅作用于 M2。
- **中英文名称**：交易双方的名称在英文界面以英文名称为主、本地名称弱化在下；中文界面相反。数据值不变。

- 需要实际跨模块跳转时，解压联看包后打开 `页面原型/面客端/M2-可信资产/可信资产.html` 或管理端同路径文件。完整目录无需服务即可双击运行；界面语言与时区随模块路由传递。
- 联看包直接归档仓库的 HTML / CSS / JS 及其已有模块依赖，不加入新的演示外壳。其他模块属于既有依赖，不代表本轮重新设计。
- `_shared/export.py` 仍可生成单模块离线视觉预览；单模块附件不含其他模块页面，不用于验证跨模块跳转。本次以联看包为完整交付。
- 企业、人名、金额、文件、编号均为演示数据；上游内容保留原文，不自动翻译。

## 列表与筛选

四处资产表（企业列表、运营全平台、监管关联资产、运营企业详情内资产）继承已确认实现，本轮未改：

- 撤回上一轮误带入的第 1、3 项字段变更，恢复债务人与回款状态列，不增加资产类型列或筛选。四张表的数据、字段、状态和操作逐项与改动前 `c86d3eb` 核对；确权仍按此前确认仅在详情展示。
- 常用筛选恢复发行状态、回款状态；更多筛选保留债务人、币种、到期范围，运营 / 监管全局列表另有债权人。角色范围不变。
- 更多筛选改为底边对齐的横向控件布局，普通字段 184 px，日期时间范围按自身宽度排列；只有空间不足时换行，不再强制将日期放在下一行。
- 在恢复字段的前提下重新平衡编号、企业名称、金额、到期、两种状态和操作的列宽，避免名称占比过大或英文发行状态挤成三行。金额右对齐，编号完整不换行，债务人 / 债权人名称单行保留首尾、按列宽中间省略；悬停或点击可查看全名，Enter / Space 同样可用，详情保留完整名称。英文申请操作纵向排列并允许换行，窄屏只在表格内横向滚动。
- 使用页码分页。资产查找和审核更需要明确位置、总量及返回位置；下拉刷新适合更新内容，不宜用于更换审核中的记录集合。当前样本为一页，显示真实记录数与页码 1，前后页禁用；未新增资产或分页模拟逻辑。生产分页查询与页大小由正式系统接入。

## 详情视觉

- 标签栏无外框、圆角及组间竖线，底部增加 1 px 贯穿分隔线区分下方内容，当前项通过深主色与加粗表现；保留键盘焦点、点击定位和滚动同步高亮。
- 核心 / 补充信息提升为 20 px / 650 深色模块标题，明确大于 16 px / 600 卡片标题、14 px / 600 内部小节。组标题与卡片外缘、导航起点对齐，组间距 40 px；副标题保留 13 px 辅助色。点击每组首个标签时同时保留组标题可见。
- 字段名在上、内容在下，间隔 4 px、字段上下内边距各 16 px、列间距 32 px。资产基本信息与回款汇总采用 `.cols-3`：字段区 ≥ 900 px 三列、762–899 px 两列、更窄一列；其余分区默认两列 / 一列。名称、交付地址和确权凭证用 `.wide` 跨整行，长值完整换行；不改变字段顺序。M1 保持两列、M5 保持其已确认变体。
- 标的物、发票、付款和回款记录与详情字段区分：表格内缩 24 px、细边框、浅底加粗表头、13 px 紧凑行；详情值保持 14 px。表头、行线和金额对齐表达重复记录关系，表格过宽时仅自身横向滚动；不将只读详情画成另一张列表。
- 摘要金额前增加 24 px 对应币种图标；币种字段采用 18 px 图标 + USD / EUR。图形复用借贷平台已有资产，保留许可证与唯一 mask ID；金额、精度与时间戳不变。
- 核心信息、上游供应商和债务人下游客户的字段、材料、缺失提示与可见范围均保留；补充交易回款仍不计入本笔资产。

## 覆盖与验证

- M2 企业端 7 个、管理端 4 个资产详情：短字段三列、长字段整行及边界响应。
- M3a 的 7 个共享资产引用画面继承同一详情组件；申请详情、路由与数据未改。
- 共享 `.facts` 的首行分隔规则兼容 `.wide`，避免跨行后的普通字段误用无顶线样式；M1 / M5 维持已确认列数，回归其共享字段。
- 列表、筛选、摘要、表格、业务字段及状态沿用原实现，不计为本轮重新设计。

本轮在完整解压的联看包内用 Chromium 核验：M2 29 屏、M3a 53 屏、M3b 74 屏、M1 33 屏、M5 141 屏，中英文 × 320 / 375 / 768 / 1280 / 1440 / 1920 px，共 3960 次共享组件画面检查。核对实际列数、长字段整行、首行及跨行分隔线、上下字段无重叠、无整页横向溢出；M1 默认两列与 M5 已有三列保持对应变体。

另做 16 次断点边界检查（字段容器 761 / 762 / 899 / 900 px）、344 次 M2 分区标签定位 / 焦点 / 高亮检查、10 次企业端申请入口及浏览器返回检查。三处共享渲染消费者的全部资产详情文本与修改前逐项比对一致，字段、数值、文件与缺失说明均保留；无脚本报错或外部请求。两个单模块 HTML 另做 32 次离线布局与导航检查。

内部目视检查了两端 1440 px 英文详情、375 px 英文单列和中文回款汇总三列。自动画面检查不代表逐屏截图评审；其他模块为共享组件回归，不计为本轮重新设计。

未验证 Safari / Firefox、真实接口、分页服务与账户权限。原型不模拟业务计算、筛选结果或生产申请数据。
