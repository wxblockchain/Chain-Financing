# M2 · 可信资产 UI 设计说明

2026-11-03｜existing-system adaptation；本轮为 console 的 delta prototype。基线 `0e69fa4`（含同期 M1 账户视觉更新），按用户最新四点反馈修订。业务分类与规则沿用 [M2 可信资产 PRD](../../../PRD/两端共用/M2-可信资产/01-可信资产-PRD.md)，组件规范为 [v1.25](../../_shared/design-system/组件规范.md)。

本轮新增：列表交易双方名称按列宽保留首尾、中间省略，并提供全名查看；入口统一“申请发行”，用户可见“上游资产编号”统一改为“资产编号 / Asset ID”；tab 栏下方增加贯穿分隔线。详情字段继续采用上下结构。

## 查看方式

- [企业端](可信资产.html) 13 屏、[管理端](../../管理端/M2-可信资产/可信资产.html) 16 屏；右下角目录保留所有原画面。
- 需要实际跨模块跳转时，解压联看包后打开 `页面原型/面客端/M2-可信资产/可信资产.html` 或管理端同路径文件。完整目录无需服务即可双击运行；界面语言与时区随模块路由传递。
- 联看包直接归档仓库的 HTML / CSS / JS 及其已有模块依赖，不加入新的演示外壳。其他模块属于既有依赖，不代表本轮重新设计。
- `_shared/export.py` 仍可生成单模块离线视觉预览；单模块附件不含其他模块页面，不用于验证跨模块跳转。本次以联看包为完整交付。
- 企业、人名、金额、文件、编号均为演示数据；上游内容保留原文，不自动翻译。

## 列表与筛选

四处资产表（企业列表、运营全平台、监管关联资产、运营企业详情内资产）统一处理：

- 撤回上一轮误带入的第 1、3 项字段变更，恢复债务人与回款状态列，不增加资产类型列或筛选。四张表的数据、字段、状态和操作逐项与改动前 `c86d3eb` 核对；确权仍按此前确认仅在详情展示。
- 常用筛选恢复发行状态、回款状态；更多筛选保留债务人、币种、到期范围，运营 / 监管全局列表另有债权人。角色范围不变。
- 更多筛选改为底边对齐的横向控件布局，普通字段 184 px，日期时间范围按自身宽度排列；只有空间不足时换行，不再强制将日期放在下一行。
- 在恢复字段的前提下重新平衡编号、企业名称、金额、到期、两种状态和操作的列宽，避免名称占比过大或英文发行状态挤成三行。金额右对齐，编号完整不换行，债务人 / 债权人名称单行保留首尾、按列宽中间省略；悬停或点击可查看全名，Enter / Space 同样可用，详情保留完整名称。英文申请操作纵向排列并允许换行，窄屏只在表格内横向滚动。
- 使用页码分页。资产查找和审核更需要明确位置、总量及返回位置；下拉刷新适合更新内容，不宜用于更换审核中的记录集合。当前样本为一页，显示真实记录数与页码 1，前后页禁用；未新增资产或分页模拟逻辑。生产分页查询与页大小由正式系统接入。

## 详情视觉

- 标签栏无外框、圆角及组间竖线，底部增加 1 px 贯穿分隔线区分下方内容，当前项通过深主色与加粗表现；保留键盘焦点、点击定位和滚动同步高亮。
- 核心 / 补充信息提升为 20 px / 650 深色模块标题，明确大于 16 px / 600 卡片标题、14 px / 600 内部小节。组标题与卡片外缘、导航起点对齐，组间距 40 px；副标题保留 13 px 辅助色。点击每组首个标签时同时保留组标题可见。
- 关联记录与共享资产详情统一为标签在上、内容在下，间隔 4 px；字段行上下留 16 px 与轻分隔线。容器达到 762 px 时为两列，其余一列，不再扩为三列。其他模块通用只读字段与弹窗保持原样。
- 标的物、发票、付款和回款记录与详情字段区分：表格内缩 24 px、细边框、浅底加粗表头、13 px 紧凑行；详情值保持 14 px。表头、行线和金额对齐表达重复记录关系，表格过宽时仅自身横向滚动；不将只读详情画成另一张列表。
- 摘要金额前增加 24 px 对应币种图标；币种字段采用 18 px 图标 + USD / EUR。图形复用借贷平台已有资产，保留许可证与唯一 mask ID；金额、精度与时间戳不变。
- 核心信息、上游供应商和债务人下游客户的字段、材料、缺失提示与可见范围均保留；补充交易回款仍不计入本笔资产。

## 覆盖与验证

- M2 四张资产列表：债务人 / 债权人名称中间省略、全名查看、申请文案与英文操作排版。
- 共享详情分区导航：tab 栏底部分隔线，继承标题、上下字段与定位行为。
- M2 / M3a / M3b / M4a / M4b / M5：仅将已有资产标识文案改为“资产编号 / Asset ID”，M3a 同步已有申请入口文案；不改编号、业务数据或路由。其他模块继承原实现，不计为本轮重新设计。

本轮 Chromium 在完整解压的联看包内核验：M2 29 屏、M3a 53 屏、M3b 74 屏，中英文 × 320 / 375 / 768 / 1280 / 1440 / 1920 px，共 1872 次画面检查；M4a 59 屏、M4b 66 屏、M5 147 屏按双语 × 375 / 1440 px 另做 1088 次文案与布局检查。合计 2960 次检查，无旧资产标识 / 发行文案、整页横向溢出、名称或操作文字溢出、脚本错误及外部请求。

48 组资产列表检查核对名称首尾内容、完整无障碍名称、点击与 Enter 查看全名；344 次分区标签点击核对底部分隔线、定位遮挡、焦点、高亮及路由不变；10 次跨模块入口核对三笔对应申请、两处申请发行入口、语言、时区与浏览器返回。两端单模块 HTML 另测 4 组双语布局、实际省略及 Space 查看全名。联看包内运行文件逐一与源码核对一致。

内部目视检查了两端代表性列表、中英文 1440 px、768 px 名称省略及详情分隔线；自动画面检查不代表逐屏截图评审。未重新设计 M4 / M5 的业务布局或扩展其范围。

未验证 Safari / Firefox、真实接口、分页服务与账户权限。原型不模拟业务计算、筛选结果或生产申请数据。
