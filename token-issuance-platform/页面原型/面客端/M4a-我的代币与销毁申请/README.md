# M4a · 我的代币与销毁申请

企业查看已铸造代币，在平台校验资格后，由铸造到账地址的钱包一次签署并直接发送销毁交易，继续查看链上结果及原监管机构的解除监管进度。依据 [PRD](../../../PRD/面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md)（`4590917`）；规则、校验与异常分支以 PRD 为准。画面中的企业、机构、地址、编号、金额均为演示数据。

本轮为既有企业端控制台适配（existing-system adaptation），只更新本目录原型及说明。共享 token、壳层、组件、菜单、消息数据和其他模块均未修改。

## 打开方式

- 仓库联看：完整同步 `页面原型/` 后双击 [index.html](../../index.html) 选择“已认证企业”，或直接双击本目录 [我的代币与销毁申请.html](我的代币与销毁申请.html)。
- 单模块附件：在 `页面原型/` 下执行 `python3 _shared/export.py --source 面客端/M4a-我的代币与销毁申请/我的代币与销毁申请.html --output <仓库外路径>.html`；生成件可双击离线打开，跨模块入口显示范围提示。
- 右下角「画面目录 · 演示数据」默认关闭，提供全部画面及「主流程下一屏」。等待钱包或链上结果的画面用该目录预览后续，不连接真实钱包、不广播交易、不模拟自动成功。

## 主流程

- 销毁：M01 我的代币 → M05 代币详情（DEMO-TOKEN-021）→ M21 确认关键信息 → M24 钱包交易签名 → M29 钱包广播 → M30 已广播 → M39 / M41 销毁中 → M43 成功 → M44 待解除监管 → M45 已解除监管。列表「申请销毁」进入 M22。
- 原失败记录重新发起：M40（BA-DEMO-0024、DEMO-TOKEN-021）→ M52 确认 → M53 交易签名 → M54 已广播 → M56 新申请销毁中（BA-DEMO-0031）；原失败记录保留。
- DEMO-TOKEN-026 失败后重新发起：M42（BA-DEMO-0021）→ M74 确认原代币及 32,000.00 cou → M75 交易签名 → M76 已广播 → M77 新申请销毁中（BA-DEMO-0032）⇄ M78 同代币详情；其中原失败编号打开 M81，只读保留原失败并引导新申请。不会跳入 DEMO-TOKEN-021 的确认画面。
- 失败且仍在质押地址：M72 原失败记录（BA-DEMO-0021）⇄ M73 代币详情；保留融资中事实，不提供再次销毁入口。
- 非平台入口：画面目录 M79（BA-DEMO-0033）⇄ M80 代币详情；明确链上销毁已成功、来源为非平台入口，等待原监管机构解除监管，不能再次销毁。这是独立的结果变体，不与平台入口主流程串接；历史失败编号打开 M82 并引导该笔已销毁记录。
- 未认证：M58 / M59 → M71 前往资产可信平台确认。

平台入口先核对原发行企业、到期、结清、下游融资及链上完整持有 / 无质押；明确不满足或必要结果未知时，详情说明原因且不显示销毁按钮。连接钱包、切换地址及网络不签名；确认销毁时只进行一次交易签名，企业钱包直接广播并承担 gas。平台不签名、不代发、不审核、不重试。

广播成功才展示申请编号及销毁中；取消、拒签、广播失败和结果未知不显示销毁成功。详情中的“销毁交易记录”保留发送地址、提交时间、来源及链上结果，移除业务签名值和审核结果。解除监管记录及企业可见范围沿用 PRD。

演示代币仍为 001、021–026，沿用原申请编号 BA-0018 / 0019 / 0021 / 0024 / 0030 / 0031；另有新交易 BA-0032 和非平台入口 BA-0033。其他模块尚未同步这些新增变体，不能据此认定跨端一致。已销毁代币的持有地址为空。DEMO-TOKEN-001 的资产、发行申请编号仍进入 M2 / M3a 对应记录；无匹配画面的编号只展示。

- 研发须验证现有合约是否支持铸造到账地址一笔交易直接销毁；若需先授权再销毁或由平台提交，与当前决定冲突。原型表达目标交互，不代表合约能力已实现。
