# 代币发行企业申请页面原型

2026-10-30 初版｜2026-11-02 入库并接入仓库联看｜existing-system adaptation｜console｜WS-509

按用户“直接输出页面原型”跳过中间阶段确认。基线为本 issue 2026-10-30 的 M3a PRD 与验收附件，以及 `cly-v6.0.0` / `19913bc` 的平台组件规范 v1.8、M1 与 M2 前序页面。规则、校验与异常分支以 PRD 为准。

## 打开与主流程

- **仓库联看**：完整同步 `页面原型/` 后双击 [`index.html`](../../index.html) 选择“已认证企业”，侧栏“代币发行”进入申请列表；也可直接双击本目录 `代币发行.html`。M1、M2、M4a 的“代币发行”菜单，以及 M2 可信资产列表 / 资产详情的“发起发行”，都进入本模块（后者落到已带入 `RA-DEMO-0128` 的选择资产画面）。本模块的可信资产、我的代币、企业账户菜单和退出登录进入对应模块。路由见 [`route.js`](route.js)。
- **单模块附件**：由 `export.py` 生成，可双击离线打开，无 CDN、网络字体、远程图片或接口依赖；可信资产菜单与退出登录落到本文件的衔接画面，其他模块入口提示范围。

默认打开申请列表；右下角“画面目录 · 演示数据”默认关闭，可到达全部画面。

主流程：申请列表 → 发起发行申请 → 选择资产 → 选择监管机构 → 选择接收账户 → 确认并提交 → 提交中 → 提交成功 → 申请详情。选择行后呈现独立的已选画面，再点击下一步；提交前可返回。提交中是静态等待画面，通过画面目录的“主流程下一屏”进入成功画面，不用计时器模拟提交。

当前为静态画面规格。账户选择的三个入口均能进入相应的确认和结果画面；没有账户数据持久化、业务校验、状态计算或真实审核 / 铸造操作。企业、机构、账户、金额、地址、意见及编号全部为演示数据。

## 业务与视觉不变量

- 沿用 v1.8 壳层、菜单、系统字体、宽屏布局、控件、地址、金额与详情分区导航。共享取值入口为 `_shared/tokens.css` 和 `components.css`；主色 `#1D4ED8`、背景 `#F7F8FB`、控件 44 / 36 px、侧栏 238 px、顶栏 68 px、内容左右各 24 px。
- 机构只展示名称，接收账户只选用已登记账户；两者均不预选。当前登录地址与顺延后的普通账户分开呈现，已提交的接收地址保持不变。M1 的 `6279b3d` 已补齐此规则，采用该最新口径。
- 数量两位小数；币种、数量、到期日只读；确认前完整披露不可撤回和修改、任一级驳回即终止、同资产不能再次申请，以及线下签署协议。
- 企业的铸造中、失败及重试统一呈现“发行处理中”，不展示内部失败、次数或重试记录。监管与融资分开表述；一审通过意见和具体运营账号不向企业展示。
- 审核进度按提交、监管一审、运营二审、铸造排列；驳回意见保留原文，切换语言不翻译。铸造成功后才展示结果及监管开始时间。
- 本轮只扩展共享组件与详情导航的显式接入标记，未改写 M1 / M2 页面。M2 新增的演示资产记录用于本原型的小数数量示例，不改变既有页面数据。

## 文件与交接边界

源码为本目录 `代币发行.html` 与 `route.js`，引用 `_shared/`；新增组件见[组件规范 §11](../../_shared/design-system/组件规范.md#11-代币发行申请m3a)。附件由 `export.py` 内联生成，生成件不放回仓库。

协议查看 / 下载呈现入口与失败画面，未附真实协议文件；我的代币、消息中心、企业账户维护与重新登录由各自模块承接，本文件不重复构建。可信资产衔接只提供本模块所需示例，没有替代完整 M2 原型；消息到达本模块后的查看落点采用同一申请详情。

本期不做：申请撤回、修改、重新提交、草稿；企业编辑发行信息；非美元资产发起；在线签署或企业上传协议；申请内新增 / 编辑账户和手输地址；监管 / 运营审核、选合约、铸造和重试；融资、销毁、解除监管、下游代币详情；新建登录、首页、工作台和消息中心；生产规则与接口实现。
