# 代币发行企业申请页面原型

2026-10-30 初版｜2026-11-02 入库并接入仓库联看｜2026-11-04 按 PRD `024b397` 改为单笔三步申请、业务签名、英文优先｜existing-system adaptation｜console｜WS-509

规则、校验与异常分支以 [M3a PRD](../../../PRD/面客端/M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md) 为准。画面中的企业、机构、账户、金额、地址、意见及编号全部为演示数据。

## 2026-11-04 修订

本轮为 delta prototype（console），依据 PRD `024b397` 与用户反馈“列表增加操作列；选择列表首列可选、点击即选中；资产编号可看详情；减少步骤；提交前签名；页面以英文为主”。

- **三步申请**：选择资产 → 填写申请信息（监管机构 + 接收账户同一步）→ 核对并签名提交。原“选择监管机构”“选择接收账户”两步合并，确认单独保留（提交后不可撤回，签名内容即核对内容）。
- **单选表**：资产、监管机构、接收账户都是单选，首列为单选标识，点击整行即选中，已选行浅主色底。按 PRD 单笔裁定，首列用单选（radio）而不是复选框，避免暗示可多选。三张表不再有操作列；未选定时“下一步”不可用，旁边说明原因。
- **资产编号看详情不中断申请**：选择表、上方已选资产条和核对页中的资产编号打开资产详情弹窗（内容复用 M2 字段渲染），关闭或“返回申请”回到原步骤，已选内容保留。
- **资产价值**：选择、核对、列表、详情统一为“资产价值 / Asset value”（金额 + 币种）；不再展示币种单列和预计发行数量。核对页说明代币数量按资产价值 1:1、单位为运营所选合约的代币符号、以铸造结果为准。铸造结果的代币数量以合约代币符号为单位（演示为 cou）。
- **业务签名**：核对页下方展示签名地址（当前登录地址），主按钮为“签名并提交”。点击后弹出钱包签名等待框，只能取消；签名取消 / 被拒、钱包地址不是登录地址、网络不是 Ethereum、签名未通过核对，各有一个结果弹窗，关闭后回到核对页，信息保留，可重新签名。签名通过后进入提交中、提交成功。
- **申请列表**：增加“操作”列，“查看”与申请编号进入同一详情；金额列改为资产价值。
- **英文优先**：默认语言为 English，列宽、按钮与提示按英文长度排布并以英文截图核对；中文界面同等可用。演示编号对齐其他模块：`RA-DEMO-0102` 的申请为 `IA-DEMO-0019`（M2 / M4a 已用），`RA-DEMO-0131` 为 `IA-DEMO-0031`（M3b 已用）；D6 铸造成功的接收地址、合约名称与地址对齐 M4a 的 `DEMO-TOKEN-001`，“查看代币”在仓库联看中进入该代币详情。
- 顺带修正：监管协议文件列表改用共享 `.file-list`（旧 `.files` 类在共享层已不存在，列表曾无样式）；协议失败弹窗遮罩类名改为 `.modal-mask`。

## 2026-11-04 详情列数

按用户“详情展示三列还是两列综合考虑”，按组件规范 §4.16 逐分区选择，不统一列数：

| 分区 | 布局 | 理由 |
| --- | --- | --- |
| 申请详情 · 申请信息（D1–D12） | `.cols-3`，3 行 × 3 项 | 9 项都是短值，原两区 2 列竖向过长、宽屏留白多。按行组织为：申请编号 / 提交时间 / 监管机构；资产编号 / 债务人 / 资产价值；到期日 / 接收账户 / 区块链网络。 |
| 申请详情 · 铸造结果（D6） | `.cols-3`，3 行 × 3 项 | 原 10 项。合约标准与网络合并为“网络 / 标准”（与 M4a 代币详情同写法），得到结果（代币数量 / 到期日 / 铸造时间）、归属与监管（接收账户 / 监管机构 / 监管开始时间）、合约（名称 / 地址 / 网络与标准）三行。 |
| 核对并签名（F1–F3、E1–E7） | 默认两列 | 资产信息、申请信息各 4 项，两两成对；三列会留下单独一项，且地址 + 复制需要宽度。核对页以逐项核对为主，两列更易对照。 |
| 资产详情弹窗摘要 | `.cols-3` | 6 项短值状态，沿用 M2 资产基本信息的三列。弹窗内资产详情沿用 M2 各分区既定列数。 |
| 签名弹窗 | `.single` | 弹窗窄，签名地址与网络上下排列。 |

容器 ≥ 900 px 三列，762–899 px 两列，更窄一列（共享断点）；接收账户的备注名与地址在列内可换行。已在 900 / 1280 / 1440 / 1920 px 中英文核对。

## 2026-11-04 审核进度并入概览

审核进度是整笔申请的当前位置，属于总览而不是详情分区。申请详情（D1–D8、D11、D12）改为：页头 → 申请概览卡（状态标签 + 当前说明 + 提交 / 监管一审 / 运营二审 / 铸造四段进度）→ 分区导航 → 驳回意见、申请信息、监管协议、铸造结果。概览卡不进入分区导航，导航只列下方分区，与组件规范 §4.16“摘要在导航之前”的阅读顺序一致。

## 2026-11-04 步骤底栏吸底

“填写申请信息”和“核对并签名提交”两步内容较长，操作按钮原来要滚到卡片底部才看得到。现在三步的底栏（上一步 / 取消 / 下一步或签名并提交，以及未满足条件的提示）吸附在窗口底部；卡片下方还有内容时底栏带浅阴影，滚到底后回到卡片底部原位。底栏吸附时，评审用的“画面目录”入口自动上移，不遮挡主按钮。列表、详情和结果页没有底栏，不受影响。

## 2026-11-04 业务签名记录

按 PRD `631c483`（C-ISSUE-06“业务签名”、AC-M3A-40），申请详情在“申请信息”之后新增“业务签名”分区，所有状态（D1–D8、D11、D12）都可查看，分区标签同步出现：

- 四项字段：签名地址、签名时间、签名内容哈希、签名值。地址、哈希、签名值都缩写为前 6 + 后 4 位，复制得到完整值；默认两列（4 项两两成对，且三项带复制按钮需要宽度）。
- 卡片副标题说明“提交时对申请信息的签名，不可修改”。不展示签名原文，也没有链上交易哈希（本期不上链）。
- 新增 D13“签名记录读取失败”：只在该分区内显示读取失败与重试，申请其他信息照常展示。
- 演示的哈希与签名值按申请编号生成，仅用于展示长度与缩写效果。

画面数由 61 变为 62。

## 打开与主流程

- **仓库联看**：完整同步 `页面原型/` 后双击 [`index.html`](../../index.html) 选择“已认证企业”，侧栏“代币发行”进入申请列表；也可直接双击本目录 `代币发行.html`。M2 可信资产列表 / 资产详情的“申请发行”进入已带入 `RA-DEMO-0128` 的选择资产画面；M2 资产详情中的关联申请进入对应申请详情。路由见 [`route.js`](route.js)。
- **单模块附件**：由 `export.py` 生成，可双击离线打开；可信资产菜单与退出登录落到本文件的衔接画面，其他模块入口提示范围。

主流程：申请列表 → 申请发行 → A1 选择资产 → A2 已选 → I1 填写申请信息 → I2 已选机构 → I4 均已选择 → F1 核对 → G1 钱包签名 → F4 提交中 → F5 提交成功 → D1 申请详情。等待类画面（G1、F4）通过画面目录“主流程下一屏”前进，不用计时器模拟。

三张选择表点击任一行（或其单选标识）即在本表内改选：取消原选中、选中当前行，对应 PRD C-ISSUE-01～03“选另一项即替换原选择”。所需的表都选中后“下一步”可用、提示消失；接收账户选登录地址或原登录地址顺延的普通账户时，下一步进入对应的核对画面。点资产编号、复制地址不改变选中。后续步骤仍以 `RA-DEMO-0128` 与 `Demo Regulator C Ltd.` 作为演示数据，不随所选行变化。

## 业务与视觉不变量

- 一笔申请一笔资产、一次签名；签名地址只用登录地址，签名不改变登录身份。机构只展示名称；接收账户只选已登记账户，均不预选。
- 申请阶段只展示资产价值，不展示预计数量或 cou；铸造成功后才展示代币数量（两位小数，合约代币符号）。
- 核对页完整披露：1:1 与以铸造结果为准、不可撤回与驳回即终止、代币进入所选地址、线下签署监管协议、提交前须签名。
- 企业的铸造中、失败及重试统一呈现“发行处理中”；监管与融资分开表述；一审通过意见和具体运营账号不向企业展示；驳回意见保留原文，不随语言翻译。
- 原型不实现签名、核对、状态计算或校验；“下一步”可用与否、各失败结果都是静态画面。

## 实际验证（2026-11-04，基于 `cly-v6.0.0` / `024b397`）

- Chromium：本模块 61 屏，以及企业端 M1 / M2 / M4a、管理端 M2 / M3b 和 M3a 导出件，每屏 × English / 中文 × 1280 / 1440 / 1920，无脚本报错或整页横向溢出。
- 英文界面逐屏扫描可见文字，除 M2 资产详情中企业的中文正式名称（按 M2 规则作为次要名称展示）外，无未翻译中文。
- 鼠标实测：M2“申请发行”→ A2；资产编号打开详情弹窗并关闭回到 A2；A2 → I1 → I2 → I4 → F1 → G1，取消签名回到 F1；D6“查看代币”进入 M4a `DEMO-TOKEN-001`；M2 `RA-DEMO-0102` 的关联申请进入 D6（`IA-DEMO-0019`）。
- 内部视觉检查覆盖英文 1280 / 1440 的列表、选择资产、资产详情弹窗、填写申请信息、核对、签名弹窗、提交成功和申请详情，以及中文填写申请信息；截图不作为交付附件。

未验证 Safari / Firefox、1280 px 以下及完整无障碍审计。原型不证明后端、签名核对、权限校验、消息投递或链上能力已实现。

## 文件与交接边界

源码为本目录 `代币发行.html` 与 `route.js`，引用 `_shared/`；组件见[组件规范 §11](../../_shared/design-system/组件规范.md#11-代币发行申请m3a)。附件由 `export.py` 生成，不放回仓库。

已知跨模块差异（本轮未改其他模块）：M4a 的 `DEMO-TOKEN-001` 监管机构演示名为 “Demo Supervision C”，代币数量仍写 USD；M3b 申请信息仍含币种、预计发行数量及“上游资产编号 / 应收账款金额”。PRD 已列为相应模块的同步项。

本期不做：申请撤回、修改、重新提交、草稿；批量申请；企业编辑发行信息；非美元资产发起；在线签署或企业上传协议；申请内新增 / 编辑账户和手输地址；监管 / 运营审核、选合约、铸造和重试；签名上链；融资、销毁、解除监管、下游代币详情；生产规则与接口实现。
