# M1 · 企业登录与企业账户

企业端钱包登录、游客引导、企业与用户信息，以及唯一当前登录地址的只读展示。本次为 existing-system adaptation（console）既有原型修订，依据 `bebee03`（2026-11-06）的 M1 PRD 四册：[功能](../../../PRD/面客端/M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md)、[流程](../../../PRD/面客端/M1-企业登录与企业账户/02-企业登录与企业账户-流程图与状态机.md)、[通知](../../../PRD/面客端/M1-企业登录与企业账户/03-企业登录与企业账户-消息通知.md)、[验收](../../../PRD/面客端/M1-企业登录与企业账户/04-企业登录与企业账户-验收.md)。规则、校验与异常分支以 PRD 为准，数据均为演示数据。

## 打开方式

- 仓库联看：完整同步 `页面原型/` 后双击 [`index.html`](../../index.html) 选择企业端身份，或直接双击 [`企业登录与企业账户.html`](企业登录与企业账户.html)。侧栏与账号菜单可跨模块跳转，语言、时区与身份随之传递。
- 单模块附件：在 `页面原型/` 下执行 `python3 _shared/export.py --source 面客端/M1-企业登录与企业账户/企业登录与企业账户.html --output <仓库外路径>.html`，离线双击打开；跨模块入口显示范围提示。
- 右下角「画面目录 · 演示数据」默认关闭，列出全部画面并提供「主流程下一屏」。等待类画面不自动推进。

## 主流程

登录：L1 → L3 → L4 → S1 → P1。L4、S1 等等待画面使用目录中的「主流程下一屏」推进，不自动建立登录；S1 仍为未登录，没有账户或消息入口。P1 后从侧栏查看企业账户和用户信息，通过账户菜单退出。游客注册与未认证企业认证均先经过 G2 确认，取消 / Esc 返回原处。

企业账户：A1 当前地址；S3 旧地址登录结束，A15 另画新地址重新登录后的唯一账户，侧栏在 A15 / P11 / U10 内保持新的地址；A3 / A5 读取或来源异常时无有效账户数据；A4 普通未认证受限，A6 无企业归属受限。无企业归属的 P3 / P8 / U7 / A6 不显示消息入口，G2 取消后也保留无企业归属身份。

企业归属 A→B：目录 P9 展示 B 的资料，侧栏仅在 P9 / U9 / A16 这组三屏内跳转，消息预览为空且不链接到 A 的消息列表。企业 B 与新地址变体仅覆盖 M1，其他模块入口显示现有范围提示；完整跨模块联看继续使用企业 A 的原地址主线。A→无归属：P8 → 侧栏 U7 / A6，保留企业用户登录，移除原企业内容和消息入口。以上仅为静态结果画面，不模拟缓存清理、在途操作或迟到响应。

## 本轮覆盖与限制

覆盖登录建立前后的身份差异、代表性签名失败、锁定 / 禁用 / 换址后的未登录结果、资料读取中 / 空 / 失败、唯一账户及其异常、企业归属变更后的界面。通知正文在共享 `inbox.js` 与最新 NT-C09 中英文一致；不添加离线触发或计时演示。

本期不做：真实钱包连接与验签、接口与鉴权、60 秒重新调取、消息产生 / 去重、旧数据清理与迟到响应拦截；不实现注册、资料修改、多账户管理或其他模块业务流程。源层继续引用 `_shared/tokens.css`、`components.css`、`frame.js`；单文件由 `export.py` 生成，不手改内联件。资料保留字段名在上、值在下的两列布局，沿用组件规范 v1.32（`--accent` #1D4ED8、`--bg` #F7F8FB、控件 44 px、侧栏 238 px、卡片内边距 24 px），未改视觉 token 或组件规范。

## 实际核验

Chromium：源码与离线单文件各 41 屏 × 中英文 × 1280 / 1440 / 1920 px，共 492 个布局组合，无整页横向溢出、壳层重叠或卡片裁切；画面目录逐项点击可达。实测登录主链、退出、无企业归属受限页与 G2 取消 / Esc、企业 B 内导航和消息空预览、新地址三个页面不恢复旧地址、首次登录失败与登录期间调取失败的身份差异。另回归 M2 企业、M3b 运营、M4b 监管、M7 未认证企业的消息入口及预览。代表画面已做视觉检查；JavaScript 语法与本地跳转目标检查通过，无远程资源请求或脚本错误。

未验证 Safari / Firefox、移动端及真实业务服务；真实钱包、上游、权限、通知及同步机制均未实现或验证，不将静态画面视为业务验收通过。
