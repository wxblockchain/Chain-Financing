# M2 · 可信资产与企业（管理端）

运营只读核对全平台资产、企业与企业数币账户，监管机构只读查看本机构关联资产。企业端画面见 [企业端 M2](../../面客端/M2-可信资产/README.md)。依据 [PRD](../../../PRD/两端共用/M2-可信资产/01-可信资产-PRD.md)（2026-11-06，`9c13023`）；**规则、校验与异常分支以 PRD 为准**。画面中的企业、机构、地址、编号、金额均为演示数据。本轮为既有系统视觉深化（existing-system adaptation / console），以英文阅读为主，保留 PRD `9c13023` 的模块边界与全部既有画面。

## 打开方式

- 仓库联看：完整同步 `页面原型/` 后双击 [`index.html`](../../index.html) 选择“运营”或“监管机构”，或直接双击 [`可信资产.html`](可信资产.html)。侧栏与账号菜单可跨模块跳转，语言、时区与身份随之传递。
- 单模块附件：在 `页面原型/` 下执行 `python3 _shared/export.py --source 管理端/M2-可信资产/可信资产.html --output <仓库外路径>.html`，离线双击打开；跨模块入口显示范围提示。
- 右下角「画面目录 · 演示数据」默认关闭，列出全部画面并提供「主流程下一屏」。

## 主流程

- 运营：O1 资产列表 → O4 资产详情（发行申请中，关联申请当前结果“处理中”）；点击申请编号 IA-DEMO-0031 查看对应申请。O6 已发行，点击代币编号 DEMO-TOKEN-001 进入这枚代币的详情。运营只读查看已关联监管机构，不在 M2 分配机构或处理申请。
- 运营 · 企业：E1 企业列表 → E4 企业详情（企业信息、企业用户、数币账户、资产）；E5 为登录地址变更后的数币账户（只展示新的当前登录地址，旧地址不保留为其他账户）。
- 监管：R1 关联资产列表 → R3 资产详情 → 点击申请编号查看本机构已关联申请。范围依据发行模块返回的机构关联结果，不描述为企业选择机构；没有审核、驳回或申请处理操作。R6 本机构已停用时关联资产仍可查看。
- O7 / R5 改为回款状态暂时无法确认的画面（`o-unknown` / `r-unknown`），保留 RA-DEMO-0143 的资产信息与三个资产状态；关联申请只显示“处理中”，不再按发行模块内部阶段命名或展示。
- 运营预警：O1 的 RA-DEMO-0128 / 0131 标记“金额待核对”，点击编号或“查看”分别到 O8 / O4；E4 / E5 的企业内资产列表也显示标记并可进入相同详情。详情并列展示应收金额、累计已回款、余额、结清状态，并说明核对上游、不影响申请。复用静态画面，不实现预警检测，不新增消息通知。
- 身份对照：RA-DEMO-0131 在企业 D3、运营 O4、监管 R3 / R6 均为应收 82,400.00 USD、已回款 82,400.00 USD、余额 0.00 USD，上游仍未结清；仅运营显示预警。RA-DEMO-0128 的企业 D1 仍可申请发行，运营 O8 只读。
- 双名称：资产列表债权人 / 债务人、企业列表分别展示上游名称及存在的英文名称；详情拆成两个字段。语言不切换名称值或顺序，也不翻译国家 / 地区、地址及其他上游内容。英文名称缺失的企业仍只展示已提供的名称。

数币账户字段沿用 M1：账户标识“登录地址”、区块链网络 Ethereum、当前数币地址（缩写、完整悬停和复制）。只读展示唯一地址，不展示备注名、来源、创建/更新时间或验证状态。

## 宽屏列间距修订（2026-11-09）

宽屏余量按字段角色分配到编号、资产价值、到期、回款、发行及企业操作列，名称仅承接部分增量；只读操作列仍保持 80 px。修复企业资产、运营全平台、运营企业详情内资产、机构关联资产四处列表的同类大空白。1920 px 下企业列表债务人列约 768 → 364 px，运营双名称列各约 428 → 258 px。

本轮仅修改上述列表的共享列宽规则及相关规范（existing-system adaptation / console）。企业列表、详情明细与其他画面继承并核查，保留金额紧凑排布；字段、名称原值、状态、分页与跳转未改。

Chromium 中英文 × 375 / 768 / 1280 / 1440 / 1920 / 2560 px，两端全部 37 屏回归；无整页横向溢出或单元格裁切，22 个已有资产编号入口核验通过。窄表继续表内滚动、右侧操作固定；长名称可核对完整值。未测 Safari / Firefox、触屏及真实接口权限。

## UI 深化（2026-11-06）

- 资产列表以编号、数值、时间、状态和操作的阅读空间为基础分配列宽，名称列分配余量；表格实际宽度 ≥1100 px 时为长英文状态留足空间，窄表允许按词换行。首末列与卡片头对齐，资产价值仍右对齐，分页与筛选规则继承。
- 两个名称按上游原值与固定顺序展示，原名 13 px、英文名称 12 px；保留各字段的完整悬停、键盘及点按核对。不会根据界面语言替换名称。
- 资产详情的债权人与债务人按实际详情容器 ≥900 px 并排，其余宽度纵向排列；长名称在各自分区完整换行，国家 / 地区与登记标识成对。资产基本信息、回款汇总沿用自适应三列，其他分区沿用各自布局，导航样式不变。
- 管理端企业列表使用专门的列宽变体；运营现有金额预警改为图标加文字，与业务状态底色标签区分。预警仍为非阻断，企业、监管不显示。
- M2 资产、企业列表在窄屏时仅表内横向滚动，操作列固定在右；滚动区可由键盘聚焦。不新增页面、状态、查询、分页、校验或处理逻辑。

组件来源：`_shared/tokens.css`、`components.css`、`asset-detail.js`，详见组件规范 **v1.65 §4.14**。本轮没有更换品牌、色彩或字体栈；共享资产详情的 M3a 引用继承双方对照组件，其业务页面与流程未改。
