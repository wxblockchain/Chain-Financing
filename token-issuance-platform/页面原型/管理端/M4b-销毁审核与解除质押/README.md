# M4b · 销毁记录、解除资产托管与代币台账

2026-11-09 · existing-system adaptation / console · 中文与 English。业务依据 M4b PRD `eba411d`（`cly-v6.0.0`）；展示结构对齐 M3b 发行审核（顶部紧凑进度、底部操作进度、分步弹窗）和 M4a 我的代币（页头、台账列、代币详情分区）。操作进度与顶部进度按 PRD `49e8ff5` 5.1 组织。**规则、校验与异常分支以 PRD 为准**。企业、机构、地址、编号、金额、文件和时间均为演示数据。

## 本轮改版

按用户要求“根据 M3b 原型和最新 PRD 优化设计，增加操作进度、优化顶部进度条”，在已确认范围内直接重建本模块，75 屏：

- **业务口径**：
  - 运营只读查看销毁记录，没有审核、驳回或重试。
  - 资产托管机构办理解除资产托管；解除说明和 1–10 份解除托管通知文件均为必填。
  - 法律服务机构、审计机构只读，没有解除事项。
  - 运营可调整未销毁、且没有销毁中申请的代币单位价值；调价记录仅运营可见。
  - 非平台入口的链上销毁按“未经过平台入口校验”展示。
- **顶部进度**：销毁记录详情、解除托管详情页头下方改为 M4a / M3b 的四阶段紧凑进度：资格校验 / 钱包提交 / 代币销毁 / 解除托管。每段显示结果、来源或机构和时间。
- **操作进度**：两类详情底部新增 M3b 式操作进度时间线，按时间记录企业钱包提交或平台补建、链上确认成功或失败、解除资产托管；每条有动作、结果、角色和账号或地址，以及带时区的时间。按用户 11-09 意见，时间线不再附“交易来源”“后续”说明，只保留失败说明（仅运营）和解除说明。
- **分步弹窗**：
  - 解除资产托管：两步，填写说明与文件 → 核对并提交。
  - 调整单位价值：三步，填写 → 核对 → 链上更新。链上更新复用 M3b 的进度列表，展示交易哈希、等待、失败与成功。
  - 顶部步骤标签与 M3b 的“通过并铸造”一致。
- **台账**：列表改为 M4a 我的代币的 11 列（加发行人），资产、合约、融资、托管等信息只在详情展示。已销毁代币的持有地址为空。代币详情分为代币发行信息、持有信息、发行关联业务、资产托管信息、发行机构文件、销毁条件与记录；运营另有单位价值调整记录。
- **菜单**：运营“销毁记录”、机构新增“解除托管”，在共享 `menu.admin.js` 登记，所有管理端模块侧栏一致。M5 菜单表的同步按 PRD 由其所属 issue 处理。
- **移除的旧画面**：审核、驳回、重试、业务签名、“原监管机构”、凭证选填，以及铸造后机构追加材料（M3b 已在铸造成功时关闭）。逐代币重复的调价画面合并为一套主流程示例。模块私有 `m4b.css` 已删除，所需布局并入共享 `.ledger-list`（组件规范 v1.63 §10）。

## 主流程

- 运营：`b-list → b-pending`（销毁中）→ `b-release`（销毁成功 · 待解除托管）；失败看 `b-failed`、`b-prior-failed`（已有新申请），非平台入口看 `b-external`。
- 解除资产托管（资产托管机构 示例机构 C）：`r-list → r-detail → r-edit → r-ready → r-confirm → r-submitting → r-result`。必填、文件上传中或失败、提交失败、结果未确认，以及停用机构、依据缺失等状态见画面目录。
- 调整单位价值（DEMO-TOKEN-001）：`l-001 → v-edit → v-ready → v-confirm → v-pending → v-success → l-001-updated`；失败为 `v-failed`，处理中详情为 `l-001-updating`。`l-021`（销毁中）的调整按钮不可用，已销毁代币不显示调整入口。
- 审计机构（示例机构 D，只读）：`r-list-audit`（无解除事项）→ `rld-list` → `rld-025`。

## 待 PRD 补充（已在 WS-515 提出）

1. **操作进度**：M4b PRD 没有定义销毁记录详情和解除托管详情的“操作进度”。原型按 13.3 / 13.4 / 13.6 已有字段组织事件和可见范围；请 PRD 写明事件清单、角色与账号的展示方式，以及各身份的可见范围。
2. **运营能否看到销毁链上交易标识**：13.3 写“运营可核对完整记录”（含链上交易标识），13.5 写“本期不向用户展示销毁交易哈希”，两处不一致。原型暂不展示销毁交易哈希。
3. **调价等待链上结果的超时**：M3b 铸造有 10 分钟超时提醒，单位价值调整没有定义。原型只展示等待状态，不加超时。
