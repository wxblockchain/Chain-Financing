2026-11-04 修订：

## 打开与维护

- 在完整仓库中双击 [管理端账号与监管机构管理.html](管理端账号与监管机构管理.html)。默认打开共用邮箱/密码登录入口，正常登录示例进入账户设置；运营可从侧栏进入监管机构管理。
- 直接查看 [机构列表](管理端账号与监管机构管理.html#rg-list)、[监管账户设置](管理端账号与监管机构管理.html#r-settings)、[首登改密](管理端账号与监管机构管理.html#first-ready)。这些链接也是可复制的画面定位。
- 右下角「画面目录 · 演示数据」默认关闭。展开后按页面/流程分组查看角色、空态、代表性异常与步骤，也可使用「主流程下一屏」。角色仅在目录内切换，不增加产品角色选择页。
- 正常主流程使用预填演示数据，空表单与不可提交结果另有画面。输入、下拉、密码显隐、双语和时区预览可操作；主操作跳转固定画面，不根据输入执行业务判断。次要操作仅呈现入口与可用状态。
- 两个子模块在一个源 HTML 中维护，方便连续查看登录、本人账户与运营机构管理。它们共用 `_shared/tokens.css`、`components.css`、`display.js`、`frame.js`；没有单独的模块主题或另一套运行时。源 HTML 不内嵌公共样式。
- 离线评审附件由现有导出器生成，生成件不入库。在 `页面原型/` 下执行：

  ```sh
  python3 _shared/export.py --source 管理端/M5-管理端登录与权限/管理端账号与监管机构管理.html --output <仓库外路径>/M5-管理端账号与监管机构管理.html
  ```

### 主要跳转

| 主流程 | 可定位的画面 ID |
| --- | --- |
| 运营登录与机构管理 | `login-ops` → `o-settings` → 侧栏监管机构管理 `rg-list` |
| 添加机构、邮件结果与新机构 | `rg-list` → `invite-ready` → `invite-sent` → `rg-initial`；返回列表为 `rg-added` |
| 首次改密与重新登录 | `login-initial` → `first-ready` → `login-changed` → `login-ops` |
| 找回密码 | `login-reg` → `recover-filled` → `recover-code` → `recover-ready` → `login-recovered`；验证码异常 `recover-code-invalid` / `recover-code-expired` → `recover-code` |
| 运营找回密码 | `login-ops` → `recover-ops-filled` → `recover-ops-code` → `recover-ops-ready` → `login-recovered-ops` |
| 首登前找回成功 | `login-recovered-initial` → `login-initial` → `first-ready` |
| 本人改密码 | `o-settings` → `password-ready` → `login-changed`；监管用 `password-reg-ready` |
| 本人改邮箱 | `r-settings` → `self-email-filled` → `self-email-code` → `self-email-confirm` → `login-email` → `r-settings-new` |
| 运营本人改邮箱 | `o-settings` → `self-email-ops-filled` → `self-email-ops-code` → `self-email-ops-confirm` → `login-email-ops` → `o-settings-new` |
| 编辑资料 | `rg-detail` → `edit-changed` → `edit-saved` |
| 停用/启用 | `rg-detail` → `disable-confirm` → `rg-off` → `enable-confirm` → `rg-detail` |

这些是固定演示画面跳转，不流转或持久化实际账号、密码和机构数据。原目标返回以 `login-target-ops` / `login-target-reg` 展示有权及无权的结果；不模拟标签页、会话或权限状态机。

## 业务不变量与待定项

- 联系邮箱与登录邮箱独立；机构名称最多 100 字，联系人最多 60 字，核心资料包含联系人、联系邮箱、国家或地区。国家下拉使用示例选项，不代表生产全集。
- 自身牌照只收 PDF，最多 10 份，每份最大 10 MB；不增加牌照编号等额外输入。上传中或失败未处理的画面不能保存，未提供与读取失败明确区分。
- 一机构只有一个有效账号。机构添加后运营不能修改登录邮箱，详情不提供修改入口；登录邮箱只能由本人在账户设置中修改，验证新邮箱、保留当前密码，无需再次首登改密，确认前说明旧邮箱失效与全部登录结束。本人修改后不改写邀请邮件发送结果。
- 两类账号均可自助找回和修改本人邮箱，验证码仅发本人当前邮箱或本次新邮箱，不向全体运营、联系邮箱或其他账号发送；修改后身份、角色、权限和历史记录归属保持不变。
- 邀请邮件失败不回滚机构/账号，不展示已提交的初始密码，不提供重发邀请。运营没有代重置密码入口。
- 停用只拦新业务，仍可登录并办理在途业务；机构启停与账号锁定独立。首登受限画面只有改密、语言和退出，没有业务菜单、消息或账户设置。
- 验证码参数按 01 册「验证码参数」：6 位数字、10 分钟有效、单码输错 5 次作废、同一邮箱间隔 60 秒、24 小时 10 次（两种用途合计）、同一网络地址每小时 20 次、发送失败可立即重试 1 次。原型画出结果：剩余秒数为静态示例（58 秒），不运行倒计时；“约 3 小时”为演示值；不演示粘贴清洗、错误计数与额度计算。等待与超限提示对任何邮箱相同。验证码邮件的内容由 03 册定义，原型不画邮件。

## 视觉与共享层

唯一取值来源为 `_shared/tokens.css`：主色 `--accent` #1D4ED8、页底 `--bg` #F7F8FB、白卡片、238 px 侧栏、68 px 顶栏、44/36 px 控件、8 px 卡片圆角、6 px 控件圆角。内容左右 24 px、无固定居中限宽。系统字体与 24/16/14/13 px 层级沿用项目规范。无网络字体或外部素材。

M5 列表沿用最新版 36 px 矩形筛选工具栏，常用下拉在左、搜索与操作在右。详情按核心资料、账号与维护信息、邀请邮件发送结果与附件分区；字段区宽度 ≥ 900 px 时每行三项，762–899 px 两项，更窄一项。账户设置的账号信息同样三列。登录与找回流程固定复用 480 px focus 卡片，验证码输入使用 `.code-control`。

通用样式只在 `components.css` 维护。本轮将眼睛按钮内嵌输入框，`frame.js` 统一图标、动作名称和按下态，`display.js` 保证切语言后名称与实际显隐一致。M1 仅替换复制邮箱的文字按钮；M2 由 `asset-detail.js` 共享材料行统一点击文件名查看、图标下载。原复制处理、文件提示、业务字段与 token 不变。`navigation.js` 补充运营改邮箱后的展示身份与 M2 双向路由；附件继续排除仓库专用路由。
