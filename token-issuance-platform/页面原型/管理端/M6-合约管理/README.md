# M6 · 合约管理

运营查看合约列表，编辑合约名称，启用或停用合约。依据 2026-11-06 版 [PRD](../../../PRD/管理端/M6-合约管理/01-合约管理-PRD.md)（范围定案 `e9c5229`，含 COU 大写确认 `308bb44`）及同目录流程图、验收册，在上游 28 屏原型 `ff1dd92` 上深化 UI；**规则、校验与异常分支以 PRD 为准**。画面中的合约、地址、账号均为演示数据。

本轮为 existing-system adaptation，管理端 console 修订。沿用 `_shared/tokens.css`、`components.css`、`frame.js`、`menu.admin.js` 与现有图标，视觉入口为[组件规范 §13](../../_shared/design-system/组件规范.md#13-合约管理m6维护列表与确认)：主色 `--accent`、页底 `--bg`，44 px 控件、238 px 侧栏、24 px 卡片内边距、13 px 表格文字。合约列表变体统一维护在共享组件层，目前仅 M6 使用；token、运行时与路由未改。

## 打开方式

- 仓库联看：完整同步 `页面原型/` 后双击 [`index.html`](../../index.html) 选择“运营”进入，或直接双击本目录 [`合约管理.html`](合约管理.html)。真实侧栏与账号菜单可跨模块跳转，语言、时区与身份随之传递；M3b 二审“前往合约管理”落到 C01。
- 单模块附件：在 `页面原型/` 下执行 `python3 _shared/export.py --source 管理端/M6-合约管理/合约管理.html --output <仓库外路径>.html`，可双击离线打开；跨模块入口显示范围提示。
- 侧栏底部（窄屏为右下角）的「画面目录 · 演示数据」默认关闭，按分组列出全部画面，并提供「主流程下一屏」。等待类画面不自动推进。

## 主流程

- 编辑名称：C01 合约列表 → C07 当前名称 → C11 保存中 → C04 名称保存成功；停用合约改名为 C14 → C15 → C16。
- 停用 / 启用：C18 停用确认 → C20 提交中 → C06；C17 启用确认 → C19 → C05。
- 已为目标状态（C23）或状态冲突（C24）均不执行本次操作，返回 C25 展示最新状态，不提示操作成功。
- 名称或状态提交结果不明：从目录进入 C26 / C27，展示暂时无法读取、结果待核对的画面。同一合约同一维护项不可重复提交，另一维护项与其他合约仍可操作；“重新读取”分别跳到名称成功 C04 / 停用成功 C06 的示例结果，不模拟接口读取或规则判断。
- 演示合约：Demo Contract K（ERC-3525，代币符号 COU，应收账款，Ethereum，启用，0x3525…3525，即 M3b 铸造与 M4a / M4b 代币所属合约）、Demo Contract L（同上，停用）。其他模块的符号与业务流程由对应模块后续修订。

## 实际核验

2026-11-06 本轮 UI 核验：源码与 `export.py` 离线附件各 28 屏，Chromium headless 在 1280 / 1440 / 1920 × 1000、中文 / English 下共检查 336 个组合，无脚本错误、整页横向溢出、单元格内容溢出或操作区超出视口。离线附件资源全部内联，运行无外部网络请求。

逐屏内容及按钮 / 输入属性与上游做静态等价比对（仅“合约”卡片标题改为“合约列表”）；原有 28 屏、数据、禁用属性、跳转目标与提示完整保留。源码与附件均实测四条主流程的真实入口、提交中禁用及目录下一屏结果、键盘 Enter 打开名称编辑、输入焦点、Escape 返回原按钮、hover、两类待核对画面的独立禁用、COU 纯符号降级及复制传递完整 42 位地址。另用临时 DOM 值检查 60 字中文 / 长英文名称换行及 1280 × 720 下启用确认按钮可达；临时值未写入交付件。源码与附件各在 1280 × 1000、200% CSS 放大下检查名称编辑、启用确认、停用失败（中英文），底部操作与画面目录按钮无重叠；未覆盖所有画面的浏览器原生缩放。

共享 CSS 只新增 M6 显式类变体；其余 10 个模块不含这些类，逐一入口加载无脚本错误，未声称完成这些模块的全屏回归。截图内部查看了默认列表、名称编辑和英文启停确认，不作为附件交付。目录默认关闭，等待画面不自动推进。未新增画面、规则、模拟校验或运行时。

未验证 Safari / Firefox、1280 px 以下宽度、真实接口 / 权限 / 链上能力；原型不证明这些能力已实现。
