# M6 · 合约管理

运营查看合约列表，编辑合约名称，启用或停用合约。依据 [PRD](../../../PRD/管理端/M6-合约管理/01-合约管理-PRD.md)（基线 `96e6093`）及同目录流程图、验收册；**规则、校验与异常分支以 PRD 为准**。画面中的合约、地址、账号均为演示数据。

本轮为 existing-system adaptation，管理端 console 修订。沿用 `_shared/tokens.css`、`components.css`、`frame.js`、`menu.admin.js` 与现有图标，视觉入口为[组件规范 §13](../../_shared/design-system/组件规范.md#13-合约管理m6维护列表与确认)：主色 `--accent`、页底 `--bg`，44 px 控件、238 px 侧栏、24 px 卡片内边距、13 px 表格文字。合约列表变体统一维护在共享组件层，目前仅 M6 使用；token、运行时与路由未改。

## 打开方式

- 仓库联看：完整同步 `页面原型/` 后双击 [`index.html`](../../index.html) 选择“运营”进入，或直接双击本目录 [`合约管理.html`](合约管理.html)。真实侧栏与账号菜单可跨模块跳转，语言、时区与身份随之传递；M3b 中的“前往合约管理”落到 C01。
- 单模块附件：在 `页面原型/` 下执行 `python3 _shared/export.py --source 管理端/M6-合约管理/合约管理.html --output <仓库外路径>.html`，可双击离线打开；跨模块入口显示范围提示。
- 侧栏底部（窄屏为右下角）的「画面目录 · 演示数据」默认关闭，按分组列出全部画面，并提供「主流程下一屏」。等待类画面不自动推进。

## 主流程

- 编辑名称：C01 合约列表 → C07 当前名称 → C11 保存中 → C04 名称保存成功；停用合约改名为 C14 → C15 → C16。
- 停用 / 启用：C18 停用确认 → C20 提交中 → C06；C17 启用确认 → C19 → C05。
- 已为目标状态（C23）或状态冲突（C24）均不执行本次操作，返回 C25 展示最新状态，不提示操作成功。
- 名称或状态提交结果不明：从目录进入 C26 / C27，展示暂时无法读取、结果待核对的画面。同一合约同一维护项不可重复提交，另一维护项与其他合约仍可操作；“重新读取”分别跳到名称成功 C04 / 停用成功 C06 的示例结果，不模拟接口读取或规则判断。
- 演示合约：Demo Contract K（ERC-3525，代币符号 COU，应收账款，Ethereum，启用，0x3525…3525，即 M3b 铸造与 M4a / M4b 代币所属合约）、Demo Contract L（同上，停用）。其他模块的符号与业务流程由对应模块后续修订。

列表一次展示七项信息：合约名称、合约标准、代币符号（图标 + COU，图标不可用时仅显示 COU，不影响查看与维护）、对应资产类型、所在网络、合约地址（缩写 + 完整地址复制）、合约状态。名称字段显示“已输入 / 60”与格式提示；60 个用户感知字符、Unicode 空白与规范等价重名比较按 PRD 实现，原型只画必填与重名两个错误示例，不实现校验或计数逻辑。

合约列表按业务列表通用规则（M2 §5.8）分页：有记录的 9 屏列表卡片带分页条（演示共 2 条，只画第 1 页）；不设筛选条，空（C02）与读取失败（C03）两屏可区分。停用确认、提交中、失败（C18 / C20 / C22）说明停用后所属代币仍可更新代币单位价值，与 PRD 代币单位价值链上更新（F-CT-07）“所属合约被平台停用不影响更新”一致。

COU 图标是平台内的识别图形，不写入合约，也不是第八项合约信息；M6 只负责合约列表的“图标 + COU”及降级（C28），其他模块在何处展示由各模块定义。F-CT-07 是合约侧规则（提交到原合约、仅接受平台指定更新地址、已销毁代币拒绝更新等），M6 不提供更新入口、地址管理或调整记录，原型不新增画面。

本期不做：七项信息之外的详情能力、跳转区块链浏览器、合约新增 / 删除 / 部署 / 升级、修改其余只读项、图标编辑、为外部钱包 / 浏览器显示图标而增加合约侧信息、搜索 / 筛选、合约统计、消息通知、转让 / 质押 / 解除质押入口、代币单位价值调整入口与记录（M4b）、发行选择与铸造重试（M3b）、销毁申请 / 钱包 / 结果承接（M4a / M4b）。七项信息本轮继续由列表承载，不增设重复详情。合约层的整枚转让和销毁硬约束不另建 M6 页面，原型不验证链上能力。

## 实际核验

Chromium headless，源码与 `export.py` 离线附件均以 file:// 打开：28 屏 × 中文 / English × 1280 / 1440 / 1920 × 1000 高，共 336 个布局组合；未出现脚本错误、整页横向溢出、单元格内容溢出或操作区越界。逐档核对英文 verification 单词不再被拆开。附件资源全部内联，无外部网络请求。

原型修订前后逐屏比较：中文与渲染后的英文文字（忽略排版空白）、画面属性、按钮 / 输入属性、分页总数保持一致。逐一点击 28 个目录入口；四条主流程保留提交中和结果屏；实测名称编辑的键盘打开与 Esc 焦点返回、两种待核对状态的独立禁用、COU 图标降级及复制传递完整地址。九条分页保留总数 2、当前页 1 及前后页禁用，页码键盘焦点可见。

补充核验：1024 × 768 的表格滚动回退（键盘进入、方向键滚动、固定操作列可见）；临时长名称；1280 × 720 的启停弹窗；部分弹窗及待核对列表在中英文 200% CSS 放大时的正文滚动与底栏 / 重新读取按钮可达。临时样本不写入交付文件。内部查看了默认列表、待核对状态、名称错误、启停确认与失败截图，截图不作为交付附件。

共享 CSS 新规则只用于 M6 显式变体，其余 10 个模块的入口加载无脚本错误，未做这些模块的全屏回归。未验证 Safari / Firefox、全部画面的浏览器原生缩放、真实接口、权限与链上能力；原型不证明这些能力已经实现。
