# M3b · 发行审核与铸造

按用户“直接输出页面原型”合并后续阶段交付。类型：existing-system adaptation / console；基线为 `cly-v6.0.0` 的 M3b PRD 四册（`330a9a4`：两步通过并铸造、平台签名与铸造进度、10 分钟超时提醒、运营可见的业务签名；含 `d6d6a8b` 的资产价值与代币符号单位），沿用组件规范，审核组件见 v1.14、v1.32～v1.34。

## 打开与维护

- 完整同步 `页面原型/` 后双击 [发行审核.html](发行审核.html)，默认进入运营「发行审核」列表；监管画面在右下角默认关闭的「画面目录 · 演示数据」中切换。
- 使用现有真实侧栏切换 M2、M5、M6；资产详情的 `IA-DEMO-0031` 可返回本模块同一笔申请。语言、IANA 时区和对应身份随仓库联看传递；未交付的代币台账、销毁等入口保留范围提示。
- 源文件只引用 `_shared/` 的 token、组件、图标、展示、壳层、导航及详情分区导航，不包含模块 CSS 或第二套运行时。审核列表、标题状态行、合约单选、意见框和文件预览样式维护在 `components.css`，审核进度复用 M3a 的 `.review-timeline`，取值全部来自既有 token。
- 从 `页面原型/` 执行 `python3 _shared/export.py --source 管理端/M3b-发行审核/发行审核.html --output <仓库外路径>.html`，生成可双击打开的单模块离线附件。附件不含 `navigation.js`，跨模块入口只提示范围；生成件不入库。

## 详情页结构

- **标题行**：企业名称作页面标题（审核对象，监管据此对应线下签协议的企业），真实申请状态标签紧随其后；下方为申请编号和时区。操作按钮在右侧，标题行滚动时吸顶，编号、状态与操作始终可见。
- **审核进度置顶**：标题与提示之后先看审核进度，四段时间线（提交、监管一审、运营二审、铸造）以颜色和状态标签区分已完成、待办、驳回 / 铸造失败、未开始，并显示审核方与时间；意见与运营审核人在时间线下方。与 M3a 企业侧进度为同一组件。
- **关联资产**沿用 M2 资产摘要：资产价值、资产编号、债务人、到期日，右侧以状态标签展示确权、结清、逾期、发行四项，配色与可信资产列表一致。
- 审核进度位于分区导航之前，导航只列其下的申请信息、业务签名（仅运营）、关联资产、监管协议、铸造结果或铸造与重试记录。
- **业务签名**（仅运营，任何状态）：签名地址、签名时间、签名值，缩写展示可复制完整值，与 M3a 同一组演示数据；监管机构的详情没有这张卡片。
- **铸造中**：铸造结果卡片说明等待链上结果，列出开始铸造时间、铸造合约和铸造交易哈希；运营在超过 10 分钟仍无结果时看到顶部“铸造已超时”提醒和卡片上的“已超时”标签，状态仍为铸造中。铸造成功展示铸造交易哈希；运营的铸造与重试记录逐次列出交易哈希，平台未能签名或提交的一次没有哈希。

## 通过并铸造与铸造进度

- **同一尺寸的标签页弹窗**：通过并铸造从选择合约到铸造结果都在同一个 600 × 700 px 弹窗内，顶部标签“1 选择合约 · 2 发起铸造 · 3 铸造进度”表示当前位置；已完成的步骤显示对勾，确认通过前可点“选择合约”返回，确认后前两步锁定。重试铸造同样为“1 确认重试 · 2 铸造进度”。
- **两步完成**：第 1 步的合约选项一次给出名称、标准、代币符号、资产类型、网络和可复制的合约地址，未选时“下一步”不可用并提示原因；第 2 步只列写入链上的代币数量（cou）、到期日、接收地址和合约名称，不再重复合约详情，可“上一步”返回且保留所选合约。
- **铸造进度**：确认后切换到“铸造进度”标签，展示四个阶段——二审通过 → 平台签名并提交（平台用开发人员配置的私钥，无需钱包）→ 等待链上结果（显示交易哈希）→ 铸造结果；成功显示代币数量与交易哈希，失败可“再次发起铸造”。关闭弹窗不影响铸造，可在详情查看所处阶段。
- **重试**只有一步确认：代币数量、接收地址和原合约名称，确认后进入同一套进度，首个阶段为“记录重试”。

## 画面清单与到达方式

上述新增画面状态为 covered；共享壳层、组件和既有 M2/M5/M6 业务画面为 preserved from existing。本次仅为 M2 申请编号补跨模块路由，未重画 M2。保持两位小数、Ethereum、只读发行字段、监管数据范围与意见原文；列表与关联资产展示资产价值（USD），代币数量以所选合约的代币符号为单位（演示 `cou`），合约选项与合约信息展示代币符号；铸造成功后写作“监管”，不写“质押”。监管看不到账户备注、运营账号、业务签名、超时提醒或铸造失败说明。“铸造超时待处理”（NT-A05）等站内消息由消息模块承接，本原型不画消息列表。

首次二审只可选可用合约。重试沿二审原合约，不重新按首次筛选条件排除平台停用合约；实际链上执行异常单独出屏。此口径来自最新 PRD `3d581de`，替代 Stage 1 基线中“平台停用须先启用再重试”的旧表述。

本期不做（out of scope）：企业提交、撤回和修改申请；驳回后重开或退回；在线签署协议；一审后替换、删除或补传协议；审核人修改代币数量、到期日、地址；合约部署与维护；融资、销毁、解除监管及任务分派认领。上述功能由 PRD 或相邻模块承接，不在本原型中新增。
