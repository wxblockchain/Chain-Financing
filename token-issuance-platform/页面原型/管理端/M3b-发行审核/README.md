# M3b · 发行审核与铸造

按用户“直接输出页面原型”合并后续阶段交付。类型：existing-system adaptation / console；基线为 `cly-v6.0.0` 的 M3b PRD 四册（`d6d6a8b`：资产价值、代币符号单位、“监管”称谓与详情识别信息），沿用组件规范，审核组件见 v1.14 与 v1.32。

## 打开与维护

- 完整同步 `页面原型/` 后双击 [发行审核.html](发行审核.html)，默认进入运营「发行审核」列表；监管画面在右下角默认关闭的「画面目录 · 演示数据」中切换。
- 使用现有真实侧栏切换 M2、M5、M6；资产详情的 `IA-DEMO-0031` 可返回本模块同一笔申请。语言、IANA 时区和对应身份随仓库联看传递；未交付的代币台账、销毁等入口保留范围提示。
- 源文件只引用 `_shared/` 的 token、组件、图标、展示、壳层、导航及详情分区导航，不包含模块 CSS 或第二套运行时。审核列表、标题状态行、合约单选、意见框和文件预览样式维护在 `components.css`，审核进度复用 M3a 的 `.review-timeline`，取值全部来自既有 token。
- 从 `页面原型/` 执行 `python3 _shared/export.py --source 管理端/M3b-发行审核/发行审核.html --output <仓库外路径>.html`，生成可双击打开的单模块离线附件。附件不含 `navigation.js`，跨模块入口只提示范围；生成件不入库。

## 详情页结构

- **标题行**：企业名称作页面标题（审核对象，监管据此对应线下签协议的企业），真实申请状态标签紧随其后；下方为申请编号和时区。操作按钮在右侧，标题行滚动时吸顶，编号、状态与操作始终可见。
- **审核进度置顶**：标题与提示之后先看审核进度，四段时间线（提交、监管一审、运营二审、铸造）以颜色和状态标签区分已完成、待办、驳回 / 铸造失败、未开始，并显示审核方与时间；意见与运营审核人在时间线下方。与 M3a 企业侧进度为同一组件。
- **关联资产**沿用 M2 资产摘要：资产价值、资产编号、债务人、到期日，右侧以状态标签展示确权、结清、逾期、发行四项，配色与可信资产列表一致。
- 审核进度位于分区导航之前，导航只列其下的申请信息、关联资产、监管协议、铸造结果或铸造与重试记录。

## 画面清单与到达方式

共 **74 屏**，全部在画面目录中可到达。列表 → 详情、上传／选择／填写 → 确认 → 提交中由页面按钮逐屏跳转；提交中与铸造中不自动推进，使用目录中的「主流程下一屏」查看后续结果。各画面为同笔演示申请的独立阶段快照，不构成实时状态机。

上述新增画面状态为 covered；共享壳层、组件和既有 M2/M5/M6 业务画面为 preserved from existing。本次仅为 M2 申请编号补跨模块路由，未重画 M2。保持两位小数、Ethereum、只读发行字段、监管数据范围与意见原文；列表与关联资产展示资产价值（USD），代币数量以所选合约的代币符号为单位（演示 `cou`），合约选项与合约信息展示代币符号；铸造成功后写作“监管”，不写“质押”。监管看不到账户备注、运营账号或铸造失败说明。

首次二审只可选可用合约。重试沿二审原合约，不重新按首次筛选条件排除平台停用合约；实际链上执行异常单独出屏。此口径来自最新 PRD `3d581de`，替代 Stage 1 基线中“平台停用须先启用再重试”的旧表述。

本期不做（out of scope）：企业提交、撤回和修改申请；驳回后重开或退回；在线签署协议；一审后替换、删除或补传协议；审核人修改代币数量、到期日、地址；合约部署与维护；融资、销毁、解除监管及任务分派认领。上述功能由 PRD 或相邻模块承接，不在本原型中新增。
