## 列表排版

- 原企业端列序为：账户备注名 / 区块链网络 / 数币地址 / 来源 / 创建时间 / 操作。管理端只读账户表还展示更新时间。它们是历史设计参考字段，后续是否采用须以新 PRD 为准。
- 原列宽比例为备注名 20%、网络 16%、地址 22%、来源 16%、创建时间 14%，操作列保留 112 px；最小表宽 960 px。表头按完整词换行，密集时在表格内部滚动，操作列固定右侧。
- `.account-current` 使用中性浅底与首列主色线，并保留“登录地址”文字。名称、来源、创建时间与长地址的处理沿用对应基础组件。
- 行操作文字至少 36 px 点击高度，删除采用危险文字与浅危险色悬停。原设计把删除限制放在确认说明中；未来启用时仍须重新确认权限、引用校验和禁用策略。
- 原设计在仅有默认项时用 `.inline-empty` 追加说明与新增入口；本期唯一登录地址并非待补充账户的空状态，因此不应用这项表现。

## 表单、弹窗与单选表

- 复用公共 `.field`、`.inp`、`.field-static`、`.steps`、`.wait`、`.modal`、`.note`、`.addr` 等组件，不建立第二套配色和字体。
- 原填写表单打开时焦点在地址输入框；编辑表单明确网络和不可修改地址，备注名为可编辑字段。是否允许编辑哪些字段由后续 PRD 决定。
- 目标地址使用 `.account-target` 只读容器和完整值复制，避免编辑或删除时误认另一条记录。打开弹窗、Tab、Escape 与焦点返回遵循公共弹窗约定。
- 原删除设计区分未引用、当前登录地址、被申请或代币引用三类提示；这些判断与对应动作均未在本期恢复。
- 原接收账户单选表列宽为：单选 52 px / 备注名 26% / 网络 22% / 地址占剩余空间；选中行浅主色底，同时有单选标识与 `aria-checked`，不只靠颜色表达。

## 样式资产与启用条件

样式及两个尺寸 token 保留在 [multi-account.css](multi-account.css)。该文件未被任何本期 HTML、CSS 或 JS 引用，`export.py` 也不会把它内联到本期单模块附件。

后续增加多账户功能时：

1. 按新 PRD 确认字段、权限、地址归属验证、引用限制及状态画面；本文件不代替业务裁定。
2. 明确旧登录地址如何处理。“旧地址顺延为普通账户”属于旧设计行为，本期已取消，不因保留规范而自动恢复。
3. 把获准使用的 token、样式合回现有公共层，并删除储备中的对应重复定义，保持活动实现只有一个来源。
4. 根据实际页面恢复展示适配与事件，不直接恢复原先依赖已删除 DOM 的脚本；重新核验中英文、响应式、键盘焦点、跳转、画面目录与离线导出。

保留设计资产不会新增本期页面、路由、菜单、默认选项或后台能力。
