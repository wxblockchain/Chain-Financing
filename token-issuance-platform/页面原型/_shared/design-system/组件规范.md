# 代币发行平台 · 组件规范（v1.0）

2026-10-29｜依据：M1 企业登录与企业账户原型提炼｜适用：本平台面客端与管理端原型

本规范说明本平台原型使用的组件，以及原型轻量化约定。规则、校验与异常分支以各模块 PRD 为准；本文只约定画面怎样呈现。

代码入口：

| 文件 | 作用 |
| --- | --- |
| [`../tokens.css`](../tokens.css) | 颜色、字号、间距、圆角、组件尺寸。唯一取值来源 |
| [`../components.css`](../components.css) | 骨架与公共组件。模块页面不重定义组件 |
| [`../frame.js`](../frame.js) | 壳层渲染、画面切换、画面目录。不承载业务逻辑 |
| [`../export.py`](../export.py) | 把模块 HTML 内联成单文件评审件，生成件不入库 |

## 1. 取值基线

视觉取值沿用借贷平台运营端的实际生效值，来源为 `cly-v6.0.0` 分支的 `lending-platform/页面原型/_shared/tokens.css` 与 `base.css`（含 `[data-end]` 覆盖层）。以下是与借贷平台的差异，均为有意调整：

| 项 | 借贷平台 | 本平台 | 原因 |
| --- | --- | --- | --- |
| 字体 | 内嵌 Geist + Noto Sans SC 子集（约 340 KB） | 系统字体栈 | 轻量化，单文件评审件约 70 KB |
| 地址与哈希字体 | 与正文同字体 | 等宽字体 | 以太坊地址需要逐位核对 |
| 多语言、暗色市场主题、官网层 | 有 | 无 | 本平台简报未要求 |
| 组件密度 | 面客端与运营端两套覆盖 | 一套 | 两端共用同一组件规格 |

## 3. 骨架

| 骨架 | 用在哪里 | 构成 |
| --- | --- | --- |
| app | 登录后的业务页 | 左侧栏（品牌 + 分组菜单）+ 顶栏（面包屑、消息入口、账户入口）+ 内容区（上 32、左右 24、下 56 px） |
| focus | 未登录、游客 | 顶部品牌条（右侧放账户入口）+ 居中卡片（480 px；内容多时用 `.wide` 600 px） |

- 菜单按产品信息架构分组，只放真实去向。面客端为「业务」（可信资产、代币发行、我的代币、销毁申请）和「企业账户」（数币账户、企业信息、用户信息）。没有首页或工作台。
- 菜单选中：主色浅底 + 主色描边 + 600 字重。需要认证才能使用的菜单，在未认证时右侧显示锁形标记，菜单仍可点击。
- 面包屑在顶栏左侧，格式为「分组 / 页面」，当前页加粗。
- 账户入口：圆角胶囊，显示缩略地址（前 6 位 + … + 后 4 位，保留大小写）。展开后顶部显示企业名称与完整登录地址（可复制），下面是菜单项与退出。游客只有地址和退出。

## 4. 组件

### 4.1 按钮

| 类型 | 类名 | 用法 |
| --- | --- | --- |
| 主按钮 | `.btn.primary` | 每屏一个主操作，放在页头右侧或弹窗底栏最右 |
| 次按钮 | `.btn` | 取消、重试、复制等 |
| 幽灵按钮 | `.btn.ghost` | 弱操作，如「上一步」「取消」 |
| 危险按钮 | `.btn.danger` | 只用在删除确认弹窗的主按钮位 |
| 紧凑按钮 | `.btn.sm` | 提示条、空状态行内的操作 |
| 图标按钮 | `.btn.icon` | 复制、关闭；必须有 `aria-label` |
| 文字链接 | `.btn-link` / `.actlink` | 行内跳转 / 表格操作列 |

- 不可用：`aria-disabled="true"`，透明度 0.55。不可用的原因必须就近可见，例如表格行副文本「已被代币引用，不能删除」，不能只放在悬停提示里。

### 4.2 表单

- 结构：`.field` > 标签 + 控件 + 提示或错误。标签 12 px 在上；必填在标签前加红色 `*`。
- 有长度上限的文本框，在标签行右侧显示计数，如「6 / 100」。
- 格式要求写在占位符或输入框下方的提示里，如「0x 开头，共 42 位」「登记后不能修改」。
- 错误：输入框红色描边（`aria-invalid="true"`）+ 下方一行红字说明原因；能给出去处时，在错误后加文字链接（如「查看已有账户」）。原型每个表单只画一个错误示例。
- 只读值放在表单中时用 `.field-static`：浅底、虚线框，与可编辑控件区分。

### 4.3 状态标签

`.tag` 加语义类：`ok`（已认证、已验证）、`warn`（审核中等待处理）、`danger`（失败、驳回）、`accent`（身份标记，如「登录地址」）、默认灰（中性）。在身份摘要中可带圆点 `.dot`。

### 4.4 钱包地址

- 页面中显示完整地址：`.addr-pill` 等宽字体浅蓝标签 + 复制图标按钮，表格中不换行。
- 缩略形式只用于账户入口按钮。
- 签名流程中待核对的地址，用 `.field-static` 等宽完整显示。

### 4.5 卡片与只读信息

- `.card`：白底、1 px 描边、8 px 圆角、无阴影。卡片头 `.card-head`：标题 + 计数（`.sub`）+ 右侧操作。
- 只读信息 `.facts`：标签 136 px + 值。内容区宽度 ≥ 762 px 时自动排成两列；`.wide` 占整行；`.single` 固定单列（弹窗内使用）。
- 身份摘要 `.ident`：首字标识 + 名称（20 px）+ 英文名 + 右侧状态标签，放在详情卡片顶部。
- 资料由外部平台维护时，在页面说明里写一句「这些信息由资产可信平台维护，本平台只读」，不在每个字段下重复。

### 4.6 数据表

- 表头 12 px、`--card-2` 底；行高由上下 16 px 内边距决定；首末列左右内边距与卡片一致（24 px）。
- 单元格主文本 `.cell-main`，副文本 `.cell-sub`（12 px）。副文本放身份说明或不可操作的原因。
- 时间用两行：日期 / 时间（副文本）。
- 操作列 `.col-act` 右对齐、固定在右侧，1280 px 下也必须可见。不可操作的行显示「—」，原因写在该行副文本里。
- 刚新增的行用 `.is-new` 浅主色底标出，同时弹出结果提示。

### 4.7 提示条

| 类型 | 类名 | 用法 |
| --- | --- | --- |
| 说明 | `.note` | 填写前需要知道的限制 |
| 重要说明 | `.note.accent` | 签名用途、关键后果 |
| 警示 | `.note.warn` | 当前受限、需要用户处理的情况 |
| 错误 | `.note.red` | 操作失败的原因 |

- 左侧 3 px 色条 + 图标 + 一段话；可在右侧放一个 `.btn.sm`。
- 页面级提示条（`.banner`）放在页头上方或下方，只用于影响整页的情况，如钱包地址与登录地址不一致、认证未通过。

### 4.8 区块状态

`.state` 用在卡片内，替代整块内容：

| 状态 | 类名 | 内容 |
| --- | --- | --- |
| 空 | `.state` | 图标 + 标题 + 一句说明；有去处时加按钮 |
| 读取失败 | `.state.err` | 「××读取失败」+「暂时无法读取，请稍后重试」+ 重试按钮；不能显示成空 |
| 受限 | `.state.gate` | 锁形图标 + 受限原因 + 前往处理的主按钮 |

列表只有系统默认项时，用 `.inline-empty`：在表格下方加一行虚线分隔的说明和新增按钮，不清空表格。

### 4.9 多步流程

- 步骤条 `.steps`：当前步主色实心圆，已完成步骤显示对勾，未开始为空心圆。
- 等待外部确认（钱包签名、调取身份）用 `.wait`：转圈 + 主说明 + 一行副说明。等待期间只保留「取消」。
- 每一步一屏；进入下一步的按钮写明下一步是什么，如「下一步：签名验证」「发起签名」。

### 4.10 弹窗与确认

- 结构：标题栏（标题 + 关闭）/ 内容 / 底栏（`--card-2` 底，按钮右对齐，主按钮在最右；「上一步」靠左）。
- 打开时焦点落在第一个输入框或主按钮；Esc 与关闭按钮回到原页面。
- 离开本平台、删除等不可撤回的操作必须先弹窗确认：写明去哪里或删除后的后果；删除用危险按钮。

### 4.11 下拉菜单、消息入口与结果提示

- 下拉 `.dd-list`：8 px 圆角、阴影，菜单项 13 px，分组之间用分隔线。点击外部或 Esc 关闭。
- 消息入口 `.bell`：36 px 圆形，未读数用红色角标，未读为 0 时不显示数字。
- 结果提示 `.toast`：深色底，在屏幕底部居中显示约 2.4 秒，用于「已复制」「已保存」「账户已登记」等结果。

## 5. 原型轻量化约定

原型只告诉前端两件事：页面怎么布局，展示哪些信息。规则、校验与异常分支写在 PRD。

**原型包含：**

- 页面 × 主状态的静态画面：每个页面一个默认、一个空、一个代表性异常；身份或阶段不同且布局或可用操作随之变化时，单独出一屏；多步流程每一步一屏。
- 规则生效后的结果：字段是否可编辑、按钮是否可用及原因、必填与格式提示、一个错误示例出现的位置、状态标签、关键后果说明。
- 主流程逐屏可走；其他按钮只表现可用或不可用。

**原型不包含：**

- 校验与计算逻辑、状态机、本地存储的数据流转、演示时钟、故障注入、引导式走查。
- 页面上的规则编号、字段来源、设计理由。
- 多语言切换、主题切换等简报未要求的能力。

**评审工具：** 右下角「画面目录 · 演示数据」按钮，默认关闭。展开后按「页面 → 状态」列出全部画面，并提供「主流程下一屏」。画面中的企业、地址、邮箱、编号均为演示数据。

**文件约定：**

- 源码：`页面原型/面客端/<编号>-<模块名>/<模块名>.html`（管理端放在 `页面原型/管理端/`），只写画面内容，引用 `_shared/` 下的公共层。
- 每屏是一个 `<section data-screen>`，用 `data-*` 声明骨架、身份、菜单、面包屑、所在弹窗的底层画面和主流程下一屏；约定写在 `frame.js` 文件头。
- 评审件：用 `_shared/export.py` 生成单文件，作为附件交付，不入库。

## 6. 新增组件的规则

1. 先复用本规范已有组件；确实缺少时，加到 `components.css` 并在本文补一节。
2. 新组件只引用 `tokens.css` 中的 token，不写字面色值、字号或时长。
3. 模块页面不写行内样式，不复制公共组件。
