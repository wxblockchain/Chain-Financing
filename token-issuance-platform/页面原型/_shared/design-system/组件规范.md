## 1. 取值基线

配色与控件尺寸以借贷平台运营端的实际生效值为基线，M1 的字号、信息排版与响应式按已确认的 UI 设计调整。基线来源为 `cly-v6.0.0` 分支的 `lending-platform/页面原型/_shared/tokens.css` 与 `base.css`（含 `[data-end]` 覆盖层）。以下是与借贷平台的差异，均为有意调整：

| 项 | 借贷平台 | 本平台 | 原因 |
| --- | --- | --- | --- |
| 字体 | 内嵌 Geist + Noto Sans SC 子集（约 340 KB） | 系统字体栈，拉丁字母优先 Arial / Liberation Sans / system-ui，中文按字形回退 | 轻量化，不嵌入字体文件 |
| 地址与哈希字体 | 与正文同字体 | 等宽字体 | 缩写地址的首尾字符更易辨认 |
| 钱包地址 | 详情完整、列表缩写 | 一律缩写，悬停看完整地址，可复制 | 用户确认 |
| 面包屑 | 内容区 | 内容区（不进顶栏） | 用户确认 |
| 语言、暗色市场主题、官网层 | 有 | 中英文即时预览，语言记忆在当前浏览器；无暗色与官网层 | 当前 M1 画面范围 |
| 信息排版 | 通用标签和值横向排列 | 通用只读字段统一名称在上、值在下，详情、关联记录与弹窗共用；桌面按容器宽度排两列 | 适应长英文标签，统一读取方式 |
| 组件密度 | 面客端与运营端两套覆盖 | 一套 | 两端共用同一组件规格 |

## 3. 骨架

| 骨架 | 用在哪里 | 构成 |
| --- | --- | --- |
| app | 登录后页面、游客引导、平台状态反馈 | 左侧栏（品牌 + 分组菜单）+ 顶栏（右侧依次为界面语言、消息入口、账户入口）+ 内容区（上 24、左右 24、下 56 px；面包屑在内容区顶部） |
| focus | 未登录的 L1 / L3 / L4 | 顶部品牌条（右侧放界面语言）+ 水平居中、上方留 56 px 的卡片（480 px；内容多时用 `.wide` 600 px） |

- G1 使用 app 的内容区、面包屑、页标题和常规卡片；顶栏保留语言与账户入口。游客不显示业务菜单、消息或时区设置，不因切换骨架获得业务权限。
- G2 在当前平台内容区展示确认卡片（`.card-b` + `.card-f`），替代原页面内容，不使用全屏遮罩或独立登录卡片；取消 / Esc 返回发起处。企业认证引导共用该确认时也保留原企业页面与身份。
- 菜单按产品信息架构分组，只放真实去向。面客端为「业务」（可信资产、代币发行、我的代币、销毁申请）和「用户中心」（企业账户、企业信息、用户信息）。没有首页或工作台。
- 管理端沿用同一 app 骨架，品牌副标题为「管理端」，菜单按 M5 菜单权限矩阵分角色：运营为「业务」（发行审核、销毁审核、代币台账、可信资产、企业）和「系统管理」（监管机构管理、合约管理）；监管机构只有「业务」（发行审核、解除监管、代币台账、可信资产）。菜单只在 `_shared/menu.admin.js` 维护（`TP.NAV_BY[身份]`），模块不复制。
- 管理端账号入口：胶囊显示账号名称；展开菜单 240 px，依次为名称、登录邮箱、角色标签（机构另附所属机构与类型），再是账户设置与退出登录。由 `TP.demo.accounts[身份]` 提供。停用机构只说明机构已停用，不在共享账号入口承诺既有业务权限。
- 菜单选中：主色浅底 + 左侧 3 px 主色标记 + 600 字重；菜单最小高度 44 px。品牌标识保持水平，不旋转。需要认证才能使用的菜单，在未认证时右侧显示锁形标记，菜单仍可点击。
- 面包屑放在内容区顶部、页面标题上方，不放进顶栏；格式为「分组 / 页面」，当前页加粗。
- **面包屑负责返回列表**：列表进入的详情、表单与子页面使用三级（或更深）面包屑，如「业务 / 发行审核 / 申请详情」。有对应画面的祖先用 `data-crumb-targets` 显式写出目标并渲染为主色真实链接（悬停下划线，可 Enter），业务分组没有页面则保持灰色文本；当前页用 `aria-current="page"`。此时页头不再放「返回列表 / 返回台账 / 返回我的代币」等只回上一级列表的按钮，页头操作区只放本页业务操作。
- **仍保留的返回按钮**：①目标不是上一级列表（返回详情、返回账户设置、返回申请、跨模块返回消息等）；②异常状态卡片内的出路（无权或不存在、读取失败时的「返回列表」）；③结果页的下一步操作（提交成功后「返回列表 / 查看申请」）；④没有面包屑的 focus 页面（登录、找回密码、首登改密中的「返回登录」）。
- **详情页标题行吸附**：三级及以上面包屑的 app 页面，标题行（编号或名称、说明、页头操作按钮）由 `frame.js` 标记 `data-sticky`，滚动时吸附在顶栏下方并显示底线，按钮位置与静止时一致，有操作的状态才有按钮。详情分区导航与锚点偏移叠加 `--sticky-head-h`，不被遮挡。操作仍放在标题行右侧，不改为右侧固定操作栏：多数状态没有操作、操作在弹窗内完成，且侧栏会挤压需逐项核对的信息。
- 账户入口：圆角胶囊，显示缩写地址。展开菜单宽 208 px，只保留缩写地址与复制、退出登录，不显示企业名称或“登录地址”标签。左侧菜单已有的页面、顶栏已有的消息入口，不在账户入口里重复。游客只有地址和退出。
- 界面语言：顶栏地球图标 + 当前语言缩写（`中文` / `EN`）+ 下拉，菜单顶部有“语言”，选项为 English / 简体中文，选中项浅蓝底并带对勾。未登录、游客、企业用户均可切换。语言入口只在平台顶栏，弹窗内不设语言切换（用户确认）。

## 4. 组件

### 4.1 按钮

| 类型 | 类名 | 用法 |
| --- | --- | --- |
| 主按钮 | `.btn.primary` | 每屏一个主操作，放在页头右侧或弹窗底栏最右 |
| 次按钮 | `.btn` | 取消、重试、复制等 |
| 幽灵按钮 | `.btn.ghost` | 弱操作，如「上一步」「取消」 |
| 危险按钮 | `.btn.danger` | 只用在删除确认弹窗的主按钮位 |
| 紧凑按钮 | `.btn.sm` | 提示条、空状态行内的操作 |
| 图标按钮 | `.btn.icon` | 复制、关闭；必须有 `aria-label` |
| 文字链接 | `.btn-link` / `.actlink` | 行内跳转 / 表格操作列 |

- 管理端详情中的发行申请编号本身作为唯一跳转入口，使用 `.btn-link.mono`；编号旁不重复放“查看申请”。沿用原有目标去向及交互反馈。

- **信息旁的微操作**：密码显隐、复制、附件下载/移除、关闭使用图标按钮，不用“显示 / 隐藏”“复制邮箱”等文字按钮；按钮至少沿用 36 px 热区，具备说明动作的 `aria-label`、同义 `title` 和可见键盘焦点。图标设置 `aria-hidden="true"`。复制完整值、显隐输入、关闭与返回关系沿用既有行为。
- **文件查看**：点击文件名本身；旁边仅放下载图标，编辑附件时放移除图标。文件名过长可换行，不复制一份文字“查看”。上传入口、查询、保存、下一步、启停、更正邮箱及业务表格的“查看”等仍用明确文字承载任务，不把业务主操作一律图标化。
- 通用不可用按钮用 `aria-disabled="true"` 或 `disabled`，并有可见说明。企业账户只读，不展示新增、编辑或删除按钮。

### 4.2 表单

- 结构：`.field` > 标签 + 控件 + 提示或错误。标签 13 px 在上；必填在标签前加红色 `*`。
- 有长度上限的文本框，在标签行右侧显示计数，如「6 / 100」。
- 格式要求写在占位符或输入框下方的提示里，如「0x 开头，共 42 位」「登记后不能修改」。
- 错误：输入框红色描边（`aria-invalid="true"`）+ 下方一行红字说明原因；能给出去处时，在错误后加文字链接（如「查看已有账户」）。原型每个表单只画一个错误示例。
- 只读值用 `.field-static`：浅底、虚线框，不伪装成可编辑选择框。

列表筛选条统一按 §4.14 的矩形控件、左右分组与展开区规范实现；普通录入表单仍沿用本节规格。

### 4.3 状态标签

`.tag` 加语义类：`ok`（已认证等成功状态；数币账户不再展示验证状态）、`warn`（审核中等待处理）、`danger`（失败、驳回）、`accent`（身份标记，如「登录地址」）、默认灰（中性）。在身份摘要中可带圆点 `.dot`。

### 4.4 钱包地址

- 所有展示位置一律缩写：前 6 位 + … + 后 4 位（如 `0x7A3f…A4bC`），保留大小写。
- 标签形式 `.addr-pill`（13 px 等宽、浅蓝底）+ 复制图标按钮；复制得到完整地址；完整地址放在 `title` 中，悬停可看。
- 表单中的只读地址用 `.field-static`，同样缩写并带 `title`。
- 用户输入地址的输入框显示用户输入的完整内容，不缩写。

### 4.5 卡片与只读信息

- `.card`：白底、1 px 描边、8 px 圆角、无阴影。卡片头 `.card-head`：标题 + 计数（`.sub`）+ 右侧操作。
- **平台通用只读字段** `.facts`：字段名在上、值在下，相距 4 px（`--sp-1`），字段上下内边距各 16 px（`--sp-4`），保留轻行线。字段名 13 px / 辅助色，值 14 px / 正文色；长标签和值完整换行，不以固定标签宽度挤压英文内容。
- `.facts-region` 容器宽度 ≥ 762 px 时排两列，列间距 32 px（`--sp-7`）；其余一列，默认宽屏也不扩为三列。短值字段较多的详情可加 `.cols-3`：容器 ≥ 900 px 时每行三项，窄于此宽度回到两列 / 一列；弹窗内成对的短值关键信息可加 `.cols-2`：容器 ≥ 420 px 即两列，避免 600 px 弹窗退回单列；长文本、文件名等用 `.wide` 跨整行。`.single` 固定单列，`.wide` 让长字段跨整行，`.inset` 用于已有内边距的容器。“上下结构”指字段内部关系，桌面仍可并排放两组字段。
- 此规则用于所有模块、角色的只读详情、关联信息及弹窗中的 `.facts`，资产详情不再是特例。表格、连接 / 状态摘要、偏好设置行和输入表单继续使用各自组件，保留其字段、顺序和操作。详情分组与表格组织见 [§4.16](#detail-presentation)。
- 用户信息用一张 `.profile-sheet`，按本次登录 / 个人资料 / 偏好设置分区。`.profile-section` 左侧为 120 px 分区标题，右侧内容中的只读字段复用通用上下结构；≤ 1100 px 分区标题移到内容上方。偏好设置保持 §4.11 的设置行，避免每个字段独立成卡造成留白。
- 身份摘要 `.ident`：首字标识 + 名称（20 px）+ 英文名 + 右侧状态标签，放在详情卡片顶部。
- 资料由外部平台维护时，在页面说明里写一句「这些信息由资产可信平台维护，本平台只读」，不在每个字段下重复。

### 4.6 数据表

- 表头 13 px、`--card-2` 底；行高由上下 12 px 内边距决定；首末列左右内边距默认与卡片一致（24 px），表格首列与卡片标题、筛选条同一左缘。密集列表变体（M2 资产列表、M4a 我的代币、M4b 代币台账，九至十列）首末列 16 px、中间列 8 px；卡片内缩的明细表 `.detail-table` 首末列 16 px。英文标签按完整单词换行，不在单词中间强制断开。
- **单元格对齐**：编号等文字链接（`.btn-link`）位于单元格或只读字段值开头时，文字与表头、字段名左缘对齐，`padding` 只承载悬停底色；操作列最右侧的 `.actlink` 文字与表头“操作”右缘对齐。状态标签单独占一格时与同行文字垂直居中，跟在其他内容之后才加 4 px 上间距。
- **换行**：表格单元格中文按词换行（`word-break: keep-all`，如“示例企业 A / 有限公司”），并用 `text-wrap: pretty` 避免末行只剩一两个字；放不下时状态标签仍可在词内断开，不撑破列宽。
- 列表单元格只展示该列对应的业务值，保持简洁；不追加行业、英文名、状态解释、可发起 / 不可发起及原因、重复标签等补充信息。限制、原因和上游变更等提示在对应详情或操作反馈中展示。时间的日期 / 时分属于同一字段值，允许用 `.cell-sub` 分行；时区放在列表表头。
- M2 按最新用户纠正，列表保留债务人与回款状态列，不增加资产类型列或筛选。进入本平台的资产已经完成确权，不在列表重复展示确权列；详情继续展示确权信息，运营详情保留后续撤销确权提示与真实状态。此列表呈现口径优先于旧 PRD 中列出确权列的说明，不改变业务校验。回款状态为未到期 / 已逾期 / 已结清，无法确定时单独展示“暂时无法确认”。结清和逾期的上游原始事实仍由业务系统保留与校验。发行状态列不叠加能否发起及其原因；允许的发起操作仍放操作列，完整原因在详情展示。
- 金额用 `.money`：数字采用正文无衬线字体与等宽数字特性（tabular nums），币种 `.ccy` 与数字基线对齐；表格 13 / 11 px、只读详情 14 / 12 px、金额摘要 28 / 14 px，币种使用辅助文字色，不与金额同大。不修改金额、精度与币种值。
- 时间用两行：日期 / 时间（副文本）；表格和计数用等宽数字，不改变原有数据。列表表头的时区为表头第二行（11 px、`--faint`、常规字重），各模块列表及内缩明细表统一。创建时间表头另行标注所选 IANA 时区。
- 操作列 `.col-act` 右对齐、固定在右侧，1280 px 下也必须可见。
- 页标题与导航入口为“企业账户”，卡片标题为“数币账户”；复用 `.facts.cols-3` 只读字段组，展示账户标识“登录地址”、区块链网络与数币地址。只有当前登录地址一条，不展示备注名、来源、创建/更新时间、默认标记或变更操作；上游换址后仅展示新地址，历史申请和代币保留原快照。
- 列表长名称 `.name-clip`：能放下时显示全名；列宽不足时单行保留开头和结尾，中间自动省略，不将名称截成不明缩写。`.name-prefix` 弹性缩小并用省略号，`.name-suffix` 保留末尾至多 8 个字素（约全名三分之一），空格与 Unicode 字符保持完整；通过 `title`、无障碍名称保留全名。悬停可查看，点击或 Enter / Space 用现有提示展示全名；详情继续展示完整名称。当前用于 M2 四张资产表的交易双方；其他字段保持所属组件约定，金额、币种、状态和操作不套用名称省略。
- 刚新增的行用 `.is-new` 浅主色底标出，同时弹出结果提示。

### 4.9 多步流程

- 步骤条 `.steps`：当前步主色实心圆，已完成步骤显示对勾，未开始为空心圆。
- 等待外部确认（钱包签名、调取身份）用 `.wait`：转圈 + 主说明 + 一行副说明。等待期间只保留「取消」。
- 登录只保留 L1（连接钱包）、L3（确认签名）、L4（等待插件钱包签名返回）。连接成功直接从 L1 到 L3；L3 的“确认签名”表示唤起插件钱包请求签名，进入 L4 等待；返回并验签通过后直接进入平台。六个业务环节不再逐项拆成独立画面，也不展示“1 / 6”等进度编号。
- 三屏共用 `.login-screen`，宽度以 480 px 的 L3 为基准，通过同一网格的内容尺寸保持等宽等高。标题、支持网络位置一致；小屏与中英文下随 L3 内容自然伸展，不用固定高度裁切内容。非当前屏保留 `hidden` 并设 `visibility:hidden`，不可见、不可聚焦；游客页面不参与此等高布局。
- 独立 L2、L5、L6、L7、L8 从源码与目录移除。身份读取中、读取失败、登录结束改为平台内容区的状态反馈；身份未确认或登录结束时不显示企业资料、业务菜单与消息入口。
- 登录入口文案为“使用在资产可信平台登记的钱包地址登录”；卡片最下方 `.network-support` 同行展示“支持网络：”与图标 + Ethereum。

### 4.10 弹窗与确认

- 结构：标题栏（标题 + 关闭）/ 内容 / 底栏（`--card-2` 底，按钮右对齐，主按钮在最右；「上一步」靠左）。
- 打开时焦点落在第一个输入框或主按钮；只有关闭操作的说明窗聚焦底栏关闭按钮。Tab 焦点留在弹窗内；Esc 与关闭按钮回到原页面并恢复触发按钮焦点。下拉菜单按 Esc 关闭后，焦点回到菜单入口。
- 页内确认：`data-overlay data-inline data-base="返回页面"` 沿用原有返回关系，但在内容区呈现，隐藏原内容，保留顶栏、面包屑与身份。它不是模态对话框，不锁定键盘焦点；确认区底栏 `.card-f` 与普通弹窗底栏共用间距与按钮层级。
- 标题文字单独放在 `.modal-title`，继续由 `aria-labelledby` 引用；语言入口和关闭按钮不混入对话框标题的可访问名称。`.modal-title` 无论用 `span` 还是 `h2` 都继承弹窗头的 16 px / 600，不使用浏览器默认标题字号。
- 弹窗内成对的关键信息统一用 `.facts.cols-2.inset`（M3b 通过并铸造第 2 步、重试，M4a 申请销毁，M4b 通过并销毁、解除监管）；只有一两项或长文本时用 `.single`。

### 4.11 偏好设置

- `.preferences` 按“语言 / 时区”两行排列；左边标签和说明，右边 280 px 原生下拉（36 px 高），行间分隔线。≤ 600 px 控件移到说明下方并占满宽度。与借贷平台管理端截图保持相同结构。
- 语言选项 English / 简体中文。首次无浏览器记忆时为 English，不读取浏览器语言。切换只替换展示文案，输入值、地址、备注名和正式企业 / 人名等业务值保留。
- 时区只在企业用户资料页显示，采用有效 IANA 标识。展示示例包含 UTC、Asia/Shanghai、Asia/Hong_Kong、Asia/Singapore、Europe/London、America/New_York，并补入浏览器推断出的有效时区。全部 `data-instant` 用同一时区格式化，原始 ISO 时间戳不变，列表表头及资料时间旁标注时区。
- 生产保存行为以 C-PROFILE-02 为准：每项改选即保存、保存中该项不可再次修改、不影响另一项、成功即时生效、失败恢复旧值；不发消息。原型补画保存中及失败两屏，正常操作仅提示“预览偏好已更新”，不伪装成真实账户保存。
- `display.js` 仅负责展示预览和当前浏览器的语言记忆；不模拟账户偏好、跨设备保存、请求时延或失败随机数。未接入接口时，时区预览只在本次打开期间保留，重新打开以浏览器时区初始化。

### 4.12 下拉菜单、消息入口与结果提示

- 下拉 `.dd-list`：8 px 圆角、阴影，菜单项 13 px，分组之间用分隔线。单选型下拉（如界面语言）用 168 px 的 `.narrow`，顶部有弱化标签，当前项浅蓝底并带对勾。点击外部或 Esc 关闭；同一时间只展开一个下拉。
- 消息入口 `.bell`：36 px 圆形，未读数用红色角标，未读为 0 时不显示数字，超过 99 显示“99+”；点击展开最近消息预览，见 [§12](#12-消息通知m7)。
- 结果提示 `.toast`：深色底，在屏幕底部居中显示约 2.4 秒，用于「已复制」「已保存」「账户已登记」等结果。

### 4.13 网络与币种标识

- 网络与币种名称前必须有对应图标，并保留可读名称。Ethereum 只用英文；币种用业务给定代码，如 ETH、USDT、USDC。图标不能替代名称。企业账户列表按 PRD 独立展示网络列，地址列只展示地址。
- 结构：`<span class="asset-label"><i data-asset="ETH"></i>Ethereum</span>`。币种组件相同，例如 `<span class="asset-label"><i data-asset="USDT"></i>USDT</span>`；由 `TP.boot` 转成 SVG。
- `.asset-icon` 默认 18 × 18 px，图文间距 6 px，保留原品牌配色；图标 `aria-hidden`、不可聚焦，由相邻文字提供身份。名称组保持不拆行。
- `asset-icons.js` 复用借贷平台现有资产库中的 ETH、USDT、USDC 原始 SVG（spothq/cryptocurrency-icons，CC0 1.0；来源版本和许可全文随代码及离线导出件保留）。未知币种使用中性圆形占位图标，同时必须展示真实币种代码。
- M1 当前只有 Ethereum 网络 / 地址，不存在币种字段；USDT / USDC 是可复用图形资产，不代表本模块支持它们，不在 M1 增加余额或币种选择。
- 覆盖登录支持网络与连接信息、企业账户网络列、只读网络表单、签名核对与编辑弹窗。其余模块接入时同样使用此组件。

### 4.14 资产信息（M2 起）

- **资产摘要** `.asset-sum`：左侧为应收账款金额（28 px 无衬线等宽数字 + 14 px 币种）与债务人、到期日；运营与监管视图另列债权人。右侧 `.status-grid` 以分隔线组织确权、回款、发行三个状态，去掉外层重复框。> 1100 px 时右侧状态区按标签内容取宽（每项至少 120 px，标签不换行），左侧金额区占剩余宽度；M2、M3a 资产引用与 M3b 关联资产共用此规则，均为确权、回款、发行三项。≤ 1100 px 摘要上下排列，≤ 600 px 状态为标签与值对齐的三行。满足发起条件使用浅灰说明条与绿色确认图标，主色留给主要操作；警告与异常保留语义色。
- **状态标签取值**：已确权 `ok`、已撤销确权 `danger`；未到期 灰、已结清 `ok`、已逾期 `danger`；可发行 `accent`、发行申请中 `warn`、已驳回 `danger`、已发行 `ok`；取不到的确权状态写“暂时无法获取”；无法确定的回款状态写“暂时无法确认”（Unable to confirm），用 `warn`，不归入正常值。归并和发起条件遵循 PRD，不在原型中编写状态计算。
- **发起条件** `.cond`：放在资产摘要卡底部。满足时 `.cond.ok`，写明“债权人已确权，满足发起条件”；不满足时 `.cond.no`，逐条列出全部原因；发行申请中、已发行时用默认 `.cond`，写说明并在右侧放去向按钮。运营和监管视图不放发起条件。
- **资产列表**：使用 `.tbl.auto.asset-list`，保留债务人、回款状态与发行状态；不增加资产类型列，不展示确权列。资产编号保持完整不换行，债务人 / 债权人名称使用下述中间省略组件。运营全平台、监管列表保留债权人；金额列表头为“资产价值”（英文 Asset value，值为应收账款金额与币种），`.num` 右对齐。资产编号用 `.btn-link.mono.asset-id` 作为详情主链接，目标与同行“查看”一致，“查看”保留。使用 `colgroup` 明确分配列宽（以英文表头与状态标签为基准）：企业及企业详情内表为编号 / 债务人 / 资产价值 / 到期 / 回款 / 发行 / 操作 = 14 / 20 / 13 / 12 / 13 / 15 / 13%；含债权人的列表为编号 / 债权人 / 债务人 / 资产价值 / 到期 / 回款 / 发行 / 操作 = 13 / 16 / 17 / 12 / 11 / 11 / 13 / 7%。避免单一名称列占满剩余空间。到期日必须展示已有值：日期 / 时分，表头标注当前 IANA 时区；源 HTML 保留日期文本，运行时再按所选时区格式化，不以空白表示有值字段。
- **上游变更提示**（只在运营端）：列表移除编号下方的额外提示，详情页头上方保留 `.note.red.banner`“上游已撤销确权”“上游已删除”，说明本平台不自动处理；详情摘要的确权状态仍展示“已撤销确权”，列表不再保留该列。不改变业务状态与处理规则。
- **详情分区标签** `.detail-nav`：结构、视觉、定位及焦点规则统一见 [§4.16](#detail-presentation)。M2 标签使用 `data-nav-label` 短名：交易双方、销售订单、货物交付、销售发票、回款进度、上游供应商、债务人下游客户；关联记录存在时另提供对应入口，不增加“资产概览”标签。
- **详情分组** `.detail-group`：标题层级、上下字段与间距统一见 [§4.16](#detail-presentation)，M2 的业务内容按下列两组组织：
  - 核心信息（债权人与债务人）：应收账款与交易双方、销售合同 / 订单、货物交付、销售发票、回款进度，各一张卡片，按业务发生顺序排列。
  - 补充信息（债权人与上游供应商，债务人与其下游客户）：“与上游供应商”一张卡片，内含采购合同 / 订单、供应商发货、采购发票、向供应商付款四个小节；“债务人与其下游客户”一张卡片（本企业不是交易一方），每笔交易一个小节（客户名称 + 注册国家 / 地区为小节标题，下接订单、交付与回款记录），卡片副标题写笔数及“回款不计入本笔应收账款”。
- **缺失值**：L1 缺失用 `.missing` 写“上游未提供”；L2 缺失用 `.missing.soft` 写“未提供”；整组或整表没有时用 `.sub-empty` 写一句说明（如“暂无回款记录”“暂无采购发票”“暂无债务人下游客户交易信息”），不画空表。补充信息整项没有时写“暂无…”，不标为缺失。
- **卡片内小节** `.sub-h` / `.card-sec`：采用 [§4.16](#detail-presentation) 的小节标题与分隔规则，M2 用于债权人 / 债务人、供应商采购 / 发货 / 发票 / 付款及各笔债务人下游交易。
- **详情记录表** `.detail-table`：标的物、发票、付款与回款记录统一采用 [§4.16](#detail-presentation) 的内缩表格，与上下字段区分；保留原记录内容和文件操作。
- **文件引用** `.file-ref`：材料随所属环节展示，不设独立材料分组。单个文件作为字段值（如确权凭证、合同文件、运输单据、交付凭证、发货记录）；逐张 / 逐条对应的文件放在该行表格的文件列（发票文件、支付凭证、付款凭证）。形式为文档图标 + 等宽文件名链接（查看）+ 下载图标按钮（带 aria-label）。打开失败用弹窗说明“本次未能打开”，可重试。
- **列表筛选条** `.asset-filters`：以 WS-508 用户提供的筛选截图为视觉基线，替换 v1.8 的胶囊及固定双行排布。本条为筛选条的权威样式，业务字段按所属模块 PRD 确定。
  - 工具栏：左侧常用下拉与“更多筛选”，右侧带搜索图标的输入框、文字型重置、主色查询按钮。中间以弹性留白分组；可用宽度不足时自然换行，不缩小字号或裁切操作。

  - 搜索：桌面首选 320 px，最小 200 px，可按可用宽度收缩；图标 16 px、距左 12 px、输入左内边距 36 px。占位符说明搜索对象，保留独立无障碍名称。M2 为资产编号精确匹配；债务人名称仍是独立条件，不合并成语义不明的统一搜索。
  - 更多筛选：浅底弱按钮，配展开箭头；默认收起，点击后在工具栏下方展开带标签的字段区，不遮挡列表。再次点击或在区内按 Esc 收起，条件保留；展开时焦点到首个输入框，Esc 后回到触发按钮，隐藏字段退出键盘顺序。用 `aria-expanded` / `aria-controls` 表达状态。有已填条件时触发按钮显示蓝色提示，该表现仅表示字段有值，不表示查询已执行。
  - 展开区：文本 / 下拉控件沿用相同的 36 px / 6 px 规格，标签在上；普通字段以 184 px 为基准横排，日期范围按两个 214 px 控件及间距占位；到期范围不再强制独占一行，一行容纳不下才换行。所有控件底边对齐，标签在上，日期范围保留当前时区；窄屏按单列排列。重置同时清空工具栏与展开区，恢复默认选项，不强制收起展开区。
  - M2 字段映射：左侧发行状态、回款状态；右侧资产编号；展开区为债务人名称、币种、到期范围，运营全平台与监管列表另有债权人名称。企业自己的资产和企业详情内资产不重复提供债权人条件。币种仅取当前列表演示数据已有币种，初始均为空 / 全部；不增加资产类型条件。
- **筛选原型边界**：控件可输入、可选择，重置使用原生表单；查询只显示原型说明，不改变结果。筛选匹配、日期范围校验、无匹配 / 失败结果与跨时区范围保持由 PRD §5.6 定义，未在原型内模拟，不新增画面或状态分支。
- **企业检索** `.searchbar`：继续保留企业名称 / 登记标识查找，不改成资产筛选；原有无结果画面继承。
- **可点击面包屑**：资产 / 企业详情按 §3 全平台约定由面包屑返回原列表；`data-crumb-targets` 显式指定已有画面，不猜测路由。
- **英文排版**：所有通用只读信息采用 §4.5 的上下字段结构，不再区分中英文标签列宽；保留原文业务值和原有双语名称，不自动翻译企业、人名、地址等上游内容。金额的字体与正文一致，编号与地址继续等宽。系统字体栈增加可靠的拉丁字母回退，不增加联网字体。
- **时间**：日期类字段用 `<time data-day>` 只显示换算后的日期；到期日显示完整日期时间；列表用 `data-compact`。详情页说明行与列表表头标注当前时区；详情页的只读字段不在每个时间后重复时区。弹窗等看不到页头说明行的位置，时区作为时间下方 12 px 副文本。
- **法币识别**：金额摘要前展示 24 px 的对应币种图标，金额仍为 28 px、代码 14 px；“币种”字段采用 18 px 图标 + ISO 币种代码（USD / EUR），图标不代替文本。复用借贷平台已有 HatScripts/circle-flags 图形（USD / EUR，MIT），保留来源、版本和许可证。每次内联生成独立 mask ID，避免多画面重复引用。其他金额单元格继续保留原数值、精度与代码，避免重复装饰。
- **资产分页** `.asset-pagination`：采用明确页码，左侧总记录数、右侧上一页 / 当前页 / 下一页。用于资产查找和审核核对，便于定位与返回；不使用滚到底部自动追加或下拉更换整页数据。当前演示数据均不足一页，显示真实条数与第 1 页，前后页禁用；不虚构更多资产或实现分页数据计算。生产查询、页大小及总数由正式数据服务承接。
- **关联申请**：企业端与管理端资产详情的“关联记录”卡片统一写法——发行申请编号为 `.btn-link.mono`，旁边为申请状态标签（企业端按 M3a 用词，管理端按 M3b 用词）；编号进入匹配的申请详情（企业端 M3a，运营 / 监管 M3b），没有匹配画面的编号只展示、不做链接。

### 4.15 响应式

- > 900 px：238 px 侧栏、内容左右各 24 px；`--content-max: none`，面包屑与主体占满侧栏以外的可用内容宽度，左边线对齐。宽屏不再叠加 1200 px 居中限宽产生的两侧留白。此规则共用于面客端、运营端及监管端。
- 内容容器铺开不改变内部字段、控件和说明文本的既有宽度约束；登录 L1 / L3 / L4 独立卡片继续按 L3 等宽等高规则呈现。
- 601–900 px：侧栏 180 px、内容左右 16 px；表格最小宽度 800 px，在表格容器内横向滚动，操作列固定右侧。
- ≤ 600 px：品牌与导航在顶部，原有菜单按原顺序横向滚动；顶栏仍保留语言、消息、账户。资料单列，页头操作可换行，弹窗左右留 12 px，内容可纵向滚动，底栏按钮可换行。
- 登录保持水平居中卡片，小屏左右 16 px、卡片内边距 24 px；不加载网络字体。尊重 `prefers-reduced-motion`，键盘焦点使用既有 2 px 主色轮廓。

### 4.16 详情页展示结构

本节从 WS-508 已确认的展示要求提炼通用详情呈现规则；只读字段统一遵循 §4.5，所有模块、角色及弹窗复用 `.facts` 即生效。具体业务分组、摘要、关联记录和操作保留模块原有语义；M2 的业务内容示例见 §4.14。样式来源为 [`components.css`](../components.css)，资产分区定位来源为 [`asset-detail.js`](../asset-detail.js)，取值沿用 [`tokens.css`](../tokens.css)。

#### 页面阅读顺序

面包屑 → 页面标题与业务操作 → 金额 / 状态摘要及相关提示 → 分区导航 → 关联记录（存在时）→ 业务信息分组及卡片。原有权限差异、披露与业务顺序保留，材料随对应环节展示。

M2 的业务信息按“核心信息 / 补充信息”纵向排列，具体交易双方和卡片内容见 §4.14。分组标题位于卡片外，卡片标题位于卡片头，小节位于卡片内；导航标签只负责定位。页面主操作放在页头，摘要内的去向操作沿用既有入口。

#### 标题、字段与导航层级

| 角色 | 组件 | 规格与用途 |
| --- | --- | --- |
| 页面标题 | `.page-title` | 24 px / 600，标识当前业务记录 |
| 分组标题 | `.detail-group-h h2` | 20 px / 650，`--text`；必须大于下属卡片标题，如“核心信息” |
| 卡片标题 | `.card-head h2/h3` | 16 px / 600，标识具体环节，如“销售合同 / 订单” |
| 内部小节 | `.asset-detail .sub-h` | 14 px / 600，区分卡片内部的信息组 |
| 分区导航 | `.detail-nav a` | 14 px / 500、辅助色；当前项用 `--accent`、650 字重，表示当前位置 |
| 字段名 / 辅助说明 | `dt` / `.sub` | 13 px、`--muted`，不与分组标题争抢重点 |
| 字段值 | `dd` | 14 px、行高 1.6，保留完整内容 |

分组标题与导航起点、卡片外缘对齐；分组之间留 40 px，分组标题到卡片留 16 px。卡片内边距 24 px，小节用标题与轻分隔线组织，避免在卡片内继续套卡片。标题允许英文换行，保持层级，不为容纳长文缩小字号。

#### 上下字段与明细表

- **只读字段**：统一复用 §4.5 的通用 `.facts`，包括用户中心、业务详情、关联记录和弹窗。字段名在上、值在下，间距 4 px；字段行上下内边距各 16 px。默认容器 ≥ 762 px 时两列、其余一列；短字段分区可选 `.cols-3`，容器 ≥ 900 px 时三列，762–899 px 两列、更窄一列；列间距统一 32 px。`.single` 固定单列，`.wide` 在所有列数下跨整行；跨行字段之后的新行保留轻分隔线。资产详情继承通用规则，不另设标签宽度或模块私有断点。
- **重复记录**：标的物、发票、付款、回款等使用 `.tablewrap.detail-table`，与上下字段分开承载。卡片内缩 24 px、底部留 20 px，细边框与 6 px 圆角；浅底表头 13 px / 600，正文 13 px，单元格上下内边距 12 px，逐行分隔。首尾内边距 16 px，金额和数量右对齐。窄屏仅表格内部横向滚动，保留全部列和操作。
- **金额与币种**：资产摘要采用 24 px 对应币种图标 + 28 px 金额 + 14 px 币种代码；币种字段为 18 px 图标 + ISO 币种代码。图标不代替文字，金额保留原值、精度和币种。文件引用、缺失提示与时间 / 时区沿用 §4.14，信息可读性不改变业务事实。

#### 展示文案

- 发行入口统一“申请发行”，英文为“Apply for issuance”；条件提示使用“不能申请发行”等一致措辞，流程与限制沿用原规则。列表多操作纵向排列，可按列宽换行，保证文字与点击区域可达。
- 用户可见的资产标识统一“资产编号 / Asset ID”，用于列表表头、筛选无障碍名称、只读字段及关联模块，不展示“上游”前缀；原资产编号、数据来源及接口字段含义保持不变。

#### 无框分区导航

资产详情的 `.detail-nav` 位于摘要之后、信息内容之前；没有摘要的企业详情位于页头之后。标签栏沿用页底色，无外框、圆角和组间竖线；底部增加 1 px `--border` 分隔线，贯穿整栏以区分下方内容，组间通过留白区分。当前项继续用主色和字重标识，分隔线不作为单项选中指示；使用短标签，卡片保留完整标题。

这是连续页面的锚点导航，所有分区保持展开。点击滚动到对应卡片并将焦点移入，页面滚动同步高亮；使用 `aria-current="location"` 和可见键盘焦点，不改画面路由。吸顶偏移随顶栏实际高度更新（桌面基线 68 px），不得遮住目标标题；点击每组首项时保留组标题可见。页尾无法顶对齐时保留所点项选中，不添加无意义空白。窄屏标签栏自身横向滚动。

## 5. 原型轻量化约定

原型只告诉前端两件事：页面怎么布局，展示哪些信息。规则、校验与异常分支写在 PRD。

**原型包含：**

- 页面 × 主状态的静态画面：每个页面一个默认、一个空、一个代表性异常；身份或阶段不同且布局或可用操作随之变化时，单独出一屏；多步流程每一步一屏。
- 规则生效后的结果：字段是否可编辑、按钮是否可用及原因、必填与格式提示、一个错误示例出现的位置、状态标签、关键后果说明。
- 主流程逐屏可走；其他按钮只表现可用或不可用。

**原型不包含：**

- 业务校验、计算、状态机、账户存储、演示时钟、故障注入或引导式走查。语言记忆和时间格式化只是展示功能。
- 页面上的规则编号、字段来源、设计理由。
- 真实钱包 / 接口、账户偏好持久化、跨设备同步或主题切换；中英文即时切换、浏览器语言记忆、展示时区换算及完整地址复制已可操作。

**评审工具：** 右下角「画面目录 · 演示数据」按钮，默认关闭。展开后按「页面 → 状态」列出全部画面，并提供「主流程下一屏」。画面中的企业、地址、邮箱、编号均为演示数据。

**文件约定：**

- 源码：`页面原型/面客端/<PRD 模块号>-<模块名>/<模块名>.html`（管理端放在 `页面原型/管理端/`），只写画面内容，引用 `../../_shared/` 下的公共层。模块号与 PRD 一致（M1、M2、M3b、M4a…）；同一模块两端都有画面时两端各一个目录、模块号相同。
- 菜单：企业端引用 `menu.client.js`，管理端引用 `menu.admin.js`，放在 `frame.js` 之后。模块 HTML 不再定义 `TP.NAV` / `TP.NAV_BY`；模块内菜单落地仍由本模块 `TP.routes` 登记。
- 仓库联看登记：模块目录内的 `route.js` 调用 `TP.registerModule`，`_shared/modules.js` 每个模块一行。
- 每屏是一个 `<section data-screen>`，用 `data-*` 声明骨架、身份、菜单、面包屑、所在弹窗的底层画面和主流程下一屏；约定写在 `frame.js` 文件头。
- 评审件：用 `_shared/export.py` 生成单文件，作为附件交付，不入库。

### 5.1 仓库联看与单模块附件

- **入口**：完整同步 `页面原型/`，双击 `index.html` 选择端与身份，或直接双击任一模块 HTML。画面目录（默认关闭）顶部提供「企业端 / 管理端」及身份切换，只在仓库联看出现，不进入产品界面。
- **仓库联看**：源码引用 `<script src="../../_shared/navigation.js" data-local-only></script>`，放在 `frame.js` 之后、模块 `TP.boot` 之前，明确启用 `repository` 模式。沿用真实侧栏和账号菜单，同一标签页通过相对文件路径和画面锚点跳转，不要求本地服务、联网请求、iframe 总览或全平台合并文件。画面目录仍独立且默认关闭。
- **单模块附件**：`export.py` 排除带 `data-local-only` 的脚本，明确设置 `module` 模式，再内联本模块必需的公共样式与脚本。附件直接进入所属模块，不加载其他模块；跨模块入口继续显示范围提示。不得只根据 `file://` 判断模式，也不得在附件中保留对仓库路径的依赖。
- **维护与体积**：跳转代码只在 `navigation.js` 维护一份；它读取 `modules.js`，再按顺序加载各模块目录的 `route.js`（解析阶段同步加载，`file://` 可用）。路由由所属模块登记，新增模块只增加自己的目录和 `modules.js` 一行，不修改其他模块或 `navigation.js`，以减少并行分支冲突。不复制其他模块 HTML、样式或演示数据，不预加载其他模块画面。导出件不包含 `navigation.js`、`modules.js`、`route.js`；交付核对源码及生成件的实际字节增量。
- **登记与身份**：`route.js` 写明 `id`、`end`（client / admin）、`file`、`routes`，必要时写 `variants`（停用机构、改邮箱等沿用同一角色画面的展示变体）。路由按端、菜单/操作键和身份对应的画面 ID 登记，同一端的 key 不得重复。端与身份切换的落地为：企业端未登录 `signIn`、已认证 `assets`、未认证 `org`；管理端未登录 `signIn`、运营与监管 `review`。仅登记当前分支已交付且实际存在的文件与画面；每个身份明确指定目标，不回退成另一角色。模块内路由和未认证受限画面优先，跨模块路由只补已有模块间的连接。无权限、游客、首登受限等画面的既有入口限制保持不变。
- **展示上下文**：跨模块传递现有演示身份、语言和有效 IANA 时区；监管机构停用及变更邮箱示例保持对应身份画面。`previewLang` / `previewZone` / `previewWho` / `previewBase` / `previewGate` 只定位展示，不携带业务记录、凭据或令牌，不作为生产登录与权限依据。地址中的展示偏好随当前选择更新，刷新后保留；确认画面保留底页与返回关系。
- **未交付模块与未出屏记录**：未交付模块的入口保留范围提示，不创建空链接或伪造业务页面。编号只在有匹配记录画面时做成链接（`data-module-key` 或 `data-go`），没有对应画面的编号用 `.mono` 纯文本展示；不能用任意列表或其他记录代替。跨模块按钮同时保留 `data-toast` 作为附件中的提示。 登录画面的 `data-module-key` 可加 `data-module-who` 指定登录后的身份（仅未登录画面生效），例如 M5 登录成功后进入该角色的「发行审核」。单模块附件中的跨模块兜底提示统一为“此入口在单模块附件中不展开，请在完整原型的 index.html 中打开。”；仓库联看中如仍有未登记入口，`frame.js` 改为提示“该入口尚未纳入原型。”。演示文件统一提示“演示文件，不提供真实文件。”，中英文由 `display.js` 统一提供。
- **新增或修订模块的检查**：登记对应文件及真实画面，验证鼠标与键盘切换、双向跳转、刷新与浏览器返回、身份/菜单/展示偏好、确认取消与未交付提示；重新导出单文件，在断网环境核对无外部依赖、无跨模块文件请求、原有画面目录及主流程可用。规则、校验与异常分支仍以 PRD 为准。

## 12. 消息通知（M7）

- **消息入口** `.dd.inbox`：顶栏铃铛 `.bell.dd-btn` + 未读角标。点击展开 400 px 的 `.inbox-panel`（`role="region"`）：“最近消息”标题 → 最近 10 条（已读、未读都包括）`.msg-item.compact` → 底部“查看全部消息”。预览不放全部已读，只打开预览不改变已读。没有消息、读取失败分别用 `.state`、`.state.err`；读取失败时角标保留原数字。点击外部、再次点击铃铛或 Esc 收起，焦点回到铃铛；预览内空白处点击不收起。
- **所有模块共用**：模块 HTML 在菜单脚本之后、`navigation.js` 之前加载 `inbox.js`，由 `frame.js` 渲染；未读数取 `TP.inbox` 演示数据，画面可用 `data-unread` 指定本屏的值，`data-inbox="open|empty|error"` 让该画面展开预览（底层为所在页面）。仓库联看中，预览的单条消息与“查看全部消息”进入 M7 对应画面（`msg-<id>` / `msg` 路由由 M7 的 `route.js` 登记），单模块附件给范围提示。
- **消息条目** `.msg-list > li > button.msg-item`：未读圆点 + 标题（未读加粗）→ 分类 + 原业务识别信息（等宽编号，只展示不做链接）→ 摘要（列表两行、预览一行截断）；右侧为阅读状态标签（未读 `.tag.accent`、已读灰）与发生时间（`data-minute`，日期 + 时分）。预览宽度有限：时间移到摘要下方，原业务识别信息只显示编号，字段名留给读屏。整行进入详情，阅读状态同时由标签表达，不只靠颜色。
- **中英文内容**：来源为每条消息提供两套标题与正文，用 `.lang-zh` / `.lang-en` 并列，按 `<html lang>` 只显示一套；驳回意见等用户填写的原文、企业与机构名称不翻译。
- **消息列表页**：页头“消息通知” + 时区说明；卡片顶部沿用 `.asset-filters`：左侧 `.seg`（全部 / 未读 / 已读，改选即生效）+ 分类下拉（“分类 · 全部”加本人实际有消息的分类），没有查询按钮；右侧 `.inbox-actions` 放“全部已读”，作用于当前筛选，当前筛选没有未读时 `aria-disabled`，并在按钮左侧写明原因。列表底部 `.msg-more`：加载更多 / 没有更多消息了 / 加载失败（保留已加载内容 + 重试）。从未收到消息不显示筛选条；筛选无结果给“清除筛选”。
- **全部已读确认**：480 px 弹窗，写明将标记的未读条数（含尚未加载）→ `.facts.cols-2.inset` 列出当前已读状态与分类 → `.note.accent` 写明只改变本人阅读状态、不代表业务已处理（运营另写不影响其他运营）→ 取消 / 标为已读。处理中用 `.wait`，按钮与关闭禁用；失败用 `.note.red`，主按钮为“重试”；成功回到列表，结果提示写实际条数。
- **消息详情**：面包屑“消息通知 / 消息详情”，消息不在侧栏菜单中，不选中任何菜单项。标题行为消息标题 + 分类标签，说明行为发生时间与时区；卡片内为完整正文 `.msg-body`（纯文本，保留换行）和“相关业务”小节。目标记录的编号 `.btn-link.mono` 即前往原业务的入口，与平台“编号即入口”一致；去向为本端固定页面时用文字按钮（如“前往用户信息”）；原业务不可访问时编号只展示，并加 `.note`“相关内容暂不可访问。”；不跳转的消息没有该小节。已读保存失败用 `.note.warn.banner` + 重试，正文照常显示。
