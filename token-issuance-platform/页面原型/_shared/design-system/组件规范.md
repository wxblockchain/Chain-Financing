## 1. 取值基线

配色与控件尺寸以借贷平台运营端的实际生效值为基线，M1 的字号、信息排版与响应式已按本轮 UI 设计调整。基线来源为 `cly-v6.0.0` 分支的 `lending-platform/页面原型/_shared/tokens.css` 与 `base.css`（含 `[data-end]` 覆盖层）。以下是与借贷平台的差异，均为有意调整：

| 项 | 借贷平台 | 本平台 | 原因 |
| --- | --- | --- | --- |
| 字体 | 内嵌 Geist + Noto Sans SC 子集（约 340 KB） | 系统字体栈，拉丁字母优先 Arial / Liberation Sans / system-ui，中文按字形回退 | 轻量化，不嵌入字体文件 |
| 地址与哈希字体 | 与正文同字体 | 等宽字体 | 缩写地址的首尾字符更易辨认 |
| 钱包地址 | 详情完整、列表缩写 | 一律缩写，悬停看完整地址，可复制 | 用户确认 |
| 面包屑 | 内容区 | 内容区（不进顶栏） | 用户确认 |
| 语言、暗色市场主题、官网层 | 有 | 中英文即时预览，语言记忆在当前浏览器；无暗色与官网层 | 当前 M1 画面范围 |
| 信息排版 | 标签和值横向排列 | 详情页与弹窗均为紧凑横向；窄屏改为上下 | 减少留白，保持标签与内容接近 |
| 组件密度 | 面客端与运营端两套覆盖 | 一套 | 两端共用同一组件规格 |

## 3. 骨架

| 骨架 | 用在哪里 | 构成 |
| --- | --- | --- |
| app | 登录后页面、游客引导、平台状态反馈 | 左侧栏（品牌 + 分组菜单）+ 顶栏（右侧依次为界面语言、消息入口、账户入口）+ 内容区（上 24、左右 24、下 56 px；面包屑在内容区顶部） |
| focus | 未登录的 L1 / L3 / L4 | 顶部品牌条（右侧放界面语言）+ 水平居中、上方留 56 px 的卡片（480 px；内容多时用 `.wide` 600 px） |

- G1 使用 app 的内容区、面包屑、页标题和常规卡片；顶栏保留语言与账户入口。游客不显示业务菜单、消息或时区设置，不因切换骨架获得业务权限。
- G2 在当前平台内容区展示确认卡片（`.card-b` + `.card-f`），替代原页面内容，不使用全屏遮罩或独立登录卡片；取消 / Esc 返回发起处。企业认证引导共用该确认时也保留原企业页面与身份。
- 菜单按产品信息架构分组，只放真实去向。面客端为「业务」（可信资产、代币发行、我的代币、销毁申请）和「用户中心」（企业账户、企业信息、用户信息）。没有首页或工作台。
- 管理端沿用同一 app 骨架，品牌副标题为「管理端」，菜单按 M5 菜单权限矩阵分角色：运营为「业务」（发行审核、销毁审核、代币台账、可信资产、企业）和「系统管理」（监管机构管理、合约管理）；监管机构只有「业务」（发行审核、解除质押、代币台账、可信资产）。模块用 `TP.NAV_BY[身份]` 给出菜单。
- 管理端账号入口：胶囊显示账号名称；展开菜单 240 px，依次为名称、登录邮箱、角色标签（监管机构另附所属机构），再是账户设置与退出登录。由 `TP.demo.accounts[身份]` 提供。
- 菜单选中：主色浅底 + 左侧 3 px 主色标记 + 600 字重；菜单最小高度 44 px。品牌标识保持水平，不旋转。需要认证才能使用的菜单，在未认证时右侧显示锁形标记，菜单仍可点击。
- 面包屑放在内容区顶部、页面标题上方，不放进顶栏；格式为「分组 / 页面」，当前页加粗。
- 账户入口：圆角胶囊，显示缩写地址。展开菜单宽 208 px，只保留缩写地址与复制、退出登录，不显示企业名称或“登录地址”标签。左侧菜单已有的页面、顶栏已有的消息入口，不在账户入口里重复。游客只有地址和退出。
- 界面语言：顶栏地球图标 + 当前语言下拉，菜单顶部有“语言”，选项为 English / 简体中文，选中项浅蓝底并带对勾。未登录、游客、企业用户均可切换。弹窗标题栏另有 36 px 地球图标入口，打开表单后仍可切换且不重建输入控件。

## 4. 组件

### 4.1 按钮

| 类型 | 类名 | 用法 |
| --- | --- | --- |
| 主按钮 | `.btn.primary` | 每屏一个主操作，放在页头右侧或弹窗底栏最右 |
| 次按钮 | `.btn` | 取消、重试、复制等 |
| 幽灵按钮 | `.btn.ghost` | 弱操作，如「上一步」「取消」 |
| 危险按钮 | `.btn.danger` | 只用在删除确认弹窗的主按钮位 |
| 紧凑按钮 | `.btn.sm` | 提示条、空状态行内的操作 |
| 图标按钮 | `.btn.icon` | 复制、关闭；必须有 `aria-label` |
| 文字链接 | `.btn-link` / `.actlink` | 行内跳转 / 表格操作列 |

- 管理端详情中的发行申请编号本身作为唯一跳转入口，使用 `.btn-link.mono`；编号旁不重复放“查看申请”。沿用原有目标去向及交互反馈。

- **信息旁的微操作**：密码显隐、复制、附件下载/移除、关闭使用图标按钮，不用“显示 / 隐藏”“复制邮箱”等文字按钮；按钮至少沿用 36 px 热区，具备说明动作的 `aria-label`、同义 `title` 和可见键盘焦点。图标设置 `aria-hidden="true"`。复制完整值、显隐输入、关闭与返回关系沿用既有行为。
- **文件查看**：点击文件名本身；旁边仅放下载图标，编辑附件时放移除图标。文件名过长可换行，不复制一份文字“查看”。上传入口、查询、保存、下一步、启停、更正邮箱及业务表格的“查看”等仍用明确文字承载任务，不把业务主操作一律图标化。
- 通用不可用按钮用 `aria-disabled="true"` 或 `disabled`，并有可见说明。企业账户列表的“删除”是例外：每条均可点击，能否删除及原因只在二次确认弹窗展示，列表不预先标注。

### 4.2 表单

- 结构：`.field` > 标签 + 控件 + 提示或错误。标签 13 px 在上；必填在标签前加红色 `*`。
- 有长度上限的文本框，在标签行右侧显示计数，如「6 / 100」。
- 格式要求写在占位符或输入框下方的提示里，如「0x 开头，共 42 位」「登记后不能修改」。
- 错误：输入框红色描边（`aria-invalid="true"`）+ 下方一行红字说明原因；能给出去处时，在错误后加文字链接（如「查看已有账户」）。原型每个表单只画一个错误示例。
- 只读值用 `.field-static`：浅底、虚线框，不伪装成可编辑选择框。新增账户字段顺序固定为区块链网络（图标 + Ethereum，只读）→ 数币地址 → 账户备注名；打开时焦点在地址输入框。

列表筛选条统一按 §4.14 的矩形控件、左右分组与展开区规范实现；普通录入表单仍沿用本节规格。

### 4.3 状态标签

`.tag` 加语义类：`ok`（已认证等成功状态；数币账户不再展示验证状态）、`warn`（审核中等待处理）、`danger`（失败、驳回）、`accent`（身份标记，如「登录地址」）、默认灰（中性）。在身份摘要中可带圆点 `.dot`。

### 4.4 钱包地址

- 所有展示位置一律缩写：前 6 位 + … + 后 4 位（如 `0x7A3f…A4bC`），保留大小写。
- 标签形式 `.addr-pill`（13 px 等宽、浅蓝底）+ 复制图标按钮；复制得到完整地址；完整地址放在 `title` 中，悬停可看。
- 表单中的只读地址用 `.field-static`，同样缩写并带 `title`。
- 用户输入地址的输入框显示用户输入的完整内容，不缩写。

### 4.5 卡片与只读信息

- `.card`：白底、1 px 描边、8 px 圆角、无阴影。卡片头 `.card-head`：标题 + 计数（`.sub`）+ 右侧操作。
- 只读信息 `.facts`：标签 120 px + 值，横向间距 12 px，上下内边距 12 px；内容区宽度 ≥ 762 px 时排两列。`.single` 固定单列，≤ 600 px 改为标签在上、值在下。
- 用户信息用一张 `.profile-sheet`，按本次登录 / 个人资料 / 偏好设置分区。`.profile-section` 左侧为 120 px 标题，右侧为内容；资料区标签 104 px。≤ 1100 px 标题移到内容上方，减少多个卡片造成的留白。
- 身份摘要 `.ident`：首字标识 + 名称（20 px）+ 英文名 + 右侧状态标签，放在详情卡片顶部。
- 资料由外部平台维护时，在页面说明里写一句「这些信息由资产可信平台维护，本平台只读」，不在每个字段下重复。

### 4.6 数据表

- 表头 13 px、`--card-2` 底；行高由上下 12 px 内边距决定；首末列左右内边距默认与卡片一致（24 px），密集资产列表首末列 16 px、中间列 8 px。英文标签按完整单词换行，不在单词中间强制断开。
- 列表单元格只展示该列对应的业务值，保持简洁；不追加行业、英文名、状态解释、可发起 / 不可发起及原因、重复标签等补充信息。限制、原因和上游变更等提示在对应详情或操作反馈中展示。时间的日期 / 时分属于同一字段值，允许用 `.cell-sub` 分行；时区放在列表表头。
- M2 按最新用户确认，列表仅展示回款、发行两个独立状态列，一列只展示一个状态值。进入本平台的资产已经完成确权，不在列表重复展示确权列；详情继续展示确权信息，运营详情保留后续撤销确权提示与真实状态。此列表呈现口径优先于旧 PRD 中列出确权列的说明，不改变业务校验。回款状态为未到期 / 已逾期 / 已结清，无法确定时单独展示“暂时无法确认”。结清和逾期的上游原始事实仍由业务系统保留与校验。发行状态列不叠加能否发起及其原因；允许的发起操作仍放操作列，完整原因在详情展示。
- 金额用 `.money`：数字采用正文无衬线字体与等宽数字特性（tabular nums），币种 `.ccy` 与数字基线对齐；表格 13 / 11 px、只读详情 14 / 12 px、金额摘要 28 / 14 px，币种使用辅助文字色，不与金额同大。不修改金额、精度与币种值。
- 时间用两行：日期 / 时间（副文本）；表格和计数用等宽数字，不改变原有数据。账户备注名列占 20%。创建时间表头另行标注所选 IANA 时区。
- 操作列 `.col-act` 右对齐、固定在右侧，1280 px 下也必须可见。登录地址行只有删除，企业新增行显示编辑与删除；不得把受限删除预先禁用。
- 页标题与导航入口为“企业账户”，卡片列表标题为“数币账户”并带数量。列表列序：账户备注名 / 区块链网络 / 数币地址 / 来源 / 创建时间 / 操作；网络列为图标 + Ethereum；不再有验证状态列。
- 刚新增的行用 `.is-new` 浅主色底标出，同时弹出结果提示。

### 4.7 提示条

| 类型 | 类名 | 用法 |
| --- | --- | --- |
| 说明 | `.note` | 填写前需要知道的限制 |
| 重要说明 | `.note.accent` | 签名用途、关键后果 |
| 警示 | `.note.warn` | 当前受限、需要用户处理的情况 |
| 错误 | `.note.red` | 操作失败的原因 |

- 左侧 3 px 色条 + 图标 + 一段话；可在右侧放一个 `.btn.sm`。
- 页面级提示条（`.banner`）放在页头上方或下方，只用于影响整页的情况，如钱包地址与登录地址不一致、认证未通过。

### 4.8 区块状态

`.state` 用在卡片内，替代整块内容：

| 状态 | 类名 | 内容 |
| --- | --- | --- |
| 空 | `.state` | 图标 + 标题 + 一句说明；有去处时加按钮 |
| 读取失败 | `.state.err` | 「××读取失败」+「暂时无法读取，请稍后重试」+ 重试按钮；不能显示成空 |
| 受限 | `.state.gate` | 锁形图标 + 受限原因 + 前往处理的主按钮 |

列表只有系统默认项时，用 `.inline-empty`：在表格下方加一行虚线分隔的说明和新增按钮，不清空表格。

### 4.9 多步流程

- 步骤条 `.steps`：当前步主色实心圆，已完成步骤显示对勾，未开始为空心圆。
- 等待外部确认（钱包签名、调取身份）用 `.wait`：转圈 + 主说明 + 一行副说明。等待期间只保留「取消」。
- 登录只保留 L1（连接钱包）、L3（确认签名）、L4（等待插件钱包签名返回）。连接成功直接从 L1 到 L3；L3 的“确认签名”表示唤起插件钱包请求签名，进入 L4 等待；返回并验签通过后直接进入平台。六个业务环节不再逐项拆成独立画面，也不展示“1 / 6”等进度编号。
- 三屏共用 `.login-screen`，宽度以 480 px 的 L3 为基准，通过同一网格的内容尺寸保持等宽等高。标题、支持网络位置一致；小屏与中英文下随 L3 内容自然伸展，不用固定高度裁切内容。非当前屏保留 `hidden` 并设 `visibility:hidden`，不可见、不可聚焦；游客页面不参与此等高布局。
- 独立 L2、L5、L6、L7、L8 从源码与目录移除。身份读取中、读取失败、登录结束改为平台内容区的状态反馈；身份未确认或登录结束时不显示企业资料、业务菜单与消息入口。
- 登录入口文案为“使用在资产可信平台登记的钱包地址登录”；卡片最下方 `.network-support` 同行展示“支持网络：”与图标 + Ethereum。
- 账户新增仍用两步 `.steps`：填写信息 → 签名验证。进入下一步的按钮写明目的。

### 4.10 弹窗与确认

- 结构：标题栏（标题 + 关闭）/ 内容 / 底栏（`--card-2` 底，按钮右对齐，主按钮在最右；「上一步」靠左）。
- 打开时焦点落在第一个输入框或主按钮；只有关闭操作的说明窗聚焦底栏关闭按钮。Tab 焦点留在弹窗内；Esc 与关闭按钮回到原页面并恢复触发按钮焦点。下拉菜单按 Esc 关闭后，焦点回到菜单入口。
- 页内确认：`data-overlay data-inline data-base="返回页面"` 沿用原有返回关系，但在内容区呈现，隐藏原内容，保留顶栏、面包屑与身份。它不是模态对话框，不锁定键盘焦点；确认区底栏 `.card-f` 与普通弹窗底栏共用间距与按钮层级。
- 删除弹窗分三种结果：未被引用账户说明后果，保留取消与危险确认；登录地址说明系统维护不能删除；被引用账户说明具体引用，示例为代币 DEMO-TOKEN-001。后两种只能关闭，无确认删除按钮。离开平台仍须先确认。
- 标题文字单独放在 `.modal-title`，继续由 `aria-labelledby` 引用；语言入口和关闭按钮不混入对话框标题的可访问名称。

### 4.11 偏好设置

- `.preferences` 按“语言 / 时区”两行排列；左边标签和说明，右边 280 px 原生下拉（36 px 高），行间分隔线。≤ 600 px 控件移到说明下方并占满宽度。与借贷平台管理端截图保持相同结构。
- 语言选项 English / 简体中文。首次无浏览器记忆时为 English，不读取浏览器语言。切换只替换展示文案，输入值、地址、备注名和正式企业 / 人名等业务值保留。
- 时区只在企业用户资料页显示，采用有效 IANA 标识。展示示例包含 UTC、Asia/Shanghai、Asia/Hong_Kong、Asia/Singapore、Europe/London、America/New_York，并补入浏览器推断出的有效时区。全部 `data-instant` 用同一时区格式化，原始 ISO 时间戳不变，列表表头及资料时间旁标注时区。
- 生产保存行为以 C-PROFILE-02 为准：每项改选即保存、保存中该项不可再次修改、不影响另一项、成功即时生效、失败恢复旧值；不发消息。原型补画保存中及失败两屏，正常操作仅提示“预览偏好已更新”，不伪装成真实账户保存。
- `display.js` 仅负责展示预览和当前浏览器的语言记忆；不模拟账户偏好、跨设备保存、请求时延或失败随机数。未接入接口时，时区预览只在本次打开期间保留，重新打开以浏览器时区初始化。

### 4.12 下拉菜单、消息入口与结果提示

- 下拉 `.dd-list`：8 px 圆角、阴影，菜单项 13 px，分组之间用分隔线。单选型下拉（如界面语言）用 168 px 的 `.narrow`，顶部有弱化标签，当前项浅蓝底并带对勾。点击外部或 Esc 关闭；同一时间只展开一个下拉。
- 消息入口 `.bell`：36 px 圆形，未读数用红色角标，未读为 0 时不显示数字。
- 结果提示 `.toast`：深色底，在屏幕底部居中显示约 2.4 秒，用于「已复制」「已保存」「账户已登记」等结果。

### 4.13 网络与币种标识

- 网络与币种名称前必须有对应图标，并保留可读名称。Ethereum 只用英文；币种用业务给定代码，如 ETH、USDT、USDC。图标不能替代名称。企业账户列表按 PRD 独立展示网络列，地址列只展示地址。
- 结构：`<span class="asset-label"><i data-asset="ETH"></i>Ethereum</span>`。币种组件相同，例如 `<span class="asset-label"><i data-asset="USDT"></i>USDT</span>`；由 `TP.boot` 转成 SVG。
- `.asset-icon` 默认 18 × 18 px，图文间距 6 px，保留原品牌配色；图标 `aria-hidden`、不可聚焦，由相邻文字提供身份。名称组保持不拆行。
- `asset-icons.js` 复用借贷平台现有资产库中的 ETH、USDT、USDC 原始 SVG（spothq/cryptocurrency-icons，CC0 1.0；来源版本和许可全文随代码及离线导出件保留）。未知币种使用中性圆形占位图标，同时必须展示真实币种代码。
- M1 当前只有 Ethereum 网络 / 地址，不存在币种字段；USDT / USDC 是可复用图形资产，不代表本模块支持它们，不在 M1 增加余额或币种选择。
- 覆盖登录支持网络与连接信息、企业账户网络列、只读网络表单、签名核对与编辑弹窗。其余模块接入时同样使用此组件。

### 4.14 资产信息（M2 起）

- **资产摘要** `.asset-sum`：左侧为应收账款金额（28 px 无衬线等宽数字 + 14 px 币种）与债务人、到期日；运营与监管视图另列债权人。右侧 `.status-grid` 以分隔线组织确权、回款、发行三个状态，去掉外层重复框。≤ 1100 px 摘要上下排列，≤ 600 px 状态为标签与值对齐的三行。满足发起条件使用浅灰说明条与绿色确认图标，主色留给主要操作；警告与异常保留语义色。
- **状态标签取值**：已确权 `ok`、已撤销确权 `danger`；未到期 灰、已结清 `ok`、已逾期 `danger`；可发行 `accent`、发行申请中 `warn`、已驳回 `danger`、已发行 `ok`；取不到的确权状态写“暂时无法获取”；无法确定的回款状态写“暂时无法确认”（Unable to confirm），用 `warn`，不归入正常值。归并和发起条件遵循 PRD，不在原型中编写状态计算。
- **发起条件** `.cond`：放在资产摘要卡底部。满足时 `.cond.ok`，写明“债权人已确权，满足发起条件”；不满足时 `.cond.no`，逐条列出全部原因；发行申请中、已发行时用默认 `.cond`，写说明并在右侧放去向按钮。运营和监管视图不放发起条件。
- **资产列表**：使用 `.tbl.auto.asset-list`，首列不固定 20%，企业端、运营端、监管端及企业详情内嵌资产列表均只展示回款、发行两项状态，不展示确权列或行内“已确权”标签；详情保留确权状态、确权日期与相关提示。上游资产编号保持完整不换行，企业名称按词换行。债权人、债务人列加 `.col-name`；金额 `.num` 右对齐。到期日必须展示已有值：日期 / 时分，表头标注当前 IANA 时区；源 HTML 保留日期文本，运行时再按所选时区格式化，不以空白表示有值字段。
- **上游变更提示**（只在运营端）：按本轮用户确认，列表移除编号下方的额外提示，详情页头上方保留 `.note.red.banner`“上游已撤销确权”“上游已删除”，说明本平台不自动处理；详情摘要的确权状态仍展示“已撤销确权”，列表不再保留该列。这一提示位置优先于旧版 PRD 的列表行内展示措辞，不改变业务状态与处理规则。
- **详情分区标签** `.detail-nav`：资产详情放在资产概览下方、基本信息及关联记录上方，不再提供“资产概览”标签。企业详情仍放在页头下方。沿用借贷平台审核详情的连续分区；吸顶偏移按实际顶栏高度更新（桌面基线 68 px）。点击标签滚动到对应分区，正常上下滚动同步高亮；全部信息始终展开，不做仅显示当前页签内容的切换面板。关联记录（存在时）、基本信息、贸易订单、采购订单、账款信息、回款进度、材料均可定位；企业详情采用同一组件。使用导航锚点、`aria-current="location"` 与可见键盘焦点，点击不改变画面路由。接近页尾无法顶对齐时仍保持点击项选中，不靠新增空白撑高页面。
- **缺失值**：L1 缺失用 `.missing` 写“上游未提供”；L2 缺失用 `.missing.soft` 写“未提供”；整组或整表没有时用 `.sub-empty` 写一句说明（如“无采购账款信息”“暂无回款记录”），不画空表。
- **卡片内小节** `.sub-h` / `.card-sec`：一张卡片里有多组信息时（债权人、债务人；销售账款、采购账款；回款汇总与回款记录），用小节标题加分隔线，不再嵌套卡片。
- **材料** `.files`：每个文件一行（图标、文件名、材料类型、查看 / 下载），宽屏两列，≤ 1100 px 单列。打开失败用弹窗说明“本次未能打开”，可重试。
- **列表筛选条** `.asset-filters`：以 WS-508 用户提供的筛选截图为视觉基线，替换 v1.8 的胶囊及固定双行排布。本条为筛选条的权威样式，业务字段按所属模块 PRD 确定。
  - 工具栏：左侧常用下拉与“更多筛选”，右侧带搜索图标的输入框、文字型重置、主色查询按钮。中间以弹性留白分组；可用宽度不足时自然换行，不缩小字号或裁切操作。
  - 控件：统一 36 px 高、6 px 小圆角（`--ctrl-h-sm` / `--radius-xs`）、13 px 字号；白底、1 px `--border-strong` 描边，无阴影，不再使用 `--radius-pill`。下拉文本为“字段 · 当前值”，初始值“全部”；选择非默认值时使用浅蓝底、蓝色描边与蓝字。英文选项随选中内容扩展宽度，最长项可完整阅读；不支持内容自适应的浏览器按原生下拉宽度回退并允许工具栏换行。

- **企业检索** `.searchbar`：继续保留企业名称 / 登记标识查找，不改成资产筛选；原有无结果画面继承。
- **可点击面包屑**：详情的资产 / 企业列表祖先使用真实链接，可用 Enter 返回原列表，当前页用 `aria-current="page"`。业务分组本身没有页面，保持文本；由 `data-crumb-targets` 显式指定已有画面，不猜测路由。

### 4.15 响应式

- > 900 px：238 px 侧栏、内容左右各 24 px；`--content-max: none`，面包屑与主体占满侧栏以外的可用内容宽度，左边线对齐。宽屏不再叠加 1200 px 居中限宽产生的两侧留白。此规则共用于面客端、运营端及监管端。
- 内容容器铺开不改变内部字段、控件和说明文本的既有宽度约束；登录 L1 / L3 / L4 独立卡片继续按 L3 等宽等高规则呈现。
- 601–900 px：侧栏 180 px、内容左右 16 px；表格最小宽度 800 px，在表格容器内横向滚动，操作列固定右侧。
- ≤ 600 px：品牌与导航在顶部，原有菜单按原顺序横向滚动；顶栏仍保留语言、消息、账户。资料单列，页头操作可换行，弹窗左右留 12 px，内容可纵向滚动，底栏按钮可换行。
- 登录保持水平居中卡片，小屏左右 16 px、卡片内边距 24 px；不加载网络字体。尊重 `prefers-reduced-motion`，键盘焦点使用既有 2 px 主色轮廓。

## 5. 原型轻量化约定

原型只告诉前端两件事：页面怎么布局，展示哪些信息。规则、校验与异常分支写在 PRD。

**原型包含：**

- 页面 × 主状态的静态画面：每个页面一个默认、一个空、一个代表性异常；身份或阶段不同且布局或可用操作随之变化时，单独出一屏；多步流程每一步一屏。
- 规则生效后的结果：字段是否可编辑、按钮是否可用及原因、必填与格式提示、一个错误示例出现的位置、状态标签、关键后果说明。
- 主流程逐屏可走；其他按钮只表现可用或不可用。

**原型不包含：**

- 业务校验、计算、状态机、账户存储、演示时钟、故障注入或引导式走查。语言记忆和时间格式化只是展示功能。
- 页面上的规则编号、字段来源、设计理由。
- 真实钱包 / 接口、账户偏好持久化、跨设备同步或主题切换；中英文即时切换、浏览器语言记忆、展示时区换算及完整地址复制已可操作。

**评审工具：** 右下角「画面目录 · 演示数据」按钮，默认关闭。展开后按「页面 → 状态」列出全部画面，并提供「主流程下一屏」。画面中的企业、地址、邮箱、编号均为演示数据。

**文件约定：**

- 源码：`页面原型/面客端/<编号>-<模块名>/<模块名>.html`（管理端放在 `页面原型/管理端/`），只写画面内容，引用 `_shared/` 下的公共层。
- 每屏是一个 `<section data-screen>`，用 `data-*` 声明骨架、身份、菜单、面包屑、所在弹窗的底层画面和主流程下一屏；约定写在 `frame.js` 文件头。
- 评审件：用 `_shared/export.py` 生成单文件，作为附件交付，不入库。

### 5.1 仓库联看与单模块附件

- **仓库联看**：完整同步 `页面原型/`，双击任一模块 HTML。源码引用 `<script src="../../_shared/navigation.js" data-local-only></script>`，放在 `frame.js` 之后、模块 `TP.boot` 之前，明确启用 `repository` 模式。沿用真实侧栏和账号菜单，同一标签页通过相对文件路径和画面锚点跳转，不要求本地服务、联网请求、iframe 总览或全平台合并文件。画面目录仍独立且默认关闭。
- **单模块附件**：`export.py` 排除带 `data-local-only` 的脚本，明确设置 `module` 模式，再内联本模块必需的公共样式与脚本。附件直接进入所属模块，不加载其他模块；跨模块入口继续显示范围提示。不得只根据 `file://` 判断模式，也不得在附件中保留对仓库路径的依赖。
- **维护与体积**：共享跳转代码和路由表只在 `navigation.js` 维护一份，每个模块仅增加脚本引用，不复制其他模块 HTML、样式或演示数据，不预加载其他模块。导出件不包含仓库路由表和专用跳转代码；交付核对源码及生成件的实际字节增量。
- **登记与身份**：路由按端、菜单/操作键、目标文件和身份对应的画面 ID 登记。仅登记当前分支已交付且实际存在的文件与画面；每个身份明确指定目标，不回退成另一角色。模块内路由和未认证受限画面优先，跨模块路由只补已有模块间的连接。无权限、游客、首登受限等画面的既有入口限制保持不变。
- **展示上下文**：跨模块传递现有演示身份、语言和有效 IANA 时区；监管机构停用及变更邮箱示例保持对应身份画面。`previewLang` / `previewZone` / `previewWho` / `previewBase` / `previewGate` 只定位展示，不携带业务记录、凭据或令牌，不作为生产登录与权限依据。地址中的展示偏好随当前选择更新，刷新后保留；确认画面保留底页与返回关系。
- **未交付模块**：继续保留原范围提示，不创建空链接或伪造业务页面。已存在的跨模块业务按钮可用 `data-module-key` 声明目标，同时保留 `data-toast` 作为附件或未登记目标的提示；业务记录详情只接到匹配的记录画面，不能用任意列表代替。
- **新增或修订模块的检查**：登记对应文件及真实画面，验证鼠标与键盘切换、双向跳转、刷新与浏览器返回、身份/菜单/展示偏好、确认取消与未交付提示；重新导出单文件，在断网环境核对无外部依赖、无跨模块文件请求、原有画面目录及主流程可用。规则、校验与异常分支仍以 PRD 为准。

## 6. 新增组件的规则

1. 先复用本规范已有组件；确实缺少时，加到 `components.css` 并在本文补一节。
2. 新组件只引用 `tokens.css` 中的 token，不写字面色值、字号或时长。
3. 模块页面不写行内样式，不复制公共组件。

## 7. 管理端账号与机构资料（M5）

- `.form-grid` 为两列信息采集，窄屏单列；`.field-caption` 放字段标签与长度计数。必填、只读、提示与错误继续使用既有 `.req`、`.field-static`、`.hint`、`.err-msg`。
- 邮箱认证流程用 `.auth-screen`，沿用 480 px focus 宽度；不套用 M1 钱包登录三屏等高规则。卡片或弹窗内容区已有内边距时，信息列表用 `.facts.inset` 去掉重复内边距，并由 `.facts-region` 判断单双列。
- `.password-control` 使用普通密码输入框与内嵌眼睛图标按钮，`data-password-toggle` 指向输入框 ID；隐藏时为眼睛（动作“显示密码”），显示时为划线眼睛（动作“隐藏密码”），`aria-pressed` 与实际显隐一致。无障碍名称与提示随语言和动作同步，不渲染可见的“显示/隐藏”文字。只改变显示方式，不做密码规则校验或自动保存。
- `.file-list` / `.file-row` 展示文件名称、格式、大小与操作；`.upload-box` 展示上传入口和限制，`.file-progress` 展示静态进度。上传中/失败的保存不可用画面由模块声明，不实现上传与状态运算。
- `.form-sheet` 按核心资料、牌照附件、登录账号分区；详情与编辑均继承既有卡片与确认契约。`.reg-list` 控制监管机构表格列宽，复用固定右侧操作列。
- 账户设置用既有 `.profile-section` 与 `.preferences`，区块标题使用 16 px token；`.facts-region` 按可用宽度自动分列。运营和监管均显示本人改邮箱入口；共用登录页的忘记密码不加角色前缀、不要求选角色。业务值不随语言翻译。
- `TP.routes.settings` 可配置模块内角色对应的账户设置画面；其他模块在仓库模式按 §5.1 连接已交付账户设置，附件模式保留范围提示。账号菜单可用 `TP.demo.accounts[身份].notice` 显示停用机构说明。
- 首登改密画面使用 `data-layout="focus" data-who="none" data-restricted`，顶栏只有语言和退出入口，不渲染业务菜单、消息或正常账号菜单。
- M5 双模块共用一个源 HTML 以连续查看主流程，不产生另一份 token、CSS 或运行时。源码路径及完整画面索引见 [M5 README](../../管理端/01-管理端登录与权限/README.md)。
