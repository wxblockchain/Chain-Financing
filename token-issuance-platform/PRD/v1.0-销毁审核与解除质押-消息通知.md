# 销毁审核、解除监管与代币台账 · 消息通知

2026-10-30｜管理端发起业务、企业／原监管机构／运营接收｜需求评审稿

本模块发出以下五类站内消息，均必发且不可关闭，不发邮件。事件编号沿用现有定义；解除相关名称按用户“只有监管”的确认表述。接收、阅读、语言、前往与异常承接按[来源接入要求（MSG-06）](./v1.0-消息通知-PRD.md#MSG-06)，发生后 60 秒内可见沿用[送达时效](./v1.0-消息通知-PRD.md#delivery-time)的已确认要求，实现与验证归研发、测试。

共同登记：发送来源均为 M4b；企业消息在面客端，原监管机构和全体运营消息在管理端。原业务名称为“销毁申请 / Token burn application”，识别信息为销毁申请编号、上游资产编号与提交时间；以[申请信息](./v1.0-销毁审核与解除质押-PRD.md#handoff-application)准确定位原申请，不能替换成同代币最新申请。解除待办也沿同一申请定位到关联解除事项。

<a id="NT-C06"></a>
## 2. 销毁成功（NT-C06）

- 触发：原代币及完整数量已经确认销毁成功，记录成功事实时发一次；发生时间取实际销毁成功时间，首次或重试后成功按同一规则。
- 不触发：审核通过、销毁中、执行结果未确认、销毁失败、驳回，或仅进入待解除详情；成功结果数量不符不能触发。
- 收件人：本次申请所属企业；不发其他企业、监管机构或运营。
- 必须包含：销毁申请编号、上游资产编号、申请提交时间、成功销毁数量与 USD、成功结果和等待原监管机构解除监管的下一步说明。
- 打开后：本企业 M4a 的该笔销毁申请详情，按[申请详情与解除监管进度（C-BURN-03）](./v1.0-我的代币与销毁申请-PRD.md#C-BURN-03)显示当前事实，可返回原消息；已解除时仍进入该原申请，不恢复办理动作。
- 同一事实：同一成功代币只发一次成功消息；重试后成功不补发历次失败给企业。

<a id="NT-C07"></a>
## 3. 销毁申请驳回（NT-C07）

- 触发：原申请的运营驳回提交生效；发生时间取本次驳回生效时间。
- 不触发：未填写意见、意见为空白、取消、提交失败、结果未确认或申请已被其他运营处理导致本次未生效。
- 收件人：本次申请所属企业；不发其他企业、监管机构或运营。
- 必须包含：销毁申请编号、上游资产编号、申请提交时间、驳回结果、原文驳回意见，以及满足当前销毁条件时可再次发起的说明（BR-22）【确认】。
- 打开后：M4a 该笔原驳回申请；即使已有新申请也不替换旧记录，是否可再次发起按当前资格与处理中申请判断。
- 同一事实：每笔申请的生效驳回一次；企业后来提交新申请并再次被驳回是新事实，另发一条。

<a id="NT-C08"></a>
## 4. 资产已解除监管（NT-C08）

- 触发：原监管机构在平台解除成功且生效记录已形成；发生时间取解除完成时间。
- 不触发：仅销毁成功、阅读待办、选填材料、取消、解除失败或结果暂未确认。
- 收件人：该笔资产所属企业；不发其他企业、运营或监管机构。
- 必须包含：销毁申请编号、上游资产编号、原监管机构名称、解除完成时间和已解除监管结果。
- 打开后：M4a 对应成功销毁申请的解除进度与结果；企业仍只见[企业可见的解除结果](./v1.0-销毁审核与解除质押-PRD.md#handoff-release)，不因通知取得内部备注、操作人或凭证权限。
- 同一事实：同一资产该笔解除仅一条；重复提交定位原记录，不能再发。

<a id="NT-R02"></a>
## 5. 代币已销毁、待解除监管（NT-R02）

- 触发：确认销毁成功并形成原机构待解除事项，与[企业销毁成功消息（NT-C06）](#NT-C06)源于同一成功事实；发生时间为销毁成功时间（BR-06）【确认】。
- 不触发：审核通过、销毁中、结果未确认、失败、驳回、再次读取成功结果。
- 收件人：该代币原发行申请所选机构。停用仍生成在途消息，更名和账号更正不改属；其他监管、运营及企业不收本事件。
- 必须包含：销毁申请编号、企业名称、上游资产编号、成功销毁数量与 USD、销毁成功时间，以及在平台解除监管的待办说明。
- 打开后：M4b 原申请关联的本机构解除事项；仍待解除且当前有权时可办理，已解除时只看原记录；不能因读消息直接完成解除。可返回原消息。
- 同一事实：同一成功代币待解除消息一次，不能因待办未办、机构停用或重新登录再发。

<a id="NT-A04"></a>
## 6. 销毁失败待重试（NT-A04）

- 触发：某次实际执行从销毁中确认进入销毁失败；发生时间为该次确认失败时间。
- 不触发：执行尚在进行、结果未确认、前置条件不满足导致未执行、成功、取消重试、重复取得同次失败结果。
- 收件人：全体运营，各自记录已读；不发企业或任一监管机构。
- 必须包含：销毁申请编号、企业名称、上游资产编号、申请提交时间、该次失败时间、需要运营手动重试的说明（BR-14）【确认】；取得内部失败说明时附原文，取不到则省略。
- 打开后：管理端原申请销毁详情；仍失败且当前条件满足才可手动重试，已被重试或成功则看当前结果，不恢复旧动作。可返回原消息。
- 同一事实：同次执行失败只一条；每次手动重试后再确认失败是新事实，另发一条。刷新、重新送达不新增，也不重置已读。

## 8. 内容、权限与重复事实

- 提交时间、数量、机构等动态值取上述原申请和对应成功／失败／解除事实；缺项按 M7 来源要求补齐后发送，不用零或假编号代替。
- 五类事件各自成消息，不把销毁成功与解除完成合并，也不把发给企业与原监管机构的消息互相替代。同一事实重复送达不新增、不改发生时间、不重新变未读。
- 消息不包含完整钱包地址、签名、个人联系方式、内部运营账号、解除备注、凭证原件或下载地址。运营失败说明只进入运营告警，不转发到企业或监管。
- 从消息前往时重新检查当前身份和业务权限；企业未认证时按 M1／M4a 限制业务访问，管理端按 M5 限制；无权或不存在统一说明不可访问。消息本身能阅读不代表取得业务权限。
- 本模块不发审核通过、处理中、手动重试已受理、台账查看、解除取消／失败等额外通知；“新的销毁申请（NT-A02）”由 M4a 自身维护。
