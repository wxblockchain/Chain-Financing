# 管理端登录与权限 · 功能与业务规则

2026-10-29｜管理端：运营管理人员、监管机构｜需求评审稿

本模块共三册：本册写功能、业务规则、字段规则与交互逻辑；[流程图与状态机](./v1.0-管理端登录与权限-流程图与状态机.md)画出主要流程与状态；[验收](./v1.0-管理端登录与权限-验收.md)供测试使用。本模块自己不发送任何消息（登录、改密、锁定、语言与时区变更都不发消息或邮件），所以没有 03 消息通知册，并非缺失。

本模块与[监管机构管理](./v1.0-监管机构管理-PRD.md)同属简报中的管理端账号、权限与监管机构管理模块（M5）：本模块写管理端账号如何登录、如何维护本人账户，以及运营与监管各能看到哪些菜单和数据；监管机构账号从哪里来、如何停用和重置密码，由监管机构管理定义。

依据标注：规则后的【确认】表示用户已明确，【建议·已采纳】表示诊断建议已由用户采纳，【参考件】表示简报未规定、按借贷平台《运营端账户与登录》的做法写入；三者同样有效。未标注的是为落实上述规则所写的产品细化。本册只定义信息需求与业务行为，页面布局、组件形态与交互承载由 Hallmark 设计决定。

## 1. 模块是什么

运营管理人员和监管机构共用一个管理端，用同一个登录入口、以登录邮箱和密码登录。登录后，平台按账号的角色决定能看到哪些菜单、能看哪些数据：运营管理人员看全平台，监管机构只看本机构的数据。运营账号由开发人员分配；监管机构账号由运营邀请添加，见[监管机构管理](./v1.0-监管机构管理-PRD.md)。所有管理端账号首次登录都必须先修改初始密码，之后可以在账户设置中修改密码、选择界面语言和时区。

基本原则：

- 一个管理端、一个登录入口，按角色区分菜单【确认】（BR-05）。登录方式只有登录邮箱加密码。
- 账号都不是自助开通的：运营账号由开发人员分配，监管机构账号由运营邀请添加【确认】（BR-04、BR-05）。产品内没有注册、忘记密码自助找回或运营账号管理。
- 监管机构只能看到本机构的申请和代币【确认】（BR-15）。这条是所有管理端业务模块共同遵守的数据范围底线，由本册定义一次，各模块引用。
- 隐藏入口不是唯一防线：未授权的菜单不出现，绕过界面直接访问同样被拒绝。

**一个完整的例子。** 运营在监管机构管理中邀请添加监管机构 X，为它分配登录邮箱 x@reg.example 和初始密码，X 收到邀请邮件。X 的人员打开管理端，用该邮箱和初始密码登录，平台要求先设置新密码；设置成功后，平台结束这次登录，X 用新密码重新登录，看到监管机构的菜单：发行审核（一审）、解除质押、代币台账、可信资产和消息通知，看不到监管机构管理和合约管理。X 在账户设置中把界面语言改为 English、时区改为 UTC+08:00，界面文字和时间随之变化。X 打开代币台账，只看到选择了本机构的申请所铸造的代币；把链接里的编号改成另一家机构的代币，看到的是“无权查看或内容不存在”。X 退出后回到登录入口。

### 1.1 需求清单

简报的两个功能标识在本模块的落点：运营登录（A-LOGIN）与监管登录（R-LOGIN）共用下表全部登录与账户功能，差别只在账号来源和首次登录；菜单权限矩阵（简报 4.4）落在第 6 节。

| 功能 | 谁 | 想做什么 | 为了什么 |
| --- | --- | --- | --- |
| [管理端账号与角色（F-LG-01）](#F-LG-01) | 运营管理人员、监管机构 | 知道自己的账号从哪里来、属于什么角色 | 按角色使用管理端 |
| [邮箱与密码登录（F-LG-02）](#F-LG-02) | 未登录的管理端用户 | 用登录邮箱和密码登录 | 进入管理端办理业务 |
| [首次登录强制改密（F-LG-03）](#F-LG-03) | 持初始密码的管理端用户 | 首次登录先换掉初始密码 | 初始密码经过他人之手，降低泄露风险 |
| [登录后进入与返回原目标（F-LG-04）](#F-LG-04) | 刚登录的管理端用户 | 进入默认页面，或回到登录前要去的地方 | 不必重新查找 |
| [连续失败与临时锁定（F-LG-05）](#F-LG-05) | 管理端用户 | 密码多次输错后账号被临时锁定 | 防止密码被猜中 |
| [登录有效期、无操作登出与退出（F-LG-06）](#F-LG-06) | 已登录的管理端用户 | 离开后登录自动结束，也能主动退出 | 防止他人在无人看管的电脑上操作 |
| [账号入口与账号信息（F-LG-07）](#F-LG-07) | 已登录的管理端用户 | 查看本人账号信息 | 确认当前登录的是哪个账号 |
| [修改密码（F-LG-08）](#F-LG-08) | 已登录的管理端用户 | 修改本人密码 | 定期更换或怀疑泄露时更换 |
| [界面语言与时区（F-LG-09）](#F-LG-09) | 所有管理端访问者 | 在简体中文和 English 之间切换，按本人时区看时间 | 用熟悉的语言和时间办理业务 |
| [菜单权限矩阵（F-LG-10）](#F-LG-10) | 运营管理人员、监管机构 | 只看到本角色能用的菜单 | 各司其职 |
| [数据范围（F-LG-11）](#F-LG-11) | 运营管理人员、监管机构 | 运营看全平台，监管只看本机构 | 监管机构之间互不可见 |
| [无权访问的处理（F-LG-12）](#F-LG-12) | 管理端访问者 | 访问未授权内容时得到统一结果 | 不泄露他人数据，也不泄露数据是否存在 |

### 1.2 本期不做

- 注册、申请开通管理端账号。
- 忘记密码自助找回。监管机构忘记密码时联系运营，由运营[重置密码（F-RG-06）](./v1.0-监管机构管理-PRD.md#F-RG-06)；运营忘记密码时联系开发人员重新分配。
- 运营账号的界面化管理：新增、停用、给其他运营改密、分配角色都由开发人员完成【确认】。
- 运营以外的角色细分：运营只有“管理员”一个角色【确认】（BR-05）。
- 本人修改登录邮箱。
- 验证码登录、钱包登录、第三方登录、“记住我”。
- 密码变更、账号锁定、登录成功或失败的通知。
- 管理端账号登录面客端，或面客端钱包地址登录管理端：两套账号互不相通，面客端登录见[企业登录与企业账户](./v1.0-企业登录与企业账户-PRD.md)。
- 各业务菜单内的具体操作规则：由各业务模块定义，本册只定义谁能看到哪个菜单、能看哪些数据。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 管理端 | 运营管理人员和监管机构共用的端，与企业使用的面客端是两套 |
| 管理端账号 | 登录管理端的账号，以登录邮箱识别。分为运营账号和监管机构账号两类 |
| 运营账号 | 角色为运营管理员的账号，由开发人员分配，可以有多个 |
| 监管机构账号 | 角色为监管机构的账号，由运营在监管机构管理中邀请添加时分配，归属一个监管机构 |
| 本机构 | 对监管机构账号而言，指它所属的那个监管机构 |
| 初始密码 | 开发人员或运营为账号设置、由他人告知账号使用者的密码，包括邀请添加和重置密码时设置的密码。只能用来完成首次登录强制改密 |
| 登录有效期 | 一次登录从成功起最多能保持多久 |
| 无操作登出 | 一段时间没有任何真实操作后，登录自动结束 |
| 临时锁定 | 连续输错密码达到次数后，账号在一段时间内不能登录；到期自动解除 |
| 原目标 | 未登录时想打开的管理端页面，例如从消息链接打开的一条消息 |

<a id="F-LG-01"></a>
## 3. 管理端账号与角色（F-LG-01）

依据：运营与监管共用管理端、按角色区分菜单；运营只有“管理员”一个角色，账号由开发人员分配【确认】（BR-05）。监管机构只能由运营邀请添加，初始账号由运营分配【确认】（BR-04）。

### 3.1 两类账号

| 角色 | 账号从哪里来 | 数量 | 产品内谁能维护 |
| --- | --- | --- | --- |
| 运营管理员 | 开发人员分配登录邮箱和初始密码【确认】 | 可以有多个【确认】 | 本人只能修改自己的密码、界面语言和时区；其他维护都由开发人员完成 |
| 监管机构 | 运营在[邀请添加监管机构（F-RG-02）](./v1.0-监管机构管理-PRD.md#F-RG-02)时分配登录邮箱和初始密码【确认】 | 每个监管机构一个，见[待确认（Q-RG-04）](./v1.0-监管机构管理-PRD.md#Q-RG-04) | 本人只能修改自己的密码、界面语言和时区；运营可在监管机构管理中编辑、停用 / 启用、重置密码 |

- 一个账号只有一个角色，角色在账号建立时确定，产品内不能更改。
- 运营管理员的权限对每个运营账号都相同，本期不按人细分。
- 监管机构账号始终归属建立时的那个监管机构，不能改属其他机构。
- 管理端账号只能登录管理端；面客端只能用钱包地址登录。

<a id="account-info"></a>
### 3.2 账号信息

以下信息对本人只读，界面语言和时区除外。

| 业务信息 | 含义 | 来源与可编辑性 |
| --- | --- | --- |
| 登录邮箱 | 登录账号。在管理端全部账号（运营账号与监管机构账号）中唯一，不区分大小写 | 运营账号由开发人员分配；监管机构账号由运营邀请时分配。本人不能修改 |
| 账号名称 | 用于识别是谁在操作。运营账号为开发人员配置的姓名；监管机构账号为所属监管机构的名称 | 运营账号由开发人员维护；监管机构账号随[编辑监管机构信息（F-RG-04）](./v1.0-监管机构管理-PRD.md#F-RG-04)更新 |
| 角色 | 运营管理员或监管机构 | 建立时确定，不能修改 |
| 所属监管机构 | 仅监管机构账号有，并展示该机构当前是启用还是停用 | 建立时确定，不能修改 |
| 账号状态 | 见[账号状态](#account-status) | 由首次改密、锁定和重置密码改变，不能手工修改 |
| 界面语言 | 本人的语言偏好：简体中文或 English | 本人可修改，见[界面语言与时区（F-LG-09）](#F-LG-09) |
| 时区 | 本人的时区偏好，决定界面上时间的展示 | 本人可修改，见[界面语言与时区（F-LG-09）](#F-LG-09) |
| 最近登录时间 | 最近一次登录成功的时间 | 系统记录，按本人时区展示并标明时区 |
| 创建时间 | 账号建立的时间 | 系统记录，按本人时区展示并标明时区 |

<a id="account-status"></a>
### 3.3 账号状态

| 状态 | 含义 |
| --- | --- |
| 待首登改密 | 账号持有初始密码，尚未完成首次登录强制改密。新建的账号、被重置密码的账号都处于此状态 |
| 正常 | 已完成首次登录强制改密，可以按角色使用管理端 |
| 锁定 | 连续输错密码达到次数后的临时状态，到期自动回到锁定前的状态，见[连续失败与临时锁定（F-LG-05）](#F-LG-05) |

各状态下能做什么：

| 能力 | 未登录 | 待首登改密 | 正常 | 锁定 |
| --- | --- | --- | --- | --- |
| 打开登录入口、切换界面语言 | 可以 | 可以 | 可以 | 可以 |
| 登录 | 须输入正确的邮箱和密码 | 登录后只能进入首次登录强制改密 | 登录后按角色进入管理端 | 不能登录，输入正确密码后才看到锁定提示与剩余时间 |
| 首次登录强制改密 | 不能 | 必须完成 | 不适用 | 不能 |
| 账户设置（账号信息、修改密码、语言与时区） | 不能 | 不能，只能切换界面语言 | 可以 | 不能 |
| 业务菜单与消息通知 | 不能 | 不能 | 按[菜单权限矩阵（F-LG-10）](#F-LG-10)和[数据范围（F-LG-11）](#F-LG-11) | 不能 |
| 退出登录 | 不适用 | 可以 | 可以 | 已有的登录不能继续使用，可以退出 |

- 监管机构被停用不改变上表：账号仍可登录，可以查看本机构数据并继续办理在途业务【确认】；停用只影响新业务，见[停用与启用（F-RG-05）](./v1.0-监管机构管理-PRD.md#F-RG-05)。
- 账号状态的变化见[管理端账号状态机](./v1.0-管理端登录与权限-流程图与状态机.md#state-1)。

<a id="password-rules"></a>
### 3.4 设置密码的共同规则

适用于所有设置密码的地方：[首次登录强制改密（F-LG-03）](#F-LG-03)、[修改密码（F-LG-08）](#F-LG-08)，以及运营在[邀请添加监管机构（F-RG-02）](./v1.0-监管机构管理-PRD.md#F-RG-02)和[重置密码（F-RG-06）](./v1.0-监管机构管理-PRD.md#F-RG-06)时设置的初始密码。开发人员分配的运营初始密码同样须满足长度、组成和空格规则。

依据：【参考件】。

| 规则 | 要求 |
| --- | --- |
| 长度 | 8～20 个字符 |
| 组成 | 至少包含 1 个英文字母和 1 个数字 |
| 空格 | 前后的空格自动去除；中间不能有空格 |
| 与当前密码 | 本人设置新密码时，不能与当前密码相同 |
| 与初始密码 | 本人设置新密码时，不能与本账号最近一次被设置的初始密码相同 |
| 两次输入 | 本人设置新密码时须输入两次且一致；不一致时在第二次输入处说明并不能提交，改为一致后提示消失 |

- 输入过程中实时说明各项规则是否满足，全部满足才能提交；不展示密码强弱分档。
- 所有密码输入都可以由本人切换显示或隐藏。
- 提交时由平台再次校验，不满足时不改变原密码，并说明哪一项不满足。
- 除本人在输入时主动切换显示外，界面、站内消息和日志中都不出现明文密码；邀请邮件中的初始密码是用户确认的例外，见[监管机构邀请邮件（NT-R03）](./v1.0-监管机构管理-消息通知.md#NT-R03)。

## 4. 登录与退出

<a id="F-LG-02"></a>
### 4.1 邮箱与密码登录（F-LG-02）

适用角色与前提：未登录的访问者。

依据：运营用开发分配的账号密码登录【确认】；监管机构用运营分配的邮箱和密码登录【确认】；共用管理端（BR-05）【确认】；防止账号被枚举、失败计数【参考件】。

- 管理端只有一个登录入口，运营和监管机构都从这里登录；不需要选择角色，平台按账号判断角色。
- 登录需要输入登录邮箱和密码。邮箱前后的空格自动去除、不区分大小写。
- 登录入口没有注册、忘记密码、验证码登录、钱包登录或“记住我”。
- 未登录时访问管理端任何其他页面，都先到登录入口，并记住原目标，见[登录后进入与返回原目标（F-LG-04）](#F-LG-04)。

登录结果：

| 情况 | 用户看到的结果 |
| --- | --- |
| 邮箱或密码为空 | 不能提交，指出未填写的一项 |
| 邮箱不是管理端账号，或密码错误 | 统一说明“邮箱或密码错误”；两种情况的提示、表现和响应快慢都不能区分。密码错误计入连续失败次数，见[连续失败与临时锁定（F-LG-05）](#F-LG-05) |
| 邮箱和密码正确，账号待首登改密 | 进入[首次登录强制改密（F-LG-03）](#F-LG-03)，不进入任何业务页面 |
| 邮箱和密码正确，账号正常 | 登录成功，按[登录后进入与返回原目标（F-LG-04）](#F-LG-04)进入 |
| 邮箱和密码正确，账号锁定中 | 不能登录；说明账号已临时锁定和剩余时间，倒计时结束后可以直接重新登录，不需要刷新 |
| 网络或服务异常 | 说明暂时无法登录、请重试；已输入的邮箱保留，不计入失败次数 |

- 登录提交期间不能重复提交。
- 首次登录成功时，按浏览器推断写入时区偏好，见[界面语言与时区（F-LG-09）](#F-LG-09)。
- 登录成功、失败及原因、锁定与解除须可追溯；日志中不记录密码。

流程参见：[登录与首次改密（图 1）](./v1.0-管理端登录与权限-流程图与状态机.md#fig-1)。

<a id="F-LG-03"></a>
### 4.2 首次登录强制改密（F-LG-03）

适用角色与前提：邮箱和密码正确、账号处于待首登改密的访问者。

依据：监管机构首次登录强制修改密码【确认】（BR-04）；运营账号同样首次登录强制改密【参考件】。

- 所有新建账号、被重置密码的账号，登录后都必须先设置新密码，才能使用管理端。这是唯一路径，不能跳过或稍后再改。
- 改密前只能做三件事：设置新密码、切换界面语言、退出登录。其他页面和业务操作都不可用，绕过界面直接访问同样被拒绝。
- 设置新密码只需输入两次新密码，不需要再输入初始密码；新密码须符合[设置密码的共同规则](#password-rules)，并且不能与初始密码相同。
- 设置成功后：账号变为正常，初始密码失效，该账号的全部登录（包括当前这次）立即结束，回到登录入口并说明“密码已修改，请用新密码重新登录”。原目标仍保留，见[登录后进入与返回原目标（F-LG-04）](#F-LG-04)。
- 设置失败时（规则不满足、网络或服务异常）账号仍为待首登改密，初始密码仍可使用，可以重试。
- 改密期间登录到期或无操作登出时，回到登录入口，账号仍为待首登改密。
- 不发送任何通知。

流程参见：[登录与首次改密（图 1）](./v1.0-管理端登录与权限-流程图与状态机.md#fig-1)。

<a id="F-LG-04"></a>
### 4.3 登录后进入与返回原目标（F-LG-04）

适用角色与前提：登录成功、账号正常的用户。

依据：【参考件】。

- 有原目标时，回到原目标；回到之前仍按当前账号的角色和数据范围重新判断，无权访问时按[无权访问的处理（F-LG-12）](#F-LG-12)处理，不能把登录成功当作有权。
- 没有原目标，或原目标不在管理端范围内时，进入本角色的默认页面（具体页面由设计确定，须是本角色可见的菜单）。
- 原目标只在发起登录的同一个浏览器标签页内保留，包括中途完成首次登录强制改密、再用新密码重新登录的情况；刷新页面或在新标签页打开登录入口后登录，进入默认页面。
- 原目标只用于本次登录，不能被其他账号使用：换成另一个账号登录时，按该账号重新判断。

<a id="F-LG-05"></a>
### 4.4 连续失败与临时锁定（F-LG-05）

适用角色与前提：所有管理端账号。

依据：【参考件】。

- 以下两处密码错误共用同一个连续失败次数：登录时输错密码；修改密码时输错当前密码。
- 连续失败达到 3 次起，每次提示还剩几次机会。
- 连续失败达到 5 次，账号临时锁定。锁定时长逐级加长：第一次 15 分钟，第二次 30 分钟，之后每次 60 分钟；第一次锁定时提示“如再次触发，锁定时间会更长”。
- 登录成功后，连续失败次数清零，锁定时长回到第一级；没有其他清零方式。
- 锁定期间不能登录；已有的登录不能继续使用，只能退出。锁定没有提前解除的办法，运营重置密码也不会提前解除锁定。
- 锁定到期自动解除，账号回到锁定前的状态（待首登改密或正常）。
- 锁定提示只在输入正确的邮箱和密码之后出现，不能借此判断某个邮箱是否是管理端账号。
- 锁定与解除不发通知，由本人从登录提示得知。

<a id="F-LG-06"></a>
### 4.5 登录有效期、无操作登出与退出（F-LG-06）

适用角色与前提：已登录的管理端用户，包括待首登改密时的受限登录。

依据：【参考件】。

| 规则 | 要求 |
| --- | --- |
| 登录有效期 | 自登录成功起 4 小时，到期即结束，不因操作延长 |
| 无操作登出 | 连续 30 分钟没有真实操作，登录自动结束。结束前给出提醒，可以选择继续保持登录或立即退出；继续保持登录只重新计算无操作时间，不延长 4 小时的登录有效期 |
| 什么算真实操作 | 点击、键盘输入、提交、页面跳转。页面自动刷新数据、消息自动更新不算 |
| 主动退出 | 账号入口中有唯一的退出入口；退出后该账号的全部登录立即结束 |
| 全部登录结束 | 主动退出、完成首次登录强制改密、本人修改密码、运营重置该账号密码时，该账号在所有设备和标签页上的登录都立即结束 |

登录结束后：

- 回到登录入口，并说明登录已结束的原因（到期、无操作、已退出、密码已修改或已被重置）。
- 受保护的内容不能继续查看，不残留上一个账号的数据；之后迟到的数据或操作结果也不显示。
- 尚未保存的内容不保留，结束前不能提交的操作不会被当作已完成。
- 同一浏览器的其他标签页一并结束。
- 后台的数据请求遇到登录已结束时，与用户操作一样按登录结束处理，不出现“页面还能操作、实际已无登录”的情况。
- 界面语言保留，不随退出而恢复默认。

流程参见：[登录有效期、无操作登出与退出（图 2）](./v1.0-管理端登录与权限-流程图与状态机.md#fig-2)、[登录状态机](./v1.0-管理端登录与权限-流程图与状态机.md#state-2)。

## 5. 账户设置

<a id="F-LG-07"></a>
### 5.1 账号入口与账号信息（F-LG-07）

适用角色与前提：账号正常、已登录的运营管理人员和监管机构。

- 登录后在任何页面都能看到账号入口，显示账号名称、登录邮箱和角色。监管机构账号同时显示所属监管机构；机构已停用时说明“本机构已停用，不再接收新的发行申请；在途业务可以继续办理”。
- 账号入口中有：账户设置和退出登录。消息通知的入口与未读数由[消息通知（M7）](./v1.0-消息通知-PRD.md#MSG-02)定义。
- 账户设置展示[账号信息](#account-info)中的全部项目，并提供修改密码、界面语言和时区的修改。
- 账户设置不展示权限清单，也不提供为自己或他人改角色、改邮箱、新增账号的入口。
- 读取失败时说明暂时无法读取、可以重试，不显示为空。

<a id="F-LG-08"></a>
### 5.2 修改密码（F-LG-08）

适用角色与前提：账号正常、已登录的本人。

依据：运营可修改密码【建议·已采纳】；监管机构之后可修改密码【确认】；当前密码校验与失败计数【参考件】。

- 修改时输入当前密码和两次新密码；新密码须符合[设置密码的共同规则](#password-rules)。
- 当前密码输错时不修改，说明当前密码不正确；输错计入[连续失败与临时锁定（F-LG-05）](#F-LG-05)的连续失败次数，达到 5 次时账号锁定、当前登录结束。
- 修改成功后：新密码立即生效，该账号的全部登录（包括当前这次）立即结束，回到登录入口并说明“密码已修改，请用新密码重新登录”。
- 修改失败、取消或离开时，原密码不变。
- 提交期间不能重复提交；修改期间登录已结束时，修改不生效。
- 不发送任何通知。

流程参见：[修改密码（图 3）](./v1.0-管理端登录与权限-流程图与状态机.md#fig-3)。

<a id="F-LG-09"></a>
### 5.3 界面语言与时区（F-LG-09）

适用角色与前提：界面语言对所有管理端访问者（包括未登录、待首登改密）；时区对账号正常、已登录的本人。

依据：平台支持中文和英文【确认】；上游时间带时区、按用户所选时区换算展示【确认】（见[可信资产 · 语言与时区](./v1.0-可信资产-PRD.md#locale)）；默认语言、时区写入方式【参考件】。

**界面语言**

- 有两种：简体中文、English。登录入口和登录后的任何页面都可以切换。
- 切换后立即生效，不需要刷新；已填写但未提交的内容不丢失。本平台的界面文字、站内消息的标题和正文都按所选语言展示，邮箱、金额、数量、时间、编号等业务值不变；用户填写的驳回意见、备注等按原文展示，不翻译。站内消息的语言规则见[消息通知 · 内容与语言](./v1.0-消息通知-PRD.md#content-rules)。
- 登录后切换即保存为本人的语言偏好，换浏览器或设备登录后仍按上次所选；保存失败时说明并恢复为切换前的语言，可以重试。
- 未登录时切换的语言保存在当前浏览器，下次打开登录入口仍按上次所选，不保存到任何账号。
- 登录后，账号已保存过语言偏好时按账号偏好展示；没有保存过时沿用当前页面正在使用的语言；都没有时默认 English。
- 退出后保留当前语言。

**时区**

- 首次登录成功时，按浏览器推断写入本人的时区偏好；推断不出时为 UTC。
- 本人可以在账户设置中修改，可选范围为标准时区。修改即保存，保存成功后立即生效；保存失败时保留原时区，可以重试。
- 管理端所有时间按本人时区展示并标明时区；时区只影响展示，不改变到期、逾期等业务判断。
- 待首登改密的受限登录期间不能修改时区。

语言与时区变更不发送任何通知。

## 6. 菜单与权限

<a id="F-LG-10"></a>
### 6.1 菜单权限矩阵（F-LG-10）

依据：菜单与角色对应关系【确认】【建议·已采纳】（简报 4.4）；运营与监管按角色区分菜单（BR-05）【确认】。

本节是管理端全部菜单的唯一权限口径。菜单是功能分组，不代表导航形式或页面数量；进入菜单后有哪些操作、按什么规则办理，由所属模块定义。

| 菜单 | 运营管理员 | 监管机构 | 所属模块 |
| --- | --- | --- | --- |
| 发行审核 | 可见：运营二审、选择铸造合约、铸造与失败重试；驳回即终止【确认】 | 可见：监管一审、上传监管协议，仅本机构；驳回即终止【确认】 | 代币发行 · 审核与铸造（M3b） |
| 销毁审核 | 可见：销毁审核（通过即销毁）、失败重试【确认】 | 不可见 | 销毁审核、解除质押与代币台账（M4b） |
| 解除质押 | 不可见 | 可见：对本机构的资产解除质押并留存记录【确认】 | 销毁审核、解除质押与代币台账（M4b） |
| 代币台账 | 可见：全平台【建议·已采纳】 | 可见：仅本机构【建议·已采纳】 | 销毁审核、解除质押与代币台账（M4b） |
| 可信资产 / 企业查看 | 可见：全平台的企业、资产和企业数币账户【建议·已采纳】 | 可见：仅本机构申请关联的资产；看不到企业列表、企业信息和数币账户【建议·已采纳】 | [可信资产（M2）](./v1.0-可信资产-PRD.md#F-AS-06) |
| 监管机构管理 | 可见【确认】 | 不可见【确认】 | [监管机构管理](./v1.0-监管机构管理-PRD.md) |
| 合约管理 | 可见，只读【确认】 | 不可见【确认】 | 合约管理（M6） |
| 消息通知 | 可见：发给全体运营的消息【确认】 | 可见：发给本机构的消息【确认】 | [消息通知（M7）](./v1.0-消息通知-PRD.md#MSG-01) |
| 账号入口与账户设置 | 可见 | 可见；首次登录须先强制改密【确认】 | 本模块 |

- 简报 4.4 中的“销毁”一行，在管理端按角色拆为两个菜单：运营的销毁审核、监管机构的解除质押。
- 上表只对账号正常、已登录的账号生效；待首登改密、锁定的账号看不到任何业务菜单，见[账号状态](#account-status)。
- 不可见的菜单在导航中不出现；直接访问按[无权访问的处理（F-LG-12）](#F-LG-12)拒绝。
- 每个运营账号的菜单完全相同；每个监管机构账号的菜单完全相同，差别只在数据范围。
- 菜单的名称和顺序由设计确定。业务模块新增菜单时，须在本表登记对两个角色是否可见及数据范围。

<a id="F-LG-11"></a>
### 6.2 数据范围（F-LG-11）

依据：监管机构只能看到本机构的申请和代币【确认】（BR-15）。

**运营管理员**：在可见的菜单内查看全平台数据，不按机构或经办人筛选。

**监管机构**：只能看到与本机构有关的数据。“与本机构有关”按下表判断，各业务模块据此筛选，不另行放宽。

| 数据 | 属于本机构的条件 |
| --- | --- |
| 发行申请 | 企业提交时选择的监管机构是本机构 |
| 代币 | 由本机构作为监管机构的发行申请铸造 |
| 销毁申请与解除质押记录 | 所销毁的代币属于本机构 |
| 可信资产 | 本机构发行申请所关联的资产，具体口径见[监管机构查看关联资产（F-AS-06）](./v1.0-可信资产-PRD.md#F-AS-06) |
| 消息 | 发给本机构的消息，见[谁能看到哪些消息（MSG-01）](./v1.0-消息通知-PRD.md#MSG-01) |
| 监管机构信息 | 只有本机构的名称和状态，在账号入口与账户设置中查看；看不到其他监管机构的任何信息 |

- 数据归属看业务发生时选择的监管机构，之后不会改属其他机构。
- 本机构被停用后，数据范围不变：仍可查看本机构全部数据，并继续办理在途业务【确认】。
- 范围判断由平台完成，不能只靠界面隐藏；改写链接中的编号、机构或角色标识，也拿不到其他机构的数据。
- 列表、详情、统计数字、搜索结果、导出（如有）、文件下载都适用同一范围；统计数字不包含其他机构的数据。

<a id="F-LG-12"></a>
### 6.3 无权访问的处理（F-LG-12）

适用角色与前提：所有管理端访问者。

| 情况 | 结果 |
| --- | --- |
| 未登录访问管理端页面 | 先到登录入口，登录后按[登录后进入与返回原目标（F-LG-04）](#F-LG-04)处理 |
| 待首登改密时访问其他页面 | 回到首次登录强制改密 |
| 访问本角色不可见的菜单 | 不返回任何内容，说明无权访问，可以回到默认页面 |
| 访问数据范围以外的某一条数据（如其他机构的申请或代币），或访问不存在的数据 | 两种情况结果完全相同：不返回任何内容，统一说明无权查看或内容不存在，不透露该数据是否存在；具体措辞由各业务模块与设计确定 |
| 发起本角色没有的操作（如监管机构尝试运营二审） | 被拒绝，数据不变，说明无权操作 |

- 从消息或其他记录打开某条数据时，按该数据所属模块的权限重新判断，不因收到消息或看到记录而获得权限。
- 越权访问须可追溯。

## 8. 待确认事项与依赖

本模块当前没有待确认事项。监管机构账号的数量与信息字段等事项见[监管机构管理 · 待确认事项](./v1.0-监管机构管理-PRD.md#pending)。

依赖：

- 开发人员：分配运营账号的登录邮箱、姓名和初始密码，并在运营忘记密码时重新分配初始密码；重新分配后账号回到待首登改密。
- 浏览器时区：用于首次登录时写入时区偏好；推断失败时为 UTC。
- 会话与锁定计时、真实操作的判定由研发实现，测试负责验证。
