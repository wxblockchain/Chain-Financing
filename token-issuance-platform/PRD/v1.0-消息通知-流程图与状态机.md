## 一条消息从来源发出到收件人看到（图 1）

```mermaid
flowchart TD
    A["来源模块的业务事实真正生效"] --> B{"来源的消息通知册规定要通知?"}
    B -->|否| B1["不发消息"]
    B -->|是| C{"必填接入信息齐全，收件范围可确定?"}
    C -->|否| C1["由来源补齐后再发<br/>不猜收件人，不用虚假信息补位"]
    C -->|是| D{"同一收件范围已收到过同一事实?"}
    D -->|是| D1["保留原消息：不新增、不改顺序<br/>不变回未读、不改发生时间"]
    D -->|否| E["新增一条消息，对收件人为未读<br/>60 秒内出现，到点事件最晚 6 分钟"]
    E --> F{"收件范围"}
    F -->|本企业| G["该企业在面客端可见"]
    F -->|本机构| H["该监管机构在管理端可见"]
    F -->|全体运营| I["每位运营管理人员可见，各自记录已读"]
```

邮件不经过本图，也不进入消息中心。

## 入口、列表、详情、已读与返回（图 4）

```mermaid
flowchart TD
    A["能看消息的用户位于本端任一业务页面"] --> B["消息入口与本人未读数"]
    B -->|打开预览| P["最近 10 条，只打开不变已读"]
    B -->|进入列表| L["消息列表：分类与已读状态筛选<br/>每次加载 20 条"]
    P -->|查看全部| L
    P -->|选择一条| D["打开消息详情"]
    L -->|选择一条| D
    D --> E{"消息属于当前身份?"}
    E -->|否或不存在| E1["按不存在处理，不透露是否存在"]
    E -->|是| F{"详情展示成功?"}
    F -->|否| F1["仍为未读，可重试或返回列表"]
    F1 --> D
    F -->|是| G["对本人自动变为已读，未读数减少"]
    G --> H{"去向"}
    H -->|不跳转或缺失| H1["只看正文，没有前往入口"]
    H -->|原业务或固定页面| I{"按当前权限与状态判断"}
    I -->|不存在或无权查看| I1["说明相关内容暂不可访问"]
    I -->|检查失败| I4["仍可前往，由原业务页面判断权限"]
    I -->|原动作仍可办理| I2["前往该笔原业务查看或办理"]
    I -->|原动作已办完或不适用| I3["前往查看该笔当前结果，不提供旧动作"]
    G -->|返回| J["回到原列表：筛选、已加载批次与位置不变"]
```

<a id="fig-6"></a>
## 全部已读（图 6）

```mermaid
flowchart TD
    A["用户在消息列表中选择全部已读"] --> B{"当前筛选下有未读?"}
    B -->|否| B1["操作不可用，并说明原因"]
    B -->|是| C["确认：写明当前筛选条件<br/>与将标为已读的未读条数，含未加载部分"]
    C -->|取消| C1["所有消息保持不变"]
    C -->|确认| D["执行中，不能重复提交"]
    D --> E{"结果"}
    E -->|成功| F["范围内全部变为已读，未读数更新<br/>按实际处理条数反馈"]
    E -->|失败| G["全部保持原状，可以重试"]
    E -->|登录失效| H["不提示成功，重新登录后按实际结果展示"]
```

确认之后新到的消息不在本次范围内；全部已读只改变本人的阅读状态。

<a id="state-1"></a>
## 本人阅读状态（状态机 1）

```mermaid
stateDiagram-v2
    [*] --> 未读: 消息产生
    未读 --> 已读: 本人打开详情且展示成功
    未读 --> 已读: 全部已读执行成功且在范围内
    未读 --> 未读: 详情加载失败、已读保存失败或全部已读失败
    已读 --> 已读: 再次打开或同一事实重复送达
```

- 已读是终态，本期没有“标为未读”。
- 状态属于“本人与这条消息”：全体运营消息对每位运营管理人员各有一份阅读状态。
- 运营账号开通前已存在的全体运营消息，对新账号直接为已读，不计入未读数。
