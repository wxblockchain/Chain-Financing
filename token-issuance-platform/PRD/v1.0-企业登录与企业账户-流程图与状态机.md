## 登录与身份判定（图 1）

```mermaid
flowchart TD
    A[未登录访问者发起连接钱包] --> B{钱包可用且已解锁?}
    B -->|否| B1[说明原因：安装、启用或解锁钱包后重试<br/>仍为未登录]
    B -->|是| C[在钱包中选择以太坊地址]
    C --> D{钱包在以太坊网络?}
    D -->|否| D1[提示切换到以太坊网络后重试<br/>不建立登录]
    D -->|是| E[说明签名只证明钱包归属<br/>不发起交易、不转移或授权资产]
    E --> F[用户在钱包中签名]
    F --> G{签名有效且签名地址与所选地址一致?}
    G -->|拒绝签名或验证不通过| G1[不建立登录，可重试]
    G -->|签名地址已变化| G2[中止并说明地址已变化<br/>可用钱包当前地址重新登录]
    G -->|请求已失效| G3[提示重新签名]
    G -->|通过| H[按登录地址到资产可信平台匹配]
    H --> I{匹配结果}
    I -->|匹配到个人信息和企业信息| J[企业态：可使用面客端业务功能<br/>登录地址自动列入数币账户]
    I -->|匹配不到| K[游客态：显示引导<br/>前往资产可信平台进行注册 / 联系平台管理人员]
    I -->|有个人信息无企业信息| K
    I -->|一个地址匹配到多个企业| L[本次登录不成立，仍为未登录<br/>说明暂时无法确认身份，请联系平台管理人员]
    I -->|上游不可用或超时| M[本次登录不成立，仍为未登录<br/>说明暂时无法确认身份，可重试]
```

“有个人信息无企业信息”“一个地址匹配到多个企业”“上游不可用或超时”三条分支的口径待确认，见功能册[待确认事项](./v1.0-企业登录与企业账户-PRD.md#pending)。

## 退出、切换钱包与钱包地址变化（图 2）

```mermaid
flowchart TD
    A[已登录：企业态或游客态] --> B{发生了什么}
    B -->|主动退出| C[结束登录，回到未登录<br/>不残留上一个地址的资料]
    B -->|切换钱包| C
    C --> C1[可用另一个地址重新登录<br/>按图 1 重新匹配，不继承原地址身份]
    B -->|登录到期| D[回到未登录并说明<br/>需重新签名登录]
    B -->|钱包内切换到另一个地址| E{是否处于新增数币账户的签名环节<br/>且切换到被登记的地址?}
    E -->|是| E1[不视为切换登录钱包<br/>本次登录仍对应原登录地址]
    E -->|否| F[提示钱包地址与登录地址不一致]
    F --> G{用户选择用新地址重新登录?}
    G -->|是| C
    G -->|暂不选择| H[本次登录仍对应原登录地址<br/>不自动改用新地址]
```

登录有效期待确认，见功能册[登录有效期（Q-M1-01）](./v1.0-企业登录与企业账户-PRD.md#Q-M1-01)。

## 新增数币账户与地址归属签名（图 3）

```mermaid
flowchart TD
    A[企业态用户选择新增数币账户] --> B[告知：只支持以太坊地址<br/>只能登记本企业能签名的地址]
    B --> C[填写账户名称和以太坊地址]
    C --> D{账户名称不为空且地址符合以太坊格式?}
    D -->|否| D1[指出具体原因，不能进入签名]
    D1 --> C
    D -->|是| E{本企业已有该地址，含登录地址?}
    E -->|是| E1[说明已存在，可查看已有那一条<br/>不能进入签名]
    E -->|否| F[说明签名用途：证明地址归本企业控制<br/>不发起交易、不改变当前登录]
    F --> G[用户在钱包中切换到被登记的地址并签名<br/>当前登录不变]
    G --> H{签名结果}
    H -->|钱包不可用或不在以太坊网络| H1[说明原因，账户未登记，可重试]
    H -->|拒绝签名或验证不通过| H1
    H -->|签名地址与被登记地址不一致| H2[说明签名的地址和要登记的地址不是同一个<br/>账户未登记，可重试]
    H -->|请求已失效| H3[提示重新签名]
    H -->|通过| I{保存成功?}
    I -->|否| I1[说明未登记成功，可重试<br/>不留下半条账户]
    I -->|是| J[登记成功，验证状态为已验证<br/>立即出现在列表和发行申请可选范围]
```

```mermaid
flowchart TD
    A[企业态用户对某账户选择删除] --> B{是登录地址这一条?}
    B -->|是| B1[不提供删除]
```

## 登录地址变更后的同步（图 5）

```mermaid
flowchart TD
    A[企业在资产可信平台把登录地址改为新地址] --> B[企业用新地址登录本平台]
    B --> C{匹配到同一企业?}
    C -->|是| D[进入企业态，原有数币账户、申请与代币全部保留]
```

<a id="state-1"></a>
## 面客端登录状态机

```mermaid
stateDiagram-v2
    state "未登录" as S0
    state "签名与匹配中" as S1
    state "企业态" as S2
    state "游客态" as S3
    [*] --> S0
    S0 --> S1: 连接钱包并签名
    S1 --> S0: 签名未通过、请求失效、上游不可用或一个地址匹配到多个企业
    S1 --> S2: 匹配到个人信息和企业信息
    S1 --> S3: 匹配不到
    S2 --> S0: 主动退出、切换钱包或登录到期
    S3 --> S0: 主动退出、切换钱包或登录到期
```

- 初始状态是未登录；没有终态，退出后可再次登录。
- 企业态和游客态之间不直接转换：游客在上游完成注册后，须退出并重新登录，经过一次签名与匹配才进入企业态。
- 匹配到个人信息但没有企业信息时当前进入游客态，一个地址匹配到多个企业时回到未登录，两者口径见功能册[匹配结果异常的处理（Q-M1-03）](./v1.0-企业登录与企业账户-PRD.md#Q-M1-03)。

<a id="state-2"></a>
## 数币账户状态机

```mermaid
stateDiagram-v2
    state "填写与签名中（不是账户）" as A0
    state "有效·未被引用" as A1
    state "有效·被引用" as A2
    state "已删除" as A3
    [*] --> A0: 企业选择新增
    A0 --> [*]: 取消、校验不通过或签名失败，不产生账户
    A0 --> A1: 地址归属签名通过并保存成功
    A1 --> A2: 被处理中的发行申请选用，或有代币铸造到该账户
    A2 --> A1: 引用全部解除
    A1 --> A3: 企业确认删除
    A3 --> [*]
```

- 只有“有效”的两个状态是账户，可在列表中查看、在发行申请中选用；两者都可以修改账户名称。
- “有效·被引用”不能删除。申请被驳回终止即解除该申请的引用；按[被代币引用的范围（Q-M1-11）](./v1.0-企业登录与企业账户-PRD.md#Q-M1-11)当前口径，代币引用不会解除。
- 已删除是终态，不可恢复；需要时重新新增并签名，产生新的账户。
- 登录地址这一条不走本状态机：首次进入企业态时由系统列入，始终有效，不能编辑或删除，随上游登录地址变更而更新地址。
