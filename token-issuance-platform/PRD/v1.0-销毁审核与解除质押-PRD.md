# 销毁审核、解除监管与代币台账 · 功能与业务规则

2026-10-30｜管理端：运营管理人员、监管机构｜需求评审稿

本模块共四册：01 本册、[02 流程图与状态机](./v1.0-销毁审核与解除质押-流程图与状态机.md)、[03 消息通知](./v1.0-销毁审核与解除质押-消息通知.md)、[04 验收](./v1.0-销毁审核与解除质押-验收.md)。文件名沿用 issue 指定的“销毁审核与解除质押”；业务正文按用户后续确认使用“监管”“解除监管”。

依据：WS-506 简报 v1.6 的销毁流程、第 5 节状态及第 11 节配对约定；M4a 现行四册；M2、M3b、M5、M6、M7 现行正式文档。用户在 WS-508 已确认“本平台只有监管”，监管与融资分开；该确认优先于简报中的旧名称。【确认】表示用户口径，【建议·已采纳】表示简报已采纳建议；其余为落实这些要求的业务细化。布局与交互承载由 Hallmark 决定。

## 1. 模块是什么

企业从面客端提交销毁申请后，运营在管理端核对到期、结清和融资质押情况，通过审核即执行代币销毁，驳回则留下意见。销毁失败由运营手动重试；成功后原监管机构在平台办理解除监管并留下记录。运营查看全平台代币台账，监管机构查看本机构代币台账，两端持续使用同一笔申请与结果。

基本原则：

- 企业发起、运营审核与销毁、原监管机构解除监管的职责固定（BR-06、BR-14、BR-15）【确认】。
- 到期、结清、融资、监管、销毁分别表达；监管中不阻断销毁，解除监管不替代解除融资质押。
- 销毁成功事实与解除监管进度分开；未知结果不能当失败重新销毁，销毁成功不能提前当作监管已解除。
- 本册维护[两端衔接字段清单](#handoff)，M4a 直接引用，不各建一套。所有对象与消息定位到原记录，历史不因再次申请而覆盖。

**一个完整的例子。** 企业 A 对 50,000.00 USD 的代币提交销毁申请。运营甲看到已到期、上游已结清，下游与链上均无融资质押，核对原代币和数量后通过，申请进入销毁中。首次执行失败，甲手动重试后成功，代币成为已销毁，企业收到成功消息，原监管机构 X 收到解除监管待办。X 核对该资产、销毁数量和时间，在平台确认解除并留记录；企业看到已解除监管、X 和解除时间。运营与 X 都能从台账回看原发行、历次销毁申请及解除记录，再返回原列表。

### 1.2 本期不做

- 运营代企业发起申请、监管机构代运营审核销毁、运营代监管机构解除监管。
- 部分销毁、输入任意销毁数量、批量处理、撤销或修改已提交申请。
- 自动重试、企业重试、销毁失败后另建销毁申请、成功后恢复代币。
- 在本平台办理融资或解除融资质押、更换原合约、数币地址或原监管机构。
- 台账编辑、转账、导出或新增统计分析；本期以查看和业务追溯为范围。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 融资质押 | 企业在下游借贷平台用代币融资形成的质押；下游结果与链上验证共同作为销毁校验依据 |
| 监管 | 原发行申请所选机构对资产的监管，从铸造成功开始，到该机构在平台解除并留记录结束 |
| 处理中申请 | 待运营审核、销毁中、销毁失败的销毁申请；销毁失败等待运营重试仍占用原申请 |
| 销毁成功 | 对应代币及本次完整数量已经确认销毁的事实，随后等待原机构解除监管 |
| 原监管机构 | 发行申请提交时选定的机构，机构改名、停用或更正账号不改变业务归属 |

<a id="access"></a>
## 3. 权限、入口与共同异常

### 3.1 身份及数据范围

- 运营在销毁审核和代币台账内查看全平台数据，只有运营能通过、驳回和重试销毁；运营不能办理解除监管。
- 监管机构在解除监管及台账内只查看本机构代币、对应销毁申请、关联资产与解除记录；只有原监管机构能解除。监管机构不进入运营销毁审核菜单。
- 机构停用后仍可登录、收到在途业务消息、办理已有代币的解除，业务不会改属其他机构【确认】，沿用[停用与启用（F-RG-05）](./v1.0-监管机构管理-PRD.md#F-RG-05)。
- 未登录、待首次改密、会话失效、无权菜单及操作按[管理端无权访问（F-LG-12）](./v1.0-管理端登录与权限-PRD.md#F-LG-12)处理；跨机构对象和不存在对象结果相同，不返回数据。列表、直接访问、办理、文件查看与下载均按当前身份判断。
- 企业只在 M4a 按本册[企业可见范围](#handoff-release)查看结果，不能调用管理端办理动作。退出或切换账号后清除旧身份内容，迟到结果不展示旧身份数据。

### 3.2 入口、展示与返回

- 运营从销毁审核列表、台账关联记录或运营待审／失败消息进入准确申请；监管从解除监管列表、台账或解除待办消息进入准确解除事项。进入不自动办理。
- 详情可返回原列表或原消息；业务关联可定位原代币、资产、发行申请和历次销毁申请，不能用最新一笔替换消息所指记录。目标不可访问时保留返回路径。
- 数量两位小数、币种 USD；网络 Ethereum、标准 ERC-3525。地址缩写并可核对完整值，沿用[地址展示](./v1.0-企业登录与企业账户-PRD.md#address-display)。
- 字段名、状态与业务说明支持中英文；意见、备注、名称等业务原文不自动翻译。管理端时间按[界面语言与时区（F-LG-09）](./v1.0-管理端登录与权限-PRD.md#F-LG-09)展示，时区切换不改变到期判断、事件先后和结果。

<a id="common-errors"></a>
### 3.3 缺失、失败与重复操作

- 读取中、读取失败、确实无记录分别表达；读取失败可以重新获取，部分信息失败保留其他已取得内容。
- 到期、结清、融资校验、销毁或解除结果缺失时说明无法确认，不补成零、无质押、成功或已解除；已取得的成功事实不因暂时读不到其他信息而倒退。
- 提交前按当前权限与当前阶段复核。其他人已经处理时显示实际结果，旧动作不再生效；同一申请不能被重复审核、重复发起销毁或重复解除。
- 明确未成功的业务提交保留原状态及可恢复的填写内容，可以重新核对后提交；结果暂未确认时只允许重新取得原操作的实际结果，不能宣称失败或另起执行。
- 取消确认不产生业务结果或通知。通知暂不可见不回滚已成功的业务，不要求用户重办。
- 申请与代币、资产、原合约、原机构或数量无法对应，或出现“未销毁却已解除”等矛盾时，展示已确认事实及无法确认项，不能放行销毁或解除。由运营核查原记录与外部结果；本期没有强制改状态的入口。

<a id="A-BURN-01"></a>
## 4. 销毁审核列表（A-BURN-01）

适用角色：已登录且账号可用的运营管理人员。

- 查看全平台企业实际提交成功的历次销毁申请，包括驳回、销毁失败、待解除监管及已解除监管记录；同一代币多次申请各自保留。
- 每条展示销毁申请编号、企业名称、上游资产编号、代币编号、申请数量与币种、提交时间、当前申请阶段，可进入对应详情。字段统一取[申请信息](#handoff-application)。
- 无申请时说明暂无销毁申请；读取失败按[共同异常](#common-errors)处理，不能显示为空。

<a id="A-BURN-02"></a>
## 5. 销毁详情与条件核对（A-BURN-02）

适用角色：运营管理人员，记录在可查看范围内。

- 展示[代币与申请信息](#handoff-token)、[审核与执行记录](#handoff-review)、[销毁结果](#handoff-burn)及已产生的[解除记录](#handoff-release)。可前往原发行申请、关联资产、代币及本代币其他申请。
- 核对到期时点、上游结清事实、下游融资质押结果与链上验证结果；到期判定沿用[可信资产的到期依据](./v1.0-可信资产-PRD.md#overdue)，结清不能按余额或回款金额推断。
- 业务条件复用 M4a [销毁资格](./v1.0-我的代币与销毁申请-PRD.md#eligibility)中的已到期、上游明确已结清，以及[融资双重校验](./v1.0-我的代币与销毁申请-PRD.md#finance-check)两项均无质押（BR-07、BR-20）【确认】【建议·已采纳】。企业提交时的“没有处理中申请”不用于拒绝本笔待审或失败申请；管理端防重按本申请当前阶段、没有其他执行及没有销毁成功事实判断。
- 两项融资结果不一致时按有融资质押处理，并提示企业联系平台（简报 Q26）【建议·已采纳】；运营可以核对两项实际结果。任一结果无法确认均不能放行；多个不满足项同时说明，不用单项通过掩盖其他限制。
- 历史申请展示本次审核时的条件依据，并区分当前再次取得的条件，不用新值改写原审核事实。到期、结清及融资结果只读，运营不能手工覆盖外部结果。

<a id="actions"></a>
### 5.1 当前阶段与可办理动作

| 当前申请阶段 | 运营动作 | 原监管机构动作 | 企业结果 |
| --- | --- | --- | --- |
| 待运营审核 | 条件齐备可通过；可填写意见驳回 | 仅在本机构台账查看关联信息 | 等待运营审核，不能再提交同代币申请 |
| 驳回 | 查看原审核及意见 | 查看本机构历史 | 满足当前条件后创建新申请，旧申请不恢复待审 |
| 销毁中 | 查看并取得原执行结果，不重试或驳回 | 查看本机构进度 | 等待结果，不能重提 |
| 销毁失败 | 当前条件齐备且明确失败时手动重试 | 查看状态，不重试 | 看到失败并等待运营处理，不能重提 |
| 销毁成功 | 查看成功事实，不再执行 | 承接待解除事项 | 代币已销毁，等待解除监管 |
| 待解除监管 | 查看成功事实及解除进度 | 本机构可核对后解除 | 代币已销毁，监管中 |
| 已解除监管 | 查看历史 | 查看解除记录，不能再次解除 | 代币已销毁，监管已解除 |

本表的后两阶段对应简报“待解除资产质押”“已解除质押”，仅名称按用户确认映射；停用合约的办理边界见[停用合约影响（Q-M4B-01）](#Q-M4B-01)。

<a id="A-BURN-03"></a>
## 6. 通过并执行销毁（A-BURN-03）

适用角色与前提：运营管理人员，申请仍待运营审核，尚无成功销毁事实且没有其他执行占用该代币；[销毁条件](#A-BURN-02)全部满足。

- 确认内容包括销毁申请编号、代币与资产、完整数量币种、原数币地址和合约、原监管机构，并说明通过即执行销毁、成功后仍由原机构解除监管（BR-06）【确认】。
- 通过时不重新选择数量、账户或合约，也不要求运营额外填写通过意见。
- 提交时重新核对当前前置条件及原代币、申请数量的一致性；不满足或无法确认时，申请保持待运营审核，显示具体限制，可重新获取条件或主动驳回，不自动驳回。
- 提交成功记录审核通过、审核方、运营审核人及时间，立即进入销毁中并执行原代币的本次完整数量；不增加审核后等待另一位运营执行的阶段。
- 执行仍在进行或结果未确认时保持销毁中。确认失败时进入销毁失败，保留失败记录并发送[销毁失败待重试（NT-A04）](./v1.0-销毁审核与解除质押-消息通知.md#NT-A04)。
- 只有链上已确认与原代币、原合约、本次完整数量一致的成功结果，才记录[销毁成功事实](#handoff-burn)，代币成为已销毁，形成原监管机构待解除事项。结果不符按[共同异常](#common-errors)处理，不当作本次成功。
- 成功时分别发出[销毁成功（NT-C06）](./v1.0-销毁审核与解除质押-消息通知.md#NT-C06)和[代币已销毁、待解除监管（NT-R02）](./v1.0-销毁审核与解除质押-消息通知.md#NT-R02)；通知、待办读取失败不允许再次销毁。

流程参见[运营审核与执行（图 1）](./v1.0-销毁审核与解除质押-流程图与状态机.md#fig-1)。

<a id="A-BURN-04"></a>
## 7. 驳回销毁申请（A-BURN-04）

适用角色与前提：运营管理人员，申请仍待运营审核。查看前置条件未通过或暂无法取得时，仍可作出有意见的驳回，不因此自动驳回。

| 可填写字段 | 类型、含义 | 必填、默认与可编辑性 | 校验及失败结果 |
| --- | --- | --- | --- |
| 驳回意见 | 文本，说明本次不通过的理由 | 驳回时必填，无默认值；仅本次提交前由运营编辑 | 空值或纯空白不能提交；长度上限待[填写与凭证边界（Q-M4B-02）](#Q-M4B-02)确认，不擅自套用其他环节上限 |

- 提交成功后原申请为驳回，记录意见、审核时间与审核人，意见以原文展示，任何角色不能修改已生效结果。
- 本次未执行销毁，不形成解除待办；发送[销毁申请驳回（NT-C07）](./v1.0-销毁审核与解除质押-消息通知.md#NT-C07)。
- 释放原申请对代币的处理中占用，代币按当前融资事实回到正常（未质押）或融资质押中；融资未知时显示无法确认，不伪装正常。原驳回记录及其消息保留。
- 企业再次发起须按 M4a 重新判断资格并创建新申请；运营不能把驳回的原申请改回待审。并发或取消按[共同异常](#common-errors)。

<a id="A-BURN-05"></a>
## 8. 销毁失败手动重试（A-BURN-05）

适用角色与前提：运营管理人员，原申请为销毁失败且原次执行已明确失败，没有成功销毁事实，当前[销毁条件](#A-BURN-02)仍满足。

- 手动重试沿用原申请、代币、原合约、原地址及完整数量币种；无需重新审批，不新增申请，不允许企业或监管机构代操作（BR-14）【确认】。
- 确认重试时能核对原申请、代币和数量；提交时重新核对权限、当前状态、到期、结清及两项融资结果。条件改变或无法确认时保留销毁失败，说明限制；不是新增失败终态，也不自动驳回。
- 成功受理本次重试后记录本次操作人和时间，申请回到销毁中；再次失败保留新一次失败记录并再发运营告警；成功按[通过并执行销毁](#A-BURN-03)承接结果。
- 刷新、重新登录或仅有外部条件恢复不触发自动重试；结果未确认时先取得原执行结果，不能按超时自行认定失败再执行。重复或并发重试只产生一次实际执行。
- 既有审核、失败和重试记录全部保留，企业只看申请状态及最终结果；完整失败说明及运营账号仅运营可见，见[审核与执行记录](#handoff-review)。重试次数、等待时长不另设无来源阈值。

<a id="R-RELEASE-01"></a>
## 9. 解除监管列表（R-RELEASE-01）

适用角色：已完成首次改密且账号可用的监管机构，包括已停用机构的在途业务。

- 只列本机构监管、已经确认代币销毁成功的事项，提供待解除与已解除两类结果；此分类不是额外状态。
- 每项可识别企业、上游资产编号、代币编号、销毁申请编号、销毁数量币种、销毁成功时间；已解除项另显示解除时间，可进入准确详情。
- 未销毁、销毁中、销毁失败或驳回不形成解除待办。消息已读不移出待解除列表，只有解除提交成功才进入已解除。
- 没有记录与读取失败分别展示，按[共同异常](#common-errors)处理；机构停用、更名或更正账号不丢历史。

<a id="R-RELEASE-02"></a>
## 10. 解除监管详情（R-RELEASE-02）

适用角色与前提：原监管机构，属于本机构的解除事项。

- 展示本笔企业与资产、原代币与合约、申请识别信息、销毁结果数量和成功时间、监管机构及当前解除进度；可进入关联资产、原发行和销毁记录。
- 字段与可见性直接使用[两端衔接字段清单](#handoff)，不向监管机构展示运营账号、内部失败说明、企业账户备注名或其他企业账户。
- 待解除时提供[解除监管并留记录](#R-RELEASE-03)；已解除时展示既有记录，不提供再解除、编辑或删除。
- 从旧待办消息进入时按当前事实展示；已经完成只看结果，无权或不存在统一拒绝。解除依据缺失或矛盾时保留已确认内容，不能直接确认完成，按[共同异常](#common-errors)。

<a id="R-RELEASE-03"></a>
## 11. 解除监管并留记录（R-RELEASE-03）

适用角色与前提：原监管机构，代币已确认销毁成功、事项仍待解除监管。

- 监管机构在平台主动确认解除该笔资产的监管并留记录（BR-21）【确认】，不把阅读消息、下载资料或代币已销毁视为解除。
- 确认前展示企业、资产、代币、成功销毁的数量币种和时间，说明操作完成后留存解除记录。原监管机构只读，不可另选；操作人和时间由本次实际操作形成，不让用户填写历史时间或冒填他人。

| 可填写字段 | 类型、含义 | 必填、默认与可编辑性 | 校验及失败结果 |
| --- | --- | --- | --- |
| 解除备注 | 文本，本次解除的补充说明 | 选填，无默认值；提交前原机构可编辑；未填不阻断 | 仅空白按未填处理；长度上限见[填写与凭证边界（Q-M4B-02）](#Q-M4B-02) |
| 解除凭证 | 文件，本次解除的可选证明材料【建议·已采纳】 | 选填，无默认文件；提交前可增删本次待提交文件 | 已选择的文件须全部上传成功，失败可重试或移除后不带凭证提交；格式、份数及大小待[填写与凭证边界（Q-M4B-02）](#Q-M4B-02)确认 |

- 重新核对当前身份、原机构归属、已销毁事实与待解除进度。提交成功形成[解除记录](#handoff-release)，申请成为已解除监管，监管情况成为已解除监管，代币保持已销毁；可查看记录并返回原列表。
- 同一事实只形成一份生效解除记录，不能重复解除。备注和已提交凭证随记录保留，任何角色不能编辑、补传、替换或删除本次生效记录；未填备注或凭证不影响正常完成。
- 取消、明确提交失败或结果暂未确认，按[共同异常](#common-errors)处理；未成功不能展示已解除、解除时间或发结果消息。
- 成功发送[资产已解除监管（NT-C08）](./v1.0-销毁审核与解除质押-消息通知.md#NT-C08)给资产所属企业；不再给运营或其他监管机构新增通知。

流程参见[原监管机构解除监管（图 4）](./v1.0-销毁审核与解除质押-流程图与状态机.md#fig-4)。

<a id="A-TOKEN-01"></a>
## 12. 全平台代币台账（A-TOKEN-01）

适用角色：运营管理人员。台账本身为简报【建议·已采纳】范围。

- 列出全平台成功铸造的全部代币，包含融资中、销毁申请中和已销毁代币；未铸造成功的发行申请不算代币，销毁不删除台账。
- 每条展示代币编号、企业、上游资产编号、数量币种、原数币地址、合约、到期日、融资情况、结清情况、监管机构、监管情况及销毁进度。详情使用[代币信息](#handoff-token)。
- 可从台账追溯原发行申请与铸造结果、关联资产、历次销毁申请和最终解除记录；审核或重试必须回到有当前办理资格的销毁申请，不因台账可见而额外授权。
- 名称采用当前值、申请与执行事实采用各次生效记录；融资与结清是当前外部事实，未知时明确标示，不用代币已销毁推断当前融资。
- 资产在 M2 的发行状态保持已发行【确认】，销毁及解除不将资产恢复可发行；业务后续情况在代币与申请中查看。
- 无成功代币与读取失败分别表达；失败可重新获取，不允许台账直接改状态或销毁。

<a id="R-TOKEN-01"></a>
## 13. 本机构代币台账（R-TOKEN-01）

适用角色：监管机构。台账本身为简报【建议·已采纳】范围，机构隔离为【确认】（BR-15）。

- 仅展示原发行申请选择本机构的成功代币，包含尚在监管、待解除及已解除的历史代币；范围不因机构停用或账户更正改变。
- 可看代币、对应企业与资产、数量币种、原数币地址、合约、到期、融资与结清情况、监管起止及销毁进度；可追溯本机构原发行、历次销毁及解除记录。
- 数据项沿用[两端衔接字段清单](#handoff)的监管列。地址只看本笔代币原地址，不看企业账户备注名、其他账户、运营账号或内部失败说明。
- 属于本机构且已销毁待解除时可以前往对应解除事项；处于其他阶段只查看，不能从台账审核、重试或提前解除。
- 空列表、读取异常、无权及历史保留按[共同规则](#access)。

## 15. 对象与状态对应

销毁申请和代币真实阶段引用简报第 5 节；监管名称按 WS-508 用户确认映射，不另建并行流程。M2 已确认资产发行状态在铸造后保持已发行，销毁与解除不改发行状态。

| 简报原阶段 | 本模块及 M4a 对应表达 | 代币及监管结果 |
| --- | --- | --- |
| 待运营审核 | 待运营审核 | 代币为销毁申请中；监管中 |
| 驳回 | 驳回 | 取消本申请占用，按当前融资事实回到正常（未质押）／融资质押中；监管中 |
| 销毁中 | 销毁中 | 代币为销毁申请中；监管中 |
| 销毁失败 | 销毁失败 | 仍是销毁申请中；运营重试后回销毁中，监管中 |
| 销毁成功 | 销毁成功事实 | 代币已销毁；监管中，承接下一阶段 |
| 待解除资产质押 | 待解除监管 | 代币已销毁；监管中，原机构待办理 |
| 已解除质押 | 已解除监管 | 代币已销毁；已解除监管 |

- 成功事实与待解除可以在同次结果承接中出现，用户无需停留在一个中间画面；销毁时间与数量必须保留。
- 驳回只结束该申请，当前融资未知则说明无法确认并限制新申请，不能用旧“正常”放行；有新申请后，旧申请仍为驳回，代币当前进度关联新申请。
- “未融资／融资中”是企业融资展示；无法确认是信息可用情况，不新增代币终态。监管中不等于有融资质押。

### 停用合约影响（Q-M4B-01）

M6 的[停用对在途业务的影响（Q-CT-01）](./v1.0-合约管理-PRD.md#Q-CT-01)仍未裁定已铸造代币在合约停用后能否提交、通过或重试销毁。M4a 的[停用合约依赖（Q-M4A-02）](./v1.0-我的代币与销毁申请-PRD.md#Q-M4A-02)与此为同一问题。

当前处理：查看原代币、历史及已经确认的销毁结果不受平台停用影响；不据此承诺停用后可以继续执行，也不把合约可用擅加为所有销毁的通用资格。仅停用相关办理分支待验，不判通过。推荐平台停用只限制新发行选择，既有代币继续在原合约销毁；链上不可用时保留原申请由运营处理。该推荐仍需用户裁定，不套用“停用后不可重试铸造”到销毁。

<a id="Q-M4B-02"></a>
### 填写与凭证边界（Q-M4B-02）

销毁驳回意见与解除备注的长度上限、可选解除凭证的格式、份数和单份大小无确认依据。简报的 PDF／图片、10 份、10MB 只适用于发行监管协议，不能自行扩展到解除凭证。

当前处理：驳回意见必填且排除空白；备注与凭证选填，未填可以完成解除；文件上传失败不能假装提交成功。上限、格式及超限分支待验，不判通过，不阻断其他功能评审。建议凭证沿用监管协议的格式与大小限制、文字采用与已有审核一致的上限，须经确认后写入有效规则。

### 依赖与跨模块同步

| 提供方 | 本模块使用的信息及不可用影响 |
| --- | --- |
| M4a | 产生申请，引用本册唯一清单并展示结果；本模块不代企业发起 |
| M2／上游 D3 | 提供带时区到期依据、结清事实与资产信息；必要依据无法取得不能通过或重试，不推断已结清 |
| M3b | 提供原发行申请与成功代币结果；旧文档的监管质押称谓在本模块映射为监管，不改变起止环节 |
| 下游 D4、Ethereum D5 | 提供融资状态与双重校验、同一代币销毁结果；不可用或未知不能放行，也不能自行认定执行失败 |
| M5 | 提供当前身份、机构及账号；停用机构继续办在途，改名或换账号不改属 |
| M6 | 提供原合约及当前名称；平台停用和链上可执行性分开，停用销毁边界待裁定 |
| M7 | 承接本模块五类消息，事件由[03 消息通知](./v1.0-销毁审核与解除质押-消息通知.md)维护；消息异常不要求重复业务操作 |

外部信息取得、链上执行与确认的实现由研发负责，验证由测试负责；本册不规定协议、确认参数、轮询周期或技术重试机制。端到端销毁流程仍在 WS-506 统一验收，本模块文件对齐不代表真实联调或需求评审已经通过。
