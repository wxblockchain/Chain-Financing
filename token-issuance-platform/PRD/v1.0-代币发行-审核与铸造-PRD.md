## 1. 模块是什么

代币发行·审核与铸造是管理端处理企业发行申请的地方。企业在代币发行·企业申请（M3a）提交申请后，所选的监管机构在这里做一审：与企业线下签署监管协议后，通过时上传协议，或填写意见驳回。一审通过后，平台运营做二审：通过时选择铸造合约，平台随即在 Ethereum 上铸造代币；也可以填写意见驳回。铸造失败时，由运营手动重试。监管机构和运营共用同一个申请详情，按角色区分能看到的数据和能做的操作。

基本原则：

- 审核顺序固定：监管一审 → 运营二审 → 铸造（BR-03）【确认】。任一级驳回，申请直接终止，不能修改，这笔资产也不能再次发起（BR-12）【确认】。
- 监管机构只看选择了本机构的申请（BR-15）【确认】；运营可查看全平台全部状态的申请，只能对待运营审核、铸造失败的申请操作【确认】，见[数据范围（F-LG-11）](./v1.0-管理端登录与权限-PRD.md#F-LG-11)。
- 监管协议在线下签署；监管机构一审通过时必须上传，PDF 或图片，最多 10 份，每份不超过 10MB（BR-10、BR-11）【确认】。
- 运营二审通过时必须选择铸造合约，可选范围按资产类型筛选（BR-14）【确认】【建议·已采纳】。代币数量、到期日和接收地址都取申请记录，审核人不能修改。
- 申请状态只引用简报第 5 节，本模块不另行定义；资产的发行状态以[发行状态](./v1.0-可信资产-PRD.md#issue-status)为准。两端衔接的信息以本册[两端衔接字段清单](#handoff)为唯一口径，M3a 引用。

**一个完整的例子。** 企业 A 以一笔 50,000.00 USD、到期日 2027-03-31 的应收账款提交了发行申请，选择监管机构 C，接收账户为“A 公司收币地址”。C 收到“新的待审申请”，在发行审核中看到这笔申请处于“待监管审核”，查看申请信息和关联资产。A 与 C 线下签署监管协议后，C 上传两份协议文件（一份 PDF、一份扫描图片），填写审核意见后一审通过；申请变为“待运营审核”，A 收到“监管审核通过”，全体运营收到“待二审的申请”。运营甲打开这笔申请，核对资产、企业、监管意见和协议，从可用合约中选择资产类型为应收账款的 ERC-3525 合约，确认代币数量 50,000.00、到期日和接收地址后二审通过；申请变为“铸造中”，A 收到“运营审核通过”。首次铸造失败，申请变为“铸造失败”，全体运营收到“铸造失败待重试”，A 不收消息；运营乙查看失败说明后重试，申请回到“铸造中”。铸造成功后，申请变为“铸造成功”，资产发行状态变为“已发行”，这笔资产自铸造成功起由 C 监管质押；A 收到“铸造成功”，在 M3a 的申请详情中看到铸造结果。

### 1.2 本期不做

- 企业提交、撤回或修改发行申请：企业提交属于 M3a；提交后任何角色都不能撤回或修改（BR-12）【确认】。
- 驳回后重新打开申请，或把申请退回上一环节修改：驳回即终止【确认】。
- 在平台上签署监管协议：协议线下签署，平台只接收监管机构上传的文件（BR-10、D7）【确认】。
- 一审通过后替换、删除或补传协议文件。
- 审核人修改代币数量、币种、到期日或接收地址：数量按应收账款美元金额 1:1（BR-19）【确认】，到期日取应收账款到期日（BR-13）【确认】，接收地址取企业提交时的选择。
- 合约的部署与初始配置由开发人员负责；运营在[合约管理（M6）](./v1.0-合约管理-PRD.md)查看、编辑名称、启用和停用【确认】；本模块只选择合约，不维护合约信息。
- 代币铸造之后的融资质押、销毁和解除质押：属于我的代币与销毁申请（M4a）、销毁审核、解除质押与代币台账（M4b）。
- 运营内部分派、认领审核任务：全体运营看到同一批申请，谁先提交谁的结果生效，见[操作的共同要求](#concurrency)。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 发行申请 | 企业以一笔可信资产申请铸造代币的记录，由 M3a 提交产生，有唯一的申请编号 |
| 一审 | 企业所选监管机构对发行申请的审核，通过时必须上传监管协议 |
| 二审 | 平台运营对一审已通过的发行申请的审核，通过时必须选择铸造合约 |
| 本机构的申请 | 对某个监管机构而言，企业提交时选择了该机构的发行申请 |
| 监管协议 | 企业与所选监管机构线下签署、由监管机构在一审通过时上传的协议文件 |
| 监管意见 | 监管机构一审通过时填写的审核意见，选填 |
| 驳回意见 | 监管机构或运营驳回时填写的理由，必填 |
| 铸造合约 | 运营二审时选择、用于铸造这笔代币的合约；合约由开发人员配置，在合约管理（M6）中查看 |
| 可用合约 | 资产类型为应收账款、网络为 Ethereum、状态为启用或同义状态的合约【确认】；合约管理现行名称为“可用”，见[可选合约范围](#available-contracts) |
| 铸造 | 二审通过后，平台用所选合约在 Ethereum 上为企业铸造代币，结果为成功或失败 |
| 监管质押 | 监管机构对这笔资产的质押，从代币铸造成功开始，到监管机构解除质押为止（BR-21）【确认】 |
| 处理中的发行申请 | 申请状态为待监管审核、待运营审核、铸造中或铸造失败的申请，与 M3a、[企业登录与企业账户](./v1.0-企业登录与企业账户-PRD.md)的口径一致 |
| 终止的发行申请 | 申请状态为监管驳回或运营驳回的申请 |

## 3. 谁能使用

依据：发行审核菜单对运营与监管的可见性与操作【确认】（简报 4.4）；监管机构只能看到本机构的申请（BR-15）【确认】。

| 身份 | 能看到发行审核吗 | 能看到哪些申请 | 能做什么 |
| --- | --- | --- | --- |
| 运营管理人员（账号正常、已登录） | 看得到 | 全平台全部状态的发行申请【确认】 | 待运营审核时二审通过（选择合约）或二审驳回；铸造失败时按[重试条件](#A-ISSUE-07)重试；其他状态只能查看【确认】 |
| 监管机构（账号正常、已登录，含机构已停用） | 看得到 | 只有本机构的申请，任何状态 | 本机构待监管审核申请的一审通过（上传协议）、一审驳回；其他状态只能查看 |
| 待首登改密、锁定的管理端账号；未登录 | 看不到 | 无 | 按[账号状态](./v1.0-管理端登录与权限-PRD.md#account-status)和[无权访问的处理（F-LG-12）](./v1.0-管理端登录与权限-PRD.md#F-LG-12)处理 |

- 监管机构被停用后，仍可查看本机构的全部申请，并继续审核已选择它的待审申请【确认】，见[停用与启用（F-RG-05）](./v1.0-监管机构管理-PRD.md#F-RG-05)。
- 访问范围以外的申请或不存在的申请（包括通过直接链接、改写编号访问），结果完全相同：不返回任何内容，统一说明“无权查看或申请不存在”，不透露申请是否存在，见[无权访问的处理（F-LG-12）](./v1.0-管理端登录与权限-PRD.md#F-LG-12)。协议文件下载同样适用。
- 发起本角色没有的操作（例如监管机构尝试二审，运营尝试一审），被拒绝，申请不变，说明无权操作。
- 拒绝由平台判定，不能只靠隐藏入口；绕过界面提交审核同样被拒绝。

### 3.1 入口

- 管理端“发行审核”菜单，运营与监管机构都可见，见[菜单权限矩阵（F-LG-10）](./v1.0-管理端登录与权限-PRD.md#F-LG-10)。进入后是本人范围内的[发行申请列表（R-ISSUE-01、A-ISSUE-01）](#R-ISSUE-01)。
- 从可信资产的资产详情中关联的发行申请进入该申请的[申请详情（R-ISSUE-02、A-ISSUE-02）](#R-ISSUE-02)：运营见[全平台资产列表与资产详情](./v1.0-可信资产-PRD.md#F-AS-05-assets)，监管机构见[监管机构查看关联资产（F-AS-06）](./v1.0-可信资产-PRD.md#F-AS-06)。
- 从消息进入：监管机构的“新的待审申请”（M3a 发出，见[新的待审申请（NT-R01）](./v1.0-代币发行-企业申请-消息通知.md#NT-R01)），运营的“待二审的申请”“铸造失败待重试”（本模块发出），打开后进入该笔申请的申请详情，按当前身份、权限和申请当前状态重新判断，见[前往原业务（MSG-05）](./v1.0-消息通知-PRD.md#MSG-05)。

<a id="concurrency"></a>
### 3.2 操作的共同要求

本节适用于一审通过、一审驳回、二审通过、二审驳回和铸造重试五个操作。

- 每个操作执行前须确认；取消或离开不保存未提交的内容，包括已上传但未提交的协议文件、已填写的意见和已选的合约，申请保持原状态。
- 提交时以申请的最新状态判断：申请已不在该操作适用的状态（例如另一位运营已完成二审、已重试），本次操作不执行，说明这笔申请的状态已变化并展示最新状态和结果；不重复执行，不覆盖他人的结果。
- 提交进行中给出处理中反馈，同一次操作不能重复提交；重复点击、刷新或网络重发都只生效一次。
- 保存失败时申请保持原状态，可以重试，不出现只改了一部分的情况（例如状态已变但协议未保存）。
- 提交过程中登录结束（主动退出、登录到期或无操作登出）时，按[登录有效期、无操作登出与退出（F-LG-06）](./v1.0-管理端登录与权限-PRD.md#F-LG-06)处理；未确认生效的操作视为未提交，迟到的结果不显示。
- 每个操作须可追溯：操作的账号、所属角色（监管机构另记机构）、时间、操作前后的申请状态，以及意见、协议文件、所选合约等提交内容。

## 4. 查看发行申请

<a id="R-ISSUE-01"></a><a id="A-ISSUE-01"></a>
### 4.1 发行申请列表（R-ISSUE-01、A-ISSUE-01）

适用角色与前提：账号正常、已登录的监管机构或运营管理人员。

- 监管机构列出本机构的全部发行申请；运营列出全平台的全部发行申请。两者都包括处理中、终止和铸造成功的申请。
- 每笔申请展示：申请编号、企业名称、上游资产编号、预计发行数量与币种、监管机构名称、提交时间、申请状态。
- 可以按申请状态筛选；可以按申请编号、上游资产编号或企业名称查找。
- 待本人处理的申请须能直接识别：监管机构为“待监管审核”，运营为“待运营审核”和“铸造失败”。
- 可以进入每笔申请的[申请详情（R-ISSUE-02、A-ISSUE-02）](#R-ISSUE-02)。
- 申请状态变化后，列表展示最新状态。
- 还没有任何申请时，说明暂无发行申请；筛选或查找没有结果时，说明没有符合条件的申请，与“暂无申请”区分。
- 读取失败时说明暂时无法获取，可以重试；不说成“没有申请”。
- 监管机构看到的条数、筛选和查找结果只包含本机构的申请，见[数据范围（F-LG-11）](./v1.0-管理端登录与权限-PRD.md#F-LG-11)。

<a id="R-ISSUE-02"></a><a id="A-ISSUE-02"></a>
### 4.2 申请详情（R-ISSUE-02、A-ISSUE-02）

适用角色与前提：账号正常、已登录的监管机构（申请属于本机构）或运营管理人员。

依据：监管和运营共用同一个申请详情，按角色区分操作和数据范围【确认】（简报第 11 节）。

申请详情由以下几部分组成，各项含义与可见范围以[两端衔接字段清单](#handoff)为准：

- 申请信息：见[申请信息](#handoff-application)。另展示企业名称，运营可以进入该企业在可信资产中的企业详情，见[运营查看企业与资产（F-AS-05）](./v1.0-可信资产-PRD.md#F-AS-05)；监管机构看不到企业详情。
- 关联资产：上游资产编号、债务人名称、应收账款金额与币种、到期日，以及资产最新的确权、结清、逾期状态【确认】和发行状态（[资产状态定义](./v1.0-可信资产-PRD.md#status-fields)）；可以进入该资产在可信资产中的资产详情。运营另看到[上游变更提示](./v1.0-可信资产-PRD.md#upstream-change)（上游已撤销确权、上游已删除）；监管机构看不到这类提示。
- 审核进度：按顺序展示提交、监管一审、运营二审、铸造四个环节；每个环节展示是否已完成、结果和完成时间，尚未到达的环节展示为未开始。各环节展示的内容见[审核结果与意见](#handoff-review)。
- 监管协议：见[查看与下载监管协议（R-ISSUE-03、A-ISSUE-03）](#R-ISSUE-03)。
- 铸造结果：见[铸造结果（A-ISSUE-06）](#A-ISSUE-06)。
- 当前可做的操作：按下方组合表。

<a id="status"></a>
**申请状态与各角色看到的内容、能做的操作。** 申请状态引用简报第 5 节：待监管审核 → 监管驳回（终止）/ 待运营审核 → 运营驳回（终止）/ 铸造中 → 铸造成功 / 铸造失败（→ 运营重试 → 铸造中）【建议·已采纳】。

| 申请状态 | 监管机构（本机构）能做什么 | 运营能做什么 | 监管协议 | 铸造结果 | 资产发行状态 |
| --- | --- | --- | --- | --- | --- |
| 待监管审核 | 一审通过（上传协议）或一审驳回 | 只能查看 | 无 | 无 | 发行申请中 |
| 监管驳回 | 只能查看，申请已终止 | 只能查看，申请已终止 | 无 | 无 | 已驳回 |
| 待运营审核 | 只能查看 | 二审通过（选择合约）或二审驳回 | 监管机构与运营都可查看、下载 | 无 | 发行申请中 |
| 运营驳回 | 只能查看，申请已终止 | 只能查看，申请已终止 | 监管机构与运营都可查看、下载 | 无 | 已驳回 |
| 铸造中 | 只能查看 | 只能查看；不能重试、不能驳回 | 监管机构与运营都可查看、下载 | 正在铸造 | 发行申请中 |
| 铸造失败 | 只能查看；看到铸造失败，看不到失败说明 | 原合约可用时可重试；原合约不可用时保持铸造失败，恢复后可手动重试，见[铸造失败手动重试（A-ISSUE-07）](#A-ISSUE-07)；看到每次失败的时间与失败说明 | 监管机构与运营都可查看、下载 | 失败记录（仅运营可见失败说明） | 发行申请中 |
| 铸造成功 | 只能查看 | 只能查看 | 监管机构与运营都可查看、下载 | 展示铸造结果 | 已发行 |

- 监管驳回、运营驳回、铸造成功是终态，申请不再变化；铸造成功后代币的后续状态在代币台账（M4b）中查看。
- 资产发行状态一列由可信资产模块定义，此处只说明对应关系。
- 操作入口只在上表允许的状态、对上表允许的角色出现；绕过界面发起同样被拒绝，见[谁能使用](#access)。

其他规则：

- 申请信息是提交时的记录，不随资产或账户之后的变化而改变；关联资产的状态展示最新值。
- <a id="review-asset-change"></a>申请提交后，资产在上游被撤销确权、删除，或已逾期、已结清时，都不自动拦截审核、铸造或重试，也不自动终止申请；详情向审核人展示资产最新的确权、结清、逾期状态，运营另见上游变更提示，由审核人判断是否驳回【确认】。能否驳回仍按[申请状态与角色](#status)判断，铸造中、铸造失败时不增加驳回操作。
- 确权、结清、逾期信息的来源与含义分别沿用可信资产的[确权状态](./v1.0-可信资产-PRD.md#confirm-status)和[结清与逾期依据](./v1.0-可信资产-PRD.md#overdue)。申请详情保留上述最新信息供审核人判断；进入可信资产详情后按该模块的[回款状态归并](./v1.0-可信资产-PRD.md#repayment-status)展示。上游已删除的资产按可信资产规则保留最近一次信息，不编造新的状态。
- 上游平台暂时不可用时，申请详情照常可查看，关联资产展示本平台最近一次保存的信息，见[上游平台暂时不可用](./v1.0-可信资产-PRD.md#common-errors)；审核操作不依赖上游，照常可用。
- 读取失败时说明暂时无法获取，可以重试。
- 字段名称、状态取值和说明文字按本人当前界面语言展示中文或英文；金额、数量、编号、机构名称、企业名称、文件名称、意见原文不随语言变化；所有时间按本人时区展示并标明时区，见[界面语言与时区（F-LG-09）](./v1.0-管理端登录与权限-PRD.md#F-LG-09)。

流程参见：[发行申请状态（图 3）](./v1.0-代币发行-审核与铸造-流程图与状态机.md#fig-3)、[查看申请与数据范围（图 4）](./v1.0-代币发行-审核与铸造-流程图与状态机.md#fig-4)。

### 4.3 查看与下载监管协议（R-ISSUE-03、A-ISSUE-03）

适用角色与前提：申请的一审已通过（申请状态为待运营审核、运营驳回、铸造中、铸造失败或铸造成功）；监管机构限本机构的申请。

依据：运营二审时查看监管协议，企业和运营都可以查看 / 下载监管协议（BR-18）【确认】；协议在一审通过时上传（BR-10）【确认】。

- 展示一审通过时上传的全部协议文件，每份可以单独查看和下载；每份展示文件名称、上传时间和上传的监管机构。
- 文件名称按上传时的原文展示。
- 一审通过前（待监管审核）和监管驳回的申请没有协议，也不能通过直接访问取得；一审过程中已上传但未提交的文件，任何人都看不到。
- 一审通过后，任何角色都不能替换、删除或补传协议文件。
- 企业在 M3a 中查看同一批文件，见[查看与下载监管协议（C-ISSUE-07）](./v1.0-代币发行-企业申请-PRD.md#C-ISSUE-07)。
- 查看或下载失败时说明本次未能打开，可以重试；不影响查看申请的其他信息。

## 5. 监管一审

依据：监管一审只看本机构申请；通过时必须上传监管协议，通过后转运营二审；驳回需填写意见，驳回即终止（R-ISSUE、BR-03、BR-10、BR-11、BR-12、BR-15）【确认】。

流程参见：[监管一审（图 1）](./v1.0-代币发行-审核与铸造-流程图与状态机.md#fig-1)。

<a id="R-ISSUE-04"></a>
### 5.1 监管一审：上传协议并通过（R-ISSUE-04）

适用角色与前提：账号正常、已登录的监管机构；申请属于本机构，状态为“待监管审核”。机构已停用的照常可以办理【确认】。

- 通过前须上传监管协议，至少 1 份、最多 10 份。
- 可以选填监管意见；监管意见对运营可见，对企业不可见，见[审核结果与意见](#handoff-review)。
- 提交前可以移除已上传的文件、继续添加，直到总数达到 10 份。
- 确认时须说明：通过后申请转入运营二审；协议文件提交后不能替换或删除；企业和运营都可以查看、下载这些文件。

协议文件与监管意见：

| 业务信息 | 含义/类型 | 必填条件/默认值 | 可编辑范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 监管协议文件 | 企业与本机构线下签署的协议；文件，可多份 | 通过时必填，至少 1 份；无默认值 | 提交前可添加、移除；提交后不能修改 | 格式须为 PDF、JPG、JPEG、PNG【确认】，其他格式不添加并说明支持的格式；单份超过 10MB 的不添加并说明上限；总数已达 10 份时不能再添加并说明上限；空文件不添加；单份上传失败时说明该文件未上传成功，可重试或移除，不影响其他文件 |
| 监管意见 | 一审通过时的审核意见；文本 | 选填；无默认值 | 提交前可修改；提交后不能修改 | 最多 500 个字符【确认】，超过时说明上限、不能提交；只含空格视为未填写 |

- 只有上传成功的文件计入份数；有文件仍在上传或上传失败未移除时，不能提交通过，并说明原因。
- 一次提交中同名文件可以并存，各自作为一份。

提交时再次核对：申请仍为“待监管审核”且仍属于本机构，按[操作的共同要求](#concurrency)处理。

通过成功后：

- 申请状态变为“待运营审核”；记录一审结果“通过”、通过时间、操作账号、监管意见和全部协议文件。
- 资产发行状态保持“发行申请中”。
- 协议文件即时对运营（本模块）和企业（M3a）开放查看与下载。
- 向企业发送[监管审核通过（NT-C01）](./v1.0-代币发行-审核与铸造-消息通知.md#NT-C01)，向全体运营发送[待二审的申请（NT-A01）](./v1.0-代币发行-审核与铸造-消息通知.md#NT-A01)。
- 监管机构看到一审已通过，申请转为只能查看。

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 没有上传成功的文件就提交 | 不能提交，说明通过时须上传监管协议 |
| 文件格式、大小、份数或空文件不符合要求 | 该文件不添加，说明具体原因；已添加的其他文件保留 |
| 申请状态已变化（例如已在另一个登录中处理） | 不执行，说明状态已变化，展示最新状态 |
| 保存失败 | 说明一审未提交成功，申请仍为待监管审核，已上传的文件和已填写的意见保留，可以重试 |

<a id="R-ISSUE-05"></a>
### 5.2 监管一审：驳回（R-ISSUE-05）

适用角色与前提：同[监管一审：上传协议并通过（R-ISSUE-04）](#R-ISSUE-04)。

| 业务信息 | 含义/类型 | 必填条件/默认值 | 可编辑范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 驳回意见 | 驳回的理由，企业与运营都可见；文本 | 必填；无默认值 | 提交前可修改；提交后任何角色都不能修改 | 为空或只含空格时不能提交，说明须填写驳回意见；最多 500 个字符【确认】，超过时说明上限、不能提交 |

- 驳回不需要上传协议文件；驳回时不保存任何协议文件。
- 确认时须说明：驳回后申请终止，不能撤销，企业不能修改申请，这笔资产不能再次发起发行申请。

驳回成功后：

- 申请状态变为“监管驳回”，终态；记录驳回时间、操作账号和驳回意见。
- 资产发行状态变为“已驳回”，见[发行状态](./v1.0-可信资产-PRD.md#issue-status)。
- 申请不再构成对接收账户的引用，见[删除数币账户（C-ACCOUNT-04）](./v1.0-企业登录与企业账户-PRD.md#C-ACCOUNT-04)。
- 向企业发送[监管审核驳回（NT-C02）](./v1.0-代币发行-审核与铸造-消息通知.md#NT-C02)；不给运营发消息。

驳回意见为空、申请状态已变化或保存失败时，申请保持“待监管审核”，按上表和[操作的共同要求](#concurrency)提示，已填写的意见保留。

## 6. 运营二审

依据：二审查看申请、资产、监管意见与协议；通过时选择铸造合约后铸造；驳回需填写意见，驳回即终止（A-ISSUE、BR-03、BR-12、BR-14、BR-18）【确认】；合约按资产类型筛选【建议·已采纳】。

流程参见：[运营二审与铸造（图 2）](./v1.0-代币发行-审核与铸造-流程图与状态机.md#fig-2)。

<a id="A-ISSUE-04"></a>
### 6.1 运营二审：选择铸造合约并通过（A-ISSUE-04）

适用角色与前提：账号正常、已登录的运营管理人员；申请状态为“待运营审核”。任何一位运营都可以办理。

- 通过时须从可用合约中选择一个铸造合约；不预选，一笔申请只能选一个。
- 每个可选合约展示：合约名称、标准（ERC-3525）、对应资产类型（应收账款）、所在网络（Ethereum）和合约地址；可以核对完整合约地址。合约信息以合约管理（M6）为准，名称展示取[当前已保存名称（F-CT-03）](./v1.0-合约管理-PRD.md#F-CT-03)；改名不改变二审所选合约及其地址。
- <a id="available-contracts"></a>只列出资产类型为应收账款、网络为 Ethereum、状态为启用或同义状态的合约【确认】；合约管理现行名称为“可用”，见[发行二审可选的合约（F-CT-02）](./v1.0-合约管理-PRD.md#F-CT-02)。三个条件须同时满足；不满足任一条件的合约不出现在可选范围中。
- 确认时须展示本次铸造的内容并说明不能修改：代币数量与币种（两位小数，USD）、到期日、接收地址（可核对完整地址）、所选合约名称与合约地址；并说明通过后平台随即铸造，结果另行展示。

| 业务信息 | 含义/类型 | 必填条件/默认值 | 可编辑范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 铸造合约 | 用于铸造这笔代币的合约；单选，从可用合约中选 | 通过时必填；不预选 | 提交前可改选；提交后不能更换，重试也沿用，见[铸造失败手动重试（A-ISSUE-07）](#A-ISSUE-07) | 未选择时不能提交；提交时所选合约已不可用的，不能提交，说明该合约当前不可用，要求重新选择 |

提交时再次核对：申请仍为“待运营审核”；所选合约仍为可用合约。

通过成功后：

- 记录二审结果“通过”、通过时间、操作账号和所选合约；申请状态变为“铸造中”。
- 平台随即用所选合约，按申请记录的代币数量、到期日，把代币铸造到申请记录的接收地址，见[铸造结果（A-ISSUE-06）](#A-ISSUE-06)。
- 资产发行状态保持“发行申请中”。
- 向企业发送[运营审核通过（NT-C03）](./v1.0-代币发行-审核与铸造-消息通知.md#NT-C03)；不给监管机构发消息。

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 没有任何可用合约 | 说明暂无可用的铸造合约，已有匹配但停用的合约时可在合约管理启用，没有匹配合约时需由开发人员配置；不能通过，仍可驳回 |
| 合约读取失败 | 说明暂时无法获取合约，可以重试；不说成“没有可用合约” |
| 未选择合约就提交 | 不能提交，说明须选择铸造合约 |
| 所选合约在提交时已不可用 | 不能提交，说明该合约当前不可用，要求重新选择；申请仍为待运营审核 |
| 申请状态已变化（例如另一位运营已完成二审） | 不执行，说明状态已变化，展示最新状态和结果 |
| 保存失败 | 说明二审未提交成功，申请仍为待运营审核，可以重试；不发起铸造 |

<a id="A-ISSUE-05"></a>
### 6.2 运营二审：驳回（A-ISSUE-05）

适用角色与前提：同[运营二审：选择铸造合约并通过（A-ISSUE-04）](#A-ISSUE-04)。

| 业务信息 | 含义/类型 | 必填条件/默认值 | 可编辑范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 驳回意见 | 驳回的理由，企业与监管机构都可见；文本 | 必填；无默认值 | 提交前可修改；提交后任何角色都不能修改 | 为空或只含空格时不能提交，说明须填写驳回意见；最多 500 个字符【确认】，超过时说明上限、不能提交 |

- 驳回不需要选择合约。
- 确认时须说明：驳回后申请终止，不能撤销，企业不能修改申请，这笔资产不能再次发起发行申请；已上传的监管协议保留。

驳回成功后：

- 申请状态变为“运营驳回”，终态；记录驳回时间、操作账号和驳回意见。
- 资产发行状态变为“已驳回”。
- 申请不再构成对接收账户的引用，见[删除数币账户（C-ACCOUNT-04）](./v1.0-企业登录与企业账户-PRD.md#C-ACCOUNT-04)。
- 监管协议照常保留，企业、监管机构和运营仍可查看、下载。
- 向企业发送[运营审核驳回（NT-C04）](./v1.0-代币发行-审核与铸造-消息通知.md#NT-C04)；不给监管机构发消息。

驳回意见为空、申请状态已变化或保存失败时，申请保持“待运营审核”，按上表和[操作的共同要求](#concurrency)提示，已填写的意见保留。

## 7. 铸造

依据：二审通过后铸造；铸造失败由运营手动重试（BR-14）【确认】；铸造成功后资产进入监管质押（BR-21）【确认】；需要“铸造中”状态承接链上结果返回前的时间差【建议·已采纳】；同一笔资产不可重复铸造（BR-08）【建议·已采纳】。

<a id="A-ISSUE-06"></a>
### 7.1 铸造结果（A-ISSUE-06）

适用角色与前提：运营管理人员；监管机构限本机构的申请。申请已进入铸造（状态为铸造中、铸造失败或铸造成功）。

- 铸造使用二审所选合约；代币数量等于申请记录的预计发行数量（两位小数，USD），到期日等于申请记录的到期日，接收地址等于申请记录的接收地址。应收账款的金额与到期日由上游提交后不再变更【确认】，所以铸造结果与申请记录一致。
- 一笔申请最多铸造成功一次；铸造中不能再次发起铸造。
- 铸造中：申请详情说明代币正在铸造；不提供重试或驳回。

铸造成功时：

- 申请状态变为“铸造成功”，终态；记录[铸造结果](#handoff-mint)。
- 资产发行状态变为“已发行”。
- 这笔资产自铸造成功起由所选监管机构监管质押，开始时间为铸造时间（BR-21）【确认】；监管质押的解除属于 M4b。
- 接收账户转为被代币引用，按[删除数币账户（C-ACCOUNT-04）](./v1.0-企业登录与企业账户-PRD.md#C-ACCOUNT-04)不能删除。
- 代币进入代币台账（M4b）与企业的我的代币（M4a）；申请详情可以进入代币台账查看这枚代币。
- 向企业发送[铸造成功（NT-C05）](./v1.0-代币发行-审核与铸造-消息通知.md#NT-C05)；不给运营和监管机构发消息。

铸造失败时：

- 申请状态变为“铸造失败”；记录这一次失败的时间和失败说明（取得时记录，取不到时不展示，不编造原因）。
- 资产发行状态保持“发行申请中”；接收账户仍被这笔申请引用。
- 运营在申请详情中看到每一次失败的时间和失败说明，以及每一次重试的时间和操作账号；监管机构只看到“铸造失败”，看不到失败说明；企业按 M3a 只看到铸造失败、无需操作，看不到失败说明。
- 向全体运营发送[铸造失败待重试（NT-A03）](./v1.0-代币发行-审核与铸造-消息通知.md#NT-A03)，每次失败一条；不给企业和监管机构发消息。

<a id="A-ISSUE-07"></a>
### 7.2 铸造失败手动重试（A-ISSUE-07）

适用角色与前提：账号正常、已登录的运营管理人员；申请状态为“铸造失败”。任何一位运营都可以办理。

- 重试一律沿用二审所选合约，不能改选【确认】；代币数量、到期日和接收地址沿用申请记录，不能更改。
- 提交重试时再次核对申请仍为“铸造失败”、二审所选合约仍符合[可选合约范围](#available-contracts)。
- 确认时须展示本次重试的合约、代币数量与币种、接收地址。
- 重试成功发起后，申请状态回到“铸造中”，之后按[铸造结果（A-ISSUE-06）](#A-ISSUE-06)处理；记录重试时间和操作账号。
- 重试不是新的审核通过，不再发送[运营审核通过（NT-C03）](./v1.0-代币发行-审核与铸造-消息通知.md#NT-C03)。
- 本期不限制重试次数。

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 二审所选合约已不可用 | 不能重试，说明原合约当前不可用；申请保持“铸造失败”，不能改选合约【确认】。平台停用的合约可由运营按[启用与停用合约（F-CT-04）](./v1.0-合约管理-PRD.md#F-CT-04)启用；链上部署等异常由开发人员恢复。原合约可用后，运营再手动重试，启用本身不发起铸造 |
| 申请状态已变化（例如另一位运营已重试） | 不执行，说明状态已变化，展示最新状态 |
| 发起失败 | 说明本次未能重新发起铸造，申请保持铸造失败，可以再次重试 |

## 8. 两端衔接字段清单

- 管理端登录与权限、监管机构管理（M5）：登录、菜单权限、数据范围、语言与时区、停用后的在途业务。

- Ethereum ERC-3525 合约（D5）：铸造的执行与成功、失败结果；铸造的实现、结果获取与验证由研发、测试负责。
- 线下协议签署（D7）：企业与监管机构线下签署监管协议，平台只接收上传的文件。
