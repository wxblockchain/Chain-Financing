## 登录与首次改密（图 1）

```mermaid
flowchart TD
    A[未登录访问者打开登录入口<br/>主动打开，或访问管理端页面时被要求登录并记住原目标] --> B[输入登录邮箱和密码并提交]
    B --> C{邮箱和密码是否正确}
    C -->|邮箱不是管理端账号| D[统一说明邮箱或密码错误]
    C -->|密码错误| E[统一说明邮箱或密码错误<br/>连续失败次数加 1，第 3 次起提示剩余次数]
    E --> E1{连续失败达到 5 次?}
    E1 -->|否| B
    E1 -->|是| E2[账号临时锁定<br/>15 分钟、30 分钟、之后每次 60 分钟]
    C -->|正确| F{账号状态}
    F -->|锁定中| G[说明已临时锁定和剩余时间<br/>到期后可直接重新登录]
    F -->|待首登改密| H[首次登录强制改密<br/>只能设置新密码、切换语言或退出]
    H --> H1{新密码符合规则且与初始密码不同?}
    H1 -->|否| H
    H1 -->|是| H2[账号变为正常，初始密码失效<br/>全部登录结束，请用新密码重新登录<br/>原目标在同一标签页内保留]
    H2 --> B
    F -->|正常| I[登录成功<br/>连续失败次数清零，锁定时长回到第一级<br/>首次登录时写入时区]
    I --> J{同一标签页内有原目标<br/>且在管理端范围内?}
    J -->|是| K{按当前角色和数据范围<br/>是否有权访问?}
    K -->|是| L[回到原目标]
    K -->|否| M[按无权访问的处理说明]
    J -->|否| N[进入本角色的默认页面]
```

<a id="state-1"></a>
## 管理端账号状态机

```mermaid
stateDiagram-v2
    state "待首登改密" as P
    state "正常" as N
    state "锁定（锁定前为待首登改密）" as LP
    state "锁定（锁定前为正常）" as LN
    [*] --> P: 开发人员分配运营账号，或运营邀请添加监管机构
    P --> N: 完成首次登录强制改密
    N --> P: 运营更正监管邮箱，或开发人员重新分配运营初始密码
    N --> N: 本人找回成功或自行改邮箱成功
    P --> P: 尚未首登改密的运营或监管账号本人找回成功
    P --> LP: 连续输错密码 5 次
    N --> LN: 连续输错密码 5 次
    LP --> P: 锁定到期
    LN --> N: 锁定到期
    LN --> LP: 锁定期间运营更正监管邮箱
```

- 两类账号初始状态均为待首登改密；本人找回与修改邮箱不改变角色或数据归属。本人改邮箱后仍是同一账号，监管机构仍只有一个有效管理端账号；旧邮箱凭据作废、旧登录结束，不再参与该账号的登录与找回。
- 锁定只是临时状态，到期自动回到锁定前的状态；锁定中本人不能完成找回；运营更正邮箱不提前解除锁定，锁定到期后用新邮箱首登改密。
- 监管机构的启用 / 停用是机构的状态，不在本状态机中，见[监管机构状态机](./v1.0-监管机构管理-流程图与状态机.md#state-1)；停用不改变账号状态，账号仍可登录。

<a id="state-2"></a>
## 登录状态机

```mermaid
stateDiagram-v2
    state "受限登录（只能改密、切换语言、退出）" as R
    state "已登录" as L
    state "已结束" as E
    [*] --> R: 待首登改密的账号输入正确邮箱和密码
    [*] --> L: 正常账号输入正确邮箱和密码
    R --> E: 完成改密、退出、到期、无操作、本人找回成功、邮箱替换或账号锁定
    L --> E: 退出、到期、无操作、本人改密、本人找回成功、邮箱替换成功、运营初始密码被重新分配或账号锁定
    E --> [*]
```

- 一次登录有效期为 4 小时，连续 30 分钟没有真实操作自动结束；两者先到先结束。
- 受限登录完成改密后直接结束，不会转为已登录；须用新密码重新登录，建立一次新的登录。
- 已结束是终态，不能恢复；之后迟到的操作结果不能让它恢复。

<a id="state-3"></a>
## 验证码状态机

```mermaid
stateDiagram-v2
    state "待使用" as V
    state "已使用" as U
    state "已过期" as E
    state "已作废" as X
    [*] --> V: 成功向合格目标邮箱发送本用途验证码
    V --> U: 本次密码或邮箱修改成功
    V --> E: 达到已确认的有效期
    V --> X: 同用途成功重发或达到错误上限
    V --> X: 密码或登录邮箱变更成功
    U --> [*]
    E --> [*]
    X --> [*]
```

- 验证码按账号、用途与目标邮箱分别有效；更换目标后不能把原目标的码用于新邮箱。
- 已使用、已过期与已作废均为终态；发送失败不产生可用验证码。时效与次数参数见[验证码待确认](./v1.0-管理端登录与权限-PRD.md#Q-LG-01)。
