## 可信资产的来源与进入本平台（图 1）

```mermaid
flowchart TD
    A[下游企业向本企业下单购买新车] --> B[本企业向厂商采购<br/>车辆海运直发下游指定仓库]
    B --> C[车辆到货<br/>下游企业提供发票]
    C --> D[本企业据发票生成<br/>对下游企业的应收账款]
    D --> E{下游企业在上游平台确权}
    E -->|未确权| F[不进入本平台<br/>任何角色都看不到]
    E -->|已确权| G[同步进入本平台<br/>确权状态：已确权<br/>发行状态：可发行]
    G --> H{L1 通用必传信息是否完整<br/>含销售发票}
    H -->|完整| I[可查看<br/>满足其他条件时可发起申请]
    H -->|有缺失| J[可查看，缺失项标明上游未提供<br/>不能发起申请]
    G --> K[下游企业回款<br/>每次回款带支付凭证，更新回款进度]
    G --> L{之后上游撤销确权或删除资产}
    L -->|是| M[只在运营端提示<br/>不自动改变任何状态]
```

<a id="fig-2"></a>
## 发行状态（图 2）

初始状态为“可发行”；“已驳回”和“已发行”是终态。铸造中、铸造失败待重试期间保持“发行申请中”。代币铸造之后的监管、融资和销毁属于代币，不改变发行状态。

```mermaid
stateDiagram-v2
    state "可发行" as S1
    state "发行申请中" as S2
    state "已驳回" as S3
    state "已发行" as S4

    [*] --> S1: 已确权应收账款同步进入本平台
    S1 --> S2: 企业提交发行申请成功（M3a）
    S2 --> S3: 监管一审驳回或运营二审驳回（M3b）
    S2 --> S4: 铸造成功（M3b）
    S3 --> [*]
    S4 --> [*]
```

## 确权与回款状态（图 4）

确权、结清、逾期事实都由上游平台提供；回款状态归并表达当前结果，与发行状态互不推动。是否到期以上游提供的、带时区的到期时点为准，查看者所选时区只影响展示。

```mermaid
stateDiagram-v2
    state "已确权" as C1
    state "已撤销确权" as C2
    [*] --> C1: 进入本平台
    C1 --> C2: 上游撤销确权
```

```mermaid
flowchart TD
    A[读取最新结清、逾期依据与到期时点] --> B{上游已确认结清}
    B -->|是| C[回款状态：已结清<br/>曾逾期时在回款进度说明]
    B -->|结清状态取不到| X[回款状态暂时无法确认<br/>不能发起申请，保留已取得信息]
    B -->|未结清| D{上游提供已逾期<br/>或已经触发到期兜底}
    D -->|是| E[回款状态：已逾期]
    D -->|否| F{上游提供未逾期<br/>且尚未到达到期时点}
    F -->|是| G[回款状态：未到期<br/>仍须满足其余发起条件]
    F -->|否，依据缺失或相互冲突| X
    G -->|到达到期时点且未结清<br/>上游未给最新状态| E
    G -->|上游提供已结清| C
    E -->|上游提供已结清| C
    X -->|依据补齐或冲突消除| A
```

到期兜底与上游后续更新的关系以[结清与逾期依据](./v1.0-可信资产-PRD.md#overdue)为准；原始依据继续保留。已结清的资产不再因到期回到已逾期，先逾期后结清按当前已结清筛选。

## 从可信资产发起发行申请（图 5）

```mermaid
flowchart TD
    A[已认证的企业用户查看本企业资产] --> B{发行状态为可发行}
    B -->|否| X[不提供发起<br/>说明：申请处理中 / 已驳回 / 已发行]
    B -->|是| C{确权状态为已确权}
    C -->|否| Y[不提供发起<br/>说明债权人确权已撤销]
    C -->|是| D{回款状态为未到期<br/>未结清、未逾期且未到达到期时点}
    D -->|否| Z[不提供发起<br/>详情说明已逾期 / 已结清 / 已到期 / 状态无法确认]
    D -->|是| E{币种为 USD、L1 完整含销售发票<br/>各状态均已取得}
    E -->|否| W[不提供发起<br/>说明仅支持美元计价 / 信息不完整 / 暂时无法确认状态]
    E -->|是| F[展示债权人已确权<br/>企业发起申请，进入代币发行·企业申请并带入资产]
    F --> G{企业是否提交}
    G -->|未提交就离开| H[资产保持可发行]
    G -->|提交| I{提交时按最新信息重新判断}
    I -->|不满足| J[不能提交，说明原因<br/>不产生第二笔申请]
    I -->|满足| K[提交成功<br/>发行状态变为发行申请中]
```

## 各角色的查看范围（图 6）

```mermaid
flowchart TD
    A[访问可信资产或企业信息] --> B{访问者身份}
    B -->|游客| G[看不到可信资产<br/>按游客引导处理]
    B -->|未认证的企业用户| U[看得到入口，看不到资产数据<br/>按认证引导处理]
    B -->|已认证的企业用户| C{资产的债权人是本企业}
    C -->|是| C1[可查看列表与详情<br/>可从满足条件的资产发起申请]
    C -->|否| N[无权查看或资产不存在<br/>不返回任何信息]
    B -->|监管机构| D{资产被本机构的发行申请使用}
    D -->|是| D1[可查看资产详情与本机构的这笔申请<br/>看不到企业信息、数币账户和上游变更提示]
    D -->|否| N
    B -->|运营管理人员| E[可查看全平台企业、资产、数币账户<br/>和上游变更提示，全部只读]
```
