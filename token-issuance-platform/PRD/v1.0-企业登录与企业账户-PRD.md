# 企业登录与企业账户 · 功能与业务规则

2026-10-29｜面客端：企业用户、游客｜需求评审稿

本模块共三册：本册写功能、业务规则、字段规则与交互逻辑；[流程图与状态机](./v1.0-企业登录与企业账户-流程图与状态机.md)画出主要流程与状态；[验收](./v1.0-企业登录与企业账户-验收.md)供测试使用。本模块自身不发送任何消息（登录、游客引导、数币账户变更都不发消息），所以没有 03 消息通知册，并非缺失。

依据标注：规则后的【确认】表示用户原文已明确，【建议·已采纳】表示诊断建议已由用户采纳，两者同样有效；未标注的是为落实上述规则所写的产品细化，涉及口径未定的已列入[待确认事项](#pending)。本册只定义信息需求与业务行为，页面布局、组件形态与交互承载由 Hallmark 设计决定。

## 1. 模块是什么

企业用户不在本平台注册，而是用以太坊钱包地址登录。本平台按登录地址到上游资产可信平台匹配个人信息和企业信息：匹配到即进入企业态，可以使用面客端的业务功能；匹配不到即为游客态，只能看到前往注册或联系平台的引导。企业态下，企业可以查看来自上游的企业信息，并维护自己的数币账户（企业账户），供发起代币发行申请时选择接收代币的账户。

基本原则：

- 身份来自上游：本平台不提供注册，也不采集、不修改个人与企业资料。
- 登录地址和数币账户用途不同：登录地址用于身份登录，数币账户用于接收代币。登录地址自动列入数币账户，只是多了一个可接收代币的选项。
- 数币账户没有默认账户，企业每次发起发行申请都要明确选一个接收账户。
- 数币账户里的每个地址都已证明归本企业控制：登录地址由登录签名证明，企业新增的地址由该地址的一次签名证明。

**一个完整的例子。** 企业 A 的操作人员用钱包中的登录地址连接本平台并签名登录。本平台按该地址在资产可信平台匹配到其个人信息和「A 公司」的企业信息，进入企业态。操作人员在企业信息中核对资料；在数币账户中看到系统已列入、标明“登录地址”的一条，又新增了一个名为“A 公司收币地址”的以太坊地址，用该地址签名通过后登记成功。之后发起代币发行申请时，操作人员从这两条中选择“A 公司收币地址”接收代币；该申请处理期间这一条不能删除。操作人员退出后回到未登录状态。

### 1.2 本期不做

- 在本平台注册企业或用户，或修改个人、企业资料：由资产可信平台负责。
- 钱包登录以外的登录方式，如账号密码、邮箱、手机验证码。
- 指定支持哪些钱包：接入成熟的钱包 SDK 服务商，具体钱包不在本册展开。
- 以太坊以外的网络。
- 默认数币账户，以及“设为默认”的操作。
- 法币（银行）账户：本模块的企业账户只指数币账户。
- 同一企业多个成员或多个登录地址：每个企业只有一个登录地址。
- 数币账户变更的审核与消息通知。
- 管理端查看企业的数币账户：由可信资产模块的企业查看功能（A-ASSET）定义。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 资产可信平台（上游） | 提供用户与企业身份、已确权应收账款等信息的外部平台。本册所称“上游”均指它 |
| 登录地址 | 企业在资产可信平台登记、用于登录本平台的以太坊钱包地址。每个企业只有一个 |
| 企业态 | 已登录，且登录地址在上游匹配到个人信息和企业信息。可以使用面客端业务功能 |
| 游客态 | 已登录，但登录地址在上游匹配不到。只能看到引导，不能使用业务功能 |
| 数币账户（企业账户） | 企业用于接收代币的以太坊地址清单，由系统列入的登录地址和企业自行新增的地址组成 |
| 登录签名 | 登录时用登录地址对一条登录消息签名，证明登录者控制该地址。不是交易，不转移或授权任何资产 |
| 地址归属签名 | 新增数币账户时，用要登记的那个地址签名一次，证明本企业控制该地址。不是登录，不改变当前登录 |
| 处理中的发行申请 | 状态为待监管审核、待运营审核、铸造中或铸造失败（待运营重试）的发行申请。状态口径以简报第 5 节为准 |

## 3. 登录与身份

<a id="C-AUTH-01"></a><a id="c-auth-01"></a>
### 3.1 连接钱包与签名登录（C-AUTH-01）

适用角色与前提：未登录的访问者。

依据：钱包地址登录、不在本平台注册（BR-01）【确认】；仅支持以太坊（BR-17）【确认】；登录时签名证明地址控制权【建议·已采纳，简报 9.2 节】。

- 未登录时只能通过连接钱包登录；本平台不提供注册入口，也不提供其他登录方式。
- 登录依次为：连接钱包 → 在钱包中选择以太坊地址 → 用该地址对登录消息签名。本平台验证签名通过才建立登录；只连接钱包、未完成签名不算登录。
- 登录地址只取自钱包，不能手动输入。
- 唤起签名前，先让用户知道本次签名只用于证明钱包归属，不发起交易，也不转移或授权任何资产。
- 签名通过后立即按[按地址匹配上游身份（C-AUTH-02）](#C-AUTH-02)判定进入企业态或游客态；判定期间给出处理中反馈。

登录过程中的异常：

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 没有可用钱包，或钱包无法唤起 | 说明原因，提示安装或启用钱包后重试；仍为未登录，不提供其他登录方式 |
| 用户取消连接，或钱包处于锁定状态 | 回到登录前的状态并说明原因（钱包已锁定时提示先解锁），可重新连接 |
| 钱包当前不在以太坊网络 | 提示在钱包中切换到以太坊网络后重试；不建立登录。绕过界面用其他网络签名同样不能登录 |
| 用户拒绝签名，或签名验证不通过 | 不建立登录，可重试 |
| 签名过程中钱包切换了地址，签名地址与所选地址不一致 | 中止本次登录并说明钱包地址已变化，可用钱包当前地址重新登录；不静默改用新地址 |
| 签名请求已失效（超过有效期或已被使用过） | 不建立登录，提示重新签名，由用户在钱包中重新确认。有效期见[签名请求的有效期（Q-M1-02）](#Q-M1-02) |

流程参见：[登录与身份判定（图 1）](./v1.0-企业登录与企业账户-流程图与状态机.md#fig-1)。

### 3.2 按地址匹配上游身份（C-AUTH-02）

适用角色与前提：刚完成登录签名的用户。

依据：按地址匹配上游，匹配到为企业态、匹配不到为游客态（BR-01、C-AUTH）【确认】；每个企业只有一个登录地址（BR-16）【确认】。

- 每次登录都按本次登录地址重新到上游匹配，不沿用上一次登录的结果。
- 只按登录地址匹配；不按企业名称、邮箱、手机号等其他信息近似匹配。
- 同一地址的大小写写法不同（以太坊地址校验格式），视为同一地址。

匹配结果与用户看到的结果：

| 匹配结果 | 本次登录结果 | 用户能做什么 |
| --- | --- | --- |
| 匹配到个人信息和企业信息 | 企业态 | 使用面客端业务功能：本模块的企业信息、数币账户，以及可信资产、代币发行、我的代币、销毁申请、消息通知（这些功能由各自模块定义） |
| 匹配不到（上游没有登记该地址） | 游客态 | 只看到游客引导，见[游客引导与功能限制（C-GUEST-01）](#C-GUEST-01) |
| 匹配到个人信息，但没有企业信息 | 当前按游客态处理 | 与游客态相同；口径见[匹配结果异常的处理（Q-M1-03）](#Q-M1-03) |
| 一个地址匹配到多个企业 | 本次登录不成立，仍为未登录；不取其中任何一个企业 | 说明暂时无法确认身份、请联系平台管理人员；口径见[匹配结果异常的处理（Q-M1-03）](#Q-M1-03) |
| 上游暂时不可用或超时，未得到匹配结果 | 本次登录不成立，仍为未登录；不当作“匹配不到”，不进入游客态 | 说明暂时无法确认身份、可重试登录；口径见[上游不可用时的登录结果（Q-M1-04）](#Q-M1-04) |

- 企业信息中带有上游认证状态。当前匹配到即进入企业态，认证状态只在企业信息中展示，不限制业务功能；是否需要认证通过才能使用业务功能见[上游认证状态是否影响企业态（Q-M1-05）](#Q-M1-05)。
- 本平台识别“同一个企业”依据上游提供的企业标识，而不是登录地址：企业的数币账户、发行申请和代币都归属于企业。登录地址变更后，企业用新地址登录并匹配到同一企业时，这些记录全部保留。所依据的上游标识见[识别同一企业的上游标识（Q-M1-07）](#Q-M1-07)。
- 登录期间上游发生变化（登录地址变更、企业信息变更、上游不再匹配该地址）时，下一次登录按新的匹配结果判定；登录期间何时发现并生效见[登录期间上游变化的生效时点（Q-M1-06）](#Q-M1-06)。

流程参见：[登录与身份判定（图 1）](./v1.0-企业登录与企业账户-流程图与状态机.md#fig-1)、[面客端登录状态机](./v1.0-企业登录与企业账户-流程图与状态机.md#state-1)。

### 3.3 退出与切换钱包（C-AUTH-03）

适用角色与前提：已登录的用户（企业态或游客态）。

依据：退出、切换钱包（C-AUTH）【确认】。

- 企业态和游客态都可以主动退出。退出后回到未登录状态，受保护的内容不能继续查看。
- 切换钱包等同于先退出当前登录，再用另一个地址重新登录：新地址按[按地址匹配上游身份（C-AUTH-02）](#C-AUTH-02)重新判定，不继承原地址的身份、资料或数据。
- 登录期间钱包内切换到了另一个地址时，提示当前钱包地址与登录地址不一致，并可选择用新地址重新登录（先结束当前登录，再走完整的签名与匹配）。用户做出选择前，本次登录仍对应原登录地址；不自动改用新地址。例外：新增数币账户时为签名切换到被登记的地址，不适用本条，见[新增数币账户（C-ACCOUNT-02）](#C-ACCOUNT-02)。
- 登录到期后回到未登录状态并说明，受保护的内容不能继续查看，需重新签名登录；登录有效期见[登录有效期（Q-M1-01）](#Q-M1-01)。
- 退出、到期或切换后，不残留上一个地址的资料或数据。

流程参见：[退出、切换钱包与钱包地址变化（图 2）](./v1.0-企业登录与企业账户-流程图与状态机.md#fig-2)。

## 4. 游客引导与功能限制（C-GUEST-01）

适用角色与前提：已登录、处于游客态的用户。

依据：引导文案【确认】；游客不能使用业务功能【建议·已采纳】。

- 游客态显示引导：“前往资产可信平台进行注册 / 联系平台管理人员”。
- 游客不能使用任何业务功能：企业信息、数币账户、可信资产、代币发行、我的代币、销毁申请、消息通知均不可用。游客直接访问这些功能时被拒绝，不返回任何业务数据；拒绝由平台判定，不能只靠隐藏入口。
- 游客态仍显示当前登录地址，便于用户到资产可信平台登记或向平台管理人员说明；可以退出或切换钱包。
- 用户在资产可信平台完成注册并登记该地址后，重新登录即按新的匹配结果进入企业态。
- 引导中是否提供前往资产可信平台的跳转入口、平台管理人员的联系方式是什么，见[游客引导的跳转与联系方式（Q-M1-13）](#Q-M1-13)。

## 5. 查看企业信息（C-PROFILE-01）

适用角色与前提：企业态用户。游客和未登录用户不可访问。

依据：数据来自上游【确认】；只读【建议·已采纳】；展示字段见简报第 7 节【分级方式确认，具体字段为建议·已采纳的初版】。

- 企业信息分三组呈现：个人信息、企业信息、当前登录地址。
- 全部只读，并说明“这些信息由资产可信平台维护”。本平台不提供编辑入口，不在本地录入、补填或推断资料；绕过界面的修改同样被拒绝。
- 资料对应本次登录匹配到的个人和企业；只有本人可见。
- 读取中、读取失败、单项未提供三种情况须可区分：读取中给处理中反馈；读取失败说明失败并可重试，不显示为空资料；上游未提供的单项明确为未提供，不由本平台补填。

| 分组 | 业务信息 | 展示要求 |
| --- | --- | --- |
| 个人信息 | 姓名 | 上游提供时展示 |
| 个人信息 | 手机 / 邮箱 | 上游提供时展示 |
| 个人信息 | 职务 | 上游提供时展示 |
| 企业信息 | 企业名称 | 必须展示 |
| 企业信息 | 统一社会信用代码 | 必须展示 |
| 企业信息 | 国家 / 地区、注册地址、法定代表人、联系人、联系方式 | 上游提供时展示 |
| 企业信息 | 上游认证状态 | 上游提供时展示；当前不影响业务功能，见[上游认证状态是否影响企业态（Q-M1-05）](#Q-M1-05) |
| 登录地址 | 本次登录使用的以太坊地址 | 必须展示；可查看完整地址并复制 |

上表字段为初版，最终以对接资产可信平台时确定的字段为准，见[企业信息的最终字段（Q-M1-14）](#Q-M1-14)。

## 6. 数币账户

<a id="account-common"></a>
### 6.1 共同规则

依据：企业维护数币账户、供铸造时引用、没有默认账户（BR-16、BR-25）【确认】；登录地址自动列入、不可编辑删除，新增账户须签名验证归属（BR-26）【建议·已采纳】；被引用的账户不可删除、修改不影响已铸造的代币（Q27）【建议·已采纳】。

- 只有企业态用户能查看和维护本企业的数币账户；游客和未登录用户看不到，直接访问被拒绝、不返回数据。
- 数币账户归属企业，不归属某个登录地址。每个企业只有一个登录地址，由使用该地址登录的人维护。
- 只支持以太坊地址。
- 没有默认账户：列表中没有“默认”标记，也没有“设为默认”的操作。
- 本企业内同一地址只能出现一次，登录地址也计算在内；比较时不区分大小写。
- 新增、编辑、删除不需要审核，也不发送消息；保存成功即生效，立即反映在列表和发行申请的可选范围中。
- 保存进行中给出处理中反馈，同一内容不重复保存；保存失败时保持上一次成功保存的状态，可以重试，不留下半条账户。取消或离开不保留未提交的内容。
- 本人查看数币账户时可看到完整地址并复制。

数币账户的信息：

| 业务信息 | 含义与类型 | 必填与默认 | 可编辑 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 账户名称 | 企业自定、便于辨识的名称（即账户备注）；文本 | 企业新增的账户必填，无默认值；登录地址这一条不设账户名称，以“登录地址”标明 | 企业新增的账户可编辑；登录地址这一条不可编辑 | 不能为空；长度上限见[账户名称长度上限（Q-M1-12）](#Q-M1-12)；本企业内允许重名 |
| 以太坊地址 | 接收代币的地址；文本 | 必填 | 登记后不可修改，见[编辑数币账户（C-ACCOUNT-03）](#C-ACCOUNT-03) | 须为以太坊地址格式（0x 开头加 40 位十六进制字符），否则不能进入签名；本企业内不能重复；须经地址归属签名通过才登记成功 |

以下信息由系统生成，本人只读：

| 业务信息 | 含义 |
| --- | --- |
| 来源 | “登录地址”或“企业新增” |
| 验证状态 | 地址是否已证明归本企业控制；列表中的账户都为“已验证”：登录地址由登录签名证明，企业新增的由地址归属签名证明。未通过签名不产生账户 |
| 创建时间 | 该账户登记成功的时点；登录地址这一条为首次列入的时点 |
| 更新时间 | 最近一次修改成功的时点；登录地址这一条为最近一次随上游登录地址更新的时点 |

### 6.2 数币账户列表与登录地址（C-ACCOUNT-01）

适用角色与前提：企业态用户。

- 列表展示本企业全部数币账户，包括登录地址这一条和企业新增的账户；每条可辨识账户名称（登录地址这一条标明“登录地址”）、以太坊地址、来源、验证状态和创建时间。
- 读取失败时说明暂时不可用并可重试，不能说成“没有账户”。
- 从列表可以新增账户，对企业新增的账户可以编辑或删除。

登录地址这一条：

- 企业首次进入企业态时由系统自动列入，标明“登录地址”。企业不新增任何账户，也能在发行申请中选它接收代币。
- 由系统维护，企业不能编辑或删除。
- 上游的登录地址变更后，企业用新地址登录并匹配到同一企业时，这一条随之更新为新地址；已经铸造到旧地址的代币不受影响，仍显示原地址。
- 旧地址此后登录时，在上游匹配不到即为游客态，不再能访问本企业数据。
- 登录地址变更时，处理中的发行申请若选的是这一条，代币铸造到哪个地址，见[登录地址变更对处理中申请的影响（Q-M1-08）](#Q-M1-08)；新登录地址此前已作为企业新增账户登记时如何处理，见[新登录地址与已有账户重复（Q-M1-09）](#Q-M1-09)。

| 账户 | 能否编辑 | 能否删除 | 能否在发行申请中选用 |
| --- | --- | --- | --- |
| 登录地址这一条 | 不能 | 不能 | 能 |
| 企业新增、未被引用的账户 | 能，仅账户名称 | 能 | 能 |
| 企业新增、被代币或处理中的发行申请引用的账户 | 能，仅账户名称 | 不能，说明被引用 | 能 |

### 6.3 新增数币账户（C-ACCOUNT-02）

适用角色与前提：企业态用户，并且能用要登记的那个地址在钱包中完成一次签名。

- 分两步：先填写账户名称和以太坊地址；再用该地址做地址归属签名，签名通过即登记成功，立即出现在列表和发行申请的可选范围中。
- 填写地址前就告知：只支持以太坊地址；只能登记本企业能用钱包签名的地址，交易所充值地址等由第三方托管、无法签名的地址无法登记。
- 地址不符合以太坊地址格式，或本企业已有该地址（包括与登录地址相同）时，不能进入签名，并说明具体原因；已有该地址时可直接查看已有的那一条。
- 签名前说明本次签名的用途：证明该地址归本企业控制，不发起交易，不转移或授权任何资产，也不改变当前登录。
- 签名时用户需在钱包中切换到被登记的地址。这次切换和签名不视为切换登录钱包：不结束当前登录，不改变登录地址和身份；签名完成后，本次登录仍对应原登录地址。
- 只有签名通过才产生账户。签名前填写的内容不是账户，不出现在列表，不参与重复判断，也不能被选用。
- 没有“跳过签名”“稍后验证”或由平台代为确认的方式。
- 平台只证明地址归属，不判断地址余额，也不给出“可收款”之类的结论。

签名环节的异常（以下情况都不登记账户、不改变当前登录，可以重试）：

| 情况 | 用户看到的结果 |
| --- | --- |
| 钱包不可用或无法唤起 | 说明原因，提示启用钱包后重试 |
| 钱包当前不在以太坊网络 | 提示在钱包中切换到以太坊网络后重试 |
| 用户拒绝签名，或签名验证不通过 | 说明未完成签名，账户未登记 |
| 签名地址与要登记的地址不一致 | 明确说明“签名的地址和要登记的地址不是同一个”，提示在钱包中切换到要登记的地址后重试 |
| 签名请求已失效 | 提示重新签名；有效期见[签名请求的有效期（Q-M1-02）](#Q-M1-02) |
| 签名通过但保存失败 | 说明账户未登记成功，可重试 |

流程参见：[新增数币账户与地址归属签名（图 3）](./v1.0-企业登录与企业账户-流程图与状态机.md#fig-3)、[数币账户状态机](./v1.0-企业登录与企业账户-流程图与状态机.md#state-2)。

### 6.4 编辑数币账户（C-ACCOUNT-03）

适用角色与前提：企业态用户；账户为企业新增，且未被删除。

- 只能修改账户名称，不需要重新签名；被引用的账户也可以修改名称。
- 以太坊地址登记后不能修改。需要换地址时，新增一个账户并重新签名，旧账户按[删除数币账户（C-ACCOUNT-04）](#C-ACCOUNT-04)另行删除。界面需说明这一点。口径见[数币账户的编辑范围（Q-M1-10）](#Q-M1-10)。
- 登录地址这一条不能编辑。
- 修改不影响已铸造的代币，也不改变已提交发行申请所选的接收地址。
- 名称为空或超出长度上限时，指出原因，保留原值；取消或离开不改变原值。

<a id="C-ACCOUNT-04"></a><a id="c-account-04"></a>
### 6.5 删除数币账户（C-ACCOUNT-04）

适用角色与前提：企业态用户；账户为企业新增。

- 登录地址这一条不能删除。
- 被引用的账户不能删除，并说明被什么引用。引用指以下任一情况：
  - 有代币铸造到该账户。“代币”的范围见[被代币引用的范围（Q-M1-11）](#Q-M1-11)，确认前按任何状态的代币（含已销毁）处理。
  - 有处理中的发行申请选择了该账户作为接收账户。被驳回而终止的申请不算引用；申请铸造成功后，转为被代币引用。
- 删除前须显式确认，并说明删除后该账户不再出现在列表和发行申请的可选范围中，且不可恢复；需要时可重新新增并签名。
- 确认删除时再判断一次引用：若此时已被引用，不删除并说明原因。
- 尚未提交的发行申请中已选了该账户时，允许删除；该申请提交时须重新选择接收账户，见[发行申请中选用接收账户（C-ACCOUNT-05）](#C-ACCOUNT-05)。
- 删除失败时账户保持原状，可以重试。

流程参见：[删除数币账户（图 4）](./v1.0-企业登录与企业账户-流程图与状态机.md#fig-4)、[数币账户状态机](./v1.0-企业登录与企业账户-流程图与状态机.md#state-2)。

<a id="C-ACCOUNT-05"></a><a id="c-account-05"></a>
### 6.6 发行申请中选用接收账户（C-ACCOUNT-05）

适用角色与前提：在代币发行·企业申请模块（M3a）中提交发行申请的企业。本节只规定被选用的账户须满足什么；选用的界面、展示与提交流程归 M3a。

依据：没有默认账户（BR-25）【确认】；每次提交都要选一个接收账户（Q24）【建议·已采纳】。

- 可选范围是本企业数币账户列表中的全部账户，包括登录地址这一条。
- 不预选任何账户；企业每次提交发行申请都须明确选择一个接收账户。
- 申请中只能选用已登记的账户，不能新增、编辑或手输地址；需要新地址时，先在数币账户中新增。
- 提交时须再确认一次所选账户仍存在；已被删除时本次提交不成立，并要求重新选择，不用旧值提交。
- 提交成功后，该账户被这笔申请引用，按[删除数币账户（C-ACCOUNT-04）](#C-ACCOUNT-04)不能删除；代币铸造到申请所选账户的地址。
