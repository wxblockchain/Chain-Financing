# 企业登录与企业账户 · 功能与业务规则

2026-10-29｜面客端：企业用户、游客｜需求评审稿

本模块共三册：本册写功能、业务规则、字段规则与交互逻辑；[流程图与状态机](./v1.0-企业登录与企业账户-流程图与状态机.md)画出主要流程与状态；[验收](./v1.0-企业登录与企业账户-验收.md)供测试使用。本模块自身不发送任何消息（登录、游客引导、数币账户变更都不发消息），所以没有 03 消息通知册，并非缺失。

依据标注：规则后的【确认】表示用户已明确，【建议·已采纳】表示诊断建议已由用户采纳，两者同样有效。功能编号沿用原值，新增功能接续编号，所以章节中的编号不按顺序排列。本册只定义信息需求与业务行为，页面布局、组件形态与交互承载由 Hallmark 设计决定。

## 1. 模块是什么

企业用户不在本平台注册，而是用以太坊钱包地址登录：连接钱包、用该地址签名，验签通过即登录成功。登录成功后，本平台按登录地址向上游资产可信平台调取账户信息：调取到即为企业用户，并取得其个人信息、企业信息和当前认证结论；调取不到即为游客，只能看到前往注册或联系平台的引导。企业用户认证通过后才能办理业务，包括维护本企业的数币账户（企业账户），供发起代币发行申请时选择接收代币的账户。

基本原则：

- 登录、身份、认证是三件独立的事：验签通过只代表登录成功；调取到上游账户代表是企业用户；认证通过才代表能办理业务。
- 身份和资料来自上游：本平台不提供注册，也不采集、不修改个人与企业资料；每次登录都重新调取，不在本平台保存“地址属于哪个企业”的绑定关系。
- 登录地址和数币账户用途不同：登录地址用于身份登录，数币账户用于接收代币。登录地址自动列入数币账户，只是多了一个可接收代币的选项。
- 数币账户没有默认账户，企业每次发起发行申请都要明确选一个接收账户；账户里的每个地址都已用签名证明归本企业控制。

**一个完整的例子。** 企业 A 的操作人员连接钱包，用登录地址签名，验签通过后登录成功。本平台按该地址向资产可信平台调取到其账户，取得个人信息、「A 公司」的企业信息和“已认证”结论，操作人员成为已认证的企业用户。操作人员在企业信息中核对资料；在数币账户中看到标明“登录地址”的一条，又新增备注名为“A 公司收币地址”的以太坊地址，用该地址签名通过后登记成功。之后发起代币发行申请时，操作人员从这两条中选择“A 公司收币地址”接收代币。操作人员退出后回到未登录状态。

### 1.2 本期不做

- 在本平台注册企业或用户，或修改个人、企业资料：由资产可信平台负责。
- 钱包登录以外的登录方式，如账号密码、邮箱、手机验证码。
- 指定支持哪些钱包：接入成熟的钱包 SDK 服务商，具体钱包不在本册展开。
- 以太坊以外的网络。
- 登录状态下的“切换钱包”入口：换地址通过退出后重新登录完成。
- 默认数币账户，以及“设为默认”的操作。
- 法币（银行）账户：本模块的企业账户只指数币账户。
- 同一企业多个成员或多个登录地址：每个企业只有一个登录地址。
- 数币账户变更的审核与消息通知。
- 代币铸造到哪个地址、如何使用申请所选的接收账户：由代币发行相关模块定义。
- 管理端查看企业的数币账户：由可信资产模块的企业查看功能（A-ASSET）定义。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 资产可信平台（上游） | 提供用户与企业身份、认证结论、已确权应收账款等信息的外部平台。本册所称“上游”均指它 |
| 登录地址 | 企业用户在资产可信平台登记、用于登录本平台的以太坊钱包地址。每个企业只有一个 |
| 企业用户 | 已登录，且按登录地址在上游调取到账户的用户。业务上也称“企业态” |
| 游客 | 已登录，但按登录地址在上游调取不到账户的用户。业务上也称“游客态”或“登录后的游客” |
| 已认证 / 未认证 | 上游给出的当前有效认证结论。只有已认证的企业用户能办理业务；没有企业归属、认证未通过或审核中都属于未认证 |
| 调取时点 | 本平台主动向上游取得最新账户、资料与认证结论的时机，见[上游变化的同步（C-AUTH-06）](#C-AUTH-06) |
| 数币账户（企业账户） | 企业用于接收代币的以太坊地址清单，由系统列入的登录地址和企业自行新增的地址组成 |
| 登录签名 | 登录时用登录地址对一条登录消息签名，证明登录者控制该地址。不是交易，不消耗 gas，不转移或授权任何资产 |
| 地址归属签名 | 新增数币账户时，用要登记的那个地址签名一次，证明本企业控制该地址。不是登录，不改变当前登录 |
| 处理中的发行申请 | 状态为待监管审核、待运营审核、铸造中或铸造失败（待运营重试）的发行申请。状态口径以简报第 5 节为准 |

## 3. 登录与身份

<a id="C-AUTH-01"></a><a id="c-auth-01"></a>
### 3.1 连接钱包与签名登录（C-AUTH-01）

适用角色与前提：未登录的访问者。

依据：钱包地址登录、不在本平台注册（BR-01）【确认】；仅支持以太坊（BR-17）【确认】；签名规则【确认】。

- 未登录时只能通过连接钱包登录；本平台不提供注册入口，也不提供其他登录方式，也不通过输入邮箱等信息识别身份。
- 登录依次为：连接钱包 → 在钱包中选择以太坊地址 → 用该地址对登录消息签名。本平台验签通过即登录成功；只连接钱包、未完成签名不算登录。
- 登录地址只取自钱包，不能手动输入。选定地址后即请求签名，不另设签名前的确认步骤。
- 唤起钱包前，本平台先说明本次将请求一次登录签名、不涉及转账或资金授权；不能只靠钱包自身的提示。
- 登录成功后立即按[按地址匹配上游身份（C-AUTH-02）](#C-AUTH-02)调取上游；调取期间给出处理中反馈。

<a id="signature-rules"></a>
登录签名规则：

- 钱包内的签名消息须声明用途：签署只用于证明拥有该钱包，不发起交易、不消耗 gas，也不转移或授权任何资产。签名时用户能核对本次登录地址的全文。
- 每个签名请求只能成功使用一次，有效期 5 分钟。已使用或已过期的签名被拒绝、不建立登录；平台准备新的签名请求，由用户重新签名。硬件钱包确认较慢时，页面不得早于 5 分钟自行判定超时。
- 签名地址必须与本次连接的地址一致，签名使用的网络必须是以太坊；由平台校验，不能只靠界面限制。
- 签名失败不累计锁定次数，也不锁定任何账户；同一 IP 1 小时内验签失败超过 20 次后降速，不封禁 IP。

登录过程中的异常：

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 没有可用钱包，或钱包无法唤起 | 说明原因，提示安装或启用钱包后重试；仍为未登录，不提供其他登录方式 |
| 用户取消连接，或钱包处于锁定状态 | 回到发起登录的原处并说明原因（钱包已锁定时提示先解锁），可重新连接 |
| 钱包当前不在以太坊网络 | 提示在钱包中切换到以太坊网络后重试；不建立登录。绕过界面用其他网络签名同样不能登录 |
| 用户拒绝签名、验签失败，或签名地址与连接地址不一致 | 不建立登录，也不透露该地址在上游是否有账户；可重试 |
| 签名过程中钱包切换了地址 | 中止本次登录并说明钱包地址已变化，提供“用该地址重新登录”：以新地址重新签名并重新调取；不静默改用新地址，新地址也不能沿用原地址的签名 |
| 签名请求已过期或已被使用 | 不建立登录，平台准备新的签名请求，提示用户重新签名 |

流程参见：[登录与身份判定（图 1）](./v1.0-企业登录与企业账户-流程图与状态机.md#fig-1)。

### 3.2 按地址匹配上游身份（C-AUTH-02）

适用角色与前提：刚登录成功的用户。

依据：按地址匹配上游，匹配到为企业、匹配不到为游客（BR-01）【确认】；每个企业只有一个登录地址（BR-16）【确认】。

- 每次登录都由本平台主动按本次登录地址向上游调取，不沿用上一次登录的结果，也不依赖上游主动推送。
- 只按登录地址调取；不按企业名称、邮箱、手机号等其他信息近似匹配。同一地址的不同写法（大小写不同、带或不带 0x 前缀）视为同一地址；上游登记的地址不是以太坊地址格式时无法比较，按调取不到处理。
- 调取由本平台服务端发起，并确认结果确实来自资产可信平台、未被篡改；客户端提交的上游数据一律不采信。无法确认来源的结果不参与判定、不改变已有登录，并产生安全告警。

调取结果与用户看到的结果：

| 调取结果 | 本次登录结果 | 用户看到的结果与可继续操作 |
| --- | --- | --- |
| 调取到唯一账户，且上游账户可用 | 企业用户 | 取得个人信息、企业信息和当前认证结论；能否办理业务按[认证资格与受限引导（C-AUTH-04）](#C-AUTH-04)。有个人信息但没有企业信息时同样是企业用户，有什么信息展示什么信息，并提示企业信息需在资产可信平台完善 |
| 调取不到（含上游没有登记该地址） | 游客 | 只看到游客引导，见[游客引导与功能限制（C-GUEST-01）](#C-GUEST-01)；不提示该地址是否曾在上游登记过 |
| 调取到，但上游账户已锁定或禁用 | 不成为企业用户，本次登录结束，回到未登录 | 说明原因，并显示实际能取得的解除信息，不编造 |
| 调取失败、超时或上游不可用 | 不等于调取不到：本次登录不成立，仍为未登录 | 说明“暂时无法确认身份，请重试”，可重新登录 |
| 一个地址调取到多个上游账户 | 按数据异常处理：本次登录不成立，不取其中任何一个账户 | 给出中性说明，产生告警 |
| 调取到，但本平台建立企业用户失败 | 本次登录不成立 | 唯一需要用户单独处理的失败：同时给出错误码、重试和退出两条出路，不静默返回 |

- 所有失败都不暴露内部判定原因。数据来源不可信、缺少稳定标识、一个地址调取到多个账户等异常须产生运维告警，这不是给运营人员发站内消息。

<a id="enterprise-identity"></a><a id="Q-M1-07"></a>
识别同一个用户与企业：

- 本平台按上游稳定、不可变的账户标识识别企业用户，按上游企业标识识别其所属企业；登录地址只是调取入口和登录凭据，不是识别依据，本平台也不保存“地址属于哪个企业”的绑定关系。具体使用上游的哪个标识，由研发在对接资产可信平台时确定。
- 首次调取到即建立本平台的企业用户，此后按稳定标识复用。同一上游账户更换登录地址，不产生新用户、不拆分历史：数币账户、发行申请、代币和消息都归属于企业，用新地址登录后全部保留。
- 缺少稳定标识的上游数据不能用于建立企业用户；邮箱、企业名称都不用于识别或合并。

流程参见：[登录与身份判定（图 1）](./v1.0-企业登录与企业账户-流程图与状态机.md#fig-1)、[面客端登录状态机](./v1.0-企业登录与企业账户-流程图与状态机.md#state-1)。

### 3.3 认证资格与受限引导（C-AUTH-04）

适用角色与前提：企业用户。

依据：调取到但未认证不能办理业务，只有认证通过才能办理【确认】；游客不能使用业务功能【建议·已采纳】。

- 能否办理业务只看上游给出的当前有效认证结论，与资料是否齐全、是否有个人信息无关。资料已存在不代表已认证。
- 已认证的企业用户可使用全部面客端业务：本模块的数币账户，以及可信资产、代币发行、我的代币、销毁申请（这些功能由各自模块定义）。
- 未认证的企业用户（没有企业归属、认证未通过或审核中）：
  - 可以查看[用户信息与企业信息（C-PROFILE-01）](#C-PROFILE-01)，可以使用消息通知（规则见消息通知模块 M7）。
  - 可以看到业务功能的入口，进入或触发业务动作时被拦下，看到“需先在资产可信平台完成认证”的说明和前往完成认证的入口；不整页封锁，不返回任何业务数据。前往时按[前往资产可信平台](#leave-confirm)确认。
  - 直接访问业务功能同样被拒绝；拒绝由平台判定，不能只靠隐藏入口。
- 认证从未认证变为已认证，或从已认证变为未认证，在下一个调取时点生效，不需要重新登录，见[上游变化的同步（C-AUTH-06）](#C-AUTH-06)。从已认证变为未认证时，不结束登录，只停止办理业务。
- 受限后的说明须对辅助技术可读，当前状态与受限原因可被获知。

流程参见：[受限引导与前往资产可信平台（图 6）](./v1.0-企业登录与企业账户-流程图与状态机.md#fig-6)。

<a id="C-AUTH-05"></a><a id="c-auth-05"></a>
### 3.4 登录后返回原目标（C-AUTH-05）

适用角色与前提：未登录时访问受保护的内容（例如从消息链接直接打开某条消息）而被要求登录的用户。主动连接钱包登录没有原目标。

- 登录前保留原目标。登录成功并完成调取后，重新按当前身份判断权限：有权访问即回到原目标；无权访问时，游客看到游客引导，未认证的企业用户看到认证引导，不能把登录成功当作已有权限。
- 没有原目标或原目标无效时，进入登录后的默认页面（具体页面由设计确定）。
- 原目标只用于本次登录，有效期 30 分钟，只能成功使用一次；完成、放弃或登录结束后失效，不能被其他会话或设备使用。
- 原目标已过期时说明链接已失效并进入默认页面；其他不允许的目标只说明已进入默认页面，不展示内部拒绝原因，不白屏。
- 调取失败导致登录不成立时，回到发起登录的原处，可重试。

<a id="C-AUTH-06"></a><a id="c-auth-06"></a>
### 3.5 上游变化的同步（C-AUTH-06）

适用角色与前提：企业用户登录期间。

上游的资料、企业归属、认证结论、账户可用性和登录地址变化，须及时反映到本平台。本平台主动调取，不接收上游推送。调取时点：

| 时点 | 内容 |
| --- | --- |
| 每次登录成功后 | 按[按地址匹配上游身份（C-AUTH-02）](#C-AUTH-02)调取账户、个人与企业信息及当前认证结论 |
| 关键业务动作提交前 | 再次调取并核对账户可用性、登录地址、有效企业与认证结论；旧结果不能放行关键动作。哪些动作属于关键业务动作由各业务模块认定（如提交发行申请、提交销毁申请） |
| 登录期间 | 距上次调取超过 60 秒后的下一次请求前，重新调取并核对上述内容；页面停留且没有请求时不主动调取 |

上游变化在下一个调取时点被发现并生效，本期不承诺秒级同步：

| 变化 | 本平台的处理 |
| --- | --- |
| 上游登录地址变更 | 登录期间发现时，立即结束用旧地址建立的登录，回到未登录并说明“资产可信平台登记的钱包地址已变更，请重新登录”，受保护内容不能继续查看。用户用新地址登录即调取到同一账户，原有数据全部保留。此后用旧地址登录按调取不到处理，为游客，不提示“请使用新地址”，也不提示该地址曾属于某个企业 |
| 上游账户锁定或禁用 | 锁定或禁用满 60 秒后，任何需要登录的操作或页面刷新都被拒绝，本平台登录结束，回到未登录并说明原因，显示实际能取得的解除信息 |
| 认证结论变化 | 不结束登录；按[认证资格与受限引导（C-AUTH-04）](#C-AUTH-04)开放或停止办理业务 |
| 有效企业归属变化 | 确认即更新；资料始终对应当前有效企业，审核中的企业变更不提前替代 |
| 个人、企业基本资料变化 | 只影响展示，在下一个调取时点更新 |

- 登录期间调取失败、超时或上游不可用：不改变本次已判定的身份与已取得资料，但关键业务动作不放行，说明暂时无法确认、可稍后重试；不把失败当作“调取不到”。
- 无法确认来源的调取结果（包括锁定、禁用或地址变更信息）不改变本次登录、不结束登录，产生安全告警；同一异常不反复打扰用户。
- 上游撤回资料可见权限的情形本期不考虑。

流程参见：[上游变化的同步（图 5）](./v1.0-企业登录与企业账户-流程图与状态机.md#fig-5)。

### 3.6 退出与切换钱包（C-AUTH-03）

适用角色与前提：已登录的用户（企业用户或游客）。

依据：退出、切换（C-AUTH）【确认】；登录有效期【确认】。

- 主动退出只有一个入口，企业用户和游客都可以使用。退出后回到未登录并说明，受保护内容不能继续查看，不残留上一个地址的资料或数据。
- 本平台退出不退出资产可信平台；用户在资产可信平台正常退出，也不结束本平台的登录。
- 登录状态下不另设“切换钱包”入口。需要换地址时，先退出，再用另一个地址登录；新地址按[按地址匹配上游身份（C-AUTH-02）](#C-AUTH-02)重新判定，不继承原地址的身份、资料或数据。新地址调取到同一上游账户时，按同一企业用户接续。
- 登录期间钱包内切换到了另一个地址：提示当前钱包地址与登录地址不一致，并提供“用该地址重新登录”；选择后先结束当前登录，再以新地址重新签名、重新调取。用户选择前，本次登录仍对应原登录地址，不自动改用新地址。例外：新增数币账户时为签名切换到被登记的地址，不适用本条，见[新增数币账户（C-ACCOUNT-02）](#C-ACCOUNT-02)。

登录有效期：

| 身份 | 有效期 |
| --- | --- |
| 企业用户（不论是否已认证） | 自登录成功起 7 天 |
| 游客 | 自登录成功起 4 小时 |

- 有效期是绝对时长，到期即结束，不因操作延长；没有“记住我”。
- 到期后回到未登录并说明，受保护内容不能继续查看，不自动跳转或弹出登录；需重新签名登录。
- 登录结束时尚未保存的内容提示未保存，不保留草稿；之后迟到的操作结果不能恢复登录。

以下登录事件须可追溯：验签结果、上游调取结果、身份判定结果、资料同步、登录建立与结束及原因、锁定禁用与地址变更的发现与处理。登录凭据与签名原文不进入日志，联系方式须脱敏。

流程参见：[退出、切换钱包与登录到期（图 2）](./v1.0-企业登录与企业账户-流程图与状态机.md#fig-2)。

## 4. 游客引导与功能限制（C-GUEST-01）

适用角色与前提：已登录、处于游客态的用户。

依据：引导文案【确认】；游客不能使用业务功能【建议·已采纳】；联系邮箱由开发配置【确认】。

- 游客看到引导：“前往资产可信平台进行注册 / 联系平台管理人员”。
  - 前往资产可信平台：提供前往入口，按[前往资产可信平台](#leave-confirm)确认后离开。
  - 联系平台管理人员：展示平台联系邮箱；邮箱由开发直接配置。
- 游客不能使用任何业务功能：用户信息、企业信息、数币账户、可信资产、代币发行、我的代币、销毁申请、消息通知都不展示。直接访问被拒绝，不返回任何业务数据；拒绝由平台判定，不能只靠隐藏入口。
- 游客的账户入口只显示当前登录地址和退出，便于用户到资产可信平台登记或向平台说明。
- 用户在资产可信平台完成注册并登记该地址后，须重新登录，调取到即成为企业用户；从资产可信平台返回本平台本身不触发重新判定。

<a id="leave-confirm"></a>
前往资产可信平台（游客引导与认证引导共用）：

- 离开前先告知将前往的平台名称“资产可信平台”，用户确认后才离开本平台。
- 用户取消时回到发起处，不改变当前登录和身份，不清空原来的浏览内容。
- 本平台不提供前往资产可信平台查看或修改资料的入口；前往入口只用于注册与认证。

## 5. 查看用户信息与企业信息（C-PROFILE-01）

适用角色与前提：企业用户（已认证或未认证）。游客和未登录用户不可访问。

依据：数据来自上游【确认】；只读【建议·已采纳】；展示字段【确认】。

<a id="account-entry"></a>
账户入口：

- 登录后持续可见一个账户入口，显示本次登录地址的可辨识标识：缩略展示时保留大小写，完整地址可核对；地址读取不到时显示“我的账户”，不使用假地址，也不阻断登录。
- 企业用户的账户入口下有：用户信息、企业信息、数币账户、消息通知，以及唯一的退出入口。游客只有登录地址标识和退出。

<a id="profile-rules"></a>
展示规则：

- 用户信息与企业信息分开，可以各自直接访问并返回原处；用户信息内不重复整套企业资料。
- 全部只读，并说明“这些信息由资产可信平台维护”。本平台不提供任何编辑入口（包括不可用状态的编辑入口），不在本地录入、补填或推断资料，也不提供前往上游查看或修改资料的入口；绕过界面的修改同样被拒绝。
- 资料只对本人可见；资料始终对应当前有效企业。退出、换地址或企业归属变化后不残留旧资料，迟到的结果不显示他人或旧企业的信息。
- 读取中、读取失败、确实没有数据三种情况须可区分：读取中给出处理中反馈；读取失败说明失败并可重试，不显示为空；单项可选值确实没有时不展示该项。个人信息整组缺失或企业信息整组缺失时，保留入口和空状态，空状态只说明资料由资产可信平台维护及当前状态。
- 证件影像、企业证明、授权材料、审核记录不在此展示。

三种企业状态的说明须分开，不能合并为一句：

| 当前情况 | 用户信息与企业信息处的说明 |
| --- | --- |
| 没有企业归属（上游未完成企业信息登记） | 说明企业信息需在资产可信平台完善；本处不提供跳转 |
| 有企业归属，但认证未通过或审核中 | 说明认证状态须在资产可信平台查看；不表述为“没有企业”，也不替上游预判结果 |
| 已认证 | 说明资料只读，由资产可信平台维护 |

用户信息：

| 业务信息 | 含义与展示要求 |
| --- | --- |
| 本次登录地址 | 本次签名验证过的登录地址，来自本次登录而不是上游资料；完整展示并可复制，不能在本平台编辑 |
| 同步时间 | 本次调取上游资料的时间；只读 |
| 邮箱 | 上游提供的联系方式，只读；没有时不展示，不在本平台采集或修改 |
| 姓名、英文姓名 | 按上游实际提供分别展示，不自行翻译或补英文名 |
| 国籍 | 按上游认证信息展示，不从证件或地址推断 |
| 证件类型 | 如身份证、护照，以上游实际提供为准 |
| 证件号码 | 上游提供且脱敏口径确认前，不展示真实明文 |
| 与企业的关系 | 如法定代表人、董事、授权代表，按上游实际提供展示，不据此设置本平台的角色权限 |

企业信息：

| 业务信息 | 含义与展示要求 |
| --- | --- |
| 企业 id | 当前有效企业在上游的标识；没有时不阻断登录，但不能凭审核中的资料推断归属 |
| 企业名称、英文名称 | 当前有效企业的名称，分别展示上游已提供的值，不用审核中的企业替代 |
| 注册国家 / 地区、州 | 按适用地区展示，不强制所有地区都有州 |
| 注册地址 | 上游提供的完整注册地址 |
| 企业登记标识 | 按注册地区展示，如中国统一社会信用代码、香港 CR / BR、美国 Entity / File / EIN、开曼及尼日利亚 RC，不混为同一项 |
| 当前有效认证结论 | 决定能否办理业务，见[认证资格与受限引导（C-AUTH-04）](#C-AUTH-04) |

以上字段以资产可信平台实际提供为准；除稳定账户标识外，都不是登录的必要条件。

## 6. 数币账户

<a id="account-common"></a>
### 6.1 共同规则

依据：企业维护数币账户、供铸造时引用、没有默认账户（BR-16、BR-25）【确认】；登录地址自动列入、不可编辑删除，新增账户须签名验证归属（BR-26）【建议·已采纳】；被引用的账户不可删除（Q27）【建议·已采纳】；编辑范围、删除范围、登录地址不重复、备注名长度【确认】。

谁能使用：

| 身份 | 能看到数币账户入口吗 | 进入后能做什么 |
| --- | --- | --- |
| 未登录、游客 | 看不到 | 直接访问被拒绝，不返回任何账户数据 |
| 未认证的企业用户 | 看得到 | 看到本功能用途和“需先在资产可信平台完成认证”的引导，见[认证资格与受限引导（C-AUTH-04）](#C-AUTH-04)；看不到账户数据，不能新增、编辑或删除 |
| 已认证的企业用户 | 看得到 | 查看本企业数币账户，新增、编辑、删除 |

- 数币账户归属企业，不归属某个登录地址。每个企业只有一个登录地址，由使用该地址登录的人维护。
- 只支持以太坊地址。
- 没有默认账户：列表中没有“默认”标记，也没有“设为默认”的操作。
- 本企业内同一地址只能出现一次，登录地址也计算在内；比较时不区分大小写。
- 新增、编辑、删除不需要审核，也不发送消息；保存成功即生效，立即反映在列表和发行申请的可选范围中。
- 保存进行中给出处理中反馈，同一内容不重复保存；保存失败时保持上一次成功保存的状态，可以重试，不留下半条账户。取消或离开不保留未提交的内容。
- 本人查看数币账户时可看到完整地址并复制。

数币账户的信息：

| 业务信息 | 含义与类型 | 必填与默认 | 可编辑 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 账户备注名 | 企业自定、便于辨识的名称；文本 | 企业新增的账户必填，无默认值；登录地址这一条不设备注名，以“登录地址”标明 | 企业新增的账户可编辑；登录地址这一条不可编辑 | 不能为空；最多 100 个字符，超过时说明上限、不能保存；本企业内允许重名 |
| 以太坊地址 | 接收代币的地址；文本 | 必填 | 登记后不可修改 | 须为以太坊地址格式（0x 开头加 40 位十六进制字符），否则不能进入签名；本企业内不能重复；须经地址归属签名通过才登记成功 |

以下信息由系统生成，本人只读：

| 业务信息 | 含义 |
| --- | --- |
| 来源 | “登录地址”或“企业新增” |
| 验证状态 | 地址是否已证明归本企业控制；列表中的账户都为“已验证”：登录地址由登录签名证明，企业新增的由地址归属签名证明。未通过签名不产生账户 |
| 创建时间 | 该账户登记成功的时点；登录地址这一条为首次列入的时点 |
| 更新时间 | 最近一次修改成功的时点；登录地址这一条为最近一次随上游登录地址更新的时点 |

<a id="C-ACCOUNT-01"></a><a id="c-account-01"></a>
### 6.2 数币账户列表与登录地址（C-ACCOUNT-01）

适用角色与前提：已认证的企业用户。

- 列表展示本企业全部数币账户，包括登录地址这一条和企业新增的账户；每条可辨识账户备注名（登录地址这一条标明“登录地址”）、以太坊地址、来源、验证状态和创建时间。
- 读取失败时说明暂时不可用并可重试，不能说成“没有账户”。
- 从列表可以新增账户，对企业新增的账户可以编辑备注名或删除。

登录地址这一条：

- 由系统自动列入，标明“登录地址”。企业不新增任何账户，也能在发行申请中选它接收代币。
- 由系统维护，企业不能编辑或删除。
- 上游的登录地址变更后，企业用新地址登录并调取到同一企业时，这一条随之更新为新地址；已经铸造到旧地址的代币不受影响，仍显示原地址。
- 新的登录地址此前已被企业作为新增账户登记时，不允许出现两条相同地址：以登录地址这一条为准，原企业新增的那一条并入登录地址这一条，不再单独列出，原备注名不再显示；该地址已有的引用关系不变。

| --- | --- | --- | --- |

| 企业新增、未被引用的账户 | 能，仅账户备注名 | 能 | 能 |
| 企业新增、被代币或处理中的发行申请引用的账户 | 能，仅账户备注名 | 不能，说明被引用 | 能 |

### 6.3 新增数币账户（C-ACCOUNT-02）

适用角色与前提：已认证的企业用户，并且能用要登记的那个地址在钱包中完成一次签名。

- 分两步：先填写账户备注名和以太坊地址；再用该地址做地址归属签名，签名通过即登记成功，立即出现在列表和发行申请的可选范围中。
- 填写地址前就告知：只支持以太坊地址；只能登记本企业能用钱包签名的地址，交易所充值地址等由第三方托管、无法签名的地址无法登记。
- 账户备注名为空或超过 100 个字符、地址不符合以太坊地址格式，或本企业已有该地址（包括与登录地址相同）时，不能进入签名，并说明具体原因；已有该地址时可直接查看已有的那一条。
- 签名前说明本次签名的用途：证明该地址归本企业控制，不发起交易，不转移或授权任何资产，也不改变当前登录。
- 签名时用户需在钱包中切换到被登记的地址。这次切换和签名不视为切换登录钱包：不结束当前登录，不改变登录地址和身份，不参与上游调取；签名完成后，本次登录仍对应原登录地址。
- 只有签名通过才产生账户。签名前填写的内容不是账户，不出现在列表，不参与重复判断，也不能被选用。
- 没有“跳过签名”“稍后验证”或由平台代为确认的方式。
- 平台只证明地址归属，不判断地址余额，也不给出“可收款”之类的结论。
- 地址归属签名的请求同样只能成功使用一次、有效期 5 分钟，规则同[登录签名规则](#signature-rules)。

签名环节的异常（以下情况都不登记账户、不改变当前登录，可以重试）：

| 情况 | 用户看到的结果 |
| --- | --- |
| 钱包不可用或无法唤起 | 说明原因，提示启用钱包后重试 |
| 钱包当前不在以太坊网络 | 提示在钱包中切换到以太坊网络后重试 |
| 用户拒绝签名，或验签失败 | 说明未完成签名，账户未登记 |
| 签名地址与要登记的地址不一致 | 明确说明“签名的地址和要登记的地址不是同一个”，提示在钱包中切换到要登记的地址后重试 |
| 签名请求已过期或已被使用 | 提示重新签名 |
| 签名通过但保存失败 | 说明账户未登记成功，可重试 |

流程参见：[新增数币账户与地址归属签名（图 3）](./v1.0-企业登录与企业账户-流程图与状态机.md#fig-3)、[数币账户状态机](./v1.0-企业登录与企业账户-流程图与状态机.md#state-2)。

<a id="C-ACCOUNT-03"></a><a id="c-account-03"></a>
### 6.4 编辑数币账户（C-ACCOUNT-03）

适用角色与前提：已认证的企业用户；账户为企业新增，且未被删除。

- 只能修改账户备注名，不需要重新签名；被引用的账户也可以修改备注名。
- 以太坊地址登记后不能修改。需要换地址时，新增一个账户并重新签名，旧账户按[删除数币账户（C-ACCOUNT-04）](#C-ACCOUNT-04)另行删除。界面需说明这一点。
- 登录地址这一条不能编辑。
- 修改不影响已铸造的代币，也不改变已提交发行申请所选的接收账户地址。
- 备注名为空或超过 100 个字符时，指出原因，保留原值；取消或离开不改变原值。

<a id="C-ACCOUNT-04"></a><a id="c-account-04"></a>
### 6.5 删除数币账户（C-ACCOUNT-04）

适用角色与前提：已认证的企业用户；账户为企业新增。

- 登录地址这一条不能删除。
- 被引用的账户不能删除，并说明被什么引用。引用指以下任一情况：
  - 有代币铸造到该账户，不论该代币当前是什么状态（包括已销毁）。
  - 有处理中的发行申请选择了该账户作为接收账户。被驳回而终止的申请不算引用；申请铸造成功后，转为被代币引用。
- 删除前须显式确认，并说明删除后该账户不再出现在列表和发行申请的可选范围中，且不可恢复；需要时可重新新增并签名。
- 确认删除时再判断一次引用：若此时已被引用，不删除并说明原因。
- 尚未提交的发行申请中已选了该账户时，允许删除；该申请提交时须重新选择接收账户，见[发行申请中选用接收账户（C-ACCOUNT-05）](#C-ACCOUNT-05)。
- 删除失败时账户保持原状，可以重试。

流程参见：[删除数币账户（图 4）](./v1.0-企业登录与企业账户-流程图与状态机.md#fig-4)、[数币账户状态机](./v1.0-企业登录与企业账户-流程图与状态机.md#state-2)。

<a id="C-ACCOUNT-05"></a><a id="c-account-05"></a>
### 6.6 发行申请中选用接收账户（C-ACCOUNT-05）

适用角色与前提：在代币发行·企业申请模块（M3a）中提交发行申请的已认证企业。本节只规定被选用的账户须满足什么；选用的界面、展示与提交流程，以及代币如何铸造到所选账户，归代币发行相关模块。

依据：没有默认账户（BR-25）【确认】；每次提交都要选一个接收账户（Q24）【建议·已采纳】。

- 可选范围是本企业数币账户列表中的全部账户，包括登录地址这一条。
- 不预选任何账户；企业每次提交发行申请都须明确选择一个接收账户。
- 申请中只能选用已登记的账户，不能新增、编辑或手输地址；需要新地址时，先在数币账户中新增。
- 提交时须再确认一次所选账户仍存在；已被删除时本次提交不成立，并要求重新选择，不用旧值提交。
- 提交成功后，该账户被这笔申请引用，按[删除数币账户（C-ACCOUNT-04）](#C-ACCOUNT-04)不能删除。

## 7. 数据来源与归属

| 数据 | 来源 | 本平台能否修改 | 谁能看到 |
| --- | --- | --- | --- |
| 个人信息、企业信息、认证结论 | 资产可信平台，按登录地址调取 | 不能 | 企业用户本人；管理端查看由可信资产模块（M2）定义 |
| 登录地址 | 资产可信平台登记，登录签名验证控制权 | 不能 | 本人（企业用户或游客） |
| 识别用户与企业的标识 | 资产可信平台 | 不能 | 不面向用户展示；具体标识由研发在对接时确定 |
| 数币账户：登录地址这一条 | 系统按当前登录地址维护 | 不能 | 已认证的企业用户本人；运营人员按 M2 只读查看 |
| 数币账户：企业新增的账户 | 本平台，由企业维护 | 能，按本册规则 | 已认证的企业用户本人；运营人员按 M2 只读查看 |

## 8. 与相邻模块的分工

| 相邻模块 | 与本模块的关系 |
| --- | --- |
| M2 可信资产 | 运营人员在企业查看（A-ASSET）中只读查看企业的数币账户；字段沿用本册[数币账户的信息](#account-common) |
| M3a 代币发行·企业申请 | 提交申请时从本模块数币账户中选择接收账户，规则见[发行申请中选用接收账户（C-ACCOUNT-05）](#C-ACCOUNT-05)；提交前按[上游变化的同步（C-AUTH-06）](#C-AUTH-06)重新核对认证结论；处理中的申请构成对账户的引用 |
| M3b 代币发行·审核与铸造 | 代币如何铸造、铸造到哪个地址由发行相关模块定义；铸造成功后账户被代币引用 |
| M4a 我的代币与销毁申请 | 提交销毁申请前按[上游变化的同步（C-AUTH-06）](#C-AUTH-06)重新核对认证结论；代币详情中的地址展示由 M4a 定义 |
| M5 管理端账号、权限与监管机构管理 | 管理端账号登录与面客端钱包登录是两套，互不影响 |
| M7 消息通知 | 本模块不发送消息；游客不能使用消息通知；企业用户的消息入口在账户入口下，规则见[消息通知](./v1.0-消息通知-PRD.md) |

## 9. 待确认事项与依赖

| 编号 | 事项 | 当前处理与影响 |
| --- | --- | --- |
| <a id="Q-M1-15"></a>Q-M1-15 | 认证失效时是否通知企业：企业从已认证变为未认证后会被停止办理业务，简报的消息事件清单（4.5 节）中没有这一条 | 本模块不发消息；确认前企业只在下次办理业务时看到认证引导。若需要通知，由消息通知模块（M7）增加事件 |

依赖：

- 资产可信平台用户匹配（D1）：按以太坊地址返回账户、个人信息、企业信息、当前认证结论和稳定标识，结果来源可验证；上游登记钱包地址时须已验证登记人控制该地址。调取失败时企业无法完成登录，见[按地址匹配上游身份（C-AUTH-02）](#C-AUTH-02)。上游登记地址的控制权验证方式、调取接口的时延与限流约定，在对接时核实。
- 钱包 SDK 服务商（D6）：提供钱包连接、地址识别与签名。具体钱包不在本册展开；签名校验、地址格式校验的实现由研发确定，验证由测试负责。
- 以太坊网络（BR-17）：登录地址和数币账户都只支持以太坊。
- 平台联系邮箱：由开发直接配置，用于游客引导中的“联系平台管理人员”。
