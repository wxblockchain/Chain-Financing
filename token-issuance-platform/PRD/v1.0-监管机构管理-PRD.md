# 监管机构管理 · 功能与业务规则

2026-10-29｜管理端：运营管理人员｜需求评审稿

本模块共四册：本册写功能、业务规则、字段规则与交互逻辑；[流程图与状态机](./v1.0-监管机构管理-流程图与状态机.md)画出主要流程与状态；[消息通知](./v1.0-监管机构管理-消息通知.md)写明本模块发出的邀请邮件；[验收](./v1.0-监管机构管理-验收.md)供测试使用。

本模块与[管理端登录与权限](./v1.0-管理端登录与权限-PRD.md)同属简报中的管理端账号、权限与监管机构管理模块（M5）：本模块写运营如何添加和管理监管机构；监管机构账号如何登录、首次改密，以及能看到哪些菜单和数据，由管理端登录与权限定义。

依据标注：规则后的【确认】表示用户已明确，【建议·已采纳】表示诊断建议已由用户采纳，两者同样有效；未标注的是为落实上述规则所写的产品细化，涉及口径未定的已列入[待确认事项](#pending)。本册只定义信息需求与业务行为，页面布局、组件形态与交互承载由 Hallmark 设计决定。

## 1. 模块是什么

监管机构不能自己注册，只能由运营管理人员在管理端邀请添加：运营为它分配登录邮箱和初始密码，平台向该邮箱发送邀请邮件，监管机构用这套账号登录管理端并在首次登录时修改密码。之后运营可以查看监管机构列表和详情，编辑机构信息，停用或启用机构，并在监管机构忘记密码时为它重置密码。启用的监管机构可以被企业在发起代币发行申请时选择；停用后不再接收新的发行申请，但已有的在途业务照常办理。

基本原则：

- 监管机构只能由运营邀请添加，初始账号由运营分配，邀请时发邮件，首次登录强制改密【确认】（BR-04）。
- 只有运营管理人员能使用本模块；监管机构看不到本模块，也看不到其他监管机构【确认】（简报 4.4）。
- 停用只挡住新业务，不打断在途业务：停用的机构不能再被企业选择，但仍可登录，在途业务的消息照常发送、仍可查看并办理【确认】。
- 运营设置的密码都是初始密码：账号持初始密码时只能完成首次登录强制改密，见[首次登录强制改密（F-LG-03）](./v1.0-管理端登录与权限-PRD.md#F-LG-03)。

**一个完整的例子。** 运营管理人员甲在监管机构管理中邀请添加“X 监管机构”，填写登录邮箱 x@reg.example 和一个符合规则的初始密码，提交成功后列表中出现 X：机构状态“启用”，账号状态“待首登改密”。平台向 x@reg.example 发出邀请邮件，写明机构名称、登录邮箱、初始密码和管理端登录入口。X 用这套账号登录并改密后，甲在列表中看到 X 的账号状态变为“正常”。企业 A 发起发行申请时可以选择 X。几个月后 X 忘记了密码，甲为 X 重置密码并线下告知新的初始密码，X 的登录全部结束，下次登录须再次改密。之后平台决定 X 不再接收新业务，甲停用 X：企业不能再选择 X；X 名下待审核的申请和已铸造的代币，X 仍可登录查看和办理。

### 1.1 需求清单

本模块即简报的监管机构管理（A-REG）。

| 功能 | 谁 | 想做什么 | 为了什么 |
| --- | --- | --- | --- |
| [监管机构列表（F-RG-01）](#F-RG-01) | 运营管理人员 | 查看全部监管机构及其状态 | 掌握有哪些机构、账号是否已开通 |
| [邀请添加监管机构（F-RG-02）](#F-RG-02) | 运营管理人员 | 为新的监管机构开通账号并发出邀请 | 让监管机构能登录管理端参与审核 |
| [查看监管机构详情（F-RG-03）](#F-RG-03) | 运营管理人员 | 查看一家机构的完整信息 | 核对信息、回答监管机构的问题 |
| [编辑监管机构信息（F-RG-04）](#F-RG-04) | 运营管理人员 | 修改机构名称 | 机构更名或录入有误时更正 |
| [停用与启用（F-RG-05）](#F-RG-05) | 运营管理人员 | 让机构不再接收新的发行申请，或恢复接收 | 控制哪些机构可以被企业选择 |
| [重置密码（F-RG-06）](#F-RG-06) | 运营管理人员 | 为忘记密码的监管机构设置新的初始密码 | 监管机构没有自助找回密码的方式 |

### 1.2 本期不做

- 监管机构自助注册或申请入驻。
- 删除监管机构：不再合作的机构用停用处理。
- 一个监管机构多个账号、机构内的成员与角色管理（见[待确认（Q-RG-04）](#Q-RG-04)）。
- 修改监管机构的登录邮箱（见[待确认（Q-RG-02）](#Q-RG-02)）。
- 重新发送邀请邮件；邀请邮件发送失败时由运营线下告知【确认】。
- 编辑、停用、启用、重置密码时向监管机构发送邮件或站内消息。
- 运营账号的管理：运营账号由开发人员分配【确认】。
- 监管机构与企业之间的监管协议：在线下签署，在发行一审时上传，由代币发行 · 审核与铸造（M3b）定义。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 监管机构 | 与企业线下签署监管协议、在管理端做发行一审和解除质押的机构。本册中的一家监管机构对应一个管理端账号 |
| 机构状态 | 监管机构能否接收新的发行申请：启用或停用 |
| 账号状态 | 该机构管理端账号的状态：待首登改密、正常或锁定，定义见[账号状态](./v1.0-管理端登录与权限-PRD.md#account-status) |
| 初始密码 | 运营在邀请添加或重置密码时设置的密码，只能用来完成首次登录强制改密 |
| 邀请邮件 | 邀请添加成功后发往登录邮箱的邮件，内容见[监管机构邀请邮件（NT-R03）](./v1.0-监管机构管理-消息通知.md#NT-R03) |
| 在途业务 | 已经与某个监管机构关联、尚未办完的业务：企业已提交且选择了该机构的发行申请，以及由该机构作为监管机构铸造的代币后续的解除质押 |
| 可选的监管机构 | 企业发起发行申请时可以选择的监管机构，见[企业可选的监管机构](#selectable) |

## 3. 共同规则

<a id="access"></a>
### 3.1 谁能使用

- 只有账号正常、已登录的运营管理人员能使用本模块的全部功能；每个运营账号的能力相同。
- 监管机构看不到本模块的菜单，直接访问按[无权访问的处理（F-LG-12）](./v1.0-管理端登录与权限-PRD.md#F-LG-12)拒绝；监管机构只能在自己的账户设置中看到本机构的名称和状态。
- 企业看不到本模块，只能在发起发行申请时看到可选的监管机构。

<a id="fields"></a>
### 3.2 监管机构的信息

运营填写的信息：

| 业务信息 | 含义与类型 | 必填与默认 | 可编辑 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 机构名称 | 监管机构的名称；文本。企业选择监管机构、各端展示与消息中都用它识别机构；按原文展示，不随界面语言翻译 | 必填，无默认值 | 运营可随时编辑 | 前后空格自动去除；去除后不能为空；最多 100 个字符（见[待确认（Q-RG-01）](#Q-RG-01)），超过时说明上限、不能保存；不能与其他监管机构的名称相同，比较时不区分大小写，重名时说明已有同名机构 |
| 登录邮箱 | 该机构登录管理端的账号，也是邀请邮件的收件地址；邮箱 | 邀请时必填，无默认值 | 邀请成功后不能修改（见[待确认（Q-RG-02）](#Q-RG-02)） | 前后空格自动去除；须为邮箱格式；最多 254 个字符；在管理端全部账号（运营账号与监管机构账号）中唯一，比较时不区分大小写，已被使用时说明该邮箱已被管理端账号使用 |
| 初始密码 | 运营为该账号设置的初始密码；密码 | 邀请、重置密码时必填，无默认值 | 只在邀请和重置时填写；保存后任何人都不能再查看 | 须符合[设置密码的共同规则](./v1.0-管理端登录与权限-PRD.md#password-rules)的长度、组成和空格要求；重置时不能与该账号当前的密码相同；输入时可切换显示或隐藏 |

系统生成、运营只读的信息：

| 业务信息 | 含义 |
| --- | --- |
| 机构状态 | 启用或停用；新添加的机构为启用 |
| 账号状态 | 待首登改密、正常或锁定，随监管机构登录、改密与锁定实时变化；锁定时展示锁定剩余时间 |
| 邀请时间、邀请人 | 邀请添加成功的时间与操作的运营账号 |
| 邀请邮件发送结果 | 已发出或发送失败，见[邀请添加监管机构（F-RG-02）](#F-RG-02) |
| 最近登录时间 | 该机构账号最近一次登录成功的时间；从未登录时为空 |
| 最近更新时间、最近更新人 | 最近一次编辑、停用、启用或重置密码的时间与操作的运营账号 |

- 所有时间按查看者的时区展示并标明时区，见[界面语言与时区（F-LG-09）](./v1.0-管理端登录与权限-PRD.md#F-LG-09)。
- 机构名称、登录邮箱等运营填写的内容按原文展示，不翻译。

<a id="status-combination"></a>
### 3.3 机构状态与账号状态的组合

机构状态与账号状态相互独立：机构状态决定能否接收新的发行申请，账号状态决定能否登录。

| 机构状态 | 账号状态 | 能否被企业新选择 | 能否登录 | 在途业务 |
| --- | --- | --- | --- | --- |
| 启用 | 待首登改密 | 能 | 能，登录后先完成首次改密 | 改密后可办理 |
| 启用 | 正常 | 能 | 能 | 可办理 |
| 启用 | 锁定 | 能 | 锁定到期前不能 | 锁定到期并登录后可办理 |
| 停用 | 待首登改密 | 不能 | 能，登录后先完成首次改密 | 改密后可继续办理【确认】 |
| 停用 | 正常 | 不能 | 能【确认】 | 可继续办理，消息照常发送【确认】 |
| 停用 | 锁定 | 不能 | 锁定到期前不能 | 锁定到期并登录后可继续办理【确认】 |

<a id="selectable"></a>
### 3.4 企业可选的监管机构

本节只规定哪些机构可以被选择；选择的界面、展示与提交流程归代币发行 · 企业申请（M3a）。

- 可选范围是机构状态为启用的全部监管机构，不论其账号是否已完成首次改密。
- 停用的机构不出现在可选范围中。
- 企业提交发行申请时，平台再确认一次所选机构仍为启用；已被停用时，本次提交不成立，要求重新选择。
- 企业只能看到可选机构的机构名称，看不到登录邮箱、账号状态和其他信息。

<a id="concurrency"></a>
### 3.5 操作的共同要求

- 编辑、停用、启用、重置密码都以提交时的最新状态判断：机构状态已被其他运营改变时，不重复执行，说明当前状态已变化并展示最新信息。
- 提交期间不能重复提交；保存失败时保持上一次成功保存的状态，可以重试，不出现只改了一部分的情况。
- 取消或离开不保存未提交的内容。
- 邀请、编辑、停用、启用、重置密码须可追溯：操作的运营账号、时间、变更前后的值；初始密码不记录明文。
- 除邀请邮件外，本模块的任何操作都不发送邮件或站内消息。

<a id="F-RG-01"></a>
## 4. 监管机构列表（F-RG-01）

适用角色与前提：账号正常、已登录的运营管理人员。

- 列表展示全部监管机构，包括停用的机构。每条可看到机构名称、登录邮箱、机构状态、账号状态、邀请时间和最近登录时间。
- 默认按邀请时间从新到旧排列。
- 可以按机构名称或登录邮箱的关键字查找，按机构状态、账号状态筛选；条件可以同时生效。
- 从列表可以邀请添加新机构，进入某个机构的详情。
- 还没有任何监管机构时，说明还没有监管机构，并提供邀请添加的入口；查找或筛选后没有结果时，说明当前条件下没有监管机构，并可以清除条件。两种情况须能区分。
- 读取失败时说明暂时无法读取、可以重试，不显示为空列表。

<a id="F-RG-02"></a>
## 5. 邀请添加监管机构（F-RG-02）

适用角色与前提：账号正常、已登录的运营管理人员。

依据：运营邀请添加，分配邮箱和初始密码，发送邀请邮件【确认】（BR-04）；邮件包含登录邮箱和初始密码，首次登录强制改密降低风险【确认】；邮件发送失败可以线下自己发送【确认】。

- 填写机构名称、登录邮箱和初始密码，字段规则见[监管机构的信息](#fields)。
- 任一项不符合规则时不能提交，并指出哪一项、什么原因；已填写的内容保留。
- 提交成功后：
  - 新增一家监管机构，机构状态为启用，立即进入企业可选的范围，见[企业可选的监管机构](#selectable)；
  - 同时建立它的管理端账号，账号状态为待首登改密，见[首次登录强制改密（F-LG-03）](./v1.0-管理端登录与权限-PRD.md#F-LG-03)；
  - 向登录邮箱发送一封邀请邮件，见[监管机构邀请邮件（NT-R03）](./v1.0-监管机构管理-消息通知.md#NT-R03)。
- 邀请成功后，运营可以看到邀请邮件的发送结果：
  - 已发出：说明邀请邮件已发往该登录邮箱。
  - 发送失败：说明邀请邮件未能发出，请线下将登录邮箱和初始密码告知该机构【确认】；机构和账号照常建立，不回滚。详情中保留“发送失败”的结果。
- 提交失败（网络或服务异常、提交时邮箱已被其他账号使用、名称已被其他机构使用）时，不建立机构和账号，不发送邮件，已填写的内容保留，说明原因，可以修改后重试。
- 平台不提供重新发送邀请邮件；运营需要再次告知时线下进行，忘记初始密码时可以[重置密码（F-RG-06）](#F-RG-06)。
- 初始密码提交后，任何页面都不再展示。

流程参见：[邀请添加监管机构（图 1）](./v1.0-监管机构管理-流程图与状态机.md#fig-1)。

<a id="F-RG-03"></a>
## 6. 查看监管机构详情（F-RG-03）

适用角色与前提：账号正常、已登录的运营管理人员。

- 展示[监管机构的信息](#fields)中除初始密码以外的全部项目。
- 从详情可以编辑机构信息、停用或启用、重置密码；可执行的操作随机构状态变化：启用的机构可以停用，停用的机构可以启用；编辑与重置密码在两种状态下都可以。
- 打开不存在的机构时，说明该监管机构不存在，可以回到列表。
- 读取失败时说明暂时无法读取、可以重试，不显示为空。

<a id="F-RG-04"></a>
## 7. 编辑监管机构信息（F-RG-04）

适用角色与前提：账号正常、已登录的运营管理人员；机构为启用或停用都可以。

依据：编辑信息【确认】（A-REG）。

- 可以修改机构名称，规则见[监管机构的信息](#fields)；登录邮箱、机构状态、账号状态不在编辑中修改。
- 名称没有变化时不需要保存。
- 保存成功后，新名称立即用于各端的展示，包括企业可选的监管机构、该机构的账号名称和各业务中的机构名称；已经发出的站内消息与邮件保留当时的名称，不改写。
- 修改名称不改变机构状态、账号状态和已有业务的归属，不结束该机构的登录，也不发送通知。
- 校验不通过或保存失败时，名称保持原值，说明原因。

<a id="F-RG-05"></a>
## 8. 停用与启用（F-RG-05）

适用角色与前提：账号正常、已登录的运营管理人员。停用针对启用的机构，启用针对停用的机构。

依据：停用 / 启用【确认】（A-REG）；监管机构停用后，消息照常生成并归属该机构，在途业务的消息通知仍然可以看到并处理【确认】。

**停用**

- 执行前须确认。确认时说明：停用后企业不能再选择该机构发起新的发行申请；该机构仍可登录，已有的在途业务照常办理。
- 停用成功后：
  - 该机构立即从企业可选的范围中移除，见[企业可选的监管机构](#selectable)；企业正在填写、尚未提交的申请中已选了它时，提交时要求重新选择。
  - 该机构的账号状态不变，仍可登录；数据范围不变，仍可查看本机构的全部数据，见[数据范围（F-LG-11）](./v1.0-管理端登录与权限-PRD.md#F-LG-11)。
  - 在途业务照常进行：已提交且选择了该机构、待监管审核的申请，仍由该机构审核；由该机构铸造的代币销毁后，仍由该机构解除质押。相关消息照常发给该机构【确认】。
  - 该机构登录后可以在账户设置中看到本机构已停用的说明，见[账号入口与账号信息（F-LG-07）](./v1.0-管理端登录与权限-PRD.md#F-LG-07)。
  - 不结束该机构当前的登录，不发送邮件或站内消息。

**启用**

- 执行前须确认。确认时说明：启用后该机构重新出现在企业可选的范围中。
- 启用成功后，该机构立即重新可选；账号状态、数据和在途业务都不变；不发送邮件或站内消息。

**共同**

- 取消时机构状态不变。
- 失败时机构状态保持原样，可以重试；提交时状态已被其他运营改变的，按[操作的共同要求](#concurrency)处理。
- 停用与启用的次数不限。

流程参见：[停用与启用（图 2）](./v1.0-监管机构管理-流程图与状态机.md#fig-2)、[监管机构状态机](./v1.0-监管机构管理-流程图与状态机.md#state-1)。

## 9. 重置密码（F-RG-06）

适用角色与前提：账号正常、已登录的运营管理人员；机构为启用或停用都可以，账号为任何状态都可以。

依据：重置密码【确认】（A-REG）；不发送邮件（见[待确认（Q-RG-03）](#Q-RG-03)）。

- 运营为该机构的账号填写新的初始密码，规则见[监管机构的信息](#fields)。执行前须确认，确认时说明：重置后该机构当前的登录全部结束，须用新的初始密码登录并再次修改密码；平台不发送邮件，请线下告知新的初始密码。
- 重置成功后：
  - 旧密码立即失效，新的初始密码生效；
  - 账号状态变为待首登改密，该机构下次登录须先完成[首次登录强制改密（F-LG-03）](./v1.0-管理端登录与权限-PRD.md#F-LG-03)；
  - 该机构在所有设备上的登录立即结束，见[登录有效期、无操作登出与退出（F-LG-06）](./v1.0-管理端登录与权限-PRD.md#F-LG-06)；
  - 账号处于锁定时，锁定不提前解除，到期后才能用新的初始密码登录；
  - 机构状态、数据和在途业务都不变；
  - 不发送邮件或站内消息。
- 取消、校验不通过或失败时，原密码不变，该机构的登录不受影响。

流程参见：[重置密码（图 3）](./v1.0-监管机构管理-流程图与状态机.md#fig-3)。
