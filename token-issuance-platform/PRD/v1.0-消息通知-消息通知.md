# 消息通知 · 各来源消息过渡登记

2026-10-30｜过渡文件｜配套[消息通知 · 功能与业务规则](./v1.0-消息通知-PRD.md)

本文件不属于消息通知模块的规则。每类消息由发送它的业务模块在自己的消息通知册中维护【确认】；本文件仅保留尚未入库的企业发行申请消息规则，来源正式文件入库并迁移引用后移除。

本文件现登记一类站内消息，必发、不可关闭。其他消息由各来源正式通知册维护：销毁提交见[我的代币与销毁申请 · 消息通知](./v1.0-我的代币与销毁申请-消息通知.md)；销毁结果与解除监管的五类消息见[销毁审核、解除监管与代币台账 · 消息通知](./v1.0-销毁审核与解除质押-消息通知.md)；发行审核与铸造见[审核与铸造 · 消息通知](./v1.0-代币发行-审核与铸造-消息通知.md)。

## 1. 尚待入库的来源事件

<a id="NT-R01"></a>
### 3.1 新的待审申请（NT-R01）

| 项目 | 规则 |
| --- | --- |
| 触发 | 企业提交发行申请成功，申请进入“待监管审核”时发送一次 |
| 不触发 | 提交失败或取消提交 |
| 收件人 | 该笔申请所选的监管机构。不发给其他监管机构，也不发给运营 |
| 必须写明 | 企业名称；上游资产编号；预计代币数量与币种（USD）；提交时间；需要进行一审 |
| 打开后去哪 | 该笔发行申请的一审（代币发行·审核与铸造，M3b） |
| 同一事实 / 新事实 | 一笔申请只发一次 |

## 2. 尚待迁入来源模块的验收

对应[新的待审申请（NT-R01）](#NT-R01)，沿用原编号；完整内容以 WS-509 最新评审稿为准，此行随来源文件入库迁移。

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| <a id="AC-M7-27"></a>AC-M7-27 | 企业 A 选择监管机构 X 提交发行申请 | 分别查看监管机构 X、Y、运营、企业 A 的消息 | 只有 X 收到“新的待审申请”，写明企业名称、上游资产编号、预计代币数量与币种 USD、提交时间、需要一审，可前往该笔申请的一审；Y、运营、企业 A 都没有新消息 |
