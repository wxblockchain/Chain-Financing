本模块自身发送一类站内消息：[新的销毁申请（NT-A02）](#NT-A02)，必发，用户不能关闭；不发送邮件。本事件由本册维护。接收、展示、已读、语言与前往的共同要求按[消息来源接入要求（MSG-06）](./v1.0-消息通知-PRD.md#MSG-06)执行；发生后 60 秒内可见的已确认要求沿用[送达时效](./v1.0-消息通知-PRD.md#delivery-time)，实现与验证由研发、测试负责。

## 新的销毁申请（NT-A02）

| 项目 | 规则 |
| --- | --- |
| 所在功能 | [确认并提交销毁申请（C-BURN-01）](./v1.0-我的代币与销毁申请-PRD.md#C-BURN-01)；[驳回后再次发起（C-BURN-04）](./v1.0-我的代币与销毁申请-PRD.md#C-BURN-04)复用相同事件 |
| 触发 | 企业实际提交成功，生成新的待运营审核销毁申请时发送一次，发生时间取本次提交成功时间 |
| 不触发 | 未到期、未结清、有融资质押、资格无法确认、权限不满足等导致未提交；取消；已确认提交失败；仅查看、刷新或重复点击；重复提交只定位到已有申请 |
| 收件人 | 管理端全体运营管理人员，各自记录已读；不发给企业，不发给监管机构，不发给游客 |
| 分类 | 审核任务 / Review tasks，沿用 M7 的有效分类 |
| 必须包含 | 销毁申请编号、企业名称、上游资产编号、申请销毁的代币数量与币种 USD、销毁申请提交时间、需要进行销毁审核的说明 |
| 原业务识别 | 原业务名称为销毁申请，识别信息为销毁申请编号、上游资产编号与提交时间；准确定位本次申请，不使用该代币的最新申请替代，定义见[申请信息](./v1.0-销毁审核与解除质押-PRD.md#handoff-application) |
| 打开后去哪 | 管理端 M4b 的该笔[销毁详情与条件核对（A-BURN-02）](./v1.0-销毁审核与解除质押-PRD.md#A-BURN-02)；只在管理端内前往，不直接触发审核或销毁 |
| 当前权限与状态 | 运营仍有权且申请待审时可审核；已被处理时查看当前结果，不恢复旧动作；不存在或无权时按 M7 与管理端统一不可访问规则处理；可返回原消息 |
| 同一事实 | 同一笔申请的这次成功提交只产生一条消息；重复送达、结果重取、刷新、重新登录不新增，也不重置已读 |
| 新事实 | 原申请被驳回后企业重新满足条件并成功生成新的申请，是新的提交事实，各发一条；原申请的消息保留 |
| 内容边界 | 业务值取本次提交事实；不含完整钱包地址、钱包签名、联系方式、凭证原件或下载地址。未知数量不能写成零，消息缺项按 M7 来源要求补齐，不能让企业重复提交 |

### 中文与英文内容

以下标题和正文为该事件的正式内容定义，动态业务值按用户当前语言与时区展示；企业名称、资产编号等事实不翻译。

| 内容 | 中文 | English |
| --- | --- | --- |
| 标题 | 新的销毁申请 | New token burn application |
| 正文 | 企业 {企业名称} 已提交销毁申请 {销毁申请编号}。资产：{上游资产编号}；代币数量：{数量} USD；提交时间：{提交时间}。请前往审核。 | {企业名称} has submitted token burn application {销毁申请编号}. Asset: {上游资产编号}; token quantity: {数量} USD; submitted at: {提交时间}. Review this application. |

动态值：销毁申请编号为本次提交成功生成的唯一编号；企业名称为提交企业的名称；上游资产编号为所选代币关联资产的编号；数量为本次申请销毁数量，按两位小数；提交时间为本次提交成功时间，以查看者当前时区展示。业务事实不因后续进度变化改写。

## 本模块不负责发出的消息

销毁结果、驳回结果、解除监管结果、监管待办和销毁失败运营告警均由 M4b 的[消息通知册](./v1.0-销毁审核与解除质押-消息通知.md)维护；企业在 M4a 查看当前进度，不因本模块被访问而重新发出这些结果消息。M4a 承接企业结果消息的业务规则见[消息进入与返回](./v1.0-我的代币与销毁申请-PRD.md#message-entry)。
