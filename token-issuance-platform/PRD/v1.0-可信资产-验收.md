# 可信资产 · 验收

2026-10-29｜需求评审稿｜供测试使用

本册只写验收标准，测试用例与执行步骤由测试小队编写。规则见[功能与业务规则](./v1.0-可信资产-PRD.md)，各节顺序与功能册一致。

怎么读：

- 共 35 条验收。编号沿用原值，已删除的条目不再占号，所以编号不连续，缺号不代表遗漏。
- 一条验收写了多个场景时，全部场景都满足才算通过。

## 0. 验收前准备

账号：

- 企业 A、企业 B：两个已认证的企业用户，分属注册在不同国家 / 地区的企业。
- 一个未认证的企业用户；一个游客（已用钱包登录、但在上游没有匹配账户的地址）。
- 运营管理人员一个。
- 监管机构 C：有本机构关联的发行申请，覆盖待监管审核、本机构驳回、运营驳回、铸造成功等申请状态。
- 监管机构 D：没有任何关联申请。

数据（均在上游平台或下游借贷平台准备，同步到本平台）：

- 企业 A 的资产，覆盖全部发行状态：可发行、发行申请中（含铸造中、铸造失败待重试）、已驳回（监管驳回与运营驳回各一笔）、已发行（含对应代币处于融资中、销毁申请中、已销毁的各一笔）。
- 企业 A 的可发行、USD、L1 完整的资产：未到期、已逾期、已结清、先逾期后结清各一笔；一笔到期日已过但上游未提供最新状态的资产；一笔上游到期时点与测试账号所选时区不在同一天的资产（例如上游到期时点为 UTC+4 的 3 月 31 日 23:30，查看者选 UTC+8）。
- 企业 A 的一笔未确权应收账款；一笔可发行后被上游撤销确权的资产；一笔被上游删除的资产。
- 企业 A 的一笔非 USD 计价、L1 完整、未到期的可发行资产；一笔缺少 L1 字段（例如缺确权日期）的资产；一笔没有销售发票的资产；一笔 L2 字段全部缺失、L1 完整、未到期的 USD 资产；一笔没有采购账款的资产。
- 一笔有多条标的物明细的资产；一笔有多条回款记录（每条带支付凭证）的资产；一笔有多张销售发票的资产；一笔没有回款记录的资产；一笔结清状态或逾期状态取不到的资产。
- 带全部材料文件的资产；一个无法打开的材料文件。
- 企业 B 的资产若干。
- 企业 A 的数币账户：登录地址这一条，加企业新增的账户至少一个；一个已被企业删除的账户。
- 上游平台可模拟暂时不可用；可在上游修改资产的回款信息与状态。
- 测试账号可在中文、英文两种界面语言和不同时区之间切换；一笔上游同时提供企业中文名称和英文名称的资产。

| <a id="AC-AS-07"></a>AC-AS-07 | 场景一：有多条回款记录、每条带支付凭证的资产；场景二：没有回款记录的资产 | 企业 A 查看资产详情 | 场景一：逐条展示回款日期、回款金额、回款流水号和支付凭证编号，每条的支付凭证文件可以查看和下载，并展示累计已回款、未回款余额、结清状态、结清日期（已结清时）、逾期状态；场景二：说明暂无回款记录，其余回款信息正常展示 |
| <a id="AC-AS-08"></a>AC-AS-08 | 一笔可发行资产 | 企业 A、运营、监管机构 C 分别查找修改、删除资产或回款信息的操作；之后在上游修改这笔资产的回款信息，再次查看 | 任何角色都没有新增、修改、删除资产、企业、回款信息的操作；上游修改后，本平台展示更新后的回款信息 |
| <a id="AC-AS-09"></a>AC-AS-09 | 资产带有全部材料文件 | 企业 A、运营、监管机构 C 分别查看和下载材料 | 三方都能查看和下载确权凭证、销售发票文件、回款支付凭证文件、贸易合同 / 订单文件、交付凭证、运输单据、采购合同 / 订单文件、采购发票文件 |

## 2. 资产状态

对应功能：[资产状态（F-AS-02）](./v1.0-可信资产-PRD.md#F-AS-02)

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| <a id="AC-AS-10"></a>AC-AS-10 | 一笔新同步的已确权资产 | 企业 A 查看；之后提交发行申请；申请进入铸造中、铸造失败待重试；最后铸造成功 | 同步后发行状态为“可发行”；提交成功后为“发行申请中”；铸造中和铸造失败待重试期间仍为“发行申请中”；铸造成功后为“已发行”，资产详情出现关联代币的入口；资产上不出现监管、融资等代币状态 |
| <a id="AC-AS-11"></a>AC-AS-11 | 两笔“发行申请中”的资产 | 一笔被监管一审驳回，另一笔通过一审后被运营二审驳回 | 两笔资产的发行状态都变为“已驳回”，之后不再变化，不能再次发起申请 |
| <a id="AC-AS-12"></a>AC-AS-12 | 发行状态为“已发行”的资产，对应代币分别处于融资中、销毁申请中、已销毁 | 企业 A 查看这些资产；从资产详情进入代币 | 三笔资产的发行状态都为“已发行”，不因代币状态变化；资产上不展示代币的监管、融资、销毁状态；从资产详情可以进入我的代币与销毁申请模块查看这枚代币 |
| <a id="AC-AS-14"></a>AC-AS-14 | 上游提供的确权、结清、逾期状态各不相同的资产 | 企业 A 查看；在上游把一笔未结清资产结清后再次查看 | 每笔资产的确权、结清、逾期状态与上游提供的一致；结清后结清状态变为“已结清”，发行状态不因此改变 |
| <a id="AC-AS-15"></a>AC-AS-15 | 场景一：一笔到期时点已过、上游未提供最新状态（仍为未结清、未逾期）的资产；场景二：一笔先逾期后结清的资产；场景三：上游到期时点为 UTC+4 的 3 月 31 日 23:30、未结清的资产 | 场景一：企业 A 查看，之后由上游提供“已结清”；场景二：查看；场景三：分别以 UTC+4 和 UTC+8 时区在 UTC+4 的 3 月 31 日 23:00 和 23:45 查看 | 场景一：逾期状态自动变为“已逾期”，上游提供“已结清”后结清状态变为“已结清”；场景二：逾期状态为“已逾期”、结清状态为“已结清”；场景三：23:00 时两个时区下都为“未逾期”、可以发起，23:45 时两个时区下都为“已逾期”（上游未提供最新状态时）、不能发起；到期日在 UTC+8 下展示为换算后的日期与时间 |
| <a id="AC-AS-16"></a>AC-AS-16 | 发行状态分别为可发行、发行申请中、已驳回、已发行的资产 | 企业 A 查看每笔资产 | 每种发行状态下的说明与去向都与[发行状态](./v1.0-可信资产-PRD.md#issue-status)表中对应行一致 |
| <a id="AC-AS-17"></a>AC-AS-17 | 结清状态或逾期状态取不到的可发行资产 | 企业 A 查看资产并查找发起入口 | 取不到的状态标明暂时无法获取，不显示为任何一个取值；这笔资产不能发起申请，说明暂时无法确认资产状态 |

## 6. 运营查看企业与资产

对应功能：[运营查看企业与资产（F-AS-05）](./v1.0-可信资产-PRD.md#F-AS-05)

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| <a id="AC-AS-30"></a>AC-AS-30 | 上游已同步企业 A、企业 B | 运营查看企业列表，按企业名称和企业登记标识查找企业 A | 列表包含上游同步到本平台的企业；每个企业展示企业名称、注册国家 / 地区、企业登记标识、登录地址、当前有效认证结论、资产笔数；两种方式都能找到企业 A |

| <a id="AC-AS-32"></a>AC-AS-32 | 全平台有多家企业的资产，部分已发起申请、部分已发行 | 运营查看全平台资产列表，按上游资产编号和债权人名称查找；进入资产详情 | 列表展示上游资产编号、债权人名称、债务人名称、应收账款金额与币种、到期日、确权状态、结清状态、逾期状态、发行状态；两种方式都能找到目标资产；详情的资产信息与企业 A 看到的一致，另外展示关联申请（申请编号、申请状态、所选监管机构）和关联代币，可以进入申请详情、代币台账和债权人企业详情；没有修改信息或发起申请的操作 |
| <a id="AC-AS-33"></a>AC-AS-33 | 场景一：一笔“发行申请中”的资产被上游撤销确权；场景二：一笔“已发行”的资产被上游删除；场景三：一笔“可发行”的资产被上游撤销确权 | 运营、企业 A、监管机构 C 分别查看这些资产 | 运营端在列表项和详情中分别标明“上游已撤销确权”“上游已删除”，被删除的资产保留最近一次保存的信息；企业端和监管端不出现这两类提示；三个场景的发行状态都不自动改变，申请不被终止；场景三中企业 A 不能再发起申请，说明债权人确权已撤销 |
