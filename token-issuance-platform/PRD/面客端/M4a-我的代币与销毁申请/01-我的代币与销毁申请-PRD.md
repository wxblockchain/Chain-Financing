# 我的代币与销毁申请 · 功能与业务规则

2026-11-06｜面客端：企业用户｜需求评审稿

本模块共三册：01 本册、[02 流程图与状态机](./02-我的代币与销毁申请-流程图与状态机.md)、[04 验收](./04-我的代币与销毁申请-验收.md)。本模块不单独发消息，因此不设 03 册；销毁链上结果、运营知会和解除监管消息统一由 M4b 定义。

本册只定义业务行为与信息需求；布局、组件形态与交互承载由设计决定。功能标识“我的代币（C-TOKEN）”“销毁申请（C-BURN）”、业务规则编号沿用《代币发行平台·需求诊断简报》v1.6；功能细分编号用于跨册定位。【确认】为用户明确口径，【建议·已采纳】为简报中已采纳建议。

配套依据：WS-506 的简报 v1.6；本项目 `cly-v6.0.0` 上 M1、M2、[M3a](../M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md)、[M3b](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md)、[M4b 的两端衔接字段清单](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff)、M6、M7 现行 PRD。

## 1. 模块是什么

企业在本模块查看本企业已铸造代币的发行信息、链上持有与融资、监管和销毁情况。平台先校验到期、结清、下游融资结果及链上持有结果；全部通过才提供销毁入口。原发行企业连接钱包并由铸造到账地址对销毁交易完成一次签名，交易由该钱包直接提交，不经过平台签名或运营审核。销毁成功后，原监管机构继续办理解除监管，企业持续查看销毁及解除进度。

基本原则：

- 代币、资产、申请是不同对象。应收账款的结清来自上游；融资来自下游并经链上验证；企业钱包直接签名并提交链上销毁交易，原监管机构在销毁成功后办理解除监管。
- 销毁须同时满足已到期、已结清、没有任何融资质押，并且没有处理中的销毁申请（BR-07、BR-09、BR-20）【确认】【建议·已采纳】；只能由该代币铸造时的第一个持有地址，即铸造到账地址，签名发起销毁【确认】。
- 监管与融资分开。本平台只有监管，不使用“监管质押”的说法；监管中不构成销毁的阻断条件。
- 代币数量按资产价值 1:1 确定，单位为铸造所用合约的代币符号，不以 USD 为单位（BR-19）【确认】，承接 [M3b 的铸造结果](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-mint)。应收账款原值、发行数量和当前单位价值分别展示；运营调价不改变前两者。
- 当前单位价值按币本位展示为“1 COU = X USD”；当前资产估值等于发行数量乘以当前单位价值。企业只能查看，不能调整。
- 列表每项只承载一类信息，用于找到代币；融资、结清、监管等办理依据放在详情中查看。代币详情区分发行时确定的代币发行信息和链上查询的持有信息，为今后转让保留扩展【确认】。识别一枚代币时，所属网络、代币图标与代币符号优先于编号；前往其他对象的详情一律点击该对象的编号；列表设操作列，与平台其他列表统一【确认】。
- 销毁只需要一次钱包交易签名：签名地址必须是该代币的铸造到账地址，签名即授权并提交本次链上销毁交易；连接钱包、切换地址及平台资格校验均不产生签名。当前登录地址、后续持有地址或受让地址都不能替代【确认】，见[销毁交易签名](#burn-signing)。
- 平台不持有销毁控制权，不进行平台签名、业务预签名或运营审核；企业钱包承担交易 gas。状态以用户最新确认的直达销毁流程为准，见[对象与状态](#states)。销毁失败由企业重新校验后发起一笔新的链上交易，不自动重试，也不由运营重试。
- 到期、结清和下游融资结果是平台入口的业务准入条件，不写入合约强制校验。直接调用合约可能绕过平台入口；平台监听到有效链上销毁后，必须按不可逆链上事实更新记录、标记“非平台入口”，并通知运营审计，不得继续显示代币有效。
- 两端共用的申请、销毁及解除记录直接引用 M4b 的[两端衔接字段清单](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff)，本册不另建跨端清单。

**一个完整的例子。** 企业 A 的发行申请铸造成功后，代币最初进入地址 A1；A1 成为不可变的铸造到账地址。之后企业登录地址改为 A2，企业仍能查看这枚代币，但销毁权不随登录地址变化。代币到期、结清、下游明确无融资，且链上确认完整代币回到 A1、质押地址为空后，平台提供销毁入口。企业把钱包切换到 A1，只对销毁交易签名一次并由钱包直接提交；平台和运营都不再签名。合约验证交易发起地址为 A1 且代币仍完整位于 A1，A2 或后续受让地址均不能替代。若链上交易失败，企业重新通过当前资格校验后发起新交易；销毁成功后代币为已销毁，运营收到结果知会，原监管机构 C 办理解除监管。

<a id="out-of-scope"></a>
### 1.2 本期不做

- 发起融资、解除融资质押、转移代币或在本平台更换代币所在地址；融资在下游借贷平台办理。
- 面向企业的代币转让入口、接收方资格与转让结果展示属于二期，见[后续规划](#roadmap)；拆分或部分转让不纳入二期，本平台合约只允许整枚转让【确认】。
- 运营审核、驳回或手动重试销毁；平台代企业签名或代付 gas。运营只接收链上结果通知。企业不能自行解除监管，该动作仍由原监管机构办理。
- 修改已提交申请、撤回申请、批量申请、部分销毁或由企业输入任意销毁数量；本期只承接选定代币的销毁，不增加这些能力。
- 企业在本模块修改资产、结清、融资、合约、监管机构或数币账户信息。
- 企业调整代币单位价值、按企业批量调价、自动按信用定价或接收调价站内消息；调价由运营在 M4b 逐笔办理。
- 从数币地址或合约地址跳转区块链浏览器：本期全平台不提供【确认】，见 [合约管理的本期不做](../../管理端/M6-合约管理/01-合约管理-PRD.md#no-explorer)；企业可复制完整地址自行查询。
- 把发行阶段企业统一显示“发行处理中”的规则延伸为销毁状态归并；销毁仍按简报的真实阶段展示。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 已铸造代币 | M3b 已确认铸造成功、属于本企业的代币；铸造中或铸造失败的申请尚不是本模块代币 |
| 所属网络 | 代币所在的区块链网络，即铸造所用合约的所在网络；当前只有 Ethereum |
| 代币符号 | 铸造所用合约的代币符号，是代币数量的单位，按 [M6 合约的代币符号](../../管理端/M6-合约管理/01-合约管理-PRD.md#symbol)原文展示，为 COU【确认】 |
| 代币图标 | 代币符号对应的识别图形，由设计提供、不写入合约，按 [M6 的代币符号与图标](../../管理端/M6-合约管理/01-合约管理-PRD.md#symbol)；不是企业或运营维护的数据 |
| 代币类型 | 代币图标与代币符号合在一起，用来识别这是哪一种代币 |
| 应收账款原值 | 关联资产的资产价值，即应收账款金额与币种 USD，按 [M2 的资产价值](../../两端共用/M2-可信资产/01-可信资产-PRD.md#2-术语)；铸造与调价都不改写 |
| 当前代币单位价值 | 最近一次链上成功生效的单位价值，按“1 COU = X USD”展示；链上更新处理中或失败时仍展示原有效值 |
| 当前资产估值 | 发行数量 × 当前代币单位价值，单位 USD；系统自动计算，不替代应收账款原值 |
| 发行人 | 申请发行这枚代币的企业，即本企业 |
| 铸造到账地址 | 铸造时代币进入的 Ethereum 数币地址，即该代币的第一个持有地址、发行申请提交时记录的接收地址；是不可变的发行事实，也是唯一可以签名发起销毁的地址，之后的登录地址或持有地址变化都不改写【确认】 |
| 持有地址 | 代币权益所在的数币地址，从链上查询取得；质押期间为转入质押地址前所在的地址；只展示地址本身，不展示账户备注名【确认】 |
| 质押地址 | 融资质押时代币所在的下游质押合约地址；一期代币只能由下游借贷平台发起转入、转出质押地址；解除质押后代币回到原持有地址，违约后代币留在质押合约地址【确认】 |
| 融资状态 | 下游借贷平台提供的融资情况，企业看到未融资或融资中；销毁资格还必须通过链上无融资质押校验 |
| 监管 | 铸造成功时发行申请记录的监管机构对该笔资产的监管，与融资质押是独立关系；从铸造成功起承接，解除由 M4b 办理 |
| 处理中的销毁申请 | 已进入销毁中、执行结果仍在进行或尚未确认的申请；销毁失败是该笔申请的结束结果，不继续占用处理中名额 |
| 平台入口 | 平台在当前业务与链上条件全部通过后提供的销毁入口；入口准入不是链上强制条件，也不赋予平台销毁控制权 |
| 非平台入口销毁 | 企业绕过本平台入口直接调用合约并形成的有效链上销毁；平台须承认结果、标记来源并通知运营审计 |
| 已到期 | 当前已达到或超过上游提供的、带时区的到期时点；查看者的时区只影响展示 |
| 已结清 | 上游明确提供已结清，不依据回款金额、余额为零或逾期状态自行推断 |

## 3. 身份、入口与共同展示规则

### 3.1 身份与数据范围

- 只有已认证的企业用户可以查看本企业代币和销毁申请；查看范围按稳定企业身份判断，不要求当前登录地址等于铸造到账地址。通过平台入口发起时，当前企业必须是该代币原发行企业，并由该代币的铸造到账地址完成销毁交易签名与提交；非发行企业和其他地址均不能发起【确认】。
- 未登录时按[登录后返回原目标（C-AUTH-05）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-05)登录后重新判断；游客按[游客引导与功能限制（C-GUEST-01）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-GUEST-01)处理；未认证企业用户按[认证资格与受限引导（C-AUTH-04）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-04)处理，不返回业务数据。
- 其他企业的代币或申请与不存在的对象统一说明“相关内容暂不可访问”，不区分是否存在；直接访问、刷新、绕过界面提交均按同一权限判断。
- 登录地址变更后，同一企业的新登录地址仍能查看既有代币和申请；铸造到账地址和销毁发起权不随当前登录地址变化。签名时可把钱包切换到铸造到账地址而不改变登录身份；无法控制该地址时不能发起销毁。企业账户只展示当前登录地址，按[查看唯一企业账户（C-ACCOUNT-01）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-ACCOUNT-01)。
- 退出、切换钱包或有效企业归属变化后，不残留旧企业业务数据；迟到的结果不得显示旧企业内容。

### 3.2 入口与返回

- 面客端保留“我的代币”和“销毁申请”两个业务入口，与 M3a 的入口口径一致；分组、位置和页面承载由设计决定。我的代币进入代币列表，销毁申请进入申请列表。
- M3a 铸造成功申请的[申请详情（C-ISSUE-06）](../M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#C-ISSUE-06)、M2 的已发行资产中，点击代币编号进入对应代币详情；未铸造成功的申请没有代币编号，不会产生可访问的代币详情。
- 从原业务或消息进入详情后，可以返回原入口；从列表进入详情后可以返回对应列表。

| 点击的编号 | 前往 | 出现位置 |

| 资产编号 | 该资产的可信资产详情，内容按[企业查看本企业可信资产（F-AS-03）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-03) | 代币详情、销毁申请列表、申请详情 |
| 发行申请编号 | 原发行申请的[申请详情（C-ISSUE-06）](../M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#C-ISSUE-06) | 代币详情 |

- 前往其他对象不另设“查看发行申请”“查看资产”等文字入口；编号可点击须能被辨认，呈现由设计决定。
- 列表操作列中的“查看”进入本行对象自己的详情，与点击本行编号进入同一详情，沿用平台列表的统一做法【确认】，见[我的代币列表的操作](#token-actions)。
- 当前所在详情对应的编号不再指向自身；申请销毁的确认环节只展示编号，不提供前往，避免中断提交。
- 目标对象暂不可访问时说明原因，仍可返回原页面；无权与不存在按[身份与数据范围](#access)统一处理。
- 数币地址、合约地址只供核对，不跳转区块链浏览器，见[本期不做](#out-of-scope)。

### 3.3 展示、缺失与读取异常

- 字段名、状态名称和说明支持中文与英文；机构名称等业务原文不自动翻译。代币符号、网络名称 Ethereum、编号和数值不随语言变化。
- 完整代币数量等于铸造时的完整资产价值，单位为铸造所用合约的代币符号，不以 USD 为单位；应收账款原值与当前资产估值带币种 USD，当前单位价值按“1 COU = X USD”展示。普通列表和详情的金额主显示沿用平台金额展示规则，计算、销毁确认、签名、申请记录和上链使用完整值。发行数量、应收账款原值、当前单位价值与当前资产估值含义不同，不能互相替代。
- 代币符号为 COU【确认】，按 [M6 的代币符号](../../管理端/M6-合约管理/01-合约管理-PRD.md#symbol)；平台内展示设计提供的代币图标，按 [M6 的代币符号与图标](../../管理端/M6-合约管理/01-合约管理-PRD.md#symbol)；暂无对应图标时只展示代币符号，不影响识别和办理。
- 日期时间按本人[偏好设置（C-PROFILE-02）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-PROFILE-02)换算；到期判断按[结清与逾期依据](../../两端共用/M2-可信资产/01-可信资产-PRD.md#overdue)，切换语言、时区不改变资格、事件先后或业务状态。
- 数币地址、合约地址按[钱包地址与网络名称的展示](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#address-display)缩写展示，可以核对完整地址；网络统一为 Ethereum，合约标准为 ERC-3525。
- 读取中、读取失败和确实没有数据应可区分。读取失败可重试，不显示成没有代币或没有申请；未知值不补为零、未融资、已结清或已解除监管。
- 上游或下游暂不可用时，仍可查看本平台已取得的代币、申请及结果；依赖信息无法取得时明确说明，不能以旧展示或未知值放行提交。部分信息失败不遮蔽其余已取得内容。
- 只展示的业务信息均不可由企业编辑；本模块没有额外自由填写字段，不增加原因、备注、凭证等提交要求。

**我的代币列表的操作【确认】。** 列表设操作列，与平台其他列表统一；操作只针对本行代币：

| 操作 | 何时提供 | 结果 |
| --- | --- | --- |
| 查看 | 每一行都提供 | 进入该代币详情，与点击代币编号相同 |
| 申请销毁 | 代币未销毁、没有销毁中的申请，并且最近一次成功取得的信息显示已到期、上游明确已结清、下游明确无融资、链上持有地址为铸造到账地址且质押地址为空；最近一次申请失败的代币满足这些条件时同样提供 | 立即重新取得必要依据，并按[销毁资格与限制原因（C-TOKEN-03）](#C-TOKEN-03)完整判断；满足时进入[申请销毁（C-BURN-01）](#C-BURN-01)，最近一次失败的按[销毁失败后重新发起（C-BURN-05）](#C-BURN-05)；不满足或无法确认时说明全部当前原因，不提供入口、不产生申请 |

- 未知或冲突的值按[共同展示规则](#shared-display)单独说明，不显示为正常结果。
- 本企业没有代币时说明当前尚无铸造成功的代币，可以前往代币发行查看申请；读取失败按[共同展示规则](#shared-display)处理。
- 列表和详情展示同一枚代币的当前结果；办理状态变化后，再次读取应反映新进度。

## 5. 代币详情（C-TOKEN-02）

适用角色与前提：已认证的企业用户，代币属于本企业。

代币详情分为：最上方的识别信息、[代币发行信息](#issuance-info)、[持有信息列表](#holding-info)、[发行关联业务](#issuer-links)、[监管信息](#regulation-info)、[销毁条件与销毁记录](#burn-info)。分区名称与排列由设计决定。

<a id="token-identity"></a>
### 5.1 最上方的识别信息

- 详情最上方须展示所属网络、代币图标与代币符号、代币编号；所属网络、代币图标与代币符号优先于代币编号【确认】。
- 代币编号不能省略：当前所有代币都是 Ethereum、COU，同网络、同符号的代币只能靠编号区分。
- 具体排列与样式由设计决定。

<a id="issuance-info"></a>
### 5.2 代币发行信息

代币发行信息只收录发行时确定、之后不随持有人变化的事实【确认】。这样今后代币允许转让时，其他持有人可以沿用同一组信息查看代币的原始发行情况；非发行人能看到哪些项在开放转让时另定，见[后续规划](#roadmap)。

| 业务信息 | 含义、来源与展示 |
| --- | --- |
| 代币编号 | 平台内唯一代币编号，与原发行申请、链上实际代币、网络和合约固定对应，按[代币及关联事实](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-token) |
| 所属网络与代币类型 | 所属网络 Ethereum；代币图标与代币符号，取铸造所用合约的代币符号 |
| 发行人 | 申请发行的企业名称，取发行申请提交时记录的企业名称，按原文展示 |
| 发行数量 | M3b 铸造成功的完整代币数量，主显示可直接截断至两位小数但须可核对完整值，单位为代币符号；企业不可改写 |
| 应收账款原值 | 关联资产的完整资产价值，主显示沿用平台金额展示规则，可核对完整值，带币种 USD |
| 铸造初始单位价值 | M3b 铸造成功时记录的单位价值，按“1 COU = X USD”展示；后续调价不改写 |
| 当前单位价值 | 最近一次链上成功生效的单位价值，按“1 COU = X USD”展示；更新处理中或失败时使用原有效值 |
| 当前资产估值 | 发行数量 × 当前单位价值，带币种 USD；平台自动计算 |
| 到期日 | 铸造结果的到期日，与发行申请所用应收账款到期日一致；上游提交后不再变更【确认】 |
| 发行时间 | 铸造成功时间，同时是监管开始时间 |
| 铸造到账地址 | 铸造时代币进入的 Ethereum 数币地址，即发行申请提交时记录的登录地址；缩写展示，可核对完整地址；之后质押、解除质押或登录地址变化都不改变这项记录 |
| 所属合约 | 合约名称、标准 ERC-3525、合约地址；名称取[合约管理的信息](../../管理端/M6-合约管理/01-合约管理-PRD.md#fields)中的当前值，合约身份保持不变 |
| 监管机构 | 铸造成功时发行申请记录的监管机构，展示当前名称；监管进度见[监管信息](#regulation-info) |

代币铸造结果继承[审核与铸造的铸造结果清单](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-mint)。合约改名不改变代币的原有合约；平台停用不影响查看既有代币；满足原销毁条件时，企业仍可由钱包直接提交销毁交易，失败后可按当前条件重新发起，无需先启用原合约【确认】，见[停用与既有业务](../../管理端/M6-合约管理/01-合约管理-PRD.md#inflight)。

<a id="holding-info"></a>
### 5.3 持有信息列表

依据：持有数据从链上查询取得；一期代币只能由下游借贷平台发起转入、转出质押地址，不能转让给其他地址【确认】。

- 持有信息在代币详情中以列表呈现，不以单项字段呈现【确认】：每条持有记录占一行，各列含义固定。每枚未销毁代币只有一行，仍按列表展示；合约禁止拆分或部分转让，不会因转让产生多条并存的持有记录，见 M6 [完整转让限制](../../管理端/M6-合约管理/01-合约管理-PRD.md#F-CT-05)【确认】。
- 列表各列如下，每列只承载一类信息；不展示账户备注名或登录地址标识【确认】：

| 列 | 取值与展示 |
| --- | --- |
| 持有地址 | 代币权益所在的数币地址，从链上记录取得；质押期间为转入质押地址前所在的地址；缩写展示，可以核对完整地址 |
| 质押地址 | 代币因融资质押而所在的下游质押地址，与持有地址在同一行【确认】；没有质押时为空【确认】；缩写展示，可以核对完整地址 |
| 持有数量 | 该行持有的完整代币数量，主显示可直接截断至两位小数但须可核对完整值，单位为代币符号；一期等于发行数量 |
| 融资状态 | 与该行对应的融资状态：未融资或融资中【确认】；与质押地址、下游结果互相矛盾或取不到时，按[融资与持有结果判定](#finance-check)说明融资结果不一致或暂时无法确认 |

- 列表外同时展示本次链上查询的时间。
- 地址只供核对，不跳转。
- 质押地址有值而下游显示未融资，或下游显示融资中而质押地址为空，属于融资结果不一致，按有融资质押处理。
- 解除质押后，代币回到原持有地址，质押地址变为空，融资状态按下游结果更新为未融资【确认】。
- <a id="defaulted"></a>**违约代币。** 融资违约后，代币留在质押合约地址【确认】：
  - 该行继续展示原持有地址和质押合约地址，融资状态按下游结果展示。
  - 本期不接入下游的违约状态，融资状态只有未融资和融资中；企业侧不区分违约与正常融资中，不另设违约标识【确认】。
  - 违约代币禁止销毁【确认】：企业不能申请销毁，说明代币仍在质押地址，见[销毁资格](#eligibility)。
  - 违约代币本期保持监管中，不提供解除监管；企业在发起前无法通过资格校验。若申请执行后才确认失败，原申请保留销毁失败，代币仍在质押地址，不能重新发起。
- 链上持有地址不是铸造到账地址，属于与一期合约约定不符的异常：如实展示该行，说明代币当前不在原地址，请联系平台；不能申请销毁，见[销毁资格](#eligibility)。
- 融资状态只在持有信息列表中按行展示，不进入我的代币列表【确认】；本平台不能办理融资或解除融资质押。

| 列表情况 | 用户看到的结果 |
| --- | --- |
| 链上查询失败 | 说明暂时无法获取持有信息，可以重试；不用铸造到账地址补一行，也不把融资状态显示为未融资；详情其他分区正常展示 |
| 代币已销毁 | 列表没有持有记录，说明代币已销毁 |

### 5.6 销毁条件与销毁记录

| 到期情况 | 未到期或已到期；到期时点无法确定时说明无法确认 | 到期依据来自上游并承接发行记录，按 M2 的带时区时点判断 |
| 应收账款结清情况 | 已结清、未结清；取不到时说明无法确认 | 上游提供的结清事实，M2 的回款状态归并不替代该事实 |
| 销毁进度与销毁记录 | 当前销毁进度；该代币的历次销毁申请，每笔展示销毁申请编号与当前阶段，点击编号进入申请详情；没有申请时为未申请，不是新增业务状态 | 申请详情见[申请详情与解除监管进度（C-BURN-03）](#C-BURN-03)，失败的历次记录仍可查看 |

融资是否满足销毁条件以[持有信息](#holding-info)中的融资状态和[融资与持有结果判定](#finance-check)为准。

- 铸造交易哈希、解除监管的操作人、备注与凭证不向企业展示，分别按 [M3b 的铸造结果](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-mint)与 [M4b 的解除监管记录](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-release)的企业可见范围。
- 销毁记录保留为独立的[销毁申请列表（C-BURN-02）](#C-BURN-02)，不并入代币列表或持有信息：每笔销毁申请有自己的编号、阶段和消息落点，同一代币在失败后可有多笔。代币列表只展示当前销毁进度，历次记录在代币详情的销毁记录和销毁申请列表中查看。

监管中与融资中互不替代；代币已销毁与监管已解除是两项独立结果。销毁成功后不得再显示为可销毁；解除监管尚未完成时不得显示业务全部完成。

流程参见[企业查看与返回（图 1）](./02-我的代币与销毁申请-流程图与状态机.md#fig-1)。

<a id="C-TOKEN-03"></a>
## 6. 销毁资格与限制原因（C-TOKEN-03）

适用角色与前提：已认证的企业用户，当前企业是所选代币的原发行企业，且代币已铸造成功。

依据：到期、结清、没有任何融资质押（BR-07）【确认】；融资与持有结果交叉校验（BR-20）【确认】【建议·已采纳】；在途申请防重（BR-09）【建议·已采纳】；结果不一致按不满足处理（Q26）【建议·已采纳】。

<a id="eligibility"></a>
### 6.1 同时满足的条件

当前企业须是原发行企业，且当前身份及企业归属有效；在此前提下，以下四项须同时满足：

1. 当前已经达到或超过应收账款的到期时点，且上游明确提供该笔应收账款已结清；提前结清仍须等到期。
2. 下游结果明确为无融资质押；链上同时显示代币当前完整位于铸造到账地址且质押地址为空，具体组合按[融资与持有结果判定](#finance-check)。
3. 同一代币没有销毁中的申请，也没有已经销毁成功的结果；销毁失败的原申请不阻断重新满足条件后发起新申请。
4. 到期、结清、融资及链上持有信息均能取得并确认。

以上四项是平台提供销毁入口的资格，其中到期、结清和下游融资结果属于链下业务准入；链上合约不重复核验。企业提交时只需由铸造到账地址完成一次销毁交易签名；当前登录地址、转让后的持有地址及其他地址不能替代铸造到账地址。

融资违约、质押或转让后，代币不在铸造到账地址或质押地址不为空，不满足条件 2，企业不能申请销毁，见[违约代币](#defaulted)。

监管中是正常的待销毁背景，不要求先解除监管再申请。历史逾期后已结清不额外阻断销毁；M2 的资产发行状态在铸造后保持已发行，不作为再次申请发行或阻止销毁的理由。上游撤销确权、删除的提示与人工处理继续按 M2 执行，本模块不新增自动终止规则；但无法取得销毁所需的结清、到期依据时不能提交。

<a id="finance-check"></a>
### 6.2 融资与持有结果判定

| 取得的结果 | 企业可见结果与本次资格 |
| --- | --- |
| 下游明确无融资质押，且链上显示代币完整位于铸造到账地址、质押地址为空 | 本项通过；仍须满足其他全部条件 |
| 下游明确有融资质押，或链上明确显示质押地址不为空、代币不在铸造到账地址 | 说明对应限制，不能申请销毁；另一来源同时显示无融资质押时，一并说明结果不一致并提示联系平台 |
| 任一必要结果未取得、失败或无法确认，且当前没有已确认的限制结果 | 说明暂时无法确认融资与持有情况，可重新获取，不能申请销毁；不声称确定有质押或无质押 |

以上是资格判断，不是新增融资状态；企业不需要理解接口或链上报文。只在下游和链上共同明确满足时放行，不能以单一来源、缓存的“未融资”展示、已结清或已解除监管替代校验。

### 6.3 多条件组合与用户结果

按表中顺序判断已销毁、处理中，再判断业务条件；同时不满足多个业务条件时说明全部已知原因。

| 代币与申请情况 | 到期、结清及融资情况 | 监管情况 | 企业能做什么 |
| --- | --- | --- | --- |
| 已销毁（含等待解除监管或已解除） | 不再用于开放新申请 | 监管中或已解除监管 | 查看原申请和解除进度，不能再申请销毁 |
| 有销毁中申请 | 即使其余条件都满足 | 监管中 | 查看处理中的申请，不能重复申请 |
| 尚无申请，或最近一次申请为销毁失败 | 已到期、已结清，融资与持有结果校验通过，且能以铸造到账地址签名 | 监管中 | 可申请销毁；失败后按[销毁失败后重新发起（C-BURN-05）](#C-BURN-05)办理 |
| 尚无申请，或最近一次申请为销毁失败 | 未到期、未结清、仍有融资质押，或持有地址不是铸造到账地址、质押地址不为空，任一不满足 | 监管中 | 说明全部已知不满足项，不允许提交 |
| 尚无申请，或最近一次申请为销毁失败 | 到期、结清、融资或链上持有信息任一无法确认 | 监管中 | 说明暂不能确认的依据，可重新获取，不能提交 |

监管结果与销毁结果互相矛盾、代币缺少必要关联信息时，保留可查事实并说明当前无法确认，不能提交；按 M4b 的[共同异常](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#common-errors)由运营核查，不向企业提供强制改状态入口。

<a id="C-BURN-01"></a>
## 7. 申请销毁（C-BURN-01）

适用角色与前提：已认证企业用户，当前企业是该代币原发行企业，并已选定满足[销毁资格](#eligibility)的本企业代币。

依据：申请销毁须连接钱包；只展示代币关键信息，其余在代币详情查看；交易签名地址固定为该代币的铸造到账地址，不随当前登录地址或后续持有地址变化【确认】。本次签名是链上销毁交易签名，不沿用 M3a 的发行申请业务签名。

<a id="burn-confirm"></a>
### 7.1 确认内容

- 只展示代币的关键信息，均只读：

| 关键信息 | 取值 |
| --- | --- |
| 所属网络 | Ethereum |
| 代币类型 | 代币图标与代币符号 |
| 代币编号 | 平台内唯一代币编号；只展示，不提供前往 |
| 申请销毁数量 | 选定代币的完整铸造数量，确认、签名、申请记录与销毁上链都使用完整值，单位为代币符号 |
| 当前单位价值 | 最近一次链上成功生效的完整值，按“1 COU = X USD”展示 |
| 当前资产估值 | 发行数量 × 当前单位价值的完整值，带币种 USD |
| 持有地址 | 链上查询的持有地址，即铸造到账地址；缩写展示，可核对完整地址 |
| 到期日 | 铸造结果的到期日，按本人时区展示 |

- 关联资产、所属合约、监管机构、发行时间、质押地址、融资与结清等其余信息不在此展示，企业在[代币详情（C-TOKEN-02）](#C-TOKEN-02)查看。只有资格判断通过才进入本环节，提交时还会重新判断，所以不再逐项展示核对结果。
- 须同时说明：平台只做入口前资格校验，不签名、不代发交易、不经运营审核；企业钱包将对销毁交易签名一次并直接提交、承担 gas；销毁成功后仍需原监管机构办理解除监管，二者不是同时完成；链上交易提交后不能在平台撤回或修改；其他地址不能发起。
- 企业不能另选代币、数量、接收地址或合约；本期不采集企业填写的原因、备注、凭证或数量。提交信息直接采用[申请信息](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-application)。
- 企业取消或未提交即离开，回到原代币，未产生申请、不改变状态、不发送通知。
- 承载形式由设计决定，与申请发行保持一致。

<a id="burn-signing"></a>
### 7.2 销毁交易签名

- 连接钱包、切换网络或地址、平台资格校验均不触发签名。企业确认后，钱包只发起一次销毁交易签名；该签名同时完成链上授权和交易提交，不再先做业务预签名，也没有平台第二次签名。
- 交易发送地址必须是本代币的铸造到账地址，即铸造时的第一个持有地址【确认】；当前登录地址、转让后的持有地址或其他地址都不能替代。钱包当前地址不是铸造到账地址时，提示切换后再继续；钱包切换不改变本次登录身份、企业归属或代币归属。
- 企业无法控制铸造到账地址时不能销毁；平台不提供由当前登录地址、受让地址、运营、监管机构或平台钱包代签的替代路径。代币转让或质押在外时不能发起；只有完整回到铸造到账地址并重新满足资格后才可发起。
- 钱包签名并提交的交易必须指向选定代币及其完整数量；企业不能修改数量或改为部分销毁。企业钱包承担 gas；平台不代付、不托管私钥。
- 合约收到交易后校验交易发送地址、代币当前位置、质押地址、完整数量及未销毁状态，具体见 M6 [销毁发起地址限制](../../管理端/M6-合约管理/01-合约管理-PRD.md#F-CT-06)。到期、结清和下游融资结果不属于合约校验字段。
- 钱包拒绝签名或交易未成功广播时不产生销毁申请；交易广播成功并取得交易标识后，平台创建销毁申请并进入销毁中。交易失败后重新发起须重新通过当前资格校验并签署一笔新的销毁交易。

<a id="burn-submit"></a>
### 7.3 提交与结果

- 申请销毁是关键业务动作，调起钱包签名前按[上游变化的同步（C-AUTH-06）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-06)重新确认身份、有效企业和认证结论，并重新判断[销毁资格](#eligibility)。查看时曾满足条件不保证本次仍满足。
- 钱包广播交易成功后生成平台内唯一的销毁申请编号，记录提交时间、交易发送地址及链上交易标识并关联原代币编号；申请进入销毁中，代币进入销毁申请中，不产生平台签名或待运营审核阶段。展示已发起结果和销毁申请编号，点击编号进入该笔申请详情，也可返回我的代币。
- 一次成功提交只产生一笔申请。同一代币已有处理中的申请时，重复提交不能生成新申请，应定位已有申请供企业查看；重复点击、刷新或结果重取不追加申请。
- 平台只在监听到链上成功或失败结果后按 M4b 发送结果消息；交易刚发起不向运营发送消息，也不形成运营任务。

提交不成功的情况（以下都不产生申请，代币状态不变）：

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 企业取消签名或钱包拒绝签名 | 本次不提交，说明交易未发起；可重新通过当前资格校验后再试 |
| 钱包当前地址不是本代币的铸造到账地址 | 不能签名提交，提示在钱包中切换到该代币的铸造到账地址后重试；当前登录身份不变 |
| 钱包当前不在 Ethereum 网络 | 不能签名提交，提示在钱包中切换到 Ethereum 网络后重试 |
| 钱包交易构造或链上预估不通过 | 不调起或不继续签名，说明当前无法发起；重新取得当前资格与链上状态后再试 |
| 认证结论已变为未认证，或提交过程中登录结束 | 按 M1 [认证资格与受限引导（C-AUTH-04）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-04)或[退出与切换钱包（C-AUTH-03）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-03)处理；迟到的提交结果不显示 |
| 签名后销毁资格已改变，或上游、下游、链上必要结果无法确认 | 说明当前限制，可返回代币查看；不放行本次提交 |
| 交易未成功广播 | 说明未完成，不产生申请；可重新校验后发起新的交易 |
| 提交结果尚未确认 | 不宣称失败或成功，不提供会形成重复申请的再次提交，先获取本次实际结果 |

流程参见[校验、签名与提交（图 2）](./02-我的代币与销毁申请-流程图与状态机.md#fig-2)。

## 8. 销毁申请列表（C-BURN-02）

适用角色与前提：已认证的企业用户。

- 列出本企业全部销毁申请，包括销毁中、销毁失败、销毁成功待解除监管和已解除监管的历史记录。
- 每笔申请展示销毁申请编号、代币编号、资产编号、申请销毁数量、提交时间、当前申请阶段和操作；数量主显示可直接截断至两位小数，但须标明已截断并可核对申请记录中的完整数量，单位为代币符号；按[申请信息](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-application)引用同一笔事实。
- 操作列每行提供“查看”，进入该笔申请详情，与点击销毁申请编号相同【确认】；本列表不提供其他操作。
- 点击销毁申请编号进入申请详情，点击代币编号、资产编号分别前往代币详情、可信资产详情，按[通过编号前往详情](#id-links)。针对同一代币失败后重新发起形成的多笔申请必须分别保留，不能用最新申请覆盖旧申请。
- 本企业尚无申请时说明暂无销毁申请，可前往我的代币选择符合条件的代币；读取失败按[共同展示规则](#shared-display)处理。
- 申请阶段取当前业务事实，列表与详情一致；查看历史失败记录不会将旧记录变成新申请的状态。

## 9. 申请详情与解除监管进度（C-BURN-03）

适用角色与前提：已认证企业用户，销毁申请属于本企业。

### 9.1 申请信息与结果

- 详情最上方须展示所涉代币的所属网络、代币图标与代币符号，以及销毁申请编号和当前申请阶段；所属网络、代币图标与代币符号优先于编号【确认】。同一代币可能有多笔申请，销毁申请编号与阶段不能省略。具体排列由设计决定。
- 展示提交时间、代币编号、资产编号、申请销毁数量（单位为代币符号）、铸造到账地址、所属合约与监管机构，按[申请信息](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-application)定位原记录；点击代币编号、资产编号分别前往代币详情、可信资产详情。
- 申请信息区分提交时的申请事实与当前关联信息，不用最新申请的值替代历史申请；机构名称展示当前名称，与[代币详情](#C-TOKEN-02)一致；本模块不展示账户备注名。
- <a id="burn-signature-record"></a>销毁交易记录展示交易发送地址、交易提交时间、交易来源（平台入口／非平台入口）和当前链上结果；与 M4b [销毁交易记录](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-signature)使用同一笔事实。发送地址必须是铸造到账地址，记录不能修改；读取失败时说明暂时无法获取，可以重试，不影响其他信息。本期企业端不展示销毁交易哈希。
- 销毁失败时展示失败结果；能重新满足条件时可重新发起销毁，见[销毁失败后重新发起（C-BURN-05）](#C-BURN-05)。
- 销毁成功展示销毁事实与结果数量；解除监管尚未完成时，明确下一步由原监管机构办理，不能让企业误认为自己还要解除融资质押。
- 解除完成后展示已解除监管结果、原监管机构当前名称和原解除完成时间，按[解除监管记录及企业可见范围](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-release)；企业看不到操作人、备注和凭证，直接访问文件也必须拒绝。
- 企业不见内部失败说明；可见本次条件核对结果、销毁阶段及失败／成功结果，按[条件与执行记录](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-review)。销毁成功显示完整结果数量（单位为代币符号）与实际成功时间，按[销毁结果](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-burn)。

<a id="states"></a>
### 9.2 对象与状态

销毁交易由企业钱包提交后直接进入链上执行，不经过平台签名或运营审核；本平台只有监管，末两项称为待解除监管、已解除监管，与 M4b [对象与状态对应](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#states)一致。此表是对应展示，不另立并行状态机。

| 销毁申请阶段 | 企业展示与可观察结果 | 可继续操作 |
| --- | --- | --- |
| 销毁中 | 企业钱包已广播销毁交易，尚无明确成功或失败结果 | 查看进度；不能重复申请 |
| 销毁失败 | 本笔交易已明确失败，代币未销毁 | 重新满足当前条件后签署并提交一笔新的销毁交易 |
| 销毁成功 | 展示代币已销毁的结果；监管解除尚未完成 | 查看销毁结果与后续解除监管进度 |
| 待解除监管 | 代币已销毁，原监管机构尚未完成解除监管 | 查看进度；不能再次销毁 |
| 已解除监管 | 展示原监管机构已完成解除监管的事实 | 查看结果和历史记录；不能再次销毁 |

- 我的代币列表与代币详情中的销毁进度取该代币最近一笔申请在上表中的企业展示阶段；没有申请时为未申请。
- 销毁成功是结果事实，待解除监管是之后的待办进度；即使业务直接进入待解除监管，仍保留销毁成功事实，不能倒退成未销毁。
- 原销毁交易仍在进行或结果尚未确认时，申请保持销毁中，不能因等待时间较长自行显示失败、已销毁或允许企业重新申请；当前只承接原交易实际结果。
- 销毁失败是本笔申请的结束结果，不自动重试，也不由运营重试。企业重新发起时形成新的申请编号和链上交易，原失败记录保持不变。
- 代币状态引用简报：正常（未质押）、融资质押中、销毁申请中、已销毁；企业融资展示为未融资／融资中。销毁失败结束本笔申请占用后，按当前融资事实回到正常（未质押）或融资质押中；未知时说明无法确认并限制新申请，不用旧正常结果放行，按[对象与状态对应](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#states)。
- 到期、结清、融资、监管与销毁各自回答不同问题，组合判定见[多条件组合](#C-TOKEN-03)；未知信息不构成新的业务终态。
- 两端对监管与融资的区分见[监管口径同步](#confirmed-sync)。

<a id="message-entry"></a>
### 9.3 消息进入与返回

- 由 M4b 发给企业的相关消息进入消息所指的那一笔销毁申请，不能换成该代币的最新申请。
- 进入时重新确认身份与权限，并展示申请当前事实。旧失败消息仍进入原失败记录；如果代币另有处理中申请，应引导查看已有申请，不能因旧消息再次放行提交。
- 该申请已完成但仍有权查看时，正常显示完成结果；申请不存在或无权时按[身份与数据范围](#access)统一拒绝，可返回原消息。
- 消息内容、事件和收件范围由 M4b 自己维护；M4a 不新增结果通知，消息的已读不推动任何业务进度。

流程参见[销毁申请状态与解除监管（图 3）](./02-我的代币与销毁申请-流程图与状态机.md#fig-3)。

<a id="C-BURN-05"></a>
## 10. 销毁失败后重新发起（C-BURN-05）

适用角色与前提：本企业存在已明确销毁失败的申请，所涉代币尚未销毁且当前没有销毁中的申请。

- 原申请维持销毁失败结果；重新发起针对原代币创建新的销毁申请，不修改、复用或覆盖旧申请。
- 重新发起仍逐项执行[销毁资格与限制原因（C-TOKEN-03）](#C-TOKEN-03)，不能将原申请曾经通过校验当作本次资格。
- 企业重新核对确认信息，按[申请销毁（C-BURN-01）](#C-BURN-01)签署并提交一笔新的销毁交易；交易广播成功后新申请直接进入销毁中。旧申请和旧交易记录保持不变。
- 原代币已有销毁中的申请时进入已有申请；已销毁时只看结果；当前未结清、有融资质押、代币不在铸造到账地址或资格无法确认时，说明当前限制，不产生新申请。

| 信息或能力 | 负责方 | 本模块使用边界 |
| --- | --- | --- |
| 身份、认证、有效企业和数币账户 | M1 | 提交前重新核对身份；代币展示不能随登录地址变化而改写原地址 |

| 铸造成功结果、原发行申请、原监管机构和监管协议 | M3a、M3b 现行 PRD | 只有成功代币进入本模块；数量、地址、到期日承接成功结果，数量单位为代币符号；监管协议直接使用原发行申请的文件 |
| 融资情况与链上持有验证 | 下游 D4、Ethereum D5 | 下游明确无融资质押，且链上确认代币完整位于铸造到账地址、质押地址为空才放行；不可用、冲突时按[融资与持有结果判定](#finance-check)限制 |
| 持有地址、质押地址与持有数量 | Ethereum D5 链上查询；质押转移由下游借贷平台按合约约定发起 | 只读展示，查询失败时说明暂时无法获取，不以平台记录代替；持有地址不是铸造到账地址或质押地址不为空时不能申请销毁 |
| 销毁申请、销毁与解除记录的跨端定义 | M4b | 直接引用 M4b 的[唯一衔接字段清单](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff) |
| 销毁执行 | 企业钱包、M4b 与 Ethereum D5 | 平台入口校验通过后，铸造到账地址只进行一次销毁交易签名并由企业钱包直接提交；平台不签名、不代发、不代付 gas，运营不审核。合约只校验链上硬约束；M4b 承接链上结果并处理非平台入口销毁，按 M4b [企业钱包直接提交销毁交易](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#platform-signing) |
| 合约名称、地址、网络、标准、代币符号与平台可用状态 | M6 | 保留代币原所属合约；代币类型取原合约的代币符号；平台停用不影响既有业务继续，见[停用与既有业务](../../管理端/M6-合约管理/01-合约管理-PRD.md#inflight) |
| 代币图标 | 设计提供，不写入合约，见 [M6 的代币符号与图标](../../管理端/M6-合约管理/01-合约管理-PRD.md#symbol) | 只用于识别；暂无图标时只展示代币符号 |
| 监管机构当前名称 | M5 监管机构管理 | 展示原监管机构的当前名称，不允许企业更换监管方 |
| 钱包签名与铸造到账地址 | M1 的登录身份、企业的钱包、M3b 铸造结果 | 当前登录身份用于判断企业范围；销毁交易发送地址固定为本代币铸造到账地址。钱包不可用、拒绝签名或地址、网络不符时不能提交，见[提交与结果](#burn-submit) |
| 销毁结果消息 | M4b 发出，M7 承接 | 链上成功或失败后向相应角色发送结果消息；本模块不发送“已发起”消息 |

<a id="pending"></a>
## 12. 跨模块口径与待确认事项

本模块沿用 M3b 的 Q-M3B-01：代币单位价值允许的小数位数和最大值尚未确认。企业端已确定按“1 COU = X USD”只读展示；产品确认精度前相关边界验收待验、不判通过。

<a id="confirmed-sync"></a>
### 监管口径同步

用户已明确“没有什么监管质押……本平台只有监管”。本册与 M4b 统一采用监管、解除监管、待解除监管、已解除监管，阶段见 M4b [对象与状态对应](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#states)，未增加业务环节；“解除质押”只指下游融资质押的解除，代币回到原持有地址。简报 v1.6 中监管相关的旧称谓按此口径理解；融资与持有结果仍按简报 BR-20、Q26 交叉校验。

M3a 企业侧“发行处理中”仅适用于发行，不隐藏销毁失败；登录地址变化后 M1 只展示新的当前登录地址，既有代币仍保留原铸造到账地址。

<a id="roadmap"></a>
### 后续规划（二期转让，不属于本期需求）

以下仅记录未来开放转让时仍需定义的产品范围，不构成本期功能和验收；合约层完整转让限制已经生效，不属于待确认项：

- 转让只能把一枚代币的当前全部持有数量一次性转给一个接收地址；禁止拆分、部分转让和同时转给多个地址，转让后原地址不再持有该枚代币。平台入口和直接调用合约均不能绕过，见 M6 [完整转让限制](../../管理端/M6-合约管理/01-合约管理-PRD.md#F-CT-05)【确认】。
- 非发行人持有人在本平台可查看的范围，以[代币发行信息](#issuance-info)为基础另定；发行关联业务、监管协议和销毁记录属于发行人业务。
- 转让入口、接收方资格、能否部分销毁，以及持有人变化的通知与 M4b 台账展示。转让不转移销毁发起权，销毁仍只能由铸造到账地址签名发起【确认】。

### 管理端填写边界

销毁没有运营审核、驳回意见或手动重试字段。解除备注及可选解除凭证仍由 M4b 的[解除监管并留记录（R-RELEASE-03）](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#R-RELEASE-03)维护，本期不设长度上限，凭证不限定格式、份数和大小【确认】。企业不可查看解除操作人、备注和凭证。
