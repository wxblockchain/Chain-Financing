# 我的代币与销毁申请 · 功能与业务规则

2026-11-09｜面客端：企业用户｜需求评审稿

本模块共三册：01 本册、[02 流程图与状态机](./02-我的代币与销毁申请-流程图与状态机.md)、[04 验收](./04-我的代币与销毁申请-验收.md)。本模块不单独发消息，因此不设 03 册；销毁链上结果、运营知会和解除资产托管消息统一由 M4b 定义。

本册只定义业务行为与信息需求；布局、组件形态与交互承载由设计决定。功能标识“我的代币（C-TOKEN）”“销毁申请（C-BURN）”、业务规则编号沿用《代币发行平台·需求诊断简报》v1.6；功能细分编号用于跨册定位。编号沿用原值，缺号不代表遗漏。【确认】为用户明确口径，【建议·已采纳】为简报中已采纳建议。

配套依据：《代币发行平台·需求诊断简报》v1.6；M1、M2、[M3a](../M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md)、[M3b](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md)、[M4b 的两端衔接字段清单](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff)、M6、M7 现行 PRD。

## 1. 模块是什么

企业在本模块查看本企业已铸造代币的发行信息、链上持有与融资、资产托管、发行机构文件和销毁情况。平台先校验到期、结清、下游融资结果及链上持有结果；全部通过才提供销毁入口。原发行企业连接钱包并由铸造到账地址对销毁交易完成一次签名，交易由该钱包直接提交，不经过平台签名或运营审核。销毁成功后，由该代币的资产托管机构办理解除资产托管，企业持续查看销毁及解除进度。

基本原则：

- 代币、资产、申请是不同对象。应收账款的结清来自上游；融资来自下游并经链上验证；企业钱包直接签名并提交链上销毁交易，该代币的资产托管机构在销毁成功后办理解除资产托管。
- 销毁须同时满足已到期、已结清、没有任何融资质押，并且没有处理中的销毁申请或提交锁（BR-07、BR-09、BR-20）【确认】【建议·已采纳】；只能由该代币铸造时的第一个持有地址，即铸造到账地址（在代币发行信息中称发行地址），签名发起销毁【确认】。
- 资产托管与融资分开。资产托管是资产托管机构对代币所对应现实资产的托管，不是融资质押；托管中不构成销毁的阻断条件。
- 代币数量按资产价值 1:1 确定，单位为铸造所用合约的代币符号，不以 USD 为单位（BR-19）【确认】，承接 [M3b 的铸造结果](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-mint)。应收账款原值、发行数量和当前单位价值分别展示；运营调价不改变前两者。
- 当前单位价值按币本位展示为“1 COU = X USD”；当前资产估值等于发行数量乘以当前单位价值。企业只能查看，不能调整。
- 列表每项只承载一类信息，用于找到代币；融资、结清、资产托管等办理依据放在详情中查看。代币详情区分发行时确定的代币发行信息和链上查询的持有信息，为今后转让保留扩展【确认】。识别一枚代币时，所属网络、代币图标与代币符号优先于编号；前往其他对象的详情一律点击该对象的编号；列表设操作列，与平台其他列表统一【确认】。
- 销毁只需要一次钱包交易签名：签名地址必须是该代币的铸造到账地址，签名即授权并提交本次链上销毁交易；连接钱包、切换地址及平台资格校验均不产生签名。当前登录地址、后续持有地址或受让地址都不能替代【确认】，见[销毁交易签名](#burn-signing)。
- 平台不持有销毁控制权，不进行平台签名、业务预签名或运营审核；企业钱包承担交易 gas。状态以用户最新确认的直达销毁流程为准，见[对象与状态](#states)。销毁失败后，企业须重新校验并发起一笔新的链上交易。
- 到期、结清和下游融资结果是平台入口的业务准入条件，不写入合约强制校验。直接调用合约可能绕过平台入口；平台监听到有效链上销毁后，必须按不可逆链上事实更新记录，不得继续显示代币有效；只有不属于任何平台提交的有效销毁才标记“非平台入口”，归属按[销毁提交锁与交易归属](#submit-lock)。
- 两端共用的申请、销毁及解除记录直接引用 M4b 的[两端衔接字段清单](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff)，本册不另建跨端清单。

**一个完整的例子。** 企业 A 的发行申请铸造成功后，代币最初进入地址 A1；A1 成为不可变的铸造到账地址，在代币发行信息中展示为发行地址。之后代币经下游借贷平台质押又解除质押，企业仍能查看这枚代币，但销毁权始终只属于 A1。代币到期、结清、下游明确无融资，且链上确认完整代币回到 A1、质押地址为空后，平台提供销毁入口。企业确认后，平台先对该代币加提交锁，再请企业把钱包切换到 A1，只对销毁交易签名一次并由钱包直接提交；平台和运营都不再签名。合约验证交易发起地址为 A1 且代币仍完整位于 A1，后续受让地址或其他地址均不能替代。若链上交易失败，企业重新通过当前资格校验后发起新交易；销毁成功后代币为已销毁，M4b 为该代币的资产托管机构建立解除托管事项，企业在本模块查看后续进度。

### 1.2 本期不做

- 发起融资、解除融资质押、转移代币或在本平台更换代币所在地址；融资在下游借贷平台办理。
- 面向企业的代币转让入口、接收方资格与转让结果展示不在本期；链上已发生的整枚转让状态仍按[持有信息列表](#holding-info)如实展示。
- 运营审核、驳回或手动重试销毁；平台代企业签名或代付 gas。运营只接收链上结果通知。企业不能自行解除资产托管，该动作由该代币的资产托管机构办理，运营只查看结果。
- 修改已提交申请、撤回申请、批量申请、部分销毁或由企业输入任意销毁数量；本期只承接选定代币的销毁，不增加这些能力。
- 企业在本模块修改资产、结清、融资、合约、资产托管机构或数币账户信息。
- 企业调整代币单位价值、按企业批量调价、自动按信用定价或接收调价站内消息；调价由运营在 M4b 逐笔办理。
- 从数币地址或合约地址跳转区块链浏览器：本期全平台不提供【确认】，见 [合约管理的本期不做](../../管理端/M6-合约管理/01-合约管理-PRD.md#no-explorer)；企业可复制完整地址自行查询。
- 把发行阶段企业统一显示“发行处理中”的规则延伸为销毁状态归并；销毁仍按简报的真实阶段展示。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 已铸造代币 | M3b 已确认铸造成功、属于本企业的代币；铸造中或铸造失败的申请尚不是本模块代币 |
| 所属网络 | 代币所在的区块链网络，即铸造所用合约的所在网络；当前只有 Ethereum |
| 代币符号 | 铸造所用合约的代币符号，是代币数量的单位，按 [M6 合约的代币符号](../../管理端/M6-合约管理/01-合约管理-PRD.md#symbol)原文展示，为 COU【确认】 |
| 代币图标 | 代币符号对应的识别图形，由设计提供、不写入合约，按 [M6 的代币符号与图标](../../管理端/M6-合约管理/01-合约管理-PRD.md#symbol)；不是企业或运营维护的数据 |
| 代币类型 | 代币图标与代币符号合在一起，用来识别这是哪一种代币 |
| 应收账款原值 | 关联资产的资产价值，即应收账款金额与币种 USD，按 [M2 的资产价值](../../两端共用/M2-可信资产/01-可信资产-PRD.md#2-术语)；铸造与调价都不改写 |
| 当前代币单位价值 | 最近一次链上成功生效的单位价值，按“1 COU = X USD”展示；链上更新处理中或失败时仍展示原有效值 |
| 当前资产估值 | 发行数量 × 当前代币单位价值，单位 USD；系统自动计算，不替代应收账款原值 |
| 发行人 | 申请发行这枚代币的企业，即本企业 |
| 铸造到账地址（发行地址） | 铸造时代币进入的 Ethereum 数币地址，即该代币的第一个持有地址、发行申请提交时记录的接收地址；作为代币发行信息的一项记录，以“发行地址”展示【确认】；是不可变的发行事实，也是唯一可以签名发起销毁的地址，之后代币所在地址变化都不改写【确认】 |
| 当前所在地址 | 代币当前所在的数币地址，从链上查询取得；未质押时即当前持有地址，质押期间（含违约）即质押地址；只展示当前所在的地址本身，不展示转入质押前的地址或账户备注名【确认】 |
| 质押地址 | 融资质押时代币所在的下游质押合约地址；代币不在质押合约中时称质押地址为空。融资质押动作只能由下游借贷平台发起，包括转入、转出质押地址；解除质押后代币回到转入质押前所在的地址，违约后代币留在质押合约地址【确认】 |
| 融资状态 | 下游借贷平台提供的融资情况，企业看到未融资或融资中；销毁资格还必须通过链上无融资质押校验 |
| 资产托管 | 资产托管机构对代币所对应现实资产（应收账款）的托管，从铸造成功开始，到资产托管机构解除托管为止；与融资质押是独立关系。哪些机构是资产托管机构、谁能解除，按 M4b [本代币的资产托管机构](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#custodian) |
| 发行机构文件 | 本代币锁定发行机构名单内机构上传的文件，按机构类型分为托管文件、法律文件和审计文件，企业只读查看、下载，见[发行机构文件](#institution-files) |
| 处理中的销毁申请 | 已进入销毁中、执行结果仍在进行或尚未确认的申请；销毁失败是该笔申请的结束结果，不继续占用处理中名额 |
| 提交锁 | 企业确认申请销毁、调起钱包签名之前，平台对该代币加的临时占用；不是申请，也不改变代币或申请状态，见[销毁提交锁与交易归属](#submit-lock) |
| 平台入口 | 平台在当前业务与链上条件全部通过后提供的销毁入口；入口准入不是链上强制条件，也不赋予平台销毁控制权 |
| 非平台入口销毁 | 该代币既没有提交锁、也没有销毁中申请时，平台监听到的有效链上销毁（如企业绕过本平台入口直接调用合约）；平台须承认结果、补建记录、标记来源并通知运营审计 |
| 已到期 | 当前已达到或超过该笔应收账款的到期时点；到期时点为来源时区下到期日当天的结束时刻（24:00），由 M2 [到期时点](../../两端共用/M2-可信资产/01-可信资产-PRD.md#due-time)定义【确认】；查看者的时区只影响展示 |
| 已结清 | 上游明确提供已结清，不依据回款金额、余额为零或逾期状态自行推断 |

## 3. 身份、入口与共同展示规则

### 3.1 身份与数据范围

- 只有已认证的企业用户可以查看本企业代币和销毁申请；查看范围按稳定企业身份判断，不要求当前登录地址等于铸造到账地址。通过平台入口发起时，当前企业必须是该代币原发行企业，并由该代币的铸造到账地址完成销毁交易签名与提交；非发行企业和其他地址均不能发起【确认】。
- 未登录时按[登录后返回原目标（C-AUTH-05）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-05)登录后重新判断；游客按[游客引导与功能限制（C-GUEST-01）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-GUEST-01)处理；未认证企业用户按[认证资格与受限引导（C-AUTH-04）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-04)处理，不返回业务数据。
- 其他企业的代币或申请与不存在的对象统一说明“相关内容暂不可访问”，不区分是否存在；直接访问、刷新、绕过界面提交均按同一权限判断。
- 每个企业只有一个登录地址，本期不允许变更，企业归属也不会变化【确认】，按 M1 [识别同一个用户与企业](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#enterprise-identity)。销毁发起权固定为代币的铸造到账地址，不以当前登录地址判断；签名时可把钱包切换到铸造到账地址而不改变登录身份；无法控制该地址时不能发起销毁。企业账户只展示当前登录地址，按[查看唯一企业账户（C-ACCOUNT-01）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-ACCOUNT-01)。
- 退出或切换钱包后，不残留旧企业业务数据；迟到的结果不得显示旧企业内容。

### 3.2 入口与返回

- 面客端保留“我的代币”和“销毁申请”两个业务入口，与 M3a 的入口口径一致；分组、位置和页面承载由设计决定。我的代币进入代币列表，销毁申请进入申请列表。
- M3a 铸造成功申请的[申请详情（C-ISSUE-06）](../M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#C-ISSUE-06)、M2 的已发行资产中，点击代币编号进入对应代币详情；未铸造成功的申请没有代币编号，不会产生可访问的代币详情。
- 从原业务或消息进入详情后，可以返回原入口；从列表进入详情后可以返回对应列表。

| 资产编号 | 该资产的可信资产详情，内容按[企业查看本企业可信资产（F-AS-03）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-03) | 代币详情、销毁申请列表、申请详情 |
| 发行申请编号 | 原发行申请的[申请详情（C-ISSUE-06）](../M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#C-ISSUE-06) | 代币详情 |

- 前往其他对象不另设“查看发行申请”“查看资产”等文字入口；编号可点击须能被辨认，呈现由设计决定。
- 列表操作列中的“查看”进入本行对象自己的详情，与点击本行编号进入同一详情，沿用平台列表的统一做法【确认】，见[我的代币列表的操作](#token-actions)。
- 当前所在详情对应的编号不再指向自身；申请销毁的确认环节只展示编号，不提供前往，避免中断提交。
- 目标对象暂不可访问时说明原因，仍可返回原页面；无权与不存在按[身份与数据范围](#access)统一处理。
- 数币地址、合约地址只供核对，不跳转区块链浏览器，见[本期不做](#out-of-scope)。

<a id="shared-display"></a>
### 3.3 展示、缺失与读取异常

- 字段名、状态名称和说明支持中文与英文；机构名称等业务原文不自动翻译。代币符号、网络名称 Ethereum、编号和数值不随语言变化。
- 完整代币数量等于铸造时的完整资产价值，单位为铸造所用合约的代币符号，不以 USD 为单位；应收账款原值与当前资产估值带币种 USD，当前单位价值按“1 COU = X USD”展示。普通列表和详情的金额主显示沿用平台金额展示规则；当前资产估值主显示两位小数，超出部分直接截断、不四舍五入，标明已截断并可核对完整值【确认】。计算、销毁确认、签名、申请记录和上链使用完整值。发行数量、应收账款原值、当前单位价值与当前资产估值含义不同，不能互相替代。
- 代币符号为 COU【确认】，按 [M6 的代币符号](../../管理端/M6-合约管理/01-合约管理-PRD.md#symbol)；平台内展示设计提供的代币图标，按 [M6 的代币符号与图标](../../管理端/M6-合约管理/01-合约管理-PRD.md#symbol)；暂无对应图标时只展示代币符号，不影响识别和办理。
- 日期时间按本人[偏好设置（C-PROFILE-02）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-PROFILE-02)换算；到期判断按[结清与逾期依据](../../两端共用/M2-可信资产/01-可信资产-PRD.md#overdue)，切换语言、时区不改变资格、事件先后或业务状态。
- 到期日按到期时点换算到本人所选时区展示，同时展示日期、时间和时区，避免把错开一天的日期误读为与应收账款到期日不一致【确认】。
- 数币地址、合约地址按[钱包地址与网络名称的展示](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#address-display)缩写展示，可以核对完整地址；网络统一为 Ethereum，合约标准为 ERC-3525。
- 读取中、读取失败和确实没有数据应可区分。读取失败可重试，不显示成没有代币或没有申请；未知值不补为零、未融资、已结清或已解除托管。
- 上游或下游暂不可用时，仍可查看本平台已取得的代币、申请及结果；依赖信息无法取得时明确说明，不能以旧展示或未知值放行提交。部分信息失败不遮蔽其余已取得内容。
- 只展示的业务信息均不可由企业编辑；本模块没有额外自由填写字段，不增加原因、备注、凭证等提交要求。

## 4. 我的代币列表（C-TOKEN-01）

适用角色与前提：已认证的企业用户。本模块只有这一种角色，列表信息按“找到代币”的用途取舍。

- 列出本企业全部已铸造代币，包含有融资质押、有销毁中申请和已销毁的代币；已销毁后保留记录，不能通过销毁使历史从列表消失。
- 每枚代币一行，每项只承载一类信息，按下表展示；列的先后除所属网络为首项【确认】外由设计决定。

| 列表信息 | 取值与展示 | 依据 |
| --- | --- | --- |
| 所属网络 | Ethereum；列表首项 | 用户指定【确认】 |
| 代币类型 | 代币图标与代币符号 | 用户指定【确认】 |
| 代币编号 | 平台内唯一代币编号；点击进入该代币详情 | 同网络、同符号的代币只能靠编号区分，且编号是进入详情的入口 |
| 代币数量 | 铸造成功的完整数量；主显示可直接截断至两位小数，但须标明已截断并可核对完整值；单位为代币符号 | 用户指定【确认】 |
| 当前单位价值 | 最近一次链上成功生效的完整值，按“1 COU = X USD”展示；更新处理中仍展示原有效值 | 用户指定【确认】 |
| 当前资产估值 | 发行数量 × 当前单位价值，带币种 USD；主显示两位小数，超出部分直接截断并标明已截断，可核对完整值；只读 | 用户指定【确认】 |

- 列表只展示状态值，不附加限制原因或解释性内容；能否申请销毁及原因统一在[销毁资格与限制原因（C-TOKEN-03）](#C-TOKEN-03)中判断。
- 以下信息不在列表展示，只在[代币详情（C-TOKEN-02）](#C-TOKEN-02)查看：

| 移出列表的信息 | 详情中的位置 | 不在列表展示的原因 |
| --- | --- | --- |
| 关联资产（资产编号、债务人名称） | 发行关联业务 | 当前单位价值、当前资产估值与到期日已在列表展示；资产编号在详情中可前往资产详情 |
| 所属合约（名称、标准、合约地址） | 代币发行信息 | 代币类型已识别代币种类；合约用于核对，不用于查找 |
| 发行人、发行时间、铸造到账地址 | 代币发行信息 | 追溯用信息，查找代币时不需要；列表已按发行时间排列 |

| 融资状态 | 持有信息列表，按行展示 | 每枚未销毁代币只有一条当前持有记录，融资状态与当前所在地址在同一行对照，不能在列表中只放一个融资值【确认】；销毁资格须以详情中的当前结果为准 |
| 到期情况、应收账款结清情况 | 销毁条件与销毁记录 | 属于销毁资格依据，与限制原因一起在详情说明 |

<a id="token-actions"></a>
**我的代币列表的操作【确认】。** 列表设操作列，与平台其他列表统一；操作只针对本行代币：

| 操作 | 何时提供 | 结果 |
| --- | --- | --- |
| 查看 | 每一行都提供 | 进入该代币详情，与点击代币编号相同 |
| 申请销毁 | 代币未销毁、没有销毁中的申请和提交锁，并且最近一次成功取得的信息显示已到期、上游明确已结清、下游明确无融资、链上当前所在地址为铸造到账地址且质押地址为空；最近一次申请失败的代币满足这些条件时同样提供 | 立即重新取得必要依据，并按[销毁资格与限制原因（C-TOKEN-03）](#C-TOKEN-03)完整判断；满足时进入[申请销毁（C-BURN-01）](#C-BURN-01)，最近一次失败的按[销毁失败后重新发起（C-BURN-05）](#C-BURN-05)；不满足或无法确认时说明全部当前原因，不提供入口、不产生申请 |

- 列表操作是依据最近一次成功取得的信息给出的办理提示，不是销毁资格承诺；列表不规定缓存时长，缓存与刷新由研发实现，不能据此跳过点击后及提交前的当前资格判断。
- 不满足提供条件、依赖信息缺失或无法确认时，不显示“申请销毁”，不预先展示禁用的操作或原因；限制原因在代币详情中查看。
- 有处理中申请、有提交锁或已销毁的代币只有“查看”，进度在销毁进度和代币详情中查看。
- 列表不提供撤回、修改、转移或融资类操作，见[本期不做](#out-of-scope)。

- 未知或冲突的值按[共同展示规则](#shared-display)单独说明，不显示为正常结果。
- 本企业没有代币时说明当前尚无铸造成功的代币，可以前往代币发行查看申请；读取失败按[共同展示规则](#shared-display)处理。
- 列表和详情展示同一枚代币的当前结果；办理状态变化后，再次读取应反映新进度。

## 5. 代币详情（C-TOKEN-02）

适用角色与前提：已认证的企业用户，代币属于本企业。

代币详情分为：最上方的识别信息、[代币发行信息](#issuance-info)、[持有信息列表](#holding-info)、[发行关联业务](#issuer-links)、[资产托管信息与发行机构文件](#regulation-info)、[销毁条件与销毁记录](#burn-info)。分区名称与排列由设计决定。

<a id="token-identity"></a>
### 5.1 最上方的识别信息

- 详情最上方须展示所属网络、代币图标与代币符号、代币编号；所属网络、代币图标与代币符号优先于代币编号【确认】。
- 代币编号不能省略：当前所有代币都是 Ethereum、COU，同网络、同符号的代币只能靠编号区分。
- 具体排列与样式由设计决定。

<a id="issuance-info"></a>
### 5.2 代币发行信息

代币发行信息只收录发行时确定、之后不随代币所在地址变化的事实【确认】。资产托管情况与解除进度属于后续业务事实，在[资产托管信息与发行机构文件](#regulation-info)中单独展示，不作为 M3b 铸造结果字段。

| 业务信息 | 含义、来源与展示 |
| --- | --- |
| 代币编号 | 平台内唯一代币编号，与原发行申请、链上实际代币、网络和合约固定对应，按[代币及关联事实](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-token) |
| 所属网络与代币类型 | 所属网络 Ethereum；代币图标与代币符号，取铸造所用合约的代币符号 |
| 发行人 | 申请发行的企业名称，取发行申请提交时记录的企业名称，按原文展示 |
| 发行数量 | M3b 铸造成功的完整代币数量，主显示可直接截断至两位小数但须可核对完整值，单位为代币符号；企业不可改写 |
| 应收账款原值 | 关联资产的完整资产价值，主显示沿用平台金额展示规则，可核对完整值，带币种 USD |
| 铸造初始单位价值 | M3b 铸造成功时记录的单位价值，按“1 COU = X USD”展示；后续调价不改写 |
| 当前单位价值 | 最近一次链上成功生效的单位价值，按“1 COU = X USD”展示；更新处理中或失败时使用原有效值 |
| 当前资产估值 | 发行数量 × 当前单位价值，带币种 USD；平台自动计算；主显示两位小数，超出部分直接截断并标明已截断，可核对完整值 |
| 到期日 | 铸造结果的到期日，与应收账款到期日一致【确认】；资产确权后不再变化【确认】；到期时点按 M2 [到期时点](../../两端共用/M2-可信资产/01-可信资产-PRD.md#due-time)，同时展示日期、时间和本人时区 |
| 发行时间 | M3b 铸造成功时间 |
| 发行地址 | 代币铸造时的第一个持有地址，即铸造到账地址、发行申请提交时记录的登录地址【确认】；缩写展示，可核对完整地址；之后质押、解除质押或转让都不改变这项记录 |
| 所属合约 | 合约名称、标准 ERC-3525、合约地址；名称取[合约管理的信息](../../管理端/M6-合约管理/01-合约管理-PRD.md#fields)中的当前值，合约身份保持不变 |

代币铸造结果继承[审核与铸造的铸造结果清单](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-mint)。合约改名不改变代币的原有合约；平台停用不影响查看既有代币；满足原销毁条件时，企业仍可由钱包直接提交销毁交易，失败后可按当前条件重新发起，无需先启用原合约【确认】，见[停用与既有业务](../../管理端/M6-合约管理/01-合约管理-PRD.md#inflight)。

<a id="holding-info"></a>
### 5.3 持有信息列表

依据：持有数据从链上查询取得；链上合约允许按 M6 [完整转让限制](../../管理端/M6-合约管理/01-合约管理-PRD.md#F-CT-05)将一枚代币的当前全部持有数量转给一个接收地址；本模块本期不提供转让入口或转让办理流程。

- 持有信息在代币详情中以列表呈现，不以单项字段呈现【确认】：每条持有记录占一行，各列含义固定。每枚未销毁代币只有一行，仍按列表展示；合约禁止拆分或部分转让，不会因转让产生多条并存的持有记录，见 M6 [完整转让限制](../../管理端/M6-合约管理/01-合约管理-PRD.md#F-CT-05)【确认】。
- 列表各列如下，每列只承载一类信息；只展示代币当前所在地址，不展示转入质押前的地址、账户备注名或登录地址标识【确认】：

| 列 | 取值与展示 |
| --- | --- |
| 当前所在地址 | 代币当前所在的数币地址，从链上记录取得；未质押时为当前持有地址；质押期间（含违约）为下游质押合约地址，并标明这是质押地址；缩写展示，可以核对完整地址 |
| 持有数量 | 该行持有的完整代币数量，主显示可直接截断至两位小数但须可核对完整值，单位为代币符号；一期等于发行数量 |
| 融资状态 | 与该行对应的融资状态：未融资或融资中【确认】；与质押地址、下游结果互相矛盾或取不到时，按[融资与持有结果判定](#finance-check)说明融资结果不一致或暂时无法确认 |

- 列表外同时展示本次链上查询的时间。
- 地址只供核对，不跳转。
- 链上显示代币位于质押地址而下游显示未融资，或下游显示融资中而链上质押地址为空，属于融资结果不一致，按有融资质押处理。
- 解除质押后，代币回到转入质押前所在的地址，当前所在地址随之更新，质押地址变为空，融资状态按下游结果更新为未融资【确认】。
- <a id="defaulted"></a>**违约代币。** 融资违约后，代币留在质押合约地址【确认】：
  - 该行的当前所在地址为质押合约地址并标明是质押地址，融资状态按下游结果展示。
  - 本期不接入下游的违约状态，融资状态只有未融资和融资中；企业侧不区分违约与正常融资中，不另设违约标识【确认】。
  - 违约代币禁止销毁【确认】：企业不能申请销毁，说明代币仍在质押地址，见[销毁资格](#eligibility)。
  - 违约代币本期保持托管中，不提供解除资产托管；企业在发起前无法通过资格校验。若申请执行后才确认失败，原申请保留销毁失败，代币仍在质押地址，不能重新发起。
- 链上显示代币已按 M6 规则完整转让、当前所在地址不是铸造到账地址且不是质押地址时，属于允许存在的转让后状态，不作为合约异常，不仅因此提示联系平台。如实展示当前所在地址和完整持有数量，说明代币已转至其他地址；在整枚代币转回铸造到账地址前不具备销毁资格，见[销毁资格](#eligibility)。

- 融资状态只在持有信息列表中按行展示，不进入我的代币列表【确认】；本平台不能办理融资或解除融资质押。

## 6. 销毁资格与限制原因（C-TOKEN-03）

适用角色与前提：已认证的企业用户，当前企业是所选代币的原发行企业，且代币已铸造成功。

依据：到期、结清、没有任何融资质押（BR-07）【确认】；融资与持有结果交叉校验（BR-20）【确认】【建议·已采纳】；在途申请防重（BR-09）【建议·已采纳】；结果不一致按不满足处理（Q26）【建议·已采纳】。

<a id="eligibility"></a>
### 6.1 同时满足的条件

当前企业须是原发行企业，且当前身份及企业归属有效；在此前提下，以下四项须同时满足：

1. 当前已经达到或超过应收账款的到期时点（按 M2 [到期时点](../../两端共用/M2-可信资产/01-可信资产-PRD.md#due-time)），且上游明确提供该笔应收账款已结清；提前结清仍须等到期。
2. 下游结果明确为无融资质押；链上同时显示代币当前完整位于铸造到账地址且质押地址为空，具体组合按[融资与持有结果判定](#finance-check)。
3. 同一代币没有提交锁、没有销毁中的申请，也没有已经销毁成功的结果；销毁失败的原申请不阻断重新满足条件后发起新申请。
4. 到期、结清、融资及链上持有信息均能取得并确认。

以上四项是平台提供销毁入口的资格，其中到期、结清和下游融资结果属于链下业务准入；链上合约不重复核验。企业提交时只需由铸造到账地址完成一次销毁交易签名；当前登录地址、转让后的持有地址及其他地址不能替代铸造到账地址。

融资违约、质押或转让后，代币当前所在地址不是铸造到账地址或质押地址不为空，不满足条件 2，企业不能申请销毁，见[违约代币](#defaulted)。

托管中是正常的待销毁背景，不要求先解除资产托管再申请。历史逾期后已结清不额外阻断销毁；M2 的资产发行状态在铸造后保持已发行，不作为再次申请发行或阻止销毁的理由。无法取得销毁所需的结清、到期依据时不能提交。

<a id="finance-check"></a>
### 6.2 融资与持有结果判定

| 取得的结果 | 企业可见结果与本次资格 |
| --- | --- |
| 下游明确无融资质押，且链上显示代币完整位于铸造到账地址、质押地址为空 | 本项通过；仍须满足其他全部条件 |
| 下游明确无融资质押，链上显示质押地址为空、代币完整位于其他单一地址 | 按允许存在的整枚转让后状态展示，说明转回铸造到账地址前不能申请销毁；不标记合约异常，不提示联系平台 |
| 下游明确有融资质押，或链上明确显示质押地址不为空 | 说明对应质押限制，不能申请销毁；下游与链上质押结果互相矛盾时，一并说明结果不一致并提示联系平台 |
| 链上同一枚代币出现多个当前所在地址、无法解释的非完整持有数量，或所在地址、质押与数量事实互相矛盾 | 说明链上持有信息异常并提示联系平台，不能申请销毁；不将此类异常与正常整枚转让混同 |
| 任一必要结果未取得、失败或无法确认，且当前没有已确认的限制结果 | 说明暂时无法确认融资与持有情况，可重新获取，不能申请销毁；不声称确定有质押或无质押 |

以上是资格判断，不是新增融资状态；企业不需要理解接口或链上报文。只在下游和链上共同明确满足时放行，不能以单一来源、缓存的“未融资”展示、已结清或已解除托管替代校验。

### 6.3 多条件组合与用户结果

按表中顺序判断已销毁、处理中，再判断业务条件；同时不满足多个业务条件时说明全部已知原因。

| 代币与申请情况 | 到期、结清及融资情况 | 托管情况 | 企业能做什么 |
| --- | --- | --- | --- |
| 已销毁（资产托管机构尚未解除或已解除） | 不再用于开放新申请 | 托管中或已解除托管 | 查看原申请和解除结果，不能再申请销毁 |
| 有销毁中申请 | 即使其余条件都满足 | 托管中 | 查看处理中的申请，不能重复申请 |
| 有提交锁、尚未形成申请 | 即使其余条件都满足 | 托管中 | 看到提交结果确认中，不能再次提交，见[销毁提交锁与交易归属](#submit-lock) |
| 尚无申请，或最近一次申请为销毁失败 | 已到期、已结清，融资与持有结果校验通过，且能以铸造到账地址签名 | 托管中 | 可申请销毁；失败后按[销毁失败后重新发起（C-BURN-05）](#C-BURN-05)办理 |
| 尚无申请，或最近一次申请为销毁失败 | 未到期、未结清、仍有融资质押，或当前所在地址不是铸造到账地址、质押地址不为空，任一不满足 | 托管中 | 说明全部已知不满足项，不允许提交 |
| 尚无申请，或最近一次申请为销毁失败 | 到期、结清、融资或链上持有信息任一无法确认 | 托管中 | 说明暂不能确认的依据，可重新获取，不能提交 |

托管结果与销毁结果互相矛盾、代币缺少必要关联信息时，保留可查事实并说明当前无法确认，不能提交；由运营线下沟通处理，平台不提供线上处理通道，也不向企业提供强制改状态入口，按 M4b 的[共同异常](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#common-errors)。

## 7. 申请销毁（C-BURN-01）

适用角色与前提：已认证企业用户，当前企业是该代币原发行企业，并已选定满足[销毁资格](#eligibility)的本企业代币。

依据：申请销毁须连接钱包；只展示代币关键信息，其余在代币详情查看；交易签名地址固定为该代币的铸造到账地址，不随当前登录地址或后续持有地址变化【确认】。本次签名是链上销毁交易签名，不沿用 M3a 的发行申请业务签名。

<a id="burn-confirm"></a>

- 只展示代币的关键信息，均只读：

- 承载形式由设计决定，与申请发行保持一致。

<a id="burn-signing"></a>
### 7.2 销毁交易签名

- 连接钱包、切换网络或地址、平台资格校验均不触发签名。企业确认后，钱包只发起一次销毁交易签名；该签名同时完成链上授权和交易提交，不再先做业务预签名，也没有平台第二次签名。
- 交易发送地址必须是本代币的铸造到账地址，即铸造时的第一个持有地址【确认】；当前登录地址、转让后的持有地址或其他地址都不能替代。钱包当前地址不是铸造到账地址时，提示切换后再继续；钱包切换不改变本次登录身份、企业归属或代币归属。
- 企业无法控制铸造到账地址时不能销毁；平台不提供由当前登录地址、受让地址、运营、资产托管机构或平台钱包代签的替代路径。代币转让或质押在外时不能发起；只有完整回到铸造到账地址并重新满足资格后才可发起。
- 钱包签名并提交的交易必须指向选定代币及其完整数量；企业不能修改数量或改为部分销毁。企业钱包承担 gas；平台不代付、不托管私钥。
- 合约收到交易后校验交易发送地址、代币当前位置、质押地址、完整数量及未销毁状态，具体见 M6 [销毁发起地址限制](../../管理端/M6-合约管理/01-合约管理-PRD.md#F-CT-06)。到期、结清和下游融资结果不属于合约校验字段。
- 钱包拒绝签名或交易未成功广播时不产生销毁申请；交易广播成功并取得交易标识后，平台创建销毁申请并进入销毁中。签名前的提交锁、签名后未取得交易标识的处理，见[销毁提交锁与交易归属](#submit-lock)。交易失败后重新发起须重新通过当前资格校验并签署一笔新的销毁交易。

<a id="burn-submit"></a>
### 7.3 提交与结果

- 申请销毁是关键业务动作，调起钱包签名前按[上游变化的同步（C-AUTH-06）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-06)重新确认身份、有效企业和认证结论，并重新判断[销毁资格](#eligibility)。查看时曾满足条件不保证本次仍满足。
- 签名前销毁资格已变化，或必要结果无法确认时，不调起钱包签名【确认】。签名后资格再变化的，由合约的链上约束处理；交易已广播的按链上实际结果记录，执行失败即为销毁失败。
- 重新判断通过后，平台先对该代币加[提交锁](#submit-lock)，再调起钱包签名。
- 钱包广播交易成功并取得交易标识后生成平台内唯一的销毁申请编号，记录提交时间、交易发送地址及链上交易标识并关联原代币编号；申请进入销毁中，不产生平台签名或待运营审核阶段。展示已发起结果和销毁申请编号，点击编号进入该笔申请详情，也可返回我的代币。
- 一次成功提交只产生一笔申请。重复点击、刷新后再次提交或并发页面在签名前被提交锁拦截，说明已有提交在处理，不调起钱包；同一代币已有销毁中申请时，定位该申请供企业查看；结果重取不追加申请。

提交不成功的情况（以下都不产生申请，代币状态不变；已加的提交锁随之解除，签名后未取得交易标识的情况除外）：

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 企业取消签名或钱包拒绝签名 | 本次不提交，说明交易未发起；可重新通过当前资格校验后再试 |
| 钱包当前地址不是本代币的铸造到账地址 | 不能签名提交，提示在钱包中切换到该代币的铸造到账地址后重试；当前登录身份不变 |
| 钱包当前不在 Ethereum 网络 | 不能签名提交，提示在钱包中切换到 Ethereum 网络后重试 |
| 钱包交易构造或链上预估不通过 | 不调起或不继续签名，说明当前无法发起；重新取得当前资格与链上状态后再试 |
| 认证结论已变为未认证，或提交过程中登录结束 | 按 M1 [认证资格与受限引导（C-AUTH-04）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-04)或[退出与切换钱包（C-AUTH-03）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-03)处理；迟到的提交结果不显示 |
| 签名前销毁资格已改变，或上游、下游、链上必要结果无法确认 | 不调起钱包签名，说明当前限制，可返回代币查看 |
| 该代币已有提交锁或销毁中申请 | 签名前拦截，说明已有提交在处理，不调起钱包；有销毁中申请时可进入该申请 |
| 交易未成功广播 | 说明未完成，不产生申请；可重新校验后发起新的交易 |
| 签名后未取得交易标识（如页面关闭、网络中断） | 提交锁保持，企业看到“提交结果确认中”，不能再次提交，也不宣称成功或失败；平台按链上实际结果收口，见[销毁提交锁与交易归属](#submit-lock) |

<a id="submit-lock"></a>
### 7.4 销毁提交锁与交易归属

**提交锁【确认】**

- 加锁时点：企业确认申请销毁，调起签名前的身份与资格重新判断通过后，平台对该代币加提交锁，再调起钱包签名。
- 提交锁不是申请，不改变代币或申请状态，不产生消息，也不出现在销毁申请列表中。
- 提交锁存在期间，同一代币不能再次调起钱包；重复点击、并发页面或其他设备上的提交均在签名前被拦截，说明已有提交在处理。
- 钱包明确拒绝签名、企业取消，或确认交易未广播时，解除提交锁，代币按当前资格判断能否重新发起。
- 取得交易标识后创建销毁申请并进入销毁中，提交锁由该申请承接；之后能否再申请按申请状态判断。
- 签名后平台未取得交易标识时，提交锁保持；企业在代币详情和再次申请时看到“提交结果确认中”，不能再次提交。平台按链上实际结果收口：监听到归入本次提交的交易时，创建平台入口的销毁申请（销毁中），再按链上结果记录；确认本次没有形成链上交易时解除提交锁。确认方式由研发实现。

**交易归属【确认】**

- 代币存在提交锁或销毁中申请时，从该代币发行地址（铸造到账地址）发出的有效链上销毁，一律归入该笔提交或申请，交易来源为平台入口，不另建“非平台入口”记录。
- 只有该代币既没有提交锁、也没有销毁中申请时监听到的有效销毁，才由 M4b 补建“非平台入口”记录，见 M4b [销毁结果承接（A-BURN-03）](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#A-BURN-03)。

**销毁中长时间没有结果【确认】**

- 交易被加速替换、取消、被网络丢弃或长时间没有明确结果时，由平台开发线下处理；平台不提供线上超时处理入口，企业不能因等待时间较长而重新申请。
- 申请进入销毁中满 10 分钟仍无明确结果时，M4b 向全体运营发送一次[销毁超时待处理（NT-A08）](../../管理端/M4b-销毁审核与解除质押/03-销毁审核与解除质押-消息通知.md#NT-A08)；企业继续看到销毁中，不收到额外消息。
- 开发查明后，平台按实际结果收口：原交易被同一发送序号的其他交易替换、且该交易完成了有效销毁的，并入原申请记为销毁成功；确认原交易不会上链且没有完成销毁的，原申请记为销毁失败。

流程参见[校验、签名与提交（图 2）](./02-我的代币与销毁申请-流程图与状态机.md#fig-2)。

## 9. 申请详情与解除托管进度（C-BURN-03）

适用角色与前提：已认证企业用户，销毁申请属于本企业。

### 9.1 申请信息与结果

- 详情最上方须展示所涉代币的所属网络、代币图标与代币符号，以及销毁申请编号和当前申请状态；所属网络、代币图标与代币符号优先于编号【确认】。同一代币可能有多笔申请，销毁申请编号与状态不能省略。具体排列由设计决定。
- 展示提交时间、代币编号、资产编号、申请销毁数量（单位为代币符号）、铸造到账地址、所属合约与资产托管机构，按[申请信息](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-application)定位原记录；点击代币编号、资产编号分别前往代币详情、可信资产详情。
- 申请信息区分提交时的申请事实与当前关联信息，不用最新申请的值替代历史申请；合约与机构名称展示当前名称，与[代币详情](#C-TOKEN-02)一致；本模块不展示账户备注名。
- <a id="burn-signature-record"></a>销毁交易记录展示交易发送地址、交易提交时间、交易来源（平台入口／非平台入口）和当前链上结果；与 M4b [销毁交易记录](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-signature)使用同一笔事实。发送地址必须是铸造到账地址，记录不能修改；读取失败时说明暂时无法获取，可以重试，不影响其他信息。本期企业端不展示销毁交易哈希。
- 销毁失败时展示失败结果与失败时间；能重新满足条件时可重新发起销毁，见[销毁失败后重新发起（C-BURN-05）](#C-BURN-05)。
- 销毁成功展示销毁事实与结果数量；资产托管尚未解除时，明确下一步由该代币的资产托管机构办理，不能让企业误认为自己还要解除融资质押。
- 解除完成后展示已解除托管结果、办理机构当前名称和原解除完成时间，按[解除资产托管记录及企业可见范围](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-release)；同时展示解除说明，解除托管通知文件可查看、下载；不展示操作人。文件读取失败时说明暂时无法获取，可以重试。
- 企业不见内部失败说明；可见本次条件核对结果、销毁状态、失败时间及失败／成功结果，按[条件与执行记录](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-review)。销毁成功显示完整结果数量（单位为代币符号）与实际成功时间，按[销毁结果](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-burn)。
- 非平台入口记录没有经过平台入口校验，条件核对结果说明“未经过平台入口校验”，不显示为已通过；企业端不展示 M4b 的[非平台入口风险项](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#burn-risk)。

<a id="states"></a>
### 9.2 对象与状态

销毁交易由企业钱包提交后直接进入链上执行，不经过平台签名或运营审核。销毁申请状态与资产托管状态是两项独立事实，分别展示【确认】，与 M4b [对象与状态对应](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#states)一致；本节是对应展示，不另立并行状态机。

**销毁申请状态**

| 销毁申请状态 | 企业展示与可观察结果 | 可继续操作 |
| --- | --- | --- |
| 销毁中 | 企业钱包已广播销毁交易，尚无明确成功或失败结果 | 查看进度；不能重复申请 |
| 销毁失败 | 本笔交易已明确失败，代币未销毁；展示失败时间 | 重新满足当前条件后签署并提交一笔新的销毁交易 |
| 销毁成功 | 展示代币已销毁的结果、完整结果数量和成功时间 | 查看销毁结果与资产托管状态；不能再次销毁 |

**资产托管状态**

| 资产托管状态 | 企业展示与可观察结果 |
| --- | --- |
| 托管中 | 从铸造成功开始；代币未销毁或已销毁但资产托管机构尚未解除，均为托管中；展示资产托管机构当前名称 |
| 已解除托管 | 展示办理的资产托管机构已完成解除资产托管的事实、机构当前名称、完成时间、解除说明和通知文件 |
| 暂时无法确认 | 托管状态无法取得时的说明，不是业务状态，不视为已解除 |

**组合展示**

| 销毁申请状态 | 资产托管状态 | 企业看到的结果 |
| --- | --- | --- |
| 销毁中 | 托管中 | 销毁处理中，代币尚未销毁 |
| 销毁失败 | 托管中 | 本笔申请已结束，代币未销毁；能否重新发起按当前资格判断 |
| 销毁成功 | 托管中 | 代币已销毁，等待该代币的资产托管机构解除资产托管；不显示业务全部完成 |
| 销毁成功 | 已解除托管 | 代币已销毁，资产托管已解除，展示解除结果 |

- “待解除托管”是资产托管机构的待办事项，不是销毁申请状态或资产托管状态。
- 我的代币列表与代币详情中的销毁进度取该代币最近一笔申请的销毁申请状态；没有申请时为未申请。
- 销毁成功是结果事实，之后无论资产托管是否解除，都不能倒退成未销毁。
- 原销毁交易仍在进行或结果尚未确认时，申请保持销毁中，不能因等待时间较长自行显示失败、已销毁或允许企业重新申请；长时间没有结果的处理见[销毁中长时间没有结果](#submit-lock)。
- <a id="non-platform-burn"></a>非平台入口记录由 M4b 在监听到不属于任何平台提交的有效销毁时补建，直接为销毁成功，没有销毁中阶段，销毁中起始时间为空；企业在销毁申请列表和代币详情的销毁记录中看到该记录，交易来源显示“非平台入口”，代币变为已销毁，不再提供申请销毁入口。
- 销毁失败是本笔申请的结束结果。企业重新发起时形成新的申请编号和链上交易，原失败记录保持不变；代币按当前融资与持有事实重新判断资格，未知时说明无法确认并限制新申请，不用旧结果放行。
- 到期、结清、融资、资产托管与销毁各自回答不同问题，组合判定见[多条件组合](#C-TOKEN-03)；未知信息不构成新的业务终态。
- 资产托管与融资是独立事实；资产托管机构的确定与解除权限由 M4b 定义，本模块不从锁定发行机构名单自行推导。

<a id="message-entry"></a>
### 9.3 消息进入与返回

- 由 M4b 发给企业的相关消息进入消息所指的那一笔销毁申请，不能换成该代币的最新申请。
- 进入时重新确认身份与权限，并展示申请当前事实。旧失败消息仍进入原失败记录；如果代币另有处理中申请，应引导查看已有申请，不能因旧消息再次放行提交。
- 该申请已完成但仍有权查看时，正常显示完成结果；申请不存在或无权时按[身份与数据范围](#access)统一拒绝，可返回原消息。
- 消息内容、事件和收件范围由 M4b 自己维护；M4a 不新增结果通知，消息的已读不推动任何业务进度。

<a id="C-BURN-05"></a>
## 10. 销毁失败后重新发起（C-BURN-05）

适用角色与前提：本企业存在已明确销毁失败的申请，所涉代币尚未销毁，且当前没有销毁中的申请或提交锁。

- 原申请维持销毁失败结果；重新发起针对原代币创建新的销毁申请，不修改、复用或覆盖旧申请。
- 重新发起仍逐项执行[销毁资格与限制原因（C-TOKEN-03）](#C-TOKEN-03)，不能将原申请曾经通过校验当作本次资格。
- 企业重新核对确认信息，按[申请销毁（C-BURN-01）](#C-BURN-01)签署并提交一笔新的销毁交易；交易广播成功后新申请直接进入销毁中。旧申请和旧交易记录保持不变。
- 原代币已有销毁中的申请时进入已有申请；有提交锁时说明提交结果确认中；已销毁时只看结果；当前未结清、有融资质押、代币不在铸造到账地址或资格无法确认时，说明当前限制，不产生新申请。

<a id="pending"></a>
## 12. 待确认事项与依赖

资产托管与融资是两类独立事实：资产托管不阻断满足条件的销毁；“解除质押”只指下游融资质押的解除，“解除资产托管”只指 M4b 在销毁成功后由资产托管机构办理的后续事项。

- 一次签名完成销毁（待验证）：本模块要求企业钱包对销毁交易只签名一次并直接提交。现有合约若必须先执行独立授权交易，或必须由平台地址提交，则与本期业务决策冲突；由研发按 M6 [销毁发起地址限制（F-CT-06）](../../管理端/M6-合约管理/01-合约管理-PRD.md#F-CT-06)验证。验证前，[一次交易签名并成功提交（AC-M4A-16）](./04-我的代币与销毁申请-验收.md#AC-M4A-16)与[发行企业与铸造到账地址独占销毁发起权（AC-M4A-37）](./04-我的代币与销毁申请-验收.md#AC-M4A-37)待验，不判通过。
- 签名后未取得交易标识的提交锁长时间未收口（待确认）：提交锁保持期间企业不能再次提交；若链上始终没有可归属的交易、平台也无法确认本次未形成交易，代币会一直显示“提交结果确认中”。目前没有对此情形的运营提醒。影响企业能否重新发起销毁。当前处理：保持提交锁，按链上实际结果收口，长时间无法确认的由平台开发线下处理。
