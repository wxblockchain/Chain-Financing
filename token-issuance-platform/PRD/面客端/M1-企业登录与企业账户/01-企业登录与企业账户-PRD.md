本模块共四册：本册写功能、业务规则、字段规则与交互逻辑；[流程图与状态机](./02-企业登录与企业账户-流程图与状态机.md)画出主要流程与状态；[消息通知](./03-企业登录与企业账户-消息通知.md)写明本模块发出的消息；[验收](./04-企业登录与企业账户-验收.md)供测试使用。

## 1. 模块是什么

企业用户不在本平台注册，而是用 Ethereum 钱包地址登录：连接钱包、用该地址签名，验签通过后进入身份判定。本平台按该钱包地址向上游资产可信平台调取账户信息：调取到即建立企业用户登录，并取得其个人信息、企业信息和当前认证结论；调取不到即建立游客登录，只能看到前往注册或联系平台的引导；调取异常则不建立登录。企业用户认证通过后才能办理需要企业认证的业务；企业账户本期只展示上游当前登录地址，不提供新增、编辑或删除其他数币账户。

基本原则：

- 钱包控制权验证、身份判定、认证资格是三个独立环节：验签通过只代表用户控制本次钱包地址；调取结果确认后才建立企业用户或游客登录；认证通过才代表能办理需要企业认证的业务。
- 身份和资料来自上游：本平台不提供注册，也不采集、不修改个人与企业资料；每次登录都重新调取，不在本平台保存“地址属于哪个企业”的绑定关系。
- 企业账户中只有上游当前登录地址这一条数币账户。

**一个完整的例子。** 企业 A 的操作人员连接钱包，用该钱包地址完成登录签名。验签通过后，本平台进入身份判定，按该地址向资产可信平台调取到唯一且可用的账户，取得个人信息、「A 公司」的企业信息和“已认证”结论，由此建立已认证企业用户登录。操作人员在企业信息中核对资料，在企业账户中看到唯一一条标明“登录地址”的 Ethereum 地址；退出后回到未登录状态。

### 1.2 本期不做

- 在本平台注册企业或用户，或修改个人、企业资料：由资产可信平台负责。
- 钱包登录以外的登录方式，如账号密码、邮箱、手机验证码。
- 指定支持哪些钱包：接入成熟的钱包 SDK 服务商，具体钱包不在本册展开。
- Ethereum 以外的网络。
- 登录状态下的“切换钱包”入口：换地址通过退出后重新登录完成。
- 新增、编辑或删除其他企业数币账户，以及账户备注名、默认账户和“设为默认”的操作。
- 法币（银行）账户：本模块的企业账户只指数币账户。
- 同一企业多个成员或多个登录地址：每个企业只有一个登录地址。
- 其他业务模块如何使用企业身份、认证结论或当前登录地址；本模块只提供当前结果与重新调取规则。
- 管理端如何展示或使用企业账户信息。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 资产可信平台（上游） | 提供用户与企业身份、认证结论、已确权应收账款等信息的外部平台。本册所称“上游”均指它 |
| 本次钱包地址 | 用户本次连接并完成签名验证的 Ethereum 钱包地址；企业用户与游客都适用 |
| 登录地址 | 企业用户在资产可信平台登记、用于登录本平台的 Ethereum 钱包地址。每个企业只有一个；游客没有上游登录地址 |
| 企业用户 | 已登录，且按登录地址在上游调取到账户的用户。业务上也称“企业态” |
| 游客 | 已登录，但按本次钱包地址在上游调取不到账户的用户。业务上也称“游客态”或“登录后的游客” |
| 已认证 / 未认证 | 上游给出的当前有效认证结论。只有已认证的企业用户能办理业务；没有企业归属、认证未通过或审核中都属于未认证 |
| 调取时点 | 本平台主动向上游取得最新账户、资料与认证结论的时机，见[上游变化的同步（C-AUTH-06）](#C-AUTH-06) |
| 企业账户 | 展示本企业当前登录地址的功能，也是其入口与页面的名称；本期只有当前登录地址这一条数币账户 |
| 数币账户 | 本期即企业当前登录地址；不包含企业新增的其他地址 |
| 登录签名 | 登录时用本次钱包地址对一条登录消息签名，证明登录者控制该地址。不是交易，不消耗 gas，不转移或授权任何资产 |

**钱包地址与网络名称的展示**（本模块各处共用）：

## 3. 登录与身份

<a id="C-AUTH-01"></a><a id="c-auth-01"></a>
### 3.1 连接钱包与签名登录（C-AUTH-01）

适用角色与前提：未登录的访问者。

依据：钱包地址登录、不在本平台注册（BR-01）【确认】；仅支持 Ethereum（BR-17）【确认】；签名规则【确认】。

- 未登录时只能通过连接钱包登录；本平台不提供注册入口，也不提供其他登录方式，也不通过输入邮箱等信息识别身份。
- 登录入口说明“使用在资产可信平台登记的钱包地址登录”，并展示支持的网络：Ethereum。
- 登录依次经过以下步骤【确认】：

| 步骤 | 用户可见结果 |
| --- | --- |
| 1. 连接钱包 | 用户发起连接，在钱包中选择 Ethereum 地址。地址只取自钱包，不能手动输入 |
| 2. 连接成功 | 展示本次连接的地址与网络。只连接成功不算登录，不调取上游、不判定身份 |
| 3. 确认签名 | 用户确认发起登录签名。确认前说明本次将请求一次登录签名、不涉及转账或资金授权；不能只靠钱包自身的提示 |
| 4. 钱包签名返回 | 用户在钱包中签名，签名结果返回本平台 |
| 5. 验签通过 | 本平台按[登录签名规则](#signature-rules)校验签名 |
| 6. 身份判定 | 验签通过后确认用户控制本次钱包地址，立即进入上游身份判定；此时平台登录尚未建立 |

- 验签通过后立即按[按地址匹配上游身份（C-AUTH-02）](#C-AUTH-02)调取上游；调取期间给出处理中反馈。只有身份判定得到有效结果后，才建立企业用户或游客登录。

<a id="signature-rules"></a>
登录签名规则：

- 钱包内的签名消息须声明用途：签署只用于证明拥有该钱包，不发起交易、不消耗 gas，也不转移或授权任何资产。签名时用户能核对本次钱包地址的全文。
- 每个签名请求只能成功使用一次。签名请求按服务端时间在“签发时刻（含）至签发时刻 + 5 分钟（不含）”内有效，到达 5 分钟整即失效；客户端倒计时只作提示，不能改变服务端判定。已使用或已过期的签名被拒绝、不建立登录；平台准备新的签名请求，由用户重新签名。硬件钱包确认较慢时，页面不得早于 5 分钟自行判定超时。
- 签名地址必须与本次连接的地址一致，签名使用的网络必须是 Ethereum；由平台校验，不能只靠界面限制。平台能否校验签名所用网络取决于登录签名格式，待验证，见[登录签名的网络校验](#signature-network)。
- 签名失败不累计锁定次数，也不锁定任何账户；同一 IP 1 小时内验签失败超过 20 次后降速，不封禁 IP。

登录过程中的异常：

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 没有可用钱包，或钱包无法唤起 | 说明原因，提示安装或启用钱包后重试；仍为未登录，不提供其他登录方式 |
| 用户取消连接，或钱包处于锁定状态 | 回到发起登录的原处并说明原因（钱包已锁定时提示先解锁），可重新连接 |
| 连接成功后未确认签名就取消或离开 | 不建立登录，回到发起登录的原处，可重新连接 |
| 钱包当前不在 Ethereum 网络 | 提示在钱包中切换到 Ethereum 网络后重试；不建立登录。绕过界面用其他网络签名同样不能登录 |
| 用户拒绝签名、验签失败，或签名地址与连接地址不一致 | 不建立登录，也不透露该地址在上游是否有账户；可重试 |
| 连接成功后或签名过程中，钱包切换了地址 | 中止本次登录并说明钱包地址已变化，提供“用该地址重新登录”：以新地址重新签名并重新调取；不静默改用新地址，新地址也不能沿用原地址的签名 |
| 签名请求已过期或已被使用 | 不建立登录，平台准备新的签名请求，提示用户重新签名 |

流程参见：[登录与身份判定（图 1）](./02-企业登录与企业账户-流程图与状态机.md#fig-1)。

<a id="C-AUTH-02"></a><a id="c-auth-02"></a>
### 3.2 按地址匹配上游身份（C-AUTH-02）

适用角色与前提：已完成签名验证、正在判定身份的未登录用户。

依据：按地址匹配上游，匹配到为企业、匹配不到为游客（BR-01）【确认】；每个企业只有一个登录地址（BR-16）【确认】。

- 每次完成验签后都由本平台主动按本次钱包地址向上游调取，不沿用上一次登录的结果，也不依赖上游主动推送。
- 只按本次钱包地址调取；不按企业名称、邮箱、手机号等其他信息近似匹配。同一地址的不同写法（大小写不同、带或不带 0x 前缀）视为同一地址；上游登记的地址不是 Ethereum 地址格式时无法比较，按调取不到处理。
- 调取由本平台服务端发起，并确认结果确实来自资产可信平台、未被篡改；客户端提交的上游数据一律不采信。首次身份判定遇到来源无法确认的结果时不建立登录；登录期间重新调取遇到该结果时不改变当前登录，并产生安全告警。

调取结果与用户看到的结果：

| 调取结果 | 本次登录结果 | 用户看到的结果与可继续操作 |
| --- | --- | --- |
| 调取到唯一账户，且上游账户可用 | 企业用户 | 取得个人信息、企业信息和当前认证结论；能否办理业务按[认证资格与受限引导（C-AUTH-04）](#C-AUTH-04)。有个人信息但没有企业信息时同样是企业用户，有什么信息展示什么信息，并提示企业信息需在资产可信平台完善 |
| 调取不到（含上游没有登记该地址） | 游客 | 只看到游客引导，见[游客引导与功能限制（C-GUEST-01）](#C-GUEST-01)；不提示该地址是否曾在上游登记过 |
| 调取到，但上游账户已锁定或禁用 | 不成为企业用户，本次登录结束，回到未登录 | 说明原因，并显示实际能取得的解除信息，不编造 |
| 调取失败、超时或上游不可用 | 不等于调取不到：本次登录不成立，仍为未登录 | 说明“暂时无法确认身份，请重试”，可重新登录 |
| 调取到账户，但当前认证结论缺失 | 按调取失败处理：本次登录不成立，仍为未登录 | 说明“暂时无法确认身份，请重试”，可重新登录 |
| 调取结果来源无法确认 | 本次登录不成立，仍为未登录 | 给出中性说明，可重新登录；产生安全告警 |
| 调取到账户，但缺少稳定账户标识 | 本次登录不成立，仍为未登录 | 说明本次无法完成登录，并给出错误码；可以重新登录，或返回发起登录的原处，仍为未登录；产生告警 |
| 一个地址调取到多个上游账户 | 按数据异常处理：本次登录不成立，不取其中任何一个账户 | 说明请联系资产可信平台；可以返回发起登录的原处或重新登录，仍为未登录；产生告警 |
| 调取到，但本平台建立企业用户失败 | 本次登录不成立 | 给出错误码，并提供重试和放弃并返回两条出路，不静默返回；放弃并返回时回到发起登录的原处，仍为未登录 |

- 所有失败都不暴露内部判定原因。数据来源不可信、缺少稳定标识、一个地址调取到多个账户等异常须产生运维告警，这不是给运营人员发站内消息。

<a id="enterprise-identity"></a><a id="Q-M1-07"></a>
识别同一个用户与企业：

- 本平台按上游稳定、不可变的账户标识识别企业用户，按上游企业标识识别其所属企业；登录地址只是调取入口和登录凭据，不是识别依据，本平台也不保存“地址属于哪个企业”的绑定关系。具体使用上游的哪个标识，由研发在对接资产可信平台时确定。
- 首次调取到即建立本平台的企业用户，此后按稳定标识复用，本模块资料与偏好接续。
- 缺少稳定标识的上游数据不能用于建立企业用户；邮箱、企业名称都不用于识别或合并。
- 上游没有提供企业标识时，按没有企业归属处理：不阻断登录，属于未认证（即使上游给出已认证结论），不能查询或查看任何企业消息，企业信息按没有企业归属说明。
- 本期资产可信平台登记的登录地址不允许变更【确认】。
- 企业归属不会变化【确认】：企业用户取得企业归属后，不会改为其他企业，也不会被移除。没有企业归属的企业用户在资产可信平台完成企业信息登记后，在下一个调取时点取得企业归属，不需要重新登录，见[上游变化的同步（C-AUTH-06）](#C-AUTH-06)。

流程参见：[登录与身份判定（图 1）](./02-企业登录与企业账户-流程图与状态机.md#fig-1)、[面客端登录状态机](./02-企业登录与企业账户-流程图与状态机.md#state-1)。

<a id="C-AUTH-04"></a><a id="c-auth-04"></a>
### 3.3 认证资格与受限引导（C-AUTH-04）

适用角色与前提：企业用户。

依据：调取到但未认证不能办理业务，只有认证通过才能办理【确认】；游客不能使用业务功能【建议·已采纳】。

- 能否办理业务只看上游给出的当前有效认证结论，与资料是否齐全、是否有个人信息无关。资料已存在不代表已认证。
- 已认证的企业用户可查看本模块的企业账户，并具备“已认证企业用户”资格；其他业务能否办理及具体规则由对应模块定义。
- 未认证的企业用户（没有企业归属、认证未通过或审核中）：
  - 都可以查看[用户信息与企业信息（C-PROFILE-01）](#C-PROFILE-01)。有有效企业归属时可以使用企业消息；没有有效企业归属时不得查询或查看任何企业消息。认证未通过或审核中时，用户信息与企业信息处提供“前往完成认证”的入口，见[三种企业状态的说明](#profile-status)。
  - 可以看到业务功能的入口，进入或触发业务动作时被拦下，看到“需先在资产可信平台完成认证”的说明和前往完成认证的入口；不整页封锁，不返回任何业务数据。前往时按[前往资产可信平台](#leave-confirm)确认。
  - 直接访问业务功能同样被拒绝；拒绝由平台判定，不能只靠隐藏入口。
- 认证从未认证变为已认证，或从已认证变为未认证，在下一个调取时点生效，不需要重新登录，见[上游变化的同步（C-AUTH-06）](#C-AUTH-06)。从已认证变为未认证时，不结束登录，只停止办理需要认证的业务，并向该企业用户本人发一条必发消息，见[认证失效通知（NT-C09）](./03-企业登录与企业账户-消息通知.md#NT-C09)；业务限制不等待消息送达。
- 受限后的说明须对辅助技术可读，当前状态与受限原因可被获知。

流程参见：[受限引导与前往资产可信平台（图 6）](./02-企业登录与企业账户-流程图与状态机.md#fig-6)。

<a id="C-AUTH-05"></a><a id="c-auth-05"></a>
### 3.4 登录后返回原目标（C-AUTH-05）

适用角色与前提：未登录时访问受保护的内容（例如从消息链接直接打开某条消息）而被要求登录的用户。主动连接钱包登录没有原目标。

- 登录前保留原目标。身份判定完成并建立企业用户或游客登录后，重新按当前身份判断权限，不能把登录成功当作已有权限：
  - 有权访问即回到原目标。
  - 无权访问时，按原目标所属模块的无权规则处理：游客看到游客引导；需要企业认证的业务功能对未认证的企业用户给出认证引导，见[认证资格与受限引导（C-AUTH-04）](#C-AUTH-04)。
  - 原目标是消息时，按消息通知模块（M7）的查看与前往规则处理；例如企业 B 的用户打开发给企业 A 的消息，按消息不存在处理，不展示其内容。
- 没有原目标或原目标无效时，进入登录后的默认页面（具体页面由设计确定）。
- 原目标只用于本次登录，按服务端时间在“保存时刻（含）至保存时刻 + 30 分钟（不含）”内有效，到达 30 分钟整即失效；客户端倒计时只作提示，不能改变服务端判定。原目标只能成功使用一次，完成、放弃或登录结束后失效，不能被其他会话或设备使用。
- 原目标已过期时说明链接已失效并进入默认页面；其他不允许的目标只说明已进入默认页面，不展示内部拒绝原因，不白屏。
- 调取失败导致登录不成立时，回到发起登录的原处，可重试。

<a id="C-AUTH-06"></a><a id="c-auth-06"></a>
### 3.5 上游变化的同步（C-AUTH-06）

适用角色与前提：完成登录签名后的身份判定阶段，以及企业用户登录期间。

上游的资料、认证结论和账户可用性变化，以及登录期间按该地址调取不到账户的情况，须及时反映到本平台。登录地址本期不允许变更，企业归属不会变化，见[识别同一个用户与企业](#enterprise-identity)。本平台主动调取，不接收上游推送。调取时点：

| 时点 | 内容 |
| --- | --- |
| 每次完成签名验证后 | 按[按地址匹配上游身份（C-AUTH-02）](#C-AUTH-02)调取账户、个人与企业信息及当前认证结论，判定是否建立登录 |
| 关键业务动作提交前 | 再次按登录地址调取，核对能否调取到账户、账户可用性与认证结论；旧结果不能放行关键动作。哪些动作属于关键业务动作由对应业务模块认定 |
| 登录期间 | 距上次成功调取超过 60 秒后的下一次请求前，重新调取并核对上述内容；恰好 60 秒时的普通请求不触发本次复查，超过 60 秒才触发；页面停留且没有请求时不主动调取 |

上游变化在下一个调取时点被发现并生效，本期不承诺秒级同步：

| 变化 | 本平台的处理 |
| --- | --- |
| 登录期间按该地址调取不到账户 | 任一调取时点确认后立即拒绝当前操作并结束本次登录，回到未登录；只说明登录已结束，不说明具体原因，受保护内容不能继续查看 |
| 上游账户锁定或禁用 | 任一调取时点确认后立即拒绝当前操作并结束登录，回到未登录并说明原因，显示实际能取得的解除信息 |
| 认证结论变化 | 不结束登录；按[认证资格与受限引导（C-AUTH-04）](#C-AUTH-04)开放或停止需要认证的业务；由已认证变为未认证时发送[认证失效通知（NT-C09）](./03-企业登录与企业账户-消息通知.md#NT-C09)，调取失败或结论缺失不算认证失效 |
| 没有企业归属的企业用户取得企业归属 | 不结束登录；展示该企业的信息，按该企业的认证结论开放或限制需要认证的业务，可以使用该企业的消息；审核中的企业登记不提前生效 |
| 个人、企业基本资料变化 | 只影响展示，在下一个调取时点更新 |

- 登录期间调取失败、超时、上游不可用、来源无法确认或关键认证结论缺失时，保持当前登录和最近一次已确认的身份与资料，不把用户降为游客，也不应用本次异常结果；如本次调取由关键业务动作触发，则拒绝当前动作，说明暂时无法确认并允许稍后重试。
- 无法确认来源的调取结果（包括锁定、禁用或调取不到账户的结果）须产生安全告警；同一异常不反复打扰用户。
- 60 秒仅是普通请求触发重新调取的间隔，不是任何上游变化的宽限期。普通请求在距上次成功调取恰好 60 秒时不触发复查，超过 60 秒后的下一次请求才触发；关键业务动作提交前无论距上次调取多久都要重新调取。任一调取时点确认变化后立即应用。
- 上游撤回资料可见权限的情形本期不考虑。

流程参见：[上游变化的同步（图 5）](./02-企业登录与企业账户-流程图与状态机.md#fig-5)。

<a id="C-AUTH-03"></a><a id="c-auth-03"></a>
### 3.6 退出与切换钱包（C-AUTH-03）

适用角色与前提：已登录的用户（企业用户或游客）。

依据：退出、切换（C-AUTH）【确认】；登录有效期【确认】；登录成功后钱包切换地址与登录无关【确认】。

- 主动退出只有一个入口，企业用户和游客都可以使用。退出后回到未登录并说明，受保护内容不能继续查看，不残留上一个地址的资料或数据。
- 本平台退出不退出资产可信平台；用户在资产可信平台正常退出，也不结束本平台的登录。
- 登录状态下不另设“切换钱包”入口。需要换地址时，先退出，再用另一个地址登录；新地址按[按地址匹配上游身份（C-AUTH-02）](#C-AUTH-02)重新判定，不继承原地址的身份、资料或数据。
- 登录成功后，本次登录只对应完成签名验证并用于身份判定的钱包地址。之后在钱包中切换到其他地址，在登录层面不受影响：不提示、不结束登录，身份、资料和数据仍按本次已建立的登录展示；不需要新增签名的内容照常浏览。
- 连接钱包和切换钱包地址本身不触发新的签名。其他功能如需钱包签名，由对应模块定义并核对所需地址；其核对结果不改变本模块已建立的登录身份、企业归属与可见资料。

登录有效期：

| 身份 | 有效期 |
| --- | --- |
| 企业用户（不论是否已认证） | 自企业用户登录建立起 7 天 |
| 游客 | 自游客登录建立起 4 小时 |

- 有效期是绝对时长，到期即结束，不因操作延长；没有“记住我”。
- 到期后回到未登录并说明，受保护内容不能继续查看，不自动跳转或弹出登录；需重新签名登录。
- 登录结束时尚未保存的内容提示未保存，不保留草稿；之后迟到的操作结果不能恢复登录。

以下登录事件须可追溯：验签结果、上游调取结果、身份判定结果、资料同步、登录建立与结束及原因、锁定禁用与登录期间调取不到账户的发现与处理。登录凭据与签名原文不进入日志，联系方式须脱敏。

流程参见：[退出、切换钱包与登录到期（图 2）](./02-企业登录与企业账户-流程图与状态机.md#fig-2)。

## 4. 游客引导与功能限制（C-GUEST-01）

适用角色与前提：已登录、处于游客态的用户。

依据：引导文案【确认】；游客不能使用业务功能【建议·已采纳】；联系邮箱由开发配置【确认】。

- 游客看到引导：“前往资产可信平台进行注册 / 联系平台管理人员”。
  - 前往资产可信平台：提供前往入口，按[前往资产可信平台](#leave-confirm)确认后离开。
  - 联系平台管理人员：展示平台联系邮箱；邮箱由开发直接配置。
- 游客不能使用用户信息、企业信息、企业账户、企业消息或任何受保护的企业业务功能。相关入口不展示；直接访问被拒绝，不返回任何业务数据，不能只靠隐藏入口。
- 游客的账户入口只显示本次钱包地址和退出，便于用户到资产可信平台登记或向平台说明。
- 用户在资产可信平台完成注册并登记该地址后，须重新登录，调取到即成为企业用户；从资产可信平台返回本平台本身不触发重新判定。

<a id="leave-confirm"></a>
前往资产可信平台（游客引导与认证引导共用）：

- 离开前先告知将前往的平台名称“资产可信平台”，用户确认后才离开本平台。
- 用户取消时回到发起处，不改变当前登录和身份，不清空原来的浏览内容。
- 本平台不提供前往资产可信平台查看或修改资料的入口；前往入口只用于注册与认证。

流程参见：[受限引导与前往资产可信平台（图 6）](./02-企业登录与企业账户-流程图与状态机.md#fig-6)。

## 5. 用户信息、企业信息与偏好设置

<a id="C-PROFILE-01"></a><a id="c-profile-01"></a>
### 5.1 查看用户信息与企业信息（C-PROFILE-01）

适用角色与前提：企业用户（已认证或未认证）。游客和未登录用户不可访问。

依据：数据来自上游【确认】；只读【建议·已采纳】；展示字段【确认】。

<a id="account-entry"></a>
账户入口：

- 登录后持续可见一个账户入口，显示本次钱包地址，按[钱包地址的展示](#address-display)缩写；地址读取不到时显示“我的账户”，不使用假地址，也不阻断登录。
- 账户入口只提供两项【确认】：本次钱包地址（可核对完整地址并复制）和退出登录，不展示其他内容。企业用户和游客相同。
- 用户信息、企业信息、企业账户、消息通知从平台的导航进入，导航形式由设计确定。

<a id="profile-rules"></a>
展示规则：

- 用户信息与企业信息分开，可以各自直接访问并返回原处；用户信息内不重复整套企业资料。
- 来自上游的资料全部只读，并说明“这些信息由资产可信平台维护”；用户信息中只有[偏好设置（C-PROFILE-02）](#C-PROFILE-02)可以修改，须与上游资料可区分。本平台不提供任何编辑入口（包括不可用状态的编辑入口），不在本地录入、补填或推断资料，也不提供前往上游查看或修改资料的入口（认证未通过或审核中时的“前往完成认证”入口用于认证，见下表）；绕过界面的修改同样被拒绝。
- 资料只对本人可见；资料始终对应当前有效企业。退出或换地址后不残留旧资料，迟到的结果不显示他人或上一次登录的信息。
- 读取中、读取失败、确实没有数据三种情况须可区分：读取中给出处理中反馈；读取失败说明失败并可重试，不显示为空；单项可选值确实没有时不展示该项。个人信息整组缺失或企业信息整组缺失时，保留入口和空状态，空状态只说明资料由资产可信平台维护及当前状态。
- 证件影像、企业证明、授权材料、审核记录不在此展示。

<a id="profile-status"></a>
三种企业状态的说明须分开，不能合并为一句：

| 当前情况 | 用户信息与企业信息处的说明 |
| --- | --- |
| 没有企业归属（上游未完成企业信息登记，或上游没有提供企业标识） | 说明企业信息需在资产可信平台完善；本处不提供跳转 |
| 有企业归属，但认证未通过或审核中 | 说明认证状态须在资产可信平台查看，并提供“前往完成认证”入口，按[前往资产可信平台](#leave-confirm)确认后离开；不表述为“没有企业”，也不替上游预判结果 |
| 已认证 | 说明资料只读，由资产可信平台维护；本处不提供跳转 |

用户信息：

| 业务信息 | 含义与展示要求 |
| --- | --- |
| 本次钱包地址 | 本次签名验证过的钱包地址，来自本次登录而不是上游资料；企业用户的该地址应与上游当前登录地址一致，游客没有上游登录地址；按[钱包地址的展示](#address-display)缩写，可核对完整地址并复制，不能在本平台编辑 |
| 同步时间 | 本次调取上游资料的时间；只读 |
| 邮箱 | 上游提供的联系方式，只读；没有时不展示，不在本平台采集或修改 |
| 姓名、英文姓名 | 按上游实际提供分别展示，不自行翻译或补英文名 |
| 国籍 | 按上游认证信息展示，不从证件或地址推断 |
| 证件类型 | 如身份证、护照，以上游实际提供为准 |
| 证件号码 | 按上游提供的原值完整展示，不脱敏、不截断【确认】；只读，没有时不展示；站内消息中不出现证件号码，见[消息通知 · 内容与语言](../../两端共用/M7-消息通知/01-消息通知-PRD.md#content-rules) |
| 与企业的关系 | 如法定代表人、董事、授权代表，按上游实际提供展示，不据此设置本平台的角色权限 |
| 偏好设置：界面语言、时区 | 本人的偏好，可以修改，规则见[偏好设置（C-PROFILE-02）](#C-PROFILE-02) |

企业信息：

| 业务信息 | 含义与展示要求 |
| --- | --- |
| 企业 id | 当前有效企业在上游的标识；没有时不阻断登录，按没有企业归属处理，不能凭审核中的资料或企业名称推断归属 |
| 企业名称、英文名称 | 当前有效企业的名称，分别展示上游已提供的值，不用审核中的企业替代 |
| 注册国家 / 地区、州 | 按适用地区展示，不强制所有地区都有州 |
| 注册地址 | 上游提供的完整注册地址 |
| 企业登记标识 | 按注册地区展示，如中国统一社会信用代码、香港 CR / BR、美国 Entity / File / EIN、开曼及尼日利亚 RC，不混为同一项 |
| 当前有效认证结论 | 决定能否办理业务，见[认证资格与受限引导（C-AUTH-04）](#C-AUTH-04) |

以上字段以资产可信平台实际提供为准；除稳定账户标识外，都不是登录的必要条件。

<a id="C-PROFILE-02"></a><a id="c-profile-02"></a>
### 5.2 偏好设置：界面语言与时区（C-PROFILE-02）

适用角色与前提：界面语言适用于所有访问者（未登录、游客、企业用户）；时区只适用于企业用户。

依据：平台支持中文和英文【确认】；增加语言与时区偏好【确认】。

企业用户在用户信息的“偏好设置”中可以看到并修改两项偏好，两项互不影响：

| 偏好 | 取值 | 初值 |
| --- | --- | --- |
| 界面语言 | 简体中文、English | 登录后按本人已保存的偏好；没有保存过时，沿用当前浏览器中正在使用的语言；也没有时为 English，不读取浏览器语言 |
| 时区 | 有效的 IANA 时区（例如 Asia/Shanghai、UTC） | 首次成为本平台企业用户时，按浏览器时区写入；推断失败时为 UTC。此后不自动覆盖本人的选择 |

修改与保存（两项相同）：

- 改选即保存，不需要另做保存确认；保存进行中给出处理中反馈，该项完成前不能再次修改，不影响另一项已生效的偏好；选择与当前相同的值不重复保存。
- 保存成功后立即生效并提示已保存；刷新、重新进入、重新登录和换设备登录后都按最后一次保存成功的值。
- 保存失败时提示保存失败、请重新选择，选项和实际生效的值都恢复为保存前的值，可以重试。无效的时区不保存。
- 退出、登录到期或换地址后，不显示迟到的保存结果。
- 偏好变更不发送任何消息。偏好只影响展示，不是资料或认证的必填项，也不改变任何业务规则。

界面语言：

- 在任何页面都可以切换，未登录和游客也可以。切换后当前页面不刷新即完成全部文字替换，已填写的内容不丢失。
- 界面文字和站内消息的标题、正文都按所选语言展示；地址、金额、数量、时间、编号等业务值不变，网络名称始终写作 Ethereum。站内消息的展示规则见消息通知模块（M7）。
- 未登录和游客切换的语言保存在当前浏览器中，关闭浏览器再打开仍然生效，但不保存到任何账户；退出登录后，当前浏览器中的语言保留。
- 没有对应译文时显示英文，不显示内部标识。

时区：

- 面客端的时间（包括上游提供的时间）按本人所选时区换算展示，并标注时区。
- 时区只影响时间的展示：同一业务时间与事件的先后顺序不因时区改变，也不作为任何有效期、时限或限频的计算起点。

<a id="account"></a>
## 6. 企业账户

<a id="account-common"></a>
### 6.1 共同规则

依据：本期企业账户只保留当前登录地址一个；不提供其他企业数币账户的新增、编辑或删除【确认】。

名称【确认】：入口与页面名称为“企业账户”；页面中的账户信息名称为“数币账户”。

谁能使用：

| 身份 | 能看到企业账户入口吗 | 进入后能做什么 |
| --- | --- | --- |
| 未登录、游客 | 看不到 | 直接访问被拒绝，不返回任何账户数据 |
| 未认证的企业用户 | 看得到 | 看到本功能用途和“需先在资产可信平台完成认证”的引导，见[认证资格与受限引导（C-AUTH-04）](#C-AUTH-04)；看不到账户数据 |
| 已认证的企业用户 | 看得到 | 查看本企业当前登录地址 |

- 每个企业只有一个数币账户，取上游当前登录地址，网络固定为 Ethereum。
- 企业账户只读，不提供新增、编辑、删除、备注名、默认标记或“设为默认”操作；绕过界面的变更请求同样被拒绝。
- 登录地址按[钱包地址与网络名称的展示](#address-display)缩写，本人可核对完整地址并复制。
- 读取失败时说明暂时不可用并可重试，不能显示为空账户，也不能沿用上次成功读取的地址。
- 登录地址本期不允许变更【确认】，企业账户中的地址不会被替换。

数币账户的信息：

| 业务信息 | 含义与取值 | 可编辑性与异常结果 |
| --- | --- | --- |
| 账户标识 | 固定标明“登录地址” | 只读 |
| 区块链网络 | 固定为 Ethereum | 只读，没有其他网络可选 |
| 数币地址 | 上游当前登录地址 | 只读；格式或来源无法确认时不展示为有效账户，说明暂时无法获取并可重试 |

<a id="C-ACCOUNT-01"></a><a id="c-account-01"></a>
### 6.2 查看唯一企业账户（C-ACCOUNT-01）

适用角色与前提：已认证的企业用户。

- 企业账户中始终只有当前登录地址一条，展示“登录地址”、Ethereum 和数币地址；不展示账户备注名、来源、创建时间、更新时间或验证状态。
- 企业不能新增其他地址，也不能编辑或删除当前登录地址；页面不提供相应操作，绕过界面的请求同样被拒绝。

<a id="pending"></a>
## 9. 待确认事项与依赖

待确认事项：本模块没有业务待确认事项；登录签名的网络校验待研发验证，见[依赖](#signature-network)。

依赖：

- 资产可信平台用户匹配（D1）：按 Ethereum 地址返回账户、个人信息、企业信息、当前认证结论和稳定标识，结果来源可验证；上游登记钱包地址时须已验证登记人控制该地址。资产可信平台本期不允许变更登录地址，企业归属取得后不变化【确认】。调取失败时企业无法完成登录，见[按地址匹配上游身份（C-AUTH-02）](#C-AUTH-02)。上游登记地址的控制权验证方式、调取接口的时延与限流约定，在对接时核实。
- 钱包 SDK 服务商（D6）：提供钱包连接、地址识别与签名。具体钱包不在本册展开；签名校验、地址格式校验的实现由研发确定，验证由测试负责。
- <a id="signature-network"></a>登录签名的网络校验（待验证）：登录签名是消息签名，平台只能校验签名内容中声明的网络，能否在服务端确认签名所用网络为 Ethereum 取决于登录签名格式，由研发确认。确认前，绕过界面用其他网络签名不能登录这一结果不能判定已实现。
- Ethereum 网络（BR-17）：登录地址和数币账户都只支持 Ethereum。
- 平台联系邮箱：由开发直接配置，用于游客引导中的“联系平台管理人员”。
