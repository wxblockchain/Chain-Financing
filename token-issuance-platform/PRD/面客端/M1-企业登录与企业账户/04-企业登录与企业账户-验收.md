## 0. 验收前准备

账号与地址：

- 已认证企业地址 A：已在资产可信平台登记，调取到的账户有个人信息、企业信息，认证结论为已认证；测试人员控制其私钥。
- 已认证企业地址 B：与 A 属于不同企业。
- 未认证企业地址：有企业归属但认证审核中或未通过的地址各一个；有个人信息、没有企业归属的地址一个。
- 未登记地址：在资产可信平台没有登记的 Ethereum 地址。
- 上游账户已锁定或禁用的地址一个；在测试数据中对应两个上游账户的地址一个。
- 用于上游变化的企业一个：可在资产可信平台更改其登录地址、认证结论、锁定或禁用状态和资料。

数据与环境：

- 钱包环境：未安装钱包、钱包已锁定、钱包处于 Ethereum 以外网络三种情形；可延迟确认的钱包（如硬件钱包）。
- 地址格式样本：同一 Ethereum 地址的全小写、大小写混合、不带 0x 前缀三种写法。
- 上游资料样本：部分可选字段未提供的企业；可模拟资产可信平台不可用、超时、关键认证结论缺失，以及返回来源无法确认的结果。
- 可控制的服务端判定时间：用于核对签名 5 分钟、原目标 30 分钟和普通请求 60 秒的等号边界；客户端时间只作显示，不作为最终判定依据。
- 登录地址变更样本：可把同一稳定账户的登录地址从旧地址改为新地址，并可连续更换。
- 企业归属变化样本：同一稳定账户可从企业 A 变更为企业 B，也可移除有效企业归属；可模拟旧企业页面、在途操作、缓存和迟到响应。
- 一条发给某企业的消息链接，用于验证登录后返回原目标；平台联系邮箱已配置。
- 偏好样本：一个从未保存过语言偏好的企业用户；首次登录时浏览器时区为 Asia/Shanghai 的企业用户，以及浏览器时区无法推断的情形；可模拟偏好保存失败。

| <a id="AC-M1-06"></a>AC-M1-06 | 未登录 | 分别用地址 A 的全小写写法、大小写混合写法登录；在上游测试数据中以不带 0x 前缀的写法登记同一地址 | 都调取到同一账户，成为同一企业用户 |
| <a id="AC-M1-07"></a>AC-M1-07 | 未登录，使用未登记地址 | 签名登录 | 成为游客，看到游客引导；不按企业名称等信息近似匹配，也不提示该地址是否曾在上游登记过 |
| <a id="AC-M1-08"></a>AC-M1-08 | 未登录 | 用有个人信息、没有企业归属的地址登录 | 成为企业用户（未认证）；用户信息展示已有的个人信息；企业信息保留入口与空状态，说明企业信息需在资产可信平台完善；不能办理需要企业认证的业务，也不能查询或查看任何企业消息 |
| <a id="AC-M1-09"></a>AC-M1-09 | 未登录 | 分别：资产可信平台不可用或超时时登录；用对应两个上游账户的地址登录；用上游账户已锁定或禁用的地址登录；模拟建立企业用户失败 | 验签通过后都仍处于未登录的身份判定阶段。不可用或超时：本次登录不成立，说明暂时无法确认身份并可重试，不成为游客；两个账户：本次登录不成立，给中性说明，不展示任一账户资料；锁定或禁用：不建立登录，说明原因并显示能取得的解除信息；建号失败：给出错误码，可重试或退出。以上都不暴露内部判定原因 |
| <a id="AC-M1-32"></a>AC-M1-32 | 未登录 | 模拟客户端提交伪造的上游数据，或上游返回来源无法确认的结果 | 伪造数据不被采信；来源无法确认的结果不参与身份判定、不建立登录，并产生安全告警 |
| <a id="AC-M1-44"></a>AC-M1-44 | 企业用户已登录 | 在登录期间重新调取时，分别模拟客户端提交伪造数据和上游结果来源无法确认；再在关键业务动作提交前模拟相同异常 | 两类数据都不被采信；当前登录、身份与已确认资料保持不变，产生安全告警；来源异常不能触发锁定、禁用、地址变化、企业归属变化或认证变化；关键业务动作被拒绝并可稍后重试 |

## 4. 上游变化的同步

| 编号 | 前提 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| <a id="AC-M1-36"></a>AC-M1-36 | 用于上游变化的企业已登录，认证结论为已认证 | 在上游把认证改为未通过；距上次成功调取恰好 60 秒时发出普通请求，再在超过 60 秒后的下一次普通请求中查看结果；随后把认证改回已认证，并在超过 60 秒后的下一次普通请求中查看结果 | 恰好 60 秒的普通请求不触发复查，仍沿用最近一次已确认结果；超过 60 秒后的下一次请求重新调取，确认未通过后不结束登录、业务功能被拦下并显示认证引导；确认恢复认证后无需重新登录即恢复办理业务 |
| <a id="AC-M1-41"></a>AC-M1-41 | 用于上游变化的企业曾被本平台确认为已认证；另有一个从未被本平台确认为已认证的企业 | 在上游把前者认证改为未通过，超过 60 秒后请求；随后多次刷新、重新登录；模拟一次调取失败；恢复认证后再次改为未通过；再模拟用户退出后在离线期间失效并于下次登录调取；分别在中文和英文界面查看消息 | 每次被本平台实际确认并应用的“同一企业由已认证变为未认证”各产生一条分类为“认证与合规”的通知，离线变化只在下次登录调取确认后产生；标题与正文符合[认证失效通知（NT-C09）](./03-企业登录与企业账户-消息通知.md#NT-C09)，不含证件号码、联系方式或钱包地址；打开后进入本人的用户信息，不自动离开本平台；业务限制立即生效，不等消息送达；重复刷新、重新登录与持续未认证都不新增消息；调取失败不发；其他企业、监管机构和运营都收不到；从未确认过已认证的企业不会收到 |
| <a id="AC-M1-37"></a>AC-M1-37 | 用于上游变化的企业已登录 | 分别：在上游锁定或禁用该账户后、距上次调取未满 60 秒时触发一个要求提交前重新调取的动作；在上游更新企业名称后，超过 60 秒再查看企业信息；在动作提交前分别模拟调取失败、超时、上游不可用和关键认证结论缺失 | 锁定或禁用：本次重新调取一经确认即拒绝当前操作并结束登录，说明原因，不等待满 60 秒；资料更新：企业信息显示新名称；四类异常都保持当前登录和最近一次已确认的身份与资料，不把用户降为游客、不应用异常结果，当前动作不放行并可稍后重试 |
| <a id="AC-M1-30"></a>AC-M1-30 | 用于上游变化的企业已用旧地址登录，且已有本模块资料与偏好 | 在上游把登录地址改为新地址，超过 60 秒后在本平台发出请求；用新地址登录并查看用户信息、企业信息、偏好和企业账户；再用旧地址登录 | 发出请求时旧地址的登录被结束，说明资产可信平台登记的钱包地址已变更、请重新登录；新地址调取到相同稳定账户后成为同一企业用户，本模块资料与偏好接续；企业账户只展示新地址这一条，旧地址不作为其他账户保留；旧地址登录成为游客，不提示请使用新地址，也不能查看企业数据 |
| <a id="AC-M1-45"></a>AC-M1-45 | 稳定账户已登录且当前属于企业 A，已打开 A 的资料与受保护页面，并存在一个未完成操作 | 分别把有效企业归属由 A 改为 B、由 A 移除；触发下一次调取；再让旧企业响应迟到返回 | A→B：立即按 B 重新授权，只展示 B 的资料，A 的资料、企业消息和受保护内容不再可见，A 页面与未完成操作被拒绝，A 的缓存和迟到结果不显示；A→无归属：保留企业用户登录但成为无企业归属的未认证状态，只能查看本人的用户信息和企业空状态，不能查看任何企业消息或受保护业务；两种变化都不发送认证失效通知 |
| <a id="AC-M1-46"></a>AC-M1-46 | 已认证企业用户已登录，距上次成功调取未满 60 秒 | 分别在上游使认证失效、改变登录地址，然后立即触发一个要求提交前重新调取的动作 | 两次都必须重新调取，不能沿用未满 60 秒的旧结果；认证失效时立即阻断当前动作但保留登录并显示认证引导，登录地址变化时立即阻断当前动作并结束登录；60 秒不作为宽限期 |
