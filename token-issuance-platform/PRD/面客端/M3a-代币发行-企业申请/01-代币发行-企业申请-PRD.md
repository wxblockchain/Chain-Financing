# 代币发行 · 企业申请 · 功能与业务规则

2026-11-09｜面客端：企业用户｜需求评审稿

本模块共三册：本册写功能与业务规则；[流程图与状态机](./02-代币发行-企业申请-流程图与状态机.md)画出申请和企业可见进度；[验收](./04-代币发行-企业申请-验收.md)供测试使用。本模块自身不发送消息，所以没有 03 册，并非缺失。

功能与验收编号沿用原值；已删除的企业选择机构、监管协议和消息条目不再占号，缺号不代表遗漏。本册只定义业务行为；布局与交互承载由 Hallmark 决定。

## 1. 模块是什么

代币发行·企业申请供已认证企业以一笔可信资产申请铸造一枚代币。企业确定资产、选填发行申请文件，系统自动使用提交时的当前登录地址作为接收地址；企业核对完整资产价值、唯一到期时点和接收地址，用钱包对四项业务值签名后提交。企业不选择机构，也不参与机构分配；提交后进入运营处理，再查看运营驳回、发行处理或铸造结果。

基本原则：

- 企业只确定资产和选填申请文件，不选择机构、接收账户、发行数量、资产价值、到期日或合约。
- 一笔资产、一笔申请、一次业务签名和一枚成功代币一一对应；提交后不能撤回或修改，运营驳回后不能用同一资产重新申请。
- 申请提交成功后企业可见状态为“运营处理中”。企业进度统一为“企业提交 → 运营处理 → 铸造”；机构分配属于运营处理的内部环节，不单独成为企业进度或状态。
- 后续处理事实由代币发行 · 审核与铸造（M3b）提供，本模块只把事实映射为企业可见状态、当前进度和结果。
- 发行申请流程和申请详情不展示分配机构名单、机构材料、分配变化或内部重试；机构分配不改变企业已提交的申请内容，也不使企业进度前进或回退。
- 铸造成功后，各机构在发行处理中上传的材料由我的代币的[发行机构文件](../M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#institution-files)展示，企业可看到哪家机构上传了哪些材料；本模块不展示这些材料。
- 上游完整资产价值是申请、签名和记录的唯一金额值。普通列表和详情按可信资产（M2）的[两位小数截断展示](../../两端共用/M2-可信资产/01-可信资产-PRD.md#amount-display)；确认和签名使用完整值。
- 代币数量按完整资产价值 1:1 确定，单位取 M3b 铸造结果中合约的代币符号；申请阶段不展示预计发行数量或初始单位价值。
- 发行申请文件选填，每笔最多 10 份，每份最大 10 MB，仅支持 PDF、JPG、JPEG、PNG。提交后文件冻结，不能替换、删除或补传。
- 每笔申请提交前须用当前登录地址的钱包签名。签名内容为资产编号、完整资产价值、唯一到期时点和接收地址；本模块随申请保存签名记录。这四项业务值与企业业务签名值都随铸造上链，完整的上链字段以 M3b [上链字段](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#onchain-fields)为准。

**一个完整的例子。** 企业 A 从可信资产中价值 50,000.00 USD、到期日为 2027-03-31（到期时点为来源时区下当天 24:00）的资产发起申请。系统固定该资产，企业上传两份申请文件，系统自动带出当前登录地址作为接收地址。企业核对完整业务值并签名后提交，企业提交环节完成，申请进入“运营处理中”。运营在管理端分配或新增机构时，企业仍看到“运营处理中”；运营发起铸造、申请在 M3b 进入“铸造中”后，企业进入铸造环节并看到“发行处理中”；铸造成功后，企业看到代币编号、完整数量、初始单位价值、合约、到账地址和铸造时间；点击代币编号进入代币详情，可查看资产托管、法律服务、审计机构各自上传的材料。

### 1.1 需求清单

| 功能 | 谁 | 想做什么 | 为了什么 |
| --- | --- | --- | --- |
| [发起申请与确定资产（C-ISSUE-01）](#C-ISSUE-01) | 已认证企业用户 | 带入或选择一笔可发起资产 | 以可信资产申请发行 |
| [上传发行申请文件（C-ISSUE-08）](#C-ISSUE-08) | 已认证企业用户 | 选填与本次申请有关的文件 | 向后续处理人补充材料 |
| [确认并提交申请（C-ISSUE-04）](#C-ISSUE-04) | 已认证企业用户 | 核对业务值并签名提交 | 生成不可撤回的发行申请 |
| [发行申请列表（C-ISSUE-05）](#C-ISSUE-05) | 已认证企业用户 | 查看本企业全部申请 | 掌握处理进度 |
| [申请详情（C-ISSUE-06）](#C-ISSUE-06) | 已认证企业用户 | 查看申请、签名、驳回和铸造结果 | 了解申请结果及代币去向 |

### 1.2 本期不做

- 企业选择、查看或变更分配机构；机构由运营在管理端分配。
- 机构审核发行申请、企业与特定机构签署监管协议，以及企业查看监管协议。
- 在发行申请流程或申请详情中查看机构上传的材料；铸造成功后的查看由我的代币的[发行机构文件](../M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#institution-files)定义。企业上传的发行申请文件与机构材料是两类独立文件。
- 撤回、修改、重新提交发行申请，或驳回后用同一资产再次发起。
- 申请草稿、批量选择资产、批量提交和批量签名。
- 企业选择、手输或更换接收地址；固定使用提交时的当前登录地址。
- 企业自行填写或修改发行数量、币种、到期日、合约或初始单位价值。
- 企业端查看链上交易哈希。
- 非美元计价的应收账款发起申请。
- 代币铸造后的融资、销毁与解除资产托管；分别由我的代币与销毁申请（M4a）及销毁执行、解除资产托管与代币台账（M4b）定义。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 发行申请 | 企业以一笔可信资产申请铸造代币的记录，提交成功后产生唯一申请编号 |
| 可发起资产 | 本企业满足[发起条件](../../两端共用/M2-可信资产/01-可信资产-PRD.md#issue-conditions)的可信资产 |
| 接收地址 | 提交时自动记录的企业当前登录地址；记录后不再改写 |
| 业务签名 | 企业用提交时登录地址的钱包，对资产编号、完整资产价值、唯一到期时点和接收地址所做的签名 |
| 发行申请文件 | 企业提交申请时选填并冻结的补充文件；不是机构材料，不属于企业业务签名内容 |
| 分配机构 | M3b 在运营处理中维护的内部结果；企业端不展示该环节、名单或变化 |
| 运营处理中 | M3b 申请状态为待分配机构或运营处理中时的企业可见状态；包含首次分配和后续新增机构等内部情况 |
| 发行处理中 | M3b 申请状态为铸造中或铸造失败时的企业统一展示；内部失败和重试不对企业展开 |
| 到期时点 | 来源时区下应收账款到期日当天 24:00，是唯一的到期业务值，定义见可信资产的[到期时点](../../两端共用/M2-可信资产/01-可信资产-PRD.md#due-time)；代币到期日与之一致 |

## 3. 谁能使用

| 身份 | 能看到入口吗 | 能做什么 |
| --- | --- | --- |
| 未登录、游客 | 看不到 | 直接访问被拒绝，不返回申请数据 |
| 未认证企业用户 | 看得到 | 只看到认证引导，不能查看数据或发起申请 |
| 已认证企业用户 | 看得到 | 发起申请，查看本企业申请、签名、进度、驳回意见和铸造结果 |

- 申请归属企业，不归属某个登录地址。
- 企业只能访问本企业申请。访问其他企业或不存在的申请时，统一说明“无权查看或申请不存在”，不透露申请是否存在。
- 权限须在业务侧判定；绕过界面提交或读取同样被拒绝。

## 4. 发起与提交发行申请

从可信资产发起时：固定资产 → 选填申请文件并确认自动接收地址 → 核对、签名、提交。

从代币发行模块发起时：选择一笔资产 → 选填申请文件并确认自动接收地址 → 核对、签名、提交。

- 企业申请流程中不出现机构选择、机构读取失败或机构停用重选。
- 从代币发行模块返回资产选择但不改选时，已上传文件保留；改选资产后清空原文件，并说明须按新资产重新上传。
- 从可信资产发起时不能在申请内改选资产；退出后未提交内容不保存。

流程参见[发起并提交发行申请（图 1）](./02-代币发行-企业申请-流程图与状态机.md#fig-1)。

<a id="C-ISSUE-01"></a>
### 4.1 发起申请与确定资产（C-ISSUE-01）

适用角色与前提：已认证企业用户。

- 可选范围只包含本企业满足发起条件的资产；一笔申请只能确定一笔资产。
- 从可信资产发起时，进入前再次核对资产资格；满足条件则固定带入，不再展示选择资产环节。
- 从代币发行模块发起时不预选资产；选择另一笔即替换原选择。
- 每笔资产展示资产编号、债务人名称、资产价值与币种、到期日。普通页面金额按[两位小数截断展示](../../两端共用/M2-可信资产/01-可信资产-PRD.md#amount-display)。
- 资产编号可进入可信资产详情；返回申请时原选择和已填写内容保持。

| 情况 | 用户看到的结果 |
| --- | --- |
| 没有可发起资产 | 说明当前没有可发起资产，可前往可信资产查看原因，不能继续 |
| 带入资产已不满足条件 | 留在可信资产并说明具体原因，不进入申请填写 |
| 可发起资产读取失败 | 说明暂时无法获取并可重试，不显示为空状态 |

<a id="C-ISSUE-08"></a>
### 4.2 上传发行申请文件（C-ISSUE-08）

适用角色与前提：已确定资产，正在填写申请信息。

| 业务信息 | 含义 | 必填与默认 | 编辑与可见范围 | 校验与失败结果 |
| --- | --- | --- | --- | --- |
| 发行申请文件 | 企业随本次申请提交的补充文件 | 选填，0 至 10 份，无默认值 | 提交前企业可添加、移除；提交后本企业可查看下载、不能修改 | 仅支持 PDF、JPG、JPEG、PNG，每份最大 10 MB；空文件、超过上限或格式不符的文件不添加并说明原因 |

- 10 MB 按 10 × 1024 × 1024 字节计算；恰好 10 份或单份恰好 10 MB 可以提交。
- 文件格式须同时按扩展名和实际文件内容识别，二者须一致且属于允许格式；仅修改扩展名不能绕过校验。
- 只有上传成功的文件计入份数；同名文件可以并存。上传失败可重试或移除，其他成功文件保留。
- 存在上传中或失败未移除的文件时，不能进入确认或提交。
- 确认环节只读展示原文件名、格式、大小和总数；返回填写后可调整。
- 提交成功后记录原文件名、格式、大小和提交时间并冻结。取消、退出、登录结束或提交失败不产生正式文件记录；保存失败时保留本次已上传文件供重试。
- 申请提交后，本企业在申请任何状态均可查看、下载；单份文件读取失败时说明暂时无法获取并可重试，不影响查看申请的其他信息。
- 文件不属于企业业务签名内容，也不作为[铸造上链字段](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#onchain-fields)；系统冻结文件并记录原文件名、格式、大小、提交时间和访问审计信息。运营与机构的文件访问范围由 M3b 定义，不在本模块规定。

<a id="C-ISSUE-04"></a>
### 4.3 确认并提交申请（C-ISSUE-04）

适用角色与前提：已确定资产；已添加文件全部上传成功，或失败项已移除。

确认环节全部只读：

| 业务信息 | 取值 | 展示要求 |
| --- | --- | --- |
| 资产 | 资产编号、债务人名称、完整资产价值与币种 | 展示完整值，不使用两位截断值 |
| 到期时点 | 资产的唯一[到期时点](../../两端共用/M2-可信资产/01-可信资产-PRD.md#due-time) | 按本人时区换算后同时展示日期、时间和时区，可核对上游原始到期日与来源时区 |
| 接收地址 | 当前登录地址，网络为 Ethereum | 自动带出，地址可核对完整值；不能选择、手输或更换 |
| 发行申请文件 | 待提交文件的原文件名、格式、大小和总数 | 未上传时明确展示；可返回修改 |

确认环节须说明：代币数量按完整资产价值 1:1 确定；提交后不能撤回或修改；运营驳回后申请终止；成功代币进入提交时接收地址；提交前须签名；申请文件不属于企业业务签名内容。确认环节不展示机构名称、分配机构名单或机构协议要求。

<a id="signing"></a>
提交时的业务签名：

- 企业点击提交后，先用当前登录地址的钱包对资产编号、完整资产价值、唯一到期时点和接收地址签名；核对通过后才提交。
- 所签到期时点是可信资产定义的[到期时点](../../两端共用/M2-可信资产/01-可信资产-PRD.md#due-time)这一业务值，不是按本人时区换算后的日期；切换时区不改变所签内容。
- 一笔申请签一次。钱包地址不是登录地址或网络不是 Ethereum 时不能提交。
- 签名不含机构、币种、签名时间、申请文件或运营后置确定的初始单位价值。
- 签名记录保存签名地址、签名时间、签名值和所签内容（资产编号、完整资产价值、唯一到期时点和接收地址四项业务字段）；企业可在任何申请状态查看上述签名记录，记录不可修改。
- 取消、拒绝、离开、登录结束、签名字段变化或提交不成功后，签名失效；再次提交须重新签名。
- 一份签名只对应本次申请提交，不能用于另一笔申请或另一次提交。
- 重复点击、刷新或网络重发只承接同一提交结果，不能生成第二笔申请。

提交时再次核对：认证结论、资产发起条件、当前登录地址与签名地址、文件规则。机构尚未分配不阻断企业提交；企业提交后由运营分配。

提交成功后：

- 生成唯一申请编号，企业提交环节完成，企业可见状态为“运营处理中”。
- 记录企业名称、资产与完整价值、到期时点、接收地址、发行申请文件、申请编号、提交时间和业务签名；不记录企业所选机构，因为企业没有机构选择。
- 资产发行状态变为“发行申请中”，不能再次发起。
- 企业看到申请编号并可进入详情；本模块不因提交发送消息。运营收到的[新发行申请待分配机构（NT-A07）](../../管理端/M3b-代币发行-审核与铸造/03-代币发行-审核与铸造-消息通知.md#NT-A07)由 M3b 发送。
- 下一笔申请重新确定资产；接收地址继续自动使用下一次提交时的当前登录地址。

<a id="submit-errors"></a>
提交不成功时不产生申请，资产发行状态不因本次失败改变，未受影响内容保留：

| 情况 | 用户看到的结果 |
| --- | --- |
| 认证已失效 | 不能提交，进入认证引导 |
| 上游不可用，无法确认认证或资产 | 说明暂时无法确认，可稍后重试 |
| 资产已不满足发起条件或已有申请 | 说明具体原因；已有申请时可进入该申请 |
| 文件不符合规则、上传中或失败未移除 | 不能提交或不添加该文件，其他成功文件保留 |
| 登录结束或钱包切换到其他地址 | 本次提交不成立；结束旧登录并要求重新登录 |
| 签名取消、地址或网络不对、签名无效或已失效 | 不提交，说明原因并要求重新签名 |
| 保存失败 | 说明未提交成功，可用已上传文件重试 |

<a id="view"></a>
## 5. 查看发行申请

<a id="status"></a>
### 5.1 企业可见状态与进度

本模块展示企业能理解的三个发行环节：企业提交 → 运营处理 → 铸造。机构分配属于运营处理的内部环节，不单独成为企业进度或状态。管理端操作条件和真实的[申请状态](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#status)由 M3b 定义，本模块不重复定义。

| M3b 申请状态 | 企业可见状态与进度 | 驳回意见 | 铸造结果 |
| --- | --- | --- | --- |
| 待分配机构、运营处理中（包含首次分配和后续新增机构） | 运营处理中；企业提交已完成，运营处理进行中 | 不展示 | 不展示 |
| 运营驳回 | 运营驳回；企业提交已完成，运营处理显示驳回结果，铸造未开始；申请终止 | 展示意见原文 | 不展示 |
| 铸造中、铸造失败（含失败后等待重试和重试中） | 发行处理中；企业提交和运营处理已完成，铸造进行中；企业无需操作 | 不展示 | 不展示 |
| 铸造成功 | 铸造成功；三个环节均已完成，代币已进入申请接收地址 | 不展示 | 展示[铸造结果](#mint-result) |

- 首次分配或后续新增机构时，企业始终显示“运营处理中”，发行进度不前进也不回退。
- 运营驳回和铸造成功是企业侧终态。铸造失败及重试过程始终显示“发行处理中”。
- 铸造长时间没有明确结果，或铸造失败后无法通过重试解决、由平台线下处理时，企业继续看到“发行处理中”，没有企业侧操作；M3b 按[铸造结果（A-ISSUE-06）](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#A-ISSUE-06)收口为铸造成功后，企业才看到“铸造成功”。
- 分配机构名称、数量、类型及变更历史不在企业端展示。

<a id="C-ISSUE-05"></a>
### 5.2 发行申请列表（C-ISSUE-05）

- 列出本企业全部申请，包括处理中、驳回和成功申请。
- 默认按提交时间由新到旧排列【确认】；分页、返回位置、空状态与读取失败按可信资产（M2）的[业务列表通用规则](../../两端共用/M2-可信资产/01-可信资产-PRD.md#list-common)。
- 每笔展示申请编号、资产编号、资产价值与币种、提交时间和企业可见状态；不展示分配机构或预计发行数量。
- 资产价值按[两位小数截断展示](../../两端共用/M2-可信资产/01-可信资产-PRD.md#amount-display)。
- 每笔均可进入详情；无申请时说明尚无发行申请并提供发起入口；读取失败时说明暂时无法获取并可重试，不显示为空状态。

<a id="C-ISSUE-06"></a>
### 5.3 申请详情（C-ISSUE-06）

申请详情展示：申请编号、提交时间、资产编号、债务人名称、资产价值与币种、到期时点、接收地址及 Ethereum、发行申请文件、业务签名、三阶段发行进度、运营驳回意见和铸造结果。详情不展示分配机构名单、机构材料、监管协议或机构审核意见；铸造成功后，企业通过铸造结果中的代币编号进入代币详情查看机构材料。

- 资产价值普通展示按[两位小数截断展示](../../两端共用/M2-可信资产/01-可信资产-PRD.md#amount-display)；到期时点按本人时区换算后同时展示日期、时间和时区，不改变业务值，见[到期时点](../../两端共用/M2-可信资产/01-可信资产-PRD.md#due-time)。
- 发行申请文件在任何状态均可查看下载；企业不能修改。读取权限和失败处理按[上传发行申请文件（C-ISSUE-08）](#C-ISSUE-08)。
- 业务签名在任何状态展示签名地址、签名时间、签名值和所签内容（资产编号、完整资产价值、唯一到期时点和接收地址）；地址和值均可核对完整内容。签名读取失败时说明暂时无法获取并可重试，不影响查看其他申请信息。企业端不展示链上交易哈希。
- 发行进度依次展示企业提交、运营处理、铸造。已完成环节展示结果，当前环节展示处理中或驳回结果，未到达环节展示未开始。
- 企业端不展示独立的操作记录、处理人员、各环节完成时间或历史轨迹，只展示当前发行进度及当前状态。运营驳回时间、意见原文和铸造时间作为当前业务结果字段保留，不形成操作记录。
- 运营驳回时展示驳回时间和意见原文；意见不随界面语言翻译。
- 资产在提交后逾期或结清，不自动终止既有申请；企业继续查看最新进度。资产价值和到期日在确权后不再变化，见[资产进入本平台与信息结构（F-AS-01）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-01)。
- 申请详情读取失败时说明暂时无法获取并可重试，不显示不完整详情或误报申请不存在。

<a id="mint-result"></a>
铸造成功时展示：

| 业务信息 | 含义 |
| --- | --- |
| 代币编号 | 平台内唯一，可进入我的代币中的代币详情 |
| 代币数量 | 完整值，等于申请完整资产价值，单位为合约代币符号 |
| 铸造初始单位价值 | 运营确认并随铸造写入链上的值 |
| 铸造初始资产估值 | 完整代币数量 × 初始单位价值，单位 USD，不改写申请资产价值；按[两位小数截断展示](../../两端共用/M2-可信资产/01-可信资产-PRD.md#amount-display)展示 |
| 到期日 | 与申请记录的唯一到期时点一致，按本人时区同时展示日期、时间和时区 |
| 接收地址 | 申请提交时记录的登录地址，可核对完整值 |
| 合约 | 合约名称、ERC-3525、Ethereum 和合约地址 |
| 铸造时间 | 铸造成功时点 |

## 6. 数据来源与归属

| 数据 | 来源 | 本模块能否修改 | 企业可见性 |
| --- | --- | --- | --- |
| 可信资产与发起条件 | 上游平台、可信资产（M2） | 不能 | 可见本企业数据 |
| 当前登录地址 | 企业登录与企业账户（M1） | 不能；提交时记录为接收地址 | 可见 |
| 发行申请与申请文件 | 本模块提交时记录 | 提交后不能修改 | 可见本企业申请 |
| 业务签名记录 | 本模块提交时记录 | 不能修改 | 可见 |
| 企业可见处理事实、驳回意见与铸造结果 | 代币发行 · 审核与铸造（M3b） | 本模块不能修改 | 按状态映射后可见 |
| 机构材料 | 代币发行 · 审核与铸造（M3b） | 不能 | 本模块不展示；铸造成功后在我的代币的发行机构文件中可见，访问范围按 M3b [申请与文件访问范围](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#file-access) |

## 7. 与相邻模块的分工

| 相邻模块 | 与本模块的关系 |
| --- | --- |
| 企业登录与企业账户（M1） | 提供认证判断和当前登录地址；本模块自动记录为接收地址 |
| 可信资产（M2） | 定义资产、发起条件、到期时点和资产发行状态；可带入目标资产发起 |
| 代币发行 · 审核与铸造（M3b） | 定义管理端处理条件和真实申请状态，向本模块提供申请状态、驳回和铸造结果；定义铸造上链字段；发送新发行申请待分配机构等运营消息；机构分配不单独映射为企业进度 |
| 我的代币与销毁申请（M4a） | 承接铸造成功代币的详情、发行机构文件和后续业务 |

## 8. 依赖

本模块没有待确认或待同步事项。

依赖：M1 提供企业身份、认证结论和当前登录地址；M2 与上游提供资产、发起资格、到期时点和资产发行状态，上游已确认资产确权后资产价值、到期日不再变化，所签业务值与资产信息一致；M3b 提供申请状态、驳回和铸造结果；M4a 承接铸造成功后的代币详情与发行机构文件。文件存储须保证申请归属、提交后不可修改及访问审计，具体实现与验证归研发、测试。
