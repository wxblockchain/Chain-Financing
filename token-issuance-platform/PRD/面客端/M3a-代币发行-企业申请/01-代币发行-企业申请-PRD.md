## 1. 模块是什么

代币发行·企业申请是面客端企业用户以可信资产申请发行（铸造）代币的地方。已认证的企业用户选一笔满足条件的应收账款和一家监管机构，可选上传发行申请文件，系统自动采用提交时的当前登录地址作为接收地址；企业核对只读的完整资产价值、唯一到期时点和接收地址，用钱包对资产编号、完整资产价值、唯一到期时点和接收地址签名后提交，产生一笔发行申请。提交后在这里跟踪监管一审、运营二审和铸造进度，查看申请文件、驳回意见、铸造结果，以及监管一审通过后的监管协议。审核与铸造本身由代币发行·审核与铸造（M3b）在管理端完成，本模块只负责企业一侧的申请与查看。

基本原则：

- 企业只需选择资产和监管机构，并可选上传发行申请文件；不填写发行数量、资产价值或到期日，也不选择接收账户。完整资产价值、唯一到期时点由系统按资产带出，接收地址取提交时的当前登录地址，企业不能修改【确认】。
- 一笔申请只用一笔资产并选择一家监管机构；需要发行多笔资产时，逐笔申请。一笔资产、一笔申请、一次签名、一枚代币一一对应。
- 一笔资产只能有一笔发行申请；每笔申请提交后不能撤回、不能修改；监管驳回或运营驳回后这笔申请终止，这笔资产不能再次发起，本企业的其他申请不受影响（BR-08、BR-12）【确认】。
- 申请时不展示预计发行数量或代币单位价值：代币数量的单位是铸造所用合约的代币符号，合约和初始单位价值都在运营二审时确定，所以申请、列表、详情和申请消息中只展示资产价值（含币种 USD）【确认】。铸造成功后展示代币数量和铸造初始单位价值；数量按资产价值 1:1 确定（BR-19），不因单位价值改变，单位为所用合约的代币符号，不以 USD 为单位【确认】。
- 上游完整资产价值是申请、签名、记录和铸造的唯一金额值。普通选择、列表和详情的主显示可以直接截断至两位小数，但须标明已截断并可核对完整值；确认提交、钱包签名和铸造结果使用完整值，任何业务计算都不使用截断值【确认】。
- 发行申请文件选填，每笔申请最多 10 份，每份最大 10 MB；按平台已有两类上传业务的统一口径，“最大 10M”解释为单份上限，不是全部文件合计上限。文件随申请提交后不可替换、删除或补传，企业、所选监管机构和运营可以查看、下载。
- 每笔申请提交前，企业须用钱包对这笔申请的业务信息签名；签名用于确认业务信息，不用于验证地址归属【确认】。签名的四项业务值和签名值随这笔申请的铸造写入链上；运营后置确定的初始单位价值单独上链，不属于企业签名内容；被驳回的申请及其签名不上链【确认】，见[上链字段](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#onchain-fields)。
- 申请状态只引用简报第 5 节，由管理端的审核与铸造结果推动；本模块不另行定义状态。资产的发行状态以[发行状态](../../两端共用/M2-可信资产/01-可信资产-PRD.md#issue-status)为准。
- 申请字段、审核结果与意见、监管协议、铸造结果共用 M3b 维护的[两端衔接字段清单](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff)；本册规定企业侧的选用、可见时点与展示结果。
- 企业看到的铸造阶段统一为“发行处理中”【确认】，按[关联发行申请的铸造阶段展示](../../两端共用/M2-可信资产/01-可信资产-PRD.md#minting-display)执行；申请真实状态与运营处理规则不变。
- 监管协议由企业与监管机构在线下签署，平台不提供签署；监管机构在一审通过时上传，企业此后可以查看和下载（BR-10、BR-18）【确认】。

**一个完整的例子。** 企业 A 的已认证企业用户在可信资产中看到一笔完整资产价值 50,000.00 USD、到期日 2027-03-31（带来源时区）的应收账款，状态为“可发行”，从这笔资产发起发行申请。系统带入并固定这笔资产，跳过选择资产，直接进入填写申请信息。用户选择监管机构 C，上传两份发行申请文件，不需要选择接收账户。确认环节只读展示完整资产价值 50,000.00 USD、按本人时区展示并标明时区的唯一到期时点、两份文件清单，以及自动带出的当前登录地址作为接收地址，并注明代币数量以铸造结果为准、提交后不能撤回或修改、驳回即终止、需与监管机构 C 线下签署监管协议。用户点击提交，用登录地址在钱包中对资产编号、完整资产价值、唯一到期时点和接收地址签名，提交成功，申请状态为“待监管审核”，资产发行状态变为“发行申请中”，监管机构 C 收到一条待审消息并可查看两份申请文件。A 与 C 线下签署协议后，C 一审通过并上传协议。运营二审选择合约，填写初始单位价值“1 COU = 0.8 USD”，平台仍按资产价值铸造 50,000.00 COU，并把初始单位价值与申请记录的接收地址、完整代币数量、唯一到期时点、资产编号和签名值一并写入链上；初始单位价值由运营在企业签名之后确定，不属于企业签名内容。铸造成功后，A 在申请详情中看到代币编号、完整代币数量、铸造初始单位价值、铸造初始资产估值、铸造到账地址、合约和唯一到期时点；A 点击代币编号进入我的代币中这枚代币的代币详情，再返回申请详情留存申请文件和协议。

### 1.2 本期不做

- 撤回、修改、重新提交发行申请，以及驳回后用同一笔资产再次发起（BR-12）【确认】。
- 申请草稿：未提交就离开时不保存任何内容。
- 批量选择资产、批量提交或批量签名：一笔申请只用一笔资产，多笔资产逐笔申请，见[选择资产为单笔的理由](#single-asset)。
- 企业端查看链上交易哈希：签名值随铸造交易写入链上，铸造交易哈希不在企业可见范围，见 M3b [铸造结果](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-mint)。管理端只有运营可查看签名地址、签名时间和签名值，监管机构不可见，见 M3b [业务签名记录](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-signature)。
- 企业自行填写或修改发行数量、币种、到期日、合约（BR-13、BR-19）【确认】。
- 非美元计价的应收账款发起申请（Q25）【建议·已采纳】。
- 在本平台签署监管协议，或由企业上传监管协议：协议线下签署，由监管机构上传（BR-10）【确认】。企业上传的是发行申请文件，不作为监管协议。
- 选择、手输或更换接收地址：本期固定使用提交时的当前登录地址。
- 监管一审、运营二审、选择合约、铸造与重试：属于代币发行·审核与铸造（M3b）。
- 代币铸造后的融资、销毁与解除监管：属于我的代币与销毁申请（M4a）及销毁审核、解除监管与代币台账（M4b）。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 发行申请 | 企业以一笔可信资产申请铸造代币的记录，从提交成功起产生，有唯一的申请编号；一笔资产对应一笔申请 |
| 可发起的资产 | 本企业满足[发起条件](../../两端共用/M2-可信资产/01-可信资产-PRD.md#issue-conditions)的可信资产 |
| 资产价值 | 可信资产列表对应收账款金额的称呼，取值就是应收账款金额与币种，不做折算、估值或扣减已回款，按[可信资产的术语](../../两端共用/M2-可信资产/01-可信资产-PRD.md#2-术语)；本模块列出、确认和展示资产时统一称资产价值 |
| 接收地址 | 申请提交时自动记录的企业当前登录地址；铸造时代币进入这个地址，即铸造到账地址。之后登录地址变化不改写该记录；代币之后所在的地址以我的代币中的[持有信息](../M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#holding-info)为准（例如融资质押期间在质押地址） |
| 代币编号 | 铸造成功时产生，平台内唯一定位一枚成功代币，按[代币及关联事实](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-token)；企业点击代币编号进入我的代币中这枚代币的[代币详情（C-TOKEN-02）](../M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#C-TOKEN-02) |
| 代币符号 | 合约对应的代币符号，作为铸造结果中代币数量的单位【确认】；按[合约的代币符号](../../管理端/M6-合约管理/01-合约管理-PRD.md#symbol)。合约在运营二审时才选定，所以申请阶段不展示代币数量 |
| 业务签名 | 企业提交前用钱包对这笔申请的资产编号、完整资产价值、唯一到期时点和接收地址所做的签名，表示企业认可这些业务信息；一笔申请签一次；签名值随铸造写入链上，见[提交时的业务签名](#signing) |
| 发行申请文件 | 企业在填写申请信息时选填、随发行申请一并提交的补充文件；不是监管协议，不纳入当前已确认的业务签名和上链字段 |
| 监管协议 | 企业与所选监管机构线下签署、由监管机构在一审通过时上传的协议文件 |
| 处理中的发行申请 | 申请状态为待监管审核、待运营审核、铸造中或铸造失败的申请 |
| 发行处理中 | 企业侧对真实状态“铸造中”“铸造失败”的统一展示名称，不是新增业务状态；两种状态下企业都无需操作 |
| 终止的发行申请 | 申请状态为监管驳回或运营驳回的申请 |

## 3. 谁能使用

依据：只有已认证的企业用户能办理业务【确认】；游客不能使用业务功能【建议·已采纳】。

| 身份 | 能看到代币发行入口吗 | 进入后能做什么 |
| --- | --- | --- |
| 未登录、游客 | 看不到 | 直接访问被拒绝，不返回任何申请数据；游客按[游客引导与功能限制（C-GUEST-01）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-GUEST-01)处理 |
| 未认证的企业用户 | 看得到 | 看到“需先在资产可信平台完成认证”的引导，看不到任何申请数据，不能发起申请，按[认证资格与受限引导（C-AUTH-04）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-04)处理 |
| 已认证的企业用户 | 看得到 | 发起申请；查看本企业全部发行申请及其进度、结果和监管协议 |

- 发行申请归属企业，不归属某个登录地址；上游登录地址变更后，用新地址登录仍看到原有全部申请【确认】。
- 企业只能查看本企业的发行申请。访问其他企业的申请或不存在的申请（包括通过直接链接访问）时，不返回任何内容，统一说明“无权查看或申请不存在”，不区分申请是否存在。
- 拒绝由平台判定，不能只靠隐藏入口；绕过界面提交申请同样被拒绝。

<a id="entry"></a>
### 3.1 入口

- 面客端设“代币发行”业务入口，与可信资产、我的代币、销毁申请并列；进入后是本企业的[发行申请列表（C-ISSUE-05）](#C-ISSUE-05)，可以从这里发起新申请。入口的名称、分组与位置以已确认的面客端组件规范为准，由设计维护。
- 从可信资产中满足条件的资产也可以直接发起：系统带入并固定该资产，跳过选择资产，直接进入填写申请信息，见[从可信资产发起发行申请（F-AS-04）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-04)；可信资产详情中的关联申请可以进入该申请的[申请详情（C-ISSUE-06）](#C-ISSUE-06)。
- 发给企业的发行相关消息（由 M3b 发送）打开后进入该笔申请的申请详情，按当前身份与权限重新判断，见[前往原业务（MSG-05）](../../两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-05)。

## 4. 发起与提交发行申请

从可信资产发起时，申请分两步：

1. 填写申请信息：资产已带入并固定；选择一家监管机构，可选上传发行申请文件，接收地址由系统自动取提交时的当前登录地址，见[选择监管机构（C-ISSUE-02）](#C-ISSUE-02)、[上传发行申请文件（C-ISSUE-08）](#C-ISSUE-08)。
2. 确认并提交：核对后签名提交，见[确认并提交申请（C-ISSUE-04）](#C-ISSUE-04)。

从代币发行模块发起时，申请分三步：

1. 选择资产：选一笔，见[发起申请与确定资产（C-ISSUE-01）](#C-ISSUE-01)。
2. 填写申请信息：规则与可信资产入口相同。
3. 确认并提交：规则与可信资产入口相同。

- 选定监管机构后才能进入确认；企业不选择、填写或更换接收地址。
- 确认单独成一步：提交后不能撤回，签名内容取自确认的内容，确认内容不与选择混在一起。
- 从代币发行模块发起时，提交前可以返回选择资产；返回查看但不改选时，已填写的信息保留。改选资产后，监管机构保留，接收地址仍由系统自动取当前登录地址，原申请文件清空并说明须按新资产重新上传，避免把前一笔资产的材料误交到新申请。
- 从可信资产发起时不提供改选资产；从填写申请信息返回原资产列表或详情，未提交内容不保存。提交前不产生发行申请，资产保持“可发行”。

流程参见：[发起并提交发行申请（图 1）](./02-代币发行-企业申请-流程图与状态机.md#fig-1)。

<a id="C-ISSUE-01"></a>
### 4.1 发起申请与确定资产（C-ISSUE-01）

适用角色与前提：已认证的企业用户。

依据：选资产为申请的第一步【确认】；可发起的条件以可信资产模块为准【确认】；一笔申请只选一笔资产【确认】，见[选择资产为单笔的理由](#single-asset)。

<a id="single-asset"></a>
选择资产为单笔的理由：

- 发行申请、监管审核、监管协议、驳回、铸造和代币都按单笔资产计；一笔资产只对应一笔申请、一次签名和一枚代币。
- 签名只覆盖这一笔申请。申请被驳回时，签名随这笔申请保留，不上链，不涉及其他申请；签名值随这笔申请的铸造写入链上，只含所铸代币对应的上链字段，不会混入未通过申请的数据。
- 批量签名会让一份签名覆盖多笔申请，部分申请被驳回后，签名中仍含未铸造申请的信息；逐笔签名虽能保留批量选择，但要连续多次钱包签名，操作并不比逐笔申请少。

- 可选范围只包括本企业满足[发起条件](../../两端共用/M2-可信资产/01-可信资产-PRD.md#issue-conditions)的资产；不满足条件的资产不出现在可选范围中，原因在可信资产中查看。
- 只能单选：选中另一笔即替换原选择；选定一笔才能进入下一步。
- 从可信资产某笔资产发起时，进入前再次核对该资产仍可发起；满足条件则带入并固定这笔资产，跳过选择资产，直接进入填写申请信息。企业不能在本次流程改选资产；需要申请另一笔资产时，返回可信资产并从目标资产重新发起。
- 从代币发行发起时，不预选任何资产。
- 每笔可选资产展示：资产编号、债务人名称、资产价值（应收账款金额与币种）、到期日。资产价值主显示直接截断至两位小数，标明已截断并可核对上游完整值；到期日按[语言与时区](../../两端共用/M2-可信资产/01-可信资产-PRD.md#locale)换算展示。
- 资产编号可以进入这笔资产在可信资产中的详情，详情内容以[企业查看本企业可信资产（F-AS-03）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-03)为准。查看详情不中断本次申请：回到申请时，已选的资产和监管机构都保留。

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 本企业没有可发起的资产 | 说明当前没有可发起申请的资产，资产须由上游平台确权同步、并满足发起条件；可以前往可信资产查看各资产不能发起的原因；不能进入下一步 |
| 从可信资产带入的资产在进入申请时已不满足发起条件 | 不进入填写申请信息，仍在可信资产中说明该资产当前不能发起申请及原因（原因口径以[从可信资产发起发行申请（F-AS-04）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-04)为准）；可以返回可信资产列表选择其他资产重新发起 |
| 可发起的资产读取失败 | 说明暂时无法获取可发起的资产，可以重试；不说成“没有可发起的资产” |

<a id="C-ISSUE-02"></a>
### 4.2 选择监管机构（C-ISSUE-02）

适用角色与前提：已认证的企业用户，已选定资产。

依据：企业只需选择监管机构（BR-13）【确认】；可选范围以监管机构管理模块为准【确认】。

- 可选范围按[企业可选的监管机构](../../管理端/M5-监管机构管理/01-监管机构管理-PRD.md#selectable)：机构状态为启用的全部监管机构。
- 每家可选机构只展示机构名称；企业看不到登录邮箱、账号状态和其他信息。
- 只能单选【确认】：不预选任何机构，企业须明确选择一家；改选另一家即替换原选择。
- 所选机构负责这笔申请的一审，并与企业线下签署监管协议（BR-03、BR-10）【确认】；选择处须说明这一点。
| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 当前没有启用的监管机构 | 说明暂无可选择的监管机构，请联系平台管理人员；不能进入确认 |
| 监管机构读取失败 | 说明暂时无法获取监管机构，可以重试 |

<a id="C-ISSUE-08"></a>
### 4.4 上传发行申请文件（C-ISSUE-08）

适用角色与前提：已认证的企业用户，已确定资产，正在填写申请信息。

依据：填写申请信息增加文件上传入口，每笔申请最多十份、最大 10M【确认】。平台现有监管协议与监管机构牌照附件都把 10 MB 定义为“每份文件”的上限，因此本功能沿用单份上限，不按全部文件合计大小限制；10 MB 按 10 × 1024 × 1024 字节计算。

| 业务信息 | 含义/类型 | 必填条件/默认值 | 可见/可编辑范围 | 校验与缺失/失败结果 |
| --- | --- | --- | --- | --- |
| 发行申请文件 | 企业随本次发行申请提交的补充文件，可多份；不是监管协议 | 选填，0 至 10 份；无默认值 | 提交前企业可添加、移除；提交后企业、所选监管机构、运营可查看和下载，任何角色都不能替换、删除或补传 | 每份最大 10 MB；恰好 10 份、单份恰好 10 MB 可以提交；超过任一上限的文件不添加并说明原因；空文件不添加；格式范围按 Q-M3A-01 裁定 |

- 只有上传成功的文件计入份数；同名文件可以并存，各自算一份。总数已达 10 份时不能继续添加，移除后可以再添加。
- 上传期间展示每份文件的进度和结果；单份失败可以重试或移除，其他已成功文件保留。仍有上传中或上传失败未移除的文件时，不能进入确认或提交。
- 进入确认前可以添加、移除；确认环节只读展示待提交的文件名称、格式、大小和总数，返回填写申请信息后可以修改。
- 提交成功才把上传成功的文件正式归入这笔申请，并记录上传时原文件名、格式、大小和申请提交时间；文件随申请不可修改。取消、离开、登录结束或未提交成功时，不产生发行申请文件记录；保存失败时保留本次已成功上传的文件，供企业重试本次提交。
- 申请提交后，企业、所选监管机构和运营均可从申请详情单独查看、下载每份文件；其他企业、其他监管机构和未登录访问者即使取得文件地址也不能读取。读取失败时说明本次未能打开，可以重试，不影响申请其他信息。
- 申请文件当前不属于已确认的业务签名和上链四字段，不改变[提交时的业务签名](#signing)；是否需要把文件内容摘要纳入签名或上链按 Q-M3A-02 裁定。

流程参见：[发起并提交发行申请（图 1）](./02-代币发行-企业申请-流程图与状态机.md#fig-1)。

<a id="C-ISSUE-04"></a>
### 4.5 确认并提交申请（C-ISSUE-04）

适用角色与前提：已认证的企业用户，已选定资产和监管机构；已添加的发行申请文件均上传成功，或失败项已移除。

依据：申请时不展示预计发行数量，展示资产价值【确认】；代币数量按资产价值 1:1 确定（BR-19）【确认】；到期日取应收账款到期日（BR-13）【确认】；提交后不允许撤回（BR-12）【确认】。

确认环节展示以下信息，全部只读，企业不能修改：

| 业务信息 | 含义与取值 | 展示要求 |
| --- | --- | --- |
| 资产 | 资产编号、债务人名称、完整资产价值（应收账款完整金额与币种，例如 12,345.675 USD） | 只读；本环节展示完整资产价值，不使用普通页面的两位截断主显示；资产编号可以进入可信资产详情，规则同[发起申请与确定资产（C-ISSUE-01）](#C-ISSUE-01) |
| 到期日 | 取应收账款唯一的到期时点，企业不填写 | 按本人时区展示并标明时区，同时能够核对上游来源时区；切换时区不改变申请、签名和上链使用的到期时点 |
| 监管机构 | 所选机构的机构名称 | 只读，可返回改选 |
| 接收地址 | 当前登录地址，区块链网络为 Ethereum | 自动带出；地址缩写展示，可核对完整地址；只读，不能选择、手输或更换 |
| 发行申请文件 | 本次待提交文件的原文件名、格式、大小和总数；未上传时说明未上传 | 只读，可返回填写申请信息后添加或移除；提交后不可修改 |

确认环节须同时说明以下内容，企业看到后才能提交：

- 代币数量按完整资产价值 1:1 确定，保留完整小数精度，单位为运营二审所选合约的代币符号；代币数量和到期时点以铸造结果为准。
- 提交后不能撤回或修改；监管机构或平台运营任一级驳回后，申请终止，这笔资产不能再次发起申请。
- 铸造成功的代币进入申请提交时记录的接收地址。
- 提交后需与所选监管机构在线下签署监管协议，监管机构审核通过时上传协议。
- 提交前须用钱包对其中的资产编号、完整资产价值、唯一到期时点和接收地址签名，签名值随铸造写入链上。
- 发行申请文件随申请一并提交，但当前不属于业务签名与上链字段；提交后不能替换、删除或补传。

<a id="signing"></a>
提交时的业务签名：

依据：签名的目的是对本次提交的业务信息签名，不是验证地址是否仍属于企业【确认】；企业业务签名值及其四项签名内容对应字段随铸造上链，运营二审后确定的初始代币单位价值不属于企业签名内容，上链字段见 M3b [上链字段](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#onchain-fields)。

- 企业点击提交后，先在钱包中对这笔申请的业务信息签名；签名成功后平台才进行下方的再次核对并提交。不签名不能提交。
- 一笔申请签一次，签名只对应这一笔申请。
- 签名地址为本次登录的登录地址【确认】。钱包当前地址不是登录地址时，提示在钱包中切换到登录地址后再签名；不接受其他地址的签名。签名不改变登录地址和身份。
- 企业签名内容为资产编号、完整资产价值（数值即完整代币数量）、到期时点、接收地址四项；这四项均随铸造写入链上，任何人只凭链上相应字段即可验证签名。运营在企业签名之后确定的初始代币单位价值也写入链上，但不属于企业签名内容。资产价值不使用两位截断展示值；到期时点是上游提供的唯一业务值，不使用查看者时区换算后的本地日期。
- 监管机构名称、币种不在签名内容中，仍保存在申请记录；签名时间也不在签名内容中，作为签名记录的一项保存和展示，记录签署时点。
- 确认环节照常展示资产、到期时点、监管机构和自动带出的接收地址，签名只覆盖其中上述四项；钱包中的完整资产价值与到期时点须能与确认环节逐项核对，不能只展示截断金额或换算后无法识别来源的本地日期。签名的具体格式由研发定义。
- 平台核对签名有效、来自登录地址，且签名内容与本次提交一致，才继续提交。
- 签名记录（签名地址、签名时间、签名值和所签内容）随这笔申请保存；企业在申请详情中查看，见[业务签名记录](#signature-record)。
- 签名值随这笔申请的铸造写入链上；签名地址可由签名值推出，不另外上链。申请被驳回时，平台不为这笔申请提交任何链上交易，签名不上链，签名记录随申请保留，不涉及其他申请。已提交但执行失败的铸造交易，其中的字段会随失败交易留在链上，这是链的特性，不代表代币已铸造。
- 一次签名只可用于当前这一次提交尝试。取消或拒绝签名、离开申请、登录结束、签名字段变化或提交不成功后，该签名失效，再次提交须重新签名。
- 同一提交因重复点击、刷新或网络重发时，只能承接同一提交结果，不能产生第二笔申请；已成功使用或已经失效的签名不能用于新的提交尝试。

提交时的再次核对（提交发行申请属于关键业务动作）：

- 按[上游变化的同步（C-AUTH-06）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-06)重新调取并核对认证结论；旧结果不能放行提交。
- 按当时的最新信息重新判断资产的[发起条件](../../两端共用/M2-可信资产/01-可信资产-PRD.md#issue-conditions)，同一笔资产不会产生第二笔申请，见[从可信资产发起发行申请（F-AS-04）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-04)。
- 确认所选监管机构仍为启用，见[企业可选的监管机构](../../管理端/M5-监管机构管理/01-监管机构管理-PRD.md#selectable)。
- 确认当前登录地址仍与本次登录及签名地址一致；上游登录地址已变化时，按[上游变化的同步（C-AUTH-06）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-06)结束本次登录，不使用旧地址提交。

提交成功后：

- 产生一笔发行申请，生成唯一的申请编号，申请状态为“待监管审核”（简报第 5 节）。
- 按[申请信息](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-application)记录提交时的企业名称、资产（含完整资产价值）、到期时点、监管机构、当前登录地址（作为接收地址）和发行申请文件，以及申请编号与提交时间；之后登录地址变化不改变申请记录的接收地址【确认】。提交时的企业名称供审核与消息使用，企业自己的申请详情不重复展示企业名称。
- 应收账款的完整金额与唯一到期时点由上游提交后不再变更【确认】，所以铸造的完整代币数量和到期时点与申请记录一致。
- 提交后上游登录地址变更的：企业账户只展示新的当前登录地址，旧地址不作为其他企业账户保留；本申请记录的接收地址不变，代币仍铸造到该地址，见[查看唯一企业账户（C-ACCOUNT-01）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-ACCOUNT-01)。
- 资产的发行状态变为“发行申请中”，不能再次发起，见[发行状态](../../两端共用/M2-可信资产/01-可信资产-PRD.md#issue-status)。
- 向所选监管机构发送[新的待审申请（NT-R01）](./03-代币发行-企业申请-消息通知.md#NT-R01)；不给企业本人和运营发消息。
- 企业看到提交成功和申请编号，可以进入这笔申请的[申请详情（C-ISSUE-06）](#C-ISSUE-06)，也可以继续为下一笔资产发起申请；下一笔申请从选择资产开始，监管机构重新选择，接收地址继续按提交时的当前登录地址自动记录。

<a id="submit-errors"></a>
提交不成功的情况（以下情况都不产生申请，资产保持“可发行”，未受影响的选择保留）：

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 认证结论已变为未认证 | 不能提交，按[认证资格与受限引导（C-AUTH-04）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-04)说明需先在资产可信平台完成认证 |
| 上游调取失败、超时或不可用，无法确认认证结论或资产最新信息 | 说明暂时无法确认，可稍后重试；不按“已认证”或“满足条件”放行 |
| 资产已不满足发起条件（例如同一企业已在另一处提交了这笔资产的申请、上游状态已变化） | 不能提交，说明具体原因（原因口径以[从可信资产发起发行申请（F-AS-04）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-04)为准）；已在另一处提交的，可以进入那笔申请查看；这笔资产不会产生第二笔申请 |
| 所选监管机构已被停用 | 不能提交，说明该机构当前不可选择，要求重新选择监管机构 |
| 文件数量、单份大小或格式不符合规则，存在空文件、上传中或上传失败未移除的文件 | 不能提交或不添加该文件，说明具体原因；其他合规且已上传成功的文件保留；按[上传发行申请文件（C-ISSUE-08）](#C-ISSUE-08)处理 |
| 提交过程中登录结束（主动退出或登录到期，见[退出与切换钱包（C-AUTH-03）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-03)；上游登录地址变更，见[上游变化的同步（C-AUTH-06）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-06)） | 本次提交不成立，提示未保存；迟到的提交结果不显示 |
| 企业取消签名或钱包拒绝签名 | 本次不提交，说明未完成签名；可以重新提交 |
| 钱包当前地址不是登录地址 | 不能签名提交，提示在钱包中切换到登录地址后重试 |
| 钱包当前不在 Ethereum 网络 | 不能签名提交，提示在钱包中切换到 Ethereum 网络后重试 |
| 签名核对不通过（签名无效、不是登录地址所签，或内容与本次提交不一致） | 不能提交，说明签名未通过核对，可以重新签名提交 |
| 签名已用于成功提交，或已因取消、离开、登录结束、字段变化、提交不成功而失效 | 新的提交尝试不能使用该签名，说明须重新签名；同一次网络重发只返回原提交结果，不创建新申请 |
| 保存失败 | 说明申请未提交成功，可以重试 |

- 提交进行中给出处理中反馈，同一次申请不能重复提交；重复点击、刷新或网络重发都只产生一笔申请。
- 企业在提交前离开申请、取消或登录结束，不保存任何内容，资产保持“可发行”。

| 监管 | 说明这笔资产自铸造成功起由所选监管机构监管，开始时间为铸造时间；融资状态独立于监管，不将监管表述为质押【确认】 |

- 点击代币编号进入我的代币中这枚代币的[代币详情（C-TOKEN-02）](../M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#C-TOKEN-02)，查看其后续状态。

- 本模块没有撤回、修改或重新提交的操作；绕过界面发起同样被拒绝。
- 读取失败时说明暂时无法获取，可以重试；上游平台暂时不可用不影响查看申请，申请由本平台保存。

<a id="C-ISSUE-07"></a>
### 5.4 查看与下载监管协议（C-ISSUE-07）

适用角色与前提：已认证的企业用户，申请属于本企业，且监管一审已通过（申请状态为待运营审核、运营驳回、铸造中、铸造失败或铸造成功）。

依据：企业可以查看 / 下载监管协议（BR-18）【确认】；协议在监管一审通过时上传（BR-10）【确认】；文件与元信息按[监管协议清单](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-agreement)：PDF、JPG、JPEG、PNG，1 至 10 份，每份不超过 10MB【确认】。

- 展示监管机构在一审通过时上传的全部协议文件，每份可以单独查看和下载。
- 每份文件展示上传时的原文件名称和一审通过提交成功的时间；上传机构就是申请所选监管机构，不单独重复展示。
- 监管一审通过之前（待监管审核）和监管驳回的申请，不展示协议，也不能通过直接访问取得。
- 协议文件只对提交该申请的企业开放；其他企业访问按[谁能使用](#access)中的“无权查看或申请不存在”处理。
- 企业只能查看和下载，不能上传、替换或删除协议文件。
- 查看或下载失败时说明本次未能打开，可以重试；不影响查看申请的其他信息。

流程参见：[查看申请与监管协议（图 3）](./02-代币发行-企业申请-流程图与状态机.md#fig-3)。

## 6. 数据来源与归属

| 数据 | 来源 | 本模块能否修改 | 谁能看到 |
| --- | --- | --- | --- |
| 可信资产信息与发起条件 | 上游平台，按[可信资产](../../两端共用/M2-可信资产/01-可信资产-PRD.md)定义 | 不能 | 企业本人；管理端查看由可信资产模块定义 |
| 可选监管机构及名称 | 监管机构管理（M5） | 不能 | 企业只看机构名称 |
| 当前登录地址 | 企业登录与企业账户（M1） | 不能，由系统在提交时自动记录为接收地址 | 企业本人 |
| 发行申请：资产（含完整资产价值）、到期时点、监管机构、接收地址、发行申请文件、提交时间、申请编号 | 本模块，提交时记录；完整金额与到期时点上游提交后不再变更 | 提交后任何角色都不能修改；两位截断展示值不写回记录；文件不能替换、删除或补传 | 企业本人；管理端由 M3b 定义 |
| 业务签名记录：签名地址、签名时间、签名值和所签内容；签名值随铸造写入链上 | 本模块，提交时随这笔申请记录 | 任何角色都不能修改 | 企业本人在申请详情查看；管理端由 M3b 定义 |
| 申请状态、审核结果与时间、驳回意见 | 代币发行·审核与铸造（M3b） | 不能 | 企业本人 |

| 铸造结果 | M3b，来自 Ethereum 链上铸造结果（D5） | 不能 | 企业本人 |

- 提交、提交失败及原因须可追溯：操作的企业用户、时间、所选资产、监管机构和接收地址。

## 8. 待确认事项与依赖

| 编号 | 事项（写清具体冲突点） | 当前处理与影响 |
| --- | --- | --- |
| Q-M3A-01 | 用户已确认发行申请文件“最多十份，最大 10M”，但未限定文件格式。是否沿用监管协议的 PDF、JPG、JPEG、PNG 范围？ | **建议：沿用 PDF、JPG、JPEG、PNG，并按文件实际内容识别，不能只改后缀绕过。** 这些格式已在发行审核中使用，能覆盖文档和扫描件，同时避免把任意可执行文件开放给审核人。用户裁定前，份数、单份大小、上传进度、权限与不可修改规则有效；格式提示与格式验收不判定为已确认。影响 C-ISSUE-08、M3b 申请详情与验收。 |
| Q-M3A-02 | 新增的发行申请文件是否也要由企业钱包签名，并把文件内容摘要写入链上？现有企业签名内容只有资产编号、完整资产价值、唯一到期时点、接收地址。 | **建议本期不扩展企业签名内容。** 文件随申请提交后冻结并留存原文件名、格式、大小、提交时间与访问审计，可控制被替换的风险；初始代币单位价值由运营二审确定并上链，但不属于企业签名内容。若业务要求对文件内容提供链上不可抵赖证明，再单独确认文件摘要生成、多个文件的排序规则和合约承载方式。当前 Hallmark 不增加文件签名或上链说明；研发仍须验证文件存储安全与越权访问拦截。 |

### 依赖

- 企业登录与企业账户（M1）：身份与认证判断、当前登录地址、关键业务动作提交前的认证及登录地址核对。
- 可信资产（M2）与上游平台（D2、D3）：资产信息、发起条件、提交时的最新状态；上游不可用时不能提交。
- 监管机构管理（M5）：启用的监管机构清单与机构名称。
- 代币发行·审核与铸造（M3b）：申请状态推动、审核结果与驳回意见、监管协议文件、铸造结果，以及两端衔接字段清单。
- 文件存储与访问控制：发行申请文件须按申请归属和角色授权读取，提交后保持不可修改；文件内容识别、安全检测、失败重试与越权拦截能力由研发验证（待验证）。
- 线下协议签署（D7）：企业与监管机构线下签署监管协议，平台只展示监管机构上传的文件。
- Ethereum ERC-3525 合约（D5）：铸造结果的来源；铸造交易携带完整代币数量、初始代币单位价值、唯一到期时点、资产编号与企业业务签名值，按 M3b [上链字段](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#onchain-fields)。合约能否无损承载数量、单位价值的小数精度及唯一到期时点、如何携带资产编号、单位价值与签名值（代币属性、事件或元数据），以及对交易成本的影响由开发人员确认（待开发验证）；未验证前不能用截断金额或本地日期替代。铸造的实现与验证由研发、测试负责。
- 合约管理（M6）：代币数量的单位为铸造所用合约的[代币符号](../../管理端/M6-合约管理/01-合约管理-PRD.md#symbol) cou【确认】；合约能否无损承载本次完整代币数量、能否在链上提供代币符号由开发人员验证（待验证）。
- 消息通知（M7）：承接本模块发出的消息，以及 M3b 发给企业、落点为本模块申请详情的消息。
