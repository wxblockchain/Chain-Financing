## 1. 模块是什么

代币发行·企业申请是面客端企业用户以可信资产申请发行（铸造）代币的地方。已认证的企业用户选一笔满足条件的应收账款，选择监管机构和接收代币的数币账户，核对只读的币种、预计发行数量和到期日后提交申请；提交后在这里跟踪监管一审、运营二审和铸造的进度，查看驳回意见、铸造结果，以及监管一审通过后的监管协议。审核与铸造本身由代币发行·审核与铸造（M3b）在管理端完成，本模块只负责企业一侧的申请与查看。

基本原则：

- 企业只需选择监管机构和接收账户，不填写任何发行信息；币种、预计发行数量、到期日由系统按资产带出，企业不能修改（BR-13、BR-19，简报 9.1）【确认】【建议·已采纳】。
- 一笔资产只能有一笔发行申请；提交后不能撤回、不能修改；监管驳回或运营驳回后申请终止，这笔资产不能再次发起（BR-08、BR-12）【确认】。
- 申请状态只引用简报第 5 节，由管理端的审核与铸造结果推动；本模块不另行定义状态。资产的发行状态以[发行状态](../../两端共用/M2-可信资产/01-可信资产-PRD.md#issue-status)为准。
- 申请字段、审核结果与意见、监管协议、铸造结果共用 M3b 维护的[两端衔接字段清单](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff)；本册规定企业侧的选用、可见时点与展示结果。
- 企业看到的铸造阶段统一为“发行处理中”【确认】，按[关联发行申请的铸造阶段展示](../../两端共用/M2-可信资产/01-可信资产-PRD.md#minting-display)执行；申请真实状态与运营处理规则不变。
- 监管协议由企业与监管机构在线下签署，平台不提供签署；监管机构在一审通过时上传，企业此后可以查看和下载（BR-10、BR-18）【确认】。

**一个完整的例子。** 企业 A 的已认证企业用户在可信资产中看到一笔 50,000.00 USD、到期日 2027-03-31 的应收账款，状态为“可发行”，从这笔资产发起发行申请。进入申请后，这笔资产已带入；用户选择监管机构 C，再从数币账户中选择备注名为“A 公司收币地址”的账户。确认环节只读展示币种 USD、预计发行数量 50,000.00、到期日 2027-03-31，并注明以铸造结果为准、提交后不能撤回、需与监管机构 C 线下签署监管协议。用户提交成功，申请状态为“待监管审核”，资产发行状态变为“发行申请中”，监管机构 C 收到一条待审消息。A 与 C 线下签署协议后，C 一审通过并上传协议，A 在申请详情中看到状态变为“待运营审核”，可以下载协议。运营二审通过后，A 看到“发行处理中”；即使铸造失败或运营重新发起铸造，也保持该展示。铸造成功后，A 在申请详情中看到代币数量 50,000.00 USD、所在接收账户、合约和到期日，并可以进入我的代币查看这枚代币，再返回申请详情留存协议。

### 1.1 需求清单

| 功能 | 谁 | 想做什么 | 为了什么 |
| --- | --- | --- | --- |
| [发起申请与选择资产（C-ISSUE-01）](#C-ISSUE-01) | 已认证的企业用户 | 从可信资产或代币发行发起申请，选定一笔资产 | 以可信资产发行代币 |
| [选择监管机构（C-ISSUE-02）](#C-ISSUE-02) | 已认证的企业用户 | 选定负责一审并签署监管协议的机构 | 申请有明确的监管方 |
| [选择接收账户（C-ISSUE-03）](#C-ISSUE-03) | 已认证的企业用户 | 选定接收代币的数币账户 | 代币铸造到企业确认的地址 |
| [确认并提交申请（C-ISSUE-04）](#C-ISSUE-04) | 已认证的企业用户 | 看清币种、数量、到期日与后果后提交 | 提交不可撤回，事先对齐发行结果 |
| [发行申请列表（C-ISSUE-05）](#C-ISSUE-05) | 已认证的企业用户 | 查看本企业全部发行申请 | 掌握每笔申请走到哪一步 |
| [申请详情：进度、驳回意见与铸造结果（C-ISSUE-06）](#C-ISSUE-06) | 已认证的企业用户 | 查看一笔申请的审核进度和结果 | 知道是否通过、为何驳回、代币在哪 |
| [查看与下载监管协议（C-ISSUE-07）](#C-ISSUE-07) | 已认证的企业用户 | 查看并下载监管机构上传的协议 | 留存已签署的协议 |

### 1.2 本期不做

- 撤回、修改、重新提交发行申请，以及驳回后用同一笔资产再次发起（BR-12）【确认】。
- 申请草稿：未提交就离开时不保存任何内容。
- 企业自行填写或修改发行数量、币种、到期日、合约（BR-13、BR-19）【确认】。
- 非美元计价的应收账款发起申请（Q25）【建议·已采纳】。
- 在本平台签署监管协议，或由企业上传协议：协议线下签署，由监管机构上传（BR-10）【确认】。
- 申请中新增、编辑数币账户或手输地址：账户在企业登录与企业账户模块维护，见[发行申请中选用接收账户（C-ACCOUNT-05）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-ACCOUNT-05)。
- 监管一审、运营二审、选择合约、铸造与重试：属于代币发行·审核与铸造（M3b）。
- 代币铸造后的融资、销毁与解除监管：属于我的代币与销毁申请（M4a）及销毁审核、解除监管与代币台账（M4b）。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 发行申请 | 企业以一笔可信资产申请铸造代币的记录，从提交成功起产生，有唯一的申请编号 |
| 可发起的资产 | 本企业满足[发起条件](../../两端共用/M2-可信资产/01-可信资产-PRD.md#issue-conditions)的可信资产 |
| 接收账户 | 申请中选定、用于接收所铸代币的数币账户 |
| 预计发行数量 | 按应收账款美元金额 1:1 计算的代币数量，提交时只读展示；实际数量以铸造结果为准 |
| 监管协议 | 企业与所选监管机构线下签署、由监管机构在一审通过时上传的协议文件 |
| 处理中的发行申请 | 申请状态为待监管审核、待运营审核、铸造中或铸造失败的申请，与[企业登录与企业账户](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md)的口径一致 |
| 发行处理中 | 企业侧对真实状态“铸造中”“铸造失败”的统一展示名称，不是新增业务状态；两种状态下企业都无需操作 |
| 终止的发行申请 | 申请状态为监管驳回或运营驳回的申请 |

<a id="access"></a>
## 3. 谁能使用

依据：只有已认证的企业用户能办理业务【确认】；游客不能使用业务功能【建议·已采纳】。

| 身份 | 能看到代币发行入口吗 | 进入后能做什么 |
| --- | --- | --- |
| 未登录、游客 | 看不到 | 直接访问被拒绝，不返回任何申请数据；游客按[游客引导与功能限制（C-GUEST-01）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-GUEST-01)处理 |
| 未认证的企业用户 | 看得到 | 看到“需先在资产可信平台完成认证”的引导，看不到任何申请数据，不能发起申请，按[认证资格与受限引导（C-AUTH-04）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-04)处理 |
| 已认证的企业用户 | 看得到 | 发起申请；查看本企业全部发行申请及其进度、结果和监管协议 |

- 发行申请归属企业，不归属某个登录地址；上游登录地址变更后，用新地址登录仍看到原有全部申请【确认】。
- 企业只能查看本企业的发行申请。访问其他企业的申请或不存在的申请（包括通过直接链接访问）时，不返回任何内容，统一说明“无权查看或申请不存在”，不区分申请是否存在。
- 拒绝由平台判定，不能只靠隐藏入口；绕过界面提交申请同样被拒绝。

<a id="entry"></a>
### 3.1 入口

- 面客端设“代币发行”业务入口，与可信资产、我的代币、销毁申请并列；进入后是本企业的[发行申请列表（C-ISSUE-05）](#C-ISSUE-05)，可以从这里发起新申请。入口的名称、分组与位置以已确认的面客端组件规范为准，由设计维护。
- 从可信资产中满足条件的资产也可以直接发起，见[从可信资产发起发行申请（F-AS-04）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-04)；可信资产详情中的关联申请可以进入该申请的[申请详情（C-ISSUE-06）](#C-ISSUE-06)。
- 发给企业的发行相关消息（由 M3b 发送）打开后进入该笔申请的申请详情，按当前身份与权限重新判断，见[前往原业务（MSG-05）](../../两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-05)。

<a id="apply"></a>
## 4. 发起与提交发行申请

一次申请依次完成选择资产、选择监管机构、选择接收账户、确认并提交四步。四步在提交前都可以返回修改；提交前不产生发行申请，资产保持“可发行”。

流程参见：[发起并提交发行申请（图 1）](./02-代币发行-企业申请-流程图与状态机.md#fig-1)。

<a id="C-ISSUE-01"></a>
### 4.1 发起申请与选择资产（C-ISSUE-01）

适用角色与前提：已认证的企业用户。

依据：选资产为申请的第一步【确认】；可发起的条件以可信资产模块为准【确认】。

- 从可信资产发起时，这笔资产已带入申请；企业可以在申请中改选其他可发起的资产。
- 从代币发行发起时，企业从本企业可发起的资产中选择一笔。可选范围只包括满足[发起条件](../../两端共用/M2-可信资产/01-可信资产-PRD.md#issue-conditions)的资产；不满足条件的资产不出现在可选范围中，原因在可信资产中查看。
- 每笔可选资产展示：资产编号、债务人名称、应收账款金额与币种、到期日。到期日按[语言与时区](../../两端共用/M2-可信资产/01-可信资产-PRD.md#locale)换算展示。
- 选定资产后可以查看该资产的详情，详情内容以[企业查看本企业可信资产（F-AS-03）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-03)为准。
- 一次申请只能选一笔资产。

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 本企业没有可发起的资产 | 说明当前没有可发起申请的资产，资产须由上游平台确权同步、并满足发起条件；可以前往可信资产查看各资产不能发起的原因；不能进入下一步 |
| 带入的资产在进入申请时已不满足发起条件 | 不带入该资产，说明该资产当前不能发起申请及原因（原因口径以[从可信资产发起发行申请（F-AS-04）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-04)为准）；可以改选其他可发起的资产 |
| 可发起的资产读取失败 | 说明暂时无法获取可发起的资产，可以重试；不说成“没有可发起的资产” |

<a id="C-ISSUE-02"></a>
### 4.2 选择监管机构（C-ISSUE-02）

适用角色与前提：已认证的企业用户，已选定资产。

依据：企业只需选择监管机构（BR-13）【确认】；可选范围以监管机构管理模块为准【确认】。

- 可选范围按[企业可选的监管机构](../../管理端/M5-监管机构管理/01-监管机构管理-PRD.md#selectable)：机构状态为启用的全部监管机构。
- 每家可选机构只展示机构名称；企业看不到登录邮箱、账号状态和其他信息。
- 不预选任何机构；企业须明确选择一家，一笔申请只能选一家。
- 所选机构负责这笔申请的一审，并与企业线下签署监管协议（BR-03、BR-10）【确认】；选择处须说明这一点。

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 当前没有启用的监管机构 | 说明暂无可选择的监管机构，请联系平台管理人员；不能进入下一步 |
| 监管机构读取失败 | 说明暂时无法获取监管机构，可以重试 |

<a id="C-ISSUE-03"></a>
### 4.3 选择接收账户（C-ISSUE-03）

适用角色与前提：已认证的企业用户，已选定资产和监管机构。

依据：没有默认账户（BR-25）【确认】；每次提交都要选一个接收账户（Q24）【建议·已采纳】。

- 可选范围和选用规则按[发行申请中选用接收账户（C-ACCOUNT-05）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-ACCOUNT-05)：本企业数币账户列表中的全部账户，包括登录地址这一条；不预选；只能选已登记的账户，不能新增、编辑或手输地址。
- 每个可选账户展示账户备注名（登录地址这一条标明“登录地址”）、区块链网络（Ethereum）和数币地址；地址按[钱包地址与网络名称的展示](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#address-display)缩写，企业可以核对完整地址。
- 选择处说明：代币将铸造到所选账户的地址，提交后不能更换。
- 企业需要新地址时，先到企业账户中新增数币账户并完成地址归属签名；登记成功的账户随即出现在可选范围中。

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 数币账户读取失败 | 说明暂时无法获取数币账户，可以重试；不说成“没有账户” |

<a id="C-ISSUE-04"></a>
### 4.4 确认并提交申请（C-ISSUE-04）

适用角色与前提：已认证的企业用户，已选定资产、监管机构和接收账户。

依据：申请时只读展示币种、预计数量和到期日，并注明以铸造结果为准（简报 9.1）【建议·已采纳】；USD 1:1 锚定（BR-19）【确认】；到期日取应收账款到期日（BR-13）【确认】；提交后不允许撤回（BR-12）【确认】。

确认环节展示以下信息，全部只读，企业不能修改：

| 业务信息 | 含义与取值 | 展示要求 |
| --- | --- | --- |
| 资产 | 资产编号、债务人名称、应收账款金额与币种 | 只读 |
| 币种 | 固定为 USD | 只读 |
| 预计发行数量 | 等于应收账款的美元金额，代币与美元 1:1 锚定；代币数量精确到两位小数【确认】 | 按两位小数展示，例如 50,000.00 |
| 到期日 | 取应收账款的到期日，企业不填写 | 按[语言与时区](../../两端共用/M2-可信资产/01-可信资产-PRD.md#locale)换算展示 |
| 监管机构 | 所选机构的机构名称 | 只读，可返回改选 |
| 接收账户 | 所选账户的账户备注名、区块链网络（Ethereum）和数币地址 | 地址缩写展示，可核对完整地址；只读，可返回改选 |

确认环节须同时说明以下内容，企业看到后才能提交：

- 币种、预计发行数量和到期日以铸造结果为准。
- 提交后不能撤回或修改；监管机构或平台运营任一级驳回后，申请终止，这笔资产不能再次发起申请。
- 提交后需与所选监管机构在线下签署监管协议，监管机构审核通过时上传协议。

提交时的再次核对（提交发行申请属于关键业务动作）：

- 按[上游变化的同步（C-AUTH-06）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-06)重新调取并核对认证结论；旧结果不能放行提交。
- 按当时的最新信息重新判断资产的[发起条件](../../两端共用/M2-可信资产/01-可信资产-PRD.md#issue-conditions)，同一笔资产不会产生第二笔申请，见[从可信资产发起发行申请（F-AS-04）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-04)。
- 确认所选监管机构仍为启用，见[企业可选的监管机构](../../管理端/M5-监管机构管理/01-监管机构管理-PRD.md#selectable)。
- 确认所选接收账户仍存在，见[发行申请中选用接收账户（C-ACCOUNT-05）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-ACCOUNT-05)。

提交成功后：

- 产生一笔发行申请，生成唯一的申请编号，申请状态为“待监管审核”（简报第 5 节）。
- 按[申请信息](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-application)记录提交时的企业名称、资产、币种、预计发行数量、到期日、监管机构和接收账户地址，以及申请编号与提交时间；之后企业修改该账户的备注名，不改变申请记录的接收地址【确认】。提交时的企业名称供审核与消息使用，企业自己的申请详情不重复展示企业名称。
- 应收账款的金额与到期日由上游提交后不再变更【确认】，所以铸造的代币数量和到期日与申请记录一致。
- 提交时选的是登录地址这一条、之后上游登录地址变更的：原登录地址这一条顺延成为普通账户，仍在本企业的数币账户中【确认】；申请记录的接收地址不变，代币铸造到这个地址。顺延后的备注名、编辑、删除与被引用判断按[数币账户列表与登录地址（C-ACCOUNT-01）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-ACCOUNT-01)。
- 资产的发行状态变为“发行申请中”，不能再次发起，见[发行状态](../../两端共用/M2-可信资产/01-可信资产-PRD.md#issue-status)。
- 所选接收账户被这笔申请引用，处理中不能删除，见[删除数币账户（C-ACCOUNT-04）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-ACCOUNT-04)。
- 向所选监管机构发送[新的待审申请（NT-R01）](./03-代币发行-企业申请-消息通知.md#NT-R01)；不给企业本人和运营发消息。
- 企业看到提交成功和申请编号，可以进入这笔申请的[申请详情（C-ISSUE-06）](#C-ISSUE-06)。

<a id="submit-errors"></a>
提交不成功的情况（以下情况都不产生申请，资产保持“可发行”，未受影响的选择保留）：

| 情况 | 用户看到的结果与可继续操作 |
| --- | --- |
| 认证结论已变为未认证 | 不能提交，按[认证资格与受限引导（C-AUTH-04）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-04)说明需先在资产可信平台完成认证 |
| 上游调取失败、超时或不可用，无法确认认证结论或资产最新信息 | 说明暂时无法确认，可稍后重试；不按“已认证”或“满足条件”放行 |
| 资产已不满足发起条件（例如同一企业已在另一处提交了这笔资产的申请、上游状态已变化） | 不能提交，说明具体原因（原因口径以[从可信资产发起发行申请（F-AS-04）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-04)为准）；已在另一处提交的，可以进入那笔申请查看；这笔资产不会产生第二笔申请 |
| 所选监管机构已被停用 | 不能提交，说明该机构当前不可选择，要求重新选择监管机构 |
| 所选接收账户已被删除 | 不能提交，说明该账户已不存在，要求重新选择接收账户，不用旧值提交 |
| 提交过程中登录结束（主动退出、登录到期或地址变更） | 本次提交不成立，按[退出与切换钱包（C-AUTH-03）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-03)提示未保存；迟到的提交结果不显示 |
| 保存失败 | 说明申请未提交成功，可以重试 |

- 提交进行中给出处理中反馈，同一次申请不能重复提交；重复点击、刷新或网络重发都只产生一笔申请。
- 企业在提交前离开申请、取消或登录结束，不保存任何内容，资产保持“可发行”。

## 5. 查看发行申请

<a id="status"></a>
### 5.1 申请状态与企业看到的内容

申请状态引用简报第 5 节：待监管审核 → 监管驳回（终止）/ 待运营审核 → 运营驳回（终止）/ 铸造中 → 铸造成功 / 铸造失败（→ 运营重试 → 铸造中）【建议·已采纳】。状态由代币发行·审核与铸造（M3b）的审核与铸造结果推动，企业在本模块不能改变任何状态。

企业侧的列表、详情和审核进度按下表展示；真实状态仅用于说明业务对应关系，不直接作为企业可见文案。企业不展示铸造失败的原因、失败时间、失败次数或重试记录。

| 真实申请状态 | 企业可见状态与进度 | 驳回意见 | 监管协议 | 铸造结果 | 资产发行状态 |
| --- | --- | --- | --- | --- | --- |
| 待监管审核 | 待监管审核；等待所选监管机构审核，需与该机构线下签署监管协议 | 不展示 | 不可见 | 不展示 | 发行申请中 |
| 监管驳回 | 监管驳回；申请已终止，这笔资产不能再次发起 | 展示监管机构填写的驳回意见 | 不可见 | 不展示 | 已驳回 |
| 待运营审核 | 待运营审核；监管机构已审核通过，等待平台运营审核 | 不展示 | 可查看、下载 | 不展示 | 发行申请中 |
| 运营驳回 | 运营驳回；申请已终止，这笔资产不能再次发起 | 展示平台运营填写的驳回意见 | 可查看、下载 | 不展示 | 已驳回 |
| 铸造中、铸造失败（含等待重试及原合约不可用） | 发行处理中；平台运营已审核通过，发行尚未完成，企业无需操作 | 不展示 | 可查看、下载 | 不展示 | 发行申请中 |
| 铸造成功 | 铸造成功；代币已铸造到所选接收账户，这笔资产从铸造成功起由所选机构监管 | 不展示 | 可查看、下载 | 展示[铸造结果](#mint-result) | 已发行 |

- 监管驳回和运营驳回是终态，申请不再变化；铸造成功后申请不再变化，代币之后的状态在我的代币中查看。
- 铸造失败后由运营按[铸造失败手动重试（A-ISSUE-07）](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#A-ISSUE-07)处理【确认】；重试沿用二审原合约，原合约不可用时保持铸造失败。企业在等待重试、合约恢复和重新铸造期间始终看到“发行处理中”，不显示内部处理差异。
- 资产发行状态一列由可信资产模块定义，此处只说明对应关系。

流程参见：[发行申请状态（图 2）](./02-代币发行-企业申请-流程图与状态机.md#fig-2)。

<a id="C-ISSUE-06"></a>
### 5.3 申请详情：进度、驳回意见与铸造结果（C-ISSUE-06）

适用角色与前提：已认证的企业用户，申请属于本企业。

申请信息按[申请信息清单](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-application)中的企业可见范围展示：提交时记录的业务值保持不变，机构名称与账户备注名展示当前值。

| 业务信息 | 含义 |
| --- | --- |
| 申请编号 | 提交成功时生成，平台内唯一 |
| 提交时间 | 提交成功的时点，按[语言与时区](../../两端共用/M2-可信资产/01-可信资产-PRD.md#locale)展示 |
| 资产 | 资产编号、债务人名称、应收账款金额与币种；可以进入该资产在可信资产中的详情 |
| 币种 | USD |
| 预计发行数量 | 提交时按应收账款美元金额计算的数量，两位小数，注明以铸造结果为准 |
| 到期日 | 提交时应收账款的到期日，注明以铸造结果为准 |
| 监管机构 | 机构名称，取机构当前名称（与[与相邻模块的分工](../../管理端/M5-监管机构管理/01-监管机构管理-PRD.md#neighbors)一致）；机构之后被停用不影响这笔申请，申请照常审核 |
| 接收账户 | 提交时所选账户的数币地址（缩写展示，可核对完整地址）、区块链网络 Ethereum，以及该账户当前的账户备注名（当前仍是登录地址这一条的，标明“登录地址”）；账户之后被删除时只展示地址，并说明该账户已删除 |

审核进度按[审核结果与意见清单](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-review)中的企业可见范围展示：

- 按顺序展示提交、监管一审、运营二审、铸造四个环节；已完成的环节展示结果和完成时间，尚未到达的环节展示为未开始，铸造阶段按下方统一展示规则处理。
- 监管一审以所选监管机构的名称呈现；运营二审以“平台运营”呈现，不展示具体运营账号。
- 驳回时展示驳回的环节、驳回时间和驳回意见；驳回意见按填写的原文展示，不翻译。
- 一审通过时填写的监管意见不向企业展示；具体运营审核账号也不向企业展示。
- 运营二审通过后、铸造成功前，铸造环节统一展示“发行处理中”；失败、未能发起重试和重试不产生企业可见的失败或重试节点。成功后展示成功结果与铸造时间。
- 当前状态的进度说明按[申请状态与企业看到的内容](#status)展示。

<a id="mint-result"></a>
铸造结果按[铸造结果清单](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-mint)中的企业可见范围展示，仅铸造成功时可见：

| 业务信息 | 含义 |
| --- | --- |
| 代币数量与币种 | 实际铸造的代币数量，两位小数，USD；与申请的预计发行数量一致 |
| 到期日 | 代币的到期日，与申请记录的到期日一致 |
| 接收账户 | 代币所在的数币地址（缩写展示，可核对完整地址），即提交时所选接收账户的地址 |
| 合约 | 铸造所用合约的名称、标准（ERC-3525）、所在网络（Ethereum）和合约地址；合约由运营在二审时选择 |
| 铸造时间 | 铸造成功的时点 |
| 监管 | 说明这笔资产自铸造成功起由所选监管机构监管，开始时间为铸造时间；融资状态独立于监管，不将监管表述为质押【确认】 |

- 铸造成功的申请可以进入我的代币中这枚代币的[代币详情（C-TOKEN-02）](../M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#C-TOKEN-02)，查看其后续状态。
- 铸造失败说明及历次失败、重试记录只由管理端按角色查看，不属于企业的铸造结果；字段清单中企业可见状态与监管名称的待同步差异见[已确认口径的跨模块同步](#confirmed-sync)。

其他规则：

- 申请详情中的资产链接进入可信资产的资产详情；提交后资产被撤销确权、删除、逾期或结清，不自动拦截审核、铸造或重试，也不自动终止申请【确认】，按[审核期间资产变化](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#review-asset-change)执行。审核人查看资产最新状态并按可操作的环节决定是否驳回；企业看到申请的当前结果，上游撤销确权与删除的专门提示只在运营端出现。
- 本模块没有撤回、修改或重新提交的操作；绕过界面发起同样被拒绝。
- 读取失败时说明暂时无法获取，可以重试；上游平台暂时不可用不影响查看申请，申请由本平台保存。
- 字段名称、状态取值和说明文字按当前界面语言展示中文或英文；金额、数量、编号和驳回意见原文不随语言变化，按[语言与时区](../../两端共用/M2-可信资产/01-可信资产-PRD.md#locale)执行；面客端的时区按本人在[偏好设置（C-PROFILE-02）](../M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-PROFILE-02)中的选择。

<a id="C-ISSUE-07"></a>
### 5.4 查看与下载监管协议（C-ISSUE-07）

适用角色与前提：已认证的企业用户，申请属于本企业，且监管一审已通过（申请状态为待运营审核、运营驳回、铸造中、铸造失败或铸造成功）。

依据：企业可以查看 / 下载监管协议（BR-18）【确认】；协议在监管一审通过时上传（BR-10）【确认】；文件与元信息按[监管协议清单](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-agreement)：PDF、JPG、JPEG、PNG，1 至 10 份，每份不超过 10MB【确认】。

- 展示监管机构在一审通过时上传的全部协议文件，每份可以单独查看和下载。
- 每份文件展示上传时的原文件名称和一审通过提交成功的时间；上传机构就是申请所选监管机构，不单独重复展示。
- 监管一审通过之前（待监管审核）和监管驳回的申请，不展示协议，也不能通过直接访问取得。
- 协议文件只对提交该申请的企业开放；其他企业访问按[谁能使用](#access)中的“无权查看或申请不存在”处理。
- 企业只能查看和下载，不能上传、替换或删除协议文件。
- 查看或下载失败时说明本次未能打开，可以重试；不影响查看申请的其他信息。

流程参见：[查看申请与监管协议（图 3）](./02-代币发行-企业申请-流程图与状态机.md#fig-3)。

| 数币账户 | 企业登录与企业账户（M1）的企业账户 | 不能，只选用 | 企业本人 |
| 发行申请：资产、币种、预计发行数量、到期日、监管机构、接收地址、提交时间、申请编号 | 本模块，提交时记录；金额与到期日上游提交后不再变更 | 提交后任何角色都不能修改 | 企业本人；管理端由 M3b 定义 |
| 申请状态、审核结果与时间、驳回意见 | 代币发行·审核与铸造（M3b） | 不能 | 企业本人 |
| 监管协议文件 | 监管机构在 M3b 一审通过时上传 | 不能 | 企业本人（一审通过后）；管理端由 M3b 定义 |
| 铸造结果 | M3b，来自 Ethereum 链上铸造结果（D5） | 不能 | 企业本人 |

- 提交、提交失败及原因须可追溯：操作的企业用户、时间、所选资产、监管机构和接收地址。

### 依赖

- 企业登录与企业账户（M1）：身份与认证判断、关键业务动作提交前的认证核对、数币账户的可选范围与引用规则。
- 可信资产（M2）与上游平台（D2、D3）：资产信息、发起条件、提交时的最新状态；上游不可用时不能提交。
- 监管机构管理（M5）：启用的监管机构清单与机构名称。
- 代币发行·审核与铸造（M3b）：申请状态推动、审核结果与驳回意见、监管协议文件、铸造结果，以及两端衔接字段清单。
- 线下协议签署（D7）：企业与监管机构线下签署监管协议，平台只展示监管机构上传的文件。
- Ethereum ERC-3525 合约（D5）：铸造结果的来源；铸造的实现与验证由研发、测试负责。
- 消息通知（M7）：承接本模块发出的消息，以及 M3b 发给企业、落点为本模块申请详情的消息。
