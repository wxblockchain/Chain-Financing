# 可信资产 · 功能与业务规则

2026-10-29｜面客端：企业用户；管理端：运营管理人员、监管机构｜需求评审稿

本模块共三册：本册写功能、业务规则与字段规则；[流程图与状态机](./v1.0-可信资产-流程图与状态机.md)画出主要流程与资产状态；[验收](./v1.0-可信资产-验收.md)供测试使用。本模块自身不发送任何消息（与资产有关的消息由发行、销毁等模块在各自环节发出，见[消息通知](./v1.0-消息通知-PRD.md)），所以没有 03 消息通知册，并非缺失。

编号说明：功能编号（F-AS-*）标在章节标题上，供验收追溯；待确认编号（Q-AS-*）用于定位待确认事项，编号沿用原值，已关闭的条目不再占号，缺号不代表遗漏。功能标识（C-ASSET、A-ASSET）、业务规则编号（BR-*）和依赖编号（D*）沿用《代币发行平台 · 需求诊断简报》v1.6（下称简报）。规则后的【确认】表示用户已明确，【建议·已采纳】表示诊断建议已由用户采纳，两者同样有效。

## 1. 模块是什么

可信资产模块把资产可信平台（下称上游平台）已确权的应收账款展示在本平台，作为企业发起代币发行的唯一资产来源。企业在这里查看本企业的应收账款、贸易背景、回款进度和材料，以及每笔资产的各项状态，并从满足条件的资产发起发行申请；运营管理人员查看全平台的企业、资产和企业数币账户，用于审核核对，并在这里看到上游撤销确权、删除资产的提示；监管机构只查看本机构申请所关联的资产。

基本原则：

- 只有下游企业确权后的应收账款才会进入本平台，才可发起发行（BR-02）【确认】。资产、企业、个人和回款信息全部来自上游平台，本平台任何角色都不能新增、修改或删除。
- 资产信息分两级：L1 通用必传字段对所有行业统一，不随行业区分，面向国际企业，不以某一国家的登记号码为准；L2 补充字段也抽象为各行业通用的字段，由行业大类说明在该行业的具体含义，本期只有汽车贸易【确认】。
- 资产状态拆成几个各自独立的字段，每个字段只回答一个问题：是否确权、是否结清、是否逾期、发行走到哪一步、是否在监管、是否在融资。不把不同来源的状态混成一条链。
- 只有未到期、债权人已确权的资产才能发起发行；一笔资产只能发起一次发行申请，申请处理中、被驳回或已铸造后都不能再次发起（BR-08、BR-12）【确认】。
- 本模块只展示状态，不提供改状态的操作。发行、监管状态由发行与销毁模块的业务结果推动；确权、结清、逾期状态由上游平台提供；融资状态由下游借贷平台提供。

**一个完整的例子。** 企业 A（注册在香港）向下游企业 B（注册在阿联酋）销售一批新车，并向车辆厂商采购；车辆海运交付到 B 指定的仓库后，A 形成一笔 50,000 USD、到期日为 2027-03-31 的应收账款。B 在上游平台确权后，这笔应收账款同步到本平台。A 用登录地址登录面客端，在可信资产中看到这笔资产：确权状态“已确权”，结清状态“未结清”，逾期状态“未逾期”，发行状态“可发行”；详情里有基本信息、贸易订单（车辆品牌、型号、VIN 与提单号）、采购订单、回款进度和材料。A 从这笔资产发起发行申请，提交成功后发行状态变为“发行申请中”。监管机构 C 审核时可以查看这笔资产；运营二审前核对 A 的企业信息、这笔资产的回款进度和 A 的数币账户。铸造成功后，发行状态变为“已铸造”，监管状态变为“监管中（监管机构 C）”；A 用代币在下游借贷平台融资期间，融资状态显示“融资中”。到期前 B 回款结清，结清状态变为“已结清”；代币销毁后，发行状态变为“代币已销毁”；监管机构 C 解除监管后，监管状态变为“已解除监管”。A 回到可信资产，能看到这笔资产的完整去向，以及关联的发行申请和代币。

### 1.2 本期不做

- 应收账款以外的资产类型。
- 汽车贸易以外的行业大类：行业大类字段已具备，但本期只有汽车贸易【确认】。
- 在本平台录入、修改、删除或补传资产、企业、个人和回款信息。
- 非美元计价的应收账款发起发行：可以查看，不能发起【建议·已采纳】。
- 上游撤销确权、删除资产后的系统处理：只在运营端提示，不自动改变任何状态【确认】。
- 企业维护数币账户、企业查看本企业的用户信息与企业信息：属于企业登录与企业账户模块。
- 与上游平台、下游借贷平台对接的接口方式与同步频率：由研发确定。

<a id="F-AS-01"></a>
## 3. 资产进入本平台与信息结构（F-AS-01）

适用范围：本节是企业、运营、监管三类查看功能共用的资产来源与字段定义，其他章节引用此处，不重复定义。

### 3.1 资产来源

业务来源【确认】：下游企业向本企业下单购买新车 → 本企业向厂商采购，约定车辆海运直发下游企业指定的仓库 → 车辆交付后，本企业形成对下游企业的应收账款 → 下游企业确权 → 已确权的应收账款同步到本平台。

- 只有确权状态为“已确权”的应收账款进入本平台；未确权的应收账款不进入，任何角色在本平台都看不到。
- 资产归属上游平台记录的债权人企业；企业只能看到本企业作为债权人的资产。
- 资产信息以上游平台的最新信息为准，上游更新后本平台展示更新后的信息；可发行的资产按最新信息判断能否发起申请【确认】。
- 上游撤销确权或删除资产时，只在运营端提示，本平台不自动改变任何状态，见[上游变更提示](#upstream-change)【确认】。

<a id="field-levels"></a>
### 3.2 信息结构与分级

资产信息分为六组：应收账款基本信息，以及用户确认的五组——贸易订单、采购订单、账款信息、回款进度、材料【确认】。每个字段标明级别：

- **L1 通用必传**：对所有行业统一，不随行业区分；每笔资产都必须具备全部 L1 字段。企业身份用“注册国家 / 地区 + 企业登记标识”表示，不限定为某一国家的登记号码【确认】。
- **L2 通用补充**：各行业通用的字段，不是必传。行业大类说明它在该行业的具体含义，下表“汽车贸易”列给出本期的对应关系；新增行业大类时沿用同一组字段，只补充该行业的对应关系【确认】。
- **回款（上游）**：回款进度来自上游平台，结清状态和逾期状态每笔资产都必须有。
- 字段是初版，最终以对接的上游平台为准，见[字段最终清单（Q-AS-01）](#Q-AS-01)。字段增减时仍按本节分级。

以下六组信息对企业（本企业资产）、运营、监管机构（关联资产）都可见，标为“只入库”的字段对所有角色都不展示。

<a id="F-AS-02"></a>
## 4. 资产状态（F-AS-02）

资产状态由下表六个独立字段组成，每个字段只回答一个问题，来源各自独立【确认】。发行与销毁相关模块（M3a、M3b、M4a、M4b）引用本节定义，不另行定义资产状态【确认】。

<a id="status-fields"></a>
### 4.1 状态字段一览

| 状态字段 | 回答的问题 | 取值 | 来源 | 何时展示 |
| --- | --- | --- | --- | --- |
| 确权状态 | 债权人的这笔应收账款是否已被债务人确权 | 已确权、已撤销确权 | 上游平台 | 始终展示 |
| 结清状态 | 这笔应收账款是否已经结清 | 未结清、已结清 | 上游平台 | 始终展示 |
| 逾期状态 | 这笔应收账款是否已经逾期 | 未逾期、已逾期 | 上游平台；到期兜底见[逾期状态](#overdue) | 始终展示 |
| 发行状态 | 这笔资产在本平台的发行走到了哪一步 | 可发行、发行申请中、已驳回、已铸造、代币已销毁 | 本平台，由发行与销毁模块的业务结果推动 | 始终展示 |
| 监管状态 | 这笔资产是否正由监管机构监管、由哪个机构监管 | 监管中、已解除监管；同时展示监管机构名称 | 本平台，由铸造结果与监管机构的操作推动 | 铸造成功后才展示 |
| 融资状态 | 对应代币是否正在下游借贷平台融资 | 未融资、融资中 | 下游借贷平台 | 发行状态为“已铸造”时才展示 |

- 各状态取不到时，标明暂时无法获取，不按任何一个取值处理。
- “未到期”不是单独的字段，而是结清状态为“未结清”、逾期状态为“未逾期”，且尚未到达到期日【确认】。
- 原“监管质押”的说法不再使用：本平台只有“监管”，由监管状态表示；资产与代币上只有下游借贷平台提供的“融资中”【确认】。

<a id="confirm-status"></a>
### 4.2 确权状态

- 资产进入本平台时为“已确权”。
- 上游撤销确权后变为“已撤销确权”，各角色看到的都是最新值；只有运营端另有[上游变更提示](#upstream-change)。
- 确权状态的变化不改变发行、监管、融资状态。

<a id="overdue"></a>
### 4.3 结清状态与逾期状态

- 结清状态和逾期状态都由上游平台提供【确认】。
- 到达到期日时，本平台仍未取得上游的最新状态（结清状态仍为“未结清”、逾期状态仍为“未逾期”）的，自动把逾期状态变为“已逾期”；之后上游提供新的状态时，以上游为准【确认】。到期日当天是否已算到达、按哪个时区，见[到期的时点（Q-AS-08）](#Q-AS-08)。
- 结清状态变为“已结清”后不再变化。
- 先逾期后结清的资产，逾期状态保留“已逾期”，结清状态为“已结清”，如实反映回款经过。
- 结清、逾期状态与发行、监管、融资状态互不推动。

<a id="issue-status"></a>
### 4.4 发行状态

- 资产进入本平台时为“可发行”，之后只按下表向前变化，不回退。“已驳回”和“代币已销毁”是终态。
- 发行申请处于待监管审核、待运营审核、铸造中、铸造失败待重试时，发行状态都为“发行申请中”。
- 销毁申请处于审核中、被驳回、销毁中、销毁失败待重试时，发行状态保持“已铸造”。

| 发行状态 | 含义 | 由什么结果进入 | 之后可能变为 |
| --- | --- | --- | --- |
| 可发行 | 资产已进入本平台，尚未发起发行申请 | 已确权的应收账款同步到本平台 | 发行申请中 |
| 发行申请中 | 已提交发行申请，正在审核或铸造 | 企业在代币发行·企业申请（M3a）中提交申请成功 | 已驳回；已铸造 |
| 已驳回 | 发行申请被驳回，申请终止，这笔资产不能再次发起（BR-12） | 在代币发行·审核与铸造（M3b）中，监管一审驳回或运营二审驳回 | 不再变化（终态） |
| 已铸造 | 代币已铸造成功 | 在代币发行·审核与铸造（M3b）中铸造成功 | 代币已销毁 |
| 代币已销毁 | 代币已销毁，这笔资产不能再次发起（BR-08） | 在销毁审核、解除质押与代币台账（M4b）中代币销毁成功 | 不再变化（终态） |

<a id="supervision"></a>
### 4.5 监管状态

- 铸造成功时，监管状态变为“监管中”，监管机构为这笔发行申请所选的监管机构。
- 代币销毁成功后，监管机构在平台上解除监管并留存记录，监管状态变为“已解除监管”；解除操作和记录内容由销毁审核、解除质押与代币台账模块（M4b）定义。
- “已解除监管”后不再变化。
- 监管的起止沿用原“监管质押”的起止（BR-21），名称与起止待简报同步，见[监管状态的口径（Q-AS-09）](#Q-AS-09)。

<a id="financing"></a>
### 4.6 融资状态

- 融资状态由下游借贷平台提供：“融资中”表示企业正用这笔资产对应的代币在下游借贷平台融资，否则为“未融资”【确认】。
- 只在发行状态为“已铸造”时展示；代币销毁后不再展示。
- 本模块只展示下游借贷平台提供的融资状态。销毁前的融资校验（下游接口 + 链上验证，BR-20）由我的代币与销毁申请模块（M4a）定义。

<a id="status-combination"></a>
### 4.7 发行、监管、融资状态的组合

发行、监管、融资三个状态只会以下表的组合出现；确权、结清、逾期状态在每种组合下都独立展示。

| 发行状态 | 监管状态 | 融资状态 | 企业看到的说明与去向 |
| --- | --- | --- | --- |
| 可发行 | 不展示 | 不展示 | 满足[发起条件](#issue-conditions)时可以发起发行申请；不满足时说明原因 |
| 发行申请中 | 不展示 | 不展示 | 已有发行申请正在处理，可以查看这笔申请的进度 |
| 已驳回 | 不展示 | 不展示 | 发行申请已被驳回，这笔资产不能再次发起，可以查看这笔申请及驳回意见 |
| 已铸造 | 监管中（监管机构名称） | 未融资 | 代币已铸造，资产由该监管机构监管中，可以查看代币 |
| 已铸造 | 监管中（监管机构名称） | 融资中 | 代币已铸造并正在下游借贷平台融资，资产由该监管机构监管中，可以查看代币 |
| 代币已销毁 | 监管中（监管机构名称） | 不展示 | 代币已销毁，等待该监管机构解除监管 |
| 代币已销毁 | 已解除监管（监管机构名称） | 不展示 | 已解除监管，流程已结束，可以查看关联的申请和代币记录 |

<a id="common-errors"></a>
## 5. 共用的访问限制与数据异常

以下规则适用于本模块的所有查看功能，各功能章节直接引用，不重复展开。

<a id="no-access"></a>
### 5.1 无权查看

- 各角色只能查看自己范围内的资产和企业：已认证的企业用户只看本企业资产；监管机构只看关联资产；只有运营能查看企业列表、企业信息、企业用户信息和数币账户。
- 访问范围以外的资产或企业（包括通过直接链接访问）时，不返回任何资产或企业信息，统一说明“无权查看或资产不存在”，不区分资产是否存在。
- 游客按[游客引导与功能限制（C-GUEST-01）](./v1.0-企业登录与企业账户-PRD.md#C-GUEST-01)处理，看不到可信资产；未认证的企业用户按[认证资格与受限引导（C-AUTH-04）](./v1.0-企业登录与企业账户-PRD.md#C-AUTH-04)处理，看得到入口，看不到任何资产数据。

<a id="missing-data"></a>
### 5.2 上游信息缺失

- L1 字段任一项缺失时，资产仍然可以查看，缺失项标明上游未提供；这笔资产不能发起申请，原因说明为资产信息不完整。
- L2 字段、回款记录中的单项缺失时，标明未提供，不影响查看和发起申请。
- 账款信息整组没有时，说明无账款信息，不视为缺失。
- 状态取不到时按[状态字段一览](#status-fields)的规则标明暂时无法获取。

### 5.3 上游或下游平台暂时不可用

- 各角色仍然看到本平台最近一次保存的资产、回款、企业信息和状态。
- 恢复后展示更新后的信息。

### 5.4 材料无法打开

- 材料查看或下载失败时，说明本次未能打开，可以重试；不影响查看其他信息。

<a id="F-AS-03"></a>
## 6. 企业查看本企业可信资产（F-AS-03）

对应功能标识：C-ASSET（可信资产）。

适用角色与前提：已认证的企业用户。游客、未认证的企业用户和越权访问按[无权查看](#no-access)处理。

### 6.1 资产列表

- 列出本企业作为债权人、已进入本平台的全部资产，包括已驳回和代币已销毁的资产。
- 每笔资产展示：上游资产编号、债务人名称、应收账款金额与币种、到期日、确权状态、结清状态、逾期状态、发行状态，以及能否发起申请。
- 本企业还没有任何资产时，说明资产由上游平台确权后同步到本平台，本平台不能录入资产。

### 6.2 资产详情

- 展示[信息结构与分级](#field-levels)中六组信息里标为展示的全部字段，以及[状态字段一览](#status-fields)中当前应展示的状态。
- 材料可以查看和下载。
- 已发起过发行申请的资产，展示关联的发行申请（申请编号、申请状态），可以进入代币发行·企业申请模块查看这笔申请。
- 已铸造代币的资产，展示关联的代币，可以进入我的代币与销毁申请模块查看这枚代币。
- 不能发起申请时，说明原因，见[发起条件](#issue-conditions)。
- 信息缺失按[上游信息缺失](#missing-data)处理。

<a id="F-AS-04"></a>
## 7. 从可信资产发起发行申请（F-AS-04）

对应功能标识：C-ASSET（从可发行资产发起申请，入口衔接 M3a）。

适用角色与前提：已认证的企业用户，针对本企业的资产。

<a id="issue-conditions"></a>
### 7.1 发起条件

同时满足以下全部条件，资产才可以发起申请：

1. 发行状态为“可发行”（BR-08、BR-12）【确认】。
2. 确权状态为“已确权”；可发起的资产须明确展示“债权人已确权”，这个状态值由上游提供【确认】。
3. 未到期：结清状态为“未结清”，逾期状态为“未逾期”，且尚未到达到期日【确认】。
4. 币种为 USD（简报 Q25）【建议·已采纳】。
5. L1 信息完整，见[上游信息缺失](#missing-data)。
6. 各项状态都已取得，没有“暂时无法获取”的状态。

### 7.2 发起与结果

- 满足条件时，企业可以从资产列表或资产详情发起发行申请，进入代币发行·企业申请流程，并带入这笔资产。选择监管机构、选择接收代币的数币账户、确认与提交，都按代币发行·企业申请模块执行。
- 企业进入申请流程后未提交就离开时，资产保持“可发行”。
- 申请提交成功后，发行状态变为“发行申请中”，不能再次发起。
- 不满足条件时，不提供发起入口，并说明全部不满足的原因：已有申请处理中、申请已被驳回、已铸造或代币已销毁、债权人确权已撤销、资产已逾期、资产已结清、已到达到期日、仅支持美元计价的资产、资产信息不完整、暂时无法确认资产状态。

### 7.3 重复发起与条件变化

- 同一笔资产在任何时候最多只有一笔发行申请。
- 申请提交时按当时的最新信息重新判断发起条件；不满足时（例如同一企业在另一处已提交了这笔资产的申请，或上游状态已变化）不能提交，说明原因，资产不会产生第二笔申请。

<a id="F-AS-05"></a>
## 8. 运营查看企业与资产（F-AS-05）

对应功能标识：A-ASSET（可信资产 / 企业查看）【建议·已采纳】。

适用角色与前提：已登录管理端的运营管理人员（管理员）。本功能全部只读：运营不能修改任何信息，也不能代企业发起申请。

### 8.1 企业列表

- 列出上游平台同步到本平台的企业【确认】。
- 每个企业展示：企业名称、注册国家 / 地区、企业登记标识、登录地址、当前有效认证结论、已进入本平台的资产笔数。
- 可以按企业名称或企业登记标识查找企业。

### 8.2 企业详情

- 展示[企业信息与企业用户信息](#field-enterprise)。
- 展示该企业当前的全部[数币账户](#field-account)，登录地址这一条标明“登录地址”；企业已删除的账户不展示。
- 展示该企业的资产列表，内容同[全平台资产列表](#F-AS-05-assets)，可以进入资产详情。

<a id="F-AS-05-assets"></a>
### 8.3 全平台资产列表与资产详情

- 资产列表列出全平台已进入本平台的资产。每笔资产展示：上游资产编号、债权人名称、债务人名称、应收账款金额与币种、到期日、确权状态、结清状态、逾期状态、发行状态，以及[上游变更提示](#upstream-change)。
- 可以按上游资产编号或债权人名称查找资产。
- 资产详情展示[信息结构与分级](#field-levels)中六组信息里标为展示的全部字段、[状态字段一览](#status-fields)中当前应展示的状态，以及上游变更提示；材料可以查看和下载。
- 已发起过发行申请的资产，展示关联的发行申请（申请编号、申请状态、所选监管机构），可以进入代币发行·审核与铸造模块查看申请详情。
- 已铸造代币的资产，展示关联的代币，可以进入代币台账查看。
- 资产详情可以进入债权人企业的企业详情。
- 信息缺失按[上游信息缺失](#missing-data)处理。

<a id="upstream-change"></a>
### 8.4 上游变更提示

- 上游撤销确权时，运营端在这笔资产的列表项和详情中标明“上游已撤销确权”【确认】。
- 上游删除资产时，本平台保留最近一次保存的信息，运营端在列表项和详情中标明“上游已删除”【确认】。
- 这两类提示只在运营端出现，企业端和监管端不出现提示【确认】。
- 本平台不做系统处理：不自动改变发行、监管、融资状态，不终止发行申请，不影响已铸造的代币；是否驳回申请等由运营在相应业务中人工处理【确认】。
- 可发行的资产被撤销确权后，按最新信息不满足[发起条件](#issue-conditions)，企业不能再发起。

<a id="F-AS-06"></a>
## 9. 监管机构查看关联资产（F-AS-06）

对应功能标识：A-ASSET 中“监管机构仅查看本机构申请关联的资产”（简报 4.4 权限矩阵）。

适用角色与前提：已登录管理端的监管机构。监管机构只能看到本机构的申请和代币（BR-15）【确认】。

- 查看范围是关联资产：选择了本机构的发行申请所使用的资产，无论这笔申请处于什么状态，包括被本机构驳回、被运营驳回的申请。
- 一笔资产最多只有一笔发行申请，所以一笔关联资产只对应本机构的一笔申请。
- 关联资产列表展示：上游资产编号、债权人名称、债务人名称、应收账款金额与币种、到期日、确权状态、结清状态、逾期状态、发行状态、监管状态。
- 资产详情展示[信息结构与分级](#field-levels)中六组信息里标为展示的全部字段，以及[状态字段一览](#status-fields)中当前应展示的状态；材料可以查看和下载。
- 资产详情展示本机构关联的这笔发行申请（申请编号、申请状态），可以进入代币发行·审核与铸造模块查看。
- 监管机构看不到企业列表、企业详情、企业用户信息、数币账户和上游变更提示；债权人只通过基本信息中的债权人名称、注册国家 / 地区和企业登记标识呈现。
- 访问非关联资产按[无权查看](#no-access)处理；信息缺失按[上游信息缺失](#missing-data)处理。
