# 可信资产 · 功能与业务规则

2026-10-29｜面客端：企业用户；管理端：运营管理人员、监管机构｜需求评审稿

本模块共三册：本册写功能、业务规则与字段规则；[流程图与状态机](./v1.0-可信资产-流程图与状态机.md)画出主要流程与资产状态；[验收](./v1.0-可信资产-验收.md)供测试使用。本模块自身不发送任何消息（与资产有关的消息由发行、销毁等模块在各自环节发出，见[消息通知](./v1.0-消息通知-PRD.md)），所以没有 03 消息通知册，并非缺失。

编号说明：功能编号（F-AS-*）标在章节标题上，供验收追溯。功能标识（C-ASSET、A-ASSET）、业务规则编号（BR-*）和依赖编号（D*）沿用《代币发行平台 · 需求诊断简报》v1.6（下称简报）。规则后的【确认】表示用户已明确，【建议·已采纳】表示诊断建议已由用户采纳，两者同样有效。

本册只定义信息需求与业务行为；页面布局、组件形态与交互承载由 Hallmark 设计决定。

## 1. 模块是什么

可信资产模块把资产可信平台（下称上游平台）已确权的应收账款展示在本平台，作为企业发起代币发行的唯一资产来源。企业在这里查看本企业的应收账款、贸易背景、账款与回款情况和材料，以及每笔资产的确权、结清、逾期和发行状态，并从满足条件的资产发起发行申请；运营管理人员查看全平台的企业、资产和企业数币账户，用于审核核对，并在这里看到上游撤销确权、删除资产的提示；监管机构只查看本机构申请所关联的资产。

基本原则：

- 只有下游企业确权后的应收账款才会进入本平台，才可发起发行（BR-02）【确认】。资产、企业、个人、账款和回款信息全部来自上游平台，本平台任何角色都不能新增、修改或删除。
- 资产信息分两级：L1 通用必传字段对所有行业统一，不随行业区分，面向国际企业，不以某一国家的登记号码为准；L2 补充字段也抽象为各行业通用的字段，由行业大类说明在该行业的具体含义，本期只有汽车贸易【确认】。
- 本模块只定义资产本身的状态：确权状态、结清状态、逾期状态、发行状态，每个字段只回答一个问题。代币铸造之后的监管、融资和销毁属于代币，由我的代币与销毁申请等模块定义，本模块不定义【确认】。
- 只有未到期、债权人已确权的资产才能发起发行；一笔资产只能发起一次发行申请，申请处理中、被驳回或已发行后都不能再次发起（BR-08、BR-12）【确认】。
- 平台支持中文和英文；上游提供的日期与时间带时区，按用户当前所选时区换算后展示【确认】。

**一个完整的例子。** 企业 A（注册在香港）向下游企业 B（注册在阿联酋）销售一批新车，并向车辆厂商采购；车辆海运到达 B 指定的仓库后，B 提供发票，A 据此生成一笔 50,000 USD、到期日为 2027-03-31 的应收账款。B 在上游平台确权后，这笔应收账款同步到本平台。A 用登录地址登录面客端，界面语言选英文、时区选 UTC+8，在可信资产中看到这笔资产：确权状态“已确权”，结清状态“未结清”，逾期状态“未逾期”，发行状态“可发行”；详情里有基本信息、贸易订单（车辆品牌、型号、VIN 与提单号）、采购订单、销售发票、回款进度和材料，日期按 UTC+8 展示。A 从这笔资产发起发行申请，提交成功后发行状态变为“发行申请中”。监管机构 C 审核时可以查看这笔资产；运营二审前核对 A 的企业信息、这笔资产的发票与回款情况和 A 的数币账户。铸造成功后，发行状态变为“已发行”，资产详情可以进入这枚代币查看它的后续状态。之后 B 分两次回款，每次回款都带支付凭证；全部回款后结清状态变为“已结清”。A 回到可信资产，能看到这笔资产的完整回款经过，以及关联的发行申请和代币。

### 1.2 本期不做

- 应收账款以外的资产类型。
- 汽车贸易以外的行业大类：行业大类字段已具备，但本期只有汽车贸易【确认】。
- 在本平台录入、修改、删除或补传资产、企业、个人、账款和回款信息。
- 非美元计价的应收账款发起发行：可以查看，不能发起【建议·已采纳】。
- 上游撤销确权、删除资产后的系统处理：只在运营端提示，不自动改变任何状态【确认】。
- 代币的监管、融资与销毁状态：属于代币，由我的代币与销毁申请（M4a）、销毁审核与代币台账（M4b）定义【确认】。
- 企业维护数币账户、企业查看本企业的用户信息与企业信息：属于企业登录与企业账户模块。
- 界面语言与时区的选择和保存：由各端的登录与账户模块提供，本模块只按当前选择展示。
- 中文、英文以外的语言。
- 与上游平台对接的接口方式与同步频率：由研发确定。

<a id="F-AS-01"></a>
## 3. 资产进入本平台与信息结构（F-AS-01）

适用范围：本节是企业、运营、监管三类查看功能共用的资产来源与字段定义，其他章节引用此处，不重复定义。

### 3.1 资产来源

业务来源【确认】：下游企业向本企业下单购买新车 → 本企业向厂商采购，约定车辆海运直发下游企业指定的仓库 → 车辆到货后，下游企业提供发票，本企业据此生成对下游企业的应收账款 → 下游企业确权 → 已确权的应收账款同步到本平台 → 之后下游企业回款，每次回款对应支付凭证。

- 只有确权状态为“已确权”的应收账款进入本平台；未确权的应收账款不进入，任何角色在本平台都看不到。
- 资产归属上游平台记录的债权人企业；企业只能看到本企业作为债权人的资产。
- 资产信息以上游平台的最新信息为准，上游更新后本平台展示更新后的信息；可发行的资产按最新信息判断能否发起申请【确认】。
- 上游撤销确权或删除资产时，只在运营端提示，本平台不自动改变任何状态，见[上游变更提示](#upstream-change)【确认】。

<a id="field-levels"></a>
### 3.2 信息结构与分级

资产信息分为六组：应收账款基本信息，以及贸易订单、采购订单、账款信息、回款进度、材料【确认】。字段清单按本节执行【确认】。每个字段标明级别：

- **L1 通用必传**：对所有行业统一，不随行业区分；每笔资产都必须具备全部 L1 字段。企业身份用“注册国家 / 地区 + 企业登记标识”表示，不限定为某一国家的登记号码【确认】。
- **L2 通用补充**：各行业通用的字段，不是必传。行业大类说明它在该行业的具体含义，下表“汽车贸易”列给出本期的对应关系；新增行业大类时沿用同一组字段，只补充该行业的对应关系【确认】。
- **回款（上游）**：回款进度来自上游平台，随回款发生而增加；结清状态和逾期状态每笔资产都必须有。

以下六组信息对企业（本企业资产）、运营、监管机构（关联资产）都可见，标为“只入库”的字段对所有角色都不展示。

<a id="field-bill"></a>
#### 账款信息

账款信息分两类【确认】：

- **销售账款（本企业与下游企业）**：必须有。到货后下游企业提供发票，本企业据此生成应收账款；发票信息是 L1。之后每次回款的支付凭证列在[回款进度](#field-repayment)中。

<a id="F-AS-02"></a>
## 4. 资产状态（F-AS-02）

资产状态由下表四个独立字段组成，每个字段只回答一个问题，来源各自独立【确认】。发行与销毁相关模块（M3a、M3b、M4a、M4b）引用本节定义，不另行定义资产状态【确认】。代币铸造之后的监管、融资和销毁状态属于代币，不在本模块定义【确认】。

<a id="status-fields"></a>
### 4.1 状态字段一览

| 状态字段 | 回答的问题 | 取值 | 来源 |
| --- | --- | --- | --- |
| 确权状态 | 债权人的这笔应收账款是否已被债务人确权 | 已确权、已撤销确权 | 上游平台 |
| 结清状态 | 这笔应收账款是否已经结清 | 未结清、已结清 | 上游平台 |
| 逾期状态 | 这笔应收账款是否已经逾期 | 未逾期、已逾期 | 上游平台；到期兜底见[结清状态与逾期状态](#overdue) |
| 发行状态 | 这笔资产在本平台的发行走到了哪一步 | 可发行、发行申请中、已驳回、已发行 | 本平台，由发行模块的业务结果推动 |

- 四个状态对企业（本企业资产）、运营、监管机构（关联资产）都始终展示。
- 各状态取不到时，标明暂时无法获取，不按任何一个取值处理。
- “未到期”不是单独的字段，而是结清状态为“未结清”、逾期状态为“未逾期”，且尚未到达到期时点【确认】。

<a id="confirm-status"></a>
### 4.2 确权状态

- 资产进入本平台时为“已确权”。
- 上游撤销确权后变为“已撤销确权”，各角色看到的都是最新值；只有运营端另有[上游变更提示](#upstream-change)。
- 确权状态的变化不改变发行状态。

<a id="overdue"></a>
### 4.3 结清状态与逾期状态

- 结清状态和逾期状态都由上游平台提供【确认】。
- 是否到期以上游提供的、带时区的到期时点为准，与查看者所选的时区无关；所选时区只影响展示，见[语言与时区](#locale)【确认】。
- 到达到期时点时，本平台仍未取得上游的最新状态（结清状态仍为“未结清”、逾期状态仍为“未逾期”）的，自动把逾期状态变为“已逾期”；之后上游提供新的状态时，以上游为准【确认】。
- 结清状态变为“已结清”后不再变化。
- 先逾期后结清的资产，逾期状态保留“已逾期”，结清状态为“已结清”，如实反映回款经过。
- 结清、逾期状态与发行状态互不推动。

<a id="issue-status"></a>
### 4.4 发行状态

- 资产进入本平台时为“可发行”，之后只按下表向前变化，不回退。“已驳回”和“已发行”是终态。
- 发行申请处于待监管审核、待运营审核、铸造中、铸造失败待重试时，发行状态都为“发行申请中”。
- 代币铸造成功后，发行状态为“已发行”，之后不再变化；代币的监管、融资、销毁等状态在代币中查看，不改变发行状态。

| 发行状态 | 含义 | 由什么结果进入 | 企业看到的说明与去向 |
| --- | --- | --- | --- |
| 可发行 | 资产已进入本平台，尚未发起发行申请 | 已确权的应收账款同步到本平台 | 满足[发起条件](#issue-conditions)时可以发起发行申请；不满足时说明原因 |
| 发行申请中 | 已提交发行申请，正在审核或铸造 | 企业在代币发行·企业申请（M3a）中提交申请成功 | 已有发行申请正在处理，可以查看这笔申请的进度 |
| 已驳回 | 发行申请被驳回，申请终止，这笔资产不能再次发起（BR-12） | 在代币发行·审核与铸造（M3b）中，监管一审驳回或运营二审驳回 | 发行申请已被驳回、不能再次发起，可以查看这笔申请及驳回意见 |
| 已发行 | 代币已铸造成功，这笔资产不能再次发起（BR-08） | 在代币发行·审核与铸造（M3b）中铸造成功 | 已发行代币，可以进入这枚代币查看它的后续状态 |

<a id="common-errors"></a>
## 5. 共用规则：访问限制、数据异常、语言与时区

以下规则适用于本模块的所有查看功能，各功能章节直接引用，不重复展开。

<a id="no-access"></a>
### 5.1 无权查看

- 各角色只能查看自己范围内的资产和企业：已认证的企业用户只看本企业资产；监管机构只看关联资产；只有运营能查看企业列表、企业信息、企业用户信息和数币账户。
- 访问范围以外的资产或企业（包括通过直接链接访问）时，不返回任何资产或企业信息，统一说明“无权查看或资产不存在”，不区分资产是否存在。
- 游客按[游客引导与功能限制（C-GUEST-01）](./v1.0-企业登录与企业账户-PRD.md#C-GUEST-01)处理，看不到可信资产；未认证的企业用户按[认证资格与受限引导（C-AUTH-04）](./v1.0-企业登录与企业账户-PRD.md#C-AUTH-04)处理，看得到入口，看不到任何资产数据。

<a id="missing-data"></a>
### 5.2 上游信息缺失

- L1 字段任一项缺失时（包括没有销售发票），资产仍然可以查看，缺失项标明上游未提供；这笔资产不能发起申请，原因说明为资产信息不完整。
- L2 字段、回款记录中的单项缺失时，标明未提供，不影响查看和发起申请。
- 采购账款整组没有时，说明无采购账款信息，不视为缺失。
- 状态取不到时按[状态字段一览](#status-fields)的规则标明暂时无法获取。

### 5.3 上游平台暂时不可用

- 各角色仍然看到本平台最近一次保存的资产、账款、回款、企业信息和状态。
- 恢复后展示更新后的信息。

### 5.4 材料无法打开

- 材料查看或下载失败时，说明本次未能打开，可以重试；不影响查看其他信息。

<a id="locale"></a>
### 5.5 语言与时区

- 平台支持中文和英文【确认】。本模块的字段名称、状态取值、说明文字都有中英文两套，按用户当前的界面语言展示；切换界面语言后随之切换。
- 上游提供的业务内容（如企业名称、标的物名称、地址）按上游原文展示，不翻译；上游同时提供中文和英文值的（如企业名称与英文名称），按企业登录与企业账户模块的口径分别展示。
- 金额、数量、编号等事实值不随界面语言变化。
- 上游提供的日期与时间都带时区，本平台按用户当前所选的时区换算后展示【确认】；切换时区只改变展示，不改变到期、逾期等判断。
- 界面语言和时区的选择与保存由各端的登录与账户模块提供（面客端为企业登录与企业账户，管理端为管理端账号、权限与监管机构管理）；本模块只按当前选择展示。

对应功能标识：C-ASSET（可信资产）。

适用角色与前提：已认证的企业用户。游客、未认证的企业用户和越权访问按[无权查看](#no-access)处理。

### 6.1 资产列表

- 列出本企业作为债权人、已进入本平台的全部资产，包括已驳回和已发行的资产。
- 每笔资产展示：上游资产编号、债务人名称、应收账款金额与币种、到期日、确权状态、结清状态、逾期状态、发行状态，以及能否发起申请。
- 本企业还没有任何资产时，说明资产由上游平台确权后同步到本平台，本平台不能录入资产。

### 6.2 资产详情

- 已发起过发行申请的资产，展示关联的发行申请（申请编号、申请状态），可以进入代币发行·企业申请模块查看这笔申请。
- 发行状态为“已发行”的资产，展示关联的代币，可以进入我的代币与销毁申请模块查看这枚代币及其状态。

<a id="F-AS-04"></a>
## 7. 从可信资产发起发行申请（F-AS-04）

对应功能标识：C-ASSET（从可发行资产发起申请，入口衔接 M3a）。

适用角色与前提：已认证的企业用户，针对本企业的资产。

<a id="issue-conditions"></a>
### 7.1 发起条件

同时满足以下全部条件，资产才可以发起申请：

1. 发行状态为“可发行”（BR-08、BR-12）【确认】。
2. 确权状态为“已确权”；可发起的资产须明确展示“债权人已确权”，这个状态值由上游提供【确认】。
3. 未到期：结清状态为“未结清”，逾期状态为“未逾期”，且尚未到达到期时点【确认】。
4. 币种为 USD（简报 Q25）【建议·已采纳】。
5. L1 信息完整（包括销售发票），见[上游信息缺失](#missing-data)。
6. 确权、结清、逾期状态都已取得，没有“暂时无法获取”的状态。

### 7.2 发起与结果

- 满足条件时，企业可以从资产列表或资产详情发起发行申请，进入代币发行·企业申请流程，并带入这笔资产。选择监管机构、选择接收代币的数币账户、确认与提交，都按代币发行·企业申请模块执行。
- 企业进入申请流程后未提交就离开时，资产保持“可发行”。
- 申请提交成功后，发行状态变为“发行申请中”，不能再次发起。
- 不满足条件时，不提供发起入口，并说明全部不满足的原因：已有申请处理中、申请已被驳回、已发行、债权人确权已撤销、资产已逾期、资产已结清、已到达到期时点、仅支持美元计价的资产、资产信息不完整、暂时无法确认资产状态。

### 7.3 重复发起与条件变化

- 同一笔资产在任何时候最多只有一笔发行申请。
- 申请提交时按当时的最新信息重新判断发起条件；不满足时（例如同一企业在另一处已提交了这笔资产的申请，或上游状态已变化）不能提交，说明原因，资产不会产生第二笔申请。

## 8. 运营查看企业与资产（F-AS-05）

对应功能标识：A-ASSET（可信资产 / 企业查看）【建议·已采纳】。

适用角色与前提：已登录管理端的运营管理人员（管理员）。本功能全部只读：运营不能修改任何信息，也不能代企业发起申请。

### 8.1 企业列表

- 列出上游平台同步到本平台的企业【确认】。
- 每个企业展示：企业名称、注册国家 / 地区、企业登记标识、登录地址、当前有效认证结论、已进入本平台的资产笔数。
- 可以按企业名称或企业登记标识查找企业。

### 8.2 企业详情

- 展示[企业信息与企业用户信息](#field-enterprise)。
- 展示该企业当前的全部[数币账户](#field-account)，登录地址这一条标明“登录地址”；企业已删除的账户不展示。
- 展示该企业的资产列表，内容同[全平台资产列表](#F-AS-05-assets)，可以进入资产详情。

<a id="F-AS-05-assets"></a>
### 8.3 全平台资产列表与资产详情

- 资产列表列出全平台已进入本平台的资产。每笔资产展示：上游资产编号、债权人名称、债务人名称、应收账款金额与币种、到期日、确权状态、结清状态、逾期状态、发行状态，以及[上游变更提示](#upstream-change)。
- 可以按上游资产编号或债权人名称查找资产。
- 资产详情展示[信息结构与分级](#field-levels)中六组信息里标为展示的全部字段、[资产状态](#status-fields)的四个字段，以及上游变更提示；材料可以查看和下载。
- 已发起过发行申请的资产，展示关联的发行申请（申请编号、申请状态、所选监管机构），可以进入代币发行·审核与铸造模块查看申请详情。
- 发行状态为“已发行”的资产，展示关联的代币，可以进入代币台账查看。
- 资产详情可以进入债权人企业的企业详情。
- 信息缺失按[上游信息缺失](#missing-data)处理；语言与时间按[语言与时区](#locale)展示。

<a id="upstream-change"></a>
### 8.4 上游变更提示

- 上游撤销确权时，运营端在这笔资产的列表项和详情中标明“上游已撤销确权”【确认】。
- 上游删除资产时，本平台保留最近一次保存的信息，运营端在列表项和详情中标明“上游已删除”【确认】。
- 这两类提示只在运营端出现，企业端和监管端不出现提示【确认】。
- 本平台不做系统处理：不自动改变发行状态，不终止发行申请，不影响已发行的代币；是否驳回申请等由运营在相应业务中人工处理【确认】。
- 可发行的资产被撤销确权后，按最新信息不满足[发起条件](#issue-conditions)，企业不能再发起。

## 9. 监管机构查看关联资产（F-AS-06）

对应功能标识：A-ASSET 中“监管机构仅查看本机构申请关联的资产”（简报 4.4 权限矩阵）。

适用角色与前提：已登录管理端的监管机构。监管机构只能看到本机构的申请和代币（BR-15）【确认】。

- 查看范围是关联资产：选择了本机构的发行申请所使用的资产，无论这笔申请处于什么状态，包括被本机构驳回、被运营驳回的申请。
- 一笔资产最多只有一笔发行申请，所以一笔关联资产只对应本机构的一笔申请。
- 关联资产列表展示：上游资产编号、债权人名称、债务人名称、应收账款金额与币种、到期日、确权状态、结清状态、逾期状态、发行状态。
- 资产详情展示[信息结构与分级](#field-levels)中六组信息里标为展示的全部字段，以及[资产状态](#status-fields)的四个字段；材料可以查看和下载。
- 资产详情展示本机构关联的这笔发行申请（申请编号、申请状态），可以进入代币发行·审核与铸造模块查看。
- 监管机构看不到企业列表、企业详情、企业用户信息、数币账户和上游变更提示；债权人只通过基本信息中的债权人名称、注册国家 / 地区和企业登记标识呈现。
- 访问非关联资产按[无权查看](#no-access)处理；信息缺失按[上游信息缺失](#missing-data)处理；语言与时间按[语言与时区](#locale)展示。

## 10. 待确认事项与依赖

本模块当前没有待确认事项。

依赖：

- 上游平台 · 可信资产（D2）：提供应收账款的基本信息、贸易订单、采购订单、账款信息和材料，以及确权状态；日期与时间带时区。
- 上游平台 · 回款与结清（D3）：提供回款进度（含支付凭证）、结清状态和逾期状态；结清状态也是代币销毁的前置条件。
- 上游平台 · 用户匹配（D1）：提供企业信息和企业用户信息，供运营查看。
- 企业登录与企业账户（M1）：已认证、未认证与游客的判断；企业信息、用户信息和数币账户的字段定义；面客端界面语言与时区的选择。
- 管理端账号、权限与监管机构管理（M5）：管理端界面语言与时区的选择。
- 代币发行·企业申请（M3a）：从资产发起后的申请流程；提交成功推动发行状态变为“发行申请中”。
- 代币发行·审核与铸造（M3b）：驳回、铸造成功推动发行状态；申请详情。
- 我的代币与销毁申请（M4a）、销毁审核、解除质押与代币台账（M4b）：代币的监管、融资、销毁等状态与查看。
- 与上游的数据同步时效没有已确认的指标，本册不设时效要求；对接方式与时效由研发确定。
