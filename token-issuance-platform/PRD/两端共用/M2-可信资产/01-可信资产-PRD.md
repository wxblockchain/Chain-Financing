## 1. 模块是什么

可信资产模块把资产可信平台（下称上游平台）已确权的应收账款展示在本平台，作为企业发起代币发行的唯一资产来源。企业在这里筛选、查看本企业的应收账款：核心信息是这笔应收账款与债务人之间的交易和回款，补充信息是本企业与上游供应商之间的交易，以及债务人与其下游客户之间的交易，以及每笔资产的确权、回款和发行状态，并从满足条件的资产发起发行申请；运营管理人员查看全平台的企业、资产和企业数币账户，用于业务核对；机构（资产托管机构、审计机构、法律服务机构）只读查看与本机构建立关联的资产。

基本原则：

- 只有行业大类为“汽车贸易”、且下游企业已确权的应收账款才会进入本平台，才可发起发行（BR-02）【确认】。本平台取得上游资产时逐笔判断；汽车贸易以外的资产逐笔拒绝，不进入本平台，不影响同批其他合格资产。资产、企业、个人、账款和回款信息全部来自上游平台，本平台任何角色都不能新增、修改或删除；上游数据由推送还是由本平台主动获取，属于开发实现选择，本 PRD 不限定。
- 资产信息按交易双方分为核心信息与补充信息，材料随所属环节展示【确认】。字段分两级：L1 通用必传字段对所有行业统一，不随行业区分，面向国际企业，不以某一国家的登记号码为准；L2 补充字段也抽象为各行业通用的字段，由行业大类说明在该行业的具体含义，本期只有汽车贸易【确认】。
- 本模块展示资产本身的确权状态、回款状态、发行状态。回款状态归并上游结清、逾期信息，表达当前为未到期、已逾期或已结清；上游原始事实仍用于业务校验与回款经过核对。发行模块内部的机构分配、处理、驳回和发行执行流程不属于本模块；本模块只消费其返回的申请状态、机构关联结果与最终发行结果。发行成功后的资产托管、融资和销毁属于代币，由我的代币与销毁申请等模块定义，本模块不定义【确认】。
- 只有未到期且债权人已确权的资产才能发起发行；累计已回款、未回款余额、原始资产价值或结清状态之间存在金额关系异常时，仍按上游原值正常展示，不作为发起条件或提交校验，仅向运营管理人员提示。同一笔资产同一时间最多只有一笔处理中的发行申请，最多发行成功一次；申请处理中或已发行时不能再次发起（BR-08）。申请被运营驳回后，资产回到“可发行”，满足发起条件时企业可用这笔资产发起新的申请【确认】。
- 资产确权后，原始资产价值、到期日等资产信息不再变化；回款记录、结清和逾期状态仍会随上游变化【确认】。
- 平台支持中文和英文；上游提供的日期与时间带时区，按用户当前所选时区换算后展示；到期时点换算展示时同时展示日期、时间和时区【确认】。

**一个完整的例子。** 企业 A（注册在香港）向下游企业 B（注册在阿联酋）销售一批新车，并向车辆厂商采购；车辆海运到达 B 指定的仓库后，B 提供发票，A 据此生成一笔 50,000 USD、到期日为 2027-03-31（来源时区 Asia/Dubai）的应收账款。B 在上游平台确权后，本平台取得这笔应收账款。A 用登录地址登录面客端，界面语言选英文、时区选 Asia/Shanghai，在可信资产中按债务人名称和回款状态“未到期”找到这笔资产：列表中回款状态为“未到期”，发行状态为“可发行”；详情中确权状态为“已确权”，核心信息依次是 A 与 B 的应收账款与交易双方、销售订单（车辆品牌、型号、VIN）、货物交付（提单号与到货凭证）、销售发票和回款进度；补充信息包括 A 向厂商的采购合同、厂商发货记录、采购发票和付款记录，以及 B 与其下游客户之间的交易；各项材料在所属环节查看，日期按 Asia/Shanghai 换算展示，到期时点（Asia/Dubai 时间 2027-03-31 24:00）显示为 2027-04-01 04:00 Asia/Shanghai。A 通过这笔资产的“申请发行”入口进入后续申请功能；提交成功后，本模块按发行模块返回的结果把发行状态展示为“发行申请中”。运营在发行模块为这笔申请分配机构 C 后，机构 C 可以只读查看这笔关联资产；运营可以在可信资产中核对 A 的企业信息、资产、回款和数币账户。本模块不定义机构分配、处理、驳回或发行执行过程。发行模块返回“已发行”和代币编号后，本模块把发行状态展示为“已发行”，A 可以从资产详情进入这枚代币的代币详情。之后 B 分两次回款，每次回款都带支付凭证；全部回款后回款状态变为“已结清”。A 回到可信资产，能看到这笔资产的完整回款经过，以及关联的发行申请和代币。

## 3. 资产进入本平台与信息结构（F-AS-01）

适用范围：本节是企业、运营、机构三类查看功能共用的资产来源与字段定义，其他章节引用此处，不重复定义。

### 3.1 资产来源

业务来源【确认】：下游企业向本企业下单购买新车 → 本企业向厂商采购，约定车辆海运直发下游企业指定的仓库，厂商发货时单独提供发货记录 → 车辆到货后，下游企业提供发票，本企业据此生成对下游企业的应收账款 → 下游企业确权 → 本平台取得已确权的应收账款 → 之后下游企业回款，每次回款对应支付凭证。

- 本平台取得上游资产时逐笔判断。只有行业大类为“汽车贸易”、且确权状态为“已确权”的应收账款进入本平台；汽车贸易以外的资产逐笔拒绝，不影响同批其他合格资产；未确权的应收账款不进入。这两类资产在本平台任何角色的列表和详情中都看不到。上游以推送还是由本平台主动获取数据，不影响本规则，本 PRD 不限定具体获取方式。
- 资产归属上游平台记录的债权人企业；企业只能看到本企业作为债权人的资产。
- 资产确权后，原始资产价值、到期日等资产信息不再变化；回款记录、结清状态和逾期状态随上游更新，本平台展示更新后的信息；可发行的资产按最新的回款与状态信息判断能否发起申请【确认】。
- 进入本平台的资产始终为“已确权”，也始终可以查看：上游不存在撤销确权或删除资产的情况【确认】。

<a id="field-levels"></a>
### 3.2 信息结构与分级

资产信息按交易双方分为两类【确认】：

- **核心信息**：本企业与这笔应收账款的债务人之间的交易，即这笔应收账款本身。按环节分为应收账款与交易双方、销售合同 / 订单、货物交付、销售发票、回款进度。
- **补充信息**：本企业与上游供应商之间的交易，用于佐证本企业的贸易背景；以及债务人与其下游客户之间的交易，用于了解债务人下游客户的经济情况。补充信息全部是 L2，可以缺失，不影响发起申请【确认】。
- 材料（文件）随所属环节展示，不单独成组；所有材料都可以查看和下载【确认】。

每个字段标明级别：

- **L1 通用必传**：对所有行业统一，不随行业区分；每笔资产都必须具备全部 L1 字段。企业身份用“注册国家 / 地区 + 企业登记标识”表示，不限定为某一国家的登记号码【确认】。
- **L2 通用补充**：各行业通用的字段，不是必传。行业大类说明它在该行业的具体含义，下表“汽车贸易”列给出本期的对应关系；新增行业大类时沿用同一组字段，只补充该行业的对应关系【确认】。
- **回款（上游）**：本笔应收账款的回款进度来自上游平台，随回款发生而增加；结清状态和逾期状态每笔资产都必须有。

“核心”表示与这笔应收账款直接相关，不等于必传：核心信息中既有 L1 字段，也有 L2 字段。核心信息与补充信息对企业（本企业资产）、运营、机构（关联资产）都可见，标为“只入库”的字段对所有角色都不展示。

<a id="F-AS-02"></a>
## 4. 资产状态（F-AS-02）

资产统一展示确权、回款、发行三个状态；回款状态合并表达原结清、逾期两项的当前结果。结清、逾期的上游来源、到期判断和发起校验依据仍按本节定义。发行状态只反映发行模块返回给可信资产的申请结果，本模块不定义发行模块内部的机构分配、处理、驳回或发行执行流程。发行成功后的资产托管、融资和销毁状态属于代币，不在本模块定义【确认】。

<a id="status-fields"></a>
### 4.1 状态字段一览

| 状态字段 | 回答的问题 | 取值 | 来源 |
| --- | --- | --- | --- |
| 确权状态 | 债权人的这笔应收账款是否已被债务人确权 | 已确权（进入本平台的资产始终为此值） | 上游平台 |
| 回款状态 | 这笔应收账款当前是否已结清，未结清时是否已逾期 | 未到期、已逾期、已结清 | 本平台根据上游结清、逾期信息与到期时点归并，见[回款状态归并](#repayment-status) |
| 发行状态 | 这笔资产在本平台的发行走到了哪一步 | 可发行、发行申请中、已发行 | 本平台，由发行模块的业务结果推动 |

- 资产详情对企业（本企业资产）、运营、机构（关联资产）始终展示三个状态。
- 资产列表只展示回款状态和发行状态，不展示确权状态：进入本平台的资产都已确权，确权状态在详情查看【确认】。
- 发行状态取不到时，标明暂时无法获取，不按任何一个取值处理。
- 回款状态按[回款状态归并](#repayment-status)确定；无法确定时说明暂时无法确认，作为异常结果单独展示和筛选，不归入三个正常取值。
- 回款状态不等同于能否发行；只有“未到期”才可能满足发起条件，还需满足[发起条件](#issue-conditions)中的全部其他要求。

<a id="confirm-status"></a>
### 4.2 确权状态

- 资产进入本平台时为“已确权”，之后不再变化【确认】。
- 确权状态只作展示，不作为单独的发起判断；可发起的资产仍明确展示“债权人已确权”，见[发起条件](#issue-conditions)。

<a id="overdue"></a>
### 4.3 结清与逾期依据

<a id="due-time"></a>
#### 到期时点

- 到期时点是来源时区下到期日的结束时刻，即到期日当天 24:00【确认】。例如到期日为 2027-03-31、来源时区为 Asia/Dubai，到期时点为 Asia/Dubai 时间 2027-03-31 24:00。
- 到期时点是唯一的到期业务值：本模块的到期判断与发起条件使用这一时点，其他模块引用的也是同一业务值；与查看者所选的时区无关，所选时区只影响展示，见[语言与时区](#locale)。
- 按查看者所选时区换算展示时，同时展示日期、时间和时区，避免把换算后错开一天的日期误读为不一致【确认】。例如上例在 Asia/Shanghai 下展示为 2027-04-01 04:00 Asia/Shanghai。资产详情可以核对上游原始到期日与来源时区。
- 到期日或来源时区缺失、无法确定到期时点时，按[上游信息缺失](#missing-data)处理，回款状态为暂时无法确认。

#### 结清与逾期

- 结清状态和逾期状态都由上游平台提供【确认】。
- 已过到期时点、本平台仍未收到已结清（上游没有推送，或本平台没有收到已结清通知），即判为“已逾期”；之后收到已结清，回款状态为“已结清”【确认】。
- 结清状态变为“已结清”后不再变化。
- 先逾期后结清的资产，结清状态为“已结清”，回款进度中保留曾逾期的事实，如实反映回款经过。“曾逾期”指上游逾期记录为“已逾期”，或结清前本平台已判为“已逾期”。
- 结清、逾期状态与发行状态互不推动。

<a id="repayment-status"></a>
#### 回款状态归并

列表与详情使用同一归并结果；按下表从上到下判断，取第一条符合的结果，已结清优先。

| 结清依据 | 逾期与到期依据 | 回款状态 | 详情的回款进度 |
| --- | --- | --- | --- |
| 已结清 | 曾逾期：上游逾期记录为已逾期，或结清前本平台已判为已逾期 | 已结清 | 展示结清日期、回款记录，并说明曾逾期；不同时展示两个当前回款状态 |
| 已结清 | 未曾逾期，或逾期记录暂时取不到 | 已结清 | 展示结清日期、回款记录；逾期记录取不到时说明该记录暂时无法获取，不推断从未逾期 |
| 未收到已结清（未结清或结清状态取不到） | 已到达到期时点 | 已逾期 | 展示未回款余额及已有回款记录 |
| 未结清 | 上游提供已逾期 | 已逾期 | 展示未回款余额及已有回款记录 |
| 未结清 | 上游提供未逾期，且尚未到达到期时点 | 未到期 | 展示未回款余额及已有回款记录 |
| 未结清 | 上游提供未逾期，但到期时点无法确定 | 暂时无法确认 | 标明到期时点无法确定，保留已取得的回款信息 |
| 结清状态取不到，或未结清但逾期状态取不到 | 尚未到达到期时点，或到期时点无法确定 | 暂时无法确认 | 标明无法获取的依据，保留已取得的回款信息 |

- 到达到期时点即属于到期，不顺延至次日；上游没有推送最新状态或暂时不可用，都不影响按到期时点判为“已逾期”。
- 上游提供已结清后，当前回款状态为“已结清”，不因曾逾期或查看时点超过到期时点而回到“已逾期”。
- 先逾期后结清的资产筛选归入“已结清”；曾逾期的事实保留在回款进度中，不计入当前“已逾期”的筛选结果。
- 回款状态暂时无法确认时，不能发起申请；不将未知状态归为“未到期”，也不按回款金额或余额自行认定结清。
- 结清、逾期原始信息继续保留供依赖方使用；归并展示不改变发行状态、确权状态或上游事实。
- 累计已回款、未回款余额、原始资产价值和结清状态均按上游原值展示。本平台不依据这些金额之间是否一致改写任一数值或自行认定结清，也不把金额关系异常作为发起条件、提交校验或状态变化依据。
- 上述金额或状态之间出现异常关系时，只按[运营端金额关系预警](#amount-warning)向运营管理人员提示；企业和机构看到正常业务字段，不看到该预警。

<a id="issue-status"></a>
### 4.4 发行状态

- 资产进入本平台时为“可发行”，之后按下表变化。“已发行”是终态。
- 申请提交成功后，只要发行模块尚未返回“已驳回”或“已发行”的最终结果，资产发行状态都为“发行申请中”。
- 发行模块返回“已驳回”后，资产发行状态回到“可发行”【确认】；被驳回的申请及其驳回结果仍可查看，满足[发起条件](#issue-conditions)时可以用这笔资产发起新的申请。
- 发行模块返回“已发行”后，资产发行状态为“已发行”，之后不再变化；代币的资产托管、融资、销毁等状态在代币中查看，不改变发行状态。
- 本模块不定义由谁分配机构、处理、驳回或执行发行。资产详情中的申请状态按查看者身份只读展示【确认】：企业看到代币发行 · 企业申请（M3a）的[企业可见状态](../../面客端/M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#status)；运营和机构看到代币发行 · 审核与铸造（M3b）的[申请状态](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#status)。已关联机构按 M3b 的[机构关联结果](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#institution-link)只读展示给运营。

| 发行状态 | 含义 | 由什么结果进入 | 企业看到的说明与去向 |
| --- | --- | --- | --- |
| 可发行 | 资产已进入本平台，当前没有处理中的发行申请，也未发行；可能从未申请，或最近一笔申请已被驳回 | 本平台取得已确权的应收账款；或发行模块返回“已驳回”结果 | 满足[发起条件](#issue-conditions)时可以发起发行申请；不满足时说明原因；最近一笔申请被驳回时，同时说明该申请已被驳回并可查看驳回结果 |
| 发行申请中 | 已提交发行申请，发行模块尚未返回最终结果 | 发行模块返回“申请已提交”或“处理中”结果 | 已有发行申请正在处理，可以查看这笔申请的当前状态 |
| 已发行 | 发行模块返回发行成功，这笔资产不能再次发起（BR-08） | 发行模块返回“已发行”结果与代币编号 | 已发行代币，展示代币编号，点击代币编号进入这枚代币的代币详情查看它的后续状态 |

<a id="common-errors"></a>
## 5. 共用规则：访问限制、数据异常、语言与时区

以下规则适用于本模块的所有查看功能，各功能章节直接引用，不重复展开。

<a id="no-access"></a>
### 5.1 无权查看

- 各角色只能查看自己范围内的资产和企业：已认证的企业用户只看本企业资产；机构只看关联资产；只有运营能查看企业列表、企业信息、企业用户信息和数币账户。
- 访问范围以外的资产或企业（包括通过直接链接访问）时，不返回任何资产或企业信息，统一说明“无权查看或资产不存在”，不区分资产是否存在。
- 游客按[游客引导与功能限制（C-GUEST-01）](../../面客端/M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-GUEST-01)处理，看不到可信资产；未认证的企业用户按[认证资格与受限引导（C-AUTH-04）](../../面客端/M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-AUTH-04)处理，看得到入口，看不到任何资产数据。

<a id="missing-data"></a>
### 5.2 上游信息缺失

- L1 字段任一项缺失时（包括没有销售发票），资产仍然可以查看，缺失项标明上游未提供；这笔资产不能发起申请，原因说明为资产信息不完整。
- L2 字段、回款记录中的单项缺失时，标明未提供，不影响查看和发起申请。
- 补充信息中某个环节整组没有（例如没有采购发票、没有付款记录、没有债务人下游客户交易）时，说明暂无该项信息，不视为缺失，见[补充信息](#field-supplement)。
- 状态取不到时按[状态字段一览](#status-fields)的规则标明暂时无法获取。

### 5.3 上游平台暂时不可用

- 各角色仍然看到本平台最近一次保存的资产、账款、回款、企业信息和状态。
- 到达到期时点仍未收到已结清的，按[结清与逾期依据](#overdue)判为“已逾期”；不能因上游暂时不可用而继续显示已过期的“未到期”。
- 恢复后展示更新后的信息。

### 5.4 材料无法打开

- 材料查看或下载失败时，说明本次未能打开，可以重试；不影响查看其他信息。

<a id="locale"></a>
### 5.5 语言与时区

- 平台支持中文和英文【确认】。本模块的字段名称、状态取值、说明文字都有中英文两套，按用户当前的界面语言展示；切换界面语言后随之切换。
- 所有上游业务内容（如企业名称、企业英文名称、标的物名称、地址）均按上游原值展示，不翻译、不替换，也不随界面语言切换；此规则同样适用于其他上游字段。
- “企业名称”和“企业英文名称”是两个独立字段。上游提供哪个字段就按原值展示哪个字段；同时提供时两个字段都展示，切换中文或英文界面都不改变字段值，也不以其中一个字段替代另一个字段。字段标题仍按界面语言切换。
- 金额、数量、编号等事实值不随界面语言变化；完整值不因语言或展示精度变化。
- <a id="amount-display"></a>两位小数截断展示【确认】：本平台金额（含原始资产价值）、代币数量和资产价值（定义见我的代币与销毁申请（M4a）的[术语](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#2-术语)）的普通展示共用本条，各模块引用，不另行定义。
  - 超过两位小数时，主显示直接截断至两位，不四舍五入。
  - 只有确实截断时，在数值旁提供图标；点击图标查看完整值。图标本身即为截断提示，不另加“已截断”等文字说明。
  - 不超过两位小数时按原值展示，不出现图标。
  - 计算、筛选、校验、确认、签名和上链都使用完整值，不使用截断后的值。
  - 代币单位价值不适用本条，按完整值展示，见代币发行 · 审核与铸造（M3b）的[代币单位价值展示](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#unit-value-display)。
- 上游提供的日期与时间都带时区，本平台按用户当前所选的时区换算后展示【确认】；到期时点换算展示时同时展示日期、时间和时区，见[到期时点](#due-time)【确认】。切换时区只改变展示，不改变来源时区、到期时点、到期与逾期判断，也不改变后续发行申请签名和上链使用的到期业务值。
- 界面语言和时区的选择与保存由各端的登录与账户模块提供：面客端见[偏好设置：界面语言与时区（C-PROFILE-02）](../../面客端/M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-PROFILE-02)，管理端的语言与时区见[界面语言与时区（F-LG-09）](../../管理端/M5-管理端登录与权限/01-管理端登录与权限-PRD.md#F-LG-09)；本模块只按当前选择展示。

### 5.6 资产列表的核心筛选

适用于企业资产列表、运营全平台资产列表、运营企业详情中的资产列表、机构关联资产列表；筛选始终在各角色原有可见范围内进行，不改变权限或资产归属。运营企业列表继续使用[企业查找](#enterprise-search)规则。

全部条件均为选填，初始为空或全部；文本输入去掉首尾空白，只有空白时按未填处理。筛选信息如下：

| 筛选信息 | 类型、取值与匹配规则 | 适用范围 |
| --- | --- | --- |
| 资产编号 | 文本，按完整编号精确匹配，不区分英文字母大小写 | 全部资产列表 |
| 债务人名称 | 文本，按名称包含输入内容匹配；不区分英文字母大小写 | 全部资产列表 |
| 债权人名称 | 文本，按名称包含输入内容匹配；不区分英文字母大小写 | 运营全平台资产列表、机构关联资产列表；企业或已选企业的资产列表不重复筛选债权人 |
| 发行状态 | 单个状态：可发行、发行申请中、已发行；可以选择全部 | 全部资产列表 |
| 回款状态 | 单个结果：未到期、已逾期、已结清、暂时无法确认；可以选择全部，结果以[回款状态归并](#repayment-status)为准 | 全部资产列表 |
| 币种 | 单个币种，选项取当前有权查看的资产所使用的币种；可以选择全部 | 全部资产列表 |
| 到期时间范围 | 起始、结束日期与时间，可只填一端；按当前所选时区解释，包含起止时点，起始不得晚于结束 | 全部资产列表 |

- 名称筛选同时匹配上游实际提供的“企业名称”和“企业英文名称”两个独立字段，不受当前界面语言影响，也不翻译后再匹配。
- 多个条件同时填写时，返回全部条件均满足的资产；单个条件清除后，保留其余条件；重置后回到本列表原有可见范围内的全部资产。
- 到期范围无效时说明起始不得晚于结束，保留输入及最近一次有效结果，不返回无效条件的查询结果。
- 只选回款状态“未到期”或发行状态“可发行”，结果中仍可能有不能发起的资产；是否提供“申请发行”入口以[发起条件](#issue-conditions)为准。
- 无资产时按所在列表的空状态说明；有资产但没有匹配结果时说明无符合条件的资产，可以调整或清除筛选，不能误报为尚未取得资产。
- 筛选读取失败时说明本次未能取得筛选结果，保留已填条件，可以重试；不能显示为无匹配结果。
- 从筛选结果进入资产详情后返回该列表，保留已生效的条件；结果按最新可见数据及当前回款状态重新判断。
- 切换时区后，到期范围仍表示原来的两个时点，输入展示随时区换算；不改变筛选到的时间范围，回款状态也不因时区选择变化。
- 资产类型和行业大类本期都只有一种，不提供无区分作用的筛选；材料、订单明细及企业账户信息不纳入核心筛选。

- 读取失败时，说明本次未能取得结果，保留已填条件，可以修改条件或重试；不能显示为空列表或无匹配结果。

<a id="F-AS-03"></a>
## 6. 企业查看本企业可信资产（F-AS-03）

对应功能标识：C-ASSET（可信资产）。

适用角色与前提：已认证的企业用户。游客、未认证的企业用户和越权访问按[无权查看](#no-access)处理。

### 6.1 资产列表

- 列出本企业作为债权人、已进入本平台的全部资产，包括申请曾被驳回和已发行的资产。
- 每笔资产展示：资产编号、债务人名称、债务人英文名称、原始资产价值（带币种）、到期日、回款状态、发行状态；上游未提供债务人英文名称时不补写。发行状态只展示状态值，不能发起的原因在详情说明，列表不附加解释性信息【确认】。
- 按[资产列表的核心筛选](#asset-filters)查找资产；满足[发起条件](#issue-conditions)的资产提供“申请发行”入口【确认】；名称、详情入口与分页按[资产列表的名称、详情入口与分页](#asset-list-display)。
- 本企业还没有任何资产时，说明本平台仅展示从上游平台取得的已确权资产，本平台不能录入资产。

### 6.2 资产详情

- 展示[信息结构与分级](#field-levels)中核心信息与补充信息里标为展示的全部字段，以及[资产状态](#status-fields)的三个状态。
- 材料可以查看和下载。
- 已发起过发行申请的资产，展示这笔资产的全部发行申请，按提交时间由新到旧；每笔展示申请编号和企业可见的申请状态，取值按代币发行 · 企业申请（M3a）的[企业可见状态与进度](../../面客端/M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#status)，不展示管理端独有的申请状态；点击申请编号进入对应的申请详情。本模块不提供机构选择、分配、处理或驳回操作。
- 发行状态为“已发行”的资产，展示关联代币的代币编号；点击代币编号进入我的代币与销毁申请（M4a）中这枚代币的[代币详情（C-TOKEN-02）](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#C-TOKEN-02)，查看代币及其状态。
- 不能发起申请时，说明原因，见[发起条件](#issue-conditions)。
- 信息缺失按[上游信息缺失](#missing-data)处理；语言与时间按[语言与时区](#locale)展示。

## 7. 从可信资产发起发行申请（F-AS-04）

对应功能标识：C-ASSET（从可发行资产进入后续发行申请功能）。

适用角色与前提：已认证的企业用户，针对本企业的资产。

<a id="issue-conditions"></a>
### 7.1 发起条件

同时满足以下全部条件，资产才可以发起申请：

1. 发行状态为“可发行”（BR-08）【确认】；最近一笔申请被驳回的资产同样适用。
2. 回款状态为“未到期”：上游结清状态为“未结清”，逾期状态为“未逾期”，且尚未到达[到期时点](#due-time)；归并展示不放宽此条件。
3. 币种为 USD（简报 Q25）【建议·已采纳】。
4. L1 信息完整（包括销售发票），见[上游信息缺失](#missing-data)。
5. 结清、逾期状态依据都已取得，且按[回款状态归并](#repayment-status)能够得到明确状态，没有暂时无法确认的情况。累计已回款、未回款余额与原始资产价值之间的关系不属于本条件。

进入本平台的资产始终为“已确权”，确权不作为单独的判断；可发起的资产须明确展示“债权人已确权”，这个状态值由上游提供【确认】。

<a id="issue-start"></a>
### 7.2 发起与结果

- 满足条件时，企业可以从资产列表或资产详情的“申请发行”入口发起申请【确认】。系统带入并固定这笔资产，直接进入代币发行·企业申请的“填写申请信息”，不再经过选择资产；企业在本次流程中不能改选资产，需要申请另一笔资产时须返回可信资产，从目标资产重新发起【确认】。进入后的申请信息、确认与提交规则由代币发行·企业申请模块定义。
- 从“填写申请信息”返回时，回到本次发起所来自的资产列表或资产详情；未提交内容不保存，资产保持“可发行”。
- 企业进入申请流程后未提交就离开时，资产保持“可发行”。
- 申请提交成功后，发行状态变为“发行申请中”，不能再次发起。
- 最近一笔申请被驳回、资产回到“可发行”后，按本节同样的入口和条件发起新的申请；新申请如何办理见代币发行 · 企业申请（M3a）的[驳回后重新发起（C-ISSUE-09）](../../面客端/M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#C-ISSUE-09)。
- 不满足条件时，不提供“申请发行”入口，一次判断全部条件，在详情中说明全部不满足的原因：已有申请处理中、已发行、资产已逾期、资产已结清、仅支持美元计价的资产、资产信息不完整、暂时无法确认资产状态（回款状态暂时无法确认或发行状态暂时无法获取）。累计已回款、未回款余额与原始资产价值之间的关系不列为不能发起的原因。回款原因使用当前归并结果：已结清时说明已结清，曾逾期的事实在回款进度说明，不再把历史逾期同时列为当前阻断原因。

### 7.3 重复发起与条件变化

- 同一笔资产在任何时候最多只有一笔处理中的发行申请，最多发行成功一次；被驳回的申请不占用名额。
- 点击“申请发行”时按最新信息再次判断发起条件；已不满足时留在可信资产，按[发起与结果](#issue-start)一次说明全部原因，不进入申请填写，资产发行状态不变。
- 申请提交时按当时的最新信息重新判断发起条件；不满足时（例如同一企业在另一处已提交了这笔资产的申请，或回款状态已变化）不能提交，说明原因，资产不会同时产生两笔处理中的申请。

## 8. 运营查看企业与资产（F-AS-05）

对应功能标识：A-ASSET（可信资产 / 企业查看）【建议·已采纳】。

适用角色与前提：已登录管理端的运营管理人员（管理员）。本功能全部只读：运营不能修改任何信息，也不能代企业发起申请。

<a id="enterprise-search"></a>
### 8.1 企业列表

- 列出本平台从上游平台取得的企业【确认】。
- 每个企业展示：企业名称、企业英文名称、注册国家 / 地区、企业登记标识、登录地址、当前有效认证结论、已进入本平台的资产笔数；两个名称字段分别按上游原值展示，上游未提供的字段不补写。登录地址按[企业信息与企业用户信息](#field-enterprise)中的规则缩写展示，可以核对完整地址。
- 可以按企业名称或企业登记标识查找企业。
- 默认按本平台取得该企业的时间由新到旧排列【确认】；分页、返回位置、空状态与读取失败按[业务列表通用规则](#list-common)。

### 8.2 企业详情

- 展示[企业信息与企业用户信息](#field-enterprise)。
- 展示该企业当前唯一的[数币账户](#field-account)，标明“登录地址”；不展示其他地址或账户维护操作。
- 展示该企业的资产列表，内容同[全平台资产列表](#F-AS-05-assets)，可以进入资产详情；按[资产列表的核心筛选](#asset-filters)查找，范围固定为该企业，不重复提供债权人筛选。

<a id="F-AS-05-assets"></a>
### 8.3 全平台资产列表与资产详情

- 资产列表列出全平台已进入本平台的资产。每笔资产展示：资产编号、债权人名称、债权人英文名称、债务人名称、债务人英文名称、原始资产价值（带币种）、到期日、回款状态、发行状态；上游未提供的英文名称不补写。发行状态只展示状态值。除[运营端金额关系预警](#amount-warning)外，列表不附加解释性信息【确认】。
- 可以按[资产列表的核心筛选](#asset-filters)查找资产；名称、详情入口与分页按[资产列表的名称、详情入口与分页](#asset-list-display)。
- 资产详情展示[信息结构与分级](#field-levels)中核心信息与补充信息里标为展示的全部字段、[资产状态](#status-fields)的三个状态，以及[运营端金额关系预警](#amount-warning)（存在时）；材料可以查看和下载。
- 已发起过发行申请的资产，展示这笔资产的全部发行申请，按提交时间由新到旧；每笔展示申请编号、申请状态（按代币发行 · 审核与铸造（M3b）的[申请状态](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#status)），以及按[机构关联结果](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#institution-link)展示的已关联机构（有值时）；点击申请编号进入对应的申请详情。本模块只读展示这些结果，不提供机构分配、处理或驳回操作。
- 发行状态为“已发行”的资产，展示关联代币的代币编号；点击代币编号进入[全平台代币台账（A-TOKEN-01）](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#A-TOKEN-01)中这枚代币的代币详情。
- 资产详情可以进入债权人企业的企业详情。
- 信息缺失按[上游信息缺失](#missing-data)处理；语言与时间按[语言与时区](#locale)展示。

<a id="amount-warning"></a>
### 8.4 运营端金额关系预警

- 当累计已回款、未回款余额、原始资产价值或结清状态之间出现异常关系时，运营资产列表对该笔资产显示非阻断预警标记，资产详情说明存在金额关系异常并并列展示上游原值。具体视觉样式由 Hallmark 设计决定。
- 该预警只帮助运营核对上游数据，不属于业务校验：不改写金额或状态，不隐藏资产，不改变发行状态，不影响“申请发行”入口或提交结果，也不触发消息通知。
- 只有运营管理人员可以看到预警标记和说明；企业用户、机构均不展示该预警。企业和机构仍按其权限正常查看上游提供的金额、回款和状态字段。

## 9. 机构查看关联资产（F-AS-06）

对应功能标识：A-ASSET 中“机构仅查看本机构关联资产”（简报 4.4 权限矩阵）。

适用角色与前提：已登录管理端的机构，包括资产托管机构、审计机构和法律服务机构。机构只能看到已与本机构建立关联的资产（BR-15）【确认】。

- 查看范围是关联资产：代币发行 · 审核与铸造（M3b）的[机构关联结果](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#institution-link)包含本机构，且该发行申请使用了这笔资产。关联何时建立、保留或变化（包括申请驳回、铸造成功、机构停用之后）都以该结果为准，本模块不另行定义。
- 同一资产可能有多笔申请；机构只看到本机构关联的那些申请，看不到同一资产的其他申请。
- 关联资产列表展示：资产编号、债权人名称、债权人英文名称、债务人名称、债务人英文名称、原始资产价值（带币种）、到期日、回款状态、发行状态；上游未提供的英文名称不补写。发行状态只展示状态值，列表不附加解释性信息【确认】。
- 按[资产列表的核心筛选](#asset-filters)查找本机构关联资产；名称、详情入口与分页按[资产列表的名称、详情入口与分页](#asset-list-display)。
- 资产详情展示[信息结构与分级](#field-levels)中核心信息与补充信息里标为展示的全部字段，以及[资产状态](#status-fields)的三个状态；材料可以查看和下载。
- 资产详情展示本机构关联的每笔申请的申请编号和申请状态（按代币发行 · 审核与铸造（M3b）的[申请状态](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#status)）；点击申请编号进入对应的申请详情。机构在可信资产中只有查看权限，不提供审核、驳回或其他申请处理操作。
- 发行状态为“已发行”、且本机构属于这枚代币的[名单内机构](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#listed-institutions)时，展示关联代币的代币编号；不属于名单内机构（例如只关联同一资产被驳回的申请）时不展示代币编号，资产发行状态仍如实展示。点击代币编号进入[本机构代币台账（R-TOKEN-01）](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#R-TOKEN-01)中这枚代币的代币详情。
- 机构看不到企业列表、企业详情、企业用户信息、数币账户和金额关系预警；债权人只通过基本信息中的债权人名称、债权人英文名称、注册国家 / 地区和企业登记标识呈现。
- 访问非关联资产按[无权查看](#no-access)处理；信息缺失按[上游信息缺失](#missing-data)处理；语言与时间按[语言与时区](#locale)展示。

<a id="pending"></a>
## 10. 待确认事项与依赖

待确认事项：本模块没有业务待确认事项。

依赖：

- 上游平台 · 可信资产（D2）：提供核心信息中的应收账款与交易双方、销售合同 / 订单、货物交付、销售发票，补充信息中本企业与上游供应商、债务人与其下游客户的交易，以及各环节材料和确权状态；日期与时间带时区，到期日连同来源时区提供。
- 上游平台约束【确认】：资产确权后，原始资产价值、到期日等资产信息不再变化；不存在撤销确权或删除资产的情况；回款记录、结清状态和逾期状态仍会变化。
- 上游平台 · 回款与结清（D3）：提供这笔应收账款的回款进度（含支付凭证）、结清状态和逾期状态；本模块据此归并回款状态；归并展示不替换上游原始依据。
- 上游平台 · 用户匹配（D1）：提供企业信息和企业用户信息，供运营查看。
- 企业登录与企业账户（M1）：已认证、未认证与游客的判断；企业信息、用户信息和数币账户的字段定义；面客端界面语言与时区的选择。
- 管理端登录与权限（M5）：管理端界面语言与时区的选择，见[界面语言与时区（F-LG-09）](../../管理端/M5-管理端登录与权限/01-管理端登录与权限-PRD.md#F-LG-09)。
- 代币发行 · 企业申请（M3a）：承接本模块带入的固定资产，提供企业可见的申请状态。
- 代币发行 · 审核与铸造（M3b）：提供申请编号、管理端申请状态、[机构关联结果](../../管理端/M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#institution-link)、最终发行结果和代币编号。本模块据此展示关联申请、确定机构的只读可见范围并更新资产发行状态；机构分配、处理、驳回和发行执行流程全部由 M3b 定义，不在本模块重复定义。
- 我的代币与销毁申请（M4a）、销毁执行、解除资产托管与代币台账（M4b）：代币的资产托管、融资、销毁等状态与查看；机构从关联资产进入[本机构代币台账（R-TOKEN-01）](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#R-TOKEN-01)；代币编号的定义见[代币及关联事实](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#handoff-token)，企业从资产详情点击代币编号进入[代币详情（C-TOKEN-02）](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#C-TOKEN-02)，运营进入[全平台代币台账（A-TOKEN-01）](../../管理端/M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#A-TOKEN-01)中的代币详情。
- 本平台取得上游数据的时效没有已确认的目标值，本册不设时效要求，也不限定由上游推送还是由本平台主动获取。
