# 我的代币与销毁申请 · 功能与业务规则

2026-10-30｜面客端：企业用户｜需求评审稿

本模块共四册：01 本册、[02 流程图与状态机](./v1.0-我的代币与销毁申请-流程图与状态机.md)、[03 消息通知](./v1.0-我的代币与销毁申请-消息通知.md)、[04 验收](./v1.0-我的代币与销毁申请-验收.md)。本模块在企业提交销毁申请成功时向运营发送消息，因此设 03 册。

本册只定义业务行为与信息需求；布局、组件形态与交互承载由设计决定。功能标识“我的代币（C-TOKEN）”“销毁申请（C-BURN）”、业务规则编号沿用《代币发行平台·需求诊断简报》v1.6；功能细分编号用于跨册定位。【确认】为用户明确口径，【建议·已采纳】为简报中已采纳建议。

配套依据：WS-506 的简报 v1.6；本项目 `cly-v6.0.0` 上 M1、M2、M3b、[M4b 的两端衔接字段清单](./v1.0-销毁审核与解除质押-PRD.md#handoff)、M6、M7 现行 PRD；WS-509 于 2026-10-30 交付的 M3a 修订稿。

## 1. 模块是什么

企业在本模块查看本企业已铸造代币及其融资、监管和销毁情况；当对应应收账款已到期、已结清，且没有任何融资质押时，企业发起销毁申请，由运营审核并执行销毁。企业持续查看审核、销毁结果，以及销毁后原监管机构解除监管的进度；被运营驳回后可以在重新满足条件时再次发起。

基本原则：

- 代币、资产、申请是不同对象。应收账款的结清来自上游；融资来自下游并经链上验证；销毁及解除监管由 M4b 推动，本模块不能代替运营或监管办理。
- 销毁须同时满足已到期、已结清、没有任何融资质押，并且没有处理中的销毁申请（BR-07、BR-09、BR-20）【确认】【建议·已采纳】。
- 监管与融资分开。按用户在可信资产议题的确认，不再将监管称为“监管质押”；监管中不构成销毁的阻断条件。
- 状态引用简报第 5 节；监管相关表述按用户后续确认映射，见[对象与状态](#states)。本模块不添加新的失败终态或自动重试规则。
- 两端共用的申请、驳回、销毁及解除记录直接引用 M4b 的[两端衔接字段清单](./v1.0-销毁审核与解除质押-PRD.md#handoff)，本册不另建跨端清单。

**一个完整的例子。** 企业 A 从铸造成功的发行申请进入我的代币，看到 50,000.00 USD 的代币、Ethereum 数币地址、所属合约、到期日及监管机构 C。到期时点已经到达，上游提供已结清，下游和链上都确认没有融资质押。A 核对代币、资产、数量和接收申请的运营环节，提交销毁申请。申请进入待运营审核，A 可以在销毁申请中继续查看。运营通过后执行销毁；若销毁失败，由运营手动重试，A 不能重复发起。销毁成功后代币为已销毁，A 看到等待 C 解除监管；C 在平台完成解除并留记录后，A 看到已解除监管，再返回我的代币仍可查到该代币及销毁经过。

### 1.2 本期不做

- 发起融资、解除融资质押、转移代币或在本平台更换代币所在地址；融资在下游借贷平台办理。
- 企业执行销毁、审核申请、手动重试销毁或自行解除监管；这些属于 M4b。
- 修改已提交申请、撤回申请、批量申请、部分销毁或由企业输入任意销毁数量；本期只承接选定代币的销毁，不增加这些能力。
- 企业在本模块修改资产、结清、融资、合约、监管机构或数币账户信息。
- 把发行阶段企业统一显示“发行处理中”的规则延伸为销毁状态归并；销毁仍按简报的真实阶段展示。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 已铸造代币 | M3b 已确认铸造成功、属于本企业的代币；铸造中或铸造失败的申请尚不是本模块代币 |
| 所在数币账户 | 代币对应的 Ethereum 数币地址；账户备注名用于帮助识别，登录地址与收币地址用途分开 |
| 融资状态 | 下游借贷平台提供的融资情况，企业看到未融资或融资中；销毁资格还必须通过链上无融资质押校验 |
| 监管 | 原发行申请所选机构对该笔资产的监管，与融资质押是独立关系；从铸造成功起承接，解除由 M4b 办理 |
| 处理中的销毁申请 | 待运营审核、销毁中或销毁失败的申请；失败等待运营重试仍属于处理中 |
| 已到期 | 当前已达到或超过上游提供的、带时区的到期时点；查看者的时区只影响展示 |
| 已结清 | 上游明确提供已结清，不依据回款金额、余额为零或逾期状态自行推断 |

<a id="access"></a>
## 3. 身份、入口与共同展示规则

### 3.1 身份与数据范围

- 只有已认证的企业用户可以查看本企业代币和销毁申请、提交销毁申请。企业归属按稳定企业身份判断，不以当前登录地址或代币接收地址相同作为授权依据。
- 未登录时按[登录后返回原目标（C-AUTH-05）](./v1.0-企业登录与企业账户-PRD.md#C-AUTH-05)登录后重新判断；游客按[游客引导与功能限制（C-GUEST-01）](./v1.0-企业登录与企业账户-PRD.md#C-GUEST-01)处理；未认证企业用户按[认证资格与受限引导（C-AUTH-04）](./v1.0-企业登录与企业账户-PRD.md#C-AUTH-04)处理，不返回业务数据。
- 其他企业的代币或申请与不存在的对象统一说明“相关内容暂不可访问”，不区分是否存在；直接访问、刷新、绕过界面提交均按同一权限判断。
- 登录地址变更后，同一企业的新登录地址仍能查看既有代币和申请；原代币地址不随登录地址、账户备注名或当前账户列表变化而改变。账户维护按[数币账户列表与登录地址（C-ACCOUNT-01）](./v1.0-企业登录与企业账户-PRD.md#C-ACCOUNT-01)。
- 退出、切换钱包或有效企业归属变化后，不残留旧企业业务数据；迟到的结果不得显示旧企业内容。

### 3.2 入口与返回

- 面客端保留“我的代币”和“销毁申请”两个业务入口，与前置 M3a 的入口口径一致；分组、位置和页面承载由设计决定。我的代币进入代币列表，销毁申请进入申请列表。
- M3a 的铸造成功申请、M2 的已发行资产可以定位到对应代币详情；未铸造成功的申请不会产生可访问的代币详情。
- 代币详情可以前往关联资产、发行申请和该代币的销毁申请；关联资产内容按[企业查看本企业可信资产（F-AS-03）](./v1.0-可信资产-PRD.md#F-AS-03)，发行申请按 WS-509 最新《代币发行·企业申请》修订稿。关联记录暂不可访问时说明原因，仍可返回代币。
- 从原业务或消息进入详情后，可以返回原入口；从列表进入详情后可以返回对应列表。

<a id="shared-display"></a>
### 3.3 展示、缺失与读取异常

- 字段名、状态名称和说明支持中文与英文；机构名称、账户备注名、驳回意见等业务原文不自动翻译。数量按两位小数展示，币种为 USD；数量规则承接 M3a、M3b 已确认的铸造结果。
- 日期时间按本人[偏好设置（C-PROFILE-02）](./v1.0-企业登录与企业账户-PRD.md#C-PROFILE-02)换算；到期判断按[结清与逾期依据](./v1.0-可信资产-PRD.md#overdue)，切换语言、时区不改变资格、事件先后或业务状态。
- 数币地址、合约地址按[钱包地址与网络名称的展示](./v1.0-企业登录与企业账户-PRD.md#address-display)缩写展示，可以核对完整地址；网络统一为 Ethereum，合约标准为 ERC-3525。
- 读取中、读取失败和确实没有数据应可区分。读取失败可重试，不显示成没有代币或没有申请；未知值不补为零、未融资、已结清或已解除监管。
- 上游或下游暂不可用时，仍可查看本平台已取得的代币、申请及结果；依赖信息无法取得时明确说明，不能以旧展示或未知值放行提交。部分信息失败不遮蔽其余已取得内容。
- 只展示的业务信息均不可由企业编辑；本模块没有额外自由填写字段，不增加原因、备注、凭证等提交要求。

<a id="C-TOKEN-01"></a>
## 4. 我的代币列表（C-TOKEN-01）

适用角色与前提：已认证的企业用户。

- 列出本企业全部已铸造代币，包含有融资质押、销毁申请中和已销毁的代币；已销毁后保留记录，不能通过销毁使历史从列表消失。
- 每条能识别对应代币与上游资产，并展示合约名称、代币数量与币种、所在数币地址、到期日、融资情况、应收账款结清情况、监管情况和销毁进度；信息含义见[代币详情（C-TOKEN-02）](#C-TOKEN-02)。未知或冲突按[融资双重校验](#finance-check)单独说明，不能混入正常的未融资结果。
- 从一条记录进入该代币详情。是否可发起销毁及限制原因在[销毁资格与限制原因（C-TOKEN-03）](#C-TOKEN-03)中统一判断，不在列表逐条展开解释性内容。
- 本企业没有代币时说明当前尚无铸造成功的代币，可以前往代币发行查看申请；读取失败按[共同展示规则](#shared-display)处理。
- 列表和详情展示同一笔代币的当前结果；办理状态变化后，再次读取应反映新进度。

<a id="C-TOKEN-02"></a>
## 5. 代币详情（C-TOKEN-02）

适用角色与前提：已认证的企业用户，代币属于本企业。

### 5.1 代币与关联信息

| 业务信息 | 含义、来源与展示 |
| --- | --- |
| 代币识别信息 | 使用平台内唯一代币编号，与原发行申请、链上实际代币、网络和合约固定对应，按[代币及关联事实](./v1.0-销毁审核与解除质押-PRD.md#handoff-token) |
| 关联资产 | 上游资产编号、债务人名称、应收账款金额与币种；可进入对应可信资产详情，资产信息按 M2 现行正文 |
| 代币数量与币种 | M3b 铸造成功的代币数量，两位小数，USD；企业不可改写，不将参考金额代替实际数量 |
| 所在数币账户 | 对应 Ethereum 数币地址及仍可取得的当前账户备注名；地址完整值可核对，当前仍为登录地址这一条时标明登录地址；备注名缺失不影响核对地址 |
| 到期日 | 铸造结果的到期日，与发行申请所用应收账款到期日一致；上游提交后不再变更【确认】 |
| 合约 | 合约名称、标准 ERC-3525、网络 Ethereum、合约地址；名称取[合约管理的信息](./v1.0-合约管理-PRD.md#fields)中的当前值，合约身份保持不变 |
| 铸造时间与发行申请 | 展示成功铸造时间，可进入对应发行申请；监管协议仍在发行申请中查看和下载 |

代币铸造结果继承[审核与铸造的铸造结果清单](./v1.0-代币发行-审核与铸造-PRD.md#handoff-mint)，企业侧“监管”的名称按用户后续确认执行。修改账户备注名、上游登录地址变化、合约改名均不改变代币的原有地址与合约；平台停用不影响查看既有代币；满足原销毁条件时，企业仍可提交销毁并跟踪运营审核、执行及失败手动重试，无需先启用原合约【确认】，见[停用与既有业务](./v1.0-合约管理-PRD.md#inflight)。

### 5.2 融资、结清、监管与销毁信息

| 业务信息 | 企业看到什么 | 提供方与变化 |
| --- | --- | --- |
| 到期情况 | 未到期或已到期；到期时点无法确定时说明无法确认 | 到期依据来自上游并承接发行记录，按 M2 的带时区时点判断 |
| 应收账款结清情况 | 已结清、未结清；取不到时说明无法确认 | 上游提供的结清事实，M2 的回款状态归并不替代该事实 |
| 融资情况 | 未融资、融资中；结果冲突或取不到时说明限制，见[融资双重校验](#finance-check) | 下游借贷平台提供融资状态，链上验证用于销毁资格；本平台不能办理融资或解除融资质押 |
| 监管情况 | 监管机构名称、监管中或已解除监管；开始时间取铸造成功时间 | 机构取原发行申请所选机构，名称展示当前值；解除结果由 M4b 提供，未知时不视为已解除 |
| 销毁进度 | 未发起、关联销毁申请的当前阶段、或已销毁事实；未发起仅表示没有申请记录，不是新增业务状态 | 申请详情见[申请详情与解除监管进度（C-BURN-03）](#C-BURN-03)，驳回的历次记录仍可查看 |

监管中与融资中互不替代；代币已销毁与监管已解除是两项独立结果。销毁成功后不得再显示为可销毁；解除监管尚未完成时不得显示业务全部完成。

流程参见[企业查看与返回（图 1）](./v1.0-我的代币与销毁申请-流程图与状态机.md#fig-1)。

## 6. 销毁资格与限制原因（C-TOKEN-03）

适用角色与前提：已认证的企业用户，所选代币属于本企业且已铸造成功。

依据：到期、结清、没有任何融资质押（BR-07）【确认】；融资双重校验（BR-20）【确认】【建议·已采纳】；在途申请防重（BR-09）【建议·已采纳】；结果不一致按有质押（Q26）【建议·已采纳】。

<a id="eligibility"></a>
### 6.1 同时满足的条件

1. 当前已经达到或超过应收账款的到期时点；恰好到达到期时点属于已到期。
2. 上游明确提供该笔应收账款已结清；即使提前结清，仍须等到期。
3. 下游融资质押结果与链上验证结果均确认没有任何融资质押。
4. 同一代币没有待运营审核、销毁中或销毁失败的申请，也没有已经销毁成功的结果。
5. 当前身份及企业归属有效，见[身份与数据范围](#access)。

监管中是正常的待销毁背景，不要求先解除监管再申请。历史逾期后已结清不额外阻断销毁；M2 的资产发行状态在铸造后保持已发行，不作为再次申请发行或阻止销毁的理由。上游撤销确权、删除的提示与人工处理继续按 M2 执行，本模块不新增自动终止规则；但无法取得销毁所需的结清、到期依据时不能提交。

<a id="finance-check"></a>
### 6.2 融资双重校验

| 下游结果 | 链上结果 | 企业可见结果与本次资格 |
| --- | --- | --- |
| 无融资质押 | 无融资质押 | 融资条件通过；仍须满足其他全部条件 |
| 有融资质押 | 有融资质押 | 说明仍有融资质押，不能发起 |
| 有融资质押 | 无融资质押 | 说明融资结果不一致，按有融资质押处理，提示联系平台，不能发起 |
| 无融资质押 | 有融资质押 | 说明融资结果不一致，按有融资质押处理，提示联系平台，不能发起 |
| 无融资质押 | 未取得、失败或无法确认 | 说明暂时无法确认没有融资质押，可重新获取，不能发起；不声称确定无质押 |
| 未取得、失败或无法确认 | 无融资质押 | 说明暂时无法确认没有融资质押，可重新获取，不能发起；不声称确定无质押 |
| 有融资质押 | 未取得、失败或无法确认 | 说明已取得的有融资质押结果和另一项无法确认，不能发起 |
| 未取得、失败或无法确认 | 有融资质押 | 说明已取得的有融资质押结果和另一项无法确认，不能发起 |
| 未取得、失败或无法确认 | 未取得、失败或无法确认 | 说明暂时无法确认没有融资质押，可重新获取，不能发起；不声称确定有质押或无质押 |

以上是资格判断组合，不是新增融资状态；企业不需要理解接口或链上报文。不能以单一来源、缓存的“未融资”展示、已结清或已解除监管替代双重校验。

### 6.3 多条件组合与用户结果

按表中顺序判断已销毁、处理中，再判断业务条件；同时不满足多个业务条件时说明全部已知原因。

| 代币与申请情况 | 到期、结清及融资情况 | 监管情况 | 企业能做什么 |
| --- | --- | --- | --- |
| 已销毁（含等待解除监管或已解除） | 不再用于开放新申请 | 监管中或已解除监管 | 查看原申请和解除进度，不能再发起 |
| 有待运营审核、销毁中或销毁失败申请 | 即使其余条件都满足 | 监管中 | 查看处理中的申请，不能重复发起；失败由运营重试 |
| 尚无申请，或最近一次申请被驳回 | 已到期、已结清、双重无质押 | 监管中 | 可进入确认提交；被驳回时使用[再次发起](#C-BURN-04) |
| 尚无申请，或最近一次申请被驳回 | 未到期、未结清或仍有融资质押，任一不满足 | 监管中 | 说明全部已知不满足项，不允许提交 |
| 尚无申请，或最近一次申请被驳回 | 到期、结清、双重无质押任一无法确认 | 监管中 | 说明暂不能确认的依据，可重新获取，不能提交 |

监管结果与销毁结果互相矛盾、代币缺少必要关联信息时，保留可查事实并说明当前无法确认，不能提交；按 M4b 的[共同异常](./v1.0-销毁审核与解除质押-PRD.md#common-errors)由运营核查，不向企业提供强制改状态入口。

<a id="C-BURN-01"></a>
## 7. 确认并提交销毁申请（C-BURN-01）

适用角色与前提：已认证企业用户，已选定满足[销毁资格](#eligibility)的本企业代币。

### 7.1 确认内容

- 展示选定代币、上游资产编号、数量与币种、到期日、所在数币地址、合约、监管机构，以及已到期、已结清和融资校验结果；均只读。
- 企业可以核对完整数币地址与合约地址，不能另选代币接收账户或合约。
- 明确本次是提交销毁申请，由运营审核，通过后执行代币销毁；代币销毁成功后仍需原监管机构办理解除监管，二者不是同时完成。
- 企业取消或未提交即离开，回到原代币，未产生申请、不改变状态、不发送通知。
- 本期不采集企业填写的原因、备注、凭证或数量；提交信息直接采用[申请信息](./v1.0-销毁审核与解除质押-PRD.md#handoff-application)，销毁数量为选定代币的完整铸造数量，两位小数 USD。

### 7.2 提交与结果

- 提交销毁申请是关键业务动作，提交前按[上游变化的同步（C-AUTH-06）](./v1.0-企业登录与企业账户-PRD.md#C-AUTH-06)重新确认身份、有效企业和认证结论，并重新判断[销毁资格](#eligibility)。查看时曾满足条件不保证提交时仍满足。
- 提交成功后生成平台内唯一的销毁申请编号，记录本次提交成功时间并关联原代币编号；当前阶段为待运营审核，代币进入销毁申请中；展示已提交结果并可进入该笔申请详情，也可返回我的代币。编号和记录按[申请信息](./v1.0-销毁审核与解除质押-PRD.md#handoff-application)。
- 一次成功提交只产生一笔申请。同一代币已有处理中的申请时，重复提交不能生成新申请，应定位已有申请供企业查看；重复点击、刷新或结果重取不追加申请。
- 提交前条件改变时，不产生申请，说明当前限制，企业可返回代币查看；认证变化按 M1 处理。上游、下游或链上必要结果无法确认时，不放行本次提交。
- 已确认提交失败且未产生申请时，说明未完成，可在重新校验后重试；结果尚未确认时，不宣称失败或成功，不提供会形成重复申请的再次提交，应先获取本次实际结果。
- 成功提交触发[新的销毁申请（NT-A02）](./v1.0-我的代币与销毁申请-消息通知.md#NT-A02)，发给全体运营；消息未及时显示不改变已经成功的申请，不要求企业为通知再次提交。

流程参见[校验与提交销毁申请（图 2）](./v1.0-我的代币与销毁申请-流程图与状态机.md#fig-2)。

<a id="C-BURN-02"></a>
## 8. 销毁申请列表（C-BURN-02）

适用角色与前提：已认证的企业用户。

- 列出本企业全部销毁申请，包括被驳回、处理中、销毁成功待解除监管和已解除监管的历史记录。
- 每条展示该笔销毁申请编号、上游资产编号、代币编号、申请销毁数量与币种、提交时间和当前申请阶段，按[申请信息](./v1.0-销毁审核与解除质押-PRD.md#handoff-application)引用同一笔事实。
- 每条可以进入对应申请详情；针对同一代币多次被驳回形成的申请必须分别保留，不能用最新申请覆盖旧申请。
- 本企业尚无申请时说明暂无销毁申请，可前往我的代币选择符合条件的代币；读取失败按[共同展示规则](#shared-display)处理。
- 申请阶段取当前业务事实，列表与详情一致；查看历史驳回记录不会将旧记录变成新申请的状态。

<a id="C-BURN-03"></a>
## 9. 申请详情与解除监管进度（C-BURN-03）

适用角色与前提：已认证企业用户，销毁申请属于本企业。

### 9.1 申请信息与结果

- 展示选定销毁申请编号、提交时间、对应代币编号和上游资产编号、申请销毁数量与币种、所在数币地址、合约与监管机构，按[申请信息](./v1.0-销毁审核与解除质押-PRD.md#handoff-application)定位原记录，可以返回对应代币或资产。
- 申请信息区分提交时的申请事实与当前关联信息，不用最新申请的值替代历史申请；机构名、账户备注名的展示沿用[代币详情](#C-TOKEN-02)的当前名称规则。
- 审核驳回时展示驳回结果与原文意见；能重新满足条件时可再次发起，见[驳回后再次发起（C-BURN-04）](#C-BURN-04)。
- 销毁成功展示销毁事实与结果数量；解除监管尚未完成时，明确下一步由原监管机构办理，不能让企业误认为自己还要解除融资质押。
- 解除完成后展示已解除监管结果、原监管机构当前名称和原解除完成时间，按[解除监管记录及企业可见范围](./v1.0-销毁审核与解除质押-PRD.md#handoff-release)；企业看不到操作人、备注和凭证，直接访问文件也必须拒绝。
- 企业可见平台运营这一审核方、通过／驳回结果及审核时间、原文驳回意见；不见具体运营账号、失败时间、内部失败说明及重试记录，按[条件、审核与执行记录](./v1.0-销毁审核与解除质押-PRD.md#handoff-review)。销毁成功显示完整结果数量与实际成功时间，按[销毁结果](./v1.0-销毁审核与解除质押-PRD.md#handoff-burn)。

<a id="states"></a>
### 9.2 对象与状态

销毁申请的真实状态链引用简报第 5 节；末两项的企业名称按用户“只有监管”的确认表述。此表是对应展示，不另立并行状态机。

| 简报中的销毁申请阶段 | 企业展示与可观察结果 | 可继续操作 |
| --- | --- | --- |
| 待运营审核 | 等待平台运营审核，尚未执行销毁 | 查看本申请；不能重复发起 |
| 驳回 | 展示被驳回及意见；这笔申请结束 | 满足当前销毁条件后再次发起新申请 |
| 销毁中 | 运营已通过，正在执行销毁，尚无成功结果 | 查看进度；不能重复发起或自行重试 |
| 销毁失败 | 展示销毁失败、由运营处理重试；不能表示代币已销毁 | 等待运营处理；不能重新申请或自行重试 |
| 销毁成功 | 展示代币已销毁的结果；监管解除尚未完成 | 查看销毁结果与后续解除监管进度 |
| 待解除资产质押 | 企业表述为待解除监管，原监管机构尚未完成解除 | 查看进度；不能再次销毁 |
| 已解除质押 | 企业表述为已解除监管，展示完成事实 | 查看结果和历史记录；不能再次销毁 |

- 销毁成功是结果事实，待解除监管是之后的待办进度；即使业务直接进入待解除监管，仍保留销毁成功事实，不能倒退成未销毁。
- 原销毁执行仍在进行或结果尚未确认时，申请保持销毁中，不能因等待时间较长自行显示失败、已销毁或允许企业重新申请；当前只承接原执行实际结果，按 M4b [通过并执行销毁](./v1.0-销毁审核与解除质押-PRD.md#A-BURN-03)。
- 销毁失败由运营在原申请手动重试，真实状态回到销毁中，销毁申请编号、代币、数量、地址和原合约保持不变；没有自动重试或企业重试。失败与发行阶段的“发行处理中”归并无关。
- 代币状态引用简报：正常（未质押）、融资质押中、销毁申请中、已销毁；企业融资展示为未融资／融资中。驳回释放原申请占用，按当前融资事实回到正常（未质押）或融资质押中；未知时说明无法确认并限制新申请，不用旧正常结果放行，按[对象与状态对应](./v1.0-销毁审核与解除质押-PRD.md#states)。
- 到期、结清、融资、监管与销毁各自回答不同问题，组合判定见[多条件组合](#C-TOKEN-03)；未知信息不构成新的业务终态。
- 两端对监管与融资的区分见[监管口径同步](#confirmed-sync)。

<a id="message-entry"></a>
### 9.3 消息进入与返回

- 由 M4b 发给企业的相关消息进入消息所指的那一笔销毁申请，不能换成该代币的最新申请。
- 进入时重新确认身份与权限，并展示申请当前事实。旧驳回消息仍进入原驳回记录；如果代币另有处理中申请，应引导查看已有申请，不能因旧消息再次放行提交。
- 该申请已完成但仍有权查看时，正常显示完成结果；申请不存在或无权时按[身份与数据范围](#access)统一拒绝，可返回原消息。
- 消息内容、事件和收件范围由 M4b 自己维护；M4a 不新增结果通知，消息的已读不推动任何业务进度。

流程参见[销毁申请状态与解除监管（图 3）](./v1.0-我的代币与销毁申请-流程图与状态机.md#fig-3)。

<a id="C-BURN-04"></a>
## 10. 驳回后再次发起（C-BURN-04）

适用角色与前提：本企业存在运营驳回的销毁申请，所涉代币尚未销毁。

依据：销毁申请被驳回后可再次发起，仍须满足销毁条件（BR-22）【确认】。

- 原申请维持驳回结果和意见；再次发起针对原代币创建新的销毁申请，不修改、复用或覆盖旧申请。
- 再次发起仍逐项执行[销毁资格与限制原因（C-TOKEN-03）](#C-TOKEN-03)，不能将曾通过校验或曾被驳回当作本次资格。
- 用户再次核对确认信息，按[确认并提交销毁申请（C-BURN-01）](#C-BURN-01)提交；成功后新申请为待运营审核，并作为一个新事实发送新的运营待审消息。
- 原代币已有其他处理中的申请时，进入已有申请；已销毁时只看结果；当前未结清、有融资质押或资格无法确认时，说明当前限制，不产生新申请。
- 销毁失败后等待运营重试属于原申请处理过程，不适用驳回后再次发起。

## 12. 跨模块口径

<a id="confirmed-sync"></a>
### 监管口径同步

用户在 WS-508 已明确“没有什么监管质押……本平台只有监管”。本册与 M4b 统一采用监管、待解除监管、已解除监管，原阶段对应关系见 M4b [对象与状态对应](./v1.0-销毁审核与解除质押-PRD.md#states)，未增加业务环节。简报 v1.6、M3b 部分旧称谓仍存在，本模块按用户确认映射；融资双重校验仍按简报 BR-20、Q26 执行。

M3a 企业侧“发行处理中”仅适用于发行，不隐藏销毁失败；登录地址变化按 M1 原登录地址顺延为普通账户处理。

### 管理端填写边界

驳回意见、解除备注的长度及可选解除凭证的限制由 M4b [填写与凭证边界（Q-M4B-02）](./v1.0-销毁审核与解除质押-PRD.md#Q-M4B-02)维护。企业不填写这些管理端字段，且不可查看解除操作人、备注和凭证；该待确认项不改变本模块提交字段、结果展示和资料隔离规则。
