# 管理端登录与权限 · 消息通知

2026-11-05｜需求评审稿｜配套[功能与业务规则](./01-管理端登录与权限-PRD.md)

本册逐项写明本模块发出的每类消息，发送对象只有运营管理人员与监管机构账号本人。运营本人的验证码和安全通知只发本人，不因属于运营角色而发给全体运营。运营邀请添加监管机构后的初始凭据邮件归[监管机构账号开通邮件（NT-R03）](../M5-监管机构管理/03-监管机构管理-消息通知.md#NT-R03)。

依据：通知规则与借贷平台《运营端账户与登录》一致【确认】。

本模块发 4 类消息，均为必发，用户不能关闭。只有密码变更通知同时发站内消息，进入消息中心并归入“账户安全”分类；其余只发邮件，不进入消息中心。站内消息的接收、展示、阅读与送达时效等共同规则由消息通知模块（M7）定义，见[来源接入要求（MSG-06）](../../两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-06)，本册不重复。

| 消息 | 渠道 | 触发功能 | 收件人 | 打开后去哪 |
| --- | --- | --- | --- | --- |
| [找回密码验证码（NT-LG-01）](#NT-LG-01) | 邮件 | [自助找回密码（F-LG-13）](./01-管理端登录与权限-PRD.md#F-LG-13) | 本人管理端账号当前有效登录邮箱 | 返回已发起的找回流程输入验证码，不自动登录 |
| [修改邮箱验证码（NT-LG-02）](#NT-LG-02) | 邮件 | [本人修改登录邮箱（F-LG-14）](./01-管理端登录与权限-PRD.md#F-LG-14) | 本次填写并通过格式与可用性检查的新邮箱 | 返回本人账户设置中的改邮箱流程输入验证码，不自动改邮箱 |
| [密码变更通知（NT-LG-03）](#NT-LG-03) | 邮件 + 管理端站内消息 | [首次登录强制改密（F-LG-03）](./01-管理端登录与权限-PRD.md#F-LG-03)、[自助找回密码（F-LG-13）](./01-管理端登录与权限-PRD.md#F-LG-13)、[修改密码（F-LG-08）](./01-管理端登录与权限-PRD.md#F-LG-08) | 账号本人：邮件发往当前登录邮箱，站内消息的收件范围为本人 | 站内消息不跳转 |
| [登录邮箱变更安全通知（NT-LG-04）](#NT-LG-04) | 邮件 | [本人修改登录邮箱（F-LG-14）](./01-管理端登录与权限-PRD.md#F-LG-14) | 本账号修改后的新邮箱与修改前的旧邮箱各一封 | 仅告知，不含免密登录链接 |

以下情况本模块不发消息：账号锁定与解除；登录成功或失败；界面语言与时区变更；修改密码、找回或修改邮箱未成功（取消、校验失败、验证过期、保存失败）。

<a id="NT-LG-01"></a>
## 找回密码验证码（NT-LG-01）

- 触发：本人在忘记密码流程获取或重发验证码，目标为本人当前有效管理端登录邮箱（运营或监管机构），已通过[发码前人机校验](./01-管理端登录与权限-PRD.md#captcha)且满足[重发间隔与发送限额](./01-管理端登录与权限-PRD.md#code-params)。
- 不触发：邮箱格式不合格、未绑定管理端账号、原账号邮箱已作废、人机校验未通过（含取消、加载失败、冷却中、通过结果失效）、发送限制未满足或请求失败。
- 收件人：只发本人账号当前登录邮箱，不发监管机构联系邮箱、不抄送其他运营或其他监管机构。
- 必须包含：本次 6 位找回验证码、用途为设置新密码、有效期 10 分钟、非本人操作时忽略的提示；不包含现有密码、新密码、初始密码或其他账号信息。
- 同一事实：同一次发送请求只产生一封，重复提交不重复发；本人再次成功获取是新的发码事实，使前一码失效。
- 异常：真实发送失败说明暂时无法发送，可立即重试 1 次，该次重试不计入发送额度、不受重发间隔限制，但仍须重新通过人机校验；密码、邮箱与已有登录不变。未绑定账号与已作废旧邮箱使用与有效邮箱相同的中性反馈，不通过提示或响应差异泄露账号与角色。
- 去向：回到本人发起的找回流程输入验证码；仅收到邮件不获得登录资格。

<a id="NT-LG-02"></a>
## 修改邮箱验证码（NT-LG-02）

- 触发：正常且已登录的运营管理人员或监管机构本人在[验证当前密码](./01-管理端登录与权限-PRD.md#reauth)的有效期内，对本次新邮箱获取或重发验证码，已通过[发码前人机校验](./01-管理端登录与权限-PRD.md#captcha)且满足[重发间隔与发送限额](./01-管理端登录与权限-PRD.md#code-params)。
- 不触发：登录失效、当前密码错误或验证已过期、账号锁定、新邮箱格式不合格或已被占用、新旧邮箱相同、人机校验未通过（含取消、加载失败、冷却中、通过结果失效）、发送限制未满足或请求失败。
- 收件人：只发本次新邮箱，不要求旧邮箱收码，不向监管机构联系邮箱、其他运营或其他监管机构发送副本。
- 必须包含：本次 6 位修改登录邮箱验证码、用途、有效期 10 分钟、非本人操作时忽略的提示；不包含当前密码与其他账号信息。
- 同一事实：同一发送请求只发一封；成功重发为新发码事实，使同用途旧码作废；目标邮箱变化后原目标码不能用于新目标。
- 异常：发送失败不能使新邮箱生效，原邮箱、密码与登录保持原值；可立即重试 1 次，该次重试不计入发送额度、不受重发间隔限制，但仍须重新通过人机校验。
- 去向：回到本人已发起的账户设置流程输入验证码；收到邮件不等于邮箱已修改。

<a id="NT-LG-03"></a>
## 密码变更通知（NT-LG-03）

**识别与归属**

| 项目 | 规则 |
| --- | --- |
| 消息名称与事件编号 | 密码变更通知（NT-LG-03） |
| 发送来源 | 管理端登录与权限；其他模块不发同义消息 |
| 渠道 | 邮件与站内消息各一条 |
| 端与分类 | 站内消息：管理端；账户安全 |
| 必发或可关闭 | 必发，本人不能关闭 |
| 收件人 | 账号本人。邮件发往该账号当前登录邮箱；站内消息的收件范围为本人，只有该管理端账号可见。不发给其他运营、全体运营或其他监管机构，不发监管机构联系邮箱 |

**触发与同一事实**

| 项目 | 规则 |
| --- | --- |
| 触发 | 新密码真实生效时发送，共三种情形：[首次登录强制改密（F-LG-03）](./01-管理端登录与权限-PRD.md#F-LG-03)设置成功（设置）、[自助找回密码（F-LG-13）](./01-管理端登录与权限-PRD.md#F-LG-13)重置成功（重置）、[修改密码（F-LG-08）](./01-管理端登录与权限-PRD.md#F-LG-08)修改成功（修改）。在新密码生效之后、该账号全部登录结束之前发出 |
| 不触发 | 密码校验不通过、当前密码错误或验证已过期、验证码无效、取消、保存失败、提交期间登录结束；账号锁定与解除 |
| 同一事实的区分依据 | 本人 + 账号 + 本次密码生效。一次密码生效只发一组（邮件一封、站内消息一条）；重试、重新登录、多设备登录结束都不构成新事实；下一次真实的密码变更是新事实 |
| 合并规则 | 不合并 |
| 发生时间 | 新密码生效的时间 |
| 发送失败 | 邮件投递或站内消息发送失败，都不回滚已生效的新密码，也不阻止该账号全部登录结束 |

**内容与去向**

| 项目 | 规则 |
| --- | --- |
| 必须写明 | 本账号密码已设置、已重置或已修改（按三种情形区分）；发生时间（按本人时区并标明时区）；非本人操作时的求助方式 |
| 不得出现 | 明文密码、初始密码、验证码、其他账号信息、免密或自动登录链接 |
| 语言 | 站内消息按[消息通知 · 内容与语言](../../两端共用/M7-消息通知/01-消息通知-PRD.md#content-rules)提供中文、英文各一套标题与正文；邮件先简体中文、后 English，两段内容相同；具体措辞由设计确定 |
| 原业务识别信息 | 无 |
| 打开后去哪 | 站内消息不跳转；阅读不改变账号状态，也不撤销已生效的密码 |

- 账号仍为待首登改密时（尚未完成首次改密的账号自助找回成功），站内消息在本人完成首次登录强制改密并重新登录后可见，见[谁能看到哪些消息（MSG-01）](../../两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-01)。
- 非本人操作时的求助方式的具体联系渠道由需求方提供，见[依赖](./01-管理端登录与权限-PRD.md#pending)。

<a id="NT-LG-04"></a>
## 登录邮箱变更安全通知（NT-LG-04）

**识别与归属**

| 项目 | 规则 |
| --- | --- |
| 消息名称与事件编号 | 登录邮箱变更安全通知（NT-LG-04） |
| 发送来源 | 管理端登录与权限；其他模块不发同义消息 |
| 渠道 | 邮件，不发站内消息，不进入消息中心 |
| 必发或可关闭 | 必发，本人不能关闭 |
| 收件人 | 本账号修改后的新邮箱与修改前的旧邮箱，各一封；仅限这两个地址。不发给其他运营、其他监管机构，不发监管机构联系邮箱 |

**触发与同一事实**

| 项目 | 规则 |
| --- | --- |
| 触发 | [本人修改登录邮箱（F-LG-14）](./01-管理端登录与权限-PRD.md#F-LG-14)中新邮箱通过验证并真实生效后发送 |
| 不触发 | 当前密码错误或验证已过期、验证码无效或过期、新邮箱被占用、账号锁定、取消、发送或保存失败等邮箱未变更的情况；仅收到修改邮箱验证码不等于邮箱已修改 |
| 同一事实的区分依据 | 账号 + 本次登录邮箱生效。一次生效只发一组（新、旧邮箱各一封），同一次修改不重复发送；再次修改邮箱是新事实 |
| 合并规则 | 不合并 |
| 发生时间 | 新邮箱生效的时间 |
| 发送失败 | 任一地址投递失败都不回滚已生效的修改，也不提示修改失败；新邮箱继续作为登录与找回地址 |

**内容与去向**

| 项目 | 规则 |
| --- | --- |
| 必须写明 | 本账号的登录邮箱已修改；发生时间（按本人时区并标明时区）；非本人操作时的求助方式。新旧两封可各自表述，但指同一次修改 |
| 不得出现 | 明文密码、验证码、占用邮箱的其他账号身份或状态、免密或自动登录链接 |
| 语言 | 先简体中文、后 English，两段内容相同；具体措辞由设计确定 |
| 打开后去哪 | 仅告知，不要求操作 |

- 修改登录邮箱不改变本账号的消息归属与已读状态，见[本人修改登录邮箱（F-LG-14）](./01-管理端登录与权限-PRD.md#F-LG-14)。

## 共同内容与有效性

- 每封邮件先简体中文、后 English，两个语言段表达同一内容；验证码邮件的两段使用同一验证码。具体措辞由设计确定。
- 验证码不出现在主题或预览文本中；所有邮件都不提供免密登录链接，也不通过邮件发送设置后的密码。
- 验证码规则见[验证码的共同规则](./01-管理端登录与权限-PRD.md#verification-rules)，位数、有效期、错误上限与发送限制见[验证码参数](./01-管理端登录与权限-PRD.md#code-params)；两类验证码邮件在同一邮箱上合计计算发送额度。
- 账号锁定与解除、登录成功与失败、语言与时区变更均不发消息。
