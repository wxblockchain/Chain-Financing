## 1. 模块是什么

运营管理人员和机构共用一个管理端，用同一个登录入口、以登录邮箱和密码登录。登录后，平台按账号的角色决定能看到哪些菜单、能看哪些数据：运营管理人员看全平台，机构只看本机构的数据。运营账号由开发人员分配；机构账号由运营添加，见[机构管理](../M5-机构管理/01-机构管理-PRD.md)。新账号须先完成首次密码设置：用初始密码登录时强制修改，也可以在登录前通过本人找回密码完成；完成后可以使用管理端并在账户设置中维护本人账户。运营管理人员和机构均可修改本人登录邮箱，并在登录入口用邮箱验证码自助找回密码；这两项为平台共用能力，不按角色分别开通【确认】。

基本原则：

- 一个管理端、一个登录入口，按角色区分菜单【确认】（BR-05）。登录方式只有登录邮箱加密码。
- 账号都不是自助开通的：运营账号由开发人员分配，机构账号由运营添加【确认】（BR-04、BR-05）。产品内没有注册或运营账号管理；账号分配后，两类账号均可使用平台自助找回密码与本人修改邮箱。本期不提供账号停用、启用或人工冻结功能。
- 机构只能看到业务模块当前授权给本机构的数据；不同机构之间互不可见。授权关系的产生、变更和终止由业务所属模块定义，本模块只提供统一越权拦截。
- 隐藏入口不是唯一防线：未授权的菜单不出现，绕过界面直接访问同样被拒绝。
- 登录、找回与账户安全规则与借贷平台《运营端账户与登录》保持一致【确认】：获取验证码前先通过人机校验，修改密码或登录邮箱前先验证当前密码，密码与登录邮箱变更后通知本人，安全记录保留 180 天。

**一个完整的例子。** 运营在机构管理中添加审计机构 X，为它分配登录邮箱 x@example.com 和初始密码，X 收到账号开通邮件。X 用该邮箱和初始密码登录，先设置新密码；设置成功后收到密码变更邮件和站内消息，当前登录结束。X 用新密码重新登录，只看到机构角色可用菜单。X 改写链接访问业务模块未授权给本机构的对象时，统一得到“无权查看或内容不存在”；对象授权条件由对应业务 PRD 决定。

### 1.1 需求清单

运营登录（A-LOGIN）与机构登录（R-LOGIN）共用下表全部登录与账户功能，差别只在账号来源、菜单和数据范围。

| 功能 | 谁 | 想做什么 | 为了什么 |
| --- | --- | --- | --- |
| [管理端账号与角色（F-LG-01）](#F-LG-01) | 运营管理人员、机构 | 知道自己的账号从哪里来、属于什么角色 | 按角色使用管理端 |
| [邮箱与密码登录（F-LG-02）](#F-LG-02) | 未登录的管理端用户 | 用登录邮箱和密码登录 | 进入管理端办理业务 |
| [自助找回密码（F-LG-13）](#F-LG-13) | 运营管理人员、机构 | 在登录入口用当前登录邮箱接收验证码、设置新密码 | 本人恢复登录，无需开发或运营代重置 |
| [首次登录强制改密（F-LG-03）](#F-LG-03) | 持初始密码的管理端用户 | 首次登录先换掉初始密码 | 初始密码经过他人之手，降低泄露风险 |
| [登录后进入与返回原目标（F-LG-04）](#F-LG-04) | 刚登录的管理端用户 | 进入默认页面，或回到登录前要去的地方 | 不必重新查找 |
| [连续失败与临时锁定（F-LG-05）](#F-LG-05) | 管理端用户 | 密码多次输错后账号被临时锁定 | 防止密码被猜中 |
| [登录有效期、无操作登出与退出（F-LG-06）](#F-LG-06) | 已登录的管理端用户 | 离开后登录自动结束，也能主动退出 | 防止他人在无人看管的电脑上操作 |
| [账号入口与账号信息（F-LG-07）](#F-LG-07) | 已登录的管理端用户 | 查看本人账号信息 | 确认当前登录的是哪个账号 |
| [修改密码（F-LG-08）](#F-LG-08) | 已登录的管理端用户 | 修改本人密码 | 定期更换或怀疑泄露时更换 |
| [本人修改登录邮箱（F-LG-14）](#F-LG-14) | 正常且已登录的运营管理人员、机构 | 验证新邮箱并替换原登录邮箱 | 维护本人账号的有效登录与找回地址 |
| [界面语言与时区（F-LG-09）](#F-LG-09) | 所有管理端访问者 | 在简体中文和 English 之间切换，按本人时区看时间 | 用熟悉的语言和时间办理业务 |
| [菜单权限矩阵（F-LG-10）](#F-LG-10) | 运营管理人员、机构 | 只看到本角色能用的菜单 | 各司其职 |
| [数据范围（F-LG-11）](#F-LG-11) | 运营管理人员、机构 | 运营看全平台，机构只看业务模块当前授权的数据 | 机构之间互不可见 |
| [无权访问的处理（F-LG-12）](#F-LG-12) | 管理端访问者 | 访问未授权内容时得到统一结果 | 不泄露他人数据，也不泄露数据是否存在 |

### 1.2 本期不做

- 注册、申请开通管理端账号。
- 运营代机构重置密码：本人找回以[自助找回密码（F-LG-13）](#F-LG-13)为准。
- 运营账号的界面化管理：新增运营账号、为运营重新分配初始密码、分配角色都由开发人员在产品外完成【确认】。
- 账号停用状态：本期不设账号停用，开发人员也不停用运营账号。
- 机构账号停用、启用或人工冻结；本期只维护机构状态，机构状态不改变账号状态。
- 运营以外的角色细分：运营只有“管理员”一个角色【确认】（BR-05）。
- 验证码登录、钱包登录、第三方登录、“记住我”。
- 账号锁定与解除、登录成功或失败、界面语言与时区变更的通知。
- 管理端账号登录面客端，或面客端钱包地址登录管理端：两套账号互不相通，面客端登录见[企业登录与企业账户](../../面客端/M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md)。
- 各业务菜单内的具体操作规则：由各业务模块定义，本册只定义谁能看到哪个菜单、能看哪些数据。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 管理端 | 运营管理人员和机构共用的端，与企业使用的面客端是两套 |
| 管理端账号 | 登录管理端的账号，以登录邮箱识别。分为运营账号和机构账号两类 |
| 运营账号 | 角色为运营管理员的账号，由开发人员分配，可以有多个 |
| 机构账号 | 角色为机构的账号，由运营在机构管理中添加时分配，归属一个机构 |
| 本机构 | 对机构账号而言，指它所属的那个机构 |
| 初始密码 | 开发人员或运营为账号设置、由他人告知账号使用者的密码，包括运营添加机构时设置的密码、开发人员分配或重新分配运营密码时设置的密码，以及开发人员为机构账号重置凭据时设置的密码。只能用来完成首次登录强制改密 |
| 重置凭据 | 开发人员为账号设置新的初始密码（机构账号同时更正登录邮箱），使账号回到待首登改密，见[开发人员重新分配初始密码与重置凭据](#credential-reset) |
| 登录有效期 | 一次登录从成功起最多能保持多久 |
| 无操作登出 | 一段时间没有任何真实操作后，登录自动结束 |
| 临时锁定 | 连续输错密码达到次数后，账号在一段时间内不能登录；到期自动解除 |
| 原目标 | 未登录时想打开的管理端页面，例如从消息链接打开的一条消息 |

## 3. 管理端账号与角色（F-LG-01）

依据：运营与机构共用管理端、按角色区分菜单；运营只有“管理员”一个角色，账号由开发人员分配。机构只能由运营添加，初始账号由运营分配。

### 3.1 两类账号

| 角色 | 账号从哪里来 | 数量 | 产品内谁能维护 |
| --- | --- | --- | --- |
| 运营管理员 | 开发人员分配登录邮箱和初始密码【确认】 | 可以有多个【确认】 | 本人可修改自己的密码、登录邮箱、界面语言和时区，并在登录入口自助找回密码；账号建立、重新分配初始密码及其他管理由开发人员在产品外完成，本模块不提供界面 |
| 机构 | 运营在[添加机构（F-RG-02）](../M5-机构管理/01-机构管理-PRD.md#F-RG-02)时分配登录邮箱和初始密码 | 每个机构只有一个有效管理端账号 | 本人可修改自己的密码、登录邮箱、语言与时区，并在登录入口自助找回密码；运营可编辑机构资料、停用或启用机构；机构添加后运营不能修改其登录邮箱，也不能代重置密码；添加时登录邮箱填错的，由运营线下联系开发人员重置凭据，见[登录邮箱填错的纠正](../M5-机构管理/01-机构管理-PRD.md#login-email-fix) |

- 一个账号只有一个角色，角色在账号建立时确定，产品内不能更改。
- 运营管理员的权限对每个运营账号都相同，本期不按人细分。
- 机构账号始终归属建立时的那个机构，不能改属其他机构。
- 管理端账号只能登录管理端；面客端只能用钱包地址登录。

| 角色 | 运营管理员或机构 | 建立时确定，不能修改 |
| 所属机构 | 仅机构账号有，并展示该机构当前是启用还是停用 | 建立时确定，不能修改 |
| 机构类型 | 仅机构账号有：所属机构当前的机构类型（资产托管机构、审计机构或法律服务机构） | 随[编辑机构资料（F-RG-04）](../M5-机构管理/01-机构管理-PRD.md#F-RG-04)更新，本人不能修改 |
| 账号状态 | 见[账号状态](#account-status) | 由首次改密、本人找回、锁定，以及开发人员重新分配初始密码或重置凭据改变；产品内不能手工修改 |

| 时区 | 本人的时区偏好，决定界面上时间的展示 | 本人可修改，见[界面语言与时区（F-LG-09）](#F-LG-09) |

| 创建时间 | 账号建立的时间 | 系统记录，按本人时区展示并标明时区 |

<a id="account-status"></a>
### 3.3 账号状态

| 状态 | 含义 |
| --- | --- |
| 待首登改密 | 账号尚未完成必需的首次密码设置。新建的账号、开发人员重新分配初始密码后的运营账号、开发人员重置凭据后的机构账号处于此状态；完成首次登录强制改密或本人自助找回成功后变为正常 |
| 正常 | 已完成首次登录强制改密，可以按角色使用管理端 |
| 锁定 | 连续输错密码达到次数后的临时状态，到期自动回到锁定前的状态，见[连续失败与临时锁定（F-LG-05）](#F-LG-05) |

各状态下能做什么：

| 能力 | 未登录 | 待首登改密 | 正常 | 锁定 |
| --- | --- | --- | --- | --- |
| 打开登录入口、切换界面语言 | 可以 | 可以 | 可以 | 可以 |
| 登录 | 须输入正确的邮箱和密码 | 登录后只能进入首次登录强制改密 | 登录后按角色进入管理端 | 不能登录，输入正确密码后才看到锁定提示与剩余时间 |
| 首次登录强制改密 | 不能 | 必须完成 | 不适用 | 不能 |
| 账户设置（账号信息、修改密码、本人改邮箱、语言与时区） | 不能 | 不能，只能切换界面语言 | 可以 | 不能 |
| 业务菜单与消息通知 | 不能 | 不能 | 按[菜单权限矩阵（F-LG-10）](#F-LG-10)和[数据范围（F-LG-11）](#F-LG-11) | 不能 |
| 本人找回密码（两类账号共用） | 可从登录入口发起 | 可找回；成功后完成首次密码设置并变为正常 | 可找回，成功后保持正常 | 可发码；正确验证后告知锁定，不可完成重置 |
| 退出登录 | 不适用 | 可以 | 可以 | 不适用：锁定时该账号的全部登录已结束 |

- 机构被停用不改变账号状态，账号仍可登录；登录后的具体业务数据和操作由业务所属模块判断，见[停用与启用（F-RG-05）](../M5-机构管理/01-机构管理-PRD.md#F-RG-05)。本期没有账号停用、启用或人工冻结状态。
- 本人修改登录邮箱成功时，旧邮箱立即失去登录与找回资格，但永久保留给本账号，不得分配给其他账号；该账号未用验证码作废，已有登录保留，见[本人修改登录邮箱（F-LG-14）](#F-LG-14)。
- 账号状态的变化见[管理端账号状态机](./02-管理端登录与权限-流程图与状态机.md#state-1)。

<a id="credential-reset"></a>
#### 开发人员重新分配初始密码与重置凭据

开发人员在产品外改变账号凭据只有两种情形，产品内没有对应入口：

- 运营账号：开发人员为运营账号重新分配初始密码【确认】。
- 机构账号：运营添加机构时登录邮箱填错，由运营线下联系开发人员，开发人员把登录邮箱改为正确邮箱并设置新的初始密码，规则见[登录邮箱填错的纠正](../M5-机构管理/01-机构管理-PRD.md#login-email-fix)【确认】。

两种情形生效后的结果相同：

- 新初始密码立即生效；此前的初始密码和账号当前密码都作废。
- 该账号在所有设备和标签页上的登录立即结束，账号回到待首登改密；用新初始密码登录后进入[首次登录强制改密（F-LG-03）](#F-LG-03)。
- 账号锁定中时，锁定照常到期、不提前解除；到期后账号为待首登改密。
- 该账号未用的验证码和未使用的人机校验通过结果全部作废。
- 账号身份、角色、所属机构、历史操作记录、消息归属与已读状态、语言和时区不变，不新建账号。
- 新初始密码由线下告知账号使用者；平台不发送站内消息或邮件，不发送[密码变更通知（NT-LG-03）](./03-管理端登录与权限-消息通知.md#NT-LG-03)、[登录邮箱变更安全通知（NT-LG-04）](./03-管理端登录与权限-消息通知.md#NT-LG-04)，也不重发[机构账号开通邮件（NT-R03）](../M5-机构管理/03-机构管理-消息通知.md#NT-R03)【确认】。
- 按[安全记录](#security-records)留存一条记录；机构账号更正登录邮箱的，记录修改前后的邮箱。

<a id="password-rules"></a>
### 3.4 设置密码的共同规则

适用于所有设置密码的地方：[首次登录强制改密（F-LG-03）](#F-LG-03)、[修改密码（F-LG-08）](#F-LG-08)，[自助找回密码（F-LG-13）](#F-LG-13)，以及运营在[添加机构（F-RG-02）](../M5-机构管理/01-机构管理-PRD.md#F-RG-02)时设置的初始密码。开发人员分配的运营初始密码同样须满足长度、组成和空格规则。

依据：【参考件】。

| 规则 | 要求 |
| --- | --- |
| 长度 | 8～20 个字符 |
| 组成 | 至少包含 1 个英文字母和 1 个数字 |
| 空格 | 前后的空格自动去除；中间不能有空格 |
| 与当前密码 | 本人设置新密码时，不能与该账号当前密码相同 |
| 与初始密码 | 本人设置新密码时，不能与本账号最近一次被设置的初始密码相同 |
| 两次输入 | 本人设置新密码时须输入两次且一致；不一致时在第二次输入处说明并不能提交，改为一致后提示消失 |

- 输入过程中实时说明各项规则是否满足，全部满足才能提交；不展示密码强弱分档。
- 所有密码输入都可以由本人通过眼睛图标切换显示或隐藏【确认】；不以“显示／隐藏”文字按钮替代。
- 提交时由平台再次校验，不满足时不改变原密码，并说明哪一项不满足。
- 除本人在输入时主动切换显示外，界面、站内消息、通知邮件和日志中都不出现明文密码；账号开通邮件中的初始密码是用户确认的例外，见[机构账号开通邮件（NT-R03）](../M5-机构管理/03-机构管理-消息通知.md#NT-R03)。

<a id="security-records"></a>
### 3.5 安全记录

依据：与借贷平台《运营端账户与登录》一致【确认】。

- 以下事件须留存安全记录，可追溯到账号、时间与结果：登录成功与失败（含失败原因）、账号锁定与解除、密码变更（首次登录强制改密、自助找回重置、本人修改密码）、本人修改登录邮箱（含修改前后的邮箱）、开发人员重新分配初始密码或重置凭据（机构账号更正登录邮箱的，含修改前后的邮箱）。
- 安全记录保留 180 天【确认】。
- 本期不向运营或机构提供安全记录的查询、筛选或导出入口；安全记录只由平台内部留存，账号本人也不在账户设置中查看。需要排查账号异常时，由内部支持人员使用平台留存记录【确认】。
- 安全记录中不出现密码或验证码明文。

## 4. 登录与退出

<a id="F-LG-02"></a>
### 4.1 邮箱与密码登录（F-LG-02）

适用角色与前提：未登录的访问者。

依据：运营用开发分配的账号密码登录【确认】；机构用运营分配的邮箱和密码登录【确认】；共用管理端（BR-05）【确认】；防止账号被枚举、失败计数【参考件】。

- 管理端只有一个登录入口，运营和机构都从这里登录；不需要选择角色，平台按账号判断角色。
- 登录需要输入登录邮箱和密码。邮箱前后的空格自动去除、不区分大小写。
- 登录入口提供[忘记密码（F-LG-13）](#F-LG-13)，没有注册、验证码登录、钱包登录或“记住我”；验证码用于找回与改邮箱，不是登录方式。
- 未登录时访问管理端受保护页面，都先到登录入口，并记住原目标，见[登录后进入与返回原目标（F-LG-04）](#F-LG-04)。

登录结果：

| 情况 | 用户看到的结果 |
| --- | --- |
| 邮箱或密码为空 | 不能提交，指出未填写的一项 |
| 邮箱不是管理端账号，或密码错误 | 统一说明“邮箱或密码错误”；两种情况的提示、表现和响应快慢都不能区分。账号未锁定时，密码错误计入连续失败次数；锁定期间不计入，见[连续失败与临时锁定（F-LG-05）](#F-LG-05) |
| 邮箱和密码正确，账号待首登改密 | 进入[首次登录强制改密（F-LG-03）](#F-LG-03)，不进入任何业务页面 |
| 邮箱和密码正确，账号正常 | 登录成功，按[登录后进入与返回原目标（F-LG-04）](#F-LG-04)进入 |
| 邮箱和密码正确，账号锁定中 | 不能登录；说明账号已临时锁定和剩余时间，倒计时结束后可以直接重新登录，不需要刷新 |
| 网络或服务异常 | 说明暂时无法登录、请重试；已输入的邮箱保留，不计入失败次数 |

- 登录提交期间不能重复提交。
- 首次登录成功时，按浏览器推断写入时区偏好，见[界面语言与时区（F-LG-09）](#F-LG-09)。
- 登录成功、失败及原因、锁定与解除按[安全记录](#security-records)留存；日志中不记录密码。

流程参见：[登录与首次改密（图 1）](./02-管理端登录与权限-流程图与状态机.md#fig-1)。

<a id="F-LG-13"></a>
### 4.2 自助找回密码（F-LG-13）

适用角色与前提：已分配管理端账号的运营管理人员或机构本人，从同一登录入口选择忘记密码；平台按输入邮箱识别账号，不要求选择角色，无需开发人员或其他运营代操作【确认】。机构为启用或停用均可发起。

- 输入当前登录邮箱，校验格式与长度（去首尾空格、不区分大小写、最长 254 字符），发起获取验证码，须先通过[发码前人机校验](#captcha)，再满足[验证码参数](#code-params)中的重发间隔与发送限额；仅向本人账号当前有效登录邮箱发码，不向联系邮箱或已作废旧邮箱发码。
- 对未绑定管理端账号、已作废旧邮箱使用与有效邮箱相同的中性反馈，不透露邮箱是否注册或角色；真实发送失败时说明暂不能发送、可重试，不虚报发送成功，不改变账号。
- 输入收到的验证码，通过后设置两次新密码，遵守[设置密码的共同规则](#password-rules)。邮箱、验证码、新密码初始均为空；不得显示或回填原密码。
- 验证码通过后取得的本次找回验证资格自验证通过起 10 分钟内有效；超过 10 分钟仍未提交成功的不能提交，原密码不变，须重新获取并验证验证码。
- 验证码只能用于本账号本次找回。错误、过期、已使用、已作废、与邮箱或用途不匹配均不能继续，说明验证码无效，可重试或重新获取；位数、有效期、错误上限与发送限制见[验证码的共同规则](#verification-rules)。
- 正确验证后才检查账号锁定：锁定未到期则告知剩余时间，本次不能重置，不提前解锁，不修改密码；到期后重新完成找回。
- 提交时重新检查当前邮箱、账号状态及本次验证资格，防止找回途中邮箱被改或密码已被其他流程改动；资格失效须重新开始，原密码不被本次操作覆盖。
- 成功后新密码生效、旧密码与原初始密码失效；平台向本人发送[密码变更通知（NT-LG-03）](./03-管理端登录与权限-消息通知.md#NT-LG-03)，随后全部登录及未使用验证码结束，回到登录入口，用当前邮箱和新密码重新登录；不自动登录。
- 所有未锁定账号找回成功后均为正常；原来待首登改密的账号视为已通过邮箱验证完成首次密码设置，重新登录后不再进入首次登录强制改密。两类账号的身份、角色及所属机构不变。
- 取消、离开、校验失败或保存失败时密码不变、不结束已有登录，不发送密码变更通知；未完成的验证码按其有效性规则处理。
- 运营后台没有代重置入口，直接请求也拒绝。找回过程中只发送[找回密码验证码（NT-LG-01）](./03-管理端登录与权限-消息通知.md#NT-LG-01)，成功后发送密码变更通知（NT-LG-03）；不通过邮件发送新密码。

<a id="verification-rules"></a>
#### 验证码的共同规则

- 找回与本人改邮箱的验证码分用途、账号与目标邮箱，互不能混用；同一账号同一用途仅最新成功发送的验证码有效。
- 重新发送成功使旧码作废；更换目标邮箱使原目标验证码不可用于新目标；使用成功、过期或累计输错达到错误上限后不可再次使用。
- 密码变更成功或登录邮箱替换成功使该账号未用验证码全部作废。提交期间不能重复提交，同一次验证资格最多成功提交一次。
- 码值只在本人邮箱中提供，不出现在公开提示、日志或其他用户资料中；验证码有效不等于已登录或已获得业务权限。

<a id="code-params"></a>
**验证码参数**

依据：与借贷平台《运营端账户与登录》一致【确认】。

| 项目 | 要求 |
| --- | --- |
| 位数与输入 | 6 位数字。只接受数字；粘贴时自动去除空格和连字符 |
| 有效期 | 自发送成功起 10 分钟，到期后不能使用，须重新获取 |
| 单个验证码错误上限 | 同一个验证码累计输错 5 次即作废，之后即使输入正确也不能使用，须重新获取 |
| 重发间隔 | 同一邮箱两次发送至少间隔 60 秒 |
| 同一邮箱发送限额 | 24 小时内最多 10 次；找回密码与修改邮箱两种用途共用这一额度，换用途不能绕过 |
| 同一网络地址（IP）发送限额 | 每小时最多 20 次 |

- 间隔未满时不能获取或重发，并显示剩余秒数；发送成功后开始重发倒计时，刷新页面不会重置等待时间，剩余时间以平台为准。
- 同一邮箱 24 小时额度用完时不发码，并说明大约还需等待多久；同一网络地址额度用完时不发码，说明稍后再试。
- 邮件真实发送失败时，可立即重试 1 次，这次重试不计入发送额度，也不受重发间隔限制，但仍须重新通过[发码前人机校验](#captcha)。
- 上述等待与超限提示对任何邮箱都相同，不因该邮箱是否为管理端账号、属于哪个角色而不同；找回时对未绑定账号的邮箱同样计算间隔与额度。
- 验证码输错只计入该验证码自己的错误次数，不计入[连续失败与临时锁定（F-LG-05）](#F-LG-05)的密码连续失败次数。

<a id="captcha"></a>
#### 发码前人机校验

依据：与借贷平台《运营端账户与登录》一致【确认】。人机校验指滑块拼图这一类校验机制，具体呈现由设计确定。

- 找回密码与本人修改登录邮箱每次获取、重发验证码，包括邮件发送失败后的立即重试，都先完成人机校验，再检查重发间隔与发送限额，全部通过才发码。之前通过过、已登录或属于发送失败重试，都不能跳过。
- 邮箱格式等前置校验通过后发起获取或重发，才进入人机校验；此时尚不发码。

| 情况 | 用户看到的结果 |
| --- | --- |
| 人机校验通过 | 说明验证通过，本次校验结束；随后检查重发间隔与发送限额，通过后才发码。人机校验通过不等于验证码已发出 |
| 人机校验单次未通过 | 说明验证失败并自动更换题目；本次校验不结束，可以立即再试，不发码 |
| 人机校验连续未通过 3 次 | 除自动更换外，还可以主动更换题目；不发码 |
| 人机校验连续未通过 5 次 | 进入 60 秒冷却：期间不能发起校验，显示剩余时间；刷新页面或重新发起都不能绕过，到期后才能重新校验；不发码 |
| 关闭或取消人机校验 | 不发码，回到原流程；已填写的邮箱等内容保留，可以再次获取，仍须重新校验 |
| 人机校验题目加载失败 | 说明加载失败、可以重试；不发码，不说明已通过；已填写内容保留 |

- 一次通过只用于随后一次发送，且须是同一目标邮箱、同一用途、同一请求来源，2 分钟内有效；已用过、超过 2 分钟，或更换了邮箱、用途、来源，都须重新校验。绕过界面直接请求发码同样须满足。
- 该账号密码变更成功时，未使用的通过结果一并失效。
- 人机校验的失败与冷却只按本节处理，不计入[连续失败与临时锁定（F-LG-05）](#F-LG-05)的密码连续失败次数，也不计入验证码的错误次数。
- 人机校验的结果、冷却提示以及其后的发送限制提示，对任何邮箱都相同；找回时不能借此透露邮箱是否为管理端账号，锁定提示仍只在正确验证邮箱验证码后出现。

流程参见：[发码前人机校验（图 6）](./02-管理端登录与权限-流程图与状态机.md#fig-6)、[管理端找回密码（图 4）](./02-管理端登录与权限-流程图与状态机.md#fig-4)。

<a id="F-LG-03"></a>
### 4.3 首次登录强制改密（F-LG-03）

适用角色与前提：邮箱和密码正确、账号处于待首登改密的访问者。

依据：机构首次登录强制修改密码【确认】（BR-04）；运营账号同样首次登录强制改密【参考件】；改密后的密码变更通知与借贷平台一致【确认】。

- 新建账号、开发人员重新分配初始密码后的运营账号、开发人员[重置凭据](#credential-reset)后的机构账号处于待首登改密；用初始密码登录时必须先设置新密码，才能使用管理端，不能跳过或稍后再改。账号如果已通过本人自助找回完成首次密码设置，则直接变为正常，不再进入本流程。
- 改密前只能做三件事：设置新密码、切换界面语言、退出登录。其他页面和业务操作都不可用，绕过界面直接访问同样被拒绝。
- 设置新密码只需输入两次新密码，不需要再输入初始密码；新密码须符合[设置密码的共同规则](#password-rules)，并且不能与初始密码相同。
- 设置成功后：账号变为正常，初始密码失效；平台向本人发送[密码变更通知（NT-LG-03）](./03-管理端登录与权限-消息通知.md#NT-LG-03)，随后该账号的全部登录（包括当前这次）立即结束，回到登录入口并说明“密码已修改，请用新密码重新登录”。原目标仍保留，见[登录后进入与返回原目标（F-LG-04）](#F-LG-04)。
- 设置失败时（规则不满足、网络或服务异常）账号仍为待首登改密，初始密码仍可使用，可以重试。
- 改密期间登录到期或无操作登出时，回到登录入口，账号仍为待首登改密。
- 设置失败或改密期间登录结束时，不发送密码变更通知。

流程参见：[登录与首次改密（图 1）](./02-管理端登录与权限-流程图与状态机.md#fig-1)。

<a id="F-LG-04"></a>
### 4.4 登录后进入与返回原目标（F-LG-04）

适用角色与前提：登录成功、账号正常的用户。

依据：【参考件】。

- 有原目标时，回到原目标；回到之前仍按当前账号的角色和数据范围重新判断，无权访问时按[无权访问的处理（F-LG-12）](#F-LG-12)处理，不能把登录成功当作有权。
- 没有原目标，或原目标不在管理端范围内时，进入本角色的默认页面（具体页面由设计确定，须是本角色可见的菜单）。
- 原目标只在发起登录的同一个浏览器标签页内保留，包括中途完成首次登录强制改密、再用新密码重新登录的情况；刷新页面或在新标签页打开登录入口后登录，进入默认页面。
- 原目标只用于本次登录，不能被其他账号使用：换成另一个账号登录时，按该账号重新判断。

<a id="F-LG-05"></a>
### 4.5 连续失败与临时锁定（F-LG-05）

适用角色与前提：所有管理端账号。

依据：【参考件】。

- 以下三处密码错误共用同一个连续失败次数：登录时输错密码、修改密码时输错当前密码、本人修改登录邮箱时输错当前密码。
- 连续失败达到 3 次起，每次提示还剩几次机会。
- 连续失败达到 5 次，账号临时锁定。锁定时长逐级加长：第一次 15 分钟，第二次 30 分钟，之后每次 60 分钟；第一次锁定时提示“如再次触发，锁定时间会更长”。
- 登录成功后，连续失败次数清零，锁定时长回到第一级。
- 锁定到期自动解除时，连续失败次数归零，锁定级别保留：之后再次连续失败 5 次，按下一级时长锁定。
- 除上述两种情况外，连续失败次数和锁定级别没有其他清零方式。
- 锁定时，该账号在所有设备和标签页上的登录立即结束，包括由他人在其他设备输错密码触发的锁定。
- 锁定期间不能登录；这期间的密码错误不计入连续失败次数，也不延长锁定。
- 锁定没有提前解除的办法，本人找回、修改邮箱或开发人员[重置凭据](#credential-reset)都不会提前解除锁定。
- 锁定到期自动解除，账号回到锁定前的状态（待首登改密或正常）；锁定期间被开发人员重新分配初始密码或重置凭据的，到期后为待首登改密。
- 登录的锁定提示只在输入正确邮箱和密码后出现；找回的锁定提示只在正确验证当前邮箱验证码后出现，不能在发码前泄露账号是否存在。
- 锁定与解除不发通知，由本人从登录提示得知。

<a id="F-LG-06"></a>
### 4.6 登录有效期、无操作登出与退出（F-LG-06）

适用角色与前提：已登录的管理端用户，包括待首登改密时的受限登录。

依据：【参考件】。

| 规则 | 要求 |
| --- | --- |
| 登录有效期 | 自登录成功起 4 小时，到期即结束，不因操作延长 |
| 无操作登出 | 连续 2 小时没有真实操作，登录失效；不提前提醒，也不在失效时主动打断当前画面。用户下一次点击、键盘输入、提交或页面跳转时，平台不执行该次操作，转到登录入口并说明需要重新登录 |
| 什么算真实操作 | 点击、键盘输入、提交、页面跳转。页面自动刷新数据、消息自动更新不算 |
| 主动退出 | 账号入口中有唯一的退出入口；退出后该账号的全部登录立即结束 |
| 全部登录结束 | 主动退出、完成首次登录强制改密、本人修改密码、本人自助找回成功、账号锁定、开发人员重新分配运营初始密码或重置机构账号凭据时，该账号在所有设备和标签页上的登录都立即结束 |
| 修改登录邮箱后 | 本人修改登录邮箱成功后，该账号已有的登录全部保留，不因只改邮箱而结束【确认】；登录有效期与无操作登出照常计算 |

登录结束或失效后的处理：

- 登录有效期到期、主动退出、密码修改或重置等可立即感知的结束场景，回到登录入口并说明原因；连续 2 小时无操作失效时，在用户下一次真实操作时回到登录入口并说明需要重新登录。
- 可立即感知的结束场景立即清除受保护内容。无操作失效时，当前画面可以保留到下一次真实操作；届时清除受保护内容并进入登录入口。失效后不再显示新的受保护数据或迟到的操作结果。
- 尚未保存的内容不保留，结束前不能提交的操作不会被当作已完成。
- 同一浏览器的其他标签页一并结束。
- 后台的数据请求不会延长无操作时长；登录失效后不得继续返回或显示新的受保护数据。无操作失效后的第一次真实操作不得被执行。
- 界面语言保留，不随退出而恢复默认。

流程参见：[登录有效期、无操作登出与退出（图 2）](./02-管理端登录与权限-流程图与状态机.md#fig-2)、[登录状态机](./02-管理端登录与权限-流程图与状态机.md#state-2)。

## 5. 账户设置

<a id="F-LG-07"></a>
### 5.1 账号入口与账号信息（F-LG-07）

适用角色与前提：账号正常、已登录的运营管理人员和机构。

- 登录后在任何页面都能看到账号入口，显示账号名称、登录邮箱和角色。机构账号同时显示所属机构及机构类型；机构已停用时只说明机构当前为停用状态，不说明任何具体业务对象是否可见或可继续办理。
- 账号入口中有：账户设置和退出登录。消息通知的入口与未读数由[消息通知（M7）](../../两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-02)定义。
- 账户设置展示[账号信息](#account-info)中的全部项目，并向两类账号提供修改密码、[本人修改登录邮箱（F-LG-14）](#F-LG-14)、界面语言和时区的修改。
- 账户设置不展示权限清单，不提供改角色、新增账号或修改他人邮箱的入口。
- 读取失败时说明暂时无法读取、可以重试，不显示为空。

<a id="F-LG-08"></a>
### 5.2 修改密码（F-LG-08）

适用角色与前提：账号正常、已登录的本人。

依据：运营可修改密码【建议·已采纳】；机构之后可修改密码【确认】；先验证当前密码、密码变更通知与借贷平台一致【确认】；失败计数【参考件】。

- 先按[验证当前密码](#reauth)确认本人身份，通过后在有效期内输入两次新密码并提交；新密码须符合[设置密码的共同规则](#password-rules)。
- 当前密码输错时不能继续，说明当前密码不正确；输错计入[连续失败与临时锁定（F-LG-05）](#F-LG-05)的连续失败次数，达到 5 次时账号锁定、该账号全部登录结束。
- 修改成功后：新密码立即生效；平台向本人发送[密码变更通知（NT-LG-03）](./03-管理端登录与权限-消息通知.md#NT-LG-03)，随后该账号的全部登录（包括当前这次）立即结束，回到登录入口并说明“密码已修改，请用新密码重新登录”。
- 修改失败、取消或离开时，原密码不变，不发送密码变更通知。
- 提交期间不能重复提交；修改期间登录已结束时，修改不生效。

<a id="reauth"></a>
#### 验证当前密码

依据：与借贷平台《运营端账户与登录》一致【确认】。适用于修改密码（F-LG-08）和[本人修改登录邮箱（F-LG-14）](#F-LG-14)。

- 每次修改密码或登录邮箱，都先输入当前密码完成验证，通过后才能填写新密码或新邮箱；验证结果只用于本次修改。
- 当前密码输错计入[连续失败与临时锁定（F-LG-05）](#F-LG-05)的连续失败次数；账号锁定后不能继续。
- 验证通过后 10 分钟内有效【确认】。超过 10 分钟仍未提交成功的，不能提交，须重新验证当前密码；本次修改不生效，原密码与原邮箱不变。
- 修改期间登录结束（到期、无操作、退出或锁定）时，验证结果一并失效，修改不生效；重新登录后重新发起。

流程参见：[修改密码（图 3）](./02-管理端登录与权限-流程图与状态机.md#fig-3)。

<a id="F-LG-14"></a>
### 5.3 本人修改登录邮箱（F-LG-14）

适用角色与前提：正常、已登录的运营管理人员或机构本人，仅修改当前登录账号的邮箱，两类账号共用本功能，无需他人审批或预先开放【确认】。机构为启用或停用均可使用。

- 在账户设置发起，依次完成[验证当前密码](#reauth)、填写新登录邮箱、获取并输入新邮箱验证码、提交。当前密码错误计入[连续失败与临时锁定（F-LG-05）](#F-LG-05)；账号被锁定或登录已结束则不能继续。
- 新邮箱初始为空，去首尾空格、不区分大小写、邮箱格式且最长 254 字符；须与当前登录邮箱不同。该邮箱从未被管理端账号使用，或历史上只归属于本账号时才可使用；历史上归属于其他账号时说明不可用，不披露占用人或历史。
- 向新邮箱发送[修改邮箱验证码（NT-LG-02）](./03-管理端登录与权限-消息通知.md#NT-LG-02)，不要求旧邮箱收码；每次获取或重发前须先通过[发码前人机校验](#captcha)；规则与参数见[验证码的共同规则](#verification-rules)，发送限额与找回密码共用同一邮箱额度。改填新邮箱须重新获取其验证码。
- 当前密码验证仍在有效期内、新邮箱验证通过、登录有效、账号正常且提交时新邮箱仍未归属于其他账号，全部满足后才使新邮箱生效、旧邮箱同时作废；确认时说明旧邮箱将作废、此后使用新邮箱与当前密码登录，当前登录保留。
- 成功后说明修改成功，账户设置与账号入口显示新邮箱。旧邮箱立即失去当前账号的登录与找回资格，旧邮箱配任意密码不能登录，以旧邮箱发起找回得到与未注册邮箱相同的中性反馈；旧邮箱仍永久归属于本账号，不得分配给其他账号。本账号以后验证旧邮箱后可以重新使用；该账号未用验证码全部失效；当前密码保留，账号仍为正常，不新增首登改密。
- 该账号在所有设备上的已有登录保留，不因只改邮箱而结束【确认】；登录有效期与无操作登出照常计算，见[登录有效期、无操作登出与退出（F-LG-06）](#F-LG-06)。
- 新邮箱生效后，平台向新邮箱和旧邮箱各发送一封[登录邮箱变更安全通知（NT-LG-04）](./03-管理端登录与权限-消息通知.md#NT-LG-04)【确认】；投递失败不回滚已生效的修改。改邮箱不发送站内消息。
- 两类账号的账号身份、名称、角色、权限、数据范围、历史操作记录、消息归属与已读状态、语言和时区保持不变，不新建第二个账号。运营账号仍为同一运营管理员，不能通过改邮箱取得他人身份或改变全体运营消息的共享规则；机构身份、启用或停用状态、业务归属不变，不同步修改联系人邮箱。
- 当前密码错误、当前密码验证已过期、新邮箱不可用、验证码无效、取消、发送或保存失败时原邮箱与密码保持原值，不发送安全通知；当前密码输错触发锁定时按锁定规则结束登录。
- 本人在不同设备同时修改邮箱时，以当前有效邮箱为准，只有一次修改成功；信息已变更则要求重新确认，不覆盖他方已完成的变更。
- 原账号开通邮件中的旧凭据不会因回看邮件恢复有效。

流程参见：[本人修改登录邮箱（图 5）](./02-管理端登录与权限-流程图与状态机.md#fig-5)。

<a id="F-LG-09"></a>
### 5.4 界面语言与时区（F-LG-09）

适用角色与前提：界面语言对所有管理端访问者（包括未登录、待首登改密）；时区对账号正常、已登录的本人。

依据：平台支持中文和英文【确认】；上游时间带时区、按用户所选时区换算展示【确认】（见[可信资产 · 语言与时区](../../两端共用/M2-可信资产/01-可信资产-PRD.md#locale)）；默认语言、时区写入方式【参考件】。

**界面语言**

- 有两种：简体中文、English。登录入口和登录后的任何页面都可以切换。
- 切换后立即生效，不需要刷新；已填写但未提交的内容不丢失。本平台的界面文字、站内消息的标题和正文都按所选语言展示，邮箱、金额、数量、时间、编号等业务值不变；用户填写的意见、备注等按原文展示，不翻译。站内消息的语言规则见[消息通知 · 内容与语言](../../两端共用/M7-消息通知/01-消息通知-PRD.md#content-rules)。
- 登录后切换即保存为本人的语言偏好，换浏览器或设备登录后仍按上次所选；保存失败时说明并恢复为切换前的语言，可以重试。
- 未登录时切换的语言保存在当前浏览器，下次打开登录入口仍按上次所选，不保存到任何账号。
- 登录后，账号已保存过语言偏好时按账号偏好展示；没有保存过时沿用当前页面正在使用的语言；都没有时默认 English。
- 退出后保留当前语言。

**时区**

- 首次登录成功时，按浏览器推断写入本人的时区偏好；推断不出时为 UTC。
- 本人可以在账户设置中修改，可选范围为有效的 IANA 时区（例如 Asia/Shanghai、UTC），与面客端[偏好设置：界面语言与时区（C-PROFILE-02）](../../面客端/M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#C-PROFILE-02)的时区口径相同。修改即保存，保存成功后立即生效；保存失败时保留原时区，可以重试。
- 管理端所有时间按本人时区展示并标明时区；时区只影响展示，不改变到期、逾期等业务判断。
- 待首登改密的受限登录期间不能修改时区。

语言与时区变更不发送任何通知。

依据：M5 负责按当前账号身份执行统一隔离和越权拦截；业务对象的授权条件、产生、变更和终止均由对象所属模块定义。

| 数据 | M5 的权限边界 |
| --- | --- |
| 各业务模块的数据 | 所属模块给出当前账号是否有权的结果；M5 不定义授权关系，只保证无权数据不会通过列表、详情、统计、搜索、导出或文件访问泄露 |
| 消息 | 收件范围与可见性由[消息通知（M7）](../../两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-01)定义，M5 只提供当前账号身份和统一拦截 |
| 机构档案 | 机构账号只能在账号入口与账户设置中查看本机构名称、类型和状态；不能查看其他机构的机构档案。业务对象中展示哪些机构信息（如名单内其他机构的名称）由业务所属模块定义 |

- 范围判断由平台完成，不能只靠界面隐藏；改写链接中的编号、机构或角色标识，也拿不到其他机构的数据。
- 机构启停只由 M5 提供机构状态；停用后的任何业务数据或操作结果由对象所属模块决定。

<a id="F-LG-12"></a>
### 6.3 无权访问的处理（F-LG-12）

适用角色与前提：所有管理端访问者。

| 情况 | 结果 |
| --- | --- |
| 未登录访问管理端受保护页面 | 先到登录入口，登录后按[登录后进入与返回原目标（F-LG-04）](#F-LG-04)处理 |
| 待首登改密时访问其他页面 | 回到首次登录强制改密 |
| 访问本角色不可见的菜单 | 不返回任何内容，说明无权访问，可以回到默认页面 |
| 访问数据范围以外的某一条业务数据，或访问不存在的数据 | 两种情况结果完全相同：不返回任何内容，统一说明无权查看或内容不存在，不透露该数据是否存在；具体措辞由各业务模块与设计确定 |
| 发起当前角色没有的操作 | 被拒绝，数据不变，说明无权操作；具体操作权限由所属模块定义 |

- 从消息或其他记录打开某条数据时，按该数据所属模块的权限重新判断，不因收到消息或看到记录而获得权限。
- 越权访问须可追溯：访问不可见菜单、访问数据范围以外的数据、发起无权操作被拒绝时，平台留存记录，可追溯到账号、时间和被拒绝的访问对象。

<a id="pending"></a>
## 8. 待确认事项与依赖

本模块没有业务待确认事项。安全记录由平台内部留存 180 天，本期不向运营或机构提供查询、筛选或导出入口。

机构核心资料与机构级基础资质规则见[机构档案与账号](../M5-机构管理/01-机构管理-PRD.md#fields)。

### 依赖

- 开发人员：初始分配运营账号的登录邮箱、姓名和初始密码，以及为运营账号重新分配初始密码；分配后运营本人使用平台忘记密码和修改邮箱能力。机构添加时登录邮箱填错的，接到运营线下联系后按[登录邮箱填错的纠正](../M5-机构管理/01-机构管理-PRD.md#login-email-fix)重置该机构账号的凭据，新初始密码线下告知。两种操作的结果见[开发人员重新分配初始密码与重置凭据](#credential-reset)。
- 邮件服务（D8）：投递找回与新邮箱验证码、密码变更通知邮件和登录邮箱变更安全通知。验证码发送失败不得提示已发出，不改变密码、邮箱或登录状态；安全通知投递失败不回滚已生效的密码或邮箱。
- [消息通知（M7）](../../两端共用/M7-消息通知/01-消息通知-PRD.md#MSG-01)：按本人收件范围承接密码变更通知的站内消息。
- 需求方：上线前提供安全通知中“非本人操作时的求助方式”的具体联系渠道。该渠道须为长期有效、可审计的官方渠道，在账号无法登录时仍可使用；不使用个人联系方式或占位内容。中文、英文通知使用同一渠道，渠道变化不改变密码、邮箱及通知触发规则。
- 浏览器时区：用于首次登录时写入时区偏好；推断失败时为 UTC。
- 会话与锁定计时、真实操作的判定，人机校验的判定与冷却，当前密码验证的有效期，安全记录的保留，以及验证码有效期、重发间隔与发送限额的计时和计数由研发实现，测试负责验证。
