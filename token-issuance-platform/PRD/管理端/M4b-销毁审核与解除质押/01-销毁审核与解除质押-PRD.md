# 销毁执行、解除资产托管与代币台账 · 功能与业务规则

2026-11-09｜管理端：运营管理人员、资产托管机构，法律服务机构与审计机构只读｜需求评审稿

本模块共四册：01 本册、[02 流程图与状态机](./02-销毁审核与解除质押-流程图与状态机.md)、[03 消息通知](./03-销毁审核与解除质押-消息通知.md)、[04 验收](./04-销毁审核与解除质押-验收.md)。为保持历史链接有效，目录和文件名暂沿用“销毁审核与解除质押”；正文已取消销毁审核，资产托管机构的动作统一称为“解除资产托管”。编号沿用原值，缺号不代表遗漏。

<a id="module"></a>
## 1. 模块是什么

本模块是管理端对代币销毁及其后续事项的承接：运营只读查看全平台销毁记录和代币台账，并调整代币单位价值；链上销毁成功后，本代币唯一的资产托管机构对代币对应的现实资产（应收账款）解除托管，并上传解除托管通知文件；名单内的法律服务机构、审计机构同步知悉结果并只读查看。

企业申请销毁、钱包签名与提交的规则属于我的代币与销毁申请（M4a），见[申请销毁（C-BURN-01）](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#C-BURN-01)；合约必须执行的链上校验属于合约管理（M6），见[销毁发起地址限制（F-CT-06）](../M6-合约管理/01-合约管理-PRD.md#F-CT-06)。本模块不审核、不签名、不代发销毁交易，只承接企业钱包交易形成的申请和链上结果。

**完整示例。** 企业 A 在 M4a 通过资格校验后，由铸造到账地址 A1 签署并广播一笔销毁交易，平台生成销毁申请，运营在销毁记录中可见“销毁中”。若链上确认失败，本笔申请结束为销毁失败，企业和运营各收到一条失败消息；企业之后在 M4a 发起的是新申请。若确认成功，企业收到成功消息，运营收到成功知会；该笔发行唯一的资产托管机构 X 收到待办，名单内的法律服务机构 Y、审计机构 Z 收到销毁结果。X 填写解除说明、上传解除托管通知文件后完成解除资产托管，企业收到已解除结果。若该代币既没有提交锁也没有销毁中申请，A 绕过平台入口直接调用合约且链上销毁成功，平台仍承认结果、补建“非平台入口”记录、按到期、结清、融资三项记录风险项，并进入相同的通知和解除流程。

### 1.2 本期不做

- 运营审核、通过、驳回或手动重试销毁；运营也不代企业发起。
- 违约或质押中代币的强制销毁，以及运营改地址的入口。
- 资产托管机构发起销毁，或运营代资产托管机构解除资产托管。
- 审计机构、法律服务机构办理解除资产托管；资产托管机构的变更、补登或重新指定。
- 销毁成功后恢复代币。

<a id="terms"></a>
## 2. 术语与状态

| 术语 | 定义 |
| --- | --- |
| 销毁中 | 销毁申请状态：企业钱包已广播销毁交易，仍在执行或结果未确认 |
| 销毁失败 | 销毁申请状态：本笔申请已终结且没有形成成功销毁事实；不在原申请上重试 |
| 销毁成功 | 销毁申请状态：链上销毁结果已确认，代币不可再销毁 |
| 资产托管 | 资产托管机构对代币所对应现实资产（应收账款）的托管；从铸造成功开始，到资产托管机构解除托管为止；与下游融资质押相互独立 |
| 托管中 | 资产托管状态：从铸造成功开始，到资产托管机构完成解除为止；代币已销毁、尚未解除时仍为托管中 |
| 已解除托管 | 资产托管状态：资产托管机构已提交有效解除记录 |
| 待解除托管事项 | 销毁成功后为本代币资产托管机构生成的待办事项，资产托管状态仍为托管中；是待办，不是销毁申请状态或资产托管状态【确认】 |
| 提交锁 | 企业调起钱包签名前平台对该代币加的临时占用，不是申请，按 M4a [销毁提交锁与交易归属](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#submit-lock) |
| 发行地址 | 代币铸造时的第一个持有地址，即铸造到账地址；作为代币发行信息的一项记录展示【确认】 |
| <a id="listed-institutions"></a>名单内机构（本代币） | 该代币原发行申请铸造成功时[锁定发行机构名单](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-mint)中的全部机构，包括一家资产托管机构，以及可能有的法律服务机构和审计机构。原发行申请指该代币对应的、唯一铸造成功的那笔发行申请；同一资产此前被运营驳回、再按 M3a [驳回后重新发起（C-ISSUE-09）](../../面客端/M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#C-ISSUE-09)形成的其他申请，其锁定名单内的机构不属于本代币的名单内机构，不因此取得代币台账、销毁结果、解除资产托管或相关消息 |
| <a id="custodian"></a>资产托管机构（本代币） | 名单内机构中唯一一家资产托管机构，按 M3b 名单记录的分配时机构类型判断。M3b 规定每种机构类型最多分配一家、发起铸造前须有一家资产托管机构，见 [选择合约并发起铸造](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#A-ISSUE-04)，因此每枚代币有且只有一家资产托管机构。权限与发行审核时保持一致，机构之后停用、更名、在 M5 修改类型或账号邮箱变化都不改变，也不按当前启用机构重新分配 |
| 交易来源 | 平台入口或非平台入口；前者是归入平台提交锁或销毁中申请的交易，后者是该代币既没有提交锁也没有销毁中申请时平台监听到的有效销毁，由平台补建记录 |

## 3. 权限、入口与共同异常

- 运营可查看全平台销毁记录和代币台账，调整未销毁代币的单位价值，并收到销毁成功或失败知会、销毁超时待处理及单位价值调整超时待处理；没有销毁发起、审核、驳回、重试或解除资产托管权限。
- 只有[本代币的资产托管机构](#custodian)可以办理解除资产托管；名单内的法律服务机构、审计机构，以及运营和企业都不能办理。
- [名单内机构](#listed-institutions)可只读查看本机构参与发行的代币台账；可查看该代币各笔销毁申请的交易来源和[处理进度](#progress)中的全部事件（含企业名称与交易发送地址）【确认】，以及解除资产托管记录（含解除托管通知文件）；原始失败说明仅运营可见，法律服务机构、审计机构不看解除操作人；不看其他发行的数据。
- 解除提交时重新校验当前账号属于本代币的资产托管机构；不满足时拒绝提交，并返回最新结果。
- 本模块在管理端提供三个菜单【确认】：
  - **销毁记录**：运营可见，机构不可见；进入[销毁记录列表（A-BURN-01）](#A-BURN-01)。
  - **解除托管**：机构可见，运营不可见；进入[解除资产托管列表（R-RELEASE-01）](#R-RELEASE-01)。三类机构的菜单相同，只有资产托管机构会有解除事项。
  - **代币台账**：运营与机构均可见；运营进入[全平台代币台账（A-TOKEN-01）](#A-TOKEN-01)，机构进入[本机构代币台账（R-TOKEN-01）](#R-TOKEN-01)。
- 运营知会、销毁记录列表和代币台账可进入准确销毁记录；进入只查看，不触发业务。
- 列表操作列只提供“查看”，与点击本行编号进入同一详情；办理动作只在详情中提供。代币编号、销毁申请编号、资产编号和发行申请编号分别进入其有权详情；无权与不存在不区分。
- 所有详情的最上方，所属网络、代币图标与代币符号排在编号之前；代币编号与销毁申请编号不能省略。
- 读取失败与无数据必须区分；未知不补成失败或成功。结果未确认时获取原结果，不新建申请、不重复销毁。

<a id="A-BURN-01"></a>
## 4. 销毁记录列表（A-BURN-01）

适用角色：运营管理人员。

- 查看全平台销毁申请，包括销毁中、销毁失败、销毁成功的记录及非平台入口补建记录；同一代币的多笔申请独立保留。
- 展示销毁申请编号、代币编号、企业、资产编号、完整销毁数量及代币符号、提交时间、交易来源、销毁申请状态、资产托管状态和操作；非平台入口须直接可辨认，其提交时间为链上确认时间。
- 销毁申请状态与资产托管状态分列展示【确认】：资产托管状态为托管中或已解除托管；销毁成功、资产托管机构尚未解除的记录为托管中。
- 可按申请编号、代币编号、企业、资产编号、交易来源、销毁申请状态和资产托管状态查找；缺省按提交时间由新到旧。
- 分页、返回位置、空状态与读取失败按可信资产（M2）的[业务列表通用规则](../../两端共用/M2-可信资产/01-可信资产-PRD.md#list-common)。

<a id="A-BURN-02"></a>
## 5. 销毁记录详情（A-BURN-02）

适用角色：运营管理人员；全程只读。

- 展示[代币与申请信息](#handoff-token)、[销毁交易记录](#handoff-signature)、[条件与执行记录](#handoff-execution)、[销毁结果](#handoff-burn)及已产生的[解除资产托管记录](#handoff-release)；非平台入口记录另展示[非平台入口风险项](#burn-risk)。
- 到期、结清、融资与当前所在地址是企业提交时的系统校验快照，不是运营待核对任务；运营不能覆盖结果。
- 代币在质押地址（含违约）时，按质押地址和融资中如实展示；本模块不提供强制销毁、改地址、审核或驳回入口。
- 销毁中满 10 分钟仍无明确结果时，运营收到[销毁超时待处理（NT-A08）](./03-销毁审核与解除质押-消息通知.md#NT-A08)，打开后进入本详情；详情只读，不提供线上超时处理、重试或判失败入口，处理方式按[销毁结果承接（A-BURN-03）](#A-BURN-03)。
- 处理进度按[销毁与解除的处理进度](#progress)展示。

<a id="progress"></a>
### 5.1 销毁与解除的处理进度

本节适用于销毁记录详情（运营）、[解除资产托管详情（R-RELEASE-02）](#R-RELEASE-02)（资产托管机构）和[本机构代币台账（R-TOKEN-01）](#R-TOKEN-01)中各笔销毁申请的查看（名单内机构），参照 M3b [申请详情（A-ISSUE-02）](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#A-ISSUE-02)分两层呈现【确认】：

- **进度概览**（页面上方）：只说明“资格校验、钱包提交、代币销毁、解除托管”四个阶段各自为完成、当前、失败或未开始，并展示已取得的交易来源、办理机构名称和时间；不展示操作人和失败说明。非平台入口的资格校验阶段显示“未经过平台入口校验”，不显示为已通过。
- **操作进度**（页面最下方）：按发生时间从早到晚记录下表事件；每条展示业务动作或结果、操作主体的角色与账号或地址、发生时间及其时区、处理结果。未取得的值不编造。

| 事件 | 操作主体 |
| --- | --- |
| 企业钱包提交 | 企业名称与交易发送地址（铸造到账地址） |
| 平台补建记录 | 平台 |
| 链上确认失败 | 链上结果 |
| 链上确认成功 | 链上结果 |
| 解除资产托管 | 资产托管机构名称与操作人账号 |

- 每条只附两类说明：链上确认失败附已取得的原始失败说明，仅运营可见；解除资产托管附解除说明。交易来源、后续指引、销毁数量等不在操作进度中重复，分别在进度概览和详情其他信息中查看；通知文件在解除记录中查看【确认】。
- 消息发送、阅读和文件访问不推动申请状态，不进入操作进度；提交锁不是申请，也不进入操作进度。
- 可见范围【确认】：
  - 运营看全部事件、操作人和原始失败说明。
  - [名单内机构](#listed-institutions)（含资产托管机构）看交易来源和全部事件，含企业名称与交易发送地址；不看原始失败说明。
  - 资产托管机构可见本机构办理解除的操作人账号；名单内的法律服务机构、审计机构看到解除事件的办理机构名称，不看操作人。
  - 企业不展示本节操作进度，销毁结果与解除结果在 M4a 查看，按[解除资产托管记录及企业可见范围](#handoff-release)。
- 上下位置与信息分层为页面约束；进度条与时间线的视觉样式由原型定义。

<a id="A-BURN-03"></a>
## 6. 销毁结果承接（A-BURN-03）

适用前提：企业已在 M4a 按[销毁交易签名](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#burn-signing)广播交易，或平台监听到合约上的有效销毁。

<a id="platform-signing"></a>
- 销毁交易由企业钱包以铸造到账地址签名并直接提交，平台不签名、不代发、不代付 gas，也不设待运营审核阶段；申请的生成时点、提交锁与提交异常按 M4a [提交与结果](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#burn-submit)和[销毁提交锁与交易归属](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#submit-lock)。
- 执行仍在进行或结果未确认时保持销毁中；平台不按超时自行定义失败，也不重复提交。
- 确认失败时记录销毁失败，分别向企业和运营发送失败消息；原申请不重试。企业按 M4a [销毁失败后重新发起](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#C-BURN-05)创建新申请。
- 确认成功时记录销毁成功的数量和时间，把结果同步给业务关联方：向企业发成功消息、向运营发成功知会，为[本代币的资产托管机构](#custodian)生成待解除托管事项和待办消息，并向名单内的法律服务机构、审计机构各发一条销毁结果消息。资产托管机构自此取得解除资产托管的权限。消息失败不改变销毁事实。
- 原合约已被平台停用不影响承接链上结果；停用不等于链上执行失败，见 M6 [停用与既有业务](../M6-合约管理/01-合约管理-PRD.md#inflight)。

<a id="burn-timeout"></a>
**销毁中或提交锁长时间没有结果【确认】**

- 交易被加速替换、取消、被网络丢弃或长时间没有明确结果时，由平台开发线下处理；平台不提供线上超时处理入口。
- 申请进入销毁中满 10 分钟仍无明确成功或失败结果时，向全体运营发送一次[销毁超时待处理（NT-A08）](./03-销毁审核与解除质押-消息通知.md#NT-A08)，提示运营联系平台开发；企业继续看到销毁中。
- 开发查明后，平台按实际结果收口：原交易被同一发送序号的其他交易替换、且该交易完成了有效销毁的，并入原申请记为销毁成功，不另建非平台入口记录；确认原交易不会上链且没有完成销毁的，原申请记为销毁失败。收口后按成功或失败分支发送消息。
- <a id="lock-timeout"></a>代币有提交锁、自加锁起满 10 分钟仍未取得交易标识时，同样向全体运营发送一次[销毁超时待处理（NT-A08）](./03-销毁审核与解除质押-消息通知.md#NT-A08)，以代币编号识别（此时没有销毁申请编号），打开后进入该代币在[全平台代币台账（A-TOKEN-01）](#A-TOKEN-01)中的详情；每次提交锁最多一次。企业继续看到“确认中”。开发线下查明后按链上实际结果收口：监听到归入本次提交的交易时，创建平台入口的销毁申请并按链上结果处理；确认交易未广播时解除提交锁。提交锁规则按 M4a [提交锁长时间未收口](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#lock-timeout)。

<a id="burn-attribution"></a>
**交易归属与非平台入口补建【确认】**

- 平台必须监听合约销毁结果。
- 代币存在提交锁或销毁中申请时，从该代币发行地址（铸造到账地址）发出的有效链上销毁，一律归入该笔提交或申请，交易来源为平台入口，不另建非平台入口记录；归属规则按 M4a [销毁提交锁与交易归属](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#submit-lock)。
- 只有该代币既没有提交锁、也没有销毁中申请时监听到的有效销毁，才补建销毁记录，来源标记为“非平台入口”：补建记录直接为销毁成功，没有销毁中阶段，销毁中起始时间为空；以链上成功事实更新代币，并按成功分支发送全部消息、为本代币的资产托管机构生成待解除托管事项。
- 非平台入口销毁记录缺少平台提交条件快照，相关字段标记“未经过平台入口校验”，不得补写为已通过；链下资格未通过或无法确认时只记为[非平台入口风险项](#burn-risk)，不能撤销链上结果或继续把代币显示为有效；运营只读审计，不得要求企业再次销毁。

<a id="burn-risk"></a>
### 6.1 非平台入口风险项

- 生成时点：非平台入口销毁在链上确认时，平台按下表三项生成风险项，记录确认时点各项的结论和确认时间【确认】。

| 风险项 | 确认时点的判断 | 构成风险的结论 |
| --- | --- | --- |
| 到期 | 是否已达到或超过该笔应收账款的到期时点，到期时点按 M2 [到期时点](../../两端共用/M2-可信资产/01-可信资产-PRD.md#due-time) | 未到期，或无法确认 |
| 结清 | 上游是否明确提供已结清 | 未结清，或无法确认 |
| 融资 | 是否有融资或质押，按下游融资结果与链上质押记录 | 有融资或质押、两者不一致，或无法确认 |

- 三项都满足时记录为无风险；任一项不满足或无法确认即为风险，并标明是哪一项。
- 风险项是确认时点的只读记录，之后不重算、不修改，也不改变销毁结果、资产托管状态或解除权限。
- 运营在[销毁记录详情（A-BURN-02）](#A-BURN-02)查看，[本代币的资产托管机构](#custodian)在[解除资产托管详情（R-RELEASE-02）](#R-RELEASE-02)查看【确认】；企业以及名单内的法律服务机构、审计机构不展示。
- 资产托管机构照常可以解除资产托管；有风险的记录在解除详情中显著提示风险，不增加解除前置条件【确认】。
- 平台入口的申请不生成风险项，其校验结果按[提交条件快照](#handoff-execution)展示。

<a id="R-RELEASE-01"></a>
## 7. 解除资产托管列表（R-RELEASE-01）

- 从“解除托管”菜单进入；也可从 NT-R02 消息或[本机构代币台账（R-TOKEN-01）](#R-TOKEN-01)前往对应事项。
- 资产托管机构查看本机构作为[本代币的资产托管机构](#custodian)的待解除托管事项与已解除托管记录；只有销毁成功形成待解除托管事项，未销毁、销毁中或销毁失败不形成。
- 展示代币编号、销毁申请编号、企业、资产编号、销毁数量与代币符号、销毁成功时间、交易来源、资产托管状态（托管中或已解除托管）和操作。
- 可按代币编号、销毁申请编号、企业名称、资产编号查找，按资产托管状态（托管中、已解除托管）和交易来源筛选【确认】。
- 默认托管中（待解除）的记录排在前，同组内按销毁成功时间由新到旧排列【确认】；分页、返回位置、空状态与读取失败按可信资产（M2）的[业务列表通用规则](../../两端共用/M2-可信资产/01-可信资产-PRD.md#list-common)。
- 每行提供“查看”进入详情，待解除事项与已解除记录都可查看；消息已读不代表已解除。
- 本机构没有待解除事项或已解除记录时说明暂无解除事项；法律服务机构、审计机构进入后为空，没有办理事项。

<a id="R-RELEASE-02"></a>
## 8. 解除资产托管详情（R-RELEASE-02）

- 仅[本代币的资产托管机构](#custodian)可查看和办理；展示代币、企业、资产、发行、交易来源、销毁成功事实、托管开始时间和已有解除记录，处理进度按[销毁与解除的处理进度](#progress)展示。
- 非平台入口记录展示[非平台入口风险项](#burn-risk)；有风险时显著提示风险项及各项结论，资产托管机构仍可照常办理解除。
- 销毁成功且尚未解除时可进入提交；结果未知、未销毁或已解除时不再提供动作；已解除时只看原记录。
- 销毁成功依据缺失或与解除记录矛盾时，说明当前无法办理；资产托管机构长期不办理的，平台也不催办。两种情形都由运营线下沟通处理，平台不提供线上处理通道或提醒【确认】。

<a id="R-RELEASE-03"></a>
## 9. 解除资产托管并留记录（R-RELEASE-03）

| 项目 | 规则 |
| --- | --- |
| 解除说明 | 必填文本，无默认值；去除首尾空白后不能为空 |
| 解除托管通知文件 | 必填；每次提交 1 至 10 份；格式、单份大小和按实际内容识别的规则与 M3b [机构材料追加](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#R-ISSUE-06)的单次文件规则相同；已选文件须全部上传成功，上传中或失败未移除时不能提交 |

- 提交时重新校验当前机构是本代币的资产托管机构、销毁成功事实及尚未解除；并发或重复提交只产生一笔生效记录，后到的提交被拒绝并返回已解除结果。
- 取消或提交失败时待解除托管事项保持不变、资产托管状态仍为托管中，已填写内容不形成记录；提交结果未确认时先取得原结果，不重复解除。
- 成功后记录机构、操作人、时间、原文解除说明和通知文件，资产托管状态变为已解除托管，待解除托管事项关闭，并向资产所属企业发送结果消息。
- 解除托管通知文件保存后不可覆盖、替换或删除；读取失败时说明暂时无法获取，不显示为没有文件。
- 可见范围按[解除资产托管记录及企业可见范围](#handoff-release)；运营只查看结果信息，不能代办。

<a id="A-TOKEN-01"></a>
## 10. 全平台代币台账（A-TOKEN-01）

适用角色：运营管理人员。

- 查看全平台铸造成功代币，包含已销毁代币；铸造中或铸造失败的申请不进入台账。
- 列表按[代币台账的列表与详情](#ledger-columns)展示；台账只查看，不产生销毁权限。
- 可追溯原发行申请（铸造成功的那笔）、关联资产、历次销毁申请和最终解除记录；同一资产被驳回的其他申请不在台账展示，运营可从资产详情进入查看。
- 未销毁且不在销毁中的代币，详情提供[调整代币单位价值（A-TOKEN-02）](#A-TOKEN-02)。
- 运营从只有提交锁时的[销毁超时待处理（NT-A08）](./03-销毁审核与解除质押-消息通知.md#NT-A08)或[单位价值调整超时待处理（NT-A09）](./03-销毁审核与解除质押-消息通知.md#NT-A09)进入该代币详情；详情只读展示当前事实，不提供线上超时处理、解除提交锁或判失败入口。

<a id="ledger-columns"></a>
### 10.1 代币台账的列表与详情

| 列表信息 | 取值与展示 |
| --- | --- |
| 所属网络 | Ethereum；列表首项 |
| 代币类型 | 代币图标与代币符号 |
| 代币编号 | 平台内唯一代币编号；点击进入该代币详情 |
| 发行人 | 发行申请提交时记录的企业名称 |
| 代币数量 | 铸造成功的完整数量，单位为代币符号；主显示按[两位小数截断展示](../../两端共用/M2-可信资产/01-可信资产-PRD.md#amount-display) |
| 当前单位价值 | 最近一次链上成功生效的值，按运营填写的完整值展示为“1 COU = X USD”，不补零、不截断（如 1 COU = 1 USD、1 COU = 0.8 USD）【确认】；更新处理中或失败时展示原有效值 |
| 当前资产估值 | 发行数量 × 当前单位价值，带币种 USD；主显示按[两位小数截断展示](../../两端共用/M2-可信资产/01-可信资产-PRD.md#amount-display)【确认】 |
| 当前所在地址 | 链上查询的代币当前所在地址，缩写展示，可核对完整地址；质押期间（含违约）即质押地址；不展示转入质押前的地址【确认】；查询失败时说明暂时无法获取；代币已销毁后没有持有记录，本项为空，不用铸造到账地址或销毁前的地址代替 |
| 到期日 | 铸造结果的到期日；到期时点按 M2 [到期时点](../../两端共用/M2-可信资产/01-可信资产-PRD.md#due-time)，换算到本人所选时区后同时展示日期、时间和时区【确认】 |
| 销毁进度 | 代币有提交锁、尚未形成销毁申请时为确认中【确认】；其余情况取该代币最近一笔销毁申请的状态：销毁中、销毁失败或销毁成功；没有申请时为未申请；取值与 M4a [销毁进度的取值](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#burn-progress)一致 |
| 操作 | “查看”，进入该代币详情 |

- 列表按发行时间（M3b 铸造成功时间）由新到旧排列；每列只展示状态值，不附解释性内容。
- 可按代币编号、发行人（企业）、资产编号查找，按销毁进度（未申请、确认中、销毁中、销毁失败、销毁成功）筛选【确认】；本机构代币台账只在本机构可见范围内查找【确认】。
- 分页、返回位置、空状态与读取失败按可信资产（M2）的[业务列表通用规则](../../两端共用/M2-可信资产/01-可信资产-PRD.md#list-common)。
- 资产、合约、发行地址、融资、结清和资产托管信息不在列表展示，只在详情查看。
- 代币详情分为：最上方的识别信息、代币发行信息、持有信息、发行关联业务、资产托管信息与发行机构文件、销毁条件与销毁记录；各分区的业务信息与 M4a [代币详情（C-TOKEN-02）](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#C-TOKEN-02)相同，口径按[代币及关联事实](#handoff-token)。分区名称与排列由设计决定。
- 代币发行信息包括发行人、完整发行数量及符号、应收账款原值、铸造初始单位价值、当前单位价值、当前资产估值、到期日、发行时间、发行地址和所属合约；铸造初始单位价值与当前单位价值都按运营填写的完整值展示为“1 COU = X USD”，不补零、不截断【确认】；发行地址是代币铸造时的第一个持有地址，即铸造到账地址【确认】；合约名称取当前值，链上身份不变。
- 持有信息以列表展示，并展示本次链上查询时间；代币已销毁时没有持有记录。运营看到当前所在地址、持有数量、融资状态、下游融资结果与链上验证结果；名单内机构只看代币当前状态和当前所在地址，按[代币及关联事实](#handoff-token)【确认】。
- 资产托管信息包括本代币的资产托管机构当前名称、托管状态（托管中或已解除托管）、托管开始时间和已有解除记录。
- 发行机构文件与 M4a [发行机构文件](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#institution-files)相同，按托管文件、法律文件、审计文件分类只读查看、下载；机构材料的访问范围按 M3b [申请与文件访问范围](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#file-access)；名单内机构在代币销毁成功前可继续追加，见[铸造后追加机构材料（R-TOKEN-02）](#R-TOKEN-02)。
- 销毁条件与销毁记录列出该代币历次销毁申请的编号、交易来源和销毁申请状态；代币有提交锁、尚未形成申请时，说明当前销毁进度为确认中，不出现申请记录。
- 运营查看的详情另外展示[单位价值调整记录](#A-TOKEN-02)。

<a id="A-TOKEN-02"></a>
## 11. 调整代币单位价值（A-TOKEN-02）

适用角色与前提：运营管理人员；代币未销毁、没有销毁中的申请，且没有处理中的单位价值调整。代币有提交锁、销毁进度为“确认中”时仍可调整【确认】。

单位价值由平台运营人员发起，平台向代币所属合约提交链上更新；链上更新能力与约束按 M6 [单位价值链上更新（F-CT-07）](../M6-合约管理/01-合约管理-PRD.md#F-CT-07)【确认】。代币在质押合约中（含违约期间）、所属合约已在平台停用时，仍可调整单位价值。

| 字段 | 规则 |
| --- | --- |
| 新单位价值 | 必填数值，单位 USD；必须大于零且不等于当前单位价值；精度不得超过合约及业务共同支持的精度，与 M3b 铸造初始单位价值相同 |
| 调整原因 | 必填文本，无默认值；去除首尾空白后不能为空；按原文保存 |

- 提交前展示新旧单位价值和按发行数量计算的新旧资产估值；新旧单位价值按完整值展示为“1 COU = X USD”，不补零、不截断，估值主显示按[当前资产估值](#ledger-columns)的两位小数截断规则；确认后提交链上更新。
- 调整不改应收账款原值、发行数量、铸造初始单位价值，也不改变持有、融资、销毁或托管状态。
- 链上更新成功后新值成为当前值并重算资产估值；失败时保留原值与失败记录，可另行提交新的调整。
- 链上结果未确认时当前值保持不变；刷新或重新进入只取得原结果，不新建调整记录。
- <a id="adjust-timeout"></a>调整长时间没有结果【确认】：单次调整自提交链上更新起满 10 分钟仍无明确成功或失败结果时，向全体运营发送一次[单位价值调整超时待处理（NT-A09）](./03-销毁审核与解除质押-消息通知.md#NT-A09)，每次调整最多一次，打开后进入该代币在[全平台代币台账（A-TOKEN-01）](#A-TOKEN-01)中的详情。平台不自动判失败，也不提供线上超时处理入口；结果确认后按实际结果收口：成功时新值生效，失败时保留原值与失败记录。
- 已有调整处理中时不能再次提交；多名运营并发提交时只有一笔生效，其余返回最新结果。
- 代币有提交锁、尚未形成销毁申请（销毁进度为“确认中”）时可以调价【确认】；调价结果未确认期间提交锁形成销毁申请的，按“调价已提交、结果尚未确认期间代币进入销毁中”的规则处理。
- 代币有销毁中的申请时不允许调价【确认】，不提供调整，直接提交也被拒绝；该笔销毁失败后可重新调价，销毁成功后不再可调。
- 调价已提交、结果尚未确认期间代币进入销毁中的，已提交的调整按链上实际结果记录，不撤销也不重新提交；不改变销毁申请或销毁结果。
- 代币已销毁时不提供调整，直接提交也被拒绝；历史价值仍可查看。
- 每次调整保留新旧单位价值（按完整值展示）、新旧资产估值、原因、操作人、提交时间、结果和已提交的交易哈希；调整记录仅运营可见【确认】，企业和名单内机构只看当前单位价值与当前资产估值。

<a id="R-TOKEN-01"></a>
## 12. 本机构代币台账（R-TOKEN-01）

- [名单内机构](#listed-institutions)只查看本机构所在锁定发行机构名单的代币及其业务事实，列表与详情按[代币台账的列表与详情](#ledger-columns)，不看其他发行的数据。只在同一资产被驳回申请的名单中的机构，看不到这笔资产后来铸造成功的代币；直接请求按无权处理。
- 持有与融资只展示代币当前状态和当前所在地址，按[代币及关联事实](#handoff-token)【确认】。
- 可查看该代币各笔销毁申请的销毁申请状态、交易来源和[处理进度](#progress)中的全部事件；不看原始失败说明和链上交易标识。
- 资产托管机构在代币销毁成功、资产托管仍为托管中时可前往对应待解除托管事项；其他阶段只查看，不能提前解除。法律服务机构和审计机构全程只读，可查看销毁事实和解除记录，没有解除动作。
- 三类名单内机构都可在代币销毁成功前追加机构材料，见[铸造后追加机构材料（R-TOKEN-02）](#R-TOKEN-02)。

<a id="R-TOKEN-02"></a>
### 12.1 铸造后追加机构材料（R-TOKEN-02）

适用角色：[名单内机构](#listed-institutions)，即资产托管机构、法律服务机构和审计机构【确认】。入口在本机构代币台账的代币详情的发行机构文件中。

适用前提：代币已铸造成功，且尚未销毁成功【确认】。代币未申请、确认中、销毁中或最近一次销毁失败时都可追加；机构在铸造成功后停用的，仍可为本代币追加。

| 项目 | 规则 |
| --- | --- |
| 上传说明 | 必填文本，无默认值；去除首尾空白后不能为空 |
| 文件 | 必填；每次 1 至 10 份；格式、单份大小和按实际内容识别的规则与 M3b [机构材料追加](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#R-ISSUE-06)的单次文件规则相同；上传中或有失败未移除的文件时不能保存 |

- 保存成功后形成一条新的机构材料记录，记录上传机构、上传说明、成功文件的原文件名、格式、大小、上传时间、上传操作人和访问操作；之后不可覆盖、替换或删除。
- 新记录按上传机构的分配时类型归入托管文件、法律文件或审计文件，可见范围与铸造成功前的机构材料相同：名单内机构共享，运营可查看全部，原发行企业在 M4a [发行机构文件](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#institution-files)只读查看、下载；企业不看上传操作人和访问记录。
- 追加不改变代币、销毁申请或资产托管状态，也不产生待办或审核结论；运营只查看，不能代为上传。
- 代币销毁成功（含非平台入口销毁）后不再提供追加入口；提交时重新校验代币是否已销毁成功和当前账号是否属于名单内机构，不满足时拒绝保存并返回最新结果，未保存的文件不形成记录。
- 资产托管机构销毁后上传的解除托管通知文件按[解除资产托管并留记录（R-RELEASE-03）](#R-RELEASE-03)办理，不属于本功能。

<a id="handoff-signature"></a>
### 13.3 销毁交易记录

保留交易发送地址、交易提交时间、交易来源、链上交易标识和当前链上结果。发送地址必须是代币铸造到账地址；不存在平台执行地址或独立业务签名。失败后的新申请使用新的链上交易，原申请记录不改写。链上交易标识（即销毁交易哈希）由平台保存，用于承接链上结果和识别非平台入口销毁，本期不向任何身份展示，包括运营，见[销毁结果](#handoff-burn)。企业、运营和名单内机构可查看发送地址、时间、来源和结果【确认】。

<a id="handoff-execution"></a>
### 13.4 条件与执行记录

| 字段组 | 口径 |
| --- | --- |
| 提交条件快照 | 到期、结清、下游融资、链上质押与当前所在地址的校验结果和时间；不是运营审核结果；非平台入口标记“未经过平台入口校验” |
| 交易提交 | 钱包广播时间、销毁中起始时间及结果确认时间；非平台入口没有销毁中阶段，销毁中起始时间为空 |

### 13.5 销毁结果

成功结果包含完整销毁数量、代币符号和成功时间。结果未确认保持销毁中；确认失败是原申请终态。本期不向企业、运营或机构展示销毁交易哈希【确认】。

<a id="handoff-release"></a>
### 13.6 解除资产托管记录及企业可见范围

记录办理的资产托管机构、实际操作人、完成时间、原文解除说明和解除托管通知文件。资产托管机构看本机构完整记录；运营可看完整记录，只读；企业以及名单内的法律服务机构、审计机构可看已解除、办理机构名称、完成时间、解除说明和通知文件，通知文件可查看和下载，不看操作人。文件读取失败时说明暂时无法获取，可以重试。

<a id="states"></a>
## 14. 对象与状态对应

销毁申请状态与资产托管状态是两项独立事实，分别展示【确认】；状态迁移见[销毁申请状态（图 2）](./02-销毁审核与解除质押-流程图与状态机.md#fig-2)与[资产托管状态（图 3）](./02-销毁审核与解除质押-流程图与状态机.md#fig-3)。

| 销毁申请状态 | 资产托管状态 | 代币与后续 |
| --- | --- | --- |
| 销毁中 | 托管中 | 代币尚未销毁；取得原执行结果，不重复发起；满 10 分钟仍无结果时按[销毁中或提交锁长时间没有结果](#burn-timeout)处理 |
| 销毁失败 | 托管中 | 代币按当前持有与融资事实展示；原申请结束，企业重新满足条件后新建申请 |
| 销毁成功 | 托管中 | 代币已销毁；本代币的资产托管机构有一项待解除托管事项 |
| 销毁成功 | 已解除托管 | 代币已销毁，资产托管已解除；终态，历史可查 |

- “待解除托管”是资产托管机构的待办事项，不是销毁申请状态或资产托管状态。
- 提交锁不是申请，不出现在上表中；提交锁存在、尚未形成申请期间，代币台账的销毁进度为“确认中”，满 10 分钟仍未取得交易标识时按[销毁中或提交锁长时间没有结果](#burn-timeout)处理；规则按 M4a [销毁提交锁与交易归属](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#submit-lock)。
- 代币持有、融资与资产托管的关系按 M4a [对象与状态](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#states)；违约或质押中代币保持托管中，不形成解除事项。
