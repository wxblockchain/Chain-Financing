## 1. 模块是什么

企业从面客端提交销毁申请后，运营在管理端核对到期、结清和融资质押情况，通过审核即执行代币销毁，驳回则留下意见。销毁失败由运营手动重试；成功后原监管机构在平台办理解除监管并留下记录。运营查看全平台代币台账，监管机构查看本机构代币台账，两端持续使用同一笔申请与结果。

基本原则：

- 企业发起、运营审核与销毁、原监管机构解除监管的职责固定（BR-06、BR-14、BR-15）【确认】。
- 到期、结清、融资、监管、销毁分别表达；监管中不阻断销毁，解除监管不替代解除融资质押。
- 销毁成功事实与解除监管进度分开；未知结果不能当失败重新销毁，销毁成功不能提前当作监管已解除。
- 代币数量按资产价值 1:1 确定，单位为原合约的代币符号，不以 USD 为单位（BR-19）【确认】，承接 [M3b 的铸造结果](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-mint)；应收账款原值、发行数量与当前单位价值分别保存，调整单位价值不改变前两者。申请、销毁及解除全程使用同一发行数量和单位。
- 每笔成功代币独立维护当前单位价值，按币本位展示为“1 COU = X USD”；当前资产估值等于发行数量乘以当前单位价值，由平台计算。运营可按单笔代币调整，链上更新成功后才替换当前值。
- 本册维护[两端衔接字段清单](#handoff)，M4a 直接引用，不各建一套。所有对象与消息定位到原记录，历史不因再次申请而覆盖。

**一个完整的例子。** 企业 A 用登录地址在钱包中签名后，对一枚代币提交销毁申请：所属网络 Ethereum，代币类型为 cou 图标与 cou，代币数量 50,000.00 cou，当前单位价值“1 COU = 0.8 USD”，当前资产估值 40,000.00 USD。运营甲看到已到期、上游已结清，下游与链上均无融资质押，核对原代币和数量后通过，申请进入销毁中。首次执行失败，甲手动重试后成功，代币成为已销毁，企业收到成功消息，原监管机构 X 收到解除监管待办。X 核对该资产、销毁数量 50,000.00 cou 和时间，在平台确认解除并留记录；企业看到已解除监管、X 和解除时间。运营与 X 都能从台账回看原发行、历次单位价值调整、销毁申请及解除记录，再返回原列表。

### 1.2 本期不做

- 运营代企业发起申请、监管机构代运营审核销毁、运营代监管机构解除监管。
- 部分销毁、输入任意销毁数量、批量处理、撤销或修改已提交申请。
- 自动重试、企业重试、销毁失败后另建销毁申请、成功后恢复代币。
- 在本平台办理融资或解除融资质押、更换原合约、数币地址或原监管机构。
- 台账编辑、转账、导出或新增统计分析；本期以查看和业务追溯为范围。
- 按企业批量调价、自动按企业信用计算价值、调价审批流；本期只允许运营逐笔调整。
- 同时手工填写单位价值与当前资产估值；当前资产估值始终由发行数量和当前单位价值计算。
- 违约代币的销毁：企业不能申请，运营不能通过或重试，也不另设违约代币的销毁流程【确认】，见[违约代币](#defaulted)。
- 违约代币的解除监管：违约代币不销毁，本期保持监管中，不提供解除【确认】。
- 销毁交易哈希、执行进度的展示和销毁超时提醒；销毁结果未确认时保持销毁中【确认】。
- 运营或企业用钱包签名销毁交易，或在平台上配置、查看签名私钥：私钥由开发人员配置，平台直接调用【确认】，见[平台签名提交销毁交易](#platform-signing)。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 融资质押 | 企业在下游借贷平台用代币融资形成的质押；下游结果与链上验证共同作为销毁校验依据 |
| 监管 | 原发行申请所选机构对资产的监管，从铸造成功开始，到该机构在平台解除并留记录结束 |
| 处理中申请 | 待运营审核、销毁中、销毁失败的销毁申请；销毁失败等待运营重试仍占用原申请 |
| 销毁成功 | 对应代币及本次完整数量已经确认销毁的事实，随后等待原机构解除监管 |
| 原监管机构 | 发行申请提交时选定的机构，机构改名、停用或修改登录邮箱不改变业务归属 |
| 代币符号 | 原合约的代币符号，是代币数量的单位，按 [M6 合约的代币符号](../M6-合约管理/01-合约管理-PRD.md#symbol)原文展示，为 cou【确认】 |
| 代币类型 | 代币图标与代币符号合在一起，用来识别是哪一种代币；图标由设计提供、不写入合约，按 [M6 的代币图标](../M6-合约管理/01-合约管理-PRD.md#icon)，不是运营或监管机构维护的数据 |
| 应收账款原值 | 关联资产的资产价值，即应收账款金额与币种 USD，按 [M2 的资产价值](../../两端共用/M2-可信资产/01-可信资产-PRD.md#2-术语)；铸造与调价都不改写 |
| 当前代币单位价值 | 1 个 COU 当前对应的 USD 价值，按“1 COU = X USD”展示；初始值取 M3b 铸造结果，之后以最近一次链上成功更新的值为准 |
| 当前资产估值 | 发行数量 × 当前代币单位价值所得的 USD 金额；平台自动计算并只读展示，不替代应收账款原值 |
| 铸造到账地址 | 铸造时代币进入的 Ethereum 数币地址，即发行申请提交时记录的登录地址；是平台的铸造记录，之后不变 |
| 持有地址 | 代币权益所在的数币地址，从链上查询取得；质押期间为转入质押地址前所在的地址 |
| 质押地址 | 融资质押时代币所在的下游质押合约地址；一期只能由下游借贷平台发起转入、转出质押地址；解除质押后代币回到原持有地址，融资违约后代币留在质押合约地址【确认】 |
| 业务签名 | 企业提交销毁申请前用钱包以登录地址对本次申请业务信息和唯一授权标识所做的签名，只确认业务信息，签名本身不是链上交易【确认】；签名值与本次申请授权标识随销毁交易写入链上 |
| 本次申请授权标识 | M4a 为一次销毁申请提交生成的唯一标识，随业务签名保存并在提交成功时被本申请占用；驳回后的新申请使用新标识，运营重试沿用原标识 |
| 平台签名 | 平台用开发人员配置的签名私钥对销毁交易签名并提交 Ethereum，与铸造一致【确认】；运营与企业都不使用钱包，也看不到私钥；与企业的业务签名不是同一件事 |

## 3. 权限、入口与共同异常

### 3.1 身份及数据范围

- 运营在销毁审核和代币台账内查看全平台数据，只有运营能通过、驳回和重试销毁；运营不能办理解除监管。
- 监管机构在解除监管及台账内只查看本机构代币、对应销毁申请、关联资产与解除记录；只有原监管机构能解除。监管机构不进入运营销毁审核菜单。
- 机构停用后仍可登录、收到在途业务消息、办理已有代币的解除，业务不会改属其他机构【确认】，沿用[停用与启用（F-RG-05）](../M5-监管机构管理/01-监管机构管理-PRD.md#F-RG-05)。
- 未登录、待首次改密、会话失效、无权菜单及操作按[管理端无权访问（F-LG-12）](../M5-管理端登录与权限/01-管理端登录与权限-PRD.md#F-LG-12)处理；跨机构对象和不存在对象结果相同，不返回数据。列表、直接访问、办理、文件查看与下载均按当前身份判断。
- 企业只在 M4a 按本册[企业可见范围](#handoff-release)查看结果，不能调用管理端办理动作。退出或切换账号后清除旧身份内容，迟到结果不展示旧身份数据。

### 3.2 入口、展示与返回

- 运营从销毁审核列表、台账关联记录或运营待审／失败消息进入准确申请；监管从解除监管列表、台账或解除待办消息进入准确解除事项。进入不自动办理。
- 详情可返回原列表或原消息；业务关联可定位原代币、资产、发行申请和历次销毁申请，不能用最新一笔替换消息所指记录。目标不可访问时保留返回路径。
- 代币数量保存并使用铸造成功的完整精度，单位为原合约的代币符号，不以 USD 为单位；应收账款原值和当前资产估值带币种 USD；当前单位价值按“1 COU = X USD”展示。普通列表和只读详情的金额主显示沿用平台金额展示规则，但调整、计算、记录及链上字段使用完整值，不得从截断值反算或执行。发行数量、应收账款原值、当前单位价值与当前资产估值含义不同，不能互相替代。
- 代币符号、网络名称 Ethereum、编号和数值不随语言变化；代币符号为 cou，代币图标按 [M6 的代币图标](../M6-合约管理/01-合约管理-PRD.md#icon)，暂无对应图标时只展示代币符号，不影响识别和办理。
- 网络 Ethereum、标准 ERC-3525。地址缩写并可核对完整值，沿用[地址展示](../../面客端/M1-企业登录与企业账户/01-企业登录与企业账户-PRD.md#address-display)。
- 字段名、状态与业务说明支持中英文；意见、备注、名称等业务原文不自动翻译。管理端时间按[界面语言与时区（F-LG-09）](../M5-管理端登录与权限/01-管理端登录与权限-PRD.md#F-LG-09)展示，时区切换不改变到期判断、事件先后和结果。

**列表与编号前往【确认】。** 本模块的销毁审核列表、解除监管列表、全平台代币台账与本机构代币台账，与 M4a 及平台其他列表保持统一：

- 每项只承载一类信息；列表只展示状态值，不附加限制原因或解释性内容，原因在详情中说明。
- 列表设操作列，每行提供“查看”，进入本行对象的详情，与点击本行编号进入同一详情；通过、驳回、重试、解除监管等办理动作在详情中进行，不放在列表中。
- 前往其他对象的详情一律点击该对象的编号，不另设“查看发行申请”“查看资产”等文字入口；编号可点击须能被辨认，呈现由设计决定。

| 点击的编号 | 运营前往 | 监管机构前往 |

| 销毁申请编号 | 该笔申请的[销毁详情与条件核对（A-BURN-02）](#A-BURN-02) | 已确认销毁成功的申请进入对应的[解除监管详情（R-RELEASE-02）](#R-RELEASE-02)；其他阶段的申请只在本机构代币详情的销毁记录中展示编号与阶段，不提供前往 |
| 资产编号 | 运营的资产详情，按[全平台资产列表与资产详情](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-05-assets) | 监管机构的关联资产详情，按[监管机构查看关联资产（F-AS-06）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-06) |
| 发行申请编号 | 原发行申请的[申请详情（A-ISSUE-02）](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#A-ISSUE-02) | 原发行申请的[申请详情（R-ISSUE-02）](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#R-ISSUE-02) |

- 目标对象暂不可访问时说明原因，仍可返回原页面；无权与不存在统一处理，见[身份及数据范围](#access)。
- 数币地址、合约地址只供核对，不跳转区块链浏览器：本期全平台不提供跳转【确认】，见 [合约管理的本期不做](../M6-合约管理/01-合约管理-PRD.md#no-explorer)，与 M4a 一致。

<a id="common-errors"></a>
### 3.3 缺失、失败与重复操作

- 读取中、读取失败、确实无记录分别表达；读取失败可以重新获取，部分信息失败保留其他已取得内容。
- 到期、结清、融资校验、销毁或解除结果缺失时说明无法确认，不补成零、无质押、成功或已解除；已取得的成功事实不因暂时读不到其他信息而倒退。
- 提交前按当前权限与当前阶段复核。其他人已经处理时显示实际结果，旧动作不再生效；同一申请不能被重复审核、重复发起销毁或重复解除。
- 明确未成功的业务提交保留原状态及可恢复的填写内容，可以重新核对后提交；结果暂未确认时只允许重新取得原操作的实际结果，不能宣称失败或另起执行。
- 取消确认不产生业务结果或通知。通知暂不可见不回滚已成功的业务，不要求用户重办。
- 申请与代币、资产、原合约、原机构或数量无法对应，或出现“未销毁却已解除”等矛盾时，展示已确认事实及无法确认项，不能放行销毁或解除。由运营核查原记录与外部结果；本期没有强制改状态的入口。
- 平台暂停新的销毁申请时，不回滚、不自动驳回或改变既有申请阶段；既有申请仍按当前权限、阶段和前置条件办理，必要依据无法确认时不能通过、重试或解除。

## 5. 销毁详情与条件核对（A-BURN-02）

适用角色：运营管理人员，记录在可查看范围内。

- 最上方按[详情最上方的识别信息](#detail-identity)展示。
- 展示[代币与申请信息](#handoff-token)、[业务签名记录](#handoff-signature)、[审核与执行记录](#handoff-review)、[销毁结果](#handoff-burn)及已产生的[解除记录](#handoff-release)。点击编号可前往原发行申请、关联资产、代币及本代币其他申请，按[列表与编号前往](#admin-lists)。
- 核对到期时点、上游结清事实、下游融资质押结果、链上验证结果及链上查询的[持有信息](#handoff-holding)；到期判定沿用[可信资产的到期依据](../../两端共用/M2-可信资产/01-可信资产-PRD.md#overdue)，结清不能按余额或回款金额推断。
- 业务条件复用 M4a [销毁资格](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#eligibility)中的已到期、上游明确已结清，以及[融资双重校验](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#finance-check)两项均无质押（BR-07、BR-20）【确认】【建议·已采纳】，以及链上持有信息显示持有地址为铸造到账地址，且质押地址为空，与 M4a 销毁资格一致。企业提交时的“没有处理中申请”不用于拒绝本笔待审或失败申请；管理端防重按本申请当前阶段、没有其他执行及没有销毁成功事实判断。
- 两项融资结果不一致时按有融资质押处理，并提示企业联系平台（简报 Q26）【建议·已采纳】；运营可以核对两项实际结果。任一结果无法确认均不能放行；多个不满足项同时说明，不用单项通过掩盖其他限制。
- 链上持有信息不满足上述地址条件时不能通过或重试：持有地址不是铸造到账地址时说明代币当前不在铸造到账地址，质押地址不为空时说明代币仍在质押地址；运营可核对持有地址、质押地址与查询时间，链上查询失败视为无法确认，不用铸造到账地址代替。
<a id="defaulted"></a>
- **违约代币禁止销毁【确认】。** 融资违约后代币留在质押合约地址【确认】，持有信息有质押地址，既不满足两项均无质押，也不满足地址条件：运营不能通过，失败后不能重试；本期没有违约代币的销毁流程，也没有运营改址或强制销毁的入口。本期不接入下游的违约状态，融资状态只有未融资和融资中；违约代币按持有信息如实展示质押地址与融资状态，不另设违约标识【确认】，与 M4a [持有信息列表](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#holding-info)一致。
- 违约代币仍有待运营审核或销毁失败的申请时，由运营填写意见驳回结束：待运营审核的申请按[驳回销毁申请（A-BURN-04）](#A-BURN-04)驳回；已处于销毁失败的申请同样可以驳回，不新增阶段【确认】。驳回后代币为融资质押中，企业因仍有质押不能再申请。
- 违约代币不销毁，原监管机构不会收到解除事项；本期监管保持监管中，不提供解除【确认】。台账中监管情况为监管中。
- 持有地址不是铸造到账地址，属于与一期合约约定不符的异常，企业侧按 M4a 提示联系平台，由运营核查原记录。
- 历史申请展示本次审核时的条件依据，并区分当前再次取得的条件，不用新值改写原审核事实。到期、结清及融资结果只读，运营不能手工覆盖外部结果。

<a id="A-BURN-03"></a>
## 6. 通过并执行销毁（A-BURN-03）

适用角色与前提：运营管理人员，申请仍待运营审核，尚无成功销毁事实且没有其他执行占用该代币；[销毁条件](#A-BURN-02)全部满足。

- 确认内容包括销毁申请编号、代币与资产、完整数量（单位为代币符号）、铸造到账地址和合约、原监管机构，并说明通过即执行销毁、成功后仍由原机构解除监管（BR-06）【确认】。
- 通过时不重新选择数量、账户或合约，也不要求运营额外填写通过意见。
- 原代币所属合约被平台停用后，销毁申请、审核、执行与失败手动重试继续沿原合约办理，无需先启用；平台停用不等于链上无法执行【确认】，按[停用与既有业务](../M6-合约管理/01-合约管理-PRD.md#inflight)。
- 提交时重新核对当前前置条件及原代币、申请数量的一致性；不满足或无法确认时，申请保持待运营审核，显示具体限制，可重新获取条件或主动驳回，不自动驳回。
- 提交成功记录审核通过、审核方、运营审核人及时间，立即进入销毁中并执行原代币的本次完整数量；不增加审核后等待另一位运营执行的阶段。
- <a id="platform-signing"></a>**平台签名提交销毁交易【确认】。** 与铸造一致，平台使用开发人员配置的签名私钥签名并提交销毁交易：
  - 运营通过后无需使用钱包，也看不到私钥；企业不使用钱包，执行时不要求企业再次签名。
  - 销毁交易写入以下四项上链字段，首次执行与每次手动重试写入的字段与取值相同：所销毁的代币（代币编号对应的链上代币）；完整销毁数量（等于该代币全部完整数量，不使用普通页面的两位截断值）；企业业务签名值；本次申请授权标识。后二者取本申请的[业务签名记录](#handoff-signature)。
  - 合约、网络和交易时间由链本身产生，不另行写入；签名地址可由签名值推出，不另外上链。
  - 不上链的内容按 M3b [上链字段](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#onchain-fields)的同一原则。销毁特有的不上链项：销毁申请编号（平台按交易哈希对应申请）、驳回意见、运营审核人与重试操作人、解除监管记录（操作人、备注与凭证）、签名时间与签名地址、当前单位价值及当前资产估值的展示文字。审核阶段直接驳回且从未提交销毁交易的申请，签名与本次申请授权标识不上链；已提交销毁交易但执行失败后被驳回的，原失败交易及其中的签名值、授权标识保留在链上，不代表代币已销毁，也不因驳回新增交易。
  - 企业提交时的[业务签名](#handoff-signature)只确认业务信息，不是链上授权，不作为执行销毁的链上依据；签名值与本次申请授权标识随销毁交易写入链上，作为企业对这一笔申请的授权凭证。
  - 合约在销毁时如何携带签名值与本次申请授权标识（代币属性、事件或元数据）及对交易成本的影响由开发人员确认（待开发验证）；本册只规定上链哪些字段，不规定写入方式。合约是否校验签名不作要求，由研发评估。
  - 签名私钥不可用或销毁交易未能提交时，本次执行明确失败，按销毁失败处理：申请进入销毁失败，保留失败记录并发送[销毁失败待重试（NT-A04）](./03-销毁审核与解除质押-消息通知.md#NT-A04)；由开发人员处理后，运营按[销毁失败手动重试（A-BURN-05）](#A-BURN-05)再次发起。
- 执行仍在进行或结果未确认时保持销毁中，等待多久都不自行认定失败；本期不展示销毁交易哈希和执行进度，也不设超时提醒或超时消息【确认】。确认失败时进入销毁失败，保留失败记录并发送[销毁失败待重试（NT-A04）](./03-销毁审核与解除质押-消息通知.md#NT-A04)。
- 只有链上已确认与原代币、原合约、本次完整数量一致的成功结果，才记录[销毁成功事实](#handoff-burn)，代币成为已销毁，形成原监管机构待解除事项。结果不符按[共同异常](#common-errors)处理，不当作本次成功。
- 成功时分别发出[销毁成功（NT-C06）](./03-销毁审核与解除质押-消息通知.md#NT-C06)和[代币已销毁、待解除监管（NT-R02）](./03-销毁审核与解除质押-消息通知.md#NT-R02)；通知、待办读取失败不允许再次销毁。

流程参见[运营审核与执行（图 1）](./02-销毁审核与解除质押-流程图与状态机.md#fig-1)。

<a id="A-BURN-04"></a>
## 7. 驳回销毁申请（A-BURN-04）

适用角色与前提：运营管理人员；申请仍待运营审核，或申请为销毁失败且当前持有信息显示代币在质押地址（含融资违约）【确认】。查看前置条件未通过或暂无法取得时，仍可作出有意见的驳回，不因此自动驳回。

| 可填写字段 | 类型、含义 | 必填、默认与可编辑性 | 校验及失败结果 |
| --- | --- | --- | --- |
| 驳回意见 | 文本，说明本次不通过的理由 | 驳回时必填，无默认值；仅本次提交前由运营编辑 | 空值或纯空白不能提交；本期不设长度上限【确认】 |

- 驳回销毁失败的申请：平台没有下游的违约状态，以持有信息中质押地址不为空作为可以驳回的依据，正常融资质押中的代币同样适用；质押地址为空或持有信息查询失败时不能驳回失败申请，按[销毁失败手动重试](#A-BURN-05)处理。提交时重新核对当前阶段与持有信息，条件已变时不生效并说明原因。
- 提交成功后原申请为驳回，记录意见、审核时间与审核人，意见以原文展示，任何角色不能修改已生效结果。
- 本次未执行销毁或已确认执行失败，不形成解除待办；从销毁失败驳回时，原审核通过、历次失败与重试记录全部保留；发送[销毁申请驳回（NT-C07）](./03-销毁审核与解除质押-消息通知.md#NT-C07)。
- 释放原申请对代币的处理中占用，代币按当前融资事实回到正常（未质押）或融资质押中；融资未知时显示无法确认，不伪装正常。原驳回记录及其消息保留。
- 企业须按 M4a [驳回后再次申请销毁（C-BURN-04）](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#C-BURN-04)重新判断资格、取得新的本次申请授权标识、重新签名并创建新申请；运营不能把驳回的原申请改回待审。并发或取消按[共同异常](#common-errors)。

<a id="A-BURN-05"></a>
## 8. 销毁失败手动重试（A-BURN-05）

适用角色与前提：运营管理人员，原申请为销毁失败且原次执行已明确失败，没有成功销毁事实，当前[销毁条件](#A-BURN-02)仍满足。

- 手动重试沿用原申请、代币、原合约、铸造到账地址、完整数量、本次申请授权标识及业务签名；无需重新审批，不新增申请，不允许企业或监管机构代操作（BR-14）【确认】，企业不再签名。
- 确认重试时能核对原申请、代币和数量；提交时重新核对权限、当前状态、到期、结清、两项融资结果及链上持有信息的地址条件。条件改变或无法确认时保留销毁失败，说明限制；不是新增失败终态，也不自动驳回。
- 成功受理本次重试后记录本次操作人和时间，申请回到销毁中；平台按[平台签名提交销毁交易](#platform-signing)签名并提交新的销毁交易，写入的上链字段与首次相同，运营不使用钱包，企业不再签名。再次失败（含签名私钥不可用或交易未能提交）保留新一次失败记录并再发运营告警；成功按[通过并执行销毁](#A-BURN-03)承接结果。
- 刷新、重新登录或仅有外部条件恢复不触发自动重试；结果未确认时先取得原执行结果，不能按超时自行认定失败再执行。重复或并发重试只产生一次实际执行。
- 既有审核、失败和重试记录全部保留，企业只看申请状态及最终结果；完整失败说明及运营账号仅运营可见，见[审核与执行记录](#handoff-review)。重试次数、等待时长不另设无来源阈值。

<a id="R-RELEASE-01"></a>
## 9. 解除监管列表（R-RELEASE-01）

适用角色：已完成首次改密且账号可用的监管机构，包括已停用机构的在途业务。

- 只列本机构监管、已经确认代币销毁成功的事项，提供待解除与已解除两类结果；此分类不是额外状态。
- 每个事项一行，按下表展示：

| 列表信息 | 取值与展示 |
| --- | --- |
| 销毁申请编号 | 点击进入该事项的[解除监管详情（R-RELEASE-02）](#R-RELEASE-02) |
| 企业名称 | 资产所属企业的名称 |
| 代币编号 | 点击进入本机构代币台账中该代币的代币详情 |
| 资产编号 | 点击进入关联资产详情 |
| 销毁数量 | 实际销毁的完整数量；主显示可向下截断到两位小数并标识“已截断”，可核对完整值；单位为代币符号 |
| 销毁成功时间 | 本次实际成功时点 |
| 解除时间 | 已解除事项为解除完成时间；待解除事项为空 |
| 操作 | “查看”，进入该事项的解除监管详情；解除监管在详情中办理 |

- 未销毁、销毁中、销毁失败或驳回不形成解除待办。消息已读不移出待解除列表，只有解除提交成功才进入已解除。
- 没有记录与读取失败分别展示，按[共同异常](#common-errors)处理；机构停用、更名或修改登录邮箱不丢历史。

## 10. 解除监管详情（R-RELEASE-02）

适用角色与前提：原监管机构，属于本机构的解除事项。

- 最上方按[详情最上方的识别信息](#detail-identity)展示。
- 展示本笔企业与资产、原代币与合约、申请识别信息、销毁结果数量和成功时间、监管机构及当前解除进度；点击编号可前往关联资产、原发行申请和代币，按[列表与编号前往](#admin-lists)。
- 字段与可见性直接使用[两端衔接字段清单](#handoff)，不向监管机构展示运营账号、内部失败说明或企业当前登录地址。
- 待解除时提供[解除监管并留记录](#R-RELEASE-03)；已解除时展示既有记录，不提供再解除、编辑或删除。
- 从旧待办消息进入时按当前事实展示；已经完成只看结果，无权或不存在统一拒绝。解除依据缺失或矛盾时保留已确认内容，不能直接确认完成，按[共同异常](#common-errors)。

## 11. 解除监管并留记录（R-RELEASE-03）

适用角色与前提：原监管机构，代币已确认销毁成功、事项仍待解除监管。

- 监管机构在平台主动确认解除该笔资产的监管并留记录（BR-21）【确认】，不把阅读消息、下载资料或代币已销毁视为解除。
- 确认前展示企业、资产、代币、成功销毁的数量（单位为代币符号）和时间，说明操作完成后留存解除记录。原监管机构只读，不可另选；操作人和时间由本次实际操作形成，不让用户填写历史时间或冒填他人。

| 可填写字段 | 类型、含义 | 必填、默认与可编辑性 | 校验及失败结果 |
| --- | --- | --- | --- |
| 解除备注 | 文本，本次解除的补充说明 | 选填，无默认值；提交前原机构可编辑；未填不阻断 | 仅空白按未填处理；本期不设长度上限【确认】 |
| 解除凭证 | 文件，本次解除的可选证明材料【建议·已采纳】 | 选填，无默认文件；提交前可增删本次待提交文件 | 已选择的文件须全部上传成功，失败可重试或移除后不带凭证提交；本期不限定格式、份数和单份大小【确认】 |

- 重新核对当前身份、原机构归属、已销毁事实与待解除进度。提交成功形成[解除记录](#handoff-release)，申请成为已解除监管，监管情况成为已解除监管，代币保持已销毁；可查看记录并返回原列表。
- 同一事实只形成一份生效解除记录，不能重复解除。备注和已提交凭证随记录保留，任何角色不能编辑、补传、替换或删除本次生效记录；未填备注或凭证不影响正常完成。
- 取消、明确提交失败或结果暂未确认，按[共同异常](#common-errors)处理；未成功不能展示已解除、解除时间或发结果消息。
- 成功发送[资产已解除监管（NT-C08）](./03-销毁审核与解除质押-消息通知.md#NT-C08)给资产所属企业；不再给运营或其他监管机构新增通知。

## 13. 调整代币单位价值（A-TOKEN-02）

适用角色与前提：运营管理人员；代币已铸造成功且未销毁。同一代币已有一次单位价值更新正在等待链上结果时，不能再次提交。

- 运营从全平台代币详情发起调整；本期逐笔办理，不提供企业批量调整或自动定价。
- 只填写新的代币单位价值和调整原因。新单位价值按“1 COU = X USD”展示，必须大于 0，且不能与当前有效值相同；小数精度与最大值按 Q-M3B-01 待确认。
- 平台按发行数量自动计算调整后的资产估值，只读展示；应收账款原值和发行数量始终不变。
- 提交前展示当前单位价值、当前资产估值、新单位价值、新资产估值和调整原因；取消不产生记录、不发起链上更新。
- 提交后形成一次单位价值更新记录并等待链上结果。等待期间继续以原值作为当前有效值，说明新值尚未生效；同一代币不能再次调价。
- 链上更新成功后，新单位价值成为当前有效值，当前资产估值随之重算；链上更新失败时保留原当前值，记录失败结果，运营可以按原记录重试或重新发起一次调整。
- 每次记录保留旧单位价值、新单位价值、旧资产估值、新资产估值、调整原因、操作账号、提交时间、结果时间、链上结果和已提交交易的交易哈希；失败记录不删除，重试结果与原记录关联。
- 调价不增发、不销毁，不改变发行数量、应收账款原值、到期时点、持有地址、融资状态和监管状态，也不触发本模块站内消息。
- 代币销毁成功后不再允许调价；提交调价与销毁成功并发时，以链上实际结果为准，销毁已成功则调价不能生效且保留失败记录。

流程参见[代币单位价值调整（图 5）](./02-销毁审核与解除质押-流程图与状态机.md#fig-5)。

## 14. 本机构代币台账（R-TOKEN-01）

适用角色：监管机构。台账本身为简报【建议·已采纳】范围，机构隔离为【确认】（BR-15）。

- 仅展示原发行申请选择本机构的成功代币，包含尚在监管、待解除及已解除的历史代币；范围不因机构停用或修改登录邮箱改变。
- 列表与代币详情的信息项、排列和“查看”操作与[全平台代币台账的列表](#ledger-columns)及[代币详情](#ledger-detail)相同，只是范围限于本机构；可追溯本机构原发行、当前单位价值、历次销毁及解除记录。监管机构没有调整单位价值入口，直接提交也被拒绝。
- 数据项沿用[两端衔接字段清单](#handoff)的监管列。地址只看本笔代币的铸造到账地址和持有信息中的地址，不看企业当前登录地址、业务签名记录、运营账号或内部失败说明。
- 属于本机构且已销毁待解除时可以前往对应解除事项；处于其他阶段只查看，不能从台账审核、重试或提前解除。
- 空列表、读取异常、无权及历史保留按[共同规则](#access)。

<a id="handoff-signature"></a>
**业务签名记录。** 企业提交前用登录地址对这笔申请业务信息与本次申请授权标识所做的签名，由 M4a 随申请保存，任何角色都不能修改；申请处于任何阶段都可以查看。签名规则与签名内容按 M4a [提交时的业务签名](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#burn-signing)；驳回后再次申请销毁是新申请，使用新授权标识并重新签名；运营手动重试沿用原授权标识与原签名。签名值与本次申请授权标识随销毁交易写入链上，作为企业对这一笔申请的授权凭证，见[平台签名提交销毁交易](#platform-signing)；本期不展示销毁交易哈希【确认】，签名记录也不另设交易哈希。审核阶段直接驳回且从未提交销毁交易的申请，签名与授权标识不上链；已提交销毁交易但执行失败后被驳回的，原失败交易及其中的签名值、授权标识保留在链上，不代表销毁成功。

| 业务信息 | 含义与取值 | 企业 | 原监管机构 | 运营 |
| --- | --- | --- | --- | --- |
| 签名地址 | 签名时企业的登录地址；缩写展示，可核对和复制完整地址；之后登录地址变更不改变它 | 可见【确认】 | 不可见【确认】 | 可见【确认】 |
| 签名时间 | 完成签名的时点，记录签署时点，不属于签名内容，不上链 | 可见【确认】 | 不可见【确认】 | 可见【确认】 |
| 签名值 | 钱包返回的签名；缩写展示，可核对和复制完整值；随销毁交易写入链上 | 可见【确认】 | 不可见【确认】 | 可见【确认】 |
| 本次申请授权标识 | 平台为本次提交生成并在成功时由本申请占用的唯一标识；缩写展示，可核对和复制完整值；随销毁交易写入链上 | 可见 | 不可见 | 可见 |

- 页面不另行展示签名原文；签名记录读取失败时说明暂时无法获取，可以重试，不影响查看申请的其他信息。
- 签名只确认企业提交的业务信息，不是链上授权，不作为运营通过的前提条件，也不替代[销毁条件](#A-BURN-02)核对。

## 16. 对象与状态对应

销毁申请和代币真实阶段引用简报第 5 节；本平台只有监管，监管相关阶段称为待解除监管、已解除监管，不另建并行流程。M2 已确认资产发行状态在铸造后保持已发行，销毁与解除不改发行状态。

| 销毁申请阶段（本模块与 M4a 相同） | 代币及监管结果 | 说明 |
| --- | --- | --- |
| 待运营审核 | 代币为销毁申请中；监管中 | 等待运营审核 |
| 驳回 | 取消本申请占用，按当前融资事实回到正常（未质押）／融资质押中；监管中 | 本笔申请结束；可由待运营审核驳回，也可在代币位于质押地址时由销毁失败驳回 |
| 销毁中 | 代币为销毁申请中；监管中 | 执行中或结果尚未确认 |
| 销毁失败 | 仍是销毁申请中；监管中 | 运营重试后回到销毁中；代币在质押地址时运营可驳回 |
| 销毁成功 | 代币已销毁；监管中 | 销毁成功是持续保留的结果事实，进入待解除监管、已解除监管后仍保留 |
| 待解除监管 | 代币已销毁；监管中 | 原监管机构待办理解除监管 |
| 已解除监管 | 代币已销毁；已解除监管 | 原监管机构已解除并留记录 |

- 成功事实与待解除可以在同次结果承接中出现，用户无需停留在一个中间画面；销毁时间与数量必须保留。
- 驳回只结束该申请，当前融资未知则说明无法确认并限制新申请，不能用旧“正常”放行；有新申请后，旧申请仍为驳回，代币当前进度关联新申请。
- “未融资／融资中”是企业融资展示；无法确认是信息可用情况，不新增代币终态。监管中不等于有融资质押。
