# 销毁执行、解除资产托管与代币台账 · 功能与业务规则

2026-11-09｜管理端：运营管理人员、资产托管机构｜需求评审稿

本模块共四册：01 本册、[02 流程图与状态机](./02-销毁审核与解除质押-流程图与状态机.md)、[03 消息通知](./03-销毁审核与解除质押-消息通知.md)、[04 验收](./04-销毁审核与解除质押-验收.md)。为保持历史链接有效，目录和文件名暂沿用“销毁审核与解除质押”；正文已取消销毁审核，资产托管机构的动作统一称为“解除资产托管”。编号沿用原值，缺号不代表遗漏。

<a id="module"></a>
## 1. 模块是什么

企业在 M4a 通过当前资格校验后，以代币铸造到账地址对销毁交易签名一次并由企业钱包直接提交。平台不签名、不代发、不代付 gas；运营只在链上成功或失败后收到知会并查看记录，不审核、不驳回、不手动重试。销毁失败结束本笔申请；企业须重新满足当前条件并签署一笔新的销毁交易。链上销毁成功后，平台把结果同步给企业、运营和该笔发行锁定发行机构名单内的全部机构（资产托管机构、法律服务机构、审计机构）；其中唯一的资产托管机构随即取得解除资产托管的权限，对该代币对应的现实资产（应收账款）解除托管，并上传解除托管通知文件。运营只查看结果信息。

**完整示例。** 企业 A 的代币铸造到 A1。平台确认到期、结清、下游无融资，且链上完整代币位于 A1、质押地址为空后提供入口。A 连接钱包并由 A1 对销毁交易签名一次，钱包直接提交。运营不参与发起。若失败，该申请保持销毁失败，A 重新校验后再签署一笔新交易；若成功，企业收到成功消息，运营收到结果知会；该笔发行唯一的资产托管机构 X 收到待办，名单内的法律服务机构 Y、审计机构 Z 收到销毁结果。X 上传解除托管通知文件后完成解除资产托管，企业收到已解除结果并可查看该通知文件。若 A 绕过平台入口直接调用合约且链上销毁成功，平台仍承认结果、标记“非平台入口”并进入相同的通知和解除流程。

### 1.2 本期不做

- 运营审核、通过、驳回或手动重试销毁；运营也不代企业发起。
- 资产托管机构发起销毁，或运营代资产托管机构解除资产托管。
- 审计机构、法律服务机构办理解除资产托管；资产托管机构的变更、补登或重新指定。
- 代币转让或质押期间的销毁，以及违约代币的强制销毁。
- 销毁成功后恢复代币。

<a id="terms"></a>
## 2. 术语与状态

| 术语 | 定义 |
| --- | --- |
| 销毁中 | 企业钱包已广播销毁交易，仍在执行或结果未确认 |
| 销毁失败 | 本笔申请已终结且没有形成成功销毁事实；不在原申请上重试 |
| 销毁成功 | 链上销毁结果已确认，代币不可再销毁 |
| 资产托管 | 资产托管机构对代币所对应现实资产（应收账款）的托管；从铸造成功开始，到资产托管机构解除托管为止；与下游融资质押相互独立 |
| 待解除托管 | 销毁成功后，资产托管机构尚未完成解除 |
| 已解除托管 | 资产托管机构已提交有效解除记录 |
| <a id="listed-institutions"></a>名单内机构（本代币） | 该代币原发行申请铸造成功时[锁定发行机构名单](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#handoff-mint)中的全部机构，包括一家资产托管机构，以及可能有的法律服务机构和审计机构 |
| <a id="custodian"></a>资产托管机构（本代币） | 名单内机构中唯一一家资产托管机构，按 M3b 名单记录的分配时机构类型判断。M3b 规定每种机构类型最多分配一家、发起铸造前须有一家资产托管机构，见 [选择合约并发起铸造](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#A-ISSUE-04)，因此每枚代币有且只有一家资产托管机构。权限与发行审核时保持一致，机构之后停用、更名、在 M5 修改类型或账号邮箱变化都不改变，也不按当前启用机构重新分配 |
| 交易来源 | 平台入口或非平台入口；前者通过平台资格校验后发起，后者由平台监听链上结果后补建记录 |

## 3. 权限、入口与共同异常

- 运营可查看全平台销毁记录和代币台账，并收到销毁成功或失败知会；没有销毁发起、审核、驳回、重试或解除资产托管权限。
- 只有[本代币的资产托管机构](#custodian)可以办理解除资产托管；名单内的法律服务机构、审计机构，以及运营和企业都不能办理。
- [名单内机构](#listed-institutions)在销毁成功后收到销毁结果，并可只读查看本机构参与发行的代币台账、销毁成功事实和解除资产托管记录（含解除托管通知文件），与发行审核时名单内机构共享材料的权限一致；不看操作人，也不看其他发行的数据。
- 解除提交时重新校验当前账号属于本代币的资产托管机构；不满足时拒绝提交，并返回最新结果。
- 运营知会、销毁记录列表和代币台账可进入准确销毁记录；进入只查看，不触发业务。
- 列表操作列只提供“查看”。代币编号、销毁申请编号、资产编号和发行申请编号分别进入其有权详情；无权与不存在不区分。
- 读取失败与无数据必须区分；未知不补成失败或成功。结果未确认时获取原结果，不新建申请、不重复销毁。

<a id="A-BURN-01"></a>
## 4. 销毁记录列表（A-BURN-01）

适用角色：运营管理人员。

- 查看全平台已提交的销毁中、销毁失败、销毁成功、待解除托管和已解除托管记录；同一代币的多笔申请独立保留。
- 展示销毁申请编号、代币编号、企业、资产编号、完整销毁数量及代币符号、提交时间、交易来源、当前阶段和操作；非平台入口须直接可辨认。
- 可按申请编号、代币编号、企业、资产编号、交易来源和当前阶段查找；缺省按提交时间由新到旧。

<a id="A-BURN-02"></a>
## 5. 销毁记录详情（A-BURN-02）

适用角色：运营管理人员；全程只读。

- 展示[代币与申请信息](#handoff-token)、[销毁交易记录](#handoff-signature)、[条件与执行记录](#handoff-execution)、[销毁结果](#handoff-burn)及已产生的[解除资产托管记录](#handoff-release)。
- 到期、结清、融资与持有地址是企业提交时的系统校验快照，不是运营待核对任务；运营不能覆盖结果。
- 违约或任何质押中代币不能新发起销毁；本模块不提供强制销毁、改地址、审核或驳回入口。

<a id="A-BURN-03"></a>
## 6. 企业钱包直接执行销毁（A-BURN-03）

适用前提：通过平台入口时，M4a 已确认发起企业为原发行企业、到期且结清，下游明确无融资质押，链上确认代币完整位于铸造到账地址且质押地址为空。企业钱包当前地址为铸造到账地址。

<a id="platform-signing"></a>
- 连接钱包、切换地址和平台资格校验不签名。企业钱包只请求一次销毁交易签名并直接广播；平台不进行业务预签名或交易签名，不等待运营审核。
- 交易广播成功并取得链上交易标识后生成申请并进入销毁中；记录交易发送地址、提交时间、来源和链上交易标识。企业钱包承担 gas。
- 合约必须校验交易发送地址等于该代币不可变的铸造到账地址、代币完整位于该地址、质押地址为空、数量为完整数量且尚未销毁。不满足时拒绝交易。
- 到期、结清和下游融资结果是平台入口的业务准入条件，不写入合约强制校验。平台入口不通过时不提供销毁操作。
- 执行仍在进行或结果未确认时保持销毁中；不按超时自行定义失败，也不重复提交。
- 确认失败时记录销毁失败，分别向企业和运营发送失败消息；原申请不重试。企业按 M4a [销毁失败后重新发起](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#C-BURN-05)创建新申请。
- 确认成功时记录销毁成功的数量和时间，把结果同步给业务关联方：向企业发成功消息、向运营发成功知会，为[本代币的资产托管机构](#custodian)生成待解除托管事项和待办消息，并向名单内的法律服务机构、审计机构各发一条销毁结果消息。资产托管机构自此取得解除资产托管的权限。消息失败不改变销毁事实。
- 原合约已被平台停用不阻断已铸造代币按原条件销毁；停用不等于链上执行失败。
- 平台必须监听合约销毁结果。若发现没有平台入口记录但链上已有效销毁，则生成或关联销毁记录，来源标记为“非平台入口”，以链上成功事实更新代币、发送运营知会和企业成功消息，并按成功分支为本代币的资产托管机构生成解除待办。链下资格未通过或未知只能作为风险信息记录，不能撤销链上结果或继续把代币显示为有效。
- 非平台入口销毁记录缺少平台提交条件快照时，相关字段标记“未经过平台入口校验”，不得补写为已通过；运营只读审计，不得要求企业再次销毁。

<a id="R-RELEASE-01"></a>
## 7. 解除资产托管列表（R-RELEASE-01）

- 资产托管机构查看本机构作为[本代币的资产托管机构](#custodian)的待解除与已解除记录；未销毁、销毁中或销毁失败不形成解除待办。
- 展示代币编号、销毁申请编号、企业、资产编号、销毁数量与代币符号、销毁成功时间、解除状态和操作。
- 待解除项提供“查看”进入详情；消息已读不代表已解除。

<a id="R-RELEASE-02"></a>
## 8. 解除资产托管详情（R-RELEASE-02）

- 仅[本代币的资产托管机构](#custodian)可查看和办理；展示代币、企业、资产、发行、销毁成功事实、托管开始时间和已有解除记录。
- 销毁成功且尚未解除时可进入提交；结果未知、未销毁或已解除时不再提供动作。销毁成功依据缺失或与解除记录矛盾时，说明当前无法办理，由运营核查。

<a id="R-RELEASE-03"></a>
## 9. 解除资产托管并留记录（R-RELEASE-03）

| 项目 | 规则 |
| --- | --- |
| 解除说明 | 必填文本，无默认值；去除首尾空白后不能为空 |
| 解除托管通知文件 | 必填；每次提交 1 至 10 份；格式、单份大小和按实际内容识别的规则与 M3b [机构材料追加](../M3b-代币发行-审核与铸造/01-代币发行-审核与铸造-PRD.md#R-ISSUE-06)的单次文件规则相同；已选文件须全部上传成功，上传中或失败未移除时不能提交 |

- 提交时重新校验当前机构是本代币的资产托管机构、销毁成功事实及尚未解除；并发或重复提交只产生一笔生效记录，后到的提交被拒绝并返回已解除结果。
- 成功后记录机构、操作人、时间、原文解除说明和通知文件，状态为已解除托管，并向资产所属企业发送结果消息。
- 解除托管通知文件保存后不可覆盖、替换或删除；读取失败时说明暂时无法获取，不显示为没有文件。
- 企业可看解除结果、办理机构名称、完成时间、解除说明和解除托管通知文件，通知文件可查看和下载；不看操作人。名单内的法律服务机构、审计机构只读可见同样内容。运营只查看结果信息，不能代办。

<a id="ledger-columns"></a>
## 10. 全平台代币台账（A-TOKEN-01）

- 运营查看全平台铸造成功代币，包含已销毁代币；按铸造时间由新到旧。
- 列表和详情展示网络、代币类型、代币编号、企业、资产、完整发行数量及符号、应收账款原值、铸造初始单位价值、当前单位价值、当前资产估值、到期时间、铸造时间、铸造到账地址、合约、融资、资产托管及销毁进度。
- 可追溯原发行申请、关联资产、历次销毁申请和最终解除记录；台账只查看，不产生销毁权限。

<a id="A-TOKEN-02"></a>
## 11. 调整代币单位价值（A-TOKEN-02）

- 只有运营可对未销毁代币调整当前单位价值；必填新单位价值和原文调整原因。
- 新值必须大于零，单位为 USD；调整不改应收账款原值、发行数量或铸造初始单位价值。
- 链上更新成功后成为当前值并重算资产估值；失败保留原值与失败记录。本功能的重试与销毁无关。

<a id="R-TOKEN-01"></a>
## 12. 本机构代币台账（R-TOKEN-01）

- [名单内机构](#listed-institutions)只查看本机构所在锁定发行机构名单的代币及其业务事实，不看其他发行的数据。
- 资产托管机构在代币已销毁、待解除时可前往对应解除事项；其他阶段只查看，不能提前解除。法律服务机构和审计机构全程只读，可查看销毁成功事实和解除记录，没有办理动作。

## 13. 两端衔接字段清单

### 13.1 代币及关联事实

| 字段组 | 口径 | 可见范围 |
| --- | --- | --- |
| 识别 | 网络、代币图标与符号、唯一代币编号、原发行申请编号、资产编号、发行企业 | 企业看本企业；名单内机构看本机构参与发行的代币；运营看全平台 |
| 发行事实 | 完整发行数量与代币符号、铸造时间、铸造到账地址、合约；数量等于资产价值 1:1，不以 USD 为代币数量单位 | 按上述数据范围 |
| 价值 | 应收账款原值、铸造初始单位价值、当前单位价值和当前资产估值分别保存 | 按上述数据范围 |
| 持有与融资 | 持有地址、质押地址、持有数量、下游融资结果、链上验证结果和查询时间 | 企业与名单内机构看结论；运营可看来源细分 |
| 资产托管 | 资产托管机构按[本代币的资产托管机构](#custodian)确定；托管开始时间为铸造成功时间，即 M3b 铸造成功时间，铸造中或铸造失败不开始托管；托管状态为托管中、待解除托管或已解除托管 | 按上述数据范围；企业可见资产托管机构当前名称、托管状态与开始时间 |

<a id="handoff-application"></a>
### 13.2 申请信息

| 字段 | 口径 |
| --- | --- |
| 销毁申请编号 | 平台入口交易广播成功时生成；非平台入口销毁被监听到时补充生成；失败后重新发起使用新编号 |
| 提交时间 | 平台入口取交易广播时点；非平台入口取链上可确认时点并标明来源，不是刷新、消息送达或后续新申请时间 |
| 申请销毁数量 | 等于该代币完整发行数量，单位为代币符号 |
| 当前阶段 | 销毁中、销毁失败、销毁成功、待解除托管或已解除托管 |
| 交易来源 | 平台入口、非平台入口 |

<a id="handoff-signature"></a>
### 13.3 销毁交易记录

保留交易发送地址、交易提交时间、交易来源、链上交易标识和当前链上结果。发送地址必须是代币铸造到账地址；不存在平台执行地址或独立业务签名。失败后的新申请使用新的链上交易，原申请记录不改写。企业可查看发送地址、时间、来源和结果；运营可核对完整记录；名单内机构只看销毁成功事实，不看链上交易标识。

<a id="handoff-review"></a>
<a id="handoff-execution"></a>
### 13.4 条件与执行记录

| 字段组 | 口径 |
| --- | --- |
| 提交条件快照 | 到期、结清、下游融资、链上质押、持有地址与质押地址的校验结果和时间；不是运营审核结果 |
| 交易提交 | 钱包广播时间、销毁中起始时间及结果确认时间；非平台入口无法取得平台快照时明确标记 |
| 失败记录 | 失败阶段、原始失败说明与失败时间，仅运营可见；不存在审核人、驳回意见或销毁重试记录 |

<a id="handoff-burn"></a>
### 13.5 销毁结果

成功结果包含完整销毁数量、代币符号和成功时间。结果未确认保持销毁中；确认失败是原申请终态。本期不向用户展示销毁交易哈希。

<a id="handoff-release"></a>
### 13.6 解除资产托管记录及企业可见范围

记录办理的资产托管机构、实际操作人、完成时间、原文解除说明和解除托管通知文件。资产托管机构看本机构完整记录；运营可看完整记录，只读；企业以及名单内的法律服务机构、审计机构可看已解除、办理机构名称、完成时间、解除说明和通知文件，不看操作人。文件读取失败时说明暂时无法获取，可以重试。

<a id="states"></a>
## 14. 对象与状态对应

| 销毁申请 | 代币／资产托管 | 后续 |
| --- | --- | --- |
| 销毁中 | 销毁进行中／托管中 | 取得原执行结果，不重复发起 |
| 销毁失败 | 代币按当前持有与融资事实展示／托管中 | 原申请结束；企业重新满足条件后新建申请 |
| 销毁成功 | 已销毁／托管中 | 进入待解除托管 |
| 待解除托管 | 已销毁／待解除 | 本代币的资产托管机构办理 |
| 已解除托管 | 已销毁／已解除 | 终态，历史可查 |
