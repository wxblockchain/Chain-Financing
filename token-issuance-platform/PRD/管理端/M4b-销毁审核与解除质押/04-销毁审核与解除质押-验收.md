# 销毁执行、解除监管与代币台账 · 验收

2026-11-06｜需求评审稿｜供测试使用

本册只列验收标准，以[01 功能与业务规则](./01-销毁审核与解除质押-PRD.md)和本册为准。共 44 条：AC-M4B-01～16、22～48 及 AC-M7-31。AC-M4B-17～21 随已取消的驳回与运营手动重试流程停用，不重新分配。

## 0. 验收前准备

- 角色：两个运营账号，原监管机构与其他监管机构，企业 A、B。
- 销毁：销毁中、结果未确认、销毁失败、销毁成功、待解除、已解除；同一代币有失败申请与新申请。
- 代币：在铸造到账地址、后续受让地址、质押地址；无质押、有质押、下游与链上不一致、查询失败；停用合约、超过两位小数的完整数量。
- 解除：备注空白、多份凭证、上传失败、并发提交、结果未确认。
- 消息：中英文、不同时区、重复送达、已读重取、无权与对象不存在。

| 前提 | 操作 | 预期结果 |
| --- | --- | --- |
| <a id="AC-M4B-01"></a>运营只读权限（AC-M4B-01）：有各阶段销毁记录 | 运营查看列表与详情 | 可看全平台记录，操作只有“查看”；无审核、通过、驳回或重试动作 |
| <a id="AC-M4B-02"></a>数据隔离（AC-M4B-02）：运营、两个监管机构分别登录 | 查看销毁、台账与解除业务 | 运营看全平台；监管只看本机构；越权与不存在统一不可访问 |
| <a id="AC-M4B-03"></a>列表内容（AC-M4B-03）：同一代币有失败与后续新申请 | 查看与查找 | 每笔记录独立保留，字段、精度、单位、默认排序和查找条件与 01 册一致 |
| <a id="AC-M4B-04"></a>空与失败（AC-M4B-04）：无数据或读取失败 | 进入列表 | 空状态与失败可区分；失败可重新读取且不伪造空数据 |
| <a id="AC-M4B-05"></a>详情识别（AC-M4B-05）：同符号多枚代币与多笔申请 | 查看详情 | 顶部网络、图标、符号、代币编号和销毁申请编号可准确区分对象 |
| <a id="AC-M4B-06"></a>提交条件快照（AC-M4B-06）：各项条件有已取得与无法确认样本 | 运营查看 | 如实展示到期、结清、双重融资、持有和质押地址校验结果与时间；运营不能覆盖 |
| <a id="AC-M4B-07"></a>违约或质押代币（AC-M4B-07）：代币在质押地址 | 查看并尝试从管理端办理 | 按融资中和实际地址展示；不提供强制销毁、改地址或驳回入口 |
| <a id="AC-M4B-08"></a>签名记录（AC-M4B-08）：申请有完整业务签名 | 企业、运营、监管查看 | 企业与运营可核对地址、时间、值、授权与校验结果；监管不看签名值和授权 |
| <a id="AC-M4B-09"></a>编号前往（AC-M4B-09）：关联对象有权或无权 | 点击代币、申请、资产与发行申请编号 | 有权时进入准确对象并可返回；无权统一拒绝；地址不作链接 |

## 2. 提交后直接执行销毁

| 前提 | 操作 | 预期结果 |
| --- | --- | --- |
| <a id="AC-M4B-10"></a>直接执行（AC-M4B-10）：企业提交条件和签名均通过 | 提交申请 | 新申请立即进入销毁中，平台签名并提交交易；不产生待运营审核阶段 |
| <a id="AC-M4B-11"></a>业务发起权（AC-M4B-11）：用铸造到账地址、登录地址、受让地址签名 | 提交 | 只有原发行企业且铸造到账地址的业务签名可通过；平台签名不替代业务签名 |
| <a id="AC-M4B-12"></a>上链内容（AC-M4B-12）：数量超过两位小数 | 核对销毁交易 | 交易写入代币、完整数量、企业业务签名和本次授权；申请编号、解除记录和展示价值不上链 |
| <a id="AC-M4B-13"></a>销毁失败（AC-M4B-13）：平台签名或链上执行确认失败 | 查看记录与消息 | 原申请终结为销毁失败；企业收到 NT-C10，运营收到只读 NT-A04；无运营重试动作 |
| <a id="AC-M4B-14"></a>结果未确认（AC-M4B-14）：原交易仍进行或结果暂缺 | 刷新、重新登录或并发取得结果 | 保持销毁中，只取原结果；不超时判失败，不重复提交 |
| <a id="AC-M4B-15"></a>销毁成功（AC-M4B-15）：完整数量已确认销毁 | 查看申请、代币和消息 | 保留成功数量与时间，代币已销毁，企业收 NT-C06，原监管机构收 NT-R02，进入待解除 |
| <a id="AC-M4B-16"></a>并发防重（AC-M4B-16）：重复提交、重复取结果或通知失败 | 并发操作 | 同一申请只有一次有效执行与一个结果；消息异常不改销毁事实 |
| <a id="AC-M4B-39"></a>平台暂停新申请（AC-M4B-39）：新申请暂停前后均有既有记录 | 查看与提交 | 暂停只阻止新申请，既有记录可查且已确认阶段不回滚；无审核或重试入口 |
| <a id="AC-M4B-40"></a>失败后新申请（AC-M4B-40）：原申请失败且当前条件再次满足 | 企业重新发起 | 新申请使用新编号、新授权和新签名；原失败记录不改写；新申请另发 NT-A02 |
| <a id="AC-M4B-43"></a>违约代币不可销毁（AC-M4B-43）：代币留在质押合约地址 | 企业或运营尝试发起 | 不生成新申请，运营不能强制执行；按质押地址和融资中如实展示 |
| <a id="AC-M4B-44"></a>停用合约的既有代币（AC-M4B-44）：原合约已停用 | 按原条件申请销毁 | 既有代币仍按原合约直接执行；停用不等于链上失败；不需要运营先审核或启用 |
| <a id="AC-M4B-45"></a>身份或系统风险变化（AC-M4B-45）：提交前身份、资格或风险暂停变化 | 继续提交 | 按当前事实重新校验，不沿用旧结果；失败不产生申请或消息 |

## 3. 解除监管

| 前提 | 操作 | 预期结果 |
| --- | --- | --- |
| <a id="AC-M4B-22"></a>待办形成（AC-M4B-22）：有销毁成功、销毁中与失败记录 | 原监管机构查看列表 | 只有销毁成功形成待解除事项；销毁中或失败不形成待办 |
| <a id="AC-M4B-23"></a>原机构独占办理（AC-M4B-23）：原机构、其他机构和运营 | 尝试解除 | 只有发行时选定的原机构可办理；其他机构与运营无权 |
| <a id="AC-M4B-24"></a>详情核对（AC-M4B-24）：待解除事项 | 进入详情 | 展示企业、资产、代币、完整销毁数量与代币符号、成功时间和监管开始时间 |
| <a id="AC-M4B-25"></a>销毁与解除分离（AC-M4B-25）：已销毁但未解除 | 企业、运营、监管查看 | 代币保持已销毁，监管显示待解除；不把销毁成功当作已解除 |
| <a id="AC-M4B-26"></a>备注与凭证（AC-M4B-26）：备注空白，凭证全部成功或部分失败 | 提交解除 | 备注必填且不可纯空白；已选凭证须全部上传成功，失败可移除后不带凭证提交 |
| <a id="AC-M4B-27"></a>解除成功（AC-M4B-27）：权限和前置条件有效 | 提交 | 记录机构、操作人、时间、备注和凭证，状态为已解除，企业收 NT-C08 |
| <a id="AC-M4B-28"></a>解除并发与未确认（AC-M4B-28）：双击、并发提交或结果暂缺 | 重复操作 | 只产生一笔生效记录；未确认时取原结果，不重复解除 |
| <a id="AC-M4B-29"></a>企业可见边界（AC-M4B-29）：完整解除记录已存在 | 企业查看或直接请求材料 | 只看已解除、机构名称和时间；操作人、备注和凭证不可取得 |
| <a id="AC-M4B-30"></a>解除结果矛盾（AC-M4B-30）：销毁成功依据缺失或已有解除记录 | 尝试提交 | 依据缺失不放行；已解除只看原记录；不伪造时间或第二笔记录 |
| <a id="AC-M4B-41"></a>机构停用与更名（AC-M4B-41）：原机构停用或更名 | 查看待办与历史 | 原归属不改；历史使用当前机构名称并保留原完成时间 |

## 4. 代币台账与单位价值

| 前提 | 操作 | 预期结果 |
| --- | --- | --- |
| <a id="AC-M4B-31"></a>全平台台账（AC-M4B-31）：有未销毁与已销毁代币 | 运营查看 | 包含全部铸造成功代币，字段、精度、价值口径与 01 册一致 |
| <a id="AC-M4B-32"></a>本机构台账（AC-M4B-32）：两个监管机构 | 分别查看 | 只返回本机构代币；已销毁待解除可前往解除事项，其他阶段只读 |
| <a id="AC-M4B-33"></a>调价输入（AC-M4B-33）：新值小于等于零、等于当前值或原因空白 | 提交 | 均不提交链上更新；有效时展示新旧单位价值与新旧估值 |
| <a id="AC-M4B-34"></a>调价成功（AC-M4B-34）：未销毁代币 | 提交并确认链上成功 | 新单位价值成为当前值并重算估值；发行数量、原值和初始值不变；保留历史 |
| <a id="AC-M4B-35"></a>调价失败（AC-M4B-35）：链上更新失败 | 查看台账 | 保留原当前值与失败记录；不影响销毁或监管状态 |
| <a id="AC-M4B-36"></a>已销毁代币不调价（AC-M4B-36）：代币已销毁 | 运营尝试调整 | 不提供调整动作，直接提交也被拒绝；历史价值可查 |
| <a id="AC-M4B-37"></a>台账追溯（AC-M4B-37）：代币有发行、多笔销毁与解除记录 | 按编号前往 | 准确到达原发行、资产、每笔销毁和解除记录；台账可见不额外授权 |
| <a id="AC-M4B-38"></a>价值精度与语言（AC-M4B-38）：有多小数值和中英文 | 查看列表、详情和历史 | 普通展示与业务完整值分工正确；“1 COU = X USD”、时区和原文原因符合共同规则 |
| <a id="AC-M4B-42"></a>合约名称变更（AC-M4B-42）：合约改名或停用 | 查看既有代币 | 合约名称取当前值，链上身份、代币、数量和历史不改 |
| <a id="AC-M4B-46"></a>并发调价（AC-M4B-46）：已有单位价值更新处理中 | 另一运营再次提交 | 不并发第二次更新；当前值在结果确认前不变 |
| <a id="AC-M4B-47"></a>调价历史（AC-M4B-47）：有成功、失败和后续成功记录 | 查看历史 | 保留新旧值、新旧估值、原因、操作人、时间、结果和已提交交易哈希 |
| <a id="AC-M4B-48"></a>未知链上结果（AC-M4B-48）：调价结果未确认 | 刷新或重新登录 | 取得原结果，不提前生效新值，不因刷新新建调价记录 |

## 5. 消息

| 前提 | 操作 | 预期结果 |
| --- | --- | --- |
| <a id="AC-M7-31"></a>销毁与解除消息（AC-M7-31）：直接执行发起、成功、失败、待解除与解除成功，包含重复送达与无权场景 | 分别以企业、运营和原监管机构查看、前往并返回 | NT-A02 只向运营知会发起且无待办；NT-C06 向企业告知成功；NT-C10 告知企业失败与新申请指引；NT-A04 只向运营知会失败且无重试动作；NT-R02 为原监管机构解除待办；NT-C08 告知企业已解除；内容、语言、时区、60 秒可见、去重、已读、准确定位与权限边界符合 03 册和 M7 |
