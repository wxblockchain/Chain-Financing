# 销毁执行、解除资产托管与代币台账 · 验收

2026-11-09｜需求评审稿｜供测试使用

本册只列验收标准，以[01 功能与业务规则](./01-销毁审核与解除质押-PRD.md)和本册为准。共 45 条：AC-M4B-01～16、22～48、51 及 AC-M7-31。一条验收写了多个场景时，全部满足才算通过。编号沿用原值，缺号不代表遗漏。

## 0. 验收前准备

- 角色：两个运营账号；企业 A、B；同一发行锁定名单内的一家资产托管机构、一家法律服务机构和一家审计机构；另一发行的资产托管机构；一家后续停用或更名的资产托管机构。
- 发行：锁定名单有且只有一家资产托管机构的已铸造代币；名单中没有法律服务机构或审计机构的代币。
- 销毁：销毁中、结果未确认、销毁失败、销毁成功、待解除、已解除；同一代币有失败申请与新申请；平台入口与绕过平台入口直接调用合约的链上成功样本。
- 代币：在铸造到账地址、后续受让地址、质押地址；无质押、有质押、下游与链上不一致、查询失败；停用合约、超过两位小数的完整数量。
- 解除：解除说明空白、未上传通知文件、1 份与 10 份通知文件、超出份数或格式不符的文件、上传失败、并发提交、结果未确认。
- 消息：中英文、不同时区、重复送达、已读重取、无权与对象不存在。

## 2. 提交后直接执行销毁

| 前提 | 操作 | 预期结果 |
| --- | --- | --- |
| <a id="AC-M4B-10"></a>直接执行（AC-M4B-10）：企业钱包位于铸造到账地址且提交条件均通过 | 提交申请 | 连接、切换和平台校验不签名；企业钱包只签署并广播一笔销毁交易、自行支付 gas；新申请进入销毁中，平台不签名、不代发，不产生待运营审核阶段 |
| <a id="AC-M4B-11"></a>链上发起权（AC-M4B-11）：分别用铸造到账地址、登录地址、受让地址作为交易发送地址 | 提交 | 合约只接受铸造到账地址；登录地址、受让地址或其他地址均被拒绝，平台和运营没有替代发起路径 |
| <a id="AC-M4B-12"></a>链上硬约束（AC-M4B-12）：数量超过两位小数，并覆盖代币在原地址、受让地址和质押地址 | 核对销毁交易 | 只有发送地址为铸造到账地址、代币完整位于该地址、质押地址为空、数量为完整数量且未销毁时成功；到期、结清和下游融资结果不作为合约强制字段 |
| <a id="AC-M4B-13"></a>销毁失败（AC-M4B-13）：企业钱包已广播交易后链上执行确认失败 | 查看记录与消息 | 原申请终结为销毁失败；企业收到 NT-C10，运营收到只读 NT-A04；无平台或运营重试动作 |
| <a id="AC-M4B-14"></a>结果未确认（AC-M4B-14）：原交易仍进行或结果暂缺 | 刷新、重新登录或并发取得结果 | 保持销毁中，只取原结果；不超时判失败，不重复提交 |
| <a id="AC-M4B-15"></a>销毁成功（AC-M4B-15）：完整数量已确认销毁 | 查看申请、代币和消息 | 保留成功数量与时间，代币已销毁，企业收 NT-C06，运营收 NT-A05，本代币唯一的资产托管机构收 NT-R02 并取得解除权限，名单内的法律服务机构、审计机构各收一条 NT-R04，进入待解除 |
| <a id="AC-M4B-16"></a>并发防重（AC-M4B-16）：重复提交、重复取结果或通知失败 | 并发操作 | 同一申请只有一次有效执行与一个结果；消息异常不改销毁事实 |
| <a id="AC-M4B-39"></a>链下入口与链上结果边界（AC-M4B-39）：平台资格任一不通过或未知；另有绕过平台入口并链上成功的样本 | 查看平台入口并核对链上监听结果 | 平台不提供销毁入口并展示风险原因；若链上仍已有效销毁，则以链上结果更新代币、补建“非平台入口”记录并通知运营审计，不回退结果、不继续显示代币有效 |
| <a id="AC-M4B-40"></a>失败后新申请（AC-M4B-40）：原申请失败且当前条件再次满足 | 企业重新发起 | 新申请使用新编号和新的销毁交易；原失败记录不改写；新交易刚发起不发送运营知会，成功或失败后按结果发送 |
| <a id="AC-M4B-43"></a>违约代币不可销毁（AC-M4B-43）：代币留在质押合约地址 | 企业或运营尝试发起 | 不生成新申请，运营不能强制执行；按质押地址和融资中如实展示 |
| <a id="AC-M4B-44"></a>停用合约的既有代币（AC-M4B-44）：原合约已停用 | 按原条件申请销毁 | 既有代币仍由企业钱包按原合约直接提交；停用不等于链上失败；不需要运营先审核或启用 |
| <a id="AC-M4B-45"></a>身份或资格变化（AC-M4B-45）：调起钱包前身份、资格或必要依据变化 | 继续提交 | 按当前事实重新校验，不沿用旧结果；不通过时不调起钱包、不产生申请或消息 |

## 3. 解除资产托管

| 前提 | 操作 | 预期结果 |
| --- | --- | --- |
| <a id="AC-M4B-22"></a>待办形成（AC-M4B-22）：有销毁成功、销毁中与失败记录 | 资产托管机构查看列表 | 只有销毁成功形成待解除事项；销毁中或失败不形成待办 |
| <a id="AC-M4B-23"></a>只有本代币的资产托管机构可办理（AC-M4B-23）：锁定名单内的资产托管机构、法律服务机构、审计机构，另一发行的资产托管机构，运营和企业；资产托管机构之后更名或停用 | 分别尝试解除 | 只有铸造成功时确定的唯一资产托管机构可办理；更名后仍为同一机构，停用后仍可办理既有事项；法律服务机构、审计机构只能查看、不能办理；其他发行的机构、运营和企业均无权办理，直接请求也被拒绝 |
| <a id="AC-M4B-24"></a>详情核对（AC-M4B-24）：待解除事项 | 进入详情 | 展示企业、资产、代币、完整销毁数量与代币符号、成功时间和托管开始时间 |
| <a id="AC-M4B-25"></a>销毁与解除分离（AC-M4B-25）：已销毁但未解除 | 企业、运营、资产托管机构查看 | 代币保持已销毁，托管显示待解除；不把销毁成功当作已解除 |
| <a id="AC-M4B-26"></a>解除说明与通知文件（AC-M4B-26）：解除说明空白；未上传通知文件；文件份数、格式或大小不符；部分文件上传失败 | 提交解除 | 解除说明必填且不可纯空白；通知文件必须 1 至 10 份且全部上传成功；格式、大小与内容识别按 M3b 机构材料的单次规则拒绝不合规文件；任一不满足都不能提交，待办保持待解除 |
| <a id="AC-M4B-27"></a>解除成功（AC-M4B-27）：权限和前置条件有效 | 提交 | 记录办理机构、操作人、时间、解除说明和通知文件，状态为已解除托管，企业收 NT-C08；通知文件之后不可覆盖、替换或删除 |
| <a id="AC-M4B-28"></a>解除并发与未确认（AC-M4B-28）：双击、并发提交或结果暂缺 | 重复操作 | 只产生一笔生效记录，后到的提交被拒绝并返回已解除结果；未确认时取原结果，不重复解除；企业只收一条 NT-C08 |
| <a id="AC-M4B-29"></a>企业与名单内机构可见范围（AC-M4B-29）：完整解除记录已存在 | 企业、法律服务机构、审计机构分别查看，并直接请求操作人信息 | 均可看已解除、办理机构名称、完成时间、解除说明，并可查看、下载解除托管通知文件；操作人不可取得；文件读取失败时说明暂时无法获取，可以重试 |
| <a id="AC-M4B-30"></a>解除结果矛盾（AC-M4B-30）：销毁成功依据缺失或已有解除记录 | 尝试提交 | 依据缺失不放行；已解除只看原记录；不伪造时间或第二笔记录 |
| <a id="AC-M4B-41"></a>机构停用与更名（AC-M4B-41）：原机构停用或更名 | 查看待办与历史 | 托管权限不改；历史使用当前机构名称并保留原完成时间 |
| <a id="AC-M4B-51"></a>销毁结果同步名单内机构（AC-M4B-51）：名单含资产托管机构、法律服务机构和审计机构；另有名单不含法律服务机构或审计机构的代币；平台入口与非平台入口各销毁成功一次 | 各机构查看消息、前往并返回 | 资产托管机构只收 NT-R02；法律服务机构、审计机构各收一条 NT-R04，打开后进入本机构代币台账的只读详情，可见销毁成功事实，解除后可见解除记录与通知文件，没有办理动作；名单没有这两类机构时不发 NT-R04；重复送达不新增消息；销毁失败不向机构发消息 |

## 4. 代币台账与单位价值

| 前提 | 操作 | 预期结果 |
| --- | --- | --- |
| <a id="AC-M4B-31"></a>全平台台账（AC-M4B-31）：有未销毁与已销毁代币 | 运营查看 | 包含全部铸造成功代币，字段、精度、价值口径与 01 册一致 |
| <a id="AC-M4B-32"></a>本机构台账（AC-M4B-32）：同一发行的名单内机构与另一发行的资产托管机构 | 分别查看 | 只返回本机构参与发行的代币；资产托管机构在已销毁待解除时可前往解除事项，其他阶段只读；法律服务机构、审计机构全程只读，无解除动作 |
| <a id="AC-M4B-33"></a>调价输入（AC-M4B-33）：新值小于等于零、等于当前值或原因空白 | 提交 | 均不提交链上更新；有效时展示新旧单位价值与新旧估值 |
| <a id="AC-M4B-34"></a>调价成功（AC-M4B-34）：未销毁代币 | 提交并确认链上成功 | 新单位价值成为当前值并重算估值；发行数量、原值和初始值不变；保留历史 |
| <a id="AC-M4B-35"></a>调价失败（AC-M4B-35）：链上更新失败 | 查看台账 | 保留原当前值与失败记录；不影响销毁或托管状态 |
| <a id="AC-M4B-36"></a>已销毁代币不调价（AC-M4B-36）：代币已销毁 | 运营尝试调整 | 不提供调整动作，直接提交也被拒绝；历史价值可查 |
| <a id="AC-M4B-37"></a>台账追溯（AC-M4B-37）：代币有发行、多笔销毁与解除记录 | 按编号前往 | 准确到达原发行、资产、每笔销毁和解除记录；台账可见不额外授权 |
| <a id="AC-M4B-38"></a>价值精度与语言（AC-M4B-38）：有多小数值和中英文 | 查看列表、详情和历史 | 普通展示与业务完整值分工正确；“1 COU = X USD”、时区和原文原因符合共同规则 |
| <a id="AC-M4B-42"></a>合约名称变更（AC-M4B-42）：合约改名或停用 | 查看既有代币 | 合约名称取当前值，链上身份、代币、数量和历史不改 |
| <a id="AC-M4B-46"></a>并发调价（AC-M4B-46）：已有单位价值更新处理中 | 另一运营再次提交 | 不并发第二次更新；当前值在结果确认前不变 |
| <a id="AC-M4B-47"></a>调价历史（AC-M4B-47）：有成功、失败和后续成功记录 | 查看历史 | 保留新旧值、新旧估值、原因、操作人、时间、结果和已提交交易哈希 |
| <a id="AC-M4B-48"></a>未知链上结果（AC-M4B-48）：调价结果未确认 | 刷新或重新登录 | 取得原结果，不提前生效新值，不因刷新新建调价记录 |

## 5. 消息

| 前提 | 操作 | 预期结果 |
| --- | --- | --- |
| <a id="AC-M7-31"></a>销毁与解除消息（AC-M7-31）：成功、失败、待解除与解除成功，包含非平台入口、重复送达与无权场景 | 分别以企业、运营和名单内机构查看、前往并返回 | 销毁刚发起不发送运营消息；NT-C06 向企业告知成功；NT-C10 告知企业失败与新交易指引；NT-A04 只向运营知会失败且无重试动作；NT-A05 向运营知会成功，非平台入口须标记来源；NT-R02 只发给本代币唯一的资产托管机构作为解除待办，NT-R04 向名单内法律服务机构、审计机构同步销毁结果；NT-C08 告知企业已解除；内容、语言、时区、60 秒可见、去重、已读、准确定位与权限边界符合 03 册和 M7 |
