# 代币发行 · 审核与铸造 · 功能与业务规则

2026-11-09｜管理端：运营管理人员、机构账号｜需求评审稿

本模块共四册：本册写功能、业务规则、字段与跨模块衔接；[流程图与状态机](./02-代币发行-审核与铸造-流程图与状态机.md)描述主流程和状态；[消息通知](./03-代币发行-审核与铸造-消息通知.md)定义本模块发出的消息；[验收](./04-代币发行-审核与铸造-验收.md)供测试使用。

机构是运营分配的材料补充角色，不承担发行审核，不提供通过、驳回、认可或“材料齐全”结论。功能编号沿用既有编号，缺号不代表遗漏。

## 1. 模块是什么

企业提交发行申请后，运营先为申请分配至少一家机构，再进行唯一一次发行处理：运营可以驳回申请，也可以选择合约并发起铸造。机构在获得分配后通过本模块的材料待办追加共享材料，但材料数量、首次上传和是否齐全都不改变申请状态，也不阻止运营驳回或发起铸造。

基本原则：

- 机构只获得获分配申请的访问与材料追加权限，不审核发行申请。
- 运营驳回或发起铸造时必须已有至少一家分配机构；发起铸造时名单中还须有一家资产托管机构，运营驳回不要求。
- 机构分配只能新增，不能移除或替换；同一份申请中每种机构类型最多分配一家。
- 机构后续停用不解除既有分配；误分配不提供替换，只能驳回。
- 铸造超时或失败无法通过重试解决时，由开发人员线下处理，平台不设终止出口。
- 代币数量按原始资产价值 1:1 确定，初始代币单位价值只用于确定每个代币铸造时的 USD 价值，不用于反算代币数量。
- 机构材料与运营处理并行，零材料也不阻断驳回或铸造。
- 运营驳回只终止本申请。资产回到“可发行”后，企业可用同一资产发起新申请，按[驳回后重新发起（C-ISSUE-09）](../../面客端/M3a-代币发行-企业申请/01-代币发行-企业申请-PRD.md#C-ISSUE-09)办理【确认】；新申请是另一笔申请，重新分配机构，原申请的名单、待办和材料不带入。

**一个完整的例子。** 企业提交一笔原始资产价值为 12,345.675 USD 的发行申请后，管理端申请进入内部状态“待分配机构”，企业端显示“运营处理中”，全体运营收到一条待分配机构消息。运营分配一家资产托管机构和一家审计机构后，管理端进入“运营处理中”，企业端状态不变；机构可并行追加材料。运营选择代币符号为 COU 的兼容合约，将初始代币单位价值设为 1 COU = 0.8 USD 并发起铸造；代币数量为 12,345.675 COU，按初始代币单位价值计算的资产价值为 9,876.54 USD。铸造成功后，企业查看代币结果，发起铸造时的机构名单快照成为本次发行的锁定机构名单并交给相邻模块承接，其中的资产托管机构由 M4b 承接后续解除资产托管。

主流程：

`企业提交 → 待分配机构 → 运营至少分配 1 家机构 → 运营处理中 → 运营驳回 / 发起铸造 → 铸造中 → 铸造成功 / 铸造失败`

### 1.2 本期不做

- 不让机构进入发行审核菜单、给出审核结论或终止申请。
- 不要求机构完成首次上传，也不判断机构材料是否齐全。
- 不向企业展示机构分配名单或机构操作过程；铸造成功前和运营驳回后，也不向企业展示机构材料。
- 不定义铸造成功后的代币数据范围、后续材料、资产托管、销毁或解除资产托管；这些范围由 M4b 定义。
- 除发起铸造须有一家资产托管机构外，不把机构类型映射为审核级别、固定顺序或必须凑齐的类型组合。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 待分配机构 | 企业已提交申请，但运营尚未保存至少一家当前分配机构；不能驳回或铸造 |
| 运营处理中 | 已成功分配至少一家启用机构，运营可以驳回；名单中有资产托管机构时也可以发起铸造 |
| 当前分配名单 | 运营在申请进入铸造或驳回前为申请新增的机构集合；只增不减，每种机构类型最多一家 |
| 铸造名单快照 | 运营发起铸造时冻结的机构集合，铸造中、失败和重试期间不变 |
| 锁定发行机构名单 | 运营驳回时取当时的当前分配名单，铸造成功时取铸造名单快照；只作为本次发行的机构关系结果；本模块不据此授予铸造后的代币、资产托管或材料权限 |
| 机构材料 | 名单内机构追加的“上传说明 + 文件”共享记录，不是审核意见，也不是铸造条件 |
| 发行申请文件 | 企业随申请提交并冻结的文件，与机构后续追加的材料不同 |
| 运营驳回 | 运营给出的唯一发行否决结果；本申请终止，不再铸造；不阻止企业用同一资产发起新申请 |
| 铸造失败 | 本次平台签名、交易提交或链上执行失败，或开发人员查明本次铸造失败；运营可按原参数重试，不能驳回或终止 |
| 机构关联结果 | 本模块向 M2 提供的、与一笔发行申请及其资产关联的机构，见[机构关联结果](#institution-link) |
| 原始资产价值 | 申请所用可信资产这笔应收账款的完整金额与币种，确权后不变，是代币数量的依据（1:1），定义见可信资产（M2）的[术语](../../两端共用/M2-可信资产/01-可信资产-PRD.md#2-术语) |
| 代币单位价值 | 每个代币对应的 USD 价值，格式为“1 COU = X USD”；发起铸造时由运营填写的值称初始代币单位价值，随铸造上链，按[代币单位价值展示](#unit-value-display)以完整值展示 |
| 资产价值 | 即代币价值 = 代币数量 × 代币单位价值，单位 USD；本模块只在发起铸造的复核与确认中展示按初始代币单位价值计算的资产价值；铸造成功后，申请记录不再展示资产价值，代币的资产价值及其调整记录在 M4b 全平台代币台账查看【确认】 |

## 3. 谁能使用

- 运营管理人员进入“发行审核”，查看全平台申请，维护机构分配，查看机构材料，并在满足条件时驳回或发起铸造。
- 机构不显示运营使用的“发行审核”菜单。机构从“机构待办”菜单进入本模块的机构材料待办，查看获分配申请并追加材料，也可查看已关闭申请的历史；不能查看未分配申请，也没有驳回、发起铸造或重试权限。运营不显示“机构待办”菜单。
- 机构在申请详情中可以看到除企业业务签名和内部铸造失败说明以外的全部信息，逐区范围见[申请详情（A-ISSUE-02）](#A-ISSUE-02)【确认】。
- 企业在 M3a 查看自己的申请和企业可见结果；企业不能选择或查看机构名单和运营内部记录。
- 原发行企业只在申请铸造成功后查看机构材料，入口为 M4a 代币详情的[发行机构文件](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#institution-files)，范围按[申请与文件访问范围](#file-access)。

所有写操作都在提交时重新校验账号、角色、申请最新状态、分配名单和业务前提。页面打开后权限或状态变化的，拒绝旧页面提交并返回最新结果，不静默覆盖。

## 4. 申请状态与动作

<a id="status"></a>

| 申请状态 | 运营可做 | 机构可做 | 企业所见 |
|---|---|---|---|
| 待分配机构 | 查看、分配机构 | 无访问权 | 运营处理中 |
| 运营处理中 | 查看、新增其他类型机构、查看材料、驳回；名单中有资产托管机构时发起铸造 | 名单内机构查看申请并追加材料 | 运营处理中 |
| 运营驳回 | 查看历史 | 锁定名单内机构历史只读；待办关闭 | 运营驳回，并见驳回意见 |
| 铸造中 | 查看进度；不能驳回、重试、重复铸造或新增机构，超时也不例外 | 名单快照内机构继续查看、追加材料 | 发行处理中 |
| 铸造失败 | 查看失败详情、按原参数重试；不能驳回、终止或新增机构 | 名单快照内机构继续查看、追加材料 | 发行处理中 |
| 铸造成功 | 查看代币结果 | 锁定名单内机构只读查看发行申请与已有材料；材料待办关闭；代币销毁成功前可在 M4b 继续追加材料，见[铸造后追加机构材料（R-TOKEN-02）](../M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#R-TOKEN-02) | 铸造成功，并见代币结果；在 M4a 代币详情只读查看机构材料 |

材料上传与状态转换相互独立。机构零材料、首次待办未完成或部分机构未上传时，运营仍可在“运营处理中”驳回或发起铸造。

## 5. 查看发行申请

<a id="A-ISSUE-01"></a>

### 5.1 发行申请列表（A-ISSUE-01）

运营查看全部发行申请。列表至少展示申请编号、企业名称、资产编号、资产类型、原始资产价值、提交时间、申请状态、已分配机构数量和最近处理时间。

- 可按申请编号、企业名称、资产编号搜索；按状态、资产类型和提交时间筛选。
- 默认按最近处理时间倒序，同一时间按申请编号倒序。
- 分页、返回位置、空状态与读取失败按可信资产（M2）的[业务列表通用规则](../../两端共用/M2-可信资产/01-可信资产-PRD.md#list-common)。
- “待分配机构”与“运营处理中”必须分开，不能用“待审核”统称。
- 已分配机构数量按当前或锁定名单计算；企业不看到该字段。
- 点击申请进入详情；无结果时说明当前条件下没有申请。

<a id="A-ISSUE-02"></a>

### 5.2 申请详情（A-ISSUE-02）

运营可查看全部申请的详情；名单内机构可查看获分配申请的详情，能看到除企业业务签名和内部铸造失败说明以外的全部信息【确认】。哪些机构属于名单内机构按[机构关联结果](#institution-link)确定。各信息区的内容与可见范围：

| 信息区 | 内容 | 运营 | 名单内机构 |
|---|---|---|---|
| 申请概览 | 申请编号、状态、提交时间、最近处理时间 | 可见 | 可见，状态为本模块真实状态 |
| 企业与资产 | 企业、企业登记标识、资产编号、类型、原始资产价值、到期时点、债务人名称、债务人英文名称（与可信资产（M2）同名字段一致；上游未提供英文名称时不补写） | 可见 | 可见 |
| 发行信息：接收地址与发行申请文件 | 接收地址；发行申请文件的原文件名、格式、大小、提交时间和访问操作记录 | 可见 | 可见 |
| 发行信息：企业业务签名 | 签名地址、签名时间、签名值和所签内容 | 可见 | 不可见，直接请求也不返回 |
| 机构分配 | 当前、快照或锁定名单，机构名称、分配时的机构类型、当前启停状态、分配时间 | 可见 | 可见 |
| 共享机构材料 | 上传机构、说明、文件、上传时间和历史记录；新上传不能覆盖旧记录。申请铸造成功后，同时只读展示名单内机构经 M4b [铸造后追加机构材料（R-TOKEN-02）](../M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#R-TOKEN-02)追加的材料；追加入口在 M4b，本模块不提供追加 | 可见 | 可见，范围按[申请与文件访问范围](#file-access) |
| 运营处理 | 驳回意见原文，或所选合约、初始代币单位价值（按[代币单位价值展示](#unit-value-display)）和发起铸造记录 | 可见 | 可见 |
| 铸造过程与结果 | 阶段、交易哈希、失败记录、重试记录、成功代币信息 | 可见，含内部铸造失败说明 | 可见，但不含内部铸造失败说明 |
| 同一资产的其他申请 | 同一资产此前或之后的其他发行申请：申请编号、申请状态、提交时间，运营驳回的另含驳回时间和意见原文；可进入对应申请详情 | 可见 | 不可见；机构只能查看本机构关联的申请 |
| 进度概览与操作进度 | 见下方两层进度，含操作主体的角色与账号 | 可见 | 可见，但铸造失败记录不含内部铸造失败说明 |

申请详情按以下两层呈现处理进度：

- 页面上方展示紧凑的进度概览，只说明“企业提交、机构分配、运营处理、铸造”四个阶段各自的完成、当前或未开始状态，不在此重复操作人、意见和失败详情。
- 页面最下方展示“操作进度”时间线，按发生时间从早到晚记录企业提交、每次新增机构、运营驳回、首次发起铸造、铸造明确失败、运营重试和铸造成功。每条至少展示业务动作或结果、操作主体的角色与账号、发生时间及其时区、处理结果；驳回记录展示驳回意见，铸造失败记录展示已取得的失败说明和交易哈希，未取得的值不编造。
- 机构材料上传历史和文件访问记录仍在各自信息区展示，不在操作进度中重复，以免把不推动申请状态的行为误解为审核环节。

上述上下位置与信息分层是已确认的页面约束；进度条高度、间距、颜色和时间线视觉样式由原型定义。

待分配机构时只开放查看和机构分配。界面和提交校验层均阻止驳回、发起铸造；保存至少一家机构后，申请进入“运营处理中”并开放驳回；名单中有资产托管机构时同时开放发起铸造，否则说明须先新增一家资产托管机构。

<a id="A-ISSUE-08"></a>

### 5.3 分配机构（A-ISSUE-08）

适用角色与前提：正常运营账号；申请为“待分配机构”或“运营处理中”。

企业提交成功、申请进入“待分配机构”时，向全体运营发送一条[新发行申请待分配机构（NT-A07）](./03-代币发行-审核与铸造-消息通知.md#NT-A07)，运营从消息进入该申请详情分配机构。

名单规则：

- 运营只能为申请新增机构；已保存的分配不能移除、替换或撤销。
- 同一份申请中每种机构类型最多分配一家。本期机构类型为 M5 固定的资产托管机构、审计机构、法律服务机构三类，因此一份申请最多分配三家机构；不要求三类齐全，但发起铸造前须有一家资产托管机构，见[选择合约并发起铸造（A-ISSUE-04）](#A-ISSUE-04)。
- 一次可新增一家或多家，但同一次所选机构的类型不得重复，也不得与名单中已有机构的类型相同。
- 机构类型以保存分配时 M5 记录的类型为准，并随分配记录保存。机构之后在 M5 修改类型，不改变已有分配记录或使名单失效；再新增时，以名单内已保存的类型和候选机构的最新类型判断是否重复。

新增与保存：

- 候选范围只包含 M5 当前为启用、且类型尚未出现在本申请名单中的机构；停用的机构不出现在候选范围中【确认】。
- 保存前须确认本次新增的机构名称和类型，并明确提示保存后不能移除或替换。
- 保存后，每家新机构立即获得本申请的访问权和一条首次材料待办。机构材料数量不影响保存结果。
- 首次成功保存后申请从“待分配机构”进入“运营处理中”。此后名单不会变空，申请不再回到“待分配机构”。
- 运营处理中仍可新增尚未分配类型的机构；申请进入运营驳回或铸造中后不能再新增。

停用与异常：

- 已分配机构后来停用时，继续承担既有分配：既有分配、待办和访问权继续有效，仍可办理本申请；作为资产托管机构的，铸造成功后仍按 M4b 承担销毁后的解除托管【确认】。该机构继续占用其类型，运营不能用同类型的其他机构替代。停用机构不能新增到其他申请。
- 误分配机构时不提供移除或替换；运营认为不能用该名单继续发行的，只能驳回申请【确认】。
- 未选择机构、所选机构已停用、同次所选类型重复、所选类型已在名单中，或申请已不在可分配状态时，本次保存整体失败并说明原因；原名单、权限、待办和申请状态均不变，不做部分保存。
- 多名运营并发新增时按最新名单重新校验：与最新名单类型不冲突的新增可以成功，冲突时整次失败并返回最新名单；任何保存都不会移除或覆盖已有分配。

<a id="R-ISSUE-06"></a>

### 5.4 机构材料待办与追加（R-ISSUE-06）

机构材料待办列表展示当前分配给本机构且尚可办理的申请，至少包含申请编号、企业名称、资产编号、分配时间、首次材料状态和申请状态。机构从待办进入申请详情，只能查看本册允许的信息与共享材料，不显示发行审核、驳回、铸造或重试操作。

待办列表的查找与排序【确认】：

- 可按申请编号、企业名称、资产编号查找。
- 可按首次材料状态筛选，取值为待上传、已完成。
- 默认按分配时间由新到旧排列。

<a id="closed-history"></a>

已关闭申请的历史查看【确认】：

- 机构材料待办同时提供已关闭申请的历史查看，列出锁定名单内包含本机构、申请状态为“运营驳回”或“铸造成功”的申请。同一资产先后多笔申请的锁定名单都包含本机构时，各笔申请分别列出。
- 历史列表至少展示申请编号、企业名称、资产编号、分配时间、首次材料状态（已关闭）、申请状态和关闭时间。关闭时间为该申请运营驳回生效的时间或铸造成功的时间。
- 可按申请编号、企业名称、资产编号查找；可按申请结果筛选，取值为运营驳回、铸造成功。
- 默认按关闭时间由新到旧排列。
- 历史申请只读：机构可按[申请与文件访问范围](#file-access)查看申请详情、企业文件和已有材料，不能上传、替换或删除。铸造成功的申请，锁定名单内机构在代币销毁成功前改在 M4b 本机构代币台账追加材料，见[铸造后追加机构材料（R-TOKEN-02）](../M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#R-TOKEN-02)。
- 本机构从未进入锁定名单的申请不出现在历史中；直接访问按无权处理。
- 没有已关闭申请时说明暂无历史申请。

待办列表和历史列表的分页、返回位置、空状态、无匹配与读取失败按可信资产（M2）的[业务列表通用规则](../../两端共用/M2-可信资产/01-可信资产-PRD.md#list-common)。

待办规则：

- 每个“机构 + 发行申请”只有一条首次材料待办，状态为待上传、已完成或已关闭。
- 首次成功保存一条材料记录后，待办变为已完成；已完成后仍可继续追加材料，后续追加不产生新的首次待办。
- 待办完成、材料数量和材料是否齐全都不改变发行申请状态，也不构成运营处理前提。
- 申请被运营驳回或铸造成功时待办关闭，申请转入已关闭申请的历史查看；关闭后在本模块只能按权限查看历史，不能继续上传。运营驳回的申请不再追加材料；铸造成功的申请，锁定名单内机构在代币销毁成功前改在 M4b 继续追加，见[铸造后追加机构材料（R-TOKEN-02）](../M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#R-TOKEN-02)。
- 申请处于铸造中或铸造失败时，名单快照内机构仍可追加材料；申请状态不因此变化。

每次追加材料均须满足：

- 上传说明必填，去除首尾空白后不得为空。
- 每次选择 1 至 10 份文件，每份最大 10 × 1024 × 1024 字节；只有上传成功的文件计入本次份数。
- 只接受 PDF、JPG、JPEG、PNG；平台按文件实际内容识别，扩展名与内容不一致、空文件、Office 文档、压缩包和可执行文件均拒绝。
- 一次上传有上传中或失败未移除项时不能保存。保存成功后形成新的材料记录，不覆盖、替换或删除历史记录。
- 本期不设累计材料份数上限；后续每次追加仍独立按上述单次规则校验。

每条材料记录保存上传机构、上传说明、成功文件的原文件名、格式、大小、上传时间和访问操作记录。材料记录保存后不可覆盖、替换或删除；读取失败时说明暂时无法获取，不把失败显示为空材料。

## 6. 运营处理

<a id="A-ISSUE-04"></a>

### 6.1 选择合约并发起铸造（A-ISSUE-04）

前提：

- 账号正常；申请最新状态为“运营处理中”。
- 当前名单中有一家资产托管机构，按该机构保存分配时记录的类型判断；审计机构、法律服务机构不要求。
- 已分配的资产托管机构后来停用，或之后在 M5 修改类型，仍满足本前提；既有分配中的机构后来停用不使名单失效。
- 机构材料可以为零。

名单中没有资产托管机构时不能发起铸造，说明须先新增一家资产托管机构；运营仍可新增机构或驳回。

运营须确认：

- 选择一个当前为启用、资产类型与申请资产相同、网络为 Ethereum 的合约，查看名称、标准、代币符号、资产类型、网络和合约地址。
- 填写大于 0 的初始代币单位价值，币种固定为 USD，默认值为 1，精度不得超过合约及业务共同支持的精度。
- <a id="unit-value-display"></a>代币单位价值展示【确认】：初始代币单位价值在本模块各处按运营填写的完整值展示，不补零、不截断，格式为“1 COU = X USD”，例如 1 COU = 1 USD、1 COU = 0.8 USD；COU 为所选合约的代币符号。
- 代币数量直接取申请中的原始资产价值，数值比例为 1:1，单位为所选合约的代币符号；不用初始代币单位价值反算数量。
- 系统按“完整代币数量 × 初始代币单位价值”计算资产价值（即代币价值），币种为 USD。资产价值不上链，按[两位小数截断展示](../../两端共用/M2-可信资产/01-可信资产-PRD.md#amount-display)展示【确认】；铸造后的变化在 M4b [调整代币单位价值（A-TOKEN-02）](../M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#A-TOKEN-02)的调整记录中查看，调整记录仅运营可见。
- 复核申请、企业业务签名、接收地址、[上链字段](#onchain-fields)、合约、初始代币单位价值和数量。

确认后再次校验申请状态、名单、合约资格和初始代币单位价值。成功时：

1. 记录操作账号、时间、合约、初始代币单位价值、数量和当时的机构名单快照。
2. 申请原子进入“铸造中”，不再允许驳回、新增机构或重复发起。
3. 向企业发送[发行申请进入铸造（NT-C03）](./03-代币发行-审核与铸造-消息通知.md#NT-C03)。
4. 平台签名并向所选合约提交铸造交易。

另一位运营已处理、名单中没有资产托管机构或合约不再满足新发行资格时，本次提交失败且不产生部分结果，页面返回最新状态。机构在既有分配后停用不属于名单失效。

<a id="onchain-fields"></a>

#### 6.1.1 上链字段

每次铸造写入链上的业务字段固定为以下六项，不增不减【确认】：

1. 资产编号。
2. 原始资产价值（完整值），与代币数量相同（按 1:1）。
3. 唯一到期时点，口径按[可信资产（M2）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#due-time)中的到期时点。
4. 企业提交时的接收地址。
5. 企业业务签名值。
6. 初始代币单位价值。

- 代币符号由所属合约体现，不作为每次铸造写入的字段。
- 交易所属的合约地址和交易哈希是交易本身的属性，记录在铸造结果中，不属于上述写入字段。
- 发行申请文件及其摘要不上链；企业资料、机构名单、机构材料、驳回意见、操作账号和消息也不上链。机构名单和材料不构成机构审核结论。

<a id="A-ISSUE-05"></a>

### 6.2 运营驳回（A-ISSUE-05）

前提：账号正常；申请最新状态为“运营处理中”；当前名单至少有一家机构。不要求选择合约，不要求名单中有资产托管机构，也不要求机构上传材料。

- 驳回意见必填，1 至 500 个字符；去除首尾空格后不能为空。
- 提交前提示驳回后本申请终止、不能恢复或铸造；企业可用同一资产另行发起新申请。
- 成功后申请进入“运营驳回”，记录意见、时间和账号，锁定当时的分配名单。
- 关闭锁定名单内未完成待办，停止机构继续上传；历史材料保留。运营可查看，锁定名单内机构按[申请与文件访问范围](#file-access)保留历史只读权限，但不获得代币权限。
- 企业收到[发行申请已驳回（NT-C04）](./03-代币发行-审核与铸造-消息通知.md#NT-C04)，并查看原文驳回意见。
- 资产发行状态按 M2 [发行状态](../../两端共用/M2-可信资产/01-可信资产-PRD.md#issue-status)回到“可发行”；满足发起条件时企业可用这笔资产发起新申请。新申请生成新的申请编号，从“待分配机构”开始重新办理；本申请的锁定名单、待办、材料和机构关联保持不变，不带入新申请。

## 7. 铸造

<a id="A-ISSUE-06"></a>

### 7.1 铸造结果（A-ISSUE-06）

<a id="minting-progress"></a>

#### 7.1.1 铸造中与超时

- 展示“平台签名并提交”和“等待链上结果”两个阶段；已提交后展示交易哈希。
- 铸造开始满 10 分钟仍无明确结果时，申请仍为“铸造中”，不自动判失败；平台不提供重试或驳回【确认】。
- 每次铸造最多向全体运营发送一条[铸造超时待处理（NT-A05）](./03-代币发行-审核与铸造-消息通知.md#NT-A05)，提示运营联系平台开发人员。企业和机构不收该消息。
- 由开发人员线下查明原因并处理；平台按链上实际结果或开发人员查明的结果，收口为[铸造成功](#handoff-mint)或[铸造失败](#mint-failed)【确认】。
- 收口前企业仍见“发行处理中”，资产保持“发行申请中”。

<a id="handoff-mint"></a>

#### 7.1.2 铸造成功

- 申请进入“铸造成功”终态；资产发行状态变为“已发行”。
- 生成唯一代币编号，记录成功时间、网络、合约地址、交易哈希、完整数量、符号、初始代币单位价值（按[代币单位价值展示](#unit-value-display)）和接收地址；铸造成功记录不展示资产价值，代币的资产价值在 M4b 全平台代币台账查看。
- 发起铸造时已冻结的名单快照在铸造成功后成为锁定发行机构名单，作为本次发行的机构关系结果，不代表审核或认可；名单记录每家机构分配时的类型，其中有一家资产托管机构。
- 关闭本模块全部未完成材料待办，停止继续上传；锁定名单内机构按[申请与文件访问范围](#file-access)只读查看发行申请和已有材料，以及铸造成功后经 M4b 追加的材料。本模块不据此授予代币、资产托管、解除资产托管或铸造后材料权限，这些由 M4b 定义；铸造成功后、代币销毁成功前的材料追加见[铸造后追加机构材料（R-TOKEN-02）](../M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#R-TOKEN-02)。
- 原发行企业自此可按[申请与文件访问范围](#file-access)，在 M4a [发行机构文件](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#institution-files)中只读查看、下载这些材料，以及铸造成功后名单内机构按 M4b 追加的材料。
- 企业收到[铸造成功（NT-C05）](./03-代币发行-审核与铸造-消息通知.md#NT-C05)。

<a id="mint-failed"></a>

#### 7.1.3 铸造失败

- 平台签名、交易提交或链上执行失败，或开发人员查明本次铸造失败时，申请进入“铸造失败”；资产保持“发行申请中”。
- 每次失败记录失败时间、取得到的失败说明和已产生的交易哈希；取不到不编造，未上链则无哈希。
- 运营看完整失败和重试记录；企业仍见“发行处理中”；机构不看内部失败说明。
- 当前机构名单和材料权限继续有效；材料上传不改变失败状态。
- 每次失败向全体运营发送[铸造失败待重试（NT-A03）](./03-代币发行-审核与铸造-消息通知.md#NT-A03)。
- 铸造失败后只能按原参数[手动重试](#A-ISSUE-07)，不提供驳回或终止。失败原因无法通过重试解决时，申请保持“铸造失败”、资产保持“发行申请中”，由线下处理；平台接受申请长期停留在该状态【确认】。

<a id="A-ISSUE-07"></a>

### 7.2 铸造失败手动重试（A-ISSUE-07）

账号正常的运营可对“铸造失败”申请重试。重试沿用首次发起时锁定的合约、上链信息、初始代币单位价值、数量、接收地址和机构名单快照，不重新审核，不重新校验资产托管机构前提，不允许改值。

- 原合约之后被平台停用，不阻断重试；重试仍使用原合约【确认】。
- 确认后再次校验状态，进入“铸造中”，记录重试时间和账号，提交新交易。
- 重试未能记录时本次重试不生效：申请保持“铸造失败”，不提交交易、不发消息，运营可再次重试。
- 平台不自动重试；每次重试都由运营手动发起。
- 重试不是新的运营处理，不重复发送 NT-C03。
- 每次交易和结果单独记录；成功后收口，失败后仍可重试。重试后的等待、超时和失败按[铸造结果（A-ISSUE-06）](#A-ISSUE-06)处理。
- 并发重试仅第一个有效提交生效，其余返回最新状态。

| 机构材料 | 铸造成功前及运营驳回不可见；铸造成功后经 M4a 只读查看、下载，不见上传账号和访问记录 | 按当前或锁定名单共享 | 可见 |
| 运营驳回意见与时间 | 可见 | 锁定名单内可见驳回意见原文、时间和操作账号 | 可见，另见操作账号 |

管理端保存本册真实状态；企业端按 M3a 只显示“运营处理中、运营驳回、发行处理中、铸造成功”。内部“待分配机构”和“运营处理中”均映射为企业“运营处理中”；首次分配、后续新增机构、机构停用、材料上传和首次待办完成都不改变企业状态或进度。

资产详情中的申请状态按查看者区分【确认】：企业看 M3a 的企业可见状态；运营和名单内机构看本模块的真实状态。

<a id="institution-link"></a>

### 8.2 机构关联结果

机构关联结果说明哪些机构与一笔发行申请及其资产关联。本模块向[可信资产（M2）](../../两端共用/M2-可信资产/01-可信资产-PRD.md)提供该结果，M2 的[机构查看关联资产（F-AS-06）](../../两端共用/M2-可信资产/01-可信资产-PRD.md#F-AS-06)和[机构管理](../M5-机构管理/01-机构管理-PRD.md)据此确定机构能查看的关联资产【确认】。

- 关联自首次分配保存成功起建立；“待分配机构”的申请没有关联机构。
- 关联机构按申请所处阶段取对应名单中的机构：

| 申请状态 | 关联机构取自 |
|---|---|
| 运营处理中 | 当前分配名单；之后新增的机构保存成功即加入 |
| 铸造中 | 铸造名单快照 |
| 铸造失败 | 铸造名单快照 |
| 运营驳回 | 锁定发行机构名单 |
| 铸造成功 | 锁定发行机构名单 |

- 运营驳回和铸造成功后，关联都保留，机构只读查看【确认】。
- 同一资产驳回后发起的新申请，按上表另行确定关联机构；原申请的关联不转入新申请，新申请的关联也不使机构看到原申请。
- 同一资产有多笔申请时，机构只要与其中任一笔关联，即可查看这笔资产；查看范围只含本机构关联的那些申请。这笔资产后来铸造成功的代币，只有铸造成功那笔申请锁定名单内的机构可以查看，按 M4b [名单内机构](../M4b-销毁审核与解除质押/01-销毁审核与解除质押-PRD.md#listed-institutions)；只关联被驳回申请的机构看不到该代币。
- 机构停用不解除关联【确认】；机构在 M5 改名或修改类型也不改变关联。
- 关联结果只决定机构可查看的发行申请及其资产，不授予审核、代币、资产托管或解除资产托管权限；代币相关权限由 M4b 定义。

## 10. 依赖

- 依赖合约无损承载[上链字段](#onchain-fields)中的资产编号、原始资产价值（完整值，即代币数量）、唯一到期时点、接收地址、企业业务签名值和初始代币单位价值，由研发验证。只展示兼容本次资产与数值的合约，本册不写死合约小数精度。
- 上游资产可信平台约束【确认】：资产确权后，原始资产价值、到期日等资产信息不再变化；回款状态（结清、逾期）仍会变化；不存在撤销确权或上游删除资产的情形。本模块因此不设提交后资产信息变化的处理规则，签名、上链使用的资产值即提交时的资产值。
- 铸造超时或失败无法通过重试解决时，依赖平台开发人员线下查明原因并处理，平台按查明结果收口，见[铸造中与超时](#minting-progress)。
- 文件读取、下载和上传必须按[申请与文件访问范围](#file-access)校验，不能仅依赖页面隐藏。
