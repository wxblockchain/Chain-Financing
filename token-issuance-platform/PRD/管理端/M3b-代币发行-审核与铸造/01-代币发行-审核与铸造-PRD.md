# 代币发行 · 审核与铸造 · 功能与业务规则

2026-11-09｜管理端：运营管理人员、机构账号｜需求评审稿

本模块共四册：本册写功能、业务规则、字段与跨模块衔接；[流程图与状态机](./02-代币发行-审核与铸造-流程图与状态机.md)描述主流程和状态；[消息通知](./03-代币发行-审核与铸造-消息通知.md)定义本模块发出的消息；[验收](./04-代币发行-审核与铸造-验收.md)供测试使用。

机构是运营分配的材料补充角色，不承担发行审核，不提供通过、驳回、认可或“材料齐全”结论。功能编号沿用既有编号，缺号不代表遗漏。

## 1. 模块是什么

企业提交发行申请后，运营先为申请分配至少一家机构，再进行唯一一次发行处理：运营可以驳回申请，也可以选择合约并发起铸造。机构在获得分配后通过本模块的材料待办追加共享材料，但材料数量、首次上传和是否齐全都不改变申请状态，也不阻止运营驳回或发起铸造。

基本原则：

- 机构只获得获分配申请的访问与材料追加权限，不审核发行申请。
- 运营驳回或发起铸造时必须已有至少一家分配机构；发起铸造时名单中还须有一家资产托管机构，运营驳回不要求。
- 机构分配只能新增，不能移除或替换；同一份申请中每种机构类型最多分配一家。
- 机构后续停用不解除既有分配。
- 代币数量按完整资产价值 1:1 确定，初始单位价值只用于确定每个代币的初始 USD 价值，不用于反算代币数量。
- 机构材料与运营处理并行，零材料也不阻断驳回或铸造。

**一个完整的例子。** 企业提交一笔完整价值为 12,345.675 USD 的发行申请后，管理端申请进入内部状态“待分配机构”，企业端显示“运营处理中”。运营分配一家资产托管机构和一家审计机构后，管理端进入“运营处理中”，企业端状态不变；机构可并行追加材料。运营选择代币符号为 COU 的兼容合约，将初始单位价值设为 0.8 USD 并发起铸造；代币数量为 12,345.675 COU，初始资产估值为 9,876.54 USD。铸造成功后，企业查看代币结果，发起铸造时的机构名单快照成为本次发行的锁定机构名单并交给相邻模块承接，其中的资产托管机构由 M4b 承接后续解除资产托管。

主流程：

`企业提交 → 待分配机构 → 运营至少分配 1 家机构 → 运营处理中 → 运营驳回 / 发起铸造 → 铸造中 → 铸造成功 / 铸造失败`

### 1.2 本期不做

- 不让机构进入发行审核菜单、给出审核结论或终止申请。
- 不要求机构完成首次上传，也不判断机构材料是否齐全。
- 不向企业展示机构分配名单或机构操作过程；铸造成功前和运营驳回后，也不向企业展示机构材料。
- 不定义铸造成功后的代币数据范围、后续材料、资产托管、销毁或解除资产托管；这些范围由 M4b 定义。
- 除发起铸造须有一家资产托管机构外，不把机构类型映射为审核级别、固定顺序或必须凑齐的类型组合。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 待分配机构 | 企业已提交申请，但运营尚未保存至少一家当前分配机构；不能驳回或铸造 |
| 运营处理中 | 已成功分配至少一家启用机构，运营可以驳回；名单中有资产托管机构时也可以发起铸造 |
| 当前分配名单 | 运营在申请进入铸造或驳回前为申请新增的机构集合；只增不减，每种机构类型最多一家 |
| 铸造名单快照 | 运营发起铸造时冻结的机构集合，铸造中、失败和重试期间不变 |
| 锁定发行机构名单 | 运营驳回时取当时的当前分配名单，铸造成功时取铸造名单快照；只作为本次发行的机构关系结果；本模块不据此授予铸造后的代币、资产托管或材料权限 |
| 机构材料 | 名单内机构追加的“上传说明 + 文件”共享记录，不是审核意见，也不是铸造条件 |
| 发行申请文件 | 企业随申请提交并冻结的文件，与机构后续追加的材料不同 |
| 运营驳回 | 运营给出的唯一发行否决结果；申请终止，不再铸造 |
| 铸造失败 | 本次平台签名、交易提交或链上执行失败；运营可按原参数重试 |

## 3. 谁能使用

- 运营管理人员进入“发行审核”，查看全平台申请，维护机构分配，查看机构材料，并在满足条件时驳回或发起铸造。
- 机构不显示运营使用的“发行审核”菜单。机构从本模块的“机构材料待办”查看获分配申请并追加材料；不能查看未分配申请，也没有驳回、发起铸造或重试权限。
- 企业在 M3a 查看自己的申请和企业可见结果；企业不能选择或查看机构名单和运营内部记录。
- 原发行企业只在申请铸造成功后查看机构材料，入口为 M4a 代币详情的[发行机构文件](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#institution-files)，范围按[申请与文件访问范围](#file-access)。

所有写操作都在提交时重新校验账号、角色、申请最新状态、分配名单和业务前提。页面打开后权限或状态变化的，拒绝旧页面提交并返回最新结果，不静默覆盖。

## 4. 申请状态与动作

<a id="status"></a>

| 申请状态 | 运营可做 | 机构可做 | 企业所见 |
|---|---|---|---|
| 待分配机构 | 查看、分配机构 | 无访问权 | 运营处理中 |
| 运营处理中 | 查看、新增其他类型机构、查看材料、驳回；名单中有资产托管机构时发起铸造 | 名单内机构查看申请并追加材料 | 运营处理中 |
| 运营驳回 | 查看历史 | 锁定名单内机构历史只读；待办关闭 | 运营驳回，并见驳回意见 |
| 铸造中 | 查看进度；不能驳回、重复铸造或新增机构 | 当前名单内机构继续查看、追加材料 | 发行处理中 |
| 铸造失败 | 查看失败详情、重试；不能驳回或新增机构 | 当前名单内机构继续查看、追加材料 | 发行处理中 |
| 铸造成功 | 查看代币结果 | 锁定名单内机构只读查看发行申请与已有材料；材料待办关闭 | 铸造成功，并见代币结果；在 M4a 代币详情只读查看机构材料 |

材料上传与状态转换相互独立。机构零材料、首次待办未完成或部分机构未上传时，运营仍可在“运营处理中”驳回或发起铸造。

## 5. 查看发行申请

<a id="A-ISSUE-01"></a>

### 5.1 发行申请列表（A-ISSUE-01）

运营查看全部发行申请。列表至少展示申请编号、企业名称、资产编号、资产类型、完整资产价值、提交时间、申请状态、已分配机构数量和最近处理时间。

- 可按申请编号、企业名称、资产编号搜索；按状态、资产类型和提交时间筛选。
- 默认按最近处理时间倒序，同一时间按申请编号倒序。
- “待分配机构”与“运营处理中”必须分开，不能用“待审核”统称。
- 已分配机构数量按当前或锁定名单计算；企业不看到该字段。
- 点击申请进入详情；无结果时说明当前条件下没有申请。

<a id="A-ISSUE-02"></a>

### 5.2 申请详情（A-ISSUE-02）

详情按权限展示：

1. 申请概览：申请编号、状态、提交时间、最近处理时间。
2. 企业与资产：企业、注册号、资产编号、类型、完整价值、到期时点、债务人与交易对手。
3. 发行信息：接收地址；企业业务签名的签名地址、时间、值和所签内容；发行申请文件的原文件名、格式、大小、提交时间和访问操作记录。
4. 机构分配：当前或锁定名单、机构名称、分配时的机构类型、当前启停状态、分配时间。
5. 共享机构材料：上传机构、说明、文件、上传时间和历史记录；新上传不能覆盖旧记录。
6. 运营处理：驳回结果，或所选合约、初始单位价值和发起铸造记录。
7. 铸造过程与结果：阶段、交易哈希、失败记录、重试记录、成功代币信息。

运营申请详情按以下两层呈现处理进度：

- 页面上方展示紧凑的进度概览，只说明“企业提交、机构分配、运营处理、铸造”四个阶段各自的完成、当前或未开始状态，不在此重复操作人、意见和失败详情。
- 页面最下方展示“操作进度”时间线，按发生时间从早到晚记录企业提交、每次新增机构、运营驳回、首次发起铸造、铸造明确失败、运营重试和铸造成功。每条至少展示业务动作或结果、操作主体的角色与账号、发生时间及其时区、处理结果；驳回记录展示驳回意见，铸造失败记录展示已取得的失败说明和交易哈希，未取得的值不编造。
- 机构材料上传历史和文件访问记录仍在各自信息区展示，不在操作进度中重复，以免把不推动申请状态的行为误解为审核环节。

上述上下位置与信息分层是已确认的页面约束；进度条高度、间距、颜色和时间线视觉样式由原型定义。

待分配机构时只开放查看和机构分配。界面和提交校验层均阻止驳回、发起铸造；保存至少一家机构后，申请进入“运营处理中”并开放驳回；名单中有资产托管机构时同时开放发起铸造，否则说明须先新增一家资产托管机构。

<a id="A-ISSUE-08"></a>

### 5.3 分配机构（A-ISSUE-08）

适用角色与前提：正常运营账号；申请为“待分配机构”或“运营处理中”。

名单规则：

- 运营只能为申请新增机构；已保存的分配不能移除、替换或撤销。
- 同一份申请中每种机构类型最多分配一家。本期机构类型为 M5 固定的资产托管机构、审计机构、法律服务机构三类，因此一份申请最多分配三家机构；不要求三类齐全，但发起铸造前须有一家资产托管机构，见[选择合约并发起铸造（A-ISSUE-04）](#A-ISSUE-04)。
- 一次可新增一家或多家，但同一次所选机构的类型不得重复，也不得与名单中已有机构的类型相同。
- 机构类型以保存分配时 M5 记录的类型为准，并随分配记录保存。机构之后在 M5 修改类型，不改变已有分配记录或使名单失效；再新增时，以名单内已保存的类型和候选机构的最新类型判断是否重复。

新增与保存：

- 候选范围只包含 M5 当前为启用、且类型尚未出现在本申请名单中的机构。
- 保存前须确认本次新增的机构名称和类型，并明确提示保存后不能移除或替换。
- 保存后，每家新机构立即获得本申请的访问权和一条首次材料待办。机构材料数量不影响保存结果。
- 首次成功保存后申请从“待分配机构”进入“运营处理中”。此后名单不会变空，申请不再回到“待分配机构”。
- 运营处理中仍可新增尚未分配类型的机构；申请进入运营驳回或铸造中后不能再新增。

停用与异常：

- 已分配机构后来停用时，既有分配、待办和访问权继续有效，仍可办理本申请；该机构继续占用其类型，运营不能用同类型的其他机构替代。停用机构不能新增到其他申请。
- 未选择机构、所选机构已停用、同次所选类型重复、所选类型已在名单中，或申请已不在可分配状态时，本次保存整体失败并说明原因；原名单、权限、待办和申请状态均不变，不做部分保存。
- 多名运营并发新增时按最新名单重新校验：与最新名单类型不冲突的新增可以成功，冲突时整次失败并返回最新名单；任何保存都不会移除或覆盖已有分配。

<a id="R-ISSUE-06"></a>

### 5.4 机构材料待办与追加（R-ISSUE-06）

机构材料待办列表只展示当前分配给本机构且尚可办理的申请，至少包含申请编号、企业名称、资产编号、分配时间、首次材料状态和申请状态。机构从待办进入申请详情，只能查看本册允许的信息与共享材料，不显示发行审核、驳回、铸造或重试操作。

- 每个“机构 + 发行申请”只有一条首次材料待办，状态为待上传、已完成或已关闭。
- 首次成功保存一条材料记录后，待办变为已完成；已完成后仍可继续追加材料，后续追加不产生新的首次待办。
- 待办完成、材料数量和材料是否齐全都不改变发行申请状态，也不构成运营处理前提。
- 申请被运营驳回或铸造成功时待办关闭；关闭后只能按权限查看历史，不能继续上传。
- 申请处于铸造中或铸造失败时，名单快照内机构仍可追加材料；申请状态不因此变化。

每次追加材料均须满足：

- 上传说明必填，去除首尾空白后不得为空。
- 每次选择 1 至 10 份文件，每份最大 10 × 1024 × 1024 字节；只有上传成功的文件计入本次份数。
- 只接受 PDF、JPG、JPEG、PNG；平台按文件实际内容识别，扩展名与内容不一致、空文件、Office 文档、压缩包和可执行文件均拒绝。
- 一次上传有上传中或失败未移除项时不能保存。保存成功后形成新的材料记录，不覆盖、替换或删除历史记录。
- 本期不设累计材料份数上限；后续每次追加仍独立按上述单次规则校验。

每条材料记录保存上传机构、上传说明、成功文件的原文件名、格式、大小、上传时间和访问操作记录。材料记录保存后不可覆盖、替换或删除；读取失败时说明暂时无法获取，不把失败显示为空材料。

<a id="file-access"></a>

### 5.5 申请与文件访问范围

本节是本次发行申请、企业发行申请文件和机构材料的访问规则源。入口所在模块只负责承载入口，不改变下表的数据范围。

| 申请阶段或身份 | 发行申请与企业文件 | 机构材料 | 允许的文件动作 |
|---|---|---|---|
| 提交企业：申请尚未铸造成功（含待分配机构、运营处理中、铸造中、铸造失败）或已被运营驳回 | 仅可访问本企业提交的申请与原文件 | 不可访问；直接请求按无权处理，不透露材料是否存在 | 查看、下载自己的发行申请文件；提交成功后不能补传、替换或删除 |
| 提交企业：申请铸造成功后 | 仅可访问本企业提交的申请与原文件 | 可访问锁定发行机构名单内机构在铸造成功前形成的全部材料，每条可见上传机构、上传说明、上传时间及文件的原文件名、格式和大小；不可访问上传账号和访问记录；入口为 M4a [发行机构文件](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#institution-files) | 查看、下载自己的发行申请文件和上述机构材料；不能上传、补传、替换或删除任何文件 |
| 运营 | 可访问全部申请、企业文件、文件元信息和访问记录 | 可访问全部机构材料与历史记录 | 查看、下载；不得修改或删除企业文件和机构历史材料 |
| 尚未分配的机构 | 不可访问 | 不可访问 | 无 |
| “运营处理中”的当前名单内机构 | 可访问获分配申请及企业文件，但不可访问企业业务签名 | 可访问当前名单共享材料 | 查看、下载企业文件；查看、下载材料；追加合规材料 |
| “铸造中”或“铸造失败”的名单快照内机构 | 可访问对应申请及企业文件，但不可访问企业业务签名和内部铸造失败说明 | 可访问名单快照共享材料 | 查看、下载企业文件和材料；追加合规材料 |
| “运营驳回”的锁定名单内机构 | 可访问对应申请、企业文件和申请结果，但不可访问企业业务签名 | 可访问驳回前已形成的材料 | 仅查看、下载；不得继续上传、替换或删除 |
| “铸造成功”的锁定名单内机构 | 可访问对应发行申请、企业文件与铸造结果，但不可访问企业业务签名 | 可访问铸造成功前已形成的材料 | 仅查看、下载；本模块不授予代币权限，也不承接后续材料 |
| 不在当前、快照、锁定名单的机构 | 不可访问 | 不可访问 | 无；直接请求与旧页面提交均拒绝且不泄露数据 |

企业发行申请文件与机构材料均不上链，文件摘要也不上链。访问、下载和上传均须按操作当时的身份、申请状态及对应名单重新校验，并记录可追溯的访问操作；不能仅依赖入口或页面隐藏。

## 6. 运营处理

<a id="A-ISSUE-04"></a>

### 6.1 选择合约并发起铸造（A-ISSUE-04）

前提：

- 账号正常；申请最新状态为“运营处理中”。
- 当前名单中有一家资产托管机构，按该机构保存分配时记录的类型判断；审计机构、法律服务机构不要求。
- 已分配的资产托管机构后来停用，或之后在 M5 修改类型，仍满足本前提；既有分配中的机构后来停用不使名单失效。
- 机构材料可以为零。

名单中没有资产托管机构时不能发起铸造，说明须先新增一家资产托管机构；运营仍可新增机构或驳回。

运营须确认：

- 选择一个当前为启用、资产类型与申请资产相同、网络为 Ethereum 的合约，查看名称、标准、代币符号、资产类型、网络和合约地址。
- 填写大于 0 的铸造初始单位价值，币种固定为 USD，默认值为 1，精度不得超过合约及业务共同支持的精度。
- 代币数量直接取申请中的完整资产价值，数值比例为 1:1，单位为所选合约的代币符号；不用初始单位价值反算数量。
- 系统按“完整代币数量 × 初始单位价值”计算铸造初始资产估值，币种为 USD。完整数量、单位价值或计算结果无法被合约无损承载时，不得提交。
- 复核申请、企业业务签名、接收地址、上链字段、合约、单位价值和数量。

确认后再次校验申请、名单、合约资格、地址、价值和数量。成功时：

1. 记录操作账号、时间、合约、单位价值、数量和当时的机构名单快照。
2. 申请原子进入“铸造中”，不再允许驳回、新增机构或重复发起。
3. 向企业发送[发行申请进入铸造（NT-C03）](./03-代币发行-审核与铸造-消息通知.md#NT-C03)。
4. 平台签名并向所选合约提交铸造交易。

另一位运营已处理、名单中没有资产托管机构、合约不再满足新发行资格或业务值变化时，本次提交失败且不产生部分结果，页面返回最新状态。机构在既有分配后停用不属于名单失效。

<a id="onchain-fields"></a>

#### 6.1.1 上链字段

链上至少承载：资产编号、完整资产价值、唯一到期时点、企业提交时的接收地址、企业业务签名值、代币数量、代币符号、铸造初始单位价值，以及交易自身的合约地址和交易哈希。发行申请文件及其摘要不上链。

企业资料、发行申请文件、机构名单、机构材料、驳回意见、操作账号和消息不上链。机构名单和材料不构成机构审核结论。

<a id="A-ISSUE-05"></a>

### 6.2 运营驳回（A-ISSUE-05）

前提：账号正常；申请最新状态为“运营处理中”；当前名单至少有一家机构。不要求选择合约，不要求名单中有资产托管机构，也不要求机构上传材料。

- 驳回意见必填，1 至 500 个字符；去除首尾空格后不能为空。
- 提交前提示驳回后申请终止、不能恢复或铸造。
- 成功后申请进入“运营驳回”，记录意见、时间和账号，锁定当时的分配名单。
- 关闭锁定名单内未完成待办，停止机构继续上传；历史材料保留。运营可查看，锁定名单内机构按[申请与文件访问范围](#file-access)保留历史只读权限，但不获得代币权限。
- 企业收到[发行申请已驳回（NT-C04）](./03-代币发行-审核与铸造-消息通知.md#NT-C04)，并查看原文驳回意见。
- 资产发行状态按 M2 进入“已驳回”终态，这笔资产不能再次发起。

## 7. 铸造

<a id="A-ISSUE-06"></a>

### 7.1 铸造结果（A-ISSUE-06）

<a id="minting-progress"></a>

#### 7.1.1 铸造中与超时

- 展示“平台签名并提交”和“等待链上结果”两个阶段；已提交后展示交易哈希。
- 铸造开始 10 分钟仍无明确结果，申请仍为“铸造中”，不自动判失败，不开放重试或驳回。
- 每次铸造最多向全体运营发送一条[铸造超时待处理（NT-A05）](./03-代币发行-审核与铸造-消息通知.md#NT-A05)。企业和机构不收该消息。
- 超时后取得明确结果时仍按成功或失败收口。

<a id="handoff-mint"></a>

#### 7.1.2 铸造成功

- 申请进入“铸造成功”终态；资产发行状态变为“已发行”。
- 生成唯一代币编号，记录成功时间、网络、合约地址、交易哈希、完整数量、符号、初始单位价值、初始资产估值和接收地址。
- 发起铸造时已冻结的名单快照在铸造成功后成为锁定发行机构名单，作为本次发行的机构关系结果，不代表审核或认可；名单记录每家机构分配时的类型，其中有一家资产托管机构。
- 关闭本模块全部未完成材料待办，停止继续上传；锁定名单内机构按[申请与文件访问范围](#file-access)只读查看发行申请和已有材料。本模块不据此授予代币、资产托管、解除资产托管或铸造后材料权限，这些由 M4b 定义。
- 原发行企业自此可按[申请与文件访问范围](#file-access)，在 M4a [发行机构文件](../../面客端/M4a-我的代币与销毁申请/01-我的代币与销毁申请-PRD.md#institution-files)中只读查看、下载这些材料。
- 企业收到[铸造成功（NT-C05）](./03-代币发行-审核与铸造-消息通知.md#NT-C05)。

#### 7.1.3 铸造失败

- 平台签名、交易提交或链上执行失败时，申请进入“铸造失败”；资产保持发行申请中。
- 每次失败记录失败时间、取得到的失败说明和已产生的交易哈希；取不到不编造，未上链则无哈希。
- 运营看完整失败和重试记录；企业仍见“发行处理中”；机构不看内部失败说明。
- 当前机构名单和材料权限继续有效；材料上传不改变失败状态。
- 每次失败向全体运营发送[铸造失败待重试（NT-A03）](./03-代币发行-审核与铸造-消息通知.md#NT-A03)。

<a id="A-ISSUE-07"></a>

### 7.2 铸造失败手动重试（A-ISSUE-07）

账号正常的运营可对“铸造失败”申请重试。重试沿用首次发起时锁定的合约、上链信息、单位价值、数量、接收地址和机构名单快照，不重新审核，不重新校验资产托管机构前提，不允许改值。

- 确认后再次校验状态，进入“铸造中”，记录重试时间和账号，提交新交易。
- 重试不是新的运营处理，不重复发送 NT-C03。
- 每次交易和结果单独记录；成功后收口，失败后仍可重试。
- 并发重试仅第一个有效提交生效，其余返回最新状态。
