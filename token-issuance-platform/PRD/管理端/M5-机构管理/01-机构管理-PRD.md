# 机构管理 · 功能与业务规则

2026-11-10｜管理端：运营管理人员｜需求评审稿

本模块共四册：本册定义机构档案和机构账号；[流程图与状态机](./02-机构管理-流程图与状态机.md)画出添加、登录邮箱填错的纠正和启停；[消息通知](./03-机构管理-消息通知.md)只定义账号开通邮件；[验收](./04-机构管理-验收.md)供测试使用。

依据标注：规则后的【确认】表示用户已明确；未标注的是为落实规则所写的产品细化。

本模块只负责机构主数据、机构级基础资质及其唯一管理端账号，不定义具体发行申请、代币或其他业务对象的分配、材料、办理流程与数据范围。M5 只向业务模块提供机构唯一标识、机构档案、固定机构类型和机构状态。

## 1. 模块是什么

运营在管理端维护 RWA 发行可能使用的机构。添加机构时选择机构类型，并同时开通该机构唯一管理端账号。本期机构类型固定为资产托管机构、审计机构、法律服务机构三类，不提供其他选项、自定义类型或类型配置维护。

基本原则：

- 平台统一使用“机构”对象，不再设置额外的特定机构类别对象。
- 每家机构只有一个有效管理端账号；账号登录、安全和本人账户维护由“管理端登录与权限”定义。
- 机构类型是固定档案分类，不自动授予任何业务权限；本期只能在三类固定值中选择。
- 机构级基础资质是机构自身长期有效的说明和附件，不属于任何具体发行申请、代币或其他业务对象的材料。
- 启用表示可以被业务模块用于新关系；停用表示不再进入新的机构选择范围。停用对既有业务的具体影响由对应业务模块决定，M5 不代替其决策。
- 机构不自助注册；只有运营可添加、编辑、停用和启用机构。
- 本期不提供机构账号停用、启用或人工冻结功能；机构状态不改变账号状态。

**一个完整的例子。** 运营添加审计机构 X，填写机构档案和机构级基础资质并设置登录邮箱与初始密码。提交成功后，平台生成不可修改的机构编号，同时建立启用状态的机构和待首登改密账号，并发送账号开通邮件。运营之后可用机构编号查找 X，也可编辑其档案或停用机构；机构编号始终不变，停用不改变账号状态。

### 1.1 需求清单

| 编号 | 功能 | 结果 |
| --- | --- | --- |
| F-RG-01 | 机构列表与查找 | 运营查看全部机构并按机构编号、名称、邮箱、类型和状态查找筛选 |
| F-RG-02 | 添加机构并开通账号 | 生成唯一机构编号，建立机构档案和唯一账号，发送开通邮件 |
| F-RG-03 | 查看机构详情 | 查看档案、机构级基础资质、机构和账号状态 |
| F-RG-04 | 编辑机构资料 | 更新名称、类型、联系人和资质资料，不改登录邮箱 |
| F-RG-05 | 停用与启用 | 控制机构能否进入新业务选择范围 |

### 1.2 本期不做

- 机构自助注册、删除机构、一个机构多个账号。
- 运营修改机构登录邮箱、代机构找回或重置密码。
- 其他机构类型、自定义类型、机构类型配置维护，或在机构类型上配置业务权限与流程模板。
- 机构账号停用、启用或人工冻结。
- 发行申请分配、机构待办、机构材料、代币台账或销毁业务。

## 2. 机构档案与账号

| 字段 | 规则 |
| --- | --- |
| 机构编号 | 添加成功时由平台生成；全平台唯一；创建后不可修改或重新分配 |
| 机构名称 | 必填；去除首尾空格后 2–100 字；全平台唯一，比较时不区分英文字母大小写 |
| 机构类型 | 必填；仅可选择资产托管机构、审计机构、法律服务机构，单选；不提供其他或自定义值。<a id="type-name-display"></a>机构类型名称按添加或编辑机构时选定的名称原样展示，不随界面语言变化；各模块的页面、站内消息和邮件的中英文内容中都原样使用【确认】 |
| 联系人姓名 | 必填；2–50 字 |
| 联系邮箱 | 必填；合法邮箱，可与登录邮箱相同 |
| 联系电话 | 必填；由国家/地区区号和电话号码两部分组成，两部分都必填。区号从下拉选项中选择，选项按“+区号 国家/地区名”展示，如“+86 中国”，英文界面为“+86 China”【确认】，见[联系电话区号规则](#phone-code)；电话号码允许数字、空格、短横线和括号，6–30 字，只计号码部分、不含区号【确认】。展示时区号在前、号码在后，如“+65 6000 0000” |
| 所在国家/地区 | 必填 |
| 注册地址 | 必填；2–300 字 |
| 机构级基础资质说明 | 选填；最多 1000 字；只描述机构自身资质，不填写具体发行申请、代币或其他业务对象的材料 |
| 机构级基础资质附件 | 选填；只保存机构自身基础资质；格式、大小和份数见[机构级基础资质附件的文件规则](#qualification-files) |
| 登录邮箱 | 必填；在全部管理端账号当前及历史使用过的登录邮箱中唯一，不区分大小写；创建后运营不能修改；历史上归属其他账号的邮箱不能分配给本账号；添加时填错的按[登录邮箱填错的纠正](#login-email-fix)处理 |
| 初始密码 | 必填；遵守管理端统一密码规则，只用于首次登录强制改密 |
| 机构状态 | 启用、停用；新增默认为启用 |
| 账号状态 | 待首登改密、正常、锁定；由登录与权限模块维护 |

<a id="phone-code"></a>
**联系电话区号规则**【确认】，添加机构和编辑机构资料时相同：

- 区号选项为全部国家/地区区号；国家/地区名与“所在国家/地区”使用同一套清单，按界面语言展示。多个国家/地区共用同一区号时各自为一个选项，如“+1 美国”“+1 加拿大”。
- 添加机构时区号初始不预选；选择所在国家/地区后，区号尚未选择时自动带出该国家/地区的区号，可以修改。已选区号后再修改所在国家/地区，不改变已选区号。
- 编辑机构资料时保留已保存的区号和号码，不随所在国家/地区自动变化。
- 未选区号、号码为空或号码不合规时不能保存，指出联系电话的问题，已填写的其他内容保留。

<a id="qualification-files"></a>
**机构级基础资质附件的文件规则**【确认】，添加机构和编辑机构资料时相同：

- 只接受 PDF、JPG、JPEG、PNG；平台按文件实际内容识别格式，扩展名与实际内容不一致或内容不属于这四种格式的文件不接受。
- 每份不超过 10 × 1024 × 1024 字节；恰好等于上限的文件可以添加。
- 每家机构最多 10 份；只有上传成功的文件计入份数，恰好 10 份可以保存，已有 10 份时不能再添加，须先移除。
- 不合规或上传失败的文件不添加并说明原因，已添加的其他文件和已填写内容保留；上传失败的文件可重试。

## 3. 机构列表与详情（F-RG-01、F-RG-03）

- 仅运营可见机构管理菜单。机构账号和未登录用户无权访问。
- 列表展示机构编号、机构名称、类型、登录邮箱、机构状态、账号状态、添加时间和最近登录时间。
- 支持按机构编号、机构名称或登录邮箱查找，按类型、机构状态、账号状态组合筛选；默认按添加时间从新到旧；分页、返回位置、空状态与读取失败按可信资产（M2）的[业务列表通用规则](../../两端共用/M2-可信资产/01-可信资产-PRD.md#list-common)。
- 详情展示机构编号、完整档案、机构级基础资质、机构和账号状态、添加与最近更新时间、最近登录时间；不展示初始密码。
- 无数据、筛选无结果和读取失败须区分；访问不存在机构与无权访问使用一致结果。

<a id="F-RG-02"></a>
## 4. 添加机构并开通账号（F-RG-02）

- 运营填写完整机构档案，选择机构类型，设置唯一登录邮箱和符合统一密码规则的初始密码。
- 提交时校验名称、固定机构类型、登录邮箱的历史唯一性和全部字段；失败不建立机构或账号，不发开通邮件，并保留仍有效输入。
- 成功时生成不可修改的机构编号，并原子化建立机构与账号：机构启用，账号待首登改密。任一部分失败均不留下机构编号对应的孤立机构或账号。
- 初始密码只在本次填写和开通邮件中使用，成功后页面不再显示。
- 成功后发送[机构账号开通邮件（NT-R03）](./03-机构管理-消息通知.md#NT-R03)。邮件失败不回滚机构与账号，运营可线下告知；本期无邮件重发入口。
- 重复点击、刷新或网络重发只建立一条机构和一个账号。

<a id="login-email-fix"></a>
### 登录邮箱填错的纠正

运营添加机构后发现登录邮箱填错的，产品内不提供修改入口，由运营线下联系开发人员处理【确认】：

- 开发人员把该机构账号的登录邮箱改为正确邮箱，并设置新的初始密码；这一操作视为一次凭据重置【确认】。
- 正确邮箱须满足[登录邮箱](#fields)的唯一性规则；新初始密码遵守管理端[设置密码的共同规则](../M5-管理端登录与权限/01-管理端登录与权限-PRD.md#password-rules)。
- 重置生效后，旧初始密码和账号当前密码都作废，该账号全部登录结束，账号回到待首登改密【确认】；账号与登录的结果按[开发人员重新分配初始密码与重置凭据](../M5-管理端登录与权限/01-管理端登录与权限-PRD.md#credential-reset)执行。
- 填错的邮箱立即失去登录与找回资格，但仍永久保留给该账号，不得分配给其他账号【确认】。
- 不重发[机构账号开通邮件（NT-R03）](./03-机构管理-消息通知.md#NT-R03)，新初始密码由线下告知机构【确认】；本情形不发送站内消息或邮件【确认】。
- 平台记一条安全记录，含修改前后的登录邮箱【确认】。
- 机构编号、机构档案、机构状态和业务归属不变；仍是该机构唯一的管理端账号，不新建账号。

<a id="F-RG-04"></a>
## 5. 编辑机构资料（F-RG-04）

- 可编辑机构名称、固定三类中的机构类型、联系人、联系电话、联系邮箱、国家/地区、地址、机构级基础资质说明和附件。
- 资质附件可添加和移除，保存后合计份数和每份文件仍须符合[机构级基础资质附件的文件规则](#qualification-files)。
- 不能编辑机构编号、登录邮箱、账号状态、添加时间、最近登录时间或初始密码。
- 名称仍须唯一；保存失败保持最近一次成功结果，可重试。
- 编辑成功使用新档案值。历史业务如何展示名称和类型快照由业务模块定义，本模块不改写历史。
- 编辑不结束机构登录，不发送通知。

<a id="F-RG-05"></a>
## 6. 停用与启用（F-RG-05）

- 停用前确认机构名称、类型和影响说明。影响说明写明：停用后该机构不再进入新业务的机构选择范围；已建立的业务关系不因停用解除，继续按所属业务模块的规则办理。
- 停用成功后机构状态为停用，不出现在任何新业务的机构可选范围中。
- 启用成功后恢复进入新业务选择范围。
- 启停不改变账号状态，不自动结束登录，不删除档案或历史，不发送通知。
- 既有申请、待办、材料、代币等业务在停用后的查看和办理结果，由 M3b、M4b 等所属模块定义；M5 只提供最新机构状态。
- 并发操作按最新状态校验，不静默覆盖；重复提交承接同一结果。

<a id="pending"></a>
## 8. 待确认事项与依赖

具体业务对象的材料、关系和办理边界由所属模块维护，不在本模块重复定义。

### 待确认事项

本模块没有业务待确认事项。

### 依赖

- 管理端账号、邮件、文件存储与访问控制能力。通用密码规则及账号状态以[管理端登录与权限](../M5-管理端登录与权限/01-管理端登录与权限-PRD.md)为准。
- 开发人员：在产品外完成[登录邮箱填错的纠正](#login-email-fix)，并线下告知新初始密码。
