# 合约管理 · 验收

2026-10-30｜需求评审稿｜供测试使用

本册只写验收标准，测试用例与执行步骤由测试小队编写。规则见[功能与业务规则](./v1.0-合约管理-PRD.md)，各节顺序与功能册一致。

怎么读：

- 共 16 条验收，沿用原编号，新增 AC-CT-10～16；按功能顺序排列。
- 一条验收写了多个场景时，全部场景都满足才算通过。
- 涉及发行二审选择合约的场景，在代币发行 · 审核与铸造（M3b）上线前只核对本模块的可选范围；选择、提交及铸造重试的办理过程随 M3b 验收。
- 依赖待确认事项的场景注明“待验，不判通过”。

## 0. 验收前准备

账号：

- 运营账号甲、乙，均已完成首次改密。
- 一个已登录的监管机构账号 X，用于验证无权访问；一个已认证的企业用户，用于确认面客端没有合约管理。

数据：

- 合约 K：ERC-3525，对应资产类型应收账款，Ethereum，状态可用，合约地址含大小写字母。
- 合约 L：ERC-3525，对应资产类型应收账款，Ethereum，状态停用。
- 合约 M：ERC-3525，对应资产类型应收账款，Ethereum，状态可用，配置时间晚于合约 K。
- 一笔关联应收账款、监管一审已通过、待运营审核的发行申请 P；另有引用 K 的铸造中、铸造失败、铸造成功申请及代币。
- 环境：可由开发人员新增合约，运营编辑名称及启用停用；覆盖无合约、读取失败、保存失败、重复提交、两人同时修改同一项及分别修改名称与状态、提交时权限失效等场景；可在二审选好合约后将其停用；可区分平台停用与链上异常。
- 名称样本：正常文本、空值、纯空白；长度与重名边界依赖功能册的待确认口径。

## 4. 启用与停用合约

对应功能：[启用与停用合约（F-CT-04）](./v1.0-合约管理-PRD.md#F-CT-04)、[维护中的取消、失败与冲突](./v1.0-合约管理-PRD.md#maintenance-results)

| 前提 | 操作 | 预期结果 |
| --- | --- | --- |
| <a id="AC-CT-13"></a>状态切换与业务影响（AC-CT-13）<br/>K 可用，L 停用 | 甲确认停用 K、启用 L；乙刷新；查看二审可选范围 | 操作前可核对当前名称、完整地址、当前和目标状态，并获知对二审选择的影响；成功后返回列表，K 停用、L 可用并重新排序，乙刷新可见；资产类型匹配时可选 L、不可选 K；其他五项信息和配置时间不变；不自动办理二审或重试铸造，不发消息或邮件 |
| <a id="AC-CT-14"></a>状态维护的边界结果（AC-CT-14）<br/>甲、乙维护 K | 覆盖取消、保存失败、重复提交、已为目标状态、他人先改状态，以及甲调整状态期间乙改名 | 取消或保存失败状态不变，失败可重试；重复提交不造成额外变化；已为目标状态时保留并说明当前状态；同一状态项的并发修改不覆盖、展示最新值供核对；状态调整不覆盖他人已保存名称；平台启用不将链上异常表示为已恢复 |
| <a id="AC-CT-15"></a>原合约恢复后手动重试（AC-CT-15）<br/>P 已二审通过，铸造失败，原合约 K 停用 | 甲尝试重试；乙启用 K；甲再手动重试 | 停用时不能重试、不能改选，P 保持铸造失败；启用本身不发起铸造；K 可用后由甲手动重试，仍用原合约，成功发起后 P 回到铸造中；链上异常由开发人员处理 |

对应功能：[发行二审可选的合约（F-CT-02）](./v1.0-合约管理-PRD.md#F-CT-02)、[合约状态](./v1.0-合约管理-PRD.md#status)
