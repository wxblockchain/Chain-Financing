<a id="fig-1"></a>
## 监管一审（图 1）

```mermaid
flowchart TD
    A[企业提交成功<br/>申请：待监管审核<br/>所选机构收到新的待审申请] --> B[企业与所选机构线下签署监管协议]
    B --> C[监管机构打开本机构的申请<br/>查看申请信息与关联资产最新状态]
    C --> D{一审结论}
    D -->|通过| E[上传监管协议 1 至 10 份<br/>PDF、JPG、JPEG、PNG，每份不超过 10MB<br/>可选填监管意见，最多 500 个字符]
    E --> F{确认提交<br/>申请仍为待监管审核<br/>至少 1 份上传成功}
    F -->|不满足或保存失败| F1[不生效，说明原因<br/>申请仍为待监管审核，可重试]
    F -->|满足| G[申请：待运营审核<br/>协议对企业与运营开放]
    G --> G1[企业收到监管审核通过<br/>全体运营收到待二审的申请]
    D -->|驳回| H[填写驳回意见，必填，最多 500 个字符]
    H --> I{确认提交<br/>申请仍为待监管审核}
    I -->|不满足或保存失败| F1
    I -->|满足| J[申请：监管驳回，终止<br/>资产发行状态：已驳回<br/>接收账户解除引用]
    J --> J1[企业收到监管审核驳回]
```

资产撤销确权、删除、结清或逾期均不自动拦截或终止申请；审核人按最新状态判断，规则见[审核期间资产状态变化](./v1.0-代币发行-审核与铸造-PRD.md#review-asset-change)。

<a id="fig-2"></a>
## 运营二审与铸造（图 2）

```mermaid
flowchart TD
    A[申请：待运营审核] --> B[运营查看申请、关联资产<br/>企业信息、监管意见与协议<br/>资产最新状态与上游变更提示]
    B --> C{二审结论}
    C -->|驳回| D[填写驳回意见，必填，最多 500 个字符]
    D --> D1{确认提交<br/>申请仍为待运营审核}
    D1 -->|不满足或保存失败| X[不生效，说明原因<br/>申请仍为待运营审核，可重试]
    D1 -->|满足| D2[申请：运营驳回，终止<br/>资产发行状态：已驳回<br/>接收账户解除引用；协议保留]
    D2 --> D3[企业收到运营审核驳回]
    C -->|通过| E{有可用合约}
    E -->|没有| E1[匹配合约停用可由运营启用<br/>无匹配合约需开发人员配置<br/>不能通过，仍可驳回]
    E -->|有| F[选择一个铸造合约<br/>确认代币数量、到期日、接收地址、合约]
    F --> F1{确认提交<br/>申请仍为待运营审核<br/>合约仍可用}
    F1 -->|不满足或保存失败| X
    F1 -->|满足| G0[二审通过，企业收到运营审核通过]
    G0 --> G[申请：铸造中<br/>平台用所选合约铸造]
    G --> H{链上铸造结果}
    H -->|成功| I[申请：铸造成功<br/>资产发行状态：已发行<br/>资产进入监管质押<br/>接收账户被代币引用]
    I --> I1[企业收到铸造成功]
    H -->|失败| J[申请：铸造失败<br/>记录失败时间与说明]
    J --> J1[全体运营收到铸造失败待重试<br/>企业与监管机构不收]
    J1 --> K{二审原合约仍可用}
    K -->|否| K1[不能重试或改选合约<br/>申请保持铸造失败]
    K1 --> K2[运营启用被停用的原合约<br/>链上异常由开发人员恢复]
    K2 --> K
    K -->|是| L{运营按原合约确认手动重试<br/>申请仍为铸造失败}
    L -->|满足并成功发起| G
    L -->|发起失败| L1[说明原因，保持铸造失败]
    L -->|申请状态已变化| L2[不执行，展示最新状态]
```

可用合约须同时满足资产类型为应收账款、网络为 Ethereum、状态为启用（M6 现行同义名称为“可用”），见[可选合约范围](./v1.0-代币发行-审核与铸造-PRD.md#available-contracts)。

## 发行申请状态（图 3）

状态引用简报第 5 节，本模块不另行定义。初始状态为“待监管审核”；“监管驳回”“运营驳回”“铸造成功”是终态。

```mermaid
stateDiagram-v2
    state "待监管审核" as S1
    state "监管驳回（终止）" as S2
    state "待运营审核" as S3
    state "运营驳回（终止）" as S4
    state "铸造中" as S5
    state "铸造成功" as S6
    state "铸造失败" as S7

    [*] --> S1: 企业提交成功（M3a）
    S1 --> S2: 监管机构一审驳回
    S1 --> S3: 监管机构上传协议并一审通过
    S3 --> S4: 运营二审驳回
    S3 --> S5: 运营选择合约并二审通过
    S5 --> S6: 链上铸造成功
    S5 --> S7: 链上铸造失败
    S7 --> S5: 运营沿用二审原合约重试，合约须可用
    S2 --> [*]
    S4 --> [*]
    S6 --> [*]
```

申请状态与资产发行状态的对应：待监管审核、待运营审核、铸造中、铸造失败对应“发行申请中”；监管驳回、运营驳回对应“已驳回”；铸造成功对应“已发行”，见[发行状态（图 2）](./v1.0-可信资产-流程图与状态机.md#fig-2)。

## 查看申请与数据范围（图 4）

```mermaid
flowchart TD
    A[访问发行申请列表、申请详情或协议文件] --> B{访问者}
    B -->|未登录| B1[先登录，之后按当前身份重新判断]
    B -->|待首登改密或锁定| B2[按管理端账号状态处理<br/>看不到发行审核]
    B -->|监管机构| C{申请属于本机构}
    C -->|否或申请不存在| N[无权查看或申请不存在<br/>不返回任何内容]
    C -->|是| D[申请详情<br/>接收信息只见地址<br/>不见企业详情与上游变更提示]
    B -->|运营| E[申请详情<br/>全平台任何状态]
    E -->|申请不存在| N
    D --> F{申请状态}
    E --> F
    F -->|待监管审核| F1[监管机构可一审<br/>运营只能查看；无协议]
    F -->|监管驳回| F2[双方只能查看驳回意见；无协议]
    F -->|待运营审核| F3[运营可二审<br/>双方可查看下载协议]
    F -->|运营驳回| F4[双方只能查看驳回意见<br/>可查看下载协议]
    F -->|铸造中| F5[双方只能查看]
    F -->|铸造失败| F6[运营查看失败说明<br/>原合约可用时才能重试<br/>监管机构只见状态]
    F -->|铸造成功| F7[双方查看铸造结果<br/>可进入代币台账]
```
