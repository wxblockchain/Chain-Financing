# 消息通知 · 验收

2026-10-29｜需求评审稿｜供测试使用

本册只写验收标准，测试用例与执行步骤由测试小队编写。规则见[功能与业务规则](./v1.0-消息通知-PRD.md)与[消息通知](./v1.0-消息通知-消息通知.md)，各节顺序与两册一致。

怎么读：

- 共 32 条验收，编号连续。
- 一条验收写了多个场景时，全部场景都满足才算通过。
- 依赖待确认事项的验收注明“待验，不判通过”及所依赖的待确认编号；确认前只核对已写明的部分。
- 触发消息的业务操作由 M3a、M3b、M4a、M4b、M5 提供；这些模块未就绪时，相应验收待验。

## 0. 验收前准备

账号：

- 企业 A、企业 B：各自的登录地址能在资产可信平台匹配到企业信息；另有一个未匹配的游客地址。
- 监管机构 X、监管机构 Y：已完成首次登录改密；另有一个刚被邀请、尚未首次登录的监管机构 Z（其登录邮箱可收信）。
- 运营管理人员甲、乙两个账号；可由开发人员新开通的运营账号丙。

数据：

- 企业 A 的可发行资产若干笔（上游资产编号各不相同，美元计价）；其中一笔选择监管机构 X，一笔选择监管机构 Y。
- 可模拟链上铸造失败、销毁失败，并可让重试再次失败或成功。
- 企业 A 一个满足销毁条件（已到期、已结清、无融资质押）的代币。
- 可模拟消息重复送达；可模拟消息列表、详情、已读保存的读取失败；可让登录失效。
- 足以触发分批加载的消息数量。
